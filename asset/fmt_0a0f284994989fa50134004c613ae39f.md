
虽然 SQL-89 和 SQL-92 仅允许一种空值，但 Codd (1990) 在关系模型的“版本 2”中提出了一种四值逻辑，以允许两种未知值（适用和不适用），但这并未获得广泛认可。

下面给出了本节介绍的四个运算符的 SQL-89 语法摘要。此处，“expn”表示一个表达式，如列名或常量（或由算术运算符 `+`、`−`、`*`、`/` 等连接的这些内容的组合……稍后讨论）。

*   ```
    expn [not] in (constant-list)
    ```

*   ```
    expn [not] between expn and expn
    ```

*   ```
    char-col [not] like quoted-string [escape quoted-char]
    ```

*   ```
    colis [not] null
    ```

此外，SQL-89 允许将 `in` 运算符与子查询一起使用，并允许在搜索条件中使用量化比较和 `exists` 量词（稍后讨论）。SQL-92（及更高版本）显著扩展了搜索条件中允许的表达式和运算符种类。

例如，SQL-92 允许将*行值表达式*（例如，一个值元组）作为任何比较器（例如 `=`、`in`）的左参数，并包含 `unique`、`match` 和 `overlaps` 谓词。`Unique` 用于检查子查询返回的每个非空行是否唯一，`match` 用于检查某行是否与子查询返回的某行匹配，`overlaps` 用于测试两个日期时间段是否重叠。

SQL:1999 更进一步，增加了用于搜索条件的 `similar`、`distinct` 和 `type` 谓词。`Similar` 允许通过正则表达式比较字符串，`distinct` 测试两个行值是否不同，`type` 测试用户定义类型值表达式是否符合用户定义类型规范。SQL 方言对这些标准谓词的支持各不相同。然而，所有 SQL 方言现在都支持本节讨论的 SQL-89 语法。

## 12.8 SQL：并集与简单子查询

本节讨论 `select` 查询作为较大 `select` 查询内部组件的两种用法。首先，我们将探讨如何在 SQL 中指定并集、交集和差集运算。接下来，我们将了解 SQL 中的基本子查询。让我们从并集运算开始。基本语法如下所示。保留字“union”仅允许出现在 `select` 查询之间，而不允许出现在表名之间。

*   ```
    select-query
    ```

*   ```
    union [ all ]
    ```

*   ```
    select-query
    ```

*   ```
              …
    ```

这些 `select` 查询必须是**并集兼容**的（即，列数相同，且对应列基于兼容的数据类型）。默认情况下，返回的集合是各个 `select` 查询返回表的并集，并消除了任何重复行。要返回包（允许重复），请指定 `all` 以包含重复行。请注意，这与 SQL `select` 列表语法相反，后者默认返回包，并使用 `distinct` 来消除重复项。

SQL:1999 允许在 `union` 后显式声明 `distinct` 选项；如果省略，则默认假定为该选项。SQL Server 支持“`union all`”语法，但不支持“`union distinct`”语法，因为除非添加 `all`，否则它总是从 `union` 中移除重复项（因此添加“`distinct`”即使可能阐明默认行为也是多余的）。

例如，图 12.50 中的查询列出了每个是美国人或驾驶福特车的人。第一个 `select` 查找美国人（“JimO”、“Lance”），第二个 `select` 查找福特车驾驶员（“Colleen”、“Lance”），而 `union` 包含了这两个中间结果中任一或两者中的任何人。尽管 Lance 出现在两个表中，但他仅在最终并集中出现一次，因为默认情况下会移除重复项。

![图 12.50 默认情况下，并集消除重复项。](img/f12-50-9780443237904.jpg)

图 12.50 默认情况下，并集消除重复项。

如果需要*重复项*，则必须在 `union` 后指定 `all` 选项，从而生成一个包。例如，前一个查询中的 `union all` 将导致 Lance 在结果中出现两次。通常，如果某行在一个结果表中出现 *m* 次，在另一个结果表中出现 *n* 次，则它在两个结果的包并集中将出现 *m* + *n* 次。

由于最终结果中的列标题取自并集中的第一个查询，因此此处出现标题“shortName”。虽然此查询可以用其他方式表述（稍后见子查询），但并集运算提供了从兼容结果表合并结果的最自然方法。

由于基表很少是并集兼容的，因此并集运算符主要用于通过投影使其并集兼容的派生表，如此例所示。`union` 运算可在一个查询中多次应用。如果使用 `order by` 子句，它必须位于并集中最后一个查询之后。例如，追加子句 `order by` shortName 将结果排序为“Colleen”、“JimO”、“Lance”、“Walter”。

在 SQL-92（及更高版本）中，可添加 `corresponding` 选项以指定用于并集的公共列。例如，如果 图 12.50 中的 driver 列改名为“shortName”，则该查询可声明为 `select` * `from` Person `union corresponding` Drives 或 `select * from` Person `union corresponding by` (shortName) Drives。大多数 SQL（包括 SQL Server）尚不支持此选项。

现在考虑查询：谁驾驶福特、霍顿或本田（即谁至少驾驶这些车型中的一种）？虽然我们可以使用两个并集来表述此查询，但只需扫描一次 Drives 表的行即可回答该查询。因此，使用 `or` 运算符更简单（且更高效），如下所示：

*   ```
    select driver from Drives
    ```

*   ```
    where carModel = ‘Ford’ or carModel = Holden’ or carModel = ‘Honda’
    ```

### SQL 集合运算与子查询

#### 不相交操作数的 Union 运算

当 `union` 运算符的操作数是不相交的（即互斥的）时，即使只涉及一个基表，`union` 运算符有时也会被用来为输出添加描述。作为一个例子，请考虑 图 12.51 中的 Expert 和 Novice 表。假设我们想要列出柔道运动员的姓名，以及一个标签来指示谁是专家、谁是新手。为了获取姓名，我们可以将一个针对柔道专家的 `select` 查询与另一个针对柔道新手的 `select` 查询进行 union 运算。然后，我们可以通过在相关的 `select` 列表中包含字符串“expert judoka”和“novice judoka”来标识专家和新手柔道运动员。

![图 12.51 常量可与 union 结合使用以指示行的来源。](img/f12-51-9780443237904.jpg)

图 12.51 常量可与 union 结合使用以指示行的来源。

我们可以通过引入“judo level”作为标签的别名来改进这一点。这为标签提供了一个有意义的列标题，并允许我们将标签缩短为仅“expert”和“novice”，如图所示。请注意“judo level”中使用双引号以允许嵌入空格。

虽然在操作数不相交时，在 union 中添加描述性字符串的技术很方便，但如果它们重叠则用处不大。当字符串值被添加到行中时（因为这些值不同），原本重叠的行会变得不相交。因此，这些行会在 union 结果中出现多次。

#### Intersect 和 Except 运算符

在 SQL-92 中（但不在 SQL-89 中），提供了用于*集合交集*的 `intersect` 运算符和用于处理*集合差*的 `except` 运算符。它们的工作方式类似于 `union` 运算符。它们仅允许在返回 union 兼容表的 `select` 查询之间使用。除非指定了 `all` 选项，否则会从结果中移除重复项。

请回顾 图 12.50 中的表 `Person`(shortName, nationality) 和 `Drives`(driver, carModel)。现在考虑查询：哪些美国人开福特车？这意味着，谁是美国人**并且**开福特车？因为国籍事实和 carModel 事实在单独的表中，这个逻辑“**与**”运算符自然可以通过表交集运算符来实现，如下所示，产生结果 {“Lance”}。

```
select shortName from Person
where nationality = ‘American’
intersect
select driver from Drives
where carModel = ‘Ford’
```

类似地，查询“哪些美国人不开福特车？”可以表述为集合差，如下所示，产生结果 {“JimO”, “Walter”}。

```
select shortName from Person
where nationality = ‘American’
except
select driver from Drives
where carModel = ‘Ford’
```

与 union 和 intersection 不同，差运算符**不**满足交换律。例如，反转前一个查询中操作数的顺序会产生 {“Colleen”}，因为反转后的查询含义不同：“哪些福特车车主不是美国人？”

如果在 `intersect` 或 `except` 后使用 `all` 选项，它分别返回包交集或包差。一般来说，如果一行在一个表中出现 *m* 次，在另一个表中出现 *n* 次，那么它在包交集中出现 min(*m, n*) 次，在包差中出现 max(*m* - *n*, 0) 次。

虽然所有主流商业 SQL 方言都支持 `union` 运算符，但有几种尚不支持 `intersect` 和 `except` 运算符。正如我们现在要讨论的，这两个运算符可以使用子查询来模拟，因此它们的缺失并不意味着功能的丧失。

#### SQL 子查询

SQL *子查询* 类似于关系代数中嵌套公式内的组件查询。虽然 SQL 子查询本身就是查询，但它们必须用括号括起来（这与进行 union 运算的 `select` 查询不同），并且对其使用有一些限制。理想情况下，一种语言应该是正交的——在任何合法使用值或结果的地方，返回该值或结果的表达式也应该是合法的。然而在 SQL-89 中，子查询仅允许在其结果合法的少数几个地方使用。虽然 SQL-92 移除了这些限制，但鲜有商业 SQL 完全实现正交性。

子查询是嵌入在另一个查询中的带括号的 `select` 查询。设 Θ 表示比较运算符之一 (=, <>, <, >, <=, >=)。在 SQL-89 中，子查询仅在以下三种上下文中合法：

```
expression [not] in (subquery)                                            -- 成员资格子查询
```

```
expression Θ [all | some | any] (subquery)         -- [量化] 比较子查询
```

```
exists (subquery)                                                                                -- 存在性子查询
```

##### 成员资格子查询

*成员资格子查询* 紧跟在 `in` 运算符之后。在 SQL-89 中，成员资格子查询必须是*单例查询*（即必须返回单个列）。这与 `in` 运算符配合值包（一列只是垂直显示的值包）的用法一致。在 SQL-92 中，`in` 运算符前面可以是行值表达式，在这种情况下子查询可以返回多列表。

##### 比较子查询

*比较子查询* 紧跟在比较器（例如 =）之后。如果比较器由量词 `all`、`some` 或 `any` 之一修饰，这就是*量化比较*。在 SQL-89 中，比较子查询必须返回单个列；如果比较未量化，子查询必须返回单个值。这与比较运算符的正常用法一致。在 SQL-92 中，比较器前面可以是行值表达式，在这种情况下子查询可以返回多列表，或者如果未量化，则返回行值。*存在性子查询* 出现在 `exists` 量词之后，可以返回任何表。

##### SQL-92 扩展

在 SQL-92 中，子查询可以用在其他地方（例如 `from` 子句和 `check` 子句），只要它们的结果表在那里讲得通（正交性）。`From` 子句子查询要求为派生表指定别名，即使不需要别名也是如此。语法是：

```
… from (subquery) [as] alias
```

SQL Server 支持 `from` 子句中的子查询，但不支持 `check` 子句中的子查询。一些 SQL 方言将其子查询支持限制在 SQL-89 的三种情况中，每种情况都将子查询嵌入在外部查询的 where 子句中，如下所示：

```
select …                    -- 外部查询
from …
where …
           (select …          -- 子查询
from … )
```

如果子查询是自包含的（即它不引用外部查询），则称之为*非相关子查询*。在这种情况下，它会首先被求值，并被其结果（例如值包）替换，然后再处理外部查询。相反，*相关子查询* 引用其外部查询。本节仅考虑简单的、非相关的成员资格和比较子查询。存在性子查询和相关子查询将在后面介绍。

##### 成员资格子查询求值

现在让我们考虑*成员资格子查询*。条件 *expression* `in` (*subquery*) 当且仅当表达式的值包含在子查询结果中时返回 True。如果子查询返回空集，该条件求值为 unknown。外部查询结果仅包含条件求值为 True 的行。

### 子查询示例与连接替代方案

为了讨论一些示例，请考虑 图 12.52 中所示的表。假设存在一个从 `Mountain.countryName` 到 `Country.countryName` 的子集约束。相反的约束不适用（例如，荷兰没有山脉）。为节省空间，每个国家仅显示部分山脉。

![图 12.52 一些国家及其部分山脉（如果有）。](img/f12-52-9780443237904.jpg)

图 12.52 一些国家及其部分山脉（如果有）。

考虑查询：“哪些山脉位于人口超过 1 亿的国家？”我们可以先找出具有相关人口的国家，然后找出这些国家中的山脉。这可以用 SQL 表示如下：

```
select mtName from Mountain
where countryName in
    (select countryName from Country
     where population > 100000000)
```

首先对子查询求值，得到包（“India”、“USA”）。子查询被此中间结果替换后，对外部查询求值，最终得到三座山脉的列表：Mana、McKinley 和 Rainier。当然，该查询本可以用连接来表述。作为练习，您可以尝试这样做。

子查询可以嵌套（即其搜索条件可以包含子查询）。为提高可读性，子查询应始终缩进。嵌套层级越深，缩进应越大。

通常，使用子查询的查询可以用 `join` 查询替代，反之亦然。某些连接无法用子查询重新表述。特别是，**如果 `select` 列表包含来自多个表的列，则必须使用连接**（如果选择列来自同一表的不同副本，则必须使用自连接）。

例如，以下查询无法重新表述为子查询（结果表将包含哪些列？）：

```
select * from Country natural join Mountain
```

假设我们要发出查询：“列出每张记录了产品标题为 'Quinquo' 的发货的发票的客户编号、客户名称和发票编号。”您可能想在继续阅读前自行尝试用 SQL 编写此查询。

需要选择客户名称、客户编号和发票编号，但它们并不都出现在同一张表中。因此，我们必须在查询中包含连接，以便在结果表的同一行中将它们汇总在一起。
