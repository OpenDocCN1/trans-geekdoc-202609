
TCP/IP 的漏洞众多。各种操作系统中实现不当的 TCP/IP 协议栈容易受到缓冲区溢出、`SYN` 洪水攻击、各种拒绝服务 (DoS) 攻击、碎片攻击、超大数据包攻击、欺骗攻击、中间人攻击、劫持攻击和编码错误攻击。

TCP/IP（以及大多数协议）还容易受到通过监控或嗅探进行的被动攻击。网络监控是监控流量模式以获取网络信息的行为。数据包嗅探是从网络捕获数据包，希望从数据包内容中提取有用信息的行为。有效的数据包嗅探器可以提取用户名、密码、电子邮件地址、加密密钥、信用卡号、IP 地址、系统名称等。

数据包嗅探和其他攻击将在第 13 章中详细讨论。

## 域名系统

### 寻址与命名

寻址与命名是实现网络通信的重要组成部分。如果没有寻址方案，联网计算机将无法区分彼此，也无法指定通信的目标。同样，如果没有命名方案，人类将不得不依靠记忆和编号系统来标识计算机。记住 `Google.com` 比记住 `64.233.187.99` 容易得多。因此，大多数命名方案的设立是为了人类使用，而非计算机使用。

掌握基于 TCP/IP 网络中寻址和编号的基本概念非常重要。需要了解三个不同的层次。此处按逆序呈现，因为第三层是最基础的：

*   **第三层，即底层，是 MAC 地址。** MAC 地址，或称硬件地址，是一个“永久”的物理地址。
*   **第二层，即中间层，是 IP 地址。** IP 地址是一个“临时”的逻辑地址，分配在 MAC 地址之上。
*   **顶层是域名。** 域名或计算机名是一个“临时”的、面向人类的约定，分配在 IP 地址之上。

这一命名与寻址系统赋予每个网络组件所需的信息，同时使其对这些信息的使用尽可能简单。人类获得便于记忆的域名，网络协议获得便于路由的 IP 地址，网络接口获得物理地址。然而，这三种方案必须关联在一起，以实现互操作性。因此，开发了 `域名系统 (DNS)` 和 `ARP` 系统，分别用于在域名与 IP 地址之间、IP 地址与 MAC 地址之间进行互换或解析。`DNS` 将便于人类记忆的域名解析为其对应的 IP 地址。然后，`ARP` 将 IP 地址解析为其对应的 MAC 地址。如果定义了 `PTR` 记录，也可以通过 `DNS` 反向查找将 IP 地址解析为域名（详见本章后面的“域名系统”）。

`DNS` 是公共网络和私有网络中使用的分层命名方案。`DNS` 将 IP 地址与便于人类记忆的 `完全合格域名 (FQDN)` 关联起来。一个 `FQDN` 由三个主要部分组成：

*   **顶级域 (TLD)**—`www.google.com` 中的 `com`
*   **注册域名**—`www.google.com` 中的 `google`
*   **子域或主机名**—`www.google.com` 中的 `www`

`TLD` 可以是任意数量的官方选项，包括最初七个 TLD 中的六个——`com`、`org`、`edu`、`mil`、`gov` 和 `net`——以及许多较新的选项，如 `info`、`museum`、`telephone`、`mobi`、`biz` 等。还有被称为**国家代码**的国家变体。（有关当前 TLD 和国家代码的详细信息，请参阅 `www.iana.org/domains/root/db/`。）请注意，第七个原始 TLD 是 `int`（代表 international，国际），已被双字母国家代码取代。

注册域名必须在经批准的域名注册商处正式注册，例如 Network Solutions 或 1and1.com。

`FQDN` 最左侧的部分可以是单个主机名，如 `www`、`ftp` 等，也可以是多节的子域名标识，如 `server1.group3.bldg5.mycompany.com`。

`FQDN` 的总长度不能超过 253 个字符（包括点）。任何单个部分不能超过 63 个字符。`FQDN` 只能包含字母、数字和连字符。

每个注册域名都有一个指定的权威名称服务器。**主权威名称服务器**托管该域的原始区域文件。**辅助权威名称服务器**可用于托管区域文件的只读副本。**区域文件**是**资源记录**的集合，包含特定域的详细信息。有几十种可能的资源记录（详见 `en.wikipedia.org/wiki/List_of_DNS_record_types`）；最常见的记录列在表 11.6 中。

#### 表 11.6：常见资源记录

| 记录 | 类型 | 说明 |
| :--- | :--- | :--- |
| `A` | 地址记录 | 将 `FQDN` 映射到 `IPv4` 地址 |
| `AAAA` | 地址记录 | 将 `FQDN` 映射到 `IPv6` 地址 |
| `PTR` | 指针记录 | 将 IP 地址映射到 `FQDN`（用于反向查找） |
| `CNAME` | 规范名称 | 将 `FQDN` 别名映射到另一个 `FQDN` |
| `MX` | 邮件交换 | 将与邮件和消息相关的 `FQDN` 映射到 IP 地址 |
| `NS` | 名称服务器记录 | 指定授权名称服务器的 `FQDN` 和 IP 地址 |
| `SOA` | 起始授权记录 | 指定关于区域文件的权威信息，如主名称服务器、序列号、超时时间和刷新间隔 |

最初，`DNS` 由一个称为 **HOSTS 文件** 的静态本地文件处理。该文件仍然存在，但动态 `DNS` 查询系统已在很大程度上取代了它，尤其是在大型私有网络和互联网中。当客户端软件指向一个 `FQDN` 时，协议栈会发起一个 `DNS` 查询，以将该名称解析为可用于构建 IP 头部的 IP 地址。解析过程首先检查本地 `DNS` 缓存，以查看答案是否已知。`DNS` 缓存由本地 **HOSTS 文件** 的预加载内容以及当前启动会话期间执行的 `DNS` 查询（尚未超时的）组成。如果缓存中没有所需答案，则会向本地 IP 配置中指定的 `DNS` 服务器发送 `DNS` 查询。解析查询的过程既有趣又复杂，但其中大部分与 `(ISC)² CISSP` 考试无关。

`DNS` 在 `TCP` 和 `UDP` 端口 `53` 上运行。`TCP` 端口 `53` 用于区域传输。这些是 `DNS` 服务器之间的区域文件交换，用于特殊的手动查询，或当响应超过 512 字节时。`UDP` 端口 `53` 用于大多数典型的 `DNS` 查询。

**域名系统安全扩展 (DNSSEC)** 是对现有 `DNS` 基础设施的安全改进。`DNSSEC` 的主要功能是在 `DNS` 操作期间为设备之间提供可靠的身份验证。`DNSSEC` 已在 `DNS` 系统的很大一部分中实施。每个 `DNS` 服务器都会被颁发一个数字证书，随后用于执行相互证书认证。`DNSSEC` 的目标是防止一系列 `DNS` 滥用行为，即虚假数据被注入解析过程。一旦完全实施，`DNSSEC` 将显著减少针对服务器的 `DNS` 滥用行为。

### DNS 投毒

**DNS 投毒** 是伪造客户端用于访问目标系统的 `DNS` 信息的行为。它可以通过多种方式发生。每当客户端需要将 `DNS` 名称解析为 IP 地址时，可能会经历以下过程：

1.  检查本地缓存（其中包含 **HOSTS 文件** 的内容）。
2.  向已知的 `DNS` 服务器发送 `DNS` 查询。
3.  向任何可能的本地子网 `DNS` 服务器发送广播查询。（此步骤并未得到广泛支持。）

如果客户端无法从上述任何步骤获得 `DNS` 到 IP 的解析，则解析失败，通信无法发送。`DNS` 投毒可能发生在上述任何步骤中，但最简单的方法是破坏 **HOSTS 文件** 或 `DNS` 服务器查询。

攻击或利用 `DNS` 有多种方法。攻击者可能会使用以下技术之一：

### DNS 攻击与防御

#### 部署流氓 DNS 服务器（DNS 欺骗/药水攻击）

**部署流氓 DNS 服务器（也称为 DNS 欺骗或 DNS 药水攻击）。** *流氓 DNS* 服务器可以监听网络流量中的任何 DNS 查询或与目标站点相关的特定 DNS 查询。然后，流氓 DNS 服务器向客户端发送包含虚假 IP 信息的 DNS 响应。此攻击要求流氓 DNS 服务器在真实 DNS 服务器响应之前将其响应返回给客户端。一旦客户端收到来自流氓 DNS 服务器的响应，客户端就会关闭 DNS 查询会话，这会导致来自真实 DNS 服务器的响应被丢弃并作为会话外数据包被忽略。

DNS 查询未经过身份验证，但它们确实包含一个称为 *查询 ID* (QID) 的 16 位值。DNS 响应必须包含与查询相同的 QID 才会被接受。因此，流氓 DNS 服务器必须在虚假回复中包含请求的 QID。

#### 执行 DNS 投毒

**执行 DNS 投毒。** *DNS 投毒* 涉及攻击真实 DNS 服务器并在其区域文件中放置不正确的信息。这会导致真实 DNS 服务器向客户端发回虚假数据。

#### 篡改 HOSTS 文件

**篡改 HOSTS 文件。** 通过在客户端的 HOSTS 文件中放置虚假 DNS 数据来修改该文件，可将用户重定向到虚假位置。

#### 损坏 IP 配置

**损坏 IP 配置。** 损坏 IP 配置可能导致客户端拥有虚假的 DNS 服务器定义。这可以直接在客户端上完成，也可以在网络的 DHCP 服务器上完成。

#### 使用代理伪造

**使用代理伪造。** 此方法仅对 Web 通信有效。此攻击在客户端浏览器中植入虚假 Web 代理数据，然后攻击者运行流氓代理服务器。流氓代理服务器可以修改 HTTP 流量数据包，将请求重定向到黑客想要的任何站点。

尽管存在多种 DNS 投毒方法，但以下是一些基本安全措施，可大大降低其威胁：

*   限制从内部 DNS 服务器到外部 DNS 服务器的区域传送。这通过阻止入站 TCP 端口 53（区域传送请求）和 UDP 端口 53（查询）来实现。
*   限制内部 DNS 服务器拉取区域传送的外部 DNS 服务器。
*   部署 *网络入侵检测系统 (NIDS)* 以监视异常 DNS 流量。
*   妥善加固专用网络中的所有 DNS、服务器和客户端系统。
*   使用 DNSSEC 保护 DNS 基础设施。
*   要求内部客户端通过内部 DNS 解析所有域名。这将要求您阻止出站 UDP 端口 53（用于查询），同时保持出站 TCP 端口 53（用于区域传送）开放。

*与 DNS 投毒和/或 DNS 欺骗密切相关的另一种攻击是 DNS 药水攻击。* *药水攻击* 是将有效网站的 URL 或 IP 地址恶意重定向到托管原始有效站点虚假版本的假网站。这通常是网络钓鱼攻击的一部分，攻击者试图诱骗受害者泄露其登录凭据。如果潜在受害者不小心或不注意，他们可能会被诱骗向虚假的药水网站提供其登录信息。药水攻击通常通过修改系统上的本地 HOSTS 文件，或通过投毒或欺骗 DNS 解析来发生。药水攻击是一个日益严重的问题，因为黑客已经发现了利用 DNS 漏洞对大量目标用户进行各种域名药水攻击的方法。

#### 域名劫持

*域名劫持*，或 *域名盗窃*，是指未经合法所有者授权，恶意更改域名注册信息的行为。这可以通过窃取所有者的登录凭据、使用 XSRF、劫持会话、使用 MitM（有关这些攻击的介绍，请参见第 21 章“恶意代码和应用程序攻击”），或利用域名注册商系统中的缺陷来实现。

有时，当另一个人在原所有者注册过期后立即注册该域名时，这被称为 *域名劫持*，但这并不准确。这是一种潜在的不道德行为，但并非实际的黑客攻击或攻击。这是利用了原所有者未能手动延长注册或配置自动续费的疏忽。如果原所有者因未能维护注册而失去域名，通常别无选择，只能联系新所有者并询问能否重新获得控制权。许多注册商对过期注册采取“先到先得”政策。

当组织失去域名且其他人接管控制权时，这对组织及其客户和访问者来说都是毁灭性的事件。原网站或在线内容将不再可用（或至少无法在同一域名下访问）。新所有者可能会托管完全不同的内容，或托管前一个站点的虚假副本。这种后一种活动可能会欺骗访问者，类似于网络钓鱼攻击，从而提取和收集个人身份信息 (PII)。

域名劫持的一个例子是 2017 年 9 月 Fox-IT.com 域名被盗；您可以在 `www.fox-it.com/en/insights/blogs/blog/fox-hit-cyber-attack/` 阅读有关此次攻击的信息。

## 融合协议

*融合协议* 是将专用或专有协议与标准协议（如 TCP/IP 套件中的协议）合并。融合协议的主要优势是能够使用现有的支持 TCP/IP 的网络基础设施来托管特殊或专有服务，而无需部署替代网络硬件的独特部署。这可以带来显著的成本节约。然而，并非所有融合协议都能提供与其专有实现相同级别的吞吐量或可靠性。此处介绍了一些常见的融合协议示例：

### 以太网光纤通道 (FCoE)

**以太网光纤通道 (FCoE)** *光纤通道* 是一种网络数据存储解决方案（*存储区域网络 [SAN]* 或 *网络附属存储 [NAS]*），允许高达 128 Gbps 以上的高速文件传输。它设计为在光纤电缆上运行；后来增加了对铜缆的支持以提供成本较低的选项。光纤通道通常需要自己的专用基础设施（单独的电缆）。但是，可以使用 *以太网光纤通道 (FCoE)* 在现有网络基础设施上支持它。FCoE 用于在以太网网络上封装光纤通道通信。它通常需要 10 Gbps 以太网才能支持光纤通道协议。使用此技术，光纤通道作为网络层或 OSI 第 3 层协议运行，取代 IP 作为标准以太网网络的有效载荷。

### MPLS (多协议标签交换)

**MPLS (多协议标签交换)** *MPLS (多协议标签交换)* 是一种高吞吐量、高性能的网络技术，它根据短路径标签而非较长的网络地址跨网络传输数据。与可能非常复杂的传统基于 IP 的路由过程相比，此技术可节省大量时间。此外，MPLS 设计用于通过封装处理各种协议。因此，网络不限于 TCP/IP 和兼容协议。这使得许多其他网络技术得以使用，包括 T1/E1、ATM、帧中继、SONET 和数字用户线路 (DSL)。

### 互联网小型计算机系统接口 (iSCSI)

**互联网小型计算机系统接口 (iSCSI)** *互联网小型计算机系统接口 (iSCSI)* 是一种基于 IP 的网络存储标准。此技术可用于在 LAN、WAN 或公共互联网连接上实现位置无关的文件存储、传输和检索。iSCSI 通常被视为光纤通道的低成本替代方案。

### 互联网协议语音 (VoIP)

**互联网协议语音 (VoIP)** 是一种隧道机制，用于通过 TCP/IP 网络传输语音和/或数据。VoIP 有潜力取代或替代 PSTN（公共交换电话网），因为它通常成本更低，并提供更多种类的选项和功能。VoIP 既可用作计算机网络上的直接电话替代品，也可用于移动设备。然而，VoIP 能够支持视频和数据传输，以实现视频会议和项目远程协作。VoIP 有商业版和开源版两种选择。某些 VoIP 解决方案需要专用硬件，以替代传统电话听筒/基站，或允许这些设备连接到 VoIP 系统并在此系统上运行。某些 VoIP 解决方案仅基于软件，例如 `Skype`，允许用户现有的扬声器、麦克风或耳机替代传统电话听筒。其他解决方案则更多基于硬件，例如 `magicJack`，它允许将现有的 PSTN 电话设备插入通用串行总线 (USB) 适配器，以利用互联网上的 VoIP。通常，VoIP 到 VoIP 的通话是免费的（假设使用相同或兼容的 VoIP 技术），而 VoIP 到固定电话的通话通常按分钟收费。

## 软件定义网络 (SDN)

**软件定义网络 (SDN)** 是一种独特的网络运行、设计和管理方法。其概念基于这样一种理论：传统网络依赖设备上的配置（即路由器和交换机），其复杂性往往迫使组织坚持使用单一设备供应商（如 `Cisco`），并限制了网络响应不断变化的物理和业务条件的灵活性。SDN 旨在将基础设施层（即硬件和基于硬件的设置）与控制层（即数据传输管理的网络服务）分离。此外，这还消除了传统网络概念（如 IP 寻址、子网、路由等）需要被编程到托管应用程序中或由其解析的需求。

SDN 提供了一种新的网络设计，可从中心位置直接编程，具有灵活性、供应商中立性，并基于开放标准。使用 SDN 使组织无需从单一供应商采购设备。相反，它允许组织根据需要混合搭配硬件，例如选择最具成本效益或吞吐量评级最高的设备，而不受供应商限制。然后通过集中管理界面控制硬件的配置和管理。此外，应用于硬件的设置可根据需要动态更改和调整。

理解 SDN 的另一种方式是将其视为网络虚拟化。它允许数据传输路径、通信决策树和流控制在 SDN 控制层中虚拟化，而不是在硬件上按设备单独处理。

### 内容分发网络

**内容分发网络 (CDN)**，或内容交付网络，是部署在互联网上众多数据中心中的一组资源服务，旨在为托管内容提供低延迟、高性能和高可用性。CDN 通过分布式数据主机的概念，提供客户所需的多媒体性能质量。媒体内容不再存储在单一位置并传输到互联网的各个部分，而是分发到互联网上的众多位置。这导致了一种地理和逻辑负载均衡。没有单个服务器或服务器集群会因所有资源请求的负载而紧张，且托管服务器位于更靠近请求客户的位置。总体结果是更低的延迟和更高质量的吞吐量。有许多 CDN 服务提供商，包括 `CloudFlare`、`Akamai`、`Amazon CloudFront`、`CacheFly` 和 `Level 3 Communications`。

虽然大多数 CDN 侧重于服务器的物理分发，但基于客户端的 CDN 也是可能的。这通常被称为 `P2P`（对等网络）。最广为人知的 P2P CDN 是 `BitTorrent`。

## 无线网络
