
# 网络钓鱼

网络钓鱼是一种非常流行的社会工程学攻击。网络钓鱼骗局是一种短信或电子邮件活动，旨在制造恐惧、好奇或紧迫感。受害者随后被诱骗点击恶意链接、打开携带恶意软件的附件，或泄露敏感信息。

## 定向钓鱼

定向钓鱼是一种网络钓鱼骗局，但通常具有针对性。攻击者会选择特定的企业或个人。然后，他根据受害者的联系人、职位或特征精心制作特定信息。他冒充受害者，诱骗其同事或联系人泄露敏感信息。

## 点击劫持

攻击者构建一个诱人的页面，承诺给用户一次免费的夏威夷之旅。攻击者在后台检查受害者是否已登录其银行网站。如果已登录，攻击者会加载允许资金转账的页面，并利用查询参数将自己的银行凭据填入表单。资金转账页面被放置在礼物页面顶部一个不可见的 `<iframe>` 中。“确认转账”按钮精准地覆盖在“领取礼物”按钮上方。受害者访问该页面，天真地点击“预订我的免费行程”按钮。用户不知情的是，他们实际上点击了一个隐藏框架，也就是点击了“确认转账”，从而不知不觉地将钱款转给了攻击者。受害者随即被重定向到一个包含礼物详情的网页。他们仍然毫不知情刚刚发生了什么。

防范点击劫持攻击主要有两种方法：

### 客户端方法

`破框技术` 是此处最常用的方法。客户端方法有时有效，但容易被绕过，因此并非最佳方案。

### 服务端方法

`X-Frame-Options` 是最常用的方法。安全专家推荐使用这些方法。

### 使用 X-Frame-Options 响应头减少点击劫持

此方法指示浏览器是否有权在 `<iframe>` 或 `<frame>` 标签内显示页面。`X-Frame-Options` 头允许三个值：

*   `DENY`：任何域名都不能在框架内显示该页面。
*   `SAMEORIGIN`：仅当其他页面位于当前域名下时，该页面才能在其框架内显示。
*   `ALLOW-FROM URI`：仅允许在特定 URI 中以框架形式显示当前页面。

### X-Frame-Options 的局限性

*   `SAMEORIGIN` 选项不允许跨站点应用。
*   无法创建允许域名的白名单。
*   无法在单个页面上使用多个选项。
*   并非所有浏览器都支持 `ALLOW-FROM` 选项。
*   大多数浏览器已弃用 `X-Frame-Options`。

## 社会工程学防范

*   安装反恶意软件或杀毒软件并保持更新。
*   不要接受诱人的提议。
*   考虑使用多因素认证。
*   不要打开可疑的电子邮件或附件。

# 第 14 章：PCI DSS

**PCI DSS**（支付卡行业数据安全标准）是由美国运通、JCB 国际、发现金融服务、万事达卡和维萨卡于 2004 年制定的一系列安全标准。合规计划由 **PCI SSC**（安全标准委员会）管理，其目标是保护借记卡和信用卡交易免受欺诈和数据窃取。PCI SSC 无法在法律上强制合规，但所有处理借记卡或信用卡交易的企业都必须获得 PCI 认证。PCI 认证通过 PCI SSC 制定的要求来保护您企业的持卡数据。其中一些要求是众所周知的最佳实践，例如：

*   使用防病毒软件
*   加密数据传输
*   安装防火墙

此外，企业必须限制对持卡人数据的访问，并监控对所有网络资源的访问。当您的企业符合 PCI 标准时，客户可以确信其信息是安全的。此外，不合规带来的声誉和经济损失足以让任何企业重视数据安全。根据每年的借记卡或信用卡交易数量，PCI 合规分为四个级别。此分类决定了企业所需满足的要求。

**1 级**：适用于每年处理超过 600 万笔卡交易的商户。必须进行年度内部审计，且须由 PCI 审计师执行。他们还必须每季度接受一次 ASV（认证扫描供应商）的 PCI 扫描。

**2 级**：适用于每年处理 100 万至 600 万笔卡交易的企业。他们每年需要使用自评问卷 (SAQ) 进行一次评估。每季度进行一次 PCI 扫描也可能是必要的。

**3 级**：适用于每年处理 20,000 至 100 万笔交易的企业。必须使用适当的 SAQ 进行年度评估。他们可能需要接受每季度一次的 PCI 扫描。

**4 级**：适用于每年处理不超过 20,000 笔卡交易的企业。需要进行年度 SAQ 评估。他们也可能需要接受每季度一次的 PCI 扫描。

PCI SSC 制定了 12 项要求，在处理持卡人数据时必须遵守。这些要求分布在六大目标中。企业必须满足这些要求才能实现合规。

## 安全网络

*   必须建立并维护防火墙配置。
*   系统密码不应使用供应商提供的默认密码，而应设置为原创密码。

## 安全持卡人数据

*   保护存储的持卡人数据。
*   在所有公共网络上加密持卡人信息的传输。

## 漏洞管理

*   使用防病毒软件并定期更新。
*   开发并维护安全的应用程序和系统。

## 访问控制

*   必须限制对持卡人数据的访问。
*   拥有计算机访问权限的员工应被分配唯一 ID。
*   限制对持卡人数据的物理访问。

## 网络监控与测试

*   监控对网络资源和持卡人数据的访问。
*   定期测试安全流程和系统。

## 信息安全

*   维护一项涉及信息安全的政策。

# 第 15 章：后门攻击

后门攻击是一种恶意软件，它绕过正常的身份验证流程以访问网络。因此，攻击者获得了对应用程序中资源的远程访问权限。一旦实现这一点，实施者就可以远程发布系统命令，甚至更新恶意软件。攻击者通过利用 Web 应用程序中任何易受攻击的区域来实现后门安装。安装后，由于文件在大多数情况下高度隐藏，因此很难被检测到。Web 服务器后门可用于各种恶意活动，例如：

*   服务器劫持
*   高级持续性威胁 (APT) 攻击
*   感染网站访问者
*   发起 DDoS 攻击
*   数据窃取
*   网页篡改

后门通常通过远程文件包含 (RFI) 来安装。这是一种攻击载体，它利用动态引用外部脚本的应用程序中的弱点。在 RFI 情况下，引用函数会从远程主机下载一个后门木马。

黑客通常使用扫描器寻找目标；他们识别出具有过时或未修补组件且允许文件注入的网站。扫描器一旦成功，就会利用该漏洞将后门安装到底层服务器中。安装后，攻击者可以随时访问它，即使漏洞修补很久之后也是如此。在大多数情况下，后门木马注入分两步进行，以绕过限制上传超过特定大小文件的安全规定。第一步，安装一个投放器——这是一个仅用于获取较大文件的小文件。然后启动第二步，涉及将后门脚本下载并安装到服务器中。

## 后门 Shell 移除：挑战

后门不易根除。通常，检测是通过软件扫描器识别系统中已知的恶意软件签名来执行的。这种方法容易出错。后门 Shell 通过代码混淆和别名来隐藏。在其他情况下，会使用多层加密。检测绝非易事，因为许多应用程序是基于外部框架（使用第三方插件）创建的。有时这些插件内置了后门或漏洞。依赖基于签名和启发式规则的扫描器无法有效识别此类框架中隐藏的代码。

即使扫描器检测到了后门，使用典型的缓解策略也很难将其从应用程序中清除。如果后门在可重写内存中反复出现，情况尤其如此。

## 利用 Imperva 减少后门 Shell 攻击

Imperva 结合了经过验证的多种方法来阻止后门安装，以及检测和隔离任何现有的后门 Shell。Imperva WAF (Web 应用程序防火墙) 结合用户定义和默认安全规则，阻止 RFI 攻击感染您的应用程序。该 WAF 部署在您网络的边缘，在恶意请求与您的应用程序交互之前将其拦截。如果您已经拥有一台被攻陷的 Web 服务器，Imperva 拥有后门防护解决方案，可从您的系统中检测并清除 Shell。

# 第 16 章：ISO/IEC 27001

它也被称为 ISO 27001，是一项安全标准，规定了创建、跟踪和改进 ISMS（信息安全管理体系）的建议要求。ISMS 是一套管理和保护企业敏感信息的策略集合。服务提供商自愿采用 ISO 27001 以确保客户信息安全。必须由经认可的独立机构正式审核组织以确认合规性。与通过 ISO 27001 认证的服务提供商合作有诸多益处：

*   **风险管理**：ISMS 规定谁可以访问特定信息。降低了该信息被泄露的风险。
*   **信息安全**：ISMS 拥有信息管理协议，规定如何处理特定数据。
*   **业务连续性**：服务提供商的 ISMS 必须持续接受测试和改进，以保持 ISO 27001 合规性。这可以防止数据泄露。

ISO 27001 合规性对于建立信息安全治理政策至关重要。构建符合 ISO 标准的 ISMS 过程全面且包含支持、培训、规划和范围界定。在企业获得认证之前，必须解决几个重要要素。

## 组织环境

任何可能阻碍企业建立 ISMS（信息安全管理体系）的问题，无论是外部还是内部，例如信息安全、合同、法律和法规义务，都应被识别出来。上一步骤中获得的信息用于概述 ISMS 的范围，记录所有相关领域。在此之后，ISMS 将根据 `ISO 27001` 的要求被应用、维护并持续改进。范围展示了将 ISMS 融入管理流程和结构的重要性。成千上万的组织必须遵守这些要求。为了维护 ISMS，组织的管理层需要具备相关的领导技能。这些技能包括 ISMS 的持续改进、将 ISMS 融入组织的流程、根据业务方向制定信息安全策略等。ISMS 流程应包含应对信息安全风险的计划。这包括：

*   创建并实施详细的风险管理流程。
*   概述并实施降低威胁的流程。

组织需要获取资源、基础设施和人员，以有效实施 ISMS。支持通常涉及指导和培训员工如何处理敏感信息。员工还应被告知如何为使 ISMS 更有效做出贡献，以及如果不遵守信息安全策略会发生什么后果。

运营关乎执行上述步骤中定义的流程和计划。企业应记录所采取的行动，以确保流程按计划执行。绩效评估确保 ISMS 持续改进并继续有效运行。它还会寻找任何需要改进的领域。任何不符合项一经发现应立即处理。企业还应采取必要措施，确保问题不再复发。

# 第 17 章：恶意软件类型

恶意软件是由攻击者分发的恶意软件，旨在感染组织的网络或个人计算机。它利用目标系统中的漏洞，例如缺陷。恶意软件有多种类型，每种都有其关注领域和应用场景。最常见的七种包括以下内容。

当勒索软件被安装到计算机系统和/或整个网络中时，它会加密文件。攻击者通过弹出窗口告知用户，只有支付赎金才会解密文件。勒索软件通过可疑的下载或电子邮件附件进入计算机。

最初，蠕虫被设计用于感染系统、自我复制，然后通过另一种媒介感染其他计算机。黑客利用来自许多连接设备的蠕虫创建僵尸网络。蠕虫的示例包括：

*   **NgrBot**：它通过社交网站和聊天工具传播。
*   **ILOVEYOU**：这种蠕虫利用虚假的恋爱诱饵引诱人们。用户可能会被鼓励打开一封携带蠕虫的电子邮件。

特洛伊木马是一种伪装成合法软件的恶意软件。与蠕虫不同，它不会自我复制。然而，它包含其他类型的恶意软件，如间谍软件、勒索软件、Rootkit 和后门。特洛伊木马攻击倾向于针对银行业。通常，恶意软件通过软件漏洞安装在目标计算机上。当用户访问该网站时，一个伪造的屏幕会覆盖在原页面上，请求信用卡详细信息等个人数据。

Rootkit 是预先准备好且可定制的。它们提供对应用程序敏感区域的访问权限，更改系统配置，并启用文件执行。它们通常通过社会工程学攻击部署（这可能导致登录凭证被盗），一旦安装，黑客就能访问网络。这种恶意软件会颠覆所有反恶意软件软件——攻击者随后可以为所欲为。Flame 是一个 Rootkit 的绝佳例子。它被用于监控网络流量、记录按键和窃取屏幕截图。

后门绕过访问网络所用的正常身份验证流程。它总是作为有针对性的攻击的一部分被安装。攻击者研究受害者，通过社会工程学攻击窃取其登录凭证，从而获得对网络、系统或应用程序的访问权限。后门通常试图避免被检测到，攻击者利用它们建立命令控制中心。攻击者随后可以发起系统命令并远程更新恶意软件。黑客利用后门进行各种恶意活动，包括感染访问者的计算机、拒绝服务攻击和数据窃取。当攻击者想要执行 APT（高级持续性威胁）时，这也是他们采取的第一步。

广告软件是最古老的恶意软件类型之一。它是一种免费软件，会不断弹出大量广告。它不一定是恶意软件，但非常烦人——它至今仍然存在。

间谍软件在未经你同意的情况下收集你的个人数据并将其出售给第三方（攻击者）。

# 第 18 章：物联网安全

物联网是一个连接设备的网络。每个设备都有一个唯一标识符，可通过网络自动交换和收集数据。许多行业和领域使用物联网设备，例如：

*   **消费者应用**：一些物联网消费产品包括智能家居、智能手表和智能手机。
*   **商业应用**：这些包括传感器、智能追踪器和智能安防摄像头。
*   **政府应用**：这些包括追踪野生动物的设备、发布自然灾害预警的设备和监控交通拥堵的设备。

物联网设备的广泛使用为安全问题打开了大门，此处将详细讨论这些问题。物联网设备既受外部管理（与其他设备的交互），也受内部管理（软件维护）。每个设备都连接到一个命令与控制中心（C&C），这是管理单元。这些中心负责固件更新、配置和软件维护。它们还负责任务认证。物联网设备之间的通信通过 API（应用程序编程接口）进行。当设备的 API 被暴露时，其他应用程序或设备可以通过它收集数据并进行通信。

## 物联网安全问题与漏洞

API 和 C&C 中心能有效管理日常的 IoT 运营。由于它们本质上是中心化的，因此存在多个可被利用的弱点，例如：

*   未修补的漏洞：在大多数情况下，设备运行的是过时软件，因为最终用户需要手动下载更新，且存在连接问题。这使得它们容易受到新发现的威胁攻击。
*   弱认证：IoT 设备（如家用路由器）通常拥有易于破解的密码。这使它们成为黑客自动化脚本的易攻击目标。
*   易受攻击的 API：针对 API 的主要威胁包括分布式拒绝服务 (DDoS)、代码注入和中间人攻击 (MITM)。

这些危险可分为两类：对用户的威胁和对他人的威胁。

*   数据窃取：IoT 设备拥有大量数据，在大多数情况下，这些数据是用户独有的。数据可能包括信用卡详情、个人健康信息等。
*   人身伤害：IoT 设备在医疗领域越来越普遍。其中包括除颤器和起搏器。当这些设备受到干扰时，患者的医疗护理可能会受到负面影响。

易受攻击的 IoT 设备可能被渗透并用于僵尸网络。对于肇事者来说，发现无防护的设备并不困难。针对 IoT 设备的威胁变得更加复杂，这导致了大量网络攻击。有数十亿台 IoT 设备，因此其安全性应被高度重视。设备用户应遵循安全实践，例如阻止远程访问（如果不必要）和更改默认密码。

设备制造商和供应商应更加警惕并投资于 IoT 管理工具。他们应采取以下措施：

*   通知用户有关过时软件的信息。
*   强调智能密码管理。
*   禁用不必要的远程访问。
*   确保 API 具有严格的访问控制策略。
*   加强 C&C 中心的安全性。

# 第 19 章：域名服务器 (DNS) 劫持

DNS 劫持（或 DNS 重定向）是一种 DNS 攻击，其中 DNS 查询被错误解析，导致用户意外被重定向到恶意网站。为了实施攻击，攻击者可以在受害者的电脑上安装恶意软件、入侵/拦截 DNS 通信，或接管路由器。攻击者利用 DNS 劫持进行网络钓鱼或域名欺骗。许多 ISP（互联网服务提供商）也利用 DNS 劫持接管用户的 DNS 请求并收集统计数据。政府也利用 DNS 劫持进行审查——用户被重定向到政府授权的网站。

DNS 重定向主要有四种形式：

*   **本地 DNS 劫持**：肇事者在受害者的计算机上安装特洛伊木马恶意软件。然后篡改本地 DNS 设置，使受害者被重定向到恶意网站。
*   **路由器 DNS 劫持**：大多数路由器存在固件漏洞或默认密码。当攻击者接管路由器时，他可以覆盖 DNS 设置，从而影响所有连接到该路由器的用户。
*   **中间人 DNS 攻击**：肇事者拦截 DNS 服务器与用户之间的通信，然后提供另一个指向恶意网站的目标 IP 地址。
*   **流氓 DNS 服务器**：肇事者入侵 DNS 服务器并篡改 DNS 记录。结果，DNS 请求被重定向到恶意网站。

当攻击者将流量从合法网站重定向到恶意网站时，就会发生 DNS 欺骗攻击。DNS 欺骗可通过 DNS 重定向实施。例如，通过攻陷 DNS 服务器，攻击者可以欺骗合法网站，然后将用户重定向到其他恶意网站。缓存投毒也可用于执行 DNS 欺骗，而无需依赖 DNS 劫持。攻击者可以放入一个非法的 DNS 条目并投毒 DNS 缓存。该条目包含一个替代目标 IP。在缓存刷新之前，该域名将被解析到被欺骗的网站。

由于 DNS 名称服务器是非常敏感的基础设施，因此需要强有力的安全措施。黑客可能劫持它并用于执行 DDoS 攻击。

*   网络上的解析器：关闭任何不需要的 DNS 解析器。至于合法的解析器，确保它们位于防火墙后面，且无法从外部访问。
*   限制对名称服务器的访问：使用网络安全措施、防火墙、物理安全和多因素访问控制。
*   警惕缓存投毒：域名中的大小写和查询 ID 应随机化，并尝试使用随机源端口。
*   处理已知漏洞：攻击者总是在寻找易受攻击的 DNS 服务器。
*   解析器应与权威名称服务器分离：两者不应运行在同一台服务器上。
*   确保区域传输受到限制。

对于最终用户，安装杀毒软件、更改路由器密码和使用加密 VPN 通道等操作可保护他们免受 DNS 劫持。

## 网站所有者的缓解措施

应采取的步骤：

*   DNSSEC
*   客户端锁定
*   安全访问

# 第 20 章：跨站请求伪造 (CSRF) 攻击

CSRF（也称为会话劫持、Sea Surf 或 XSRF）是一种操纵 Web 浏览器在用户已登录的应用程序中执行非预期操作的攻击。当 CSRF 攻击成功时，用户和企业都会受到影响。它可能导致未经授权的资金转移、数据窃取（包括会话 Cookie）、密码篡改或客户关系受损。CSRF 通常通过社会工程学攻击执行，例如诱导用户向服务器发送伪造请求的链接或电子邮件。应用程序在攻击期间对毫无戒心的用户进行身份验证——这使得很难区分伪造请求和合法请求。
