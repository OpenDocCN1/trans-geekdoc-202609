## 技术演进（RFCs、ISO）

有没有想过谁负责互联网？有几个机构负责此工作。让我们从互联网学会（ISOC）开始。ISOC 负责互联网技术标准，并作为互联网信息和教育的全球清算中心。向 ISO 报告的实体包括互联网架构委员会（IAB）、互联网工程指导小组（IESG）、互联网工程任务组（IETF）、互联网研究指导小组（IRSG）、互联网研究任务组（IRTF）以及意见征求小组（RFC）组。

IAB 负责协议和标准并管理 IETF。IETF 的角色是监督技术文档的创建，这些文档指导互联网如何设计、使用和管理。这项任务很大一部分集中在创建 RFC 上，白皮书作为互联网的道路规则。RFC 描述了互联网技术实践的方法、行为和创新。当创建一个 RFC 时，它会被分配一个永不改变的编号。当发布新技术时，首先会创建一个新的 RFC 作为互联网草稿，然后最终确定为 RFC。此时，旧的 RFC 可能会过时。这一过程与 ISO 等其他组织不同。一些著名的 RFC 及其标题所示[表 8.1](#)。

国际标准组织（ISO）描述自己为一个由 162 个国家标准协会组成的网络，每个国家一个，在瑞士日内瓦设有秘书处，协调连接公共和私营部门的桥梁。

CASP 应该了解几个 ISO 文档。其中之一是 ISO 15408。ISO 15408 经过多年草稿后最初发布于 1997 年。它目前版本为 3.1，并广泛称为共同标准。共同标准的目的是为产品和系统需求提供一种通用的结构和语言。供应商希望描述他们的产品的功能，买家希望确保它们符合特定需求。共同标准最大的成就之一是它弥补了早期文档如 ITSEC 和 TCSEC 之间的差距。共同标准确保计算机安全产品的规范、实施和评估过程是以严谨且标准的方式进行的。因此，共同标准可以在全球范围内使用，并对更大的受众产生意义。[8.2] 给出了共同标准评估保证级别（EAL）的示例。

另一个值得审查的 ISO 文档是 ISO 27002。该标准被认为是一套信息安全管理实践。它源于 ISO 17799 和英国标准 7799。ISO 27002 被认为是一项管理指南，而非技术文档。您可以在 `www.27000.org/iso-27002.htm` 了解更多信息。ISO 27702 为负责领导、计划、实施和维护安全的人员提供了信息安全管理的最佳实践建议。ISO 27702 标准包含以下 12 个部分：

- **风险评估**：如何评估组织风险
- **安全策略**：管理方向和结构
- **信息安全组织构架**：信息安全的治理
- **资产管理**：信息资产的清和和分类
- **人力资源安全**：员工入职、调动和离开组织时的安全方面
- **物理和环境安全**：计算机设施的保护
- **通信和运营管理**：系统和网络中技术安全控制的管理
- **访问控制**：对网络、系统、应用程序、功能和数据访问权限的限制
- **信息系统的获取、开发和维护**：通过系统开发生命周期（SDLC）和标准化流程将安全性构建到应用程序
- **信息安全事件管理**：通过制定事件响应程序和流程，预测并妥善应对信息安全违露
- **业务连续性管理**：保护、维护和恢复关键业务流程和系统
- **合规性**：确保符合信息安全策略、法律和法规

## 态势感知

态势感知要求您对周围发生的事情保持关注，以便如何应对特定情况。今天，安全专业人员必须比以往任何时候都更加关注动态。IT 安全是什么，以及它随着技术进步如何持续演变。今天，我们对网络、计算机和技术的依赖远超过过去。这给许多人的日常生活带来了巨大进步，但也使得计算机犯罪和网络攻击的威胁增加。根据 `R40599.pdf` 中的国会研究报告，美国联邦调查局（FBI）估计，仅每年就有 100 万美国人成为身份盗窃的受害者。尽管他人对威胁程度意见不一，但趋势是不争事实的，即计算机犯罪正以前所未有的速度增长。态势感知要求 CASP 跟上最新的客户端攻击、攻击向量、新兴趋势和零日攻击。

### 最新客户端攻击

虽然服务器曾是攻击者的首要目标，但现在不再如此。今天，客户端攻击变得更加突出。原因之一是客户端系统是一个目标丰富的环境。客户端可能运行 Flash、Office、Acrobat、iTunes、Firefox、Java 等。这些程序中的每一个都为攻击者提供了一个潜在目标。互联网方面的交互性也大大增强，这为攻击者提供了针对基于 Web 应用程序的选择。最后一个原因是，现在的工具比过去多得多。今天，这些工具更易使用且随处可见。许多基于 Web 的客户端攻击在性质上是技术性的，但也利用了社会工程学。这些技术可以诱骗受害者点击链接或访问恶意网页。当受害者访问网页时，攻击者执行恶意代码，利用应用程序中存在的漏洞。客户端攻击的示例包括：

#### Cookie 窃取或操纵

Cookie 用于维护状态、跟踪用户在网站页面之间的移动，以及在跨多个请求/响应周期时跟踪用户。问题在于，Cookie 可能包含令黑客感兴趣的“肥肉信息”。某些 Cookie 持有用户名、密码或其他用于身份的数据。如果 Cookie 包含用于识别客户端的数据，那么对于攻击者来说，劫持会话或伪装客户端将具有极高价值。Reddit、LinkedIn 和 Digg 等许多 Web 2.0 网站使用 Cookie 来识别用户，这样用户每次访问账户时无需提供凭据。从态势感角度来看，每个人都需要理解，如果没有加密，他们的 Cookie 很容易被窃取。Cookie Cadger、Session Thief 和 Fireshape 等工具已被证明窃取这些 Cookie 是多么简单。图 8.6 显示了 Fireshape 用于获取 Facebook Cookie 的 JavaScript 代码，练习 8.4 展示了如何对 Cookie Cadger 进行基本操作。

核心漏洞在于，大多数网站加密了登录过程，但随后的请求在明文 URL 中带有用户的 Cookie。这些信息没有加密。如果网站加密整个用户会话，这就不会是一个风险。那么为什么网站不加密呢？原因可能是加密流量给运行网站的公司带来了更多的运营负担。对于高流量网站，它们需要昂贵的硬件来加速加密过程。另一个可能是加密也复杂化了来自合法执法机构请求的合法拦截。使用 Cookie Cadger 是获取 LinkedIn 等其他凭据的一种简单方法。运行该程序需要 winzip、Wiener 和 Java。

#### 练习 8.4 安装 Cookie Cadger

使用 Cookie Cadger 是获取 LinkedIn 等其他凭据的一种简单方法。

1. 从 `https://cookiecadger.com` 下载 Cookie Cadger 包。
2. 双击 Cookie Cadger JAR 文件并按照安装脚本运行。
3. 登录您的 LinkedIn 账户。
4. 观察 Cookie Cadger 窗口并注意 LinkedIn 凭据是如何被获取的。
