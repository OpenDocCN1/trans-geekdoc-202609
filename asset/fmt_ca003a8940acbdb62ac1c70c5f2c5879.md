## 14 智慧城市中无线多媒体传感器网络的相关性与可预测性

Raj Gaurang Tiwari, Pratibha, Sandip Vijay, Sandeep Dubey, Ambuj Kumar Agarwal and Megha Sharma

DOI: [`10.1201/9781003353034-14`](https://doi.org/10.1201/9781003353034-14)

### 14.1 引言

如今，无线传感器网络（`WSN`）上的多媒体应用需求巨大，在智慧城市时代已成为每个人日常生活中必不可少的一部分。由于 `WSN` 的某些局限性，如电池问题、安全问题、通信速度低等，多媒体传感器正受到研究人员越来越多的关注。最有利的是，多媒体传感器能够采集精美的视频、音频、图像和标量传感器数据，并通过传感器网络传输多媒体数据。

`WSN` 由多达数千个协同工作的传感器节点组成，它们利用物联网传感器在不同地点检测声音、运动、温度、振动、压力等变化条件 [1, 2]。`WSN` 在许多应用中表现良好，如目标跟踪、医疗应用、安全监控、栖息地监测等。在数据传输过程中，`WSN` 发生数据丢失的概率比有线网络更高。在有线网络中，数据丢失通常是由于拥塞问题；然而，在 `WSN` 中，导致数据丢失的原因有很多，如节点故障、栖息地接口、噪声、链路不可靠、意外损坏等 [3]。

由于传感器节点固有特性的局限性，`WSN` 上的通信并不十分可靠。而可靠性是面向质量的 `WSN` 的主要特征，由于具有较高误码率的无线链路普遍存在，实现可靠通信变得更加困难。由于多媒体应用需求（如时间约束、高带宽和可变的可靠性要求）的提出，还引入了一些更多挑战 [4, 5]。这些是勾勒通信协议以在传感器网络中实现熟练多媒体传输的关键因素。

图 14.1 显示了一个传统的 `WSN`。汇聚节点或基站位于网络和用户之间。通常，`WSN` 网络包含数千个传感器节点，所有传感器节点均可通过无线电信号轻松相互通信。这些节点配备了先进的计算和传感设备、电源组件和无线电收发器。当传感器节点发现高优先级事件时，会将包含图像的消息传输给汇聚节点 [6, 7]。紧急消息具有更高的重要性，要求最小的端到端延迟，而优先级较低的消息具有较大的端到端延迟。在接收端被延迟的数据将被丢弃，无法显示。因此，需要使用适合且便于多媒体通信、并能处理传感器节点所有限制的先进传输协议。

![图 14.1 传统无线传感器网络。](img/fig14_1.jpg)

图 14.1 传统无线传感器网络。

使用先进传输协议的主要目的是在 `WSN` 上实现更可靠、节能的实时多媒体数据传输，并实现网络的延长寿命周期。为了避免拥塞，还需要拥塞控制机制以获得更高质量的多媒体数据 [8]。

### 14.2 相关工作

实时多媒体传输在有线/无线网络/`WSN` 上已通过许多现有协议成为可能。有人提议使用实时传输协议（`RTP`）[9] 在基于 IP 的网络上传输多媒体数据。它不允许对流量进行分片或重组。由于 `RTP` 的高电力消耗，在 `WSN` 上实现 `RTP` 并非可行方案。

多流实时传输协议（`MRTP`）是对现有 `RTP` [10] 的改进。`RTP` 与多路径传输结合使用。`MRTP` 是一种面向会话的协议，可用于确定数据流。

针对 `WSN`，已经开发了许多用于传输多媒体数据的协议。为了实现 `WSN` 中的有效多媒体传输，Puga [11] 提出了面向传感器网络的多媒体分布式传输（`M-DTSN`）。该网络评估特定数据量的传输，并确定信道环境是否足以完成传输。`M-DTSN` 评估多种特性以实现有效传输。其中探讨的两个因素包括耗时的多媒体流以及用于传输的能效不高的传感器。因此，缺乏消除任何干扰所必需的**干扰控制机制**。

Zakaria 和 El-Marakby [12] 提出了一种名为 `AdamRTP` 的协议，它与 `MRTP` 具有可比性。`MRTP` 是一种为自组网设计的面向会话的协议，而 `AdamRTP` 是为 `WSN` 设计的。在 `MDC` 编码器的帮助下，`AdamRTP` 将多媒体源流分离成次要的自主流，并通过联合/不相交信道为每个流向接收点传输数据。

在 `WSN` 中，Qaisar 和 Radha [13] 提出了一种名为 `MMDR` 的协议，该协议采用三种技术来提高接收视频质量。源编码视频被划分为优先级流，视频包通过路径多样性路由，数据包部分解码。

许多协议（如 `MMDR`）包含可靠性机制，但不考虑**干扰控制机制**。在多媒体数据传输过程中，**干扰控制系统**对于降低能量消耗至关重要。未来，能效应成为 `WSN` 传输协议的主要标准，特别是针对多媒体数据，由于传感器节点寿命短，此类数据需要大带宽和实时低延迟。需要一种能够可靠传递消息、以最节能的方式控制拥塞并处理多媒体需求的传输协议。

传感器传输控制协议（`STCP`）、事件到汇聚点传输协议（`ESRT`）以及非对称可靠传输协议（`ARTP`）是一些同时关注可靠性和拥塞控制（`ART`）的协议。然而，它们确实存在一些缺陷和改进空间 [14]。

`STCP` [15] 的大多数功能都在基站实现。`STCP` 允许多个程序共享单个网络，并提供可靠的拥塞检测。拥塞信息的管理严重依赖数据包。`SenTCP` 存在若干性能问题，但 `STCP` 通过假设 `WSN` 中所有传感器节点都有时钟同步来解决这些问题。`STCP` 是一种广泛使用、可扩展且可靠的传输层协议。

`ESRT` [16] 协议是新型传输选项之一。`ESRT` 能够在消耗最少能量的情况下准确识别 `WSN` 中的事件。`ESRT` 的目的是管理源节点的报告发生，以在消耗最少能量的情况下提供所需的端到端一致性保证。

`ART` [3] 的主要特征是分布式拥塞控制、可靠查询传输和坚定不移的事件传输。关键节点（`E-节点`）是传感器节点的一个子集，它们以节能的方式覆盖全待感知区域，而非关键节点（`N-节点`）覆盖完整的待感知区域。如果没有干扰，`E-节点` 和 `N-节点` 都与汇聚点通信。`ART` 的缺点是，如果任何数据包因 `N-节点` 处的拥塞而丢失且未被识别，则无法保证恢复，因为 `E-节点` 管理双向可靠性和拥塞控制。

除了上述区块链、机器学习、增强现实和虚拟现实等最新技术在 4G/5G 网络上的智慧城市融合之外，如果没有快速数据和持续数据通信，这是不可能实现的。最新的几项贡献已经在无线多媒体传感器网络上设计并实现了智慧城市服务 [17, 18]。

### 14.3 传输协议

传输协议的工作是在应用层和网络层之间建立连接，以便数据能在源端和目标端之间可靠地传递；它还管理拥塞控制，并同步突然注入网络的大量流量。通常，大量实时数据与多媒体系统和源相结合。这导致需要高比特率来维持通信质量。因此，需要一种既能满足多媒体通信需求，又能兼容传感器节点特性的协议 [19–21]。

#### 14.3.1 可靠性机制

根据 `WSN` 应用的不同，可能需要不同级别的可靠性。在 `WSN` 中，通信发生在传感器节点和汇聚节点之间，应区分通信方向。在上行通信中，传感器节点是发送方，汇聚节点（传感器到汇聚点）是接收方，下行通信则反之 [22]。

#### 14.3.2 性能指标

为了评估任何传输层协议的性能，可以使用可靠性、拥塞和能效等指标。

##### 14.3.2.1 可靠性

上行（传感器到汇聚点）和下行（汇聚点到传感器）的可靠数据传输可满足可靠性指标（汇聚点到传感器）。`WSN` 有两种形式的可靠性：事件和数据包。

包可靠性定义为所有数据包的成功交付或成功率 [23]。事件可靠性定义为事件报告的成功 [24]。

```
\sum_{t = 1}^{T}\frac{Probability~of~success~of~m_{t}}{T}
```

其中 T 为总事件数，m 为消息，t 为事件，它是包含 t 的消息。

```
节点 j 的可靠性，[Rn(j)] = 汇聚点在 j 处接收的数据包数 / 在 j 处生成的总数据包数
```

##### 14.3.2.2 拥塞程度

```
d(j) = t_s^j / t_a^j
```

其中 d 为**干扰检测指标** [24]，`t_s^j` 为平均数据包服务所需时间，`t_a^j` 为节点 `j` 平均数据包到达间隔所需时间。

```
节点效率或平均投递率 = 节点 j 接收的数据包数 / 节点 j 前一节点接收的数据包数
```

##### 14.3.2.3 实时多媒体传输分析

由于传感器节点的能量非常受限，因此传输协议必须节省巨大的能量，以最大限度地延长系统寿命。在 `WSN` 中，由于比特错误或干扰，数据包丢失可能很频繁。

因此，

```
数据包丢失率 = 丢失的数据包数 / 感知节点产生的数据包数
```

假设丢弃的数据包与能量耗竭直接相关 [24]，

```
每个节点的能量损耗 [E(j)] = 节点 j 丢弃的总数据包数 / 节点 j 接收的总数据包数
```

###### 数学模型与公式

####### 网络能量损耗

$$E_{\text{network}} = \frac{\text{Total number of packets dropped by network}}{\text{Total number of packets received by the sink}}$$

####### 传感器节点剩余能量

$$E_r = \frac{\text{Remaining energy}}{\text{Initial energy}}$$

####### 数据包投递率

数据包投递率对于评估数据传输性能至关重要，因为由于干扰，数据包丢失可能发生在网络的任何步骤中。

$$\text{Packet delivery rate} = \frac{\text{No. of packets received by sink}}{\text{No. of packets generated by the source}}$$

####### 峰值信噪比 (PSNR)

“峰值信噪比 (PSNR)”用于确定解码器处视频序列的质量 [[25]](#chapter14.xhtml#ref14_25)：

$$\text{PSNR} = 20 \log \frac{255}{\sqrt{\text{MSE}}}$$

其中 `MSE` 是均方误差。

##### 14.3.2.4 根据数据类型进行数据传输

通常，大量实时数据与多媒体系统和源相结合 [[26]](#chapter14.xhtml#ref14_26)。由于这一需求，产生了高比特率以维持质量和应用。因此，需要一种既能满足多媒体通信需求，又兼容传感器节点特性的协议 [[27]](#chapter14.xhtml#ref14_27)–[[29]](#chapter14.xhtml#ref14_29)。

在 `MPEG` 服务器或视频编码器等多媒体数据流中，图像（“I、P 和 B 帧”）、视频和音频都被划分为帧。每一帧具有不同级别的可靠性。基于这一级别，数据通信仅限于图像传输。`PR-SCTP` 协议可用于实现一种新的建议传输协议，该协议提供各种级别的可靠性 [[30]](#chapter14.xhtml#ref14_30)。由于存在三种图像数据，数据通过三个流传输（参见 图 14.2）。
