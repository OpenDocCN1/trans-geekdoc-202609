
让我们从如何决定约翰尼喜欢哪些派的问题开始。输入由一组训练示例组成，每个示例由可用属性描述。输出——最终状态——是一个布尔表达式，对于训练集中的每个正示例为真，对于每个负示例为假。该表达式涉及属性-值对、逻辑算子（与、或、非）以及任何可能需要的括号组合。评估函数衡量给定表达式在训练集上的错误率。对于初始状态，可以使用任何随机生成的表达式。

## 1.4 诱导分类器的性能

到为止，我们通过比较训练示例的已知类别与分类器推荐的类别来衡量错误率。但从实践上来说，我们的目标并不是对已经知道类别的对象进行重新分类；我们真正想要的是标记那些我们尚不知道类别的未来示例。分类器在这些示例上的预期性能是通过实验估计的。了解这种方法非常重要。

### 独立测试示例

简单的场景是将可用的预分类示例分为部分：用于诱导分类器的训练集，以及用于评估分类器的测试集（图 1.6）。因此，在具有 12 个预分类示例的`pies`领域中，可以在随机选取的 8 个上进行诱导，并在剩下的 4 个上进行测试。如果分类器正确“猜”中了 3 个测试示例的类别（同时错了一个 1 个），则其性能估计为 75%。

尽管这种方法看起来合理，但它存在一个主要的缺点：随机选择的 8 个训练示例可能无法充分代表底层概念——这对于（甚至更小的）测试集来说也是如此。如果我们从一个由鲸鱼、海豚和鸭嘴兽组成的训练集中诱导哺乳动物的含义，学习者可能会被误认为哺乳动物生活在海里（鲸鱼、海豚），有时会生蛋（鸭嘴兽），这绝不是生物学家会接受的观点。然而，另一种训练示例的组合可能会产生一个符合最高标准的分类器。问题的点在于，不同的训练/测试集划分会产生不同的分类器——并产生对未来性能的不同估计。如果预分类示例的数量较少，这个问题会尤为严重。

假设我们想就其诱导出的产物质量比较两种机器学习算法。非代表性训练集的问题可以通过所谓的“随机子采样”来缓解。其想法是多次重复随机划分为训练集和测试集，始终从第`i`个训练集诱导分类器，然后测量第`i`个测试集上的错误率`Ei`。就分类而言，提供平均`Ei`较低分类器的算法被认为更好。

### 解释的必要性

在某些应用中，确定类别是不够的。知道其背后的原因同样重要。但如何找到解释呢？在`pies`领域中，可以从表达式中获得。相比之下，分类器是一个“黑箱”，它接受一个示例并返回标签，而不告知任何其他信息。在某些应用中，解释只是额外的奖励；而在另一些应用中，它是多余的。

### 替代方案的存在

顺便提一下，我们注意到从数据可以诱导出许多看起来完美的分类器。在`pies`领域中，训练集包含 12 个示例，其余示例的类别未知。通过一些简单的组合数学，我们意识到有`2⁹⁶`个可以正确标记训练示例的分类器——而另一个则会将它们全部分类错误。

## 1.5 数据中的一些困难

### 无关属性

首先，某些属性是重要的，而另一些则不然。虽然约翰尼可能真的很喜欢罂子酱馅饼，但他对派的偏好几乎不会取决于厨师的脚码大小。这是一个值得关注的问题：无关属性会增加计算成本；它们甚至会误导学习者。这些属性可以避免吗？

通常不能。诚然，在手动创建的领域中，专家应该知道哪些属性是真正重要的，但即使在此情况下，情况也并不简单。因此，“派类”领域的作者可能已经尽力挑选了她认为重要的属性。但由于对约翰尼口味背后的真实原因尚不确定，她可能包含了一些她怀疑其必要性但无法保证的属性。相关性问题更多地发生在从数据库中提取示例时。数据库的开发主要意图是提供对大量信息的访问——其中通常只有一小部分与学习任务有关。至于具体是哪一部分，我们通常一无所知。

### 缺失属性

相反，某些关键属性可能会缺失。考虑到父母的财务状况，约翰尼可能对昂贵的派产生偏见。属性`price`的缺失将导致无法导出良好的分类器：两个在可用属性上完全相同的示例，在关键的“缺失”属性值上可能不同。难怪尽管描述相同，一个示例是正样本，而另一个是负样本。当这种情况发生时，我们称该训练集是不一致的。这种情况有时很难避免：不仅专家可能不知道属性`price`的相关性；可能无法提供该属性的值，因此该属性根本无法使用。

### 冗余属性

损害较小的是冗余属性，即其值可以从其他属性获得。如果数据库包含患者的`date-of-birth`（出生日期）以及`age`（年龄），那么后者就是必要的，因为可以通过从今天的日期中减去`date-of-birth`来计算。幸运的是，冗余属性没有无关或缺失属性那么危险。

### 缺失属性值

在某些应用中，用户识别正确的属性选择没有问题。然而，问题在于某些属性的值是未。例如，分析员工数据库的公司可能不知道每个人的孩子数量。

### 属性：值噪声

由于信息来源不可靠、测量设备糟糕、拼写错误、用户的困惑以及许多其他原因，属性值和类别标签往往是不可信的。我们说数据遭受了各种噪声的影响。

随机噪声是随机的。例如，由于我们的体重在一天中会变化，我们早晨得到的读数与晚上的不同。人为错误也可能起作用：由于没有时间测量患者的血压，一名疏忽的护士简单地写下了上一次读数的修改值。相比之下，系统性噪声将所有值向同一方向移动。例如，校准不当的温度计给出的读数总是比应该的低。任意伪迹的情况下发生了另一种情况；在这里，给定的值与现实没有任何关系，例如 EEG 电极松动，从那时刻起，所有后续读数都为零。

### 类别标签噪声

类别标签面临着与属性类似的问题。专家推荐的标签可能没有被正确记录；或者，某些示例发现处于两个类别之间的“灰色地带”，在这种情况下，正确的标签是不确定的。这两种情况都代表随机噪声，后者可能只负面影响两个类别边界区域的示例。然而，类别标签噪声也可以系统性的：医生可能不愿意诊断罕见病，除非证据是压倒性的——那么他的类别标签更有可能是负样本而非正样本。最后，类别标签中的任意伪迹出现在由错误的自动化过程提供类别的领域。类别标签噪声可能比属性值噪声更危险。因此，在“圆类”领域中，位于正区域深处的示例即使属性值被轻微修改，也会停留在那里；只有边界示例会遭受“被送到边界之外”的影响。相比之下，类别标签噪声将使任何示例失效。

## 2.1 单属性情况

让我们从一个简单到不切实际的情况开始：每个示例都由单个属性描述的领域。一旦我们开发了基本原理，我们将将其泛化，以便用于更具实践性的领域。

基础知识可以使用上一章的玩具领域很好地解释。训练集包含十二个派（`Nall = 12`），其中六个是给定概念的正样本（`Npos = 6`），六个是负样本（`Nneg = 6`）。假设示例代表了真实情况，那么约翰尼随机挑选一个派的概率是 50%：

```
P.pos = Npos / Nall = 6 / 12 = 0.5
```

![image](img/image236.png)

现在考虑一个属性，例如填充大小。训练集包含八个具有厚填充的示例（`Nthick = 8`）。其中有三个被标记为正样本（`Nposidth = 3`）。这意味着“在填充大小=厚的情况下，一个示例为正样本的条件概率”为 37.5%——这就是厚填充示例中正样本的相对频率所意味着的：

```
P.pos|thick = Nposjthick / Nthick = 3 / 8 = 0.375
```

![image](img/image346.png)![image](img/image367.png)

### 将条件概率应用于分类

重要的是，相对频率是仅针对具有给定属性值的饼计算的。在这些相同的八块饼中，有五个代表负类，这意味着`P.neg thick/ = 5/8 = 0.625`。通过观察到`P.neg thick/ > P.pos thick/`，我们得出结论：约翰尼（Johnny）不喜欢厚馅饼的概率大于相反情况的概率。因此，分类器将所有`filling-size=thick`（填充物厚）的示例标记为“约翰尼喜欢的饼”的负实例是有有意义的。

![image](img/image112.png)![image](img/image114.png) 注意，条件概率`P.pos thick/`比先验概率`P.pos/`更值得信赖，因为它的计算中加入了额外信息。这是自然所然的。在一个男孩和女孩人数相等的托儿中心，我们预期随机选中的孩子是男孩的概率为`P.boy/ = 0.5`。但当我们听到有人叫那个孩子约翰尼时，我们就会增加这种预期，因为知道女孩起这个名字很常见。这就是为什么`P.boyjJohnny/ > P.boy/`。

### 联合概率

条件概率不应与两个事件同时发生的联合概率混淆。请确保使用正确的符号：在联合概率中，项之间用逗号分隔，`P.pos; thick/`；在条件概率中，用垂直线分隔，`P.pos thick/`。对于一个随机选取的饼，`P.pos; thick/` 表示该示例为正例且其填充物为厚厚的概率；而`P.pos thick/`指的是在所有`filling-size=thick`的示例中出现正例的概率。
