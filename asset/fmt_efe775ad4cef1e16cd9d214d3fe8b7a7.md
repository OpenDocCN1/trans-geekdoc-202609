
# Corda 平台概述

Corda 是一个用于 `CorDApps` 编写和执行的平台；这些应用程序通过添加新功能来增强全局数据库。这些应用程序定义新的数据类型和节点之间新的协议流程，以及所谓的 `smart agreements`（智能协议）来确定变更。Corda 愿景中值得注意的一点是，通过一个通用的、共享的、开放治理的网络，为许多公司、供应商、客户和第三方实现广泛的 CorDApps，以便在同一平台上管理庞大且多样的协议范围。Corda 押注于这样一个观点：通过更好的数据、更少的差异以及公司间更快的细节协调所产生的节约将是巨大的。此外，部署这种典型的业务架构将为现有和新供应商定义一个新平台，以竞争满足其客户的需求。各种 Corda 软件解决方案需要共享通用标准并就特定的通用参数达成一致，这与不太有用的远程、非互操作、独立部署形成对比 [[6]](#ch15.xhtml#r272)。

## Corda 平台的组件

Corda 平台具有各种元素，下文将对其进行讨论，以便更好地理解其工作背后的整体概念。以下是其主要组件：

*   **节点** 是 Corda 系统的一个软件部分，用于运行 `CorDApps`，并排列在一个经过身份验证的点对点网络中。

*   **Corda 网络** 是具有连接性的完全连接的点对点节点。所有通信都是直接的。因此，不提供全局广播或 Gossip 协议。通过传输层安全性 (TLS) 使用高级消息队列协议 (AMQP) 进行安全、可靠且异步的通信。网络映射上的服务列出对等节点，就像目录服务一样。

*   **状态** 是一个原子且不可变的对象，代表一个或多个 Corda 节点在特定时间点已知的事件。状态可以包含任意信息，这使得节点能够代表任何实体。任意数据可以是库存、债券、贷款、KYC 数据或身份信息等。状态是 `UTXO`（未花费交易输出）和 `DAG`（有向无环图）节点。只有“未花费”状态决定世界的当前状态。“已花费”状态是世界状态历史的组成部分之一。状态是独一无二的。此外，它们只能被消费或花费一次。分布式账本状态是所有网络节点持有的每个状态的聚合。因为没有中央账本，且并非所有节点都知道所有状态，所以从每个参与者的角度来看，整体账本是主观的。在大多数情况下，至少有两个不同的节点持有相同的状态。

*   **双边账本** 是一个保险库——一个数据库，用于跟踪并考虑其所知道的所有当前和历史状态，由网络上的每个节点持有。简单来说，它是从每个节点视角出发的账本，包含其已知的所有当前陈述（即非历史）的集合。

*   **交易** 定义现有状态的消费和输出，这些输出向现有状态添加新数据以生成新状态；因此，状态是原子的，因为它们要么完全完成交易，要么完全不影响交易。交易具有包含多个阶段的生命周期，但不存在部分完成的“进行中”交易；尽管它们具有包含多个阶段的生命周期。Corda 交易不像 SQL 交易或以太坊交易那样，传递命令和参数，由状态引擎“决定”新状态是什么。相反，它引用现有的输入和未来的输出。尚未被各方接受的交易被称为“提议交易”。发行交易可以向数据库添加新状态，而无需使用现有状态。此外，这些交易不是特定的（图 7.2）。

*   **合约** 定义状态的特定属性，而不是描述状态的创建。属性像清单一样限制允许的状态转换。因此，可以验证提议的状态转换。简单来说，合约规定了允许的状态转换规则和提议的状态交易。交易中的一方或多方提出世界的新状态，合约接受这个新状态。合约还指代法律条文——即争议推定可被法院接受的概念。状态包含对合约的引用，并提及允许其创建和消费或阻止它们的代码。重要的是要注意，在 Corda 平台上，状态、交易和合约是基本的数据和事务元素。

*   **命令** 是交易的元素，通过为交易提供意图来帮助指导解释。命令发出提议过渡状态的意图信号，以允许接收方对交易进行分类和考虑。智能合约也可以基于命令对其验证逻辑进行分支。特别是，命令通过指示交易目的、收集输入并列出使用其公钥签名所需的签署人，来对交易进行参数化。

*   **时间戳** 是断言，声称某事发生在给定的时间窗口内。窗口可以是开放或封闭的。分布式系统中没有真实的时间；只有许多不同步的时钟。因此，时间戳被定义为一个窗口，而不是一个精确的时间。

    对于智能合约代码的实现，合约逻辑应传达交易在时间线上的位置。这是通过时间戳实现的。时间戳的其他用途，如监管报告或用户界面中的事件排序，不需要任何义务。此外，即使它们与其他方观察到的时间不完全匹配，本地观察到的时间戳在某些情况下可能更可取。或者，如果需要时间线上的特定点且多方必须同意，则默认可以使用时间窗口的中点。虽然这可能与任何活动（如按键或口头共识）不完全一致，但通常很有帮助。

*   **附件** 是包含在交易中的 `.zip` 和 `.jar` 文件。附件可以由带有模板和参数的法律条文组成。它还包括交易信息文件，如货币定义、相应的状态定义、日历、财务信息以及合约代码。

*   **流程** 是轻量级进程，通过协调多步骤业务操作，帮助对等方就共享状态达成共识。换句话说，流程对监控交易状态发展的业务流程进行建模。流程必须包含适当的命令和所需交易参与者的列表，以授权智能合约，后者必须始终检查必要的签署人。流程可以被广泛复用，也可以即时创建。只要合约允许计划的状态变更，就可以立即生成针对特定情况的流程。流程的复杂度与涉及的参与方数量成正比。流程可以包含两方以上。例如，如果交易需要监管监督，流程将指示一个额外步骤来通知第三方——监管机构。

## 共识

**共识**是各方对共享状态获得确定性的过程。适用于 Corda 的共识机制有两个方面，即验证共识和唯一性共识。

### 公证服务

**公证服务**提供事件的可靠证据，类似于传统的公证人服务。简单来说，公证人维护一份关键的映射表，记录其输入状态及其交易。公证服务无需知晓状态和交易的内容。公证服务对交易唯一需要做的就是可靠地识别它。当节点将交易发送给公证服务时，可能发生两种情况之一。如果公证人的映射表包含任意一条状态，公证人将抛出异常。如果没有任何状态输入已被认定为已使用，公证人会将每条信息添加到映射表中，并对拟议交易进行签名。此过程提供了唯一性共识。可以要求公证人验证交易，以防止攻击者提交虚假交易发起可能的 DoS 攻击。在这种情况下，只有当其智能合约接受该交易时，公证人才会将其视为常规节点处理。

### 预言机

**预言机**是关于外部世界的可信信息来源。为了确立一种货币，各方可能同意使用第三方报价。该第三方被称为预言机。预言机通过其签名有效担保交易中包含的信息。它还可应请求提供有效信息，从而使节点更容易构建经预言机批准的交易。此外，为了增加隐私，可以使用默克尔树和默克尔证明仅向预言机传输所需的最少信息。这被称为**交易撕离** [6, 10]。

### Corda 智能合约

作为 CorDApps 合约代码的一部分，智能合约逻辑确保状态转换在约定规则下是有效的。在 Corda 中，智能合约是一个纯函数，用于接受或拒绝拟议交易，并由更具体、可复用的函数组成。对于拟议交易中的每种状态类型，这些函数中的一个都将针对每笔拟议交易执行，所有各方有义务同意——根据每种状态的规则——拟议交易是允许的。因此，只有当包含的状态在所有合约代码上达成一致时，交易才有效。交易提议者负责生成满足每个包含的状态对象约束条件的交易。

Corda 使用一种名为 **Kotlin** 的编程语言来编写其智能合约。Kotlin 是一种通用的、静态类型的编程语言，具有跨平台实现和类型推断功能。Kotlin 旨在完全兼容 Java，且基于 JVM 的 Kotlin 标准库版本即 Java 类库。同时，类型推断允许语法更加简洁。它主要为 JVM 设计，但也可编译为 JavaScript 或原生代码。得益于 JVM（Java 虚拟机）丰富的现有库和广泛的专业知识基础，以及行业标准的复用，金融机构能够在合约中复用其现有代码。标准化字节码使用户能够根据偏好，在合约语言设计中创新或复用知名语言 [6, 10]。

## Corda 的共识机制

Corda 中的共识有两个方面，如下所示：

*   共识的**交易有效性**方面确保各方能够确定拟议的定义输出状态的更新交易是有效的，方法是确保相关合约代码（必须是确定性的）通过拥有所有必需签名而成功验证。

*   共识的**交易唯一性**方面确保交易参与者能够确定正在考虑的交易是交易中输入的所有状态的唯一消费者。此外，它还确保不存在先前已达成一致的、使用了相同任何状态的其他交易。

然而，两笔有效交易可能同时存在，因此参与者需要一种方法来选择优先考虑哪笔交易。为此，在一组相互不信任的公证人参与者中需要一个观察者。许多人可以在同一网络中参与，同时拥有不同的特征和协议，这是 Corda 设计的一个独特功能。单个服务可以由许多相互不信任的节点通过拜占庭容错算法协调组成。

重要的是要注意，此类唯一性服务只能确认之前的状态是否被消耗；在这种情况下，它们不应证明交易的有效性 [4, 6, 10]。

## Corda 用例

随着区块链行业的快速扩展，企业对区块链在性能、安全性和用户友好性方面有更高的期望。Corda 是被认为能满足所有这些需求的平台之一。下一节讨论 Corda 的三个用例。所有这些用例都展示了 Corda 解决各种挑战的能力。

一个著名的 Corda 应用是在**医疗保健行业**。医疗保健行业认识到对区块链的需求，因为即使是最好的医疗系统也可能变得碎片化。欺诈增加、理赔处理延迟和患者护理不令人满意都是碎片化的后果。

医疗保健系统已将使用电子健康记录（EHR）作为重中之重。Corda 区块链将允许系统之间相互通信，并提供全面的患者健康历史，而无需第三方验证服务。医疗保健可将每条记录保存在带时间戳、可审计且不可篡改的账本中。

Corda 也常用于**建筑业务**，因为其身份识别、隐私和工作流特性使其成为此类操作的理想选择。在建筑领域，承包商定期将工作转包给分包商。Corda 调整网络上数据分布的能力对于创建最适合行业现有参与者的区块链解决方案至关重要。Corda 允许房地产开发商和承包商保存与其达成协议从事各项工作的对手方记录，并允许及时补偿这些方。Corda 还允许项目成员以统一且易访问的方式查看项目进度和达成的里程碑。此外，Corda 的状态和合约框架有助于定义共享规则和数据结构，以及这些数据结构将如何随时间演变。这将有助于防止参与者产生分歧和/或犯错。即使参与者通过同一网络连接，Corda 的按需知情数据分发也能防止其他方发现项目的具体细节 [18]。

Corda 区块链的分布式账本和透明度还可以帮助**金融公司**高效可靠地获取最新的消费者数据。因此，组织绩效、非自动化数据收集、运营费用和处理时间均有所降低，而机构信任度得到提高。交易终局性、可扩展性、隐私、法律认可的参与方、开发人员生产力和企业集成是 Corda 为金融机构提供的一些优势。

## Corda 中的用户隐私

### Corda 隐私保护方法

Corda 采用多种方法来提升用户隐私，优于其他分布式账本系统。在 Corda 中，交易不会像许多其他区块链系统那样全局广播。此外，Merkle 树被用于构建交易结构，并且可以向已经知道 Merkle 根哈希的各方揭示单个子组件。此外，各方可以在无法看到交易全貌的情况下对其进行签名 [4, 10]。节点上的密钥管理服务生成并使用与身份无关的随机密钥。涉及流动性资产的大型交易图可以通过要求资产发行方使用新的引用字段在账本上重新发行资产来进行“修剪”。虽然这不是一个原子操作，但它有效地将资产的新旧版本解耦，这意味着节点在验证期间不会尝试探索原始的依赖图 [6]。

Corda 的隐私保护侧重于利用安全硬件飞地对整个账本进行加密和验证。在发生故障时，它可以提供同态加密和零知识证明的优势，而无需牺牲可扩展性或可审计性。

## Corda 的局限性

Corda Network Foundation 为使业务网络能够注册而收取的高昂实施和运营成本，是阻碍全球 Corda 网络（网络的网络）自然和加速增长的关键障碍。虽然大型金融机构不会反对这些费用，但许多较小的业务网络可能会拒绝加入，因为成本将超过使用 Corda DLT 技术的收益。因此，采用全球 Corda 网络的成本可能会限制其未来增长。此外，这些成本壁垒可能导致使用 Corda 开源版本的商业网络与使用企业版本的商业网络之间产生无法弥合的鸿沟 [9]。

# 总结与结论

实施区块链的理念已从现代数字加密货币的底层技术演变为一类新的分布式和去中心化应用，它们能在无信任的点对点环境中有效运行。无信任、去中心化账本支持历史不可变性的特性，已成为许多行业实现安全和保障的日益流行的理念。

本章旨在简要介绍三种当前流行的区块链框架，即 Ethereum、Hyperledger 和 Corda。这些框架将区块链技术的优势应用于银行业、网络安全、审计、医疗保健、供应链管理、通信系统和物联网等当前业务流程中。如果有效利用，这些框架可以支持在数据分布式且去中心化的无信任环境中，保护网络、通信和数据的现有努力。要将这些区块链框架实施到任何特定的业务用例中，首先必须了解实施安全区块链网络的底层及相关机制和技术。

值得注意的是，这些框架在拥有所有隐私和安全特性的同时，也存在相关的漏洞和局限性。在考虑将本章讨论的任何框架应用于业务流程之前，必须研究其可行性。涉及信任、共识和不可变性顾虑的用例应探索区块链技术作为有前景的解决方案。否则，其他替代方案（如使用数据库技术）通常将证明更具成本效益。

# 核心概念

## 区块链平台概述

### 核心平台特性

*   **Ethereum** 的主要目标是通过使用一种加载且无歧义的语言定义状态变更系统，并设计一个合理预期协议将自主应用的系统，使同意的个人能够在无信任环境中与另一个同意的个人进行交易。

*   **Ethereum** 通过允许用户制定其个性化的所有权规则、状态转换函数和交易格式，赋予用户编写定制智能合约和去中心化应用的能力。

*   **Ethereum** 提供了一个打包在开放客户端中的通用可编程区块链，可供所有人使用。

*   目前，**Ethereum** 采用 `PoW` 共识协议，但已开始从工作量证明向权益证明过渡。与工作量证明不同，验证者不需要巨大的计算能力，因为他们是随机选择的，且不进行竞争。

*   **Hyperledger** 是一个开源项目，旨在推动区块链技术在不同行业的发展，致力于集体协作而非单打独斗。

*   **Hyperledger** 充当孵化器，帮助将来自全球各个领域和市场空间的开发者和用户聚集在一起。
