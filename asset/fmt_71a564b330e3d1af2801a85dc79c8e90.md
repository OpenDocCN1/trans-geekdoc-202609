# 第 2 章：领域 1：安全与风险管理

## 摘要

安全与风险管理是本章及 CISSP® 领域 1 的主题，其中包含许多至关重要的术语和概念，这些内容贯穿多个领域。本章介绍了 CIA 三要素——机密性、完整性和可用性，它们几乎涉及每个领域和章节。除了 CIA，本章还介绍了最小权限原则和知悉需要等概念。与风险管理相关的关键术语、概念和公式也在本章中呈现。`Risk`、`threat`、`vulnerability` 是必须理解的基本术语，以便在该领域取得成功。理解如何使用 `Annualized Loss Expectancy (ALE)`（年度损失期望值）、`Single Loss Expectancy (SLE)`（单次损失期望值）、`Annualized Rate of Occurrence (ARO)`（年度发生率）和 `Exposure Factor (EF)`（暴露因子）进行计算，被作为定量风险分析的一部分重点强调。与信息安全治理相关的重要概念，如隐私、应有注意、应有尽责、认证和授权，也是本章的重点。

*   **完整性**——旨在防止信息未经授权的修改。换句话说，完整性旨在防止对数据的未授权写入访问。完整性还旨在确保以授权方式写入的数据是完整且准确的

## 简介

作为信息安全专业人员，我们的工作是评估针对关键 `assets`（资产）的 `risks`（风险），并部署 `safeguards`（保障措施）以缓解这些风险。我们在各种角色中工作：防火墙工程师、渗透测试员、审计员、管理层等。共同的主线是风险：它是我们职位描述的一部分。

安全与风险管理领域侧重于风险分析和缓解。该领域还详述了安全治理，即成功的信息安全计划所需的组织架构。在这一领域，成功与失败的组织之间的区别，通常不取决于资金或员工规模：而是取决于将合适的人放在合适的岗位上。拥有支持并投入其中的领导层的、知识渊博且经验丰富的信息安全员工是成功的关键。

说到领导层，学会说领导层的语言是你在该行业取得个人成功的另一关键。能够用 C 级高管听得懂的语言有效沟通信息安全概念，是一种罕见且急需的技能。本领域将通过讨论 `Total Cost of Ownership (TCO)`（总拥有成本）和 `Return on Investment (ROI)`（投资回报率）等风险术语，帮助你掌握他们的语言。

### 机密性、完整性和可用性

`Confidentiality`（机密性）、`Integrity`（完整性）和 `Availability`（可用性）被称为“CIA 三要素”，是信息安全的基石概念。如图 2.1 所示，该三要素构成了信息安全赖以建立的“三脚凳”。首字母缩写的顺序可能会变化（有人偏好用“AIC”，或许是为了避免与某情报机构产生联想），这并不重要：理解每个概念才是关键。本书将使用“CIA”这一缩写。

#### 机密性

机密性旨在防止信息未经授权的披露：它保持数据秘密。换句话说，机密性旨在防止对数据的未授权读取访问。机密性攻击的一个例子是窃取 `Personally Identifiable Information (PII)`（个人身份信息），如信用卡信息。

数据必须仅对具有许可、正式访问批准和知悉需要的用户可访问。许多国家都希望保守其国家安全信息秘密，并通过确保到位的机密性控制来实现这一目标。

大大小小的组织都需要保持数据机密。美国的一项法律《健康保险流通与责任法案》（HIPAA）要求医疗服务提供者对患者的个人和医疗信息保密。你能想象如果患者的医疗和个人数据以某种方式泄露给公众，会对医疗机构造成多大的潜在损害吗？这不仅会导致信心丧失，还可能使医疗服务提供者面临患者或政府监管机构可能采取的法律行动。

#### 完整性

完整性旨在防止信息被未授权修改。换句话说，完整性旨在防止对数据的未授权写访问。

完整性分为两种类型：数据完整性和系统完整性。数据完整性旨在保护信息免受未授权修改；系统完整性旨在保护系统（如 Windows Server 2022 操作系统）免受未授权修改。如果一名不道德的学生入侵大学成绩数据库以提高其不及格的成绩，则他违反了数据完整性。如果他在系统上安装恶意软件以允许未来的“后门”访问，则他违反了系统完整性。

#### 可用性

可用性确保在需要时信息可用。系统需要可用（可用性）以供正常业务使用。针对可用性的攻击示例是 `拒绝服务` (DoS) 攻击，其旨在拒绝系统的服务（或可用性）。

### 概念间的张力

机密性、完整性和可用性有时相互对立：将数据锁在保险箱里并扔掉钥匙可能有助于机密性和完整性，但会损害可用性。这是错误的答案：我们作为信息安全专业人员的使命是平衡机密性、完整性和可用性的需求，并根据需要进行权衡。信息安全新手的一个明显标志是向问题抛出所有机密性和完整性控制，而不解决可用性问题。正如图 2.3 所示，妥善平衡这些概念并非易事，但值得做的事情很少是容易的。

### 泄露、篡改和破坏

CIA 三要素也可用其对立面来描述：`泄露`、`篡改` 和 `破坏` (DAD)。泄露是信息的未授权发布；篡改是数据的未授权修改；破坏是使系统或数据不可用。虽然 CIA 缩写中各个组成部分的顺序有时会变化，但 DAD 缩写按该顺序显示。

## 身份与认证、授权和审计 (AAA)

术语“AAA”常用于描述基石概念 `认证`、`授权` 和 `审计`。AAA 缩写中遗漏了 `标识`（在实现其余三个“A”之前需要先完成标识）。

### 身份与认证

身份是一种声称：如果你的名字是“X 先生”，你通过说“我是 X 先生”来标识自己。仅凭身份是薄弱的，因为没有证明。你也可以通过说“我是 Y 先生”来标识自己。证明身份声称称为认证：你对身份声称进行认证，通常通过提供只有你拥有的信息或对象，例如数字世界中的密码，或物理世界中的护照。

当你在机场办理登机手续时，票务代理会询问你的名字（你的身份）。你可以随便说任何名字，但如果你撒谎，很快就会面临问题：代理会要求你出示驾照或护照。换句话说，他们将寻求认证你的身份声称。

图 2.4 显示了身份与认证之间的关系。用户 Deckard 登录到 [ericconrad.com](http://ericconrad.com) 的电子邮件账户。他在用户名框中输入“deckard”；这是他在系统上的身份。请注意，Deckard 可以在用户名框中输入任何内容：仅凭标识是薄弱的。它需要证明，即认证。Deckard 随后输入密码“R3plicant!”这是 [ericconrad.com](http://ericconrad.com) 上用户 Deckard 的正确密码，因此 Deckard 的身份声称得到证明，他成功登录。

![图 2.4 标识和认证。](img/f02-04-9780443187346.jpg)

图 2.4 标识和认证。

身份必须唯一：如果两名员工都叫 John Smith，他们的用户名（身份）不能都是 jsmith：这会损害审计。共享账户（身份）也会损害审计：策略应禁止共享账户，并应开展安全意识培训以教育用户了解这一风险。

理想情况下，用户名应为非描述性的。示例用户名“jsmith”是一个描述性用户名：攻击者只需知道用户的真实姓名即可猜测出用户名。这将提供发起成功密码猜测攻击所需信息的一半（有效身份），另一半是 jsmith 的密码（认证所需）。非描述性身份“bcon1203”将使密码猜测攻击（以及许多其他类型的攻击）更加困难。

### 授权

授权描述了在你被标识和认证后，可以在系统上执行的操作。操作可能包括读取、写入或执行文件或程序。如果你是拥有人力资源数据库公司的信息安全经理，你可能被授权查看自己的数据，或许还有一些员工的数据（如累计病假或休假时间）。你将无权查看 CIO 的薪水。

图 2.5 使用 Ubuntu Linux 系统展示了授权。用户 Deckard 已标识并认证自己，并登录到系统。他使用 Linux `cat` 命令查看“sebastian-address.txt”的内容。Deckard 被授权查看此文件，因此权限被授予。随后 Deckard 尝试查看文件 `/etc/shadow`，该文件存储用户的密码哈希值。Deckard 无权查看此文件，因此权限被拒绝。

![图 2.5 Linux 文件授权。](img/f02-05-9780443187346.jpg)

图 2.5 Linux 文件授权。

### 审计

审计要求用户对其行为负责。这通常通过记录和分析审计数据来完成。强制执行审计有助于让“诚实的人保持诚实”。对某些用户而言，仅知道数据被记录不足以提供审计约束：他们必须知道数据被记录和审计，且违反 `策略` 可能导致 `制裁`。

医疗公司 Kaiser Permanente 执行了审计，因违反策略（并可能违反 HIPAA 等法规）在不知情的情况下查看 Nadya Suleman（即“八胞胎妈妈”）的医疗记录，解雇或惩戒了 20 多名员工。详见 [`www.scmagazine.com/news/security-news/octomoms-hospital-records-accessed-15-workers-fired`](https://www.scmagazine.com/news/security-news/octomoms-hospital-records-accessed-15-workers-fired)。仅记录数据是不够的：识别违规行为并制裁违规者也是必需的。

## 不可抵赖性

`不可抵赖性` 意味着用户无法否认（抵赖）已执行的事务。它结合了认证和完整性：不可抵赖性认证执行事务用户的身份，并确保该事务的完整性。你必须同时具备认证和完整性才能拥有不可抵赖性：证明你签署了购车合同（认证你作为购买者的身份）若汽车经销商可将价格从 20,000 美元改为 40,000 美元（违反合同完整性），则毫无用处。

## 最小权限和需知原则

### 最小权限与知悉必要性

*最小权限*意味着用户应仅被授予完成其工作所需的最低访问权限（授权），而不得更多。*知悉必要性*比最小权限更细粒度：用户在访问特定信息前，必须具有知悉该特定信息的业务需求。

塞巴斯蒂安是一名护士，在一家拥有多个诊所的医疗机构工作。他的诊所共有四名医生，塞巴斯蒂安可以为这四名医生中的任意一位诊治患者。最小权限可允许塞巴斯蒂安访问这四名医生患者的记录，但不允许访问其他诊所其他医生患者的记录。

知悉必要性意味着塞巴斯蒂安只有在有业务需要时，才能访问患者的记录。如果有一名患者由塞巴斯蒂安所在诊所诊治，但并非由塞巴斯蒂安本人诊治，最小权限可能允许访问，但知悉必要性则不允许。

#### 举例学习

##### 现实世界中的最小权限

一家大型医疗服务提供商拥有一支 60 人的 IT 团队，负责管理 4000 台运行 Microsoft Windows 的系统。该公司未实施最小权限：整个 IT 团队均被授予了 Windows 域管理员访问权限。拥有此类权限的人员包括服务台人员、备份管理员等众多角色。所有 60 名域管理员在所有 4000 台 Windows 系统上均拥有超级用户特权。

这种权限级别过高，并导致了问题。操作错误导致了 CIA（机密性、完整性、可用性）原则被违反。由于人人都能做太多事情，环境破坏频发。数据丢失；发生未授权更改；系统崩溃，且难以定位原因。
