
# 网络攻击与防御概述

网络攻击与其他任何雄心勃勃的事业一样，必须经过精心策划和精确执行才能成功。根据行业研究，高级攻击在被发现前，平均会在组织系统中潜伏 200 天。在此期间，攻击者一直在收集数据、绘制网络拓扑图并监控通信。如果你能从攻击者的角度理解他们为成功实施攻击所采取的步骤，那么你就可以防止此类事件发生在你的组织身上，或者缩短发现攻击所需的时间。

## 攻击阶段

### 侦察
侦察意味着在行动前先摸清情况。黑客首先确定一个薄弱的目标，然后想出最佳的利用方式。他们了解组织架构，寻找任何薄弱环节的员工，并决定是攻击第三方还是公司网站。任何人都可能成为初始目标。攻击者只需要一个切入点。一旦黑客确定了目标，他们就会寻找能够获得访问权限的弱点。他们通过使用互联网上的扫描工具检查组织网络来实现这一点。这个过程可能需要一些时间。

### 访问与权限提升
一旦他们发现了网络中的漏洞，就会进行访问和权限提升，在不被发现的情况下访问网络并在其中横向移动。在这种情况下，他们需要特权访问以便自由移动。诸如彩虹表之类的工具可以帮助黑客窃取凭证并获得管理员权限。然后他们可以通过管理员账户访问任何系统。有了提升的权限，入侵者基本上就接管了网络，现在“拥有”了该网络。

### 数据窃取与破坏
凭借在网络中自由移动的能力，黑客可以访问组织系统中最敏感的数据并将其窃取。他们可能不仅对窃取私有数据感兴趣——如果他们愿意，还可以删除或更改文件。

### 维持访问
他们的下一步是在网络中悄无声息地潜伏。他们可能会决定安装 Rootkit 和其他恶意程序，以便随时返回。既然他们已经拥有了提升的权限，就不再依赖单一的切入点。

### 攻击阶段
并非每次网络攻击都会进入攻击阶段。在这个阶段，情况可能会变得非常糟糕。入侵者可能会更改硬件功能，甚至完全禁用硬件。

### 踪迹混淆
在这一步中，攻击者可能不再保持安静。有时，黑客会想掩盖踪迹，而其他时候，他们可能决定留下“签名”。踪迹混淆旨在使取证检查过程迷失方向、感到困惑并偏离正轨。踪迹混淆涉及的一些工具和技术包括特洛伊木马命令、僵尸账户、骨干网跳转、错误信息、欺骗和日志清理工具。根据 Mandiant 的数据，约 97% 的组织至少被攻破过一次。防御网络攻击最有效的方法是控制特权访问。

# 第 7 章：事件响应

在 Web 应用安全领域，事件是指对应用安全策略的尝试性违反或实际违反。篡改网站内容、数据窃取、未授权访问尝试、漏洞利用和网络入侵都是典型例子。事件响应是对此类威胁的缓解或预防。企业会采取有组织的方法来帮助他们改善网络防御并阻止安全漏洞。

这通过以下方式实现：

*   找出应用的薄弱环节。
*   加强针对威胁的安全参数。
*   保护对应用所有敏感部分/数据的访问。

即使尝试未成功，将其视为事件处理仍然是明智之举。

## Web 应用防火墙 (WAF) 的角色

Web 应用防火墙（`WAF`）是事件响应策略中非常重要的一部分。了解它们的用法有助于你制定高效的事件响应策略。该生命周期可分为三个阶段：准备阶段、检测/分析阶段和事件后活动阶段。在每个阶段，`WAF` 技术扮演不同的角色。

### 准备阶段
准备阶段是一个两部分的过程。它涉及建立安全配置并测试应用是否存在弱点。你可以采取以下几个步骤来准备应对威胁，同时保护应用的敏感区域：

*   **部署 WAF**：`WAF` 对传入流量进行分析，并阻止所有针对应用层的攻击尝试。一些 `WAF` 甚至可以保护应用免受零日攻击。
*   **设置访问控制策略**：识别并保护包含敏感信息的应用和网站部分。这通过 `2FA`（双因素认证）完成。它提供额外的访问控制。
*   **安全编排**：通过简化安全措施来开发一个连贯的工作流。例如，重新定义每个安全团队成员的任务和角色。
*   **弱点测试**：通常使用渗透测试来测试你的应用，以查看是否有任何可以被入侵者利用的软肋。然后进行调整以修补已识别的软肋。

### 检测/分析阶段
一旦部署，安全措施就会分析和过滤所有传入的 Web 流量。如果检测到任何事件，它们会阻止恶意请求、发出警报，并将有关威胁的所有详细信息记录在称为事件检测分析的综合安全日志中。

日志包括：

*   犯罪者的地理位置和 IP 数据。
*   攻击向量。
*   入侵者的 HTTP 指纹。
*   尝试进入的页面。

当你拥有安全事件的详细描述时，你就可以理解它并制定适当的响应。

### 事件后活动阶段
事件后活动是整个过程的最后阶段，致力于利用前几个阶段学到的经验教训。它包含三个部分：

*   审查日志，以确定事件是否暴露了任何软肋。
*   更改 `WAF` 规则并制定新策略以消除弱点。
*   测试新规则。

“冲洗并重复”是一个持续的过程。每个事件都是一个学习机会。它将帮助你提高企业的安全性并增强准备程度。

# 第 8 章：DNSSEC

# DNSSEC（域名系统安全扩展）

`DNSSEC` 是一套增强 `DNS`（域名系统）安全性的扩展，通过确认结果未被篡改来保障安全。`DNSSEC` 可帮助企业加强其 `DNS` 安全性。`DNS` 欺骗是针对 `DNS` 基础设施攻击的一个典型案例。攻击者劫持 `DNS` 解析器的缓存。当用户访问该网站时，他们会收到错误的 IP 地址，从而查看攻击者的恶意站点，而非合法站点。组织可使用 `DNSSEC` 保护其 `DNS` 服务器中的定义和敏感数据。主机信息、邮件交换服务器详情和 IP 地址均属于 `DNS` 中的数据示例。`DNSSEC` 保护这些数据。它还可阻止通过 `DNS` 进行的数据渗漏。`DNSSEC` 旨在确保名称服务器发送给客户端的回复是真实的。这是通过数字签名技术实现的。加密签名被添加到 `DNS` 记录中，从而保护发布在 `DNS` 中的信息。`DNSSEC` 为 `DNS` 定义了新的资源记录类型，以增强数字签名验证。

*   **资源记录签名 (`RRSIG`)**：包含特定记录集的加密签名。
*   **DNSKEY 记录**：包含用于 `DNS` 认证过程的公钥。
*   **DS（授权签名者）记录**：公共 `DNSKEY` 的指纹，保存在父区域中。
*   **NSEC（下一条安全记录）**：利用 `DNSSEC` 排序顺序提取下一个有效的记录名称。因此，`DNS` 解析器可证明某 `DNS` 记录不存在。
*   **NSEC3**：通过在区域中对所有记录名称进行加密哈希，克服了 `NSEC` 遍历的潜在风险。

## NSEC3 参数 (`NSEC3PARAM`)

它为 `DNS` 服务器提供参数，以确定针对不存在名称的 `DNSSEC` 请求响应中将包含的 `NSEC3` 记录。`DNSSEC` 可验证 `DNS` 请求，因此有助于降低 `DNS` 欺骗风险。但它并不解决利用 `DNS` 服务器的 `DDoS`（分布式拒绝服务）攻击。事实上，它可能会放大攻击效果。`DNSSEC` 包含额外的加密信息和字段来验证记录，因此针对 `DNS` 问题发送的回复数据包更大。大响应使攻击者能获得更大的攻击流量。

## DNSSEC 验证流程

`DNSSEC` 验证流程包含以下阶段：

1.  用户输入 URL 地址。
2.  浏览器查询本地计算机的 `DNS` 解析器以确定主机名的 IP 地址。
3.  若 IP 地址在解析器缓存中，则直接反馈给浏览器。
4.  若未找到，请求被传递给递归解析器。
5.  若递归解析器有该地址，则返回它。
6.  若没有，则启动递归查询以确定持有所请求域名权威信息的 `DNS` 服务器。
7.  首先联系根 `DNS` 服务器，它将解析器引荐给该域名的 `TLD`（顶级域）`DNS` 服务器。
8.  解析器随后被 `TLD DNS` 引荐给权威名称服务器。
9.  在所有阶段中，解析器都会请求与 `DNS` 区域关联的 `DNSSEC` 密钥，以验证服务器的真实性。
10. 解析器将验证 `RRSIG` 并确认其在传输过程中未被篡改。

# 第 9 章：反射型跨站脚本（XSS）攻击

Web 应用程序的一种漏洞，允许入侵者将代码注入到外部网站的内容中，这被称为跨站脚本攻击（`XSS`）。当有人访问该网站上被感染的页面时，代码会在其浏览器中执行。因此，入侵者绕过了浏览器的“同源策略”，并可访问受害者的私密信息。

## 反射型 XSS 攻击

**反射型 XSS 攻击**，也称为非持久性攻击。当恶意脚本从 Web 应用反射到受害者的浏览器时发生。脚本通过链接激活。发送一个带有漏洞的请求到网站，从而使恶意脚本得以执行。此漏洞通常由未充分清理传入请求引起，这使 Web 应用程序的功能面临被操纵的风险。攻击者将恶意链接嵌入第三方网站或电子邮件以进行分发。链接提示用户点击，从而发起 `XSS` 请求。

反射型攻击与存储型攻击的区别在于：后者要求攻击者寻找允许注入恶意脚本的网站；而反射型攻击中，脚本嵌入在链接上。要使该事件成功，用户必须点击该链接。

### 存储型和反射型 XSS 攻击的差异

*   反射型攻击更为常见
*   警惕的用户可避免反射型攻击
*   两者的影响范围不同

`XSS` 攻击中的攻击者玩的是概率游戏。他将链接发送给成千上万的用户以增加成功几率。即使只有极小比例的用户决定点击链接，他仍将拥有大量受感染的论坛用户。这些用户将被定向到论坛网站，恶意脚本将在其浏览器中反射执行。因此，攻击者可通过窃取其会话 Cookie 劫持其账户。

## 预防与缓解

您可以通过多种方式预防和缓解 `XSS` 攻击。首先，对用户而言，保持警惕是防御 `XSS` 脚本的最佳手段。具体来说，用户应避免点击任何可疑链接，因为您永远不知道哪个链接包含恶意代码。您可在以下位置发现可疑链接：

*   社交媒体动态
*   未知联系人发送的电子邮件
*   网站的评论区

网站运营商也应保护其用户免受潜在滥用。

`Web` 应用程序防火墙（`WAF`）在预防反射型 `XSS` 攻击方面大有裨益。它们可阻止输入清理缺失的异常请求。在存储型攻击中，阻止的是攻击者对网站的恶意请求；而在反射型攻击中，阻止的是用户的请求。这保护了用户和旁路受害者（其他网站用户）。一些 `Web` 应用程序防火墙使用签名过滤来对抗反射型 `XSS` 攻击。这些 `WAF` 利用众包技术自动收集整个网络的攻击数据。

# 第 10 章：入侵检测和入侵防范

入侵检测和入侵防范都是广泛的术语。它们描述了用于减少攻击和防范新威胁的应用安全实践。

*   **检测**是一种被动措施。它使用入侵检测系统（`IDS`）识别并中和正在进行的攻击。它清除现有恶意软件并检查社会工程学攻击。
*   **防范**是主动的。它使用入侵防范系统（`IPS`）预先阻止应用攻击。

## 入侵检测系统 (IDS)

`IDS` 是一种软件应用或硬件设备，它使用已知的入侵特征检测并分析出站和入站网络流量，以检查异常活动。

这通过以下方式实现：

*   将系统文件与恶意软件特征进行比对
*   通过扫描进程检测有害模式的迹象
*   通过监控用户行为检测恶意意图
*   监控系统配置和设置

当检测到安全策略违规、配置错误或病毒时，`IDS` 可以将违规者踢出网络，并通知安全人员该事件。`IDS` 具有巨大的优势，包括攻击检测和网络流量分析。然而，它也有缺点。由于它仅使用已知的入侵特征库，因此可能无法检测新发现的威胁。此外，`IDS` 无法检测即将到来的攻击，只能检测正在进行的攻击。因此，入侵防御系统是必要的。

## 入侵防御系统 (IPS)

`IPS`（入侵防御系统）会检查系统的传入流量并移除任何恶意请求。常规的 `IPS` 配置利用流量过滤解决方案和 `Web` 应用防火墙来保护应用程序。它丢弃恶意数据包、阻断恶意 IP，并将任何潜在威胁告知安全人员。由于这些系统使用现有的数据库进行特征识别，因此可以对其进行编程，以基于行为和流量异常来识别攻击。`IPS` 系统在阻断攻击载荷方面非常高效，但它们仍有局限性。它们过度依赖预定义规则，因此容易产生误报。

## Imperva 云 WAF 解决方案

Imperva 云 `WAF` 解决方案是完全可定制的工具。它们阻断任何安全威胁并减少误报。以下是 Imperva 云 `WAF IPS` 的一些功能：

*   **WAF（Web 应用防火墙）**：这种基于云的防火墙部署在您网络的边缘。它将使用特征、行为和信誉启发式方法来过滤应用攻击和恶意传入请求，从而保护您现有的 `IPS`。它具有高级功能，如应用感知技术、动态分析和访问控制，以缓解误报。
*   **自定义规则**：Imperva 云 `WAF` 的功能得以扩展，允许您应用自己的访问控制和安全策略。定制功能有助于缓解误报，并清除您组织特有的任何隐藏威胁。
*   **双因素认证 (`2FA`)**：`2FA` 要求用户在登录系统时通过两种方式/步骤进行验证，例如一次性密码 (`OTP`) 和密码。这额外的保护层保护敏感数据。
*   **后门防护**：由于 `IDS` 配置依赖已知的恶意软件特征来识别后门，因此这只是一种权宜之计。攻击者可以轻松避开识别。Imperva 的后门防护彻底解决了这个问题。

# 第 11 章：Ping 扫描

## Ping 扫描

`Ping` 是系统基于网络的实用程序，用于判断主机是存活还是宕机。从技术上讲，它被称为回显应答。此处“存活”是指主机（网站、网络、系统、计算机等）处于活动状态。“宕机”意味着它处于关机模式。

> **注意：** 主机可以是任何设备，如网络、打印机、计算机系统、网站或任何其他设备。

那么，什么是 Ping 扫描？它是一种通过 Ping 主机来识别存活主机的信息收集技术。更详细的技术细节：Ping 扫描也可称为双向握手协议、`ICMP` 扫描（互联网控制消息协议）或 Ping 扫描。一台主机发送数据包（数据），另一台主机验证并返回反馈（数据包，同样）确认 Ping 是否成功——这就是为什么它被称为双向握手协议。

Ping 扫描可用于多种目的：在识别出主机的 IP 地址后，您可以 Ping 该地址以了解主机是存活还是宕机。如果数据包被正确接收，则表明主机存活，您可以继续对受害者（主机）发起攻击。

有许多可用于常规 Ping 扫描的工具，例如 `Nmap`、`gping` 和 `fping`。您也可以直接在 Linux 和 Windows 平台上使用循环 Shell 脚本来执行。

### Windows 上的操作步骤

1.  转到 **开始** > **运行** > `CMD`。
2.  输入 `PING 127.0.0.1`（主机的 IP 地址）。

## 洪水 Ping

洪水 Ping 是一种拒绝服务攻击。它通过向主机或网站发送大量 Ping 来实施。结果是，合法或普通用户将无法访问该网站，因为每个主机（受害网络或网站）都有最大容量限制。洪水 Ping 超过了该限制并阻塞了网络。主机将随之停止响应。

洪水 Ping 通过创建自动化脚本或使用洪水 Ping 软件来实施。有时洪水 Ping 被称为“死亡之 Ping”，因为实施时会导致主机表现得像一台宕机的主机。

> **注意：** 只有当攻击者的带宽大于主机时，这才能成功。然而，成群结队地实施攻击可以达到目的。

通常，并非许多网站所有者拥有无限带宽计划，因为它们太昂贵。他们转而选择其他计划（如 10GB 带宽）。如果您尝试从 2 或 4 Mbps 的连接进行洪水 Ping，将不会成功。如果您组织一组人，比如说 20 个人，您可能会成功。从 20 台计算机同时发起攻击，每台具有 2 Mbps 的连接，将使您的主机承受 40 Mbps 的冲击。当主机带宽为 10GB 时这可能吗？黑客通常从一台电脑创建许多连接，这足以拖慢网站的数据库和功能。

# 第 12 章：点击劫持

点击劫持是一种网络攻击，受害者被诱骗点击一个不可见的网页元素，或一个伪装成另一个元素的元素。受害者随后可能在不知情的情况下下载恶意软件、泄露敏感信息/凭证、访问恶意页面、在线购买产品或转账。

通常，在点击劫持攻击中，一个不可见的 `HTML` 元素或页面会通过 `iframe` 显示在用户当前网页的顶层。用户点击它，以为它是可见的页面，而实际上它是一个不可见的元素。这个不可见的页面可能是受害者无意访问的页面，也可能是一个恶意页面。

## 点击劫持攻击形式

*   **Likejacking（赞劫持）**：一种操纵 Facebook“赞”按钮的技巧，导致人们赞了他们本不想赞的页面。
*   **Cursor jacking（光标劫持）**：一种改变光标位置的技术。这种攻击过去依赖 Firefox 和 Flash 中的漏洞——这些漏洞现已修复。

# 第 13 章：社会工程学

社会工程学是指通过人际互动实施的恶意攻击。这些攻击在心理上操纵受害者，导致其泄露敏感信息或犯下安全错误。社会工程学攻击可能分多个步骤进行，也可能仅需一步。攻击者会调查目标受害者以获取背景信息。接下来，他/她会试图赢得受害者的信任，并诱导其采取后续行动从而泄露敏感信息。社会工程学攻击之所以危险，是因为它们不依赖操作系统或软件的弱点，而是依赖人为错误。

社会工程学攻击类型繁多，只要有人际互动的地方就可能发生。然而，某些形式更为常见，以下是五种广为人知的类型：

## 诱饵攻击

诱饵攻击利用受害者的好奇心或贪婪。攻击者将受害者引入陷阱，从而获得安装恶意软件或窃取敏感信息的能力。物理媒介广泛用于此类社会工程学攻击。恶意黑客可能会将一个感染了恶意软件的 `U` 盘作为诱饵，遗留在停车场、洗手间、电梯等显眼区域。一旦受害者将该驱动器插入家用或工作电脑，系统就会被感染。

## 怖吓软件

怖吓软件也称为欺诈软件、流氓扫描软件和欺骗软件。它向受害者抛出虚构的威胁和虚假警报。攻击者让用户误以为其系统感染了恶意软件。随后，他提示受害者安装一款（虚假的）反恶意软件。这款软件通常就是恶意软件本身。怖吓软件攻击通常以浏览器中外观逼真的弹窗形式呈现，告知你系统中可能存在病毒。它们也可能通过垃圾邮件传播。

## 借口攻击

借口攻击是指攻击者通过撒谎来套取信息。他冒充税务官员、银行、同事或警察，向受害者索要敏感信息。在大多数情况下，他会通过提问提示你确认身份。利用这种手段可以窃取大量个人信息，如通话记录、电话号码和社会安全号码。
