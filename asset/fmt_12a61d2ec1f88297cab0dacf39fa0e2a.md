### 答案

- **D.** 初始化向量 (`IV`) 攻击旨在对密码初始化方式的加密实现进行攻击。这是 Wi-Fi 网络 `WEP` 加密标准中的已知漏洞。

- **A.** SQL 注入是通过在输入过滤不佳的字段内部使用分隔符或其他 SQL 命令结构来实现的。网页随后将该字段传递给数据库，然后由数据库执行注入的命令。

- **C.** 战争夺车（War driving）是指携带无线扫描仪和 `GPS` 开车行驶，并记录 Wi-Fi 接入点的位置。

- **D.** 缓冲区溢出是一种流行的攻击，因为它可以通过直接将代码插入内存来提供任意代码执行。

- **B.** 蓝牙嗅探（Bluesnarfing）取决于与移动设备的配对，因此关闭配对可以停止蓝牙嗅探攻击。

- **D.** 跨站脚本（XSS）将恶意内容（通常来自第三方网站）折叠到从服务器正确交付的验证内容部分中。

- **A.** 近场通信（NFC）没有集成加密功能，依赖高层协议来提供安全性。

- **C.** 经常，`SSL` 仅用于网站的登录页面，因此嗅探 Wi-Fi 的攻击者可以捕获用户的会话 Cookie 并用它来冒充用户。

- **B.** 建立在 IT 控制之外的非法接入点通常会允许任何检测到该接入点的人连接到企业内部网络。

- **D.** 所有答案都是正确的。当两个大数相加超出指定的整数位数时就会发生整数溢出，导致一个非常小的数字。这会导致意外的应用程序行为。

- **B** 和 **D**（SQL 注入和 `LDAP` 注入）是最佳答案。清理输入有助于确保没有原始命令直接传递给支持程序。

- **D.** 通过对整个站点进行加密可以防止会话劫持，防止攻击者盗取已建立的用户会话。

- **B.** 目录遍历攻击集中于执行外部用户不应能够访问的项目。适当的权限和移除所有不必要的执行权限有助于缓解攻击。

- **14.** **A**、**C** 和 **D**。这些措施有助于识别可能的原因。

- **15.** **C.** 无线恶意孪生设备可能被检测到。

# 第 15 章

## 缓解技术

在本章中，你将：

- 选择合适的日志类型

- 学习系统监控如何缓解风险

- 学习加固如何缓解风险

- 学习采用网络安全如何缓解风险

任何安全策略的一个部分都是缓解风险。目前使用一些方法。本章将探讨：

### 监控系统日志

日志文件是活动的记录：发生了什么、何时发生、谁做的、来自哪里等。尽管许多管理员对日志文件的审计和分析感到畏惧，但简单的事实是，有效的日志和分析可以是极佳的工具。第一步也是最关键的一步是在系统和网络设备上启用日志。记录失败的登录是有益的，但记录每次成功访问文件可能过度了。决定记录什么、如何记录以及维护审计日志多长时间，是系统管理员之间讨论不完的话题。

决定应该记录什么的某一个关键决定因素之一，是检查需要将哪些信息作为取证记录的记录。在事件发生时记录日志允许调查人员在事后检查活动情况。日志本身并不是万灵药，因为它们需要经过检查和解释才能发挥作用，这需要持续的努力和资源。这是决定应该记录什么的第二个关键决定因素——记录从不被审查的项目是一个常见问题。

### 常见日志

计算机系统中的许多事件都可以被记录。来自 `OSI` 模型不同层次的事件都可以记录在通用日志方案中。在远程服务器上维护日志提供了安全性，并在维护集中日志解决方案方面具有简单性。以下是日志记录有效且必要的某些区域的示例：

- **安全应用**：泛而言，“安全应用”可以是任何有助于评估或保护网络的程序。任何具有生成日志文件能力的安全应用都应配置为生成，并定期分析生成的日志。

- **DNS**：`DNS` 服务器可以配置为记录事务——解析请求、已执行或尝试执行的更新、转发解析的请求等。应该审计 `DNS` 日志文件以帮助识别尝试的入侵、攻击、欺诈更新、中毒尝试等。

- **性能**：性能日志跟踪内存使用率、CPU 使用率、磁盘使用率、网络流量等项目。性能日志可以是恶意活动的另一个良好指标，因为与正常水平相比，系统可能异常地“忙碌”或异常“安静”。

- **事件**：事件日志是应用程序日志的一种，用于跟踪系统上发生的事件。

- **访问**：跟踪哪个用户访问了特定资源、他们如何使用该资源、对该资源做了什么或使用了什么以及访问何时发生是一项至关重要的日志活动。审计访问日志是检测恶意活动、用户管理疏漏和其他活动的极佳方法。

- **防火墙**：防火墙活动日志跟踪尝试的连接、网络流量、源地址、目的地址、所用端口等。应定期对防火墙日志进行审计，以确保防火墙按预期运行，帮助识别常见的攻击流量源，识别常见的受攻击目标系统和服务等。

- **杀毒软件**：杀毒软件日志通常跟踪受感染的电子邮件或文件、违规邮件或文件的来源、更新状态、扫描活动等。需要定期进行审计，以确保杀毒软件程序提供了预期的保护水平，并有效地扫描了电子邮件流量和系统。

- **IDS/IPS**：入侵检测系统和入侵预防系统的日志也是跟踪可疑、不良或恶意活动的极佳来源。这些日志可以识别攻击流量、攻击流量源、目标资源、可能及实际的攻破、数据丢失和其他信息。

### 安全设置的定期审计

作为任何良好安全计划的一部分，管理员必须执行定期审计，以确保用户、系统、策略和流程方面“一切符合预期”。安装和配置安全机制固然重要，但必须按照定期计划定期对其进行审查，以确保其有效性、时效性并发挥预定功能。以下是一些应定期审计的项目示例，但绝不是完整列表：

- **用户访问**：管理员应检查哪些用户正在访问系统、他们何时访问、他们正在使用哪些资源等。管理员应密切留查是否存在用户不当地访问资源，或在异常时间访问合规资源的情况。

- **用户权限**：当用户更换工作或职责时，她可能需要分配不同的访问权限；她可能会获得新资源的访问权限并失去对其他资源的访问。为了确保用户仅拥有其当前职位所需的资源和能力，应定期对所有用户权限进行审计。

- **存储**：许多组织拥有策略，规定了“公司”资源上可以存储什么内容，以及特定用户或组可以使用多少空间。定期审计有助于确保组织资源上不存在任何不良或非法的材料。

- **保留**：在某些组织中，存储特定文档或记录持续的时间可能与存储的内容本身一样重要。记录保留政策有助于定义存储什么、如何存储、存储多久以及在到期时如何处理。定期审计有助于在记录或文档不再需要时将其移除。

- **防火墙规则**：对防火墙规则进行定期审计非常重要，这可以确保防火墙正在按预期过滤流量，并帮助确保“临时”规则不会变成规则集中的永久添加项。

### 系统加固

在维护企业安全方面，关键要素是企业基础设施中所用硬件和软件的安全态势。确保系统配置恰当且所有系统都安装了补丁并保持最新状态，是安全企业的关键组成部分。系统和操作系统的多种用途需要灵活的组件，允许用户设计、配置和实施他们所需的系统。然而，正是这种灵活性导致了计算机系统中一些最大的薄弱点。计算机和操作系统的开发者经常以“默认”模式构建和交付系统，这种模式几乎无法保护系统免受外部攻击。从开发者的角度来看，这是效率最高的交付模式，因为他们无法预判每个用户在每情况下需要什么。然而，从用户的角度来看，这意味着在系统投入使用之前必须投入大量精力来保护和安全系统。为生产环境保护并准备系统的过程被称为 `hardening`（加固）。遗憾的是，许多用户并不理解有效保护其系统所需的步骤，导致每天都有数百个系统被攻破。

**考试提示** 系统加固是准备和保护系统的过程，涉及移除所有必要的软件和网络服务。

### 禁用未使用的接口和未使用的应用程序服务端口

运行安全系统设置的关键管理问题是识别系统正常运行的特定需求，并仅启用这些功能所需的项目。保持系统关闭所有其他服务和服务用户可以提高系统吞吐量并增加安全性。减少与服务器相关的攻击面，可以减少现在和未来由于需要更新而产生的漏洞。

![image](img/examtip.jpg)

**考试提示** 特定的安全需求取决于服务器的具体用途，但至少采取以下预防措施是有有益的：

- 移除不必要的协议，如 `Telnet`、`NetBIOS`、`Internetwork Packet Exchange (IPX)` 和 `File Transfer Protocol (FTP)`。

- 移除所有不必要的共享。

- 禁用所有不需要的服务和端口；在任何加固过程中，通常应禁用 `ECHO`、`CHARGEN` 等简单的 TCP 服务。

- 重命名管理员账户并使用强密码进行保护。

- 移除不必要的用户账户。

- 保持 `OS` 已修补并保持最新。

- 控制对服务器的物理访问。

### 保护管理接口和应用程序

某些机器具有“管理接口”，允许远程管理设备本身。管理接口允许连接到管理应用程序、`SSH` 服务，甚至是基于 Web 的配置 GUI，而这些在其他接口上是不被允许的。由于这种高访问权限，必须保护管理接口和应用程序不受授权的访问。它们不应连接到公共网络连接（即互联网）或 DMZ 连接。在可能的情况下，在组织内部限制对管理接口和应用程序的访问，使得没有相应访问权限和权利的员工无法连接到这些接口和应用程序。

### 密码保护

密码保护是良好安全基准中经常被忽视的关键活动之一。该问题的核心在于，当今的大多数系统仅受简单用户 ID 和密码的保护。如果攻击者发现了正确的用户 ID 和密码的组合——无论是通过手动尝试，还是使用任何许多免费提供的暴力破解攻击工具——他们就能进入系统，并完全绕过了为保护系统安全而采取的所有正常步骤。更糟糕的是，在支持多用户的服务器系统上，攻击者只需要猜中一个正确的用户 ID 和密码组合即可获得访问权限。

从操作系统到应用程序，我们在本章中检查的每一个主题都存在这种基础的安全挑战。为所有用户账户选择一个良好的密码对于保护信息系统至关重要。什么是好密码？是一个既相对容易记忆又难以被猜到的密码吗？遗憾的是，没有一个魔术答案可以涵盖所有情况，但如果你在选择密码时遵循一些基本的指南和原则，就可以确保系统上使用的密码能够保护你的资产。

## 密码策略指南

要求使用用户名和密码进行身份验证无疑是目前最流行的安全机制。遗憾的是，它也是配置最不当、最被忽视且最容易被绕过的系统。解决密码问题的第一步是创建一个有效且易于管理的 `password policy`，让系统管理员和用户都能执行。在创建策略时，你应该仔细检查你的业务和安全需求。什么程度的风险是可以接受的？系统需要多大的安全性？用户应该多久更改密码？是否应该锁定账户？用户在选择密码时应该遵循哪些指南？你的问题列表会有很大差异，但关键是要花时间识别你的担忧并在密码策略中针对性地解决它们。

一旦你创建了密码策略，就要让大家知道。确保每个用户都有一份。将其发布在公司内网首页。在为新用户创建账户之前，让他们阅读一遍策略副本。定期发送电子邮件提醒，强调密码策略中的要点。在公司聚会上发布公告。方法并不比目标重要，目标仅仅是确保每一位用户都理解并遵循该策略。

一旦你向大家教授了该策略，就必须执行它以使其生效。为密码设置一个最小字符长度，并且永远不要接受短于该长度的密码。实施密码老化（稍后会讨论）并提示用户定期更改密码。不要接受基于词典单词的密码。不要允许用户反复使用同一个密码。许多操作系统都有内置的实用或插件，允许管理员强制执行良好的密码选择、强制密码老化并防止密码重用。

花时间运行一些流行的密码破解工具来审计你自己的密码文件。在拥有许多用户账户（超过一千个）的大型组织中，这将消耗时间和计算资源，但这是非常值得的。尽可能频繁地进行这些审计——每月、每两个月或每季度一次。如果你发现密码易被破解的账户，让用户重新查看密码策略并立即更改密码。

大多数密码审计/破解工具可以使用以下任一或所有技术来检查密码文件：

*   `Dictionary attack`：使用单词列表作为潜在密码。工具读取列表中的每个单词，对其进行加密，然后尝试将加密结果与文件中的密码进行匹配。

*   `Hybrid attack`：结合单词并将字母替换为字符。例如，用 `3` 替换 `e`。

*   `Brute force`：工具尝试所有可能的字符组合（`A–Z`、`a–z`、`0–9`）。

*   `Rainbow table`：预计算 `hashes` 的查找表。攻击者不需要实时计算 `hash`；他们只需读取即可。

### 选择密码

选择密码的多种方法从随机生成到一次性使用不等。每种方法都有其优缺点，但通常当安全性增加时，易用性往往会降低。例如，随机生成往往难以记忆，用户经常会将密码写在机器附近，从而违背了密码的初衷。安全与易用之间的最佳折中方案在于教用户如何根据易于记忆的短语（passphrase）来选择自己的密码。

基于短语的密码可以用许多方式形成：使用句子中每个单词的首字母；使用第一个单词的第一个字母、第二个单词的第二个字母，以此此类推；组合单词；或将字母替换为其他字符。以下是一些短语示例以及生成的密码：

*   使用句子中每个单词的首字母：

    句子：`I love to drive my 1969 Mustang!`

    密码：`Iltdm69M!`

*   组合单词并将字母替换为字符：

    句子：`Bad to the Bone`

    密码：`Bad2theB`

短语可以几乎是任何内容——你喜欢的电影台词、你喜欢的歌曲歌词，或者你随口编造的内容。使用你选择的任何方法，但最终结果应该是一个难以猜、容易记的密码。

### 好密码的组成

通过使用短语法，用户应该能够创建自己的易记的密码。然而，由于密码的目的是保护访问和资源免受入侵者侵害，它不应该让人们使用 `John the Ripper` 或 `Crack` 等密码破解工具猜测或获取。为了让密码难以猜测或获取，它应该满足以下指南：

*   长度应至少为八个字符（某些操作系统默认要求长密码）

*   应包含以下四个元素中的至少三个：

    *   一个或多个大写字母（`A–Z`）

    *   一个或多个小写字母（`a–z`）

    *   一个或多个数字（`0–9`）

    *   一个或多个特殊字符或标点符号（`!@#$%^&*,.:;?`）

*   不应由字典单词组成

*   绝不能与用户的登录名相同，或包含登录名

*   不应包含用户的姓、名、家庭成员姓名、出生日期、宠物名称或其他任何易于识别用户的项目

## 密码老化

在有足够的时间和计算能力的情况下，几乎任何密码都可以通过简单的暴力破解法测试所有可能的密码来破解。如果永久使用同一个密码，在大多数情况下，攻击者最终将能够获取密码并访问用户的账户。定期更改密码有助于防止暴力破解攻击，因为当密码发生变化时，攻击者必须从头开始重新启动攻击。如果密码更改得足够频繁，攻击者将永远无法在下一次密码更改之前遍历完所有可能的组合。

由于几乎任何密码最终都能被破解，因此防止用户“循环利用”密码（反复使用同一个密码）也同样重要。频繁更改密码还可以减少密码泄露时对系统造成的潜在损害，以及攻击者可能获得的访问权限。如果攻击者访问了用户账户且密码被更改，攻击者可能会失去对该账户的访问，并必须重新尝试破解新密码。许多操作系统提供了选项，允许系统管理员强制密码老化并防止密码重复。考虑使用以下指南：

-   让用户每 60 到 90 天更改一次密码（非常安全的设施可能希望每 30 到 45 天更改一次密码）。

-   让系统“记住”每个用户最后五到十个密码，不允许用户再次使用这些密码。

虽然确保每个账户都有良好的密码至关重要，但简单禁用或删除不必要的账户也是一个很好的主意。如果你的系统不需要支持来或匿名账户，请禁用它们。当不再需要用户或管理员账户时，将其删除或禁用。作为最佳实践，应定期对所有用户账户进行审计，以确保系统中没有必要的、过时的或需要的账户。
