
不要被名称搞混：子类比超类“大”——它包含更多的数据和更多的方法！

继承为代码复用提供了有效机制。假设超类的代码已经过测试和调试。由于子类对象共享超类对象的特征，因此只需为子类的额外特征编写新代码。

## 继承层次结构

一个子类本身可以作为另一个子类的超类，从而形成类的*继承层次结构*。

例如，考虑以下类之间的关系：`Person`、`Employee`、`Student`、`GradStudent` 和 `UnderGrad`。

![images](img/f129-01.jpg)

对于这些类中的任意一个，箭头指向其超类。箭头表示类之间的继承关系，或者非正式地表示*是一个*关系。因此，`Employee` *是一个* `Person`；`Student` *是一个* `Person`；`GradStudent` *是一个* `Student`；`UnderGrad` *是一个* `Student`。注意，反之不一定成立：`Person` 可能不是 `Student`，`Student` 也不一定是 `UnderGrad`。

请注意，*是一个*关系具有传递性：如果 `GradStudent` *是一个* `Student` 且 `Student` *是一个* `Person`，那么 `GradStudent` *是一个* `Person`。

每个子类都继承其超类的公共或受保护变量和方法。（参见 第 132 页。）子类可能拥有超类中没有的额外方法和实例变量。子类可以重新定义其继承的方法。例如，`GradStudent` 和 `UnderGrad` 可能使用不同的算法来计算课程成绩，并需要更改从 `Student` 继承的 `computeGrade` 方法。这称为*方法重写*。如果保留了超类中原始方法实现的部分，我们称这种重写为*部分重写*。（参见 第 133 页。）

### 继承实例方法和变量

子类继承其超类的所有公共和受保护方法。然而，它不继承父类的私有实例变量或私有方法，因此无法直接访问它们。要访问私有实例变量，子类必须使用其继承的访问器或修改器方法。

在 `Student` 示例中，`UnderGrad` 和 `GradStudent` 子类继承了 `Student` 超类的所有方法。但请注意，`Student` 的实例变量 `name`、`tests` 和 `grade` 都是私有的，因此不被继承，也无法被 `UnderGrad` 和 `GradStudent` 子类中的方法直接访问。然而，子类可以直接调用超类的公共访问器和修改器方法。因此，`UnderGrad` 和 `GradStudent` 都使用 `getTestAverage`。此外，两者都使用 `setGrade` 来间接访问并修改 `grade`。

如果 `Student` 中实例变量的访问说明符不是 `private`，而是 `public` 或 `protected`，那么子类就可以直接访问这些变量。关键字 `protected` 不在 AP Java 考试大纲范围内。

层次结构图中处于同一层级的类不会相互继承任何东西（例如 `UnderGrad` 和 `GradStudent`）。它们共有的仅仅是从超类继承的相同代码。

### 方法重写与 `super` 关键字

超类中的任何公共方法都可以在子类中通过定义一个具有相同返回类型和签名（名称和参数类型）的方法来重写。例如，`UnderGrad` 子类中的 `computeGrade` 方法重写了 `Student` 超类中的 `computeGrade` 方法。

有时重写方法的代码包括对超类方法的调用。这称为*部分重写*。这通常发生在子类方法想要执行超类的操作，再加上一些额外操作时。这通过在实现中使用关键字 `super` 来实现。`GradStudent` 子类中的 `computeGrade` 方法部分重写了 `Student` 类中的同名方法。语句

`super.computeGrade();`

表示此处应调用超类中的 `computeGrade` 方法。额外的测试

`if (getTestAverage() >= 90)`

`...`

允许 `GradStudent` 拥有 `Pass with distinction` 等级。注意此选项仅对 `GradStudent` 开放。

#### 注意

私有方法不能被重写。

### 构造器与 `super`

构造器永远不会被继承！如果没有为子类编写构造器，将生成一个无参的*默认构造器*，它会调用超类的无参构造器。如果超类没有无参构造器，只有带参数的构造器，将发生编译错误。如果超类中有无参构造器，继承的数据成员将按超类的方式初始化。子类中的额外实例变量将获得默认初始化——基本类型为 `0`，引用类型为 `null`。

请务必为子类至少提供一个构造器。构造器永远不会从超类继承。

默认构造器是当子类没有显式构造器时由编译器生成的无参构造器。

### 子类规则

- 子类可以添加新的私有实例变量。
- 子类可以添加新的公共、私有或静态方法。
- 子类可以重写继承的方法。
- 子类不能将公共方法重新定义为私有方法。
- 子类不能重写父类的静态方法。
- 子类应该定义自己的构造器。
- 子类不能直接访问其父类的私有成员。必须使用访问器或修改器方法。

### 动态绑定（后期绑定）

在运行时决定调用哪个实例方法称为 **动态绑定** 或 **后期绑定**。将其与选择正确方法进行对比，当方法是 **重载**（参见 p. 99）而非重写时。编译器通过比较方法签名在编译时选择正确的重载方法。这称为 **静态绑定** 或 **早期绑定**。在多态中，实际将被调用的方法不是由编译器决定的。可以这样理解：编译器决定**是否**可以调用一个方法（即该方法是否存在于引用的类中？），而运行时环境决定**如何**调用它（即应使用哪种重写形式？）。

### 多态方法调用的类型规则

![images](img/f141-01.jpg)

* 对于像 `Superclass a = new Subclass();` 这样的声明，`a` 在编译时的类型是 `Superclass`；在运行时是 `Subclass`。

* 在编译时，`method` 必须在 `a` 的类中找到，即在 `Superclass` 中。（无论该方法是否为多态方法，此规则均适用。）如果在 `a` 的类中找不到 `method`，则需要对 `a` 进行显式转型为其实际类型。

* 对于多态方法，在运行时会确定 `a` 的实际类型——本例中为 `Subclass`——并从 `Subclass` 中选择 `method`。如果不存在覆盖方法，这可能是一个继承的方法。

* 参数 `b` 的类型在编译时进行检查。它必须针对方法声明中的类型通过 *is-a* 测试。你可能需要对 `b` 进行显式转型为子类类型以使其正确。

给定任意超类，你应该能够编写自己的子类。

* 重载方法和覆盖方法
* 动态绑定（晚期绑定）和静态绑定（早期绑定）
* 默认构造器和无参构造器
