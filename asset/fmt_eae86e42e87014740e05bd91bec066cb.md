
根据上述第一个关键观察，显然如果计数是精确的，`H_d` 等于 `N(v,d)`；由于近似导致的误差原则上可能随着 `d` 的增加而累积和放大，但 [47] 中的实验并未显示这种效应。一旦计算出 `H[d]`，我们就可以丢弃 `H[d-1]` 计数器，并重用它们占用的空间。因此，我们可以用 `d` 次边数据库的顺序扫描和 `O(n log log n)` 内存来近似距离 `d` 以内的邻域函数。

利用这一想法和大量巧妙的优化，Backstrom 等人 [21] 能够解决 Facebook 图中距离的估计问题，该图的节点是 Facebook 用户，边是他们直接的好友关系。该图拥有 7.21 亿用户和 690 亿条链接。值得注意的是，他们在单台机器上仅用几小时就完成了用户间平均距离的计算，结果为 4.74，对应 3.74 个中介或“分隔度”。非正式地说，这证实了 S. Milgram 在 1960 年代著名的实验 [177]，该实验使用实体信件和邮政服务，暗示当时世界上大多数人之间的分隔度不超过六度。

### 4.5.5 讨论：对数 vs. 线性

关于寻找不同元素算法的更多细节可参见 [176]，其中也提供了实证评估。它关注何时值得使用相对复杂的亚线性草图，而不是简单的线性计数。结论是，当需要极高精度时，例如低于 `ε = 10^(-4)`，线性草图更可取。对数草图通常需要 `O(1/ε²)` 空间来实现乘法误差 `ε`，对于高精度要求来说，这确实可能很大。

在数据挖掘和机器学习应用中，通常可以接受相对较大的近似误差，例如 `ε = 10^(-1)` 以内，因为挖掘出的模型是许多统计量的组合，单个统计量本身都不太关键，而且无论如何数据都被视为现实的随机样本。因此，对数空间草图可能是一个有吸引力的选择。

还值得一提的是，[144] 给出了一种更复杂、渐近最优的计算不同元素算法，使用 `O(ε^(-2) + log d)` 位，即去除了 HyperLogLog 中的 `log log d` 因子。对于实际用途，HyperLogLog 似乎仍然更快且更小。

#### 4.6 频率问题

在许多情况下，我们不仅仅想计算流中所有项目的总数，而是分别计算流中不同类型项目的数量。在一般情况下，用亚线性内存估计所有项目的频率是不可能的，但通常只需获得最高频项目的近似计数即可。

对于流的长度为 `t` 的初始片段，项目 `x` 的*绝对频率*是它在该片段中出现的次数，其*相对频率*是绝对频率除以 `t`。我们主要考虑以下问题表述：

**重击者问题。** 给定阈值 `ε` 和对流的访问权限，在从流中读取任意数量的项目后，生成*重击者*集合，即所有相对频率超过 `ε` 的项目。

该问题与数据库领域计算*冰山查询* [97] 的问题密切相关。一个基本观察是：相对频率高于 `ε` 的项目最多只能有 `1/ε` 个；否则相对频率之和将超过 1，这是不可能的。

重击者问题的一个初步近似解是使用采样；例如，使用水库采样从流中抽取均匀样本，并始终声明样本中的频繁元素就是流中的频繁元素。这是一个有效的算法，但要达到任何固定的置信度，所需的样本量与 `1/ε²` 成正比。在本节中，我们将介绍三种重击者问题的算法，每种都有其自身的优势。第一种是基于计数器的确定性算法；另外两种基于哈希。

综述 [80, 164] 讨论并评估了我们将要介绍的算法及其他几种算法。

在本节中，我们以字（word）为单位衡量内存，假设一个项目、整数、指针等简单变量适合存放在一个内存字中。

##### 4.6.1 SPACESAVING 草图

基于计数器的算法历史上是 Boyer 和 Moore [50] 方法的演变，该方法用于在多数元素（频率至少为 1/2 的元素）存在时找到它。Misra 和 Gries [179]、Demaine 等人 [86] 以及 Karp 等人 [145] 独立发现了该方法的一个改进版本。通常称为 FREQUENT，该方法仅用 `O(1/ε)` 内存就能找到一个保证包含所有 `ε`–重击者的元素列表。

FREQUENT 的一个缺点是它只提供重击者，而无法给出其频率的可靠估计，而频率估计通常很重要。其他提供频率近似值的基于计数器的草图包括 Lossy Counting 和 Sticky Sampling，均由 Manku 和 Motwani [165, 166] 提出，以及 Space Saving，由 Metwally 等人 [175] 提出。我们描述 Space Saving，据 [80, 161, 164] 报道，它在多种重击者算法中性能最好。此外，它简单直观，并对近似质量有严格的保证。

图 4.6 展示了 `SPACESAVING` 的伪代码。它在内存中维护一组至多 `k` 个（项目，计数）对，用前 `k` 个不同元素及其计数进行初始化。当新的流项目到达时，如果该项目在集合中已有条目，则其计数加 1。如果没有，则该项目替换计数最低的项目，后者的计数随后加 1。非直观的部分在于，该项目继承了它所驱逐元素的计数，即使这是它的首次出现。然而，正如以下断言所示，误差永远不会太大，既不会让稀有元素看起来过于频繁，也不会让真正的重击者看起来过于不频繁。

令 `f[t,x]` 为前 `t` 个流元素中项目 `x` 的绝对频率，若 `x` 在时刻 `t` 位于概略图中，令 `count_t` 为其关联的计数；当从上下文中清楚时，我们省略下标 `t`。以下对于每个项目 `x` 且在所有时间 `t` 均成立：

总而言之，取 `k = ⌈1/ε⌉` 时，`SPACESAVING` 可找到所有 `ε`–重击者，其频率近似正确至 `ε`，使用 `O(1/ε)` 个内存字和常数摊还时间。

`SPACESAVING`、`FREQUENT`、`Lossy Counting` 和 `Sticky Sampling` 均为确定性算法；除哈希表内部可能用于搜索集合的哈希函数或随机化外，它们不使用哈希函数或随机化。很容易将 `SPACESAVING` 适配为形式为 `(x,c)` 的更新，其中 `x` 为项目，`c` 为任意*正*权重，该对代表赋值 `f[x] ← f[x] + c`，对内存或更新时间无显著影响。但它无法模拟项目删除，或等价地，无法处理带*负*权重的更新。

回到重击者问题，CM-sketch 为重击者元素的频率提供了合理的近似，但没有明显的方法从数据结构中定位它们。对所有可能的 `x` 调用 `Query(x)` 的暴力搜索对于大型项目全集是不可行的。解决方案使用了所谓的*区间求和查询* 的高效实现，这在许多情况下具有独立的研究价值。

区间求和查询定义在可与 `{1, . . . , |I|}` 中的整数对应的项目集合上。参数为 `[x,y]` 的区间求和查询返回 `f[x] + f[x+1] + ⋯ + f[y-1] + f[y]`。例如，考虑一个处理发往 IP 地址数据包的路由器。路由器的一个区间求和查询可能是：“你见过多少发往 IPv4 地址范围 172.16.aaa.bbb 的数据包？”我们期望比遍历该范围内的 2¹⁶ 个地址更快地解决此查询。

###### 使用 CM-Sketch 进行范围求和查询

范围求和查询可以使用 CM-Sketch 实现，方法如下：设 `|I| = 2^n` 为潜在项的数量。对于每个 2 的幂 `2^i`（`0 ≤ i ≤ n`），创建一个 CM-Sketch `C[i]`，用于对大小为 `2^i` 的区间内的项进行范围求和。更准确地说，向 `C[i]` 发出的 `Query(j)` 将返回区间 `[j·2^i … (j + 1)·2^i − 1]` 内项的总计数。或者，我们可以想象在第 `i` 层，每个项 `x` 都属于“超级项” `x mod 2^(n−i)`。特别地，`C[0]` 存储单个项的计数，而 `C[n]` 存储所有计数的总和。然后，我们可以使用以下递归来回答针对 `C[i]` 的范围求和查询 `(x, y)`，其中 `x` 和 `y` 位于同一个大小为 `2^i` 的区间内：

1. 如果 `x` 和 `y` 落在同一个大小为 `2^(i-1)` 的区间内，我们向 `C[i-1]` 查询 `(x, y)` 并返回其答案。

2. 否则，如果存在某个 `j` 使得 `x < j·2^(i-1) ≤ y`（即 `x` 和 `y` 不属于同一个大小为 `2^(i-1)` 的区间），我们向 `C[i-1]` 查询范围求和 `(x, j·2^(i-1) − 1)` 和 `(j·2^(i-1), y)`，然后返回两个答案的总和。

Sketch `C[0]` 是递归的基础。

现在，带参数 `k` 的重击项问题可以通过按深度探索区间集合 `[j·2^i, (j + 1)·2^i − 1]` 来解决。如果区间的权重低于 `F/k`，则其下方的任何叶节点都不可能是重击项，因此返回空列表。否则，将其划分为两个大小相等的区间分别探索，并将返回的列表连接起来。当到达叶节点时，当且仅当它是重击项时（即其权重为 `F/k` 或更多）才返回它。此外，在树的每一层中，权重为 `F/k` 或更多的节点最多有 `k` 个，因此最多探索树的 `k log |I|` 个节点。总而言之，重击项的查找使用 `O((log |I|) ln(1/δ) / ε)` 个内存字。

如前所述，CM-Sketch 可用于高效解决流上的其他几个问题 [81]，包括分位数计算、项频率直方图、相关性以及两个流的内积。然而，对于分位数计算的情况，专用 Sketch FrugalStreaming [163] 被认为是最先进的技术。我们将在第 6.4.3 节描述分类问题中数值属性的管理时介绍另一种分位数摘要。

##### 4.6.3 CountSketch

COUNTSKETCH 算法由 Charikar 等人 [64] 提出。与 CM-SKETCH 一样，它支持具有正负权重的更新。它使用 `O(1/ε²)` 的内存，但能找到所谓的 `F_2`–重击项，这是常规重击项（或 `F_1`–重击项）的一个有趣的超集。

流的 `F_2` 范数定义为 `√(∑_x f[x]²)`。如果 `f[x] ≥ ε √(∑_y f[y]²)`，则项 `x` 是阈值为 `ε` 的 `F_2`–重击项。一些简单的代数运算表明，每个 `F_1`–重击项也是 `F_2`–重击项。

在其最简单的形式中，COUNTSKETCH 可以描述如下。它选择两个哈希函数。函数 `h` 将项映射到一组 `w` 个桶 `{0, …, w-1}`。函数 `σ` 将项映射到 `{-1, +1}`。假设两者都足够随机。特别是 `σ` 的一个重要性质是：对于不同的 `x` 和 `y`，`σ(x)` 和 `σ(y)` 相互独立，这意味着 `Pr[σ(x) = σ(y)] = 1/2`，进而意味着 `E[σ(x) · σ(y)] = 0`。

算法维护一个包含 `w` 个累加器的数组 `A`，初始化为 0。对于流中的每一对 `(x, c)`，它向 `A[h(x)]` 添加值 `σ(x) · c`。注意，给定 `x` 的更新要么全部相加，要么全部相减，取决于 `σ(x)`。当被要求提供 `f[x]` 的估计值时，算法返回 `Query(x) = σ(x) · A[h(x)]`。如果没有其他项 `y` 被映射到 `A` 中与 `x` 相同的单元格，该估计将是精确的，但这种情况很少见。尽管如此，可以证明在哈希函数的随机选择下，其期望是正确的。确实：

```
E[Query(x)] = E[σ(x) · A[h(x)]]
            = E[σ(x) · ∑_y σ(y) · f[y] · I(h(y) = h(x))]
            = ∑_y f[y] · E[σ(x)σ(y)] · Pr[h(y) = h(x)]
            = f[x]
```

因为如前所述，对于 `x ≠ y`，`E[σ(x)σ(y)] = 0`，且 `σ(x)² = 1`。类似的代数运算表明 `Var(Query(x)) ≤ F_2 / w`。

现在我们可以使用类似第 4.9.2 节所述的策略，先提高精度，再提高置信度：取 `w = 12/(5ε²)` 个独立副本的平均值；根据切比雪夫不等式，这以 `5/6` 的概率用加性误差 `ε √(F_2/w)` 估计每个频率。然后独立地重复此过程 `d = O(ln(1/δ))` 次并返回结果的中位数；霍夫丁不等式表明（见练习 4.9），这将置信度提升至 `1 - δ`。因此，满足 `Query(x) ≥ ε √(F_2)` 的 `x` 的集合以高概率包含每个 `F_2`–重击项。注意，与 CM-SKETCH 和 SPACESAVING 不同，这里除了假阳性外可能还有假阴性，因为使用的是中位数而非最小值。内存使用为 `O(ln(1/δ) / ε²)` 字。

此时，我们可以将基本算法的 `d` 个副本视为一个类似于 CM-SKETCH 的单一算法：它选择哈希函数 `h[0], …, h[d-1]`、`σ[0], …, σ[d-1]`，并维护一个具有 `d` 行 `w` 列的数组 `A`。伪代码如 图 4.9 所示。为了高效地恢复重击项，COUNTSKETCH 还基于估计权重维护一个迄今为止见过的最频繁元素的堆。
