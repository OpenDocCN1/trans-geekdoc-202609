
这两条语句声明了一个名为 `Employee` 的结构体类型和一个名为 `dilbert` 的变量，该变量是 `Employee` 的一个实例：

```
type Employee struct {
    ID        int
    Name      string
    Address   string
    DoB       time.Time
    Position  string
    Salary    int
    ManagerID int
}

var dilbert Employee
```

`dilbert` 的各个字段通过点号表示法访问，如 `dilbert.Name` 和 `dilbert.DoB`。因为 `dilbert` 是一个变量，所以它的字段也是变量，因此我们可以给字段赋值：

```
dilbert.Salary -= 5000 // 因写代码行数太少被降职
```

或者获取其地址并通过指针访问：

```
position := &dilbert.Position
*position = "Senior " + *position // 因外包给 Elbonia 而晋升
```

点号表示法也适用于结构体指针：

```
var employeeOfTheMonth *Employee = &dilbert
employeeOfTheMonth.Position += " (proactive team player)"
```

最后一条语句等价于：

```
(*employeeOfTheMonth).Position += " (proactive team player)"
```

给定员工的唯一 ID，函数 `EmployeeByID` 返回一个指向 `Employee` 结构体的指针。我们可以使用点号表示法来访问其字段：

```
func EmployeeByID(id int) *Employee { /* ... */ }

fmt.Println(EmployeeByID(dilbert.ManagerID).Position) // "Pointy-haired boss"

id := dilbert.ID
EmployeeByID(id).Salary = 0 // 因……没有真正的原因被解雇
```

最后一条语句更新了由 `EmployeeByID` 调用结果指向的 `Employee` 结构体。如果 `EmployeeByID` 的结果类型被改为 `Employee` 而不是 `*Employee`，赋值语句将无法编译，因为其左侧不会标识一个变量。

字段通常每行写一个，字段名在其类型之前，但相同类型的连续字段可以合并，如这里的 `Name` 和 `Address`：

```
type Employee struct {
    ID            int
    Name, Address string
    DoB           time.Time
    Position      string
    Salary        int
    ManagerID     int
}
```

字段顺序对类型标识至关重要。如果我们也合并了 `Position` 字段的声明（也是字符串），或交换了 `Name` 和 `Address`，我们将定义一个不同的结构体类型。通常我们只合并相关字段的声明。

如果结构体字段名以大写字母开头，则该字段被导出；这是 Go 语言主要的访问控制机制。一个结构体类型可能包含导出和未导出字段的混合。

结构体类型往往比较冗长，因为它们通常每个字段占一行。虽然我们可以在每次需要时写出完整的类型，但重复会让人厌烦。相反，结构体类型通常出现在像 `Employee` 这样的命名类型声明中。

命名结构体类型 `S` 不能声明一个相同类型 `S` 的字段：聚合值不能包含它自己。（类似的限制也适用于数组。）但 `S` 可以声明一个指针类型 `*S` 的字段，这使我们能创建递归数据结构，如链表和树。下面的代码演示了这一点，它使用二叉树实现了插入排序：

```
gopl.io/ch4/treesort

type tree struct {
    value       int
    left, right *tree
}

// Sort 就地排序 values。
func Sort(values []int) {
    var root *tree
    for _, v := range values {
        root = add(root, v)
    }
    appendValues(values[:0], root)
}

// appendValues 将 t 的元素按顺序追加到 values
// 并返回结果切片。
func appendValues(values []int, t *tree) []int {
    if t != nil {
        values = appendValues(values, t.left)
        values = append(values, t.value)
        values = appendValues(values, t.right)
    }
    return values
}

func add(t *tree, value int) *tree {
    if t == nil {
        // 等价于 return &tree{value: value}。
        t = new(tree)
        t.value = value
        return t
    }
    if value < t.value {
        t.left = add(t.left, value)
    } else {
        t.right = add(t.right, value)
    }
    return t
}
```

结构体的零值由其每个字段的零值组成。通常希望零值是一个自然或合理的默认值。例如，在 `bytes.Buffer` 中，结构体的初始值是一个可直接使用的空缓冲区，而 `sync.Mutex` 的零值（我们将在第 9 章看到）是一个可直接使用的未锁定互斥锁。有时这种合理的初始行为是自动获得的，但有时类型设计者必须为此付出努力。

没有字段的结构体类型被称为 *空结构体*，写作 `struct{}`。它的大小为零且不携带信息，但仍可能有用。一些 Go 程序员用它代替 `bool` 作为表示集合的 map 的值类型，以强调只有键才重要，但节省的空间微乎其微且语法更繁琐，所以我们通常避免使用它。

```
seen := make(map[string]struct{}) // 字符串集合
// ...
if _, ok := seen[s]; !ok {
    seen[s] = struct{}{}
    // ...第一次看到 s...
}
```

### 4.4.1 结构体字面量

结构体类型的值可以用 *结构体字面量* 来书写，它为字段指定值。

```
type Point struct{ X, Y int }

p := Point{1, 2}
```

结构体字面量有两种形式。第一种形式如上所示，要求为*每个*字段按正确顺序指定值。它要求编写者（和阅读者）准确记住字段是什么，并且如果字段集合后来增长或重新排序，会使代码变得脆弱。因此，这种形式倾向于仅在定义该结构体类型的包内使用，或用于有明显字段排序约定的较小结构体类型，如 `image.Point{x, y}` 或 `color.RGBA{red, green, blue, alpha}`。

更常用的是第二种形式，即通过列出部分或全部字段名及其对应的值来初始化结构体值，就像第 1.4 节 Lissajous 程序中的这条语句：

```
anim := gif.GIF{LoopCount: nframes}
```

如果字段在该类型的字面量中被省略，它将被设置为其类型的零值。因为提供了名称，字段的顺序无关紧要。

这两种形式不能在同一个字面量中混合使用。也不能使用（基于顺序的）第一种字面量形式来绕过规则，即不能从另一个包引用未导出的标识符。

点击此处查看代码图像

```
package p
type T struct{ a, b int } // a 和 b 未导出

package q
import "p"
var _ = p.T{a: 1, b: 2} // 编译错误：无法引用 a, b
var _ = p.T{1, 2}       // 编译错误：无法引用 a, b
```

尽管最后一行没有提及未导出的字段标识符，但它实际上隐式地使用了它们，因此这是不允许的。

结构体值可以作为参数传递给函数，也可以从函数返回。例如，此函数按指定因子缩放 `Point`：

点击此处查看代码图像

```
func Scale(p Point, factor int) Point {
    return Point{p.X * factor, p.Y * factor}
}

fmt.Println(Scale(Point{1, 2}, 5)) // "{5 10}"
```

为了效率，较大的结构体类型通常通过指针间接地传递给函数或从函数返回，

点击此处查看代码图像

```
func Bonus(e *Employee, percent int) int {
    return e.Salary * percent / 100
}
```

如果函数必须修改其参数，则需要这样做，因为在像 Go 这样的按值调用语言中，被调用函数仅接收参数的副本，而不是对原始参数的引用。

点击此处查看代码图像

```
func AwardAnnualRaise(e *Employee) {
    e.Salary = e.Salary * 105 / 100
}
```

因为结构体通常通过指针来处理，所以可以使用这种简写符号来创建并初始化一个 `struct` 变量并获取其地址：

```
pp := &Point{1, 2}
```

它完全等同于

```
pp := new(Point)
*pp = Point{1, 2}
```

但 `&Point{1, 2}` 可以直接在表达式中使用，例如函数调用。

## 4.4.2 比较结构体

如果结构体的所有字段都是可比较的，那么该结构体本身就是可比较的，因此该类型的两个表达式可以使用 `==` 或 `!=` 进行比较。`==` 操作按顺序比较两个结构体的对应字段，因此下面打印的两个表达式是等价的：

点击此处查看代码图像

```
type Point struct{ X, Y int }

p := Point{1, 2}
q := Point{2, 1}
fmt.Println(p.X == q.X && p.Y == q.Y) // "false"
fmt.Println(p == q)                   // "false"
```

可比较的结构体类型，像其他可比较类型一样，可用作映射的键类型。

点击此处查看代码图像

```
type address struct {
    hostname string
    port     int
}

hits := make(map[address]int)
hits[address{"golang.org", 443}]++
```

## 4.4.3 结构体嵌入和匿名字段

在本节中，我们将看到 Go 不寻常的*结构体嵌入*机制如何让我们将一个命名结构体类型用作另一个结构体类型的*匿名字段*，提供了一种方便的语法快捷方式，使得简单的点表达式如 `x.f` 可以代表一串字段如 `x.d.e.f`。

考虑一个 2D 绘图程序，它提供了一个形状库，如矩形、椭圆、星星和轮子。以下是它可能定义的两种类型：

```
type Circle struct {
    X, Y, Radius int
}

type Wheel struct {
    X, Y, Radius, Spokes int
}
```

`Circle` 拥有其圆心 `X` 和 `Y` 坐标的字段，以及一个 `Radius`。`Wheel` 拥有 `Circle` 的所有特性，外加 `Spokes`（内切辐条的数量）。让我们创建一个轮子：

```
var w Wheel
w.X = 8
w.Y = 8
w.Radius = 5
w.Spokes = 20
```

随着形状集合的增长，我们必然会注意到它们之间的相似性和重复性，因此提取其公共部分可能会很方便：

```
type Point struct {
    X, Y int
}

type Circle struct {
    Center Point
    Radius int
}

type Wheel struct {
    Circle Circle
    Spokes int
}
```

应用程序可能因此变得更清晰，但这项更改使得访问 `Wheel` 的字段变得更加冗长：

```
var w Wheel
w.Circle.Center.X = 8
w.Circle.Center.Y = 8
w.Circle.Radius = 5
w.Spokes = 20
```

Go 允许我们声明一个只有类型没有名称的字段；这样的字段称为*匿名字段*。该字段的类型必须是命名类型或指向命名类型的指针。在下面的代码中，`Circle` 和 `Wheel` 各有一个匿名字段。我们说 `Point` 被*嵌入*在 `Circle` 中，而 `Circle` 被嵌入在 `Wheel` 中。

```
type Circle struct {
    Point
    Radius int
}

type Wheel struct {
    Circle
    Spokes int
}
```

得益于嵌入，我们可以在不给出中间名称的情况下引用隐式树叶子节点的名称：

点击此处查看代码图像

```
var w Wheel
w.X = 8        // 等价于 w.Circle.Point.X = 8
w.Y = 8        // 等价于 w.Circle.Point.Y = 8
w.Radius = 5   // 等价于 w.Circle.Radius = 5
w.Spokes = 20
```

上面注释中显式的形式仍然有效，这表明“匿名字段”在一定程度上是个误称。字段 `Circle` 和 `Point` 确实有名称——即命名类型的名称——但这些名称在点表达式中是可选的。在选择其子字段时，我们可以省略任意或所有匿名字段。

遗憾的是，结构体字面量语法没有相应的简写，因此以下两行都无法编译：

点击此处查看代码图像

```
w = Wheel{8, 8, 5, 20}                       // 编译错误：未知字段
w = Wheel{X: 8, Y: 8, Radius: 5, Spokes: 20} // 编译错误：未知字段
```

结构体字面量必须遵循类型声明的结构，所以我们必须使用下面两种形式之一，它们彼此等价：

点击此处查看代码图像

gopl.io/ch4/embed

```
w = Wheel{Circle{Point{8, 8}, 5}, 20}

w = Wheel{
    Circle: Circle{
        Point:  Point{X: 8, Y: 8},
        Radius: 5,
    },
    Spokes: 20, // 注意：此处尾随逗号是必要的（Radius 处也是）
}

fmt.Printf("%#v\n", w)
// Output:
// Wheel{Circle:Circle{Point:Point{X:8, Y:8}, Radius:5}, Spokes:20}

w.X = 42

fmt.Printf("%#v\n", w)
// Output:
// Wheel{Circle:Circle{Point:Point{X:42, Y:8}, Radius:5}, Spokes:20}
```

注意 `#` 修饰符导致 `Printf` 的 `%v` 动词以类似 Go 语法的形式显示值。对于结构体值，这种形式包含每个字段的名称。

因为“匿名”字段确实有隐式名称，所以不能有两个相同类型的匿名字段，因为它们的名称会冲突。而且因为字段的名称由其类型隐式决定，字段的可见性也是如此。在上面的例子中，匿名字段 `Point` 和 `Circle` 是导出的。如果它们是未导出的（`point` 和 `circle`），我们仍然可以使用简写形式

点击此处查看代码图像

```
w.X = 8 // 等价于 w.circle.point.X = 8
```

但注释中显示的显式长形式将在声明包之外被禁止，因为 `circle` 和 `point` 将不可访问。

到目前为止我们看到的结构体嵌入只是用于选择结构体字段的点表示法上的一点语法糖。稍后我们将看到，匿名字段不必是结构体类型；任何命名类型或指向命名类型的指针都可以。但为什么要嵌入一个没有子字段的类型呢？

答案与方法有关。用于选择嵌入类型字段的简写表示法也适用于选择其方法。实际上，外部结构体类型不仅获得了嵌入类型的字段，还获得了它的方法。这种机制是将复杂对象行为从简单行为中组合而成的主要方式。`Composition`（组合）是 Go 语言面向对象编程的核心，我们将在第 6.3 节中进一步探讨它。

## 4.5 JSON

JavaScript 对象表示法（JSON）是一种用于发送和接收结构化信息的标准表示法。JSON 并非唯一的此类表示法。XML（§7.14）、ASN.1 和 Google 的 Protocol Buffers 服务于类似目的，各有其适用领域，但由于其简洁性、可读性和通用支持，JSON 是应用最广泛的。

Go 语言通过标准库包 `encoding/json`、`encoding/xml`、`encoding/asn1` 等为这些格式的编码和解码提供了出色的支持，这些包都拥有相似的 API。本节简要概述 `encoding/json` 包中最重要的部分。
