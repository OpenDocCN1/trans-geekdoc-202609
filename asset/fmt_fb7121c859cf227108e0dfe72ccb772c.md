### TensorFlow Serving

TensorFlow (TF) Serving 允许您通过模型服务器将训练好的 TensorFlow 模型作为 API 端点托管。TensorFlow Serving 处理模型服务和版本管理，并允许您提供模型服务。它允许您从不同来源加载模型。

TensorFlow Serving 允许两种类型的 API 端点：REST 和 gRPC。

设置 TF Serving 的步骤如下：

1. 使用 Docker 安装 TensorFlow Serving。
2. 使用 TensorFlow 训练并保存模型。
3. 使用 TensorFlow Serving 服务已保存的模型。

更多信息请参阅 `www.tensorflow.org/tfx/serving/api_rest`。

#### 使用 TensorFlow Serving 服务已保存的模型

运行在 host:port 上的 TensorFlow ModelServer 接受以下 REST API 请求：

```
POST http://host:port/<URI>:<VERB>

URI: /v1/models/${MODEL_NAME}[/versions/${MODEL_VERSION}]
VERB: classify|regress|predict
```

要调用 `predict()` REST 端点，您需要定义一个 JSON 数据载荷，因为 TF Serving 期望数据为 JSON 格式，如下所示：

```
data = json.dumps({"signature_name": "serving_default",
 "instances": instances.tolist()})
headers = {"content-type": "application/json"}
json_response = requests.post(url, data=data, headers=headers)
predictions = json.loads(json_response.text)['predictions']
```

`signature_name` 指定输入/输出数据类型。`instances` 是您想要预测的数据/输入/实例。您应该将其作为列表传递。

TF Serving 为您处理所有模型和 API 基础设施，以便您专注于模型优化。在考试中，可能会给您一个 TF Serving JSON 负载的实例和签名，并要求您提供 `predict()` 函数的输出。

以下是一个张量实例的示例：

```json
{
 // 两个形状均为 [1, 2] 的张量列表
 "instances": [ [[1, 2]], [[3, 4]] ]
}
```

要了解您的 `predict()` 响应格式，您需要查看 SavedModel 的 SignatureDef（更多信息请参阅 `www.tensorflow.org/tfx/serving/signature_defs`）。您可以使用 SignatureDef CLI 来检查已保存的模型。给定的 SavedModel SignatureDef 包含以下输出：

```
outputs['class_ids'] tensor_info:
dtype: DT_INT64
shape: (-1, 1)
name: dnn/head/predictions/ExpandDims:0
outputs['classes'] tensor_info:
dtype: DT_STRING
shape: (-1, 1)
name: dnn/head/predictions/str_classes:0
outputs['logits'] tensor_info:
dtype: DT_FLOAT
shape: (-1, 3)
name: dnn/logits/BiasAdd:0
outputs['probabilities'] tensor_info:
dtype: DT_FLOAT
shape: (-1, 3)
name: dnn/head/predictions/probabilities:0
Method name is: tensorflow/serving/predict
```

根据前面的 SignatureDef，`predict()` 请求会在响应体中返回一个 JSON 对象，如下面的代码所示：

```json
{
 "predictions": [
 {
 "class_ids": [3],
 "probabilities": [2.0495e-7, 0.0243, 0.9756],
 "classes": ["2"],
 "logits": [-5.74621, 5.94074, 9.62958]
 }
 ]
}
```

前面的示例具有形状为 (−1,1) 的类别 ID 整数、形状为 (−1,1) 的字符串类别、形状为 (−1,3) 的浮点数 logits 以及形状为 (−1,3) 的浮点数概率。

由于类别 ID 和类别的形状均为 (−1,1)，因此它们在预测中将只有一个值。同样，对于概率和 logit，形状 (−1,3) 将在响应中给出三个张量值。−1 意味着我们可以向已保存的模型传递任意大小。

一旦模型在模型目录或文件夹中可用，TF Serving 会自动加载新模型。此外，当新模型版本可用时，TF Serving 会自动卸载旧模型并加载更新的版本。此技术非常高效，且可以轻松添加到 MLOps 流水线中。这有助于您更专注于模型优化，而不是模型服务基础设施。我们将在 **第 11 章 "设计 ML 训练流水线"** 中介绍使用 TFX/Kubeflow 进行系统设计的主题。

更多信息请参阅 `https://neptune.ai/blog/how-to-serve-machine-learning-models-with-tensorflow-serving-and-docker`。

### 预计算和缓存预测

改善在线预测延迟的另一种方法是在离线批量评分作业中预计算预测，并将它们存储在像 Memorystore 或 Datastore 这样的低延迟读取数据存储中，以便在线服务。在这些情况下，客户端（移动端、Web、数据流水线工作器、后端或前端 API）不会调用模型进行在线预测。相反，假设预测存在，客户端会从数据存储中获取预计算的预测。该过程如下：

1. 数据被摄取、处理并存储在键值存储中。
2. 一个训练并部署好的模型在准备好的数据上运行批量预测作业，为输入数据生成预测。每个预测由一个键标识。
3. 数据流水线将按键引用的预测导出到针对单点读取进行了优化的低延迟数据存储中。
4. 客户端发送一个由唯一键引用的预测请求。
5. ML 网关使用条目键从数据存储中读取并返回相应的预测。

客户端接收预测响应。图 10.4 展示了该流程。

预测请求可用于两类查找键：

#### 特定实体预测

特定实体预测是指基于 ID（如 `customerid` 或 `deviceid`）或特定的输入特征组合，针对单个实体进行预测。如果实体过多（基数高），则很难在有限的时间内预先计算预测结果。一个例子是按商品预测日销量，此时您拥有数十万甚至数百万种商品。在这种情况下，您可以按照架构图采用混合方法，为排名前 N 位的实体（如最活跃的客户或浏览量最高的产品）预先计算预测结果。然后，您可以直接使用模型对其余实体进行在线预测。

#### 特定输入特征组合

特定输入特征组合用于判断匿名或新客户是否会在您的网站上购买商品。当您拥有一组输入特征时，您需要创建一种哈希方法，其中键是所有可能输入特征的哈希组合，值则是预测结果。

### Google Cloud 服务选项

在 Google Cloud 中，您可以部署模型以进行在线预测或批量预测。您可以对 AutoML 模型和自定义模型同时执行批量预测和在线预测。在以下章节中，我们将介绍如何使用 Vertex AI 设置在线和批量作业。

#### 在线预测

要设置实时预测端点，您可能会遇到以下两种用例：

* **使用 Vertex AI 训练在 Vertex AI 中训练的模型：** 这可以是 AutoML 模型或自定义模型，详见 **第 8 章“模型训练与超参数调优”**。
* **在其他地方训练的模型（本地部署、其他云或本地设备）：** 如果您已在其他地方训练好模型，则需要在部署和创建端点之前将模型导入 Google Cloud。

如果您是作为预构建容器导入，请确保您的模型工件文件名与以下示例完全匹配：

* **TensorFlow SavedModel：** `saved_model.pb`
* **scikit-learn：** `model.joblib` 或 `model.pkl`
* **XGBoost：** `model.bst`、`model.joblib` 或 `model.pkl`

如果您是导入自定义容器，则需要创建一个容器镜像，并根据自定义容器托管的要求，可能需要使用 `Cloud Build` 将镜像推送到 `Artifact Registry`。

对于这两种选项，您都需要遵循以下步骤来设置 Vertex AI 预测：

1. 将模型资源部署到端点。
2. 进行预测。
3. 如果端点未被使用，则取消部署模型资源。

##### 部署模型

当您使用 Vertex AI 预测端点部署模型时，您需要为端点的容器（TensorFlow、scikit-learn 或 XGBoost）指定自动扩缩配置。Vertex AI 会自动配置容器资源并为您的端点设置自动扩缩。您可以将多个模型部署到一个端点，也可以将一个模型部署到多个端点。有两种方式可以部署模型：使用 API 和使用 Google Cloud 控制台。

###### 使用 API 部署模型
