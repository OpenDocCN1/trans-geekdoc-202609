## 考试目标总结

在本章中，我们讨论了运营安全。运营安全关注系统和数据在生产环境中主动使用时的安全性。归根结底，运营安全关乎人员、数据、介质和硬件，所有这些都是需要从安全角度考虑的要素。如果没有预防或检测控制措施，世界上最好的技术安全基础设施也会因拥有特权访问权限的个人决定背叛组织而变得毫无用处。

我们还讨论了业务连续性和灾难恢复规划，它们作为组织防止失败的最后一项控制。在所有控制中，失败的 BCP 或 DRP 破坏性最大，可能导致组织倒闭，或造成人员伤亡。

除了降低此类严峻风险之外，业务连续性规划和灾难恢复规划已演变为能为组织提供真正的业务价值，即使在没有灾难发生的情况下也是如此。构建全面的 BCP/DRP 所需的组织尽职调查，可以通过彻底了解关键业务流程、资产追踪、审慎的备份与恢复策略以及标准的使用，带来诸多红利。将风险映射到关键业务流程，可导致在任何灾难发生前采取预防性风险措施，这一过程可能完全避免未来的灾难。

## 简介

软件无处不在：不仅存在于我们的计算机中，还存在于我们的房屋、汽车和医疗设备中，而所有软件程序员都会犯错。随着软件复杂性的增加，错误的数量也随之增长。我们将在本章了解到，程序员每千行代码可能会犯 15-50 个错误，但遵循诸如*能力成熟度模型集成*（`CMMI`）之类的编程成熟度框架，可以将这一数字降低到每千行 1 个错误。这听起来很令人鼓舞，但请记住，Microsoft Vista 操作系统拥有 5000 万（50,000,000）行代码。较新的操作系统（如 Windows 11）很可能拥有更多。

随着软件复杂性的增加，软件崩溃的潜在影响也随之增大。许多汽车现在已连接互联网，并使用“线控”（软件）来控制车辆：在这种情况下，换挡杆不再与变速箱直接机械连接；相反，它充当电子输入设备，类似于键盘。如果软件崩溃中断了 `I/O` 会怎样？如果有人远程入侵汽车并夺取控制权会怎样？正如 Charlie Miller 和 Chris Valasek 所演示的那样？[\[1\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0010)

开发健壮且安全的软件至关重要：本章将展示如何实现这一点。我们将涵盖编程基础知识，如编译型与解释型语言，以及过程式和面向对象编程语言。我们将讨论应用开发模型，如*瀑布模型*、*螺旋模型*、*极限编程*（`XP`）等。我们还将讨论 `DevOps` 等较新概念。我们将描述常见的软件漏洞、测试漏洞的方法，以及用于评估编程过程成熟度并提供改进途径的成熟度框架。

## 编程概念

### 理解基石编程概念

让我们从理解一些基石编程概念开始。随着计算机变得更强大、更普及，创建计算机软件的过程和方法也在增长和变化。请记住，没有一种方法必然优于另一种：正如我们在下一节将看到的，高级语言（如 `C`）允许程序员比低级语言（如汇编语言）更快地编写代码，但用汇编语言编写的代码可能效率高得多。哪种更好取决于项目的需求。

#### 机器码、源代码和汇编器

**机器码**（也称为机器语言）是由 `CPU` 直接执行的软件。机器码依赖于 `CPU`；它是一系列 1 和 0，转换为 `CPU` 能够理解的指令。**源代码**是以文本编写的计算机编程语言指令，必须在 `CPU` 执行前翻译成机器码。高级语言包含类英语的指令，例如 `printf`（格式化打印）。

**汇编语言**是一种低级计算机编程语言。汇编语言指令是简短的助记符，如 `ADD`、`SUB`（减法）和 `JMP`（跳转），它们与机器语言指令一一对应。**汇编器**将汇编语言转换为机器语言。**反汇编器**尝试将机器语言转换回汇编语言。

#### 编译器、解释器和字节码

**编译器**获取源代码（如 `C` 或 `Basic`），并将其编译为机器码。

以下是一个 `C` 语言“Hello World”示例程序：

```c
int main()
{
    printf("hello, world");
}
```

编译器（如 `gcc`，即 GNU 编译器套件，参见 [`gcc.gnu.org`](http://gcc.gnu.org)）将这种高级语言翻译成机器码，并将结果保存为可执行文件（如 `hello-world.exe`）。一旦编译完成，机器语言就由 `CPU` 直接执行。`hello-world.exe` 只编译一次，之后可运行无数次。请注意，执行（即运行）程序的过程称为**运行时**。

**解释型语言**与编译型语言不同：解释型代码（如 Shell 代码）在每次运行程序时即时编译。以下是用解释型脚本语言 `Python` 编写的“Hello World”程序示例（参见 [`www.python.org`](https://www.python.org)）：

```python
#!/usr/local/bin/python
print("Hello World!")
```

此代码保存为 `hello-world.py`。每次运行时，`Python` 解释器（在前面的代码中位于 `/usr/local/bin/python`）将 `Python` 指令翻译成机器语言。如果 `hello-world.py` 运行 100 次，它将被编译 100 次（而 `hello-world.exe` 只编译一次）。

**字节码**（如 `Java` 字节码）也是解释型代码。字节码作为一种中间形式存在（从源代码转换而来），但在 `CPU` 上运行前仍必须转换为机器码。`Java` 字节码是与平台无关的代码，由 `Java` 虚拟机（`JVM`，参见第 4 章，领域 3：安全架构与工程，了解更多关于 `Java` 字节码的信息）转换为机器码。

#### 过程式语言和面向对象语言

**过程式语言**（也称为面向过程语言）使用子程序、过程和函数。示例包括 `Basic`、`C`、`Fortran` 和 `Pascal`。**面向对象语言**尝试通过使用结合了方法和数据的对象来模拟现实世界。示例包括 `C++`、`Ruby` 和 `Python`；更多信息请参见下文的“面向对象设计与编程”部分。过程式语言中的函数等同于面向对象语言中的方法。
