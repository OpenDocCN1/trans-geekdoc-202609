
# 安全硬件架构

安全硬件架构关注实现安全系统所需的物理计算机硬件。硬件必须为进程、数据和用户提供机密性、完整性和可用性。

## 机箱与主板

**机箱**是计算机的外壳：它包含所有内部电子计算机组件，包括主板、内部磁盘驱动器和电源。**主板**包含 CPU、内存插槽、固件以及外设插槽（如 `PCI`（外设组件互连）插槽）等硬件。键盘单元是外部键盘。

**计算机总线**（如图 4.8 所示）是计算机系统上的主要通信通道。CPU、内存以及键盘、鼠标、显示器等输入/输出设备之间的通信通过总线进行。

### 北桥与南桥

某些计算机设计使用两条总线：一个**北桥**和一个**南桥**。名称源于视觉设计，通常北桥显示在顶部，南桥显示在底部，如图 4.9 所示。北桥，也称为内存控制器中心（`MCH`），将 CPU 连接到*内存*和显存。南桥，也称为 I/O 控制器中心（`ICH`），连接输入/输出（I/O）设备，如磁盘、键盘、鼠标、光驱和 USB 端口。北桥直接连接到 CPU，速度比南桥快。

## CPU

中央处理单元（CPU）是计算机的“大脑”，能够控制并执行数学计算。归根结底，计算机所做的一切都是数学运算：加法（可扩展为减法、乘法、除法等）、执行逻辑运算、按地址访问内存位置等。CPU 以每秒时钟周期数来衡量性能。一款 2.4 GHz 的奔腾 4 CPU 每秒拥有 24 亿个时钟周期。

### 算术逻辑单元与控制单元

**算术逻辑单元**（ALU）执行数学计算：它进行“运算”。它由*控制单元*提供指令，控制单元充当“指挥官”，将指令发送给 ALU。

### 取指与执行

CPU 取出机器语言指令（如“1 + 1”）并执行它们（相加得出“2”）。**“取指与执行”**（也称为“取指、译码、执行”，或 `FDX`）过程实际上包含四个步骤：

1.  取指令 1
2.  译码指令 1
3.  执行指令 1
4.  写回（保存）结果 1

这四个步骤在一个时钟周期内完成。

### 流水线

**流水线**将多个步骤合并为一个组合过程，允许对不同指令同时进行取指、译码、执行和写回步骤。每个部分称为一个流水线阶段；流水线深度是可同时完成的阶段数量。

以我们之前“1 + 1”的取指执行示例为例，没有流水线的 CPU 必须等待一个完整周期才能执行下一次计算。四阶段流水线可以组合其他四条指令的阶段：

1.  取指令 1
2.  取指令 2，译码指令 1
3.  取指令 3，译码指令 2，执行指令 1
4.  取指令 4，译码指令 3，执行指令 2，写回（保存）结果 1
5.  取指令 5，译码指令 4，执行指令 3，写回（保存）结果 2，以此类推。

流水线类似于汽车装配线：不是一次从头到尾制造一辆车，而是许多汽车进入装配流水线，离散阶段（如安装轮胎）依次在一辆接一辆的车上进行。这提高了吞吐量。

### 中断

**中断**表示发生了异步事件。CPU 中断是一种硬件中断，导致 CPU 停止处理当前任务，保存状态，并开始处理新请求。新任务完成后，CPU 将继续处理先前的任务。

### 进程与线程

**进程**是加载并在内存中运行的可执行程序及其相关数据。“重量级进程”（HWP）也称为任务。父进程可能衍生出称为**线程**的额外子进程。线程是轻量级进程（LWP）。线程可共享内存，与重量级进程相比开销更低。

进程可能处于多种状态：

*   新建：正在创建的进程
*   就绪：等待 CPU 执行的进程
*   运行：正在由 CPU 执行的进程
*   阻塞：等待 I/O
*   终止：已完成的进程

另一种进程类型是“僵尸进程”，即父进程已终止的子进程。

### 多任务与多处理

应用程序作为进程在内存中运行，由可执行代码和数据组成。**多任务**允许多个任务（重量级进程）在一个 CPU 上同时运行。较旧且较简单的操作系统（如 `MS-DOS`）是非多任务的：它们一次运行一个进程。大多数现代操作系统（如 Linux、Windows 10 和 OS X）支持多任务。

> **注意**
>
> 有些资料提及与多任务相关的其他术语，包括多道程序设计和多线程。多道程序设计是多个程序在一个 CPU 上同时运行；多任务是多个任务（进程）在一个 CPU 上同时运行；多线程是多个线程（轻量级进程）在一个 CPU 上同时运行。

## 多道程序设计和多任务处理

多道程序设计是多任务处理的一种较早形式；许多资料将这两个术语同义使用。本书将使用“多任务处理”一词来指代在一个 CPU 上运行的多个同时进行的进程。

**多处理**与多任务处理有根本区别：它在多个 CPU 上运行多个进程。多处理的两种类型是**对称多处理**和**非对称多处理（AMP，某些资料使用 ASMP）**。SMP 系统使用一个操作系统来管理所有 CPU。AMP 系统每个 CPU 拥有一个操作系统映像，本质上表现为独立的系统。

## 看门狗定时器

**看门狗定时器**旨在当关键进程挂起或崩溃时，通过重启来恢复系统。当看门狗定时器归零时，它会重启系统；关键操作系统进程会持续重置该定时器，因此只要它们在运行，定时器永远不会归零。如果关键进程挂起或崩溃，它们将不再重置看门狗定时器，定时器随之归零，系统随即重启。

## CISC 和 RISC

**CISC**（Complex Instruction Set Computer，复杂指令集计算机）和 **RISC**（Reduced Instruction Set Computer，精简指令集计算机）是两种 CPU 设计形式。CISC 使用大量复杂的机器语言指令，而 RISC 使用精简的、更简单的指令集。

关于“最佳” CPU 设计方式一直有争议：底层命令应该更长、更强大，用更少的单个指令执行复杂任务（CISC），还是命令应该更短、更简单，执行复杂任务需要更多单个指令（RISC），但允许每条指令更少的周期和更高效的代码？没有“正确”的答案：两种方法各有优缺点。×86 CPU（以及许多其他）属于 CISC；ARM（用于许多手机和 PDA）、PowerPC、Sparc 等属于 RISC。

## 内存寻址

值可存储在内存的多个位置，包括 CPU 寄存器和通用 RAM。这些值可被直接寻址（“加上存储在这里的值”）或间接寻址（“加上此处引用的内存位置存储的值”）。间接寻址类似于指针。寻址模式取决于 CPU；常见支持的模式包括直接、间接、寄存器直接和寄存器间接。

直接模式表示“将 X 加到存储在内存位置 #YYYY 的值上。”该位置存储数字 7，因此 CPU 执行 X + 7。间接模式起始方式相同：“将 X 加到存储在内存位置 #YYYY 的值上。”区别在于 #YYYY 存储的是另一个内存位置（#ZZZZ）。CPU 顺着指针找到 #ZZZZ，其中存有值 7，并执行 X + 7。

寄存器直接寻址与直接寻址相同，只是它引用 CPU 高速缓存寄存器，如寄存器 1。寄存器间接寻址也与间接寻址相同，只是指针存储在寄存器中。图 4.10 总结了这四种寻址模式。

## 内存保护

内存保护防止一个进程影响另一个进程的机密性、完整性或可用性。这是安全多用户（多个用户同时登录）和多任务（多个进程同时运行）系统的要求。

### 进程隔离

**进程隔离**是一种逻辑控制，旨在防止一个进程干扰另一个进程。这是 Linux、UNIX 或较新的 Microsoft Windows 操作系统等多用户操作系统的常见特性。较旧的操作系统（如 MS-DOS）不提供进程隔离。缺乏进程隔离意味着任何 MS-DOS 应用程序的崩溃都可能导致整个系统崩溃。

如果您在网上购物并输入信用卡号购买书籍，该号码将以明文形式存在于内存中（至少持续一小段时间）。进程隔离意味着同一台计算机上的另一个进程无法干扰您的进程。

干扰包括对机密性的攻击（读取您的信用卡号）、完整性的攻击（修改您的信用卡号）和可用性的攻击（干扰或阻止购买书籍）。

用于提供进程隔离的技术包括虚拟内存（下一节讨论）、**对象封装**和**时间复用**。对象封装将进程视为“黑盒”，我们将在第 9 章（领域 8：软件开发安全）中讨论。时间复用在多个进程之间共享（复用）系统资源，每个进程拥有专用的时间片。

### 硬件分段

硬件分段通过将进程映射到特定内存位置，将进程隔离向前推进了一步。这比（逻辑）进程隔离单独提供更高的安全性。

### 虚拟内存

**虚拟内存**在应用程序和硬件内存之间提供虚拟地址映射。虚拟内存提供多种功能，包括多任务处理（多个任务在一个 CPU 上同时执行）、允许多个进程访问内存中的同一共享库、交换等。

> **考试警告**
>
> 虚拟内存允许交换，但虚拟内存还有其他功能。换句话说，虚拟内存不等于交换。

#### 交换和分页

**交换**利用虚拟内存将主内存（RAM）中的内容复制到辅助内存（CPU 不可直接寻址，位于磁盘上），或从辅助内存复制回主内存。交换空间通常是一个专用磁盘分区，用于扩展可用内存量。如果内核尝试访问存储在交换空间中的页面（固定长度的内存块），会发生缺页中断（表示该页面不在 RAM 中的错误），随即将该页面从磁盘“换入”到 RAM。

> **注意**
>
> “交换”和“分页”常互换使用，但两者略有区别：分页将内存块复制到磁盘或从磁盘复制，而交换将整个进程复制到磁盘或从磁盘复制。本书使用术语“交换”。

大多数配置了虚拟内存的计算机（如图 4.11 所示系统）将仅使用 RAM，直到 RAM 接近或完全填满。随后系统会将进程交换到虚拟内存。它会尝试寻找空闲进程，以使交换的影响最小化。

最终，随着更多进程启动且内存持续填满，RAM 和交换空间都将填满。在系统耗尽可交换的空闲进程后，可能被迫交换活动进程。系统可能开始“颠簸”，花费大量时间在交换空间间复制数据，严重影响可用性。

交换设计为一种保护措施，用于处理偶发的内存使用高峰。系统不应常规性地使用大量交换空间：若出现这种情况，应增加物理内存，或移除、迁移、缩减进程。

## BIOS

### IBM PC 兼容基本输入输出系统

IBM PC 兼容基本输入输出系统包含固件中的代码，这些代码在 PC 上电时执行。它首先运行*加电自检*（POST），执行基本测试，包括验证 BIOS 本身的完整性、测试内存、识别系统设备等任务。一旦 POST 过程成功完成，它会定位引导扇区（对于从磁盘启动的系统），其中包含操作系统内核的机器代码。随后内核加载并执行，操作系统启动。

## WORM 存储

**WORM**（一次写入，多次读取）存储只能写入一次，但可读取多次。它常用于支持法律或法规合规性要求的记录保留。WORM 存储有助于确保其所含数据的完整性：除非销毁介质本身，否则可以确信数据未被（也无法被）篡改。

最常见的 WORM 介质类型是 CD-R（可刻录光盘）和 DVD-R（可刻录数字多功能光盘）。请注意，CD-RW 和 DVD-RW（可重写）不属于 WORM 介质。某些数字线性磁带（DLT）驱动器和介质支持 WORM 功能。

## 可信平台模块

由可信计算组开发和更新的可信平台模块（TPM）芯片是一种处理器，可在硬件级别提供额外的安全功能。并非所有计算机制造商都采用 TPM 芯片，但其采用率稳步上升。如果包含 TPM 芯片，通常位于系统的主板上。

TPM 芯片支持基于硬件的加密操作。安全功能可利用 TPM 进行随机数生成、使用对称、非对称和哈希算法，以及安全存储加密密钥和消息摘要。TPM 芯片最常见的用例是确保启动完整性。通过在硬件级别运行，TPM 芯片有助于确保内核模式 Rootkit 更难以破坏操作系统安全。除了启动完整性，TPM 还通常与某些全盘加密实现相关联。在加密场景下，TPM 可用于安全存储解密硬盘所需的密钥。

鉴于存储了高度敏感和宝贵的信息，TPM 芯片本身可能成为攻击者的目标。由于 TPM 基于硬件，从操作系统远程篡改 TPM 的可能性大大降低。TPM 芯片还具有防篡改特性，旨在确保物理上受损的 TPM 芯片不会导致其提供的安全功能被轻易绕过。

## 数据执行保护和地址空间布局随机化

试图利用软件漏洞时的主要目标之一是实现某种形式的代码执行能力。概念上，攻击者希望提供自己选择的指令或提供的代码，由受损应用程序执行。例如，通过基于栈或堆的缓冲区溢出条件故意破坏系统内存，是攻击者常用的手段。

针对这类内存破坏或溢出攻击，最显著的两种保护机制是 DEP（数据执行保护）和 ASLR（地址空间布局随机化）。DEP 可在硬件和/或软件中启用，旨在确保未预定义包含可执行内容的内存位置无法执行代码。例如，攻击者利用允许攻击者提供的 Shellcode 最终位于内存中通用数据存储位置的缓冲区溢出漏洞。若启用了 DEP，且该位置未被标记为预期包含可执行内容，则成功利用可能被缓解。

另一种保护机制 ASLR 旨在通过使系统使用的内存地址更难预测，从而降低成功利用的可能性。在开发漏洞利用代码和构建后利用能力时，利用代码会利用运行中系统上已加载的现有代码。如果这些组件始终位于相同的内存地址，则利用难度会降低。通过随机化内存地址，攻击者面临更难利用的目标。作为 ASLR 成功的一个例子，设想攻击者在自己的测试机器上开发出一个成功的可用漏洞利用代码。当该代码（依赖特定操作系统库和代码位于可预测的内存地址）移植到启用了 ASLR 的机器上时，漏洞利用可能会失败。

这些保护机制的目标常被认为是防止利用。然而，这一目标虽值得赞赏，但永远无法始终如一地实现。更准确地说，这些缓解技术的目标应被视为试图增加攻击者开发漏洞利用代码的成本。

# 安全操作系统和软件架构

安全操作系统和软件架构建立在上一节所述的安全硬件之上，在硬件与访问硬件的应用程序（及用户）之间提供安全接口。操作系统提供内存、资源和进程管理。

## 内核

内核是操作系统的核心，通常运行在 Ring 0。它提供硬件与操作系统其余部分（包括应用程序）之间的接口。如前所述，当 IBM 兼容 PC 启动或重启时，BIOS 会定位存储设备（如硬盘）的引导扇区。该引导扇区包含软件内核机器代码的开头部分，随后被执行。内核有两种基本设计：*单内核*和*微内核*。

单内核被编译成一个静态可执行文件，整个内核运行在管理员模式下。单内核所需的所有功能必须预先编译进去。例如，如果你有一个不支持 FireWire 接口的单内核，并向系统插入 FireWire 设备，该设备将无法工作。内核需要重新编译以支持 FireWire 设备。

微内核是模块化内核。微内核通常较小，原生功能比典型单内核少（因此称为“微”），但可通过可加载内核模块添加功能。微内核也可能在用户模式（通常为 Ring 3）而非管理员模式下运行内核模块。沿用前例，原生微内核不支持 FireWire。插入 FireWire 设备后，内核加载 FireWire 内核模块，设备即可工作。

### 参考监视器

内核的核心功能是运行*参考监视器*，它调解主体与客体之间的所有访问。它强制执行系统的安全策略，例如阻止普通用户写入受限文件（如系统密码文件）。在强制访问控制（MAC）系统中，参考监视器阻止机密主体读取绝密客体。参考监视器始终启用且无法绕过。安全系统可对参考监视器的安全性进行评估。

文件权限（如读、写、执行）控制对文件的访问。可用的权限类型取决于所使用的文件系统。

- **读取**（“r”）
- **写入**（“w”）

### Microsoft NTFS 权限

Microsoft NTFS（新技术文件系统）具有以下基本文件权限：

*   读取
*   写入
*   读取和执行
*   修改
*   完全控制（读取、写入、执行、修改，此外还包括更改权限的能力）

NTFS 的权限类型比大多数 UNIX 或 Linux 文件系统更多。NTFS 文件由所有者控制，所有者可向其他用户授予权限。图 4.14 显示了位于 `C:\Users\Public\Pictures\Sample Pictures\Penguins.jpg` 的示例照片的权限。
