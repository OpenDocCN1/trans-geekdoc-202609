
**4chan's Group** 使用智能合约创建了 **Proof of Weak Hands Coin**（POWH）。尽管它被设置为庞氏骗局，但人们仍继续投资。然而，POWH 代币的开发者未能保护所有操作，也无法针对溢出和下溢攻击建立足够的防护。通过利用这一编码疏忽，一名未知黑客窃取了价值至少 1,000,000 美元的 2000 ETH [8]。

### 未检查的返回值

在 Solidity 中有多种执行外部调用的方式，其中 `transfer` 是常用于向外部账户发送以太币的方法之一。`send` 函数也被使用，它执行消息调用，并将以太币转移到指定地址。另一方面，对于更灵活的外部调用，Solidity 中直接使用 `CALL` 操作码。如果这些操作中的任何一个成功或失败，`call` 和 `send` 函数将返回一个布尔值指示状态。如果外部调用失败，执行 `call` 和 `send` 函数的交易不会返回（revert），调用函数的执行将自然继续，而函数将返回布尔值 `false`。开发者期望外部调用失败时会发生返回，从而未能检查 `false` 返回值（图 14.4）[1]。

**Etherpot** 是一个智能合约彩票。由于区块哈希的错误使用而失败。在 Etherpot 中，使用区块的哈希值——具体为决策区块——来决定获胜者。理论上，获胜者可以在任何时候被计算并报告为获胜者。但在获胜者在决策区块的 256 个区块内退出之前，区块哈希函数返回 0。该合约受到未检查调用值的影响 [1]。

### DoS 攻击

拒绝服务攻击可以采取以下几种形式：

*   **区块 Gas 限制 DoS**：以太坊区块链上的每个区块都有 Gas 限制。区块 Gas 限制的优势在于防止攻击者构建无限交易循环。然而，如果交易的 Gas 消耗达到此限制，交易将失败。这可能以多种方式导致 DoS 攻击 [15]。

*   **通过区块填充进行的网络 Gas 限制 DoS**：无论智能合约是否包含无界循环，恶意行为者都可以使用一系列高 Gas 价格的交易，阻止其他交易在多个区块中被区块链处理。攻击者发布了多笔消耗整个 Gas 限制的交易。攻击者试图用大量交易填满整个区块，如果这些交易中的 Gas 价格很高，就可以阻止其他交易被处理 [15]。

*   **意外回滚 DoS**：当用户尝试向另一个用户转账且功能依赖于交易成功时，会发生 DoS（拒绝服务）攻击。如果资金被转移到攻击者创建的智能合约，这允许攻击者创建一个回退函数以回滚所有付款（图 14.5）[15]。

#### 通过 Revert 实现的拒绝服务

在这种情况下，如果攻击者从一个带有回退函数的智能合约进行竞价，该函数会撤销所有支付。他们将永远无法获得退款，且没有人能够再出价超过他们。在 Revert 数组函数代码中，用户希望通过遍历数组来支付一组用户，并希望确保每位用户都能得到公平支付。问题在于，如果某笔支付失败，整个函数将被回滚，导致无人获得补偿 [15]。

#### 真实案例场景

一个收集了大量以太币的庞氏骗局是 *GovernMental*。它曾一度积累了 1100 个以太，但容易受到 DoS 漏洞攻击。为了提取以太币，合约修改涉及消除一个主要映射。删除该映射的 Gas 开销达到了区块 Gas 上限，因此这 1100 个以太无法被提取 [1]。

### 竞态条件

竞态条件是一种发生在多用户环境中的攻击，用户对竞态代码的执行会导致不良事件 [1]。当矿工与智能合约的参与者竞争，通过更改合约中的权限，将矿工的交易插入到原始交易之前时，可能会发生区块链竞态条件 [2]。

在以太坊区块链上，区块由以太坊节点处理的交易池形成。当矿工解决“工作量证明”机制时，区块才有效。以太坊平台上的交易费被称为“Gas”，其价格由矿工设定。通常，矿工决定哪笔交易应被包含在区块中，并根据每笔交易的“Gas 价格”从一组有序交易中选择。如前所述，以太坊是一个公共区块链，允许用户查看其他用户的待处理交易。攻击者可以查看包含合约中工作量证明解决方案的交易，从而从交易中获取数据。随后，攻击者可以创建一笔 Gas 价格更高的交易并将其包含在区块中，以获取合约中的以太币。在竞态条件中，潜在的攻击向量可能修改合约中的权限，这种修改可能对解题者产生不利影响 [1]。

根据 2021 年以太坊更新（EIP-1559），最新的交易费方法是将费用拆分为基础费用和“小费”，其中基础费用根据每笔交易的一组算法自动计算。此外，交易现在直接发送到网络，而不是发送给矿工。进一步解释，“小费”指用户为加快交易处理而自愿支付的额外费用。这种最新的交易费方法还能防止恶意行为者垃圾交易（图 14.7） [10]。

图 14.7  导致竞态条件漏洞的示例代码缺陷 [1]。 ¶ 来源：[25]。

#### 真实案例场景

*Bancor* 是一个知名平台，它促进了在以太坊区块链上无需 *买家* 和 *卖家* 干预即可进行数字资产交换 [3]。Ivan Bogatty 及其团队成员记录了一次针对 Bancor 的攻击。由于以太坊的公开性质，交易在广播到网络时对所有人可见 [1]。这些交易位于待处理交易部分，等待被打包。如果攻击者有足够的时间抢跑待处理交易，并以略高于原价的价格买入订单，该攻击者就能获利 [3]。

### 短地址攻击

短地址攻击是针对第三方应用程序执行的攻击。短地址或参数攻击展示了攻击者如何操纵参数以访问合约中的代币。尽管现实中尚无此类攻击的案例，但本节解释的概念场景有助于说明此类攻击中参数如何被操纵 [1, 26]。

短地址攻击允许攻击者绕过长度小于指定长度的参数；例如，发送一个 35 个十六进制字符的地址，而不是 40 个十六进制字符。在这种情况下，以太坊虚拟机默认会在该地址末尾填充零以匹配预期长度。当第三方应用程序未验证输入时，这会导致攻击（图 14.8） [1]。

### 时间戳依赖

时间戳依赖是另一种可被恶意矿工利用的漏洞。这是由于智能合约中对时间记录的不完美解读导致的，其结果是以太坊网络脱离了同步的全球时钟。例如，以太坊智能合约使用当前时间戳生成随机数，并根据结果发放奖励。其工作原理如下：当智能合约使用时间戳生成随机数时，恶意矿工会在区块验证前后 30 秒内发布一个时间戳，从而改变合约的执行结果以使其获利。因此，随机数生成器的结果可以被篡改（图 14.9）[8]。

#### 真实案例场景

`GovernMental` 是一个积累了大量以太币的庞氏骗局。`GovernMental` 合约按轮次收集玩家的以太币，并且每局游戏只向单个获胜者支付奖金。合约奖励给每轮中最后加入的玩家（至少晚一分钟）。该游戏的持续赢家是一名矿工，他能够调整时间戳，使其看起来像该玩家是最后加入的 [9]。

## 智能合约审计考量

### 智能合约审计

智能合约审计旨在验证底层代码。此类审计有助于识别漏洞，并确保在合约部署到区块链之前对合约代码进行审查。目前，智能合约审计方法采用 (i) 交易样本以分析重大错报风险，(ii) 年度时间点审计方法，以及 (iii) 回溯审计方法。

企业组织采用智能合约以提高业务效率。审计师可以选择从不同供应商处购买数据分析工具。审计师还可以集成多种审计工具，以实现透明及时的审计报告 [19, 25]。

### 控制流分析工具

#### McCabe IQ

可利用流程图和带注释的源代码清单，对攻击图中的每个特性进行详细审查。路径信息会经过测试，以确保所显示的控制流路径准确、稳定且符合规范 [31]。

McCabe IQ 的数据字典功能是另一种策略，可用于更彻底地调查程序代码中使用的禁用函数。用户可在数据字典中扫描数据元素和函数调用，并对包含这些调用的函数内的路径进行分类 [31]。该工具可在 GitHub 上获取：[`github.com/PyCQA/mccabe`](https://github.com/PyCQA/mccabe)。

#### 以太坊虚拟机

EVM 由一个建立在具有自定义指令格式的栈上的单一虚拟机组成。每条指令均表现为一个单字节操作码。在数据栈上传递参数。用于将常量压入栈的 push 指令是唯一例外。这些常量直接转换为指令的字节。由于 EVM 具有用于简单块入口的显式标记，因此检索基本块边界是可行的 [30]。该工具可在 GitHub 上获取：[`github.com/exthereum/evm`](https://github.com/exthereum/evm)。

### 污点分析工具

#### TAJ

Java 污点分析 (TAJ) 是一种旨在以足够可靠性生成低误报率，并具有足够通用性以允许评估大型应用程序的方法。TAJ 提供了一系列策略，可在极大型程序上产生实际效果，尽管它们受限于给定的时间或内存预算。当实现极其庞大且最终用户仍希望分析在有限时间内终止或保持在指定内存使用水平内时，TAJ 主张采用优先级方法，将研究重点放在可能参与污点传播的 Web 应用程序部分上 [27]。该工具可在 GitHub 上获取：[`github.com/TJAndHisStudents/TaintFlowAnalysis`](https://github.com/TJAndHisStudents/TaintFlowAnalysis)。

#### DYTAN

动态污点分析因数据流和控制流而能充分管理程序内的知识流，并支持在不同维度上定制分析。通过动态污点技术可避免 SQL 注入攻击，攻击者会向 Web 服务器发送恶意构造的字符串以进入底层数据库。大多数基于动态污点的 SQL 注入防范方法通过污染和监控来自用户的不安全输入文件来工作。一旦查询字符串提交给数据库，就会对其进行审查，以确保该字符串或其片段未使用任何已损坏的数据生成 [28]。该工具可在 GitHub 上获取：[`github.com/behzad-a/Dytan`](https://github.com/behzad-a/Dytan)。

### 动态代码分析工具

#### MAIAN
