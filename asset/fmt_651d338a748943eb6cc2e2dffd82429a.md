
## 8.4 Channel

如果 goroutine 是并发 Go 程序的活动，那么 *channel* 就是它们之间的连接。Channel 是一种通信机制，它让一个 goroutine 可以向另一个 goroutine 发送值。每个 channel 都是特定类型值的传输管道，这种类型被称为 channel 的*元素类型*。元素类型为 `int` 的 channel 类型写作 `chan int`。

要创建一个 channel，我们使用内置的 `make` 函数：

```
ch := make(chan int) // ch 的类型为 'chan int'
```

与 map 类似，channel 是对 `make` 创建的数据结构的*引用*。当我们复制一个 channel 或将其作为参数传递给函数时，我们复制的是引用，因此调用者和被调用者引用的是同一个数据结构。与其他引用类型一样，channel 的零值是 `nil`。

同类型的两个 channel 可以使用 `==` 进行比较。如果两者引用同一个 channel 数据结构，则比较结果为真。Channel 也可以与 `nil` 进行比较。

Channel 有两个主要操作，*发送* 和 *接收*，统称为*通信*。发送语句将一个值从一个 goroutine 通过 channel 传输到另一个正在执行相应接收表达式的 goroutine。这两个操作都使用 `<-` 运算符。在发送语句中，`<-` 分隔 channel 和值操作数。在接收表达式中，`<-` 写在 channel 操作数之前。结果未被使用的接收表达式是一条有效的语句。

```
ch <- x  // 一条发送语句

x = <-ch // 赋值语句中的接收表达式
<-ch     // 一条接收语句；结果被丢弃
```

Channel 支持第三种操作 *close*，它设置一个标志，表明该 channel 不会再有值发送；后续的发送尝试将引发 panic。对已关闭 channel 的接收操作会先取出已发送的值，直到没有值剩余；此后的任何接收操作会立即完成，并产出 channel 元素类型的零值。

要关闭一个 channel，我们调用内置的 `close` 函数：

```
close(ch)
```

通过简单调用 `make` 创建的 channel 称为*无缓冲* channel，但 `make` 接受一个可选的第二个参数，即 channel 的*容量*。如果容量非零，`make` 会创建一个*有缓冲* channel。

```
ch = make(chan int)    // 无缓冲 channel
ch = make(chan int, 0) // 无缓冲 channel
ch = make(chan int, 3) // 容量为 3 的有缓冲 channel
```

我们将首先介绍无缓冲 channel，然后在 8.4.4 节 介绍有缓冲 channel。

### 8.4.1 无缓冲 Channel

在无缓冲 channel 上的发送操作会阻塞发送 goroutine，直到另一个 goroutine 在同一个 channel 上执行接收操作，此时值被传输，两个 goroutine 都可以继续执行。反之，如果先尝试接收操作，接收 goroutine 会阻塞，直到另一个 goroutine 在同一个 channel 上执行发送。

通过无缓冲 channel 的通信会导致发送和接收的 goroutine *同步*。因此，无缓冲 channel 有时被称为*同步* channel。当一个值被发送到无缓冲 channel 时，该值的接收 *happens before*（发生在……之前） 发送 goroutine 的重新唤醒。

在并发讨论中，当我们说 *x happens before y* 时，我们不仅仅是指 *x* 在时间上比 *y* 早发生；我们是指保证它一定如此，并且 *x* 所有先前的效果（如变量更新）均已完成，你可以依赖它们。

当 *x* 既不 happens before *y*，也不 happens after *y* 时，我们说 *x 与 y 并发*。这并不意味着 *x* 和 *y* 一定是同时发生的，只是意味着我们无法对它们的顺序做任何假设。正如我们在下一章将看到的，为了避免两个 goroutine 并发访问同一变量所引发的问题，有必要在程序执行期间对某些事件进行排序。

8.3 节 中的客户端程序在其主 goroutine 中将输入复制到服务器，因此一旦输入流关闭，客户端程序就会终止，即使后台 goroutine 仍在工作。为了让程序在退出前等待后台 goroutine 完成，我们使用一个 channel 来同步这两个 goroutine：

gopl.io/ch8/netcat3

```
func main() {
    conn, err := net.Dial("tcp", "localhost:8000")
    if err != nil {
        log.Fatal(err)
    }
    done := make(chan struct{})
    go func() {
        io.Copy(os.Stdout, conn) // 注意：忽略错误
        log.Println("done")
        done <- struct{}{} // 通知主 goroutine
    }()
    mustCopy(conn, os.Stdin)
    conn.Close()
    <-done // 等待后台 goroutine 完成
}
```

当用户关闭标准输入流时，`mustCopy` 返回，主 goroutine 调用 `conn.Close()`，关闭网络连接的两个半边。关闭写半边会导致服务器看到文件结束条件。关闭读半边会导致后台 goroutine 对 `io.Copy` 的调用返回“read from closed connection”错误，这就是为什么我们移除了错误日志记录；练习 8.3 建议了一个更好的解决方案。（注意 `go` 语句调用了一个字面量函数，这是一种常见的构造模式。）

在返回之前，后台 goroutine 记录一条消息，然后在 `done` channel 上发送一个值。主 goroutine 等待直到接收到该值才返回。因此，程序在退出前总会记录 `"done"` 消息。

通过 channel 发送的消息有两个重要方面。每条消息都有一个值，但有时通信这一事实及其发生的时刻同样重要。当我们想强调这一方面时，我们称消息为*事件*。当事件不携带额外信息时，即其唯一目的是同步，我们会通过使用元素类型为 `struct{}` 的 channel 来强调这一点，尽管使用 `bool` 或 `int` 类型的 channel 也很常见，因为 `done <- 1` 比 `done <- struct{}{}` 更简短。

**练习 8.3：** 在 `netcat3` 中，接口值 `conn` 的具体类型是 `*net.TCPConn`，它代表一个 TCP 连接。TCP 连接由两个半边组成，可以分别使用其 `CloseRead` 和 `CloseWrite` 方法独立关闭。修改 `netcat3` 的主 goroutine，使其仅关闭连接的写半边，这样即使标准输入已关闭，程序仍将继续打印来自 `reverb1` 服务器的最终回显。（对于 `reverb2` 服务器这样做更难；请参阅 练习 8.4。）

### 8.4.2 Pipeline

Channel 可以用来将 goroutine 连接在一起，使一个的输出成为另一个的输入。这被称为*管道*。下面的程序由三个 goroutine 和两个 channel 连接而成，如 图 8.1 所示。

![三阶段管道示意图。](img/csp.png)

**图 8.1.** 三阶段管道。

第一个 goroutine `counter` 生成整数 0、1、2……，并通过一个 channel 将它们发送给第二个 goroutine `squarer`，后者接收每个值，计算其平方，并通过另一个 channel 将结果发送给第三个 goroutine `printer`，后者接收平方值并将其打印出来。为了示例的清晰性，我们特意选择了非常简单的函数，尽管当然在实际程序中，它们的计算太过简单，不值得拥有各自独立的 goroutine。

点击此处查看代码图像

`gopl.io/ch8/pipeline1`

```
func main() {
    naturals := make(chan int)
    squares := make(chan int)

    // Counter
    go func() {
        for x := 0; ; x++ {
            naturals <- x
        }
    }()

    // Squarer
    go func() {
        for {
            x := <-naturals
            squares <- x * x
        }
    }()

    // Printer (在 main goroutine 中)
    for {
        fmt.Println(<-squares)
    }
}
```

正如你所料，该程序打印无限的平方数序列 0、1、4、9，依此类推。这种管道可能存在于长期运行的服务器程序中，在这些程序中，channel 被用于包含无限循环的 goroutine 之间的终身通信。但如果我们只想通过管道发送有限数量的值怎么办？

如果发送者知道某个 channel 上永远不会再发送更多值，那么将这一事实告知接收者 goroutine 会很有用，这样它们就可以停止等待。这通过使用内置的 `close` 函数*关闭* channel 来实现：

```
close(naturals)
```

在一个 channel 被关闭后，对它的任何进一步发送操作都将 panic。在关闭的 channel 被*耗尽*后，即最后一个发送的元素被接收后，所有后续的接收操作将不再阻塞，但会产出零值。关闭上面的 `naturals` channel 将导致 squarer 的循环空转，因为它接收到源源不断的零值，并将这些零值发送给 printer。

无法直接测试一个 channel 是否已被关闭，但接收操作有一个变体可以产生两个结果：接收到的 channel 元素，外加一个布尔值，通常称为 `ok`，成功接收时为 `true`，在已关闭且已耗尽的 channel 上接收时为 `false`。利用这一特性，我们可以修改 squarer 的循环，使其在 `naturals` channel 耗尽时停止，并依次关闭 `squares` channel。

点击此处查看代码图像

```
// Squarer
go func() {
    for {
        x, ok := <-naturals
        if !ok {
            break // channel 已关闭且已耗尽
        }
        squares <- x * x
    }
    close(squares)
}()
```

由于上述语法笨拙且这种模式很常见，Go 语言允许我们使用 `range` 循环来迭代 channel。这是一种接收 channel 上发送的所有值并在最后一个值之后终止循环的更方便的语法。

在下面的管道中，当 counter goroutine 在处理完 100 个元素后结束循环，它会关闭 `naturals` channel，导致 squarer 结束其循环并关闭 `squares` channel。（在更复杂的程序中，让 counter 和 squarer 函数在一开始就 defer 调用 `close` 可能更合理。）最后，main goroutine 结束其循环，程序退出。

点击此处查看代码图像

`gopl.io/ch8/pipeline2`

```
func main() {
    naturals := make(chan int)
    squares := make(chan int)

    // Counter
    go func() {
        for x := 0; x < 100; x++ {
            naturals <- x
        }
        close(naturals)
    }()

    // Squarer
    go func() {
        for x := range naturals {
            squares <- x * x
        }
        close(squares)
    }()

    // Printer (在 main goroutine 中)
    for x := range squares {
        fmt.Println(x)
    }
}
```

当你用完某个 channel 时，不必关闭每一个 channel。只有当需要告诉接收 goroutine 所有数据已发送完毕时，才有必要关闭 channel。垃圾回收器判定为不可达的 channel，无论是否关闭，其资源都会被回收。（不要将这与打开文件的 close 操作混淆。用完文件后，*必须*调用每个文件的 `Close` 方法。）
