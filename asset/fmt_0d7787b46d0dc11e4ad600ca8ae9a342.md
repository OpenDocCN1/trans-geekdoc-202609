
# OWL 谓词

OWL 谓词是有向的二元关系类型，将主语个体（实例）映射到宾语个体。OWL 包含一个预定义的通用类 `owl:Thing`，它包含所有个体。它还预定义了空类 `owl:Nothing`，该类没有成员。默认情况下，所有 OWL 谓词都具有无限制的定义域和值域（等于 `owl:Thing`）。

`Object properties`（对象属性）是将实体关联到实体的二元谓词。`Data properties`（数据属性）是将实体关联到字面量的二元谓词。例如：

```
ObjectProperty: wasBornIn
DataProperty: hasName
Individual: Einstein
Facts: wasBornIn Germany, hasName "Albert Einstein"^^xsd:string
```

以下极端的 OWL 谓词（“属性”）是预定义的。`owl:topObjectProperty` 是所有对象属性的类，因此是一个将模型中所有个体关联到模型中所有个体的二元谓词（其外延是笛卡尔积 `owl:Thing × owl:Thing`）。每个对象属性都是该属性的子属性。`owl:topDataProperty` 是所有数据属性的类，因此是一个将所有个体关联到所有字面量的二元谓词。每个数据属性都是该属性的子属性。`owl:bottomObjectProperty` 是空对象属性，因此是每个对象属性的子属性。`owl:bottomDataProperty` 是空数据属性，因此是每个数据属性的子属性。

`Annotation properties`（标注属性）是提供关于本体、陈述或 IRI 的非正式文档标注的二元谓词。例如，`rdfs:comment` 标注属性用于提供注释，如下例所示：

```
Class: Moon
Annotations: rdfs:comment "Natural satellite of a planet or other celestial body."
```

其他预定义的标注属性如下所示：

*   `rdfs:label` 标注属性用于提供人类可读的标签。
*   `rdfs:seeAlso` 标注属性用于将一个 IRI 与另一个 IRI 关联，使后者提供关于前者的附加信息。
*   `rdfs:isDefinedBy` 标注属性用于将一个 IRI 与另一个 IRI 关联，使后者提供前者的定义。
*   具有 `owl:deprecated` 标注属性且值等于 `true^^xsd:boolean` 的标注，用于指定某 IRI 已被弃用。
*   `owl:versionInfo` 标注属性用于将一个 IRI 与一个描述该 IRI 版本的字符串关联。
*   `owl:priorVersion` 标注属性指定包含本体的先前版本的 IRI。
*   `owl:backwardCompatibleWith` 标注属性指定包含本体的先前版本的 IRI，该版本与包含本体的当前版本兼容。
*   `owl:incompatibleWith` 标注属性指定包含本体的先前版本的 IRI，该版本与包含本体的当前版本不兼容。

OWL 工具通常支持 `ontology parsing`（本体解析）——即将以特定语法编写的本体文档转换为 OWL 本体的过程。根据所用语法，本体解析器可能需要知道哪些 IRI 用于哪种实体类型（例如，谓词是对象属性、数据属性还是标注属性？）。例如，`wasBornIn` 是对象属性还是数据属性？这种类型信息可以从声明中提取——将 IRI 与实体类型关联的公理（例如，`ObjectProperty: wasBornIn`）。

## 比较个体、类、数据类型和谓词

OWL 预定义了 `owl:sameAs` 和 `owl:differentFrom` 谓词，分别用于个体之间的“=”和“≠”（因此它们的定义域和值域均为 `owl:Thing`）。这些谓词用于声明同一文档或不同文档中的两个 IRI 是指代同一个体还是不同个体，例如：

```
Individual: Elvis
SameAs: TheKing
DifferentFrom: Donovan
```

OWL 预定义了 `owl:equivalentClass` 谓词以等同两个类或类表达式。在 Manchester 语法中，这称为 `EquivalentTo`，例如：

```
Class: Human
Class: Person
EquivalentTo: Human
```

在 Manchester 语法中，`EquivalentTo` 也可用于定义 `data range`（数据范围）。例如，数据类型 `RatingNr` 可限制为 {1..7}，即 `Datatype: RatingNr EquivalentTo: integer[>= 1, <=7]`。

在 Manchester 语法中，`DisjointWith` 谓词用于声明两个类（或类表达式）互斥，例如：

```
Class: Cat
DisjointWith: Dog
```

预定义类 `DisjointClasses` 是其成员两两互斥的类（即每一对成员类都是不相交的）。在 Manchester 语法中，在两个或多个类描述前加上 `DisjointClasses:` 表示它们互斥（因此没有共同实例）。这提供了一种声明多个类两两不相交的高效方式。

在 ORM 中，顶层实体类型被假定为互斥。例如，在图 18.23(a) 的 ORM 模式中，如果 Person、Car 和 Dog 不是子类型，则假定它们是不相交的。然而在 OWL 中，这种不相交性需要显式声明，如图 18.23(b) 的第一条语句所示。

![图 18.23 在 (a) ORM 和 (b) OWL（Manchester 语法）中声明某些事实类型。](img/f18-23-9780443237904.jpg)

使用 `DisjointClasses` 的单个语句等同于使用 `DisjointWith` 为每一对声明不相交性的冗长方法。`Domain` 和 `Range` 规范将谓词限制为指定的对象类型。

给定以下语句：

```
Individual: Adam
Types: Man
Individual: Eve
Types: Woman
DisjointClasses: Man, Woman
```

我们可以推断：

```
Individual: Adam
DifferentFrom: Eve
```

在 Manchester 语法中，`SubPropertyOf` 谓词可用于声明一个谓词的所有（主语，宾语）实例必须是另一个谓词的实例。一旦声明了资源，您可以一次性列出其所有属性。例如，您可以将 `fatherhood` 谓词及其超属性、域和范围一起声明，如下所示：

```
ObjectProperty: isFatherOf
    SubPropertyOf: isaParentOf
    Domain: MalePerson
    Range: Person
```

在 Manchester 语法中，`DisjointWith` 谓词可用于指示二元谓词的总体必须是*互斥*的。这等同于 ORM 中的成对排除约束。例如，没有人既撰写又审阅同一本书的排除约束可以按如下方式指定：

```
ObjectProperty: authored
    Domain: Person
    Range: Book
ObjectProperty: reviewed
    Domain: Person
    Range: Book
    DisjointWith: authored
```

如果两个以上的谓词互斥，只需在 `DisjointProperties` 标题后列出它们即可，效率更高，例如：

```
ObjectProperty: gotFirstPlaceIn
ObjectProperty: gotSecondPlaceIn
ObjectProperty: gotThirdPlaceIn
DisjointProperties: gotFirstPlaceIn, gotSecondPlaceIn, gotThirdPlaceIn
```

如果两个谓词必须始终具有相同的实例总体，则称它们为（实质上）等价。这等同于在两个方向上声明 `subPropertyOf` 关系。在 Manchester 语法中，通过在 `EquivalentProperties` 标题后列出谓词来声明谓词间的等价性。

例如，确保人们开车当且仅当他们拥有该车的 ORM 成对等值约束（该约束实际上适用于某些出租车公司）可按如下方式指定：`EquivalentProperties: owns, drives`。

等价属性的另一个用途是支持同一文档（或不同文档）中谓词读法的同义词，例如，`EquivalentProperties: worksFor, isEmployedBy`。等价属性的第三个用途是为派生谓词指定派生规则。

## Functional、Inverse、Mandatory 和 Key 关系

默认情况下，所有 OWL 谓词都是可选的且为多对多（`m:n`）。尽管用于等同和区分个体的预定义谓词具有无限制的域和范围，但用户定义的谓词通常至少显式声明一个域和一个范围。对于 ORM、ER 和 UML 等信息建模方法中声明的关系，情况总是如此。

图 18.24(a) 描绘了两个 ORM 事实类型。事实类型“Politician was born in Country”是一个多对一（`n:1`）关联（每个政客最多出生在一个国家，许多政客可能出生在同一个国家）。两个角色都是可选的，因为我们的知识可能不完整。事实类型“Politician heads/is headed by Country”是 1:1 的（每个政客最多领导一个国家，每个国家最多由一个政客领导）。

![图 18.24 (a) ORM 和(b) OWL Manchester 语法中的 n:1 和 1:1 关联。](img/f18-24-9780443237904.jpg)

图 18.24 (a) ORM 和(b) OWL Manchester 语法中的 `n:1` 和 `1:1` 关联。

图 18.24(b) 使用 Manchester 语法在 OWL 中描绘了 ORM 模式。OWL 令人困惑地使用术语“property”来表示谓词。因此，`n:1` 谓词被称为*函数属性*。函数谓词被声明为对象属性，然后通过在其*characteristics* 中包含 `Functional` 来声明其函数性质。对函数属性的了解使 OWL 工具能够进行有用的推理。例如，给定：

```
Individual: Terry
Facts: wasBornIn TheLuckyCountry, wasBornIn Australia
```

我们可以推断：

```
TheLuckyCountry SameAs Australia
```

ORM 将基本事实类型视为一个或多个类型化谓词的集合。在图 18.24(a) 中，政府首脑事实类型具有前向谓词读法“heads”，以及一个从 Country 指向 Politician 的*逆向*谓词读法“is headed by”（正斜杠“/”分隔前向和逆向读法）。

OWL 允许您使用 `owl:inverseOf` 谓词声明一个谓词为另一个谓词的逆向。在 Manchester 语法中，您可以在逆向谓词前加上 `InverseOf:`，例如，`ObjectProperty: isaChildOf InverseOf: isaParentOf`。

函数和逆函数声明*全局*适用于所有上下文中的谓词。然而，OWL 基数约束仅局部适用于在局部上下文中引入的域类。基数限制的这种局部性质与信息建模中的常规方法截然不同。

*OWL 不允许为数据属性声明逆向*，部分原因是它*永远不允许字面量成为谓词的主语*。这很遗憾，因为我们可能希望谈论字面量。

考虑数据属性 `Person misspelt Word`。OWL 不允许我们声明其逆向 `Word wasMisspeltBy Person`。此外，OWL 不允许我们断言事实类型 `Word is a synonym for Word`。为了在 OWL 中解决此类问题，您必须采取变通方法，例如将 `Word` 视为实体类型而非值类型（字面量类型）。

考虑事实类型 `Person is in Country` 和 `City is in Country`。在 ORM、ER 和 UML 等信息建模方法中，这两个 `is in` 谓词将被视为不同的谓词/关系/关联。然而，在 OWL 中，我们可以通过为它们分配相同的 IRI，将这些视为*同一谓词的不同出现*。

*OWL 不允许声明数据属性为逆函数*。实际上，许多数据属性要么是 1:1 要么是 1:`n`，因此要求对字面量所扮演的角色施加唯一性约束。虽然我们不能将字面量角色上的唯一性约束声明为逆函数特征，但我们可以在 OWL 2 中使用 `HasKey` 声明来指定此类约束。

在图 18.24(a) 中，政客由其姓名标识，国家由其国家代码标识。ORM 图使用带括号的引用模式紧凑地描绘了这一点，但在内部这些被扩展为单射（强制、1:1）引用关系 `Politician has PoliticianName` 和 `Country has CountryCode`。

不幸的是，`HasKey` 特性只能部分满足为实体类型指定标识方案（简单或复合）的需求，因为*`HasKey` 仅捕获数据属性的逆函数性质*。

此特性的名称选择“HasKey”略显误导，因为它比关系数据库中“键”的概念要弱。为了完全捕获标识方案，我们需要显式声明数据属性既是函数的又是强制的。

在 Manchester 语法中，每个 `Politician` 都有一个姓名的*强制角色约束*通过使用 `SubClassOf` 属性来声明 `Politician` 是那些在 `hasPoliticianName` 谓词中扮演主语角色且 `minCardinality` 为 1（或更多）的事物的子类来表示，如下所示：

```
Class: Politician
    SubClassOf: hasPoliticianName min 1
```

`maxCardinality` 为 1 的声明可以用类似的方式使用 `max 1` 来表示，这是声明谓词为函数式的另一种方式。如果 `minCardinality = maxCardinality`，可以使用 `exactCardinality` 一次性设置两者。例如，`Politician`（政治家）的 1:1 引用方案可以在 OWL 2 中按如下方式声明：

```
Class: Politician
SubClassOf: hasPoliticianName exactly 1
HasKey: hasPoliticanName
DataProperty: hasPoliticianName
Domain: Politician
Range: PoliticianName
```

现在，请考虑图 18.26(a) 中的 ORM 模式。在事实类型 `Employee drives Car`（员工驾驶汽车）中，`drives` 谓词是可选的且为 *m:n*。FORML 中的两个文本约束添加了一个*受限强制角色约束*（参见约束脚注 1）和一个*受限唯一性约束*（参见约束脚注 2）。在此，`drives` 谓词仅相对于 `NonExecutive`（非高管）是函数式的，而非相对于 `Employee`（员工）。我们*不应*将 `drives` 声明为 `FunctionalProperty`，因为那将适用于所有员工（以及模型的 OWL 版本中 `drives` 谓词的任何其他主语）。这些受限约束可以使用限定基数限制在 OWL 中声明，如图 18.26(a) 所示，使用的是 Manchester 语法。

在实践中，很少遇到 `minCardinality = 0` 和 `minQualifiedCardinality = 0` 的显式声明，因为这些是默认适用的，所以可以忽略。然而，将最大基数设置为零确实有一些用途。设置 `maxCardinality = 0` 意味着主语类表达式 `A` 的每个实例都通过谓词 `R` 与零个对象实例相关联。

设置 `maxQualifiedCardinality = 0` 意味着主语类表达式 `A` 的每个实例都通过 `R` 与指定范围 `B` 的零个实例相关联。这些限制主要用于定义子类，且在这类情况下通常使用限定版本。图 18.27(a) 和图 18.27(b) 总结了相应的 ORM 模式。图 18.27(c) 提供了一个具体示例，图 18.27(d) 展示了 OWL 代码。

除 1 之外的 `ExactCardinality` 限制也是允许的。例如，以下 OWL 2 代码可用于声明 `Asimov` 恰好撰写了 506 本书。

```
ObjectProperty: authored
Domain: Person
Range: Book
Individual: Asimov
Types: Person
authored exactly 506 Book
```
