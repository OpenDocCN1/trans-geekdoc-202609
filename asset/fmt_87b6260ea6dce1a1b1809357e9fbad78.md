
# gopl.io/ch2/echo4

```go
// Echo4 prints its command-line arguments.
package main

import (
    "flag"
    "fmt"
    "strings"
)

var n = flag.Bool("n", false, "omit trailing newline")
var sep = flag.String("s", " ", "separator")

func main() {
    flag.Parse()
    fmt.Print(strings.Join(flag.Args(), *sep))
    if !*n {
        fmt.Println()
    }
}
```

函数 `flag.Bool()` 会创建一个类型为 `bool` 的新标志变量。它接受三个参数：标志的名称（`"n"`）、变量的默认值（`false`），以及当用户提供无效参数、无效标志，或 `-h` 或 `-help` 时将要打印的提示信息。类似地，`flag.String()` 接受一个名称、一个默认值和一条提示信息，并创建一个 `string` 变量。变量 `sep` 和 `n` 是指向标志变量的指针，必须通过 `*sep` 和 `*n` 间接访问。

程序运行时，必须在使用标志之前调用 `flag.Parse()`，以便从默认值更新标志变量。非标志参数可通过 `flag.Args()` 作为字符串切片获取。如果 `flag.Parse()` 遇到错误，它会打印一条用法提示并调用 `os.Exit(2)` 终止程序。

让我们对 `echo` 运行一些测试用例：

```bash

$ ./echo4 a bc def
a bc def
$ ./echo4 -s / a bc def
a/bc/def
$ ./echo4 -n a bc def
a bc def$
$ ./echo4 -help
Usage of ./echo4:
  -n    omit trailing newline
  -s string
        separator (default " ")
```

## 2.3.3 `new` 函数

创建变量的另一种方法是使用内置函数 `new()`。表达式 `new(T)` 会创建一个类型为 `T` 的*未命名变量*，将其初始化为 `T` 的零值，并返回其地址，该地址属于类型 `*T`。

```go
p := new(int)   // p，类型为 *int，指向一个未命名的 int 变量
fmt.Println(*p) // "0"
*p = 2          // 将未命名的 int 设置为 2
fmt.Println(*p) // "2"
```

用 `new()` 创建的变量与一个获取了地址的普通局部变量没有什么区别，只是不需要发明（并声明）一个虚拟名称，而且我们可以在表达式中使用 `new(T)`。因此 `new()` 只是一个语法上的便利，而非基本概念：下面两个 `newInt()` 函数具有完全相同的行为。

```go
func newInt() *int {
    return new(int)
}

func newInt() *int {
    var dummy int
    return &dummy
}
```

每次调用 `new()` 都会返回一个具有唯一地址的不同变量：

```go
p := new(int)
q := new(int)
fmt.Println(p == q) // "false"
```

这条规则有一个例外：类型不携带任何信息因而大小为零的两个变量，例如 `struct{}` 或 `[0]int`，取决于实现，可能拥有相同的地址。

`new()` 函数使用相对较少，因为最常见的未命名变量是结构体类型，对于结构体类型，结构体字面量语法（§4.4.1）更加灵活。

由于 `new()` 是预声明函数而非关键字，因此可以在函数内部将该名称重新定义为其他用途，例如：

```go
func delta(old, new int) int { return new - old }
```

当然，在 `delta()` 内部，内置的 `new()` 函数将不可用。

## 2.3.4 变量的生命周期

变量的*生命周期*是指变量在程序执行过程中存在的时间段。包级变量的生命周期是整个程序的执行过程。相比之下，局部变量具有动态生命周期：每次执行声明语句都会创建一个新的实例，变量一直存活直到变得*不可达*，此时其存储空间可能被回收。函数参数和返回值也是局部变量；每次调用其外层函数时都会创建它们。

例如，在 1.4 节 Lissajous 程序的这个片段中，

```go
for t := 0.0; t < cycles*2*math.Pi; t += res {
    x := math.Sin(t)
    y := math.Sin(t*freq + phase)
    img.SetColorIndex(size+int(x*size+0.5), size+int(y*size+0.5),
        blackIndex)
}
```

变量 `t` 在 `for` 循环开始时创建，而新变量 `x` 和 `y` 在循环的每次迭代中创建。

垃圾收集器如何知道变量的存储空间可以被回收？完整的故事比我们这里需要的要详细得多，但基本思想是：每个包级变量，以及每个当前活跃函数的每个局部变量，都可能成为通往相关变量路径的起点或根，通过跟踪指针和其他类型的引用最终到达该变量。如果不存在这样的路径，该变量就变得不可达，因此不再能影响后续的计算。

因为变量的生命周期仅由其是否可达决定，所以局部变量可能比外层循环的单次迭代存活得更久。即使其外层函数已经返回，它也可能继续存在。

编译器可能会选择在堆上或栈上分配局部变量，但令人惊讶的是，这个选择并不取决于使用 `var` 还是 `new()` 来声明变量。

```go
var global *int

func f() {
    var x int
    x = 1
    global = &x
}

func g() {
    y := new(int)
    *y = 1
}
```

这里，`x` 必须在堆上分配，因为即使在 `f()` 返回后，它仍可从变量 `global` 访问，尽管它被声明为局部变量；我们说 `x` *从* `f()` *逃逸*。相反，当 `g()` 返回时，变量 `*y` 变得不可达并可被回收。既然 `*y` 没有从 `g()` 逃逸，编译器将 `*y` 分配在栈上就是安全的，尽管它是用 `new()` 分配的。无论如何，逃逸的概念不是你编写正确代码时需要担心的事情，但在性能优化时最好记在心里，因为每个逃逸的变量都需要一次额外的内存分配。

垃圾收集对编写正确程序有极大帮助，但它并不能免除你思考内存的负担。你不需要显式地分配和释放内存，但要编写高效程序，你仍然需要了解变量的生命周期。例如，在长寿命对象（尤其是全局变量）中保留指向短寿命对象的不必要指针，会阻止垃圾收集器回收这些短寿命对象。

## 2.4 赋值

变量持有的值通过赋值语句更新，其最简单的形式是在 `=` 号左侧放一个变量，右侧放一个表达式。

```go
x = 1                       // 命名变量
*p = true                   // 间接变量
person.name = "bob"         // 结构体字段
count[x] = count[x] * scale // 数组、切片或映射元素
```

每个算术和位运算的二元运算符都有一个对应的*赋值运算符*，例如，允许将最后一条语句重写为

```go
count[x] *= scale
```

这避免了我们必须重复（并重新求值）变量的表达式。

数值变量也可以通过 `++` 和 `--` 语句进行增量和减量操作：

```go
v := 1
v++    // 等同于 v = v + 1；v 变为 2
v--    // 等同于 v = v - 1；v 再次变为 1
```

### 2.4.1 元组赋值

另一种赋值形式，称为*元组赋值*，允许同时为多个变量赋值。所有右侧的表达式会在任何变量被更新之前求值，这使得这种形式在某些变量同时出现在赋值运算符两侧时最为有用，例如交换两个变量的值时：

```go
x, y = y, x

a[i], a[j] = a[j], a[i]
```

或者在计算两个整数的最大公约数（GCD）时：

```go
func gcd(x, y int) int {
    for y != 0 {
        x, y = y, x%y
    }
    return x
}
```

或者在迭代计算第 *n* 个斐波那契数时：

```go
func fib(n int) int {
    x, y := 0, 1
    for i := 0; i < n; i++ {
        x, y = y, x+y
    }
    return x
}
```

元组赋值还可以使一系列简单的赋值更加紧凑：

```go
i, j, k = 2, 3, 5
```

尽管从风格上讲，如果表达式复杂，应避免使用元组形式；一系列单独的语句更易于阅读。

某些表达式，例如调用一个具有多个返回值的函数，会产生多个值。当这种调用用在赋值语句中时，左侧必须拥有与函数返回值数量相同的变量。

```go
f, err = os.Open("foo.txt")  // 函数调用返回两个值
```

通常，函数利用这些额外的返回值来指示某种错误，要么像调用 `os.Open()` 那样返回一个 `error`，要么返回一个 `bool`，通常称为 `ok`。正如我们在后续章节将看到的，有三个操作符有时也会表现出这种行为。如果映射查找（§4.3）、类型断言（§7.10）或通道接收（§8.4.2）出现在期望两个结果的赋值中，每个操作都会产生一个额外的布尔结果：

```go
v, ok = m[key]             // 映射查找
v, ok = x.(T)              // 类型断言
v, ok = <-ch               // 通道接收
```

与变量声明一样，我们可以将不需要的值赋给空标识符：

```go
_, err = io.Copy(dst, src) // 丢弃字节计数
_, ok = x.(T)              // 检查类型但丢弃结果
```

### 2.4.2 可赋值性

赋值语句是赋值的显式形式，但在程序中有许多地方会发生*隐式*赋值：函数调用会隐式地将实参值赋给对应的形参变量；`return` 语句会隐式地将返回操作数赋给对应的结果变量；以及复合类型的字面量表达式（§4.2），例如这个切片：

```go
medals := []string{"gold", "silver", "bronze"}
```

会隐式地赋值每个元素，就如同按如下方式编写一样：

```go
medals[0] = "gold"
medals[1] = "silver"
medals[2] = "bronze"
```

映射和通道的元素虽然不是普通变量，但也受类似的隐式赋值约束。

无论显式还是隐式，如果左侧（变量）和右侧（值）具有相同的类型，赋值总是合法的。更一般地说，只有当值*可赋值*给变量的类型时，赋值才是合法的。

*可赋值性*规则针对各种类型有不同情况，因此我们将在介绍每种新类型时解释相关情况。对于我们目前讨论的类型，规则很简单：类型必须完全匹配，且 `nil` 可以赋值给任何接口类型或引用类型的变量。常量（§3.6）具有更灵活的可赋值性规则，避免了大多数显式转换的需要。

两个值是否可以用 `==` 和 `!=` 进行比较与可赋值性有关：在任何比较中，第一个操作数必须可赋值给第二个操作数的类型，反之亦然。与可赋值性一样，我们将在介绍每种新类型时解释*可比较性*的相关情况。

## 2.5 类型声明

变量或表达式的类型定义了它可能取值的特征，例如其大小（位数或元素数量）、内部表示方式、可对其执行的内在操作以及与其关联的方法。

在任何程序中，都存在具有相同表示但表示完全不同概念的变量。例如，`int` 可用于表示循环索引、时间戳、文件描述符或月份；`float64` 可表示米/秒的速度或几种温标之一的温度；`string` 可表示密码或颜色名称。

`type` 声明定义了一个新的*命名类型*，它与现有类型具有相同的*底层类型*。命名类型提供了一种方法，将底层类型的不同且可能不兼容的用途分隔开，以免它们被无意中混合使用。

```go
type name underlying-type
```

类型声明最常出现在包级别，此时命名类型在整个包内可见，如果名称被导出（以大写字母开头），也可从其他包访问。

为了演示类型声明，让我们将不同的温标转换为不同的类型：

```go
// Package tempconv performs Celsius and Fahrenheit temperature computations.
package tempconv

import "fmt"

type Celsius float64
type Fahrenheit float64

const (
    AbsoluteZeroC Celsius = -273.15
    FreezingC     Celsius = 0
    BoilingC      Celsius = 100
)

func CToF(c Celsius) Fahrenheit { return Fahrenheit(c*9/5 + 32) }

func FToC(f Fahrenheit) Celsius { return Celsius((f - 32) * 5 / 9) }
```

该包为两种温度单位定义了两个类型，`Celsius` 和 `Fahrenheit`。尽管两者具有相同的底层类型 `float64`，但它们不是同一类型，因此不能在算术表达式中进行比较或组合。区分类型使得避免错误成为可能，例如无意中混合使用两种不同温标的温度；需要显式的类型*转换*，如 `Celsius(t)` 或 `Fahrenheit(t)`，才能从 `float64` 转换。`Celsius(t)` 和 `Fahrenheit(t)` 是转换，而非函数调用。它们不会以任何方式改变值或表示，但会使含义的变更变得显式。另一方面，函数 `CToF()` 和 `FToC()` 在两种温标之间转换；它们*确实*返回不同的值。

对于每种类型 `T`，都有一个对应的转换操作 `T(x)`，将值 `x` 转换为类型 `T`。如果两种类型具有相同的底层类型，或者都是指向相同底层类型变量的未命名指针类型，则允许从一种类型转换到另一种类型；这些转换改变类型但不改变值的表示。如果 `x` 可赋值给 `T`，则允许转换但通常是多余的。

转换也允许在数值类型之间、字符串和某些切片类型之间进行，正如我们将在下一章看到的。这些转换可能会改变值的表示。例如，将浮点数转换为整数会丢弃任何小数部分，将字符串转换为 `[]byte` 切片会分配字符串数据的副本。在任何情况下，转换在运行时永远不会失败。

底层类型决定了命名类型的结构和表示，以及它支持的内置操作集，这与直接使用底层类型时相同。这意味着算术运算符对 `Celsius` 和 `Fahrenheit` 的作用方式与对 `float64` 的作用方式相同，正如你所期望的那样。

```go
fmt.Printf("%g\n", BoilingC-FreezingC) // "100" °C
boilingF := CToF(BoilingC)
fmt.Printf("%g\n", boilingF-CToF(FreezingC)) // "180" °F
fmt.Printf("%g\n", boilingF-FreezingC)       // 编译错误：类型不匹配
```

比较运算符（如 `==` 和 `<`）也可用于比较命名类型的值与同类型的另一个值，或与底层类型的值。但两个不同命名类型的值不能直接比较：

```go
var c Celsius
var f Fahrenheit
fmt.Println(c == 0)          // "true"
fmt.Println(f >= 0)          // "true"
fmt.Println(c == f)          // 编译错误：类型不匹配
fmt.Println(c == Celsius(f)) // "true"!
```

请仔细注意最后一种情况。尽管名为类型转换，`Celsius(f)` 并不会改变其参数的值，只会改变其类型。该测试为真是因为 `c` 和 `f` 都是零。

如果命名类型有助于避免反复编写复杂类型，它可以提供符号上的便利。当底层类型像 `float64` 这样简单时，优势很小；但对于复杂类型，优势很大，我们在讨论结构体时将会看到。

命名类型还使得为该类型的值定义新行为成为可能。这些行为表示为与该类型关联的一组函数，称为该类型的*方法*。我们将在第 6 章详细介绍方法，但这里先略窥一二。

下面的声明中，`Celsius` 参数 `c` 出现在函数名之前，这为 `Celsius` 类型关联了一个名为 `String()` 的方法，该方法返回 `c` 的数值后跟 `°C`：

```go
func (c Celsius) String() string { return fmt.Sprintf("%g°C", c) }
```
