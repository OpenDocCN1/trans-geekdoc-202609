
`R is irreflexive  iff  ∀ x      ~xRx`

在图 7.13(b) 的点箭头图标中，带箭头的弧描绘了从对象到其自身的关系，横穿其上的竖线表示这是不允许的。`非自反约束`通过将该图标的简化版本（去掉箭头尖）连接到角色对来描绘（如果角色是连续的，则在其连接处连接），如图 7.13(c) 所示。该约束口头表述为“**没有** Person 是其**自身**的父母”。ORM 1 中用于非自反约束的替代符号是“^O*ir*”。

![图 7.13 父母关系被声明为非自反。但仍有问题。](img/f07-13-9780443237904.jpg)

图 7.13 父母关系被声明为非自反。但仍有问题。

图 7.13(c) 添加了非自反约束并相应地减少了实例集。注意，“非自反”比“非自反性”更强。例如，如果 Likes 是非自反的，那么没人喜欢他们自己。如果有些但并非所有人喜欢他们自己，那么 Likes 既不是自反的也不是非自反的。

非自反性是行内约束（即，通过仅检查该行即可确定某行是否违反约束）。它规定同一行的两个单元格中不得出现同一个条目。这使得该约束易于且廉价地强制执行。注意，父母关系是非自反但非排他的。例如，Bill 既可以作为 Colin 的父母出现，也可以作为 Ann 的孩子出现。

图 7.13(c) 仍存在一些问题。如果我们接受第一行，就应该拒绝第二行。如果 Ann 是 Bill 的父母，那么 Bill 是 Ann 的父母就不可能为真。父母关系是`非对称的`。一般来说，对于任意谓词 *R*：

```
R is asymmetric  iff  ∀ x,y (xRy  → ~ yRx)
```

即，如果第一个对象 *R* 第二个，则第二个不能 *R* 第一个。这里，如果一个人是另一个人的父母，则另一个人不能是该人的父母。说一个关系是非对称的，比说该关系非对称性更强（你可能希望将此作为练习来证明）。图 7.14(b) 显示了非对称性的直观图标。

![图 7.14 父母关系和汇报关系是非对称关系。](img/f07-14-9780443237904.jpg)

图 7.14 父母关系和汇报关系是非对称关系。

`非对称约束`通过将该图标的简化版本（无箭头尖）用虚线连接到受约束的角色对来图形化描绘，如图 7.14(c) 所示。强制执行此约束后，父母关系实例集如图所示减少。图 7.14(d) 显示了涉及子类型的另一个非对称约束示例。ORM 1 中用于非对称性的替代约束符号是“^O*as*”。

图 7.14(c) 省略了非自反约束。这是错误吗？不是。任何非对称的关系必须是非自反的。证明留作练习（*提示*：*x* 和 *y* 不必不同）。反之不成立。有些非自反关系不是非对称的（例如，是……的姐妹）。为避免隐含约束，如果已声明非对称性，请勿声明非自反性。

如果我们移除非自反性要求，将获得较弱的反对称性属性。例如，≤ 和 ⊆ 是`反对称的`但非非对称的。图 7.15(a) 中的直观图标使用不同颜色的节点来指示对象不同。该图标的简化版本（无箭头尖）用于描绘`反对称约束`，如图 7.15(b) 所示。图 7.15(b) 底部的等价式表明，非对称性结合了反对称性和非自反性。

![图 7.15 反对称性。](img/f07-15-9780443237904.jpg)

图 7.15 反对称性。

R is antisymmetric  iff  ∀  x,y  [(x  ≠  y  &  xRy)  →  ~yRx]

如果一个词是另一个词的同义词，则另一个词也是它的同义词。所以 has-synonym 是对称的。但表 7.1 违反了此条件。例如，序对（“abbreviate”，“reduce”）仅按此顺序出现。如果我们查找单词“reduce”，将不会看到“abbreviate”作为其同义词之一。这是同义词书的缺陷，计算机化同义词系统应避免此问题。如何避免此问题？

同义词的传递性如何？这个问题很复杂。你可能熟悉基于“如果我们在秃头男人的头上加一根头发，他仍然是秃头”这一主张的“秃发悖论”（悖论在哪里？）。类似的滑坡论证反对同义词传递性（近似序列最终导致非近似）。此外，同一个词可能有不同的含义，从而导致不同的同义词组。如果我们仍想保留某种传递性，可以包含一个同义词传递性的推导规则，并通过传递链的最大长度加以约束，且相对于词组含义。

现在考虑图 7.17 中的婚姻事实类型。丈夫和妻子角色是互斥的。与要求同一行条目不相等的非自反约束不同，排除约束作用于列之间，因此强得多。如果任何条目都不能同时出现在两列中，我们就不能有形式为 (a, b) 和 (b, a) 的两行。因此，**排除性蕴含非对称性**。而且，**非对称性蕴含非自反性**。因为它们是被蕴含的，所以非对称约束和非自反约束都不应添加到模式中。

现在，让我们回到图 7.18(a) 中填充的父母关系模型。这里仍然存在一个问题。你能发现吗？让我们约定在我们的 UoD 中不能发生乱伦（如果可以，我们改为声明道义规则，如第 10 章所述）。如果 Ann 是 Bill 的父母，Bill 是 Colin 的父母，那么 Ann 不能是 Colin 的父母。父母关系是**非传递的**（即，如果一个人是第二个人的父母，第二个人是第三个人的父母，那么第一个人不可能是第三个人的父母）。一般来说，对于任何关系类型 *R*：

```
R is intransitive  iff  ∀ x,y,z  [(xRy  &  yRz) → ~xRz]
```

图 7.18(b) 显示了非传递性的直观图标，横杠表示禁止的跳跃。该图标的简化版本（无箭头尖）用作非传递约束符号，如图 7.18(b) 右侧所示。图 7.18(c) 通过在单个图标中组合约束，表示父母关系既是非传递的又是非对称的。填充数据已更改以满足约束。

作为练习，证明非传递性蕴含非自反性（提示：*x*、*y* 和 *z* 不必不同）。有时用“非传递”代替“非传递”。说一个关系是非传递的，比说它不是传递的更强。反对称性、非对称性和非传递性都不是行内约束，因为它们的实施需要将相关行与其他现有行进行比较。

如果一个非自反关系包含一个函数角色（而不是 *m:n*），它也必须是非传递的。图 7.19 通过*归谬法*说明了这一点的证明。设 *R* 为一个第一角色是函数的非自反关系（即，它有一个简单的唯一性约束）。现在，用前两行所示填充 *R*。因为 R 是非自反的，*a* ≠ *b* 且 *b* ≠ *c*。假设 *R* 不是非传递的。这允许我们添加所示的第三行。因为 *b* ≠ *c*，第 1 行和第 3 行是不同的行。这意味着 *a* 扮演了 *R* 的第一角色两次。但这与唯一性约束矛盾。因此，必须拒绝第 3 行（用穿过第 3 行的虚线表示）。因此，该关系必须是非传递的。隐含的非传递约束通常最好保持隐式；如果显式显示，则标为绿色，如图 7.19(c) 所示。如果第二角色是函数的，此蕴含也适用。

我们完成环约束了吗？还没。看看图 7.18(c) 中的父母关系填充。所有指定约束都满足，但仍有错误。你能发现问题吗？

这里，Ann 是 Bill 的父母，Bill 是 Colin 的父母，Colin 是 Ann 的父母。这使得 Ann 成了自己的曾祖父母。虽然轮回可能使这成为可能，但假设我们希望从 UoD 中排除这种可能性。我们可以通过声明关系为**非循环**来实现。这意味着关系没有环（即，不存在通过关系从一个对象回到其自身的路径）。

使用 `∃`（读作“存在某个”）表示**存在量词**，我们递归地定义路径谓词 *P*（读作“有一条路径到”）以给出 *R* 的传递闭包，然后用它定义关系 *R* 为非循环：

```
∀ x,y (xPyiff [xRyor ∃z (xRz & zPy)])
R is acyclic iff ∀x ~xPx
```

图 7.20(a) 显示了非循环性的直观图标，横杠表示不允许回环。该图标的简化版本（无箭头尖）用作**非循环约束**符号，如图 7.20(b) 所示。ORM 1 使用替代的非循环约束符号 ^O*ac*。

![Fig. 7.20 在非循环关系中，不允许回环。](img/f07-20-9780443237904.jpg)

图 7.20 在非循环关系中，不允许回环。

环可能包含一个或多个链接。非对称性只是环中有两个链接的非循环性的特例。因为**非循环蕴含非对称**，如果角色对被声明为非循环，则不要声明它为非对称。

在图 7.20(c)中，父子关系的实例集既是非循环的，也是非传递的。这两个环约束组合成一个图标，如图所示。同质二元关系可以显示为图，使用命名节点表示对象，箭头表示关系实例，如图 7.20(d)所示。这使得在视觉上很明显地判断给定实例集是否形成非循环关系。

回想一下，子类型家族的图是有向且非循环的。由于其递归性质，非循环约束在某些数据库系统中可能开销昂贵，甚至无法强制执行。在 SQL 中，可以使用递归联合运算符实现；在逻辑编程语言中，则很容易强制执行。在其他系统中，递归约束检查可能需要留给数据录入员手动完成。

当且仅当 ∀*x,y,z*\[(*xRy* & *yPz*) → ~*xPz*\] 时，环谓词 *R* 是**强非传递**的，其中路径谓词 *P*（读作“有一条路径到”）被递归定义以给出 *R* 的传递闭包。例如，忽略乱伦和轮回转世，“Person 是 Person 的祖先”这一关系就是强非传递的。**强非传递约束**在非传递图标上加一个额外的点来表示（参见图 7.21）。

![图 7.21 主要环约束之间的关系。](img/f07-21-9780443237904.jpg)

图 7.21 主要环约束之间的关系。

在所有环约束中，非自反性的执行开销最小。对于非循环性等昂贵的约束，**增量检查**（针对当前更新请求的违规情况进行检查，假设之前的实例集与约束一致）通常比完全检查便宜得多。

图 7.21 中的欧拉图展示了主要环约束之间的关系。非循环关系的集合构成了**非对称**关系集合的真子集，因此非循环关系必须是非对称的。非传递关系必须是非自反的，而非对称关系既是非自反的又是反对称的。

对称约束可以与非传递或非自反约束组合。环关系的其他性质也可能适用（例如连通性），但此处不作讨论。嵌入式环关系的一个经典例子是“物料清单”或“零件分解”问题（参见练习 4.4），它涉及三元事实类型“Product 包含 Product，数量为 Quantity”。在后续练习中，邀请你为该问题提供一个更完整的解决方案。
