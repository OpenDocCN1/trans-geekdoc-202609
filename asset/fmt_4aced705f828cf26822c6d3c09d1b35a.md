
IDS 上的基于知识库的检测类似于反恶意软件应用程序使用的基于特征库的检测。反恶意软件应用程序拥有已知恶意软件的数据库，并根据数据库检查文件以查找匹配项。正如反恶意软件必须定期使用来自供应商的新特征库进行更新一样，IDS 数据库也必须定期使用新的攻击特征库进行更新。大多数 IDS 厂商提供自动更新特征库的方法。

## 基于行为的检测

第二种检测类型是**行为检测**（也称为*统计入侵检测*、*异常检测*和*启发式检测*）。行为检测首先创建系统上正常活动和事件的基线。一旦积累了足够的基线数据来确定正常活动，它就可以检测可能表明恶意入侵或事件的异常活动。

此基线通常在有限的时间段（如一周）内创建。如果网络被修改，则需要更新基线。否则，IDS 可能会对其识别为异常的正常行为发出警报。某些产品会持续监控网络以了解更多关于正常活动的信息，并将根据观察结果更新基线。

基于行为的 IDS 使用基线、活动统计和启发式评估技术将当前活动与以前的活动进行比较，以检测潜在的恶意事件。许多产品可以执行有状态数据包分析，类似于有状态检查防火墙（第 11 章介绍）根据网络流量的状态或上下文检查流量的方式。

异常分析通过允许 IDS 识别并对流量或活动的突然增加、多次登录失败、正常工作时间之外的登录或程序活动，或错误或故障消息的突然增加做出反应，从而增加了 IDS 的功能。所有这些都可能表明基于知识库的检测系统可能无法识别的攻击。

基于行为的 IDS 可以被标记为专家系统或伪人工智能系统，因为它可以学习并对事件做出假设。换句话说，IDS 可以通过评估当前事件与已知事件来充当人类专家。向基于行为的 IDS 提供的关于正常活动和事件的信息越多，它检测异常的准确性就越高。基于行为的 IDS 的一个显著优势是它可以检测没有特征库且无法用基于特征库的方法检测到的较新攻击。

基于行为的 IDS 的主要缺点是它经常引发大量误报，也称为误警报或假阳性。用户和系统活动的模式在正常操作期间可能会有很大差异，这使得准确定义正常和异常活动的边界变得困难。

### SIEM 系统

许多 IDS 和 IPS 将收集的数据发送到安全信息和事件管理（SIEM）系统。SIEM 系统还收集网络中许多其他来源的数据。它提供流量的实时监控、分析和潜在攻击的通知。此外，它提供数据的长期存储，允许安全专业人员分析数据。

SIEM 通常包含多项功能。因为它从不同设备收集数据，所以包含一个关联和聚合功能，将这些数据转换为有用的信息。SIEM 内部的高级分析工具可以分析数据并根据预配置的规则引发警报和/或触发响应。这些警报和触发器通常独立于 IDS 和 IPS 发送的警报，但可能会发生一些重叠。

### IDS 响应

虽然基于知识库和基于行为的 IDS 检测事件的方式不同，但它们都使用警报系统。当 IDS 检测到事件时，它会触发警报。然后它可以使用被动或主动方法进行响应。被动响应记录事件并发送通知。主动响应除了记录和发送通知外，还会更改环境以阻止活动。

#### 被动响应

通知可以通过电子邮件、短信或寻呼消息、弹出消息发送给管理员。在某些情况下，警报可以生成一份报告，详细说明事件发生前的活动，如果需要，管理员可以查看日志以获取更多信息。许多 24 小时网络运营中心（NOC）都有主支持中心所有人都能看到的中央监控屏幕。例如，一面墙上可以有多个大屏幕显示器，提供 NOC 不同要素的数据。IDS 警报可以显示在这些屏幕之一上，以确保人员了解事件。这些即时通知有助于管理员快速有效地响应不需要的行为。

#### 主动响应

主动响应可以使用多种不同的方法修改环境。典型的响应包括修改 ACL 以根据端口、协议和源地址阻止流量，甚至禁用特定电缆段上的所有通信。例如，如果 IDS 检测到来自单个 IP 地址的 SYN 洪水攻击，IDS 可以更改 ACL 以阻止来自该 IP 地址的所有流量。同样，如果 IDS 检测到来自多个 IP 地址的 ping 洪水攻击，它可以更改 ACL 以阻止所有 ICMP 流量。IDS 还可以阻止可疑或行为不当的用户访问资源。安全管理员预先配置这些主动响应，并可以根据环境中不断变化的需求对其进行调整。

### 基于主机和基于网络的 IDS

IDS 类型通常分为基于主机和基于网络两类。*基于主机的 IDS (HIDS)* 监控单台计算机或主机。*基于网络的 IDS (NIDS)* 通过观察网络流量模式来监控网络。

一种不太常用的分类是基于应用程序的 IDS，它是一种特定类型的基于网络的 IDS。它监控两台或多台服务器之间的特定应用程序流量。例如，基于应用程序的 IDS 可以监控 Web 服务器和数据库服务器之间的流量，以查找可疑活动。

#### 基于主机的 IDS

HIDS 监控单台计算机上的活动，包括进程调用以及记录在系统、应用程序、安全和基于主机的防火墙日志中的信息。它通常比 NIDS 能更详细地检查事件，并能确定攻击中受损的特定文件。它还可以跟踪攻击者使用的进程。

HIDS 相对于 NIDS 的一个优势是 HIDS 可以检测 NIDS 无法检测到的主机系统上的异常。例如，HIDS 可以检测到入侵者渗透系统并远程控制它的感染。您可能会注意到这听起来类似于反恶意软件在计算机上所做的事情。确实如此。许多 HIDS 包含反恶意软件功能。

尽管许多供应商建议在所有系统上安装基于主机的 IDS，但由于 HIDS 的一些缺点，这种做法并不普遍。相反，许多组织选择仅在关键服务器上安装 HIDS，作为一种额外的保护层。HIDS 的一些缺点与成本和易用性有关。HIDS 的管理成本高于 NIDS，因为它们需要对每个系统进行单独的管理关注，而 NIDS 通常支持集中管理。HIDS 无法检测针对其他系统的网络攻击。此外，它通常会消耗大量的系统资源，从而降低主机系统的性能。虽然通常可以限制 HIDS 使用的系统资源，但这可能导致其错过正在进行的攻击。此外，HIDS 更容易被入侵者发现并禁用，且其日志保存在系统上，一旦攻击成功，日志就容易被篡改。

## 基于网络的 IDS

NIDS 监控并评估网络活动，以检测攻击或事件异常。单个 NIDS 可以通过使用远程传感器在关键网络位置收集数据，并将数据发送到中央管理控制台和/或 SIEM，从而监控大型网络。这些传感器可以监控路由器、防火墙、支持端口镜像的网络交换机以及其他类型的网络分流器上的流量。

中央控制台通常安装在一台专用计算机上，该计算机经过加固以抵御攻击。这减少了 NIDS 中的漏洞，并使其能够近乎隐形地运行，从而使攻击者更难发现并禁用它。NIDS 对整体网络性能的负面影响微乎其微，当部署在专用系统上时，它不会对任何其他计算机的性能产生不利影响。在流量巨大的网络上，单个 NIDS 可能无法跟上数据流，但可以通过添加额外的系统来平衡负载。

通常，NIDS 可以通过执行反向地址解析协议 (RARP) 或反向域名系统 (DNS) 查找来发现攻击源。然而，由于攻击者经常欺骗 IP 地址或通过僵尸网络利用僵尸主机发起攻击，因此需要进一步调查以确定实际来源。这可能是一个繁琐的过程，且超出了 IDS 的范围。不过，通过一定的调查，有可能发现欺骗 IP 的来源。

NIDS 通常能够检测攻击的发起或正在进行的攻击，但并不总能提供关于攻击是否成功的信息。它无法知晓攻击是否影响了特定系统、用户账户、文件或应用程序。例如，NIDS 可能会发现缓冲区溢出漏洞利用代码通过网络发送，但不一定知道该漏洞利用是否成功渗透了系统。然而，管理员收到警报后可以检查相关系统。此外，调查人员可以将 NIDS 日志作为审计追踪的一部分，以了解发生了什么。

### 入侵防御系统

入侵防御系统 (IPS) 是一种特殊类型的主动 IDS，它试图在攻击到达目标系统之前检测并阻止攻击。它有时被称为入侵检测与防御系统 (IDPS)。IDS 和 IPS 之间的一个显著区别在于 IPS 部署在流量的直通路径上，如图 17.4 所示。换句话说，所有流量都必须经过 IPS，IPS 在分析后可以选择转发哪些流量、阻止哪些流量。这使得 IPS 能够防止攻击到达目标。

IPS 可以使用基于知识的检测和/或基于行为的检测，就像其他任何 IDS 一样。此外，它还可以记录活动并向管理员提供通知，就像 IDS 所做的那样。

## 具体预防措施

尽管入侵检测和防御系统在保护网络方面发挥了巨大作用，但管理员通常还会实施额外的安全控制来保护其网络。以下几节将介绍其中几种作为额外的预防措施。

### 蜜罐/蜜网

*蜜罐* 是作为诱捕入侵者陷阱而创建的单个计算机。*蜜网* 是两个或多个联网的蜜罐，它们协同工作以模拟一个网络。它们看起来并表现得像合法系统，但不存放对攻击者有任何真实价值的数据。管理员通常会配置带有漏洞的蜜罐，以引诱入侵者攻击它们。它们可能未打补丁，或者管理员故意留下安全漏洞。目的是吸引入侵者的注意力，使其远离托管宝贵资源的合法网络。合法用户不会访问蜜罐，因此对蜜罐的任何访问极有可能是未经授权的入侵者。

除了将攻击者隔离在生产环境之外，蜜罐还为管理员提供了一个在不危及实时环境的情况下观察攻击者活动的机会。在某些情况下，蜜罐的设计目的是拖延入侵者足够长的时间，以便自动化 IDS 检测到入侵并尽可能多地收集关于入侵者的信息。攻击者在蜜罐上花费的时间越长，管理员调查攻击并潜在识别入侵者的时间就越多。一些安全专业人员（如从事安全研究的人员）认为蜜罐是针对零日漏洞利用的有效对策，因为它们可以观察攻击者的行为。

管理员通常在虚拟系统上托管蜜罐和蜜网。攻击发生后，这些系统更容易重建。例如，管理员可以配置蜜罐，然后对蜜罐虚拟机进行快照。如果攻击者修改了环境，管理员可以将机器恢复到快照时的状态。使用虚拟机 (VM) 时，管理员应密切监控蜜罐或蜜网。攻击者通常能检测出自己身处 VM 中，并可能尝试 VM 逃逸攻击以突破 VM。

蜜罐的使用引发了诱惑与诱捕的问题。如果入侵者是在蜜罐所有者没有任何外部努力的情况下自行发现蜜罐，组织可以合法地将蜜罐作为诱惑装置使用。将一个带有开放安全漏洞和已知漏洞利用的活动服务的系统放置在互联网上属于诱惑。被诱惑的攻击者会自行决定实施非法或未经授权的行为。诱捕是非法的，当蜜罐所有者主动招揽访问者访问该站点，然后指控其未经授权的入侵时，就会发生诱捕。换句话说，当你欺骗或鼓励某人实施非法或未经授权的行为时，这就是诱捕。不同国家的法律各异，因此了解当地关于诱惑和诱捕的相关法律非常重要。

#### 伪缺陷

**伪缺陷** 是有意植入系统中的虚假漏洞或明显的漏洞，旨在引诱攻击者。它们常用于蜜罐系统，以模拟众所周知的操作系统漏洞。试图利用已知缺陷的攻击者可能会偶然发现伪缺陷，并误以为已成功渗透系统。更复杂的伪缺陷机制实际上会模拟渗透过程，使攻击者信服他们已获得系统的额外访问权限。然而，当攻击者正在探索系统时，监控和警报机制会触发并向管理员发出威胁警报。

### 填充单元

**填充单元** 系统类似于蜜罐，但它采用不同的方法执行入侵隔离。当 IDPS 检测到入侵者时，该入侵者会被自动传送到填充单元。填充单元具有实际网络的外观和感觉，但攻击者无法从填充单元内执行任何恶意活动或访问任何机密数据。

填充单元是一个模拟环境，提供虚假数据以保持入侵者的兴趣，这点与蜜罐相似。然而，IDPS 在未通知入侵者变更已发生的情况下，将入侵者传送到填充单元。相比之下，攻击者会直接选择攻击蜜罐，而不会被 IDPS 传送到蜜罐。管理员会密切监控填充单元，并利用它们来检测和观察攻击。安全专业人员可利用它们来检测攻击手法，并收集证据以便可能对攻击者提起诉讼。填充单元如今不常用，但考试中可能仍会涉及。

### 警告横幅

警告横幅告知用户和入侵者基本的安全策略准则。它们通常提及在线活动会被审计和监控，并经常提供关于受限活动的提醒。在大多数情况下，从法律角度来看，横幅中的措辞很重要，因为这些横幅可以在法律上约束用户遵守允许的行为、举止和流程。

以某种方式设法登录系统的未授权人员也会看到警告横幅。在这种情况下，你可以将警告横幅视为“禁止入内”标志的电子等效物。当警告明确声明禁止未授权访问，且任何活动都将被监控和记录时，大多数入侵和攻击都可以被起诉。

### 反恶意软件

防范恶意代码最重要的保护措施是使用具有最新签名文件和启发式功能的反恶意软件。攻击者定期发布新的恶意软件，并经常修改现有恶意软件以防止被反恶意软件检测到。反恶意软件供应商会寻找这些变化，并开发新的签名文件来检测新的和修改过的恶意软件。多年前，反恶意软件供应商建议每周更新一次签名文件。然而，如今大多数反恶意软件都包含每天多次自动检查更新的功能，无需用户干预。

许多组织采用多管齐下的方法来阻止恶意软件并检测任何进入系统的恶意软件。具有内容过滤功能的防火墙（或专用内容过滤设备）通常部署在互联网与内部网络的边界，以过滤掉任何类型的恶意代码。专用反恶意软件安装在邮件服务器上，以检测和过滤通过电子邮件传递的任何类型的恶意软件。此外，反恶意软件安装在每个系统上，以检测和阻止恶意软件。组织通常使用中央服务器部署反恶意软件、下载更新的定义，并将这些定义推送到客户端。

在每个系统上安装反恶意软件并过滤互联网内容的多管齐下方法，有助于保护系统免受来自任何来源的感染。例如，在每个系统上使用最新的反恶意软件将检测并阻止员工 USB 闪存驱动器上的病毒。

反恶意软件供应商通常建议在任何系统上仅安装一个反恶意软件应用程序。当系统上安装了多个反恶意软件应用程序时，这些应用程序可能会相互干扰，有时会导致系统问题。此外，拥有多个扫描程序会消耗过多的系统资源。

遵循最小权限原则也有帮助。用户将没有系统的管理权限，也无法安装可能是恶意的应用程序。如果病毒确实感染了系统，它通常会冒充登录用户。当该用户拥有有限权限时，病毒的能力也会受到限制。此外，随着额外应用程序的增加，与恶意软件相关的漏洞也会增加。每个额外的应用程序都为恶意代码提供了另一个潜在的攻击点。

教育用户了解恶意代码的危险、攻击者如何诱骗用户安装恶意代码，以及他们可以采取什么措施来降低风险，是另一种保护方法。很多时候，用户只需不点击链接或不打开通过电子邮件发送的附件，就能避免感染。

第 14 章涵盖了社会工程学战术，包括网络钓鱼、鱼叉式网络钓鱼和鲸钓。当用户了解这些类型的攻击时，他们不太可能上当受骗。尽管许多用户接受过关于这些风险的教育，但网络钓鱼邮件仍然充斥互联网并进入用户的收件箱。攻击者之所以继续发送它们，唯一的原因是它们仍然能欺骗一些用户。

#### 白名单与黑名单

应用程序白名单和黑名单可以是一种有效的预防措施，防止用户运行未授权的应用程序。它们也有助于防止恶意软件感染。白名单标识获授权在系统上运行的应用程序列表，而黑名单标识未获授权在系统上运行的应用程序列表。

白名单不包含恶意软件应用程序，因此会阻止它们运行。某些白名单使用哈希算法创建哈希值来标识应用程序。然而，如果应用程序感染了病毒，病毒会有效地改变哈希值，因此这种类型的白名单也会阻止受感染的应用程序运行。（第 6 章“密码学和对称密钥算法”更深入地介绍了哈希算法。）

运行在 iPhone 和 iPad 上的 Apple iOS 是白名单极端版本的一个示例。用户只能安装 Apple App Store 上提供的应用。Apple 人员会审核并批准 App Store 上的所有应用，并迅速移除行为不当的应用。虽然用户可以绕过安全措施并越狱其 iOS 设备，但大多数用户不会这样做，部分原因是这会导致保修失效。

如果管理员知道要阻止哪些应用程序，黑名单是一个不错的选择。例如，如果管理层希望确保用户不在系统上运行游戏，管理员可以启用工具来阻止这些游戏。

### 防火墙

防火墙通过过滤流量为网络提供保护。正如第 11 章所讨论的，防火墙多年来经历了许多变化。

基本防火墙根据 IP 地址、端口和一些协议（使用协议编号）过滤流量。防火墙在 ACL 中包含允许特定流量的规则，并以一条隐式拒绝规则结束。隐式拒绝规则会阻止前一条规则未允许的所有流量。例如，防火墙可以通过分别允许使用 TCP 端口 80 和 443 的流量来允许 HTTP 和 HTTPS 流量。（第 11 章更深入地介绍了逻辑端口。）

#### ICMP 与防火墙基础

ICMP 使用协议编号 1，因此防火墙可以通过允许协议编号为 1 的流量来允许 ping 流量。同样，防火墙可以通过分别允许协议编号 50 和 51，来允许 IPsec 封装安全载荷（ESP）流量和 IPsec 认证头（AH）流量。

#### 防火墙代际演进

第二代防火墙增加了额外的过滤功能。例如，`应用层网关防火墙`基于特定应用程序要求过滤流量，而`电路级网关防火墙`基于通信电路过滤流量。第三代防火墙（也称为`状态检测防火墙`和动态包过滤防火墙）基于流量在流中的状态进行过滤。

`下一代防火墙`充当`统一威胁管理（UTM）`设备，并结合了多种过滤功能。它包含防火墙的传统功能，如包过滤和状态检测。然而，它能够执行包检测技术，从而识别并阻止恶意流量。它可以使用定义文件和/或白名单和黑名单过滤恶意软件。它还包含入侵检测和/或入侵防御功能。

#### Sandboxing

Sandboxing 为应用程序提供安全边界，防止应用程序与其他应用程序交互。反恶意软件应用程序使用 sandboxing 技术测试未知应用程序。如果应用程序显示可疑特征，sandboxing 技术会防止该应用程序感染其他应用程序或操作系统。

应用程序开发人员通常使用虚拟化技术测试应用程序。他们创建一个虚拟机，然后将其与主机和网络隔离。然后他们能够在此沙箱环境中测试应用程序，而不影响虚拟机外部的任何内容。同样，许多反恶意软件供应商使用虚拟化作为 sandboxing 技术来观察恶意软件的行为。

#### 第三方安全服务

一些组织将安全服务外包给第三方，即组织外部的个人或组织。这可以包括许多不同类型的服务，如审计和渗透测试。

在某些情况下，组织必须向外部实体提供保证，证明第三方服务提供商符合特定的安全要求。例如，处理主要信用卡交易的组织必须遵守支付卡行业数据安全标准（PCI DSS）。这些组织通常会外包部分服务，PCI DSS 要求组织确保服务提供商也遵守 PCI DSS 要求。换句话说，PCI DSS 不允许组织外包其责任。
