
对于循环的每次迭代，写下循环变量和其他关键变量的值。通常，纸上仅几个值就能揭示规律，阐明算法在做什么。

当你跟踪一个带有参数的方法的算法时，画出内存槽来直观展示值的变化。记住，调用方法时，会复制实参的副本。除非参数是引用，否则无法修改实际值。（参见第 104 页。）

要找出递归算法返回的值，写下多次方法调用以便跟踪。（例如参见第 297 页的第 5 题。）

对于涉及继承的复杂题目，快速绘制一个 UML（继承）图以加强对类之间关系的理解。（参见第 196 页。）

在选择题部分，经常出现类似以下的问题：

- 该算法有什么作用？
- ……的后置条件可能是什么？
- ……将导致哪个数组作为结果？
- 将返回哪个字符串？

轻松解决这些问题的关键是思考`小规模`情况。给自己一个 3 元素的数组，或一个 2×2 的矩阵，或一个 3 字符的字符串，在你易于管理的小数据结构上手工执行代码。写下数值。跟踪循环变量。答案就会显现出来。

### 故障排查——这段代码有什么问题？

一些选择题会告诉你代码无法按预期工作。你需要找出`/* more code */`的错误替代项，或直接找出错误。以下是一些可快速检查的细节：

- 如果是递归算法，它有基本情况吗？
- 递归算法中的基本情况真的会导致终止吗？
- 在数组算法中，索引能等于`arr.length`吗？如果可以，则越界。
- 算法是否包含`arr[i]`和`arr[i + 1]`？通常`arr[i + 1]`会越界。
- 在包含`str.substring[start]`的字符串算法中，`start`是否大于`str.length()`？如果是，则越界。
- 在包含`str.substring[start, end]`的字符串算法中，`start`是否大于或等于`end`？如果是，会导致错误。`end`是否大于`str.length()`？如果是，则越界。
- 在除`add`以外的`ArrayList`方法中，索引值是否大于或等于`list.size()`？如果是，则越界。
- `SomeClass`的客户端程序是否试图直接访问`SomeClass`的私有实例变量或私有方法？这会导致错误。
- 是否在构造函数中使用了关键字`super`？如果是，它最好位于代码的第一行；否则，会导致编译时错误。
- 如果要将值插入有序列表，是否有范围检查，以确保算法不会超出列表末尾？

### 循环跟踪

以下是一些技巧：

- 有几道题会询问循环执行了多少次。问题的表述方式可能不同：某个单词或短语将打印多少次？循环体中的方法将执行多少次？如果数字较小，写下循环将执行时循环变量的所有值，然后数一数！那就是答案。
- 如果带有循环的问题的答案取决于参数`n`，尝试将`n`设为 2 或 3 以观察规律。
- 务必注意循环测试使用的是`<`还是`<=`（或`>`还是`>=`）。
- 留意循环变量是如何变化的。它不总是`i++`（增 1）或`i--`（减 1）。

### Java 异常

有时，其中一个答案选项如下：

> 代码抛出`<某种运行时异常>`。

浏览算法检查以下情况：

- 数组、`ArrayList`或`String`越界。每种情况都会抛出相应的异常：`ArrayIndexOutOfBoundsException`、`IndexOutOfBoundsException`或`StringIndexOutOfBoundsException`。如果发现了，甚至无需瞥一眼其他选项即可继续做下一题。
- 整数除以零。如果除以零发生在复合测试的第一部分，则`ArithmeticException`总会被抛出。如果除法在测试的第二部分，且整个测试的值已知（短路求值），则不会抛出异常。（参见第 70 页。）

### 矩阵操作

假设给定一个矩阵和一个以某种方式修改该矩阵的算法。这些算法通常难以跟踪，而且更棘手的是，你没有太多时间。

假设`row`和`col`是算法中的循环变量。对于快速解法，尝试查看对应循环中第一个`row`值和第一个`col`值的元素。通常这是左上角的元素。它会变吗？基于这一个元素，你能排除某些选项吗？对最终的`row`和`col`值重复此过程。通常这是右下角的元素。你能排除其他选项吗？

换句话说，你不总是需要跟踪所有值就能找到答案。

### 算法比较

可能会有几道题要求你比较两个据称实现相同算法的算法。它们可能会问你哪个算法更高效。影响效率的因素是比较次数和数据移动次数。检查每个循环的主体。统计比较次数和数据移动次数。将总数乘以循环的迭代次数。答案较低的算法即为更高效的算法。

你可能会被要求比较数据结构。这些是你应该自问的问题：

- 哪种结构定位给定元素所需的比较次数最少？
- 哪种结构插入或删除元素所需的数据移动次数最少？
- 该结构是否存储对象的完整状态？

### 包和类

典型的 Java 程序包含用户定义的类，它们的对象与 Java 类库中的对象进行交互。在 Java 中，相关的类被分组到*包*中，其中许多随编译器提供。例如，包`java.util`包含集合类。注意，你可以将自己的类放入一个包中——这便于它们在其他程序中使用。

包`java.lang`包含许多常用类，会自动提供给所有 Java 程序。要在程序中使用任何其他包，必须使用`import`语句。要导入名为`packagename`的包中的所有类，请使用以下形式：

```
import packagename.*;
```

注意包名全为小写字母。要从包中导入名为`ClassName`的单个类，请使用：

```
import packagename.ClassName;
```

Java 具有包和子包的层次结构。子包通过多个点来选择：

```
import packagename.subpackagename.ClassName;
```

例如：

```
import java.util.ArrayList;
```

`import`语句允许程序员使用指定包中定义的对象和方法。你不需要编写任何`import`语句。

Java 程序必须至少有一个类，即包含*主方法*的那个类。组成程序的 Java 文件称为*源文件*。

*编译器*将源代码转换为称为*字节码*的机器可读形式。

### 类型与标识符

### 标识符

**标识符**是变量、参数、常量、用户定义方法或用户定义类的名称。在 Java 中，标识符是由字母、数字和下划线字符组成的任意序列。标识符不能以数字开头。标识符区分大小写，这意味着`age`和`Age`是不同的。在可能的情况下，标识符应当简洁且自文档化。名为`area`的变量比名为`a`的变量更具说明性。

按照惯例，变量和方法的标识符使用小写。大写字母用于将多个单词分隔开，例如`getName`、`findSurfaceArea`、`preTaxTotal`等。注意类名以大写字母开头。保留字全为小写，不能用作标识符。
