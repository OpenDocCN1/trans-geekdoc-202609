
```
if 'a' <= c && c <= 'z' ||
    'A' <= c && c <= 'Z' ||
    '0' <= c && c <= '9' {
    // ...ASCII 字母或数字...
}
```

布尔值不会隐式转换为 0 或 1 等数值，反之亦然。必须使用显式的 `if` 语句，如：

```
i := 0
if b {
    i = 1
}
```

如果经常需要此操作，编写一个转换函数可能很有用：

```
// btoi 如果 b 为 true 返回 1，如果为 false 返回 0。
func btoi(b bool) int {
    if b {
        return 1
    }
    return 0
}
```

逆操作非常简单，不值得写一个函数，但为了对称，这里给出：

```
// itob 报告 i 是否非零。
func itob(i int) bool { return i != 0 }
```

## 3.5 字符串

字符串是一个不可变的字节序列。字符串可以包含任意数据，包括值为 0 的字节，但通常它们包含人类可读的文本。文本字符串通常被解释为 UTF-8 编码的 Unicode 码点（`rune`）序列，我们很快将详细探讨这一点。

内置的 `len` 函数返回字符串中的字节数（而非 `rune` 数），索引操作 `s[i]` 获取字符串 `s` 的第 `i` 个字节，其中 `0 ≤ i < len(s)`。

```
s := "hello, world"
fmt.Println(len(s))     // "12"
fmt.Println(s[0], s[7]) // "104 119"  ('h' 和 'w')
```

尝试访问此范围之外的字节会导致 panic：

```
c := s[len(s)] // panic: index out of range
```

字符串的第 `i` 个字节不一定是字符串的第 `i` 个*字符*，因为非 ASCII 码点的 UTF-8 编码需要两个或更多字节。稍后将讨论如何处理字符。

*子字符串*操作 `s[i:j]` 生成一个新字符串，该字符串由原字符串从索引 `i` 开始、直到但不包括索引 `j` 处字节的字节序列组成。结果包含 `j-i` 个字节。

```
fmt.Println(s[0:5]) // "hello"
```

同样，如果任一索引越界，或者 `j` 小于 `i`，则会导致 panic。

`i` 和 `j` 操作数中的任一个或两个均可省略，在这种情况下，分别假定其默认值为 `0`（字符串开头）和 `len(s)`（字符串结尾）。

```
fmt.Println(s[:5]) // "hello"
fmt.Println(s[7:]) // "world"
fmt.Println(s[:])  // "hello, world"
```

`+` 运算符通过连接两个字符串来创建一个新字符串：

```
fmt.Println("goodbye" + s[5:]) // "goodbye, world"
```

字符串可以使用 `==` 和 `<` 等比较运算符进行比较；比较是逐字节进行的，因此结果是自然的字典序。

字符串值是不可变的：字符串值包含的字节序列永远不能被改变，尽管当然我们可以给字符串*变量*赋一个新值。例如，要将一个字符串追加到另一个字符串后面，我们可以写：

```
s := "left foot"
t := s
s += ", right foot"
```

这不会修改 `s` 原来持有的字符串，而是导致 `s` 持有由 `+=` 语句形成的新字符串；同时，`t` 仍然包含旧字符串。

```
fmt.Println(s) // "left foot, right foot"
fmt.Println(t) // "left foot"
```

由于字符串不可变，试图原地修改字符串数据的构造是不被允许的：

```
s[0] = 'L' // compile error: cannot assign to s[0]
```

不可变性意味着两个副本的字符串共享相同的底层内存是安全的，这使得复制任意长度的字符串代价很低。类似地，字符串 `s` 和像 `s[7:]` 这样的子字符串也可以安全地共享相同的数据，因此子字符串操作也很廉价。这两种情况都不需要分配新内存。图 3.4 说明了一个字符串及其两个子字符串共享同一个底层字节数组的排列。

![字符串 "hello, world" 及其两个子字符串。](img/stringshare.png)

### 3.5.1 字符串字面量

字符串值可以写成*字符串字面量*，即用双引号括起来的一系列字节：

```
"Hello, "
```

因为 Go 源文件总是采用 UTF-8 编码，且 Go 文本字符串按惯例解释为 UTF-8，所以我们可以在字符串字面量中包含 Unicode 码点。

在双引号字符串字面量中，以反斜杠 `\` 开头的*转义序列*可用于将任意字节值插入字符串。一组转义序列处理像换行、回车和制表符这样的 ASCII 控制码：

| 转义序列 | 说明 |
| --- | --- |
| `\a` | “alert” 或响铃 |
| `\b` | 退格 |
| `\f` | 换页 |
| `\n` | 换行 |
| `\r` | 回车 |
| `\t` | 制表符 |
| `\v` | 垂直制表符 |
| `\'` | 单引号（仅用于 rune 字面量 `'\''`） |
| `\"` | 双引号（仅用于 `"..."` 字面量内） |
| `\\` | 反斜杠 |

任意字节也可以通过十六进制或八进制转义包含在字面量字符串中。*十六进制转义*写作 `\xhh`，包含恰好两个十六进制数字 `h`（大小写均可）。*八进制转义*写作 `\ooo`，包含恰好三个八进制数字 `o`（0 到 7），不超过 `\377`。两者都表示一个具有指定值的单个字节。稍后我们将看到如何在字符串字面量中以数字形式编码 Unicode 码点。

*原始字符串字面量*写作 `` `...` ``，使用反引号代替双引号。在原始字符串字面量中，不处理任何转义序列；内容按字面意思获取，包括反斜杠和换行符，因此原始字符串字面量在程序源代码中可以跨越多行。唯一的处理是删除回车符，以便字符串的值在所有平台上都相同，包括那些习惯在文本文件中放置回车符的平台。

原始字符串字面量是编写正则表达式的便捷方式，因为正则表达式往往包含大量反斜杠。它们对于 HTML 模板、JSON 字面量、命令用法消息等也很有用，这些内容通常跨越多行。

```
const GoUsage = `Go is a tool for managing Go source code.

Usage:
    go command [arguments]
...`
```

### 3.5.2 Unicode

很久以前，生活很简单，至少在狭隘的视角下，只有一个字符集需要处理：ASCII，即美国信息交换标准代码。ASCII，或更准确地说 US-ASCII，使用 7 位来表示 128 个“字符”：英文大小写字母、数字，以及各种标点和设备控制字符。在计算机早期的大部分时间里，这已经足够，但它导致世界上很大一部分人口无法在计算机中使用自己的书写系统。随着互联网的增长，各种语言的数据变得更加普遍。如何处理这种丰富的多样性，如果可能的话，如何高效处理？

答案是 Unicode (`unicode.org`)，它收集了世界上所有书写系统中的所有字符，以及重音符号和其他变音符号、像制表符和回车符这样的控制码，还有大量晦涩字符，并为每一个分配一个标准编号，称为* Unicode 码点*，或者用 Go 术语来说，称为* rune*。

Unicode 8.0 版为 100 多种语言和文字中的 120,000 多个字符定义了码点。这些在计算机程序和数据中如何表示？保存单个 rune 的自然数据类型是 `int32`，这正是 Go 所使用的；它为此目的提供了同义词 `rune`。

我们可以用一系列 `int32` 值来表示一系列 rune。在这种称为 UTF-32 或 UCS-4 的表示法中，每个 Unicode 码点的编码大小相同，均为 32 位。这简单且统一，但比必要的空间大得多，因为大多数计算机可读文本是 ASCII，每个字符只需 8 位或 1 字节。广泛使用的所有字符总数仍少于 65,536，可以放入 16 位。我们能做得更好吗？

### 3.5.3 UTF-8

# UTF-8 编码

UTF-8 是 Unicode 码点作为字节的变长编码。UTF-8 由 Ken Thompson 和 Rob Pike 发明，他们是 Go 语言的两位创始人，现在 UTF-8 已成为 Unicode 标准。它使用 1 到 4 个字节来表示每个 rune，但 ASCII 字符仅需 1 字节，常用的大多数 rune 只需 2 或 3 字节。编码中首字节的高位指示后续有多少字节。高位 `0` 表示 7 位 ASCII，每个 rune 仅占 1 字节，因此与传统 ASCII 完全相同。高位 `110` 表示该 rune 占 2 字节；第二字节以 `10` 开头。更大的 rune 具有类似的编码方式。

| `0xxxxxx` | runes 0–127 | (ASCII) |
| --- | --- | --- |
| `110xxxxx 10xxxxxx` | 128–2047 | (values <128 unused) |
| `1110xxxx 10xxxxxx 10xxxxxx` | 2048–65535 | (values <2048 unused) |
| `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx` | 65536–0x10ffff | (other values unused) |

变长编码使得无法通过直接索引访问字符串的第 *n* 个字符，但 UTF-8 拥有许多理想的特性来弥补这一点。编码紧凑、兼容 ASCII 且自同步：通过回退不超过三个字节即可找到字符的开头。它还是一种前缀码，因此可以从左向右解码，无需任何歧义或前瞻。没有任何 rune 的编码是其他 rune 编码的子串，甚至不是一串 rune 编码的子串，所以你可以通过搜索其字节来查找 rune，而无需担心前面的上下文。字典序字节顺序等于 Unicode 码点顺序，因此对 UTF-8 排序自然有效。没有嵌入的 NUL（零）字节，这对于使用 NUL 终止字符串的编程语言非常方便。

Go 源文件始终采用 UTF-8 编码，UTF-8 也是 Go 程序处理文本字符串的首选编码。`unicode` 包提供了处理单个 rune 的函数（如区分字母和数字，或将大写字母转换为小写），`unicode/utf8` 包提供了使用 UTF-8 将 rune 编码和解码为字节的函数。

许多 Unicode 字符难以在键盘上输入，或难以在视觉上与外观相似的字符区分；有些甚至是不可见的。Go 字符串字面量中的 Unicode 转义序列允许我们通过其数值码点来指定它们。有两种形式：`\u`*hhhh* 表示 16 位值，`\U`*hhhhhhhh* 表示 32 位值，其中每个 *h* 都是十六进制数字；32 位形式极少用到。每种形式都表示指定码点的 UTF-8 编码。因此，例如，以下字符串字面量都表示相同的六字节字符串：

```
""
"\xe4\xb8\x96\xe7\x95\x8c"
"\u4e16\u754c"
"\U00004e16\U0000754c"
```

上述三种转义序列为第一个字符串提供了替代表示法，但它们表示的值是相同的。

Unicode 转义也可用于 rune 字面量。以下三个 rune 字面量等价：

```
''  '\u4e16'  '\U00004e16'
```

值小于 256 的 rune 可用单个十六进制转义表示，例如 `'\x41'` 表示 `'A'`，但对于更大的值，必须使用 `\u` 或 `\U` 转义。因此，`'\xe4\xb8\x96'` 不是合法的 rune 字面量，尽管这三个字节是单个码点的有效 UTF-8 编码。

得益于 UTF-8 的优良特性，许多字符串操作不需要解码。我们可以测试一个字符串是否包含另一个作为前缀：

```
func HasPrefix(s, prefix string) bool {
    return len(s) >= len(prefix) && s[:len(prefix)] == prefix
}
```

或作为后缀：

```
func HasSuffix(s, suffix string) bool {
    return len(s) >= len(suffix) && s[len(s)-len(suffix):] == suffix
}
```

或作为子串：

```
func Contains(s, substr string) bool {
    for i := 0; i < len(s); i++ {
        if HasPrefix(s[i:], substr) {
            return true
        }
    }
    return false
}
```

对 UTF-8 编码文本使用的逻辑与原始字节完全相同。这对其他编码不成立。（上述函数源自 `strings` 包，尽管其 `Contains` 实现使用哈希技术以更高效地搜索。）

另一方面，如果我们真正关心单个 Unicode 字符，就必须使用其他机制。考虑我们最开始示例中的字符串，它包含两个东亚字符。图 3.5 展示了它在内存中的表示。该字符串包含 13 个字节，但按 UTF-8 解码仅包含 9 个码点或 rune：

![range 循环解码 UTF-8 编码的字符串。](img/stringutf8.png)

**图 3.5.** `range` 循环解码 UTF-8 编码的字符串。

```
import "unicode/utf8"

s := "Hello, "
fmt.Println(len(s))                    // "13"
fmt.Println(utf8.RuneCountInString(s)) // "9"
```

要处理这些字符，我们需要 UTF-8 解码器。`unicode/utf8` 包提供了一个，用法如下：

```
for i := 0; i < len(s); {
    r, size := utf8.DecodeRuneInString(s[i:])
    fmt.Printf("%d\t%c\n", i, r)
    i += size
}
```

每次调用 `utf8.DecodeRuneInString` 都会返回 `r`（rune 本身）和 `size`（`r` 的 UTF-8 编码占用的字节数）。`size` 用于更新下一个 rune 在字符串中的字节索引 `i`。但这很笨拙，且我们经常需要这种循环。幸运的是，Go 的 `range` 循环应用于字符串时会隐式执行 UTF-8 解码。下面循环的输出也显示在图 3.5 中；注意索引如何为每个非 ASCII rune 跳过多于 1 的位置。

```
for i, r := range "Hello, " {
    fmt.Printf("%d\t%q\t%d\n", i, r, r)
}
```

我们可以用简单的 `range` 循环来统计字符串中的 rune 数量，如下所示：

```
n := 0
for _, _ = range s {
    n++
}
```

与其他形式的 `range` 循环一样，我们可以省略不需要的变量：

```
n := 0
for range s {
    n++
}
```

或者直接调用 `utf8.RuneCountInString(s)`。

我们之前提到过，在 Go 中将文本字符串解释为 UTF-8 编码的 Unicode 码点序列主要是约定俗成，但对于在字符串上正确使用 `range` 循环，这不仅仅是约定，而是必要条件。如果我们对包含任意二进制数据的字符串，或者包含错误的 UTF-8 数据的字符串进行 range 迭代，会发生什么？

每当 UTF-8 解码器（无论是显式调用 `utf8.DecodeRuneInString`，还是在 `range` 循环中隐式调用）遇到意外的输入字节时，都会生成一个特殊的 Unicode *替换字符* `'\uFFFD'`，通常显示为黑色六边形或菱形中带白色问号的形状 ![Image](img/icon-6.jpg)。当程序遇到此 rune 值时，通常表明生成该字符串数据的上游系统部分在处理文本编码时不够严谨。

UTF-8 作为交换格式非常方便，但在程序内部，rune 可能更方便，因为它们大小统一，因此在数组和切片中易于索引。

将 `[]rune` 转换应用于 UTF-8 编码的字符串，会返回该字符串编码的 Unicode 码点序列：

```
// "program" 的日文片假名写法
s := ""
fmt.Printf("% x\n", s) // "e3 83 97 e3 83 ad e3 82 b0 e3 83 a9 e3 83 a0"
r := []rune(s)
fmt.Printf("%x\n", r)  // "[30d7 30ed 30b0 30e9 30e0]"
```

(第一个 `Printf` 中的动词 `% x` 会在每对十六进制数字之间插入一个空格。)

如果将一个 rune 切片转换为字符串，它会生成每个 rune 的 UTF-8 编码的连接：

```
fmt.Println(string(r)) // "プログラム"
```

将整数值转换为字符串会将该整数解释为一个 rune 值，并生成该 rune 的 UTF-8 表示形式：
