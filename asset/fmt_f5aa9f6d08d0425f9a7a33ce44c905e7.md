# IT 基础设施管理的最佳实践
可以通过许多方法管理风险。以下列表代表了 IT 专业人员考虑的做法：

*   **制定安全策略**——高层管理识别并支持安全工作，并制定安全策略，该策略提供了安全目标的高层概述，但不涉及如何实施安全技术的细节。经理使用该策略识别资源并制定实施计划。一旦安全策略获得批准，就需要进行实施和执行。

*   **购买保险**——公司购买保险以减少威胁的影响。他们通常购买火灾、盗窃和环境事件导致损失的保险。这里考虑的重要原则是：
    *   **比例原则**——用于缓解风险的支出（如购买保险）应与风险成比例。例如，不应购买 10 万美元的保单来保护 5 万美元的资产。

*   **使用访问控制**——用户应通过身份验证，并仅授予访问所需内容的。使用访问控制包括以下两个原则：
    *   **最小权限原则**——最小权限原则涉及仅授予用户执行其工作所需的权利和权限，而不多给。通过这种方式，可以防止用户意外或故意地引起问题。
    *   **知情需要原则**——知情需要原则涉及仅授予用户执行其工作所需的数据访问权限，而不多给。例如，某人可能拥有机密（Secret）数据的安全许可。然而，该人员并不会自动获得所有机密数据的访问权限。相反，该人员仅被授予其工作所需的访问权限。这有助于防止不必要的访问权限被滥用。

*   **使用自动化**——应尽可能实现流程自动化，以减少人为错误。

*   **包含输入验证**——为了确定数据是否有效，应在任何应用程序使用该数据之前对其进行测试。

*   **提供培训**——培训可用于提高安全意识并减少事故，还可以增强安全意识以减少安全事件。

*   **使用防病毒软件**——所有系统都应安装防病毒软件，并安排自动进行病毒库更新。

*   **保护边界**——至少应使用防火墙来保护内网与互联网之间的边界。入侵检测系统（`IDSs`）也可以用于额外的保护层。

### 提示
安全策略可能包含若干项单独的策略。例如，它可以包含密码策略、可接受使用策略和防火墙策略。

### 注意
权限包括权利和许可。`Rights`（权利）指的是用户在对象上可以执行的操作。例如，用户可能拥有更改系统时间的权利。`Permissions`（许可/权限）指的是对对象的访问。例如，用户可能拥有读取和修改文件的许可。`最小权限原则`包含了权利和许可。`知情需要原则`侧重于数据访问许可。

## 缓解技术
任何企业都可以使用多样化的缓解技术。在探索本节中的技术时，应牢记以下要素：

*   技术的有效性
*   技术的初始成本和持续成本

例如，杀毒软件有一项初始成本，其中包括在某段时间内（如一年）的更新订阅费用。当订阅过期时，必须进行续费。

在估算任何这些技术的价值和成本时，可以考虑资源的价值和损失的影响。例如，基础社会工程策略的培训可能每年耗花费 10,000 美元。然而，如果用户没有接受培训，公司可能会损失 100,000 美元。因此，培训的价值为 90,000 美元。

然而，在估算缓解技术的价值时，还有其他需要考虑的变量。公司去年可能损失了 100,000 美元。如果进行了培训，公司预计今年将损失 5,000 美元。因此，培训的价值为 85,000 美元。计算方法如下：

```
Last year’s loss − Training cost − This year’s loss
$100,000 − $10,000 − $5,000 = $85,000
```

以下列表列出了任何企业都可以使用的常用缓解技术：

*   **策略和程序**——书面策略和程序提供了标准。这些标准明确了应该实施什么以及如何实施。正如前面提到的，许多组织从创建安全策略开始。应该定期审查策略和程序。

*   **文档记录**——文档在许多领域都很有用。更新的网络文档使问题更易排查。一旦发生问题，就可以更快地修复，从而提高可用性时间。随着网络和系统的变化，更新文档是必要的。

*   **培训**——培训帮助员工理解安全是每个人的责任。某些培训面向所有用户，而其他培训必须针对特定用户。例如，所有终端用户都应接受关于社会工程师的培训，管理员应接受当前威胁和漏洞的培训，经理应接受风险管理策略的培训。培训是一项持续活动；随着情况的变化，应提供更新的培训课程。

*   **职责分离**——职责分离原则（也称为职责分工）确保没有某个人能控制关键流程的所有功能。该原则旨在防止欺诈、盗窃和错误。例如，会计部门将应收账款和应付账款分开。一个部门接收并批准账单，另一个部门则支付已批准的账单。职责分离还助于防止利益冲突。

*   **配置管理**——当系统配置标准化时，系统更易于排查和维护。配置管理的一种方法是使用基准。例如，对系统进行配置然后创建一个系统镜像。该镜像可以部署到其他 100 台系统中，使每个系统都完全相同。维护这些系统中的每一个的方法是相同的。技术人员学会了一个系统，就学会了所有此类系统。如果没有基准，系统可能会有 100 种不同的配置方式，导致技术人员在提供有效支持之前必须学习每个系统是如何配置的。镜像随配置而更新。配置管理还确保系统不会被不当修改。大多数组织都有变更管理流程，以确保只进行授权的更改。通过合规性审计确保不会发生未经授权的更改。

*   **版本控制**——当多人协作同一份文档或应用程序时，数据可能会丢失或损坏。版本控制系统常用于应用程序开发。它们跟踪所有的更改并可以减少浪费的时间和，特别是当需要撤销更改时。该过程要求程序员在修改模块或文件之前将其检出。文件修改后，可以提交，其他人也可以修改该文件。某些版本控制软件允许将多个更改合并到一个文件中。

*   **补丁管理**——随着时间的推移，软件中可能会发现漏洞。软件漏洞是可以被利用的缺陷。当发现漏洞时，供应商会发布补丁；然而，攻击者也会发现这些漏洞。未打补丁的系统容易受到攻击。全面的补丁管理规范了如何理解、测试以及将补丁部署到系统和客户端。策略应包括合规审计，以验证客户端是否是最新的。补丁管理还可以包括隔离未打补丁客户端的能力。补丁管理几乎是一个持续的过程。

*   **入侵检测系统**——入侵检测系统（`IDS`）旨在检测威胁而非防御威胁。被动 `IDS` 会记录事件并可能提供报警。主动 `IDS` 在检测到攻击后可能会修改环境以拦截。许多 `IDS` 使用定义就像杀毒软件使用签名。基于网络的 `IDS`（`NIDS`）提供整体网络保护。基于主机的 `IDS`（`HIDS`）可以保护单个系统。

*   **事件响应**——当公司做好准备并能够响应事件时，它更有机会减少影响。响应事件时的一项重要步骤是遏制，这确保了事件不会扩散到其他系统。事件响应团队试图识别发生了什么。他们寻找导致事件发生的漏洞，然后寻求在未来减少这些漏洞的方法。另一方面，有些公司希望尽快忘记事件。他们试图修复眼前的问题，而不去解决底层问题。必须解决根本性问题，以减少相同问题再次发生事件的概率。

在代码的语境下，利用主要攻击面向公共的服务器。换句话说，它攻击在互联网上可用的服务器。常见的互联网服务器有：

由于 `DMZ` 中的服务器面向公共的，任何具有公共互联网协议（`IP`）地址的人都可以访问它们，这包括攻击者或黑客。

尽管内部服务器容易受到员工的攻击，但员工利用漏洞攻击内部服务器并不常见。员工可以进行攻击并造成损害；但窃取数据或进行破坏对他们来说容易得多。内部人员通常不会花时间编写程序来攻击内部系统。内部人员拥有至少一些基本的员工权限和内部知识。通常，内部网络是受信任的，因此公司对内部网络上的利用关注较少。

`缓冲区溢出` 是一种常见的攻击类型。当攻击者发送的数据比系统或应用程序预期的多或不同时，就会发生这种情况。当系统或应用程序未准备好拒绝这些数据时，漏洞就会存在，这会导致系统运行不可靠。此外，如果漏洞创建者特别高明，漏洞将运行额外的指令，从而在系统上获得额外的权限。

通常情况下，系统会验证并拒绝非预期的数据。偶尔，漏洞会允许无效数据被使用。

例如，这里有一个简单的验证计算：`X / Y = Z`。程序期望提供 `X` 和 `Y` 的值。然后它将两者相除以计算 `Z` 的值。然而，如果将 0 作为 `X` 或 `Y` 的值，则无法计算 `Z`。零不能被任何数字除。如果程序没有检查 `X` 和 `Y` 是否为有效数字，当用户输入零时，程序可能会失败。如果错误处理得不当，攻击者可能会利用这一失败。

缓冲区溢出错误允许攻击者插入额外数据，这些数据通常是要求立即运行的意外命令的形式。该命令可能会插入一个在网络中传播的蠕虫，或导致服务器关闭且无法重启，也可能是寻找并破坏系统上数据的代码。

当厂商发现缓冲区溢出漏洞时，他们会修复代码以防止未来发生此类错误。应该下载并应用此补丁以修补该漏洞。

### 注意
虽然除以零错误很容易解释，但它在今天引起问题的可能性不大。大多数应用程序都会检测到该问题并且永远不会尝试除以零。然而，还有许多未被预见的更高级错误。

## Nimda 病毒
Nimda 病毒是一个旧病毒的例子，它利用了微软 Internet 信息服务（`IIS`）中的缓冲区溢出问题。这个病毒有助于解释从 IT 风险管理中学到的许多教训。

首先，在安装 Windows 2000 Server 时会默认安装 `IIS`。由于 `IIS` 是默认安装的，它通常没有被管理，而未管理的服务更容易受到攻击。

当缓冲区溢出被发现时，微软发布了一个补丁，只要应用了该补丁就能解决问题。然而，当时补丁管理还处于起步阶段。许多公司没有有效的补丁管理计划，并且没有一致地应用补丁。许多系统管理员错误地得出结论，因为他们没有使用 `IIS`，所以他们的系统没有受到威胁。然而，因为 `IIS` 是默认安装的，他们的系统实际上是有漏洞的。

Nimda 发布在互联网上，采取了多管齐下的方法。缓冲区溢出允许它利用 `IIS` 系统，它有一个蠕虫组件，允许它寻找并感染内部网络上的其他系统，它寻找互联网上容易受到相同缓冲区溢出的其他 `IIS` 服务器，并让网络活动慢到爬行速度且破坏数据。

被 Nimda 强化的两个基本安全实践是：

*   **减少服务器的攻击面**——不应安装不需要的服务和协议。如果已经安装，就应该将其删除。如果服务器上没有安装 `IIS`，它就不会受到 Nimda 的攻击。这种情况在本文后部分会有解释。
*   **保持系统更新**——如果 `IIS` 服务器已经用发布的补丁进行了更新，它们就不会受到这种攻击。

其他攻击手段包括：

*   **SQL 注入攻击**——SQL 注入攻击利用了对用户提供数据的审查或检查的疏严。许多网站要求用户在文本框或网络地址中输入数据。如果用户提供的数据没有经过适当验证，这些数据就可以被直接用作 SQL 语句，这就是 SQL 注入攻击发生的情况。通常，在提供预期的数据末尾，会添加一个 SQL 命令。这种注入攻击执行了一段不同的 SQL 代码字符串。这段不同的代码可能会破坏数据库。通过使用参数和存储过程可以很容易避免 SQL 注入攻击，它们在允许代码影响系统之前会对代码进行审查。然而，并不是所有的数据库开发者都意识到这些风险。

*   **拒绝服务（`DoS`）攻击**——拒绝服务（`DoS`）攻击旨在防止系统提供服务。例如，`SYN` 洪水攻击就很常见。通常情况下，传输控制协议（`TCP`）使用三次握手来建立连接。主机发送一个设置了同步（`SYN`）标志的数据包。服务器返回设置了 `SYN` 和确认（`ACK`）标志的包。主机随后返回设置了 `ACK` 标志的包以完成握手。在 `SYN` 洪水攻击中，主机永远不会响应第三个包。这种场景可以比作主机和服务器伸出手要握手，但主机随后收回了手，导致服务器的手悬在空中。当在短时间内重复进行这种操作时，会消耗服务器的资源并导致其崩溃。

*   **分布式拒绝服务（`DDoS`）攻击**——分布式拒绝服务（`DDoS`）攻击从多个客户端同时启动。例如，许多犯罪分子和攻击者从命令和控制中心运行僵尸网络。僵尸网络控制多个作为 `克隆` 或 `僵尸` 的主机。这些克隆可以在任何时间接收命令并进行攻击。攻击可能只是简单地 ping 服务器。如果成千上万个客户端都在 ping 服务器，它就无法轻松响应其他请求。

### 注意
结构查询语言（`SQL`）是用于查询和修改数据库的语言。它有必须遵守的规则。动态 `SQL` 是直接接受用户输入的 `SQL` 语句。例如，语句可能是 `SELECT FROM Users Where LName = ‘txt.Name’`。在这个例子中，`txt.Name` 的值是从文本框中获取并在程序运行时使用的。不建议在没有任何输入过滤的情况下允许用户直接输入。

*   **公共服务器发现**——互联网上的每个系统都有公网 IP 地址。该部门可以使用 `ping` 扫描器来识别运行公网 IP 地址的系统。IP 地址是按地理分配的，因此服务器也可以映射到地理位置。

*   **服务器指纹识别**——该部门可以使用多种方法来尽可能多地了解被发现服务器的信息。可以使用 `ping` 来识别系统运行的是 UNIX 还是微软操作系统。该部门可以使用端口扫描来识别哪些端口是开放的。根据开放的端口，可以识别出正在运行的协议。例如，端口 `80` 是超文本传输协议（`HTTP`）的常用。因此，如果端口 `80` 是开放的，那么 `HTTP` 可能正在运行。如果 `HTTP` 正在运行，该服务器可能是一个 Web 服务器。该部门可以使用其他技术来确定服务器是 Apache 还是 IIS Web 服务器。
