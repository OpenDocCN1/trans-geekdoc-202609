### 专有和闭源情报

商业安全供应商、政府组织和其他以安全为中心的组织也会创建和使用专有或**闭源情报**。它们进行自己的信息收集和研究，并可能使用自定义工具、分析模型或其他专有方法来收集、策划和维护其威胁源。

使用专有威胁情报有多种原因。组织可能希望保持其威胁数据的机密性，可能希望出售或授权该数据，且其方法和来源属于商业机密，或者他们可能不愿冒险让威胁行为者知晓他们正在收集的数据。

商业闭源情报通常作为服务产品的一部分，这对安全专业人员来说可能是一个极具吸引力的资源。通过开源威胁情报源获得的海量数据可能会让许多组织应接不暇。梳理威胁源以识别相关威胁，然后确保它们定义明确且适合您的组织适当应用，可能需要付出巨大的努力。在许多情况下，验证威胁数据可能很困难，一旦您完成了确保拥有高质量威胁数据的工作，您仍然必须对其采取行动！

### 评估威胁情报

无论您的威胁情报信息来源如何，您都需要对其进行评估。当您评估威胁情报来源或特定威胁情报通知时，有许多常见因素会发挥作用。

1.  它及时吗？运行在延迟上的源可能导致您错过威胁，或在威胁不再相关后才做出反应。

#### 信息准确性

信息是否准确？你能否依赖其内容，评估有多大可能是有效的？它是依赖单一来源还是多个来源？这些来源的正确频率如何？

#### 信息相关性

信息是否相关？如果它描述了错误的平台、软件或组织成为目标的原因，那么该数据可能非常及时、非常准确，但与你的组织完全无关。

#### 置信度评分

总结威胁情报评估数据的一种方法是通过置信度评分。置信度评分允许组织根据他们能给予多少信任来筛选和使用威胁情报。这并不意味着较低置信度的信息没有用处；事实上，许多威胁情报最初都是从较低的置信度评分开始的，随着信息的巩固以及额外信息来源的确认或全面分析，该评分会逐渐提高。低置信度的威胁信息不应被完全忽视，但也不应在不考虑其低置信度评分的情况下，依赖它做出重要决策。

### 威胁指标管理与交换

在任何规模下管理威胁信息都需要标准化和工具支持，以便以自动化方式处理和使用威胁信息。有了明确定义的术语集，指标管理会容易得多。这正是结构化标记语言（如 `STIX` 和 `OpenIOC`）发挥作用的地方。

#### STIX

*Structured Threat Information eXpression (STIX)* 是一种最初由美国国土安全部赞助的 XML 语言。在其当前版本中，`STIX 2.0` 定义了 12 个 STIX 领域对象，包括攻击模式、身份、恶意软件、威胁行为者和工具等。这些对象随后通过两种 STIX 关系对象模型之一相互关联：要么作为关系，要么作为目击。

一个 `STIX 2.0` JSON 格式的威胁行为者描述示例如下：

```json
{
 "type": "threat-actor",
 "created": "2019-10-20T19:17:05.000Z",
 "modified": "2019-10-21T12:22:20.000Z",
 "labels": [ "crime-syndicate"],
 "name": "Evil Maid, Inc",
 "description": "Threat actors with access to hotel rooms",
 "aliases": ["Local USB threats"],
 "goals": ["Gain physical access to devices", "Acquire data"],
 "sophistication": "intermediate",
 "resource:level": "government",
 "primary_motivation": "organizational-gain"
}
```

像 `sophistication` 和 `resource level` 这样的字段使用定义好的词汇选项，以允许 `STIX 2.0` 用户在自动化和手动系统中一致地使用数据。

自创建以来，`STIX` 已移交给结构化信息标准促进组织（`OASIS`），这是一个国际非营利联盟，维护着许多与信息格式化相关的其他项目，包括 `XML` 和 `HTML`。

#### TAXII

`STIX` 的伴侣协议是 *Trusted Automated eXchange of Indicator Information (TAXII)*。`TAXII` 旨在允许通过 `HTTPS` 在应用层传输网络威胁信息。`TAXII` 专门设计用于支持 `STIX` 数据交换。你可以在 `OASIS` 的 GitHub 文档站点 `oasis-open.github.io/cti-documentation` 上详细了解 `STIX` 和 `TAXII`。

#### OpenIOC

另一种选择是 *Open Indicators of Compromise (OpenIOC)* 格式。与 `STIX` 一样，`OpenIOC` 是一个基于 XML 的框架。`OpenIOC` 模式由 `Mandiant` 开发，并使用 `Mandiant` 的指标作为其基础框架。典型的 IOC 包含作者、IOC 名称和指标描述等元数据。IOC 的完整定义还可能包括导致指标发现的实际妥协细节。

### 公共和私人信息共享中心

除了威胁情报供应商和资源外，还建立了威胁情报社区来共享威胁信息。在美国，被称为信息共享与分析中心（`ISACs`）的组织帮助基础设施所有者和运营商共享威胁信息，并为其成员提供工具和协助。`ISAC` 国家委员会在 `www.nationalisacs.org/member-isacs` 列出了基于行业的 `ISACs`。

`ISAC` 概念于 1998 年作为总统决策指令 63（`PDD-63`）的一部分引入，该指令要求关键基础设施部门建立组织以共享威胁和漏洞信息。`ISACs` 基于信任模型运行，允许针对物理和网络威胁进行深度威胁信息共享。大多数 `ISACs` 全天候运行，为其行业内的 `ISAC` 成员提供事件响应和威胁分析。

除了 `ISACs` 外，每个关键基础设施领域还有特定的美国机构或部门合作伙伴。按行业细分的列表可在 `www.dhs.gov/cisa/critical-infrastructure-sectors` 找到。

在美国以外，许多国家都存在具有类似职责的政府机构和部门。英国国家基础设施保护中心（`www.cpni.gov.uk`）负责向工业界、学术界以及政府和执法部门的其他部分提供威胁信息、资源和指导。

### 开展自主研究

作为安全专业人员，你应该继续对新兴网络安全威胁进行自主研究。以下是在构建威胁研究工具包时可能咨询的来源：

*   供应商安全信息网站
*   来自供应商、政府机构和私人组织的漏洞和威胁情报源
*   学术期刊和技术出版物，如互联网 RFC 文档。`RFC` 文档特别有用，因为它们包含互联网协议的详细技术规范。
*   专业会议和当地行业团体会议
*   知名安全专业人士的社交媒体账号

在参考这些来源时，请特别留意关于对手 *战术、技术和程序（TTPs）* 的信息。更多地了解攻击者的运作方式，有助于你改进自己的威胁情报计划。

### 总结

网络安全专业人员必须对威胁形势有深入的理解，以便评估其组织面临的风险以及缓解这些风险所需的控制措施。网络安全威胁可根据其内部或外部状态、复杂程度和能力、资源和资金、意图和动机进行分类。

威胁行为者形式多样，从寻求成功入侵快感的相对不成熟的“脚本小子”，到将网络攻击作为军事武器以获取政治优势的先进国家行为者。黑客活动家、犯罪集团、竞争对手和其他威胁行为者可能出于不同原因针对同一组织。

网络攻击通过多种威胁向量发起。最常见的向量包括电子邮件和社交媒体；其他攻击可能通过直接物理访问、供应链漏洞利用、基于网络的攻击和其他向量发起。组织应建立强大的威胁情报计划，以帮助其掌握新兴威胁，并调整控制措施以适应不断变化的环境。

### 考试要点

**威胁行为者在几个关键属性上存在差异。** 我们可以使用四个主要标准对威胁行为者进行分类。首先，威胁行为者可能是组织内部的，也可能来自外部来源。其次，威胁行为者在复杂程度和能力上有所不同。第三，它们在可用资源和资金上有所不同。最后，不同的威胁行为者具有不同的动机和意图程度。

### 威胁行为者与攻击向量

#### 威胁行为者来源多样

威胁行为者的技术手段可能非常简单，例如利用他人编写的漏洞利用代码的“脚本小子”；也可能相当复杂，例如国家支持的行为者和犯罪集团构成的高级持续性威胁（APT）。黑客活动家可能旨在推行政治议程，而竞争对手可能寻求经济利益。我们可以根据黑客的动机和授权情况，将其分为白帽、灰帽和黑帽三类。

#### 攻击者利用不同向量获取初始访问权限

攻击者可能试图通过互联网远程获取对组织的初始访问权限，通过无线连接访问，或尝试直接物理访问。他们也可能通过电子邮件或社交媒体接触员工。攻击者可能试图利用可移动媒介诱骗员工无意中危害其网络，或者试图通过云服务传播漏洞利用代码。复杂的攻击者可能试图干扰组织的供应链。

#### 威胁情报提供有价值的洞见

安全团队可利用来自公开和私有来源的威胁情报，了解当前的威胁和漏洞。他们可能会寻找详细的妥协指标，并对自己的数据执行预测性分析。威胁情报团队通常会用自己的研究来补充从外部获取的开源情报和闭源情报。

#### 安全团队必须监控供应链风险

现代企业依赖硬件、软件和云服务供应商向内部和外部客户提供 IT 服务。供应商管理技术可保护供应链，防止攻击者破坏这些通往组织网络的外部环节。安全专业人员应特别关注外包代码开发、云数据存储以及外部与内部系统集成所带来的风险。

## 第 3 章：恶意代码

恶意软件形式多样，从勒索软件和远程访问木马到特洛伊木马、僵尸程序，以及允许攻击者运行整个受损系统网络的命令与控制基础设施。

### 恶意软件
