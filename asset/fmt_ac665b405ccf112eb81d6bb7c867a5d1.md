
# 现代操作系统与应用程序编程安全

现代操作系统和应用程序编程非常复杂。程序员在最初开发产品时，可能会犯编码错误，或创建出与开发团队中其他程序员创建的元素无法良好协作的产品部分。他们还可能从开源软件仓库（如 `GitHub`）下载有缺陷的代码片段和库。攻击者通常会利用软件漏洞插入并隐藏恶意代码，以破坏服务或操作。

特别是，攻击者可能会修改现有代码，在计算机内存中创建一种称为*缓冲区溢出*的条件，导致行为异常、内存访问错误和/或系统崩溃。系统实际上被禁用，用户无法使用。这种攻击被称为*拒绝服务*或 *DoS 攻击*。

## 信息泄露

OWASP 十大网络安全漏洞之一被指定为**信息泄露**。信息泄露是指敏感数据暴露的状况。导致数据暴露的最常见原因见于 HTML 或脚本注释、错误消息、或部署前未清理的源代码，以及配置错误的服务器或应用程序。这些攻击向量为攻击者提供了进入系统或从中提取数据的访问权限。

软件开发团队是恶意攻击者的主要目标。随着软件开发越来越多地在广泛分布的全职、外包/承包团队中进行，软件包中潜在攻击面的数量显著增加。

基于云的计算和存储操作是信息泄露的另一来源。配置错误的云存储桶（云环境中的数据存储区域）为攻击者提供了访问敏感云数据的途径。`Azure`、`GCP` 和 `Amazon S3` 等网站上配置不当的云权限可能会使大量数据暴露在互联网上。

此外，`GitHub` 等网站通常存放配置不当、泄露或共享的代码，这些代码可能为恶意行为者提供本不打算公开的源代码、`API` 密钥和数据。

为防止信息泄露，组织应采取以下活动：

*   为所有软件开发团队标准化编码实践。
*   集中加密密钥和机密存储实践。
*   在账户访问中采用最小权限原则——特别是与基于云的计算或存储相关的账户。
*   加密存储的数据（静态数据）。
*   采用外部泄露监控系统，检查暴露的 `GitHub` 仓库、配置错误的权限和暴露的云存储桶等攻击面。

## 应用软件更新和补丁

从上一节可以看出，由于产品开发的性质以及软件生产商推向市场的压力，新软件版本似乎永远不完整或不完美。随着软件产品的安全问题被揭露，其生产商被迫为其产品发布*安全补丁*以修复弱点。

安全补丁是为纠正观察到的弱点以防止漏洞被利用而专门发布的更新。`Microsoft` 每月为其产品发布一次安全补丁，并在该月的第二个星期二发布。其他软件开发商使用专门的安全团队，在发现漏洞后尽快开发和发布安全补丁。

出于安全和稳定性原因，您应始终为连接到互联网的计算设备修补操作系统。在大多数组织中，风险管理团队下设一个称为*补丁审查团队*的子团队，负责做出关于应用于 OT 设备补丁的决策。该团队在 **第 10 章 “ICS 安全监控和事件响应”** 的 **“控制补丁分发和安装”** 一节中有更详细的讨论。

理想情况下，组织应实施程序，以固定间隔安排软件升级和补丁管理程序。此外，这些程序应规定及时应用安全补丁，并定期实施软件供应商的建议。这些步骤可以大幅限制敌对方针对新发现漏洞（这些漏洞会被立即广泛公开）进行攻击的机会。

然而，在 OT 环境中，软件修改可能受 ICS 供应商的合同控制。其操作系统和应用软件的变更必须遵守其时间表，这涉及广泛的性能测试，以保证满足实时性能要求。在许多 OT 环境中，控制器通常受处理器性能限制，运行任何未经验证的软件组件（如操作系统补丁或安全软件）都会产生不可接受的高响应延迟，从而威胁过程控制稳定性。因此，其系统无法及时打补丁。这通常导致软件版本过时，且几乎没有恶意软件防护。

# 数据库加固

大多数企业组织最有价值的资产是其信息（数据）。这可能包括从员工信息到客户财务或健康信息等不同类型的数据。因此，信息的分类范围可以从机密、内部到公开。这通常涉及包含机密客户数据的`数据库`以及高度安全的设备、结构、策略和政策。

通常，`数据库`代表大多数组织最有价值的资产，当然也是攻击者极具吸引力的目标。回顾 **第 3 章“安全 ICS 架构”**，这些设备中的资源访问必须经过授权和认证。还应在这些设备上采用数据存储加密。还记得应用级加密是首选，但在应用级加密选项不可用时，应采用文件系统加密。

`数据库`通常位于组织网络内的服务器上。在 OT 网络的情况下，最著名的`数据库`是存储在数据历史服务器上的那些。与企业网络相关的服务器一样，关于`数据库`安全最重要的问题是`数据库`应位于网络中的何处。

正如您在前几章中所学，保护数据历史服务器最常用的方法是将其置于安全的网络结构中，例如 IT 网络和 OT 网络之间的 DMZ，如 **图 4.16** 所示。本章后面详细描述的通用服务器加固工具和技术也应应用于数据历史服务器。

## SQL 注入

也许最常见且最可预防的软件漏洞利用称为 `SQL 注入`。如 **图 4.17** 所示，黑客可能会尝试将 SQL 命令注入面向公众的表单（如登录表单），希望从而获得对底层`数据库`中存储数据的访问权限。

现代 Web 的强大功能很大程度上与在线`数据库`的使用有关，许多 Web 设计师使用 SQL（或类 SQL）`数据库`引擎来驱动它们。网站通常是功能强大的 Web 应用程序，可能存储大量信息。使用 SQL，您可以轻松地将查询和命令链接在一起，通常只需添加一个分号（`;`）然后加上一个 SQL 命令即可。

想象一个可能根据邮政编码查找资源的 Web 表单。它将使用如下单个查询：

```
SELECT * FROM Locations WHERE Zip='$zipcode'; 
```

其中 `$zipcode` 实际上来自用户提供的输入字段。如果黑客输入 `99336; DROP TABLE Locations` 而不仅仅是 `99336`，则`数据库`可能会链接这些命令并完全删除（drop）`Locations` 表。

![图 4.17 SQL 注入](img/c04f017.png)

**图 4.17** SQL 注入

黑客判断应用程序是否容易受到 `SQL 注入` 的常见方法是在登录表单上寻找单引号漏洞。认证查询可能如下所示：

```
SELECT ID FROM Users WHERE Username = '$username' 
AND Password = '$password'; 
```

如果黑客知道或能猜到您有一个名为 `Steve` 的用户，他可以尝试输入以下密码的简单技巧：

```
something' OR 'a'='a 
```

请注意，没有开始或结束的单引号，因为应用程序查询将提供它们。现在可能执行的查询如下所示：

```
SELECT ID FROM Users WHERE Username = 'Steve' 
AND Password = 'something OR 'a'='a';
```

即使密码不是 `"something"`，`'a'` 将永远等于 `'a'`，并且通过使用逻辑 OR，只需其中一个比较匹配即为真。黑客甚至可能不需要通过在用户名字段尝试相同技巧来猜测用户名。

```
SELECT ID FROM Users where Username = 'Steve' OR 'x'='x' 
AND Password = 'something OR 'a'='a';
```

在这里，黑客猜测了用户名和密码，但这些都不重要，因为 `'x'='x'` 和 `'a'='a'` 永远为真。此外，OR 子句确保每个都匹配，黑客将获得访问权限。您可能已经想到我们只需不允许输入单引号。对于用户名和密码字段，该选项可能行得通。但是，如果您请求数字数据，如下所示：

```
SELECT ID FROM Users where UserID=$inputValue;
```

数字字段不需要引用，通过简单输入以下信息，查询应该会匹配，因为 5 确实等于 5，即使`数据库`中没有等于 8686 的 UserID。

```
8686 OR 5=5
```

好消息是，这种情况很容易预防。Web 应用程序程序员只需在将每个输入字段包含在查询之前对其进行过滤或清理。这可以通过多种方式完成，但请考虑以下方法：

*   仅允许从白名单输入字符。显然，单引号不在该白名单上。
*   转义输入字段数据。
*   解析输入字段数据并禁止 `OR` 和 `||`（当然还有 `DROP`）。
*   始终给数字输入字段加引号。

这些方法会产生一定影响，对于许多表单可能已经足够。然而，似乎总有一些注入字符串可以绕过输入验证。转义有问题，并且可能会导致某些字段出现问题（考虑姓名字段，用户可能会输入撇号作为其名字的一部分）。如果黑客输入反斜杠（`\\`）字符来转义其输入，或使用 Unicode 或其他编码，他们可能最终会破坏您的清理程序。

防止 `SQL 注入` 的最佳方法是使用 `SQL 参数`。现代 SQL 系统支持参数化查询，其中参数严格作为数据进行求值，不允许任何命令执行。示例如下：

```
SELECT ID From Users where Username='@user' AND Password='@pass';
```

在代码的某处，服务器将拥有处理这些参数的存储过程，并强制执行严格的数据类型和验证，以确保仅执行作者的代码。程序员在编写查询时仍需小心，并理解表和列不能作为参数。然而，在使用 SQL 系统时，这被认为是最佳实践。

# 反恶意软件

## 连接性增强与恶意软件威胁

通过网络和互联网的连接性增强，使得个人电脑容易受到各种类型的 `malware`（恶意软件）和 `grayware`（灰色软件）的攻击。`Malware` 是指描述那些被设计为具有恶意性质的程序的术语。术语 `grayware` 描述的是具有未披露行为或不良行为的程序。

通常会安装多种不同的防御产品，以保护端点及其数据免受未经授权的访问和恶意干扰。最广泛用于这些目的的产品包括：

*   杀毒程序
*   反间谍软件程序

### 杀毒软件

在大多数情况下，每台计算设备都应具备某种防范计算机病毒的手段。最常见的病毒防护手段是安装病毒扫描（`antivirus`）程序，在磁盘和文件被计算机使用前对其进行检查。多家公司提供第三方病毒防护软件，可配置为以各种方式运行。

如果计算机是非联网的独立设备，让杀毒软件在每次系统启动时运行可能是无益的。让程序检查连接到系统的任何可移动介质会更加切合实际，因为这是计算机唯一可能的非网络入口。

所有连接互联网的计算机，在连接互联网之前都应受到杀毒解决方案的保护。在这些情况下，将软件设置为每次启动时运行更为理想。此外，大多数杀毒软件都包含实用程序，用于检查通过网络或互联网连接下载到计算机的电子邮件和文件。

安装杀毒应用程序后，可将其配置为提供不同级别的病毒防护。您需要配置希望病毒软件在何时以及在何种情况下运行。

对于 OT 控制设备，不存在杀毒补救措施。由于这些设备具有实时操作要求，运行这些应用程序的开销使其无法被使用。病毒防护必须通过其他选项提供。

### 反间谍软件

基本上有两类 `antispyware`（反间谍软件）产品可用——一种是在间谍软件安装后查找并将其移除，另一种是在间谍软件试图自行安装时将其拦截。当这两种方法与关于如何避免间谍软件的用户知识相结合时，都更有机会使计算机免受间谍软件侵害。

`detect-and-remove method`（检测并移除法）是编写起来简单得多的反间谍软件产品类型。因此，有多款商业可用产品采用此方法。与杀毒软件包类似，此类反间谍软件产品依赖现有定义的数据库来识别间谍软件威胁。这些数据库必须频繁更新，以识别已发现的新版本间谍软件。

实时预防型反间谍软件产品不依赖历史数据来识别间谍软件。相反，它们监控特定的配置参数，并在发生可疑安装活动时通知用户。用户随后可以选择允许或阻止安装尝试。一些反间谍软件产品结合了这两种处理间谍软件的方法。

除了安装反间谍软件应用程序外，用户还可以通过多种其他方式对抗间谍软件：

*   安装安全的 Web 浏览器。
*   使用最新的安全补丁保持浏览器最新，或下载提供最佳安全功能的最新浏览器版本。
*   与使用防火墙和代理来阻止已知分发间谍软件的网站的 ISP 合作。
*   仅从信誉良好的网站下载软件，以防止随其他程序附带的间谍软件。

#### 反恶意软件实施

在几乎所有环境中，组织策略都会要求所有服务器安装实时扫描杀毒应用程序，以及实时反间谍软件程序。特别是，如果服务器是文件服务器，或拥有具有远程访问能力的非管理用户，则需要这些应用程序。

如前所述，任何运行 HTTP/FTP 协议且具有互联网访问权限的计算设备都应安装反恶意软件应用程序。然而，对此要求有两个显著的例外：SQL 服务器和专用邮件服务器。

对于网络上的其他端点，所有此类机器都应安装组织标准的杀毒和反间谍软件程序，并按计划定期运行。所有用户控制的计算设备上，杀毒和恶意软件扫描应至少每周运行一次。除网络或域管理员外，任何人不得被允许停止恶意软件定义更新或扫描。

然而，大多数 OT 网络由多个 `soft targets`（软目标）组成，这些是传感器和控制设备，因极少或没有内置安全功能且极少有添加安全功能的选项而易受干扰。这些组件通常几乎没有内置安全能力，许多可能不具备足够的资源（内存和处理能力）来支持额外功能，例如第三方安全插件。如果它们被直接或虚拟访问，很容易被操纵。

这使得杀毒软件和其他反恶意软件程序不适合用于 OT 计算和控制设备。这些类型的扫描应用程序在运行时是性能占用大户。如前所述，由于 OT 控制器的实时计算要求，这些类型的安全应用程序的存在可能会引入不可接受且可能对设备和人员造成危险的通信和计算延迟。

与其将杀毒软件和其他反恶意软件产品应用于 OT 网络，不如在到达网络 OT 侧的这些设备之前，采用纵深防御策略（防火墙和 DMZ）。

#### 更新反恶意软件

反恶意软件应用程序及其定义文件必须保持最新，以应对每日涌现的大量新恶意软件。一些组织要求杀毒定义至少每天更新一次。与服务器和应用软件产品不同，杀毒软件和其他反恶意软件产品更新安装前不应需要沙箱测试。

## 监控

组织的全局反恶意软件防护系统必须由网络管理员持续 `monitored`（监控），以检测可能表明可疑或恶意活动的事件。发生重大事件时，系统应配置为记录事件并通知管理员（或管理员们）。

事件被报告时，管理员应查阅杀毒或反恶意软件应用程序的日志文件，了解事件的性质和参数。然而，管理员应定期例行审查这些日志文件，以发现即将发生问题的迹象。除了这些日志包含的标准操作数据外，管理员还可以利用日志执行以下操作：

*   识别遇到异常高数量病毒的端点（和用户）。这可能表明该端点的用户是高风险操作者，可能需要额外培训。
*   将网络端点与特定用户关联。
*   识别与拥有高风险黑客工具的用户相关的内部威胁。虽然此类软件在某些环境下可能有合法用途，但识别此类用户的能力使识别潜在内部威胁变得更容易。
*   识别与拥有文件和文件夹名称被识别为不同类型隐藏监控工具（如键盘记录器）的软件的用户相关的内部威胁。
*   跟踪未能获取更新的端点。

## 跟踪端点及其操作系统和引擎版本

在 IT 网络中实施*端点检测和响应*（EDR）应用程序变得越来越普遍。EDR 会在网络的所有端点上部署端点数据收集代理，以对其进行监控并收集其运行数据。这些数据被汇总到一个集中的*安全运营中心*（SOC），在那里进行实时分析。

分析通常会检查每个端点上发生的活动量、与其的连接以及通过它传输的数据。这使得 EDR 能够*诊断*威胁，并根据威胁的性质及其配置参数自动触发响应。

当检测到威胁时，EDR 会采取行动*遏制*攻击。一旦采取了遏制行动并将威胁*沙箱隔离*后，EDR 随后会调查威胁的性质并采取行动*将其消除*。

## 反恶意软件：净化

大多数恶意软件以嵌入在标准文件格式（如 DOC、XLS、PDF、PPT 等）中的活动内容形式分发。攻击者只需将恶意代码（宏、脚本、Web 链接或二进制对象）隐藏在内容中，并通过电子邮件、Web 链接或可移动媒体将其传递给目标。恶意软件载荷通常设计为躲避防病毒和其他反恶意软件扫描。

您可能还记得，著名的*震网攻击*^(\*)使用了这些相同的要素，严重破坏了伊朗推进其核能力的努力。最近，一个被称为*“蜻蜓行动”*的类似行动针对 OT 网络发起。在此次攻击中，组织的网站被攻陷，来自受信任供应商的文件被感染。当管理员最终用户将这些文件作为受信任的软件执行时，该漏洞利用绕过了所有防火墙、白名单和防病毒安全控制。

反恶意软件厂商开发了新的文件*净化工具*，用于搜索附加在电子邮件中或通过 Web 链接、拇指驱动器和其他可移动媒体引入的文件中的此类对象。当在本不应包含这些对象的文件中发现它们时，工具会*净化*（剥离）文件整体内容中的可利用对象，并将文件的干净版本交付给用户。

净化与传统反恶意软件产品使用的检测/隔离/删除方法不同，后者通过将文件与病毒/恶意软件定义数据库进行比较，以确定标记或放行哪些文件给用户。在大多数情况下，净化与传统反恶意软件工作相结合，以交付真正受信任的净化文件，如 **图 4.18** 所示。

在这个三部分的过程中，文件首先通过传统的防病毒/反恶意软件解决方案进行处理，以消除那些明显受感染的文件。通过第一次检查的文件被引入文件净化器，其中会应用专门为指定文件类型设计的算法，以定位隐藏在文件结构中的任何恶意对象。如果检测到恶意代码，它会被从文件中剥离，而不会破坏其内容的完整性。最后，净化后的文件被交付给最终用户。

为了在不影响可用性的情况下保护 OT 网络，净化器通常以与传统 DMZ 相同的方式部署在企业网络和 OT 网络之间，如 **图 4.19** 所述。净化功能可以由 DMZ 中工作的服务器提供，或以 DMZ 内（或代替 DMZ）的网络设备形式提供。

# 嵌入式设备安全

*嵌入式设备*被定义为在更大系统中提供指定功能的计算设备。在 ICS 环境中，这包括控制器、`PLC`、`RTU` 和 `IED` 等设备，您在前面的章节中已了解过这些设备。然而，根据所讨论的 OT 网络的确切类型，可能还有其他类型的嵌入式设备需要考虑，例如分析仪、仪表和聚合器（汇聚器）。
