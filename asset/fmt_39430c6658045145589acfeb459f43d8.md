
任何建议都应该是现实的。它们需要考虑业务文化以及这些建议被接受的实际可能性。

### 风险接受

某些组织愿意比其他组织接受更多风险，这既不是错也不对；接受更多风险只是业务运营的一种。对于某些业务来说，承担风险表明了它们的创新能力。在创建风险评估时，了解业务文化非常重要。

接受更多风险有两个侧面：

1. 风险越大，回报越高。
2. 更大的风险可能导致更大的损失。

例如，现今许多公司曾出现过低于 1 美元的股票。任何购买价值 10,000 美元股票的人在今天都会成为百万富翁。然而，很少有人真的购买了价值 10,000 美元的股票。原因是，当股价处于低位时，没有人知道公司是否能够生存。一些人承担了风险并获得了丰厚的回报。然而，其他人在其他公司承担了类似的风险，而这些公司后来破产了。他们的风险投资事实证明是巨大的损失。

记住高层管理人员负责公司的重大决策是重要的。他们负责识别哪些风险需要减轻、共享、转移、避免或接受。向高层经理提出的建议应该基于并与其预期接受的剩余风险保持一致。

### 注意

**剩余风险**是在管理层决定实施控制后仍然存在的任何风险。高层管理负责做出这些决策。此外，高层管理还对由于剩余风险导致的任何损失负责。

无论如何，提交所有数据的责任仍然存在。如果某些建议看起来显然不会被接受，可以将它们包含在报告中，但不要放在实际建议列表中。

## 风险评估的最佳实践

风险评估在不同组织中的执行方式可能不同。对网络服务器的风险评估与评估 `HIPAA` 数据的评估可能会有很大不同。然而，可以包含几项内容以帮助确保成功。

以下列表列出了风险评估方法的几项最佳实践：

- **从明确的目标和定义的范围开始**——风险评估应该包含一个范围声明。范围声明有助于保持评估在正轨上，并防止范围蔓延。
- **获得高层管理的支持**——高层管理需要对风险评估做出承诺。没有支持，风险评估就会失去价值。当风险评估团队意识到风险评估没有受到重视时，他们投入的时间和精力就会随之减少。没有高层经理支持的评估从一开始就几乎是注定要失败的。
- **建立一支强大的风险评估团队**——风险评估的价值基于风险评估团队的能力和专业知识。团队成员应该具备该系统的专业知识。例如，在进行定性分析时，如果从非专家人员那里收集数据，那么他们的意见就不会像从专家那里收集的数据那样。团队成员还应该理解用于风险评估的方法论。
- **定期重复风险评估**——威胁、风险和漏洞在不断演变；因此，应该定期重复风险评估。某些联邦机构要求至少每三年重复一次风险评估。许多组织制定风险评估政策，该政策确定了组织预期定期执行的操作，并为任何风险评估定义通用目标。
- **定义要使用的方法论**——通过一致地使用相同的方法，人们会变得更加精通。例如，一家公司可以决定定期进行定性风险评估。如果是这样，应该定义所使用的量表。当以相同的方式反复进行评估时，它们更容易完成。
- **提供包含明确建议的报告**——每次风险评估都应以一份报告结束，报告应识别并清晰陈述发现。评估的最终目的是通过建议的控制措施来减轻风险。如果建议不明确，报告将失去大量的价值。

## 总结

风险评估用于识别和量化风险。它们通过识别威胁和漏洞，然后应用评估来对风险进行排序。一旦风险被量化，就可以确定控制和保护措施。

两种主要的风险评估方法是定量和定性。当可用历史数据时，使用定量风险评估：`ALE = SLE × ARO`。定性风险评估则使用专家意见并提供。

## 选择风险评估方法

一旦决定进行风险评估，就需要创建一个大纲来指导具体采取步骤。执行风险评估不是今天决定明天就能完成的。它需要时间和规划。

两种主要的风险评估方法是`定量`和`定性`。本章有助于描绘这两种方法的整体状况。通常，风险评估涉及以下步骤：

* 识别要处理的资产和活动
* 识别和评估相关的威胁
* 识别和评估相关的脆弱性
* 识别和评估相关的控制措施
* 评估威胁、脆弱性和利用
* 评估风险
* 开发缓解风险的建议
* 向管理层展示建议

在进行风险评估之前，需要完成两个初步行动：

* 定义评估
* 查看之前的发现

#### 定义评估

必须明确定义什么。如果需要评估一个系统，则需要描述该系统。系统的示例可以是人力资源部门（`HR`）的人员数据库。如果需要评估一个过程，则需要描述该过程。过程的示例可以是财务部门创建发票。

一个重要的因素是描述当前的系统或过程。风险评估是一个特定时间点的评估，而整体风险管理是一个持续的过程。

在描述系统或过程时，通常关注两个主要领域：

* 运行特性
* 系统使命

定义风险评估范围也很重要，以防止不受控的变化，这可能会导致成本超支和错过日期。

### 注意

**风险评估范围**：根据 `NIST SP 800-30`，“评估范围决定了评估的内容。评估范围影响基于风险决策的信息范围，由请求评估的组织官员和风险管理策略决定。”类似于“范围蔓延”，当项目增加未计划的工作时，风险经理需要定义风险评估范围以避免未计划的数据收集和分析。

##### 运行特性

##### 系统任务

系统任务定义了系统的功能。与系统的运行特性相比，任务很容易定义。任何单一系统的任务定义可以短如一段话，也可以由简单的项目符号列表组成。

例如，一个邮件系统可以有如下任务：邮件服务器为组织提供所有邮件服务，包括以下功能：

* 在内部客户端之间路由邮件
* 接收来自外部邮件服务器的邮件并路由到内部客户端
* 接收来自内部客户端的邮件并路由到外部邮件服务器
* 扫描所有邮件附件并删除恶意软件
* 扫描所有邮件以识别垃圾邮件并剔除确认的垃圾邮件

### 配置与变更管理

配置管理和变更管理是两个重要的风险管理过程，它们对风险评估也有直接影响。有时，这两个过程被放在一起提到，但它们是不同的。

配置管理确保相似系统具有相同或至少相似的配置。它关注系统各个部分的安排。当系统非常相似时，可以使用基线、脚本和自动化等技术更高效地配置它们。共享相同配置的系统更容易进行集体维护和风险评估。

变更管理防止对系统进行未经批准的更改。

## 识别管理结构

管理结构指的是权和责任的分配方式。在定义风险评估范围时，将范围保持在单一实体的所有范围内是有帮助的。与单一实体合作可以更容易实施建议。

小型组织可能有一个单一的信息技术（`IT`）部门，负责所有的 `IT` 系统和流程。由于其员工控制所有 `IT` 系统，他们可以对任何系统实施建议。

然而，较大的组织可能会有多个 `IT` 部门。在这种情况下，不同的经理或管理团队负责不同的 `IT` 系统，每个经理都有不同的职责。例如，一个组织可能设有以下 `IT` 管理部门：

* **网络基础设施**——该部门负责网络中所有的路由器和交换机，并可能包括所有的防火墙。
* **用户与计算机管理**——该部门负责网络和账户的日常管理，并可能包括基础的安全措施。例如，`组策略` 工具可以管理 Microsoft 域中的账户，管理 Microsoft 域的管理员将管理 `组策略`。
* **电子邮件服务器**——某些大型组织拥有 10 台或更多电子邮件服务器来管理邮件，并配有经过训练的人员专门管理这些服务器。这些人员确保电子邮件的递送，并管理垃圾邮件过滤和恶意附件。
* **Web 服务器**——一个组织可以在一个或多个 Web 池中配置几十个 Web 服务器。一个 Web 池可以产生大量的收入，并有专门的人员进行管理。
* **数据库服务器**——许多组织在数据库中存储了大量数据。大型数据库存储在专用服务器上。管理这些服务器所需的知识是专业性的，因此某些组织设有专门的数据库管理员来管理它们。
* **配置与变更管理**——该部门监督所有服务器或所有系统的配置设置和更改。团队成员可能负责构建新服务器，并协调和记录所有的变更请求。

### 注意

`Group Policy` 是一种自动化管理工具。策略可以设置一次并适用于域内的所有用户和计算机。例如，可以设置一种适用于所有用户的密码策略，以确保用户使用强密码并定期更换。

小型组织可能同时对许多系统进行风险评估。然而，较大的组织可能会将风险评估分开。例如，一个大型组织托管了电子商务网站。网站的元素包括 Web 服务器、数据库服务器和防火墙。然而，组织内部的各个部门负责管理这些不同的元素。一个部门管理 Web 服务器；另一个部门管理数据库服务器；第三个部门管理网络安全（包括防火墙）。对所有三个元素进行单次风险评估可能是具有挑战性的，在实施建议时尤为如此。不同部门的经理可能会有竞争性的目标、时间表和优先事项。

然而，如果组织一次评估一个部门，其结果将更容易实施。例如，可以进行三次独立的风险评估，分别针对 Web 服务器、数据库服务器和防火墙进行评估。每项评估都将针对系统所有者提供具体的建议。

## 在风险评估边界内识别资产和活动

`资产估值` 是确定资产公平市场价值的过程，这是风险管理的首要任务之一。资产价值可以根据资产的重置价值、资产为组织提供的价值或恢复资产的成本来确定。价值也可以结合这两种价值来确定。

在确定资产价值后，就可以对其重要性进行排序。如果某个资产价值 1,000 美元，它可能需要一级保护。如果另一项资产价值 100 万美元，那么该资产可能需要另一个级别的保护。

### 注意

本节介绍了与风险评估相关的资产和活动。

只有处于风险评估边界内的资产才应该被评估。当评估风险评估范围之外的资产时就会发生范围蔓延，这一过程会导致精力和资源的浪费。

资产的价值可以从不同的角度来看：

* **重置价值**——重置价值是购买新资产来替换现有资产的成本。例如，如果笔记本电脑故障或被盗，购买一台具有相似硬件和软件的新笔记本电脑的价格可能是 1,500 美元。
* **恢复价值**——恢复价值是在故障后使资产恢复运行的成本。例如，如果服务器的硬盘故障，不会更换整台服务器，而是只会更换硬盘，并采取步骤恢复系统，这可能需要重新安装操作系统并从备份中恢复数据。执行维修所需也需要考虑。例如，如果维修需要两个小时，那么系统将中断两个小时。例如，如果该系统是每小时产生 10,000 美元收入的 Web 服务器，那么 20,000 美元将包含在恢复价值中。

确定任何资产的价值时需要考虑几个元素。这些包括：

### 系统访问与可用性

* 系统功能
* 硬件和软件资产
* 人员资产
* 数据和信息资产
* 设施和用品

#### 系统访问与可用性

访问和可用性是指资产需要何时以及如何保持可用。某些资产需要每天 24 小时每周 7 天可用。其他资产仅需周一至周五的办公时间内可用。资产需要的可用性越高，与停机相关的风险就越大。

例如，Web 服务器用于在互联网上销售产品。客户可以随时访问网站，但如果客户在尝试访问时网站未运行，公司就会失去一笔订单。此外，还可能失去一个客户。

考虑到这一点，风险评估需要考虑与该网站在任何时间宕机相关的风险，这包括如何在不关闭网站的情况下对系统进行维护。维护包括对数据进行备份并保持系统更新。

Web 服务器可能是 Web 池中许多服务器之一，也可能是故障转移集群中几个 Web 服务器之一。这两种配置都允许单台服务器宕机而网站继续运行，但如果运行单台服务器，停机可能是灾难性的。

另一方面，系统可能有一个文件服务器，仅供员工在工作时间（周一至周五，上午 8 点至下午 5 点）内部使用。这种时间表为员工不在工作时进行备份或其他维护提供了充足的时间。

#### 系统功能

在确定资产价值时，应考虑提供服务的系统的功能。特别重要的是这些功能是手动执行的还是通过自动化执行的。

例如，正在评估组织电子邮件的价值。该电子邮件系统可能有多个元素，包括垃圾邮件过滤器。研究报告，通过互联网发送的邮件中高达 90% 是垃圾邮件。垃圾过滤器将消除部分垃圾邮件，且目标是不过滤掉任何有效邮件。
