
这可能一次性思考的内容有点多，但当第一次组建团队解决机器学习问题成为必要时，所有这些都将变得清晰明了。我对人才来源的回答是：随着时间的推移，将优秀的专业人士融合在一起，创建高效能团队。这可能涉及招聘关键技能人员来补充团队，或者如果有足够的准备时间，则投资培训团队。准备时间越短，快速引入外部人才的需求就越大。

## 2. 如何让人才协同工作？

团队关乎不同成员如何协同工作。我倾向于将机器学习项目视为拥有两个关键支柱。首先，你需要弄清楚谁对产品、数据以及数据如何与客户旅程相关联拥有深度知识。这可能显而易见，也可能很困难。有时这些对数据拥有最大机构知识的人是发挥重要作用的关键主题专家，但他们可能隐藏在组织深处的分析师岗位上，或者可能已经转岗到其他角色。

## 第二，让具备深厚领域知识的人与你找到的机器学习专家共事

将这两者配对将成为你正在做的事情中最关键的枢纽。大多数组织**没有**从一开始就为机器学习而架构设计的数据结构。弄清楚正确的切入点意味着确定要标记什么数据，以及什么与旅程的起点相关。这就是为什么具备全栈机器学习技能的人如此重要的原因之一。

### 这究竟意味着什么？全栈机器学习技能

我可以走进你的组织搭建 `TensorFlow`，甚至让团队今天就开始共享一些 `Jupyter` 笔记本。拥有正确的数据源、正确的机器学习硬件，以及能够访问正确的生产端基础设施，以便在不压垮或破坏系统的情况下迅速移动数据，这些正是全栈技能必不可少的地方。

也许真正敏捷的团队应该是自我组织的，但这在初次尝试时很难实现。寻找共同或共享的目标听起来比实际操作容易得多。让人们围绕这个共同或共享的目标自我组织，可能需要一些基本规则或火花。

有时高绩效团队会直面挑战，努力消除可能面临的任何障碍或阻碍。大多数团队不具备那种程度的奉献精神、坚持或韧性。通常，项目需求或普遍的业务问题会将一群人聚集在一起采取某种行动。管理这类情况总是很有挑战性，通常包括试图将具有不同技能的人聚集在一起。

这涵盖了你将遇到的两类团队：已经组建好的高绩效团队，以及基于特定业务问题聚在一起的团队。除了这两种常见情况外，你可能面临的另一种人才状况很可能是“有解决方案找问题”。现在这种情况比以往任何时候都多见，因为市场上充斥着开源项目，让人们能够直接跳进来使用复杂工具。这种模式的下一步是想用这些新奇的工具做点什么。为此，你可能会发现一个解决方案正等着去解决某个问题。然而，这可能不是正确的解决方案，甚至可能与应采取的行动方案完全背道而驰。

对我来说，让人才协同工作，核心在于业务问题以及团队试图达成的目标。如果最终目标模糊不清，或者被务实地挪用为除解决当前业务问题以外的其他东西，那么很难围绕该目标团结大家。

我们最好直接深入，花一点时间了解必要的工具，以便让机器学习专家能够高效地与团队协作。你现在大概能看出，我倾向于使用像 `TensorFlow` 这样健壮的工具深入探索并开始大规模进行机器学习。你也可以从日志文件入手，使用像 `Splunk` 机器学习工具包这样的现成产品深入挖掘。这是一个让团队开始使用通用平台开展工作的切入点示例。

## 3. 这些工作流是什么，为什么它们很重要？

我们讨论了人才来源以及如何开始思考让团队协同工作。下一个问题应该与机器学习可用的现有工作流有关。我通常将工作流分为四个不同类别：数据流、存储数据、实时交易和正在运行的批量/大批量作业。每一种工作流都需要不同类型的机器学习方法。你可能会觉得这是牵强附会，但并非如此。将机器学习应用于流式数据所需的工作量，比处理静态数据难得多。仅仅因为你能在数据流上启动机器学习，并不意味着模型会准确或高效。

真正可靠、经过训练的生产模型，如果又快又准，就很有价值。说真的，那才是你想要达到的境地，但这不会偶然发生。在流式数据场景中，你必须拥有一种训练和处理模型的方法，以及一种在不中断数据流的情况下加载运行模型的方法。

处理存储数据比较容易，但有时当你不处理数据流时，会忘记速度的重要性。你可以允许机器学习模型花费更多时间。例如，汽车视觉处理所用的模型比处理美国职业棒球大联盟历史统计数据的模型对速度要求高得多。这是团队可以围绕他们想要评估的相对静态数据集成长和发展的地方。

实时交易是该过程中较有趣的部分之一。交易涉及的工作流通常非常清晰。数据流更流动，不如基于交易的视图那样是纯粹的模式。视频流总是比网站上的金融交易变化更大，但两者都有真实的机器学习机会。

我们真正开始进行一些端到端的思考，关于如何在你的组织内大规模将机器学习模型投入运营。你已经开始思考你的团队、团队如何协作，以及一些可作为数据源的工作流来开展工作。我们今天攻坚的下一步将是看看一些你可以用机器学习解决的具体问题。

我们需要的模式无处不在。现在是拥抱这种复杂性的时候了，数字世界的互联本质创造了一种场景，即工作流无处不在。工作流存在于各种业务流程中。有时它们是出于良好意图建立的，有时只是因需求而自然形成。在工作流上强行加装某种机器学习听起来很有趣。这是尝试用先进流程做点事情的一种方式。它可能是一个推荐系统、一个异常检测器，甚至是一个打破模式的对抗性设置。事情在工作流中以可定义和可重复的方式发生。这几乎就是跳进去使用某种机器学习算法的完美配方。是的，这可能读起来像“有解决方案找问题”，这很有可能是事实，也可能是一个等待被发现的机会。

将潜在工作流类型细分为几类，包括内容流、静态内容挖掘、基于交易的工作流和批量/大批量流程。这些类别中的每一个在机器学习实现方面都包含不同的工作流挑战。显然，静态内容挖掘是许多团队的起点。它不是一个移动的目标，而且时间可能站在你这边，让你深入研究弄清楚事情究竟如何运作。你有充足的训练时间，模型可以被应用和调整。或许与之相反的类别是尝试在内容流上应用机器学习。你的模型必须准备就绪，流程必须迅速推进。流中发生的任何事情都必须足够流畅，以允许吞吐量持续流动而不产生积压或延迟。同类论点也适用于基于交易的工作流，但在交易层面上，你会获得更多缓冲空间来允许模型完成工作。

# 机器学习策略与向量深度解析

## 机器学习在实际应用中的场景

如果您的团队开始深入探索使用机器学习模型来解决问题，您将很快开始考虑推荐、检测、排序和辅助流程。您会发现，实际落地的机器学习核心在于**数据**和**用例**。您是否拥有可靠、可信的数据源？这些数据是否支持您的目标？最近，越来越多的辅助型机器学习算法被构建出来，旨在加速工作流并强化职场流程。

### 推荐系统

推荐是机器学习算法擅长解决的问题之一。在涉及采购的工作流中，推荐功能非常实用且极具威力。将推荐精准化、洞察化、实用化，能使推荐引擎取得巨大成功。与其他事物一样，推荐系统必须持续调优和维护，否则将面临收益递减。如果反复向同一用户推荐相同内容，若不加干预，用户最终会忽略它。

### 检测系统

检测系统种类繁多。部分与汽车领域的计算机视觉相关，大量系统围绕图像处理构建。这些是目前最有趣的一些实际应用场景。

### 排序算法

构建优秀的排序机器学习算法总能创造价值。排序算法最佳用例之一当属减少垃圾邮件。这类努力近期效果甚至好得“过头”了。

### 辅助流程与自动化

目前最令人兴奋的新兴用例之一与辅助流程及其他自动化形式相关。目前可构建和利用的工具令人惊叹，它们能加速事务处理，将可定义、可重复的流程自动化，使其无需人工干预即可执行。

## 5. 什么是机器学习策略？

我们已探讨了人才、团队、工作流和问题。现在该深入研究您的机器学习策略了。我特意将此话题延后，直到我们建立起基础认知。您的机器学习策略必须包含**目的性**、**可复制性**和**可复用性**。机器学习通常作为可定义、可重复流程的一部分应用于生产系统，这正是保证质量与速度的关键。您需要设置护栏，将模型行为限定在其能力范围内。除此之外，您必须明确在组织中使用机器学习的目的。

- 您可能纯粹为提升员工参与度而引入机器学习，因为团队渴望做些酷的事情。

- 您可能身处团队强烈意愿驱动的环境中，您可以支持其实现。团队或许能找到创新方式，将这种热情转化为符合组织总体指导目标的成果。部分创新可能驱动未来战略，**但最好让战略主导组织内创新的基础建设**。

**根据潜在 ROI 统一应用您的理念**。完成后，您将确信自己因正确理由选择了正确路径。随后，您可以开始考虑在尽可能多的应用中复制结果和流程。**迁移学习**在此发挥关键作用。一旦弄清如何以质量和速度应用流程，将其应用到一系列事物中将更快实现。这就是团队协作交付成果的力量。

**跳出随机森林的树木视角审视策略，需要透视力**。有时更容易聚焦特定项目，而忽略其如何融入更广泛的战略。拥有自上而下应用的针对性机器学习策略，有助于确保正确的高管赞助和资源聚焦于成果获取。与其运行一堆独立的自我孵化项目，不如建立可定义、可重复的推广流程，以具成本效益的方式在组织内复制相同方法。

扎实的机器学习策略示例：与成本控制或节约计划相关，引入辅助型机器学习产品，让员工以更少错误、更快速度完成工作。执行该策略需要将其运营化，并收集流程运行数据以追踪、衡量并确保积极成果。

## 6. 什么是机器学习向量？

在初步探讨机器学习策略后，我们需深入核心技术领域。之前的所有讨论都在为这一刻铺垫。我们将深入剖析**机器学习向量**。这是我们今天讨论的最技术性部分，初期理解可能有难度，因此我们将由浅入深。大规模使用机器学习意味着您已弄清如何在技术栈中使用模型，并知晓如何、何处应用该模型。

**向量在此发挥核心作用**。假设您有一个数据流，需调用外部产品的 API 验证图像，这是向量的重要组成部分。此时，您的向量是一个外部接入点，允许该 API 跳出您的工作流并应用机器学习模型。此时模型执行、图像识别、数据回传；理想情况下接近实时完成。若需向外部发送巨大图像，且需考虑传输延迟和模型推理时间，您的极速数据流可能急剧放缓。

然而，若您的向量是内部且轻量级的，可在图像存储时甚至数据流发生时在内存中处理，您将更快获得可用信息。

---

让我们尝试换个角度解释。数据以多种方式到达。传输方式和传输目标可构成向量。在该特定用法中，**向量**描述机器学习如何应用于某种传入数据。这可能发生在 API 交换期间、流程内的 API 调用、使用训练模型的内部云、跨越外部云、数据中心内的本地部署，甚至边缘计算实例中。在边缘端，您需确保模型训练充分且以轻量级方式部署，以在不增加计算时间的前提下驱动用例——边缘本应是您最快的用例场景。

弄清应用机器学习算法的正确方式需要规划。了解应用如何工作及部署位置至关重要。了解向量对数据流和可行操作影响巨大，我认为这是设计和部署生产环境机器学习模型的基础。处理流式数据使向量的方向性考量更为关键。

## 7. 什么是 KPI 综合指标体系？

基于时间限制，我们只能花几分钟时间介绍 KPI 综览，以及它对机器学习战略整体执行的重要性。你必须能够以 ROI 和其他关键驱动因素的形式，在组织内展示机器学习的成果，这些因素能体现出对业务的关键性。老实说，你必须把机器学习仪表盘看作是极其易于消费的东西，以至于在 30 秒内就能直观地理解整体状态。这才是好的报告。要做到这一点需要时间和大量的艰苦努力，但一旦在执行中达到这个境界，影响力就会很大。就我个人而言，我的战略包括“以终为始”，当团队在执行时，我会致力于弄清楚如何汇总指标、如何讲好故事。有时，直接参与工作的团队没有时间深入研究并制作仪表盘，因为他们正忙于构建和调优模型。仅将数据整理好并准备就绪，就是你机器学习旅程中的一个重要里程碑。同时还要搭建仪表盘，这会让团队感到不堪重负。

在组织中弄清楚如何使用机器学习的一切，都必须归结为一个战略计划。你需要弄清楚如何将该战略计划的执行可视化，这很可能涉及拥有一份 KPI 综览，以展示交付机器学习解决方案的价值。以这种结果为出发点很重要。它有助于构建正在运营化的整个解决方案的框架。在战略层面，团队运营化的事项必须有助于实现特定的基于预算的成果。这从本质上以一种可衡量的方式，将整个组织的支出与收益联系了起来。

从构想到运营化，机器学习收益必须映射到 KPI。所有这些内容汇总在一份综览中，有助于呈现战略规划对具体行动贡献的全貌。所有这些都以清晰易懂的结果形式被定义。将这些示例汇集在一份综览中，是确保组织清晰了解进展情况的正确方式。理解 KPI 综览的各要素如何协同工作，有助于人们可视化组织正在执行的战略计划。它描绘出一幅非常清晰的战略图景，以及该战略是否被正确运营化。

## 8. 机器学习“推动轮子转动”有哪些例子？

职场中流程无处不在。一些流程集合在一起形成工作流。在这个工作流中，机器学习可以帮助“推动轮子转动”一次。机器学习的这一特定应用可以帮助推动事物向前发展、轻推事物前行，或者在需要时让“列车保持在轨道上”。我见过的机器学习“推动轮子转动”的方式包括推荐、检测、分类和辅助部署。每一种可能的转动都能增加价值，并使机器学习成为持续战略规划的一部分。

在商业世界中，人们每天都在决定在哪里运行机器学习实例。之前，我们讨论过身处云端的持续支出正转向来自 `Azure`、`AWS` 和 `GCP` 的 API。回在第 11 周的 Substack 文章“什么是 ML 规模？ML 使用的地点与时机”中，我引入了一个此处需要引用的概念。该概念包括将机器学习用例类别细分为三个桶：

### 使用 API 服务支持机器学习用例可带来诸多益处

大多数此类 API 过去已支持并将继续支持多种不同的工作。这意味着，尽管模型交付并非针对您的特定用例进行专门定制，但其已通过时间的验证。您可以节省模型训练和持续维护的所有成本。如果您经营的是一家小公司，还能获得在真实工作条件下利用所有其他数据来调整和奠定模型基础的益处。这些 API 服务不会高度专业化，采用这种方式启动机器学习用例时，您基本上是“拿来即用”。成本按单位或在大多数情况下按使用批次计算，具有可预测性。这意味着您必须预测每月将调用 API 的次数，以预估成本并维持您的 ROI 模型。

## 类别 2：“您可以所在之地”，或您可在其中拓展业务版图的生态系统

云端的成本预测计算器优劣不一。当您开始在云端拓展业务版图时，计算和存储资源将开始联合发力，给您的组织带来成本。随着数据量增加和针对这些数据运行的计算资源增多，您的成本模型将发生变化。本段前几句话虽未提及机器学习，但包含了对其的考量。您需要处理、流水线传输、转换、修改数据或用于训练模型的数据总量，都将在您的云版图中引入成本。有人可能因对云端训练数据过于兴奋，而租用大量酷炫硬件以加速进程。这在当时对他们而言可能看似是云端的绝佳用法；但最终可能代价高昂。或许短期爆发式地投入以启动并将机器学习用案和模型部署到生产环境是值得的。在这种情况下，整个训练设置需尽快关闭以控制成本。若保持开启，训练将持续增加成本。您会发现云端可提供一些非常强大的专用硬件用于机器学习工作。其中部分定价比其他部分更合理。

## 类别 3：“自行构建”，如开源和自研工具解决方案

视您的设置而定，此类别可能不产生任何显著的云成本。许多初创公司和其他组织可能在小型物理机或机架上进行训练。当您自行构建时，只需核算硬件成本及任何其他相关成本，如托管位置、备份方式、电力和网络。
