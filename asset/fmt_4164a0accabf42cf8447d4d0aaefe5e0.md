## 前言

**Enrico Franconi**，博士，意大利博尔扎诺自由大学计算机科学教授，KRDB 知识与数据研究中心主任。

我怀着极大的热情和深深的荣誉感，为这本杰出书籍的第三版撰写前言。这是一本关于信息建模和关系数据库的全面而深刻的指南，凸显了其在企业建模和数据管理领域的深远重要性。甚至在新版中，人们也不得不承认其页面中所包含的知识的广度和深度。

本书是理解**对象-角色建模（ORM）**语言及其面向事实的建模方法论不可或缺的资源。ORM 作为数据建模领域的一座灯塔，提供了一种严谨且用户友好的方法。本书以严格的细节关注，细致地剖析了企业的语义复杂性。作者致力于探索和评估各种概念建模符号并与 ORM 进行对比，这使本书脱颖而出，为读者提供了数据建模范式全景图，同时呈现了对概念建模的准确理解以及 ORM 优势的证据。

各章阐明了概念建模的细微差别，强调了建模语言必要的精确性。作为来自基于逻辑的知识表示与推理背景的人，我非常欣赏 ORM 符号的形式化严谨性，在这种符号中，歧义和马虎无处遁形，这与许多其他（广为人知的）概念建模符号形成鲜明对比。此外，本书不仅描述了建模构造的精确含义，还阐释了这些构造在语言中存在的原因。对其用例的细致分析及其设计方法论在本书中具有同等重要的地位。

我发现 ORM 提供了一种强大、精确且易于理解的概念建模方法，以及本书以精确且易懂的方式呈现 ORM，这让我着迷。正如预期的那样，与 ORM 相关的面向事实的建模方法论在书中得到了清晰而详尽的阐述，构成了本书的另一大支柱。它指导读者理解数据语义，并设计能够真实、正确地反映业务现实与需求的数据结构。本书还相当大篇幅地关注概念模型与其在某些数据库结构中的实现之间的关系，在强调正确性和有效性的同时，也不忘现实世界中 SQL 的复杂性。

书中前几版所阐述的面向事实的建模方法论对我许多研究产生了深远影响。确实，正是在初读此书后，我开始致力于基于经典逻辑的知识表示与 ORM 及其面向事实的建模方法论的交叉研究。书中讨论的 ORM 语言的文本版本（FORML）也对我产生了影响。我曾与 Terry Halpin 会面讨论我的研究成果，结果却意识到在此之前我还有太多东西需要学习！Terry 是一位谦逊的科学家，每次讨论后，他似乎总是对的。

Terry Halpin 和 Tony Morgan 毕生致力于开发企业建模概念，这充分证明了这项工作的重要性。更新和扩展的内容，以及嵌入各章的大量练习，增强了本书的价值。本书紧跟最新版本和趋势，确保读者能获取该领域最新的发展成果。涵盖 ORM、ER、UML、SQL 和 OWL 的内容均经过了全面更新，融入了它们的最新迭代版本。本版新增了针对 NoSQL 技术的章节，如键值、面向列和图数据库。还新增了一章涵盖当代流行的数据文件格式，如 XML 和 JSON。所有其他章节都进行了大幅修订，加深了对众多主题的覆盖深度。

最后，我想强调本书对包括数据建模师、数据工程师、数据分析师、企业架构师和程序员在内的多元受众的适用性，突显了其包容性和易用性。全书融入的练习为读者提供了互动和沉浸式的学习体验，促进了对概念建模的深入理解。

## 前言

Herman Balsters，博士，NorthChain 合伙人，荷兰格罗宁根。

我于 2005 年在塞浦路斯举行的 ORM 研讨会上首次接触 ORM，该研讨会是 OTM 联合国际研讨会和会议的一部分。我刚在 OODB 会议上发表了一篇关于数据联邦的论文，出于纯粹的好奇，我短暂地访问了 ORM 研讨会，想多了解一些关于 ORM 语言的情况。当我走进去时，Terry Halpin 正在做演讲。我对演讲期间热烈的讨论感到惊讶，不仅研讨会参与者的热情让我惊讶，他们评论和提问的高质量也让我惊讶。我没有只是短暂停留，而是在塞浦路斯逗留的剩余时间里一直待在 ORM 研讨会，从此成为了 ORM 的忠实拥趸。

在格罗宁根大学担任研究员和副教授期间，我深度参与了统一建模语言（UML）和业务流程模型和标记法（BPMN）等语言的工作，试图捕捉信息建模的本质。我一直在与这些被视为最先进的语言作斗争，因为我就是无法完全掌握用这些语言编写的模型到底意味着什么。我拥有纯数学（特别是数理逻辑）和计算机科学背景，我希望能清楚地了解我试图指定的数据和流程模型的语义和完整性。我也想看到模型与模型实现之间清晰的联系。在这两方面，我对当时主流的建模语言都感到不安。这种缺乏精确性和完整性的感觉不仅存在于研究中，也存在于教学中。没有什么比老师自己都不完全理解的东西更难向学生解释了。

这一切从我走进塞浦路斯那个 ORM 研讨会的那天起就改变了。我花了一段时间才掌握 ORM 的所有细节，但在那之后，我能够真正以完全的理解和极高的精确度编写模型，使模型能够直接与实现挂钩。即使在今天，我仍怀着深深的敬意和满足感使用 ORM。

ORM 是一种所谓的面向事实的数据建模语言。在 ORM 中，你编写关于我们周围世界的事实。这意味着你指定对象及其之间的关系，从而得出关于世界的某些陈述。ORM 以这样一种方式做到这一点：即使是非技术领域的专家也能建模其专业领域内的事实。这得益于 ORM 与描述我们周围世界的自然语言规范有着紧密的相似性。然而，ORM 也能以一种极高细节和（数学）精度来建模事实的方式来做到这一点。ORM 是一种图形化语言，具有直观易懂的符号。ORM 还配备了一个强大的工具（NORMA），允许对 ORM 模型进行图形化编辑和验证检查。ORM 的另一个吸引人的方面是可以将 ORM 模型直接编译为关系数据模型，然后再编译为 SQL。因此，在 ORM 中，你可以直接从建模走向实现。

2008 年，作者 Terry Halpin 和 Tony Morgan 发布了这本精彩书籍的第二版。我自那时起一直在使用它。多年来，我已向数百名学生教授 ORM，并指导硕士和博士生进行涉及 ORM 的研究。本书以其简洁明了的写作风格脱颖而出，涵盖了信息建模几乎所有的主题。此外，大量解释使用 ORM 进行建模的理论与实践的案例，使本书成为任何想要理解信息建模所有细节的人的必读之作。

这本书既技术又哲学。它是技术性的，因为它提供了大量材料，涉及理论、符号、案例和工具，以应对信息建模师面临的几乎所有挑战。作为额外收获，我们还看到了如何将这些模型在技术上实现为关系数据库。但在某种意义上，这本书也是哲学的，因为它将你带入一个充满挑战性问题的领域，这些问题关乎我们对周围世界的表征。ORM 的核心在于使用语言来捕捉那个世界，以及完成这项工作的最佳语言应是什么样子。

作为一名大学教授，我有幸用 ORM 教授学生建模、撰写研究论文，并指导信息建模领域的硕士和博士生。自 2018 年离开学界以来，我一直在工业层面从事信息建模工作，面临一些实际中极具挑战性的建模问题。在这些涉及数据、业务规则和业务流程建模问题的复杂情境中，ORM 提供了解决方案，我确信如果没有 ORM，我是找不到这些解决方案的。

Terry Halpin 是 ORM 领域世界领先的专家，没有比这本书更好的读物来理解 ORM 以及如何应对信息建模。因此，我全力向所有对信息建模感兴趣的人推荐本书的第三版。

## 前言

Gordon C. Everest，博士，美国明尼苏达大学卡尔森管理学院 MIS 与“数据”建模荣誉退休教授。

我很高兴并深感荣幸能再次撰写前言，这次是为本书的第三版。这给了我另一个机会，来说服数据建模领域的人们：有一种更好的方法。我深信，对象角色建模（ORM）是进行数据建模的更好方式。我的目标是充分激发您的兴趣，使您认真学习 ORM。本书是目前可用的最佳资源。

希腊哲学家苏格拉底建议“认识你自己”，以过上有价值的生活。同样，我们可以说“认识你的世界”，即你生活、运作和做决策的现实。因为任何一个人都不可能了解关于其世界的一切，所以我们需要那个世界的一种*表征*，一种能捕捉该世界中事物、关系、活动/过程和规则信息的*模型*。这种表征由两部分组成：结构和格式的定义，称为*模式*，以及与其定义一致的实际存储数据。信息“数据库”的集合成为该世界的重要*替身*。

我们基于构建的替身数据库，在我们的世界中并关于我们的世界做出决策。这是一项令人敬畏的责任，因此要求我们的数据存储具有高度的完整性、质量和可用性。这需要一种能够捕捉丰富语义集的数据建模方案，而 ORM 是当今所有方案中最好的。

“数据建模”一词的使用往往具有误导性。它暗示我们在建模数据，而实际上我们是在建模某个用户关注领域中的事物和关系（关系中的对象和角色）——即*在数据中建模*，使用数据构造，一旦模型填充了数据，最终就会成为一个“数据”模型。

数据建模是信息系统开发的基础——如果数据库设计不“正确”，那么构建的系统就会像纸牌屋一样，在未来不可避免的增强、集成和质量改进压力下崩溃。因此，我们需要一种方案来指导我们的数据建模工作，以产生清晰、准确地代表用户论述领域、并促进人际沟通、共同理解和质量控制验证的数据模型。生活在并了解用户领域的人员必须直接参与建模过程，由理解设计方法论的数据建模专家提供支持。

对于任何认真对待数据建模的人来说，本书都是必读之作，但有个提醒：你必须投入足够的时间和精力才能真正理解 ORM。幸运的是，我有一整个学期的学生作为固定受众——时间足够长，让他们学习和实践 ORM，并确信这是一种更好的方法。有了 ORM，你可以将数据建模技能提升到一个全新的水平。

本书还考察了基于记录的建模方案：UML、基于 Ted Codd 关系模型的 SQL，以及 Peter Chen 的实体关系（ER）图及其众多变体——Oracle 使用的 Barker 表示法、Finkelstein 的信息工程（IE）和 IDEF1X（如 ERwin 中所用），并新增了关于 XML、JSON 和 NoSQL 中数据结构表示的内容。从 ORM 视角审视这些熟悉的建模方法，能提供对其底层本质更丰富的理解。

**基于记录的建模方案**使用*三种*构造：实体、属性和关系。它们最多只能直接表示二元、一对多关系。但将属性聚类到实体记录中，才是我们数据建模中许多问题的根源。规范化是检验我们是否聚类过度的测试，而记录分解是纠正违反范式的补救措施。

**规范化**是数据建模的阿喀琉斯之踵。能完全避免规范化该多好？这个建议本身就足以引起数据建模学习者和从业者的兴趣。好吧，使用 ORM 你就可以做到。问题源于当我们将东西（属性）扔进实体记录或表时，缺乏对关系清晰完整的定义，导致记录内部结构被隐式地定义或假设。ORM 强迫你单独考虑并显式定义你领域中所有相关对象域之间的关系和约束。

**ORM** 仅基于*两种*构造：对象和关系（分别对应句子中作为主语或宾语的名词概念，以及作为谓语的动词概念）。实体和属性（在关系建模方案中）都基于 ORM 中的对象（不要与面向对象技术中的对象混淆）和角色。对象在与其他对象的关系中扮演角色。因此，对象因在与其他对象的关系中扮演的角色，而隐式地拥有属性（描述符或特性）。

在基于记录的建模中，有两种关系：记录间关系（显式定义并使用外键表示），以及记录内属性之间的关系（未显式定义任何关系的特征，这也是我们需要强制执行规范化规则的原因）。在 ORM 中，所有关系都用单一构造以相同方式表示。当 ORM 模型是对被建模世界的有效表征时，函数依赖和多值依赖被显式定义，因此“记录”（在关系表中）的生成可以自动化，并能保证结果符合范式（达到 5NF）。这对数据建模者来说是个好消息。

ORM 并不取代 ER 图或关系数据库设计；相反，它是一个前置阶段。它能赋能、启发并指导我们对 ER/关系数据模型的开发和理解。我们构建记录更多是为了系统效率，而非人类的便利或理解。过早引入记录概念（一组属性域加上一个标识符来代表实体）妨碍了良好的数据建模。ORM 不涉及记录、表或属性。因此，我们不会陷入“表思维”（参见 <https://tdan.com/recognizing-and-treating-tableitis/26060>）的泥沼。使用 ORM，不需要显式的规范化过程。

第三版更加聚焦于数据在信息系统中的核心地位，以及语义的重要性。从用户（集体）知道的比我们在数据模型中所能捕捉的更多这一认识出发，我们必须使用一种能捕捉尽可能广泛语义范围、并以图形化方式表达这种含义的数据建模方案。语义至上，ORM 在图形化描绘语义方面远远超越了任何基于记录的建模方案。

那么，这足以激发您深入了解 ORM 的兴趣了吗？如果您是一位有志于学习 ORM 的学生，并且重视数据建模，我鼓励您花些时间阅读本书。您不会后悔的。您将逐渐领会 ORM 的精髓，并因此成为一名更优秀的数据建模师——不妨问问我的数千名前学生便知。要开发出有效且可维护的信息系统，我们需要优秀的数据模型，而这需要一套优秀的数据建模方案或方法论。ORM 让我们能够在最高概念层面上开发数据库设计，而不受那些非用户领域专家主要关注点的事物的束缚。我衷心希望看到越来越多的数据库设计师使用 ORM。我们构建的系统和我们生活的世界将因此变得更好。加入我的这趟旅程，享受这场探险吧。

## 前言

本书论述信息系统，重点关注信息建模和数据库系统（特别是关系数据库系统，但也涵盖非关系系统）。其主要读者对象是数据建模师、数据库从业者，以及计算机科学或信息管理专业的学生。对于任何希望以一种既便于人类理解又易于在计算机上实现的方式来构建业务领域信息结构的人士，本书也应大有裨益。此外，它还为理解数据库系统的真实面貌提供了一个简单的概念框架，并对 SQL 及数据管理中的其他关键主题进行了详尽的介绍。

本书的很大一部分内容论述*面向事实建模*，这是一种概念建模方法，它通过对象及其所扮演角色的简单事实来审视世界。面向事实的方法起源于欧洲，如今已在全球范围内使用，并衍生出多种流派，包括业务词汇与业务规则语义学（SBVR）。本书所述的面向事实版本是第二代*对象角色建模*（ORM 2），基于自然语言信息分析方法（NIAM）的扩展而构建。

信息建模另外两种流行的表示法是*实体关系*（ER）图和*统一建模语言*（UML）类图。就概念信息分析而言，ORM 方法相较于 ER 和 UML 方法具有若干优势。例如，ORM 模型易于口语化表述并填充实例以便领域专家验证，它们在业务领域变更下更加稳定，且通常能以图形形式捕获更多业务规则。

然而，ER 图和 UML 类图擅长提供紧凑的摘要，且其结构更接近最终实现，因此也颇具价值。鉴于此，本书涵盖了 ER 和 UML 数据建模章节，并指明了如何轻松从 ORM 模型生成 ER 和 UML 数据模型。

为使对数据库感兴趣的普通读者也能轻松阅读，本书语言力求简练，尽量避免形式化的数学处理。在必要时，会在应用前先行探讨来自基础逻辑和集合论的相关概念。本书大部分内容已在面向业界和学界的课程中经过课堂检验，基本 ORM 方法甚至已在高中阶段成功教授。内容采用模块化组织，以便希望省略部分内容的教师能为其课程做出合适的选择。

第一章阐述概念建模研究的动机，并简要对比 ORM、ER 和 UML 方法。还包含信息系统的历史与结构概览。第 2 章 提供结构背景，解释信息系统的概念架构及开发框架。它引入若干关键概念，这些概念在后续章节中将得到更透彻的论述，数据库经验很少或没有的读者应完整阅读本章。

第 3 章 至关重要。在概述概念建模语言标准和 ORM 概念模式设计程序（CSDP）之后，本章涵盖 CSDP 的前三个步骤。第一步（用基本事实口语化表述熟悉的例子）看似平凡，但不应操之过急，因为它为模型奠定了基础。本章其余部分介绍事实类型的基本图形表示法，随后提供关于如何将对象分类为类型以及识别可算术推导信息的指导。

第 4 章 开始着手规定事实类型实例集的约束。最重要的约束类型（唯一性约束）得到详细探讨。随后讨论一些关于事实类型元素性的检查。本章还在概念层面引入连接和投影运算；这些运算的关系版本在后续的关系数据库工作中非常重要。

第 5 章 涵盖强制角色约束，包括一项用于检测可逻辑推导信息的检查。随后深入探讨引用模式。此处探讨的一些更复杂的引用模式可在短期课程中略过。随后通过案例研究应用迄今所涵盖的 CSDP 步骤进行复习，并进而探讨逻辑推导检查。

第 6 章 涵盖值约束、集合比较约束（子集、相等和排除）以及子类型约束。第 6.6 节 探讨子类型的高级方面。尽管在实践中很重要，但该节内容可在初读时略读。

第 7 章 处理 CSDP 的最后一步。探讨较少见的约束（如频率约束和环约束），并对设计进行最终检查。第 7.3–7.5 节 稍显高级，可在短期课程中略过。

第 8 章 论述 ER 方法，从 Chen 的原始表示法入手，继而介绍当前最流行的三种表示法：Barker ER 表示法、信息工程表示法和 IDEF1X 表示法（实为 ER 和关系表示法的混合体）。过程中穿插与 ORM 的对比。

第 9 章 探讨 UML 类图在数据建模中的应用，包含与 ORM 的详细对比。识别出 ORM 中无 UML 图形对应物的业务规则构造，并利用用户定义的约束或注释在 UML 中予以捕获。

第 10 章 探讨信息建模的若干高级方面，如连接约束、历史事实类型、集合类型、开/闭世界语义和高阶类型。关于道义规则和名词化的讨论对于理解面向事实的 SBVR 流派至关重要。本章在技术上是全书最具挑战性的，可在入门课程中略过。

第 11 章 描述如何在关系数据库系统中实现概念模型。前三节对于理解概念模式如何映射到关系模式至关重要。第 11.4 节 探讨高级关系映射方面，可在短期课程中省略。

## 章节概览

### 第 12 章：关系数据库与 SQL 查询基础

第 12 章 提供了关系数据库和 SQL 查询的基础介绍。

- 12.1 节 涵盖关系代数；虽然它不作为实用的查询语言使用，但该代数对于理解 SQL 支持的基本关系操作非常重要。

- 12.2 节 概述了数据的关系模型与某些关系数据库管理系统所采用的数据模型之间的比较。

- 12.3–12.14 节 涵盖 SQL 的主要特性，重点关注国际标准化组织规定的标准 SQL 版本，同时也关注商业 SQL 系统。

### 第 13 章：SQL 进阶

第 13 章 讨论 SQL 的进阶方面（如数据定义、触发器和存储过程），并介绍安全性、元数据和并发控制等实际问题。

### 第 14 章：模式转换与优化

第 14 章 讨论如何以及何时在同一级别（概念或逻辑）将一个模式转换为另一个模式。

- 14.1–14.4 节 探讨概念模式等价的概念，以及重塑概念模式的方法。

- 作为该理论的一个应用，14.5 节 规定了一个通过在映射前执行概念转换来优化数据库设计的过程。

- 14.6 节 简要介绍了规范化理论，包括一些新见解。

- 14.7 节 简要探讨反规范化和底层优化。
