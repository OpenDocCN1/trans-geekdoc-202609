### 虚拟化和虚拟化安全

在本节中，您将了解虚拟化的目的以及虚拟化的安全顾虑。您可以预期在 Security+ 认证考试中会遇到一两道关于此主题的问题。

#### 虚拟化简介

*虚拟化* 的概念是：您不必为运行每个不同的操作系统或服务准备不同的服务器或计算机，而是可以在一台计算机上，在单独的 *虚拟机 (VM)* 中运行每个操作系统或服务。虚拟机由虚拟化软件（如 VMware 的 `ESXi` 或 Microsoft 的 `Hyper-V`）提供，它允许您在隔离的环境中运行每个操作系统，即使所有系统都在同一台物理计算机上运行。图 16-1 显示了一个运行两台虚拟机的系统——一台 VM 运行 Windows Server，另一台运行 Windows 客户端。

![Image](img/f0646-01.jpg)

图 16-1  

在单台主机计算机上运行的 Windows Server 和 Windows 客户端虚拟机

#### 虚拟化的优势

虚拟化技术提供了巨大的优势，主要优势在于您能更好地利用服务器资源，因为传统上服务器一直处于低利用率状态。例如，过去公司会购买一台文件服务器，这给系统带来的负载很小。然后当公司需要一台内部网服务器时，会再购买一台物理服务器用于此目的。在这种情况下，这两台服务器可能只使用了 20% 的 CPU，这意味着公司并没有真正从服务器中获得应有的投资回报。通过虚拟化，您只需购买一台物理服务器，在其上运行两台 VM（一台用于文件服务器，另一台用于内部网服务器），并使用 40% 的 CPU 算力，从而更好地利用公司资产，减少资金浪费。

如果您从事支持工作，需要协助运行不同操作系统 (OS) 的客户，这为您提供了一种方法，可以在一台计算机上安装每个已授权操作系统的副本。如果您需要响应特定操作系统的支持呼叫，您面前就有该操作系统。

测试和培训环境受益于虚拟化，因为您可以在同一台物理机器上安装不同的服务器和客户端，以创建网络环境的模拟。

# 虚拟化的管理优势

管理也能从虚拟化技术中受益。您可以将数十台服务器整合为仅需几台物理服务器，因为您只需在各自的虚拟机中运行每台服务器，从而减少了对物理服务器的需求。我的一位客户将 26 台服务器整合为四到五台物理服务器。结果，由于仅需维护四到五台物理服务器，该公司在硬件升级和维护方面节省了大量资金。

使用虚拟化的环境效益在于功耗更低，因为涉及的物理服务器更少。这也为组织节省了资金。我的一位客户通过虚拟化整合服务器，是因为其功耗已达到上限！

## Hypervisor（管理程序/虚拟机监视器）

系统的虚拟化由 `hypervisor`（管理程序）提供，它也被称为 `virtual machine monitor (VMM)`（虚拟机监视器），是允许您在系统上创建和运行虚拟机的软件组件。当您在系统上安装管理程序时，该系统称为 `host system`（宿主系统），而每个虚拟机称为 `guest system`（客户机系统）。

管理程序有不同类型：

*   **Type I（类型 I）** 此类管理程序是直接运行在硬件之上的软件，随后宿主操作系统作为父虚拟机运行。这使得管理程序能够控制宿主系统和客户机系统对硬件的访问。Microsoft 的 `Hyper-V` 和 VMware 的 `ESXi Server` 是类型 I 管理程序的示例。这些管理程序也被称为 `bare-metal hypervisors`（裸金属管理程序），因为它们直接运行在硬件之上。

*   **Type II（类型 II）** 类型 II 管理程序涉及先在硬件上安装操作系统，然后安装虚拟化软件来创建虚拟机。类型 II 管理程序的示例包括 `VMware Workstation` 和 `Oracle VM VirtualBox`。

以下是使用虚拟化技术和管理虚拟机时应熟悉的其他术语：

*   **Application cells/containers（应用程序单元/容器）** 应用程序容器是一项功能，允许您在一个拥有自己分配资源的隔离环境中运行应用程序。容器就像虚拟机，但它们共享宿主系统的操作系统内核，因此性能优于虚拟机（但提供了虚拟机的隔离特性）。`Docker` 是提供应用程序容器的软件示例，也是 `Windows 10` 的一项功能。

*   **VM sprawl avoidance（虚拟机蔓延防范）** 当组织创建大量虚拟机，却没有建立构建虚拟机的流程时，就会发生虚拟机蔓延。问题在于虚拟机的创建速度超过了网络管理员管理所有虚拟机的能力。到处出现无中心管理的虚拟机意味着无人能确保所有系统在需要时都能打上补丁。请记住，未打补丁的系统可能会在您的网络中造成安全漏洞。利用管理软件部署虚拟机，集中管理虚拟机宿主系统是解决虚拟机蔓延的关键。

*   **VM escape protection（虚拟机逃逸防护）** 虚拟机逃逸允许某人从虚拟机的客户机操作系统访问宿主操作系统。虚拟化厂商会为其产品中存在的任何虚拟机逃逸漏洞创建补丁，因此请务必保持虚拟化软件处于已打补丁状态。

![Image](img/exam.jpg)

> **考试提示：请记住，虚拟机蔓延是指公司内部的虚拟机数量失控。应使用虚拟机管理软件来管理跨宿主系统的虚拟机。还请记住，虚拟机逃逸是指软件可以从虚拟机内部向宿主系统发起调用，这是一个巨大的安全风险！定期为虚拟化平台打补丁以消除虚拟机逃逸漏洞。**

## 虚拟化的安全问题

请记住关于虚拟化技术与安全性相关的以下要点：

*   **Less hardware to secure（需保护的硬件更少）** 虚拟化的一大优势是您将在一台物理服务器上运行多个系统，这意味着您需要保护的硬件更少。请务必遵循宿主系统的物理安全实践，但好处在于它只有一个系统。

*   **Disk space（磁盘空间）** 虚拟化技术允许您创建系统的快照，以便您随时恢复到该快照。这是一项很棒的功能，因为如果您在系统配置中犯了错，可以恢复到快照。但请记住，每个快照都会占用磁盘空间。

*   **Patching（打补丁）** 虽然所有虚拟机都运行在同一物理系统上，但给宿主系统打补丁并不会给虚拟机打补丁。您有责任为每台虚拟机打补丁。

![Image](img/exam.jpg)

> **考试提示：请记住，虚拟化的一个优势是您需要担心物理安全的系统更少。请确保遵循宿主系统的物理安全最佳实践，但不用担心那么多硬件确实很不错！**

如今，大多数组织都使用虚拟化软件在单台服务器上托管多台虚拟机，从而节省硬件采购成本并降低功耗。以下是关于虚拟化的一些安全最佳实践：

*   **Snapshots（快照）** 创建快照可为您提供一个还原点，以便在虚拟机出现问题时恢复。例如，如果您进行了错误的配置更改，或虚拟机遭受恶意软件攻击，您可以恢复到之前的快照以还原虚拟机的状态。

*   **Patch compatibility（补丁兼容性）** 在将补丁应用于虚拟化环境中的生产系统之前，请确保补丁经过测试且兼容。

*   **Host availability/elasticity（宿主可用性/弹性）** 请确保您已实现宿主系统的高可用性，因为如果宿主发生故障，则运行在该宿主上的所有虚拟化服务器都将不可用。虚拟化解决方案的优势之一是 `elasticity`（弹性），即启动新服务器以应对增加的负载需求，同时在负载减少时轻松减少运行中的服务器数量。弹性也是云计算的一项重要特性（下一节将详述云计算）。

*   **Security control testing（安全控制测试）** 请确保在虚拟化环境中测试所有安全控制，以确保它们按预期工作。虚拟化技术还使创建额外的测试系统以验证网络上的安全功能变得容易。

*   **Sandboxing（沙箱）** 您可以创建沙箱（受限环境）来控制虚拟机有权访问的内容。

## 云计算概述

云计算已成为未来的趋势，并具有许多优缺点。在本节中，您将了解云计算并发现其中的一些优缺点。

借助云计算，您可以以极低的前期成本快速轻松地创建应用程序环境。例如，我想要一个电子邮件服务器环境，所以我创建了一个 `Microsoft 365` 订阅账户。几分钟内，我就拥有了一个启动并运行的电子邮件服务器环境（称为 `Exchange Online`），它允许我创建一些邮箱并开始发送电子邮件。这个例子最好的部分是我不必购买服务器硬件或软件，也不需要为高可用性做规划。所有这些都是云服务提供的内容！

### 云术语

在深入探讨不同的云模型（这对考试很重要）之前，让我们先定义一些与云计算相关、您会经常听到的术语：

### 云服务提供商

**云服务提供商 (CSP)**

`cloud service provider (CSP)` 是你订阅以接收云服务的公司。例如，如果你订阅 Azure，那么微软就是云服务提供商。

**托管服务提供商 (MSP)/托管安全服务提供商 (MSSP)**

`托管服务提供商 (MSP)` 是为你管理云环境并处理许多 IT 功能的公司，例如预配用户、管理云服务、执行数据备份和恢复以及监控活动。`托管安全服务提供商 (MSSP)` 是为你的环境处理安全管理的公司。MSSP 用于云环境的安全配置、活动监控、入侵检测系统 (IDS) 和防火墙的管理、补丁管理、响应安全事件以及在组织内执行安全评估。

**本地部署 vs. 异地部署**

`On-premises`（本地部署）是我们用于安装在你办公室局域网 (LAN) 中的某个位置的系统的术语。`Off-premises`（异地部署）是用于描述可能位于备用站点的系统的术语。

**雾计算/边缘计算**

`Fog computing`（雾计算）是指你可以让边缘设备（例如驻留在网络边缘并连接到互联网的路由器和防火墙）在将数据发送到云端之前先处理数据。作为边缘计算的一个例子，设想一个网络环境，其中所有记录的数据都被发送到云端进行处理。这会浪费带宽，因为部分记录的数据并非必需。通过雾计算，处理在更靠近生成数据的用户网络处完成，然后仅将处理后的信息转发到云端进行分析，从而节省带宽。雾计算也称为 `fogging` 或 `edge computing`（边缘计算）。

**瘦客户机**

`thin client`（瘦客户机），也称为 `dumb client`（哑客户机），是一种不执行大量处理、只是连接到远程服务器或云服务以进行所有处理的系统。例如，你可以拥有一台 CPU 性能极低、内存极小且无硬盘的瘦客户机，它连接到 Microsoft 终端服务器，后者反过来将应用程序的屏幕截图发送到瘦客户机。用户可以在瘦客户机上使用鼠标点击应用程序中的选项，随后将这些点击操作发送到服务器，导致屏幕刷新。关键在于你使用的是服务器的处理能力，而不是客户端的。

云计算模型

**软件即服务 (SaaS)**

采用 SaaS，应用程序由云提供商提供给客户，以便客户可以从世界上任何有互联网连接的地方使用该应用程序。如果你使用免费电子邮件服务，如 Gmail 或 [Outlook.com](http://Outlook.com)，这就是 SaaS 的一个例子。更好的例子是 Microsoft 365，订阅后你可以获得 Exchange、SharePoint 和 Microsoft Office 等服务。云提供商管理应用程序基础设施并为你维护它，通过执行应用更新等任务。

**平台即服务 (PaaS)**

采用 PaaS，云提供商向云客户提供开发环境（也称为运行时环境），允许他们在云中创建应用程序。PaaS 的例子包括编程工具、代码库、Web 服务器、Web 服务和数据库环境。其好处是开发人员可以在云中使用这些功能，而无需像传统方式那样将它们作为本地服务器安装。使用 Azure SQL 数据库就是 PaaS 的一个例子。

**基础设施即服务 (IaaS)**

IaaS 是在云中创建虚拟数据中心的一种方式，因为它允许你在云中提供服务器、虚拟机、存储、网络和其他数据中心资源。当客户订阅 IaaS 时，他们仅为所用资源付费。例如，当你使用 Azure 虚拟机时，你就是在使用 IaaS。请注意，使用 IaaS 时，你仅为所用资源付费。

**一切即服务 (XaaS)**

前三种模型是最初的三种云模型，但随着时间的推移情况发生了变化，现在所有事物（或任何事物）都可作为云中的服务获得。例如，公司现在可以为云中的安全服务付费，这可能属于一切即服务类别。

### 云部署模型

实施云服务有多种不同的方式。你可以通过以下方式实施云：

**私有云**

私有云意味着你在内部为公司创建云服务，使公司能够利用弹性和自助功能等云特性。例如，你可以拥有一个私有云，允许 IT 人员根据需要启动虚拟机。私有云的关键在于数据存储在公司内部。

**公有云**

公有云由服务提供商提供，存储在云中的数据将位于该提供商的服务器上。重要的是要强调，许多组织不允许将敏感数据存储在服务器托管在国外的公有云中。值得注意的是，云提供商正在不同国家建立数据中心以解决这一顾虑。

**混合云**

混合云是公有云和私有云的组合。公司可能将非敏感数据存储在公有云中，但将敏感数据保存在私有云中。

**社区云**

这种类型的云汇集计算资源，使 IT 服务可供多个具有共同需求的组织使用，例如实时访问后端数据库。

**云存储**

云技术的一大优势是云存储的使用。用户现在能够轻松地将数据存储在云中，并从台式机、笔记本电脑、平板电脑和手机等多种不同设备访问该数据。云存储可用于存储照片和文档等个人文件，也可用于存储设备的配置设置，以便在需要擦除设备时能轻松恢复配置。
