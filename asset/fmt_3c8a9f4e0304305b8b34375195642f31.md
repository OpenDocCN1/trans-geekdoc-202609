
# 操作上，`try` 语句的运行方式如下

当进入 `try` 语句时，Python 标记当前程序上下文，以便在发生异常时可以返回。`try` 头下嵌套的语句首先运行。接下来发生的事情取决于 `try` 块的语句运行时是否引发异常，以及它们是否与 `try` 正在查找的异常匹配：

*   如果在 `try` 块的语句运行时发生异常，并且该异常与语句命名的某个异常匹配，Python 会跳回到 `try` 并运行第一个匹配引发异常的 `except` 子句下的语句，在将引发的异常对象赋值给子句中 `as` 关键字后命名的变量之后（如果存在）。`except` 块运行后，控制随即继续在整个 `try` 语句之下（除非 `except` 块本身引发另一个异常，在这种情况下，从代码中的这一点重新开始该过程）。
*   如果在 `try` 块的语句运行时发生异常，但该异常与语句命名的异常不匹配，则该异常向上传播到下一个最近进入的、匹配该异常的 `try` 语句；如果找不到这样的匹配 `try` 语句且搜索达到进程的顶层，Python 会终止程序并打印默认错误消息。
*   如果在 `try` 块的语句运行时没有发生异常，Python 运行 `else` 行下的语句（如果存在），然后控制继续在整个 `try` 语句之下。

换句话说，`except` 子句捕获 `try` 块运行时发生的任何匹配异常，而 `else` 子句仅在 `try` 块运行时未发生异常时运行。引发的异常通过我们将在下一节探讨的超类关系与 `except` 子句中命名的异常匹配，空的 `except` 子句（没有异常名）匹配所有（或所有其他）异常。`except` 子句是聚焦的异常处理器——它们仅捕获发生在相关 `try` 块语句内的异常。然而，由于 `try` 块的语句可以调用程序其他地方编写的函数，异常的来源可能在 `try` 语句本身之外。事实上，`try` 块可能调用任意数量的程序代码——包括可能有自己的 `try` 语句的代码，当异常发生时将首先被搜索。也就是说，`try` 语句可以在运行时嵌套。

## Try 语句子句

当你编写 `try` 语句时，各种子句可以出现在 `try` 头之后。如果你列出了所有潜在形式的大纲之一，你应该列出它。我们已经遇到了其中一些：正如你所知，`except` 子句捕获异常，`finally` 子句在退出时运行，`else` 子句在未遇到异常时运行。正式地，可以有任意数量的 `except` 子句，但只有在有一个 `except` 的情况下才能编写 `else`，并且只能有一个 `else` 和一个 `finally`。在 Python 2.4 及之前，`finally` 子句必须单独出现（没有 `else` 或 `except`）；`try/finally` 实际上是一个不同的语句。从 Python 2.5 开始，`finally` 可以出现在与 `except` 和 `else` 相同的语句中（当我们遇到统一的 `try` 语句时，稍后将详述排序规则）。

| 子句形式 | 解释 |
| :--- | :--- |
| `except:` | 捕获所有（或所有其他）异常类型。 |
| `except name:` | 仅捕获特定的异常。 |
| `except name as value:` | 捕获列出的异常并赋值其实例。 |
| `except (name1, name2):` | 捕获列出的任何异常。 |
| `except (name1, name2) as value:` | 捕获列出的任何异常并赋值其实例。 |
| `else:` | 如果 `try` 块中未引发异常则运行。 |
| `finally:` | 退出时始终执行此块。 |

当我们稍后在本章中遇到 `raise` 语句时，我们将更详细地探讨带有额外 `as value` 部分的条目。它们提供对作为异常引发的对象的访问。

### 捕获所有异常

此处的第一和第四个条目是新的：

*   不列出异常名的 `except` 子句（`except:`）捕获 `try` 语句中先前未列出的所有异常。
*   在括号中列出一组异常的 `except` 子句（`except (e1, e2, e3):`）捕获列出的任何异常。

由于 Python 通过从上到下检查 `except` 子句来在给定的 `try` 中查找匹配项，括号形式的效果与在各自的 `except` 子句中列出每个异常相同，但你只需为每个异常编写一次关联的语句体。这是多个 `except` 子句工作的示例，展示了你的处理器可以有多具体：

```
try:
    action()
except NameError:
    ...
except IndexError:
    ...
except KeyError:
    ...
except (AttributeError, TypeError, SyntaxError):
    ...
else:
    ...
```

在该示例中，如果在 `action` 函数调用运行时引发异常，Python 会返回到 `try` 并搜索第一个命名引发异常的 `except`。它从上到下、从左到右检查 `except` 子句，并在第一个匹配项下运行语句。如果没有匹配项，异常将传播到此 `try` 之外。请注意，`else` 仅在动作中未发生异常时运行——当引发没有匹配 `except` 的异常时，它不运行。

### 捕获所有：空的 `except`

如果你确实想要一个通用的“捕获所有”子句，请使用空的 `except`：

```
try:
    action()
except NameError:
    ... # 处理 NameError
except IndexError:
    ... # 处理 IndexError
except:
    ... # 处理所有其他异常
else:
    ... # 处理无异常情况
```

空的 `except` 子句是一种异常包含形式——因为它能发现一切，它允许你的处理器像你想要的那样通用或具体。在某些情况下，这种形式可能比在 `try` 中列出所有可能的异常更有用。例如，以下代码在不列出任何内容的情况下发现一切：

```
try:
    action()
except:
    ... # 捕获所有可能的异常
```

然而，空的 `except` 也引发了一些结构问题。虽然方便，但它们可能会捕获与你的代码无关的意外系统异常，并可能无意中捕获用于其他处理器的异常。例如，即使在 Python 中系统退出调用和 `Ctrl-C` 组合键也会触发异常，通常你希望这些能通过。更糟糕的是，空的 `except` 也可能捕获真正的编程错误，对于这些错误你很可能想看到错误消息。我们将在本书这一部分的最后作为一个陷阱回到这个问题。目前，我只想说，“谨慎使用。”

Python 3.X 更强烈地支持一种替代方案，解决了其中一个问题——捕获名为 `Exception` 的异常几乎具有与空 `except` 相同的效果，但忽略与系统退出相关的异常：

```
try:
    action()
except Exception:
    ... # 捕获所有可能的异常，除了退出
```
