Tinker 是一位全能渗透测试员，在测试和绕过逻辑、物理和社交环境的安全方面拥有经验。他曾在美国、加拿大和欧洲作为红队任务的一部分执行过社会工程学行动。Tinker 曾建立、管理并培训过红队和渗透测试团队。在此之前，Tinker 曾在 SOC（安全运营中心）一线担任入侵检测分析师。在此之前，他曾服务于美国海军陆战队。

## 你是如何开始红队的？

一个名叫 Bubbles 的壮汉在达拉斯黑客协会的会议后找到了我。我曾在当地社区做过关于我在美国海军陆战队如何处理动能攻击和防御的演讲，以及关于我如何捕获中国恶意软件进行分析的技术演讲。他说我具备做红队成员的心态，并想知道我是否想加入他的团队。他承诺会提供培训和指导。我拒绝了。我当时正在做蓝队的工作，并且刚刚开始一个我想做完的项目。六个月后，我完成了那个项目，他又来找我。这次我答应了。

我通过了面试流程并获得了这份工作。他们向我保证，在开始阶段，他们会慢慢让我适应工作。他们会培训我，并让我观察其他团队成员。半年后，他们就会让我开始独立执行任务。

在我刚开始时，我的新公司就被收购了，大多数成员离开了。我、另一个新手和我们的技术负责人就是团队留下的最后成员。我的头衔被改为高级渗透测试员，我被派往洛杉矶入侵两个不同的目标。在经历了几个漫长的白天、不眠之夜晚，利用团队剩余的知识、向当地朋友寻求技术建议并经历了大量的适应后，我成功控制了两个目标网络，并开始了我的红队生涯。

## 获取红队工作的最好方法是什么？

就像获取任何工作一样，你将时间分配在建立所需的技能和建立人脉上。

- 建立技能：学习以下内容：系统、网络、虚拟环境和云、桌面应用、Web 应用、移动应用、脚本、物理环境、社交交流、基础攻击、基础防御。
- 在你实际开始之前，你不会成为其中任何一个领域的专家。只需要感觉一下。这看起来很困难，但现在不要进行深入研究。学习高层知识并看看它们是如何联系的。以后，你会开始深入研究。
- 还要练习以下内容：参加脚本挑战，在廉价的笔记本电脑上构建虚拟实验室并安装系统，通过网络连接它们，在在线或会议上参加夺旗赛（CTF）。

## 专业人脉建立

拥有基础技能组合后，你通过人脉来获得工作。尽管可以尝试通过在线申请工作，但不要在上面花费太多时间。把大部分时间花在参加当地的聚会和会议来寻找工作上。加入一些良好的在线群组。如果你当地没有聚会或会议，就自己创建并组织一个。除了参加会议，还要为这些会议担任志愿者。面对面的人脉是最好的，但这受到金钱、手段以及远离大城市的限制。尽你所能，利用提供的任何资源，例如奖学金和志愿者费用报销（某些地方会报志愿者的机票和住宿费用等）。

“你认识谁”（人脉）决定了你能否获得工作。而“你懂什么”（建立技能组合）将帮助你结识和了解他人。这是一个向上的良性循环。突破口是最难的部分。之后，随着你不断积累经验、技能组合和专业声誉，事情会变得容易。

## 如何在不触犯法律的情况下获得红队技能？

有一种老调调，认为你必须违反法律才能学习黑客技术。这种观点产生于资源匮乏的年代，人们学习的唯一途径就是摆弄别人的东西。

如今，如果你能弄到一台旧笔记本电脑（eBay 上很便宜，或者社区组织免费提供——到处找找！），你可以使用免费工具构建虚拟环境，并练习所需的所有技能。使用免费的 Linux 系统，免费安装`VirtualBox`，从`vulnhub`下载免费的漏洞虚拟机，并攻击这些机器。

如果你能参加线下或线上的 CTF（夺旗赛），请参与其中。在网上或当地图书馆获取免费书籍。在`Cybrary`、`EdX`和`Coursera`上参加免费的在线课程。你学习和训练所需的一切都是免费且合法的。

## 为什么我们无法对什么是“红队”达成共识？

我们尝试过采取各种安全评估，并将它们浓括为几个口号。就是如此简单。“攻击性安全测试”的核心在于对既有安全架构进行质量保证，或者证明既有安全架构中存在漏洞。

> “攻击性安全测试”的核心在于对既有安全架构进行质量保证，或者证明既有安全架构中存在漏洞。”

如果你想测试特定的实现方案，你就进行“针对性渗透测试”。如果你想测试特定的环境，你就进行“目标环境下的开放范围渗透测试”。如果你想针对特定的威胁场景测试所有环境，你就进行“基于以下威胁行为者威胁场景的全环境开放范围渗透测试”。

在讨论这些更具开放性的评估时，`red team`（红队）这个词读起来更顺口。问题在于界限划在在哪里。针对性渗透测试从何时演变成一场全面的红队攻防？为了增加复杂性，我们将防御者设定为蓝队，因此所有攻击方测试人员都是红队，所以他们做的任何行动（即使是白盒安全审计）都可以被视为红队行动。

最后，营销部门的人非常喜欢“红队”这个概念，因为它听起来很性感很酷，我们可以用它来推销所有产品！因此`red team`的定义变得更加模糊。别担心，所有的概念性术语都会因为内涵的扩张而变得毫无意义。

## 何时应该为组织的安全计划引入正式的红队？

安全质量保证评估和渗透测试可以在也应该在安全成熟度模型的所有阶段进行。最初，它可以帮助证明对安全的迫切需求，确定初始步骤的优先级，并帮助建立基准标准。在整个成熟度模型中，它可以建立持续的基准，协助趋势分析和进一步的安全优先级排序。

公司何时从向第三方咨询公司外包这种需求转为内部？这与任何工作都一样：当成本效益分析显示引入内部资源优于外包时即可。通常，当一家公司足够大以支持开销，且这种充满活力的安全模型需要持续测试时，就是由专门的人员或团队进行攻击性安全评估的好时机。

## 如何向不情愿或非技术性的客户或组织解释红队的价值？

我将红队测试简化为质量保证。它仅此此。如果一个不情愿或非技术性的客户首先看到了安全的需求，那么他们就会看到测试这种安全的必要性以确保其有效性。如果同一个人看不到安全的需求，我会向他们展示红队或渗透评估如何证明这种需求。

最终这取决于那个人的威胁模型。他们的优先级是什么？如果这些优先级受到攻击他们会担心什么？他们想建立什么样的架构来保护这些优先级？以及他们希望如何测试并确保安全架构正常工作？

## 你看到的投入产比最低的安全控制措施是什么？

这是一个有趣的问题。我看到人们投入了安全措施，但与其他安全控制措施相比，对阻止攻击的作用微乎其微？说实话，我并没有看到太多的安全措施，所以通常比没有要好。

但尽管如此，我认为我看到的投入产比最低的安全控制是漏洞扫描器。并不是我不喜欢漏洞扫描器；如果它们真的能被充分利用，它们是非常棒的。但它们从未被充分利用。我说这句话并不是因为认为渗透测试比漏洞扫描器更好。它们都是安全质检，涵盖不同的领域并有不同的优势和应用，公司应该兼者顾。

这里我看到的一个典型场景：ACME 公司实施了一个来自顶级供应商的漏洞扫描器。这是一个非常可靠的扫描器。它可以检测相当比例的已知漏洞、简单的配置错误和缺失补丁。

ACME 运行了一次扫描器，生成了一份关于所有漏洞的巨大报告！太棒了！现在怎么办呢？你必须修复这些问题。经过多次会议，发现的问题减少到了危急（Critical）和一些高危（High），并在几个月后，只有极小一部分被修复了。剩余的中低级发现被忽略了（尽管修复其中许多项很容易，且见效快）。

但那只是一次偶然的、点点的扫描。在那段时间没有建立漏洞管理计划。没有补丁管理策略。所以，ACME 再次扫描，生成了更长的列表（因为增加了新的漏洞和对旧漏洞的新检测）。

指标显示该计划落后了。

于是，ACME 使用漏洞扫描器进行持续扫描，但扫描结果从未（或执行频率低到等同于从未）处理。此外，大多数扫描并没有覆盖整个 CIDR 范围；而是使用已知的 IP 和主机信息，因此遗漏了异常系统或遗留系统。此外，有些系统太陈旧且漏洞太多，漏洞扫描器的运行会导致它们崩溃，因此并没有让系统变得健壮，而是将其从扫描列表中移除并被遗忘。

## 你是否建议过不要进行红队攻防行动？

很多人不需要全面的红队行动。在这些人中，如果客户相信并信任我，他们通常能从白盒安全审计中获得更多益处。

通常，人们要么没有足够的经验背景来理解可能发生什么，要么他们并不了解我，或者无法通过信赖的声誉来判断我的话是否可信。这没关系。通常，红队测试（red teams）提供的影响证明至关重要，或者全面渗透测试得出的优先级排序和基准测试是其安全方法中极具价值的部分。

对于那些确实认识我、拥有安全文化且不需要黑盒测试的客户，我通常建议采用更多的白盒方法。例如，我会进行开放式安全审计，查看所有内容——网络拓扑、防火墙规则、组策略偏好、物理巡检等——然后根据从上而下看到的内容对我可以做什么进行分析。或者，我会进行更具局限性更有针对性的渗透测试，假设攻击者已获得某种程度的访问权限，并专注于其安全机制的一个关键领域。

白盒评估通常所需的时间更短，成本更低。在适当的情况下我会推荐这种方法。

## 为什么你认为遵守参与规则（Rules of Engagement）至关重要？

参与规则（ROE）由于以下几个原因至关重要。首先，可能不需要测试所有内容。例如，如果客户知道自己容易受到网络钓鱼攻击，并且已经开始缓解该漏洞的过程，那么通过网络钓鱼攻入他们的测试对他们来说将无益无完。这能证明什么他们已经不知道的事情呢？除了他们已经在正在缓解的问题之外，这还能说明其他什么？因此，我们可能会在`ROE`中加入“不进行网络钓鱼尝试”，以便将评估引导到其他可能导致入侵的其他因素，并帮助进一步缩小攻击面。

其次，`ROE`有助于防止实际损害。我可能会证明我获得了足够的访问和特权来删除所有数据，但我永远不会真的删除所有数据。我可以给员工留在车里的笔记本电脑拍照，但我不会去撞破他们的车窗来偷笔记本电脑。除了法律问题之外（我不会为了进行测试而违反当地法律，即使攻击者可能会这样做），我们希望我们的测试能阻止实际伤害，而不是由我们自己造成实际伤害。因此，我们的`ROE`将专门包含此类表述，说明我们可能会展示访问或特权，但不会进行极有可能导致实际损害的影响证明。

## 如果你在渗透测试或其他任务中被“抓包”了，你是如何处理的？

我很少在传统意义上被“抓包”。通常在获得访问权限并展示影响证明后，我的动作会变得越来越大，直到我（故意地）被发现。然后，我会设定一个检测基准，帮助客户知道他们看到了什么，错过了什么。话虽如此，我确实被多次叫停过。我喜欢通过讲述故事、演讲和参加播客节目来强调这些时刻。其中一些包括我的《唱忧歌：当蓝队踢掉红队的屁股》系列。

让我回想一个我没说得那么多的例子……我当时正从互联网黑入一个网站。我发现了一个漏洞，允许我进行盲注 SQL 注入攻击并访问后端数据库。在了一些试探性的探测后，我使用`sqlmap`开始发力并让它尽情发挥。在三个不同的日子里，我进行了攻击并转储了数据库碎片。

然而，获取完整的身份哈希值非常困难。该 Web 应用并不健健壮，盲注 SQL 攻击需要大量的调整才能获得可靠的输出。在我获取关键账户信息之前，我被彻底拦截了。

我的`IP`地址被封锁了，更重要的是漏洞被修复了。我和另一位同事更换了 IP 并找到了新的攻击向量，但那个也被修复了，新的 IP 地址也被封锁了。当我们耗尽了几个 IP 地址且无法找到更多攻击向量时，我通过他们的登录门户向目标发送了最后一条信息：

```
UNION SELECT "Hello Team! Good Job!" --
```

（注：此处原文代码块内包含 SQL ，根据指令代码块不需要翻译，但为了保持逻辑连贯，保留了其结构）

对于希望我们在事后协助缓解问题的客户，我们通常会将工作交给其他团队，由他们负责构建缓解措施并加强安全性。我们在整个过程中都会为他们提供协助。

对于希望采用更多“紫军”（purple team）方法的客户，我们将蓝队成员加入我们的行动中，或与他们并肩作战。我们将观察他们是否能看到我们的行动，并帮助他们调整工具，直到达到预期的最终状态。

这一切在项目的范围界定过程中都会安排好。

### 关于编写良好的报告，有什么实用的建议？

使用模板和报告生成工具。

- 针对常见的评估设置模板报告。模板报告应包含有关评估方法的详细信息、最可能采取的操作列表，以及最可能使用的工具列表。这些内容应该是通用的。例如，工具列表应该包含经常使用的多套工具集。如果某个工具没有被使用，或者使用了但未列出，稍后在健壮的列表中添加或删除都会容易得多。
- 设置模板化的发现项（findings），其中包含通用的总结、通用的缓解建议以及详细的资源信息列表。红队通常会在多个客户和目标中发现共同问题。如果他们能从模板中提取这些问题并调整模板以满足该评估的特定发现，就能节省大量生成报告的精力。
- 调整所有模板，以描述在该评估期间发现的特定问题。由于大部分报告工作已经通过模板完成，重点就可以放在了该客户或目标特有的问题上。这防止了测试人员忽略那些他们能理解但客户可能不理解的问题。这让客户能够获得深入的信息，而测试人员不需要在每次评估完成后都将这些撰写一遍。

### 你如何确保你的程序结果对于需要完整叙述和背景的人来说具有价值？

最重要的一点是回顾攻击方法，并展示攻击中哪些操作是有效的，哪些是无效的。记录良好的方法论将向客户展示尝试了哪些内容以及测试是如何开展的。攻击叙述将提供有关背景的细节，说明测试人员从哪里开始、到达了何处以及是如何到达那里的。

除了展示负面发现或漏洞外，突出正面发现也同样重要。正面发现将包括防止特定攻击的安全防御机制，以及蓝队检测到、响应并遏制攻击的时刻。

### 除了指出不足之处，你如何建议改进安全措施？

指出漏洞是安全质量保证的第一步。构建缓解措施或修复漏洞是第二步。提供多种缓解或修复问题的方法非常重要，因为每个客户或业务部门都处于不同的状况。通常，我们会提供分级建议（立即执行以获得快速成效的事）和长期解决方案（解决根本问题并随时间推移防止进一步问题的事）。

如果客户或业务部门允许红队更积极地协助修复过程，那么围绕威胁建模、预算限制和优先级排序的讨论将能够在特定限制下提供最佳的安全。

### 你是如何开始红队工作的？

我相信我一直有着红队心态，即使是在从事物理安全工作、巡逻新建筑或在新站点开始时也是如此。我总是会观察防御设施，并检查摄像头的位置是否正确，以确保周边界安全。我会确保门已锁好，并且没有绕过门的方法，所以我总是以那种心态思考——我会如何破入并成为那个坏人。直到职业生涯中期，我才真正开始担任正式的红队角色。当我开始关注物理方面时，部分是受到看到其他红队成员在会议上演讲的启发，我意识到：“哇，那是另一个我可以开始尝试的途径，”于是开始在我的组织内开展红队工作。他们非常支持，并让我做这些事情，这帮助完善了我的技能，并让我更有信心去真正追求它——这非常合适。他们的支持令他们受益，从长远来看也令我受益。

### 获得红队工作的最好方法是什么？

我认为获得红队工作的最好方法是从蓝队开始。我总是告诉人们红队工作很有趣，而且出于某种原因，我们让这一切听起来就像他们是很酷的人，比如：“噢，看这些人正在闯入并偷东西。他们正在入侵网络并下载所有的核心资产。”这确实很酷，但我认为如果你了解防御是什么、防御者如何思考，以及防御是如何制造、构建和监控的，你就无法成为真正优秀的红队。我确定大家都在讨论获得工作的不同方法和面试地点，但如果你想成为一名优秀的红队，请忘记这些部分。如果你想成为一个在该领域非常出色的人，请从蓝队开始做防御者的工作。学习他们的流程，学习他们如何升级问题，学习他们在监控什么，以便你绕过他们。如果你想获得一份非常棒的红队工作并成为一名高效的红队，请理解蓝队运作的所有细节，这将让你成为优秀得多的对手。同时，你成为更好的对手将为客户带来价值，因为红队的作用实际上是评估并帮助蓝队。

### 为什么我们对什么是红队无法达成一致？

我完全没有头绪。我想是因为每个人对于红队应该是什么样都有自己的理想。我已经描述过红队了，我会再说一遍——我认为红队不仅仅是渗透工作中的一个物理层面；我认为它也是基于网络的。我相信红队对抗（Red Teaming）与渗透测试、漏洞评估或审计之类的工作是不同的。这是一种对抗性的思维方式。你仍然必须遵守与客户达成的约定范围，但这是一个更具对抗性的角色，你正尝试通过模拟真实攻击者的行为并入侵网络来跳出固有框架进行思考。这不仅仅是启动`Nmap`扫描查看他们是否暴露了端口，或者运行`Nessus`扫描。这其实实是进入内部并寻找创建载荷的方法，发送一个受感染的 PDF，或者在停车场留一个 USB 盘。你必须像对手一样思考，而且当你把报告交给他们时，蓝队团队将从这些信息中获益。

### 信息安全其他领域对红队哪一点最不理解？你听过的关于红队、蓝队或紫色队最具危害性的谎言是什么？

我认为红队忘记的最主要的一点之一是：他们的存在仅仅是为了造福、帮助和改进蓝队，仅此而已。没有其他意图。红队的唯一功能就是让蓝队变得更好。我要为最后排的人再强调一遍——红队成员只为蓝队而存在；他们不是独立的，也不存在于一个独立的领域去进行审计，或仅仅为了展示哪里坏了。他们的工作是促进整个公司更加安全，通过向蓝队提供关于缺陷和差距的信息来指导他们，并向他们如何加固和修复这些问题。

我认为最具危害性的谎言是，红队、蓝队或紫色队之间存在很大差异。归结底，我们都应该在同一个团队中——即努力让事情变得更好、更安全的团队。我们执行的功能不同，但我们都在同一个团队里。当公司比我们开始之前更安全时，我们最终都赢了。
