## TCP 头部

使用 TCP 协议发送的每个数据包都分配有一个 TCP 头部，其中包含与 TCP 相关的信息，如源端口、目的端口和 TCP 标志。图 1-13 显示了 TCP 头部中的不同字段。以下是每个字段的简要说明：

![Images](img/f0025-01.jpg)

**图 1-13** TCP 头部

- **源端口** 这个 16 位字段标识发送系统的端口号。
- **目的端口** 这个 16 位字段标识数据包在目的系统上要发往的端口号。
- **序列号** 这个 32 位字段标识数据包的序列号。
- **确认号** 这个 32 位字段标识该数据包所确认的数据包。
- **偏移量** 这个 4 位字段指示数据从何处开始。
- **保留** 这个 6 位字段始终设置为 0，为将来使用而设计。
- **标志** 这个 6 位字段存放 TCP 标志。前文提到的每个标志都有一个 1 位字段。
- **窗口大小** 这个 16 位字段决定在需要确认之前可以发送多少信息。
- **校验和** 这个 16 位字段用于验证 TCP 头部的完整性。
- **紧急指针** 这个 16 位字段仅在设置了 `URG` 标志时使用，它指向最后一个紧急信息片段。
- **选项** 这是一个可变长度字段，指定 TCP 头部中可能需要的任何附加设置。

# Internet Protocol（互联网协议）

互联网协议（IP）为模型中更高层的协议提供数据包传递服务。它是一种无连接传递系统，会“尽最大努力”将数据包传递到正确的目的地。IP 不保证数据包的传递——那是传输层协议的责任；IP 只是发送数据。

![Image](img/exam.jpg)

> **IP 是 OSI 模型的第 3 层协议，负责逻辑寻址和路由。**

互联网协议还负责 TCP/IP 的逻辑寻址和路由，因此被视为 OSI 模型的第 3 层协议。路由器上的互联网协议负责递减（通常减 1）数据包的 TTL（生存时间），以防止其陷入“网络环路”中。Windows 操作系统的默认 TTL 为 128。

![Image](img/exam.jpg)

> **虽然 OSI 模型更多是 Network+ 考试的主题，但对于 Security+ 考试也很重要，因为它作为背景知识有助于理解网络技术，如网络设备和访问控制列表。例如，如果你理解 OSI 模型，并在考题中读到一种可以基于第 3 层或第 4 层信息进行过滤的防火墙技术，那么你就知道该技术可以基于源和目的 IP 地址（第 3 层）以及 TCP 或 UDP 端口信息（第 4 层）进行过滤。**

## IP Header（IP 头部）

数据包中的 IP 头部包含帮助数据包从源传输到目的地的信息。以下是字段及其含义的列表，而 图 1-15 显示了 IP 头部结构：

![Images](img/f0028-01.jpg)

**图 1-15 IP 头部**

- **Version（版本）** 4 位字段，标识所用 IP 版本（例如 4 或 6）
- **Header length（头部长度）** 4 位字段，指示 IP 头部的大小
- **Type of service（服务类型）** 8 位字段，指示系统应如何处理该数据包。例如，如果指定了 Low Delay（低延迟）选项，意味着系统应立即处理该数据包
- **Total length（总长度）** 16 位字段，指示 IP 数据包的总大小（注：原文为 "size of the IP header"，实为总长度）
- **Identification（标识）** 16 位字段。网络只能处理特定最大尺寸的数据包——称为最大传输单元（`MTU`）——因此系统可能会将发送的数据分割成多个片段。该字段唯一标识该片段
- **IP flags（标志）** 3 位字段，指定如何处理片段。例如，More Fragments（MF，更多片段）标志指示后续还有片段。此外，Don't Fragment（DF，不分片）位指定不对数据包进行分片
- **Fragment offset（片段偏移）** 13 位字段，指定数据包重组时片段重新组装的顺序
- **Time to live (TTL)（生存时间）** 8 位字段，指定数据包何时过期。TTL 值随数据包经过的每个路由器递减。当 TTL 达到 0 时，数据包被丢弃
- **Protocol（协议）** 8 位字段，指定数据包应使用哪种第 4 层协议（TCP 或 UDP）
- **Header checksum（头部校验和）** 16 位字段，验证 IP 头部的完整性
- **Source address（源地址）** 32 位字段，表示发送系统的 IP 地址。接收系统据此知道向何处发送回复消息
- **Destination address（目的地址）** 32 位字段，表示数据包要发往的系统的 IP 地址
- **IP options（IP 选项）** 可变长度字段，用于指定 IP 头部中的任何其他设置

# Internet Control Message Protocol（互联网控制消息协议）

互联网控制消息协议（ICMP）使 TCP/IP 网络上的系统能够共享状态和错误信息。你可以利用状态信息检测网络故障。ICMP 消息被封装在 IP 数据报中，以便在网络中路由。使用 ICMP 消息的两个程序是 `ping` 和 `traceroute`（Linux）或 `tracert`（Windows）。

你可以使用 `ping` 向某 IP 地址发送 ICMP 回显请求并等待 ICMP 回显响应。`ping` 报告发送请求和接收响应之间的时间间隔。通过 `ping`，你可以判断网络上特定的 IP 系统是否正常工作。你可以结合多种选项使用 `ping` 实用程序。

![Image](img/exam.jpg)

> **ICMP 是 TCP/IP 协议套件中负责错误和状态报告的协议。`ping` 和 `tracert` 等程序使用 ICMP。**

`tracert` 追踪到达特定主机所经过的路径。该实用程序在排查互联网络故障时非常有用。`tracert` 向某 IP 地址发送 ICMP 回显请求，同时将 IP 头部中的 TTL 字段从 1 开始每次递增 1，然后分析返回的 ICMP 错误消息。每次后续的回显请求应比前一次深入网络一跳，直到 TTL 字段达到 0，尝试转发它的路由器返回“ICMP time exceeded”（ICMP 超时）错误消息。

## ICMP Types and Codes（ICMP 类型和代码）

ICMP 不使用端口号，而是使用 ICMP 类型和代码来标识不同类型的消息。例如，`ping` 请求使用的回显请求消息使用 ICMP 类型 8，而 `ping` 回复返回 ICMP 类型 0 消息。

# 地址解析协议

地址解析协议 (ARP) 在 TCP/IP 网络上提供逻辑地址到物理地址的解析，即将 IP 地址转换为 MAC 地址。为实现这一功能，ARP 会发送一个包含 ARP 请求数据包的广播消息，该数据包内含有其试图查找的系统的 IP 地址。本地网络上的所有系统都会看到该消息，而拥有 ARP 正在查找的 IP 地址的系统会通过在 ARP 回复数据包中发送其物理地址给发起系统来进行响应。该物理/IP 地址组合随后会被存储在发起系统的 ARP 缓存中以供将来使用。

所有系统都维护着包含 IP 地址到物理地址映射的 ARP 缓存。在发起广播之前，系统总会先检查 ARP 缓存中是否存在 IP 地址到物理地址的映射。

![Image](img/exam.jpg)

> **ARP 负责将 IP 地址（第 3 层地址）转换为物理 MAC 地址（第 2 层地址）。**

# 理解应用层协议

备考 Security+ 认证考试时，您需要了解应用程序用于通信的各种协议。在本节中，您将学习互联网应用程序和网络应用程序常用的常见协议。

## HTTP 和 HTTPS

超文本传输协议 (HTTP) 用于互联网，允许客户端从 Web 服务器请求网页，并允许客户端与这些 Web 服务器进行交互。HTTP 是一种无状态协议，这意味着 Web 服务器不知道客户端请求过什么或未请求过什么，也无法跟踪请求过特定内容的用户。该系统不利于与 Web 服务器进行良好的交互，但确实允许检索存储在网站上的 HTML 页面。为了帮助跟踪客户端请求，我们使用 Cookie——存储在客户端计算机上的小文件，允许 Web 服务器在客户端存储数据，客户端会在每次向服务器发送请求时将这些数据发送回服务器。

安全超文本传输协议 (HTTPS) 允许您连接到网站，并使用安全套接字层 (SSL) 或其继任者 `Transport Layer Security (TLS)` 以加密格式接收和发送内容。HTTPS 最常用于电子商务网站，允许您发送个人信息，特别是信用卡号和其他机密数据，而无需担心互联网黑客窥视这些信息。您可以通过网站地址以 `https://` 开头而非 `http://`（标志着常规 HTTP 协议）来判断是否正在使用 HTTPS。HTTPS 正在使用的另一个迹象是浏览器地址栏中出现一把锁——锁的状态为关闭或锁定（如 图 1-17 所示）。

## DNS

域名系统 (DNS) 服务用于将完全合格域名 (FQDN) 转换为 IP 地址。访问互联网站点或互联网上的服务器时，您会使用诸如 [www.gleneclarke.com](http://www.gleneclarke.com) 之类的名称来连接系统。在尝试连接之前，您的系统会通过 UDP 端口 53 查询 DNS 服务器，请求该系统的 IP 地址。一旦您的系统获得了目标系统的 IP 地址，它就会使用该 IP 地址与该系统建立连接。

## SMTP

简单邮件传输协议 (SMTP) 用于通过 TCP/IP 网络（如互联网）发送或路由邮件。大多数电子邮件服务器产品支持 SMTP（TCP 端口 25），以便将邮件从企业发送到互联网。

## POP3

邮局协议版本 3 (POP3) 是用于通过 TCP 端口 110 从邮件服务器将电子邮件检索到 POP3 客户端的互联网协议。客户端通过其邮箱认证后，电子邮件会被“弹出”或下载到客户端。就文件夹支持而言，POP3 的功能有限。POP3 客户端仅支持收件箱、发件箱、已发送项目和已删除项目。如果需要额外的文件夹支持，则需要使用 IMAP4 客户端。

![Image](img/exam.jpg)

> **POP3 和 IMAP4 是用于读取电子邮件的互联网协议，而 SMTP 是用于发送电子邮件的互联网协议。**

## IMAP4

### 互联网消息访问协议版本 4 (IMAP4)
