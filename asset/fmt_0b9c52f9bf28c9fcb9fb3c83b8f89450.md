
IPv6 主机可以无状态地自动配置唯一的 IPv6 地址，从而省去了静态寻址或 DHCP 的需求。IPv6 无状态地址自动配置（SLAAC）获取主机的 MAC 地址并用其来配置 IPv6 地址。图 5.3 中的 `ifconfig`（接口配置）输出显示 MAC 地址为硬件地址（HWAddr）`00:0c:29:ef:11:36`。

![图 5.3 显示 MAC 地址和 IPv6 地址的“ifconfig”输出。](img/f05-03-9780443187346.jpg)

图 5.3 显示 MAC 地址和 IPv6 地址的“ifconfig”输出。

IPv6 地址长 128 位，使用冒号而非句点来分隔段。一串连续的零可以压缩为两个冒号（`::`）。图 5.3 中的“ifconfig”输出显示了两个 IPv6 地址：

*   `fc01::20c:29ff:feef:1136/64`（作用域：全局）
*   `fe80::20c:29ff:feef:1136/64`（作用域：链路）

第一个地址（`fc01::…`）是“全局”（可路由）地址，用于本地网络以外的通信。IPv6 主机依赖 IPv6 路由通告来分配全局地址。在图 5.3 中，本地路由器发送了 `fc01` 网络的路由通告，主机利用它来配置其全局地址。

第二个地址（`fe80::…`）是链路本地地址，仅用于本地网络通信。系统独立分配链路本地地址，无需 IPv6 路由器通告。即使没有任何集中式 IPv6 基础设施（如发送 IPv6 路由通告的路由器），任何 IPv6 系统也会分配一个链路本地地址，并可使用该地址与 LAN 上的其他链路本地 IPv6 地址通信。

`/64` 是 CIDR 格式的网络大小：见下文“无类域间路由”一节。这意味着网络前缀长 64 位：完整的全局前缀为 `fc01:0000:0000:0000`。

图 5.3 中的主机使用以下过程无状态地配置其全局地址：

*   获取 MAC 地址：`00:0c:29:ef:11:36`
*   在中间两字节嵌入“fffe”常量：`00:0c:29:ff:fe:ef:11:36`
*   设置“通用位”：`02:0c:29:ff:fe:ef:11:36`
*   添加网络前缀并转换为“:”格式：`fc01:0000:0000:0000:020c:29ff:feef:1136`
*   将一串连续的零转换为“::”：`fc01::20c:29ff:feef:1136`

### IPv6 安全挑战

IPv6 解决了许多问题，包括增加足够的地址空间和自动配置，使路由变得更简单。但其中一些解决方案（如自动配置）可能会引入安全问题。

一个启用了 IPv6 的系统将自动配置一个链路本地地址（以 `fe80:…` 开头），而无需任何其他启用 IPv6 的基础设施。该主机可以与同一 LAN 上的其他链路本地地址通信。即使管理员不知道 IPv6 正在他们的网络上流动，这也是成立的。

ISP 也在启用 IPv6 服务，有时客户并不知情。现代网络工具，如网络入侵检测系统，可以“看到” IPv6，但通常未配置为这样做。而且许多网络专业人员对 IPv6 的经验或理解有限。从攻击者的角度来看，这可能提供一个绝佳的机会，通过 IPv6 发起攻击或窃取数据。

所有非必需的网络服务都应禁用：这是系统加固的基本组成部分。如果不需要 IPv6，应将其禁用。要在 Windows 主机上禁用 IPv6，请打开网络适配器并选择“属性”。然后取消勾选“Internet 协议版本 6”复选框，如图 5.4 所示。

### 有类网络

最初的 IPv4 网络（1993 年之前）是“有类的”，分为 A 类到 E 类。A 类到 C 类用于正常网络用途。D 类为组播，E 类为保留。表 5.4 显示了每类的 IP 地址范围。

| 类别 | IP 范围 |
| --- | --- |
| A 类 | 0.0.0.0–127.255.255.255 |
| B 类 | 128.0.0.0–191.255.255.255 |
| C 类 | 192.0.0.0–223.255.255.255 |
| D 类（组播） | 224.0.0.0–239.255.255.255 |
| E 类（保留） | 240.0.0.0–255.255.255.255 |

有类网络缺乏灵活性：用于普通终端主机的网络只有三种规模：16,777,216 个地址（A 类）、65,536 个地址（B 类）和 256 个地址（C 类）。最小的可路由有类网络是拥有 256 个地址的 C 类网络：使用有类网络的可路由点对点链路需要在两点之间建立一个网络，浪费了 250 多个 IP 地址。

### 无类域间路由

无类域间路由（CIDR）允许比有类地址更灵活的网络规模。CIDR 允许超出任意有类网络规模的许多网络尺寸。

A 类网络 `10.0.0.0` 包含以 10 开头的 IP 地址：`10.1.2.3.4`、`10.187.24.8`、`10.3.96.223` 等。换句话说，`10.*` 是一个 A 类地址。点分十进制 IPv4 地址的前 8 位是网络部分（10）；剩余的 24 位是主机地址：`3.96.223`，即上例中的最后一个 IP 地址。A 类网络的 CIDR 表示法为此用 `/8`：`10.0.0.0/8`。“/8”是网络掩码，意味着网络部分长 8 位，为主机留出 24 位。

同样，`192.0.2.0` 的 C 类网络包含任何以 `192.0.2` 开头的 IP 地址：`192.0.2.177`、`192.0.2.253` 等。该 C 类网络在 CIDR 格式中为 `192.0.2.0/24`：前 24 位（`192.0.2`）描述网络；剩余 8 位（上例中的 `177` 或 `253`）描述主机。

一旦网络用 CIDR 表示法描述，就可以有更多可路由的网络规模。需要 128 个 IP 地址？将一个 C 类（`/24`）对半分，得到两个 `/25` 网络。需要 64 个 IP 地址？将一个 `/24` 网络四等分，得到四个拥有 64 个 IP 地址的 `/26` 网络。

### RFC 1918 寻址

*RFC 1918 地址* 是私有 IPv4 地址，可用于不通过互联网路由的内部流量。这允许节约稀缺的 IPv4 地址：无数内部网可以使用相同的重叠 RFC 1918 地址。为此划分了三个 IPv4 地址块：

*   `10.0.0.0–10.255.255.255` (`10.0.0.0/8`)
*   `172.16.0.0–172.31.255.255` (`172.16.0.0/12`)
*   `192.168.0.0–192.168.255.255` (`192.168.0.0/16`)

任何使用未转换的 RFC 1918 地址作为目标的公共互联网连接都将失败：这些网络没有公共路由。发送带有未转换的 RFC 1918 源地址的互联网流量将永远无法返回。使用有类术语，`10.0.0.0/8` 网络是一个 A 类网络，`172.16.0.0/12` 网络是 16 个连续的 B 类网络，而 `192.168.0.0/16` 是 256 个 C 类网络。

RFC 1918 地址用于节约供应短缺的公共 IPv4 地址。RFC 代表“征求意见”，是一种在互联网上讨论和发布标准的方式。关于 RFC 1918 的更多信息请访问 [`www.rfc-editor.org/rfc/rfc1918.txt`](https://www.rfc-editor.org/rfc/rfc1918.txt)。

> **注意**
>
> 考试通常不要求记忆 RFC 编号；RFC 1918 地址是这一规则的例外。考试旨在测试信息安全通用语言的知识。“RFC 1918 地址”一词在网络专业人员中常用，信息安全专业人员应予以理解。

### 网络地址转换

*网络地址转换*（NAT）用于转换 IP 地址。它常用于将 RFC 1918 地址从内部网传递到互联网时进行转换。如果您想知道如何使用配置了私有 RFC 1918 地址的 PC 浏览公共 Web，NAT 是一种答案（代理是另一种）。

NAT 有三种类型：静态 NAT、地址池 NAT（也称为动态 NAT）和端口地址转换（PAT，也称为 NAT 过载）。静态 NAT 在地址之间进行一对一转换，例如 `192.168.1.47 → 192.0.2.252`。地址池 NAT 在地址池中预留多个公共 IP 地址，例如 `192.0.2.10 → 192.0.2.19`。地址可从池中分配，随后归还。最后，PAT 通常将多个私有地址多对一转换为一个公共 IP 地址，例如 `192.168.1.*` 到 `192.0.2.20`。PAT 是家庭和小型办公室的常见解决方案：多个内部设备（如笔记本电脑、台式机和移动设备）共享一个公共 IP 地址。表 5.5 总结了 NAT 类型的示例。

NAT 隐藏了数据包的来源：源地址是 NAT 网关（通常是路由器或防火墙），而非主机本身。这提供了一些有限的安全优势：针对系统 NAT 转换地址的攻击通常会针对 NAT 网关，而非最终主机。这种保护有限，绝不应被视为主要安全控制。始终需要纵深防御。

### ARP 和 RARP

*ARP* 是地址解析协议，用于在第二层 MAC 地址和第三层 IP 地址之间进行转换。ARP 通过询问“谁拥有 IP 地址 192.168.2.140，请告诉我”将 IP 解析为 MAC 地址。ARP 回复示例为“192.168.2.140 位于 00:0c:29:69:19:66”。

```
arp who-has 192.168.2.140 tell 192.168.2.4
arp reply 192.168.2.140 is-at 00:0c:29:69:19:66
```

> **注意**
>
> ARP 等协议非常“信任”他人：攻击者可能利用这一点，通过伪造 ARP 响应来劫持流量。任何本地系统都可能响应 ARP 请求，包括攻击者。这可能导致 ARP 缓存投毒攻击，受害系统缓存指向恶意系统的虚假 ARP 条目。ARP 缓存投毒常用于中间人（MitM）攻击，攻击者频繁投毒关键系统（如默认网关）的 ARP 条目，将流量重定向到攻击者的系统。
>
> 出于此原因，安全网络应考虑硬编码 ARP 条目。

*RARP* 曾被旧式无盘工作站用于确定其 IP 地址。节点询问“谁拥有 MAC 地址 00:40:96:29:06:51，请告诉 00:40:96:29:06:51”。

```
ARP, Reverse Request who-is 00:40:96:29:06:51 tell 00:40:96:29:06:51
```

换句话说，RARP 询问：“我是谁？请告诉我。”RARP 服务器会响应节点的 IP 地址。

### 单播、组播和广播流量

#### 单播、多播和广播

**单播** 是一对一流量，例如客户端浏览网页。**多播** 是一对多，且“多”是预先选定的。**广播** 是局域网上的一对所有。

**多播** 流量在 IPv4 中使用“D 类”地址。节点被放入多播组。常见的多播应用是流式音频或视频。通过单播发送 1000 个音频流将需要大量带宽，因此使用多播。它的工作原理类似于一棵树：初始流是树干，多播组的每个成员是一片叶子。一个流从流媒体服务器发出，当它到达拥有通往多播组中节点的多条路由的路由器时，会在网络上分支。多播通常使用 UDP。

#### 受限广播地址和定向广播地址

**广播** 流量发送给局域网上的所有站点。IPv4 广播地址有两种类型：受限广播和定向广播。受限广播地址是 `255.255.255.255`。之所以称为“受限”，是因为它永远不会被路由器转发，这与定向广播不同。

`192.0.2.0/24` 网络的定向（也称为网络定向）广播地址是 `192.0.2.255`（地址的主机部分在二进制中全为“1”，即 255）。之所以称为“定向”广播，是因为发往这些地址的流量可能来自远程网络（可以被“定向”发送）。

#### 第 2 层广播流量

第 2 层广播流量到达“广播域”内的所有节点。同一局域网（或 VLAN）上的设备处于同一广播域中。以太网广播地址是 MAC 地址 `FF:FF:FF:FF:FF:FF`：发送到以太网交换机上该地址的流量将被所有连接的节点接收。

#### 混杂网络访问

访问网段上的所有单播流量需要“**混杂**”网络访问。网络入侵检测系统 (NIDS) 等系统需要混杂网络访问，以便监控网络上的所有流量。网络节点通常只能“看到”直接发送给它们的单播流量。访问发送给其他节点的单播流量需要两样东西：配置为混杂模式的网络接口卡 (NIC) 以及访问网段上其他单播流量的能力。

将 NIC 置于混杂模式通常需要超级用户访问权限，例如 UNIX 系统上的 `root` 用户。交换机等设备提供流量隔离，因此每个主机将只接收发送给它的单播流量（除了广播和多播流量）。正如我们在后面章节将看到的，**集线器**、交换机 SPAN 端口或 TAP 通常用于提供混杂网络访问。

TCP 是传输控制协议，一种可靠的第 4 层协议。TCP 使用三次握手在网络上创建可靠连接。TCP 可以对乱序到达的段进行重新排序，并重传丢失的段。

### TCP 端口

TCP 从源端口连接到目的端口，例如从源端口 `51178` 到目的端口 `22`。TCP 端口字段为 16 位，允许端口号从 `0` 到 `65535`。

端口分为两类：**保留端口** 和 **临时端口**。保留端口为 `1023` 或更低；临时端口为 `1024`–`65535`。大多数操作系统要求超级用户权限才能打开保留端口。任何用户均可打开（未使用的）临时端口。

常见服务（如 HTTP）使用知名端口。互联网号码分配局 (IANA) 在 [`www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml`](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml) 维护一份知名端口列表。大多数 Linux 和 UNIX 系统在 `/etc/services` 中有一份较小的知名端口列表。
