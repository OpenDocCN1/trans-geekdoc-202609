### 网络杀伤链

洛克希德·马丁的**网络杀伤链**是一个七步流程，如图 14.5 所示。

![图 14.5 网络杀伤链](img/c14f005.png)

**图 14.5** 网络杀伤链

以下是网络杀伤链的七个阶段：

#### 侦察

此阶段用于识别目标。攻击者正在规划攻击，并将收集关于目标的情报，包括开源情报以及通过扫描直接获取的目标数据。防御者必须收集关于侦察活动的数据，并根据该信息确定防御优先级。

#### 武器化

此阶段涉及构建或以其他方式获取 `weaponizer`（武器化工具），它将恶意软件和漏洞利用组合成可投递给目标的载荷。这可能需要创建诱饵文档、选择合适的命令与控制（`C2`）工具以及处理其他细节。该模型强调了这样一个事实：防御者需要在此阶段进行完整的恶意软件分析，不仅要了解投放了什么载荷，还要了解武器化漏洞利用是如何制作的。防御者还应为武器化工具构建检测规则，查看恶意软件创建时间与使用时间的时间线对比，并收集文件和元数据，以帮助判断这些工具是广泛共享的，还是严格保密的，从而可能具有高度针对性。

#### 投递

当攻击者直接针对目标部署工具，或通过依赖目标员工与其交互的方式发布工具（如电子邮件载荷、USB 存储棒，或通过他们访问的网站）时，即发生此阶段。此阶段的防御者必须观察攻击是如何投递的以及针对什么目标，然后推断攻击者意图达成的目的。日志保留至关重要，因为它有助于确定发生了什么，并协助攻击分析。

#### 利用

此阶段利用软件、硬件或人为漏洞获取访问权限。它可能涉及零日漏洞利用，并可能使用攻击者触发的漏洞利用或受害者触发的漏洞利用。针对此阶段的防御侧重于用户意识、安全编码、漏洞扫描、渗透测试、端点加固以及类似活动，以确保组织拥有强大的安全态势和极小的攻击面。

#### 安装

此阶段专注于为攻击者建立持久化后门访问。防御者必须监控持久化远程 Shell 或其他远程访问方法的典型工件。

#### 命令与控制（C2）

`C2` 访问允许双向通信和对远程系统的持续控制。防御者将通过加固网络、部署检测能力以及进行持续研究，来寻求检测 `C2` 基础设施，以确保他们了解新的 `C2` 模型和技术。

#### 目标行动

当任务目标达成时，将发生最后阶段。攻击者将收集凭证、提升权限、在环境中横向移动和转移，并收集和窃取信息。他们还可能对系统或数据造成破坏。防御者必须建立事件响应剧本，检测攻击者的行动并捕获相关数据，响应警报，并评估攻击者造成的损害。

### 事件响应数据与工具

事件响应人员依赖各类数据开展工作。作为安全专业人员，你需要了解可能需要哪些类型的数据来进行调查，并确定发生了什么以及如何防止再次发生。

#### 安全信息与事件管理系统

在许多组织中，核心安全监控工具是 `安全信息与事件管理 (SIEM)` 工具。`SIEM` 设备和软件具有广泛的安全功能，这些功能通常基于从多种来源收集和聚合日志数据的能力，然后利用这些数据执行关联和分析活动。这意味着组织会将数据输入（包括来自系统、网络安全设备、网络基础设施和许多其他来源的日志及其他有用信息）发送到 `SIEM` 进行摄取，与其拥有的其他数据进行比较，然后对数据应用规则、分析技术以及机器学习或人工智能。`SIEM` 系统可能包括审查和警报用户行为的能力，或执行情感分析，这是一个利用自然语言处理和其他文本分析工具查看文本以从文本数据中确定情绪的过程。

`SIEM` 设备的另一个数据输入是数据包捕获。从网络流量中捕获和分析原始数据包数据，或从其他数据源接收数据包捕获，对于事件分析非常有用，特别是在需要关于网络事件的具体信息时。将原始数据包数据与 `IDS` 或 `IPS` 事件、防火墙和 `WAF` 日志以及其他安全事件相关联，为安全从业者提供了一个强大的工具。

`SIEM` 设备还提供警报、报告和响应功能，使组织能够了解何时需要处理问题，并跟踪该问题在其生命周期内的响应情况。这可能包括取证能力，也可能更侧重于工单和工作流流程来处理问题和事件。

##### SIEM 仪表板

许多安全从业者看到的 `SIEM` 的第一部分是仪表板，如图 14.6 所示的 AlienVault `SIEM` 仪表板。仪表板可配置为显示组织或个人分析师认为最有用和最关键的信息，并且可以配置多个仪表板以显示特定视图和信息。仪表板的关键在于理解它们提供了所包含信息的高层级可视化表示。这有助于安全分析师快速识别潜在问题、异常模式和可能感兴趣或令人担忧的新趋势。

##### 传感器

尽管设备可以直接将数据发送到 `SIEM`，但通常会部署传感器来收集额外数据。传感器通常是软件代理，尽管它们也可以是虚拟机甚至专用设备。传感器通常部署在云基础设施、远程数据中心或其他产生大量独特数据的环境中，或者现有能力无法满足数据获取需求、需要专用设备的位置。传感器为 `SIEM` 收集有用数据，并可能按原始形式转发，或在 `SIEM` 摄取前进行一些预处理以优化数据。选择传感器部署位置是网络和安全架构及设计工作的一部分，传感器必须像其他网络安全组件一样得到保护，防止遭受攻击和妥协。

###### 灵敏度与阈值

组织可以产生海量数据，安全数据也不例外。分析师需要了解如何控制和限制 `SIEM` 产生的警报。为此，他们设置阈值、过滤规则，并使用其他管理 `SIEM` 灵敏度的方法。警报可设置为仅在事件发生特定次数时触发，或仅在影响特定高价值系统时触发。或者，警报可设置为仅触发一次，而不是成百上千次。无论您的 `SIEM` 如何处理灵敏度和阈值，配置和管理它们以确保仅在需要警报的项目上发送警报，有助于避免警报疲劳和误报。

##### 趋势

查看趋势信息的能力是 SIEM 平台功能中极具价值的一部分。趋势可以指向一个开始出现的新问题、正在发生并蔓延的漏洞利用，或者仅仅是你组织中最流行的恶意软件是什么。在图 14.7 中，你可以看到一个对恶意软件活动进行分类的示例，识别出检测频率最高的签名、最流行的恶意软件家族，以及其发送流量的去向。这有助于组织在新威胁浮出水面时识别它们。

###### 关联与分析

在调查事件时，单个数据点可能很有用，但将数据点与其他数据点进行匹配是大多数调查的关键部分。关联需要拥有诸如事件发生的时间、发生在什么系统上、涉及哪些用户账户以及其他有助于分析过程的详细信息等数据。SIEM 允许你基于这些多个数据点搜索和过滤数据，以缩小与事件相关的信息范围。自动化关联与分析旨在匹配已知事件和妥指标（IOC），以构建一个完整的数据集供事件或事故审查和分析。正如你在 AlienVault SIEM 的屏幕截图中所见，你可以为数据添加标签和调查。尽管每个 SIEM 工具可能用略微不同的术语来称呼这些功能，但基本概念和能力保持不变。

###### 规则

SIEM 的告警、警报和关联引擎的核心是驱动这些组件的规则集。图 14.9 展示了一个如何利用 SIEM 收集的信息构建告警规则的示例。规则条件可以使用逻辑来确定规则是否以及何时被激活，随后可基于规则触发动作。结果可能只是简单的警报，也可能是复杂的程序化动作，例如更改基础设施、启用或禁用防火墙规则，或触发其他防御措施。

![FIGURE 14.9 Rule configuration in AlienVault](img/c14f009.png)

**图 14.9** AlienVault 中的规则配置

规则很重要，但也可能引发问题。构建不当的规则逻辑可能导致漏报事件，或造成误报或过于宽泛的检测。如果规则包含主动响应组件，错误触发的规则可能导致中断或其他基础设施问题。因此，规则需要被仔细构建、测试，并定期审查。虽然 SIEM 厂商通常提供默认规则和检测能力，但组织为其环境和系统设计的自定义规则是成功部署 SIEM 的关键。

最后，SIEM 设备还遵循数据的整个生命周期。这意味着大多数都具备为每种数据类型设置保留期和数据生命周期的能力，并支持合规性要求。事实上，大多数 SIEM 设备都有预构建的规则或模块，旨在根据所需标准满足特定的合规性要求。

##### 日志文件

日志文件为事件响应人员提供有关已发生事件的信息。当然，这也使得日志文件成为攻击者的目标，因此事件响应人员需要确保他们使用的日志未被篡改，并且其中的时间戳和其他数据是正确的。一旦你确信正在处理的数据是可靠的，日志就能提供大量与事件相关的宝贵信息。

图 14.10 展示了 Windows 事件查看器，这是查看单个 Windows 系统日志最常用的方式之一。在许多企业环境中，特定日志或关键日志条目会被发送到安全的日志基础设施，以确保存在终端系统收集日志的可信副本。安全从业人员仍会审查本地日志，特别是因为组织中各终端的日志数据量巨大，通常不会为每个系统维护所有日志的完整副本。

![FIGURE 14.10 The Windows Event Viewer showing a security log with an audit event](img/c14f010.png)

**图 14.10** Windows 事件查看器显示包含审核事件的安全日志

Security+ 考试大纲涵盖的事件响应人员常用的日志包括以下内容：

*   **系统日志**包括从服务更改到权限问题的所有内容。Windows 系统日志记录系统运行时生成的信息。
*   **应用程序日志**在 Windows 中包含应用程序的安装程序信息、应用程序生成的错误、许可证检查，以及应用程序生成并发送到应用程序日志的任何其他日志。
*   **安全日志**在 Windows 系统中存储有关登录失败和成功的信息，以及其他身份验证日志信息。Linux 系统的身份验证和安全日志存储在 `/var/log/auth.log` 和 `/var/log/secure` 中。
*   **漏洞扫描输出**是另一种可纳入事件分析活动的数据形式。扫描可提供关于攻击者可能瞄准的目标、服务变更，甚至攻击者在身后封堵漏洞导致的突然修补问题的线索。
*   **网络和安全设备日志**可包括路由器和交换机的配置更改、流量信息、网络流量，以及 **数据包分析器**（如 Wireshark）捕获的数据。
*   **Web 日志**，如来自 Apache 和 Internet Information Services (IIS) 的日志，记录对 Web 服务器的请求及相关事件。这些日志有助于追踪访问了什么、何时访问的，以及发送请求的 IP 地址。由于请求会被记录，这些日志还有助于识别攻击，包括 SQL 注入和其他针对 Web 服务器和 Web 应用程序的特定攻击。
*   **DNS 日志**提供关于 DNS 查询的详细信息。这看似用处不大，但 DNS 日志可以显示攻击者收集信息的行为，根据系统的 DNS 请求提供哪些系统可能已被入侵的信息，并显示内部用户是否滥用组织资源。
*   **身份验证日志**可用于确定账户何时被登录，还可能显示权限使用、登录系统或位置、错误密码尝试，以及可关联到入侵和滥用的其他登录和使用详情。
*   **转储文件**，如 Windows 出现蓝屏死机时创建的内存转储，看似对事件响应没什么用处，但它们可能包含显示崩溃时内存和系统状态的信息。如果崩溃是由攻击者或漏洞利用导致的，或者系统上存在恶意软件或攻击工具，转储文件可能包含这些工件。

VoIP（IP 语音）、呼叫管理器日志以及会话发起协议（SIP）日志可以提供关于已拨打电话以及 VoIP 系统上其他事件的信息。

安全从业人员将使用 SIEM 工具以及 `grep` 和 `tail` 等手动搜索工具来审查日志，查找可能与事件相关的特定日志条目。重要的 Windows 事件 ID 列表通常易于获取，许多 Linux 日志条目也可以通过其包含的文本轻松识别。

###### 日志记录协议和工具

除了知道如何查找和搜索日志外，您还需要知道日志如何发送到远程系统、使用哪些工具来收集和管理日志，以及如何获取日志。

传统的 Linux 日志通过 `syslog` 发送，客户端将消息发送给收集和存储日志的服务器。随着时间的推移，创建了其他 `syslog` 替代品以改进 `syslog` 的基本功能和能力。当需要速度时，用于日志处理的高速系统 `rsyslog` 是一个选择。它支持极高的消息速率、通过 TLS 进行安全日志记录、基于 TCP 的消息以及多种后端数据库选项。另一种替代方案是 `syslog-ng`，它提供增强的过滤功能、直接记录到数据库，并支持通过受 TLS 保护的 TCP 发送日志。`rsyslog` 和 `syslog-ng` 等 `syslog` 替代品的增强功能意味着许多组织用这些选项之一替换其 `syslog` 基础设施。日志收集的最后一个选项是 NXLog，这是一个开源且商业支持的 `syslog` 集中化和聚合工具，可以解析和生成多种常见格式的日志文件，同时将日志发送到分析工具和 SIEM 解决方案。

无论您使用哪种日志记录系统，都必须在本地系统和中央日志记录及监控基础设施上做出关于保留的决策。要考虑运营需求；可能需要您收集的日志的可能场景；以及您需要满足的法律、合规性或其他要求。在许多情况下，组织选择根据其需求保留日志 30、45、90 或 180 天，但某些情况甚至可能导致某些日志被保留一年或更长时间。保留伴随着硬件成本，如果您保留了可能不希望在法庭上披露的日志，还会面临潜在的法律挑战。

###### 超越日志：使用元数据

日志条目并不是系统包含的唯一有用数据。作为系统操作、通信和其他活动正常组一部分生成的元数据也可用于事件响应。元数据是关于其他数据的数据——在系统和服务的情况下，元数据作为文件的一部分创建、嵌入在文档中、用于定义结构化数据，并包含在事务和网络通信中，以及您可以找到它的许多其他地方。

Security+ 考试大纲重点关注四种类型的元数据，但元数据分析背后的技术在许多情况下也可用于其他数据类型。您需要为考试考虑的四种元数据类型如下：

*   **电子邮件元数据**包括电子邮件中发现的标头和其他信息。电子邮件标头提供关于发件人、收件人、消息发送的日期和时间、电子邮件是否有附件、电子邮件经过哪些系统以及系统可能添加的其他标头标记的详细信息，包括反垃圾邮件和其他信息。
*   **移动设备元数据**是在手机和其他移动设备使用时收集的。它可以包括通话记录、短信和其他消息数据、数据使用情况、GPS 位置跟踪、基站信息以及通话详单中发现的其他详细信息。移动设备元数据非常强大，因为它记录了关于手机在一天中任何时间点所在位置的大量地理空间信息。
*   **Web 元数据**作为网站代码的一部分嵌入到网站中，但通常对普通用户不可见。它可以包括元标签、标头、Cookie 和其他信息，这些信息有助于搜索引擎优化、网站功能、广告和跟踪，或可能支持特定功能。
*   **文件元数据**在审查文件创建时间、创建方式、是否以及何时被修改、由谁修改、创建设备的 GPS 位置以及许多其他细节时，可以成为强大的工具。以下代码显示了使用 ExifTool (`exiftool.org`) 从单张照片中恢复的选定元数据。输出显示该照片是用数码相机拍摄的，相机插入了诸如拍摄日期、拍摄相机的具体型号、相机设置甚至固件版本等元数据。如果移动设备未设置从照片中移除该信息，它们也可能包含照片的 GPS 位置，从而导致更多信息泄露。
