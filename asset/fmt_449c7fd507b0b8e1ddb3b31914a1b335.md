
# 认证与授权

当主体想要声明身份时，他们需要证明该身份属于他们自己。这意味着他们需要进行认证。认证技术（如认证协议、服务器和标准）旨在确保主体就是他们声称的那个人，确保认证过程保持安全可靠，并确保单点登录（SSO）等功能正常工作。

授权验证您有权访问的内容。两者结合时，认证和授权首先验证您是谁，然后根据您被授权使用的内容，允许您访问资源、系统或其他对象。

## 认证与授权技术

目前有大量认证和授权技术用于认证和授权。针对 Security+ 考试，您需要熟悉其中许多技术的基础知识，包括当前和历史技术。让我们来看看您需要了解的认证技术。

**可扩展认证协议（EAP）** 是一种常用于无线网络的认证框架。存在许多使用 EAP 框架的不同实现，包括厂商专有和开放方法，如 `EAP-TLS`、`LEAP` 和 `EAP-TTLS`。这些协议中的每一个都使用该协议的消息传递标准来实现 EAP 消息。EAP 通常用于无线网络认证。

**质询握手认证协议（CHAP）** 是一种认证协议，旨在提供比 PAP（您将在本节后面读到）等协议更高的安全性。CHAP 使用加密质询和三次握手来发送凭据，如图 8.1 所示。

![图 8.1 CHAP 质询与响应序列](img/c08f001.png)

**图 8.1** CHAP 质询与响应序列

Microsoft 推出了他们自己的 CHAP 版本，称为 MS-CHAP，但 MS-CHAP 第 1 版和第 2 版中发现的漏洞导致它在很大程度上被其他协议取代。

**密码认证协议（PAP）** 是一种以密码为中心的认证协议，常与点对点协议（PPP）配合使用以认证用户。尽管 PAP 仍出现在 Security+ 考试大纲中，但您不太可能在现代实现中使用 PAP，因为它已被 CHAP 和 EAP 实现所取代。

### 802.1X

**802.1X** 是一种用于网络访问控制 (NAC) 的 IEEE 标准，用于对想要连接到网络的设备进行身份验证。在 802.1X 系统中，请求者向验证器（如网络交换机、接入点或无线控制器）发送身份验证请求。这些控制器连接到身份验证服务器，通常通过 **RADIUS** 协议。**RADIUS** 服务器随后可能依赖后端目录，使用 **LDAP** 或 **Active Directory** 作为身份信息来源。图 8.2 展示了一个使用 **EAP**、**RADIUS** 和 **LDAP** 的常见 802.1X 架构设计示例。

### RADIUS（远程认证拨号用户服务）

**RADIUS（远程认证拨号用户服务）** 是网络设备、无线网络和其他服务最常用的认证、授权和审计 (AAA) 系统之一。**RADIUS** 可以通过 **TCP** 或 **UDP** 运行，采用客户端-服务器模型。**RADIUS** 发送的密码通过共享密钥和 **MD5** 哈希进行混淆，这意味着其密码安全性不是很强。**RADIUS** 网络接入服务器与 **RADIUS** 服务器之间的流量通常使用 **IPSec** 隧道或其他保护机制进行加密，以保护流量安全。

### 终端访问控制器访问控制系统 Plus (TACACS+)

**终端访问控制器访问控制系统 Plus (TACACS+)** 是思科设计的 **TACACS**（终端访问控制器访问控制系统）的扩展。**TACACS+** 使用 **TCP** 流量提供认证、授权和审计服务。它提供完整的数据包加密以及细粒度的命令控制，允许根据需要保护单个命令。

### Kerberos

**Kerberos** 旨在不受信任的网络上运行，并使用身份验证来保护其认证流量。**Kerberos** 用户由三个主要元素组成：主体（通常是用户名）；实例（有助于区分相似的主体）；以及领域（由用户组组成）。领域通常由信任边界分隔，并拥有独立的 **Kerberos** 密钥分发中心 (**KDC**)。图 8-3 演示了基本的 **Kerberos** 认证流程。

![图 8.3 Kerberos 认证过程](img/c08f003.png)

**图 8.3** Kerberos 认证过程

当客户端想要使用 **Kerberos** 访问服务时，客户端会请求一张认证票据，即票据授予票据 (**TGT**)。认证服务器检查客户端的凭据，并使用票据授予服务 (**TGS**) 的密钥加密 **TGT** 作为响应返回。当客户端想要使用某项服务时，客户端将 **TGT** 发送给 **TGS**（通常也是 **KDC**），并包含其想要访问的资源名称。**TGS** 返回该服务的有效会话密钥，客户端向服务出示该密钥以访问它。

### 基于互联网的认证技术

基于互联网的系统通常依赖许多核心技术来实现认证和授权。这些技术包括：

#### 安全断言标记语言 (SAML)

**安全断言标记语言 (SAML)** 是一种基于 **XML** 的开放标准，用于交换认证和授权信息。**SAML** 常用于 Web 应用程序的身份提供者和服务提供者之间。使用 **SAML** 意味着服务提供者可以接受来自一系列身份提供者的 **SAML** 断言，这使其成为联合环境（我们将在本章后面讨论）的常见解决方案。

#### OpenID

**OpenID** 是一种用于去中心化认证的开放标准。**OpenID** 身份提供者可以利用已建立的身份为第三方网站提供服务。一个常见的例子是许多网站提供的“使用 Google 登录”功能，但 Google 并不是主要 **OpenID** 身份提供者 (**IdP**) 的唯一例子。Microsoft、Amazon 和许多其他组织也是 **OpenID** 身份提供者 (**IdP**)。依赖方 (**RP**) 将认证请求重定向到 **IdP**，然后接收带有断言的响应，断言因成功认证而证明用户就是他们声称的那个人，随后用户使用该用户的 **OpenID** 登录。

#### OAuth

**OAuth** 是许多网站使用的一种用于授权的开放标准。**OAuth** 为用户提供了一种方法，以确定向第三方应用程序和网站提供什么信息，而无需共享凭据。您可能在 Google Drive 插件请求访问您的文件或文件夹时体验过这一点，或者在使用 Web 会议工具请求访问 Google 日历及其所需或想要的权限列表以执行请求的功能时体验过。

这些技术是许多基于 Web 的 **SSO** 和联合实现的基础主要部分。

### 单点登录

**单点登录 (SSO)** 系统允许用户使用单一身份登录，然后使用多个系统或服务而无需重新认证。**SSO** 系统提供了显著优势，因为它们简化了用户与认证和授权系统的交互，但它们需要在现有的基于身份的安全边界数量上做出权衡。这意味着许多组织最终会为许多系统实施单点登录，但可能会为高安全环境要求额外的认证步骤或使用额外的特权账户。

**单点登录** 通常使用 **LDAP** 和 **Kerberos** 实现（如在 Windows 域和 Linux 基础设施中），或通过 **SAML** 实现用于 Web 应用程序和联合服务。

### 联合身份

在许多组织中，身份信息由 **身份提供者 (IdP)** 处理。身份提供者管理数字身份的生命周期，从创建、维护到最终在所支持的系统和服务中退役该身份。身份提供者通常是 **联合身份** 部署的一部分，它们与依赖方配对，依赖方信任身份提供者处理认证，然后依赖该认证来授予服务访问权限。联合身份常用于许多 Web 服务，但其他用途也是可能的。

以下是联合环境中常用的一些术语，您应该了解：

*   主体，通常指用户
*   **身份提供者 (IdP)**，通过 *证明* 过程提供身份和认证服务，在该过程中 **IdP** 验证用户就是他们声称的那个人
*   **服务提供者 (SP)**，向身份已由身份提供者证明的用户提供服务

此外，有时会使用 **依赖方 (RP)** 这一术语，其含义与服务提供者类似。**RP** 将要求来自 **IdP** 的认证和身份声明。

## 目录服务

**目录服务** 用于网络中，以提供关于系统、用户和组织其他信息的信息。像 **轻量级目录访问协议 (LDAP)** 这样的目录服务通常作为身份管理基础设施的一部分部署，并提供关于组织的层次化组织信息。它们常用于提供用于电子邮件和其他联系信息的组织目录。图 8.4 展示了 `Inc.com` 的 **LDAP** 目录层次结构示例，其中有两个组织单位 (**OU**)：安全和人力资源。每个单位都包含许多用通用名称 (**CN**) 标记的条目。除了图中显示的结构外，每个条目还将具有此简化图中未显示的附加信息，包括可分辨名称、电子邮件地址、电话号码、办公室位置和其他详细信息。

![图 8.4 LDAP 组织层次结构](img/c08f004.png)

由于目录包含大量组织数据，并可能用于支持一系列服务（包括基于目录的身份验证），因此必须对其进行严格保护。同样的需求往往意味着目录服务器需要公开暴露，以便为需要访问目录信息的系统或业务合作伙伴提供服务。在这些情况下，可能需要额外的安全措施、更严格的访问控制，甚至完全独立的公共目录服务。

## 身份验证方法

一旦你通过提供用户名或其他方式声明了身份，下一步就是证明该身份属于你。这一过程是身份验证过程的核心。

使用密码仍然是最常见的身份验证手段，但密码存在许多缺陷。首先，也是最重要的一点是，密码很容易被窃取并被第三方利用。除非密码所有者对其进行更改，否则攻击者将一直能够使用该密码。密码也容易遭受暴力破解攻击，这使得有决心的攻击者若能花费足够时间自由尝试，最终便能闯入系统。这促使人们采用多因素认证，防止丢失或被盗的密码导致账户轻易被攻破。

### 多因素认证

确保单一受损因素（如密码）不会造成过度风险的一种方法是使用**多因素认证（MFA）**。多因素认证正变得广泛可用，事实上，它越来越多地成为更具安全意识的组织的默认选项。如今，在大多数情况下，被钓鱼的账号和密码不会使个人或组织面临潜在的数据泄露风险。

主要有三类因素：

*   **知识因素**，包括密码、PIN 码或安全问题的答案。
*   **拥有因素**，如智能卡、USB 或蓝牙令牌，或你持有的其他物品（如 图 8.5 所示的 Titan 安全密钥）。

    ![FIGURE 8.5 A Titan key USB security key](img/c08f005.png)

    **图 8.5** Titan 安全密钥 USB 密钥

*   **固有因素**，依赖于正在进行身份验证的人员的身体特征。指纹、视网膜扫描、声纹，甚至你的打字速度和模式都包含在此类因素的选项中。

Security+ 考试大纲还描述了属性因素：

*   **位置因素**，有时称为位置因素，基于你当前的位置。GPS、网络位置和其他数据可用于确保只有身处其应在之处的用户才能进行身份验证。
*   **行为因素**，用于 Windows 10 的图片密码功能或 Android 手机的手势密码。这是一种需要不同交互形式的知识因素。
*   **特征因素**，可能是行为模式或类似特征。这些通常属于“固有因素”的一种形式，如打字速度或类似模式。
*   **熟人因素**，可包含来自他人的信任关系。

与所有安全技术一样，多因素认证系统被新型攻击攻破只是时间问题。当前的攻击已聚焦于使用短信作为第二因素的系统的弱点，通过克隆手机或重定向通过 VoIP 系统发送的短信来实施。能够通过感染手机等类似技术窃取并快速使用第二因素的定向攻击，将成为攻击者攻破账户越来越必要的手段，因此在不久的将来将出现得更加频繁。

### 一次性密码

第二因素的常见实现方式是使用**一次性密码**。一次性密码是打击密码窃取和其他基于密码攻击的重要手段。顾名思义，一次性密码仅可使用一次。攻击者可能获取一次性密码，但无法继续使用它，这意味着暴力破解攻击将不断尝试识别一个不断变化的目标。尽管暴力破解攻击有可能在一次性密码有效期内随机匹配成功，但此类攻击成功的可能性微乎其微，且防止暴力破解的常见控制措施将使这种成功从根本上变得不可能。

一次性密码生成主要有两种模型。第一种是**基于时间的一次性密码（TOTP）**，它使用算法结合当前时间作为代码生成过程的一部分来推导一次性密码。**认证应用程序**（如 Google Authenticator）使用 TOTP，如 图 8.6 所示。该代码在设定的时间段内有效，随后转为下一个基于时间的代码，这意味着即使代码被泄露，也仅在相对较短的时间内有效。

![FIGURE 8.6 Google authenticator showing TOTP code generation](img/c08f006.png)

**图 8.6** Google Authenticator 显示 TOTP 代码生成

图 8.6 展示了 Google Authenticator 的示例，这是一种常见的免费基于应用程序的 TOTP 系统。代码在设定的时间段内有效，由右下角饼图的动画指示，在应用程序中，代码即将过期并被新代码替换时会变红。

另一种一次性密码生成模型是**基于 HMAC 的一次性密码（HOTP）**。HMAC 代表基于哈希的消息认证码。HOTP 使用令牌或 HOTP 代码生成应用程序与验证服务器共同使用的种子值，以及一个移动因子。对于按按钮工作的 HOTP 令牌，移动因子是一个计数器，该计数器也存储在令牌和服务器上。如图 8-7 所示的 PayPal 令牌等 HOTP 密码生成器，依赖按下按钮等事件来触发生成代码。由于代码是迭代的，可以从令牌最后一次已知使用时开始检查，向前迭代直到找到当前按下对应的代码。与 TOTP 解决方案一样，认证应用程序也可以实现 HOTP，其工作方式与硬件令牌实现相同。

![FIGURE 8.7 An HOTP PayPal token](img/c08f007.png)

**图 8.7** HOTP PayPal 令牌

除了应用程序和硬件令牌外，一次性密码系统的第三种常见实现是使用基于**短消息服务（SMS）**（即短信）的代码。在该模型中，当用户尝试进行身份验证时，会向其手机发送一条短信，然后他们输入该代码作为身份验证过程的额外因素。

在硬件令牌、软件令牌和短信均不适用的情况下，一些组织会实施基于电话呼叫的**推送通知**。推送通知是发送给用户以告知其事件（在本例中为身份验证尝试）的消息。如果用户通过按下键盘上的特定按钮等请求验证方式回应电话，则身份验证可以继续进行。电话呼叫作为身份验证因素存在诸多问题，包括速度较低（可能导致登录超时问题）、通过多种方式被劫持呼叫的可能性，以及因通话费用给实施组织带来的额外成本。

虽然按需动态生成的一次性密码更为常见，但有时也需要一种不需要设备或连接的一次性密码。在这种情况下，`static codes`（静态代码）仍然是一个有用的选项。静态代码与其他一次性密码一样也是通过算法生成的，但它们是预先生成的，通常打印出来或存储在安全的位置。这创造了一种新的风险模型：即打印它们的纸张可能被盗，或者如果它们是电子存储的，存储它们的文件可能会丢失或被访问。这相当于丢失了一个按键激活的令牌或一部未锁定的智能手机，因此如果静态代码没有得到妥善保管，它们可能会很危险。

### 生物特征

生物特征因素是“你是谁”因素的一个例子，它们依赖用户独特的生理特征来验证其身份。某些生物特征技术也算作 Security+ 考试大纲中描述的因素之一，因为它们属于“你表现出的东西”，如声纹或步态。一些最常见的生物特征技术包括以下内容：

*   `Fingerprints`（指纹），使用光学、超声波或电容式扫描仪检查指尖上脊和谷的独特模式。指纹扫描已在 Windows 中广泛部署（使用笔记本电脑上的指纹扫描仪），以及使用指纹读取器的 Android 和 Apple 设备中。
*   `Retina scanning`（视网膜扫描）利用视网膜中血管的独特模式来区分用户。
*   `Iris recognition`（虹膜识别）系统使用模式识别和红外成像来唯一识别个人的眼睛。虹膜识别可以比视网膜扫描在更远的距离完成，使其在许多情况下更受青睐。
*   `Facial recognition`（面部识别）技术将特定特征与数据库中的原始图像进行匹配。面部识别广泛用于 Apple iPhone 的 FaceID，使其成为一种广泛部署的生物特征技术。
*   `Voice recognition`（语音识别）系统依靠用户声音本身的模式、节奏和声音来识别用户。
*   `Vein recognition`（静脉识别），有时称为静脉匹配或血管技术，使用可以看到静脉模式的扫描仪，通常是用户手指的静脉。与指纹扫描仪不同，静脉扫描仪不需要接触用户，因此不太可能受到污垢或皮肤状况等因素的影响。
*   `Gait analysis`（步态分析）通过测量一个人的行走方式来识别他们。

生物特征技术基于四个主要指标进行评估。第一是 I 类错误，即 `false rejection`（误拒）率（FRR）。误拒错误意味着提交了合法的生物特征度量，但系统拒绝了它。II 类错误，或 `false acceptance`（误纳）错误，以误纳率（FAR）来衡量。当提交生物特征因素并被接受（但本不该被接受）时，就会发生这些错误。这些通过一种称为 `relative operating characteristic (ROC)`（相对工作特征曲线）的指标进行比较。ROC 将系统的 FRR 与 FAR 进行比较，通常以图表形式呈现。对于大多数系统，随着降低误拒的可能性，误纳率会增加，确定系统准确性应设置在何处以最小化误纳并防止误拒，是生物特征系统配置中的一个重要要素。

### 基于知识的认证
