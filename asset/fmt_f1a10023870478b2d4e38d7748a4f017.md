
数据收集到仓库后，使用`数据挖掘`来搜索模式。常见的模式包括欺诈迹象。信用卡公司管理着世界上一些最大的数据仓库，每年跟踪数十亿笔交易。欺诈交易是导致信用卡公司每年损失数百万美元收入的主要问题。没有人能监控所有这些交易，因此信用卡公司使用数据挖掘将信号与噪音分离。一个常见的数据挖掘欺诈规则监控一张卡在短时间内在不同州或国家发生的多笔购买。发生这种情况时，会生成违规记录，导致卡片被暂停或向持卡人家中打电话。

## 面向对象设计与编程

面向对象设计与编程使用对象隐喻来设计和编写计算机程序。我们的身体由独立运行并相互通信的对象组成。我们的眼睛是独立的器官（对象），接收光输入，向大脑发送神经冲动输出。我们的心脏从静脉接收脱氧血、从肺部接收氧气，向动脉输送含氧血。许多器官可以被替换：患病的肝脏可以被健康的肝脏替换。`面向对象编程`（OOP）在计算机程序中复制对象的使用。`面向对象设计`（OOD）将对象视为一种高层设计概念，类似于流程图。

### 面向对象编程 (OOP)

面向对象编程（OOP）改变了旧的结构化编程方法，将程序视为一系列通过消息通信的连接对象。面向对象编程试图模拟现实世界。OOP 语言的例子包括 `Java`、`C++`、`Smalltalk` 和 `Ruby`。

对象是一个能够执行功能、发送和接收消息的“黑盒”。对象包含数据和`方法`（它们执行的函数）。对象提供`封装`（也称为`数据隐藏`）：从外部我们不知道对象如何执行其功能。这提供了安全效益：用户不应暴露于不必要的细节。把水槽想象成一个功能是洗手的对象。输入消息是清水；输出消息是脏水。你不需要知道也不关心水从哪里来、流向哪里。如果你在考虑这些问题，水槽可能坏了。

#### 面向对象编程基石概念

面向对象编程的基石概念包括对象、方法、消息、继承、委托、多态和多实例化。我们将使用一个名为“Addy”的示例对象来说明这些基石概念。Addy 是一个将两个整数相加的对象；它是一个极其简单的对象，但具有足够的复杂性来解释核心 OOP 概念。Addy 从其`父类`（该类称为数学运算符）`继承`了对数字和数学的理解。一个具体的对象称为`实例`。注意，对象除了可以从类继承外，还可以从其他对象继承。

#### 耦合与内聚

耦合和内聚是描述对象的两个概念。高度耦合的对象（如 `Addy`）需要大量其他对象来执行基本任务，如数学运算。高内聚的对象则更加独立：它可以独立执行大多数功能。高耦合的对象具有低内聚，反之亦然：低耦合的对象具有高内聚。

`Addy` 高度耦合且内聚性低：他必须委派任何不包含 `+` 的消息。想象另一个名为 `Calculator` 的对象，它可以进行加、减、乘、除、开平方、指数运算等。`Calculator` 将具有高内聚和低耦合。

#### 举例学习：通过对象管理风险

对象设计为可重用：这降低了开发成本。对象也可以降低风险。就像强加密（如 `AES`）一样，一个对象在安全使用中存在的时间越长，我们就越有把握认为该对象是真正安全的。像加密算法一样，随着时间的推移，无数次攻击都证明是不成功的，该对象展示了其现实世界中的强度。

假设贵公司过去 5 年一直在网上销售信息安全书籍。您的网站允许用户选择一本书，例如 W. Richard Stevens 编写的 *TCP/IP Illustrated*，并输入他们的姓名、地址和信用卡账单信息。信用卡交易风险很大：风险包括客户 PII 的泄露，以及信用卡欺诈风险；被盗卡被用于欺诈性购买书籍。

该网站使用面向对象语言编程。它包含一个名为 `CCValidate` 的信用卡处理对象，最早编写于 5 年前。输入消息是客户输入的信用卡号和有效期。输出消息是二元的：“批准”或“拒绝”。

`CCValidate` 对象隐藏了在输入信用卡号和有效期后，后台发生的复杂性。它执行以下方法：

1.  该对象拥有用于信用卡号的变量缓冲区，可执行边界检查。
2.  该对象确保输入消息长度适当，且每个字段包含适当类型的字符。
    a.  以 `MasterCard®` 为例，为 16 位数字（信用卡号），后跟日期（两位数月份后跟四位数年份）。
    b.  任何不符合这些标准的输入消息将被立即拒绝。
3.  该对象确保有效期在将来。
    a.  任何不符合此标准的输入消息将被立即拒绝。
4.  该对象随后评估所输入信用卡号中的格式和自校验数字。
    a.  有效的 `MasterCard®` 号以 51–55 开头，且为 16 位数字。
    b.  它们还必须包含适当的自校验数字。
        i.  详见 [`web.eecs.umich.edu/~bartlett/credit_card_number.xhtml`](http://web.eecs.umich.edu/~bartlett/credit_card_number.xhtml)
    c.  任何不符合这些标准的输入消息将被立即拒绝。
5.  该对象随后向相应的信用卡公司服务器发送消息，检查该卡是否有效且余额足以进行购买。
    a.  信用卡公司发回“接受”或“拒绝”的返回消息，信用卡对象将其作为消息发送给 Web 服务器。

随着 `CCValidate` 的使用，可能会发现并修复 Bug。可能会确定并编码改进。随着时间的推移，对象逐渐成熟，只需完成其工作即可。它在互联网上遭受攻击；攻击者发起缓冲区溢出攻击并插入垃圾数字，但该对象表现出色。

如果新网站上线，程序员不应从头创建新的信用卡验证对象：重复造轮子风险太大。他们应通过定位并使用经受住时间考验的成熟对象来管理风险：`CCValidate`。

### 对象请求代理

正如我们之前所见，成熟对象设计为可重用：它们降低风险和开发成本。`对象请求代理`（ORB）可用于定位对象：它们充当对象搜索引擎。ORB 是`中间件`：它们将程序连接到程序。常见的对象代理包括 `COM`、`DCOM` 和 `CORBA`。

#### COM 和 DCOM

微软的两种对象代理技术是 `COM`（`组件对象模型`）和 `DCOM`（`分布式组件对象模型`）。`COM` 定位本地系统上的对象；`DCOM` 还可以通过网络定位对象。

`COM` 允许用不同 OOP 语言编写的对象进行通信，例如，用 `C++` 编写的对象向用 `Java` 编写的对象发送消息。它旨在隐藏任何单个对象的细节，并专注于对象的能力。`COM+` 是 `COM` 的扩展，在 Microsoft Windows 2000 中引入。`ActiveX` 在第 4 章，领域 3：安全架构与工程中讨论。

`DCOM` 是 `COM` 的网络化续作。`DCOM` 包含`对象链接与嵌入`（OLE），一种将文档链接到其他文档的方式。

`COM` 和 `DCOM` 正逐渐被 `Microsoft.NET` 取代，后者可以与 `DCOM` 互操作，但为 `COM` 和 `DCOM` 都提供了高级功能。

#### CORBA

`公共对象请求代理体系结构`（CORBA）是由对象管理组（OMG）制定的开放、厂商中立、网络化的对象代理框架。`CORBA` 与微软专有的 `DCOM` 竞争。`CORBA` 对象通过消息接口进行通信，由`接口定义语言`（IDL）描述。有关 `CORBA` 的更多信息，请参见 [`www.corba.org`](http://www.corba.org)。

CORBA 的本质不仅在于作为网络对象代理，更在于将接口（与对象通信的语法）与实例（特定对象）相分离：“每个对象的接口都有非常严格的定义。相反，对象的实现——其运行代码及其数据——被隐藏在系统的其余部分之外（即封装），位于客户端不可跨越的边界之后。客户端只能通过其公开的接口访问对象，仅能调用对象通过其 `IDL` 接口暴露的操作，且仅限于调用中包含的那些参数（输入和输出）”[\[27\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0140)。

除了通过网络定位对象外，CORBA 还强制执行基本的面向对象设计：底层细节对客户端封装（隐藏）。对象在不透露实现方式的情况下执行其方法。实现者专注于连接，而非代码。

### 面向对象分析（OOA）与面向对象设计（OOD）

**面向对象分析**（OOA）和**面向对象设计**（OOD）是软件设计方法论，它们将对象的概念提升到比面向对象编程（OOP）更高、更概念化的层面。这两个术语有时合称为面向对象分析与设计（OOAD）。

这就像在白板上绘制流程图，展示程序在概念上应如何运行。程序中数据的流动和操作方式被可视化为一系列消息和对象。软件设计完成后，代码可使用 `Ruby` 等面向对象编程语言编写。

面向对象分析（OOA）旨在理解（分析）**问题域**（你试图解决的挑战），并识别所有对象及其交互。面向对象设计（OOD）则开发（设计）解决方案。

我们将使用面向对象分析与设计来设计一个网络入侵检测系统（NIDS）。正如我们在第 8 章“领域 7：安全运营”中所学，NIDS 执行以下操作：

1.  从网络嗅探数据包并将其转换为 `pcap`（数据包捕获）格式；
2.  分析数据包中的攻击迹象，这可能包括拒绝服务、客户端攻击、服务端攻击、Web 应用攻击及其他；
3.  如果发现恶意攻击，NIDS 发送警报。NIDS 可通过电子邮件、寻呼、`syslog` 或安全信息和事件管理器（SIEM）发送警报。

上述步骤构成了我们面向对象分析的基础。嗅探器对象以数据包形式接收来自网络的消息。嗅探器将数据包转换为 `pcap`（数据包捕获）数据，并将其发送给分析对象。分析对象执行多项功能（方法），包括检测拒绝服务、客户端、服务端或 Web 应用攻击。如果检测到任何攻击，它会向警报对象发送警报消息。警报对象也可执行多项功能，包括通过电子邮件、寻呼、`syslog` 或 SIEM 进行告警。NIDS 面向对象设计如图 9.12 所示。

## 评估软件安全的有效性

项目启动且软件编程完成后，接下来的步骤是测试软件，重点关注系统、应用程序及应用程序处理的数据的机密性、完整性和可用性。必须特别注意发现可能导致数据或系统泄露的软件漏洞。最后，组织需要能够衡量其软件创建过程的有效性，并找出改进方法。

### 软件漏洞

程序员会犯错：自计算机编程诞生以来，这始终是真理。在《代码大全》中，Steve McConnell 表示，“经验表明，每 1000 行交付代码中会有 15–50 个错误”[\[28\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0145)。一千行代码有时称为 `KLOC`；“K”代表千。遵循正式的应用成熟度框架模型可以降低这一数字。卡内基梅隆大学软件工程研究院研究员 Watts S. Humphrey 声称，遵循 SEI 能力成熟度模型集成（CMMI，见下文“软件能力成熟度模型集成 (CMMI)”一节）的组织，可将错误数量降低到每 `KLOC` 一个[\[29\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0150)。

即使每千行代码仅有一个错误，随着软件日益复杂，也会引入巨大的安全风险。以 Microsoft Windows 为例：“因此，Windows 的每个新版本都背负着其过去的包袱。随着 Windows 的增长，技术挑战变得日益艰巨。数千名工程师辛勤工作以构建和测试 Windows Vista，这是一个庞大、复杂的软件建设项目，拥有 5000 万行代码，比 Windows XP 大 40% 以上”[\[30\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0155)。请注意，Microsoft 尚未发布其近期操作系统（包括 Windows 11 和 Server 2022）的代码行数。

如果 Microsoft Vista 的程序员每 `KLOC` 仅犯一个错误，那么 Vista 将有 50,000 个错误。大型软件项目凸显了对稳健且系统化的软件测试方法的需求。

#### 软件漏洞类型

本节将简要描述常见的应用程序漏洞。请同时参阅第 4 章“领域 3：安全架构与工程”中的“系统漏洞、威胁和对策”部分，以了解其他漏洞类型的信息。最新的漏洞信息可参考“CWE Top 25 Most Dangerous Software Weaknesses”（CWE 25 个最危险的软件弱点），网址为 <https://cwe.mitre.org/top25/archive/2021/2021_cwe_top25.xhtml>；以下摘要基于此列表。`CWE` 指通用弱点枚举，是 MITRE 维护的软件漏洞字典（见 <https://cwe.mitre.org/>）。

*   **越界写入**（又称缓冲区溢出，发生在程序员未执行变量边界检查时）
*   **跨站脚本**（Web 页面生成过程中对输入的不当中和）
*   **越界读取**（读取缓冲区末尾之后的数据）
*   **输入验证不当**
*   **操作系统命令注入**
*   **SQL 注入**：通过前端 Web 服务器操纵后端 SQL 服务器
*   **跨站请求伪造 (CSRF)**
*   **目录路径遍历**：通过引用 `../..` 等目录，从 Web 服务器根目录（如 `/var/www`）逃逸到常规文件系统[\[31\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0160)

##### 缓冲区溢出

当程序员未执行边界检查时，会发生**缓冲区溢出**。以下是“输入用户名”程序的伪代码。该程序声明 `$username` 变量长度为 20 个字符，打印“Enter Username:”，然后将用户输入存储在 `$username` 变量中：

```
variable $username[20]
print “Enter Username:”
getstring($username)
```

此函数包含缓冲区溢出。程序员声明 `$variable` 长度为 20 字节，但未对 `getstring` 函数执行边界检查。程序员假设用户会输入类似“bob”的内容。

如果攻击者输入 50 个“A”：

```
AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA
```

答案是：许多编程语言（如 C 语言）不提供内置的边界检查：前 20 个字节将被复制到为 `$username` 变量分配的内存中。接下来的 30 个字节将覆盖内存中接下来的 30 个字节。这些内存可能包含其他数据或指令。这被称为“栈溢出”。这种技术可用于插入并运行 Shellcode（执行 Shell 的机器码语言，例如 Microsoft Windows 的 `cmd.exe` 或 UNIX/Linux Shell）。

缓冲区溢出可通过安全的应用程序开发来缓解，包括边界检查。

##### TOCTOU/竞争条件

`检查时间/使用时间`（TOCTOU）攻击也称为`竞争条件`：攻击者试图在操作系统检查完某个条件后、但在使用该条件前，对其进行篡改。TOCTOU 是状态攻击的一个例子，攻击者利用操作系统状态的变化进行攻击。

下面是一个名为“打开测试文件”的 setuid root 程序（以超级用户权限运行，无论运行用户是谁）的伪代码，该程序包含一个竞争条件：

1.  如果文件“test”可被用户读取
2.  则打开文件“test”
3.  否则打印“错误：无法打开文件。”

竞争条件发生在第 1 步和第 2 步之间。请记住，大多数现代计算机都是多任务处理的：CPU 同时执行多个进程。当我们的“打开测试文件”程序运行时，其他进程也在运行。换句话说，计算机可能会这样运行我们的程序：

1.  如果文件“test”可被用户读取
2.  运行另一个进程
3.  运行另一个进程
4.  然后打开文件“test”
