
```
update tablename
set colname = expression   [, …]
[where condition]
```

例如，考虑表模式 `Employee` (empNr, …, job, salary)。以下语句给所有薪资低于 50,000 美元的建模师增加 5% 的薪资：

```
update Employee
set salary = salary * 1.05
where job = ‘Modeler’
and salary < 50000
```

由于 `insert`、`delete` 和 `update` 命令具有批量更新的能力，因此拥有用于撤销（回滚）和安全性（例如，授予相关访问权限）的工具至关重要。

## 12.14 总结

关系模型的数据操纵方面包括关系代数和关系赋值（`:=`）。除了在表达条件时使用逻辑和比较运算符外，代数还包括九种基本表操作。比较运算符优先于逻辑运算符，逻辑运算符优先于表运算符。

表 12.3 列出了运算符的六个优先级：`=`、`<>`、`<`、`>`、`<=`、`>=`；`not`；`and`；`or`；选择（`where` …）和投影（`[ ]`）；最后是 `union` ∪、`intersection` ∩、`difference` −（在 SQL 中称为 `except`）、`Cartesian product` ⨉、`natural join` ⨝ 和 `division` ÷。括号可用于覆盖此顺序。学术期刊中常用的符号显示在左侧，我们的符号显示在右侧。

*   `σc ≡ T where c`
*   `πa,b,… ≡ T [a,b,…]`
*   `A ⨝[c] B ≡ (A ⨉ B) where c`

同一优先级上的运算符具有左结合性（按其在表达式中出现的顺序从左到右求值）。我们的优先级约定旨在尽量减少括号的使用，且比其他一些正在使用的约定更强。如果有疑问，或者纯粹为了清晰起见，请随意添加额外的括号。

`关系型 DBMS` 以关系表作为其唯一的基本数据结构，并支持关系选择、投影和连接，而无需指定访问路径。

SQL 是关系型 DBMS 中使用的主导语言，多年来各个版本已被标准化，最新的是 SQL:2023。大多数商业 SQL 方言支持所有 SQL-89 功能、SQL-92 和 SQL:1999 中部分额外功能，以及它们自己的一些特殊功能。

数据库对象（如表和列）可以使用标准标识符或分隔标识符（允许双引号内包含任意字符）来命名。数据库字段可以用预定义数据类型（例如 `varchar(20)`）来定义。SQL:1999 增加了用户定义类型、行类型、引用类型和数组。SQL:2003 增加了对 `multiset`（包）作为集合类型的支持，以及 `bigint` 和 `xml` 数据类型。

SQL:2016 增加了对行模式匹配、多态表函数以及存储在字符字符串字段中的 JSON 数据操作的支持。SQL:2019 增加了对多维数组（MDarray 类型和运算符）的支持。

SQL:2023 ([`www.iso.org/standard/76584.html`](https://www.iso.org/standard/76584.html)) 修订版增加了许多可选功能（唯一约束中的空值、字符串填充函数等）、对 JSON 的更深层支持，以及对属性图查询（SQL/PGQ）的支持。

用于查询的 SQL `select` 语句具有以下基本语法。

```
select [all | distinct] * | expression [[as] column-alias ] [,…]
from table [[as] alias]
[, | cross join table [[as] alias]
| natural [inner | {left | right | full} [outer]] join table [[as] alias]
| [inner | {left | right | full} [outer]] join table [[as] alias]
{ on condition | using (col-list) }
| union join table [[as] alias]
[,...]]
[where col-condition]
[group by colname [,...]
[having group-condition]]
[union | intersect | except ...]
[order by col [asc | desc] [,...] ]
```

`select` 列表选择结果列，`from` 子句声明源表和连接，`where` 子句用于筛选行，`group by` 子句形成行组，`having` 子句用于筛选组，而 `order by` 子句决定行的顺序。

*子查询* 是外部查询内部的一个带括号的 `select` 查询。如果子查询包含引用外部查询的条件，则它是一个 *相关* 子查询。`exists` 量词后面的子查询是存在性子查询。如果子查询返回一行，则 `exists` 条件为真，否则为假。带有嵌入式子查询的条件最常见的三种形式如下所示，其中 Θ 是比较运算符。

*   ```
    expression [not] in (subquery)                                            - - 成员资格子查询
    ```

*   ```
    expression Θ [all | some | any] (subquery)         - - [量化] 比较子查询
    ```

*   ```
    exists (subquery)                                                                                - - 存在性子查询
    ```

## 13.1 SQL：整体概览

在上一章中，我们介绍了用于检索数据（`select`…）和修改数据（`insert`…、`update`…、`delete`…）的结构化查询语言（SQL）语句。这组语句传统上称为*数据操作语言*（DML）。现在我们将关注 SQL 的其他方面。我们将介绍用于定义数据库模式各种元素的语句，这些语句使用 SQL 的一个子集，传统上称为*数据定义语言*（DDL）。

表当然是任何模式的基础，但我们还将讨论其他几种数据库对象及其在概念模式实现中的作用。特别是*视图*（views）和*触发器*（triggers）等数据库对象常用于实现最初可能在概念层面定义的约束和派生规则。

可扩展标记语言（XML）的广泛采用主要得益于其在结构化数据交换中的应用。然而，这也产生了关系数据与 XML 数据之间更好集成的相应需求。后续章节将讨论 SQL 标准如何被调整和扩展以增加 XML 相关功能，以及非 SQL 数据操作（如 XQuery）如何在关系框架中得到支持。

## 13.2 SQL：定义表

### 创建表

*基表*（base table）的数据驻留在数据库中（这与结果表和视图不同，我们稍后将介绍）。基表必须在填充数据前创建。从 SQL-92 开始，基表（及数据库的其他方面）是在使用 `create schema` 语句创建的*数据库模式*（database schema）的作用域内定义的。模式可使用 `drop schema` 语句删除。商业 SQL 通常提供不同的语法来创建新数据库（例如 `create database`）。

在 SQL 标准中，表是使用 `create table` 语句创建的。此外，大多数数据库管理系统（DBMS）还提供图形界面，供用户通过输入文本和选择选项来创建表。表定义的主要部分是列列表，标识每列的列名、数据类型，以及该列是否禁止 *nulls*（即该列是否为强制列）。也可为某些列声明约束。

SQL-89 `create table` 语句的语法可概括如下。此处，*literal* 表示数字或字符串常量，*col-list* 表示用逗号分隔的一个或多个列名列表，*unique-col-list* 表示已集体声明为主键或唯一键的列列表。如果约束适用于单个列，可在列定义末尾声明。多列约束必须在表定义末尾声明。**Check** 子句仅限于涉及表中单行的条件。
