
虽然许多商业 SQL 方言（如 SQL Server）支持标准的 `upper` 和 `lower` 字符串函数，但某些方言提供了控制字符串常量大小写敏感性的其他方法。

图 12.35 中的示例演示了三个新特性。表模式 `Actor` (surname, firstname, gender) 的样本数据包含姓氏 “D’Abot”，其中包含单引号作为其字符之一。如前所述，字符串常量由单引号限定。要在这样的字符串中嵌入单引号，我们需要通知 SQL 该引号是字符串的一部分，而不是结束它。为此，我们使用两个相邻的单引号来表示嵌入的单引号。

![Fig. 12.35 Two single quotes embed a single quote, and “as” introduces an alias.](img/f12-35-9780443237904.jpg)

Fig. 12.35 两个单引号嵌入一个单引号，“as”引入一个别名。

以下 `insert` 语句可用于将第二行数据添加到表中：`insert into Actor values (‘D”Abot’, ‘Maryam’, ‘F’)`。请注意，这在“D”Abot”中使用了两个单引号。虽然查询时可能仅显示为“D’Abot”，但在 SQL 语句中使用该值时，我们必须使用两个单引号。例如，请注意搜索条件：`surname = ‘D”Abot’`。

关于该查询要注意的第二点是，我们可以将常量作为 `select` 项包含在内。此处 `select` 列表包含字符串常量“This isn”t hard”。请再次注意使用两个单引号来嵌入单引号。包含在 `select` 列表中作为项目的任何常量都将包含在查询返回的每一行中。在本例中，返回了两行。

该示例说明的第三个方面是，关键字 `as` 可用于为 `select` 项引入别名。该别名将作为结果表中该项列的名称出现。示例为添加到 `select` 列表中的字符串常量引入了别名“comment”。在实践中，`select` 项的别名主要用于为更复杂的表达式提供简单的名称，稍后将讨论这一点。

搜索条件可能包含项、比较运算符 (`=`, `<>`, `<`, `>`, `<=`, `>=`) 和逻辑运算符 (`not`, `and`, `or`)。某些 SQL 方言允许使用“<>”以外的符号表示“不等于”（例如，“ˆ=”、“!=”）。SQL Server 还包含用于“不小于”的“!<”和用于“不大于”的“!>”，它们分别等同于“>=”和“<=”。为保证可移植性，应避免使用此类非标准符号。采用与关系代数相同的优先级约定。因此，除非括号另有规定，否则先计算比较运算符，再计算逻辑运算符，逻辑运算符按 `not`、`and`、`or` 的顺序计算。

涉及空值时，SQL 基于三值逻辑运行。条件的求值结果可能为真、假或未知。更准确地说，条件是“已知为真”、“已知为假”或“未知”。项之间的比较，如果其中一项为空，则求值结果始终为未知。这适用于任何比较运算符（`=`, `<>`, `<` 等）。请看员工 1002 那一行，`carType` 记录了空值（此处显示为“？”）。对于 Fig. 12.37(a) 中的查询，条件为“null = Ford”；对于 Fig. 12.37(b) 中的查询，条件为“null <> Ford”。在这两种情况下，条件求值结果均为未知。

`where` 子句执行的选择操作仅返回求值为真（即已知为真）的行。求值为假或未知的行将被过滤掉。因此，员工 1002 和 1005（Jones 和 Dennis）的行在两个查询中均被过滤掉。过滤掉未知值有助于避免无根据的假设。稍后将讨论，SQL 提供了用于检测空值的特殊函数。

现在，让我们讨论如何控制结果表中列和行的排序。列按其在 `select` 列表中出现的顺序显示。因此，如果想要不同的列顺序，只需重新排列 `select` 列表即可。但是，显示行的顺序可以通过 `order by` 子句来控制。如果使用，`order by` 子句必须位于 `select` 语句的末尾。`select` 列表中的一个或多个列（按名称或按在 `select` 列表中的位置标识）可用作排序标准。

排序默认为升序。你也可以通过在列标识符后附加 `asc` 来显式指定升序。要指定降序，必须附加 `desc`。对于数值，“升序”意味着较小的数字排在前面。例如，1 < 3 < 7，因此 1、3、7 为升序。对于字符串值，“升序”意味着在排序序列中靠前的字符串排在前面。粗略地说，按字母顺序靠前的单词通常排在前面。

作为一个简单示例，Fig. 12.38 中的每个查询均可用于按员工姓名的字母顺序列出员工。虽然极不推荐，但此处 `order by` 子句中可以用“2”代替“empName”，因为 `empName` 是 `select` 列表中的第二项（它不必是基表的第二列）。如果稍后修改 `select` 列表，这种位置编号的用法会造成问题，使查询更难理解，并且是 SQL 标准中已弃用的特性（即可能在后续版本中移除）。因为如果需要，可以使用 `as` 来引入结果列名，所以永远不需要求助于位置编号进行排序。因此不要使用它们。

![Fig. 12.38 Listing employees in ascending order of employee names.](img/f12-38-9780443237904.jpg)

Fig. 12.38 按员工姓名升序列出员工。

字符串按字符排序序列进行排序。例如，如果使用 ASCII，则空格（“ ”）排在数字（0..9）之前，数字排在大写字母（A..Z）之前，大写字母排在小写字母（a..z）之前。例如，在 ASCII 中，“M2” < “MY” < “Ma” < “Ma Kettle” < “MacTavish” < “Zen” < “apple”。不过，其他排序序列可能与此不同。例如，在 EBCDIC 中，小写字母排在大写字母之前，大写字母排在数字之前。

`order by` 子句可被视为将一组行转换为行序列的一种方式。就排序而言，空值被视为相等，并且根据实现的不同，要么小于所有非空值（如 SQL Server），要么大于所有非空值。请看以下查询：

```
select carType from Employee order by carType
```

这将返回序列“Ford”、“Ford”、“Toyota”，前面或后面跟着两个 null 值，具体取决于实现。

如果所选的排序列没有唯一性约束，则可以通过在 `order by` 子句中指定更多列，在其重复值内获得进一步的排序。`order by` 子句中列在前面的标准优先排序。对于任何特定列，均可应用升序或降序选项。例如，形式如下的查询：

```
select * from T order by a, b desc
```

首先按 `a` 的升序对行进行排序，然后将具有相同 `a` 值的每组行按 `b` 的降序排序。例如，请参见 图 12.39。这里女性排在前面，因为“F” < “M”，并且在每个性别内，姓名按字母逆序显示。

![图 12.39 依据两个标准排序。](img/f12-39-9780443237904.jpg)

图 12.39 依据两个标准排序。

请注意在 图 12.39 中，`desc` 具有最小后向作用域，仅适用于 `firstname`，而不适用于 `gender`。如果两者都需要降序，我们将使用 `gender desc`、`firstname desc`。如果 `order by` 列表中的某项未用 `asc` 或 `desc` 选项限定，则默认始终假定为 `asc`。因此，要按性别升序然后姓名升序列出，我们可以只使用 `gender`、`firstname`，因为这被视为 `gender asc`、`firstname asc` 的缩写。要测试您的理解，请看看能否预测 图 12.40 中查询的结果，然后对照所示表格核对您的答案。

您答对了吗？这些行首先按 `starsign` 升序排序，因为 `starsign` 后假定为 `asc`（见第 1 列）。然后，作为第二标准，与女性具有相同 `starsign` 的男性排在该女性之前（见第 1、2 行），因为这是按 `gender` 降序。最后，对于具有相同 `starsign` 和 `gender` 的人，年龄较大者（按 `birthyr` 升序作为第三标准）排在前面（见第 3、4 行）。`order by` 子句可通过包含隐含的排序选项来显式指定：

```
order by starsign asc, gender desc, birthyr asc
```

让我们用术语 `colname` 表示列名，用 `col` 表示列规范（按名称或编号）。迄今为止所涉及的 `select` 语句的那部分语法可用 EBNF 概括如下。虽然列别名可以在 `select` 项后立即引入而无需使用 `as`，但最好在这类情况下包含 `as`，因为这有助于可读性。

```
select [all | distinct] * | colname | constant [[as] column-alias] [,...] from tablename where condition order by col [asc | desc] [,...]
```

## 12.6 SQL：连接

我们已经了解了如何从单个表中选择和排序列与行。但假设我们从单个查询中所需的信息分散在许多表中。SQL 提供了两种主要方法来访问此类信息。第一种使用关系连接，将在本节中讨论。第二种涉及子查询，将在后面的章节中介绍。

表的交叉连接（笛卡尔积）将一个表的所有行与另一个表的所有行进行配对。在 SQL-89 中，通过在 `from` 子句中列出表，使用逗号 “,” 作为笛卡尔积运算符（关系代数中的 ⨉）来指定交叉连接。条件连接（Θ-连接）仅从笛卡尔积中选择满足指定条件的那些行。在 SQL-89 中，条件在 `where` 子句中指定。因此，表 12.7 中的查询表达式是等价的。
