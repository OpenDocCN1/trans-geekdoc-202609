
- **密钥长度** 请了解密钥长度越大，加密强度越高。例如，`256-bit AES` 加密比 `128-bit AES` 加密更强。

- **弱密钥** 使用弱加密密钥会使加密容易受到攻击。使用具有尽可能最大密钥长度的加密标准可降低密钥被破解的风险。

- **时间** 请了解不同加密类型在加密和解密大量数据时所需时间不同。例如，使用对称加密加密大文件所需时间比非对称加密少。

- **寿命** 了解加密协议或应用程序的预期寿命非常重要。您不希望投资一种技术，结果在实施后不久就不再被接受。

- **可预测性** 使用难以预测技术所用随机值的技术。例如，使用可预测的 `IVs`（初始化向量）可能会给正在加密的数据隐私带来风险。

- **重用** 重用密钥可能会给您的环境带来安全风险，因为这有助于攻击者破解加密密钥。

- **熵** 熵是加密应用程序用来加密数据的关于系统的随机信息。无法生成良好熵的应用程序可能容易受到攻击者解密数据的威胁。

- **计算开销** 加密算法越先进，系统所需的处理能力就越强。您可以使用 `GPU` 来处理强加密应用程序的计算开销。

- **资源与安全约束** 这与计算开销相关，加密算法和密钥长度越强，使用的资源（内存和处理器）就越多。在获得良好安全性和不使系统过载之间找到平衡非常重要。

## 加密数据

如果您想确保公司信息不被未授权人员查看，就需要对数据进行加密。在考虑加密数据时，请考虑加密以下内容：

- **传输中数据** 对数据在从源头传输到目的地的网络传输过程中进行加密，这样如果有人窃听通信，将无法读取数据。您将在本章后面了解通信加密协议。

- **静态数据** 当在磁盘或数据库中存储信息时，对数据进行加密，这样如果有人访问了驱动器或数据库，就无法查看敏感数据。

- **使用中数据** 对存储在 `RAM`、`CPU 缓存` 甚至 `CPU 寄存器` 中的数据进行加密。目的是确保没有人能通过编写代码从这些区域检索数据来访问敏感数据。

让我们在此专注于存储中的数据，并回顾一下您在 第 7 章 中学到的一些关键点。作为复习，您可以使用以下任何成熟技术来加密存储中的数据：

- **全盘** 当今大多数操作系统都支持全盘加密 (`FDE`)。例如，Windows 拥有 `BitLocker`，它允许您加密整个驱动器的内容（包括操作系统），或加密特定分区。为了完全启动系统，个人需要知道密钥，以便解密加密内容。

- **数据库** 在数据库中存储信息时，加密敏感信息至关重要。例如，如果您的公司有一个存储客户信用卡号甚至客户密码的应用程序，您应该加密数据库中的该数据，因为黑客可能访问数据库并发现这些信息。许多数据库产品允许您加密整个数据库，因此如果攻击者窃取了数据库文件，他们无法读取数据，因为其系统上不存在解密密钥。

- **单个文件** 如果您不加密整个驱动器的内容，则可以加密选定敏感文档的内容。例如，您可以使用 Windows 中的加密文件系统 (`EFS`) 来加密单个文件和文件夹。

- **可移动介质** 如果您将数据存储在可移动驱动器（如闪存驱动器）上，请务必加密该驱动器上的所有公司数据。闪存驱动器太容易丢失或遗忘在某处了，如果数据未加密，任何人都可以读取！

- **移动设备** 大多数移动设备允许您加密移动设备的内容，以便在设备丢失或被盗时，无人能够检索设备上的数据。

## 加密操作：软件与硬件

加密数据时，加密操作既可以由系统上的软件执行，也可以由硬件（安装在系统上的计算机芯片）执行。基于硬件的加密优于软件解决方案，由于计算的复杂性，你会发现硬件解决方案能更快地完成工作。

## 可信平台模块 (TPM)

可信平台模块 (TPM) 是系统上的一个计算机芯片，用于存储加密数据所用的加密密钥。使用密码加密数据的应用程序容易遭受字典攻击；TPM 内置了防字典攻击模块。Windows BitLocker 支持使用 TPM 存储密钥。但请记住，要在系统上使用 TPM，必须拥有支持 TPM 的 BIOS。

## 通过隐匿实现安全

通过隐匿实现安全是一种安全原则，即将技术的设计或实现变得极其复杂，从而使其保持机密。例如，你可以将系统文档写得晦涩难懂，使其无法被完全理解。或者你可以将应用程序或系统的命令设计得晦涩难懂，以至于攻击者需要花费很长时间才能入侵系统，因为他们首先必须学习该系统。我必须强调，**不应将通过隐匿实现安全作为唯一的安全方法！**

## 加密通信

如果你在网络或互联网上发送或接收机密信息，甚至在移动设备上通信时，都要确保通过安全通道进行通信。`安全通道` 是一种已建立的通信对话，它加密对话中系统之间发送的流量。

### 安全通信协议/传输加密

你可能需要加密的常见流量类型包括 Web、电子邮件、Telnet 和 FTP 流量。在设计或评估安全性时，你要确保使用尽可能最安全的通信协议。Security+ 认证考试要求你根据场景了解应实施哪些安全协议。以下是成熟技术或应用程序用于加密传输中通信（网络流量）的常见安全协议：

*   **HTTP Secure (HTTPS)** 不应使用 HTTP（非安全 Web 流量的协议），而应使用 HTTPS，也称为 Secure HTTP (SHTTP)。HTTPS 使用 SSL（下文讨论）来加密客户端与 Web 服务器之间的通信。HTTPS 的一个使用场景或用例是：如果你有一个允许客户更新其个人资料信息的网站，并且希望确保其信息在穿越互联网时经过加密。

*   **安全套接字层 (SSL)/传输层安全性 (TLS)** 多年来，SSL 一直是加密流量（如 Web 和电子邮件流量）的流行协议。TLS 是一种更安全的协议，旨在取代 SSL。SSL 或更新的 TLS 协议可用于加密组织内部服务器之间的通信。你也可以用它来保护组织内部或与合作伙伴公司之间两台电子邮件服务器之间的通信。

*   **安全多用途互联网邮件扩展 (S/MIME)** S/MIME 是网络上用于加密电子邮件消息的协议。例如，S/MIME 可用于加密来自客户端的电子邮件消息。

*   **安全实时传输协议 (SRTP)** 对于使用 RTP 的语音和视频会议应用程序，如果你担心有人捕获你的语音和视频流量并回放，可以实施 SRTP 作为替代协议。它为语音和视频通信提供加密和认证服务。

*   **基于 SSL 的轻量级目录访问协议 (LDAPS)** LDAPS 是一种安全的目录服务访问协议，当安全性是关注点时，应使用它代替 LDAP，因为它加密与目录服务器的所有通信。

*   **域名系统安全扩展 (DNSSEC)** DNSSEC 是 DNS 的一项重要安全协议。DNSSEC 不加密与 DNS 服务器的通信，但确实为 DNS 记录增加了完整性，以便客户端知道 DNS 数据是否被未经授权的人员修改。DNSSEC 通过向每条记录添加包含数据哈希值的数字签名来实现这一点，该哈希值可被验证。

*   **互联网协议安全 (IPSec)** IPSec 是一种流行的安全协议，旨在加密所有 IP 流量，而不管应用程序如何。IPSec 有两种模式：传输模式和隧道模式。使用 `传输模式` 时，仅对数据包的有效载荷（数据部分）进行加密。使用 `隧道模式` 时，对数据包的头部和数据都进行加密。IPSec 对不同的加密服务使用不同的协议：

    *   **认证头 (AH)** 负责 IPSec 中的数据完整性和发送方认证。

    *   **封装安全载荷 (ESP)** 通过加密数据包中的数据（也称为有效载荷）来提供数据完整性、认证和数据机密性。

    IPSec 的一个使用场景是：如果你需要加密所有网络流量，或者可能是加密一组系统之间的所有网络流量。

    ![Image](img/exam.jpg)

    > **考试重点：请记住，AH 提供数据完整性和认证，但不提供数据机密性（加密）。ESP 在 IPSec 中提供数据完整性、认证和数据机密性。**

*   **安全外壳协议 (SSH)** SSH 旨在成为 Telnet 的安全替代品，并提供认证和加密服务。SSH 可用于创建加密通道，以便通过该通道的通信经过加密。SSH 的一个常见使用场景是对交换机和路由器进行远程访问。

*   **FTP Secure (FTPS)** FTP Secure，也称为 FTP-SSL，应作为 FTP 的安全替代品使用，因为它使用 SSL 或 TLS 安全协议加密 FTP 通信。

*   **SSH FTP (SFTP)** SFTP 是 SSH 的扩展，允许通过 SSH 通道安全地传输和管理文件。请注意，这与 FTPS 不同，后者使用 SSL 或 TLS 来保护 FTP 流量。

*   **简单网络管理协议 v3 (SNMPv3)** 与早期版本的 SNMP 相比，应使用此版本，因为它提供认证和通信加密功能。SNMP 用于监控和管理网络上的设备，如路由器和交换机。你应该检查这些设备，并验证它们是否使用 SNMPv3 而不是版本 1 或版本 2。

*   **安全邮局协议/互联网消息访问协议 (安全 POP/IMAP)** 当你有一个位于互联网上的电子邮件客户端，将使用 POP 或 IMAP 连接到公司电子邮件服务器时，这些协议以未加密格式发送数据（包括用户名和密码），你应该考虑使用安全 POP 或安全 IMAP 来加密通信。安全 POP 和安全 IMAP 均使用 TLS 或 SSL 来保护电子邮件通信。

*   **安全复制协议 (SCP)** 与 SFTP 类似，SCP 运行在 SSH 通道之上，以加密用于传输文件的通信。

*   **无线** 你应该使用 WPA2 加密无线通信。

## 安全协议的用例

在许多常见场景中，你应该使用安全协议而非协议的非安全版本。以下列出了一些关键场景：

*   **语音和视频** 如果你的组织使用 VoIP 解决方案，请务必使用 SRTP 加密网络上的语音流量。

*   **时间同步** 许多网络设备（如路由器和防火墙）都具备连接到时间同步服务器以维持设备时间的能力。

### 电子邮件和 Web

如果您在线收集敏感信息，请务必使用 `HTTPS` 而不是 `HTTP`。对于需要加密电子邮件的组织，可以使用 `S/MIME` 进行电子邮件加密。

### 文件传输

通过互联网下载文件时，您需要加密通信以维护机密性——请务必使用 `SFTP` 或 `SCP` 来保护您的文件传输通信。

### 目录服务

访问目录服务（如 `Active Directory`）时，请使用 `LDAPS` 加密客户端与服务器之间的通信。

### 远程访问

当您需要授予用户对网络的远程访问权限时，请寻找用于远程访问的 `VPN` 解决方案，并使用 `SSTP` 或 `L2TP` 等协议来加密 `VPN` 流量。

### 域名解析

在保护 `DNS` 环境方面，请考虑使用 `DNSSEC` 为其增加完整性。如今，黑客入侵您的 `DNS` 环境，然后更改 `DNS` 记录使其指向黑客的系统，这种情况很常见。`DNSSEC` 可以为您的 `DNS` 记录增加完整性。

### 路由和交换

对于您的路由器和交换机，请使用 `SSH` 代替 `Telnet` 进行远程访问；如果您打算在设备上运行 `SNMP`，请使用 `SNMPv3`，因为它是最安全的 `SNMP` 版本。

### 网络地址分配

您可以配置设备在网络上分配 `IP` 地址。请务必仅分配所需数量的地址。

### 订阅服务

许多设备都提供可订阅的服务以增强安全性。例如，您可能可以订阅防病毒服务或 `DDoS` 防护服务。

### 密码套件和完美前向保密

近年来，出现了许多有助于提高安全性并防止针对加密技术攻击的技术。加密技术的一个弱点是使用相同的密钥加密通信；一旦黑客知道了密钥，他们就能破解所有消息。以下安全概念是 `Security+` 考试目标中的新内容，您应该熟悉这些术语：

## 临时密钥

一种临时密钥，通常用于加密通信中的单条消息，而不是使用同一个密钥加密通信中的所有消息。

## 完美前向保密

用于描述一种为每个会话生成随机公钥（临时密钥）的系统，以便在通信过程中进行密钥交换。

## 密钥延伸

也称为密钥强化，这是一种用于确保弱密钥（如密码）不成为暴力攻击受害者的技术。通过密钥延伸，使用特殊算法将弱密码转换为更强的密钥。用于强化密钥的两种常见算法是 `PBKDF2` 和 `Bcrypt`。

*密码套件* 是一组安全算法，用于提供身份验证、加密和消息认证码功能。密码套件用于在 `SSL` 和 `TLS` 通信中协商安全设置。

密码套件中可使用许多不同的算法，按其功能分组如下：

- 密钥交换算法，如 `RSA`、`Diffie-Hellman` 和 `ECDH`

- 身份验证算法，如 `RSA`、`DSA` 和 `ECDSA`

- 加密算法，如 `RC4`、`3DES` 和 `AES`

- 消息认证算法，如 `MD5` 或 `SHA`

请注意，`TLS` 使用的两种密钥协商协议是 `Diffie-Hellman Ephemeral (DHE)` 和 `Elliptic Curve Diffie-Hellman Ephemeral (ECDHE)`。`DHE` 和 `ECDHE` 均旨在为 `TLS` 通信提供完美前向保密。此外，请注意某些密码比其他密码更强，您可以通过所用协议和密钥的位长度来判断。例如，`DES` 是 56 位加密，而 `AES` 是 128 位、256 位或 512 位加密——这意味着 `AES` 比较弱的 `DES` 是更强的密码。

值得注意的是，`Diffie-Hellman (DH)` 使用称为 `DH Groups` 的组来定义密钥交换通信的密钥强度。组号越高越安全，但资源消耗也越大。以下列表列出了部分 `DH Groups`：

- **DH Group 1** 768-bit

- **DH Group 2** 1024-bit

- **DH Group 14** 2048-bit

许多不同的网络设备，如 `WatchGuard` 防火墙和 `Cisco` 设备，允许您指定应使用的 `DH Group`。

## 使用 VPN 保护通信

当公司决定希望通过互联网传输机密信息时，会寻求虚拟专用网络 (`VPN`) 解决方案。`VPN` 旨在在不受信任的网络（如互联网）上建立一条安全（加密）的隧道，用于加密穿越该不受信任网络的流量。

以下是用于保护 `VPN` 流量的三种常见协议：

### 点对点隧道协议 (PPTP)

`PPTP` 是一种较旧的 `VPN` 协议，用于加密 `PPP` 流量，在 Microsoft 环境中很常见。`PPTP` 使用通用路由封装 (`GRE`) 协议传输 `PPP` 数据包，但使用 Microsoft 点对点加密 (`MPPE`) 协议加密流量。要允许 `PPTP` 流量通过防火墙，您需要在防火墙上打开 `TCP` 端口 `1723`（控制端口）和协议 ID `47`（承载数据）。

### 第 2 层隧道协议 (L2TP)

`L2TP` 是一种较新的 `VPN` 协议，使用更安全的 `IPSec` 进行流量加密，而不是 `MPPE`。要允许 `L2TP` 流量通过防火墙，您需要在防火墙上打开 `UDP` 端口 `500`（用于密钥交换）、`UDP` 端口 `5500`（用于 `IPSec NAT`）和 `UDP` 端口 `1701`。

### 安全套接字传输协议 (SSTP)

`SSTP` 是这三种 `VPN` 协议中最新的一种，使用 `SSL` 加密 `VPN` 流量。使用 `SSL` 的 `VPN` 协议的优势在于防火墙上的配置较少；您无需在防火墙上打开端口以允许 `PPTP` 或 `L2TP` 通信，只需在防火墙上打开端口 `443`（`HTTPS` 使用的端口），而这通常已经完成。

## 使用 PGP

一种常用于使用非对称通信加密信息的应用程序是 Pretty Good Privacy (`PGP`)。`PGP` 允许您生成密钥，并通过电子邮件以安全的方式与他人共享您的公钥。

`PGP` 允许您加密电子邮件消息和文件，以及对消息进行数字签名，以便收件人确信消息来自您。

请注意，虽然 `PGP` 已在 `Windows` 平台上使用，但 `GNU` 系统有一个替代品，称为 GNU Privacy Guard (`GnuPG`)，简称 `GPG`。
