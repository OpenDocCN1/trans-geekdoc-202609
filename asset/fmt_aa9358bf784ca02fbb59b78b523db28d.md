
# Go 的方法使其区别于许多其他语言

Go 的方法使其区别于许多其他语言，后者使用`异常`而非普通值来报告失败。虽然 Go 确实有某种异常机制，正如我们将在第 5.9 节中看到的，但它仅用于报告表示 bug 的真正意外错误，而非健壮程序应预期处理的常规错误。

这种设计的原因是异常倾向于将错误描述与处理它所需的控制流纠缠在一起，往往导致不良结果：常规错误以难以理解的堆栈跟踪形式报告给最终用户，其中充满了关于程序结构的信息，但缺乏关于出了什么错的可理解上下文。

相比之下，Go 程序使用 `if` 和 `return` 等普通控制流机制来响应错误。这种风格不可否认地要求对错误处理逻辑给予更多关注，但这正是重点所在。

## 5.4.1 错误处理策略

当函数调用返回错误时，调用者有责任检查它并采取适当行动。根据情况，可能有多种可能性。让我们看看其中五种。

首先，也是最常见的是**传播**错误，使子程序中的失败变成调用程序的失败。我们在第 5.3 节的 `findLinks` 函数中看到了这种例子。如果 `http.Get` 调用失败，`findLinks` 会将 HTTP 错误直接返回给调用者，无需进一步处理：

```
resp, err := http.Get(url)
if err != nil {
    return nil, err
}
```

相反，如果 `html.Parse` 调用失败，`findLinks` 不会直接返回 HTML 解析器的错误，因为它缺乏两个关键信息：错误发生在解析器中，以及正在解析的文档的 URL。在这种情况下，`findLinks` 会构造一个新的错误消息，包含这两条信息以及底层的解析错误：

```
doc, err := html.Parse(resp.Body)
resp.Body.Close()
if err != nil {
    return nil, fmt.Errorf("parsing %s as HTML: %v", url, err)
}
```

`fmt.Errorf` 函数使用 `fmt.Sprintf` 格式化错误消息并返回一个新的 `error` 值。我们用它来构建描述性错误，方法是将额外的上下文信息逐层添加到原始错误消息的前面。当错误最终由程序的 `main` 函数处理时，它应提供一条从根本原因到整体失败的清晰因果链，这让人联想到 NASA 的事故调查报告：

```
genesis: crashed: no parachute: G-switch failed: bad relay orientation
```

因为错误消息经常被串联在一起，所以消息字符串不应大写，也应避免换行。生成的错误可能很长，但当被 `grep` 等工具发现时，它们将是自包含的。

设计错误消息时，要深思熟虑，使每一个错误都是对问题的有意义描述，包含充分且相关的细节；并要保持一致，使同一函数或同一包中一组函数返回的错误在形式上相似，并能以相同的方式处理。

例如，`os` 包保证文件操作（如 `os.Open` 或打开文件的 `Read`、`Write`、`Close` 方法）返回的每个错误，不仅描述故障的性质（权限被拒、无此目录等），还包含文件名，因此调用者无需在其构造的错误消息中包含此信息。

通常，调用 `f(x)` 负责报告尝试的操作 `f` 和参数值 `x`，以及它们与错误上下文的关系。调用者负责添加它拥有但调用 `f(x)` 所没有的进一步信息，例如上面对 `html.Parse` 的调用中的 URL。

让我们继续讨论处理错误的第二种策略。对于表示暂时性或不可预测问题的错误，重试失败的操作可能是合理的，尝试之间可能有延迟，并且可能对尝试次数或完全放弃前花费的时间设置限制。

```
gopl.io/ch5/wait

// WaitForServer 尝试联系 URL 的服务器。
// 它使用指数退避策略尝试一分钟。
// 如果所有尝试都失败，它报告一个错误。
func WaitForServer(url string) error {
    const timeout = 1 * time.Minute
    deadline := time.Now().Add(timeout)
    for tries := 0; time.Now().Before(deadline); tries++ {
        _, err := http.Head(url)
        if err == nil {
            return nil // success
        }
        log.Printf("server not responding (%s); retrying...", err)
        time.Sleep(time.Second << uint(tries)) // exponential back-off
    }
    return fmt.Errorf("server %s failed to respond after %s", url, timeout)
}
```

第三，如果无法继续执行，调用者可以打印错误并优雅地停止程序，但这种做法通常应保留给程序的 main 包。库函数通常应将错误传播给调用者，除非该错误标志着内部不一致——即一个 bug。

```
// (在 main 函数中。)
if err := WaitForServer(url); err != nil {
    fmt.Fprintf(os.Stderr, "Site is down: %v\n", err)
    os.Exit(1)
}
```

达到相同效果的更方便的方法是调用 `log.Fatalf`。与所有 `log` 函数一样，默认情况下它会在错误消息前加上时间和日期前缀。

```
if err := WaitForServer(url); err != nil {
    log.Fatalf("Site is down: %v\n", err)
}
```

默认格式对长期运行的服务器很有帮助，但对交互式工具则不那么适用：

```
2006/01/02 15:04:05 Site is down: no such domain: bad.gopl.io
```

为了获得更美观的输出，我们可以将 `log` 包使用的前缀设置为命令名称，并禁止显示日期和时间：

```
log.SetPrefix("wait: ")
log.SetFlags(0)
```

第四，在某些情况下，仅记录错误然后继续执行就足够了，或许功能会有所降低。同样可以选择使用 `log` 包（它会添加常规前缀）：

```
if err := Ping(); err != nil {
    log.Printf("ping failed: %v; networking disabled", err)
}
```

或者直接打印到标准错误流：

```
if err := Ping(); err != nil {
    fmt.Fprintf(os.Stderr, "ping failed: %v; networking disabled\n", err)
}
```

（如果 `log` 函数的输出中不包含换行符，它们会追加一个换行符。）

第五，也是最后，在极少数情况下，我们可以安全地完全忽略错误：

```
dir, err := ioutil.TempDir("", "scratch")
if err != nil {
    return fmt.Errorf("failed to create temp dir: %v", err)
}

// ...use temp dir...

os.RemoveAll(dir) // ignore errors; $TMPDIR is cleaned periodically
```

对 `os.RemoveAll` 的调用可能会失败，但程序忽略它，因为操作系统会定期清理临时目录。在这种情况下，丢弃错误是有意为之，但如果我们忘记处理它，程序逻辑将是一样的。养成在每次函数调用后考虑错误的习惯，当你有意忽略一个错误时，请清楚地记录你的意图。

Go 语言的错误处理有一种特定的节奏。检查错误后，通常先处理失败再处理成功。如果失败导致函数返回，成功的逻辑不会缩进在 `else` 块中，而是在外层继续执行。函数倾向于表现出一种通用结构：一系列初始检查以排除错误，随后是函数的实质内容，缩进最小。

## 5.4.2 文件结束 (EOF)

通常，函数可能返回的各种错误对最终用户很有趣，但对中间的程序逻辑则不然。然而有时，程序必须根据发生的错误类型采取不同的行动。考虑从文件中读取 *n* 字节数据的尝试。如果 *n* 被选为文件的长度，任何错误都代表失败。另一方面，如果调用者反复尝试读取固定大小的块直到文件耗尽，调用者对文件结束条件的响应必须与对所有其他错误的响应不同。因此，`io` 包保证由文件结束条件引起的任何读取失败始终由一个独特的错误 `io.EOF` 报告，其定义如下：

```
package io

import "errors"

// EOF 是当没有更多输入可用时 Read 返回的错误。
var EOF = errors.New("EOF")
```

调用者可以使用简单的比较来检测此条件，如下面的循环所示，它从标准输入读取 Unicode 字符。（第 4.3 节 中的 `charcount` 程序提供了一个更完整的示例。）

```
in := bufio.NewReader(os.Stdin)
for {
    r, _, err := in.ReadRune()
    if err == io.EOF {
        break // finished reading
    }
    if err != nil {
        return fmt.Errorf("read failed: %v", err)
    }
    // ...use r...
}
```

由于在文件结束条件下，除了这一事实本身外没有其他信息可报告，因此 `io.EOF` 具有固定的错误消息 `"EOF"`。对于其他错误，我们可能需要报告错误的“性质”和“数量”，可以说，因此固定的错误值将无法满足需求。在 7.11 节 中，我们将介绍一种更系统的方法来将特定错误值与其他错误值区分开来。

## 5.5 函数值

在 Go 中，函数是*一等值*：与其他值一样，函数值拥有类型，它们可以被赋值给变量，也可以作为参数传递给函数或从函数返回。函数值可以像其他函数一样被调用。例如：

```
func square(n int) int     { return n * n }
func negative(n int) int   { return -n }
func product(m, n int) int { return m * n }

f := square
fmt.Println(f(3)) // "9"

f = negative
fmt.Println(f(3))     // "-3"
fmt.Printf("%T\n", f) // "func(int) int"

f = product // 编译错误：无法将 f(int, int) int 赋值给 f(int) int
```

函数类型的零值是 `nil`。调用 nil 函数值会导致 panic：

```
var f func(int) int
f(3) // panic: call of nil function
```

函数值可以与 `nil` 比较：

```
var f func(int) int
if f != nil {
    f(3)
}
```

但它们不可比较，因此不能相互比较，也不能用作 map 的键。

函数值让我们能够不仅针对数据，还能针对行为对函数进行参数化。标准库中包含许多示例。例如，`strings.Map` 会将一个函数应用于字符串的每个字符，将结果连接起来形成另一个字符串。

```
func add1(r rune) rune { return r + 1 }

fmt.Println(strings.Map(add1, "HAL-9000")) // "IBM.:111"
fmt.Println(strings.Map(add1, "VMS"))      // "WNT"

fmt.Println(strings.Map(add1, "Admix"))    // "Benjy"
```

5.2 节 中的 `findLinks` 函数使用了一个辅助函数 `visit`，来访问 HTML 文档中的所有节点并对每个节点应用一个操作。通过使用函数值，我们可以将树遍历的逻辑与要应用于每个节点的操作逻辑分离开来，从而让我们能够用不同的操作复用遍历逻辑。

```
gopl.io/ch5/outline2

// forEachNode 对树 n 中的每个节点 x 调用函数 pre(x) 和 post(x)。
// 这两个函数都是可选的。
// pre 在访问子节点之前被调用（前序），post 在之后被调用（后序）。
func forEachNode(n *html.Node, pre, post func(n *html.Node)) {
    if pre != nil {
        pre(n)
    }

    for c := n.FirstChild; c != nil; c = c.NextSibling {
        forEachNode(c, pre, post)
    }

    if post != nil {
        post(n)
    }
}
```

`forEachNode` 函数接受两个函数参数，一个在访问节点的子节点之前调用，一个在之后调用。这种安排给调用者提供了极大的灵活性。例如，函数 `startElement` 和 `endElement` 打印 HTML 元素的开始和结束标签，如 `<b>...</b>`：

```
var depth int

func startElement(n *html.Node) {
    if n.Type == html.ElementNode {
        fmt.Printf("%*s<%s>\n", depth*2, "", n.Data)
        depth++
    }
}

func endElement(n *html.Node) {
    if n.Type == html.ElementNode {
        depth--
        fmt.Printf("%*s</%s>\n", depth*2, "", n.Data)
    }
}
```

这些函数还利用另一个 `fmt.Printf` 技巧来缩进输出。`%*s` 中的 `*` 修饰符会打印一个用可变数量的空格填充的字符串。宽度和字符串由参数 `depth*2` 和 `""` 提供。

如果我们在 HTML 文档上调用 `forEachNode`，像这样：

```
forEachNode(doc, startElement, endElement)
```

我们将获得比之前的 `outline` 程序输出更详尽的变体：

```
$ go build gopl.io/ch5/outline2
$ ./outline2 http://gopl.io
<html>
  <head>
    <meta>
    </meta>
    <title>
    </title>
    <style>
    </style>
  </head>
  <body>
    <table>
      <tbody>
        <tr>
          <td>
            <a>
              <img>
              </img>
...
```

## 5.6 匿名函数

命名函数只能在包级别声明，但我们可以使用*函数字面量*在任何表达式中表示一个函数值。函数字面量的写法类似于函数声明，但在 `func` 关键字后没有函数名。它是一个表达式，其值被称为*匿名函数*。

函数字面量让我们能够在使用点定义函数。作为一个例子，前面对 `strings.Map` 的调用可以重写为：

```
strings.Map(func(r rune) rune { return r + 1 }, "HAL-9000")
```

更重要的是，以这种方式定义的函数可以访问完整的词法环境，因此内部函数可以引用外部函数的变量，如下例所示：

```
gopl.io/ch5/squares
```
