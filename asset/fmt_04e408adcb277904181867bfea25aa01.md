
虽然我们通常将智能设备和 IoT 与家庭或个人使用联系在一起，但它们也是每个组织关注的问题。这部分是因为员工在公司设施内甚至在组织网络上使用移动设备。网络专业人员关注的另一个方面是，许多 IoT 或网络自动化设备正被添加到业务环境中。这包括环境控制，如供暖、通风和空调（HVAC）管理、空气质量控制、碎屑和烟雾检测、照明控制、门禁自动化、人员和资产追踪，以及耗材库存管理和自动补货（如咖啡、零食、打印机碳粉、纸张和其他办公用品）。因此，智能设备和 IoT 设备都是现代业务网络的潜在组成部分，需要适当的安全管理和监督。有关智能设备和 IoT 设备进行适当安全管理重要性的更多阅读材料，请参阅“NIST Initiatives in IoT”，网址为 [`www.nist.gov/itl/applied-cybersecurity/nist-initiatives-iot`](https://www.nist.gov/itl/applied-cybersecurity/nist-initiatives-iot)。

## 工业控制系统

**工业控制系统**是一种计算机管理设备，用于控制工业过程和机器。ICS 广泛应用于制造、加工、发电和配电、配水、污水处理和石油炼制等众多行业。ICS 有多种形式，包括**分布式控制系统**、**可编程逻辑控制器**和**数据采集与监视控制系统**。

DCS 单元通常用于工业过程工厂，在这些场所从单一位置收集数据并对大规模环境实施控制至关重要。DCS 的一个重要方面是控制元件分布在受监控的环境中，例如制造车间或生产线，而集中监控位置向这些局部控制器发送命令，同时收集状态和性能数据。根据执行的任务或受控设备的不同，DCS 可能是模拟或数字性质的。例如，液体流量阀 DCS 将是模拟系统，而电压调节器 DCS 很可能是数字系统。

PLC 单元实际上是专用或特定用途的数字计算机。它们通常部署用于各种工业机电操作的管理和自动化，例如控制装配线上的系统或大规模数字灯光显示（如体育场的巨型显示系统或拉斯维加斯大道招牌上的显示屏）。

SCADA 系统可以作为独立设备运行，与其他 SCADA 系统联网，或与传统信息技术（IT）系统联网。大多数 SCADA 系统设计有极简的人机界面。通常，它们使用机械按钮和旋钮或简单的 LCD 屏幕界面（类似于商务打印机或 GPS 导航设备上的界面）。然而，联网的 SCADA 设备可能具有更复杂的远程控制软件界面。

理论上，SCADA、PLC 和 DCS 单元的静态设计及其极简的人机界面应使系统相当能抵抗攻破或修改。因此，这些工业控制设备内置的安全性很少，尤其是在过去。但近年来发生过几起著名的工业控制系统攻破事件；例如，Stuxnet 向位于核设施的 SCADA 系统投递了首个根工具包。许多 SCADA 供应商已开始在其解决方案中实施安全改进，以防止或至少减少未来的攻破。然而，在实践中，SCADA 和 ICS 系统通常仍然安全防护薄弱、漏洞众多且更新不频繁，未针对安全设计的旧版本仍广泛使用。

## 评估和缓解基于 Web 的系统中的漏洞

## Web 安全评估与 SQL 注入攻击

### Web 应用漏洞与 OWASP

在基于 Web 的系统中，存在各种各样的应用和系统漏洞及威胁，且范围在不断扩大。漏洞包括与可扩展标记语言（XML）和安全断言标记语言（SAML）相关的问题，以及由专注于开放社区的 Web 项目 **Open Web Application Security Project (OWASP)** 讨论的许多其他问题。

OWASP 是一个非营利性安全项目，专注于改进在线或基于 Web 的应用程序的安全性。OWASP 不仅仅是一个组织，它还是一个庞大的社区，大家共同努力，自由分享与更好的编码实践和更安全的部署架构相关的信息、方法论、工具和技术。有关 OWASP 的更多信息以及参与社区，请访问 [www.owasp.org](http://www.owasp.org)。

OWASP 组织维护了一份评估 Web 服务安全性的建议指南，地址为 [`www.owasp.org/index.php/Web_Application_Security_Testing_Cheat_Sheet`](https://www.owasp.org/index.php/Web_Application_Security_Testing_Cheat_Sheet)。OWASP 还维护了一份十大最关键 Web 应用攻击清单，地址为 [`www.owasp.org/images/7/72/OWASP_Top_10-2017_%28en%29.pdf.pdf`](https://www.owasp.org/images/7/72/OWASP_Top_10-2017_%28en%29.pdf.pdf)。这两份文档都是规划组织 Web 服务安全评估或渗透测试的合理切入点。

### 安全评估流程

任何安全评估都应从侦察或信息收集开始。此步骤旨在收集尽可能多的目标信息，供后续步骤使用。这通常包括查看每个托管的 Web 页面、发现正在使用的自动化技术、查找不应发布的信息，以及检查配置和安全泄露。

随后进行站点配置管理评估（如文件处理、使用的扩展、备份、在客户端代码中查找敏感数据），并评估站点的传输安全性（如检查安全套接字层（SSL）/传输层安全性（TLS）版本支持、评估密码套件、Cookie/会话 ID/令牌管理，以及对伪造请求的易感性）。

Web 安全评估的下一步是评估身份认证和会话管理。随后评估站点的加密技术以及用于数据验证和清理的方法。Web 安全评估还应涉及检查 DoS 防御、评估风险响应，并测试错误处理。

这只是 Web 安全评估概念的简要概述，因为 CISSP 考试不要求你成为专业的渗透测试人员，但你应该大致了解安全评估的概念。如果你对这个主题感兴趣，欢迎从 OWASP 指南中探索更多关于 Web 安全评估的细节。

> **注意**：你可能想了解的 OWASP 十大 Web 风险包括注入、XML 利用、跨站脚本（XSS）和 XSRF。

### 注入攻击

**注入攻击**是指允许攻击者向目标系统提交代码，以修改其操作和/或污染和破坏其数据集的任何利用行为。存在各种潜在的注入攻击。通常，注入攻击以其利用的后端系统类型或投递（注入）到目标上的有效载荷类型命名。示例包括结构化查询语言（SQL）注入、轻量级目录访问协议（LDAP）、XML 注入、命令注入、超文本标记语言（HTML）注入、代码注入和文件注入。本节将详细介绍其中几种。

#### SQL 注入攻击

从组织的角度来看，**SQL 注入攻击**比 XSS 攻击（见下节）风险更大，因为 SQL 注入攻击的目标是组织资产，而 XSS 攻击的目标是网站的客户或访问者。SQL 注入攻击利用意外输入来更改或破坏 Web 应用程序。然而，SQL 注入攻击不是利用此输入试图欺骗用户，而是利用它来获得对底层数据库及相关资产的未授权访问。

##### Web 应用演进背景

在 Web 早期，所有网页都是**静态**的，即不变的。网站管理员创建包含信息的网页并将其放置在 Web 服务器上，用户可使用其 Web 浏览器检索这些页面。Web 迅速超越了这一模式，因为用户希望能够根据个人需求访问定制信息。例如，银行网站的访问者不仅对包含银行位置、营业时间和服务信息的静态页面感兴趣，他们还想检索包含其个人账户信息的**动态**内容。显然，网站管理员不可能在 Web 服务器上为每个用户创建包含该用户个人账户信息的页面。在大型银行中，这将要求维护数百万个包含最新信息的页面。这就是动态 Web 应用程序发挥作用的地方。

Web 应用程序利用数据库在用户发出请求时按需创建内容。在银行示例中，用户登录 Web 应用程序，提供账号和密码。Web 应用程序随后从银行数据库检索当前账户信息，并利用它即时创建包含用户当前账户信息的网页。如果该用户一小时后返回，Web 服务器将重复该过程，从数据库获取更新的账户信息。

##### 安全架构影响

作为安全专业人员，这对你意味着什么？Web 应用程序增加了传统安全模型的复杂性。Web 服务器作为公共可访问服务器，属于独立的网络区域，通常称为**非军事区（DMZ）**，与其他服务器分离。另一方面，数据库服务器不面向公众访问，因此属于内部网络，或至少是与 DMZ 隔离的安全子网。Web 应用程序需要访问数据库，因此防火墙管理员必须创建一条规则，允许从 Web 服务器访问数据库服务器。这条规则为互联网用户访问数据库服务器创建了一条潜在路径。

如果 Web 应用程序运行正常，它只允许对数据库进行授权请求。然而，如果 Web 应用程序存在缺陷，它可能会让个人通过 **SQL 注入攻击**以意想不到且未授权的方式篡改数据库。这些攻击允许恶意个人直接针对底层数据库执行 SQL 事务。SQL 注入攻击可能使攻击者绕过身份认证、从数据库表中泄露机密数据、更改现有数据、向数据库添加新记录、销毁整个表或数据库，甚至通过某些数据库功能（如命令 Shell 存储过程）获得类命令行访问权限。

## 防御 SQL 注入的两种技术

你可以使用两种技术来保护 Web 应用程序免受 SQL 注入攻击。

### 1. 执行输入验证

输入验证可让你限制用户在表单中提供的数据类型。存在许多输入注入或操纵攻击的变体，需要广谱防御方法，包括白名单和黑名单过滤器。应采用的主要输入清理形式包括限制输入长度、基于已知恶意内容模式进行过滤，以及转义**元字符**。

### 2. 限制账户权限

Web 服务器使用的数据库账户应拥有尽可能小的权限集。如果 Web 应用程序只需检索数据，则应仅具备该能力。

## SQL 注入及相关攻击

归根结底，SQL 注入是处理前端（通常是 Web 服务器）与后端数据库交互的脚本的漏洞。如果脚本编写时采取了防御措施，并包含转义（使无效或拒绝）元字符的代码，则 SQL 注入将不可能发生。

### LDAP 注入

**LDAP 注入**是输入注入攻击的一种变体；然而，攻击的焦点在于 LDAP 目录服务的后端，而非数据库服务器。如果 Web 服务器前端使用脚本根据用户输入构建 LDAP 语句，则 LDAP 注入可能构成威胁。正如 SQL 注入一样，输入清理和防御性编码对于消除此威胁至关重要。

### XML 注入

**XML 注入**是 SQL 注入的另一种变体，其后端目标是 XML 应用程序。同样，输入清理对于消除此威胁是必要的。

### XML 利用

**XML 利用**是一种编程攻击形式，用于伪造发送给访问者的信息，或导致其系统在未经授权的情况下泄露信息。关于 XML 攻击，一个日益令人担忧的领域是**安全断言标记语言 (SAML)**。SAML 滥用通常集中在基于 Web 的身份认证上。SAML 是一种基于 XML 的约定，用于在安全域之间组织和交换通信身份认证和授权详细信息，通常通过 Web 协议进行。SAML 常用于提供基于 Web 的 SSO（单点登录）解决方案。如果攻击者能够伪造 SAML 通信或窃取访问者的访问令牌，他们可能能够绕过身份认证并获得对站点的未授权访问。

### 跨站脚本 (XSS)

**跨站脚本 (XSS)** 是一种恶意代码注入攻击形式，攻击者能够攻破 Web 服务器，并将其自己的恶意代码注入发送给其他访问者的内容中。黑客已经发现了许多巧妙的方法，通过通用网关接口 (CGI) 脚本、Web 服务器软件漏洞、SQL 注入攻击、框架利用、DNS 重定向、Cookie 劫持以及许多其他形式的攻击，将恶意代码注入网站。成功的 XSS 攻击可能导致身份盗窃、凭证窃取、数据窃取、财务损失，或在访问客户端上植入远程控制软件。

对于网站管理员而言，防御 XSS 的措施包括维护已修补的 Web 服务器、使用 Web 应用防火墙、运行基于主机的入侵检测系统 (HIDS)、审计可疑活动，最重要的是执行服务器端输入验证，包括长度检查、恶意内容检查和元字符过滤。作为 Web 用户，您可以通过保持系统已修补、运行防病毒软件、避免访问非主流网站来防御 XSS。某些 Web 浏览器有插件，例如 Firefox 的 NoScript 和 Chrome 的 uBlock Origin，它们仅允许执行您选择的脚本。

### 跨站请求伪造 (XSRF)

**跨站请求伪造 (XSRF)** 是一种性质类似于 XSS 的攻击。然而，XSRF 的攻击焦点更多地在于访问用户的 Web 浏览器，而非被访问的网站。XSRF 的主要目的是诱骗用户或用户的浏览器执行其未打算或未授权的操作。这可能包括注销会话、上传站点 Cookie、更改账户信息、下载账户详情、进行购买等。XSRF 的一种形式会用恶意软件感染受害者的系统，该软件保持休眠状态，直到访问特定网站。然后恶意软件以用户身份伪造请求，以欺骗 Web 服务器并对 Web 服务器和/或客户端执行恶意操作。

利用 XSRF 的一个此类漏洞示例是 Zeus，它会隐藏在受害者的系统中，直到用户访问其网上银行站点；随后，在检查其账户余额并确定其银行账号后，这些详细信息会被发送给控制攻击者，后者会发起 ACH 转账到另一家银行。因此，这是恶意软件协助直接从受害者账户窃取资金的一个示例。

网站管理员可以通过在连接的客户端请求敏感或高风险操作时要求确认或重新认证，来实施针对 XSRF 的预防措施。这可能包括要求用户重新输入密码、通过短信或电子邮件向用户发送必须提供回网站的代码、触发基于电话的验证，或解决全自动区分计算机和人类的图灵测试 (CAPTCHA)（一种区分人类和软件机器人的机制）。另一种潜在的保护机制是向每个 URL 请求和会话建立添加一个随机字符串（称为**一次性数 (nonce)**），并检查客户端 HTTP 请求头引用页是否存在欺骗。最终用户可以养成更安全的习惯，例如运行反恶意软件扫描器；使用 HIDS；运行防火墙；避免访问非主流网站；始终从网站注销，而不是关闭浏览器、关闭标签页或转到另一个 URL；保持浏览器已修补；并定期清理临时文件和缓存的 Cookie。

关于 XSS 和 XSRF 的更多内容，请参见第 21 章“恶意代码和应用程序攻击”。

## 评估和缓解移动系统中的漏洞

随着智能手机和其他**移动设备**越来越多地具备与互联网以及企业网络交互的能力，它们带来的安全风险也日益增加。当个人拥有的设备被允许在没有限制、监督或控制的情况下进出安全设施时，潜在危害是巨大的。

恶意内部人员可以通过各种存储设备从外部带入恶意代码，包括手机、音频播放器、数码相机、存储卡、光盘和通用串行总线 (USB) 驱动器。这些相同的存储设备可用于泄露或窃取内部机密和私人数据，以便向外界披露。（您认为 WikiLeaks 上的大部分内容来自哪里？）恶意内部人员可以执行恶意代码、访问危险网站，或故意执行有害活动。

移动设备通常包含敏感数据，如联系人、短信、电子邮件，以及可能的笔记和文档。任何带有摄像头功能的移动设备都可以拍摄敏感信息或地点的照片。移动设备的丢失或被盗可能意味着个人和/或企业机密的泄露。

移动设备是黑客和恶意代码的常见目标。重要的是要将非必要信息保留在便携设备之外，运行防火墙和防病毒产品（如果可用），并保持系统锁定和/或加密（如果可能）。

许多移动设备还支持 USB 连接，以便与台式机和/或笔记本电脑同步通信和联系人，以及传输文件、文档、音乐、视频等。

此外，移动设备也无法免疫窃听。借助合适类型的复杂设备，大多数移动电话通话都可能被窃听——更不用说任何 15 英尺范围内的人都能听到您在说话。通过手机讨论事情时要小心，尤其是在公共场所。

移动设备上提供了广泛的安全功能。然而，支持某项功能并不等同于该功能已正确配置并启用。只有当安全功能生效时，才能获得安全收益。请务必检查设备上所有期望的安全功能是否按预期运行。

## 设备安全

设备安全是指移动设备可能提供的各种潜在安全选项或功能。并非所有`便携式电子设备 (PEDs)`都具备良好的安全功能。但即使设备拥有安全功能，除非启用并正确配置，否则它们毫无价值。在做出购买决定前，请务必考虑新设备的安全选项。

### 全设备加密

某些移动设备（包括便携式计算机、平板电脑和手机）可能提供设备加密。如果设备的大部分或全部存储介质均可加密，这通常是一项值得启用的功能。然而，加密并不能保证数据绝对安全，特别是当设备在解锁状态下被盗，或系统本身存在已知的后门攻击漏洞时。

当使用网络电话协议 (VoIP) 服务时，移动设备上可能实现语音加密。计算机类设备之间的 VoIP 服务比连接传统固定电话或普通手机的 VoIP 连接更有可能提供加密选项。当语音通话被加密后，窃听将变得毫无意义，因为通话内容无法解读。

### 远程擦除

如果设备丢失或被盗，执行`远程擦除`或`远程清理`正变得越来越普遍。远程擦除允许你从远处删除设备上的所有数据，甚至可能包括配置设置。擦除过程可通过移动电话服务触发，有时也可通过任何互联网连接触发。然而，远程擦除并不能保证数据安全。窃贼可能足够聪明，在导出数据的同时阻断会触发擦除功能的连接。此外，远程擦除主要是一种删除操作。使用取消删除或数据恢复工具，通常可以恢复已擦除设备上的数据。为确保远程擦除能销毁数据使其无法恢复，设备应当加密。这样，取消删除操作恢复的仅是加密数据，攻击者将无法解读。

### 锁定

移动设备上的锁定类似于公司工作站上的账户锁定。当用户在反复尝试后未能提供凭据时，账户或设备将被禁用（锁定）一段时间，或直到管理员清除锁定标志。

移动设备可能提供锁定功能，但仅在配置了屏幕锁定时才会生效。否则，简单的屏幕滑动解锁无法提供足够的安全性，因为未发生认证过程。某些设备会随着认证失败次数的增加，触发越来越长的访问尝试延迟。某些设备允许设定尝试次数（如三次），超限后触发持续数分钟的锁定。其他设备则触发持久锁定，要求使用不同的账户或主密码/代码才能重新获得设备访问权。

### 屏幕锁定

屏幕锁定旨在防止他人随意拿起你的手机或移动设备即可使用。然而，大多数屏幕锁定可通过滑动图案或在键盘显示上输入数字来解锁。这两者都不是真正安全的操作。屏幕锁定可能存在变通方法，例如通过紧急呼叫功能访问电话应用程序。而且，如果黑客通过蓝牙、无线网络或 USB 线缆连接设备，屏幕锁定不一定能保护设备。
