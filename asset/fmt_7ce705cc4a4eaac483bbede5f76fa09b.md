## 配置 SSL

现在您已安装 CA，可以向 CA 发送请求，获取供应用程序使用的证书。证书最常见的用途之一是将证书安装在 Web 服务器上用于 SSL，以加密客户端和服务器之间的流量。

在 Web 站点上配置 SSL 或将证书应用于任何应用程序时，主要有四个步骤：

1.  **创建请求。** 第一步是创建证书请求，也称为 *证书签名请求 (CSR)*。您通常导航到 CA 的网站以填写 Web 表单来创建请求，或从实际应用程序创建请求。例如，Microsoft 的 IIS 和 Exchange Server 都提供了用于创建证书请求的向导。创建请求后，它将存储在文本文件中。您也可以从 Microsoft 管理控制台 (MMC) 中的“证书”管理单元创建证书请求。
2.  **提交请求。** 将请求存储在文本文件中后，您即可将请求（文本文件的内容）提交给 CA。同样，您可以通过导航到 CA 的网站来执行此操作。
3.  **下载证书。** 通过网站提交请求后，您需要将生成的证书下载到计算机上。通常在“提交请求”阶段结束时会提供一个用于下载证书的链接。
4.  **安装证书。** 下载证书后，您可以将其安装在应用程序中。

# 认证总结

在本章中，您学习了与 PKI 相关的概念，以及如何创建自己的 CA 以向系统颁发证书来保护通信。以下列表总结了您所学的 PKI 知识：

- 证书是一种电子文件，它将公钥绑定到一个实体。证书由证书的创建者进行数字签名。
- 注册机构 (RA) 负责验证请求。证书颁发机构 (CA) 负责创建和管理证书。
- 证书吊销列表 (CRL) 是由 CA 吊销的证书的已发布列表。
- 对消息进行数字签名时，使用发送方的私钥加密消息摘要，然后将其发送给接收方。

## ✓ 两分钟演练

##### 公钥基础设施简介

- 证书将主体（人或计算机）绑定到公钥或私钥。
- 证书由创建该证书的 CA 进行数字签名，以便应用程序可以验证证书的来源。
- RA 验证证书请求，然后 CA 创建证书。

### 管理公钥基础设施

- 证书分配有一个有效期。
- 证书可以在有效期过期前进行续订（而不是获取新证书）。
- CRL 是一份列出已吊销的 PKI 证书的文档，会定期更新。
- 应用程序通过检查有效期和 CRL 来验证证书是否有效，以确保证书仍可使用。
- 要允许密钥恢复，您应实施密钥存档和遵循 M-of-N 控制规则的密钥恢复过程。

### 实施公钥基础设施

- 使用 SSL 时，客户端生成一个随机对称密钥来加密通信，但使用 Web 服务器的公钥来加密该对称密钥，以便安全地将密钥传输给 Web 服务器。
- 对消息进行数字签名时，发送方生成消息摘要并使用其私钥加密该消息摘要。
