
在这里，与之前一样，我们首先在 A 部分中连接到“pawszone”数据库。接下来，在 B 部分中，我们使用 `SELECT` 语句从“pets”表中选取“petname”和“owner”列。执行该语句后，我们使用 `while` 循环通过 `FETCH_ASSOC` 样式逐行获取行。最后，我们在 `while` 循环内部使用 `echo` 语句显示获取的数据。接下来，我们再次执行 `SELECT` 语句，并使用另一个 `while` 循环通过 `FETCH_NUM` 样式获取行。如果你在浏览器中加载 `sql_select.php`，你将看到以下输出显示两次：

```
Owner = En
Pet Name = Boots

Owner = En
Pet Name = Dora

Owner = Jamie
Pet Name = Max
```

# 第 12 章：管理错误和异常

我们已经到了项目前的最后一章。在这一章中，我们将学习如何在我们的 PHP 脚本中管理错误和异常。坦率地说，这是 PHP 中最混乱的领域之一，因为 PHP 区分了异常（exception）和错误（error）。当出现问题时，我们会得到异常或错误。PHP 内部函数在出现问题时主要向我们提供错误信息。另一方面，现代的面向对象扩展（例如我们在上一章中学到的 `PDO` 扩展）更倾向于使用异常。在本章中，我们将分别讨论异常和错误，然后再对它们进行整合。

## 处理异常

### 什么是异常？

异常是 PHP 中的一个预定义对象，允许我们在发生不理想的情况时改变执行流。例如，如果我们尝试连接数据库但连接失败了。

要查看异常，请在 `htdocs` 中创建一个名为 `connect.php` 的文件并添加以下代码：

```php
<?php
$pdo = new PDO("mysql:host=localhost;dbname=pawszone", "pz_admin", "ABCD");  
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
```

在这里，我们尝试使用无效用户名连接“pawszone”。接下来，在 `htdocs` 中创建 `exceptionHandling.php` 并添加以下代码：

```php
<?php 
include "connect.php"; 
echo '<BR>Welcome to szone';
```

在创建两个文件后，尝试在浏览器中加载 `exceptionHandling.php`（确保 Apache 和 MySQL 正在运行），你得到了什么？你得到了类似下面的消息，对吧？我对消息进行了格式化并下划了部分内容以便于阅读。

```
Fatal error: Uncaught PDOException: SQLSTATE[HY000]: [1045] Access denied for user 'wrongadmin'@'localhost' (using password: YES) in /opt/lampp/htdocs/connect.php:3 Stack trace: #0 /opt/lampp/htdocs/connect.php(3): PDO->__construct('mysql:host=loca...', 'wrongadmin', 'ABCD') #1 /opt/lampp/htdocs/exceptionHandling.php(2): include('/opt....') #2 {main} thrown in /opt/lampp/htdocs/connect.php on line 3
```

此消息告诉我们发生了 `PDOException` 且未被捕获（即未被处理）。该异常是因为我们在连接数据库时使用了无效用户名。当异常发生且未被捕获时，PHP 会显示类似上面的消息。此输出包含了与异常相关的堆栈跟踪。上面的跟踪告诉我们当前异常与 `connect.php` 的第 3 行以及 `exceptionHandling.php` 的第 2 行有关。此外，数据库密码“ABCD”在堆栈中暴露了。注意 `exceptionHandling.php` 中的第二个语句（`echo '<BR>Welcome to szone';`）没有执行。这是因为任何未被捕获的异常都会导致致命错误；脚本在执行 `echo` 语句之前就会终止。

### try-catch-finally

为了捕获异常，我们使用 `try`、`catch` 和 `finally` 块。语法如下：

```php
try {
    //执行某些操作
} 
catch (异常类型) {
    //当发生异常时执行其他操作
} 
finally {
    // 无论 try 还是 catch 块是否执行，都会执行此操作
}
```

`try` 块首先尝试执行任务。如果任务失败，将抛出一个异常。抛出异常简单意味着 PHP 将使用一个处理异常的预定义类创建一个对象。

这些类包含了 `Exception`、`PDOException`、`DOMException` 和 `OutOfBoundsException` 类。当发生异常时，PHP 会创建相关异常类的对象。该对象包含有关该异常的信息，并可用于调用类中定义的各种方法。这些方法包括 `getMessage()`、`getFile()`、`getLine()` 和 `getTraceAsString()` 方法，它们分别为我们提供异常的消息、文件名、行号和堆栈跟踪。

在异常被抛出后（即在 PHP 创建异常对象之后），我们需要使用 `catch` 块来捕获它。我们可以定义多个 `catch` 块来处理不同类型的异常。在 `catch` 块之后，是 `finally` 块。该块是可选的，无论 `try` 块成功还是失败，它总是会被执行。为了说明 `try`、`catch` 和 `finally` 块的工作原理，请将 `exceptionHandling.php` 中的原始代码替换为以下代码：

```php
<?php
try{
include "connect.php";
}catch(PDOException $e){
echo '<BR>Unable to connect '.$e->getMessage();
}catch(Exception $e){
echo '<BR>Something else happened'.$e->getMessage();
}finally{
echo '<BR><BR>The finally block is always executed';
}
echo '<BR>After connecting';
```

在这里，我们首先在 `try` 块中尝试连接到“pawszone”数据库。

如果我们无法连接，PHP 会抛出一个异常，并执行 `catch` 块之一。在我们的示例中，我们有两个 `catch` 块。第一个 `catch` 块捕获 PDO 异常（`PDOException`），而第二个 `catch` 块捕获通用异常（`Exception`）。`PDOException` 是一个预定义类，用于处理 PDO 无法执行其任务时的异常。另一方面，`Exception` 是所有异常类的父类，用于处理通用异常。`$e` 代表相应异常类的对象。在 `catch` 块内部，我们使用 `$e` 调用内置的 `getMessage()` 方法，并使用 `echo` 语句输出错误消息。

如果我们运行上面的代码，将得到以下输出：

```
Unable to connect SQLSTATE[HY000] [1045] Access denied for user 'wrongadmin'@'localhost' (using password: YES) The finally block is always executed After connecting
```

第一行输出来自 `catch(PDOException $e)` 块。由于 PHP 无法连接到 `connect.php` 中的数据库，它抛出了一个 PDO 异常。第二行来自 `finally` 块。无论 `try` 块中的代码成功还是失败，该块都会执行。最后，最后一行来自 `try-catch-finally` 块之后的 `echo` 语句。这一行说明了当异常发生并被成功捕获时，脚本将继续执行。很直接吧？很好！

### 12.1.3 抛出异常

接下来，让我们学习如何抛出自己的异常。在上面的部分中，我们学习了如何捕获 PHP 抛出的异常。除了依赖 PHP 为我们抛出异常外，我们也可以抛出自己的异常。我们使用 `throw` 关键字来实现。让我们来看一个示例。将下面的函数添加到 `exceptionHandling.php` 的末尾（即在 `echo '<BR>After connecting';` 语句之后）：

```php
function displayUserInput($userInput){
    if ($userInput > 100){
        throw new OutOfRangeException('<BR>User input is too big');
    }else{
        echo '<BR>'.$userInput;
    }
}
```

在这里，我们定义了一个名为 `displayUserInput()` 的函数，它有一个参数 `$userInput`。如果 `$userInput` 大于 100，我们使用 `throw` 关键字抛出一个 `OutOfRangeException` 异常。`OutOfRangeException` 是 PHP 中一个继承自 `Exception` 的预定义类。抛出 `OutOfRangeException` 异常涉及创建一个新对象。为了创建 `OutOfRangeException` 异常，我们可以传递字符串 `'<BR>User input is too big'`。

如果我们使用下面的 `try-catch` 块调用 `displayUserInput()`：

```php
try {
    displayUserInput(105);
}catch (OutOfRangeException $e) {
    echo $e->getMessage();
}
```

`OutOfRangeException` 异常将在 `try` 块中抛出，因为 `$userInput` 大于 100。它被 `catch` 块捕获。在 `catch` 块内部，我们使用 `getMessage()` 方法获取错误消息。如果我们运行上面的代码，将得到：

```
User input is too big
```

如果我们将其改为 `displayUserInput(16);` 则不会抛出异常，我们将得到 `16`。明白了吗？太棒了！

### 12.1.4 异常处理器

在之前的章节中，我们学习了抛出和捕获异常。某些异常（如 PDO 异常）很容易处理，而其他的可能很难。在大多数情况下，尽管我们尽了努力，仍然会有无法预料的异常。在这种情况下，PHP 允许我们指定一个自定义异常处理器，当发生无法捕获的异常时调用。我们可以使用此自定义处理器向用户显示自定义消息。然而，异常处理器被调用后，PHP 脚本将终止。为了查看异常处理器的工作原理，将以下代码添加到 `exceptionHandling.php` 的末尾：

```php
function myExceptionHandler($e) {
    echo '<BR>Oppsss... An uncaught exception occurred.<BR>'.$e->getMessage();
}
set_exception_handler('myExceptionHandler');
```

在这里，我们定义了一个名为 `myExceptionHandler()` 的函数作为异常处理器。为了符合，该函数需要一个参数来存储未捕获的异常对象。在我们的示例中，该参数是 `$e`。在函数内部，我们使用 `$e` 调用 `getMessage()` 方法，并使用 `echo` 语句输出消息。在编写完函数后，我们需要使用一个内置函数 `set_exception_handler()` 将 `myExceptionHandler()` 设置为异常处理器。为此，我们编写了 `set_exception_handler('myExceptionHandler');`。为了测试我们的异常处理器，将以下行添加到 `exceptionHandling.php` 的末尾：

```php
$pdo = new PDO("some invalid database");
echo 'This will not be executed';
```

在这里，我们尝试使用无效的参数创建一个 PDO 对象。这导致了一个 PDO 异常，该异常没有被任何 `catch` 块捕获。如果你运行上面的代码，将得到：

```
Oppsss... An uncaught exception occurred.invalid data source name added to the output.
```

异常处理器（`myExceptionHandler`）成功处理了该异常。然而，注意到 PDO 实例化语句之后的 `echo` 语句没有执行？这是因为在异常处理器被调用后，PHP 脚本终止了。明白了吗？

## 处理错误

### 什么是错误？

太棒了！现在你已经熟悉了异常（exceptions），让我们来讨论错误（errors）。正如之前提到的，当 PHP 中出现问题时，你将获得一个异常或错误。错误和异常之间的一个主要区别是，异常可以被捕获，而默认情况下错误无法被捕获。这在 PHP 7 之前尤其如此。从 PHP 7 开始，发生某些错误时，PHP 会抛出一个 `Error` 异常；此异常可以被捕获。

PHP 定义了四种主要的错误类型：通知（notices）、警告（warnings）、语法错误（syntax errors）和致命错误（fatal errors）。每个错误类型进一步分为子类型，每个子类型由一个常量和一个错误代码表示。警告和通知是不导致脚本终止的轻微错误。常见原因包括尝试除以零（产生警告）和尝试访问未定义的变量（产生通知）。相反，语法错误会导致脚本终止。它们是由程序员在代码语法中犯错引起的。例如，忘记关闭括号或缺少分号。最后，我们还有致命错误，它也会导致脚本终止。常见原因包括尝试调用不存在的函数。

不要担心不同错误类型之间的区别。当错误发生时，PHP 有一个非常优秀的报告系统。例如，如果你尝试使用语句 `echo $some_undefined_variable;` 访问不存在的变量，你将得到类似下方的输出：

```
Notice: Undefined variable: some_undefined_variable in ...mycode.php on line 6
```

此输出告诉我们该错误是一个通知，并给了我们错误的原因。它还给了我们错误的文件名和发生的行号。如你所见，错误消息包含了大量信息。此类消息使我们非常容易地调试代码。然而，它们可能会向终端用户泄露过多信息。因此，我们的通常做法是只在网站的开发阶段显示这些消息。当我们的网站上线时，强烈建议不要向终端用户显示此类消息。要调整是否显示错误消息，我们需要更新 PHP 服务器中的错误设置。

### 12.2.2 PHP 中的错误报告设置

这里有两个相关的设置：`error_reporting` 和 `display_errors`。`error_reporting` 设置影响 PHP 报告的错误类型。我们有几个预定义的常量可以分配给此设置。如果我们希望 PHP 只报告致命错误（而不报告警告和通知等），我们就为此设置分配 `E_ERROR` 常量。另一方面，如果我们希望 PHP 报告所有错误，我们就为它分配 `E_ALL`。除了 `E_ERROR` 和 `E_ALL` 之外，我们还可以将其他常量分配给 `error_reporting` 设置。你可以在 `https://www.php.net/manual/en/errorfunc.constants.php` 查看所有错误常量和代码列表。

接下来，我们有 `display_errors` 设置。它影响由 PHP 报告的错误是否显示在浏览器上。在开发阶段，我们希望显示错误。为了做到，我们将 `display_errors` 设置为 `On`。在在线网站上，我们不希望显示任何错误。为了这样做，我们将 `display_errors` 设置为 `Off`。当 `display_errors` 关闭时，我们通常会将 PHP 报告的错误记录到日志文件中。我们稍后会学习这样做。
