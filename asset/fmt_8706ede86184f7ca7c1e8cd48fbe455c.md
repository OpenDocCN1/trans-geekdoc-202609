
贯穿全书，我们一直在使用两个用于字符串格式化的相似函数：`fmt.Printf`，它将结果写入标准输出（一个文件）；以及 `fmt.Sprintf`，它将结果作为 `string` 返回。如果格式化结果这项艰苦工作，仅因结果用法上的这些表面差异就不得不重复编写，那将是不幸的。得益于接口，并非如此。这两个函数实际上都是第三个函数 `fmt.Fprintf` 的包装器，后者对如何处理其计算出的结果持不可知态度：

```
package fmt

func Fprintf(w io.Writer, format string, args ...interface{}) (int, error)

func Printf(format string, args ...interface{}) (int, error) {
    return Fprintf(os.Stdout, format, args...)
}

func Sprintf(format string, args ...interface{}) string {
    var buf bytes.Buffer
    Fprintf(&buf, format, args...)
    return buf.String()
}
```

`Fprintf` 的 `F` 前缀代表 *file*（文件），表明格式化输出应写入作为第一个参数提供的文件。在 `Printf` 的情况下，参数 `os.Stdout` 是一个 `*os.File`。然而在 `Sprintf` 的情况下，参数不是文件，尽管它表面上类似于文件：`&buf` 是一个指向内存缓冲区的指针，字节可被写入其中。

`Fprintf` 的第一个参数也不是文件。它是一个 `io.Writer`，这是一个具有以下声明的接口类型：

```
package io

// Writer is the interface that wraps the basic Write method.
type Writer interface {
    // Write writes len(p) bytes from p to the underlying data stream.
    // It returns the number of bytes written from p (0 <= n <= len(p))
    // and any error encountered that caused the write to stop early.
    // Write must return a non-nil error if it returns n < len(p).
    // Write must not modify the slice data, even temporarily.
    //
    // Implementations must not retain p.
    Write(p []byte) (n int, err error)
}
```

`io.Writer` 接口定义了 `Fprintf` 与其调用者之间的契约。一方面，契约要求调用者提供一个具体类型的值，如 `*os.File` 或 `*bytes.Buffer`，该类型拥有名为 `Write`、具有适当签名和行为的方法。另一方面，契约保证 `Fprintf` 在给定任何满足 `io.Writer` 接口的值时都能完成其工作。`Fprintf` 不能假设它在写入文件或内存，只能假设它可以调用 `Write`。

因为 `fmt.Fprintf` 对值的表示形式不做任何假设，仅依赖 `io.Writer` 契约保证的行为，我们可以安全地将任何满足 `io.Writer` 的具体类型的值作为第一个参数传递给 `fmt.Fprintf`。这种用满足同一接口的另一种类型替换一种类型的自由被称为 *substitutability*（可替换性），是面向对象编程的标志。

让我们使用一种新类型来测试一下。下面 `*ByteCounter` 类型的 `Write` 方法仅统计写入的字节数，然后丢弃它们。（需要进行类型转换，以使 `+=` 赋值语句中 `len(p)` 和 `*c` 的类型匹配。）

```
type ByteCounter int

func (c *ByteCounter) Write(p []byte) (int, error) {
    *c += ByteCounter(len(p)) // convert int to ByteCounter
    return len(p), nil
}
```

既然 `*ByteCounter` 满足 `io.Writer` 接口契约，我们就可以将它传给 `Fprintf`；后者会执行字符串格式化，而无需知晓这一变化；`ByteCounter` 会正确累积结果的长度。

```
var c ByteCounter
c.Write([]byte("hello"))
fmt.Println(c) // "5", = len("hello")

c = 0 // reset the counter
var name = "Dolly"
fmt.Fprintf(&c, "hello, %s", name)
fmt.Println(c) // "12", = len("hello, Dolly")
```

除了 `io.Writer`，还有一个接口对 `fmt` 包至关重要。`Fprintf` 和 `Fprintln` 为类型提供了一种控制其值如何打印的方式。在 2.5 节 中，我们为 `Celsius` 类型定义了一个 `String` 方法，以便温度能以 `"100°C"` 的形式打印；在 6.5 节 中，我们为 `*IntSet` 配备了一个 `String` 方法，以便集合能使用传统的集合表示法（如 `"{1 2 3}"`）进行渲染。声明一个 `String` 方法会使该类型满足最广泛使用的接口之一——`fmt.Stringer`：

```
package fmt

// The String method is used to print values passed
// as an operand to any format that accepts a string
// or to an unformatted printer such as Print.
type Stringer interface {
    String() string
}
```

我们将在 7.10 节 中解释 `fmt` 包是如何发现哪些值满足该接口的。

## 7.2 接口类型

接口类型指定了一组方法，具体类型必须拥有这些方法才能被视为该接口的实例。

`io.Writer` 类型是使用最广泛的接口之一，因为它为所有可以写入字节的类型提供了抽象，包括文件、内存缓冲区、网络连接、HTTP 客户端、归档工具、哈希器等。`io` 包定义了许多其他有用的接口。`Reader` 代表任何可以从中读取字节的类型，`Closer` 代表任何可以关闭的值，例如文件或网络连接。（到目前为止，你可能已经注意到了 Go 语言中许多单方法接口的命名约定。）

```
package io

type Reader interface {
    Read(p []byte) (n int, err error)
}

type Closer interface {
    Close() error
}
```

进一步查看，我们会发现新接口类型的声明是作为现有接口的组合。以下是两个示例：

```
type ReadWriter interface {
    Reader
    Writer
}

type ReadWriteCloser interface {
    Reader
    Writer
    Closer
}
```

上述使用的语法类似于结构体嵌入，允许我们将另一个接口命名为其所有方法的简写。这被称为*嵌入*接口。我们本可以不使用嵌入来编写 `io.ReadWriter`，尽管不那么简洁，如下所示：

```
type ReadWriter interface {
    Read(p []byte) (n int, err error)
    Write(p []byte) (n int, err error)
}
```

甚至可以混合使用这两种风格：

```
type ReadWriter interface {
    Read(p []byte) (n int, err error)
    Writer
}
```

这三种声明效果相同。方法出现的顺序无关紧要。唯一重要的是方法的集合。

## 7.3 接口满足

如果一个类型拥有接口所需的所有方法，则该类型*满足*该接口。例如，`*os.File` 满足 `io.Reader`、`Writer`、`Closer` 和 `ReadWriter`。`*bytes.Buffer` 满足 `Reader`、`Writer` 和 `ReadWriter`，但不满足 `Closer`，因为它没有 `Close` 方法。简言之，Go 程序员常说具体类型“是”某个特定接口类型，意指它满足该接口。例如，`*bytes.Buffer` 是一个 `io.Writer`；`*os.File` 是一个 `io.ReadWriter`。

接口的可赋值规则 (§2.4.2) 非常简单：只有当表达式的类型满足接口时，才能将其赋值给接口。因此：

```
var w io.Writer
w = os.Stdout           // OK: *os.File 有 Write 方法
w = new(bytes.Buffer)   // OK: *bytes.Buffer 有 Write 方法
w = time.Second         // 编译错误: time.Duration 缺少 Write 方法

var rwc io.ReadWriteCloser
rwc = os.Stdout         // OK: *os.File 有 Read、Write、Close 方法
rwc = new(bytes.Buffer) // 编译错误: *bytes.Buffer 缺少 Close 方法
```

即使右侧本身是一个接口，此规则依然适用：

```
w = rwc                 // OK: io.ReadWriteCloser 有 Write 方法
rwc = w                 // 编译错误: io.Writer 缺少 Close 方法
```

因为 `ReadWriter` 和 `ReadWriteCloser` 包含 `Writer` 的所有方法，任何满足 `ReadWriter` 或 `ReadWriteCloser` 的类型必然满足 `Writer`。

在继续之前，我们应该解释一下类型拥有方法的一个细微差别。回顾 6.2 节，对于每个命名的具体类型 `T`，其某些方法的接收者类型是 `T` 本身，而另一些则需要 `*T` 指针。还记得，只要参数是*变量*，就可以在类型为 `T` 的参数上调用 `*T` 方法；编译器会隐式地获取其地址。但这只是语法糖：类型 `T` 的值并不拥有 `*T` 指针的所有方法，因此它可能满足更少的接口。

一个示例将使这一点变得清晰。来自第 6.5 节的 `IntSet` 类型的 `String` 方法需要一个指针接收者，因此我们不能在一个不可寻址的 `IntSet` 值上调用该方法：

```
type IntSet struct { /* ... */ }
func (*IntSet) String() string

var _ = IntSet{}.String() // 编译错误：String 需要 *IntSet 接收者
```

但我们可以在一个 `IntSet` 变量上调用它：

```
var s IntSet
var _ = s.String() // OK：s 是一个变量且 &s 拥有 String 方法
```

然而，由于只有 `*IntSet` 拥有 `String` 方法，因此只有 `*IntSet` 满足 `fmt.Stringer` 接口：

```
var _ fmt.Stringer = &s // OK
var _ fmt.Stringer = s  // 编译错误：IntSet 缺少 String 方法
```

第 12.8 节包含一个程序，用于打印任意值的方法，而 `godoc -analysis=type` 工具（§10.7.4）显示每种类型的方法以及接口与具体类型之间的关系。

就像一个包裹并隐藏其所装信件的信封一样，接口包裹并隐藏了它所持有的具体类型和值。只能调用接口类型揭示的方法，即使具体类型还有其他方法：

```
os.Stdout.Write([]byte("hello")) // OK：*os.File 拥有 Write 方法
os.Stdout.Close()                // OK：*os.File 拥有 Close 方法

var w io.Writer
w = os.Stdout
w.Write([]byte("hello")) // OK：io.Writer 拥有 Write 方法
w.Close()                // 编译错误：io.Writer 缺少 Close 方法
```

一个拥有更多方法的接口（如 `io.ReadWriter`）比一个拥有较少方法的接口（如 `io.Reader`）能告诉我们更多关于它所包含值的信息，并对实现它的类型提出更高的要求。那么，没有任何方法的 `interface{}` 类型，能告诉我们满足它的具体类型的什么信息呢？

答案是：什么也没说。这看似无用，但实际上 `interface{}` 类型（称为**空接口**类型）是不可或缺的。因为空接口类型对满足它的类型没有任何要求，我们可以将**任意**值赋给空接口。

```
var any interface{}
any = true
any = 12.34
any = "hello"
any = map[string]int{"one": 1}
any = new(bytes.Buffer)
```

虽然这并不明显，但我们从本书的第一个示例开始就一直在使用空接口类型，因为正是它允许像 `fmt.Println` 这样的函数，或 第 5.7 节 中的 `errorf`，接受任意类型的参数。

当然，创建了一个包含布尔值、浮点数、字符串、映射、指针或任何其他类型的 `interface{}` 值后，我们无法直接对其持有的值进行任何操作，因为该接口没有方法。我们需要一种方法将值取出。我们将在第 7.10 节中看到如何使用**类型断言**来实现这一点。

由于接口满足性仅取决于所涉及的两种类型的方法，因此无需声明具体类型与其满足的接口之间的关系。话虽如此，有时记录并断言这种关系很有用，即当这种关系是预期的但未被程序强制执行时。下面的声明在编译时断言 `*bytes.Buffer` 类型的值满足 `io.Writer`：

```
// *bytes.Buffer 必须满足 io.Writer
var w io.Writer = new(bytes.Buffer)
```

我们无需分配一个新变量，因为任何 `*bytes.Buffer` 类型的值都可以，甚至是 `nil`，我们可以使用显式转换将其写为 `(*bytes.Buffer)(nil)`。而且既然我们永远不打算引用 `w`，我们可以用空标识符替换它。这些修改共同给出了一个更节约的变体：

```
// *bytes.Buffer 必须满足 io.Writer
var _ io.Writer = (*bytes.Buffer)(nil)
```

非空接口类型（如 `io.Writer`）最常由指针类型满足，特别是当接口的一个或多个方法暗示对接收者进行某种修改时，就像 `Write` 方法那样。指向结构体的指针是一个特别常见的带方法类型。
