
## TCP 连接终止

1.  **FIN（完成）标志数据包**：最常用的方法。每一方在其所有数据传输完毕后发送一个标记了 `FIN` 标志的数据包，触发对方用一个标记了 `ACK` 标志的确认数据包进行确认。因此，优雅地拆除一个 TCP 会话需要四个数据包。

2.  **RST（复位）标志数据包**：导致会话立即且突然地终止。（请参阅本节后面关于 TCP 头部标志的讨论。）

## 排序、确认与流量控制

TCP 传输的段被标记上序列号。这使得接收方能够通过将接收到的段重新排序回其正确的排列来重建原始通信，而不管它们的接收顺序如何。

通过 TCP 会话传输的数据会定期通过确认进行验证。确认由接收方发回发送方，方法是将 TCP 头部的确认序列值设置为在传输窗口内从发送方接收到的最后一个序列号。在发送确认数据包之前传输的数据包数量称为**传输窗口**。

数据流通过一种称为**滑动窗口**的机制进行控制。TCP 能够在发送确认之前使用不同大小的窗口（换句话说，不同数量的传输数据包）。

- **较大的窗口**：允许更快的数据传输，但应仅用于丢失或损坏数据极少的可靠连接上。

- **较小的窗口**：应在通信连接不可靠时使用。

当需要数据交付时应采用 TCP。滑动窗口允许此大小动态变化，因为 TCP 会话的可靠性在使用过程中会发生变化。如果传输窗口的所有数据包未全部被接收，则不发送确认。超时后，发送方将重新发送整个传输窗口的数据包集合。

## TCP 头部结构

与另一种常见的传输层协议 UDP 相比，TCP 头部相对复杂。TCP 头部长度为 20 到 60 字节。该头部划分为多个部分或字段，详见**表 11.1**。

**表 11.1** **TCP 头部构造（按头部开始到结束顺序）**

| 位大小 | 字段 |
| :--- | :--- |
| 16 | 源端口 |
| 16 | 目的端口 |
| 32 | 序列号 |
| 4 | 数据偏移 |
| 4 | 保留供将来使用 |
| 8 | 标志（见**表 11.2**） |
| 16 | 窗口大小 |
| 16 | 校验和 |
| 16 | 紧急指针 |
| 可变 | 各种选项；必须是 32 位的倍数 |

所有这些字段都有独特的参数和要求，其中大多数超出了 CISSP 考试的范围。但是，您应该熟悉标志字段的详细信息。标志字段可以包含一个或多个标志（或控制位）的指定。这些标志指示 TCP 数据包的功能，并请求接收方以特定方式响应。标志字段长 8 位。每个位位置代表单个标志或控制设置。每个位置可以设置为 1（开）或 0（关）。在某些条件下，可以同时启用多个标志（例如，TCP 三次握手中的第二个数据包，此时 `SYN` 和 `ACK` 标志均被设置）。**表 11.2** 详细列出了标志控制位。

**表 11.2** **TCP 头部标志字段值**

| 标志位指示符 | 名称 | 描述 |
| :--- | :--- | :--- |
| CWR | 拥塞窗口减小 | 用于管理拥塞链路上的传输；见 RFC 3168 |
| ECE | ECN 回显（显式拥塞通知） | 用于管理拥塞链路上的传输；见 RFC 3168 |
| URG | 紧急 | 指示紧急数据 |
| ACK | 确认 | 确认同步或关闭请求 |
| PSH | 推送 | 指示需立即将数据推送给应用程序 |
| RST | 复位 | 导致 TCP 会话立即断开 |
| SYN | 同步 | 请求使用新序列号进行同步 |
| FIN | 完成 | 请求优雅关闭 TCP 会话 |

## IP 头部协议字段

一个额外的重要细节是，TCP 的 IP 头部协议字段值为 `6` (`0x06`)。协议字段值是每个 IP 数据包头部中发现的标签或标志，它告诉接收系统数据包的类型。IP 头部的协议字段指示下一个封装协议的标识（换句话说，当前协议层载荷中包含的协议，如 ICMP 或 IGMP，或上一层协议，如 TCP 或 UDP）。可以把它想象成你从冰箱里拿出的、用白纸包裹的神秘肉包装上的标签。没有标签，你必须打开并检查才能弄清它是什么。但有了标签，你就可以快速搜索或筛选以找到感兴趣的项目。有关其他协议字段值的列表，请访问 `www.iana.org/assignments/protocol-numbers`。

## 用户数据报协议 (UDP)

用户数据报协议 (UDP) 也工作在 OSI 模型的第 4 层（传输层）。它是一种无连接的“尽力而为”通信协议。它不提供错误检测或纠正，不使用排序，不使用流量控制机制，不使用预建立的会话，因此被认为是不可靠的。UDP 开销极低，因此可以快速传输数据。然而，UDP 应仅在数据交付非关键时使用。UDP 常被实时或流式通信用于音频和/或视频。UDP 的 IP 头部协议字段值为 17 (0x11)。

如前所述，与 TCP 头部相比，UDP 头部相对简单。UDP 头部长 8 字节（64 位）。该头部分为四个部分，或字段（每个长 16 位）：

*   `Source port`（源端口）
*   `Destination port`（目标端口）
*   `Message length`（消息长度）
*   `Checksum`（校验和）

## 网络层协议和 IP 网络基础

TCP/IP 协议套件中的另一个重要协议工作在 OSI 模型的网络层，即互联网协议 (IP)。IP 为数据包提供路由寻址。正是这种路由寻址构成了全球互联网通信的基础，因为它提供了一种标识手段并规定了传输路径。与 UDP 类似，IP 是无连接的，是一种不可靠的数据报服务。IP 不保证数据包会被交付，不保证数据包会按正确顺序交付，也不保证数据包仅被交付一次。因此，必须在 IP 上使用 TCP 以获得可靠且受控的通信会话。

### IP 类别

IP 寻址和 IP 类别的基础知识是任何安全专业人员的必修课。如果你对寻址、子网划分、类别及其他相关主题生疏了，请花时间复习一下。表 11.3 和表 11.4 提供了类别和默认子网关键细节的快速概览。完整的 A 类子网支持 16,777,214 台主机；完整的 B 类子网支持 65,534 台主机；完整的 C 类子网支持 254 台主机。D 类用于组播，而 E 类保留供将来使用。

**表 11.3** **IP 类别**

| 类别 | 首位二进制数字 | 首个八位字节的十进制范围 |
| --- | --- | --- |
| A | 0 | 1–126 |
| B | 10 | 128–191 |
| C | 110 | 192–223 |
| D | 1110 | 224–239 |
| E | 1111 | 240–255 |

**表 11.4** **IP 类别的默认子网掩码**

| 类别 | 默认子网掩码 | CIDR 等效值 |
| --- | --- | --- |
| A | 255.0.0.0 | /8 |
| B | 255.255.0.0 | /16 |
| C | 255.255.255.0 | /24 |

请注意，整个 127 类 A 网络被预留用于 `loopback address`（回环地址），尽管实际上仅需一个地址即可实现该目的。

子网划分的另一种选择是使用 `Classless Inter-Domain Routing (CIDR)`（无类别域间路由）表示法。CIDR 使用掩码位而非完整的点分十进制子网掩码表示法。因此，CIDR 会在 IP 地址后加上斜杠，例如 `172.16.1.1/16`，而不是使用 255.255.0.0。CIDR 相较于传统子网掩码技术的一个显著优势是能够将多个不连续的地址集合合并为单个子网。例如，可以将多个 C 类子网合并为一个更大的子网组。如果你对 CIDR 感兴趣，请参阅维基百科上的 CIDR 条目，或访问 IETF 的 CIDR RFC 文档：[`tools.ietf.org/html/rfc4632`](http://tools.ietf.org/html/rfc4632)。

### ICMP 和 IGMP

ICMP 和 IGMP 是 OSI 模型网络层的其他协议：

**ICMP** `Internet Control Message Protocol (ICMP)`（互联网控制消息协议）用于确定网络或特定链路的健康状况。`ping`、`traceroute`、`pathping` 和其他网络管理工具均使用 ICMP。`ping` 实用程序使用 ICMP 回显数据包并将其反弹至远程系统。因此，你可以使用 `ping` 来确定远程系统是否在线、远程系统是否及时响应、中间系统是否支持通信，以及中间系统通信的性能效率水平。`ping` 实用程序包含重定向功能，允许将回显响应发送到不同于源系统的目标。

不幸的是，ICMP 的特性常被利用于各种基于带宽的拒绝服务 (DoS) 攻击，例如死亡之 Ping、Smurf 攻击和 Ping 洪水攻击。这一事实塑造了当今网络处理 ICMP 流量的方式，导致许多网络限制 ICMP 的使用，或至少限制其吞吐率。死亡之 Ping 发送一个大于 65,535 字节（大于最大 IPv4 数据包大小）的畸形 Ping 给计算机，试图使其崩溃。Smurf 攻击通过伪造广播 Ping 在目标网络上产生巨大流量，而 Ping 洪水则是一种基本的 DoS 攻击，依赖于耗尽目标可用的所有带宽。

你应该了解关于 ICMP 的几个重要细节。首先，ICMP 的 IP 头部协议字段值为 1 (0x01)。其次，ICMP 头部中的类型字段定义了 ICMP 有效载荷中所含消息的类型或用途。已定义了 40 多种类型，但只有 7 种常用（见表 11.5）。你可以在 [www.iana.org/assignments/icmp-parameters](http://www.iana.org/assignments/icmp-parameters) 找到 ICMP 类型字段值的完整列表。值得注意的是，列出的许多类型可能也支持代码。代码只是提供关于 ICMP 消息有效载荷功能或用途的更多细节的额外数据参数。会导致 ICMP 响应的一个事件示例是：尝试连接到一个 UDP 服务端口，但该服务和端口实际上并未在目标服务器上使用；这将导致向源发送 ICMP 类型 3 响应。由于 UDP 没有发回错误的机制，协议栈会为此目的切换到 ICMP。

**表 11.5** **常见 ICMP 类型字段值**

| 类型 | 功能 |
| --- | --- |
| 0 | 回显应答 |
| 3 | 目标不可达 |
| 5 | 重定向 |
| 8 | 回显请求 |
| 9 | 路由器通告 |
| 10 | 路由器请求 |
| 11 | 超时 |

**IGMP** `Internet Group Management Protocol (IGMP)`（互联网组管理协议）允许系统支持组播。组播是将数据传输给多个特定接收者。（RFC 1112 讨论了执行 IGMP 组播的要求。）IGMP 由 IP 主机用于注册其动态组播组成员身份。连接的路由器也使用它来发现这些组。通过使用 IGMP 组播，服务器可以为整个组最初仅传输单个数据信号，而不是为每个预期接收者分别传输初始数据信号。使用 IGMP 时，如果存在通往预期接收者的分歧路径，单个初始信号会在路由器处被复制。IGMP 的 IP 头部协议字段值为 2 (0x02)。

**ARP** `Address Resolution Protocol (ARP)`（地址解析协议）对于逻辑和物理寻址方案的互操作性至关重要。ARP 用于将 IP 地址（用于逻辑寻址的 32 位二进制数）解析为媒体访问控制 (MAC) 地址（用于物理寻址的 48 位二进制数）——或 EUI-48 甚至 EUI-64。网段上的流量（例如，跨集线器的电缆）使用 MAC 地址从源系统定向到目标系统。

### ARP 缓存与广播机制

ARP 使用缓存和广播来执行其操作。将 IP 地址解析为 MAC 地址（或反之）的第一步是检查本地 ARP 缓存。如果所需信息已存在于 ARP 缓存中，则直接使用。此活动有时会被一种称为 **ARP 缓存投毒** 的技术滥用，攻击者会将虚假信息插入 ARP 缓存。如果 ARP 缓存不包含必要信息，则会以广播形式发送 ARP 请求。如果被查询地址的所有者在本地子网中，它可以响应必要信息。如果不在，系统将默认使用其默认网关来传输通信。然后，默认网关（即路由器）需要执行其自己的 ARP 过程。

## 常见应用层协议

在 TCP/IP 模型的应用层（包含 OSI 模型的会话层、表示层和应用层）中存在许多特定于应用程序或服务的协议。了解这些协议及其相关服务端口对于 CISSP 考试很重要：

*   **Telnet**，`TCP` 端口 `23`：这是一个终端仿真网络应用程序，支持远程连接以执行命令和运行应用程序，但不支持文件传输。

*   **文件传输协议 (FTP)**，`TCP` 端口 `20`（被动数据）/ 临时端口（主动数据）和 `21`（控制连接）：这是一个支持文件交换的网络应用程序，需要匿名或特定身份验证。

*   **简单文件传输协议 (TFTP)**，`UDP` 端口 `69`：这是一个支持文件交换的网络应用程序，不需要身份验证。

*   **简单邮件传输协议 (SMTP)**，`TCP` 端口 `25`：这是一种用于将电子邮件从客户端传输到电子邮件服务器，以及从一个电子邮件服务器传输到另一个电子邮件服务器的协议。

*   **邮局协议 (POP3)**，`TCP` 端口 `110`：这是一种用于将电子邮件服务器收件箱中的电子邮件拉取到电子邮件客户端的协议。

*   **互联网消息访问协议 (IMAP)**，`TCP` 端口 `143`：这是一种用于将电子邮件服务器收件箱中的电子邮件拉取到电子邮件客户端的协议。IMAP 比 POP3 更安全，并提供从电子邮件服务器拉取邮件头以及直接在电子邮件服务器上删除消息的功能，而无需先下载到本地客户端。

*   **动态主机配置协议 (DHCP)**，`UDP` 端口 `67` 和 `68`：DHCP 使用端口 `67` 作为服务器上的目标端口以接收客户端通信，使用端口 `68` 作为客户端请求的源端口。它用于在系统启动时分配 TCP/IP 配置设置。DHCP 实现了网络寻址的集中控制。

*   **超文本传输协议 (HTTP)**，`TCP` 端口 `80`：这是用于将网页元素从 Web 服务器传输到 Web 浏览器的协议。

*   **安全套接字层 (SSL)**，`TCP` 端口 `443`（用于 HTTP 加密）：这是一种在传输层运行的类 VPN 安全协议。SSL 最初设计用于支持安全的 Web 通信 (HTTPS)，但能够保护任何应用层协议通信。

*   **行式打印机守护进程 (LPD)**，`TCP` 端口 `515`：这是一种用于打印作业缓存和将打印作业发送到打印机的网络服务。

*   **X Window**，`TCP` 端口 `6000–6063`：这是命令行操作系统的 GUI API。

*   **网络文件系统 (NFS)**，`TCP` 端口 `2049`：这是一种用于支持异构系统间文件共享的网络服务。

*   **简单网络管理协议 (SNMP)**，`UDP` 端口 `161`（`UDP` 端口 `162` 用于 Trap 消息）：这是一种通过从中央监控站轮询监控设备来收集网络健康和状态信息的网络服务。

## 多层协议的影响

从前面几节可以看出，TCP/IP 作为一个协议套件，包含分布在各个协议栈层中的数十个单独协议。因此，TCP/IP 是一个 **多层协议**。TCP/IP 从其多层设计中获得了几项益处，特别是与其封装机制有关。例如，当通过典型网络连接在 Web 服务器和 Web 浏览器之间通信时，`HTTP` 封装在 `TCP` 中，后者又封装在 `IP` 中，后者又封装在 `Ethernet` 中。这可以表示如下：

```
[ Ethernet [ IP [ TCP [ HTTP ] ] ] ]
```

然而，这并不是 TCP/IP 封装支持的全部。还可以添加额外的封装层。例如，向通信添加 `SSL/TLS` 加密会在 `HTTP` 和 `TCP` 之间插入一个新的封装：

```
[ Ethernet [ IP [ TCP [ SSL [ HTTP ] ] ] ] ]
```

这反过来还可以进一步用网络层加密（如 `IPSec`）进行封装：

```
[ Ethernet [ IPSec [ IP [ TCP [ SSL [ HTTP ] ] ] ] ] ]
```

然而，封装并不总是用于良性目的。有许多隐蔽信道通信机制利用封装来隐藏或隔离另一个授权协议内部的未授权协议。例如，如果网络阻止使用 `FTP` 但允许 `HTTP`，则可以使用 `HTTP Tunnel` 等工具绕过此限制。这可能导致如下的封装结构：

```
[ Ethernet [ IP [ TCP [ HTTP [ FTP ] ] ] ] ]
```

通常，`HTTP` 承载其自身的 Web 相关负载，但使用 `HTTP Tunnel` 工具时，标准负载会被替换为替代协议。这种虚假封装甚至可能发生在协议栈的较低层。例如，`ICMP` 通常用于网络健康测试，而非一般通信。然而，使用 `Loki` 等实用程序，`ICMP` 可转换为隧道协议以支持 `TCP` 通信。`Loki` 的封装结构如下：

```
[ Ethernet [ IP [ ICMP [ TCP [ HTTP ] ] ] ] ]
```

由无界封装支持引起的另一个关注领域是跨虚拟局域网 (VLAN) 跳转的能力。VLAN 是通过标签逻辑分离的网段。这种攻击称为 **VLAN 跳转**，通过创建双重封装的 **IEEE 802.1Q VLAN 标签** 来执行：

```
[ Ethernet [ VLAN1 [ VLAN2 [ IP [ TCP [ HTTP ] ] ] ] ] ]
```

通过这种双重封装，第一个遇到的交换机将剥离第一个 VLAN 标签，然后下一个交换机会被内部的 VLAN 标签欺骗，将流量移动到另一个 VLAN。

多层协议提供下列益处：

*   可以在高层使用各种协议。
*   可以在各层加入加密。
*   支持复杂网络结构中的灵活性和弹性。

多层协议有几个缺点：

*   允许隐蔽信道。
*   过滤器可被绕过。
*   逻辑施加的网络段边界可能被跨越。

## TCP/IP 漏洞
