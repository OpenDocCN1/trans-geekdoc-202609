
*   利用硬件或软件漏洞的攻击。这种对弱点、错误或软件标准功能的利用，旨在导致系统挂起、冻结、耗尽所有系统资源等。最终结果是受害计算机无法处理任何合法任务。
*   用垃圾网络流量淹没受害者通信管道的攻击。这些攻击有时被称为流量生成攻击或洪水攻击。最终结果是受害计算机无法发送或接收合法的网络通信。

无论哪种情况，受害者都被剥夺了执行正常操作（服务）的能力。

`DoS` 不是单一攻击，而是一整类攻击。一些攻击利用操作系统软件中的缺陷，而另一些则针对已安装的应用程序、服务或协议。一些攻击利用特定协议，包括 `Internet Protocol (IP)`、`Transmission Control Protocol (TCP)`、`Internet Control Message Protocol (ICMP)` 和 `User Datagram Protocol (UDP)`。

`DoS` 攻击通常发生在一名攻击者和一名受害者之间。然而，情况并不总是那么简单。大多数 `DoS` 攻击都采用某种形式的中间系统（通常是不情愿且不知情的参与者）来向受害者隐藏攻击者。例如，如果攻击者直接向受害者发送攻击数据包，受害者有可能发现攻击者是谁。通过使用欺骗（本章其他地方有更详细的描述），这变得更加困难，尽管并非不可能。

许多 `DoS` 攻击始于攻破或渗透一个或多个中间系统，这些系统随后充当发起点或攻击平台。这些中间系统通常被称为次级受害者。攻击者在这些系统上安装远程控制工具，通常称为 `bots`、`zombies` 或 `agents`。然后，在约定的时间或响应攻击者的发起命令时，对受害者发动 `DoS` 攻击。受害者可能能够发现导致 `DoS` 攻击的僵尸系统，但很可能无法追踪到实际的攻击者。涉及僵尸系统的攻击称为 `分布式拒绝服务 (DDoS)` 攻击。跨多个不知情的次级受害者部署大量 bots 或 zombies 的行为被称为 `botnets`。

以下是针对这些攻击的一些对策和防护措施：

*   添加能够检测 `DoS` 流量并根据源地址或目标地址自动阻断端口或过滤数据包的防火墙、路由器和入侵检测系统 (`IDSs`)。
*   与服务提供商保持良好联系，以便在发生 `DoS` 时请求过滤服务。
*   在外部系统上禁用回显应答。
*   在边界系统上禁用广播功能。
*   阻止欺骗数据包进入或离开您的网络。
*   使用供应商提供的最新安全更新为所有系统打补丁。
*   考虑商业 `DoS` 防护/响应服务，如 `CloudFlare's DDoS mitigation` 或 `Prolexic`。这些服务可能很昂贵，但通常很有效。

关于 `DoS` 和 `DDoS` 的进一步讨论，请参见第 17 章“预防和响应事件”。

### 窃听

顾名思义，`窃听` 就是监听通信流量以复制它。复制可以采取将数据记录到存储设备的形式，也可以使用提取程序动态尝试从流量流中提取原始内容。一旦通信内容的副本落入攻击者手中，他们通常可以提取多种形式的机密信息，如用户名、密码、流程程序、数据等。

`窃听` 通常需要物理访问 IT 基础设施，以便将物理记录设备连接到开放端口或电缆接头，或在系统上安装软件记录工具。`窃听` 通常通过使用网络流量捕获或监控程序或协议分析系统（通常称为 `sniffer`）来实施。`窃听` 设备和软件通常难以检测，因为它们用于被动攻击。当 `窃听` 或窃听演变为篡改或注入通信时，该攻击被视为主动攻击。

您可以通过维护物理访问安全来防止未经授权的人员访问您的 IT 基础设施，从而对抗 `窃听`。至于保护发生在您网络外部的通信，或防范内部攻击者，在通信流量上使用加密（如 `IPsec` 或 `SSH`）和一次性认证方法（即一次性密码本或令牌设备）将大大降低 `窃听` 的有效性和时效性。

常见的 `窃听` 威胁是维护可靠通信安全的主要动机之一。数据在传输过程中往往比在存储时更容易被拦截。此外，通信线路可能位于组织控制范围之外。因此，在数据传输离开内部基础设施时采取可靠手段保护其安全至关重要。一些常见的网络健康和通信可靠性评估及管理工具（如 `sniffers`）可能被用于不法目的，因此需要严格的控制和监督以防止滥用。

### 冒充/伪装

**冒充**，或**伪装**，是指假装成你不是的某人或某物，以获取对系统的未授权访问。这通常意味着认证凭据已被窃取或伪造，以满足（即成功绕过）认证机制。这与欺骗不同，欺骗是指实体提出虚假身份但不提供任何证明（例如虚假使用 IP 地址、MAC 地址、电子邮件地址、系统名称、域名等）。冒充通常通过捕获用户名和密码或网络服务的会话建立过程来实现。

防止冒充的一些解决方案包括使用一次性密码本和令牌认证系统、使用 Kerberos，以及使用加密来增加从网络流量中提取认证凭据的难度。

#### 重放攻击

**重放攻击**是冒充攻击的一种衍生形式，通过窃听捕获网络流量而成为可能。重放攻击试图通过向系统重放捕获的流量来重新建立通信会话。你可以通过使用一次性认证机制和排序的会话标识来防止它们。

#### 修改攻击

在**修改攻击**中，捕获的数据包被篡改后再针对系统重放。修改后的数据包旨在绕过改进的认证机制和会话排序的限制。针对修改重放攻击的对策包括使用数字签名验证和数据包校验和验证。

#### 地址解析协议欺骗

**地址解析协议 (ARP)** 是 **TCP/IP** 协议套件的一个子协议，在数据链路层（第 2 层）运行。ARP 用于通过使用 IP 地址进行轮询来发现系统的 MAC 地址。ARP 通过广播一个包含目标 IP 地址的请求数据包来工作。拥有该 IP 地址的系统（或已有其 ARP 映射的其他系统）将回复相关联的 MAC 地址。发现的 IP 到 MAC 映射存储在 ARP 缓存中，并用于指导数据包转发。

ARP 映射可能通过欺骗受到攻击。**ARP 欺骗**为请求的 IP 地址系统提供虚假 MAC 地址，以将流量重定向到备用目标。ARP 攻击通常是中间人攻击的一个要素。此类攻击涉及入侵者的系统将其 MAC 地址针对目标 IP 地址伪装到源系统的 ARP 缓存中。从源系统接收的所有数据包会被检查，然后转发给实际的预期目标系统。你可以采取措施来对抗 ARP 攻击，例如为关键系统定义静态 ARP 映射、监控 ARP 缓存中的 MAC 到 IP 地址映射，或使用 IDS 检测系统流量中的异常和 ARP 流量的变化。

#### DNS 投毒、欺骗和劫持

**DNS 投毒**和 **DNS 欺骗**也称为解析攻击。**域名系统 (DNS)** 投毒发生在攻击者篡改 DNS 系统中的域名到 IP 地址映射时，以将流量重定向到恶意系统，或仅仅是对系统执行拒绝服务。DNS 欺骗发生在攻击者向请求系统发送虚假回复，抢在有效 DNS 服务器的真实回复之前到达时。这在技术上也是一种竞争条件的利用。防止由投毒和欺骗导致的虚假 DNS 结果的保护措施包括：仅允许授权的 DNS 更改、限制区域传输，以及记录所有特权 DNS 活动。

2008 年，Dan Kaminsky 发现并向世界披露了一个相当重大的漏洞。该漏洞在于本地或缓存 DNS 服务器从根服务器获取特定域权威服务器身份信息的方法。通过向缓存 DNS 服务器发送针对不存在子域的伪造回复，攻击者可以劫持整个域的解析详细信息。有关 DNS 如何工作以及此漏洞如何威胁当前 DNS 基础设施的详细图解说明，请访问“Kaminsky DNS 漏洞图解指南”，网址为 [`unixwiz.net/techtips/iguide-kaminsky-dns-vuln.html`](http://unixwiz.net/techtips/iguide-kaminsky-dns-vuln.html)。

另一个 DNS 问题是同形异义攻击。这些攻击利用字符集的相似性来注册虚假的国际化域名 (IDN)，肉眼看上去却是合法的。例如，西里尔字母中的某些字母看起来像拉丁字符；例如，拉丁字母中的 *p* 看起来像西里尔字母 Palochka。因此，[apple.com](http://apple.com) 和 [paypal.com](http://paypal.com) 等域名看起来像有效的拉丁字符，但实际包含西里尔字符，解析时会将你导向到一个不同于你预期的站点。有关同形异义攻击的详尽讨论，请参阅 [`blog.malwarebytes.com/101/2017/10/out-of-character-homograph-attacks-explained/`](https://blog.malwarebytes.com/101/2017/10/out-of-character-homograph-attacks-explained/)。

解决此 DNS 劫持漏洞的唯一真正解决方案是将 DNS 升级为 **域名系统安全扩展 (DNSSEC)**。详情请访问 [dnssec.net](http://dnssec.net)。

#### 超链接欺骗

另一种相关攻击是**超链接欺骗**，它类似于 DNS 欺骗，用于将流量重定向到恶意或冒充系统，或仅仅是将流量从其预期目的地转移开。超链接欺骗可以采取 DNS 欺骗的形式，也可以简单地篡改发送给客户端的文档 HTML 代码中的超链接 URL。超链接欺骗攻击通常之所以成功，是因为大多数用户不会通过 DNS 验证 URL 中的域名；相反，他们假设超链接是有效的，直接点击它。

防范超链接欺骗的措施包括针对 DNS 欺骗采取的相同预防措施，以及保持系统打补丁和谨慎使用互联网。

### 总结

远程访问安全管理要求安全系统设计师解决实施中的硬件和软件组件，以及策略问题、工作任务问题和加密问题。这包括部署安全通信协议。对本地和远程连接进行安全认证是整体安全的重要基础要素。

保持对通信路径的控制对于支持网络、语音和其他形式通信的机密性、完整性和可用性至关重要。许多攻击都集中在拦截、阻塞或以其他方式干扰数据从一个位置传输到另一个位置。幸运的是，也有合理的对策来减少甚至消除许多此类威胁。

隧道技术，或封装，是一种将一种协议中的消息使用第二种协议通过另一个网络或通信系统传输的方法。隧道技术可以与加密结合，为传输的消息提供安全性。VPN 基于加密隧道技术。

**VLAN** 是由交换机创建的硬件强制的网络分段。VLAN 用于在不改变物理拓扑的情况下对网络进行逻辑分段。VLAN 用于流量管理。

远程办公，或远程连接，已成为商务计算的常见功能。当在任何环境中部署远程访问能力时，必须考虑并实施安全性，以保护私有网络免受远程访问并发症的影响。远程访问用户在获得访问权限前应接受严格认证；这可以包括使用 **RADIUS** 或 **TACACS+**。远程访问服务包括 **IP 语音 (VoIP)**、应用程序流式传输、**VDI**、多媒体协作和即时消息传递。

### NAT

NAT 用于隐藏私有网络的内部结构，并使多个内部客户端能够通过少量公共 IP 地址访问互联网。NAT 通常是边界安全设备的原生功能，例如防火墙、路由器、网关和代理。

### 电路交换与分组交换

在电路交换中，会在两个通信方之间创建一条专用的物理路径。分组交换是指将消息或通信分割成小段（通常是固定长度的分组，具体取决于所采用的协议和技术），并通过中间网络发送到目的地。在分组交换系统中，有两种通信类型：路径和虚拟电路。虚拟电路是在分组交换网络上两个特定端点之间创建的逻辑路径或电路。虚拟电路有两种类型：永久虚拟电路（PVC）和交换虚拟电路（SVC）。

### WAN 链路

WAN 链路，或长距离连接技术，可分为两大类：专用线路和非专用线路。专用线路连接两个特定端点，且仅连接这两个端点。非专用线路是在数据传输发生前需要建立连接的线路。非专用线路可用于连接任何使用相同类型非专用线路的远程系统。WAN 连接技术包括 X.25、帧中继、ATM、SMDS、SDLC、HDLC、SDH 和 SONET。

### 网络通信的安全控制

在为网络通信选择或部署安全控制时，您需要结合您的环境、能力和安全策略评估众多特性。安全控制应对用户透明。哈希总计和 CRC 校验可用于验证消息完整性。记录序列用于确保传输的序列完整性。传输日志记录有助于检测通信滥用行为。

### 虚拟化

虚拟化技术用于在单台主机计算机的内存中托管一个或多个操作系统。此机制允许几乎任何操作系统在任何硬件上运行。它还允许多个操作系统在同一硬件上同时工作。虚拟化提供多种优势，例如能够根据需要启动服务或服务的单独实例、实时可扩展性，以及能够运行应用程序所需的确切操作系统版本。

### 电子邮件安全

除非您采取措施保护，否则基于互联网的电子邮件是不安全的。要保护电子邮件，您应提供不可抵赖性，限制授权用户访问，确保完整性得以维护，验证消息来源，确认投递，甚至对敏感内容进行分类。这些问题必须在安全策略中得到解决，然后才能在解决方案中实施。它们通常以可接受使用策略、访问控制、隐私声明、电子邮件管理程序以及备份和保留策略的形式出现。

电子邮件是恶意代码的常见传播机制。过滤附件、使用防病毒软件和教育用户是针对此类攻击的有效对策。电子邮件垃圾邮件或邮件轰炸是一种拒绝服务形式，可通过过滤器和 IDS 予以阻止。可以使用 S/MIME、MOSS、PEM 和 PGP 来提高电子邮件安全性。

### 传真和语音安全

通过使用加密来保护文档传输并防止窃听，可以提高传真和语音安全性。有效培训用户是防范社会工程学攻击的有用对策。

### 安全边界

安全边界可以是一个安全区域与另一个安全区域之间的划分，也可以是一个安全区域与一个非安全区域之间的划分。这两者都必须在安全策略中予以解决。

### 通信系统漏洞

通信系统容易受到多种攻击，包括分布式拒绝服务（DDoS）、窃听、冒充、重放、篡改、欺骗，以及 ARP 和 DNS 攻击。幸运的是，针对这些攻击中的每一种都存在有效的对策。PBX 欺诈和滥用以及电话破解也是必须解决的问题。

### 考试要点

#### 理解远程访问安全管理相关问题

远程访问安全管理要求安全系统设计人员解决实现过程中的硬件和软件组件问题，以及与策略、工作任务和加密相关的问题。

#### 熟悉可用于 LAN 和 WAN 进行数据通信的各种协议和机制

这些包括 `SKIP`、`SWIPE`、`SSL`、`SET`、`PPP`、`SLIP`、`CHAP`、`PAP`、`EAP` 和 `S-RPC`。它们还可以包括 `VPN`、`TLS/SSL` 和 `VLAN`。

#### 了解什么是隧道技术

隧道技术是将协议可传递消息封装在第二个协议中。第二个协议通常执行加密以保护消息内容。

#### 理解 VPN

VPN 基于加密隧道技术。它们可以作为点对点解决方案提供身份验证和数据保护。常见的 VPN 协议有 `PPTP`、`L2F`、`L2TP` 和 `IPsec`。

#### 能够解释 NAT

NAT 保护私有网络的寻址方案，允许使用私有 IP 地址，并使多个内部客户端能够通过少量公共 IP 地址获得互联网访问权限。NAT 受许多安全边界设备支持，例如防火墙、路由器、网关和代理。

#### 理解分组交换与电路交换的区别

在电路交换中，会在两个通信方之间创建一条专用的物理路径。分组交换是指将消息或通信分割成小段，并通过中间网络发送到目的地。在分组交换系统中，有两种通信路径或虚拟电路：永久虚拟电路（PVC）和交换虚拟电路（SVC）。

#### 理解专用线路与非专用线路的区别

专用线路始终处于开启状态，并为特定客户保留。专用线路的示例包括 `T1`、`T3`、`E1`、`E3` 和有线调制解调器。非专用线路在数据传输发生前需要建立连接。它可用于连接任何使用相同类型非专用线路的远程系统。标准调制解调器、`DSL` 和 `ISDN` 是非专用线路的示例。

#### 了解与远程访问安全相关的各种问题

熟悉远程访问、拨号连接、屏幕抓取器、虚拟应用程序/桌面以及一般远程办公安全顾虑。

#### 了解各种 WAN 技术

了解大多数 WAN 技术需要信道服务单元/数据服务单元（CSU/DSU），有时称为 WAN 交换机。存在多种类型的载波网络和 WAN 连接技术，例如 `X.25`、`帧中继`、`ATM`、`SMDS`、`SDH` 和 `SONET`。某些 WAN 连接技术需要额外的专用协议来支持各种类型的专用系统或设备。

#### 理解 PPP 与 SLIP 的区别

点对点协议（`PPP`）是一种封装协议，旨在支持通过拨号或点对点链路传输 IP 流量。`PPP` 包括广泛的通信服务，包括 IP 地址的分配和管理、同步通信的管理、标准化封装、复用、链路配置、链路质量测试、错误检测，以及功能或选项协商（如压缩）。`PPP` 最初设计用于支持 `CHAP` 和 `PAP` 进行身份验证。然而，`PPP` 的最新版本也支持 `MS-CHAP`、`EAP` 和 `SPAP`。`PPP` 取代了串行线路互联网协议（`SLIP`）。`SLIP` 不提供身份验证，仅支持半双工通信，没有错误检测功能，且需要手动建立和拆除链路。

#### 理解安全控制的通用特征

安全控制应对用户透明。哈希总计和 CRC 校验可用于验证消息完整性。记录序列用于确保传输的序列完整性。传输日志记录有助于检测通信滥用行为。

#### 理解电子邮件安全的工作原理

互联网电子邮件基于 `SMTP`、`POP3` 和 `IMAP`。它本质上是不安全的。虽然可以对其进行保护，但所使用的方法必须在安全策略中加以规定。电子邮件安全解决方案包括使用 `S/MIME`、`MOSS`、`PEM` 或 `PGP`。

#### 了解传真安全的工作原理

传真安全主要基于使用加密传输或加密通信线路来保护传真资料。主要目标是防止截获。活动日志和异常报告可用于检测传真活动中的异常，这些异常可能是攻击的症状。

#### 了解与 PBX 系统相关的威胁以及应对 PBX 欺诈的对策

应对 PBX 欺诈和滥用的对策包括许多用于保护典型计算机网络的相同预防措施：逻辑或技术控制、管理控制和物理控制。

#### 理解与 VoIP 相关的安全问题

VoIP 面临来电显示欺骗、语音钓鱼、SPIT（垃圾互联网电话）、呼叫管理器软件/固件攻击、电话硬件攻击、`DoS`、`MitM`、欺骗和交换机跳转的风险。

#### 识别什么是“电话破解者”

电话破解是一种特定类型的攻击，攻击者利用各种技术绕过电话系统，以拨打免费长途电话、更改电话服务功能、窃取专用服务，甚至导致服务中断。电话破解者常用的工具包括黑盒、红盒、蓝盒和白盒。
