## 前言

实时流数据分析正成为从当前正在发生的事件中获取有用知识的标准，使组织能够在问题出现时快速反应，或检测新趋势，从而帮助其提升绩效。本书介绍了数据流挖掘领域目前使用的许多算法和技术。一个实现了本书许多技术的软件框架可在网络上作为名为 `MOA` 的开源项目获得。

本书的目标是向三类特定读者展示数据流挖掘技术：

1.  希望将流挖掘作为工具使用的读者，他们没有扎实的算法或编程背景，但具备基本的数据挖掘背景。例如管理、商业智能或市场营销等领域的学生或专业人士。我们以面向任务（而非面向算法）的方式，提供了 `MOA` 的实践入门介绍。

2.  希望在数据流挖掘领域进行研究或创新的读者。他们希望了解算法、评估方法等的细节，以便创建新算法或使用现有算法，评估其性能，并可能将其集成到应用中。这类读者包括计算机或数据科学领域的高年级本科生、硕士生和博士生，以及创新环境中的开发人员。

3.  除了上述需求外，还希望尝试在 `MOA` 中加入新算法，并可能将其贡献给该项目的读者。他们需要了解 `MOA` 的类结构，以及如何为 `MOA` 创建新学习器等。

为实现这一目标，本书分为三部分。第一部分是大数据流挖掘的快速入门。它包含三章：两章介绍大数据挖掘和挖掘数据流的基本方法论，还有一章是面向希望自行上手探索的读者的 `MOA` 实践指南。

# 第一部分：简介

## 1 简介

如今，我们每天都在从各种设备、以不同格式、从独立或关联的应用程序中创造海量数据。这种大数据洪流已超越了我们处理、分析、存储和理解这些数据集的能力。社交网络应用的普及率大幅提升，允许用户自由创建内容，进一步加速了这种急剧扩张，使得本已庞大的 Web 规模持续膨胀。

此外，随着手机成为从不同侧面获取人员实时数据的感知网关，移动运营商潜在可处理的海量数据（旨在改善我们的日常生活）已显著超越过去基于通话详单的处理模式（该模式仅为计费目的而设计）。我们可以预见，物联网应用将把数据规模提升到前所未有的水平。人和设备（从家用咖啡机到汽车、公交车、火车站和机场）都松散地连接在一起。数万亿个此类连接组件将生成一个巨大的数据海洋，必须从中发现有价值的信息，以帮助提高我们的生活质量，让世界变得更美好。例如，我们每天早上起床后，为了优化上班通勤时间并在抵达办公室前完成优化，系统需要处理来自交通、天气、施工、警方活动以及我们日程安排的信息，并在严格的时间限制下执行深度优化。

为了应对这种惊人的海量数据，我们需要能够在合理资源消耗下实时运行的快速高效方法。

### 1.1 大数据

用特定的数据集大小（例如 PB 级）来定义 `big data` 并没有太大用处。一个更有用的定义是：数据集大到无法在不使用非标准算法或技术的情况下进行管理，特别是当它要用于知识抽取时。

虽然二十年前人们还在为 GB 级数据而苦恼，但在撰写本书时，表 1.1 中对应的内存单位介于 TB 和 PB 之间。毫无疑问，再过二十年，我们将从这个位置向下推移几个数量级。

**表 1.1** 以字节为基础的内存单位倍数。

| --- | --- | --- |
| 千字节 (kB, KB) | 10³ | 2¹⁰ |
| 兆字节 (MB) | 10⁶ | 2²⁰ |
| 吉字节 (GB) | 10⁹ | 2³⁰ |
| 太字节 (TB) | 10¹² | 2⁴⁰ |
| 拍字节 (PB) | 10¹⁵ | 2⁵⁰ |

Laney 在文献 [154] 中用大数据管理的“三个 V”来刻画大数据：

*   **容量**：数据量前所未有地庞大，且规模持续增长，但我们的工具能处理的数据比例却没有增加。
*   **多样性**：存在多种不同类型的数据，如文本、传感器数据、音频、视频、图等，我们希望从中提取信息。
*   **速度**：数据以流的形式持续到达，我们有兴趣实时从中获取有用信息。

此后又增加了其他几个 V：

*   **可变性**：数据的结构，或用户解读数据的方式，会随时间变化。
*   **价值**：数据只有在能带来更好决策、并最终形成竞争优势的程度上才具有价值。
*   **有效性与真实性**：部分数据可能不完全可靠，管理这种不确定性非常重要。

#### Gartner 对大数据的定义

Gartner [200] 在 2012 年对大数据的定义中总结道：“高容量、高速度和高多样性的信息资产，需要具有成本效益的创新形式的信息处理，以增强洞察力和决策能力。”

大数据的应用应使人们能够获得更好的服务、更好的客户体验，并更加健康：

*   **商业**：客户个性化和流失检测（客户从一家公司转移到竞争对手）。
*   **技术**：将处理时间从小时缩短到秒级。
*   **健康**：挖掘人们的医疗记录和基因组数据，以监测和改善他们的健康。
*   **智慧城市**：专注于可持续经济发展和高质量生活的城市，并对自然资源进行明智管理。

作为大数据挖掘实用性的一个例子，我们参考 Global Pulse [236] 的工作，该工作利用大数据改善发展中国家的生活。Global Pulse 是联合国的一项倡议，作为一个创新实验室运作，其策略是挖掘大数据以：

1.  研究分析实时数字数据的创新方法和技术，以检测早期出现的脆弱性。
2.  组装一个免费的开源技术工具包，用于分析实时数据和共享假设。
3.  建立一个集成的全球 Pulse Labs 网络，在国家层面试点该方法。

大数据挖掘革命不仅限于工业化世界，因为移动设备在发展中国家也在普及。据估计，移动电话超过 50 亿部，其中 80% 位于发展中国家。

##### 1.1.1 工具：开源革命

大数据现象与开源软件革命密不可分。雅虎、Twitter、LinkedIn、Google 和 Facebook 等大公司既受益于开源项目，也为开源项目做出了贡献。一些例子包括：

*   **Apache Hadoop** [16]：一个用于数据密集型分布式应用的平台，基于 `MapReduce` 编程模型和 `Hadoop Distributed File System (HDFS)`。`Hadoop` 允许我们编写应用程序，在计算节点集群上并行快速处理大量数据。
*   **与 Apache Hadoop 相关的项目** [260]：`Apache Pig`、`Apache Hive`、`Apache HBase`、`Apache ZooKeeper`、`Apache Cassandra`、`Cascading`、`Scribe` 和 `Apache Mahout` [17]（主要基于 `Hadoop` 的可扩展机器学习和数据挖掘开源软件）。
*   **Apache Spark** [253]：一个用于大规模数据处理的引擎，运行在 `Hadoop` 基础设施上。`Spark` 提供了一个库栈，包括 `SQL` 和 `DataFrames`、`MLlib`（用于机器学习）、`GraphX` 和 `Spark Streaming`。这些库可以在同一个应用程序中轻松组合。
*   **Apache Flink** [62]：一个流数据流引擎，为分布式计算提供数据分发、通信和容错。`Flink` 包含多个用于创建应用程序的 API。如果 `Apache Spark` 是一个批处理引擎，可以使用微批次通过 `Spark Streaming` 模拟流处理，那么 `Apache Flink` 就是一个流处理引擎，也可以执行批处理。
*   **Apache Storm** [168]：用于流数据密集型分布式应用的软件，类似于 `Apache S4` 和 `Apache Samza`。
*   **TensorFlow** [1]：一个用于机器学习和深度神经网络的开源包。

### 1.2 大数据挑战

大数据管理和分析的未来面临许多挑战，源于数据的本质：大量、多样和不断演变 [128]。研究人员和从业者在未来几年将不得不面对的一些挑战包括：

*   **分析架构**。目前尚不清楚如何构建最优的分析系统架构，以同时处理历史数据和实时数据。Nathan Marz [169] 提出了 `Lambda` 架构作为首个方案。`Lambda` 架构通过将问题分解为三层来解决实时计算任意数据上任意函数的问题：批处理层、服务层和速度层。它在同一系统中结合了用于批处理层的 `Hadoop` 和用于速度层的 `Storm`。一个较新的提议是 `Kappa` 架构，由 LinkedIn 的 Kreps [152] 提出。它简化了 `Lambda` 架构，移除了批处理系统。
*   **评估**。实现统计学显著结果很重要，不能被随机性误导。如果不妥善处理“多重假设问题”，在海量数据集和数千个同时待答问题面前很容易出错，Efron [95] 对此有解释。此外，避免只关注误差或速度等技术指标而忽视现实世界影响的陷阱也很重要，Wagstaff [242] 讨论了这一点：只有定期发布符合本文中解释的挑战问题合理标准的应用，才能反驳认为大数据全是炒作的观点。
*   **分布式挖掘**。许多数据挖掘技术并非易于并行化。要获得某些方法的分布式版本，需要通过实际实验和理论分析进行大量研究。
*   **时变数据**。数据可能随时间演变，因此大数据挖掘技术能够适应变化，并在某些情况下显式检测变化非常重要。本书中的许多数据流挖掘技术正是由这一需求驱动的 [110]。
*   **压缩**。处理大数据时，存储所需的空间量非常相关。主要有两种方法：压缩（不丢失信息）和采样（选择被认为有代表性的数据）。使用压缩，我们用更多时间换取更少空间，可视为从时间到空间的转换。使用采样，我们丢失信息，但空间收益可能达到数量级。例如 Feldman 等人 [99] 使用核心集来降低大数据问题的复杂度；核心集是数据的一个小子集，可针对给定问题可证明地近似原始数据。
*   **可视化**。大数据分析的一个主要问题是如何可视化结果。以人类可理解的方式呈现来自大量数据的信息是一项挑战。这需要新的技术和框架来讲述故事，如精美书籍 *The Human Face of Big Data* [228] 所涵盖的内容。
*   **隐藏的大数据**。大量有用数据实际上毫无用处，因为它们未标记、基于文件且非结构化。2012 年 IDC 的大数据研究 [117] 解释说，2012 年数字宇宙中 23%（643 EB）的数据如果经过标记和分析将对大数据有用。然而，当时只有 3% 的潜在有用数据被标记，分析的更少。近年来数据可能变得更糟。开放数据和语义 Web 运动的出现，部分是为了让我们意识到并改善这一状况。

### 1.3 实时分析

大数据场景的一个特例是实时分析。组织不仅需要立即获得查询答案，还需要根据刚刚到达的数据来获得答案。

#### 1.3.1 数据流

##### 数据流

*数据流* 是一种算法抽象，用于支持实时分析。它们是项目的序列，可能是无限的，每个项目都有一个时间戳，因此具有时间顺序。数据项逐个到达，我们希望实时构建并维护这些项目的模型，例如模式或预测器。处理流式数据时存在两个主要的算法挑战：流数据量大且速度快，我们需要实时从中提取信息。这意味着通常我们需要接受近似解，以便使用更少的时间和内存。此外，数据可能在演变，因此当数据发生变化时，我们的模型必须能够适应。

##### 时间与内存

准确性、时间和内存是流挖掘过程的三个主要资源维度：我们关注的是那些能以最少的时间和较低的总内存获得最大准确性的方法。稍后我们将展示，通过将内存和时间结合在一个单一的成本度量中，可以将评估简化为一个二维任务。另请注意，由于数据以高速到达，无法被缓冲，因此处理单个项目的时间与总时间一样重要，而总时间通常是传统数据挖掘中考虑的指标。

##### 应用

流式数据有许多场景。这里我们提供几个示例领域：

*   **传感器数据与物联网**：每天，工业界使用更多的传感器来监控流程并提高其质量。城市开始部署庞大的传感器网络，以监控人员流动、检查桥梁和道路的健康状况、城市交通、人们的生命体征等。
*   **电信数据**：电信公司拥有大量的通话数据。如今，移动通话和手机位置是需要处理的海量数据源，通常要求实时处理。
*   **社交媒体**：Facebook、Twitter、LinkedIn 和 Instagram 等社交网站的用户持续产生关于其互动和贡献的数据。话题与社区发现以及情感分析只是由此产生的实时分析问题中的两个例子。
*   **市场营销与电子商务**：销售企业实时收集大量交易数据，可对其进行分析以挖掘价值。检测电子交易中的欺诈行为至关重要。
*   **医疗保健**：医院在照顾病人时会收集大量时效性数据，例如监测病人的生命体征，如血压、心率和体温。远程医疗也将在病人居家时对其进行监测，可能包括通过独立传感器获取的日常活动数据。此外，系统还可能包含实验室检测结果、病理报告、X 光片和数字影像。其中一些数据可用于实时提供病人病情变化的预警。
*   **流行病与灾难**：源自互联网的数据流可用于检测流行病和自然灾害，并可与疾病控制和预防中心及灾害控制和预防中心的官方统计数据相结合 [63]。
*   **计算机安全**：计算机系统必须免受硬件、软件和信息的盗窃与损坏，以及所提供服务的中断或误导，特别是内部威胁检测 [11, 229] 和入侵检测 [194, 195]。
*   **电力需求预测**：供应商需要提前一段时间知道客户将请求多少电力。这些数字随一天中的时间、一年中的季节、地理位置、天气、经济状况、客户习惯以及许多其他因素而变化，使其成为一个在海量分布式数据上的复杂预测问题。

## 本书内容

在大数据的众多方面中，本书专注于从数据流中进行挖掘和学习，因此专注于对高速到达的序列数据执行数据分析的技术。在定义大数据的诸多“V”特征中，我们主要解决的是**速度** 问题。

这些技术通过 `MOA`（大规模在线分析）以实操方式进行演示。`MOA` 是最流行的开源数据流挖掘框架，拥有非常活跃且不断壮大的社区。它包含一系列机器学习 (ML) 算法（分类、回归、聚类、模式挖掘、异常检测、变化检测和推荐系统）以及评估工具。`MOA` 与 `WEKA` 项目相关，同样使用 Java 编写，但设计用于扩展以应对更苛刻的问题。

第一部分介绍大数据领域、主要技术概览以及 `MOA` 使用的初步实操指南。第二部分详细介绍了大量流挖掘算法，优先介绍已在 `MOA` 中实现的算法，并为有兴趣深入了解的读者提供相关文献指引。第三部分深入探讨 `MOA`。它提供了一些额外的实操练习和 `MOA` 的部分内部结构，面向希望向 `MOA` 添加算法、修改现有算法，或通过其 API 在应用程序中使用 `MOA` 的读者。
