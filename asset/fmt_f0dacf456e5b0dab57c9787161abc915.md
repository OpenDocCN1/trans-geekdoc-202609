##### 容器

`Containers`（容器）提供应用级虚拟化。容器不创建需要自己操作系统的复杂虚拟机，而是打包应用程序，允许将它们视为可跨操作系统和硬件平台移植的虚拟化单元。

实施容器化的组织运行容器化平台（如 `Docker`），这些平台为操作系统资源提供标准化接口。无论底层操作系统或硬件如何，此接口保持一致，接口的一致性使容器能根据需要在系统间移动。

容器化平台与虚拟化平台共享许多相同的安全考量。它们必须强制执行容器间的隔离，以防止运行在一个容器中的应用程序意外或故意与分配给另一个容器的资源交互而导致运营和安全问题。

### 云网络

云网络遵循与其他云基础设施资源相同的虚拟化模型。云消费者可访问网络资源以连接其其他基础设施组件，并能根据需要配置带宽以满足其需求。

云网络通过允许工程师通过 API 与云资源交互和修改，支持了 `软件定义网络 (SDN)` 运动。同样，它们为网络安全专业人员提供了 `软件定义可视性 (SDV)`，使其能够洞察其虚拟网络上的流量。

#### 安全组

安全专业人员在其物理网络上使用防火墙，以限制允许进入组织安全边界的网络流量类型。云服务提供商也实施了防火墙，但它们不向客户提供对这些防火墙的直接访问权限，因为这样做会违反隔离原则，因为这可能允许一位客户对防火墙进行更改，从而影响其他客户。

相反，云服务提供商通过使用 `安全组` 来满足防火墙的需求，安全组定义了允许的网络流量。这些安全组由一组网络流量规则组成，这些规则与防火墙规则集实质上相同。图 10.17 展示了一个安全组的示例。

![图 10.17 限制对云服务器访问的安全组](img/c10f017.png)

**图 10.17** 限制对云服务器访问的安全组

安全组通常被视为提供商虚拟服务器的一项功能，因此不会产生额外费用。

#### 虚拟私有云 (VPC)

`分段` 是网络安全的核心概念之一。分段允许网络工程师将不同安全级别和功能的系统放置在不同的网络子网上。类似分组的系统能够相互通信，同时与其他网段上的系统保持隔离。

在物理网络中，网络和安全专业人员使用虚拟局域网 (VLAN) 技术来实现分段。在云环境中，`虚拟私有云 (VPC)` 起到相同的作用。使用 VPC，团队可以将系统分组到子网中，并根据是否允许从互联网访问，将这些子网指定为公共或私有。云提供商还提供 `VPC 终端节点`，允许使用云提供商的安全网络骨干将 VPC 相互连接。云 `传输网关` 进一步扩展了这一模型，允许云 VPC 与本地 VLAN 直接互联，以实现混合云操作。

组织和运行技术团队的传统方法侧重于以技术角色为中心构建专业知识孤岛。特别是，软件开发和技术运维通常被视为截然分离的两个领域。开发人员致力于创建业务所需的软件应用程序，并拥有自己的一套流程来指定需求、设计接口、编写代码、测试应用程序和维护代码库。当他们完成新版本应用程序的测试后，会将其移交给技术运维团队，由后者管理支持该应用程序的服务器和其他基础设施。

将开发和运维世界分离开来，为技术人员提供了一个舒适的工作环境，他们的任务定义清晰，且周围是同行社区。然而，这也带来了显著的劣势，包括以下几点：

*   将运维团队与开发过程隔离开来，阻碍了他们对业务需求的理解。

*   将开发人员与运维考量隔离开来，导致设计在处理器、内存和网络消耗方面显得浪费。

*   要求从开发到运维的明确移交，通过要求漫长的过渡阶段，降低了敏捷性和灵活性。

*   增加与过渡相关的开销，鼓励将许多小的修复和增强合并为一个主要版本，从而增加了满足需求的时间。

认识到将开发和运维团队分离的固有劣势，许多组织现在采用 `DevOps` 方法进行技术管理。这种方法将开发和运维团队聚集在一个统一的过程中，让他们以敏捷的方式共同进行软件开发。软件测试和发布过程变得高度自动化和协作化，使组织能够从漫长的发布管理流程转变为每天可能发布数十次更新的世界。

`基础设施即代码 (IaC)` 是 DevOps 运动背后的关键赋能技术之一，也是云计算服务集成的关键优势之一。IaC 是通过脚本代码而非人工干预，自动完成基础设施服务的预配、管理和取消预配的过程。IaC 是所有主要 IaaS 环境（包括 AWS、Microsoft Azure 和 Google Cloud Platform）的关键特性之一。

IaC 形式多样，既可以是云服务提供商提供的一项功能，也可以是由第三方云管理平台启用的功能。在大多数情况下，运维团队通过云提供商的 Web 界面可用的操作，也都可通过代码实现。

AWS 提供了一项名为 `CloudFormation` 的服务，允许开发人员以多种格式指定其基础设施需求，包括 `JavaScript 对象表示法 (JSON)` 和 `YAML Ain't Markup Language (YAML)`。图 10.19 展示了一个用于 EC2 实例的 JSON 规范示例。

### 云安全问题

云为组织带来了巨大的运营和财务优势，但这些优势也伴随着云环境中出现的新安全问题。

#### 可用性

##### 云环境中的可用性问题

正如在本地部署环境中一样，可用性问题也存在于云环境中。云的主要优势之一是云服务商可能在许多不同的地理区域运营，并且它们通常提供简单的机制，用于跨这些区域备份数据和/或跨不同可用区以高可用性模式运行。例如，一家在云中运行 Web 服务器集群的公司可能会选择在每个主要大洲部署服务器，以服务这些地区的客户，并在特定地理区域发生大规模问题时提供地理多样性保障。

#### 数据主权

正如您刚才所读，云计算的分布式特性涉及使用地理位置遥远的设施来实现高可用性，并将内容放置在靠近用户的位置。这可能意味着客户的数据存储并处理在许多不同国家的数据中心中，无论是否有明确通知。除非客户了解其数据的存储方式，否则这可能会引发法律问题。

**数据主权**是一项原则，规定数据受其被收集、存储或处理所在司法管辖区的法律限制。根据这一原则，客户可能会受制于某个司法管辖区的法律要求，而他们与该司法管辖区唯一的关联仅在于其云服务商在该管辖区内运营一个数据中心。

负责管理云服务的安全专业人员应确保了解其数据如何跨司法管辖区存储、处理和传输。他们也可以选择使用仍保留在服务商控制之外的密钥来加密数据，以确保其对数据保持唯一控制权。

#### 虚拟化安全

**虚拟机逃逸**漏洞是虚拟化环境中可能存在的最严重问题，特别是在虚拟主机运行不同安全级别的系统时。在逃逸攻击中，攻击者拥有对单个虚拟主机的访问权限，然后设法利用该访问权限侵入分配给另一台虚拟机的资源。Hypervisor（虚拟机监视器）本应通过将虚拟机的访问限制在仅分配给该机器的资源上来防止此类访问。逃逸攻击允许在虚拟机上运行的进程“逃逸”出这些 Hypervisor 限制。

**虚拟机蔓延**发生在 IaaS 用户创建虚拟服务实例后将其遗忘或放弃，导致这些实例随着时间推移产生费用并积累安全问题。组织应保持实例感知，以避免虚拟机蔓延问题。

#### 应用安全

云应用遭受许多与其他应用相同的安全问题。这些软件安全问题已在第 6 章“安全编码”中介绍。

云应用高度依赖应用程序编程接口（API）来提供服务集成和互操作性。除了实施第 6 章中讨论的安全编码实践外，负责基于 API 应用的安全分析师还应实施**API 检查**技术，以审查 API 请求中的安全问题。这些功能通常存在于 Web 应用防火墙解决方案中。

**安全 Web 网关（SWG）**也为依赖云的组织提供了一层应用安全。SWG 监控内部用户发出的 Web 请求，并根据组织的安全策略进行评估，阻止违反这些要求的请求。SWG 通常用于阻止访问潜在恶意内容，但也可用于强制执行内容过滤限制。

#### 治理与审计

技术治理工作指导 IT 组织的工作，并确保其与组织战略和政策保持一致。这些工作还应指导云供应商关系的建立和维护。云治理工作有助于：

*   审查拟建立云合作伙伴关系的供应商

*   管理供应商关系并监控供应商稳定性问题的早期预警信号

*   监督组织的云活动组合

**可审计性**是云治理的重要组成部分。云计算合同应包含保证客户有权审计云服务提供商的条款。他们可以选择自行执行这些审计，或聘请第三方进行独立审计。审计的使用对于向客户提供保证至关重要，即提供商正在以安全的方式运营并履行其合同数据保护义务。

### 云安全控制

云服务商和第三方组织提供各种解决方案，帮助组织在云中实现其安全目标。组织可以选择采用其云服务商提供的云原生控制、第三方解决方案，或两者的结合。

云服务商提供的控制具有与服务商产品直接集成的优势，通常使其具有成本效益且用户友好。第三方解决方案通常成本较高，但它们带来了与多种云服务商集成的优势，便于多云环境的管理。

#### 云访问安全代理

大多数组织出于不同目的使用多种云服务商。大型组织从数十家甚至数百家不同的提供商处购买云服务并不罕见。当组织使用高度专业化的 SaaS 产品时，这种情况尤为常见。在这些服务中一致地管理安全策略对网络安全分析师构成了重大挑战。

**云访问安全代理（CASB）**是充当云服务用户和云服务提供商之间中介的软件工具。这种定位使它们能够监控用户活动并强制执行策略要求。CASB 采用两种不同的方法运行：

*   **内联 CASB 解决方案**在物理或逻辑上驻留在用户和服务之间的连接路径中。它们可以通过硬件设备或将请求路由通过 CASB 的端点代理来实现这一点。这种方法需要配置网络和/或端点设备。其优势在于可以在请求发送到云服务之前看到它们，从而允许 CASB 阻止违反策略的请求。

*   **基于 API 的 CASB 解决方案**不直接与用户交互，而是通过提供商的 API 直接与云提供商交互。这种方法提供了对云服务的直接访问，且不需要任何用户设备配置。然而，它也不允许 CASB 阻止违反策略的请求。基于 API 的 CASB 仅限于监控用户活动，并在事后报告或纠正策略违规。

#### 资源策略

云服务商提供**资源策略**，客户可用其限制其账户用户可执行的操作。实施资源策略是一种良好的安全实践，可限制意外命令、账户泄露或恶意内部人员造成的损害。
