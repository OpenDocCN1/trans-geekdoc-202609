
# 访问管理

## 简介

在上一章中，您了解了与物理安全管理相关的术语和实践。在本章中，讨论将转向与 IT 和 OT 网络相关的逻辑访问控制模型和实践。

这些策略的设计应反映与经典信息安全模型相关的三个目标：`机密性`、`完整性` 和 `可用性` (`CIA`)。然而，请回顾第 5 章 "ICS 网络安全要点" 中的内容，在 OT 环境中，`AIC` 方法通常比 IT 网络环境中使用的传统 CIA 努力更为重要。

任何网络的“执法者”都是 `网络管理员`。在网络环境中，这些人负责在网络设备上实施组织的安全策略。在大型组织中，通常会创建专门的管理角色来处理网络运营的不同方面。这可能包括设立单独的服务器管理员和网络管理员。`服务器管理员` 或 `系统管理员` (`sysadmin`) 负责组织安全策略及服务器计算机的设计、实施和维护，而网络管理员则为网络及其介质和连接设备提供相同的职能。

管理职责的划分还可能涉及专门的安全管理员，其负责为网络中的服务器、主机和连接设备执行信息安全任务。在这些环境中，管理职责的分离应尽可能清晰、明确且受控。

通常，这些管理员中的一位负责确定谁获得网络服务器、网络连接设备和数据的操作访问权。在大多数组织中，他们通过网络操作系统管理工具实施组织的策略声明，这些工具控制“谁”有权访问网络及其资源，以及他们可以对这些资源做什么。在第 4 章 "ICS 模块与要素加固" 中，您了解了三种传统访问控制模型。这些传统模型已通过此处描述的额外访问控制模型得到增强：

*   `强制访问控制 (MAC)`：系统建立哪些用户或组可以访问文件、文件夹和其他资源。
*   `自主访问控制 (DAC)`：这包括用户有自由裁量权决定谁可以访问其对象以及访问程度的配置。
*   `非自主、基于角色的访问控制 (RBAC)`：这基于每个用户在组织中的工作角色。
*   `基于规则的访问控制 (RB-RBAC)`：与 RBAC 类似，RB-RBAC 首先基于工作角色，但随后通过规则集进一步限制以修改角色内的访问权限。
*   `基于属性的访问控制 (ABAC)`：这包括基于策略的身份和访问控制管理，通过组合属性来授予或拒绝访问。该概念在 NIST 网络安全框架中引入，并与主体、操作、客体和上下文属性相关联，这些属性在 if-then-and 布尔语句中组合使用。
*   `基于上下文的访问控制 (CBAC)`：这是一种防火墙中的访问控制模型，用于维护 TCP/UDP 网络流量以进行更深层的数据包有效载荷检查。

## 访问控制模型

`访问控制` 本质上是一种策略，用于识别从事特定工作的人员，通过某种识别系统对其进行认证，然后仅授予他们访问所需资产所需的“钥匙”，而不授予更多权限。在上一章中，您了解了访问控制在物理基础设施环境中是如何提供的。

在 IT 环境中，这始于为用户提供用户名和密码，以便进入完成工作所需的计算设备、文件、文件夹和网络连接。然后，必须配置他们对每个资产的访问级别，以确保他们拥有完成工作所需资源的适当权限级别。Bob 是否需要创建（完全控制）原始文档的能力，还是仅负责编辑它们（写入），抑或只是审阅它们（读取）？为了实现这一点，管理员必须确定每个组或个人执行职责所需的权限级别。这就是访问控制模型发挥作用的地方。

### 强制访问控制

回顾第 4 章，`MAC` 策略为网络对象分配敏感度标签，并根据用户的权限级别授予访问权，如图 7.1 所示。在此模型下，只有所有者（和指定的保管人，即管理员）被授予访问控制的管理权。这意味着最终用户无法控制任何提供特权给任何人的设置。

MAC 安全模型实际上有两个版本——一个侧重于 `数据机密性` (Bell-LaPadula)，另一个侧重于 `数据完整性` (Biba)。`Bell-LaPadula` 版本规定，处于特定安全级别（例如绝密）的用户可以在该级别写入，但不能在较低级别写入。然而，他们可以在较低安全级别读取（上写/下读）。`Biba` 版本允许较低安全级别的用户读取较高级别，而较高安全级别的用户可以为较低安全级别写入（上读/下写）。

Biba 通常用于企业网络，管理层可在其中编写信息供员工阅读。Bell-LaPadula 更常见于政府/军事网络，其中的安全许可级别决定了任何用户有权访问哪些类型的信息。如果你没有某资产的适当许可，则无需知晓其存在。

### 自主访问控制

`DAC 模型`是限制最少的访问控制模型，因为它赋予单个用户对其拥有的资产以及任何相关资产的完全控制权。这在 `DAC 模型`中造成了两大弱点。

1.  首先，所有者被赋予了为其他用户设置安全级别的能力，这可能导致他们拥有超出应有范围的特权。
2.  其次，用户拥有的权限将通过继承扩展到其他资产。这使用户在不知情的情况下执行恶意软件。此类恶意软件可能会利用用户的扩展特权访问系统中更高层级的数据。

### 基于角色的访问控制

`RBAC 模型`根据用户在组织中的职位提供访问控制。每个网络用户或组被分配一个或多个角色，如图 7.2 所述。

然后为每个角色分配对特定对象的特定特权。

在大多数情况下，`RBAC 模型`使网络管理员更容易管理中型或大型网络中的多个用户。然而，当引入具有特殊工作职责（超出群组范围）的用户进入网络时，必须采取特殊措施为他们提供额外的访问需求。

### 基于规则的访问控制

在 `基于规则的访问控制` 模型下，网络管理员像前面描述的基于角色的方法一样定义用户角色，然后为这些定义实施规则标准，例如时间限制，以防止用户在工作时间之外访问数据。

在每种策略类型中，在通过权利和权限分配为用户提供对象访问权限时，都应实施最小权限原则。根据最小权限规则，每个用户仅被授予执行其工作角色所需的访问级别。始终如一地应用此原则，将安全漏洞造成的损害限制在初始任务、进程或用户范围内。

### 基于属性的访问控制

与前面列出的四种传统基于用户的访问控制模型相比，`基于属性的访问控制` (`ABAC`) 被认为是一种新一代的 AC 模型，基于源自策略语句的复杂布尔规则集。该模型操纵三类组件来确定对资源的访问或拒绝。

*   `架构`：`ABAC` 应用于三点架构中的应用和数据：策略执行点 (`PEP`)、策略决策点 (`PDP`) 和策略信息点 (`PIP`)。
*   `属性`：属性描述 `主体`（尝试访问资源的用户）、`操作`（正在尝试的活动）、`客体`（被访问的资源）和环境（可能涉及时间、位置、IP 地址或其他控制因素的上下文）。
*   `策略`：这些是结合在一起以确定是授予还是拒绝访问的场景和技术语句。

当请求访问资源时，`PEP` 检查请求并向 `PDP` 部分发送授权请求。`PDP` 将请求与其策略语句进行比较，并咨询 `PIP` 以获取外部数据链接，然后发出许可/拒绝决定。图 7.3 描述了 `ABAC` 过程。

### 基于上下文的访问控制

`基于上下文的访问控制` (`CBAC`) 是防火墙中使用的一种智能深度包过滤功能，允许指定的 TCP/UDP 流量通过防火墙。它利用从应用层协议获得的有状态检查信息在防火墙的 `ACL` 中打开端口。这增强了 `ACL` 的作用，后者仅提供高达传输层的访问控制。

`CBAC` 在防火墙内存中维护一个状态表。当受信网络内的设备发起会话时，会在状态表中放置一个动态条目，并允许流量通过防火墙并流出网络。`CBAC` 机制在防火墙的 `ACL` 中为请求的会话打开一个临时漏洞，以允许出站流量的 `回复` 通过并进入受信网络。`CBAC` 仅允许由受信网络内部设备发起的外部流量进入网络。

## 访问控制中的关键安全组件

在前面描述的 AC 模型中，逻辑访问控制主要在服务器级别实现，并基于四个关键安全组件：

*   `密码`：密码是现存最基本的逻辑访问控制机制。密码的使用和要求之前已在 第 4 章 中介绍，因此此处不再赘述。
*   `组策略`：这些是目录服务数据库对象，管理员使用它们根据用户在组织中的职位和工作角色创建对网络资产的组访问和限制。这些对象使管理员能够从单一管理环境跨网络实施这些策略。
*   `访问控制列表 (ACLs)`：`ACLs` 是将权限附加到网络对象的列表，系统使用它们来控制对资产（程序、文件夹、文件、打印机）的访问，以及可以在这些资产上执行的活动。
*   `用户账户限制`：账户限制是添加到模型中的最后一个访问控制组件。这些是管理员应用于用户账户（而非文件夹、文件和打印机）的配置，旨在限制其在本地计算机（本地账户）或整个网络（域账户）上的活动。

## 目录服务

管理员依赖的用于跨网络管理访问控制的工具之一，是运行在网络服务器操作系统上的目录服务结构。`目录服务` 是分布式、可定制的信息存储结构，提供了一个单一节点，用户可从中搜索和定位分散在整个网络中的资源。

这些结构还为网络管理员提供了一个管理网络对象和资源的单一管理点。这些资源通常包括关于用户（姓名、电子邮件地址等）和系统（主机、文件共享、打印机等）的信息。它们是任何中大型企业网络的必需品。因此，企业级目录服务通常为网络提供几项关键功能：

*   可跨多个地理位置分布的信息存储
*   用户可用来高效搜索分布在整个网络中的信息的信息存储
*   可从多种不同操作系统访问的信息存储
*   随网络发展可接受新对象的信息存储

最知名的目录服务结构莫过于互联网基于的 `域名系统` (`DNS`)。企业网络级目录服务首次亮相于 Novel Netware 操作系统，称为 `Novel Directory Service` (`NDS`)。该结构后来从 Novell 购买并重新品牌为 `NetIQ` eDirectory。

## 企业网络中的目录服务

您在当前企业网络中可能遇到的目录服务均基于 `Lightweight Directory Access Protocol` (`LDAP`)，也称为 `X.500-lite standard`。该协议提供了一种与供应商无关的协议，用于通过 IP 网络创建和访问控制分布式网络目录服务。已有许多不同的 DS 软件产品基于 LDAP 协议开发。以下章节将讨论用于 Microsoft Windows 和 Linux 网络环境的目录服务。

### Active Directory

Microsoft Windows 网络架构的核心特性是 `Active Directory` (`AD`) 结构。Active Directory 是一个用户和资源信息的分布式数据库，用于描述网络的构成（即用户和应用程序设置）。它也是实现分布式身份验证过程的一种方法。

Windows 仍然是一个依赖域的操作系统。它将域用作管理、安全和复制目的的边界。每个域必须至少由一个域控制器来代表。域控制器是一台设置为保存网络目录数据库的服务器。

此数据库包含有关用户账户、组账户和计算机账户的信息。它跟踪域内所有对象的名称和资源请求。您可能还会发现此数据库被称为 `Security Accounts Manager` (`SAM`)。此功能有助于在 Windows 客户端网络中集中管理系统和用户配置，以及服务器上的数据备份。

Active Directory 结构采用了两种常见的 Internet 标准——LDAP 和 DNS。LDAP 协议用于定义目录信息如何被访问和交换。DNS 是将域名解析为实际 IP 地址的 Internet 标准。它也是与客户端和其他目录交换目录信息的标准。

Active Directory 以层次结构排列域，并在树状结构中建立所有域之间的信任关系，如图 7.4 所示。

**图 7.5** Active Directory 关系

Windows 操作系统通过双向信任自动将树内的所有域连接起来。`信任` 是允许用户在域之间移动并执行规定操作类型的关系。

如果在示例中销售域与市场域之间建立了信任关系，且销售域与管理域之间存在类似的信任，则市场域与管理域之间也存在信任关系。信任使管理员能够为用户和组提供对对象的不同权限。

`权限` 是控制用户（或用户组）访问对象和执行操作（如读取或写入文件）权威的权限设置。管理权限提供对用户的权威，直至组织单位 (OU) 级别。OU 是容纳网络域内所有对象的容器。这些单位可通过容纳其他 OU 来为域提供层次结构。

管理权限不跨越域级别建立的边界，但可以被同一树中具有从属位置的其他 OU 继承。另一方面，用户权限必须为单个用户或组成员建立。使用组可以通过单个管理操作将通用权限分配给多个用户（这与为每个人单独设置和维护权限形成对比，例如为 150 人的会计人员设置权限）。

处理 Active Directory 的主要工具是 `Active Directory Users and Computers` 控制台，如图 7.6 所示。域的组织单位包含用户、组和资源。Active Directory Manager 工具用于向目录中添加用户、组和组织单位。

Windows 环境的整体运行由 `系统策略` 管辖。基本上，策略赋予管理员对用户的控制权。使用系统策略，系统管理员可以授予或限制用户对本地资源（如驱动器和网络连接）的访问。

管理员可以建立策略，强制特定用户在指定时间登录，并在其他所有时间将其锁定在系统之外。系统策略还使管理员能够发送更新并为网络客户端配置桌面。从根本上说，控制面板中找到的任何项目都可以通过系统策略进行管控。

通过组策略，管理员可以为整个企业的用户制定大量详细设置，而无需手动建立每一项设置。GPO 可用于通过 AD 向计算机和用户应用大量更改。

### Linux 目录服务

较旧的 Linux 发行版支持一种称为 `Network Information Services` (`NIS`) 的目录服务结构。然而，较新的发行版已转向基于 LDAP 的目录服务。这些包括 Red Hat 的 389 Directory Server、Apache Directory Server 和 OpenLDAP，以及一系列鲜为人知或专有的目录服务器平台。

与 Active Directory 一样，基于 LDAP 的 Linux 平台为系统信息查找和身份验证提供单一目录源。将用户信息存储在基于 LDAP 的目录服务器中，使网络具有可扩展性、可管理性和安全性。

与 Microsoft 的 AD 不同，目录服务不是 Linux 操作系统结构的组成部分。相反，它们是在操作系统安装后添加到结构中的。然而，安装后，基于 Linux 的目录服务模块采用基于 GUI 和菜单驱动的工具（如图 7.7 所示）来定义网络的组织单位。

![图 7.7 Linux 目录服务菜单](img/c07f007.png)

通常，这些目录服务服务器提供基于网络的注册表，使管理员能够集中存储用户身份和应用程序信息，例如：

*   应用程序设置
*   用户配置文件
*   组权限
*   策略
*   访问控制数据

通过在目录结构中存储和检索此类信息，用户和应用程序变得与位置无关。用户能够登录到网络中的任何位置，并访问其在指定位置或网络中任何其他位置所拥有的相同应用程序和数据。

## 应用程序运行时与执行控制

软件应用程序变得日益复杂、分布式和互联。向云计算、容器化和混合架构解决方案的转变增加了这些应用程序的攻击面。随着这些变革重新定义了我们 IT/OT 网络架构模型中的边缘和边界术语，提供额外安全性的压力也随之增加。

## 运行时攻击

运行时攻击是基于内存的攻击，利用应用程序在运行时内存中执行的代码。攻击者利用应用程序代码与数据之间缺乏边界的特性，将恶意代码注入内存结构。这类攻击传统上极难检测和防御。
