
# Cable modems

`Cable modems` 由有线电视提供商用于通过宽带有线电视提供互联网接入。有线电视接入并非无处不在，但在工业化地区的大多数大城镇和城市都可用。宽带与基带不同，拥有多个信道（如电视频道），因此为网络服务分配带宽需要为此目的专用信道。有线调制解调器为有线电视公司提供了一个引人注目的“最后一英里”解决方案：他们已经投资连接了最后一英里，而互联网服务则基于该投资提供了另一条收入来源。

与 DSL 不同，有线调制解调器带宽通常与同一网段上的邻居共享。

## 回拨和来电显示

`Callback` 是一种基于调制解调器的认证系统。创建回拨账户时，会将用户拨打的调制解调器号码录入账户。用户稍后通过调制解调器连接并进行认证。系统挂断后，再回拨到预配置的号码。

`Caller ID` 是一种类似的方法：除了用户名和密码外，它要求从正确的电话号码拨打。来电显示很容易被伪造：许多电话服务商允许最终用户选择任何他们想要的来电显示号码。这使得来电显示成为一种薄弱的认证形式。

## 远程桌面控制台访问

许多用户需要远程访问计算机的控制台。自然，应使用某种形式的安全通道，如 `IPsec VPN`、`SSH` 或 `SSL` 隧道，以确保连接的机密性，特别是当连接源自组织外部时。有关远程控制台访问这一层的更多详细信息，请参阅上文的“VPN”部分。

几十年来，使用协议远程访问控制台一直是常见做法，例如类 UNIX 操作系统上明文且认证薄弱的 `rlogin` 和 `rsh`，它们分别利用 `TCP` 端口 `513` 和 `TCP` 端口 `514`。提供远程桌面访问的两种常见现代协议是虚拟网络计算（`VNC`），通常运行在 `TCP 5900` 上，以及远程桌面协议（`RDP`），通常运行在 `TCP` 端口 `3389` 上。`VNC` 和 `RDP` 允许对远程系统进行图形化访问，这与基于终端的旧式远程访问方法形成对比。`RDP` 是微软的专有协议。

越来越多的用户期望能快速、从任意数量的个人设备通过互联网轻松访问图形化桌面。出于安全考虑，传统的基于 `VNC` 和 `RDP` 的方法通常通过 `VPN` 等加密通道进行隧道传输，这使得满足这些期望变得困难。

这些方法的一个近期替代方案是使用反向隧道，它允许建立出站加密隧道的用户通过同一隧道连接回来。这通常需要在用户计算机上安装一个小型代理，该代理将使用 `HTTPS over TCP 443` 发起出站连接。该连接将终止于一台中央服务器，用户可对其进行认证（从办公室外部）以控制其办公室桌面机器。采用这种方法的两个最著名的解决方案是 `GoToMyPC` 和 `LogMeIn`。

## 桌面和应用虚拟化

除了远程访问独立桌面系统外，提供对计算资源远程访问的另一种方法是通过桌面和应用虚拟化。桌面虚拟化是一种提供集中式基础设施的方法，该基础设施托管可由员工远程利用的桌面镜像。桌面虚拟化通常称为 `VDI`，根据相关供应商不同，代表虚拟桌面基础设施或虚拟桌面接口。`VDI` 也称为 `DaaS`（桌面即基础设施）。

与提供完整桌面环境相反，组织可以选择仅虚拟化将集中提供的关键应用程序。与桌面虚拟化一样，应用虚拟化相关的集中控制允许组织实施严格的访问控制，并可能更快地修补应用程序。此外，应用虚拟化还可用于运行传统应用程序，否则这些应用程序将无法在员工使用的系统上运行。

# 虚拟化、远程访问与协作技术

虽然该方法的术语和细节相对较新，但桌面虚拟化和应用虚拟化的底层概念已以瘦客户机、大型主机和终端服务器的形式存在了几十年。无论是新方法还是传统方法，其主要前提都是：与大量更复杂的系统相比，拥有更集中、更整合的计算系统和基础设施可能会带来组织效益。除了通用的“规模经济”理由外，从受到更严格控制的桌面和应用程序环境中，也可能获得安全优势。在集中式环境中修补更复杂的应用程序可能更易于管理。同样，当有一个甚至多个中央主镜像来确定每个相应虚拟桌面的设置时，按照安全基线开发和维护桌面也会更容易实现。

## 屏幕抓取

屏幕抓取提供了一种对系统进行图形远程访问的方法。屏幕抓取协议将绘制被访问系统屏幕所需的信息打包并传输到用于远程访问的系统的显示器上。`VNC`（虚拟网络计算）是一种常用的远程桌面访问技术，从根本上说，它是一种屏幕抓取风格的远程访问方法。并非所有远程访问协议都构建为屏幕抓取器。例如，微软流行的 `RDP`（远程桌面协议）不使用屏幕抓取来提供图形远程访问。

## 多媒体协作

多媒体协作包含一套技术，包括即时消息和远程会议技术。这些技术中的许多都允许文件传输、远程控制 PC、录制音频和视频，以及其他可能给组织带来风险的功能。

### 即时消息

即时消息允许两个或多个用户通过实时“聊天”相互通信。聊天可以是一对一的，也可以是通过聊天组进行多对多的。除了聊天之外，大多数现代即时消息软件还允许文件共享，有时还允许音频和视频会议。

较旧的即时消息协议包括 `IRC`（互联网中继聊天）、`AOL Instant Messenger` 和 `XMPP`（可扩展消息和状态协议，以前称为 Jabber）。这些较旧的即时消息技术通常使用明文 `TCP/IP` 协议传输数据，并且易于在网络上监控。现代即时消息解决方案（如 `Google Talk`、`Discord` 和 `Slack`）使用 `HTTPS` 进行通信，并且难以监控得多。

聊天软件可能面临各种安全问题，包括远程利用，必须像其他软件一样进行修补。聊天软件的文件共享功能可能允许用户通过分发敏感文档来违反策略，这些程序中的音频和视频共享功能也可能引发类似问题。组织应制定控制聊天软件使用的策略，并建立技术控制来监控并在必要时阻止其使用。

### 远程会议技术

远程会议技术是一种较新的技术，允许用户通过互联网进行在线会议，包括桌面共享功能。商业远程会议解决方案包括 `Zoom`、`Citrix Systems` 的 `GoToMeeting` 和 `Microsoft Live Meeting`。这些技术通常包括在所有连接到会议的 PC 上显示 `PowerPoint` 幻灯片、共享电子表格等文档，有时还共享音频或视频。某些解决方案允许用户远程控制另一台连接的 PC。

许多此类解决方案旨在通过出站 `SSL` 或 `TLS` 流量建立隧道，这些流量通常可以通过防火墙和任何 Web 代理。如果站点的远程访问策略要求使用强身份验证的 `IPsec VPN` 连接以允许远程控制内部 PC，这些解决方案可能会绕过现有控制（如强身份验证要求）并违反策略。应理解、控制远程会议技术的使用，并确保其符合所有适用策略。

## 保护第三方连接

许多组织通过 `VPN`、专线等与第三方维护外联网连接。外联网通常用于远程办公室，为合作伙伴组织提供连接，以及供应商支持。这些第三方连接代表了重大风险：第三方可能被攻破，攻击者或恶意软件可能通过外联网连接转向攻击组织本身。这些类型的连接要求组织在一定程度上信任第三方的安全性。

外联网连接应始终通过专线或加密 `VPN` 进行。访问控制列表（`ACL`）应严格控制可通过外联网连接访问的系统。从检测角度来看：应使用增强监控，包括检测被 `ACL` 阻止的系统的尝试连接。应在可通过外联网连接访问的系统上部署强大的基于主机的控制：修补、加固、使用双因素认证等。

## 无线应用协议

无线应用协议（`WAP`）旨在为智能手机等手持无线设备提供安全的 Web 服务。`WAP` 基于 `HTML`，包含 `HDML`（手持设备标记语言）。认证由无线传输层安全（`WTLS`）提供，后者基于 `TLS`。

`WAP` 浏览器是一个微型浏览器，比完整的 Web 浏览器更简单，所需资源更少。它连接到 `WAP` 网关，后者是一个旨在转换网页的代理服务器。微型浏览器访问用（或转换为）`WML`（无线标记语言）编写的站点，后者基于 `XML`。

> **注意**
>
> `WAP` 是一个重载的首字母缩略词，映射到多种技术和协议。在无线方面尤其令人困惑：`WAP` 可能代表无线接入点或无线应用协议。而 `WPA`（Wi-Fi Protected Access）字母相同但顺序不同。
>
> 请勿混淆这些无线协议和技术：考试会明确说明问题涉及哪一个；不要匆忙阅读问题而忽略上下文。此外，不要将 `802.11` 无线安全标准（包括 `WEP` 和 `802.11i`/`WPA2`）与手持设备 `WAP` 安全（`WTLS`）混淆。

## 内容分发网络

内容分发网络（`CDN`，也称为内容交付网络）使用一系列分布式缓存服务器来提高性能并降低下载在线内容的延迟。它们会自动确定离最终用户最近的服务器，以便用户从互联网上速度最快、距离最近的服务器下载内容。示例包括 `Akamai`、`Amazon CloudFront`、`Cloudflare` 和 `Microsoft Azure`。

`CDN` 还能提高可用性，并能减轻拒绝服务攻击的影响：“虽然内容分发网络也解决了改善全球可用性和减少带宽等附带问题，但它们解决的主要问题是延迟：主机服务器接收、处理并交付页面资源（图像、CSS 文件等）请求所需的时间。延迟主要取决于用户距离服务器有多远，并因网页包含的资源数量而加剧。

例如，如果您的所有资源都托管在旧金山，而用户在伦敦访问您的页面，那么每个请求都必须从伦敦到旧金山再返回伦敦进行一次漫长的往返。如果您的网页包含 100 个对象（这处于正常范围的低端），那么用户的浏览器必须向您的服务器发出 100 个单独的请求才能检索这些对象” [\[19\]](#Ch005_225-293_B9780443187346000039.xhtml#bb0100)。

# 考试目标总结

## 通信与网络安全

通信与网络安全是一个庞大且复杂的领域，要求对棘手的技术问题有广泛且有时需要深入的理解。我们的现代世界依赖于网络，而这些网络必须保持安全。不仅要理解我们为何使用分组交换网络和 `OSI` 模型等概念，还要理解我们如何实现这些概念。

我们已经从集线器演进到提供流量隔离的交换机。我们增加了诸如 `HIDS` 和 `NIDS` 之类的检测设备，以及诸如 `HIPS` 和 `NIPS` 之类的防御设备。我们部署了诸如 `TLS` 和 `IPsec` 之类的安全协议。

我们在每一步都改进了网络纵深防御，并提高了网络数据的机密性、完整性和可用性。
