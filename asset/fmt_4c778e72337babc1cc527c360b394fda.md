## BeEF

BeEF 是一个用于 Web 测试的利用框架。BeEF 利用浏览器漏洞并与一个或多个浏览器交互以启动定向命令模块。每个浏览器都可以配置在不同的安全环境中。BeEF 允许你启动一组独特的攻击向量，并选择特定模块来针对每个浏览器和环境。

### 常见的反编译、反汇和调试工具

### GNU 项目调试器 (GDB)

GNU 项目调试器（`GDB`）是软件开发者和安全专业人员中最受欢迎的调试器之一。通过像`GDB`这样的调试器，你可以对软件进行故障排除并查找软件漏洞，理解程序在崩溃瞬间正在做什么，让程序在特定条件下停止，并修改程序的元素以进行实验或修复问题。

传统上，`GDB`主要用于调试用 C 和 C++ 编写的程序；然而，它也支持其他几种编程语言——例如 Go、Objective-C 和 OpenCL C。

**注意** 要查看支持的编程语言完整列表，请访问 [`www.gnu.org/software/gdb`](https://www.gnu.org/software/gdb)。

示例 10-43 展示了如何使用 GDB 调试和运行一个用 C 编写的漏洞应用程序（`vuln_program`）的简单示例。

**注意** 示例 10-43 中漏洞应用程序的源代码可以在 [`github.com/The-Art-of-Hacking/art-of-hacking/tree/master/buffer_overflow_example`](https://github.com/The-Art-of-Hacking/art-of-hacking/tree/master/buffer_overflow_example) 获取。

`run`命令用于在 GDB 内部运行应用程序。程序执行并要求你输入一些文本。在这个示例中，输入了大量的`A`字符，程序退出。当执行 GDB 命令`continue`时，屏幕会显示文本“Program terminated with signal SIGSEGV, Segmentation fault”。这表明存在潜在的缓冲区溢出（在示例 10-43）。

### Windows 调试器

你可以使用 Windows 调试器（`WinDbg`）调试内核和用户模式代码。你还可以用它来分析崩溃转储（dumps），并在代码执行时分析 CPU 寄存器。你可以通过以下方式从微软获取调试工具：
- 通过下载并安装 Windows 驱动程序包（`WDK`）
- 作为独立工具
- 通过下载 Windows 软件开发包（`SDK`）
- 通过下载 Visual Studio

**提示** 参考“Windows 调试入门”白皮书来学习如何使用`WinDbg`及相关工具；参见 [`docs.microsoft.com/en-us/windows-hardware/debugger/getting-started-windows-debugging`](https://docs.microsoft.com/en-us/windows-hardware/debugger/getting-started-windows-debugging)。
