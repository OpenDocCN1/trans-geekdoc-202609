
关于从 ORM 视角进行子类型化的早期讨论，非形式化的处理可见于 Halpin (1995)，形式化的处理可见于 Halpin and Proper (1995b)。针对 ORM 2 更新的早期处理可见于 Halpin (2007b)；该文献还区分了刚性子类型与角色子类型，这一区别将在第 10.3 节中进一步探讨。Halpin (2009a) 讨论了子类型化的一些进一步扩充。Halpin and Curland (2013) 讨论了 ORM 更近期的增强功能，包括超类型链接角色上的约束，该主题将在第 10.8 节中讨论。

## 7.2 频率约束

设 *n* 为正整数。为指示事实列中的每个条目必须在该列中**恰好出现 n 次**，数字 *n* 通过虚线连接到角色（参见图 7.1）。这是**频率约束**（又称发生频率约束）的一个例子。如果 *n* = 1，这等同于唯一性约束——在这种情况下，应使用通常的竖线符号表示唯一性，而不是“1”标记。

![图 7.1 角色 r 上的简单发生频率约束。](img/f07-01-9780443237904.jpg)

图 7.1 角色 *r* 上的简单发生频率约束。

与唯一性约束一样，频率约束是作用于角色的**局部**约束，而非作用于对象类型的全局约束。图 7.1 中的约束意味着：对于数据库的每个状态，*如果* A 的实例扮演角色 *r*，则必须扮演 *n* 次。这**并不**意味着 A 的每个实例都必须扮演该角色 *n* 次。如果角色是可选的，A 的某些实例可能根本不扮演该角色。

频率约束的一个用途是确保如果记录了详细信息，则必须为枚举类型的所有实例记录这些信息。假设一家公司库存并销售三种计算机驱动器（C = CD 驱动器，D = DVD 驱动器，H = 硬盘驱动器），且仅在两个城市（悉尼和东京）运营。考虑图 7.2 所示的概念模型。前两个角色上的 UC 确保每个城市-驱动器种类组合仅出现在一行中。第一个角色上的频率约束 3 要求出现在第一列中的每个城市必须出现三次。

![图 7.2 如果记录库存数字，则为每个城市和驱动器种类记录。](img/f07-02-9780443237904.jpg)

图 7.2 如果记录库存数字，则为每个城市和驱动器种类记录。

因此，如果为某城市记录了任何库存数字，则必须记录所有三种驱动器类型的数字。同样，第二个角色上的频率约束 2 确保第二列中的每种驱动器类型必须出现两次。由于唯一性约束，这意味着如果为某驱动器类型记录了库存，则必须包含两个城市的数字。

频率约束、唯一性约束和值约束的组合确保了任何记录的库存数字在城市和驱动器类型方面都是*完整*的。需要一个复合事务来初始填充此事实类型，要求至少添加六个事实。

跨越事实类型两个或多个角色的频率约束称为*复合频率约束*。在这种情况下，我们用虚线将频率连接到相关角色（如果将频率数字移得足够靠近受约束角色，此虚线可能会隐藏）。如果只有两个受约束角色且它们相邻，则频率可通过虚线连接到这些角色的连接处。例如，在图 7.3 中，事实表中的每个城市-年份组合必须出现三次。鉴于前三个角色上的唯一性约束，表中每个城市-年份组合的所有三种驱动器的销售额都必须记录。注意，这并不要求必须为两个城市记录年度销售额。示例填充仅包含一个城市，但满足所有约束。

![图 7.3 年度销售数字可能省略城市但不能省略驱动器类型。](img/f07-03-9780443237904.jpg)

图 7.3 年度销售数字可能省略城市但不能省略驱动器类型。

图 7.4 通过要求两个城市以及三种驱动器类型的年度销售数字来加强约束。鉴于唯一性约束和值约束，这通过年份角色上简单的出现频率 6 来实现——作为一个简单的练习，请证明这一点。跨城市-年份的复合频率 3 被省略，因为它是隐含的。跨年份-驱动器类型的复合频率 2 也被隐含，因此也被省略。

![图 7.4 年度销售数字必须涵盖所有城市和驱动器类型。](img/f07-04-9780443237904.jpg)

图 7.4 年度销售数字必须涵盖所有城市和驱动器类型。

*频率范围*也可以指定。使用“≤*n*”表示*至多 n*，其中 *n* ≥ 2。使用“≥*n*”表示*至少 n*，其中 *n* ≥ 1。使用“*n .. m*”表示*至少 n 且至多 m*，其中 2 ≤ *n* < *m*。频率下限 1 是允许的最小频率，默认假设为 1，因为列中的每个条目本身就已存在一次。由于约束适用于角色的填充而非对象类型的填充，声明出现频率为零是没有意义的。可选角色表示对象类型填充中的某些成员可能不扮演该角色。

作为示例，请参考图 7.5。这是会议应用程序模式的一部分。每位专家至少在一个专题组中（如强制角色所示），且至多评审五篇论文（可能为零，因为该角色是可选的）。每个有成员的专题组至少有四名且至多七名成员。因为 Panel 是独立的，我们可以在分配成员之前记录专题组的存在。每篇被评审的论文至少有两名评审人。某些论文可能尚未分配评审人。原则上，频率约束可以组合值和范围（例如，“1, 5..7”），但在实践中这极为罕见。

![图 7.5 最小和最大频率约束示例。](img/f07-05-9780443237904.jpg)

图 7.5 最小和最大频率约束示例。

正如内部唯一性约束可以推广为频率约束，外部唯一性约束可以推广为*外部频率约束*，后者适用于来自不同谓词的角色。例如，一些大学允许学生最多选修同一门课程两次（如果第一次未通过，只允许再尝试一次）。如图 7.6 所示，此外部频率约束通过将频率指示器连接到相关角色来显示。在这些事实类型的上下文中，每个学生-课程组合最多关联两次选课。外部唯一性约束确保每个日期-学生-课程组合最多只有一个选课记录。

## 7.3 环约束

当谓词中的两个角色由同一对象类型扮演时，从该对象类型经过角色对再回到该对象类型的路径形成一个“环”。如果角色由具有共同超类型的子类型扮演，则从超类型出发并回到超类型的路径也形成一个环。该角色对通常形成一个二元谓词，称为*环谓词*，但也可能是较长谓词的一部分（参见图 7.7 中的阴影角色对），甚至可能来自连接路径中的不同谓词（连接约束将在第 10 章中讨论）。*环约束*可能仅适用于此类角色对。

![图 7.7 环约束可能适用于阴影角色对。](img/f07-07-9780443237904.jpg)

图 7.7 环约束可能适用于阴影角色对。

在图 7.8 中，谓词 *R* 可能是通过在角色 *r*[1] 和 *r*[2] 上投影从较长谓词获得的，*A* 可能是扮演 *r*[1] 和 *r*[2] 的对象类型的超类型。对于数据库的每个状态，pop(*r*[1],*r*[2]) 是一组有序对，因此是类型 *R* 的一种关系。允许派生关系和断言关系。

![图 7.8 环二元谓词（可能嵌入在较长的事实类型中）。](img/f07-08-9780443237904.jpg)

图 7.8 环二元谓词（可能嵌入在较长的事实类型中）。

考虑图 7.9(a)中的模型。为简单起见，假设该 UoD 中的人由其名字标识。在这里，每个人都喜欢他/她自己。假设在我们的 UoD 中，这对所有可能的总体都成立——扮演喜欢角色或被喜欢角色的每个人都必须喜欢他/她自己。在这种情况下，Likes 谓词被称为*局部自反的*（或在其总体上自反）。如果我们仅从图 7.9(a)中删除第三行，那么 Bill 就不喜欢自己，该关系也就不是自反的。中缀表示法“*xRy*”（读作“*x R y*”）意味着 *x* 与 *y* 具有关系 *R*。使用上述一般意义的 *R*，用“→”表示“*蕴含*”，用 ∀ 表示*全称量词*（读作“对于每一个”），我们定义：

![图 7.9 (a) 局部自反约束，和 (b) 纯自反约束。](img/f07-09-9780443237904.jpg)

图 7.9 (a) 局部自反约束，和 (b) 纯自反约束。

```
R 是局部自反的 当且仅当 ∀ x,y (xRy → xRx)
R 是纯自反的 当且仅当 ∀ x,y (xRy → x = y)
```

如果我们将对象描绘为黑点，将 Likes 描绘为箭头，则可以将这种自反描绘为一条从同一对象开始并结束于同一对象的关系线，如图 7.9(a)左侧所示。*局部自反约束*使用该图标的简化版本（移除箭头尖），附着在角色对上显示。*纯自反约束*在圆圈内添加一条垂直笔画，如图 7.9(b)所示。

许多重要关系都是自反的（例如 =、≤、平行于、蕴含）。在 UoD 中对所有事物都自反的关系被称为*全局自反的*（或*完全自反的*），即对于所有 *x*，*xRx*。在上述四个例子中，只有“=”是全局自反的。例如，“蕴含”针对命题定义，而非针对人。当我们说“自反”时，通常指局部自反。在实践中，纯自反约束很少见，而全局自反约束极其罕见，以至于对象角色建模（ORM）不支持它们。

现在，考虑一个 UoD，其中喜欢某人的人也会被那个人喜欢。一个满足的总体包含三个事实：Ann 喜欢 Bill；Bill 喜欢 Bill；Bill 喜欢 Ann（见图 7.10(a)）。在这里，给定任意人员 *x* 和 *y*，不一定不同，如果 *x* 喜欢 *y*，则 *y* 喜欢 *x*。如果这总是成立，则 Likes 是*对称的*。图 7.10(a)中的点箭图传达了这样一种思想：如果关系在一个方向上成立，则在另一个方向上也成立。*对称约束*使用该图标的简化版本（移除箭头尖），附着在角色对上显示，如图所示。我们对任意谓词或关系 *R* 定义此概念如下：

![图 7.10 对称环约束。](img/f07-10-9780443237904.jpg)

图 7.10 对称环约束。

```
R 是对称的 当且仅当 ∀ x,y (xRy → yRx)
```

现在考虑一个 UoD，如果一个人喜欢第二个人，而第二个人喜欢第三个人，那么第一个人必须喜欢第三个人。在这种情况下，我们说 likes 是*传递的*。该定义包括人员相同的情况。图 7.11(a)中的填充模式说明了这一性质。

![图 7.11 传递环约束。](img/f07-11-9780443237904.jpg)

图 7.11 传递环约束。

图 7.11(a)中的点箭图表明，如果存在一条关系链，则该关系也适用于链的第一个成员到最后一个成员。*传递约束*使用该图标的简化版本（移除箭头尖），附着在角色对上显示。一般来说，传递性可以定义如下。这里我们用“&”表示“与”，并规定“&”优先于“→”（因此先计算 & 运算）。注意 *x*、*y* 和 *z* 不必不同。

```
R 是传递的 当且仅当 ∀ x,y,z [(xRy & yRz) → xRz]
```

我们将其作为练习留给读者证明：一个既对称又传递的关系在其总体上也必须是自反的。一个既自反、对称又传递的关系被称为“RST 关系”或“等价关系”。经典例子是恒等关系“=”。不等关系“≠”仅是对称的，而小于关系“<”仅是传递的。

自反性、对称性和传递性等关系特性可以被视为约束，因为它们限制了允许的关系。然而，此类特性是*正向的*，更多时候用于*推导*额外事实，而非约束现有事实。

我们现在考虑*负向*关系特性，如非自反性和反对称性。给定某些事实的存在，此类负向特性意味着某些其他事实的不存在。此类特性最好作为简单约束来处理。一个例子将有助于理清概念。请看图 7.12 中填充的父母事实类型，看看你能否发现有什么不对劲。

![图 7.12 这里有什么不对劲？](img/f07-12-9780443237904.jpg)

图 7.12 这里有什么不对劲？

所示总体与指定的约束一致。父母关系是多对多的，且每个人最多有两位父母。但正如你无疑注意到的，表中的某些事实与现实世界中的父母概念不一致。我们需要添加更多约束，以便信息系统能够拒绝此类错误的总体。

首先，第一个事实（Ann 是 Ann 的父母）必须被拒绝，因为没有人可以是他/她自己的父母。我们说父母关系是*非自反的*，并按如下方式为任意关系类型 *R* 定义此概念。这里，波浪号“~”表示逻辑“**非**”（即“并非如此”）运算符。
