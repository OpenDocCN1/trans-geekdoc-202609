
# R3

R3 由 David E Rutter 和 Todd McDonald 于 2014 年创立，是一家企业软件公司，正通过企业级区块链技术引领数字化转型。R3 的解决方案为金融服务行业以及其他垂直领域提供了信任，在这些领域企业或公司之间的协作和交易一直存在信任赤字。R3 专门构建的企业级区块链平台 `Corda` 正在将公司依赖的流程和系统数字化，以便通过贸易金融、保险、银行和资本市场中的区块链网络进行相互连接和交易。有超过 350 家机构正在部署、维护并构建 R3 的产品。R3 还开发了 `Conclave` —— 一种机计算平台，用于增强企业应用中的隐私性，多个用户可以安全地共享和分析数据。

# Rabbit MQ

`RabbitMQ` 属于 VMware，是一种开源消息中间件软件，其功能包括：1. 支持涵盖多种消息协议的异步消息传递、消息队列和到队列的灵活路由；2. 帮助使用 `Java`、`.NET`、`PHP`、`Python`、`Javascript` 等语言开发跨语言消息通信；3. 带有分布式部署；4. 适用于企业级和云就绪。`RabbitMQ` 最初使用高级消息队列协议（`AMQP`）实现，后来扩展到支持流文本面向消息协议（`STOMP`）、`MQ` 遥测传输协议等协议。

# React JS

由 `Jordan Walke` 在 2011 年于 Facebook 工作期间创建，主要用于构建 Web 应用程序并处理 Web 和移动应用的视图层。它允许开发者创建无需刷新页面即可更改数据的大型 Web 应用，并支持服务器端。在区块链领域，它被广泛用于开发加密货币仪表板和构建以太坊去中心化应用（dApps）。

# RxJS

JavaScript 响应扩展（`RxJS`）是一个用于转换、组合和查询异步数据流或回调代码的 JavaScript 库。`RxJS` 既可以在浏览器中使用，也可以在服务器端使用。

# REKT

`REKT` 是网络俚语“wrecked”（毁坏）的缩写，意为严重损毁或彻底摧毁完蛋。在加密货币世界，`REKT` 指那些因错误交易或投资遭受巨大财务损失的人。它也被用来指代价值流水的数字资产。

# Relayer

`Relayer`（中继器）是一种允许托管 `ox` 订单簿的实体，订单中充满了许多来自不同以太坊地址的单独签名订单。对于订单履行，通过部署的 `ox` 智能合约在以太坊区块链上进行直接结算。托管和促进订单的费用以 `ZRX` 代币收取。

# Reputation

声誉（`Reputation`）被用作增加区块链整体可信度的激励机制，其中矿工或验证者会在区块具有最高信任值时促使将其添加到区块链中。作者对节点行为不作任何假设，因此恶意行为可能会破坏所需的共识。

# Rest API

`REST API` 由计算机科学家 `Roy Fielding` 创建，是一种遵循 `REST` 架构风格限制的应用程序编程接口，并允许与 `RESTful` Web 服务进行交互。`API` 是一组用于构建和集成应用程序软件的定义和协议。`REST API` 也称为 `RESTful API`。它的创建初衷是建立一种标准，允许世界上任何地方的两个服务器进行通信和数据交换。

# Rinkeby

`Rinkeby` 是一个以太坊测试网。测试网通常供开发者在应用程序或软件部署到生产环境或主网之前进行测试。测试网上持有的加密货币不包含任何价值。`Rinkeby` 测试网与以太坊主网不同，它是权威证明（`PoA`）网络，而不是像以太坊主网这样的工作证明（`PoW`）网络。`Rinkeby` 的平均区块时间为 15 秒，平均网络算力为每秒 0.1 Hexa hashes。

# Ripple

`Ripple` 由 `Chris Larsen` 和 `Jed McCaleb` 于 2012 年创立，最初被称为 `Opencoin`，在 2015 年更名为 `Ripple Labs`。`Ripple Labs` 创建 `Ripple` 是作为一个实时全额结算系统、货币交换网络和汇款网络。它基于分布式开源协议构建，支持代表法币、加密货币、商品或其他价值单位的代币。`XRP` 是原生货币。其 `RippleNet` 托管了银行、金融机构和汇款提供商等支付供应商，他们使用 `Ripple` 解决方案以更低的成本和更高的速度在全球范围内转账。

# RPC (远程过程调用)

认为 `Bruce Jay Nelson` 在 1981 年创造了 `RPC` 术语。它有助于构建基于客户端-服务器的分布式应用程序，其架构基于本地过程调用，其中被调用的过程可能与调用过程不在同一个环境或网络中。在区块链网络中，`RPC` 提供了更直接的连接，由客户端发起并向区块链节点发送消息。用户可以通过 `RPC` 接口查询区块链相关信息（如区块高度、区块、节点连接）并发送交易请求。

# Ropsten

`Ropsten` 是一个 2016 年启动的工作证明测试网，由于旧测试网存在多个问题，它类似于当前的以太坊区块链。`Ropsten` 以太坊（也称为以太坊测试网）正如其名是一个运行与以太坊相同协议的测试网络，用于部署到主网（`Mainnet`）之前的测试目的。`Ropsten` 在 2016 年 2 月遭到攻击，`Ropsten` 地址被大量自动生成的故障交易所淹没。它在 2017 年 3 月通过开发者重写 `Ropsten` 区块链得以复活。

# RSI (相对强弱指数)

它是技术分析中使用的一种重要指标，通过近期价格变化的量子，来确定股票和其他资产的超卖或超买状态。`RSI` 数值 70 及以上表示超买或价值过高，可能意味着趋势调整和价格下调。`RSI` 读数 30 表示价值过低。在加密货币中，`RSI` 指标基于加密货币的价格变化及其变化速度。

# Rugging / Rugpull

拉地毯（跑路）是指开发者抛弃加密货币或区块链项目并带着投资者资金逃离的情况。许多跑路事件发生在去中心化交易所（`DEX`）上，因为 `DEX` 允许在不进行任何事先尽职调查的情况下轻松列出代币。拉地毯也指从流动性池中移除流动性。为了防止跑路，项目实施了通过锁定合约和流动性池相关的代币销毁等措施。`DeFi100` 代币的创建者曾过接近 3200 万美元的跑路。`SushiSwap` 也遭受过跑路。

# 聪 (Satoshi)

聪（`Satoshi`）是比特币的最小单位，相当于比特币的亿分之一。比特币可以被分成更小的单位，以便于小额交易或微支付。该术语是为了纪念比特币创始人——中本聪（`Satoshi Nakamoto`）而命名的。

# 中本聪 (Satoshi Nakamoto)

中本聪是假定使用区块链或分布式账本技术开发世界上首个去中心化加密货币——比特币的个人（或人员）所使用的化名。中本聪撰写了名为《点对点电子现金系统》的比特币白皮书，创建并部署了比特币的原始实现。作为实现的一部分，中本聪设计了第一个区块链数据库并挖了第一个比特币。据估计，中本聪拥有 100 万枚比特币。

# 锯齿 (Sawtooth)

`Hyperledger Sawtooth` 是一个开源的企业级区块链即服务平台，可以在无需了解核心系统底层设计的情况下运行自定义的智能合约。它使用等待时间证明（`PoET`）共识机制，并允许使用 `Python`、`Javascript`、`Rust`、`Go` 和 `C++` 语言开发智能合约。它可以被部署为许可链或无许可链。`Intel`、`T Mobile`、`IBM` 和亚马逊云服务（`AWS`）都是 `Sawtooth` 的主要用户。

# 施诺 (Schnorr)

`Schnorr` 签名是由 `Claus Schnorr` 描述的 `Schnorr` 算法生成的数字签名。它是一种以简单著称的数字签名方案，安全性基于某些离散对数问题的不可解决性。它非常高效且能生成短签名。它曾受美国专利保护，该专利已 2008 年 2 月过期。它被用于实现“知识证明”（`Proof of Knowledge`）。

# Scrypt

`Scrypt` 由 `Colin Percival` 创建，是一种基于密码的密钥解密解释算法。它最初用于使大规模硬件攻击变得不可行。授权用户在验证时仅需执行一次操作，但暴力攻击者需要在给定时间间隔内执行数十亿次操作，使得攻击变得不可且失败。`Scrypt` 算法的设计使其使用大量内存，这与 `PBKDF2` 等其他密码派生函数（`KDF`）不同。`Litecoin`、`Dogecoin`、`Viacoin` 和 `Gulden` 等许多加密货币在各自的协议中采用了简化版的 `Scrypt` 作为基于工作证明的共识。

# SDK (软件开发工具包)

软件开发工具包（`SDK`）代表了供应商提供的工具和程序集，旨在帮助开发者为各种用途构建应用程序。`SDK` 通常与移动应用相关联。例如：`Android` 工具包用于构建 `Android` 应用，`iOS SDK` 用于构建 `Apple` 应用。`SDK` 包含了与构建、运行、测试和调试相关的 `API`、集成开发环境（`IDE`）以及工具。有 1000 多个 `SDK` 可用于区块链和加密货币应用程序。例如：`Hyperledger Fabric SDK`、`Corda Token SDK` 和 `Cosmos` 以太坊虚拟机 `SDK`。

# SegWit (分离见证)

`SegWit` 指的是比特币在增加区块大小方面对交易数据存储所做的更改，这是通过从比特币交易中移除签名数据实现的。当交易的某些部分被移除时，它释放了空间或容量，以便在链中添加更多交易。

它在 2015 年发布后于 2017 年 8 月上线。它还帮助修复了此前可能的比特币交易 ID 改改问题。`SegWitX` 是一项将比特币区块大小从 1MB 增加到 2MB 的提案。`SegWitX` 开发者曾想硬分叉比特币来执行这些更改，但由于缺乏共识而放弃了该计划。

# 自毁 (Self-Destruct)

这是以太坊网络提供的一个函数，当自毁智能合约被触发时会销毁该合约。它在攻击情况下非常有用，自毁函数可以从以太坊中移除智能合约并将 `Ether` 转移到所有者的地址。大多数开发者使用自毁函数在销毁旧合约后部署更新后的合约。

# 自执行 (Self-Executing)

智能合约是自执行的合约。它们包含了协议的条款和条件，这些条款被嵌入到软件代码中，并在区块链网络的节点之间复制。

# 宁静 (Serenity)

以太坊 2.0 版本被称为 `Serenity`。它是主网上现有以太坊的升级。新功能包括实现分片，以便用权益益证明（`PoS`）共识取代工作量证明（`PoW`），从而提高交易速度。`Serenity` 将分三个阶段启动，第三阶段实施将于 2022 年年中完成。`Topaz`、`Rinkeby`、`Medella`、`Zinken` 都是 `Serenity` 的一些测试网络。

# 蛇 (Serpent)

在加密标准中，`Serpent` 指的是在高级加密标准（`AES`）竞赛中位列于 `Rijndael` 之后的块密码应用。它由 `Lars Knudsen`、`Ross Anderson` 和 `Eli Biham` 开发。`Serpent` 的块大小为 128 位，支持 128、192 和 256 位的密钥。在区块链世界，由 `Vitalik Buterin` 开发的 `Serpent` 指用于在以太坊中编写智能合约的语言。它与 `Python` 非常相似。由于 `Vitalik` 认为其技术已过时并存在安全担忧，该语言已被废弃。

# SGX (软件防护扩展)

`Intel` 在 2015 年引入了 `SGX`，它代表内置在 `Intel x86` 架构中央处理器（`CPU`）中的安全指令集。`SGX` 通过将计算机内存划分为执行区（`enclaves`），更好地保护用户的敏感信息。执行区是内存中私有的预定义区域。对于区块链，`SGX` 提供了增强的隐私安全性以保护交易，并有助于提高共识效率和吞吐量。

# SHA (安全哈希算法)

由国家安全局于 2001 年创建，用于数字签名。它被公密钥基础设施市场广泛数字签名。它广泛应用于包括 `TLS`、`SSL`、`PGP`、`SSH`、`IPsec` 和 `S/MIME` 在内的安全应用程序和协议。`SHA-256` 算法用于区块链每次获取 256 位的恒哈哈。该算法也是加密技术的一部分。

# 分片 (Sharding)

分片是一种数据库架构技术，可对数据库包含的数据进行水平拆分。它是将一个表的行分成多个不同的表（称为分区）。在区块链中，分片通过将区块链分成称为分片（`Shard`）的部分来提高交易速度。每个分片都有自己的账户余额和智能合约。每个节点仅拥有区块链的部分数据而不是完整信息。`Zilliqa` 是第一个实现分片的公共区块链。

# 形象 (Shill)

`Shill` 指公开帮助个人或组织提供信誉的人，而不披露他们与之有密切的关系。加密货币中的 `Shill` 是指持有某些加密货币并试图推广特定代币或代品牌以提高价格并卖出持仓获利的人。`John McAfee` 被认为是加密货币领域著名的 `Shill`。

# 侧链 (Side Chains)

侧链是与主链连接并具有双向锚的次级区块链，用于从主链到侧链以及反之的交易交换。它们为主链提供了效率和可扩展性。侧链可能有自己的共识协议，这些协议可能与主链协议完全不同。双向锚还允许资产按照预定汇率安全地从一个区块链交换到另一个。

## 单点故障 (Single_Point_of_Failure)

这是系统中的错误配置、弱点或缺陷，会导致系统停止运行。它也可能是由于恶意攻击引起的，例如拒绝服务（`DoS`）或分布式拒绝服务（`DDoS`）攻击。中心化系统往往容易产生单点故障。像区块链这样的分布式和去中心化系统可以不受此类故障的影响。

## 单一事实来源 (Single Source of Truth)

单一事实来源是将组织内部多个运营或业务系统中的数据、信息聚合到单一位置、账本或系统中的做法。在区块链中，单一事实来源意味着网络中的每个节点都包含相同的数据。这导致信息在网络其他成员不知的情况下无法被更改，从而实现了不可篡改性。基本上是一个防错且防篡改的记录系统。

## 削罚机制 (Slashing Condition)

削罚是内置在权益证明（`PoS`）区块链协议中的一种机制，旨在惩罚验证者的错误行为，例如持续离线、双签和委托。惩罚措施包括减少质押、抑制未来奖励以及剔除节点。因此，削罚的设计是为了激励节点安全、可用性和网络参与。以太坊 2.0、`Celo`、`Cosmos`、`ICON` 和 `Polkadot` 都对离线、委托和双签设有各种削罚惩罚。

## 智能合约 (Smart Contracts)

智能合约由 `Nick Szabo` 在 1994 年首次提出，它们是存储在区块链上的程序，在满足预设条件时运行。它们被用于自动执行协议，使所有参与者都能知结果并遵守结果，而无需任何时间损失或中介参与来强制执行。以太坊是世界上最流行的智能合约平台，它使用 `Solidity` 编写智能合约并运行在以太坊虚拟机（`EVM`）上。

## 软分 (Soft Fork)

当区块链协议的更改向后兼容且用户只需升级软件时就会发生软分。这类似于升级手机、平板电脑或智能手表的操作系统以修复漏洞并更新安全功能。软分后，将只有一个区块链，不像硬分会导致区块链分裂为两个。以太坊的 `Metropolis` 就是软分的一个良好例子。

## Solidity

它由 `Gavin Wood` 提出，由 `Christian Reitwiessner`、`Alex Beregszaszi` 以及几位前以太坊核心贡献者开发。`Solidity` 受 `C++`、`JavaScript` 和 `Python` 的影响，设计用于与以太坊虚拟机交互。本质上，它是以太坊网络的基础，允许开发者创建自己的去中心化应用（`dApps`）。`dApps` 可以运行智能合约，根据预定义的条件完成传输资金、交换份额或移动任何有价值物品的活动。

## Sovrin

`Sovrin` 会成立于 2016 年，是一个私营的国际非营利组织，旨在治理 `Sovrin` 身份网络。`Sovrin` 网络是一个公共的、许可的分布式账本，专为保护互联网上的身份而构建，其中个人应该在没有管理机构干预的情况下拥有并控制自己的身份，因此被称为自主主权身份（`SSI`）。`Sovrin` 会提供以信誉的方式运行 `SSI` 网络所需的轻量级治理。

## SPV 客户端（简单支付验证，Simple Payment Verification）

这是一项在 `Satoshi Nakamoto` 的论文中首次描述的技术。它允许轻量级客户端在不下载整个区块链的情况下验证交易是否包含在比特币区块链中。它通常用于运行在智能手机上的比特币钱包应用，通过使用特殊的 `SPV` 节点作为应用程序与矿工节点之间的中介。

## SQL（结构化查询语言）

`SQL` 最初由 `IBM` 研究人员于 20 世纪 70 年代开发，是一种用于数据库存储、查询和检索数据的标准语言。它用于创建、删除、获取和修改数据库行。

## SSI（自主主权身份，Self Sovereign Identity）

`SSI` 是一种身份验证和认证模型，其前提是个人应该拥有并控制自己的身份。它为用户提供了安全性和灵活性，使他们能够在意图分享时才分享信息。它免于管理机构或中心化/联邦身份提供者的干预，并基于“无人拥有，但每个人都有访问权”的概念。它消除了收集已经在其他地方收集过的文档的需求。验证者仅获得用户授权共享的信息，此类信息通过加密方式在分布式账本上共享，从而防止被修改。`Evernym` 和 `Sovrin` 是从事 `SSI` 的知名公司。

## 稳定币 (Stable Coins)

稳定币是价值锚钩到参考其资产或货币市场价值的加密货币。稳定币可能挂钩美元等货币，也可能挂钩黄金等商品价格。最流行的稳定币有 `Tether`、`Diem`、`USD coin`、`Dai` 和 `PAX`。与其他加密货币不同，它们通常提供价格稳定性，因此非常受不喜欢价格过度波动的投资者和用户的欢迎。

## 过期区块 (Stale Block)

这些区块也被称为孤儿区块（`Orphan blocks`），它们被成功挖掘但未包含在当前最佳区块中。这发生在添加到非最长链中时。在比特币区块链中，只有最长链胜并推动区块链向前。

## 状态 (State)

状态反映了区块链上所有提交的交易。这基本上是一个键值存储，随着交易和链码的执行而更新。为此，使用了 `LevelDB` 或 `CouchDB`。

## 状态通道 (State Channel)

通道是一种私有的区块链覆盖层，允许数据隔离和机密性。通过状态通道，用户在链外直接进行交易。它们通过减少节点在处理和存储交易时的负载，有助于提高公共区块链的吞吐量。它们还预计降低以太坊网络的使用，因为用户只在开启和关闭通道时支付交易费用（也称为 `gas`），而不为交易本身付费。

## 静态节点 (Static Nodes)

它们代表一组预配置的受信节点。在 `Hyperledger Besu` 中，静态节点不受某些限制，例如最大对等数量和远程连接限制。静态节点还被用作寻找对等节点的替代方法。
