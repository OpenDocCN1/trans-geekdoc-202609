## 14.4 基于区块链的药品追踪架构

本节介绍并探讨了三种区块链架构的构建，以满足药品追踪的关键需求。这些结构或架构基于三个不同的区块链平台：`Hyperledger fabric`、`Hyperledger besu` 和 `Ethereum`。因为与其他区块链平台相比，它提供了高水平的可靠性、权力分配、清晰度、机密性、安全性、数据可靠性、安排以及故障处理能力。这些是用于生成经批准的私有/公有区块链的主要区块链架构，在其中生产者、贡献者和最终用户被记录在案。这三种结构和传输流程在后续小节中定义 [[27]](#C_019_c14.xhtml#r14_27)。

### 14.4.1 基于 Hyperledger Fabric 区块链的架构

基于 `Hyperledger fabric` 区块链的架构是一种具有链式结构设计的分布式账本技术 (DLT)，提供最高程度的保密性、稳健性和弹性。它是一种基于区块链的商业 DLT，采用智能合约在众多参与者之间建立信任。它摒弃了挖矿的概念，同时保留了基于区块链技术的传统加密货币的优势，如区块的不可篡改性、事件的顺序性以及双重支付保护。`Hyperledger fabric` 已被证明能提供更高的交易吞吐量，每秒可达数千笔交易 [[28]](#C_019_c14.xhtml#r14_28)。由于这些特性以及下文将进一步讨论的其他特性，`Hyperledger fabric` 成为具有众多流程和参与者的复杂供应链网络的绝佳选择。智能合约的采用标准低于使用特定编程语言（如 `Java`、`Go` 和 `NodeJS`）的其他技术 [[29]](#C_019_c14.xhtml#r14_29)。基于 `Hyperledger fabric` 区块链的药品追踪架构是基于区块链的企业级供应链系统的初稿，其中 PSC 内的不同利益相关者得到识别，他们之间的关联通过各种通道实施，以确保极高水平的保密性、权威性以及数据的全面保护。`Hyperledger fabric` 首创了通道的概念。通道允许同一网络中的不同利益相关者隔离其业务逻辑和数据隐私标准。它还提供了一个安全清晰、抗故障且容错的交易收集机制，确保不可避免的事件记录、安全传输以及一群互不信任的利益相关者之间可靠的医疗对话。这有助于在 PSC 中建立标准化的追踪归因机制 [[30]](#C_019_c14.xhtml#r14_30)。建议的区块链设计采用独特的模块化方法，以实现最高程度的可追溯性、适应性和匿名性。该架构创建了一个许可型区块链系统，其中卫生管理局 (HA) 使用成员服务提供商 (MSP)（架构的一个组件）来识别和注册所有参与组织及其最终用户。`Hyperledger fabric` 的 MSP 组件可以提供证书颁发机构 (CA)，或者提供的 CA 可以是外部的，例如与活动目录配合使用的 `OpenSSL` 证书。该架构要求使用 MSP 来在互不信任的各方之间创建机密环境 [[31]](#C_019_c14.xhtml#r14_31)。

最后，排序服务 (OS) 和对等节点是 `Hyperledger fabric` 设计的核心。`Hyperledger fabric` 对等节点维护账本副本，运行智能合约（也称为链码）、背书并提交交易。操作系统从客户端应用程序接收授权交易，并将它们组织成区块，带有背书方的加密数字签名以及批准贵族的签名，最后将这些区块转发给系统中的有望节点，以根据授权策略进行验证 [[32]](#C_019_c14.xhtml#r14_32)。图 14.2 显示了基于 `Hyperledger fabric` 区块链的架构。

#### 14.4.1.1 基于 Hyperledger Fabric 区块链架构的药品追踪流程

制造商发起一项业务交易提案，根据区块链的背书策略，该提案将与网络的所有对等节点共享。背书策略是一组预先指定的策略，规定了对等节点可以签署/检查每笔交易的程度。这些交易提案由背书策略中指定的总节点数执行。交易提案的结果（也称为背书）连同背书对等节点的数字签名、读/写 (RW) 集一起共享，并作为提交提案的确认发送回用户/客户端应用程序。当足够多的响应到达用户应用程序时，它会检查它们以确定 RW 集是否相同，以确保区块链不会因提案和认证阶段而更新。在此之后，用户应用程序将提案及其响应广播到排序服务 (OS) 的一笔业务交易中。分布式 OS 使用共识算法，对每个通道转发的业务交易的实施顺序进行适当估算和维护。排序服务按时间顺序将多笔药品传输排序在一个区块中，并将区块哈希链接到前一个区块。然后，操作系统将所有新区块转发给架构上的首要节点。首要节点的任务是使用对话协议将区块传播给组织中其他参与节点。首要节点由联盟选出，然后也被接纳到订阅服务中。对等节点通过“根据链码的认证策略进行背书合法且一致的验证”，同时还验证 RW 集自上次验证以来未被破坏。如果某些背书不可接受或与 RW 集不匹配，则该操作被标记为非法。或者，记录有效，此外，所有对等节点按预定义顺序将交易添加到通道账本中以确保准确性。有效交易将更新世界状态。无效交易将保留在账本中，但世界状态不会更新。最后，发送交易提议的客户端应用程序将通过系统上的每个对等节点收到通知，告知发生的业务交易成功 [[33]](#C_019_c14.xhtml#r14_33)，[[34]](#C_019_c14.xhtml#r14_34)，[[35]](#C_019_c14.xhtml#r14_35)。

### 14.4.2 基于 Hyperledger Besu 区块链的架构

为了生成一个具有私有访问权限的许可区块链以供 PSC 使用，基于 Hyperledger Besu 区块链的架构允许使用关联网络账户来创建特定组织及其用户。Hyperledger Besu 利用固有的基于基础设施的公钥进行数字签名，并对业务交易/事务进行认证；每个节点的地址用于中间节点的唯一识别。为了区分存储过程、管理过程和业务逻辑，建议结合使用 EthSigner 与基于 Hyperledger Besu 区块链的架构，作为钱包服务的第三方供应商。交易被接受后，EthSigner 平台将使用存储的私钥生成签名，并通过一个完全合法的签名向以太坊客户端广播业务交易，以便将其添加到区块链中[36, 37, 38]。

为了保护股东之间的交易隐私，架构使用了像 Orion 这样的私有交易管理器（PTM）。符合企业以太坊联盟（EEA）客户端规范的 PTM，允许智能合约中的通用企业逻辑仅对远程且受限数量的参与者可见，从而使每笔业务交易及与这些智能合约相关的状态也保持私密。Orion 是 Hyperledger Besu 的原生 PTM，属于一种 PTM[39]。最后，为了授予不同用户及其个人账户在系统中的准入权，它提供了链上和链下权限。授权系统启用节点和账本权限以供访问，并将网络访问限制为仅特定节点和账户。此外，Hyperledger Besu 的权限功能允许实时暂停账户、拒绝访问受损的智能合约，并根据所需的群组详细信息限制操作[40]（图 14.3 展示了基于 Hyperledger Besu 区块链的架构）。

#### 14.4.2.1 基于 Hyperledger Besu 区块链架构的药品追踪流程

本节详细描述了如何在基于 Hyperledger Besu 区块链的系统中，在不同股东之间执行和通信药品相关的可追溯性交易。当组织用户想要执行交易时，他们将首先通过分布式应用（DApp）向 Hyperledger Besu 电子投票机（EVM）节点发送签名的私有交易请求。签名交易包括接收者地址列表或隐私组 ID、发送者地址、交易类型、交易载荷等。为了解释群组的机密性，所有中间节点通过唯一的隐私组 ID 被 Orion 识别。Orion 使用隐私组 ID 存储每笔私有交易。基于 Hyperledger Besu 区块链架构的节点维护区块链的公共世界状态和每个隐私组的私有状态。私有状态包含不在全球复制的世界状态中共享的数据。隐私组仅允许一组账户/节点访问特定数据。应用操作员接口通过 JSON-RPC 经由私有交易处理程序（PTH）向 Orion 执行交易发送任务。Orion 根据私有组 ID 或接收者地址识别，将交易分配给其他 Orion 节点。一旦 Orion 节点接收到交易，它将其存储在状态记录中，并将交易哈希返回给 PTH。除了私有交易外，PTM 还会创建一个用于传输的隐私标记交易（PMT），该交易被包含在账本的区块中并进行传输。系统中每个节点上的主网交易处理器将处理 PMT，并将交易传递给合约，在包含一致的预编译智能合约的节点上执行。合约使用交易哈希值查询 Orion 以获取私有交易，并将业务交易移交给私有交易处理器；它执行交易并将读写（RW）过程发送到私有状态，以更新其余参与节点。缺少预编译合约的节点将忽略标记交易[41, 42, 43]。

### 14.4.3 基于以太坊的架构

以太坊是一种无许可的公共区块链技术，任何人都可以对其进行编辑[44]。智能合约使用 Solidity 编写；测试和编译通过 Remix 集成开发环境（IDE）完成。Remix 是一个基于 Web 的工具，用于实现和调试智能合约代码，也可以检查代码的健壮性。智能合约将由生产商提交，该合约包含生产药批的所有事实，包含说明以及在供应链环境中触发事件。每当新成员加入系统时，他们将能够使用这些操作，因为这些操作完全存储在分布式账本中，因此他们可以轻松观察某些生产药批的过去交易。生产商可以选择将药批的图片上传到星际文件系统（IPFS），以便参与人员可以轻松访问和查看药批树。对于药批的销售，必须先进行铸造；然后生产商将通过触发事件向其他参与者宣布新获得的药批可供交易。想要购买新获得药批的参与生产商需要执行特定函数以进行药批转移，交易完成后，事件将通知参与者宣布新的药批所有者[45]。在 FDA 批准之前，生产商将无法提交药批的智能合约；然而，由于简化考虑，该授权未在智能合约中实现（图 14.4 展示了基于以太坊的区块链架构）。

#### 14.4.3.1 基于以太坊架构的药品追踪流程

智能合约将通过持有者 ID 等特性实现，并包含最近合约持有者的以太坊位置[46]。关键点在于持有者 ID 是主要位置而非映射，因为批次智能药品合约只能有一个持有者 ID，每当持有权发生变更，交易/动作就会被释放并存储在区块链中，这些动作用于追踪药品批次的初始信息[47]。智能合约代表特定的一批药品，还包含批次名称、批次价值、总箱数、每箱价格及其实物照片等其他特征[48]。此外，三个必需的认证属性映射允许在智能合约内访问生产商、供应商和药剂师等服务。智能合约具有多种角色，执行药品批次的生产流程和销售流程[49]。此外，生成的药品批次信息包含作为输入参数的药品批次活动详情，包括批次名称、批次价值、总箱数、每箱价格及其实物照片。而且，生产商可选择将照片上传至 IPFS，IPFS 照片的哈希函数将被存储并通过另一属性检索。智能合约与 IPFS 的连接比例为 1:1，因为每个药品批次一次只能上传一张照片到 IPFS[50]。

### 14.4.4 Hyperledger Fabric、Hyperledger Besu 和 Ethereum 架构的比较

本节对三个讨论的基于区块链的平台进行深入实用的评估，强调其优缺点。虽然 Ethereum 可设为私有系统，但本关联将其视为公共网络。比较特征汇总自先前研究建议、扩展、真实文献及部分进行中项目[51]。

与基于 Ethereum 的架构相比，基于 Hyperledger Fabric 的架构和基于 Hyperledger Besu 的架构旨在作为独立、有效的 B2B 系统。Ethereum 是一种略微面向 B2C 的方法，天然不支持机密性或个人记录/交易的维护。Hyperledger Fabric 和 Hyperledger Besu 支持快速最终确认并提供高交易速率。Hyperledger Fabric 中的智能合约易于升级，因为它们使用标准软件设计语言，这与使用特定领域语言的 Hyperledger Besu 区块链架构和 Ethereum 区块链架构不同。Hyperledger Fabric 区块链架构没有 Besu 和 Ethereum 可用的改进结构的适当共识。Hyperledger Fabric 的系统配置、格式化和分发非常高，但因所有模块均已容器化，故易于管理和升级。使用 Hyperledger Fabric 区块链架构也带来了改进的客户请求功能；然而，它增加了消费端的控制器数量。对于由物理和逻辑双重包含来管理的专有行政和准入，Hyperledger Fabric 区块链架构优于 Hyperledger Besu 和 Ethereum 区块链架构。在治理计划中，基于 Hyperledger Fabric 和基于 Hyperledger Besu 的区块链均提供了一些最佳的替代方案和主动追踪解决方案的结构[52]。**表 14.3** 旨在提供上述架构比较效果的深度细节。

### 14.5.1 利益相关者协议

区块链建立是一个分散平台，所有制药服务提供商在此存储其必要商业记录，且所有人均可通过区块链平台访问给定的机密记录。参与者可能不愿加入这些系统，因为这可能导致其经济利益受损，特别是当多个商业参与者处于同一供应链上时[54]。

### 14.5.2 互操作性

其定义为通过多个政府部门广泛接受商业软件和平台，以提供政策的有效整合。它作为不同软件和平台用户相互交互并自由创建合理业务活动的方式。现有的药品追踪解决方案（如序列、条形码、RFID 标签、基于区块链技术的解决方案和平台）无法完全发挥作用，因为缺乏经过验证的解决方案来实现组合、灵活性和简易性。此外，Hyperledger 旗下不同的基于区块链的平台在提供协作方面面临挑战，难以确保高范围和灵活性，以允许商业管理机构之间的内部和外部通信[55]。

### 14.5.3 实施成本
