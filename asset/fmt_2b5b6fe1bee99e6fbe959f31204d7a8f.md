
- **服务生命周期结束（EOSL）**：EOSL 标记通常分配给不再受供应商支持的硬件或软件。达到 EOSL 的产品将不再获得供应商开发的安全更新，这会使该产品成为组织的风险。

- **保密协议（NDA）**：NDA 是概述双方关系保密性及何种信息视为机密的文件。NDA 还规定了在关系存续期间及结束后如何处理机密信息。

##### 影响数据的策略

许多安全策略影响员工对数据的访问及公司对数据的管理。以下是一些影响数据的常见策略：

### 分类

正如您在本章前面所学，数据会被分配一个安全标签，为了访问该信息，用户必须拥有相应的安全许可级别。准备 Security+ 考试时，请务必复习本章前面介绍的数据分类。

### 治理

为帮助将数据安全事件降至最低，公司应制定数据治理政策，以确定谁对数据拥有控制权，以及数据在组织内部如何被处理。

### 保留

公司应制定保留政策，规定数据应保留多长时间。不同类型的数据可能有不同的保留要求——例如，财务记录通常保留七年。

# 凭据策略

另一种应存在的策略是凭据策略。凭据策略确定业务内不同实体使用的凭据（或用户名）。以下是关于凭据的一些常见考量因素：

#### 人员

公司内每位员工都应拥有自己的凭据，用于访问网络和计算机系统。应教育员工遵循凭据安全最佳实践，例如不与其他员工共享凭据。

#### 第三方

第三方实体（如业务合作伙伴或承包商）也应拥有凭据，以访问所需的系统。遵循这些凭据的最佳实践非常重要，例如确保在承包商的凭据上设置了账户过期选项。

# 设备

您可能需要通过几种不同的方式来管理设备凭据。首先，您会在设备上设置密码，以便只有授权人员才能访问这些设备。您还应在每台设备上设置空闲超时，以便设备在短暂空闲后自动锁定。

## 服务账户

在系统上运行的软件也需要以“某人”的身份运行，因此您应为该软件创建所谓的服务账户。创建账户后，您再将软件配置为使用该账户向系统进行身份验证。这将成为软件在访问网络资源时的安全身份。

#### 管理员/Root 账户

您还应管理系统上管理员账户（也称为 root 账户）的凭据。重要的是要确保每个系统上的管理员账户都使用不同的密码，这样如果某个系统的密码泄露，同一密码就无法用于其他系统。

![Image](img/exam.jpg)

**针对 Security+ 认证考试，请熟悉关于凭据策略的安全最佳实践，例如将软件配置为使用服务账户，以及确保每个系统上的管理员账户配置了不同的密码。**

### 隐私和敏感数据概念

了解公司及其数据面临的安全风险是安全专业人员的一项重要技能。在本节中，您将了解公司发生安全漏洞后的后果、我们要保护的数据类型，以及用于保护这些数据的工具。

#### 隐私和数据泄露对组织的后果

如果公司发现发生了隐私和数据泄露，可能会面临许多后果。以下是备考 Security+ 考试时需牢记的关键后果：

##### 声誉受损

对公司最大的后果之一是声誉受损。如果客户得知您的企业未保护敏感数据，他们可能决定不再与贵公司开展业务。这会影响公司的财务状况，甚至可能导致公司倒闭。

## 身份盗窃

如果发生敏感数据未授权访问，您或您的客户可能会遭遇身份盗窃。

# 罚款

因未妥善保护敏感数据，您可能面临罚款。这些罚款可能给公司带来财务压力。

##### 知识产权盗窃

如果数据泄露导致敏感公司数据被未授权访问，可能会导致攻击者窃取知识产权。

#### 违规通知

如果您的企业发生数据泄露，您需要通知相关人员。通知对象将取决于您的业务类型和发生的安全事件类型。通知主要有以下两种形式：

##### 升级

发现安全事件发生后，您可能需要向事件响应团队报告该事件。在调查事件后，事件响应团队可能需要根据事件情况将其升级报告给另一方。例如，如果是云事件，他们可能需要向云服务提供商升级报告。

##### 公开通知和披露

根据管辖贵组织的法规和法律，您可能需要就任何安全事件发表公开声明，并披露已泄露信息的类型详情。法律可能要求公司单独通知受影响的用户和客户。

# 数据类型

在制定安全策略时，您的目标是保护组织内的隐私和敏感数据。了解组织内存在的数据类型将帮助您理解所需的安全控制类型。例如，了解本章前面讨论的信息的不同 `classifications`（如私有数据和公共数据）对于保护这些数据非常重要。企业中需要保护的其他数据类型列举如下：

##### 个人身份信息 (PII)

PII 是指能够唯一标识某个人的任何信息。例如，驾照号码被视为 PII 数据。您将在下一节详细了解 PII 信息。

##### 健康信息

健康信息通常包含关于一个人的机密医疗信息，仅应由授权人员（如患者的医生）访问。

# 财务信息

财务信息（如信用卡号和银行账户信息）应保持机密，并采取措施确保数据不以明文形式存储在信息系统中。

##### 政府数据

如果泄露可能对政府构成安全风险的信息，应予以严格保护，确保只有授权人员才能访问该信息。

# 客户数据

敏感客户数据应始终受到保护，例如联系详情、地址信息以及与客户相关的任何财务数据。

#### 隐私增强技术

您可以使用多种不同的技术来帮助保护不同类型的敏感信息，如信用卡号和健康信息。针对 Security+ 考试，您应记住以下维护隐私的关键技术：

# 数据最小化

保护敏感数据的第一步是将收集的信息量降至最低。数据最小化是指仅收集必要信息的过程。

# 数据掩码

数据掩码是一种用于保护机密或私有数据的技术，涉及将数据中的字符替换为无关字符。数据掩码的使用示例是：如果您有顾问在处理数据库，您向他们提供数据库的掩码版本，以便数据中发现的敏感信息对顾问不可见。

### 标记化

数据标记化是指将数据中发现的敏感信息替换为一个称为标记的非相关数据字符串。然后，该字符串存储在别处的数据映射表中，可在需要时查找该映射表，将标记数据转换回敏感数据。这是一种用于保护信用卡信息的常用技术，使得信用卡数据不与客户数据一起存储。

### 匿名化

匿名化是一种数据隐私技术，涉及从数据中移除个人身份信息，以便数据中描述的人物保持匿名。

### 假名化

也称为化名化，假名化是指数据库字段中的人员可识别信息被替换为假名。

![Image](img/exam.jpg)

> **针对 Security+ 认证考试，请熟悉可用于增强数据隐私的不同技术。特别是要记住，数据掩码通常用于数据库，而标记化用于需要反复重复使用的私有数据，例如信用卡号。**

### 其他考量

Security+ 认证考试要求你了解与数据隐私概念相关的其他一些术语：

- **信息生命周期**：信息在业务中有一个生命周期，从信息创建、分发给员工、被员工使用、维护，直到最终销毁。

- **影响评估**：影响评估用于评估安全妥协对业务的影响。例如，公司的电子商务网站被黑客攻击且黑客访问了客户记录，会产生什么影响？

- **协议条款**：协议条款是一份文件，概述了双方同意遵守的关系规则和条件。

- **隐私声明**：隐私声明也称为隐私政策，是一份向个人传达公司如何收集、使用、披露、管理和处置客户数据的声明。

![Image](img/exam.jpg)

> **针对 Security+ 认证考试，请熟悉影响评估和隐私声明，以及它们各自对数据隐私的重要性。**

## 认证目标 3.05

##### 法规与标准

Security+ 认证要求你了解围绕信息安全的一些常见法规、标准和框架，以及这些要素如何用于提升组织的安全态势。

### 法规、标准与立法

组织实施安全策略的原因各异——组织可能为遵守其行业的法规而实施策略，或为遵循特定标准而实施。某些法规和标准可能影响组织创建策略的方式和原因，因此请务必查找针对您所在行业的具体法规和标准。

以下部分概述了当今一些流行的法规和标准示例。

#### ISO/IEC 17799

*国际标准化组织 (ISO)* 和 *国际电工委员会 (IEC)* 制定了 `ISO/IEC 17799` 标准，该标准规定了信息安全管理的最佳实践。`ISO/IEC 17799` 将信息安全管理分为不同的类别（通常称为*域*）。以下是遵循该标准应重点关注的一些信息安全类别列表：

- 风险评估
- 安全策略
- 安全组织
- 资产保护
- 人员安全
- 物理与环境安全
- 通信与运营管理
- 访问控制
- 系统维护
- 业务连续性

`ISO/IEC 17799` 于 2000 年正式采纳，2005 年更新，并于 2007 年重新编号为 `ISO/IEC 27002`。重新编号的目的是使该标准与 `ISO 27000` 系列中的其他标准保持一致。

#### PHI 与 HIPAA

美国有许多旨在保护健康信息隐私的政策和法案。*受保护健康信息 (PHI)* 是指关于患者、其护理、健康状况和付款历史的健康信息，受《健康保险流通与责任法案 (HIPAA)》中的规则保护。组织通常会将患者的此类信息匿名化以维护其隐私。

`HIPAA` 于 1996 年颁布，涉及医疗保健记录的隐私。`HIPAA` 是一项美国标准，其关键关注领域是保护任何可单独识别的健康信息并控制对该信息的访问。

#### 个人可识别信息

个人可识别信息 (PII) 是指能够唯一识别个人的任何信息。它应始终受到保护。以下是被视为 PII 的信息的两个示例：

- **国家身份识别号**：国家身份识别号如美国的社会安全号 (Social Security number) 或加拿大的社会保险号 (social insurance number)。

- **驾照号**：驾照号是关于个人的唯一信息的一个很好的例子，需要予以保护。

![Image](img/exam.jpg)

> **针对 Security+ 认证考试，请熟悉什么是个人可识别信息 (PII) 并能识别 PII 的示例。PII 应始终受到保护并保持机密。**

在创建安全策略时，还有其他标准和法规你应该熟悉，以确保你的业务遵循管辖你组织的任何法规。创建安全策略时应牢记的其他一些标准和法规如下：

- **通用数据保护条例 (GDPR)**：`GDPR` 是一项欧洲法规，旨在保护个人的私人数据。处理或处理个人数据的组织必须建立安全控制，以确保未经授权的访问不会发生。`GDPR` 概述了数据处理者（处理个人数据的实体）和数据控制者（负责保护个人数据的实体）的安全要求和责任。

- **国家、领地或州法律**：请务必遵守管辖您组织的任何国家、领地或州法律，特别是与保护资产以及具体的员工和客户数据有关的法律。

- **支付卡行业数据安全标准 (PCI DSS)**：`PCI DSS` 是一项由信用卡公司强制要求的信息安全标准，旨在确保商家采取必要措施保护信用卡数据。`PCI DSS` 有一系列必须由收集信用卡数据的公司满足的安全要求，例如定期进行安全评估、网络分段与安全、持卡人信息保护，以及实施强访问控制方法来保护数据。

![Image](img/exam.jpg)

> **针对 Security+ 认证，请务必了解不同标准之间的区别，例如 ISO、GDPR 和 PCI DSS。**

### 框架与安全指南

有许多行业框架和安全指南规定了安全不同方面的最佳实践，例如物理安全最佳实践、安全系统最佳实践、网络安全最佳实践和安全编码最佳实践。*安全框架* 包含许多文档化的程序、安全流程和安全策略，为了遵循该框架应遵守这些内容。以下是你应能为 Security+ 认证考试描述的框架：

### 行业标准与框架

#### 互联网安全中心 (CIS)

CIS 是一个成立于 2000 年的非营利组织，致力于制定和推广网络安全防御最佳实践，以帮助保护系统安全。您可以在 [www.cisecurity.org](http://www.cisecurity.org) 查阅最佳实践文档并下载网络安全工具。

#### 美国国家标准与技术研究院 (NIST) 风险管理框架 (RMF)/网络安全框架 (CSF)

**NIST 风险管理框架 (RMF)** 是一份概述了将安全风险管理集成到系统开发生命周期中的步骤的文档。该框架分为七个阶段来执行风险管理，可在 [`csrc.nist.gov/projects/risk-management/about-rmf`](https://csrc.nist.gov/projects/risk-management/about-rmf) 访问。

**NIST 网络安全框架 (CSF)** 是 NIST 提供的一套资源，包含一系列策略，旨在帮助公司管理网络安全风险。该文档帮助组织了解应采取哪些安全措施和控制来降低资产风险并更好地保护资产。您可以在 [www.nist.gov/cyberframework](http://www.nist.gov/cyberframework) 查看 CSF。

#### NIST SP 800-171

NIST 特别出版物 800-171 是联邦组织在非联邦系统上处理、存储和使用信息时保护信息的推荐标准。该框架定义了一系列可用于保护信息的技术控制。

#### 国际标准化组织 (ISO)/IEC 27001/27002/27701/31000

如前所述，ISO 制定了一系列作为国际标准的文档，指导读者如何在其组织内管理信息安全。以下概述了每个标准的目的：

*   **ISO 27001** 定义了如何在组织内管理安全，包括实施安全策略和安全控制，以协助资产管理、物理安全和运营安全。

*   **ISO 27002** 是对 27000 标准的更新，用于实施安全控制以帮助保护信息系统。

*   **ISO 27701** 定义了实施安全控制和流程以维护个人可识别信息 (PII) 隐私的标准。

*   **ISO 31000** 定义了一个框架，帮助组织管理其内部风险。

#### SSAE SOC 2 Type I/II

服务组织控制 (SOC) 2 是一项审计标准，服务提供商可用其确保客户数据受到保护。

*   **SOC 2 Type I** 审计旨在确认服务提供商已部署适当的安全控制。

*   **SOC 2 Type II** 审计更为深入，审计员将对组织内的安全控制和安全策略进行更彻底的审查。

#### 云安全联盟

云安全联盟 (CSA) 提供了一个框架，用于制定安全最佳实践以创建安全的云计算环境。CSA 通过提供云控制矩阵 (CCM) 来实现这一点，CCM 是一份由 197 个控制目标组成的文档，分为 17 个域，涵盖了云计算的所有关键方面。您可以在 [cloudsecurityalliance.org](http://cloudsecurityalliance.org) 了解 CSA。CSA 还提供了一个称为企业架构 的参考架构，这是一种评估内部 IT 或云提供商安全能力的方法论。

### 基准/安全配置指南

此外，还有许多安全配置指南，提供关于保护特定类型产品或系统的最佳实践。NIST 发布了保护特定平台的步骤文档，但您也可能会发现产品供应商会发布自己的文档，说明如何保护其产品。NIST 安全配置指南的一个示例是 **特别出版物 (SP) 800-123**，这是一份概述通用服务器安全应采取步骤的文档（即适用于任何服务器的安全实践）。

NIST 拥有涵盖不同类型产品的许多安全配置指南。例如，它提供了 Web 服务器（如 Microsoft IIS）、操作系统（如 Windows）、不同类型的应用程序服务器（如 Microsoft SQL Server 或 Microsoft Exchange Server 的安全配置）以及网络基础设施设备（如交换机和路由器）的安全配置指南。

许多供应商创建安全配置指南，解决其操作系统、软件和设备的最佳实践。以下是一些示例：

*   **Cisco IOS 安全配置指南，版本 12.4**  
    [www.cisco.com/c/en/us/td/docs/ios/security/configuration/guide/12_4/sec_12_4_book.html](http://www.cisco.com/c/en/us/td/docs/ios/security/configuration/guide/12_4/sec_12_4_book.html)

*   **VMware vSphere 6.5 安全配置指南**  
    [`www.vmware.com/security/hardening-guides.html`](https://www.vmware.com/security/hardening-guides.html)

在寻找安全配置指南时，您可能会在以下类别中找到指南：

*   **平台/供应商特定指南**  
    供应商特定指南概述了应针对该供应商特定产品采取的关键安全配置步骤。

*   **Web 服务器**  
    有安全配置指南概述了配置特定 Web 服务器（如 IIS 或 Apache）的关键步骤。

*   **操作系统**  
    操作系统配置指南概述了保护 Windows、macOS 和 Linux 等操作系统的关键配置步骤。

*   **应用程序服务器**  
    应用程序服务器可以是 Microsoft Exchange Server、SQL Server 或 IBM WebSphere 等服务器。有安全配置指南概述应用程序服务器及其实施的最佳实践。

*   **网络基础设施设备**  
    有许多针对不同供应商网络设备（如交换机、路由器和无线接入点）的安全指南。

*   **通用指南**  
    通用指南概述了应遵循的通用安全实践，如修补系统、使用网络防火墙或使用基于主机的防火墙。这些是遵循通用安全实践的绝佳指南，但您也需要为您的产品寻找特定的供应商指南。

*   **供应商多样性和控制多样性**  
    这不是一份指南，而是指南中应识别的一个重要观点。您应该在环境中使用来自不同供应商的不同产品，这样如果黑客能够入侵一种产品，他们就无法使用相同的方法攻破另一种产品（不同产品具有不同的漏洞）。

# 认证总结

在本章中，您了解了安全策略的重要性，因为它为公司内部的安全计划奠定了基础。重要的是要确保不时审查和更新安全策略，以跟上当前的趋势和安全问题。以下是关于安全策略、培训和意识的一些关键点：

*   安全策略是一个由不同策略组成的大型文档。安全策略中常见的策略示例包括可接受使用策略、密码策略、无线策略和远程访问策略。

*   每个策略都应以一致的方式创建，所有策略中应包含相同的章节。例如，每个策略中都应包含概述、范围、策略、执行、定义和修订历史章节。
