通过这项研究，我们清晰地阐述了如何利用行为建模预测个人在特定测量时间所处的行为改变阶段。我们强调了跨理论改变模型（TTM）。作为一个基本前提，TTM 是一个预设的行为改变模型，它被专门整合到研究工具中，以识别受访者相对于身体健康的改变阶段。研究结果对于评估受访者与健康行为相关的改变阶段起到了重要作用，从而识别了促使阻他们留在特定阶段的因素。识别改变阶段至关重要，事实上，它是开发针对性行为改变干预措施的前决条件。

## 10.1 引言

阅读和理解医学报告具有挑战性，因为普通公众缺乏专业的医学知识，尤其是由于使用了较多的术语。这种障碍可能会阻碍医疗提供者与患者之间的有效沟通，导致误解和非理想的结果。研究人员已经解决了许多技术和非技术问题，包括高级术语的使用；领域特定知识的缺乏导致了误解。

处理和解释医学报告面临多重挑战。传统的机器学习算法需要训练数据集，包括医学字典，这些字典必须定期更新以跟上领域进展。这些数据集还需要大量的存储空间，而且根据解码所需的术语，解码的响应时间可能缓慢且不稳定。在本章中，我们提议使用 `LLM` 结合 `OCR` 将处方解码为通用语言，同时优化空间、时间和成本。我们的目标是消除基于传统数据集解码。

我们还提议使用更高效的云端 OCR 工具来理解扫描文档并从中准确提取文本。研究人员长期以来旨在理解临床笔记，而 `OCR` 一直是从扫描文档中提取文本的核心概念。作者提供了一种解决方案，通过使用 `OCR` 从处方中提取文本并理解药物，然后将其添加到在线篮中。描述的 `OCR` 流程可以通过在 `Azure Cognitive Service` 上实现来优化，相比 `AWS Rekognition` 提供更高的准确率，且每月处理百万张图片的成本更低。

## 10.2 方法论

### 10.2.1 OCR

字符识别是最强大的技术之一，旨在将多种形式的物理文档（如扫描件、PDF 或数字相机拍摄的图像）转换为可编辑和可搜索的数字文本。`OCR` 使用专用硬件软件提取打印文本，将图像转换为计算机可以理解的文本。扫描设备创建文档的数字映像，并通过识别字符将图像转换为文本，使信息易于获取、搜索和存储。

#### 10.2.1.1 OCR 的机制

`OCR` 通过扫描仪或相机（如手机）捕捉图像。一旦文档被扫描，`OCR` 软件会将文档简化为高对比度的黑白格式，将深色区域识别为潜在字符，将亮区域识别为背景。然后 `OCR` 会扫描并将文本分割成单个字符、单词或文本块以便后续处理。

模式识别通过将将扫描文档中的字符与存储的字体示例进行比较，使软件能够识别匹配项。另一方面，特征识别则依赖于定义字符形状的结构规则，例如线条和曲线的数量和方向。例如，在特征识别中，字母“A”是通过两条在顶部交汇的对角线和中间的一条水平横梁来识别的。一旦检测到字符，它就会被转换为广为人知的 ASCII（即美国标准信息交换代码）。此后，计算机可以对检索到的文本进行进一步的处理、存储或操作。正是这一多步过程使得 OCR 能够正确地解释并将打印体文本转换成可编辑的数字格式。

### 10.2.1.3 评估 OCR 模型

评估是验证和分析我们应用程序的必要方面。我们的 OCR 应用程序有两个主要的评估指标：字符错误率 (CER) 和单词错误率 (WER) [18, 19]。CER 衡量系统识别出的错误字符率。计算公式为：

```
CER = ( Incorrect chars/Total chars ) × 100
```

WER 衡量系统识别出的错误单词率，计算公式为：

```
WER = ( Incorrect words/Total words ) × 100
```

### 10.2.2 大语言模型

人工智能的最新进展导致了极其智能的大语言模型（LLMs）的发展。

### 10.2.2.1 LLM 的架构与功能

LLM 使用许多层构建；其中一个关键组件被称为 `transformers` 的东西。它们通过两个主要步骤进行学习：`pretraining`（预训练）和 `fine-tuning`（微调）。在 `pretraining` 阶段，模型从大量的文本中学习以理解语言。然后在 `fine-tuning` 阶段，模型在特定任务上变得更出色。

### 10.2.2.2 LLM 与传统机器学习的区别

LLM 的工作方式与传统机器学习不同；因此它们的学习过程、语言理解和灵活性存在差异。我们在表 10.3 中对两者进行了对比。

### 10.2.4 翻译

英语是医疗行业的通用语言。作为标准做法，报告、诊断、处方和其他所有医疗文件都用英语编写。然而，世界上很大甚至大部分人口并不懂英语。目前有多种云端翻译解决方案可用，如 `Google Translate`、AWS 上的 `Amazon Translate` 以及 `Microsoft Azure Translator`。然而，脱颖出的解决方案是 `DeepL Translator` [15]。
