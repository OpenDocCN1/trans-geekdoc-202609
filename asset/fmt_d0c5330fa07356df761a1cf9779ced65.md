
从示例 1 的输出中可以断定，如果字符串和字节切片之间的转换结果大于 32，则字节切片元素分配在堆上。注意，常量字符串转换的阈值放宽到了 64K，这就是为什么 `h` 函数中没有逃逸。

## 4.8.4 使用更小的阈值

请注意，如果指定了 `-smallframes` 编译器选项，上述的 64K 和 10M 阈值会变得小（分别为 16K 和 128K）。例如，如果我们使用命令 `go run -gcflags='-smallframes' main.go` 来运行下面的程序，所有检查的函数都将在堆上进行一次分配。

```go
// main.go
package main

import "testing"

const N = 16 * 1024 // 16384
const M = 128 * 1024 // 131072

var x byte = 123

func new16384() byte {
	// ({65535}byte) escapes to heap
	var a = new([N+1]byte)
	for i := range a { a[i] = x }
	return a[x]
}

func comptr16384() byte {
	// ({65535}byte) escapes to heap
	var a = &[N+1]byte{}
	for i := range a { a[i] = x }
	return a[x]
}

func make16384() byte {
	// make([]byte, N+1) escapes to heap
	var a = make([]byte, N+1)
	for i := range a { a[i] = x }
	return a[x]
}

func declare131073() byte {
	var a [M+1]byte
	for i := range a { a[i] = x }
	return a[x]
}

func main() {
	stat := func(f func()) int {
		allocs := testing.AllocsPerRun(10, func() {
			f()
		})
		return int(allocs)
	}

	// Print 1 if "-smallframes" is specified,
	// and print 0 if "-smallframes" is unspecified,
	println(stat(new16384))
	println(stat(comptr16384))
	println(stat(make16384))
	println(stat(declare131073))
}
```

如果我们使用命令 `go run main.go` 来运行程序，那么所有被检查的函数都不会在堆上进行分配。

## 4.8.5 即使切片的底层数组大小大于或等于 64K（但不大于 10M），也在栈上分配其底层数组

我们已经了解到，可以在栈上分配的最大切片底层数组是 65536（在 Go v1.17 之前为 65535）。有一个技巧可以将此限制提高到 10M：从栈分配的数组派生切片。例如，在下面的程序创建的切片 `s` 的元素被分配在栈上。`s` 的长度为 10M，远大于 65536。

```go
package main

import "testing"

const N = 10 * 1024 * 1024 // 10M
var n = N/2

func func1() byte {
	var a [N]byte // allocated on stack
	for i := range a {
		a[i] = byte(i)
	}
	var s = a[:n] // a slice with 10M elements
	var p = &a
	return s[n] + p[n]
}

func main() {
	stat := func(f func()) int {
		allocs := testing.AllocsPerRun(10, func() {
			f()
		})
		return int(allocs)
	}
	println(stat(func1)) // 0
}
```

从 Go 1.21 版本开始，这个技巧仍然有效。

## 4.8.6 在栈上分配任意长度的切片的底层数组

看起来当前标准 Go 编译器实现（v1.21.n）中的逃逸分析模块漏掉了使用复合字面量创建切片的情况。当使用复合字面量创建切片时，切片元素始终会被分配在栈上（如果编译器认为切片元素仅由一个 goroutine 使用），无论切片的长度和元素的大小。例如，下面的示例程序将在栈上分配字节切片的 500M 个元素。

```go

var v byte = 123

	// []byte{...} does not escape
	var s = make([]byte, N)
	for i := range s { s[i] = v }

	stat := func(f func()) int {
		allocs := testing.AllocsPerRun(10, func() {
			f()
		})

}
```

## 5.2 自动 GC 可能会影响 Go 程序的执行性能

GC 周期会消耗某些 CPU 资源，因此取决于程序代码的编写方式，可能会影响 Go 的执行性能。通常，如果程序代码写得很好，我们不需要担心 GC 带来的性能影响，因为 GC 周期仅消耗主程序逻辑消耗的 CPU 资源的一小部分。与自动 GC 带来的便利相比，这种微小的性能损失是值得的。

然而，如果程序中的某些代码编写不当，导致 GC 周期变得繁忙（频繁运行并扫描大量指针），那么 GC 可能会严重影响程序的执行性能。

## 5.3 如何减轻 GC 压力？

无论 GC 调优器如何（以及未来如何），减轻 GC 压力的基本原理包括：

- 在堆上分配更少短周期的内存块（垃圾回收产生速度）。
- 创建更少的指针（扫描工作负载控制）。

当局部值分配在堆上时，栈上会创建一个隐式指针来引用该局部值，以便该值部分是可追溯的（从栈开始）。这意味着减少堆分配有助于减少指针。

在编程中，内存分配和指针创建是不可避免的。如果需要，就尽管去做。我们不需要费尽精力去刻意避免指针。

事实上，指针通常可以用来降低成本。是否使用某些指针取决于具体情况。我们应该在缺点显而易见的情况下避免使用指针。

我们应该避免不必要的内存分配，尤其是不必要的内存分配。然而，由于许多原因（如语言安全性和 API 设计限制），不必要的内存分配很难完全避免。Go 不是 C，我们应该承认并接受这一事实。毕竟，Go 比 C 提供了更多便利性。

之前的章节已经介绍了一些避免分配的技巧。接下来的章节将介绍更多内容。

## 5.4 内存碎片

随着内存块不断被分配和回收，内存会变得碎片化。目前的官方标准 Go 运行时以有效的方式管理内存（基于 tcmalloc），因此碎片在 Go 编程中通常不是问题。

本书没有提供避免内存碎片的建议。

## 5.5 共享内存块导致的内存浪费

有时，多个值部分被载在同一个内存块（分配在堆上）中。只有当所有值部分都不被使用时，该内存块才能被回收。换句话说，内存块上的一个微小值部分就会阻止内存块被回收，即使该微小部分只占内存块的一小部分。

通常，这种情况发生在以下场景：

- 切片（或数组或字符串）的若干元素仍然存活，但其他未使用。
- 结构体值的字段仍然存活，但其他字段未使用。
- 以上两者的结合。

以下是一个展示这种情况的示例。示例中，切片的 1000 个元素都载在同一个内存块上。

```go
package main

import (
	"log"
	"runtime"
	"time"
)

func main() {
	log.SetFlags(0)
	var s = make([]int, 1000)
	for i := range s {
		s[i] = 1
		runtime.SetFinalizer(&s[i], func(v interface{}) {
			log.Println("element", *v.(*int), "is collected")
		})
	}
	var p = &s[999]
	runtime.GC()
	// log.Println(*p) // 999
	time.Sleep(time.Second)
}
```

运行此程序，它将打印：

```text
element 999 is collected
element 998 is collected
element 997 is collected
...
element 1 is collected
element 0 is collected
```

输出表明新的 GC 周期（由手动调用 `runtime.GC` 触发）使得载有切片元素的内存块被回收，否则这些元素的终结器将不会执行。

让我们取消注释 `log.Println(*p)` 行并再次运行程序，然后它将仅仅打印 999，这表明当手动 GC 周期结束时，载有切片元素的内存块仍未被回收。是的，事实上切片中的最后一个元素仍在使用阻止了内存块被回收。

我们可以将长生存值部分拷贝（使其载在较小的内存块上）到被回收的旧较大内存块中。例如，我们替换上述程序中的以下行（并开启 `log.Println(*p)` 行）：

```go
var p = &s[999]
```
