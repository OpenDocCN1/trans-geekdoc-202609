
2016 年，SQL 标准修订为支持行模式匹配、多态表函数，以及对存储在字符字符串字段中的 JSON 数据的操作。

2019 年，SQL 标准修订为增加第 15 部分：多维数组（`MDarray` 类型和运算符）。

### SQL:2023

最新版 SQL 标准（ISO/IEC 9075:2023）于 2023 年 6 月正式采纳（[`www.iso.org/standard/76584.html`](https://www.iso.org/standard/76584.html)）。此修订增加了许多可选特性（唯一约束中的空值、字符串填充函数等）、对 JSON 的更深层支持，以及第 16 部分：属性图查询（SQL/PGQ）。关于 SQL:2023 的更多细节，另请参阅 [SQL:2023 - Wikipedia](https://en.wikipedia.org/wiki/SQL:2023)。

### 商业实现

目前，大多数商业 DBMS 已实现 SQL:1999 中增加的许多特性（如触发器、行类型和大对象），以及后续版本中增加的一些特性。然而，任何商业系统完全实现 SQL:2023 的可能性极低。商业方言对标准中实现的某些特性使用自己的非标准语法，也有自己的扩展特性未包含在标准中。

## 12.4 SQL：标识符与数据类型

对于给定模式，某些数据库对象（如基本表、视图、域、触发器、规则和约束）由名称标识。列通过将其（局部）名称附加到其表的名称后，使用“点符号”来标识。这区分了不同表中具有相同局部名称的列。

例如，表 `Subject`（subjectCode, title, credit）和 `Book`（isbn, title）的第二列分别标识为 `Subject.title` 和 `Book.title`。

在 SQL 中，所有名称（包括局部名称）都称为*标识符*，尽管局部名称仅在有限上下文中提供标识。

### 标识符规则演进

在 SQL-89 中，标识符限制为最多 18 个字符，且所有字母必须大写。

从 SQL-92 起，标识符分为常规标识符或分隔标识符。

*常规标识符*是一个最多 128 个字符的字符串，其首字符必须是字母（"a".."z", "A".."Z"）。后续每个字符必须是字母、数字（"0".."9"）或下划线（"_"）。此外，**保留字不得用作常规标识符**。但你可以将保留字作为标识符的一部分使用。例如，"note" 可作为标识符，尽管它包含保留字 `NOT`。

Microsoft SQL Server 允许最多 128 个字符的标识符，但也允许首字符为 "_"、"#" 或 "@"，后续字符为 "#"、"@" 或 "$"。它使用 "#" 开头命名临时对象，用 "@" 开头命名变量名。一些商业系统允许最多 255 个字符的标识符。

### SQL 标识符、关键字和数据类型

#### 定界标识符

*定界标识符* 是一个最多包含 128 个字符的字符串，由双引号界定（即括在双引号内）。双引号内可使用任何字符，包括保留字。例如，以下均为合法的定界标识符：“customer nr”、“speed (km/h)”、“&ˆ%!!”、“date”、“group”。与常规标识符不同，定界标识符**区分大小写**（即大写字母不等同于小写字母）。例如，定界标识符 “invoiceNr”、“InvoiceNr” 和 “INVOICENR” 互不相等，但常规标识符 `InvoiceNr` 和 `INVOICENR` 是相等的。

#### 字符串常量与定界标识符

在 SQL 中，字符串常量由*单*引号界定。例如，‘USA’ 可能是 `countryCode` 列中的一个值。某些商业 SQL 允许使用双引号代替，例如，“USA”。**不应提倡**这种做法，因为它与双引号用于定界标识符的现行标准用法相冲突。

在 Microsoft SQL Server 中，命令 `set quoted_identifer on` 可确保双引号仅用于定界标识符，禁止其用于界定字符串常量。SQL Server 还允许使用方括号（`[…]`）作为双引号（“…”）的替代方案。

#### 保留字和关键字

在早期版本中被保留的字，在后续版本中可能不再保留。例如，名称 `avg`、`between`、`exists` 和 `sum` 在 SQL:1999 中从保留词降级为非保留关键字。*关键字* 是具有预定义含义的单词。*保留字* 是不能用作常规标识符的关键字。

如前所述，保留字可以嵌入标识符中。假设某列要存储辅导组的名称。因为 `group` 是保留字，所以我们不能直接将其（不加引号）用作列名。但是，我们可以加上引号使其成为定界标识符，或者将 “group” 包含在较长的常规标识符中（例如，“group”、`TuteGroup`、`GroupName`）。

通过检查某 SQL 方言的关键字列表，尤其是其保留字列表，可以初步了解该方言与标准的对比情况。在本书涉及 SQL 的地方，关键字通常通过**粗体**显示来区分。其他系统常使用大写，例如 “SELECT”。

#### 标准数据类型

表列中输入的值属于为该列声明的*数据类型*。表 12.4 列出了某些旧版 SQL 标准的标准数据类型。此处，方括号表示可选组件。所有 SQL 方言至少支持字符串和数值类型。

##### SQL:2016 和 SQL:2023 新增内容

SQL:2016 和 SQL:2023 新增了更多数据类型，例如 `tinyint` (0.0.255)、`datetime` (yyyy-mm-dd hh:mi:ss 格式)、`text` (长度可变、最大 2 GB 的字符串)、`ntext` (最大 1 GB) 和 `JSON` (JavaScript Object Notation) 数据。

##### 字符串类型

在标准中，`char(n)` 表示值作为固定长度为 *n* 个字符的字符串存储。如果值不足 *n* 个字符，则追加空格以补齐长度。如果未指定大小 (*n*)，则视为仅包含一个字符的字符串。`varchar(n)` 类型的值作为最多 *n* 个字符的字符串存储。如果值较短，则不添加额外空格直接存储。`varchar(n)` 字符串还有一个“字符串结束”标记，其大小因实现而异。在估算所需存储空间时必须考虑这一点。对于长度变化不大的短字符串，`char(n)` 可能是首选。

##### 国家字符集

SQL-92 允许声明各种国家字符集。使用 `nchar` 或等效的语法变体，表明字符选自指定的国家字符集。这意味着字符编码使用 *Unicode*，通常每个字符需要两字节存储，而编码标准英文字符和符号（常称为 *ASCII* 码，源自标准机构名称）过去通常每字符只需一字节。

##### 数值类型

对于 `numeric` 数据类型，精度 *p* 是数字中包含的最大位数，标度 *s* 是小数点后的位数。例如，声明为 `numeric(6, 2)` 的列允许的值范围为 -9999.99 到 +9999.99。`decimal` 类型类似于 numeric 类型，只是实现有时可能提供大于 *p* 的精度。许多系统将 `numeric` 和 `decimal` 实现为同一类型。`integer`（包括 `smallint` 和 `bigint`）数据类型仅允许整数（无小数部分）。三种近似数值数据类型允许将极大或极小的数字按指定精度，以尾数乘以 10 的指数形式存储。缩写 `char`、`dec`、`int` 和 `nchar` 可分别展开为 `character`、`decimal`、`integer` 和 `national character`。

##### 时间和位串类型

SQL-92 及后续标准为位串以及时间点和时间间隔提供了直接支持。除非指定 `with time zone` 选项，否则时间为本地时间。该选项包含相对于 UTC（协调世界时，旧称格林威治标准时间 (GMT)）的偏移量。提供了各种时间运算符（例如，通过用一个时间点减去另一个时间点来计算间隔）。

##### SQL:1999 预定义类型和用户定义类型

在 SQL:1999 中，所有前述数据类型称为*预定义类型*。正如表 12.4 所示，SQL:1999 新增了四种预定义类型：字符大对象、国家字符大对象、二进制大对象和布尔类型（真或假）。此外，SQL:1999 还允许行类型、用户定义类型 (UDT)、*引用类型* 和 *集合类型*。行类型基本上是一系列字段的序列，可用作定义表的基础。UDT 由其名称标识，并可能包含方法规范列表。如果基于单一预定义类型，则称为*独特类型*。如果指定为属性定义列表，则称为*结构化类型*。SQL:1999 允许的唯一集合类型构造器是数组。SQL:2003 标准新增了对 `multiset`（包）作为集合类型、大整数 (`bigint`) 的支持，以及重要的是，将 `xml` 作为 SQL 中公认的数据类型（我们将在后续章节回到 `xml` 类型）。

##### 商业 SQL 支持与差异

目前，大多数商业 SQL 支持所有 SQL-89 数据类型；几乎支持所有额外的 SQL-92 数据类型；支持部分 SQL:1999、SQL:2003、SQL:2016 和 SQL:2023 新增数据类型；并支持一些非标准数据类型。

存在许多差异。例如，Oracle 将 `varchar` 视为 `char`，并使用 `varchar2` 表示标准 `varchar`。SQL Server 包含许多额外数据类型，如 `money`、`smallmoney` 和 `uniqueidentifier`。大多数标准类型的范围通常由实现定义而非标准化。例如，`smallint` 的范围通常（但不总是）为 −32,768..32,767。

## 12.5 SQL：选择列、行和排序

回顾一下，关系代数包含以下八种表操作：并、交、差、笛卡尔积、选择、投影、连接和除。所有这些操作（以及其他操作）均可用 SQL 功能强大的 `select` 语句来表达。本节讨论如何使用 SQL 执行关系投影和选择，以及包投影和行排序。

### 选择列

首先，让我们看看如何**选择列**。考虑一个小型的论域（UoD），其中人员通过名字来识别。表 12.5 提供了表模式 `Person` (firstname, gender, starsign, birthyr) 的样本数据。

#### 表 12.5 存储个人详细信息的关系表

![t12-01-9780443237904](img/t12-01-9780443237904.jpg)

可以通过在所有列上投影来检索整个表。在关系代数中，这可以表述为 `Person` 或 `Person [firstname, gender, starsign, birthyr]`。在 SQL 中，这表示如下：

```
select * from Person
```

这里，星号 `*` 意味着“所有列”，可以读作“everything”或“all”。`from` 后面指定的表名表示从中检索数据的表。执行此命令时，结果是一个**未命名**表，具有与原始 `Person` 表相同的列名和内容。

如果只需要部分列，则应列出相关列（用逗号分隔）代替 `*`。如果列包含键，则结果中不会出现重复行，因此结果对应于这些列上的关系投影（例如，参见图 12.32）。为了提高可读性，SQL 查询通常分布在多行上（例如，新行用于开始 `from` 子句）。除限定（带引号）标识符或字符串常量外，字母的大小写（大写或小写）没有意义。我们大多使用小写，但表名以大写字母开头。许多组织都有自己关于大小写使用的详细标准。

#### 图 12.32 在包含键的列上投影

![Fig. 12.32 Projecting on columns that include a key.](img/f12-32-9780443237904.jpg)

如果所选列不包含键，则结果中可能出现重复行。例如，图 12.33(a) 中的查询返回一个包（多重集）而非集合，因为 (“M”, “Gemini”) 出现了两次。此操作可称为**包投影**。有时包含重复行很有用（例如，列出体操比赛中裁判给出的所有分数）。可以通过在 `select` 列表前使用限定符 `all` 显式请求包含重复行，但这在 SQL 中反正是默认行为。因此，`select all a,b,… from T` 形式的查询等同于 `select a,b,… from T`。

#### 图 12.33 distinct 限定符可用于删除重复行

![Fig. 12.33 The distinct qualifier may be used to remove duplicate rows.](img/f12-33-9780443237904.jpg)

要消除重复，请在 `select` 列表前包含限定符 `distinct`。这可确保显示的行是唯一的，从而提供关系投影。因此，`distinct` 限定符将行包转换为行集。例如，图 12.33(b) 中的查询消除了重复的 (“M”, “Gemini”) 行。

列按 `select` 列表中指定的顺序显示。如果使用 `*`，则所有列按与原始表相同的顺序显示。因此，命令 `select * from Person` 仅仅是 `select firstname, gender, starsign, birthyr from Person` 的简写。

一般来说，关系代数的关系投影 `T[a, b,...]` 可以用以下形式的 SQL 语句表示：

```
select distinct a,b,… from T
```

我们可以用以下扩展巴科斯-诺尔范式（EBNF）表示法总结迄今为止涵盖的 `select` 语句部分。符号 `::=` 可读作“is defined as”。这里，方括号中的项目是可选的。表达式 `[,...]` 表示前一个构造可以重复任意次数，其出现之间用逗号分隔。竖线 `|` 用于分隔备选项。默认情况下，`|` 具有最小作用域（即，它仅适用于紧邻它的项）。关键字以粗体显示。此处显示的 `select` 查询的最后一行称为 `from` 子句。从逻辑角度来看，最好在选择列表之前指定 `from` 子句，但该语言的语法不允许这样做。

```
select-list  ::=  columnname [,...]
select-query ::=  select [all | distinct ] select-list | * from tablename
```

```
select * from Person
where upper(starsign) = ‘AQUARIUS’
```
