
# 数据库事务持久性与安全

数据库事务必须是持久的。即一旦提交到数据库，就必须被保留。数据库通过备份机制（如事务日志）来确保持久性。

在以下章节中，我们将讨论数据库开发人员和管理员关注的各种具体安全问题。

## 多级数据库安全

正如您在第 1 章所学，许多组织使用数据分类方案，根据分配给数据对象和个别用户的安全标签来实施访问控制限制。当组织的安全策略强制要求时，这一分类概念也必须扩展到组织的数据库中。

多级安全数据库包含不同分类级别的信息。它们必须验证分配给用户的标签，并根据用户请求，仅提供适当的信息。然而，在考虑数据库安全时，这一概念变得更加复杂。

当需要多级安全时，管理员和开发人员必须努力将具有不同安全要求的数据分开。混合不同分类级别和/或“需知”要求的数据被称为**数据库污染**，这是一个重大的安全挑战。通常，管理员会部署可信前端，为遗留或不安全的 DBMS 增加多级安全功能。

### 并发控制

**并发控制**（或编辑控制）是一种预防性安全机制，旨在确保数据库中存储的信息始终正确，或者至少保护其完整性和可用性。此功能可用于单级或多级数据库。

未能正确实现并发控制的数据库可能会遭受以下问题：

*   **丢失更新**：当两个不同的进程在不知晓对方活动的情况下对数据库进行更新时发生。例如，设想一个仓库的库存数据库，有不同的接收站。仓库目前可能有 `10` 本《CISSP 学习指南》库存。如果两个不同的接收站同时各收到一本《CISSP 学习指南》，它们都可能检查当前库存水平，发现是 `10`，将其加 `1`，并将表更新为 `11`，而实际值应为 `12`。

*   **脏读**：当一个进程读取未成功提交的事务的记录时发生。回到仓库示例，如果一个接收站开始向数据库写入新库存记录，但在更新中途崩溃，如果事务未完全回滚，可能会在数据库中留下部分不正确的信息。

并发控制使用“锁”功能允许一个用户进行更改，但拒绝其他用户同时访问视图或更改数据元素。然后，更改完成后，“解锁”功能恢复其他用户访问所需数据的能力。在某些情况下，管理员会将并发控制与审计机制结合使用，以跟踪文档和/或字段更改。当审查这些记录数据时，并发控制就变成了一种侦查型控制。

### 其他安全机制

使用 DBMS 时，管理员可以部署其他几种安全机制。这些功能相对容易实现，在行业中很常见。例如，与语义完整性相关的机制是 DBMS 的常见安全功能。语义完整性确保用户操作不违反任何结构规则。它还检查所有存储的数据类型是否在有效域范围内，确保只存在逻辑值，并确认系统符合所有唯一性约束。

管理员可以使用时间和日期戳来维护数据完整性和可用性。时间和日期戳常出现在分布式数据库系统中。当时间戳被放置在所有更改事务上，并且这些更改被分发或复制到其他数据库成员时，所有更改都会应用到所有成员，但会按正确的时间顺序实施。

DBMS 的另一个常见安全功能是数据库内的对象可以被细粒度控制；这也可以改进安全控制。**基于内容的访问控制** 是细粒度对象控制的一个例子。基于内容的访问控制基于被访问对象的内容或有效载荷。因为必须逐个对象做出决策，基于内容的控制会增加处理开销。另一种细粒度控制形式是**单元抑制**。单元抑制是隐藏单个数据库字段或单元，或对它们施加更多安全限制的概念。

**基于上下文的访问控制** 常与基于内容的访问控制一起讨论，因为术语相似。基于上下文的访问控制从大局出发做出访问控制决策。基于上下文的访问控制的关键因素是每个对象、数据包或字段如何与整体活动或通信相关联。任何单个元素单独看可能都无害，但在更大的上下文中，该元素可能被揭示为良性或恶性。

## 数据库分区与多实例化

管理员可能会采用**数据库分区**来规避聚合和推理漏洞，这些漏洞将在本章后面的“聚合”部分讨论。数据库分区是将单个数据库拆分为多个部分的过程，每个部分具有唯一且不同的安全级别或内容类型。

**多实例化**，在数据库上下文中，是指同一关系数据库表中的两行或多行似乎具有相同的主键元素，但包含供不同分类级别使用的不同数据。它常被用作防御某些类型推理攻击的手段（参见第 9 章中的“推理”）。

考虑一个包含多艘巡逻海军舰艇位置的数据库表。通常，该数据库在机密级别存储每艘舰艇的确切位置。然而，有一艘特定的舰艇——`USS UpToNoGood`——正在执行一项前往绝密地点的秘密任务。军事指挥官不希望任何人知道该舰艇偏离了其正常巡逻路线。如果数据库管理员仅将 `USS UpToNoGood` 的位置分类更改为绝密，拥有机密许可的用户在无法查询该舰艇位置时，就会知道发生了异常情况。但是，如果使用多实例化，可以向表中插入两条记录。第一条记录在绝密级别，反映舰艇的真实位置，仅对具有相应绝密安全许可的用户可用。第二条记录在机密级别，表明该舰艇正在执行例行巡逻，并将返回给拥有机密许可的用户。

最后，管理员可以将虚假或误导性数据插入 DBMS，以重定向或挫败信息机密性攻击。这是一个称为**噪声和扰动**的概念。使用此技术时必须极其小心，以确保插入数据库的噪声不影响业务操作。

## 开放数据库互连

**开放数据库互连 (ODBC)** 是一项数据库功能，允许应用程序与不同类型的数据库通信，而无需为与每种类型的直接交互进行编程。ODBC 作为应用程序和后端数据库驱动程序之间的代理，使应用程序程序员在创建解决方案时拥有更大的自由度，而无需担心后端数据库系统。图 20.9 说明了 ODBC 与后端数据库系统之间的关系。

## NoSQL

随着数据库技术的发展，许多组织在需要提高速度或其数据不适合整齐地放入表格形式的情况下，开始放弃关系模型。NoSQL 数据库是一类使用除关系模型以外的模型来存储数据的数据库。

NoSQL 数据库主要有三大类：

*   **键/值存储** 或许是数据库最简单的形式。它们以键/值对的形式存储信息，其中键本质上是一个用于唯一标识记录的索引，记录由一个数据值组成。键/值存储适用于高速应用程序和超大数据集。

*   **图数据库** 以图格式存储数据，使用节点表示对象，使用边表示关系。它们适用于表示任何类型的网络，例如社交网络、地理位置以及其他适合图表示的数据集。

*   **文档存储** 与键/值存储类似，它们使用键来存储信息，但存储的信息类型通常比键/值存储中的更复杂，且以文档形式存在。文档存储中常用的文档类型包括可扩展标记语言 (XML) 和 JavaScript 对象表示法 (JSON)。

NoSQL 数据库使用的安全模型可能与关系数据库有显著差异。使用此技术的组织中的安全专业人员应熟悉其所用解决方案的安全功能，并与数据库团队协商设计适当的安全控制。

## 存储数据和信息

数据库管理系统帮助利用数据的力量，并对谁可以访问数据以及他们可以对数据执行什么操作获得一定程度的控制。然而，安全专业人员必须记住，DBMS 安全仅涵盖通过传统“前门”渠道访问信息的情况。数据还通过计算机的存储资源进行处理——包括内存和物理介质。必须采取预防措施，确保这些基本资源也受到保护，免受安全漏洞的影响。毕竟，你永远不会花费大量时间和金钱保护家里的前门，却把后门大敞四开，对吧？

### 存储类型

现代计算系统使用多种类型的存储来维护系统和用户数据。系统在各种存储类型之间取得平衡，以满足组织的计算需求。有几种常见的存储类型：

*   **主存储（或“实”存储）** 由直接可用于系统 CPU 的主内存资源组成。主存储通常由易失性随机存取存储器 (RAM) 组成，通常是系统可用的最高性能存储资源。

*   **辅助存储** 由价格较低、非易失性的存储资源组成，可供系统长期使用。典型的辅助存储资源包括磁性和光学介质，如磁带、磁盘、硬盘驱动器、闪存驱动器和光盘/数字多功能光盘 (CD/DVD) 存储。

*   **虚拟内存** 允许系统通过使用辅助存储来模拟额外的主内存资源。例如，一个昂贵 RAM 资源不足的系统可能会将一部分硬盘用于直接 CPU 寻址。

*   **虚拟存储** 允许系统通过使用主存储来模拟辅助存储资源。虚拟存储最常见的例子是 RAM 磁盘，它向操作系统呈现为辅助存储设备，但实际上是用易失性 RAM 实现的。这为各种应用程序提供了极快的文件系统，但不提供恢复能力。

*   **随机存取存储** 允许操作系统从介质内的任意点请求内容。RAM 和硬盘驱动器是随机存取存储资源的例子。

*   **顺序存取存储** 要求从头开始扫描整个介质以到达特定地址。磁带是顺序存取存储资源的常见例子。

*   **易失性存储** 在电源从资源移除时丢失其内容。RAM 是最常见的易失性存储资源类型。

*   **非易失性存储** 不依赖电源的存在来维护其内容。磁性/光学介质和非易失性 RAM (NVRAM) 是典型的非易失性存储资源示例。

### 存储威胁

#### 数据存储系统的信息安全威胁

信息安全专业人员应了解针对数据存储系统的两大主要威胁。首先，无论使用何种类型的存储，非法访问存储资源的威胁始终存在。如果管理员未实施足够的文件系统访问控制，入侵者可能仅通过浏览文件系统就偶然发现敏感数据。在更敏感的环境中，管理员还应防范绕过操作系统控制并直接访问物理存储介质以检索数据的攻击。这最好通过使用加密文件系统来实现，该文件系统仅可通过主操作系统访问。此外，在多级安全环境中运行的系统应提供足够的控制，以确保共享内存和存储资源设置了失效安全控制，使得某一密级的数据在较低密级下不可读。

隐蔽通道攻击构成了针对数据存储资源的第二大主要威胁。隐蔽存储通道允许通过直接或间接操纵共享存储介质，在密级之间传输敏感数据。这可能仅仅是将敏感数据写入无意中共享的内存部分或物理存储中。更复杂的隐蔽存储通道可能被用来操纵磁盘上的可用空间大小或文件的大小，以隐蔽地在安全级别之间传递信息。有关隐蔽通道分析的更多信息，请参见第 8 章“安全模型、设计与能力原则”。

## 理解基于知识的系统

自计算机诞生以来，工程师和科学家一直致力于开发能够执行常规操作的系统，这些操作会让人类感到厌烦并消耗大量时间。该领域的大多数成就都集中在减轻计算密集型任务的负担上。然而，研究人员在开发具有“人工智能”且能模拟（某种程度上）纯人类推理能力的系统方面也取得了巨大进展。

以下部分将探讨两种基于知识的人工智能系统：专家系统和神经网络。我们还将了解它们在计算机安全问题上的潜在应用。

### 专家系统

专家系统旨在体现特定主题专家的积累知识，并以一致的方式将其应用于未来的决策。多项研究表明，当专家系统得到妥善开发和实施时，在面对常规决策时，其决策往往优于部分人类对应者。

每个专家系统都有两个主要组件：知识库和推理引擎。

知识库包含专家系统已知的规则。知识库旨在将人类专家的知识编纂为一系列“如果/那么”语句。让我们考虑一个简单的专家系统，旨在帮助房主决定当飓风来袭时是否应撤离该区域。知识库可能包含以下语句（这些语句仅为示例）：

* 如果飓风为 4 级或更高，则洪水通常会达到海平面以上 20 英尺的高度。
* 如果飓风风速超过 120 英里/小时 (mph)，则木结构建筑将被摧毁。
* 如果处于飓风季节末期，则飓风在逼近海岸时往往会变得更强。

在实际的专家系统中，知识库将包含数百或数千条类似上述的断言。

专家系统的第二个主要组件——推理引擎——分析知识库中的信息以得出适当的决策。专家系统用户通过某种用户界面向推理引擎提供当前情况的详细信息，推理引擎结合逻辑推理和模糊逻辑技术，基于过去的经验得出结论。继续以飓风为例，用户可能会告知专家系统一个 4 级飓风正以平均 140 英里/小时的风速逼近海岸。推理引擎将分析知识库中的信息，并基于这些过往知识做出撤离建议。

专家系统并非万无一失——它们的优劣取决于知识库中的数据和推理引擎中实现的决策算法。然而，它们在压力情境下有一个主要优势——其决策不涉及被情绪模糊的判断。专家系统可在分析紧急事件、股票交易及其他情感投入有时会妨碍逻辑决策的场景中发挥重要作用。因此，许多贷款机构现在使用专家系统做出信贷决策，而不依赖可能会想“吉姆虽未按时还款，但他看起来是个挺好的人”的贷款官员。

### 机器学习

机器学习技术利用分析能力从数据集中开发知识，而无需直接应用人类洞察。机器学习的核心方法是允许计算机直接分析数据并从中学习，开发和更新活动模型。

机器学习技术分为两大类。

* **监督学习** 技术使用标记数据进行训练。创建机器学习模型的分析师提供数据集及正确答案，并允许算法开发可应用于未来案例的模型。例如，如果分析师想开发恶意系统登录的模型，分析师将提供一段时间内系统登录信息的数据集，并标明哪些是恶意的。算法将利用这些信息开发恶意登录的模型。

* **无监督学习** 技术使用未标记数据进行训练。提供给算法的数据集不包含“正确”答案；相反，算法被要求独立开发模型。在登录案例中，算法可能被要求识别相似登录的群组。分析师随后可查看算法开发的群组，并尝试识别可能为恶意的群组。

### 神经网络

在神经网络中，计算单元链被用来尝试模仿人类大脑的生物推理过程。在专家系统中，一系列规则存储在知识库中；而在神经网络中，则建立了一条长长的计算决策链，它们相互馈送并最终求和以产生所需输出。神经网络是机器学习技术的延伸，也常被称为*深度学习*或认知系统。

请记住，迄今为止设计的任何神经网络都远未达到人类思维的推理能力。尽管如此，神经网络显示出巨大潜力，可将人工智能领域推向当前状态之外。神经网络的优势包括线性、输入输出映射和自适应性。这些优势在语音识别、人脸识别、天气预测以及思维和意识模型探索的神经网络实现中显而易见。

典型的神经网络涉及多层求和运算，每一层都需要对信息进行加权，以反映该计算在整体决策过程中的相对重要性。权重必须根据神经网络预期要做出的每种决策类型进行定制。这是通过训练期来实现的，在训练期内，网络会被提供已知正确决策的输入。然后算法从这些决策反向推导，以确定计算链中每个节点的适当权重。此活动使用所谓的 `Delta rule`（增量规则）或 `learning rule`（学习规则）来执行。通过使用 `Delta rule`，神经网络能够从经验中学习。

#### 安全应用

基于知识的分析技术在计算机安全领域有着广泛的应用。这些系统提供的主要优势之一是其快速做出一致决策的能力。计算机安全中的一个主要问题是，系统管理员无法始终如一且彻底地分析海量的日志和审计追踪数据以查找异常。这简直是天作之合！

## 摘要

数据是许多组织拥有的最有价值的资源。因此，信息安全从业者必须理解保护数据本身以及协助处理该数据的系统和应用程序的必要性。每个技术感知型组织都必须实施针对恶意代码、数据库漏洞以及系统/应用程序开发缺陷的防护措施。

恶意代码对象对组织的计算资源构成威胁。这些威胁包括病毒、逻辑炸弹、特洛伊木马和蠕虫。

到此，你无疑已经认识到，在这些宝贵的信息资源上设置适当的访问控制和审计追踪的重要性。数据库安全是一个快速发展的领域；如果数据库在你的安全职责中扮演重要角色，请花时间与数据库管理员坐下来交流，研读课程和教材，学习其底层理论。这是一项有价值的投资。

最后，在系统和应用程序开发过程中可以实施各种控制，以确保这些过程的最终产品能够在安全环境中运行。此类控制包括进程隔离、硬件分段、抽象，以及服务级别协议（SLA）等合同安排。安全应始终在任何开发项目的早期规划阶段引入，并在设计、开发、部署和维护等生产阶段持续受到监控。

## 考试要点

**解释关系数据库管理系统（RDBMS）的基本架构。** 了解关系数据库的结构。能够解释表（关系）、行（记录/元组）和列（字段/属性）的功能。了解表之间关系是如何定义的以及各种键的作用。描述聚合和推理带来的数据库安全威胁。

**了解各种存储类型。** 解释主存储器和虚拟内存、辅助存储和虚拟存储、随机存取存储和顺序存取存储、易失性存储和非易失性存储之间的区别。

**解释专家系统、机器学习和神经网络的工作原理。** 专家系统由两个主要组件组成：一个包含一系列“如果/那么”规则的知识库，以及一个利用该信息对其他数据得出结论的推理引擎。机器学习技术试图通过算法从数据集中发现知识。神经网络通过安排一系列分层计算来解决问题，在有限程度上模拟人类思维的运作。神经网络在能够提供解决方案之前，需要针对特定问题进行大量训练。

**理解系统开发模型。** 了解 `waterfall model`（瀑布模型）描述了一个顺序开发过程，最终产出成品。如果发现错误，开发人员在该过程中最多只能回退一个阶段。`spiral model`（螺旋模型）使用多次 `waterfall model` 迭代来生成多个规格完整且经过测试的原型。`Agile development models`（敏捷开发模型）强调客户需求，并以迭代方式快速开发满足这些需求的新功能。

**描述软件开发成熟度模型。** 了解成熟度模型通过实施一条从临时性、混乱过程演进到成熟、规范化软件过程的路径，帮助软件组织提高其软件过程的成熟度和质量。能够描述 `SW-CMM` 和 `IDEAL` 模型。

**理解变更和配置管理的重要性。** 了解变更控制的三个基本组成部分——请求控制、变更控制和发布控制——以及它们如何促进安全。解释配置管理如何控制组织中使用的软件版本。

**理解测试的重要性。** 软件测试应作为开发过程的一部分进行设计。测试应被用作一种管理工具，以改进设计、开发和生产过程。
