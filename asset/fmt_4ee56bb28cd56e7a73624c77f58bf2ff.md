## 3.3 使用命令行

使用命令行的一个简便方法是复制并粘贴 GUI 中 `Configure` 行的文本。例如，假设我们想从命令行执行任务：

```
EvaluatePrequential -l trees.HoeffdingTree -i 1000000 -w 10000
```

我们可以简单地写成：

```

```

注意某些参数缺失，因此将使用默认值。我们将在以下段落中解释该行命令。

类 `moa.DoTask` 是在命令行运行任务的主类。它将接受一个任务名称及其相应的任何参数。第一个使用的任务是 `LearnModel` 任务。`-l` 参数指定学习器，本例中为 `HoeffdingTree` 类。`-s` 参数指定学习所用的流，本例中为 `generators.WaveformGenerator`，这是一个数据流生成器，产生一个识别三种波形类型的三分类学习问题。`-m` 选项指定用于训练学习器的最大示例数，本例中为 1,000,000 个示例。`-O` 选项指定一个文件以输出结果模型：

```

```

这将创建一个名为 `model1.moa` 的文件，其中包含训练期间生成的决策树模型。

# 第二部分：流挖掘

## 4 流与素描

流可以被视为数据的一次性读取序列。流上的算法必须在我们称为*数据流公理*的条件下工作，这些公理已在第二章中说明：

1.  只允许对流进行一次遍历；每个流项目只能被观察一次。
2.  每个项目的处理时间必须很低。
3.  内存使用也必须很低，当然要低于流长度的亚线性级别；这意味着只能显式存储少量流项目。
4.  算法必须能够随时提供答案。
5.  流随时间演化，即它们是非平稳数据源。

本章关注的是满足前四条公理的算法设计。我们对流、生成流项目的过程或其可能遵守的任何统计规律*不做任何概率假设*。流是*对抗性*生成的，即遵循对算法最困难的模式。因此，公理 5 在本章中无关紧要。相比之下，在第五章中，我们将定义一种更良性的流生成模型，其中项目根据某个随机过程生成，因此遵守统计规律。这一假设让我们能够形式化公理 5，且隐含在大多数可用的流机器学习和数据挖掘算法中。

许多流问题的解决方案都使用流*素描*或*摘要*的概念。素描是一种数据结构及其伴随算法，它们读取流并存储足够的信息，以便能够回答关于流的一个或多个预定义查询。我们将把素描视为流上高层学习和挖掘算法的构建模块。从这个角度来看，使用少量内存的要求尤为迫切，因为挖掘算法通常不会创建单个素描，而是创建许多素描，以同时跟踪数据上的许多不同统计量。

### 4.1 设置：近似算法

#### 符号与预备知识

我们首先确定本书其余部分将使用的一些符号。我们用 `E[X]` 和 `Var(X)` 分别表示随机变量 `X` 的期望值和方差。不带下标的对数表示以 2 为底的对数，而 `ln` 表示自然对数。如果存在常数 `c > 0` 使得对每个 `x` 都有 `f(x) ≤ c · g(x)`，则称函数 `f` 为 `O(g)`。集合 `A` 的基数记为 `|A|`。在伪代码中，`←` 表示变量赋值，`⊳` 开启注释行。

在流处理中，*项* 仅仅是项的全集 `I` 中的一个元素，不包含任何相关的内部结构。集合 `I` 可能非常大，这意味着使用与 `|I|` 成正比的内存是不可行的。我们有时会假设存储 `I` 的一个元素占用一单位内存；当 `I` 是无限集时（例如实数集），这是必要的。在其他情况下，我们将更详细地计算存储一个项所需的比特数，这至少为 `log |I|`。

我们通过给出三个操作来定义一个 *草图* 算法：一个 `Init(...)` 操作用于初始化数据结构，可能带有一些参数，如所需的近似精度或要使用的内存量；一个 `Update(item)` 操作将应用于流上的每个项；以及一个 `Query(...)` 操作返回迄今为止已读流上某个感兴趣函数的当前值（可能带有参数，也可能不带）。通常，一个草图可能实现多种类型的查询。

许多可以在离线数据上轻松计算的函数，无法在亚线性内存下 *精确* 计算流上的结果。例如，在最坏情况和足够大的项全集下，计算所见不同项的数量需要与流长度成线性关系的内存。另一方面，对于许多函数，存在提供 *近似* 解的算法，仅以很小的精度损失换取内存和时间的巨大提升，这在应用中通常是可以接受的。接下来我们引入一些形式化方法来讨论近似计算。

设 `f` 和 `g` 为两个实值函数。我们将 `g` 视为 `f` 的近似。对于一个 *精度* 值 `ε`，我们称 `g` 为

*   `f` 的 *绝对* 或 *加性* `ε`-近似，如果对每个输入 `x` 都有 `|f(x) − g(x)| ≤ ε`；
*   `f` 的 *相对* 或 *乘性* `ε`-近似，如果对每个输入 `x` 都有 `|f(x) − g(x)| ≤ ε |f(x)|`。

流上的许多近似算法也是 *随机化* 的，意味着它们可以访问随机比特或随机数源以做出选择。它们在固定输入上的输出不是唯一定义的，因为不同运行可能产生不同结果。因此，其输出应被视为一个 *随机变量 g*，希望它在大多数情况下接近期望的 `f`。*(ε, δ)*-近似（绝对或相对）的定义类似于上述的 `ε`-近似，但只要求上述近似以至少 `1 − δ` 的概率（在算法的多次运行中）成立，而非在每一次运行中都成立。例如，要说算法的输出 `g` 是期望函数 `f` 的绝对 `(0.1, 0.01)`-近似，我们要求对每个 `x`，`g(x)` 至少在 99% 的运行中落在 `f(x)` 的 `±0.1` 范围内。值 `1 − δ` 通常称为 *置信度*。

该框架类似于用于形式化预测学习问题的 PAC 学习模型 [146]，其中 PAC 代表“概率近似正确”。应注意，通常近似保证仅在更新和查询不依赖于先前查询返回的答案时成立。也就是说，我们不能将这些保证应用于 *自适应查询*，后者在探索性数据分析中很常见。

在统计学中，近似描述随机变量 `X` 的传统方法是给出其期望值 `E[X]` 和方差 `Var(X)`。假设我们有一个随机化算法 `g` 近似期望函数 `f`，即 `E[g(x)] = f(x)` 且方差 `Var(g) = σ²`。在这种情况下，我们可以在 `g` 的基础上设计另一个算法 `h`，使其在看似更严格的 *(ε, δ)*-近似意义上近似 `f`。新算法 `h` 除 `x` 外，还接受任意 `ε` 和 `δ` 作为参数，并使用 `O((σ²/ε²) ln(1/δ))` 倍于 `f` 的内存和运行时间。正如预期的那样，随着所需精度和置信度的提高，它消耗更多资源。转换的细节见第 4.9.2 节，但我们接下来描述主要成分，因为它在流算法和流挖掘中无处不在。
