
例如，我们可能有一个名为 `photo` 的指针，它包含存储照片的内存位置的地址。当应用程序需要访问实际照片时，它会执行一个称为 `pointer de-referencing`（指针解引用）的操作。这仅意味着应用程序遵循指针并访问指针地址引用的内存。此过程并无异常。应用程序一直在这样做。

可能出现的一个特定问题是指针为空，包含程序员所谓的 `null`（空）值。如果应用程序尝试解引用此 `null` 指针，会导致称为 `null pointer exception`（空指针异常）的情况。在最好的情况下，`null pointer exception` 会导致程序崩溃，向攻击者提供可用于侦察应用程序安全性的调试信息。在最坏的情况下，`null pointer exception` 可能允许攻击者绕过安全控制。安全专业人员应与应用程序开发人员合作，帮助他们避免这些问题。

### 缓冲区溢出

当攻击者操纵程序将比为该程序分配的内存区域更多的数据放入其中时，会发生 `Buffer overflow`（缓冲区溢出）攻击。其目标是用可能由系统上运行的其他进程执行的指令覆盖内存中的其他信息。

缓冲区溢出攻击非常普遍，且往往在首次发现后持续多年。例如，2016 年 Verizon 数据泄露调查报告确定了 10 个漏洞，它们导致了研究中 85% 的妥协事件。前 10 名中有四个是溢出问题：

*   `CVE 1999-1058`：Vermillion FTP Daemon 中的缓冲区溢出
*   `CVE 2001-0876`：Windows 98、98SE、ME 和 XP 上通用即插即用 (UPnP) 中的缓冲区溢出
*   `CVE 2002-0126`：BlackMoon FTP Server 1.0 至 1.5 中的缓冲区溢出
*   `CVE 2003-0818`：Microsoft ASN.1 库中的多个整数溢出

每个漏洞标题中字母 `CVE` 后面的四位数字表示发现该漏洞的年份。在一项发生于 2015 年的泄露事件研究中，导致泄露的前 10 个问题中有四个是利用了已有 12 到 16 年历史的溢出漏洞！Verizon 在最近的报告中未包含此类分析，但没有理由认为这一趋势已改变。

在漏洞扫描期间发现 `buffer overflow`（缓冲区溢出）漏洞的网络安全分析师应寻找修复该问题的补丁。在大多数情况下，扫描报告将直接指出可用的补丁。

#### 竞争条件

当代码段的安全性取决于系统内事件发生的顺序时，会发生 `Race conditions`（竞争条件）。`time-of-check-to-time-of-use (TOCTTOU or TOC/TOU)`（检查时间到使用时间）问题是一种竞争条件，它发生在程序过早检查访问权限（远在资源请求之前）时。例如，如果操作系统在用户登录时构建一份详尽的访问权限列表，然后在整个登录会话期间查阅该列表，则存在 `TOCTTOU` 漏洞。如果系统管理员撤销了特定权限，该限制直到用户下次登录时才会应用。如果用户在访问权限撤销时已登录，他们将无限期地拥有对该资源的访问权限。用户只需保持会话打开数天，新限制就永远不会被应用。为防止此竞争条件，开发人员应在每次请求时评估访问权限，而不是缓存权限列表。

#### 无保护的 API

组织通常希望其他开发人员在其创建的平台基础上进行构建。例如，`Twitter` 和 `Facebook` 可能希望允许第三方应用程序开发人员创建向用户社交媒体动态发布内容的应用。为了实现这种创新，服务通常会创建 `application programming interfaces (APIs)`（应用程序编程接口），以实现自动化访问。

如果未妥善保护，无保护的 API 可能导致功能被未经授权地使用。例如，未使用适当身份验证的 API 可能允许任何知道 API URL 的人修改服务。非供公共使用的 API 应始终使用身份验证机制（如 `API key`（API 密钥））进行保护，并且仅通过加密通道访问，以保护这些凭据免受窃听攻击。

#### 驱动程序操纵

`Device drivers`（设备驱动程序）在计算中发挥着重要作用。它们充当硬件设备与操作系统之间的软件接口。设备驱动程序是您可以将几乎任何制造商的打印机与 `Windows` 或任何其他操作系统配合使用的原因。`Microsoft` 无需设计 `Windows` 以适配市场上每一款单独的打印机。相反，他们为打印机制造商提供为其打印机编写 `Windows` 驱动程序的能力。当制造商制造新打印机时，他们还会设计一个驱动程序，为 `Windows` 提供如何与打印机交互的指令。

设备驱动程序需要对操作系统进行低级访问，并以管理员权限运行。如果攻击者能说服用户在其计算机上安装恶意驱动程序，该恶意软件就能完全控制系统。

攻击者实现这一点的一种方法是*重构*现有驱动程序。如果他们能访问驱动程序的源代码，就可以对其进行修改，使其也包含恶意软件元素。然而，在实践中这非常难以实现，因为获取驱动程序的源代码并不容易。

无法访问驱动程序源代码的攻击者可以使用一种称为*垫片*的技术。这会获取一个合法驱动程序，并在其外部包裹一个恶意驱动程序。恶意驱动程序（称为垫片）接收来自操作系统的请求，并将其直接传递给合法驱动程序，以便设备正常运行。然而，该驱动程序也可以在后台执行其恶意软件载荷。

幸运的是，现代操作系统都包含针对恶意驱动程序的保护措施。其中最重要的保护是代码签名。设备制造商编写驱动程序，然后对其应用数字签名，以便操作系统能够验证其真实性。如果驱动程序未经过数字签名，操作系统可能会警告用户存在可疑驱动程序，或直接阻止其安装。

驱动程序的特权性质使其能深度访问操作系统。安全专业人员必须确保其组织中使用的驱动程序是合法的，且未被修改用于执行恶意活动。

## 摘要

软件在每个组织中都发挥着不可或缺的作用，执行的任务范围从财务交易到敏感物理基础设施组件的管理。网络安全专业人员必须确保其环境中使用的软件经过严格测试，以确保其满足业务需求，且不会使组织面临严重的网络安全风险。

实现这一目标需要深入了解源代码以及客户端-服务器和 Web 应用程序部署中可能出现的不同类型的漏洞。在本章中，您了解了许多此类漏洞以及用于管理软件安全风险的工具。

## 考试要点

**了解如何分析与应用程序攻击相关的指标。** 软件应用程序可能遭受各种漏洞的影响，使其容易受到攻击。您应该熟悉这些攻击，包括权限提升、跨站脚本、注入攻击、请求伪造攻击，以及攻击者利用应用程序代码的许多其他方式。了解这些攻击背后的方法有助于安全专业人员建立充分的防御并识别针对其组织的攻击。

**理解安全软件开发概念。** 软件应使用标准化的软件开发生命周期来创建，该周期将软件移动通过开发、测试、暂存和生产环境。开发人员应了解与代码重用和软件多样性相关的问题。Web 应用程序的开发应符合行业标准原则，例如开放 Web 应用程序安全项目 (OWASP) 制定的原则。

**解释安全代码部署和自动化概念。** 代码仓库充当版本控制机制，以及代码安全预配和取消预配的集中授权机构。开发人员和运维团队应共同制定自动化行动方案，因为他们在实施创建和部署软件的 DevOps 方法。软件应用程序的设计应支持可扩展性和弹性。

**了解如何实施数据库安全控制。** 数据库通常存储组织最敏感的信息，应采取数据库安全控制来充分保护该信息。这始于使用规范化的数据库设计，并继续使用存储过程与数据库交互。存储在数据库中的敏感信息应通过数据最小化、数据标记化，以及加盐和哈希的组合来保护。

**了解如何实施应用程序安全控制。** 应用程序安全应成为安全运营原则的重中之重。这包括通过输入验证保护代码。依赖 Cookie 进行会话管理的 Web 应用程序应通过传输加密来保护这些 Cookie。代码应定期接受代码审查以及静态和动态测试。

# 第 7 章：密码学与公钥基础设施

**密码学** 是以一种无法在没有所需解密密钥的情况下解码的方式对信息进行编码的实践。密码学包含两个主要操作：**加密**，即使用加密密钥将明文信息转换为密文；**解密**，即使用解密密钥将密文转换回明文。

密码学有几个重要目标。首要目标是**机密性**，这对应 CIA 三要素的三个支柱之一。组织使用加密来保护敏感信息免受窥探。第二个目标**完整性**，也对应 CIA 三要素的三个要素之一。组织使用密码学确保数据不会被恶意或无意地篡改。当我们谈到第三个目标**认证**时，密码学的目标开始与 CIA 三要素有所不同。虽然认证以字母 A 开头，但请记住 CIA 三要素中的 A 代表“可用性”。认证是指利用加密来验证个人身份。第四个目标**不可否认性**，确保个人能够向第三方证明消息确实来自其声称的发送者。不同的密码系统能够实现不同的目标，您将在本章中了解这些内容。

## 密码学概述

密码学是一门几乎与人类历史一样悠久的学科。最早有记录的密码学尝试发生在 4000 年前。这些早期尝试包括将信息从一种语言翻译成另一种语言，或替换字符。从那时起，密码学已发展为包含大量可能性。这些早期的密码学探索完全专注于实现机密性这一目标。经典方法使用相对简单的技术，人类通常能在合理的时间内破解。现代密码学中使用的混淆技术要复杂得多，在实际时间范围内可以是不可破解的。

### 历史密码学

历史密码学方法早于现代计算机时代。这些方法不依赖数学（许多现代方法都依赖数学），而是依赖某种打乱文本的技术。

**密码** 是一种用于打乱或混淆字符以隐藏其值的方法。**加密** 是使用密码对消息进行此类打乱的过程。两种主要的非数学密码学（或加密方法）是**替换**和**置换**。我们将在本节中讨论这两种方法。

#### 替换密码

**替换密码** 是一种将一个字符或符号更改为另一个字符或符号的编码或加密系统。字符替换可以是一种相对简单的信息加密方法。最古老的已知替换密码之一称为**凯撒密码**。据称由尤利乌斯·凯撒使用。该系统仅涉及将字母表中的所有字母向右移动特定数量的位置。据推测，尤利乌斯·凯撒使用了向右移动三位的方法。这意味着将消息中的 A 变为 D，B 变为 E，依此类推。当到达字母表末尾时，只需“循环”回到开头，因此 X 变为 A，Y 变为 B，Z 变为 C。

凯撒当然是在使用拉丁语，但同样的方法可以应用于包括英语在内的任何语言。以下是一个示例：

```
I WILL PASS THE EXAM
```

如果将每个字母向右移动三位，将得到以下内容：

```
L ZLOO SDVV WKH HADP
```

使用凯撒密码加密的消息的解密遵循相反的过程。解密不是将每个字母向右移动三位，而是将密文的每个字母向左移动三位以恢复原始明文字符。

凯撒密码和 ROT13 是替换密码非常简单的示例。它们过于简单，不适合今天使用，因为任何密码学家都能在几秒钟内破解这些密码或任何类似的替换。然而，替换操作构成了许多现代加密算法的基础。它们只是执行更复杂的替换，并多次执行这些操作以增加复杂性，使密码更难破解。

#### 多表替换

替换密码的问题之一在于它们没有改变文本底层的字母和单词频率。解决此问题的一种方法是对同一消息使用多个替换字母表。使用这种方法的密码称为**多表替换密码**。例如，您可以将第一个字母向右移动三位，第二个字母向右移动两位，第三个字母向左移动一位；然后对接下来的三个字母重复此公式。

历史上最著名的多表代换示例是 `Vigenère cipher`（维吉尼亚密码）。它使用一个关键字在表中查找密文，如图 7-1 所示。用户将想要加密的文本的第一个字母，在维吉尼亚表中与关键字中的字母进行匹配，以找到密文字母。此过程将重复进行，直到整条消息加密完毕。关键字中的每个字母都会生成一个不同的代换字母表。
