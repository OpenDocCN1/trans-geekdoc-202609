
此风险并非 `range` 形式的 `for` 循环所独有。下面示例中的循环因无意中捕获索引变量 `i` 而遭受相同问题：

```go
var rmdirs []func()
dirs := tempDirs()
for i := 0; i < len(dirs); i++ {
    os.MkdirAll(dirs[i], 0755) // 正确
    rmdirs = append(rmdirs, func() {
        os.RemoveAll(dirs[i]) // 注意：错误！
    })
}
```

迭代变量捕获问题最常在使用 `go` 语句 (第 8 章) 或 `defer`（稍后将介绍）时遇到，因为两者都可能将函数值的执行推迟到循环结束之后。但该问题并非 `go` 或 `defer` 固有。

## 5.7 变参函数

*变参函数* 是指可以接受不同数量参数调用的函数。最熟悉的例子是 `fmt.Printf` 及其变体。`Printf` 开头需要一个固定参数，随后接受任意数量的后续参数。

要声明变参函数，需在最后一个参数的类型前加上省略号 `...`，这表示该函数可以接受任意数量的该类型参数。

```go
func sum(vals ...int) int {
    total := 0
    for _, val := range vals {
        total += val
    }
    return total
}
```

上面的 `sum` 函数返回零个或多个 `int` 参数的和。在函数体内，`vals` 的类型是 `[]int` 切片。调用 `sum` 时，可以为其 `vals` 参数提供任意数量的值。

```go
fmt.Println(sum())           //  "0"
fmt.Println(sum(3))          //  "3"
fmt.Println(sum(1, 2, 3, 4)) //  "10"
```

隐式地，调用者分配一个数组，将参数复制进去，并将整个数组的切片传递给函数。因此上面的最后一次调用与下面的调用行为相同，后者展示了当参数已在切片中时如何调用变参函数：在最后一个参数后加上省略号。

```go
values := []int{1, 2, 3, 4}
fmt.Println(sum(values...)) // "10"
```

虽然 `...int` 参数在函数体内表现得像个切片，但变参函数的类型与带有普通切片参数的函数类型是不同的。

```go
func f(...int) {}
func g([]int)  {}

fmt.Printf("%T\n", f) // "func(...int)"
fmt.Printf("%T\n", g) // "func([]int)"
```

变参函数常用于字符串格式化。下面的 `errorf` 函数在开头带上行号构造一个格式化的错误消息。后缀 `f` 是一个广泛遵循的命名约定，用于接受 `Printf` 风格格式字符串的变参函数。

```go
func errorf(linenum int, format string, args ...interface{}) {
    fmt.Fprintf(os.Stderr, "Line %d: ", linenum)
    fmt.Fprintf(os.Stderr, format, args...)
    fmt.Fprintln(os.Stderr)
}

linenum, name := 12, "count"
errorf(linenum, "undefined: %s", name) // "Line 12: undefined: count"
```

`interface{}` 类型意味着该函数的最后参数可以接受任意类型的值，我们将在第 7 章中解释。

## 5.8 延迟函数调用

我们的 `findLinks` 示例使用 `http.Get` 的输出作为 `html.Parse` 的输入。如果请求的 URL 内容确实是 HTML，这工作良好，但许多页面包含图片、纯文本和其他文件格式。将此类文件送入 HTML 解析器可能会产生不良影响。

下面的程序获取一个 HTML 文档并打印其标题。`title` 函数检查服务器响应的 `Content-Type` 头部，如果文档不是 HTML 则返回错误。

```go
func title(url string) error {
    resp, err := http.Get(url)
    if err != nil {
        return err
    }

    // 检查 Content-Type 是否为 HTML（例如 "text/html; charset=utf-8"）。
    ct := resp.Header.Get("Content-Type")
    if ct != "text/html" && !strings.HasPrefix(ct, "text/html;") {
        resp.Body.Close()
        return fmt.Errorf("%s has type %s, not text/html", url, ct)
    }

    doc, err := html.Parse(resp.Body)
    resp.Body.Close()
    if err != nil {
        return fmt.Errorf("parsing %s as HTML: %v", url, err)
    }

    visitNode := func(n *html.Node) {
        if n.Type == html.ElementNode && n.Data == "title" &&
            n.FirstChild != nil {
            fmt.Println(n.FirstChild.Data)
        }
    }
    forEachNode(doc, visitNode, nil)
    return nil
}
```

以下是一个典型的会话，为适应版面略作编辑：

```bash
$ go build gopl.io/ch5/title1
$ ./title1 http://gopl.io
The Go Programming Language
$ ./title1 https://golang.org/doc/effective_go.html
Effective Go - The Go Programming Language
$ ./title1 https://golang.org/doc/gopher/frontpage.png
title: https://golang.org/doc/gopher/frontpage.png
    has type image/png, not text/html
```

观察重复的 `resp.Body.Close()` 调用，它确保 `title` 在所有执行路径上（包括失败时）都关闭网络连接。随着函数变得更复杂并需要处理更多错误，这种清理逻辑的重复可能会成为维护问题。让我们看看 Go 独特的 `defer` 机制如何简化事情。

从语法上讲，`defer` 语句是一个普通的函数或方法调用，前面加上关键字 `defer`。函数和参数表达式在语句执行时求值，但实际调用被*延迟*到包含 `defer` 语句的函数结束时，无论是正常结束（通过执行 return 语句或运行到末尾），还是异常结束（通过 panic）。可以延迟任意数量的调用；它们按与延迟顺序相反的顺序执行。

`defer` 语句常用于成对的操作，如打开和关闭、连接和断开、或加锁和解锁，以确保在所有情况下都释放资源，无论控制流多么复杂。释放资源的 `defer` 语句的正确位置是紧跟在成功获取资源之后。在下面的 `title` 函数中，单个延迟调用替换了之前对 `resp.Body.Close()` 的两次调用：

```go
func title(url string) error {
    resp, err := http.Get(url)
    if err != nil {
        return err
    }
    defer resp.Body.Close()

    ct := resp.Header.Get("Content-Type")
    if ct != "text/html" && !strings.HasPrefix(ct, "text/html;") {
        return fmt.Errorf("%s has type %s, not text/html", url, ct)
    }

    doc, err := html.Parse(resp.Body)
    if err != nil {
        return fmt.Errorf("parsing %s as HTML: %v", url, err)
    }

    // ...打印文档的 title 元素...

    return nil
}
```

相同的模式可用于网络连接以外的其他资源，例如关闭打开的文件：

```go
package ioutil

func ReadFile(filename string) ([]byte, error) {
    f, err := os.Open(filename)
    if err != nil {
        return nil, err
    }
    defer f.Close()
    return ReadAll(f)
}
```

或解锁互斥锁（§9.2）：

```go
var mu sync.Mutex
var m = make(map[string]int)

func lookup(key string) int {
    mu.Lock()
    defer mu.Unlock()
    return m[key]
}
```

`defer` 语句还可用于在调试复杂函数时配对“入口”和“出口”动作。下面的 `bigSlowOperation` 函数立即调用 `trace`，后者执行“入口”动作，然后返回一个函数值，该函数被调用时执行相应的“出口”动作。通过这种方式延迟调用返回的函数，我们可以在一条语句中检测函数的入口点和所有出口点，甚至可以在两个动作之间传递值，如 `start` 时间。但不要忘记 `defer` 语句中的最后一对括号，否则“入口”动作会在出口时发生，而出口动作根本不会发生！

```go
func bigSlowOperation() {
    defer trace("bigSlowOperation")() // 别忘了额外的括号
    // ...大量工作...
    time.Sleep(10 * time.Second) // 通过休眠模拟慢操作
}

func trace(msg string) func() {
    start := time.Now()
    log.Printf("enter %s", msg)
    return func() { log.Printf("exit %s (%s)", msg, time.Since(start)) }
}
```

每次调用 `bigSlowOperation` 时，它都会记录其入口和出口以及两者之间的 elapsed time（我们用 `time.Sleep` 来模拟慢操作）。

```bash
$ go build gopl.io/ch5/trace
$ ./trace
2015/11/18 09:53:26 enter bigSlowOperation
2015/11/18 09:53:36 exit bigSlowOperation (10.000589217s)
```

延迟函数在 return 语句更新了函数的结果变量*之后*运行。因为匿名函数可以访问其外层函数的变量，包括命名结果，所以延迟的匿名函数可以观察函数的结果。

考虑函数 `double`：

```go
func double(x int) int {
    return x + x
}
```

通过命名其结果变量并添加 `defer` 语句，我们可以使函数在每次被调用时打印其参数和结果。

```go
func double(x int) (result int) {
    defer func() { fmt.Printf("double(%d) = %d\n", x, result) }()
    return x + x
}

_ = double(4)
// 输出：
// "double(4) = 8"
```

对于像 `double` 这样简单的函数，这属于过度设计，但在有许多 return 语句的函数中可能很有用。

延迟的匿名函数甚至可以更改外层函数返回给调用者的值：

```go
func triple(x int) (result int) {
    defer func() { result += x }()
    return double(x)
}

fmt.Println(triple(4)) // "12"
```

## 5.9 Panic

Go 的类型系统在编译时捕获许多错误，但其他错误（如数组越界访问或空指针解引用）需要在运行时检查。当 Go 运行时检测到这些错误时，它会 **panic（恐慌）**。

在典型的 panic 过程中，正常执行停止，该 goroutine 中所有延迟函数调用被执行，程序随即崩溃并输出日志信息。该日志包含 **panic value（恐慌值）**，通常是某种错误消息，以及每个 goroutine 的 **stack trace（堆栈跟踪）**，显示 panic 发生时活动的函数调用栈。此日志通常包含足够的信息来诊断根本原因，无需再次运行程序，因此应始终包含在关于 panic 程序的 bug 报告中。

并非所有 panic 都来自运行时。内置的 `panic` 函数可被直接调用；它接受任意值作为参数。当发生某种“不可能”的情况时，panic 往往是最佳处理方式，例如执行到逻辑上不可能到达的 case 分支：

```go
switch s := suit(drawCard()); s {
case "Spades":   // ...
case "Hearts":   // ...
case "Diamonds": // ...
case "Clubs":    // ...
default:
    panic(fmt.Sprintf("invalid suit %q", s)) // Joker?
}
```

断言函数的前置条件是良好的实践，但容易过度。除非你能提供更有信息量的错误消息或更早地检测错误，否则断言运行时会为你检查的条件毫无意义。

```go
func Reset(x *Buffer) {
    if x == nil {
        panic("x is nil") // unnecessary!
    }
    x.elements = nil
}
```

虽然 Go 的 panic 机制类似于其他语言的异常，但使用 panic 的场景截然不同。因为 panic 会导致程序崩溃，它通常用于严重错误，如程序逻辑不一致；严谨的程序员将任何崩溃视为代码中存在 bug 的证明。在健壮的程序中，“预期内”的错误（源于错误输入、配置错误或 I/O 失败）应被优雅处理；它们最好通过 `error` 值来处理。

考虑 `regexp.Compile` 函数，它将正则表达式编译为用于匹配的高效形式。若模式格式错误，它返回 `error`，但如果调用者知道特定调用不可能失败，检查此错误则是不必要且繁琐的。在这种情况下，调用者通过 panic 处理错误是合理的，因为它被认为不可能发生。

由于大多数正则表达式是程序源码中的字面量，`regexp` 包提供了一个封装函数 `regexp.MustCompile` 来执行此检查：

```go
package regexp

func Compile(expr string) (*Regexp, error) { /* ... */ }

func MustCompile(expr string) *Regexp {
    re, err := Compile(expr)
    if err != nil {
        panic(err)
    }
    return re
}
```

该封装函数使客户端能方便地用编译后的正则表达式初始化包级变量，如下所示：

```go
var httpSchemeRE = regexp.MustCompile(`^https?:`) // "http:" or "https:"
```
