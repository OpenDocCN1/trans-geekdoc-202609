
您可以使用 `Vertex AI Pipelines` 运行 `Kubeflow Pipelines` 或 `TensorFlow Extended` 流水线，而无需搭建任何服务器来设置 `Kubeflow` 基础设施或 `TFX` 基础设施。`Vertex AI Pipelines` 会自动为您预配和管理底层基础设施。您可以携带现有的 `Kubeflow` 或 `TFX` 流水线代码，在 `Vertex AI Pipelines` 上以无服务器方式运行。

`Vertex AI Pipelines` 还提供数据血缘。*血缘* 在机器学习中是指跟踪数据随时间从源系统流向转换过程，再到被模型消费的过程。这包括数据一路经历的所有转换，从源系统开始、数据如何被转换、发生了什么变化以及为什么变化。每次流水线运行都会生成*元数据*和 ML *工件*，例如模型或数据集。*工件血缘* 描述了导致工件产生的所有因素，例如用于模型训练的训练数据或超参数。通过使用工件血缘，您可以理解多次流水线运行中性能或准确率的差异：

*   流水线让您能够自动化、监控 ML 工作流中相互依赖的部分并进行实验。
*   ML 流水线具有可移植性、可扩展性，且基于容器。
*   您的流水线工作流的每个单独部分（例如创建数据集或训练模型）均由代码定义。此代码称为*组件*。组件的每个实例称为*步骤*。组件由一组输入、一组输出和一个容器镜像位置组成。组件的容器镜像是一个包，包含组件的可执行代码和代码运行环境的定义。

#### 流水线组件

流水线组件是执行流水线工作流中某一部分的独立代码集合，例如数据预处理、数据转换和模型训练。

您可以构建自定义组件，也可以复用预构建组件。要在流水线中使用 Vertex AI 的功能（如 AutoML），请使用 Google Cloud 流水线组件。您可以在 `https://cloud.google.com/vertex-ai/docs/pipelines/build-pipeline#google-cloud-components` 了解更多关于在流水线中使用 Google Cloud 流水线组件的信息。

#### Apache Airflow

Apache Airflow 是一个用于数据工程流水线的开源工作流管理平台。它于 2014 年 10 月在 Airbnb 诞生，旨在解决该公司日益复杂的工作流管理问题。

Airflow (`https://airflow.apache.org/docs/apache-airflow/stable/concepts/overview.html`) 是一个允许您构建和运行工作流的平台。工作流表示为有向无环图 (DAG)，并包含称为*任务* 的独立工作单元，这些任务经过依赖关系和数据流的考虑进行排列。它自带 UI、调度器和执行器。

#### Cloud Composer

Cloud Composer 是一个基于 Apache Airflow 构建的全代管式工作流编排服务。

通过使用 Cloud Composer 而不是 Apache Airflow 的本地实例，您可以在无需安装或管理开销的情况下享受 Airflow 的所有优势。Cloud Composer 可帮助您快速创建 Airflow 环境并使用 Airflow 原生工具（如功能强大的 Airflow Web 界面和命令行工具），以便您专注于工作流而非基础设施。Cloud Composer 旨在编排数据驱动的工作流（特别是 ETL/ELT）。

Cloud Composer 最适合能够容忍任务执行之间几秒钟延迟的批处理工作负载。您可以使用 Cloud Composer 编排数据流水线中的服务，例如触发 BigQuery 中的作业或启动 Dataflow 流水线。

#### 调度 Vertex AI Pipelines

调度 Vertex AI 管道有两种方式：

*   **使用 Cloud Scheduler 调度管道执行：** 您可以使用 Cloud Scheduler，配合具有 HTTP 触发器的事件驱动型 Cloud Function，来调度预编译管道的执行。要使用 Cloud Scheduler 调度管道，请构建并编译一个简单的管道，将编译后的管道 JSON 上传到 Cloud Storage 存储桶，创建一个具有 HTTP 触发器的 Cloud Function，并创建一个 Cloud Scheduler 作业。您可以手动运行您的作业（可选）。
*   **使用 Cloud Pub/Sub 触发管道运行：** 您可以使用具有 Cloud Pub/Sub 触发器的事件驱动型 Cloud Function，来调度预编译管道的执行。在 Cloud Functions 中，Pub/Sub 触发器使函数能够响应 Pub/Sub 消息而被调用。当您为函数指定 Pub/Sub 触发器时，还需要指定一个 Pub/Sub 主题。每当消息发布到指定主题时，您的函数就会被调用。

#### 使用 Kubeflow/TFX 进行系统设计

在以下章节中，我们将讨论使用 Kubeflow DSL 进行系统设计，然后介绍使用 TFX 进行系统设计。

##### 使用 Kubeflow DSL 进行系统设计

在 Kubeflow Pipelines 中创建的管道以 YAML 文件的形式存储，由一个名为 Argo 的程序执行。Kubeflow Pipelines 默认运行在 Argo Workflows 上。Kubeflow 暴露了一个 Python 领域特定语言（DSL）用于编写管道。DSL 是对 ML 工作流中执行的操作的 Python 表示，专门为 ML 工作负载而构建。DSL 还允许将一些简单的 Python 函数用作管道阶段，而无需您显式构建容器。

对于每个容器（使用 Kubeflow Python SDK），您需要执行以下操作：

1.  将容器创建为简单的 Python 函数，或使用任意 Docker 容器创建。
2.  创建一个操作，该操作引用该容器以及要传递给容器的命令行参数、数据挂载和变量。
3.  对操作进行排序，定义哪些可以并行发生，哪些必须完成后才能继续下一步。
4.  将这个用 Python 定义的管道编译成 Kubeflow Pipelines 可以使用的 YAML 文件。

###### Kubeflow Pipelines 组件

要在管道中调用组件，您需要创建一个 `component op`。您可以使用以下方法之一创建 component op：

*   **实现轻量级 Python 组件：** 此组件不要求您为每次代码更改构建新的容器镜像，旨在用于笔记本环境中的快速迭代。在轻量级 Python 函数中，我们定义一个 Python 函数，然后让 Kubeflow 负责将该函数打包到容器中并创建操作。
*   **创建可重用组件：** 此功能要求您的组件在 `component.yaml` 文件中包含组件规范。在管道编译期间，使用 Kubeflow Pipelines SDK 中的 `ComponentStore.load_components` 函数，从 `component.yaml` 文件自动创建 Component ops。
*   **使用预定义的 Google Cloud 组件：** Kubeflow Pipelines 提供预定义组件，这些组件通过提供所需参数来执行各种托管服务，例如 Google Cloud 上的 AutoML。这些组件可帮助您使用 BigQuery、Dataflow、Dataproc 和 AI Platform 等服务执行任务。与使用可重用组件类似，这些 component ops 通过 `ComponentStore.load_components` 从预定义的组件规范自动创建。其他预定义组件可用于在 Kubeflow 和其他平台上执行作业。

##### 使用 TFX 进行系统设计

在讨论 TFX 管道之前，让我们先了解什么是 TFX。TFX 是一个基于 TensorFlow 的 Google 生产级机器学习（ML）平台。它提供了一个配置框架和共享库，使您的 ML 代码具备生产就绪能力。TFX 是一个用于在生产环境中构建和管理 ML 工作流的平台。TFX 提供以下内容：

*   TFX 管道允许您在多个平台上编排 ML 工作流，例如 Apache Airflow、Apache Beam 和 Kubeflow Pipelines。
*   TFX 提供组件，您可以将其用作管道的一部分，或用作 ML 训练脚本的一部分。
*   TFX 提供库，这些库为许多标准组件提供基础功能。TFX 包括库和管道组件。我们在 第 2 章 "探索数据和构建数据管道" 中介绍了 TFDV 等 TFX 库。图 11.12 说明了 TFX 库和管道组件之间的关系。

![图 11.12 TFX 管道、库和组件 ¶ 来源：www.tensorflow.org/tfx/guide#tfx_standard_components](img/c11f012.png)

**图 11.12** TFX 管道、库和组件 ¶ 来源：`www.tensorflow.org/tfx/guide#tfx_standard_components`

TFX 管道通常包括以下组件：

*   **ExampleGen** 是管道的初始输入组件，负责摄取并可选择性地拆分输入数据集。
*   **StatisticsGen** 计算数据集的统计信息。
*   **SchemaGen** 检查统计信息并创建数据架构。
*   **ExampleValidator** 查找数据集中的异常和缺失值。
*   **Transform** 对数据集执行特征工程。
*   **Trainer** 训练模型。
*   **Tuner** 调整模型的超参数。
*   **Evaluator** 对训练结果执行深度分析，帮助您验证导出的模型，确保它们“足够好”以推送到生产环境。
*   **Model Validator** 检查模型是否真正可从基础设施提供服务，并防止错误模型被推送。
*   **Pusher** 将模型部署到服务基础设施上。
*   **Model Server** 使用未标记的推理请求对模型执行批量处理。

了解上述组件对于考试很重要。

TFX 管道是一系列组件的序列，这些组件实现了专门为可扩展、高性能机器学习任务设计的 ML 管道。组件使用 TFX 库构建，这些库也可以单独使用。TFX 使用元数据存储来维护管道运行的状态。

您可以使用编排系统（如 Apache Airflow 或 Kubeflow）来编排 TFX 管道。

*   使用运行在 GKE 上的 Kubeflow Pipelines。
