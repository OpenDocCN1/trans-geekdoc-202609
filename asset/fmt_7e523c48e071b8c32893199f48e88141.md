## 第 6 章：领域 5：身份与访问管理 (IAM)

## 摘要

身份与访问管理领域侧重于对数据和系统的访问进行适当控制。在授予任何访问权限之前，必须先进行正确的标识和认证。该领域探讨了单因素和多因素认证 (MFA) 的各个方面，包括仅用密码认证的缺陷、生物识别面临的挑战以及令牌的使用。该领域论证了在本地环境中进行凭据管理和单点登录 (SSO) 的必要性，并认识到组织对云身份提供商和联合身份管理 (FIM) 的日益增长的使用需求。该领域探讨了 Kerberos、SAML、OAuth 和 OpenID Connect (OIDC) 等认证和授权协议。在完成适当的标识和认证后，重点转向授权以及访问控制模型的正确应用，如强制访问控制 (MAC)、自主访问控制 (DAC)、基于属性的访问控制 (ABAC) 和基于角色的访问控制 (RBAC)。该领域最后探讨了完整的身份与访问配置生命周期，以确保应用适当的控制，并强调了特权访问监控的重要性。

### 关键词

认证；多因素认证 (MFA)；生物识别；授权；访问控制；单点登录 (SSO)；联合身份管理 (FIM)；强制访问控制 (MAC)；基于角色的访问控制 (RBAC)；基于属性的访问控制 (ABAC)

本章考试目标：

*   身份与访问配置
*   认证方法
*   访问控制技术
*   访问控制模型
*   联合身份管理 (FIM)

## 独特术语和定义

*   **交叉错误率 (CER)**——描述误拒率 (FRR) 和误认率 (FAR) 相等的点。
*   **自主访问控制 (DAC)**——赋予主体对其创建或被授权访问的对象的完全控制权，包括与其他主体共享这些对象。
*   **误认率 (FAR)**——当未经授权的主体被生物识别系统接受为有效主体时发生。也称为 II 类错误。
*   **误拒率 (FRR)**——当经过授权的主体被生物识别系统拒绝为未经授权主体时发生。也称为 I 类错误。
*   **强制访问控制 (MAC)**——基于主体的许可和对象的标签的系统强制访问控制。
*   **基于角色的访问控制 (RBAC)**——主体被分组为角色，每个定义的角色基于角色而非个人拥有访问权限。
*   **基于属性的访问控制 (ABAC)**——一种较新的访问控制方法，可通过在访问请求时考虑主体和对象的各种属性来确定访问权限。

## 简介

身份与访问管理（也称为访问控制）是所有安全学科的基础，不仅仅是 IT 安全。访问管理的目的是允许授权用户访问适当的数据，并拒绝未经授权的用户访问。听起来很简单，对吧？要想完全锁定系统，仅允许预定义的操作而不留任何余地，这很容易做到。事实上，许多组织（包括美军）正是这样做的：将用户对系统的访问权限限制在非常小的功能范围内。

然而，随着对互联网执行工作的依赖日益增加，系统必须足够灵活，能够运行各种不受中央控制的软件。

影响访问控制的另一个顾虑是对陈旧（也称为“遗留”）软件应用程序的依赖。大型 IT 基础设施（如美军）可能运行着超过 10 年的关键任务应用程序！更换这些遗留应用程序的成本往往太高，组织无法在一个资金周期内完成。IT 专业人员往往必须在运行引入访问控制风险的不安全遗留应用程序的同时管理安全。

有一点是确定的：随着将 IT 作为开展业务的一种手段，以及身份与访问管理作为第一道防线之一，理解如何正确实施访问管理已成为追求安全通信的关键。

访问控制可防范未经授权的访问、数据的不当修改和机密性丢失等威胁。访问控制通过实施强有力的技术、物理和管理措施来执行。本章侧重于访问控制的技术和管理方面；我们在第 4 章（领域 3：安全架构与工程）中讨论了物理安全。请记住，物理安全隐含在大多数其他安全控制中，包括访问控制。

## 认证方法

实施任何类型访问控制的一个关键概念是控制 IT 系统中主体的适当认证。主体首先标识其身份；仅凭该标识本身是不可信的。然后主体通过提供保证来进行认证，证明所声称的身份是有效的。`credential set`（凭据集）是用于指代用户标识和认证两者结合的术语。

有三种基本认证方法：`Type 1`（你所知）、`Type 2`（你所有）和 `Type 3`（你本身）。第四种认证类型是你所在的位置。

### Type 1 认证：你所知

Type 1 认证（你所知）要求通过某种质询/响应方式测试主体，主体必须以知情者的回答进行响应。主体凭借其所知内容（如密码或 `PIN (Personal Identification Number)`——基于数字的密码）获得访问权限。这是最简单，但往往也是最薄弱的认证形式。

#### 密码

密码一直是 IT 系统访问控制的基石。它们相对容易且廉价地实现。许多在线银行、股票投资组合服务、私人 Web 邮箱和医疗系统仍使用用户名和密码作为访问控制方法。

实施访问控制时需考虑四种类型的密码：静态密码、口令、一次性密码和动态密码。

*静态密码* 是可重复使用的密码，可能过期也可能不过期。它们通常由用户生成，最好与其他认证类型（如智能卡或生物识别控制）结合使用。

*口令* 是由单词短语或句子组成的长静态密码。口令示例：“I will pass the CISSP® in 6 months!”（我将在 6 个月内通过 CISSP® 考试！）。可以通过使用无意义单词（例如将前一个口令中的 CISSP® 替换为“XYZZY”）、混合大小写以及使用额外的数字和符号来增强口令的强度。

与较短的复杂密码（如 `B$%Jiu*!`）相比，口令通常每个字符的随机性较低，但通过长度来弥补随机性的不足。大多数人发现口令比较短的复杂密码更容易输入和记忆：我们习惯于输入句子。口令在安全性和易用性之间提供了合理的折衷：许多用户可能会被诱导记录高度复杂的密码，但却能记住口令。任何静态密码都有其固有局限性，无论长度或复杂度如何：它可能被窃取并重用。

**一次性密码**可用于单次认证。它们非常安全但难以管理。一次性密码无法重用，仅在单次使用时有效。

**动态密码**按固定时间间隔变化。RSA Security 制造了一种名为 SecurID 的同步令牌设备，每 60 秒生成一个新的令牌码。用户将其静态 PIN 与 RSA 动态令牌码相结合，创建一个每次使用都会改变的动态密码。使用动态密码的一个缺点是令牌本身的成本较高。

### 多因素认证 (MFA)

**多因素认证 (MFA)** 要求用户利用不止一种要素来证明其身份以进行认证。MFA 与仅需一种方法证明身份的经典单因素认证方法形成鲜明对比。最常见且仍普遍存在的认证方法仅要求提供用户名以进行标识，以及与该账户关联的已知密码。攻击者已经开发出多种极其成功的方法来攻破仅基于密码的认证。可能存在一些用例，用替代的但仍属于单因素的认证方法取代仅密码的方法，确实能实质性地提高安全性。然而，完全依赖任何单因素方法的安全性都明显低于迁移到基于 MFA 的解决方案。

为了举例说明 MFA，我们可以考虑 ATM 卡或借记卡。用户可以利用借记卡从其银行账户取款。然而，除了持有该卡外，他们还必须输入正确的 PIN 才能充分证明其身份。这可以防止多种类型的攻击，包括简单的重放攻击。在重放攻击中，攻击者可能拥有 PIN，但如果没有实际的 ATM 卡，他们将无法取款。同样，如果攻击者复制了 ATM 卡但无法获取 PIN，也可以应用同一逻辑。即使是简单的四位数 PIN，当与物理持有要求相结合时，也能极大地提高该认证系统的安全性。

考虑到针对密码的攻击技术普遍存在（其中一些我们将在下文讨论），迁移到需要任何形式 MFA 实施的认证被证明是一项极其宝贵的安全控制。然而，并非所有 MFA 实施都能提供同等程度的安全态势改进。严格来说，MFA 并不一定要求采用不同类型的因素，但最佳实践建议利用那些不太可能被同时成功颠覆的因素。此外，随着组织增加对 MFA 的采用，对手也同样将更多精力集中在攻破除典型静态密码之外的额外因素上。

在实施或更新组织的 MFA 方法时，应考虑所采用的额外因素相关的攻击面。虽然采用任何 MFA 都比单因素仅密码认证代表了巨大的安全性提升，但通过短信或电子邮件发送一次性密码给用户等因素，代表了鲁棒性差得多的实施，更容易成为对手的攻击目标。

### 密码猜测

**密码猜测**是一种在线技术，涉及尝试向系统认证特定用户。正如我们将在下一节学到的，**密码破解**是指一种离线技术，攻击者已获取密码哈希或数据库。请注意，大多数针对密码的基于 Web 的攻击属于密码猜测类型，因此 Web 应用程序在设计时应从检测和预防的角度考虑到这一点。

可以通过监控登录失败的系统日志来检测密码猜测。**截断级别**用于区分恶意攻击和普通用户意外输错密码的情况。截断级别定义了最低报告阈值。以密码猜测为例，可以建立一个截断级别，使得审计系统仅在特定用户每小时认证失败频率超过五次时才发出警报。截断级别有助于将攻击与噪音区分开来；然而，如果攻击者能够摸清必须低于其运作的阈值，也可能导致假阴性。

防止成功的密码猜测攻击通常通过**账户锁定**来实现。账户锁定用于防止攻击者通过尝试大量潜在密码来简单地猜出正确密码。一些组织要求对锁定账户进行人工补救，通常以服务台介入的形式进行。然而，一些组织将账户锁定配置为仅具有自动重置时间，这不一定需要人工干预。账户锁定配置应谨慎对待：攻击者（虽然未能成功猜出正确密码）可能会通过故意锁定大量账户造成巨大的管理负担。

### 密码哈希与密码破解

在大多数情况下，明文密码不会存储在 IT 系统中；仅存储这些密码的哈希输出。**哈希**是使用算法且无密钥的单向加密。当用户尝试登录时，他们输入的密码（有时结合盐值，我们稍后将讨论）会被哈希，并将该哈希与系统上存储的哈希进行比较。哈希函数不可逆：无法逆向算法从哈希生成密码。虽然哈希无法逆向，但攻击者可以多次正向运行哈希算法，选择各种可能的密码，并将输出与目标哈希进行比较，希望找到匹配项（从而推导出原始密码）。这被称为**密码破解。**

现代 UNIX/Linux 系统的密码哈希存储在 `/etc/shadow` 中（通常仅 root 用户可读）。Windows 系统将哈希同时存储在本地计算机和域控制器 (DC) 上，存储在所谓的安全账户管理文件或 SAM 文件中。必须访问密码哈希才能进行认证。如果 Microsoft Windows 系统无法访问 DC，则可能会恢复到工作站本身本地存储的密码哈希。如果用户运行的是独立系统（大多数家庭用户的典型情况），则仅使用本地密码哈希。

密码哈希也可能在网络上被嗅探或从内存中读取。SAM 文件在 Windows 操作系统运行时处于锁定状态：诸如 mimikatz (`https://github.com/gentilkiwi/mimikatz`) 和 Metasploit (`https://www.metasploit.com`) 的“hashdump”命令等工具可以从内存中转储哈希。图 6.1 显示了通过工具 mimikatz (`https://github.com/gentilkiwi/mimikatz`) 从 Windows 工作站获取的 SAM 文件输出。用户 deckard 的 LM 哈希和 NT 哈希均显示出来，可用作密码破解工具的输入。

### 字典攻击

*字典攻击*使用字表：一个预定义的单词列表，列表中的每个单词都会被哈希。如果破解软件将字典攻击产生的哈希输出与密码哈希匹配，攻击者就成功识别出了原始密码。

> **注意**
>
> 攻击者通常会根据目标调整其字典，例如为讲西班牙语的目标组织在字表中添加西班牙语字典，甚至为拥有《星际迷航》粉丝的组织添加克林贡语字典。Packet Storm Security 在 <https://packetstormsecurity.com/Crackers/wordlists/> 维护着多个字典。

因为字典攻击可以快速执行，许多组织要求用户创建包含特殊字符、数字、大写字母且长度在八位或以上的密码。Fig. 6.2 展示了使用密码破解工具 `John the Ripper` (<https://www.openwall.com/john/>) 对抗 Fig. 6.1 中所示从 SAM 文件获取的详细信息。即使运行简单的字典攻击也能快速揭示用户 deckard 的密码为“replicant”。应限制对 SAM 文件 (Windows) 和 shadow 文件 (UNIX/Linux) 的访问。

### 暴力破解和混合攻击

*暴力破解攻击*耗时更长，但效果更好。攻击者计算所有可能密码的哈希输出。就在几年前，基本计算机速度仍然足够慢，使这成为一项艰巨的任务。然而，随着 CPU 速度和并行计算的进步，暴力破解复杂密码所需的时间已大幅减少。

近期密码破解的另一项突破是利用 GPU（图形处理单元）破解密码：“为应对电脑游戏日益增长的需求而设计，当今顶级 GPU 的信息处理速率接近每秒两万亿次浮点运算（一万亿次浮点运算等于每秒一万亿次浮点运算）。为了更直观地理解这一点，在 2000 年，世界上最快的超级计算机——一组耗资 1.1 亿美元的联网机器——运算速度仅略高于每秒七万亿次浮点运算。图形处理单元之所以如此之快，是因为它们被设计为并行计算机。在并行计算中，给定的问题被分配给多个称为核心的处理单元，这些核心同时处理问题的不同部分” [\[1\]](#Ch006_295-335_B9780443187346000052.xhtml#bb0010)。

攻击者也可能使用彩虹表进行密码攻击。*彩虹表*充当一个数据库，包含大多数或所有可能密码的预计算哈希输出。生成彩虹表需要大量时间，且并不总是完整的：它们可能不包含所有可能的密码/哈希组合。虽然彩虹表充当数据库，但其内部更为复杂，依赖时间/内存权衡来表示和恢复密码及哈希。我们将在第 4 章（领域 3：安全架构与工程）中更详细地讨论彩虹表的技术细节。

> **注意**
