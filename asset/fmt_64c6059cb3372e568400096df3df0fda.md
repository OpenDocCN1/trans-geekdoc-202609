
# Hacme 系列场景

1. `Hacme Travel` 模拟真实的在线预订系统，可以使用 SQL 和 Web 攻击进行利用。安装该场景的系统要求包括 Windows XP、`MSDE 2000 Release` 和 `.NET Framework v1.1`。

2. `Hacme Bank` 模拟真实的在线银行，可以使用 SQL 和 Web 攻击进行利用。最低系统要求是 `.NET Framework v1.1`、`IIS`、`MSDE` 或 `Microsoft SQL Server 2000` 以及 `Internet Explorer 6.0`。

3. `Hacme Shipping` 模拟在线物流应用，可以使用 SQL、跨站脚本和原生漏洞进行利用。安装该场景的系统要求包括 Windows XP、`IIS`、用于 Windows 的 `Adobe ColdFusion MX 7.0` 以及禁用严格模式的 `MySQL`（`4.x` 或 `5.x`）。

4. `Hacme Casino` 模拟具有原生漏洞的在线赌场。使用 Ruby on Rails 编写。

5. `Hacme Books` 模拟具有原生漏洞的在线书店。安装该场景的最低系统要求包括 `Java Development Kit (JDK) 1.4.x` 和 Windows XP。

# 使用可利用的目标

通常人们创建的第一类实验室是那些涉及可利用的操作系统或包含漏洞应用程序的实验室。旧操作系统被更新或废用的原因之一就是漏洞。诸如 `Metasploit` 等工具可以有效地用于旧且未打补的操作系统，并向系统管理员和管理层演示定期系统维护的必要性。高级渗透测试人员还将把现代操作系统纳入渗透测试实验室的目标，特别是当新漏洞的消息公布时。重新创建利用程序，特别是在尚未发布概念证明（PoC）的情况下，是开发逆向工程和缓冲区溢出技能的极佳方法。更高级的技术攻击操作系统内核，特别是在 rootkit 开发中。分析内核的工程师现在能够更好地理解操作系统的内部机制。最终，那些为了安全漏洞而分析内核的人将成为发现最新操作系统漏洞的人，并在此过程中获得名声（或臭名）。

## 操作系统

大多数利用程序是针对应用程序编写的。然而，某些漏洞专门设计用于攻击操作系统，无论是库文件、内核、固件还是作为虚拟化管理程序。一个良好的 rootkit 仓库可以在 [www.packetstormsecurity.org/UNIX/penetration/rootkits/](http://www.packetstormsecurity.org/UNIX/penetration/rootkits/) 找到，包括 Windows rootkit（尽管 URL 名称中提到了 UNIX）。Packet Storm 提供了可下载的 rootkit 链接，可以在实验室环境中进行剖析和研究。理解操作系统漏洞对于取证分析以及渗透测试中的维持访问阶段非常有益。安装一个无法被检测且保留高级管理权限的后门的能力，对于恶意黑客和专业渗透测试人员来说都非常有益。

注意：在渗透测试中使用 rootkit 很少见，除非在测试实验室中演示概念证明。尽管渗透测试方法论建议使用 rootkit，但在专业的渗透测试中实施 rootkit 应谨慎使用。rootkit 扫描器的有效性是另一个可以在渗透测试实验室探索的领域。理解 rootkit 扫描器的原理以及它们为何能检测（或未能检测）rootkit 对于取证和渗透测试很有帮助，特别是在测试系统防御控制时。

## 应用程序

与操作系统一样，随着新漏洞的发现而被更新。从漏洞应用程序中重新创建利用程序有时比破解操作系统更容易，特别是对于开源应用程序，因为可以获取实际源代码且更容易利用。在真实的渗透测试中，应用程序经常需要检查安全漏洞；很少有渗透测试团队收到破解操作系统内核的请求。如果创建应用程序利用程序超某人的技能范围，并不意味着他们应该回避至少了解它们。`Metasploit` 拥有约 200 个应用程序利用程序，可以通过审查它们来理解应用程序如何以及为何可利用。另一个来源是 `milw0rm`，它是一个许多应用程序利用程序的仓库。以下是 Webmin 利用程序的片段，发现于 [www.milw0rm.com/exploits/2017](http://www.milw0rm.com/exploits/2017)：

```perl
#!/usr/bin/perl
($target, $port,$filename, $tar) = @ARGV;
$temp=“/..%01” x 40;
...
my $url= “http://”. $target. “:” . $port .“/unauthenticated/”.$temp . $filename;
$content=get $url;
```

如果我们仔细观察代码，就可以看到，如果 URL 使用以下字符串 `/..%01` 填充 40 次，Webmin 将打印出系统文件。如果我们试图理解为什么这个利用程序起作用，我们会看到该利用程序利用了 Webmin 应用程序内部对 URL 的处理不当。通过向应用程序提供额外数据（在此例中为 `/..%01` 字符串），我们可以强制 Webmin 显示目标系统中的任何文件，这将在第二部分 (`9781597494250000130.xhtml#978-1-5974-425-0`) 中演示。基于这些信息，我们可以尝试在不实际使用脚本的情况下，针对 Webmin 应用程序手动重新创建这种利用。`milw0rm` 有许多远程和本地利用的示例，包括缓冲区溢出、拒绝服务和 shellcode。

# 分析恶意软件 – 病毒和蠕虫

高级恶意软件开发技术的使用正在上升——根据 McAfee 的数据，2007 年 11 月到 2008 年 12 月之间，独特的恶意软件二进制文件数量从 400 万以下增长到 1600 万以上 (McAfee Threat Center, 2009)。这种增长大部分是恶意软件作者为了避免被病毒检测程序检测而进行的打包工作；尽管重新打包软件的使用增加扭曲了 McAfee 研究中呈现的数据，并可能意味着野外实际恶意软件二进制文件的数量并没有那样剧烈增加，但这确实表明开发者在变更管理和部署方法方面变得越来越熟练。在实验室中分析恶意软件与系统和应用程序渗透测试有显著不同。“恶意软件”的目的与渗透测试的目的相反；恶意软件作者通常设计他们的软件在网络中横冲直撞，不在过程中发生了什么损害。渗透测试工程师会尝试以受控的方式发现利用程序，很少意图造成不可恢复的损害。理解恶意软件的破坏性以及当前用于在公司系统中注入恶意软件的技术，是专业渗透测试人员的一项关键技能；能够逆向工程恶意软件可以增加这项技能，为渗透测试工程师对这种不断增加的威胁提供更深入的理解。

## 设置实验室

创建一个恶意软件实验室与我们之前描述的有所。恶意软件攻击其他系统的威胁是肯定的，应该预期的实验室中的所有系统都会被完全攻破。更复杂的是，某些恶意软件可以检测到虚拟虚拟机的使用，这为任何设置渗透测试（PenTest）实验室的人增加了额外工作。许多版本的恶意软件被设计为僵尸网络的一部分，也称为 `botnet`。感染了僵尸网络恶意软件的系统将尝试连接到远程服务器并监听指令，无论是为了生成垃圾邮件、参与拒绝服务攻击，还是从主机系统上收集敏感信息（例如信用卡数据、登录名和密码或击键记录）。在实验室中分析恶意软件需要在使用第 4 章中讨论过的措施之外额外的安全措施。恶意软件分析还需要不同的工具。我们将讨论蜜罐程序（`honeypots`）的使用、存在哪些类型以及如何使用它们收集恶意软件。我们还将讨论正确分析收集到的恶意软件需要哪些工具。

**警告** 恶意软件作者故意编写试图规避逆向工程或检测的代码，并以非常激进的方式在整个网络中传播。在实验室中使用恶意软件需要最高的安全措施；未能实施适当的安全措施可能导致外部系统被破坏，这可能导致政府调查或诉讼。

## 虚拟机与非虚拟机实验室

如所述，某些恶意软件可以检测到更常用的虚拟机应用程序的使用，包括 `VMware` 和 `Xen` 等。当恶意软件检测到虚拟机的使用时，它可能会表现得无害且不进行恶意活动。由于虚拟机在恶意软件分析中被广泛使用，恶意软件作者设计其恶意软件不被检测，以尽可能地防止分析，从而延长恶意软件的寿命。在恶意软件分析中使用虚拟机有许多原因——最重要的一是时间。能够在虚拟机中检查恶意软件的活动，然后立即将虚拟机恢复到原始状态，允许分析人员更快速地检查恶意软件。如果恶意软件的细节发布给安全供应商（例如病毒检测软件制造商），恶意软件分析的快速转换可以防止成千上万系统被感染——恶意软件未被分析的时间越长，全球范围内受感染的系统就越多。

## 虚拟机检测

恶意软件对虚拟机的检测正在减少。许多公司正在使用虚拟机管理程序解决方案以节省成本，并将服务器迁移到企业级虚拟机应用程序。检测到虚拟机使用的恶意软件可能会忽略可被利用的合法系统。随着虚拟化在企业环境中的应用越来越多，恶意软件将尝试减少对其使用的检测。进行恶意软件分析的实验室需要同时拥有虚拟机和非虚拟机系统以开展分析。虽然只分析不寻找虚拟机的恶意软件可能很有吸引力，但更高级（更有趣）的恶意软件需要更健健的渗透测试实验室。避免高级恶意软件将限制对当前恶意软件环境和威胁的理解。
