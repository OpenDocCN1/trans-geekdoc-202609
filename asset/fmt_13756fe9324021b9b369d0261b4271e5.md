
我们可能期望将 `debug` 改为 `false` 会禁用输出收集，但实际上这会导致程序在 `out.Write` 调用时 panic：

点击此处查看代码图像

```
if out != nil {
    out.Write([]byte("done!\n")) // panic: nil pointer dereference
}
```

当 `main` 调用 `f` 时，它将一个 `*bytes.Buffer` 类型的 nil 指针赋给 `out` 参数，因此 `out` 的动态值是 `nil`。然而，它的动态类型是 `*bytes.Buffer`，这意味着 `out` 是一个包含 nil 指针值的非 nil 接口（图 7.5），所以防御性检查 `out != nil` 依然为真。

![包含空指针的非空接口。](img/iface4.png)

**图 7.5。** 包含空指针的非空接口。

和之前一样，动态分发机制确定必须调用 `(*bytes.Buffer).Write`，但这一次接收者的值是 nil。对于某些类型（如 `*os.File`），nil 是合法的接收者（§6.2.1），但 `*bytes.Buffer` 不在其中。该方法被调用了，但当它试图访问缓冲区时发生了 panic。

问题在于，虽然 nil `*bytes.Buffer` 指针拥有满足接口所需的方法，但它不满足接口的*行为*要求。具体来说，该调用违反了 `(*bytes.Buffer).Write` 的隐式前置条件——其接收者不能为 nil，因此将 nil 指针赋给接口是一个错误。解决方法是将 `main` 中 `buf` 的类型改为 `io.Writer`，从而避免一开始就将这个有缺陷的值赋给接口：

点击此处查看代码图像

```
var buf io.Writer
if debug {
    buf = new(bytes.Buffer) // 启用输出收集
}
f(buf) // 正确
```

既然我们已经介绍了接口值的机制，接下来让我们看看 Go 标准库中一些更重要的接口。在接下来的三节中，我们将看到接口如何用于排序、Web 服务和错误处理。

## 7.6 使用 `sort.Interface` 进行排序

就像字符串格式化一样，排序是许多程序中常用的操作。虽然最小化的快速排序只需约 15 行代码就能写出来，但一个健壮的实现要长得多，这不是我们每次需要时都想重新编写或复制粘贴的代码。

幸运的是，`sort` 包提供了根据任意排序函数对任意序列进行**原地排序**的功能。其设计相当独特。在许多语言中，排序算法与序列数据类型相关联，而排序函数与元素类型相关联。相比之下，Go 的 `sort.Sort` 函数对序列或其元素的表示形式不做任何假设。相反，它使用一个接口 `sort.Interface` 来指定通用排序算法与每个可排序序列类型之间的契约。该接口的实现同时决定了序列的具体表示（通常是切片）及其元素的期望排序顺序。

原地排序算法需要三样东西——序列的长度、比较两个元素的方法、交换两个元素的方法——因此它们就是 `sort.Interface` 的三个方法：

点击此处查看代码图片

```
package sort

type Interface interface {
    Len() int
    Less(i, j int) bool // i, j 是序列元素的索引
    Swap(i, j int)
}
```

要对任意序列进行排序，我们需要定义一个实现了这三个方法的类型，然后将 `sort.Sort` 应用于该类型的一个实例。作为最简单的例子，考虑对字符串切片进行排序。下面展示了新类型 `StringSlice` 及其 `Len`、`Less` 和 `Swap` 方法。

点击此处查看代码图片

```
type StringSlice []string

func (p StringSlice) Len() int           { return len(p) }
func (p StringSlice) Less(i, j int) bool { return p[i] < p[j] }
func (p StringSlice) Swap(i, j int)      { p[i], p[j] = p[j], p[i] }
```

现在我们可以通过将字符串切片 `names` 转换为 `StringSlice` 来对其进行排序，如下所示：

```
sort.Sort(StringSlice(names))
```

该转换产生一个切片值，它与 `names` 具有相同的长度、容量和底层数组，但其类型拥有排序所需的三个方法。

对字符串切片进行排序非常常见，因此 `sort` 包提供了 `StringSlice` 类型，以及一个名为 `Strings` 的函数，以便将上述调用简化为 `sort.Strings(names)`。

此技术很容易适应其他排序顺序，例如忽略大小写或特殊字符。（为本书对索引词和页码进行排序的 Go 程序就做了这件事，并额外添加了处理罗马数字的逻辑。）对于更复杂的排序，我们使用相同的思路，但会用到更复杂的数据结构或更复杂的 `sort.Interface` 方法实现。

我们用于排序的持续示例将是一个音乐播放列表，以表格形式显示。每个曲目是一行，每一列是该曲目的一个属性，如艺术家、标题和运行时长。想象一个图形用户界面呈现该表格，点击列头会按该属性对播放列表进行排序；再次点击同一列头则反转顺序。让我们看看响应每次点击可能发生的情况。

下面的变量 `tracks` 包含一个播放列表。（作者之一为另一作者的音乐品味道歉。）每个元素都是间接的，即指向 `Track` 的指针。虽然如果我们直接存储 `Track` 值，下面的代码也能工作，但排序函数将交换许多元素对，因此如果每个元素是一个指针（单个机器字），而不是整个 `Track`（可能有八个字或更多），运行速度会更快。

`sort.Reverse` 函数值得仔细研究，因为它使用了组合（§6.3），这是一个重要的概念。`sort` 包定义了一个未导出类型 `reverse`，它是一个嵌入了 `sort.Interface` 的结构体。`reverse` 的 `Less` 方法调用嵌入的 `sort.Interface` 值的 `Less` 方法，但交换了索引，从而反转了排序结果的顺序。

点击此处查看代码图片

```
package sort

type reverse struct{ Interface } // 即 sort.Interface

func (r reverse) Less(i, j int) bool { return r.Interface.Less(j, i) }

func Reverse(data Interface) Interface { return reverse{data} }
```

### `reverse` 中的 `Len` 和 `Swap`

`Len` 和 `Swap` 是 `reverse` 的另外两个方法，它们由原始的 `sort.Interface` 值隐式提供，因为它是一个嵌入字段。导出函数 `Reverse` 返回一个包含原始 `sort.Interface` 值的 `reverse` 类型实例。

### `customSort` 类型

对于我们需要的每一种切片元素类型和排序函数，我们都要声明一个新的 `sort.Interface` 实现。正如你所见，对于所有切片类型，`Len` 和 `Swap` 方法都有相同的定义。在下一个示例中，具体类型 `customSort` 将一个切片和一个函数结合在一起，让我们只需编写比较函数即可定义一种新的排序顺序。顺便说一下，实现 `sort.Interface` 的具体类型并不总是切片；`customSort` 是一个结构体类型。

点击此处查看代码图片

```
type customSort struct {
    t    []*Track
    less func(x, y *Track) bool
}

func (x customSort) Len() int           { return len(x.t) }
func (x customSort) Less(i, j int) bool { return x.less(x.t[i], x.t[j]) }
func (x customSort) Swap(i, j int)      { x.t[i], x.t[j] = x.t[j], x.t[i] }
```

让我们定义一个多层排序函数，其主排序键是 `Title`，次排序键是 `Year`，第三排序键是运行时间 `Length`。下面是使用匿名排序函数调用 `Sort` 的代码：

点击此处查看代码图片

```
sort.Sort(customSort{tracks, func(x, y *Track) bool {
    if x.Title != y.Title {
        return x.Title < y.Title
    }
    if x.Year != y.Year {
        return x.Year < y.Year
    }
    if x.Length != y.Length {
        return x.Length < y.Length
    }
    return false
}})
```

这是结果。请注意，两个标题均为 “Go” 的曲目之间的平局，倾向于较旧的那一个。

### 检查是否已排序
