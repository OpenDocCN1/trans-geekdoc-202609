
随着服务和工作负载的增加，管理它们的复杂性自然也随之而来。前面提到的运维开销缺点只是微服务复杂性的一个特定用例。此外，管理数据和一致性变得更难——数据分布在各个服务中，因为每个服务都有自己的数据库。

每个团队可以使用其最喜欢或最相关的编程语言编写服务。这种能力有利有弊。运维必须为所有这些编程语言创建、维护和解决运维问题。

此外，当每个服务都用其他编程语言编写时，在团队间调动开发人员将变得更难。

我们选择在本书中编写 Kubernetes 并将微服务架构部署在 Kubernetes 上而非其他平台，这绝非巧合。主要原因是 Kubernetes 旨在解决这一复杂性问题。

## 难以排查故障

这是前一点的延续。由于微服务的复杂性，要在其之上获得可见性并创建完整的可观测性变得更难。许多障碍阻碍我们获得良好的可见性。

### Go 的发明

那么这门语言是如何开始的？一切始于 Google。2007 年，Google 的三位工程师决定创建一门新语言。该语言由 Ken Thompson、Rob Pike 和 Robert Griesemer 设计，他们各自带来了独特且相关的背景。他们参与了 UTF-8、Unix、C 编程语言等重大技术发明。该语言的全称是 Golang，由“go”+“lang”组合而成，其中“lang”是 language 的缩写。不过，他们更倾向于称其为 Go 而非 Golang，以强调该语言旨在简单易记。“Go”是一个常见的英语单词，暗示着移动、进步和效率，这与该语言为软件开发提供简单高效方法的目的相一致。此外，“Go”也是 Google 的前两个字母。

在获得 Google 批准后，他们开始开发这门语言。他们的核心内部协议之一是：仅包含他们所有人都认同的编程原则。尽管这门语言发明于 2007 年，但它主要受 C 编程语言（创建于 1972 年）影响，而非 C++、Java、C# 等较新语言。Go 和 C 编程语言有许多相似之处。确实，一些人将 Go 称为 C 语言的现代版本。

他们开始使用 Go、C++ 和汇编语言编写这门编程语言。

到 2008 年，Google 内部许多人都想加入该项目。它在 Google 内部迅速获得了积极的发展势头。

2009 年，Go 通过 GitHub 正式作为开源项目发布，来自世界各地的开发者都能并愿意贡献代码。此外，我们在上一章提到的 Gopher 吉祥物也于 2009 年亮相。参考资料中提供了项目链接。

请注意，Go 组织下的许多其他代码库也非常重要，且是 Golang 生态系统的一部分，我们稍后将讨论。将语言开源并让全球开发者可用的决定，对其当前的成功起到了关键作用。

2012 年，Go 1.0 版本发布，提供了对简洁性和高效性最广泛的保障，我们将在本章后面讨论这一点。从此，Go 每年发布两个版本（2012 年除外）。1.5 版本是最重大的更新，该版本将编译器工具链完全转换为 Go 实现。另一个里程碑版本是 1.18，引入了泛型和模糊测试概念。本书遵循的当前 Go 版本是 1.20（2023 年 7 月）。

### 核心原则与范式

在设计 Go 编程语言时，发明者遵循了几项原则。直到今天，所有这些核心原则仍在每个 Go 版本的发布说明中得到体现。我们建议每次发布新版本时都查看 Go 发布说明。这些说明不长，阅读理解大约需要一小时。每年投入 2-3 小时了解语言的最新进展非常有价值。发布说明清晰、直白、易于理解。

正如上一章所见，该语言设计初衷是很好地适应云计算平台部署、多核计算机、大型代码库处理等场景。

在深入探讨每项原则的细节之前，必须提及官方 Go 文档《Effective Go》。我们建议阅读它，讲解清晰明了。另一个宝贵资源是 Go 官方 GitHub 组织的代码审查评论 Wiki，建议浏览并加以利用。

Go 有三大核心原则：

*   **简洁性**：Go 设计为直观易懂，语法简洁，避免不必要的复杂性。这使开发者更容易编写、阅读和维护代码。
*   **高效性**：Go 以速度和性能著称。它直接编译为机器码，使其速度媲美 C 或 C++，却拥有高级语言的易用性。
*   **可维护性**：Go 强调清晰、模块化的代码结构和强类型，有助于防止错误，并使代码随时间推移更易于更新和重构。

> **免责声明**：这些核心原则并非在 Go 官方文档中正式声明，而是笔者归纳总结的。

### Go 范式

Go 编程语言的范式在官方文档中已正式声明，包括：

*   命令式
*   并发编程
*   面向对象

#### 命令式

以下是命令式编程的简要概述：命令式编程是一种软件范式，代码旨在逐步解决问题，每一行代码都旨在推进问题的解决。它关注**如何**解决问题。命令式编程与声明式编程形成对比，后者更关注声明**想要**得到什么。声明式语言的例子包括 HTML、SQL、CSS 等。Go 是一门命令式语言。证明 Go 是命令式编程语言的特性包括语句、变量、循环等。

#### 并发编程

并发编程涉及设计软件以同时执行多个任务，通常能提高处理多种操作的应用程序的性能和响应能力。我们稍后将详细讨论如何使用 Go 并发。这一范式是创建该语言的核心原因之一。Go 可以是多线程、多进程和异步的，这些是并发编程语言的关键因素。

#### 面向对象

> “是的，也不是。虽然 Go 有类型和方法，并允许面向对象风格的编程，但没有类型层级。Go 中‘接口’的概念提供了一种不同的方法，我们认为它易于使用，且在某些方面更通用。还有将类型嵌入其他类型的方法，提供了类似于（但不等同于）子类化的功能。此外，Go 中的方法比 C++ 或 Java 更通用：它们可以为任何类型的数据定义，甚至包括内置类型，如普通的‘未装箱’整数。它们不限于结构体（类）。
>
> 此外，缺乏类型层级使得 Go 中的‘对象’感觉比 C++ 或 Java 等语言轻量得多。”

这段引文取自 Golang FAQ，很好地解释了 Go 中的面向对象概念。当然，我们将在后续详细讨论 Go 中的组合、结构体、接口等内容。

**Go 支持的 OOP 原则**：

*   **封装**：Go 通过包和结构体支持封装。我们可以在结构体上定义方法，将行为与数据关联，类似于传统 OOP 中的方法。
*   **组合**：Go 不使用经典继承，而是使用组合，通过嵌入概念从简单类型构建复杂类型。

**Go 不支持的 OOP 原则**：

*   **继承**：Go 不支持传统意义上的继承。没有类，因此无法定义类层级。Go 的方法是使用接口和组合代替。
*   **多态**：虽然 Go 不支持通过继承实现多态，但它通过接口支持一种形式的多态。单个接口可由多种类型实现，接受接口作为参数的函数可接收任何实现该接口的类型。

### Go 特性

编程语言的另外两个属性是动态/静态和强/弱。对 Go 而言，这些属性是：

*   静态类型
*   强类型

#### 静态类型

在 Go 中，一旦变量类型确定，运行时就无法更改。我们不能在不声明类型的情况下声明变量。请注意，我们可以这样做：

`x := 5`

在这种情况下，我们没有显式声明类型，但 Go 使用“类型推断”来决定变量类型。推断并不总是生效，直到我们使用 `:=` 运算符。

在该用例中，推断类型当然是 `int`。

#### 强类型

“强”编程语言与“弱”编程语言的区别在于，我们可以对变量类型执行某些操作。请看此例：

`myString := "name" + 2`

这行代码会导致编译错误，因为我们不能将整数添加到字符串中。

### 简洁性与极简设计方法

目前有许多广泛使用的编程语言。这些语言在每次新版本发布时变得相似的趋势日益明显。这种相似性表现为它们的能力和特性日益趋同。

最初，每种编程语言都是为特定目的而创建的，拥有有限的能力和特性集。然而，随着这些语言每个后续版本的发布，都会发生许多增强。这些更新包括错误修复、改进、新特性、核心库扩展、新库、新概念等。

大多数编程语言采用“越多越好”的方法，不断扩展其能力、特性和库，使它们能够处理各种任务。

尽管如此，必须注意 Go 语言可能并不符合这一情况，因为它偏离了这种常量扩展的模式。

查阅 Go 语言的发布说明后会发现，大多数更新主要集中在编译增强、性能改进和准确性优化上。虽然确实引入了一些新特性和功能（一个显著的例子是泛型），但它们并不构成变更的主体。这种对简洁性的强调正是 Go 语言的追求。他们希望保持 Go 语言**枯燥**（boring）。

Go 语言简洁性和极简主义的一个例子是语言的关键字数量。下图展示了关键字数量的对比。

![](img/Figure-2.1.jpg)

**图 2.1：** 编程语言关键字数量对比

如果一种编程语言拥有许多关键字，并不一定意味着它是一门糟糕的语言。反之，关键字数量少也并不自动意味着它是一门优秀的编程语言。编程语言的质量和有效性取决于许多因素，而不仅仅是它拥有的关键字数量。

但可以肯定地说，关键字越少，越容易记忆和使用。我们可以看到 Go 语言是关键字最少的语言之一。

#### 隐藏的复杂性

语言内部包含许多概念，为了在打造一门强大的编程语言的同时保持语言的简洁，投入了大量精力。

并发模型是隐藏复杂性的绝佳例子。我们将在本章后面详细讨论并发模型。它仅需三个按键即可实现并发——`g`、`o`、` `——这令人惊叹。

另一个极致简洁的例子是访问修饰符。共有两种场景：函数/变量/常量可以是私有的或公有的。在 Go 语言中，要使某个标识符公开，只需做两件事：

*   它需要声明在最高作用域。
*   它需要以大写字母开头。

仅此而已；无需额外的关键字。

Go 语言中的其他一些简洁特性：

*   垃圾回收
*   常量
*   接口
*   包

所有这些示例背后都隐藏着巨大的复杂性。

总结本节，Go 语言不在功能上竞争。“*至于 Go 1.0，语言规范已冻结。*”

### 适合云环境的快速语言

> *“Go 语言快速、有趣且高效。”* —— Ken Thompson。

这是发明这门语言的核心原因之一：提供一门可以在云端并发运行的快速语言。

我们将详细阐述使 Go 语言如此快速的三个方面：

*   编译速度快
*   类似 C 语言
*   并发模型

#### 编译速度快

Go 语言不仅旨在运行时快速，还极其重视编译速度，这类似于敏捷方法论的理念，即显著提高发布频率。

那么是什么让它编译得如此之快？是什么让二制制文件如此精简？原因如下：

*   避免循环依赖
*   编译设计
*   未使用的导入和声明
*   Go 语言的简洁性

##### 避免循环依赖

如果我们尝试以循环方式导入包，将会遇到编译错误。如果存在循环依赖，Go 语言无法编译。所有依赖都可以表示为一个 DAG（即有向无环图）。由于这种包结构，只有当树中的所有包都已编译完成后，每个包节点才能被编译。

**图 2.2：** 包依赖 DAG

在该示例中，包 A 和 B 已经编译完成，我们可以并发编译 C、D 和 E。

##### 编译设计

引用 Golang FAQ 中对“为什么要创建一门新语言？”的回答：

> *“最后，使用 Go 语言旨在追求速度：在单台计算机上构建大型可执行文件最多应只需几秒钟。实现这些目标需要解决许多语言层面的问题：表达能力强但轻量级的类型系统；并发和垃圾回收；严格的依赖规范；等等。这些无法通过库或工具很好地解决；因此需要一门新语言。”*
