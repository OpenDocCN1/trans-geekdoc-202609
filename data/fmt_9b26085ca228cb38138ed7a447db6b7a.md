
在外部渗透测试项目中，目标是识别穿越网络中各种障碍（如防火墙和入侵检测系统 `IDSes`）的方法，并获得这些防御背后的系统。为了完成这项任务，渗透测试系统需要放置在外部网络中。通常，系统被放置在独立的*非军事区*中，以便对渗透实验室系统的访问受到限制，但对公司资产的访问与任何连接互联网的系统类似。

## 设备

进行内部或外部渗透测试所需的设备各异，取决于公司的大小和需求。通常，使用多个平台来托管不同的应用程序，例如漏洞识别程序、漏洞利用平台、网络扫描器和其他黑客工具。在进行远程破解攻击的情况下，必须解决带宽限制。公司渗透测试人员还可以从具有处理能力的服务器受益，特别是当需要进行密码或加密破解时。渗透测试设备的物理访问应受到控制。实验室设备不应让渗透项目之外的任何人访问。可能的物理访问使得访问系统变得更容易，因此应根据数据敏感性评估并加强物理安全。

## 软件

有很多商业和开源工具供渗透测试人员使用，可以提高渗透测试的速度和准确性。可以在 [www.sectools.org](http://www.sectools.org) 获取工具列表。我们在第二部分讨论 `sectools.org` 网站列出的工具，并在章节示例中使用商业和开源工具。使用哪些工具取决于渗透测试的目的、业务需求和预算——在大型组织中，包含各种应用程序以涵盖所有类型的渗透测试并不罕见，包括针对网络、系统、数据库和 Web 攻击设计的应用程序。

### 保护渗透测试数据

在渗透测试过程中，工程师会访问性质敏感的客户数据。在渗透测试期间保护收集的客户数据至关重要。本节将讨论保护客户数据和渗透测试系统的一些挑战和解决方案。

## 加密方案

在渗透实验室中，使用了许多不同的操作系统和软件应用程序。安全地存储这些磁盘非常重要，原因有二：(1) 磁盘会长脚并“走出”实验室（无论是有意的无意的）；(2) 磁盘上数据的完整性至关重要。

### 数据加密

关于安装盘的“流失”问题，任何支持过网络的人都会发现自己光盘短缺。有时是因为人们借走了它们，或者网络管理员忘记将光盘留在了光驱槽中。虽然这看起来可能并不严重，但软件的丢失通常意味着程序和控制措施薄弱，这可能会威胁渗透测试团队的信誉。如果任何包含第三方应用程序或操作系统的安装盘离开了渗透测试实验室，敏感数据泄露的风险可能较低。然而，如果安装盘包含敏感信息（例如专有软件代码或配置信息），数据丢失可能会造成财务上的损失。为了防止任何损失演变成公司灾难，应尽可能对所有数据进行加密。这包括实验室系统中的静态数据——因为设备也可能像安装盘一样容易被“流失”。对所有静态数据强制加密给实验室工程师增加了额外责任，因为加密密钥必须得到妥善保护。其他可以考虑的加密方法包括硬盘加密和基本输入/输出系统（BIOS）密码保护。存在某些应用程序可以加密整个硬盘，这可以在硬盘（或整个系统）被盗时保护数据免受未经授权的泄露。虽然设备丢失可能代价高昂，但任何敏感数据的丢失可能会糟糕得多。BIOS 密码保护还降低了恶意用户访问系统数据的风险，特别是对于笔记本电脑。系统可以配置为在启动前需要 BIOS 密码，从而有效防止未经授权的用户访问系统。

### 数据哈希

安装盘的完整性问题也是一个严肃的问题。某些操作系统和补丁盘是通过定义良好且安全的通道交付的；但大多数情况下，补丁和更新是直接从互联网下载的。通过互联网下载软件的人如何知道他们下载的内容是文件的真实副本，且没有被损坏或被恶意篡改呢？答案是哈希函数。所有为渗透测试实验室下载应用程序和软件都应该使用哈希函数进行验证。`hash function` 是一种数学过程，将文件转换为单个值。这个值在（理论上）对于每个文件都是唯一的。对文件的任何修改，即使只改变一个位，也会剧烈改变哈希值。最流行的是 `MD5`，对于那些具有安全意识的软件编写者，每个下载项通常都有一个发布的 `MD5` 值。一旦渗透测试团队下载了文件，关键的一点是对文件进行 `MD5 hash` 校验并与作者发布的值进行比较，以确保他们拥有文件的真实副本。一旦验证通过，应将该值记录在某处以备后参考，例如存储在保险箱的文件夹中。

**警告** 程序可能具有不同的哈希值，取决于它被编译运行的操作系统。在一个 Linux 发行版中的 `MD5 hash` 可能在另一个发行版（如 Microsoft Windows）中有所不同。在记录哈希时，跟踪你正在使用的哪种操作系统发行版非常重要。`MD5 hashes` 也应该在任何安装盘上使用，以验证使用的是正确的光盘，特别是在它们被用于渗透测试实验室之前。这让渗透测试团队确信他们使用的是文件的真实副本。验证哈希可以提供一种机制，用于检测何时考虑在实验室中使用错误版本的应用程序。通过将应用程序的 `MD5 hash` 与一份打印的列表进行比较，可以很快看出是否在实验室中选择了错误的光盘或文件。

### 加固渗透测试系统

作为最佳实践，所有计算机都需要具备防护措施，其强度至少应与其存储数据的价值相等。保护你的系统所需的最低保护水平应由你的公司政策概述。然而，超出这一水平总是可以接受的。在公司政策似乎并不足够的情况下，这里是一些可以改进你的保护措施的建议：

- **加密硬盘**：在 Windows 的后续版本中，文件、目录甚至整个硬盘都可以被加密。然而，要理解解密硬盘有多种方法——计算机加密通常由公司控制，并希望掌握在渗透测试人员手中。

- **将硬盘锁在保险箱中**：如果硬盘可以从工作电脑上取出，将硬盘放在保险箱中是保护它们的极佳方法。在火灾或地震等物理灾害发生，硬盘可能会完好无损地出来（取决于保险箱的质量）。如果工作电脑是笔记本电脑，请将整个笔记本放在保险箱内。在客户现场使用的笔记本电脑应该始终处于安全状态，并且绝不能无人看管。将笔记本留在汽车内绝不能被视为保护方法。

- **将系统存放在物理控制的室内**：渗透测试实验室应位于具有物理安全控制的独立房间，以限制授权的人员访问。在许多大型组织中，测试实验室是分开并位于钥匙控制门后的。然而，在许多情况下，渗透测试实验室占据了来自各个部门服务器的空间。这可能会产生问题；拥有这些其他服务器合法权限的人可能不应该拥有渗透测试服务器的物理访问权限，因为它们可能包含比房间内其他系统更具性质的数据。

- **对渗透测试系统进行渗透测试**：了解渗透测试系统是否容易受到攻击，最好的方法莫过于实际上攻击它们。自然地，需要提前进行备份（并妥善保护），并在之后执行清理程序。

**备份可能会被感染**

我最糟糕的经历之一是处理 `Blaster Worm`。我当时工作的公司遭受了严重打击，花了很长时间才清理网络。更糟糕的是，我们近一年的时间里每月至少感染一次，网络团队和安全团队都无法弄清楚 `Blaster` 是如何穿透我们的防御的。后来，我们发现生产实验室创建了各种受感染服务器的副本作为“镜像”映像，这些镜像可以快速恢复服务器。虽然对于实验室团队来说这是一个非常节省时间的工具，但每当他们使用受感染的镜像映像启动服务器时，网络就会受到冲击。

许多渗透测试是在客户的财产附近或其内部进行的。随着当今移动技术的发展，许多渗透测试都包含了对无线网络的检查。在涉及无线网络（或任何网络）的渗透测试中，必须发生的第一件事是 `PenTest` 团队需要获得该网络的访问权限。是通过网络的无线部分还是通过墙上的插座进行访问，这并不重要，重要的是建立了访问。当通过无线进行访问时，会产生额外的风险——敏感数据被截获。在某些情况下，客户的无线接入点没有使用强效的加密方法来保护传输到连接客户端的数据。如果渗透测试涉及访问无线接入点，最好限制无线访问并仅在需要时使用。一旦完成无线网络访问，渗透测试人员应尝试将该访问权限转移到有线网络，以便在何处可以实施额外的保护措施。

另一个与移动计算相关的安全问题是对 `PenTest` 系统的访问。在大型企业中，`PenTest` 系统被永久放置在不同地理位置的内部和外部网络中，以便渗透测试人员可以远程攻击资产。这有助于更好地了解内部和外部威胁存在哪些风险，从而针对威胁采取适当的安全措施。对远程 `PenTest` 系统的访问需要使用强安全控制进行管理。网络 `PenTest` 系统应该放置在限制了外部访问的安全网络中；可以使用虚拟专用网络（VPN）来控制对网络的访问，同时仍允许渗透测试工程师访问其系统以便他们发起攻击。

## 无线实验室数据

渗透测试实验室可能包含无线接入点，为 `PenTest` 工程师提供测试无线黑客技术的环境。在需要无线接入点的情况下，保护实验室内的系统非常重要，因为无线信号的访问会延伸墙壁和地板。为了保护系统免受未经授权的访问，应该创建两个独立的实验室——一个用于练习无线攻击的无线实验室，和一个用于进行系统攻击的独立实验室。无线实验室应用于训练无线黑客技术或对自定义配置进行测试。在你的无线实验室附近有多个无线接入点的情况下，需要极其小心，以确保对实验室无线网络的访问受到控制，至少要使用强加密和强身份验证方法。目前的科技（如 `WPA2`）应当是建立和运行无线渗透测试实验室的标准做法。强安全和隔离的无线网络不仅保护了渗透测试实验室内的数据，还保护了意外连接到实验室的任何人，特别是在那些将病毒、蠕虫或僵尸网络用于测试目的的情况下。

## 工具与陷阱……

## 自动连接的危险

不久前，我在家里搭建了一个无线实验室。事实证明，我公寓隔壁的当地警察局与我打算用于测试的无线配置相同。经过进一步检查，我意识到警察局设置其无线接入点时没有进行加密。如果我当时直接插上 `BackTrack LiveCD` 并开始黑客攻击，很有可能我攻击的是警察的网络，而不是我自己的。我不确定他们是否会对我的活动表现得友善。

## 额外的网络硬件

在企业环境中，网络硬件通常包含在网络评估的渗透测试中。在生产网络中，攻击网络设备（如 `routers`、`IDSes`、`firewalls` 和 `proxies`）有时会导致网络崩溃或拒绝服务 (`DoS`)。

在企业环境中，`PenTest` 项目通常将它们的攻击分为两种不同的场景。第一种场景是攻击与生产网络相同的测试网络。这允许网络管理员监控 `PenTest` 对网络的影响。在测试网络经过充分测试后，从攻击测试网络中学到的知识将用于攻击生产网络，但会排除那些更具攻击性的方法。对于个人渗透测试实验室来说，访问网络设备比在企业世界要困难得多。为了练习针对网络设备的攻击和规避技术，通常需要硬件。如果个人实验室的唯一目标是学习如何攻击应用程序和操作系统，则可以忽略网络硬件。然而，为了理解网络攻击涉及的所有细微差别，真的没有购买硬件的选择。

注意：尽管网络配置似乎在渗透测试的主题之外，但理解如何读取配置并学习网络设计的“最佳实践”对于渗透测试是非常有帮助的。正如我们在第 3 章中讨论的，具有网络架构背景的渗透测试人员可以识别各种网络设计中的缺陷，这可能是渗透测试项目成功的关键。

### 路由器

路由器攻击可能是网络渗透测试中最常见的攻击类型。在 `PenTest` 实验室中包含路由器和交换机将为网络攻击提供额外的教育维度，包括路由器配置错误、网络协议攻击和 `DoS` 攻击。家用路由器不是包含在个人实验室中的良好选择，因为它们仅仅是真实网络设备的精简版。购买哪种路由器是个人选择，取决于选择了何种网络架构职业路径。提供网络认证的公司是选择哪些路由器的良好信息来源。例如，在选择 Cisco 或 Juniper 认证时，获得建议的用于 Cisco 认证网络专业人员 (`CCNP`) 或 Juniper 认证互联网专家 (`JNCIS-ER`) 的路由器是明智的。如果资金不是问题，那么获得建议的 Cisco 认证互联网专家 (`CCIE`) 或 Juniper 网络认证互联网专家 (`JNCIE-ER`) 实验室设备是最合理的。

### 防火墙

规避防火墙是一项需要练习的高级技能。其困难之处之一在于识别何时是防火墙阻止了后端系统的访问，而何时系统本身才是障碍。有状态和无状态的防火墙会带来不同的问题，这同样需要通过练习来识别和克服。网络防火墙设备可以从供应商处获得，例如 `Cisco`、`Juniper`、`Check Point` 等。也有一些开源替代方案，包括客户端防火墙（如 `netfilter/iptables`）。开源替代方案提供了一个真实的目标，并且具有免费的额外优势。从供应商处获取设备的优势在于，熟悉商业防火墙上不同的配置有助于企业渗透测试，因为在大型组织中很少看到开源防火墙。渗透测试实验室并不需要购买高端防火墙。低端厂商产的防火墙包含与高端防火墙相同的操作系统和代码库。通常，廉价和昂贵厂商设备之间的区别在于带宽。

## 入侵检测系统/入侵防御系统

`IDS` 和入侵防御系统（`IPS`）的规避在渗透测试的早期非常有帮助。最终，渗透测试团队将尝试触发 `IDS/IPS` 系统以警报网络管理员注意团队的黑客尝试，但最初，渗透测试团队将尝试在不被发现的情况下获取尽可能多的信息，以测试客户的应急响应程序。可能被广泛使用的 `IDS/IPS` 系统是名为 `Snort` 的开源软件应用程序，可以在 [www.snort.org](http://www.snort.org) 获取。许多用于检测网络目标上恶意活动的规则针对病毒和蠕虫活动设计。然而，也有一些规则设计用于检测黑客尝试，例如暴力破解攻击和网络扫描。理解“事件阈值”并学习修改攻击速度可以帮助成功完成专业的渗透测试。

## 总结

在本章中，我们讨论了围绕渗透测试实验室的一些通用概念，包括个人实验室和企业实验室。个人实验室的首要目的是教育，可用于重现针对专有和开源软件及操作系统的漏洞利用。我们将使用 `VMs` 在个人实验室中完成书本及附带 DVD 中的示例。如果 `VM` 软件不是一个选项，可以将 `LiveCDs` 刻录到 CD 介质并在物理实验室内的系统上使用。在 第 5 章 中，我们将更详细地介绍在实验室中使用 `LiveCDs`。然而，企业实验室用于识别内部和外部网络中的系统漏洞。预计工程师已经具备了进行渗透测试所需的知识；在需要测试的情况下，在对生产服务器进行任何渗透测试之前，测试实验室是首选目标。可以将网络设备添加到渗透测试实验室，以提供额外的真实感和学习机会。对于路由器和交换机，最好获取商业版本，因为为家庭用户设计的设备往往不是大型企业所用设备的良好范例。对于防火墙和 `IDS` 设备，有开源版本可以准确地模拟商业设备。

## 解决方案快速车道

### 个人实验室

- 成本通常是保持个人实验室较小且易于管理的驱动因素。

- 除非个人实验室保留任何敏感数据，否则可以消除许多安全控制。

- 开源软件通常足以学习黑客技术，包括系统、应用、数据库和 Web 攻击，除非需要获取专有软件。

### 企业实验室

- 渗透测试系统的精确架构将取决于公司的业务需求以及渗透测试期间收集的数据的敏感性。

- 内部渗透测试的目的是识别易受“内部威胁”攻击的漏洞。

- 在外部渗透测试项目中，目标是识别穿透防御的方法。

### 保护渗透测试数据

- 在实验室中使用的所有应用程序和软件都应使用哈希函数进行验证，以保护渗透测试资产。

- 渗透测试系统通常包含需要安全控制的数据。

### 附加网络硬件

- 在生产网络中，攻击设备有时会导致网络崩溃或服务器 `DoS`。在针对生产网络之前，在测试网络中进行是谨慎的。

- 渗透实验室可以引入路由器以学习网络渗透技术。商业路由器和交换机优于家庭设计的设备。

- 开源防火墙可以用于学习防火墙规避技术。如果目标是学习防火墙配置及其误配置，商业防火墙是有益的。

- `Snort` `IDS` 应用程序是实验室中的价值工具，用于学习如何修改攻击速度以避免检测。

Q：Linux 系统上还有其他 `VM` 软件吗？答：`Xen Hypervisor` 已成功在 Linux 上用于托管 `De-ICE LiveCDs`。`Xen` 可以在 [www.xen.org](http://www.xen.org) 获取。

Q：如果我在实验室中使用无线接入点，或者使用任何加密，我应该关心什么？答：围绕未经访问无线网络的法律仍在制定中。问题是大多数无线设备被配置为自动连接到最强信号。如果该信号来自实验室，用户可能甚至没有意识到他们已经连接到了敌对网络。强加密可以防止事故的发生。

Q：如果我感兴趣的只是 Web 黑客攻击，我应该考虑在向我的实验室中添加网络设备吗？答：可能不需要。然而，网络中使用 Web 代理将提供额外的挑战，并提供更符合大型企业保护其 Web 服务器的真实场景。在实验室引入网络设备增加了真实性，并可以提高渗透工程师的技能和知识。
