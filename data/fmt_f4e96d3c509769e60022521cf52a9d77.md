
这些如何应用取决于数据类型是分类型还是数值型。用于基准的分布计算如下：

*   **分类特征的分布计算：** 每个可能值的实例计数或百分比。
*   **数值特征的分布计算：** 落入各个桶中的值的计数或百分比。（全范围被划分为等大小的桶。）

2. 使用上述方法计算在生产环境中看到的最新值的统计分布。

3. Vertex AI 随后将基准与步骤 2 中计算的最新分布进行比较。距离度量的计算如下：

*   **分类特征：** 基准分布与最新生产分布之间的距离得分使用 `L-无穷距离` 计算。这是沿任何坐标维度测量的两个向量之间的最大距离。
*   **数值特征：** 距离得分使用 `Jensen-Shannon 散度` 计算。（其数学定义超出了考试范围。）

4. 当距离得分达到配置的阈值时，Vertex AI 会将其识别为异常（偏差或漂移）。

### 启用监控的实际注意事项

有几件事需要牢记，以便有效地监控数据，同时使其具有成本效益：

*   **采样率：** 配置 `预测请求采样率` 以仅获取生产输入的样本。
*   **监控频率：** 配置 `频率` 以设置监控模型记录输入以检测偏差或漂移的速率。这设置了每次运行中分析的已记录数据的监控窗口大小。
*   **告警阈值：** 为您感兴趣的每个特征配置阈值。当基准与生产输入特征分布之间的统计距离超过此阈值时，会生成告警。默认值为 0.3。
*   **端点中的多个模型：** 当您在端点上启用并配置偏差或漂移检测时，该配置将应用于部署在该端点后面的所有模型，包括以下内容：
    *   检测类型
    *   采样率
    *   监控频率

#### 输入架构

输入值是预测请求负载的一部分。Vertex AI 应能够解析输入值以进行监控。您可以在配置模型监控时指定架构，以帮助解析此输入。

对于 AutoML 模型，输入架构会自动解析，因此您无需提供。对于不使用键/值输入格式的自定义训练模型，您必须提供一个。

##### 自动架构解析

为偏差或漂移启用模型监控时，通常可以自动解析输入架构。Vertex AI 模型监控将分析前 1,000 个请求以检测架构。如果输入值采用键/值对的形式，这种自动检测的效果最好。此处 `key` 是特征的名称，实际值紧随冒号之后。请参阅以下以键/值对形式呈现的输入（汽车）示例：

```
{"make":"Ford", "model":"focus": year: "2011", "color":"black"}
```

##### 自定义架构

为了确保 Vertex AI 正确解析输入值，您可以在所谓的 `分析实例` 中指定架构。分析实例预期为 Open API 架构格式。

以下是预期架构的详细信息：

*   “type” 可以是以下之一：
    *   `object`：键/值对
    *   `array`：类数组格式
    *   `string`：csv 字符串
*   `Properties`：每个特征的类型。
*   对于 `array 或 csv` 字符串格式，指定特征的顺序。

以下是预测汽车转售价值的模型的输入示例：

```yaml
type: object
properties:
  make:
    type:string
  model:
    type:string
  year:
    type:number
  color:
    type:string
  known_defects:
    type: array
    items:
       type: string
required:
 -make
 -model
 -year
 -color
```

上述架构以 `object` 格式指定。特征 `make`、`model` 和 `color` 是字符串特征，`year` 是数字。特征 `known_defects` 是字符串数组。最后一部分告诉您除 `known_defects` 外所有特征均为必需。

在 CSV 格式中，您可以通过提供空字段来跳过可选输入特征。例如，假设您期望五个特征：`["a","b",,"d","e"]`。请注意第三个特征被跳过。第三个缺失特征将被理解为“null”值。

### 日志记录策略

当您部署模型进行预测时，除了监控输入（即跟踪输入特征的趋势）外，记录请求可能也很有用。在某些领域（如受监管的金融垂直领域），出于未来审计的目的，所有模型都强制要求记录日志。在其他情况下，收集监控数据以更新您的训练数据可能很有用。

在 Vertex AI 中，您可以为 AutoML 表格模型、AutoML 图像模型和自定义训练模型启用预测日志。这可以在模型部署或端点创建期间完成。

#### 预测日志的类型

您可以启用三种日志以从预测节点获取信息。这三种日志类型相互独立，因此可以独立启用或禁用。

##### 容器日志记录

这会将预测节点的 `stdout` 和 `stderr` 记录到 Cloud Logging。这对于调试您的容器或模型非常有用且相关。了解 GCP 上更大的日志记录平台可能会有所帮助。

##### 访问日志记录

这会将诸如每个请求的时间戳和延迟之类的信息记录到 Cloud Logging。这在 v1 服务端点上默认启用；此外，您在将模型部署到端点时可以启用访问日志记录。

##### 请求-响应日志记录

这会将在线预测请求和响应的样本记录到 BigQuery 表中。这是主要机制。通过它，您可以创建更多数据来增强您的训练或测试数据。您可以在创建预测端点期间启用此功能，也可以稍后更新它。

#### 日志设置

创建端点或将模型部署到端点时，可以更新日志设置。了解日志记录的默认设置很重要。如果您已经使用默认日志设置部署了模型，但想要更改日志设置，则必须取消部署模型，并使用新设置重新部署。

如果您预计模型会有大量请求，除了扩展部署外，还应考虑日志记录的成本。高“每秒查询率”，即 `QPS`，将产生大量日志。

以下是为图像分类模型配置日志记录的 `gcloud` 命令示例。请注意最后两行，其中指定了日志记录配置。

```
gcloud ai endpoints deploy-model 1234567890 \
  --region=us-central1 \
  --model=model_id_12345 \
  --display-name=image_classification \
  --machine-type=a2-highgpu-2g \
  --accelerator=count=2,type=nvidia-tesla-t4 \
  --disable-container-logging \
  --enable-access-logging
```

##### 模型监控和日志记录

模型监控和请求-响应日志记录在后端使用相同的基础设施（BigQuery 表）。因此，当这两项服务同时涉及时，存在一些限制：

* 如果端点上已启用模型监控，则无法启用请求-响应日志记录。
* 如果先启用了请求-响应日志记录，然后启用模型监控，则无法修改请求-响应日志记录。

## 模型和数据集谱系

当你尝试不同类型的模型时，需要一种有条理的方法来记录实验的参数和相应的观察结果。机器学习实验的参数、工件和指标称为实验的*元数据*。元数据可帮助你执行以下操作：

* 检测部署后的模型性能下降。
* 比较不同超参数集的有效性。
* 跟踪机器学习工件（包括数据集和模型）的谱系。谱系有助于查找所有工件的来源，也能从给定的模型/数据集找到派生工件。
* 使用相同的参数重新运行机器学习工作流。
* 为审计目的跟踪工件的下游使用情况。这也可用于了解给定工件影响了什么。

### Vertex ML Metadata

使用 Vertex ML Metadata，你可以记录工件的元数据，并查询元数据以进行分析、调试或审计。Vertex ML Metadata 基于 Google TensorFlow Extended 团队开发的开源 ML Metadata (MLMD) 库。

Vertex ML Metadata 使用以下数据模型和相关术语：

* **元数据存储区：** 这是所有元数据资源的顶级容器。它是区域级的，且在 Google Cloud 项目范围内。通常，一个元数据存储区由整个组织共享。
* **元数据资源：** Vertex ML Metadata 使用类图数据模型来表示资源之间的关系。这些资源如下：
    * **工件：** 工件是由机器学习工作流创建或可被其使用的实体或数据片段。示例包括数据集、模型、输入文件、训练日志和指标。
    * **上下文：** 上下文是一组可供查询的工件和执行。假设你正在优化超参数；每个实验将是一个具有自己参数和指标集的不同执行。你可以将这些实验分组到一个上下文中，然后比较该上下文中的指标以确定最佳模型。
    * **执行：** 这代表机器学习工作流中的一个步骤，并可附带运行时参数进行标注。示例可以是一个“训练”操作，附带关于耗时和使用的 GPU 数量的标注。
    * **事件：** 事件连接工件和执行。诸如工件作为执行的输出和下一个执行的输入等详细信息，可使用事件来捕获。当你试图追踪谱系时，它有助于确定工件的来源。图 12.3 显示了一个包含事件、工件、执行和上下文的简单图。

* **元数据架构：** 元数据架构指定工件或执行等特定类型数据所使用的架构。类型架构使用 YAML 格式的 OpenAPI 架构对象表示。

#### 管理 ML 元数据架构

存储在 Vertex ML Metadata 中的每个元数据资源都遵循一个称为 `MetaDataSchema` 的架构。对于存储的最常见资源类型，有称为*系统架构*的预定义架构。系统架构位于 `system` 命名空间下。以下是 YAML 格式的预定义模型系统类型示例：

```yaml
title: system.Model
type: object
properties:
  framework:
    type: string
    description: "The ML framework used, eg: 'TensorFlow' or 'PyTorch'."
  framework_version:
    type: string
    description: "The version used, eg: '1.16' or '2.5'"
  payload_format:
    type: string
    description: "The format of the model stored: eg: 'SavedModel' or 'pkl'"
```

让我们看看两个重要操作：创建工件和查找工件。其他操作（此处未显示）包括删除工件、创建执行和上下文管理。你可以使用 REST、命令行或 Python 来执行这些操作，我们将展示 Python 示例。以下是在 Python 中创建工件的方法：

```python
def create_artifact_sample(
    project: str,
    location: str,
    uri: Optional[str] = None,
    artifact_id: Optional[str] = None,
    display_name: Optional[str] = None,
    schema_version: Optional[str] = None,
    description: Optional[str] = None,
    metadata: Optional[Dict] = None,
):
    system_artifact_schema = artifact_schema.Artifact(
        uri=uri,
        artifact_id=artifact_id,
        display_name=display_name,
        schema_version=schema_version,
        description=description,
        metadata=metadata,
    )
    return system_artifact_schema.create(project=project, location=location)
```

在此示例中，我们定义了一个新函数，接收 URI、工件 ID、位置、显示名称、架构版本、描述和元数据（定义元数据本身的属性）等详细信息。在函数内部，我们调用 `artifact_schema.Artifact()` 函数创建一个系统工件实例，第二步调用 `create()` 函数在元数据存储区中创建它。

在下一个示例中，我们将看到如何查询或查找数据集或模型等工件：

```python
def list_artifact_sample(
    project: str,
    location: str,
    display_name_fitler: Optional[str] = "display_name=\"my_model_*\"",
    create_date_filter: Optional[str] = "create_time>\"2022-06-11\"",
):
    aiplatform.init(
        project=project,
        location=location)
  
    combined_filters = f"{display_name_fitler} AND {create_date_filter}"
    return aiplatform.Artifact.list(filter=combined_filters)
```

我们在这里使用类似的方法，定义一个名为 `list_artifact_sample` 的函数来完成这项工作。这也只有三行代码，第一行是 `init()` 函数，第二行创建一个 `combined_filters` 查询。第三行我们使用 `combined_filters` 字符串作为参数调用 `aiplatform.Artifact.list()` 函数。这些代码块和更多信息可以在 `https://cloud.google.com/vertex-ai/docs/ml-metadata/managing-metadata` 的文档中找到。

### Vertex AI Experiments

在开发机器学习模型时，目标是为用例找到最佳模型。您可以尝试各种不同的库、算法、模型架构、超参数等。Vertex AI Experiments 可帮助您跟踪这些试验，并分析不同的变体。

具体而言，Vertex AI Experiments 可帮助您：

* 跟踪实验运行的步骤（如预处理、嵌入、训练等）
* 跟踪输入，如算法、超参数、数据集等
* 跟踪这些步骤的输出，如模型、指标、检查点等

基于上述信息，您可以了解什么有效，并选择探索的方向。Google Cloud 控制台提供了一个统一的视图来查看您的实验，您可以在其中对实验运行的结果进行切片分析，并深入查看单次运行的结果。使用 Vertex AI SDK for Python，您可以访问实验、实验运行、实验运行参数、指标和工件。结合 Vertex ML Metadata 使用时，您可以跟踪工件并查看谱系。

### Vertex AI Debugging

有时在训练模型时，您会遇到问题，并怀疑 GPU 未被高效利用，或者权限问题限制了对数据的访问。要调试这类问题，Vertex AI 允许您直接连接到运行训练的容器。为此，请按以下步骤操作：

1. 在训练容器中安装交互式 Bash shell。预构建容器中已预装 Bash shell。
2. 运行支持交互式 shell 的自定义训练。
3. 确保用户拥有正确的权限。如果您使用的是服务帐号，请确保服务帐号拥有正确的权限。
4. 将 `enableWebAccess` API 字段设置为 true 以启用交互式 shell。
5. 导航到您启动自定义训练作业时 Vertex AI 提供的 URI。
6. 使用交互式 shell 执行以下操作：
    1. 检查 Vertex AI 用于训练代码的服务帐号的权限。
    2. 使用 py-spy 等分析工具可视化 Python 执行情况，您可以使用 pip3 安装它。
    3. 使用 perf 分析训练节点的性能。
    4. 检查 CPU 和 GPU 使用情况。
