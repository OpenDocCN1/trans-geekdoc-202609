
一种旨在处理简单请求（上行）和静态数据（下行）的机制，已成为大量不同种类数据以及可执行代码进行高容量双向传输的通道。

网页包含超文本标记语言（`HTML`），它描述网页各部分**是什么**，而不是其确切的格式。例如，`HTML` 标签标记段落、标题、列表等。浏览器可以利用关于每部分是什么类型的 `HTML` 信息来决定如何显示它，同时了解将显示它的设备的屏幕尺寸和分辨率。

Web 流量的主要漏洞之所以成为可能，是因为网页中作为代码或用户生成内容的部分也用标签标记。因此，这些部分内部的文本在到达浏览器或 Web 服务器时就变成了可执行代码。检查这种可执行代码是否合理且安全是困难的，而且往往甚至不曾尝试。

三种主要攻击利用了数据变为可执行代码的这种能力。第一种称为 `cross-site request forgery`（跨站请求伪造）。攻击者利用自己的网站，通过不知情用户的浏览器向另一台 Web 服务器发起恶意请求。例如，假设用户已登录银行网站的银行账户，同时在另一个标签页打开了攻击者的网站。攻击者可以导致用户的 Web 浏览器下载一个恶意请求（例如转账），然后将其传递给银行网站。银行知道用户已通过身份验证，却没有意识到该请求并非来自用户的操作，而是间接来自另一个网站。用户甚至可能没有意识到发生了任何事情。

第二种称为 `cross-site scripting`（跨站脚本）攻击，其工作方式相反。攻击者在允许用户上传内容的网站上插入 `HTML` 格式的内容——例如，社交媒体网站可能允许用户描述他们的兴趣。在这个上传的内容中，有一个包含可执行代码的 `HTML` 部分。每当用户下载该内容时，这段代码就会在他们的计算机上执行，并能执行浏览器中允许执行代码做的任何事情。下载的恶意代码可能直接做一些坏事，但也可能导致下载其他恶意代码。

这两种攻击看似应该很容易预防，但它们与 `HTML` 和浏览器的核心机制相互作用：可执行代码如何处理、身份验证和 `Cookie` 如何工作，以及同时与多个网站交互的能力。已经有过几次防止这些攻击的尝试，这是一个不断发展的领域，但解决方案需要所有浏览器和所有网站就确切需要做什么达成一致。实际上，浏览器尝试了不同的方法来试图解决根本问题，而不需要更改网站（因为这在全世界范围内永远不会发生）。

第三种攻击称为 `SQL injection`（SQL 注入），也许是最流行的单一网络攻击机制。网站在收到请求时通常即时创建页面。例如，如果你访问你的银行，你必须首先填写一个提供你的账户标识和密码的表单；但随后银行会显示一个包含你的余额和其他个人详细信息的页面。当然，这个页面对每个人都是不同的。

填充此页面的数据来自一个数据库，该数据库拥有每个客户的记录。数据库是专门的数据存储，响应以查询形式表示的请求提供信息：“显示具有此账户号码的个人的余额”、“显示该分行所有人的账户号码”，等等。这些查询使用查询语言以结构化方式表示，其中 `SQL`、`Structured Query Language` (SQL) 是最流行的一种。

当你在 Web 浏览器的表单中输入信息（“账户 xxxx 的余额是多少”）时，它会变成一个 `SQL` 查询，被传递给 Web 服务器，Web 服务器再将其传递给数据库。当数据库响应 Web 服务器时，服务器将响应转换为 `HTML` 并发送给浏览器以供显示。

问题在于 Web 浏览器和/或 Web 服务器不（在某些情况下，不能）验证输入表单的文本是否为安全的 `SQL` 查询。因此，知识渊博的用户可以在表单中输入执行数据库中恶意操作的信息，甚至包括删除全部内容。

已知有几种针对 `SQL` 注入攻击的对策，大多基于在输入到达数据库之前更努力地验证输入。然而，这些依赖于正确配置 Web 服务器和数据库。许多 Web 服务器（和数据库）是为中小型企业构建的，它们可能不了解这些问题，因此允许这些攻击的错误配置仍然很常见。

这些攻击可以协同作用。跨站请求攻击允许恶意网站向另一个网站创建请求。该请求可以是针对位于该其他网站后面的数据库的 `SQL` 注入攻击。

用于运行 Web 服务器的代码也可能存在潜在攻击者已知的漏洞。即使是存在已久的知名 Web 服务器也包含错误。例如，`Apache` Web 服务器每年大约发布 10 个安全修复。复杂的攻击者可能能够直接攻击此类网站，即不依赖浏览器作为中介。

许多允许恶意行为者进入个人社交媒体账户或银行账户的攻击，使用钓鱼或定向钓鱼将恶意软件植入个人的计算机或手机。此类恶意软件可以监视个人何时登录其账户，捕获其密码，然后在后台悄悄登录；随后发布内容到社交媒体、发送垃圾邮件，或从其银行账户转移资金。用户可以通过使用防病毒和反恶意软件来防范这些攻击，这些软件可在恶意软件进入设备前或后检测到它们。

利用 Web 服务器机制的攻击更难检测，因为它们大多是瞬态的——攻击发生在一瞬间，当时没有产生任何迹象表明正在发生什么，并且留下的痕迹很少。

### 7.3 区块链

`Blockchains`（区块链）是一种应用层系统，依赖于我们在第 3 章讨论的许多加密思想。尽管区块链的长期用处仍是一个开放性问题，但它们创造了一个值得探索的复杂安全环境。

#### 区块链技术概述

##### 数字哈希

回顾一下，数字哈希是一种将字符串映射为固定大小表示（在此语境下通常为 32 字节）的函数，其特点是无法实际逆向还原，且两个相似的输入字符串会被映射到完全不同的固定大小表示。它们代表了输入字符串内容的摘要。

##### 公钥加密

还要回顾的是，公钥密码系统使用一对私钥和公钥，允许双方在无需交换密钥的情况下通过加密进行通信。此类系统允许任何人向私钥持有者发送内容，并允许私钥持有者以不可抵赖的方式对任何内容进行数字签名。

##### 区块链基础

区块链是一种分布式交易记录系统，旨在成为交易历史的永久记录。它由区块组成，每个区块包含一个时间戳和一条或多条交易记录，并按链式结构连接。每个区块都包含其前驱区块的数字哈希，因此实际上无法篡改前一个区块。

##### 交易流程与身份

想要向区块链添加交易的用户必须拥有一个或多个私钥-公钥对。区块链上的活动与持有每对密钥的身份相关联，但该身份与拥有它们的特定个人之间没有必要的联系。当用户想要添加交易时，会将其广播给参与的计算机（节点），这些节点随后竞争获得将交易添加到链上的权利。获胜的节点称为发布节点。每个区块链系统必须有某种方式奖励发布节点，以激励它们参与竞争。这可以简单到收取一笔交易费。

不同的区块链设计采用多种机制进行这种竞争。所有机制的设计初衷都是防止单个节点或一组节点串通以永远获胜，从而能够破坏向区块链插入新区块的过程。

##### 共识机制

###### 工作量证明

第一种机制称为**工作量证明**。在此机制下，潜在的发布节点必须解决计算成本高昂但解决方案正确性易于验证的难题。想要串通的一组节点必须投入巨大资源才能始终最先解出难题，从而控制区块链。最先解出难题的节点获得将下一个区块添加到链上的权利，并将扩展后的链传播给所有参与区块链的节点。

可能会出现多个节点同时解出难题，并各自向区块链添加一个（可能不同的）区块的情况。

工作量证明方法存在两大主要问题：

1.  **生态灾难**：因为许多节点通过进行消耗大量电力的昂贵计算来竞争成为发布者。

2.  **高延迟**：由于链在一段时间内可能不一致，最好等到多个区块被添加到链上后，再确认特定交易已永久添加到链中——经验法则是等待后续六个区块。由于某些区块链每 10 分钟才添加一个区块，这给成功完成交易带来了巨大的延迟。

###### 权益证明

第二种机制称为**权益证明**，其中获胜节点（即获得发布权的节点）按其在系统中质押的份额（通常是货币）比例随机选出。其理念是：在区块链正确运行上拥有利益的节点有动力使其难以被收买。随机选择获胜节点的过程经过精心设计，旨在尽可能增加破坏该过程的难度。精心设计成为发布节点的过程可以使其极不可能被腐蚀。

尽管权益证明方法不需要工作量证明所需的巨大计算量，但它们仍有性能成本。例如，长期运行的区块链链大小可达 200 GB（且必然还会增长），因此存储和移动链的成本很高。

##### 区块链类型

###### 无许可区块链

区块链可以是**无许可**的，使其真正实现分布式，用户和节点只需对其他参与实体保持最低限度的信任。区块链带来大规模系统性变革的大部分预期源于其去中心化特性，即交易不再需要受信任的中介（通常会收取少量服务费）。据称，无许可区块链消灭了许多形式的中介或守门人。

###### 有许可区块链

区块链也可以是**有许可**的，例如完全在大型组织内部运行。由于实体间可以有更大的信任，这减少了某些区块链流程的摩擦。

##### 应用：加密货币

区块链最显眼的应用之一是实现**加密货币**，其中比特币可能是最著名的。在此场景下，区块链用于记录所有金融交易，从而完整记录每个价值单位（如比特币）的所有权归属。价值从更广泛的金融系统进入区块链；一旦进入，它可以在不同身份间转移；最终可以移回更广泛的金融系统。由于身份仅通过加密密钥识别，用户可以匿名转移价值。这显然为罪犯和洗钱者创造了以无法追踪到他们的方式转移价值的途径。请注意，所有交易都是可见的；只是进行交易的个人身份被隐藏了。因此，加密货币的功能类似于“瑞士银行账户”，因为你无法知道谁拥有这些价值。

价值单位的所有权与用于获取该所有权的私钥相关联。大多数备受瞩目的“窃取”加密货币的黑客攻击，实际上都是非法获取了私钥，从而将价值单位转移给他人。这些私钥有时被称为数字钱包，因为拥有私钥等同于拥有区块链中记录的价值单位。

用于加密货币的区块链有一种自然的方式来奖励发布节点，即给予它们加密货币作为奖励。各国花费了数百年才理解如何保持货币稳定，而加密货币尚未解决这一问题。其相对于现实货币的价格剧烈波动，导致节点成为发布节点的激励也随之波动，使得潜在发布节点难以规划其资源投入。

##### 网络安全漏洞

区块链存在许多网络安全漏洞，包括：

*   **针对发布节点选择分布式机制的攻击**：这些机制旨在公平随机。攻击包括串通以使特定节点被选为发布节点，以及所谓的 **51% 攻击**，即超过一半的潜在发布节点被腐蚀，从而创建自己的竞争版本区块链，包含自己的交易（添加额外交易或删除真实交易），该版本比真实链更长，因此被采纳为权威链。

*   **利用未上链交易仅为数据这一事实的攻击**：这些交易可能被丢弃、篡改或误导。

*   对（分布式）治理结构的攻击，该结构平衡了软件开发者、潜在发布节点集合以及用户自身的权力。这些群体中的每一个都对其他群体拥有一定的影响力，而其中任何一个群体中有足够多的恶意成员都可能破坏或腐蚀区块链。编写糟糕的软件也会导致问题，即使这只是意外造成的。例如，用于将价值从金融系统转移到加密货币区块链的代码中的软件错误，导致价值完全消失——可以说，它“在”区块链中，但以一种永远无法转移或提取的方式存在。

*   基于僵尸网络的攻击，旨在获取成为发布节点的奖励。不法分子利用僵尸网络执行所需的计算，甚至将毫无戒心的用户的浏览器用作计算引擎。由于此类发布节点无需支付电力或设备费用，工作量证明的经济成本收益比更具吸引力。

*   窃取私钥的攻击，即窃取数字钱包。由于私钥必须存储在某处（它们太长，无法每次都手动输入），因此成为极具吸引力的攻击目标。恶意软件可以搜索加密货币用户的计算机，寻找长度适合作为私钥的字符串，或者在用户向区块链转入或转出价值时监视剪贴板，随后窃取该字符串。

*   对区块链网络节点实施的拒绝服务攻击，阻止它们看到新交易，从而使其无法竞争成为这些交易的发布节点。这可能会扰乱区块链的整个运行，或通过在一轮竞争中淘汰某些潜在发布节点来扭曲竞争。

区块链依赖于其使用的加密协议保持足够强大。算法本身或其实现方式中存在漏洞的例子已有多起。区块链面临一个特殊问题，因为它们旨在成为永久记录。因此，在不与区块链之前的状态产生断裂的情况下，很难改变其工作的基本原理；而这种剧烈的变化往往会造成错误和漏洞。

## Chapter 8

## Summary

网络安全的大多数挑战最终都可以追溯到互联网的起源——名为 Arpanet 的研究网络。Arpanet 连接了少量的大学和美国政府研究实验室，因此其用户是受信任且可问责的。Arpanet 还被设计为能在核攻击中幸存，因此其操作和控制在设计上就是分布式的。

Arpanet 从未打算成为全球网络的基础，而今天的互联网连接了世界上一半的人口和数十亿台设备。当今的互联网覆盖地球上的每一个国家，拥有 Arpanet 最初的设计者无法想象的能力，包括万维网、电子商务、在线银行和金融服务、社交网络平台、对管道和电网的分布式控制，以及远程控制的灯泡和恒温器。互联网不仅规模极大，而且是动态的，因为设备会随着开关机或故障而上下线，且数据流会在每个源和目的地之间瞬时最佳的路径上流动。

Arpanet 的分布式特性意味着，随着它发展成为互联网，不存在对发生什么以及如何发生的中央控制。至今仍没有中央治理机构能强制所有硬件和软件开发者以特定方式行事。因此，全球决策复杂，需要各利益相关方之间的谈判，因而十分罕见。互联网的大多数变更都是由对新功能的渴望驱动的，想要实施变更的人必须获得那些也必须做出改变者的认可。互联网社区的规模、分布式治理和惯性，以及对向后兼容性的需求，意味着即使有明显好处的变更也无法实施，或者只能缓慢实施。

安全性不是那种可以在系统设计完成后添加进去的属性。虽然桥梁的设计可以修改以承受 30% 更大的负载，但复杂的软硬件系统无法真正通过修改使其安全性提高 30%。更安全的设计必须从一开始就着手，这对于已存在的系统来说是不可能的。所能做的只是加固，添加临时特性使突破安全变得稍微困难一些。关于设计和构建“互联网 2.0”长期以来一直有提议，但都因当前互联网的沉没成本而搁浅。

互联网中的大部分安全性都是围绕城堡隐喻构建的——高大的防护墙，配有限制数据流动的大门，仅允许经过认证的数据通过。认证仍然是一个复杂的问题，因为涉及的身份数量庞大，且认证点通常距离被认证的系统很远。许多类型的数据自由流动，因为没有方法能对其进行稳健认证（如电子邮件），或者出于商业原因不进行认证（如万维网）。

互联网用户对更高安全性的需求也很少，至少在新型基于互联网的服务的诱惑面前是如此。便利性在实践中总是胜过安全性，这是一条真理。

互联网始于一个不太重视网络安全的基础设施；其规模和功能的爆炸性增长几乎没有提供激励或机会来添加安全特性；其分布式的性质和治理意味着没有杠杆能在开发者和用户偏好其他特性的情况下强制实施更好的安全性。网络安全的困难几乎都追溯到这一历史和这些驱动因素。

本可（至少理论上）简化为可处理问题的网络安全，已演变为一场消耗战。这场战争的对手分为三类：破坏者，为取乐而破坏；罪犯，将网络空间作为平台和机制通过犯罪获利；以及国家，将网络空间作为情报收集平台，并越来越多地作为国家政策的工具。

他们之所以能取得成果，是因为网络空间设计和运行中的弱点，也因为普通网络空间用户对危险缺乏足够的认识。网络空间中发生的许多事情对普通用户是不可见的。从某种角度看，这是一个成功故事，因为它向普通人隐藏了巨大的复杂性；但这也意味着他们不知道自己在网络空间中的哪些行为是安全的、哪些有风险、哪些是危险的。教育有助于解决这个问题，但网络空间变化迅速，几年前明智的建议今天可能不再适用。

使网络空间更安全的斗争有两个方面。第一是尽可能继续加固实例化网络空间的硬件和软件。问题在于，加固网络空间是一种全球公共产品，但不可避免地会让某些组织付出比其他组织多得多的成本——因此资源投入不足，好的想法因无法接触到能发挥作用的关键点而失败。

第二个方面是利用执法手段惩罚滥用网络空间的人。这存在许多问题：不同司法管辖区的法律框架各异，且法律与犯罪分子使用的漏洞利用之间存在滞后；执法人员的技能组合；以及犯罪分子能在一个国家生活却在另一个国家实施犯罪。

然而，执法方法面临的最大限制在于将在线身份与现实世界身份关联起来的问题。在线认证机制不够强健，无法将在线行为与实施者紧密绑定，当然更达不到“排除合理怀疑”的程度。在网络空间实施恶意行为者几乎无需担心刑事定罪。

网络安全可以得到改善，但只能通过微小的、积极的变化，而非优雅的大规模扫荡式行动。
