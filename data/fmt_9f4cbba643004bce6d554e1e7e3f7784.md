
Web 让你足不出户就能购买机票、查收邮件、支付账单和购买股票。如今几乎每个企业都运营着一个网站，许多网站允许你通过该站点进行敏感交易。

除了 Web 应用程序带来的便利性优势外，还伴随着一系列新的漏洞，这些漏洞可能使支持 Web 的组织面临安全风险。在接下来的几节中，我们将介绍一些常见的 Web 应用程序攻击。关于 Web 应用程序安全的更多详细信息，请参阅第 9 章“安全漏洞、威胁和对策”。

### 跨站脚本

当 Web 应用程序包含某种类型的`反射输入`时，会发生`跨站脚本 (XSS) 攻击`。例如，考虑一个简单的 Web 应用程序，它包含一个文本框，要求用户输入姓名。当用户点击提交时，Web 应用程序加载一个新页面，显示“Hello, *name*。”

在正常情况下，此 Web 应用程序按设计运行。然而，恶意个人可能利用此 Web 应用程序欺骗不知情的第三方。正如你所知，可以通过使用超文本标记语言 (HTML) 标签 `<SCRIPT>` 和 `</SCRIPT>` 在网页中嵌入脚本。假设你不在“姓名”字段中输入 *Mike*，而是输入以下文本：

```
Mike<SCRIPT>alert('hello')</SCRIPT>
```

当 Web 应用程序以网页形式“反射”此输入时，你的浏览器会像处理任何其他网页一样处理它：显示网页的文本部分并执行脚本部分。在本例中，脚本只是打开一个弹出窗口，其中显示“hello”。然而，你可以更恶意地包含一个更复杂的脚本，要求用户提供密码并将其传输给恶意第三方。

此时，你可能会问自己，怎么会有人落入这种攻击的圈套。毕竟，你不会通过在提供给执行反射的 Web 应用程序的输入中嵌入脚本来攻击自己。这种攻击的关键在于：可以在链接中嵌入表单输入。恶意人员可以创建一个网页，其中包含一个标题为“查看您在第一银行的账户”的链接，并在该链接中编码表单输入。当用户访问该链接时，网页看起来像是一个真实的第一银行网站（因为它确实是！），工具栏中显示着正确的地址，且拥有有效的数字证书。然而，该网站随后会执行恶意用户在输入中包含的脚本，该脚本看起来是有效网页的一部分。

跨站脚本攻击的对策是什么？当你创建允许任何类型用户输入的 Web 应用程序时，必须确保执行 `input validation`（输入验证）。在最基本的层面上，你绝不应允许用户在反射输入字段中包含 `<SCRIPT>` 标签。然而，这并不能完全解决问题；对于勤奋的 Web 应用程序攻击者来说，还有许多巧妙的替代手段可用。最佳解决方案是确定你 `will`（将）允许的输入类型，然后验证输入以确保其符合该模式。例如，如果你有一个允许用户输入年龄的文本框，你应该只接受一到三位数字作为输入。你的应用程序应拒绝任何其他输入作为无效输入。

#### 跨站请求伪造

`Cross-site request forgery`（跨站请求伪造）攻击，缩写为 XSRF 或 CSRF 攻击，与跨站脚本攻击相似，但利用的是不同的信任关系。XSS 攻击利用用户对网站的信任，在用户的计算机上执行代码。XSRF 攻击利用远程站点对用户系统的信任，代表用户执行命令。

XSRF 攻击的原理是基于一个合理的假设：用户通常同时登录到许多不同的网站。攻击者随后在一个网站中嵌入代码，该代码向第二个网站发送命令。当用户点击第一个网站上的链接时，他或她会在不知情的情况下向第二个网站发送命令。如果用户碰巧登录了第二个网站，该命令可能会成功。

例如，考虑一个在线银行网站。如果攻击者想从用户账户窃取资金，攻击者可能会去一个在线论坛发布一条包含链接的消息。该链接实际上是一个直接指向资金转账网站的链接，会发出一条将资金转入攻击者账户的命令。攻击者随后将该链接留在论坛上，等待毫无戒心的用户点击该链接。如果用户碰巧登录了银行网站，转账就会成功。

开发人员应保护其 Web 应用程序免受 XSRF 攻击。一种方法是创建使用安全令牌的 Web 应用程序，攻击者无法知道该令牌以将其嵌入链接中。另一种防护措施是网站检查从最终用户接收到的请求中的引用 URL，并且只接受源自其自身站点的请求。

#### SQL 注入

从组织的角度来看，`Structured Query Language (SQL) injection attacks`（结构化查询语言 [SQL] 注入攻击）比 XSS 攻击风险更大。与 XSS 攻击一样，SQL 注入攻击利用 Web 应用程序的意外输入。然而，SQL 注入攻击不是利用此输入试图欺骗用户，而是利用它来获得对底层数据库的未授权访问。

##### 动态 Web 应用程序

在 Web 早期，所有网页都是 `static`（静态）的，即不变的。网站管理员创建包含信息的网页并将其放置在 Web 服务器上，用户可以使用其 Web 浏览器检索这些网页。Web 迅速超越了这一模式，因为用户希望能够根据其个人需求访问定制信息。例如，银行网站的访问者不仅对包含银行位置、营业时间和服务信息的静态页面感兴趣。他们还想检索包含其个人账户信息的 `dynamic`（动态）内容。显然，网站管理员不可能在 Web 服务器上为每个用户创建包含该用户个人账户信息的页面。对于一家大型银行来说，这将需要维护数百万个包含最新信息的页面。这就是动态 Web 应用程序发挥作用的地方。

当用户发出请求时，Web 应用程序利用数据库按需创建内容。在银行示例中，用户登录 Web 应用程序，提供账号和密码。然后，Web 应用程序从银行数据库检索当前账户信息，并利用它即时创建一个包含用户当前账户信息的网页。如果该用户一小时后返回，Web 服务器将重复该过程，从数据库获取更新的账户信息。图 21.2 说明了此模型。

作为安全专业人员，这对你意味着什么？Web 应用程序增加了我们传统安全模型的复杂性。如图 21.2 所示，Web 服务器作为一台公开可访问的服务器，属于与其他服务器分离的网络区域，通常称为非军事区 (DMZ)。另一方面，数据库服务器不打算供公众访问，因此它属于内部网络。Web 应用程序需要访问数据库，因此防火墙管理员必须创建一条规则，允许从 Web 服务器访问数据库服务器。这条规则为互联网用户访问数据库服务器创建了一条潜在路径。（有关防火墙和 DMZ 的更多信息，请参见第 11 章“安全网络架构和保护网络组件”。）如果 Web 应用程序功能正常，它将只允许对数据库进行授权请求。然而，如果 Web 应用程序存在缺陷，它可能会允许个人通过使用 SQL 注入攻击，以意想不到且未经授权的方式篡改数据库。

##### SQL 注入攻击

SQL 注入攻击允许恶意个人直接对底层数据库执行 SQL 事务，这违反了图 21.2 所示的隔离模型。

在前面使用的示例中，银行客户可能会输入账号以访问一个检索当前账户详细信息的动态 Web 应用程序。Web 应用程序必须使用 SQL 查询来获取该信息，其形式可能如下，其中 `<number>` 是用户在 Web 表单上提供的账号：

```
SELECT *
FROM transactions
WHERE account_number = '<number>'
```

还有一个重要事实你需要知道：数据库将同时处理多条 SQL 语句，前提是每条语句都以分号结尾。

如果 Web 应用程序不执行适当的输入验证，用户可能会将自己的 SQL 代码插入由 Web 服务器执行的语句中。例如，如果用户的账号是 145249，他们可以输入以下内容：

```
145249'; DELETE * FROM transactions WHERE 'a' = 'a
```

然后 Web 应用程序会顺从地将其插入前面 SQL 语句中的 `<number>` 字段，导致如下结果：

```
SELECT *
FROM transactions
WHERE account_number ='145249'; DELETE * FROM transactions WHERE 'a' = 'a'
```

稍微重新格式化该命令，得到如下内容：

```
SELECT *
FROM transactions
WHERE account_number ='145249';
DELETE *
FROM transactions
WHERE 'a' = 'a'
```

##### 防范 SQL 注入

这是一个包含两条语句的有效 SQL 事务。第一条语句从数据库检索请求的信息。第二条语句删除数据库中存储的所有记录。糟糕！

您可以使用三种技术来保护 Web 应用程序免受 SQL 注入攻击：

###### 使用预处理语句

Web 应用程序开发人员应利用预处理语句来限制应用程序执行任意代码的能力。预处理语句（包括参数化查询和存储过程）将 SQL 语句存储在数据库服务器上，只有拥有适当访问权限的数据库管理员和开发人员才能对其进行修改。调用预处理语句的 Web 应用程序可以向其传递参数，但无法更改 SQL 语句的底层结构。

###### 执行输入验证

正如本章前面在讨论跨站脚本时所述，输入验证允许您限制用户在表单中提供的数据类型。就我们在上一节提供的 SQL 注入示例而言，从输入中移除单引号字符（`'`）将防止该攻击成功实施。最强且最安全的输入验证形式是白名单验证，即开发人员指定预期输入的确切性质（例如，小于 1024 的整数或少于 20 个字符的字母数字字符串），然后代码在将用户提供的输入提交给数据库之前验证其是否与预期模式匹配。

###### 限制账户权限

Web 服务器使用的数据库账户应仅拥有尽可能小的权限集。如果 Web 应用程序仅需检索数据，则应仅赋予其该能力。在该示例中，如果账户仅具有 `SELECT` 权限，`DELETE` 命令将会失败。

### 侦察攻击

虽然恶意代码通常依赖于诱骗用户打开或访问恶意软件，但其他攻击则直接针对机器。执行侦察可让攻击者发现弱点，以便直接用其攻击代码进行瞄准。为协助这种定位，攻击工具开发者创建了许多执行网络侦察的自动化工具。在以下章节中，我们将介绍其中三种自动化技术——IP 探测、端口扫描和漏洞扫描——然后解释这些技术如何通过更费力的垃圾箱翻找技术得到补充。

#### IP 探测

**IP 探测**（也称为 **IP 扫描** 或 **Ping 扫描**）通常是针对目标网络进行的第一种网络侦察类型。使用此技术时，自动化工具只是尝试 Ping 指定范围内的每个地址。响应 Ping 请求的系统会被记录下来以供进一步分析。不产生响应的地址被假定为未使用而被忽略。

IP 探测在当今的互联网上极为普遍。事实上，如果您为系统配置了公共 IP 地址并将其连接到互联网，您可能会在启动后几小时内收到至少一次 IP 探测。这种技术的广泛使用为禁用 Ping 功能（至少针对网络外部用户）提供了有力的理由。

#### 端口扫描

攻击者执行 IP 探测后，会得到网络上活动系统的列表。下一个任务是选择一个或多个系统作为目标，对其发动进一步的攻击。通常，攻击者心中已有目标类型；Web 服务器、文件服务器和支持关键操作的其他服务器是主要目标。

为缩小搜索范围，攻击者使用 **端口扫描** 软件探测网络上所有活动系统，以确定每台机器上运行的公共服务。例如，如果攻击者想以 Web 服务器为目标，他们可能会运行端口扫描以定位运行在端口 80（超文本传输协议 (HTTP) 服务的默认端口）上的服务的系统。管理员应利用此信息禁用其控制下系统上不必要的服务。这会减少系统的攻击面，使攻击者更难找到发起攻击的立足点。

#### 漏洞扫描

第三种技术是 **漏洞扫描**。一旦攻击者确定了要攻击的特定系统，他们需要发现该系统中可被利用以获取所需访问权限的特定漏洞。互联网上有各种工具可协助完成此任务。用于此目的的较流行工具包括 Nessus、OpenVAS、Qualys、Core Impact 和 Nexpose。这些工具包含已知漏洞的数据库，并探测目标系统以定位安全缺陷。随后，它们会生成非常详尽的报告，详细列出检测到的每个漏洞。从那时起，只需找到利用特定漏洞的脚本并针对受害者发动攻击即可。

重要的是要注意，漏洞扫描器是高度自动化的工具。它们可用于针对特定系统发动攻击，但攻击者同样可能使用一系列 IP 探测、端口扫描和漏洞扫描来缩小潜在受害者名单。然而，入侵者很有可能会针对整个网络运行漏洞扫描器，以探测任何可被利用的弱点。

再次强调，只需将操作系统更新至最新的安全补丁级别，即可修复漏洞扫描器报告的几乎所有弱点。此外，明智的系统管理员会学会像敌人一样思考——他们下载并针对自己的网络运行这些漏洞扫描器（在获得高层管理许可的情况下），以查看潜在攻击者可能会发现哪些安全漏洞。这使他们能够迅速将资源集中在加固网络中最薄弱的环节上。

### 伪装攻击

获取您原本无权使用的资源的最简单方法之一，是冒充拥有适当访问权限的人。在现实世界中，青少年经常借用年长兄弟姐妹的驾照购买酒精，计算机安全领域也会发生同类事情。攻击者借用合法用户和系统的身份来获取第三方的信任。在以下章节中，我们将介绍两种常见的伪装攻击——IP 欺骗和会话劫持。

#### IP 欺骗

在 **IP 欺骗攻击** 中，恶意人员只需重新配置其系统，使其拥有受信任系统的 IP 地址，然后尝试访问其他外部资源。在许多未安装足够过滤器以防止此类流量的网络上，这出奇地有效。系统管理员应在每个网络的边界配置过滤器，以确保数据包至少满足以下标准：

*   具有内部源 IP 地址的数据包不从外部进入网络。
*   具有外部源 IP 地址的数据包不从内部离开网络。
*   具有私有 IP 地址的数据包不向任何方向通过路由器（除非作为内部网配置的一部分被特别允许）。

这三条简单的过滤规则可以消除绝大多数 IP 欺骗攻击，并极大地增强网络安全。

#### 会话劫持

当恶意人员拦截授权用户与资源之间通信的一部分，然后使用劫持技术接管会话并假冒授权用户身份时，就会发生会话劫持攻击。以下列表包含一些常见技术：

*   捕获客户端与服务器之间认证的详细信息，并使用这些详细信息假冒客户端身份
*   诱骗客户端误以为攻击者的系统是服务器，在客户端与服务器建立合法连接时充当中间人，然后断开客户端的连接
*   使用未正确关闭连接的用户的 Cookie 数据访问 Web 应用程序

所有这些技术都可能给最终用户带来灾难性后果，必须通过管理控制（如防重放认证技术）和应用程序控制（如在合理时间内使 Cookie 过期）来加以解决。

### 概要

应用程序开发人员有很多操心的事！随着黑客工具和技术日益复杂，应用层因其复杂性和多个脆弱点，正日益成为攻击的焦点。

恶意代码（包括病毒、蠕虫、特洛伊木马和逻辑炸弹）利用应用程序和操作系统中的漏洞，或利用社会工程学感染系统，并获取其资源和机密信息的访问权。

应用程序本身也可能包含许多漏洞。缓冲区溢出攻击利用缺乏适当输入验证的代码来影响系统内存的内容。后门为前开发人员和恶意代码作者提供了绕过正常安全机制的能力。Rootkit 为攻击者提供了一种简便的方式来实施提权攻击。

许多应用程序正在转向 Web，这创造了新的暴露和脆弱性层面。跨站脚本攻击允许黑客诱骗用户向不安全的网站提供敏感信息。SQL 注入攻击允许绕过应用程序控制，直接访问和操纵底层数据库。

侦察工具为攻击者提供了自动化工具，可用于识别稍后可能被攻击的脆弱系统。IP 探测、端口扫描和漏洞扫描都是检测组织安全控制薄弱点的自动化方法。伪装攻击使用隐蔽技术，允许冒充用户和系统。

### 考试要点

**理解病毒使用的传播技术。** 病毒使用四种主要传播技术——文件感染、服务注入、引导扇区感染和宏感染——来渗透系统并传播其恶意载荷。你需要理解这些技术，以有效保护网络上的系统免受恶意代码侵害。

**了解杀毒软件包如何检测已知病毒。** 大多数杀毒程序使用基于特征码的检测算法来查找已知病毒的明显模式。这使得定期更新病毒定义文件以维持对新出现病毒的防护变得至关重要。基于行为的检测也越来越普遍，杀毒软件监控目标系统的异常活动，并将其阻止或标记以供调查，即使该软件不匹配已知的恶意软件特征码。

**解释攻击者用于破坏密码安全的技术。** 密码是当今最常用的访问控制机制，理解如何防范试图破坏其安全性的攻击者至关重要。了解密码破解工具、字典攻击和社会工程学攻击（如网络钓鱼）如何被用来击败密码安全。

**熟悉攻击者用于利用编写糟糕的软件的各种应用程序攻击类型。** 应用程序攻击是现代计算面临的最大威胁之一。攻击者利用缓冲区溢出、后门、检查时间到使用时间 (TOCTOU) 漏洞和 Rootkit 来获取对系统的非法访问。安全专业人员必须清楚地了解这些攻击中的每一种及相关的对策。

**理解常见的 Web 应用程序漏洞和对策。** 随着许多应用程序转移到 Web，开发人员和安全专业人员必须了解此环境中存在的新型攻击以及如何防范它们。最常见的两个例子是跨站脚本 (XSS) 和 SQL 注入攻击。

**了解攻击者在准备攻击网络时使用的网络侦察技术。** 在发起攻击前，攻击者使用 IP 扫描搜寻网络上的活动主机。然后对这些主机进行端口扫描和其他漏洞探测，以定位可能被攻击以破坏网络的薄弱点。你应该了解这些攻击，以帮助保护你的网络免受其害，限制攻击者可能获取的信息量。
