
where `q[j]^(c)` is the centroid of the `j`th cluster and the matrix `S ∈ {0,1}^(L×C)` partitions the query vectors into `C` non-overlapping clusters, so if `S[i,j] = 1`, then `q[i]` is in cluster `j`. The centroid queries are grouped into `Q^(c) ∈ ℝ^(C×d_k)`, the matrix of centroid vectors. We can then substitute the real query matrix with the query centroid matrix, `Q^(c)`, and compute the clustered attention matrix:

$$
\begin{array}{l}
{\mathbf{A}^{c} = \text{softmax}\left( \frac{\mathbf{Q}^{\text{c}}\mathbf{K}^{\text{T}}}{\sqrt{\text{d}_{\text{k}}}} \right), \in {\mathbb{R}}^{\text{C} \times \text{L}}} \\
\end{array}
$$

(5.67)

You can stop here and just use the clustered attention weights to compute the output of the attention mechanism. This calculation has time complexity of `O(CL·d_k + LC·d_v)`, which is explicitly linear in the sequence length. But, the clustered attention approximation can be improved finding `k` keys that have the highest attention score within each of the `C` clusters. And, for each of the top-`k` keys for a cluster, compute the attention with the queries in that cluster:

$$
\begin{array}{ll}
A_{il}^{t} &=
\begin{array}{ll}
\left\{ \frac{\hat{m}_{j}\exp(\mathbf{q}_{i}\mathbf{k}_{l}^{T})}{\sum\limits_{r=1}^{L}T_{jr}\exp(\mathbf{q}_{i}\mathbf{k}_{r}^{T})}, \right. & \text{if } T_{jl} = 1 \\
A_{jl}^{c}, & \text{otherwise}
\end{array}
\end{array}
$$

(5.68)

where `m̂_j = ∑_{i=1}^{L} T[i,j] A[i,j]^c` and `T ∈ {0,1}^(C×L)`: if `T[i,j] = 1`, then `k[i]` is one of the top-`k` keys for cluster `j`.

Then compute the context vectors (weighted average of the values) of the clustered attention and use it as the value matrix: `V̂ = A^(t)V ∈ ℝ^(L×d_v)`. This makes the complexity of the clustered attention calculation to `O(CL·d_k + LC·d_v + kL·max(d_k, d_v))`, which is linear in the sequence length.

**Performance** Clustered attention outperforms standard transformer and Reformer on automatic speech recognition with WSJ and Switchboard audio datasets. It also approximates pre-trained RoBERTa on GLUE and SQuAD, with minute performance loss. It performs better on GLUE that RoBERTa, but not SQuAD, where it is slightly worse.

As number of clusters increases, the approximation becomes more accurate. It converges up to twice as fast as the standard transformer, for long sequence lengths and, for short sequence lengths, clustered attention is *not* faster than the standard transformer.

### 5.2.6 Compressed Key-Value Memory

#### 5.2.6.1 Luna: Linear Unified Nested Attention

Luna [177], which stands for Linear Unified Nested Attention, replaces the attention weight computation in each attention head with two nested linear attention computations using an extra, learnable, input sequence that learns to encode contextual information: `P ∈ ℝ^(l×d)`, where `l` is the length of the sequence.

As discussed earlier, the output of an attention head between a query sequence, `X ∈ ℝ^(n×d)`, and a context sequence, `C ∈ ℝ^(m×d)`, can be written as

$$
\begin{array}{l}
{\mathbf{Y} = Attn(\mathbf{X},\mathbf{C}) = \text{softmax}\left( \frac{\mathbf{X}\mathbf{W}_{\text{q}}{(\mathbf{C}\mathbf{W}_{\text{k}})}^{\text{T}}}{\sqrt{\text{d}_{\text{k}}\text{/h}}} \right)\mathbf{CV}, \in {\mathbb{R}}^{\text{n} \times \text{d}}} \\
\end{array}
$$

(5.69)

where `W[q]`, `W[k]`, `W[v]` are the linear projections that project an input sequence into the query, key, and value spaces, respectively, as in (5.24).

Training begins with the generator chooses a random set of `k` positions, `m = (m[1], …, m[k])`, from the input sequence, such that each position `m[i]`, with `i = 1, …, k`, is drawn uniformly from `[1, L]`, where `L` is the sequence length. Each token in the input sequence `x = (x[1], …, x[L])` that is at the positions in `m` will be replaced with the `[MASK]` token. The masked sequence is

$$
\begin{array}{l}
{\mathbf{x}^{\text{masked}} = \text{REPLACE}(\mathbf{x},\mathbf{m},\lbrack MASK\rbrack)} \\
\end{array}
$$

(5.71)

The generator then learns the unmasked versions of the masked tokens in `x`. The probability that the generator outputs a particular token `x[t]` is

$$
\begin{array}{l}
{Prob_{G}(x_{t}|\mathbf{x}) = \frac{\exp({\mathbf{e}_{t}^{T}\mathbf{h}_{G}{(\mathbf{x})}_{t})}}{{\sum\limits_{t^{\prime}}{\exp}}({\mathbf{e}{(x^{\prime})}^{T}\mathbf{h}_{G}{(\mathbf{x})}_{t}})},} \\
\end{array}
$$

(5.72)

where `e[t]` is the embedding vector for the token `x[t]`.
