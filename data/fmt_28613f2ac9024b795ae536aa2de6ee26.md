
# 安全实时传输协议

**安全实时传输协议** 是实时传输协议的安全版本，后者是一种旨在通过网络提供音频和视频流的协议。SRTP 使用加密和身份验证，试图降低成功攻击的可能性，包括重放攻击和拒绝服务攻击尝试。RTP 使用成对的协议，即 RTP 和 RTCP。RTCP 是控制协议，用于监控服务质量和流同步，RTCP 也有一个安全的对应版本，即 SRTP。

# 安全轻量级目录访问协议

**安全轻量级目录访问协议** 是受 TLS 保护的 LDAP 版本，提供机密性和完整性保护。

## 电子邮件相关协议

尽管许多组织已转向基于 Web 的电子邮件，但邮局协议 (POP) 和互联网消息访问协议 (IMAP) 等电子邮件协议仍在邮件客户端中使用。为两者实现 TLS 作为保护层的安全协议选项均已存在，从而催生了 **POPS** 和 **IMAPS** 的部署。

**安全/多用途互联网邮件扩展** 提供了加密和签名 MIME 数据的能力，MIME 是用于电子邮件附件的格式。因此，电子邮件的内容和附件可以受到保护，同时为使用 S/MIME 发送的消息提供身份验证、完整性、不可抵赖性和机密性。

与此处讨论的许多其他协议不同，S/MIME 要求用户拥有证书，才能发送和接收受 S/MIME 保护的消息。需要本地生成的证书或来自公共证书颁发机构 (CA) 的证书。这一要求增加了想要与其他个人安全通信的 S/MIME 用户的复杂性，因为证书管理和验证可能变得复杂。因此，尽管许多电子邮件提供商和工具广泛支持，S/MIME 的使用频率较低。

当然，相当一部分电子邮件是通过 Web 访问的，这实际上使 HTTPS 成为电子邮件访问最常用的安全协议。

## 文件传输协议

尽管通过 FTP 进行文件传输越来越少见，但 FTP 的安全版本确实存在且仍在使用。主要有两种选择：**FTPS**，它使用 TLS 实现 FTP；以及 **SFTP**，它利用 SSH 作为通道来执行类似 FTP 的文件传输。SFTP 经常被选用，因为它更容易穿越防火墙，因为它仅使用 SSH 端口，而 FTPS 可能需要额外的端口，具体取决于配置。

## IPSec

IPSec (Internet Protocol Security，互联网协议安全) 不仅仅是单一协议。事实上，IPSec 是一整套用于加密和认证 IP 流量的安全协议套件。Security+ 考试大纲重点关注该标准的两个组件：

*   **认证头** 使用哈希和共享密钥来确保数据完整性，并通过认证发送的 IP 数据包来验证发送者。AH 可确保 IP 负载和头部受到保护。
*   **封装安全载荷** 在传输模式或隧道模式下运行。在隧道模式下，它为整个数据包提供完整性和认证；在传输模式下，它仅保护数据包的负载。如果 ESP 与认证头一起使用，可能会给需要更改 IP 或端口信息的网络带来问题。

IPSec 经常用于 VPN，在隧道模式下用于在两个位置之间创建安全的网络连接。

# 攻击与评估网络

Security+ 考试要求你熟悉一些网络攻击技术和概念。在复习这些内容时，请思考在发现它们的场景中，你将如何识别、预防和响应它们。

## 中间人攻击

**中间人** 攻击（有时也称为中间人攻击 [MitM]）发生在攻击者导致本应发送给预期接收者的流量，通过攻击者控制的系统或设备进行中转时。一旦攻击者让流量流经该系统，他们就可以窃听，甚至随意篡改通信。图 12.2 显示了中间人攻击成功后，流量流向如何从正常状态发生改变。

![图 12.2 中间人攻击前后的通信](img/c12f002.png)

**图 12.2** 中间人攻击前后的通信

中间人攻击可用于实施 **SSL 剥离**，这是一种在现代实现中移除 TLS 加密、以读取本应发送给可信端点的流量内容的攻击。典型的 SSL 剥离攻击分三个阶段发生：

1.  用户发送网页的 HTTP 请求。
2.  服务器响应重定向到该页面的 HTTPS 版本。
3.  用户发送重定向页面的 HTTPS 请求，网站随之加载。

SSL 剥离攻击在 HTTP 请求发生时利用中间人攻击，将后续通信重定向通过攻击者控制的系统，从而允许读取或可能修改通信。虽然 SSL 剥离攻击可在任何网络上实施，但最常见的实现方式之一是通过开放无线网络，攻击者可控制无线基础设施，从而修改通过其接入点和网络连接的流量。

最后一种中间人攻击变体是基于浏览器的攻击（以前称为 **中间人浏览器** MitB 或 MiB）。这种攻击依赖于植入用户浏览器的木马。该木马随后能够访问和修改浏览器发送和接收的信息。由于浏览器接收并解密信息，基于浏览器的中间人攻击可以成功绕过 TLS 加密和其他浏览器安全功能，还可以访问具有打开会话的站点或浏览器已认证的站点，这使得 MitB 攻击成为攻击者的一个非常强大的选项。由于基于浏览器的中间人攻击需要安装木马，无论是作为浏览器插件还是代理，系统级安全防御（如反恶意软件工具、系统配置管理和监控功能）最适合防范此类攻击。

## 域名系统攻击

剥离加密并不是唯一能让恶意行为者窥探你流量的网络攻击类型。事实上，如果他们能控制流量发送到的系统，那就简单多了！这就是 DNS 攻击发挥作用的地方。Security+ 考试大纲重点关注三种类型的 DNS 和域相关攻击，以及一个关键的安全和监控工具。

### 域名劫持

**域名劫持** 会更改域名的注册信息，既可能通过技术手段（如域名注册商的漏洞或对授权用户所属系统的控制），也可能通过非技术手段（如社会工程学）实施。域名劫持的最终结果是攻击者可以更改域名的设置和配置，从而拦截流量、收发电子邮件，或在冒充合法域名持有者的情况下采取其他行动。域名劫持并非获取域名用于恶意目的的唯一途径。事实上，许多域名最终落入非预期所有者手中，是因为它们未被妥善续费。如果你只是域名系统和服务的用户，检测域名劫持可能比较困难，但域名所有者可以利用域名注册商提供的安全工具和功能来保护和监控其域名。

### DNS 投毒

**DNS 投毒** 可通过多种方式实现。其中一种形式是旁路攻击的另一种变体，攻击者冒充权威 DNS 服务器提供 DNS 响应。DNS 协议或实现中的漏洞也可能允许 DNS 投毒，但这类情况较为罕见。DNS 投毒还可能涉及对系统上 DNS 缓存的投毒。一旦恶意 DNS 条目进入系统缓存，系统将继续使用该信息，直到缓存被清除或更新。这意味着即使入侵防御系统（IPS）或其他安全设备发现并阻止了攻击，DNS 投毒仍可能产生长期影响。DNS 缓存投毒可能被用户注意到，或被入侵检测系统（IDS）或 IPS 等网络防御设备检测到，但如果实施得当，则很难被发现。

### URL 重定向

当域名劫持不可行且 DNS 无法被投毒时，攻击者的另一个选择是 **URL 重定向**。URL 重定向可呈现多种形式，具体取决于攻击者利用的漏洞，但最常见的一种是将备用 IP 地址插入系统的 `hosts` 文件中。当系统通过 DNS 查找站点时，会首先检查 `hosts` 文件，这使得被修改的 `hosts` 文件成为能够更改它的攻击者的有力工具。修改后的 `hosts` 文件可手动检查，也可由了解 `hosts` 文件是常见攻击目标的系统安全反恶意软件工具进行监控。在大多数组织中，大多数机器的 `hosts` 文件永远不会从其默认状态被修改，这使得变更易于被发现。

### 域名信誉

尽管 DNS 攻击可为恶意行为者提供攻击组织的途径，但你也可以利用 DNS 相关信息来帮助防御攻击。**域名信誉** 服务和工具提供关于域名是否为受信任的电子邮件发送者或是否发送大量垃圾邮件的信息。此外，个别组织可能会使用自己的电子邮件安全和反垃圾邮件工具，为电子邮件发送者分配域名信誉评分。

## 第 2 层攻击

攻击数据链路层对于拥有网络访问权限的攻击者来说是一种有效技术。与高层攻击不同，这些攻击需要对网络或网络上的系统具有本地访问权限，因为第 2 层流量受本地广播域的限制。

Security+ 考试大纲列出了三种你需要了解并可能需要识别的特定第 2 层攻击：

*   **地址解析协议 (ARP) 投毒** 攻击向网络的默认网关发送恶意 ARP 数据包，意图更改网关维护的 MAC 地址到 IP 地址的映射关系。攻击者会发送 ARP 回复，声称目标机器的 IP 地址与其 MAC 地址关联，导致系统和网关将发往目标系统的流量发送到攻击者的系统。攻击者可利用此方法通过中继流量到目标系统来实施旁路攻击，或直接收集和使用接收到的流量。ARP 投毒还可通过导致流量无法到达预期系统来制造拒绝服务。ARP 投毒可通过 Wireshark 等工具以及执行协议分析和网络监控的专用网络安全设备进行检测。
*   **媒体访问控制 (MAC) 泛洪** 通过向交换机发送大量 MAC 地址，填满存储端口与 MAC 地址映射关系的 CAM 表或 MAC 表。由于这些表空间有限，泛洪会导致默认行为：当目标未知时，将流量发送到所有端口以确保流量继续流动。攻击者随后可捕获该流量供己用。可通过使用端口安全来防止 MAC 泛洪，这会限制预期由工作站或设备使用的端口可学习的 MAC 地址数量。此外，NAC 或其他网络认证授权工具可将 MAC 地址与已知或已认证的系统进行匹配。
*   **MAC 克隆** 复制设备的媒体访问控制地址（硬件地址）。Linux `macchanger` 和 `iproute2` 等工具允许手动更改系统的 MAC 地址。攻击者可能选择这样做以绕过 MAC 地址受限的网络，或获取受 MAC 地址限制的访问权限。如果没有来自网络设备以外来源的系统额外信息，MAC 克隆很难被检测到。网络准入控制 (NAC) 功能或其他机器认证和验证技术有助于识别呈现克隆或伪造 MAC 地址的系统。

这些并非第 2 层唯一可实施的攻击。尽管 Security+ 考试不包含这些内容，但修改网络流量逻辑结构的生成树协议攻击、VLAN 跳跃和中继攻击以及 DHCP 欺骗也发生在第 2 层。

## 分布式拒绝服务攻击

安全专业人员需要知道如何检测和识别分布式拒绝服务 (DDoS) 攻击。分布式拒绝服务攻击从多个位置、网络或系统发起，这使其难以阻止且难以检测。同时，DDoS 的分布式特性意味着它可能对目标系统或网络投入大量资源，通过其规模之大潜在地压垮目标。

### 网络 DDoS

分布式拒绝服务攻击最常见的形式之一是基于网络的 DDoS。恶意行为者通常利用大规模僵尸网络实施网络 DDoS 攻击，且存在提供 DDoS 攻击和类 DDoS 行为的商业服务，用于压力和负载测试。所有这些意味着组织需要制定计划来检测和处理网络 DDoS 攻击。

在许多情况下，组织的互联网服务提供商 (ISP) 可能会提供 DDoS 防护服务，无论是默认提供还是作为额外的订阅选项。了解 ISP 是否提供该功能以及在何种情况下会激活或可开启该功能，可能是组织的一项关键网络防御措施。如果 ISP 不提供 DDoS 防护，第二个选择是确保网络边界安全设备具备 DDoS 防护能力。

#### 网络 DDoS 攻击与侦察工具

##### 常见的网络 DDoS 攻击类型

网络分布式拒绝服务攻击可分为两大类：基于流量的攻击和基于协议的攻击。

###### 基于流量的网络 DDoS 攻击

基于流量的网络 DDoS 攻击侧重于海量流量导致拒绝服务状况。某些基于流量的 DDoS 攻击依赖放大技术，利用协议和服务中的缺陷或特性，产生比攻击者发送的流量大得多的流量。基于流量的攻击示例包括 UDP 和 ICMP 洪水攻击：

*   **UDP 洪水攻击**利用了 UDP 不像 TCP 那样使用三次握手这一事实，因此只需发送大量流量，目标主机就会接收并尝试处理，从而执行 UDP 洪水攻击。由于 UDP 不受速率限制或其他保护，且不使用握手，因此攻击系统只需极少资源即可发动 UDP 洪水攻击。可使用具有 UDP 洪水检测规则或模块的 `IDSs` 和 `IPSs` 及其他网络防御设备来检测 UDP 洪水攻击。作为响应过程的一部分，可使用数据包分析器手动检测洪水攻击，但对实时攻击进行手动分析可能具有挑战性，且未必及时。
*   **ICMP 洪水攻击**（有时称为 ping 洪水攻击）发送大量 ICMP 数据包，每个数据包都请求响应。与 UDP 不同，许多现代操作系统对 ICMP 进行了速率限制。ICMP 洪水攻击要求攻击方拥有比防御方更多的总带宽，这也是为什么可能会尝试通过 ICMP 发动分布式拒绝服务攻击。许多组织在网络入口处对 ping 进行速率限制或阻断，以防止此类攻击，它们也可能对安全区域之间的 ICMP 进行速率限制。与 UDP 洪水攻击非常相似，网络安全设备上的检测规则以及手动检测均可使用，但主动防御相对容易且部署非常普遍，尽管如果触及速率限制，可能会丢失一些 ICMP 流量。

###### 基于协议的网络 DDoS 攻击

基于协议的网络 DDoS 攻击侧重于网络所用的底层协议。

*   **SYN 洪水攻击**发送三次握手的第一步，但不响应返回的 `SYN-ACK`，从而耗尽 TCP 栈资源。这些攻击是最常见的现代基于协议的网络 DDoS 攻击之一。
*   **早期攻击**针对脆弱的 TCP 栈，采用如**死亡之 Ping** 等攻击，发送过大的 ping 数据包导致许多系统无法处理；以及 **Smurf 攻击**，利用带有伪造发送者地址的 ICMP 广播消息，导致广播域内的系统向所谓的发送者发送流量，从而将其淹没。
*   **分片数据包**、所有 TCP 标志位均置 1 的数据包（**Christmas Tree** 或 **Xmas 攻击**），以及各种其他攻击，均利用了操作系统中网络实现的缺陷和局限性。

安全专业人员需知晓，网络协议的特性及这些协议的具体实现可能被用作攻击的一部分，并且他们可能需要识别这些攻击。

图 12.4 显示了在 `Wireshark` 中开启适当过滤器后看到的 SYN 洪水攻击。识别 SYN DDoS 通常意味着查看针对目标主机的流量，并注意到有大量 `SYN` 数据包被发送，但请求方未完成握手的其余部分。请注意，在该图中，单个系统正在发送 SYN 洪水；在真实的 DDoS 中，会显示多个系统作为流量来源。需要按目标系统进行过滤，并确保三次握手未完成，以验证 DDoS 攻击。

### 运营技术 DDoS

**运营技术 (OT)** 是控制建筑、工厂、发电厂及其他行业中设备和系统的软件和硬件。**物联网 (IoT)** 的增长导致更多设备具备网络功能，从而产生了一整套可通过网络攻击的新设备。由于 IoT 设备通常缺乏计算机和网络设备所具备的安全防护，且可用的处理器、内存和存储可能更有限，因此它们比网络上的其他设备更容易受到基于网络的 DDoS 攻击。

尽管 OT DDoS 攻击在 **Security+** 考试大纲中被列为一个独立主题，但大多数运营技术攻击将依赖我们已讨论的相同类型的网络和基于应用程序的 DDoS 攻击。安全从业者需牢记的一个关键要素是：OT 通常具有较少的报告、较少的管理和较少的内置安全功能，这意味着针对 OT 设备和系统的网络 DDoS 和其他攻击的检测与响应，将需要使用外部设备和工具来处理。

在没有额外安全工具的情况下，检测针对 OT 设备或网络的攻击，通常意味着注意到其无响应或似乎已从网络掉线。进一步调查可能会显示设备已崩溃，或虽在线但因不堪重负而不响应网络流量。此时，可启动传统的事件响应和网络事件调查技术。

由于 OT 和 IoT 设备总体上对潜在敌对网络的准备仍不足，设计和架构规划可能是保障其安全的关键控制措施。使用隔离的 `VLAN`、限制网络流量的入站和出站、防止未知设备添加到隔离的 `VLAN`、以及对这些网络进行监控检测，均是防止各类 OT 网络攻击的有用技术。

### 路由、DNS 信息和路径

当你想确定系统是否在线以及发送到该系统的流量延迟时，最简单的工具是 `ping`。`ping` 向目标主机发送 `ICMP` 回显请求数据包，并计算最小、最大和平均往返时间。正如你所料，你可以使用命令行标志来确定发送多少个 ping、载荷大小以及各种其他设置。最有用的标志之一是 `-t` 标志，它会持续发送 ping 直到被停止。运行 `ping -t` 可以显示系统是否突然停止响应，或系统的响应时间是否大幅波动。

了解系统在互联网上的逻辑位置，以及流量从该系统到其他系统将采取的路由，在你试图了解网络拓扑或进行故障排除时也非常有用。Windows 和基于 Linux/Unix 的系统都包含运行路由跟踪命令的功能，该命令将尝试验证系统之间的路由。
