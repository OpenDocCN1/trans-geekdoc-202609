在评估上述各因素后，安全团队设计并验证一套全面的评估和测试策略。该策略可能包括频繁的自动化测试，辅以不频繁的手动测试。例如，信用卡处理系统可能会每晚进行自动化漏洞扫描，当扫描检测到新漏洞时立即向管理员发出警报。自动化扫描一旦配置完成，无需管理员投入工作，因此很容易非常频繁地运行。安全团队可能希望用外部顾问执行的手动渗透测试来补充这些自动化扫描，但这需要支付高额费用。为将成本和对业务的干扰降至最低，此类测试可能每年进行一次。

当然，仅执行安全测试是远远不够的。安全专业人员还必须仔细审查这些测试的结果，以确保每项测试都成功完成。在某些情况下，这些审查包括手动阅读测试输出并验证测试是否成功完成。一些测试需要人工解读，必须由受过培训的分析师执行。

其他审查可能是自动化的，由安全测试工具执行，这些工具验证测试的成功完成、记录结果，除非有重大发现否则保持静默。当系统检测到需要管理员关注的问题时，根据警报的严重程度和管理员的偏好，可能会触发警报、发送电子邮件或短信，或自动打开一个故障单。

## 安全评估

**安全评估** 是对系统、应用程序或其他受测环境安全性的全面审查。在安全评估期间，受过培训的信息安全专业人员执行风险评估，识别受测环境中可能导致妥协的漏洞，并根据需要提出补救建议。

安全评估通常包括使用安全测试工具，但不局限于自动化扫描和手动渗透测试。它们还包括对威胁环境、当前和未来风险以及目标环境价值的深思熟虑的审查。

安全评估的主要工作成果通常是一份致管理层的评估报告，其中包含用非技术语言编写的评估结果，并以改进受测环境安全性的具体建议作为结语。

评估可由内部团队进行，也可外包给在受评估领域具有特定专业知识的第三方评估团队。

## 安全审计

**安全审计** 使用许多与安全评估期间相同的技术，但必须由独立审计员执行。虽然组织的安全人员可能会定期执行安全测试和评估，但审计则不然。评估和测试结果仅供内部使用，旨在评估控制项以发现潜在改进。另一方面，审计是为了向第三方证明控制项有效性而进行的评估。为组织设计、实施和监控控制项的员工在评估这些控制项的有效性时存在固有的利益冲突。

审计员提供对安全控制状态公正、无偏见的看法。他们撰写的报告与安全评估报告非常相似，但这些报告面向不同的受众，可能包括组织的董事会、政府监管机构和其他第三方。主要有三种类型的审计：内部审计、外部审计和第三方审计。

### 内部审计

**内部审计** 由组织的内部审计人员执行，通常面向内部受众。执行这些审计的内部审计人员通常拥有完全独立于其评估职能的汇报线。在许多组织中，首席审计执行官直接向总裁、首席执行官或类似角色汇报。首席审计执行官也可能直接向组织的治理董事会负有汇报责任。

### 外部审计

**外部审计** 由外部审计公司执行。这些审计具有高度的外部效度，因为执行评估的审计员理论上与组织本身不存在利益冲突。有数千家公司执行外部审计，但大多数人对所谓的“四大”审计公司给予最高的信誉：

*   安永
*   德勤
*   普华永道
*   毕马威

由这些公司执行的审计通常被大多数投资者和治理机构成员所接受。

### 第三方审计

**第三方审计** 由另一组织执行或代表另一组织执行。例如，监管机构可能有权根据合同或法律发起对受监管公司的审计。在第三方审计的情况下，发起审计的组织通常选择审计员并设计审计范围。

向其他组织提供服务的组织经常被要求参与第三方审计。如果拥有大量客户，这对被审计组织来说可能是相当大的负担。美国注册会计师协会（AICPA）发布了一项旨在减轻这一负担的标准。《鉴证业务准则声明第 16 号》（**SSAE 16**），即《控制报告》，提供了一项通用标准，供审计员在评估服务组织时使用，旨在允许组织进行一次外部评估，而非多次第三方评估，然后将生成的报告与客户和潜在客户共享。

SSAE 16 业务产出两种不同类型的报告。

*   **I 型报告** 提供对被审计组织所提供控制项的描述，以及审计员基于该描述发表的意见。I 型审计涵盖单一时间点，不涉及审计员对控制项的实际测试。
*   **II 型报告** 涵盖至少六个月的时间段，还包括审计员基于其实际执行的测试，对这些控制项有效性发表的意见。

II 型报告被认为比 I 型报告可靠得多，因为它们包含对控制项的独立测试。I 型报告仅根据服务组织的陈述，认为控制项按描述实施。

信息安全专业人员经常被要求参与内部、外部和第三方审计。他们通常必须通过面谈和书面文档向审计员提供有关安全控制的信息。审计员还可能要求安全人员参与控制评估的执行。审计员通常拥有访问组织内所有信息的完全权限，安全人员应遵守这些要求，并在需要时咨询管理层。

## 审计与评估标准

在进行审计或评估时，执行审查的团队应明确他们用于评估组织的标准。该标准提供了应满足的控制目标描述，随后审计或评估旨在确保组织已正确实施控制以满足这些目标。

用于进行审计和评估的一个常见框架是*信息及相关技术控制目标*。COBIT 描述了组织在其信息系统周围应建立的通用要求。

国际标准化组织 (ISO) 还发布了一套与信息安全相关的标准。`ISO 27001` 描述了建立信息安全管理体系的标准方法，而 `ISO 27002` 则更详细地阐述了信息安全控制的具体细节。这些国际公认的标准在安全领域被广泛使用，组织可以选择正式认证为符合 `ISO 27001`。

## 执行漏洞评估

漏洞评估是信息安全专业人员工具箱中最重要的测试工具之一。漏洞扫描和渗透测试为安全专业人员提供了关于系统或应用程序技术控制中弱点的视角。

### 描述漏洞

安全社区依赖一套通用标准，为描述和评估漏洞提供通用语言。NIST 为社区提供了*安全内容自动化协议* 以满足这一需求。SCAP 提供了这一通用讨论框架，并促进了不同安全系统之间交互的自动化。SCAP 的组件包括以下内容：

*   *通用漏洞披露* 提供了一套描述安全漏洞的命名系统。
*   *通用漏洞评分系统* 提供了一套描述安全漏洞严重程度的标准化评分系统。
*   *通用配置枚举* 提供了一套描述系统配置问题的命名系统。
*   *通用平台枚举* 提供了一套描述操作系统、应用程序和设备的命名系统。
*   *可扩展配置清单描述格式* 提供了一种指定安全清单的语言。
*   *开放漏洞与评估语言* 提供了一种描述安全测试过程的语言。

### 漏洞扫描

*漏洞扫描* 会自动探测系统、应用程序和网络，寻找攻击者可能利用的弱点。这些测试中使用的扫描工具提供快速的“点击式”测试，无需人工干预即可执行原本繁琐的任务。大多数工具允许按周期安排定期扫描，并提供报告显示不同日期执行的扫描之间的差异，为管理员提供了了解其安全风险环境变化的视角。

漏洞扫描主要有四大类：网络发现扫描、网络漏洞扫描、Web 应用程序漏洞扫描和数据库漏洞扫描。各种各样的工具可执行这些类型的扫描。

#### 网络发现扫描

网络发现扫描使用多种技术扫描一系列 IP 地址，搜索具有开放网络端口的系统。网络发现扫描器实际上并不探测系统的漏洞，而是提供一份报告，显示网络上检测到的系统以及网络和服务器防火墙（位于扫描器与被扫描系统之间的网络路径上）所暴露的端口列表。

网络发现扫描器使用许多不同的技术来识别远程系统上的开放端口。一些较常见的技术如下：

**TCP SYN 扫描** 向每个被扫描端口发送一个设置了 SYN 标志的单个数据包。这表示请求打开一个新连接。如果扫描器收到的响应同时设置了 SYN 和 ACK 标志，则表明系统正在进入三次 TCP 握手的第二阶段，且该端口是开放的。TCP SYN 扫描也称为“半开放”扫描。

**TCP Connect 扫描** 在指定端口上与远程系统建立完整连接。当运行扫描的用户没有运行半开放扫描所需的权限时，会使用此扫描类型。大多数其他扫描类型都需要发送原始数据包的能力，而用户可能会受到操作系统限制而无法发送手工制作的数据包。

**TCP ACK 扫描** 发送一个设置了 ACK 标志的数据包，表明它是开放连接的一部分。此类扫描可能旨在确定防火墙强制执行的规则和防火墙方法。

**Xmas 扫描** 发送一个同时设置了 FIN、PSH 和 URG 标志的数据包。设置了如此多标志的数据包被称为“像圣诞树一样亮起来”，因此得名。

用于网络发现扫描的最常用工具是一个名为 `nmap` 的开源工具。`nmap` 最初于 1997 年发布，令人惊讶的是它至今仍在维护并普遍使用。它仍然是最流行的网络安全工具之一，几乎每个安全专业人员要么定期使用 `nmap`，要么在其职业生涯的某个阶段使用过它。您可以在 <http://nmap.org> 下载 `nmap` 的免费副本或了解更多关于该工具的信息。

当 `nmap` 扫描系统时，它会识别系统上每个网络端口的当前状态。对于检测到结果的端口，它会提供该端口的当前状态：

**开放** 该端口在远程系统上是开放的，且有应用程序正在该端口上主动接受连接。

**关闭** 该端口在远程系统上是可访问的，意味着防火墙允许访问，但没有应用程序在该端口上接受连接。

**被过滤** 由于防火墙干扰了连接尝试，`nmap` 无法确定端口是开放还是关闭。

图 15.1 展示了 `nmap` 运行的示例。用户在 Linux 提示符下输入了以下命令：

```
nmap –vv 52.4.85.159
```

`nmap` 软件随即开始对 IP 地址为 `52.4.85.159` 的系统进行端口扫描。命令中指定的 `–vv` 标志只是告诉 `nmap` 使用详细模式，报告其结果的详细输出。图 15.1 底部附近出现的扫描结果表明，`nmap` 在该系统上发现了三个活动端口：`22`、`80` 和 `443`。端口 `22` 和 `80` 是开放的，表明系统正在主动接受这些端口上的连接请求。端口 `443` 是关闭的，意味着防火墙包含允许该端口连接尝试的规则，但系统未运行配置为接受这些连接的应用程序。

要解读这些结果，您必须了解常见网络端口的用途，这在第 12 章“安全通信与网络攻击”中已讨论过。让我们演练一下此 `nmap` 扫描的结果：

*   端口列表的第一行 `22/tcp open ssh` 表明系统接受 TCP 端口 `22` 上的连接。安全外壳 (SSH) 服务使用此端口允许对服务器进行管理连接。
*   端口列表的第二行 `80/tcp open http` 表明系统正在接受端口 `80` 上的连接请求，该端口由超文本传输协议 (HTTP) 用于传送网页。
*   端口列表的最后一行 `443/tcp closed https` 表明存在一条防火墙规则允许访问 443 端口，但没有服务在该端口上监听。443 端口由超文本传输安全协议（HTTPS）用于接受加密的 Web 服务器连接。

从这些结果中我们能学到什么？被扫描的系统很可能是一台 Web 服务器，它公开接受来自扫描系统的连接请求。扫描器与该系统之间的防火墙配置为允许安全（443 端口）和不安全（80 端口）连接，但服务器并未设置为实际执行加密事务。该服务器还开放了一个管理端口，可能允许命令行连接。

阅读这些结果的攻击者可能会对系统做出一些观察，从而进行进一步探测：

*   将 Web 浏览器指向该服务器，很可能会很好地了解服务器的功能及其运营者。只需在浏览器地址栏输入 `http://52.4.85.159` 即可能揭示有用信息。图 15.2 显示了执行此操作的结果：该站点运行的是 Apache Web 服务器的默认安装版本。
*   与该服务器的连接未加密。如果可能，窃听这些连接可能会泄露敏感信息。
*   开放的 SSH 端口是一个有趣的发现。攻击者可能会尝试针对该端口上的管理账户进行暴力破解密码攻击，以获取系统访问权限。

#### 网络漏洞扫描

*网络漏洞扫描* 比发现扫描更深入。它们不仅检测开放端口，还会继续探测目标系统或网络是否存在已知漏洞。这些工具包含数千个已知漏洞的数据库，以及可用于识别系统是否易受数据库中每个漏洞影响的测试。

当扫描器测试系统漏洞时，它使用数据库中的测试来确定系统是否可能包含该漏洞。在某些情况下，扫描器可能没有足够的信息来确定性地判断漏洞是否存在，从而在实际上不存在问题时报告漏洞。这种情况称为*误报*，有时被系统管理员视为麻烦。更危险的是，漏洞扫描器遗漏了漏洞，未能提醒管理员存在危险情况。这种错误称为*漏报*。

默认情况下，网络漏洞扫描器运行未认证扫描。它们在没有密码或其他授予扫描器特殊权限的特殊信息的情况下测试目标系统。这使扫描能够从攻击者的角度运行，但也限制了扫描器全面评估可能漏洞的能力。提高扫描准确性并减少误报和漏报的一种方法是对系统执行*认证扫描*。在这种方法中，扫描器拥有对被扫描服务器的只读访问权限，并可利用此访问权限从目标系统读取配置信息，在分析漏洞测试结果时使用这些信息。
