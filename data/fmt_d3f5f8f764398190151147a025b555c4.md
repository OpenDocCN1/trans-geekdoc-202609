本章讨论了应用安全和渗透测试。应用测试是 IT 安全的重要部分。应用程序与任何其他物品都不同。如果你购买的汽车加速踏板或轮胎有缺陷，供应商通常会维修或更换这些部件。然而，软件大不相同。如果软件有缺陷，供应商可能不再支持它，可能提供补丁，甚至可能付费提供升级。这些只是为什么对应用程序进行安全问题测试如此重要的几个原因之一。

本章的第二部分涵盖了渗透测试。渗透测试通过对网络进行测试来验证安全控制。渗透测试可以作为外部审查、内部审查或两者兼有的方式进行。渗透测试在组织安全中起着至关重要的作用，因为它提出了一个问题：“攻击者能看到什么，攻击者利用这些信息能做什么？”

对于 CASP 考试，你将被要求理解应用安全的重要性以及测试应用程序的方法。如果你足够幸运可以获得代码，则可以使用代码审查。在无法代码的情况下，黑盒测试可能更为合适。尽管代码审查很重要，但安全还需要网络评估。此类评估可能会使用密码破解器、利用框架，甚至是模糊测试。本章将讨论这些项目中的每一项。

# 应用安全测试

应用安全测试是使用软件、硬件和程序化方法防止应用程序出现安全漏洞并保护其免受利用的过程。作为一名 CASP，并不要求你成为精通程序员或理解 C++ 程序的工作原理。CASP 必须理解的是应用安全的重要性、在代码开发期间如何与程序员合作，以及对代码进行测试以确保安全控制的作用。作为 CASP，你需要理解各种测试方法。例如，当代码可用时，可能进行全面的代码审查。在无法访问代码的情况下，你可能选择黑盒应用评估技术。还有其他你应该注意的测试类型。每种测试类型都有特定的目的。表 5.1 显示了一些常见的测试类型。这些测试类型都应该包含安全测试作为整体测试目标的一部分。

**表 5.1** 常见应用测试类型

| 测试类型 | 描述 |
|---|---|
| Alpha 测试 | 应用程序的最早期测试，随后是 Beta 测试。两者在软件完全发布前进行。 |
| Beta 测试 | 用于评估应用程序的功能。 |
| 白盒测试 | 验证内部逻辑和安全性；针对大型应用程序。 |
| 黑盒测试 | 基于完整性的安全类型；关注输入和输出。 |
| 功能测试 | 根据需求验证程序，其中包含安全组件。 |
| 回归测试 | 更改后使用以确保输入和输出正确。 |
| 并行测试 | 通过输入数据并比较结果来验证新系统或未更改系统。 |
| 社会测试 | 验证系统能够在目标环境中运行。 |

理解代码开发过程对于安全专业人员至关重要。练习 5.1 研究了公司可能使用的某些测试类型。回归测试是在更改后用于确保输入和输出正确。从安全角度来看这一点非常重要，因为输入验证是最常见的漏洞之一。

# 特定应用程序问题

应用程序是用编程语言编写的。编程语言可以是低级的（以便系统容易理解该语言）也可以高级的（以便人类容易理解，但必须为系统进行翻译）。所有程序的共同点是它们都是通过代码开发的，并由人类编写。

根据《纽约时报》2006年的一篇文章（`www.nytimes.com/2006/03/27/technology/27/soft.html`），Windows Vista 拥有 500 万行代码。在微软发布操作系统或任何应用程序之前，必须进行安全审查。这种规模的项目需要花费大量的时间精力进行审查。无论应用程序大小如何，都必须对其潜在的安全问题进行审查。程序员不仅要计划用户应该输入什么，还要计划用户不应该输入什么。

例如，曾有一个程序员告诉我，他只需 50 行代码就能编写我需要的应用程序。然而，他补充说还需要另外五百行代码来考虑到可能发生的所有情况。我的观点是，编写良好的代码是一项巨大的任务。如果处理不当，可能会发生一系列应用程序问题和错误，例如缓冲区溢出和跨站脚本。应用程序的安全通常有三种解决方式：通过设计、通过默认和通过部署。安全措施是内置的，必须在开发早期阶段进行安全审查以发现潜在的安全问题。开发延迟越长，修复问题的成本就越高。因此，早期添加安全措施比后期添加要便宜得多。审查使应用程序更健壮，更能抵御攻击者。安全审查帮助程序员识别常见问题并识别最佳实践。

另一个问题是用户不断要求功能。宏是一组旨在使某些任务更简单的指令。但这种功能利用了文字处理器、电子表格和其他应用程序提供的功能。漏洞是产品中固有的，除非用户选择禁用所有宏，否则所有用户都容易受到影响。功能请求驱动了开发，因为复杂性是安全的敌人。应用程序安全至关重要。因此，候选人应该理解，每一步都必须检查安全性。

# 跨站脚本

跨站脚本（XSS）攻击是一种由于注入引起的应用程序问题。当恶意脚本被注入到原本受信任的网站时，就会发生 XSS。恶意脚本随后传递给用户的浏览器，浏览器无法知道该脚本是恶意的。一旦在用户的计算机上执行，恶意脚本就可以访问你的浏览器所保留的任何 cookie、会话令牌或其他敏感信息，并与网站直接通信。

当无效的输入数据包含在发送给用户的动态内容中，就会发生 XSS 攻击。例如：

```
index.php?name=guest<script>alert('attacked')</script>
```

或者

```
index.php?name=<script>window.onload = function() { var link=document.getElementsByTagName("a")[0].href="http://xssexamples.com/";}</script>
```

当 Web 应用程序在生成的输出中使用用户输入，而不对其进行验证或编码时，就会发生 XSS。攻击者可以注入恶意的 JavaScript、VBScript、ActiveX 或 HTML 以在用户的计算机上执行。这可能包含一个或多个模拟场景，你从中识别脚本或命令；候选人必须熟悉许多如 XSS、XSRF 和目录遍历等已知攻击。这里显示了一个示例：

```
http://ip_address/scripts/../etc%/windows/system32/cmd.exe?dir=
```

# 跨站请求伪造

与 XSS 密切的是跨站请求伪造（CSRF）攻击。CSRF 攻击欺骗用户的浏览器发送伪造的 HTTP 请求（包括用户的会话 cookie 身份验证信息）到脆弱的 Web 应用程序。CSRF 允许攻击者强制用户浏览器生成请求，使脆弱的应用程序认为合法请求来自受害者。XSS 和 CSRF 漏洞都非常泛滥。获取更多信息的良好来源是开放 Web 安全项目（OWASP），`www.owasp.org`。

# 不恰错误处理

安全的很大一部分是建立良好的控制措施来检查所有输入数据、处理后的数据和输出数据。即使执行正确，你仍必须处理潜在的错误。有时这就是应用程序开发者遇到麻烦的地方，因为他们向用户提供了过多的信息。例如，如果我去处理身份验证的网页并输入错误的密码，应用程序是响应“密码错误”，还是仅响应“用户名/密码错误”？后者会让入侵者的难度增加。这里是此类问题的几个例子。首先是 `http.conf` 文件：

```
<location /server-status
SetHandler server-status
</location>
```

此配置允许任何人查看服务器状态页面，该页面包含关于 Web 服务器使用的详细信息。另一个例子是许多 Web 服务器上的 `php.ini` 文件。使用时，该文件提供详细的错误信息：

```
display_error = on
log_errors = on
Error_log = syslog
ignore_repeated_errors = Off
```

必须始终测试应用程序的边界，以查看返回什么响应以及显示哪些错误消息。

# 地理标记

地理位置和基于位置的服务是 CASP 的另一个关注点。这项技术包括对照片进行地理标记的能力。大多数智能手机和平用户在激活设备时会开启此功能，但从未意识到这些信息被用于他们拍摄的每张照片。大多数人没有意识到他们的手机上开启了地理标记，要么它是默认开启且未作为选项暴露给用户，要么他们被要求启用后很快就忘记了。结果，个人经常分享过多的信息，甚至精确到他们的位置。安全担忧是，黑客或其他可能具有追踪特定个人位置的能力。如果你觉得这听起来有点诡异，那确实如此！有一个应用程序（`http://ilektrojohn.github.io/creepy/`）允许用户

个人利用他们在在线上发布的照片。来自社交网络网站的诡异地理位置相关信息会使用 Google Maps 显示结果。

许多应用程序还利用这项技术来识别用户的精确位置。其理念是根据用户的位置来提供服务或获取收入。例如，包括来自附近咖啡店和餐厅的优惠券。

# 点击劫持 (Clickjacking)

*点击劫持，或 UI 伪装（UI redressing），*维基百科将其描述为“一种恶意技术，通过欺骗用户在点击看似无害的网页时泄露机密信息或对其计算机进行控制。”这种攻击通过控制用户访问网页时看到的内容来实现。攻击者以这种方式构建页面：控制用户可以点击的链接或按钮。受害者点击了一个可见的链接，但实际上在选择另一个他们看不见的链接。这是通过攻击者设计的网页的方式实现的。本质上，攻击者构建了一个页面，用户看到并点击的内容并不反映其实际执行的操作。

点击劫持针对的是*状态管理（state management）*。状态管理是指对图形用户界面中按钮、图标或选项等或多个用户界面控件的状态的管理。如果攻击者能够遮挡受害者选择的项目，用户就无法看到按钮是否处于启用状态或是否做出了有效选择。在许多情况下，安全专业人员可能对应用程序的开发没有控制权，只能寻找防御漏洞的方法。为了防御基于 Flash 的漏洞，请在 Flash Player 的全局隐私设置中设置“始终拒绝”（Always Deny）选项。其他防御措施包括使用插件和诸如 NoScript(`http://noscript.net/`) 工具。

> CASP 候选人应该描述如 XSS、CSRF 和点击劫持等特定攻击。

# 会话管理 (Session Management)

会话管理攻击发生在攻击者入侵 Web 应用程序会话管理机制以绕过身份验证控制并伪造有效用户。通常使用两种技术：

- 会话令牌预测 (Session token prediction)
- 会话令牌嗅探和篡改

会话令牌预测攻击发生在令牌遵循可预测模式或按数字递增时。如果攻击者可以发送大量请求，可能更容易确定应用程序使用的模式。

在某些情况下，令牌可能没有加密，甚至可能在使用弱效的编码（如十六进制编码或 Base64）。攻击者还可能尝试使用 Wireshark 或 Burp Proxy（见图 5.1）等工具嗅探有效令牌。如果正在使用 HTTP cookie 且未设置安全标记，攻击者可以尝试重放 cookie 以获得未经授权的访问。其他会话管理问题包括：

**放在 URL 中的 Session ID** 某些网站会将会话 ID 编码并将其放在页面的 URL 中。

**超时利用（Timeout Exploitation）** 如果受害者使用公共计算机并仅关闭浏览器，网站可能不会注销用户，允许攻击者重新打开网站并获得完全访问。

# SQL 注入 (SQL Injection)

许多数据库产品如 Microsoft SQL Server、MySQL 和 Oracle 允许复杂的访问查询。如果数据库和底层操作系统没有适当的安全控制，攻击者可以针对数据库创建查询以泄露未经授权的信息。这类攻击通常被称为 SQL 注入。SQL 注入攻击发生在攻击者使用一系列恶意的 SQL 查询直接操作 SQL 数据库时。SQL 注入攻击可以从网站的地址栏、应用程序字段或通过查询和搜索启动。一旦启动 SQL 注入，畸形的输入可能会导致数据库变得不稳定或泄露信息。攻击者使用单引号（'）等逻辑来测试数据库：

```
Microsoft OLE Provider for ODBC Drivers error '80040SQL Server line 5
```
