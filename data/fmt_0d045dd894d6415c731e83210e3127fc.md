
虽然不广为人知，但垃圾邮件的一种变体是`spim`，它基本上是通过 Yahoo! Messenger 或 AOL Instant Messenger (AIM) 等即时消息应用程序发送的垃圾信息。恶意 spim 的目的与垃圾邮件相同——即传递恶意内容或链接。

## 网络钓鱼 (Phishing)

`phishing`（读音为 fishing”）是一种社会工程攻击，攻击者试图通过在发送给大量通常随机用户的电子邮件或即时消息中伪装成受信任的实体，从而从用户处获取敏感信息。攻击者试图获取用户名、密码、信用卡号以及用户银行账户详情等信息。发送的消息通常鼓励用户访问一个看起来像 PayPal 或 eBay 等信誉良好的实体的网站，这两个实体都经常被用于钓鱼尝试。然而，用户实际访问的网站并不属于该信誉良好的组织，而是要求用户提供可在稍后攻击中使用的信息。通常，发送给用户的消息会声称用户的账户已被入侵，并出于安全考虑要求用户输入其账户信息以验证详情。

网络钓鱼的另一个非常常见的例子是，攻击者发送一封据称来自银行的大群邮件，告诉收件者发生了安全泄露，并指示他们点击链接以验证其账户是否未被篡改。如果个人确实点击了该链接，他们将被带到一个看起来由银行所有、但实际上由攻击者控制的网站。当他们出于“验证”目的提供账户和密码时，他们实际上是将这些信息交给了攻击者。

## 鱼叉式钓鱼 (Spear Phishing)

`spear phishing` 是一个术语，指针对具有共同特征的特定群体的钓鱼攻击。通过针对特定群体，成功攻击的比例（即收到的响应数量）与发送的电子邮件或消息总数之比通常会增加，因为针对性攻击看起来比随机发送给用户的消息更具合理性。

### 语音钓鱼 (Vishing)

`vishing` 是钓鱼的一种变体，它利用语音通信来获取信息。语音钓鱼利用了人们对电话网络的信任。用户并不知道攻击者可以使用 IP IP (`VoIP`) 技术伪造（模拟）合法实体的电话。语音消息也可以被破坏并用于这些尝试。通常，攻击者希望获取信用卡号或其他可用于身份盗窃的信息。用户可能会收到一封邮件，要求他们拨打一个可能被破坏的语音系统的电话。如果用户收到声称来自信誉良好的实体并要求敏感信息，不应提供，而应通过互联网或检查账户账单来找到联系电话。用户随后可以验证收到的消息是否合法或报告该钓鱼尝试。

## 圣诞树攻击 (Xmas Attack)

`xmas` `attack` 或圣诞树攻击源于特定的协议选项。圣诞树数据包是一个所有选项都开启的数据包。这个名字源于这些数据包像圣诞树一样点亮的说法。当作为扫描发送时，圣诞树数据包设置了 `FIN`、`URG` 和 `PSH` 选项。许多操作系统实现遵循 IP 数据包规范的 `RFC 791` 的方式略有不同。它们对数据包的响应可以告诉扫描器存在什么操作系统。另一种情况是在 DoS 攻击中，圣诞树数据包会消耗更多的路由器处理，消耗资源。

简单的无状态防火墙检查设置的 `SYN` 标志以防止 SYN 洪水，而圣诞树数据包设计为不设置 `SYN`，因此可以跳过这些设备。新的安全设备（如高级防火墙）可以检测这些数据包，提醒人们注意扫描活动。

## 入站 (Pharming)

`pharming` 包括将用户重定向到看起来官方的虚假网站。通过钓鱼，个人被逐一针对。要成为受害者，接收者必须采取行动（例如通过提供个人信息做出响应）。在注入过程中，由于 DNS 污染（更改服务器域名表中 URL 的攻击）或修改本地主机文件（用于将 URL 转换为相应的 IP 地址）等活动，用户将被引导至虚假网站。一旦进入虚假网站，用户可能会认为那是合法站点而提供个人信息。

### 权限提升 (Privilege Escalation)

网络攻击是一个多步骤的过程。大多数攻击从与普通用户相关的权限级别开始。从该级别开始，攻击者利用漏洞获得 root 或管理员权限的访问权限。攻击链中的这一步被称为权限提升（`privilege escalation`），对于许多攻击努力至关重要。

实现权限提升有几种方法。其中一条路径是利用现有权限并执行能够允许你窃取更高级凭据的操作。使用嗅探器抓取凭据、获取 `SAM` 或 `/etc/passwd` 文件，是获取“更高级”凭据的一种方法。另一种方法是通过以特权权限运行的进程中的漏洞或缺陷。在这些进程中注入恶意代码也可以实现权限提升。

#### 恶意内部威胁

系统上的所有活动都在一个账户名下进行。账户定义了分配给用户的权限级别。用户之所以拥有这些访问权限，是因为他们执行职责时需要信任，而这种信任反映在赋予其账户的权限中。当内部人员进行恶意活动时，他们是在滥用这种信任。但他们也比外部攻击者具有显著优势，因为他们拥有系统上的基本权限。在攻击链中，早期的步骤之一（有时也是困难的步骤）是在系统上建立基本用户访问权限。恶意内部威胁本质上是从完成这一步开始的。

如果恶意内部人员具有特权权限（例如系统管理员），那么这种形式的攻击可能特别别有害。具有 root 级访问权限和技术的恶意内部人员可以绕过许多安全措施，并在避免检测的情况下执行许多破坏性任务。最近美国安全局（NSA）内部人员爱德华·斯诺登（Edward Snowden）的案例表明，这种攻击向量对组织具有多大的破坏性。

针对内部人员的最佳防御是由两部分组成的层次防御。第一是通过 HR 对新员工进行筛选，并监控员工的活动和士气。另一个工具是职责分工。确保系统管理员没有操作其所管理系统日志的能力，可以通过多个日志服务器和多组管理控制来实现。

#### 缓存中毒

许多网络活动依赖各种地址方案才能正常工作。当你通过输入银行的 URL 访问银行网站时，浏览器会查询系统的 DNS 系统将单词转换为数字地址。当数据包通过网络交换到你的机器时，会涉及到一系列地址缓存。无论缓存是用于 DNS 系统还是 ARP 系统，其存在的原因都是相同的：效率。这些缓存防止了重复的冗余查询，为系统节省时间。但它们也可能被中毒，向终端用户的应用程序发送错误信息、重定向流量并改变系统行为。

###### DNS 中毒

DNS 系统用于将名称转换为 IP 地址。并不是一个单一的 DNS 系统，而是一个 DNS 服务器层级结构，从互联网骨干网上的根服务器，到你 ISP 处的副本、你的家庭路由器和你的本地机器，每个节点都以 DNS 缓存的形式存在。要检查特定地址的 DNS 查询，你可以使用 `nslookup` 命令。图 12-8 显示了在 Windows 机器上执行的一系列 DNS 查询。在第一次请求中，DNS 服务器位于 ISP，而在第二次请求中，DNS 服务器来自 VPN 连接。在两次请求之间，网络连接发生了变化，导致了不同的 DNS 查询结果。这是一种 DNS 中毒攻击。

DNS 中毒是一类被称为 `DNS 欺骗` 的更大攻击类中的变体。在 DNS 欺骗中，攻击者通过许多方式更改 DNS 记录，其中包括破坏 DNS 服务器、Kaminsky 攻击以及使用虚假网络节点。攻击者甚至可以使用 DNS 缓存中毒导致 DNS 欺骗。通过中毒上游缓存，所有下游用户将获得被欺骗的信息。

由于 DNS 请求和响应的重要性，一个项目开始使用数字签名来保护 DNS。该项目由美国政府发起并称为域名安全扩展 (`DNSSEC`) 通过对记录进行数字签名来工作。这是通过向 DNS 系统添加密钥和证明密钥有效性的签名来实现。有了这些信息，请求者可以确保他们收到的信息是正确的。该新系统需要大量时间（几年）传播到整个 DNS 基础设施，但最终系统将获得更大的保障。

###### ARP 中毒

在机器之间移动数据包时，设备有时需要知道如何使用 MAC 或二层地址发送数据包。地址解析协议 (`ARP`) 通过四种基本消息类型解决这个问题：

- `ARP 请求`：“谁拥有此地址？”

- `ARP 响应`：“我有该 IP 地址，我的 MAC 地址是……”

- `反向 ARP 请求 (RARP)`：“谁拥有此 MAC 地址？”

- `RARP 响应`：“我有该 MAC 地址，我的 IP 地址是……”

这些消息与设备的 ARP 表结合使用，ARP 表是存储与这些数据元素相关的内存的地方。这些命令被用作简单的查找。当机器向网络发送 ARP 请求时，响应会被所有听到该响应的设备接收并记录。这有利于高效的地址查找，但也使系统容易受到攻击。

当 ARP 表收到响应时，它会自动信任该响应并更新表格。某些操作系统甚至在从未听到过原始请求的情况下也会接受 ARP 响应数据。目前没有机制可以验证收到的数据的真实性。攻击者可以发送消息、破坏 ARP 表并导致数据包被错误路由。这种攻击形式被称为 ARP 中毒，会导致恶意地址重定向。这允许一种机制，使得攻击者可以插入到两台机器之间的对话中间，即中间人攻击。

#### TCP/IP 劫持

`TCP/IP hijacking` 和 `session hijacking` 是用于指代接管客户端与服务器之间已存在会话的术语。对于攻击者而言，相比尝试渗透计算机系统或网络，劫持的优势在于攻击者不需要绕过任何验证机制，因为用户已经通过了验证并建立了会话。一旦用户完成了验证序列，攻击者就可以夺取会话并继续操作，就好像是攻击者而不是用户对系统进行了验证一样。为了防止用户察觉到任何异常，攻击者可以决定攻击用户的系统并对其进行 `DoS` 攻击，使其宕机，这样用户和系统就不会注意到正在发生的额外流量。

劫持攻击通常用于 Web 和 Telnet 会话。用于身份欺骗的序列号也适用于会话劫持，因为劫持者需要提供正确的序列号来继续相应的会话。

### 传递性访问

`Transitive access` 是一种通过破坏机器之间的信任关系来攻击系统的方法。一个简单的例子是：服务器受到了良好的保护，而客户端没有，且服务器信任客户端。在这种情况下，攻击客户端可以获得对服务器的传递性访问。

### 客户端攻击

网页浏览器已成为用户跨 Web 参与资源的主要应用程序。该界面的流行和实用性使其成为攻击者获取系统访问控制权的首要目标。通过浏览器可以发生各种攻击，通常是由于在使用输入前未能对其进行妥当验证。未验证的输入可能导致一系列注入攻击、头部操作以及其他形式的攻击。

#### 注入攻击

当在不进行输入验证的情况下使用用户输入时，为攻击者提供了了机会，通过构造输入以便在输入被应用程序解析和使用时触发特定事件。`SQL 注入攻击` 涉及对输入的操纵，导致产生与设计者意图不同的 `SQL` 语句。`XML` 和 `LDAP` 注入也是以此方式完成。由于 `SQL`、`XML` 和 `LDAP` 用于存储数据，这可能让攻击者获取违反业务规则的数据。`命令注入攻击` 发生在输入以一种允许命令行操纵的方式被使用时。这可以让攻击者在应用程序的权限级别上获得命令行访问权限。

#### 头部操作

当通过用户输入动态生成 `HTTP` 时，未验证的输入可以给攻击者更改 `HTTP` 元素的机会。当用户提供的信息用在头部中时，可能会创建各种攻击，包括缓存投毒、跨站脚本、跨用户篡改、页面劫持、Cookie 操纵或开放重定向。

### 密码攻击

最常见的验证形式是用户 ID 和密码的组合。虽然这在本质上不是一种糟糕的身份验证机制，但这种组合可以以多种方式受到攻击。很多时候，这些攻击为攻击者带来了有利的结果，这并不是因为方案本身有缺陷，而通常是因为用户没有遵循良好的密码规范。

#### 糟糕的密码选择

在各种密码攻击技术中，技术性最低的一种是攻击者简单尝试猜测系统或网络授权用户的密码。这种简单的方法竟然如此有效，令人惊讶，原因在于人们因选择糟糕密码而臭名昭著。用户需要选择他们能记住的密码，因此他们创建了简单的密码，例如生日、母亲的娘姓、配偶或孩子的名字，甚至直接使用用户 ID 本身。攻击者只需要在开始猜测之前获得有效的用户 ID（这通常是简单的事，因为组织倾向于以某种组合使用个人姓名——例如，名字的首字母加上姓氏）以及关于用户的一点信息即可。组织有时会通过在其网站上发布其“管理团队”和其他个人的姓名（有时还附有简短介绍），让攻击者更容易获取此类这类信息。

即使某人没有使用某些个人细节作为密码，攻击者可能仍然好运，因为许多人使用常用单词作为密码。攻击者可以获得常用密码列表——互联网上存在许多此类列表。像“password”和“secret”之类的单词经常被用作密码。喜欢的运动队名称也经常出现在常用密码列表中。

### 字典攻击

确定密码的另一种方法是使用密码破解程序，该程序使用字典单词列表来尝试猜测密码，因此被称为 `dictionary attack`（字典攻击）。单词可以单独使用，也可以将两个或多个较小的单词组合成一个单一可能的密码。许多商业和公有域的密码破解程序采用多种方法来破解密码，包括使用用户 ID 的变体。

这些程序通常允许攻击者创建各种规则，告诉程序如何组合单词以形成新的可能的密码。用户通常用特定的数字代替特定的字母。例如，如果用户想用 `secret` 作为密码，可以将字母 `e` 替换为数字 `3`，产生 `s3cr3t`。这个密码不会出现在字典中，因此纯字典攻击无法破解它，但这个密码对用户来说仍然很容易。然而，如果创建一个规则尝试字典中的所有单词，然后用数字 `3` 代替字母 `e`，密码就会被破解。

规则还可以被定义让破解程序用特殊字符替换其他字符或组合单词。攻击者破解密码的能力取决于用户创建密码的方法，以及所使用的字典和规则。

### 暴力破解

如果用户选择的密码不在字典中，即使用各种数字或特殊字符代替字母，破解密码的唯一方法是攻击者尝试 `brute-force attack`（暴力破解），密码破解程序尝试所有可能的密码组合。

密码的长度和密码中可能字符集的大小将极大影响暴力破解所需的时间。几年前，这种攻击方法非常耗时，因为生成所有组合需要大量时间。然而，随着计算机速度的提高，生成密码组合的速度快得多，使得对某些计算机系统和网络发起暴力破解变得更加可行。

对密码的暴力破解可以在两个层面进行：它可以攻击攻击者在登录提示处尝试猜测密码系统，也可以攻击密码文件中包含的密码哈希值列表。如果账户在几次登录尝试后锁定，则第一种攻击会变得更加困难。如果密码文件维护良好，他人无法获取其副本，则第二种攻击就可以被阻止。

#### 混合攻击

`hybrid`（混合型）密码攻击是一种结合了上述方法的系统。大多数破解工具都内置了此选项，首先尝试字典攻击，然后转向暴力破解方法。

## 生日攻击

`birthday attack`（生日攻击）是一种特殊的暴力破解攻击，其名称源于所谓的“生日悖论”。该悖论指出，在至少有 23 个人的群体中，至少两个个人生日相同的概率大于 50%。在数学上，我们可以使用方程 `1.25*k*^(1/2)`（其中 `k` 等于可能值集合的大小），在生日悖论中，`k` 等于 365（可能的生日数量）。这种现象同样适用于密码，此时 `k`（密码数量）要比大得多。

## 彩虹表

`rainbow tables`（彩虹表）是与密码关联的预计算表或哈希值。这可以将密码的搜索从一个计算问题变为查找问题。这可以极大地减少攻击密码时的工作量。针对彩虹表的最佳防御是加盐哈希（salted hashes），因为添加盐值增加了问题的复杂性，使得预计算过程在系统之间无法复制。

## 抢注攻击/URL 劫持

`typo squatting`（抢注攻击）是一种利用常见拼写错误的攻击形式。如果用户输错了 URL，结果本应该是 404 错误或“未找到资源”。但如果攻击者注册了拼写错误的 URL，你就会进入攻击者的页面。这种攻击模式也被称为 `URL hijacking`（URL 劫持）、`fake URL`（虚假 URL）或基于品牌欺骗的 `brandjacking`（品牌劫持）。

攻击者追求这种攻击途径有几个原因。最明显的是作为钓鱼攻击的一种。假网站收集凭据并将其传递给真实网站，然后在获取凭据后退出对话以避免检测。它还可被用于在受害者机器上植入路式恶意软件（drive-by malware）。它还可以通过联盟网络传输数据包，根据拼写错误赚点击收益。使用虚假 URL 作为起点还可以实施许多其他形式的攻击。

## 水坑攻击

最广为人知的攻击向量是那些直接针对目标的攻击。由于其具有进入性和直接性，防御措施是为检测和防御它们而设计的。但如果用户通过访问网站“主动请求”了攻击呢？就像猎人坐在水坑旁等待动物来喝一样，攻击者可以在用户可能经常访问的网站放置恶意软件。水坑攻击（watering hole attacks）最早由 RSA 发现，涉及用恶意软件感染目标网站。在检测到的某些案例中，感染被限制在特定的地理区域。这些不是简单的攻击，但对于向特定的终端用户组传递恶意软件可能非常有效。水坑攻击实现起来复杂，并且似乎有国家级或其他高资源攻击者的支持。鉴于其风险之大，典型的攻击向量将是零日攻击，以进一步避免检测。
