
## OSPF

### 开放最短路径优先 (OSPF)

开放最短路径优先 (OSPF) 是一种开放的链路状态路由协议。OSPF 路由器会学习其“区域”（即其维护路由的网络部分，对于小型网络通常是整个网络）的整个网络拓扑。OSPF 路由器发送事件驱动的更新。如果网络收敛了一周，OSPF 路由器将不会发送任何更新。与 RIP 等距离矢量协议相比，OSPF 的收敛速度要快得多。在图 5.21 中，OSPF 会选择从办公室 A 到 B 的两跳 T3 路由，而不是单跳 T1 路由。

> **注意**
>
> 考试非常倾向于开放标准而非专有标准，这就是为什么思科的 EIGRP 等专有路由协议未在此讨论的原因。

## BGP

BGP 是边界网关协议，即互联网上使用的路由协议。BGP 在自治系统之间路由，自治系统是指具有多个互联网连接的网络。BGP 具有一些距离矢量特性，但正式被认为是一种路径矢量路由协议。

## 调制解调器

`Modem`（调制解调器）是 Modulator/Demodulator（调制器/解调器）的缩写。它接收二进制数据并将其调制为可在电话网络上传输的模拟声音（电话网络设计用于传输人声）。接收端的调制解调器再将模拟声音解调回二进制数据。调制解调器是异步设备：它们不依靠时钟信号运行。

## DTE/DCE 和 CSU/DSU

`DTE`（数据终端设备）是一种网络“终端”，指任何类型的网络连接用户机器，如台式机、服务器或实际终端。`DCE`（数据电路终端设备，有时也称为数据通信设备）是连接 DTE 的设备，如路由器。这些术语最常见的用法是 DTE/DCE，且各自含义更为具体：DCE 标志着 ISP 网络的末端。它连接到数据终端设备 (DTE)，后者由客户负责。DCE 与 DTE 相接的点称为分界点：即分界点，ISP 的责任在此结束，客户的责任由此开始。

通过 DCE/DTE 传输的电路是同步的（使用时钟信号）。双方必须同步到由 DCE 提供的时钟信号。DCE 设备是调制解调器或 `CSU/DSU`（信道服务单元/数据服务单元）。

## 硬件运维

硬件运维涉及日常运营问题，如冗余电源、维护适当的保修以及支持合同。

### 冗余电源

路由器和防火墙等关键设备应配备冗余电源。每个电源应连接到不同的电源插座，且这些插座应位于不同的电路回路上。应使用浪涌保护器和 UPS，关键设备应具备发电机备用电源。我们将在第 8 章（Chapter 8），领域 7：安全运营中讨论浪涌保护器、UPS 和发电机。

所有关键设备应在有效的供应商保修期内，并拥有适当的支持合同。支持合同的定价通常基于响应时间和其他变量（响应越快费用越高）。思科 SmartNet 提供多个级别的保障：

*   **8 × 5 × 4**：4 小时响应，基于仓库时间的当地工作时间，每周 5 天，不含节假日
*   **8 × 7 × Next Calendar Day**：次日历日送达，基于仓库时间的当地工作时间，每周 7 天，含节假日
*   **8 × 5 × Next Business Day**：下一个工作日送达，基于仓库时间的当地工作时间，每周 5 天，不含节假日 [[17]](#Ch005_225-293_B9780443187346000039.xhtml#bb0090)

## 安全通信

保护传输中的数据是我们面临的最复杂的挑战之一。互联网提供了廉价的全球通信——但几乎没有内置的机密性、完整性或可用性。为了保护我们的数据，我们通常必须自己动手；安全通信描述了实现这一目标的方法。

### 认证协议与框架

认证协议通过网络验证身份声明。良好的安全设计假设网络窃听者可能会嗅探客户端与认证服务器之间发送的所有数据包：协议应保持安全。正如我们稍后将看到的，PAP 无法通过此测试，但 CHAP 和 EAP 可以。

#### PAP 和 CHAP

PAP（密码认证协议）是一种非常脆弱的认证协议。它以明文形式发送用户名和密码。能够嗅探认证过程的攻击者可发起简单的重放攻击，通过重放用户名和密码来登录。PAP 不安全，不应使用。

CHAP（质询握手认证协议）是一种更安全的认证协议，它不暴露明文密码，且不易受重放攻击。CHAP 依赖共享密钥：即密码。密码在安全创建时（如账户注册期间）生成并存储在 CHAP 服务器上。由于用户和 CHAP 服务器共享一个密钥（明文密码），它们可利用该密钥进行安全通信。

为进行认证，客户端首先通过 `LCP`（链路控制协议）创建初始（未认证）连接。服务器随后启动三次 CHAP 认证过程：

1.  服务器发送一个质询，即一个小的随机字符串（也称为一次性数 `nonce`）。
2.  用户获取质询字符串和密码，使用 MD5 等哈希密码创建哈希值，并将该值作为响应发回 CHAP 服务器。
3.  CHAP 服务器同样对密码和质询进行哈希运算，生成预期响应。然后将预期响应与从用户收到的响应进行比较。

如果响应相同，则用户必定输入了正确密码，从而通过认证。如果不同，则用户输错了密码，拒绝访问。

CHAP 服务器可通过发送新的（且不同的）质询来重新认证。每次质询必须不同；否则，攻击者可通过重放旧的加密响应进行认证。

CHAP 的一个缺点是服务器以明文存储每个客户端的密码。攻破 CHAP 服务器的攻击者可能窃取其上存储的所有密码。

#### 802.1X 和 EAP

`802.1X` 是“基于端口的网络访问控制”，包含 EAP（`可扩展认证协议`）。EAP 是一个认证框架，描述了多种具体的认证协议。EAP 旨在提供第 2 层认证（它是“基于端口的”，如交换机上的端口），在节点获得 IP 地址之前进行。它适用于有线和无线网络，但更常部署于 WLAN。

主要的 802.1X 角色包括：

*   **申请者**：802.1X 客户端
*   **认证服务器 (AS)**：认证申请者的服务器
*   **认证器**：一种设备（如接入点），允许申请者进行身份验证并连接。

#### 考试警告

不要混淆 `802.1X` (EAP) 与 `802.11` (无线)。

EAP 解决了许多问题，包括“漫游感染笔记本电脑”问题。携带受感染笔记本电脑的用户插入典型办公网络，并向 DHCP 服务器请求 IP 地址。一旦获得 IP，安装在笔记本电脑上的恶意软件便开始攻击网络上的其他系统。

当笔记本电脑能够请求 IP 地址时，它已经处于可在网络上造成危害的位置，包括机密性、完整性和可用性攻击。此问题在 WLAN 上最为严重（位于距离大楼 100 英尺处的外部笔记本电脑可能即可访问网络）。理想情况下，应在笔记本电脑加入网络前要求进行身份验证：EAP 正是实现这一功能的。

EAP 有多种类型；我们将重点介绍 `EAP-MD5`、`LEAP`、`EAP-FAST`、`EAP-TLS`、`EAP-TTLS` 和 `PEAP`：

*   **EAP-MD5** 是最弱的 EAP 形式之一。它仅提供客户端-服务器端认证（本节讨论的所有其他形式的 EAP 均支持客户端和服务器的相互认证）；这使其容易受到中间人攻击。`EAP-MD5` 也容易受到密码破解攻击。
*   **LEAP** (*Lightweight Extensible Authentication Protocol*，轻量级可扩展认证协议) 是思科专有协议，在 `802.1X` 最终确定前发布。`LEAP` 存在重大安全缺陷，不应使用。
*   **EAP-FAST** (*EAP-Flexible Authentication via Secure Tunneling*，通过安全隧道进行的 EAP 灵活认证) 由思科设计，旨在取代 `LEAP`。它使用 *Protected Access Credential* (PAC，受保护访问凭证)，其作用类似于预共享密钥。
*   **EAP-TLS** (*EAP-Transport Layer Security*，EAP 传输层安全) 使用 PKI，要求同时具备服务器端和客户端证书。`EAP-TLS` 建立用于认证的安全 TLS 隧道。由于使用 PKI，`EAP-TLS` 非常安全，但也因同一原因而复杂且成本高昂。其他主要版本的 EAP 试图在不需要客户端证书的情况下创建相同的 TLS 隧道。
*   **EAP-TTLS** (*EAP Tunneled Transport Layer Security*，EAP 隧道传输层安全) 由 Funk Software 和 Certicom 开发，通过取消客户端证书要求简化了 `EAP-TLS`，允许使用其他认证方法（如密码）进行客户端认证。因此 `EAP-TTLS` 比 `EAP-TLS` 更易于部署，但省略客户端证书时安全性较低。
*   **PEAP** (*Protected EAP*，受保护的 EAP) 由思科系统、微软和 RSA Security 开发，类似于（且可被视为竞争对手）`EAP-TTLS`，同样不需要客户端证书。

### VPN

虚拟专用网络 (VPN) 保护通过互联网等不安全网络发送的数据。其目标是虚拟地提供专线（如 T1）所提供的隐私。VPN 的核心机制涉及安全认证、加密哈希（如 `SHA-1`）以提供完整性，以及加密算法（如 `AES`）以提供机密性。

> **注意**
>
> 此处讨论的 VPN 协议的加密细节在第 4 章 第 4 章，领域 3：安全架构与工程中有深入介绍。

#### SLIP 和 PPP

`SLIP` (Serial Line Internet Protocol，串行线路互联网协议) 是一种第 2 层协议，通过异步连接（如串行线路和调制解调器）提供 IP 连接。`SLIP` 于 1988 年首次推出时，首次允许通过调制解调器链路路由数据包（此前，调制解调器主要用于非路由的终端访问）。`SLIP` 是一种极简协议，不提供内置的机密性、完整性或认证。`SLIP` 已基本弃用，被 `PPP` 取代。

`PPP` (Point-to-Point Protocol，点对点协议) 是一种第 2 层协议，已基本取代 `SLIP`。`PPP` 基于 `HDLC`（前文已讨论），并通过点对点链路增加了机密性、完整性和认证。除了异步链路（如调制解调器）外，`PPP` 还支持同步链路（如 T1 线路）。

#### PPTP 和 L2TP

`PPTP` (Point-to-Point Tunneling Protocol，点对点隧道协议) 通过 IP 隧道传输 `PPP`。它由包括微软、3COM 在内的多家厂商联盟开发。`PPTP` 使用 `GRE` (Generic Routing Encapsulation，通用路由封装) 通过 IP 传输 `PPP`，并使用 TCP 作为控制通道（使用 TCP 端口 1723）。

`L2TP` (Layer 2 Tunneling Protocol，第 2 层隧道协议) 结合了 `PPTP` 和 `L2F` (Layer 2 Forwarding，第 2 层转发，旨在隧道传输 `PPP`)。`L2TP` 专注于认证，不提供机密性：它经常与 `IPsec` 结合使用以提供加密。与 `PPTP` 不同，`L2TP` 也可用于非 IP 网络，如 ATM。

#### IPsec

`IPv4` 没有内置机密性；通常使用 `TLS` 等高层协议来提供安全性。为解决第 3 层缺乏安全性的问题，设计了 `IPsec` (Internet Protocol Security，互联网协议安全) 以通过加密为 `IPv6` 提供机密性、完整性和认证。`IPsec` 已移植至 `IPv4`。`IPsec` 是一套协议；主要两个是封装安全载荷 (`ESP`) 和认证头 (`AH`)。每个都有一个 IP 协议号：`ESP` 是协议 50；`AH` 是协议 51。

> **注意**
>
> 本章描述 `IPsec`、`SSL` 和 `TLS` 的网络方面：这些协议的加密方面见第 4 章 第 4 章，领域 3：安全架构与工程。

##### IPsec 体系结构

`IPsec` 有三种体系结构：主机到网关、网关到网关和主机到主机。主机到网关模式（也称为客户端模式）用于将运行 `IPsec` 客户端软件的一个系统连接到 `IPsec` 网关。网关到网关（也称为点对点）连接两个 `IPsec` 网关，它们形成的 `IPsec` 连接充当共享可路由网络连接，如 T1 线路。最后，主机到主机模式通过 `IPsec` 将两个系统（如文件服务器）相互连接。许多现代操作系统（如 Windows 10 或 Ubuntu Linux）可原生运行 `IPsec`，允许它们形成主机到网关或主机到主机连接。

##### 隧道模式和传输模式

`IPsec` 可用于隧道模式或传输模式。隧道模式为整个原始数据包（包括原始 IP 头部）提供机密性 (`ESP`) 和/或认证 (`AH`)。会添加新的 IP 头部（包含 `IPsec` 网关的源和目的地址）。传输模式仅保护 IP 数据（第 4-7 层），原始 IP 头部不受保护。两种模式均添加额外的 `IPsec` 头部（一个 `AH` 头部和/或一个 `ESP` 头部）。图 5.24 显示了隧道模式和传输模式的区别。

#### SSL 和 TLS

安全套接字层 (`SSL`) 旨在保护 HTTP (Hypertext Transfer Protocol，超文本传输协议) 数据：HTTPS 使用 TCP 端口 443。`TLS` (Transport Layer Security，传输层安全) 1.0 等同于 `SSL` 3.1 版。`TLS` 当前版本为 1.3，详见 RFC 8446（参见 [`datatracker.ietf.org/doc/html/rfc8446`](https://datatracker.ietf.org/doc/html/rfc8446)）。

虽然最初面向 Web，但 SSL 或 TLS 可用于加密多种类型的数据，并可用于隧道传输其他 IP 协议以形成 VPN 连接。SSL VPN 可能比其 IPsec 对应物更简单：IPsec 对 IP 网络进行了根本性更改，因此安装 IPsec 软件会更改操作系统（这需要超级用户权限）。SSL 客户端软件不需要更改操作系统。此外，IPsec 很难通过防火墙；SSL 则简单得多。

## 远程访问

在远程办公和移动办公的时代，安全的远程访问是一项关键控制。这包括通过 DSL 或有线调制解调器等方式连接移动用户，回拨等安全机制，以及即时通讯和远程会议技术等较新的关注点。

### ISDN

综合业务数字网（ISDN）曾尝试通过“铜线对”提供数字服务，即普及于全球家庭和小型办公室的 `POTS`（普通老式电话服务）。这被称为“最后一英里”，通过（历史上为铜线对的）最后一英里提供高速数字服务一直是一个长期存在的挑战。

ISDN 设备称为终端。ISDN 基本速率接口（BRI）服务通过铜线对提供两个 64 K 数字信道（外加一个 16K 信令信道）。PRI（主速率接口）提供二十三个 64K 信道，外加一个 16K 信令信道。

ISDN 从未在家庭中得到广泛应用；它很快就被 DSL 和有线调制解调器所取代。ISDN 通常用于电话会议和视频会议。

### DSL

数字用户线路（DSL）拥有类似于 ISDN 的“最后一英里”解决方案：利用现有的铜线对为家庭和小型办公室提供数字服务。与 ISDN 相比，DSL 因速度更高而获得了更广泛的应用，速度可达 10 兆比特及以上。

常见的 DSL 类型包括对称数字用户线路（SDSL，上传和下载速度匹配）、非对称数字用户线路（ADSL，下载速度快于上传）和超高速数字用户线路（VDSL，具有快得多的非对称速度）。另一种选择是 HDSL（高速率 DSL），它使用两对铜线达到 SDSL 的速度；HDSL 用于提供廉价的 T1 服务。

对称 DSL 也称为单线 DSL。ADSL 的一个优势是它允许同时使用 POTS 线路，通常可从 DSL 流量中分离出来。一般来说，站点距离中心局（CO）越近，可用服务速度越快。

### 有线调制解调器
