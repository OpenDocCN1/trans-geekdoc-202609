
- **同步**：防止移动设备与计算机同步，因为同步可能会从设备中删除数据。如果您到达现场时移动设备已连接到计算机，则应将其断开连接以防止同步。

- **防止远程擦除**：确保防止移动设备接收任何信号，因为信号可用于向设备发送远程擦除命令。`法拉第袋` 可用于屏蔽移动设备，使其无法与任何其他组件通信。

![Image](img/exam.jpg)

> **针对 Security+ 认证考试，请了解：作为证据收集的移动设备应存放在`法拉第袋`中，以阻断发往移动设备的任何信号，这将防止数据在设备被扣押后出现或消失。`法拉第袋`还有助于防止嫌疑人远程擦除设备，因为远程擦除信号将被阻断。**

# CERTIFICATION OBJECTIVE 21.03（认证目标 21.03）

# 查看事件响应

在本节中，您将了解事件响应和事件响应团队的概念。Security+ 认证考试将测试您关于如何在组织内响应安全事件的知识。

## 事件响应团队

为处理组织内的安全事件做准备的第一步是确保已建立事件响应团队（也称为 *Computer Incident Response Team* [CIRT] 或 *计算机事件响应小组*）。事件响应团队负责知道如何处理组织内发生的安全事件，并负责及时纠正和记录安全问题。

第一步是组建团队。团队将由组织内具有不同技能的不同类型的员工组成。以下是通常出现在响应团队中的一些成员的简要列表：

- **Team leader**（团队负责人） 团队负责人负责确保所有团队成员在发生安全事件时都知道自己的角色。团队负责人还负责与可能在特殊情况下被征召的外部资源建立关系。

### 技术专家

技术专家拥有评估和识别安全事件规模以及了解如何纠正问题所需的技术专长。CIRT 可能拥有多名专精于不同领域的技术专家。例如，您可能拥有一名 Windows Server 专家、一名 Linux 专家和一名 Cisco 专家。

### 文档专家

文档专家知道如何记录整个响应过程，并负责在文档数据库中记录每起事件、问题的原因以及解决方案。

### 法律顾问

法律顾问了解公司在计算机取证和事件响应方面必须遵循的法律法规。如果团队其他成员对取证问题有疑问（例如实时取证是否合适），可以向法律顾问寻求帮助。

团队组建完成后，团队成员便可开始制定事件响应程序，包括如何应对不同类型的安全事件。

#### 事件响应计划

事件响应团队到位后，您便可以开始制定事件响应计划。事件响应计划应包含多个要素，例如识别不同类型的事件以及每位团队成员在事件期间的职责。以下是事件响应计划中常见的要素：

### 记录在案的事件类型/类别定义

该计划应定义组织内可能发生的不同类型的安全事件。例如，您可能会有一种称为“社会工程学攻击”的事件类型，另一种称为“拒绝服务攻击”。重要的是要注意，每种事件类型不一定非要是一种攻击类型；您也可以有一种称为“意外未授权访问”的事件类型。列出各种不同的事件类型后，您可以为它们分配定义，以标识事件类型。

### 角色与职责

该计划应定义每位团队成员的角色和职责。这包括每位成员在安全事件发生前、发生期间和发生后的职责。

### 报告要求/升级

该计划应明确用户应如何以及何时报告潜在的安全事件。事件响应计划还应明确首要响应人是谁，以便将事件升级报告给其。最后，该计划应明确安全事件的任何报告要求以及报告中应包含的要素。

### 计算机（或网络）事件响应团队

该计划应明确不同的 CIRT 成员及其职责。

## 演练

确保每个人都为安全事件发生的那一天做好准备非常重要，因此请务必计划演练，以便从识别阶段练习到经验总结阶段（如下文所述）期间发生的事件。

#### 事件响应过程

Security+ 考试要求您专门了解在商业环境中发生安全事件时如何响应的具体过程。确保 CIRT 了解事件响应过程的不同阶段至关重要。

以下概述了事件响应过程的各个阶段：

### 准备

第一步是通过组建 CIRT 和制定事件响应程序来为安全事件做准备。务必教育全体组织人员了解他们响应安全事件的责任及其角色。

### 识别

下一步是公司内部的某人识别出潜在的安全事件已经发生。这可能是从用户注意到其计算机响应异常，到员工发现 Web 服务器上的文件已被替换等任何情况。

一旦员工识别出安全事件，该员工需及时通知 CIRT，后者将派遣首要响应人。务必让员工知道应向谁报告安全事件，以便首要响应人能立即处理事件。首要响应人将判断是否发生了事件，以及该事件是否需要升级。

### 遏制

首要响应人的主要目标之一是隔离安全事件，防止其演变成更大的问题。例如，如果响应涉及病毒的事件，首要响应人应立即将系统从网络断开，以防止病毒传播到网络上的其他系统。

### 根除

安全事件被识别并遏制后，CIRT 将识别并执行根除导致事件的任何问题所需的步骤。这可能只是部署防火墙或加强病毒防护这样简单的操作。

### 恢复

恢复阶段是 CIRT 将系统恢复到安全事件发生前状态的阶段。这通常涉及使用恢复程序，即包含恢复系统分步说明的详细文档资源。

### 经验总结

事件处理完毕后，CIRT 需要记录经验教训。此步骤让团队能够着眼大局，回答“这里发生了什么，我们如何防止其再次发生？”等问题。

![Image](img/exam.jpg)

**务必了解事件响应过程的各个阶段以及每个阶段执行的活动。请注意，遏制阶段在识别出事件发生之后，因为您希望尽快隔离事件。**

#### 首要响应人

如前所述，如果您是安全事件的首要响应人，您的首要目标是遏制事件。例如，如果您响应用户投诉其系统似乎运行缓慢，并在到达后发现可能是由于病毒导致，请将系统从网络断开（通过拔掉计算机上的网线），以免病毒感染网络上的其他系统。比处理一台受感染的计算机更糟糕的是处理多台受感染的系统！

如果您发现网络上的系统正在向互联网复制蠕虫病毒，您可能不得不关闭整个交换机的电源，甚至断开与互联网的连接，以防止病毒继续从您的网络向互联网复制。

![Image](img/exam.jpg)

**针对 Security+ 考试，请了解首要响应人应专注于遏制安全事件，使其不演变成更大的问题。这可能涉及将受损系统从网络断开，以防止安全事件在网络中蔓延。**

#### 损害与损失控制

Security+ 认证考试将测试您关于损害与损失控制的知识。在损害与损失控制中，目标是在安全事件期间评估损害，然后尝试控制因安全事件造成的损失。

到达现场时首先要做的是评估安全事件的严重程度。自问诸如“事件仅影响一台系统还是多台网络系统？”之类的问题。

# 事件响应：控制损失、演练、策略与数据源

控制损失的另一个目标是控制损失。控制安全事件造成的损失的最佳方法是通过将涉及的系统从网络中断开来遏制该事件。如果只有一个系统涉及其中，你可以直接将该系统从网络中断开；而如果整个部门的系统都涉及其中，你可能需要关闭网络交换机的电源，以便无法进行任何网络连接。

## 演练

作为事件响应策略的一部分，参与不同类型的演练非常重要，这样当实际事件发生时你才能做好准备。你可以使用不同类型的演练来帮助员工为安全事件做准备：

*   **桌面推演** 在桌面推演中，事件响应团队会审查事件发生时应遵循的响应程序。这有助于每个人了解事件发生时的工作角色。

*   **演练** 演练比桌面推演更详细，因为它提供了一个安全事件场景，允许事件响应团队讨论在该场景下应采取的步骤。

*   **模拟** 模拟是在模拟环境中进行的实际事件，以确保事件响应团队知道如何使用工具并执行响应事件所需的步骤。

## 事件响应的策略和程序

组织应花时间准备事件响应计划，以便整个公司都知道如何应对安全事件。除了创建事件响应团队和制定事件响应计划外，在事件响应策略和程序方面还应考虑以下组成部分：

*   **利益相关者管理** 了解赞助事件响应项目的利益相关者是谁，并理解他们在事件响应方面的目标。

*   **沟通计划** 制定沟通计划，以便了解组织内部使用的沟通渠道。这包括与利益相关者使用的沟通渠道。

*   **灾难恢复计划（DRP）和业务连续性计划（BCP）** 你在第 18 章中了解了灾难恢复和业务连续性。请确保已制定完整的灾难恢复计划和业务连续性计划。

*   **运营连续性规划（COOP）** 与业务连续性计划相关的是运营连续性规划（COOP），这是一个确保企业所有关键功能在紧急情况或灾难期间仍能运行的计划。

*   **保留策略** 保留策略规定了信息在组织内保留多长时间，包括备份和数据的异地存储。

存在许多攻击框架，可以帮助你确定如何应对攻击事件。以下是 Security+ 考试目标中提到的几个攻击框架：

*   **MITRE ATT&CK** MITRE 对抗战术、技术和通用知识（ATT&CK）是一个旨在概述攻击生命周期阶段和常见目标平台的框架。

*   **钻石入侵分析模型** 该威胁情报模型确定了对手、能力、基础设施和受害者这四个攻击组件之间的关系。

*   **网络攻击链** 网络攻击链由洛克希德·马丁公司开发，将攻击过程分解为七个阶段：侦察、武器化、投递、利用、安装、命令与控制、目标行动。

### 考点深度解析：事件响应术语

除了理解事件响应团队、事件响应计划和事件响应流程等概念外，你还应了解与事件响应相关的以下关键术语：

*   **首席响应人员** 首席响应人员是在安全事件被识别后最先响应的安全专业人员。首席响应人员的主要目标是遏制安全事件。

*   **恢复** 涉及安全事件的系统被视为受损系统，在许多情况下，恢复涉及擦除硬盘、重新安装或重新镜像操作系统，并从最后一次良好的备份中恢复数据。

*   **报告** 应创建描述事件和经验教训的文档，以帮助教育其他安全团队成员和组织。

*   **隔离** 受损或受影响的系统应从网络中移除，直到安全事件得到解决。

*   **法律保全** `法律保全` 是指将数据置于特殊保全状态，以便用户在调查期间无法删除该数据。例如，`Microsoft Exchange Server` 允许管理员将邮箱置于法律保全状态，以便在搜索邮箱以获取证据时用户无法删除邮件。

*   **数据泄露** 当被视为敏感的数据被提供给不受信任的源时，就会发生数据泄露。请务必控制对信息的访问和外部闪存驱动器的使用，以帮助防止组织中的数据泄露。

*   **损害和损失控制** 每个安全事件都需要确定损害的程度，并遏制事件以控制与之相关的损失。

*   **战略情报/反情报收集** 安全团队的一项重要任务是持续监控和记录系统及网络上的活动，以便团队在安全事件发生时察觉到它们。持续监控是一个永无止境的过程，涉及监控资源访问、网络流量和安全日志中的事件。
