## 8.9 取消

有时我们需要指示一个 goroutine 停止它正在做的事情，例如，在 Web 服务器代表已断开连接的客户端执行计算时。

没有任何方法让一个 goroutine 直接终止另一个 goroutine，因为那样会留下所有共享变量处于未定义状态。在火箭发射程序（§8.7）中，我们向一个名为 `abort` 的通道发送了单个值，倒计时 goroutine 将其解释为请求自行停止。但如果我们需要取消两个 goroutine，或者任意数量的 goroutine 怎么办？

一种可能性是在 `abort` 通道上发送与要取消的 goroutine 数量相同的事件。然而，如果其中一些 goroutine 已经自行终止，我们的计数就会过大，导致发送操作卡住。另一方面，如果这些 goroutine 又衍生出了其他 goroutine，我们的计数就会过小，导致某些 goroutine 无法感知到取消。一般来说，很难知道在任何给定时刻有多少个 goroutine 在为我们工作。此外，当一个 goroutine 从 `abort` 通道接收值时，它会消费该值，导致其他 goroutine 无法看到它。对于取消操作，我们需要一种可靠的机制，通过通道*广播*事件，以便许多 goroutine 能在事件发生时*看到*它，并且事后也能知道它*已经*发生。

回想一下，通道关闭且已发送的值被接收完毕后，后续的接收操作会立即进行，产生零值。我们可以利用这一点创建一个广播机制：不要在通道上发送值，*关闭*它。

我们可以通过几个简单的更改为上一节的 `du` 程序添加取消功能。首先，我们创建一个取消通道，该通道永远不发送值，但其关闭表示程序该停止工作了。我们还定义了一个工具函数 `cancelled`，它在被调用的瞬间检查或*轮询*取消状态。

```go
var done = make(chan struct{})

func cancelled() bool {
    select {
    case <-done:
        return true
    default:
        return false
    }
}
```

接下来，我们创建一个从标准输入读取的 goroutine，标准输入通常连接到终端。一旦读取到任何输入（例如，用户按下回车键），该 goroutine 通过关闭 `done` 通道来广播取消信号。

```go
// 当检测到输入时取消遍历。
go func() {
    os.Stdin.Read(make([]byte, 1)) // 读取单个字节
    close(done)
}()
```

现在我们需要让 goroutine 对取消做出响应。在主 goroutine 中，我们向 select 语句添加第三个 case，尝试从 `done` 通道接收。如果选中此 case，函数会返回，但在返回之前，它必须先耗尽 `fileSizes` 通道，丢弃所有值，直到通道关闭。这样做是为了确保任何活跃的 `walkDir` 调用能够运行完成，而不会因向 `fileSizes` 发送值而卡住。

```go
for {
    select {
    case <-done:
        // 耗尽 fileSizes 以允许现有 goroutine 完成。
        for range fileSizes {
            // 什么都不做。
        }
        return
    case size, ok := <-fileSizes:
        // ...
    }
}
```

`walkDir` goroutine 在开始时轮询取消状态，如果状态已设置则直接返回而不做任何事情。这使得取消事件后创建的所有 goroutine 变为空操作：

```go
func walkDir(dir string, n *sync.WaitGroup, fileSizes chan<- int64) {
    defer n.Done()
    if cancelled() {
        return
    }
    for _, entry := range dirents(dir) {
        // ...
    }
}
```

在 `walkDir` 的循环内再次轮询取消状态可能会有益处，以避免在取消事件后创建 goroutine。取消涉及权衡；更快的响应通常需要对程序逻辑进行更侵入式的更改。确保取消事件后不再发生任何昂贵操作可能需要更新代码中的许多位置，但通常只需在几个关键位置检查取消即可获得大部分收益。

对该程序进行少量性能分析显示，瓶颈在于 `dirents` 中获取信号量令牌。下面的 `select` 使该操作可取消，并将程序的典型取消延迟从数百毫秒降低到几十毫秒：

```go
func dirents(dir string) []os.FileInfo {
    select {
    case sema <- struct{}{}: // 获取令牌
    case <-done:
        return nil // 已取消
    }
    defer func() { <-sema }() // 释放令牌
    // ...读取目录...
}
```

现在，当取消发生时，所有后台 goroutine 会迅速停止，且 `main` 函数返回。当然，当 `main` 返回时，程序就会退出，因此很难分辨一个会自我清理的 main 函数和一个不会自我清理的 main 函数。我们可以在测试期间使用一个方便的技巧：如果在发生取消时不从 `main` 返回，而是执行一个 `panic` 调用，那么运行时会转储程序中每个 goroutine 的堆栈。如果 main goroutine 是唯一剩下的，那么它就已经自我清理完毕了。但如果还有其他 goroutine 残留，它们可能没有被正确取消，或者虽然已被取消但取消过程需要时间；稍作调查可能很有价值。panic 转储通常包含足够的信息来区分这些情况。

## 8.10 示例：聊天服务器

我们将用一个聊天服务器来结束本章，它允许多个用户相互广播文本消息。该程序中有四种 goroutine。`main` 和 `broadcaster` goroutine 各有一个实例，而对于每个客户端连接，则有一个 `handleConn` 和一个 `clientWriter` goroutine。broadcaster 很好地说明了 `select` 的用法，因为它必须响应三种不同类型的消息。

下面展示的 main goroutine 的工作是监听并接受来自客户端的传入网络连接。对于每一个连接，它都会创建一个新的 `handleConn` goroutine，就像我们在本章开头看到的并发 echo 服务器一样。

```go
func main() {
    listener, err := net.Listen("tcp", "localhost:8000")
    if err != nil {
        log.Fatal(err)
    }
    go broadcaster()
    for {
        conn, err := listener.Accept()
        if err != nil {
            log.Print(err)
            continue
        }
        go handleConn(conn)
    }
}
```

接下来是 broadcaster。其局部变量 `clients` 记录当前已连接客户端的集合。关于每个客户端记录的唯一信息是其传出消息通道的标识，稍后将详述。

```go
type client chan<- string // 一个传出消息通道

var (
    entering = make(chan client)
    leaving  = make(chan client)
    messages = make(chan string) // 所有传入的客户端消息
)

func broadcaster() {
    clients := make(map[client]bool) // 所有已连接的客户端
    for {
        select {
        case msg := <-messages:
            // 将传入消息广播给所有
            // 客户端的传出消息通道。
            for cli := range clients {
                cli <- msg
            }
        case cli := <-entering:
            clients[cli] = true
        case cli := <-leaving:
            delete(clients, cli)
            close(cli)
        }
    }
}
```

broadcaster 监听全局 `entering` 和 `leaving` 通道，以获取客户端到达和离开的通知。当它收到其中一个事件时，会更新 `clients` 集合，如果事件是离开，则关闭该客户端的传出消息通道。broadcaster 还监听全局 `messages` 通道上的事件，每个客户端将其所有传入消息发送到该通道。当 broadcaster 收到此类事件时，会将消息广播给每个已连接的客户端。

现在让我们看看每个客户端的 goroutine。`handleConn` 函数为其客户端创建一个新的传出消息通道，并通过 `entering` 通道向 broadcaster 宣布该客户端的到来。然后它从客户端读取每一行文本，将每一行发送到全局传入消息通道，并以前缀发送者的身份标识每条消息。一旦没有更多内容可从客户端读取，`handleConn` 就会通过 `leaving` 通道宣布该客户端的离开并关闭连接。

```go
func handleConn(conn net.Conn) {
    ch := make(chan string) // 传出客户端消息
    go clientWriter(conn, ch)
    who := conn.RemoteAddr().String()
    ch <- "You are " + who
    messages <- who + " has arrived"
    entering <- ch
    input := bufio.NewScanner(conn)
    for input.Scan() {
        messages <- who + ": " + input.Text()
    }
    // 注意：忽略了 input.Err() 的潜在错误
    leaving <- ch
    messages <- who + " has left"
    conn.Close()
}

func clientWriter(conn net.Conn, ch <-chan string) {
    for msg := range ch {
        fmt.Fprintln(conn, msg) // 注意：忽略网络错误
    }
}
```

此外，`handleConn` 为每个客户端创建一个 `clientWriter` goroutine，它接收广播给客户端传出消息通道的消息，并将它们写入客户端的网络连接。当 broadcaster 在收到 `leaving` 通知后关闭通道时，client writer 的循环就会终止。
