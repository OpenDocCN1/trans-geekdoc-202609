
# 网络地址转换

网络地址转换，即 NAT，是一种沿用多年的网络技术，它允许您在网络内部使用私有地址范围，然后在 NAT 网关（参见图 8-16）上将其转换为公共地址。其安全优势在于隐藏了内部系统上网所使用的内部 IP 地址，因为所有出站流量的源 IP 地址都被转换为 NAT 网关的地址。

![Image](img/f0362-01.jpg)

**图 8-16**  
NAT 用于隐藏内部网络并共享一个公共地址。

如前所述，内部网络通常使用所谓的私有地址范围，这些地址不能在互联网上使用。这意味着任何出站流量的数据包中的源 IP 地址都必须由 NAT 设备从私有 IP 地址转换为公共可路由地址。内部网络使用的三个私有 IP 地址范围如下：

- `10.0.0.0` 至 `10.255.255.255`
- `172.16.0.0` 至 `172.31.255.255`
- `192.168.0.0` 至 `192.168.255.255`

NAT 主要有两种类型：NAT 过载和静态 NAT。使用 `NAT 过载` 时，网络内的所有客户端都使用分配给 NAT 设备公共接口的一个公共地址来访问互联网。NAT 设备不仅将私有 IP 地址转换为公共 IP 地址，还转换端口地址信息。这被称为 `端口地址转换 (PAT)`，用于让 NAT 设备能够通过一个公共地址跟踪每个不同的客户端请求。

![Image](img/exam.jpg)

> **针对 Security+ 考试，请记住 NAT 用于隐藏内部 IP 地址方案，方法是让所有系统通过 NAT 设备发送流量，由 NAT 设备将数据包中的源 IP 地址替换为 NAT 设备的公共 IP 地址。**

`静态 NAT` 是指 NAT 设备上的单个公共 IP 地址映射到网络内部的单个私有地址。这通常用于处理发送给 DMZ 中服务器的入站请求，公司将这些服务器（如网站或 FTP 站点）发布到互联网。

# 网络准入控制

网络准入控制 (NAC) 是当今一项非常热门的技术，它允许您根据连接系统的状态来控制谁能获得有线或无线网络的访问权限。通过网络准入控制，您可以指定系统必须满足的条件才能获得网络访问权限。如果不满足这些条件，您可以将用户重定向到一个受限网络，以便他们修复系统。

例如，您可能要求系统要连接网络，必须安装防病毒软件，且病毒定义是最新的。您可能还要求系统启用了个人防火墙。如果不满足其中任何条件，NAC 系统会将客户端置于受限网络中，在那里他们通常可以应用补丁，或者在本例中，执行病毒定义更新。

当连接到受限网络时，客户端无法访问网络资源，因为从受限网络到私有公司网络的通信受到控制。图 8-17 显示了一个网络准入控制环境。

如今有许多使用 NAC 的场景。以下是您应该熟悉的一些场景，以及为 Security+ 考试需要了解的一些 NAC 概念：

## 连接到无线网络

连接到无线网络时，NAC 系统可能会要求客户端在获得网络访问权限前接受无线网络使用条款。

## 补丁状态

当客户端尝试连接到网络（无论是本地还是通过 VPN）时，会检查其健康状况，以确保安装了防病毒软件、病毒定义是最新的、系统打好了最新补丁，然后才允许连接。

## 连接到交换机

如果交换机符合 `802.1X` 标准，则可对其进行配置，以确保在允许客户端访问网络之前，由认证服务（如 `RADIUS`）对连接的客户端进行认证。

## 代理 vs. 无代理

网络准入控制解决方案可以是基于代理的，也可以是无代理的解决方案。基于代理的解决方案要求客户端安装客户端软件（即代理），该软件允许客户端向系统进行认证，并使 NAC 能够确定系统的健康状况。无代理解决方案不要求客户端系统安装代理软件。在这种情况下，NAC 检查通常由认证服务器作为登录过程的一部分来执行。

## 可溶解 vs. 永久

如果在客户端系统或设备上安装代理软件，则称为永久（或持久）代理，因为 NAC 系统可以持续监控系统的健康状况。可溶解代理是指不永久安装的代理。它是一段用于检查系统当前状态的软件，但不会被安装。

## 主机健康检查

NAC 解决方案的一项关键功能是它有能力检查尝试连接到网络的系统的健康状态。作为健康检查的一部分，NAC 解决方案可以验证操作系统是否为最新、是否安装了具有最新定义的防病毒软件，以及是否安装并启用了防火墙。

# 数据保护

保护网络基础设施的部分工作是确保你在数据上设置保护控制，以确保未经授权的个人无法访问敏感数据。你可以使用多种保护方法来帮助保护数据，例如数据丢失防护、加密，以及令牌化和掩码等功能。

## 数据丢失防护

如今，组织正在寻找实施数据丢失防护 (DLP) 解决方案的方法，这些解决方案旨在防止数据泄露到组织外部。DLP 涉及许多安全控制，以确保数据不会被有意或无意地泄露到组织外部。以下是实施 DLP 安全控制的一些关键领域：

- **USB 阻断** 你可以禁用系统上的 USB 设备使用，以便用户无法将数据复制到 USB 驱动器并将数据带出组织。你可以通过软件配置禁用 USB 设备，甚至可以在 BIOS 设置中从硬件层面禁用它们。

- **基于云的解决方案** 许多基于云的解决方案提供创建 DLP 策略的功能，以防止共享敏感数据。例如，`Office 365` 提供为不同类型的敏感信息（如财务数据和健康信息）创建 DLP 规则的功能。这些规则可以防止用户通过电子邮件发送敏感信息、将信息存储在云中，甚至在组织的内部网上共享信息。

- **电子邮件** 电子邮件系统是应用 DLP 的典型场景。为了防止用户在电子邮件中发送敏感信息，你可以使用具有 DLP 策略功能的电子邮件系统，或者购买/订阅为电子邮件系统提供 DLP 功能的服务。

## 掩码

数据掩码是应用程序中保护敏感数据的常用技术，它通过用掩码字符（如星号 `*`）替换数据来实现。一个常见的使用示例是在屏幕上显示客户数据时，将信用卡号掩盖，以便查看客户记录的员工不知道客户的信用卡号码。

## 加密

如果处理敏感数据，如 PII 数据、健康信息或财务数据，通常会寻求对数据进行加密，以便未经授权的个人无法访问这些敏感数据。你将在 `第 12 章` 和 `第 13 章` 中了解更多关于加密的内容，但目前需要知道的是，敏感数据应在以下情况下进行加密：

- **静态** 敏感数据应在存储时加密，无论它是在磁盘上还是存储在数据库中。
- **传输中/运动中** 当敏感数据从一个系统传输到另一个系统时，它应以加密格式传输。
- **处理中** 数据在处理过程中也可能被加密，直到信息实际被读取并需要解密时为止。

## 令牌化

你在 `第 7 章` 中了解过令牌化，但让我们在此复习一下。`Tokenization` 是指敏感数据与令牌服务一起存储，而不是与使用该敏感数据的应用程序数据一起存储。令牌服务还为该敏感数据提供一个无关的替代值。然后，令牌服务存储敏感数据与无关值之间的映射关系以供将来参考，以便在需要时查找。

## 权限管理

权限管理涉及在数据本身上设置保护控制，以管理可对数据执行的操作类型。例如，电子邮件系统可能会在电子邮件上设置权限管理保护，防止用户将邮件转发给其他人。或者，电影租赁公司可能会在电影上设置权限管理保护，允许你观看两天，但之后则不能观看。

## 哈希

正如你在 `第 2 章` 中所学，哈希是一种确保数据完整性的方法。你可以将数据通过哈希算法运行以生成哈希值。如果稍后你想验证文件未被修改，可以再次将文件通过哈希算法运行，看看是否计算出相同的哈希值（不同的内容会产生不同的哈希值）。

# 数据主权

`Data sovereignty` 是指数据受数据所在国家/地区法律管辖的概念。这是云计算中的一个主要顾虑，因为公司希望确保其数据位于其所在国家/地区内，以便了解管辖该数据的法律。

# 邮件网关

邮件网关是放置在 DMZ 中的设备或服务器，用于为组织发送和接收电子邮件。当互联网上的人员向组织内的员工发送电子邮件时，邮件会被定向到 DMZ 中的邮件网关。此时，邮件网关应对邮件进行病毒扫描和垃圾邮件过滤检查，以确保邮件是有效且无病毒的。一旦邮件通过病毒检查和垃圾邮件过滤，邮件网关会将邮件转发给内部邮件服务器。请记住，DMZ 和内部网络之间通常有一个防火墙，因此你需要在此防火墙上配置一条规则，仅允许从邮件网关到内部邮件服务器的邮件流量。

以下是你应在邮件网关中寻找的功能：

- **垃圾邮件过滤器** 应配置垃圾邮件过滤器以检查邮件是否为污染用户邮箱的垃圾邮件。
- **DLP** 数据丢失防护应是一项可在邮件网关上实施的功能，以便邮件网关确保出站电子邮件不包含财务或健康记录或任何公司机密等敏感信息。

## 加密

邮件网关可以与公司内部其他位置的邮件服务器，或合作伙伴公司的邮件服务器实现服务器到服务器的加密，这样发送给该公司的邮件在穿越互联网时就不会以明文形式传输。此外，`Cisco IronPort` 等产品通过在设备上托管加密邮件，直到远程用户连接并阅读，从而支持用户到用户的加密。

# 网络通信加密

网络安全的很大一部分在于确定是否要加密网络通信。许多不同的技术可用于加密网络通信。让我们来看看其中的一些选项。

## IPSec

IP Security，通常称为 IPSec，是一种协议，根据其配置方式提供不同的安全功能。IPSec 可以提供三种不同的安全服务：

- **Authentication（认证）** 确保 IP 数据包确实来自数据包声称的发送者（源地址）
- **Integrity（完整性）** 确保数据包在传输过程中未被篡改
- **Confidentiality（机密性）** 通过加密数据包确保数据包中的数据保密

Security+ 考试要求了解 IPSec 中提供这三种不同安全服务的各种协议：

- **ESP** 封装安全载荷协议可提供认证、完整性和机密性这三种服务。
- **AH** 认证头协议仅提供认证和完整性服务。不能用于加密 IP 数据包。
- **IKE** 互联网密钥交换协议用于在双方之间建立 `security association (SA)`。SA 是单向安全信道，因此如果双方都要发送数据，通常会建立两个 SA——每个方向一个。IKE 协议也是 IPSec 的密钥管理协议，允许双方交换加密密钥。

![Image](img/exam.jpg)

> **For the Security+ exam, remember the difference between IPSec protocols such as ESP, AH, and IKE.**

IPSec 可以配置为传输模式或隧道模式。传输模式用于主机到主机的加密，即如果两个系统想要加密它们之间的通信，则运行在传输模式。如果你希望加密一个网络上所有系统与另一个网络上所有系统之间的通信，可以将 IPSec 配置为隧道模式。隧道模式的好处是每个客户端系统或主机不需要配置 IPSec；只需在各网络的网关上配置 IPSec 即可。

## SSL/TLS 加密

传输层安全（TLS）加密是安全套接字层（SSL）加密的继任者，用于许多场景，如加密 Web 流量、邮件流量或 VoIP 流量。TLS 通过使用对称密钥加密双方之间的通信来提供机密性，并通过确保数据在传输过程中未被篡改来提供数据完整性。也可以使用非对称加密配置认证服务。你将在 `Chapters 12` 和 `13` 中了解更多关于对称和非对称加密的内容。

安全套接字层（SSL）/传输层安全（TLS）检查是当今讨论网络安全时的常见话题，因为 SSL 检查（或 TLS 检查）允许安全专业人员在 SSL/TLS 流量从发送方传输到接收方的过程中将其拦截，并解密数据以进行监控或检查。如果你的安全解决方案需要检查加密流量中的恶意内容，你可能需要这样做，因为黑客正利用加密作为隐藏恶意内容的手段。

## VPN 保障通信安全

VPN 技术使你能够在互联网等不受信任的网络上加密双方之间的通信。实施 VPN 解决方案时，可以将其配置为远程访问模式，由客户端与 VPN 服务器创建加密隧道。如果需要保护跨越互联网的两个网络之间的所有通信，可以配置站点到站点 VPN。使用站点到站点 VPN 时，安全隧道由每个办公地点的中心设备创建。每个网络上的所有客户端通过中心加密隧道发送数据，这样就不需要在每个客户端系统上配置 VPN 软件。

VPN 可用的另一个场景是无线网络。由于无线安全协议已知存在缺陷，你可以将无线网络视为不受信任的网络，要求无线客户端在访问企业网络前先与服务器建立 VPN 连接。

**Always-On（始终开启）** VPN 领域有一种新趋势，称为 `always-on VPN`。使用传统 VPN 解决方案时，用户必须通过在其系统上启动 VPN 软件来主动发起安全 VPN 连接，以便与企业网络通信。使用 `always-on VPN` 时，计算机被配置为一旦检测到互联网连接（通常在系统启动时）就自动与公司网络建立安全连接。`always-on VPN` 的好处是不依赖用户操作；系统自动建立连接，且该功能对用户透明。

**Split Tunnel vs. Full Tunnel（分隧道与全隧道）** 另一个 VPN 选项是将 VPN 实现为全隧道还是分隧道。

- **Full tunnel（全隧道）** 是传统实现方式，用户从远程网络（如家庭网络）启动 VPN 软件，在其系统与企业网络 VPN 服务器之间创建加密隧道。用户在使用全隧道时遇到的一个问题是无法访问其所连接的 LAN 上的任何资源（本例中为家庭网络）；例如，如果他们想打印到家庭打印机，将无法实现，因为从技术上讲，一旦建立 VPN 连接，用户就处于企业网络上，只能访问那些资源。
- **Split tunnel（分隧道）** 是一项 VPN 功能，允许用户在启动 VPN 软件后通过安全 VPN 隧道访问企业网络，但保留访问 LAN 资源的能力。分隧道功能可以指定哪些目标系统的流量通过隧道传输，哪些流量保留在 LAN 上。这称为 `split-include tunnel`。

**Remote Access vs. Site-to-Site（远程访问与站点到站点）** 在考察 VPN 解决方案时，你应该决定是需要远程访问解决方案还是站点到站点解决方案。远程访问解决方案涉及员工在笔记本电脑上使用 VPN 软件。当他们想要连接网络时，启动 VPN 软件，登录，然后连接到网络。如前所述，站点到站点解决方案免去了在每个员工系统上安装 VPN 软件的必要，因为当用户发送数据出网时，路由器会向另一位置创建 VPN 隧道，并通过该连接发送所有员工数据。这是卫星办公室需要连接到总部的常见场景。

**VPN Protocols（VPN 协议）** 你将在 `Chapters 12` 和 `13` 中了解更多关于用于执行加密的安全协议的细节，但为了完成 VPN 的讨论，我们必须讨论 VPN 解决方案使用的协议：

- **IPSec** 互联网协议安全（IPSec）是一种可用于加密所有 IP 流量并可用于加密 VPN 流量的协议。
- **SSL/TLS** 许多厂商提供的 VPN 解决方案使用 SSL/TLS 加密流量，这与使用数字证书加密 Web 流量非常相似（同样，你将在 `Chapters 12` 和 `13` 中了解这一点）。

# 网络安全概念

## VPN 协议

- **HTML5** HTML5 VPN 基于 SSL/TLS 加密，为我们提供了一种通过 Web 浏览器使用无客户端 VPN 连接来远程访问内部网络系统的方法。
- **第二层隧道协议 (L2TP)** L2TP VPN 协议使用 IPSec 对 VPN 隧道内的数据进行加密。

## API 注意事项

`应用程序编程接口 (API)` 是一个函数库，软件开发人员可以从其应用程序中调用这些函数。安全性的一部分在于确保内部应用程序所调用的任何第三方库都遵循安全最佳实践。您可以确保开发人员遵循安全编码实践，但也应测试第三方组件。

## 网络管理原则

要创建安全的网络环境，网络管理员遵循通用的安全网络管理原则至关重要。以下概述了网络管理员在致力于创建更安全环境时应遵循和使用的一些基本原则或安全技术：

- **基于规则的管理** 使用支持基于规则管理的技术（包括路由器、防火墙和代理服务器）来实施规则。务必测试允许或拒绝流量的规则，并确保规则按预期工作。
- **防火墙规则** 管理防火墙上的规则，仅允许所需流量通过防火墙。配置防火墙默认规则为拒绝所有，然后为允许通过的流量添加例外。
- **VLAN 管理** 务必利用 VLAN 在网络上创建通信边界。默认情况下，系统只能与同一 VLAN 中的其他系统通信，除非您配置路由器在 VLAN 之间路由。
- **安全路由器配置** 确保以安全方式配置路由器。这包括创建访问控制列表、设置设备本地访问密码、设置远程访问密码，以及仅使用安全的远程访问协议（如 `SSH`）。
- **访问控制列表** 在可能的情况下实施 ACL。ACL 通常应用于文件和文件夹权限，以及路由器和防火墙。
- **802.1X** 实施此常见认证协议，它通过要求客户端针对中央认证数据库（如 `RADIUS` 服务器）进行认证，来控制谁能获得有线或无线网络的访问权限。
- **隐性拒绝** 尽可能将路由器和防火墙配置为隐性拒绝。这意味着，除非您有专门添加到设备的规则允许流量进入网络，否则路由器和防火墙将自动拒绝该流量。文件夹和文件的权限也应具有隐性拒绝规则。
- **网络分段/隔离** 如前所述，将网络划分为较小的网络段，然后控制从一个网络段到另一个网络段的流量至关重要。
- **日志分析** 定期审查日志文件是安全性中一个被忽视的方面。重要的是要确保在所有关键系统和设备上实施日志记录，并定期审查日志。
- **网桥** 网桥技术使一个网络上的系统能够连接到另一个网络上的系统。网桥的一个例子是无线网桥，两个网络通过无线链路连接在一起。从安全角度来看，要记录正在使用的任何网桥技术，以便了解存在的所有通信通道。
- **SSL 加速器/TLS 加速器** 在大量使用加密的环境中，您可以通过使用 SSL/TLS 加速器来避免拖慢系统处理器的速度，该加速器是一张安装在系统中的卡，拥有自己的处理器来处理系统的加密功能。
