
当然，`MustCompile` 不应用于不受信的输入值。`Must` 前缀是此类函数的常见命名约定，如 `template.Must`（见 4.6 节）。

当 panic 发生时，所有延迟函数按逆序运行，从栈顶函数的延迟调用开始，一直执行到 `main`，如下程序所示：

```go
}

```

## 5.10 Recover（恢复）

放弃运行通常是对 panic 的正确响应，但并非总是如此。有时可能以某种方式恢复，或者至少在退出前清理烂摊子。例如，遇到意外问题的 Web 服务器可以关闭连接，而不是让客户端一直挂起；在开发阶段，它甚至可能将错误报告给客户端。

如果在延迟函数中调用内置的 `recover` 函数，且包含该 `defer` 语句的函数正在 panic，`recover` 会结束当前的 panic 状态并返回 panic 的值。导致 panic 的函数不会从离开的地方继续执行，而是正常返回。如果在其他任何时候调用 `recover`，它没有任何效果，并返回 `nil`。

为了说明这一点，请考虑语言解析器的开发过程。即使它看起来工作良好，鉴于其工作的复杂性，bug 仍可能潜伏在晦涩的边缘情况中。我们可能更希望解析器将这些 panic 转化为普通的解析错误，而不是直接崩溃，或许还能附带一条额外信息，敦促用户提交 bug 报告。

```go
func Parse(input string) (s *Syntax, err error) {
    defer func() {
        if p := recover(); p != nil {
            err = fmt.Errorf("internal error: %v", p)
        }
    }()
    // ...parser...
}
```

`Parse` 中的延迟函数从 panic 中恢复，利用 panic 值构造一条错误信息；更复杂的版本可能会使用 `runtime.Stack` 包含完整的调用堆栈。然后延迟函数将错误赋值给 `err` 结果参数，该参数会被返回给调用者。

不加选择地从 panic 中恢复是一种可疑的做法，因为 panic 后包变量的状态很少有明确的定义或文档说明。也许关键的数据结构更新未完成，文件或网络连接已打开但未关闭，或者锁已获取但未释放。此外，通过用（例如）日志文件中的一行记录来替代崩溃，不加选择的恢复可能导致 bug 被忽视。

在同一个包内从 panic 中恢复有助于简化复杂或意外错误的处理，但作为一条通用规则，你不应该试图从另一个包的 panic 中恢复。公共 API 应该将失败作为 `error` 报告。同样，你也不应该恢复可能经过你不维护的函数（如调用者提供的回调函数）的 panic，因为你无法判断其安全性。

例如，`net/http` 包提供了一个 Web 服务器，它将传入的请求分派给用户提供的处理函数。服务器会调用 `recover`、打印堆栈跟踪并继续服务，而不是让这些处理函数中的 panic 杀死进程。这在实践中很方便，但确实存在泄露资源或让失败的处理函数处于未指定状态的风险，这可能导致其他问题。

基于上述所有原因，最安全的做法是有选择地恢复，甚至不恢复。换句话说，只恢复那些*打算*被恢复的 panic，这应该很少见。这种意图可以通过为 panic 值使用一个独特的、未导出的类型来编码，并检测 `recover` 返回的值是否具有该类型。（我们将在下一个示例中看到一种实现方式。）如果是，我们将 panic 作为普通的 `error` 报告；如果不是，我们用相同的值调用 `panic` 以恢复 panic 状态。

下面的示例是 `title` 程序的一个变体，如果 HTML 文档包含多个 `<title>` 元素，它会报告错误。如果是这种情况，它会通过使用特殊类型 `bailout` 的值调用 `panic` 来中止递归。

`gopl.io/ch5/title3`

```go
func soleTitle(doc *html.Node) (title string, err error) {
    type bailout struct{}

    defer func() {
        switch p := recover(); p {
        case nil:
            // 无 panic
        case bailout{}:
            // "预期的" panic
            err = fmt.Errorf("multiple title elements")
        default:
            panic(p) // 意外的 panic；继续 panic
        }
    }()

    // 如果发现多个非空标题，则跳出递归。
    forEachNode(doc, func(n *html.Node) {
        if n.Type == html.ElementNode && n.Data == "title" &&
            n.FirstChild != nil {
            if title != "" {
                panic(bailout{}) // 多个 title 元素
            }
            title = n.FirstChild.Data
        }
    }, nil)
    if title == "" {
        return "", fmt.Errorf("no title element")
    }
    return title, nil
}
```

延迟的处理函数调用 `recover`，检查 panic 值，如果值为 `bailout{}` 则报告普通错误。所有其他非 nil 值都表示意外的 panic，在这种情况下处理函数会用该值调用 `panic`，撤销 `recover` 的效果并恢复原始的 panic 状态。（这个示例在一定程度上违背了我们关于不将 panic 用于“预期”错误的建议，但它紧凑地说明了其中的机制。）

某些情况无法恢复。例如，内存耗尽会导致 Go 运行时以致命错误终止程序。

**练习 5.19：** 使用 `panic` 和 `recover` 编写一个不包含 `return` 语句却能返回非零值的函数。

# 6. Methods（方法）

自 1990 年代初以来，面向对象编程（OOP）一直是工业界和教育界的主导编程范式，此后开发的几乎所有广泛使用的语言都包含了对它的支持。Go 也不例外。

尽管面向对象编程没有公认的统一定义，但就我们而言，*对象* 简单来说就是一个拥有方法的值或变量，而 *方法* 是与特定类型关联的函数。面向对象程序就是使用方法来表达每个数据结构的属性和操作的程序，这样客户端就不需要直接访问对象的表示。

在前几章中，我们已经经常使用标准库中的方法，比如 `time.Duration` 类型的 `Seconds` 方法：

```go
const day = 24 * time.Hour
fmt.Println(day.Seconds()) // "86400"
```

我们还在 第 2.5 节 中定义了自己的一个方法，即 `Celsius` 类型的 `String` 方法：

```go
func (c Celsius) String() string { return fmt.Sprintf("%g°C", c) }
```

在本章中，作为面向对象编程两章中的第一章，我们将展示如何有效地定义和使用方法。我们还将介绍面向对象编程的两个关键原则：*封装* 和 *组合*。

## 6.1 Method Declarations（方法声明）

方法的声明是在普通函数声明的变体中，在函数名之前多出一个参数。该参数将该函数附加到该参数的类型上。

让我们在一个简单的平面几何包中编写第一个方法：

## gopl.io/ch6/geometry

```go
package geometry

import "math"

type Point struct{ X, Y float64 }

// 传统函数
func Distance(p, q Point) float64 {
    return math.Hypot(q.X-p.X, q.Y-p.Y)
}

// 同样的功能，但作为 Point 类型的方法
func (p Point) Distance(q Point) float64 {
    return math.Hypot(q.X-p.X, q.Y-p.Y)
}
```

额外的参数 `p` 称为方法的 **接收器**，这是早期面向对象语言的遗留术语，那些语言将调用方法描述为“向对象发送消息”。

在 Go 中，我们不像其他语言那样使用 `this` 或 `self` 这种特殊名称作为接收器；我们选择接收器名称的方式与选择其他参数名称的方式相同。由于接收器名称会被频繁使用，最好选择简短的名称，并在所有方法中保持一致。常见的做法是使用类型名称的首字母，例如 `Point` 使用 `p`。

在方法调用中，接收器实参出现在方法名之前。这与声明时的顺序一致，在声明中接收器参数出现在方法名之前。

```go
p := Point{1, 2}
q := Point{4, 6}
fmt.Println(Distance(p, q)) // "5", 函数调用
fmt.Println(p.Distance(q))  // "5", 方法调用
```

上述两个名为 `Distance` 的函数声明之间不存在冲突。第一个声明了一个包级函数 `geometry.Distance`。第二个声明了 `Point` 类型的方法，因此其名称为 `Point.Distance`。

表达式 `p.Distance` 称为 **选择器**，因为它为类型为 `Point` 的接收器 `p` 选择了合适的 `Distance` 方法。选择器也用于选择结构体类型的字段，如 `p.X`。由于方法和字段处于同一命名空间，在结构体类型 `Point` 上声明方法 `X` 会产生歧义，编译器会报错拒绝。

因为每个类型都有自己的方法命名空间，我们可以为其他类型的方法使用相同的名称 `Distance`。让我们定义一个表示线段序列的 `Path` 类型，并为它也定义一个 `Distance` 方法。

```go
// Path 表示由直线连接各点形成的路径。
type Path []Point

// Distance 返回沿路径行进的距离。
func (path Path) Distance() float64 {
    sum := 0.0
    for i := range path {
        if i > 0 {
            sum += path[i-1].Distance(path[i])
        }
    }
    return sum
}
```

`Path` 是一个命名的切片类型，而非像 `Point` 那样的结构体类型，但我们仍然可以为它定义方法。在允许将方法关联到任意类型这点上，Go 与许多其他面向对象语言不同。为数字、字符串、切片、映射等简单类型，有时甚至为函数定义额外的行为通常很方便。只要在同一个包中定义了命名类型，且其底层类型既不是指针也不是接口，就可以为其声明方法。

这两个 `Distance` 方法拥有不同的类型。它们彼此毫无关联，尽管 `Path.Distance` 在内部使用 `Point.Distance` 来计算连接相邻点的每个线段的长度。

让我们调用这个新方法来计算一个直角三角形的周长：

```go
perim := Path{
    {1, 1},
    {5, 1},
    {5, 4},
    {1, 1},
}
fmt.Println(perim.Distance()) // "12"
```

![Image](img/triangle.png)

在上述两个调用名为 `Distance` 的方法的代码中，编译器根据方法名和接收器的类型来决定调用哪个函数。在第一个调用中，`path[i-1]` 的类型是 `Point`，因此调用 `Point.Distance`；在第二个调用中，`perim` 的类型是 `Path`，因此调用 `Path.Distance`。

给定类型的所有方法必须具有唯一的名称，但不同类型可以为方法使用相同的名称，就像 `Point` 和 `Path` 的 `Distance` 方法那样；无需通过限定函数名（例如 `PathDistance`）来消除歧义。这里我们看到了使用方法而非普通函数的第一个好处：方法名可以更短。对于包外部的调用，这一优势更加明显，因为它们既可以使用较短的名称，又可以省略包名：

```go
import "gopl.io/ch6/geometry"

perim := geometry.Path{{1, 1}, {5, 1}, {5, 4}, {1, 1}}
fmt.Println(geometry.PathDistance(perim)) // "12", 独立函数
fmt.Println(perim.Distance())             // "12", geometry.Path 的方法
```

## 6.2 指针接收器的方法

因为调用函数会对每个实参值进行拷贝，如果函数需要更新变量，或者实参过大导致我们希望避免拷贝，就必须传递变量的地址，即使用指针。对于需要更新接收器变量的方法也是如此：我们将它们绑定到指针类型，例如 `*Point`。

```go
func (p *Point) ScaleBy(factor float64) {
    p.X *= factor
    p.Y *= factor
}
```

该方法的名称是 `(*Point).ScaleBy`。括号是必需的；没有括号，该表达式会被解析为 `*(Point.ScaleBy)`。

在实际编程中，惯例规定：如果 `Point` 的任意方法使用了指针接收器，那么 `Point` 的 **所有** 方法都应该使用指针接收器，即使是那些并不严格需要指针接收器的方法。我们在 `Point` 上打破了这条规则，以便展示两种方法。

只有命名类型（`Point`）及其指针（`*Point`）才能出现在接收器声明中。此外，为了避免歧义，不允许在本身就是指针类型的命名类型上声明方法：

```go
type P *int
func (P) f() { /* ... */ } // 编译错误：无效的接收器类型
```

`(*Point).ScaleBy` 方法可以通过提供 `*Point` 接收器来调用，如下所示：

```go
r := &Point{1, 2}
r.ScaleBy(2)
fmt.Println(*r) // "{2, 4}"
```

或这样：
