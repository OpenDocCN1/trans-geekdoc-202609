
有时在将输入送入模型之前，会对模型的输入进行修改、增强或构建，就像哈希示例那样。应用于输入的转换中包含有价值的信息。应用于训练数据集输入的转换，如果模型部署在生产环境中，也必须应用于输入。因此，转换代码是在进行预测时流水线的一部分。BigQuery 有一个优雅的解决方案来解决这个问题，称为 `TRANSFORM` 子句，它是 `CREATE_MODEL` 函数的一部分：

```
CREATE OR REPLACE MODEL m
  TRANSFORM(ML.FEATURE_CROSS(STRUCT(f1, f2)) as cross_f,
            ML.QUANTILE_BUCKETIZE(f3) OVER() as buckets,
            label_col)
  OPTIONS(model_type='linear_reg', input_label_cols=['label_col'])
AS SELECT * FROM t
```

在前面的示例 SQL 中，我们正在对 `f1` 和 `f2` 创建一个“特征交叉”转换，第二个转换是对特征 `f3` 进行分位数分桶。这些转换将应用于输入字段 `f1`、`f2` 和 `f3`，以创建名为“cross_f”和“buckets”的新特征。BigQuery ML 将自动将此转换代码添加到构建的模型中。因此，在预测期间，当你传递输入 `f1`、`f2` 和 `f3` 时，它将在将输入发送到模型之前自动执行这些转换。

BigQuery 提供了许多此类有用的转换，如 `POLYNOMIAL_EXPAND`、`FEATURE_CROSS`、`NGRAMS`、`QUANTILE_BUCKET`、`HASH_BUCKETIZE`、`MIN_MAX_SCALER` 和 `STANDARD_SCALER`。

有关 `TRANSFORM` 子句的更多详细信息，请参阅文档：

`https://cloud.google.com/bigquery-ml/docs/reference/standard-sql/bigqueryml-preprocessing-functions`

此设计模式的注意事项是，带有转换的模型将无法在 BigQuery ML 之外工作，例如，如果你将模型导出到 Vertex AI。

#### 总结

BigQuery 是一项重要的服务，它彻底改变了 SQL 社区中 ML 的使用方式。BigQuery ML 实现了机器学习的民主化，使其可供更多人使用。

在本章中，我们了解了如何使用 SQL 执行 ML 流水线的所有操作。我们还学习了如何直接使用 SQL 对输入值应用转换，从而减少创建模型的时间。虽然 BigQueryML 是一项独立的服务，但它与 Vertex AI 高度互操作。最后，我们还看到了一些 BigQuery ML 独有的有趣设计模式。

#### 考试要点

*   **理解 BigQuery 和 ML。** 了解 BigQuery 的历史以及将机器学习引入数据仓库、数据分析以及任何熟悉 SQL 人员的创新。学习如何使用 SQL 进行训练、预测和提供模型解释。

*   **能够解释 BigQuery ML 和 Vertex AI 之间的区别以及它们如何协同工作。** 这些服务提供相似的功能，但面向不同的用户设计。BigQuery ML 面向分析师和任何熟悉 SQL 的人设计，而 Vertex AI 面向 ML 工程师设计。了解使这两项服务之间无缝协作的各种集成点。

*   **理解 BigQuery 设计模式。** BigQuery 拥有解决机器学习中反复出现问题的优雅方案。哈希、转换和无服务器预测很容易应用到你的 ML 流水线中。
