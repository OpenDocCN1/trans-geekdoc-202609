
# 5.2 递归

```go
package html

type Node struct {
    Type                    NodeType
    Data                    string
    Attr                    []Attribute
    FirstChild, NextSibling *Node
}

type NodeType int32

const (
    ErrorNode NodeType = iota
    TextNode
    DocumentNode
    ElementNode
    CommentNode
    DoctypeNode
)

type Attribute struct {
    Key, Val string
}

func Parse(r io.Reader) (*Node, error)
```

`main` 函数将标准输入解析为 HTML，使用递归函数 `visit` 提取链接，并打印每个发现的链接：

```go
package main

import (
    "fmt"
    "os"

    "golang.org/x/net/html"
)

func main() {
    doc, err := html.Parse(os.Stdin)
    if err != nil {
        fmt.Fprintf(os.Stderr, "findlinks1: %v\n", err)
        os.Exit(1)
    }
    for _, link := range visit(nil, doc) {
        fmt.Println(link)
    }
}
```

`visit` 函数遍历 HTML 节点树，从每个锚元素 `<a href='...'>` 的 `href` 属性中提取链接，将链接追加到一个字符串切片中，并返回生成的切片：

```go
// visit appends to links each link found in n and returns the result.
func visit(links []string, n *html.Node) []string {
    if n.Type == html.ElementNode && n.Data == "a" {
        for _, a := range n.Attr {
            if a.Key == "href" {
                links = append(links, a.Val)
            }
        }
    }
    for c := n.FirstChild; c != nil; c = c.NextSibling {
        links = visit(links, c)
    }
    return links
}
```

要遍历节点 `n` 的树，`visit` 会为 `n` 的每个子节点递归调用自身，这些子节点保存在 `FirstChild` 链表中。

下一个程序使用对 HTML 节点树的递归来以大纲形式打印树的结构。当它遇到每个元素时，会将元素的标签压入栈，然后打印该栈。

gopl.io/ch5/outline

```go
func main() {
    doc, err := html.Parse(os.Stdin)
    if err != nil {
        fmt.Fprintf(os.Stderr, "outline: %v\n", err)
        os.Exit(1)
    }
    outline(nil, doc)
}

func outline(stack []string, n *html.Node) {
    if n.Type == html.ElementNode {
        stack = append(stack, n.Data) // push tag
        fmt.Println(stack)
    }
    for c := n.FirstChild; c != nil; c = c.NextSibling {
        outline(stack, c)
    }
}
```

注意一个细微点：虽然 `outline` 将元素“压入” `stack`，但没有相应的弹出操作。当 `outline` 递归调用自身时，被调用者接收到的是 `stack` 的副本。虽然被调用者可能向该切片追加元素，修改其底层数组，甚至分配新数组，但它不会修改调用者可见的初始元素，因此当函数返回时，调用者的 `stack` 与调用前完全相同。

这是 `https://golang.org` 的大纲，同样为简洁起见进行了编辑：


通过尝试 `outline` 可以看出，大多数 HTML 文档只需几层递归即可处理，但构造需要极深递归的病态网页并不难。

许多编程语言实现使用固定大小的函数调用栈；64KB 到 2MB 是典型大小。固定大小的栈限制了递归的深度，因此在递归遍历大型数据结构时必须小心避免栈溢出；固定大小的栈甚至可能构成安全风险。相比之下，典型的 Go 实现使用可变大小的栈，起始很小，按需增长，上限可达 GB 级别。这让我们能安全地使用递归，无需担心溢出。

# 5.3 多返回值

函数可以返回多个结果。我们已经见过许多标准库函数返回两个值：期望的计算结果，以及一个指示计算是否成功的错误值或布尔值。下面的示例展示了如何编写自己的多返回值函数。

下面的程序是 `findlinks` 的一个变体，它自身发起 HTTP 请求，因此不再需要运行 `fetch`。因为 HTTP 和解析操作都可能失败，`findLinks` 声明了两个返回值：发现的链接列表和一个错误。顺便提一下，HTML 解析器通常能从错误输入中恢复并构建包含错误节点的文档，所以 `Parse` 很少失败；失败时通常是由于底层 I/O 错误。

gopl.io/ch5/findlinks2

```go
func main() {
    for _, url := range os.Args[1:] {
        links, err := findLinks(url)
        if err != nil {
            fmt.Fprintf(os.Stderr, "findlinks2: %v\n", err)
            continue
        }
        for _, link := range links {
            fmt.Println(link)
        }
    }
}

// findLinks performs an HTTP GET request for url, parses the
// response as HTML, and extracts and returns the links.
func findLinks(url string) ([]string, error) {
    resp, err := http.Get(url)
    if err != nil {
        return nil, err
    }
    if resp.StatusCode != http.StatusOK {
        resp.Body.Close()
        return nil, fmt.Errorf("getting %s: %s", url, resp.Status)
    }
    doc, err := html.Parse(resp.Body)
    resp.Body.Close()
    if err != nil {
        return nil, fmt.Errorf("parsing %s as HTML: %v", url, err)
    }
    return visit(nil, doc), nil
}
```

`findLinks` 中有四条 `return` 语句，每条都返回一对值。前三条 `return` 将 `http` 和 `html` 包的底层错误传递给调用者。第一种情况直接返回错误；第二、三种情况通过 `fmt.Errorf`（§7.8）附加上下文信息后返回。如果 `findLinks` 成功，最后一条 `return` 语句返回链接切片，错误为 `nil`。

我们必须确保关闭 `resp.Body`，以便在出错时也能正确释放网络资源。Go 的垃圾回收器会回收未使用的内存，但不要指望它会释放未使用的操作系统资源，如打开的文件和网络连接。这些资源应显式关闭。

调用多返回值函数的结果是一个值元组。如果要使用其中的任何值，调用者必须显式地将它们赋给变量：

```go
links, err := findLinks(url)
```

要忽略其中一个值，可将其赋给空标识符：

```go
links, _ := findLinks(url) // errors ignored
```

多返回值调用的结果本身可以从一个（多返回值的）调用函数中返回，如这个记录参数日志的函数，其行为类似 `findLinks`：

```go
func findLinksLog(url string) ([]string, error) {
    log.Printf("findLinks %s", url)
    return findLinks(url)
}
```

## 多值调用与错误处理

### 多值调用

多值调用可以作为唯一参数出现在多参数函数的调用中。虽然在生产代码中很少使用，但此功能在调试时有时很方便，因为它允许我们使用单个语句打印调用的所有结果。下面两条打印语句效果相同。

```go
log.Println(findLinks(url))

links, err := findLinks(url)
log.Println(links, err)
```

精心选择的名称可以记录函数结果的意义。当函数返回多个相同类型的结果时，名称特别有价值，例如：

```go
func Size(rect image.Rectangle) (width, height int)
func Split(path string) (dir, file string)
func HourMinSec(t time.Time) (hour, minute, second int)
```

但并不总是有必要仅为文档目的而命名多个结果。例如，惯例规定最后一个 `bool` 结果表示成功；`error` 结果通常不需要解释。

在具有命名结果的函数中，`return` 语句的操作数可以省略。这称为**裸返回**。

```go
// CountWordsAndImages 对 HTML 文档 url 执行 HTTP GET 请求，
// 并返回其中的单词数和图像数。
func CountWordsAndImages(url string) (words, images int, err error) {
    resp, err := http.Get(url)
    if err != nil {
        return
    }

    doc, err := html.Parse(resp.Body)
    resp.Body.Close()
    if err != nil {
        err = fmt.Errorf("parsing HTML: %s", err)
        return
    }
    words, images = countWordsAndImages(doc)
    return
}

func countWordsAndImages(n *html.Node) (words, images int) { /* ... */ }
```

裸返回是按顺序返回每个命名结果变量的简写方式，因此在上述函数中，每个 `return` 语句等同于：

```go
return words, images, err
```

在像这样的函数中，有许多返回语句和多个结果，裸返回可以减少代码重复，但它们很少使代码更容易理解。例如，乍一看并不明显，两个早期的 `return` 等同于 `return 0, 0, err`（因为结果变量 `words` 和 `images` 被初始化为其零值），而最后的 `return` 等同于 `return words, images, nil`。因此，最好少用裸返回。

# 5.4 错误

有些函数总能成功完成其任务。例如，`strings.Contains` 和 `strconv.FormatBool` 对所有可能的参数值都有明确定义的结果，且不会失败——除非发生灾难性且不可预测的场景，如内存耗尽，此时症状远离原因，且几乎没有恢复希望。

其他函数只要满足其前提条件就总能成功。例如，`time.Date` 函数总是根据其组成部分——年、月等——构造一个 `time.Time`，除非最后一个参数（时区）为 `nil`，这种情况下它会 panic。这种 panic 是调用代码中存在 bug 的明确标志，在编写良好的程序中永远不应发生。

对于许多其他函数，即使在编写良好的程序中，成功也无法保证，因为这取决于程序员无法控制的因素。例如，任何执行 I/O 的函数都必须面对错误的可能性，只有天真的程序员才会相信简单的读写不会失败。事实上，正是当最可靠的操作意外失败时，我们最需要知道原因。

因此，错误是包 API 或应用程序用户界面的重要组成部分，失败只是几种预期行为之一。这是 Go 处理错误的方法。

对于失败属于预期行为的函数，会返回一个额外的结果，通常是最后一个。如果失败只有一种可能的原因，该结果是一个布尔值，通常称为 `ok`，如这个总是成功的缓存查找示例，除非该键没有条目：

```go
value, ok := cache.Lookup(key)
if !ok {
    // ...cache[key] does not exist...
}
```

更常见的是，特别是对于 I/O，失败可能有多种原因，调用者需要解释。在这种情况下，额外结果的类型是 `error`。

内置类型 `error` 是一个接口类型。我们将在第 7 章中看到这意味着什么及其对错误处理的影响。目前只需知道 `error` 可能为 `nil` 或非 `nil`，`nil` 表示成功，非 `nil` 表示失败，并且非 `nil` 的 `error` 有一个错误消息字符串，我们可以通过调用其 `Error` 方法获取，或通过调用 `fmt.Println(err)` 或 `fmt.Printf("%v", err)` 打印。

通常当函数返回非 `nil` 错误时，其其他结果未定义且应被忽略。然而，少数函数可能在错误情况下返回部分结果。例如，如果从文件读取时发生错误，`Read` 调用会返回它能够读取的字节数和一个描述问题的 `error` 值。对于正确行为，某些调用者可能需要在处理错误前处理不完整的数据，因此此类函数清楚地记录其结果非常重要。
