## 非对称密码学

第 6 章中的“现代密码学”部分介绍了私钥（对称）和公钥（非对称）密码学背后的基本原理。您了解到，对称密钥密码体制要求通信双方拥有相同的共享密钥，从而产生了安全密钥分发的问题。您还了解到，非对称密码体制通过使用公钥和私钥对来促进安全通信，避免了复杂密钥分发系统的开销，从而绕过了这一障碍。这些系统的安全性依赖于逆转单向函数的难度。

在以下章节中，我们将更详细地探讨公钥密码学的概念，并了解当今使用的三种较常见的公钥密码体制：Rivest–Shamir–Adleman（`RSA`）、El Gamal 和椭圆曲线密码学（`ECC`）。

### 公钥和私钥

回顾第 6 章可知，`公钥密码体制` 依赖于分配给密码体制每个用户的一对密钥。每个用户都维护一个公钥和一个私钥。顾名思义，公钥密码体制用户将其公钥免费提供给任何他们想要通信的人。第三方仅持有公钥并不会给密码体制带来任何弱点。另一方面，私钥仅供拥有密钥的个人单独使用。它绝不与任何其他密码体制用户共享。

公钥密码体制用户之间的正常通信非常简单直接。图 7.1 展示了通用流程。

请注意，该过程不需要共享私钥。发送方使用接收方的公钥加密明文消息（`P`）以创建密文消息（`C`）。当接收方打开密文消息时，他们使用自己的私钥对其进行解密，以重新创建原始明文消息。

一旦发送方使用接收方的公钥加密了消息，如果不知道接收方的私钥（用于生成消息的公私钥对的另一半），任何用户（包括发送方）都无法解密该消息。这就是公钥密码学的精妙之处——公钥可以通过不安全的通信自由共享，然后用于在先前互不相识的用户之间创建安全通信通道。

您在上一章中还了解到，公钥密码学涉及更高程度的计算复杂性。公钥系统中使用的密钥必须比私钥系统中使用的密钥更长，才能产生具有同等强度的密码体制。

### RSA

最著名的公钥密码体制以其创建者的名字命名。1977 年，Ronald Rivest、Adi Shamir 和 Leonard Adleman 提出了 `RSA 公钥算法`，该算法至今仍是全球标准。他们为该算法申请了专利，并成立了一个名为 RSA Security 的商业企业，以开发其安全技术的主流实现。如今，RSA 算法已发布到公共领域，并被广泛用于安全通信。

RSA 算法依赖于分解大素数所固有的计算难度。密码体制的每个用户都使用以下步骤中描述的算法生成一对公钥和私钥：

1.  选择两个大素数（每个约 200 位），标记为 `p` 和 `q`。

2.  计算这两个数的乘积：`n = p * q`。

3.  选择一个数 `e`，满足以下两个要求：

    1.  `e` 小于 `n`。

    2.  `e` 和 `(p – 1)(q – 1)` 互质——即这两个数除了 1 之外没有其他公因数。

4.  找到一个数 `d`，使得 `(ed – 1) mod (p – 1)(q – 1) = 1`。

5.  将 `e` 和 `n` 作为公钥分发给所有密码体制用户。保密 `d` 作为私钥。

如果 Alice 想要向 Bob 发送加密消息，她会使用以下公式从明文（`P`）生成密文（`C`）（其中 `e` 是 Bob 的公钥，`n` 是密钥生成过程中创建的 `p` 和 `q` 的乘积）：

```
C = Pe mod n
```

当 Bob 收到消息时，他执行以下计算以检索明文消息：

```
P = Cd mod n
```

### El Gamal

在第 6 章中，您了解了 Diffie–Hellman 算法如何利用大整数和模运算，促进在不安全通信信道上安全交换密钥。1985 年，T. El Gamal 博士发表了一篇文章，描述了如何将 Diffie–Hellman 密钥交换算法背后的数学原理扩展为支持用于加密和解密消息的完整公钥密码体制。

在发布时，El Gamal 相对于 RSA 算法的主要优势之一是它被发布到了公共领域。El Gamal 博士没有为其对 Diffie-Hellman 的扩展申请专利，因此它可自由使用，这与当时已获专利的 RSA 技术不同。（RSA 于 2000 年将其算法发布到了公共领域。）

然而，El Gamal 也有一个主要缺点——该算法会使其加密的任何消息长度加倍。在加密长消息或将通过窄带宽通信线路传输的数据时，这构成了一个主要困难。

### 椭圆曲线

同样在 1985 年，两位数学家——来自华盛顿大学的 Neal Koblitz 和来自 IBM 的 Victor Miller——独立提出了将 `椭圆曲线密码学`（`ECC`）理论应用于开发安全密码系统。

任何椭圆曲线都可以由以下方程定义：

```
y2 = x3 + ax + b
```

在该方程中，`x`、`y`、`a` 和 `b` 均为实数。每条椭圆曲线都有一个对应的 `椭圆曲线群`，由椭圆曲线上的点以及位于无穷远处的点 `O` 组成。同一椭圆曲线群内的两个点（`P` 和 `Q`）可以通过椭圆曲线加法算法相加。该运算非常简单地表示如下：

```
P + Q
```

通过假设 `Q` 是 `P` 的倍数，即以下情况，可以将此问题扩展为涉及乘法：

```
Q = xP
```

计算机科学家和数学家认为，即使已知 `P` 和 `Q`，找到 `x` 也极其困难。这个被称为椭圆曲线离散对数问题的难题，构成了椭圆曲线密码学的基础。人们普遍认为，该问题比 RSA 密码系统所依赖的大整数分解难题，以及 Diffie-Hellman 和 El Gamal 所利用的标准离散对数问题更难求解。侧边栏“密钥长度的重要性”中的表格数据直观地说明了这一点：1,024 位的 RSA 密钥在密码学强度上等同于 160 位的椭圆曲线密码系统密钥。

## 哈希函数

本章后面将介绍密码系统如何实现数字签名，以证明消息源自特定用户，并确保消息在双方传输过程中未被篡改。在完全理解该概念之前，我们必须先解释*哈希函数*的概念。我们将探讨哈希函数的基础知识，并了解现代数字签名算法中使用的几种常见哈希函数。

哈希函数的目的非常简单——它们接收一个可能很长的消息，并根据消息内容生成一个唯一的输出值。该值通常称为*消息摘要*。消息发送者可以生成消息摘要，并将其与完整消息一起传输给接收者，主要出于以下两个原因。

首先，接收者可以使用相同的哈希函数，从完整消息中重新计算消息摘要。然后将计算出的摘要与传输的摘要进行比较，以确保发送者发送的消息与接收者收到的消息完全一致。如果两个摘要不匹配，则意味着消息在传输过程中被篡改。重要的是，消息必须*完全*相同，摘要才会匹配。如果消息在空格、标点或内容上哪怕只有细微差别，摘要值也会完全不同。无法通过比较摘要来判断两条消息的差异程度。即使是微小的差异，也会生成完全不同的摘要值。

其次，消息摘要可用于实现数字签名算法。本章后面的“数字签名”部分将介绍这一概念。

在大多数情况下，消息摘要为 128 位或更长。不过，单个数字值可用于执行奇偶校验功能，这是一种低级的或单数字的校验和值，用于提供单个验证点。在大多数情况下，消息摘要越长，其完整性验证就越可靠。

根据 RSA Security 的说法，加密哈希函数有五项基本要求：

*   输入可以是任意长度。
*   输出具有固定长度。
*   对于任何输入，哈希函数计算相对容易。
*   哈希函数是单向的（即在给定输出的情况下，极难确定输入）。单向函数及其在密码学中的用途将在第 6 章中介绍。
*   哈希函数无冲突（即极难找到产生相同哈希值的两条消息）。

在以下章节中，我们将介绍四种常见的哈希算法：安全哈希算法（SHA）、消息摘要算法 2（MD2）、消息摘要算法 4（MD4）和消息摘要算法 5（MD5）。本章后面还将讨论基于哈希的消息认证码（HMAC）。

### SHA

安全哈希算法（SHA）及其后继者 SHA-1、SHA-2 和 SHA-3，是由美国国家标准与技术研究院（NIST）推广的政府标准哈希函数，并在一份官方政府出版物——安全哈希标准（SHS），也称为联邦信息处理标准（FIPS）180 中规定。

SHA-1 接受几乎任意长度的输入（实际上，该算法的上限约为 2,097,152 TB），并生成 160 位的消息摘要。SHA-1 算法以 512 位分块处理消息。因此，如果消息长度不是 512 的倍数，SHA 算法会用额外数据填充消息，直到长度达到下一个 512 的倍数。

密码分析攻击表明 SHA-1 算法存在弱点。这促使了 SHA-2 的诞生，SHA-2 有四个变体：

*   SHA-256 使用 512 位分块大小，生成 256 位消息摘要。
*   SHA-224 使用 SHA-256 哈希的截断版本，配合 512 位分块大小，生成 224 位消息摘要。
*   SHA-512 使用 1,024 位分块大小，生成 512 位消息摘要。
*   SHA-384 使用 SHA-512 哈希的截断版本，配合 1,024 位分块大小，生成 384 位摘要。

密码学界普遍认为 SHA-2 算法是安全的，但它们理论上存在与 SHA-1 相同的弱点。2015 年，联邦政府发布了 Keccak 算法作为 SHA-3 标准。SHA-3 套件的开发旨在作为 SHA-2 哈希函数的直接替代品，使用更安全的算法提供相同的变体和哈希长度。

### MD2

消息摘要算法 2（MD2）由 Ronald Rivest（RSA 中的 Rivest）于 1989 年开发，旨在为 8 位处理器提供安全的哈希函数。MD2 对消息进行填充，使其长度成为 16 字节的倍数。然后计算一个 16 字节的校验和并将其追加到消息末尾。最后使用原始消息连同追加的校验和生成 128 位消息摘要。

针对 MD2 算法存在密码分析攻击。具体而言，Nathalie Rogier 和 Pascal Chauvaud 发现，如果在摘要计算前未将校验和追加到消息中，可能会发生冲突。Frederic Mueller 后来证明 MD2 不是单向函数。因此，不应再使用该算法。

### MD4

1990 年，Rivest 改进了其消息摘要算法以支持 32 位处理器并提高安全级别。该增强算法称为 MD4。它首先填充消息，确保消息长度比 512 位的倍数小 64 位。例如，16 位消息将填充 432 位额外数据，使其成为 448 位，比 512 位消息小 64 位。

MD4 算法随后在三轮计算中处理消息的 512 位分块。最终输出为 128 位消息摘要。

多位数学家发表论文记录了完整版 MD4 以及错误实现的 MD4 存在的缺陷。特别是 Hans Dobbertin 于 1996 年发表论文，阐述了如何利用现代个人电脑在一分钟内找到 MD4 摘要的冲突。因此，MD4 不再被视为安全的哈希算法，如果可能，应避免使用。

### MD5

1991 年，Rivest 发布了其消息摘要算法的下一个版本，称为 MD5。它同样处理消息的 512 位分块，但使用四轮不同的计算生成摘要，长度与 MD2 和 MD4 相同（128 位）。MD5 的填充要求与 MD4 相同——消息长度必须比 512 位的倍数少 64 位。

#### MD5 安全局限性

MD5 实现了额外的安全特性，但会显著降低消息摘要的生成速度。不幸的是，最近的密码分析攻击表明 MD5 协议容易发生碰撞，这使其无法用于确保消息完整性。具体而言，Arjen Lenstra 等人在 2005 年证明了可以从不同的公钥创建两个具有相同 MD5 哈希值的数字证书。

## 数字签名

一旦你选择了一个密码学上可靠的哈希算法，就可以用它来实现*数字签名*系统。数字签名基础设施有两个不同的目标：

*   数字签名消息向接收者保证消息确实来自声称的发送者。它们强制执行**不可抵赖性**（即防止发送者事后声称消息是伪造的）。
*   数字签名消息向接收者保证消息在发送者和接收者之间传输时未被篡改。这可以防止恶意修改（第三方更改消息含义）和无意修改（由于通信过程中的故障，如电气干扰）。

数字签名算法依赖于本章已介绍的两个主要概念的组合——公钥密码学和哈希函数。

如果 Alice 想要对发送给 Bob 的消息进行数字签名，她会执行以下操作：

1.  Alice 使用一种密码学上可靠的哈希算法（如 `SHA3-512`）生成原始明文消息的消息摘要。
2.  Alice 然后仅使用她的私钥加密该消息摘要。这个加密后的消息摘要就是数字签名。
3.  Alice 将签名后的消息摘要附加到明文消息后。
4.  Alice 将附加后的消息发送给 Bob。

当 Bob 接收到数字签名消息时，他会反向执行该过程，步骤如下：

1.  Bob 使用 Alice 的公钥解密数字签名。
2.  Bob 使用相同的哈希函数基于从 Alice 接收到的完整明文消息创建一个消息摘要。
3.  Bob 然后将从 Alice 处收到的解密后的消息摘要与他自己计算的消息摘要进行比较。如果两个摘要匹配，他可以确信收到的消息是由 Alice 发送的。如果不匹配，则消息不是由 Alice 发送的，或者消息在传输过程中被修改过。

请注意，数字签名过程本身并不提供任何保密性。它仅确保满足完整性、认证和不可抵赖性这些密码学目标。然而，如果 Alice 想要确保她发给 Bob 的消息的保密性，她可以在消息创建过程中增加一个步骤。在将签名后的消息摘要附加到明文消息后，Alice 可以使用 Bob 的公钥加密整个消息。当 Bob 收到消息时，他会先用自己的私钥解密，然后再执行上述步骤。

### HMAC

哈希消息认证码 (HMAC) 算法实现了一种部分数字签名——它保证消息在传输过程中的完整性，但不提供不可抵赖性。

HMAC 可以通过使用共享密钥与任何标准消息摘要生成算法（如 `SHA-3`）结合使用。因此，只有知道该密钥的通信双方才能生成或验证数字签名。如果接收者解密消息摘要但无法将其与从明文消息生成的消息摘要成功比较，则意味着消息在传输过程中被篡改了。

因为 HMAC 依赖于共享密钥，所以它不提供任何不可抵赖性功能（如前所述）。然而，它的运行效率比下一节描述的数字签名标准更高，可能适用于对称密钥密码学适用的场景。简而言之，它代表了未加密使用消息摘要算法与基于公钥密码学的计算成本高昂的数字签名算法之间的一个折中点。

### 数字签名标准

美国国家标准与技术研究院在联邦信息处理标准 (FIPS) 186-4 中规定了联邦政府可用的数字签名算法，该标准也称为数字签名标准 (DSS)。该文档规定，所有联邦批准的数字签名算法必须使用 SHA-3 哈希函数。

DSS 还规定了可用于支持数字签名基础设施的加密算法。目前有三种批准的标准加密算法：

*   FIPS 186-4 中规定的数字签名算法 (DSA)
*   ANSI X9.31 中规定的 Rivest–Shamir–Adleman (RSA) 算法
*   ANSI X9.62 中规定的椭圆曲线 DSA (ECDSA)

## 公钥基础设施

公钥加密的主要优势在于其能够促进相互未知的各方之间的通信。这得益于*公钥基础设施 (PKI)* 信任关系层级。这些信任关系允许将非对称密码学与对称密码学相结合，并配合哈希和数字证书，从而实现混合密码学。

在以下章节中，你将学习公钥基础设施的基本组件以及使全球安全通信成为可能的密码学概念。你将了解数字证书的组成、证书颁发机构的角色，以及生成和销毁证书的过程。

### 证书

数字*证书*为通信双方提供保证，确认他们正在通信的人确实是他们声称的那个人。数字证书本质上是个人公钥的背书副本。当用户验证证书是由受信任的证书颁发机构 (CA) 签名时，他们就知道该公钥是合法的。

数字证书包含特定的标识信息，其构建遵循一项国际标准——X.509。符合 X.509 标准的证书包含以下数据：

*   证书遵循的 X.509 版本
*   序列号（来自证书创建者）
*   签名算法标识符（指定证书颁发机构用于对证书内容进行数字签名的技术）
*   颁发者名称（颁发证书的证书颁发机构的标识）
*   有效期（指定证书有效期间的日期和时间——开始日期/时间和结束日期/时间）
*   主体名称（包含拥有证书中公钥的实体的可分辨名称，即 DN）
*   主体公钥（证书的核心——证书所有者用于建立安全通信的实际公钥）

当前版本的 X.509（版本 3）支持证书扩展——由证书颁发机构插入证书中以支持证书跟踪或各种应用的包含数据的自定义变量。
