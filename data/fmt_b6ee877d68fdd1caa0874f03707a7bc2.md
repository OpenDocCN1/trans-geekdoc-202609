
## 4.3 采样

采样是处理流的一种显而易见的方法：对流中的每个项，以概率 `α` 处理它，以概率 `1 - α` 忽略它。

对于许多任务，包括学习和数据挖掘语境中的许多任务，我们可以通过在采样元素的 `α` 部分上计算函数，在降低计算成本的同时获得相当好的近似。但要警惕采样并非万能解，因为它在某些任务上表现不佳。例如，对于估计不同元素数量的问题，稀有元素可能完全被遗漏，其数量通常会被低估。

通常，我们希望减少待处理的项数，同时保持给定大小 `k` 的流的代表性样本。**水库采样**，由 Vitter [240] 提出，是一种实现此目的的简单高效技术。它在图 4.1 中展示。

![图 4.1 水库采样草图。](img/Fig4-1.png)

**图 4.1** 水库采样草图。

水库采样具有这样一个性质：无论迄今已读取了多少流元素 `t`，每个元素当前都在水库中，且概率相同，为 `k/t`。也就是说，它对早期元素和后期元素的偏向程度相同。要看出这是真的，可对 `t` 使用数学归纳法。在前 `t` 步之后（对于 `t ≤ k`），这显然成立。在稍后的时间 `t > k`，第 `t` 个流项在水库中的概率是 `k/t`，因为它以该概率被加入。对于编号为 `i` 的项（其中 `i < t`）要在水库中，必须满足：(1) 它在时刻 `t - 1` 时在水库中，根据归纳假设这发生的概率为 `k/(t - 1)`；(2) 第 `t` 个项*不*被选中（概率 `k/t`）*且*被放置在水库中第 `i` 项所在的位置（概率 `1/k`）的事件*不*发生。所有这些按期望发生的概率为

```
k/(t-1) * (1 - k/t * 1/k) = k/t
```

一种称为**跳跃计数**的变体，在处理一项的时间超过项到达间隔时效果更好。其思路是在时刻 `t` 随机选择下一个将被纳入样本的项的索引 `t' > t`，并跳过它之前的所有记录而无需计算——特别是无需相对昂贵的随机数生成。给定 `t` 和 `k` 随机选择 `t'` 的规则可以推导出来，使该方法的输出在概率上与水库采样完全相同 [240]。

## 4.4 计数总项数

计数迄今已见的总项数，或许是人们能在流上想象出的最基本问题。平凡的解法维护一个标准整数计数器，更新操作只是将计数器加一。典型编程语言用固定位数实现整数，如 16、32 或 64 位，这至少应为 `log t` 才能计数到 `t`。

一种更节省的解法是 **Morris 近似计数器** [183]。它是一种随机近似计数器，使用 `log log t` 位而非 `log t` 位即可计数到 `t`。这意味着它可以用 `log log 10⁹ = 5` 位计数到 10⁹，用 6 位计数到任何实际的项数。当然，代价是计数只是近似的。

最初的想法是使用我们之前描述的均匀采样：固定某个是 2 的幂的概率 `p`，设为 `2^(-k)`。像以前一样使用整数计数器 `c`，但在收到一项时，以概率 `p` 增加计数器，以概率 `1 - p` 什么都不做。现在，`t` 项后 `c` 的期望值是 `pt`，所以 `c/p` 应该是 `t` 的一个良好近似。草图使用 `log(pt) = log t - k` 位而不是 `log t` 位；例如，当 `p = 1/8` 时，节省 3 位。不过，由于 `c` 在 `pt` 周围的随机波动，返回值将不准确。

Morris 简单而巧妙的想法是：不预先固定 `k` 并计数到 `2^k`，而是用 `c` 代替 `k`。算法如图 4.2 所示；注意它没有提及 `k`。

![图 4.2 Morris 近似计数算法。](img/Fig4-2.png)

**图 4.2** Morris 近似计数算法。

更精确地说，可以证明 [103] 在读取 `t` 个流元素后，`2^c` 的期望值为 `t + 1`，方差为 `t(t - 1)/2`。也就是说，它在期望下返回正确值，尽管方差较大。只需存储 `c` 的值，这使用 `log c ≃ log log t` 位，在 `Update` 过程中仅额外保留一份 `c` 的副本。

我们可以通过运行多个算法副本并取平均来减小方差。但在这种情况下，存在一种特设的更高效方法。直观上，`c` 大约每在 `t` 翻倍时增加一次——这就是为什么 `t ≃ 2^c`；草图在概率上将 `t` 放入形如 `(2^c, 2^(c+1))` 的区间中。如果我们将算法中的 2 替换为较小的底数 `b < 2`，直观上我们将分辨率提高到形如 `(b^c, b^(c+1))` 的更细区间。可以证明 [103] `b^c` 的期望值为 `(b - 1)t + 1`，方差为 `(b - 1)t(t - 1)/2`。所需位数大致为 `log c = log log t - log log b`。例如，取 `b = 1.08`，我们可以用 1 字节内存计数到 `t ≃ 10⁹`，标准差为 `0.2t`。

作为应用示例，Van Durme 和 Lall [94] 通过使用 Morris 计数器的一个变体，解决了在大型文本语料库中估计 `k`-gram 频率的问题。即使对于中等 `k` 值，出现的 `k`-gram 数量也可能巨大，且为求速度必须保存在内存中，因此为每个计数器使用尽可能少的位至关重要。

## 4.5 计数不同元素

一个更具挑战性的问题是计算迄今为止在流中观察到的*不同*元素的数量（也有些不正确地称为*唯一*元素，也许是类比 Unix 的 `uniq` 命令）。困难在于，一个项目可能只出现一次，而另一个项目出现数百万次，但两者对不同元素计数的贡献相同，都是 1。

作为动机，考虑计算互联网链路所见不同流（源-目的 IP 地址对）数量的问题。潜在项目的数量巨大：IPv6 地址为 64 位，因此有 $2^{128} \simeq 10^{38}$ 个潜在项目，即地址对。直接的解决方案是保留某种关联表，如哈希表，并记录实际已见的地址对。对于繁忙链路，这可能很快变得太大而无法存储。幸运的是，我们通常可以用近似质量换取内存使用量。

### 4.5.1 线性计数

不同元素计数的几种方法都是经典 *Bloom filter*（布隆过滤器）思想的变体。作为示例，我们讨论 **LINEAR COUNTING**（线性计数），由 Whang 等人 [246] 提出，如图 4.3 所示。

![图 4.3 LINEAR COUNTING 概要。](img/Fig4-3.png)

**图 4.3** LINEAR COUNTING 概要。

初始化中的参数 `D` 是流中不同元素数量 `d` 的上界，即我们假设 `d ≤ D`。两个集合之间的*哈希函数*，直观上讲，将第一个集合中的每个元素 `x` 映射到第二个集合中的一个“随机”元素。关于这究竟意味着什么，以及如何构建可用少量位存储的“足够好”的哈希函数的技术讨论留待第 4.9.1 节。我们只说明，对于我们的目的足够随机且将 `{0,…,m-1}` 映射到自身的哈希函数，可以从 `O(log m)` 个真正随机位获得，并用 `O(log m)` 位存储。

流中存在的每个项目都将表 `B` 的一个条目设为 1，无论它出现多少次，设置的都是同一个条目。直观上，一个好的哈希函数确保流中出现的不同项目均匀地分配到 `B` 的条目中。然后，`Query` 返回的期望值是流中见到的不同值的数量加上一个微小的偏差项，其标准差为 `√(d(D-d)/D)`。对于相当大的不同元素数量 `d ≪ D`，这比 `d` 本身小得多，这意味着 LINEAR COUNTING 在相对意义上将相当准确。

### 4.5.2 Cohen 的对数计数器

**Cohen 计数器** [74] 基于这一思想，但利用以下观察转移到对数空间。`B` 中两个连续 1 之间的平均间隔由流中 1 位的数量决定，约为 `s/d`。这对于第一个间隔特别成立，等价地，对于第一个 1 的位置也是如此。方便的是，存储这个第一个位置只需 `log s` 位，因为它是观察到的哈希函数值的最小值。概要如图 4.4 所示。Cohen 计数器仅使用 `log D` 位来存储 `p`。

![图 4.4 Cohen 计数算法。](img/Fig4-4.png)

**图 4.4** Cohen 计数算法。

可以证明 `p` 的期望值为 `D/d`，且 `Query` 过程在期望下返回 `d`。其方差较大，约为 `(D/d)²`。可以通过并行运行多个副本并取平均值来减小方差，但这需要构建多个独立且“良好”的哈希函数，这是有问题的。一种使用单个哈希函数的替代方法将作为下一个概要的一部分呈现。

### 4.5.3 Flajolet-Martin 计数器与 HyperLogLog

一系列算法始于 Flajolet-Martin 计数器 [105]，终于 HyperLogLog [104]，能以更少的位实现相对近似 `ε`，即 `O((log log D)/ε²)`，外加存储哈希函数所需的空间。该方法的直觉如下：设 `D` 为 `2^k`。在范围 `[0, 2^k - 1]` 内不重复地均匀随机选择数字；这就是将良好的哈希函数应用于流项目后得到的结果。所有这些数字都可以用二进制的 `k` 位表示；其中一半的第一位为 0，四分之一有两个前导 0，八分之一以 `000` 开头，依此类推。一般来说，前导模式 `0^i 1` 出现的概率为 `2^{-(i+1)}`，因此如果 `0^i 1` 是迄今为止哈希值中最长的此类模式，则我们可以预期 `d` 约为 `2^{i+1}`。Durand 和 Flajolet [93] 在改进 Flajolet-Martin 算法时意识到，只需记住 `k`，用 `log k = log log D` 位，即可跟踪最长模式，即最大的 `i`。带有此改进的基本 Flajolet-Martin 概率计数器以伪码形式给出在图 4.5 中。

![图 4.5 基本 Flajolet-Martin 概率计数器。](img/Fig4-5.png)

**图 4.5** 基本 Flajolet-Martin 概率计数器。

该方法需要一个哈希函数 `h`，将每个项目尽可能随机地转换为 0 到 `L - 1` 之间的整数。文献 [105] 表明，如果已读取 `d` 个不同项目，`p` 的期望值为 `log(0.77351 d)`，其标准差为 `1.12127…`。概要仅需存储 `p` 的内存，其值最大为 `L = log D`，因此需要 `log log D` 位。

该方法的主要缺点是估计中的相对较大误差，数量级约为 `d`。如前所述，可以通过平均多个副本来减小误差。但这有两个问题：一是相应地增加了更新操作的计算时间。二是获取多个真正独立的哈希函数很难。

Flajolet 和 Martin 提出了一种他们称为*随机平均*的技术：概念上将流分成 `m = 2^b` 个子流，每个子流馈送一个不同的计数器副本。对于每个项目 `x`，使用 `h(x)` 的前 `b = log m` 位来决定 `x` 分配到哪个子流，并用 `h(x)` 的其余 `m - log m` 位来馈送相应的计数器。现在可以使用单个哈希函数，因为不同子流中的项目看到的是同一函数的独立部分，且更新时间本质上与单个计数器相同。内存使用仍乘以 `m`。

上述算法的不同变体在于如何将 `m` 个副本的结果组合成单一估计。

*   **LogLog** [93] 返回其估计的几何平均数，即其变量 `p` 的算术平均数的 2 的幂，乘以一个常数。
*   **SuperLogLog** [93] 在执行上述操作前移除排名前 30% 的估计值；这减小了异常值的影响。
*   **HyperLogLog**，由 Flajolet 等人 [104] 提出，则返回 `m` 个估计值的调和平均数，这同样能平滑较大的异常值。

上述变体实现的标准差分别为 `1.3d/√m`、`1.05d/√m` 和 `1.04d/√m`，并使用 `O(m log log D)` 内存，外加 `O(log D)` 位存储可在所有计数器实例间共享的哈希函数。通过使用切比雪夫不等式，只要 `m = O(1/(δ ε²))`，即可获得 `(ε, δ)`-近似；注意不清楚如何应用霍夫丁界，因为估计值不是平均值。换种说法，取 `ε = O(1/√m)`，我们使用 `O((log log D)/ε²)` 位内存，即可为固定置信度实现相对近似 `ε`。

用更具体的术语来说，根据 [104]，HyperLogLog 可以在 2% 误差内近似高达 `10⁹` 的基数，仅使用 1.5 千字节内存。关于 HyperLogLog 在大规模应用中的实际实现讨论，见 [134]。

### 4.5.4 应用：计算图中的距离函数

让我们提及 Flajolet-Martin 计数器的一个非流式应用，以说明流式算法有时可用于提高非流式问题的时间或内存效率。

Boldi 等人 [47] 在 [192] 的基础上改进，提出了 HyperANF 计数器，它使用 HyperLogLog 来近似图的*邻域函数 N*。对于节点 `v` 和距离 `d`，`N(v,d)` 定义为从节点 `v` 出发，通过长度至多为 `d` 的路径可达的节点数量。该概率计数器允许在给定 `N(.,d-1)` 值的情况下，以内存高效的方式近似计算 `N(.,d)`，并且只需对图的边进行一次顺序遍历，顺序为它们在磁盘上存储的任意顺序，即无需昂贵的磁盘随机访问。

我们给出实现此目的的直观解释。第一个关键观察是：如果一个顶点要么通过长度至多为 `d - 1` 的路径从 `v` 可达，要么通过长度至多为 `d - 1` 的路径从顶点 `u` 可达（其中 `(v,u)` 是一条边），那么它就通过长度至多为 `d` 的路径从 `v` 可达。第二个关键观察是 HyperLogLog 计数器是可合并的，这是一个我们将在第 4.8 节探讨的概念。这意味着，给定两个 HyperLogLog 计数器 `H[A]` 和 `H[B]`，它们分别由处理流 `A` 和 `B` 得到，存在一种方法获得一个新的 HyperLogLog 计数器 `merge(H[A], H[B])`，它与处理 `A` 和 `B` 的拼接 `C` 所得到的计数器完全相同。也就是说，它包含 `C` 中不同项目的数量。然后，假设归纳地我们已经为每个顶点 `v` 计算了一个 HyperLogLog 计数器 `H_{d-1}`，它（近似地）计算距离 `v` 至多为 `d - 1` 的顶点数量，换句话说，近似 `N(v, d - 1)`。然后按如下方式计算 `H_d`：

1.  `H_d ← H_{d-1}`。
2.  对每条边 `(v,u)`（按任意顺序）执行

```
H_d ← merge(H_d, H_{d-1})
```
