# 防火墙核心概念与架构

## 主要问题与评估标准
- **两大主要问题**：防火墙的配置错误和代码漏洞。
- **四个主要项**：安全、性能、速度、管理（包括“易用性”）。
- 在选择防火墙前，需要评估潜在风险并制定安全策略。

## 防火墙无法保护的内容
- 企业工作站上的调制解调器。

## 防火墙架构：三种基本的访问控制方法
1.  **包过滤**：检查所有看到的数据包，然后根据预定义规则转发或丢弃它们。
2.  **代理**：作为用户请求的中间体，在应用层（应用代理）或会话/传输层（电路中继）为所需资源设置第二个连接。
3.  **状态检查**：像包过滤一样检查数据包，但进一步记住哪个端口号用于哪个连接，并在连接关闭后关闭对该端口的访问。Check Point 开发了状态检查架构，使防火墙能够安全地传输几乎任何应用。

## 可执行内容风险
可执行内容（如 Java 和 ActiveX 对象）是互联网和内部网流量的一个令人不安的方面。可执行内容可以通过许多防火墙所允许的服务直接通过防火墙。Web 用户可能会下载包含恶意 ActiveX 或 Java 对象的页面。由于防火墙已配置为允许 Web 访问，它会直接放行这些内容。

## DMZ 设计
为内部网增加额外的保护措施。即使外部段的攻击者成功入侵 DMZ 机器，内部网络仍然受防火墙保护。

## 日志管理策略
日志文件会填满：此时最好关闭外部访问。与其覆盖旧日志条目或在没有日志的情况下继续运行，关闭外部访问更安全。

## 防火墙警报
设置分页或电子邮件警报以应对未经授权的访问尝试。

## SYN 洪水攻击
也称为同步风暴；一种拒绝服务攻击；对 ISP 非常严重，会向防火墙发送大量 TCP 同步请求，导致防火墙耗尽所有缓冲区，无法接受合法连接。

## Java 与 ActiveX 对比
- **Java** 被认为比 **ActiveX** 风险更小，因为它具有内置的安全控制，而 ActiveX 没有。
- Microsoft 表示，ActiveX 的长期安全解决方案是数字签名，用于保证每个对象的安全。
- 网管员最好在防火墙处筛选可执行内容。

## 防火墙配置项
1.  页面或电子邮件对未经授权的访问尝试发出警报。
2.  远程禁用外部访问（外部接口）。
3.  任何允许远程配置的产品都应对防火墙的连接进行身份验证和加密。
4.  拒绝来自特定子网的访问。
5.  记录被阻止的访问尝试。
6.  SYN 洪水攻击防护。
7.  Ping of death（死亡 Ping）防护。
8.  记录满（full）告警。
9.  磁盘满告警。
10. 电子邮件或分页警报用于：
    1.  传输超过 20 MB。
    2.  1 点到 6 点之间的使用量超过 5 MB，且流量超过 40 MB。
    3.  每分钟请求的连接数过多。
    4.  每分钟超过 10 次尝试访问不存在的 IP 地址。
    5.  IP 欺骗尝试：攻击者在防火墙外部将其机器配置为使用内部 IP 地址。
    6.  传输 `/etc/password` 或类似文件。

# Appendix F: Discovering unauthorized access to your computer

使用 `netstat` 命令确定是否存在对工作站的未经授权连接。如下所示，使用 `/?` 参数可以查看 `netstat` 命令的“帮助”部分。

```
netstat /? 显示协议统计和当前 TCP/IP 网络连接。

NETSTAT [-a] [-e] [-n] [-s] [-p proto] [-r] [interval]
```

| 参数 | 说明 |
| :--- | :--- |
| `-a` | 显示所有连接和监听端口。（服务器端连接通常不显示） |
| `-e` | 显示以太网统计信息。可以与 `-s` 选项组合。 |
| `-n` | 以数值形式显示地址和端口号。 |
| `-p` | 显示指定协议（proto）的连接；proto 可以是 TCP 或 UDP。如果与 `-s` 选项一起使用以显示按协议的统计信息，proto 可以是 TCP、UDP 或 IP。 |
| `-r` | 显示路由表的内容。 |
| `-s` | 显示按协议的统计信息。默认情况下，统计信息显示 TCP、UDP 和 IP；可以使用 `-p` 选项指定子集。 |
| `interval` | 在每次显示之间暂停 interval 秒，重复显示统计信息。按 `CTRL+C` 停止重复显示。如果省略 interval，`netstat` 仅打印当前配置信息一次。 |

## 使用 `netstat -a` 检测木马端口
`netstat -a` 显示本机的端口列表。NetBus 将在 `12345` 端口上监听；BackOrifice 将在 `31337` 端口上监听。这些端口号可能被攻击者修改，但大多数攻击者要么懒，要么不知道如何更改。正常情况下，你应期望看到 `135`、`137`（nbname）、`138`（nbdatagram）和 `139`（nbsession）端口。此外，还应看到从 `1024` 到约 `1030` 的几个端口。这些端口大概率是正常的。在这些端口中，你还会看到你的机器正在连接的对象。如果攻击者使用 BackOrifice，你将看不到连接（它使用 UDP，属于“无连接”）；如果使用 NetBus，你将看到攻击者的名称。

运行 `netstat -an` 并查找端口 `1025` 的任何内容。关闭另一个程序后再次查看。如果在关闭所有可见程序后端口仍然打开，按 `Ctrl + Alt + Delete` 一次，结束除 Explorer 和系统托盘之外的所有进程。如果该端口仍然打开，则可能存在木马程序；使用 `telnet` 连接 `localhost 1025` 并查看是否有常见的木马横幅。
