
现在您已熟悉一些控制网络访问权限的常用技术，让我们看看一些可用于加固系统的常用工具。您需要熟悉这些概念以应对 Security+ 认证考试，因此请务必尝试它们。

## 组策略

加固 Windows 系统的第一个重要工具称为**组策略**，它是 Windows 的一项核心功能，允许网络管理员启用和禁用 Windows 中的不同功能——例如，组成员身份、正在运行的服务、密码策略，以及桌面限制（如用户是否应有**运行**命令可用）。

组策略可以在本地系统（管理员正在配置的系统）上配置，也可以在 Active Directory 域中集中配置，这意味着设置将每 90 分钟、在下次用户登录时或在系统重启时应用到多个系统和用户。

要在单个系统上配置组策略，请单击“开始”按钮，然后键入 `mmc`（Microsoft Management Console 的缩写）。进入 MMC 后，选择“文件” | “添加/删除管理单元”。当您在“添加或删除管理单元”对话框中看到管理单元列表时，选择“组策略对象编辑器”并单击“添加”将其移至“选定的管理单元”列表。单击“完成”按钮以接受您正在配置本地计算机，然后单击“确定”。

您现在可以配置系统上的本地组策略了（参见图 6-6）。组策略分为两类——计算机设置和用户设置。计算机设置无论谁登录都应用于该计算机，而用户设置应用于用户帐户。总而言之，用户设置通常包含限制桌面设置的方法，而计算机设置允许您通过密码策略、禁用服务和软件限制（允许在系统上运行什么软件）等来加固系统。

![Image](img/f0247-01.jpg)

**图 6-6** 查看 Windows 中的组策略对象编辑器

以下是组策略中“计算机配置”部分一些常见策略的简要说明：

- **Windows 设置 | 脚本（启动/关机）** 在此策略中，您可以为计算机首次启动时配置启动脚本，或为计算机关机时配置关机脚本。

- **安全设置 | 帐户策略** 此策略部分允许您配置与用户帐户相关的策略，如帐户锁定和密码策略。

- **安全设置 | 本地策略** 一个与系统加固密切相关的重要策略部分。在本部分中，您可以配置系统上的用户权利、审核以及其他安全设置，如创建登录横幅。

- **安全设置 | 带有高级安全的 Windows 防火墙** 此策略允许您配置 Windows XP 之后的 Windows 系统内置的新防火墙功能。

- **安全设置 | 软件限制策略** 此策略允许您配置允许在系统上运行的软件。

- **安全设置 | 高级审核策略配置** 此策略允许您更好地控制系统审核以及要审核的事件类型。

以下概述了组策略“用户配置”设置中一些常用的策略：

- **Windows 设置 | 脚本（登录/注销）** 此策略用于配置用户登录或注销时执行的脚本。

- **Windows 设置 | Internet Explorer 维护** 此策略用于配置 IE 中的设置，如收藏夹列表或默认主页。

- **管理模板 | 控制面板** 此策略允许您启用或禁用 Windows 控制面板中的功能。其好处是通过禁用控制面板中的组件，可以防止用户进行系统更改。

- **管理模板 | 桌面** 此策略设置允许您控制桌面上应出现哪些图标，如“我的电脑”、“Internet Explorer”和“我的文档”。

- **管理模板 | 开始菜单和任务栏** 此策略设置允许您控制“开始”菜单中可以出现哪些项目，如“运行”命令和“搜索”命令。

如果您想修改网络上所有系统的策略，可以在域级别配置组策略。您还可以在 Active Directory 中的特定组织单位 (OU) 上配置组策略，以便该策略仅应用于特定 OU 内的计算机或用户。例如，您可能希望确保 Tom 是会计部门所有计算机的本地管理员。您可以在会计 OU 上配置组策略，将 Tom 放入所有会计系统的 Administrators 组中。这省去了您去会计部门的每个系统手动将 Tom 放入 Administrators 组的麻烦。图 6-7 显示了使用组策略管理控制台 (GPMC) 在 Active Directory 中配置策略。

### 补丁管理

如前所述，给系统应用补丁是系统强化的一个非常重要的方面。当软件供应商发现其软件中的漏洞时，他们会通过补丁发布针对这些缺陷的修复程序。如果您不给系统打补丁，就无法获得这些修复。

重要的是要规划修补策略，而不仅仅是在每个系统上执行 Windows Update。您可以使用 Windows Server Update Services (WSUS) 等软件从中央服务器下载、审查和部署补丁（请参阅图 6-9）。

### 配置安全基线

*安全基线* 是公司批准的标准配置，被认为对于特定类型的系统或设备是安全的。所有系统都需要此标准配置，以满足公司所需的安全要求。

在系统实施了安全基线之后，对系统的任何更改都必须遵循公司定义的变更管理流程。如果您对已应用安全基线的系统进行更改，重要的是在更改后评估系统，以确保未影响系统的安全状态。例如，确保管理员对系统进行更改后，该更改未向系统开放端口，也未安装易受缓冲区溢出攻击的软件。这两种意外结果都可能导致您的系统受到威胁，从而将系统的安全状态从安全变为不安全。

您可能会为网络上不同类型的系统和设备制定不同的安全基线。例如，DMZ（非军事区）中 Web 服务器的安全基线将比 LAN 上内部系统的安全基线严格得多。这并不是说您不保护内部系统，但内部系统可能安装了比 DMZ 中的 Web 服务器所需的更多软件和服务。

每种类型系统的安全基线都应有适当的文档记录，在分发给安全管理员之前，必须准确记录并测试实现安全基线的步骤。此文档将包含实现安全基线的详细步骤。

![Images](img/job.jpg) **前面描述的安全模板功能是在 Windows 中实现安全基线的绝佳方式。**

如前所述，安全基线会被记录在文档中，以便网络上配置特定系统的任何人都可以查阅该文档，了解如何满足该系统的安全基线。安全基线文档可能包含以下项目：

- 该类型系统的物理安全要求

- 网络连接要求

- 有助于保护系统的配置设置

- 补丁要求

## 配置基线要求

配置基线的要求可能包含任意数量的操作系统或应用程序配置步骤，以满足公司对安全系统的标准。以下是应考虑的一些配置要求示例：

- **文件系统** 如今所有 Windows 系统都应使用新技术文件系统（`NTFS`），而非 `FAT`/`FAT32` 文件系统，因为 `NTFS` 包含权限、加密、配额和审核服务等功能。

- **权限** 系统硬盘上的文件夹应得到妥善保护。这不仅包括存储在系统上的任何数据，还包括 `Windows` 目录和程序文件目录。

- **运行的服务** 确保系统上仅运行所需的服务。

- **网络连接** 确保系统连接到正确的网段。

- **运行的协议** 确保系统或设备上仅运行所需的协议。

- **防火墙规则** 确保系统上所需的任何防火墙规则已实施，以帮助保护系统免受不需要的流量侵害。

- **存储加密** 考虑是否应加密存储中的信息——无论是在文件系统内，还是在包含敏感信息的数据库中。

- **通信加密** 调查是否应加密网络上传输的数据。

- **补丁管理** 确保系统得到适当的修补，且补丁级别得以维护。这对 `DMZ` 中的公共服务器尤为重要，因为它们在部署后有时会被遗忘。

## 安全态势与报告

在本节中，您将学习如何管理系统的安全态势，以及应用程序用于发送安全通知的报告方法类型。

### 安全态势

一旦建立并记录了安全基线要求，接下来就要将安全基线付诸实践。本节概述了管理安全基线的关键阶段。

#### 初始基线配置

您需要使用安全基线文档在系统上配置初始安全基线。在将初始安全基线应用到系统的各种方法中，最有效的方法之一是使用预配置映像为系统创建映像，或者将安全模板应用到需要初始安全基线的系统。

#### 持续安全监控

使用初始安全基线配置好系统后，必须监控系统以确保其持续处于安全运行状态。持续监控涉及许多工具和技术，有助于在安全问题发生时识别它们。公司应定期使用漏洞扫描器检查系统的已知漏洞。漏洞扫描将告知您系统安全的任何错误配置，以及是否缺少任何补丁。执行漏洞扫描的常用软件包括 `Nessus`（Linux 常用）、`Microsoft Baseline Security Analyzer`（`MBSA`）和 `GFI` 的 `LANguard`。您可以从微软网站免费下载并使用 `MBSA`，也可以使用 `Nessus` 免费版扫描多达 16 个 IP 地址。`Nessus` 完整版和 `LANguard` 是商业产品，需要付费。还有许多可购买的企业级监控解决方案，例如微软提供的 `System Center Operation Manager`（`SCOM`）和 `System Center Configuration Manager`（`SCCM`）。

持续监控还涉及使用反恶意软件，以始终保护系统免受恶意软件侵害。您还需要确保定期向系统应用安全补丁。有几种工具可帮助您进行修补，包括微软的 `WSUS`。`LANguard` 也有一个可用于向系统部署补丁的功能。

最后，持续监控还涉及使用简单网络管理协议（`SNMP`）来监控支持 `SNMP` 的网络设备的配置和统计信息。

![Image](img/exam.jpg)

> **考试提示：请记住，持续监控涉及对漏洞和错误配置的持续监控、反恶意软件保护、补丁部署，以及使用 `SNMP` 监控设备配置和统计信息。**

#### 补救

运行漏洞扫描器以发现任何配置错误或缺失补丁后，您需要确保纠正问题。补救是纠正系统故障的过程。例如，如果您发现某个安全配置设置未应用到系统，可能需要回到初始安全基线，确保应用了该配置步骤。

补救还可能涉及修复尝试连接到网络的用户的安全态势。例如，如果使用网络策略服务器（`NPS`），它会检查用户是否具有更新的补丁和病毒定义更新。如果用户不满足这些特定条件，`NPS` 会将用户置于受限子网中，以便系统下载并安装缺失的补丁和病毒定义更新。这是在保持安全的同时利用技术辅助补救的一个示例，因为用户被置于无法访问网络资源的受限子网中。

### 报告

大多数系统、设备和应用程序都可以配置为在发生特定事件时发送通知，但它们使用不同的方法报告与事件关联的不同严重级别。以下是您需要为 `Security+` 考试熟悉的常用报告方法。

**警报** 警报用于报告通常需要系统或网络管理员采取某种行动的关键事件。例如，警报可用于通知管理员网络上的可疑流量。在这种情况下，警报用于引起网络管理员的注意，以便他们调查问题。

**通知** 通知是一种不太关键的通知类型，用于通知系统或网络管理员已发生特定事件，但管理员可能不需要采取行动。通常，通知用于通知管理员发生的变更，例如系统上线或打印机被清空。

**趋势** 趋势是一种用于识别安全问题的报告方法，例如有人对网络执行端口扫描。趋势分析通常涉及查看日志文件或数据包捕获，并分析信息以识别可能帮助管理员了解网络上发生情况的趋势。例如，如果网络管理员查看数据包捕获，发现同一源 IP 地址在极短时间内连接到多个端口，则很可能正在发生端口扫描。

# 认证目标 6.03

## 服务器加固最佳实践

本节介绍您应遵循的常见做法，以加固网络上的服务器，例如锁定每个服务器上打开的端口数量和正在运行的服务。本节概述了保护大多数网络中常见的不同类型服务器的步骤。

## 所有服务器

在查看常见服务器类型及其安全保护的常用步骤之前，我想强调应对所有服务器采取的步骤。您对任何服务器首先要做的就是对其进行加固，以便仅在其上安装必要的软件和服务。

系统加固后，请确保已为系统及其上运行的应用程序打上补丁。打完补丁后，务必配置相关策略，如密码策略和账户锁定策略，然后在系统上启用审核。

此外，请务必检查用户账户。禁用不必要的账户，并为剩余账户设置强密码。将默认账户名重命名为不易猜测的名称也是一种安全最佳实践。例如，你可以将名为 Administrator 的账户重命名为 HAL12345。

## HTTP 服务器

对于 Web 服务器，应应用前文“所有服务器”部分提到的所有概念，但也需遵循一些额外步骤。首先，确保 Web 服务器放置在 DMZ 中——即位于外部防火墙和内部防火墙之间的区域。Web 服务器应经过加固，以确保服务器上不存在多余的软件或用户账户。

此外，禁用 Web 服务器中不打算使用的功能。例如，如果你的网站仅使用静态 HTML 页面，则务必在 Web 服务器上禁用所有活动内容功能，如 ASP 和服务器端包含。如果你转到“服务器管理器”并选择“删除角色和功能”，即可管理 Microsoft IIS 服务器的功能。在向导中，当显示角色列表时，展开“Web 服务器”角色并取消选择你不打算使用的功能（请参见图 6-10）。

![Image](img/f0257-01.jpg)

值得注意的是，多年前 Windows 服务器默认安装了 IIS，但现在已不再如此。在评估服务器安全性时，你应该检查安装了什么内容，如果有人安装了 IIS，你应该验证它是否必要——如果不必要，请卸载它。

如果 Web 服务器不供公众访问，则请确保禁用匿名访问（允许任何人访问服务器）并在服务器上启用身份验证。如果网站上处理机密数据，请务必使用 SSL/TLS 保护 Web 流量。

### DNS 服务器

要加固 DNS 服务器，你应该应用前文“所有服务器”部分的所有步骤，此外还应限制 DNS 服务器上的区域传送。`区域传送` 是指主 DNS 服务器将 DNS 数据发送给辅助 DNS 服务器。如果黑客通过区域传送获取了 DNS 数据，他们将知晓你不同系统所使用的 IP 地址。

在 DNS 服务器的属性中，你应该能看到一个选项，用于限制哪些系统可以从你的 DNS 服务器接收区域传送。通常你应确保此处仅列出你的 DNS 服务器。图 6-11 显示了如何在 Microsoft DNS 服务器上限制区域传送。
