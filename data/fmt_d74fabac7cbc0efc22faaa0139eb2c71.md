
域名服务（DNS）是互联网的主力之一。DNS 运行在每个地址转换之后，负责将完全限定域名（FQDN）解析为数字 IP 地址。DNS 起着至关重要的作用，如果有人搞掉 DNS，互联网将继续运行，但用户需要知道他们想要访问的每个站点的 IP 地址。DNS 是一种请求响应协议。当 DNS 服务器对请求发送响应时，回复消息包含原始请求的事务 ID 和问题，以及它本应找到的任何答案。

多年来，计算机犯罪分子在 DNS 协议及其实现它的软件中发现了大量漏洞。有时，攻击者可能不会直接针对 DNS，而只是针对注册过程。一种方法是反复注册和删除域名，以便注册者可以临时拥有该域名而无需付费。这被称为域名劫持（domain hijacking）。在任何服务器上启用服务之前，应该对其进行安全防护。一些最流行的 DNS 软件（如 BIND）曾遭受漏洞影响。BIND 的替代方案（如 Unbound）已经可用，如果你的基础设施允许，你应该考虑它们。DNS 同样容易受到拒绝服务（DoS）攻击的影响。DNS 使用 UDP 53 端口进行查询，使用 TCP 53 端口进行区域传输。保护区域传输过程非常重要。2002 年发生过一次针对 DNS 的分布式拒绝服务（DDoS）攻击，是针对根服务器发起的。攻击仅持续了一个小时，但指出了根服务器是一个弱点。你可以在此处阅读更多：`securityplanet.com/trends/article.php/148698/Massive-DDoS-Attack-Hit-DNS`。

# 安全区域传输

DNS 数据库由一个或多个区域文件组成。每个区域都是结构化资源记录的集合。常见的记录类型包括起始授权记录（SOA）、A 记录、CNAME 记录、NS 记录、PTR 记录和 MX 记录。每个区域只有一个 SOA 记录。它描述了区域空间。A 记录最常见，因为它包含了特定主机的 IP 地址和名称。CNAME 记录是别名。NS 记录列出了其他名称服务器的 IP 地址。PTR 记录用于反向查找。MX 记录是邮件交换记录。该记录包含投递电子邮件的服务器 IP 地址。

保护区域传输从确保你的 DNS 服务器未设置为允许区域传输开始。如果你的主机同时拥有外部和内部 DNS 服务器，那么安全管理员还应该关闭 TCP 53 端口。内部 DNS 服务器应该配置为与根服务器通信。如果攻击者可以访问 DNS 信息，他们就可以获得网络的虚拟地图。理解保护区域传输对于对于 CASP 以及你作为安全专业人员的工作至关重要。练习 2.6 将向你展示如何检查 DNS 服务器的配置是否正确。考试可能会向你提出一个或多个关于区域传输概念的问题。

# 起始授权

起始授权（SOA）详细说明了哪个 DNS 服务器是主名称服务器、你的联系信息、辅助服务器何时更新以及 DNS 记录的默认生存时间（TTL）值。SOA 定义了 DNS 区域的通用参数。对于 CASP 来说，一个重要问题是 TTL 设置。TTL 提供了关于 DNS 缓存毒化的重要信息。TTL 越长，读取记录的频率就越低，被毒化的可能性就越小。练习 2.7 将向你展示如何强制区域传输。

## 安全 DNS

DNS 的完整性和可用性对于整个健康至关重要。保护 DNS 的一种方法是管理两个 DNS 服务器，一个内部外部。另一种方法是使用 DNS 安全扩展 (DNSSEC)。DNSSEC 是一个现实考虑因素，因为运行两个 DNS 服务器的问题之一是外部 DNS 服务器向外部主机提供的信息仍然受到攻击。这是因为 DNS 服务器没有信任机制。DNS 客户端通常无法判断 DNS 响应是否有效。

> CASP 测试候选人应该注意，DNSSEC 不提供数据的机密性。此外，DNSSEC 不防御 DDoS 攻击。

通过 DNSSEC，DNS 服务器提供签名并对每个响应进行数字签名。为了让 DNSSEC 正常工作，必须在使用之前分发身份验证密钥。否则，如果客户端没有验证身份验证的方法，DNSSEC 就几乎没有意义。DNSSEC 仅验证 DNS 服务器而不验证内容。即使 DNS 服务器配置了 DNSSEC，也可能出现服务器对其正在冒充的域名结果签名的情况。你可以在 `www.dnssec.net` 阅读更多关于 DNSSEC 的信息。

> CASP 测试候选人应该注意，尽管 DNSSEC 提供了安全优势，但仍然存在潜在的漏洞。其中一个漏洞是 DNSSEC 不防止域名劫持。

## 事务签名

动态 DNS (DDNS) 允许 DNS 服务器在客户端的主机名或 IP 地址更改时自动更新其资源记录。当你使用 DDNS 时，用于验证 DDNS 更新的机制被称为事务签名 (TSIG)。TSIG 设计时采用了加密控制，并使用共享秘密密钥和单向哈希。

当客户端和 DNS 服务器交换一组 DNS 消息以建立安全会话时，DNS 客户端发送的更新消息包含用于验证 DNS 客户端的 TSIG 记录。TSIG 用于提供一种验证 DDNS 数据库更新的方法。

尽管 TSIG 提供了某种程度的安全性，但已经发现了漏洞。例如，如果攻击者在没有相应密钥的情况下构造了响应，可能会发生缓冲区溢出。完成此任务的攻击者可能会导致服务器崩溃或获得 shell 的 root 权限。

## Fast Flux DNS

另一个与 DNS 相关的安全威胁是快速变化 DNS (Fast Flux DNS)。这是一种以不同复杂程度实现的技术。它通常被今天更先进的僵尸网络采用，以隐藏它们的命令与控制 (C&C) 服务器。

快速 DNS 有两种类型：单泛洪 (single flux) 和双泛洪 (double flux)。单泛洪是一种简单的检测和防止方法，因为它通常作用于单个域名。然而，双泛洪会频繁使用一台被感染的机器（通常称为肉鸡或僵尸）作为代理服务器，保护 C&C 服务器免受任何窥探目光的影响。事实上，可能有很多层代理，这使得定位这些 C&C 服务器变得非常困难。这也使得使用传统方法很难找到这些机器的 IP 地址。这些代理服务器经常注册具有极短 TTL 值的 DNS 节点，这在注册商处看起来很可疑；然而，这种注册通常在不执行网络犯罪法律的国家进行。对这些国家的了解以及对日志的严密监控和自动化检测规则，对于发现此类威胁至关重要。

## 轻量级目录访问协议

最初，轻量级目录访问协议 (LDAP) 的创建是作为访问 X.500 目录服务的轻量级替代协议。X.500 是一系列涵盖电子目录服务的网络标准。X.500 开发是为了支持 X.400 交换和名称查找的需求。

LDAP 使用与 X.500 相同的对象格式，其中每个对象由属性组成，并通过区分名称 (distinguished name) 进行引用。每个对象都有一个唯一的名称，以适应全局命名空间，有助于确定对象的关系并允许对象被唯一引用。

## Active Directory

Active Directory (AD) 是微软对 IEEE 开发的 X.500 建议的版本。AD 保留了网络中所有用户和组的访问权限信息。当用户登录系统时，AD 为用户发放一个唯一标识符 (GUID)。支持 AD 的应用程序可以使用此 GUID 进行访问控制。AD 帮助登录并减少管理员的开销，它有几种方法可能被攻击。

攻击 AD 的难度是面向内部的，这意味着内部人员比外部人员更容易针对它。一种攻击方法是权限提升。在这种情况下，攻击者将现有用户的权限提升到管理员或域管理员。其他潜在的攻击向量可能包括针对密码哈希或 Kerberos 预认证。一个著名的例子是 2011 年的 Night Dragon 攻击。除了使用 RAT、社会工程学、鱼叉式钓鱼和各种操作系统漏洞外，Night Dragon 还试图破坏 AD。

## 安全信息事件管理

另一种流行的安全解决方案是安全信息事件管理 (SIEM)。该服务是两个独立的报告和记录区域的结合：安全信息管理 (SIM) 和安全事件管理 (SEM)。SIM 技术用于处理和处理审计和事件数据的长期存储。SIM 工具用于事件的实时报告。这两种技术的结合为用户提供了告警、捕获、聚合、审查和存储来自许多不同系统和来源事件数据的能力。使用这些系统的主要缺点是配置复杂且需要多个数据库。提供 SIEM 工具的供应商包括 ArcSight、e-Security、Intelligatics、netForensics 和 Network Intelligence。

## 数据库活动监控

考虑你如何使用入侵检测系统来告警潜在的网络攻击。那种保护可以扩展到数据库，形式为数据库活动监控 (DAM) 系统。DAM 设计用于监控数据库并报告未经授权的活动。这种技术被担心安全漏洞和攻击的组织广泛使用，包括银行、金融机构和其他高度监管的市场。DAM 的功能之一是独立于数据库内置控制，并可以执行活动监控、特权用户监控和网络攻击监控。

## 联邦身份

你是否也像有时难以记住访问大量系统的密码和凭据？这就是联邦身份

联邦身份（Federated ID）是连接个人电子身份和属性的方法，这些属性存储在多个不同的身份管理系统中。当然，这些系统的漏洞通常与其他任何系统一样。一个例子是受 CVE-2010-2337 影响的 RSA 联邦管理器。这个特定示例可能允许远程攻击者将用户重定向到任意网站并进行钓鱼攻击，参考 NIST 国家漏洞数据库：`http://web.nvd.nist.gov/view/vuln/detail?vulnID=CVE-2010-2337`。

## 单点登录

管理大量密码的另一种方法是单点登录。单点登录允许用户向单个认证机构进行一次验证，然后无需重新验证即可访问所有其他受保护资源。最常用的单点登录系统之一是 Kerberos。

## Kerberos

Kerberos 有三个部分：客户端、服务器和一个在它们之间调解的可信第三方密钥中心（KDC）。客户端从 KDC 获取票据，并在建立连接时向服务器提交这些票据。Kerberos 票据代表客户端的凭据。Kerberos 依赖于使用数据加密标准（DES）实现的对称密钥加密。当作为 Active Directory 的一部分，Kerberos 是 Windows 7/8/server 2008/server 2012 主机的默认认证机制。Kerberos 提供了快速连接、相互认证、委托认证、简化的信任管理和互操作性。

Kerberos 确实存在一些被犯罪分子利用的领域。其中一个是 Kerberos 与所有认证协议一样，具有定义的寿命。因此，任何使用 Kerberos 协议进行认证的网络都必须确保通过网络时间协议（NTP）等协议使所有系统的时钟同步。请注意，保护 NTP 也同样重要。方法取决于您的特定配置；但是，如果您的网络从 `pool.ntp.org` 接收 NTP 信息，那么与这些特定 NTP 服务器关联的 IP 地址应该是允许通过 UDP 端口 123（默认 NTP 端口）进入网络的唯一地址。可以使用更高级的配置。

## 安全设施解决方案

书中的大部分内容侧重于逻辑控制，但这只是完整安全解决方案的一部分。真正的安全需要逻辑控制、运行控制和物理控制。这正是安全设施解决方案的核心。如果有人物理进入布线间或获得清洁工权限，其危险程度与逻辑攻击一样。

虽然在考虑安全时，建筑布局可能不是首先想，但它们是一个重要的关注点。只需考虑安全的一个方面：对员工和人员的保护。在疏散或灾难期间，出口路线需要良好的标记，应配备电池备用照明，并且建筑出口应保持畅通且已知，以便人们能够安全离开。

从逻辑角度来看，CASP 应该审查建筑布局以确定资产的放置。良好的物理安全使用了分层防御的概念。这种分层方法应用于威慑和延迟入侵。一些关注的项目包括：

- 布线间是否安全？
- 数据中心位于何处？
- 使用了什么类型的窗户？
- 门是空心的还是实心的？
- 关键资产是否位于设施中心？
- 关键区域周围的墙壁是实心的吗？
- 墙壁是否延伸到屋顶而不仅仅是吊顶？
- 是否使用了防撞门（mantraps）？
- 锁是否高质量？
- 是否使用了视频电视监控（CCTV）？

这些只是 CASP 在审查建筑布局时应该考虑的几个项目。
