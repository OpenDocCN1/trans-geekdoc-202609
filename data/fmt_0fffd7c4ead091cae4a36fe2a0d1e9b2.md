
# 代码审查

质量保证和安全编码的最佳实践之一是代码审查（Code Review），它是由代码作者以外的人员对组成软件的指令进行的系统性检查。这种方法是成熟软件开发流程的标志。事实上，在许多组织中，在其他人完成代码审查并签字通过之前，开发者不被允许推送软件模块。可以将此比为在将重要文档发送给重要人物之前对其进行校对。如果你尝试自己进行校对，可能无法像别人检查那样容易地发现所有尴尬的拼写错误和语法错误。

不过，代码审查远不止检查拼写错误，尽管这确实是其中的一个元素。它始于编写软件的组织所开发的编码标准。这可能是一个内部团队、外包开发人员或商业供应商。显然，对现成的商业软件进行代码审查极其罕见，除非该软件是开源的，或者你恰好是一个大型政府机构。尽管如此，每家开发公司都会有一份风格指南或文档化的编码标准，涵盖了从代码缩进到何时以及如何使用现有代码库的所有内容。因此，代码审查的初步步骤是确保作者遵循了团队的标准。除了有助于软件的可维护性外，这一步还让代码审查人员预览了后续工作量；一个粗心的程序员其代码中可能存在许多其他、更难发现的缺陷，而这些每一个缺陷都是潜在的安全漏洞。

# 回归测试

软件几乎不是在第一次尝试时就得安全的。具有成熟开发流程的组织将采取本章讨论的步骤，在系统投入生产之前检测并修复软件缺陷和漏洞。错误不可避免会被发现并导致修复。问题在于，修复漏洞很可能在无意中破坏系统的其他功能，甚至创建出一系列新的漏洞。`regression testing`（回归测试）是一种正式过程，通过对修改过的代码进行测试，以确保没有任何功能和安全特征受到修改的影响。显然，回归测试的有效性取决于为其开发的标准化测试套件。如果测试覆盖范围不足，回归测试可能无法发现在修复过程中可能引入的新缺陷。

# 安全测试

到为止，我们关注的是通常由软件开发或质量保证团队执行的实践（包括测试）。随着项目从开发转向实施，IT 运营和安全团队通常会执行额外的安全测试，以确保新软件以及在新程序引入后整个生态系统的机密性、完整性和可用性。如果组织正在使用 `DevSecOps`，部分或大部分安全测试可以在软件开发期间进行，因为安全人员也将是该阶段的一部分。否则，开发团队将软件交给安全团队进行测试，这些人将几乎会发现缺陷，从而引发一个往复循环，这可能会延迟最终的实施。

## Web 应用漏洞扫描

Web 应用漏洞扫描是漏洞扫描的一种特定形式，我们这种漏洞扫描在本书的第二部分中讨论过（即第 5 章）。与我们在讨论安全编码实践时讨论的测试不同，Web 应用漏洞扫描通常是从恶意用户的角度进行的外部测试。与其他漏洞扫描器一样，这些工具只会尝试识别它们拥有插件的漏洞。这里列出了一些最常见的检查项目：

- 过时的服务器组件（例如，那些可用补丁的组件）
- 服务器配置错误
- 用户的安全身份验证
- 安全会话管理（例如，随机会话令牌）
- 信息泄露（例如，过度暴露服务器信息）
- 跨站脚本 (XSS) 漏洞
- HTTPS 使用不当（例如，允许 SSL）

有许多商业和开源的 Web 应用漏洞扫描器。在本书的第 15 章中，我们介绍了最流行的工具之一，名为 `Nikto`。大多数扫描器都允许你为特定环境开发自定义测试，因此如果你有一些必须满足的独特策略或安全需求，学习如何为你喜的扫描器编写插件或测试是值得的。

## 拦截代理

`interception proxy`（拦截代理）是一种插入在两个通信端点之间的软件工具，用于检查、修改或记录两者之间的消息。通常，拦截代理与其中一个端点（通常是客户端）位于同一个网络（甚至是同一主机）中。在安全测试中，这些代理最常用于检查 Web 应用和移动应用的安全性，因为它们允许安全测试人员检查客户端和服务器之间的每条消息。以下可以使用拦截代理进行测试的安全特征列表：

- **input validation (输入验证)**：虽然可以通过标准用户界面测试输入验证，但通常使用一个环境进行正式（或脚本化）测试更容易，这使得使用代理更高效。
- **parameter validation (参数验证)**：通过修改用户不应获得的值（例如，隐藏的表单字段或 Cookie）或在客户端已验证的值，安全团队可以验证服务器端是否进行了验证。
- **plaintext credentials (明文凭据)**：虽然确保 Web 应用使用 HTTPS 发送凭据相对容易，但在处理移动应用时要困难得多，除非你可以拦截流量。这也可以通过数据包嗅探器完成。
- **session tokens (会话令牌)**：会话通常通过令牌跟踪，令牌是服务器分配的一个值，通常称为会话 ID。如果该值不是真正的随机，攻击者可以猜到有效的会话 ID 并用来冒充合法用户。代理有助于对会话令牌进行统计分析，以确保它们具有足够的随机性。

## 模糊测试

模糊测试是一种通过向目标程序发送大量畸形、意外或随机数据来发现软件缺陷和漏洞的技术。攻击者可以操纵这些错误和缺陷将自己的代码注入系统，从而损害其安全性和稳定性。测试工具通常能够成功识别缓冲区溢出、拒绝服务 (DoS) 漏洞、注入缺陷、验证缺陷以及可能导致软件冻结、崩溃或抛出意外错误的其他活动。图 14-2 显示了一个名为 American Fuzzy Lop (AFL) 的流行模糊测试器导致了目标应用程序崩溃。
