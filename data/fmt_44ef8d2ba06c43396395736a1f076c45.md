
如果 XQuery 求值结果为 null（可能作为参数从 SQL 传递），则谓词结果为 unknown。对于非 null 值，如果 XQuery 求值返回空序列，则谓词值为 false；否则结果为 true。以下示例展示了在 select 语句中使用 `xmlexists` 来检索给定城市中客户的“id”值，客户详细信息存储在 `xml` 类型的列中。

```
select c.custId from customer as c where xmlexists ( ‘ $d/*:customerinfo/*:addr [ *:city = “Salt Lake City” ] ’ passing info as “d” )
```

`is valid` 谓词检查 XML 值是否根据给定的 XML 模式有效。有效性评估的细节有点复杂，此处不予介绍。简化语法如下：

```
xml-value-expression is [ not ] valid [ identity-constraint-option ] [ according to xmlschema { uri | registered-name } ] [ valid-element-clause ]
```

根据命名空间的选择所标识的模式，对 xml-value-expression 进行检查。如果未指定，则根据与其命名空间关联的模式验证每个元素。如果指定，则可以通过 URI 或其注册名称来标识模式。可选的 identity-constraint-option 和 valid-element-clause 参数提供了关于如何执行模式检查的更详细规范。

SQL:2003 标准引入了若干内置 XML 运算符。其中一个运算符 `xmlroot` 可用于修改 XML 表达式的版本和独立属性，但在 SQL/XML:2006 中已被移除，因此此处不予介绍。

## SQL/XML 操作：xmlparse、xmlserialize、xmlconcat 和发布函数

### xmlparse 和 xmlserialize

我们将要查看的前两个 SQL/XML 操作 `xmlparse` 和 `xmlserialize`，用于在 XML 的结构化表示和字符串表示之间进行相互转换。

`xmlparse` 操作接受一个 SQL 字符串表达式并生成等效的 XML 结构。一个参数用于定义字符串表达式预期表示的是文档还是内容。基本语法自 SQL:2003 以来一直保持一致。

```
xmlparse ( { document | content } stringexpression [ { preserve | strip } whitespace ] )
```

操作的结果可以赋给 `xml` 类型的变量，或存储在 `xml` 列中。`xmlparse` 处理空白字符的确切方式受详细规则约束，此处不予讨论。

`xmlserialize` 操作执行 `xmlparse` 的逆操作，生成给定 XML 表达式的字符串版本。SQL 标准并未强制规定结果字符串的确切格式，但要求对 `xmlserialize` 生成的字符串进行后续的 `xmlparse` 应能还原出原始的 XML 表达式。换句话说，给定一个名为 `myXmlData` 的 XML 文档，以下结构：

```
xmlparse ( document ( xmlserialize ( document myXmlData as varchar ( max ) ) ) )
```

应产生等同于 `myXmlData` 的结果。`xmlserialize` 原始的 SQL:2003 语法在 SQL/XML:2006 中得到了扩展。

```
xmlserialize ( { document | content } xmlexpression as SQLdatatype [ version string ] [ including xmldeclaration | excluding xmldeclaration ] )
```

结果的 SQL 数据类型可以是任何 SQL 字符串类型（如 `char`、`varchar`），但序列化后的 XML 往往很长，因此字符大对象（`clob`）类型可能是常见的选择。可选地，`including xmldeclaration` 会在结果前添加 XML 声明 `<?xml version="1.0" encoding="UTF-8"?>`；默认为 `excluding xmldeclaration`。XML 版本也可单独指定；目前这将限制为 "1.0"。

### xmlconcat

SQL:2003 中引入的 `xmlconcat` 操作在 SQL:2006 中得以保留。它只是简单地连接一组 XML 表达式，生成一个新的 XML 表达式。

```
xmlconcat ( xmlexpression [, …] [ returning { content | sequence } ] )
```

可选的 `returning` 子句是在 SQL/XML:2006 中添加的。如果省略此子句，则由实现定义隐式返回 content 还是 sequence。

### 发布函数

SQL:2003 标准定义了多个“发布”函数，用于从 SQL 表达式生成 XML 表达式。这些函数在 SQL/XML:2006 中得到了扩展，并新增了函数。此处我们仅介绍 SQL/XML:2006 中这些函数的定义。

#### xmlelement

`xmlelement` 函数用于根据给定的一组参数创建一个 XML 元素。回顾一下，XML 元素具有基本形式：

```
<tagname optionalAttributes> optionalElementContent </tagname>
```

因此，例如，一个表示客户的元素可能如下所示：

```
<cust custid = "1234"> Widgets Inc </cust>
```

如果需要，标签名可以通过添加命名空间前缀来进一步限定，在这种情况下也必须指定命名空间 URI。`xmlelement` 函数根据提供的参数构建单个 XML 元素，并将其作为 `xml` 值返回。此处展示了字符串的基本语法。还存在一个用于二进制字符串的变体，我们不予讨论。

嵌入的 `xmlnamespaces` 和 `xmlattributes` 函数可选择性地用于给定元素的上下文中，以向元素添加所需的命名空间声明或属性。元素内容由一个表达式列表定义，该列表是可选的，因此可以创建空元素。`returning` 子句也是可选的，我们之前已经见过。

```
xmlelement ( name xmlelementname [ , xmlnamespaces (namespace-declaration-item [,…] ) ] [ , xmlattributes ( attributevalue [as attributename ] [,…] ) [ , elementcontent [,…] [ option { null on null | empty on null | absent on null | nil on null | nil on no content } ] ] [ returning { content | sequence } ] )
```

内容选项需要更多解释。在 SQL 中，缺失的可选值显式标记为 `null`。这不是 XML 中识别的值，尽管 `null` 对 SQL `xml` 数据类型是合法的。根据期望的结果，缺失值可以在 XML 中通过简单地省略相关元素来表示，或者通过包含不含值的元素开始/结束标签来表示。如果需要显式的等同于 `null` 的指示符，另一种选择是“XML Schema For Instances”命名空间中指定的“nil”机制。该命名空间通常通过如下声明引入：

```
xmlns:xsi = "http://www.w3.org/2001/XMLSchema-instance"
```

`xsi` 前缀按惯例使用，但也可替换为其他前缀。一旦定义了该命名空间，XMLSchema-instance 中定义的 `nil` 属性即可设置为 True。

```
<myElement xsi:nil = "true"></myElement>
```

以这种方式标记的元素不能有任何元素内容，但仍可携带其他属性。SQL:2003 标准承认了 `xsi:nil` 选项，但未规定如何将其与 `xmlelement` 等操作结合指定。SQL/XML:2006 对这些选择提供了精细控制，如表 16.4 所示。

#### xmlforest

`xmlforest` 函数是将 `xmlconcat` 应用于一系列 `xmlelement` 结果的便捷方式：它从表达式列表生成一系列元素。这些元素可以显式或隐式命名。与 `xmlelement` 一样，对 `xmlforest` 的调用也可以嵌套。基本语法如下：


## SQL Server XML 构造与 SQL/XML 函数

### FOR XML 构造

SQL Server 使用各种 `for xml` … 构造将关系数据转换为 XML。`for xml path` 变体可按列逐列地完全控制 XML 结构的生成方式。`type` 参数指定结果应为 `xml` 类型，而非其字符串等价物。

### XML 聚合函数

回到 SQL/XML，`xmlagg` 函数是一种聚合函数，类似于 SQL 的 `sum`、`avg` 等。它从给定的一组值中返回单个值，这些值必须是 `xml` 类型表达式的结果。生成的 `xml` 值会被连接以产生单个 `xml` 值。可选择使用 `order by` 子句在连接前对结果进行排序，其语法类似于 SQL。连接前会丢弃任何 `null` 值。如果表达式的所有结果均为 `null`，或该组为空，则 `xmlagg` 函数的结果为 `null` 值。基本语法如下：

```
xmlagg ( XML-value-expression [ order by sort-specification ] [ returning { content | sequence } ] )
```

作为 `xmlagg` 函数的示例，假设我们有一个“Orders”表，并希望按客户分组，为每个客户显示其下单的每个订单的一个元素。为简单起见，我们假设订单和客户均由简单的 ID 值表示。我们可以按如下方式构造结果：

```
select xmlelement ( name “Customer”, xmlattributes ( o.custId as “customerId” ), xmlagg ( xmlelement ( name “order”, o.orderId ) order by o.orderId ) ) as XcustOrders from Orders as o group by o.custId
```

### XML 构造函数

`xmlpi` 函数生成单个 XQuery 处理指令节点，如下所示：

```
xmlpi ( name target [ , string-expression ] [ returning { content | sequence } ] )
```

目标标识符（`name`）不能为 ‘xml’（任何大小写组合），且字符串表达式不能包含子字符串 ‘?>’。`xmlcomment` 和 `xmltext` 函数也很简单，各自仅生成相应类型的节点。以下是这些函数用法的一些示例。

* `xmlpi` ( `name` “Warning”, “Turn off now” ) 生成 `<?Warning Turn off now?>`
* `xmlcomment` ( “This is my comment” ) 生成 `<!-- This is my comment -->`
* `xmltext` ( “Here is my text” ) 生成 `Here is my text`

`xmldocument` 函数返回一个文档节点（按 XQuery 数据模型定义），其内容为给定的 XML 值。这对于将任意 XQuery 序列转换为 XML 文档很有用。

```
xmldocument ( xmlvalue [ returning { content | sequence } ] )
```

### XML 转换与验证

提供了单独的转换函数 `xmlcast`，用于在 XML 值与其他类型之间进行转换。其工作方式与标准 SQL `cast` 函数相同，不同之处在于涉及的数据类型中至少有一个必须是 `xml`。在遵守特定规则（此处不详述）的前提下，也可在 `xml` 的子类型之间进行转换。请注意，XML 值与字符串之间的相互转换，与使用 `xmlparse` 和 `xmlserialize` 函数并不相同。

与 `valid` 谓词类似，`xmlvalidate` 函数确保给定的 XML 表达式根据相关模式定义是有效的。与 `valid` 谓词一样，模式可选择显式指定。然而，与 `valid` 谓词不同的是，`xmlvalidate` 函数还会持久地用类型信息标注 XML 表达式。语法如下：

```
xmlvalidate( { document | content | sequence } xmlexpression [ according to xmlschema { uri | registered-name } ] [ valid-element-clause ] )
```

### XML 命名空间

我们之前看到过 `xmlnamespaces` 函数如何在 `xmlelement` 和 `xmlforest` 函数的上下文中使用。`xmlnamespaces` 更完整的语法为：

```
xmlnamespaces ( { XML-namespace-URI as namespace-prefix | default XML-namespace-URI | no default } [,...] )
```

`default` 选项将命名空间定义应用于任何嵌套元素，除非被较低层级的 `no default` 覆盖。同样，`no default` 选项可被较低层级的 `default` 覆盖。`default` 和 `no default` 选项在 `xmlnamespaces` 参数列表中最多只能各指定一次。
