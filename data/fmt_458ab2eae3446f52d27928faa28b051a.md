正如第 1 章中介绍的，`protocol analyzer`（协议分析器）仅仅是一种工具（硬件或软件），用于捕获和分析通过通信通道（如网络）的流量。虽然协议分析器存在许多类型的通信通道（例如电信流量和系统总线），但 `protocol analyzer` 最常用的用途是捕获和检查网络流量。在网络领域，这通常有多种名称，如 `packet sniffer`（数据包嗅探）、`network analyzer`（网络分析器）或 `network sniffer`（网络嗅探）。嗅探器可用于捕获和分析有线或无线流量，可以是基于软件的（最常见），也可以是专用硬件/软件平台。有效的嗅探器必须能够将网络接口设置为混杂模式（promiscuous mode），这会指示接口接受并处理它看到的每一个数据包——而不仅仅是针对该特定系统或发送到广播、组播或单播地址的数据包。在交换式网络中，嗅探器通常插在 `SPAN`（下一节讨论）或监控端口，这些端口被配置为接收通过同一交换机上一个或多个接口的数据包副本。数据包分析器的能力差异很大——有些只能进行简单的数据包捕获，而另一些则尝试通过解码后的数据包和颜色标记流量流重建整个 TCP/IP 会话。

从安全的角度来看，协议分析器是非常有用且有效的工具。想看你的网络上是否有系统正在通过特定端口传输流量吗？想看是否有数据包被发送到竞争对手公司的地址吗？想看哪些员工整天都在逛 eBay 吗？想找到那个用广播流量淹没本地网络的系统吗？`protocol analyzer` 可以帮助你解决所有这些以及更多问题——只要你将分析器插在网络的正确位置，并能够“看到”你关心的流量。大多数组织在网络中都有多个可以嗅探流量的节点——核心交换机处、在用户群和服务器群之间、在远程用户和核心网络之间、在组织与任何互联网链路之间等。知道如何确保嗅探器能“看到”你想要分析的流量、知道将分析器放置在何处以及如何使用分析器，都是从 `protocol analyzer` 获得最佳结果的关键。

### 漏洞扫描器

`应用程序漏洞扫描器` 旨在寻找应用程序或特定类型应用程序中的漏洞。应用程序扫描器是最专门的扫描器之一——尽管它们包含了成百甚至数千项检查，但它们只针对特定类型应用程序的配置错误或漏洞。可以说，最流行的应用程序扫描器是用于测试 Web 应用程序的缺陷和漏洞的。Web 应用程序的设计目标是可见的、与用户交互并接收和处理用户输入——这些特性都使其成为攻击者极具吸引的目标。因此，市场上存在大量的 Web 应用程序扫描器，从开源到订阅制不等。要成为一个有效的 Web 应用程序扫描器，该工具必须能够对漏洞、配置错误、默认内容、设置、问题等进行数千次检查，并涵盖从 `IIS` 到 `Apache` 再到 `PHP`、`ASP` 以及其之间的所有 Web 技术。应用程序扫描器通常能够执行高级检查，例如 `SQL 注入` 或 `JavaScript 注入`，这些检查需要与被检测的 Web 应用程序进行交互，并根据应用程序的反馈修改请求和响应。图 16-4 显示了 `Acunetix WVS`（网络漏洞扫描器）的截图，这是一种专门针对 Web 技术的应用程序扫描器。

### 蜜罐 (Honeypots)

`蜜罐` 是一个被设计成表现像企业网络中真实服务器的服务器，但它并不拥有真实数据，其包含的数据是伪造的。蜜罐是攻击者极具吸引力的目标。蜜罐充当了攻击者的陷阱，因为蜜罐中的流量可以假设是恶意的。

### 蜜罐网 (Honeynets)

`蜜罐网` 是被设计成像企业网络，但对攻击者具有吸引力的网络。`蜜罐网` 是多个蜜罐的集合。它看起来像企业网络，但由于已知它是虚假的副本，因此所有流量都被认为是非法的。这使得刻画攻击者的流量变得容易，并有助于了解攻击源自何处。

### 端口扫描器 (Port Scanner)

`端口扫描器` 是一种用于探测系统或系统开放端口的工具。它的工作是探测开放（或监听）端口，并向用户报告哪些端口是关闭的、哪些是被过滤的、哪些是开放的。端口扫描器几乎适用于所有的操作系统和几乎所有流行的移动计算平台——从平板电脑到手机。在工具箱中拥有良好的端口扫描工具并知道如何使用它将非常有益。关于端口扫描器的消息/坏消息是，“坏人”使用它们的原因与好人使用它们的原因基本上相同。端口扫描器可以执行以下操作：

* **搜索网络上的“活动”主机。** 大多数端口扫描器允许你使用 `ICMP`、`TCP` 或 `UDP` 包进行快速扫描，以搜索给定网络或网段上的活动主机。`ICMP` 在此任务中仍然流行，但由于许多现代操作系统（如 `Windows 7` 及更高版本）默认拦截了 `ICMPv4`，用户越来越多地转向 `TCP` 或 `UDP` 扫描来完成这些任务。

* **搜索网络上的任何开放端口。** 端口扫描器最常用于识别主机、主机组或网络上的任何开放端口。通过在大量主机上扫描大量端口，端口扫描器可以向你（或攻击者）提供关于你的网络中哪些主机运行着哪些服务的极佳图景。扫描可以针对“默认”的热门端口集、大范围端口或每一个端口进行。

* **搜索特定的端口。** 端口扫描器也可以针对热门端口集、大范围端口或每一个端口进行扫描。Web 服务器？邮件服务器？端口扫描器也可以配置为只查找特定的端口。

* **识别端口上的服务。** 某些端口扫描器可以根据服务或返回的信息帮助识别在开放端口上运行的服务。

* **查找 TCP/UDP 服务。** 大多数端口扫描器可以扫描两者，尽管某些工具不允许同时扫描两者。

作为安全专业人员，你将以与攻击者相同的方式使用端口扫描器：探测系统的开放端口。端口扫描器实际上是如何工作的？这很大程度上取决于你在配置扫描时选择的选项，但为了便于说明，假设你正在对 `192.168.1.20` 运行扫描。当扫描器发送 `SYN` 包时，它会等待响应的 `SYN/ACK`。如果收到 `SYN/ACK`，扫描器将尝试完成三次握手并将端口标记为`开放`。如果发送的数据超时或收到 `RST` 包，扫描器可能会将该端口标记为`关闭`。如果返回“管理禁止”或类似的消息，扫描器可能会将该端口标记为`过滤`。扫描完成后，扫描器将摘要格式显示结果——列出开放、关闭、过滤的端口。通过检查每个端口的响应，你通常可以推断出关于所扫描系统的更多信息，详细如下：

* **开放**端口接受连接。如果你能通过端口扫描器连接到这些端口，说明端口没有在网络层被过滤。然而，在某些情况下，你可能会发现一个被端口扫描器标记为`开放`的端口，当你以其他方式连接它时，它会立即丢弃连接。例如，`SSH` 的 22 端口在端口扫描器看来可能是开放的，但它会立即丢弃你的 `SSH` 连接。在这种情况下，服务可能被主机防火墙或服务本身的防火墙功能过滤。

* **关闭** 当扫描目标返回 `RST` 包时，你通常会看到这种响应。

* **过滤** 当返回 `ICMP` 不可用错误时，你通常会看到这种响应。这通常表明端口被防火墙或其他设备过滤。

* **其他类型** 某些端口扫描器会尝试对响应进行进一步分类，例如丢弃、阻塞、拒绝、超时等。这些具有特定的工具属性，你应该参考随附该端口扫描器的任何文档或帮助文件以获取更多信息。

通常情况下，你可能希望使用不同的选项多次运行扫描，以确保获得更全面的视图。`SYN` 扫描返回的结果可能与 `NULL` 扫描或 `FIN` 扫描不同。你可能还需要同时运行 `TCP` 和 `UDP` 扫描。你可能需要调整扫描方法，在一天中夜晚的不同时段使用多种技术，以确保完全覆盖。坏人现在正对你的网络进行这些操作，所以你也可以使用与他们相同的工具来查看他们所看到的内容。端口扫描器在测试防火墙配置时也非常有用，因为端口扫描的结果可以精确地显示你哪些端口是开放的、哪些端口是你允许通过的、哪些端口正运行着服务等等。

那么，你该如何防御端口扫描呢？嗯，这很困难。端口扫描现在几乎是互联网流量格局的一部分。尽管你可以阻止扫描扫描的 IP 地址，但大多数组织并不会这样做，因为你面临着攻击者伪造源地址以作为其他扫描活动诱饵的风险。最好的防御方法是使用防火墙、网络过滤器和主机过滤器来仔细控制进出你网络的流量。然后仔细监控任何你允许进入的流量。

#### 风险计算

评估系统安全态势的要素是确定系统面临的风险。尽管存在许多潜在的威胁和漏洞，但对代表最大风险的攻击向量优先采取行动和防御措施是非常关重要的。风险通过发生的概率和威胁的严重性来衡量。这两个衡量标准刻画了风险，并可以根据对系统的影响做出适当决策。

正如第 5 章中详细所示，风险计算中常用的一种方法是：

```
风险 = 威胁 × 漏洞（影响）× 资产价值
```
