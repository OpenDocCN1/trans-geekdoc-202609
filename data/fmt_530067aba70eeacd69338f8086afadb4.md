
为了开始使用以太坊区块链，开发者需要将系统配置为以太坊节点。根据数据大小，开发者可以在机器上配置三种类型的节点：全节点、轻节点或归档节点。运行自己的节点在数据和电源管理方面有些复杂。替代方案是第三方 API 提供商，如 `Infura` 或 `Alchemy`。Infura 是一个在其端维护以太坊区块链节点的应用程序，而非在客户端机器上。在 `Geth` 的情况下，客户端需要安装以太坊区块链并保持其在机器上运行以同步区块链账本。要使用 Infura，用户需要在 [`infura.io`](https://infura.io) 注册，以获取用于连接区块链的链接和唯一令牌 [3]。

## Mist

**Mist** 是被认可为 ETH 官方钱包的以太坊钱包。Mist 是一个基于浏览器的应用程序。Mist 由以太坊团队开发和管理，在撰写本文时仍处于 Beta 版本。客户端脚本（如 `JavaScript`）在浏览器上运行，以获取用于与 `Geth` 通信的各种 API。Mist 的主要目标是创建第三代网络（Web 3.0），通过利用以太坊、`Whisper` 和 `Swarm` 作为中心化服务器的替代方案，消除对服务器的需求 [34]。

## Geth

为了与以太坊区块链交互，需要一个客户端。交易广播、挖矿和其他任务由客户端处理。以太坊有两个流行的客户端：`Geth` 和 `Parity`。Geth，即 `Go Ethereum` 的简称，是一个以太坊区块链客户端，允许用户与其他客户端建立点对点通道，进行挖矿、浏览、部署和与智能合约交互。Geth 是一个用 Go 编程语言编写的命令行应用程序。Geth 下载包支持所有主流操作系统 [4, 34]。

## 去中心化应用

**DApps** 是在区块链或计算机点对点网络上运行的数字应用程序或系统，而非单个独立设备或系统。典型的 Web 应用（如 Uber 或 Twitter）运行在由公司拥有和控制的计算机系统上，使其完全控制应用的功能。换句话说，可能有多个用户，但后端由单一实体管理。DApps 可以在点对点（P2P）网络或区块链网络上运行。`BitTorrent`、`Tor` 和 `Popcorn Time` 是运行在点对点（P2P）网络中计算机上的软件，多个用户在其中消费内容、播种内容，或同时执行两者。DApps 在一个公开、开放、去中心化的世界中运行，在使用加密货币时没有限制。例如，开发者可能构建一个类似 Twitter 的 DApp 并将其部署在区块链上，允许任何用户发布消息。一旦消息上传，没有人（包括应用开发者）可以将其删除 [14]。

## IPFS

**IPFS** 是一个区块链兼容的存储系统，始于 2015 年 Protocol Labs 的一个项目，旨在创建一个框架，从根本上改变信息在全球传输的方式，并为分布式、更健壮的网络铺平道路。IPFS 已发展以服务于各种用例，并正在为从音乐行业的去中介化到农业天气风险安全等各个行业开发知识处理。IPFS 是文件、网站、程序和数据的分布式存储和访问机制。它是传输层无关的，这意味着它可以使用多种传输层进行通信，包括 `TCP`、`UTP`、`UDT`、`QUIC`、`TOR` 甚至 `Bluetooth`。IPFS 拥有管理数据和内容在网络中移动的规则和协议。一个例子是 `Kademlia`，一种点对点分布式哈希表（DHT），因其在 `BitTorrent` 协议中的使用而普及 [20]。

## Remix

**Remix** 是一个开源的移动和桌面框架，提倡包含许多用户友好界面插件的快速开发周期。Remix 用于合约创建过程，以及以太坊的学习和教学环境。Remix IDE 是 Remix 项目的一部分，包含一个用于基于插件的开发工具的论坛。Remix Plugin Engine、Remix Libs 和 Remix-IDE 是其子项目。Remix IDE 是一个流行的开源平台，用于直接在浏览器中编写 Solidity 合约。它用 `JavaScript` 编写，可在浏览器或桌面上使用。Remix IDE 包括智能合约训练、调试和部署等模块 [36]。

### 预言机

**预言机**：这些链下数据存储库充当区块链与外部世界之间的桥梁。链下数据对区块链和智能合约不可见；然而，为了执行特定的合约安排，拥有来自外部世界的相关细节至关重要。这就是区块链预言机发挥作用的地方，因为它们提供了链下和链上信息之间的连接。预言机在区块链生态系统中很重要，因为它们扩展了可使用的智能合约的范围。通常，如果没有预言机提供的更新且独立的数据，智能合约将毫无用处。区块链预言机是一个层，它在中继信息之前查询、验证和认证外部数据源。价格详情、支付的有效完成或传感器测量的温度都是由预言机传输的数据示例。必须调用智能合约并消耗网络资源，才能从外部世界调用数据。除了将信息中继给智能合约外，某些预言机还可能将信息发送回外部源。

工具使开发区块链应用的过程更容易，并有助于软件应用的创建。因此，它们促进了我们区块链认知的扩展 [30, 38]。

## 集成开发环境

根据 Lyn 的说法，集成开发环境 (IDE) 是一种应用软件，为应用开发人员提供一个单一平台来设计、测试和调试计算机程序。消除错误或缺陷的过程称为调试，借助调试工具来实现。调试创造了一种环境，使创建或开发卓越的软件应用变得容易。文本编辑器、终端、调试工具和代码片段是集成开发环境中通常包含的工具 [29]。

IDE 甚至可以使用编译或解释工具，或两者兼用，从而提供一个有利于软件开发的氛围。现代 IDE 配备了对象浏览器、类浏览器和类层次结构图功能 [9]。

一些 IDE 在 JavaScript 或 Python 平台上运行 [45]。IDE 是一个单一的图形用户界面，以调试器、本地构建自动化和源代码编辑器为支柱。供开发人员使用，本地构建自动化利用简单的冗余任务。凭借语法高亮等广泛功能，源代码编辑器有助于软件代码的创建 [19]。

IDE 工具提高了生产力和执行持续编译、自动化测试、集成调试、重构和类间导航等任务的能力。Eclipse 和 Visual Studio 也可与 IDE 配合使用。在使用 Visual Basic 时，IDE 开发人员可以在代码行旁设置或清除断点。此外，在 IDE 底部的“即时窗口”中，开发人员可以使用 Visual Basic 语句。因此，IDE 的重点是为软件程序员在软件应用开发中提供全面的设施 [41]。

## 区块链开发的良好实践

*   **谨慎调用外部合约，优先使用自有合约**：强烈建议尽可能优先使用内部合约而非第三方创建的合约。换句话说，所有内部开发的合约都已经过与解决方案其余部分相同级别的安全性、审查、测试和验收标准的约束，因此它们将符合为解决方案其余组件设定的相同质量和安全标准。应分配足够的审计和测试时间及精力，以仔细审查任何外部合约的源代码。使用第三方合约时，必须确保不存在由第三方造成的固有安全缺陷。

*   **处理所有错误；捕获外部调用中的所有异常**：在智能合约中，函数必须被 `try/catch` 语句包围，并且必须显式处理每一个异常，无论其看起来多么不可能发生。所有未被显式捕获和管理的异常都应被抛出，并将异常上抛至其调用函数或合约。合约应尝试妥善处理异常，并尝试在无需用户干预的情况下继续执行。如果无法做到这一点，应发送一条错误消息，并附带关于如何解决该错误的建议。如前所述，在处理外部合约时，不应假设另一位开发人员已采取相同的预防措施。如果用户收到任何意外或晦涩难懂的错误，他们会认为该应用程序存在缺陷 [8]。

*   **推送支付与拉取支付**：基于推送的金融交易是指卖方使用自动交易从客户账户中电子扣除或添加资金。执行自动每月或每年扣款的订阅或公用事业付款计划是基于推送的金融交易的一个例子。在区块链环境中，拉取支付提供了一项重要优势。进一步解释，拉取支付应将支付过程分为两个阶段。第一步应是一条通知，告知用户有可用资金等待从智能合约中拉取。在第二步中，收款人应根据通知采取行动，将可用资金从收款人的正确钱包地址中拉出。与传统银行交易不同，这种方法将有助于避免资金被发送到无法撤销的错误钱包地址的问题 [7, 12, 32, 35, 43]（图 9.1 和 9.2）。

## 区块链开发最佳实践

### 链上公开数据

链上交易的常见示例是发生在区块链上并由区块链状态验证的加密货币交易。这些交易提供了高安全性和透明度。与链上公开交易相比，链下公开交易通常受到更好的保护，因为更细粒度的交易信息不会公开暴露。此外，链下交易通常成本更低、速度更快。链上公开数据具有高可用性，但隐私和机密性的丧失是权衡因素，因为任何节点都可以随时自由加入网络。使用公共区块链的其他缺点包括交易吞吐量低、存储可扩展性差以及处理费用。为了更好地保护链上公开数据，可以在链上配置中使用辅助链，基于性能、成本和隐私权衡构建存储层级 [[23]](#ch17.xhtml#r336), [[31]](#ch17.xhtml#r344), [[33]](#ch17.xhtml#r346)。

### 从本地测试开始，再部署到测试网络，最后上生产环境

开发人员需要确保在将新区块链推送到测试或生产区块链之前，在本地开发环境中对其进行广泛测试。这在使用以太坊公共区块链（如 `Ganache` (TestRPC)）时尤为重要。由于区块链的特性，区块链上的所有记录都是永久的（仅追加账本），智能合约永久存储在区块链上，因此即使过时和停用的合约仍保留在网络上。在外部测试网络（如 `Rinkeby` 或 `Ropsten`）上测试之前先在本地测试软件是一个良好的实践。一旦部署到生产区块链，成本会迅速增加，因此彻底的测试是必要的。将区块链嵌入生产环境需要一些实际成本，因此开发人员需要确保先运行大量测试以防止不必要的支出 [[8]](#ch17.xhtml#r321)。第 10 章 更详细地讨论了测试程序和方法。

### 发布前和发布后采用敏捷方法

敏捷方法通常最适合小型、自我组织的团队，这些团队可能位于同一地点，且正在处理需求变化的项目。敏捷方法被认为能够按 DApp 项目的预期频繁且快速地交付。需要考虑的问题是，在设计区块链应用程序时是否仍可使用敏捷方法。智能合约和区块链的本质为这个问题提供了答案。由于每个智能合约都在区块链上创建一条无法在激活后删除的永久记录，因此不建议在合约投入生产后保持持续发布和开发的敏捷周期，因为终止合约或调用合约的 `self-destruct` 函数（如果已实现）会带来重大后果 [[7]](#ch17.xhtml#r320), [[8]](#ch17.xhtml#r321), [[28]](#ch17.xhtml#r341)。

### 将复杂性保持在中间层

开发人员应努力使新区块链应用程序的底层和顶层尽可能基础。因此，新区块链的用户界面和智能合约层应尽可能保持简单。业务逻辑作为应用程序中更复杂的部分，应在中间层实现 [[8]](#ch17.xhtml#r321), [[15]](#ch17.xhtml#r328)。

## 总结与结论

本章讨论了许多区块链工具和技术，旨在帮助信息和内部审计师熟悉新区块链的应用开发过程。类似于洋葱，区块链架构由多层组成。使用集成开发环境（`IDE`）是有益的，因为该环境提供了用于编写代码、组织文本分组和自动化编程冗余的用户界面。

本章讨论了许多推荐的应用开发概念。这些包括倾向于拉取支付、在开发过程中遵循“三明治复杂性模型”、倾向于内部合约等。这些概念将有助于创建没有不必要安全漏洞的解决方案。

## 核心概念

*   区块链技术在过去几年中极大地增长了知名度。由于许多惊人的相似之处，许多人发现很难区分区块链和数据库。区块链是一种数据库形式。反之则不然。

*   区块链平台有助于开发基于区块链的应用程序，可以是许可型或无许可型。`Ethereum`、`Hyperledger`、`R3` 和 `Ripple` 是一些允许人们在区块链上开发和托管应用程序的内置框架。

*   区块链工具的主要目的是解决在区块链应用程序开发的各个阶段发生的众多需求。区块链工具的功能是使设计区块链软件解决方案的过程更容易。

*   集成开发环境（`IDE`）是一种软件应用程序，它通过允许软件开发人员在一个环境中设计、构建、测试和调试计算机程序来为他们提供便利。`IDE` 中可能包含的一些工具包括调试工具、文本编辑器、终端和代码片段。

*   在开发区块链解决方案的背景下，许多人质疑敏捷方法论是否仍可应用。答案在于区块链开发应主要被视为固件（相对于软件）开发来对待。

*   建立一个基于拉取而非推送基础的区块链支付系统。拉取支付将支付过程分为两半，给合约两个地方来检查正确的用户是否在提取资金，并允许用户在之前的钱包地址不再有效或已被泄露时提供新的钱包地址。因此，将拥有更安全的环境。
