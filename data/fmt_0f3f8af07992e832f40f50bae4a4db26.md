
互联网消息访问协议版本 4 (IMAP4) 是另一种类似于 POP3 的协议，它允许客户端使用 TCP 端口 143 从邮件服务器检索消息。除了 POP3 提供的四个基本文件夹外，IMAP4 还允许使用其他文件夹。例如，你可以使用 IMAP4 客户端连接到存储在 Microsoft Exchange Server 上的公共文件夹。

## SNMP

简单网络管理协议 (SNMP) 是一种互联网标准，它为通过 UDP 端口 161 远程管理几乎任何支持 SNMP 的网络设备提供了一种简单的方法。网络设备可以是服务器中的网卡；运行在服务器上的程序或服务；或网络设备，如集线器、交换机或路由器。

SNMP 标准定义了一种管理网络设备的双层方法：中央管理系统和位于被管理设备上的管理信息库 (MIB)。管理系统可以监控一个或多个 MIB，从而实现对网络的集中管理。通过管理系统，你可以查看宝贵的性能和网络设备运行统计数据，使你无需离开办公室即可诊断网络健康状况。

管理系统的目标是提供集中的网络管理。任何运行 SNMP 管理软件的计算机都被称为管理系统。为了使管理系统能够执行集中网络管理，它必须能够收集和分析多种类型的数据，包括以下内容：

- 网络协议识别和统计
- 动态识别连接到网络的计算机（称为 `discovery`）
- 硬件和软件配置数据
- 计算机性能和使用统计
- 计算机事件和错误消息
- 程序和应用程序使用统计

## FTP

文件传输协议 (FTP) 是一种 TCP/IP 协议，用于在 FTP 服务器和客户端之间上传和下载文件。与 Telnet 和 ping 一样，FTP 可以通过使用主机名或 IP 地址与远程计算机建立连接，并且必须将主机名解析为 IP 地址，以便与远程计算机建立通信。

![Image](img/exam.jpg)

**考试重点：请记住 FTP 是一个使用两个端口的协议。TCP 端口 21 在系统之间传输 FTP 命令，而 TCP 端口 20 负责在 FTP 会话中在两台主机之间传输数据。**

安装 TCP/IP 时，会提供一个 FTP 实用程序，但所有操作系统也都有许多第三方图形用户界面 (GUI) FTP 客户端可用。如果你大量使用 FTP，GUI FTP 客户端可以在处理 FTP 命令时为你节省大量时间和精力。

### TFTP

简单文件传输协议 (TFTP) 是一种相比 FTP 更简单的协议，仅支持文件的读取和写入。TFTP 不支持列出目录内容或身份验证等功能。TFTP 使用 UDP 作为传输协议，而 FTP 使用 TCP。TFTP 通常用于通过 UDP 端口 69 将路由器和交换机配置从设备复制到 TFTP 服务器。TFTP 也可用于通过加载存储在 TFTP 服务器上的配置来引导设备。

### SFTP

安全文件传输协议 (SFTP) 是一种类似于 FTP 的交互式文件传输协议，但它会加密 SFTP 客户端和 SFTP 服务器之间的所有流量。SFTP 支持公钥身份验证和压缩等附加功能。与 TFTP 不同，SFTP 在其交互式 Shell 中确实支持许多命令，例如列出目录内容、创建目录、下载文件和上传文件。

### Telnet

Telnet 是一种运行在 TCP 端口 23 上的终端仿真协议，允许客户端运行或仿真服务器上运行的程序。许多设备允许你“Telnet”进入该设备，并使用 Telnet 会话可用的命令集对网络设备执行远程管理。

### SSH

安全外壳 (SSH) 是一种程序，用于通过 TCP 端口 22 上的安全连接与远程系统创建一个 Shell 或会话。一旦建立远程会话，客户端就可以在此 Shell 中执行命令并将文件复制到本地系统。SSH 的主要目的是支持具有安全身份验证和加密通信支持的远程 Shell；因此，应使用 SSH 代替 Telnet，因为 Telnet 使用未加密的通信。

### SCP

安全复制协议 (SCP) 负责通过安全连接将文件从远程服务器复制到本地系统，确保传输中的数据保持机密。许多 SCP 产品使用 SSH 连接来确保安全复制操作的安全性。

## NetBIOS

网络基本输入/输出系统 (NetBIOS) 是一种应用程序编程接口 (API)，用于对远程系统进行网络调用以及会话管理功能。NetBIOS 是一种会话层协议，随其他可路由协议（如 TCP/IP）一起安装，以允许 NetBIOS 流量跨网络传输。NetBIOS 有两种通信模式：

- **会话模式** 用于面向连接的通信，在这种通信中，NetBIOS 负责与目标系统建立会话、监控会话以检测传输中的任何错误，并通过重传任何丢失或损坏的数据来从这些错误中恢复。
- **数据报模式** 用于无连接通信，这种通信不需要会话。数据报模式也用于 NetBIOS 的任何广播。数据报模式不支持错误检测和纠正服务，因此这些服务由使用 NetBIOS 的应用程序负责。

Microsoft 使用 NetBIOS 名称（也称为计算机名称）作为在网络上识别系统的方法。NetBIOS 名称最长可达 16 字节——15 字节用于名称，1 字节用于 NetBIOS 名称后缀（名称末尾的代码，代表正在运行的服务）。NetBIOS 计算机名称在局域网上必须是唯一的。

### 网络存储协议

#### 多种协议允许系统与网络上的磁盘存储设备通信

- **光纤通道** 一种可传输高达 128 Gbps 数据并使用特殊光缆将共享存储设备连接到服务器的技术。
- **iSCSI** 互联网小型计算机系统接口是一种基于 IP 的协议，用于与存储设备通信。`iSCSI` 流量将 `SCSI` 磁盘命令从主机传输到网络上的存储设备。与 `Fibre Channel` 相比，`iSCSI` 的优势在于连接共享磁盘解决方案不需要特殊硬件；您可以使用现有的网络基础设施，结合 `iSCSI`，与网络上的共享磁盘通信。最佳实践是在专用网络基础设施上运行 `iSCSI`，以便在使用传统网络硬件的同时获得最佳性能。
- **FCoE** 以太网光纤通道是一种协议，用于在以太网帧中通过以太网网络传输 `Fibre Channel` 命令。重要的是要注意 `Fibre Channel` 运行在第 2 层，因此它不可跨 IP 网络路由（而 `iSCSI` 基于 IP，因此可路由）。

### 理解 IPv6

Security+ 考试针对任何 TCP/IP 相关内容均聚焦于 TCP/IP 版本 4 (`IPv4`)，但您需要了解 `IPv6` 带来的变化。第一个主要区别在于寻址方案——`IPv4` 基于 32 位寻址方案，而 `IPv6` 基于 128 位寻址方案。

互联网的部分区域已在使用 `IPv6`，新区域也在每天升级。`IPv6` 采用 128 位寻址方案，是因为 `IPv4` 的 32 位寻址方案已无法创建足够的地址。`IPv6` 协议的重点之一是解决 `IPv4` 存在的地址短缺问题，因此该协议使用 128 位寻址方案。

![Image](img/exam.jpg)

**`IPv4` 使用 32 位寻址方案，而 `IPv6` 是一种使用十六进制地址格式的 128 位寻址方案。对于 Security+ 考试，您需要了解 `IPv6` 地址方案的基础知识。**

#### IPv6 地址

`IPv6` 地址是一个以十六进制格式显示的 128 位地址，而非 `IPv4` 使用的点分十进制表示法。`IPv6` 地址被划分为八个 16 位组，每组之间用冒号 (`:`) 分隔。以下是一个 `IPv6` 地址示例：

![Image](img/p0039-01.jpg)

`IPv6` 地址不区分大小写，引用开头带有前导零的系统时，您无需在地址开头放置前导零。您还可以在引用包含零组的地址时，用双冒号 (`::`) 替换连续的零。例如，`IPv6` 中的回环地址是 `0:0:0:0:0:0:0:1`，可缩写为 `::1`，其中 `::` 替换了地址开头所有连续的零。此过程称为*零压缩*。请记住，地址只能压缩一次，因此如果地址中有多处连续零，您只能压缩其中一处。

![Image](img/exam.jpg)

**对于 Security+ 考试，您需要知道 `IPv6` 使用 128 位地址空间。您可能还会被要求识别 `IPv6` 回环地址 `0:0:0:0:0:0:0:1`。**

`IPv6` 使用三种地址类型：

- **单播** 用于一对一通信。
- **多播** 用于向一组系统发送数据。
- **任播** 应用于提供服务的一组系统。向任播地址发送数据的客户端，其数据可能被发送给属于该任播地址的任意系统。

为了增加复杂性，您应熟悉 Security+ 考试涉及的不同类型的单播地址：全球单播、站点本地单播和链路本地单播地址处理不同类型的单播流量。以下是各类单播地址的快速细分：

- **全球单播** 可在互联网上路由的公共 `IPv6` 地址。分配给主机的地址在互联网上必须唯一。此地址类型相当于 `IPv4` 中的公网 IP 地址。
- **站点本地单播** `IPv6` 协议的私有地址；地址始终以 `FEC0` 开头。给系统分配站点本地地址相当于在 `IPv4` 中使用私有地址，如 `10.0.0.0`。站点本地地址不能用于站点或网络外的通信，也无法被互联网上的其他站点或系统访问。
- **链路本地单播** 一种自动分配的地址，仅用于与链路上的其他节点通信。链路本地地址始终以 `FE80` 开头。此地址类型相当于 `IPv4` 中的 `APIPA` 地址。

![Images](img/job.jpg)

**您应熟悉 `IPv6` 中的两个保留地址：回环地址 `0:0:0:0:0:0:0:1`（或 `::1`），以及未指定地址的系统地址 `0:0:0:0:0:0:0:0`（或 `::`）。**

#### IPv6 协议

不仅地址方案随 `IPv6` 发生了变化，`IPv6` 协议套件中存在的协议也随之改变。以下是 `IPv6` 协议套件中使用的几个协议的快速细分。

**IPv6**   新版 IP 负责逻辑寻址和路由功能，这与 `IPv4` 的情况相同。它是一种无连接协议，依赖 `TCP` 等上层协议来保证传输。

**ICMPv6**   `ICMP` 协议负责错误和状态信息，这与 `IPv4` 中一样，但它已被修改。`ICMPv6` 使用代码，而 `ICMPv4` 使用类型和代码。对于 `ICMPv6`，每个代码指示消息类型。代码 0 到 127 用于错误消息，而代码 128 到 255 用于信息消息。例如，回显请求消息在 `ICMPv6` 中是代码 128，回显应答消息是代码 129。

与 `IPv4` 相比，`ICMPv6` 扩展了其功能。您应熟悉 `ICMPv6` 协议的以下两个特性：

- **多播监听器发现 (MLD)** 取代了 `IPv4` 中称为互联网组管理协议 (`IGMP`) 的多播协议，用于多播通信
- **邻居发现 (ND)** 通过执行相同功能取代了 `IPv4` 中的 `ARP`，但它还负责邻居路由器发现、自动地址分配和重复地址检测等功能

`IPv6` 已完全重新设计并提供许多额外的新功能，但对于 Security+ 考试，您只需掌握基础知识。有关 `IPv6` 的更多信息，请访问 <http://technet.microsoft.com/library/dd379473.aspx>。

#### IPv6 的影响

Security+ 考试确实要求您了解使用 `IPv6` 的安全影响。以下是 `IPv6` 安全顾虑的综述：

- **缺乏专业知识** 由于 `IPv6` 对大多数网络而言仍相对较新，因此缺乏专业知识和对协议实现中可能存在的安全漏洞类型的充分理解。这意味着对于不熟悉该协议的 IT 人员来说，了解如何防范 `IPv6` 攻击也是一个关注点。
- **协议复杂性** 与 `IPv4` 相比，`IPv6` 协议套件的复杂性增加了黑客潜在的攻击途径，超出了我们在 `IPv4` 中看到的范围。例如，`IPv6` 不仅有用于 IP 地址分配的 `DHCPv6`，还拥有*无状态地址自动配置 (SLAAC)*，这是另一种可能为黑客提供不同攻击途径的技术。
- **IPv6 安全设备支持** 另一个考量因素是保护公司资产的安全设备。这些安全设备是否已更新以支持 `IPv6` 的功能？您能否同等使用安全设备的功能集来应对 `IPv4` 和 `IPv6`？您可能会发现设备上 `IPv6` 对安全功能的支持有所欠缺。
- **双栈漏洞** 由于公司正缓慢迁移至 IPv6，因此它们仍需运行 IPv4。这意味着您同时在运行两种不同的协议，每种协议都有其自身的一系列需要注意的安全问题。同时运行这两种协议的一个常见风险是，您的企业可能专注于加固 IPv4，却未意识到 IPv6 默认已加载在您的系统和网络设备上。如果您不加固 IPv6，就有遭受基于 IPv6 协议攻击的风险。

### 网络安全最佳实践

本章向您介绍了许多网络概念、协议和设备，旨在复习 Network+ 知识，但更重要的是确保您理解与后续章节中某些安全主题相关的关键网络概念。在进入下一章之前，我想总结一些关于网络设备和协议安全最佳实践的关键点。

#### 设备使用

本章前面您了解了路由器、交换机和代理服务器等设备的用途。以下是关于网络设备使用的一些关键点，有助于创建安全的网络环境。

##### 物理安全

确保所有服务器和网络设备（如路由器和交换机）存放在安全位置，例如上锁的服务器机房。您还应确保控制并监控谁有权访问网络的这些物理组件。

##### 不要使用集线器

如今大多数环境使用的是交换机而非集线器，但如果您发现网络上连接了旧集线器，请务必用交换机替换它，以便流量仅发送到目标系统所在的端口。

##### 使用端口安全

您还应确保交换机上未使用的端口均已禁用，以帮助防止未经授权的人员连接到可用端口。在高安全环境中，您应在端口上配置端口安全，这是一种指定允许哪些 MAC 地址连接到特定端口的方法。

端口安全也是对抗 `MAC 泛洪` 的绝佳对策，后者涉及黑客向交换机发送包含不同源 MAC 地址的帧。这可能导致两种情况发生：

- 交换机在 MAC 地址表中看到所有虚假条目，不再信任该表，导致交换机将所有帧泛洪到所有端口（称为故障开启状态）。
- MAC 地址表中的条目被覆盖，导致交换机不知道有效 MAC 地址位于哪个端口。当交换机不知道特定 MAC 地址的位置时，它会将帧 `泛洪` 到交换机的所有端口，这给了黑客捕获流量的机会，因为交换机不再过滤流量。

![Image](img/exam.jpg)

> **针对 Security+ 考试，请记住 MAC 泛洪是指黑客使交换机陷入混乱，将所有帧泛洪到所有端口。这允许黑客连接到交换机上的任意端口，并能够接收网络上的所有流量。**

黑客绕过交换机过滤功能的另一种方法是 `ARP 投毒`，它会毒害所有系统上的 ARP 缓存，迫使它们将数据发送到黑客的系统以访问互联网。黑客捕获流量，然后将其路由到互联网供用户使用！您将在第 4 章详细了解 ARP 投毒。

##### 使用 VLAN

交换机另一个应使用的重要功能是 VLAN，因为它们提供了一种通过将端口划入其中来创建不同通信边界的方法。请记住，默认情况下，一个 VLAN 中的系统无法与另一个 VLAN 中的系统通信。

#### 线缆和协议使用

在高安全环境的网络布线方面，您应使用光纤布线，因为传输是通过光脉冲而非电信号进行的。这具有巨大的安全优势，因为作为电信号通过铜缆传输的数据容易受到其他电气组件的干扰，而通过光纤传输的数据不受电气干扰影响。另请注意，UTP 线缆会泄漏信号，因此理论上传输可能被窃听。由于光纤布线不使用电信号，传输不会泄漏，因此无法被窃听。

与同轴或双绞线通信相比，光纤布线也不容易被 `窃听`。黑客有可能通过反射部分光线，然后将该光线转换为电信息供其计算机查看，从而窃听光纤线路。尽管这种攻击是可能的，但使用线缆上的适当入侵检测系统，也很容易检测到此攻击造成的光损耗。
