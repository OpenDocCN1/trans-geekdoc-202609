# 文档高层视图

安全专业人员可以通过审查战略计划并检查公司的政策与流程，学习关于该组织的大量知识。在管理良好的公司中，政策等高层文档反映了管理层对公司的看法。在过去 10 到 15 年的安全评估经验中，我发现许多公司没有完整或深入的政策来涵盖运营的关键领域。政策应当存在，以涵盖组织控制的大多数方面，因为公司在法律和业务要求上必须制定政策和程序。其中一个例子是《萨班斯-奥克斯莱法案》（SOX）。该法案强制要求公司实施严格控制，并要求它们建立政策和程序。对于那些不合规的公司，责任人员将面临罚款，并可能面临最高 20 年的监禁。政策应该规定谁负责，以及必须遵守哪些标准以满足最低的公司治理要求。

管理层负责定义组织结构，因此将公司划分为较小的子小组以控制特定功能。政策和程序是控制文档，规定了每个功能区域活动的如何进行。安全专业人员应该始终查看了哪些文档、文档更新的频率，以及它们涵盖了哪些活动。你可能会发现公司没有建立相关政策。在某些情况下，可能是因为技术发展太快，导致公司尚未适应。在其他情况下，可能是公司认为没有必要政策，或者尚未将政策开发作为首要任务。

# 政策开发过程

政策的开发有两种基本方法。在某些组织中，政策的开发从组织的顶层开始。这种方法被称为自上而下的政策开发，意味着政策从高级管理层推送到公司的较低层次。自上而下政策开发的巨大优势是确保了政策与高级管理层的战略和愿景保持一致。这种过程的缺点是需要大量时间来实现，并且可能无法完全解决普通员工的运营关注问题。另一种方法是从下而上开发政策。自下而上的政策开发方法考虑了普通员工的关注。该过程从他们的投入和关注开始，并在组织小组的员工和经理识别出的已知风险的基础上构建。主要的缺点是，该过程可能无法与高级管理层的策略良好匹配。

在尝试 CASP 考试之前，你应该能够识别特定类型的政策。一些基本类型包括：

- **监管性（Regulatory）**：监管性政策确保组织的标准符合当地、州和联邦法律。经常使用这些政策的行业包括医疗、公用事业、炼油、教育和联邦机构。
- **信息性（Informative）**：信息性政策不是为了执行；它们的创建是为了教学或帮助员工及他人理解特定规则。信息性政策的目标是告知员工或客户。零售店信息性政策的一个例子是如果你保留收据，在商店购买的物品享 90 天内现金退货政策。
- **咨询性（Advisory）**：咨询性政策旨在确保所有员工了解某些行为和行动的后果。咨询性政策的一个例子是接受使用政策（AUP）。该政策可能建议员工如何使用互联网，并可能禁止员工访问社交网络或色情网站。政策可能规定被发现违反政策的员工可能面临纪律处分，最高可包括解雇。

> 你们公司是否有明确定义的政策？员工应至少每年通过电子或纸质手册手动审核流程对政策进行审查，以便让员工清楚什么是允许的、不允许的，以及正确的程序是什么。

# 政策与程序

政策是高层文档，由管理层开发，用于将管理的整体战略和哲学传给所有员工。高级管理层和流程所有者负责该组织。政策是一种模板，意义在于它们将指导应用于管理层的意愿。政策详细说明、定义并规定了对员工的期望，以及管理层打算如何满足客户、员工和利益相关者的需求。

CASP 应该感兴趣的一种特定类型政策是公司的安全策略。安全策略（security policy）是规定管理层对信息系统的的使用、操作和安全的承诺文档。你可能认为该策略只涉及逻辑安全，但大多数安全策略还考虑物理控制。物理安全是构建安全环境和整体安全计划不可或的一部分。安全策略规定了安全在公司内部扮演的角色。安全策略应由业务目标驱动。安全策略还必须符合所有适用的法律法规。例如，你可能想监控员工——但这并不要在浴室或更衣室安装监控摄像头。

安全策略应作为将安全整合到所有业务功能的基础，并且必须是平衡的，因为所有组织都在寻找实施足够安全而不阻碍生产力或违反法律的方法。与员工建立敌对关系是很重要的。成本是一个问题，因为你用于安全控制的支出不能超过资产的价值。作为安全专业人员，你的工作是根据组织需求在安全策略的实施中发挥关键作用。

> 如果你发现自己被要求开发政策并需要一个框架作为起点，你可能需要访问 SANS 政策项目（`www.sans.org/security-resources/policies/`）。该资源有很多常用的政策模板来帮助你开始。

无论政策如何开发，良好的安全策略都是重要的。在你作为安全专业人员的角色中，要仔细查看适用于你的安全策略。作为 CASP，你应该能够对比安全策略、隐私策略和程序。如果你被赋予审查政策的任务，考虑政策与活动的匹配程度。此外，你考虑到新技术了吗？

CASP 必须能够根据技术变化看到政策开发和更新的需求。自带设备（BYOT）和云计算等趋势可能需要 CASP 创建或修订政策。

最后，记住政策不是永久不变的。1992 年关于调制解调器使用和限制的政策可能需要重新审视。随着新技术的变得负担得起，因此业务流程必须发生变化。有时很容易看到低级程序需要更新，这种变化也适用于高层政策。政策只是过程控制的一个层次。接下来，我们的讨论将重点关注程序。这些文档的结构如图 7.2 所示。

# 程序

程序属于政策。将程序视为从父策略构建的更详细文档。程序提供了逐步说明。例如，你的公司可能从 Cisco 防火墙迁移到 Check Point 防火墙。在这种情况下，策略不会改变——即策略规定了什么类型的流量可以进入或离开网络。改变的是程序，因为 Cisco 和 Check Point 设备的设置和配置是不同的。

# 标准、基线与指南

标准比策略更具体。标准（Standards）可以被视为战术性文档——列出了满足某些特定要求所需的具体步骤或流程。标准的一个很好的例子是你的公司对笔记本电脑硬盘可能采取的控制措施。正如你在第一章“加密工具与技术”中所看到的，其中一种控制措施就是对硬盘加密。

你的公司可能会设定一个基线，强制要求所有公司笔记本电脑必须使用全盘加密。该标准可能不会具体说明如何进行加密，但会规定无论使用何种技术（EFS、BitLocker 或同等技术），加密都是一项强制性活动。

另一种类型的文档是基线（Baseline）。它可以被认为是最低水平的安全性。请记住，基线是系统、网络或设备必须遵守的绝对最低安全水平。例如，安保人员必须拒绝未佩戴或贴在腰部以上的身份证牌，或在入境时未能出示证件的人员。

我想介绍的最后一种文档是指南（Guideline）。指南指向策略或程序中的某项声明，以此确定行动方案。例如，从非技术的角度来说，我有一项指南要求我青少年儿子必须在晚上 10 点前回家。虽然这是一项指南，但有一次我儿子的轮胎爆了，打电话说会晚到。在这种情况下，是可以接受的。指南通常被称为最佳实践。

> 理解公司可能拥有的不同类型文档及其目的将帮助你通过 CASP 考试。

# 审查与更新策略与程序

作为安全人员，你应该记住，策略和程序等文档是活文档，需要定期进行审查。根据策略、环境和业务的变化，流程和程序可能需要进行更改或更新。审查的时间取决于公司及其运营的行业。尽管许多公司每年至少审查一次策略，但间隔范围从六个月到五年一次不等。在审查期间，应该提出以下问题：

- 流程或程序是否发生了变化？
- 策略是否相关？
- 法律是否发生了变化？
- 变更流程是否包含了文档变更？
- 行业最佳实践是否发生了变化？
- 定期审计结果是否表明策略和程序等文档存在问题？

在审查文档时，要考虑涉及内部实践的文档，也要考虑公司与外部实体、业务伙伴和承包商的互动。公司可能与供应商或供应商签订一系列产品和服务的合同。在策略、程序和文档的审查过程中，任何以下情况都可能指示潜在问题：

- 负面审计结果
- 缺乏文档
- 文档过时
- 不支持的硬件更改或未经授权的
- 员工不了解或不熟悉文档

CASP 应通过与人力资源（HR）、法务、管理层和其他实体的合作，确保所有利益相关者参与其中，从而支持法律合规和维护。CASP 可能非常熟悉安全，但更改或更新文档不能在真空状态进行。CASP 需要他人的帮助。对于员工关注的事项，应该让 HR 部门参与。对于合规或支付卡行业（PCI）数据安全标准等事项，法律部门应该参与，因为这些人了解公司必须在哪些要求下工作。

# 保护持卡人数据

许多公司需要解决的策略领域之一是满足支付卡行业（PCI）数据安全标准。处理和处理信用卡信息的公司必须实施特定的控制措施来保护持卡人数据。

公司策略必须涵盖的两个保护领域是保护静态信用卡数据和传输中的中的信用卡数据。如果你的公司处理信用卡，PCI 标准规定存储的持卡人数据必须处理为不可读或加密以保护客户隐私。为了满足这一要求，你的公司必须实施安全控制措施，在信用卡数据存储期间以及信用卡数据跨越开放、公共网络移动时提供加密方法。必须遵守 PCI 标准的公司表示，文档是获得和维护 PCI 合规性最乏味的方面之一，也是通常需要更多工作的一个领域。

一个必须处理的事项是信息生命周期管理（ILM）。公司积累了大量数据。策略必须规定如何分类信息、使用哪些控制措施、保留多久以及如何销毁。需要 COOP（业务连续性计划）文档，是因为公司在发生故障或灾难时必须有计划和程序来继续运营。业务连续性包含了组织为了确保业务能够继续运行而必须建立的所有流程和程序。COOP 文档是必要的，因为公司在发生故障或灾难时，必须有计划和程序来继续运营。

BIA（影响分析）是灾难恢复业务连续性的核心部分。BIA 有三个组成部分：优先级排序、机时间估计和资源需求。BIA 用于识别与故障相关的成本，例如现金损失或设备更换、现金流、工资或其他损失。BIA 的设计可以是定量的，也可以是定性的。

# 支持安全的业务文档

所有组织都必须在法律、规则和法规框架内工作。该框架通常由多种文档规定，规定了如何处理、存储和销毁数据。未正确处理数据可能会导致罚款、失去公众信任、业务失败或高管人员入狱。

用于支持安全且 CASP 应回答的某些文档包括：

**风险评估 (RA)/适用性声明 (SOA)** 这是适用性声明变得重要的点。在风险评估过程中，你需要确定哪些控制措施。这是适用性声明变得重要的点。适用性声明 (SOA) 规定了为特定环境选择了哪些控制措施以及为什么这些控制措施是适当的。你可以将 SOA 视为风险评估与风险处理/控制之间的联系。这是 ISO 27001 的核心关注。控制可以是管理性的、技术的或物理的，SOA 应说明使用了哪些控制以及它们与哪些特定控制相关。

**互操作性协议 (IA)** 互操作性协议 (IA) 是一份详细说明建立和维护组织间数据交换要求的的文档。例如，美国航空可能会与汉莎航空共享航班代码，因为双方都需要访问共同数据集。这些共同数据集通常通过使用 TCP/IP 等协议或 XML 或 SQL 等标准规定。

**互连安全协议** An interconnection security agreement

ISA（信息系统连接协议）是一份安全文档，详细说明了建立、维护和运行系统或网络之间互连的各项。该文档规定了连接系统和网络的要求，并详细说明了应使用哪些安全控制措施保护系统和敏感数据。ISA 通常会详细说明特定系统和网络是如何连接的，并包含网络拓扑图。

# 合作备忘录 (Memorandum of Understanding)

合作备忘录（MOU）通常用于记录必须共享数据和信息资源的外包合作伙伴机构的条件和适用条款。有时，MOU 可在签署全面的概括性合同或协议之前作为一种临时手段。MOU 与 NDA（保密协议）不同。NDA 用于维护信息的机密性或保密性，而 MOU 的意义要广泛得多：它概述了每个方负责的内容，以及每个方应该做什么或执行什么。选择正确的合作伙伴至关重要，并且必须极其谨慎地进行。为了具有法律约束力，MOU 必须由每个具有签署权限的组织代表签署。这通常是高级管理人员、法律人员或董事会成员。由于此类文件通常被视为机密，因此通常会受到保护。之所以要求保密性，是因为协议可能描述了签署方不希望他人获知的流程、活动甚至服务。

# 服务水平协议 (Service Level Agreement)

在签署 ISA 或 MOU 时，应考虑的另一个控制措施是服务水平协议（SLA）。如果您签署了 MOU 的外包提供商将提供对时间敏感的流程，那么 SLA 是获取合作伙伴同意提供的服务水平保证的一种方式。

SLA 应该规定他们同意的运行时间、响应时间和最大停机时间。SLA 也可以作为与硬件供应商签订的一种合同类型，提供特定水平的保护。通过支付费用，供应商同意在约的时间内维修或更换设备。

SLA 应该规定与响应时间、恢复时间、保障空间等相关的项目。数据恢复和存储是与 SLA 密切相关的两个项目。如果系统故障且需要备份，数据的存储和恢复将是维持组织运行的关键。

运营级别协议 (Operating Level Agreement) 运营级别协议（OLA）与 SLA 协同工作，支持 SLA 流程。OLA 定义了每个合作伙伴内部支持小组的职责。因此，当 SLA 可能承诺停机时间不超过五分钟时，OLA 则定义了使用哪个小组和资源来满足指定的目标。

# 运行时间协议 (Uptime Agreement)

运行时间协议（UA）是最著名的 SLA 类型之一；它详细说明了约定的运行时间。例如，UA 可用于网络服务，如 WAN 链路或设备服务器。常见的运行时间标准包括 99.999%（在行业术语中被称为“五九九”），这相当于每年停机约五分钟。如果 UA 指定为 99.9999%（“六九九”），停机时间将降至每年最多约 30 秒。

# 保密协议 (Nondisclosure Agreement)

保密协议（NDA）旨在保护机密信息。例如，在参加 CASP 考试之前，你将被要求签署一份 NDA，声明你不会向他人泄露考试题。许多公司要求员工和承包商在获取特定信息之前签署 NDA。

# 业务伙伴安全协议 (Business Partnership Security Agreement, BPA)

业务安全协议（BPA）是另一个法律约束性文档示例，旨在就业务伙伴之间的特定安全相关活动提供保护措施并强制执行某些行动。BPA 是律师根据合作伙伴意见创建的书面协议，包含了与安全和合作相关的标准条款。

![](img/7868547987f5920cfe632b85047c64af_431_0.png)

安全专业人员在处理合作伙伴时应考虑的一项基本项目是审计标准（SAS 70）。SAS 70 报告验证了合作伙伴通过了独立审计公司对其控制目标和活动的审查。

您的公司是否有员工或合作伙伴签署 NDA？NDA 是为敏感信息和专有数据提供保护的一种方式。练习 7.2 你将审查其应包含的内容。

你的个人信息受保护程度如何？遗憾的是，有些公司先入为主地认为，安全控制会降低业务流程的效率或速度。隐私权利清理小组（`www.privacyrights.org`）报告称，在 2013 年 1 月 1 日至 2013 年 12 月 31 日期间，美国发生了 621 次数据泄露事件。这些泄露事件影响了数百万美国人。这些公司没有采取足够的控制措施来保护个人身份信息。TechTarget 将个人身份信息（PII）定义为“任何关于个人的、可能识别出该人员身份任何数据，例如姓名、指纹或其他生物识别数据、电子邮件地址、街道地址、电话号码或社会安全号码。”

作为安全专业人员，你的工作是与管理层合作，帮助他们理解强化安全控制的重要性。良好的安全实践并不是大多数管理人员或用户直觉上意识到的。它们需要教育。该过程的一个关键组成部分是安全意识和培训。教育过程的一部分是增加对敏感信息丢失时所涉及成本的认识。

以下是针对个人身份信息（PII）的一些通用隐私原则：

- PII 数据将以公平、合法的方式收集。
- PII 数据仅将用于收集时的目的。
- PII 数据在存储和传输过程中将保持安全。
- PII 数据的保留时间仅为合理时长。
