
让我们看一个例子。假设您想要加密消息“Richard will deliver the secret package to Matthew at the bus station tomorrow”，使用刚才描述的密钥。该消息长度为 66 个字符，因此您将使用运行密钥的前 66 个字符：“With much interest I sat watching him. Savage though he was, and hideously marred.” 然后可以使用任何算法通过此密钥加密明文消息。让我们看一下模 26 加法的例子，它将每个字母转换为十进制等值，将明文与密钥相加，然后执行模 26 运算以生成密文。如果给字母 `A` 赋值 0，给字母 `Z` 赋值 25，则对于密文的前两个单词，有以下加密操作：

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 密钥 | | W | | I | | T | | H | | M | | U | | C | | H | | I | | N | | T |
| 数值明文 | | 17 | | 8 | | 2 | | 7 | | 0 | | 17 | | 3 | | 22 | | 8 | | 11 | | 11 |
| 数值密钥 | | 22 | | 8 | | 19 | | 7 | | 12 | | 20 | | 2 | | 7 | | 8 | | 13 | | 19 |

### 分组密码

`分组密码`作用于消息的“块”或分组，并一次性将加密算法应用于整个消息分组。置换密码是分组密码的例子。质询-响应算法中使用的简单算法获取整个单词并反转其字母。更复杂的列置换密码作用于整个消息（或消息的一部分），并使用置换算法和秘密关键字对其进行加密。大多数现代加密算法实现某种类型的分组密码。

### 流密码

`流密码`一次对消息（或数据流）的一个字符或位进行操作。凯撒密码是流密码的一个例子。一次性密码本也是一种流密码，因为该算法独立地作用于明文消息的每个字母。流密码也可以作为一种分组密码运行。在此类操作中，有一个缓冲区填充实时数据，然后作为一个分组加密并传输给接收方。

### 扩散与混淆

加密算法依赖两种基本操作来隐藏明文消息——混淆和扩散。`混淆`发生在明文与密钥之间的关系过于复杂，以至于攻击者无法仅通过不断改变明文并分析生成的密文来确定密钥。`扩散`发生在明文的一个变化导致分布在整个密文中的多个变化时。例如，考虑一种加密算法，它首先执行复杂的替换，然后使用置换来重新排列替换后的密文字符。在这个例子中，替换引入了混淆，置换引入了扩散。

## 现代密码学

现代密码系统使用计算上复杂的算法和长加密密钥，以满足机密性、完整性、认证和不可否认性的密码学目标。以下部分介绍加密密钥在数据安全领域中的作用，并考察当今常用的三种算法类型：对称加密算法、非对称加密算法和哈希算法。

### 加密密钥

在密码学的早期，主要原则之一是“通过隐蔽实现安全”。一些密码学家认为，保持加密算法安全的最好方法是向外界隐藏算法的细节。旧密码系统要求通信双方将用于加密和解密消息的算法对第三方保密。算法的任何泄露都可能导致对手攻破整个系统。

现代密码系统不依赖其算法的保密性。事实上，大多数密码系统的算法都可在随附文献和互联网上广泛供公众审查。向公众开放算法进行审查实际上提高了其安全性。计算机安全社区对算法的广泛分析使从业者能够发现并修正潜在的安全漏洞，并确保他们用于保护通信的算法尽可能安全。

现代密码系统不依赖秘密算法，而是依赖一个或多个加密密钥的保密性，这些密钥用于为特定用户或用户组个性化算法。回顾置换密码的讨论，关键字与列置换一起用于指导加密和解密工作。执行列置换的算法是众所周知的——您刚刚在本书中读到了它的细节！然而，只要选择的关键字不会被外部人员猜到，列置换就可以用于双方之间的安全通信。只要保持该关键字的安全，第三方知道算法的细节也无关紧要。

在本章前面关于一次性密码本的讨论中，你了解到一次性密码本算法的主要优势源于它使用极长密钥这一事实。事实上，对于该算法，密钥长度至少与消息本身一样长。大多数现代密码系统使用的密钥没有那么长，但密钥长度仍然是决定密码系统强度以及加密不被密码分析技术破解的可能性的一个极其重要的因素。

计算能力的快速提升使你能够在密码学工作中使用越来越长的密钥。然而，这种计算能力也掌握在试图破解你所用算法的密码分析师手中。因此，必须使用足够长的密钥来击败当代密码分析工作，从而超越对手。此外，如果你想提高数据在未来一段时间内免受密码分析威胁的安全几率，必须努力使用能在数据必须保密的整个时间段内，超越预期密码分析能力增长的密钥。例如，量子计算的出现可能会改变密码学，使当前的密码系统变得不安全，正如本章前面所讨论的那样。

几十年前，当数据加密标准（`DES`）被创建时，56 位密钥被认为足以维护任何数据的安全。然而，现在普遍认为 56 位 `DES` 算法不再安全，这是因为密码分析技术和超级计算能力的进步。现代密码系统使用至少 128 位的密钥来保护数据免受窥探。请记住，密钥长度与密码系统的工作函数直接相关：密钥越长，破解密码系统就越困难。

### 对称密钥算法

对称密钥算法依赖于分发给所有参与通信成员的“共享密钥”。该密钥由所有参与方用于加密和解密消息，因此发送方和接收方都持有共享密钥的副本。发送方使用共享密钥加密，接收方使用该密钥解密。当使用大尺寸密钥时，对称加密非常难以破解。它主要用于执行批量加密，且仅提供机密性安全服务。对称密钥密码学也称为 `secret key cryptography`（秘密密钥密码学）和 `private key cryptography`（私钥密码学）。图 6.3 说明了对称密钥加密和解密过程。

对称密钥密码学有几个弱点。

**密钥分发是一个主要问题。** 在使用对称密钥协议建立通信之前，各方必须有一种安全的方法来交换秘密密钥。如果没有可用的安全电子通道，通常必须使用离线密钥分发方法（即带外交换）。

**对称密钥密码学不实现不可抵赖性。** 因为任何通信方都可以使用共享密钥加密和解密消息，所以无法证明给定消息的来源。

**算法不可扩展。** 大型群体使用对称密钥密码学进行通信极其困难。组内个人之间的安全私密通信只有在每一对可能的用户组合共享一个私钥时才能实现。

**密钥必须频繁重新生成。** 每当一名参与者离开群体时，该参与者所知的所有密钥都必须废弃。

对称密钥密码学的主要优势在于其运行速度极快。对称密钥加密非常快，通常比非对称算法快 1,000 到 10,000 倍。由于所涉及数学的本质，对称密钥密码学也天然适合硬件实现，从而创造了更高速操作的机会。

本章后面的“对称密码学”部分将详细介绍当今使用的主要秘密密钥算法。

### 非对称密钥算法

`Asymmetric key algorithms`（非对称密钥算法），也称为 `public key algorithms`（公钥算法），为对称密钥加密的弱点提供了解决方案。在这些系统中，每个用户有两个密钥：一个公钥，与所有用户共享；一个私钥，保密且仅用户本人知道。但这里有个转折：必须成对使用相反且相关的密钥来进行加密和解密。换句话说，如果公钥加密消息，则只有相应的私钥能解密它，反之亦然。

图 6.4 显示了公钥密码系统中用于加密和解密消息的算法。考虑这个例子。如果 Alice 想使用公钥密码学向 Bob 发送消息，她创建消息，然后使用 Bob 的公钥对其加密。解密该密文的唯一可能方法是使用 Bob 的私钥，而拥有该密钥访问权限的唯一用户是 Bob。因此，Alice 加密后甚至无法自己解密该消息。如果 Bob 想回复 Alice，他只需使用 Alice 的公钥加密消息，然后 Alice 使用她的私钥解密即可读取消息。

以下是非对称密钥密码学主要优势的列表：

**添加新用户只需生成一对公私钥。** 同一密钥对用于与非对称密码系统的所有用户通信。这使得算法具有极强的可扩展性。

**从非对称系统中移除用户要容易得多。** 非对称密码系统提供密钥吊销机制，允许取消密钥，从而有效地将用户从系统中移除。

**只有在用户的私钥泄露时才需要重新生成密钥。** 如果用户离开社区，系统管理员只需使该用户的密钥失效。没有其他密钥被泄露，因此不需要为任何其他用户重新生成密钥。

**非对称密钥加密可提供完整性、认证和不可抵赖性。** 如果用户不与其他个人共享其私钥，则由该用户签名的消息可被证明是准确且来自特定来源的，且事后无法抵赖。

**密钥分发是一个简单的过程。** 想要参与系统的用户只需将其公钥提供给他们想通信的任何人。没有任何方法可以从公钥推导出私钥。

**不需要预先存在的通信链路。** 两个个体可以从开始通信的那一刻起就进行安全通信。非对称加密不需要预先存在的关系即可为数据交换提供安全机制。

公钥加密的主要弱点是其运行速度缓慢。因此，许多需要安全传输大量数据的应用程序使用公钥加密来建立连接，然后交换一个对称密钥。会话的其余部分随后使用对称加密。表 6.1 对比了对称和非对称加密系统。仔细查看该表可发现，一个系统的弱点恰好被另一个系统的优势所弥补。

### 哈希算法

在上一节中，你了解到公钥密码系统在与消息摘要结合使用时可以提供数字签名功能。消息摘要是由哈希算法生成的消息内容摘要（类似于文件校验和）。从理想的哈希函数中推导出原始消息极其困难，甚至不可能，且两条不同消息产生相同哈希值的可能性极低。哈希函数为两个不同输入产生相同值的情况称为 `collisions`（碰撞），碰撞的存在通常会导致该哈希算法被弃用。

第 7 章将详细介绍当代哈希算法，并解释它们如何用于提供数字签名功能，这有助于实现完整性和不可抵赖性这两个加密目标。

## 对称加密

你已经了解了对称密钥加密、非对称密钥加密和哈希函数的基本概念。在接下来的章节中，我们将深入探讨几种常见的对称密码系统：数据加密标准（`DES`）、三重 DES（`3DES`）、国际数据加密算法（`IDEA`）、Blowfish、Skipjack 和高级加密标准（`AES`）。

### 数据加密标准

美国政府于 1977 年发布了数据加密标准，作为所有政府通信的拟议标准密码系统。由于算法存在缺陷，密码学家和联邦政府不再认为 `DES` 是安全的。人们普遍认为情报机构会例行解密 `DES` 加密的信息。`DES` 于 2001 年 12 月被高级加密标准取代。理解 `DES` 仍然很重要，因为它是三重 DES（`3DES`）的基础构建模块，后者是下一节将讨论的一种强加密算法。

`DES` 是一种 64 位分组密码，具有五种操作模式：电子密码本（`ECB`）模式、密码分组链接（`CBC`）模式、密码反馈（`CFB`）模式、输出反馈（`OFB`）模式和计数器（`CTR`）模式。这些模式将在以下章节中解释。所有 `DES` 模式一次对 64 位明文进行操作，以生成 64 位密文分组。`DES` 使用的密钥长度为 56 位。

`DES` 使用一长串异或（`XOR`）操作来生成密文。该过程在每次加密/解密操作中重复 16 次。每次重复通常称为一轮 `round` 加密，这解释了为什么说 `DES` 执行 16 轮加密。

#### 电子密码本模式

电子密码本（`ECB`）模式是最容易理解但安全性最低的模式。每当算法处理一个 64 位分组时，它只是使用选定的密钥加密该分组。这意味着如果算法多次遇到相同的分组，它将产生相同的加密分组。如果窃听者正在监听通信，他们可以简单地建立所有可能加密值的“密码本”。收集到足够数量的分组后，即可使用密码分析技术破译部分分组并破解加密方案。

这种漏洞使得 `ECB` 模式除极短传输外均不切实际。在日常使用中，`ECB` 仅用于交换少量数据，例如用于启动其他 `DES` 模式的密钥和参数，以及数据库中的单元格。

#### 密码分组链接模式

在密码分组链接（`CBC`）模式中，每个未加密文本分组在使用 `DES` 算法加密前，都会与其前一个密文分组进行 `XOR` 运算。解密过程只需解密密文并反向执行 `XOR` 操作。`CBC` 实现了一个 `IV`（初始化向量）并将其与消息的第一个分组进行 `XOR` 运算，使每次操作都产生唯一的输出。`IV` 必须发送给接收者，可能是将 `IV` 以明文形式附加在完成的密文前面，或者使用与消息相同的密钥通过 `ECB` 模式加密来保护它。使用 `CBC` 模式时一个重要考量是错误会传播——如果传输过程中某个分组损坏，将无法解密该分组和下一个分组。

#### 密码反馈模式

密码反馈（`CFB`）模式是 `CBC` 的流密码版本。换句话说，`CFB` 针对实时产生的数据进行操作。然而，它不将消息分成分组，而是使用与分组大小相同的内存缓冲区。当缓冲区填满时，对其进行加密并发送给接收者。然后系统等待下一个缓冲区在新数据生成时填满，随后依次加密并传输。除了从预存数据变为实时数据这一变化外，`CFB` 的操作方式与 `CBC` 相同。它使用 `IV`，并采用链接机制。

#### 输出反馈模式

在输出反馈（`OFB`）模式下，`DES` 的操作方式与 `CFB` 模式几乎相同。然而，`DES` 不是将明文与前一个密文分组的加密版本进行 `XOR` 运算，而是将明文与一个种子值进行 `XOR` 运算。对于第一个加密分组，使用初始化向量来创建种子值。未来的种子值通过在前一个种子值上运行 `DES` 算法得出。`OFB` 模式的主要优势是没有链接功能，且传输错误不会传播以影响未来分组的解密。

#### 计数器模式

在计数器（`CTR`）模式下运行的 `DES` 使用类似于 `CFB` 和 `OFB` 模式的流密码。然而，它不是从前一个种子值的结果中创建每次加密/解密操作的种子值，而是使用一个简单的计数器，每次操作递增一次。与 `OFB` 模式一样，错误不会在 `CTR` 模式中传播。

### 三重 DES

如前几节所述，面对现代密码分析技术和超级计算能力，数据加密标准（`DES`）的 56 位密钥不再被认为足够安全。然而，`DES` 的一个改进版本——三重 DES（`3DES`）——使用相同的算法产生更安全的加密。

`3DES` 有四个版本。第一个版本仅使用三个不同的密钥：`K[1]`、`K[2]` 和 `K[3]` 对明文加密三次。它被称为 `DES-EEE3` 模式（`E` 表示有三次加密操作，数字 3 表示使用三个不同的密钥）。`DES-EEE3` 可用以下符号表示，其中 `E(K,P)` 表示用密钥 `K` 加密明文 `P`：

```
E(K1,E(K2,E(K3,P)))
```

`DES-EEE3` 的有效密钥长度为 168 位。

第二种变体（`DES-EDE3`）同样使用三个密钥，但将第二次加密操作替换为解密操作。

```
E(K1,D(K2,E(K3,P)))
```

3DES 的第三个版本（`DES-EEE2`）仅使用两个密钥，`K[1]` 和 `K[2]`，具体如下：

```
E(K1,E(K2,E(K1,P)))
```

3DES 的第四种变体（`DES-EDE2`）同样使用两个密钥，但在中间使用解密操作。

```
E(K1,D(K2,E(K1,P)))
```

第三种和第四种变体的有效密钥长度均为 112 位。

多年来开发出这四种 3DES 变体，是因为几位密码学家提出理论认为其中一种变体比其他变体更安全。然而，目前的共识是所有模式的安全性相当。

### 国际数据加密算法

国际数据加密算法（`IDEA`）分组密码的开发是为了回应关于 `DES` 算法密钥长度不足的抱怨。与 `DES` 一样，`IDEA` 对 64 位的明文/密文分组进行操作。然而，它使用 128 位密钥开始操作。该密钥在一系列操作中被分解为 52 个 16 位子密钥。然后，子密钥通过 XOR 和模运算的组合作用于输入文本，以生成输入消息的加密/解密版本。`IDEA` 能够在 `DES` 使用的相同五种模式下运行：`ECB`、`CBC`、`CFB`、`OFB` 和 `CTR`。
