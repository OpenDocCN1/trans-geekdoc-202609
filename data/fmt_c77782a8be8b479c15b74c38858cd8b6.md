如果用于连接的列在两个表中具有相同的名称，则在连接结果中使用非限定名称。生成的表称为原始表的**自然内连接**。因为默认假定为“inner”，所以**自然内连接**可简称为**自然连接**（外连接稍后讨论）。这是实践中最常见的连接操作。表 *A* 和 *B* 的自然连接可写为 `A ⨝ B`，或用文字表示为“*A* **自然连接** *B*”。可总结如下。

*   计算 `A ⨝ B`：形成 `A ⨉ B`
*   对于同时出现在 `A` 和 `B` 中的每个列名 `c`
*   应用限制 `A.c = B.c`
*   删除 `B.c`
*   将 `A.c` 重命名为 `c`

无需命名连接列，因为这些列是在两个表中同名的列（当然这些列必须基于同一个域）。为帮助记忆领结符号“⨝”，请注意“⨝”看起来像一个加上两条垂直线的叉“⨉”，暗示自然连接是笛卡尔积加上两个其他操作（选择公共列值相等的行，然后投影以删除冗余列）。图 12.21 显示了驾驶示例的自然连接。注意 `empNr` 列仅出现一次且为非限定名称。

![图 12.21 自然连接。](img/f12-21-9780443237904.jpg)

图 12.21 自然连接。

如果表没有共同的列名，则自然连接就是笛卡尔积。与笛卡尔积一样，自然连接具有结合性：`(A ⨝ B) ⨝ C = A ⨝ (B ⨝ C)`。因此，`A ⨝ B ⨝ C` 形式的表达式是明确无歧义的。

被连接的表可能有零个、一个或多个公共列。无论哪种情况，自然连接仅限于那些在两个表中所有公共属性具有相同值的行。*A ⨝ B* 中的列数等于 *A* 和 *B* 中列数之和，减去两者公共的列数。

### 关系除法

我们考虑的下一个关系运算是关系**除法**。仅当表 *A* 的列多于表 *B* 时，表 *A* 除以表 *B* 才有意义。假设表 *A* 有两组列 *X* 和 *Y*，表 *B* 有一组列 *Y*。换句话说，*X* 是 *A* 中不在 *B* 中的列集。我们假设 *A* 和 *B* 中的 *Y* 列之间存在有序关系，以便知道 *B* 中哪一列对应 *A* 中的哪一列。

`A` ÷ `B` 的结果是通过将结果限制为 `A` 中那些 `X` 条目来形成的，这些条目在 `A` 中关联的 `Y` 条目包含 `B` 的*所有*行条目。表达式 `A` ÷ `B` 也可以写作 `A` **divide-by** `B`。图 12.26 显示了一个简单示例，其中属性域用 `X1`、`X2`、`Y1` 表示。

![Fig. 12.26 A simple example used to explain relational division.](img/f12-26-9780443237904.jpg)

图 12.26 用于解释关系除法的简单示例。

虽然不常用，但除法运算在列出与另一个表表达式的*至少所有*行相关联的行时很有用（例如，谁能供应我们库存清单上的所有物品？）。

作为一个实际示例，假设表 `Speaks`（country, language）存储了关于哪些国家说（即使用）哪些语言的事实。图 12.27 中的大表显示了一个样本数据。现在考虑查询：哪些国家说加拿大所说的*所有*语言？要回答这个问题，我们首先使用表达式 `Speaks` **where** country = ‘Canada’ *\[*language*\]* 找出加拿大所说的所有语言。这将返回表 {English, French}。然后我们如图所示将 `Speaks` 表除以此结果，以获得最终答案 {Canada, Dominica}。

### 重命名

回顾图 12.7，我们在那里为表名定义了别名。关系赋值也可用于提供新表名，但不能用于*更改属性名*。为此，我们需要 ***rename***（重命名）算子。关系代数表达式可以包含前面讨论的任何关系运算（并、投影、选择、连接等），本质上是一个返回表的查询。通常，*对关系表达式应用重命名算子将返回一个具有相同行*（相同数据内容）*但表或列名不同的表*。

重命名算子的正式语法使用希腊字母“***ρ***”（*rho*）。如果 `Rexp` 是一个返回具有表模式 `R`(`a`[1], …, `a`[*n*]) 的表的关系表达式，则以下表达式返回一个具有表模式 `S`(`b`[1], …, `b`[*n*]) 的表。其下方的表达式使用了我们的替代语法。

*    `ρ``S`(`b`[1], …, `b`[*n*]) `Rexp`
*    **define** `S`(`b`[1], …, `b`[*n*]) **as** `Rexp`

如果省略属性列表 (`b`[1], …, `b`[*n*])，该操作仅提供一个新表名。在这种情况下，如果 `Rexp` 只是一个表名，使用定义别名表示法（例如，**define alias** `Person2` **for** `Person`）会更自然，如图 12.7 所示。

作为一个简单示例，考虑表模式 `Person` (personName, age, genderCode) 和 `Drives` (personName, carRegNr)，其中 `Drives.personName` 是指向 `Person` 表的外键。以下声明可用于定义一个 `WomanDriver` 表，仅将人名属性用“name”代替“personName”。

```
define WomanDriver   ( name, carRegNr ) as
    Employee ⨝ Drives
where age >= 18 and genderCode = ‘F’
[personName, carRegNr]
```

一旦定义，`WomanDriver` 表可像其他任何表一样在后续查询中使用。这类似于 SQL 中的*视图*（见后续章节）。

为了帮助用关系代数构建查询，以下*查询策略*很有用：

*   • 用自然语言表述查询，并理解其含义。
*   • 询问哪些表持有该信息。
*   • 如果你有表数据，自己回答查询，然后回溯你的思维步骤。
*   • 将查询分解为步骤或子问题。
*   • 如果结果列来自不同的表，声明表之间的连接。
*   • 如果你需要关联同一表的两行，使用别名或重命名定义来执行自连接。
*   • 要更改结果中的任何表或列名，使用重命名定义。

我们的第一步是用自然语言表述查询，确保我们理解查询的含义。接下来，确定哪些表持有回答查询所需的信息。信息可能在单个表中，也可能分布在两个或更多表中。如果要列出的列来自不同的表（或同一表的不同副本），则通常必须指定这些表之间的连接。这些连接可以是任何类型：内连接或外连接、自然连接或 θ 连接，或交叉连接（笛卡尔积）。

除了涉及 ∪、∩ 或 - 的某些情况外，无论结果列是否来自同一表，只要必须访问不同的表来确定结果，关系代数就要求使用连接。SQL 引入了子查询，当结果列来自同一表时，可以用子查询代替连接。

让我们看一个使用银行账户数据库的示例。为减少翻页，数据库在图 12.28 中重现。现在考虑查询：哪些客户拥有余额超过 700 美元的账户？在用关系代数表述之前，我们应确保理解自然语言查询的含义。在某些情况下，我们可能需要通过询问最初提出查询的人来澄清含义。例如，我们是否只想要相关客户的客户编号，还是也想要他们的姓名？假设我们也想要客户姓名。

![Fig. 12.28 How can this query be formulated in relational algebra?](img/f12-28-9780443237904.jpg)

图 12.28 如何用关系代数表述此查询？

查看这些表，我们现在可以看到需要所有三个表。`Account` 表存储余额，`Client` 表存储客户姓名，`AcUser` 表指示谁使用哪个账户。

因为我们有样本数据，可以先尝试回答英文查询，检查我们的操作步骤，最后尝试用关系代数的形式语言来表达。如果我们自己回答该请求，可能会去 `Account` 表中选取余额超过 $700 的行。这将得到账户 (10, 54) 和账户 (23, 54)。然后我们可能会查看 `AcUser` 表，看谁在使用这些账户。这将得到编号为 1001、1002 和 7654 的客户。现在我们查看 `Client` 表以找出他们的名字（“Jones, ME”、“Jones, TA”、“Seldon, H”）。因此，我们的答案是 {(1001, “Jones, ME”), (1002, “Jones, TA”), (7654, “Seldon, H”)}。

回顾并概括我们的步骤，我们发现通过匹配账户（`branchNr` 和 `accountNr`）将 `Account` 和 `AcUser` 表连接起来，并通过在 `clientNr` 上连接与 `Client` 表链接。因为这些属性在各表中具有相同的名称，所以我们可以使用自然连接。我们可以用关系代数将其表述为：

*   ```
    (Account where balance > 700) [ branchNr, accountNr ]
    ```
*     ⋈ AcUser
*     ⋈ Client *\[* clientNr, clientName *\]*

这并不是表达该查询的唯一方式。例如，采用自顶向下的方法，两次连接都可以在选择或投影之前完成，如下所示：

*      (Account ⋈ AcUser ⋈ Client
*   ```
    where balance > 700
    ```
*   ```
    [ clientNr, clientName ]
    ```

请注意查询如何分散在多行中以使其更具可读性。一个有用的语法检查是确保左括号和右括号的数量相同。虽然这两个查询在逻辑上是等价的，但如果按所示的求值顺序执行，第二个查询效率较低，因为它涉及更大的连接。

关系代数可用于指定等价查询之间的转换规则，以获得最优或至少更高效的表达形式。SQL 数据库系统包含查询优化器，可在执行前将查询转换为优化形式。因此，在实践中，我们通常以易于思考的方式构思查询，而不必担心效率问题。

因为关系代数系统在实践中不被使用，所以在做关系代数练习时可以忽略效率考虑。然而，对于 SQL 中的复杂查询，实际的优化器并不完美，你可能需要调整查询以达到预期性能。在某些情况下，手工调优复杂查询可大幅缩短其执行时间（例如从数小时缩短到数分钟）。
