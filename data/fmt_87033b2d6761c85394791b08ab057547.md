
# 自主访问控制

自主访问控制，也称为 DAC，是一种根据 `自主访问控制列表 (DACL)` 决定谁可以访问资源的模型。DACL 是被授予资源访问权限的用户或组（称为安全主体）的列表，并且 DACL 通常决定用户拥有哪种类型的访问权限。也就是说，DACL 是分配给文件的权限。DACL 中的每个条目称为 `访问控制条目 (ACE)`，如图 11-1 所示。

ACE 是 ACL 中的单个条目。

![Image](img/exam.jpg)

> **针对 Security+ 认证考试，请记住自主访问控制 (DAC) 涉及在资源上配置权限。**

在 Microsoft 环境中，每个安全主体（如用户账户、计算机账户或组）都分配有一个 `安全标识符 (SID)`。当用户登录网络时，身份验证过程的一部分是为用户生成访问令牌（这称为 `逻辑令牌`）。访问令牌包含用户账户 SID，以及用户所属组的所有 SID。

当用户尝试访问资源时，访问令牌将与 DACL 进行比较，以决定用户是否应获得对资源的访问权限（请参阅图 11-2）。

## 强制访问控制

在强制访问控制 (MAC) 模型中，每个个体（称为 `主体`）被分配一个许可级别，如机密、秘密或绝密。组织中的数据和其他资产被分配分类标签，以表示信息的敏感度。分类标签的示例包括公开、机密、秘密、绝密和非密等。

![Image](img/exam.jpg)

> **针对考试，请记住强制访问控制涉及员工根据其许可级别和分配给资源的数据分类标签来获取资源访问权限。**

系统根据主体的许可级别与分配给资源的分类标签是否匹配来控制谁获得资源访问权限，如图 11-3 所示。重要的是要注意，如果一个人拥有较高的许可级别，他们可以访问分配了该敏感度标签或更低敏感度标签的任何信息。

![Image](img/f0478-01.jpg)

**图 11-3**

使用 MAC 时，许可级别必须等于或高于敏感度标签。

在设计 MAC 系统时，数据所有者必须决定信息的敏感度，然后将分类标签分配给该信息。组织决定在何种情况下可以更改信息的分类标签或使其成为非密也很重要。例如，当公司为新产品设计计划时，可能会决定该信息属于机密，这意味着该信息未经授权不得公开发布。但一旦产品已设计完成、售出并过时，公司是否应将产品设计文档的分类标签更改为“公开”，因为设计计划不再是机密信息？

### 考场内部

#### 查看分类标签

你在 Security+ 认证考试中肯定会遇到一些关于访问控制模型的问题，其中一两个问题将集中在强制访问控制模型上。请记住，对于考试而言，MAC 将许可级别分配给主体（个人），将敏感度标签（也称为分类标签）分配给资源（例如文件）。

在 MAC 系统中，可以分配不同的敏感度标签和许可级别。以下概述了政府组织常用的敏感度级别。请记住，拥有特定许可级别的人可以访问分配了该标签及更低级别标签的信息。例如，拥有机密许可的人可以访问机密、受限和非密信息。

- **绝密** 最高敏感度标签。如果泄露给公众，被分类为绝密的信息可能会对国家安全造成*严重损害*。

- **秘密** 第二高敏感度标签。如果泄露给公众，被分类为秘密的信息可能会对国家安全造成*严重损害*。

- **机密** 第三高敏感度标签。如果泄露给公众，被分类为机密的信息可能会对国家安全造成*损害*。

- **受限** 分配此分类标签的信息如果暴露给公众可能会导致*不良后果*。

- **非密** 任何未分配分类标签的信息均视为非密，适合公开发布。

商业部门通常使用不同的分类标签来标识信息的敏感度。以下是可分配给信息的敏感度标签和可分配给人员的许可级别的示例：

- **机密** 最高敏感度标签。如果泄露给公众，被分类为机密的信息可能会对组织造成*严重损害*。

- **私密** 第二高敏感度标签。如果泄露给公众，被分类为私密的信息可能会对组织造成*严重损害*。

- **敏感** 分配此分类标签的信息如果暴露给公众可能会导致*不良后果*。

- **公开** 分配此分类标签的信息适合公开发布。

同样，这是一个层级结构，拥有机密许可的人不仅可以访问机密数据，还可以访问任何具有较低分类（如私密、敏感和公开）的数据。

## 基于角色的访问控制

`基于角色的`访问控制 (RBAC) 采用不同于 MAC 的方法来控制对资源和特权的访问：系统向不同角色授予特殊特权。`角色` 是系统中具有预定义特权的容器对象。当你将用户放入角色时，用户将获得分配给该角色的特权或访问控制权限。

![Image](img/exam.jpg)

**对于 Security+ 认证考试，请记住基于角色的访问控制涉及将用户放入容器（称为角色），并为这些角色分配执行特定任务的特权。当用户被放入角色时，他们将继承该角色被分配的任何能力。**

#### 基于属性的访问控制

基于属性的访问控制 (ABAC) 是一种访问控制模型，涉及向用户和资源分配属性，然后在规则中使用这些属性来定义哪些用户可以访问哪些资源。例如，您可以配置一条规则，指定如果用户具有“Accounting”部门属性和“Boston”城市属性，则他们可以访问该文件。这与 RBAC 或 GBAC 不同，因为那些模型仅检查用户是否在角色或组中。

#### 其他访问控制工具

许多其他工具可以与访问控制结合使用。以下是一些用于控制访问的其他工具：

*   **条件访问** 在设置系统访问控制时，您可能有选项指定访问的条件。这在基于声明的环境中很常见，因为访问令牌可以包含用户的城市或部门以及他们正在使用的设备等属性。您可以在权限上设置条件，例如：“如果用户的部门是 accounting 且他们使用的设备的部门是 accounting，则用户获得修改权限。”

*   **特权访问管理** 这是限制哪些用户账户拥有对系统的特权访问的概念。作为降低安全妥协风险的一种技术，您应该限制哪些用户账户拥有系统的管理员特权。如果拥有系统管理员特权的用户意外运行了恶意代码，该代码可能会损害系统。

*   **文件系统权限** 正如您在本章中所学，您可以在每个操作系统中的文件夹和文件上实现文件权限，作为控制谁可以访问数据的一种方式。

### 实施访问控制

现在您了解了各种访问控制模型，让我们看看访问控制在不同环境中是如何实施的。在本节中，您将了解安全组、权利与权限的区别，以及如何在路由器上实施访问控制列表。

#### 身份标识

*身份标识* 是访问系统或数据的人员。身份标识的最佳示例是用户账户，但也可能是计算机账户或组。身份标识也称为安全主体，并被授予对系统或网络上资源的访问权限。

身份标识存在于*身份提供程序* 中。身份提供程序是创建用户和组的数据库或身份验证系统。例如，Active Directory 是基于 Microsoft 域的网络的身份提供程序。

每个对象（如用户账户）都具有随账户存储的*属性*。属性示例包括名、姓、用户名、城市、部门、登录时间——列表还在继续。

身份标识可以由其他对象表示或识别，例如在登录系统时使用*数字证书*或 `SSH 密钥`。您将在 第 12 章 和 第 13 章 中了解更多关于证书的信息。代表用户的数字证书可以放置在*智能卡* 上，插入系统以便向系统进行身份验证。用户还需要输入与智能卡关联的 PIN 码。

*令牌* 也用于控制对系统的访问。这可能是您必须持有以便刷卡访问系统的硬件令牌，也可能是在登录过程中生成的软件令牌。

# 账户类型

在控制对资源的访问时，您通常应首先为组织内的每个人定义用户账户。重要的是要知道，拥有用户账户有不同的原因，因此存在不同类型的账户：

*   **用户账户** 您组织内的每位员工都应分配一个单独的用户账户，供他们用来访问网络和系统。此用户账户不应被任何其他人使用，因为它代表该特定用户并控制员工将有权访问的资源。您还将通过记录用户账户执行的操作来监控员工活动，因此请强调员工不要共享其账户的密码。

*   **共享和通用账户/凭据** 您有时可能会考虑创建一个由多个员工共享的账户，因为他们共享相同的工作角色。例如，Sue 是上午的会计文员，而 Bob 是下午的会计文员。您可能会考虑创建一个名为 `AccountingClerk` 的共享账户，让每位员工使用该账户，而不是创建多个账户。但请记住，从安全角度来看，安全专业人员尽量避免让多个员工共享一个账户。出于监控和审计的目的，能够记录 Bob 执行了哪些操作、Sue 执行了哪些操作是非常受青睐的。日志中有一条 `AccountingClerk` 删除了文件的记录无法帮助您确定是谁执行了该操作。当心共享或通用账户！

![Image](img/exam.jpg)

**考试重点：务必了解这些不同类型的账户。同时请记住，由多名员工共用的共享账户会导致难以审计谁执行了操作。从审计角度来看，您应确保每位员工都拥有自己的账户。**

## 来宾账户

**来宾账户** 来宾账户是指当某人没有账户时，可用于访问系统的账户。这允许个人在无需为其创建账户的情况下获得对资源的临时访问权限。大多数操作系统都有来宾账户，但默认情况下处于禁用状态，这意味着如果有人想要访问系统，则需要为其创建一个账户。保持来宾账户处于禁用状态是一项安全最佳实践。

## 服务账户

**服务账户** 安全的操作系统（如 Windows 和 Linux）要求所有内容都向系统进行身份验证，无论是用户还是一段软件。当软件在系统上运行时，它需要作为特定用户运行，以便为该软件分配权限。您与某软件关联的用户账户称为服务账户，因为操作系统中运行的服务也会使用此功能。创建服务账户（软件应用程序将配置为使用的用户账户）时，通常会为服务账户配置强密码，并指定密码永不过期。

![Images](img/job.jpg)

**请确保服务账户不具备管理功能，因为否则，如果服务遭到缓冲区溢出攻击等攻击而被攻破，攻击者将拥有与该服务关联账户相同的凭据。**

## 特权账户

**特权账户** 特权账户是指拥有超出分配给普通用户权限之外的额外权限的账户。特权账户通常被授权对系统进行配置更改，或执行普通员工通常不执行的操作。

# 权利与特权

系统安全的很大一部分源于这样一个事实：只有特定的安全主体（用户或组）才能执行特定操作。例如，如果任何人都能备份系统上的任意文件，那将是一个巨大的安全隐患。在 Microsoft 环境中，只有拥有“备份文件和目录”权利的人才能执行备份。

在 Windows 系统上，通常必须以管理员身份登录才能对系统进行更改；而在 Linux 中，通常需要以 root 身份登录才能进行更改。通过授予他人正确的权利或特权，可以允许他们对系统进行更改。

Microsoft 操作系统在系统策略中设有 **用户权利分配** 部分，您可以在其中控制谁可以执行常见的管理任务，例如备份文件和目录或更改系统时间。以下概述了 Windows 中一些常见的权利：

## 常见 Windows 权利

- **从网络访问此计算机** 此权利控制允许谁通过网络连接到该系统。

- **允许本地登录** 此权利控制允许谁坐在计算机前进行登录。

- **备份文件和目录** 此权利控制谁可以在系统上执行备份。

- **更改系统时间** 此权利控制允许谁调整计算机上的时间。

- **获取文件或其他对象的所有权** 此权利控制允许谁获取文件、文件夹或打印机的所有权。资源的所有者可以随时更改该资源的权限。
