
操作系统发布一段时间后，供应商可能会将多项产品改进合并，并为特定的待升级操作系统分发一个编号的 `service pack`（服务包）。关键文件应始终备份，以防服务包或操作系统在安装服务包后无法工作。

### 补丁

`Patches`（补丁，微软也称为 `hotfixes` 热修复）是针对已发布分发的特定操作系统的通用改进。许多补丁和更新纯粹是外观改进和便利的附加功能，而其他补丁则是关键的安全升级，旨在应对特定病毒、发现的威胁或操作系统中发现的弱点。

### 更新

`update`（更新）是指提高操作系统可靠性、安全性或吸引力的服务包或补丁。某些更新可能使操作系统更方便，但不一定更安全。因此，实施前应进行测试。考虑备份关键文件，以防补丁或操作系统在安装后无法工作。

## 实施本地登录要求

个人计算设备使用的主要用户身份验证工具是 `username`（用户名）和 `password`（密码）登录。通常，有三种与用户相关的登录类型需要处理：本地计算机登录、特定软件应用程序登录和网络登录。

在本地计算机级别，通常需要本地登录。此级别的登录验证用户使用本地计算机资源、文件和设备的资格。然而，在多个用户可能被允许使用同一台计算机的共享计算机环境中，`local user and group credentials`（本地用户和组凭据）通过存储在本地计算机上的 `user accounts database`（用户账户数据库）创建和配置。

这些凭据用于获得对计算机的初始访问权限、控制对其本地资源的访问以及控制对网络资源的访问。在 Windows 环境中，这些账户通过计算机管理下的“本地用户和组”实用程序创建和管理，如图 4.12 所示。

![图 4.12 Microsoft 本地用户和组账户](img/c04f012.png)

**图 4.12** Microsoft 本地用户和组账户

独立系统首次启动时，会在操作系统的本地账户数据库中自动创建一个 `administrator's account`（管理员账户）。管理员拥有对系统所有硬件和软件资源的权利和权限。管理员反过来创建其他用户，并根据需要授予他们对系统资源的权利和权限。

管理员可以单独处理 `users`（用户），或将用户聚集到 `groups`（组）中以进行统一管理。这样，管理员可以对个人或整个组分配权限或限制。使用组的价值在于，它节省了将通用权限应用于多个用户的时间，而无需逐个应用。

操作系统首次启动时创建的另一个默认组是一种称为 `Guests` 组的账户类型。此默认组通常对系统具有最小化的访问权限，且其所有成员共享同一用户配置文件。Guest 用户账户自动成为该组的成员。

本地环境中的每个用户和组都有一个配置文件，描述为其创建的资源和桌面配置。配置文件中的设置可用于限制用户可执行的操作，例如安装、移除、配置、调整或复制资源。

当用户登录系统时，系统会检查其配置文件并根据其信息调整系统。这些凭据用于获得对计算机的初始访问权限，并控制每个用户对其本地资源的访问权限。此外，对某些软件应用程序和其他资源的访问可能由额外的应用程序级密码控制。

### 密码

为了使密码有效，它必须具备一定程度的 `complexity`（复杂性）。其 `entropy`（熵值，不可预测性的度量）必须足以挫败前文提到的各种密码破解技术的企图。

密码的长度直接影响其被破解的难易程度。密码越长，破解难度越大。通常建议密码应由 6 到 9 个字符组成。必须避免使用 5 个或更少字符的密码。如果操作系统允许，可使用更长的密码，前提是员工或客户能够记住它们。

密码的宽度涉及可包含的不同字符类型的数量，包括不属于字母表的字符。数字、特殊字符以及大小写字母的组合能增强密码强度，特别是当操作系统将大写和小写字母视为完全不同的字符时。

在某些操作系统中，密码可以包含控制字符、替代字符甚至空格。理想情况下，管理员在为服务器机房或云访问选择密码时，应从以下所有字符集中选取字符：

*   大写字母，如 `A`、`B`、`C`
*   小写字母，如 `a`、`b`、`c`
*   数字，如 `1`、`2`、`3`
*   特殊字符，如 `$`、`?`、`&`
*   替代字符，如 `μ`、`∞` 和 `√`

密码的深度涉及猜测其含义的难度。虽然好的密码应易于记忆，但仍应难以猜测。密码的含义不应是通过简单推理即可轻易猜测或推断出来的东西。

一种行之有效的方法是采用短语而非单词进行构思。助记短语常被采用，从而创建出既难以猜测又无需写下来就能记住的密码。然后，可将短语中某些单词的首字母转换为替代字符。例如，数字 `4` 可用于替换所有使用字母 `f` 的位置。

在美国，美国国家标准与技术研究院（NIST）制定了安全密码创建指南。例如，根据 NIST 标准，用户生成的密码长度应至少为 8 个字符，而机器生成的密码最小长度必须为 6 个字符。最大长度应为 64 个字符。

在验证处理过程中，密码应经过哈希和加盐处理。NIST 还建议废弃密码“提示”的使用，改用基于知识的身份验证技术来证明身份。

#### 额外的密码安全

随着骗子窃取密码的手段日益简易，对额外密码安全的需求得到了更多认可。密码最终甚至可以像直接索要一样轻易被获取。人员绝不应与任何人讨论密码，无论这种对话看起来多么无害或合法。

尽管标准的密码保护实践通常足以阻挡潜在入侵者，但某些情况需要更复杂的方法。在这些情况下，可通过加密技术和 `one-time passwords`（`OTPs`，一次性密码）提供额外保护。

`Password encryption`（`hashing`，密码加密/哈希）是获取标准密码并将其打乱，使其对嗅探器、破解者或其他窃听者变得毫无意义的过程。NIST 建议在存储或检索密码时使用哈希算法。

一次性密码仅适用于单次交易。虽然这种安全方法非常可靠，但它要求管理员携带存储密码的安全密码管理器，或使用第三方服务为组织的超级用户账户提供 `privileged identity management`（`PIM`，特权身份管理）。

最佳密码实践包括以下内容：

*   使用一致的命名约定
*   始终为账户提供初始密码，并要求用户在首次登录时修改
*   保护密码（不要写在公开场所）
*   为组织使用密码管理器
*   不使用默认密码
*   教育用户创建强密码
*   在组织的所有层级强制执行密码策略

#### 账户锁定策略

操作系统提供密码 `lockout policy settings`（锁定策略设置），使管理员能够实施密码策略，防止攻击者反复尝试访问系统。这可以防止攻击者使用 `brute-force attacks`（暴力破解攻击）猜测账户密码从而闯入系统。

暴力破解攻击涉及反复尝试登录以猜测密码。如图 4.13 所示，典型的锁定策略设置包括以下内容：

*   `Account lockout duration/Failure Reset Interval`（账户锁定时长/失败重置间隔）：在预设的登录失败次数后，账户将被锁定多长时间。将此值设为 `0` 将阻止账户自动解锁，直到管理员手动重置为止。
*   `Account lockout threshold/Max Failures`（账户锁定阈值/最大失败次数）：账户被锁定前允许尝试访问的次数。此设置的默认值为 `0`，即禁用账户锁定功能。NIST 规范要求在用户被锁定前允许 `10` 次失败尝试。
*   `Reset account lockout counter after/Lockout Duration`（重置账户锁定计数器时间/锁定持续时间）：账户锁定计数器归零前可经过的时间量。

#### 计算机锁定

用户登录后绝不应让计算机无人看管。这样做会给他人访问和操纵其计算机、数据及网络敞开大门。所有用户都应接受培训，在离开计算机时（即使仅几分钟）要么 `log off`（注销）要么 `lock`（锁定）计算机。在管理层面，可配置系统策略，在一段不活动期后（如 7 到 15 分钟）自动注销用户，并要求其重新登录才能使用系统。

锁定计算机可防止入侵并保留当前系统状态。解锁时，系统中处于活动状态的应用程序和数据仍保持打开，使用户能更轻松地继续未完成的工作。还应指导用户确保在下班时注销。这将关闭所有应用程序并确保数据文件已保存。

#### 物理身份验证设备

当无法像前文所述那样对硬件进行物理锁定时，可以使用一些硬件设备，使个人计算机系统仅供授权用户使用，而其他人无法使用。这些设备包括智能卡和生物识别设备等。

智能卡的可编程性使其能够配合动态密码策略工作，并能与主机计算机来回传递令牌和证书。智能卡系统将用户的秘密 `PIN` 码（仅用户本人知晓的信息）结合起来使用。`Tokens`（令牌）由网络的 `certificate authority`（证书颁发机构）认证系统生成，以产生唯一的通行码。该通行码用于验证用户身份及其对不同资源的访问权限。

## 虚拟化

现代计算平台已发展到可以在单一硬件环境中模拟多个硬件平台（如服务器、端点、交换机以及大多数其他网络资源）的程度。这归功于 `virtualization software`（虚拟化软件），它使配备多个微处理器或 `multicore processors`（多核处理器）的计算硬件能够支持多个设备的 `virtual instances`（虚拟实例），每个实例都能像原始主机硬件一样运行。

例如，单个服务器操作系统可用于托管多个在特定 IP 地址上运行的 Windows 和 Linux 操作系统实例。这些虚拟实例也称为 `virtual machines`（`VMs`，虚拟机），可根据需要启用以应对需求和可扩展性，或提供极高的可移植性。

服务器和端点虚拟化涉及在管理程序内部连接不同类型的虚拟设备。`hypervisor`（管理程序/虚拟机监视器）是一种 `virtual operating platform`（虚拟操作平台），用于托管其他客户操作系统的实例，如图 4.15 所示。正如图中所示，管理程序主要有两种变体：原生和托管型。原生管理程序作为一项服务内置于主机操作系统中，而托管管理程序是添加到底层主机操作系统之上的第三方产品。

还可以使用在管理程序中创建的 `white-box switches`（白盒交换机，通用虚拟路由和交换实例）在主机内创建虚拟化网络。每个 VM 都会被分配一个虚拟网络适配器，负责处理该 VM 的网络流量。这些虚拟适配器可以连接到创建的任意虚拟交换机，以在管理程序内形成网络连接（通过管理程序的虚拟交换组件进行 VM 间通信）。

外部虚拟交换机用于将管理程序连接到底层操作系统及其一个或多个物理网络适配器。此交换机使连接到它的虚拟适配器能够与其他物理网络通信。虚拟环境中的路由器功能由 VM 执行，这些 VM 的操作系统已配置为执行该功能。

![FIGURE 4.15 Hypervisors](img/c04f015.png)

**图 4.15** 管理程序

在主机内创建虚拟网络提供了多项安全优势：

*   **隔离**：除非主机配置为允许其外部物理网络与内部虚拟网络互联，否则虚拟网络默认与物理网络隔离。虚拟网络内的通信永远不会离开虚拟环境。
*   **分段**：除非主机另有配置，否则虚拟网络内的通信不会离开虚拟环境，因此无需在物理网络或防火墙上配置和维护网络分段。
*   **防火墙**：在配置为虚拟网络首端的 VM 上安装基于主机的防火墙，可为虚拟网络与主机的物理网络连接之间提供保护。
*   **最小权限使用配置**：最小权限是信息安全的一项原则，根据用户或群组为履行职责所需，限制其可访问的资源。

### VM 安全

虚拟化平台、管理程序和 VM 都是软件产品。因此，它们都存在缺陷和漏洞。因此，针对这些产品的基本安全建议与操作系统和应用程序相关的建议相同：

*   对主机和用户实施良好的补丁/服务包/更新管理程序。
*   移除已知漏洞或有漏洞历史的应用程序。
*   测试并应用虚拟平台安全补丁。

除了这些基本的虚拟化安全预防措施外，还可以采取许多其他步骤来强化虚拟化计算环境：

*   强化主机设备。实施文件和文件夹权限，控制用户和组，并配置日志记录和时间同步。
*   保护主机与网络用户之间的通信链路。大多数 VM 平台支持 SSH、SSL 和 IPSec 进行通信。
*   保护连接在管理程序内的端点设备。大多数 VM 平台为其虚拟交换机提供 L2 交换控制。这允许以与传统外部网络环境相同的方式监控虚拟平台内的流量。
*   在 VM 与底层主机之间建立安全机制（VM 逃逸漏洞）。这涉及关闭执行正常操作不需要的任何服务。如果不需要某项特定服务，请将其关闭。

### 容器配置完整性

**Containers**（容器）是一种类似于虚拟机的应用程序虚拟化形式。然而，与 VM 不同，容器不依赖管理程序在物理硬件上运行。它们不需要打包的操作系统即可运行。相反，它们虚拟化主机操作系统，使容器应用程序及其库和依赖项成为容器的唯一组件。这种结构使它们比 VM 更快、更便携。它还使它们能够在任何环境中独立运行，包括台式机、笔记本电脑和云环境。

容器的优势使其成为混合云和多云环境中的实用工具。其可移植性使它们能够跨公共云环境混合以及组织的数据中心运行。

虽然容器使云部署更易于实施，但也带来了一系列网络安全问题。大多数组织通常在其云环境中使用的容器数量庞大，且替换或更新频率高，这为大规模漏洞提供了机会。运行的容器越多，潜在攻击面就越大。此外，容器通常基于第三方代码构建，这也随之带来了第三方漏洞。

保护容器的第一步是仔细实施**身份与访问管理 (IAM)**，以控制分配给容器用户的角色和访问权限，以及授予或拒绝权限的条件。一如既往，在为容器分配权限时，遵循*最小权限原则*是个好主意。保护容器的下一步是在部署前对其运行漏洞扫描。您还应为环境中使用的所有镜像创建并使用受信任来源列表。有可用于此目的的开源工具，如 Notary。请参阅 `www.docker.com/blog/notary-v2-project-update`。最后，强化整个环境，包括主机和所有守护进程。

## 应用软件安全

软件*应用包*作为操作系统的扩展而运行。根据所使用的操作系统类型，应用程序可能直接控制某些系统资源（如打印机和网络接口），而操作系统在后台提供基础支持。在更高级的系统中，操作系统为系统中的所有应用程序提供通用的输入、输出和磁盘管理功能。

某些应用程序包含内置安全工具，可在操作系统提供的级别之外控制对应用程序的访问。然而，许多应用程序在编写时很少考虑安全问题。此类程序的重点是功能性和共享，将安全问题留给操作系统和安全工具。

### 软件漏洞利用

*软件漏洞利用*一词用于描述旨在利用软件产品、操作系统和应用程序中的漏洞或弱点的网络攻击。这些漏洞可能是由于在创建软件时很少或根本不考虑安全问题，也可能是由于软件在发布使用前测试不充分所导致。

计算机软件行业存在两个截然冲突的目标：

*   使产品尽可能开放且易于使用，以便非技术用户也能使用。
*   使应用程序坚不可摧，永远不会发生任何坏事。软件程序员被要求在同一产品中同时满足这两个目标。

在某些情况下，程序员可能试图创建一个真正开放的产品，而不考虑它可能如何被恶意人员利用。在其他情况下，他们可能缺乏足够的经验来预见其产品可能被如何利用。随着全球程序员队伍的不断壮大，有许多个人拥有测试、操纵和修改编程的大量知识库。这包括*黑帽黑客*。
