## 6.5 剪枝

![image](img/chapter_title_below.png)

第 6.2 节赞扬了小型决策树的优点：可解释性、移除无关和冗余属性、降低过拟合风险。这些是驱动在决策树引导过程中使用信息理论的论据；它们也激励了随后的步骤：剪枝。

![image](img/image071.png)![image](img/image071.png)![image](img/image080.png)![image](img/image111.png)图 6.2 一种简单的剪枝方法是将子树替换为叶节点

![image](img/image071.png)![image](img/image071.png)本质图 6.2 将帮助我们解释这一原理。左侧是原始决策树，其六个属性测试命名为`t1...t6`。右侧是剪枝后的版本。注意，原始树中以测试`t3`为根的子树在剪枝后的树中被替换为标记为负类的叶节点；而以测试`t6`为根的子树被替换为标记为正类的叶节点。读者可以看出这一点：剪枝由将一个或多个子树替换为叶节点组成，每个叶节点的标记为到达（在原始分类器中）被移除的子树的训练示例中最常见的类别。

这最后一个想法听起来违背直觉：归纳机制试图创建一个在训练示例上得分为零错误的决策树，但这种完美可能会在剪枝后的树中丢失！但务实的工程师并不会报警。最终目标不是分类训练示例（它们的类别已经是已知的）。相反，我们需要一个能够标记未来示例的工具。经验表明，这种性能通常通过合理的剪枝得到提高。

### 误差估计

剪枝通常按一系列步骤进行：首先用叶节点替换一个子树，然后是另一个，以此类推，只要它们根据某些标准是有益的。“有益”一词是为了警告较小的值不应被性能所抵消。

这引出了误差估计的问题。该原理在 6.2 中说明（注：此处包含一些乱码字符，但遵循逻辑流）。

### 后剪枝

该术语指的是决策树在从数据中完全引导后进行剪枝的情况（另一种方案是下一小节的主题）。我们已经知道本质是将子树替换为标记为到达该叶节点的训练示例中频繁的类别。由于通常有多个可以这样替换的子树，必须做出选择；选择的存在意味着我们需要一个标准来指导决策。

这里有一种可能性。我们知道剪枝可能会改变分类器的性能。评估这种变化的一种方法是比较剪枝前后的决策树的误差估计：

```
D = Eafter - Ebefore
```

在可选的剪枝方案中，我们选择差异最小的`Dmin`；但只有当`Dmin < c`时才执行剪枝，其中`c`是用户设置的为了树的紧凑可以容忍的性能下降阈值。然后重复该机制，决策树变得越来越小，停止准则由常数`c`施加。因此在图 6.2 中，第一次剪枝步骤可能移除是以`t3`为根的子树；第二步移除是以`t6`为根的子树。在这里，程序停止了是因为任何进一步的剪枝尝试导致误差估计增加过多：差异超过了用户的阈值：`D > c`。

该原理通过表 6.8 中的伪代码进行了总结。

### 在线剪枝 (On-line Pruning)

在分治过程中，每个后续属性都会将训练示例集划分成越来越小的子集。不可避免的是，支持树低层级测试选择的证据将变得非常薄弱。当一个树节点仅由两个训练示例（例如，一个正样本和一个负样本）达到时，一个完全无关的属性可能纯属巧合地成功将正负样本分开。向决策树中添加此类测试所获得的唯一“收益”是训练集的过拟合。

在线剪枝的动机是为了防止这种情况的发生。规则如下：如果训练子集小于用户定义的最小值`m`，则停止树的扩展。

### 剪枝的影响 (Impact of Pruning)

剪枝的程度由两个参数控制：后验剪枝中的`c`和在线剪枝中的`m`。在两种情况下，较高的值都会导致更小的树。

### 表 6.8 决策树剪枝算法

![image](img/image731.png)

`c` ::: 用户集常量

1. 估计原始决策树的错误率。将其值记为`Ebefore`。
2. 估计通过其他剪枝方式得到的树的错误率。
3. 选择剪枝后估计错误率增加最小的，`Dmin = Ebefore - Eafter`，但前提是`Dmin < c`。
4. 只要`Ebefore - Eafter < c`，就重复步骤 (2) 和 (3)。

剪枝往往提高未来示例性能的主要原因是：移除统计支持较少的低级测试通常会减少过拟合风险。然而，这种方法只作用于一定程度。如果过度，极高程度的剪枝会导致决策被替换为标记为多数类的叶节点。这样的分类器可能没用。

图 6.3 显示了逐渐增加剪枝对分类性能的影响。横轴是由`c`或`m`控制的剪枝程度。纵轴表示在训练集以及某些假设的测试集（后者由未用于学习但标签已示例组成）上量的错误率。

在训练集曲线上，当没有任何剪枝时，错误率最小。然而，更有趣的是测试集曲线。它的形状告诉我们，未剪枝的树在测试数据上的表现很差，这是由于未剪枝树倾向于过拟合训练集，可以通过增加剪枝程度来减轻。然而，过度剪枝会移除有用信息的属性测试，会对分类性能产生不利影响。

通过这两条曲线，我们可以了解到关于底层数据的很多信息。在某些应用中，即使是极其微小的剪枝也会损害测试数据的错误率；另一个注意的是，测试集的错误率几乎大于训练集的错误率。

## 6.6 将决策树转换为规则

![image](img/chapter_title_below.png)

决策树与其他分类器相比的优势之一是它们的可解释性。从根节点到叶节点路径上的任何测试序列都代表一个“如果……那么……”的规则，该规则解释了分类器为何将给定示例标记为该类或那类。

### 决策树生成的规则

读者会发现将决策树转换为一组规则非常容易。只需要注意到叶节点是通过一系列边到达的，这些具体选择是由沿路遇到的属性测试结果决定的。因此，每个叶节点都与测试结果的具体交结相关联。

为了说明，让我们从图 6.1a 的决策树中写出`pos`类的完整规则集。

```
if crust-size=big AND filling-size=big then pos

if crust-size=big AND filling-size=small AND shape=circle then pos

if crust-size=small AND shape=circle then pos

else neg
```

### 规则剪枝

之前描述的树后验剪枝机制将子树替换为叶节点。这意味着低级测试是首先移除的，因为该技术无法在移除下方节点之前移除高级节点。在线剪枝的情况也是类似的。

然而，一旦树转换为规则，剪枝获得了更大的灵活性：任何规则中`if`部分的任何测试都是移除的候选对象；以及整个……
