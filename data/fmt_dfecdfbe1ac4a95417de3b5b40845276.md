
# 基址+偏移量寻址

**基址+偏移量寻址**使用存储在 CPU 寄存器之一中的值作为开始计数的基址位置。CPU 然后将指令提供的偏移量加到该基址上，并从计算出的内存位置检索操作数。

## 辅助存储器

**辅助存储器**通常用来指代磁性、光学或基于闪存的介质，或其他包含 CPU 不能立即访问的数据的存储设备。为了让 CPU 访问辅助存储器中的数据，操作系统必须先读取数据并将其存储在实存中。然而，辅助存储器比主存便宜得多，可用于存储海量信息。在此背景下，硬盘、闪存驱动器和光学介质（如光盘 (`CD`)、数字多功能光盘 (`DVD`) 和蓝光光盘）都可以作为辅助存储器发挥作用。

虚拟内存是一种特殊的辅助存储器，操作系统对其进行管理，使其外观和行为就像实存一样。最常见的虚拟内存类型是大多数操作系统作为其内存管理功能一部分来管理的页面文件。这个特殊格式的文件包含之前存储在内存中但近期未被使用的数据。当操作系统需要访问存储在页面文件中的地址时，它会检查该页面是否驻留在内存中（如果是，可以立即访问），或者它是否已被换出到磁盘，在这种情况下，它会将数据从磁盘读回实存（这个过程称为**换页**）。

### 使用虚拟内存

使用虚拟内存是一种低成本的方法，可让计算机运行起来就好像它拥有的真实内存比实际安装的物理内存更多。其主要缺点是，当数据在主存和辅存之间交换时发生的分页操作相对较慢（内存功能以纳秒为单位，磁盘系统以微秒为单位；通常这意味着三个数量级的差异！）并消耗大量的计算机开销，从而拖慢整个系统。随着实际物理 `RAM` 容量的增加，对虚拟内存的需求会减少，并且可以通过使用闪存卡或 `SSD` 来托管虚拟内存分页文件，以减轻虚拟内存带来的性能损失。

#### 内存安全问题

内存存储并处理您的数据——其中一些可能极其敏感。您必须了解各种类型的内存，并知晓它们如何存储和保留数据。任何可能保留敏感数据的内存设备，在允许其因任何原因离开您的组织之前，都应进行清除。对于设计为断电后仍能保留数据的辅助内存以及 `ROM`/`PROM`/`EPROM`/`EEPROM` 设备，这一点尤为重要。

然而，内存数据保留问题并不局限于那些设计用于保留数据的内存类型。请记住，静态和动态 `RAM` 芯片通过电容器和触发器存储数据（参见侧边栏“动态 RAM 与静态 RAM”）。从技术上讲，这些电气元件在断电后可能会在有限的时间内保留部分电荷。技术娴熟的个人理论上可以对这些元件进行电学测量，并检索存储在这些设备上的部分数据。然而，这需要相当深厚的技术专长，除非您的对手拥有令人难以置信的深厚资金，否则这不太可能构成威胁。

存在一种攻击会冻结内存芯片，以便在系统关闭或 `RAM` 从主板上拔出时延缓驻留数据的衰减。请参阅 <http://en.wikipedia.org/wiki/Cold_boot_attack>。甚至还有针对内存镜像转储或系统崩溃转储以提取加密密钥的攻击。请参阅 <http://www.lostpassword.com/hdd-decryption.htm>。

围绕内存最重要的安全问题之一，是在计算机使用期间控制谁可以访问存储在内存中的数据。这主要是操作系统的责任，也是本章前几节中描述的各种处理模式所涉及的主要内存安全问题。在本章后面的“基本安全保护机制”部分，您将了解进程隔离原则如何用于确保进程无法访问读取或写入未分配给它们的内存空间。如果您在多级安全环境中操作，确保采取足够的保护措施以防止内存内容在安全级别之间发生意外泄露（无论是通过直接内存访问还是隐蔽信道）就显得尤为重要（隐蔽信道的完整讨论将在本章后面出现）。

#### 存储

*数据存储设备*构成了我们将要讨论的计算机系统组件的第三大类。这些设备用于存储信息，以便计算机在数据写入后的任何时间使用。我们将首先探讨一些与存储设备相关的常用术语，然后介绍与数据存储相关的一些安全问题。

##### 主存与辅存

主存储和辅存储的概念可能会让人有些困惑，尤其是在与主存和辅存进行比较时。有一个简单的方法可以理清它们——它们是同一回事！*主内存*，也称为*主存储*，是计算机在运行时用于保持必要信息随时可供 CPU 使用的 `RAM`。*辅助内存*（或*辅助存储*）包括您每天使用的所有熟悉的长期存储设备。辅助存储由磁性和光学介质组成，例如 `HDD`、`SSD`、闪存驱动器、磁带、`CD`、`DVD`、闪存卡等。

##### 易失性与非易失性

您已经从我们之前关于内存的讨论中熟悉了易失性的概念，尽管您可能以前没有听说过用该术语来描述它。存储设备的易失性仅仅是衡量其在断电时丢失数据的可能性有多大。设计用于保留数据的设备（如磁性介质）被归类为*非易失性*，而设计用于丢失数据的设备（如静态或动态 `RAM` 模块）被归类为*易失性*。回顾前一节的讨论，复杂的技术有时可能能够在断电后从易失性内存中提取数据，因此两者之间的界限有时可能会变得模糊。

##### 随机与顺序

存储设备可以通过两种方式之一进行访问。*随机访问存储*设备允许操作系统通过某种寻址系统，立即从设备内的任意点进行读取（有时也可写入）。几乎所有主存储设备都是随机访问设备。您可以使用内存地址访问 `RAM` 芯片中任意位置存储的信息，而无需读取其之前物理存储的数据。大多数辅助存储设备也是随机访问的。例如，硬盘驱动器使用可移动磁头系统，允许您直接移动到磁盘上的任意点，而无需旋转经过先前磁道上存储的所有数据；同样，`CD` 和 `DVD` 设备使用光学扫描仪，可将自身定位在盘片表面的任何位置。

另一方面，*顺序存储*设备不提供这种灵活性。它们要求您读取（或跳过）物理存储在所需位置之前的所有数据。顺序存储设备的一个常见示例是磁带驱动器。为了访问存储在磁带中间的数据，磁带驱动器必须物理扫描整个磁带（即使在快进模式下不一定处理其经过的数据），直到到达所需位置。

显然，顺序存储设备的运行速度比随机访问存储设备慢得多。然而，您再次面临成本/收益的决策。许多顺序存储设备可以在相对廉价的介质上存储海量数据。这一特性使磁带驱动器成为与灾难恢复/业务连续性计划相关的备份任务的独特选择（请参阅第 3 章“业务连续性规划”和第 18 章“灾难恢复规划”）。在备份场景中，您通常有极大量的数据需要存储，且极少需要访问这些存储的信息。这种情况非常适合使用顺序存储设备！

##### 存储介质安全

我们在上一节中讨论了围绕主存储设备的安全问题。对于辅助存储设备的安全性，有三个主要关注点；它们都反映了针对主存储设备提出的担忧：

*   数据可能即使在被擦除后仍保留在辅助存储设备上。这种情况称为*数据残留*。大多数精通技术的计算机用户都知道，即使文件已被删除，也有可用的实用程序可以从磁盘中检索文件。从技术上讲，从已重新格式化的磁盘中检索数据也是可能的。如果您真的想从辅助存储设备中移除数据，必须使用专门设计用于销毁设备上所有数据痕迹的实用程序，或将其损坏或销毁到无法修复的程度（通常称为*清理*）。

### SSD 与清除

`SSD` 在清除方面存在独特问题。`SSD` 的磨损均衡意味着通常存在一些未标记为“活动”的数据块，但它们在数据被复制到磨损程度较低的块时保存了数据的副本。这意味着传统的零擦除作为 `SSD` 的数据安全措施是无效的。

### 辅助存储设备盗窃

辅助存储设备也容易被盗。经济损失并非主要因素（毕竟，备份磁带或硬盘值多少钱？），但机密信息的丢失构成巨大风险。如果有人将你的商业机密复制到可移动介质光盘上并带出大门，其价值远超光盘本身的成本。因此，使用全盘加密以降低未经授权实体访问数据的风险至关重要。由于 `SSD` 的磨损均衡技术，在存储任何数据之前对其进行加密是良好的安全实践。这将最大程度地减少明文数据驻留在休眠块中的可能性。幸运的是，许多 `HDD` 和 `SSD` 设备提供设备原生加密功能。

### 辅助存储的访问控制

对存储在辅助存储设备上的数据的访问，是计算机安全专业人员面临的最关键问题之一。对于硬盘，数据通常可以通过操作系统访问控制的组合来保护。可移动介质构成更大的挑战，因此保护它们通常需要加密技术。

### 介质保留与淘汰

由于可用性也是安全三要素的一部分，因此选择能在所需时间长度内保留数据的介质至关重要。例如，备份磁带可能在数据保留期结束前就已降解。此外，用于辅助存储的技术可能会过时，导致难以恢复/读取数据。

## 输入和输出设备

输入和输出设备通常被视为基本、原始的外设，通常在它们停止正常工作前不会受到太多关注。然而，即使这些基本设备也可能给系统带来安全风险。安全专业人员应了解这些风险，并确保采取适当的控制措施来缓解它们。接下来的四节将探讨特定输入和输出设备带来的一些风险。

### 显示器

显示器看起来相当无害。毕竟，它们只是显示操作系统呈现的数据。当你关闭它们时，数据从屏幕上消失且无法恢复。然而，名为 `TEMPEST` 的程序技术可能会危及显示器上显示数据的安全。通常，阴极射线管（`CRT`）显示器更容易产生显著辐射，而液晶显示器（`LCD`）泄露的辐射少得多（有人声称不足以泄露关键数据）。

`TEMPEST` 是一种技术，允许从远处读取每个显示器产生的电子辐射（称为 `Van Eck 辐射`）（此过程称为 `Van Eck 窃听`），甚至可以从另一个位置读取。该技术也可用于防范此类活动。各种演示表明，你可以轻松读取办公楼内显示器的屏幕内容，只需使用停在街边货车内的设备即可。不幸的是，防止 `Van Eck 辐射` 所需的保护控制（大量的铜！）实施成本高昂且使用笨重。可以说，任何显示器最大的风险仍然是肩窥或相机长焦镜头。有人用肉眼或摄像机看到你屏幕内容的概念称为 `肩窥`。不要忘记 `肩窥` 适用于台式机显示器、笔记本显示器、平板电脑和手机。

### 打印机

打印机也可能代表安全风险，尽管相对简单。取决于组织采用的物理安全控制，带走纸质形式的敏感信息可能比带走闪存驱动器或磁性介质容易得多。如果打印机是共享的，用户可能忘记取走敏感打印件，使其暴露在窥视之下。许多现代打印机还在本地存储数据，通常在硬盘上，有些甚至无限期保留打印副本。打印机通常在网络上暴露以便访问，且通常未设计为安全系统。但根据打印机型号，可能有许多配置设置可提供合理级别的安全网络打印服务。这些可以包括加密数据传输和打印机交互前的身份验证。这些问题最好由组织的安全策略来解决。

### 键盘/鼠标

键盘、鼠标和类似的输入设备也无法免疫安全漏洞。所有这些设备都容易受到 `TEMPEST` 监控。此外，键盘还容易受到不那么复杂的窃听。一个简单的装置可以放置在键盘内部或其连接线上，以拦截所有按键并利用无线电信号传输给远程接收器。这具有与 `TEMPEST` 监控相同的效果，但可以用成本低得多的设备完成。此外，如果你的键盘和鼠标是无线的，包括蓝牙，它们的无线电信号可能被拦截。

### 调制解调器

随着普遍宽带和无线连接的出现，调制解调器正成为稀缺的遗留计算机组件。如果你的组织仍在使用旧设备，调制解调器可能是硬件配置的一部分。用户系统上存在调制解调器，往往是安全管理员最大的烦恼之一。调制解调器允许用户在你的网络中创建不受控制的接入点。在最坏的情况下，如果配置不当，它们会造成极其严重的安全漏洞，允许外部人员绕过所有边界保护机制，直接访问网络资源。在最好的情况下，它们创建了一个替代的出口通道，内部人员可用来将数据输送到组织外部。但请记住，只有当调制解调器连接到正在运行的电话固定线路时，这些漏洞才能被利用。

除非确实有业务需求，否则你应在组织的安全策略中认真考虑全面禁止调制解调器。在这些情况下，安全官员应知晓网络上所有调制解调器的物理和逻辑位置，确保它们配置正确，并确保采取适当的保护措施以防止其非法使用。

## 固件

`固件`（在某些领域也称为 `微代码`）是用于描述存储在 `ROM` 芯片中的软件的术语。这种类型的软件不经常更改（实际上，如果存储在真正的 `ROM` 芯片上而非 `EPROM`/`EEPROM` 上，则永不更改），且通常驱动计算设备的基本操作。固件有两种类型：主板上的 `BIOS` 以及通用的内部和外部设备固件。

### BIOS 和 UEFI

`基本输入/输出系统 (BIOS)` 包含计算机启动并从磁盘加载操作系统所需的、与操作系统无关的原始指令。`BIOS` 包含在固件设备中，计算机在启动时立即访问它。在大多数计算机中，`BIOS` 存储在 `EEPROM` 芯片上以便于版本更新。更新 `BIOS` 的过程称为“`刷新` BIOS”。

已有少数恶意代码嵌入 `BIOS`/固件的案例。还有一种称为 `phlashing` 的攻击，即安装官方 `BIOS` 或固件的恶意变体，在设备中引入远程控制或其他恶意功能。

自 2011 年以来，大多数系统制造商已将其主板上的传统 `BIOS` 系统替换为统一可扩展固件接口 (`UEFI`)。`UEFI` 是硬件与操作系统之间更高级的接口，它保持对传统 `BIOS` 服务的支持。

#### 设备固件

许多硬件设备（如打印机和调制解调器）也需要一定的有限处理能力来完成其任务，同时将对操作系统本身造成的负担降至最低。在许多情况下，这些“微型”操作系统完全包含在其所服务设备上的固件芯片中。与计算机的 `BIOS` 类似，设备固件通常存储在 `EEPROM` 设备上，以便在必要时进行更新。

## 基于客户端的系统

基于客户端的漏洞将用户、其数据及其系统置于被攻破和破坏的风险之中。客户端攻击是指任何能够危害客户端的攻击。通常在讨论攻击时，默认主要目标是服务器或服务器端组件。客户端攻击或以客户端为中心的攻击，是指客户端本身或客户端上的某个进程成为目标。客户端攻击的一个常见例子是：恶意网站将恶意移动代码（如小程序）传输到客户端上运行的易受攻击的浏览器中。客户端攻击可通过任何通信协议发生，不仅限于超文本传输协议 (`HTTP`)。另一个基于客户端的潜在漏洞是本地缓存投毒的风险。

### 小程序

回顾一下，代理是从用户系统发送的代码对象，用于查询和处理存储在远程系统上的数据。`Applets` 执行相反的功能；这些代码对象从服务器发送到客户端以执行某些操作。事实上，小程序实际上是独立的微型程序，独立于发送它们的服务器而执行。万维网领域正处于持续变化之中。如今小程序的使用不如 2010 年代初期那样普遍。然而，小程序并未从网络中消失，大多数浏览器仍然支持它们（或仍安装有支持它们的插件）。因此，即使您的组织在内部或公共网页设计中不使用小程序，您的网页浏览器在浏览公共网络时仍可能遇到它们。

设想一台向网络用户提供各种金融工具的 Web 服务器。其中一种工具可能是抵押贷款计算器，它处理用户的财务信息，并根据贷款本金、期限和借款人的信用信息提供每月抵押贷款付款额。远程 Web 服务器不是处理这些数据并将结果返回给客户端系统，而是可能向本地系统发送一个小程序，使其能够自行执行这些计算。这为远程服务器和最终用户都提供了许多好处：

*   处理负担转移给了客户端，释放了 Web 服务器上的资源以处理来自更多用户的请求。
*   客户端能够使用本地资源生成数据，而无需等待远程服务器的响应。在许多情况下，这会使对输入数据变化的响应更快。
*   在编写得当的小程序中，Web 服务器不会接收提供给小程序作为输入的任何数据，从而保持用户财务数据的安全性和隐私性。

然而，正如代理一样，小程序也引入了许多安全顾虑。它们允许远程系统发送代码到本地系统执行。安全管理员必须采取措施，确保发送到其网络上系统的代码是安全的，并经过适当筛查以防恶意活动。此外，除非逐行分析代码，否则最终用户永远无法确定小程序不包含特洛伊木马组件。例如，抵押贷款计算器可能确实会在最终用户不知情或未经同意的情况下，将敏感财务信息传输给 Web 服务器。

小程序类型的两个历史示例是 `Java` 小程序和 `ActiveX` 控件。

#### Java 小程序

`Java` 是由 Sun Microsystems（现归 Oracle 所有）开发的一种与平台无关的编程语言。`Java` 在很大程度上已被现代应用程序取代，且在大多数浏览器中不再直接受支持。然而，您仍应对 `Java` 有基本的了解，因为它可能仍在内部使用，或受贵组织实施的特定浏览器支持。虽然现代网页设计已摒弃 `Java`，但这并不意味着 `Java` 已从互联网上彻底清除。大多数编程语言使用编译器生成针对特定操作系统定制的应用程序。这需要使用多个编译器为单个应用程序生成不同版本，以支持每个平台。`Java` 通过引入 `Java 虚拟机 (JVM)` 克服了这一限制。每个运行 `Java` 代码的系统都会下载其操作系统支持的 `JVM` 版本。然后 `JVM` 获取 `Java` 代码并将其转换为该特定系统可执行的格式。这种安排的巨大好处是代码可以在操作系统之间共享而无需修改。`Java` 小程序就是通过互联网传输的简短 `Java` 程序，用于在远程系统上执行操作。

安全性是 `Java` 平台设计期间的重中之重，Sun 的开发团队创建了“沙箱”概念，对 `Java` 代码施加权限限制。沙箱将 `Java` 代码对象与操作系统的其余部分隔离开来，并强制执行关于这些对象可访问资源的严格规则。例如，沙箱会禁止 `Java` 小程序从未专门分配给它的内存区域检索信息，防止小程序窃取该信息。不幸的是，虽然沙箱减少了可通过 `Java` 发起的恶意事件形式，但仍有许多其他漏洞被广泛利用。

#### ActiveX 控件

`ActiveX` 控件是微软针对 Sun 的 `Java` 小程序推出的对应产品。它们的运作方式类似，但使用多种语言实现，包括 `Visual Basic`、`C`、`C++` 和 `Java`。`Java` 小程序和 `ActiveX` 控件之间有两个关键区别。首先，`ActiveX` 控件使用微软专有技术，因此只能在运行微软浏览器的系统上执行。其次，`ActiveX` 控件不受 `Java` 小程序所受沙箱限制的约束。它们拥有对 Windows 操作环境的完全访问权，并可执行许多特权操作。因此，在决定下载和执行哪些 `ActiveX` 控件时，必须采取特别预防措施。一些安全管理员采取了相当严厉的立场，禁止从极少数受信任站点之外的任何站点下载 `ActiveX` 内容。

`ActiveX` 仍受 `Internet Explorer 11` 支持，但随 `Windows 10` 发布的微软最新浏览器 `Edge` 不包含对 `ActiveX` 的支持。这表明微软正在逐步淘汰 `ActiveX`。

### 本地缓存概述

**本地缓存** 是指临时存储在客户端以供将来重用的任何内容。典型客户端上存在许多本地缓存，包括地址解析协议（`ARP`）缓存、域名系统（`DNS`）缓存和 Internet 文件缓存。
