### DHCP 服务器

你可以通过应用“所有服务器”部分讨论的所有加固技术来帮助保护 DHCP 服务器，但也可以采取一些额外的预防措施。首先，当你创建作用域（DHCP 要分发的 IP 地址）时，仅创建网络所需数量的地址。例如，如果你有 20 台需要地址的系统，你应该创建一个仅分发 20 个地址的作用域。其好处是，如果未经授权的个人连接到网络（第 21 台系统），作用域中将没有可供 DHCP 服务器分发给客户端系统的可用 IP 地址。结果是该系统将无法在网络上通信。

除了在作用域中仅保留足够的地址外，你还可以实施地址预留，即你在作用域中创建的 20 个地址中的每一个都关联一个 MAC 地址。其好处是每个地址将仅分配给具有相关联 MAC 地址的网卡。

### SMTP 服务器和 FTP 服务器

对于 SMTP 服务器和 FTP 服务器，你都应该应用“所有服务器”部分讨论的加固技术，但同样也应进一步加强安全实践。

在处理 SMTP 服务器时，请确保使用防火墙保护服务器，并打开 TCP 端口 25 以允许 SMTP 服务器通过防火墙到达服务器。你还需要确保在 SMTP 服务器上禁用 SMTP 中继。SMTP 中继是指你的 SMTP 服务器将任何非发往自身的 SMTP 消息转发至目标服务器的概念。中继是有害的，因为黑客可能向你的服务器发送垃圾邮件，然后由你的服务器转发给目标服务器。从目标服务器的角度来看，是你的服务器在发送垃圾邮件！

对于 FTP 服务器，请确保限制谁可以向 FTP 服务器上传文件，或许仅允许从服务器下载文件。你还应决定是允许匿名访问 FTP 服务器，还是强制用户向服务器进行身份验证。如果你确实强制进行身份验证，请务必以安全的方式进行。

### 常见缓解策略

你已经了解了一些降低（缓解）安全事件发生可能性的常见策略。以下是这些要点的总结，供你复习认证考试时参考：

- **网络分段** 网络分段允许你控制网络上哪些系统可以相互通信。你可以使用 VLAN 和 IP 子网来创建网络段。在某些常见场景中，你会希望对网络进行分段，以将生产系统与客户系统分隔开——例如酒店客人系统或教室环境中的学生系统。在高安全环境中，你也希望将绝密系统与其他机密系统分隔开。

- **安全分层** 通过修补系统、使用防火墙和网络分段以及加固系统，分层实施安全防护。

- **应用层防火墙** 使用应用层防火墙，因为它们允许你根据数据包中的有效载荷数据过滤流量。

- **手动更新** 定期执行系统更新，以确保修补系统中任何已知的安全问题。

### 固件版本控制

请务必定期为路由器和交换机等设备应用固件更新。

### 包装器

如果可能，您应使用包装器（如 TCP 包装器）来创建连接策略，以控制对系统上特定服务的访问。例如，在 Linux 中，您可以使用 `/etc/hosts.allow` 文件来指定可访问 FTP 服务和 HTTP 服务等服务的系统。

### 控制冗余性和多样性

控制冗余性和多样性是一项安全原则，旨在确保您使用多样化的产品来创建多层安全防护。例如，如果您决定在内部网络和互联网之间部署多个防火墙，您可以创建多层防火墙，黑客必须攻破所有这些防火墙才能访问内部网络。如果您在每一层都使用相同的防火墙产品，一旦黑客攻破了第一个防火墙，就能轻松绕过其余防火墙。如果您在每一层采购不同的防火墙产品，每个产品将拥有不同的漏洞，黑客就需要花费时间去研究如何绕过每一个防火墙，而不能利用从第一个防火墙获得的知识。

# 认证总结

在本章中，您学习了缓解系统和应用程序常见安全威胁的方法。备考 Security+ 认证考试时，应牢记以下要点：

- 所有系统都应进行加固，即移除不必要的软件并禁用不必要的服务。

- 加固系统时，请调查系统上运行的每一项服务，并确定该服务是否必要。如果不需要，应将其禁用。

- 作为系统加固的一部分，请确保禁用不必要的账户并重命名默认账户（如 `administrator`）。此外，务必定期为系统打补丁。

- 交换机等网络设备也应进行加固。请务必更新路由器和交换机上的固件。在高安全环境中，请禁用交换机上未使用的端口，并在已用端口上配置端口安全，这是一种将特定 MAC 地址与某个端口关联的功能。

- 请确保在网络设备上使用安全管理协议（如 `SSH` 而非 `Telnet`）。

- `802.1X` 标准被称为端口访问控制标准，它通过使用中央认证服务器（如 `RADIUS`）来控制谁有权访问有线或无线网络。

- 在可用于协助系统加固的众多软件工具中，两种常用方法是安全模板和组策略。您可以使用安全模板来帮助创建安全基线，组策略则是用于对系统应用限制的一种方法。

- 请参考常见的服务器加固技术，例如：仅允许 `DNS` 服务器向特定主机进行区域传输，将 `DNS` 和 Web 服务器等公共服务器放置在 `DMZ` 中，以及禁用 Web 服务器上未使用的功能。

## 理解操作系统加固

- 操作系统加固的目标是通过移除不必要的软件和禁用不需要的服务，来减少系统的攻击面。

- 请确保禁用不需要的用户账户并重命名默认账户名。

## 系统加固程序

- 从加固路由器和交换机等网络设备开始您的加固程序。第一步是更新设备上的固件。

- 禁用网络交换机上未使用的端口，以免未经授权的人员连接到可用端口。

- 在交换机上实施端口安全，以限制哪个系统可以连接到交换机上的特定端口。此外，使用 `MAC` 过滤来过滤哪些系统可以向网络上的其他系统发送数据。

- `802.1X` 是一种网络访问控制标准，它允许您通过使用中央认证服务器（如 `RADIUS` 服务器）来控制谁可以连接到网络。

- 组策略是在 `Active Directory` 环境中从一个中心位置配置所有系统的方法。您可以配置组成员身份和运行的服务，并通过组策略控制桌面外观。

- 安全模板是创建安全基线的绝佳方式。安全模板是一个包含策略设置的文本文件，随后可将其导入到系统或 `Active Directory` 中。

- 安全基线是一种标准配置，已获批准为将系统置于安全状态所需的配置。

- 要建立并维护良好的安全态势，您必须首先应用安全基线，然后使用漏洞扫描器等工具持续监控系统状态。最后一步是修复因监控而发现的系统配置中的任何错误。

## 服务器加固最佳实践

- 所有服务器都应进行加固和打补丁。

- Web 服务器应进行加固，同时还要确保 Web 服务器放置在 `DMZ` 中（如果是互联网服务器）并受到防火墙保护。此外，禁用 Web 服务器上不打算使用的功能。

- 要保护 `DNS` 服务器，请将其放置在 `DMZ` 中，并在防火墙上开放 `UDP 53` 端口以允许 `DNS` 查询到达 `DNS` 服务器。请务必将 `DNS` 服务器上的区域传输限制为仅传输给您的辅助 `DNS` 服务器，如果您不向互联网上的辅助 `DNS` 服务器进行区域传输，请在防火墙上阻止 `TCP 53`。

- 在高安全环境中，请配置 `DHCP` 预留，将每个 IP 地址与特定的 `MAC` 地址关联。这将确保网络上的未授权系统无法从 `DHCP` 服务器获取 IP 地址。

- `SMTP` 服务器应禁用 `SMTP` 中继，而 `FTP` 服务器应实施身份验证以控制谁有权访问 `FTP` 服务器上的文件。

### 主机和应用程序安全解决方案

Security+ 考试的一个重点是了解不同系统面临的风险以及如何缓解这些风险。例如，公司可能担心敏感公司数据泄露或被盗，并寻求您提供降低该风险的解决方案。在这种情况下，您会建议在计算机上禁用 USB 端口，以便无法将可移动驱动器连接到系统，并使用 `数据丢失防护 (DLP)` 解决方案阻止敏感数据类型通过电子邮件发送。

在本节中，您将学习如何通过使用常见的安全解决方案（如端点防护、启动完整性和数据安全功能）在系统（称为主机）以及运行在该系统上的应用程序上实施安全防护。

# 端点防护

`端点防护`，也称为 `端点安全`，是指可用于保护客户端设备（如台式机、笔记本电脑、平板电脑和移动设备——这些统称为端点）的技术术语。以下是您应实施以帮助保护端点的技术列表：

- **防病毒** 您在 第 5 章 中了解了恶意软件和病毒。为了防范不同类型的病毒，请务必在端点（客户端）上安装防病毒软件，并保持病毒定义为最新，以最大程度地提高防护能力。
