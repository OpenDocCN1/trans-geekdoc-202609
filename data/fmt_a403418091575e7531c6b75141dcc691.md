### 4.6.4 矩计算

*频率矩* 是项频率的一种推广，能提供关于流中项分布的不同信息。在每个项 `x` 具有绝对频率 `f[x]` 的流中，第 `p` 阶矩定义为

```
F[p] = ∑_x f[x]^p
```

观察可知，`F[1]` 是流的长度，而 `F[0]` 是流包含的不同项的数量（如果我们取 `0⁰` 为 0，且对于任何其他 `f` 有 `f⁰ = 1`）。`F[2]` 尤为重要，因为它可用于计算流中项的方差。极限情况是 `F[∞]`，定义为

```
F[∞] = max_x f[x]
```

即最高频元素的频率。

Alon 等人 [14] 开启了用于计算频率矩近似值的流算法研究。他们针对 `p ≥ 2` 的 Sketch（称为 Alon-Matias-Szegedy 或 AMS Sketch）使用了一种类似于 CM-SKETCH 的技术：选取将每个项映射到 `{−1, +1}` 的哈希函数，利用它们构建一个无偏但高方差的矩估计器，然后对多个副本取平均和中位数，以产生任意精确的估计。

他们的工作已经表明，计算 `p ≤ 2` 时的 `F[p]` 与 `p > 2` 时的 `F[p]` 在内存需求上存在突发性差异。经过一长系列论文的研究，文献 [141] 证明了，考虑相对近似：

*   对于 `p ≤ 2`，`F[p]` 可以在数据流中使用 `O(ε^(−2) (log t + log m) ln(1/δ))` 比特内存进行近似，且
*   对于 `p > 2`，`F[p]` 可以在数据流中使用 `Ω(m^(1−2/p) / (ε² log m))` 比特内存进行近似。

忽略对数因子，其中 `t` 是流的长度，`m = |I|` 是项目集合的大小。此外，对于除 0 和 1 以外的每个 `p`，该数量级的内存实际上是*必要*的。后续工作也基本消除了对数间隙。特别是，对于 `F[∞]` 或最大频率，需要流长度级别的线性内存。请注意，对于特殊情况 `p = 0` 和 `p = 1`，我们在前几节中给出的算法使用的内存是 `O(log log t)`，而不是 `O(log t)`。

### 4.7 滑动窗口的指数直方图

通常，流中较新的项目对于分析应被视为更重要。我们将在第 5 章中通过几种方式对这一想法进行建模，但这里我们考虑最简单的模型，即*滑动窗口*：在任何时候，我们只认为最后接收到的 `W` 个项目是相关的，其中 `W` 是窗口大小；所有之前的项目都是无关的。或者，我们固定一个时间持续时间 `T`（如一周、一小时或一分钟），并且只考虑从现在起时间 `T` 内到达的项目。我们将主要考虑第一种模型，但适应第二种模型也很容易。

考虑在实数流中维护最后 `W` 个值的和这一问题。自然的解决方案是使用大小为 `W` 的循环缓冲区；每个到达的元素都加到总和中；它将最旧的元素从缓冲区中逐出，并从总和中减去该元素。该方案具有常数更新时间，但使用内存 `W`。事实上，可以证明任何*精确*解决此问题的流算法必须使用至少 `W` 的内存。

接下来我们将看到一种仅存储 `O(log W)` 个值来维护和的*近似*值的方法。Datar 等人 [83] 提出的*指数直方图*草图维护实数滑动窗口上聚合函数的近似值。我们仅详细描述聚合函数为求和且项目为比特的情况。

该草图将长度为 `W` 的窗口划分为一系列子窗口，并用一个*桶*表示每个子窗口。直观上，桶编码了大小为 `W` 的所需窗口，其中较旧的 1 以越来越低的分辨率表示。每个桶有一个*容量*，它是 2 的幂，并表示一个包含与其容量一样多的 1 的子窗口。它包含一个整数值，即*时间戳*，这是它所代表的子窗口中最近的 1 的时间戳。对于参数 `k > 1`，有 `k` 个容量为 1 的桶，由最近的 `k` 个 1 界定；`k` 个容量为 2 的桶；`k` 个容量为 4 的桶；依此类推，直到容量为 `2^(m)` 的 `k` 个桶，其中 `m` 是确保有足够桶来容纳 `W` 个项目的最小值，即

```
m ≃ log(W/k)
```

注意 `m ≃ log(W/k)`，因此共有 `km ≃ k log(W/k)` 个桶。

该方法的伪代码见图 4.11，将滑动窗口划分为桶的示例见图 4.10。该示例展示了在某一时刻 `t`，流的最后 29 个比特如何划分为 6 个桶，其中 `k = 2`。每个桶包含的 1 的数量等于其容量。最近的比特在右侧，时间戳为 `t`。最旧的比特在左侧，时间戳为 `t − 28`。每个桶的时间戳是其最近的 1 的时间戳。如果所需的滑动窗口大小 `W` 为 25，则最近 `W` 个比特中 1 的真实计数为 11，因为时间戳在 `t − 24` 和 `t` 之间的 1 有 11 个。草图将报告窗口的和为 12：所有桶中 1 的总数（14），减去最旧桶容量的一半（2）。因此相对误差为 `(12 − 11)/11 ≃ 9%`。

近似中的误差仅由最旧的桶引入。它必须至少包含一个时间戳大于 `t − W` 的 1，否则它就会被丢弃，但也可能包含多达 `2^(m) − 1` 个时间戳至多为 `t − W` 且不应被精确方法计数的 1。因此相对误差至多为最旧桶容量的一半除以所有桶的容量之和。由于经过短暂的过渡期后，除最大桶外，每种大小的桶都有 `k − 1` 或 `k` 个，因此相对误差至多为 `(2^(m)/2)/(2^(m) + (k − 1)(2^(m−1) + ⋯ + 1)) ≃ 1/2k`。

如果期望的近似率为 `𝜖`，则设置 `k = 1/2𝜖` 即可。桶的数量则为 `(log W)/2𝜖`。每个桶包含一个时间戳，原则上这是一个无界数。然而，我们可以通过对 `W` 取模计数，将时间戳缩减到区间 `0…W − 1`，因此一个时间戳有 `log W` 位，总共需要 `O((log W)²/𝜖)` 位内存。如果桶更新的级联影响所有桶，最坏情况下更新时间为 `O(log W)`，但这种情况很少发生；摊还时间为 `O(1)`。一种称为*确定性波*的指数直方图变体实现了最坏情况 `O(1)` 时间 [122]。

该草图可以通过将内存乘以 `log B` 来适应范围 `[0, B]` 内的非负数，也可以维护其他聚合的近似值，如方差、最大值、最小值、不同元素数量和直方图 [83]。

### 4.8 分布式草图：可合并性

到目前为止讨论的大多数草图都具有称为*可合并性*的属性，这使它们适合分布式计算。如果一种草图类型是*可合并的*，则意味着从数据流 `D[1]` 和 `D[2]` 构建的两个草图可以高效地合并为同类型的另一个草图，该草图能正确回答关于 `D[1]` 和 `D[2]` 交织的查询。请注意，对于仅依赖项目频率的问题，所有流交织的答案都是相同的。对于其他问题，可合并性的定义可能更复杂。

作为一个简单的例子，考虑一个由计算流中项目数量的整数组成的“草图”。现在我们从两个流构建两个这样的草图。如果我们将它们的值相加，结果正确地是将原始两个流合并后得到的任何流中的项目数量。

不那么平凡的是，取 OR 运算是线性计数器的正确合并操作。对于 Cohen 和 Flajolet-Martin 计数器及其变体，取其存储值的最小值（如果我们使用多个副本以减少方差，则逐分量取最小值）。对于 CM-sketch，将两个计数器数组逐分量相加。在这些情况下，待合并的两个草图必须使用相同的哈希函数。SPACESAVING 和指数直方图的情况留作练习。

可合并性允许按如下方式进行分布式处理：假设我们有 `k` 个不同的计算节点，每个节点接收不同的流——或者等价地接收一个大型分布式流的某一部分。想要为这个大型隐式流构建草图的中心节点可以定期请求 `k` 个节点发送它们的草图，并将它们合并到自己的全局草图中。

对于 Morris 计数器，Cohen（[75] 第 7 节）提出了一种合并方法；它不像上述方法那样平凡，特别是正确性分析方面。

#### 4.9.1 哈希函数

但认为 *h*(*x*[*i*]) 每次调用都生成一个新的随机值是不正确的——它必须始终在相同输入上返回相同的值。因此它是随机的，但可复现地随机。要创建这样的 *h*，我们可以为每个 *x*[*i*] ∈ *I* 随机猜测并存储 *h*(*x*[*i*]) 的值，但存储 *h* 将使用与 |*I*|log |*B*| 成比例的内存，这违背了使用远低于 |*I*| 内存的目标。

当 |*I*| 是某个素数 *p* 时，这里有一个成对独立哈希函数族的简单构造。将 *I* 视为区间 \[0…*p* − 1\]。族中的函数 *h* 由 \[0…*p* − 1\] 中的两个值 *a* 和 *b* 定义，并计算 *h*(*x*) = (*ax* + *b*) mod *p*。注意，这样一个函数由 *a* 和 *b* 描述，因此用 2log *p* 位。这个族是成对独立的，因为给定 *x*、*y* 和值 *h*(*y*)，对于每个可能的值 *h*(*x*)，方程组 {*h*(*x*) = *ax* + *b*, *h*(*y*) = *ay* + *b*} 都有唯一解 (*a*, *b*)，所以 *h*(*x*) 的所有值等可能。然而请注意，如果我们知道 *x*、*y*、*h*(*x*) 和 *h*(*y*)，我们可以唯一地求解 *a*、*b*，从而知道对于其他每个输入 *z* 的值 *h*(*z*)。如果 |*I*| 是素数幂 *p*^(*b*)，我们可以通过在大小为 *p*^(*b*) 的有限域中运算来推广这个构造；请注意这*不*等同于模 *p*^(*b*) 运算。我们也可以选择一个略大于 |*I*| 的素数，得到仅在边缘上偏离成对独立性的函数。

成对独立函数足以用于 CM-sketch。矩估计算法需要一种称为 4-wise independence 的推广。对于其他算法，如 HyperLogLog，据我们所知，*k*\-wise independence 无法被正式证明为足够。然而，尽管不存在正式保证，著名的哈希函数如 `MD5`、`SHA1`、`SHA256` 和 `Murmur3` 在实践中似乎没有问题 [104, 134]。文献 [71] 提出了理论论据，解释为什么简单的哈希函数在草图等数据结构问题上可能表现良好。

#### 4.9.2 创建 (𝜖, *δ*)-近似算法

设 *f* 为待近似的函数，*g* 为随机算法，使得对所有 *x* 有 E\[*g*(*x*)\] = *f*(*x*)，且 Var(*g*(*x*)) = *σ*²。运行 *k* 个独立的 *g* 副本，记为 *g*[1], …, *g*[*k*]，通过平均它们的输出来组合，结果记为 *h*。我们有 E\[*h*(*x*)\] = *f*(*x*)，且由方差的简单性质，Var(|*f*(*x*) − *h*(*x*)|) ≤ Var(*f*(*x*) − *h*(*x*)) = Var(*h*(*x*)) = *σ*²/*k*。然后由切比雪夫不等式，对于每个 𝜖，有 |*f*(*x*) − *h*(*x*)| > 𝜖 的概率至多为 *σ*²/(*k*𝜖²)。这意味着如果我们选择 *k* = *σ*²/(𝜖²*δ*)，则 *h* 是 *f* 的 (𝜖, *δ*)-近似。*h* 的内存和更新时间是 *g* 的 *k* 倍。

通常为了达到精度 𝜖，需要 *σ*²/𝜖² 形式的依赖关系，但 1/*δ* 形式的依赖关系可以按如下方式改进：使用上述方法达到固定置信度，例如 (𝜖, 1/6)-近似。然后运行该固定置信度算法的 *ℓ* 个副本并取结果的*中位数*。使用霍夫丁不等式可以证明，如果取 *ℓ* = *O*(ln(1/*δ*))，则新算法是 (𝜖, *δ*)-近似；见练习 4.9。因此最终算法使用的内存和运行时间是原始算法 *g* 的 *k* · *ℓ* = *O*((*σ*²/𝜖²) ln(1/*δ*)) 倍。

这种转换已经存在于 Alon 等人 [14] 关于流上矩估计的开创性论文中。

本章展示的草图是因其在流挖掘和数据流学习中的潜在用途而选取的。数据流上还提出了许多其他算法问题，例如解决组合问题、几何问题和图问题。此外，我们的展示中省略了小波、低维嵌入和压缩感知等深度算法技术的流式变体。近期的综合参考文献包括 [79, 172]。
