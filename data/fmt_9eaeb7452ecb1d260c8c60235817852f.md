
尽管最初的 DNS 服务未作任何安全规定，但很快人们就发现它包含多个可被利用的漏洞。为缓解这些漏洞，开发了一套 `DNS 安全扩展` (`DNSSEC`) 来保护 DNS 记录。这些扩展基于一个称为 `区域签名` 的过程，即将扩展添加到 DNS 协议中，以提供来源授权、数据完整性和经过认证的不存在证明。这使得 DNS 攻击（如 DNS 欺骗）难以实施得多。

然而，恶意软件可利用 DNS 流量创建 DoS 攻击、执行命令与控制功能、从网络中窃取数据并执行 `DNS 隧道`。在将 OT 网络和 IT 网络相互隔离时，许多管理员并不禁止 DNS 流量。这使得 `DNS 隧道` 可被用于利用 DNS 查询和响应（针对属于攻击者的域名）向网络内外发送数据。据估计，超过 90% 的恶意软件依赖 DNS 来渗透和利用目标。

虽然拒绝 OT 网络的所有 DNS 流量是缓解 DNS 相关风险最彻底的解决方案，但在某些情况下需要本地 DNS。在这些情况下，应将 DNS 配置为拒绝涉及外部域的 DNS 请求。

另一方面，DNS 数据记录工作可用于分析模式并识别网络中的异常。这些技术在保护以极不安全著称的 SCADA 系统方面特别有帮助：其固件通常不安全，且其通信协议往往缺乏认证和加密组件。但所有连接 SCADA 的设备都必须拥有 IP 地址，这使得它们可以通过 DNS 过程进行监控。面向客户端的 DNS 防火墙/安全设备可用于监控活动、破坏攻击，并为基于 SCADA 的 OT 网络提供弹性。

## 拒绝服务

`拒绝服务` (`DoS`) `攻击` 是旨在过度使用主机、服务器或网络资源，以使其功能上停止提供服务的攻击。拒绝服务攻击如图 5.20 所示。视攻击的确切性质而定，故障可能是暂时的，也可能是无限期的。`分布式拒绝服务` (`DDoS`) `攻击` 涉及使用多个远程系统同时对目标资源发起攻击。

### DoS 攻击与 DDoS 攻击

DoS 和 DDoS 攻击特别令人头疼，因为它们非常容易实施，且没有办法完全使网络免疫于这些攻击。

最常见的 DoS 攻击类型涉及 `洪水攻击`，即用异常大量的"垃圾"外部通信请求（如 `ping` 命令生成的流量）淹没或过载目标服务器或其他网络资源。所有这些垃圾请求要么会将目标的响应速度拖慢到无法使用的地步，要么会阻止资源响应合法的网络流量资源请求。

DoS 攻击针对的实际资源可以是特定目标系统、该系统上的一个端口、计算机网络中的特定组件，或整个网络。DoS 攻击也可以设计为执行恶意软件，耗尽处理器等系统资源，这迟早会使任何系统瘫痪。DoS 攻击的最终目标是迫使系统不再像攻击前那样响应合法请求，无论服务是被严重限制还是完全拒绝。

大多数 DoS 攻击成本低廉且难以防御。由于其有效性，它们是脚本小子和技术熟练的黑客青睐的攻击类型。DoS 攻击经常源于对另一个个人或组织怀有怨恨的个人或组织。

## DoS 和 DDoS 攻击示例

一个典型的例子是黑客组织 Anonymous 据称在 2011 年对索尼发起的 DoS 攻击，导致索尼 PlayStation Network 服务中断一个月。2014 年，他们又遭遇了一次大规模 DoS 攻击，黑客组织 Lizard Squad 和 FamedGod 声称对关闭其 PlayStation 和索尼娱乐网络负责。该攻击由网络时间协议（NTP）放大发起，产生的网络流量高达 263.35 Gb/s。

### 泪滴攻击

*泪滴攻击*是一种 DoS 攻击，向目标系统发送畸形（分片）数据包。旧版操作系统的 TCP/IP 重组机制存在漏洞，导致分片数据包重叠并使主机崩溃。在任何合理的近期操作系统版本或发行版中，此问题均已解决。

### Mirai 僵尸网络攻击

最著名的 DDoS 攻击之一是利用 Mirai 僵尸网络针对全球许多最热门网站发起的。Mirai 僵尸程序旨在搜寻并感染互联网上成千上万个安装不安全的物联网设备，类型涵盖智能恒温器、安全摄像头和其他智能家居设备，以及视频游戏控制器。Mirai 软件检查这些设备，寻找制造商默认的用户名/密码组合以获取访问权限。

一旦在僵尸设备上建立了控制权，攻击者只需等待，便可针对目标发起 DDoS 攻击——目标是一个名为 Dyn 的组织，它是为 Twitter、Netflix、GitHub、HBO、Reddit、PayPal 和 Airbnb 等网站提供 DNS 服务的 ISP 和域名服务商。这是一场多向量攻击，涉及来自 600,000 多台受感染设备的协调流量，产生的流量速率超过 1 Tb/s。攻击持续了七天。

规模更大、时间更近的 DDoS 攻击瞄准了亚马逊云科技（AWS）和 Google Cloud Services 等知名高层组织。2020 年的 AWS 攻击持续了三天，流量速率达到 2.3 Tb/s。攻击目标是运行易受攻击的连接技术的 AWS 第三方客户。Google Cloud 攻击的网络流量峰值达到 2.5 Tb/s，持续了三天。

## 拒绝视图攻击

*拒绝视图攻击*，也称为*视图丢失*（*LOV*）事件，会造成操作员无法了解其处理系统或其某个组件的实际状态。在 DOV 攻击中，目的是导致操作员（或控制程序）采取不适当或潜在破坏性的行动。例如，如果攻击者将蠕虫引入系统以感染 HMI，导致操作员无法看到进程操作，则必须关闭进程、排查视图丢失问题，并将控制系统恢复运行。在美国，核电站曾发生此类事件，导致其停止生产，直到全面恢复控制后才能重新启动。

一种称为*视图操纵*（*MOV*）的类似事件并不隐藏进程状态，而是故意错误地表示它。同样，其意图是导致操作员或控制器采取不适当或危险的行动。例如，如果化学过程上的温度传感器被攻破，并向 SCADA 系统提供了不准确的值，操作员（或控制器）可能会尝试将温度调整到一个实际上不安全的值。这类活动的效果是使操作员或控制器成为控制场景中的实际攻击向量。

此类攻击也可针对 SCADA 系统的控制端发起。*拒绝控制*（*DOC*）和*控制丢失*（*LOC*）攻击或事件阻止操作员或控制器对关键系统采取纠正措施，从而失去对进程的控制。这些事件可能由网络攻击、组件故障或操作员活动引起。

## Ping 洪水攻击

*Ping 洪水攻击*是最简单的 DoS 攻击之一。它利用一种名为 *ICMP* 的网络协议，该协议常用于测试从设备到网络的连通性。*Ping* 和用于 IPv6 主机的 *ping6* 在许多操作系统中作为命令行工具提供，各种软件产品也提供此功能，通常与 traceroute 功能打包在一起。

在日常生活中，你可以使用 `ping` 命令向目标 IP 地址发送 *ICMP 回显请求*。如果收到来自目标地址的回复，你可以放心地假设你能够在网络上通信。不过，这是一个宽泛的假设，并不总是成立。

Ping 可以很好地判断主机是否存活，以及你的网络与主机之间的连接质量。然而，ICMP 流量通常被视为低优先级流量，因此繁忙的网络可能会忽略它。

Ping 有一些可用选项，例如调整数据包大小或不等待回复直接发送，这些可用于制造 *Ping 洪水*，导致 DoS 状况。这种 Ping 洪水肯定会消耗入站带宽。然而，如果网络回复 ICMP 请求，则出站带宽也会被消耗。

Ping 洪水攻击通过大量 ICMP 回显请求淹没受害者来实现。攻击者将发送启用了 flood 选项的 ping，这允许攻击者的网卡在发送另一个回显请求前无需等待受害者的回复。受害者的带宽随即被回显请求淹没，受害者尝试进行响应。理想情况下，入站和出站洪水流量的结合将破坏带宽并导致网络连接问题。

遗憾的是，也有可能恶意发送畸形的 ping 数据包。例如，旧系统无法处理大于 65,535 字节的数据包，任何超过该大小的数据包都会导致计算机崩溃。现代路由器应检查这些数据包的大小和分片，并强制执行规则，防止“死亡之 Ping”引发任何问题。

由于可能会用 ping 请求淹没网络，ICMP 流量通常会被阻断。大多数防火墙设备可用于完全阻断此类流量。虽然在公共网络上通常允许 ICMP 流量是良好的做法，但出于多种原因，防火墙阻断本地网络的 ICMP 流量至关重要。事实上，对于大多数网络而言，将防火墙设置为不回复这些请求可能更为可取。

有许多工具可用于发起 ping 洪水攻击。其中之一是 `Low Orbit Ion Cannon (LOIC)`，这是一种基于 GUI 的工具，用于向指定目标发起非常有效的 ping 洪水攻击。该工具通常会被主机上的防病毒程序阻止，安装它需要设置豁免。

### Smurf 攻击

**Smurf 攻击**是一种用 ICMP 数据包淹没网络的 DDoS 攻击。这种攻击在 ping 洪水攻击的基础上增加了反射特性。这种反射特性是通过在攻击中利用更多参与者（称为 **Smurf 放大器**）来创建的。

攻击者通过获取发送者地址（最初是攻击者的地址）并将其设定为受害者的地址来伪造一个 ping 请求数据包，如图 5.23 所示。然后，攻击者将目标地址更改为网络的广播地址。

![FIGURE 5.23 Smurf amplification](img/c05f023.png)

**图 5.23** Smurf 放大

当攻击者发送 ping 请求时，网络上能够响应 ping 请求的 Smurf 放大器将使用受害者的 IP 地址作为目标地址进行回复。由于许多设备都在向受害者回复，受害者会被流量淹没，从而几乎瘫痪。

ICMP 隧道也可用于传递恶意数据包。此处的最佳防御是配置网络设备不响应 ICMP 回显请求。另一种选择是直接阻断所有 ICMP 流量以及入站广播流量。

### UDP 洪水攻击

**UDP 洪水攻击**是一种类似于 ping 洪水攻击的 DoS 攻击，它使用 **用户数据报协议 (UDP) 数据包**。由于 UDP 是无连接的，且缺乏 TCP 那样的错误检查能力，因此它不具备 TCP 的三次握手过程。

在这种攻击中，攻击者会向受害者的随机端口发送大量 UDP 数据包。由于这些数据包被发送到特定端口，受害者必须检查是否真的有应用程序在监听这些端口。

当受害者发现没有程序在监听时，它将回复一个 ICMP 目标不可达数据包。在这种情况下，受害者将难以发回所有 ICMP 数据包，任何其他试图连接受害者的尝试都将被拒绝。此外，攻击者很可能会欺骗用于发送 UDP 数据包的 IP 地址以避免被发现。

**Fraggle 攻击**在概念和缓解措施上与 Smurf 攻击类似，只是它使用 UDP 数据包代替 ICMP。

### SYN 洪水攻击

**SYN 洪水攻击**是一种拒绝服务攻击形式，攻击者利用使用 SYN 和 ACK 消息建立两个主机间可靠连接的 TCP 握手过程。与 UDP 可以丢弃数据包而无需任何错误纠正不同，TCP 使用三次握手来确保消息被正确可靠地发送，如图 5.24 所示。

![FIGURE 5.24 SYN flooding](img/c05f024.png)

**图 5.24** SYN 洪水

三次握手的工作原理如下：

1.  客户端希望在自己和服务器之间建立连接。它向服务器发送一个 SYN 消息。

2.  服务器收到消息并回送一个 SYN 确认，表示为 SYN-ACK。

3.  客户端随后通过向服务器发送一个 ACK 消息来响应 SYN 确认。

在 SYN 洪水攻击中，攻击者利用三次握手过程。攻击者将向服务器发送大量 SYN 消息，每秒几十个甚至上百个。服务器试图跟上节奏并回送 SYN-ACK 消息给攻击者，但攻击者从不回复 ACK 消息。随后，当合法客户端想要连接服务器时，他们无法做到，因为服务器被 SYN 消息淹没，无法回复。

因为这也可能看起来像网络拥塞，服务器通常会等待一小段时间再响应，希望拥塞能缓解。真正的恶意攻击将继续耗尽服务器资源，拒绝为其他客户提供服务。此时某些服务器可能会发生故障甚至崩溃。

根据所涉及的操作系统，有针对 SYN 洪水的有效对策。处理 SYN 洪水的一种方法是使用 **计算序列号** 而不是 **状态表**。不幸的是，这种计算可能非常消耗 CPU，因此这种技术通常涉及实施专用负载均衡器或专门设计用于处理 DoS 攻击的网络设备。

现代防火墙也可以通过丢弃半开连接在一定程度上应对 SYN 洪水。然而，大流量的 SYN 洪水通常仍会对网络性能产生明显影响。

## 数据操纵攻击

并非所有攻击都旨在窃取数据；有些仅旨在操纵数据以降低其完整性。许多网络安全专家认为 **数据操纵** 比传统的数据窃取或物理基础设施攻击是一个更大的问题。这类攻击破坏了组织、客户和政府对其所掌握数据的信心。最终结果是无法基于态势感知数据做出明智的商业决策或军事决策。

例如，Stuxnet 攻击的主要手段基于数据操纵而非窃取。该攻击篡改了伊朗离心机的运行速度数据，导致操作员不知道其系统的真实速度。因此，他们根本不知道离心机面临毁坏的危险。

随着物联网 (IoT) 和工业物联网 (IIoT) 市场在生活的方方面面（包括工业加工和公用事业运营）持续增长，基于数据操纵的攻击机会呈指数级增长。这包括传感器网络、住宅恒温器、胰岛素泵、交换设备等。

因为数据操纵攻击是隐蔽的、有针对性的攻击，且发生在前面描述的网络链的多个环节中，所以组织协调其网络安全工具以检测、调查和缓解网络中覆盖数据的企图非常重要。

### 中间人攻击

在中间人攻击中，攻击者监控网络，并根据预期攻击的性质执行不同活动。一种可能是攻击者使用 ARP 欺骗拦截本应发送给路由器的流量。当受害设备发出广播帧时，如图 5.28 所示，攻击者接收该帧并回送自己的信息，导致受害者误以为攻击者才是信息的真实目的地。

当受害者将信息发送给其预期目的地时，攻击者会接收并收集该信息，随后要么将其转发给真实目的地（这也是其被称为“中间人”的原因），要么回送虚假信息。

![FIGURE 5.28 Man-in-the-middle attack](img/c05f028.png)

**图 5.28** 中间人攻击

从道德黑客的角度来看，中间人攻击可产出大量信息，因为此类攻击可收集并重定向数据。例如，*Linux 社会工程学工具包* *(SET)* 可用于复制一个网站，以协助收集访问该网站用户的凭证。SET 是 Kali Linux 中的预装工具，也可从 `https://github.com/trustedsec/social-engineer-toolkit` 下载。也可在 Microsoft Windows 机器上安装 SET 工具。

如果用户看到的似乎是他们打算登录的网站并输入了凭证，该虚假网站通常会将他们重定向到真实的登录页面。通常，用户会认为自己凭证输入有误，最终登录到真实网站。

与此同时，中间人已从虚假网站收集了他们的凭证，并利用这些凭证登录真实网站，破坏用户账户。使用 HTTPS 将提供安全通信通道，使攻击者无法收集用户凭证。尽管现代浏览器会在用户即将连接到 HTTP 网站时发出警报，但仍应培训用户留意识别 HTTPS 而非 HTTP。

*中间人* *(MITM)* 攻击，或*消防队攻击*，是一种会话劫持类型，涉及拦截或嗅探并修改用户间的通信。可将其视为一种网络窃听形式。因此，攻击者通常与其他双方处于同一网络或广播域中，并将代理双方通信，在此过程中插入或篡改数据。在 SSL 连接中，攻击者可能使用 ARP 欺骗将流量引向攻击者，而非正常的网络路由器。

## 外来软件

你的软件里藏着什么？在生产软件中隐藏恶意内容的想法并不新鲜。你不难想象，商业软件公司可能提供掺杂了高级恶意软件的安全软件，这些恶意软件设计为在特定时间点激活。当然，该软件公司早已准备好恶意软件的“解药”，一旦其淹没安装了该软件的人员、企业和政府机构，便立即上市销售。

你也不难想象，政府和民族国家会与其本地软件生产商合作，在其商业产品中植入恶意软件。恶意软件可能潜伏不确定的时间，等待该政府的指令以执行攻击。
