
# 智能传感器与执行器

无需人工干预即可运行的传感器称为智能传感器。传感器可以集成到计算机中，也可以是独立传感器，或者是可穿戴传感器。例如，健身手表具有跟踪心率的传感器（Sankar and Srinivasan, 2018d）。这些传感器与所有智能设备协作以满足应用需求（Astill et al., 2020; Sankar and Srinivasan, 2017; Sennan et al. 2020a; Sankar et al., 2020c）。

## 3.3.1.3 智能执行器

无需人工干预即可基于感知数据自动工作的物理机器称为智能执行器。它能使任何应用更加高效，减少员工数量，并节省成本。工业 4.0 基于智能执行器，整个生产工厂的设计采用可消除人工操作的机器。

## 3.3.2 连接层

### 3.3.2.1 通信

通过增强功能，电子设备变得更智能。物联网推出了其无线通信标准。物联网的核心在于将应用与网络连接相结合以共享数据。通信协议内置于系统中，用于指导数据交换格式、编码、寻址和路由，同时保持序列控制和流控制。它还为丢失数据的重传提供了灵活性。电气和电子工程师协会 (IEEE) 制定了无线局域网 (WLAN) 802.11 标准 (Mishra et al., 2020)。

### 3.3.2.2 IEEE 802.11 标准 – WiFi

无线保真 是一种 WLAN。IEEE 802.11 有不同版本，如 a、b、d、e 等。它是一组 WLAN，支持媒体访问控制 (MAC) 和最底层的物理层规范。它提供 20 至 110 米的最小覆盖范围。它使用正交 FDM（频分复用）。WiFi 路由器大约在 2.3 GHz 和 4 GHz 频段上运行。802.11g 标准的室内范围为 125 英尺，802.11n 标准为 235 英尺 (Karthiprem et al., 2015; Sankar and Srinivasan, 2016)。

### 3.3.2.3 IEEE 802.16 标准 – Wi-Max

微波接入全球无缝互操作 是一种固定、便携且高速的互联网接入技术。它建立在一组 IEEE 802.16 标准之上。它在硬件层 (PHY) 和 MAC 层提供多种选项。无线城域网 (WMAN) 通过非授权频段连接到授权频段，如 900 MHz、2.4 和 5.8 GHz、700 MHz、2.5 至 3.6 GHz。这是通过正交 FDM（频分复用）实现的。表 3.1 列出了不同协议标准的范围、数据速率和频段。

### 3.3.2.4 IEEE 802.15.4 标准 – 低速率 – WPAN

IEEE 802.15.4 描述了称为 LR-WPANs 的低速率无线个域网 (Personal Area Networks) 的应用，并管理 IEEE 802.15 工作组。该协议以较低的功耗和存储连接数百万设备。这些通常用于智慧城市和家庭自动化。

### 3.3.2.5 2G/3G/4G/5G (未来展望)

电信标准的进步经历了蜂窝区域网的各个代际演进。第二代包含全球移动通信系统 (GSM) 和码分多址 (CDMA)。第三代包含通用移动电话系统 (UMTS) 和 CDMA2000。由于 4G、4.5G、4.75G（包括 LTE）提供更好的覆盖，这些技术不太可能被终端用户使用。4G 的数据速率范围从 100 Mbps 开始。预计 5G 未来将大规模部署。

### 3.3.2.6 IEEE 802.15.1 标准 – 蓝牙

蓝牙是一种由 IEEE 802.15.1 标准开发的无线设备。它支持 PAN。它提供约 10 米的极短距离通信，并提供约 1 至 3 Mbps 的相对较低带宽。大多数低功耗手持设备可在此网络中运行。

### 3.3.2.7 LoRaWAN R1.0 – 长距离

LoRa (Long Range) 是一种采用扩频技术的调制技术，具有长效电池寿命，工作在 868 和 900 MHz ISM 频段。ISM 无线电频段在全球范围内保留供工业、科学和医疗 (ISM) 用途。数据速率约为 0.2 至 55 kb/s。LoRa 部署于智能供应链、智能物流等领域。它保证了不同运营商之间的互操作性。

### 3.3.2.8 光保真 – LiFi 技术

光保真 是一种通过可见光通信 (VLC) 提供无线高速数据的技术。它配合发光二极管 (LED) 工作，可最大限度地降低能耗。由于光信号干扰，其效率受到限制。因此它应用于容错应用中。

### 3.3.2.9 软件定义网络 (SDN)

SDN 是一种灵活、稳定、可适应且具有成本效益的网络架构。基于 SDN 的受保护物联网架构使用协议来控制和管理物联网设备、资源和网络实体，如交换机和路由器。SDN 为物联网设备提供认证和授权服务 (Bera et al., 2017)。

### 3.3.2.10 区块链

物联网将数据发送至私有区块链账户，以便在公共交易中插入防篡改记录。IBM 区块链即为一例。它使企业客户能够在无需中央管理和监控的情况下控制和分发物联网数据。每份协议都应经过检查以防止冲突，并确保每位合作伙伴对其立场负责。用于人与机器之间价值和数据交换的第一个分布式账本是 IOTA，它是“万物互联网” (Zheng et al., 2018)。

### 3.3.2.11 新标准

ETSI (欧洲电信标准协会) 是一个服务于欧洲和全球商业需求的通信技术领域自主、非营利的标准化机构。总部位于法国索菲亚-安提波利斯。ETSI 促进面向 ICT 系统、软件和服务的全球适用技术标准的开发和测试，这些标准广泛应用于商业和社会的所有领域。

## 3.3.3 全球基础设施层

全球基础设施层是第三层。每当部署节点时，提供的中心化服务应提升性能。考虑到性能参数，部署在云和雾中进行。每当节点距离云基础设施太远时，可考虑雾计算。

### 3.3.3.1 云与雾

物联网应用通常在云基础设施上运行。大多数物联网系统与云提供商集成。物联网云作为一系列数字工具，可为公司提供有价值的数据和客户洞察。云技术因使用传感器的实施而受青睐。位于不同位置的传感器将数据发送到中心化云端进行处理。云具有通用性，因为它是按需基础设施。Kaa 和 DeviceHive 等云提供商支持物联网即服务平台 (PaaS)。物联网服务提供商使用基础设施即服务 (IaaS) 从客户处获取软件即服务 (SaaS)。雾计算有助于在传输数据时降低延迟，提高可扩展性。如果终端用户距离云太远，则可优先选择雾计算来扩展服务，因为它感知位置和服务分布。它能够连接大量设备，同时保持移动性 (Osanaiye et al., 2017)。

### 3.3.3.2 数据交换协议

为了管理大型网络产生的海量数据，需要一种技术来高效管理传输给接收端的数据。物联网拥有应用层协议来完成这种管理。要交换数据，节点必须注册为网络的成员；这个过程称为订阅。一旦节点完成订阅，发布者就可以获取与服务相关的数据；当数据发布时，这被称为发布/订阅过程。当部署大量节点时，这种方式很合适。对于极少量的节点，可以执行请求/响应过程。在此过程中，汇聚节点通常会显式请求与服务相关的信息，并获得包含所请求数据的响应。当节点进入系统时，它会分配网络服务，并且还可以开始交换数据并作为物联网系统组件发挥作用。表 3.2 列出了物联网数据交换协议、部署平台及所提供的安全类型（Sankar and Srinivasan, 2016）。

| --- | --- | --- | --- | --- | --- | --- | --- |

### 3.3.3.3 受限应用协议

IETF 设计了 CoAP，这是一种用于在受限环境（如较低的 RAM 容量和丢包网络）中工作的协议。它专门设计用于在无线个域网上运行并使用低功耗 (WPAN)。它是一种基于 Web 的协议，具有 HTTP 接口。它允许机器到机器应用的自动化。它采用客户端-服务器模型，客户端发起请求，服务器进行响应。即使对于大量用户，它也能提供良好的性能。它提供组播通信，消息发送给发布者，订阅者接收消息。

CoAP 是一种可靠且简单的协议，包含两层。顶层由 UDP 构建，称为消息层。另一层称为请求/响应层。它通过请求/响应消息提供可靠通信。图 3.2 显示了 CoAP 消息格式，图 3.3 显示了 CoAP 的客户端-服务器架构，其中交互通过 REST API 进行。CoAP 通过 UDP 传输。它采用固定大小的二进制消息格式。它包含选项和负载。消息支持可确认、非可确认、确认和重置。数据报传输层安全 (DTLS) 用作安全协议。它提供高带宽，因此连接到它的设备是可靠的。

### 3.3.3.4 消息队列遥测传输协议

MQTT 由 IBM 设计，旨在减少带宽消耗并实现可靠的数据包传输。它通过最小化流量来减少网络协议开销。MQTT 通过支持低功耗设备、组播和发布者/订阅者架构，与 CoAP 相似。它构建在 TCP/IP 模型之上。可靠传输通过三个服务质量 (QoS) 级别来考量，即至多一次、至少一次和恰好一次。最低级别是至少传输一个数据包，无需确认。中间级别支持确认，但可能有重复消息。为了仅传输一次消息并带有确认，应使用特殊协议以达到最高 QoS 级别。图 3.4 显示了 MQTT 代理架构。图 3.4 中的传感器节点可以是温度传感器、湿度传感器等。传感器节点收集的数据发布到 MQTT 代理，而不是直接发送给设备。代理将数据发布给已订阅的设备。因此，大量数据可以通过 MQTT 代理进行监控和控制。

### 3.3.3.5 可扩展消息与 Presence 协议

最常见的通信协议是可扩展消息与 Presence 协议 (XMPP)。其可扩展特性允许根据功能定制协议。它是一种轻量级协议，用于许多实时应用，如多方聊天、即时消息、语音通话、视频通话等。它使用传输控制协议 (TCP)。它具有高度灵活性，并采用去中心化架构实现可扩展性。发布者和订阅者启用事件通知，并作为社交网络、即时新闻推送和许多其他实时交互的基础。图 3.5 表明 XMPP 客户端不直接与另一个客户端交互，而是通过 XMPP 服务器进行交互。每个客户端由一个称为 Jabber ID (JID) 的唯一 ID 标识。它由用户、服务器和资源组成。例如，如果用户访问 Facebook，则 JID 中的“用户”是“Facebook 账号”，“服务器”代表“Facebook 服务器”，资源代表访问应用程序的“移动端/桌面端”。

### 3.3.3.6 高级消息队列协议

AMQP 是一种开源的异步消息传递标准。它允许应用程序和组织之间进行安全且互操作的通信。该协议用于客户端/服务器通信和物联网应用的管理。它可靠、紧凑、安全且多通道。二进制协议提供 SASL 或 TLS 认证和加密，依赖于 TCP 等传输协议。

该消息传递协议速度快，具有确保投递并确认消息接收的特性。它由一个庞大且简单的组件组成，该组件在代理操作器中记录和存储通信，以及一组用于连接组件的策略。AMQP 协议帮助客户端系统与代理对话并连接到 AMQP 模型。图 3.6 显示了 AMQP 代理将消息从发布者交换给订阅者。代理模型中的队列允许为订阅者提供有保证的服务（Glaroudis et al., 2020）。

## 3.3.4 数据摄入层

数据摄取层是第四层，包括大数据、清洗、流式处理和数据管理。`Apache Flume` 和 `Apache NiFi` 是大数据摄取工具的示例。`Apache Flume` 提供分布式服务。大量数据被收集、聚合并传输，同时保持可靠性。从多个来源收集的数据流被存储并在 `Hadoop` 中进行分析。基于数据流式处理的流向，其架构变得简单。它健壮且具备容错能力，拥有多种故障恢复机制。`Apache NiFi` 是一个易于使用、可靠的系统，广泛用于数据分发和处理。它支持数据流跟踪，为监控和控制提供无缝服务。数据通过 `SSL`、`HTTPS`、`SSH` 加密，因此是安全的。

### 3.3.4.1 存储工具

#### 3.3.4.1.1 Hadoop 分布式文件系统

一种基于 Java 的文件系统，用于大数据的安全存储，称为 `Hadoop 分布式文件系统 (HDFS)`。它具有可扩展性，可服务大型客户，并允许从大型存储库轻松访问。由于数据的多个副本存储在不同的机器上，因此保持了冗余。它采用主/从架构模型，通过划分数据并将其放置在不同的集群中，实现并行处理（Nazini and Sasikala, 2019）。

#### 3.3.4.1.2 Gluster 文件系统

`Gluster 文件系统 (Gluster FS)` 是一个开源、可靠的分布式文件系统，在存储方面提供线性扩展性能。它可部署用于非结构化数据。它具有可扩展性并允许分布式存储。`Gluster FS` 可用于云计算、媒体流和内容分发。

#### 3.3.4.1.3 Amazon 简单存储服务

`Amazon 简单存储服务 (Amazon S3)` 是一种简单的对象存储 Web 服务。它提供最高的持久性，并可大规模扩展。云应用程序使用 `S3` 服务。它允许拥有具备故障恢复能力的大型数据存储库。数据迁移比其他服务更容易。存储在 `S3` 上时，成本相对降低。

## 3.3.5 数据分析

数据分析是第五层，涉及数据调查、提取和机器处理。大多数公司使用大数据分析来提高生产力、收入并降低成本。`Apache Hive`、`Apache Spark SQL`、`Amazon Redshift`、`Presto SQL 查询引擎` 是大数据查询工具的示例（Kamilaris et al., 2017；Samanta et al., 2021；Vinodhini et al., 2020；Karthiprem et al., 2016）。

### 3.3.5.1 Apache Hive

`Apache Hive` 运行在 `Apache Hadoop` 之上。它为分析提供大型数据集，并支持通过临时查询进行汇总。用于 Hive 的 `SQL` 查询称为 `HiveQL`。它具有可扩展性；随着数据增长，会添加许多机器以提升性能。

### 3.3.5.2 Apache Spark SQL

`Apache Spark SQL` 拥有用于结构化数据处理的 Spark 模型。它具有基于成本的优化器。它提供代码生成器以实现快速查询。其可扩展性出奇地高，且具备容错能力。

### 3.3.5.3 Amazon Redshift

`Amazon Redshift` 在云端处理 PB 级数据。它用于查询数据处理。当 `SQL` 运行时，可按需创建数据库。可获取客户和业务洞察。整体管理由 `Redshift` 协调。这些任务包括提供集群算力、监控和备份，以及向 `Amazon Redshift` 系统部署更新和改进。

### 3.3.5.4 Presto – SQL 查询引擎
