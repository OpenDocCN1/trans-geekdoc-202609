
### 6. 保护原始证据

因为你现在有了证据的完美副本，请将原始证据存放在安全的地方，并确保没有人能够访问它。

## 分析

分析是解释提取出的数据以确定其对案件意义的过程。可能执行的分析类型示例包括：时间线（即在什么时候发生了什么）、数据隐藏（即被刻意隐藏的内容）、应用程序和文件（即哪些应用程序访问了哪些文件）以及所有权和占有（即哪些用户账户访问了哪些应用程序和文件）。尽管你使用的特定应用程序和命令可能会根据涉及的操作系统或文件系统而异，但关键问题是相同的。取证分析师最重要的工具之一是时间线。它为比较系统在不同时间点的状态建立了一个框架。例如，你可能怀疑用户可能在上周五通过将文件复制到 U 盘来盗取文件，但直到周一你才在系统上看到该驱动器的注册记录。在没有系统数据和时间被篡改的证据的情况下，你可以得出结论：外泄机制并不是那个 U 盘。时间线仅仅是在系统上执行的操作的有序列表。这些操作可以归类为对感兴趣项的读取、写入、修改和删除操作。我们认识的许多调查员只需在电子表格中跟踪他们的时间线，包含如下所示的列：

- 数据和时间
- 时区
- 源（例如 Windows 注册表或 `syslog`）
- 项目名称（例如注册表项名称或文件名）
- 项目位置（完整路径）
- 描述

**考试提示** 你应该始终对系统时间戳保持适度的怀疑。众所威胁者有时会修改系统时钟来隐藏其操作的真实顺序。这种做法被称为 `timestomping`（时间戳攻击）。

在过程的每一步，你都应该对你采取的每个特定操作记录详细的笔记，精确到你使用的命令和参数。如果你使用如 `EnCase` 或 `FTK` (Forensic Toolkit) 等取证分析套件，工具将为你记录你的操作。尽管如此，在整个调查过程中记录自己的笔记仍然是一种最佳实践。

## 报告

如果你一直在做笔记，那么在进行调查的过程中就已经一直在编写报告的部分内容。一旦你根据可用证据得出了可靠的结论，你只需要汇总叙述性陈述，以易读的方式展示你的论点和结论。像任何形式的通信一样，了解你的受众至关重要。如果报告面向执行领导层，该文档将与你在法庭上提交报告时不同。所有主要的商业套件也具有生成可供你自定义的草稿报告的功能。

### 取证调查套件

取证调查本质本质是极其耗时的。幸运的是，许多软件开发者创建了套件来辅助该过程的许多方面。

### 采集工具

取证调查的采集阶段在确保证据、分析和结论的可采性方面可能是最关键的点。这是你可能希望放慢速度、使用检查清单并确保完全不犯任何错误的地方，因为这样做可能会导致后续的所有工作失效。

### 取证复制器

取证复制器是可以在从源到目标复制数据，同时确保没有任何比特位被更改的系统。它们与任何复制工具的区别在于，它们不依赖于文件系统操作，这意味着它们可以恢复文件系统构件，例如 Windows 中的主文件表 (`MFT`) 和 Linux 中的节点节点表。

### dd

Linux 中资老的苦力是是 `dd` 工具，大多数系统都默认自带它。由于 Linux 使用的扩展文件系统 (`ext`) 中的几乎所有内容都是“文件”，`dd` 可以在文件、设备、分区和卷之间复制数据。以下命令将硬盘 `hda` 逐位复制到文件 `case123.img`，块大小为 4096 字节，如果遇到错误，它将用空符号填充剩余块：

```
dd if=/dev/hda of=case123.img bs=4k conv=noerror,sync
```

注意，此命令没有生成输出文件的哈希，而我们需要它来进行验证。解决方案是单独使用 `sha1sum` 命令。

### FTK Imager

`FTK Imager` 是 Access Data 开发的免费数据预览和镜像工具。与 `dd` 工具不同，该镜像是一个功能齐全的产品，允许你执行符合取证要求的采集，通过生成 `MD5` 和/或 `SHA-1` 哈希进行验证，并以只读方式预览文件和文件夹。`FTK Imager` 还可以读取 Windows 注册表项并让你预览它们及其值。它还支持压缩、加密和多种输出格式，包括 EnCase 证据文件格式 (`E01`) 和 `dd` 生成的原始格式。

## 密码破解器

在从移动设备到后端服务器的一切中，发现加密文件或`drives`变得越来越常见。如果嫌疑人无法或不愿提供密码，或者根本没有可以审问的嫌疑人，你可能需要借助专用软件，这些软件旨在猜测密码并解密受保护的。该领域一种流行的商业解决方案被称为 `Passware Kit Forensic`。它可以独立运行，也可以与 `EnCase` 集成。`Passware Kit Forensic` 可以解密 280 多种类型的保护文件，包括 `BitLocker`、`FileVault`、`iCloud` 和 `Dropbox`。此外，由于密码破解可能需要很长时间，该工具可以利用图形处理器（`GPUs`）和多台网络计算机来加速这一过程。

## 加密工具

我们通常必须确保调查及其证据的机密性。为了实现这一点，我们可以转向适用于多个平台的各种加密工具。加密文件最简单的方法可能是使用大多数操作系统自带的压缩实用程序，但你必须确保提供了密码。这种方法的优点是，这些应用程序无处可见，且文件在大多数平台上都是通用的。

如果你需要更健壮一些的东西，可以尝试任何可用的加密工具。最受欢迎且推荐的开源解决方案之一是 `VeraCrypt`，它基于已失效的 `TrueCrypt`。该工具免费，并适用于 Windows、`OS X` 和 Linux 系统。`VeraCrypt` 支持多种加密系统，包括 `AES`、`TwoFish` 和 `Serpent`。它还支持在卷内部创建隐藏的加密卷，如图 9-2 所示。最后，该工具正在持续开发，并定期进行安全更新。

## 哈希实用程序

法证分析中最流行的哈希算法是 `MD5` 和 `SHA-1`，本章讨论的所有流行工具都支持它们。如果你需要一个独立的哈希实用程序，许多操作系统都默认包含了这些工具。`Mac OS` 提供了从命令行使用的 `md5` 工具。`Linux` 通常同时拥有 `md5` 工具和 `sha1sum`。最后，微软提供了`文件校验和完整性验证器`（`FCIV`）工具作为免费但不受支持的下载。`FCIV` 能够计算 `MD5` 和 `SHA-1` 哈希。

## 分析实用程序

最广泛使用的商业分析工具是 `Guidance Software` 的 `EnCase` 和 `Access Data` 的 `Forensic Toolkit (FTK)`。这些工具并不便宜，但也有许多免费或较廉的选项，包括 The Sleuth Kit。我们将在本节中逐一描述这些这些工具。

### EnCase

`EnCase` 可能是执法机构以及一些大型企业中使用得广泛的分析工具。仅将其描述为分析工具可能不太准确，因为它实际上可以执行采集（包括在线和离线）、分析和报告。在采集方面，该产品提供了在所有端点和服务器上运行代理的选项，可用于通过网络远程采集。这意味着你不需要物理收缴设备即可获取其数据。

`EnCase` 对领域的贡献之一是创建了专有的（但广泛使用的）`EnCase Evidence File`格式。这种格式的文件通常具有 `.E01` 扩展名，尽管这不是必须的。该格式之所以具有如此影响力，是因为它将压缩、加密和元数据集成在同一个文件中。如果你正在开发证据驱动器的原始镜像或位对镜像，你将得到多个文件：副本、哈希值和元数据（例如，证据标签和案件号）。你完全可能还有与副本相关的其他文件。此外，如果你想节省空间或确保证据的机密性，你必须单独压缩和/或加密文件。`EnCase` 的格式允许以几乎透明的方式将这一切整合到一个文件中。

### FTK

另一个非常流行的套件是 `Forensic Toolkit`，它的使用范围几乎与 `EnCase` 相当。两个系统的用户有时会指出 `FTK` 的用户界面更直观，但这显然是一个主观问题。真正让 `FTK` 与许多区分开来的是它的基础数据管理模型。由于该工具构建在数据库管理系统之上，它能够高效地处理海量数据。在最新版本中，`FTK` 赞称支持 `ElasticSearch`，这是一种非常流行的、为处理大数据源设计的开源搜索引擎。然而，与这些功能相关的数据预处理和索引可能会导致初始案件上传比其他解决方案耗时长。

### The Sleuth Kit

完善我们分析套件的是 Brian Carrier 的开源工具 `The Sleuth Kit`。`EnCase` 和 `FTK` 极力呈现一种统一的用户体验，隐藏了在后台支持分析师运行的许多工具，而 `The Sleuth Kit` 则更直白地是一系列可操作的工具，其中许多工具专门使用命令行界面。然而，如果你更倾向于拥有与商业解决方案相当的图形用户界面（`GUI`），你可以配合 `The Sleuth Kit` 使用 `Autopsy` 来完成工作，如图 9-3 所示。这些工具共同完成了 `EnCase` 和 `FTK` 执行的大部分工作，但与每个许可证数千美元的价格相比，它们是免费的。

## OS 和进程分析

操作系统（`OS`）是管理和控制与计算机交互的软件系统。虽然今天有很多操作系统，但它们执行相同的三个基本功能：

- 管理所有计算机资源，如内存、CPU 和磁盘
- 提供用户界面
- 为运行应用程序提供服务

对于法证分析师来说，第一项是特别感兴趣的，因为计算机系统上发生的每一个操作都是通过其 `OS` 进行的。

如果你正在调查微软 Windows 系统，两个最重要的信息源是注册表和事件日志。注册表是 Windows 存储大多数系统设置的主要数据存储。虽然主要的分析套件包含了此类数据库的查看器，但你也可以在任何 Windows 计算机上通过启动注册表编辑器直接检查它。注册表中可以找到数百个感兴趣的制品，包括：

- **自动运行位置**：这是程序告诉 Windows 应该在引导过程中启动的地方。恶意软件经常利用此处持久化（例如，`HKLM\Software\Microsoft\Windows\CurrentVersion\Run`）。
- **最近使用列表**：通常称为 `MRUs`，在这里找到最近启动的应用程序、最近使用或修改的文档以及最近更改的注册键。例如，如果你想查看最近使用的 Word 文档，你将查看 `HKEY_CURRENT_USER\Software\Microsoft\Office\12.0\Common\Open Find`。
- **无线网络**：每当计算机连接到无线网络时，这都会记录在注册表中，你作为调查人员可以在 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\NetworkList\Profile` 中进行检查。

另一个有用的信息源是事件日志，你可以通过在任何 Windows 计算机上启动“事件查看器”应用程序来访问它。实际上存在多组日志，其数量取决于特定的系统。然而，所有的 Windows 计算机都有应用程序日志，应用程序会在其中报告使用情况、错误和其他信息。此外还有安全日志，操作系统在其中维护安全相关的事件，例如未成功的登录尝试。最后，每个 Windows 系统都有系统日志，操作系统在其中记录整个系统范围的事件。

虽然 Linux 没有像 Windows 那样方便的集中注册表，但对于法医调查人员来说，它有自己的一套丰富的痕物来源。首先，许多相关数据可以在明文文件中找到（与 Windows 不同，这使得搜索字符串变得简单）。Linux 通常还包含许多实用的工具，如 `dd`、`sha1sum` 和 `ps`，它们可以分别帮助你获取证据、对其进行哈希处理，并获取运行进程列表（以及与之相关的资源）。你可以在 Windows 中完成所有这些操作，但需要安装额外的工具。

Linux 文件系统从根目录开始，用斜杠 `/` 表示。作为一名分析师，你需要熟悉某些目录。我们重点介绍了其中的几个，但你应该从此开始建立你自己的列表。

- `/etc`: 这是主要的系统配置目录，包含大多数已安装应用程序的子目录。
- `/var/log`: 所有运行良好的 Linux 应用程序都会将日志文件保在此目录下的明文文件中，这里是分析师的金矿。
- `/home/$USER`: 这里，`$USER` 是一个变量名，你应该将其替换为指定的用户名。所有用户数据和配置数据都存储在这里。

请注意，这个列表只是一个开始。你应该从这里建立你自己的列表。

### 移动设备取证

虽然可以在运行中的 Windows 或 Linux 系统上进行一些取证分析，但移动设备需要专门的取证工具。这一规则的例外是越狱的 iPhone 或 iPad 以及已根的 Android 设备，因为这两者都暴露了与 Linux 非常类似的操作系统，并包含一些相同的工具和位置。为了增加趣味性，许多手机需要特殊的电缆，尽管近年来向 USB-C 的迁移由于更多设备采用此接口而简化了这一点。

移动取证涉及的挑战之一仅仅是获取数据。移动操作系统的设计并不支持数据提取，这意味着法医分析师必须先让设备加载备操作系统。这通常需要自定义引导加载程序（bootloader），这几乎是任何移动取证工具包必不可少的特征。

移动设备的另一个特性是，其大部分数据存储在如 `SQLite` 等微型数据库管理系统中。这些系统需要特殊工具才能正确查看其数据。然而，它们的优势是，当用户要求删除时，它们几乎不会删除。相反，它们会将数据库表中的行标记为已删除，并保持其完整内容不变，直到新数据覆盖它们。即使如此，底层文件系统也允许恢复这些被删除的信息。与引导加载程序一样，任何常用的分析套件都将包含分析这些数据的方法。

## 日志查看器

每个主流操作系统都提供了查看日志文件内容的方法。你可能需要专用日志查看器的原因是，内置工具旨在用于初步检查，而不是详尽分析，特别是当日志数量达到数千条时。与目前为止描述的大多数功能一样，这种功能通常出现在法医分析套件中。如果你需要专用的日志查看器，选择并不匮乏，包括许多免费选项。

使用独立日志查看器有意义的场景是：当你正尝试汇总来自多台计算机的各种日志，以建立全局事件的时间线时。你需要一个允许你导入多个文件（或运行系统）并以多种方式过滤其内容的工具。允许你此的一些工具包括 Splunk、SolarWinds Event Log Consolidator/Manager 以及 Ipswitch 的 WhatsUp。

## 构建你的取证工具包

对于取证工具包中应该放什么，没有万一不变的答案。这实际上取决于你的环境和工作流程。尽管如此，如果你的工作涉及取证分析，那么几乎每个人都应该准备一些通用类型的工具。

### 应急包 (Jump Bag)

应急包是一组预先包装好的工具，随时准备好在不接到通知的情况下出发。当你被要求放下手头所有工作去响应可能涉及取证检查的事件时，它是你的第一道防线。由于你想确保工具包始终处于就绪状态，你可能希望制定一个清单，在每次使用后对包进行清点，以确保它为下次运行做好准备。你可能想在其中包含以下每一项物品。

### 写保护器和驱动器适配器

硬件写保护器可以在获取存储设备内容时防止对其进行修改。它们有许多种类和价位，但本质上它们的作用都是相同的。最重要的考虑因素是它们支持的接口类型。你应该咨询你的资产清单，看看你的环境中有多少种不同的磁盘接口。某些工具支持 SCSI 和 ATA，但不支持 SATA，另一些工具可能不支持 USB 设备。只要你为组织中的每种存储设备接口都准备了适配器和电缆，你的情况就是很理想了。

### 电缆

你应急包的很大一部分可能分配给各种类型的电缆。一个可以遵循的良好原则是：如果你以前需要过某种特定的电缆，那么你可能应该永远把它放在你的应急包里。以下是一些你可能想要开始准备的电缆建议：

- 网线（交叉线、直通线、单向线）
- 串口线（各种类型的 USB 和 RS-232）
- 电源
- 一个小型以太集线器
- 静电手环

### 已擦除的可移动介质

在响应事件之前，你可能没有几个小时的时间来擦除硬盘，因此提前准备几个是明智的。接口类型并不太重要（只要你的写保护器支持它即可），但容量很重要。一个良好的原则是查阅你的资产清单，找到组织中最大的工作站或外部硬盘，并在包中准备至少两倍大小的存储空间。服务器的硬盘通常比工作站大得多，所以如果你担心这个问题，你可能需要投资像 Forensic Computers 的 Forensic Data Monster 这样的便携式 RAID 解决方案。

对于经常处理调查的组织，一种常见的方法是为取证镜像专门设置网络附属存储 (NAS) 解决方案。只要有快速的网络连接，你轻松地镜像任何工作站或服务器。一个额外的优势是，NAS 可以作为尚待法决的过去调查的存档机制。在这种情况下，遵守组织的数据留存政策很重要。

#### 相机

相机是你的应急包（jump bag）中一个经常被忽视但关键的物品。拍摄犯罪或事件现场非常重要，但任何带有闪光灯的数字相机都能胜任。相机的一个很有用的补充是一个小尺子，每当你需要捕捉距离感或比例时，都可以将其纳入拍摄范围。理想情况下，尺子应该具有哑光表面以减少反光。

## 犯罪现场带

这听起来可能有些多此一举，但通过手段通知该区域的人员不要进入对于取证过程至关重要。犯罪现场带（或其他限制区域标签胶带）可以很好且廉价地完成这项工作。

## 防封条

当你收集的证据数量或运输距离需要他人的协助（例如驱动员）时，你可能希望用防篡封条密封证据容器。在紧急情况下，你可以使用胶带并在上面签名。然而，如果能负担得起费用，专用的带锁容器是最好的。

## 文档和表格

根据你所属机构，许多表格和其他文档可能只以数字形式存在。尽管如此，打印纸质副本并放在你的应急包中是一个好主意，因为你永远不知道在事件响应过程中是否能够访问公司的数据存储。以下是我们大多数人会放在包里的某些物品。

### 证据链表单

图 9-1 显示了一个典型的证据链表单，但如果你还没有这种表单，应该根据你组织的要求对其进行定制。重要的方面是确保每件被扣押的证据都有有足够的副本。理想情况下，你的证据运输容器外部有一个防水袋，你可以将容器的表单放入袋中（其中的单个物品可能仍需要自己的表单）。
