
## 2. 审查变更

组织内的专家审查变更。审查变更的人员通常来自组织内的几个不同领域。在某些情况下，他们可能会迅速完成审查并批准或拒绝变更。在其他情况下，变更可能需要在广泛测试后，由正式的变更审查委员会批准。

## 3. 批准/拒绝变更

基于审查结果，这些专家随后批准或拒绝变更。他们还会在变更管理文档中记录响应。例如，如果组织使用内部网站，有人会在网站的数据库中记录结果。在某些情况下，变更审查委员会可能要求制定回滚或退出计划。这确保了如果变更导致故障，人员可以将系统恢复到其原始状态。

## 4. 测试变更

一旦变更获批，就应该对其进行测试，最好在非生产服务器上进行。测试有助于验证变更不会导致意外问题。

## 5. 计划并实施变更

变更会被安排计划，以便以对系统和系统客户影响最小的方式实施。这可能要求在非值班时间或非高峰时段安排变更。

## 6. 记录变更

最后一步是记录变更，以确保所有相关方知情。这通常需要更新配置管理文档。如果发生无关灾难，要求管理员重建系统，变更管理文档将为他们提供变更信息。这确保他们能将系统恢复到变更前的状态。

有时可能需要紧急变更。例如，如果攻击或恶意软件感染导致一个或多个系统瘫痪，管理员可能需要对系统或网络进行变更以遏制事件。在这种情况下，管理员仍需记录这些变更。这确保变更审查委员会可以审查变更的潜在问题。此外，记录紧急变更可确保受影响的系统在需要重建时包含新配置。

当强制执行变更管理流程时，它会为系统的所有变更创建文档。如果人员需要撤销变更，这提供了信息追踪。如果人员需要在其他系统上实施相同的变更，文档也提供了可遵循的路线图或程序。

变更管理控制是 ISO 通用准则中某些安全保证要求（SAR）的强制性要素。然而，许多不要求遵守 ISO 通用准则的组织也实施了变更管理控制。它通过防止导致意外损失的未授权变更，提高了环境的安全性。

### 版本控制

版本控制通常指软件配置管理中使用的版本控制。标签或编号系统用于区分跨多台机器或单台机器在不同时间点的不同软件集和配置。例如，应用程序的第一个版本可能标记为 `1.0`。第一个小版本更新将标记为 `1.1`，第一个大版本更新将是 `2.0`。这有助于跟踪已部署软件随时间发生的变更。

虽然大多数成熟的软件开发人员认识到版本控制和修订控制在应用程序中的重要性，但许多新晋 Web 开发人员并不认识到其重要性。这些 Web 开发人员学习了一些用于创建很棒网站的优秀技能，但并不总是认识到底层原则（如版本控制）的重要性。如果他们不通过某种版本控制系统来控制变更，可能会实施一个实际上导致网站瘫痪的变更。

### 配置文档

配置文档标识系统的当前配置。它标识系统负责人和系统用途，并列出应用于基线的所有变更。多年前，许多组织使用简单的纸质笔记本记录服务器的此类信息，但如今将这些信息存储在文件或数据库中要普遍得多。当然，将文档存储在数据文件中的挑战在于，在停机期间可能无法访问。

## 管理补丁与减少漏洞

补丁管理和漏洞管理流程协同工作，帮助保护组织免受新兴威胁的侵害。操作系统和应用程序中会定期发现 Bug 和安全漏洞。发现后，供应商会编写并测试补丁以消除漏洞。补丁管理确保应用适当的补丁，漏洞管理有助于验证系统不易受已知威胁的影响。

### 管理的系统

值得强调的是，补丁和漏洞管理不仅适用于工作站和服务器。它也适用于任何带有操作系统的计算设备。网络基础设施系统（如路由器、交换机、防火墙、设备（如统一威胁管理设备）和打印机）都包含某种类型的操作系统。有些基于 Cisco，有些基于 Microsoft，还有些基于 Linux。

嵌入式系统是指具有中央处理单元（CPU）、运行操作系统，并拥有一个或多个旨在执行一个或多个功能的应用程序的设备。示例包括摄像头系统、智能电视、家用电器（如防盗报警系统、无线恒温器和冰箱）、汽车、医疗设备等。这些设备有时被称为物联网（IoT）。

这些设备可能存在需要补丁的漏洞。例如，2016 年底针对域名系统（DNS）服务器的大规模分布式拒绝服务攻击，通过阻止用户访问数十个网站，实际上导致了互联网瘫痪。据报道，攻击者使用 Mirai 恶意软件控制物联网设备（如互联网协议 [IP] 摄像头、婴儿监视器和打印机）并将它们加入僵尸网络。数千万台设备向 DNS 服务器发送 DNS 查找请求，有效地使其过载。显然，这些设备应打补丁以防止此类攻击重演，但许多制造商、组织和所有者并不给物联网设备打补丁。更糟的是，许多供应商甚至不发布补丁。

最后，如果组织允许员工在组织网络内使用移动设备（如智能手机和平板电脑），这些设备也应纳入管理。

### 补丁管理

补丁是一个统称，指为修正 Bug 或漏洞或改进现有软件性能而编写的任何类型的代码。软件可以是操作系统，也可以是应用程序。补丁有时被称为更新、快速修复和热修复。在安全语境下，管理员主要关注安全补丁，即影响系统漏洞的补丁。

尽管供应商定期编写并发布补丁，但这些补丁只有在应用后才有用。这似乎显而易见，但许多安全事件发生的原因仅仅是组织未实施补丁管理策略。例如，第 14 章讨论了 2017 年对 Equifax 的多次攻击。2017 年 5 月的攻击利用了 Apache Struts Web 应用程序中的一个漏洞，本可以在 2017 年 3 月修补。

一个有效的补丁管理计划确保系统通过最新补丁保持最新状态。有效补丁管理计划中的常见步骤如下：

#### 评估补丁

当供应商宣布或发布补丁时，管理员会对其进行评估，以确定它们是否适用于其系统。例如，修复配置为域名系统（DNS）服务器的 Unix 系统漏洞的补丁，与运行 Windows 版 DNS 的服务器无关。同样，如果功能未安装，则不需要修复 Windows 系统上运行功能的补丁。

#### 测试补丁

只要可能，管理员会在隔离的非生产系统上测试补丁，以确定补丁是否会导致任何不良副作用。最坏的情况是应用补丁后系统将无法启动。例如，补丁偶尔会导致系统开始无限重启循环。它们启动进入停止错误，并不断尝试重启以从错误中恢复。如果测试在单个系统上显示此问题，则仅影响一台系统。然而，如果组织在测试前将补丁应用到一千台计算机，可能会造成灾难性后果。

### 补丁管理流程

#### 批准补丁

管理员测试补丁并确定其安全后，会批准补丁进行部署。通常会将变更管理流程（本章前面已介绍）作为批准流程的一部分。

#### 部署补丁

测试和批准完成后，管理员部署补丁。许多组织使用自动化方法来部署补丁。这些可以是第三方产品，也可以是软件供应商提供的产品。

#### 验证补丁是否已部署

部署补丁后，管理员会定期测试和审核系统，以确保系统保持已修补状态。许多部署工具都包含审核系统的功能。此外，许多漏洞评估工具也包含检查系统以确保其安装了适当补丁的功能。

## 漏洞管理

漏洞管理是指定期识别漏洞、评估漏洞，并采取措施缓解与之相关的风险。无法消除风险。同样，也无法消除所有漏洞。然而，有效的漏洞管理计划有助于组织确保其定期评估漏洞，并缓解那些代表最大风险的漏洞。漏洞管理计划的两个常见要素是例行漏洞扫描和定期漏洞评估。

### 漏洞扫描

**漏洞扫描器**是用于测试系统和网络已知安全问题的软件工具。攻击者使用漏洞扫描器来检测系统和网络中的弱点，例如缺失的补丁或弱密码。检测到弱点后，他们会发起攻击以利用这些弱点。许多组织的管理员使用同类型的漏洞扫描器来检测其网络上的漏洞。他们的目标是在攻击者发现这些漏洞之前检测并缓解它们。

正如防病毒软件使用特征库来检测已知病毒一样，漏洞扫描器包含一个已知安全问题的数据库，并根据该数据库检查系统。供应商会定期更新此数据库，并向客户出售更新订阅。如果管理员不保持漏洞扫描器为最新状态，他们将无法检测到较新的威胁。这类似于防病毒软件如果没有当前的病毒特征定义，将无法检测到较新的病毒。

**Nessus** 是由 Tenable Network Security 管理的一款流行漏洞扫描器，它结合多种技术来检测各种漏洞。Nessus 分析系统发出的数据包以确定系统的操作系统及其他详细信息。它使用端口扫描来检测开放端口，并识别这些系统上可能正在运行的服务和协议。一旦 Nessus 发现了关于系统的基本详细信息，它便可以通过查询进一步测试系统的已知漏洞，例如系统是否安装了当前的补丁。它还可以发现网络上使用 IP 探测和 Ping 扫描的潜在恶意系统。

重要的是要认识到，漏洞扫描器的功能不仅仅是检查未打补丁的系统。例如，如果系统正在运行数据库服务器应用程序，扫描器可以检查数据库是否使用带有默认账户的默认密码。同样，如果系统托管了一个网站，扫描器可以检查该网站以确定其是否使用输入验证技术来防止不同类型的注入攻击，例如 SQL 注入或跨站脚本攻击。

在一些大型组织中，专门的安全团队将使用可用工具执行定期漏洞扫描。在较小的组织中，IT 或安全管理员可能会将扫描作为其其他职责的一部分来执行。但请记住，如果负责部署补丁的人员也负责运行扫描以检查补丁，这代表了潜在的利益冲突。如果某些因素阻止管理员部署补丁，该管理员也可能会跳过本应检测到未打补丁系统的扫描。

扫描器包含生成报告的功能，以标识其发现的任何漏洞。报告可能建议应用补丁或进行特定的配置或安全设置更改，以改进或强制实施安全性。显然，仅仅建议应用补丁并不能减少漏洞。管理员需要采取措施来应用补丁。

然而，在某些情况下，这样做可能不可行或不可取。例如，如果修复次要安全问题的补丁破坏了系统上的应用程序，管理层可能会决定在开发人员创建变通方法之前不实施该修复。即使组织已处理了该风险，漏洞扫描器仍会定期报告该漏洞。

相反，从不执行漏洞扫描的组织可能会存在许多漏洞。此外，这些漏洞将保持未知状态，管理层将没有机会决定缓解哪些漏洞、接受哪些漏洞。

### 漏洞评估

漏洞评估通常包含漏洞扫描的结果，但评估的作用不止于此。例如，年度漏洞评估可能会分析过去一年所有的漏洞扫描报告，以确定组织是否在处理漏洞。如果同一漏洞在每份漏洞扫描报告中都重复出现，一个合乎逻辑的问题是：“为什么这还没有得到缓解？”可能有正当理由且管理层选择了接受风险，也可能是执行了漏洞扫描但从未采取行动来缓解发现的漏洞。

漏洞评估通常作为风险分析或风险评估的一部分进行，以识别某一时间点的漏洞。此外，漏洞评估还可以检查其他领域以确定风险。例如，漏洞评估可以检查敏感信息在其整个生命周期中是如何被标记、处理、存储和销毁的，以解决潜在漏洞。

第 15 章“安全评估与测试”涵盖了渗透测试。许多渗透测试始于漏洞评估。

## 常见漏洞与披露

漏洞通常使用**常见漏洞与披露（CVE）**字典来引用。CVE 字典提供了一种用于识别漏洞的标准约定。MITRE 维护 CVE 数据库，您可以在此处查看：[www.cve.mitre.org](http://www.cve.mitre.org)。

补丁管理和漏洞管理工具在扫描特定漏洞时，通常使用 CVE 字典作为标准。例如，前面提到的 WannaCry 勒索软件利用了未打补丁的 Windows 系统中的漏洞，微软发布了微软安全公告 MS17-010 并附带更新以防止该攻击。同一漏洞被标识为 **CVE-2017-0143**。

CVE 数据库使创建补丁管理和漏洞管理工具的公司受益。它们无需花费任何资源来管理漏洞的命名和定义，而是可以专注于用于检查系统漏洞的方法。

## 摘要

## 几项基本安全原则

几项基本安全原则构成了任何环境中安全运营的核心。这些原则包括知情需要、最小权限、职责分离与责任分离、轮岗以及强制休假。这些实践相结合，有助于防止安全事件的发生，并限制确实发生的事件的影响范围。管理员和操作员需要特殊权限才能遵循这些安全原则执行其工作。除了实施这些原则外，监控特权活动以确保特权实体不滥用其访问权限也至关重要。

## 资源保护

通过资源保护，包含数据的介质和其他资产在其整个生命周期内得到保护。介质包括任何能够存放数据的载体，例如磁带、内部驱动器、便携式驱动器（`USB`、`FireWire` 和 `eSATA`）、CD 和 DVD、移动设备、存储卡以及打印输出件。存放敏感信息的介质应使用组织认可的方法进行标记、处理、存储和销毁。资产管理不仅限于介质，还延伸至组织认为有价值的任何资产——例如计算机等物理资产，以及购买的应用程序和软件密钥等软件资产。

### 虚拟资产

虚拟资产包括虚拟机、虚拟桌面基础设施（`VDI`）、软件定义网络（`SDN`）和虚拟存储区域网络（`VSAN`）。管理程序是管理虚拟组件的软件组件。管理程序增加了额外的攻击面，因此确保其以安全状态部署并及时应用补丁保持最新非常重要。此外，每个虚拟组件都需要单独更新。

### 基于云的资产

基于云的资产包括存储在云中的任何资源。在与云服务提供商谈判时，您必须了解谁负责维护和安全。一般来说，云服务提供商对软件即服务（`SaaS`）资源承担最大责任，对平台即服务（`PaaS`）产品承担较少责任，对基础设施即服务（`IaaS`）产品承担最小责任。许多组织在签订基于云的服务合同时会使用服务级别协议（`SLA`）。`SLA` 规定了性能预期，且通常包含供应商未达标时的惩罚条款。

## 变更与配置管理

变更管理和配置管理是有助于减少停机的两项额外控制措施。配置管理确保系统以一致且已知安全的方式部署。镜像是一种常见的配置管理技术，可确保系统从已知基线启动。变更管理有助于减少由未授权变更导致的意外停机，还能防止变更削弱安全性。

## 补丁与漏洞管理

补丁管理和漏洞管理程序协同工作，使系统免受已知漏洞的侵害。补丁管理使系统通过相关补丁保持最新状态。漏洞管理包括漏洞扫描，以检查各种已知漏洞（包括未打补丁的系统），并包含作为风险评估一部分进行的漏洞评估。

## 考试要点

### 理解知情需要和最小权限原则

**理解知情需要和最小权限原则。** 知情需要和最小权限原则是在安全网络中实施的两项标准 IT 安全原则。它们限制对数据和系统的访问，使得用户和其他主体仅能访问其所需的内容。这种有限的访问有助于防止安全事件，并在事件发生时限制其影响范围。如果不遵循这些原则，安全事件将给组织造成更大的损害。

### 理解职责分离和轮岗

**理解职责分离和轮岗。** 职责分离是一项基本安全原则，确保没有单个人能够控制关键功能或系统的所有要素。通过轮岗，员工会轮换到不同的岗位，或将任务分配给不同的员工。串通是指多人达成协议实施某些未授权或非法行为。实施这些策略通过限制个人在不串通他人的情况下所能采取的行动，有助于防止欺诈。

### 理解监控特权操作的重要性

**理解监控特权操作的重要性。** 特权实体是受信任的，但它们可能滥用特权。因此，监控所有特权分配和特权操作的使用非常重要。目标是确保受信任的员工不滥用被授予的特殊权限。监控这些操作还可以检测到许多攻击，因为攻击者在攻击过程中通常会使用特殊权限。

### 理解信息生命周期

**理解信息生命周期。** 数据需要在其整个生命周期内得到保护。这始于对数据进行适当的分类和标记。还包括对数据进行适当的处理、存储和销毁。

### 理解服务级别协议

**理解服务级别协议。** 组织与供应商等外部实体使用服务级别协议（`SLA`）。它们规定了性能预期，例如最长停机时间，且通常包含供应商未达标时的惩罚条款。

### 理解安全供应概念

**理解安全供应概念。** 资源的安全供应包括确保资源以安全方式部署，并在其整个生命周期内以安全方式维护。例如，台式个人计算机（`PC`）可以使用安全镜像进行部署。

### 理解虚拟资产

**理解虚拟资产。** 虚拟资产包括虚拟机、虚拟桌面基础设施、软件定义网络和虚拟存储区域网络。管理程序是管理虚拟资产的主要软件组件，但管理程序也为攻击者提供了额外的攻击目标。确保托管虚拟资产的物理服务器针对操作系统和管理程序应用适当的补丁以保持最新非常重要。此外，所有虚拟机都必须保持最新状态。

### 识别基于云的资产的安全问题

**识别基于云的资产的安全问题。** 基于云的资产包括通过云访问的任何资源。将数据存储在云中会增加风险，因此可能需要采取额外措施来保护数据，具体取决于其价值。租用基于云的服务时，您必须了解谁负责维护和安全。在 `IaaS` 模型中，云服务提供商提供的维护和安全最少。

### 解释配置和变更控制管理

**解释配置和变更控制管理。** 有效的配置和变更管理计划可以防止许多停机和事件。配置管理确保系统配置相似，且系统配置是已知且有文档记录的。基线化确保系统使用通用基线或起点进行部署，镜像是一种常见的基线化方法。变更管理有助于减少由未授权变更导致的停机或安全性削弱。变更管理流程要求变更必须被请求、批准、测试和记录。版本控制使用标签或编号系统来跟踪更新版本软件中的变更。

### 理解补丁管理

**理解补丁管理。** 补丁管理确保系统通过当前补丁保持最新状态。您应该知道，有效的补丁管理计划将评估、测试、批准和部署补丁。此外，请注意系统审计会验证已批准补丁向系统的部署。补丁管理通常与变更和配置管理交织在一起，以确保文档反映这些变更。当组织没有有效的补丁管理计划时，往往会因本可预防的已知问题而遭遇停机和事件。

**解释漏洞管理。** 漏洞管理包括例行漏洞扫描和定期漏洞评估。漏洞扫描器可以检测已知的安全漏洞和弱点，例如缺失补丁或弱密码。它们生成报告，指示系统的技术漏洞，并作为补丁管理计划的有效检查手段。漏洞评估不仅限于技术扫描，还可以包括审查和审计以检测漏洞。
