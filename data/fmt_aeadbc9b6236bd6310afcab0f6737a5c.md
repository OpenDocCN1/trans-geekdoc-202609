
“已知密钥攻击”这一术语具有误导性：如果密码分析师知道密钥，攻击就结束了。已知密钥意味着密码分析师了解关于密钥的某些信息，从而减少攻击它所需的工作量。如果密码分析师知道密钥仅由大写字母和数字组成，则在攻击中可以省略其他字符。

### 差分密码分析

*差分密码分析*旨在找出被加密的相关明文之间的“差异”。这些明文可能仅相差几位。它通常作为自适应选择明文攻击发起：攻击者选择要加密的明文（但不知道密钥），然后加密相关的明文。

然后密码分析师使用统计分析在密文中搜索非随机性的迹象，锁定明文有差异的区域。相关密文的每一位都应该有 50/50 的翻转几率：密码分析师寻找不符合这一规律的区域。任何这种潜在的规律都是恢复密钥的线索。

### 线性密码分析

*线性密码分析*是一种已知明文攻击，密码分析师找到大量使用同一密钥创建的明文/密文对。研究这些对以推导出创建它们所用密钥的信息。

差分分析和线性分析均可结合为*差分线性分析*。

### 实现攻击

实现攻击利用在实现应用程序、服务或系统时犯下的错误（漏洞）。Bruce Schneier 对实现攻击的描述如下：“许多系统因实现错误而失效。有些系统不能确保明文在加密后被销毁。其他系统使用临时文件来防止系统崩溃时的数据丢失，或使用虚拟内存来增加可用内存；这些功能可能会意外地在硬盘上留下明文。在极端情况下，操作系统会将密钥留在硬盘上。我们见过的一个产品使用特殊窗口进行密码输入。密码即使在窗口关闭后仍保留在窗口的内存中。无论该产品的加密技术有多好；它都被用户界面攻破了”[\[41\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0205)。

### 侧信道攻击

*侧信道*攻击利用物理数据来破解密码系统，例如监控加密或解密时使用的 `CPU` 周期或功耗。一些纯粹主义者可能声称这违反了某种规则，但正如 Bruce Schneier 所说：“一些研究人员声称这是作弊。没错，但在现实世界的系统中，攻击者会作弊。他们的工作是恢复密钥，而不是遵守某种行为准则。安全系统的审慎工程师会预见到这一点并做出适应”[\[42\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0210)。

#### 定时攻击

定时攻击是一种侧信道攻击，利用时间来破解系统或泄露敏感数据。想象一个登录表单，对于无效登录返回以下错误：

*   无效用户/无效密码：“无此用户”
*   有效用户/无效密码：“密码错误”

在这种情况下，远程攻击者可以发起用户名收集攻击，尝试一系列用户名（`asmith`、`bsmith`、`cmsith`、`dsmith` 等），并记录何时返回“密码错误”错误（标志着有效用户名）。网站设计者使用此逻辑来挫败用户名收集：

*   **无效用户名**：返回 `“Login incorrect”`
*   **有效用户名**：
    *   对提供的密码进行哈希运算，并与用户的密码哈希值进行比较
    *   **有效密码**：认证用户
    *   **无效密码**：返回 `“Login incorrect”`

这似乎使得用户名收集成为不可能：无效用户/无效密码和有效用户/无效密码均返回 `“Login incorrect.”` 但后一种情况耗时更长：服务器必须检查哈希值（而对于无效用户则不检查哈希值）。这意味着快速响应 = 无效账户，慢速响应 = 有效账户。如果使用快速哈希算法（如 `SHA-3`），这种时序差异将难以测量，但使用慢速哈希算法（如 `bcrypt`，前文已讨论）时则更容易检测到。

### 故障注入攻击

侧信道攻击（前节讨论）是被动的：它们监控（读取）系统。故障注入攻击是主动的物理攻击：它们改变系统，通常通过注入电力、光或电磁干扰（`EMI`）等能量来实现。故障注入攻击（`FIAs`）使设备的物理条件超出其设计预期范围；例如，使用强烈的电磁（`EM`）脉冲、高环境温度，以及对设备供电电压进行欠压和过压操作。这些攻击可诱导内部电子元件产生错误，进而被利用来恢复加密密钥和其他秘密数据 [\[43\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0215)。

### 勒索软件

勒索软件是一种利用强加密（如 `AES`）并扣留解密密钥以勒索赎金的恶意软件。勒索软件主要是一种针对可用性的攻击（阻止用户访问其文件），通常在系统被攻陷后部署。通常会加密所有（潜在）敏感或重要文档。以下是 Cryptolocker 加密的文件扩展名列表（非考点）：`*.odt`、`*.ods`、`*.odp`、`*.odm`、`*.odc`、`*.odb`、`*.doc`、`*.docx`、`*.docm`、`*.wps`、`*.xls`、`*.xlsx`、`*.xlsm`、`*.xlsb`、`*.xlk`、`*.ppt`、`*.pptx`、`*.pptm`、`*.mdb`、`*.accdb`、`*.pst`、`*.dwg`、`*.dxf`、`*.dxg`、`*.wpd`、`*.rtf`、`*.wb2`、`*.mdf`、`*.dbf`、`*.psd`、`*.pdd`、`*.pdf`、`*.eps`、`*.ai`、`*.indd`、`*.cdr`、`*.jpg`、`*.jpe`、`*.dng`、`*.3fr`、`*.arw`、`*.srf`、`*.sr2`、`*.bay`、`*.crw`、`*.cr2`、`*.dcr`、`*.kdc`、`*.erf`、`*.mef`、`*.mrw`、`*.nef`、`*.nrw`、`*.orf`、`*.raf`、`*.raw`、`*.rwl`、`*.rw2`、`*.r3d`、`*.ptx`、`*.pef`、`*.srw`、`*.x3f`、`*.der`、`*.cer`、`*.crt`、`*.pem`、`*.pfx`、`*.p12`、`*.p7b`、`*.p7c` [\[44\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0220)。

加密完成后，勒索软件通常会更改桌面壁纸以显示警告（也可能显示图像和/或文本文件），其中包含如何支付赎金（通过加密货币如 `Bitcoin`）以取回加密密钥的说明。

罪犯通常在收到赎金后释放密钥。通常设有支付时限（如 72 小时），若在此期间未支付赎金，密钥将被销毁。

良好的备份配合快速恢复可缓解勒索软件威胁。许多组织重视备份（这很重要），却忽视了从备份中恢复所需的时间（这同样非常重要）。如果整个数据中心都感染了勒索软件，从备份中恢复（诚实地）需要多长时间？在某些情况下，答案可能是数月，这导致勒索软件受害者为了加快恢复工作而支付赎金——即使他们拥有良好的备份。

### 生日攻击

生日攻击得名于生日悖论。其名称基于这样一个事实：在一个有 23 人或以上的房间里，至少有两人生日相同的概率超过 50%。许多人觉得这违反直觉，生日悖论也说明了为何许多人对概率（和风险）的直觉是错误的。你不是试图匹配某个特定的生日（如你自己的生日）；而是试图匹配任意一个生日。

如果你在一个挤满 23 人的房间里，你与其他 22 人中的每一个人生日相同的概率都是 1/365，总共 22/365 的机会。如果你匹配失败，你离开房间，Joe 与剩余人员生日相同的概率为 21/365。如果 Joe 也失败，他离开房间，Morgan 的概率为 20/365，以此类推。如果你把 22/365 + 21/365 + 20/365 + 19/365 … + 1/365 相加，总概率将超过 50%。

生日攻击用于制造哈希碰撞。正如匹配*你的*生日很难一样，找到一个与另一个输入哈希值碰撞的特定输入也很难。然而，正如匹配*任意*生日更容易一样，由于生日攻击，找到*任意*一个能与其他任意输入产生碰撞哈希的输入也更容易。

### 密钥聚类

任何加密密码的目标之一是只有唯一的密钥能从密文中导出明文。密钥聚类是指两个不同的对称密钥应用于同一明文时产生了相同的密文。这使得两个不同的密钥都能解密该密文。

## 实现密码学

对称、非对称和基于哈希的密码学并非孤立存在：它们在现实世界中被应用，常结合使用，以提供机密性、完整性、认证和不可抵赖性。

### 数字签名

数字签名用于对文档进行加密签名。数字签名提供不可抵赖性，包括对签名者身份的认证，以及对文档完整性的证明（证明文档未被篡改）。这意味着发送者事后无法否认（或抵赖）曾对该文档签名。

Roy 想给 Rick 发送一封带数字签名的电子邮件。Roy 撰写邮件，即明文。然后他使用 `SHA-1` 哈希函数生成明文的哈希值。接着，他用自己的 `RSA` 私钥加密该哈希值来创建数字签名。图 4.26 展示了这一过程。Roy 随后将签名附加到明文邮件中并点击发送。

如果两个哈希值匹配，Rick 可知以下几点：

1.  邮件必定由 Roy 发送（只有 Roy 知道他的私钥）。这认证了 Roy 的发送者身份。
2.  邮件未被篡改。这证明了邮件的完整性。

如果哈希值匹配，Roy 事后无法否认曾对该邮件签名。这就是不可抵赖性。如果哈希值不匹配，Rick 就知道要么不是 Roy 发的，要么邮件的完整性遭到破坏。

> **注意**
>
> 数字签名提供认证和完整性，二者构成不可抵赖性。它们不提供机密性：明文保持未加密状态。

### 消息认证码

消息认证码（`MAC`）是一种使用密钥的哈希函数。常见的 `MAC` 实现是密码分组链消息认证码（`CBC-MAC`），它使用对称分组密码（如 `DES`）的 `CBC` 模式来创建 `MAC`。消息认证码提供完整性和真实性（证明发送者持有共享密钥）。

### HMAC

*散列消息认证码* (HMAC) 将共享密钥与散列运算相结合。IPsec 使用 HMAC（见下文）。

双方必须预先共享一个密钥。共享后，发送方使用 XOR（异或）将明文与共享密钥结合，然后使用 `MD5`（称为 `HMAC-MD5`）或 `SHA-1`（称为 `HMAC-SHA-1`）等算法对输出进行散列。该散列值再次与密钥结合，从而生成 HMAC。

接收方在本地将相同的明文与共享密钥结合，然后遵循上述相同过程，生成本地 HMAC。接收方将其与发送方的 HMAC 进行比较。如果两个 HMAC 匹配，则发送方通过认证（这证明发送方知道共享密钥），并确保消息的完整性（消息未被篡改）。

### 公钥基础设施

*公钥基础设施* (PKI) 利用所有三种形式的加密来提供和管理*数字证书*。数字证书是由数字签名签署的公钥。数字证书可以是基于服务器的（例如用于 SSL 网站，如 [`www.ebay.com`](https://www.ebay.com)），也可以是基于客户端的（绑定到个人）。如果两者结合使用，则提供相互认证和加密。标准的数字证书格式是 `X.509`。

NIST 特别出版物 800-15 描述了 PKI 的五个组成部分：

*   签发和吊销证书的*证书颁发机构* (CA)
*   为公钥与证书持有者身份及其他属性之间的绑定作担保的*组织注册机构* (ORA)
*   获得证书并可对数字文档签名的*证书持有者*
*   从已知的受信任 CA 公钥验证数字签名及其认证路径的*客户端*
*   存储并提供证书和*证书吊销列表* (CRL) 的*存储库* [\[46\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0230)

#### 证书颁发机构和组织注册机构

数字证书由*证书颁发机构* (CA) 签发。组织注册机构 (ORA) 在向证书持有者签发证书前，对其身份进行认证。一个组织可以作为 CA 或 ORA 运营（或两者兼任）。

CA 可以是私有的（内部运行）或公共的（如 VeriSign 或 Thawte）。例如，路人不能简单地请求并获得 [www.ebay.com](http://www.ebay.com) 的证书；他们必须证明有权这样做。这种认证由 CA 完成，可以包括商业记录调查、向域联系人发送电子邮件等类似方法。

#### 证书吊销列表

证书颁发机构维护*证书吊销列表* (CRL)，顾名思义，其中列出了已被吊销的证书。如果私钥被盗、员工离职等，证书可能会被吊销。CRL 是一个平面文件，扩展性不佳。*在线证书状态协议* (OCSP) 是 CRL 的替代方案，采用客户端-服务器设计，扩展性更好。

#### 密钥管理问题

证书颁发机构签发数字证书并将其分发给证书持有者。在分发过程中，必须保证持有者私钥的机密性和完整性。

PKI 中使用的公钥/私钥对应集中（且安全地）存储。用户丢失私钥就像忘记密码一样容易。如果丢失的私钥未安全存储，则使用匹配公钥加密的任何内容都将丢失（除非进行前文所述的密码分析）。

请注意，密钥存储不同于密钥托管。密钥存储意味着签发公钥/私钥对的组织保留一份副本。密钥托管，我们稍后将讨论，意味着由第三方组织（有时是多个组织）保留一份副本，通常用于执法目的。

已退役的密钥不得用于新事务，但可用于解密先前加密的明文。已销毁的密钥不再存在，不能用于任何目的。

### SSL 和 TLS

安全套接字层 (SSL) 将 PKI 的强大功能引入 Web。SSL 对 Web 流量进行认证并提供机密性。*传输层安全性* (TLS) 是 SSL 的继任者。它们通常作为 HTTPS (*超文本传输安全协议*) 的一部分使用。

当你连接到 [`www.isc2.org/`](https://www.isc2.org/) 等网站时，数据是加密的。即使你没有预共享密钥，这也是成立的：数据从一开始就被加密。这是通过非对称加密完成的：你的浏览器下载 [www.isc2.org](http://www.isc2.org) 的数字证书，其中包含该网站的公钥，并由证书颁发机构的私钥签名。如果你的浏览器信任该 CA（如 VeriSign），则该签名可认证该网站：你知道它是 [isc2.org](http://isc2.org) 而不是流氓网站。然后，你的浏览器使用该公钥安全地交换对称会话密钥。私钥存储在 [isc2.org](http://isc2.org) Web 服务器上，允许其解密任何用公钥加密的内容。然后使用对称密钥加密会话的其余部分。

用于认证、密钥交换和对称加密的密码套件是灵活的：你的浏览器将与服务器协商每一项。支持的算法包括（但不限于）用于密钥交换的 `RSA` 和 `Diffie-Hellman`，用于认证的 `RSA` 和数字签名算法 (DSA)，以及用于机密性的 `AES` 和三重 DES。

SSL 于 1990 年代为 Netscape Web 浏览器开发。SSL 2.0 是首个发布版本；SSL 3.0 修复了版本 2 的多个安全问题。TLS 基于 SSL 3.0。TLS 与该版本非常相似，但有一些安全改进。虽然通常用于 HTTPS 以保护 Web 流量，但 TLS 也可用于其他应用程序，如 Internet 聊天和电子邮件客户端访问。TLS 1.3 是当前版本。

### IPsec

IPsec（互联网协议安全）是一套协议，为 IPv4 和 IPv6 都提供加密层。它是提供*虚拟专用网络* (VPN) 的方法之一，VPN 允许你通过不安全网络（如互联网）发送私有数据（数据穿越公共网络，但却是“虚拟私有”的）。IPsec 包含两个主要协议：*认证头* (AH) 和*封装安全载荷* (ESP)。AH 和 ESP 提供不同的功能，有时功能会重叠。

支持 IPsec 的协议包括*互联网安全关联和密钥管理协议* (ISAKMP) 和*互联网密钥交换* (IKE)。

> **注意**
>
> 本章描述 IPsec 的加密方面：IPsec 的网络相关方面请参见第 5 章，领域 4：通信与网络安全。

#### AH 和 ESP

认证头为每个网络数据包提供认证和完整性。AH 不提供机密性；它充当数据的数字签名。AH 还防范*重放攻击*，即数据从网络上被嗅探并重发，通常是为了欺诈性地重用加密的认证凭据。

封装安全载荷主要通过加密数据包数据来提供机密性。它也可以选择性地提供认证和完整性。

#### 安全关联和 ISAKMP

AH 和 ESP 可以单独使用，也可以组合使用。IPsec 安全关联（`SA`）是一个单工（单向）连接，可用于协商 ESP 或 AH 参数。如果两个系统通过 ESP 通信，它们将使用两个 SA（每个方向一个）。如果系统除了 ESP 还利用 AH，则会再使用两个 SA，总共四个。一个称为安全参数索引（`SPI`）的唯一 32 位数字用于标识每个单工 SA 连接。互联网安全关联和密钥管理协议（`ISAKMP`）管理 SA 的创建过程。

#### 隧道模式和传输模式

IPsec 可用于隧道模式或传输模式。隧道模式由安全网关使用（可提供点对点 IPsec 隧道）。ESP 隧道模式加密整个数据包，包括原始数据包头部。ESP 传输模式仅加密数据（不加密原始头部）；这通常用于发送和接收系统能够原生“讲” IPsec 的场景。

AH 对原始 IP 头部进行认证，因此它常用于（配合 ESP）传输模式，因为原始头部未被加密。隧道模式通常单独使用 ESP（原始头部被 ESP 加密，从而受到保护）。

> **注意**
