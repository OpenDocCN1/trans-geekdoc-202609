- 计划
- 执行
- 监控与控制
- 收尾
- 专业与社会责任

我们将在书中将这些领域与不同的渗透测试方法相结合；但是，我们只讨论渗透测试特定的问题。与 `PM` 相关的知识非常多，我们无法在书中可行地涵盖 `PM` 的所有方面。对于那些完全不熟悉项目管理的人，我将尝试解释我们在书中讨论的任何与 `PM` 相关的内容；只需理解，像书中的任何其他主题一样，你将需要花时间阅读我们所涵盖之外的其它参考资料。

### 动态系统开发方法（DSDM）联盟会

我不提一下敏捷项目管理将是我的失职。大多数人至少听过敏捷编程，但现在有很多项目经理（PM）已经转向了更灵活的项目管理风格。`DSDM` 是一种软件开发方法论，最初基于快速应用开发（Rapid Application Development）方法。诚然，`DSDM` 只是众多敏捷软件开发方法之一；然而，对于发现敏捷管理对你的渗透测试工作是否有帮助，这是一个很好的起点。其他的敏捷方法还包括：极限编程（Extreme Programming）、`Scrum`、自适应软件开发（Adaptive Software Development）、水晶（Crystal）、特征驱动开发（Feature Driven Development）以及实用编程（Pragmatic programming）。你使用哪种方法取决于你自己，但所有形式的敏捷方法都存在一些基本原则，这些原则在《敏捷宣言》（Beck et al., 2001）中规定：我们的最高优先级是通过早期和持续交付交付价值软件来满足客户。欢迎需求的变化，即使在开发后期也是如此。敏捷过程利用变化为客户赢得竞争优势。频繁地交付工作软件，从几周到几个月不等，并倾向于更短的时间。业务人员和开发人员在整个项目中必须每天工作。围绕有激情的个人构建项目。给予他们所需的环境和支持，并信任他们能够完成工作。向开发团队内部及传递信息的最高效且有效的方法是面对面交流。工作软件是衡量进展的主要标准。敏捷过程促进可持续开发。赞助者、开发者和用户应该能够无限保持恒定的速度。对技术卓越和良好设计的持续关注增强敏捷性。简单——即最大化未完成工作量的艺术——至关重要。最好的架构、需求和设计源于自组织团队。团队定期反思如何变得高效，然后相应地调整和优化行为。敏捷方法相比于 `PMI` 所提倡的更具结构化的方法，其优势在于敏捷方法非常适用于那些不产生可重用组件的项目。在渗透测试中，两个`PenTest` 项目完全相同的情况非常罕见；使用敏捷过程允许你的团队在面对不可预见的挑战时更加灵活。有一些与敏捷编程和项目管理相关的认证，包括由 `DSDM Consortium` 提供的一些；但敏捷方法背后的理念倾向于认为，认证永远不应该用作职场的筛选标准。这的效果是降低了个人持有的任何与敏捷过程相关的认证权重，并迫使公司仔细检查工作历史，以确定组织内最优秀的人才。尽管这让人们能够根据自己的实力而不是一张纸来立足，但这确实给招聘经理带来了问题，因为没有统一的标准来衡量看似相似的申请者。对于本书，我们将坚持使用 `PMI` 的项目管理标准，主要因为该方法论在 IT 行业内有更大的接受度。再次，这并不意味着 `PMI` 更好；事实上，我认为与敏捷方法相比，情况恰恰相反。

## 针对特定技能和厂商的认证

对于管理层人员来说，拥有高级认证通常就足够了。毕竟，经理真的不需要知道 `TCP` 报头中的控制位是如何存在的——他们只需要知道有这些位，并且 `PenTest` 工程师可以操纵这些位。然而，如果你是工程师，你应该非常熟悉信息安全的技术方面。

**注意**：本节讨论的许多认证有效期仅 2 或 3 年，并需要重新认证。某些认证是特定厂商的。根据你的关注点，你可以获得厂商中性的认证。选择的原因是多样的。

### Cisco

虽然 `Cisco` 有多个网络认证路径，但在信息安全领域内兴趣和吸引力最大的是网络安全路径。该路径包含三种认证：思科认证网络关联助理（`CCNA`）、思科认证安全专业人员（`CCSP`）和思科认证互联网互域专家（`CCIE`）。虽然这些认证涉及对思科设备的实际操作经验，但在获得认证时获得的知识将很好地转化为渗透测试。

### CCNA Security

`CCNA Security` 认证要求申请者已拥有有效的 `CCNA` 认证。申请者随后可以参加另一项目前名为 `640-553 IINS`（代表 Implementing Cisco IOS Network Security）的考试以获得 `CCNA Security` 标识。`IINS` 考试涵盖以下额外主题（Cisco Systems, Inc., 2009b）：

- 描述现代基础设施面临的安全威胁
- 保护思科路由器
- 使用本地路由器数据库和外部 `ACS` 在思科路由器上实现 `AAA`
- 使用 `ACLs` 缓解针对思科路由器和网络的威胁
- 实现安全的网络管理和报告
- 缓解常见的第二层攻击
- 使用 `SDM` 实现 Cisco IOS 防火墙功能 set
- 使用 `SDM` 实现 Cisco IOS IPS 功能 set
- 使用 `SDM` 在思科路由器上实现站点到站点 `VPNs`

#### CCSP

此认证将 `CCNA Security` 认证列为前提，并要求申请者在授予证书之前参加额外的四项测试。这些测试是（Cisco Systems, Inc., 2009a）：

- 使用思科路由器和交换机保护网络
- 使用自适应安全设备（`ASA`）Foundation 保护网络
- 实现思科入侵防御系统
- 以及以下项之一：
  1. 实现思科网络准入控制（`NAC`）设备
  2. 实现思科安全监控、分析和响应系统
  3. 带有 `ASA` 的网络

#### CCIE Security

坦率地说，我从未见过有 `CCIE` 参与过渗透测试项目。我绝不是说在渗透测试项目中拥有一位 `CCIE` 是多此一举或毫无效率的——仅仅是 `CCIE` 有许多大得多的问题需要处理，而且他们的薪水远高于普通渗透测试工程师能拿到的。如果能聘请一位 `CCIE` 作为领域专家并在偶尔需要时使用，那将是太棒了，这在拥有永久性渗透测试团队的大型组织中是有可能实现的。否则，你可能只需要满足于拥有 `CCNA`、`CCNP` 或 `CCSP`（如果你真的足够幸运的话）。无论难度如何，了解 `CCIE Security` 专家精通哪些领域仍然很有帮助，这样你可以针对性地分配培训预算来扩展渗透测试团队的技能（表 3.2）（Cisco Systems, Inc）。
