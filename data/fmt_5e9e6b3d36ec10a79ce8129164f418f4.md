
## 补丁决策树

设备的暴露因子最初应用于组织的安全态势以确定其影响。根据影响是微不足道、轻微还是重大，可以做出决定（推迟应用补丁），或流程分支以解决任何安全态势问题。如果对安全的影响重大且对安全性的影响是直接或间接的，则可以决定尽快实施补丁。

如果对安全态势的影响轻微，则安全影响将指向流程影响决策（如果无安全影响）或技术影响评估（如果安全影响是间接或直接的）。如果无安全影响且非关键流程影响降级，则技术影响评估将产生安排补丁或尽快应用补丁的选项，具体取决于低、中、高技术影响评估的判定。

## ICS 资产清单与检测管理

`ICS 资产清单与检测管理工具` 在实施补丁决策树时至关重要。这些工具提供了识别 OT 网络资产上缺失补丁的能力。它们用于维护组织 OT 网络中运行设备的硬件和软件数据聚合。一个准备充分的工具将跟踪所有设备的硬件规格、IP 地址、操作系统版本、补丁修订版本、用户账户和补丁状态。它还将包括已知漏洞、攻击向量以及分配给每个设备的 CVSS 评分。

## 补丁测试

在 IT 和 OT 网络环境中，补丁的部署往往伴随着意想不到的后果。例如，考虑一个拥有数千台计算机的企业网络，在安装了导致意外或异常操作的软件补丁后。网络管理员可能不得不花费数小时时间在这么多机器上回滚安装。此外，由于所有这些机器功能丧失，用户可能会损失数小时的生产力。

由于 OT 网络要求极高的正常运行时间，与补丁相关的问题更加严重。例如，某些工业部门要求其 ICS 的正常运行时间达到 99.999%（也称为“五个九”正常运行时间）或更高。将此要求应用到日历年，你会发现 ICS 全年因任何原因停机的时间只能在 5.5 分钟或更少。考虑到这一点，不难理解为什么 OT 设备经常处于未打补丁的状态。

对于此类 ICS 环境，打补丁必须安排在其正常运行时间要求允许的范围内。在生产环境中，让一个原本正常运行的过程系统停摆，直到查明并修复失败的补丁工作的影响，成本可能非常高昂。如果其他工序恰好依赖于受影响的工序，问题将呈指数级复合。还有一些 OT 环境可能涉及位于多个站点的数百台设备打补丁。这种工作的范围使得补丁计划在这些组织中变得更加重要。

由于这两种网络环境都容易出现与补丁相关的问题，因此在部署到生产网络之前进行 `补丁测试` 尤为重要。这种测试通常使用运行与生产网络中相同类型硬件的 `测试床` 或 `沙箱` 网络来执行，以便紧密模拟操作环境。此配置通常专门用于测试目的。

实际测试应旨在验证补丁是否修复了供应商确定的问题或消除了漏洞。它还应验证补丁不会导致与网络上现有硬件和应用程序的冲突。此外，测试应包括在补丁安装后将其从系统中移除。

测试的这一部分应验证补丁能否在不影响设备或网络操作的情况下被移除。移除补丁可能有些棘手，补丁测试必须为安装人员提供恢复关键系统功能的程序和选项。

最后，应为每次补丁测试创建文档。首先，应创建清单和程序以指导现场的打补丁活动，确保打补丁过程的初始准确性和可重复性。补丁记录、测试记录以及任何配置变更都应记录在案，并作为配置管理文档的一部分予以保存。

NERC CIP-007-6 标准旨在确保新的网络资产或对现有网络资产的重大更改不会对现有网络安全控制产生不利影响。NERC CIP 的这一部分要求 BES 组织为其适用的网络资产（包括操作系统、应用程序、数据库平台和第三方软件/固件）提供补丁管理流程，用于跟踪、评估和安装网络安全补丁。标准的跟踪部分要求确定适用于其可打补丁设备的补丁发布来源。潜在补丁必须在该来源上次评估后的 35 个日历日内完成评估。

## 软件重装与固件管理

在 OT 网络中，`嵌入式设备` 不在软件平台上运行；相反，它们是 `固件驱动设备`。在许多情况下，该固件的管理不被视为整体安全策略的一部分。相反，它被视为一项运维职能，很少将其视为安全风险。回想一下，SCADA 和 OT 系统最初是为可靠性和安全性设计的——而非安全（Security）。

越来越多的证据表明，攻击者在攻击中以工业固件为目标。除了与社会工程学攻击和缺乏软件打补丁相关的众多漏洞和违规事件外，许多违规事件和漏洞发现都被追溯到固件问题。

微软 2021 年的一份报告指出，在过去两年期间，超过 80% 的企业经历过至少一次固件攻击。此外，NIST `国家漏洞数据库` (`NVD`) 显示，此类攻击在四年内增加了五倍。最著名的固件攻击包括 `Thunderclap` 和 `ThunderSpy` 攻击，它们通过英特尔 Thunderbolt 端口的硬件访问利用 Thunderbolt 控制器。在这些攻击中，攻击者将外部 Thunderbolt 控制器和可写内存芯片组合连接到 Thunderbolt 端口，即使机器处于关机状态，也能读取内核级内存。

`固件转储` 是提取并潜在利用端点、控制器、网络设备和服务器的固件设备中的漏洞和数据的另一种形式。在此过程中，读取器设备获得对存储固件的闪存设备的访问权限。这可以通过使用跳线或 Saleae 探针将读取器设备的引脚连接到集成电路的相应物理引脚来实现。接下来，读取器的应用程序执行一系列操作以检测目标设备的内存结构并将其内容复制到攻击者的内存设备中——这被称为 `十六进制内存转储`。从这一点开始，剩下的就是使用设计用于解包二进制文件并扫描其中有用信息的软件包，例如存储在固件中的密码、私钥、后门、敏感 URL 和配置文件。相反，攻击者也可以使用类似的读/写设备修改 OT 设备的固件，以在目标网络中建立高级持续性威胁。

因此，ICS 组织越来越意识到固件安全日益重要的地位。因此，他们专门将固件管理纳入其变更管理策略和审计实践中。

虽然安全打补丁是解决企业网络环境中许多软件漏洞的关键，但这是一个在 IT 产品生命周期中持续进行的循环过程。然而，SCADA/ICS 环境无法像企业打补丁流程那样频繁地关机和启动。

此外，针对 OT 设备的自动化 `固件管理解决方案` 尚未广泛普及。因此，大多数 ICS 打补丁操作仍然是人工进行的。然而，对于关键 ICS 环境，外部要求（如 NERC CIP 标准）将固件管理作为整体文档化配置管理流程的一部分。

## 监控

### 网络监控与审计

正如前文所述，网络监控和审计是任何组织网络管理/安全运营的关键组成部分。监控涉及使用系统或工具持续观察设备和网络对象，以查找特定类型的活动或事件。一般来说，任何网络中都应检查三种常见类型的活动：

*   **事件监控** 跟踪监控系统配置设置所要求的特定类型事件。当发生指定类型的活动时，监控系统会记录该事件并将其提交到日志以供后续检查。监控系统也可配置为创建并发送通知给指定接收人。
*   **网络监控** 检查监控系统配置设置所要求的网络流量和活动。网络监控职责可分布在多种不同类型的设备上，例如：监控来自网络外部威胁活动的入侵检测系统；监控网络流量的网络连接设备，如托管交换机、路由器、防火墙和工具设备；以及监控计算设备活动的服务器。
*   **安全监控** 跟踪已被定义为安全事件的特定类型活动的发生。这些事件通常包括登录/认证失败、尝试访问关键系统文件等项目。

#### 事件监控

**事件监控** 是跟踪活动并监视某些事件（发生）出现的做法。当指定事件出现在活动流中时，事件信息会被存储在日志中，并可能发出通知以告知指定人员该事件的发生。端点设备、服务器和网络设备都具备监控其不同类型事件操作的能力。

在 Microsoft Windows 环境中，主要的事件监控工具是内置的 `Event Monitor` 应用程序。该工具通过过滤器进行配置，过滤器定义了要监控和记录的事件的 Category（类别）、Description（描述）和 Type（类型）。可监控的事件类型包括 Errors（错误）、Warning Information（警告信息）、Success Audits（成功审核）和 Failure Audits（失败审核）。监控任务返回的信息存储在操作系统的 **Windows Event Log** 中。Windows 产品默认包含三种类型的事件日志——Application（应用程序）、Security（安全）和 System（系统）日志。

Linux 操作系统包含 12 个关键事件日志文件，服务器管理员需要监控这些文件以跟踪其设备上发生的重要事件。这些是与服务器、内核、服务及其设备上运行的应用程序相关的 Linux 日志文件。这些日志文件通常可分为四类：Application logs（应用程序日志）、Event logs（事件日志）、Service logs（服务日志）和 System logs（系统日志）。监控这些日志使管理员和信息安全人员能够在问题发生前预判即将出现的问题。

以下是需要监控的关键 Linux 日志：

*   `/var/log/messages`——通用系统活动日志，跟踪非内核启动错误和系统启动时的应用程序相关服务错误。
*   `/var/log/syslog`——基于 Debian 的通用系统活动日志，跟踪非内核启动错误和系统启动时的应用程序相关服务错误。
*   `/var/log/auth.log`——基于 Debian 和 Ubuntu 的认证和授权事件。失败的登录尝试、暴力破解攻击等。
*   `/var/log/secure`——基于 RedHat 和 CentOS 的认证和授权事件。失败的登录尝试、暴力破解攻击等。还跟踪 SSH 登录和错误。
*   `/var/log/boot.log`——系统初始化脚本启动消息。与不当关机、非计划重启和启动失败相关的问题。
*   `/var/log/dmesg`——关于设备状态和硬件错误的内核缓冲区消息。
*   `/var/log/kern.log`——关键内核信息。
*   `/var/log/faillog`——失败登录尝试的列表。是识别企图安全入侵活动的关键。
*   `/var/log/cron`——关于 cron 作业操作的信息。
*   `/var/log/yum.log`——使用 YUM 安装相关的新软件包安装信息。
*   `/var/log/mail.log`——邮件服务器日志，用于邮件服务器上运行的电子邮件相关服务——发送和接收的邮件、可能的垃圾邮件尝试、传入邮件的来源。
*   `/var/log/httpd`——与 httpd 错误相关的 Apache 服务器日志。
*   `/var/log/mysqld.log`——MySQL 日志。

有许多开源工具可用于集中监控和分析这些日志，以减轻管理员的负担。一款广泛使用的用于管理服务器日志的商业软件包是 `Nagios Log Server`。这些应用程序使管理员能够查看、排序、配置和分析来自网络中不同来源的日志。

#### 网络监控

IT 和 OT 网络通常都会采用多种不同的网络监控工具，包括防火墙、IDS/IPS 系统、操作系统日志、商业监控工具、定制监控工具和高级日志管理系统，以及 **Security Information Event Management (SIEM)** 工具。此外，还有许多 NSM 软件包用于提供对这些监控系统的自动化管理。提供有效的主动管理和监控计划需要以下组件：

*   **监控软件**——在监控软件配置期间，会选择各种硬件和软件操作进行跟踪。生成的事件信息可存储在日志文件中。
*   **报警/警告系统**——如果网络或其设备之一显示入侵或故障迹象，可立即以向管理控制台发送警报或向管理员发送寻呼的形式发出即时警告。
*   **远程管理功能**——管理员可从远程位置登录其端点、服务器和网络设备以检查其状况。诊断日志可远程查看，故障服务器系统可远程开机、关机甚至重启以恢复运行，无需等待技术人员到场。

使用这些关键网络管理组件，管理员可以主动监控和管理其网络以优化其可用性。通过在故障发生前向系统管理员提供预警，网络监控软件帮助他们识别并处理问题，防止其演变为灾难性故障，从而避免组织损失生产力和利润。

网络管理员通常将其监控/审计工具配置为评估特定网络对象或事件，然后在审计日志中跟踪这些结果以供后续评估。另一方面，一些防火墙、**入侵检测系统 (IDSs)** 和 NSM 软件可配置为在识别出异常模式或事件时，向管理员提供即时警报或通知。

组织网络模型的 OT 侧通常不必处理给基于 IT 的 NSM 操作带来困难的项目。这些项目包括加密网络、NAT 的广泛使用、设备在网段间移动、极端的网络流量水平和隐私担忧。应用于此功能的常用工具包括：

*   **Security Onion**——一个开源 Linux 发行版，专为威胁狩猎、企业级安全监控和日志管理而设计。它常用于 NIDS、HIDS、SOC 分析和静态分析。（参见 `www.securityonionsolutions.com`。）
*   **FlowBAT**——一个基础网络分析工具，提供网络可见性、安全监控、事件响应和低存储开销。（参见 `www.flowbat.com`。）

### 网络安全监控工具

*   **NetFlow** — 一种由 Cisco 开发的网络协议，用于收集 IP 流量信息并监控网络流量。当与 NetFlow 管理应用程序配合使用时，它可以将粒度数据转换为用户友好的图表和报告，以识别网络利用率。（参见 `www.solarwinds.com/netflow-traffic-analyzer`。）
*   **Pcap** — 一种 API 数据包捕获实用程序，旨在捕获网络流量。它通常用于异常分析，包括 ARP 欺骗、源自 ICS 的异常 DNS 流量，或识别格式错误的 Modbus 数据包。Pcap 实用程序可通过互联网上的许多渠道获得，并已集成到许多为特定用途设计的其他安全工具中。
*   **Zeek IDS**（前身为 Bro IDS）— 一种开源网络安全监控 IDS 工具。它提供全面的网络流量分析。它以日志的形式提供事务数据和提取的内容数据，汇总网络中移动的协议和文件。在 OT 网络中，它可以解析 DNP3 和 Modbus 协议。（参见 `www.zeek.org`。）
*   **Snort IDS** — 一种开源入侵防御系统（IPS），采用基于规则的方法来定义可接受/恶意的网络活动。它利用这些规则集来定位和识别不遵守规则的数据包，并为用户生成警报以供审查。它也可以配置为阻止这些数据包。Snort 还支持 DNP3 和 Modbus 预处理器，以及特定的 SCADA 包。（参见 `www.snort.org`。）
*   **Suricata IDS** — 一种开源威胁检测引擎。Suricata 将 IDS、IPS、NSM 和 Pcap 处理功能结合到一个产品中，旨在识别、阻止和评估网络攻击。Suricata 提供 DNP3 解析器和 ET SCADA 规则。（参见 `https://suricata.io`。）
*   **Syslog** — 一种行业标准的消息记录实用程序，它在知名或注册端口上监听网络，接收指示日志消息的协议请求，并将它们存储在 Syslog 服务器中。该工具通常用于系统管理和安全审计目的。它也广泛用于各种设备，包括网络、服务器和终端设备。（参见 `www.kiwisyslog.com`。）

### 安全监控

在关键 OT 环境中，组织可能需要实施一个或多个文档化的流程，以满足*安全事件监控*的特定要求。遵守这些要求涉及记录安全事件，并为组织确定需要警报的事件生成警报。

这些安全事件监控流程可能包括要求定期按给定间隔（例如，间隔不超过 15 个日历天）审查记录的安全事件样本或摘要，以识别网络安全事件。它们还可能包括要求保留安全事件日志一段规定的时间（例如至少连续 90 个日历天）。

在实施层面，安全监控涉及使用设备和工具来监控和报告网络或设备安全问题。在其最新的 SP800-137《联邦信息系统和组织的信息安全持续监控 (ISCM)》文档中，NIST 组织将持续安全监控定义为包括以下内容：

*   漏洞监控
*   应用监控
*   威胁监控

这些监控活动共同为 OT 安全管理员提供了对其系统、用户和活动的态势感知，以及针对其网络进行的可能攻击。通常有两类与这些活动相关的工具：

*   **主动工具** — 这些工具（如 IDS 和 SIEM）了解网络设备及其安全状态。这些工具帮助 ICS 安全管理员监控系统的多种不同类型问题，例如配置错误的设备、不正确的软件版本、设备固件缺陷、硬件故障、意外的内部和外部 IP 地址以及网络上的意外协议。然后，他们可以利用生成的信息来纠正设备配置，与供应商合作修复软件和固件问题，并加固其网络。
*   **检测工具** — 这些工具提供上下文感知的威胁监控、分析和警报功能。这些是持续的 NSM 工具，它们从网络设备和应用程序收集日志数据，分析网络流量，并向管理员提供威胁和高级问题的实时报告。OT 安全管理员可以使用这些工具来应对高级问题，例如零日恶意软件、命令与控制流量以及数据渗漏活动。

### 日志记录与审计

所有监控活动的工作产出都是针对特定事件或活动发生而产生的信息。为了使这些数据有用，必须保留它们直到可以被分析——无论是手动还是自动。网络管理员配置监控/审计工具以记录特定的网络活动或*事件*，然后在*审计日志*中跟踪其结果以供评估。*日志记录*是为了分析（审计）目的而记录和存储特定事件和事务的过程。如今几乎所有在用的计算和网络设备都以某种格式生成日志。

尽管审计日志通常提供多条信息，但组织主要使用审计日志来评估其网络的漏洞。因此，审计日志是每个管理员工作的重要组成部分，也是整体网络安全计划的关键。例行日志审计对于识别安全事件、策略违规、欺诈活动和操作问题至关重要。它也是事件发生后进行取证分析的关键。审计跟踪可能提供攻击者和入侵者的证据，无论他们来自本地网络内部还是网络外部。

在某些情况下，审计操作仅涉及筛选日志以查找错误或其他问题，这对网络管理员来说可能是一项艰巨的任务。然而，在企业和 OT 网络环境中审计日志的一个根本问题是网络内产生的海量日志数据。这往往导致日志仅以兼职或不规则的方式进行监控。
