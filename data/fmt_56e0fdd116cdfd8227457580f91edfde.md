
6. 单击 **添加用户或组** 按钮，将 **Authors** 添加到可以执行备份的列表中。

在课堂讲授安全概念时，我经常纠正大家的术语——**权利** 是指某人执行任务的特权，而 **权限** 是指某人对资源的访问级别。例如，Authors 组被授予了 Publications 文件夹的 **修改** *权限*。Authors 组并未被授予 **修改** *权利*。反之亦然——Authors 组被授予了执行备份的 *权利*，而非执行备份的 *权限*！

![Image](img/exam.jpg)

**对于 Security+ 考试，请记住：权限是指一个人对资源的访问级别，而权利是指他们执行特定任务的特权。**

## 组策略

Microsoft 环境允许您通过使用单个系统的本地安全策略来保护系统，或通过使用组策略在多个系统上配置安全设置。组策略用于配置网络中各系统的大量设置：

- **安装软件** 使用组策略，可以在客户端计算机启动时或用户登录时自动安装软件。

- **配置密码策略** 组策略允许您配置密码策略，包括密码历史记录、密码复杂度、密码长度和密码过期（称为最大密码期限）。

- **配置审核** 使用组策略，可以将审核策略部署到多个系统，以便跟踪这些系统上的事件。

- **配置用户权利** 组策略还用于配置用户权利，即执行任务的特权。

### 组策略功能

- **受限组** 使用组策略，您可以控制哪些用户或组是不同组的成员。

- **禁用服务和配置事件日志** 作为系统加固程序的一部分，您可以使用组策略在多个系统上禁用服务并配置事件日志。

- **文件系统权限** 使用组策略，您可以将权限部署到不同的文件夹。

- **软件限制** 组策略还可用于部署软件限制，以限制系统上允许运行的软件。

- **通过禁用功能锁定系统** 使用组策略，您可以通过从“开始”菜单、桌面和“控制面板”中移除功能来控制整个 Windows 桌面。

配置组策略时，了解不同类型的组策略非常重要，这些策略按可配置策略的位置进行分类。以下按位置列出组策略的类型：

- **本地** 本地策略是在一台系统上配置的策略，即您正在运行组策略对象编辑器的那台系统。要配置本地策略，您可以创建一个自定义 Microsoft 管理控制台 (MMC) 并添加组策略对象编辑器。

- **站点** 您可以将组策略部署到 Active Directory 站点，它能够应用于该站点中的多个域。

- **域** 您可以在域级别应用组策略，以便它影响 Active Directory 域中的所有用户和计算机。

- **组织单位 (OU)** 您可以在 OU 级别应用组策略，以便该策略仅应用于一小组用户或计算机。

刚才列出的策略位置也决定了这些策略的处理顺序。例如，当计算机启动时，它首先应用其本地策略，然后应用站点、域和任何 OU 策略。之所以提到这一点，是因为如果您在四个策略之间存在冲突设置，最后应用的策略生效（通常最终是域或 OU 策略）。

# 数据库安全

新的 Security+ 认证考试要求您了解数据库安全的各个方面。数据库是存储公司或实体大量信息的系统。数据库通常存储需要保护的敏感信息，作为安全人员，我们必须控制谁有权访问这些信息。我们可以采取许多步骤来保护数据库环境：

- **角色** 大多数数据库系统（包括 Microsoft SQL Server）使用角色在数据库系统中分配权限。例如，将用户放入 `sysadmin` 角色可赋予其 SQL Server 的完全管理功能，但将其放入 `diskadmin` 角色仅允许其管理磁盘文件。

- **权限** 在保护数据库环境时，您可以通过使用权限指定哪些用户有权访问哪些对象。例如，您可以授予 Bob 和 Sue `Orders` 表的 `select` 权限，但不授予 `update` 或 `delete` 权限。这意味着他们可以查看订单信息，但无法修改或删除数据。

- **加密** 在数据库中存储敏感信息时，加密数据非常重要。例如，在数据库中存储信用卡号或社会安全号码时，您应该加密该信息，使其以加密格式存储。这意味着从数据库读取数据时，需要先解密。

- **审核** 实施安全性时要记住的关键点之一是要为审核做计划。在规划数据库审核时，请自问：“发生什么事时我想知道？”例如，您想知道何时有人查看数据吗？想知道何时有人修改或更新数据库中的信息吗？想知道何时有人从数据库中删除记录吗？您可以在数据库中配置审核来跟踪所有这些活动。

## 账户策略实施

您应该熟悉许多与访问控制相关的概念和最佳实践。其中一些主题在本章中已经详细讨论过，但我希望创建一个在组织内实施账户策略的最佳实践摘要。

- **共享账户** 所有用户都必须拥有自己的账户，这一点至关重要，这样才能唯一地应用权限，并能审核每个人的操作。

- **凭据管理** 确保您拥有一个集中的凭据管理工具，以及一项关于用户必须多久更改一次密码的策略。

- **组策略** 应使用组策略将安全设置部署到网络上的所有服务器和客户端。

- **密码复杂性** 确保系统上的任何账户和网络访问都使用复杂密码。这些密码比非复杂密码更难破解。

- **过期** 确保密码在一段时间后过期，并且用户必须设置新密码。此外，请务必设置创建的任何临时用户账户的过期日期。

- **恢复** 确保能够恢复任何被删除的账户，或重置任何被遗忘的密码。

- **禁用** 请务必禁用任何不必要的账户，并为休假的员工禁用账户。

- **锁定** 配置账户锁定策略，以便在连续三次输入错误密码后，账户被锁定（不可用），直到管理员将其解锁。

- **密码历史记录** 一个需要配置的重要密码设置是密码历史记录选项——确保您的系统通过在历史记录中保留以前的密码，防止用户重复使用相同的密码。

- **密码重用** 确定贵组织关于重用密码的策略，并务必配置密码历史记录以强制执行该策略。

- **密码长度** 大多数组织要求最小密码长度为八个字符。

- **通用账户禁用** 与前面提到的共享账户要点类似，请确保没有为用户或系统共享而创建的通用账户，因为这会使审核操作变得困难。
