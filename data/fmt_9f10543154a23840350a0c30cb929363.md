
# 电路交换

**电路交换**最初是为在公用交换电话网上管理电话呼叫而开发的。在电路交换中，会在两个通信方之间创建一条专用的物理路径。一旦呼叫建立，双方之间的链路在整个通话过程中保持不变。这提供了固定或已知的传输时间、统一的质量水平，以及极少或没有信号丢失或通信中断。电路交换系统采用永久的物理连接。然而，`永久`一词仅适用于每个通信会话。该路径在单次通话期间是永久的。一旦路径断开，如果双方再次通信，可能会组装一条不同的路径。在单次通话期间，相同的物理或电子路径贯穿整个通信过程，且仅用于该次通信。电路交换授予当前通信伙伴对通信路径的独占使用权。只有在会话关闭后，路径才能被其他通信重用。

## 分组交换

最终，随着计算机通信的增加超过了语音通信，开发了一种新形式的交换。**分组交换**发生在消息或通信被分解成小段（通常是固定长度的分组，具体取决于所采用的协议和技术）并通过中间网络发送到目的地时。每个数据段都有自己的头部，其中包含源和目的地信息。每个中间系统读取头部，并用它将每个分组路由到其预期目的地。每个信道或通信路径仅在分组实际在其上传输时被保留使用。一旦分组发送完毕，该信道即可供其他通信使用。

分组交换不强制通信路径的独占性。它可以被视为一种逻辑传输技术，因为寻址逻辑决定了通信如何在通信伙伴之间穿越中间网络。表 12.2 对比了电路交换与分组交换。

### 表 12.2：电路交换 vs. 分组交换

| 电路交换 | 分组交换 |
| --- | --- |
| 恒定流量 | 突发流量 |
| 固定已知延迟 | 可变延迟 |
| 面向连接 | 无连接 |
| 对连接丢失敏感 | 对数据丢失敏感 |
| 主要用于语音 | 用于任何类型的流量 |

就安全而言，有几个潜在问题需要考虑。分组交换系统将来自不同源的数据放在同一物理连接上。这可能导致泄露、篡改或窃听。需要适当的连接管理、流量隔离，通常还需要加密，以防范共享物理路径带来的担忧。分组交换网络的一个优势是，它们不像电路交换那样依赖特定的物理连接。因此，当物理路径损坏或离线时，可以使用备用路径继续数据/分组传输。电路交换网络经常因物理路径故障而中断。

## 虚电路

**虚电路**（也称为通信路径）是在分组交换网络上两个特定端点之间创建的逻辑路径或电路。分组交换系统中有两种类型的虚电路：

*   **永久虚电路 (PVC)**
*   **交换虚电路 (SVC)**

PVC 类似于专用租用线路；逻辑电路始终存在并等待客户发送数据。PVC 是一种预定义的虚电路，始终可用。虚电路在不使用时可能会关闭，但需要时可即时重新打开。SVC 更像拨号连接，因为必须使用当前可用的最佳路径创建虚电路后才能使用，传输完成后再将其拆除。在任一类型的虚电路中，当数据包进入虚电路连接的 A 点时，该数据包会被直接发送到 B 点或虚电路的另一端。然而，同一传输中一个数据包的实际路径可能不同于另一个数据包的路径。换句话说，作为虚电路两端的 A 点和 B 点之间可能存在多条路径，但进入 A 点的任何数据包最终都会到达 B 点。

PVC 就像双向无线电或对讲机。每当需要通信时，你按下按钮开始说话；无线电会自动重新打开预定义的频率（即虚电路）。SVC 更像短波或业余无线电。每次想与某人通信时，你都必须将发射机和接收机调谐到新频率。

# WAN 技术

广域网链路用于连接远程的网络、节点或单个设备。这可以改善通信和效率，但也可能使数据面临风险。为了确保连接安全，尤其是在公共网络链路上，需要适当的连接管理和传输加密。WAN 链路和长距离连接技术可分为两大类：

**专用线路**（也称为**租用线路**或点对点链路）是无限期且持续为特定客户保留使用的线路（参见表 12.3）。专用线路始终开启并等待传输流量。客户局域网与专用 WAN 链路之间的链接始终是开放且已建立的。专用线路连接两个特定端点，且仅连接这两个端点。

### 表 12.3：专用线路示例

| 技术 | 连接类型 | 速度 |
| --- | --- | --- |
| 数字信号级别 0 (DS-0) | 部分 T1 | 64 Kbps 至 1.544 Mbps |
| 数字信号级别 1 (DS-1) | T1 | 1.544 Mbps |
| 数字信号级别 3 (DS-3) | T3 | 44.736 Mbps |
| 欧洲数字传输格式 1 | E1 | 2.108 Mbps |
| 欧洲数字传输格式 3 | E3 | 34.368 Mbps |
| 电缆调制解调器或电缆路由器 | | 10+ Mbps |

**非专用线路**是指在数据传输发生前需要建立连接的线路。非专用线路可用于连接任何使用相同类型非专用线路的远程系统。

标准调制解调器、DSL 和 ISDN 是非专用线路的示例。数字用户线路 (DSL) 是一种利用升级后的电话网络为消费者提供 144 Kbps 至 20 Mbps（或更高）速度的技术。DSL 有多种格式，如 ADSL、xDSL、CDSL、HDSL、SDSL、RASDSL、IDSL 和 VDSL。每种格式在具体提供下行和上行带宽方面有所不同。

DSL 线路距离中心局（即电话网络的一种特定类型的分发节点）的最大距离约为 5,000 米。

*综合业务数字网 (ISDN)* 是一种完全数字化的电话网络，同时支持语音和高速数据通信。ISDN 服务有两种标准类别或格式：

*   **基本速率接口 (BRI)** 为客户提供包含两个 B 信道和一个 D 信道的连接。B 信道支持 64 Kbps 的吞吐量，用于数据传输。D 信道用于呼叫建立、管理和拆除，带宽为 16 Kbps。尽管 D 信道并非设计用于支持数据传输，但 BRI ISDN 被称为可为用户提供总计 144 Kbps 的总吞吐量。
*   **主速率接口 (PRI)** 为用户提供包含多个 64 Kbps B 信道（2 到 23 个）和一个 64 Kbps D 信道的连接。因此，PRI 可部署的带宽范围从 192 Kbps 到 1.544 Mbps。但请记住，这些数字是带宽而非吞吐量，因为它们包含了不能用于实际数据传输的 D 信道（至少在大多数正常的商业实现中不能）。

## WAN 连接技术

对于需要多个地点之间甚至外部合作伙伴之间通信服务的公司，有许多可用的 WAN 连接技术。这些 WAN 技术在成本和吞吐量方面差异很大。然而，大多数共享一个共同特性：对连接的 LAN 或系统是透明的。WAN 交换机、专用路由器或边界连接设备提供了网络运营商服务与公司 LAN 之间所需的所有接口。边界连接设备称为 `信道服务单元/数据服务单元 (CSU/DSU)`。这些设备将 LAN 信号转换为 WAN 运营商网络使用的格式，反之亦然。CSU/DSU 包含 `数据终端设备/数据电路终接设备 (DTE/DCE)`，它为 LAN 的路由器（DTE）和 WAN 运营商网络的交换机（DCE）提供实际的连接点。CSU/DSU 充当转换器、存储转发设备和链路调节器。WAN 交换机只是针对特定类型的运营商网络、内置 CSU/DSU 的 LAN 交换机的专用版本。有许多类型的运营商网络或 WAN 连接技术，例如 `X.25`、`Frame Relay`、`ATM` 和 `SMDS`。

### X.25 WAN 连接

*X.25* 是一种较老的分组交换技术，曾在欧洲广泛使用。它使用永久虚拟电路在两个系统或网络之间建立特定的点对点连接。它是 Frame Relay 的前身，运作方式大致相同。由于与 Frame Relay 或 ATM 相比，其性能和吞吐率较低，X.25 的使用正在减少。然而，即使是 Frame Relay 和 ATM 也计划退役，因为它们正被光纤和无线解决方案取代。

### Frame Relay 连接

与 X.25 类似，*Frame Relay* 也是一种分组交换技术，也使用 PVC（参见虚拟电路的讨论）。然而，与 X.25 不同的是，Frame Relay 支持在单个 WAN 运营商服务连接上建立多个 PVC。Frame Relay 是一种第 2 层连接机制，它使用分组交换技术在通信端点之间建立虚拟电路。与专线或租用线（其成本主要基于端点间的距离）不同，Frame Relay 的成本主要基于传输的数据量。Frame Relay 网络是一种共享介质，通过在其上创建虚拟电路来提供点对点通信。所有虚拟电路彼此独立且不可见。

与 Frame Relay 相关的一个关键概念是 `承诺信息速率 (CIR)`。CIR 是服务提供商向客户保证的最小带宽。它通常远低于提供商网络的实际最大能力。每个客户可能会在其合同中建立并定义不同的 CIR。当有额外带宽可用时，服务网络提供商可能允许客户在短时间内超过其 CIR。这称为按需带宽。（尽管乍一听这似乎是一项杰出的福利，但现实是客户需为额外消耗的带宽支付溢价。）Frame Relay 作为一种面向连接的分组交换传输技术，在 OSI 模型的第 2 层（数据链路层）运行。

Frame Relay 要求在每个连接点使用 DTE/DCE。客户拥有 DTE，它充当路由器或交换机，为客户网络提供对 Frame Relay 网络的访问。Frame Relay 服务提供商拥有 DCE，它执行数据在 Frame Relay 上的实际传输，以及为客户建立和维护虚拟电路。然而，Frame Relay 现在是一种较老的技术，正在被更快的光纤解决方案逐步淘汰。

### ATM

*异步传输模式 (ATM)* 是一种单元交换 WAN 通信技术，不同于像 Frame Relay 这样的分组交换技术。它将通信分片为固定长度的 53 字节单元。固定长度单元的使用使 ATM 能够非常高效并提供高吞吐量。ATM 可以使用 PVC 或 SVC。与 Frame Relay 提供商一样，ATM 提供商可以为其租用服务保证最小带宽和特定的服务质量等级。当服务网络上有可用带宽时，客户通常可以按需消耗额外带宽，并按使用付费。ATM 是一种面向连接的分组交换技术。然而，ATM 现在是一种较老的技术，正在被更快的光纤解决方案逐步淘汰。

### SMDS

*交换多兆位数据服务 (SMDS)* 是一种无连接的分组交换技术。通常，SMDS 用于连接多个 LAN 以形成城域网 (MAN) 或广域网 (WAN)。SMDS 曾是连接通信不频繁的远程 LAN 的首选连接机制。SMDS 支持高速突发流量和按需带宽。它将数据分片为小的传输单元。

### 同步数字体系和同步光网络

同步数字体系 (SDH) 和同步光网络 (SONET) 是光纤高速网络标准。SDH 由国际电信联盟 (ITU) 标准化，SONET 由美国国家标准协会 (ANSI) 标准化。SDH 和 SONET 主要是硬件或物理层标准，定义基础设施和线路速率要求。SDH 和 SONET 使用同步时分复用 (TDM) 实现高速双工通信，且只需极少的控制和管理开销。

这两个标准只有细微差别，并使用相同的带宽级别层次结构。传输服务支持 51.48 Mbps 的基础速度级别，该级别支持 SDH 的同步传输信号 (STS) 和/或 SONET 的同步传输模块 (STM)。光载波 (OC) 一词也可替代 STS。SDH 和 SONET 的主要带宽级别如表 12.4 所示。

**表 12.4 SDH 和 SONET 的带宽级别**

| SONET | SDH | 数据速率 |
| :--- | :--- | :--- |
| STS-1 / OC-1 | STM-0 | 51.84 Mbps |
| STS-3 / OC-3 | STM-1 | 155.52 Mbps |
| STS-12 / OC-12 | STM-4 | 622.08 Mbps |
| STS-48 / OC-48 | STM-16 | 2.488 Gbps |
| STS-96 / OC-96 | STM-32 | 4.876 Gbps |
| STS-192 / OC-192 | STM-64 | 9.953 Gbps |
| STS-768 / OC-768 | STM-256 | 39.813 Gbps |

## SDH 和 SONET 拓扑

SDH 和 SONET 均支持网状和环状拓扑。这些光纤解决方案通常作为电信服务的骨干网实施，并将容量的划分或部分租赁给客户。SDH 和 SONET 的互连点或节点通常是加/析复用器（ADM），它允许将低速比特流连接或产品添加到主干线中或从中移除。

### 专用协议

某些 WAN 连接技术需要额外的专用协议来支持各种类型的专用系统或设备。其中三种协议是 SDLC、HDLC 和 HSSI：

#### 同步数据链路控制（SDLC）

**同步数据链路控制**用于专用租用线的永久物理连接，为大型主机（如 IBM 系统网络架构 [SNA] 系统）提供连接。SDLC 使用轮询，工作在 OSI 第 2 层（数据链路层），是一种面向比特的同步协议。

#### 高级数据链路控制（HDLC）

**高级数据链路控制**是 SDLC 的改进版本，专为串行同步连接设计。HDLC 支持全双工通信，并支持点对点和多点连接。与 SDLC 一样，HDLC 使用轮询并工作在 OSI 第 2 层（数据链路层）。HDLC 提供流量控制，并包含错误检测和纠正功能。

### 拨号封装协议

点对点协议（PPP）是一种封装协议，旨在支持 IP 流量通过拨号或点对点链路传输。PPP 允许支持串行链路的 WAN 设备实现多厂商互操作性。所有拨号连接和大多数点对点连接本质上都是串行的（而非并行）。PPP 包含广泛的通信服务，包括 IP 地址的分配和管理、同步通信的管理、标准化封装、复用、链路配置、链路质量测试、错误检测，以及功能或选项协商（如压缩）。

PPP 最初设计用于支持 CHAP 和 PAP 进行认证。然而，PPP 的新版本还支持 MS-CHAP、EAP 和 SPAP。PPP 还可用于支持 Internetwork Packet Exchange（IPX）和 DECnet 协议。PPP 是一项记录在 RFC 1661 中的互联网标准。它取代了串行线路互联网协议（SLIP）。SLIP 不提供认证、仅支持半双工通信、无错误检测能力，且需要手动建立和拆除链路。

# 杂项安全控制特性

当您为网络通信选择或部署安全控制时，需要结合您的环境、能力和安全策略评估众多特性。我们将在以下章节讨论这些问题。

## 透明性

顾名思义，*透明性*是服务、安全控制或访问机制的一种特性，确保其对用户不可见。透明性通常是安全控制的理想特性。安全机制越透明，用户绕过它甚至察觉其存在的可能性就越小。透明性意味着缺乏直接证据证明某项功能、服务或限制的存在，且其对性能的影响微乎其微。

在某些情况下，透明性可能需要作为可配置功能而非永久运行特性发挥作用，例如管理员在排查故障、评估或调整系统配置时。

## 验证完整性

要验证传输的完整性，可以使用称为哈希总和的校验和。在消息或数据包通过通信路径发送前，对其执行哈希函数。获得的哈希总和被添加到消息末尾，称为消息摘要。消息接收后，目标系统执行哈希函数，并将结果与原始哈希总和进行比较。如果两个哈希总和匹配，则可以高度确定消息在传输过程中未被篡改或损坏。哈希总和与循环冗余校验（CRC）类似，二者均作为完整性工具。在大多数安全事务系统中，使用哈希函数来保证通信完整性。

记录序列检查类似于哈希总和检查；不过，它验证的是数据包或消息序列的完整性，而非内容完整性。许多通信服务采用记录序列检查，以验证消息的任何部分均未丢失，且消息的所有元素均按正确顺序排列。

## 传输机制

传输日志记录是一种专注于通信的审计形式。传输日志记录记录有关源、目的地、时间戳、识别码、传输状态、数据包数量、消息大小等详细信息。这些信息可用于排查故障、追踪未经授权的通信，或被用作提取系统运作数据的手段。

传输错误纠正是内置于面向连接或面向会话的协议和服务中的一项能力。如果确定消息（整体或部分）已损坏、篡改或丢失，可请求源端重发全部或部分消息。重传控制决定在传输错误纠正系统发现通信问题时，是重发全部还是部分消息。重传控制还可决定是否发送多份哈希总和或 CRC 值，以及是否采用多条数据路径或通信通道。

# 安全边界

*安全边界*是指具有不同安全要求或需求的任意两个区域、子网或环境之间的交界线。安全边界存在于高安全区域和低安全区域之间，例如 LAN 和互联网之间。识别网络和物理世界中的安全边界至关重要。一旦识别出安全边界，就需要部署机制来控制跨越这些边界的信息流。

安全区域之间的划分可以采取多种形式。例如，对象可能具有不同的分类。每个分类定义了哪些主体可以对哪些对象执行哪些功能。分类之间的区别即构成安全边界。

安全边界也存在于物理环境和逻辑环境之间。为提供逻辑安全，必须提供不同于物理安全所用的安全机制。两者均须到位以提供完整的安全架构，且均须在安全策略中予以阐述。然而，二者不同，必须作为安全解决方案的独立要素进行评估。

安全边界（如受保护区域与非受保护区域之间的边界）应始终清晰定义。在安全策略中说明控制开始或结束的点，并在物理和逻辑环境中标识该点非常重要。逻辑安全边界是电子通信与贵组织依法负责的设备或服务进行接口的点。在大多数情况下，该接口有明确标识，并告知未经授权的主体其无访问权限，且尝试获取访问权将导致起诉。

物理环境中的安全边界通常是逻辑环境安全边界的反映。在大多数情况下，组织依法负责的区域决定了安全策略在物理领域的覆盖范围。这可以是办公室的墙壁、建筑物的墙壁，或是校园周围的围栏。在安全环境中，会张贴警示标志，表明禁止未经授权的访问，且企图获取访问权限的行为将被阻止并追究法律责任。

将安全策略转化为实际控制措施时，必须分别考虑每个环境和安全边界。只需推断可用的安全机制中，哪些能为特定环境和情况提供最合理、最具成本效益且最高效的解决方案。然而，所有安全机制都必须与其所保护对象的价值进行权衡。部署成本超过受保护对象价值的对策是不合理的。

## 预防或缓解网络攻击

通信系统容易遭受攻击，这与 IT 基础设施的任何其他方面容易受到攻击的方式大致相同。了解威胁和可能的对策是保护环境安全的重要组成部分。任何可能对数据、资源或人员造成危害的活动或状况都必须得到处理，并在可能的情况下加以缓解。请记住，危害不仅包括破坏或损坏，还包括泄露、访问延迟、拒绝访问、欺诈、资源浪费、资源滥用和丢失。针对通信系统安全的常见威胁包括拒绝服务、窃听、冒充、重放和篡改。
