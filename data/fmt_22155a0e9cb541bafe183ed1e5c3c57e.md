## 身份传播

身份传播是另一个问题。例如，如何将已登录用户的身份传播到网络服务中？幸运的是，有几种技术可以提供帮助。

**OpenID** OpenID 是一种作为身份方案的开放标准。OpenID 允许用户在每个网站上使用相同的身份登录许多不同的网站。例如，你可以使用你的 Facebook 用户名和密码登录新闻网站。OpenID 由 OpenID 基金会开发。OpenID 作为一套标准发挥作用，包括 OpenID 身份验证、属性交换、简单注册扩展和提供者身份验证策略交换。

**Shibboleth** Shibboleth 可以被描述为一种分布式网络资源访问控制系统。Shibboleth 通过允许共享基于 Web 的资源来增强联邦。当你使用 Shibboleth 时，目标网站信任源来验证其用户并正确地管理其属性。这种模型的缺点是身份验证机构和属性机构之间没有区别。

**WAYF** 你来自哪里（Where Are You From, WAYF）是一种单点登录方法，允许使用单一登录访问多个基于 Web 的服务。当请求者向其尚未验证其身份的远程网站提交请求时，远程网站会将请求者的登录请求转发给 WAYF 服务，然后由该服务在连接的机构的登录系统与外部基于 Web 的服务之间建立连接。这与 Kerberos 不同，因为它在公司基础设施内部运行以提供单点登录。WAYF 可用于连接不同的系统。

## XACML

XACML（可扩展访问控制标记语言）是一种基于 XML 的开放标准，用于规定网络服务、数字信息和企业安全应用程序的安全策略和权利。

XACML 的真实目的是用 XML 创建一种标准化的访问控制机制。XACML 是一种流行的数据编码格式，广泛用于各种应用程序，从 Microsoft Office 等文档格式到 Web 格式等。XACML 允许用户通过单一登录访问多个关联网站。因此，用户可能登录并访问一个航空公司网站，然后访问租车网站和酒店网站而无需重新进行身份验证。XACML 与 SAML 协同工作。XACML 使用规则引擎和元素来比较信息并确定用户权限。三个顶层 XACML 元素包括：

**策略集（Policy Set）** 这些是策略或策略子集，通过评估它们来确定该策略集的授权决策。

**策略（Policy）** 一组相关的规则，为该策略产生授权决策响应。

**规则（Rule）** 一个指示操作是否被允许的陈述。

## SOAP

简单对象访问协议（SOAP）是一种用于在计算机网络网络服务的实现中交换结构化信息的协议规范。SOAP 规定了消息格式以及数据类型的规则，包括结构化类型和数组。SOAP 依赖 XML 作为其消息格式，并利用这些信息在去中心化的分布式环境中的节点之间交换结构化和类型化信息。

SOAP 可以形成网络服务协议栈的基础层，提供一个基础消息框架，在该框架之上构建网络服务。SOAP 消息的基本结构是 SOAP 消息的顶部元素作为封包，带有可选的标头元素和一个强制的正文元素作为子元素。

## 单点登录

单点登录（SSO）允许用户验证一次即可访问其授权的所有资源。对单个资源的身份验证由 SSO 处理，且对用户透明。SSO 有几种变体，包括 Kerberos 和 Sesame。Kerberos 使用最广泛。Kerberos 由三部分组成：客户端、服务器和一个信任第三方（KDC），在它们之间进行调解。KDC 由两个系统组成：

**身份验证服务** 身份验证服务发放票据（TGT），用于进入票据颁发服务（TGS）。网络客户端在获取服务的票之前，必须先从身份验证服务获取 TGT。

**票据颁发服务** 票据颁发服务为客户端发放特定的票。

使用 Kerberos 的常用方法是将其用于验证，并将轻量目录访问协议（LDAP）作为目录服务存储身份验证信息。SSO 使用户只需登录一次即可无需管理多个不同的用户名和密码。通过使用一个或多个中央服务器，安全专业人员可以在需要时允许或阻止访问资源。SSO 的缺点是它可能是许多资源的单点故障，因此服务器的可用性会影响所有依赖它进行身份验证服务的可用性。此外，服务器的任何破坏意味着攻击者可以访问许多资源。

另一个问题是双向身份验证；如果未使用 SSO 同时验证客户端和服务器，则可能容易受到中间人攻击。即使实现了 SSO，只有身份验证过程是安全的。如果身份验证后使用了不安全的协议（如 FTP），密码和其他信息可能会被嗅探，或通过键盘记录或其他手段捕获。

# 服务配置标记语言

服务配置标记语言 (SPML) 是由 OASIS 设计的一种配置机制，旨在简化和优化身份管理，更具体地说是这些身份的配置。在人员必须访问一系列系统的大型环境中，SPML 可以提供一种自动化的手段来提供此类访问。例如，假设 A 公司聘请了一位新的“路面战士”（销售顾问）。现在，人力资源部门创建了员工档案，并通过应用程序使用 SPML，该用户的所有访问权限都将自动转发给 IT 人员。这可以包括对不同分类级别的多个系统的访问：目录访问、应用程序访问、VPN 等。在特定场景下，可能该公司的“路面战士”还需要访问合作伙伴 B 和公司 C 的网页版销售门户。这些访问请求也可以是自动化的。此外，SPML 简化了员工离职时移除权限的操作，同时使用户权限审计变得更容易，因为针对特定工作角色的人员有一套基准。SPML 还可以用于硬件（如发放给新员工的公司或笔记本电脑）的发放请求或归还请求。事实上，发放和归还请求都可以自动化。

SPML 版本 1 的详细说明可参阅 `www.ibm.com/developerworks/xml/library/x-secspml/`。SPML 目前处于版本 2，又称为 SPML2。SPML 有一个开源版本，称为 OpenSPML，并且有各种工具包允许通过非传统方法实现客户端与 SPML 服务器之间的互操作性——例如，使用 Java 类进行客户端-服务器的请求和响应。

# OAUTH

开放授权 (OAUTH) 是许多网站使用的一种授权标准。其目的是允许用户或服务访问资源。它允许用户在不提供个人凭据的情况下授权访问第三方资源。例如，你可能允许一个 Facebook 应用程序访问你的 Facebook 账户。在这种情况下，OAUTH 将允许授权服务器在 Facebook 账户持有者的批准下生成访问令牌并将其颁发给第三方应用程序。

# 证明 (Attestation)

# 基于证书的认证

基于证书的认证是使用 SSL 和证书进行身份验证和流量加密。证书的主体（Subject）通常是人，但也可能是一个网络设备，如路由器、Web 服务器或公司。基于证书的认证使用公钥基础设施 (PKI) 框架来管理、创建、存储和分配密钥以及数字证书。VeriSign 和 Thawte 等公司是作为证书颁发机构的示例。X.509 标准是数字证书的接受格式。图 10.5 显示了 X.509 数字证书的示例。
