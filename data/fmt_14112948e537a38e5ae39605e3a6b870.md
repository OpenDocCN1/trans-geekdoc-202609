
当风险成为现实时，`威胁主体`、`威胁行为体`或`威胁事件`已利用漏洞，导致一个或多个资产遭受损害或泄露。安全的全部目的是通过消除漏洞、阻断威胁主体和威胁事件对资产的危害，防止风险成为现实。作为一种风险管理工具，安全是防护措施的实施。

### 防护措施

`防护措施`、`安全控制`或`对策`是指任何能消除或减少漏洞、或针对一个或多个特定威胁提供保护的事物。防护措施可以是安装软件补丁、进行配置变更、雇佣安保人员、变更基础设施、修改流程、完善安全策略、更有效地培训人员、给周界围栏通电、安装照明等。它是指组织内任何能通过消除或减轻威胁或漏洞来降低风险的行动或产品。防护措施是缓解或消除风险的唯一手段。重要的是要记住，防护措施、安全控制或对策不一定非要购买新产品；重新配置现有元素，甚至从基础设施中移除元素，也是有效的防护措施。

### 攻击

`攻击`是威胁主体对漏洞的利用。换句话说，攻击是指任何试图利用组织安全基础设施漏洞以造成资产损坏、丢失或泄露的有意行为。攻击也可以被视为任何违反或未能遵守组织安全策略的行为。

### 违规

`违规`是指安全机制被威胁主体绕过或挫败的事件。当违规与攻击相结合时，可能导致渗透或入侵。渗透是指威胁主体通过绕过安全控制获得了对组织基础设施的访问权限，并能直接威胁资产的状态。

资产、威胁、漏洞、暴露、风险和防护措施这些要素是相互关联的，如图 2.4 所示。威胁利用漏洞，从而导致暴露。暴露即风险，风险通过防护措施来缓解。防护措施保护受威胁危害的资产。

### 识别威胁和漏洞

风险管理的一个基本部分是识别和检查威胁。这涉及为组织已识别的资产创建一份详尽的所有可能威胁清单。该清单应包括威胁主体和威胁事件。重要的是要记住，威胁可能来自任何地方。IT 威胁不局限于 IT 来源。在编制威胁清单时，请务必考虑以下因素：

*   病毒
*   级联错误（一系列不断升级的错误）和依赖性故障（由依赖不存在的事件或项目引起）
*   授权用户的犯罪活动（间谍活动、知识产权窃取、挪用公款等）
*   移动（振动、震动等）
*   故意攻击
*   重组
*   授权用户患病或流行病
*   恶意黑客
*   不满的员工
*   用户错误
*   自然灾害（地震、洪水、火灾、火山、飓风、龙卷风、海啸等）
*   物理损坏（挤压、抛射物、电缆切断等）
*   数据、资源或服务的滥用
*   数据分类或安全策略的变更或妥协
*   政府、政治或军事的入侵或限制
*   处理错误、缓冲区溢出
*   人员特权滥用
*   温度极端
*   能量异常（静电、电磁脉冲、射频 [RF]、断电、电压浪涌等）
*   数据丢失
*   信息战
*   破产或业务活动的变更/中断
*   编码/编程错误
*   入侵者（物理和逻辑）
*   环境因素（气体、液体、生物体的存在等）
*   设备故障
*   物理盗窃
*   社会工程学

在大多数情况下，风险评估和分析应由团队而非单个个人执行。此外，团队成员应来自组织内的不同部门。通常不要求所有团队成员都是安全专业人员，甚至不要求是网络/系统管理员。基于组织人口统计特征的团队多样性将有助于详尽地识别和应对所有可能的威胁和风险。

### 风险评估/分析

风险管理/分析主要是高层管理人员的工作。他们有责任通过定义工作的范围和目的，发起并支持风险分析和评估。执行风险分析的实际过程通常委托给安全专业人员或评估团队。然而，所有风险评估、结果、决策和结果都必须被高层管理人员理解并批准，作为提供审慎应有照顾的一个要素。

### 所有 IT 系统都存在风险

所有 IT 系统都存在风险。无法消除 100% 的所有风险。相反，高层管理人员必须决定哪些风险是可接受的，哪些是不可接受的。确定哪些风险是可接受的，需要进行详细且复杂的资产和风险评估。

一旦你制定了威胁清单，就必须单独评估每个威胁及其相关风险。有两种风险评估方法：定量和定性。`定量风险分析`为资产损失分配实际的美元数字。`定性风险分析`为资产损失分配主观且无形的价值。这两种方法对于完整的风险分析都是必要的。大多数环境采用这两种风险评估方法的混合体，以获得对其安全顾虑的平衡视角。

### 定量风险分析

定量方法产生具体的概率百分比。这意味着最终结果是一份报告，其中包含风险等级、潜在损失、对策成本和保护措施价值的美元数字。这份报告通常相当容易理解，尤其是对于熟悉电子表格和预算报告的人来说。可以将定量分析视为给风险分配数量的行为——换句话说，就是为每个资产和威胁标上价格。然而，纯粹的定量分析是不够的；并非分析的所有要素和方面都可以量化，因为其中一些是定性的、主观的或无形的。

定量风险分析的过程始于资产估值和威胁识别。接下来，你需要估算每种风险的潜在程度和频率。然后利用这些信息计算各种成本函数，用于评估保护措施。

定量风险分析的六个主要步骤或阶段如下（图 2.5）：

1.  盘点资产，并分配价值（资产价值，即 `AV`）。（资产价值将在本章后面名为“资产估值”的部分进一步详述。）
2.  调查每项资产，并列出每个单独资产的所有可能威胁。对于列出的每个威胁，计算暴露因子（`EF`）和单次损失期望值（`SLE`）。
3.  执行威胁分析，计算每个威胁在一年内实现的可能性——即年化发生率（`ARO`）。
4.  通过计算年化损失期望值（`ALE`）得出每个威胁的总体损失潜力。
5.  针对每个威胁研究对策，然后根据应用的对策计算 `ARO` 和 `ALE` 的变化。
6.  对每个资产的每个威胁的每个对策执行成本/效益分析。为每个威胁选择最合适的响应。

与定量风险分析相关的成本函数包括暴露因子、单次损失期望值、年化发生率和年化损失期望值：

#### 暴露因子

**暴露因子（`EF`）** 代表如果特定资产因已实现的风险而受到侵害，组织将经历的损失百分比。`EF` 也称为损失潜力。在大多数情况下，已实现的风险不会导致资产的完全损失。`EF` 仅表示因单一已实现风险而导致的预期总体资产价值损失。对于易于替换的资产（如硬件），`EF` 通常较小。对于不可替代或专有的资产（如产品设计或客户数据库），`EF` 可能非常大。`EF` 以百分比表示。

#### 单次损失期望值

计算 `SLE` 需要 `EF`。**单次损失期望值（`SLE`）** 是针对特定资产的单一已实现风险所关联的成本。它表明如果资产因特定威胁发生而受损，组织将经历的确切损失金额。

`SLE` 使用以下公式计算：

*   `SLE = 资产价值 (AV) * 暴露因子 (EF)`
*   或者更简单地：
*   `SLE = AV * EF`

`SLE` 以美元价值表示。例如，如果一项资产价值 200,000 美元，且针对特定威胁的 `EF` 为 45%，则该资产针对该威胁的 `SLE` 为 90,000 美元。

#### 年化发生率

**年化发生率（`ARO`）** 是特定威胁或风险在一年内发生（即实现）的预期频率。`ARO` 的范围可以从 0.0（零），表示该威胁或风险永远不会实现，到一个非常大的数字，表示该威胁或风险频繁发生。计算 `ARO` 可能很复杂。它可以源自历史记录、统计分析或猜测。`ARO` 计算也称为概率确定。某些威胁或风险的 `ARO` 是通过将单次发生的可能性乘以可能发起该威胁的用户数量来计算的。例如，塔尔萨市发生地震的 `ARO` 可能为 .00001，而旧金山发生地震的 `ARO` 可能为 .03（针对 6.7 级以上），或者你可以将塔尔萨市地震的 `ARO` .00001 与塔尔萨市某办公室电子邮件病毒的 `ARO` 10,000,000 进行比较。

#### 年化损失期望值

**年化损失期望值（`ALE`）** 是特定已实现威胁针对特定资产的所有实例可能产生的年度成本。

`ALE` 使用以下公式计算：

*   `ALE = 单次损失期望值 (SLE) * 年化发生率 (ARO)`
*   或者更简单地：
*   `ALE = SLE * ARO`

例如，如果一项资产的 `SLE` 为 90,000 美元，且特定威胁（如完全断电）的 `ARO` 为 .5，则 `ALE` 为 45,000 美元。另一方面，如果特定威胁（如用户账户泄露）的 `ARO` 为 15，则 `ALE` 将为 1,350,000 美元。

#### 计算实施保护措施后的年化损失期望值

除了确定保护措施的年成本外，还必须计算实施保护措施后该资产的 `ALE`。这需要针对该保护措施特定的新 `EF` 和 `ARO`。在大多数情况下，即使应用了保护措施，资产的 `EF` 保持不变。（回想一下，`EF` 是风险实现时所遭受的损失金额。）换句话说，如果保护措施失效，资产会受到多大损害？可以这样考虑：如果你穿了防弹衣，但防弹衣未能阻止子弹穿透你的心脏，你仍然会遭受与未穿防弹衣时相同的伤害。因此，如果保护措施失效，资产上的损失通常与没有保护措施时相同。然而，某些保护措施*确实*能减少由此产生的损害，即使它们未能完全阻止攻击。例如，虽然火灾仍可能发生，且设施可能因火灾和喷淋系统的水而受损，但总损失可能比整栋楼烧毁要小。

即使 EF 保持不变，保护措施也会改变 ARO。事实上，保护措施的全部意义在于降低 ARO。换句话说，保护措施应减少攻击成功造成资产损害的次数。最理想的保护措施会将 ARO 降至零。虽然存在一些完美的保护措施，但大多数并非如此。因此，许多保护措施的应用后 ARO 比未防护时的 ARO 要小（希望是小得多），但通常不为零。有了新的 ARO（以及可能的新 EF），即可计算应用保护措施后的新 ALE。

计算出实施保护措施前的 ALE 和实施后的 ALE 后，执行成本/收益分析还需要一个值：保护措施的年成本。

#### 计算保护措施成本

对于每个特定风险，必须从成本/收益角度评估一种或多种保护措施（或对策）。为执行此评估，必须先为每个威胁编制保护措施清单。然后为每个保护措施分配一个部署值。实际上，必须衡量保护措施的部署值或成本与受保护资产的价值。因此，受保护资产的价值决定了保护机制的最大支出。安全应具有成本效益，因此用于保护资产的现金或资源不应超过该资产对组织的价值。如果对策成本大于资产价值（即风险成本），则应接受该风险。

计算对策价值涉及众多因素：

*   采购、开发和许可成本
*   实施和定制成本
*   年度运营、维护、管理等成本
*   年度维修和升级成本
*   生产力提升或损失
*   环境变更
*   测试和评估成本

了解保护措施的潜在成本后，即可评估其应用于基础设施后的收益。如前所述，保护措施的年成本不应超过预期的资产年损失成本。

#### 计算保护措施成本/收益

此过程中的最终计算之一是*成本/收益计算*或*成本/收益分析*，以确定保护措施是否在不过高成本的前提下真正提高了安全性。为判断保护措施是否在财务上合理，请使用以下公式：

> 实施保护措施前的 ALE – 实施保护措施后的 ALE – 保护措施年成本（ACS）= 保护措施对公司的价值

如果结果为负，则该保护措施在财务上不是负责任的选择。如果结果为正，则该值代表组织部署该保护措施可能获得的年节省额，因为发生率不等于发生保证。

评估保护措施时，不应仅考虑其带来的年节省或损失。还应考虑法律责任和审慎尽职调查问题。在某些情况下，部署保护措施亏损比冒资产泄露或损失时的法律责任风险更合理。

回顾一下，要执行保护措施的成本/收益分析，必须计算以下三个要素：

*   资产-威胁组合的实施对策前 ALE
*   资产-威胁组合的实施对策后 ALE
*   ACS（保护措施的年成本）

有了这些要素，即可得出此特定保护措施针对特定风险、特定资产的成本/收益公式值：

*   （实施对策前 ALE – 实施对策后 ALE）– ACS
*   或更简单地表示为：
*   （ALE1 – ALE2）– ACS

成本/收益公式计算结果值最大的对策，针对特定的资产-威胁组合部署最具经济意义。

必须认识到，定量风险评估过程中所有计算得出的最终值，用于优先级排序和选择。这些值本身并不真正反映现实世界中因安全漏洞造成的损失或成本。这显而易见，因为该过程需要大量的猜测、统计分析和概率预测。

为影响每项资产的每项风险的每项保护措施计算出成本/收益后，必须对这些值进行排序。在大多数情况下，成本/收益值最高的保护措施是针对特定风险、特定资产的最佳实施选择。但如同现实世界中的所有事物，这只是决策过程的一部分。虽然非常重要且通常是主要指导因素，但它不是唯一的数据要素。其他因素包括实际成本、安全预算、与现有系统的兼容性、IT 人员的技能/知识储备、产品可用性，以及政治因素、合作伙伴关系、市场趋势、时尚、营销、合同和偏袒。作为高级管理层甚至 IT 人员，您有责任获取或利用所有可用数据和信息，为组织做出最佳安全决策。

大多数组织的预算有限且极其紧张。因此，以最低成本获得最佳安全性是安全管理的关键部分。要有效管理安全职能，必须评估预算、每项安全控制的收益和性能指标以及必要资源。只有经过彻底评估，才能确定哪些控制不仅对安全有益，而且对利润也有益。

### 定性风险分析

定性风险分析更多基于场景而非计算器。您不给可能的损失分配确切的美元数字，而是按等级对威胁进行排序，以评估其风险、成本和影响。由于纯定量风险评估不可能实现，平衡定量分析结果至关重要。将定量和定性分析结合成最终组织风险评估的方法称为混合评估或混合分析。执行定性风险分析的过程涉及判断、直觉和经验。可使用多种技术执行定性风险分析：

*   头脑风暴
*   德尔菲法
*   故事板
*   焦点小组
*   调查
*   问卷
*   清单
*   一对一会议
*   面谈

采用哪种机制取决于组织文化以及涉及的风险和资产类型。通常会同时采用多种方法，并在最终提交给高层管理的风险分析报告中对比其结果。

#### 场景

### 基本流程

所有这些机制的基本流程都涉及场景的创建。**场景** 是对单一主要威胁的书面描述。该描述侧重于威胁如何被引发，以及其发生可能对组织、IT 基础设施和特定资产产生什么影响。通常，场景限制在一页文本以内，以保持其可管理性。对于每个场景，都会描述一种或多种防护措施，这些措施可以完全或部分地防范场景中讨论的主要威胁。分析参与者随后为场景分配威胁级别、损失潜力以及每种防护措施的优势。这些分配可以非常简单——例如高、中、低，或基本的 1 到 10 数字等级——也可以是详细的论述式回答。所有参与者的回答随后被汇编成一份单一报告，提交给高层管理人员。有关参考评级和级别的示例，请参阅美国国家标准与技术研究院 (NIST) 特别出版物 (SP) 800-30 中的表 3-6 和表 3-7：

[`csrc.nist.gov/publications/nistpubs/800-30/sp800-30.pdf`](http://csrc.nist.gov/publications/nistpubs/800-30/sp800-30.pdf)

定性风险分析的有效性和效度会随着参与评估的人员数量和多样性的增加而提高。只要可能，应包含组织层级中每个层面的一名或多名人员，从高层管理人员到最终用户。同样重要的是，要包含每个主要部门、处、办公室或分支机构的横截面人员。

#### Delphi 技术

`Delphi 技术` 可能是前面列表中唯一一种不能立即被识别和理解的机制。**Delphi 技术** 只是一种匿名的反馈与响应过程，用于使群体达成匿名共识。其主要目的是引出所有参与者诚实且不受影响的回答。参与者通常聚集在一个会议室中。针对每次反馈请求，每位参与者匿名在纸上写下他们的回答。结果被汇总并呈现给小组进行评估。该过程重复进行，直到达成共识。

定量和定性风险分析机制都能提供有用的结果。然而，每种技术都涉及评估同一组资产和风险的独特方法。审慎的应有注意义务要求同时采用这两种方法。**表 2.2** 描述了这两种系统的优缺点。

**表 2.2 定量与定性风险分析的比较**

| 特征 | 定性 | 定量 |
| :--- | :--- | :--- |
| 采用复杂函数 | 否 | 是 |
| 使用成本/效益分析 | 否 | 是 |
| 产生具体数值 | 否 | 是 |
| 需要猜测 | 是 | 否 |
| 支持自动化 | 否 | 是 |
| 涉及大量信息 | 否 | 是 |
| 客观 | 否 | 是 |
| 使用意见 | 是 | 否 |
| 需要大量时间和精力 | 否 | 是 |
| 提供有用且有意义的结果 | 是 | 是 |

### 风险响应

风险分析的结果有很多：

*   所有资产的完整详细估值
*   详尽的威胁和风险清单、发生率以及实现时的损失程度
*   特定威胁的防护措施和对策清单，标识其有效性和 ALE
*   每种防护措施的成本/效益分析

这些信息对于管理层做出关于防护措施实施和安全策略变更的明智、理智的决策至关重要。

一旦风险分析完成，管理层必须处理每个特定风险。对风险有几种可能的响应：

*   降低或缓解
*   转移或分担
*   接受
*   威慑
*   规避
*   拒绝或忽略
