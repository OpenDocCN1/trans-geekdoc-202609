
# 12.11 SQL：存在量词子查询

存在量词子查询可用于 `where` 子句的搜索条件中，从而形成以下形式的整体查询：

```
select …
from …
where [ not ] exists
    ( select * …)
```

因为子查询结果中仅关心行的存在与否，所以在存在量词子查询的 `select` 列表中通常直接使用 `*` 代替列列表。

在 SQL-92 之前，存在量词子查询是唯一可以返回多列的子查询，因为在 SQL-89 中，成员资格子查询和比较子查询都必须返回单列。某些 SQL 方言至今仍保留这一限制。

## 示例：武术俱乐部成员及其段位

让我们看一些使用图 12.61 中填充模式的示例。`Member` 表存储武术俱乐部成员的详细信息。`Ranked` 表指示成员在何种武术中达到了什么段位（如有）。黑带以下使用 *kyu* 级，黑带及以上使用 *dan* 级。

![图 12.61 武术俱乐部成员及其段位（如有）。](img/f12-61-9780443237904.jpg)

图 12.61 武术俱乐部成员及其段位（如有）。

考虑查询：谁（成员编号和姓名）至少在一种武术中是黑带？我们可以用存在性子查询在 SQL 中表述此查询，如下所示。这也是一个相关子查询，因为子查询条件引用了外部表（`Member`）。由于外部表与内部表（`Ranked`）名称不同，因此无需为其引入别名。存在性条件检查成员在 `Ranked` 表中是否有 `dan` 段位的行。

```
select memberNr, memberName
from Member
where exists
    (select * from Ranked
     where memberNr = Member.memberNr
     and rank like '% dan')
```

同样的查询也可以用成员资格查询来表述，例如：

```
select memberNr, memberName
from Member
where memberNr in
    (select memberNr from Ranked
     where rank like '% dan')
```

要列出**没有**黑带的成员，我们只需在之前的查询中用 `not exists` 替换 `exists`，用 `not in` 替换 `in`。以下查询也适用吗？

```
select memberNr, memberName
from Member natural join Ranked
where rank not like '% dan'
```

毫无疑问，你已经意识到，这会失败，因为它也会返回同时拥有 `dan` 段位和非 `dan` 段位的成员。

作为一个更复杂的例子，假设俱乐部成员由姓氏和名字组合来标识。此填充模式如图 12.62 所示。

![图 12.62 成员具有复合引用方案。](img/f12-62-9780443237904.jpg)

图 12.62 成员具有复合引用方案。

现在考虑查询：谁在柔道中未排名？存在性子查询解决方案很简单，同时匹配姓氏和名字：

```
select surname, firstname from Member
where not exists
    (select * from Ranked
     where surname = Member.surname
     and firstname = Member.firstname
     and art = 'judo')
```

虽然我们可以用成员资格子查询来做这件事，但在 SQL-89 中逻辑变得更复杂，因为我们不能将列名对（此处为 `surname, firstname`）作为 `in` 运算符的参数。在以下查询中，`surname` 列使用 `in` 运算符进行比较，而 `firstname` 则使用相关性进行匹配：

```
select surname, firstname from Member
where surname not in
    (select surname from Ranked
     where firstname = Member.firstname
     and art = 'judo')
```

对于这种情况，存在性解决方案更容易理解。

该查询的另一种解决方案是使用连接运算符将姓名部分合并为单个字符串（回想一下，某些方言使用 `+` 代替 `||`）：

```
select surname, firstname from Member
where surname || firstname not in
    (select surname || firstname from Ranked
     where art = 'judo')
```

更多相关子查询和存在性子查询的示例将在高级 SQL 补充材料（附录 C）的集合比较查询上下文中讨论。

# 12.12 SQL：递归查询

层次数据结构在业务中很常见。常见示例包括包含部门和子部门的组织结构，以及涉及组件和子组件的物料清单信息。递归提供了一种查询此类结构的强大方式。

在 SQL 中，递归查询涉及三阶段过程：

1. 创建初始结果集（有时称为 *anchor*）。
2. 递归地将进一步查询的结果添加到初始结果集中。
3. 对累积结果执行最终查询。

递归通常需要某种终止条件。此处终止是隐式的：当第 2 阶段没有更多结果可添加时，递归结束。特定的 SQL 实现可能提供控制最大递归深度的功能，以避免无限循环。

创建初始结果集涉及 *公用表表达式*（`CTE`）的概念，该概念最早于 SQL:1999 中引入。公用表表达式可以想象为一个视图定义，其作用域仅限于紧随其后的查询。下一章讨论 *视图*，视图基本上是存储在系统中的命名 `select` 语句。视图的结果可以视为一个表，尽管这种表通常不以任何物理意义存储。`CTE` 的基本语法为：

```
with cte-name [ (col-list) ] as cte-query-definition
query-statement
```

由于 `cte-query-definition` 返回不同的列，因此不需要 `col-list`。紧随 `with` 子句之后的 `query-statement` 使用 `cte-query-definition` 的结果，引用 `cte-name`。任何其他查询试图引用此 CTE 都会失败，这与视图定义不同。这种结构在 SQL 中还有其他用途，但我们这里关注的是它在形成递归查询中所起的作用。递归查询的锚定部分可以涉及多个子查询，其结果使用标准 SQL 集合操作（`union`、`intersect` 和 `except`）进行组合，但为简单起见，我们这里假设只有一个查询。

锚定结果形成后，递归的结果将使用 SQL 的 `union all` 操作添加。在每个阶段，查询的递归部分将累积结果作为输入，运行查询，并将结果添加到结果集中。这将持续到不再产生新结果为止。通常，当层次结构中不再有未探索的节点时，就会发生这种情况。

递归 CTE 的框架如下所示：

```
with cte-name [ (col-list) ] as anchor-query-definition
union all
   recursive-query-definition
   query-statement
```

为了使其更具体，我们将看一个简单的示例。图 12.63 显示了一个表的模式，该表保存组织中部门的层次结构信息，以及示例数据填充。

![图 12.63 (a) 表模式和数据 (b) 部门层次结构。](img/f12-63-9780443237904.jpg)

图 12.63 (a) 表模式和数据 (b) 部门层次结构。

如图 12.63(b) 所示，该组织有三个部门层级。我们可能想要编写各种查询来利用层次结构中固有的父子关系，而递归查询是实现这一目标的自然方式。鉴于图 12.63 中场景的简单性，使用递归查询可能显得大材小用，但我们可以轻松演示其基本特性。

我们将从一个简单的逐层部门列表开始，以说明结果是如何产生的。查询如下：

```
with myCTE (deptId, deptName, parentDept, "level") as (
    select anchor.deptId, anchor.deptName, anchor.parentDept, 1 as "level"
    from Dept as anchor
    where parentDept is null
    union all
    select child.deptId, child.deptName, child.parentDept, "level" + 1
    from Dept as child join myCTE as parent
    on child.parentDept = parent.deptId
)
select deptId, deptName, "level" from myCTE
```

执行后，查询产生以下结果：

| --- |

此处，“level”列表示层次结构中的相对深度，以 1 为顶层（“level”此处是分隔标识符，因为它是 SQL 中的保留关键字）。

我们通过指定 `where parentDept is null` 将顶层作为锚定，因此锚定元组为 `<101, 'Management', null, 1>`。在下一层，我们现在查找 `deptId` 为 101 的部门。`union all` 操作添加元组 `<201, 'Sales', 101, 2>` 和 `<202, 'Production', 101, 2>`。

CTE 递归部分中的 `join` 现在可以添加 Sales 下的部门。Production 没有子部门，因此 `join` 不产生结果。添加完 Sales 的三个子部门后，`join` 没有其他可能性（因为没有部门的父级 `deptId` 为 301、302 或 303），因此递归结束。

执行 CTE 后的 `select` 语句时，它会为 `myCTE` 创建结果集，然后应用其自身的查询，在本例中仅提取递归 CTE 产生的三列。

当然，最终结果取决于作用于 CTE 结果的查询，并且不必列出 CTE 的所有行。

例如，以下递归查询查找层次结构中特定节点下的员工总数——同样，我们采用了顶层节点，但只需对定义锚定的查询进行简单更改，就可以采用层次结构中的任意节点。

```
with myCTE (deptId, totalStaff, parentDept) as (
    select anchor.deptId, anchor.totalStaff, anchor.parentDept
    from Dept as anchor
    where parentDept is null
    union all
    select child.deptId, child.totalStaff, child.parentDept
    from Dept as child join myCTE as parent
    on child.parentDept = parent.deptId
)
select sum(totalStaff) as totalStaff from myCTE
```

这将产生预期结果：

![](img/u12-25-9780443237904.jpg)

显然，我们本可以使用简单得多的查询来产生这个特定结果，但总体而言，递归允许我们构建针对层次结构的查询，而用其他方式很难（或笨拙地）实现。大多数商业 SQL 方言都支持 CTE 和递归，但细节可能与我们在此概述的不同。

# 12.13 SQL：更新表填充

一般来说，数据库表填充的“更新”可能涉及三种关系操作中的任意一种：向表中插入一行、从表中删除一行，或修改一行上的一个或多个值。在 SQL 中，修改操作称为“update”，因此该术语有时用于这种受限含义。

让我们首先考虑如何向表中 `insert rows`。为此，SQL 提供了两种基本形式的 `insert` 语句。第一种向表添加*单行数据*。其 SQL-89 语法为：

```
insert into tablename [ (col-list ) ]
values (constant-list )
```

如果未列出列，则必须提供所有列的值。字符串必须用单引号分隔。空值可作为 `null` 输入。SQL-92 引入了 `insert` 语句的以下形式：`insert into` *tablename* `default values`。这将添加一行，其中每列均赋予其默认值（可能为 `null`）。如果任何列没有默认值，则会导致错误。SQL:1999 增加了使用构造函数和覆盖的选项。

作为一个简单示例，考虑表模式 `Employee` ( empNr, surname, firstname, gender, `[phone]`, `[email]`)。假设一名名为“Eve Jones”的新女员工被分配了员工编号 715。要将这位新员工的详细信息添加到表中，可以使用以下任一命令。

```
insert into Employee
values ( 715, 'Jones', 'Eve', 'F', null, null )
```

或

```
insert into Employee ( empNr, surname, firstname, gender )
values ( 715, 'Jones', 'Eve', 'F' )
```

商业系统还提供从文件快速批量加载数据的命令（例如，采用分隔符分隔的 ASCII 格式）。用户的数据录入通常通过屏幕表单进行，而不是直接录入表中。由于表单上的约束或表间约束，单行插入可能要求在同一事务中插入其他数据。事务是一系列 SQL 语句，由 `commit` 语句终止：

```
commit [work]
```

如果未提交，事务可被取消，如下所示：

```
rollback [work]
```

SQL:1999 允许在事务中包含一个或多个*保存点*。然后可以将工作回滚到特定保存点，而不是回滚整个事务。释放保存点的作用类似于对保存点之前的事务部分进行暂时提交。许多 SQL 供应商尚不支持保存点。

最强大的 `insert` 语句形式允许我们一次性将多行插入到表中。其基本语法是：

```
insert into tablename [ (col-list ) ]
select-query
```

这将插入从子查询返回的行集合。这有很多用途，例如制作表的副本，或临时存储连接结果以加快后续查询。例如，考虑在图 12.63 中之前图示化的软件零售商数据库模式。现在，假设我们想运行许多关于数据库产品销售的查询。为了便于此操作，我们可以创建一个名为“DBsales”的合适表，然后填充它，如下所示：

```
insert into DBsales
select *
from Invoice natural join LineItem natural join Item
where category = 'DB'
```

出于给定时期（例如 1 周）的分析目的，可能可以忽略对底层基表的更新。现在可以在 DBsales 上制定查询，而无需承担原始连接的性能开销。这种方法用于数据仓库。

现在，让我们考虑如何 `delete rows`（删除行）。在 SQL 中，`delete` 语句用于从表中删除部分或全部行。删除后，表结构仍然存在（直到执行相关的 `drop table` 命令）。`delete` 语句的基本语法是：

```
delete from tablename
[where condition]
```

这里有两个基于我们零售商数据库的示例：

```
delete from Item              -- 删除 Item 表中的所有行
delete from Item
where category = 'DB'   -- 从 Item 中删除所有数据库商品行
```

接下来，让我们考虑如何 `update rows`（更新行）（即更改现有行中的一个或多个值）。在 SQL 中，`update` 语句用于修改行。其基本语法如下所示。在 SQL-89 中，表达式必须是标量表达式、`null` 或 `default`。标量表达式可能包含列名、常量和标量运算符。
