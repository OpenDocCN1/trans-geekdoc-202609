# 领域 4：设计成本优化架构

# AWS 考题解析

## 1. A, B

当实例成本是问题时，答案几乎总是考虑某种形式的降低实例定价。AWS 为此提供了预留实例和竞价实例以及竞价市场。此外，一次性全额支付预留实例是获取预留实例最具成本效益的方式。因此，A 和 B 正确。C 有问题，因为运行较小实例更长时间不一定比运行大实例更短时间更便宜。选项 D 有一定道理，但 AWS 几乎肯定会将你指回预留实例或竞价市场（A 和 B）。

## 2. C, D

预留实例可以采用无预付、部分预付和全部预付模式付费，其中全部预付最便宜，无预付最贵。

## 3. D

预留实例锁定在创建它们的区域中，因此 D 正确。你需要在新区域中创建新的预留实例。

## 4. C

这应该是一个简单的正确答案：鉴于你的计算具有灵活的时序和需求，通过竞价市场使用竞价实例是潜在的最便宜选项。

## 5. B, C

具有突发性工作负载的应用程序是使用按需实例的原因，因为按需实例可以快速扩展和缩减。灵活的开始和结束时间是选择竞价实例的标准，而稳态使用是预留实例的理想选择。每当你测试新应用程序时，按需实例都是一个很好的选择。

## 6. B, D

具有突发性工作负载的应用程序是使用按需实例的原因，因为按需实例可以快速扩展和缩减。灵活的开始和结束时间是选择竞价实例的标准，而稳态使用是预留实例的理想选择。当其他实例类型无法负担大量计算时，竞价实例也能使其变得负担得起。

## 7. C, D

第一个选项很容易，因为它的措辞中实际上包含了 *reserved*。稳态使用也是预留实例的用例，以获得成本节约。大量且即时的额外容量需求最适合由竞价实例来满足，而按需实例最适合没有初始支付能力的用户。

## 8. A, B

S3 与所有 S3 存储类共享 11 个 9 的持久性。它还提供了所有 S3 存储类中最高的可用性吞吐量。非频繁访问是 S3-IA 的用例，而重新创建对象的能力则建议使用 S3 One Zone-IA。

## 9. A, D

这里的问题是实例缩减得太快。这导致它们被重新启动，从而产生成本。这里的解决方案应该是让实例多停留一段时间，以满足需求。A 和 D 都能做到这一点。冷却计时器增加了组确保先前缩放操作完成的时间（A），并且用于缩减的 CloudWatch 警报周期也应增加（D）。

## 10. D

这是一道相当“按教科书”的问题，在这种情况下，这正是 S3-IA（非频繁访问）的建造初衷。即时访问且请求频率较低非常适合 S3-IA。

## 11. A

无论用例如何，S3-IA 都比 S3 便宜。S3-IA 当然可能不*适合*某个特定用例，但在“每检索字节”的情况下，它更便宜。

## 12. C

CloudFront 将允许你缓存频繁访问的文件。在这种情况下，这实际上应该会降低成本。虽然 CloudFront 确实会产生新的额外成本，但它可能会被减少的 EFS 流出流量以及处理请求的额外 EC2 实例计算所抵消。

## 13. D

这里的所有描述都建议使用 Glacier。文档是一个大型归档，许多将永远不会被访问。然而，快速检索的要求指向了加急检索的需求。对于不那么频繁的访问，带有加急检索的 Glacier 仍将比 S3-IA 便宜。

## 14. B

首先，对于单实例应用程序，EBS 比 EFS 好得多。虽然数据库肯定会从 IOPS 中受益，但这里没有必要；峰值很小，总体使用率很低。通用型 SSD 此处已足够。

## 15. C

如果你有更大的数据库工作负载，预置 IOPS SSD 是理想选择。

## 16. D

冷 HDD 是成本最低的 EBS 卷类型。

## 17. A

这是一个棘手的问题。你可以排除 B 和 C，因为两者都涉及额外的服务：CloudWatch、Lambda 和额外的 EC2 实例。获取 EBS 快照是好的，通过将这些快照移入 S3（这是默认行为），你可以自动获得持久性。镜像数据也是一个很好的选择——提供容错——但这不提供持久性组件，这是问题专门要求的。因此，A 是最佳答案。

## 18. B

这个问题有两个组成部分：哪种存储介质合适，以及如何删除旧记录。要同时获得即时检索和生命周期管理，你需要 S3，如选项 B 所示。（此外，EBS 不提供生命周期管理，如选项 D 所示。）

## 19. A, C

RDS 读取副本将从数据库实例中分担一些读取负载，ElastiCache 也是如此。前者允许读取转移到其他实例，后者缓存已访问的数据。

## 20. B, D

Glacier 是显而易见的选择，因为它可以处理最旧的数据，同时仍能满足 10 小时的检索时间。S3 RRS 已弃用，不应考虑。这留下了 S3 和 S3-IA。S3-IA 始终比 S3 便宜，所以它是这里的更好选择。

## 21. B

置放群组通常位于单个可用区中，但现在分散置放群组可以跨可用区放置。

## 22. B

通常认为分散置放群组是跨可用区分布的群组，但这是一个误称。*分散*在分散置放群组中意味着实例分布在不同的底层硬件上，虽然它们*可以*跨可用区分布，但不必如此。

## 23. C

分散置放群组每个可用区最多可以有七个正在运行的实例。

## 24. A, C

分散置放群组主要提供实例间降低的网络延迟（C）。它们还允许跨 VPC 跨越实例（A）。

## 25. C

这里唯一的错误陈述是 C：分散置放群组无法跨区域设置，因此整个陈述不真实。

## 26. B, C

流出流量始终有相关成本（B），而流入流量始终免费。跨区域传输数据与传输到互联网的处理方式相同。只有跨可用区数据传输保证无成本（D），这使得 C 成为另一个正确答案。

## 27. C

最低成本永远是“免费”，所以要寻找任何可能是流入流量的东西。在这种情况下，上传到 S3 是纯流入流量，因此免费且是最便宜的选项。

## 28. B

这里没有流入流量选项，所以没有什么是保证免费的。在这种情况下，你应该寻找在同一可用区内移动数据的东西。那总是最便宜的（通常免费，取决于 IP 地址），在本例中，那是选项 B：实例间的跨可用区数据传输。

## 29. A, B

首先，CloudFront 总是一个好选择。从 EC2 移动数据到 CloudFront 是免费的，所以这可以减少数据必须传输的距离和相关成本。然后，私有 IP 允许不路由到互联网的通信，通常 AWS 对私有 IP 到私有 IP 的通信收费较低。

## 30. B

虽然有一个免费层，但它是一个计费选项，而不是实际的支持级别。这使得 B 是此答案集中的非级别选项。

## 31. C

AWS 减少了大量资本支出的需求，并提供按需付费模式。

## 32. B

AWS 对其所有服务使用按需付费模式。

## 33. D

D 不正确；随着 AWS 的增长，由于规模经济，你实际上支付得更少。
