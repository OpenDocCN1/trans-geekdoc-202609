
当你需要一个值来代表同一类型的几个方法中的选择，以便能用许多不同的接收者调用选定的方法时，方法表达式会有所帮助。在下面的例子中，变量 `op` 代表类型 `Point` 的加法或减法方法，`Path.TranslateBy` 为 `Path` 中的每个点调用它：

```
type Point struct{ X, Y float64 }

func (p Point) Add(q Point) Point { return Point{p.X + q.X, p.Y + q.Y} }
func (p Point) Sub(q Point) Point { return Point{p.X - q.X, p.Y - q.Y} }

type Path []Point

func (path Path) TranslateBy(offset Point, add bool) {
    var op func(p, q Point) Point
    if add {
        op = Point.Add
    } else {
        op = Point.Sub
    }
    for i := range path {
        // 调用 path[i].Add(offset) 或 path[i].Sub(offset) 中的一个。
        path[i] = op(path[i], offset)
    }
}
```

## 6.5 示例：位向量类型

Go 中的集合通常实现为 `map[T]bool`，其中 `T` 是元素类型。用映射表示的集合非常灵活，但对于某些问题，专门的表示可能性能更好。例如，在数据流分析等领域，集合元素是较小的非负整数，集合拥有许多元素，且并集和交集等集合操作很常见，位向量是理想选择。

位向量使用无符号整数值的切片或“字”，每一位代表集合的一个可能元素。如果第 *i* 位被置位，则集合包含 *i*。下面的程序演示了一个带有三个方法的简单位向量类型：

`gopl.io/ch6/intset`

```
// IntSet 是一个包含小非负整数的集合。
// 其零值代表空集。
type IntSet struct {
    words []uint64
}

// Has 报告集合是否包含非负值 x。
func (s *IntSet) Has(x int) bool {
    word, bit := x/64, uint(x%64)
    return word < len(s.words) && s.words[word]&(1<<bit) != 0
}

// Add 将非负值 x 添加到集合中。
func (s *IntSet) Add(x int) {
    word, bit := x/64, uint(x%64)
    for word >= len(s.words) {
        s.words = append(s.words, 0)
    }
    s.words[word] |= 1 << bit
}

// UnionWith 将 s 设为 s 和 t 的并集。
func (s *IntSet) UnionWith(t *IntSet) {
    for i, tword := range t.words {
        if i < len(s.words) {
            s.words[i] |= tword
        } else {
            s.words = append(s.words, tword)
        }
    }
}
```

因为每个字有 64 位，为了定位 `x` 的位，我们用商 `x/64` 作为字索引，用余数 `x%64` 作为该字内的位索引。`UnionWith` 操作使用按位或运算符 `|` 一次计算 64 个元素的并集。（我们将在练习 6.5 中重新审视 64 位字的选择。）

这个实现缺少许多理想特性，其中一些作为下面的练习提出，但有一个是不可或缺的：将 `IntSet` 打印为字符串的方法。让我们给它一个 `String` 方法，就像我们在第 2.5 节中为 `Celsius` 做的那样：

```
// String 将集合以 "{1 2 3}" 的形式返回为字符串。
func (s *IntSet) String() string {
    var buf bytes.Buffer
    buf.WriteByte('{')
    for i, word := range s.words {
        if word == 0 {
            continue
        }
        for j := 0; j < 64; j++ {
            if word&(1<<uint(j)) != 0 {
                if buf.Len() > len("{") {
                    buf.WriteByte(' ')
                }
                fmt.Fprintf(&buf, "%d", 64*i+j)
            }
        }
    }
    buf.WriteByte('}')
    return buf.String()
}
```

请注意上述 `String` 方法与 3.5.4 节 中 `intsToString` 的相似之处；`bytes.Buffer` 在 `String` 方法中常以这种方式使用。`fmt` 包会特殊对待拥有 `String` 方法的类型，以便复杂类型的值能以用户友好的方式显示自身。`fmt` 不会打印值的原始表示（本例中为结构体），而是调用 `String` 方法。该机制依赖于接口和类型断言，我们将在 第 7 章 中解释。

现在我们可以演示 `IntSet` 的实际运行效果：

```
var x, y IntSet
x.Add(1)
x.Add(144)
x.Add(9)
fmt.Println(x.String()) // "{1 9 144}"

y.Add(9)
y.Add(42)
fmt.Println(y.String()) // "{9 42}"

x.UnionWith(&y)
fmt.Println(x.String()) // "{1 9 42 144}"

fmt.Println(x.Has(9), x.Has(123)) // "true false"
```

注意：我们将 `String` 和 `Has` 声明为指针类型 `*IntSet` 的方法，并非出于必要性，而是为了与其他两个方法保持一致，因为那两个方法需要指针接收者，因为它们要对 `s.words` 进行赋值。因此，`IntSet` 值没有 `String` 方法，这偶尔会导致如下意外情况：

```
fmt.Println(&x)         // "{1 9 42 144}"
fmt.Println(x.String()) // "{1 9 42 144}"
fmt.Println(x)          // "{[4398046511618 0 65536]}"
```

在第一种情况下，我们打印一个 `*IntSet` 指针，它确实拥有 `String` 方法。在第二种情况下，我们在 `IntSet` 变量上调用 `String()`；编译器会插入隐式的 `&` 操作，给我们一个指针，该指针拥有 `String` 方法。但在第三种情况下，因为 `IntSet` 值没有 `String` 方法，`fmt.Println` 会打印结构体的表示形式。切记不要忘记 `&` 操作符。将 `String` 定义为 `IntSet` 的方法而非 `*IntSet` 的方法可能是个好主意，但这需要根据具体情况判断。

## 6.6 封装

如果对象的变量或方法对该对象的客户端代码不可见，则称该变量或方法被封装。封装有时称为信息隐藏，是面向对象编程的关键方面。

Go 只有一种机制来控制名称的可见性：大写字母开头的标识符会从定义它们的包中导出，小写字母开头的名称则不会。限制包成员访问的同一机制也限制了对结构体字段或类型方法的访问。因此，要封装一个对象，我们必须将其定义为结构体类型。

这就是上一节中 `IntSet` 类型被声明为结构体类型的原因，尽管它只有一个字段：

```
type IntSet struct {
    words []uint64
}
```

我们本可以将 `IntSet` 定义为切片类型，如下所示，尽管当然我们必须在其方法中将每处 `s.words` 替换为 `*s`：

```
type IntSet []uint64
```

虽然这种版本的 `IntSet` 本质上是等价的，但它会允许其他包的客户端代码直接读取和修改切片。换句话说，表达式 `*s` 可在任何包中使用，而 `s.words` 只能出现在定义 `IntSet` 的包中。

这种基于名称的机制的另一个后果是，封装的单元是包，而不是像许多其他语言那样是类型。结构体类型的字段对同一个包内的所有代码可见。代码出现在函数中还是方法中并无区别。

封装提供了三个好处。首先，因为客户端代码无法直接修改对象的变量，所以只需检查更少的语句即可了解这些变量的可能值。

其次，隐藏实现细节可以防止客户端代码依赖可能会改变的事物，这使设计者拥有更大的自由来演进实现，而无需破坏 API 兼容性。

作为一个例子，考虑 `bytes.Buffer` 类型。它经常用于累加非常短的字符串，因此在对象中预留一点额外空间以避免这种常见情况下的内存分配是一项有利的优化。由于 `Buffer` 是结构体类型，这部分空间表现为一个类型为 `[64]byte` 且名称小写的额外字段。当添加此字段时，因为它未被导出，`bytes` 包外部的 `Buffer` 客户端代码除了性能提升外，不会察觉到任何变化。下面展示了简化后的 `Buffer` 及其 `Grow` 方法：

```
type Buffer struct {
    buf     []byte
    initial [64]byte
    /* ... */
}

// Grow 在必要时扩展缓冲区容量，
// 以保证有空间容纳另外 n 个字节。[...]
func (b *Buffer) Grow(n int) {
    if b.buf == nil {
        b.buf = b.initial[:0] // 最初使用预分配的空间
    }
    if len(b.buf)+n > cap(b.buf) {
        buf := make([]byte, b.Len(), 2*cap(b.buf) + n)
        copy(buf, b.buf)
        b.buf = buf
    }
}
```

封装的第三个好处，在许多情况下也是最重要的，是它防止客户端代码随意设置对象的变量。因为对象的变量只能由同一个包中的函数设置，该包的作者可以确保所有这些函数都维护对象的内部不变量。例如，下面的 `Counter` 类型允许客户端代码增加计数器或将其重置为零，但不允许将其设置为任意值：

```
type Counter struct { n int }

func (c *Counter) N() int     { return c.n }
func (c *Counter) Increment() { c.n++ }
func (c *Counter) Reset()     { c.n = 0 }
```

### 仅访问或修改内部值的函数

仅访问或修改类型内部值的函数，例如下面 `log` 包中 `Logger` 类型的方法，被称为 getters（获取器）和 setters（设置器）。然而，在命名 getter 方法时，我们通常省略 `Get` 前缀。这种对简洁性的偏好适用于所有方法，而不仅仅是字段访问器，也适用于其他冗余前缀，如 `Fetch`、`Find` 和 `Lookup`。

```
package log

type Logger struct {
    flags  int
    prefix string
    // ...
}

func (l *Logger) Flags() int
func (l *Logger) SetFlags(flag int)
func (l *Logger) Prefix() string
func (l *Logger) SetPrefix(prefix string)
```

### Go 风格不禁止导出字段

Go 风格不禁止导出字段。当然，一旦导出，若不进行不兼容的 API 变更，字段就无法取消导出，因此初始选择应当审慎，并应考虑必须维护的不变量的复杂性、未来变更的可能性，以及会受变更影响的客户端代码量。

### 封装并非总是可取的

封装并非总是可取的。通过将其表示形式揭示为纳秒数的 `int64`，`time.Duration` 让我们能将所有常用的算术和比较操作用于时长，甚至可以定义该类型的常量：

```
const day = 24 * time.Hour
fmt.Println(day.Seconds()) // "86400"
```

### IntSet 与 geometry.Path

作为另一个例子，将 `IntSet` 与本章开头的 `geometry.Path` 类型进行对比。`Path` 被定义为切片类型，允许其客户端使用切片字面量语法构造实例，使用 range 循环遍历其点，等等，而这些操作对 `IntSet` 的客户端则是被禁止的。

这里是关键区别：`geometry.Path` 本质上就是一个点的序列，不多不少，我们预见不到会给它添加新字段，因此 `geometry` 包揭示 `Path` 是一个切片是合理的。相比之下，`IntSet` 只是恰好用 `[]uint64` 切片表示。它本可以用 `[]uint` 表示，或者对于稀疏或极小的集合用完全不同的表示，它或许还能从额外功能中受益，比如一个用于记录集合元素数量的额外字段。基于这些理由，让 `IntSet` 保持不透明是合理的。

## 小结

在本章中，我们学习了如何将方法与命名类型关联，以及如何调用这些方法。虽然方法对面向对象编程至关重要，但它们只是全貌的一半。为了完善它，我们需要 interfaces（接口），这是下一章的主题。

# 7. 接口

接口类型表达了对其他类型行为的泛化或抽象。通过泛化，接口让我们能编写更灵活、适应性更强的函数，因为它们不依赖于某一特定实现的细节。

许多面向对象语言都有接口的概念，但 Go 接口的独特之处在于它们是 satisfied implicitly（隐式满足）的。换句话说，无需声明某个具体类型满足了哪些接口；仅拥有必要的方法就足够了。这种设计让你能创建新接口，使现有的具体类型满足它们，而无需修改现有类型，这对于你无法控制的包中定义的类型特别有用。

在本章中，我们将首先了解接口类型及其值的基本机制。在此过程中，我们将研究标准库中的几个重要接口。许多 Go 程序对标准接口的使用程度不亚于它们自己的接口。最后，我们将探讨 type assertions（类型断言）（§7.10）和 type switches（类型开关）（§7.13），并了解它们如何实现另一种泛化。

## 7.1 接口即契约

我们迄今为止看到的所有类型都是 concrete types（具体类型）。具体类型指定了其值的确切表示形式，并暴露了该表示形式的内在操作，例如数字的算术运算，或切片的索引、append 和 range。具体类型还可以通过其方法提供额外的行为。当你拥有一个具体类型的值时，你确切地知道它是什么以及你能用它做什么。

Go 中还有另一种类型，称为 interface type（接口类型）。接口是一种 abstract type（抽象类型）。它不暴露其值的表示形式或内部结构，也不暴露它们支持的基本操作集；它只揭示它们的某些方法。当你拥有一个接口类型的值时，你不知道它是什么；你只知道它能做什么，更准确地说，是其方法提供了哪些行为。
