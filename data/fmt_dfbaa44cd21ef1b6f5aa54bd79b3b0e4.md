
正如我们所见，创建 Go 语言的主要原因之一是开发一门易于使用的快速语言。这种理念始终存在于 Go 团队的脑海中。

### 未使用的导入和声明

在 Go 语言中，我们不能导入未使用的包，也不能声明未使用的变量。这两种情况都会导致编译错误。Go 语言仅编译必要的依赖，从而实现精确编译，避免编译未使用的依赖。

### Go 语言的简洁性

如前所述，Go 语言以其简洁性著称。它仅包含约 25 个关键字，这使得编译过程更加直接。这种简洁性在编译时间上带来了显著的回报。

### 类似 C 语言

有人可能会将 Go 语言描述为 C 语言的现代版本。虽然许多其他语言通常使用类和继承，但 Go 语言采取了不同的方法，利用结构体和接口配合组合。Go 语言从 C 和 C++ 继承了各种元素，例如数据结构、指针、按引用或按值传递的能力等。

C 和 C++ 以速度著称，Go 语言旨在达到类似的性能水平。然而，它也力求成为一门现代且用户友好的语言，使编写代码更加容易，从而提高生产力。

### 并发模型

并发是 Go 语言的首要任务。通过 `Goroutine` 和 `Channel`，Go 语言使并发编程变得简单高效。`Goroutine` 是由 Go 运行时管理的轻量级线程，允许多个任务独立运行。`Channel` 是 `Goroutine` 之间通信的方式，实现了安全且同步的数据交换，从而构建更快、更具扩展性的应用程序。

`Goroutine` 和 `Channel` 是一等公民。并发是 Go 语言旨在建立并做好的核心概念之一。我们将简要探索 Go 语言独特的并发模型。

Go 语言是一门多线程语言。然而，Go 语言与其他语言不同，作为开发者，我们无法直接访问线程。这是基于“线程是操作系统的资源”这一理念实现的。在 Go 语言中，我们不应关心线程。当然，也有需要担心的地方，比如不同 `Goroutine` 对同一对象的访问（`sync` 核心库应通过锁、唯一对象等帮助解决这一问题）。

另一个担忧是 `Goroutine` 泄漏。我们将在后续章节中解决这两个问题。

那么，什么是 `Goroutine`？Go 团队通过 `Goroutine` 封装了传统线程。它们在资源使用和初始化方面极具成本效益。

关于内存占用，初始化 `Goroutine` 栈仅需 2 KB，而默认线程栈为 8 KB。这轻量了 4 倍！`Goroutine` 内存轻量的直接效果是，分配和释放它们比线程快得多。

`Goroutine` 具有革命性，完全由 Go 运行时管理而非操作系统。它们拥有便捷的通信机制、轻量级内存、快速初始化，且不依赖硬件。

为了解释 `Goroutine` 的工作原理，让我们谈谈 Go 调度器。它是 Go 运行时中的一个组件，拥有对内核的直接访问权，负责管理我们执行的每一个 `Goroutine`。

`Goroutine` 被调度在线程上，调度器负责将它们分配到线程上。

![](img/2.3.jpg)

**图 2.3：** Go 调度器

在这张图中，我们可以看到系统的核心。操作系统调度器管理着一层线程；在它之上，我们可以看到执行 `Goroutine` 的 Go 程序，而 Go 调度器管理着这一切。

让我们观察单核系统的行为。

![](img/2.4.jpg)

**图 2.4：** 单核操作系统分配一个 goroutine

这张图展示了一个单核操作系统，它执行一些被称为 G1 的 `Goroutine`。然后在最后执行另一个被称为 G2 的 `Goroutine`。

但当我们拥有多核时会发生什么？当一个 Go 程序启动时，调度器会初始化一个线程；如果一些 `goroutine` 正在执行而之前的 `goroutine` 尚未完成，它会分配更多线程，直到达到最大线程数。配置中的最大线程数即为 Go，它被设置为一个名为 `GOMAXPROCS` 的环境变量。Go 团队通过基准测试得出的默认且推荐的值是核心数。例如，如果一台机器有 8 个核心，`GOMAXPROCS` 的值就是 8，调度器不会调度超过 8 个线程。我们可以配置该环境变量，但这不推荐。

当需要执行的 `goroutine` 多于可用线程时，调度器是如何工作的？

![](img/2.5.jpg)

**图 2.5：** 由调度器管理的、带有队列的多线程

每个线程都有一个专用队列，该队列知晓下一个应该在此线程上调度的 `goroutine`。每分配一个新线程，就会创建一个新队列。每个 `goroutine` 在某个线程上运行时被分配，并直接进入同一线程的队列。为了防止单个队列负载过重，调度器会在线程间执行工作窃取，并平衡它们之间的工作。

以上简要解释了 Go 调度器。调度器还会考虑许多其他因素，如系统锁、代码锁、线程间通信、线程分配、空闲线程等。

### Go 的可维护性

Go 易于维护有几个原因：

*   兼容性
*   Go 的简洁性
*   错误处理

### 兼容性

> “旨在让符合 Go 1 规范编写的程序在该规范的生命周期内持续能够正确编译和运行，且无需更改。在未来的某个不确定时间点，可能会出现 Go 2 规范，但在那之前，今天能工作的 Go 程序在未来 Go 1 的“点”版本发布（Go 1.1、Go 1.2 等）时应继续保持工作。”

这是 Go 第一个版本发布时文档中的引述。参考资料中附有该文档。请注意，文档后续部分设定了预期，并指出事情可能会出错，例如 bug、安全问题、结构体字面量等。

每当发布一个 Go 版本时，都旨在保持向后和向前兼容性。根据 Russ Cox 在 GopherCon 2022 上的演讲，Go 团队使用两种主要方法来保持兼容性：

*   API 检查
*   测试

#### API 检查

为了防止破坏之前的 Go 版本，我们不能移除导出的符号、API 方法、包等。否则程序将无法运行。Go 不能移除库、结构体、方法等。

Go 团队使用一个包含所有 Go 版本所有导出 API 签名的工具。然后，Go 团队运行测试，将包的 API 与导出的 API 签名进行比较，如果有变化则发出通知。如果发生变化，他们会采取行动来阻止它，或者至少将其影响降到最低。

#### 测试

Google 在 Go 维护中拥有的一个巨大优势是可以在 Google 内部对其进行测试。Go 的开发版本会针对 Google 所有内部 Go 程序的测试进行测试。所有这些测试通过后，Go 开发分支会被用于 Google 的生产环境和工具链中。

每次发布 Go 版本时，他们都会记录新版本中是否有东西被破坏。Go 还提供了一个名为 `GODEBUG` 的强大工具，帮助我们升级版本并验证我们的程序不会 panic。

### Go 的简洁性

正如我们之前所见，Go 的主要目标之一是简洁性。当我们审视程序的可维护性时，这种简洁性就会得到回报。Go 团队的一个显著优势是他们制定所有规则。在上一章中，我们讨论了“Effective Go”，其中包含了所有约定、最佳实践和文档，指导如何做事。与其他一些语言的约定来自不同地方不同，在 Go 中，Go 团队决定一切。

### 错误处理

Go 与其他语言不同。在许多其他语言中，我们期望看到 `try-catch-finally` 惯用语。

Go 并非如此。在 Go 中，我们会显式地创建一个错误并将其作为变量返回。这里引用一段 Go FAQ 的内容。

> “我们认为将异常与控制结构耦合（如 `try-catch-finally` 惯用语）会导致代码复杂化。这也倾向于鼓励程序员将太多普通错误（如无法打开文件）标记为异常。”

有时看到这样的代码会让人沮丧：

```
if err != nil {
    return err
}
```

然而，如果我们理解其动机，就能接受它。此外，根据 Go FAQ，Go 的错误处理给了我们一种讲述故事的方式。我们不只是返回错误，而是可以为其添加上下文，从而创建错误的“故事”，例如：

```
if err != nil {
    return fmt.Errorf("connecting to DB: %w", err)
}
```

现在我们有了上下文，知道这个错误是在尝试连接数据库时发生的。这只是一个理解 Go 中错误处理隐藏力量的例子。

### 从入门到生产

编程语言不仅仅由编译器、语法等语言组件组成。它还包含工具链中至关重要的几个工具，如包管理器、文档、格式化工具、静态分析工具、测试工具等。

Go 旨在通过在工具链中提供这些工具，给 Go 开发者一种整体体验。Go 团队想要创建工具链有三个原因。

一是他们不需要依赖匿名贡献者来创建工具。第二个也是更重要的原因是 Go 团队最清楚构建此类工具的最佳方式。第三个原因是为了实现标准化。

我们不想要两个做非常相似的事情但运作方式不同的格式化工具，我们可以在其他语言中看到这种模式。格式化工具只是标准化的一个例子。它可以是静态分析工具、测试、time 包等。

新手从接触语言到将其部署到生产环境需要哪些步骤？

1.  入门
2.  规划
3.  包管理
4.  编写代码
5.  故障排查
6.  测试
7.  安全
8.  构建
9.  其他

#### 入门

语言新手不了解语言语法的样子。Go 团队创建了一个 playground（演练场），因此阅读过该语言介绍的开发者可以立即参与并上手练习。所有文档和 playground 都在 `go.dev` 中。

#### 规划

新手爱上了这门语言。现在，他们想开始一个项目。但在跳进代码之前，我们要先规划。我们想了解项目将是什么样子。为此，我们必须了解并探索我们打算使用的包。所有 Go 包有一个单一的制品管理器，毫不意外，它存在于 `go.dev` 中，具体在 `pkg.go.dev`。

#### 包管理

要与 Go 工具链中的各种工具交互，我们只需要拥有 Go CLI。在 Go CLI 中，各种工具帮助我们启动项目。我们完成了项目规划，现在想开始。我们将运行以下命令来初始化一个项目：

`go mod init github.com/nirsht/microservices-with-go`

如果我们想要安装任何包，可以运行：

`go install github.com/nirsht/myawesomepackage`

有各种工具可以帮助我们管理包，如 `go mod tidy`、`go vet` 等。这些命令功能强大，让我们能够管理包。

#### 编写代码

项目设置完成并引入所有所需的包后，我们就可以开始编写代码了。我们可以选择 Visual Studio Code、Vim 或 GoLand（由 JetBrains 开发）等集成开发环境（IDE）来高效地编写代码。这些 IDE（以及其他 IDE）依赖语言服务器协议（LSP）来实现其功能。

微软对 LSP 给出了一个很好的定义：

> “语言服务器协议（LSP）是开发工具与语言服务器进程之间交换消息的标准化产物。使用语言服务器或守护进程并非新颖概念。Vim 和 Emacs 等编辑器已经这样做了一段时间，以提供语义自动补全支持”

对于许多编程语言，LSP 并非由语言的原作者提供。但在 Go 中情况不同。Go 的 LSP 是 `gopls`，由 Go 团队维护。此外，Go 团队还为 VS Code 提供了一个名为 `vscode-go` 的扩展。

#### 故障排查

与所有软件工程师一样，我们的代码有时能完美运行。我们的工作包括阅读代码、调试和排查烦人的 Bug。Go 团队深知这一点。他们开发了一款旨在协助开发者进行调试和故障排查的工具。例如，他们提供了官方 Go 调试器 - `gdb`。此外，Go 团队还开发了一款名为 `pprof` 的优秀性能分析器，它支持对性能分析数据进行可视化和分析。

#### 测试

任何自尊的软件工程师都会编写测试。这是创建系统可维护性的行业标准。Go 也为我们提供了一个高效执行测试的工具。不需要外部库，只需 Go CLI。运行时：

`go test.`

它会遍历所有文件，找出具有 `_test` 后缀的文件，然后运行所有以 `Test` 为前缀的函数。

Go 团队在 `go test` 命令中提供了多种配置。我最喜欢的是通过 Go CLI 使用以下命令测试竞态条件的选项：

`go test -race`

从 Go 1.18 开始，模糊测试可用。

> “模糊测试是一种自动化测试，它持续操纵程序的输入以查找 Bug。”

模糊测试是一个方便且强大的工具，用于验证我们的程序在获得错误输入时不会崩溃。

### 安全

现在，我们想要发布代码用于生产环境。但有一个问题。我们需要检查包的依赖项中是否存在安全漏洞。

自 Go 1.18 起，我们可以运行一个命令来检查所有漏洞 - `govulncheck`。Govulncheck 由 Go 团队维护的 Go 漏洞数据库提供支持。

#### 构建

剩下的唯一事情就是打包我们的代码。Go 有一个编译器，负责将我们的代码编译为所需的二进制架构和操作系统。这些可以通过环境变量轻松配置 - `GOARCH` 用于架构，`GOOS` 用于操作系统。

构建命令内置于 Go CLI 中，我们可以通过运行以下命令来使用它：

`go build main.go`

#### 其他

在这趟旅程中，我们只介绍了 Go 工具链中的一小部分工具。为了保持一致性，Go 将几件事集中管理，如代码检查（检查代码错误等）和格式化（让代码整洁美观，这在 Go 中至关重要）。我们认为 Go 团队选择了合适的包纳入语言，比如用于处理时间相关任务的 “time” 包。

如今，大多数编程语言都是 OSS（即开源软件）。Go 就是其中之一，并且从第一天起就是开源驱动的。

如今，许多人都非常激动并渴望为 Go 或 Go 开发工具链中的许多其他项目做贡献。就包的数量而言，Go 是最流行的编程语言之一（正如我们在上一章所见）。

### 简介

本章将深入探讨 Go 的基本方面，包括其基本语法、模式、惯例、风格，以及成为熟练 Go 开发人员所需的一切基本知识。它将为新手和经验较浅的 Go 开发人员提供阅读本书所需的最低限度知识。
