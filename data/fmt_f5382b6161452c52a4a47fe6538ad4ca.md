作为示例，我们将编写 Java 代码来执行预测评估。

要执行预测评估，我们必须先测试然后在流中的每个实例上训练。同时，我们保留一些准确率统计数据以便计算最终的准确率值。

**Listing 14.4: 预测评估的 Java 代码。**

```java
int numInstances = 10000;
int numberSamplesCorrect = 0;

       numberSamples < numInstances) {
    Instance inst = stream.nextInstance().getData();
    if (isTesting) {

            numberSamplesCorrect++;
        }
    }

    learner.trainOnInstance(inst);
}
```


### 15 在 MOA 中开发新方法

在某些情况下，开发扩展 MOA 功能的新方法很有用。在本章中，我们介绍 MOA 中一些最流行对象的结构，并展示如何实现新对象。本章需要对 Java 中的数据结构有良好的理解。

#### 15.1 MOA 中的主要类

MOA 中的所有对象都应实现 `MOAObject` 接口并继承 `AbstractMOAObject` 抽象类。要在 Java 中创建一个需要配置选项的新类，需要继承 `AbstractOptionHandler` 抽象类。MOA 选项非常灵活，并且由于它们可以是递归的，因此可以将具有选项的对象本身定义为选项。例如，这是一个具有不同于默认选项的霍夫丁树分类器的规范：

```
moa.classifiers.trees.HoeffdingTree
-n (VFMLNumericAttributeClassObserver -n 20)
-g 300 -s GiniSplitCriterion -t 0.04 -l MC
```

在该示例中，我们选择 `VFMLNumericAttributeClassObserver` 对象作为数值属性类观察器，它有 20 个箱。我们将数字 20 作为选项传递给该类。注意选项是递归的，并且可以包含大量 Java 类。

MOA 中的主要学习器接口有：

*   **Classifier**：该接口由分类器和回归器使用。分类器通常继承 `AbstractClassifier` 抽象类，并实现以下三个方法：
    *   `resetLearningImpl`：重置或初始化分类器
    *   `trainOnInstanceImpl`：使用新实例更新学习器
    *   `getVotesForInstance`：从学习器获得预测

    `AbstractClassifier` 抽象类包含以下两个用于 API 的方法：
    *   `prepareForUse`：调用 `resetLearningImpl` 以准备分类器
    *   `trainOnInstance`：使用 `trainOnInstanceImpl` 通过新实例训练学习器

*   **Regressor**：回归方法实现此接口并继承 `AbstractClassifier` 抽象类。分类和回归的区别在于，对于分类，`getVotesForInstance` 返回一个包含每个类估计预测值的数组，而对于回归，`getVotesForInstance` 返回一个长度为 1 的数组，包含预测结果。

*   **Clusterer（聚类器）**：此接口由聚类器和离群点检测器使用。聚类器继承 `AbstractClusterer` 抽象类，并实现以下方法：
    *   `resetLearningImpl()`：用于重置或初始化聚类器
    *   `trainOnInstanceImpl()`：用于使用新实例更新聚类器
    *   `getClustering()`：用于获取聚类器计算出的聚类点

*   **OutlierDetector（离群点检测器）**：与聚类器类似，但专门设计用于离群点检测。

#### 15.2 创建新分类器

为了演示系统中学习算法的实现和使用，我们展示并解释了一个简单决策树桩分类器的 Java 代码。该分类器监控在每个属性上分割时的类别信息增益，并选择使该值最大化的属性。该决策会被多次重新审视，因此随着更多示例的出现，树桩有可能随时间改变。实际上，如果流分布没有变化，在充分训练后它不太可能再发生改变。

##### 清单 15.1：选项处理

![](img/pg229-1.png)

要设置分类器的公共接口，必须指定可供用户使用的选项。为了让系统自动处理选项，这些选项需要作为类的公共成员，并继承 `moa.options.Option` 类型，如清单 15.1 所示。

示例分类器——决策树桩——有三个选项，每个类型不同。用于构建选项的前三个参数的含义在不同选项类型之间是一致的。第一个参数是用于标识选项的短名称。第二个是用于命令行的字符，应当唯一——命令行字符不能在不同选项间重复，否则会抛出异常。第三个标准参数是描述选项用途的字符串。选项构造函数的额外参数允许指定附加信息，如默认值或值的有效范围。

决策树桩分类器指定的第一个选项是“宽限期”。该选项用整数表示，因此类型为 `IntOption`。该参数控制从示例流学习时重新考虑最佳树桩的频率。这提高了分类器的效率——在每个单独示例后评估代价高昂，且单个示例不太可能改变当前最佳树桩的选择。默认值 1,000 意味着树桩的选择仅每 1,000 个示例重新评估一次。最后两个参数指定选项允许的值范围——负的宽限期没有意义，因此范围限制为大于或等于 0 的整数。

第二个选项是一个标志，即二元开关，由 `FlagOption` 表示。默认情况下所有标志均关闭，仅在用户请求时开启。此标志控制决策树桩是否仅允许二向分裂。默认情况下树桩允许有两个以上的分支。

第三个选项确定用于决定哪个树桩最佳的分裂准则。这是一个 `ClassOption`，需要特定的 `SplitCriterion` 类型 Java 类。如果所需类恰好是 `OptionHandler`，则这些选项将用于配置传入的对象。

##### 清单 15.2：杂项字段

![](img/pg230-1.png)

清单 15.2 中使用了四个全局变量来维护分类器的状态：

*   `bestSplit` 字段维护分类器当前选择的树桩。其类型为 `AttributeSplitSuggestion`，该类用于将实例分割成不同子集。
