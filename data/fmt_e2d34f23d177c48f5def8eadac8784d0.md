
# 变更管理流程

1. 变更请求
2. 变更请求批准
3. 计划评审
4. 变更的测试
5. 变更的计划发布
6. 通知受计划变更影响的人员
7. 变更的实施
8. 所有变更的记录
9. 变更后评审
10. 需要时回滚变更的方法

无论使用何种变更控制过程，都应在变更控制策略中记录。此外，还应指定策略涵盖和不涵盖的内容。例如，某些微小变更（如更新杀病毒软件）可能不包含在控制过程中，而具有持久影响的大型机构变更则包含在内。变更控制策略还应列出应急变更如何发生，因为可能会出现在未完成正常审查的情况下必须进行变更。在这种情况下，所有步骤都应完成，但可能无法在实施应急变更之前完成。变更管理必须能够处理发生的任何潜在变更，例如：

- 政策、程序和标准的变更
- 要求和新法规的更新
- 网络配置的更改
- 新网络设备或设备
- 收、合并或分拆导致公司结构变化
- 安装新的电脑、笔记本电脑、智能手机或平板电脑
- 安装新的或更新的应用程序
- 安装补丁和更新
- 集成新技术

当发生任何此类变化时，保持合规性需要将安全职责分配到整个组织，并存在多层控制。特定的安全流程还应分配给具有唯一角色的个人。例如，物理安全经理可能负责监控摄像头（CCTV）和对录制介质进行定期审查。安全经理可能负责对网络组创建的安全日志进行定期审查，而设施经理可能负责向清洁人员小组分发钥匙，并在其中任何员工离职时收回钥匙并将其交给物理安全经理。构建此类变更控制有助于即使在组织发生变化的情况下确保合规性。监管环境的要求以及对内部策略、标准和程序的合规性，都要求具备合规性。

## 为什么人们抵制变化

实施安全控制绝非易事，许多人对额外的控制产生抵制。原因之一是认为增加安全性会减少完成工作所需的访问权限。此外，还担心“老大哥（Big Brother）”正在日益监控员工。另一个原因可能是对失去自由的感知。最后，安全是需要成本的。无论原因何，CASP（高级安全认证专家）必须与他人合作实施必要的变更。

## 满足不断变化的业务需求的数据流

二十年前，安全数据流和网络安全分段并没有被放在与今天相同的语境下考虑，因为大多数企业在封闭的处理环境中运行大型机。主机的数据输入通过哑终端完成，而放置主机的房间限制为少数授权的员工进入。今天，我们生活在一个不同的世界中，员工很可能使用笔记本电脑、平板电脑和智能手机等设备从多个位置访问资源。

安全数据流需要结构化的安全方法和对各种元素进行审查。以下是其中一些元素：

- **虚拟专用网络 (VPN)**：VPN 可以通过为从远程位置连接的个人添加隐私层来帮助保护数据流。VPN 为移动工作人员提供了一种安全的解决方案，并在移动用户与其办公室或 VPN 内部指定的任何点之间充当安全隧道。用于 VPN 的一些技术包括二层转发、点对点隧道协议（PPTP）、二层隧道协议（L2TP）和 IPSec。此示例指的是接入 VPN，但其他类型如站点到站点、专线和 ISP 管理的 VPN（如多协议标签交换 MPLS）。在某些情况下，VPN 类型可以进一步分类——例如，站点到站点 VPN 可以进一步细分为基于内网或基于外网。还存在更高级的选择，例如动态多点 VPN (DMVPN)，它为静态站点到站点配置提供了动态替代方案。

- **网络分段**：网络划分需要对潜在的网络访问点进行审查。一旦定义了这些访问点，可以使用许多不同的技术来划分网络。常见和不常用的技术包括使用包过滤器、状态检测、应用代理防火墙、Web 应用防火墙、多层交换、分散路由和虚拟局域网 (VLAN)/虚拟可扩展局域网 (VXLAN)。

- **访问控制**：访问控制正被迫适应 IT 的持续消费者化。随着员工将个人笔记本电脑、智能手机、平板电脑和其他设备带入工作场所，划分变得困难得多。分层访问控制可以通过提供额外的粒度来应对这些变化。例如，公司策略可能允许员工访问 Facebook，但可能不允许他们玩 Facebook 游戏（如德州扑牌）。分层访问控制的一个示例如图 9.8 所示。

联邦访问控制是安全分段的另一个挑战；联邦访问控制的概念是允许用户身份和访问配置在跨分布式企业架构中运行。虽然联邦访问控制很有用，但必须正确实施，因为你正在允许用户在整个企业范围内重用电子身份，同时保持信任和安全。这意味着单个账户的泄露很容易导致多个联邦系统的泄露。

- **无线安全**：在考虑网络分段时，无线安全非常重要。无线网络将网络扩展到了物理场地的边界之外。虽然所谓的连接需要攻击者插接入以获取访问，但无线接入点为攻击者提供了远程连接的能力。使用正确的天线，攻击可以在四分之一英里或更远的地方。无线保护机制包括 Wi-Fi 安全访问 (WPA) 和 Wi-Fi 安全访问 II (WPA2)。两者都是安全协议的示例，旨在保护无线计算机网络。应该使用 WPA2，因为 WEP 已经被破解：WPA。其他控制还包括无线入侵检测系统 (WIDS) 和无线入侵防御系统 (WIPS)。WIDS 可以监控射频谱是否存在未经授权的接入点，而 WIPS 可以自动反制那些滥用射频谱的行为。

- **平台加固**：由于终端设备可以轻松访问网络资源，平台加固对于网络防御至关重要。平台加固的一些基本技术是删除不需要的服务和应用程序，以及对系统进行定期补丁和更新。

![](img/7868547987f5920cfe632b85047c64af_549_0.png)

Linux 平台加固的一个良好示例是 Bastille。你可以在 `http://bastille-linux.sourceforge.net` 下载。此外，SELinux 是美国安全局推荐的加固方案。微软也维护了特定系统的指南，可以在此处找到示例：`www.microsoft.com/download/details.aspx?displaylang=en&id=15910`。

- **入侵检测/防御系统**：IDS/IPS 可能无法直接帮助划分，但它们是检测入侵并帮助你应对事件的有用设备。

# 审计与事件管理

IDS/IPS 审计和事件管理以及安全信息事件管理 (SIEM) 解决方案有助于检测网络入侵。SIEM 解决方案以软件、设备或托管服务的形式销售，用于记录安全数据并生成用于合规的报告。SIEM 还可以长期存储日志，以便对数据进行关联分析。

逻辑部署代表了系统的部署视图。它们映射了信息系统物理基础设施中硬件组件之间的关系。系统工程师使用部署图来可视化系统的物理组件拓扑结构以及软件组件部署的位置。部署图的元素包括节点、构件和通信路径。

# 安全基础设施设计

安全很重要。这就是为什么 CASP 必须理解安全基础设施设计，并能够决定某些设备和应用程序的位置。安全基础设施设计包括路由器、防火墙、IDS/IPS、应用服务器、数据库服务器等的放置。它甚至包括日志设备的放置。

日志应当被创建并发送到远程服务器进行定期审查。另一个重要事项是信息如何从一个设备传输到另一个设备。应该考虑 SSL 和 TLS 等加密协议。路由器和其他网络设备应该能够通过多种安全访问协议进行管理。如果可能，应避免 TFTP、HTTP 和 FTP 等不安全协议。其他需要考虑的项目还包括：

- 规划
- 设计与布局
- 配置
- 管理

## 标准

所有组织必须在法律、标准和法规的框架内运行。这些标准、政策和法规规定了数据如何被处理、操作、存储和销毁。如果企业未能正确保护或处理信息，可能会面临法律罚款、失去公众信任甚至监禁。如果个人数据泄露给未经授权的人员，公司可能承担法律责任。

标准可以被描述为理想的测量、规范或平均值。有时公司会因缺乏标准而遭受痛苦。例如，处理个人身份时缺乏标准导致了各州法律不一的混乱局面。问题在于竞争性的标准。一个著名的例子是 BetaMax 与 VHS 之争；另一个是蓝光光与 HD DVD 之争。有时东西可能会成为事实标准（de facto standard）。事实标准是通过公众认可或市场力量获得主导地位的产品或活动。例如，可以考虑 Adobe 为 PDF 的事实标准，而 Microsoft Office 为文字处理的事实标准。

遵守标准是另一个重要关注的问题，因为违反标准的代价可能是昂贵的。例如，美国《健康保险流通性与责任法案》（HIPAA）对个人信息的处理实施了控制。未能提供适当保护水平的实体可能会面临每次违规 50,000 美元的罚款，每年上限为 150 万美元。

其他标准、政策和法规包括：

- **萨班斯-奥克斯莱法案（Sarbanes—Oxley Act）**：美国财务和会计披露与问责制
- **2003年美国公平准确信用交易法案（FACTA）**：一项旨在减少欺诈和身份盗窃的法律
- **巴塞尔协议III标准（Basel Accord Standard III）**：对银行业监管的建议
- **美国联邦信息安全管理法（FISMA）**：美国政府系统的安全标准

## 合并、收购及拆分/剥离过程中的设计考量

公司不断寻找业务优势。对于某些公司而言，合并和收购提供了增加业务机会的路径。例如，2010年大陆航空与联合航空的合并是一项超过 30 亿美元的合并。想想这两家航空公司的飞行系统、预订应用程序、网站以及它们网络的所有部分是如何整合为一个实体的。尽管这两家公司的运营方式相似，但此类合并的规模令人惊叹。

CASP 应该理解技术部署模型和设计考量，如外包、内包、合作伙伴关系、合并、收购和拆分。CASP 以及其他负责组织 IT 安全的人员在合并和收购期间应发挥作用。通常情况下，合并可以被描述为两家规模相当的公司合并，而收购则是一家大公司收购较小公司。在两种情况下，在整个过程中保持适当的安全控制都是至关重要的。这可以通过实施审慎和勤勉来实现。

![](img/7868547987f5920cfe632b85047c64af_552_0.png)

许多公司要求参与合并和收购的员工签署非竞争协议和保密协议，因为由于他们在过渡期间可能获得内幕信息。

## 技术部署模型（外包、内包、托管服务、合作伙伴关系）

在技术部署期间，IT 安全专业人员应该有机会审查外包、内包、托管服务或合作伙伴公司的安全控制和实践。如果发现违规行为，应向管理层报告，以便妥善识别费用和担忧。在合并或激活系统之前，CASP 应该询问这些基本问题：

- 谁允许访问资源？
- 将提供什么类型的访问？
- 用户将如何请求访问？
- 由谁授予用户访问权限？
- 将使用什么类型的访问日志？记录什么内容？何时进行审查？
- 对于不恰当使用资源将采取什么程序？
- 如何报告和记录安全事件？由谁来处理？
- 谁将负责调查可疑活动？

CASP 还应该关注制定基于知情业务决策的行动方案，旨在提供长期安全。以下是 CASP 熟悉的某些技术部署模型：

**外包**：外包可以定义为从外部提供者获取资源或项目。例如，考虑戴尔电脑。戴尔可能位于德克萨斯州的朗德岩，但其分销枢纽位于田纳西州的孟菲斯；戴尔在马来西亚组装电脑，并在印度提供客户支持。许多其他部分来自全球各地。

**内包**：内包可以定义为使用公司的人员来构建项目、资源或执行某活动。

**托管服务**：某些组织使用托管服务。一种常见的方法是使用托管云服务。托管云托管提供长期的服务，如数月或数年。在这种情况下，你可能以时间分片或作为虚拟服务器上的服务购买服务。这意味着数据聚合和数据隔离可能会发生。

数据聚合的安全担忧是，你的数据可能与其他数据合并，甚至可能被重复使用。例如，某些非营利捐赠者数据库可能与其他数据共享或被转用。数据隔离应解决你的数据如何存储的问题。

| 项目 | 测试风险使用的方法 |
|---|---|
| 试点测试 (Pilot test) | 验证应用程序的功能 |
| 白盒测试 (Whitebox test) | 验证程序内部逻辑；对于大型应用程序或系统而言，成本过高 |
| 黑盒测试 (Blackbox test) | 基于完整性的测试；关注输入和输出 |
| 功能测试 (Function test) | 根据清单或需求对程序进行验证 |
| 回归测试 (Regression) | 用于更改后，以验证输入和输出是否正确 |
| 并行测试 (Parallel test) | 通过将数据输入新系统和未更改的系统并比较结果，来验证新系统或更改后的系统 |
| 社会测试 (Sociability test) | 验证系统能够在其目标环境中运行 |
| 模糊测试 (Fuzz test) | 通过向输入中插入随机数据来监控软件反应，从而进行安全测试 |

无论你决定使用哪种开发方法，必须首先建立一套清晰的应用程序需求。应用程序需求就是应用程序要求执行的活动。例如，是否需要安全性？你是否需要为每个用户提供唯一的用户名和密码？你是否需要适用于云端部署的应用程序？这些只是你在制定征求书（RFP）之前可能提出的问题。

另一个关键问题是确定此新应用程序将如何与旧系统和当前系统协作。如果你有为 32 位计算机开发的应用程序，它们会在你的 Windows Server 2012 服务器上运行吗？它们会以旧模式运行吗？这些都是开发任何新应用程序之前需要询问的问题。

# 内部开发

如果你的公司正在考虑内部开发，应首先询问：

- 是否存在一个可以直接使用的产品？
- 现有产品是否已具备所需的安全控制？
- 供应商是否可以修改产品以满足我们的安全需求？

如果公司希望外包一个项目，将制定一份详细的 RFP。RFP 将用于向供应商征集方案。应该仔细检查供应商的响应，以找到符合项目团队要求的供应商。价格将是一个重要问题，CASP 还应该考虑供应商的声誉。例如，`www.macworld.co.uk/macsoftware/news/index.cfm?newsid=3286194` 于 2011 年 6 月 15 日报道，Adobe 必须在九天内第二次对其 Flash Player 中的关键漏洞进行补丁，因为黑客已经在利用它。即使选择了供应商，仍必须谈判合同。CASP 将希望确保产品中设计了足够的安全水平，并尽可能降低风险。

![](img/7868547987f5920cfe632b85047c64af_556_0.png)

软件托管是那些决定采用定制开发软件的公司的一种选择。软件托管允许组织在供应商破产或因某些原因不再支持该产品时，保持对应用程序源代码的访问。虽然组织可以修改软件以继续使用，但它不允许他们窃取设计或在公开市场上出售代码。

# 商业型/商业定制

当一个组织决定购买商业产品而不是自行构建时，决定通常取决于时间、成本以及预定义替代品的可用性。商业现货（COTS）软件的吸引之处在于，可以从 Microsoft 和 Adobe 等公司购买或许可软件，而不是在内部编写。COTS 缩短了部署时间；但代价是对第三方组件供应商的依赖性增加。在某些情况下，可能有一个商业产品可以满足你的大部分需求，但不是全部。在这种情况下，你可以与供应商签订合同，为你的公司开发商业定制应用程序。

# 调查你的公司

找到你公司中负责新产品和服务的员工，并请求通过电话、电子邮件或面对面对该个人进行访谈。制定几个问题来确定他们如何评估第三方产品，以确保只接受可控的风险。询问他们在处理 RFP 时有哪些类型的疑虑，以及使用什么种方法计算风险。

# 互操作性问题

在将产品和服务集成到环境中时，CASP 需要确定什么类型的互操作性问题。一个非常有用的工具是计算机辅助软件工程（CASE）。CASE 不仅用于软件过程活动，还可用于重构、开发和测试。测试可以帮助发现开发过程中未发现的互操作性问题。

![](img/7868547987f5920cfe632b85047c64af_558_0.png)

> 在构建早期发现互操作性问题总是更便宜的。然而，良好的安全设计流程会在开发过程的每一步寻找问题。

CASE 工具通常被分为不同的领域，如下：

- 反向工程
- 需求管理
- 过程管理
- 软件设计

开发过程中未发现的互操作性问题可能会在部署期间发现。这就是部署策略如此重要的原因之一。部署技术包括以下：

**硬切换（Hard Changeover）**：硬切换在特定日期部署新产品或服务。在这一时间点，所有用户都被强制切换到新产品或服务。硬切换的优势是切换是彻底且完成的。我将其类比为快速撕掉创可贴。可能会有一些疼痛或不适感。

**并行运行（Parallel Operation）**：在并行运行下，现有系统和新系统同时运行。优点是为你提供了比较结果的机会。当用户开始使用新系统工作时，旧系统就可以关闭。这种方法的主要缺点是必须维护两个系统，因此会有额外费用。

**分阶段切换（Phased Changeover）**：如果选择分阶段切换，将逐步升级新系统。例如，首先推向营销部门，然后是销售部门，最后是生产部门。这种方法也有优势，但需要额外成本。希望产品和服务的用户接受了培训。培训策略有很多，但通常包括课堂培训、在线培训、练习课程和用户手册。在产品和服务集成完成且员工接受培训后，你可能被评估投资回报率（ROI）或查看真实的回收分析。

> 在过程结束时，询问一些基本问题，例如新系统是否足够、真实的 ROI 是多少、是否遵循了所选标准以及是否遵循并实施了所有安全标准。

# 企业应用集成要素

随着全球经济的兴起，企业日益面临从哪里获取材料、商品服务的根本决定。资源往往远超产品制造地，分布在世界各地。一些可能的解决方案包括：

**CRM**：客户关系管理（CRM）由公司用于管理与客户关系的工具、技术和软件组成。CRM 解决方案旨在跟踪并记录有关客户的所有信息。这包括购买历史、预算、时间表、兴趣领域以及他们计划的未来购买。设计的产品从简单的现货联系管理应用程序到结合营销、销售和执行信息的高级交互系统。CRM 通常涉及三个领域：销售自动化、客户和服务企业营销。

**ERP**：另一种改进方法是企业资源计划（ERP）。该方法的目标是将组织的所有流程集成到一个单一集成系统中。构建一个统一系统具有许多优势，可以满足财务、人力资源、制造等人员的需求。
