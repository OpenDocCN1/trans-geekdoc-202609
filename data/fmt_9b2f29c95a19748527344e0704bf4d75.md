## 5.6 尝试减轻 GC 压力

无论 GC 调优器如何（以及未来如何），减轻 GC 压力的基本原理包括：

- 在堆上分配更少短周期的内存块（垃圾回收产生速度）。
- 创建更少的指针（扫描工作负载控制）。

当局部值分配在堆上时，栈上会创建一个隐式指针来引用该局部值，以便该值部分是可追溯的（从栈开始）。这意味着减少堆分配有助于减少指针。

在编程中，内存分配和指针创建是不可避免的。如果需要，就尽管去做。我们不需要费精力去刻意避免指针。

事实上，指针通常可以用来优化成本。是否使用某些指针取决于具体情况。我们应该在缺点显而易见的情况下避免使用指针。

我们应该避免不必要的内存分配，尤其是不必要的内存分配。然而，由于许多原因（如语言安全性和 API 设计限制），不必要的内存分配很难完全避免。Go 不是 C，我们应该承认并接受这一事实。毕竟，Go 比 C 提供了更多便利性。

## 5.7 使用 GC 控制频率

`GOGC` 变量设置了 GC 周期后堆的目标百分比。默认值为 100，这意味着在触发下次 GC 周期时堆将翻倍。你可以通过 `GOGC` 环境变量或调用 `runtime/debug.SetGCPercent` 来更改此值。

如果 `GOGC` 值为负数，则禁用 GC。

当 `GOGC` 值为正数时，Go 运行时将使用以下公式计算下次 GC 周期的目标堆大小：

```
target heap size = live heap * (1 + GOGC/100)
```

例如，如果 `GOGC` 为 100，目标堆大小将是活堆的两倍。如果 `GOGC` 为 200，目标堆大小将是活堆大小的三倍。

通过增加 `GOGC` 可以减少 GC 周期的频率但会增加内存占用。通过减少 `GOGC` 可以减少内存占用但会增加 GC 周期的频率。

	"math/rand"
	"time"
)

	rand.Seed(time.Now().UnixNano())
	for i := 0; i < 1; i++ {
		n := 6 + rand.Intn(6)

			x[j] = make([]int, 1<<n)
			for k := range x[j] {
				x[j][k] = new(int)
			}
		}
	}
	time.Sleep(time.Second / 1000)
}

## 5.10 使用 Go 工具链 v1.19 引入的内存限制策略避免频繁的 GC 循环

Go 标准编译器 v1.19 引入了一种新的调度策略：内存限制策略。该策略可以通过 `GOMEMLIMIT` 环境变量或 `runtime/debug.SetMemoryLimit` 函数进行配置。此内存限制设置了 Go 运行时使用的内存上限。换句话说，如果 Go 使用的内存总量（近似）超过了限制，当限制不再被超过时，将启动新的垃圾回收过程。内存限制的默认值为 `MaxInt64`，这实际上是禁用了该策略。

`GOMEMLIMIT` 环境变量可以有一个可选单位。支持的后缀包括 `B`、`KiB`、`MiB`、`GiB` 和 `TiB`。没有单位的值表示 `B`（字节）。内存限制和新的堆内存百分比策略可能会相互影响。为了演示目的，让我们禁用新的堆内存百分比策略并启用内存限制策略，以运行上面的 `gctrace` 示例。否则，`GOGC` 环境变量将被设为 `off`，因此自动垃圾回收将被关闭。

```
$ GOGC=off GOMEMLIMIT=157MiB GODEBUG=gctrace=1 go run gctrace.go
gc 1 @0.283s 1%: 153->156 MB, 157 MB goal, ...
gc 2 @0.784s 1%: 151->152 MB, 155 MB goal, ...
gc 3 @1.445s 1%: 149->151 MB, 152 MB goal, ...
gc 4 @2.113s 1%: 148->150 MB, 152 MB goal, ...
gc 5 @2.765s 1%: 148->150 MB, 152 MB goal, ...
gc 6 @3.394s 1%: 147->150 MB, 152 MB goal, ...
gc 7 @4.006s 1%: 147->147 MB, 152 MB goal, ...
gc 8 @4.653s 1%: 147->147 MB, 152 MB goal, ...
gc 9 @5.326s 1%: 148->152 MB, 152 MB goal, ...
gc 10 @6.007s 1%: 148->149 MB, 152 MB goal, ...
```

从输出中可以看出，内存限制策略还可以让 GC 间隔变得大得多且平稳分布。

内存限制策略的目标之一是提供一种官方方法来替代内存气球（memory ballast）技巧。对于 Go 程序，如果合理设置了内存限制值，就能实现该目标。然而，有时很难为内存限制选择一个合适的值。如果该值小于 Go 程序实际需要的内存量，GC 循环将频繁启动。与上述所示的内存气球方案相比，这是一个缺点。请阅读关于使用内存限制策略的建议（其中包含了一篇理解 Go 垃圾回收的优秀文章）。
