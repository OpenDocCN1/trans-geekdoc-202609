
例如，假设贵公司拥有一个学习管理系统（LMS），一个学生订阅课程的平台。您拥有学生的活动数据，并希望利用机器学习改善体验。您可以做以下几件事：

*   创建推荐引擎，为学生推荐新课程。
*   流失预测，判断学生是否会退课。
*   流失预测，判断教师是否不会回归。
*   识别什么让课程对学生更有吸引力（样题、更多图片、更多表格、短视频等）。
*   识别学生偏好的学习类型（听觉型、视觉型或动觉型）。

哪个影响最大，这个问题只能由业务所有者来回答。

一旦您确定了对业务影响最大的用例，就需要确定机器学习解决方案的结果。简而言之，如果您实施了您的解决方案，会发生什么？有时，您的模型会做出准确的预测，但环境可能会以适得其反的方式对这些预测做出反应。这是因为环境很少是静态的；用户可能会适应，或者可能会对预测的行为感到困惑。

例如，假设贵公司拥有一个视频分享网站，拥有数百万视频。您正试图构建一个 ML 模型向用户推荐视频。您可以从以下方案中选择：

*   一个推荐热门创作者未看视频的 ML 模型。问题在于这不够个性化。如果用户不喜欢其中一些创作者怎么办？
*   一个推荐点击量大的视频的 ML 模型。但如果这些只是标题党，人们点击后后悔浪费时间怎么办？
*   一个推荐相似用户看完的视频的 ML 模型。这将改善用户体验。

在该示例中，您需要对用例、总体目标和最终用户有良好的理解，才能找到合适的切入点。

接下来，弄清楚该问题是否甚至可以用机器学习来解决。业务领导者在媒体上听到企业用 ML 解决问题的鼓舞人心的故事，听起来很神奇，他们也想用它来解决自己的业务问题。他们需要像您这样的专家来判断用 ML 解决他们的问题甚至是否可行。这听起来不像那么容易；这取决于多个因素，如现有技术、可用数据和预算。例如，自然语言处理已取得长足进步，使得几年前不可能的事情成为可能，例如使用 ML 根据一段文本回答问题。熟悉自然语言处理的最新进展将帮助您识别更简单、更快、更好的 ML 方法来解决业务问题。

作为下一步，您将需要识别适合您用例的 ML 学习方法。

### 机器学习方法

许多机器学习问题已得到充分研究并拥有优雅的解决方案，但有些算法并不完美，有些问题可以用多种方式解决。有时，用例将完美契合 ML 框架，有时则不然。您需要了解 ML 问题的全貌。机器学习方法有多种途径。其中一些方法已被研究数十年，而另一些则相对较新。应用机器学习技术的方法有成百上千种。为了帮助我们掌握这些方法的广度，我们将它们组织成几个类别（也称为方法、类型、途径或问题）。每种方法解决一类特定的问题，由数据类型、预测类型等区分。

我们将在以下章节中探讨对这些方法进行分类的不同方式。

#### 监督学习、无监督学习和半监督学习

对机器学习方法进行分类的一种常用方法是基于学习类型。当你拥有一个可用于训练模型的**带标签数据集**时，这被称为 `supervised learning`（监督学习）。例如，监督学习就是尝试构建一个模型来对狗和猫的图像进行分类，并能够使用相应标记好的图像数据集。

在某些情况下，你只有**无标签数据**，例如一组图像（没有任何标签或标记），并且你会被要求对它们进行分类或分组。这将是一个 `unsupervised`（无监督）ML 模型。聚类算法是一套属于此类的算法，用于对数据进行分组和/或分类。自编码器也是一类属于此类的算法。自编码器用于降低输入数据的维度，这是许多机器学习模型中的预处理步骤。

另一个流行的无监督 ML 用例是 `topic modeling`（主题建模），这是一种文档聚类问题。算法接收文档，并根据文本中单词和句子的共性将它们分为 N 个类别。将其与人类对书籍（例如在图书馆中）的分类方式进行比较，你可能会将它们分为小说、非小说、科学、历史等。有时，你可能会根据语言对书籍进行分类（例如英语、中文、印地语）。同样，无监督算法可能会也可能不会按照你预期的方式进行分类。无监督学习方法的输出无法完全控制，而且几乎从来都不完美，因此需要仔细调整以获得所需结果。表 1.1 提供了 Google Cloud 中现成的一些流行 ML 模型类型的详细信息。

为了解决无监督学习中的不确定性问题，有一种称为 `semi‐supervised learning`（半监督学习）的混合解决方案，即部分数据带标签，而其他数据不带标签。这就像引导算法朝向你想要看到的聚类方向。虽然半监督模型是有趣的研究课题并具有一定效用，但在大多数用例中，仍使用监督模型。

除了这些之外，还有许多其他类型的机器学习模型，包括强化学习（算法不获得数据，而是获得一个环境，智能体在其中探索并学习）和主动学习算法，但它们超出了认证考试的范围。

对机器学习算法进行分类的另一种方式是基于预测类型。模型将预测的数据类型决定了机器学习算法的多个方面及所用的方法。接下来我们将探讨这一点。

#### 分类、回归、预测和聚类

`Classification`（分类）是预测“标签”、“类别”或“种类”的过程。给定一张宠物图片，区分狗与猫就是一个分类问题。如果只有两个标签，称为 `binary classification`（二元分类）；如果有更多标签，称为 `multiclass classification`（多分类）。你可能会有成千上万个标签的分类；例如，Cloud Vision API 可以对图片中数百万种不同的物体进行分类，这是一个更难解决的问题。你不能将同一个模型同时应用于二元分类、多分类和成千上万类别的分类。

在 `regression`（回归）中，ML 模型预测一个数字——例如，房价预测（给定卧室数量、面积、邮政编码）、降雨量预测（给定温度、湿度、位置）。这里预测值的范围取决于用例。用于回归的 ML 算法通常不同于分类。通常，你会发现结构化数据（行和列的数据）被用于回归问题，如表 1.2 所示。

**表 1.2** 结构化数据

| --- | --- | --- |
| 1 | 34 | 75 |
| 2 | 23 | 59 |
| 3 | 36 | 92 |
| 4 | 31 | 67 |

`Forecasting`（预测/时间序列预测）是另一种类型，其输入是时间序列数据，模型预测未来值。在时间序列数据集（表 1.3）中，你会获得一系列按时间顺序索引的输入值。例如，你有一系列由传感器每小时采集一次、持续 10 小时的温度测量值。在这种情况下，某一次温度读数与前一次和后一次读数相关，因为它们来自同一传感器、在后续小时内采集，且通常每小时仅在小范围内变化，因此它们不被视为“独立”（这是与其他类型结构化数据的一个重要区别）。

`Clustering`（聚类）是另一种类型的问题，算法根据不同数据点之间固有的相似性和差异在数据中创建组。例如，如果我们获得地球上每栋房子的经纬度，算法可能会根据房屋群之间的距离，将每个数据点分组为城市聚类。K-means 是此类中流行的算法。

#### 二分类模型评估指标

假设你正试图从 X 光片中检测一种罕见的致命疾病。这是一个二分类问题，有两种可能的结果：阳性/阴性。给定一组一百万张带标签的 X 光图像，其中只有 1% 的病例患有该疾病（即阳性样本）。在这种情况下，错误的阴性预测（假阴性），即我们预测患者没有患病而实际上患病，可能导致患者无法及时采取行动，因不作为而造成伤害。但错误的阳性预测（假阳性），即我们预测患者患病而实际上未患病，可能给患者带来过度担忧，并导致进一步的医学检查以确认预测。在这种情况下，准确率（正确预测的百分比）不是正确的度量指标。

现在让我们考虑一个不平衡数据集二分类预测数字的示例，如表 1.4 所示。

**表 1.4** 二分类示例的混淆矩阵

| | 预测结果 |
| --- | --- |
| **实际类别** | **阳性预测** | **阴性预测** |
| **阳性类别** | 5 | 2 |
| **阴性类别** | 3 | 990 |

有两个可能的预测类别：阳性和阴性。通常较小的类别（几乎总是更重要的类别）被表示为阳性类别。在表 1.4 中，我们共有 1,000 个数据点，并对每个数据点进行了预测。我们将预测值与实际值进行了列表对比。在 1,000 个数据点中，有 7 个属于阳性类别，993 个属于阴性类别。模型预测 8 个为阳性类别，992 个为阴性类别。右下角代表真阴性（990 个正确预测为阴性），左上角代表真阳性（5 个正确预测为阳性）。左下角代表假阳性（3 个错误预测为阳性），右上角代表假阴性（2 个错误预测为阴性）。现在，利用该混淆矩阵中的数字，我们可以根据需要计算各种指标。

如果该模型用于检测癌症，我们不希望漏检疾病；换句话说，我们希望假阴性率较低。在这种情况下，**召回率** 是一个好的指标。

```
Recall = True Positive / (True Positive + False Negative)
```

在本例中，召回率 = 5 / (5 + 2) = 0.714。如果假阳性较高，召回率指标会降低，因为假阴性在分母中。召回率范围为 0 到 1，分数越高越好。直观上，召回率衡量的是模型正确预测的阳性数据点所占的百分比。

另一方面，如果这是不同的用例，你试图减少假阳性，则可以使用**精确率** 指标。

```
Precision = True Positive / (True Positive + False Positive)
```

在本例中，我们有 3 个假阳性，因此精确率得分为 5 / (5 + 3) = 0.625。直观上，精确率量化了实际正确的阳性预测所占的百分比。

有时，你的用例可能同时关注减少假阳性和假阴性。在这种情况下，我们使用精确率和召回率的调和平均数，称为 **F1 分数**。（存在更通用的 Fβ 分数，取决于你希望如何加权精确率和召回率，F1 只是其中一种情况。）

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

在本例中，我们得到 2 × (0.625 × 0.714) / (0.625 + 0.714) = 0.666。同样，F1 范围为 0 到 1，分数越高表示模型质量越高。这三个指标总结在表 1.5 中。

#### 回归

回归预测数值。指标应尝试显示实际值与预测值之间的定量差异。

*   **MAE** 平均绝对误差（`MAE`）是实际值与预测值之间平均绝对差异。
*   **RMSE** 均方根误差（`RMSE`）是目标值与预测值之间平均平方差的平方根。如果您担心模型可能会错误地预测一个非常大的值并希望惩罚模型，则可以使用此指标。范围从 0 到无穷大。
*   **RMSLE** 对数均方根误差（`RMSLE`）指标类似于 `RMSE`，不同之处在于它使用预测值和实际值 +1 的自然对数。这是一个非对称指标，它惩罚低估（预测值低于实际值）而非高估。
*   **MAPE** 平均绝对百分比误差（`MAPE`）是标签与预测值之间平均绝对百分比差异。当您关心实际值与预测值之间的成比例差异时，应选择 `MAPE`。
*   **R²** R 平方（`R²`）是标签与预测值之间皮尔逊相关系数（`r`）的平方。此指标范围从 0 到 1；通常较高的值表示模型拟合度更好。

### 负责任的 AI 实践

AI 和机器学习是强大的新工具，权力越大责任越大。您应在 ML 解决方案中考虑公平性、可解释性、隐私和安全性。您可以借鉴软件工程的最佳实践，并结合机器学习特有的考量因素。

*   **通用最佳实践** 始终牢记最终用户及其用户体验。您的解决方案如何改变某人的生活？在设计过程早期征求反馈。与您预期会使用该解决方案的多样化用户群体互动并进行测试。这将构建丰富的多元视角，并允许您在设计阶段早期进行调整。
*   **公平性** 公平性非常重要，因为机器学习模型可能反映并强化不公平的偏见。在实践中公平性也很难实现，因为从不同视角（学术、法律、文化等）有多种公平性定义。此外，不可能将同一种“公平性”应用于所有情况，因为它非常依赖上下文。首先，您可以使用统计方法衡量数据集中的偏见，并在评估阶段测试 ML 模型的偏见。
*   **可解释性** 一些流行的最先进机器学习模型（如神经网络）过于复杂，人类难以理解，因此被视为黑盒。缺乏可见性会产生疑虑，并可能隐藏偏见。*可解释性*是深入了解模型和预测的科学。某些模型天生更具可解释性（如线性回归、决策树），而另一些则可解释性较差（深度学习模型）。提高可解释性的一种方法是使用*模型解释*。模型解释量化了每个输入特征对预测的贡献。然而，并非所有算法都支持模型解释。在某些领域，模型解释是强制要求的，因此您的算法选择会受到限制。
*   **隐私** 训练数据与预测之间的唯一联系是 ML 模型。虽然模型仅根据输入值提供预测，但在某些情况下，它可能会泄露关于训练数据的一些细节。如果您使用敏感数据（如病史）进行训练，这将成为一个严重问题。尽管检测和防止数据泄露的科学仍是活跃的研究领域，但幸运的是，现在已有技术能够以精确且原则性的方式最大程度地减少泄露。
*   **安全性** 网络安全威胁非常适用于机器学习。除了任何数字应用面临的常规威胁外，机器学习应用还面临一些独特的安全挑战。这些威胁无处不在，从数据收集阶段（投毒数据）、训练阶段（训练数据泄露）到部署阶段（模型窃取）。识别系统的潜在威胁、持续学习以保持领先以及制定应对这些威胁的方法非常重要。

您可以在 `https://ai.google/responsibilities` 阅读更多内容。

*   **将业务挑战转化为机器学习** 理解希望使用机器学习解决问题的业务用例。了解问题类型、数据可用性、预期结果、利益相关者、预算和时间线。
*   **理解问题类型** 理解回归、分类和预测。能够区分每种问题类型的数据类型和流行算法。
*   **了解如何使用 ML 指标** 理解什么是指标，并将指标与用例匹配。了解每种问题类型的不同指标，如精确率、召回率、F1、AUC ROC、RMSE 和 MAPE。
*   **理解 Google 的负责任 AI 原则** 在公平性、可解释性、隐私和安全性的背景下理解 AI 的推荐实践。
