
你必须为威胁、影响和资产价值确定合适的值以计算风险。

## 威胁 vs. 可能性

系统受到的威胁的严重性是一个重要的衡量标准。如果攻击成功但结果没有重大影响，那么这种攻击可能不构成太真正的风险。另一种攻击可能具有破坏性，以至于系统无法使用，这显然需要缓解。另一个衡量标准是攻击成功的可能性。如果可能性较低，则风险就会降低。如果可能性很高，则风险更高。真正的衡量标准是严重性和可能性的结合，通常将两者相乘。高可能性和高严重性的组合尤为危险，比低水平的组合值得多得多的关注。

攻击者也使用相同的衡量标准，因为他们会花费更多时间在成功率更高的方法上。在所有其他方面都相等的情况下，这提供了一种优先考虑防御措施的方法。

## 评估类型

可以进行几种类型的评估。`评估`（assessment）是针对一组特定条件对系统进行的检查。评估可以针对威胁、漏洞和风险。这些评估每种输出都侧重于提供有关实际评估内容的信息。因此，虽然各种类型的评估可以互换使用，但它们的结果不同。

## 风险

`风险分析`（risk analysis）和`漏洞评估`（vulnerability assessment）有时互换使用，但这并不准确。分析和评估这两个词可以无缝替换，但风险不同于漏洞。漏洞将在本章后面的部分介绍。

风险分析通常从定量视角或定性视角进行。量化风险分析试图为坏情况发生的概率和该事件造成的损失设定数值（通常以美元为单位）。定性风险分析更多地依赖于估计的潜在损失以及相关的风险等级。

**考试提示** 量化风险分析试图为坏情况发生的概率和该事件造成的损失设定数值，而定性风险分析则依赖于发生和影响的相对水平。

## 威胁

`威胁评估`（threat assessment）是对企业面临的威胁的结构化分析。理解威胁很重要，因为你通常无法改变威胁——你只能改变它如何影响你。威胁评估首先是列举所有存在的威胁，然后对每个威胁的成功可能性进行估计。分析每个威胁对企业的潜在影响，可以提供一个优先关注的威胁列表。

## 漏洞

`vulnerability assessment`（漏洞评估）对于评估网络及其关键系统的安全态势非常有益。所有系统都存在漏洞，因此了解系统中存在哪些特定漏洞是确保系统的关键。识别已存在的漏洞并量化其影响可以帮助你决定采取何种缓解/保护策略。漏洞评估可以帮助确定在何方面投入安全预算，以及在何方面投入人力，甚至可以用于帮助获取额外资源。通常，保护网络或系统的第一步是找出它们损坏得有多严重。

## 评估技术

可以采用多种技术对系统进行评估。每种技术都有其自身的优势，并旨在详细说明系统的某些特定方面。基准报告（Baseline reporting）可以衡量系统在基准配置下的安全态势。代码审查（Code reviews）作为检查可审查代码库应用程序的评估工具是非常有用的。检查攻击面和审查架构是确定安全态势的其他方法。

## 基准报告

对系统的基准报告可以提供有关系统安全方面状态的信息。正如本节前面讨论的，存在诸如 `Microsoft Baseline Security Analyzer`（微软基准安全分析器，见图 16-3）之类的工具，用于衡量系统的基准安全配置。虽然之前的示例侧重于操作系统的安全态势，但存在独立的工具可以对安装的应用程序基础执行相同的分析。图 16-7 显示了 `Secunia Personal Software Inspector (PSI)` 对系统进行扫描的结果。`Secunia PSI` 是一个设计用于监控应用程序更新并帮助用户保持应用程序最新状态的程序。

## 代码审查

`Code review`（代码审查）本质上是对源代码的校对。代码审查旨在发现编程错误和糟糕的编码实践，这些因素可能导致缓冲区溢出、内存泄漏、未处理的异常等漏洞。代码审查可以通过多种方式进行，从非正式的（一名程序员在另一位开发者身后查看）到极其正式的（例如团队对整个代码库进行走读）。代码审查可以手动进行，但也存在提供自动化代码审查能力的工具。这些自动化审查工具可用于扫描大型代码库，并识别潜在问题或可能存在问题的区域。开发者就可以关注这些区域，而无需手动扫描整个代码库。自动化扫描后进行手动审查是一种广泛接受的通用做法，与手动审查整个代码库相比，它以低得多的“成本”提供了良好的覆盖率。

代码审查的主要益处是尽快发现并解决漏洞和安全问题——最好在软件进入正式测试之前。在开发过程中越早发现并解决漏洞，修复成本就越低。以 `Microsoft Word` 为例——如果在开发阶段发现了一个漏洞，那么在那里纠正它比在发布产品中修复该漏洞要便宜得多。在开发阶段解决该漏洞可能涉及几名开发者和几行带注释的代码。而在已发布的产品中解决同一个漏洞则涉及代码修订、配置管理、回归测试、补丁开发、补丁说明开发等。如你所见，生产后解决漏洞所需的巨大工作促使许多组织在开发周期内早期且频繁地进行代码审查。

## 确定攻击面

软件的 `attack surface`（攻击面）是指系统中可被未经授权的方访问的代码。这不仅包括代码本身，还包括与代码相关的广泛资源，如用户输入字段、协议、接口、资源文件和服务。攻击面的一个衡量标准是可访问项目的总数或加权数量。根据严重程度进行加权可能会改变某些决策点，但底线很简单：可攻击元素越多，风险就越大。攻击面的大小并不代表代码的质量——它仅仅衡量了可攻击项的数量。一项长久的安全实践是不启用不需要的功能。通过关闭不需要的功能，可以缩小攻击面并减少安全风险。在开发过程中理解攻击面是一个重要的安全功能。定义攻击面并记录更改有助于做出更好的安全决策。

无论软件是什么或功能如何，它都会受到攻击，且通过非常常见的方式进行。例如，薄弱的访问控制列表（ACLs）是一个常见的攻击点，无论操作系统如何都可以被利用。针对操作系统的攻击也可以用于许多原本安全的应用程序。攻击面评估是衡量和确定与设计相关的风险的方法。

要了解产品的攻击面，你需要衡量它被“访问”的方法。每个软件产品可能不同，但它们也会共享元素。与其他许多安全项目一样，团队首次构建攻击面元素列表时会比较困难。但随着时间的推移，增进式的检查将详细更多项目，使未来的列表更容易制定。在此背景下，以下是微软发布的与 Windows 相关的攻击面元素列表。虽然此列表并不完全适用，但它提供了一个起点，并作为攻击面元素类型的指南。

- 打开的套接
- 打开的远程过程调用 (RPC) 端
- 打开的命名管道
- 服务
- 默认运行的服务
- 以 `SYSTEM` 身份运行的服务
- 活动的 Web 处理程序（ASP 文件、HTR 文件等）
- 活跃的 Internet 服务器应用程序接口 (ISAPI) 过滤器
- 动态网页（ASP 等）
- 可执行的虚拟目录
- 已启用的账户
- 管理员组中的已启用账户
- 对管道和共享的空会
- 访客账户启用
- 文件系统中的薄弱 ACLs
- 注册表中的薄弱 ACLs
- 共享的薄弱 ACLs

另一个信息来源是与之前的开发相关的已知漏洞历史。确定旧漏洞的根源有助于修复它们并防止未来发生，这也是用于确定攻击面的宝贵信息。

构成攻击面的特征列表，与攻击者用于攻击特定软件的列表是同一个列表。列表中的项目并不一定是漏洞，但它们是攻击者会尝试破坏的项。这些元素是所有漏洞的基础，因此对于某个特定的攻击面元素，可能存在也可能不存在漏洞，但每个漏洞下都会有一个未被发现的。这使得对攻击面的衡量成为对潜在漏洞表面的可靠估计。

## 审查架构

对系统架构进行审查可以为系统的弱点和漏洞提供重要线索。架构审查应涵盖组件、数据如何在组件之间传输、组件的访问控制列表、数据传输以及用户连接。有许多安全架构框架可以帮助正确地设计系统。Web 应用的一种常用框架是开放 Web 应用程序安全项目（OWASP），这是一个专注于 Web 应用程序安全的社区驱动型开源活动。其他架构指南可以在信息和相关技术控制目标（COBIT）和信息技术基础库（ITIL）中找到。

## 审查设计

需要根据安全需求对设计进行审查，包括访问控制需求、数据安全和系统配置需求。利用攻击面区域文档和威胁模型的结果，安全团队能够适当评估应用程序中的安全功能。代码走查、设计审查、攻击面区域检查以及针对完整性的威胁建模文档是这些审查的关键元素。

## 渗透测试

`penetration test`（或 `pentest`）模拟来自恶意外部人员的攻击——探测你的网络和系统以寻找进入方式（通常是任何进入方式）。渗透测试通常是最侵略性的安全测试形式，可以采取多种形式，取决于什么被视为“范围之内”或“范围之外”。例如，某些渗透测试仅仅是寻找进入网络的方法——任何进入方法。这可以从跨网络链路的攻击到社会工程，再到让测试人员物理闯入建筑。其他渗透测试则受到限制——仅允许跨网络链路的攻击，而不允许任何物理攻击。

无论范围和允许的方法如何，渗透测试的目标都是：确定攻击者是否可以绕过你的安全措施并访问你的系统。与漏洞评估不同（漏洞评估通常只是列出漏洞），渗透测试尝试利用漏洞以查看该漏洞允许多大的访问。渗透测试非常有用，体现在：

- 可以显示一系列“低风险”项目之间的关系，这些项目可以被顺序利用以获得访问权限（使其在总体上成为一个“高风险”项）。
- 可以用于测试员工的培训、安全措施的有效性，以及员工检测和响应潜在攻击者的能力。
- 通常可以识别并测试传统扫描工具难以甚至无法检测的漏洞。

**考试提示** 渗透测试专注于确定保护系统所使用的安全控制措施的有效性。

## 验证威胁是否存在

渗透测试的一个方面是演示现实世界中遇到的威胁向量。由于渗透测试旨在提供可以增强系统的信息，潜在攻击的范围源于环境。

## 绕过安全控制

渗透测试人员执行的关键测试之一是绕过安全控制。如果安全控制缺失、无效或配置不当，发现这种情况就是渗透测试人员的任务。

## 主动测试安全控制

安全控制的存在是为了缓解威胁带来的风险。渗透测试可以在现实条件下主动攻击这些控制措施。

## 利用漏洞

渗透测试的关键元素是对漏洞的实际利用。利用遇到的漏洞有两个目的：首先，它证明了存在的风险水平；其次，它证明了攻击向量的可行性。在渗透测试期间，利用不会达到破坏性活动的程度。

## 漏洞扫描

帮助管理员保护系统的一种非常有价值的方法是漏洞扫描。漏洞扫描是检查系统和网络设备中的漏洞、弱点和问题的过程，并在攻击者发现之前找到它们。名为 `vulnerability scanners` 的专用工具旨在帮助管理员发现并解决漏洞。但漏洞扫描远不止于简单运行工具和检查结果——管理员必须能够分析任何发现的漏洞并确定其严重性、如何处理它们，以及是否会对任何业务流程产生影响。漏洞扫描还可以帮助识别账户设置、补丁级别和操作系统中的常见配置错误。大多数组织将漏洞扫描视为一个持续的过程，因为仅仅扫描一次系统并假设从那个时候起它们是安全的是不够的。

## 被动测试安全控制

当使用自动漏洞扫描器检查系统漏洞时，其副作用之一是对安全控制措施的被动测试。这被称为 `passive testing`，因为漏洞扫描器的目标是系统而不是控制措施。如果安全控制是有效的，那么漏洞扫描可能无法正确识别漏洞。

## 识别漏洞

漏洞是已知实体；否则扫描器将没有扫描它们的能力。当扫描器发现系统中存在漏洞时，它会记录这一事实。最后，发现的漏洞的枚举是漏洞分析报告的一部分。

漏洞方面的一个失败来源是系统配置不当。常见的配置错误包括访问控制失败和未能保护配置参数。漏洞扫描器可以编写为测试这些特定条件并进行报告。

漏洞扫描器需要一种方法来检测是否存在以及是否可以利用漏洞。一种方法是执行一种改变系统状态的测试，即侵入式测试。另一种方法是以一种不直接与特定漏洞交互的方式进行测试。这种非侵入式方法在实际确定漏洞时，准确性可能会低得多。如果漏洞扫描涉及大量检查，那么非侵入式方法可能具有优势，因为服务器可能不需要频繁重启。

## 有凭据扫描与无凭据扫描

漏洞扫描器可以被录入系统的凭据，使其拥有与授权用户相同的访问权限。这被认为比在没有凭据的情况下运行相同测试要容易，而后者被广泛认为是更符合现实世界的攻击尝试。运行这两种扫描都是非常重要的，因为如果攻击者能够攻破账户，他们很可能拥有内部凭据。有凭据扫描在确定漏洞是否存在时会更准确，因为它们不受访问控制的限制。

## 误报

工具并非完美。有时，它们会将某些事情错误地报告为问题，但实际上它们并不是问题；而在另一些时候，它们完全不会报告某个问题。`false positive`（误报）是一个错误的发现——即被错误报告为漏洞的内容。扫描器告诉你存在某个问题，但实际上什么问题也没有。`false negative`（漏报/假阴性）则是指扫描器未能报告一个实际上存在的漏洞——扫描器简单地遗漏了该问题，或者没有将其报告为问题。

## 测试

在描述漏洞测试和渗透测试的环境时，可以使用不同的测试方法论。就像在测试环境中一样，黑盒、白盒和灰盒测试术语被用于识别与测试相关的系统知识水平。

### 黑盒

`Black-box testing`（黑盒测试）是一种软件测试技术，通过自动化方式注入畸形/半畸形数据来发现实现层漏洞。黑盒技术测试软件的功能，通常从外部或用户的角度进行。使用黑盒技术的测试人员通常对他们正在测试的软件的内部运行机制一无所知。他们将整个软件包视为一个“黑盒”——输入数据并观察输出。他们无法看到应用程序内部如何处理数据，只能看到返回给他们的输出。黑盒测试的测试用例通常围绕预期功能（软件应该执行的操作）构建，并侧重于提供有效和无效的输入。

黑盒软件测试技术对于检查任何基于 Web 的应用程序非常有用。基于 Web 的应用程序从暴露在公共流量的一刻起，通常会受到大量有效、无效、畸形和恶意输入的攻击。通过在应用程序发布之前进行黑盒测试，开发者可能可以在开发或测试阶段发现并纠正错误。

黑盒测试也可以应用于网络或系统。渗透测试和漏洞评估通常从纯粹的外部视角进行，测试人员对他们正在检查的网络或系统没有内部知情。

### 白盒

`White-box testing`（白盒测试）几乎是黑盒测试的对立面。它也被称为透明盒测试，白盒技术测试应用程序内部结构和处理过程，以寻找漏洞、缺陷等。白盒测试人员将对他们正在检查的应用程序有详细了解——他们将开发旨在执行应用程序每个路径、决策树、输入字段和处理例程的测试用例。

白盒测试通常用于测试应用程序内部路径（如果 X，则执行此；如果 Y，则执行彼）、数据流、决策树等。有时 `white-box testing` 术语也应用于网络评估，此时测试人员将对网络有详细了解，包括但不限于 IP 地址、网络路由、有效用户凭据等。在这些情况下，测试人员通常被称为“白帽”。

### 灰盒

那么，当把一点黑盒测试和一点白盒测试混合时会发生什么？你得到了灰盒测试。在灰盒测试中，测试人员通常对他们正在测试的软件、网络或系统有一定的了解。由于这个原因，灰盒测试可以非常高效有效，因为测试人员通常可以快速排除整个测试路径、测试用例和工具集，并排除那些根本无效且不值得尝试的东西。

![image](img/examtip.jpg)

**考试提示** 黑盒测试与白盒测试的主要区别在于视角和知识。黑盒测试人员对内部机制一无所知，从外部视角进行测试。白盒测试人员对内部机制有详细了解，从内部视角进行测试。

### 答案

1. 如果审计部门需要一份系统及其上开放服务的列表，端口扫描器就是你需要的。任何好用的端口扫描器（如 `nmap`）都能检测这些系统。
2. 如果你想在不了解软件内部原理或构建方式的情况下对其进行测试，那么你寻找的是黑盒测试。黑盒测试在不了解数据结构的情况下检查软件的功能。
3. 风险评估是识别潜在危害并分析这些危害实际发生时影响的过程。
4. 你的老板实际上在寻找一个蜜罐——一个故意设置了漏洞和配置错误的系统，使其对攻击者产生吸引力。蜜罐通常用于研究攻击者的方法和工具。
5. 开发人员正在进行代码审查——对源代码进行系统的检查，以发现并消除错误、拼写错误等。
6. 确定风险三个要素是威胁的可能性、漏洞的可发现性和资产的影响价值。你必须考虑威胁、影响和资产价值来计算风险。
7. 如果你在寻找一种帮助你分析网络流量的工具，你应该购买协议分析器。协议分析器是用于捕获和检查通信通道中的信号和数据的工具。几乎每种通信通道都有协议分析器。
8. 如果你想评估来自恶意内部人员的威胁，你最可能使用凭证测试。凭证测试在进行测试时使用一组有效的用户凭据。这允许测试人员以与用户相同的视角和权限检查应用程序。
9. 漏洞扫描器是列出的工具唯一能提供这三项信息的。端口扫描器可以告诉你端口 80 是否开启，但无法测试共享访问或脆弱的 PHP 版本。大多数漏洞扫描器（如 `Nessus`）都会执行基本的 TCP 端口扫描，还会扫描配置错误、不软件版本等。

10. B. 显示如“220 Microsoft FTP Service”等服务“横幅”（banners）的列表通常是通过获取横幅创建的。有很多专门用于获取横幅的工具，但你可以简单地使用 `Telnet` 客户端连接到服务来实现相同的功能。在大多数情况下，服务会返回一个包含该服务各种细节的 banner。

11. B. 测试中一定存在用户错误。当任何扫描工具报告一个实际上并不存在且真实不存在的“发现”时，这被称为 `false positive`（误报）。

12. B. 灰盒测试是白盒测试和黑盒测试的结合。测试人员对所检查的系统或应用程序有一定的了解，例如数据结构和算法，但并不像白盒测试那样完全了解该应用程序。

13. D. 应用程序的攻击面实际上是对攻击者可能渗透或破坏应用程序的所有不同位置的描述。这包括进入和离开应用程序的所有数据路径、应用程序使用的所有数据，以及保护和处理数据及数据路径的代码。

14. B. 如果你需要一个既能寻找漏洞又不会干扰网络流量的工具，最好的折中方案是某种类型的被动网络漏洞扫描器。“被动”扫描器等待数据传输给它——它不会自行执行任何扫描或探测，也不会与其观察到的流量进行交互。

15. D. 每当你发现一个漏洞并使用工具或技术利用该漏洞获取访问权限或操纵数据时，你就执行了漏洞利用。识别漏洞止于对发现的漏洞进行任何操作。使用 `SQL injection` 攻击获取系统的访问权限绝对符合漏洞利用。

## 应用程序安全控制

在本章中，你将：

应用程序安全控制和技术对于确保部署的应用程序尽可能安全至关重要。从安全编码技术开始，通过添加安全控制提供深度防御，从而建立应用程序的安全性。使用应用程序加固技术以及适当的配置和变更控制，提供了一种流程驱动的方法，以确保根据定义的风险状况持续安全性。

### 安全编码概念

应用程序安全始于安全且无漏洞的代码。遗憾的是，所有代码都有弱点和漏洞，因此以一种具有有效防御防止漏洞被利用的方式实例化代码，可以维持预期的安全水平。对配置、错误、异常和输入进行适当处理有助于创建安全应用程序。在整个系统生命周期内对应用程序进行测试可以确定系统的实际安全风险状况。

软件开发生命周期（`SDL`）中有许多单独元素可以帮助团队开发安全代码。正确的 `SDL` 流程，如输入验证、适当的错误和异常处理，以及跨站脚本和跨站请求伪造缓解，可以提高代码的安全性。安全测试、模糊测试（fuzzing）和补丁管理等流程元素也有助于确保应用程序符合预期风险状况。

常见的错误有两个主要的分类：由 `MITRE` 维护的 `Top 25` 列表以及针对 Web 应用程序的 `OWASP Top Ten` 列表。根据评估的应用程序类型，这些列表为已知错误类型的安全分析提供了一个坚实的起点。`MITRE` 是标准程序标准列表的库，`OWASP` 是 Web 应用程序的库。由于常见错误的产生变化并不快，这些列表并非每年更新。

### 错误与异常处理

每个应用程序都会遇到错误和异常，这些需要以安全的方式进行处理。一种攻击方法包括强制错误使应用程序从正常运行切换到异常处理。在发生异常期间，通常的做法是记录/报告该状态，包括支持性信息，例如导致错误的数据。这些信息对于诊断错误原因可能是无价的。挑战在于在哪里捕获这些信息。最好的方法将其捕获到日志文件中，并通过 ACL 进行安全保护。最糟糕的情况是回显给用户。当攻击者故意制造错误时，向用户回显错误状态细节可以提供价值信息。

**考试提示**：所有的错误/异常都应该在生成例程中捕获并处理。

不当的异常处理会导致各种泄露。与 `SQL` 语句相关的错误可能会暴露数据结构和数据元素。远程过程调用（`RPC`）错误可能会提供敏感信息，如文件名、路径和服务器名称。程序错误可能会提供发生异常的行号、被调用的方法以及堆栈元素等信息。

### 输入验证

随着 Web 应用程序的普及，错误已从缓冲区溢出转向输入处理问题。用户具有操纵输入的能力，因此开发者需要适当处理输入以防止恶意输入产生影响。缓冲区溢出可以被视为不当输入的一类，但新的攻击包括规范化攻击和算术攻击。可能采用的最重要的防御机制是输入验证。将所有输入在经过妥当验证之前视为敌性的，可以缓解许多基于常见漏洞的攻击。这是一个挑战，因为验证工作需要在所有解析器完成对输入流的操作之后进行，这在使用 Unicode 和其他国际字符集的 Web 应用程序中是一个常见功能。

输入验证特别适用于以下漏洞：缓冲区溢出、安全决策中依赖不可信输入、跨站脚本（`XSS`）、跨站请求伪造（`XSRF`）、路径遍历和缓冲区大小计算错误。输入验证似乎适用于各种注入攻击，但考虑到输入的复杂性以及合法但不当输入流带来的后果，这种方法对于大多数注入攻击都显得不从心。有效的方法是一种识别和白名单方法，即输入经过验证后解析为标准结构，然后执行。这把攻击面限制在不仅是合法输入，还包括预期的输入之内。

**考试提示** 认为所有输入都是敌对性的。输入验证是所采用的最安全编码技术之一，它可以缓解许多潜在的漏洞。

在许多情况下，输出验证与输入验证同样重要。如果查询数据库以匹配用户名和密码，则 `match` 函数预期的输出形式应该是有一个匹配项或一个匹配项都没有。如果使用记录数来指示匹配程度（这是一种常见做法），那么除 `0` 或 `1` 以外的值都应视为错误。使用输出验证进行防御性编码时，应对 `>1` 的值执行操作，因为这些值显然是错误，应被处理为失败。

### 模糊测试 (Fuzzing)

测试中可以使用的最强大的工具之一是 `fuzzing`（也称为模糊测试），它通过系统地应用一系列畸形输入来测试程序的如何响应的。多年来，黑客一直利用模糊测试寻找可能被利用的缓冲区溢出漏洞，而无需任何特定的编码知识。无论是白盒测试还是黑盒测试，模糊测试都能完美工作。模糊测试是发现意外输入验证错误的最佳实践。

测试人员可以使用模糊测试框架来自动生成大量的输入序列。在检查某个函数是否会受到缓冲区溢出的攻击时，测试人员可以运行大量输入，测试长度和最终的有效负载交付选项。如果特定的输入字符串导致了可以被利用的崩溃，测试人员将详细检查此输入。模糊测试在开发领域仍然相对较新，但正在迅速成熟，并将很快与其他自动化代码检查工具并驾竞争。

### 跨站脚本攻击防护 (Cross-site Scripting Prevention)

跨站脚本 (XSS) 是常见的网络攻击方法之一。该漏洞产生由于用户输入验证薄弱。如果输入没有经过适当验证，攻击者可以在输入中包含脚本并使其作为 Web 过程的一部分被渲染。有不同类型的 XSS 攻击，根据脚本的效果进行区分：

- **非持久性 XSS 攻击**：注入的脚本不会持久化或存储，而是立即执行并通过 Web 服务器传回。
- **持久性 XSS 攻击**：脚本被永久存储在 Web 服务器或某些后端存储中。这使得脚本可以用于攻击系统的其他用户。
- **基于 DOM 的 XSS 攻击**：脚本通过文档对象模型 (DOM) 过程在浏览器中执行，而不是通过 Web 服务器。

跨站脚本攻击可能导致广泛的后果，在某些情况下，列表可以是任何聪明的脚本编写者能设计的。在现实中看到的常见用途包括：

- 从 Web 应用程序中窃取身份信息
- 会话劫持
- 部署敌性内容
- 更改用户设置（包括未来的用户）
- 冒充用户

保护设置至关重要，保护这些设置的最常用机制包括访问控制列表和受保护目录。所需设置的文档是一份重要的安全文档，有助于管理员确保在更新后维持适当的配置。

### 跨站请求伪造 (Cross-site Request Forgery)

跨站请求伪造 (CSRF) 是一种漏洞，恶意站点欺骗用户在他们当前已验证的另一个应用程序上执行不希望的操作。之所以可能，是因为浏览器在向目标域发送每个请求时都会自动包含如会话 Cookie 等凭据。为了防止 CSRF，开发者通常使用反 CSRF 令牌，这是为每个会话或请求生成的唯一且不可预测的值。服务器在处理请求之前会验证令牌，以确保其源自合法应用程序。

### 应用程序加固 (Application Hardening)

应用程序加固的工作方式与系统加固（下文讨论）相同。第一步是移除不必要的组件或选项。第二步是系统的正确配置。每次更新或补丁都可能导致这些条件发生变化，应在每次更新后进行确认。

确保系统加固的主要工具是安全应用程序配置基准和补丁管理流程。当合理使用时，这些工具可以带来最安全的系统。

### 应用程序配置基准 (Application Configuration Baseline)

*基准* (baseline) 是计算机系统的一组适当设置。*应用程序配置基准*概述了一个或一组应用程序的适当设置和配置。这些设置包含了许多元素，从应用程序设置到安全设置。

### 应用程序补丁管理 (Application Patch Management)

应用程序补丁管理是应用程序和系统加固的基础组成部分。目标是运行最安全的应用程序版本，在极少数情况下，这应该是软件的当前版本（包括补丁）。大多数更新和补丁都包含修复安全问题和关闭漏洞。当前的补丁也是许多合规性方案的要求。

补丁并不总是按计划进行，某些补丁可能会导致生产系统出现问题。需要一个正式的补丁管理系统，以变更控制的方式测试并实施补丁。

### NoSQL 数据库与 SQL 数据库

当前的编程趋势包括如使用 SQL 数据库还是 NoSQL 数据库等话题。SQL 数据库是指使用结构化查询语言 (SQL) 来处理以表的形式关系地引用的项。NoSQL 指既不使用 SQL 也不使用关系表结构的数据存储。每个系统都有其优缺点，两者都可以用于广泛的数据存储需求。

SQL 数据库是目前最常见的数据库，其中 IBM、Microsoft 和 Oracle 的实现是主要的参与者。NoSQL 数据库倾向于使用低级语言进行自定义构建，并且缺乏现有数据库的许多标准。但这并没有阻止 NoSQL 数据库在大规模、资源充足的环境中的增长。

以安全方式访问数据的重要因素在于正确地使用编程结构和框架来抽象访问过程。诸如内联 SQL 生成结合输入验证错误的方法，是导致 SQL 注入攻击形式的灾难的祸源。

## 服务端验证 vs. 客户端验证

在现代的客户端-服务器环境中，可以在服务器端或客户端检查数据是否符合输入/输出要求。在将数据发送到服务器之前在客户端验证数据元素具有优势，即效率。在客户端上进行检查可以节省一次往返及其延迟，从而在用户发现问题之前对其发出警告。这可以提高软件界面的易用性。

客户端不是执行任何关键值检查或安全检查的合适位置。原因有两点：第一，客户端可以在检查后更改任何内容；其次，数据在传输过程中或在中间代理处可能会被篡改。对于所有出于业务原因或安全考虑而至关重要的检查，验证步骤应在服务端执行，因为那里的数据没有未经授权的更改。输入验证检查只能在服务端安全地执行。

## 移动设备安全

在本章中你将：

- 探索移动安全概念
- 学习移动技术
- 检查移动设备相关的风险
- 检查云环境相关的风险

移动设备在商务和个人使用方面已经发生了惊人的融合。云存储能力与软件即服务 (SaaS) 的融合正剧烈地改变移动设备的使用格局。移动设备的无处不在以及跨平台持续访问数据的需求，导致移动设备在个人和业务用途上的方式发生了巨大变化。过去，公司为员工提供移动设备主要用于业务用途，但也允许用于个人使用。随着设备的不断出现和技术的不断演进，许多公司允许员工自带设备（BYOD: bring your own device）同时用于个人和业务用途。

### 设备安全

在使用智能手机和平板电脑等移动设备时，必须遵循适用于笔记本电脑的安全原则。必须保护数据，必须正确配置设备，并鼓励良好的用户习惯。本章将回顾许多针对移动设备的特定主题。你可能会发现已经学过的安全原则仍然适用，只需要适应移动技术。这是计算机安全领域变化最快的领域之一，因为移动技术很可能是变化最快的。

### 全盘加密

正如笔记本电脑应该通过加密以防丢失一样，移动设备需要加密来保护敏感信息。这是一项新兴技术，许多公司需要它来保护移动设备。

### 远程擦除

一些高级的安全形式与擦除配合工作。如果错误输入密码达到指定次数，设备将自动擦除。这是 BlackBerry 的安全功能之一，传统上使其受到了对安全敏感的用户关注。Apple 在较新的设备上也提供了此选项。Apple 还允许从用户的 iCloud 账户远程锁定设备。

### 锁定限制

有多种产品可以帮助管理设备。远程锁定通常是保护设备安全的第一步。

### 屏幕锁

大多数公司政策都要求屏幕锁。这通常包括输入密码或 PIN 码。然而，用户倾向于使用方便或容易的密码。某些设备允许复杂的密码。如图 18-1 所示，左侧的设备屏幕仅支持四位数字简单密码，而右侧的设备屏幕支持长度任意的密码并可以包含字母和数字。

在移动设备上，将个人数据与公司数据隔离开是非常困难的。一些公司开发了创建独立虚拟容器的能力，以将个人数据与公司数据及应用程序隔离开。对于处理高度敏感公司数据的设备，强烈建议采用这种形式的保护。

## 资产控制

由于每个用户都可能有多个设备连接到公司网络，因此实施可行的资产追踪和库存控制机制至关重要。出于安全和责任考虑，公司需要知道哪些设备连接到了其系统，以及授予了哪些访问权限。正如 IT 系统一样，维护一份已批准设备列表是一项关键的控制措施。

## 移动设备管理

`Mobile device management (MDM)` 是今天设备安全领域最热门的话题之一。`MDM` 最初作为一个营销术语，指一组与移动设备相关的、常用的保护元素的合集。当将其视为移动设备的整套安全选项方案时，每家公司都应该拥有并执行 `MDM` 策略。该策略应要求：

- 使用强密码锁定设备
- 对设备上的数据进行加密
- 在一段时间未活动后自动锁定设备
- 在设备丢失或被盗时具有远程锁定设备的能力
- 在多次尝试登录失败后具有自动擦除设备的能力
- 在设备丢失或被盗时具有远程擦除设备的能力

密码策略应扩展到移动设备，包括锁定以及在可能的情况下自动擦除数据。公司对于移动设备数据加密的策略应与笔记本电脑加密策略保持一致。换句话说，如果你不需要便携式电脑进行加密，那么你是否应该对移动设备要求加密？这个问题没有统一的答案；在实践中，移动设备比笔记本电脑要移动得多，且更容易丢失。这根结底是一个管理层必须解决风险问题：采用的方案风险是什么，成本是多少？这还提出了一个更大的问题：哪些设备应该将加密作为基础安全保护机制？是根据设备类型，还是根据哪些数据暴露于风险的用户？幸运的是，现在存在 `MDM` 解决方案，使得这些选择变得可控。

## 设备访问控制

密码策略应扩展到移动设备，包括锁定以及在可能的情况下自动擦除数据。公司对于移动设备数据加密的策略，应与笔记本电脑的数据加密策略保持一致。换句话说，如果你不需要便携式电脑进行加密，那么你是否应该对移动设备要求加密？这个问题没有统一的答案；在实践中，移动设备比笔记本电脑要移动得多，且更容易丢失。这根结底是一个管理层必须解决风险问题：采用的方案风险是什么，成本是多少？这还提出了一个更大的问题：哪些设备应该将加密作为基础安全保护机制？是根据设备类型，还是根据哪些数据暴露于风险的用户？幸运的是，现在存在 `MDM` 解决方案，使得这些选择变得可控。

## 密钥和凭证管理

`MDM` 市场正在迅速成熟。密钥和凭证管理服务正在集成到大多数 `MDM` 服务中，以确保现有的强策略和程序可以安全地扩展到移动平台。这些服务包括数字签名密钥以及 `S/MIME` 加密解密。密钥和凭证是移动设备上可以找到的价值最高物品，因此对其进行保护是移动设备安全的关键。存储在设备上的密钥和凭证可以使用多个应用程序。在保持可用性的同时为这些密钥提供保护是现代应用程序安全的要素。

## 身份验证

当使用移动设备访问业务网络时，身份验证就会变成一个问题。存在几个层面：设备是否允许访问网络？设备的用户是网络用户吗？如果是，如何验证用户？移动设备具有某些优势，因为它们可以存储证书，本质上比密码更安全。这把身份验证问题转移到了终端，依赖于密码、屏幕锁定和其他移动设备保护。除非结合使用（包括在有限次数失败后擦除），否则这些可能是薄弱的。移动认证的风险在于存储在设备中的强凭证受不受严格密码的保护。用户可以共享他们的移动设备，并无意中共享他们的强身份代码。

### 地理标记

在移动设备上或具有 `GPS` 功能的相机拍摄的照片可以在数字照片中嵌入位置信息。这被称为“地理标记”。发布嵌入地理标记的照片有其用途，但也可能无意中发布用户不想共享的信息。例如，如果你用智能手机拍摄了车库里的汽车照片并将其发布到互联网上尝试出售，如果智能手机开启了地理标记，拍摄位置的位置将作为元数据嵌入数字照片中。这种发布可能会无意中暴露你家的位置。关于这一主题已有许多公开讨论，大多数移动设备都可以禁用地理标记。

### 应用白名单

正如本章早期“应用控制”部分所讨论的，控制设备可以访问的应用程序可能是公司移动设备策略的重要元素。应用白名单和黑名单允许您控制并阻止移动设备上可用的应用程序。这通常通过某种类型的 MDM（移动设备管理）功能进行管理。应用白名单可以通过防止未经批准的应用程序在设备上安装和运行来提高安全性。

### 加密

正如设备应该被加密以保护设备上的所有信息一样，应用程序也应该被加密。仅对数据存储进行加密是不够的。如果设备经过全加密，那么所有应用都将能够访问数据，从本质上从应用程序的角度来看绕过了加密。带有敏感信息的应用程序应通过自身的一套保护措施来控制访问。在设备内隔离数据的唯一方法是应用程序通过特定的加密来管理自己的数据存储。这将允许敏感数据免受恶意应用程序的侵害，如果允许统一访问，这些程序可能会泄露数据。

### 传递信任/认证

跨多个域/平台的安全通过信任关系提供。当域或平台之间存在信任关系时，每个域的身份验证信任所有其他受信任域的身份验证。因此，当一个应用程序通过身份验证时，其身份验证会被所有信任该认证域或平台的其他域/平台接受。移动设备中的信任关系可能非常复杂，而且安全方面往往没有得到妥善实施。移动设备倾向于用于许多系统，包括业务、个人、公共和私有系统。这极大地扩大了风险配置以及基于传递信任的攻击机会。与其他所有应用程序一样，应该对移动应用程序进行仔细审查，以确保信任关系是安全的。

### BYOD（自带设备办公）考虑

BYOD 在业务中有很多优势，而不仅仅是从设备成本的角度来看。用户倾向于拥有一台设备而不是携带多个设备。用户在他们已经感兴趣学习的设备上，学习曲线更短。

### 数据所有权

BYOD 模糊了数据所有权的界限，因为它模糊了设备管理的界限。如果公司拥有分发给员工的智能手机，公司可以在员工离职时收回该手机。这种做法通过让公司配发的设备仅留在员工手中来保护公司数据。然而，公司在重新发放设备之前不能依赖于简单的出厂重置，因为出厂重置可能无法删除设备上的所有数据。如果设备被重新发放，之前所有者的某些个人信息（如私人联系人）可能仍然留在设备上。另一方面，如果员工的设备是用于业务目的的个人设备，在员工离职时，尽管公司尽力删除设备上的数据，手机上可能仍留有一些公司数据。如果该设备被转售或回收，公司数据可能会留在设备上并传递给后续所有者。将业务数据保留在单独的 MDM 管理容器中是解决这一问题的方法之一。

### 支持所有权

移动设备的支持成本是企业的一个重要考虑因素。每台设备都有其各种功能的实现。虽然这些功能通常是根据规范实现的，但软件实现可能没有完全或正确地实现该规范。这可能导致向您的帮助热线或支持组织的支持电话增加。对于企业帮助热线来说，要熟悉访问公司网络的所有可能设备的各个方面是非常困难的。例如，您的支持组织必须能够对 iPhone、Android 设备、平板电脑等进行故障排除。这些设备更新频繁，新设备不断发布，新功能也定期添加。您的支持组织将需要可靠的知识库文章和工作辅助，以便为各种不断变化的设备提供足够的支持。

### 补丁管理

正如您的公司政策应强制及时更新桌面电脑和笔记本电脑以帮助消除这些平台上的安全漏洞一样，它也应该要求移动设备保持补丁更新。拥有最新的应用程序、操作系统等是防御病毒、恶意软件和其他威胁的重要最佳防御。

员工离职流程需要修改，以包含移动设备账户的注销。在员工离职几个月后，仍发现其账户甚至公司设备仍连接到公司网络，这种情况并不罕见。作为员工离职政策和流程的一部分，应及时删除电子邮件账户。离职时应收回公司提供的移动设备。作为离职流程的一部分，应终止 `BYOD` 设备对公司资源的访问权限。应对旧账户或未注销的账户进行定期审计，以确保离职员工的账户被及时删除。

### 遵循公司政策

您关于 `BYOD` 设备的公司政策应与现有的计算机安全策略保持一致。您的培训计划应包含有关移动设备安全的指导。纪律处分应保持一致。应该加强您的监控程序，以包含对移动设备的监控和控制。

### 用户接受

`BYOD` 本质上产生了个人利益与公司利益之间的冲突。使用自己的设备进行公司业务的员工，本质上对该设备有强烈的所有感，并可能对公司控制下载到设备上的公司信息感到反感。另一方面，公司期望公司数据得到适当的控制和保护，因此希望实施远程擦除或锁定要求以保护公司数据。如果某个人丢失了特殊活动中的个人照片，而公司擦除了她的设备（包括那些无法替代的照片），她可能会对公司产生不满情绪。您的公司 `BYOD` 政策需要明确定义，经过公司法务部门批准，并通过培训清晰地告知所有员工。

### 架构/基础设施考虑

移动设备消耗到公司 IT 基础设施的连接。现在，一个人通过一个或多个智能手机、平板电脑以及笔记本电脑或桌面电脑连接到公司基础设施的情况已不罕见。过去的一些基础设施实现在设计上并不高效，有时一个设备会占用多个连接。这会减少其他终端用户的可用连接数。建议进行负载测试，以确保您的设计或现有基础设施能够支持来自多个设备可能的大量连接。

当系统根据多个连接跟踪用户账户时，多个连接也可能产生安全问题。用户需要意识到这一点，以免无意中制造了应急响应情况，或发现自己由于自己的操作而被锁定。这是一个棘手的问题，需要比传统的“`userid` 等于一个当前连接”的理念更具智能性的设计。

### 法律问题

从本章讨论的各种主题可以明显看出，用于公司业务的移动设备带来了许多安全挑战。由于技术变化非常快，最好确保您对政策进行了稳妥的法律审查。涉及移动设备时既有法律问题，也有公关问题。使用公司所有和个人设备的员工在涉及公司数据时承担相应责任。应定期审查政策和程序以跟上技术发展。

### 可接受使用策略

与您对笔记本电脑和桌面电脑的可接受使用策略类似，您的移动设备策略应解决移动或 `BYOD` 设备的可接受使用问题。应解决授权公司设备用于个人目的的问题。应对违反移动设备政策的纪律处分。`BYOD` 为公司和用户都带来了优势；应具体说明其影响以及具体的用户责任。

## 基于主机的安全

在本章中，你将：

- 发现建立主机安全的适当解决方案
- 理解如何实施适当的控制以确保数据安全
- 检查基于主机的安全控制和应用程序
- 学习如何在多个环境中确保数据安全

### 主机安全

基于主机的安全采取细粒度的安全视角，重点保护每台计算机和设备，而不是整个网络。当使用基于主机的安全时，依靠每台计算机保护自己。

大多数环境充满了不同的操作系统（Windows、Linux、OS X）、这些操作系统的不同版本以及不同类型的安装应用程序。此外，今天移动设备操作系统的主机安全是一个重要的安全问题，这使得操作系统列表扩展到了 iOS、Android 和 BlackBerry。每个操作系统的安全配置都不同，相同操作系统的不同版本之间实际上也存在差异。

主机安全很重要，并且应该始终被关注。然而，安全不应止于此，因为主机安全是与网络安全相结合的互补过程。如果单个主机计算机内部存在漏洞，那么网络安全可以提供另一层保护，希望阻止那些已经进入环境内部的入侵者。

早期版本的家庭操作系统没有为不同用户提供独立的命名账户。这被视为一种便利性机制；毕竟，谁想去受登录机器的麻烦呢？这导致了一个简单的问题：所有用户都可以查看、修改和删除其他人的内容。虽然可以使用访问控制机制来隔离内容，但这需要对操作系统进行配置以管理每个用户的身份。许多操作系统的早期版本几乎所有选项都处于开启状态。同样，这也是出于方便性考虑，但它导致系统运行了它们从未用过的进程和服务，并不必要地增加了主机的攻击面。

确定正确的设置并正确实施它们是加固主机系统的重要步骤。本章将探讨为了在主机系统上实现合理的安全水平，需要恰当使用的多种控制和选项。

## 操作系统加固 (OS Hardening)

操作系统开发者和制造商都面临着一个共同的问题：他们无法预判用户社区对产品提出的各种不同配置和变体。因此，制造商并没有花费无数的时间和资金尝试满足每种需求，而是为其产品提供“默认”安装，这通常包含基础操作系统以及一些常用的常用选项，如驱动程序、实用程序和增强功能。由于操作系统可以用于各种用途，并可以放置在任何数量的逻辑位置（局域、DMZ、WAN 等），制造商在安全方面通常无所作为。制造商可能会提供一些建议或简化的工具和设置来帮助保护系统，但通常情况下，终端用户负责自己系统的安全。这通常涉及删除不必要的应用程序和实用程序、禁用不需要的服务、对文件设置适当权限，并将操作系统和应用程序代码更新到最新版本。

这种保护操作系统的过程被称为 `hardening`（加固），目的是使系统更具抵抗力，就像装甲或钢材经过硬化变得不易破碎或损坏一样。每个操作系统都有自己的安全方法，虽然加固过程通常是相同的，但针对每个操作系统必须采取不同的步骤。为生产环境准备和加固操作系统并非易事；它需要准备和规划。遗憾的是，许多用户并不理解有效保护系统的必要步骤，导致每天都有数百个系统被破解。

![image](img/examtip.jpg)

**考试提示** 系统加固是准备和保护系统的过程，涉及移除所有不必要的软件和服务。

你必须满足几个关键要求，以确保本节描述的系统加固过程达到其安全目标。这些要求独立于操作系统，并且应该是所有系统维护操作的正常部分：

- 所有操作系统和应用程序软件的基础安装均来自可信源，并使用哈希值验证正确性。
- 在安装、加固和更新过程中，机器仅连接到完全可信的网络。
- 基础安装包含操作系统和应用程序的所有当前服务包和更新。
- 在加固和更新后拍摄备份镜像，以便系统恢复到已知状态。

这些步骤确保你了解机器上有什么内容，可以验证其真实性，并拥有一个已建立备份版本。

## 反恶意软件 (Anti-malware)

在 PC 使用的早期，威胁是有限的：大多数家庭用户并非通过宽带连接连接到互联网，最常见的威胁是通过感染的软盘在计算机之间传播的病毒（就像医学定义一样，计算机病毒是可以感染主机并自我复制的东西）。但自那些早期以来，情况发生了巨大变化，现在的威胁带来的风险比以往任何时候都大。根据 SANS 网络风暴中心，互联网上未打补丁的 Windows PC 的平均生存时间小于 60 分钟（`http://isc.sans.org/survivaltime.html`）。这是自动探测发现、渗透并破解系统之前的估计时间。来自僵尸网络和蠕虫的自动探测并不是网络上唯一的威胁——还有通过电子邮件传播的病毒和恶意软件、钓鱼网站、访问时会在你的系统中执行代码的受感染网站、广告软件、间谍软件等。幸运的是，随着威胁复杂性和能力的增加，旨在阻止它们的产品也在不断增强。

### 杀毒软件 (Antivirus)

杀毒软件尝试识别、中和或移除恶意程序、宏和文件。这些产品最初旨在检测和删除计算机病毒，但许多杀毒软件现在都包含了额外的安全产品和功能。

尽管杀毒软件已经有了近二十年的时间来完善其能力，但杀毒软件的目的未变：检测并消除计算机病毒和恶意软件。大多数杀毒软件在扫描病毒时结合了以下方法：

- **基于特征的扫描 (Signature-based scanning)**：类似于入侵检测系统 (`IDS`)，杀毒软件扫描程序、文件、宏、电子邮件和其他数据，以寻找已知的蠕虫、病毒和恶意软件。杀毒软件包含数千个已知病毒特征的病毒字典，由于每天都会发现新病毒，必须频繁更新。这种方法可以捕获已知病毒，但受限于病毒字典——它不知道的内容就无法捕获。
- **启发式扫描（或分析) (Heuristic scanning)**：启发式扫描不依赖病毒字典。相反，它寻找可疑行为——任何不符合受保护系统上运行的操作系统和应用程序“正常”行为模式的行为。

由于基于特征的扫描是一个熟悉的概念，让我们详细检查一下启发式扫描。`Heuristic scanning`（启发式扫描）通常寻找应用程序中通常不会发现的命令或指令，例如访问保留内存寄存器的尝试。大多数杀毒软件在它们的启发式扫描中使用基于权重的系统或基于规则的系统（更有效的产品结合了这两种技术）。`weight-based system`（基于权重系统）根据行为相关的威胁程度对每个可疑行为进行评分。如果根据单一行为或组合行为超过了设定阈值，杀毒软件会将执行该行为的进程、应用程序、宏等视为系统威胁。`rule-based system`（基于规则系统）将活动与用于检测和识别恶意软件的规则集进行比较。如果软件的部分匹配规则，或者进程、应用程序、宏等执行了与规则匹配的行为，杀毒软件将将其视为对本地系统的威胁。

某些启发式产品非常先进，包含了检查内存使用和地址的能力、检查可执行代码的解析器、逻辑流分析器以及反汇编器/模拟器，以便它们可以“猜测”代码的设计目的以及是否具有恶意。

与 IDS/IPS 产品一样，加密和混淆也给杀毒软件构成了挑战：任何无法读取的内容都无法与当前的病毒字典或活动模式进行匹配。为了对抗恶意软件和病毒中的加密技术，许多启发式扫描器会寻找加密和解密循环。由于恶意软件通常被设计为独立且无人看管地运行，如果它使用了加密，则必须包含所有按需加密和解密自身的指令。启发式扫描器会寻找此类指令，例如使用有效内存地址初始化指针、操作计数器，或基于计数器值的分支条件。虽然这些操作并不总是意味着加密/解密循环的存在，但如果启发式引擎能够找到循环，它可能能够在受保护的内存空间（如模拟器）中解密软件，并对软件进行更详细的评估。许多病毒共享加密/解密程序，这有助于杀毒软件开发人员。

目前的杀毒产品具有高度的可配置性，大多数产品都具备以下功能：

- **自动更新**：一个良好的杀毒解决方案最重要的功能可能是其能够通过频繁自动下载最新的病毒特征来保持自身更新。这通常要求系统以某种方式连接互联网，并每天（或更频繁地）执行更新。
- **自动扫描**：大多数杀毒产品允许调度自动扫描，以便你可以指定杀毒产品检查本地系统受感染文件的时间。这些自动扫描通常可以安排在特定的日期和时间，并可以配置扫描参数以指定扫描哪些驱动器、目录和文件类型。
- **媒体扫描**：可移动介质仍然是病毒和恶意软件传播的常见方法，大多数杀毒产品可以配置为在本地系统连接或访问光介质、USB 驱动器、内存或其他任何类型的可移动介质时立即进行自动扫描。
- **手动扫描**：许多杀毒产品允许用户“按需要”扫描驱动器、文件或目录（文件夹）。
- **邮件扫描**：电子邮件仍然是病毒和恶意软件传播的主要方法。许多杀毒产品赋予用户扫描收件箱邮件以及任何附件的能力。
- **处理**：当杀毒产品检测到受感染的文件或应用程序时，它通常可以执行几种操作之一。杀毒产品可能会将文件隔离，使其无法访问；它可能会尝试通过移除感染或违规代码来修复文件；或者可能会删除受感染的文件。大多数杀毒产品允许用户指定所需的操作，某些产品允许操作升级，例如在可能的情况下清理受感染的文件，如果无法清理则隔离文件。

杀毒解决方案通常安装在单个系统（桌面电脑、服务器甚至移动设备）上，但许多商业网关产品也提供了基于网络的杀毒功能。这些网关产品通常将防火墙、IDS/IPS 和杀毒功能集成到单一的平台中。大多数组织还在电子邮件服务器上采用杀毒解决方案，因为这仍然是病毒非常流行的传播方法。

尽管安装良好的杀毒软件仍被认为是一种必要的最佳实践，但人们对杀毒软件应对不断发展的威胁的有效性日益担忧。早期的病毒通常表现出破坏性行为；编写质量较差；经过修改的文件；而且对隐藏行迹的关注不如传播。我们正看到由专业人士创建的病毒和恶意软件（有时由犯罪组织或政府资助），它们竭尽全力隐藏行迹。这些病毒和恶意软件通常用于窃取敏感信息，或将受感染的 PC 变成僵尸网络的一部分，用于垃圾邮件或攻击操作。

### 反垃圾邮件

`spam`（垃圾邮件）是各地用户和系统管理员的噩梦，它本质上是未经请求或不受欢迎的批量电子信息。虽然通常应用于电子邮件，但可以通过短信发送到手机和移动设备、作为互联网论坛帖子或其他方式传输。如果你用过电子邮件账户，很可能你收到过垃圾邮件。

从生产力和安全角度来看，垃圾邮件每年给企业和用户造成数十亿美元的损失，这是一个如此普遍的问题，以至于美国国会通过了 2003 年的《CAN-SPAM 法》，授权联邦贸易委员会执行该法案，并授权司法部对垃圾邮件发送者实施刑事制裁。该法案对发送商业电子邮件的人制定了要求，规定了违反法律的垃圾邮件发送者以及在垃圾邮件中投放广告公司的处罚，并赋予消费者要求邮件发送者停止发送垃圾邮件的权利。然而，尽管我们付出了巨大努力，垃圾邮件仍然源不断；随着阻止垃圾邮件的技术和手段变得越来越先进复杂，发送这些未经请求信息的工具和技术也随之增加。

以下是一些用于对抗垃圾邮件泛滥的流行方法；其中大多数技术用于过滤电子邮件，但也可以应用于其他介质：

- **黑名单**：黑名单本质上是记录哪些域名和源地址有发送垃圾邮件的声誉，并拒绝来自这些域名和源地址的消息。这基本上是一种永久的“忽略”或“来电”类型的功能。几个组织和一些商业公司提供了已知垃圾邮件发送者列表。
- **内容或关键词过滤**：与互联网内容过滤类似，这种方法过滤电子邮件消息中的不受欢迎内容或垃圾邮件迹象。类似于对网页内容的内容过滤，基于关键词等内容过滤电子邮件可能会导致意想不到的结果，因为某些术语可能同时出现在合法邮件和垃圾邮件中。大多数内容过滤技术使用正则表达式匹配进行关键词过滤。
- **可信服务器**：黑名单的相反，可信服务器列表包含了被“信任”为不会转发垃圾邮件的 `SMTP` 服务器。
- **基于延迟的过滤**：某些简单邮件传输协议（`SMTP`）服务器被配置在建立连接和发送 `SMTP` 服务器欢迎语之间插入故意延迟。某些生成垃圾邮件的程序不会等待该欢迎语，任何在连接打开后立即开始发送数据的系统会被视为垃圾邮件生成器并被 `SMTP` 服务器丢弃。
- **PTR 和反向 DNS 检查**：某些电子邮件过滤器检查邮件发送者的源域名。如果反向检查显示邮件来自拨号用户、家庭宽带或动态分配的地址，或者具有通用域名或缺失域名，那么过滤器将拒绝它，因为这些是垃圾邮件消息的常见来源。
- **回调验证**：由于许多垃圾邮件使用伪造的“发件人”地址，某些过滤器尝试验证入站邮件的“发件人”地址。接收服务器可以联系发送服务器以尝试验证发送地址，但这并不总是有效的，因为伪造的地址有时是经过验证的有效电子邮件地址。
- **统计过滤**：统计过滤非常类似于文档分类系统。用户将收到的消息标记为垃圾邮件或合法邮件，过滤系统会从用户的输入中学习。看到并分类为垃圾邮件的消息越多，过滤软件拦截入站垃圾邮件的能力就越强。垃圾邮件发送者通过在消息中插入随机单词和字符来反制许多过滤技术，使得内容过滤器难以识别垃圾邮件的共同模式。
- **基于规则的过滤**：基于规则的过滤是一种简单的技术，仅查找某些字段或关键词的匹配。例如，基于规则的过滤系统可能会查找主题中包含“发财”字样的任何消息。许多流行的电子邮件客户端都具有实现基于规则过滤的功能。
- **出站过滤**：一些组织会对离开其组织的电子邮件执行垃圾邮件过滤，这被称为出站过滤。可以使用相同类型的反垃圾邮件技术来验证和过滤出站邮件，以对抗垃圾邮件。
- **混合过滤**：大多数商业反垃圾邮件方法使用混合过滤，或使用几种不同技术的组合来对抗垃圾邮件。例如，过滤解决方案可能会将每条入站消息与已知的垃圾邮件发送者进行匹配，然后与基于规则的过滤器匹配，接着是内容过滤器，最后与基于统计的过滤器匹配。如果消息通过了所有过滤阶段，它将被视为合法消息；否则，将作为垃圾邮件被拒绝。

许多垃圾邮件过滤是在网络或 SMTP 服务器级别完成的。使用集中解决方案扫描所有入站和出站消息，比在整个组织的终端用户机器上部署单独的解决方案要有效得多。电子邮件默认本质上是一种代理服务：消息通常进入并离开组织的邮件服务器。（用户通常不会连接到远程 SMTP 服务器来发送和接收消息，但他们可以这样做。）反垃圾邮件解决方案以软件形式存在，加载在 SMTP 服务器本身上，或者加载在次要服务器上，在消息到达 SMTP 服务器之前或消息被 SMTP 服务器处理之后对其进行处理。反垃圾邮件解决方案还以设备的形式存在，软件和硬件是一个单一集成的解决方案。许多集中的反垃圾邮件方法允许个人用户为其特定的收件箱自定义垃圾邮件过滤，指定他们自己的过滤规则和评估入站邮件的标准。

### 反间谍软件

大多数杀毒产品还将包含反间谍软件功能。虽然杀毒程序的设计目的是监控向文件系统写入文件，但许多当前形式的恶意软件会避开文件系统以避免这种形式的检测。较新的杀毒产品正在适应并扫描内存，同时监控文件系统的访问，试图检测高级恶意软件。`Spyware` 是用于定义旨在从系统中窃取信息的恶意软件的术语，例如击键、密码、PIN 和密钥。反间谍软件帮助你的系统免受日益增加的恶意软件泛滥，这些恶意软件试图监控你的击键、窃取你的密码并将敏感信息报告给攻击者。许多此类攻击向量在系统内存中运行，以避免被轻易检测。

### 弹出窗口拦截器

网页浏览相关的最令人恼的困扰之一是弹出广告。弹出广告是为了吸引网络流量访问特定网站、捕获电子邮件地址投放产品以及执行其他任务设计的在线广告。如果你在互联网上冲浪超过了一个小时，你无疑见过它们。当你正在访问的网站为了显示广告而打开新的网页浏览器窗口时，弹出广告就创建了。弹出广告通常出现在你当前浏览器窗口的前面，吸引你的注意力（并干扰你的浏览）。弹出广告的程度从轻微烦恼（产生一或两个弹出窗口）到导致系统瘫痪（如果恶意网站尝试在你的系统上打开成千上万个弹出窗口）不等。

与弹出广告类似的是弹出后广告，它会在你当前的浏览器窗口后面打开。在关掉当前窗口之前，你看不到这些广告，某些人认为它们比弹出窗口不那么烦。另一种弹出窗口形式是悬停广告，它使用动态 HTML 显示为覆盖在你的浏览器窗口之上的浮动窗口。对于某些用户来说，弹出广告像垃圾邮件一样不受欢迎，许多网络浏览器现在允许用户使用内置在网络浏览器中或作为插件提供的功能来限制或阻止弹出窗口。Internet Explorer 包含一个内置的弹出拦截器（如图 19-1 所示，并在 Internet Explorer 11 的“工具”菜单中可用）。

弹出广告可以通过多种方式生成，包括 JavaScript 和 Adobe Flash，一个有效的弹出拦截器必须能够处理用于创建弹出窗口的许多方法。当创建弹出窗口时，用户通常可以点击弹出窗口内部的关闭或取消按钮，或者通过操作系统提供的可用方法关闭新窗口（例如从任务栏关闭窗口）。由于他们在 Web 开发环境中使用可以使用的高级功能，一些不道德的开发者对他们弹出窗口中的关闭或取消按钮编写程序，以启动新的弹出窗口、重定向用户、在本地系统上运行命令，甚至加载软件。

弹出窗口不应与广告软件混淆。弹出窗口是你访问页面时出现的广告。广告软件是广告支持的软件。在安装广告软件后，广告软件会自动在你的计算机上下载并显示广告，这些广告通常在使用软件期间显示。广告软件通常被吹称为“免费”软件，因为用户不需要为软件付费，但在使用软件之前必须同意允许下载并显示广告。这种方法在智能手机和移动设备上非常流行。

### 补丁管理

大多数计算机程序都是由几十甚至数千个独立个人编写的相互关联软件模块的大型复杂组合。随着过去几年向基于 GUI 的功能和增强能力的推动，操作系统持续增长和扩展。供应商通常遵循软件更新的层级结构：

- **热补丁 (Hotfix)**：此术语指的是（通常是）小的软件更新，旨在解决特定问题，例如应用程序中的缓冲区溢出，这会导致系统暴露在攻击之下。热补丁通常是针对发现的问题开发的，并迅速制作和发布。热补丁通常处理关键的安全相关问题，应尽快应用于受影响的应用程序或操作系统。
- **补丁 (Patch)**：该术语通常指的是更正式、规模更大的软件更新，它可能解决多个或许多软件问题。补丁通常包含功能增强或额外能力，以及对已知漏洞的修复。补丁的开发周期通常较长。
- **服务包 (Service pack)**：该术语通常指的是将大量的补丁和热修复（hotfixes）整合成一个单一的、规模较大的包。服务包的设计旨在让系统一次性提升到已知的良好水平，而不是要求用户或系统管理员单独下载几十个或上百个更新。

**考试提示** 所有的软件随着时间的推移都需要更改/补丁。管理补丁是安全计划中不可或缺的环节。

## 操作系统补丁

Windows 7 包含约 4000 万行代码，尽管它可能不是最大的一个，但其他现代操作系统也处于同一数量级。随着操作系统的不断增长和新功能的引入，代码出现问题的可能性也随之增加。操作系统厂商几乎不可能在每个可能的平台、每种可能的情况下测试其产品，因此在操作系统发布后确实会出现功能和安全问题。对于普通用户或系统管理员来说，这意味着会有持续不断的更新流，旨在纠正问题、替换代码段，甚至为已安装的操作系统添加新功能。

从 Linux 到 Windows，每个操作系统都需要软件更新，而且每个操作系统都有不同的方法来帮助用户保持系统处于最新状态。例如，微软通常会在其网站上提供供下载的更新。虽然大多数管理员或技术精通的用户可能倾向于单独识别并下载更新，但微软意识到非技术用户更倾向于更简单的方法，而微软已将这种方法内置到其操作系统中。在 Windows 7、8 和 Windows Server 2012 中，微软提供了自动化更新功能，一旦配置完成，它将定位任何所需的更新，将其下载到你的系统，并根据你的喜好甚至可以安装这些更新。在 Microsoft Windows 中，`Windows Update` 工具（参见图 19-2）可以按需搜索更新，或配置为自动扫描、下载甚至自动安装更新——本质上与具有新界面的自动更新功能相同。`Windows Update` 的一个非常好的特性是能够扫描并下载其他微软软件（如 Office）的补丁，以及操作系统自身的更新和补丁。

无论你使用哪种方法更新操作系统，保持系统处于最新状态至关重要。新的安全公告每天都会发布，虽然缓冲区溢出今天可能是一个“潜在”问题，但它在不久的将来几乎会变成一个“确定”的问题。就像建立操作系统基准和初始安全保护的步骤一样，保持每个系统都打上补丁并保持最新状态对于保护系统及其包含的信息至关重要。

## 应用更新

正如操作系统需要补丁一样，应用程序也需要。管理各种应用程序以及来自许多不同软件供应商的所需更新可能是一项巨大的挑战。这为补丁管理软件创造了一个利基市场。在大多数企业中，使用了某种形式的自动化补丁管理解决方案，既为了减少劳动，也为了确保在整个企业范围内应用更新。

## 应用白名单与黑名单

可以在操作系统层面控制应用程序，这通过白名单（Whitelisting）或黑名单（Blacklisting）来实现。`黑名单` 本质上是记录哪些应用程序不应运行。白名单则相反：它由允许运行的应用程序列表组成。这两种方法都有优缺点。黑名单在应对动态威胁时很难使用，因为可以轻松避免特定的应用程序。白名单则更容易实施——可以使用哈希值确保可执行文件未被篡改。其挑战在于，对于单一用途的机器（例如数据库服务器），白名单相对容易实施；对于多功能机器，则可能更为复杂。

微软提供了两种内置机制来控制用户可以使用哪些应用程序：

- **软件限制策略**：通过组策略实施，允许脚本和可执行文件进行大量控制。主要模式是基于机器而非用户账户。
- **用户帐户级控制**：通过 `AppLocker` 实施，允许控制哪些用户执行哪些程序。通过规则，企业可以对访问和使用软件施加大量控制。

在 Linux 平台上，第三方供应商应用程序也提供了类似的功能。

## 可信操作系统 (Trusted OS)

`可信操作系统`是一种设计用于运行时允许多级安全的操作系统。它通过满足美国政府要求的一系列标准进一步定义。创建和维护可信系统的成本很高，因为任何更改通常都需要经过重新认证。定义可信操作系统最常用的标准是信息技术安全通用标准（简称为共同标准或 `CC`），这是由美国、加拿大、英国以及大多数欧盟国家在内的许多国家认可的统一安全标准。Windows、Linux、大型操作系统和特殊操作系统的版本已通过不同标准的认证。

## 主机防火墙

个人防火墙是基于主机的保护机制，监控并控制进出单个系统的流量。为终端用户设计的软件防火墙通常具有可配置的安全策略，允许用户确定哪些流量是“良好的”并允许通过，哪些流量是“坏的”并被拦截。软件防火墙非常常见——大多数现代操作系统都自带了某种个人防火墙。

从 Windows XP 专业版开始，微软在所有现代 Windows 操作系统中包含了基于主机的防火墙解决方案。`Windows Firewall` 具有良好的配置性；它可以设置为阻塞所有流量、为允许通过的流量设置例外，并记录被拒绝的流量以供以后分析。在每个系统中，微软都扩展了防火墙的功能和可配置性。

## 主机入侵检测

第一代入侵检测系统是基于主机的，旨在检查特定主机的活动。基于主机的入侵检测系统（HIDS）检查日志文件、审计日志以及进入或离开特定主机的网络流量。HIDS 可以以实时模式运行，监控正在发生的活动，也可以以批处理模式运行，定期检查活动。基于主机的系统通常是独立的，但许多新的商业产品被设计为向中央系统报告并由其管理。基于主机的系统在运行时还需要本地系统资源。也就是说，HIDS 会消耗其受保护系统的部分内存和 CPU 周期。早期的 HIDS 以批处理模式运行，每小时或每天检查一次异常活动，通常只查看系统日志中的特定事件。随着处理器速度的提高，后版本的 HIDS 能够实时查看日志文件，甚至增加了检查主机正在生成和接收的数据流量的能力。

大多数 HIDS 关注本地操作系统生成的日志文件或审计日志。在 Linux 系统上，检查的日志通常包括由 syslog 创建的日志，例如消息、内核日志和错误日志。在 Windows 系统上，检查的日志通常是三个主要的“事件”日志：应用程序、系统和安全。某些 HIDS 还可以覆盖特定的应用程序（如 FTP 或 Web 服务），通过检查这些特定应用程序产生的日志或检查这些服务的流量来实现。在日志文件中，HIDS 正在寻找代表敌意行为的活动或：

- 身份验证失败
- 登录
- 添加新账户
- 修改关键文件
- 启动或停止
- 权限提升
