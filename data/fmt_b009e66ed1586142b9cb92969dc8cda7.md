# 14.7 为什么需要特征图？

现在让我们转向自组织特征图的一些实际益处。

### 降维

上一节介绍的技术本质上是将原始属性向量的 N 维空间映射到神经元矩阵的二维空间：每个示例都有其胜出神经元，胜者可以通过在矩阵中的两个坐标来描述。这些坐标可以被视为原始示例的新描述。

### 创建高级特征

在属性数量极高的应用中，减少属性数量至关重要，特别是当这些属性大部分无关或冗余时。例如，在计算机视觉领域可能会出现，每幅图像（即一个示例）都可以由数十万个像素描述。

学习了第 7 章后，读者理解直接将例如感知机学习应用于极长长度的属性向量是不可能成功的：在此类领域，在训练集上表现良好的分类器在测试数据上往往会失败得非常惨。这种失败的数学解释是，无数属性使得问题的 VC 维度如此高，以至于除非训练集大得不现实，否则是不可学习的。因此，高级机器学习应用程序寻求通过属性选择或（与本文更相关的）通过映射多维问题到较小空间来降低维度。这是通过创建原始特征函数的新特征来实现的。

## 因此可以创建哪些新特征

人们可能会将这个想法进一步。这里有一个简单的建议，仅供灵感。假设训练样本由`100`个属性描述，并假设我们有理由怀疑某些属性是相互依赖的，而许多其他属性是`无关的`。

在这样的领域中，维度可能是不必要的高，任何降低维度的尝试都是欢迎的。一种方法是提取（例如）五个不同的属性子集，然后重新描述训练样本五次，每次使用不同的属性集。之后，这些新获得的训练集中的每一个都经过`SOFM`处理，然后它将每个多维空间映射到两个维度。由于这种操作执行了五次，我们得到了`5 x 2 D 10`个新属性。

### 可视化

人类大脑在可视化二维或三维数据方面没有问题，并能对具体示例的相似性（或相互距离）、示例的分布或它们倾向于形成的群体形成意见。然而，当属性超过三个时，这就变得不可能了。这正是自组织特征图可以发挥用场的时候。通过将每个示例映射到二维矩阵上，我们可能能够可视化数据中固有的某些关系。例如，相似的属性向量可能会映射到同一个神经元，或者至少映射到物理上相互靠近的神经元。对于普通数据分布也可以做出类似的观察。从这个意义上说，特征图可以被视为一种有用的可视化工具。

### 初始化 k-Means

神经矩阵中的每个权重向量都可以被视为代码向量。`SOFM`的机制使得找到这些向量的合理值成为可能——这些值随后可以用于初始化如`k-means`等聚类分析方法。这是否是一种实用的方法是另一个问题，因为`SOFM`是一种计算代价很大的技术。

### 关于“深度学习”的简要提及

我们还应该指出，所谓的深度学习使用了从非常长的属性向量中自动创建高级特征的方法。本质上，深度学习是一种神经网络技术，它将神经元组织在许多层中，比我们在`Chap. 5`中多层感知器背景下看到的层多得多。从这个意义上说，这些网络是“深”的，这赋予了该范式的名称。

这些网络的顶层通过监督学习技术进行训练，例如读者已经知道的`误差反向传播`。相比之下，底层任务是创建一组合理的特征。可以想象自组织特征图可以用于此目的；在现实中，通常更倾向于更先进的技术，但它们的详细处理超出了本入门教材的范围。

然而，必须保持谨慎。一个具体的范式流行并不意味着它是一个解决所有机器学习问题的万灵药。远非如此。如果特征的数量是可控的，如果训练集的大小是有限的，那么经典方法的效果和深度学习一样好，甚至更好。⁵

## 规则形式的分类器

某些分类器采用所谓的“if-then”（如果-那么）规则形式：如果满足 if 部分的条件，则将示例标记为 then 部分指定的类别。通常，分类器不是由单个规则表示，而是由一组规则（规则集）表示。这种范式具有某些优点。一方面，规则捕捉了底层逻辑，因此有助于解释为什么某个示例必须被标记为给类别；另一方面，规则集的归纳能够发现递归定义，这在其他机器学习范式中很难实现。

在寻找从数据归纳规则或规则集的技术时，我们将借鉴来自归纳逻辑编程（Inductive Logic Programming）的思想，这是一门研究自动创建和改进 Prolog 程序方法的学科。然而，我们只对分类器的归纳感兴趣。

# 15.1 由规则描述的类

为了后面介绍简单的规则归纳算法，让我们看看规则的本质。表 15.1 包含了我们之前遇到的训练集。在该领域中，以下表达式作为正类的可能描述：

\[ (shape=circle) AND (filling-shade=dark) \] OR \[ NOT(shape=circle) AND (crust-shade=dark) \]

在分类示例`x`时，分类器将示例的值与表达式进行比较。因此，如果`x`是圆形且填充颜色为深色，表达式为真，分类器会将`x`标记为

297

![image](img/image575.png)表 15.1 以形式表示的十二个训练示例

正类。如果表达式为假，分类器会将`x`标记为负类。该表达式可以转换为以下规则：

R1: if (shape=circle) AND (filling-shade=dark) then pos.
R2: if NOT(shape=circle) AND (crust-shade=dark) then pos. else neg.

在机器学习的术语中，每个规则由一个前件（if 部分，在此背景下是属性的与）和一个结论（then 部分）组成。注意的是，这两个规则的结论都指向正类。要将示例标记为正类，必须满足至少一个规则的前件。否则分类器会将示例标记为默认类。我们要记住，在处理此类规则集时，不能忘记指定默认类。

### 简化假设

在本章中，我们将依赖以下简化假设：

1. 所有训练示例都由离散值属性描述。
2. 训练集无噪声的。
3. 训练集是一致的：具有相同属性的示例必须属于同一类别。

### 机器学习任务

我们的目标是找到一种从满足上述假设的数据中归纳规则集的算法。我们将限制在那些结论指向正类的规则上，默认类总是负类。

由于训练集预期是一致且无噪声的，我们将对能够正确分类所有训练示例的分类器感兴趣。这意味着

对于每个正示例，至少一个规则的前件为真。对于任何负示例，没有规则的前件为真，示例被标记为默认（负）类。

### 规则“覆盖”示例

让我们引入一个实用的术语：示例要么被规则覆盖，要么不被。一个简单的插图将澄清这一概念。考虑以下规则：

R: if (shape=circle) then pos.

![image](img/image371.png)如果我们把此规则应用到表 15.1 中的示例，我们将观察到前件的条件 shape=circle 被以下示例集满足：ex1; ex2; ex4; ex6; ex7; ex0 。 我们说 R 覆盖了这六个示例。通常来说，如果规则前件中的表达式对于该示例为真，则该规则覆盖该示例。注意的是，被此特定规则覆盖的示例中有四个是正的，两个是负的。

规则特化如果我们通过向上述规则的前件添加另一个条件`filling-shade=dark`来修改该规则，将得到：

R1: if (shape=circle) AND (filling-shade=dark) then pos.

![image](img/image615.png)在训练集上检查 R1，我们意识到它覆盖了以下示例：ex1; ex2; ex4; ex6 。我们观察到这是 R 原覆盖的六个示例的子集。幸运的是，现在只有正示例（而没有负示例）被覆盖。

这引出了另一个有用术语的定义。如果规则前件（antecedent）的修改使得覆盖的示例集减少到一个子集，我们称这种修改对规则进行了特化（specialized）。换句话说，特化是将覆盖的示例集缩小到一个真子集。特化规则的一种典型方法是在规则的前件中添加一个新的条件。

### 规则泛化

相反，如果规则的修改将其覆盖的示例集扩大到一个超集，则该规则被泛化（generalized）——如果新版本涵盖了旧版本涵盖的所有示例，加上额外的一些。泛化规则最简单的方法是从其前件中删除一个条件。例如，当我们从规则`R1`中去掉条件`(filling-shade=dark)`时就会发生这种情况。

### 规则集的特化与泛化

我们已经提到，我们感兴趣的是规则集的归纳，如果一个示例至少有一个规则的前件为真，则将该示例标记为正类。例如，上述由规则`R1`和`R2`组成的规则集就是这种情况。

如果我们从一个规则集中移除一条规则，规则集可能不再覆盖之前覆盖过的某些示例。我们已经知道，这被称为特化。相反，向规则集中添加一条新规则将泛化该规则集，因为新规则会增加覆盖的示例集。

# 15.2 通过顺序覆盖归纳规则集

![image](img/chapter_title_below.png)

现在让我们介绍一种简单的技术，它可以从满足上一节简化假设的训练数据中归纳规则集。

### 原理

目标是找到一个规则集，使其每条规则都覆盖某些正示例，但不覆盖任何负示例。这些规则共同应该覆盖所有的正示例且不覆盖任何负示例。我们将使用的程序每次创建一条规则，始终从一个非常通用的初始版本（也覆盖负示例）开始，然后逐渐特化，直到所有负示例都被排除在覆盖之外。规则是顺序创建的，且每条规则都应该覆盖被之前的规则遗漏的正示例，这种特性赋予了该名称：顺序覆盖（sequential covering）。

### 顺序覆盖的基准版本

表 15.2 提供了归纳规则集的简单方法的伪代码。主体包含了顺序覆盖算法。其思想是找到一条覆盖某些正示例但不覆盖任何负示例的规则。一旦创建了该规则，它覆盖的示例就会从训练集中移除。如果没有剩余的正示例，算法停止；否则，将算法应用于缩小后的训练集。
