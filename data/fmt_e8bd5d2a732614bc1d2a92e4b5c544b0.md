
# 引言

在这一章中，我们将透过钥匙孔窥向另一侧……我们将从日常理智且合理的世界跨越边界，进入数据科学家那扭曲的多维领域；即那些拥有数学学位和博士学位的技术专家。在旅程中，我们将：

* 描述数据科学家在应用机器学习开发预测模型时应遵循的流程，这些模型将作为自动化决策系统的一部分，用以驱动业务收益。

* 以一种普通人也能听懂的方式来解释这一过程。这有助于你随时掌握数据科学家在做什么。反过来，这也确保了你获得的是你所要求的，而不是数据科学家认为你的组织需要的东西。

根据我的经验，当数据科学家被放任“自己去忙”，并在项目结束时交付结果作为“致命一击”（`coup de grace`）时，交付的往往是次优解决方案。在最糟糕的情况下，他们可能无法交付任何有用的东西。

我合作过的大多数数据科学家非常清楚需要让客户参与到机器学习过程中，并为项目获取业务投入付出了努力。然而，遗憾的是，我也见过不止一个案例，即数据科学家刻意用技术术语来迷惑普通人，或者完全避免与他们交流。这样做是为了让他们能够专注于重要的数学工作，而不必去应付那些每天必须负责运营组织的“愚蠢的笨蛋”。

一个简单的规则是：如果数据科学家无法向你解释他们做了什么以及为什么这么做，那么他们就没有完成任务。他们还需要让业务部门清楚地理解他们工作的收益是什么。作为一个业务用户，我对于一个预测模型的准确率为 95%，且它比它要取代的流程判别性高出 10%并不感兴趣。我想知道的是它能为我赚多少钱，能救多少人的命，能让我减少多少员工，或者其他信息。如果一个数据科学家无法根据为客户底线提供的收益来表达其价值，那就是一个糟糕的数据科学家。

然而，这是双向的，把所有责任都推在数据科学家身上是不公平的。要求业务用户努力理解数据科学家如何进行机器学习过程，这并不是过分的要求。随着项目的进展，应该进行双向的信息交换，并定期召开会议，以非技术性的、以业务为中心的方式展示并讨论初步发现、结果、问题和挑战。这将引导项目的推进。

考虑到这些，我将避免深入探讨用于机器学习的各种算法的数学原理，例如用于训练神经网络或决定决策树划分方式的算法。对于那些对技术细节感兴趣的读者，机器学习中最常用的算法都有非常详尽的文档（参见附录 B 中的推荐书籍和网站）。同样，这些算法的实现在现在你可以购买的商业统计软件包中，或者通过开源软件免费获得（例如`R`和`Python`代码库）。因此，你不需要知道如何编写特定的机器学习算法；你只需要知道如何在你所选的软件包中调用相关的函数或过程即可。

## 机器学习流程

数据科学家需要做的第一件事是量化业务问题；即将业务试图实现的目标表示为一个简单的数字或分数。零售店的销售总监可能会这样开始与数据科学家的会话：

“我们需要一个预测模型来识别我们的优质客户。”

所以，要问的第一个问题是：

“你说的‘优质’是什么意思？”

销售总监回答道：

“对我们的业务做出财务贡献最大的客户。”

好的，这看起来很合理，但“财务贡献”是指总销售额还是净利润？我们讨论的是每次进店、每次点击，还是每个单位时间（周/月/年）的贡献？当我们谈论“客户”时，我们看的是个人还是家庭的贡献？问题以此类推。数据科学家需要梳理出业务所要求的精确定义，然后用可以用他们构建的模型所生成的分数来表示的方式表达出来。

在这个例子中，可能在与营销总监讨论后，达成共识将模型设计为预测个人每季度的总支出。选择季度总支出是因为这个定义与组织的报告周期相符，且总收入（支出总和）是销售总监的关键绩效指标。

选择个人支出而非家庭支出，是因为双方达成共识：尽管从理论上讲家庭支出更好，但组织的客户数据库是以个人而非家庭为级别构建的。在组织目前的 IT 基础设施限制范围内，无法部署基于家庭支出的模型。IT 设施可以升级以提供家庭视图吗？不，绝对不能，不能作为该项目的一部分，因为业务部门今年没有为 IT 变动分配任何预算。

基于这些信息，数据科学家应该确定这是一个回归类型的问题，用于预测每个个人客户在三个月预测期内的支出金额。

在确定如何量化表达业务目标的同时，数据科学家还需要进行探索性分析，以了解组织的数据和 IT 资产、它们是如何运作的以及它们是如何相互作用的。这包括：

* 组织拥有哪些数据库？

* 每个数据库的目的是什么？哪些业务流程使用了它们？

* 数据库中包含什么？即包含哪些数据项以及这些数据项的格式。例如，是数值数据还是文本数据。

* 每个数据库是如何更新和维护的？大多数组织拥有“实时”客户数据库（在发生变化时立即更新）和批处理数据库（更新频率较低；例如在夜间或月底）。

* 已经部署了哪些决策系统？模型将实现在现有系统中，还是需要新功能？

* 组织目前使用哪些数据进行决策？即使这些数据用于一个过时的手动流程，这些数据对于机器学习目的也可能极具价值。

在理想世界中，组织拥有完善的文档（元数据），提供数据资产的清单，包括数据类型、数据格式及其来源。然而，在实践中，这类信息往往是不完整的、错误的或过时的。许多有用信息存储在业务用户的脑中，他们作为日常工作的一部分经常使用它们。可能会有一个名为`客户人口统计 3`的数据项，包含字母`A`、`B....G`。这到底意味着什么？哪里都没有记录，但运营部的 Claire 知道这与他们使用的收入等级匹配。`A`代表年收入低于 20,000 美元，`B`代表 20,000-35,000 美元，以此类推。

许多组织还保留着他们已不再理解的数据。然而，他们害怕删除这些数据，万一它们是某些关键业务流程所依赖的重要信息呢。在探索性分析阶段，还应该检查内部和外部的潜在新数据源，因为这些数据可能会增强任何开发模型的预测能力。

总而言之，需要投入大量精力来探索可以收集数据的“宇宙”，并决定哪些数据可能被使用，哪些又不能使用。

一旦数据科学家对组织拥有的数据以及其结构有了良好的理解，他们就可以进入`Stage 3`，考虑创建将用于机器学习过程的开发样本。

为业务构建预测模型的一种非常天真的方法，仅仅是将组织拥有的每一条信息都直接丢进机器学习过程中。在实践中，许多数据是过时的、不稳定的或在其他方面是不合适的。因此，应该将这些数据从开发样本中排除，以防它们降低机器学习过程的性能。

从机器学习过程中排除某些数据的常见典型原因包括：

- **过时的数据。** 如果数据与当今的世界不再相关，那么就不要考虑它。关于智能手机出现之前人们如何使用手机的数据，对于告诉你今天智能手机的使用情况将没有太大帮助。

- **不代表目标总体。** 开发样本应仅包含与模型将要应用的总体镜像的案例。如果一个收入模型是专门为在线客户开发的，而这两个渠道的消费模式不同，那么你应该排除门店交易记录。同样，如果你从声音样本中开发语音识别系统，那么所有样本都应该与语音有关。如果你有狗叫声或交通噪音的示例，那么这些需要被移除。

- **数据的稳定性。** 机器学习过程中使用的数据在模型应用时是否可用？如果某个数据项在实施点上是不可用的，那么它应该被排除在外。

- **法律和伦理原因。** 你是否想使用如种族、性别和性取向等敏感个人数据？这类数据可能极具预测性，但使用它们可能是非法的。如果它是合法的，但一旦你对待某些群体的方式与其他不同被为人知，那么使用此类数据可能会产生声誉风险。如果基于模型评分的折扣策略导致你只对异性恋男性提供折扣——那很可能会引起争议。

- **确定性案例。** 如果你对某些客户非常确定地知道将如何对待他们，那么你就不需要为他们建立预测模型。将他们包含在开发样本中只会削弱模型在其余总体上衡量的效力。

- **不可解释性。** 机器学习的一个基本原则是，在使用你不完全理解的数据构建模型时，应该非常谨慎。这对于受行业监管的模型或对组织的成功具有战略意义的模型来说，尤其真实。如果数据科学家向你展示了一个使用他们无法解释的数据的模型，那么这就是你应该关注的风险。

如果一个组织拥有巨大的数据库，那么在作为机器学习过程的一部分来分析这些数据库时，计算机资源方面可能会出现问题。只选择样本（例如`1:10`或`1:100`的案例）纳入开发样本的情况并不罕见。“大数据纯粹主义者”可能会认为，你应该分析所有可用数据，因为未能这样做可能会遗漏某些微妙的模式，从而创建出次优的模型。在某种意义上他们是正确的，因为如果你采用样本而不是使用整个总体，生成的模型准确性不会那么高。然而，这在很大程度上是一个收益递减的过程。对于几乎所有的实际业务问题，增加几万个案例带来的收益是微乎其微的。如果你以适当的方式进行采样，那么你从使用`100,000`个案例开发的模型中将获得使用`1000 万`个案例模型`99%`的收益。换句话说，仅仅因为你有海量数据并不意味着你需要投资专业的硬件/软件来应用机器学习——你只需要在执行上足够聪明，并专注于真正重要的数据。

该过程的第四阶段是数据准备。这是必要的，因为原始数据可能格式糟糕、包含错误，或者没有提供数据的最佳表示；即不同的表示将使机器学习过程更容易发现数据中的重要模式。在数据准备期间有四项主要任务：

- **创建新数据。** 对于大多数类型的问题，`Age`比`Date of Birth`更具预测性。因此，如果只有`Date of Birth`，则可能需要计算`age`。同样，如果你有信用卡交易数据，最好是创建汇总变量，代表每笔交易的平均支出、上个月的交易次数、距离上次交易的时间等。

- **数据清洗。** 数据可能缺失或不正确。数据准备的一个关键目的是识别此类数据存在于何处，并将其移除（排除）或对其进行重新格式化；即用标准值对所有数据进行重新编码。如果用于计算年龄的出生日期在未来或在过去遥遥的过去，你可能想为年龄定义一个例如`-1`的默认值来表示这些情况。

- **合并。** 以相似的方式表示相似的数据是一项良好的做法。如果你有一个名为`property type`的数据项，其中`D`、`Det`和`Detached`的值都相同；即都是`Detached`（独立屋），那么这些应该合并为一个单一值，用于代表所有`Detached`案例。

- **转换为数值。** 机器学习算法喜欢数值数据。`Yes`/`No`/`Maybe`将被转换为`0/1/2`标记。对于复杂的文本或语音（如推特流），一种方法是包含标记以指示某些词是否出现，或者生成某些词出现次数的计数。

一旦准备好合适的数据样本，就该进行数据预处理和初步变量选择了（`Figure 9`中的`Stage 5`）。通过数据预处理，你是将数据转化为一种最有利于所选机器学习算法的格式。

预处理通常涉及两个过程：标准化和转换。标准化过程通过缩放数据使所有数据具有相似的值。如果你有两个数据项，如`gross annual income`和`height in metres`，那么标准化的一种方法是减去各自的平均值，然后除以范围（或其他衡量标准）。这样，两者都将以零为中心，并具有大致相似的范围。

# 数据预处理

在这里，我们将开始查看的第一项可以帮助我们开始学习机器学习相关内容就是数据预处理。在进行任何机器学习工作之前，你必须确保你正在处理的任何数据都处于正确的格式。将数据转换为正确的格式以便进行机器学习工作，就被称为数据预处理。

现在，这取决于你想要处理的数据类型，但为了帮助你看到预处理工作的良好运行，通常需要执行几个步骤。这些步骤对于后续工作来说至关重要，因为它们将确保数据以正确的形式被使用。在此部分你应该关注的步骤包括：

* 获取数据集

* 导入你的库

* 导入数据集

* 处理任何缺失值

* 处理分类数据

* 将数据划分为不同的训练集和测试集

* 缩放数据

让我们仔细查看这些中的每一个项，以及它们如何协同工作以正确地准备你的数据。

## 获取数据集

现在，我们需要花一点时间来看这组数据。当我们查看时，开始注意到其中有很多关于手头患者年龄、性别和`BMI`的信息。该数据集还包含一个额外列，显示我们观察的患者是否患有糖尿病。你应该注意到，年龄和`BMI`列将是数值型的，而另外两列在本质上是分类的。

在这里我们需要做的另一个区分是因变量和自变量之间的区别。当我们观察这些变量时，值被预测的变量作为因变量，而用于做出这些预测的变量将成为我们的自变量。当我们看这类例子时，`diabetic`列将被视为因变量，因为它至少在某种程度上依赖于其他列。我们会注意到其他列将是我们的自变量。

## 划分数据

当我们到达流程的这一步时，下一步是将数据集划分为特征矩阵和因变量向量。特征集将包含所有你认为是独立的变量。

例如，`patients.csv`数据集的特征矩阵将包含你为年龄、`BMI`和性别放置的信息。此外，你在特征矩阵中看到的大小将等于自变量的数量乘以记录的数量。对于这个例子来说，我们的矩阵最终将是三乘十二。这是因为我们有三个自变量和十二位我们要观察的带有记录的患者。

为了帮助我们开始这项工作，我们首先需要遍历并创建特征。你可以为它提供任何喜欢的名称，但传统的做法方法是使用大写的`X`。为了让我们有更好的机会阅读代码，我们将其命名为`features`，然后使用下面的脚本：

```python
features = patient_data.iloc[:,0:3].values
```

通过我们上面使用的脚本，数据框的`iloc`函数用于帮助从`patient_data`中选择所有行以及前三列。这个`iloc`函数将接受两个参数：第一个是选择的行范围，第二部分是你想让程序选择的列范围。

如果你想从这里创建自己的标签向量，你可以使用以下脚本来完成：

```python
labels = patient_data.iloc[:3].values
```

如果你现在停止并查看标记为`patient_data`的对象，你会发现该患者的`BMI`列在索引`4`处缺少了一条记录。为了帮助我们能够处理值缺失的情况，最简单的方法是找到一种删除掉缺失值记录的方法。然而，这条记录也可能包含一些我们需要关注的关键信息，因此你有时可能希望将其保留在那里。

你可以使用的另一种帮助处理这些缺失值的选项，是添加某种类型的数值或字符，以替换缺失的值。通常我们发现，替换该值的最佳选择是该列中所有其他存在值的平均值或中位数。为了帮助你在缺失值出现时对其进行处理，你只需要使用`sklearn.preprocessing`库中找到`Imputer`类。你需要确保实现这一操作的脚本如下所示：

```python
from sklearn.preprocessing import Imputer 

imputer = Imputer(missing_values="Nan", strategy="mean", axis =0) 

imputer = Imputer.fit(features[:,1:2]) 

features[:,1:2] = imputer.transform(features[:,1:2]) 
```

## 回归算法

列表上的下一个是回归算法。你可以使用它，因为它是一种你可以在其中调查因变量与你喜欢的预测变量之间关系的类型。每当你发现你所做的预测、时间序列建模以及所有变量之间存在因果关系时，你就想要使用这些算法。

你会发现，当你想要尽可能地拟合一条直线或曲线时，这是可能的。这有助于你真正看到这些数据点之间是否存在某些共同因素，以便你可以学习数据并可能进行一些预测。

与现有的其他两种学习算法相比，这种会稍微不同。事实上，一些程序员会将此视为一种比较“懒惰”的学习过程，因为除非你运行并要求它进行新的预测，否则它无法真正创建任何模型。但如果你希望保持模型中的信息具有相关性，或者对你添加到模型中的内容有更多话语权，这对某些项目来说是一件好事，但在其他情况下，它可能没那么帮助。

使用`KNN`学习算法有很多益处。例如，当你选择使用这种算法时，你可以学习如何过滤掉有时出现在数据集中的噪声。这种方法之所以有效，是因为它将完全通过竞争的方法来帮助筛选所有数据，以期找到最理想的内容。这种算法很有用，因为它可以同时接收大量数据，甚至更大量的数据，在许多不同情况下都很有用。

然而，当涉及到这种算法时，你需要考虑一些条件。最大的问题是计算成本很高，特别是当你将其与其他某些学习算法进行比较时。这是因为`KNN`在向你发送预测之前将查看所有的点。这在总体上花费了大量的时间和金钱，可能不是你想要使用的算法。
