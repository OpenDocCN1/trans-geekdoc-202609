
尽管访问系统中涉及了保护措施，总是存在可以绕过这些保护的机制。这些通常被称为“隐蔽道”（covert channels）。隐蔽道通常定义为系统设计者无预期的通信路径（Techopedia, 2018）。

在多级安全系统中可能存在这样一个例子。假设用户 George 具有绝密许可，而另一个用户 Phyllis 具有机密许可。此外，假设文件空间是共享的。在这种情况下，George 创建了一个名为`ABC.txt`的文件，由于是其创建的，将被分配绝密级别。当然，只有机密许可的 Phyllis 无法读取该文件。然而，为了让 George 逐位向 Phyllis 通信，Phyllis 每分钟检查一次目录。如果第一分钟看到文件存在，她记录“1”。如果一分钟后 George 删除了文件而 Phyllis 再次检查——没有看到文件——她将记录“0”。然后，George 可能再次创建文件，这样下一分钟 Phyllis 将看到文件存在并记录“1”。因此，在例如 60 分钟内，George 实际上可以泄露 60 位比特的消息。

再考虑一个隐蔽道的例子。假设我们有一个 100MB 的绝密文件，在绝密级别上以未加密的形式存储。然而，加密版本可能存储在非密级别，以便从一个系统传输到另一个系统。这不会产生安全风险，因为我们假设没有密钥的人发现这个加密版本是毫无用的。然而，密钥（当然存储在绝密级别）可能只占用几百个比特。因此，通过如上所述的方法，从绝密级别逐位泄露到非密级别，可以在几分钟内让非密级别获得完整的密钥，并获得解密 100MB 文件的能力。

## 8.5 推论控制

对于许多人来说，一个主要应用是在大型数据库中使用和访问它，例如企业数据库或大学数据库。数据库的目的是允许多个用户根据上述描述的访问规则，从数据库中读取或修改信息。然而，对数据库的访问并不是固定在某一时刻的。任何具有提交数据库查询能力的用户都可能在无意中（或可能是有意地）获得该用户可能被禁止直接访问的信息。考虑以下这个来自大学数据库的示例：

答案：$95,000

问题：XYZ 大学有多少位女性心理学教授？

答案：1

由于这两个查询的结果，特定的信息已经从对一般性问题的回答中泄露了！

## 8.8 防火墙

防火墙必须决定什么进入内部网络，允许什么出去。换句话说，防火墙旨在为网络提供访问控制（Cisco, 2018）。你可以将防火墙想象成门卫。要与执行官会面，首先联系门卫。门卫决定会议是否合理；此外，门卫还会过滤掉许多请求。假设你想见心理学系主任。门卫进行了一些过滤。防火墙有几类：

* 数据包过滤器
* 状态检测数据包过滤器
* 应用代理
* 个人防火墙——用于单用户、家庭网络等。

### 8.8.1 数据包过滤器

这种防火墙工作在网络层，它可以根据以下几项进行过滤：

* 源 IP 地址
* 目的 IP 地址
* 源端口
* 目的端口
* 标志位位（`SYN`、`ACK`等）
* 出站或入站

## 8.9 入侵检测

尽管有防火墙或其他入侵预防方法，坏人往往会进入系统。因此，如果我们假设系统会被攻破，我们应该寻找能够判断是否发生了此类渗透的系统。此类系统通常被称为入侵检测系统（`IDS`）（Cyberpedia, 2018）。

`IDS`设计用于通过寻找“异常活动”来检测攻击。IDS 目前是一个非常热门的话题。入侵者是谁？可能是外部人员。入侵者会做什么？他们可能会执行已知的攻击。有两种主要的入侵检测方法：基于签名的`IDS`和基于异常的`IDS`。

## 8.10 签名检测系统

这里是签名检测的一种示例：密码破解攻击可能正在进行。签名`IDS`使用`M seconds`内的登录尝试作为签名。如果`N`或更多登录尝试发生在`M seconds`内，签名`IDS`会发出警告。注意，这种警告是特定的。假设攻击者知道签名，他们可以在`M seconds`内尝试`N - 1`次登录！在这种情况下，签名检测会减慢攻击者，但可能无法阻止他们。签名检测的缺点包括：

* 签名文件必须保持更新
* 签名数量可能很大
* 只能检测已知攻击
* 已知攻击的变体可能无法检测

## 8.11 异常检测系统

异常检测系统寻找异常或异常的行为。在尝试开发此类系统时，面临着至少两个挑战：首先，对于该系统来说什么是“正常”？然后，异常距离正常有多远？这种方法意味着我们必须使用某些统计测量，例如标准差和方差。通常，平均值定义了正常，标准差或方差指示异常离正常有多远。

问题变成了：我们如何衡量“正常”？我们需要在“代表性”行为期间分析系统，而不是在攻击期间，否则攻击看起来是正常的。我们如何衡量“异常”？当然，异常是相对于某些“正常”，异常指示可能的攻击。

假设我们监控三个命令：`open`、`read`、`close`。在正常使用下，我们观察到 Ellen 经常执行以下序列：

`open, read, close, open, open, read, close, ...`

在六种可能的排序对中，有四对对 Ellen 来说是“正常”的：

`(open,read)`, `(read,close)`, `(close,open)`, `(open,open)`。

我们可以使用这些序列识别异常活动吗？我们监控三个命令：`open`、`read`、`close`。如果异常对与正常的比例“过高”，我们就对可能的攻击发出警告。

最近，Ellen 以速率`An`访问了文件`Fn`（见表 8.3）。

| 表 8.3 时间 $t2$ 时四种用例的异常检测 |
| --- |
| A0 | A1 | A2 | A3 |
| 0.10 | 0.40 | 0.30 | 0.20 |

这是“正常”用用法吗？为了估计这一点，我们计算其与平均值的距离：

`S = (H[0] − A[0])² + (H[1] − A[1])² + ⋯ + (H[3] − A[3])² = 0.02`

我们做出判断：如果`S < 0.1`，则该行为是正常的。在这种情况下，`S = 0.02 < 0.1`，因此这是正常的。

### 问题：我们如何处理随时间变化的用例？

为了让“正常”适应新的用例，我们按如下更新长期平均值：

`H[n] = 0.2A[n] + 0.8H[n]`

此时，`H0`和`H1`保持不变，`H2 = 0.2 × 0.3 + 0.8 × 0.4 = 0.38`，且`H3 = 0.2 × 0.2 + 0.8 × 0.1 = 0.12`

| 0.10 | 0.40 | 0.38 | 0.12 |

| --- |

这是正常用例吗？

计算`S = (H0 − A0)2 + ⋯ + (H3 − A3)2 = 0.0488`

由于`S = 0.0488 < 0.1`，我们认为这是正常的。
