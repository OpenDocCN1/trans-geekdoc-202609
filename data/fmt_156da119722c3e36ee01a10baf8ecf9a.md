## 5.6 总结

对于数据库的给定状态，角色 `r` 的*总体*，记为 `pop(r)`，是在该状态下作为扮演该角色而被引用的对象集合。`A ∪ B`，即集合 `A` 和 `B` 的*并集*，是包含 `A`、`B` 或两者中所有元素的集合。*空集*，记为 `{ }`，没有成员。

实体类型 `A` 的总体，记为 `pop(A)`，是其角色总体的并集。基本事实类型的角色称为*事实角色*。

纯粹用于标识或引用某个对象的关系类型称为引用类型；其角色称为*引用角色*。对于给定状态，事实类型（存储的或导出的）的总体是其事实实例的集合。

概念模式设计过程的*步骤 5*要求我们*添加强制角色约束并检查逻辑导出*。当且仅当（iff）对象类型 `A` 的总体 `pop(A)` 中的每个成员都已知扮演角色 `r`（针对知识库的每种状态）时，该角色 `r` 对对象类型 `A` 而言是*强制的*（或*全称的*）；否则，该角色是*可选的*。强制角色用一个大圆点表示，位于角色与对象类型的连接处。该圆点也可放置在角色末端。

默认情况下，如果基本实体类型在全局模式中仅扮演一个事实角色，则该角色是强制的——在这种情况下，圆点可省略，因为它是隐含的。模式约束适用于模型，不一定适用于现实世界。

如果角色在现实世界中是可选的，则在模型中也是可选的。然而，在现实世界中强制的角色在模型中可能是可选的（例如，信息可能未知或出于隐私考虑而省略）。

角色 `r[1]`，…，`r[n]` 的*析取*对对象类型 `A` 是*强制的* **iff** `pop(A)` 中的每个成员都已知至少扮演这些角色中的一个（在每种状态下）。这种*包含性或*或*析取强制*约束用一个带圆圈的圆点 `⊙` 表示，通过虚线连接到这些角色。

默认情况下，基本实体类型在全局模式中所扮演的事实角色的析取是强制的——在这种情况下，圆点可省略，因为它是隐含的。然而，如果简单或析取强制角色约束适用于子类型（见下一章），则应显式显示。

为简化具有许多角色的对象类型的描绘，对象类型可在模式页面上*复制*，也可跨多个页面复制。在这种情况下，隐含强制角色析取的规则适用于所有副本的并集。不同的计算机辅助软件工程（CASE）工具使用不同的符号（例如，用阴影表示复制）。

每个实体类型必须有一个或多个候选引用方案。其中一个被选为*首选标识*方案，其他的则视为基本事实类型。首选引用方案（也称为主标识符）应尽可能简单且稳定。*刚性标识符*在应用程序的整个生命周期内标识同一对象。首选标识必须提供从每个实体到一个或多个值的元组的强制 1:1 映射。

*简单引用*方案将每个实体映射到单个值（例如，`Subject` 到 `SubjectCode`）。*复合引用*方案将每个实体类型映射到两个或更多对象类型（例如，`Room` 到 `Building` 和 `RoomNr`）。除嵌套情况外，复合引用的标识方面用外部唯一性约束表示，描绘为带圆圈的双唯一性杠 `⊜`。采用*析取引用*时，同一类型的不同实体的值的数量可能不同（例如，`Person` 到 `Surname` 和 `Firstname` 以及可选的 `Middlename`）。

同一实体的候选标识符称为*同义词*。当存在多个候选标识方案时，首选引用方案在模式上按如下方式指示：如果是简单的，使用带括号的引用模式；如果是复合的，使用 `⊜`。如果引用模式扩展为显式的二元关联，则标识角色用双唯一性杠标记。

如果对同一数量使用*不同单位*，则必须对这些单位之间的语义联系建模（例如，通过声明这些单位属于同一*维度*）。不同单位可建模为引用模式，或通过使用 `Unit` 对象类型。对于任何给定的物理量，通常选定一种单位作为标准单位；提供转换规则将导出单位映射到标准单位。

导出事实类型可从图中省略，但必须指定其导出规则。如果导出事实类型包含在图中，通常应显示其所有约束。*通常，导出事实类型上显示的所有约束都是可导出的*（从其导出规则和其他约束导出）。

添加强制角色约束后，应执行*逻辑导出检查*，以查看是否某些事实类型可使用逻辑而非算术运算导出。首先，通过询问“对象类型之间是否存在其他感兴趣的关系，特别是函数关系？”，来检查是否有缺失的事实类型。如果二元关系类型的至少一个角色是函数的（即该角色是简单键），则该二元关系类型是*函数的*。函数角色的每一列条目在函数上决定另一角色的条目。

我们现在询问，*是否有任何事实类型可从其他事实类型导出*？为帮助判断此点，请记住导出事实类型上的约束通常应是可导出的。如果我们有一条包含两个或更多函数事实类型的链，且所有第一角色上都有唯一性约束，则从该链的开始到结束的函数二元事实类型，如果通过对这些事实类型的连接进行投影来定义，则是可导出的——其唯一性约束是*传递隐含的*。在这种情况下，导出事实类型的第一角色是强制的 **iff** 链的第一角色是强制的，且链中每个二元事实类型的第二角色子集化于下一个二元事实类型的第一角色（例如，如果链中每个二元事实类型的第一角色都是强制的）。

导出规则通常应为双条件（即其主要运算符为“**iff**”）。如果其主要运算符为“**if**”，则该事实类型为*半导出*。当且仅当对于业务领域的某些状态，其某些实例可从其他事实导出，而某些实例仅被断言时，该事实类型为半导出。半导出事实类型在其谓词读法后用加号 `^(+)` 标记。

导出事实类型不需要拥有简单键。无论是否导出，除非事实类型对应用程序有意义，否则应从模式中排除。

### 章节注释

某些 ORM 版本使用全称量词 (∀) 代替强制角色点，并将其置于角色连接线上，而不是放在一端（例如，参见 De Troyer et al., 1988）。正如后续章节所讨论的，实体-关系建模 (ER) 和统一建模语言 (UML) 支持大多数情况下的简单强制角色约束，但不支持析取强制角色约束。某些 ER 版本用实线表示强制，用虚线表示可选（例如，参见 Barker, 1990a,b），某些用双线表示强制（例如，参见 Elmasri and Navathe, 1994），而包括 UML 在内的某些版本则使用基数或多重性标记，如用 0 表示可选，用 1（或更多）表示强制。UML 允许属性被声明为强制或可选，但并非所有 ER 符号都允许这样做。

讨论析取参考方案时所用的植物学示例来自 Peter Ritson，他与我们中的一位合作开发了一种建模此类方案的方法。关于该主题的技术性讨论，请参见 Halpin and Ritson (1992)。

## 6.1 CSDP 第 6 步简介

到目前为止，我们已经学会了如何用基本事实来口头表达示例、绘制事实类型、标记唯一性约束和强制角色、指定派生事实类型的规则，以及使用简单和复杂的参考方案来标识实体。概念模式设计过程 (CSDP) 的下一步涵盖三种约束：值、集合比较和子类型。集合比较约束本身又分三种：子集、相等和排斥。

本章详细介绍第 6 步。为了阐明约束背后的形式化概念，首先回顾一些基本集合论。然后，我们讨论值约束（即对值类型的限制）。例如，在建模彩色显示器时，我们可能将 `ColorCode` 的值限制为“R”、“G”和“B”（分别代表红、绿、蓝）。在讨论了独立对象的相关概念后，我们将探讨三种集合比较约束——这些约束声明一个角色序列的实例集必须包含于、等于或与另一个角色序列的实例集互斥。

## 6.2 基本集合论

由于第 6 步中的约束大量使用集合和集合运算，让我们首先回顾一些基本集合论。为了提供所需背景知识的综合摘要，其中包含了一些前面遇到的概念。

直观上，`集合` 是项目的一个定义明确的聚合。项目可以是具体的（例如，人、计算机）或抽象的（例如、数字、点），被称为集合的 `元素` 或 `成员`。集合本身是抽象的。它们在数量上是确定的，意思是每个集合都有确定数量的元素。`类型` 是一组可能的项目，理解为共享某些共同特征（可能未明确陈述）。

集合的成员共同构成集合的 `外延`。虽然集合可能 `包含` 成员，但它并不 `由` 这些成员 `组成`。例如，火星卫星的集合是超越其成员（福波斯和戴摩斯）的一种抽象，因此它没有质量或体积等物理属性。尽管集合（不同于堆）不应等同于其成员，但它们由其成员决定，因为当且仅当两个集合具有相同的外延时，它们才是 `相同的` 或 **相等的**。用“iff”表示“当且仅当”，`外延定律` 可表述如下：

```
给定任意集合 A 和 B，A = B 当且仅当 A 和 B 拥有相同的成员。
```

因为集合由其成员决定，定义集合的一种简单方法是 `枚举` 或列出集合的元素。这样做时，使用大括号作为定界符，逗号作为项目分隔符（例如，*A* = {3, 6}）。这里，*A* 被定义为仅包含元素 3 和 6 的集合。

`外延定律` 的一个推论是，集合不因其成员的 `重复` 而改变。例如，如果 *A* = {3, 6} 且 *B* = {3, 6, 6}，则可得出 *A* = *B*，因为两个集合都恰好包含相同的成员（3 和 6）。集合 *A* 的 `基数`，记作 `#A`，是 *A* 中不同元素的数量。例如，#{3, 6} = #{3, 6, 6} = 2。

枚举集合时，通常不重复成员。但有时允许重复很有用。例如，在陈述关于集合变量 {*x*, *y*} 的一般结果时，包含 *x* = *y* 的情况可能会有帮助。有时成员重复会不被察觉。例如，有些人没有意识到实体集 {Morning Star, Evening Star} 只包含一个成员（金星）。当然，值集 {“Morning Star”, “Evening Star”} 包含两个成员。

如果重复被视为有意义，我们就得到一个 `包` 或 `多重集`。为了区分包和集合，我们使用不同的定界符。我们用方括号表示包，用大括号表示集合。包的基数等于其元素数量，包括重复项。例如，#[3, 6] = 2，但 #[3, 6, 6] = 3。包的一个用途是收集值以进行统计工作。例如，集合 {3, 6, 6} 的平均值是 4.5，但包 [3, 6, 6] 的平均值是 5。包常与 `SQL` 等语言一起使用。

`外延定律` 的另一个推论是，列出元素的 `顺序` 无关紧要。例如，如果 *A* = {3, 6} 且 *B* = {6, 3}，则 *A* = *B*，因为每个集合包含相同的成员。包也不敏感于顺序，如 [3, 6] = [6, 3]。如果顺序被视为有意义，我们就得到一个“有序集合”。

### 序列与集合

### 序列

通常，当顺序变得重要时，重复也随之变得重要。在这种情况下，我们得到一个**序列**（也称为列表、排列或元组）。因此，序列是一个有序的包。序列通常用圆括号或尖括号界定，例如 `(1,2)` 或 `〈1, 2〉`。序列 `(6, 3, 6)` 有三个成员，且不同于序列 `(3, 6, 6)`。序列的基数是其成员数量，包括重复项。例如，`#(3, 6, 6) = 3`。在实践中，使用几种不同的界定符号。例如，`[`、`]` 在 Pascal 中用作集合界定符，在 Prolog 中用作列表界定符。

#### 集合枚举与范围

如果一个集合被完全枚举，则顺序无关紧要。然而，自然排序通常提供了一种明显的模式；在这种情况下，部分枚举可以定义该集合。例如，十进制数字集合可以表示为 `{0..9}`，其中 `..` 表示缺失的数字。这里，`0..9` 通常称为**范围**。无限集合可以在一端或两端用 `..` 表示。例如，自然数集合可以表示为 `{1, 2, 3..}`。

#### 外延定义与内涵定义

前面的集合定义完全或部分地枚举了集合的外延，因此是**外延定义**的例子。集合也可以通过**内涵定义**来定义。这里，通过一个仅适用于集合成员的属性来声明*内涵*或含义。也就是说，给出一个描述，该描述构成了一个项目属于该集合的必要且充分条件（即“当且仅当条件”）。

例如，外延定义为 `{1,2,3}` 的集合 *A*，可以内涵定义为 *A* = 小于 4 的自然数集合。该定义可以用集合构造符号重述为 `{x: x is a natural number less then 4}`，或更简略地表示为 `{x: x ∈ ℕ & x < 4}`，其中 `∈` 缩写为“是……的成员”，`ℕ` 是自然数集合。在集合构造符号中，竖线 `∣` 可代替冒号使用，例如 `{x∣ x < 4}`。

#### 命题形成运算符

一些集合运算产生命题，而另一些产生集合。请注意以下**命题形成运算符**：`=`、`≠`、`⊆`、`⊂`、`⊇` 和 `⊃`。它们分别读作“等于”、“不等于”、“是……的子集”、“是……的真子集”、“是……的超集”和“是……的真超集”。

#### 子集与超集

给定任意集合 *A* 和 *B*，我们称 *A* 是 *B* 的**子集**，当且仅当 *A* 的每个成员也是 *B* 的成员。例如，`{1,3} ⊆ {1, 2, 3}`。一个等价的定义是：*A* 是 *B* 的子集，当且仅当 *A* 没有不在 *B* 中的成员。这个第二个定义使得很容易看出**空集**是每个集合的子集。空集没有成员，可以表示为 `{}` 或 `∅`。

每个集合都是其自身的子集。例如，`{1, 3} ⊆ {1, 3}`。我们称 *A* 是 *B* 的*真子集*，当且仅当 *A* 是 *B* 的子集但不等于 *B*。例如，`{1, 3} ⊂ {1, 2, 3}`。我们称 *A* 是 *B* 的**超集**，当且仅当 *B* 是 *A* 的子集；称 *A* 是 *B* 的*真超集*，当且仅当 *B* 是 *A* 的真子集。例如，`{1, 2, 3}` 既是 `{1, 3}` 的超集，也是其真超集。

#### 欧拉图

两个集合之间的比较关系通常用**欧拉图**描绘。由瑞士数学家莱昂哈德·欧拉（Leonhard Euler，1707–1783 年）开发，这些图表具有*空间性*和*存在性*。每个集合被描绘为椭圆内的一组点。这使得集合之间的关系可以通过椭圆的空间排列来“看见”。例如，将椭圆 *A* 放在 *B* 内部表明 *A* 是 *B* 的真子集（参见图 6.1）。在这里，我们看到 *A* 的每个元素也是 *B* 的元素（因此 *A* 是 *B* 的子集）。存在性观点意味着欧拉图中的每个区域都包含一些元素。因此，*B* 有一些不在 *A* 中的元素。因此 *A* 是 *B* 的真子集。
