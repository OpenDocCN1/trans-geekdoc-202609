
它还包含 SGD，一种用于学习各种线性模型（二分类 SVM、二分类逻辑回归和线性回归）的随机梯度下降法，以及 SPegasos，即 Shalev-Shwartz 等人 [226] 提出的 Pegasos（支持向量机的原始估计次梯度求解器）方法的随机变体。

## 9 聚类

聚类是一项*无监督*学习任务，作用于无标签数据。它包含根据实例的共性或亲和性将一组实例分配到不同组中。与分类的主要区别在于，在学习过程开始前组别是未知的，事实上任务正是创建这些组别。聚类的用途包括市场营销中的客户细分和社交网络中的社区发现等。

许多（但非全部）聚类方法基于这样一个假设：实例是某空间中的点，我们可以在该空间上施加距离函数 `d`，且更相似的实例在距离上更近。在许多此类方法中，聚类由该空间中的一组质心点决定。一种更正式的基于质心的聚类定义如下：给定一组属于某空间 `X` 的实例 `P`，`X` 中元素间的距离函数 `d`，以及可选的聚类数 `k`，聚类算法计算一组质心或聚类中心 `C ⊆ P`，满足 `|C| = k`，使其（近似地）最小化目标函数

```
cost(C, P) = Σ_{x∈P} d(x, C)
```

其中

```
d(x, C) = min_{c∈C} d(x, c)
```

即 `x` 到 `C` 中最近点的距离。

如所述，一些算法要求用户指定 `k` 的值，而另一些则自行确定聚类数量。请注意，若取 `k = |P|` 并将每个实例单独分配到一个聚类，会导致代价为 0 的聚类，因此如果 `k` 不受限制，为了获得有意义的结果，将需要对聚类数量施加某种形式的惩罚。

我们首先讨论聚类中的评估问题，并回顾流行的 `k`-means 方法。然后我们讨论三种增量方法，它们或多或少地受到 `k`-means 的启发：Birch、BICO 和 CLUSTREAM。之后，我们将研究两种基于密度的方法，从用于非流数据的 DBSCAN 开始，这引出了用于流式设置的 Den-Stream。最后，我们描述了两种更新的、最先进的基于树的流式聚类方法：ClusTree 和 StreamKM++。我们在结束语第 9.7 节中提供了其他方法的参考和简要讨论。

### 9.1 评估度量

不幸的是，评估聚类不像评估分类器那样明确无误。文献中描述了许多不同的聚类质量度量，也许太多了，它们形式化了“良好聚类”应达到的不同期望。

度量可分为两大类：结构性或内部度量，以及基于真实标签的度量，称为外部度量。第一类严格基于数据点和获得的聚类结果。关于三十种内部度量的广泛研究见文献 [178]，外部度量的其他研究包括 [57, 231, 250]。一些示例如下：

*   **凝聚度：** 数据集中某点到其分配的簇质心的平均距离。越小越好。
*   **SSQ（误差平方和）：** 数据点到其分配质心的平方距离之和。与凝聚度密切相关。越小越好。
*   **分离度：** 某点到分配给其他簇的点的平均距离。越大越好。
*   **轮廓系数：** 粗略地说，是凝聚度与点到其第二近质心的平均距离之比。它奖励那些点非常接近其分配的质心且远离任何其他质心的聚类结果，即具有良好凝聚度和良好分离度的聚类。

另一方面，外部度量需要知道数据点的“真实”聚类，或真实标签，根据定义，这在实际场景中几乎总是未知的。然而，在评估新的聚类算法时，人们通常从已知的生成器创建合成数据集，因此可以将算法获得的聚类与真实模型进行比较。在这种情况下，某些度量类似于分类或信息检索中应用的其他度量：

*   **准确率：** 分配到其“正确”簇的点的比例。
*   **召回率：** 一个簇中实际上被分配到该簇的点的比例。
*   **精确率：** 分配到一个簇且真正属于该簇的点的比例。
*   **纯度：** 在纯度最高的聚类中，簇内的所有点都属于同一个真实标签类别或簇。形式上，纯度为

```
Purity = (1/|P|) Σ_{c∈C} max_{j} |c ∩ j|
```

（簇 `c` 中属于 `c` 的多数类别的点数）：

*   **簇映射度量 (CMM)：** Kremer 等人 [151] 引入的一种度量，专门为演化数据流设计，它考虑到簇随时间的合并和分裂可能会产生表面上的错误。

如果质心保持固定，上述列出的度量可以通过存储固定数量的值轻松增量维护。当质心随时间演化时，我们可以求助于将这些值转化为 EWMA 累加器，或在滑动窗口上进行评估。

`k`-means 假设点集 `P` 是某维度 `d` 下 ℜ^(`d`) 的子集，以便点可以相加和求平均。算法以未指定的方式选择 `k` 个质心开始——例如，随机选择。之后，迭代两个步骤：首先，将每个实例分配给最近的质心；其次，将质心重新计算为分配给它的示例的均值或质心。该过程通常在没有点改变质心时停止，或在执行了最大迭代次数后停止。产生的 `k` 个质心决定了算法找到的 `k` 个簇。

`k`-means 隐含的贪心启发式仅保证收敛到局部最小值，且 `k`-means 找到的解的质量和收敛速度众所周知地取决于初始随机分配步骤。`k`-means++ [19] 通过使用新的初始化步骤，提高了该方法相对于纯随机方法的稳定性：

```
1        choose center c[1] to be p[1]
2        for i = 2,…,k
3              do select c[i] = p ∈ P with probability d(p,C)/cost(C,P).
```

简而言之，初始中心随机选择，但所有后续中心的选择概率与其到已选中心的距离成正比。分散 `k` 个初始簇中心有助于加快收敛速度并达到更好的局部最小值。流式聚类方法 StreamKM++ 也采用了这一策略。

将 `k`-means 转换为流式设置并不直接，因为它需要反复迭代数据集。我们将看到，大多数流式聚类方法有两个阶段，一个在线阶段和一个离线阶段。在线阶段更新数据的统计信息，生成某种形式的摘要或草图，通常表示为称为 `microclusters`（微簇）的少量点。然后离线阶段利用这些摘要高效地计算最终聚类，要么在固定的时间间隔，要么按需进行。

### 9.3 BIRCH、BICO 和 CLUSTREAM

这三种算法是增量式的，并共享一个共同的思想：用微簇来总结数据流，以便在离线阶段对它们进行聚类。

平衡迭代缩减和聚类利用层次结构 (BIRCH) 由 Zhang 等人 [258] 提出。它是第一种提出使用所谓的 `clustering feature`（聚类特征，CF）向量来表示微簇的增量聚类方法。假设数据集点是 `d` 个实数的向量，CF 是一个三元组 (`N, LS, SS`)，由以下项目组成：

*   `N`：CF 中数据点的数量
*   `LS`：`N` 个数据点的 `d` 维向量和
*   `SS`：`N` 个数据点的 `d` 维平方和。

CF 具有以下有用属性：

*   它们是可加的：`CF[1] + CF[2] = (N[1] + N[2], LS[1] + LS[2], SS[1] + SS[2])`。
*   从 CF 很容易计算点到簇的距离、平均簇间距离和平均簇内距离。

BIRCH 的另一个特点是使用 `CF trees`（CF 树），一种类似于经典 `B+` 树数据结构的高度平衡树。它由两个参数定义：分支因子 `B`，即任何给定节点可能拥有的最大子节点数，以及叶子半径阈值 `R`。算法维护这样一个属性：由叶子表示的所有点都落在该处质心半径 `R` 的球内。每个叶子节点和每个内部节点都包含一个 CF 向量。

BIRCH 算法包含多达四个阶段：

> 阶段 1：扫描所有数据并构建初始内存 CF 树
>
> 阶段 2：将 CF 树压缩成一个更小的树（可选）
>
> 阶段 3：全局聚类
>
> 阶段 4：细化簇（可选且离线，因为它需要更多遍数）。

#### 第 2、3 和 4 阶段：离线部分

特别是第 3 阶段，基于 CF 树中收集的信息执行批量聚类。第 1 阶段是在线过程，也是实际作用于数据流的过程。对于每个到达的点，算法会下降树，更新遍历的内部节点 CF 的统计信息，以到达最接近该点的叶节点。然后它检查叶节点是否能在半径 `R` 内吸收该点。如果可以，则通过更新叶节点统计信息将该点“分配”给叶节点。如果不行，则为新点创建一个新叶节点。这个新叶节点可能导致父节点拥有超过 `B` 个子节点；如果是这样，它必须分裂成两个，以此类推，递归地向上直到根节点。此处未描述的另一条规则，会被应用于合并在此过程中可能变得过近的叶节点和内部节点。

#### BICO

**BICO**（“BIRCH meets coresets for `k`-means clustering”，即 BIRCH 结合用于 `k` 均值聚类的核心集）由 Fichtenberger 等人 [101] 提出。它将 BIRCH 的数据结构与用于聚类的核心集理论概念相结合。核心集在 9.6 节中有详细解释。BIRCH 通过启发式方式决定如何将点分组到子簇中。BICO 的目标是找到一个不仅规模小，而且能提供近似原始点集保证的简化集合。

#### CLUSTREAM

**CLUSTREAM** 由 Aggarwal 等人 [6] 提出，旨在作为 BIRCH 的一种自适应扩展，能够处理不断变化的数据流。在 CLUSTREAM 中，CF 树的节点维护形式为 `(N, LS, SS, LT, ST)` 的 CF 向量，这通过两个额外的时间特征扩展了 BIRCH CF：

*   `LT`：时间戳之和
*   `ST`：时间戳平方和

CLUSTREAM 的离线阶段只是定期对 CF 树叶节点处的微簇应用 `k` 均值算法。在线阶段类似于 BIRCH，但它考虑了簇的新近度。它在内存中保持最大数量的微簇。如果一个点需要创建一个新微簇（叶节点）但没有更多可用空间，算法要么删除最旧的微簇，要么合并两个最旧的微簇。“最旧”微簇的概念是通过考虑微簇中是否有显著的近期活动来定义的。更准确地说，统计量 `LT` 和 `ST` 被用来计算其时间戳的平均值和标准差；假设时间戳呈正态分布，算法可以利用它们来决定微簇中所需比例的点是否早于期望的新近度阈值。

由于选择删除的是最旧的簇而不是最小的簇，这赋予了 CLUSTREAM 一个有趣的特性：通过查看具有相似时间戳分布的微簇，我们可以获得所需时间范围内的聚类快照，对更近的时间范围分辨率更高，随着时间推移分辨率逐渐降低。这有时被称为*金字塔式*时间范围。

### 9.4 基于密度的方法：DBSCAN 和 Den-Stream

基于密度的聚类器基于这样一种思想：簇的形成不仅基于距离上的整体邻近性，还基于连接的密度。因此，它们生成的簇可能不是球形的，而是具有适应特定被聚类数据形状的形状。

**DBSCAN** 算法 [96] 由 Ester 等人提出，是最著名的基于密度的离线算法。它基于这样一种思想：簇应该围绕其邻域内拥有大量点的点来构建。以下定义将这一思想形式化：

*   `p` 的 `ε`-邻域是距离 `p` 在 `ε` 或以内的点的集合。
*   **核心点** 是其 `ε`-邻域具有至少 `μ` 总权重（数据集点的比例）的点。
*   **密度区域** 是核心点 `ε`-邻域的并集。
*   如果 `q` 在 `p` 的 `ε`-邻域内，则点 `q` 从 `p` **直接可达**。如果存在序列 `p[1], …, p[n]` 使得 `p[1] = p`，`p[n] = q`，且每个 `p[i+1]` 都从 `p[i]` 直接可达，则点 `q` 从 `p` **可达**。
*   核心点 `p` 与所有从它可达的（核心或非核心）点形成一个簇。
*   所有从核心点不可达的点都被视为 **异常值**。

请注意，簇由其包含的任意核心点决定，并且对于给定的 `ε` 和 `μ` 值，这些定义为任何数据集创建了唯一的聚类。

DBSCAN 算法具有参数 `ε` 和 `μ`，并利用这些属性来寻找这个唯一的聚类。它以任意顺序访问数据集中的点。对于一个先前未访问的点 `p`，它找到所有从 `p` 直接 `ε`-可达的点。如果发现 `p` 是一个 `μ` 核心点，则形成一个新簇，并将所有从 `p` 可达的点添加到该簇中并标记为已访问；否则，如果 `p` 的权重低于 `μ`，则暂时将其标记为“异常值”，并继续处理下一个未访问的点。异常值稍后可能被发现从真正的核心点可达，并被宣布为“非异常值”并添加到某个簇中。

观察可知，DBSCAN 强烈依赖非流式处理，因为每个点可能被反复访问。

**Den-Stream** 由 Cao 等人 [61] 开发，是一种基于与 DBSCAN 相似思想但使用微簇快速计算在线统计信息的基于密度的流式方法。它使用阻尼窗口模型，意味着每个数据点的权重使用衰减函数 `f(t) = 2^(-λt)` 指数级减小，其中 `λ > 0`。

对于一个中心为 `c` 且代表点 `p[1], p[2], …, p[n]`、时间戳为 `T[1], T[2], …, T[n]` 的微簇，Den-Stream 在时间 `t` 维护以下信息：

*   **权重**：`w = Σ_{i=1}^n 2^{-λ(t - T[i])}`
*   **中心**：`c = (1/w) Σ_{i=1}^n p[i] 2^{-λ(t - T[i])}`
*   **半径**：`r = sqrt( (1/w) Σ_{i=1}^n ||p[i] - c||^2 2^{-λ(t - T[i])} )` （实际上，保存的是 `p[i]` 平方和，需要时可由此计算 `r`）

微簇有两种类型：根据权重是大于还是小于 `μ`，微簇被称为 **潜在核心微簇** 或 **异常值微簇**。因此，异常值微簇是尚未（或还没有）拥有足够权重被视为核心的微簇。

**DEN-STREAM** 方法有两个阶段：在线阶段和离线阶段。它们的伪代码如 图 9.2 所示。在在线阶段，每当一个新点到达时，DEN-STREAM 首先尝试将其合并到潜在微簇之一中。如果不可能，则尝试将该点与异常值微簇合并。如果异常值微簇的权重增加到足以成为潜在微簇，则该微簇被提升。否则，DEN-STREAM 启动一个新的异常值微簇。离线阶段包括移除未达到足够权重的微簇，并执行批量 DBSCAN 聚类。

### 9.5 CLUSTREE

迄今为止介绍的流式聚类算法都需要应用离线阶段才能在请求时生成簇。相比之下，**CLUSTREE**（Kranen 等人 [150]）是一种 **随时聚类** 方法，即它可以在任何时间点提供聚类结果。它是一种无参数算法，能自动适应流的速度，并能检测流中的概念漂移、新颖性和异常值。

CLUSTREE 使用一种紧凑且自适应的索引结构来维护流摘要，具有对数插入时间。该结构是一棵平衡树，其中每个节点包含一定数量点的 CF，类似于 CLUSTREAM。这棵树包含不同粒度层级的微簇层次结构。平衡条件保证了对所有微簇的对数访问时间。

当一个新点到达时，CLUSTREE 方法会沿树向下遍历，以找到与该新点最相似的微簇。如果到达的叶节点处的微簇足够相似，则更新该微簇的统计信息；否则创建一个新的微簇。但是，与其他算法不同的是，该过程是可中断的：如果在到达叶节点之前有新点到达，正在处理的点会被暂时存储在当前内部节点的一个聚合中，插入过程随即中断。当稍后有新点通过该节点时，缓冲的局部聚合会作为“搭便车者”被带走并继续向下推送。通过这种方式，CLUSTREE 可以防止在变速流的突发时刻丢失数据点。

### 9.6 StreamKM++：核心集

给定一个问题和一组输入实例 `P`，*核心集* 是一个小的加权子集，可用于近似该问题的解。换句话说，为核心集求解该问题，即可为 `P` 上的问题提供一个近似解。在聚类中，我们可以将 (`k`, 𝜖)-核心集定义为一对 (`S, w`)，其中 `S` 是 `P` 的子集，函数 `w` 为每个点分配一个非负实数值（即权重），使得对于 `P` 的每个大小为 `k` 的子集 `C`，以下条件均成立：

```
cost_w(C) ≤ (1 + ε) cost_P(C)
```

其中 `cost_w` 表示成本函数，其中 `S` 的每个点 `s` 由 `w(s)` 加权。也就是说，在 `P` 上选择的任何可能的聚类，在由 `w` 加权的 `S` 上几乎同样好，反之亦然。因此，在 `S` 和 `P` 上求解聚类问题确实是近似相同的。

StreamKM++ 由 Ackermann 等人 [3] 提出，基于这一核心集思想。它使用第 9.2 节解释的随机 `k`-means++ 算法来创建一组初始种子 `S = {s[1], …, s[m]}`。然后将 `w(s[i])` 定义为 `P` 中比 `S` 中任何其他种子更接近 `s[i]` 的点的数量。文献 [3] 的主要结果之一是，如果 `m` 大致为 `O((k d / ε²) log n)` 形式，则以这种方式定义的 (`S, w`) 以概率 1 − `δ` 成为一个 (`k`, 𝜖)-核心集。此处，`d` 是 `P` 中点的维度，`n` 是 `P` 的基数。对 `n` 的依赖性非常好；对 `d` 的依赖性则不那么理想，尽管实验结果似乎表明该界限关于 `d` 远非紧致。

此外，StreamKM++ 将点放置在一个*核心集树*中，这是一种二叉树，旨在根据 `d` 加速采样。该树以层次结构描述簇，即根节点代表整个点集 `P`，树中每个节点 `p` 的子节点代表 `p` 中示例的一个划分。

StreamKM++ 执行在线和离线两个阶段。在线阶段使用核心集树桶维护大小为 `m` 的核心集。对于包含 `n` 个点的流，该方法维护 `L = ⌈log₂(n/m)⌉` 个桶 `B[0], B[1], ..., B[L−1]`。桶 `B[0]` 可存储少于 `m` 个数，其余桶为空或维护 `m` 个点。每个桶维护一个大小为 `m` 的核心集，代表 `2^(i−1)m` 个点。每当一个点到达时，它被插入第一个桶。如果第一个桶已满，则计算一个新桶，将 `B[0]` 和 `B[1]` 合并为一个新的核心集树桶，并移入 `B[2]`。如果 `B[2]` 不为空，则重复此合并并移动过程，直到到达一个空桶。
