##### BIOS 启动设备/顺序控制

大多数 `BIOS` 提供启动设备启用、禁用和排序功能，应利用这些功能来控制计算机如何启动运行。通常，`BIOS` 为用户和管理员提供下列类型设备的启用或禁用选项：

*   光盘驱动器
*   硬盘驱动器
*   `USB` 设备
*   `SD` 卡
*   `eSATA` 设备

除非有必要例行地从其他设备启动系统，否则除主硬盘驱动器选项外，所有启动选项都应禁用，以提供最佳安全性。

##### Microsoft Autorun 功能

Microsoft 某些版本的操作系统包含一项称为 `Autorun` 的功能，一旦检测到驱动器或读取器中存在介质，它就会自动运行在可移动介质设备上发现的可执行程序。此功能构成了非常严重的安全威胁，因为位于介质上的恶意软件程序可以被设计为自动运行并感染宿主设备。

据统计，在旧版 Windows 系统中，高达 50% 的恶意软件感染归咎于此功能。只需在 Windows 中禁用 `Autorun` 功能（通过下载应用程序将其关闭）即可消除该威胁。另一种替代方案是修改 Windows 注册表以关闭 `Autorun`。

### 移动设备保护

前一章指出，无线传感器和控制网络已在 OT 环境中取得了一些进展。这些传感器和控制设备使用其他移动设备中常见的传统无线技术，例如 `Bluetooth`、`Wi-Fi`、近场通信 (`NFC`) 和蜂窝网络。

Wi-Fi 和蓝牙的传输范围均有限，但在这些范围内，黑客有可能拦截无线连接，或者至少干扰无线连接。当然，这些网络也带来了前文所述的所有漏洞，这使得它们对黑客更具吸引力。

除了无线技术向工业传感器和控制环境迁移之外，企业中也出现了一种日益增长的趋势，即允许员工自带笔记本电脑、平板电脑和智能手机等端点计算设备进入工作场所。在许多情况下，企业还提供 Wi-Fi 接入以适应这种 `自带设备` (`BYOD`) 环境。正如将 OT 网络连接到企业网络为外部人员利用此前相对更安全的 OT 环境开辟了新途径一样，连接到 OT 网络的 `BYOD` 设备敞开了更多的漏洞。

网络管理员和安全人员必须确定这种 `BYOD` 环境是否会给其网络造成安全缺口。例如，与特定 `BYOD` 端点（或其特定配置）相关的漏洞可能使未经授权的用户能够通过该设备访问网络，并利用该连接窃取专有或敏感数据。在这些情况下，组织必须在其风险评估中纳入这些额外的漏洞，以确定其对这类政策和做法的风险接受程度。

### 近场通信

`近场通信` (`NFC`) 是一种短距离无线连接协议标准，可用于在设备彼此靠近时发起通信。通信发起后，另一种无线技术（如蓝牙或 Wi-Fi）可能会接管以执行数据交换。这种高频技术非常适合某些安全应用，因为它要求标签（如 RFID 身份徽章）与读卡设备之间必须近距离接触。这种近距离要求非常重要，因为它可以最大限度地减少未经授权的访问尝试。许多低频（通常为 125 KHz）系统已被用于安全徽章系统。

虽然利用这些系统并非易事，但它们容易被拥有专用硬件和一定技能的人利用。黑客通过靠近佩戴 RFID 徽章的用户，利用自己的读卡器读取目标的徽章信息。一旦捕获到徽章数据，他们就可以制作自己的徽章以绕过访问控制。这可能发生在用户身处食堂、当地咖啡厅，甚至通过藏在办公室或生产设施中的小型 `IIoT 设备` 时发生。

在互联网上并不难找到制作攻击工具的方案，该工具可插入商用 RFID 读卡器（也很容易获取）。在支持任何 `NFC` 系统之前，网络管理和安全人员审查其安全机制至关重要，因为某些系统比其他系统更脆弱。

### 移动设备安全防护

虽然 `移动设备` 的安全顾虑在非 ICS 应用中当然更大，但所有移动用户在使用移动网络以及在工作场所使用移动设备时都应保持谨慎。

*   除非您正在与设备配对且需要此功能，否则请关闭蓝牙自动发现功能。也请留意蓝牙设备上的其他安全选项。
*   避免使用公共热点。但是，如果您确实使用它们，请注意潜在的恶意行为，并使用 `TLS/SSL` 连接，仅在受保护的系统中输入凭据。
*   关闭自动连接（重新连接）到 Wi-Fi 接入点的功能。
*   蜂窝网络不太可能被攻破；当需要高安全性时，请使用蜂窝网络。
*   如果实现了端到端加密，所有无线技术都会更安全。

## 操作系统安全/加固

`操作系统` 是旨在控制和协调计算机系统运行的程序。作为一类，它们无疑是有史以来设计得最复杂的程序之一。在所有基于微处理器的环境中，操作系统从程序或输入源（如计算机用户）接收命令并执行它们以执行某些所需操作。同样，操作系统在近乎同样复杂的软件应用程序和它们运行所在的计算机硬件之间充当中介。

由于操作系统是通往计算机应用程序和数据的电子网关的主要组成部分，您必须了解不同的操作系统通用类型，以及可用于保护它们的工具和技术。

### 文件系统安全

`文件管理系统` 在保护存储在磁盘、光盘或可移动存储设备上的数据的存在性和完整性方面极为重要。如果文件系统被破坏或损坏，数据将变得不可访问并丢失。此外，如果未经授权的用户获得了对文件系统及其存储数据的访问权限，他们就获得了破坏、销毁或窃取数据的机会。

保护文件系统及其数据的主要工具之一是使用 `访问控制列表` (`ACLs`)。文件系统使用 `ACLs` 向特定用户授予或拒绝对其不同文件的访问权限，并控制授予访问权限后个人可执行的活动类型。例如，在文件管理系统的控制下，您可能被赋予运行文件、读取文件、写入文件或对其执行其他操作的能力。

操作系统的 `ACLs` 还用于控制对其他对象的访问，如 `TCP/UDP` 端口以及 I/O 设备。它们的 `ACL` 表维护记录，标识每个用户对特定系统对象拥有的访问权利。

根据操作系统的不同，资源访问控制可以以 `强制访问控制` (`MAC`) 或 `基于角色的访问控制` (`RBAC`) 的形式实现。UNIX 和 Linux 系统通常提供 `MAC` 方法，而 Microsoft Windows 平台提供 `RBAC` 控制。

在 `MAC` 版本中，操作系统决定谁可以做什么以及可以做到什么程度。在 `RBAC` 下，系统根据用户的授权来限制或允许对对象的访问。`RBAC` 结构通常是大型企业采用的访问控制方法。

在 UNIX 和类 UNIX 操作系统中，开发了一套称为 `可移植操作系统接口` (`POSIX`) 的互操作性标准，以标准化 UNIX 版本的变体。符合 `POSIX` 的系统（UNIX、Linux 和 macOS 系统）支持某种类型的 `ACL` 来管理传统的 UNIX 文件访问权限。

在 Microsoft Windows 环境中，这些功能以 `权限` 的形式分配给文件夹和文件。权限也可以被定义为执行某项操作的特权。在基于 UNIX 和 Linux 的系统中，为用户分配文件的 `访问权限`。

保护数据的另一个工具是对其进行 `加密`，使其在没有解密密钥的情况下变得不可用。加密/解密过程可以在数据存储和从设备检索时执行，也可以在数据从一个位置移动到另一个位置时执行。

## 数据加密

加密数据涉及获取数据并使用密钥代码（或 `encryption key`）对其进行处理，该密钥定义了数据的原始（`plaintext`）版本是如何被操作的。此概念在图 4.9 中进行了说明。

![图 4.9 数据加密](img/c04f009.png)

**图 4.9** 数据加密

任何获得加密密钥的人都可以使用它，通过使用解密算法或 `decryption key` 的解密过程来解码消息。没有解密密钥的人无法确定原始数据是什么。

一种特别有效的密钥系统是 `Public Key Encryption`（`PKE`，公钥加密）。该技术采用两个密钥来确保加密数据的安全——一个 `public key`（公钥）和一个 `private key`（私钥）。公钥（人人皆知）用于加密数据，而私钥或密钥（仅指定接收者知晓）用于解密数据。公钥和私钥以这样的方式关联：仅凭拥有公钥无法推导出私钥。

数字设备或网络中的数据加密可以在许多层面发生：

*   作为文件系统级（文件和文件夹级）加密
*   作为磁盘级加密
*   作为传输级加密

大多数主要的磁盘操作系统都通过其文件管理系统提供某种类型的数据加密功能。根据操作系统的设计，加密可以应用于设备级别、磁盘（或卷）级别，或文件和文件夹级别。第三方加密应用程序也可用于这些操作系统中。

不同操作系统可用的数据加密服务将在本章后续部分讨论。数据加密技术在第 5 章“ICS 网络安全要点”中有详细介绍。

启用了 `No-Execute`（`NX`，不可执行）技术的操作系统（该技术在某些微处理器中可用）会将内存的特定区域标记为不可执行，以便这些区域中的任何代码都无法被执行。此功能用于防止某些类型的恶意软件将其代码注入这些内存区域并执行以接管系统。这些攻击被称为 `buffer overflow attacks`（缓冲区溢出攻击），将在下一节中更详细地描述。

操作系统还包含 `isolation mechanisms`（隔离机制），可在主机内存中创建容器，将不同进程相互隔离。这使操作系统能够在与其他进程隔离的情况下运行进程文件系统，并保护其免受意外更改。在 UNIX/Linux 系统中，change root（`chroot`，更改根目录）操作会改变表面上的根目录。在 Windows 操作系统中，`WIN32 API` 负责密码认证、可共享对象的自主保护、访问控制以及操作系统文件系统中的权限管理。

## 文件系统攻击

针对操作系统文件系统的典型攻击包括以下几种：

*   `Race condition attacks`（竞争条件攻击）：当攻击者在多用户/多任务环境中利用连续事件的时序，在事件之间插入恶意代码时，就存在竞争条件。

    例如，当操作系统创建临时文件时，存在 `time of check, time of use`（`TOCTOU`，检查时刻，使用时刻）条件。在操作系统检查该文件名是否存在与实际写入文件之间的时间差内，攻击者执行程序，使用临时文件的文件名保存恶意代码包。

    恶意代码可能包含更高的访问权限，以便攻击者可以读取或操作文件，或者它可能包含指向脚本文件的链接，该脚本文件授予对存储管理员密码的密码文件的访问权限。

*   `Using Alternate Data Streams`（`ADS`，备用数据流）`to hide files`（隐藏文件）：高级黑客利用此 NTFS 操作系统兼容性功能隐藏 rootkit 或其他黑客工具，以建立一个匿名基地来发起对系统的攻击。

    ADS 功能最初内置于 NTFS 中，旨在为 Apple 的 HFS 文件系统提供支持，后者有时会将数据“分叉”到不同的文件中。然而，此技术已被采用用于存储文件元数据和提供临时存储。

    如前所述，黑客利用 ADS 功能将其工具对系统隐藏，因为使用原生用户界面几乎无法检测到。隐藏的 ADS 文件嵌入某个标准操作系统文件后，即可在不被检测为非法操作的情况下执行。ADS 操作的唯一迹象是注入隐藏工具的文件上出现非法时间戳。

*   `Performing directory traversals`（执行目录遍历）：这些攻击利用安全性薄弱的软件应用程序访问本不应可访问的文件，以“遍历”到更高级别的文件夹或目录，如图 4.10 所示。此类攻击也称为 `backtracking`（回溯）、`directory climbing attacks`（目录攀爬攻击）或 `canonicalization attacks`（规范化攻击）。

![图 4.10 目录遍历](img/c04f010.png)

**图 4.10** 目录遍历

黑客利用这种形式的 `HTTP exploitation`（HTTP 漏洞利用）访问 Web 服务器的目录树。获得访问权限后，他们可以浏览目录树以查看受限文件或在服务器上执行命令。此类攻击使用常见的 Web 浏览器针对配置不当的 Web 服务器发起。通过仔细的 Web 服务器配置、过滤 Web 浏览器输入以及使用 `vulnerability scanner`（漏洞扫描器）软件，可以最大程度地减少此类攻击。

## 文件系统加固

尽管文件系统是操作系统的一部分，但仍可使用一些特定于文件系统的技术来改进或加固文件系统安全性。

*   第一步是如果可能，在整个组织中采用标准化的文件系统。
*   考虑将引导/系统文件与共享目录和数据分离，方法是将它们放置在每台服务器和用户计算设备的不同分区中。
    *   对于 Windows 系统，将引导和系统文件放在 `C:\`，将共享文件放在其他驱动器（如 `D:\` 或 `E:\`）中。
    *   对于 Linux 系统，更改 `/etc/fstab` 中的挂载选项以限制用户访问。此外，用户可写目录（如 `/home`、`/temp`、`/var` 和 `/temp`）应挂载在其他分区上。
*   从引导/系统分区以及包含不应共享信息的任何其他分区中移除任何隐藏共享功能。
*   对于关键文件夹和文件权限，使用单独分配的权限，而不是基于角色的访问控制选项。仅对真正需要跨组共享的信息使用 RBAC 选项。RBAC 和其他逻辑访问控制策略将在本章后面讨论。
*   在可用的情况下采用文件和文件夹加密选项。
*   为对组织运营最关键的文件夹和文件建立定期审计和报告机制。

## 操作系统安全选择

由于其普及度，Microsoft Windows 成为恶意和恶作剧性质的恶意软件及灰件编写者的最大攻击目标。因此，Windows 承受了与病毒和间谍软件相关的绝大多数攻击。

这一事实导致一些 Windows 客户转向其他操作系统平台，如 Linux 或 macOS，它们成为恶意软件目标的可能性要小得多。表 4.2 总结了与各种操作系统相关的常见安全功能。

### Linux SystemV 与 Systemd

#### 现代 Linux 发行版

现代 Linux 发行版基于两种基本设计之一——`SystemV` 和 `Systemd`。`SystemV` 是一个较旧的平台，可追溯到最初的 Linux，而 `Systemd` 是一个较新的平台，许多 Linux 发行版已迁移至此。Systemd 设计提供了更快的启动速度和更好的依赖管理。

Systemd 采用现代系统服务管理器，负责管理在后台运行并为其他程序提供功能的 `daemons`（守护进程）。其中一些守护进程用于监控安全事件并提供警报。它们还提供安全功能，用于将服务和应用程序与底层操作系统隔离，以及彼此隔离。

Red Hat、CentOS、Fedora、Amazon、Debian、Ubuntu 和 Mint 等组织已在 Systemd 平台上构建其 Linux 发行版。基于 SystemV 架构的发行版包括 Alpine、Slackware 和 Linux from Scratch。

## 操作系统加固

如前所述，防御本地计算机系统免受攻击的第二层级是保护其操作系统。这涉及在开发人员发现操作系统的易受攻击代码段后对其进行更新。操作系统加固通过应用服务包、补丁和更新形式的新编程来实现。

### 服务包
