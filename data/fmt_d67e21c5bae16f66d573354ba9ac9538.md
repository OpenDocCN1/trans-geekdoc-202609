
内存泄漏是应用程序没有释放其分配且不再需要的内存的结果。内存一直是某些标准库中常见的编程错误。问题发生在应用程序无法正确释放已分配内存时。虽然泄漏最初可能很小，但随着时间的推移，程序泄漏会越来越多，内存可能会出现症状从性能下降到内存耗尽并死机。内存泄漏在某些语言中比其他语言更容易。例如，在 C 编程语言中，你使用`malloc`函数分配内存，可能忘记调用`free`。

# 整数溢出

整数溢出发生在程序或应用程序尝试在变量中存储大于该变量类型可以处理的数字时。考虑一种分配的缓冲区可以容纳最大到 65535 的值。如果有人超过此值并尝试在无符号整数类型中存储大于最大值的值，则只剩下余数——例如，65535 + 1 = 0。因为超过了最大值，该值实际上会绕回 0。如果结果值用于计算，可能会导致某些异常行为。一个很好的例子如图 5.5 所示。

## 竞态条件 (TOC/TOU)

竞态条件是一种通常针对时机的攻击形式。其目标是利用检查时间（TOC）与使用时间（TOU）之间的延迟。这些攻击有时被称为异步攻击。这是因为攻击者试图在对象存储之后、系统使用它之前对其进行更改。

竞态条件被认为是应用安全测试中最难检测的应用问题之一。竞态条件最好在流程早期（即代码审查期间）识别出来。竞态条件也很难利用，因为攻击者在成功之前可能需要尝试多次利用竞态条件。

竞态条件会防止保护系统正常运行，或拒绝向合法用户提供资源可用性。例如，写入数据库的速度比另一个应用程序处理数据的速度，导致错误数据被写入并发生错误情况。

如果程序员的代码按照给定的顺序处理互斥锁资源，并按相反顺序解锁资源，就可以消除竞态条件。

## 资源耗尽

资源耗尽是一种拒绝服务（DoS）技术，发生在执行某操作所需的资源被完全消耗时。这阻止了所需操作发生。资源耗尽的影响是正常操作和通信的破坏。很多时候，攻击者实现这一点比访问系统或应用程序更容易。此处列出的内容是为了说明这些工具多年来是如何使用的。这些攻击大部分在今天已不再有效，对于较新的资源耗尽攻击，通常使用负载均衡器来提供集中防御。

- Smurf 攻击：通过发送指向广播地址且将受害者地址列为源的伪造数据包来利用互联网控制消息协议（ICMP）。

- SYN 洪水攻击：通过发送大量设置了 SYN 标志的伪数据包来中断传输控制协议（TCP）连接。大量的半开 TCP 连接填充了受害者系统上的缓冲区，导致资源耗尽。

- 死亡 Ping（Ping of Death）：超大数据包是非法的，但当分片在另一端重组为完整数据包时是可能的，这会导致旧系统上的缓冲区溢出。

- 水滴攻击（Teardrop）：发送格式错误的数据包，其分片偏移值导致接收的数据包重叠。受害者不知道如何处理这些重叠的分片，导致系统崩溃或死锁，引起拒绝服务。

- Land 攻击：在 TCP SYN 包中发送源端口、目的端口及 IP 地址相同的包。由于系统不知道如何处理此类流量，CPU 使用率会被推高至 100%，所有现有资源被消耗。

- Trinoo：向受害者发送大量不需要的流量。在 20 世纪 90 年代，Trinoo 攻击者很容易使用且非常强大，它可以泛洪目标系统并消耗所有可用带宽。

> 洪泛过滤器（Flood guards）可保护网络免受经典的下游 DoS 攻击、VoIP 服务器和 SIP，以及更现代的 DoS 威胁，例如低轨道离子炮（LOIC）。

## 安全评估与渗透测试

安全评估是指对组织的网络、策略和安全控制措施进行系统性检查。安全评估用于确定安全措施的充分性，识别安全缺陷，并提供数据以预测潜在安全措施的有效性。安全评估可以采用不同的方法和技术。

## 测试方法

CASP 考试要求你了解各种安全评估测试方法，以便你能够完全应对提出的任何挑战。安全评估可以分为以下几类：

**安全审计**：安全审计是对 IT 系统进行的独立审查和检查，以确定控制措施的充分性。安全审计还查看现有策略及其如何映射到操作程序。

**漏洞评估**：漏洞评估通常利用 Nessus、Saint 和 Retina 等自动化工具。这些工具可以检查系统、应用程序和设备，评估其控制措施并报告其安全水平。漏洞评估工具每周或每月运行一次，以发现可能未安全或缺少关键补丁和软件更新的系统。

**渗透测试**：渗透测试旨在以对抗的方式查看网络。渗透测试可以回答诸类问题，例如如果攻击者针对公司，他们可以看到什么信息，以及攻击者可以使用这些信息做什么。渗透测试侧重于寻找“唾手可得的果实”，并查看计算机犯罪在网络上可以实现什么。

## 渗透测试步骤

渗透测试遵循与攻击者使用的类似的标准方法论。主要的区别是渗透测试是在没有恶意且获得目标公司许可的情况下进行的。在渗透测试开始之前，客户和渗透团队会面讨论测试目标。它可能被设计为检查外部或内部、有或无访问权限、访问和利用。一旦完成了首次会议，团队将制定一份供客户审查的合同；一旦所有人都同意条款，渗透测试即可开始。

> 在开始渗透测试之前完成的最关键步骤是获得书面许可。你还应该有一个公司联系人（POC）和一封授权测试的信。这在现场进行测试时尤为有价值。

- 1. 迹迹（Footprinting）：此步的目的是检查关于目标公司可用哪些信息。

- 2. 扫描：这一步包括端口扫描和操作系统指纹识别。常用 Nmap 和 Zenmap 等工具。

> 学习计算机系统上运行哪些 Web 服务的一种良好方法是 Telnet 打开端口并寻找返回的任何 banner，这种技术被称为 banner 抓取（banner grabbing）。例如，你会输入 `www.mysite.com 80`。

- 3. 获取访问权限：这一步是渗透测试团队尝试访问目标网络的时刻。方法可能包括社交工程学、利用弱密码、木马和键盘记录器。

- 4. 使用技术提升权限：虽然获取访问有所帮助，但渗透测试团队必须成为系统、root 或管理员权限以获得完全控制。用于完成此任务的技术可能包括缓冲区溢出、SQL 注入或 XSS。

- 5. 维持访问权限：系统可能会被修补，漏洞可能会被发现，或者安全漏洞可能会被注意到。这一步是渗透测试团队试图维持其访问。这可以通过创建账户、规划后门或创建加密隧道来实现。

- 6. 隐藏踪：一旦完成测试目标，团队将移除放置在网络上的任何项目，恢复系统并移除任何剩余代码。

- 7. 确定建议：这是过程中团队开始对发现的结果进行最终审查的点。通过会议和审查，团队开始确定他们的建议。

- 8. 编写报告并展示结果：最后一步是创建报告。报告列出了发现的漏洞和风险。报告还列出了关于管理、技术和物理控制措施的建议

# 保持客户知情

在进行渗透测试时，一项关键任务是让客户保持知情。在整个过程中，应该让客户随时了解团队的发现，以确保报告中不会出现意外。

# 评估类型

渗透测试有不同的方法。根据情况以及你的雇主或客户的需求，评估可能会以几种方式之一进行。这些包括以下内容：

**黑盒测试**。在黑盒测试中，对目标网络或系统的了解非常少或完全没有。黑盒测试模拟了外部人员攻击，因为外部人员通常对他们正在探测的网络或系统并不了解多少。渗透测试必须在开始测试之前收集有关目标的所有类型信息。团队在尝试渗透网络并开始分析其优劣势之前，通常会验证 IP 地址是否正确。在黑盒测试中，公司的人员不应该知道自己正在接受测试。这提供了额外的优势，可以确定监控、检测和响应策略的执行情况以及这些策略的有效性。

![](img/7868547987f5920cfe632b85047c64af_338_0.png)

> 白盒/灰盒/黑盒方法论也应该从公司 IT 和安全人员的视角参考情况。

**白盒测试**。白盒测试采取与黑盒测试相反的方法。白盒评估是指渗透测试对网络、系统和基础设施有完全的了解。这些信息允许渗透测试遵循更具结构化的方法。白盒测试和黑盒测试之间的另一个大区别是，黑盒测试通常花费更多时间收集信息，而白盒测试则将这些时间花在探测漏洞上。

**灰盒测试**。灰盒方法意味着对设备的了解有限，例如掌握一些代码知识。

了解更多渗透测试过程的一种良好方法是花些时间审阅《开源安全测试方法论手册》（OSTMM）。OSSTMM 是一个安全评估框架，详细列出了所需的活动和时机。它可以在 `www.isecom.org/osstmm.html` 找到它。

# 漏洞评估领域

并不是所有的安全评估都是相同的；对于每项单独评估，可能会审查不同的领域。常见的评估领域包括以下内容：

- **拒绝服务**。DoS 测试查看公司抵御潜在 DoS 攻击的能力。某些组织可能还会通过此来检查网络在重负载或高利用率下的运行情况。此类测试的目标通常包括评估 DoS 攻击的影响、确定网络性能，以及衡量受攻击设备的影响。

- **无线网络**。无线网络在今天的网络中发挥的作用比以往任何大得多。毕竟，它们易于设置、易于使用且无需电缆。无线评估检查组织的网络。它解决诸如是否使用了加密、如果是，是什么种类型以及是否可以被破解等问题。无线测试还检查 DoS 攻击、地址解析协议（ARP）中毒和中间人攻击的风险。

无线网络不仅仅是 WiFi 和 802.11b/g/n。它可能包括蓝牙，甚至更冷门的协议，如 HVAC 系统中的 Zigbee。还有无线射频识别（RFID），它被用于从大型连锁店的标签到建筑访问控制的员工证的一切地方。

- **电话**。测试语音系统不仅涉及传统的电话系统。电话测试包括对 IP 语音（VoIP）、PBX 和所有语音线路的检查。现代系统中仍连接有计算机，以供供应商访问特种系统（例如 HVAC），以及供网络人员准备的应急备份远程访问。每个领域对公司都可能至关重要。例如，如果公司的 PBX 被黑入，它可能会遭受工具欺诈、收入损失，甚至机密信息丢失。

- **应用程序和安全代码审查**。有时，安全评估可能不会侧重于网络、防火墙、内部人员甚至外部人员。毕竟，代码是允许应用程序和软件满足我们共同组件。即使在部署良好且安全的网络中，脆弱的应用也可能让公司的资产暴露在攻击者面前。安全代码审查是对应用程序进行检查，旨在识别和评估对组织造成的威胁。

安全审查假设你拥有了被检查应用程序的所有源码。有时，你可能没有代码，或者外部库或组件等项目无法访问。在没有代码的情况下，可以使用黑盒测试技术，以及如安全粗审（RATS）和 Flawfinder 等工具。无论情况如何，关注的领域包括由用户提供的初始数据等项目。用户提供的任何值都必须检查以确定其是否有效。所有输入、处理的数据、正在存储或处理的值以及输出数据都必须检查。

![](img/7868547987f5920cfe632b85047c64af_340_0.png)

CASP 候选人应该理解在源码不可用时黑盒测试的重要性。

# 社会工程测试

社会工程学是欺骗某人向你提供你不应拥有的信息或访问权限。如果你被要求作为安全评估的一部分执行社会工程测试，有一些常见的领域需要审查。这些包括帮助台、现场员工和承包商。作为一种攻击向量，社会工程学是最危险的攻击之一，因为它不直接针对技术。拥有良好的防火墙、入侵检测系统（IDS）和边界安全意义不大，因为攻击者可以使用社会工程技术（语音钓骗）拨打帮助台并索要密码。社会工程是危险的，因为它针对的是人。社会工程也可以基于计算机。

物理测试涉及对公司物理控制的检查。这包括锁、门、围栏、保安、身份认证。

## 足迹探测工具

评估的第一步是足迹探测。足迹探测确定有多少信息暴露在外部以及其潜在的损害。我喜欢将足迹探测视为老式的侦探工作。它关乎将你收集的信息碎片组合在一起。足迹探测通常分为类：主动侦察和被动侦察。

**主动侦察 (Active Reconnaissance)** 以某种主动方式与目标交互，例如拨打目标公司要求参观。

**被动侦察 (Passive Reconnaissance)** 以被动方式与目标交互，例如查看目标公司的网站或查看其招聘公告。

开始被动侦察的好地方是目标的网站。某些公司在网站上泄露了这么多信息，以及攻击者如何利用这些信息，这令人惊讶。电子邮件地址可以用于网络钓鱼，员工姓名可以用于社会工程，或者地理位置可以用于物理攻击。公司必须考虑它们在网站上公开内容的安全影响，尽管这始终是在寻找平衡。公司还会在招聘公告中发布大量信息，例如所使用的技术类型。虽然安全评估团队可能不会花费几周进行足迹探测活动，但他们可能会花费几个小时或一天。

为了了解你在业务网站上可以找到的信息类型，请花时间回顾练习 5.3。

## 练习 5.3

对你的公司或其他组织进行被动侦察

花费 20 到 30 分钟对你的组织进行足迹探测，看看有哪些信息是公开的。

1. 访问公司网站，寻找联系人姓名、电子邮件地址和电话号码。

2. 使用 `www.domaintools.com` 等 whois 工具对你的公司进行 whois 查询，查看谁被列为联系人。是通用名称还是真实人的信息？

3. 搜索公司的招聘列表，并查找有关使用了哪些技术的信息。职位要求是否列出了特定的微软、苹果或思科技术或产品？

4. 访问 `www.sec.gov` 并搜索你公司的财务上市信息。是否存在任何记录？它们列出了利润和收入吗？

5. 访问 `http://toolbar.netcraft.com/site_report?url=undefined#last_reboot` 并搜索你的公司网站运行的是什么。列出了服务器版本和类型吗？它们正确吗？

渗透测试团队在足迹探测期间可能访问的其他网站包括

### 招聘网站

这些网站可以用来发现组织使用的设备类型。

### 财务记录

可以通过 Hoovers (`www.hoovers.com`)、邓氏直信 (`www.dnb.com`) 和美国证券委员会 (`www.sec.gov`) 对上市公司进行搜索。此类记录包括人员、董事成员和高级高管的姓名和地址；财务数据；有关收购或剥离行业的信息。

### 旧网站

Internet 时代存档网站托管了 Wayback Machine (`http://wayback.archive.org`)。它是一个网页目录。

### 社交媒体

社交媒体可以包括 LinkedIn、Facebook、推特、维基、播客。社交媒体的一个问题是隐私，渗透测试期间应检查这些网站。如果你不认为社交媒体是问题，考虑以下：

- 检查端口 探测 使用 TCP 和 UDP 端口扫描，以判断是否被防火墙拦截，端口是开放的还是关闭的。

- 探测 探测  是一个建立的 Facebook 个人资料。

- 我们知道你在做什么 一个建立的 Facebook 个人资料以收集数据。

- TCP FIN 探测 向目标端口发送一个 FIN 数据包。关闭端口应该发送一个 RST。

- TCP ACK 探测 尝试确定规则集或识别是否在使用无状态检查。如果返回 ICMP 目标不可到达消息（类型 3 代码 13），则该端口被视为过滤。
