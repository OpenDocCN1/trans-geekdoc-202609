## 更通用的公式

读者可以发现，根号符号下的项是对应属性距离平方的和。¹ 这一观察在数学上的表达如下：

![image](img/image457.png)![image](img/image135.png)`dM(x; y) = sqrt(∑(i=1 to n) d(xi; yi))` (3.2)

![image](img/image118.png)![image](img/image372.png)![image](img/image632.png)在离散属性和连续属性混合的向量情况下，通常是这样计算距离的（在符号中，`dM(x; y)` 由下标 `M` 表明）。例如，对于连续属性，我们可以使用 `d(xi; yi) = (xi - yi)²`，而对于离散属性，如果 `xi ≠ yi`，我们令 `d(xi; yi) = 0`，如果 `xi = yi`，则令 `d(xi; yi) = 1`。

![image](img/image112.png)![image](img/image063.png)注意，如果所有属性都是连续的，则公式与欧几里得距离相同；如果所有属性都是离散的，该公式仅规定了两个向量不同的属性数量。在纯布尔域中，对于任何属性，只允许取 `true` 或 `false` 值（我们将这些值分别缩写为 `t` 和 `f`），后一种情况被称为汉明距离 `dH`。例如，向量 `x = (t; t; f; f)` 和 `y = (t; f; t; f)` 之间的汉明距离为 `dH(x; y) = 2`。然而，通常情况下，公式 (3.2) 用于由离散和连续属性混合描述示例的领域。

## 属性间的距离可能具有误导性

我们必须小心不要机械地应用公式 (3.2)，而忽略给定领域的特定方面。让我们简单讨论一下两种容易出错的情况。

![image](img/image613.png)假设我们的示例由三个属性描述：尺寸、价格和季节。其中，前两个显然是连续的，最后一个一个是离散的。如果 `x = (2; 1.5; summer)` 和 `y = (1; 0.5; winter)`，那么公式 (3.2) 给出了这两个示例之间的如下距离：

![image](img/image474.png)![image](img/image726.png)`dM(x; y) = sqrt((2 - 1)² + (1.5 - 0.5)² + 1) = sqrt(3)`

![image](img/image112.png)让我们先考虑第三个属性：夏季不同于冬季，我们之前的考虑引导我们建立了 `d(summer; winter) = 1`。

实际上，夏季和冬季之间的差异有时被认为大于夏季与秋季（例如，它们是“相邻季节”）之间的差异。然而，另一种逻辑可能会说服我们，春天和秋季比夏季和冬季更相似——至少从天气角度而言。我们可以看到，0 和 1 这两个值在这里显然是不够的。也许应该考虑中间值，具体选择取决于给定应用程序的特定需求。不关注此类因素的工程师可能获得良好的结果。

![image](img/image525.png)![image](img/image223.png)混合连续和离散属性在另一个方面也存在风险。不加思考地应用公式 (3.2) 可能会导致这种情况：两个尺寸之间的距离（在基础版本中不能超过 1）。这一观察与缩放问题密切相关。

正如预期的，所有正样本都位于沿“水平”属性两个临界点界定的阴影区域内：温度超过最大值的表示发烧；低于最小值的表示体温过低。然而，对于“垂直”属性，我们看到正样本和负样本都分布在整个范围内，鞋码无法揭示关于个人健康状况的任何信息。我们想要分类的对象位于高亮区域，根据常识，它应该被标记为正样本——尽管它的最近邻居恰好是负样本。

### 经验教训

如果只使用第一个属性，两个示例之间的欧几里得距离为 `dE(x; y) = sqrt((x1 - y1)²)`。如果两个属性都使用，且其中一个属性是无关的，那么项 `(x2 - y2)²` 就是多余的——然而，它会对 `k-NN` 的相似性概念产生不利影响！这就是图 3.3 中发生的情况，这也是为什么对象 1 被误分类的原因。

## 属性值的尺度问题

假设我们想要评估两个示例 `x = (t; 0.2; 254)` 和 `y = (f; 0.1; 194)` 的相似性，它们由三个属性描述，其中第一个是布尔值，第二个是范围在 `[0, 1]` 间的连续值，第三个是范围在 `[0, 1000]` 间的连续值。使用公式 (3.2)，读者会发现很容易计算 `x` 和 `y` 之间的距离，得到如下：

![image](img/image451.png)

```
dM(x; y) = sqrt((1 - 0)² + (0.2 - 0.1)² + (254 - 194)²)
```

![image](img/image507.png)![image](img/image370.png)

检查这个表达式，我们注意到第三属性完全占据主导地位，使另外两个属性变得几乎微不足道。无论我们如何在其范围内修改它们的值，距离 `dM(x; y)` 也几乎不会变化。幸运的是，这种情况很容易纠正。如果在训练集中，将第三属性的所有值除以 1000，从而将其范围“压缩”到 `[0, 1]`，那么属性的影响将变得更加平衡。我们可以看到，属性值的尺度可以从根本上影响 `k-NN` 的行为。

### 属性缩放的另一个方面

还有更多内容。考虑以下两个训练示例 `ex1` 和 `ex2` 以及我们想要确定类别的对象 `x`：

`ex1 = (10; 10); pos`
`ex2 = (20; 0); neg`
`x = (32; 20)`

![image](img/image481.png)![image](img/image292.png)![image](img/image292.png)

距离为 `dM(x; ex1) = 58` 和 `dM(x; ex2) = 44`。后者较小，`1-NN` 将 `x` 标记为 `neg`。然而，假设第二个属性表示温度，并且使用的是摄氏度。如果我们决定改用华氏度，那么三个向量将变为：

`ex1 = (10; 50); pos`
`ex2 = (20; 32); neg`
`x = (32; 68)`

```
dM(x; ex1) = 88
dM(x; ex2) = 40
```

此时前者较小，`1-NN` 将 `x` 标记为 `pos`。

### 属性归一化

有一种方法可以轻松解决这种情况。在训练集中，将所有属性的值缩放到并归一化到 `[0, 1]`，这样属性的影响将变得更加平衡。我们可以看到属性值的尺度可以从根本上影响 `k-NN` 的行为。

### 属性缩放的另一个方面

问题不仅于此。归一化在许多应用中可以减少误差，特别是当属性尺度差异很大。缺点是示例的描述被扭曲了。此外，将所有值限制在 0 到 1 之间的做法可能并不合理。例如，如果夏季和秋季之间的差异总是大于两个归一化的体温之间的差异。这取决于工程师的常识，可能还需要一些实验。
