
回想一下，表的列名必须唯一。如果 `A` 和 `B` 没有共同的列名，则 `A` ⨉ `B` 使用 `A` 和 `B` 的简单列名。如果 `A` 和 `B` 不同但有一些共同的列名，则 `A` ⨉ `B` 中对应的列通过使用*限定名*（带前缀“`A`.”或“`B`.”）来唯一引用。但是，如果 `A` 和 `B` 相同（即我们希望形成一个表与自身的笛卡尔积）怎么办？

考虑图 12.6 中的 `Person` ⨉ `Person` 表。这打破了表中列名必须唯一的规则。在这种情况下，仅使用限定列名也无法解决问题，因为我们将会有两个名为“`Person.firstname`”的列和两个名为“`Person.gender`”的列。

#### 关系选择

我们现在考虑 Codd 引入的四种表运算。第一种是选择（或*限制*）。不要将其与 SQL 的 **`select`** 命令混淆。在关系代数中，选择运算仅选取满足指定条件的那些行。直观上，我们可以将该运算描绘为返回一个*水平*或*行*子集，因为它从原表返回零行或多行（参见图 12.8）。

![图 12.8 关系代数中的选择运算。](img/f12-08-9780443237904.jpg)

图 12.8 关系代数中的选择运算。

选择运算可以使用 `T` **`where`** `c` 形式的表达式来指定。这里，`T` 表示一个*表表达式*（即值为表的表达式），`c` 表示一个*条件*。选择运算仅返回条件评估为 True 的那些行，过滤掉条件评估为 False 或 Unknown 的行。“**`where`** `c`”部分称为 *`where` 子句*。

这种表示法鼓励自顶向下的思维（先找到相关表，再担心行），并与 SQL 语法一致。另一种表示法 `σ``c` 常用于学术期刊。“`σ`”是西格玛，希腊字母“`s`”（“selection”的首字母）。

在图 12.9 中，`Player` 表存储了关于网球运动员的详细信息。要列出仅男性网球运动员的详细信息，我们可以按图示制定此选择，得到所示结果。这里，选择条件只是等式：`gender` = ‘M’。对“M”使用单引号表示该值字面上是字符 ‘M’。引用字符串值（如 ‘David’）时也使用单引号。数值不应加引号。尽管选择产生的表未命名，但其列与原表同名。

![图 12.9 选择运算选取满足条件的那些行。](img/f12-09-9780443237904.jpg)

图 12.9 选择运算选取满足条件的那些行。

条件 `c` 可包含六种*比较运算符*中的任意一种：`=`（等于）；`<>`（不等于）；`<`（小于）；`>`（大于）；`<=`（小于或等于）；和 `>=`（大于或等于）。有时表运算的结果是一个空表（参见空集）。例如，没有行满足 `Player` **`where`** `height` > 180 中的条件。

如果条件不涉及与空值的比较，它们就是布尔表达式——评估结果为 True 或 False。如果条件确实包含与空值的比较，则改用三值逻辑，因此条件可能评估为 True、False 或 Unknown。这也是 SQL 中发生的情况。无论哪种情况，选择运算仅返回条件为 true 的那些行。条件评估为 false 或 unknown 的任何行都会被过滤掉。

除了比较运算符，条件还可包含三种*逻辑运算符*：**`and`**、**`or`**、**`not`**。像往常一样，**`or`** 运算符是包含性的。作为练习，制定一个查询来列出身高低于 170 cm 的女性详细信息。参考 `Player` 表，看看你能否陈述结果，然后与图 12.10 核对答案。为了提高可读性，保留字采用粗体显示。

![图 12.10 这个查询需要括号吗？](img/f12-10-9780443237904.jpg)

图 12.10 这个查询需要括号吗？

图 12.10 中的查询使用括号来阐明运算顺序。然而，对于复杂表达式，大量的括号会使事情看起来非常混乱（参见 LISP）。与几种编程语言（如 Pascal）不同，大多数查询语言（如 SQL）赋予*比较运算符比逻辑运算符更高的优先级*。因此，出于评估目的，运算符 `=`, `<>`, `<`, `>`, `<=`, `>=` 的优先级高于 **`not`**、**`and`** 和 **`or`**。我们在关系代数中做出相同的选择，因为这减少了复杂表达式所需的括号数量。理解这一点后，图 12.10 中的查询可以更简洁地重写为：

```
Player where gender = ‘F’ and height < 170
```

#### 关系投影

下一个表操作称为 **投影**，在 第 4 章 中已介绍。此操作涉及 *从表中选择一个或多个列*，然后 *消除可能产生的任何重复行*。它被称为产生 *垂直子集* 或 *列子集*。图 12.14 说明了两列上的投影。

![Fig. 12.14 关系代数中的投影操作。](img/f12-14-9780443237904.jpg)

图 12.14 关系代数中的投影操作。

我们可以将投影操作表示为 `T [a, b, …]`，其中 `T` 是一个表表达式，`a, b, …` 是所需列的名称（此列列表称为 *投影列表*）。为了界定投影列表，我们使用方括号而不是圆括号，因为后者在查询中有其他用途（例如，更改操作的计算顺序）。将方括号“`[ ]`”斜体化有助于将它们与用于界定可选项、包或指示额外任务（选择列后的重复消除）的“[ ]”区分开来。

替代符号 `πa,b…` 在学术期刊中很常见。“π” 符号是 pi，希腊字母 “*p*”（"projection" 的首字母）。像 SQL 一样，此符号在表之前列出所需的列。我们首选的符号则通过在列出列之前先确定相关表来鼓励自顶向下的思维。

图 12.15 基于表 `Player` (name, gender, height) 给出了两个示例。当在单个基本表上投影时，如果所选列包含候选键，则不会产生重复行。如果不包含，则可能出现重复。例如，仅选择 gender 列会得到包 `["M", "F", "F", "M"]`。为了完成投影，消除重复值，得到集合 `{"M", "F"}`。如果我们投影所有列，最终会得到相同的表。例如，Player `[name, gender, height]` 与 Player 是同一个表。

![Fig. 12.15 投影涉及选取列并移除任何重复项。](img/f12-15-9780443237904.jpg)

图 12.15 投影涉及选取列并移除任何重复项。

投影中不得两次提及同一列。例如，Player `[name, name]` 是非法的（为什么？）。投影也可用于以不同顺序显示列。例如，Player `[height, gender, name]` 反转了顺序。因为结果中列出了唯一的列名，这不会改变含义。

如果关系模式完全规范化，基本表兼容并（union compatible）的情况相当少见（前面考虑的 Eats 和 Likes 表是个例外）。因此，∪、∩ 和 − 操作几乎专门用于因投影而变得兼容并的结果表。

我们现在来看一些稍微困难的例子。为了便于讨论分步处理此类情况的方法，我们使用 **关系赋值** 操作。因为它们的内容可能变化，表模式可被视为 *变量*。事实上，表是关系代数中允许的唯一一种变量。关系赋值操作严格来说独立于代数本身，类似于编程语言中的赋值。使用符号 “:=” 表示 “变为” 或 “被赋值为”，我们可以编写如下形式的赋值语句。

```
table variable := table expression
```

这是一个指令，要求先计算右侧的表达式，然后将其值放置在左侧命名的变量中。如果该变量之前有值，旧值将直接被新值替换。例如，如果 `X`、`A` 和 `B` 是表值，那么语句 `X := A := B` 意味着 `X` 被赋予 `A - B` 的值。其他一些表示法使用 `=` 或 `⟵` 代替 `:=`。

一旦在关系赋值中命名，结果表可以在后续表达式中像基表一样使用。例如，要将高个子男性球员的详细信息存储在名为 `TallMalePlayer` 的表中，我们可以进行以下三次赋值。要列出这些详细信息，我们现在只需使用查询 `TallMalePlayer`。

```
MalePlayer := Player where gender = 'M'
TallPlayer := Player where height > 175
TallMalePlayer := MalePlayer ∩ TallPlayer
```

作为一个更复杂的例子，考虑 图 12.16 的 UoD。我们如何用关系代数表达以下查询：哪些非欧洲国家说法语？在继续阅读前请尝试自己解答。

![Fig. 12.16 Conceptual and relational schemas, with sample population.](img/f12-16-9780443237904.jpg)

图 12.16 概念模式和关系模式，包含示例数据。

我们可以分步表述查询，在获得最终结果表的过程中使用中间表。例如：

```
NonEuroCountry := (Location where region <> 'Europe') [country]
FrenchSpeakingCountry := (SpokenIn where language = 'French') [country]
FrenchSpeakingNonEuroCountry := NonEuroCountry ∩ FrenchSpeakingCountry
```

在这里，我们的第一步是找到非欧洲国家：{Australia, Canada}。然后我们找到说法语的国家：{Belgium, Canada, France}。最后，我们取这些集合的交集，得到结果：{Canada}。

以这种方式列出查询被称为**逐步表述**。分阶段进行有时可以更容易地表述困难的查询。然而，用单个表达式表达查询可以节省一些书写工作。例如，刚才考虑的三个赋值语句可以用以下方式替换：

```
FrenchSpeakingNonEuroCountry :=
    (Location where region <> 'Europe') [country] ∩
    (SpokenIn where language = 'French') [country]
```

赋给 `FrenchSpeakingNonEuroCountry` 的冗长表表达式被称为**嵌套表述**，因为它将一个或多个查询嵌套在另一个查询内部。对于复杂查询，我们可能在脑海中或草稿纸上进行逐步表述，然后将其转换为嵌套表述。一般来说，任何能够通过一系列关系代数查询提取的信息，都可以在单个关系代数查询中指定。

请注意，投影不分配过交集。换句话说，给定表 `A` 和 `B` 以及投影列表 `p`，`(A ∩ B)[p]` 可能不等于 `A[p] ∩ B[p]`。例如，以下查询与前一个不等价（为什么？）。

```
((Location where region <> 'Europe') ∩ (SpokenIn where language = 'French')) [country]
```

该查询是非法的，因为 `∩` 的表操作数不兼容。即使 `A` 和 `B` 兼容，投影也不一定分配过 `∩` 或 `-`。如果 `A` 和 `B` 兼容，投影确实分配过 `∪`，即 `(A ∪ B)[p] = A[p] ∪ B[p]`。作为练习，您可能希望证明这些结果。

#### 关系连接

概念层面的对象连接在第 4.4 节中引入，以帮助阐明外部唯一性约束的含义。我们现在考虑两个表（或同一表的两次出现）之间的关系连接操作，它使用比较运算符（`=`、`<`、`>`、`<>`、`<=`、`>=`）比较表中的属性值。

有几种连接操作，这里我们只讨论其中一些。任何连接操作中被比较的列必须定义在同一域上；它们不需要具有相同的名称。在需要区分具有相同局部名称的连接列时，我们使用它们的全限定名称。

设 `Θ` (theta) 表示任意比较运算符（`=`、`<` 等）。然后，表 `A` 和 `B` 在 `A` 的属性 `a` 和 `B` 的属性 `b` 上的 `Θ-连接` 等于笛卡尔积 `A ⨉ B`，限制在 `A.a Θ B.b` 的那些行上。我们如下所示书写此操作。大括号中显示的是一种替代的学术表示法。

```
(A ⨉ B) where c           {or A ⨝[c] B}
```

用于表达表之间属性比较的条件 `c` 称为**连接条件**。连接条件可以是复合的（例如 `a1 < b1 and a2 < b2`）。由于笛卡尔积，结果表的列数等于 `A` 和 `B` 列数之和，但由于选择操作，它通常比连接表的行数乘积少得多。

在大多数连接中，使用的比较运算符是 `=`。此时 `Θ-连接` 称为**等值连接**。因此，将 `A` 的列 `a` 中的值与 `B` 的列 `b` 中的值相等的 `A` 和 `B` 的等值连接是 `A ⨉ B` 限制在 `A.a = B.b` 的行上。如果每个表中的连接列名称不同，则无需用表名限定它们。我们如下所示书写此操作。一般来说，连接条件可能包含多个等式。

```
(A ⨉ B) where A.a = B.b

or

(A ⨉ B) where a = b       { if a, b occur in only one of A, B }
```
