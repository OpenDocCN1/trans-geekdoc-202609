
# Substack 第 8 周：我们需要的机器学习现在无处不在吗？

发布于 2021 年 3 月 19 日

正如你读到的标题“我们需要的机器学习现在无处不在”，你们中的一些人看了一眼 Apple Watch。你不必费力寻找，就能在日常生活中看到机器学习的应用。多年来，人们一直在论证机器学习无处不在 [1]。现在，如果机器学习在你的日常生活中已变得如此显而易见，你只能想象它在商业世界中渗透得有多深 [2]。几乎每个供应商、每个应用程序和每项底层技术都在投资机器学习和人工智能的某种组合 [3]。这创造了一些有趣的局面：机器学习模型以意想不到的方式复合且相互干扰地运行。是的，我为最后那句话感到自豪。我致力于探讨模型如何既能复合又能相互干扰。这或许只是用啰嗦的方式说：要么模型产生了有效结果，要么产生了冲突。

## 我们已到达这样一个阶段：企业可能不了解组织内运行的所有不同机器学习要素

我们已到达这样一个阶段：企业可能不了解组织内运行的所有不同机器学习要素。它们甚至可能相互冲突。聊天机器人可能试图快速回答简单问题并以极低摩擦结束对话。另一个机器学习要素可能正在运行，评估组织能为客户提供哪些选项、机会或建议，而那整条对话线可能永远不会被触发。你必须记住，定向优化算法可能与参与度策略背道而驰。你也可能拥有复杂工作流的不同部分、程序或要素，它们沿途以截然不同的目的和结果运行。这种相互纠缠的依赖关系将给你的整体机器学习战略带来灾难。这很可能是机器学习战略失败或根本不存在真实战略的证据。

# Substack 第 9 周：基于规模评估机器学习用例价值

发布于 2021 年 3 月 26 日

本周我们将直接切入主题：基于规模评估机器学习用例价值。你会发现，在增加价值方面，规模几乎是一切。能够快速扩展机器学习解决方案以在工作流中提供价值，通常是收益开始加速的地方 [1]。极少有案例显示仅靠少量交互就能带来大部分价值。那些可能是机器学习尚未准备好处理你业务中如此关键部分的用例。有时将机器学习应用于某个用例并非通往成功的可行路径 [2]。你必须评估并投资于具有高潜在 ROI 的机器学习用例。从工作中获得的价值将直接与 ROI 对齐。

## 从概念上讲，我一直将机器学习用例的类别细分为三大类

从概念上讲，我一直将机器学习用例的类别细分为三大类：

- **“可调用的事物”**，如外部 API 服务
- **“可驻留的场所”**，或你可在其中构建版图的生态系统，如 `AWS`、`GCP`、`Azure`，以及许多其他为机器学习运营（`MLOps`）交付而涌现的平台
- **“自行构建的事物”**，如开源和自研工具解决方案

这种分类有助于我思考用例相关的事情将发生在何处。这是一个战术层面而非战略层面的问题。这三大类将在本系列后续文章中获得更多覆盖 [3]。就 API 服务而言，你可以非常快速地扩展。你现在就可以出去，在 `AWS`、`Azure` 或 `GCP` 上获取多种 API 机器学习解决方案的访问权限，几乎没有任何真正的障碍。进入这种外部技术驱动用例的摩擦水平相对较低。说真的，这些解决方案确实是低摩擦选项，后端拥有高度可扩展的基础设施。人们现在到处都在使用它们 [4]。

# 机器学习部署路径的分歧

在机器学习领域，存在一个分岔路口：如何评估机器学习用例的价值，这在一定程度上将用例分为了两类。

## 开箱即用的云 API 方案

您有大量开箱即用的选项，只需基于云 API 端点提供的模型进行少量配置和设置即可使用。当然，您需要建立连接并建立商业关系，但总体而言，这是大规模入门机器学习领域最简单的方式。这些解决方案并非高度定制化的部署，并且从一开始就包含了一定的按交易计费成本。

## 自建模型部署方案

或者，您可以构建并提供自己的模型，而不必求助于基于云的 API 机器学习解决方案。这意味着开箱即用且可扩展的解决方案与需要一定程度的初始和持续投资的高度定制化部署之间存在天然冲突。

# Substack Week 10: 面向小样本 GPT-2 的模型可扩展性

**发布日期：2021 年 4 月 2 日**

您可能已经听说过生成式预训练转换器模型，或在过去一年的新闻文章中读到过它。它在发布时引起了相当大的轰动。让我们深入探讨，从一个问题开始：“什么是 GPT-2 甚至 GPT-3？” 让我们先了解一些关于小样本学习究竟包含什么的基础知识，随后再研究它如何与 GPT-2 相关联。

您可能知道，小样本学习是一种方法，它获取一个构建完善且定义明确的模型，仅使用少量训练数据通过尝试几次来实现有利的结果 [1]。基本上，您是基于少量数据进行预测。网上有更好的表述方式并已免费分享，您稍微搜索一下就能找到，但我认为这为探讨主题的第二部分奠定了基础。

我对 OpenAI 的 GPT-2 和 GPT-3 模型项目都非常感兴趣 [2]。它们是以预测性语言建模为目标设置的 GPT 模型。这是一套非常有趣的技术，基于其在实践中所承诺的潜力，吸引了我的注意力以及许多其他人的关注 [3]。目前 GPT-3 的提供方式是，您可以通过 API 部署以功能性方式调用模型，并能获得非常有趣的结果。您只需给它一个提示或一小段文本，它就准备好输出内容。人们担心 GPT-3 可能会创造出近乎无尽的内容流，变得如此普遍以至于挤占所有其他相关内容。这可能是首次通过泛滥内容流发起的“拒绝内容攻击”。它可能创建独特的内容，以至于过滤和拦截方法难以轻易遏制。

完全基于调用 GPT-2 或 GPT-3 生成式语言模型的机器学习工作流部署，目前可能尚未达到生产就绪状态。模型可能会输出一些奇怪而有趣的东西，除非这正是您想要的用例，否则它可能还没准备好输出帮助台类型的文档或可直接面向客户的内容。考虑到模型偶尔会产生的惊人结果，那可能是一个非常糟糕的计划。

您可以访问 OpenAI 网站，深入了解他们试图用语言模型做什么。大型语言模型的影响才刚刚开始从研究演示转向商业实现 [4]。人们正在谈论它们，用例在理论上开始堆积，但在实践中尚未完全落地。如果这些内容还不够您消费，也许可以去了解一下 BERT [5]。

# Substack Week 11: 什么是机器学习规模？机器学习使用的地点与时机

**发布日期：2021 年 4 月 9 日**

本周的主题正是我为今年演讲季准备的演示文稿的核心。无论您觉得它是否引人入胜，都请将其视为我对深入理解这一主题极感兴趣的证明。我投入了时间研究它，并认为值得在正式演讲中与他人分享。

当您坐下来思考机器学习时，大量的炒作扑面而来，而少许真相藏身其中。某个业务驱动的用例将存在于某个工作流中。在该工作流中，某种可定义且可重复的任务将受益于机器学习，以推动某个拐点。也许是一个简单的推荐引擎，又或许您需要弄清照片或文本块中的内容以触发某种动作。一次或几次执行可能只是一个有趣的小概念验证（POC）来设置和执行。但要解决细节，使其一次又一次地在成百上千万次执行中运行，则完全是另一码事。

大规模执行机器学习模型——无论是通过调用 API 还是托管模型——都将暴露边缘情况和意外后果。这必然会发生。您认为非常契合且将以高准确度执行的事物，将面临现实世界的挑战，问题随之而来。您必须为此做好准备，拥有一种有计划的方法，将事物控制在预先规划的容差范围内。这就是您如何确保 ROI 路径行之有效，而不是让一个严重的性能问题击垮您整个财务用例。人们开始真正谈论在现实世界机器学习案例中扩展的重要性 [1]。

# ML 规模问题：策略、分桶与阶段

## 第一部分：启动阶段：规模究竟是什么？

从概念上讲，我将机器学习用例的类别细分为三个桶：

**桶 1** 是最简单的，因为你只需去获取并使用它。你只需连接到它，发送一些信息出去并获取一些信息回来，然后就可以开始工作了。

**桶 2** 关乎你可以完全身处其中以构建业务版图的生态系统。`AWS`、`Azure` 和 `GCP` 以及许多为 `MLOps` 交付而涌现的其他平台——我确实是指很多其他的——已准备好为你提供生态系统。你开始看到除了三大巨头之外的其他生态系统。它们正在涌现，并将提供不同的工作流，在不同的地方部署你的机器学习模型并快速切入该领域。

现在是第三类，即 **桶 3**，这是你自行构建东西的地方。这些是开源和自研工具解决方案。我试图让这个桶稍微大一点，因为我觉得很多工作都是从这里开始的。几年前，这是主要阵地，现在我们正看到一种转变。我们看到向其他桶的移动。那些 API 如此易于获取，你可以进入这些生态系统并快速上手。事物正在移动和变化。这三个桶的分类帮助我思考用例目前处于何处，以及未来将在何处发生。这是一个非常战术性的问题，而非战略性的。

要看到随机森林中树木之外的战略，需要一点透视。有时更容易锁定并专注于一个特定项目，而忘记了该项目如何融入更广泛的战略。拥有一个自上而下应用的有针对性的机器学习战略，有助于确保正确的高管赞助和资源专注于取得成果。与其运行一堆独立的自我孵化工作，不如拥有一个可定义、可复用的流程来推广，并有助于确保相同的方法能以具有成本效益的方式在组织内复制。话虽这么说……当然你需要一个机器学习战略。

所以这不仅关乎三个桶以及你在做什么、在考虑什么。它关乎你如何组织这份推介。你的机器学习战略必须能够告诉人们你试图完成什么，以及它将为组织带来什么。

现在，如果你要出去分享那个机器学习战略，并试图让组织投入他们宝贵的资金支持你的战略，你很可能是在谈论预算层面的投资。那笔预算级投资将要求你做一些有承诺的事情。

这些承诺可能包括机器学习支出的预算级 KPI。我该如何管理？我该怎么做？嗯，你早就知道那将是一个 KPI 综合体，包含 ROI。所以我从一开始就在整个过程中构建这些指标，以便跟踪、建模并准确理解我的机器学习战略部署中将发生什么。这样做是为了让我能在各个层面沟通成功——或者在某些情况下，你可能会遇到一些需要重新调整并向人们解释你在做什么的失败。但你的 KPI 综合体将能够构建那种沟通策略，让你取得成功。

在你完成前面这四件事之后，然后且仅然后，你才能转向开始进行一些机器学习用例交付。那才是有趣的部分，对吧？当你开始交付机器学习用例时，你会很快发现，你将需要一个持续的 `MLOps` 战略，以便维持并继续做所有你在申请资金获得预算级承诺时所承诺的事情。
