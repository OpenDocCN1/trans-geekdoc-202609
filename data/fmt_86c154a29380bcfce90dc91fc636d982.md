
- **反恶意软件** 为了防范其他形式的恶意软件，您应该安装反恶意软件。大多数情况下，反恶意软件也是您的防病毒软件。

- **端点检测和响应 (EDR)** `端点检测和响应` 是一种安全技术，用于监控端点设备上的活动和事件，将从端点设备收集的数据发送到中央数据库，分析收集的数据，并从数据中识别任何潜在的网络安全威胁。当 `EDR` 软件识别到威胁时，它会通知客户端采取何种行动来缓解威胁。

- **DLP** 您在 第 5 章 中了解了 `数据丢失防护 (DLP)`，简而言之，`DLP` 是一种可实施的解决方案，它将监控敏感数据向组织外部的泄露并防止其发生。例如，您可以在电子邮件软件中实施 `DLP` 解决方案，防止员工在电子邮件地址中共享信用卡号码（或其他敏感数据）。

- **基于主机的防火墙** `基于主机的防火墙` 是安装或启用在计算机系统上的防火墙软件，旨在控制哪些流量可以到达该系统。例如，如果您网络上有一台旨在向客户端提供网页的内部网服务器，您可以在该系统上启用 `基于主机的防火墙`，仅允许 `HTTP` 或 `HTTPS` 流量到达该系统。这是一种保护该系统免受恶意流量侵害的方法，例如黑客进入网络，或者网络上存在恶意软件。另一个应使用 `基于主机的防火墙` 的示例是将笔记本电脑连接到不受信任的网络（如无线网络或酒店网络）时。例如，如果您有出差住酒店的员工，您希望在该员工的笔记本电脑上启用 `基于主机的防火墙`，因为酒店网络被视为不受信任的网络。

- **基于主机的入侵检测系统 (HIDS)** `基于主机的入侵检测系统` 通过查看系统上的日志和事件来确定该系统是否遭受攻击。入侵检测系统会发出潜在入侵发生的通知，但不会尝试纠正问题。

- **基于主机的入侵防御系统 (HIPS)** `基于主机的入侵防御系统` 类似于 `HIDS`，因为它能检测系统上的潜在攻击，但它可以采取纠正措施，例如阻止来自导致可疑流量的 IP 地址的连接。您将在本章后面了解更多关于 `HIDS` 和 `HIPS` 的信息。

- **下一代防火墙 (NGFW)** `下一代防火墙` 是一种常规防火墙，它能过滤流量，并执行深度包检测（检查数据包的有效载荷），还包含类似于 `IPS` 中的入侵防御功能。

### 启动完整性

攻击者获取敏感公司数据的常见方式是找到丢失的笔记本电脑或窃取笔记本电脑，然后从位于可启动介质（如可启动 USB 驱动器或 DVD 驱动器）上的其他操作系统启动。一旦启动到他们自己的操作系统，黑客就可以浏览随笔记本电脑附带的驱动器上的文件（假设未加密）。为了帮助防止此类攻击，您应该使用全盘加密，但也可以使用系统的启动完整性功能来验证启动环境未发生变化（从 USB/光盘启动即是改变启动环境）。以下是一些可用于确保启动完整性的解决方案：

- **启动安全/统一可扩展固件接口 (UEFI)** `安全启动` 是 `UEFI` 类型 BIOS 系统的一项功能，可检测启动环境是否发生变化。如果启动环境已更改，`安全启动` 功能将停止启动过程。启动环境通过存储启动文件的哈希值并在启动时验证这些值来进行验证。

- **度量启动** `度量启动` 与 `安全启动` 类似，它在允许系统启动前验证启动环境的完整性。`度量启动` 通过将启动文件的哈希值存储在系统上的 `可信平台模块 (TPM)` 芯片中来实现这一点。

- **启动证明** `启动证明` 是指系统向远程系统证明在该系统上运行的软件的可信度。请注意，这与 `安全启动` 或 `度量启动` 略有不同，因为软件已经在运行并已通过验证，系统正在证明该验证。

## 数据库

# 敏感数据的安全解决方案

Security+ 考试要求你了解数据库中用于敏感数据的安全解决方案。这包括令牌化、哈希和加盐。

### 令牌化

令牌化是指敏感数据存储在令牌服务中，而不是与使用该敏感数据的应用程序数据存储在一起。令牌服务还为该敏感数据提供一个无关的替代值。然后，令牌服务存储敏感数据与无关值之间的映射关系以供将来参考，以便在需要时查找。例如，网站进行在线购物时可能会使用以下步骤：

1. 网站提示用户输入信用卡号。

2. 当用户输入信用卡号时，网站联系位于安全网络上的令牌服务，并将信用卡号提供给令牌服务。

3. 令牌服务创建一个用于购物的替代号码，并将其发送给网站，以便与电子商务数据库中的客户数据一起存储。

4. 令牌服务在令牌服务数据库中存储真实信用卡号与替代值的映射关系。

5. 当用户稍后进行购买时，电子商务应用程序将替代值提供给令牌服务，以便其检索真实的信用卡号。

这种令牌化和令牌服务的好处在于，电子商务数据不存储信用卡号——它是通过令牌服务检索的。令牌化系统及其数据库（确实存储信用卡号）位于一个受限的安全网络上，只有网站（和任何其他授权应用程序）可以访问。这降低了信用卡号泄露的风险，因为如果电子商务网站和数据库被黑客攻击，信用卡号不在那里，而令牌服务数据库位于另一个受限的网络上。

![Image](img/exam.jpg)

> **针对 Security+ 考试，请记住：应使用令牌化来保护信用卡号等敏感数据，以便以安全的方式重复使用信用卡。**

### 哈希

你在 第 2 章 中已接触过哈希，但为了复习，哈希是指将数据通过哈希算法运行以生成哈希值。哈希的用途之一是密码存储。系统不会以明文形式将用户密码存储在数据库中，而是可能将密码通过哈希算法运行，然后将哈希值存储在数据库中。这样，如果有人入侵数据库，他们就不会看到明文密码。

那么，如果数据库中不存储密码的明文版本，身份验证在这种情况下是如何工作的呢？很简单！当用户登录系统时，他们提供的密码将使用相同的哈希算法进行哈希以生成哈希值。然后将尝试密码的哈希值与认证数据库中的哈希值进行比较，如果匹配，系统就知道提供了正确的密码。

这种技术的问题在于密码破解工具的工作原理——它们从密码列表文件（称为字典文件）中获取单词，将单词通过哈希算法运行，然后将每个哈希值与数据库中的哈希值进行比较，直到找到匹配项。

### 加盐

为了防止哈希密码被破解，可以使用的一种技术是*加盐*，即获取一个随机值，将其添加到明文值中，然后对加盐值 + 密码的组合进行哈希，并将其存储在数据库中。该盐值也单独存储，以便当用户登录时，其密码与存储的盐值结合，然后进行哈希。如果生成的哈希值与数据库中存储的哈希值匹配，则用户通过身份验证。

![Image](img/exam.jpg)

> **针对 Security+ 考试，请记住：应使用哈希结合加盐来保护数据库中存储的密码。**

加盐可以防止在不知道盐值的情况下破解哈希密码，并确保只有在应用程序逻辑执行以包含盐值时才能进行身份验证。

# 认证目标 7.02

## 实施基于主机的防火墙和 HIDS

创建安全环境的一个重要部分是确保每个单独的系统都经过安全配置——这包括台式机、服务器、移动设备，特别是员工在不同网络环境间漫游时使用的笔记本电脑。

### 基于主机的防火墙

应在系统上配置的第一个安全应用程序之一是基于主机的防火墙，也称为个人防火墙。基于主机的防火墙是一款控制系统入站和出站通信的软件。如今，大多数网络在网络边界都有防火墙来控制进出网络的流量，但你也应该在工作站和服务器上配置基于主机的防火墙。

我发现大多数网络管理员不会在网络内的所有工作站和服务器上配置基于主机的防火墙，我能理解他们为什么不这样做。在网络内的所有系统上配置基于主机的防火墙会使远程连接这些系统和排查问题变得困难。在企业环境中，基于主机的防火墙应允许适当的入站流量。

也就是说，某些系统安装并配置基于主机的防火墙很重要。例如，如果你有经常出差的员工，并在酒店或机场网络上连接公司笔记本电脑，则应为该系统配置基于主机的防火墙，以保护系统免受这些网络上恶意活动的侵害。

![Image](img/exam.jpg)

> **针对 Security+ 考试，请记住：连接到不受信任网络（如酒店网络或任何无线网络）的系统应受基于主机的防火墙保护。**

你也可以在特定服务器上安装基于主机的防火墙，以确保与该服务器的通信仅限于防火墙允许通过的流量类型。例如，如果网络上有一台 FTP 服务器，且 FTP 是该服务器的唯一用途，则可以启用基于主机的防火墙，仅开放 FTP 端口，以保护服务器免受任何恶意流量的侵害。

大多数基于主机的防火墙具有许多通用功能，如下所列：

- **阻止入站流量** 可以阻止从网络或互联网上的主机发送到系统的数据包。

- **阻止出站流量** 可以阻止从系统发出前往网络或互联网的数据包。

- **通知** 大多数基于主机的防火墙可配置为在有人尝试连接到你的系统，或你的系统上的程序尝试在网络或互联网上发送数据时显示消息，如 图 7-1 所示。

- **默认规则** 一旦启用，大多数防火墙都有一条拒绝所有流量的默认规则，除非你允许流量进入。你可以将默认规则更改为允许所有流量，除了你指定的数据包，但这极少采用。

- **创建规则** 大多数防火墙允许你在默认规则之上添加规则，以自定义允许或拒绝进入或离开系统的流量。

### 配置概述

配置基于主机的防火墙时，通常安装软件（如果由第三方公司提供），或启用防火墙（如果使用随操作系统附带的防火墙软件）。

启用防火墙后，它通常会有一条默认规则：拒绝所有流量，除非该流量是对防火墙所在系统发出的请求的响应。例如，启用 Windows 防火墙时仍可浏览互联网，因为你通过输入网站 URL（实际上是发送 HTTP GET 请求）来请求网页，因此响应（即网页内容）被允许通过防火墙。

如果你在系统上托管服务，则需要在基于主机的防火墙上打开端口，以允许这些请求通过。例如，若要通过远程桌面访问服务器且已启用基于主机的防火墙，则需打开远程桌面端口（TCP 端口 3389）。

虽然它不是真正的防火墙功能，但 **TCP Wrappers** 是 Linux 中另一个出色的访问控制功能。`TCP Wrappers` 允许你控制对 Linux 系统上运行的不同服务（如 Telnet、SSH 和 FTP）的访问。`TCP Wrappers` 功能易于实现，因为你只需配置两个文件：

- **/etc/hosts.allow** 此文件列出你希望允许客户端访问的不同服务，并指定哪些客户端可以访问这些服务。

- **/etc/hosts.deny** 此文件列出你希望拒绝客户端访问的不同服务，并允许你指定哪些客户端被拒绝访问这些服务。

对于这两个文件中的每一个，你都可以为允许客户端访问的服务添加规则（如果服务配置在 `hosts.allow` 文件中），以及为不允许客户端访问的服务添加规则（如果服务配置在 `hosts.deny` 文件中）。通常通过 IP 地址或 DNS 名称来允许或拒绝对不同系统的访问。

当客户端连接到特定服务（如 Telnet）时，Linux 系统会读取 `hosts.allow` 文件以确定该客户端是否被允许访问该服务。如果 `hosts.allow` 文件中没有该服务的规则，则会读取 `hosts.deny` 文件以查找规则。如果在任一文件中都不存在与该客户端匹配的服务规则，则尝试连接该服务的客户端将被授予访问权限。

作为使用 `TCP Wrappers` 的示例，我将编辑 `hosts.deny` 文件，指定拒绝所有系统访问 FTP 服务。要为此规则配置该文件，我添加一行新内容，输入服务名，加一个冒号（`:`），并列出该规则适用的客户端，如下面的代码所示：

```
# 示例：拒绝所有客户端访问 FTP 服务
vsftpd: ALL
```
