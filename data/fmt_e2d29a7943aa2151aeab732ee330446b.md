
Учение в счастье украшает， а в несчастьи утешает。 俄罗斯谚语：“学习是幸运中的点缀，是不幸中的慰藉。”（Mertvago, 1995）。在上一章中，我们讨论了不同类型的渗透测试实验室，包括个人和企业级。我们还探索了书中练习所需的渗透测试实验室配置是怎样的。在本章中，我们将更详细地讨论实验室设计，并探讨练习渗透测试技能的几种不同方法。我们已经讨论过未经许可的情况下攻击目标的伦理问题，因此为了论证起见，我们假设所有对真实目标的攻击引用都是在法律和伦理允许范围内进行的。真实目标提供了学习黑客技巧的绝佳机会，因为它们是学习黑客所花费资金和时间的合理理由。然而，真实世界的服务器很难获得（即使通过合法渠道），这就是为什么渗透测试实验室如此重要。实验室提供了一个训练场地，可以在那里犯错、吸取教训并精炼技能。遗憾的是，渗透测试实验室可能昂贵，并且可能无法反映真实目标。我们将讨论真实攻击与实验室场景之间的差异，以便我们有效管理学习黑客的成本和时间。某些应用程序被开发用于在受控环境中学习渗透测试技术。我们将识别那些可以在实验室使用的、模拟包含可利用漏洞的真实服务器的应用。我们还将识别有助于专业渗透测试人员提高技能的 Web 挑战以及黑客大赛。恶意软件分析是渗透测试可能的用途之一。本章还将讨论如何从互联网获取恶意软件，以及如何在受控且安全的情况下分析恶意二进制文件。

# 开箱方案对比真实目标

无论某人是在大型全球性公司的渗透测试团队，还是刚刚在公寓的空房间里起步，并不重要。对于那些拥有公司资金支持的人，练习目标通常是内部系统，或已签约渗透测试的客户系统。对于那些没有“现成”系统的人，目标必须临时凑出来，希望从中能学到有价值的东西。在本节中，我们将讨论在实验室环境中学习进行渗透测试相关的问题，并查看开箱方案和真实目标的优缺点。

## 学习黑客的问题

为了最好地描述学习黑客的问题，我想分享一下我自己的个人经历。当我第一次想学习如何攻击计算机系统时，我发现有几本书可以指导我如何进行渗透测试。然而，我确实在互联网上发现了大量的渗透测试工具，以及许多使用这些工具的示例。我很快发现，尽管有许多工具和示例，我无法在网上找到任何合法的目标来练习。那时，我决定需要一个自己的渗透测试实验室。作为一个电脑极客，我自然有很多闲置的额外系统。我拿了一个旧系统，加载了没有打补丁的`Microsoft NT`。我安装了微软的`IIS` Web 服务器并创建了一个非常无聊的 Web 页面，以便我有东西测试。我对目标运行了`Nessus`扫描，发现`Microsoft NT`确实存在可利用漏洞。我启动了`Metasploit`来利用发现的漏洞之一。果如其然——我进入了系统，并获得了管理员权限。然后我修改了 Web 页面以证明我可以篡改它，并且成功了。之后，我坐下来思考我刚才做了什么。然后我嘲笑自己，我什么都没学到——我攻击了一个我已知有漏洞的机器，并使用了完成所有工作的工具。在他们看来，这是一次毫无意义的尝试。我知道我自己的个人经历已经根据 [Heorot.net](http://Heorot.net) 论坛上的帖子被多次上演。根本问题在于，一个人无法创建一个可以让自己从中学习的渗透测试场景。通过开发渗透测试场景，创建者会自动知道如何利用系统；唯一的学习方法是针对他人创建的场景进行练习。学习任何东西都必须存在不确定因素。直到最近，还没有可以练习的开箱方案。这种情况在过去几年里发生了变化，进入专业渗透测试领域的人可以在比以前安全得多的环境中学习攻击技术。

## 真实场景

使用真实世界的服务器学习黑客是有风险的。如果操作失误，拥有该服务器的公司可能会遭受财务损失。即使没有产生损失，也有很大可能发生疏忽，导致系统漏洞未被识别。由于`learning`一词意味着渗透测试工程师可能没有足够的知识来识别所有漏洞，因此不能假设发现结果是准确或完整的。在某些情况下，公司会为渗透测试人员提供生产测试实验室。这些实验室通常与生产系统非常接近，可以为渗透测试团队提供一个无风险的培训机会。遗憾的是，生产实验室非常昂贵，而且实验室的可用性通常有限；生产实验室通常忙于测试新的补丁、软件和硬件。允许渗透测试人员在实验室中进行练习通常被分配到非常低的优先级。使用生产测试实验室的一个更严重的障碍是，网络和系统管理员通常不希望渗透测试工程师攻击他们的系统，即使在实验室里也是如此。在实验室中的任何发现都会让实验室所有者面临巨大的压力，要求他们增加测试系统和生产网络的安全性。除了额外的工作负载，安全发现可能会让实验室所有者觉得自己也成了目标，并被针对了。他们可能认为任何发现都会反映他们作为网络或系统管理员的水平。为了有效地允许渗透测试人员在生产测试实验室或针对生产系统进行练习，资产所有者与渗透测试团队之间存在高水平的沟通与合作，并且高层必须支持这项工作。在个人实验室中使用真实目标也是可能的。真实世界的漏洞几乎每天出现在新闻中；在某些情况下，可能可以使用相同的软件和硬件在实验室中重建事件。复制真实事件的缺点是，并不总是能够完全重现事物。公司不愿讨论攻击的细节或被利用网络的详细信息。重建真实事件通常是最好的猜测，并且可能不包括安全事件中发现的防御措施，如防火墙和入侵检测系统。大型公司中的可利用漏洞通常会通过多种防御措施得到缓解，由于没有在实验室中包含这些防御，学习体验会受到损害，因为在没有防火墙和入侵防御系统的情况下，利用系统通常更容易。如果有人试图理解针对公司的真实漏洞利用的全貌，必须也识别网络防御措施；在许多情况下，导致安全泄露的不仅仅是一个漏洞系统。

# 开箱场景 (Turn-Key Scenarios)

如所述，现在创建的开箱渗透测试场景比过去要多。结果是更多的人能够学习如何安全地进行渗透测试。开箱渗透测试场景的缺点是它们只是`imitate`真实服务器，但可能并不忠实。大多数开箱解决方案专注于渗透测试中的一个特定方面。`Foundstone`和`WebGoat`服务器集中于结构化查询语言（`SQL`）和基于 Web 的漏洞，而`Damn Vulnerable Linux (DVL)`专注于 Linux 操作系统（`OS`）攻击。`De-ICE LiveCD`服务器试图模拟可利用的应用程序和配置漏洞，而`pWnOS`提供了各种可用于脚本攻击的应用程序。所有这些场景都模拟了真实事件，但可能无法反映今天的真实环境。尽管有这些缺点，开箱场景仍然是学习如何进行渗透测试的首选方法。测试服务器可以快速重建（特别是使用`LiveCDs`和虚拟机时），并且通常提供说明文档，当用户卡住时，文档会引导他们完成漏洞利用。尽管这些开箱解决方案专注于几个不同的攻击向量，但它们通过包含在现实情况中见过的漏洞来挑战用户；它们可能无法反映在专业渗透测试中遇到的所有组件，但它们确实提供了关于渗透测试如何演变的接触。结合正式的方法论培训，开箱场景有助于学习执行专业渗透测试所需的基础知识和中间技能。目前，渗透测试实验室仅有少数基于实验室的场景。有很多网站提供模拟的 Web 攻击，例如`SQL`攻击、目录遍历和 Cookie 操纵；虽然 Web 漏洞攻击是一项关键技能，但它只是开展全面渗透测试项目的一个小部分。对于那些在有现有生产目标供训练的公司工作的人，请认为自己是幸运的。对于大多数人来说，我们必须依靠创建自己的场景，或者寻找预先制作的场景。以下是一些较著名的开箱场景，可以使用它们进行练习以学习渗透测试技能。

## 什么是 LiveCD？

`LiveCD`是一种可启动光盘，包含一个完整的操作系统，能够运行服务和应用程序，就像安装在硬盘上的服务器一样。然而，该操作系统自包含在 CD 中，不需要安装到你的计算机硬盘上即可工作。`LiveCD`在运行时既不会改变你系统当前的操作系统，也不会修改系统硬盘；`LiveCDs`可以用于不包含硬盘的系统上。`LiveCD`不改变任何内容，因为它从内存中运行一切——它也将所有目录都挂载到内存中。因此，当系统“写入数据”时，它实际上是将该数据保存在内存中，而不是某些存储设备上。当我们使用完随附 DVD 中包含的任何`LiveCDs`后，只需拔掉光盘，重启系统，就会回到原始的操作系统和系统配置。虽然我们在整本书中都会提到`LiveCDs`，但另一个选项是使用`Live USB`闪存。优存盘可以包含与`LiveCDs`相同的文件，并且启动方式与`LiveCDs`类似；`Live USBs`比`LiveCDs`的优势在于优存盘上的数据可以轻松更改并持久化。有关下载的`LiveCD`（或`Live USB`）镜像列表，请访问 [www.livecdlist.com](http://www.livecdlist.com)。

## De-ICE

De-ICE LiveCD 旨在为提供练习和学习渗透测试（PenTest）技能的合法目标，它们是包含真实挑战的服务器。每张光盘提供了一个探索渗透测试世界的机会，既适用于初学者也适用于专业人士。De-ICE 项目自 2007 年 1 月起发布，已在美国各地的安全会议上进行过，并首次在 Syngress 于同年 9 月出版的名为 *Metasploit Toolkit for Penetration Testing, Exploit Development, and Vulnerability Research* 的书中被提及。

目前位于 [www.heorot.net/livecds/](http://www.heorot.net/livecds/)，那里有多个 LiveCD 可供免费下载（这些也包含在附带的 DVD 中）。这些服务器提供了基于 Linux 发行版“Slax”（源自 slackware）构建的真实世界场景。在这些光盘上，包含了可能可以被利用也可能不可被利用的不同应用程序，这就像现实世界一样。挑战在于发现哪些应用程序配置不当或可被利用，并获取 root 账户的未经授权访问权限。

使用这些 LiveCD 的优势是不需要任何服务器配置——LiveCD 可以直接放入 CD 驱动器，配置系统从 CD 启动，几分钟内，实验室中就会运行一个功能完全的可黑客攻击服务器。我们也可以直接在虚拟机中使用 LiveCD 镜像，如第 4 章所示，这让事情变得更加简单。De-ICE 光盘的开发旨在演示系统和应用程序配置中常见的问题。

De-ICE 光盘中包含的可能漏洞列表如下：

* 错误/弱密码

* 不必要的服务（文件传输协议 [`ftp`]、`telnet`、`rlogin` [`?!?!]`）

* 未打补丁的服务

* 可用信息过多（联系信息等）

* 糟糕的系统配置

* 糟糕或无加密方法

* 权限过大的用户权限（Elevated user privileges）

* 无 IP 协议安全 (IPSec) 过滤

* 错误的防火墙规则（插上就忘了？）

* 明文密码

* 软件中嵌入用户名/密码

* 无告警监控

De-ICE 挑战中不包含已知的漏洞利用，消除了使用自动化漏洞识别应用程序的可能性。

## 场景

附带的 DVD 包含了三个提供的 De-ICE LiveCD。它们每一个都有一个不同的场景，并需要不同的技能来解决。较易的挑战是 1.100 和 1.110 场景，而更困难的场景是 2.100。

### 1.100

此 LiveCD 配置的互联网协议 (IP) 地址为`192.168.1.100`——不需要对服务器进行任何额外配置。此 LiveCD 的场景是：一家小公司的首席执行官 (CEO) 在董事会的压力下，要在公司内部进行渗透测试。CEO 认为他的公司是安全的，觉得这极度浪费资金，特别是他已经让一家公司使用`Nessus`扫描过其网络漏洞了。

为了让董事会满意，他决定雇你做一份为期 5 天的工作；由于他真的不相信公司是不安全的，他合同让你只查看一台服务器——一个旧系统，上面只有一个基于 Web 的公司联系信息列表。CEO 期望你证明系统管理员遵循了所有适当且认可的安全实践，并且你无法获得该机器的访问权限。PenTest 实验室系统和 PenTest 机器必须连接到配置了以下值的路由器：

* 动态主机配置协议 (DHCP) 服务器：已激活

* 地址池起始地址：`192.168.1.2`

* 局域网传输控制协议/网协议 (LAN TCP/IP)：

* IP 地址：`192.168.1.1`

* IP 子网掩码：`255.255.255.0`

**警告**：大多数人在使用 De-ICE 光盘搭建 PenTest 实验室时，会尝试“ping”系统以查看一切配置是否正确。某些真实世界的系统被`刻意`配置为`忽略` ping 请求。不要仅仅因为服务器对 ping 没有响应，就假设实验室设置有问题。

## Foundstone

Foundstone Network Security 是 McAfee 的一个部门，它开发了一系列涉及 Web 和 SQL 攻击的微软基础场景。该系列名为`Hacme`，可以在 [www.foundstone.com/us/resources-tools.asp](http://www.foundstone.com/us/resources-tools.asp) 下载。这些场景不是 LiveCD，而是作为 Windows 服务器的软件安装程序提供的。在安装`Hacme`场景之前有不同的应用程序要求。注意：我们不会在书中使用 Foundstone`Hacme`场景，因此我们不会讨论服务器配置。Foundstone 在下载包中提供的配置将有助于在渗透测试中设置服务器。

## 场景
