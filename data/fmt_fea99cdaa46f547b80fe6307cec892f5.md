### 认证目标 20.01

## 理解评估类型

定期评估安全是一项重要任务，而知道如何执行该评估是一项重要技能。安全不仅仅是防火墙和权限。了解如何评估业务的不同领域以及与这些领域相关的风险非常重要。

在本节中，你将了解不同类型的安全评估。请确保你对这些内容非常熟悉，以应对 Security+ 认证考试。

### 评估类型

安全评估包括风险评估、威胁评估、配置评估、漏洞评估和渗透测试。每种类型的评估采用不同的方法来评估安全性。

#### 风险评估

风险评估是安全诸多方面（如业务连续性规划）广泛使用的一种评估类型。风险评估也称为风险分析，它涉及识别组织内资产面临的风险，然后寻找解决方案以将这些风险降至最低。第 17 章 更详细地介绍了风险分析，但以下列表概述了风险评估的主要阶段：

- **识别资产** 风险评估的第一步是识别组织内的资产。资产是指对组织有价值的任何事物；例如，如果一家公司拥有一个每天带来数十万美元收入的电子商务网站，那将是一项资产。
- **识别针对资产的威胁（风险）（威胁评估）** 一旦识别出资产，接下来就要识别针对每项资产的威胁。每项资产通常会面临不止一种威胁。此时只需列出这些威胁。例如，该网站可能遭受拒绝服务 (DoS) 攻击，或者 Web 服务器的硬盘可能发生故障。
- **分析影响** 此阶段称为影响分析阶段，用于确定每种威胁对资产造成的影响。例如，分布式拒绝服务 (DDoS) 攻击对公司电子商务网站的影响将是在从攻击中恢复所需的时间内造成收入损失。这种威胁会产生高影响。
- **确定威胁优先级** 在识别出资产的所有威胁后，你需要根据威胁若成为现实将对业务造成的影响，以及威胁发生的概率，对每个威胁进行评级。此时你应该已了解哪些威胁更为严重。
- **缓解威胁** 一旦确定了威胁的优先级，你就可以着手考虑如何缓解它们。例如，你可以通过将 Web 服务器置于防火墙后面来帮助防止对其的攻击。你可以通过实施 RAID 解决方案来防范硬盘故障。

![Image](img/exam.jpg)

> **在 第 17 章 中，你学习了 SLE 和 ALE 等公式，但你也需要知道计算风险的通用公式：风险 = 概率 × 潜在损失（即 R = P × L）**

#### 威胁评估

威胁评估实际上是风险评估的一部分，你在其中识别针对资产的不同威胁。如前所述，单个资产将面临许多不同的威胁，而风险评估的一部分工作就是对这些威胁确定优先级。

### 配置评估

通过配置评估，安全管理员将审查系统或网络的安全配置。这通常涉及拥有一份配置最佳实践清单，并确保遵循了这些最佳实践。以下是你需要检查配置的资产列表：

- **所有系统** 在评估任何系统的安全性时，请确保其已打好补丁并经过加固。确保系统上没有运行不必要的软件或服务。所有系统都应要求用户使用强密码登录。所有系统都应安装防病毒软件，并使病毒定义数据库自动更新。还应配置并启用基于主机的防火墙。
- **文件服务器** 在检查文件服务器的安全配置时，请确保用户必须通过身份验证才能访问服务器上的文件。确保为文件夹分配了权限以控制谁有权访问信息，并确保遵循了最小权限原则。
- **Web 服务器** 对于 Web 服务器配置，请验证如果网站处理访问者的敏感信息，则已实施 SSL/TLS。确保实施了适当的身份验证，并确保 Web 服务器上没有不应存在的文件。确保 Web 服务器已启用日志记录，以便你可以监控对网站的访问。
- **SMTP 服务器** 除了给系统打补丁和加固外，请确保 SMTP 服务器位于防火墙后面，且不允许 SMTP 中继。SMTP 服务器应具备邮件级病毒防护，且应启用垃圾邮件过滤功能以维护邮件卫生。我曾与一位启用了邮件服务器垃圾邮件过滤功能的客户交谈，其垃圾邮件过滤器每天拦截 40,000 封非合法邮件！
- **DNS 服务器** 请确保组织使用两套 DNS 解决方案——一套用于内部名称解析，另一套用于公共名称解析。公共 DNS 服务器应位于 DMZ 中并经过加固。DNS 服务器应仅允许向辅助服务器进行 DNS 区域传送。

### 路由器

路由器应配置控制台、辅助和 Telnet 密码，以控制谁能获得路由器的管理访问权限。出于安全考虑，您应使用 Secure Shell (SSH) 而非 Telnet 来远程管理路由器。确保路由器已实施访问控制列表 (ACL)，以控制允许什么流量通过路由器。例如，思科路由器上的以下配置将创建访问列表 45，允许来自 12.0.0.0 网络和 11.0.0.0 网络的流量。ACL 末尾存在一条*隐式拒绝所有*规则，因此除非流量来自 11.0.0.0 或 12.0.0.0 网络，否则将被拒绝。该规则随后应用于路由器的串行接口以处理入站流量，这将导致试图进入网络的流量被 ACL 过滤。

![Image](img/p0778-01.jpg)

### 防火墙

防火墙应配置为拒绝所有流量，除非是明确允许通过防火墙的流量。这种配置称为*隐式拒绝*——除非另有指定，否则拒绝所有流量。由于防火墙连接到互联网，您应确保已禁用任何远程管理功能，并且设备上使用了强身份验证。

### 交换机

就交换机的配置而言，请确保在控制台端口、辅助端口和 Telnet 端口上配置了密码，以控制谁能获得设备的管理访问权限。此外，请检查是否有任何未使用的端口被禁用，以确保端口安全。要将系统分离到不同的网络段，请检查是否正在使用 VLAN，如果没有，请考虑是否应该使用。

### 员工

在执行手动评估时，还应通过计划并针对员工实施几次社会工程学攻击，来评估员工的安全知识。例如，您可以测试员工是否会泄露他们的密码。您还可以在办公室的不同区域放置无标签的 USB 驱动器，看有多少员工将 USB 驱动器连接到他们的系统。这里的想法是 USB 驱动器可能包含病毒，员工不应在系统中使用未知介质。

### 物理安全

通过手动评估，您还需要评估物理安全。所有必要的门窗都已上锁吗？系统的 CMOS 设置是否已更改，以防止从光盘或 USB 驱动器启动？对于显示机密信息的工作站，它们是否远离未经授权的查看者？机密系统是否存放在受保护区域并禁用了 USB 端口，以防止使用闪存驱动器？

### 漏洞评估

漏洞评估是一种评估，您在其中识别配置中使系统容易受到攻击或安全事件影响的区域。大多数漏洞评估通过使用漏洞评估工具（如 `Nessus`、`OpenVAS` 或 `GFI’s LANguard`）实现自动化（请参见图 20-1）。

![Image](img/f0780-01.jpg)

**图 20-1**

漏洞扫描器将扫描网络并报告每个系统的安全问题。

漏洞评估工具的目的是分析系统的配置，以确定从安全角度需要改进的领域。例如，漏洞评估工具将检查系统的补丁级别，并告知您是否缺少补丁。如果您有无密码的用户账户、近期未登录的账户或过多的管理账户，它也会报告。所有这些要点都会在系统上造成安全风险。

关于漏洞评估需要理解的关键点是，尽管您可能正在运行一个程序来为您进行评估，但该软件仅检查系统的配置，以决定在哪里应进行改进。该软件实际上并未对系统执行攻击；它只是检查系统的配置。这被称为对评估采取*被动*方法（*被动评估*），因为您并未实际尝试利用系统；您只是检查配置并基于此做出决策。

> **针对考试，请记住漏洞评估被视为被动评估，因为您并未实际尝试绕过安全控制并入侵系统。**

密切关注管理账户（请参见图 20-2）。管理账户越少越好，因为您需要限制能够对环境进行更改的人数。您还需要留意额外的管理账户，因为黑客可能已将其植入作为系统的后门。

#### 未修补的软件

#### 易受攻击的软件

漏洞评估软件的一大优势是它能识别系统上运行的任何易受攻击的软件。例如，如果您的系统容易受到通用网关接口 (CGI) 攻击，评估软件会通知您。

Security+ 考试要求您了解漏洞扫描的特征以及执行扫描时应考虑的事项：

- **被动测试安全控制** 请知晓，执行漏洞扫描被视为被动测试系统的安全性，因为您并未实际尝试入侵系统或利用漏洞。
- **识别漏洞** 漏洞扫描的目标是识别系统中的漏洞或弱点。例如，如果该系统未及时应用补丁，则被视为一个漏洞。
- **识别安全控制的缺失** 执行漏洞评估时，您旨在识别是否有任何本应使用但当前未使用的安全控制。例如，您可能评估数据库服务器的安全性，并注意到它未受防火墙保护。在这种情况下，您应报告该系统可使用防火墙来控制与数据库服务器的通信。
- **识别常见的错误配置** 执行漏洞扫描时，您要深入检查系统的配置，以确定任何可能导致安全问题的错误配置。例如，您可能会注意到服务器上的管理员账户未被重命名。

### 渗透测试

渗透测试与漏洞评估是完全不同类型的安全评估。渗透测试中，测试人员使用常见攻击方法，查看能否绕过系统的安全防护。若渗透测试人员无法利用常见漏洞攻破系统，则系统通过测试；反之，若系统被攻破，则测试失败，测试人员将报告发现的问题及加固建议。

Security+ 考试要求掌握渗透测试的特征，主要特征与注意事项如下：

- **验证威胁是否存在** 渗透测试对系统发起实际攻击，若模拟攻击成功，便是威胁存在的最有力证明。
- **绕过安全控制** 测试针对已加固的系统，测试人员需像黑客一样绕过这些控制，以验证安全方案的实际有效性。
- **主动测试安全控制** 渗透测试属于主动测试系统安全，而漏洞扫描属于被动测试。
- **利用漏洞** 渗透测试主动利用系统漏洞以验证系统是否安全。漏洞评估仅指出漏洞存在，而渗透测试通过尝试利用漏洞，判断其是否构成实际风险。

![Image](img/exam.jpg)

> **考试提示**：若安全策略规定安全测试不得使用实战攻击或主动测试，则应避免渗透测试，改用漏洞扫描。

### 法律问题

作为执行安全评估的顾问，必须警惕渗透测试的法律风险，因为实际攻击系统属于违法行为。必须明确：**未经授权访问任何系统均属违法，即使目的是报告发现并协助加固**。执行渗透测试时，关键在于获取公司授权签署人（应为业务所有者或高管，而非 IT 经理或网络管理员）提供的书面许可。

高层管理人员可能不太支持渗透测试，因为这涉及对生产系统的实战攻击。若受邀执行测试，应向管理层充分说明测试内容、潜在风险（如可能导致系统在工作时间崩溃），以便其决策。管理层可能倾向于选择风险较低的漏洞评估。

![Image](img/exam.jpg)

> **务必在执行任何渗透测试前，获得由律师起草、经组织高层管理人员签署的法律文件，授权执行此类测试。这称为 `渗透测试授权`。执行漏洞扫描前同样需获授权，称为 `漏洞测试授权`。**

可向管理层承诺不故意发起拒绝服务攻击以免影响生产，但需明确：因攻击工具特性，可能意外触发拒绝服务；将预先测试工具以降低风险，但无法绝对保证不发生拒绝服务。生产系统上某些软件可能对攻击产生负面响应导致崩溃。

- 渗透测试属于**主动评估**，因其实际尝试绕过安全控制并入侵系统。
- **必须**获得高层管理人员书面许可方可执行评估。
- 即使无意发起拒绝服务攻击，系统对黑客工具的响应仍可能导致拒绝服务。

## 评估技术

了解常见安全评估类型后，介绍执行评估的具体技术。渗透测试虽是热门术语，但掌握其他安全测试方法同样重要。

### 基线报告

基线报告通过采集系统正常运行时的基线状态，再将其与性能数据对比。常用于涉及拒绝服务或恶意软件导致系统性能不达预期的安全事件。

评估时，对比当前性能与基线以定位问题。例如：某日服务器变慢，性能监视器显示 CPU 占用 89%，但业务无异常；基线显示正常 CPU 占用为 29%。这表明有进程占用大量 CPU。可使用性能监视器追踪占用 CPU 周期的软件。

### 代码审查

虽身为程序员不愿承认，但大多数安全问题源于开发人员以不安全方式构建应用。例如：安全编码的关键规则是验证发送给应用的所有数据，否则黑客可实施 SQL 注入或缓冲区溢出攻击。

应定期对内部开发软件进行代码审查。安排专门的安全测试人员审查开发人员编写的所有应用代码，查找可能导致安全问题的代码错误。

> **考试重点**：术语 `攻击面` 指系统上运行的软件和服务。

### 确定攻击面

通过确定系统的攻击面来评估安全。攻击面包括系统上安装的所有软件和运行的服务。作为安全专业人员，关键职责是协助组织通过移除不必要的软件和服务来缩减攻击面。
