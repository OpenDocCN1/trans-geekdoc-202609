
- **单模光纤 (SMF)** 使用单束光（称为模式）来进行远距离传输
- **多模光纤 (MMF)** 同时使用多束光（模式），每束光以不同的反射角度运行，以进行短距离传输

> **考试请记住：光纤是一种更安全的线缆类型，因为它不传输电信号，而是以光脉冲形式传输数据。**

## 认证目标 1.02 理解 TCP/IP

既然你已经了解了网络上使用的一些不同类型的网络设备以及正在使用的电缆类型，让我们转换方向来谈谈 TCP/IP 协议。作为一名安全专业人员，你不仅要熟悉 TCP/IP 协议，还要理解通信是如何在 TCP/IP 网络上发生的，这至关重要。让我们从快速回顾协议基础开始。

### 复习 IP 寻址

TCP/IP 需要一点知识才能正确配置系统。配置 TCP/IP 时，你需要知道 IP 地址、子网掩码和默认网关的设置。让我们从 IP 地址开始。

#### IP 地址

IP 地址是一个 32 位的值，用于在网络（或互联网）上唯一标识系统。IP 地址的外观类似于 `192.168.1.15`。IP 地址中的四个十进制值由小数点分隔。每个值由 8 位（1 和 0）组成，因此有四个十进制值，8 位 × 4 = 32 位地址。

由于每个十进制值都由 8 位组成（例如 192），我们将每个十进制值称为一个八位字节。一个 IP 地址中有四个八位字节。非常重要的是要理解，IP 地址中的四个八位字节分为两部分——`网络 ID` 和 `主机 ID`。子网掩码决定了组成网络 ID 的位数和组成主机 ID 的位数。让我们看看这是如何工作的。

#### 子网掩码

查看子网掩码时，如果某个八位字节中有 255，则 IP 地址中对应的八位字节属于网络 ID 部分。例如，如果我有一个 IP 地址 `192.168.1.15` 和子网掩码 `255.255.255.0`，则前三个八位字节将组成网络 ID，最后一个八位字节将是主机 ID。网络 ID 为网络本身分配一个唯一地址，而主机 ID 在网络上唯一标识系统。表 1-3 总结了此示例。

你可以在 表 1-3 中看到，网络 ID（用 `N` 表示）为 `192.168.1`，主机 ID 为值为 15 的最后一个八位字节。这意味着该系统位于 `192.168.1` 网络上，同一网络上的任何其他系统将具有相同的网络 ID。

举另一个例子，如果你的子网掩码为 `255.0.0.0`，则意味着 IP 地址的第一个八位字节用作网络 ID 部分，而最后三个八位字节是 IP 地址的主机 ID 部分。

那么子网掩码的目的是什么？更确切地说，为什么我们要有一个将 IP 地址分解为网络 ID 和主机 ID 的子网掩码？因为当一个系统（如 `192.168.1.15`，子网掩码为 `255.255.255.0`）向 `192.198.45.10` 发送一段数据时，发送系统首先需要确定目标计算机是否存在于同一网络上。它通过比较网络 ID 来做到这一点（参见 表 1-4）；如果网络 ID 相同，则两个系统存在于同一网络上，一个系统可以直接发送给另一个系统，而无需使用路由器。如果系统存在于不同的网络上，则数据需要传递给路由器，以便路由器将数据发送到另一个网络。

#### 默认网关

当你的系统想要向网络上的另一个系统发送数据时，它会查看自己的网络 ID 并将其与目标系统的 IP 地址进行比较。如果它们具有相同的网络 ID，则数据会直接从你的系统发送到目标系统。如果这两个系统位于不同的网络上，你的系统必须将数据传递给路由器，以便路由器将数据发送到目标系统的路由器。

你的系统如何知道使用哪个路由器？答案是“默认网关”。默认网关是可以将数据从你的网络发送出去的路由器的 IP 地址。

要在互联网上通信，你的系统需要配置 IP 地址、子网掩码和默认网关。如果你只需要与网络上的其他系统通信，则只需要 IP 地址和子网掩码。

#### 地址类别

每个 IP 地址都属于一个不同的地址类别。互联网社区定义这些类别旨在适应各种规模的网络。IP 地址所属的类别最初决定了地址的网络 ID 和主机 ID 部分，以及该网络上支持的主机数量。不同的类别地址被称为 A 类、B 类、C 类、D 类和 E 类。本节详细介绍每类地址。

##### A 类地址

A 类地址的默认子网掩码为 `255.0.0.0`，这意味着第一个八位字节是网络 ID，最后三个八位字节属于地址的主机 ID 部分。每个八位字节可以包含 256 个可能的值（0–255），因此 A 类地址支持网络上有 16,777,216 台主机（256 × 256 × 256）。实际上，每个 IP 网络上都保留了两个地址：所有主机位设为 0 的地址（网络 ID）和所有主机位设为 1 的地址（广播地址），因此只有 16,777,214 个有效地址可用于系统。所以使用 A 类地址时，你将无法将 `n.0.0.0` 或 `n.255.255.255`（其中 `n` 是你的网络 ID）分配给网络上的任何主机。

你总是可以通过第一个八位字节的值在 1 到 126 之间来识别 A 类地址。以 127 开头的地址也是 A 类地址，但你不允许使用任何以 127 开头的地址，因为它被保留用作环回地址（本章后面将详细介绍环回地址）。例如，IP 地址 `12.56.87.34` 是 A 类地址，因为第一个八位字节是 12，处于 1 到 126 的范围内。

##### B 类地址

B 类地址的默认子网掩码为 `255.255.0.0`，这意味着前两个八位字节是网络 ID，最后两个八位字节是地址的主机 ID 部分。这意味着我们可以在网络上拥有 65,536 台主机（256 × 256）。哦，但别忘了减去那两个保留地址，这样就给了我们 65,534 个可分配给网络上主机的地址。

由于 B 类地址支持的主机数量，通常会发现中型公司拥有 B 类地址。你可以通过第一个八位字节以 128 到 191 之间的数字开头来识别 B 类地址。

##### C 类地址

C 类地址的子网掩码为 `255.255.255.0`，这意味着前三个八位字节是网络 ID，最后一个八位字节是主机 ID。只有唯一的一个八位字节作为主机 ID，意味着 C 类地址只能支持网络上有 254 台主机（256 – 2）。

你可以通过第一个八位字节的值在 192 到 223 之间来识别 C 类地址。例如，IP 地址 `202.45.8.6` 是 C 类地址，因为 202 介于 192 和 223 之间。我们也知道该系统的子网掩码为 `255.255.255.0`，因为它是 C 类地址。

##### D 类地址

D 类地址用于网络上称为*多播应用程序*的特殊类型应用程序。这些应用程序通过将数据发送到多播地址，同时向多个系统发送数据，任何已向该地址注册的系统都将接收数据。多播地址即是 D 类地址的用途，因此你不会将它们专门分配给网络上的主机用于正常的网络通信。

D 类地址的第一个八位字节的值范围为 224 到 239。拥有如此多的范围，D 类地址有可能提供 268,435,456 个唯一的多播组，用户可以从多播应用程序订阅这些组。

##### E 类地址

E 类地址的有趣之处在于，它们仅为实验目的而设计，因此你永远不会在网络上看到 E 类地址。E 类地址的第一个八位字节的值落在 240 到 247 的范围内。

###### 特殊地址

你已经了解到，不允许将第一个八位字节值为 127 的 IP 地址分配给主机。这是因为 A 类地址范围 127 已被保留用于环回地址。

*环回地址*用于指代本地系统，也称为 localhost。如果你想验证 TCP/IP 软件是否已在本地系统上初始化，即使你可能没有 IP 地址，也可以 ping 环回地址，通常称为 `127.0.0.1`。

*私有地址*是可以分配给系统但不能用于任何类型 Internet 连接的地址。私有地址是不可路由地址，因此使用它们的任何系统将无法在网络外运行。以下是三个私有地址范围：

- `10.0.0.0` 到 `10.255.255.255`
- `172.16.0.0` 到 `172.31.255.255`
- `192.168.0.0` 到 `192.168.255.255`

使用这些地址无法跨 Internet 路由数据不会构成问题，因为实际上，这些私有地址将位于网络地址转换 (NAT) 服务器后面，该服务器会将私有地址转换为可在 Internet 上路由的公共地址。

Windows 客户端支持一项称为*自动专用 IP 寻址 (APIPA)* 的功能。当客户端无法联系动态主机配置协议 (DHCP) 服务器时，此功能会使 Windows 客户端自动使用 `169.254.x.y` 地址进行配置。如果 DHCP 服务器出现故障，导致网络上的所有系统都无法从 DHCP 服务器获取地址，则客户端都会为自己分配一个 `169.254` 地址范围内的地址，然后能够相互通信。

APIPA 不分配默认网关，因此你将无法访问远程网络和 Internet 上的资源——但仍可与本地网络上的系统通信。在排查计算机无法在网络上通信的原因时，请留意具有 `169.254.x.y` 地址范围的系统，因为这意味着它们找不到 DHCP 服务器。

###### 无效地址

你不仅应该熟悉 TCP/IP 中的私有地址范围，还应该能够识别无效地址。无效地址是不允许分配给网络上主机（如系统或路由器）的地址。从认证考试的角度来看，你需要能够识别这些无效地址。以下被视为无效地址：

- **以 127 开头的任何地址** 以 127 开头的 IP 地址保留用于环回地址，不能分配给系统。此类无效地址的示例是 `127.50.10.23`。
- **所有主机位均设置为 0** 不允许为系统分配主机 ID 部分所有位均设置为 0 的 IP 地址，因为这是网络 ID。此类无效地址的示例是 `131.107.0.0`。
- **所有主机位均设置为 1** 不允许为系统分配所有主机位均设置为 1 的 IP 地址，因为这对应于网络的广播地址。此类无效地址的示例是 `131.107.255.255`。
- **重复地址** 不允许为系统分配另一系统正在使用的地址，因为这会导致“重复 IP 地址”错误。

### 理解 TCP/IP 协议

现在你已了解 IP 寻址的基础知识，让我们来谈谈 TCP/IP 协议套件中存在的不同协议。作为负责配置防火墙和路由器访问列表的安全专业人员，理解每个 TCP/IP 协议至关重要。

#### 传输控制协议

传输控制协议 (TCP) 负责提供面向连接的通信，并确保数据交付（称为可靠交付）。面向连接的通信涉及首先在两个系统之间建立连接，然后确保跨连接发送的数据到达目的地。TCP 通过重传任何丢失或损坏的数据来确保数据到达目的地。TCP 由需要可靠传输的应用程序使用，但由于会话的建立以及跨会话的数据监控和重传，这种传输比无连接协议具有更多开销。

关于 TCP 要记住的另一个因素是，该协议要求接收方确认成功接收数据。当然，所有确认（称为 ACK）都会在网络上产生额外流量，从而减少在给定时间范围内可传递的数据量。TCP 会话的创建、监控和结束所涉及的额外开销，换来的是 TCP 确保数据到达目的地的确定性，这是值得的。

##### TCP

TCP 通过使用所谓的序列号和确认号来确保数据被送达。`序列号` 是分配给发送的每个数据片段的一个编号。系统在接收到一个数据片段后，会通过向发送方发回一个确认消息来确认已收到该数据，其中原始序列号将作为回复消息的确认号。

##### TCP 三次握手

在系统能够通过 TCP 进行通信之前，它必须首先与远程系统建立连接。为了与远程系统建立连接，TCP 使用所谓的 TCP 三次握手。TCP 三次握手分为三个阶段（如 图 1-10 所示）：

![Images](img/f0022-01.jpg)

**图 1-10**  

TCP 三次握手

- **SYN** 在第一阶段，发送系统向接收系统发送一条 `SYN` 消息。发送的每个数据包都被分配一个唯一的序列号。`SYN` 消息包含 `初始序列号 (ISN)`，即将要使用的第一个序列号。在本例中，计算机 A 正在连接计算机 B 上的网站，因此向计算机 B 的端口 80 发送了一条 `SYN` 消息。
- **SYN/ACK** 第二阶段称为 `SYN/ACK` 阶段，因为该消息在确认第一条消息的同时，也指示了其自身的初始序列号。在本例中，计算机 B 发回 `SYN/ACK` 消息，确认已收到数据包 123（通过确认 124 为下一个序列号），同时也指定了其 `ISN` 为 326。
- **ACK** 三次握手的最后阶段是确认消息，它确认第二阶段发送的数据包已被接收。在本例中，计算机 A 发送 `ACK`，通过确认下一个数据包将为序列号 327，来确认已收到数据包 326。

##### 断开 TCP 会话

正如 TCP 使用三次握手来创建两个希望通信的系统之间的连接一样，TCP 也有一个流程让参与者退出对话。查看 图 1-11，可以看到如果计算机 A 想要断开 TCP 会话，它必须首先发送一个 `FIN` 标志以示意要结束对话。

![Images](img/f0022-02.jpg)

**图 1-11**  

终止 TCP 连接

当计算机 B 收到 `FIN` 消息时，它会回复一个确认，然后向计算机 A 发送自己的 `FIN` 消息。作为该流程的最后一步，计算机 A 必须确认已收到来自计算机 B 的 `FIN` 消息。这类似于打电话交谈——要结束通话，你说再见，然后等待对方说再见后再挂断。我将其描述为以一种“礼貌”的方式结束对话。

还有一种以“不礼貌”方式结束对话的方法。回到电话类比：你可以在不说再见的情况下挂断电话，从而不礼貌地结束对话。在 TCP 世界中，你可以通过发送一个设置了 `RST`（复位）标志的 TCP 消息来“挂断”。

##### TCP 标志

TCP 协议使用 TCP 标志来识别重要类型的数据包。以下是您应为 Security+ 认证考试熟悉的常见 TCP 标志：

- **SYN** `SYN` 标志分配给属于三次握手 `SYN` 阶段的任何数据包。
- **ACK** 确认标志确认之前的数据包已被接收。
- **PSH** 推送标志旨在强制将数据传递给应用程序。
- **URG** 紧急标志指定某个数据包为紧急数据包。
- **FIN** 结束标志指定您想要终止或结束连接。这以礼貌的方式结束 TCP 连接，就像打电话时说再见来结束通话一样。
- **RST** 复位标志用于以不礼貌的方式结束 TCP 对话。这就像不打招呼就挂断电话一样。
