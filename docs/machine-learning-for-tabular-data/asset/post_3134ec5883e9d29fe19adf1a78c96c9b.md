The train data is split into multiple batches, and each batch is proposed for learning to the stochastic descent (SGD) algorithm. SGD is not a stand-alone algorithm but an optimization procedure for linear models, optimizing the weights by iteratively learning from small batches of the data or even just examples alone. It is based on the gradient descent optimization procedure and is also used in deep learning. Gradient descent starts with an initial guess for the model weights and computes the error. The next step involves computing the gradient of the error, which is obtained by taking the negative of the vector that contains the partial derivatives of the error with respect to the model weights. Since the gradient can be interpreted as taking the steepest descent on an error surface, a common example for gradient descent is to figure it as descending from high in the mountains to the lowest valley by taking the steepest path downward. The "mountains" in this analogy represent the error surface, and the "lowest valley" represents the minimum of the error function. Figure 4.12 visually shows this process by the progressive descent from a random high to the lowest point in a bowl-shaped error curve.

Besides angle, it is important to remember that the gradient determines how the weights should be adjusted to reduce the error at each step. Through repeated iterations, the error can be minimized by adjusting the model's weights. However, the weights updated can significantly affect the outcome. If the updates are too large the algorithm may take wide steps, potentially causing the model to overshoot the target and climb the error curve. In the worst-case scenario, this can result in a continuous worsening of the error, with no possibility of recovery. Conversely, taking smaller steps is generally safer but computationally burdensome. The size of such steps is decided by the learning rate, a parameter that regulates how updates are done.

Linear models can be optimized easily using gradient descent because their error surface is simple and bowl-shaped. However, more complex models like gradient boosting (which will be discussed in the next chapter) and deep learning architectures encounter challenges in optimization due to their higher complexity, with interrelated parameters and a more complex error landscape. Depending on the starting point, as illustrated in figure 4.13, these models may become stuck in a local minimum or plateau during optimization, leading to suboptimal results.

Learning a linear model by SGD is made possible using Scikit-learn's method `partial_fit`, which, after an informed start (the algorithm needs to know the target labels), can learn by partially filling one batch after the other. The same procedure is repeated multiple times, called iterations or epochs, to consolidate and improve the learning. The algorithm will see, though in a different order, the examples multiple times and update its coefficients every time. To avoid abrupt changes in the coefficients, which frequently occur when an outlier is in the batch, the updated coefficients are not substituted for the existing ones. Instead, they are averaged together, allowing a more gradual transition.

The result is quite comparable with in-core learning logistic regression. Out-of-core learning, though limited to only the simplest machine learning algorithms such as linear or logistic regression, is an effective way to train on tabular data when many samples cannot fit into memory. All deep learning solutions also use the idea of a stream of batches, and will be discussed in the chapters devoted to deep neural network methods for tabular data, together with strategies as early stopping, a technique necessary to avoid overfitting the data due to an excessive use of the algorithm as seen in previous iterations.

We can now anticipate that a fundamental principle of such learning is the randomization of the order of the examples. Since the optimization is progressive, if your data is ordered in a specific way, it will cause a biased optimization, which repeating the same batches in the same order can negatively influence your results. Hence, randomizing the order is critical for a better trained algorithm. Another important point with SGD, is the data preparation phase. In such a phase, you should include all feature rescaling operations, because the optimization process is sensitive to it.

### 4.3.6 Choosing your algorithm

As a rule of thumb, you should first consider whether machine learning algorithms scale differently based on how many rows you have. Starting from $10^2$ to $10^3$ rows, simple models such as linear and logistic regression are best suited. For up to $10^3$ to $10^5$ rows, deep learning solutions may outperform other choices. Hence, the variety of needs in tabular problems and models of machine learning defines the notion that one best algorithm is all you need for your work.

## Summary

- Determining what machine learning algorithm involves several factors: the number of examples and features, the expected performances, speed at prediction time, and interpretability.
- As a rule of thumb:
    - Statistical machine learning is suitable for datasets with few cases.
    - Classical machine learning is suitable for datasets with a moderate number of cases.
