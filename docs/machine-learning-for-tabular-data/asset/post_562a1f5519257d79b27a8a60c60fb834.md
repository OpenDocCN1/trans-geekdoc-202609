Note that whether you are using a classification or a regression, the SHAP values obtained by them are log transformations of a multiplicative model. It means that if you want to recreate the original prediction, you will need to exponentiate the values and then multiply them by themselves, as demonstrated by the following code snippet, reconstruction for the first prediction from the SHAP values and comparing it to the effective prediction:

```python
np.prod(np.exp(shap_values[0])), preds[0]
```

However, in general, the SHAP values provide a good approximation of the predictions. When applying the approach to the training set and assessing its adherence to the original predictions using Pearson’s correlation, it demonstrates a strong fit of the SHAP values to the predictions:

As an alternative to directly outputting the SHAP values as an XGBoost prediction, you can use the TreeExplainer function from the SHAP package (https://mng.bz/pKXR). The function, though being declared built with fast C++ implementations, is slower than the direct predictions from XGBoost. However, using the TreeExplainer, you can specify other options, particularly the output type, and the calculation method, which can allow you to reconstruct the original prediction as seen previously (using the parameter `feature_perturbation="tree_path_dependent"`) or using a method that "breaks the dependencies between features according to the rules dictated by causal inference," providing more reliable insights when using such collinearity among the features (using the parameter `feature_perturbation="interventional"`). You can obtain the interventional SHAP values using the following code snippet:

```python
from shap import TreeExplainer
explainer = TreeExplainer(pipeline['xgb'], data=Xt, model_output='raw', feature_perturbation='interventional')
interventional_shap_values = explainer.shap_values(Xt)
```

The resulting SHAP values matrix is less truthful than the original data and cannot reconstruct the predictions as seen before. Still, such an approach could provide more reliable estimates "true to the model" as explained in technical terms in the following GitHub problem: https://github.com/shap/issues/1098. Based on our experience, we use TreeExplainer and the interventional approach, although it may require longer computation when dealing with data presenting highly multicollinearity.

Importance, however, tells just a part of the story. We also need directionality. Hence, the violin chart can provide even more information on the model's behavior. In a violin plot produced by the shap package, you can get hints from these details:

- Feature importance—The width of the violin plot indicates the density of SHAP values. Wider sections represent more instances with similar SHAP values for that feature.
- Shape of the violin—The shape indicates the distribution of SHAP values. If the violin is symmetric, it suggests that values are evenly distributed around the median. Asymmetry indicates skewness and suggests that certain values have more significant effects.
- Positive and negative contributions—The violin plot's center line (median) is usually zero. The left and right halves of the violin represent their respective contributions for positive and negative values. Positive SHAP values push predictions higher, while negative values push them lower.
- Association with feature value—The color of the violin plot can help you associate blue areas, where the feature has lower values, and red areas, where the feature has higher values, with specific SHAP contributions.
- Outliers—extreme SHAP values outside the range where the corresponding feature has an unusually strong effect on the prediction.

In the following listing, the violin plot provides useful insights into the distribution and the role of each feature on the model's predictions.
