## 6.2.2 Shadow features and Boruta

Boruta is a smart procedure for determining whether a feature is relevant in a machine learning problem by relying on the internal parameters of the model, such as coefficients in linear models or importance values based on gain, as in decision trees and their ensembles. It was first published in “Feature Selection with the Boruta Package” by Miron B. Kura and Witold R. Rudnicki (Journal of Statistical Software 36 (2010): 1-13); for a copy of the article, see https://www.jstatsoft.org/article/view/v0361.

Boruta, innovative, presents a few advantages over stability selection. It can be used with decision tree-based ensembles. To measure the relevance of a feature, as in stability selection, we look for non-zero coefficients. In Boruta, we count the times when the feature exceeds the highest importance obtained by shadow features. We call them them. Shadow features are random versions of the features (basically shuffled features), given that they are random, should attain any importance just by chance. If any feature cannot exceed the maximum importance of a shadow feature, it cannot be considered more predictive than any random sequence of values.

A threshold for selection, usually a minimum of occurrences of non-zero coefficients in stability selection, is given in Boruta by the number of its translates into a binomial distribution. A significance threshold for retaining or dropping a feature test according to the distribution if the number of hits can prove that the feature is consistently better than any random construct.

Listing 6.10 shows example using Boruta to select all the relevant features for an XGBoost classification on the Airbnb NY dataset. Boruta in the implementation (https://github.com/scikit-learn-contrib/boruta_py) has limitations because, apart from working only with tree-based models, such as random forests or gradient boosting (no matter what the implementation is), it cannot work with pipelines. Hence, we had to transform the data and then run Boruta on transformed features as we were training the final model. Boruta takes as key parameters the estimator—that is, the model you want to use, the number of decision trees in the ensemble, and the

n_estimators hyperparameter, which can be empty, set to an integer, or set to "auto" where the number of trees is decided upon the size of the dataset. Other important parameters in Boruta are max_iter, the number of rounds of testing, usually set to 100, and the alpha threshold for the binomial test, which can be increased from 0.05 to allow features to be retained or decreased for more features to be discarded.

## Listing 6.10 Boruta selection

```
from XGBoost import XGBClassifier
from boruta import BorutaPy
xgb = XGBClassifier(booster='gtree',
                    objective='logistic',
                    n_estimators=300,
                    max_depth=4,
                    min_child_weight=3)

X = column_transform.fit_transform(data, target_median)
boruta_selector = BorutaPy(estimator=xgb, n_estimators='auto')
boruta_selector.fit(X, target_median)
selected_features = boruta_selector.support_
selected_data = column_transform.get_feature_names()[selected_features]
print(selected_data)
```

- Initializes a BorutaPy feature selection object using an XGBClassifier
- Transforms the input data, performing any necessary preprocessing steps
- Retrieves a Boolean mask of features determined by the Boruta feature selector
- Fits the Boruta feature selector

## 6.2.3 Forward and backward selection

One limitation of Boruta is that it selects all the features. In our example, we apply a forward selection to an XGBoost model trained on the Airbnb dataset. The selection is set to define the correct number of features, and the low tolerance (to 0.0001 on accuracy measures ranging from 0 to 1) should show at the first signs of deterioration of the predictive performances. The obtained results point out to six features to be used: three binary, one high cardinality, and two numeric:

- [low_categories = neighborhood_group_Bronx]
- [low_categories = room_type_Entire_home/apt]
- [low_categories = room_type_shared_room]
- [high_card_categories = numeric_minimum_nights]
- [numeric_number_of_reviews = 'numeric_reviews_per_month']
- [numeric_calculated_host_listings_count = 'numeric_availability_365']
