Though the emphasis is placed on setting the best value to the k parameter the key to balancing the underfitting and overfitting of the algorithm to the training we instead raise attention to other aspects for an effective employ of this model. As the algorithm works by analogy and distances in complex spaces, we consider two important matters about this approach:

+   - The dimensions to measure and the curse of dimensionality

+   - The appropriate distance measure and how to process the features

In k-NN, the classification or the regression estimates depend on the most similar examples based on a distance metric computed on the features. However, in a dataset, not all features can be deemed important in judging an example similar to the other, and not all of the features can be compared in the same way. Prior knowledge of the problem does count a lot using K-NN because you have to select only the features relevant to the task you want to solve. If you assemble too many features for the problem, Figure B shows how a kN algorithm works with two features (represented on the x and y dimensions), and you can intuitively grasp classifying instances (the triangles in the figure) may be difficult if there are mixed classes in an area or if there are no train examples near a new instance. You have to rely on farther ones.

Here comes the curse of dimensionality, which says that as the number of features increases, the more examples you should have to maintain a meaningful distance between points. In addition, the curse implies that the number of necessary examples grows exponentially with respect to the number of features. For a k-NN algorithm, it implies that if you provide too many features, it will work in an empty space if the number of examples is not enough. Looking for neighbors will become daunting, and if you have just assembled relevant and irrelevant features, the risk is that the algorithm will as neighbors some examples that are very far from the case you have to, and the choice could be based on features that are not useful for the problem. Hence, if you are going to use k-NN, you should choose with care the features to be used (if you don't know which one, you need to rely on selection) or be very familiar with the problem to determine what should go into the algorithm. Parsimony is essential for the proper use of a k-NN.

When you decided about the features, regarding the distance metric you will use, you will need to standardize, remove redundancies, and transform the features. This because distance metrics are based on absolute measurements, and different scales can weigh in different ways. Considering using measurements in kilometers, meters, and centimeters together. The centimeters will likely predominate because they will easily have the largest numbers. Also, having features similar to each other (the problem of multicollinearity) can entail the distance measurement to outweigh certain sets of features over others. Finally, a distance measurement implies having the same dimensions to measure. However, in a dataset, you may find different kinds of data—numeric, categorical, and time-based—which one need to fit better in a distance calculation because they have different numeric characteristics.
