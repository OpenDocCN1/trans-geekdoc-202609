## Review of the gradient boosting solution from chapter 7

The goal of the model we created in chapter 7 was to predict the price of a new listing. This is actually a more challenging problem for deep learning than the NYC problem that we can see from table 12.1.

Table 12.1 Airbnb NYC vs Airbnb Tokyo

| | Airbnb NYC | Airbnb Tokyo |
|---|---|---|
| Rows in dataset | 48,000 | 10,000 |
| Columns in dataset | 18 | 31 |
| Target | Classification: predict whether price is over or under median | Regression: predict price |

In fact, the Tokyo dataset has fewer than 25% of the records of the NYC dataset and over double the columns as NYC dataset. With fewer data points, you need to rely more on domain expertise (hence the role of feature engineering). Having more columns implies there is more risk of overfitting during training, and in any case, you have to deal with more complex relationships between features and the target variable.

Generally speaking, classical machine learning approaches can get better results on small datasets than deep learning. Techniques such as data augmentation can mitigate this downside of deep learning, but deep learning approaches will struggle with a dataset with tens of rows. Research on why deep learning requires more data is not complete, but the large number of parameters in deep learning architectures and the need for a certain amount of data for the model to generalize is identified as one of the reasons why deep learning struggles with smaller datasets [see, “The Computational Limits of Deep Learning” by Thompson et al.
