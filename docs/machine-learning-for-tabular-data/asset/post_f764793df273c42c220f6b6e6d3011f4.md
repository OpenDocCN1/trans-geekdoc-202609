def show_prediction():

        scoring_dict[col] = float(request.args.get(col))
    scoring_dict['size_type_bin'] = int(request.args.get('size_type_bin')) or 1
    features = {tf.convert_to_tensor([value]) for name, value in scoring_dict.items()}
    predictions = loaded_model.predict(input_dict)
    prob = predictions[0][0]
    if prob < 0.5:
        predict_string = "Prediction is property has a price less than median"
    else:
        predict_string = "Prediction is property has a price more than median"
    prediction = {'prediction_key':predict_string}

```

# CHAPTER 10 Model deployment

The view function shown in listing 10.3 takes the query string returned from home.html, loads all the values from the query string into the Python dictionary scoring_dict, and uses those values to invoke the model loaded by the code in listing 10.1 to get a prediction. One exception is size_type_bin. For the purposes of this simple web deployment, we hard-code the bin value. As an exercise, consider how you would calculate the bin value without hard coding. The value of prediction is used to set a string value that is sent to show-prediction.html to be displayed when the page is rendered.

From 10.5 we can see the main actions taken by the load-selections() JavaScript function:

- For continuous fields, the default value. This is the value that appears in the field when the page is initially loaded and passed to the Flask server if the user doesn't change it.
- For categorical fields, define the values from which the user can select and update the field list with. In home.html, these values are defined in a hard-coded list. In a more web application, these values would be maintained in a control file separate from the code to make it easier to maintain the values and reduce the chance of adding registers to the code.
