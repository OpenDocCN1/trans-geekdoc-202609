In our case, as it is often with tabular data, the situation is complicated by categorical features, which when one-hot encoded, will turn into binaries ranging from 0 to 1, with a different scale from normalized features. The solution we propose is to discretize the numeric features, effectively turning them into binary features, each representing a feature's numeric values fall into a specific range. Binarization of continuous features is obtained thanks to the KBinsDiscretizer class (https://mng.bz/N12N) embedded into the numeric_discretizing pipeline, which will turn each numeric feature into binary ones, each covering a bin of values. We also apply principal component analysis (PCA) to reduce the dimensionality and make all the features unrelated. We might attenuate nonlinearities inside the data since PCA is a technique based on linear combinations of variables. Having uncorrelated resulting features is a characteristic of data processed by PCA, which suits k-NN: it is based on distances, and distance measurement properly works if dimensions are unrelated. Therefore, any distance change is due to changes in a single dimension, not multiple ones. The following listing shows the code implementing the data transformation process and training the k-NN.

# k-NN 467

Though the emphasis is placed on setting the best value to the k parameter the key to balancing the underfitting and overfitting of the algorithm to the training we instead raise attention to other aspects for an effective employ of this model. As the algorithm works by analogy and distances in complex spaces, we consider two important matters about this approach:

- The dimensions to measure and the curse of dimensionality
- The appropriate distance measure and how to process the features

In k-NN, the classification or the regression estimates depend on the most similar examples based on a distance metric computed on the features. However, in a dataset, not all features can be deemed important in judging an example similar to the other, and not all of the features can be compared in the same way. Prior knowledge of the problem does count a lot using K-NN because you have to select only the features relevant to the task you want to solve. If you assemble too many features for the problem, Figure B shows how a kN algorithm works with two features (represented on the x and y dimensions), and you can intuitively grasp classifying instances (the triangles in the figure) may be difficult if there are mixed classes in an area or if there are no train examples near a new instance. You have to rely on farther ones.

Here comes the curse of dimensionality, which says that as the number of features increases, the more examples you should have to maintain a meaningful distance between points. In addition, the curse implies that the number of necessary examples grows exponentially with respect to the number of features. For a k-NN algorithm, it implies that if you provide too many features, it will work in an empty space if the number of examples is not enough. Looking for neighbors will become daunting, and if you have just assembled relevant and irrelevant features, the risk is that the algorithm will as some examples that are very far from the case you have to, and the choice could be based on features that are not useful for the problem. Hence, if you are going to use k-NN, you should choose with care the features to be used (if you don't know which one, you need to rely on selection) or be very familiar with the problem to determine what should go into the algorithm. Parsimony is essential for the proper use of a k-NN.

When you decided about the features, regarding the distance metric you will use, you will need to standardize, remove redundancies, and transform the features. This because distance metrics are based on absolute measurements, and different scales can weigh in different ways. Considering using measurements in kilometers, meters, and centimeters together. The centimeters will likely predominate because they will easily have the largest numbers. Also, having features similar to each other (the problem of multicollinearity) can entail the distance measurement to outweigh certain sets of features over others. Finally, a distance measurement implies having the same dimensions to measure. However, in a dataset, you may find different kinds of data—numeric, categorical, and time-based—which one need to fit better in a distance calculation because they have different numeric characteristics.

# B.2 SVMs

Before the 2010s, SVMs had a reputation as the most promising algorithm for tabular problems. In the past 10 years, tree-based models have eclipsed SVMs in the go-to approach for tabular data. However, SVMs remain a family of techniques for handling binary, multiclass, regression, and anomaly/novelty detection. They are based on the idea that if your observations can be represented as points in a multidimensional space, there is a hyperplane (i.e., a separation plane cutting through multiple dimensions) that can separate them into classes or values, by ensuring the largest separation between them, also guarantees the most robust and reliable predictions. Figure B.2 shows a simple example of an SVM applied to a binary classification problem with two features, represented on the x- and y-axis predictors. The SVM model produces a separator line with the largest slack space between the two groups, as shown in the figure, where the dashed lines limit the slack space. In doing so, it considers only a few points near the separator, called the support vectors. Instead, it ignores the points that are near but confusing for the algorithm because, for instance, they are on the wrong side. It also ignores the points that are far away from the separator line. Outliers have little influence on this algorithm.
