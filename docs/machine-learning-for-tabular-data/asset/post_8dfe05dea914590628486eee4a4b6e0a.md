## 6.3 Optimizing hyperparameters

Feature engineering can improve the results you obtain from your classical machine learning models. Creating new features can reveal the underlying patterns and relationships in data that the models cannot grasp because of their limitations. Feature selection can improve your models' results by removing useless and redundant features for the problem, thus reducing the noise and spurious signals in data. Finally by optimizing hyperparameters, you can gain another performance boost and have your classical learning model shine on the tabular data problem you are dealing with.

As discussed in chapter 4, hyperparameters are those settings that work under the hood of all machine learning algorithms and determine how specifically they can work. From an abstract point of view, each machine learning algorithm potentially offers a limited, yet wide, range of functional forms—that is, the mathematical ways you can relate predictor variables to your outcome. Straight out of the box, a machine learning algorithm may less or more match the functional required by your specific machine learning problem.

For instance, if you are using a gradient boosting algorithm to solve a classification problem, it may be that the default number of iterations or how its trees are grown not match the requirements of the problem. You may need fewer or more iterations and tree growth then specified by the default values. By optimally your hyperparameters, you can find the best settings that work better with your problem.

However, it is not just a matter of twiddling the many knobs that an algorithm presents until it gets the results you. Sometimes the knobs are too many to be tested, and even if you manage to test enough of them, if not done properly, it will result in overfitting your data and, the contrary, obtaining worse results. You need a systematic search after defining one or more evaluation metrics:

- Defining a search space containing the hyperparameters whose effects you want to explore and the boundaries of the values to test
- Building a proper cross-validation scheme to ensure that you are discovering a solution that generalizes beyond the data you have
- Choosing a search algorithm, by a proper strategy, will find out in less time and with less cost—for instance, in terms of computations—the solution you need

In the following subsections, under the light of different search strategies, we discuss the way you can accomplish tuning some of the classical machine learning algorithms we have seen so far.

### 6.3.1 Searching systematically

Grid search works through all the possible combinations of hyperparameters' values. For every hyperparameter you want to test, pick a sequence of values and iterate through all their combinations exhaustively. In the end, you pick the combination that returns the best results.

In listing 6.12, we apply it to a logistic regression model, to choose the kind of regularization and the settings of L1 and L2 regularization values. The most important part of the code is the search grid, which is a list containing one or multiple dictionaries. Instead, each dictionary is a search space, a sequence of hyperparameters (the keys of the dictionary) associated with a list of a generator of values, which are the possible values you want to test (the values of the dictionary). Structuring one or more search spaces is a common practice across all the optimization methods, whether they are from Scikit-learn or not. Just notice how the name of the hyperparameters are formulated in the model_name_of_the_hyperparameter because we are optimizing a pipeline and addressing parameters that are first internal to the pipeline and then of them. We will come back to this in the next subsection with more explanations.

#### Listing 6.12 Grid search

```python
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import KFold, GridSearchCV
from sklearn.metrics import make_scorer
from sklearn.pipeline import Pipeline
import numpy as np

accuracy = make_scorer(accuracy_score)
cv = KFold(n_splits=5, shuffle=True, random_state=0)

model = Pipeline([
    ('processing', StandardScaler()),
    ('model', LogisticRegression(solver='liblinear', max_iter=5000))
])

search_grid = {
    'model__penalty': [None, 'l1', 'l2', 'elasticnet'],
    'model__C': np.logspace(-4, 4, 10),
    'model__l1_ratio': [.1, .3, .5, .7, .9, .99]
}

search_func = GridSearchCV(estimator=model,
                             param_grid=search_grid,
                             scoring='accuracy',
                             cv=cv)

search_func.fit(X, target_median)

print(search_func.best_params_)
print(search_func.best_score_)
```
