# Using XGBoost

In our case, the Hessian is probably not particularly helpful because it is the same for all due to the kind of objective function we use: the squared error. However, in the context of optimization with other objective functions, the Hessian matrix provides information about the curvature of a function, which can be used to determine the direction and rate of change of the function. Intuitively, you can figure out that with larger curvatures, you have larger Hessian values, which reduce the effect of the gradient acting as a brake for the learning rate. On the contrary, smaller curvatures lead to an acceleration of the learning rate. Using the information of the Hessian, you get an adaptive learning rate for each of your training examples. However, as a side effect, computing the second derivative can be complicated or intractable, necessitating significant computation. Analytical expressions and numerical methods for determining the second derivative require substantial computational effort. In the next chapter, devoted to more advanced techniques, we will provide further information on how to guide your customized objective functions by computing gradients and Hessians analytically and numerically.

A role in the Newton optimization used by XGBoost is also played by the regularization that is used in Hessian and reduces the target further—that is, the adjustment to be made the base learners. Another idea taken from gradient descent uses regularization in the form of L2 regularization, implemented in our example, and L1 regularization. The additional regularization terms help to smooth the final weights and avoid overfitting by directly modifying the Newton descent step. Consequently, it is important to consider how to tune both L1 and L2 values, referred to as lambda and alpha in the XGBoost and LightGBM implementations, as significant hyperparameters for improving optimization results and reducing overfitting. These regularization values ensure that the Newton descent takes smaller steps during optimization.

# 5.4.3 Accelerating with histogram splitting

Gradient boosting is based on binary trees, which work by partitioning the data to have a better-objective metric resulting in splits than the original set. Since gradient boosting treats all the features as numeric, it has a unique way of deciding how to partition. To find the feature to use for the split, a binary tree should iterate through all the features, sort each feature, and evaluate every split. Ultimately, the decision tree should pick the feature and its split point that led to better improvement. With the emergence of larger datasets, the splitting procedure poses serious scalability and computational problems for the original GBDT architecture based on serial models that continuously scan through data. From a computational view, the main cost in GBDT is learning the decision trees, and the most time-consuming part of learning a decision tree is finding the best split.

Continuously looking for the best splitting point takes some time, rendering the algorithm quite demanding when training on large number of features and instances. Histogram splitting reduces the time by replacing each feature's value with a histogram. In doing so, we define a function that can operate both as the original tree splitting or by the faster histogram-based splitting.

# Listing 5.14 The histogram split

```python
import numpy as np

def gini_impurity(y):
    counts = np.unique(y, return_counts=True)
    probs = counts / np.sum(counts)
    return 1 - np.sum(probs**2)

def split(x, y, histogram, n_bins):
    if histogram:
        hist, thresholds = np.histogram(x, bins=n_bins, density=False)
    else:
        thresholds = np.unique(x)
    best_score = -1
    best_threshold = None
    for threshold in thresholds:
        left_mask = x <= threshold
        right_mask = x > threshold
        left_y = y[left_mask]
        right_y = y[right_mask]
        score = gini_impurity(left_y) * len(left_y) + gini_impurity(right_y) * len(right_y)
        if score < best_score:
            best_threshold = threshold
            best_score = score
    return best_threshold, best_score
```

In the code in listing 5.14, after defining a scoring function, the Gini impurity, we define a function that picks a feature and evaluates the values of its potential splits to be evaluated. Using the basic approach, Using the histogram approach, a 256-bin histogram is computed, and we use the bins delimiting values as potential split candidates. If our feature has more than 256 unique values, using the histogram will save a lot of time when we just iterate through all candidates and evaluate them by the scoring function.

Looking under the hood of histogram splitting, we find binning, where values for a variable are grouped into discrete bins, and each bin is assigned an integer to preserve the order between the bins. Binning is also commonly referred to as k-bins, where the k in the name refers to the number of groups into which a numeric value is rearranged, and it is used in histogram plotting, where you can declare a value for k or automatically have it to summarize and represent your data distribution.

The speed-up is not only to a minor number of split points to evaluate, which can be tested in parallel, using multicore architectures, but also to the fact that histograms are integer-based data structures that are much faster to handle than continuous values vectors.

XGBoost uses an algorithm to compute the best split based on presorting the values. The presorting splitting works as follows:

- For each node, enumerating the features
- For every feature, sorting instances by their values
