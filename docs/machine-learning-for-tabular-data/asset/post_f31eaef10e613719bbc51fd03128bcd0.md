## CHAPTER 7 An end-to-end example using XGBoost

The list comprises 18 columns, largely the same as the Airbnb NYC dataset introduced in chapter 3. Here we describe each of them:

- id—A unique identifier for each listing on Airbnb. It is an int64 data type, meaning it is a numerical ID representation. In other tables, it can be referred to as listing_id.
- name—The description of the Airbnb listing. It is the object data type, which typically represents a string or text.
- host_id—A unique identifier for each host on Airbnb. It is an int64 data type.
- host_name—The name of the host who owns the listing. It is of the object data type.
- neighbourhood_group—Represents the broader area or region the neighborhood belongs to. It is stored as a float64 data type, but it is important to note that using a float data type to represent groups or categories is uncommon. In that, the presence of float values indicates the data for this field is entirely made up of missing values.
- neighborhood—The specific neighborhood where the listing is located. It is of object data type.
- latitude—The latitude coordinates of the listing's location. It is of the float64 data type.
- longitude—The longitude of the listing's location. It is of the float64 data type.
- room_type—The type of room offered (e.g., entire apartment, shared room). It is of the object data type.
- price—The price per night to rent the listing. It is of the int64 data type.
- minimum_nights—The minimum number of nights is required for the listing. It is of the int64 data type.
- number_of_reviews—The total number of reviews received. It is of the int64 data type.
- last_review—The date of the last review. It is of the object data type.
- reviews_per_month—The average number of reviews per month. It is of the float64 data type.
- calculated_host_listings_count—The total number of listings the host has. It is of the int64 data type.
- availability_365—The number of days the listing is available for booking in a year. It is of the int64 data type.
- number_of_reviews_1tm—The number of reviews in the last 12 months. It is of the object data type.
- license—The license number or information related to the listing. It is the object type, which typically represents a string or text.

We can safely ignore features as host_id.

As for the other features, whereas most of them are numeric, the name feature is a string containing various pieces of information to be extracted based on how the data has been. By visualizing a single example from it, we can gain an idea of its organization:

```python
summary_listings['name'].iloc[0]
```

The string is arranged into five parts separated by conventional signs:

'Rental unit in Sumida · 4.78 · 1 bedroom · 2 beds · 1 bath'

The first portion of the string is the unit type and location. The second portion is the average score received from guests. The third portion is the number of bedrooms, the fourth portion is the number of beds, and the last is the number of bathrooms. Apart from the numeric values, we can also extract some specific information related to the accommodation or services offered—for instance, if the apartment is a studio, if it is shared, and if it is a half-bath (a room with a toilet and washbasin but no bath or shower). We can deal with this by creating string correspondence and obtaining a binary feature pointing out the presence or absence of the characteristic using regex commands (short for regular expressions) commands are a sequence of characters constituting a search pattern. They are used for pattern matching within strings. Table 7.1 shows the transformations we apply to the description field and highlights what strings we strive to match, what regex command:

Table 7.1 Regex commands for feature engineering
