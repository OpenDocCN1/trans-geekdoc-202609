Table 7.1 Regex commands for feature engineering (continued)

| Matched description | Regex | Resulting feature |
| --- | --- | --- |
| Text containing a numerical value followed by zero or more whitespace characters and the words "bedroom" or "bedrooms" (or without the "s" at the end) | r'(\d+)\s*(?:bedroom |bedrooms)' | Number of bedrooms |
| Text containing a numerical value followed by one or more whitespace characters and the word "bed" or "beds" as a whole word (or without the "s" at the end) | r'(\d+)\s+(?:beds)?\b' | Number of beds |
| Text containing a numerical value representing the number of baths | r'(?P<baths>\d+)\s*(shared|)?(?:half)??baths?\b' | Number of baths |

Working with regex commands is a bit complicated. Hence is this first application where generative AI could help. Most LLMs, like ChatGPT, have a good knowledge of different programming languages (in particular, most of them are strong in Python) that have been trained on and extract information from the internet, where there is plenty of information about how to code even very specific problems. In our case, showing an example of the strings in the prompt and asking for the desired information to be extracted would:

+   I have a series of strings in this format: *Rental unit in Sumida *4.78 - 1 bedroom 2 beds -1 bath* Show me a series of regex commands to extract the following information: 1) the area of Tokyo of the listing 2) the stars expressed as floats 3) the number of bedrooms 4) the number of beds 5) the number of baths.

Usually, the solutions provided may vary from query to query and differ from the solution provided in the table. This is because LLMs are, in the end, probabilistic machines. The temperature parameter is used to influence the randomness of the model's output. It is used during text generation to control the generated content's creativity. In simple terms, temperature affects the likelihood of model choosing the next word in a sequence. Low-temperature values result in more deterministic and expected output.
