The differences between the dataset we used in chapter 8 and the dataset we use now for the comparison between XGBoost and deep learning—that is, a dataset that was previously much larger (with four as many rows as the Airbnb dataset) and much simpler (with less than half many columns as the Airbnb dataset)—for comparison with XGBoost will not weigh in favor of any of the proposed solutions. In fact, Keras and fastai are general-purpose deep learning frameworks and are not specifically designed for small or complex datasets. TabNet's design gives it an edge with high-dimensional data, but when applied to smaller datasets, the advantage over Keras or fastai turns out to be less significant.

What weighs more in our choice is the fact we want a fair comparison between XGBoost and a deep learning approach. As you saw in chapter 7, XGBoost shines with its ease of use, and it gets good results without a lot of tuning. If we decide on a complex deep learning model that takes a long time to set up, tweak, and optimize, it wouldn't turn into a fair comparison for the deep learning model.

Given this deep learning framework which should we choose? We will Pass over Tab-Net because of the complexity of getting it to run reliably. That leaves us with a choice between Keras and fastai. As mentioned in table 12.3, Keras is ideal for production and boasts a larger community. However, fastai aligns better with our goals. Recall that in chapter 8 we noted that fastai is built for tabular data like ours, and it comes with smart defaults. This means you can get decent results quickly, without spending ages on optimizations. fastai handles a lot of the nitty-gritty stuff and details for you behind the scenes. As you'll see later, choosing fastai for this problem paid off. For the moment, we believe it provides a strong deep learning solution for the Airbnb problem without much hassle, ready in a few steps to take on the XGBoost model from chapter 7.
