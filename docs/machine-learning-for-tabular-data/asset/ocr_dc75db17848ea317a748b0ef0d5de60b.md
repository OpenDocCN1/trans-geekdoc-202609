# Review of the gradient boosting solution from chapter 7

The goal of the model we created in chapter 7 was to predict the price of a new listing. This is actually a more challenging problem for a deep learning model than the Airbnb NYC problem that we tackled in chapter 8, as we can see from the comparison in table 12.1.

Table 12.1 Airbnb NYC vs Airbnb Tokyo problem

| | Airbnb NYC | Airbnb Tokyo |
|---|---|--|
| Rows in dataset | 48,000 | 10,000 |
| Columns in dataset | 18 | 31 |
| Target | Classification: predict whether the price is over or under the median price | Regression: predict price |

In fact, the Tokyo Airbnb dataset has fewer than 25% of the records of the NYC Airbnb dataset and over double the columns as the NYC Airbnb dataset. With fewer data points, you need to rely more on domain expertise (hence the role of feature engineering). Having more columns implies there's more risk of overfitting during training, and in any case, you have to deal with more complex relationships between features and the target variable itself.

Generally speaking, classical machine learning approaches can get better results on small datasets than deep learning. Techniques such as data augmentation can mitigate this downside of deep learning, but deep learning approaches will struggle with a dataset with tens of rows. Research on why deep learning requires more data is not complete, but the large number of parameters in deep learning architectures and the need for a certain amount of data for the model to generalize is identified as one of the reasons why deep learning struggles with problems with smaller datasets [see, “The Computational Limits of Deep Learning” by Thompson et al. (https://arxiv.org/pdf/2007.05558.pdf)], which also how computational efficiency is necessary for the approach to proposed]

The smaller number of rows in the Tokyo dataset here clearly presents a challenge for the successful implementation of a deep learning solution. In addition, the larger number of columns in the dataset necessitates more extensive processing and feature engineering to ensure that the resulting features are relevant and useful for modeling purposes. Since we have followed the same data preparation steps as in chapter 7, we should not have to worry about dealing with more columns for this particular application, but it is worth keeping in mind for other datasets that more columns equals coming up with effective strategies for missing values, dealing with multicollinearity (as we discussed in chapter 2), and selecting the most informative features.
