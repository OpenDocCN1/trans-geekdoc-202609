In such cases, you face the challenge of working with similar tables and the identical need to consolidate and assemble them into a coherent structure. For an assembling task between event tables, item tables, and dimension tables, there are different tools available on the market—some of them the no-code type, where you operate without scripting using icons and point-and-click actions. Historically, SQL has been the elective tool for programmers to gather and combine multiple data sources. Still, SQL is the best choice when all your data resides in a relational database. It can help you structure a series of queries and temporary tables until you arrive at a final table to download or directly feed to a machine learning algorithm. When there are multiple sources and we need to handle diverse data types, however, our choice in the first place is pandas to master. Pandas has a lot of functionalities, ordering and processing are extend those of SQL queries. Selecting, aggregating, and processing are as easy as pandas on a relational database, and they follow the same principles, though sometimes based on different terms. For instance, indexes in DataFrames are dissimilar to primary keys in relational databases. In addition, pandas DataFrames present further characteristics that make them more versatile and powerful than SQL for data science tasks:

+   - An API that is common to other tools makes it easy to switch from pandas, which were created for use on a single CPU, multiprocessing or distributed computing.
- You can achieve processing and data exploration at the same time. In particular, it is straightforward to plot the data you have prepared, as we will see at the end of this chapter.
- You have more control of all the changes and the necessary manipulation steps that should happen on the data, which also means that it is easier to make an error, allowing you to store away intermediate results and preserve some data characteristics, such as data types and data ordering, which are sometimes hard to achieve in SQL.
