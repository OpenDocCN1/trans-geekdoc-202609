# 11.1 Introduction to ML pipelines

Consider the steps that we have covered so far in this book to prepare a deep learning model trained on tabular data:

+   * Process the data to deal with problems such as missing values, columns containing distinct kinds of data, and numeric data expressed as strings
* Train the model using the processed data
* Deploy the trained model so that it can be used by an application

Suppose we need to go through this process repeatedly for the Kuala Lumpur real estate problem. This is a reasonable expectation because the real estate market will keep changing as prices rise, interest rates change, and macroeconomic factors affect the demand for real estate. Rather than running the various notebooks and deployment steps manually for each end-to-end cycle from raw to deployed model, it would be better to have a coded solution that we could run as a unit repeatedly. # 11.1.1 Three kinds of pipelines

Before getting into the details of an ML pipeline, it is worth noting that the term pipeline has evolved with different meanings over time. At the moment, there are at least three distinct meanings for the term pipeline that are predominant in the world of ML/data science:

+   * Training/inference pipeline—This pipeline ensures that data transformations, such as assigning text to tokens or assigning values in a categorical to numeric identifiers, are consistently in the training and inference steps. The preprocessing Keras layers in the Kuala Lumpur model constitute this kind of pipeline because they ensure, for example, the transformations done on the processed data prior to training exactly match the transformations done on the data points entered in home.html in the web deployment.
