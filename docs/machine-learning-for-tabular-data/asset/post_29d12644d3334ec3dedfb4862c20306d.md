Random search optimization, in spite of its simplicity and the fact it relies on randomness, and it provides the best optimization in many situations. Many AutoML systems rely on this optimization strategy when there are many hyperparameters, to tune (see, "Google Vizier: Search for Black-Box Optimization", by D. Golubnikov, 2017 at https://mg.bz/80HrZ). Compared to grid search, which works well when you have a limited set of hyperparameters that you expect to be impactful and a limited set of values to tune, random search works the best when you have too many values to tune, without prior knowledge of how they work.

All you have to do is rely on random tests to have a good combination emerge, which may not take long. In our experience, 30 random draws usually suffice for good optimization. One strong point of random search optimization is that it works well for complex problems and is not affected by irrelevant hyperparameters. The number of elements determines how fast you can find a good solution. The algorithm is also suited for parallel search on different computers or instances (you pick the best result among all). Still, this positive point comes with the limitation that since tests are independent, they do not inform each other about their results.

### 6.3.3 Reducing the computational burden

Both grid search and random search do not utilize the outcomes from previous experiments. Grid search strictly adheres to a predefined procedure, while random search conducts a set of independent tests. In both cases, the prior results are not considered or used in any way during the search process. Successive halving, a wrapper of strategies, can instead take advantage of the knowing results. The idea is like that of a tournament where you first hold many rounds and put few resources to test different hyperparameters' values. Then, as you progress and drop the values that underperform, you invest more resources to the remaining values thoroughly. Usually, the resource you initially dilute and then later concentrate on the number of training examples. More examples imply certain results from a hyperparameter test, but it costs more computational power.

### 6.3.4 Extending your search by Bayesian methods

Another optimization strategy that makes informed choices is Bayesian optimization. The idea behind this strategy is to understand how the hyperparameters work, by building a model. Usually, the surrogate function in all of this is nothing more a model. Usually, Gaussian processes are chosen as a model for the surrogate function. Still, there are alternatives, such as using tree algorithms or structured Parzen estimators, which are a multivariate distribution capable of describing the behavior of the hyperparameters. Packages like Scikit-optimize (https://scikit-optimize.github/) or KerasTuner (https://keras.io/keras_tuner/) are Gaussian, with Scikit-optimize also capable of using tree ensembles and KerasTuner using bandits, as well. Optuna, an optimization framework developed by Preferred Networks, a Japanese research and development company, use tree-structured Parzen estimators. Initially released in May 2019 as an open-source project, Optuna is particularly popular in the Python machine learning community due to its simplicity, versatility, and integration with popular machine learning libraries such as TensorFlow, PyTorch, and Scikit-learn.
