The .isna() method will help you keep track of the NaN values in your features. As discussed, a large number of missing values may conceal some interesting pattern and be turned into binary variables. You can use MissingIndicator in Scikit-learn for this purpose. Additionally, depending on your algorithm, you have to deal with missing values whether there are many or just a few. If you use deep learning, you must impute the missing values with a numeric value. Usually, use the mean, median, or mode as replacement for missing values. Still, sophisticated treatments are also based on iterative estimates. An example is IterativeImputer in Scikit-learn. It is helpful to remember that imputing the missing values with zero value is a good strategy for neural networks when your features are standardized and divide by the standard deviation: in such case, the zero value corresponds to the mean for most machine learning algorithms but the approach is different for most gradient boosting implementations such as XGBoost and LightGBM. Sometimes conventional numbers (such as -999) are used in tabular datasets. If you know a certain value points out to a missing value, you have to modify such situation:

```python
data[numeric_feats==-999].sum(axis=0)
```

# Exploratory data analysis

In the previous code, all numeric features against value -999, which is marker for missing data. Basically, any number could be used as marker and you have to know in advance what is used to set missing value. Though a number won't cause any error when training your model, it will seriously mislead its interpretation. Hence, the marker should be addressed to prevent potential misinterpretation by deep learning models. Tree-based models, like gradient boosting and random forests, are better equipped to handle such situations especially when the marker is positioned at extreme end of the feature's distribution.
