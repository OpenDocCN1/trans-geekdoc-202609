# Selecting features

in the backward procedure, you start slow and tend to accelerate after discarding a number of features. The backward procedure may be impractical if you start from many features to evaluate and the training is very slow.

As a rule for procedure, you may set a certain number of features, or you leave the selection algorithm to find the point at adding or removing a feature bears no more improvements to the predictions. A tolerance threshold helps give the algorithm a certain freedom to proceed or not: the larger the tolerance, the more likely the algorithm will proceed in its operations, even if adding or removing a feature somewhat deteriorates the performance.

In listing 6.11, we apply a forward selection to an XGBoost model trained on the Airbnb NYC dataset. The selection algorithm is set to define the correct number of features, and the low tolerance (to 0.0001 on accuracy measures ranging from 0 to 1) should show at the first signs of deterioration of the predictive performances.

# Listing 6.11 Forward selection

from sklearn.feature_selection import SequentialSelector
from sklearn.metrics import accuracy_score, make_scorer

xgb = XGBClassifier(bootstrap='gtree',
                     objective='reg:logistic',
                     n_estimators=300,
