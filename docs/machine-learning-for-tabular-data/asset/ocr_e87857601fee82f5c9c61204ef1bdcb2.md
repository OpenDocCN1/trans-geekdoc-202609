However, there are some minor differences from the XGBoost implementation that you can notice from the code. The eval_metric takes different names (that you can check at https://mng.bz/RVZK) and to suppress the printing of the evaluations during training, you do not use the verbose in XGBoost; rather you have to specify a callback function (log_evaluation) that has been declared at the fitting time in the list of callbacks.

Early stopping has been implemented as a callback function too (https://mng.bz/2yK0). Keeping the declaration of early stopping rounds during model instantiation stays just for maintaining API compatibility with XGBoost. In case you use early stopping as a callback, you have more control over the way the LightGBM stops training:

+   * first_metric_only allows you to indicate to use only the first metric for early stopping or any metric you prefer using.
* min_delta signals the minimum improvement in the metric to keep training, which is usually set to zero (any improvement), but it could be raised to impose strict control over the growth of the ensemble.

In the previous example, you just need to remove the early_stopping_rounds from the LGBMClassifier instantiation and add the proper callback back to the callback list in the method to obtain the same result:

```
early_stopping:
stopping_rounds=150,
first_metric_only=True,
verbose=False,
min_delta=0.0
```

Whatever method you use, the iteration, resulting in the best validation score, will be stored in the best_iteration attribute of a model, and that iteration will be automatically used when predicting.
