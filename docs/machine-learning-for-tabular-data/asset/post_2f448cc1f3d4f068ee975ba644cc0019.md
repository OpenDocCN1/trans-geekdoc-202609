- When zero_missing=true, NA and zeros in sparse matrices (including unrecorded values in [LightSVM]) are treated as missing.

This strategy for handling missing data works well on average, especially if your data is MCAR. This means that the missing instances is completely random and unrelated to any other feature or hidden during process. The situation is different with MAR when missingness is related to other features' values but not to the values of the feature itself and NMAR, where there is a systematic pattern of missing values related to the feature itself and other features. In MAR and NMAR cases, the best solution is to impute these values by other means because the XGBoost and LightGBM strategy for missing data may reveal itself as underperforming.

There are alternatives to imputing missing data, for instance you can create missing data indicators, which are binary features in correspondence to missing instances in a variable. Missing data indicators can prove quite valuable if your data is not completely random, and can work with any classical machine learning algorithm. Another popular solution with decision trees is to assign values to an extreme value (usually a negative value) not used by any variable in the dataset. If you use splits, not histogram-based ones, where values are reduced into bins, missing data replaced by such value can prove an efficient and easy solution.

## 6.1.3 Target encoding

Categorical features, usually represented in a dataset as strings, can be efficiently dealt through different strategies. We already mentioned one-hot encoding in chapter 2 and chapter 4. As one-hot encoding, all the other strategies for categorical features, whether presenting low or high cardinality, require encoding, a procedure to transform data numerically into a suitable format for machine learning algorithms. Although there are some similarities, encoding is not to be confused with embeddings, which is a procedure to reduce high-dimensional data, such as text or images, into a lower-dimensional space while preserving certain characteristics or relationships of the original data. Embeddings are typically learned through neural network-based models and are briefly touched in our book.

The Scikit library offers a couple of encoding solutions:

- OneHotEncoder—For one-hot encoding (i.e., transforming each unique string into a binary feature), which is the solution we have used so far
- OrdinalEncoder—For ordinal encoding (i.e., transforming the string values in a feature into ordered numbers; is LabelEncoder, but it works the same, and it is mainly for transforming categorical targets)

Generally, one-hot encoding works fine for both linear and tree-based models, and ordinal encoding works fine for more complex tree-based models, as random forests and GBDTs, because trees can recursively split on the categorical feature and finally found a set of partitions for predictions.

# CHAPTER 6 Advanced feature processing methods

However, problems arise with high cardinality categoricals when using one-hot or ordinal encoding. High cardinality is a weak point for both linear and tree-based models. When one-hot encoded, high categoricals produce sparse matrices that cannot easily be turned into the shell because of memory limitations. In addition, decision trees with many levels may need help splitting encoded high cardinality categorical features into meaningful partitions for prediction.

There is no fixed standard to declare when a categorical is high cardinality because that also depends on how many rows your dataset has and how large one-hot encoded features generally include IDs, zip codes, and or geographical names with many unique values. For instance, a reasonable threshold could be over 512, but it may be depending on the dataset. Using the rule of thumb that the number of classes in a feature should not exceed 5%–10% of the total rows in the dataset, 512 may be too high for smaller datasets. In such circumstances, standard practice, especially from data science competitions such as Kaggle's, suggests to target encoding (also known as mean encoding).

First presented by Michel-Barrea, "A Preprocessing for High-Cardinality Attributes and Classification Problems" (ACM) SIGKDD Newsletter 3.1, 2001), target encoding is simply to transform the values in a categorical feature into their expected target values. If your value is a regression, target encoding use the average target value corresponding to that value in the dataset, with a classification problem: conditional probability or odds ratio. Such a process, being brought about the risk of overfitting for the model when the category has few in the shell, is mitigated by using a weighted average between the expected value for that category (posterior probability of the target) and the expected value of all the dataset (prior probability of the target over all the training data).

Target encoding is available in the category-encoders package (https://mng.bz/gave), Scikit-learn compatible project for the TargetEncoder class (https://mng.bz/5glqp), and you can install it with a pip install category_encoders command in the shell. In the TargetEncoder class, you have to specify a smoothing parameter (to be fixed at a value above zero) to balance between the posterior probability of the target and the prior probability over all training data. The best smoothing parameter for your data has to be found by experimentation, or you can rely on another similar encoder the James Steiner encoder, which guesses the way to smooth your expected target values based on the variance of the category you want to encode (https://mng.bz/5glqp). The James Steiner encoder makes stronger assumptions about your data. You have to decide among different ways to estimate variance by the model parameter (for regression problems, it is advisable to use "independent" and for classification ones, "binary"). Still, it lifts you from experimenting with different thresholds as if it were a hyperparameter.

In our example, we use the neighborhood feature, which has over 200 unique values, and the latitude and longitude coordinates after mapping them into a 100 x 100 grid space. The mapping returns a feature presenting over 2,000 distinct values, which makes it a high cardinality categorical feature without any doubt. In 6.3, we first bin latitude and longitude and combine them by summing them in a way that results in a distinct code for every bin of latitude and longitude. Binning is obtained by dividing the range between the feature's minimum and maximum value into equal parts. Also, the code snippet performs binning on two features, resulting in sets of integer values for each feature. The values of one feature are multiplied by a factor of 10, which is larger than the maximum value of the other. This ensures that a unique value is always obtained when the two sets of values are summed, regardless of the specific values used.

# Listing 6.3 Creating a high cardinality categorical feature

```python
def bin_2_cat(feature, bins=100):
    min_value = feature.min()
    bin_size = (feature.max() - min_value) / bins
    bin_values = (feature - min_value) / bin_size
    return bin_values.astype(int)

data['coordinates'] = (
    bin_2_cat(data['latitude']) * 1000
    + bin_2_cat(data['longitude'])
)
high_card_categorical += ['coordinates']

print(data['high_card_categorical'].nunique())
```
