We can also extract the tree structure from LightGBM, though the approach is a bit different because the LightGBM package follows a few different conventions. For instance, XGBoost splits the minus until the threshold on the left; LightGBM instead, for each node, defines a rule using minus or major-equal and threshold and splits on the left if it is true and if it is false.

def extract_lggbm_node_info(tree):

def extract_lggbm_leaf_info(tree):
    return [
        tree['leaf_index'],
        tree['origin'],
        tree['count'],
        tree['leaf_value']
    ]

def traverse_lggbm_tree(tree):
    if 'origin' in tree:
        tree['origin'] = "*"
        if not 'left_child' in tree and not 'right_child' in tree:
            return [Leaf(*extract_lggbm_leaf_info(tree))]
        left_branch = tree['left_child']
        right_branch = tree['right_child']
        left_branch['origin'] = 'yes'
        right_branch['origin'] = 'no'
        left_paths = traverse_lggbm_tree(left_branch)

## 6.4.3 Speeding up GBDTs

When the number of cases or available features are many, the LightGBM take long time to train a model on such data. At training time, you can speed up by reducing the cases and features by smaller values of the subsample parameter for each decision tree. However, reducing cases or features may not be optimal for getting the best results from your model. An alternative is using GPUs, which are widespread.

![](img/def89cc476fa39f4c54bd34e78d91674_259_0.png)
**Figure 6.9 LightGBM's plot_tree output**

GPUs can speed up training operations, especially with XGBoost, and in a lesser but significant way, with LightGBM models. From a modeling point of view, your GPU usage is quite straightforward: you just need to specify "gpu_hist" as a value for the tree_method parameter. With the new 2.0.0 version, such method is however deprecated, and users can now instead specify the device parameter. You can set it to "cpu" or device="cuda" to run XGBoost on a CUDA-powered GPU, which is the only option at the moment, but in the future, more GPU types will be supported. If you have multiple GPUs, you can specify their ordinal to choose a particular one; for instance device="cuda:1" will execute on your second GPU.

For XGBoost to perform, you need at least CUDA 11.0 installed and a GPU with capability 5.0. If you have more GPUs available, you can specify which one by the gpu_id parameter, which represents the GPU device ordered by CUDA runtime (usually set to zero if you have a single GPU). Once GPU trains a model, it can be used for prediction on a machine with a GPU. All have set the predictor parameter to gpu_predictor or cpu_predictor if you want to use your GPU. Selecting the predictor parameter to GPU can also speed up things when you want to compute SHAP values and SHAP interaction values for interpretability:

```python
model.set_param({"predictor": "gpu_predictor"})
shap_values = model.predict(X, pred_contribs=True)
shap_interaction_values = model.predict(X, pred_interactions=True)
```

Using a GPU with XGBoost, it becomes a bit trickier with LightGBM. LightGBM doesn't have an option for GPU running but rather requires a special version of itself to be compiled for the purpose. Depending on your operating system (Windows, Linux/Ubuntu, MacOS), the compilation may be less or more challenging. Instructions are available for POSIX systems and for Windows systems. However, if you have any prerequisites ready on your system stated by the instructions, you can just require to directly install it using the pip instruction on your shell or command prompt:

```bash
pip install lightgbm --install-option=--gpu
```

Once everything has been installed, you need to set the parameter device to GPU to expect astonishing performance improvements. However, by LightGBM authors, the best results are obtained on large-scale and dense datasets because of the inefficient data turnover that causes latencies working on smaller datasets. In addition, setting a lower number of bins for the histogram algorithm will make the GPU work more efficiently with LightGBM. The suggestion is to set max_bin=15 and single precision, gpu_use_dp=false, for the best performances.

GPUs are quite useful for speeding up training, there are more options for prediction time. With tree structures readily available, as we have seen in the previous section, it has been possible for specific projects to use such information for rebuilding prediction trees using more programming languages as C, JAVA, or LLVM that can turn your model into pure assemble code. Such tree-compressing projects aim for fast prediction and easier deployment. Examples are Treelite (https://github.com/dmlc/treelite), which can read models produced by XGBoost, LightGBM, and Scikit-learn, and leaves (https://github.com/siboehm/leaves), which is a project for LightGBM only.
