## 2.7 Pathologies and remedies

As a general rule, you must always strive to avoid certain conditions among your features, no matter what their kind, which we previously mentioned when discussing each type of column you have in a dataset.

Previous data from data science competitions can help us see what could go wrong with a tabular dataset. Let's take, for instance, the Madelon dataset (https://archive.ics.edu/ml/datasets/Madelon), which is remembered after many years as a very challenging dataset because of its specific characteristics that make prediction hard. The Madelon dataset is an artificial dataset generated using an ad hoc algorithm developed by Isabel Guyon (https://guyon.chalearn.org/), who joined Google in 2022 as a director. The data has been presented at a contest at the NIPS 2005 conference, the seventh Annual Conference on Neural Information Processing Systems. She placed errors in data in the form of random noise and the target by having a part of the labels flipped. She added redundant and highly collinear features, clustered observations along the vertices of a five-dimensional hypercube without providing information, and finally inserted irrelevant features. That many data scientists strive to wrap their heads around the problem. See https://mng.bz/ga4V for details about the generative process of the synthetic dataset if you are interested.

Recently, Kaggle competitions such as Don't Overfit (https://www.kaggle.com/competitions/overfitting), Don't Overfit II (https://www.kaggle.com/competitions/dont-overfit), Categorical Feature Encoding Challenge I and II (https://www.kaggle.com/competitions/cat-in-the-data and https://mng.bz/jPyP), extending the problem to categorical features and missing data, proved when there are too many problems in data, even the most powerful machine learning algorithms can do little.

Starting from practical examples, generally speaking, the conditions you have to care about the most in tabular data are:

- Avoiding constant or quasi-constant columns
- Avoiding duplicated or highly collinear columns
- Avoiding irrelevant features and prioritize features that demonstrate high predictive power
- Dealing with rare categories or with too many labels with categorical
- Spot incongruencies and misplaces, flipped, or distorted values
- Avoiding too missing cases in a column and handling existing ones
- Excluding leakage features

Let's go through each of these from a theoretical and practical point of view using some artificial data. More-world examples and commands for the detection and resolution of such conditions will be illustrated in our example in the paragraph concluding the chapter. It is pretty challenging to present examples for each of them or find a single real-world dataset distributed to the public containing all bad data examples (actually, such are abundant in private repositories). Public datasets are enough curated to have most of such data traps already exhausted.

### 2.7.1 Constant or quasi-constant columns

Avoid constant or quasi-constant columns. As a rule of thumb, the variance shouldn't approximate zero for numeric features, and the majority class shouldn't be over 99.9% for categorical features. All this is paramount because machine learning algorithms learn only from how empirical expectations of your target vary with respect to your features. No change in the features implies no conditional change on your target from to learn. Constant features result in more cumber to be handled by numerical processes before learning algorithms, and quasi-constant features may even result in some overfitting because the minimal nonconstant part may be deterministically associated with some target output. The solution is to drop constant or quasi-constant columns.

#### Listing 2.2 Dropping zero variance features

```python
import pandas as pd
from sklearn.preprocessing import OrdinalEncoder
from sklearn.feature_selection import VarianceThreshold

data = pd.DataFrame({"feature_1": ['A' for i in range(15)],
                      "feature_2": ['B' if i<=0 else 'C' for i in range(15)],
                      "feature_3": ['I' for i in range(15)]})
ord_enc = OrdinalEncoder()
data[data.columns] = ord_enc.fit_transform(data)
var_threshold = VarianceThreshold(threshold=0)

clean_data = var_threshold.fit_transform(data)
print(var_threshold.variances_)
print(clean_data.shape)
```

An ordinal encoder will transform your data from string labels to numeric codes.

The VarianceThreshold will filter all features whose variance is equal or below the threshold.

### 2.7.2 Duplicated and highly collinear features

Avoiding duplicated or highly collinear columns is helpful because information redundancy makes your learning more robust, there are some caveats. Most rendering becomes more complicated and computationally expensive. First, duplicated features are useless and should be discarded immediately because they just waste memory space and computation time. The discourse is different for highly collinear ones. No matter whether we are talking about numeric features, where you measure collinearity by correlations, or categorical ones, where you measure collinearity by association measures based on chi-square statistics when a set of features are very strongly associated, it is because:

- One is the causative feature of the other. For instance, in a dataset related to academic results, time spent and test scores are highly correlated because time spent is one of the determinants of good test scores, as studies have determined.
- They all reflect a latent feature that causes or influences them. For instance, in a dataset about performance and emissions are partially determined by the type of fuel used. Even if the feature characteristics are not recorded in the data and their relationship is not apparent, the performance and emissions features will be strongly associated with each other.

In the first situation, the solution is simple because you just have to keep the causative feature and drop all others. Nothing will tell you which is the causative feature, and you can basically figure out which one is only by domain knowledge, theoretical deductions, or causal analysis, which requires additional modeling and experimentation.
