+   - Avoiding constant or quasi-constant columns
- Avoiding duplicated or highly collinear columns
- Avoiding irrelevant features and prioritize features that demonstrate high predictive power

- Spot incongruencies and misplaces, flipped, or distorted values
- Avoiding too missing cases in a column and handling existing ones

# 2.7.1 Constant or quasi-constant columns

Avoid constant or quasi-constant columns. As a rule of thumb, the variance shouldn't approximate zero for numeric features, and the majority class shouldn't be over 99.9% for categorical features. All this is paramount because machine learning algorithms learn only from how empirical expectations of your target vary with respect to your features. No change in the features implies no conditional change on your target from to learn. Constant features result in more cumber to be handled by numerical processes before learning algorithms, and quasi-constant features may even result in some overfitting because the minimal nonconstant part may be deterministically associated with some target output. The solution is to drop constant or quasi-constant columns.
