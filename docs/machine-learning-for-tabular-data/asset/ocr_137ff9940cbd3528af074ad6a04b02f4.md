Table 3.1 Comparing the code complexity of XGBoost and Keras in three areas

| Aspect of complexity | XGBoost | Keras deep learning model |
|---|---|---|n| Data preparation | Code block required to transform the list of numpy arrays into numpy array of lists | NA–the data preparation was designed with the Keras deep learning solution in mind |
| Model definition | Single statement, consistent with the Scikit-learn pattern | Block of code required to define the layers of model, with unique sets of layers for each type: continuous, categorical, text |
| Model training | Single statement, consistent with the Scikit-learn pattern | Block of code required to allow callback of the training process to avoid training iterations that provide benefit and to ensure the process outputs the trained model with the best performance |
| Model saving | Single statement, consistent with the Scikit-learn pattern | Included as part of model saving callback |
| Model loading | Block of code—requires installing the latest version of XGBoost or loaded model will fail with error: AttributeError: 'XGBClassifier' object has no attribute '_le' | Single statement

Let’s look at the code in the NYC solution for each of these aspects of complexity.
The XGBoost solution has some additional data preparation code. The Airbnb NYC solution was originally created using Keras deep learning and the XGBoost solution was created using the Keras solution as a starting point. The original Keras model required training input in the form of a list of numpy arrays. XGBoost requires input in the form of a numpy array of lists.
