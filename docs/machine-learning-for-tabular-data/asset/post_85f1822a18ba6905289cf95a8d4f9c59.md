Let's imagine having three tables in a data warehouse, each containing different information about a company's products. These tables need to be joined to create an analysis or train a machine learning model, as shown in figure 2.2.

The task is a quite simple example that would require a SQL query to return a dataset combining the three of them:

```sql
SELECT df1.product_id, df1.product_name, df1.price,
df2.product_description, df2.category, df3.manufacturer, df3.weight
FROM df1
JOIN df2 ON df1.product_id = df2.product_id
JOIN df3 ON df1.product_id = df3.product_id;
```

The same could be easily achieved using the merge function, keeping control of the various stages where the data is merged and having ready for further transformations to render it suitable to machine learning.

## Listing 2.4 Merging datasets in pandas

```python
import pandas as pd
df1 = pd.DataFrame({'product_id': [1, 2, 3, 4], 'product_name': ['Product A', 'Product B', 'Product C', 'Product D'], 'price': [10.99, 20.99, 15.99, 8.99]})
df2 = pd.DataFrame({'product_id': [1, 2, 3, 4], 'product_description': ['A great product', 'A high-quality product', 'A reliable product', 'An affordable product'], 'category': ['Category A', 'Category B', 'Category C', 'Category D']})
df3 = pd.DataFrame({'product_id': [1, 2, 3, 4], 'manufacturer': ['Manufacturer A', 'Manufacturer B', 'Manufacturer C', 'Manufacturer D'], 'weight': [1.5, 2.0, 1.8, 1.2]})
merged_df = pd.merge(df1, df2, on='product_id')
merged_df = pd.merge(merged_df, df3, on='product_id')
print(merged_df)
```

As stated in the previous point, different products have more or less compatibility with pandas:

- Dask (https://www.dask.org/) is an open-source library that presents both low-level and high-level interfaces for the user. It is designed to run on cluster. Dask can also work in multiprocessing on multiple CPU processors, and it handles out-of-core tasks easily. In these tasks, you process more data than your RAM can handle by working it by chunks on the disk. This data structure copies the pandas API but is much more capable of handling many rows.
- Ray (https://www.ray.io/) is a low-level framework that parallelizes Python code across processors or clusters. It is also as a backend for other high-end solutions, such as Modin.
- Modin (https://github.com/modin/modin) is the most compatible tool with pandas API. It works by just a simple replacement as import modin pandas as pd, and it performs better with Ray as a backend.
- Vaex (https://vaex.io/) is a Python library for lazy out-of-core DataFrames (pandas). You can also visualize and explore big datasets on your stand-alone machine or server. Being lazy, it can optimize its operations and reach a performance of up to a billion objects/rows processed per.
- RAPIDS (https://rapids.ai/) is a collection of libraries for using GPUs computational capabilities on large matrices. It also uses cuDF, a partial replacement for pandas. Data processing (to compute), not scalability, can improve efficiency (time to compute), because GPUs access your memory to determine what to calculate.
- Spark (https://spark.apache.org/) is a solution for map-reduce, a big processing technique, graph algorithms, streaming data, and SQL queries running on single-node or clusters. It offers various packages and a DataFrame data structure similar to pandas. It is the solution best suited to handling massive quantities of tabular.
- Polars (https://www.polars.rs/) is designed as a high-performance DataFrame library. It is written in Rust, which allows for faster execution, comparable to C/C++, and distributive computations. Polars also has better memory management and large dataset handling and using a columnar storage format.
