## 3.1.4 Training features

The goal of both solutions is to predict whether a given Airbnb listing will have a price that is above or below the average price in the input dataset. To achieve this, both models are trained on the same set of features. The subset of features that we will use to train the model is defined in the config file for model training: https://mng.bz/OE. The following is the portion of the config file that specifies the features used to train the models:

```
categorical: # categorical columns
- 'neighbourhood_group'
- 'neighbourhood'
- 'room_type'
continuous: # continuous columns
- 'minimum_nights'
- 'number_of_reviews'
- 'reviews_per_month'
```

The config file also includes a list of features that are excluded:

```
excluded: # columns not used
- 'price'
- 'id'
- 'latitude'
- 'longitude'
- 'host_id'
- 'last_review'
- 'name'
- 'host'
```

The reasons why these columns are not used are as follows:

- price is the target variable we want to predict.
- id is a unique identifier and not a predictive feature.
- latitude and longitude are handled by specific methods or excluded in this simple model.
- host_id is a unique identifier.
- last_review and name are text-based data that require more complex processing.
- host is not used for this specific model.

If the solutions only differ in these files, how can we use this example to contrast the simplicity of XGBoost vs deep learning? Table 3.1 compares the code complexity across several areas.

| Aspect of complexity | XGBoost | Keras deep learning |
| :--- | :--- | :--- |
| Data preparation | Code required to transform the list of arrays into numpy array of lists | NA–the data preparation was designed with the Keras solution in mind |
| Model definition | Single statement, consistent with the Scikit-learn pattern | Block of code required to define the layers, with unique sets of layers for each type: continuous, categorical, text |
| Model training | Single statement, consistent with the Scikit-learn pattern | Block of code required to allow callback of the training process to avoid overfitting and to ensure the process outputs the trained model with the best performance |

| Model loading | Block of code—requires installing the latest version of XGBoost or loaded model will fail | Single statement |
