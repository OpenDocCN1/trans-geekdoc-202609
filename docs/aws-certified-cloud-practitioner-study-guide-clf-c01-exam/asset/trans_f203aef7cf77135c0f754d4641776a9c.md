`[https://docs.aws.amazon.com/AmazonS3/latest/user-guide/what-is-s3.html](https://docs.aws.amazon.com/AmazonS3/latest/user-guide/what-is-s3.html)`

AWS 文档还有其他形式，如你在接下来的章节中会发现。

### 知识中心

AWS 知识中心 (`[https://aws.amazon.com/premiumsupport/knowledge-center](https://aws.amazon.com/premiumsupport/knowledge-center)`) 实际上是一个常见问题解答（FAQ）页面，它不小心吞下了一包体积大到药瓶大小的类固醇，然后穿着湿漉漉的睡衣走进了核电站的放射性核心。或者，用更通俗的话说，这里收集了大量信息。

知识中心页面包含按服务分类的近 1,000 个问题，每个问题都是 AWS 实际客户经常遇到的常见问题。你会看到诸如“如何在 Ubuntu 或红帽企业 Linux 上安装 AWS CloudFormation 辅助脚本？”以及“当我的预留实例到期后会发生什么？”等问题。

选择一个问题后，会跳转到一个提供解决方案的页面，并有更多指向相关信息的链接。如果你卡住了，快速浏览一下知识中心，看看是否已有解决方案，通常是值得的。

### 安全资源

AWS 明确表示希望你的部署尽可能安全。它通过维护一条专门的文档页面，提供有用且实用的安全相关资源链接来简化实现。该页面位于 `[https://aws.amazon.com/security/security-resources](https://aws.amazon.com/security/security-resources)`，指向 AWS 博客、白皮书、文章和教程，涵盖安全最佳实践以及在传输中和静止时加密数据等主题。

AWS 会不断添加新内容，博客的链接始终指向最新、最新鲜的内容。

### 讨论论坛

当事情不按预期工作时，通常可以安全地假设你并不是第一个遇到这个特定的“砖墙”。即使只有少数人（比如几十人）遇到过，也有很大概险在某个在线论坛上有人提出过类似问题。虽然很多问题可能是在 Stack Overflow 或其他公共站点上提出的，AWS 讨论论坛同样处理了不少问题。

论坛所在的站点（`[https://forums.aws.amazon.com](https://forums.aws.amazon.com)`）分为多个类别，包括 Amazon Web Services（进一步细分为各个服务）、AWS Startups（面向新入门者）、AWS 网站与资源（如 Java 开发、高性能计算等）以及服务于非英语使用者的日语、德语等区域。你可以在整个站点或单个论坛中搜索，看看你的问题是否已经得到解答。

要在论坛发帖，你需要登录 AWS 账号，并拥有论坛昵称和邮箱。

### Trusted Advisor

你使用 Trusted Advisor 来直观确认账户资源配置是否符合最佳实践。Trusted Advisor 将合规性警报分为五个类别，如 [表 3.3](#c03.xhtml#table3-3) 所述。

[**TABLE 3.3**](#c03.xhtml#tableanchor3-3) Trusted Advisor 警报的五大类别

| 类别 | 目的 | 示例 |
| --- | --- | --- |
| 成本优化 | 识别运行中但浪费或闲置的资源，导致不必要的支出 | 闲置的 EC2 实例或 Redshift 集群 |
| 性能 | 识别可能阻碍性能提升的配置设置 | 过度依赖慢速磁盘或低吞吐量 EBS 卷 |
| 安全 | 识别未遵循安全最佳实践的配置缺失 | S3 桶公开可访问或安全组开放访问 |
| 容错性 | 识别因配置不当而不必要暴露于服务中断的资源 | 未做备份的数据卷或未复制的实例 |
| 服务限制 | 识别使用量接近 AWS 区域或服务限制的情况 | 贴近 S3 桶 100 个限制的使用量 |

一个 advisor *check* 的状态由其左侧的图标体现。[Figure 3.1](#c03.xhtml#figure3-1) 展示了健康的服务限制状态示例。如果，例如，你未为根账户启用多因素认证，则会出现红色警报图标，提示你应认真处理此问题。每个项目都可以展开以提供上下文信息。

![FIGURE 3.1 The green “healthy” icon indicating that these services are not approaching their service limits](images/c03f001.jpg)

[**FIGURE 3.1**](#c03.xhtml#figureanchor3-1) 绿色“健康”图标，表示这些服务未接近服务限制

如前所述，Trusted Advisor 的完整警报范围仅对 Business 或 Enterprise Support 服务层的用户可见。其余用户（包括免费 Basic Support 计划）仅能查看服务限制和部分安全警报。所有用户均可浏览已下线的完整警报历史，以了解自己错失的内容。

这是一个自动化服务，正如你在 Exercise 3.2 中所见，你会遇到一些误报。例如，Trusted Advisor 会标记任何公开可访问的 S3 桶，这通常暗示严重问题，但有时（如使用该桶托管静态网站）正是期望的行为。因此，请不要盲目遵循所有建议，它是 *顾问*，而非你的母亲。

## 总结

AWS 提供四种支持计划供选择。Basic 计划免费，Developer 计划起始价为 $29，Business 计划起始价为 $100，Enterprise 计划起始价为 $15,000。非免费计划（超出最低收费）按总月度资源使用量的百分比收费。支持级别越高，提供的技术故障排除和规划支持越及时且个性化。

-   **Developer Support** 计划面向正在测试和规划部署的组织。
-   **Business Support** 计划适用于运行相对轻量生产基础设施的较小规模业务。
-   **Enterprise Support** 计划适合全球部署、不能容忍停机的大型生产环境。

AWS 提供详尽且定期更新的文档，采用多种样式在多个网络平台上呈现，包括用户指南页面、知识中心、安全资源以及讨论论坛。

AWS Trusted Advisor 通过警报提醒用户其运行账户资源的最佳实践合规性。Basic 和 Developer Support 用户仅获取服务限制和部分安全信息，而 Business 与 Enterprise 客户则可访问全部警报。
