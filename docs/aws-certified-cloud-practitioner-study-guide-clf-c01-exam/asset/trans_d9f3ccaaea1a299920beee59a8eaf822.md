
IT安全是一个不断变化的目标。尽管管理去年的威胁很困难，但你知道新的威胁会紧随其后。作为企业，你已经负责保护办公室中运行的工作站和网络硬件，并保障组织的数据以及开发人员在应用中写入的代码的安全。底层服务器基础设施的完整性只是你需要担心的又一个潜在漏洞。

无论你的IT安全团队有多么出色，他们可能并不比大型云服务提供商的同行更了解、更具备装备或更受培训。因为AWS在做好其平台底层网络和计算基础设施安全方面表现出色，并且对平台的安全承担责任，这正是外包通常是合理的地方。

这不会让你免除所有担忧。正如第4章“了解AWS环境”将会向你展示的那样，AWS共享责任模型的条款意味着，在很多情况下，你在云上运行的资源的安全和完整性仍然是你的问题。但*云本身*由AWS管理。

### 计费模式

任何公共云计算平台的一个决定性特征是它会自动分配资源以满足客户请求。实际上，这意味着你可以，例如，登录AWS浏览器控制台，定义并启动一个虚拟服务器（在AWS世界中称为*实例*），几秒钟后你的新实例就会准备就绪。无需等待AWS员工进行手动干预。

自助式系统的灵活性使得一些在传统计算范式中不可能实现的使用模式得以实现。假设你需要快速测试一个正在开发的应用配置。在旧时代，即使测试只持续一小时，你仍需要在服务器机房中寻找空闲的物理服务器容量。测试结束后，即使该容量闲置，你仍需支付该服务器容量的维护和所有权成本。

相反，在云中，你启动一个实例，运行它所需的测试时间，然后关闭它。你只需为这段时间付费，在某些情况下，费用可能低至一分钱的几十分之一。

由于云计算计费不涉及人工处理，提供商向用户收取几分钱甚至数千美元的成本 similarly 容易。这种按使用计费的模式使得你可以尝试全新的测试和交付应用的方式，并且通常意味着你的成本周期支出会显著低于使用本地物理服务器的情况。

要对比云部署与本地部署的成本，你需要充分考虑资本支出（capex）和运营支出（opex）两方面。本地基础设施往往资本支出很重，因为你需要一次性购买大量昂贵的硬件。而云操作几乎没有资本支出，你的成本是持续发生的，主要是按小时租用资源的费用。

关于AWS计费的更多内容将在第2章“了解你的AWS账户”中详细说明。

## 服务器虚拟化：基础知识

让云提供能够以各种配置向客户提供按需计算资源的秘诀是虚拟化。当你请求一个具有特定处理速度、内存容量和存储大小的*虚拟机*（VM）时，AWS不会派一些普通工程师在数据中心的走廊里寻找正好匹配该配置的现有机器。相反，如[图1.1](#c01.xhtml#figure1-1)所示，AWS会从较大的现有设备中切分出所需的资源。

![FIGURE 1.1 VMs accessing storage and compute resources from their host server ](images/c01f001.jpg)

[**FIGURE 1.1**](#c01.xhtml#figureanchor1-1) VMs accessing storage and compute resources from their host server 

例如，一个5 TB的存储驱动器可以被分割成数十个较小的虚拟卷，每个卷对应一个不同的虚拟服务器（或实例）。单个物理服务器的资源可以在多个实例之间透明地共享。这些实例上安装的操作系统可以毫无觉察地运行，因为它们实际上只掌控着更大服务器环境中的一小部分资源。

虚拟化模式带来两个极具吸引力的好处：

*   **速度：** 定义、购买、配置、测试并启动新的物理服务器可能需要数月时间。即使是一次简单的重启也可能让你等待数分钟。请求新的云端VM并登录、开始工作的时间可能只有秒级，绝不会超过几分钟。重新启动VM的速度甚至可以快于你输入登录信息的时间。

*   **效率：** 很少能在非虚拟化的物理服务器上实现接近100%的利用率。更可能的情况是，服务器要么大部分时间闲置，要么被过度使用，直到你等待更多容量上线。多个虚拟机可以通过超融合（hypervisor）技术紧密打包在同一台物理服务器上。当一台服务器腾出空间时，你可以迅速将另一个虚拟工作负载填入。当服务器达到容量上限时，溢出工作负载可以迁移到其他机器。你管理的工作量越多，系统的灵活性就越高。

得益于Amazon强大的规模和物流能力，它常常能够利用虚拟化的优势，提供更高的性能和更优的价格。

## 云平台模型

云服务有多种形态。选择适合你项目的形态取决于具体需求以及你需要对底层“杠杆”和“开关”拥有多大程度的控制。

### 基础设施即服务（IaaS）

基础设施即服务（IaaS）产品通常模拟你管理物理资源时的使用体验。IaaS产品直接提供提供商的计算、存储和网络资源。由于你在操作硬件层面，责任在你而非IaaS提供商——你需要为任何配置不当的后果承担责任。其代价是你能够细致配置操作栈的每一层。

稍后在本书中会有更多示例，但AWS的IaaS产品包括弹性云计算（EC2）用于虚拟机实例、弹性块存储（EBS）用于存储卷、以及弹性负载均衡。

### 平台即服务（PaaS）

与IaaS不同，平台即服务（PaaS）产品通过*隐藏*其运行基础设施的复杂性来简化应用的构建过程。你通过一个界面定义应用的行为和环境，这通常包括运行应用的代码。

AWS的PaaS产品包括弹性Beanstalk和弹性容器服务（ECS）。

### 软件即服务（SaaS）

软件即服务（SaaS）产品提供面向最终用户的服务。最典型的例子是Google的Gmail服务，它让用户通过浏览器界面或本地运行的邮件客户端（如Microsoft Outlook）管理邮件。

虽然有些人可能对这一分类持异议，但AWS的SaaS产品可以认为包括Simple Email Service和Amazon WorkSpaces。
