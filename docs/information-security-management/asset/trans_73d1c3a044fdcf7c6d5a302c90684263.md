## 2.1 软件工程与开发

无论是在保险、银行、零售等垂直行业工作，还是为提供软件产品的公司工作，组织通常会拥有软件工程与开发部门，或在许多情况下是信息技术（IT）部门。大多数组织将软件工程与开发与技术支持角色区分开来。技术支持（tech support）如你所想象，是在软件部署到客户后提供支持，包括识别并报告缺陷（bug），有时进行修复，或解决基础设施问题，如修改应用程序或系统配置。大多数公司都有内部和外部两类技术支持团队——分别负责内部客户和外部客户。

软件工程与开发主要涉及编程任务，以及设计和其他技术功能。编程可能用于开发应用程序，或用于基础设施自动化、编写应用程序接口等。计算机编程涉及利用逻辑和数学（主要是代数）来制定指令，从而生成代码。在计算机程序中，逻辑包括赋值运算符、条件判断，以及通过循环、函数调用或实现控制逻辑（如 if–then–else）来重复程序指令。常见语言有 C++、Java、Python 等脚本语言，以及 JSON、YAML 等标记语言。重要的是，还有自动化工具，其中一些会生成代码。对于 Amazon Web Services（AWS®），我们常看到 CloudFormation® 和 Elastic Beanstalk®；对于云和本地系统，我们经常看到 Ansible® 和 Jenkins®。这些工具提供自动化的方式来打包和部署程序、程序包、库以及其他技术基础设施的组件。它们还能够从 GitHub 等仓库拉取代码修订，并创建分支或额外的修订，例如使用 Git、CVS 或 Subversion（SVN）或其他版本控制系统。

从传统意义上说，软件工程与软件开发有所不同，尽管两者可能都涉及编程。事实上，软件工程师和软件开发人员可能是同一个人。工程涉及系统的设计和架构要素，包括基础设施规格、应用程序程序接口（APIs）、网络和操作系统。工程功能通常基于一组需求，将其转化为架构、设计和框架。软件开发功能主要涉及应用程序和工作流的编程。

在大多数情况下，具体的逻辑规格和需求由业务分析师和其他利益相关者开发，这些需求必须从这些规格转化为逻辑和物理设计，最终转化为编程代码。我们称该过程中的编码和单元测试部分为“开发”。当所有的开发组件都经过测试时，会进入质量保障（QA）团队进行功能测试和集成测试阶段。部分工作具有分析性，需要解决问题并将抽象概念具体化为软件；部分工作则是机械性的，如编写文档或使用生成文档的工具，或生成编程代码。我们称从软件构思到软件部署的完整流程为软件开发生命周期（SDLC）。

### 2.1.1 DevOps 与软件开发生命周期

历史上，开发部门和运营部门位于 SDLC 的两端，各自拥有不同的优先事项。开发部门负责在进度和预算范围内交付软件，而运营部门的任务是确保持续、成本效益的业务运行。DevOps 是一种较新的方法论，旨在通过实施流程和实践，使这两个部门更加紧密合作，实现共享责任，从而提升软件构建的速度和灵活性。两个部门都强调通过自动化构建和部署应用程序及相关基础设施的必要控制和功能来提高效率。DevOps 通常与一种称为 Agile 的软件开发方法相结合。Agile 有多种变体，但主要的两种流派是 SCRUM 和 Kanban。

Agile 是一种迭代式软件开发方法，灵感来源于橄榄球，团队成员协同工作，利用团队成员的优势和角色来实现目标。诸如“scrum”（冲刺）和“sprint”（冲刺周期）等术语均源自该运动。简单来说，这意味着任务被组织进所谓的“待办列表”，其工作量以“故事点”进行估算和框架化，然后被放入用于不同阶段推进的“泳道”。任务通过一系列短时的“冲刺”（sprints）逐步演进——冲刺是短时间的集中努力。工具如 Jira® 用于跟踪任务阶段，而每日“站会”（stand-ups）则由团队成员快速报告任务状态。

Agile 与 DevOps 相辅相成，实际上是互补的。由 SCRUM 主管和产品负责人（POs）领导，团队被组建，并共同在整个 SDLC 过程中从构思到部署推进开发。一个重要的“仪式”是在开发周期结束后进行的回顾会（retrospective），团队在此会议中总结经验教训，并将其纳入下一个开发周期。

在信息安全及更具体地说，网络安全领域，团队成员负责代码审查；他们确保代码符合法规和编码规范，对代码进行缺陷和漏洞扫描，并负责修复发现的问题。存在静态和动态代码分析工具。静态代码分析工具通过检查源代码来报告漏洞，例如未参数化的输入可能导致 SQL 注入攻击。在此基础上，它们可能结合使用“设计模型器”（design modeler），如 GNS3® 或 Microsoft 的 Threat Modeling Tool®，用于绘制架构和配置图，并生成需要考虑的漏洞报告。
