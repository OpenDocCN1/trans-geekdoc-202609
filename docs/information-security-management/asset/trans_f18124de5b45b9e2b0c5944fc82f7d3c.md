
DevSecOps 继续将 DevOps 概念扩展，在生命周期中纳入 IT 和网络安全。它涵盖整个 IT 栈，包括主机和服务器、终端节点、计算机（台式机、笔记本电脑、移动设备和手机）、容器、云设备、应用程序以及所有物联网（IoT）设备。DevSecOps 还包括从开发到运维的全生命周期的程序和任务，其主要目标是识别并防止在运营、监控和防御系统及应用程序中的漏洞。最终，DevSecOps 涵盖 SDLC 的主要类别，包括业务安全、运营安全、开发安全、内部安全和未计划安全。该方法致力于在规模上强制执行基础设施配置和合规性，交付可在该类环境中得到保护的移动和云原生解决方案，并比传统方法（涉及更长的规划和评估周期）更快地修复基础设施和网络安全问题。换言之，该方法在持续的基础上通过短迭代周期进行计划和实施。安全风险和任务按影响最大、发生可能性最高的顺序进行优先级排序，然后创建待办清单。从该待办清单中分配任务给最有能力修复它们的人员。

| 业务安全 | 确保运营连续性、应急预案、资源管理、评估并实施人员安全控制，包括招聘前的背景调查，以及通过身份验证、授权、基于角色的访问控制、加密和合规措施实施访问控制。 |

| 运营安全 | 包括基础设施监控、入侵检测与防御、扫描、防火墙管理、应用安全补丁、软件升级、漏洞修复、错误修复、响应警报、严重一级呼叫、升级、安全管理、资产管理、运营分析等类似活动。 |

| 内部安全 | 处理行为和分析性威胁，特别是内部人员威胁。Splunk® 行为分析技术专门针对内部安全开发。这些技术还涉及内部控制，如安全策略（书面和代码化）、访问控制、权限管理、监控等。 |

| 安全未知项 | 使用预测分析和建模来预测新攻击，进行风险评估，审查攻击趋势，查看来自 CERT 等来源的常见漏洞，并实施相应的预防措施、紧急安全补丁、审查安全架构，并深入研究安全研究以了解威胁和对策的趋势。 |

### 2.1.3 信息安全管理生命周期

与 SDLC 类似，信息安全管理生命周期（ISML）由迭代阶段组成。通常包括安全分析与规划、安全设计、安全测试、安全实施以及安全审计与评估。由于阶段是迭代的，审计和评估的反馈会回流到分析与规划阶段，从而重新启动循环。安全分析与规划职能是所有部门的共同责任，但相对于工程和开发，这一阶段是将资产和资源根据价值、敏感度和暴露程度进行分类的地方。根据识别出的威胁和漏洞，制定安全需求。还会建立风险缓解策略和应急预案，以及业务连续性和恢复计划。这些偏向行政性质，但需要工程和开发团队的输入。

随后进入设计阶段，制定安全策略和流程。设计阶段包含逻辑设计和物理设计两个方面。逻辑设计涉及确定将要实施的安全措施的范围和深度。物理设计则基于成本效益和风险评估，选择用于保护信息和网络安全的技术和技术手段。根据具体技术或手段，可能会进行实施前的测试阶段，以评估计划安全措施的质量和影响。安全测试阶段可与实施同步或在实施之后进行。随后制定安全标准和检查表，用于在审计和评估信息的保密性、完整性和可用性时使用。

ISML 的一部分是提出并回答关键安全问题，例如：(1) 如何在 CI/CD 环境中管理应用程序的部署，确保包含安全补丁、版本控制和漏洞测试与修复等关键要素；(2) 如何在负载高峰、低谷或拒绝服务攻击时动态扩展基础设施；(3) 当基础设施和应用程序受损时，如何进行修复并实现自愈；(4) 如何安全存储（或保险箱）敏感信息并防止未授权访问；(5) 如何通过不同形式的密码学和密钥管理安全处理数据；(6) 如何配置防火墙并进行防火墙修改；(7) 如何确保系统和资源的高可用性（HA）。

### 2.1.4 SDLC 与信息安全

如前所述，SDLC 包含将新服务引入或开发软件应用、技术或整合新系统的全部过程。相对于信息和网络安全，安全配置管理（SeCM）是一个相关概念。大多数现代 SDLC 都使用某种迭代过程，如前文所述。为了理解系统的行为，业务分析师、系统架构师、设计师和系统开发人员（以及可能的设计团队）会阐述需求如何确定、逻辑和物理设计、代码编写以及测试程序。正是在这一阶段或迭代中，团队实现对问题的理解，并确定所要解决的应用——即收集需求并确定可行的解决方案。
