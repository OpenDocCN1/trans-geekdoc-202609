
业务分析师可能使用所谓的“故事板”或“故事卡”，这些内容会导向所谓的“功能声明”。从这些功能声明中，我们可以构建信息生态系统的模型。在 UML 中，用例描述业务流程以及程序组件之间的交互。当涉及信息和网络安全的功能或要求时，这些内容形式相同，但特性不同。

在更为严格的流程中，技术管理者更容易确保安全已被涵盖，例如防止“后门”被编写，或遵守一组强制性标准。在像 Agile 这样适应性和演进性的方法中，由团队——而不仅仅是管理者——来做出这一判断，有时唯一的把关者是产品所有者（PO），他们代表利益相关者，以及 SCRUM 主管，后者维护流程并保持团队专注于手头的任务。虽然这些灵活的开发方法有时能提升生产力和质量，但它们往往以功能为导向，有时会让“狐狸守鸡舍”，为恶意内部人员后来的利用留下漏洞。因此，必须纳入 ISML。通过 ISML，团队强调安全特性和安全意识。此外，技术管理者不应放弃监督职责，而应在整个 SDLC 中保持参与，以确保安全得到实施和审查。

技术管理者需要完成至少两项关键工作。首先，我们应坚持设立专门针对安全要求的审查循环。其次，应审查业务要求——如用例或功能声明——以确保业务要求、质量指标和安全要求均得到满足。技术管理者应在产品所有者（PO）参加审查会议之前完成审查，并在会议后审阅结果和决策，确保存在渠道以纠正会议中发现的任何问题。

### 2.1.5 规划：失败是常态，而非例外

即使系统在设计时已考虑安全，事情仍会出错。技术管理者制定应急预案并非因为他们希望使用，而是因为他们预期在特定情况下会用到。应急预案列出了在开发、实施或业务运营因某些事件或“事件”而受到干扰时所需的要求和步骤。应急预案可能使用“情景”来设想可能导致网络和系统不可用的事件，包括因意外或自然灾害引起的情况；例如，它们处理因火灾、洪水、暴风雨或地震等自然灾害导致的数据处理能力丧失。

实际上，应急预案是一种框架，在其下进行多种其他类型的规划。虽然应急预案的核心是最小化因自然灾害或人为攻击导致的技术或信息资源停机时间，它还包含灾难恢复规划，在灾难发生时提供信息处理和恢复的替代方案。它还包括设施管理，涵盖防火程序、离站备份存储设施以及利用分布式操作和监控中心来防止单点故障并支援恢复作业。应急预案因此确立了通过规划和实施物理、技术和行政对策来应对威胁的方式。

| 物理对策 | 这些包括在系统故障时使用“热备”冗余系统，采用“独立磁盘阵列”（RAID）镜像数据以防磁盘损坏，在电力中断时使用“不间断电源”（UPS），使用物理屏障和电子或生物锁，将备份介质运送到离站存储设施以防火灾或洪水破坏现场，为服务器机房选择化学灭火剂（对设备的危害小于水）的灭火系统，或利用共 colocations（ colocated facilities）在不同地点复制计算设施，以便在一处受影响时另一处可接管工作。 |
| --- | --- |
| 技术对策 | 这些包括使用防病毒扫描器、系统硬化、使用防火墙和加密技术。换言之，技术控制涵盖所有用于防止未经授权访问信息资源、防止程序和数据被篡改、以及使用入侵或未经授权访问检测系统，并在检测到攻击后阻断或阻止攻击者连接系统的技术与技术。 |
| 行政对策 | 这些旨在确保没有单个人能够单独执行关键任务，例如在系统管理员离职时，确保所有配置、密码和加密能够恢复。它还包括确保员工在紧急或灾难情况下知道如何应对，以及制定良好的安全政策，确保人员不仅了解这些政策而且真正理解并严格遵守。 |

### 2.2 生命周期流程

如前所述，DevOps 是一种利用由软件开发人员、基础设施工程师和运维人员组成的团队，通过 CI/CD 工具、技术和目标（[Figure 2.6](#9781284211658_CH02_02.xhtml#c2-fig0006)）持续交付应用和服务的系统开发生命周期。虽然采用瀑布生命周期的人们认为软件和系统生命周期的责任在工程和开发部门，DevOps 将工作范围扩展到运维部门——它是一个跨部门的功能和过程。

尽管 DevOps 采用短而迭代的循环，但它仍然包含若干阶段。这些阶段取决于以下因素：（1）组织选择的开发/交付方法；（2）组织选择的用于促进 CI/CD 的工具；（3）治理标准，如信息技术基础库（ITIL）、信息相关技术控制目标（COBIT）或其他标准；（4）待交付的产品或服务类型。

了解生命周期流程和文档对信息和网络安全至关重要，原因有几点。首先，某些文档是法律和法规合规所必需的。eDemand 是一家提供合规门户的公司，该门户渲染合规检查表，并允许用户上传文档和证明材料，以证明对包括 HIPAA、SOC-2、NIST 800-53、NERC CIP、FISMA、SSAE、ISO/IEC 27001、萨班斯–奥克斯利法案、格拉姆–莱赫–布赖利法案在内的各类程序的合规性。另一个原因是，每个阶段都提供信息和网络安全的检查点，如代码审查、代码分析、安全架构审查、安全设计等。
