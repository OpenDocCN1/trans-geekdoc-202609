
技术管理在运营中考虑的技术问题包括保持系统运行、通过部署容错和冗余系统（高可用性）避免中断、检测并防止内部和外部攻击成功、以及在 DevOps 实施生命周期中使用行政设施，如将安全监督和系统质量检查纳入流程。简言之，这意味着在正确的时间、地点、人员配备合适的技术和人员。

### 2.3.1 NOC/TOC

运营的核心是网络操作中心（NOC）或技术操作中心（TOC）（[Figure 2.7](#9781284211658_CH02_03.xhtml#c2-fig0007)）。这些房间内布满大型和小型显示器。大型显示器通常显示基础设施的汇总和顶层状态、操作员应共同关注的警报、天气报告、新闻报告以及汇总信息。

运营中心的人员通常被分配监控特定基础设施，如网络段及该网络上的节点。监控基础设施（如 `Zabbix®` 和 `New Relic®`）用于收集基础设施数据，包括 CPU 利用率、网络利用率、系统温度等传感器数据；在具备钻取功能的仪表盘上显示状态信息；并在触发特定事件（如 CPU 消耗量在一定时间内激增）时向人员发出警报。他们还拥有网络分析仪、入侵检测系统（IDS）、防火墙仪表盘、日志分析工具、工单系统等多种工具。

监控系统和网络是保持运营连续性的关键要素，入侵检测与防范系统（IDPS）是监控过程中最必要的工具之一。IDS 通常用于提醒人工干预的网络或主机进程活动异常。一些安全文献将防火墙视为主机基于 IDS（HIDS），而另一些则不这么认为；同样，部分文献将路由器过滤警报视为网络基于 IDS（NIDS），而另一些则不认同。要弄清 HIDS 与 NIDS 的本质可能颇具挑战，因为在实际操作中它们既监控网络又监控系统。总体而言，防火墙具备警报功能，可指示入侵，但其功能属于通用型。网络数据包分析工具（如 `Wireshark®`）使运营团队能够查看网络数据包、捕获端点通信、展开 TCP/IP 头部，并检查负载内容。其他工具（如 `Splunk®`）可从多个工具和日志文件收集数据，提供分析和报告，以此类推。所有这些工具和活动的核心在于保持系统及其他基础设施的完整运行。

### 2.3.2 Monitoring Infrastructure with IDS

IDS 专注于识别活动，并针对攻击签名或与攻击行为相关的关联进行检测。主机基于 IDS 是监控系统和文件访问、评估配置的软件应用。流行的开源 HIDS 示例是 `OSSEC®`，它监控系统日志、检查文件完整性、帮助发现根套件组件，并在特权提升、实时警报等情况下发出通知，并支持通过电子邮件或电话向人员发送可配置的主动响应。

NIDS（如 `Solar Winds Event Manager®`）侧重于检测网络活动异常，可能预示拒绝服务尝试、端口扫描或其他网络攻击。NIDS 通常基于以下两种技术之一：签名或异常检测。签名基于 NIDS 类似于病毒扫描器，依赖传感器或称为代理的软件组件提供的已知模式；一旦识别到该模式，即依据预设规则和逻辑采取相应动作。这种方式相对静态，存在明显局限，但优势在于误报率较低。

| False-Positive or Type 1 Error || Falsely identifying a benign condition as an attack is a false-positive or type 1 error. |
| --- | --- |
| False-Negative or Type 2 Error || Failure to detect an attack is called a false-negative or type 2 error. |
| Agent || A software component that is installed on a device to perform a set of tasks. There are different kinds of agents. Some are merely data collector–forwarders, others have some “intelligent” capabilities of understanding current states, and triggering different actions based on certain conditions. |
| Rootkit || Software components that enable an attacker to escalate the permissions to perform privileged functions, for example, a user process that is allowed to promote its capabilities to that of an administrator. The term comes from the Unix operating system, where “root” is the “administrator” for a computer. |
| Blacklist || Devices such as routers can be configured to take a security stance. Basically, there are two stances, a whitelist is optimistic, the router will allow all connections through to the network unless blacklisted. A blacklist is a pessimistic stance; it blocks all connections except those that are whitelisted. |

由于签名或模式基于的 IDS 对新型攻击处理不佳，且更易产生误报（即漏报真实攻击），因此存在替代方案。其中一种是采用异常或启发式 IDS。这类 IDS 更关注异常行为，即与预期行为的差异。异常检测扫描预期行为与实际行为之间的差异。这些 IDS 使用规则、启发式或统计偏差与相关性的方式。例如，系统可能被配置为仅在端口 80 上期望浏览器的 HTTP 请求；若在 8080 端（通常由数据库等服务器使用）发起类似请求，则会被判定为攻击并触发警报，甚至与防火墙协同阻断尝试，将源 IP 加入黑名单以阻止后续连接。

混合 IDS 同时监控网络协议活动、服务、网络进程、带宽利用率以及端口使用情况。它们结合签名检测、异常检测和启发式方法，以更智能地推断滥用行为。对特定活动的警报可设为规则或过滤条件；当发生攻击时，管理员可以逐层展开协议栈，甚至在每层封装中读取负载内容。若负载加密，许多工具具备解密（或破解）能力。这些工具还会记录日志，供后续审阅。
