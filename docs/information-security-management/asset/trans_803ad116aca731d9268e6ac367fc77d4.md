
下一步，当攻击者反向工程软件时，他们可以窃取或修改代码。在开源软件中，有时贡献者会留下后门（例如最近一次针对 Linux 的攻击），由于内部工作机制易于获取，黑客可以研究它以寻找漏洞进行利用。对软件的修改可能被用于创建恶意软件或病毒。通过这种方式，执行的程序可能看起来合法，但实际上已被修改以执行恶意操作。操作系统安全研究项目（RISOS）发现，操作系统的若干常见区域倾向于产生更多的漏洞。其中包括不完整或不一致的参数验证，即低特权进程之间的进程间通信允许传递参数给高特权进程，这可能导致特权提升。此外，还发现隐式地将特权数据共享给特权较低的进程或用户。研究人员还发现异步验证或数据不当序列化，即违反了某些进程应按指定顺序进行的假设，导致用户和进程的缺失或不足的认证，或可绕过的禁止逻辑，可能导致栈或受保护数据空间被破坏，以及可利用的逻辑错误，包括错误或遗漏的错误处理。

在大多数情况下，软件应用程序是为主机和服务器开发的。虽然市场上可以购买大量软件，但我们在此强调的是内部开发的程序和商用即插即用（COTS）系统。标准化机构和组织一直在努力制定开发生命周期的标准和流程——最受欢迎的包括 CMMi、Six Sigma 和 ISO900x。如前所述，大多数管理框架都要求建立并管理信息系统的适当配置。尽管 ISO 27002、ITIL、COBIT 和 NIST SP 800-53 明显缺乏此方面，但它们都认可变更和配置管理对计算机信息系统的运行和安全管理的重要性。

Behr 等人[⁴](#9781284211658_CH08_10.xhtml#c8-bib0004) 发现，遵循这些规定的组织具有更高的平均故障间隔时间、更低的最大修复时间、在 IT 操作流程中早期且持续地集成安全控制、审计发现重复次数较少且所需人员时间较少，以及服务器到系统管理员比率较高且非计划工作量较少的高效率。

在其他基于控制使用的研究中[⁵](#9781284211658_CH08_10.xhtml#c8-bib0005)，高性能组织与其他组织的关键控制差异在于高度使用变更和配置管理控制。从操作角度看，高性能组织完成的项目数量是中等和低性能组织的八倍，管理的应用程序和 IT 服务数量是六倍。他们实施的变更数量是后者的 15 倍，在管理 IT 资产时，其服务器到系统管理员比率是中等性能组织的 2.5 倍、低性能组织的 5.4 倍。此外，他们相对于中等性能组织的变更失败率仅为其二分之一，相对于低性能组织的变更失败率仅为其三分之一。

总体而言，从安全角度来看，这意味着发生的泄露事件被更早发现，且极大概率不会导致财务、声誉或客户损失。Keller 和 Rothchild 研究的组织理解到管理信息系统及其相关风险的重要性，而不是让系统通过一系列临时的、非正式的添加和修改不断增长和变化。虽然通常很难应对威胁环境，但组织可以管理系统中的漏洞。正如 NIST SP 800-128 中所述，“利用配置管理对 IT 资源进行更大控制并确保其完整性，有助于资产管理、改进事件响应、客服、灾难恢复和问题解决、支持软件开发和发布管理、实现更大程度的流程自动化，并支持符合政策及审计准备。”[⁶](#9781284211658_CH08_10.xhtml#c8-bib0006)

### 8.6.2 计算机安全与配置管理

我们已经讨论了配置管理，但必须再次强调，因为它虽然基础，却往往是基础设施管理中最被忽视的环节。请记住，配置管理（过程和技术）并非仅属于 IT 部门。在《质量是免费的》一书中，Philip Crosby 强调了跨组织的技术管理责任对输出质量的重要性。核心在于“符合要求”，即组织需要衡量并理解其性能随时间的变化的一致性。这一概念也出现在许多质量改进方法中，包括摩托罗拉在 1981 年开发的流行 Six Sigma 策略。让我们用一个例子来加以说明。

虽然本节主要讨论质量，但可以将质量视为网络安全的一部分。我们以电气工程师为例，假设他为家电制造商工作。工程团队会设计一款满足特定要求的家电。原型机将被生产并测试，以确保符合功能和安全要求。设计获批后，系统进入生产，工程团队将继续完善现有产品的设计或开发新产品。但如果在生产过程中家电出现问题呢？

如果工程师认为需要对家电的生产进行修改，通常不会有人立即跑到生产线上进行更改。更改会先在测试环境中实施，评估该变更对功能和安全要求的影响，只有在获得批准后，才会在生产中实施更改。可以想象，如果每位工程师都在装配线上随意、即时地对家电进行即时更改，制造商将面临何种严重后果。配置和变更管理对于计算机系统和软件同样适用。简而言之，配置管理是“……一系列以控制产品和系统的初始化、变更和监控过程为重点，以确保产品和系统的完整性的活动集合。配置管理通过建立基线配置来实施。”[⁶](#9781284211658_CH08_10.xhtml#c8-bib0006) 配置控制过程的一个离散目标是配置项（CI），其定义并同意的初始配置称为基线配置。因此，配置管理的关键功能是变更控制，并通过安全管理配置项（CI）及配置数据库（CMDB）来确保系统的完整性和一致性。
