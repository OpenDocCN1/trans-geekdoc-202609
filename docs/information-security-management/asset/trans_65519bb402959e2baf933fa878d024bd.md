
安全控制措施必须让人能够高效、有效地工作；因此，防范措施必须在最小约束的前提下实现最大控制——这与确保合法工作者的资源可用性相关。管理者需要思考安全行动的后果；然而，在现代组织中，成功工作通常意味着成功的团队协作和开放的沟通，信息必须能够跨越组织障碍以确保运营有效执行，同时保证安全运营的有效性。正如 Malatji 等人[³](#9781284211658_CH07_08.xhtml#c7-bib0003) 所描述的，这是一种“有机组织能力”，能够使公司实现适应性和敏捷性——这对管理者而言是重要的关注点。然而，所有为了安全目的而将人员隔离、分割的努力都违背了这些被研究证明能够提升组织绩效的有机原则。因此，诸如职责分离和分割等严格的安全措施应仅局限于公司中最敏感的操作、职能和角色。

### 7.2.2 希望最好，计划最坏

技术管理者当然希望其主动保护组织资源和人员的措施能够成功，但也必须考虑最坏情况。正如我们所指出的，风险管理是处理威胁及其相关成本并规划应急措施的过程。应急计划通常涉及制定“如果发生…会怎样”的灾难情景，常用的方法包括 Delphi（一种匿名集体决策过程，参与者匿名提供输入和想法，随后由小组评估）或电脑化随机模型（根据从他人获取的信息、数据挖掘或人工智能与专家系统查询得出的统计概率，对可能结果进行概率估算）。

应急计划包括灾难恢复规划过程，在灾难发生时制定替代的信息处理和恢复方案。该过程产出业务连续性计划，说明在灾难（人为或自然）发生时，业务应如何继续运行。管理者还需考虑灾难发生后的应对措施以及如何恢复。恢复计划侧重于如何恢复正常运营。这些计划可能包括使用灾难恢复中心，在灾难发生时保持设备并派遣人员。例如，SunGard 等公司专门提供此类服务。另一个重要过程是设施管理，它包括灾害应对程序，如使用离站备份和存储设施、分布式运营与监控中心，以及自愈系统的使用。

## 7.3 风险评估概述

截至本章节前段，我们已经回顾并深化了文本第一部分所介绍的许多概念。希望您已经看到全貌。现在，让我们转向行政和程序性问题，首先是风险评估。

请回顾，威胁既可来自内部也可来自外部，并且与系统内固有的脆弱性紧密相连，这些脆弱性会被威胁实体利用。如前所述，风险是不良事件发生在个人或组织上的可能性。风险概念存在于不确定性的领域，伴随已知或未知的脆弱性以及相应的威胁。将风险应用于信息系统时，指的是系统无法按预期或所需方式运行的可能性。虽然定义简单，但在实际实施中却相当复杂。它是风险管理的基石和目标所在，目标是使系统以我们期望的方式运行，且以最低成本满足需求（无论成本是时间、精力还是金钱）。

风险可以接受、缓解、降低或转移。接受风险通常意味着威胁发生的概率较低，或成本‑收益比不足以投入防范资源。例如，为一款托管小型网站的 Web 服务器投入数千美元购买备用系统可能并不划算。缓解是指在现有约束下改进局面至可接受水平的尝试。例如，经理可能为一台执行小型任务的孤立办公室电脑选择免费防病毒软件（如 AVG‑free），而为通过局域网连接的办公室电脑则升级至 AVG 商业版。

技术管理者和安全专业人员需要对组织的风险进行量化和质化评估。典型做法是将风险因素放入表格中，并根据管理者主观判断为不同资产、系统和服务赋予权重。这些权重反映了 exploit 成功可能导致的潜在损害。通过统计计算可得出威胁风险的汇总，从而识别出最大的损害潜能。大部分关于风险概率和潜在影响的判断属于主观判断；也有可能是基于统计计算或概率计算（如[Figure 7.1](#9781284211658_CH07_03.xhtml#c7-fig0001) 所示）。

### 7.3.1 风险缓解

组织投资于信息技术（IT）基础设施，是因为它们相信这些投资能够提升业务运营。这一思路得到研究支持，研究表明，投入大量 IT 基础设施和资源的组织往往优于未作大量投资的组织。[⁴](#9781284211658_CH07_08.xhtml#c7-bib0004) ^，[⁵](#9781284211658_CH07_08.xhtml#c7-bib0005) 将有形和无形资源独特结合的方式，正如 McKeen 等人所定义的，称为 IT 能力。关于 IT 能力的研究不仅表明 IT 投资与组织价值之间存在明确关系，还指出其组成部分与 ITIL（信息技术服务管理体系框架）和 COBIT（信息技术治理框架）等最佳实践与控制框架的要素相似。此外，研究表明，像 ISO 17799 和 NIST 特刊 800-53 这样的技术最佳实践标准在降低信息系统风险方面极具价值。[⁷](#9781284211658_CH07_08.xhtml#c7-bib0007) 这些最佳实践与控制框架的共同点在于它们都认识到信息系统中的风险。最近，国家标准技术研究所（NIST）及其他标准机构发布了针对勒索软件的草案文件，例如 SP‑1800‑25：数据完整性：识别并保护资产免受勒索软件及其他破坏性事件侵害，以及 SP‑1800‑26：数据完整性：检测并应对勒索软件及其他破坏性事件。
