
云计算是一个不断演进的术语，因为用于云计算的技术仍在不断演进。国家标准与技术管理局（NIST）[¹](#9781284211658_CH06_07.xhtml#c6-bib0001) 定义云计算为：一种提供便捷、按需网络访问共享可配置计算资源池（例如网络、服务器、存储、应用程序和服务）的模式，这些资源可以快速配置和释放，管理努力或服务提供商交互极少。云模型促进了可用性，并由五个基本特征组成：[²](#9781284211658_CH06_07.xhtml#c6-bib0002) (1) 按需服务，即系统和网络的使用是按需提供的，(2) 无论平台和地理位置如何，都可 ubiquitous access（普遍访问），(3) 资源共享，允许以更经济的方式交付服务，(4) 弹性，意味着计算和通信可以根据需求进行扩展，(5) 可预测性，即由于资源可扩展，服务交付的可预测性高于预先配置的情况。

云计算的基本架构基于三种计算资源利用方式，即所谓的服务模型。[¹](#9781284211658_CH06_07.xhtml#c6-bib0001) 它们是 (1) 软件即服务（SaaS），它使客户能够“租用”基础设施来运行应用程序；(2) 平台即服务（PaaS），它允许客户在提供商“租用”的计算设施上部署自己的应用程序；以及 (3) 基础设施即服务（IaaS），它允许客户处理、存储数据、配置网络，并部署和运行系统和应用程序。IaaS 与 PaaS 的区别在于，客户对操作系统、存储、部署的应用程序以及部分网络组件（如主机防火墙）拥有控制权。换句话说，它在某种程度上是 SaaS 与 PaaS 之间的混合体。[⁴](#9781284211658_CH06_07.xhtml#c6-bib0004) 虽然最初定义的基本“即服务”模型已经确立，但它们正在扩展为各种“即服务”形式，例如容器即服务（CaaS），它以使代码和/或基础设施的组合便于跨平台移植并提供标准化的上传、配置、启动、停止、扩展和管理容器环境的方式虚拟化这些内容。Docker® 是一个流行的容器，Kubernetes® 是用于管理容器化应用程序的流行容器编排系统（[Figure 6.3](#9781284211658_CH06_01.xhtml#c6-fig0003)）。

尽管使用这些设施可以提高资源利用率并更好地支持质量服务（QoS），但它们也带来安全和隐私问题，尤其是在多租户配置中。[⁵](#9781284211658_CH06_07.xhtml#c6-bib0005) 根据最近的一项 Forrester 研究调查，51% 的小企业参与者表示，安全和隐私问题是他们不使用云服务的首要原因。隐私问题涉及提供商如何利用公司信息的方式。例如，像 Google 这样的提供商明确表示在其政策中会收集数据用于消费者画像和营销目的。此外，尽管提供商声称因资源共享而拥有更高的可用性，但许多技术管理者仍担心提供商无法兑现承诺——这与许多旧 ASP 提供商的情况类似。最后，一些技术管理者对数据丢失或泄露表示担忧。几起高调的泄露事件加剧了这些担忧。在开发解决方案之前，理解这些问题和权衡至关重要。

### 6.1.3 服务器和主机计算机

当人们想到信息系统时，通常会联想到服务器和主机计算机。然而，信息系统（IS）实际上涵盖所有组织信息基础设施，包括网络、文档的纸质副本、服务器机房以及甚至物理存储金库。服务器和主机计算机构担负了大多数组织的计算平台的主体，同时还包括连接它们的网络以及用于操作的软件应用程序和数据库。除了帮助企业在全球市场中有效运营外，管理者还必须同时考虑保护系统和信息以防止泄露或损坏的实际可行性。对于许多技术管理者而言，安全可能被视为业务成本的超支，但实际上安全的概念类似于质量——虽然这些措施并不直接影响财务底线（除非产生负面的财务支出），但糟糕的安全，正如糟糕的质量一样，会间接甚至直接地影响底线。例如，考虑品牌声誉因质量问题受损，或信用局发生重大安全泄露导致客户信任丧失。但情况更为严重，因为在网络安全事件中，还可能涉及诉讼和处罚。

如今，信息和通信系统可以从全球任何地方受到攻击，这有时使技术管理者几乎没有或完全没有应对手段，除非他们先进行良好的规划并随后采取相应的行动。虽然信息技术可以被不道德地使用或用于可疑目的，但这些技术本身是中性的，也就是说，是否将它们用于善意或恶意目的取决于使用技术的人。在管理者能够保护其信息基础设施之前，他们必须首先理解这些技术是如何工作的，至少在高层面上。这意味着在我们真正能够欣赏每项安全关注的技术组件之前，需要先建立一些基础。

#### 6.1.3.1 操作系统

文章开头我们提到，要充分理解本材料（尤其是网络安全），需要对操作系统（如 Windows、Linux 或 macOS）有一定经验，最好是三者都有。虽然在实现层面上，Unix、Linux、macOS 和 Windows 操作系统有所不同，但它们的功能是相同的。我们将介绍这些功能，以便在讨论针对它们的威胁、漏洞以及技术问题和缓解措施时，能够产生理解。例如，了解恶意软件如何导致栈溢出或缓冲区溢出以及应对措施至关重要。

总体而言，操作系统可以被视为编程代码和数据结构的集合。编程代码通常使用低级语言（如 C/C++ 和汇编语言）编写。大多数操作系统是事件驱动的，这意味着当用户在键盘上输入内容或点击鼠标时，当内存中的存储位置被填满，或当运行队列中的程序准备好由 CPU 执行时，软件（或固件）会生成信号，中断 CPU 以切换功能。由于多个用户同时使用计算机，且多个程序同时在同一台机器上运行，这些事件的协调和程序执行由一组子系统负责。首先，提到操作系统时，通常指的是内核或核心功能，但许多支持系统使用或被内核使用，例如设备驱动、shell（命令行界面）和图形用户界面。下面列出了一些操作系统的主要功能。
