# Store Locator

The Store Locator script is an important component of the process. After much debate I decided that I liked this approach much better than returning all the records in the table, then using PHP code to calculate which ones to display. Both methods have their merit. However, I decided that for extensibility purposes it would be better to display the specific set of records in the $records variable than constantly having to use extra PHP code to filter the display.

Every script that is run from the Server will start by turning User Alert and Error Capture to On. This will prevent unsupported script steps from stopping the script and making sure error boxes are not shown, which can cause unpredictable results on the Server. Next I will need to insert the Latitude and longitude into the SearchLat and SearchLon global fields. The values are inserted into these fields where the data is calculated for every record. If you remember from the previous section, the values are passed as a script parameter. That means you can access the data using the function GetScriptParameter); However, I passed three values in one script parameter. I’ve used the ParseXMLData custom function, which allows you to parse the value from parameter by specifying the name. All the heavy lifting is performed by the custom function. See the example Article ParseXML Script Parameters, which is available at formulationspro.com. The Distance field requires a little extra handling. By adding "<=" to the search criteria of the script we will retrieve all the records from 0 to the specified distance. Finally, sort the records by the Distance and Name fields before ending the script and returning the found set of records back to the page. That wasn’t so hard — the script is no more than anything else you’d create in a client-based solution.
