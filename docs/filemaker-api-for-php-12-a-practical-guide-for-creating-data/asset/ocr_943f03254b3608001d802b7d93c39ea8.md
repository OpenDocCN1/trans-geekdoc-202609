Now that we have all information as variables, we can get to work evaluating the customer's authorization to download the file. When the customer first tries someone is spoofing the IPAddress field will be blank. That makes sense because we won't necessarily know where they are coming from. Therefore, if the $ipaddress is empty, we can update the record with the customer's current IP Address. This will look in the download for that specific IP Address. Therefore, nobody will be able to access the download using the supplied link. After that it's as easy as checking the IPAddress in the database against the customer's current IP address to continue

```
if(empty($ipaddress)) {

  $edit->addField('IPAddress', $remoteipaddress);

}
```

The next step is to validate the expiration date of the link. If the current is greater than the expiration date in the record you can run the script. Alternatively, some people might recommend immediately deleting the record at this point to prevent it from being accessed. However, I would caution you from a customer service perspective that this will be much easier to allow your employees to reset the expiration date of an existing record than to create a new record. I am just thinking about customers who have to call FileMaker to get a new link to their software downloads.

Next we want to update the DownloadAttempts field. This can be used to limit the number of times the file can be downloaded by anyone — even someone spoofing their IP address. For this demo I set the maximum number of download attempts to 5. The added benefit of this concept is that you can also use it for your web site statistics — how many times a specific file has been downloaded, how many times has a specific page been accessed, etc. Do you see the potential in just a few lines of code and a simple record in the database?
