# Container Bridge File

**Objective:** The ContainerBridge.php is a file that you'll include as is with your solution. There's absolutely nothing to do in this file. It simply works on its own. It is used to convert images in container fields so you can display them on a web page.

> I don't recommend that you display images using container fields. You are much better off storing the images on the server and using a text field with a path to the image. The ContainerBridge.php works. However, you will take a big performance hit. The FileMaker API for PHP is nice that it will work with container images. The XDBC drivers for ASP and JSP do not work with FileMaker's proprietary container field.

Difficulty: Easy

**Sample Files:** PHPFiles/Core/Lesson12/ContainerBridge.php

**Page Navigation:** Include file only.

FileMaker API Methods: N/A

Code:

Since this is already a stand-alone file, rather than going through each line of code I'll describe its intended use. In PHP code you want to display an image from a container you will use the following example code:

```
<img src="ContainerBridge.php?path=' . urlencode($_GET['record']) . ' />
```

The point of this is to do two things. First, define the image source. You can see that the code is passing the image source to ContainerBridge.php with the variable "path" as an urlencoded container field in the database named "Image". If you follow the value passed to the ContainerBridge.php file you will see that it starts by verifying that the path information was set. Next it uses the PHP substr to strip away the path stored in the file to return just the extension of the image. Once the extension is determined it will return the appropriate jpg or gif in the header. Finally, the fm object will use the getContainerData method to retrieve the image from the container field. Again, you don't necessarily need to know why or how. The upcoming lessons will demonstrate exactly how to display an image from a container field both internally and externally. For now, you'll include this file in your web sites "as is" if you intend to display images from a container.

> substr Returns a portion of the string by the start and length parameters. This is very similar to the FileMaker Middle function.

```
http://us.php.net/manual/en/function.substr.php
```

> header Used to draw a raw HTTP header.

```
http://us.php.net/manual/en/function.header.php
```

```php
<?php
require_once("../dbaccess.php");
if (isset($_GET['path']))
{
  $url = $_GET['path'];
  $url = substr($url, 0, strpos($url, "?"));
$url = substr(strpos($url, ".") + 1);
if($url == "jpg") {
    header('Content-type: image/jpeg');
} else if($url == "gif") {
    header('Content-type: image/gif');
} else {
    header('Content-type: application/octet-stream');
}
echo $fm->getContainerData($_GET['path']);
```

# Lesson 1: Find All Records

**Objective:** In this lesson you will learn how how to find all the records and display them in a simple table.

**Difficulty:** Easy

**Sample Files:** PHPFiles/Core/Lesson1/FindAllRecords.php

**Page Navigation:**

![](img/5a2c5fda68d42e5d65f51850276e49ec_86_0.png)

**FileMaker API Methods:**
newFindAllCommand()
execute()
getRecords()
getField()

**Code:**

Any time you need to connect to the database you'll start your php code with the include file for dbaccess.php.

```php
<?php
include("../dbaccess.php");
?>
```

The main section of your php code by creating a new search transaction to find all the records. Create the $result variable to tell the $f object to use the newFindAllCommand() to retrieve the records from the Demo layout. Remember that the $f object was created in the dbaccess.php file which was included in the code that starts every single page.

```php
<?php
$result = $f->newFindAllCommand('Demo php');
```

> FileMaker API Syntax: newFindAllCommand('LayoutName')
$result = $f->newFindAllCommand('Demo php');

After you make a request to the database you always have to execute it. Create the $result variable to execute the $request. The found set of records will be stored in the $records, which will be used in the code below.

```php
$result = $request->execute();
```

Any time you execute a request to the database you will need to trap for errors. You can simply copy/paste this generic code after you execute any methods.

```php
if (FileMaker::isError($result)) {
echo "<p>Error: " . $result->getMessage() . "</p>";
}
```

Next, you need to tell the $result variable to get the records using the getRecords() method and store them in the array. Even though you may have only one record in the found set, the $result variable will handle multiple records if they exist.

```php
$records = $result->getRecords();
```

Now we can display the results, using the foreach loop to go through the array. This is how you generate the html table for the data.

```php
foreach ($records as $record) {
    echo "<tr>";
    echo "<td>" . $record->FirstName() . "</td>";
    echo "<td>" . $record->LastName() . "</td>";
    echo "<td>" . $record->Number() . "</td>";
    echo "<td>" . $record->Date() . "</td>";
    echo "<td>" . $record->TimeStamp() . "</td>";
    echo "<td>" . $record->Calculation() . "</td>";
    echo "</tr>";
}
```

```php
<?php
$result->getField('FieldName');
```

Finally, end by closing the table and the php code.

```php
echo '</table>';
```
