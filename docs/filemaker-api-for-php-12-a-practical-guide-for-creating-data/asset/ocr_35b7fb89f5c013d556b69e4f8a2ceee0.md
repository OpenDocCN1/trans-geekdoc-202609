# Part II — Publishing FileMaker Data

This is the part of the book you've been waiting for or some of the part you've been dreading. This section will dig into the FileMaker API for PHP and show you examples for all the available methods to create production quality, commercial web pages with the data from your FileMaker database. We'll start out with the core examples, which demonstrate required techniques that you'll need for every single web page. Then we'll continue with the basics of display, search, create, delete, and edit records. Here we'll tackle more complex topics such as portals and container fields. Finally, we'll work on details that every site needs such as log in security, navigation, running scripts, using value lists, and validation. We'll move on to the Advanced section that demonstrates everything else we learned. Once you've mastered these techniques you'll have learned 95% of everything you need to use the FileMaker API for PHP. At that point you should be comfortable looking up anything else that you might need, which is what I also have to do as a professional developer.

What is the best way to learn these methods? I suggest that you take your time and try to absorb only one or two examples per day. Each example will explain the objective, the difficulty level, provide page navigation appropriate, explain each line of code, and provide screenshots of the expected results on a web browser. The sample files included with this book are complete and functional. The absolute best way for you to learn the methods and PHP code is to type it out in your own text editor or using Dreamweaver. Rest assured, you will make mistakes and know that this is part of the learning process. The more you practice, the better you will get. One thing to keep in mind is that all the code is fully commented, so you will never get lost. In a production version you can remove most, if not all of the comments. Leave just enough comments in your files so you can back-track your train of thought. Comments in the PHP code will not appear on the web pages as they are stripped by the web server. However, this still doesn't mean that you should store sensitive information such as account names, passwords, etc. in the comments because it still represents a possible security issue if someone was able to download your web pages.
