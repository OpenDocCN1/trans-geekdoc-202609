Now that we have the Lat, Lon, and Distance we can pass those to the Store Locator script in the database. I use variables when I code the newPerformScriptCommand to make it cleaner to read and modify. Specify $layout you use in the database (Demo), the exact $script name (Store Locator), and the $script parameter. If you look closely at my script parameters for SearchLat, SearchLon, and Distance you'll notice that I'm passing them in an XML-like format (e.g., <SearchLat>39.6403</SearchLat>). I prefer to pass variables because I have a custom function in the database that parses these values by specifying only the name of the field. This is done in the Store Locator script as follows: Now, it's enough to join the format to the script parameters. After you execute this code it will return the records back to the user. All you need to do is trap for errors, the most common being no records found.

```
$layout = 'Demo';
$script = 'Store Locator';
$parameter = '<SearchLat>$SearchLat</SearchLat><SearchLon>$SearchLon</SearchLon><Distance>$Distance</Distance>';
$result = new newPerformScriptCommand($layout, $script, $parameter);
$result = $result->execute();
if (FileMaker::isError($result)) {
    echo 'There are no stores in your located location.';
}
```
