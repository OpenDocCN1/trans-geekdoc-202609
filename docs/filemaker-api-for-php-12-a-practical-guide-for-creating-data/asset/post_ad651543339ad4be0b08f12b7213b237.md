
How does AJAX work? The user's browser displays one or more records. On the web page (show_all.php) there is a button that the user can click to show more detail. JavaScript on the web page creates an XMLHttpRequest to send the HttpRequest to a second web page (show_detail.php). In layman's terms this means when the user clicks the button a pre-defined URL string is created to request information from a second web page. Usually the request is in POST format so we can send large amounts of data if necessary. Next the web page receives the HttpRequest and passes it to the server to retrieve the requested data. The database returns the records the second web page creates (using PHP) to format the data using HTML/CSS which is displayed directly on the user's web page. Finally the JavaScript processes the data and updates the page content without a reload.

Do you need to implement AJAX? There are no classes or JavaScript files (js) to install or order. Obviously, you'll need to use FileMaker and PHP for this example. Realistially, you should know some basic JavaScript, HTML, and CSS. You can get away without knowing how to use HTML and CSS instead which is what I recommend. Most important is that the JavaScript function is perfectly defined. You're not going to make too many changes to it. You'll copy/paste the same code all the time and only tweak what need, such as the function name and/or any variables you want to pass to it. However, I'm going to show you how to use the * RecordID to easily grab the record every time without having to change the core JavaScript code for any solution.

The body is where the dynamic work to display and the Show Detail button is performed. The AJAX works is that it replaces the content of a div tag that is returned from the show_detail.php page. In this case, we're going to replace the contents of the DIV tag, which is intentionally empty for this demonstration. If you have any content in the DIV tag, it can't be replaced. Since we're working with multiple records on the page the ID of the DIV tag can't be fixed. If we use a fixed name, only the first occurrence of a DIV tag will be replaced (which is very limited). However, it has to be dynamic. We will use JavaScript to dynamically name the DIV tag for each record that is displayed in the browser. The code loops through each of the records to store the RecordID value as the $id variable. We define the name field and the Show Detail button below it. When the user clicks the (onclick) it triggers the ShowDetail JavaScript function. Since the JavaScript to update a specific the key pathway to this section of code - passing the dynamic DIV tag name as the RecordID to the JavaScript function. Again, if you have more than one record on the page, you have to dynamically name the DIV tag or the JavaScript won't work. As you expect if only one record on the page, you can give the DIV tag a fixed name. However, since we are dealing with a database and little tweaking code, I'd rather copy/paste the same code over and over and not have to worry about changing anything. This code will work for one record or multiple records.

```javascript
<script>
function showDetail(id) {
    var xmlhttp = new XMLHttpRequest();
    xmlhttp.onchange = function() {
        if (xmlhttp.readyState == 4 && xmlhttp.status == 200) {
            document.getElementById(id).innerHTML = xmlhttp.responseText;
        }
    };
    xmlhttp.open("POST", "show_detail.php?id=" + id, true);
    xmlhttp.send();
}
</script>
```

Additionally, I've also defined the asynchronous parameter as true, which means that other scripts can execute waiting for the server response and the JavaScript function can wait until the onreadystatechange is ready (xmlhttp.readyState=4, xmlhttp.status=200). It defeats the purpose of using AJAX if you set the value to false.

Finally, when the code runs, the onreadystatechange event will have to change. Therefore, the following code will send the POST request to the show_detail.php.
