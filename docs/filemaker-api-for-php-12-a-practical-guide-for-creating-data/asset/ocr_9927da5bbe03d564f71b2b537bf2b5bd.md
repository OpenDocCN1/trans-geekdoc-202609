That's because the environment is exactly the same and using '127.0.0.1' instead of a domain or IP address will still work correctly. There is one notable issue to be aware of: DO NOT use 'localhost' as Windows has trouble resolving localhost will cause major performance and crashing issues. If you use a two-server setup with Apache or IIS and PHP on one machine, then using 'localhost' won't work in your production environment. In this case you would have to change the hostspec connection in the dbaccess file on your server to your IP or domain name. The trick is to remember it and not to overwrite the production connection file with your development file. If the connection to the database won't work. It won't break anything or corrupt data, but your users won't be able to access any web pages that they need from the database until you fix it.

When testing your page on your testing server you will use the URL. Note that I placed the example files in the folder 'PHPFiles/Core/Lesson#'. This is simply to keep your testing server organized for different projects.

```
127.0.0.1/PHPFiles/Core/Lesson/FindAllRecords.php
```

When you access files on the production server use the URL:

```
http://www.mydomain.com/PHPFiles/Core/Lesson/1/FindAllRecords.php
```
