# Display Check Boxes and Update Records

To make the features of selecting and updating multiple records all the records will need to be displayed in a single form. I did not include any type of sophisticated search field on the page, as the point of this lesson is the technique of building the form with all the checkboxes and record data, not a complicated interface. I'll let you build that yourself. Once you have mastered the technique it is easy enough to do.

One of my goals is to apply the KISS principle to my techniques. I believe that fewer lines of code and fewer bells is always more. If you've been close attention then you will probably noticed that there is no database field for the Select checkbox. There's a reason for that - it's not necessary. The only place we need it is on the web page as a placeholder for the user to check the box on their screen. The significance of the checkbox is that it will need to be dynamically named as the RecordID so that we can identify which record(s) needs to be updated. Now that we have some of the background information regarding how the form and fields we can get into the code to make sense of this whole process.

Always by connecting to the database.

```
<?php
require_once ('FileMaker.php');
$fm = new FileMaker();
$fm->setProperty('database', SelectMultipleRecords);
$fm->setProperty('hostspec', 'http://127.0.0.1/');
$fm->setProperty('username', 'Admin');
$fm->setProperty('password', '1234');
?>
```

The next section of code will only run when the user clicks the Update button on the form. Normally your form would process this information using the POST method because you don't want the users to be bookmark records that change. I use the GET method here so we can set the name=value pairs passed in the URL. Loop through each of the records in the $records array to determine which ones need to be updated. This enables you to uniquely identify every record as update the records based on the RecordID, which is retrieved by FileMaker. If, the RecordID is set as the name in the URL you can update the record. Otherwise, you can skip the record. In this demo I'm simply updating the Timestamp field for each record.
