
# Lesson 17: Run a Script — Delete Records

**Objective:** In this lesson you will learn how to run a script stored in the database. The script will delete all the blank records in the table. The focus of this example is how to use a script to delete blank records and return to the correct set of records back to the web page. As mentioned in the previous example, when you delete a found set of records the database will return the remaining records in the table back to the web page, not zero records in the found set as you get with FileMaker Pro. Therefore, your expectations for the data being displayed on the web vs a FileMaker Pro client are completely different.

**Difficulty:** Medium

**Sample Files:** RunScriptDelete.php

Page Navigation:

- FileMaker API Methods:
- newPerformScriptCommand()
- execute()
- getMessage()
- newFindAll()
- getRecords()
- getField()

**Code:**
The display of the records will follow the same design as the Alternate Background example. Embed the css style in the head tag to alternate the background color.

Always start by including the connection to the database.


Create the form with the button to update the records in the database. The form will point back to the same page using the Post method.

```
<form action="RunScriptDelete.php" method="post" name="Delete">
Click the Delete button to run the PHP Delete Blank Records script <br />
<input name="Delete" type="submit" value="Delete" />
</form>
```

The next section of PHP code will run the script. Start by checking to see if the $_POST superglobal has been set for Delete and that the user clicked the Delete button. Create the variable for the $layout name. The layout does not need to have a script or button attached to it, but you do have to run the script based on the context of a layout. The $script variable is the exact name of the script stored in the database. The $parameter is what you will pass to the script. This is very similar to using script parameters in FileMaker Pro. You will also retrieve parameters using the exact method in the FileMaker script — Get(ScriptParameter). Finally, put all the variables together using the newPerformScriptCommand and execute the script.

```php
if ($_POST['Delete'] && $_POST['Update'] == 'Delete') {
$layout = 'Demo php';
$script = 'PHP Delete Blank Records';
$parameter = '';
$request = $fm->newPerformScriptCommand($layout, $script, $parameter);
$result = $request->execute();
}
```

Trap for errors.

```php
if (FileMaker::isError($result)) {
echo "<p>Error: " . $result->getMessage() . "</p>";
exit;
}
```

At this point the records in the database should all be processed by the script and will display the changes on the browser.

```php
$request = $fm->findAll('Demo php');
$result = $request->execute();
```

Trap for errors.

```php
if (FileMaker::isError($result)) {
echo "<p>Error: " . $result->getMessage() . "</p>";
exit;
}
```

Store the records in the records array.

```php
$records = $result->getRecords();
```

Create the header for the table.

```php
echo '<table border="1">
<tr>
<th>First Name</th>
<th>Last Name</th>
<th>Number</th>
<th>Date</th>
<th>Time Stamp</th>
<th>Calculation</th>
<th>Record ID</th>
</tr>';
```

Use the foreach method to display the fields from the records. Don't forget to alternate the background color of the odd rows.

```php
$row = 0;
foreach ($records as $record) {
    if ($row % 2 == 0) {
        echo '<tr class="alt_row_color">';
    } else {
        echo '<tr>';
    }
    echo '<td>' . $record->getField('FirstName') . '</td>';
    echo '<td>' . $record->getField('LastName') . '</td>';
    echo '<td>' . $record->getField('Number') . '</td>';
    echo '<td>' . $record->getField('Date') . '</td>';
    echo '<td>' . $record->getField('Timestamp') . '</td>';
    echo '<td>' . $record->getField('Calculation') . '</td>';
    echo '<td>' . $record->getField('RecordID') . '</td>';
    $row++;
}
?>
```

# PHP Delete Records Script

- Allow User On to stop if there are any errors.
- Set Error Capture to block the FileMaker dialog if there are errors.
- Allow Abort [ On ]
- Set Error Capture [ On ]
- Find all the records based on FirstName being empty.
- Find [ Specified Requests; Criteria: FirstName = "" ]
- If there are any errors, such as no records found during the search, make sure to show all the records.
- Delete all records in the found set.
- Finally, by committing the records so the web page is updated with the latest records.
- If Get(LastError) > 0
- Show All Records
- Delete All Records [ No dialog ]
- Show All Records
- Commit Records/Requests

# Lesson 17: Run a Script — Send Mail

**Objective:** In this lesson you will learn how to run a script using a parameter. The script will send the user lost password using the built in FileMaker Send function.

**Difficulty:** Medium

**Sample Files:** RunScriptSendMail.php

**Page Navigation:**

**FileMaker API Methods:**
- PerformScriptCommand()
- execute()

**Code:**
Always start by including the connection to the database.

```php
<?php
include ('../conn/dbaccess.php');
?>
```

Start with a default message on top of the layout to tell the user to click the submit button to retrieve their password. Before the user's email address is entered to the script make sure the Submit button is set and has been clicked. Then create the layout name and variables. For the first time in a script we're going to pass a parameter to the script using the email address entered in the form that is retrieved from the URL. Remember, the email address will contain the @ symbol, which will be URL encoded as %40. Therefore, we'll need to convert that back to the @ symbol by using the PHP urldecode method. Finally, put all the variables together and execute the script.

```php
<?php
$message = 'Click the submit button to retrieve your password.' . '<p>';
if (isset($_GET['Submit']) && $_GET['Submit'] == 'Submit') {
$layout = 'Demo php';
$script = urldecode($_GET['email']);
$parameter = $fm->newPerformScriptCommand($layout, $script, $parameter);
$result = $request->execute();
}
```

Trap for errors and supply update message based on the results from FileMaker Server. If no records are found it will throw an error. Therefore, you can update the message to let the user know that their email address does not exist. Otherwise, you can let them check their email for their password.

```php
if (FileMaker::isError($result)) {
$message = 'The email address you entered does not exist' . '<p>';
} else {
$message = 'Your password will be sent to your email address shortly.' . '<p>';
}
?>
```

Finally, create the form to let the user enter their email address and submit it to get their password.

```html
<form action="RunScriptSendMail.php" method="get" name="Submit" id="Submit">
<?php echo $message; ?>
<input name="email" type="text" />
<p>
<input name="Submit" type="submit" value="Submit" />
</p>
</form>
```

# PHP Lost Password Script

Having the capability to send automated emails is incredibly useful. Not only can you use this concept to retrieve lost passwords, but you can also use it to do things like send invoices from your ecommerce system. The great part of this is that you don't have to have a special SMTP server running on your web server and you don't have to configure anything in Apache or IIS to forward emails to your SMTP server. Just use the built in FileMaker SMTP features and it works like charm.
