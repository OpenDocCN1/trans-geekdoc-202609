Now we can build the calendar with the function we need to get the data into it. For that, we need to pass data for the month, year, and the records from the database. When the user first enters the page, the URL's NVP values will be empty for the month and the year. So we'll have to generate the values for the current month and year. That makes the calendar make more sense if they start at the current month rather than some random preset month or no month at all until they select a season

```
if(isset($_GET['month'])) {
  $month=$_GET['month'];
}else
  $month=date('n');
```

```
if(isset($_GET['year'])) {
  $year=$_GET['year'];
}else
  $year=date('Y');
```

Now, we'll search for the database for all the records. The nice part is that FileMaker accepts wildcards such as //2011 to find the records for the month of July. We'll also want to sort the records by Time and Date so they display in a logical order. Especially since we set the database up to allow a single record to span one or more days. Don't forget to trap for errors. If there are no records in the found set FileMaker will return an error, which will prevent the calendar from being drawn. We least want to draw an empty calendar.

```
$request = $fm->newFindCommand('Demo');
$request->addFindCriterion('DateRange', $month . '/*' . $year);
$request->addSortRule('DateFrom', 'Time', 2);
$result = $request->execute();
if(FileMaker::isError($result)) {
  // No Records Found. Display a blank calendar.
}else {
  $records = $result->getRecords();
}
```

Now that we have the $month, $year, and $records variables defined, we can draw the calendar where we want on our page with one single line of code.

```
echo draw_calendar($month,$year,$records);
```
