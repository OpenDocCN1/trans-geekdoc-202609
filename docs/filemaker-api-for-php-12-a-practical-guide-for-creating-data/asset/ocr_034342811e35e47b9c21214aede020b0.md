# Meta Refresh and Redirect

Meta refresh is also known as a redirect. It's used to refresh or reload the current page or redirect the user to a different page after a defined amount of time. This is usually installed on a web site if pages have moved or your PHP code has changed and you have to have the user redirected to the starting page in the workflow.

To refresh your page every 3 seconds you can use the following code. You probably don't want to refresh your page very frequently because it makes a new call to the web server each time. I think you can imagine the load it put on the server if hundreds or thousands of users were refreshing their page every few seconds. That's where AJAX (Asynchronous JavaScript) is probably much more useful because it can refresh certain sections of your page. An AJAX example will be covered later in the book.

```
<meta http-equiv="refresh" content="3" />
```

If you want to redirect happen at a certain time interval and send the user to a specific URL you can use the following code. The URL, of course is either a relative or absolute path.

```
<meta http-equiv="refresh" content="3;URL=SearchResults.php" />
```

If you want to redirect the user you only need to provide the following code without any tags on the page (i.e. html, head, body, etc.). Substitute the page (location) you want to go to.

```
? PHP
header("Location:FindAllRecords.php");
```

# Designing a Web Application

Designing a web application is anything you've probably had to do when compared to developing a FileMaker Pro is the hook. As FileMaker makes most of the processes so seamless that you really don't need to know what goes under the hood. As a FileMaker developer you've become accustomed to making one layout that does absolutely everything — search, create new records, modify records, delete records, etc. Well let's say that a web application isn't as quick as FileMaker. As a stateless process, there is no connection to the database server, you have to tell (program) the pages absolutely everything they need to know. That means you have to create all the necessary web pages for every single workflow. In many cases the workflows really can't be reused. For example, to accommodate one FileMaker layout and all the things that it can do, you'll have to make less than four web pages! If you portals on your layout, you'll need to double that number. The good news is that there are standard methods and nomenclature to describe the workflow.
