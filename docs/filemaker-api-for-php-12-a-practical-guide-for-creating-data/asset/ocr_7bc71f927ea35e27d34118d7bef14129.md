# # Error Server Logs

When I write my PHP code I'm constantly checking each section of code for errors by loading the web page in a browser. There's nothing worse than trying to write an entire page to find out that there's a semicolon or misspelling in the code somewhere and I have to spend several hours to troubleshoot it. Sometimes it's so bad that I actually re-write the entire page from scratch because it's simply faster than troubleshooting. It's also helpful to refer to the error logs Apache, IIS, the web publishing engine, or the web publishing core to find out what's going wrong. This is especially true if you are troubleshooting script from your PHP code.

Apache and IIS Server generate an access log and an error log. These text files record every request made to the web server by a. The access log contains information such as the URL, the date, the time, the IP address, the requested files, etc. These logs can be used to help measure the metrics of your web site. The error logs record every problem the server has encountered. Common issues are missing web pages (broken links). Free tools like AWStat from aws.net can help you analyze these files with visual graphs and statistics help you improve your site. If you have the budget for enterprise analytics you might want to check your Google analytics software.

You can use any application capable of opening plain files, the Mac OS Console application, or the FileMaker Server Administration Log Viewer to view or export the log files. Events are logged continuously, with the most recent log at the bottom of the window. In a multiple machine deployment, the log files are on the same machine as the FileMaker Server component that generates the log. All log files are located in the Logs folder:

Windows: [d]:\Program Files\FileMaker\Server\Logs

Mac OS:/Library/FileMaker Server/Logs
