# Windows Server 2008 R2 and Windows 7 Specific Issues

Windows Server 2008 R2 and Windows 7 is kind of a pain in the ass (to say politely) to get it to run correctly. Pretty much everything turned off by default, so it takes a lot of extra configuration with no documentation to really tell you what do when things get down. Here's what I've found works reasonably well from a FileMaker Server perspective:

+   1. The operating system firewall is set to block all incoming ports by default. That means you'll need to add exceptions to the firewall and/or turn the firewall completely off, which isn't a bad idea. It will only be used as a server with limited access by administrators, so your risk of having a problem is fairly small. FileMaker Server needs the following ports per Tech Article #10672.

80, 5003, 16000, 16001, 16016, 16018, 2399, 16006, 16008, 16010, 16012, 16014, 16004, 50006, 5013

+   2. If you are running a single server setup you need to specify a "hostspec" setting in your PHP connection file. If you do, you should use https with the IP address of the server followed by port 443. This is the same value that you use in the web server deployment scenario that I discussed earlier. For:

```
https://192.168.1.5:443
```

Actually, a little known fact is that FileMaker assumes the correct localhost connection (http://127.0.0.1 or https://127.0.0.1:443) if no hostspec is defined. Therefore, it's just as well to leave out of your connection file in a single machine deployment.

3. PHP uses the C:/Windows/Temp to store temporary files, session information, etc. However, by default IIS Server no longer has access to folder. You need to add IUSR and the IIS_IUSRS Groups with full control to the Temp folder.
