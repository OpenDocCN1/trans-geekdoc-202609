The limiting factor for performance is the web publishing engine. Where you place this component will obviously affect the performance of the machine it's. So the question is, do you affect the performance of your web users or your FileMaker Pro as a result? FileMaker suggests placing it on the web server or on the machine hosting FileMaker Server as the overall method. That's probably a good recommendation in most cases where the database is to hog RAM, but the downside of this configuration is that you have to invest in two servers. Lastly, the three machine option places each of the components on their own server. The downfall of this approach is that you're talking about purchasing three servers. An inside tip about the three machine model is that not FileMaker has been able to prove that this configuration is significantly faster than two machine model. The only reason it exists is because some of your larger clients felt it better for the overall scale of the architecture. I'm not sure about that.

So which model is right for you? For location server I would start with the easiest and cheapest deployment option, which is the single server model. If you find that you need more performance you can always use the installation wizard in the Admin Console to change the server to a two machine model. Your testing server can absolutely be a single server model on your work station or laptop top at the same time you have a FileMaker Pro client installed. I have the single machine model on my laptop so I can demonstrate sample web sites and databases running with Apache and FileMaker Server for client presentations.
