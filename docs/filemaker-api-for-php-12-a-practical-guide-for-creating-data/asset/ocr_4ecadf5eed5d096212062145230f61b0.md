# Create a Form

Forms will quickly become best friend when working with data from a database. You will use forms to search for records and submit data to create, update, and delete records. Inside the form you will be able to pass various pieces of information to the web server and database. The data can be either entered, as in the Search field 2, or can be hidden that you don't want the user to be able to see.

All forms use the `<form>` tag. The action attribute points to the document you want to process the form. It can either be an absolute path such as `http://www.mysite.com/Form.php` or it can be a relative path to another document in another format such as `../Different.php`. Sometimes the form will point to itself and sometimes it will point to a different file. It depends on how you want to set up your form for the user workflow. There are distinct advantages to both methods. Pointing the action to the same document means that you'll only have one document to manage. However, the code on one document may be quite long to handle a variety of branching operations, discrete, logical fashion — similar to a second document will allow you to process the form in a more organized way. The downfall is that you'll have your site to manage.

```
<form action="Form.php" method="get">
<input name="id" type="hidden" value="<?php echo $_GET['id']; ?>">
<p>
<input name="Search" type="submit" value="Submit">\p>
</form>
```

The method attribute is of critical importance. There are two methods that you can use to pass information between web pages — GET and POST. GET will send all the data from the form in the URL. The URL is visible to the users. The advantage of sending the data in the URL is that users will be able to bookmark your page. The disadvantage is that the users may be able to see information you don't want them to be able to see. Additionally, there is a limit to how much data you can send in the URL.
