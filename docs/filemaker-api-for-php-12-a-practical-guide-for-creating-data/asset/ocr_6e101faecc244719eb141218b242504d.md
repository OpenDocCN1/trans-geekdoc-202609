# Disconnect Idle Users.

FileMaker Server is a client-server product. It means that there is a constant connection between the FileMaker Server and the FileMaker Pro clients. If the clients are idle for long periods of time it wastes the performance of the server. You should set the maximum idle time for FileMaker Pro clients to a setting such as one or two hours. I prefer this time range because it gives users enough time to go to a meeting or lunch break. Come back and resume the work. If they are longer than that they will be disconnected automatically. Otherwise your internal security issues will dictate if this needs to be more strict.

This setting has nothing to do with your web server. The web server is not a persistent connection. When a search query is sent by the web server to a database connection opened, the records are found by the database and returned to the web server, then the connection is closed. That's why FileMaker Server only allows 200 concurrent connections from the web server. The process is literally completed in milliseconds. Therefore, 200 concurrent connections can be thousands of concurrent users. If you have a lot of users they will wait in the queue until the server is ready to handle the request.

# Assign FileMaker Server as Much RAM as Possible

In most cases you will assign 64 GB of RAM to FileMaker Server which does not mean that this is the best idea. Again, just because you need enough RAM for the operating system and your web server to operate efficiently, you do have to determine the setting for how frequently you need to flush the cache. Most modern operating systems and processes can flush several gigabytes of RAM in 1 minute, which is the recommended setting. However, if you have a busy web server or a lot of users you can boost the performance of the server by increasing the time interval for the flushing process. The longer the interval, the more RAM you will use. By constantly changing and clearing the caches with information in RAM, the change will be. This is why you will want to set the flush interval lower. If your database doesn't often change you can increase the flush interval and rely on the backup schedules to recover from an older copy if the file server crashes. You really don't need to assign more RAM to FileMaker Server than the total size of your databases. You're better off allowing the operating system and web server to utilize the extra RAM. Anytime the operating system has to dig into Virtual RAM the performance will take a huge hit because Virtual RAM is actually taken from the hard drive, which is the slowest component on your server.

# Turn off the Server Logs

For absolute performance you can turn off the logging for both the database and web server. The logs don't take up much space. However, it's just one more for the server to do that may not provide you with the most useful information. You can keep them on for your testing server so you can troubleshoot the web server, database server, and web pages. When you first set up your production server you also keep them for a period of time until you determine that the server is stable. If you encounter any problems you can always turn them back.

# Turn off IWP

If you are not going to use Instant Web Publishing IWP places to retrieve data from the database and generate all the images and design from your layouts. The more complex you make your layouts the longer the server will take to respond. Additionally, if you insert high quality graphics rather than those built in tools and colors from the color palette it will add more tax to the server to display your graphics.

IWP shares the count web connections. You can assign up to 100 connections. Again, just because you can not make it the best. Typically when you are developing an IWP application you will know how many users will use the server via IWP. You can start with that number. Then after a few weeks you can check the server statistics for the peak number of users. Then change the setting to that number.

# Choose the Appropriate Server Model

FileMaker Server can be deployed by the application with three different models (4 configurations). The one you choose depends on your budget, performance needs, and security issues. The single server model is the cheapest, but has the slowest performance because all the applications have to share the same processor. The single machine model places the database server, web publishing engine, and web server all on one machine.
