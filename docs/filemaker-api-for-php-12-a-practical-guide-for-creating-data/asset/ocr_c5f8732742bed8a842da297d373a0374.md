# Lesson 35: Compare Dates

Objective: In this lesson you will learn how to compare dates with FileMaker vs. PHP. Sooner or later you're going to need to display records that are filtered by date or some type of comparison to make a branched decision. For example, only showing a schedule of related records with a date greater than today. Most of you thinking, easy, I'll simply filter the portal on the database layout and use the setRelatedSetsFilters to filter the display and it will be a piece of cake. The problem with that is at the time of the writing of this lesson, the setRelatedSetsFilters function didn't work. So you're going to create a specific occurrence (TOG) with extra fields and then code the Privilege Set to filter the records, or perform a date comparison in your PHP code. Each has its pros and cons. Extra TOG means unwanted overhead for your PHP site. The Privilege Set is no different than using the portal filter set dialog box. All the records are returned to you. Which records are controlled by the FileMaker engine. So you will have the same load on the server as if you were sending all the records. The problem is that the Privilege Set filters all the records, all the time, on every layout, rather than just one portal on your special PHP page. So your only reasonable choice to cut on overhead is to program the date comparison on your PHP page to keep your database as clean as possible. This lesson will show you several different methods (and pitfalls) that you can use to compare dates in FileMaker vs. PHP.
