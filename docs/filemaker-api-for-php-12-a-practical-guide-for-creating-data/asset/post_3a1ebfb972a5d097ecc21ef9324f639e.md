# page2.php

The second page serves two purposes. The first is to "catch" the fields and values posted from the first page and store them as hidden fields in the form. The second is to display another set of fields, all of which will be posted to the final page in the process.

Rather than describe an identical form order again, let's focus on the PHP code placed at the bottom of the form. All the fields from page1.php were sent using the POST method. As you are aware, POST formatting is name=value. That's basically an array where name=key and value=value. Therefore, we'll loop through each of the name=value pairs as an associative array using the foreach method. The only one we want to skip is the "next" button because that data is got by the URL encoding process using strip_tags. Otherwise we'll un-quote, or remove any backslashes the hidden field text inserted by HTML or PHP tags. Finally, the value will be converted back to the original text using htmlentities. The last notable item you may need to change is the word name of the submit button from the previous page. I encourage you to view the source code to see how the hidden fields were added to the bottom of the form.

```
<?php
foreach($_POST as $key=>$value) {
  if($key!="next") {
    $value=htmlentities(stripslashes(strip_tags($value)));
    echo "<input type=hidden name=$key value=$value\">\n";
  }
}
?>
```

# Lesson 43: Print PDF Report

**Objective:** In this lesson you will learn how to create a PDF report. If you are developing PHP applications, sooner or later your client is going to request the ability to print a report as a formatted document. At first you're going to cringe because printing from a web page has some limitations. Therefore, you might suggest that the report be downloaded as PDF file rather than relying upon your browser's PDF driver. Let's face it. FileMaker clients are very accustomed to reports being installed at breakspeed wherever, PDF reports generated from a web application can take hours or days to produce. You'll definitely need to let your customer know that each report can cost thousands of dollars to produce. The goal of the report is to create a header, an Excel-table-like body with all the data from the database, and a footer with the page number. There are two decent classes that you can use as an alternative. The simplest is FPDF, which is very easy to use. It is perfect because you can get up and running in a reasonably short amount of time if your report is simple. The other free class is tcpdf.org. This class has more features and slightly more examples. To be realistic, creating a PDF report from a web application is not easy or fast. It can be daunting, especially if you have dynamic content that changes in length. PDF is supported by the FDF class from PHP.net. It's not free. You don't have to purchase a commercial license from pdflib.com. The price starts at $195 for Windows and OS X. Although this is a very robust class with a lot of features it might be far more advanced than you need. I highly recommend that you at least look through the examples before you proceed with this lesson because I'm only going to provide a basic working example that utilizes a few built in features to generate the report.
