**Objective:** In this lesson you will learn how to run a script stored in the database. This is where the power of the FileMaker API for PHP shines well over ASP and JSP. When you incorporate running a script with your PHP code you will quickly recognize that you can make very powerful applications. ## Modify Number Script

As I mentioned earlier, the goal of this script is quite simple: Update the Number field in all the records. However, there are several important issues worth noting when running scripts from PHP:

- 1. Only Server compatible scripts work.
- 2. You may have to pass script parameters to the script.
- 3. If you use Allow Alert On unsupported script steps stop the script. If you use Allow Off Off script steps are skipped and the script will continue to execute.
- 4. You should use Error Capture On. If FileMaker returns an error make sure the dialog box doesn't show.
- 5. FileMaker Server will return whatever records are in the found set at the end of the script.
- 6. If you delete all the records in the found FileMaker will return the remaining records in the table.
- 7. Test, test, and test more. Then test it again because I'm sure you missed something. When you combine PHP code and FileMaker scripts the complexity of their interaction creates a totally different level of testing and validation requirements.
- 8. Testing the script absolutely must be done via a web page or through the FileMaker Server Admin console as the results can vary greatly if you only test on a local FileMaker Pro client. Remember, only Server compatible scripts will run and you may have to test script parameters, which can't be replicated using FileMaker Pro.
