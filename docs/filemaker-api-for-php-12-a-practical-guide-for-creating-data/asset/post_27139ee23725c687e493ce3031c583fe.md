# Lesson 46: Validate Phone Number

**Objective:** In this lesson you will learn how to validate a phone number. Formatting phone numbers using FileMaker Pro has been around for a long time. Making sure users enter the phone numbers in a consistent format should be part of your developer's tool bag of capabilities. The methods we've used over the years have changed several times in FileMaker Pro. If you need to allow web users to enter phone numbers into your database you will need to validate their data entry using PHP. Fortunately, this is a relatively easy process using regular expressions to test the format prior to submitting the form to the database.

**Difficulty:** Difficult

Start by connecting to the database.

When you click the button in the html form the PHP code below will run. It will validate the phone number format before it's submitted to the database. I'm using the GET method for demonstration purposes so you can see the URL. In a production website you'll probably be using the POST method. To start the code you want to make sure the GET method is set and that the button's name is Submit. Next, I'm going to use a regular expression to define the pattern I want my phone format to match (XXX-XXX-XXXX). To explain the regular expression, I'm going to provide a list of options that you can choose from your own phone format. The only thing you have to do is regular with regular expressions is to separate matching criteria with "^" if you want to use the $match option for the preg_match function.

```
//
Start the data (required)
[0]
0 or 1 "(\ character
(\d{0,3})
0 to 3 numbers for the area code
[1]
0 or 1 character
[\s]
0 or 1 white space character
[-]
0 or 1 dash
```

(\d(3)) Exactly 3 numbers for the exchange
[\s] 0 or 1 white space character
[-] 0 or 1 dash
(\d(4)) Exactly 4 numbers for the number

If you use all the options above, your phone number would be formatted as XXX-XXX or (XXX) XXX-XXXX.
A regular expression would look something like:

```
/^(\d(0,3))?[-\s]?\(\d(3))\)?[-\s]?(\d(4))$/
```

On the other hand, I prefer to force the user to supply the entire phone number, including the area code.
Therefore, I suggest that you use the code below for this example. I also know that when the user is done typing in their phone number the length of the number should be exactly 12 characters, including the dashes.
So I'm also going to use the str (length) function. If there is anything that doesn't match I'm going to set the $message variable with the response for the user and display it in this form.

```php
<?php
If(isset($_GET['Submit']) && $_GET['Submit']=='Submit') {
    // Match the number 858-555-1212 and be 12 digits
    $pattern = '/^(\d(3))?[-\s]?(\d(3))?[-\s]?(\d(4))$/';
    if (preg_match($pattern, $_GET['PhoneNumber']) &&
        strlen($_GET['PhoneNumber'])==12) {
        $message = 'Thank you for using the correct phone number format.<br>';
    } else {
        $message = 'Invalid phone format.<br>';
        $errors = 1;
    }
}
```

When we've validated the phone number we can insert it into the Database. Since the data is coming from the web I use the strip_tags function to clean up the data just in case some hacker has figured out how to spoof a phone number with malicious code. Alternatively, if you want to use the FileMaker engine use preg_replace('/D/', '', $_GET['PhoneNumber']), where preg_replace is used to strip everything except the numbers from the phone. I have included the code commented out in the PHP page if you want to try it. I have also included the calculation in the database to auto-format the data entry by default.

```php
if(empty($errors)) {
    $request = $fm->newAddCommand('Demo');
    $request->setfield('PhoneNumber', strip_tags($_GET['PhoneNumber']));
    $request->execute();
    if(FileMaker::isError($result)) {
        $message = 'Error: ' . $result->getMessage() . ' Please try submitting your phone number again.<br>';
        exit;
    }
}
```
