## Security

Security is extremely important when it comes to web users having access to your data. I cannot stress enough that you should NOT give any PHP enabled account access to the database that they should not have. You should specify custom privileges for records, layouts, value lists, and scripts. You should only allow access via PHP Web Publishing. You should not allow printing, managing extended privilege sets, overriding data validation, or allowing us to change the password. Menu commands should be set to minimum, if not completely removed with custom menus. The only privilege the PHP users should have access to is exporting records so the data can be displayed on the web. Other that be cautious about what privileges you give to the PHP users as they certainly do what you give to them. This means you may have one account for external customers who is locked down except records and a second for internal users that have more access based on their level of training.

Choose privileges and save them as a "Privilege Set", which can be used by one or more accounts. If you edit a set, all accounts that use it will be affected.

**Code:**
All PHP code starts with <?php and ends with ?>. Start by using the PHP method require_once to load the FileMaker API. This allows you to access the methods.

```php
<?php
require_once ('FileMaker.php');
$fm = new FileMaker();
```
Create the $fm object Take note of the variable name fm. This object will be called in every sample to retrieve data from the database.

The next section is your "connection string" to the database. Database is the exact name of the database. You do not need to include the fmp extension. Hostspec is the IP address (ex. http://192.168.1.100 or http://127.0.0.1) or domain name (ex. http://formulationspro.com) where the database is being served. If you have a single server solution http://127.0.0.1 will work perfectly. Technically, FileMaker assumes the hostspec of 127.0.0.1 if the property is not declared. I am assuming you are using a single server in this book. If you have a two server solution you will need to use the address of the server hosting the database. Username is the account name in the database — remember that the account needs to be assigned to a Privilege Set that is PHP enabled. Password is the password for the account. For the sample files and php_demo.fmp12 sample database the account is "Admin" and the Password is "1234".

```php
$fm->setProperty('database', 'php_demo');
$fm->setProperty('hostspec', 'http://localhost');
$fm->setProperty('username', 'Admin');
$fm->setProperty('password', '1234');
```

> Do not use http://localhost on Windows. Windows is unable to resolve localhost to 127.0.0.1 and may cause poor performance and/or crashing problems. Instead, always use //127.0.0.1.
