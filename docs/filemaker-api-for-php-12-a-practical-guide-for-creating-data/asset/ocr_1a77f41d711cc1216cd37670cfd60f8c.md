# Lesson 39: Google Map API Geocodes

**Objective:** In this lesson you will learn how to integrate the Google map API. This lesson will focus on how to update your database with latitude and longitude values. You might be wondering why you want to use lat/lon values rather than relying on the Google Maps API to convert an address to coordinates. The reason is performance. If you use lat/lon values you will update your web site significantly faster. For example, the database supplied with this lesson has 152 records. It takes approximately 20 seconds to retrieve the data from Google and update the records. Can you imagine how long it would take to convert a zip code for 45,000+ geocodes? Try more than 30 hours if the browser doesn't crash, the server runs out of memory, or Google kicks you out of their service. Therefore, it's important before you start to use the Google Map API that you acquire the latlon values for your records before you go.

Code:

The PHP page is really an administrator only feature. That means it's not intended for a web user to retrieve a list of Geocodes, which would be a violation of the Google Terms of Service. It's a tool for an administrator to populate an existing table of data before you implement the use of Google Maps on your web site. With that I would suggest to you that the majority of the code on the sample PHP page is totally unnecessary. For demonstration purposes I've included a lot of extra code to display the data in the browser so you can see the lat/lon values that are added to the database. However, you don't really need to see it in your browser. I have extensively commented the code to identify only the code that is necessary as well as the code that you can remove if you're a pure speedy. This lesson will only discuss the minimum code that is necessary to update the records with the lat/lon values.

Always start by using the connection to the database.
