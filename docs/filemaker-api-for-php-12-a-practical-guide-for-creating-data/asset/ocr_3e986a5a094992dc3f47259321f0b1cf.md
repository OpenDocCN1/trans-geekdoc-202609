# Lesson 45: Subsummary Report

**Objective:** In this lesson you will learn how to create a sub summary report. Displaying data from your database PHP is relatively easy. Eventually you'll be asked to create reports on the web. I'm sure you know what that means — your customer will want to create a sub summary report that's also reordered by a summary file. The classic example is the sales report that is sorted by the sales person and reordered by the sales subtotal. That report is difficult to design in FileMaker for most developers. Then when you add the web into it adds another level of complexity. The key is to understand the FileMaker API returns data based on your layout design. Therefore, if you can create the report on a FileMaker layout you will have completed most of the battle to generate the report using PHP.

The intended use of the database table is to mimic an invoice table that is used to generate a sales report. The **Amount** field is the invoice total. The **SalesPerson** field contains the sales person for the invoice. The **Subtotal** and **GrandTotal** summary fields are generated by the report on the Subsummary Report layout. If you switch to the Subsummary Report layout and inspect the layout you'll see that the report is sorted by the SalesPerson and reordered by the Amount field. This will generate a report that is sorted with the highest Sales Subtotal listed. The goal of this lesson is to reproduce the FileMaker report on a PHP web page.

To create the report it is imperative that you understand the following concept. When you display data on a PHP page your fields must be in the body of the FileMaker layout to make them available to the API. The issue you'll run into generating a sub summary report is that the summary fields won't be in the body of a FileMaker layout, they'll be in the summary section, footer, trailing grand summary, etc. That means the key fields you need, such as the Subtotal for each sales person and the GrandTotal not be available to the API. So you might be asking, how do we get this data from the database if it's not available to the API? The answer is we'll have to recreate the math using PHP to generate these values on the fly. That is the key to generating the web page that we'll demonstrate below.
