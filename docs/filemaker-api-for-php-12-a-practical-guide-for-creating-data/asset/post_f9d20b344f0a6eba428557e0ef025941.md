# PHP Duplicate Record Script

The script's task is to take the Record ID passed by the web page and find the parent record. Once the parent record is found it will duplicate the parent and related records. This is a very common script even for FileMaker client programming.

Start by making sure you turn on User Abort and Set Error Capture.

- Allow User Abort [ On ]
- Set Error Capture [ On ]

Create the $RecordID variable from the script parameter passed by the PHP code.

```filemaker
Set Variable [ $RecordID; Value:Get(ScriptParameter) ]
```

Use the Demo php layout to find the parent record.

```filemaker
Go to Layout [ "Demo php" (php_demo) ]
Enter Find Mode [ ]
Set Field [ php_demo::RecordID; $RecordID ]
Perform Find [ ]
```

Make sure you trap for errors and stop the script if no records are found.

```filemaker
If [ Get(LastError) > 0 ]
Halt Script
End If
```

Duplicate the record and store the Record ID of the new record so it can be passed to the foreign key for the new related records.

```filemaker
Duplicate Record/Request
Set Variable [ $PK; Value:php_demo::RecordID ]
```

Duplicate the portal records from the original record. Then change the foreign keys to the new primary key.

```filemaker
Go to Record/Request/Page [ Previous ]
Go to Related Record [ From table: "related_data"; Using layout: "Related Data php" 
(related_data) ] Show only related records
```

I like to start from the last record when I duplicate records. It makes it easier to know when you duplicate all the records because there are no records remaining in the set as you omit the records after the foreign key is updated with the new key value.

```filemaker
Go to Record/Request/Page [ Last ]
```

Loop through all the records, creating a duplicate for each one and changing the foreign key.

```filemaker
Loop
Duplicate Record/Request
Set Field [ related_data::$PK ]
Omit Record
Omit Record
Exit Loop If [ Get(FoundCount) = 0 ]
End Loop
```

Commit the records to make sure they show up on the web.

```filemaker
Commit Records/Requests [ Skip data entry validation; No dialog ]
```

# Lesson 32: Install and Configure SSL to Work with FileMaker Server

**Objective:** In this lesson you will learn how to install and configure SSL to work on Windows or OS X with FileMaker Server. There are although no sample files, it is important to know how to configure SSL.

**Difficulty:** Easy

**Sample Files:** None

**Page:** N/A

**Procedure:**

![](img/5a2c5fda68d42e5d65f51850276e49ec_258_0.png)

1. Open IIS.
2. Click your server in the Connections window.
3. Click Certificates in the Security section.
4. Click Create Certificate Request in the Actions window.

![](img/5a2c5fda68d42e5d65f51850276e49ec_258_1.png)

Figure 7-78: Prepare the Certificate Request

5. Follow the wizard to create the certificate, also known as CSR.
   a. Organization: use the business legally registered to the domain.
   b. Organizational Unit: use the department in your company.
   c. Common Name: enter the fully qualified domain or URL for which you plan to use, such as formulationspro.com. You can also use wildcard domains as *.formulationspro.com. However, this typically cost money.
   d. Country: use the 2-letter ISO code for your country, US for United States of America.
   e. State/Province: use the full name of your state, such as California.
   f. City/Location: use the full name of the city where you are located, such as San Diego.
6. Click Next
7. In the Cryptographic Service Provider window, select Microsoft RSA Cryptographic Provider with 2048 bit length.
8. Enter the path where you want to save the (i.e. your desktop of folders) and click finish.
9. Send the certificate to your Certificate Authority (CA). The company that you will with your SSL certificate (i.e. Verisign, Go Daddy, etc.). Some may want you to request and copy/paste content into their web server for submission.
10. They will typically send you a file by your server. Then click Complete Certificate Link in the Actions window and follow the wizard to install the certificate.

![](img/5a2c5fda68d42e5d65f51850276e49ec_259_0.png)

11. Choose your site in the Connections window.
12. Click the bindings in the Actions window. Your regular HTTP (Port 80) binding should be active.
13. Edit the Port 80 binding and change the host name to your web site (i.e. formulationspro.com). That will tell IIS to listen to any request using that domain for the web site folder.
14. Now click Add to install the SSL binding. Choose hosts for the Type and Port 443. You should be able to choose your newly installed certificate from the pop up menu for the binding.
15. Click save when you are done and your web site should now be enabled to use SSL (i.e. https)
