The import table is a stand-alone table used for the import (upload) scripts. It's purpose is to log each file that is uploaded to the server and capture information to determine if the upload was successful or not. The URL is the path to the original location and file name uploaded to the server. Success identifies how many records were imported from the .XLS file. If it's blank, the import was not successful. ScriptParameter is the name of the file as converted by the PHP code and script each file has a unique name. DocumentsPath is the final location of the uploaded file.

# Field Validation

Field validation is a very important consideration when building your web site with PHP. If you include-level validation you'll need to test your PHP web pages carefully to ensure that creating, updating, or deleting records does not throw an unexpected error. You'll also need to configure FileMaker Server's Web Publishing PHP setting to enable record data pre-validation. One thing to keep in mind is that although FileMaker's validation options are very robust, you may be better off using validation on the web pages so you don't have to check the web server or web-publishing engine for errors. The example files will demonstrate how both the PHP and FileMaker methods work to ensure the integrity of your data.

> When testing the Strict data type: Date Only, I found that even though the web page was sending the correct date format, the web publishing engine would reject the data and not update the record.

> Validate by calculation does not work when validating data using the web server or web publishing engine. Validating by calculation will have to be performed on your web page before submission to the database.
