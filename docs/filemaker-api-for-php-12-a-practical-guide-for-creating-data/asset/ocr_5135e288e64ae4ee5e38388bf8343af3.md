# Other Methods — PHP/ODBC, ASP, JSP, IWP

There are quite a few options available to publishing data to the web with FileMaker. The FileMaker API for PHP is not the only available option. CDML (from Claris/FileMaker) and LDML (from Lasso) came many years ago, but long since been abandoned because they were proprietary technologies that didn't keep up with the standards. PHP is not necessarily the best option depending on your requirements. Therein the problem: Before you embark down the road of building your web site you need to know the pros and cons of each technology. Therefore, I will not be providing any examples of installing, configuring, or utilizing these technologies. These technologies are outside the scope of this book. If you would like more information regarding the use of these technologies you can visit our web site at www.formulationspro.com.

# PHP/ODBC

PHP can utilize an ODBC driver to access FileMaker Server. This is similar to MySQL. Therefore, if you are comfortable with MySQL you may find that using the standard ODBC driver will get you up and running without modifying your code (with the exception of MySQL specific functions).

Server Operating System: Windows or OS X

Application Server: IIS or Apache

Driver: ODBC

+   Pros:
1. Allows you to use standard SQL commands to access the database. This is a very traditional approach that many people are comfortable using.
2. Dreamweaver has built in support for PHP, ODBC, and SQL. You would be using the MySQL settings since there is no built in configuration for FileMaker Pro.
3. FileMaker provides the ODBC drivers for free.
4. You can use the FileMaker API for PHP code, such as running scripts.
5. You can utilize a lot of the PHP/MySQL materials and third party products without having to do much work to convert the code to the FileMaker API for PHP.
6. You can display images from a container using PHP.
7. Apache is free and can be installed on either Windows or OS X.
8. IIS Server comes with Windows Server and has a nice user interface to configure the server.

+   Cons:
1. Installing the ODBC driver can be hassle.
2. The ODBC driver can be a major issue in the long run when you upgrade the OS or FileMaker Server. FileMaker has switched ODBC drivers manufacturers since is not capable of providing OEM technical support if there is a problem. If anything is broken you may have to wait a long, long time before it gets fixed.
3. Using an ODBC driver is just one more layer of technology to develop.
4. The ODBC driver is not as fast as the FileMaker API for PHP.
5. The Windows Server software and CALS are not free. Using Windows will be a more expensive approach.
6. Apache requires manual configuration.
