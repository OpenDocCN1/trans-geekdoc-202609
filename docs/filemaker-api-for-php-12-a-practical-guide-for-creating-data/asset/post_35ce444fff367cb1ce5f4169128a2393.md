# Code:

Line charts have a lot of features that can get complex incredibly fast. Especially when you have more than one series of data. The Google Chart API allows you to build simple charts and without axis, define both x and y coordinates for each point, and compound line charts. I chose to create a compound line chart to represent my graph for the data, upper control limit (UCL), and lower control limit (LCL).

The Google Chart API makes charts incredibly easy for every skill level. The hardest thing you'll encounter is retrieving the data from the database and formatting it to their standards, which isn't all that difficult. After that, it's up to you to determine which features of the chart you want to utilize. There are a few required elements and a whole of optional elements that you can utilize. The sample web page for this lesson includes every element with one simple line of code for an embedded image that passes all the data to Google and returns a chart to your web page.

> For complete information regarding the Google Chart API, please visit the Google web page: http://google.com/apis/chart/image/docs/making_charts.html

Always start by the connection to the database.

```php
<?php
```

For this article I'm simply going to find all the records in the database and sort them by the Date field in ascending order. Then store the data in the format required by the Google API. (i.e. Number, UCL and LCL fields) from each record to be formatted with commas and each index series of data separated by the chart axis as 1,2,3,4,5,6,7,8,9. The X axis (i.e. is a running count of the records starting at 1 for the first data point) needs to be formatted with the pipe character, such as |1|2|3|. These formats need to be edited or the chart will return an error. Note that the pipe character is wider than the numbers so it would look strange but I wouldn't expect to fix this time soon.

We'll also calculate the min and max values for the Y axis. If you didn't define these numbers the API will normalize yours to 100%, which will be off the scale of the chart. To calculate the value we will start it by the LCL. Then as we loop through the records we'll only need to check if it is less than any of the data, UCL or LCL values, which will accommodate a full-chart with negative values. Otherwise, it will scale the Y axis to 5% to ensure the max value for the Y axis is a little earlier. Start the value at the UCL. Then as we loop through each of the records we can change it if any of the data, UCL or LCL values are larger. I also recommend that you scale the final max value 5% to ensure the line fits inside the chart for a clear visual appearance.

```php
$request = $fm->newFindAllCommand('Demo');
$request->sort->addSortRule('Date', 1, FILEMARKER_SORT_ASCEND);
$result = $request->execute();
$records = $result->getRecords();
$record = $result->getFirstRecord();
if($record) {
	$min=$record->getField('LCL');
	$max=$record->getField('UCL');
	$n=1;
foreach($records as $record) {
		$data[]=$n . ",";
		$labels[] = "," . $n . ",";
		$ucl=$record->getField('UCL') . ",";
		$lcl=$record->getField('LCL') . ",";
		if(min($record->getField('LCL'), $record->getField('UCL')) < $min) {
			$min=min($record->getField('LCL'), $record->getField('UCL'));
			$record->getField('Number');
		}
		if(max($record->getField('LCL'), $record->getField('UCL')) > $max) {
			$max=max($record->getField('LCL'), $record->getField('UCL'));
			$record->getField('Number');
		}
		$data = rtrim($data, ",");
		$ucl = rtrim($ucl, ",");
		$lcl = rtrim($lcl, ",");
		$labels = rtrim($labels, ",");
		$data = $data . "." . $ucl . "." . $lcl;
		$n++;
}
}
```

# Required Elements

Unlike the others, the goal is to build a URL string for an image container. The base URL string for type of chart is:

https://googleapis.com/chart/

From we'll add all the name=value pairs (NVP's) separated by & which is the URL encoded value for ".". Because we will be embedding the chart URL in the web page as an image source. To obtain the correct URL string special characters need to be URL encoded. That also includes any values in the data that might cause problems with the string. Rather than make a huge string of values I decided to define the required and optional variables within the PHP code. Then assemble the final URL string in any order to read and modify format. The NPs can be assembled in any order.

```php
<?php
// ... (logic to assemble the final URL string)
$scht = "https://googleapis.com/chart/?cht=lc&";
```
