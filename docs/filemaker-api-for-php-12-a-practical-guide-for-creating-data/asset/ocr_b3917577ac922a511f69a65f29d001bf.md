# PHP Duplicate Record Script

The script's task is to take the Record ID passed by the web page and find the parent record. Once the parent record is found it will duplicate the parent and related records. This is a very common script even for FileMaker client programming.

Start by making sure you turn on User Abort and Set Error Capture.

+   - Allow User Abort [ On ]
- Set Error Capture [ On ]

Create the $RecordID variable from the script parameter passed by the PHP code.

```
Set Variable [ $RecordID; Value:Get(ScriptParameter) ]
```

Use the Demo php layout to find the parent record.

```
Go to Layout [ "Demo php" (php_demo) ]
Enter Find Mode [ ]
Set Field [ php_demo::RecordID; $RecordID ]
Perform Find [ ]
```

Make sure you trap for errors and stop the script if no records are found.

```
If [ Get(LastError) > 0 ]
Halt Script
End If
```

Duplicate the record and store the Record ID of the new record so it can be passed to the foreign key for the new related records.

```
Duplicate Record/Request
Set Variable [ $PK; Value:php_demo::RecordID ]
```

Duplicate the portal records from the original record. Then change the foreign keys to the new primary key.

```
Go to Record/Request/Page [ Previous ]
Go to Related Record [ From table: "related_data"; Using layout: "Related Data php" 
(related_data) ] Show only related records
```

I like to start from the last record when I duplicate records. It makes it easier to know when you duplicate all the records because there are no records remaining in the set as you omit the records after the foreign key is updated with the new key value.

```
Go to Record/Request/Page [ Last ]
```

Loop through all the records, creating a duplicate for each one and changing the foreign key.

```
Loop
Duplicate Record/Request
Set Field [ related_data::$PK ]
Omit Record
Omit Record
Exit Loop If [ Get(FoundCount) = 0 ]
End Loop
```

Commit the records to make sure they show up on the web.

Commit Records/Requests [ Skip data entry validation; No dialog ]
