# PHP Modify Number Script

As I mentioned earlier, there's nothing spectacular about this script. The goal of the script is quite simple. Update the Number field on all the records in the table. Normally this script would only be a few lines long. However, because it is running from a web page by the server we have to include extra steps to ensure that it does what we want it to do. There are several important issues worth noting when running scripts from your php application:

+   1. The script knows about the found set. Just like the records displayed on the web page you will have to tell the script everything it needs to work on the correct found set of records. Therefore, you may have to pass one or more script parameters to assist the script to operate on the correct records.

+   2. Only scripts that are Server compatible work. Therefore, I recommend that you use Show Compatibility to "Server". It is really too bad that Save as Excel, Save as PDF, and Print are not supported. However, there are third party PHP modules for this that will demonstrate later in the book.

+   3. If you use Allow Alert On unsupported script steps will stop the script. If you don't include the Allow User Alert step FileMaker Server will assume that is set to On. If you use Allow User Ab Off unsupported script steps are skipped and the script will continue to execute. Because this will produce unpredictable results.

+   4. You should use Error Capture On. If FileMaker Server returns an error you don't want the dialog box to show because it may produce unpredictable results.

+   5. FileMaker Server will return whatever records are in the found set at the end of the script.

+   6. If you delete all the records in the found set FileMaker Server will return the remaining records in the table. That means you will have to include steps to Show All Records and Show Omitted Only to get 0 records in the found set.

+   7. Test, test, and test more. Then test it again because I'm sure you missed something. Everything you can possibly think of to break the script or destroy the records as your users will surely find a way to defeat your code! When you combine PHP code and FileMaker scripts the complexity of their interaction creates a totally different level of testing and validation requirements.

+   8. Testing the script absolutely must be done via a web page or through the FileMaker Server Admin console as the results can vary greatly if you only test on a local FileMaker Pro client. Remember, only Server compatible scripts will run and you may have to test passing script parameters, which can't be replicated using FileMaker Pro.
