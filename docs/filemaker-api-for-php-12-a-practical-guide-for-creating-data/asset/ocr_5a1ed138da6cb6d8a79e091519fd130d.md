The related_data table is very simple. The FK field is used to store the foreign key supplied by the php_demo table's RecordID field. The only field that is used for actual data entry is the Text field. As in all practices, you'll also notice that this table also has a RecordID field. You might be wondering at this point if the FileMaker API for PHP has a method to acquire the record's internal serial number, why do you need this extra field in the table and on the layouts? The answer is there is no FileMaker script function that can find records using internal RecordID having an actual field. Therefore, to make this information available to FileMaker Server and the scripts, you must create a field to display this information.
