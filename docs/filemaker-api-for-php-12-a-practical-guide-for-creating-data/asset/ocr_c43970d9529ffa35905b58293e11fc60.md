IIS and PHP performance is tied to pretty much the minimum performance settings out of the box. How much RAM you have on your server will dictate how much you can allocate to IIS and PHP. That means that you don't want to set FileMaker to hog 100% of the remaining RAM. You want to have additional RAM for your web server. You can improve the performance of PHP by changing a few settings in the php.ini file. I recommend that you do least the stock settings for the following items:

```
max_execution_time = 30 to 120 (seconds)
max_input_time = 60 to 120 (seconds)
memory_limit = 8MB to 16MB (MB)
POST_SIZE = 8MB to 16MB (MB)
```

I've seen significant improvement in overall server response time by changing these settings.. You will have to evaluate in your own environment on your web site, database design, and user load.

On IIS Manager you might also consider the following settings.

Output Caching to at least 16 MB
Cached Response size bytes 262144 to 2621440 bytes

The last item may be of concern for you is how to redirect users that gain access to your site with when they need to use them through PHP. PHP has some very simple code to redirect users.
