
## Bind the SSL Certificate to your web site on OS X.

Binding the SSL certificate to your web site on OS X server is very similar to Windows. Although there are far fewer steps.

- 1. Open Server Admin. Click your web server from the list of servers. Then click the Certificates icon.
- 2. Click the plus + button to Create a Certificate Identity.

![](img/5a2c5fda68d42e5d65f51850276e49ec_260_0.png)

Figure 7-80: Create a new certificate identity.

- 3. Enter the name of the domain for your web site.
- 4. Choose the identity type Self Signed Root. Don't worry, this will change automatically when you install the signed certificate from your Certificate Authority.
- 5. Choose the certificate type SSL Server.

- 7. Click the action icon and Generate Certificate Signing Request (CSR). This will create a text file (.csr) on your desktop. The CA will send you back a signed certificate that you will place in the next steps.

## Reconfigure FileMaker Server

At this point your web server is running like a champ on both http and https if you open the default web page (iisestart.html on Windows or index.html on QX) in your browser. However, you'll quickly notice that if you try to access your dynamic PHP pages from the database that nothing works and the web publishing engine crashes. Summer! There is some obscure documentation at FileMaker (Tech Article #7619) to use cURL with SSL certificates. Don't worry, you don't need to know anything about cURL for this work. Perform the following tasks to enable the cURL library:

- 1. Open the FileMaker API file located at:
/FileMaker Server/Web Publishing/publishing-engine/php/FileMaker/conf/filemaker-api

- 2. Uncomment the following line of code:

```
$_FM_CONFIG['cURLOptions'] = array(CURLOPT_SSL_VERIFYPEER => false)
```

```php
<?php
 * FileMaker API configuration file.
 * All settings are put up into the $__FM_CONFIG array to maintain a
 * clean global namespace.
 * * The default character encoding ('UTF-8' or 'ISO-8859-1', case matters).
 * $FM_CONFIG['charset'] = 'UTF-8';
 *
 * The default locale for providing string translations of error
 * codes. options are: 'en'
 * $FM_CONFIG['locale'] = 'en';
 *
 * The log level, if a logging object is provided.
 * $FM_CONFIG['loglevel'] = 'FILEMAKER_LOG_ERR';
 *
 * The default hostspec (127.0.0.1, for example), using http://localhost:80/
 * as it can cause performance loss. Do NOT include /php/xml in this string.
 * $FM_CONFIG['hostspec'] = '192.168.0.20:4043';
 *
 * Specify any additional cURL SSL certificates, etc. - in
 * an array, with curl option names as the keys, and values
 * $FM_CONFIG['curloptions'] = array(CURLOPT_SSL_VERIFYPEER => false);
 *
 * The PHP class to use for representing Records
 * $FM_CONFIG['recordclass'] = 'FileMaker_Record';
 *
 *
 * * Do prevalidation (validate in PHP) on Record data?
 * $FM_CONFIG['validate'] = false;
?>
```

![](img/5a2c5fda68d42e5d65f51850276e49ec_264_0.png)

- 3. Edit the server deployment for the web publishing engine by opening the FileMaker Server Admin Console (http://localhost:16000). Click the link to edit the server deployment. Follow the wizard to install the server deployment.
