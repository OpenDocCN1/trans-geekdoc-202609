Therefore, the only way to improve performance is to create PHP workflow layouts that have only the fields and portals you need to display on your web pages. Of course, more layouts also mean more system management and more documentation. The good news is that FileMaker clients won't access your PHP layouts. Therefore, you probably don't need to create an extensive user interface. Just the fields and portals will give you the opportunity to do things such as put development and name the layout something specific as "Contact php" and to never ever delete the layout unless you want to break your PHP pages. I also suggest that you have all your PHP layouts organized into a single folder FileMaker Pro as an additional reminder to developers to be incredibly careful when making changes to any database content related to PHP.

Changes to your layouts, value lists, tables, and scripts will break your PHP pages. If you make changes to your database you will have to update your PHP web pages.

# Naming Conventions

Naming conventions for fields are not only important for FileMaker Pro, but also for PHP. Web pages tend to be a lot more fickle when it comes to special characters, whereas FileMaker lets you get away with them. Standard web conventions state that you should name fields using a-z, 0-9, underscore, and no special characters such as periods, spaces, or high ASCII characters such as "?. The field name should start with a letter rather than a number or underscore. For example, use "FirstName", not "First Name". Notice that I used an uppercase letter to start each word to make reading the field name easier.
