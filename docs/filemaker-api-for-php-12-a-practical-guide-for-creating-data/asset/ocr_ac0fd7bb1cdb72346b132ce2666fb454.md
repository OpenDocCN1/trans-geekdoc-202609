# Store Locator script

The Store Locator is an important component of this process. After much debateated I decided that I liked this approach much better than returning all the records in the table, then using PHP code to calculate which ones to display. Both methods have their merit. However, I decided that for extensibility purposes it would be better to have the specific found record of the $records variable than constantly having to use extra PHP code to filter the display.

Every script that is run from the Server should start by turning Alert and Error Correction to On. This will prevent unsupported scripts from stopping the script and making sure error dialog boxes are not shown, which can cause unpredictable results on the Server. Next we need to insert the Latitude and Longitude values into the SearchList and SearchGlobal variables. Once the values are filled the distance will be calculated for every record in the table. If you remember from the previous section, the values are passed as a script parameter. That means you can access the data using the function Get(ScriptParameter). However, we've inserted the Parse-XMLData custom function, which allows us to parse the value of the parameter and perform the heavy lifting with the custom function to return the correct value. If you want to know more about the custom function you can read the article Parse XML Script Parameters, which is available at www.formulatinspro.com. The Distance requires a little extra handling. By adding "<" to the search criteria of the script we'll retrieve all the records from 0 to the specified distance. Finally, sort the records by the Distance and Name fields before ending the script and returning the found set of records back to the web page.
