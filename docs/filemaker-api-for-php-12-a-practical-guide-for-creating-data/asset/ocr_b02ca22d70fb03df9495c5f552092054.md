However, IIS does not handle redirects via PHP, so it throws an error. Apparently this is a known issue on the Microsoft support web site with no node of resolution. Therefore, you have exactly two ways to resolve this. First, is to enable the settings in IIS Server that requires access to the site only by SSL and change the 500 error page to redirect the user to the correct URL or make sure all your web pages and marketing links to your secure pages use https. Then hope that the users don't type in http on their own or bookmark the wrong URL.
