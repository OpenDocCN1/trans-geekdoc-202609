# Lesson 12: Display Externally Stored Container Field

**Objective:** In this lesson you will learn how to display the contents of a container field that stores the image or file externally to the container using the ContainerBridge.php file. This is a new feature in the FileMaker12 database. The getContainerDataURL method is the only method in the FileMaker 12 API. This new method opens some opportunities to not store files on the server to make the database smaller and more efficient, and it also allows FileMaker users to upload files to the container field and not have to utilize a specialized upload page or web server.

In my testing of this newgetContainerDataURL method, I found that it worked fine with images. However, displaying files, such as PDF, mp3, movie etc. exhibited major cross-browser problems. The worst being Firefox, showed the raw source code of the web page! Normally you would use the embed or object tag to display files. These do not work at all with this method. The alternative tag is iframe, which works on most browsers. Firefox users will need to install the View PDF addon and Adobe Acrobat Reader 10 or later. Since you cannot control which browsers and plugins are installed on the user's machine, your best method to display files is still going to be store the files on the server and use a text field with the path to the file.

Externally stored files are stored on FileMaker Server at:

```
FileMaker Server/Data/Databases/RC_Data_FMS/<ContainerDirectory>
```

Where Container Directory is the storage path that you set up for your container.
