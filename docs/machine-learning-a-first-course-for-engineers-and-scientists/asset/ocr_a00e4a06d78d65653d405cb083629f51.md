# 5 Learning parametric models

We can extend this idea of subsampling with even fewer data points used in each gradient computation. The extreme version of subsampling would be to use only a single data point when we compute the gradient. In practice it is most common to call a small subsample of data a mini-batch, which can typically contain $n_b=10, n_b=100$ or $n_b=1000$ points. One pass through the training data is called an epoch, and consequently of $n/n_b$ iterations.

When using mini-batches it is important to ensure that the mini-batches are balanced and representative for the whole dataset. If we have a big training dataset with a different output classes and the dataset is sorted with the output, the mini-batch with first $n_b$ data points would only include one class and not give a good approximation of the gradient for the full dataset. For this, the mini-batches should be forced randomly. One implementation of this is to first shuffle the training data, and thereafter dividing it into mini-batches in order and no pass through the training data. We summarize descent with mini-batches, often called *stochastic gradient descent*, by Algorithm 5.3.

Stochastic gradient descent (	extit{SGD}) is widely used in machine learning, and there are many extensions tailored for different methods. For deep neural networks (Chapter 6), some commonly used methods include automatic adaptation of the learning rate and an idea called momentum and constant to counteract the randomness caused by subsampling. The AddGrad (short for adaptive gradient), RMSProp (short for root mean square propagation) and Adam (adaptive moments methods) are such examples. For logistic regression in the "big data" using the stochastic average gradient (SAG) method, which agrees over all previous gradients has proven useful, to only mention a few

```
Algorithm 5.3: Stochastic gradient descent
**Input:** Objective function $J(	heta)=\frac{1}{n}\sum_{i=1}^{n} L(\mathbf{x}_i, y_i, 	heta)$, $	heta^{(0)}$, learning rate $\gamma^{(t)}$
**Result:** $\hat{	heta}$
1 **Set** $t \leftarrow 0$
2 **while** convergence criteria are not met
3 **for** $i=1, 2, \dots, E$ **do**
4   Randomly shuffle the training data $(\mathbf{x}_i, y_i)_{i=1}^n$
5 **for** $j=1, 2, \dots, n_b$ **do**
6   Approximate the gradient using the mini-batch $(\mathbf{x}_i, y_i)_{i=(j-1)n_b+1}^{jn_b}$
7   $\hat{	heta}^{(t)} = \frac{1}{n_b}\sum_{i=(j-1)n_b+1}^{jn_b} \nabla_{	heta} L(\mathbf{x}_i, y_i, 	heta)$
8   **Update** $	heta \leftarrow 	heta - \gamma^{(t)}\hat{	heta}^{(t)}$
9 **end**
10 **Update** $t \leftarrow t+1
11 **end**
12 **return** $	heta^{(t-1)}$
```

# Learning rate and convergence for stochastic gradient descent

Standard gradient descent converges if the learning rate is wisely chosen, since the gradient itself is zero at the minimum (or any other stationary point). For stochastic gradient descent, on the other hand, we can *obtain* convergence with a constant learning rate. The reason is that we only use an *estimate* of the true gradient, and this estimate will not necessarily be at the minimum of the objective function, but there might be a considerable amount of "noise" in the gradient estimate due to the subsampling. As a consequence, the stochastic gradient descent algorithm with a constant learning rate will not converge towards a point, but to "wander around" forever.
