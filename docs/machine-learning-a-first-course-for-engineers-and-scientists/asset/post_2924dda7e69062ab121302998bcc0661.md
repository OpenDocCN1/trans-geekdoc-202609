### Example 5.7: Early stopping with logistic regression for the machine classification example

We consider again the machine classification problem from Example 2.1. We apply multi-class logistic regression, and to evaluate the point of this example, we apply 20 degree polynomial input transformation. The polynomial transformation means that of having $\theta_0 + \theta_1x_1 + \theta_2x_2 + \dots + \theta_ux_u \rightarrow (\dots + \theta_{x1}^2x_1^2 + \theta_{x2}^2x_2^2)$ within the logistic regression, we now have 231 parameters and a limited amount of data which will most likely lead to overfitting if no regularization is used.

Logistic regression is learned using a Newton-type numerical optimization algorithm (Section 5.4). We can therefore apply early stopping to it. For this purpose we set aside hold-out validation data and monitor how $E_{hold-out}$ (with misclassification error) evolves as the optimization proceeds.

This example is indeed somewhat exaggerated, but the same effect can be seen in particular when training deep neural networks (Chapter 6).

In machine learning the training data may have $n=$ millions (or more) of data points. Computing, for example, of the cost function

$$\nabla_{\theta}J(\theta) = \frac{1}{n} \sum_{i=1}^{n} \nabla_{\theta}L(x_i, y_i, \theta) (5.37)$$

thus involves summing a million of terms. Besides taking lot of time to use, it can also be an issue to keep all data points in the memory at the same time. However, with many data points many of them are relatively simple, and in practice we might not need to consider all of them looking only a subset of them might give sufficient information. This is a general idea subsampling, and we will have a closer look at how subsampling can be combined with gradient descent method stochastic gradient descent. It is, however, possible to combine the subsampling idea with other methods.

### Stochastic gradient descent

With $n$ being big, we can compute the gradient only for the first half of the dataset $\nabla_{\theta}J(\theta) \approx \sum_{i=1}^{n/2} \nabla_{\theta}L(x_i, y_i, \theta)$ to be almost identical to the gradient based on the second half of the dataset $\nabla_{\theta}J(\theta) \approx \sum_{i=n/2}^{n} \nabla_{\theta}L(x_i, y_i, \theta)$. Consequently, it would be a waste of time to compute the gradient based on the whole training dataset at each iteration of gradient descent. Instead, we could compute the gradient based on the first half of the training dataset, update the parameters according to the gradient descent method Algorithm 5.1, and then compute the gradient for the second half of training.

$$\theta^{(t+1)} = \theta^{(t)} - \frac{\gamma}{n} \sum_{i=1}^{n/2} \nabla_{\theta}L(x_i, y_i, \theta)$$

$$\theta^{(t+1)} = \theta^{(t)} - \frac{\gamma}{n} \sum_{i=n/2}^{n} \nabla_{\theta}L(x_i, y_i, \theta)$$
