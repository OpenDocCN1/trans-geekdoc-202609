Instead, there are two properties that distinguish boosting from other models.

+   1. The basic functions are learned from data and, specifically, each function (that is ensemble member) corresponds to a machine learning model itself—the base of the boosting procedure.
2. The basic functions and their coefficients are learned sequentially. That is, we add one component to the sum in (7.14) at each iteration and after $B$ iterations the learning algorithm terminates.

The goal when training an additive model is to select $(\alpha^{(b)}, f^{(b)}(X))_{b=1}^B$ such that the final $f^{(B)}(X)$ minimizes

```
$J(f) = \sum_{i=1}^n L(y_i, f(x_i)) \quad (7.15)$
```

for some arbitrary loss function $L$, see Section 5.2. In a binary classification setting, choosing the logistic (or some other robust loss function) instead of the exponential loss results in a much less sensitive to outliers. Here define $f(X) = [f(x_1), \dots, f(x_n)]^T$ as the vector of values obtained by evaluating $f$ at the training data points. Since we do not have an explicit parametric form for $f(x)$, we consider $f$ to be a function of the model $(f)/x$.
A consequence of the first point in the list above—that the basic functions are generic machine models—is that the objective (7.15) will lock a fixed minimum, and we then need to respect some numericalthe objective (7.15) will lock a fixed minimum, and we then need to approximate some numerical solution. The sequential learning (second point) can be viewed as one way of handling this by using a "greedy" step-wise training. Connecting this to the AdaBoost algorithm, using the exponential loss is convex since it results in tractable expressions for each step of iteration training procedure. However, this is not strictly necessary. Indeed, by using arguments in numerical optimization, we can improve the model at each iteration as long as we move in the right direction. That, at iteration $b$ we introduce a new ensemble member with the objective of reducing the value of the cost function (7.15), without requiring that it is (greedily) minimized. This leads us to the idea of gradient boosting.
Consider the $b$th iteration of the training procedure. As before we use the sequential nature of the method to write

```
$f^{(b)}(X) = f^{(b-1)}(X) + \alpha^{(b)}f^{(b)}(X), \quad (7.16)$
```

and the goal is to select $(\alpha^{(b)}, f^{(b)}(X))$ to reduce the value of the cost function (7.15). That is, we want to choose the $b$th ensemble member by

```
$J(f^{(b-1)}(X) + \alpha^{(b)}f^{(b)}(X)) \le J(f^{(b-1)}(X)). \quad (7.17)$
```

Akin to the gradient descent algorithm (see Section 5.4), we do this by taking a step in the negative direction of the cost function.
In the context of boosting we do not assume a specific form for the base function, but rather construct each ensemble member using a learnable model, such as a tree. What then, should we compute the gradient of the cost function with respect to? The idea behind gradient boosting, which allows us to address this, is to use a nonparametric approach and represent the model $(f)/x$ by the values it assigns to the $n$ training data points. That is, we compute the gradient of the cost function directly with respect to the (vector of) function values $f(X)$. This is an $n$-dimensional gradient vector

```
$\frac{\partial J}{\partial f(X)} = \begin{pmatrix} \frac{\partial L(y_1, f(x_1))}{\partial f(x_1)} \ \vdots \ \frac{\partial L(y_n, f(x_n))}{\partial f(x_n)} \end{pmatrix} = n \begin{pmatrix} \frac{\partial L(y_1, f(x_1))}{\partial f(x_1)} \ \vdots \ \frac{\partial L(y_n, f(x_n))}{\partial f(x_n)} \end{pmatrix}, \quad (7.18)$
```
