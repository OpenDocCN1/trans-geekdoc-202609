Writing down an explicit form of $E_{out}$ as a function of the hyperparameter $\lambda$ can be quite tedious, not to mention its derivative. In fact, $E_{out}$ includes an optimization problem itself—$	heta$ for a given value of $\lambda$. However, we can nevertheless evaluate the objective function for any $\lambda$, by running the entire learning procedure and computing the predictions on the validation set.

The simplest way to solve such an optimization problem is to "try a different parameter values, and pick the one that works best". This is the idea of grid search and its likes. The term "grid" refers to some (more or less arbitrary) set of parameters to try out, and we illustrated it in Example 5.9.

Although simple, grid search can be computationally expensive, in particular if the parameter vector has a high dimension. As an example, having a grid with a resolution of 10 points per dimension (which is a very coarse-grained grid) for a 5-dimensional parameter vector requires $10^5 = 100,000$ evaluations of the objective function. But one should avoid using grid search for this reason, for example, with low-dimensional hyperparameters (in $L^1$ and $L^2$ regularization, $\lambda$ is 1-dimensional, where we use it for determining a regularization parameter $\lambda$.

```
**Algorithm 5.4** Grid search for regularization parameter $\lambda$
**Input:** $(x_i, y_i)_{i=1}^{n_v}$ validation data $(x_j, y_j)_{j=1}^{n_v}$
**Result:** $\hat{\lambda}$
1. for $\lambda = 10^{-3}, 10^{-7}, \dots, 10^{-10}$ (as an example) do
2. Learn $	heta$ with regularization parameter $\lambda$ from training data
3. Compute error on validation data $E_{val}(\lambda) \leftarrow \frac{1}{n_v} \sum_{j=1}^{n_v} (\hat{y}(x_j; 	heta) - y_j)^2$
4. end
5 return $\hat{\lambda}$ as $\arg\min_{\lambda} E_{val}(\lambda)$
```
