The models (10.19) and (10.20) are equivalent, we have not yet accomplished anything with this reformation. The latter forms us a non-linear generalization. Specifically, we can model the distribution of $x$ as the transformation of a Gaussian random variable,

```
$p_{\theta}(z) = N(z|0, I)$,
$x = f_{\theta}(z)$,
```

for some parametric function $f_{\theta}$. Note that we saw from a Gaussian, the implied distribution of $x$ is going to be non-Gaussian due to the nonlinear transformation. Indeed, we can model arbitrarily complex distributions in this way considering complex and flexible nonlinear transformations.

The challenge with this approach is how to learn parameters from data. Following the maximum likelihood approach we would like to solve

```
$$\hat{\theta} = \arg max p(\{x_i\}|\theta) = \arg max \sum_{i=1}^n \ln p(x_i|\theta)$$
```

Hence, we still need to *evaluate* the likelihood of $x$ to learn the parameters, but this likelihood is not explicitly given in the model specification (10.21).

To make progress, we will start by making the assumption that $f_{\theta}: \mathbb{R}^p \to \mathbb{R}^p$ is an invertible function, with inverse $h_{\theta}(x) = f_{\theta}^{-1}(x) = z$. Note that this $z$ is of the same dimension as $x$. Under this assumption, we can use the change of variables formula for probability density functions to write,

```
$p(x|\theta) = |\nabla h_{\theta}(x)| p_z(h_{\theta}(x))$,
```

where

```
$\nabla h_{\theta}(x) = \begin{pmatrix} \frac{\partial h_{\theta}(x)}{\partial x_1} & \dots & \frac{\partial h_{\theta}(x)}{\partial x_p} \\ \vdots & \ddots & \vdots \\ \frac{\partial h_{\theta}(x)}{\partial x_1} & \dots & \frac{\partial h_{\theta}(x)}{\partial x_p} \end{pmatrix}$,
```

is the $p \times p$ matrix of all partial derivatives of $h_{\theta}(x)$, referred to as the Jacobian matrix, and $|\nabla h_{\theta}(x)|$ is the absolute value of its determinant.
Plugging this expression into the maximum likelihood problem (10.22) we can then learn the model as:

```
$$\hat{\theta} = \arg max \sum_{i=1}^n \ln |\nabla h_{\theta}(x_i)| + \ln p_z(h_{\theta}(x_i))$,
```

where both terms of the loss are given by the model specification (10.21). This provides us with a practical approach for learning the transformation-based generative model from data, although we make the following observations:

- 1. The inverse mapping $h_{\theta}(x) = f_{\theta}^{-1}(x)$ needs to be explicitly available, as it is part of the loss function.
- 2. The Jacobian determinant $|\nabla h_{\theta}(x)|$ needs to be tractable. In the general case, the computational cost associated with (practical algorithms) for computing the determinant of a $p \times p$ matrix scales cubically with $p$. For high-dimensional problems, this results in a prohibitively large computational bottleneck, unless the Jacobian has some special structure that can be exploited for faster computation.

## 10.3 Generative models

3. The forward mapping $f_{\theta}$ does not enter the loss function, so in principle we can learn the model without explicitly defining this function (it is enough to know that it exists). However, if we want to use the model to generate samples from $p(x)$, then explicit evaluation of the forward mapping is also needed. Indeed, the way to sample from the model (10.21) is to first sample a standard gaussian $z$ and then propagating it through the mapping to obtain a sample $x=f_{\theta}(z)$.

Designing parametric functions that satisfy these conditions, while still being flexible enough to accurately describe high-dimensional probability distributions is non-trivial. Models based on neural networks are often used, but to satisfy requirements for invertibility and computational tractability, special-purpose network architectures are needed. This involves, for instance, restricting the mapping $f_{\theta}$ so that the Jacobian of its inverse becomes a triangular matrix, in which case the determinant is easily computable.

An observation when designing this type of transform-based models using neural networks, is that to ensure invertibility and tractability of each layer of the network independence, Assume that $f(x)$ is invertible with $L$ layers, where the $l$ layer corresponds to a function $f^{(l)}: \mathbb{R}^p \rightarrow \mathbb{R}^p$. We can then write $f(x) = f^{(L)} \circ f^{(L-1)} \circ \dots \circ f^{(1)}(x)$, where $\circ$ denotes the composition of functions. This is just a mathematical shortcut for saying that the evaluation of an $L$-layer network is obtained by first finding the layer inverse, then propagating the result through the second layer, and so on, until we obtain the final output $L$. The inverse of $f$ is then obtained by applying the layer-wise inverse functions in reverse order, $h_{\theta}(x) = h_{\theta}^{(1)} \circ h_{\theta}^{(2)} \circ \dots \circ h_{\theta}^{(L)}(x)$, where $h_{\theta}^{(l)}$ is the inverse of $f^{(l)}$. Furthermore, by the chain rule of differentiation and the multiplication of determinants, we can express the Jacobian as:

```
|\nabla f_{\theta}(x)| = \prod_{i=1}^{L} |\nabla h_{\theta}^{(i)}(x)|, \quad x^{(i)} = h_{\theta}^{(i+1)} \circ h_{\theta}^{(i+2)} \circ \dots \circ h_{\theta}^{(L)}(x).
```

This means that it is enough to design each $f^{(l)}$ so that it is invertible and has a computationally tractable Jacobian. There are many ways in which this can be achieved. We can build more complex models by stacking multiple layers after each other, with a computational cost growing linearly with the number of layers. Models exploiting this property are referred to as normalizing flows. The idea is that a data point $x$ "flows" through a sequence of transformations, $f^{(1)}, f^{(2)}, \dots, f^{(L)}$.

Many architectures for normalizing flows have been proposed in the literature, such as generative networks.

## Generative networks

The idea behind generative networks is to use a critic to evaluate the quality of the synthetic sample. In a practical learning algorithm, a human-in-the-loop to judge the synthetic sample x' is of course not feasible. Instead, the idea behind generative networks is to learn an auxiliary classifier to generate the generative model, which takes the role of the critic in the game. Specifically, we use a binary classifier $g_{\phi}(x)$ which takes a data point (for an example of image as input) and outputs the probability that it is synthetically generated, that is

```
g_{\phi}(x) = p(y = 1|x).
```

Here, $\phi$ denotes the parameters of the auxiliary classifier, which differ from the parameters $\theta$ of the generative model. The classifier is learned as usual to minimize its classification loss,

```
\phi = \arg min_\phi [L(y, g_{\phi}(x'))].
```

where the expected value is with respect to the random variables y and x' generated by the process described above. Note that this becomes supervised binary classification problem, where the labels are automatically generated as part of the "game".
