3. The forward mapping f_θ does not enter the loss function, so in principle we can learn the model without explicitly defining this function (it is enough to know that exists). However, if we want to use the model to generate samples from p(x), then explicit evaluation of the forward mapping is also needed. Indeed, the way to sample from the model (10.21) is to first sample a standard gaussian $z$ and then propagating it through the mapping to obtain a sample $x=f_{	heta}(z)$.

Designing parametric functions that satisfy these conditions, while still being flexible enough to accurately describe high-dimensional probability distributions is non-trivial. Models based on neural networks are often used, but to satisfy requirements for invertibility and computational tractability, special-purpose network architectures are needed. This involves, for instance, restricting the mapping $f_{	heta}$ so that the Jacobian of its inverse becomes a triangular matrix, in which case the determinant is easily computable.

An observation when designing this type of transform-based models using neural networks, is that to ensure invertibility and tractability of each layer of the network independence, Assume that f(x) is invertible with L layers, where the lth layer corresponds to a function $f^{(l)}: \mathbb{R}^p \rightarrow \mathbb{R}^p$. We can then write $f(x) = f^{(L)} \circ f^{(L-1)} \circ \dots \circ f^{(1)}(x)$, where $\circ$ denotes the composition of functions. This is just a mathematical shortcut for saying that the evaluation of an L-layer network is obtained by first finding the layer inverse, then propagating the result through the second layer, and so on, until we obtain the final output L. The inverse of f is then obtained by applying the layer-wise inverse functions in reverse order, $h_{	heta}(x) = h_{	heta}^{(1)} \circ h_{	heta}^{(2)} \circ \dots \circ h_{	heta}^{(L)}(x)$, where $h_{	heta}^{(l)}$ is the inverse of $f^{(l)}$. Furthermore, by the chain rule of differentiation and the multiplication of determinants, we can express the Jacobian as:

```
|\nabla f_{\theta}(x)| = \prod_{i=1}^{L} |\nabla h_{\theta}^{(i)}(x)|, \quad x^{(i)} = h_{\theta}^{(i+1)} \circ h_{\theta}^{(i+2)} \circ \dots \circ h_{\theta}^{(L)}(x).
```

This means that it is enough to design each $f^{(l)}$ so that it is invertible and has a computationally tractable Jacobian. There are many ways in which this can be achieved. We can build more complex models by stacking multiple layers after each other, with a computational cost growing linearly with the number of layers. Models exploiting this property are referred to as normalizing flows. The idea is that a data point $x$ "flows" through a sequence of transformations, $f^{(1)}, f^{(2)}, \dots, f^{(L)}$, and after such transformations result of the sequence of mappings is such that the data point has been transformed into a standard gaussian $z$.

Many practical architectures for normalizing flows have been proposed in the literature, with different properties. We should not pursue these specific architectures further, but instead turn to an alternative way of learning deep generative models that circumvents the architectural restrictions of normalizing flows resulting in so-called generative adversarial networks.
