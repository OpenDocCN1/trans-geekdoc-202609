## 6.3 Convolutional neural networks

Convolutional neural networks (CNN) are a special kind of neural networks originally tailored for tasks where the input data is a grid-like structure. In this text we focus on images, where its pixels reside on a 2D grid. Images are also the most common type of input data where CNNs are applied. However, CNNs can be used for any input data, also in 1D (e.g. audio wavelet data) and 3D (volumetric data e.g. CT scans or video data). We will focus on grayscale images, but the approach can be easily extended to color images as needed.

### Data representation of an image

Digital images consist of pixels ordered in a matrix. Each pixel can be represented as a range from 0 (total absence, black) to 1 (total presence, white) and values between 0 and 1 represent different shades of gray. In Figure 6.9 this is illustrated for an image with 6 × 6 pixels. In an image classification problem, an image is the input $x$ and the pixels in the image are the input variables $x_{1,1}, x_{1,2}, \dots, x_{6,6}$. The two indices $j$ and $k$ determine the position of the pixel in the image, as illustrated in Figure 6.9.

If we put all inputs representing the pixels in a layer as we did in Example 6.1 and Example 6.2, by doing that, a lot of the structure in the hidden layer will be lost. For example, when we know that two pixels close to each other typically have more in common than two pixels apart. This information would be destroyed by such a vectorization. In contrast, CNNs preserve this information by representing the input variables as well as the hidden layers as matrices. The core component in a CNN is the convolutional layer, which will be explained next.

### The convolutional layer

Following the input layer, we use a hidden layer with as many units as there are input variables. For the image with 6 × 6 pixels we consequently have 6 × 6 = 36 hidden units. We choose to order the hidden units in a 6 × 6 matrix, the same manner as we did for the input variables, see Figure 6.10a.

The neural layers presented in earlier sections (like the one in Figure 6.3) have dense layers. This means that each input variable is connected to all units in the subsequent layer, and each connection has an associate weight $W_{ij}$ associated to it. These layers have been empirically found to provide too much flexibility for images and we might not be able to capture the patterns of real importance, and hence not generalize and perform well on unseen data. Instead, a convolutional layer exploits the structure in images to find a more efficiently parametrized model. In contrast to a dense layer, a convolutional layer leverages two important aspects - sparse connections and parameter sharing - to achieve such a parametrization.

### Sparse interactions

With sparse interactions we mean that most of the parameters in a dense layer are forced to be equal to zero. More specifically, a hidden unit in a convolutional layer only depends on pixels in a small region of the image and not on all. In Figure 6.10 this size is of 3x3. The position of the region is related to the position of the hidden unit in its representation. If we move one unit to the right, the corresponding region also moves, as displayed by comparing Figure 6.10a and 6.10b. For the hidden units on border, the corresponding region is partially located outside the image. For these cases, we typically use zero-padding where the missing pixels are replaced with zeros. Zero-padding is illustrated in Figure 6.11.

### Parameter sharing

In a dense layer each link between an input variable and a hidden unit has its own parameter. In parameter sharing we let the same parameter be present in multiple places in the network. In a convolutional layer the set of parameters for the different hidden units are all the same. For example, in Figure 6.10a we use the same set of parameters to map the input to the hidden units. This allows the network to be invariant to translations.

### Convolutional layer with strides

In the convolutional layer presented above we have equally many hidden units as we have pixels. When we add more layers we want to reduce the number of hidden units. One way of doing this is by applying the filter every two pixels. If we filter every two pixels row-wise and column-wise, the hidden units will have half as many rows and and columns. For a $6\times6$ image we get $3\times3$ hidden units. This is illustrated in Figure 6.12.

The stride controls how many pixels the filter shifts. In Figure 6.12 the stride is $s=2$ because it moves two pixels row and column-wise. Note that the convolutional layer in 6.12 still requires 10 parameters, just as the original layer. Mathematically, the convolutional layer can be expressed as:

$$q_{i,j} = \sum_{k=1}^{F} \sum_{l=1}^{F} x_{(i-1)s+k,(j-1)s+l}W_{k,l}$$

Specifically this is equal to (6.29) if we used $s=1$ in the equation above.

### Pooling layer

Another way of summarizing the information in previous layers is achieved by **pooling**. A pooling layer acts as an additional layer after the convolutional layer. Similar to the convolutional layer, it depends on a region of pixels. However, contrast to convolutional layers, the pooling layer does not have any extra trainable parameters. In pooling layers we also use strides to condense the information, meaning that region is shifted by $s>1$ pixels. Two common versions of pooling are average pooling and max pooling. In average pooling, average of the units in the region is computed. Mathematically, this means:

$$\hat{q} = \frac{1}{F^2} \sum_{k=1}^{F} \sum_{l=1}^{F} q_{(i-1)s+k,(j-1)s+l}$$
