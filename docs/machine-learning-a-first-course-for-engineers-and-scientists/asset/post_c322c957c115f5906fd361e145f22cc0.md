
## 5.1 Principles of parametric modeling

formulated as an optimization problem, such as

```
$$\hat{\theta} = \arg\min_{\theta} \sum_{i=1}^n L(y_i, f_{\theta}(x_i)). \quad (5.4)$$
```

cost function $J(\theta)$

That is, we seek to minimize a cost function defined as an average of (some-chosen) loss $L$ evaluated on the training data. In some special cases (such as linear regression with squared loss) we can compute the solution to this optimization problem exactly. However, in most cases, and in particular when working with nonlinear models, this is not possible and we need to resort to numerical optimization. We will discuss algorithms in detail in Section 5.4, but it is useful to note already that these optimizations are often iterative. That is, the algorithm runs many iterations and each iteration the current approximate solution to the optimization problem (5.4) is updated into new (hopefully) better solution. This could lead to a computational trade-off. The longer we run the better solution we expect to find, but at the cost of a longer training time.

Finding the value of $\theta$ such that the model fits the training data as well is a natural idea. However, as we discussed in the previous chapter the ultimate goal of machine learning is not to fit the training data as well, but rather to find a model that can generalize to new data, not used for the training model. Put differently, the problem that we are actually interested in solving is not (5.4) but rather

```
$$\hat{\theta} = \arg\min_{\theta} E_{new}(\theta) \quad (5.5)$$
```

where $E_{new}(\theta) = \mathbb{E}_{*}[E(y_*, f_{\theta}(x_*))]$ is the expected error data (or error function $E$ of interest); see Chapter 4. The issue is that the expected error data is unknown to us. The "true" data distribution is not available and we cannot compute the expected error with respect to new data, nor can we optimize the objective (5.5) explicitly. However, this insight is of practical importance, because means that

> the training objective is a proxy for the actual objective of interest, (5.5).

This view of the training objective has implications for how we approach the optimization problem (5.4) in practice. We make the following observations.

- **Optimization accuracy vs. statistical accuracy:** The cost function $J(\theta)$ is computed based on the training data and is subject to the noise in the data. It is viewed as a random approximation of the "true" expected (obtained as $n \to \infty$). It is not meant to optimize $J(\theta)$ with greater accuracy than the statistical error in the estimate. This is particularly relevant in situations when we need to spend a lot of computational effort to obtain a very accurate solution to the optimization problem. This is unnecessary as long as the result is within the statistical accuracy of the estimate. In practice it is difficult to determine whether the statistical accuracy is enough (and we will not elaborate on methods that can be used for estimating in this), but this trade-off between optimization accuracy and statistical accuracy is still useful to have in the back of the mind.

- **Loss function vs error function:** As discussed in Chapter 4 we can use an error function $E$ for evaluating the performance of a model which is different from the loss function $L$ during training. In words, when the training we minimize an objective which is different from the one that we are actually interested in. This might seem counter-intuitive, but based on the proxy view of the training objective it makes perfect sense and, in fact, provides the machine learner with additional flexibility in designing a useful training objective. There are many reasons why we might want to use a loss function that is different from the error function. It can result in a model which is expected to generalize. The typical is when evaluating a classifier model based on accuracy (equivalently, misclassification error). If we were to train the model by minimizing the misclassification loss we would only care about placing decision boundaries to get many data points on the right side, but without taking the distances to the decision boundaries into account. However, with the noise in the data having some margin to the decision boundary can result in better generalization, and there are losses that explicitly encourage this. We can also choose the loss function with aim of making the optimization problem (5.4) easier to solve for instance by using convex loss function (see Section 5.4). Third, certain losses can encourage other favorable properties of the final model, such as making the model less computationally demanding to use “in production”.

- **Early stopping.** When optimizing the (5.4) using an iterative numerical method, this can be thought of as generating a sequence of candidate models. At each iteration of the optimization algorithm we have the current state of the parameter vector and thus obtain a “path” of parameter values. Interestingly, is not necessarily the end point of this path that is closest to the solution of (5.5). Indeed, the path of parameter values can pass a useful solution (with good generalization properties) before drifting off to a worse solution (due to overfitting). Based on this observation, there is another reason for stopping the optimization algorithm, apart from the purely computational reason mentioned above. Early stopping of the algorithm can obtain a final model with superior performance to the one we obtain if we run the algorithm until convergence. We refer to this as *implicit regularization* and discuss the details of how it can be implemented in Section 5.3.

- **Explicit regularization** Another strategy is to simplify the cost (5.4) by adding a term independent of the training data. We refer to this as explicit regularization. The aim is to make the final model generalize better, that is, we hope to solve the modified problem close to the solution of (5.5). We saw an example of this in Section 3.3 where we introduced $L^2$ regularization. The underlying idea is the law of parsimony, that the simplest explanation of an observed phenomenon is usually the right. In the context of machine learning this means that if both “simple” and “complicated” model fit the data (more or less) well, then the “simple” will typically have superior generalization properties and should therefore be preferred. Explicit regularization qualifies the vague notion “simple” and “complicated” to simply mean small and large parameter values, respectively. In order to favor a simple model an extra term is added to the cost function that penalizes large parameter values. We will discuss regularization further in Section 5.3.

## 5.2 Losses and likelihood-based models

Which loss $L$ to use in the training objective (5.4) is a design choice and different loss functions will give rise to different solutions $\hat{\theta}$. There is no “right” or “wrong” loss function, for a given problem one particular choice can be superior to others in terms of small $E_{new}$ (note that there is a similar design choice below how to choose the error function which defines we measure the performance of the model). Certain combinations of models and loss functions have proved useful and have historically been branded as specific methods. For example the method “linear regression” often refers to the combination of a linear-in-the-parameter model and the squared error loss, whereas the “support vector classification” (see Chapter 8) refers to a linear-in-the-parameter model trained using the hinge loss.
