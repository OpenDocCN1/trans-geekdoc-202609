
## 4.2 Estimating $E_{new}$

If the amount of available data is more limited, this becomes a problem. We are in practice faced with the following dilemma: *the better we want to know $E_{new}$ (more hold-validation data gives less variance in $E_{hold-out}$), the worse we have to make it* (less training data increases $E_{new}$). That is not very satisfying, and we have to look for an alternative to the hold-out validation approach.

### **k-fold cross-validation:** $E_{k-fold} \approx E_{new}$ without setting aside validation data

To avoid setting validation data, but still obtain an estimate of $E_{new}$, one could suggest a two-step procedure of

- (i) splitting the data into training and one hold-validation set, train the model on the training data and compute $E_{hold-out}$ using hold-validation data (as in Figure 4.1), and then
- (ii) training the model again, using the entire dataset.

By such procedure, we get an estimate of $E_{new}$ at the same time as a model trained on the entire dataset. That is not bad, but not perfect. Why to achieve small variance in the estimate, we have to put lots of data in the hold-out validation data in step (i). Unfortunately the model trained in (i) will be quite different from the one obtained in step (ii), and the estimate of $E_{new}$ concerns from step (i), not the possibly different model from step (ii). This will not give us a good estimate of $E_{new}$. However, we can use this idea to obtain the useful k-fold cross-validation method.

We would like to use all available data to train a model, and at the same time get an estimate of $E_{new}$ for that model. By *k-fold cross-validation* we can approximately achieve this. The idea of k-fold cross-validation is to simply repeat the hold-out validation approach multiple times with different hold-out datasets each time, in the following:

- (i) split the dataset in $k$ batches of similar size (see Figure 4.2), and the remaining batches as training data
- (ii) take each batch $\ell$ as the hold-out validation data, and
- (iii) train the model on the training data, and compute $E_{hold-out}^{(\ell)}$ as the average error on the hold-out validation data, as (4.6)
- (iv) if $\ell < k$, then $\ell \leftarrow \ell + 1$ and return to (ii). This is the k-fold cross-validation error

```
$E_{k-fold} \triangleq \frac{1}{k} \sum_{\ell=1}^{k} E_{hold-out}^{(\ell)}$
```

- (v) train the model again, using this the entire dataset

This procedure is illustrated in Figure 4.2.
With $k$-fold cross-validation, we get a model which is trained on all data, as well as an approximation of $E_{new}$ for that model, namely $E_{hold-out}$ (Section 4.2) was an unbiased estimate of $E_{new}$ (to the cost of setting aside hold-out validation data), this is not the case for $E_{k-fold}$. With large $k$, it turns out to be a sufficiently good approximation. Let us to understand why k-fold cross-validation works.

First, we have to distinguish between the final model, the which is trained on all data except a $1/k$ fraction of the data in step (iii). The key in $k$-fold cross-validation is if $k$ is large enough, the intermediate models are similar to the final model (since they are trained on almost the same dataset), each intermediate $E_{hold-out}^{(\ell)}$ is an unbiased but high-variance estimate of $E_{new}$ for the corresponding *intermediate index*. Since all intermediate and final models are similar, $E_{k-fold}$ (4.7) is approximately the average of $k$ high-variance estimates of $E_{new}$, for the final model. When averaging, the variance decreases and $E_{k-fold}$ will become a better estimate of $E_{new}$ *hold-out*

A simple solution is to first shuffle the entire dataset, and thereafter split it into batches We usually talk about training (or learning) as a procedure that is executed once. However, in $k$-fold cross-validation it is repeated (or $k$ times). A special case is $k=n$ which is called leave-one-out cross-validation. For methods such as linear regression, the actual training (solving the normal equations) is usually done within milliseconds on modern computers, and doing it $n$ times might not be a problem. ### Using a test dataset

A very important use of $E_{k-fold}$ (or $E_{hold-out}$) is to choose between methods and different types of hyperparameters such that $E_{k-fold}$ (or validation data) becomes as small as possible. Typical hyperparameters to choose in this way are $k$-NN, tree depth or regularization parameters. However, since we cannot use the training error $E_{train}$ to estimate $E_{new}$, selecting methods and hyperparameters based on $E_{k-fold}$ (or validation data) will invalidate it. If hyperparameters are selected to minimize $E_{k-fold}$ there is a risk of overfitting to the data. If it is important to have a good estimate of $E_{new}$, it is to first set aside another dataset, which we refer to as a *test* set. This set should be used only once (after selecting methods and hyperparameters) to estimate $E_{new}$ for the final model.

## 4.3 The training error-generalization decomposition of $E_{new}$

Designing a method with small $E_{new}$ is a central goal in supervised machine learning, and cross-validation helps in estimating $E_{new}$. However we can gain insights and better understand the behavior of supervised machine learning methods by analyzing $E_{new}$ mathematically. To be able to reason we introduce another abstraction, namely the training-data averaged versions of $E_{new}$ and $E_{train}$. To make the notation explicit, we write $E_{new}(T)$ and $E_{train}(T)$ to emphasize that both are functions of some training dataset $T$. Let us not forget

```
$$\hat{E}_{new} \triangleq E_{new}(T)$$
$$\hat{E}_{train} \triangleq E_{train}(T).$$
```

Here, $\hat{E}$ denotes the expected value with respect to the training dataset $T = \{x_i, y_i\}_{i=1}^n$ (of a fixed size, assuming that this consists of independent draws from $p(x,y)$). Thus $E_{new}$ is the average if we train the model multiple times on different training datasets, all of size $n$, and similarly for $E_{train}$. The point of introducing these two is that it is easier to reason about the average between $E_{new}$ and $E_{train}$ than the errors $E_{new}$ and $E_{train}$ obtained when the model is trained on one specific training dataset $T$.
