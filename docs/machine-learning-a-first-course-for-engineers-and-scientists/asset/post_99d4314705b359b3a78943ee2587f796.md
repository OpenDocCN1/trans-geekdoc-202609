In semi-supervised learning we formulate and train a generative model for the inputs in Dataset A and Dataset B. The generative model of the inputs and the supervised model for Dataset A are trained jointly. The idea is that the generative model on the inputs, which is trained on the much larger dataset, improves the performance of the supervised task. Semi-supervised learning is further described in Chapter 10.

In semi-supervised learning we use Dataset B in a very similar way as we do transfer learning described previously. Since Dataset B does not contain any inputs, we automatically generate outputs for Dataset B and pretrain our model with these generated outputs. The automatically generated outputs can be for example a of the input variables or a transformation thereof. In transfer learning, the idea is that the pretrained model learns extract features from the input data, which can then be used to improve the performance of the supervised task we are interested in. Besides the amount and distribution of data, a machine learning engineer may also face other data issues. In this section we will discuss some of the most common ones; outliers, missing data and some features can be removed.

### Outliers

In applications, a common issue is *outliers*, meaning data points whose outputs do not follow the overall pattern. Two typical examples of outliers are sketched in Figure 11.7. Even though the situation in Figure 11.7 looks simple, it is quite hard to find outliers when the data has higher dimensions and is harder to visualize. The error analysis discussed in Section 11.2, which amounts to inspecting misclassified data points in the validation data, is a systematic way to discover outliers.

When facing with a problem, the first question is to ask whether the outliers are meant to be captured by the model or not. The encircled data points in Figure 11.7 describe an interesting phenomenon that we would like to predict, or are irrelevant noisy (possibly originating from a data collection process)? The answer to this question depends on the actual problem and ambition. Since outliers (no matter origin) do not follow the overall pattern, they are typically hard to predict.

If the outliers are not of any interest, the first thing we should do is to consult the data provider to identify the reason for the outliers or if something could be changed in the data collection to avoid these outliers, for example if outliers are unavoidable, there are basically two approaches one could take. The first approach is to simply delete (replace) the outliers in the data. Unfortunately this means we have to first find the outliers, which can be hard, but sometimes some thresholding and manual inspection (that is, look at all data points whose output is smaller/larger than value) can help. Once the outliers are removed from the data, one can proceed. The second approach is to make the learning robust against outliers, by using a robust function with such absolute error of squared error loss (see Chapter 5 for more details). Making a model more robust amounts, to some extent, making it less flexible. However, robustness amounts to be making the model less flexible in a particular way, by putting less emphasis on the data points where predictions are severely wrong.

If the outliers are of interest to predict, they are not really an issue, but rather a challenge. We have to use a model that is flexible enough to capture the behavior (small bias). This has to be done with care, since very models have a high risk of overfitting to noise. If it turns out the outliers in a classification problem are interesting and from an underrepresented class, we are rather facing an imbalanced problem, see Section 4.5.

### Missing data

A common practical issue is that data are sporadically missing. Throughout this book so far the data has always consisted of consistent input-output pairs $[x_i, y_i]_n$, and missing data refers to the situation where some (a few) values from either the input $x_i$ or the output $y_i$, for some $i$, are missing. If the output $y_i$ is missing, we can also refer to it as unlabeled data. It is a common practice to note missing data with a NaN (not a number), but less obvious codes also exists, such as cod. Reasons for missing data could be a malfunctioning sensor or similar issues at the data collection time, or when certain values for some reason have been discarded during the data processing.

As for outliers, a sensible first option is to figure out the missing data. By going back to the data provider this issue could potentially be fixed and the missing data recovered. If this is not possible, there is some common practice which we use as a guideline. If the output $y_i$ is missing, the data point is useless for supervising machine learning. In the following, we assume that the missing values are only in the input $x_i$.

The easiest way to handle missing data is to discard the data points (rows in $X$) where $Y$ is missing. That is, if some feature is missing in $x$, the entire input $x_i$ and its output $y$ is discarded from the data, and we are left with a smaller dataset. If the dataset that remains after this procedure still contains all data, this approach can work well. However, if it would lead to a too small dataset, it is of course problematic. More subtle, but also important, is the situation when the data is missing in a systematic fashion, for example that missing data is more common for a certain class. In such a situation, discarding data points with missing data would lead to a mismatch between reality and training data, which may degrade the performance of the learned model.

If missing data is common, but for certain features, another easy option is to not use those features (“column of $X$”) which are suffering from missing data. It depends on whether this is a fruitful approach or not. Instead of discarding data, if the/th feature $x_j$ is missing from data point $x_i$, a simple imputation strategy would be to take the mean or median of $x_j$, for all other data points (if it is a classification problem). Another approach is to explore if there are redundant features, with the reasoning that having two features that (essentially) contain the same information will lead to an increased variance compared to having only one feature with the same information. Based on this argument one may look at the pairwise correlation between features, and investigate removing features that have high correlation to other features.
