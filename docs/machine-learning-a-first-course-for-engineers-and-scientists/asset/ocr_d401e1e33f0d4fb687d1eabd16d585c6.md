Equation (4.5) does not hold, and the reason is that the samples used to approximate the integral are given by the training data points. However, these data points are used to train the model, and indeed, there is an explicit dependence on the complete training data set $\mathcal{T}$ in the first factor of the integrand. We can therefore not use these data points to approximate the integral. Put differently, the expected value in (4.5) should be conditioned on a fixed training data set $\mathcal{T}$.

In fact, as we will discuss much later, the typical behavior is $E_{train} < E_{new}$ (although this is not always the case). Hence, a model that performs worse on unseen data, than on training data. The performance on training data $E_{train}$ is not a reliable estimate of $E_{new}$.

# $E_{hold-out} \approx E_{new}$: We can estimate $E_{new}$ from hold-out validation data

We could not use the training data directly to approximate the integral in (4.2), that is, estimating $E_{new}$ by $E_{train}$ since this would effectively use the training data twice: first, to train the model $(\mathcal{T}$ in (4.4)) and second, to evaluate the error function (the sum in (4.4)). A remedy is to use some hold-out validation data $(x'_j, y'_j)_{j=1}^{n_v}$, which are not in $\mathcal{T}$ for training, and then use only for estimating the model performance from the hold-out validation

```
$E_{hold-out} \approx \frac{1}{n_v} \sum_{j=1}^{n_v} E(x'_j; \mathcal{T}), y'_j$.
```

In this way, all data will be used for training, but some data points will be saved and used only for computing $E_{hold-out}$. This procedure for estimating $E_{new}$ is illustrated by Figure 4.1.

**Beware!** When splitting your data, always do it randomly, for instance someone might—intentionally or unintentionally—have sorted the dataset. If you do not split randomly, your binary classification method might end up with one class in your training data and the other class in your hold-out validation ...

Assuming that all (training and validation) data points are drawn from $p(x, y)$, it follows that $E_{hold-out}$ is an unbiased estimate of $E_{new}$, each time with new data, the average of $E_{hold-out}$ will be $E_{new}$. This is at least, on a theoretical level, but it does not tell us how the size of hold-out validation data $n_v$ decreases; a small increase in variance of $E_{hold-out}$ that we can expect to be close to $E_{new}$. If we take the hold-out validation dataset bigger, $E_{hold-out}$ will be close to $E_{new}$. However, setting a large validation dataset means that the data left for training becomes smaller. The more data, the smaller $E_{new}$ (which we will discuss later in Section 4.3). But bad news is achieving such a small $E_{new}$ is our ultimate goal.

Sometimes there is a lot of available data. When we have a lot of data, we can afford to create a reasonably large hold-out validation dataset, without sacrificing the size of the training data too much. In such data-rich situations, the hold-out validation data approach is sufficient.
