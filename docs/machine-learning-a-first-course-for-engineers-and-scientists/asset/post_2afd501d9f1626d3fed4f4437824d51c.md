
## 10.3 Deep generative models

Moving to the third step of the procedure, we wish to update the mapping $f_{\theta}(z)$, defining the generative model, to make the generated samples as difficult as possible for the critic to reject as fake. In is some sense the most important step of the procedure, this is where we learn the generative model. This is done in a competition with the auxiliary classifier, where the objective for the generative model is to maximize the classification loss (10.27) over $\theta$.

```
$$\max_{\theta} \mathbb{E}[L(1, g_{\theta}(f(x)))] + \mathbb{E}[L(-1, g_{\theta}(x_i))]$$
```

This results in a so-called minimax problem, where two adversaries compete for the same objective, one tries to minimize it and the other tries to maximize it. Typically, the problem is approached by alternating updating $\theta$ and $\eta$ using stochastic gradient optimization. We provide pseudo-code for one such algorithm in Method 10.4.

### Learn a generative adversarial network

- **Data:** $T = \{x_i\}_{i=1}^n$ initial parameters $\theta$ and $\eta$, learning rate and batch size $n_b$.
- **Result:** Generative model $f_{\theta}(z)$
- repeat
  for $t = 0, \dots, T_{critic}$ do
    Sample mini-batch $\{x_i\}_{i=1}^{n_b}$ from training data
    Sample mini-batch $\{z_i\}_{i=1}^{n_b}$ independently from $\mathcal{N}(0, I)$
    Compute gradient $\hat{g}_{critic} = \sum_{i=1}^{n_b} \nabla_{\eta} L(1, g_{\eta}(f_{\theta}(z_i))) + L(-1, g_{\eta}(x_i))$
    Update critic: $\eta \leftarrow \eta - \gamma\hat{g}_{critic}$
  end
  Sample mini-batch $\{x_i\}_{i=1}^{n_b}$ independently from $\mathcal{N}(0, I)$
  Compute gradient $\hat{g}_{gen} = \sum_{i=1}^{n_b} \nabla_{\theta} L(1, g_{\eta}(f_{\theta}(z_i)))$
  Update generator: $\theta \leftarrow \theta + \gamma\hat{g}_{gen}$
until convergence

### Sample from a generative adversarial network

- **Data:** Generative model $f_{\theta}(z)$
- **Result:** Synthetic sample $x'$
- 1 Sample $z' \sim \mathcal{N}(0, I)$
- 2 Output $x' = f_{\theta}(z')$

## 10.4 Representation learning and dimensionality reduction

A deep generative model $x = f_{\theta}(z)$ defines a relationship between the observed data point $x$ and some latent representation $z$ of the same data point. The word latent (hidden), here refers to the fact that $z$ is not directly observed, but it nevertheless carries useful information about the data. Given the mapping $f$ (which, once it has been, knowing the latent variable $z$ is enough to reconstruct the data point $x$, by simply computing $x = f_{\theta}(z)$). The variable $z$ is also commonly referred to as a (latent) code, and the mapping as a decoder, which we use to reconstruct the data. Much of contemporary machine learning, and in particular deep learning, with intricate dependencies between the coordinates $x_i, i=1,...,p$. Put differently, in the "raw data space", each coordinate $x_i$ might not carry useful information, but when we put together meaningful patterns across $x$ we wish to learn. The typical example is (again) when $x$ corresponds to an image, and one-by-one pixel values are not very informative about the contents of the image, deep neural networks can learn to recognize features, and solve many non-trivial tasks. Similar examples are found in natural language processing where $x_i$ might correspond to a character in a text, but until we put all characters together $x$ that the semantic meaning of the text can be understood. With these examples, it can be argued that the success of deep learning is due to its capability of learning a useful representation of high-dimensional data. For supervised learning of neural networks, as discussed in Chapter 6, the representation learning is often implicit and takes place alongside classification. There is no clear-cut definition of what we mean by a latent representation in such cases. In contrast with deep generative models, as pointed out above, the latent representation is an explicit part of the model. However, the possibility of learning a representation directly from data is not unique to generative models. In this section we will introduce a method for unsupervised learning referred to as auto-encoder. The autoencoder is used for dimensionality reduction by mapping the data to a lower-dimensional latent code. We will then derive a statistical method from PCA and show how this can be viewed as a special case of auto-encoder which is restricted to linear.

### Auto-encoders

For many high-dimensional problems it is reasonable to assume that the effective dimensionality of data is smaller than the observed dimension. That is, most of the information in $p$-dimensional $x$ can be retained if we compress the data into $q$-dimensional representation $z$ with $q < p$. For instance, in the context of generative adversarial networks (see Section 10.3) argued that the latent variable $z$ can be of much lower dimension than $x$. In such a case the effective dimension of the generated samples for $f_{\theta}$ is $q$. Training a autoencoder amounts to learning the decoder mapping $x = f_{\theta}(z)$, which takes a latent representation $z$ and maps it to this higher-dimensional output $x$. We say that the data lies on a $q$-dimensional manifold in $p$-dimensional space. If $z \in \mathbb{R}^2$ and $x = f_{\theta}(z) \in \mathbb{R}^3$, then all points generated in this way will lie on such a curved surface. That is, the representation in this case would correspond to hidden units in the middle of the network.

Can we make a mapping that goes in the other direction? That is, an encoder mapping $z = h_{\theta}(x)$ which takes a data point $x$ (lower-dimensional) latent representation. For generative networks is far from trivial, $f_{\theta}$ in general is a very complicated non-invertible function and there is no simple way of reversing this mapping. For normalizing that we also discussed in Section 10.3, reversing the decoder mapping is in fact possible since these models we assumed that $f_{\theta}$ has an inverse $h_{\theta} = f_{\theta}^{-1}$. However, this requires restrictions on the model and in particular that dimensions of $x$ and $z$ are same. Hence, such mappings are not useful for dimensionality reduction.

In an auto-encoder we tackle this by relaxing the requirement that $h_{\theta}$ is an exact inverse of $f_{\theta}$. Instead, we learn the encoder and decoder mappings via the objective that $f_{\theta}(h_{\theta}(x)) = x$, enforcing the dimensionality reduction through the model architecture. Specifically, we assume that:

- Encoder $h_{\theta}: \mathcal{R}^p \to \mathcal{R}^q$ maps a data point to a latent representation,
- Decoder $f_{\theta}: \mathcal{R}^q \to \mathcal{R}^p$ maps a latent representation back to a point in data.

Important, the dimension of the latent representation is expected to be smaller than $p$. Often, the encoder and decoder parameters functions are constructed separately and they are allowed to depend on different parameters. However, for brevity we group both the encoder and decoder parameters into the identity parameter $\theta$.

If we take a data point $x$, we can compress its latent representation using the encoder as $z = h_{\theta}(x)$. If we feed this representation through the decoder, we obtain a reconstruction $\hat{x} = f_{\theta}(z)$ of the data point. In general, this will not be identical to $x$, because we have forced the encoder to compress the data into a lower-dimensional representation in the first step. This will typically result in a loss of information that the decoder is unable to compensate for. However, we can traverse the model to approximate the identity mapping as closely as possible by minimizing the reconstruction error over the training data. For instance, using the squared error we learn the training objective,

```
$$\min_{\theta} \sum_{i=1}^n \|x_i - f_{\theta}(h_{\theta}(x_i))\|^2$$
```

It is important that $q < p$ for this method to be interesting, otherwise we would just end up learning an identity mapping. However, when $q$ is smaller than $p$, then it will encourage the encoder to compress the data into a lower dimensional vector, while retaining much of the actual information as possible to enable accurate reconstruction. In other words, the encoder is forced to learn a useful representation of data.

When using networks to parameterize the encoder and decoder mappings, the autoencoder can also be viewed as a neural network, with a “bottleneck layer” in the middle to represent the latent code. We illustrate this in Figure 10.10.

One issue when using encoders is the risk of memorizing the training data. To illustrate this, assume that $q=1$ so that we have a scalar latent code $z$. For any realistic problem, this might be insufficient to represent the actual content in complex data like $x$. However, the auto-encoder could learn to map any data point $x_i$ to the value $z_i=i$, and then learn to reconstruct the data point exactly based on this unique identifier. This will never happen exactly in practice, but we can still suffer to some extent from this memorization effect. The model might learn more from the training data in the parameter vector $\theta$, which helps us to minimize the reconstruction error, instead of learning a useful and generalizable representation. This is a potential issue when the model is very flexible. 

Various extensions to the basic auto-encoder have been proposed in the literature, among other things, combat memorization. Regularization is one approach. For instance, it is possible to learn a probabilistic prior on the distribution of the latent representation, effectively bridging the gap between auto-encoders and generative models.
