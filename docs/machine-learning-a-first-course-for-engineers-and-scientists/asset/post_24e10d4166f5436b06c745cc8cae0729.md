Fig.-7.4 What we see in Figure 7.4 is that the squared error eventually reaches a plateau as $B \to \infty$. Had there been an overfitting issue with $B \to \infty$, the squared error would have started to increase again for large value of B.

Despite that the number of parameters in the model increases as $B$, the level of overfitting as $B \to \infty$ according to Example 7.3 is the expected (and intended) behavior. It is important to understand that by the construction of bagging, *ensemble members do not make the resulting model more flexible*, but only reduce the variance. This is worth noting that the addition of an ensemble member is *not* done in order to obtain a better fit to the training data. On the contrary, each ensemble member overfits to its own perturbed version of the training data, averaging across the ensemble results in a smoothing effect which typically results in a larger training error (compared to the individual ensemble members' trainings), but also better generalization. We can also understand this by considering the limiting behavior as $B \to \infty$. By the law of large numbers, the bagging model becomes

```
$\hat{y}_{bag}(x_{*}) = \frac{1}{B} \sum_{b=1}^{B} \hat{y}^{(b)}(x_{*}) \xrightarrow{B \to \infty} \mathbb{E}[\hat{y}(x_{*}) |\mathcal{T}]$
```

where the expectation is with respect to the randomness of the bootstrapping algorithm. As B increases we expect the bagging model to converge to the hypothetical (limited flexibility) model on the right hand side. With this in mind, in practice the choice of B is mainly made by computational constraints. The better the better, increasing B when there is no further reduction in test error is computationally wasteful.

**Be aware!** Bagging can still suffer from overfitting since each ensemble member can overfit. The only claim we have made is that the overfitting is not caused by B (not getting worse) using too many ensemble members, and there is no problem with taking $B \to \infty$.

## Out-of-bag error estimation

When bagging (or random forests, which we discuss below), it turns out that there is a way to estimate the new data error $E_{new}$ without cross-validation. The first observation we have is is not all data points from the original dataset $\mathcal{T}$ have been used for training all ensemble members. It can be shown with the bootstrap, on average 63% of the original training points in $\mathcal{T} = \{x_i, y_i\}_{i=1}^n$ will be present in a bootstrapped dataset $\tilde{\mathcal{T}} = \{\tilde{x}_i, y_i\}_{i=1}^n$. Roughly speaking, this means for any $\{x_i, y_i\}$ in $\mathcal{T}$ about one third of the ensemble members will not have used for data point during training. We refer to these (roughly $B/3$) ensemble members as out-of-bag for data point $i$, and we let them form our out-of-bag ensemble. Note that the out-of-bag ensemble is different for each data point $\{x_i, y_i\}$.

The next key is that for the out-of-bag member $i$, the data point $(x_i, y_i)$ can act as a test point since it has not been seen by any of the ensemble members. By computing the (e.g., squared or misclassification) error when the out-of-bag member $i$ predicts $y_i$, we get an estimate of $E_{new}$ for this out-of-bag ensemble. Since $E_{OOB}$ is based on only data point $i$, it will be a poor estimate of $E_{new}$. If we repeat this for all data points $\{x_i, y_i\}$ in $\mathcal{T}$ and average $E_{OOB} = \frac{1}{n} \sum_{i=1}^n E_{OOB,i}$ we get a better estimate of $E_{new}$. Indeed, $E_{OOB}$ will be an estimate of $E_{new}$ with only $B/3$ (and not) members, as we have seen in (7.3), the performance of bagging plateaus after a certain number of ensemble members. However, if $B$ is large enough so that with $B/3$ members perform similarly, $E_{OOB}$ provides an estimate of $E_{new}$ which can be at least as good as the estimate $E_{k-fold}$ from $k$-fold cross-validation. Most importantly, $E_{OOB}$ requires much more computation than re-training $k$ times.

## 7.2 Random forests

In bagging we reduce the variance by averaging an ensemble of members. Unfortunately, the variance reduction is limited by the correlation between the individual ensemble members (compare the dependence on the correlation $\rho$ in (7.2b)). However, using a simple trick it is possible to reduce the correlation what is achieved by the bootstrap, using several methods referred to as random forests.

While bagging is a general technique that can be used to reduce the variance of any base model, random forests assume that base models are classification or regression trees. The idea is to introduce randomness when constructing each tree, in order to further reduce the correlation among the base models. At this first sight it might seem a silly idea: randomly perturbing the tree would intuitively degrade its performance. There is a rationale for this perturbation, which we will discuss below, before we present the details of the algorithm.

Let $n$ be the size of the bootstrapped dataset. To train a classification or regression tree on this data we proceed as usual (Section 2.3), but with one difference: Through the training, we will observe that at some point we not consider all possible variables $x_1, \dots, x_n$ as splitting variables. Instead, we pick a random subset of $q \leq n$ inputs and only consider these $q$ variables as splitting variables. At the next split we draw a new random subset of $q$ inputs to use for each of the ensemble members, so that (with high probability) we use different splitting variables, and so on. This random selection is independent of each member and end up using different trees. This will cause the trees to be less correlated and averaging their predictions can therefore result in larger variance reduction compared to the process which will increase the variance $E_{new}$ in the equation of (7.2b). Random forests decreases $\rho$ (good) but increases $r^2$ (bad) compared to bagging. Experience has shown that the reduction in correlation is the dominant effect, so that the averaged variance is often reduced. We illustrate this in Example 7.4 below.

To understand why this is based on recursive subset of inputs as splitting variables, recall that tree building is a greedy algorithm. This is that the algorithm can make early choices on input that appear to be good, but which nevertheless turns out ^3And also the bags, in similar in a manner as the bootstrap might increase the bias, see Footnote 2, page 30. suboptimal further down the splitting procedure. For instance, consider the case when there is one dominant input variable. If we construct an ensemble of trees using plain bagging, it is very likely that all of the ensemble members will pick this dominant variable as the first splitting variable, making all trees identical (that is, perfectly correlated) after the first split. If we instead apply random forests, some of the ensemble members will not even have access to this dominant variable at the first split, since it most likely will not be present in the random subset of $q$ inputs selected at the first split for some of the ensemble members. This will force those members to split according to other variable. While there is no reason for why this would improve the performance of the individual tree, it could prove to be useful further down the splitting process, and since we average over many ensemble members the overall performance can therefore be improved.
