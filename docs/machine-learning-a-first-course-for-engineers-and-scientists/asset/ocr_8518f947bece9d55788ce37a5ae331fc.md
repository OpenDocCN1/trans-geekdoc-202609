Two possible strategies for guiding us to meaningful actions to improve the system are by training error and generalization gap, or by applying error analysis.

# Training error vs generalization gap

With the notation from Chapter 4, the error E_{train} is the performance of the model on training data and the validation error E_{holdout} is the performance on hold-out validation. In the validation step, we are interested in the model complexity and that E_{holdout} is minimized. We can validate the validation error as a sum of the training error and the generalization gap

```
$E_{hold-out} = E_{train} + (E_{hold-out} - E_{train})$$\n≈ generalization gap
```

In words, the generalization gap is approximated by the difference between the validation error E_{hold-out} and the training error E_{train}^{1}.

We can easily compute the training error E_{train} and the generalization gap E_{holdout} - E_{train}, we just have to evaluate the error on the training data and validation data respectively. By computing these, we can get good guidance for what changes we make for the next iteration.

As discussed in Chapter 4, if the error is small and the generalization gap is big (E_{train} small, E_{holdout} big), we typically overfitted the model. The opposite situation, big error and small generalization gap (both E_{train} and E_{holdout} big), indicates underfitting.

+   * Use a less flexible model. If we have a very flexible model we might start overfitting to training data, that is, E_{train} is much smaller than E_{holdout}. If we use a less flexible model, we also reduce this gap.
* Use more regularization. Using more regularization will reduce the flexibility of the model, and hence reduce the generalization gap. Read more about regularization in Section 5.3
* Early stopping. For models that are trained iteratively we can stop the training before reaching the minimum. One good practice is to monitor E_{holdout} during training and if it starts increasing, see Example 5.7.
* Bagging, or use ensemble members if we are using it. Bagging is a method for reducing the variance of the model, which also means that we reduce the generalization gap, see in Section 7.1.
* Collect more training data. If we collect more training data, the model is less prone to overfit that extended training dataset and is forced to focus on aspects that generalizes to the validation data.

If we want to reduce the training error (4.11), by approximating E_{train} ≈ E_{train} and E_{new} ≈ E_{holdout}. If we use k-fold validation instead of a hold-out validation data, we use E_{fold} ≈ E_{holdout}, when computing the generalization gap.
