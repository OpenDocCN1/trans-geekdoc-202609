No matter which classification or regression method we consider, once it has been learned from training data $T=\{(x_i, y_i)_{i=1}^n\}$, it will return predictions $\hat{y}(x)$ for any new input $x$ we feed to it. In this chapter we will emphasize $\hat{y}(x)$ to emphasize that the model depends on the training data $T$. Indeed, if we would use a different training data to learn the same (type of) model, this would typically result in a different model with different predictions.

In the other chapters we will discuss how a model predicts the output for one, or few, tests $x_*$. Let us get to the next level: learning (averaging) the error function (4.1) over all test data points with respect to $p(x_*, y_*)$. We refer to this as the *expected data error*:

$E_{new} = \mathbb{E}_* [E(\hat{y}(x_*; T), y_*)], \quad (4.2)$

$E_* [E(\hat{y}(x_*; T), y_*)] = \int E(\hat{y}(x_*; T), y)p(x_*, y)dx_* dy. \quad (4.3)$

Remember that the model (regardless whether it is a linear regression, a classification tree, an ensemble of trees, or something else) is learned on a given training data $T$ and represented by $\hat{y}(;T)$. What is happening in equation (4.2) is an averaging over possible test data points $(x_*, y_*)$. Thus, $E_{new}$ describes how the model *generalizes* from the training data $T$ to new situations.

We also introduce the error:

$E_{train} = \frac{1}{n} \sum_{i=1}^n E(\hat{y}(x_i; T), y_i), \quad (4.4)$

where $\{x_i, y_i\}_{i=1}^n$ is the training data $T$. $E_{train}$ simply describes how the model performs on the specific data on which it was trained, but it carries no information on how the model will perform for unseen data points.

Whereas $E_{train}$ describes how well the model is to “reproduce” the data from which it learned, the expected data error $E_{new}$ tells us how well a model performs when we put it in “production”. For instance, what is the rate of false and missed pedestrians that we expect a self-driving car to make? Or, how large proportion of all future patients will a medical diagnosis system get?

> The overall goal in supervised learning is to achieve as small $E_{new}$ as possible.

This sheds some additional light on the claim we made previously, that the loss function $L(\hat{y}, y)$ and the error function $E(\hat{y}, y)$ do not have to be the same. As we will discuss in this chapter, a model which fits the training data well and has a small $E_{train}$ might still have a large $E_{new}$ when faced with unseen data. The best strategy to achieve a small $E_{new}$ is not necessarily minimize. Beside the fact that the classification (4.1) is unsuitable to use as optimizing objective (which is discontinuous and has derivative zero almost everywhere) it can also be, depending on the method, be that $E_{new}$ can be made smaller by a more clever choice of loss function. Examples of this are in the case of gradient boosting (Chapter 7) and other vector machines (Chapter 8).

*Term risk* is used in literature for the expected loss, which is the same as the data error $E_{new}$ if the loss function and the error function are to be the same. The training error $E_{train}$ is then referred to as “empirical risk”, and the minimizing of the cost function as “empirical risk minimization”.

## 4.2 Estimating $E_{new}$

Finally, it is worth noting that not all methods are trained by explicitly minimizing a loss function ($k$-NN is one such example), but the idea of evaluating the performance of the model using an error function still applies, no matter how it is trained.

Unfortunately, in practical cases we can never compute $E_{new}$ to assess how well we are doing. The reason is $p(x, y)$—which we do not know in practice—is part of the definition of $E_{new}$. However, $E_{new}$ is too important to abandon since we cannot compute it. Instead, we will spend some effort on estimating $E_{new}$ from data, as well as analyzing $E_{train}$ to better understand how we can decrease it. We emphasize that $E_{new}$ is a property of the trained model. That is, we cannot talk about “E_{new}$ for logistic regression” in general, but instead we have to make more specific statements, like “E_{new}$ for handwritten digit recognition”.

There are multiple reasons why an engineer is interested in $E_{new}$:

- judging if the performance is satisfying (whether $E_{train}$ is small enough), or if more training data should be collected
- choosing different methods
- choosing hyperparameters (as $k$ in k-NN, the regularization parameter in ridge regression, or the number of hidden layers in deep learning) to minimize $E_{new}$
- reporting the expected performance to the customer

As discussed above, we unfortunately cannot compute $E_{new}$ in any practical situation. We will then explore various ways of estimating $E_{new}$, which will lead to the very useful concept of cross-validation.

$E_{train} \neq E_{new}$: We cannot estimate $E_{new}$ from training data

We have both introduced the expected data error $E_{new}$, and the training error $E_{train}$. We assume for now that $T$ consists of data points drawn from $p(x, y)$. When an expected value, such as in the definition of $E_{new}$ in (4.2), cannot be computed in closed form, one option is to approximate the expected value by a finite sum. Effectively this means we can approximate the integral:

$E_{new} = \int E(x; T) p(x, y)dx \approx \frac{1}{n} \sum_{i=1}^{n} E(x_i; T)$

Put differently: Can we perform a method well when faced with new, unseen data, as we did on training data? The answer is **no**.

Equation (4.5) does not hold, the reason is that the samples used to approximate the integral are the training data points. However, these data points are used to train the model, and indeed, there is an explicit dependence on the complete training set $\mathcal{T}$ in the integrand. We can therefore not use these data points to approximate the integral. Put differently, the expected value in (4.5) should be conditioned on a fixed training set $\mathcal{T}$.

In fact, as we will discuss much later, the typical behavior is $E_{train} < E_{new}$ (although this is not always the case). Hence, a model performs worse on unseen data than on training data. The performance on training data $E_{train}$ is not a reliable estimate of $E_{new}$.

$E_{hold-out} \approx E_{new}$: We can estimate $E_{new}$ from hold-out validation data

We could not use the training data directly to approximate the integral (4.2), that is, estimating $E_{new}$ by $E_{train}$, since this would effectively use the training data twice: first, to train the model ($\mathcal{T}$) and second, to evaluate the error function (4.4). A remedy is to use some hold-out validation data $(x'_j, y'_j)_{j=1}^{n_v}$, which are not in $\mathcal{T}$ for training, and then use only for estimating the model performance from the hold-out validation:

$E_{hold-out} \approx \frac{1}{n_v} \sum_{j=1}^{n_v} E(x'_j; \mathcal{T}), y'_j$.

In this way, all data will be used for training, but some data points will be saved and used only for computing $E_{hold-out}$. This procedure for estimating $E_{new}$ is illustrated by Figure 4.1.

**Beware!** When splitting your data, always do it randomly, for instance someone might—intentionally or unintentionally—have sorted the dataset. If you do not split randomly, your binary classification method might end up with one class in your training data and the other class in your hold-out validation...

Assuming that all (training and validation) data points are drawn from $p(x, y)$, it follows that $E_{hold-out}$ is an unbiased estimate of $E_{new}$; each time with new data, the average of $E_{hold-out}$ will be $E_{new}$. This is at least on a theoretical level, but it does not tell us how the size of hold-out validation data $n_v$ decreases; a small increase in variance of $E_{hold-out}$ allows us to expect to be close to $E_{new}$. If we take the hold-out validation dataset bigger, $E_{hold-out}$ will be close to $E_{new}$. However, setting a large validation dataset means that the data left for training becomes smaller. The more data, the smaller $E_{new}$ (which we will discuss later in Section 4.3). But bad news is achieving such a small $E_{new}$ is our ultimate goal.

Sometimes there is a lot of available data. When we have a lot of data, we can afford to create a reasonably large hold-out validation dataset, without sacrificing the size of the training data too much. In such data-rich situations, the hold-out validation data approach is sufficient.
