As an example if we have $x_2 = [2.5, 3.5]$, in the first split we would take the right branch since $x_2 = 3.5 \ge 3.0$ and in the second split we would take the left branch since $x_1 = 2.5 < 5.0$. The prediction for this test point would be $\hat{Y}(x_*)$ = Blue.

To endonymize, the output of each branch $R_1, R_2$ and $R_3$ in Example 2 are called leaf nodes and the internal splits, $x_j < 3.0$ and $x_i < 5.0$ are known as internal nodes. The lines that connect the nodes are referred to as branches. The tree is referred to as binary since each internal node splits into exactly two branches.

With more than two inputs it is difficult to illustrate the partitioning of the input spaces into regions (Region 2.7), but the tree representation can be used in the same way. Each internal node contains a rule where one of the $p$ inputs $x_j, j=1,\dots,p$ is compared with a threshold $s$. If $x_j < s$ we continue along the left branch and if $x_j \ge s$ we continue along the right branch.

The constant predictions that associate with the leaf nodes can be either categorical (as in Example 2 above) or numerical. Decision trees can be used for classification and regression problems. Example 2.5 illustrates how a decision tree can be used to make a prediction. We will now move to address the question of how a tree can be learned from training data.

# Learning a regression tree

We will start by discussing how to learn (or, equivalently), a decision tree for a regression problem. The classification problem is conceptually similar and will be explained later.

As mentioned above, the prediction $\hat{Y}(x_*)$ from a regression tree is a piecewise function of the input $x_*$. We can write this mathematically as,

> $\hat{Y}(x_*) = \sum_{l=1}^{L} \hat{Y}_l \mathbb{I}(x_* \in R_l), \quad (2.3)$

where $L$ is the number of leaves in the regression tree, $R_l$ is the $l$-th leaf, and $\hat{Y}_l$ is the constant prediction for the $l$-th node. Note that the constant setting $\hat{Y}_l$ is a numerical value, and we will consider it to be a real for simplicity. In the equation above we have used the indicator function, $\mathbb{I}(x \in R_l) = 1$ if $x \in R_l$ and $0$ otherwise.

Learning from the data requires finding suitable values for the parameters defining the function (2.3), namely the regions $R_l$ and the constant predictions $\hat{Y}_l, l=1,\dots,L$, as well as the size of the tree. If we start by assuming the shape of the tree, the partition $(L, \{R_l\}_{l=1}^L)$ is known, then we can compute the predictions $\{\hat{Y}_l\}_{l=1}^L$ in a natural way, simply as the average of the training data points falling in each region:

> $\hat{Y}_l = \text{Average}(y_i : x_i \in R_l)$

To find the shape of the tree, the regions $R_l$, requires a bit more work. The basic idea is to select the regions so that the tree fits the training data. This means that the outputs from the tree should match the training data accurately. Unfortunately, even when restricting ourselves to simple regions like the “boxes” obtained by a decision tree, the tree fitting the training data turns out to be computationally expensive. The problem is that combinatorial explosion in the number of ways in which we can partition the input space. Searching through all possible trees is not possible unless the tree size is so small that it is practically useless.
