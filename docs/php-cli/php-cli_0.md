## 2. 摆脱 Web - PHP CLI 编程概览

本章将介绍涉及使用 `PHP` 摆脱 Web 局限的基本步骤。我们将涵盖涉及的技术步骤，以及编程实践和重点的差异。

### 2.1 没有 Web 服务器的 PHP

大多数 `PHP` 程序员严格仅在 Web 服务器环境中使用 `PHP`。在这样的环境中，`PHP` 是一个 `CGI/Fast GGI` 或服务器模块，由 `HTTP` 服务器（通常是 `Apache`、`IIS`、`Nginx` 或类似软件）调用和控制。`HTTP` 服务器接收到基于 `PHP` 的网页请求，并调用 `PHP` 进程执行它，该进程通常会将输出返回给 `HTTP` 服务器，以便发送给最终用户。

人们曾多次尝试使用本地安装的 Web 服务器通过 `PHP` 创建本地应用程序（脚本系统、桌面应用等），并取得了一些成功。然而，在本地应用中使用这种 Web 类型模型的缺点有许多：

*   就它们在这些场景中提供的价值而言，像 `Apache` 这样的 Web 服务器通常配置过高且消耗资源

*   除非经过妥善锁定，否则运行在本地的 Web 服务器会为外部恶意访问者提供访问你机器的接入点

*   `HTTP` 是一种冗长的协议，且（可以说）非常适合 Web，然而，对于本地进程间通信来说，它通常是大材小用，并为你的应用程序增加了额外的资源和复杂性开销

*   你的应用程序界面通常在 Web 浏览器中，因此看起来完全不像本地应用（除非你为应用专门安装浏览器，否则会有额外的支持/升级烦恼）

`PHP` 从 `5.4` 版本开始包含一个内置 Web 服务器，这解决了上述描述的一些问题。然而，它是为了本地测试旨在部署在生产环境的完整 `HTTP` 服务器（如 `Apache`）上的 `PHP` 脚本而设计的。对于某些本地应用来说，这是一个可以探索的路线，特别是当你想要运行一个已有的私有 `PHP` Web 应用实例时。然而，它的稳定性、可靠性和对于生产级本地应用的性尚待证明，而且仍然带有 `HTTP` 和 Web 浏览器的包袱。

从 4.3 版本开始，PHP 就拥有一项可以解决所有这些问题的“王牌杀手”。PHP CLI SAPI（正式名称为“命令行接口”或“服务器应用程序编程接口”）本质上是“独立运行 PHP”的一种冗长说法。它消除了对 Web 服务器的需求，并为你提供了一个独立的 PHP 二进制文件供你交互。例如，在 shell 提示符中输入以下内容：

```bash
1 ~$ php /home/myfiles/myprogram.php
```

这将直接执行你的 `myprogram.php` 文件（你编写它的方式与任何其他 PHP 脚本无异），并将任何输出返回到终端（除非你另有说明），而不是发送到 Web 服务器（而该服务器根本不存在！）。

通常情况下，直接使用 PHP CLI SAPI 调 PHP PHP 脚本的行为通过 Web 服务器调用时相同，尽管存在一些差异。例如，你将无法找到任何 `$_GET` 或 `$_POST` 数组，且 PHP 默认不会发送任何 HTTP 头部，因为这些概念在 Web 之外并没有意义。像 `max_execution_time` 等默认设置被设置为适用于本地使用的合理值（在这种情况下设置为 0，这样你的脚本就不会超时），输出缓冲被关闭，且错误信息以纯文本而非 HTML 显示。

关于如何安装（如有必要）和使用 CLI SAPI 的完整细节，请见下一章。

### 2.2 PHP 版本 - 你用的是哪一个？

PHP 从 4.3.0 版本开始就支持 CLI SAPI，因此书中的许多示例可以在此后的任何 PHP 版本上运行。在编写本书时，PHP 的当前版本是 7.02，书中的代码已针对该版本进行了测试。如果你发现某个特定函数似乎不存在或运行不符合预期，请检查该函数的在线 PHP 手册。手册会显示哪些版本支持哪些函数，并描述新版本所引入的任何破坏性更改。

如果你正在使用旧版本，有几个非常充分的理由进行升级：

*   在最近的版本中，性能显著提高（相应地，使用的资源也减少了）。

*   虽然对于非 Web 应用，安全性并不总是那么关键（请参见本章稍后关于安全讨论中的注意事项），但如果你正在处理来自外部源的数据，并且将相同的版本用于 Web 工作，那么最近版本中的安全增强和安全相关的漏洞修复是必不可少的。

*   可以使用现代语言特性，这可以提高你的编码效率，并帮助他人更认真地对待你的代码。

与 PHP 的 Web 版本一样，如果你觉得需要，也可以编译你自己的 CLI SAPI 版本。如果你想包含操作系统软件仓库未预装的扩展、出于性能考虑移除非核心代码，或使用 PHP 支持的任何其他编译时选项，那么学习“自制”一个版本可能是值得值得的。在附录 A 中可以找到编译和安装 PHP 及相关扩展的入门指南。

### 2.3 不要在 PHP 中执行它的几个好理由

如果你告诉某人你将用 PHP 编写 CLI 脚本，他们通常会抱怨 PHP 是一门 Web 语言，认为你应该选择一种“更适合”该任务的语言。本书侧重于用 PHP 完成所有工作，对于 90% 的任务，PHP 都能胜任所有要求。PHP 现在是一门通用语言，它是图灵完备的，虽然它仍被主要用于运行“网站”，但现在它越来越多地也意味着后端服务。但在你决定用 PHP 重写你的世界之前，有几个相关问题是你可能在跳入之前仔细考虑的。

#### 高性能需求

如果你需要非常高的性能，特别是在硬件有限的情况下，PHP 可能不适合你。PHP 在最近的版本中性能有了飞跃性的提升，在基准测试中经常击败 Python 等语言和 Ruby-on-Rails 等框架。然而，PHP 本质上是一种抽象的脚本语言，对于某些任务，它永远无法获得像 C 这样更接近底层的低级语言相同的性能。但不要因此否定它所有高性能任务，如果你从成本的角度考虑性能，你可能会发现，通过 PHP 的快速开发所节省的开发者时间成本，超过了为了获得性能而投入的额外硬件成本。

#### 不要（没必要）重造轮子

你*可以*用 PHP 编写一个 Web 服务器（参见附录 D 的示例），但*现有的*服务器如 Apache 难道不能满足你的需求吗？对于许多或大多数基础设施方面的“痒点”，已经存在软件（用许多不同的语言编写）可以提供你所需的“解决方案”。除非你真的需要其他功能，否则编写自己的软件所花费的时间通常比学习和实现现有软件花费的时间要长。当然，对某些人来说，反过来也是的。“因为我可以”可以是一个合理的理由，而且编写软件始终是一次宝贵的学习经历。

#### 保持源代码关闭

PHP 是一种脚本语言，这意味着如果你正在编写要出售或部署在其他地方软件，你将向接收者公开你的源代码。许多人（包括作者）会认为“开源”（即使是商业开源）是一好事。但如果那不是你的领域，那么你就需要付出更大的努力来保护你的代码。网上有很多源代码混淆器，它们使用各种技巧让你的代码难以（但并非不可能）阅读，而且还有许多 PHP 编译器可以生成二进制程序（尽管在语法和扩展覆盖方面存在局限性）。但 PHP 主项目尚未表达过支持代码隐藏或编译的意图，因此此类方法的长期可行性尚不明。闭源软件的商业案例在中长期也不是定论。

### 2.4 思考安全性

进入离线软件的世界，情况则显著不同。通常我们看到的软件仅针对受信任的用户，部署在本地受信任的机器上，并受仁慈用户的完全控制。用户不会故意攻击软件或机器，他们处理的是自己的数据。功能绝对不能被破坏。在开发命令行程序和桌面应用时，很少会考虑安全性，更不用将其作为设计时指定的功能了，因为这并不“必要”。

但世界并非如此运作的。看看任何软件漏洞邮件列表（如 `BugTraq`），你会发现像 `Adobe Reader`、`Microsoft Word` 甚至像 `GIMP` 这样的开源骨干等“离线”应用中存在大量的漏洞。事实是，即使在本地应用中，安全也非常重要，原因主要有二：第一是“典型用户”行为长期存在的问题。对于一个从不犯错的智能且精通技术的用户（比如亲爱的读者，你）来说，这不是一个问题；但对于我们其他人使用的任何软件，灾难往往只差一次误点可疑邮件。安全重要的另一个原因是，对于大多数机器来说，许多非 Web 应用程序并不是真正的“离线”。即使桌面应用或系统守护进程本身不与网络、本地网络或其他外部服务交互，它所连接的机器也必然插着以太网线，或者激活着 WiFi/3G/4G 连接。你的软件不会运行在自己不受外界干扰隔绝的舒适小世界里。当然，完美的沙箱化虚拟机除外。

软件安全是另一整本书的主题（其他人已经写过很多了，请参见下方的延伸阅读部分），许多原则既适用于系统软件也适用于 Web 软件，因此你可以利用现有的 Web `PHP` 安全实践知识来指导自己。在规划你的脚本安全措施和监控时，应该考虑以下列出的面向用户和系统软件的典型漏洞类型和攻击向量列表：

*   **受损的数据文件**

    来自外部源的受损文件（由用户刻意或无意加载）。这些通常是数据文件，特别是被注册为特定文件类型默认查看器的软件风险最高，因为无意或恶意的文件激活要容易得多。

*   **被恶意软件利用**



恶意软件寻找无辜的软件进行利用以获取权限提升。像`PHP`代码这样的脚本化软件更容易被恶意软件重写或修改，而且未编译形式源代码的可用性对恶意软件作者有所帮助。

### 用户行为不当

合法用户的行为不当。例如，John Smith 试图在他们的共享业务系统上查看其老板 Jane Doe 的文件或浏览历史。

### 权限提升

与合法用户行为不当类似，这是合法软件的行为不当，即无意或蓄意地尝试获取并使用它不具备的访问权限。

### 依赖漏洞

`PHP`漏洞以及其他依赖和相关软件中的漏洞。你的软件当然完全没有安全问题，但它不可避免地依赖其他库、软件和`PHP`扩展，当然，不要忘记`PHP`解释器本身。其中任何一个都可能包含安全漏洞和攻击向量。

上述章节列出了所有类型软件中常见的安全问题来源，而不是`PHP`。在设计阶段规划这些问题，并在部署前进行测试，以尽量减少你的风险。然后祈好运吧……

## 2.5 CLI 专用代码框架

`PHP`有许多编码框架，其中许多框架可以用于`CLI`应用，尽管只有一个框架是专门为非 Web 编程创建的。各种框架中的代码可能假设它们会在 HTTP 相关的环境中被调用，因此你可能需要编写额外的代码来规避这一点。

在决定是否使用框架或使用哪一个框架时，你应该考虑到它们的适用性（取决于它们对 Web 的关注）以及你的应用程序性能是否会因为它们可能带来的开销而降低。你通常还需要查看它们的许可证，因为它们通常包含需要与你的脚本一起分发的组件。

这并不是说它们在通用编程中没有用，然而，作者目前没有一个可以专门推荐用于非 Web 项目的框架。如果你目前在 Web 项目中使用特定框架感到很自在，那么可能值得看看它在 CLI 项目中的表现。

## 3. 理解并使用 CLI

正如我们在上一节中提到的，`PHP`脚本涉及使用`CLI`。因此，了解如何使用它、如何配置以及它与 Web `SAPIs`的区别是非常重要的。

### 3.1 CLI 有何不同？

以下是`CLI`与标准`SAPI`实现之间的主要差异：

- 默认不写入 HTTP 头部。这是因为在命令行中它们没有意义，如果你的输出稍将传输到浏览器，你需要手动使用`header()`函数添加必要的头部。

- `PHP`不会将工作目录更改为脚本所在的目录。要手动这样做，请使用`getcwd()`和`chdir()`获取和设置当前目录。否则，工作目录将是调用脚本的地方。例如，如果你在`/home/rob`中输入`php /home/peter/some_script.php`，`PHP`使用的工作目录将是`/home/rob`，而不是`/home/peter`。

- 任何错误或警告信息都以纯文本输出，而不是 HTML 格式文本。如果你想要 HTML 错误（例如你正在生成静态 HTML 文件），可以在脚本中使用`ini_set('html_errors', 1);`覆盖此设置。

- `PHP`隐式地立即刷新所有输出，默认不缓冲。在线直接输出往往会损害性能，因此输出会在缓冲区满时以最佳大小的块发送。离线时这可能不是问题，因此`print`和`echo`等构造的输出会立即发送到 shell。当你等待进一步输出时，不需要使用`flush()`来清除缓冲区。如果你愿意，可以使用 PHP 的输出缓冲函数来捕获和控制输出，请参见 PHP 手册中的“输出控制”部分。

- 没有设置执行时间限制。你的脚本将持续运行直到它自愿退出，即使它挂起了 PHP 也不会终止它。如果你想设置时间限制来约束行为不当的脚本，可以在脚本中使用`set_time_limit()`函数。

- 描述传递给脚本的命令行参数的变量`$argc`和`$argv`会自动设置。这些将在本章后面详细讨论。

- `PHP`定义了与同名标准流相关的常量`STDIN`、`STDOUT`和`STDERR`，并自动打开它们的 I/O 流。

要使用 PHP CLI SAPI，你可能需要先安装它。附录 A 提供了关于安装（以及在必要时编译）PHP 的细节。不过，如果你已经安装了 PHP，可能会发现它已经安装了（通常在 PHP 程序目录中名为`sapi/cli`的文件夹下），如果没有，它通常在现代操作系统的软件仓库中可用（例如，在 Ubuntu 中，有一个名为`php5-cli`的包，可以通过任何包管理器或通过命令行使用`sudo apt-get install php5-cli`进行安装）。

如果它已安装在命令行搜索路径中，在命令行中输入`php -v`将打印版本详情，确认它确实已安装。

### 3.3 PHP 命令行选项

PHP 二进制文件将接受许多命令行选项/开关/参数，这些选项会影响它的运行。可以通过输入`php -h`查看完整列表。虽然某些选项仅适用于 CGI SAPI（当没有“模块”时使用，例如没有 PHP Apache 模块时），但以下是用于在与 CLI SAPI 交互时一些有趣且常用的选项：

#### `-f` 或 `--file`

这允许你指定要运行的脚本文件名，它是可选的。存在`-f`选项是为了兼容某些软件和脚本（例如自动化软件，可以通过编程方式调用命令行程序，但要求以这种方式形成文件名参数）。它还允许在 Windows 上为 PHP 脚本轻松设置默认文件类型处理器。

上述两个版本命令在用法上的唯一真实区别在于解释传递给脚本的命令行参数，我们将在下文的“你的脚本的命令行参数”部分中查看这一内容。在大多数情况下，以下两行代码大部分是等价的：

```bash
1 ~$ php -f myscript.php
2 ~$ php myscript.php
```

#### `-a` 或 `--interactive`

以交互模式运行 PHP。这允许你逐行输入 PHP 代码，而不是执行一个已保存的 PHP 脚本。这种运行模式通常被称为“REPL”（读取-评估-打印-循环）。

除了为测试和开发代码提供交互式界面外，它还可以作为一个增强的 PHP 启用 shell 或命令行，我们将在本章稍后的部分进行详细讨论。

#### `-c` 或 `--php-ini`

指定 PHP 为此应用使用的 PHP ini 文件。如果你在同一台机器上还使用 PHP 运行 Web 服务，这特别有用，因为如果没有指定，PHP 将在多个默认位置查找`php.ini`，并最终可能与你的 Web 服务使用同一个。

通过为你的 CLI 应用提供一个特定的文件，你可以“开启”各种更符合离线应用程序的限制。请注意，通过使用 CLI SAPI，无论你是否使用此选项指定了自定义 ini 文件，PHP 都会自动覆盖几个`php.ini`设置。

这些被覆盖的设置会影响上述“CLI SAPI 有何不同？”中列出的行为，虽然在这些情况下`php.ini`文件被忽略，但你可以在代码中使用`ini_set()`函数或类似函数直接还原或更改这些设置。

你还可以使用`-d`或`--define`选项来设置选项（例如`php -d max_execution_time=2000 myscript.php`）。如果你将软件部署到你无法控制的机器上（例如，如果你正在销售软件让用户安装在自己的机器上），那么使用这些机制之一来确保 PHP 以你预期的设置运行，而不是用户可能恰好拥有的设置。请同样参见下文的`-n`。

#### `-n` 或 `--no-php-ini`

这告诉 PHP 不要加载任何`php.ini`文件。如果你不想随应用程序分发一个文件，而是希望在代码中使用`ini_set()`或类似函数直接设置所有配置，这就会很有用。如果没有提供 ini 文件，PHP 将使用其默认设置。

#### `-e` 或 `--profile-info`

将 PHP 放入“扩展模式”。它为分析器和调试器生成额外信息。关于分析器和调试器的更多信息可以在下一章中找到。在使用分析器或调试器时，启用此模式可能会影响性能。

#### `-i` 或 `--info`

调用`phpinfo()`函数并输出。这输出关于 PHP 安装的大量信息，采用纯文本格式而不是 HTML（假设我们从 CLI 调用它）。这对于追踪问题非常有用，提供了版本信息、扩展列表等。

与其他任何 shell 命令一样，输出可以管道到其他命令，例如你可以尝试：

```bash
1 ~$ php -i | grep "ipv6"
```

#### `-l` 或 `--syntax-check`

解析文件并检查语法错误。这是一个基础的“语法”检查器，更高级的代码分析工具将在下一章讨论。请注意，此选项只检查语法错误，不会执行代码。

某些 IDE 和文本编辑器会在你输入时在后台运行`php -l`。例如，Atom 编辑器中的 linter-php 插件就使用这种方法进行实时检查。

#### `-m` 或 `--modules`

列出所有加载的 PHP 模块/扩展。这些是 PHP 时的模块，可能包括“core”、“mysql”、“PDO”、“json”等。对于检查 PHP 安装是否具有应用程序所需的功能非常有用。

你也可以在脚本内部使用`extension_loaded()`函数或调用`phpinfo()`函数进行检查。`-m`提供了上述`-i`标志信息的子集，而`-i`则将返回更多关于模块的配置、版本等信息。

#### `-r` 或 `--run`

运行作为参数提供的 PHP 代码，而不是从文件执行。代码行应该用单引号括，因为像 bash 这样的 shell 会尝试对双引号变量进行插值。

这与`-a`交互模式的作用相似，只是每执行一行后，PHP 的“状态”都会清除。这意味着提供的代码行被视为要执行的整个脚本，并在运行后终止。示例如下：

```bash
1 ~$ php -r 'echo (2+2)."\n";'
```

注意，该行必须是语法上正确的 PHP 代码，所以不要漏掉结尾的分分号！我们将在本章稍后的“调用 PHP 脚本的多种方法”部分重新回到`-r`。

#### `-B` 或 `--process-begin`

#### `-R` 或 `--process-code`

#### `-F` 或 `--process-file`

#### `-E` 或 `--process-end`

这四个参数允许你指定在 PHP 处理来自`STDIN`的输入之前、期间和之后执行的 PHP 代码。`-B`指定在处理输入之前执行一行代码，`-R`指定在处理每一行输入时执行一行代码，而`-F`指定为每行输入执行一个 PHP 文件。最后，`-E`在输入过程结束时执行一行代码。

在`-R`和`-F`中，有两个特殊变量可用：`$argn`——正在处理的行文本，以及`$argi`——正在处理的行行号。这在在 shell 脚本中直接使用 PHP 时非常有用。例如，要打印带有行号的文本文件，你可以 own 这样做：

```bash
1 ~$ cat my_text_file.txt | php -B 'echo "Lets add line numbers...\n";'
2         -R 'echo "$argi: $argn\n";' -E 'echo "That''s the end folks\n";'
```

输出结果如下：

```text
1 Lets add line numbers...
2 1: Lorem ipsum dolor sit amet, consectetur adipisicing elit, sed do 
3 2: eiusmod tempor incididunt ut labore et dolore magna aliqua. Ut enim ad
4 3: minim veniam, quis nostrud exercitation ullamco laboris nisi ut aliquip
5 4: ex ea commodo consequat. Duis aute irure dolor in reprehenderit in 
6 That's the end folks
```

#### `-s` 或 `--syntax-highlight`

这会输出 PHP 脚本的 HTML 版本，带有彩色的语法高亮。PHP 脚本不会被执行或验证，仅仅是进行“美化”。美化后的 HTML 打印到`STDOUT`，这在检查代码以寻找错误、问题和优化时非常有用。

这仅适用于文件中的 PHP，不适用于通过`-r`选项提供的代码。虽然大多数现代 IDE 和代码编辑器默认都提供语法高亮，但如果你只能通过命令行访问机器，且你使用的编辑器不支持语法高亮，这就会很有用。

在这种情况下，使用`-s`创建脚本的彩色版本，如果机器安装了 Web 服务器，可以下载它或通过浏览器查看。

#### `-v` 或 `--version`

这会输出 PHP 版本信息。你也可以在上述的`-i`选项的输出中找到它。在假设特定格式时要小心，某些软件包仓库（例如 Ubuntu）会在版本字符串中包含它们的名称和自己的构建版本，因此不要仅对其过滤任何数字。

#### `-w` 或 `--strip`

这会输出删除了任何不必要的空格和注释后的源代码内容。这只能用于代码文件（不适用于通过`-r`提供的代码行），且与上述语法高亮选项不兼容。

这用于“压缩”文件，即减小文件大小。与流行观点相反，这不会加快大多数脚本的速度，因为解析注释和空格的开销微乎其微。

即使保留了“完整”代码的副本，你也应该警惕支持和调试问题，因为错误报告中的行号在原始版本和剥离版本之间不再匹配。它也不会压缩变量名等标识符，因此不能用于混淆你的代码。

正如你可能从上一节的命令行选项中看出的，在使用 CLI SAPI 时，有几种不同的方法可以执行 PHP 代码。虽然我们已经涵盖了其中几种，但为了完整起见，我们在这里再次讨论了它们。

### 3.5.1 从文件执行

你可以告诉 PHP 执行特定的 PHP 源代码文件。例如：

```bash
1 php myscript.php
2 php -f myscript.php
```

请注意`-f`是可选的，上述两行在功能上是等价的。上述详细的`php`命令行选项在适当的情况下也适用于此方法。例如：

```bash
1 ~$ php -e myscript.php
```

将在扩展信息模式（Extended Information Mode）下执行`myscript.php`文件。

与 PHP 的 Web 版本一样，源文件可以与 HTML（或在命令行上更有用的纯文本）进行插值（混合）。因此，你仍然需要你的起始标签`<?`或`<?php`，否则你的源代码将直接被打印出来，而不会被执行。

### 3.5.2 从字符串执行

你可以使用`-r`标志执行单行代码：

```bash
1 ~$ php -r 'echo("Hello World!\n");'
```

许多其他命令行选项在`-r`方法中不可用，例如语法高亮。注意 shell 变量替换（在代码周围使用单引号而不是双引号）以及 shell 对你代码的其他形式篡改。

除非这确实是一个快速的一次性任务，否则将相关行存入文件并改为执行该文件可能更安全、也更简单。`-r`选项的一个常见用途是执行由其他（可能非 PHP）shell 命令生成的 PHP 代码，其中整个 shell 脚本需要在内存中执行而不触碰磁盘（例如权限禁止磁盘写入访问的情况）。

### 3.5.3 从标准输入（STDIN）执行

如果你不指定文件或不使用`-r`选项，PHP 将把`STDIN`的内容视为要执行的 PHP 代码，如下所示：

```bash
1 ~$ echo '<? echo "hello\n";?>' | php
```

你还可以结合`-B`、`-R`、`-F`和`-E`使用此方法，使 PHP 成为 shell 脚本中的一等公民，让你能够将数据管道输入和输出到 PHP。

例如，要反转文件的每一行（或任何管道到它的数据源），使用：

```bash
1 ~$ cat file.txt | php -R 'echo strrev($argn)."\n";' | grep php
```

在这行代码中，我们将文本文件的内容管道到 PHP。`-R`选项告诉 PHP 在每行输入上执行随后的 PHP 代码，该行存储在特殊变量`$argn`中。

在这种情况下，我们使用字符串反转函数`strrev()`反转`$argn`，然后再次`echo`反转后的字符串。任何`echo`的输出都会进入`STDOUT`，它会被打印到 shell 中，或者像在本例中这样可以管道到另一个 shell 命令。

在我们的案例中，我们使用`grep`只显示包含字符串‘php’的行，即‘php’的反转字符串。关于`-R`及其兄弟选项的更多细节请见上一节。

如果你想使用像`-R`这样的选项，但 PHP 代码太多无法方便地放在命令行中，可以将代码放在普通的 PHP 源代码文件中并`include()`它，例如：

```bash
1 ~$ cat something.txt > php -R 'include("complicated.php");'
```

如果这是一个复杂的 PHP 脚本，将其封装成函数并使用`-B`包含一次（`-B`意味着在主代码之前执行）可能效率更高，然后使用`-R`每次执行该函数。以下示例在开始时加载一次`my_functions.php`内容，然后通过`-R`执行函数`complicated()`：

```bash
1 php -B 'include("my_functions.php");' -R 'complicated();'
2	data.txt
```

尽管这些命令看起来很简单，但你可以在后面放置的 PHP 代码没有限制。你可以使用类和对象、多个文件以及本书书中探讨的许多技术，并在 shell 层级暴露函数或方法。我们还可以打开标准流作为 PHP 流来读写数据，这将在下一节中讨论。

### 3.5.4 作为可执行脚本：Unix/Linux

在 Unix/Linux 类型系统中，你可以将 PHP 脚本变为可执行的 shell 命令。只需在脚本文件的第一行使用`#!`行（通常称为“shebang line”或“hashbang line”），并指向 PHP 二进制文件的路径，例如：



# 作为可执行脚本：Unix

```php
#!/usr/bin/php
<?

echo('Hello World!');
```

并使用 `chmod` 或类似的命令设置执行位，例如：

```bash
~$ chmod a+x myscript.php
```

然后在命令行中输入 `./myscript.php` 即可执行它。你也可以通过重命名文件移除 `.php` 扩展（如果原本有的话），这样你只需要输入

```bash
~$ ./myscript
```

在 shell 提示符处运行。你可以通过将其移动到路径来进一步简化 `./`。

## 作为可执行脚本：Windows

类似地，Windows 下可以直接调用执行脚本。然而，设置 Windows 执行此操作的过程要复杂一些，涉及注册表和文件类型关联。因此，我建议阅读官方 PHP 文档，它详细介绍了这一点。

## Windows php-win.exe

Windows 版 PHP 还带有 `php-win.exe`，它与 PHP 的 CLI 版本类似，但不会打开命令行窗口。这对于后台运行系统软件或运行创建图形界面的脚本有用。

## 退出你的脚本

我们已经了如何启动脚本，但在运行结束时会发生什么呢？

像 Web 版 PHP 脚本一样，CLI 脚本在到达脚本文件末尾时会顺利终止，并以相同的方式清理所有使用的资源。同样，如果我们想提前结束，可以调用 `exit`（或等价 `die`）语言结构。

然而，在 CLI 脚本的世界中这被认为是不礼貌的。由于 CLI 命令的设计是为了协同工作（通常以命令链的形式运行），大多数 shell 程序和脚本在终止时都会提供一个“退出码”（exit code），以便让其他程序知道它们*为什么*结束。它们是执行完毕？还是遇到了错误？或者是被错误地调用？好奇的心灵想要答案。

当你的脚本可能是 shell 脚本中的最后一个项时，提供退出码尤为重要，因为整个 shell 脚本的退出码被视为内部返回的最后一个退出码。我们可以通过通过将退出码作为 `exit` 或 `die` 的参数，让我们的 PHP 脚本提供退出码。退出码是一个整数，有许多常见的退出码：

* `0` : 成功 - 我们已正常退出。
* `1` : 通用错误 - 通常用于应用程序/语言特定的错误和语法错误
* `2` : 用法不正确
* `126` : 命令不可执行 - 通常与权限有关
* `127` : 找不到命令
* `128+N`（最高至 `165`）：命令被 POSIX 信号数 N 终止 - 例如在 `kill -9 myscript.php` 的情况下，它应该返回代码 137 (128+9)
* `130` : 命令被 Ctrl-C 终止（Ctrl-C 是 POSIX 代码 2，因此如上述 128+2 = 130）

任何其他正整数通常被解释为由于未指定的错误而退出。例如，如果你判断用户提供的命令行参数格式不正确，你应该使用 `exit(2)` 终止脚本。如果一切顺利且你的脚本一直运行到文件末尾，你实际上可以让它自行退出（或通过不带参数地调用 `exit`），因为它默认返回状态码 0。

与 Web 脚本一样，你可以使用 `register_shutdown_function()` 函数注册在 PHP 脚本退出时执行的函数。这的一种用途可能是检查一切是否正常，并评估应该返回哪种退出码。在注册的关机函数内部，作为 `exit` 或 `die` 参数使用的退出码，将覆盖启动关机的初始退出调用中所使用的代码码。这意味着你可以放心地在任何地方使用 `exit(0)`，如果你检测到元空间对象中的 foo 聚合与 bar 初始化不匹配，则在关机函数中执行 `exit(76)`。或者类似的操作。

## PHP REPLs

当你想要测试几行 PHP 代码时，你的直觉可能是创建一个新的 PHP 文件，保存它，然后用 PHP 执行它。然而，有一种更好、更快且更具交互性的方法。PHP “交互式外壳”，也称为 PHP REPL（读取-求值-打印循环），是一种输入代码并使其立即执行的快速简便的方法。与使用 `php -r` 执行单行代码不同，REPL（通过调用 `php -a` 启动）会在你输入的每行之间保持脚本的状态（例如变量和对象的内容），直到你退出为止。你可以使用 PHP 的所有函数，尽管默认没有加载任何库，并且你可以 `include()` 或 `require()` 现有的 PHP 代码文件。后一种功能对于调试问题脚本的最终输出非常有用只需 `include()` 你的脚本，它就会执行；只要脚本没有提前终止，你就可以使用 `echo()` 或 `print_r()` 或其他方式探索运行结束时变量和其他资源的状态。还有其他类型的 REPL，将在在本节的后续部分列出。根据其性质，它也可以本身作为 CLI / Shell 使用，调用其他 PHP 和非 PHP 程序，就像你在 bash shell 中调用它们一样。

下面的示例是使用标准 PHP REPL 的实际交互式 REPL 会话的。

```php
~$ php -a
Interactive shell

php > # 既然我们可以输入任何有效的 PHP，我添加了注释
php > # 直接添加到 REPL 中，而不是事后再编辑！
php > 
php > # 让我们从一些简单的赋值开始：
php > 
php > $a = 5;
php > $b = 6;
php > 
php > # REPL 会根据情况抛出通知、警告和错误，
php > # 并且实时显示：
php > 
php > $c = nothingdefined;
PHP Notice:  Use of undefined constant nothingdefined - assumed 
'nothingdefined' in php shell code on line 1
php > 
php > # 就像对于普通的 PHP 源文件一样，我们可以跨行拆分命令。
php > # 解释器只有在遇到终止的分号时才会介入：
php > # 分号：
php > 
php > $d 
php > =
php > 7
php > ;
php > 
php > # 下面显示了上述变量中的状态被
php > # 保留了：
php >
php > echo $a + $b + $c + $d ."\n";
18
php >
```

除了上述介绍的内置 PHP REPL 之外，还有许多第三方 REPL 可用，其中一些包含了诸如已输入命令历史、命令 Tab 补全、致命错误保护，甚至是简要函数文档等功能。

## 命令行界面基础

尽管图形界面如今似乎占据着主导地位，但文本界面仍然有许多用处，特别是在技术精通的用户环境中。在创建一个运行在命令行的基于文本的程序时，除了你已经熟悉的 PHP 之外，还有三个首要考虑的因素。这些因素是：

1. 获取键盘输入
2. 向屏幕输出文本（和图形）
3. 程序流控制

我们不会孤立地描述每项内容，而是通过一个包含这三个元素的简单程序来观察。请阅读下面的代码和注释。该程序是一个屏幕保护程序程序，通过一个蠕动的蛇形光标为 shell 填充颜色。

```php
<?php
# 首先，我们将定义一些命名常量。
# 这些是 shell 转义码，用于格式化。
# 将它们定义为命名常量有助于提高我们代码的可读性。

define("ESC", "\033");
define("CLEAR", ESC."[2J");
define("HOME", ESC."[0;0f");

# 我们将向用户输出一些指令。注意我们使用的是 fwrite
// 而不是 echo。目标是将我们的输出写回 shell，
// 这样用户可以在那里看到它。fwrite(STDOUT...) 写入
// php://stdout 流。Echo（以及 print）写入 php://output
// 流。通常情况下二者是同一个东西，但并不一定如此。
// 此外，php://output 受到输出控制和
// 缓冲函数（http://www.php.net/manual/en/book.outcontrol.php）的影响，
// 这可能是需要的，也可能不需要。

fwrite(STDOUT, "按回车键开始，再次按回车键结束");

# 现在我们等待用户按下回车。默认情况下，STDIN 是
// 一个阻塞流，这意味着当我们尝试从它读取内容时，
// 我们的脚本将停止并等待输入。当用户按下回车键时，
// shell 的键盘输入将（通过 fread）传递给我们的脚本。

fread(STDIN,1);

# 我们希望程序一直运行直到用户再次按下回车键。
// 这意味着我们希望定期使用 fread 检查输入，
// 但在没有输入时不暂停/阻塞程序。因此，我们将 STDIN
// 设置为非阻塞模式。

stream_set_blocking(STDIN, 0);

// 画一个精美的框。要做到这一点，我们需要知道当前终端
// 窗口有多大。没有内置的方法可以实现这一点，因此我们调用
// 一个名为 tput 的外部 shell 命令，它提供了关于当前终端的信息。

$cols = intval(`tput cols`);

# 现在我们向终端写入两个特殊的转义码，其中第一个
# (\033[2J) 清除屏幕，第二个 (\033[0;0f) 将
# 光标置于屏幕的左上角。我们已经在脚本开头
# 将它们定义为常量 CLEAR 和 HOME。

fwrite(STDOUT, CLEAR.HOME);

# 现在我们想在窗口周围画一个框。在终端中绘制
#“图形”（或“半图形”）最简单的方法是使用
// 大多数等宽字体中包含的框线字符。

# 通过逐行移动光标每一侧来绘制垂直框。
# 光标通过转义码移动，例如 ESC."[$rowcount;1f

for ($rowcount = 2; $rowcount < $rows; $rowcount++) {
	fwrite(STDOUT, ESC."[$rowcount;1f║"); // 例如 \033[7;1f 用于第 7 行
	fwrite(STDOUT, ESC."[$rowcount;${cols}f║");
}

# 现在对水平框执行同样的操作。

for ($colcount = 2; $colcount < $cols; $colcount++) {
	fwrite(STDOUT, ESC."[1;${colcount}f═");
	fwrite(STDOUT, ESC."[$rows;${colcount}f═");
}

# 最后填充四个角。

fwrite(STDOUT, ESC."[1;1f╔");
fwrite(STDOUT, ESC."[1;${cols}f╗");
fwrite(STDOUT, ESC."[$rows;1f╚");
fwrite(STDOUT, ESC."[$rows;${cols}f╝");

# 你可以在此处查看框线字符范围
// http://en.wikipedia.org/wiki/Box-drawing_character
// 它们就像任何其他字符一样，所以你可以轻松复制
// 并粘贴到大多数编辑器中。

// $p 是一个存储光标位置的数组 [x,y]。我们将将其
// 初始化为屏幕中心。

$p = ["x"=>intval($cols/2), "y"=>intval($rows/2)];

# 现在处理第一个流程控制元素。我们需要让程序
// 一直运行直到用户提供输入。最简单的方法是
// 使用 while(1) 使用不结束的循环。“1”始终为真，
// 所以 while 循环永远不会结束。当我们（或用户）准备
// 结束程序时，可以使用“break”结构跳出循环，
// 并继续执行循环后的剩余脚本。

while (1) {

	# 每当通过循环时，我们都想检查用户在
	// 上一个循环中是否按了回车键。记住
    // ... (后续逻辑由于原文截断省略)
}
```

## 高级命令行输入

在上面的小节中，我们使用了 `fread()` 来读取键盘输入。这对于简单的程序非常合适，但如果你想创建一个更复杂的界面来允许用户发布命令，那么你可能希望查看 `readline` 扩展，你可以使用它来实现一个类似 shell 的可编辑命令行程序。

接下来的示例脚本展示了如何使用 `readline` 库实现一个简单的自定义命令行类型界面。

```php
<?
# 创建数组来存储我们的命令历史记录和有效命令列表。

$history = array();
$validCommands = array();

# 定义一些有效命令。

$validCommands[] = 'kill';
$validCommands[] = 'destroy';
$validCommands[] = 'obliterate';
$validCommands[] = 'history';
$validCommands[] = 'byebye';

# 我们希望启用命令的制 键补全功能，这允许用户
# 开始输入命令，然后按 Tab 键完成输入，就像在
# Bash shell 等类似环境中发生的那样。我们需要提供一个函数（通过
# readline_completion_function）来提供一个可能的函数
# 名称数组。这可以基于用户输入的 $partial 字符
# 或者程序所处的位置，或者任何我们想要的
# 因素。在我们的情况下，我们将提供一个包含所有
# 有效命令的数组。

function tab_complete ($partial) {
	global $validCommands;
	return $validCommands;
};

readline_completion_function('tab_complete');

# 现在进入主程序循环。注意我们没有包含 usleep，
# 因为 readline 在等待用户输入时会暂停程序的执行。

while (1) {

	# 我们调用 readline 并传入一个构成命令提示符的字符串。
	# 在我们的情况下，我们将日期和时间放在其中，显示每次
	# 调用时都会更改。用户输入的任何内容都会被返回。这
	# 行简单的代码实现了 readline 的大部分魔法功能。在此阶段
	# 用户可以利用 Tab 补全、历史记录（使用上/下方向键）等功能。

	$line = readline(date('H:i:s')." 正在输入命令 > ");

	# 我们需要手动将命令添加到历史记录中。这用于
	# 用户通过上/下方向键访问的命令历史。如果我们想，
	# 可以选择忽略命令（例如，输入错误的命令或
	# 中间输入）。
	
	readline_add_history($line);
	
	# 如果我们想通过程序检索历史记录，可以使用
	#名为 readline_list_history() 的函数。然而，只有当
	# PHP 使用 libreadline 编译时才可用。在大多数情况下，
	# 现代发行版由于许可等原因使用兼容的
	# libedit 库进行编译。因此我们将在数组中保留一份
	# 历史行的副本以便程序化访问。

	$history[] = $line;

	# 现在我们决定对用户的输入做什么。在现实生活中，
	# 我们可能需要先对输入进行 trim()、strtolower() 和其他过滤。

	switch ($line) {

		case "kill":
			echo "你不想做那个。\n";
			break;

		case "destroy":
			echo "那真的不是个好主意。\n";
			break;

		case "obliterate":
			echo "好吧，如果我们真的必须这样做。\n";
			break;

		case "history":
			# 我们将使用之前创建的命令历史副本
			# 来显示命令历史记录。

			$counter = 0;

			foreach($history as $command) {
				$counter++;
				echo("$counter: $command\n");
			};
			break;

		case "byebye":
			# 如果该离开了，我们想要跳出语句
			# 和 while 循环，所以使用级别为 2 的 break。
			break 2;

		default :
			# 始终记住在用户出错时给出反馈。
			echo("抱歉，".$line." 未被识别。\n");
	}
}
# 如果我们到达这里，说明用户输入了 byebye。
echo("再见，下次见！\n");
```

你可能注意到我选择使用 `byebye` 作为退出命令。这不仅仅是我个人的心血来之，，而是为了说明“可发现性”（discoverability）的重要性。如果你面对这个程序，在没有看到源代码的情况下，并被要求关闭它，你可能会在诉诸使用 `Ctrl-C` 之前尝试 `quit`、`exit` 等。在 GUI 界面中，当你面对一个写着“Bye!”的按钮时，也会遇到此类问题。在文本输入中，最好遵循常见且易于记忆的格式，尽可能提供视觉引导和线索，并通过 `help` 命令和用户训练来辅助可发现性。

PHP CLI SAPI 在脚本启动时会自动为你打开标准流，因此不需要发布诸如 `php://stdin` 之类的命令。你可以将这些流视为任何其他 PHP 流，并直接启动它们。我们在上面已经包含了一些示例，但这里有更多示例用于说明。



```php
<?
# 从 STDIN 获取一行输入
echo ('请输入 : >');

$line1 = fgets(STDIN);
echo ('**** 第一行 : ****\n');

# 获取不带换行符的输入
echo ('请输入 : >');

$line2 = trim(fgets(STDIN));
echo ('**** 第二行 : ****\n');

# 将数组写入 STDOUT 并转换为 CSV 格式。
# 首先创建一个数组...
$records[] = array('User', 'Full Name', 'Gender');
$records[] = array('Ada', 'Countess of Lovelace', 'F');
$records[] = array('Grete', 'Hermann', 'F');
$records[] = array('Rob', 'Aley', 'M');

echo ("以下是 CSV 格式的数据 :\n\n");

# ...动态将每个数组转换为 CSV
foreach ($records as $record) {
	fputcsv(STDOUT, $record);
};

echo ("\n 数据结束\n");

# 等待用户输入数字
echo ('请输入一个或多个数字 : >');

while (! fscanf(STDIN, "%d\n", $your_number) ) {
	echo ("未找到数字 :>");
};

echo ("你的数字是 $your_number\n\n");

# 将网页文本发送到 STDOUT
echo ("回车查看网页内容 :\n\n");

fread(STDIN, 1); # fread 等待按键

fwrite(STDOUT, strip_tags( file_get_contents('http://www.cam.ac.uk') ) );

# 将错误消息发送到 STDERR。你可以直接 fwrite(STDERR,...
# 如果你需要，或者可以使用 error_log 函数，它使用
# 定义的错误处理程序。对于 CLI SAPI，默认是
# 打印到 STDERR。

error_log('系统啤酒光光了。中止。中止。',4);
```

最后一行记录的错误通常会在你的 shell 中与其他输出一起显示，因为这是大多数 shell 放置 `STDERR` 的地方。如果你想检查它确实来自 `STDERR` 而不是 `STDOUT`，下面的 bash 命令会将任何 `STDERR` 输出（由 `2>` 标记）显示为红色。它使用转义代码来着色错误（31 设置为红色，07 反转颜色，然后 0 清除）：

```bash
php script.php 2> >(while read errors; do echo -e "\e[07;31m$errors\e[0m" 
	>&2;  done)
```

简而言之，我们可以以多种方式使用标准流，通常将其视为任何其他文件指针或流。

有一些预先写的库/组件可以使用，可以减少创建交互式控制台软件的工作量。我在下面列出了三个常用的库。与大多数此类库一样，它们对程序的结构组织有非常“主观性”的见解，因此在选择最适合你项目的库之前，请务必彻底阅读每个库的文档。`Symfony console`（`Symfony Framework` 项目的一部分）经过了充分测试，非常稳定，与大多数 `Symfony` 组件一样，它拥有良好的文档说明和支持。如果你熟悉 `Symfony Framework`，那么这种代码风格会让你很熟悉，但它与其他框架也同样游刃有（它被用于 `Laravel Framework` 的 `Artisan Console` 工具）。`Webmozart Console` 工具包是 `Symfony Console` 组件的重构版本，因此具有相似的功能，但编码风格有所不同。它目前仍处于 Beta 阶段。最后，`Hoa Console` 可能是这三者中最独特的，它的编码风格侧重于真实世界的任务，对于开发者来说可能更容易上手。

## 5. PHP CLI 脚本与你的系统

PHP CLI 脚本通常与你的系统交互涉及多个领域。虽然大多数系统交互与你在 Web 脚本中习惯的相同，但有几个领域你可能没有用过，我们将查看一些可能会让你困惑的坑（gotchas）。

### 5.1 从 PHP 启动外部进程，或“调用 shell”（shelling out）

CLI 脚本的一个常见功能是调用并与其他脚本及进程交互。在脚本中使用其他脚本和程序作为“构建块”是 CLI 编程的一种常见模式。正如我们之前看到的，你通常可以将你的 PHP 脚本与其他通用的 shell 脚本结合，但通常让 PHP 脚本本身在需要时启动其他软件也往往是很有用的。这通常被称为“调用 shell（shelling out）”。

PHP 提供了许多函数来实现这一目标，每个函数的实现方式略有不同，且具有不同的优处：

* `exec()`：执行程序并将文本输出发送给用户

* `passthru()`：执行程序并将二进制输出发送给用户

* `system()`：执行程序并收集输出供 PHP 使用

* `shell_exec()`：通过 shell 执行命令并收集其输出供 PHP 使用

* 反引号运算符（例如 `\`command\``）：与上述的 `shell_exec()` 相同

* `pcntl_exe()`：在当前进程空间中执行程序，也就是说，它会停止当前的 PHP 脚本并用指定的程序替换它

* `popen()`：执行程序并打开一个文件指针（与 `fopen()` 返回的指针相同），通过 `STDOUT` 或 `STDIN` 对进程进行读取或写入。只能读或写，不能兼顾。

* `proc_open()`：类似于 `popen()`，但具有更多控制权。允许同时读取和写入。使用起来没有 `popen()` 那么简单。

选择哪种方法取决于你打算对新打开的进程做什么，以及你如何（或者实际上是否）想与其通信。如果你无法根据上面的描述确定哪个函数适用于你的用途，下方的“延伸阅读”列表提供了一些提示、信息和实现示例，应该能给你提供方向。

调用外部脚本时，请记住在命令名或选项中使用不可信的用户输入是安全灾难的来源！`escapeshellarg()` 函数可以保护你免受一些无意错误，但不能阻止你执行“坏”函数或文件。

### 5.2 文件状态和 Realpath 缓存

在 Web 世界，速度就是王道。PHP 运行两个信息缓存来加速文件系统的访问。第一个是文件状态缓存，它缓存有关给定文件的信息（例如是否存在、是否可读、大小和类型等）。第二个是 realpath 缓存，它缓存给定文件或目录的实际路径（展开符号链接、相对路径、`.` 和 `..` 路径、`include_path` 等）。PHP 每当遇到新文件时都会自动将信息添加到缓存中，在下一次任何数量函数尝试查看该相同文件时，这些信息就会被使用。对于一个转瞬即逝的网页来说，由于文件系统可能没有发生什么变化，这通常是提高性能的一种很好的权衡。

然而，在你的脚本运行期间，文件或路径细节发生更改的概率显然随着脚本执行时间的增加而增加。因此，PHP 为我们提供了处理这两个缓存的选项。

下面的示例展示了文件状态缓存的作用，以及如何使用 `clearstatcache()` 来清空它。

```
 1 <?
 2 
 3 # 创建一个文件并为其添加一些文本
 4 
 5 $filename = 'test.txt';
 6 
 7 $handle = fopen($filename, 'w+');
 8 
 9 fwrite($handle, 'test');
10 
11 # 下面应该打印 4
12 
13 echo stat($filename)["size"]."\n";
14 
15 # 现在向文件写入一些数据，增加文件大小。
16 
17 fwrite($handle, 'more test');
18 
19 # 直觉上，下面的命令应该打印 13，因为文件现在
20 # 比之前大了。然而，它仍然打印 4，因为这个文件的 filesize
21 # 值现在被缓存了。
22 
23 echo stat($filename)["size"]."\n";
24 
25 # 如果我们清空缓存……
26 
27 clearstatcache();
28 
29 # 那么下一行应该如预期打印 13
30 
31 echo stat($filename)["size"]."\n";
32 
33 fclose($handle);
```

realpath 缓存的工作方式类似，可以通过调用 `clearstatcache(true)` 来清空，即通过将第一个参数设置为 true 来调用它。你也可以通过调用 `clearstatcache(true, 'myfile.txt')` 只清除一个文件的缓存，其中第二个参数是文件名（第一个参数必须设置为 true）。

当然，在你的应用程序中可能没有必要清除这些缓存，而且这样做会有性能影响。请根据具体情况考虑每次文件访问。

### 5.3 APC 和其他代码缓存

你可能已经知道 APC 缓存系统和其他用于加速脚本启动时间的代码缓存系统。APC 以及大多数其他系统不适用于 CLI 脚本（或者至少不会产生任何收益），因为它们基于 Apache 等 Web 服务器找到的共享进程模型。由于 PHP CLI 脚本（通常）在完成后会终止自己的进程，这些系统无法工作。

### 编译并安装 PHP 本身

Windows 开发者注意——这些步骤适用于 Linux/Unix 类型系统，并使用几乎总是随操作系统自带的免费编译器工具。对于 Windows，需要专有的 Visual Studio 编译器，步骤有所不同且超出了本书的范围。Windows 源码、预编译二进制文件可以在 [`windows.php.net/`](http://windows.php.net/) 获取。

OS X 开发者注意——虽然步骤与 Mac 类似，但根据你使用的操作系统可能会遇到一些问题。

在 Linux 机器上，我们的第一步是从 PHP 网站 [`www.php.net/downloads.`](http://www.php.net/) 下载源码。该页面列出了当前的稳定版本和上一个稳定版本。仍在开发中的新版本可以在 [`snaps.php.net/`](http://snaps.php.net/) 获取，旧版本可以在 [`museum.php.net/`](http://museum.php.net/) 获取。Git 用户也可以从官方镜像 [https://github.com/php] 拉取源码。

当你确定了想要的版本后，记下 .tar.gz 源码的 URL，我们稍后会用到。

```
1 ~$ mkdir php5.4
2 ~$ cd php5.4
3 ~$ wget http://uk3.php.net/get/php-5.4.6.tar.gz/from/uk3.php.net/mirror 
4	-o php-5.4.6.tar.gz
5 ~$ tar zxvf php-5.4.6.tar.gz
6 ~$ cd php-5.4
```

前两行为工作创建一个目录并进入。该目录存放源码和中间文件，一旦 PHP 安装完成就可以删除。然而，通常建议保留它，以防以后需要重新安装或检查你下载的是哪个版本的源码。第三行将源码文件下载到我们的目录中。第五行将包解压到包含单个源码文件的目录。最后一行我们进入源码目录。现在我们开始实际的编译过程。

```
1 ~$ ./configure
```

`configure` 命令用于创建编译的“设置”环境。我们用它为编译会话提供所需的设置和参数。例如，我们可以指定想要在构建中包含哪些核心扩展。如果我们不像上面那样指定任何参数，则将使用 PHP 开发团队提供的默认值。如果你没有特殊需求，并希望获得一个与大多数发行版中包含的版本相当相似/兼容的版本，那么这是一个很好的选择。你也可以在日后的某个时间单独地安装扩展，或者通过从头开始编译 PHP 来安装，我们将在下一节中讨论这一点。如果你想在此阶段包含一个默认设置中未包含的扩展，那么这里就是进行操作的地方。例如，如果你想包含 ldap 扩展，则可以将上面的命令更改为 `./configure --with-ldap[=DIR]`，其中 `[=DIR]` 是系统上 ldap 的基础安装目录。要使用的具体选项以及任何必要的依赖项，可以在 PHP 手册中相关扩展的“安装/配置（Installing/Configuring）”部分找到。例如，ldap 扩展的详细信息可以在 [`www.php.net/manual/en/ldap.setup.php`](http://www.php.net/manual/en/ldap.setup.php) 找到。可以传递给 `configure` 命令的选项列表（略微过）可以在 [`www.php.net/manual/en/configure.about.php`](http://www.php.net/manual/en/configure.about.php) 找到；或者，为了获取你正在尝试编译的当前版本在你系统中支持的完整列表，你可以执行命令 `autoconf` 然后跟上 `./configure --help`。关于 `configure` 命令的更多信息可以在 [`www.airs.com/ian/configure/`](http://www.airs.com/ian/configure/) 找到。现在我们来实际编译 PHP。

```
1 ~$ make clean
2 ~$ make
3 ~$ sudo make install
```



我们使用`make`工具来编译二进制 PHP 文件。第一行会删除任何之前创建的文件并重置到`make`过程的起点。在第一次运行编译时这并不是严格必要的，但如果你的尝试由于某些原因失败了（例如缺少依赖项、设置错误、进程被无意中断等），它可能会有所帮助，因此默认包含它通常是一个很好的选择。第二行执行对文件的实际构建和编译。第三行随后获取这些文件并将它们安装到系统中。默认情况下，PHP 通常会安装在 Linux 的`/usr/bin`目录下。然而，你可以通过上面的`./configure`阶段指定`prefix`目录来选择安装位置。只需添加开关`--prefix=/path/to/dir`，其中`/path/to/dir`是你希望安装 PHP 的目录即可。如果你想在同一台机器上安装多个版本，这通常非常有用（尽管请注意这样做会有其他考虑因素）。请注意`make install`行必须以更高的权限（`sudo`）运行，以便将其文件复制到“特权”位置。

如果一切顺利，恭喜你，安装了 PHP！要检查是否安装了正确的版本并且可用，请在命令行中使用`php -v`，PHP 将显示当前版本号。如果你将 PHP 安装在搜索路径之外的位置，你需要指定完整路径，例如`/path/to/dir/php -v`。要检查安装了哪些扩展和其他选项，请在命令行使用`php -i`来运行`phpinfo()`函数。除了扩展信息（以及许多其他信息外），它还返回了使用`./configure`命令时的选项列表。这在重新安装 PHP 或尝试在另一台机器上克隆安装时（无法直接重用相同的二进制文件）非常有用。

如果一切不顺利，请仔细查看产生的错误。最常见的错误发生在你的系统没有安装为特定扩展的相关依赖项时。通常错误消息会显式说明这一点，但即使它只给出了一个提到扩展名称的模糊错误消息，最好的建议也是双检 PHP 手册中该扩展的安装部分，以找出确切需要哪些依赖项。缺少的依赖项通常可以使用系统的包管理器进行安装，而无需手动编译它们。你还应该检查在上面的配置阶段是否按要求提供了任何依赖项的位置。

如果所有其他方法都失败了，将准确的错误消息复制并粘贴到你喜欢的网络搜索引擎中，如果出现多个错误，可能从显示的第一个错误消息开始。有非常很多人编译过 PHP，大多数错误已经在网上遇到并记录下来了。不要让这些关于错误的话阻碍你尝试编译 PHP。你的配置得越复杂，发生错误的概率就越大，如果你对依赖项非常小心，通常可以完全避免它们。因此，请尝试使用默认选项进行简单的编译以熟悉操作，然后在此基础上进行！

关于安装的更多信息（主要关注 Web 服务器，但在其他方面也很有用）可以在 PHP 手册的[`www.php.net/manual/en/install.php`](http://www.php.net/manual/en/install.php)找到。

## 编译并安装额外的核心扩展

正如我们在上一节看到的，安装核心扩展的最常见方法是在编译主 PHP 安装期间在配置阶段启用相关标志（注意默认情况下，许多扩展会自动启用）。然而，稍后需要安装额外扩展并不罕见，例如当你的程序需求发生从初始设计的变化时。处理此问题有两种方法。第一种（你会在网上经常看到推荐这种方法）是从头开始重新编译/安装 PHP，在配置阶段添加新需要的模块（在执行`php -i`后以记住你第一次使用了哪些配置选项）。虽然这种方法效果完美，但编译完整的 PHP 二进制文件是一项工程，特别是对于老旧电脑来说可能需要很长时间才能完成。不过有一个捷径。

每个核心扩展实际上都是一个`.so`二进制文件，可以独立编译。要做到这一点，请遵循上一节中的第一步骤下载并解压 PHP 源码并进入该目录。如果你没有从编译的 PHP 本身中删除它，它应该已经准备就绪。源码内部有一个名为`ext`的目录，其中包含每个扩展的独立目录。

```
1 ~$ cd ext
2 ~$ ls
```

这将向你显示所有可用的核心扩展。例如，如果我们想添加`pcntl`扩展（本书用于守护进程软件），我们可以进入`pcntl`目录并按照我们在上一节中编译整个 PHP 包的方式仅编译/安装该扩展。

```
1 ~$ cd pcntl
2 ~$ phpize
3 ~$ ./configure
4 ~$ make clean
5 ~$ make
6 ~$ sudo make install
```

上述额外的命令`phpize`用于为扩展准备构建环境。在构建完整的 PHP 二进制文件时是不必要的，但在构建单个扩展时是必要的。如果你发现系统中没有`phpize`，它通常可以通过系统的包管理器通过`php-dev`软件包获得（例如在 Ubuntu 上，它作为`php5-dev`软件包中的`phpize5`提供）。关于`phpize`获取它的更多详细信息可以在[`us.php.net/manual/en/install.pecl.phpize.php`](http://us.php.net/manual/en/install.pecl.phpize.php)找到。

运行完上述命令后，你应该会发现一个`.so`文件（在我们的示例中为`pcntl.so`）已经编译并放置在 PHP 的扩展目录下。最后一步是告诉 PHP 它的存在，只需在你的`php.ini`文件的某处添加以下行：

```
1 extension=pcntl.so
```

如果你不确定`php.ini`文件在哪里，可以在命令行中运行`php -i | grep "Loaded Configuration File"`来查找。你也可以使用`php -i`来检查你的扩展现在是否已正确安装并可以使用。

## 安装多个版本的 PHP

某些情况下（特别是在开发机上），你可能想同时安装多个版本的 PHP，例如，当你需要部署给已经安装了 PHP 但可能使用不同版本的终端用户时。实现这一目标的一种简单直接的方法是创建一组虚拟机（我为此使用 VirtualBox），并在每台虚拟机上安装不同版本的 PHP。在这种情况下，你始终可以确切自己正在运行的是哪一个版本，并确保一个版本的安装和配置不会干扰另一个版本。这种方法的缺点是启动和关闭不同的虚拟机可能很慢（或者同时运行它们会消耗资源），而且如果你使用的是 Windows 等专有操作系统，可能会产生额外的许可费用。正如我在前面的章节中提到的，直接在同一台机器上安装并运行多个版本是可能的。然而，如果你不小心，要将这些版本及其依赖项分开，并确保始终知道自己正在使用哪个版本，可能会变成一场噩梦。因此，我不会在书中深入探讨。不过，下面是两位受尊敬的 PHP 社区成员写的文章，他们恰恰做了这些工作，可能会为你提供一些操作建议和涉及的陷阱提示。我建议在你尝试此之前，先彻底熟悉编译和安装 PHP、PHP 使用的文件和目录结构及位置，以及如何检查正在运行的是哪些版本的 PHP 和扩展。

所有问题和答案都根据主题标记了“标签”，以便你找到与你相关的内容。若要浏览标记有 PHP 标签的问题，请访问[`stackoverflow.com/questions/tagged/php`](http://stackoverflow.com/questions/tagged/php)。你也可以使用网站的搜索功能，在搜索词中添加`[tag]`以将范围缩小到仅包含 PHP 相关的答案。例如，如果你想搜索关于`date`函数的问题（该词在英语中是常用单词，也是许多编程语言中的常用函数名），请搜索`[php] date`以仅获取 PHP 特有的信息。

在编写本文时，有 864,182 个标记为`php`的问题，1,087 个标记为`php`且`command-line`的问题，以及 1,094 个标记为`php`且`cli`的问题。版主通常关闭关闭重复问题，所以从这些数字中你可以看到有大量的相关信息可用。

## 其他书籍

虽然你可能认为这是你需要的唯一一本 PHP 书籍，但我被告知市面上可能还有其他的 PHP 书籍。虽然我无法专门推荐任何书籍（除了我已经在相关章节中提到的那些之外），但如果你浏览任何大型书店，你会发现琳琅满目的 PHP 相关书目。如果你确实想购买另一本书，并希望支持 PHP.net 项目，请通过[`php.net/support.php`](http://php.net/support.php)书籍板块的链接进入一家知名书店，在你点击他们的链接后购买的任何物品，PHP.net 都将获得佣金。

## 新闻组 (Newsgroups)

PHP 有一组官方的新闻组，列在[`news.php.net/`](http://news.php.net/)上并进行归档，涵盖了广泛的 PHP 主题领域。这些可能值得浏览，而且有时可以对查询做出回应（尽管某些内部列表绝对不适合胆小的人看）。

## PHP Reddit 版块 (Subreddit)

reddit.com 上的 PHP “Subreddit”位于[`www.reddit.com/r/PHP/`](http://www.reddit.com/r/PHP/)，它是 PHP 新、观点、有用链接和求助的混合体。虽然这里通常非常有趣，并对问题提供有帮助的回答，但偶尔也能发现一些喷子以及无帮助/无礼的人。

## Github 上的 PHP

有时解决问题的最佳方法是查看其他人编写的类似代码。Github 作为流行的源代码托管网站，有大量的内容供你挖掘。你可以在[`github.com/search`](https://github.com/search)搜索所有代码仓库，并在搜索词中使用修饰符`language:php`将搜索结果缩小到使用我们最喜爱的语言的项目。如果你只想关注最近哪些 PHP 项目流行，可以查看[`github.com/trending?l=php`](https://github.com/trending?l=php)上的 PHP 趋势列表。
