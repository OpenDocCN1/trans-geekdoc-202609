# Countermeasures against Timejacking

To validate new blocks to the Blockchain, network time is used. A Timejacking attack occurs when an attacker writes incorrect timestamps, modifies the time clock of the node, and fools it into accepting a block from another Blockchain instead of one from its own. This is a fictitious attack. Boverman [5] provides the following solutions as

+   - Instead of using network time for timestamps, the node's system time is used.
+   - 70 to 140 minutes is the maximum initial attack timeframe.
+   - 70 to 140 minutes is the maximum initial attack timeframe. This time is cut in half, to 30 to 60 minutes, bringing the network node time down to around 30 minutes. This strategy will not be able to entirely eliminate attacks, but it will help to reduce them.
+   - Blocking untrusted peers and establishing a safe node can help to minimise the scope of an attack, however, it will not solve the problem of global problem related to time agreement.
+   - In order to accept a transaction, the number of confirmations required is being increased.

Time-jacking attacks are rare, so no new strategies to combat them have been devised. As it is always related to double-spending, the majority of double-spending security measures also hold products for time-jacking attacks.

# Countermeasures against Routing Attacks

There are numerous strategies for defending against routing attacks [6]. Multi-homed bitcoin is recommended since it makes it more difficult to conduct attacks when there are more connections. Attackers must either know both IP addresses or abort all cryptographic communication, which is easily discovered, in order to interrupt links between nodes. In the second approach, during the attack, the round-trip time (RTT) to hijacked destinations increases. A node could notice abrupt changes in the RTT towards its peers. As a protective strategy, the node will make random connections as a result of the outlier identification. Using another approach, UDP packets between nodes can also be updated regularly to identify if traffic has been withdrawn in part and in case it is connected to the network.
