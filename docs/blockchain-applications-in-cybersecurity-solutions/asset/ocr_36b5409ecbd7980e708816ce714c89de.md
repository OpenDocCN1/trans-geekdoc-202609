# Vulnerabilities in Contract Source Code

The parties signing the smart contract are at risk if the contract's source code is defective. For example, errors found in the Ethereum deal cost its owners $ 80 million in 2016. The re-entry attack, which is one of the most common vulnerabilities in Solidity, allows untrusted functions from other smart contracts to delegate control to them. Contract A calls a function from contract B, whose behavior during this attack is undefined. Contract B, on the other hand, may use the function of contract A for harmful purposes [33].

# Immutable Defects

Since blockchain blocks are inherently immutable, once a smart contract has been formed, it can no longer be changed. However, if there are errors in the code of a smart contract, they cannot be fixed either. As with the DAO attack, there is a risk that hackers could detect and steal ether or create a new fork, and take advantage of programming faults.
