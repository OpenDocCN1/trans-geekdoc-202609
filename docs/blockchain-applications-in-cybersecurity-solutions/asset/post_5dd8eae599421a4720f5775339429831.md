Users could encounter two different types of Byzantine failures, among which, the first one is entirely technical in nature. A slight technical error in the node could influence its functionality, and in certain cases, it might discontinue reacting or working in general. The other type of Byzantine failure is related to random node failure. In case of a random node failure, a node might exhibit the following traits:

- Replying with erroneous results
- Replying with intentionally ambiguous results for queries
- Replying to a single query with various results to various constituent parts of the system

## Proof-of-Burn (PoB)

PoB also expends minimum energy when compared to other consensus mechanisms [16]. PoB is a decentralized mechanism that involves removing the stakes from exchange to indicate that miners already reached an agreement. This removal process is referred to as burning. This serves to reduce inflation. PoB-based blockchain is used to authenticate transactions. PoB employs virtual mining rigs to authenticate transactions. PoB miners begin coin burning to display their contribution in the network and are permitted to mine. The number of coins burnt by a miner exhibits his virtual mining capacity. Higher mining power enhances the speed of determining new blocks. As a result, the miner is rewarded more. In PoB networks, the coins are addressed to a randomized eater address. This address is openly verifiable but unreachable. PoB is analogous to PoS in terms of using stakes for network protection. The main issue that needs to be considered is that the burned stakes are removed logically and not eternally which permits users to misuse them by peddling them to another one as the processor can still access them. PoB results in a scarcity of coins. PoB is a new consensus algorithm that is not tried on larger networks. However, PoB is sustainable and its mining is greatly decentralized.

### Proof of Elapsed Time (PoET)

In PoET, each user is assigned a random waiting time [17]. The user who waits for a longer time with earlier finish time will get a chance to generate the new block. PoET relies on the random waiting time assigned to the users and it has to ensure waiting time is assigned purely in a random fashion.

### Proof of Identity (PoId)

In PoId, the user’s private key is compared with a qualified identity [18]. This ensures that all transactions are embedded with the private key of the user involved in that transaction. In this way, every certified user is allowed to generate a new block and circulate it to all other users in the network. This helps to maintain the authenticity and integrity of the blocks. PoId is widely used in smart cities to authenticate the citizen's identity.

### Proof of Authority (PoAu)

PoS is customized in such a way that the identities of validators are at stake [19]. The validator’s identity associates credentials of individual with the organisation and then the combined credentials serve as the validator’s identity to authenticate the transactions. In this way, the reputation of validators is at stake in the network. PoAu allows only the validators to generate new blocks. Also, validators are responsible for maintaining and protecting the blockchain network. The number of validators is usually limited to less than 25.

The industries using blockchain use different consensus mechanisms in its business transaction, as a single mechanism will not satisfy all the stipulated specifications of the blockchain technology. As the specification of blockchain gets changed frequently in today’s digital world, any particular consensus mechanism is accommodated for an extended time duration. Consensus mechanism which is more efficient today, will not help much in the future. Hence the organisations that employ blockchain technology in their business must upgrade their consensus mechanism from time to time.

class Blockchain:

In the above code fragment, the parameter ts represents the timestamp that is used to store the time at which the block is created, the parameter record represents the information or transaction details that are stored inside the block and the parameter pHash represents the string that contains the hash of the previous block.

Intuitively, a hash represents the fingerprint of the main document. Each block consists of a unique hash value. The hash value of a particular block is computed by applying the hash function to all the contents of the block. The compute_Hash method is used for computing the hash of the newly generated block. ## Verify the Integrity of the Blockchain

Blockchains are great because once a new block is included in the chain, it is computationally difficult to alter its content without invalidating the remaining blocks present in the chain. The integrity of the blocks is validated using new method is_chain_valid() which is included in the Blockchain class. This method returns a true value when the blocks present in the chain are untampered otherwise it returns false value. The code for is_chain_valid() method is given below:

```python
def is_chain_valid(self, blockchain):
    previous_block = blockchain[0]
    block_index = 1
    while block_index < len(blockchain):
        block = blockchain[block_index]
        if block['previous_hash'] != self.hash(previous_block):
            return False
        previous_proof = previous_block['proof']
        proof = block['proof']
        hash_operation = hashlib.sha256(
            str(proof**2 - previous_proof**2).encode()).hexdigest()
        if hash_operation[:4] != '000000':
            return False
        previous_block = block
        block_index += 1
    return True
```
