Having the blockchain as the sole means of keeping track of all transactions in the system, the only way to manage funds is to keep track of those transactions. The only way to divide or aggregate funds is to spend them. A transaction can originate from more than one input address and output more than one address, meaning that a transaction can withdraw funds from more than one address and send funds to more than one address. Furthermore, each input is signed by the owner of the private key that corresponds to the address where the funds will be spent.

As part of a transaction, a voluntary fee can also be specified to cover the costs associated with the validation process. The purpose of this fee is to act as an incentive for users to participate in the consensus protocol that was previously mentioned. It is possible to see each output as a couple (amount, recipient address) in the context of a transaction. Inputs instead specify where to withdraw the funds, i.e., the previous transaction (through its hash) where the funds were created and where the funds will be withdrawn. In addition to the scripting language used in the Bitcoin protocol to specify conditions for the redemption of funds, Bitcoin's protocol uses a stack-based scripting language, which is not Turing complete.

Despite the fact that blockchain technology is mostly known for applications in cryptocurrencies [8], such as Bitcoin, it can be used outside of the monetary domain as well, for example, to trace the origins and transformations of products in a supply chain. Huckle et al. [9] discuss how blockchain can be used to create decentralized, shared economy applications that will enable people to monetize their things in a secure manner in order to become more wealthy. A study conducted by [10] notably notes that having a worldwide-available, verifiable, and untamperable source of data will enable anyone who wishes to offer trusted third-party services to do so in a cost-effective and robust way.

Most digital resources nowadays are exposed to the Internet, which necessitates a well-designed security framework that provides protection. Users with actual rights to access the information. There are systems that deal with access control specifically designed to deal with these types of situations, and they look after expressing the rights of subjects to access resources through the use of policies, which are then evaluated against the prevailing access context for each access request. Sometimes, authorization to perform access is continuously validated during the access, so that previously authorized accesses are interrupted as soon as these rights expire.

In the scientific literature, different types of control models have been proposed for defining different types of controls. One of the most popular ABAC schemes represents the access context through a set of attributes that describe their relevant characteristics in relation to the subjects, resources, and the environment, and the Access Control policies consist of a set of conditions over these attributes. It is possible for the Access Control systems to be deployed, managed and operated on the premises of the resource owners or by third parties trusted by the resource owners.

As a resource owner, the cost of maintaining an Access Control system can be a notable constraint. To avoid this cost, it is possible to outsource the evaluation of its security policies to external systems. For instance, over the last few years, a number of Access Control systems have been proposed and implemented as independent services on top of the Cloud following the Software as a Service (SaaS) paradigm. It is common for these services to use an open-platform API, so that users are not locked into using one specific implementation, and they can use them to have a uniform configuration for controlling all their resources with the same policy. As for the other Cloud services, each user pays for the usage of the Access Control Services on a per use basis.

## BLOCKCHAIN-BASED ACCESS CONTROL FOR IOT

According to the authors [11], the Blockchain is the mechanism used to generate and manage access tokens representing a subject's rights to access a resource. The model introduces a new type of subscription transaction. PCT (Policy Creation Transaction) and RTT (Right Transfer Transaction). The resource owner must first perform a transaction when the resource attributes comply with the individual access policies, in order to generate and transfer an access token. Access requests may be evaluated for approval by two different systems (the resource owner and the external authorization system). Both systems must interact for the process to be successful. An access token can also be passed from one subject to another in the second type of transaction. This process is called access delegation. Based on the XACML standard, an external authorization system is implemented using the Bitcoin platform to manage user access tokens.

Novo [12] provides a design for offering a decentralized access control system that is composed of a network of sensors that are operational in multiple parts of the world. Smart contracts are designed to reduce the amount of communication overhead between nodes in order to provide real-time, decentralized access control for the benefit of users. Since IoT devices are not capable of connecting to the Blockchain due to their limited capabilities, the architecture instead specifies a new component called a management hub which can request access control information on the Blockchain from IoT devices. There are also two types of Blockchain nodes defined by the system architecture, namely managers and agents. A manager does not participate in mining, and is considered a lightweight Blockchain node. A single smart contract is deployed by the agent node to manage the access control permission of IoT devices. This specific smart contract comprises all of the capabilities of an access management system in one package. As soon as an IoT device receives an access request, it sends the request to the hub, which is connected directly to a Blockchain node, for example, to a miner that works together with the smart contract to determine whether the requestor is authorized to access the resource. In a proof-of-concept implementation, Blockchain technology has been used as a distributed access management technology for IoT.

Researchers identified two primary problems with IoT access control in [13]. The first is that of centralized architecture, and the second has to do with handling static policies. Using machine learning algorithms in conjunction with a blockchain architecture, the authors propose a framework for ensuring complete distributed access control while managing dynamic access policies based on machine learning algorithms. Utilizing a Smart Contract concept, this framework implements a resource owner's (RO) access control policy to manage access to a resource that he owns. It is important to remember that in order for the Policy Contract to properly execute, the requester must meet policies regarding accessing the data in question, thus allowing the Policy Contract to generate and issue an authorization token allowing him access to the resource. Every time the Policy Contract is interacting with something; a transaction is generated, which is recorded in the Blockchain register. The resource owner will also receive feedback information about the system's current state after the contract is executed by using Reinforcement Learning (RL) algorithms. The feedback information can be used to dynamically improve security parameters such as trust and integrity. A Proof of Concept is required to validate the proposed model.

IoT Chain is a Blockchain-based architecture called by the authors in [14] for securing End to End access management to IoT resources. Resources that are stored on the resources servers will be encrypted and signed and will be stored on a proxy server that the owners of the resources will own. It is, therefore, the client who requests access to the protected resources on behalf of a third party. Upon requesting the decryption key, it checks the Blockchain to verify if the client has been authorized before requesting the decryption key.
