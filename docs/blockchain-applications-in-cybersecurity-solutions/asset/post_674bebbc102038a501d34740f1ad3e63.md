## Method 2:
The second method is Consensus-based, wherein the peer-to-peer network is followed [13]. Any participant can join the network. Each of the participants gets a full copy of the Blockchain. The Blockchain is distributed across different sites. Each authenticated device sends the block of data to all the peers of the network. More than 51 percent of the peers should validate the transaction, and then the block is added to the chain. In case of any modification of the data, recalculation of the hash and getting validation by more than 50 percent of the standard devices is very difficult.

### Encryption [14]:
Blockchain Technology uses Hashing. Hashing of the transaction uses mainly the SHA-256 algorithm to secure the data. The public key of the sender, the transaction information, and the receiver's address are encrypted by the SHA-256 algorithm to generate the fixed-length encrypted information. This process of verification done in the Blockchain is called Encryption. Each of the users in the Blockchain has a private and a public key. A private key is used to authenticate the user and to confirm the origin of the transaction is legitimate. The public key of the user is the key that is shared across the peer network for verification of the transaction.

### Verification of the sender
Once the Hash key or a message digest is generated, a digital signature is created, and along with the private key, a digitally signed document is created. The original message, digitally signed document and a public key are sent to the receiver. The receiver retrieves the hash value from the digitally signed document along with the shared public key of the sender compared with the hash value created at the receiver side by considering the original message.

### Proof of Work
Validation of the data is done by using a method called Mining [15]. The miners determine the nonce value, i.e., the random value combines it with the hash of the previous block, rehash the value, and compare this to the target hash. If the miners correctly determine the hash value and if it is less than the target value, the transaction is said to be validated by the user and the block is added to the Blockchain, and the transaction is processed. If one of the miners can determine the nonce value and decrypt the information. The other users can just validate the transaction so that the block is added to the Blockchain. The mathematical puzzle required to find the right nonce value such that the generated hash value meets the requirement, say it has to be less than the target value, requires an enormous amount of computation power as it has to be done using the Brute force method. And such an enormous amount of computation can be attempted only by standard users. As the nonce value is “Number only used Once”, Proof of Work is used to determine that the transaction done by the user is only once and is depicted in Fig. (7).

### Smart Contract
To have a more secure and automatic machine-to-machine transaction in IoT, a Smart contract is built over the Blockchain [16]. Smart Contract is an executable script that allows the automatic execution of multiple steps: the agreement to be met and the transaction to be carried over by all the peers in the network. It enables automatic transactions that are initiated by an action. Smart contracts built on Blockchain inherit the properties of Blockchain, hence will validate, capture and see that the agreement is met by multiple parties involved in the transaction without the need for a third party. Every device in the IoT gets a copy of the smart contract. On the receipt of an action to its address, a smart contract is executed. Ethereum provides the concept of smart contracts and Solidity (the programming language used to write these contracts) that enables decentralized applications. A low-latency and low-computation consumption protection model based on a smart contract has been researched [17]. Each node that has to send the block as a transaction in the network has to get registered in the smart contract. The smart contract issues a token that validates the transaction, and it is stored in the block. This token acts as proof of validity, and the block can be considered to be added to the Blockchain.

## RELATED WORKS
To preserve the privacy of the data generated by IoT devices, many authors have proposed many algorithms and techniques [18], proposing a hybrid approach that involves homomorphic encryption to encrypt the sensor data during the transmission and blockchain technology to maintain privacy. However, there is a storage overhead for this technique which can be resolved by maintaining only the hashes instead of the entire chain. Not only preserving the sensor data but Blockchain can also be used to preserve the privacy of medical IoT data [19]. proposed a four-layer architecture to provide security for the medical data which is retrieved from the IoT devices. The data generated is stored in the databases using blockchain technology; if the third party wants to retrieve the data, they have to use a smart contract that provides the authenticity of the user. This model could provide security but lacks efficient image retrieval systems and has storage overhead and computational complexity. To address the problems of extensive computational complexity, and storage overhead [20], proposed a modified blockchain framework that uses the cloud for storing the blocks generated, which in turn reduces the storage overhead. All the blocks that belong to one Blockchain are given a unique identifier which makes the retrieval process authenticated. The users or the doctors who want to access the data can send a request using the smart contract and the public key. In addition to the Blockchain, many cryptographic techniques were also implemented to provide security from different kinds of attacks. Similar to the above method [21], proposed a four-layered architecture that includes many technologies such as cloud for storage, Blockchain for privacy, and IoT for monitoring the health of a person. The data generated by these sensors are stored in the cloud using a NoSQL database and is hashed using blockchain technology which makes the retrieval process fast [22]. extended the usage of Blockchain to provide security to smart cities using mobile edge computing as every person has a mobile device with a cellular network area. This technique uses already existing mobile computing to generate the data and includes Blockchain to provide secure peer-to-peer communication [22]. Also proposed a similar framework for smart cities by storing the data in a blockchain to provide reliability, using somewhat homomorphic encryption for providing security, and machine learning algorithms to classify the data and use it for predictions. Most of the mentioned techniques provide security for the generated data, whereas, they have used blockchain technology to provide a reliable and secure platform to exchange the data between the device to device and the human to a device. In addition, many authors have used machine learning algorithms to classify the data into two categories: critical and non-critical, data before giving access to third-party servers. Extra security is provided by encrypting critical or non-critical data using different encryption algorithms.
