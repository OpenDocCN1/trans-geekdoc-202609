## Blockchain Clients for Participants

There are three different types of blockchain clients, each of which interacts with the blockchain ecosystem via application programming interfaces. The first sort of client is created in the information systems of the participants; this includes both management information systems and embedded systems. Smart contracts, or those given by the Blockchain operating systems, such as blockchain browsers, are the second type of client. The Blockchain's third form of the client is public facilities, which provide a public user interface for both participants and potential participants.

To support blockchain-based enterprises, data collection approaches are precarious. The data in a blockchain is intended to be private and self-regulated by the members, which poses a number of common data collection difficulties, including data insufficiency, data scarcity, and data redundancy. ## SECURITY ATTACKS ON SMART CONTRACTS

Despite the fact that smart contracts employ external resources such as the current library, other smart contract functions, API calls, and third-party services, they are vulnerable to programming faults, human mistakes, and malicious hacking. Several smart contract vulnerabilities have been discovered and rated as critical by researchers. Among the most critical are destructible smart contracts, unrestricted write operations, unrestricted fund transfers, integer overflow, integer underflow, re-entry, and external call issues. In recent years, these flaws have resulted in real hacks on smart contracts, with attackers profiting from massive amounts of stolen data.

Given that smart contracts are digital programmes written by humans, mistakes in programming and human error pose serious risks. The Ethereum blockchain's immutability prevents malicious modification and manipulation of smart contracts that have been deployed. However, this feature prevents smart contract owners or real developers from editing their code once it has been deployed. While running on the Blockchain, their active Ethereum smart contracts cannot be fixed if they have any errors. To ensure that smart contracts are precise and error-free, developers must carefully implement and test them.

Numerous open-source tools are accessible to analyse smart contract solidity source code or bytecode or contract address at Blockchain. Researchers submit the bytecode of smart contract applications to the selected analysis tools because all smart contract applications do not disclose their certified solidity code. Before any tools could be used to scan smart contracts with certified solidity source code, many compilation issues had to be fixed. Oyente is a security analysis tool that detects a parity multi-sig issue. Osiris, in particular, discovers a variety of arithmetic flaws, which are critical to verify in all smart contract applications. Mythril is a strong tool that scans for 14 different vulnerabilities related to solidity programming difficulties.
