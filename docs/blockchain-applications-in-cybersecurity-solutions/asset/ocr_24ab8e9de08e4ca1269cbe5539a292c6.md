# d. Transaction Verification Mechanism Attacks

# Double Spending Attack

Blockchains, unlike financial institutions, only confirm transactions after approval by all nodes in the network. The transaction is considered unverified until the block containing the transaction is verified. On the other hand, verification takes time, making it an ideal vector for cyber attacks. A typical blockchain attack using a transaction validation mechanism is twice as high. To be valid, all blockchain transactions need to be validated by users, which takes time. System latency can be used by attackers to mislead the system into utilising similar crypto-coins or tokens in repeated transactions [35].

# Finney Attacks

When the transaction is converted to a block, and another identical transaction is performed prior to that block being published prior to network exploration, the other same transaction becomes invalid.

# Race Attacks

When an attacker makes two mismatched transactions, it is called a racing attack. The money is sent to the victim in the first transaction. (and ships the merchandise, for example) before the transaction is verified. At the same time, the conflicting transaction is sent to the network, causing the attacker to return the same amount of bitcoins, effectively canceling the original transaction.

A malevolent miner constructs two nodes in this situation; one is just connected to the exchange node, while the other is connected to the blockchain network's well-connected peers. After that, the miner creates two transactions, one with a high value and one with a low value. The attacker makes preemption and then holds the lock from an exchange service that contains a high-value transaction. After an accident announcement, the attacker quickly delivers the precast block to the operator's service. He and some miners will confirm this transaction by treating the pre-mined block as the main chain.
