# Sybil Attack

When numerous identifiers are assigned to the same node, a Sybill attack is launched. There are no trusted nodes in blockchain networks, and each request is sent to many nodes. During Sybil attack, Multiple identifiers are assigned to the same node in the Sybil attack. Each request is forwarded to several nodes in blockchain networks since there are no trusted nodes. A hacker takes control of many network nodes during a Sybil assault. The victim is then surrounded by phoney nodes that finish all the victim's transactions. After a while, the victim becomes exposed to double-contribution assaults. Sybil assaults are difficult to detect and avoid, however, increasing the cost of creating a new identity, maintaining a certain level of trust to join the network, and determining user reputation can all help [24].

# Eclipse Attacks

An Eclipse attack necessitates a huge number of IP addresses or a sparse botnet for the hacker. The attacker then overwrites the addresses in the victim node's “attempted” database and waits for the victim node to resume. After restarting the target node, all outbound connections will be redirected to the attacker's IP addresses. This prevents the victim from obtaining transactions that they are interested in. Boston University researchers launched an eclipse assault on the Ethereum network, which they were able to achieve with only one or two workstations [25].
