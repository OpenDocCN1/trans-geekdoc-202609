## Privacy

Data protection and secrecy are crucial components of blockchain transactions because each node can access the data of another node, and anyone looking at the blockchain can see all transactions. Various studies have offered solutions to this challenge; however, these solutions are only useful for a limited number of applications and do not solve all problems. Owing to the huge amount of data transmitted, attackers can target network communications, including sensitive data, with attacks, such as Man-in-the-middle (MitM) and DoS / DDoS among the peer-to-peer structure from attacks.

Reducing the vulnerability of systems and software program is one manner to enhance system safety. Many safety projects are targeted at the want to reduce attack surfaces. When it involves software program safety, maintaining the attack surfaces of software program environments as minimum as feasible is critical.

Your programmes' attack surface now represents their vulnerability to attack, not their vulnerability to assault. In a data system, an attack surface refers to the virtual footprint, which comprises hundreds of assets, components, and controllers. In a software programme environment, the attack surface is the sum of all the many attack vectors through which unauthorised users or attackers can try to input or extract data from the environment.

Cryptocurrencies have a bigger attack surface than non-blockchain packages, which is concerning. Blockchain packages with attack surfaces are essential for cryptocurrencies, tokens, and smart contracts. To permit peer-to-peer transactions with virtual currency and ensure safety for users, blockchains rely upon secure software program code. As with their application-specific rules and peer-to-peer (P2P) networks, blockchains are steady in their practical use as a cryptographic construction, however liable to several attacks.

A blockchain community consists of nodes that create and run transactions and offer different services. For instance, the network is formed by using nodes that send and receive transactions and miners that append approved transactions to blocks. Cybercriminals search for network communication threats and make the most of them with the subsequent kinds of attacks.

### a. Blockchain Network Attacks

#### Transaction Malleability Attack

An attack on the malleability of the transaction aims to make the victim pay double. In blockchain network, a hash digest serves as a transaction identifier for each transaction. Before committing an original transaction, if attackers manage to change the ID of a transaction, you can try to send the transaction to the network with a modified hash and verify it before the original transaction [21]. If successful, the sender assumes the original transaction was unsuccessful, but the funds are still withdrawn from the sender's account. If the sender repeats the transaction, the same amount will be charged both times. Once both transactions have been validated by the miners, the hack is complete [22].

#### Routing Attack

The goal of this technique is to modify transactions before sending them to peers. Since the hacker is dividing the network into areas that cannot connect to each other, it is almost impossible for other nodes to notice this manipulation. Routing attacks are actually two different attacks.

- i. A partition attack that splits network nodes into different groups.
- ii. A delay attack interrupts the propagation of the message and transmits it to the network.

#### Sybil Attack

When numerous identifiers are assigned to the same node, a Sybil attack is launched. There are no trusted nodes in blockchain networks, and each request is sent to many nodes. A hacker takes control of many network nodes during a Sybil assault. The victim is then surrounded by phony nodes that finish all the victim's transactions. After a while, the victim becomes exposed to double-contribution assaults. Sybil assaults are difficult to detect and avoid, however, increasing the cost of creating a new identity, maintaining a certain level of trust to join the network, and determining user reputation can all help [24].

#### Eclipse Attacks

An Eclipse attack necessitates a huge number of IP addresses or a sparse botnet for the hacker. The attacker then overwrites the addresses in the victim node's “attempted” database and waits for the victim node to resume. After restarting the target node, all outbound connections will be redirected to the attacker's IP addresses. This prevents the victim from obtaining transactions that they are interested in. Boston University researchers launched an Eclipse attack on the Ethereum network, which they were able to achieve with only one or two workstations [25].

#### Long-range Attacks

These are directed at networks that use the proof of stake (PoS) consensus method, which allows users to mine or validate block transactions based on their asset in terms of the coin.

Three types of attacks can be distinguished:

1. Simple — when nodes don't check block timestamps, this is a simple version of the proof of stake protocol.
2. Posterior corruption — attempting to mint more blocks in a particular time frame than the main chain.
3. Stake leakage — duplicating a transaction from a properly kept ledger.

When initiating a remote attack, a hacker utilises a purchased or stolen private key from a big token balance that has previously been utilised for verification. The hacker can modify the blockchain's history and receive rewards based on PoS validation [26].

### b. User Wallet Attacks

In fact, when it comes to blockchains and cybersecurity, they are like salt and pepper. It may come as a surprise, but blockchain users are the most dangerous to security. People tend to overvalue the blockchain's security and overlook its flaws. Cybercriminals are mostly interested in user wallet credentials.

Hackers attempt to get wallet credentials using both old tactics, such as phishing and dictionary attacks, as well as more complex ones, such as identifying flaws in cryptographic techniques. Here's a rundown of popular ways to get into people's wallets [27].

#### Phishing

In 2018, iotaseed.io (now offline), a phoney online seed generator, was used to launch an attack on IOTA wallets. Hackers used this service to execute a phishing campaign and obtain logs, including secret seeds. As a result, hackers were able to steal more than $4 million worth of IOTA from victims' wallets in January 2018 [28].

#### Dictionary Attacks

During these attacks, a hacker tries to hash values of common passwords like password1 to decrypt a victim's cryptographic digest and salt. Attackers can find wallet credentials by converting clear text passwords to cryptographic hashes [29].

#### Vulnerable Signatures

Blockchain networks establish user signatures using a variety of cryptographic algorithms, but they may be vulnerable.
