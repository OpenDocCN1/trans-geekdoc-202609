# Chapter 4
Templating

At the moment we’ve got all of our code in one source file ( index.php). In our PHP web framework we want to separate our logic from the display. This will be more scalable and easier to maintain as our project gets bigger. It also means that designers can work on the templates separately without having to know any PHP code. We can also benefit from security features such as automatic escaping (filtering of dangerous content).

There are many template engines available as PHP packages^1. You (or your web designers) might have a favourite. You might want to use a specific template because it’s supported by other tools in your workflow. Mustache[13] is popular because it has implementations in almost every language, but some find it’s logic-less templates limiting. We will be using Twig[29] because it’s “flexible, fast, and secure.”

Let’s install Twig using Composer:

```
$ composer require twig/twig
```

The require section of your composer.json configuration file should now look like listing 4.1.

```
9 "require": {
10 "symfony/http-foundation": "^3.0", 11 "twig/twig": "^1.24"
12 }
```

# Listing 4.2: templates/index.html

The Twig website has a full reference for the template syntax[28]. Notice how it uses {{ and }}to delimit expressions. The content outside the delimiters is output as HTML. The expressions inside the delimiters are evaluated and their output inserted into the HTML. In this example the simple expression {{ name }}evaluates to the value of the provided name variable.
