# Routing

Now we are ready to implement a basic router. In the previous step we moved all the functionality into a run() method on our App class. The run() method takes a Request object as input, and returns a Response object. This is the foundation for all web apps, and all web frameworks have this basic functionality.

The limitation of our simple app (in it's current state) is that the functionality is hard coded into the run() method. We will need a way to route calls to different functionality depending on the request.

First let's try a simple router that uses the information in the request and the configuration in the data/menu.json file we created earlier. We get the requested path from the request using the getPathInfo() method:

```
$path = $request->getPathInfo();
```

Now we can alter the $content of the response by inspecting the $path variable. For example, by using a switch statement like this:

```
$content = ""; switch ($path) {
case '/':
case '/index':
$content = $twig->render('index.html', $Variables['index']);
break;
case '/about':
$content = $twig->render('index.html', $Variables['about']);
break;
}
```

This switch statement defines two different routes and the corresponding code for each. We will come back to this, but you may already see ways to improve this. In our run() method we then just need to wrap the $content in a Response and return it. We also do an error check and return a 404 when the path was not matched:

```
if (empty($content))
{
return Response::create("Not found", 404);
}
return Response::create($content);
```

You can confirm this works by trying each one of these URLs:

+   * http://localhost:4000/
+   * http://localhost:4000/index
+   * http://localhost:4000/about

Also, try loading a URL that does not have a route defined and check that you get a 404 error:

```
http://localhost:4000/contact
```
