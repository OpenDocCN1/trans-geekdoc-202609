# Testing

Now that our controllers are independent, they should be easier to test. Let’s try this out by revisiting our simple test.php script. Listing 8.1 shows how the functionality of the controller can be tested separately. We’re not testing the dependencies, so we create fake (simplified) versions of the dependencies and pass them in to the controller. We do this for all the scenarios we want to test our controller against.

```
1 <?php
2 use Weekend\Controller\BasicPageController;
3 require_once 'vendor/autoload.php';
4 $templates = [
5 'index.html' => '{{ title }}',
6 ];
7 $twig = new Twig_Environment(
8 new Twig_Loader_Array($templates));
9 $menu = ['test' => [
10 'title' => 'Hello World!',
11 'content' => 'Test content'
12 ]];
13 $Controller = new BasicPageController($twig, $menu); 14 $output = $controller->get('/test');
15 if (strpos($output, "Hello World!"))
16 {
17 echo "Test passed!", PHP_EOL;
18 }
```

# Listing 8.1: test.php

This is a simple example, and in reality you would probably use a testing framework. PHPUnit is a popular testing framework and provides a mechanism to create fake objects (or Mocks, as they’re called in testing) to use as dependencies. Many PHP packages come with adapters and plugins to use as dependencies in tests. For example, the Flysystem package we are using as a filesystem abstraction provides a Memoryand a Nulladapter that you can use to create fake filesystems in your tests.
