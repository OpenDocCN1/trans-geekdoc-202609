# # Template Inheritance

Remember when we added the contact form, and we had to change the output of {{ content }} to {{ content | raw }}? We did this because we rendered the form template and then passed this into our page template in the content variable. Twig has the rawfilter to bypass it’s automatic filtering and escaping. This is an important security measure, so ideally we don’t want to disable it.

We could create separate HTML page templates, one for our basic page controller, and one for our contact page, but this introduces unnecessary duplication. We want to be kind to our future selves and think about maintenance. When we come back in the future to update our design, we want a single place to make those changes. This can be achieved by putting all the common code into a single template, then extending this template to create custom versions when we need to do something different.

To show how this works we first change our main index.html to be a parent template that others can inherit from. To do this we define Twig blocks that can be customised. Lines 20-23 of listing 9.3 define a content block. We then create a new template file called basic.html that extends index.html. This is shown in listing 9.4. There is very little in this template because we don’t have to recreate the whole page. This template reuses the HTML from the index template, except with the region defined by {% block content %} replaced with it’s own content block. Don’t confuse the two uses of the word content in the basic.html template. We have a block called content, and an output variable called content. The block refers to the content block from the parent template that we are replacing. The variable refers to the content variable that is passed in to the template.

Listing 9.5 shows a new template created for the contact page. This also extends the main index template. We redefine the content block again, but this time include the form instead of printing the content variable.

Listings 9.6, 9.7, and 9.8 show the updates required to the controllers to output using the new templates.
