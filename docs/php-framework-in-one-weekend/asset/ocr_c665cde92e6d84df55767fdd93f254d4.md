# Using a DI Container

We will configure a dependency injection container to create objects and their dependencies when we request them. Doing this means that our objects will only get instantiated when they are needed, and make the calling code easier to write as we will be able to just create objects, without worrying about instantiating dependencies first.

We will use the Symfony Dependency Injection container and a YAML configuration file. Use the Composer requirecommand to install these PHP packages as dependencies:

```
$ composer require symfony/dependency-injection $ composer require symfony/config
$ composer require symfony/yaml
```

We can now remove the _global services_ we created in App and replace them with the Container:

```
protected $container;
public function __construct() {
$this->container = new ContainerBuilder(); $loader = new YamlFileLoader($this->container, new
FileLocator(__DIR__));
$loader->load('services.yml');
}
```

This code uses a YamlFileLoader to load up a configuration file where our _service_ definitions are stored. Listing 8.2 shows the services.ymlconfig file for our example. The format of this file is defined by the Symfony DI container. It allows you to specify a parameters section, and a list of services. The services are the objects that the container knows how to build. The configuration for each one specifies which class is used, and what arguments are needed for it's constructor. These can reference other services (dependencies) or configuration from the parameters section.

```
1 parameters:
2 template_dir: '../templates'
3
4 data_dir: '../data'
5
6 services:
7 loader:
8 class: Twig_Loader_Filesystem
9 arguments: ["%template_dir%"]
10 twig:
11 class: Twig_Environment
12 arguments: ["@loader"]
13 adapter:
14 class: League\\Flysystem\\Adapter\\Local 14 arguments: ["%data_dir%"]
15 filesystem:
16 class: League\\Flysystem\\Filesystem 17 arguments: ["@adapter"]
```
