from typing import List

import tensorflow as tf

def tf_ragged_range(n: tf.Tensor, pad=-1, flatten=True, dtype=tf.int64):
    """Implement ragged matrix using a dense matrix with paddings."""
    # Find the maximum length
    n = tf.cast(n, dtype)
    pad = tf.cast(pad, dtype)
    max_n = tf.reduce_max(n)
    # Construct and repeat arange
    r = tf.expand_dims(tf.range(max_n, dtype=dtype), axis=0)
    # Masking with broadcasting
    mask = r >= tf.expand_dims(n, axis=1)
    r = tf.where(mask, pad, r)
    # Flatten
    if flatten:
        # Flatten
        r = tf.reshape(r, (-1,))
        # Remove padding values
        r = tf.boolean_mask(r, r != pad)

    return r

### 5.3.3 Length Regulator Module of FastSpeech2

In a typical text-to-speech (TTS) application, a sequence of bytes or strings is converted into a time series of waveforms. This is the sequence-to-sequence problem in machine learning, where the sequential representation of a certain information modality is converted into another sequence, sometimes in another modality. Classic approaches to solve the TTS problem were using auto-regressive modeling (e.g. Hidden-Markov Model [Zen et al., 2007] and WaveNet [van den Oord et al., 2016]), where prompt waveforms and contexts are used to generate subsequent new speech waveforms. On the other hand, non-auto-regressive approaches like FastSpeech/2 [Ren et al., 2019, 2020] use sequence-to-sequence (seq2seq) learning, where the input texts are converted into audio signals using only one pass.

One problem with the seq2seq learning approach between two different information modalities is that the input and output sequences may represent information at different densities and lengths. For example, a sentence like “I love machine learning” uses an array of 4-string tokens to form the full text, but it may require ~2 seconds of 16 kHz single-channel audio, or an array of 32,000 float32 numbers to encode the speech signal. Depending on the words in the text, a sentence containing only four words may correspond to audios made up of either several thousands or tens of thousands of float32 values (“I love machine learning” vs. “How to pronounce Supercalifragilisticexpialidocious”); and depending on the speaker, the same sentence “I love machine learning” may be spoken under a second, or stretched over tens of seconds (e.g. “I looooooooooove machine learniiiiiiiiing”). This is the so-called many-to-many mapping problem.

FastSpeech2 proposed the Length Regulator module to solve the many-to-many mapping problem. During training time, tokens of the text are passed through the embedding layer which encodes the words in the sentence as a sequence of embedding vectors, forming the tensor [batch_size, seq_len, emb_size], where seq_len here can be a variable sequence size and is the length of the longest sentence in the batch. The corresponding speech audio signals (1D vectors) are converted into 2D mel-spectrograms via Fourier Transform, forming a tensor of [batch_size, time_length, num_channels], where time_length here can be variable and is the length of the longest audio in the batch, measured as the number of time steps or frames of the temporal domain of the mel-spectrogram. It is easy to observe that seq_len != time_length. However, we have the following observations on the TTS data:

- 1. Each word is pronounced one after another.
- 2. Each word takes a certain amount of time to pronounce with durations independent of each other.
- 3. The sum of the time to pronounce all the words in a sequence should equal to the final audio length.

Each token in the sentence is first passed through an embedding layer to create an embedding vector. We also assume that each token is represented by one embedding vector, but may correspond to multiple (or at least 1) time-steps in the mel-spectrogram which we know from the dataset labeling process. With these observations and assumptions, the Length Regulator module serves as an adaptor to repeat/tile the token embedding vectors over the period of pronunciation in the mel-spectrogram. For a batch of variable-length text inputs, the Length Regulator module will then return a tensor of shape `[batch_size, time_length, num_channels]` and a corresponding binary mask for masking out the paddings later on. We will leverage the knowledge of indexing and scattering to implement the vectorized Length Regulator module.
