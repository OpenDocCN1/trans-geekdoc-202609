## 2.11 Broadcasting

**Broadcasting** is an element-wise operation on a pair of tensors of different dimensions [Harris et al., 2023c]. The tensor of the lower dimension is as if repeated many times to match the size of the higher dimensional tensor. For a simple example, a scalar (0-dimensional tensor) and a vector (1D tensor) can be added together via broadcasting, as shown in Figure 2.6.

Notes:

- Views: An important concept in NumPy's reshape is the concept of "views". Instead of making a copy of the array with the new shape, NumPy can figure out a smart way to map the elements from the original array to the new array via "views" [Harris et al., 2023b]. This reduces the memory trace of the program by storing the data only once. Well-known operations that return views instead of copies include np.reshape and np.transpose (as well as slicing operations which we will introduce in Chapter 3). Tensorflow does not specifically mention the concept of view, but the tf.reshape operation also reuses the underlying data buffer rather than making a copy of the data according to their documentation [Abadi et al., 2023c]. PyTorch also has similar concepts about views and copies. Therefore, when appropriate, it is more preferred to use Tensor.view(shape) method to reshape the tensor rather than using torch.reshape (in the latter case, a copy of the tensor with the new shape is returned, contrasting np.reshape).

- Order: Another important concept, order, is related to how the underlying tensor data is represented in the memory (RAM). There are typically two conventions in data ordering in memory: row-major (order="C" as in the C language) or column-major (order="F" for Fortran). Consider, for a 2D matrix, the row-major representation will store elements along the rows of the matrix next to each other, while the column-major representation will store elements along the columns of the matrix next to each other (see Figure 2.5); typically, RAM does not have the concept of shape when it stores data. This matters for the sake of computational efficiency. Suppose we would like to sum together all the elements in a single row. It would be faster to look up the values needed to be combined by reading contiguous elements along the registers; in contrast, it would be slow to sum these numbers together if it needs to constantly skip elements and read more elements along the memory register until all needed elements are gathered. More concretely, in the example provided in Figure 2.5, it would be faster to compute the sum of the rows in a row-major (C) representation of the matrix (i.e. summing together, [1, 2, 3, 4], [5, 6], [7, 8, 9]) than summing together the rows in a column-major (F) representation of the matrix (i.e. summing together, [1, 4, 7], [2, 5, 8], [3, 6, 9]).

b) squeeze and expand_dims (a.k.a unsqueeze) are a pair of reciprocal operations. squeeze removes the singleton dimension (dimension or axis of size 1), e.g.(3,1,2)--> squeeze -->(3,2). In contrast, expand_dim unsqueeze adds a singleton dimension, e.g. (3,2)--> unsqueeze -->(3,1,2). Note that NumPy and Tensorflow call the dimensions axis (or axes when used plurally, while PyTorch calls the dimensions dim (or dims when used plurally). Using slicing notations, we can also expand the dimensions using None or np.newaxis. For example, a tensor of shape (3, 2) to be converted to shape (3, 1, 2) can be implemented in two ways:

```
import numpy as np
X = np.random.rand(3, 2)
# using expand dims
y1 = np.expand_dims(X, axis=1)
# using None slicing
y2 = X[:, None, :]
# using np.newaxis
y3 = X[:, np.newaxis, :]
```

Similarly, squeezing a dimension can also be implemented by slicing

```
import numpy as np
X = np.random.rand(3, 1, 2)
# using squeeze
y1 = np.squeeze(X, axis=1)
# using slicing
y2 = X[:, 0, :]
```

We will discuss more on slicing operations in Chapter 3. Note that slicing is less preferred in Tensorflow implementations than the squeeze and expand_dims operations, as it sometimes may not be compatible with the graph execution.

c) The atleast_nd functions help ensure the inputs are of the expected shape. These operations are often helpful when we need to perform broadcasting operations (i.e. element-wise operations between lower and higher dimensional tensors), which we will discuss in the upcoming section. They are somewhat equivalent to and are often used as shortcuts for the expand_dims operations. Suppose we would like a scalar value to be at least three-dimensional. Then, we can either implement using expand_dims as

```
import numpy as np

x = np.array(6)
y = np.expand_dims(x, axis=0) # np.array([[6]])
y = np.expand_dims(y, axis=0) # np.array([[[6]]])
y = np.expand_dims(y, axis=0) # np.array([[[[6]]]])
```

Or simply as

```
import numpy as np

x = np.array(6)
y = np.atleast_3d(x) # np.array([[[6]]])
```

One nice feature about these functions is that we do not need to know beforehand how many expand_dims operations we need to make before reaching the desired number of dimensions. So in the above example, by using np.atleast_3d, I can also let the input x = np.array([6]) without modifying any subsequent code to ensure the shape of y to be always at least three-dimensional, which gives the input shape a lot of flexibility. On the other hand, the name atleast suggests that, when the input x is of a higher dimension, all the dimensions will be kept as is:

```
import numpy as np

x = np.array([[[[[6]]]]]) # 5-dimensional
y = np.atleast_3d(x) # still 5-dimensional
```
