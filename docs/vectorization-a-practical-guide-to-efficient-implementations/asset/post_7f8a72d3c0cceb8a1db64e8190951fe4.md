
such as generative pretrained transformer (GPT) [Radford et al., 2018], decoder architecture specifically refers to a transformer block that has only one causal attention layer.

More often than not, subsequent transformer-based models may use only either the encoder or decoder part of the transformer for specific tasks. For instance, bidirectional encoder representation from transformers (BERT) [Devlin et al., 2019] is an encoder-only pretrained language model from Google. Many sequence representers also tend to use encoder architecture, e.g. FastSpeech2 and Whisper, whose hidden states are then decoded by downstream architectures that may not necessarily be a transformer block, e.g. convolutional layers. By contrast, the GPT model family uses decoder-only architecture, where causal attention is used. The choice of specific architecture is tightly associated with the training tasks used by different models, which we will discuss in Section 11.5.

## 11.1.2 Training of Transformer Models

Self-supervised pretraining has been an effective technique in building models solving NLP tasks. Researchers would gather a large text corpus with billions to trillions of tokens to build models that “understand” text so that they can be fine-tuned downstream to solve NLP-specific tasks like text classification or sentiment analysis, which usually has less human-labeled data available. What they typically do is pretraining the model using the “Cloze” task (i.e. fill in the blank) [Devlin et al., 2019], in which a word in a sentence is blanked out, and the model learns to predict the word in the blank. It is said that the model learns via a self-supervised fashion, where the data used to generate both the input and the label come from the same sentence, without a human deciding what the inputs and the labels are. Indeed, text data are “self-labeling” (as explained by Yann Lecun). Similar to text data, time series or time-associated events data are also self-labeling. Let’s say, we can use the last seven days of historical data to forecast the next event, e.g. whether or not it is raining tomorrow. At the inference time, we do not know what tomorrow’s weather is going to be, so we do not have the label at the moment. But, we only need to wait to see the weather on the next day, and the label is automatically generated, without a human deliberately deciding what it is.

Going back to the context around NLP, the BERT model that uses encoder-only transformer architecture with bidirectional attention is trained using the Cloze task. The goal of BERT is to learn a sequence representation, such that it can be used in downstream tasks that would utilize the entirety of the sentence inputs. The Cloze task is an auxiliary task for the model to comprehend a full sentence. By contrast, the GPT model that uses decoder-only transformer architecture with causal attention is trained to predict the next token. The goal of GPT is, as the name suggests, to generate new tokens given an input prompt, in contrast to predicting a token in the middle of the sentence. Therefore, GPT will never see any future tokens during generation, so it needs to learn to predict the ordering of the tokens rather than representing a full sentence. Therefore, different training objectives can dictate different model architecture decisions in a model.

## 11.2 Pre-LN vs. Post-LN Transformer

Ever since the original transformer paper, various improvements to the architecture have been suggested to further enhance the learning capacity and training stability of the model. For the rest of the chapter, we will introduce various improvements made to the transformer model, which led to what is currently considered to be the strongest recipe for transformer, called Transformer++ [Gu and Dao, 2023] or LLaMA [Touvron et al., 2023a].

One significant caveat about the original transformer architecture is that the training of the model can become unstable, where the loss can diverge. To address this issue, the original transformer paper used a learning-rate schedule during model training, specifically

$l_{rate} = d_{model}^{-0.5} \cdot \min(\text{step}^{-0.5}, \text{step} \cdot \text{warm-up\_steps}^{-1.5})$

where

- step is the number of training steps
- $d_{model}$ is the embedding size of the tokens
- warm-up_steps is the number of steps used for a linear ramping-up period, which the original paper set to 4000.

The learning rate curve is plotted in Figure 11.1, with the accompanying implementation in NumPy below:

```python
import numpy as np
import matplotlib.pyplot as plt

# learning rate schedule
d = 128 # d_model
step = np.arange(160_000)
warmup_steps = 4000
lr = (1/np.sqrt(d)) * np.minimum(1/np.sqrt(step), step * warmup_steps**-1.5)

fig, ax = plt.subplots(1, 1, figsize=(10, 4))
ax.plot(step, lr)
ax.set_xlabel("Step")
ax.set_ylabel("Learning Rate")
```

**Figure 11.1** Learning rate schedule from the original transformer paper.

However, many researchers still found that they need to carefully tune the learning rate for their specific tasks. Techniques used in the transformer model such as normalization and skip connections are known to address the problem of either an exploding or vanishing gradient, which is crucial for model training stability and convergence, yet these problems still exist. Hence, Xiong et al., 2020 proposed an alternative arrangement of the layers within the transformer block [Xiong et al., 2020]. They call it Pre-LN architecture, to distinguish it from the original architecture which they call Post-LN. A comparison of the two architectures is illustrated in Figure 11.2. The key difference between the two architectures is that the original Post-LN architecture performs attention and feedforward operations and then normalizes their outputs, whereas Pre-LN architecture starts with layer normalization on the inputs. With this change, Xiong et al., 2020 demonstrated that the transformer can be trained more stably without the use of a learning-rate schedule with a warm-up period, hence significantly improving the training efficiency of the transformer model by allowing faster convergence. I have seen many domains of study still use Post-LN with a learning-rate schedule in their neural architecture design. If trained successfully, the Post-LN architecture almost always outperforms that of Pre-LN architecture, especially in certain areas such as text-to-speech.

Post-LN architecture places the layer normalization between the residual blocks (indicated by "+" in the diagram), whereas Pre-LN architecture places layer normalization inside the residual blocks. ```python
import torch
from torch import nn

class PreLNEncoderBlock(nn.Module):
    def __init__(self, embed_dim, ffn_size, num_heads=2, dropout=0.1):
        super().__init__()
        self.mhattn = nn.MultiheadAttention(
            embed_dim=embed_dim,
            num_heads=num_heads,
            dropout=dropout,
            batch_first=True,
        )
        self.ffn = nn.Sequential(
            nn.Linear(embed_dim, ffn_size),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(ffn_size, embed_dim),
        )
        self.input_ln = nn.LayerNorm(embed_dim)
        self.ffn_ln = nn.LayerNorm(embed_dim)

    def forward(self, x):
        y = self.input_ln(x)
        y, _ = self.mhattn(y, y, y)
        y += x

        z = self.ffn_ln(y)
        z = self.ffn(z)
        z += y

        return z


class PostLNEncoderBlock(nn.Module):
    def __init__(self, embed_dim, ffn_size, num_heads=2, dropout=0.1):
        super().__init__()
        self.mhattn = nn.MultiheadAttention(
            embed_dim=embed_dim,
            num_heads=num_heads,
            dropout=dropout,
            batch_first=True,
        )
        self.ffn = nn.Sequential(
            nn.Linear(embed_dim, ffn_size),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(ffn_size, embed_dim),
        )
        self.input_ln = nn.LayerNorm(embed_dim)
        self.ffn_ln = nn.LayerNorm(embed_dim)

    def forward(self, x):
        y, _ = self.mhattn(x, x, x)
        y += x
        y = self.input_ln(y)

        z = self.ffn(y)
        z += y
        z = self.ffn_ln(z)

        return z
