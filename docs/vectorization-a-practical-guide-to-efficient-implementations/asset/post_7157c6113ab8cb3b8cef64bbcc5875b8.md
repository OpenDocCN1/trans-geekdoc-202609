- length: Instead of specifying the start and end indices, specify the length of each segment in the sequence. The lengths of the segments needs to be nonnegative. So, it is possible to create segments with zero lengths, e.g.

```python
import torch
data = torch.tensor([1, 2, 3, 2, 5, 4, 7, 2, 8, 3], dtype=float)
lengths = torch.tensor([3, 3, 0, 4])
rea_torch = torch.segment_reduce(data, "sum", lengths=lengths)
# tensor([ 6., 11., 0., 20.], dtype=torch.float64)
```

At the time of writing, PyTorch's torch.segment_reduce operation is only implemented for float dtype arrays.

- Segment id: Tensorflow's segment operations as well as PyTorch's scattering operations use this strategy. Instead of explicitly inferring the segments based on the intervals between the start and end indices, segment ids specifically label which group a segment belongs to. Here, the segment_id input is treated as the group key. This can be advantageous because we can then use operations that do not necessarily have all elements of the same group arranged next to each other before aggregation. Tensorflow implements three variants of segment aggregation operations, which assume the first axis(axis=0) is the segment dimension to be aggregated.
  - tf.math.segment_sum: This operation still assumes that the values of the same segments are adjacent to each other. It requires the segment ids to be sorted. The integer values can be skipped to create 0-length entries between segments as the last segments can be skipped to create 0 entries between the segments with lengths greater than 0; it can also create 0-length entries as the last segments by specifying the num_segments argument. Negative segment ids will be ignored. PyTorch's scatter_reduce operation can be viewed as the equivalent operation to
  - tf.math.unsorted_segment_sum: This operation does not assume the values of the same segments are adjacent to each other. That is, the elements of each segment can be scattered around. The integer values can be skipped to create 0 entries between the segments with lengths greater than 0; it can also create 0-length entries as the last segments by specifying the num_segments argument. Negative segment ids will be ignored. PyTorch's scatter_reduce operation can be viewed as the equivalent operation to
  - tf.sparse.segment_sum: The previous two operations require the number of segment ids to be equal to the number of elements in the first dimension of the data input. This operation takes an additional argument indices, which is paired with segment_ids to extract the elements from the data input by group. Suppose we have data = [1, 2, 3, 4, 5] and grouping ids [0, 0, 1, 1, 1]. If we specify indices = [0, 1, 2, 3, 4], then this is equivalent to using tf.math.segment_sum or tf.math.unsorted_segment_sum, obtaining [3, 12], which is from [data[0]+data[1], data[2]+data[3]+data[4]], or [1+2, 3+4+5]. But, if we specify indices = [0, 1, 2, 3, 0], then we will obtain [3, 8] which is from [data[0]+data[1], data[2]+data[3]+data[0]], or [1+2, 3+4+1]. Similar to tf.math.segment_sum, negative segment ids will throw an error.

b) NumPy does not implement a groupwise mean function. This is probably because the mean operation is technically not an element-wise reduction operation, as it not only needs to track the sum but also the total number of elements within each group. However, an easy workaround is to utilize `np.add.reduceat` to implement the equivalent function, where we compute the groupwise sum first, and then count the number of elements within the group by summing together an indicator array of 1s. The implementation is as follows:

```python
import numpy as np
def np_mean_reduceat(arr, indices, **kwargs):
    # Compute groupwise sum
    gsum = np.add.reduceat(arr, indices, **kwargs)
    # Compute groupwise count
    indicator = np.ones_like(arr)
    gcount = np.add.reduceat(indicator, indices, **kwargs)
    # Compute mean
    return gsum / gcount
```

c) Tensorflow does not implement the tf.sparse version of the segment multiplication operation. But it is possible to work around this by performing segment addition of log values, then raising back to the exponent (with some sacrifice on numerical precision), i.e.

```python
import tensorflow as tf

def tf_sparse_segment_prod(data, indices, segment_id, num_segments=None) :
    # take log values
    data_out = tf.math.log(tf.cast(data, tf.float32))
    # Segment sum of log
    data_out = tf.sparse.segment_sum(
        data_out, indices, segment_id, num_segments
    )
    # Raise back to exponents
    data_out = tf.exp(data_out)
    if data.dtype in (tf.int32, tf.int64):
        data_out = tf.round(data_out)
    data_out = tf.cast(data_out, data.dtype)
    return data_out

data = tf.constant([1, 2, 3, 2, 3, 6, 3, 4])
indices = tf.constant([0, 1, 2, 3, 4, 5, 6, 7])
segment_id = tf.constant([0, 0, 0, 1, 1, 1, 2, 2])
data_out = tf_sparse_segment_prod(data, indices, segment_id)
# <tf.Tensor: shape=(3,), dtype=int32, numpy=array([ 6, 36, 12], dtype=int32)>
```

d) segment_sqrt_n is a special function that was motivated by previous natural language modeling studies that attempted to summarize embeddings of tokens within a sentence, i.e. representing a sentence as a bag of words (e.g. pretrained feed-forward Neural-Net Language Model, or NNLM [Bengio et al., 2003], from TFHub [Google, 2023]). These studies found that taking the square root of the sum of the embeddings is more effective in representing sentences than averaging the embeddings of the tokens together. Similar to the groupwise mean reduction solution, this can also be implemented using np.divide.reduceat in NumPy or torch.scatter_add in PyTorch. We illustrate an implementation in the following code block using PyTorch:

```python
import torch

def torch.scatter_reduce_sqrt_n(arr, segment_ids, **kwargs) :
  # Initialize accumulators
  numerator = torch.zeros(segment_ids.max() + 1)
  denom = torch.zeros_like(numerator)
  # Compute groupswise sum
  gsum = numerator.scatter_add_(0, segment_ids, arr)
  # Compute groupwise count
  indicator = torch.ones_like(arr)
  gcount = denom.scatter_add_(0, segment_ids, indicator)
  # Compute the sum / sqrt_n
  return gsum / torch.sqrt(gcount)
```

e) These operations compute the segment-wise minimum and maximum values. A caveat with the Tensorflow operations using unsorted segment ids, i.e. tf.math.unsorted_segment_max and tf.math.unsorted_segment_min, is that if we skip over some integer ids with the intention to create zero entries, we will find that these skipped entries will have -∞ (e.g. 3.4028235e+38) or +∞ (e.g. +3.4028235e+38) filled, respectively, instead of having zeros. So, care needs to be taken when using these operations.
