More recent versions of tree-based model libraries like LightGBM and XGBoost can handle pd.Categorical features directly without the need to create further index lookups. This is another advantage of using pd.Categorical when working with machine learning models.

# 6.4.3 Scikit-learn sklearn.preprocessing.LabelEncoder

None of the encoding methods we have discussed so far allow us to easily reuse the mapping between the string value and the indices, a requirement when making inferences on new data during production. The sklearn.preprocessing.LabelEncoder class allows us to create and save the mapping for later use.

```
```python
from sklearn.preprocessing import LabelEncoder
vocabulary = [chr(ii+97) for ii in range(26)]
feature_train = ["b", "a", "c", "d", "z"]
# Create the encoder
feature_lookup = LabelEncoder()
feature_lookup.fit(vocabulary)
# Transform during training
index_train = feature_lookup.transform(feature_train)
# array([1, 0, 2, 3, 25])
# New data during inference
feature_test = ["f", "g", "a", "b", "h"]
index_test = feature_lookup.transform(feature_test)
# array([5, 6, 0, 1, 7])
```
```

Notice that both feature_train and feature_test features have the string value a and b in them. The corresponding index_train and index_test indices are both 0 and 1, respectively. This demonstrates that sklearn.preprocessing.LabelEncoder can (re)produce consistent string value to index mappings.
