Note `np.s_` also supports convenient construction of slicing configurations of multiple dimensions, with the syntax `np.s_[start_0:stop_0:step_0, start_1:stop_1:step_1, ..., start_n:stop_n:step_n]`. This will return a tuple of `slice` objects, e.g. `(slice(start_0, stop_0, step_0), slice(start_1, stop_1, step_1), ..., slice(start_n, stop_n, step_n))`. To clarify, I have overloaded the ellipsis ... symbol here and it carries two meanings here:

- I intend the ellipsis “...” here as a notation to indicate there may be a variable number of dimensions when constructing the slices.
- However, putting the ellipsis operator `...` in the `np.s_` method is also valid here, which indicates that the slices across the omitted dimensions select all items within the dimension. This is just how ellipsis operator is being used previously. When `...` is used to construct multidimensional slices, the elided dimensions will be represented as Python's `Ellipsis` constant, e.g. (`slice(start_0, stop_0, step_0)`, `slice(start_1, stop_1, step_2)`, `Ellipsis`, `slice(start_3, stop_3, step_3)`).

Once we have built the `slice` configuration object, we can apply the slicing logic the same way as we did before, e.g.

```
import numpy as np
X = np.random.rand(5, 8, 6)
Y = np.random.rand(3, 9, 7)
Y
# Build the slice object
s = np.s_[:4, 2:4, 5:]
# Shape may not necessarily be identical
print(X[s].shape) # shape (4, 2, 1)
print(Y[s].shape) # shape (3, 2, 2)
```

You may notice that the first dimension of tensor Y is of size 3 but we are slicing four items. Yet, the program did not throw an error, and returned three items in the first dimension, less than the four items asked by the slice. In general, Python’s tensor slicing will take as many elements it can as possible; so if we specify the slice to take up to a `stop` index beyond the size of the tensor’s dimension, it will return only whatever elements it can take in the slice. **Taking a single element at a position beyond the length of the array will throw an error**. To illustrate this behavior in another set of examples,

```
x = [1, 2, 3, 4, 5]
# stop beyond the size of the array
print(x[:7]) # [1, 2, 3, 4, 5]
# stop beyond the size of the array, stride 2
print(x[:7:2]) # [1, 3, 5]
# empty, no elements to take
# since the slice is beyond the length of the array
print(x[6:8]) # []
# The following, however, will throw an error
print(x[7]) # IndexError: list index out of range
```

## 3.3 Case Study: Get Consecutive Index

Suppose we have a list of integers [-1, 1, 2, 3, 4, 7, 9, 10, 11, 12, 13, 15], we can recognize that there are two groups that are composed of consecutive integers, [1, 2, 3, 4] and [9, 10, 11, 12, 13]. We would like to find the start and end indices of these two blocks of integers. This can be helpful when we want to convert the list of integers into texts like "-1, 1~4, 7, 9~13 , 15" which may be easier to read than the long list of integers. The following code implements our desired function:

```
import numpy as np

def get_consecutive_index(t, N=1, interval=True):
    """
    Given a sorted array of integers, find the start and the end
    of consecutive blocks
    e.g. t = [-1, 1,2,3,4, 7, 9,10,11,12,13, 15],
         return [1,4], [6,10]

    Inputs:
    * t: the sorted array of integers
    * N: filter for at least N consecutive. Default 1
    * interval: if True, we are filtering by N consecutive
                intervals instead of N consecutive numbers
    """
    # Determine if the (next element) = (1 + previous)
    x = np.diff(t) == 1
    # Determine which element is the start or end of the block
    f = np.concatenate(([False], x)) != np.concatenate((x, [False]))
    # Index of the start and end of the block
    f = np.where(f)[0]
    # reshape: the start and end must come in pairs
    f = np.reshape(f, (-1, 2))
    # filter for at least N consecutive
    interval = 1 - int(interval) # 0 if True, 1 if False
    # Determine which interval has more than desired N consecutive
    # numbers
    f = f[(interval + np.diff(f, n=1, axis=1).T[0]) >= N, :]
    return f
```

- Line 17 uses np.diff to determine if the current element is a consecutive integer of the previous element. If it is a consecutive integer, then its difference from the previous element should be 1, otherwise, it will be greater than 1. For instance, given the list `[-1, 1, 2, 3, 4, 7, 9, 10, 11, 12, 13, 15]`, the backward differences between the successive elements are `[2, 1, 1, 1, 3, 2, 1, 1, 1, 1, 2]` (note that this is 1 element shorter than the original input). Therefore, elements at indices `[2, 3, 4, 7, 8, 9, 10]` are elements that are 1 greater than the preceding elements.

- Line 19 determines which element is the start or end of the block. Given `x = [False, True, True, True, False, True, True, True, True, True, True, True, False, False]` in the previous step, we can observe that if the element is the start of the block, then the boolean value will transition from `False` to `True` (or if the first element is also the start of the block, then the first element in `x` should also be `True`). Similarly, if the element is the end of the block, then the boolean value will transition from `True` to `False` (or if the last element is the end of the block, then the last element should also be `True`). By padding `x` with a leading `False`, we offset `x` by 1 index backward; by appending `x` with a trailing `False`, we offset `x` by 1 index forward. Then, when we compare the values of the two offset boolean arrays, we are comparing:

```
[(False, False), # -1 (start)
[False, True], # 1
[True, True], # 2
[True, True], # 3
[True, False], # 4
[False, False], # 7
[False, True], # 9
[True, True], # 10
[True, True], # 11
[True, True], # 12
[True, False], # 13
[False, (False)]] # 15 (end)
```

This construction would allow us to determine if we are transitioning from `False` to `True` or from `True` to `False`, or if there is no transition at all, between successive elements. We can observe that,

- Values are both False, then the elements are not part of the consecutive block.
- Values are both True, then the elements are in the middle of the block.
- Values are `[False, True]`, the elements are the start of the block.
- Values are `[True, False]`, the elements are the end of the block.

- Line 21 uses `np.where` to determine the indices of the start and the end block.

Line 23 reshapes the 1D vector into a (num_blocks, 2) matrix. This is because there should always be a start and end of the block. Since the input array is already sorted, the end of the block should always occur after the start of the block, given a single block.

Lines 25–27 perform a filtering for block size. There are two modes of this: either counting the number of elements or the number of intervals. The number of intervals can be computed by end_index - start_index, while the number of elements can be computed by end_index - start_index + 1. I use the flag interval to switch between the two cases: if interval=True, then I do not need to add the 1; if interval=False, then I do need to add 1; hence, the expression int (~interval).
