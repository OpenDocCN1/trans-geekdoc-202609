
the true conditions along each dimension. See Figure 3.4 for an illustration of the above example.

NumPy, TensorFlow (through `tf.experimental.numpy`), and PyTorch also implement a special where operation, `nonzero`, and its flat version `flatnonzero` (only in NumPy). As the names suggest, `nonzero` returns the indices (as a tuple) of the tensor along each dimension where the elements are not zeros (equivalently, `np.where(X != 0)`); `flatnonzero` returns the non-zero indices as if the tensor is being flattened (equivalently, `np.where(X.flatten() != 0)`). Since zeros are commonly used to fill missing data (e.g. padding, as we will see in Chapter 5), these convenient operations can sometimes be useful to determine the extent of valid data stored in the tensor.

## 3.2 Slicing

In Section 3.1, we have looked at ways to retrieve a single element using different indexing systems. However, sometimes, we would also like to select a segment or an interval of values from an array. This is known as **slicing**. In Python, we can “slice” an array by selecting elements between a start and an end index of a list `l` using the syntax `l[start:stop]`. For example, let `l = [1, 3, 5, 7, 9]`, and we would like to select all elements starting from index 1 to index 4 (excluded), using `l[1:4]`, which returns `[3, 5, 7]`. Similar to **slicing** is the concept of **striding**: instead of selecting all consecutive elements between two indices, **striding** selects elements between two indices by consistently skipping over a certain number of elements, with the syntax `l[start:stop:step]`. For example, suppose we would like to select every other element between index 1 and index 4 (excluded) (i.e. skipping 1 element when selecting between the indices, or selecting every second element. We can use `l[1:4:2]`, which returns `[3, 7]`. Additional commonly used slicing and striding syntaxes in Python are listed in Table 3.1.

In NumPy, TensorFlow, and PyTorch, slicing and striding operations can not only be applied to 1D vectors but can also generalize to each axis of a multi-dimensional tensor. Figures 3.5 and 3.6 illustrate several examples of slicing and striding operations in 2D matrix and 3D tensors, respectively.

| Slicing from a start index to the last element | start: | l[2:] -> [5, 7, 9] |

In addition to the syntaxes listed in Table 3.1, there are two additional convenient slicing operators, None (equivalently, np.newaxis in NumPy and tf.newaxis in TensorFlow) and ... (or equivalently Ellipsis, a Python's builtin constant), that can be used only with NumPy, TensorFlow, and PyTorch tensor slicing, but not with Python list. Slicing a dimension with None or np.newaxis adds an extra singleton dimension at the axis of slicing.

The operation is equivalent to np.expand_dims in NumPy, tf.expand_dims in TensorFlow, or torch.unsqueeze in PyTorch, respectively. For example,

```
import numpy as np
X = np.random.rand(4, 5) # shape (4, 5)
# Add an extra 3rd dimension
# shape (4, 5, 1)
assert np.allclose(
    X[:, :, None].shape,
    np.expand_dims(X, axis=2).shape
)
# Insert an extra dimension in the first dimension
# shape (1, 4, 5)
assert np.allclose(
    X[None, :, :].shape,
    np.expand_dims(X, axis=0).shape
)
# Insert an extra dimension between the original
# 1st and 2nd dimensions: shape (4, 1, 5)
assert np.allclose(
    X[:, np.newaxis, :].shape,
    np.expand_dims(X, axis=1).shape
)
```

... (ellipsis) operator, on the other hand, allows us to simplify the expression when slicing all elements across multiple consecutive dimensions. For example, let X be a tensor of shape [5, 2, 3, 8, 7], and we would like to select all elements along dimensions 2–5 but a subset along the first dimension. We can do X[2:4, :, :, :, :] or equivalently, X[2:4, ...].

```
import numpy as np
X = np.random.rand(5, 2, 3, 8, 7)
# Selecting subset of a batch
assert np.allclose(
    X[2:4, :, :, :, :].shape,
    X[2:4, ...].shape
)
# Selecting the first slice of the last dimension
assert np.allclose(
    X[:, :, :, :, 0].shape,
    X[..., 0].shape
)
# Selecting a subset of the first dimension and
# the last slice from the last dimensions
assert np.allclose(
    X[1:3, :, :, :, -1].shape,
    X[1:3, ..., -1].shape
)
```

The use of ellipsis (...) for slicing can be convenient when implementing functions that accept variable dimensional tensors. For example, suppose we would like to implement a function that always extracts items in a sequence with one of the forms (batch_size, seq_length), (batch_size, seq_length, feature_size), or (batch_size, seq_length, feature_size, num_instances). Notice that the sequence dimension is always at the axis=1, and the batch dimension is always at axis=0, then we can do

```
import numpy as np

def extract_last_event(X):
    return X[:, -1, ...]

# (batch_size, seq_length)
X1 = np.random.rand(16, 50)
assert np.allclose(
    extract_last_event(X1).shape,
    (16, )
)

# (batch_size, seq_length, feature_size)
X2 = np.random.rand(16, 50, 32)
assert np.allclose(
    extract_last_event(X2).shape,
    (16, 32)
)
# (batch_size, seq_length, feature_size, num_instances)
X3 = np.random.rand(16, 50, 32, 8)
assert np.allclose(
    extract_last_event(X3).shape,
    (16, 32, 8)
)
```

With the ellipsis ..., the function can handle all three variants of the sequence inputs. Notice that in the case when the input has the form (batch_size, seq_length), there are only two dimensions, while in our implementation, it looks like we are extracting from at least three dimensions. It turns out that the ellipsis operator ... will ignore the slicing of the third dimension since the dimension does not exist.

Finally, there can only be one ellipsis . . . operator when specifying a slice. Specifying more than one ellipsis will throw an error, for example:

```
X = np.arange(30).reshape(3, 2, 5)
X[..., 0, ...]
```

throws the error in NumPy:

```
IndexError: an index can only have a single ellipsis ('...')
```

This is because the slicing dimensions represented by the two ellipses are ambiguous. X[..., 0, ...] could potentially represent any of the following:

- X[0, :, :]
- X[:, 0, :]
- X[:, :, 0]

The program cannot determine which is the intended slicing operation.

Throughout the book, I will sometimes overload the ellipsis operator ... as the unspecified value of the argument when describing the usage of function, or used for omitting the enumeration of values in a list. However, these usages should never occur inside a code block (as all code blocks should be runnable as is). I will indicate the meaning of the ellipsis when the notation becomes confusing.

### 3.2.1 Reusing Slice Configuration

There may be times when we would like to apply identical slicing logic to more than 1 tensors, or perhaps we would like to pass the slicing configuration as a variable to a function. In these scenarios, we would need to construct the slice object. Python has a built-in method to build slices, slice, which is used as

- slice(stop), which is equivalent to the slice as in l[:stop];
- slice(start, stop), which is equivalent to the slice as in l[start:stop];
- slice(start, stop, step), which is equivalent to the slice as in l[start:stop:step].

Similarly, NumPy implements np.s_ which can be used in an identical way but it uses the more commonly used colon : syntax than slice. Table 3.2 re-enumerates the examples of slicing operations as listed in Table 3.1 previously, but using slice and np.s_ to build the slicing configurations.
