The usage pattern and the logic of the operation are not identical to that of tf.tensor_scatter_nd_reduce> ornp.ufunc.at for accumulation. In this section, I attempt to explain the differences between the two operations.

After comparing the equivalent Python for-loop equivalent code from the documentations for torch.Tensor.scatter_reduce [Paszke et al., 2023c] (the in-place version of torch.scatter_reduce) and torch.gather [Paszke et al., 2023a], we can deduce that these two operations follow the same formulation. In general, indices, values, and target X should have the same number of dimensions, i.e. indices.ndim == values.ndim == X.ndim. It is also required that the size of indices is no greater than the size of input X or the scattering values at the corresponding axis dimensions, i.e. indices.shape[dim] <= X.shape[dim] and indices.shape[dim] <= values.shape[dim]. This means, we can specify an index that is shorter than the size of the inputs or the scattered values; the extra elements will be ignored during the scattering operation.
