In the example, the protobuf for the byte string needs to encode the data types using separate protobuf definitions, i.e. string features need to be cast to bytes first and then encoded by tf.train.BytesList, integer features need to be encoded by tf.train.Int64List, and float features need to be encoded by tf.train.FloatList. Notice that the value assigned for each feature is a list with a single element. This is because these protobuf types actually encode a list of values of a certain type rather than a single value. Suppose {num_classes_taken: [5, 3, 4]}, then we can encode this feature as int64_list=tf.train.Int64List(value=[5, 3, 4]).

To write our string representations of the data into a TFRecord, we can first serialize the protobuf string into bytes, and then write into a compressed TFRecord. To understand how exactly TFRecord is formatted to store the data in a serialized format, see the implementation from the Ray Data library [Moritz et al., 2023].
