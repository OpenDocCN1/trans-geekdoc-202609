> You may notice that, for Tensorflow operations, some functions are under the tf. module and some are under the tf.math. module. This is because, although all are implemented under the tf.math. module, some frequently used functions are aliased under the main tf module for ease of access. You can verify this by printing out the module path. For example, tf.math.abs and tf.abs both refer to the operation <function tensorflow.python.ops.math_ops.abs(x, name=None)>.

PyTorch has many of these operations implemented as methods on its torch.Tensor class. Therefore, instead of using the function from the main module, one can call the corresponding methods on the array/tensor instances. For example, instead of torch.abs(x), we can do x.abs(). This makes PyTorch more object-oriented.

# ## 2.4 Reduction Operations

Reduction (or reduce) operations are mathematical operations that summarize a set of values into a single value. It “reduces” the size of the tensor, from higher-dimensional to lower-dimensional, or single scalars. Table 2.4 lists examples of reduction operations.

NumPy and PyTorch also have many of these reduction operations implemented as methods on their respective np.ndarray and torch.Tensor classes. Therefore, instead of using the function from the main module, one can call the corresponding methods on the array/tensor instances. For example, instead of np.sum(x) or torch.sum(x), we can do x.sum(). TensorFlow is more function-oriented and does not have these reduction operations implemented on its tf.Tensor class, likely because it needs to support the construction of computational graphs by tracing through function calls.
