# ## 7.5 Sparse Matrix in Other Python Libraries

In addition to the sparse matrix implementations in Scipy, Tensorflow, and PyTorch, other Python libraries also have sparse data structure implemented, including but not limited to:

+   - pandas: Implemented as types `SparseArray` and `SparseDataFrame`, similar to `coo`, and interfaces with `scipy.sparse.coo_matrix` very well.
+     - conversion from pandas to `scipy.sparse.coo_matrix` with `df.sparse.to_coo()`
+     - conversion to pandas from `scipy.sparse.coo_matrix` with `pd.Series.sparse.from_coo()`
+   - pyspark: `pyspark.mllib.linalg.SparseMatrix`, default `csc` format. But when the matrix is transposed by setting the argument `isTransposed=True`, this sparse matrix can be viewed as `csr` format.
+   - pyarrow: pyarrow supports `coo` (`pyarrow.SparseCOOTensor`), `csr` (`pyarrow.SparseCSRTensor`), `csc` (`pyarrow.SparseCSCTensor`), and `csf` (`pyarrow.SparseCSFTensor`, or Compressed Sparse Fiber [Nisa et al., 2019]) format. `pyarrow` is an efficient library for big data operations and integrates tightly with `numpy` and `pandas`.

# ## 7.6 When (Not) to Use Sparse Matrix

Data sparsity is the key to deciding if we should be using a sparse matrix or a dense matrix to represent our data. In general, the space complexity of a multidimensional sparse tensor is O((d + 1)N), where N is the size of the data and d is the number of dimensions of the tensor. In the case of a two-dimensional matrix, we need to store three times the information about the data. We need 2N of spaces to store the row and column indices, and another space of size N to store the data itself. As a rule of thumb, when the data sparsity is <33% (i.e., only less than one-third of the matrix is filled with non-missing values), then it is probably more efficient to represent the data using a sparse matrix rather than a dense tensor.
