![](img/e891acaacd4fb5b80dab2ed824618203_148_0.png)

Figure 4.3 Illustration of tensordot operations when axes=1. (a) For a pair of 1D vectors each having a shape of (5,), the tensor dot product along axes=1 is equivalent to simple vector inner dot product, which results in a scalar; (b) adding another vector along the first dimension of a, the operation becomes dot products between two vectors in a (shape (2, 5), each against b (shape (5,). This should yield a resulting vector of shape (2,1). But, since the implicit singleton dimension is squeezed, the resulting vector has shape (2,). (c) Adding an additional column dimension on the second input b, this results in an operation that performs pair-wise dot product between each vector in a (shape (2,5)) and b (shape (5, 2)). The resulting tensor has shape (2, 2), which is equivalent to matrix multiplication ab.

The axes argument can also be specified as a pair of lists of dimensions for contraction. In fact, in some specific cases, integer value arguments for axes can have a corresponding list version. For examples:

- np.tensordot(a, b, 0) is equivalent to np.tensordot(a, b, [[]], [[]]) where a and b can be any arbitrary tensor.

![](img/e891acaacd4fb5b80dab2ed824618203_149_0.png)

**Figure 4.4** Illustration of tensordot operations when axes=2. (a) For a pair of 2D matrices each having a shape of (2, 3), the tensor dot product along axes=2 is equivalent to tensor double contraction a : b = Tr(ab^T), which yields a scalar; (b) after adding one leading dimension, making the first tensor a have shape (2, 2, 3), the tensor dot product becomes 1 matrix contraction operations, for each matrix within a against matrix b; (c) after adding one trailing dimension, making the second tensor b have shape (2, 3, 2), the tensor dot product becomes a set of matrix contraction operations for each combination of matrices between a and b. The matrices in a are taken along the axes 1 and 2, making axis=0 the batch dimension. The matrices in b are taken along the axes 0 and 1, making axis=2 the batch dimension. The resulting tensordot product has shape (2, 2).

- np.tensordot(a, b, 1) is equivalent to either np.tensordot(a, b, [[1], [0]]) when a is a matrix and b is at least a 1D vector (but it can also be greater dimensions), or np.tensordot(a, b, [[0], [0]]) when a and b are both vectors. More generally, axes=[[-1], [-1]] will cover both cases.

- np.tensordot(a, b, 2) is equivalent to np.tensordot(a, b, [[0, 1], [0, 1]]) when a and b are both 2D matrices, or more generally, np.tensordot(a, b, [[-2, -1], [0, 1]]) for arbitrary tensors with a number of dimensions greater than or equal to 2.

We can similarly derive a general rule here: let the first input tensor a have shape (m, n, ..., s_i, ...) and the second input tensor b have shape (p, q, ..., s_{p_i}, ..., r_j, ...), and let s_i == r_j, for i, j ∈ 1, 2, ..., k, where k is the number of dimensions to contract. We then specify the axes argument as axes=[[..., i, ...], [..., j, ...]] to indicate contractable dimensions. Then, the elements along the corresponding contractable dimensions are multiplied together element-wise and then summed together to obtain a single scalar. The operation is repeated (i.e. vectorized) over all combinations of dimensions that are not contracted, and the resulting tensor has shape (m, n, ..., p, q, ...).

## 4.4 Einsum

Einstein Summation (or einsum) Convention is a generalization of various forms of vector, matrix, and tensor summations and multiplications. Suppose we want to perform matrix multiplication between two tensors X and Y, each element of the matrix should be expressed mathematically as

\([XY]_{ij} = \vec{X}_i \cdot \vec{Y}_j = \sum_k X_{i,k} \cdot Y_{k,j}\)

and using a for-loop, we would compute the product like the following, e.g.:

```
import numpy as np

X = np.random.rand(5, 3)
Y = np.random.rand(3, 7)
Z = np.zeros((5, 7)) # expected shape
for ii in range(5):
    for jj in range(7):
        Z[ii, jj] = X[ii, :].dot(Y[:, jj])
```

> **Note**
>
> Various sources I have found on the history of the Einstein Summation Convention pointed to Albert Einstein's original manuscript on General Relativity, “Die Grundlage der allgemeinen Relativitätstheorie,” or in English, “The Foundation of the General Theory of Relativity” [Einstein, 1996]. But, based on what was described in Section 4.5, Einstein credited “Ricci and Levi-Civita” (i.e. Gregorio Ricci-Curbastro and Tullio Levi-Civita) for these notations.

In einsum notation, the matrix multiplication operation will track only the indices, ik and kj, respectively. Then, matrix multiplication is expressed as ik,kj->ij. Notice that the repeated index k is collapsed or summed together after multiplication along its dimension.

There are two modes of expressing the einsum equations. The above example is called the “explicit mode,” in which the equation string has a right arrow "->" to indicate the ordering of the indices of the resulting tensor. If there are no indices to the right of the arrow, then a constant is assumed to be returned.

By contrast, in “implicit” mode, the equation string does not have a right arrow -> specifying the resulting indices, and the results are computed with the following assumptions:

- Indices are sorted alphabetically. If indices in the equations are specified not in alphabetical order, then the returned tensor will have the indices sorted alphabetically. For example, "ji" (whose equivalent explicit mode is "ji->ij") is equivalent to X^T.

- Repeated indices are summed together. For example, "ij, j" (whose equivalent explicit mode is "ij, j->i") is equivalent to \(\sum_j X_{ij} . Y_j = z_i\), and to NumPy operation `np.sum(X * Y, axis=1)`.

Note that certain operations can only be expressed in explicit mode. See various examples in Table 4.2.

In Sections 4.5 and 4.6, we will look at several examples of implementing mathematical formulas and algorithms using tensor multiplications.

Table 4.2 Examples of einsum equations and equivalent NumPy operations.

| Operation | Equation String (Explicit) | Equation String (Implicit) | Equivalent NumPy Operations |
|---|---|---|---|
| Inner product^a) | "i, i->" | "i, i" | np.inner |
| Outer product^b) | "i, j->ij" | "i, j" | np.outer |

Notes:
a) Dot product of two vectors.

```
1 a = np.random.rand(8)
2 b = np.random.rand(8)
3 np.allclose(
4     np.inner(a, b),
5     np.einsum("i,i", a, b)
6 )
```

b) Outer product of two vectors.

```
1 a = np.random.rand(8)
2 b = np.random.rand(8)
3 np.allclose(
4     np.outer(a, b),
5     np.einsum("i,j", a, b)
6 )
```

Table 4.2 (Continued)

| Operation | Equation String (Explicit) | Equation String (Implicit) | Equivalent NumPy Operations |
| :--- | :--- | :--- | :--- |
| Extract diagonal^c) | "ii->i" | NA | np.diagonal, np.diag |
| Trace c) | "ii->" | "ii" | np.trace |
| Transpose d) | "ij->ji" | "ji" | np.transpose |
| Swapaxes d) | "ijk->kji" | "kji" | np.swapaxes |

c) Diagonal extraction vs. Trace. Even though the two expressions are similar, the Trace operation should return the sum of the diagonal as a scalar, while diagonal extraction should return the diagonal entries as a vector.

```
X = np.random.rand(8, 8)
np.allclose(
    np.trace(X),
    np.einsum("ii->", X)
)
np.allclose(
    np.diag(X),
    np.einsum("ii->i", X)
)
```

d) Transpose and Swapaxes. These two are similar operations in einsum. The implicit mode takes advantage of the assumption that the axes of the returned tensor will be sorted alphabetically.

```
# Transpose of matrix
X = np.random.rand(4, 5)
np.allclose(
    np.transpose(X),
    np.einsum("ij->ji", X)
)
np.allclose(
    np.transpose(X),
    np.einsum("ji", X)
)
# Swapaxes
Y = np.random.rand(4, 5, 6)
np.allclose(
    np.swapaxes(Y, 0, 2),
    np.einsum("ijk->kji", Y)
)
np.allclose(
    np.swapaxes(Y, 0, 2),
    np.einsum("kji", Y)
)
```

Table 4.2 (Continued)

| Operation | Equation String (Explicit) | Equation String (Implicit) | Equivalent NumPy Operations |
|---|---|---|---|
| Sum along row^e) | "ij->j" | NA | np.sum(..., axis=0) |
| Sum along column^e) | "ij->i" | NA | np.sum(..., axis=1) |
| Sum all^f) | "ij->" | NA | np.sum(...) |
| Identity^f) | "ij->ij" | "ij" | np.array |

e) Sum along rows and columns.

```python
X = np.random.rand(3, 4)
# Sum along rows
np.allclose(
    np.sum(X, axis=0),
    np.einsum("ij->j", X)
)
# Sum along columns
np.allclose(
    np.sum(X, axis=1),
    np.einsum("ij->i", X)
)
```

f) Sum All vs. Identity (an operation that gives output identical to input, not to be confused with a mathematical identity matrix). "Sum All" can only be expressed using the explicit mode, whereas "Identity" has an explicit mode "ij->ij" as well as the implicit mode "ij". This is because when there is no value to the right of the arrow, the equation is always interpreted as summing into a constant; by contrast, when there is no right arrow (i.e. in implicit mode), summation only happens when indices are repeated.

```python
X = np.random.rand(4, 5)
# Identity function
np.allclose(
    X,
    np.einsum("ij->ij", X)
)
np.allclose(
    X,
    np.einsum("ij", X)
)
# Sum all elements
np.allclose(
    X.sum(),
    np.einsum("ij->", X)
)
```
