## 2 Basic Tensor Operations

Numerical libraries like NumPy [Harris et al., 2020], Tensorflow [Abadi et al., 2015], and PyTorch [Paszke et al., 2019] implement various types of vectorized operations to facilitate scientific computing. Throughout this book, we define the following set of terminologies: if a variable is called a

- **scalar**, then the variable has zero dimensions and represents a single numerical value.
- **array**, or **vector**, then the variable has one dimension and represents a list of values.
- **matrix**, then the variable has two dimensions and represents a typical two-dimensional matrix.
- **tensor**, then the variable is a generic collection of values of _N_-dimension(s), where \(N \in {0, 1, 2, ...}\) is a natural number. More often, I will use the term “tensor” to indicate the high-dimensional collection of values where _N > 2_.

In this chapter, we will examine various operations that are used on a single tensor or a pair of tensors.

### 2.1 Tensor Initializers

Tensor initializers provide quick and convenient ways to pre-allocate some spaces in memory to store values to be filled in later on. It can also be used for masking and indexing operations, which we will see in later chapters. To initialize a list of values, we would typically use a for loop like the following example:

```
# Initialize an array of zeros
value = []
for _ in range(1_000_000):
    value.append(0)
```

which seems to be slow (on my M1 MacBook Pro)

```
32.3 ms ± 390 µs per loop (mean ± std. dev. of 7 runs, 10 loops each)
```

Using list comprehension

```
[0 for _ in range(1_000_000)]
```

seems to improve the performance

```
17.3 ms ± 586 µs per loop (mean ± std. dev. of 7 runs, 100 loops each)
```

We can also use a one-liner with Python's syntax candy operator * on the list

```
[0] * 1_000_000
```

which is much faster

```
2.69 ms ± 66.6 µs per loop (mean ± std. dev. of 7 runs, 100 loops each)
```

Still, none of the above beats the performance of the NumPy function np.zeros

```
np.zeros(1_000_000)
```

which is the fastest

```
537 µs ± 39.8 µs per loop (mean ± std. dev. of 7 runs, 1,000 loops each)
```

By using np.zeros, we can also easily create a multi-dimensional tensor (not just a 1-D vector), which then helps us perform additional downstream vectorized operations.

But why pre-allocate or initialize a vector at all? This again has something to do with performance. It can be said that extending an array on the fly is more costly than pre-allocating a portion of the memory for our computations. Let's show this

```
import math
def sqrt_iter():
    values = []
    for ii in range(1_000_000):
        values.append(math.sqrt(ii))
    return values
```

> 87.5 ms ± 1.27 ms per loop (mean ± std. dev. of 7 runs, 10 loops each)

Alternatively, we can pre-allocate an array of zeros to store the results

```
import math
def sqrt_iter_preallocate():
    values = [0] * 1_000_000
    for ii in range(1_000_000):
        values[ii] = math.sqrt(ii)
```

> 78.4 ms ± 828 µs per loop (mean ± std. dev. of 7 runs, 10 loops each)

### Anecdote

I first started doing vectorized programming in MATLAB. Pre-allocating a vector before starting a for-loop is a classic lesson on MATLAB performance. Although in the above small Python example, we were only seeing about 10% improvement, in the case MATLAB, this can be a 10-50x performance gain! See for MATLAB's official documentation on this: https://www.mathworks.com/help/matlab/matlab_prog/preallocating-arrays.html. Anecdotes in real-world software development have also suggested that preallocation is an effective strategy for better performance when dealing with large arrays in many other languages such as JavaScript [Nenashev, 2024], R [Sellers, 2024], and C++ [Usi, 2023].

Table 2.1 List of tensor initializers in Python, NumPy, Tensorflow, and PyTorch.

| Init Operation | Python | NumPy | Tensorflow | PyTorch |
|---|---|---|---|---|
| Zeros | [0] * n | np.zeros | tf.zeros | torch.zeros |
| Ones | [1] * n | np.ones | tf.ones | torch.ones |
| Empty | [[]] * n | np.empty | tf.experimental.numpy.empty | torch.empty |
| Full | [value] * n | np.full | tf.fill, tf.experimental.numpy.full | torch.full |
| Random uniform | random.uniform | np.random.rand | tf.random.uniform | torch.rand |
| Random normal | random.normal | np.random.randn | tf.random.normal | torch.randn |
| Random int | random.randint | np.random.randint | tf.experimental.numpy.random.randint | torch.randint |
| Range | range | np.arange | tf.range | torch.arange |
| Linspace | N/A, use range | np.linspace | tf.linspace | torch.linspace |
| Identity matrix | N/A | np.eye | tf.eye | torch.eye |
| Diagonal matrix | N/A | np.diag | tf.linalg.diag | torch.diag |

Note:
a) Many of these tensor initializers have corresponding _like methods where the shape of the initialized tensor can be inferred from the shape of another provided tensor. These methods are convenient when trying to initialize tensors with the same shape as the existing tensors. In other scenarios, where a tensor's shape may not be known until runtime, the _like methods allow the user to initialize the tensor dynamically by inferring its shape from the runtime result.
- zeros: np.zeros_like, tf.zeros_like, torch.zeros_like
- ones: np.ones_like, tf.ones_like, torch.ones_like
- empty: np.empty_like, tf.experimental.numpy.empty_like, torch.empty_like
- full: np.full_like, tf.experimental.numpy.full_like, torch.full_like
- uniform: torch.rand_like
- normal: torch.randn_like
- randint: torch.randint_like
b) Tensorflow implements an experimental NumPy module tf.experimental.numpy. Oftentimes, many NumPy operations equivalent or alternative to the Tensorflow operations (e.g. Full vs. fill) can be found in this module. This module does not include all NumPy operations; some operations have limited capabilities compared to NumPy (most likely due to the need for efficient graph tracing [Abadi et al., 2023a] in Tensorflow).
