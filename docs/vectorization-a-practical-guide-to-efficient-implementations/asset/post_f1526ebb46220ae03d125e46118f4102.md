```python
import torch
def rotary_positional_encoding(emb_size, seq_len):
    pos = torch.arange(seq_len).unsqueeze(1)
    depths = torch.arange(emb_size//2).unsqueeze(0)
    theta = 10000 ** (-2*depths/emb_size)
    p_theta = theta * pos
    # Construct empty R matrix (1, d, d)
    R = torch.zeros(seq_len, emb_size, emb_size)
    # Fill the R matrix
    depths_0 = torch.arange(0, emb_size, 2)
    depths_1 = torch.arange(1, emb_size, 2)
    # Computing rotations
    R[:, depths_0, depths_0] = torch.cos(p_theta)
    R[:, depths_1, depths_1] = R[:, depths_0, depths_0]
    R[:, depths_0, depths_1] = -torch.sin(p_theta)
    R[:, depths_1, depths_0] = -R[:, depths_0, depths_1]
    return R
```

- Lines 4–7 compute \(p\theta\) based on Equation 11.5.
- Line 9 initializes the placeholder tensor for the rotation matrix output.
- Lines 11–12 determine the positions to insert the sine and cosine values. Specifically, each block \(i\) has four positions, which are \((i, i)\) for cos, \((i, i+1)\) for \(-\sin\), \((i+1, i)\) for sin, and \((i+1, i+1)\) for cos.
- Lines 14–17 insert the sine and cosine values based on the positions.

We can visualize the first nine slices of the rotation matrix, given a sequence length of 500 and embedding size of 64 in Figure 11.7.

Although we can simply multiply together the rotation matrix with the input sequence of embedding based on the vanilla formulation, the sparsity of the matrix \(R\) suggests that there may be a more efficient way to formulate the encoding mechanism. The open-source repository for LLaMA from Meta implements a rather smart reformulation of rotary positional embedding [Facebook Research, 2023]. It can be seen that the matrix \(R\) is a block-diagonal matrix, where each block is a size of \(2 \times 2\) rotation matrix. This means when multiplying together with the embedding sequence vector \(X\), each rotation block at the position \(p\), embedding positions \(k\) and \(k+1\) is only multiplied with a pair of values along the same position \(p\) and embedding positions \(k\) and \(k+1\) (see Figure 11.8 for illustration). We can denote the pair at embedding positions \(k\) and \(k+1\) as group \(i\), which corresponds to the index \(i\) for each \(\theta\) in Equation 11.5. Then, we can write the multiplication within each group \((p, i)\) as

> \[ \begin{bmatrix} \cos(p\theta_i) & -\sin(p\theta_i) \\ \sin(p\theta_i) & \cos(p\theta_i) \end{bmatrix} \begin{bmatrix} x_1^{(i)} \\ x_2^{(i)} \end{bmatrix} = \begin{bmatrix} x_1^{(i)} \cos(p\theta_i) - x_2^{(i)} \sin(p\theta_i) \\ x_1^{(i)} \sin(p\theta_i) + x_2^{(i)} \cos(p\theta_i) \end{bmatrix} \quad (11.6) \]

![](img/e891acaacd4fb5b80dab2ed824618203_413_0.png)

Figure 11.7 Rotation matrix of the first nine sequence positions, given embedding size of 64.

It turns out we can reformulate the rotation matrix using a complex value as

$$\phi_p^{(i)} = \cos(p\theta_i) + \sin(p\theta_i)j$$ (11.7)

where the imaginary number $\sqrt{-1}$ is denoted by the letter $j$ following the engineering convention, rather than $i$ under the mathematical convention. We can also treat the pair of values as a complex number, i.e.

$$x_p^{(i)} = x_1^{(i)} + x_2^{(i)}j$$ (11.8)

Then, it can be shown that

$$\begin{aligned} x_p^{(i)}\phi_p^{(i)} &= \left(x_1^{(i)} + x_2^{(i)}j\right) \left(\cos(p\theta_i) + \sin(p\theta_i)j\right) \\ &= \left(x_1^{(i)}\cos(p\theta_i) - x_2^{(i)}\sin(p\theta_i)\right) + \left(x_1^{(i)}\sin(p\theta_i) + x_2^{(i)}\cos(p\theta_i)\right)j \end{aligned}$$ (11.9)

![](img/e891acaacd4fb5b80dab2ed824618203_414_0.png)

Figure 11.8 Corresponding values in R and X to be multiplied. Suppose we have an embedding size of 12 and a sequence length of 4. The R tensor (a) should have the shape 4 x 12 x 12, and the sequence input tensor X (b) should have the shape 4 x 12. Due to the sparsity nature of the matrix R (a block diagonal matrix), the only effective multiplication is between the corresponding upper left corner regions in R (the upper left corner 4-grid square block) and X (the first two grids in the first row). In this example, the first block in R is multiplying together with the first pair in X, at the corresponding sequence position.

Notice that this is the same as representing the right-hand side column vector in Equation 11.6 (as the result of the multiplication) as a complex value.

This means if we represent the diagonal block as a vector of complex numbers and convert each pair of embedding values into a complex number as well, then we can simply do an element-wise product between the transformed vectors and then recover the result by converting the complex results back into a pair of numbers along the embedding dimension. Therefore, we can implement the following two functions which we can use to apply the rotary positional encoding on an input of shape (batch_size, seq_len, ..., emb_size), where the elided dimension can be the additional num_heads dimension depending on the specific settings of the attention mechanism.
