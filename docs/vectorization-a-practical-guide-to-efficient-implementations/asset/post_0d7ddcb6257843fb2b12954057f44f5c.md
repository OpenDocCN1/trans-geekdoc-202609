- i is the index along the embedding dimension, i \in (0, 1, 2, ..., d_{model} // 2),
- d_{model} is the embedding size.

This is typically referred to as sinusoidal positional encoding since it utilizes sinusoidal waves parameterized by position along the sequence and embedding dimensions. The following code block shows how to implement sinusoidal positional encoding from the original paper using PyTorch:

```python
import torch

def sinusoidal_positional_encoding_vaswani(emb_size, seq_len):
    position = torch.arange(seq_len)
    timescales = torch.pow(
        1 / 10000,
        2 * (torch.arange(emb_size) // 2) / emb_size,
    )
    angles = position.unsqueeze(1) * timescales.unsqueeze(0)
    out = torch.zeros((seq_len, emb_size))
    # Interleaving sin and cos along embedding dimension
    out[:, 0::2] = torch.sin(angles[:, 0::2])
    out[:, 1::2] = torch.cos(angles[:, 1::2])
    return out
```

- Lines 4–9 implement the term inside the sine and cosine function in Equation 11.3. This creates a sequence (e.g. time) by embedding a dimension matrix.
- Line 10 creates the output placeholder, initialized with zeros.
- Lines 12–13 assign the even position with sine values and odd positions with cosine values, respectively.

We can plot out the positional encoding given the embedding size of 256 and sequence length of 500, as shown in Figure 11.4.

An alternative formulation of the sinusoidal positional encoding was introduced in the TransformerXL architecture implemented by Google’s tensor2tensor [Vaswani et al., 2018] deep learning library [Vaswani et al., 2023]. (This is also the implementation in Google’s tutorial on transformer [Abadi et al., 2023].) Instead of interleaving the sine and cosine terms along the depth dimension, the two pieces are simply concatenated together. Here is the implementation of this variant of sinusoidal positional encoding, and the encoding map is plotted in Figure 11.5.

```python
import torch

def sinusoidal_positional_encoding_tensor2tensor(emb_size, seq_len):
    position = torch.arange(seq_len)
    timescales = torch.pow(
        1 / 10000,
        2 * (torch.arange(emb_size) // 2) / emb_size,
    )
    angles = position.unsqueeze(1) * timescales.unsqueeze(0)
    out = torch.zeros((seq_len, emb_size))
    # Stacking the two partitions
    out = torch.cat([
        torch.sin(angles[:, 0::2]),
        torch.cos(angles[:, 1::2])
    ], axis=1)
    return out
```

## 11.4.2 Position as Categorical Embeddings

The sinusoidal position information is hard-coded. However, it is also possible to learn to represent the position information. An approach to learning to represent positional information is to treat positions as a categorical feature. Then, through back-propagation, the network learns to efficiently encode positional information. Well-known architectures that use learned categorical embeddings of position include BERT [Devlin et al., May 2019] and RoBERTa [Liu et al., 2019]. Let us implement a simple layer that adds positional embedding to an input.

```python
import torch
from torch import nn

class PositionalEmbedding(nn.Module):
    def __init__(self, seq_len, emb_size):
        super().__init__()
        self.embed = nn.Embedding(seq_len, emb_size)

    def forward(self, x):
        # x: (batch_size, seq_len, emb_size)
        pos = torch.arange(x.shape[1], dtype=torch.int32)
        # embedding lookup (batch_size, seq_len, emb_size)
        pos_emb = self.embed(pos)
        # add
        x = x + pos_emb
        return x
```

- __init__ (Lines 5–7): Initializes the positional embedding module and creates the embedding lookup table.
- forward (Lines 9–17):
  - Line 11 creates the position vector for the current sequence inputs.
  - Line 13 looks up the corresponding embedding vector.
  - Line 15 adds the positional embedding vector to the input.

## 11.4.3 Relative Positional Encoding (RPE)

The sinusoidal positional encoding is sometimes also called absolute positional encoding. Thus, as a counterpart, relative positional encoding (RPE) is developed to encode only the relative distances between pairs of the sequence in the attention mechanism. Recall that self-attention is defined in the original transformer paper [Vaswani et al., 2017] as

![](img/e891acaacd4fb5b80dab2ed824618203_409_0.png)

where

- \(d_k\) is the embedding size of the key.

Q, K, and V are query, key, and value vectors that are obtained by passing inputs into a dense projection layer, e.g. Q = W_q X_q with X_q being the embedding vector of the query. In the scenario of self-attention, X_q, X_k, and X_v are identical, so we will denote it as X.

In the case of absolute sinusoidal positional encoding, it is typical to add positional encoding on top of the embedding output X, then project with a dense layer before computing the attention score. Mathematically, we can formulate it as Q = (X + PE)W_q and K = (X + PE)W_k. Then,

```
QK^T = (X + PE)W_q \cdot ((X + PE)W_k)^T
```

RPE, however, formulates this term as [Luo et al., 2022]

```
QK^T = (XW_q) \cdot (XW_k)^T + B
```

where B is a square matrix. That is, RPE adds the positional encoding information on top of the attention score map, instead of directly on the input token representation, where relative distances between each pair of tokens are computed. Well-known formulations of B include:

- Original RPE paper [Shaw et al., 2018]: b_ij = X_i W_q r_{i-j}^T where r_{i-j} is a learnable parameter between the positions i and j in the sequence.
- Transformer-XL [Dai et al., 2019]: b_ij = X_i W_q (r_{i-j} \tilde{W}_k)^T + u(X_j W_k)^T + v(r_{i-j} \tilde{W}_k)^T, where u, v, and \tilde{W}_k are learnable vectors, while r_{i-j} is a sinusoidal positional encoding.
- T5 (Text-to-Text Transfer Transformer) [Raffel et al., 2020]: b_ij is a learnable parameter on its own.

Figure 11.6 illustrates the case for the T5 model. Pair-wise distances between the positions of the key and the query are computed. Then, the embedding of the relative distances is used to construct the position embedding tensor of shape (q_len, k_len, emb_size), which is then added to the attention score [Wolf et al., 2020; HuggingFace, 2023]. Note that the T5 model uses a strategy to map large relative distances to a bucket number in a logarithmic scale, such that these large relative distances may correspond to the same embedding vectors.

## 11.4.4 Rotary Positional Encoding (RoPE)

The RoFormer paper [Su et al., 2020] introduced the rotary positional encoding (RoPE), which is also a form of relative attention. Instead of adding a positional encoding to the input, the idea is to rotate the embedding vector of the sequence

![](img/e891acaacd4fb5b80dab2ed824618203_411_0.png)

by an angle parameterized by the position. Specifically, given a rotation matrix \( R \), rotary positional encoding is incorporated into the input \( X \) by multiplication \( RX \). Here, \( R \) has the form:

```
R_{\Theta, d}^{(p)} = \begin{bmatrix} \cos(p\theta_1) & -\sin(p\theta_1) & 0 & 0 & \dots & 0 & 0 \\ \sin(p\theta_1) & \cos(p\theta_1) & 0 & 0 & \dots & 0 & 0 \\ 0 & 0 & \cos(p\theta_2) & -\sin(p\theta_2) & \dots & 0 & 0 \\ 0 & 0 & \sin(p\theta_2) & \cos(p\theta_2) & \dots & 0 & 0 \\ \vdots & \vdots & \vdots & \vdots & \vdots & \vdots & \vdots \\ 0 & 0 & 0 & 0 & \dots & \cos(p\theta_{d/2}) & -\sin(p\theta_{d/2}) \\ 0 & 0 & 0 & 0 & \dots & \sin(p\theta_{d/2}) & \cos(p\theta_{d/2}) \end{bmatrix}
```

where,

- \( R_{\Theta, d}^{(p)} \) is the pth slice of the rotation matrix for position \( p \).
- Each slice is a \( d \times d \) matrix, where \( d \) is the embedding size (i.e. \( d_{model} \)).
- \( \Theta \) is an array with each element as \( \theta_i = 10,000^{-2(i-1)/d} \), where \( i \in [1, 2, 3, \dots, d/2] \).

Notice that each block is a 2D rotation matrix of the form

```
\begin{bmatrix} \cos(\theta) & -\sin(\theta) \\ \sin(\theta) & \cos(\theta) \end{bmatrix}
```

This means, we are rotating each pair of values along the embedding vector by an angle computed by \( p\theta_i \). The following code block is an implementation of the rotation matrix \( R \):
