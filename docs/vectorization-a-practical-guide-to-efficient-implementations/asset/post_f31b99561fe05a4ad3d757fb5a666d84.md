## 5.2.1 Case Study: Padding in Convolutional Neural Networks

Understanding padding is quite useful when implementing convolutional neural networks. There are two typical padding modes in a convolutional layer: `valid` and `same`. `valid` simply means there is no padding added, and convolution results are smaller than the input. `same` means adding some zero padding to the heights and widths of the convolutional dimensions such that the result of the convolution has the same heights and widths as the input. See Figure 5.12 for an example that compares the differences between the two. See also the below code example to verify the shapes of `same` vs. `valid` padding in convolutional operations.

```python
import tensorflow as tf
X = tf.constant([
    [5, 3, 2, 7],
    [4, 1, 3, 7],
    [1, 4, 4, 1],
    [7, 6, 4, 2],
], dtype=tf.float32)[None, :, :, None]
Filters = tf.constant([
    [0, 2],
    [1, 1]
], dtype=tf.float32)[:, :, None, None]
y_valid = tf.nn.conv2d(
    X,
    Filters,
    1,
    "VALID",
    data_format='NHWC',
    dilations=None,
    name=None
)
assert y_valid.shape[1] == X.shape[1] - 1
assert y_valid.shape[2] == X.shape[2] - 1
y_same = tf.nn.conv2d(
    X,
    Filters,
    1,
    "SAME",
    data_format='NHWC',
    dilations=None,
    name=None
)
assert y_same.shape[1] == X.shape[1]
assert y_same.shape[2] == X.shape[2]
```

## 5.2.2 Case Study: Truncate or Pad Sequence to Desired Length

Suppose we have two batches of sequences, X and y. X has shape (batch_size, seq_len_1) and y has shape (batch_size, seq_len_2). We do not know beforehand which sequence is longer, however, we would like to have y with sequence lengths identical to that of X. The following code uses the idea of padding and slicing to align the lengths of X and y.

```python
import numpy as np
def align_lengths(X, y):
    """Align y to the length (axis=1) of X."""
    # Get the desired length
    X_len = X.shape[1]
    # Compute pad_size.
    # No padding (pad_size=0) if y length is enough
    pad_size = max(X_len - y.shape[1], 0)
    # Pad if not enough
    y = np.pad(y, [(0, 0), (0, pad_size)])
    # Truncate if y is too long
    y = y[:, :X_len]
    return y
```

- Line 5 gets the desired length that we would like y to have.
- Line 8 computes the desired padding size. If X is longer, then we need to pad the difference between X and y; but if X is shorter, we should not pad (pad_size=0).
- Line 10 does the padding based on the pad_size we calculated. This will handle cases where y is shorter than X but has no effect when y is the same length or longer than X.
- Line 12 truncates any extra elements in y. If y is indeed longer than X, then after truncation, y should be the same size as X. If y is the same length as X or is shorter than X, padding from the previous step will first bring y to the same length as X. Then slicing up to the length X will have no effect.

We can quickly test out our implementation:

```python
X1 = np.random.rand(16, 50)
X2 = np.random.rand(16, 30)
y = np.random.rand(16, 37)
y1 = align_lengths(X1, y)
assert np.allclose(X1.shape, y1.shape)
print(y1.shape)
y2 = align_lengths(X2, y)
assert np.allclose(X2.shape, y2.shape)
print(y2.shape)
```

A practical use case of the above algorithm is to align a generated sequence to some desired length. For example, a ground-truth speech audio sample has two words, lasts one second and contains 16,000 data points (i.e. 16 kHz sampling rate). However, the generated sample due to series of upsampling by factors of [16, 16, 32] from the two words creates a sequence of 2 x 16 x 16 x 32 = 16,384 data points. In order to learn from the audio sample by calculating a loss between the prediction and the ground-truth, we can use the above algorithm to align the two sequences (e.g. truncate the generated sequence to 16,000 data points). It is worth noting that many practical applications of machine learning that deal with sequence data, the predicted sequence y should in general be of similar length as the template or input sequence X. If the predicted sequence is significantly longer or shorter than expectation, it is important to understand if upsampling steps are implemented correctly, or hyper-parameters for upsampling are chosen appropriately.

### 5.3.1 Scaled-Dot Product Attention

Transformer models introduced by the paper “Attention Is All You Need” [Vaswani et al., 2017] are probably the most successful type of sequence model by far. It has been used widely in modeling sequence data such as texts, audio, and images, for tasks including natural language understanding [Devlin et al., 2019], speech recognition [Gulati et al., 2020], singing voice synthesis [Liu et al., 2021], and image recognition [Dosovitskiy et al., 2021]. A key component of transformer models is the Scaled Dot-Product Attention mechanism, which teaches the model which part of the sequence to focus the learning on. Scaled Dot-Product Attention is defined as

$$A(Q, K, V) = \text{softmax} \left( \frac{QK^T}{\sqrt{d_k}} \right) V$$ (5.1)

where

- Q, K, V are the query, key, and value sequence.
- d_k is the “depth” or embedding dimensions of the keys.
- softmax(·) is the softmax activation function, defined as σ(xᵢ) = exp(xᵢ) / Σⱼ exp(xⱼ).

In Equation 5.1, query and key first perform a dot product QK^T before scaled by the square root of the depth of the key √d_k. Then, the computed attention score is transformed with the softmax function to convert into probabilities and applied to the value sequence via tensor multiplication.

In addition, there are two major flavors of this attention mechanism:

- **Self-attention**: key, query, and value are all the same sequence inputs. The attention weights are computed within the sequence itself, between pairs of its own elements.
- **Cross-attention**: key, query, and value are not the same sequence. Here, elements in the key and query sequences need to have identical embedding or so-called depth dimensions, while key and value need to have identical sequence lengths. Attention weights are computed between two distinct sequences represented by key and query and applied to a third sequence represented by value.

There are two major flavors of self-attention (see Figure 5.13):

- **Bidirectional self-attention**: A single token within the sequence can attend to not only the tokens coming before it (and itself) but also the tokens coming after it. This type of self-attention is implemented as part of the Encoder layers of the Transformer model, where all the contexts surrounding the current token help inform the model.
- **Causal self-attention**: A single token within the sequence can only attend to the tokens coming before it (and itself). This type of self-attention is implemented as part of the Decoder layers of the Transformer model, where only the historical token sequences are used to predict the tokens coming next.
