Notes:
a) NumPy does not implement a safe divide operation, but one can use np.divide(a, b, out=np.zeros_like(b), where=b!=0) to achieve the same effect as tf.divide_no_nan
b) PyTorch does not implement the safe divide operation, but one can use torch.nan_to_num to fill the NaNs or infs in the quotient to zeros. NumPy also has a similar function np.nan_to_num.
c) Like the np.divide method, NumPy does not implement the safe reciprocal operation, but one can use np.reciprocal(x, out=np.zeros_like(x), where=x!=0) to achieve the same effect.
- d) Like the `divide` method, PyTorch also does not implement the safe reciprocal operation, but one can use `torch.nan_to_num` to fill the `NaN`s or `inf`s.
- e) `expm1(x)` is useful for computing the expression \(e^x - 1\) more accurately compared to `exp(x) - 1` when \(x \to 0\). A well known example is to compute annualized interest rate, \((1+x)^{t/y} - 1\), which can be expressed as \(\exp(t/y * \log1p(x)) - 1\), and implemented as `exp(t / y * np.log1p(x)) - 1` (see notes on example below).
- f) Tensorflow does not implement log bases other than e, but one can use e.g. `math.log(x) / tf.math.log(base)` to convert bases.
- g) `log1p(x)` is useful for computing the expression \(\log(1 + x)\) more accurately compared to `log(1 + x)` when \(x \to 0\). Well-known examples include computing annualized interest rate, \((1+x)^{t/y} - 1\) which can be expressed as \(\exp(t/y * \log1p(x)) - 1\), and implementation of inverse hyperbolic functions. For example, \(\text{arctanh}(x) = \frac{1}{2} \log(\frac{1+x}{1-x})\) can be implemented as \(0.5 * (\log1p(x) - \log1p(-x))\).
- h) `logaddexp` is useful for computing the expression \(\log(\exp(x_1) + \exp(x_2))\) more accurately when x is extremely large or extremely small. This is a special case of `logsumexp` (see notes below).
- i) `logsumexp` is a more general implementation of the above `logaddexp`, which can operate on more than two numbers, computing the expressions \(\log(\sum_i \exp(x_i))\). Notice that the summation expression is the normalization term for the softmax loss function in maximum-likelihood estimation \(p_j = \text{softmax}(x)_j = \frac{\exp(x_j)}{\sum_i \exp(x_i)}\), and the log probabilities then have form \(\log(p_j) = x_j - \log(\sum_i \exp(x_i))\). NumPy does not have a native implementation of this function, but it can be found in Scipy's `scipy.special.logsumexp`, using the so-called log-sum-exp trick [Wikipedia, 2023]:

![](img/e891acaacd4fb5b80dab2ed824618203_50_0.png)

where \(x_{\max} = \max(x_0, x_1, \dots, x_p)\). A naive implementation is

```
import numpy as np
def logsumexp(x):
    x_max = np.max(x)
    return np.log(np.exp(x - x_max).sum()) + x_max
```

j) You may wonder why we even need to have a specific function for computing the square of a number, instead of simply using `x ** 2`. This is all about performance. It turns out that is faster to compute `x * x` than `pow(x, 2)`. Having a specialized square function is convenient for implementing something like `this_is_a_variable_with_super_long_name, e.g. See this issue [Paszke et al., 2023a] in PyTorch's repository.

k) Python complex numbers can be constructed as `<real> + <imag>j`, e.g. `1 + 2j` (notice no spaces between `2` and `j`). This is why I typically do not use `j` as indices when writing a for-loop since it may be confused with Python's reserved variable for the imaginary number.

> You may notice that, for Tensorflow operations, some functions are under the tf module and some are under the tf.math module. This is because, although all are implemented under the tf.math module, some frequently used functions are aliased under the main tf module for ease of access. You can verify this by printing out the module path. For example, tf.math.abs and tf.abs both refer to the operation <function tensorflow.python.ops.math_ops.abs(x, name=None)>.

PyTorch has many of these operations implemented as methods on its torch.Tensor class. Therefore, instead of using the function from the main module, one can call the corresponding methods on the array/tensor instances. For example, instead of torch.abs(x), we can do x.abs(). This makes PyTorch more object-oriented.

## 2.4 Reduction Operations

Reduction (or reduce) operations are mathematical operations that summarize a set of values into a single value. It “reduces” the size of the tensor, from higher-dimensional to lower-dimensional, or single scalars. Table 2.4 lists examples of reduction operations.

NumPy and PyTorch also have many of these reduction operations implemented as methods on their respective np.ndarray and torch.Tensor classes. Therefore, instead of using the function from the main module, one can call the corresponding methods on the array/tensor instances. For example, instead of np.sum(x) or torch.sum(x), we can do x.sum(). TensorFlow is more function-oriented and does not have these reduction operations implemented on its tf.Tensor class, likely because it needs to support the construction of computational graphs by tracing through function calls.
