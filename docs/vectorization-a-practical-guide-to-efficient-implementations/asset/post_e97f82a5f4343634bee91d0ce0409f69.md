## 10 Sorting and Reordering

Whether it is processing of continuous time series or analysis of other forms of sequentially represented discrete data, it is usually more efficient to process the sequence data in a batch rather than using for-loops to apply the processing logic one sequence at a time. Sequence data are often represented as dense tensors if all sequences are having the same length. However, not all sequences have the same length, and therefore, sequence data are often represented as a dense tensor with paddings (whose data entries can be determined by a padding mask), or left-aligned ragged or sparse tensors. In this chapter, we will focus on several case studies on various ways to sort and reorder a batch of variable-length sequence data. We will use all the knowledge we have gained so far on vectorization to implement solutions to these problems.

> Typically, Tensorflow represents a batch of sequence data as a tensor of shape `(batch_size, seq_len, <embed_size> ...)`, while PyTorch represents it with shape `(batch_size, <embed_size> ..., seq_len)`. This is a small detail on the different conventions used by the libraries. In this chapter, I will use the Tensorflow convention in our sample code examples, but implementing the PyTorch convention can be achieved relatively easily by transposing the tensors properly.

### 10.1 Sorting Operations

**Sorting** is a basic operation in computer science that rearranges the elements within an array according to certain ordering rules. Table 10.1 provides a list of equivalent sorting operations implemented in NumPy, Tensorflow, and PyTorch.

### Table 10.1 List of sorting operations in NumPy, Tensorflow, and PyTorch.

| Operation | NumPy | Tensorflow | PyTorch |
| :--- | :--- | :--- | :--- |
| Sorting^a) | np.sort | tf.sort | torch.sort |
| Indices to sort an array^a) | np.argsort | tf.argsort | torch.argsort |
| Lexicographical sorting^b) | np.lexsort | N/A | N/A |
| Unique values/indices^c) | np.unique | tf.unique, tf.unique_with_counts | torch.unique |
| Max value^d) | np.max | tf.reduce_max | torch.max |
| Index of the max value^d) | np.argmax | tf.argmax | torch.argmax |
| Min value^d) | np.min | tf.reduce_min | torch.min |
| Index of the min value^d) | np.argmin | tf.argmin | torch.argmin |
| Top K min/max values^c) | N/A | tf.math.top_k | torch.topk |
| Partitioning^f) | np.partition | N/A | N/A |
| Indices to partition an array^f) | np.argpartition | N/A | N/A |
| Insertion index of sorted array^g) | np.searchsorted | tf.searchsorted | torch.searchsorted |

Notes:
a) The `.sort` operation sorts the array in ascending order (from smallest to largest) by default. In Tensorflow and PyTorch's implementations, however, users can specify arguments to sort descendingly (from largest to smallest). For Tensorflow, this is `tf.sort(direction="DESCENDING")`, and for PyTorch, this is `torch.sort(descending=True)`. For NumPy, we can reverse the sorted order with `[:, -1]`. The `.argsort` operation returns the indices that can be used to sort the original array.
b) `np.lexsort` is unique to NumPy. It sorts a set of arrays together based on the keys specified. In one of the following case studies, we will see how we can use `np.lexsort` to sort rows of a matrix.
c) The `.unique` operation returns the unique set of contents. It can also return:
- indices that can be used to convert the original tensor to the unique set. In NumPy, this is to set `return_index=True`; in Tensorflow, this is to use `tf.unique` and use the second returned output. PyTorch does not seem to implement this functionality at the time of writing this chapter.
- indices to recover the original tensor from the unique set. In NumPy and PyTorch, this is to set `return_inverse=True`. In Tensorflow, this is to call `tf.unique_with_counts` and use the second returned output.
