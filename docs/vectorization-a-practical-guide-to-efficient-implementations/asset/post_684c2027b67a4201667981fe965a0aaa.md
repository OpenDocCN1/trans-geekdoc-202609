- __init__ **method**: Initializes the layer subclass
  - num_channels stores the embedding dimension size, since later in the call method, we will need to reshape the embedding tensors. It is indeed also possible to determine the embedding dimension size from the input dynamically.
  - max_len stores the maximum audio sequence length. If the user specified a value greater than zero, then the output will have this sequence length, instead of being dynamically determined from the inputs.
- The call method implements the main logic of the Length Regulator module, given a batch of token sequence embeddings, as well as the durations of each token pronunciation as the number of mel-spectrogram frames.
  - token_embedding has the shape [batch_size, seq_len, num_channels] and has dtype tf.float32. The padding token should correspond to 0 valued embedding vectors.
  - spect_durations has shape [batch_size, seq_len]. Padding tokens have 0 durations.
  - Line 44 first rounds off the durations to integers. This is because, during inference time, another module of the FastSpeech2 model will also make a prediction of the duration of the tokens, which will not necessarily be integers. This line makes sure that in the subsequent operations, we are dealing with the number of mel-spectrogram frames expressed as integers.
  - Lines 45 and 46 compute how many times each token embedding needs to be repeated. This is again an inference-time consideration: we need to repeat any token in the sequence at least once. We will encounter two scenarios where the duration can be 0 during inference time:
    1. The duration of pronunciation is predicted to be short so we rounded to 0 durations at inference time.
    2. We are dealing with paddings at the end of the sequence. In this case, the values of the embedding vectors for the padding token should be all zeros. Even if we leave the zero paddings around, the model should be able to learn not to generate any audio on top of it. Toward the end of the call function, we will do extra cleaning to remove these paddings.
  - Lines 49–52 store some shapes which we will leverage later on to reshape our inputs. This also includes pre-computing the expected duration of the audio (max_durations).
  - Lines 54–56 reshape the batch of token sequence embeddings into shape [batch_size x seq_len, num_channels]. This turns the 3D tensor into a stack of embedding vectors, which we will then use the tf.repeat operation to repeat/upsample the vectors.
  - Line 57 reshapes the batch of durations into a 1D array of [batch_size x seq_len]. This new array will indicate how many times each piece of embedding vectors from hidden_states (Lines 54–56) needs to be repeated.
  - Line 60 performs the tiling/repetition operation. We now should have a stack of embedding vectors of shape [batch_size x time_len, num_channels].
  - Lines 63–73 implement a scattering logic to reshape the stack of repeated embedding vectors back into the shape of [batch_size, time_len, num_channels]. Because our repeated embedding vectors are organized in the shape of [batch_size x time_len, num_channels], we need to reshape the first dimension and split them into two separate dimensions, i.e. [batch_size, time_len]. Since this is a 2D matrix, we use the terminology row to indicate the batch dimension and col to indicate time_len here:
    - row_indices: This is the index of the batch dimension. It is constructed with two steps of tf.repeat operations. We first construct the batch index [0, 1, ..., batch_size]. We then repeat each batch index by the sequence length. That way, we are assigning a batch index to each token embedding, which becomes [0, 0, ..., 1, 1, ..., batch_size, batch_size, ...]. Finally, since each token embedding vector is repeated duration times (Line 60), we also repeat the batch index by that many times corresponding to each token. This should give us an array whose length is identical to the second dimension (axis=1) of hidden_states that we obtained from Line 60.
    - col_indices: This is the index of the time dimension, which is constructed by our helper function tf_ragged_range. For each batch, we enumerate the vectors one by one, assigning an index [ 0, 1, 2, 3, ..., batch_0_duration, 0, 1, 2, 3, ..., batch_1_duration, ...]. The batch_duration variable we computed earlier tells us how many frames the current sequence should have.
  - Lines 68-73 utilize the indices we computed to re-create the tensor of shape [batch_size, time_len, num_channels]. The scatter operation will automatically leave zero paddings to accommodate the representation of variable length sequences.
  - Lines 75-89 implement the same scattering logic, except now it is operating on a tensor of shape [batch_size, time_len, 1].
  - Lines 92-94 remove any extraneous padding zeros beyond the expected duration as indicated by spect_durations.
