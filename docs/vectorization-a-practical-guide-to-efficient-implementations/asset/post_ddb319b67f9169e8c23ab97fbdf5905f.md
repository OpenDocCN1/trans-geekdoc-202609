## 7.5 Sparse Matrix in Other Python Libraries

In addition to the sparse matrix implementations in Scipy, Tensorflow, and PyTorch, other Python libraries also have sparse data structure implemented, including but not limited to:

- pandas: Implemented as types `SparseArray` and `SparseDataFrame`, similar to `coo`, and interfaces with `scipy.sparse.coo_matrix` very well.
  - conversion from pandas to `scipy.sparse.coo_matrix` with `df.sparse.to_coo()`
  - conversion to pandas from `scipy.sparse.coo_matrix` with `pd.Series.sparse.from_coo()`
- pyspark: `pyspark.mllib.linalg.SparseMatrix`, default `csc` format. But when the matrix is transposed by setting the argument `isTransposed=True`, this sparse matrix can be viewed as `csr` format.
- pyarrow: pyarrow supports `coo` (`pyarrow.SparseCOOTensor`), `csr` (`pyarrow.SparseCSRTensor`), `csc` (`pyarrow.SparseCSCTensor`), and `csf` (`pyarrow.SparseCSFTensor`, or Compressed Sparse Fiber [Nisa et al., 2019]) format. `pyarrow` is an efficient library for big data operations and integrates tightly with `numpy` and `pandas`.

## 7.6 When (Not) to Use Sparse Matrix

Data sparsity is the key to deciding if we should be using a sparse matrix or a dense matrix to represent our data. In general, the space complexity of a multidimensional sparse tensor is O((d + 1)N), where N is the size of the data and d is the number of dimensions of the tensor. In the case of a two-dimensional matrix, we need to store three times the information about the data. We need 2N of spaces to store the row and column indices, and another space of size N to store the data itself. As a rule of thumb, when the data sparsity is <33% (i.e., only less than one-third of the matrix is filled with non-missing values), then it is probably more efficient to represent the data using a sparse matrix rather than a dense tensor.

## 7.7 Case Study: Sparse Matrix Factorization with ALS

In this case study, we will implement the classic recommender system algorithm matrix factorization. The matrix factorization problem is solved numerically by using the method called **alternating least squares (ALS)** [Bell and Koren, 2009].

### 7.7.1 Matrix Factorization

Let the user-item rating matrix $R$ be of shape $N \times M$, where there are $N$ users and $M$ items. $R$ can be approximated by $\hat{R}$, which is a product of two smaller matrices $U$ ($N \times K$) and $W$ ($M \times K$), i.e.

$R \approx \hat{R} = UW^T$

where $U$ is usually called the user matrix (encoding $N$ users), whereas $W$ is the item matrix (encoding $M$ items). $K$ is the number of latent features, which is usually between 10 and 50. Note that our data is arranged as row vectors rather than column vectors that are more commonly used in mathematical derivations.

At prediction time, suppose we want to find the rating for $i$th user and $j$th item, then we only need to calculate

$\hat{r}_{ij} = \vec{u}_i \cdot \vec{w}_j^T$

where $\vec{u}_i, \vec{w}_j$ are length $K$ vectors of user $i$ and item $j$, respectively.

### Interpretation

Suppose we have $K = 5$ explicit features, where

- $K = 1$ Action/adventure
- $K = 2$ Comedy
- $K = 3$ Romance
- $K = 4$ Horror
- $K = 5$ Animation

then,

- $u_{i,1}$ means how much user $i$ likes Action/adventure
- $u_{i,2}$ means how much user $i$ likes Comedy
- $w_{j,1}$ means how much movie $j$ contains Action/adventure
- $w_{j,2}$ means how much movie $j$ contains Comedy

Then, the dot product

$\hat{r}_{ij} = \vec{u}_i \cdot \vec{w}_j^T = \|\vec{u}_i\| \|\vec{w}_j\| \cos \theta \propto \text{Similarity}(i,j)$

means how much user $i$ is correlated with movie $j$.

However, in practice, the features are usually **latent**.

### 7.7.2 Parameter Updates with ALS

The loss function for this regression problem is the sum-squared error

$J = \sum_{i,j \in \Omega} (r_{ij} - \hat{r}_{ij})^2 = \sum_{i,j \in \Omega} (r_{ij} - \vec{u}_i \vec{w}_j^T)^2$

We want to minimize \(J\). By setting the gradients as zero, we have

\(\frac{\partial J}{\partial u_i} = 2 \sum_{j \in \Psi_i} (r_{ij} - \vec{u}_i \vec{w}_j^T)(-\vec{w}_j) = 0\)

\(\sum_{j \in \Psi_i} r_j(-\vec{w}_j) - \sum_{j \in \Psi_i} (\vec{u}_i \vec{w}_j^T)(-\vec{w}_j) = 0\)

\(\sum_{j \in \Psi_i} (\vec{u}_i \vec{w}_j^T)\vec{w}_j = \sum_{j \in \Psi_i} r_j \vec{w}_j\)

\(\sum_{j \in \Psi_i} \vec{u}_i (\vec{w}_j^T \vec{w}_j) = \sum_{j \in \Psi_i} r_j \vec{w}_j\)

\(\vec{u}_i \left( \sum_{j \in \Psi_i} \vec{w}_j^T \vec{w}_j \right) = \sum_{j \in \Psi_i} r_j \vec{w}_j\)

Notice that \(\vec{w}_j^T \vec{w}_j\) is an outer product. Also, notice that the last step is in the form of \(AX = b\) (if \(X\) is column vector, or \(XA = b\) is \(X\) is a row vector).

We can invert the matrix \(A = \sum_{j \in \Psi_i} \vec{w}_j^T \vec{w}_j\) part to solve for \(\vec{u}_i\), yielding

\(\vec{u}_i = \sum_{j \in \Psi_i} r_{ij} \vec{w}_j \left( \sum_{j \in \Psi_i} \vec{w}_j^T \vec{w}_j \right)^{-1}\)

Numerically, we can take advantage of numpy's `np.linalg.solve(A, b)` function to solve for \(\vec{u}_i\).

To solve for \(w_j\), we yield similar results

\(\vec{w}_j = \sum_{i \in \Omega_j} r_{ij} \vec{u}_i \left( \sum_{i \in \Omega_j} \vec{u}_i^T \vec{u}_i \right)^{-1}\)

We apply the isolated \(u_i\) and \(w_j\) updates iteratively to minimize the loss function \(J\). This is called **alternating least squares (ALS)**. We first initialize \(u_i\) and \(w_j\) randomly, then update according to the equations we obtained.

### 7.7.3 Adding Bias Terms to Matrix Factorization

Recall that in our collaborative filtering, we have the similarity measure as

\(s(i, j) = \bar{r}_i + \frac{\sum_{l' \in \Omega_j} w_{il'}(r_{il'} - \bar{r}_{l'})}{\sum_{l' \in \Omega_j} \| w_{il'} \|}\)

where we have the bias term \(\bar{r}_i\). Thus, we revised the rating as

\(\hat{r}_{ij} = \vec{u}_i \cdot \vec{w}_j^T + b_t + c_j + \mu\)
