```
print(y[0, :, 0])
# array([3, 1, 0, 4, 2])
print(y[1:, :, 2])
# array([-3, -5, -4, -2, -1])
print(y[2:, :, 1])
# array([60, 20, 30, 40, 50])
```

We can easily verify that

+   * `np.take(X[0, :, 0], reorder_index[0, :, 0]) == y[0, :, 0];`
+   * `np.take(X[1, :, 2], reorder_index[1, :, 2]) == y[1, :, 2];`
+   * `np.take(X[2, :, 1], reorder_index[2, :, 1]) == y[2, :, 1];`
+   * `...etc.`

In general,

```
for ii in range(X.shape[0]):
    for jj in range(X.shape[2]):
        assert np.allclose(
            np.take(X[ii, :, jj], reorder_index[ii, :, jj]),
            y[ii, :, jj],
        )
```

Hence, `take_along_axis` is the vectorized version of `take` operation where it parallelizes the process of element selections from 1D vectors across batches (which may be arranged over multiple dimensions).

# ### 3.4.3 Gather

The `gather` operation is an alternative implementation of `take` and `take_along_axis` operations. Tensorflow and PyTorch implement the `gather` operation differently. `tf.gather` always selects the elements or slices along a certain dimension, specified by `axis`, which defaults to `None`. The value of `axis` is dependent on another argument, `batch_dims` (the number of batch dimensions starting from axis 0; this is not to specify which dimensions or axes are the batch dimensions), which defaults to `0`. It is necessary that `axis >= batch_dims` and `batch_dims <= index.ndim`. Despite the name, PyTorch's `torch.gather`, on the other hand, selects only single elements at a time given each index instead of selecting slices via broadcasting (i.e., `X` and `indices` do not broadcast). As a consequence, the results of `torch.gather` have the same shape as `indices`. Also, like `np.take_along_axis`, `torch.gather` requires the input `X` and `indices`
