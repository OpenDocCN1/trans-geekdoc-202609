
![](img/e891acaacd4fb5b80dab2ed824618203_128_0.png)

```python
import tensorflow as tf
values = tf.random.uniform((2, 3, 4))
indices = tf.constant([3, 0])[:, None]
X = tf.scatter_nd(indices, values, shape=(5, 3, 4))
```

In general, we can split the final target tensor shape into two parts: leading batch dimensions and lagging slice dimensions (Tensorflow's documentation also calls these outer dimensions and inner dimensions, respectively [Abadi et al., 2023d]). In the above example, the target tensor has a shape of (5, 3, 4), with the batch dimension as (5,) and slice dimension as (3, 4). We can observe that (i) the size of the first dimension (batch dimension) of values (used for updating the target tensor) is the same as the size of the first dimension of the indices; (ii) the size of the last two dimensions of the values are the same as the last two dimensions of the target tensor X; (iii) the size of the last dimension of the indices indicates how many dimensions the slices should have. By inductive reasoning, we can attempt an even more general example, where we want to rearrange the list of slices into multi-dimensional batches within the target tensor, as illustrated in Figure 3.18. The concept of scattering slices also applies to NumPy's np.ufunc.at and PyTorch's torch.index_put, with exactly the same behavior.

```python
import tensorflow as tf
values = tf.random.uniform((2, 3, 4))
indices = tf.constant([[1, 0], [0, 1]]) # (2, 2)
X = tf.scatter_nd(indices, values, shape=(2, 2, 3, 4))
```

Tensorflow's tf.scatter_nd further generalizes the concept of batching, where the batch dimensions of the values and indices can also be arranged into multiple dimensions rather than staying as a flat list of slices or indices.

![](img/e891acaacd4fb5b80dab2ed824618203_129_0.png)

Figure 3.18 Illustration of scattering slices into multiple batch dimensions of the target tensor. The leading two batch dimensions are unfolded into a 2 x 2 grid in this schematic representation. The first slice is being put in position (1, 0) (second row, first column) of the 2 x 2 grid; the second slice is being put in position (0, 1) (first row, second column) of the 2 x 2 grid.

We only need to make sure that the leading batch dimensions for values and indices match exactly. Nonetheless, the tf.scatter_nd operation will still treat the multi-dimensional arrangement of batches of slices as if it were a flattened list of slices. This generalization is only for the sake of convenience when the input data batches are already arranged into multiple dimensions.

```python
import tensorflow as tf
values = tf.random.uniform((4, 3, 4))
indices = tf.constant([
    [1, 0],
    [0, 1],
    [0, 0],
    [2, 2],
]) # (4, 2)
shape = (3, 3, 3, 4)
X = tf.scatter_nd(indices, values, shape=shape)
# fold indices and values into a 2 x 2 grid -> (2, 2, 2)
folded_indices = tf.reshape(indices, (2, 2, 2))
folded_values = tf.reshape(values, (2, 2, 3, 4))
X_folded = tf.scatter_nd(indices, values, shape=shape)
# same output results
assert np.allclose(X, X_folded)
```

## 3.6.4 Additional Scatter Operations from PyTorch

PyTorch implements two additional methods for accumulation, i.e. torch.scatter_reduce [Paszke et al., 2023c] and torch.index_reduce [Paszke et al., 2023b]. Both methods are currently in beta at the time of writing. torch.scatter_reduce is a generalization of torch.scatter while torch.index_reduce complements torch.index_add to allow additional scatter-reduction methods including prod, mean, max, or min to be implemented. The usage pattern and the logic of the operation are not identical to that of tf.tensor_scatter_nd_reduce or np.ufunc.at for accumulation. In this section, I attempt to explain the differences between the two operations.

After comparing the equivalent Python for-loop equivalent code from the documentations for torch.Tensor.scatter_reduce [Paszke et al., 2023c] (the in-place version of torch.scatter_reduce) and torch.gather [Paszke et al., 2023a], we can deduce that these two operations follow the same formulation. In general, indices, values, and target X should have the same number of dimensions, i.e. indices.ndim == values.ndim == X.ndim. It is also required that the size of indices is no greater than the size of input X or the scattering values at the corresponding axis dimensions, i.e. indices.shape[dim] <= X.shape[dim] and indices.shape[dim] <= values.shape[dim]. This means, we can specify an index that is shorter than the size of the inputs or the scattered values; the extra elements will be ignored during the scattering operation. Let us construct the following examples on how we can use torch.scatter_reduce, and see how similar it was to torch.gather (see also illustration in Figure 3.19):

![](img/e891acaacd4fb5b80dab2ed824618203_130_0.png)

Figure 3.19 Illustration of torch.scatter_reduce on 2D matrices. (a) Scattering along dim=0; (b) Scattering along dim=1.

### Example 3.1 Scattering along dim=0.

```python
import torch
values = torch.tensor([
    [3, 8, 2, 1, 4],
    [5, 4, 7, 6, 2],
    # [1, 3, 2, 4, 6], this extra row will be ignored
], dtype=int)
indices = torch.tensor([
    [1, 2, 3, 0, 1],
    [2, 1, 0, 3, 2],
])
# Scatter along dim=0
X = torch.zeros((4, 5), dtype=int)
Y = torch.scatter_reduce(
    input=X, dim=0, index=indices, src=values, reduce="sum"
)
# tensor([[0, 0, 7, 1, 0],
#         [3, 4, 0, 0, 4],
#         [5, 8, 0, 0, 2],
#         [0, 0, 2, 6, 0]])
# Not exactly matching the full columns:
# indices will be left aligned
Y = torch.scatter_reduce(
    input=X,
    dim=0,
    index=indices[:, :-1],
    src=values[:, :-1],
    reduce="sum",
)
# tensor([[0, 0, 7, 1, 0],
#         [3, 4, 0, 0, 0],
#         [5, 8, 0, 0, 0],
#         [0, 0, 2, 6, 0]])
```

### Example 3.2 Scattering along dim=1.

```python

    [3, 7],
    [8, 6],
    [4, 2],
    [5, 9],

# [8, 0, 0, 6, 0],
# [2, 0, 0, 0, 4],
# [0, 9, 5, 0, 0]])

# [8, 0, 0, 6, 0],
# [2, 0, 0, 0, 4],
# [0, 0, 0, 0, 0]])
```

On the other hand, torch.index_reduce resembles the slice scattering operation as we have seen in tf.scatter_nd. It also can be seen as the opposite operation of torch.take_along_dim, as it scatters the slices only along a certain dimension, using the 1D vector indices within that dimension. We can also compare it with NumPy's np.put_along_axis, though it has additional accumulation methods while lacking broadcasting capability since the indices must be a 1D vector. torch.index_reduce also requires the values and the target X having the same number of dimensions.
