+   • However, putting the ellipsis operator `...` in the `np.s_` method is also valid here, which indicates that the slices across the omitted dimensions select all items within the dimension. This is just how ellipsis operator is being used previously. When `...` is used to construct multidimensional slices, the elided dimensions will be represented as Python's `Ellipsis` constant, e.g. (`slice(start_0, stop_0, step_0)`, `slice(start_1, stop_1, step_2)`, `Ellipsis`, `slice(start_3, stop_3, step_3)`).

Once we have built the `slice` configuration object, we can apply the slicing logic the same way as we did before, e.g.

```
import numpy as np
X = np.random.rand(5, 8, 6)
Y = np.random.rand(3, 9, 7)
Y
# Build the slice object
s = np.s_[:4, 2:4, 5:]
# Shape may not necessarily be identical
print(X[s].shape) # shape (4, 2, 1)
print(Y[s].shape) # shape (3, 2, 2)
```

You may notice that the first dimension of tensor Y is of size 3 but we are slicing four items. Yet, the program did not throw an error, and returned three items in the first dimension, less than the four items asked by the slice. In general, Python’s tensor slicing will take as many elements it can as possible; so if we specify the slice to take up to a `stop` index beyond the size of the tensor’s dimension, it will return only whatever elements it can take in the slice. **Taking a single element at a position beyond the length of the array will throw an error**. To illustrate this behavior in another set of examples,

```
x = [1, 2, 3, 4, 5]
# stop beyond the size of the array
print(x[:7]) # [1, 2, 3, 4, 5]
# stop beyond the size of the array, stride 2
print(x[:7:2]) # [1, 3, 5]
# empty, no elements to take
# since the slice is beyond the length of the array
print(x[6:8]) # []
```
