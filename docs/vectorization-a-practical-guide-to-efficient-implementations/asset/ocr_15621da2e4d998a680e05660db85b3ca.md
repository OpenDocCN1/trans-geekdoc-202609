It is also interesting to see how Tensorflow handles (or perhaps is not able to handle) the multi-element indexing when X is a 1D vector. This works in both NumPy and PyTorch, but not in TensorFlow. If X is a tf.Tensor, then X[[0, 2]] throws the following error:

# 3.1.2 Flat Index vs. Multi-index

For matrices (2D) or higher-dimensional tensors, there are in general two conventions to represent the indices of the elements: **flat index** (a.k.a. linear index) and **multi-index**. The examples we have seen in Section 3.1.1 were using multi-index, which points to the spatial coordinate of the elements across multiple dimensions and represents the indices as a list of integers (each one corresponding to each dimension of the tensor). In contrast, flat indices enumerate the elements from 0 up to the number of elements in the tensor and represent each index as a single integer. As illustrated in Figure 3.3, suppose we have a 3 × 4 2D matrix, which has 12 elements. The flat index enumerates the elements one by one using indices from 0 to 11. In Chapter 2, we briefly discussed the “C” order and “F” order conventions when introducing reshaping operations. So depending on the ordering convention used by the matrix, there are two ways to specify the indices, either along the rows (row-major “C” ordering) or along the columns (column-major “F” ordering). In the case of “C” ordering, flat indices [0, 1, 2, ⋯, 11] correspond to (0, 0), (0, 1), (0, 2), ⋯, (1, 0), (1, 1), ⋯, (2, 3), where the indices along the second dimension increase first; in the case of “F” ordering, flat indices [0, 1, 2, ⋯, 11] correspond to (0, 0), (1, 0), (2, 0), ⋯, (0, 1), (1, 1), ⋯ , (2, 3), where the indices along the first dimension increase first.
