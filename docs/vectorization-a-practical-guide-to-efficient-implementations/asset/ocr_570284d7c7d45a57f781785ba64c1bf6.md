# **Table 9.2 List of groupwise aggregation operations in NumPy, Tensorflow, and PyTorch.**

| Operation | NumPy | Tensorflow | PyTorch |
|---|---|---|---|
| Groupwise sum<sup>a)</sup> | np.add.reducat | tf.math.segment_sum, tf.math.unsorted_segment_sum, tf.sparse.segment_sum | torch.scatter_add, torch.scatter_reduce(..., reduce="sum"), torch.segment_reduce(arr, "sum", offsets) |

Notes:
• **Start-end indices**: This is reminiscent of `car_matrix` `indptr` property from Scipy, where an array of ascending integer indices indicates the starts and ends of each segment along a flattened array. This also assumes the elements of the same group are adjacent to each other. When working with NumPy's groupwise operations `np.ufunc.reduceat`, the value to the indices argument is an array of starting indices of each segment, signifying the slices to aggregate (this means, it does not have to be strictly monotonically increasing). It assumes the last segment starts from the last element of `indices` to the last element of the array, i.e. `data[indices[-1]:]`. `indices` here is also equivalent to `indptr[:-1]` which excludes the last element that denotes the end of the segment. Example usage:

```
1
import numpy as np
2
data = np.array([1, 2, 3, 2, 3, 4, 5, 4, 7, 2, 8, 31])
3
indices = np.array([0, 3, 6])
4
res_np = np.add.reduceat(data, indices)
5
# sum(data[0:3]), sum(data[3:6]), sum(data[6:])
6
# array([ 6, 11, 20])
7
8
# non-monotonically increasing indices
9
indices = np.array([0, 3, 2, 6])
10
res_np = np.add.reduceat(data, indices)
11
# sum(data[0:3]), sum(data[3]), sum(data[2:6]), sum(data[6:])
12
# array([ 6, 2, 14, 20])
```

In the case of non-monotonically increasing indices, the second slice [3:2] is interpreted as [3], which then takes the element at index 3 only. Therefore, there is no good way to create segments with zero elements. On the other hand, PyTorch's torch.segment_reduce operation has two arguments to indicate the start and end indices: – offsets: Unlike NumPy, the value to this argument needs to include the end index of the last segment, just like the indptr property of csr_matrix. Unlike the indices argument of np.ufunc.reducat, the offsets property needs to be strictly monotonically increasing, since offsets is being used to compute the length of the segments.
