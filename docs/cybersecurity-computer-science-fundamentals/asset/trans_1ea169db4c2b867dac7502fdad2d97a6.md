## 常见 Web 应用漏洞（SQL 注入、XSS）

“Web 应用安全”模块中的“常见 Web 应用漏洞”章节旨在深入剖析困扰 Web 应用的两种最普遍、最危险的漏洞：SQL 注入和跨站脚本攻击（XSS）。对于负责保障 Web 应用安全的任何人员而言，理解这些漏洞、其影响及其基于代码的利用方式至关重要。

### SQL 注入：利用不当的输入处理

SQL 注入是一种普遍存在的漏洞，当 Web 应用在将用户输入纳入 SQL 查询前未能妥善清理时就会发生。攻击者可向输入字段注入恶意 SQL 代码，从而可能未经授权访问数据库或篡改数据。基于代码的示例演示了 SQL 注入的后果及利用过程。

```python
# 示例：展示存在漏洞的 SQL 查询的 Python 代码
user_input = "'; DROP TABLE users--"
query = f"SELECT * FROM products WHERE name = '{user_input}'"
```

### 跨站脚本攻击（XSS）：注入恶意脚本

当 Web 应用允许将恶意脚本注入到其他用户查看的网页中时，就会产生 XSS 漏洞。攻击者可窃取 Cookie、会话数据，或将用户重定向至恶意网站。基于代码的 XSS 示例展示了攻击者如何向存在漏洞的应用注入脚本。

```javascript
// 示例：演示简单 XSS 攻击的 JavaScript 代码
const maliciousScript = `<script>alert('XSS Attack');</script>`;
document.getElementById('comment').innerHTML = maliciousScript;
```

### 影响与缓解：基于代码的防御

理解这些漏洞基于代码的利用方式是有效缓解的第一步。本模块涵盖缓解技术，包括输入验证、数据库查询的预处理语句以及输出编码，以防范 SQL 注入和 XSS 攻击。

```python
# 示例：使用预处理语句防止 SQL 注入的 Python 代码
user_input = "'; DROP TABLE users--"
cursor.execute("SELECT * FROM products WHERE name = %s", (user_input,))
```

### 安全编码实践：全方位方法

本模块强调涵盖前后端开发的安全编码实践。学员将学习实施安全响应头、采用内容安全策略（CSP）并强制执行输入验证，从而在应用技术栈的多个层面降低这些漏洞的风险。

理解并缓解 SQL 注入和 XSS 漏洞对 Web 应用安全至关重要。这些漏洞依然普遍存在，其被利用可能导致严重的数据泄露和隐私侵犯。通过基于代码的示例和实操练习，学员将获得保护 Web 应用免受这些普遍威胁的实战经验，确保在线服务的完整性与安全性。

## Web 服务器安全（HTTP 与 HTTPS）

“Web 应用安全”模块中的“Web 服务器安全”章节深入探讨了保护传输中数据以及在 Web 服务器与客户端之间建立信任的关键方面。本章节探讨了 HTTP 与 HTTPS 的显著差异，强调采用 HTTPS 保护敏感数据和确保通信安全的重要性。基于代码的示例和最佳实践对于理解和有效实施这些安全措施至关重要。

### HTTP：不安全的基础

HTTP（超文本传输协议）长期以来一直是 Web 通信的基础协议。然而，它缺乏基本的安全特性，使其易受各种攻击，包括窃听、中间人攻击和数据拦截。基于代码的演示展示了 HTTP 流量固有的不安全性及其易被拦截的特点。

```http
GET /login HTTP/1.1
Host: example.com
Connection: keep-alive
```

### HTTPS：确保数据机密性与完整性

HTTPS（超文本传输安全协议）通过使用 TLS/SSL 等协议加密传输中的数据，解决了 HTTP 的安全缺陷。这种加密保证了客户端与服务器之间交换数据的机密性和完整性。基于代码的示例展示了 HTTPS 如何通过加密通信来增强安全性。

```http
GET /login HTTP/1.1
Host: example.com
Connection: keep-alive
...
```

### TLS/SSL 证书：信任的基石

TLS/SSL 证书在建立 HTTPS 通信信任方面发挥着关键作用。这些数字证书将公钥绑定到 Web 服务器，确保客户端能够验证服务器的真实性。基于代码的实践包括在 Web 服务器上安装和配置证书以启用 HTTPS。

```bash
# 示例：生成 TLS 证书的 Bash 命令
openssl req -new -newkey rsa:2048 -days 365 -nodes -x509 -keyout server.key -out server.crt
```

### 强制使用 HTTPS：最佳实践

本模块重点介绍在 Web 应用中强制使用 HTTPS 的最佳实践。基于代码的示例演示了如何配置 Web 服务器将 HTTP 请求重定向到 HTTPS，确保所有流量均经过加密且安全。这些实践保护用户隐私和数据。

```apache
# 示例：强制 HTTPS 的 Apache 配置
<VirtualHost *:80>
    ServerName example.com
    Redirect / https://example.com/
</VirtualHost>
```

理解 HTTP 与 HTTPS 的对比及其基于代码的实现，对 Web 应用安全至关重要。实施 HTTPS 不再是可选项；它是保护用户数据、防止窃听、在日益互联和数据驱动的世界中建立信任的基本安全措施。
