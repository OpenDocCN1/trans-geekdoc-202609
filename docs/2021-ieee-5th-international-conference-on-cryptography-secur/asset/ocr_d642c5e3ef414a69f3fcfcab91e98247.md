# II. BACKGROUND

Blockchain Technology. In 2008, to maintain transaction orders and avoid the double payment problem of bitcoin, Nakamoto introduced the blockchain structure. The distributed features can be utilized in many areas to provide a strong level of network security and privacy preservation. Moreover, it can provide anonymous and transparent services without the participation of third parties or other verification organizations [10].

Inter-Planetary File System. The IPFS is a distributed file system in the form of Peer-to-Peer. It is also a hypermedia transmission protocol which is based on content addressing and able to avoid centralized failure due to the point-to-point architecture. The files are stored within the system as IPFS objects. We can enhance the availability of blockchain and IPFS by enabling off-chain storage and anonymous file sharing [11].

Local Sensitive Hashing. The Local Sensitive Hashing (LSH) [12] is used to map the datasets via their similarity. In specific, the similar data tend to be mapped into the same bucket, while for the dissimilar data, the different buckets. Various forms of LSH can be implemented according to different similarity calculation methods. In this paper, we use binary Min-Hash algorithm based on Jaccard similarity. The details of the algorithm can be found in Section 3.2. In this case, the similarity calculation formula for dataset A and B is defined as follows:

\(J(A, B) = \frac{|A \cap B|}{|A \cup B|}\) (1)

Local Differential Privacy. At present, differential privacy is commonly used in the centralized environment where data is collected into a central server. In this paper, we apply differential privacy directly at the users’ sides, precluding the malicious third-parties from obtaining the raw data with sensitive information and greatly enhancing the privacy preservation ability. In addition, the random response mechanism disables attackers to infer correct sensitive information from users. In this paper, we choose a local differential privacy algorithm based on Private Count Mean Sketch (PCMS [13]), the details of which can be found in section 3.3.

# III. OUR MECHANISM

In this section, we will describe the proposed mechanism based on blockchain in detail. More specifically, the mechanism consists three main procedures. At first, LSH clustering and local differential privacy are performed locally to each user, the obfuscated data is sent to IPFS for storage. After that, each user will get a unique hash value returned by IPFS, through which, the user can have access to the data again. Then, the outputs in

the last process along with other information, such as clustering results (i.e., bucket number), the hash value, the pseudonym and the current timestamp, are uploaded to the blockchain. Each user is responsible for recording those data. Therefore, users can pick up the similar hash values from the transaction data stored in blockchain. Finally, users obtain the obfuscated data for TOP-N recommendations from the IPFS via selected hash values. The illustration of the proposed mechanism is shown in Fig.1. More details are presented in the following subsection.

In the blockchain, genesis block contains the LSH function required for clustering, the dimension of the data and the hash function set for PCMS calculation. Each user is required to upload a pseudonym and a timestamp to distinguish whether it is the latest data because rating of the data is dynamic. In addition, the information is allowed to be uploaded only once at a certain time interval, which is decided by the application developer.

In traditional decentralized recommendation systems, the whole cost is dominated by the data transmission between users and the server, the cost of transaction process and transaction verification in blockchain is trivial in this case. In the proposed mechanism, we have much smaller-sized data (e.g., the hash values, the timestamp, and the pseudonym) to be transmitted between blockchain and users. Moreover, the LSH clustering and differential privacy process is executed in parallel among different users. Consequently, our mechanism shows high efficiency in various aspects. Furthermore, the inherent features (such as stability, robustness, and scalability) of blockchain [4] within our mechanism are not well supported by the traditional decentralized or centralized recommendation systems.
