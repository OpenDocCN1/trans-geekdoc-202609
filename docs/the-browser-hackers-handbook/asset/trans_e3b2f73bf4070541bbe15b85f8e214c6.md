
Google 例如为其 Chrome 浏览器实现了静默更新功能。16 用户没有被给予禁用该功能的选项，从而确保所有更新都能在及时的情况下通过用户干预自动应用。

一个显著的例子是，Google 利用静默更新功能在 Chrome 中部署其自研 PDF 渲染引擎，以取代 Adobe Reader 软件。这确保了 Chrome 的每个自动更新实例不再依赖于该第三方插件的更新过程。

现在的关键问题是：浏览器在后台自动更新和添加功能，如果操作不当，会显著增加每个浏览器的攻击面。这也迫使任何组织的安全团队向浏览器开发者外包一定程度的依赖。当浏览器开发者关注的领域与特定终端组织的需求不一致时，这种依赖会感到沮丧。

### Extensions

Extensions 提供一种无需独立软件即可增强浏览器行为的方法。它们可以影响浏览器加载的每一页，反之亦然——每一页都可能影响到它们。

每个扩展都为黑客提供了攻击目标，从而增加了浏览器的攻击面。在某些情况下，通用 XSS 漏洞甚至可以被引入该浏览器。你在 7 章中会进一步深入研究扩展及其漏洞。

### Plugins

插件通常是一个可以独立于浏览器运行的软件组件。与扩展不同，浏览器只有在 Web 应用通过 `<object>` 标签或在某些情况下通过内容类型头部将插件包含在页面中时才会运行插件。

有些网页内容需要正确的插件才能访问，因此浏览器提供了扩展其功能的能力。例如，Java Applet 在 Juniper 等 VPN 网关中被用于实现功能。

许多主流浏览器插件是标准业务实践所必需的，而其中一些插件的历史上存在安全漏洞。这意味着防守者必须在使用存在漏洞的软件和禁用部分业务活动之间做出抉择。

大多数插件没有集中的更新机制，这意味着在某些情况下安全补丁必须手动应用。这显然会增加防御基础设施的工作量和复杂度。

插件在安全媒体中经常受到大量负面报道。许多这些应用程序曾出现重大漏洞，甚至在某些情况下被证明极度不安全，导致安全专业人员建议组织彻底将它们移除。操作系统厂商也独立行动，通过自身的自动更新方案在 indefinitely 或直到找到解决方案之前，自动禁用了脆弱的插件。

插件会显著增加攻击面，它们暴露了额外的功能和攻击目标。你将在 8 章中更深入地研究插件。

## Surrendering Control

浏览器会从互联网上的任意位置请求指令。其主要功能是将内容渲染到屏幕上，并以用户期望的方式提供用户界面。作为这种核心功能的副产品，浏览器必须向 Web 服务器 surrender 相当大的控制权。浏览器必须执行所提供的命令，否则页面可能无法正确渲染。在现代 Web 中，网页应用通常包含来自多个来源的大量资源和脚本，这些资源和脚本也必须被执行，页面才能按预期显示。

传统上这些指令可能很简单，比如“把这段文字放在哪里，这张图片放在哪里”。但现代 Web 应用和浏览器则可能发出“现在我要打开你的麦克风，并将这些数据异步发送到远程服务器”的指令。

这种具有侵入性的功能立即引发了一个问题：是否所有用户都只能浏览非恶意网站。答案几乎毫无疑问是否定的！无法实时保证远程资源内容的神圣性是所有浏览器安全漏洞及其被利用的根本原因。

## TCP Protocol Control

在服务器-客户端模型中，服务器通常不会提供如此灵活的端口选择或客户端可用 IP 地址范围，这在数据交换时并不常见。

这种灵活性对攻击者非常有用。它几乎没有限制只能攻击 HTTP 协议或特定系统，为新一类攻击奠定了基础。你将在 10 章中探讨这些跨协议攻击。

## Encrypted Communication

SSL 和 TLS 可用于通过 Internet 与受信任的组织进行通信，保护消息的完整性和机密性。相反，同样的技术也可用于与攻击者安全通信。

浏览器与服务器之间的加密通信旨在保护这两个端点之间的数据。这为防御方带来了巨大的复杂性。他们无法看到恶意数据。由浏览器支持的加密隧道有利于攻击者，他们可以在其中携带命令并携带出获取的数据。

## Same Origin Policy

同源策略 (SOP) 在不同浏览器技术之间的适用不一致，可能是最令人困惑的概念之一。如前所述，SOP 是为了在浏览器中隔离资源，防止一个位置的资源与另一位置的非关联资源相互作用。它本质上是一个 sandbox。

这个 sandbox 对浏览器安全至关重要。由于浏览器在网络活动中的核心位置，它实际上将不同的信任区域作为标准相互连接，并负责维持这种连接的和平。为了满足每个区域的需求，浏览器允许与源（origin）交互的自主功能范围相当广泛。如果这些功能可以突破 SOP，原本合法的功能就会变得敌意，因为它们可以跨越安全区域。

理解 SOP 不仅限于浏览器内部的实现。SOP 的实现往往在不同浏览器、不同版本以及插件之间差异很大。第 4 章深入探讨了 SOP 的所有变体，并提供了大量绕过该控制的方法。这些绕过方法得益于 Java、Adobe Reader、Silverlight 以及各种浏览器实现中的 SOP 奇特性。

## Fallacies

过去适用的许多经验法则在当前全球威胁环境中已不再适用。下面的谬误是容易陷入的常见陷阱。遗憾的是，许多这些谬误仍然被那些心存良善的人继续传播。

### Robustness Principle Fallacy

Robustness Principle（也称为 Postel’s Law）指示程序员要“在自己执行的操作上保持保守，在接受他人提供的输入时保持宽容”。这与实际安全性并不相辅相成。

浏览器对它将渲染的内容极其宽容，这也是 XSS（跨站脚本）难以根除的主要原因。浏览器使得开发安全的过滤和编码变得困难，因为它会允许以多种方式执行指令。
