# 探索浏览器

当你触及网页时，网页也会触及你。事实上，无论你是否有意识到，你都在邀请它触及你。你让它穿透为保护网络而设置的各种安全措施，执行你仅有高层控制权的指令，只为渲染页面并在屏幕上呈现此前未知/不可信的内容。

浏览器以操作系统授予的权限运行，与任何其他用户空间程序的权限相同。这些权限等同于你，用户所分配的权限！让我们不要忘记，用户输入始终不过是当前运行程序的一系列指令——即使该程序是 Windows Explorer 或 UNIX shell。与从其他来源接收的输入相比，唯一的区别在于接收输入的程序所施加的差异！

当你将这种理解应用于网页浏览器时，其主要功能是接收并执行来自外部任意位置的指令，潜在风险便显而易见。

## 与 Web 应用的共生关系

Web 采用了在 1970 年代开发的广泛网络方法——客户端-服务器模型。3 它使用请求-响应4的通信方式，其中浏览器发起请求，服务器返回响应。

服务器和客户端缺一不可，它们高度依赖彼此：浏览器几乎没有内容可看，服务器也失去了服务内容的意义。这种根本性的共生关系构成了网络中无数动态、交织的丝线。

这两个关键组件之间的关系也延伸到安全态势。浏览器的安全性会影响 Web 应用，反之亦然。虽然某些控制可以孤立保护，但许多依赖于其对应方。在很多情况下，正是浏览器与应用的关系需要加固，或者从黑客的视角来看进行攻击。例如，当服务器为特定来源设置 Cookie 时，预期浏览器会遵守该指令，不向其他来源泄露（潜在敏感的）Cookie。

浏览器与 Web 应用的安全涉及上下文理解。许多情况下，讨论会聚焦于这两个组件之间的交互。利用这两个实体之间的关系在下文章节中被讨论。

进一步研究 Web 应用漏洞强烈推荐。对初学者和经验丰富的安全专业人员而言，Web Application Hacker’s Handbook（Dafydd Stuttard 和 Marcus Pinto 著，Wiley，2011 年出版），当时正处于第二版。

## 同源策略

浏览器内最重要的安全控制是同源策略（SOP），也称为同源政策。该控制限制同一来源的资源与其他来源的交互。

SOP 认为，拥有相同的主机名、方案和端口的页面位于同源。如果这三个属性中的任何一个不同，资源即属于不同的来源。因此，只要资源来自相同的主机名、方案和端口，它们就可以在没有限制的情况下相互交互。

同源策略最初仅针对外部资源，后被扩展以包含其他类型的来源，包括使用 file:// 方案访问本地文件，以及使用 chrome:// 方案访问浏览器相关资源。今天的浏览器还支持许多其他方案。

## HTTP 头部

你可以把 HTTP 头部看作信封上的地址和其他指示，用来指明包裹的去向以及包裹内容的处理方式。

例如，“Fragile: Handle with Care”（易碎：请轻柔处理）、“Keep Flat”（保持平整）、“Danger: Explosives!”（危险：炸药！）是 HTTP 协议用来指示如何处理随后内容的主要指令。Web 客户端在向服务器发起所有请求时都会提供 HTTP 头部，服务器在任何响应的第一项内容中也会返回 HTTP 头部。

头部的内容决定了随后内容的处理方式，无论是由服务器还是浏览器完成。有些头部是必需的，以确保交互能够正常工作；其他是可选的，有些则仅用于提供信息。

## 标记语言

标记语言是一种指定如何显示内容的方式，具体而言，它们定义了在同一文档中创建数据占位符以及与数据相关的注释占位符的标准化方法。你一生中看到的每一张网页很可能都使用了标记语言，向浏览器提供显示页面的指令。

不同种类的标记语言存在，它们的流行度各有不同，每种都有优势和劣势。正如你可能已经知道的那样，HTML 是浏览器首选的标记语言。

### HTML

超文本标记语言（HTML，HyperText Markup Language）是当前用于显示网页的主要程序语言。它最初是从标准通用标记语言（SGML）中扩展而来，自那时起，HTML 经历了众多变更。

对标记（即数据与注释或指令共存）的绝对依赖是导致多种重要、持久且系统性安全问题的根本原因。你将在本书中进一步了解 HTML 及其诸多特性。
