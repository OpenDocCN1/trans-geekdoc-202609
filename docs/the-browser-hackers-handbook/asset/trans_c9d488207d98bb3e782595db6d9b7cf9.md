
XML 是 HTML 的亲密关系。如果你熟悉 HTML，你就不会觉得 XML 太具挑战性。虽然两者都不特别讨人喜欢，但它们都提供了非常丰富的方式来表示复杂数据。你会在网页上频繁使用 XML，通常作为 Web 服务或其他远程过程调用（RPC）交互的传输方式。

## 级联样式表

级联样式表（CSS）是浏览器用来指定网页内容样式的主要方法（不要与 XSS 混淆，XSS 是跨站脚本安全漏洞的缩写）。

CSS 提供了分离内容和样式的方法。一个非常基础的例子是将句子显示为粗体。当然，CSS 远比这个简单的例子更强大，并且能够处理网页上看到的复杂程度。

## 脚本

Web 脚本语言是值得学习的艺术！如果你在技术层面与网页交互，你终将遇到它们。脚本一般是信息技术中 somehow snuck in 和占据了浏览器非常显著位置的前提条件。

你在后续章节中会了解到，浏览器中的脚本被攻击者用来发起许多常见的攻击，包括 XSS。你需要将这些知识作为你的武器。

### JavaScript

JavaScript 支持函数式和面向对象编程概念。与 Java 不同，Java 是强类型语言，而 JavaScript 是弱类型。该语言在 Web 生态系统中占据主导地位，并且将在可预见的未来继续存在。它默认在每个浏览器中运行。

作为读者，理解 JavaScript 是至关重要的，因为本书中的大部分代码都使用这种语言。用 JavaScript 编写的攻击（不考虑浏览器 quirks）在所有浏览器中都兼容。这使其成为浏览器劫持的绝佳基础语言。

### VBScript

VBScript 仅在 Microsoft 浏览器中受支持，且很少用于正式的 Web 开发。这是因为它缺乏跨浏览器支持。它是 Microsoft 对 Netscape JavaScript 的替代，其起源可追溯到早期的浏览器战争。

它的许多功能可以在 JavaScript 中实现。这自然引发了 VBScript 是否必要的问题。如果有什么，它看起来像是 Internet Explorer 拥有绝对主导权的年代的回溯。

## 文档对象模型

文档对象模型（更常被称为 DOM）是浏览器的基础概念。它是一个用于与 HTML 或 XML 文档内的对象进行交互的 API。DOM 为脚本语言提供了与渲染引擎交互的方法，通过提供对 HTML 元素的引用，以对象的形式呈现。

DOM 与 JavaScript（或其他选择的脚本语言）紧密结合。它被创建用来提供对“活”渲染文档的定义访问方法，使得运行在浏览器中的脚本能够动态读取和/或写入它。这使得页面可以在不向 Web 服务器发起新请求且无需用户交互的情况下发生变化。

## 渲染引擎

渲染引擎在浏览器语境中被称作多种名称，包括布局引擎和 Web 浏览器引擎。5 这些名称在本书中互换使用。

这些组件在浏览器生态系统中扮演着重要角色。它们负责将数据转换为用户在屏幕上看到的可呈现格式。浏览器通常会结合 HTML 和图像以及 CSS 来生成用户在浏览器中看到的最终图形。正是这些引擎提供了用户的图形体验。虽然通常以图形意义上提及，但文本渲染引擎也存在，例如 Lynx 和 W3M。

网页上使用了大量渲染引擎。6 本书中讨论的常见图形渲染引擎包括 WebKit、Blink、Trident 和 Gecko。

### WebKit

WebKit 是最流行的渲染引擎，被许多浏览器采用。最著名的使用该引擎的浏览器是 Apple Safari，过去 Google Chrome 也使用它。它是当前使用最广泛的渲染引擎之一。7

该开源项目的目标是让 WebKit 成为软件应用的通用交互和呈现引擎。除了在 Web 浏览器中的使用，该引擎还被用于各种软件，包括电子邮件客户端和即时通讯工具。

### Trident

Microsoft 的渲染引擎称为 MSHTML，或更常见的 Trident。这不足为奇，因为 Trident 是闭源引擎，并且存在于 Internet Explorer 中。它是第二流行的渲染引擎。

与 WebKit 类似，Trident 也被用于浏览器之外的软件。例如，Google Talk 使用该引擎。软件可以通过 mshtml.dll 库使用该引擎，该库随 Windows 一起安装。

Trident 首次出现在浏览器版本 4 中，自此一直是 Internet 的基石。Microsoft 最新版本的 Internet Explorer 仍然使用 Trident 作为核心渲染引擎。

### Gecko

Firefox 是使用开源 Gecko 渲染引擎的最显著软件程序。它可能是 WebKit 和 Trident 之后第三流行的渲染引擎。

Gecko 是 90 年代由 Netscape 为其 Netscape Navigator 浏览器开发的开源渲染引擎。现代版本的 Gecko 主要出现在 Mozilla Foundation 和 Mozilla Corporation 开发的应用中，最著名的是 Firefox 浏览器。

### Presto

Presto 是 Opera 浏览器的渲染引擎（在本文撰写时）。然而，2013 年 Opera 团队公开宣布，它将 soon 丢弃其自研的 Presto 渲染引擎，并迁移到 WebKit Chromium 包。9 该 WebKit Chromium 包随后被重命名为 Blink（将在下一节讨论）。

在书籍的其他任何时刻，没有其他主要浏览器以如此戏剧性的方式改变其渲染引擎。这几乎肯定预示着 Presto 的灭绝，它将成为浏览器战争中最新的牺牲品。

### Blink

2013 年，Google 宣布它将从 WebKit 分叉出新的 Blink 渲染引擎。Blink 的初衷是更好地支持 Chrome 的多进程架构，并简化浏览器的复杂度。时间会证明该引擎是否能像 WebKit 一样表现出色，但 Google 削减非必要功能的建议是一个良好开端。

## 地理位置

Geolocation API 为移动设备和桌面提供了访问 Web 浏览器地理位置的能力。它通过多种方法实现，包括 GPS、蜂窝基站三角定位、IP 地理位置和本地 Wi‑Fi 接入点。

许多明显的场景中，这些信息可能被滥用。浏览器已实施严格的安全防护措施以降低利用风险，主要的攻击向量成为社交工程。这将在后续章节中进一步讨论。

## Web 存储

Web 存储（有时称为 DOM 存储）曾是 HTML5 规范的一部分，但现在不再是。如果你想把 Web 存储看作“超级 cookies”，会更容易理解。

与 cookies 类似，Web 存储有两种主要类型：一种持久化本地，一种在会话期间有效。与 cookies 相比，local storage 在用户多次访问时会持久保留，而 session storage 仅在创建它的标签页期间有效。
