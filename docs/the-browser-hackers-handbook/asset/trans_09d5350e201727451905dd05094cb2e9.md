
为了鼓励开发者遵循安全编码规范，Robustness Principle 应该被替换为“在你所做的方面保持保守，在你从他人处接受的方面保持极度保守”。如果这种原则被灌输给下一代开发者，黑客将会面临更大的困难！

### 外围安全误区

许多组织喜欢抽象化其安全边界，以构建定制的“城堡与护城河”模型。它们会认为，自己的防护措施像同心护城河一样，能够保护关键资产。错误的假设是，分层洋葱式的结构能够提供最安全的结果。遗憾的是，这并非中世纪的欧洲，而是一个复杂的网络！

这种防御模式的根本问题是，它假设攻击者从最外层进入，并以《勇敢的心》式的方式依次突破每一道防线。这种观念与现实的差距几乎与好莱坞电影与真实历史事件的差距一样大。

组织的内部网络是一个不断演变的环境，攻击者会在基础设施的各个层面像“捣鼓”一样出现。事实上，浏览器十分普及，在某些情况下，它的作用就像是直接穿透外围防线的门户。

因此，防护边界被间接妥协，无法抵御通过浏览器反弹的攻击。防御资源需要投入到“微型安全边界”中，该边界必须覆盖关键资产。当今的网络必须防御设备在最意想不到的时候从盟友变为敌人。

在现实世界中，安全是有限资源，应当分配到能够最有效提升最有价值资产防护的位置。

# 浏览器攻击方法论

在本章节中，我们希望您能够感受到面对浏览器所面临的挑战的复杂性。保护网络并非易事，或许大部分责任都落在浏览器肩上。它是第一道也是最后一道防线。

在一个假设的、后末日、高科技世界里，所有网站都被入侵且充满恶意，理想的浏览器仍应能保护您的电脑安全。我们离这种安全乌托邦还很遥远。

是时候拆解模糊的“浏览器攻击”概念，将其转化为一个在消除当前弱点后仍能持续、超越审删的阶段化方法。我们定义了一套方法，希望它在当前安全环境下依然保持相关性。

本节介绍我们的方法论及其对浏览器攻击的时间顺序。如图 [Figure 1-1](#c01.html#figure1-1) 所示，它展示了攻击路径和决策的流程，以实现 compromise。

该方法论旨在有效指导您的浏览器攻击活动。本书的章节已按直接对应方法论主要阶段进行组织。每章聚焦于实际阶段，并深入技术细节。随着您掌握每章内容，对整体方法论的理解将随之提升。

根据目标不同，方法论中的某些路径可能因已有安全工具的自动化而变得平凡。其他部分则会更具挑战性。

浏览器攻击方法论包含三个主要部分，这些部分封装了高层次的 hacking 步骤。它们以虚线圆圈表示，围绕图中的各个阶段。这个分组提供了从 Initiating（启动）到 Retaining（保持）再到 Attacking（攻击）的方法论演进概览。

第一个封装是 Initiating，它是整个过程的准备阶段。随后是 Retaining 封装，这里是你保持对浏览器掌控的地方。它是创建浏览器 beachhead（桥头堡）的过程，即在目标浏览器或其所在设备上初始化浏览器被攻破的过程。

真正的行动发生在下一个分组。Attacking 封装包含七种攻击选项，后续章节将详细阐述。在这些阶段中，会针对浏览器的不同方面进行攻击和利用。某些 Attacking 技术可能会在其他浏览器实例上触发额外的 Initiating 阶段，从而实现对攻击范围和破坏程度的循环扩展。

### Initiating

Initiating 封装内包含一个阶段。这个看似无害的阶段是 hacking 浏览器的第一步，也是最重要的一步。没有这一步，其他攻击都无法进行，目标浏览器将无法被触及。

#### Initiating Control

每一种攻击序列都始于在浏览器中运行指令。为了让这发生，浏览器必须在你的控制下遇到并执行指令。

这正是第 2 章的主题，讨论如何诱骗、诱导、欺骗或强制浏览器在你的控制下遇到并执行任意代码。

### Retaining

现在你已经成功发动，如何增加对目标的控制？你需要以一种能够便利进一步发起攻击的方式保持对浏览器的控制。

#### Retaining Control

让我们考虑一个神话故事：神话中出现的精灵会赐予三个愿望。聪明的获 wish 的人可能会利用最后一个愿望，请求更多的愿望，从而检验精灵的排除政策！

在保持与被攻破浏览器的通信时，最初的代码会让浏览器不断询问你的下一个愿望。你在 hooking 阶段召唤了精灵，从此控制浏览器，使其持续granting wishes。

正如精灵可能在烟雾中消失，这种状态可能不会长久。无限愿望的状态取决于用户随后的行为。用户可能会关闭最初利用的标签页，或者在其他网站浏览，从而终止 JavaScript 负载，进而终止通信通道。

在发起进一步攻击之前，保持耐心、考虑如何增加对浏览器的影响是明智的。在本方法论的这一阶段，你旨在通过降低用户浏览离开源站点或直接关闭浏览器的可能性，来提升对浏览器控制的稳健性。

你可以通过不同层次的持久性手段实现这一点。要耐心，充分利用本阶段，因为你能保持浏览器被钩住的时间越长，就能探索更多的攻击面，使你的攻击更受控。

此外，在随后的 Attacking 封装中，某些成功攻击会揭示提升桥头堡强度的方法，从而增强控制力。因此，方法论图中在两个阶段之间存在双向箭头。经验将帮助你判断应将精力集中在增强控制通道的弹性上，还是将其让位于攻击努力；也会让你明白攻击努力如何反馈并提升控制通道的灵活性和持久性。

### Attacking
