# *Chapter 2*

# *Initiating Control*

你的第一个浏览器攻击步骤是获取目标浏览器的控制权。这就像是踏入前门。虽然在实现最终目标之前你需要完成许多其他操作，但这一步骤在每种情况下都必须首先进行。这是浏览器攻击方法论中的“启动控制”阶段。

每当 Web 浏览器执行来自 Web 服务器的代码时，它就会打开一个你捕获控制的机会。通过执行 Web 服务器代码，浏览器实际上让出了一部分影响力。你需要构造一个场景，使浏览器运行你编写的代码。一旦你完成这点，你就有机会利用浏览器的功能对其进行反向操作。

“启动控制”阶段可能涉及不同程度的复杂性。你可以通过多种方式执行你的指令；有些方法相对简单，而有些则需要更大的努力。最明显的获取控制的方法是让目标直接访问你的 Web 应用。

Web 应用安全测试人员会熟悉本章讨论的许多技术。事实上，其中一些技术已经被广泛发表，并在安全社区中反复分析。

一旦你在浏览器中执行了你的指令，你就需要检查并理解你的约束条件。但在此之前，让我们深入探讨如何在“启动控制”阶段实现初始控制。

# 理解控制启动

你的第一个挑战是找到一种能够对目标实现一定程度影响的方法。为此，你需要找到一种执行初始指令的方式。将初始代码注入目标浏览器是实现控制并开始浏览器攻击过程的方式。

这段代码可以采取多种形式。例如，JavaScript、HTML、CSS 或任何其他浏览器相关的逻辑都可以作为启动控制的载体。有时，这段逻辑可能甚至被封装在字节码文件中，例如恶意的 SWF（Adobe Flash 格式）文件。

实现对目标的控制在很大程度上取决于攻击环境的具体情况。如果你利用被入侵的站点，可以执行 drive-by downloads（即用户访问恶意站点时自动下载恶意文件）。如果你进行钓鱼攻击，Cross-site Scripting（XSS）漏洞可能是最佳选择；如果你在咖啡店，网络攻击可能是可行的途径。你将在后续章节中详细研究这些攻击形式。

在本章中，你将接触到“钩子”（hooking）这一概念。钩子浏览器的过程从执行初始代码开始，然后延伸到保持通信通道（将在下一章探讨）。当然，在此之前你需要将你的指令注入目标浏览器，让我们从那里开始。
