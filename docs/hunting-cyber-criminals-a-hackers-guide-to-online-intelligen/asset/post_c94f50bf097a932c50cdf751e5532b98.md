# Directory Hunting

Inevitably on your quest to find information about a website, you will need to look for hidden (i.e., forgotten) treasures. The best way to do this is to look for random directories. If you have not tried this yet, you will be amazed at how much information people just forget about: webshells, phpMyAdmin pages, folders with directory browsing and/or full read/write permissions, private files, and so much more. There are several ways to accomplish this. One is brutforcing the target to find working directories, and the other is analyzing crawl data. This chapter will look at both.

## Dirhunt

Dirhunt is a type of web crawler designed to search and analyze directories and folders within a web application. Dirhunt is not a real scraper, and it does not use brute to find folders. Instead, Dirhunt checks a number of sources to find interesting files or folders, including Google and VirusTotal. Dirhunt is also designed to detect false 404 errors to minimize the number of false positives in your results.

> NOTE You can download Dirhunt at https://github.com/Nekmo/dirhunt.

The parameters of Dirhunt include:

- -t, --threads INTEGER Number of threads to use
- -x, --exclude-flags TEXT Exclude results with these flags
- -i, --include-flags TEXT Only include results with these flags
- -e, --interesting-extensions TEXT Look for files with the extensions
- -f, --interesting-files TEXT The files with these names are interesting
- --stdout-flags TEXT Return only in stdout the urls of these
- --progress-enabled / --progress-disabled
- --timeout INTEGER
- --max-depth INTEGER Maximum links to follow
- --not-follow-subdomains Subdomains will be ignored
- --exclude-sources TEXT Exclude source engines: robots, virustotal, google Set one or more proxies to alternate
- -p, --proxies TEXT Delay between requests
- -d, --delay FLOAT --not-allow-redirects Redirects will not be followed
- --limit INTEGER Max number of pages processed

The parameters of Dirhunt can be tweaked to focus (or not focus) on specific files, file types, and more. Looking for compressed file extensions (like .zip, .rar, or .gz) using the -e switch can give you access to files that should have been deleted:

```
dirhunt http://domain.com -e php,zip,sh
```

There is also a good chance you will discover interesting files like configuration files, backups, and log files that may have been forgotten. To specifically for files, use the -f switch, like this:

```
dirhunt http://domain.com -f access_log,error_log
```

When looking for files, you can also specify a list of files to search from a dictionary. To specify a dictionary file, use the following:

```
dirhunt http://domain.com -f /var/files/dictfile.txt
```

## Wfuzz

Wfuzz has been around for a long time, and is probably one of the best-known web application testing tools available. Wfuzz is, in essence, a brute force tool, and one of the best available forforcing web applications.

Fuzzing is the process of using automated tools to look for software bugs by sending malformed data to the application. In this case, we are not sending Wfuzz (web fuzz) malformed data. We are using to send legitimate words and phrases to a web server to check for the existence of hidden or private files and folders. Wfuzz is available for download at https://github.com/xmendez/wfuzz.

Options of Wfuzz include:

```
-h : This help
--help : Advanced help
--version : Wfuzz version details
-e <type> : encoders/payloads/iterators/printers/scripts
```

- -C : Output with colors
- -V : Verbose information.
--interact : This allows you to interact with the program.
- -p addr : Use Proxy in format ip:port:type. Where could be SOCKS4, SOCKS5 or HTTP if omitted.
- -t N : Specify number of concurrent connections (10 default)
- -s N : Specify time delay between requests
- -R depth : Recursive path discovery depth
- -L, --follow : Follow HTTP redirections
- -u : Specify a URL for the request.
- -z payload : Specify a payload type,parameters, encoder.
- -w wordlist : Specify a wordlist file (alias for -z file,wordlist).
- -V alltype : All parameters bruteforcing (vars and allpost).
- -X method : Specify an HTTP method for the request
- -b cookie : Specify a cookie for the requests
- -d postdata : Use post data (ex: "id=FUZZ&catalogue=1")
- -H header : Use header (ex: "Cookie:id=1312321&user=FUZZ") in format "user:pass" or "FUZZ:FUZZ"
--basic/ntlm/digest auth : or "domain\FUZZ:FUZZ"

Wfuzz contains an infinite number of characters that you can use to "fuzz" a web application. We can do the same when looking for web directories on a target domain.

Wfuzz works by taking your target URL and attempts to insert every word in your wordlist wherever and whenever you specify "fuzz" in your URL.

Let's start with a simple example of trying to brute force the main domain path using a wordlist. For our sample word, we are going to use the big.txt word in the SecLists repository discussed in Chapter 2. We are also going to use the --hc tag to hide all 404 responses:

```
root@OSINT:wfuzz -c -z file,/SecLists/Discovery/Web-Content/big.txt --hc 404 http://www.biz-up.at/FUZZ
```
