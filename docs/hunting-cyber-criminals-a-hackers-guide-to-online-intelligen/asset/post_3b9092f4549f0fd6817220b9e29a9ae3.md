These are exactly the types of leftover files that can sink entries. I hope this example illustrates the importance for organizations and CISOs to ensure they are running against their own websites.

I have personally worked for organizations that had rogue servers lingering on their network. People forget, jobs turn over, administrations change. The larger organization, the more likely things will be forgotten. And when dealing with servers, if admins do not remember the server exists or know to look for it, there is a good chance that server will be excluded from patch cycles, regular admin password resets, and so on.

But why scan one site when we can scan many sites? Large organizations may not even realize that web apps are running on their network, so this is a great way to quickly fingerprint everything in a given environment.

For our next example, I lived off five sites into a file targets.txt. (For those playing along at home, you can pick any number of sites and put them in a file—one per site). We will use WIG to scan all of them, while changing our user agent and outputting all results to a file called results.txt.
The following code will tell wig.py to scan all targets in target.txt, tell it to use a specific browser user agent when performing the scans, and output everything to results.txt.

```python
python3 wig.py -l targets.txt -u Mozilla/5.0 (Android 4.4; Mobile; rv:41.0) Gecko/41.0 Firefox/41.0 -N -w results.txt
```

# CMSMap

CMSMap is an open-source Python scanner that automates the process of detecting flaws in popular content management systems (CMSs). CMSMap is similar to WIG in that both tools are able to map and identify CMS systems, but CMSMap is more advanced and comes with additional features.

You can download CMSMap here: https://github.com/dionach/CMSMap.

Though similar, CMSMap is considerably more advanced than WIG and supports a number of different options and parameters. In addition to detecting CMSs in use by web, CMSMap can also enumerate site plugins, brute logins, and crack passwords. CMSMap also uses the official ExploitDB repo, which you can download here: https://github.com/offensive-security/exploitdb.. of the available CMSMap parameters include:

- -f W/D/M, --force W/D/M
- -P, --full scan (W), (J)oomla or (D)rip or (M)oodle scan using large plugin lists.
- -t, --threads number of threads (Default 5)
- -a, --agent set user-agent
- -H, --header add custom header (e.g., 'Authorization: Basic ')
- -i, --input scan multiple targets in a given file
- -o, --output save output in file
- -E, --noembed enumerate plugins without searching exploits
- -c, --noacleurls disable clear urls for Drupal only
- -s, --nolcheck don't validate the server's certificate
- -d, --dictattack run low intense dictionary attack during scan

Brute-Force:

- -u, --user username or file
- -p, --pass password or password file
- -x, --noxmlrpc brute-forcing WordPress without XML-RPC

Post Exploitation:

- -k, --crack password hashes file (Require hashcat installed. For WordPress and Joomla only)
- -w, --wordlist wordlist file

Others:

- -v, --verbose verbose mode (Default false)
- -h, --help show this help message and exit
- -D, --default run CMSMap with default options
- -U, --update use (C)MSMap, (P)l or (PC) for both
