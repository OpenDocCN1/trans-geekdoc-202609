# Using Inurlrb

It should be obvious by now that Inurlrb is really meant to be a blackhat tool to scan for easily exploitable vulnerabilities That means it does not have legitimate and useful purposes.

# TIP If you are a security entrepreneur to start a business or gain some security experience, you can use this tool as a foot in the door with vulnerable organizations. Once you identify the vulnerability, you can notify the organization of the bug. They will be so impressed by your work they may hire you to help secure their systems!

But be careful. You have to tell them about the vulnerability and help them close it before you take on as a client or they might construe the gesture as a shakedown.

Inurlrb is PHP based, so running it might be a little different than the other Python scripts. Make sure you have a PHP environment set up. To start, let's search for a deep dump to search for active AXIS cameras using only Bing (results shown in Figure 8.11):

```
inurlrb.php --dock inurl:view/index.shtml -q 2 -s save.txt
```

That's 164 results, and that is only Bing! If you want to expand your search to more than Just, use -q all.

The sky is really the limit. As you dive deeper into searching, you will almost certainly run into engine blocks (i.e., CAPTCHAs) to verify that you are human. You can try to circumvent these checks by alternating your proxies.

If you are looking for dorks to search for, don't forget about the Exploit Database (https://www.exploit-db.com).

The --proxy parameter will let you specify a proxy to use, or --proxy-file will let you alternate proxies within a file. You can also alternate the proxies using a timed interval that you define with --time-proxy.

The following dork is designed to help find admin panels. It will search all search engines

```
php inurlrb.php --dork inurl:admin intitle:login -q all --proxy-file --time-proxy --save.txt
```
