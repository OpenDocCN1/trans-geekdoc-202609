Extracted metadata will be stored within nicely organized sub-tree lists. For example, Figure 12.17 shows the documents tree with a DOC sub-tree. Additional sub-trees will appear as new document types are detected (such as PDF, XLS, etc.). Possible extracted metadata includes user names, folder locations and server names, printer information, software titles, email addresses, and passwords.

FOCA allows users to manually add a file (or folder containing several files) to the list on the grid to auto-extract their metadata. You can also add a list of URLs from a file in order to instruct FOCA to gather information on those URLs.

After the metadata extraction process is complete, each file will have numbers displayed next to them. These numbers indicate how many pieces of metadata were discovered in each document.

Any of this information can easily be used to carry out targeted attacks against an organization. For example, any detected names can be used to deduce a user’s login name. From there, a credential lookup site (discussed in Chapter 18) can be used with the combined results to carry out a password spray attack against an organization’s web login panels (e.g., Office 365).

# Summary

This chapter looked at document metadata, which is information located within a file that is used to describe the contents of that file. This chapter also discussed different file types, the type of sensitive information that can potentially be left behind within a document, and tools that can be used to automatically discover and extract potentially sensitive metadata from publicly accessible documents.

The tools in this chapter vary in terms of complexity and base feature sets and therefore have their own sets of pros and cons. For example, I would consider tools like Exiftool and Metagfoil to be “quick and dirty” solution if you need to get something done quickly.

On the other hand, FOCA is a tool designed purely for document metadata analysis. If your goal is to analyze metadata (or make sure you are performing the most thorough analysis possible), this would be the tool to use. Intrigue.io provides a good middle ground for analysis capabilities while bundling in a huge array of features.

The next chapter will focus on unique interesting places to look for potentially sensitive (or earth-shattering) information.

# TheHarvester

TheHarvester is an open-source OSINT tool that gathers publicly available email addresses, subdomains, and URLs from a wide range of data sources, including Baidu, Bing, Censys.io, Cr.sh, Dogpile, Google, LinkedIn, NetCraft, PGP, ThreatCrowd, Twitter, and VirusTotal.

This is probably one of the best command-line reconnaissance tools available because it covers a wide search area. I would go so far as say that if it doesn't turn up results, then you aren't using it.

TheHarvester uses a number of techniques to find information about its targets, including DNS brute attacks using dictionary enumeration, DNS reverse lookups, hostnames, and of course, engine dorking.

> NOTE: I went back and forth about which chapter to include this in because it is so versatile. This chapter feels like the best fit because theHarvester covers more than the topics we discussed in the previous chapters, and I did not want to leave out any features that did not fit within the scope of these chapters.

I personally useTheHarvester when I am looking to broadly scrape available information on company names and email addresses that are lingering on search engines.

You can download theHarvester from https://github.com/lararies/theHarvester.

# Running a Scan

Search engines typically frown on people scraping data, so theHarvester will insert time delays between requests to avoid detection. You can also limit the number of requests by limiting the number of results. This will also allow you to work with a more manageable list. When saving your output, theHarvester will always output your results in HTML and XML. Running a scan with theHarvester can be a little quirky.

WARNING If you do not input the parameters when running a scan, theHarvester will appear to run a scan with 0 results.

In order for the Harvester to kick off a scan, you must use the domain (-d), limit (-l), and source (-b) parameters. If you do not include all three parameters, you will see the following:

```
[ root@os~ ] > ..//theHarvester.py -d apple.com
```

* No IPs found.

* No emails found.

* No hosts found.

If you receive a message that says no IPs, emails, or hosts found, you most likely did not enter the parameters correctly. The -d parameter is how you specify the domain or company name you want to search. The -l parameter is the limit on how many searches you want to perform against each engine. The -b parameter is how you specify the source engine for your search. This can include sites like Censys, crt.sh, Google, Bing, or Yahoo, to name a few. If you don't want to search to any specific engine, you must enter -b all.
