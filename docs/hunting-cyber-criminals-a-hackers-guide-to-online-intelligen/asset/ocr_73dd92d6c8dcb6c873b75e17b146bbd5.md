# Fragmented Packets/MTU

Although there is a very low likelihood that just using the fragmented packets switch will work (-f), it's worth trying in case there is a misconfigured IDS.
The -f switch tells NMAP to send 8-byte packets, fragmenting the probe into smaller packets:

```
root@OSINT: nmap -f -sX -Pn -v pepsi.com
```

The --mtu (maximum transmission unit) option is similar to -f in that it sends a limited amount of data during the transmission. This can potentially confuse some older firewalls and will take some experimentation to get working properly:

```
root@OSINT: nmap -sX v --mtu 32 pepsi.com
```

# Service Detection Trick

If a port is closing or filtered, you might be able to trick the host into providing a response by querying the service version. The trick behind both of these techniques is to use NMAP to assume that all ports are open with the -Pn switch. Without needing to decide if a port is open or closed, NMAP will run all of its operating system and service detection tests regardless. You might get lucky and receive a response.
A -A switch will enable "advanced and aggressive" features of OS detection. Using the -A switch is the same as specifying a few NMAP options like -o (OS detection), and -sV (which will run the default scripts against a host).
The -sv switch will enable version detection on a port. This is incredibly noisy due to the scan having to test for multiple versions. If you don't care about making noise, this might be weird. The -sv switch is often needed to differentiate between open and filtered UDP ports. Also important to, version detection is very slow as it involves sending a large number of application-specific probes to every port. Because of that, this command also has the ability to crash poorly written applications, so use with caution.
