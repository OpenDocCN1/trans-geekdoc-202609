Applications of network coding (multicast/broadcast/p2p), which represent a somewhat limited use case, but network coding can have a global impact. How may you ask? ## The heart of the network - the transport layer

HTTP rings a bell to you, right? It is an application protocol for transmitting hypermedia documents and resources. Basically, the foundation of the web as we know it. Under the hood, HTTP uses TCP (transmission control protocol) to reliably exchange data between two endpoints. However, the performance of TCP is severely impaired by the presence of packet loss and latency. The reason is two-fold:

- TCP (general) interprets packets loss as congestion and reduces its transmission rate
- TCP is based on ARQ and therefore highly dependent on feedback packets to operate

Now, the first point is not really valid in today’s world, specifically when speaking about WiFi/mobile. Packets get for many reasons! Interference, signal propagation issues, faulty hardware and so on. If you’re experiencing random packet losses why should you reduce your transmission rate? These losses do not necessarily mean that you are congesting the network...

The second point, we've discussed a little bit. Do we really need to wait for acknowledgments to be able to operate a reliable transport protocol? If you are sending untouched data, you will need your packet sequencing and everything in between. If you are using coding, not really… Any packet can be used to recover useful data.

So instead of reasoning about losses as signals of congestion, we may look at how much information is passing through the channel (good put). This way, you’ll get a much better idea if you are actually congesting the network.
And, in a network coding mindset, good put is simply the amount of information your receiver is able to decode.

What network coding offers to the transport layer is the following?

- Intrinsic loss recovery (any packet can be used to recover data in a stream)
- The possibility of designing congestion control mechanisms based on decoded information (packet loss can be easily taken out of the equation and we focus on more relevant metrics as goodput, latency, whatever...)
- New ways of acknowledging data (when we don't need to wait for feedbacks anymore, data will get there eventually)
- New flow control mechanisms (we can create coding schemes for optimizing different metrics such as immediate decodability, pure throughput, ...)

So, in effect, network coding allows you to design a better transport layer protocol and consequently a better Internet for all!

## Concept of Linear network coding

Linear network coding is a fundamental concept in information theory and computer networking that revolutionizes the way data is transmitted and exchanged within networks. At its core, network coding involves the combination and transformation of data packets to enhance the efficiency and reliability of data delivery. Unlike traditional routing techniques that forward packets without modification, linear network coding allows nodes to perform mathematical operations on incoming packets, resulting in encoded packets that contain a linear combination of the original data.
