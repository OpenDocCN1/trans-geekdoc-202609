For example, the third problem listed above is a consequence of a weakness in the implementation of the RC4 stream cipher that is exposed by a poorly designed protocol.

Some of the problems associated with WEP and 802.11 WLAN security are summarized in Table 2.

# Table 2: Key Problems with Existing 802.11 Wireless LAN Security

| Security Issue or Vulnerability | Remarks |
| --- | --- |
| 1. Security features in vendors products are not fairly enabled | Security features, albeit poor in some cases, are not enabled when shipped, and others do not enable when installed. Bad security is generally better than no security. |
| 2. IVs are short (or static). | 24-bit IVs caused the generated key to repeat. Repetition allows easy decryption of data for a more sophisticated adversary. |
| 3. Cryptographic keys are short. | 40-bit keys are inadequate for any system. It is generally accepted that key sizes are greater than 80 bits. The longer the key, the less likely a compromise is possible from a brute-force attack. |
| 4. Cryptographic keys are shared. | Keys that are shared can compromise a system. As the number of people sharing the key, security risks also grow. A fundamental tenant of cryptography is that the security of the system is largely dependent on the secrecy of the keys. |
| 5. Cryptographic keys cannot be updated automatically and frequently | Cryptographic keys should be changed often to prevent brute-force attacks. |
| 6. RC4 has a weak schedule and is improperly used in WEP | The combination of revealing 24 bits in the IV and a weakness in the initial few bytes of RC4 key leads to an efficient attack that recovers the key. Most applications of RC4 do not expose the weaknesses of RC4 because they do not reveal key bits and do not restart the key for every packet. This attack is available to moderately sophisticated adversaries. |
| 7. Packet injection is poor. | CRC32 and linear block codes are inadequate for cryptographic integrity. Message modification is possible. Linear attacks are inadequate for protection against attacks against data integrity. Cryptographic protection is required to prevent deliberate attacks. Use of noncryptographic protocols facilitates attacks against cryptography. |
| 8. No user authentication occurs | Only the device is authenticated. A device that is stolen can access the network. |
| 9. Authentication is not enabled; only simple SSID identification. | Identity-based systems are highly vulnerable particularly in a wireless system because signals can be easily intercepted. |
| 10. Device authentication is simple shared-key response. | One-way challenge-response authentication is susceptible to "man-in-the-middle" attacks. Mutual authentication is required to provide verification that users and the network are legitimate. |
| Security Issue or Vulnerability | Remarks |
| 11. The client does not authenticate the AP. | The client needs to authenticate the AP to ensure that it is legitimate and prevent the introduction of rogue APs. |
