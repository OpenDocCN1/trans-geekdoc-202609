## 1.3.2 IoT Protocols

### 1.3.2.1 OSI Model

The OSI (Open Systems Interconnection) model for IoT protocols, as shown in Figure 1.1, includes five layers: physical layer, link layer, internet layer, transport layer, and application layer.

The physical layer is comprised of devices, objects, and things. The link layer operates on protocols like IEEE 802.15.4, IEEE 802.11, ISO/IEC 18092:2004, Bluetooth, ANT, NB-IoT, EC-GSM-IoT, uIP, EnOcean, and LTE-MTC. The internet layer protocols are 6LoWPAN, IPv6, and NanoIP. The transport layer protocols are CoAP, TCP, UDP, MQTT, XMPP, AMQP, LLAP, DDS, SOAP, and DTLS. The application protocols are JSON-ISO, REST API objects, and binary objects.

| Application layer | Protocols |
| :--- | :--- |
| Application layer | REST API, JSON-ISO objects, Binary objects |
| Transport layer | CoAP, MQTT, XMPP, AMQP, LLAP, DDS, SOAP, UDP, DTLS |
| Internet layer | 6LoWPAN, IPv6, uIP, NanoIP |
| Link layer | IEEE 802.15.4, IEEE 802.11, ISO/IEC 8092:2004, NB-IoT, EC-GSM-IoT, Bluetooth, ANT, ISA100.11a, EnOcean, LTE-MTC |
| Physical layer | Devices, objects, things |

## Introduction to Internet of Things

### 1.3.2.2 Organizational Levels

IoT protocols can also be categorized on the basis of the organization levels, as follows:

- Infrastructure (IPv4/IPv6, 6LoWPAN, RPL)
- Identification (EPC, IPv6, uCode, URIs)
- Communication (Bluetooth, Wi-Fi, LPWAN)
- Discovery (DNS-SD, mDNS, Physical Web)
- Data Protocols (AMQP, MQTT, Websocket, CoAP, Node)
- Device Management (TR-069, OMA-DM)
- Semantic (Web Thing Model, JSON-LD)
- Multi-layer Frameworks (Weave, IoTivity, Alloyin, Homekit)

**IPv6:** IPv6 is popular as an internet layer protocol to transmit packets in an end-to-end transmission over multiple Internet Protocol (IP) networks.

**6LoWPAN:** 6LoWPAN stands for IPv6 over Low-power Wireless Personal Area Networks. It is an extended layer for IPv6 through IEEE 802.15.4 links. It operates on 2.4 GHz of frequency with a data transmission rate of 250 kbps.

**RPL:** It is IPv6-based routing protocol used in less power and lossy network.

**UDP (User Datagram Protocol):** This protocol is meant for IP-based protocol networked between client/server. UDP is used in applications for real-time performance. It was designed for security protocol to reduce latency in connection and transportation of information over a network.

**μIP:** The acronym is micro Internet Protocol. It is widely used as of open source TCP/IP stack, which can be used for 8- and 16-bit microcontrollers.

**DTLS (Datagram Transport Layer):** The DTLS protocol provides the communication privacy for datagram protocols. It is for prevention of tampering, message forgery, or eavesdropping in a network.

**NanoIP:** Nano Internet Protocol is meant to establish communication among embedded sensors and devices without the overhead of TCP/IP.

**Time-Synchronized Mesh Protocol (TSMP):** It is a communication protocol to establish communication among self-customized wireless sensor nodes called motes.

**Physical Web:** The Physical Web is an approach to interconnect devices and access them seamlessly.

**HyperCat:** It is an open source JSON-based lightweight hypermedia catalogue for exposing collections of URIs.

**MQTT (Message Queuing Telemetry Transport):** The MQTT is a light-weight protocol that enables a publish/subscribe messaging model. Used for remote connection in a network.

**CoAP (Constrained Application Protocol):** CoAP is an application layer protocol. It is designed to translate to HTTP for simplified integration with the web.

**SMCP:** It is a C-based CoAP stack, which can be used for embedded environments. It has fully asynchronous I/O and supports both UIP and BSD sockets.

**STOMP:** It stands for Simple Text Oriented Messaging Protocol in communication networks.

**XMPP:** It stands for Extensible Messaging and Presence Protocol.

**XMPP-IoT:** XMPP-IoT is a variant of XMPP for IoT applications.

**M2M:** M2M refers to machine-to-machine communication.

**AMQP:** Advanced Message Queuing Protocol is used for reliable messaging.

**DDS:** Data Distribution Service is a middleware for real-time data exchange.

**SOAP:** Simple Object Access Protocol is used for web services.

**REST:** Representational State Transfer is an architectural style for networked applications.

**Websocket:** A protocol providing full-duplex communication over a single TCP connection.

**SensorML:** Sensor Modeling Language is an XML schema for describing sensors.

**RESTML:** RESTful Modeling Language used for describing web services.

**IoTivity:** IoTivity is a framework for managing IoT devices.

## Introduction to Internet of Things

### 1.4 Enabling Technologies for IoT

In the present world, many technologies contribute to IoT:

#### Short-Range Wireless Technology
- **Bluetooth:** Bluetooth is a short-range wireless technology. Many devices use Bluetooth Energy (BLE).
- **Light-Fi (Li-Fi):** This uses light spectrum for communication.
- **Near-field communication (NFC):** NFC is used for communication over a very short distance.
- **QR codes and barcodes:** These are optical codes used to store information.
- **Radio-frequency identification (RFID):** RFID uses electromagnetic fields to identify tags.
- **Thread:** Thread is a low-power mesh wireless network protocol. 
- **Wi-Fi:** Wi-Fi is a local area network technology.
- **ZWave:** ZWave is a wireless protocol used for home automation.
- **ZigBee:** ZigBee is a protocol for low-power, wireless mesh area networks.

#### Medium-Range Wireless Technology
- **HaLow:** HaLow is a variant of Wi-Fi for low-power devices.
- **LTE-Advanced:** LTE-Advanced is a high-speed cellular communication standard.

#### Long-Range Wireless Technology
- **Low-power wide-area network (LPWAN):** LPWAN provides communication over a wide area with low bit rate.
- **Very small aperture terminal (VSAT):** VSAT uses satellite technology for communication.

#### Wired Technology
- **Ethernet:** Ethernet is wired communication using twisted pair or optical fiber.
- **Multimedia over Coax Alliance (MoCA):** MoCA allows video over existing coaxial cables.
- **Power-line communication (PLC):** PLC uses electrical power lines for data transmission.

## 1.5 IoT Levels

- **Level 1 IoT:** A level 1 IoT system performs sensing, actuation, storing, and analysis operations and is comprised of a single node/device. An example is a home automation system where a single node is designed to control the lights and appliances remotely.
- **Level 2 IoT:** A level 2 IoT system performs sensing, actuation, and analysis has a single node/device. This is suitable for big data analysis. The data is stored on the cloud. It is popular for cloud-enabled applications like smart farming.
- **Level 3 IoT:** A level 3 IoT system is a single-node-based cloud platform. This type of system is suitable for big data needs that are computationally intensive. An example is the package tracking system. The system comprises of a single node (for a package), which monitors the vibration level of a package being shipped.
- **Level 4 IoT:** A level 4 IoT system has multiple nodes that perform the analysis and data stored on the cloud. The system may have local and cloud-based server nodes that receive the information and upload to the cloud. Server nodes only process the information and perform no control action. It is suitable where multiple nodes are required and involve big data that is computationally intensive. An example is noise monitoring.
- **Level 5 IoT:** A level 5 IoT system has end nodes and a single coordinator node. The end node performs the sensing and/or actuation. Collections of data done by the coordinator node form the sensor nodes and communicates it to the cloud and is analyzed.
