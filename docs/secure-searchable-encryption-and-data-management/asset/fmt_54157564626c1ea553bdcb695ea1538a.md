
# PPT Algorithm B in Reduction Proofs

PPT algorithm B plays two key roles here. It simulates a real challenger as A expects its communication with a real challenger in the security game of scheme X. On the other hand, B acts as an adversary to the outside challenger as per the security game of scheme Y. A receives some input from B, as seen in the game-based security definition in [Figure 4.1](#04chap_04.xhtml#fig4_1), but we have no idea how A works. The interesting part is to construct B and write its pseudocode such that it simulates the challenger for A; thus, its code should be similar to the challenger in X's security game. While writing the code, remember that B has no idea of A's working; B just knows that A behaves according to the security game of scheme X. If we consider eavesdropper security, then B knows that A outputs two messages and finally outputs a guess bit. For B, there is a different security game—the game associated with scheme Y. As far as scheme Y is concerned, we know B behaves as an adversary and interacts with some outside challenger defined for scheme Y. This outside challenger gives something to B as per the security game of scheme Y, and like A, B can also send to and receive something from the outside challenger. Finally, B also needs to output something to win the security game Y. For scheme Y, there exists a well-defined code for the challenger (outside challenger).

For scheme X, we only know the interaction between A and B and must write the code for B. However, for scheme Y, we know both the interaction and the code. Hence, our goal is to write code for B such that the interaction with the outside challenger is somehow tied to the interaction of B with A. At the end, if A wins the security game of X, we hopefully want B to win the security game of Y.

## Three Rules in a Reduction Approach

*   **The algorithm we construct (B) must be a PPT algorithm.** We must consider three things to ensure B is a PPT algorithm. First, the pseudocode we write for B must take polynomial time (PT). Second, inside B, A is called as a sub-routine; we do not know the working of A, but we know whatever A does is done in PT. Therefore, the first and second together also result in PT. Third, the interactions of B with the outside challenger must be polynomial in number.

*   **Simulation.** B simulates the challenger for A. The interactions between A and B, as far as A is concerned, must be indistinguishable; i.e., B should do exactly the same as a real challenger would have done in the security game of X. Alternatively, B's behavior in terms of interaction with A should be like the behavior of a challenger in the security game of scheme X.

*   **Probability of winning the security game.** A wins the security game X (this means correctly distinguishing the messages and thus correctly guessing the bit, in the case of eavesdropper security) with probability `1/2 + non-negl(n)`. Now, let's say B's winning condition is that it needs to find something with non-negligible advantage. We need to show that if A wins the security game X, then B takes the output of A, runs it through some code, outputs its response, and B must also win the security game Y with non-negligible advantage.

For every reduction proof, while writing the code for B, we need to analyze these three rules.

### Reasoning in Terms of the Contrapositive

The contrapositive of the third rule, as shown in [Figure 4.3](#04chap_04.xhtml#fig4_3), is the following: since we do not know any such algorithm B that has non-negligible advantage, therefore, all algorithms that try to break Y have only negligible advantage, because Y is a known hard problem. As for the contrapositive, this means all algorithms A must also have negligible advantage. Hence, scheme X is secure.

## 4.2.1 Example of Reduction Proof

To see the application of the reduction approach, we consider a simple pseudorandom generator (PRG)-based encryption scheme. Here, we are basically developing a practical one-time pad. As mentioned in [Chapter 2](#02chap_02.xhtml), one-time pad (OTP) has perfect secrecy but cannot be applied to messages of very long length because we must use a key of the same length to encrypt the message.

### PRG-based Encryption Scheme (X)

A PRG is a function `G` that takes `n`-bit input and produces `n'`-bit output. It is a deterministic algorithm that produces something that looks random but is not a randomized algorithm itself. A PRG is said to be secure if the attacker/distinguisher `D` cannot distinguish whether the output is pure random (R) or pseudorandom (PR). A PRG is assumed to be secure as long as the seed `s` it initially takes is purely random. Formally, PRG security is defined in terms of the distinguishing probability.

∀ PPT `D`, ∃ negligible function in security parameter `n`, `negl(n)`, such that

```
Pr[s←{0,1}^n; r←G[s]: D[1^n, r]→R] − Pr[r←{0,1}^n': D[1^n, r]→R] = ± negl(n)
```

(4.3)

It signifies that the distinguisher indeed cannot distinguish between R and PR with more than a negligible probability.

**Scheme X contains the following algorithms:**

*   `k←Gen(1^n): k←{0,1}^n`
*   `c←Enc(k, m): G(k)⊕m = c`
*   `m'←Dec(k, c): G(k)⊕c = m'`

Since `G(k)` maps `n`-bit to `n'`-bit, the message space is `{0,1}^n'`. This scheme is perfectly correct, as XORing a value with itself results in 0. The security of this scheme is proved with the help of the following theorem:

**Theorem:** If `G` is a secure PRG, then scheme X is a secure encryption scheme under single-message eavesdropper security.

**Proof:** If ∃ PPT `A` who breaks X, then we will construct another PPT adversary `B` who breaks `G`. `B` plays the PRG security game; the challenger provides a security parameter and some value `r`, which may be either randomly picked or generated by `G` from a random seed. Let us draw the box diagram shown in [Figure 4.4](#04chap_04.xhtml#fig4_4), which helps us understand the proof clearly. As seen in [Figure 4.4](#04chap_04.xhtml#fig4_4), inside `B` we play the security game of encryption scheme X. `A` is given the security parameter like `B`, and `A` gives us `m[0]`, `m[1]` as per the eavesdropper security definition. `B` returns the encryption of one of these messages, `m[b]`, and sends `c` to `A`. Finally, `A` outputs `b'` as its guess for `b`.

![Figure 4.4 Box representation of reduction proof approach of scheme X.](images/fig4_4.jpg)

*Figure 4.4 Box representation of reduction proof approach of scheme X.*

Now, we need to write the pseudocode for `B`, keeping in mind that `B` behaves like a challenger to `A` in X's security game and as an adversary in PRG's security game. The security parameter received from the PRG challenger is just passed from `B` to `A`. For the encryption part, `B` picks a bit `b←{0,1}` and then encrypts `m[b]`, but it needs to tie it to the random or pseudorandom value `r` in the PRG security game. Hence, `B` computes `c = r⊕m[b]` and sends it to `A`. Now, `A` does something and returns `b'`. Upon receiving `b'`, we have two options:

*   If `b' = b` (i.e., A guesses correctly), then output **pseudorandom**.
*   Otherwise, output **random**.
