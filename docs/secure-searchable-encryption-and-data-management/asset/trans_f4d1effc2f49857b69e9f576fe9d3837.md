

# 归约证明中的 PPT 算法 B

PPT 算法 B 在此扮演两个关键角色。它模拟一个真实的挑战者，正如 A 在方案 X 的安全游戏中期望与真实挑战者通信那样。另一方面，B 按照方案 Y 的安全游戏，充当外部挑战者的对手。如 [图 4.1](#04chap_04.xhtml#fig4_1) 中基于游戏的安全定义所示，A 从 B 接收一些输入，但我们不知道 A 是如何工作的。有趣的部分在于构建 B 并编写其伪代码，使其为 A 模拟挑战者；因此，其代码应类似于 X 安全游戏中的挑战者。编写代码时，请记住 B 不知道 A 的工作原理；B 只知道 A 按照方案 X 的安全游戏行事。如果我们考虑窃听者安全，那么 B 知道 A 输出两条消息并最终输出一个猜测比特。对于 B 来说，有一个不同的安全游戏——与方案 Y 相关的游戏。就方案 Y 而言，我们知道 B 作为对手行事，并与为方案 Y 定义的某个外部挑战者交互。该外部挑战者按照方案 Y 的安全游戏给 B 一些东西，并且像 A 一样，B 也可以向外部挑战者发送和接收东西。最后，B 也需要输出一些东西以赢得安全游戏 Y。对于方案 Y，存在一个定义良好的挑战者代码（外部挑战者）。

对于方案 X，我们只知道 A 和 B 之间的交互，必须为 B 编写代码。然而，对于方案 Y，我们既知道交互也知道代码。因此，我们的目标是为 B 编写代码，使其与外部挑战者的交互以某种方式与 B 与 A 的交互联系起来。最后，如果 A 赢得了 X 的安全游戏，我们希望 B 也能赢得 Y 的安全游戏。

## 归约方法中的三条规则

*   **我们构造的算法 (B) 必须是一个 PPT 算法。** 我们必须考虑三件事以确保 B 是 PPT 算法。首先，我们为 B 编写的伪代码必须在多项式时间 (PT) 内运行。其次，在 B 内部，A 作为子程序被调用；我们不知道 A 的工作原理，但我们知道 A 所做的一切都是在 PT 内完成的。因此，第一点和第二点结合起来也会导致 PT。第三，B 与外部挑战者的交互次数必须是多项式的。

*   **模拟。** B 为 A 模拟挑战者。就 A 而言，A 和 B 之间的交互必须是不可区分的；即，B 应该完全按照真实挑战者在 X 的安全游戏中所做的那样做。或者，B 在与 A 交互方面的行为应类似于方案 X 安全游戏中挑战者的行为。

*   **赢得安全游戏的概率。** A 以概率 `1/2 + non-negl(n)` 赢得安全游戏 X（这意味着在窃听者安全的情况下，正确区分消息从而正确猜测比特）。现在，假设 B 的获胜条件是它需要以非微不足道的优势找到某样东西。我们需要证明，如果 A 赢得了安全游戏 X，那么 B 接受 A 的输出，通过一些代码运行它，输出其响应，并且 B 也必须以非微不足道的优势赢得安全游戏 Y。

对于每一个归约证明，在为 B 编写代码时，我们都需要分析这三条规则。

### 从逆否命题的角度进行推理

如 [图 4.3](#04chap_04.xhtml#fig4_3) 所示，第三条规则的逆否命题如下：因为我们不知道存在任何具有非微不足道优势的算法 B，所以所有试图攻破 Y 的算法只有微不足道的优势，因为 Y 是一个已知的困难问题。就逆否命题而言，这意味着所有算法 A 也必须只有微不足道的优势。因此，方案 X 是安全的。

## 4.2.1 归约证明示例

为了了解归约方法的应用，我们考虑一个基于简单伪随机生成器 (PRG) 的加密方案。这里，我们基本上是在开发一个实用的一次性密码本。正如 [第 2 章](#02chap_02.xhtml) 所述，一次性密码本 (OTP) 具有完美保密性，但不能应用于非常长的消息，因为我们必须使用与消息长度相同的密钥来加密消息。

### 基于 PRG 的加密方案 (X)

PRG 是一个函数 `G`，它接受 `n` 位输入并产生 `n'` 位输出。它是一个确定性算法，产生的东西看起来是随机的，但它本身不是一个随机算法。如果攻击者/区分器 `D` 无法区分输出是纯随机 (R) 还是伪随机 (PR)，则称 PRG 是安全的。只要 PRG 最初接收的种子 `s` 是纯随机的，就假定 PRG 是安全的。形式上，PRG 安全性是用区分概率来定义的。

∀ PPT `D`, ∃ 安全参数 `n` 中的可忽略函数 `negl(n)`, 使得

```
Pr[s←{0,1}^n; r←G[s]: D[1^n, r]→R] − Pr[r←{0,1}^n': D[1^n, r]→R] = ± negl(n)
```

(4.3)

这表明区分器确实无法以超过微不足道的概率区分 R 和 PR。

**方案 X 包含以下算法：**

*   `k←Gen(1^n): k←{0,1}^n`
*   `c←Enc(k, m): G(k)⊕m = c`
*   `m'←Dec(k, c): G(k)⊕c = m'`

由于 `G(k)` 将 `n` 位映射到 `n'` 位，消息空间为 `{0,1}^n'`。该方案是完全正确的，因为一个值与自身异或结果为 0。该方案的安全性通过以下定理证明：

**定理：** 如果 `G` 是安全的 PRG，则方案 X 是单次消息窃听者安全下的安全加密方案。

**证明：** 如果 ∃ PPT `A` 攻破 X，那么我们将构造另一个 PPT 对手 `B` 攻破 `G`。`B` 参与 PRG 安全游戏；挑战者提供一个安全参数和某个值 `r`，它可能是随机选取的，也可能是由 `G` 从随机种子生成的。让我们绘制 [图 4.4](#04chap_04.xhtml#fig4_4) 所示的框图，这有助于我们清晰地理解证明。如 [图 4.4](#04chap_04.xhtml#fig4_4) 所示，在 `B` 内部我们进行加密方案 X 的安全游戏。`A` 像 `B` 一样被给予安全参数，`A` 按照窃听者安全定义给出 `m[0]`, `m[1]`。`B` 返回其中一条消息 `m[b]` 的加密，并发送 `c` 给 `A`。最后，`A` 输出 `b'` 作为其对 `b` 的猜测。

![Figure 4.4 Box representation of reduction proof approach of scheme X.](images/fig4_4.jpg)

*图 4.4 方案 X 归约证明方法的框图表示。*

现在，我们需要为 `B` 编写伪代码，牢记 `B` 在 X 的安全游戏中表现得像对 A 的挑战者，而在 PRG 的安全游戏中表现得像对手。从 PRG 挑战者接收到的安全参数只是从 `B` 传递给 `A`。对于加密部分，`B` 选择一个比特 `b←{0,1}` 然后加密 `m[b]`，但它需要将其与 PRG 安全游戏中的随机或伪随机值 `r` 联系起来。因此，`B` 计算 `c = r⊕m[b]` 并将其发送给 `A`。现在，`A` 做一些事情并返回 `b'`。收到 `b'` 后，我们有两个选项：

*   如果 `b' = b`（即 A 猜测正确），则输出 **伪随机**。
*   否则，输出 **随机**。
