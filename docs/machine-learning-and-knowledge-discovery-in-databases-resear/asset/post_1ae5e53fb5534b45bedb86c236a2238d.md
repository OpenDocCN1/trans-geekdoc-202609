
## Algorithm 1. GRAPHWEAVE

```
function GRAPHWEAVE(G, F, \alpha, k)
   \mathcal{R} \leftarrow \cup_{A \in G} \cup_{f \in \mathcal{F}} RWT(A, f, \alpha, k)
   \mathcal{D} \leftarrow \{(v_j, v_{j+1}); v_j \rightarrow v_{j+1} \text{ in some RWT in } \mathcal{R}\}
   Define B : \mathcal{R} \rightarrow [K] \triangleright \text{Binning function with } K \text{ bins}
   Define B(v) := [B(v_1), B(v_2), ..., B(v_n)]^T \text{ for any } v \in \mathbb{R}^n
   \triangleright \text{Learn to reverse RWTs}
   Define \mathcal{E} : [K] \rightarrow \mathbb{R}^m \triangleright \text{value embedding function}
   Define \mathcal{E}' : |\mathcal{F}| \times k \rightarrow \mathbb{R}^m \triangleright \text{setting embedding function}
   Define T_b \leftarrow \text{Transformer : } \mathbb{R}^{n \times m} \rightarrow \mathbb{R}^{n \times m} \text{ for any } n
   P_{\Phi, \Psi}(v, j, f) \leftarrow \text{Project}_\Psi (T_b(v \otimes \mathcal{E}(B(v)) + 1 \otimes \mathcal{E}'(f, j)))
   \Phi, \Psi, \mathcal{E}, \mathcal{E}' \leftarrow \text{arg min} \sum_{(v_j,v_{j+1}) \in \mathcal{D}} (P_{\Phi, \Psi}(v_{j+1}, f, j+1) - v_j)^2
   \triangleright \text{Generate degree distribution}
   G \leftarrow \text{sample graph from } G
   {d_i} \leftarrow \text{Perturbed degree distribution of } G
   d'_i \leftarrow (1 - \alpha)d_i + \alpha \text{ for all nodes } i
   \triangleright \text{Generate RWTs}
   V_1, V_2 \leftarrow \phi
   \text{for all } f \in \mathcal{F} \text{ do}
     \bar{v}_k \leftarrow \gamma \sqrt{d'} \triangleright d' \text{ has entries } d'_i; \gamma \text{ is from Theorem 1}
     \bar{v}_{k-j} \leftarrow P_{\Phi, \Psi}(\bar{v}_{k-j+1}, f, k-j+1) \text{ for } j = 1, 2, ..., k-1
     V_1 \leftarrow V_1 \cup \{\bar{v}_j; j = 1, ..., k-1\}
     V_2 \leftarrow V_2 \cup \{\bar{v}_{j+1}; j = 1, ..., k-1\}
   \text{end for}
   \triangleright \text{Infer graph}
   A \leftarrow \text{solve Equation 5 using } V_1 \text{ and } V_2
   \text{return unweighted graph with adjacency matrix } A
\text{end function}
```

We assume that the transformer's size is fixed (i.e., O(1) layers and heads). So, the cost of training the transformer is O(|F||G|kn^2m), and this is also the overall cost of training.

To generate a graph, we create its RWTs via k|F| passes of the transformer. Each pass takes O(n^2m) time. Since Integer Linear Programs (Eq. 5) can have variable costs, we instead analyze the convex optimization (Eq. 6). To generate a graph of n nodes requires O(n^2) parameters. The main cost is in computing the matrix-matrix product of V1 (size k|F| x n and (D')^-1/2 A' (D')^-1/2 (size n x n) in the objective. Assuming we run gradient descent for a fixed number of steps, the convex optimization takes O(MatMult(k|F| x n, n x n)) time. The threshold step (Eq. 7) costs O(n^2) for grid search. Hence, the total cost of generation is O(k|F|n^2m + MatMult(k|F| x n, n x n)) = O(k|F|n^2m).

Note that the dominant costs are training a transformer, matrix multiplication, and convex optimization. There are fast off-the-shelf libraries for all three.

## 3 Experiments

### Comparison Metrics
We consider measures of node centrality (degree and Pagerank), local neighborhoods (clustering coefficient and ORBIT scores), quality of random partitions (cut-size, conductance, and modularity), connectivity between random node pairs (max-flow and resistance), and overall connectivity (if the graph is connected or not). Apart from overall connectivity, each measure results in a vector \(\phi(G)\) for any graph \(G\) (e.g., the vector of node degrees, or the modularities of 100 random partitions). We then compute the relative error
\[\text{error}_\phi(\mathcal{G}_{gen} | \mathcal{G}_{test}) := \left| \frac{\sum_{G_i \in \mathcal{G}_{gen}, G_j \in \mathcal{G}_{test}} \text{distance}(\phi(G_i), \phi(G_j))}{\sum_{G_i, G_j \in \mathcal{G}_{test}} \text{distance}(\phi(G_i), \phi(G_j))} \times \frac{|\mathcal{G}_{test}|}{|\mathcal{G}_{gen}|} - 1 \right|,\]
where \(\mathcal{G}_{gen}\) is the set of generated graphs, \(\mathcal{G}_{test}\) the set of test graphs from the same family as the training data, and the distance function is the Wasserstein metric between any two vectors \(\phi(G_i)\) and \(\phi(G_j)\). If the generated graphs fit the test distribution, the error is close to 0.

### Competing Methods
We compare GRAPHWEAVE against several state of the art methods: DiGress [17], GSDM [11], GRASP [14], GDSS [8], and GraphRNN [19]. Apart from GraphRNN, which is an autoregressive model, all the others use diffusion. These methods are recent, and have been shown to outperform older methods. Hence, we compare GRAPHWEAVE against these methods.

### Simulated Datasets
We consider four types of simulated graphs:
- a stochastic blockmodel with 3 communities containing 50%, 30%, and 20% of the nodes, and a connection probability of 0.8 for nodes in the same community and 0.3 otherwise,
- a Watts-Strogatz model with 4 edges per node and a rewiring probability of 0.3,
- a Barabasi-Albert preferential attachment model, and
- an expected-degree random graph model, whose degrees are the same as the Stochastic Blockmodel.

### Real-World Datasets
We also tested our method on five real-world benchmark datasets. These include:
- Cora,
- Citeseer, and
- Pubmed, where the nodes represent documents and edges represent citation relationships from which we extract 3-hop ego networks [15].
We also use:
- Proteins, containing molecular graphs with 100 to 500 nodes in each graph [4], and
- QM9, comprising stable organic molecules with up to nine heavy atoms [18].

### Experimental Settings
For each dataset and each method, we train on 100 graphs and then generate (at least) 40 graphs. We compute various comparison metrics for each of the generated graphs, and compare them against unseen test graphs from the same dataset using Eq. 8.

### Effect of Optimization
We compared our two optimization approaches: the Integer Linear Program of Eq. 5 (Integer), and the convex relaxation with rounding of Eqs. 6 and 7 (Convex). We also considered a baseline (Random) that picks a random graph with the same degrees as Integer. The comparison metric is the objective function of Eqs. 5 and 6, which measures how closely the generated graph matches the desired RWTs.
