

# 早期倾斜输入研究

早期关于倾斜输入的研究可追溯至 20 世纪 90 年代，主要考察了其在文档滚动 [\[25\]](#Chp003_93-160_B9780443140969000099.xhtml#br0125)、[\[177\]](#Chp003_93-160_B9780443140969000099.xhtml#br0885)、[\[455\]](#Chp003_93-160_B9780443140969000099.xhtml#br2275)、平移与缩放 [\[455\]](#Chp003_93-160_B9780443140969000099.xhtml#br2275)、菜单导航 [\[411\]](#Chp003_93-160_B9780443140969000099.xhtml#br2055) 以及改变屏幕方向 [\[192\]](#Chp003_93-160_B9780443140969000099.xhtml#br0960) 等任务中的潜力。与任何新技术一样，研究最初关注的是*“能做什么”*而非*“能做得有多好”*。重点在于技术本身及其在原型设备中的集成。用户测试结果往往基于轶事，而非实证。事实上，倾斜输入是一种非常适合实证研究的用户输入基元。对于刚才提到的每一项任务，要么已存在多种输入方法，要么可以设想出替代方案。利用倾斜输入实现这些任务是新颖且令人兴奋的。但是，这些任务执行得有多好？从人类表现角度来看，倾斜输入与替代方法相比如何？倾斜的哪些方面会影响人类表现？这些问题非常适合实证研究。其中一项评估比较了四种倾斜增益设置：25、50、100、200 [\[326\]](#Chp003_93-160_B9780443140969000099.xhtml#br1630)。^([^(69)](#fn69))

在另一个应用中，智能手机的倾斜被用来控制机器人的移动 [\[542\]](#Chp003_93-160_B9780443140969000099.xhtml#br2710)。其他应用将倾斜输入用于游戏，例如控制弹珠迷宫游戏中小球的移动 [\[86\]](#Chp003_93-160_B9780443140969000099.xhtml#br0430) 或乒乓游戏中挡板的移动 [\[484\]](#Chp003_93-160_B9780443140969000099.xhtml#br2420)。

# 空间感知显示

加速度计输入的另一个应用是空间感知显示。在这种情况下，显示器上的视图会随着设备的移动而移动，这由加速度计感知。参见 [图 3.62](#Chp003_93-160_B9780443140969000099.xhtml#f0315)。这引发了各种新问题。对于平面 2D 移动，交互是直观的。但如果设备旋转，或前后移动怎么办？视图应如何变化？交互是否流畅自然？这些问题非常适合实证研究。Fitzmaurice [\[128\]](#Chp003_93-160_B9780443140969000099.xhtml#br0640)、Rohs 和 Oulasvirta [\[419\]](#Chp003_93-160_B9780443140969000099.xhtml#br2095)、Cao 等人 [\[57\]](#Chp003_93-160_B9780443140969000099.xhtml#br0285) 等人报道了关于空间感知显示的实验研究。

[图 3.62](#Chp003_93-160_B9780443140969000099.xhtml#cf1445) 空间感知显示。随着设备移动，虚拟图像中的视图也随之移动。

如果从每年一度的 ACM SIGCHI 大会中能得出一个观察结果，那就是 HCI 领域的创新步伐正在加快。新技术和新的交互理念层出不穷，且涌现迅速。它们通常像倾斜输入初期那样，作为可能性被呈现。原型、演示、视频、海报、进行中的工作贡献等，将这些想法传播出去。但迟早，合理的想法需要经过用户测试。建议进行实证和实验性的测试。结果将增加工程师和设计师在推出新颖酷炫产品时所依赖的知识库。

## 3.8 交互错误

本章大多数分析针对人机界面的物理属性，例如 2D 或 3D 中的自由度，或输入控制器与输出显示器之间的空间和时间关系。虽然人类表现在第 [2](#Chp002_31-91_B9780443140969000087.xhtml) 章中已详细阐述，但此处未深入讨论，仅通过次要观察提及某些交互较好、较差、笨拙或不直观。然而，归根结底，人类表现才是关键。物理属性虽具指导性且必不可少，但属于次要。换个说法，人类表现如同食物，而物理属性如同盘碗。我们追求的是美味且营养丰富的食物。

HCI 领域的实证研究主要在于寻找能改善和增强人类表现的物理属性及其组合。我们以关于那个令人沮丧的人类表现层面——交互错误——的评论作为本章关于交互元素的结语。虽然完成任务的时间可在一定程度上促进或阻碍表现，但错误只会阻碍。没有错误在很大程度上是不可见的。事实证明，错误——交互错误——与 HCI 体验息息相关。大错误是容易发现的——它们会被修复。有意思的是那些小错误。让我们来看看。

随着 HCI 领域的成熟，一种普遍观点浮现出来：困难问题（在桌面计算中）已解决，研究人员应专注于新前沿——移动性、表面计算、虚拟现实、普适计算、在线社交网络、游戏等。这种观点部分正确。是的，新兴主题令人振奋，是 HCI 研究的沃土。而且过去令人沮丧的许多 UI 问题已不复存在。但桌面计算仍充满问题，大量问题。让我们审视其中几个。虽然下面的例子来自桌面计算，但移动计算中也有对应情况。另见学生练习 [3-10](#Chp003_93-160_B9780443140969000099.xhtml#o0055)。

下面展开的四个例子选择自特定原因。它们呈递进关系。在严重程度上，从导致信息丢失的严重问题，到大多数用户很少考虑甚至可能注意不到的无害问题。在频率上，从极少发生（甚至不再发生），到用户从事计算活动时可能每分钟发生多次。那些大而棘手的问题在文献中广为流传，有来源提供了关于出错原因和缘由的深度分析（例如 [\[66\]](#Chp003_93-160_B9780443140969000099.xhtml#br0330)、[\[67\]](#Chp003_93-160_B9780443140969000099.xhtml#br0335)、[\[87\]](#Chp003_93-160_B9780443140969000099.xhtml#br0435)、[\[229\]](#Chp003_93-160_B9780443140969000099.xhtml#br1145)、[\[238\]](#Chp003_93-160_B9780443140969000099.xhtml#br1190)、[\[376\]](#Chp003_93-160_B9780443140969000099.xhtml#br1880)）。大问题受到大量关注，通常会被修复，而小问题往往挥之不去。我们马上就会看到其效应。让我们从一个大问题开始。

### 3.8.1 信息丢失

大多数用户在使用电脑时，都曾在某个时刻丢失过信息。新工作没有保存，反而被错误地丢弃、覆盖，或以其他方式丢失。有哪个用户没经历过这种事吗？当然，每个人都有因某种愚蠢方式丢失数据的经历。也许是分心了，也许只是不知情。不管怎样，事故发生了。[图 3.63](#Chp003_93-160_B9780443140969000099.xhtml#f0320) 展示了一个例子。对话框弹出，用户反应稍快了一点。在“保存更改？”对话框（[图 3.63](#Chp003_93-160_B9780443140969000099.xhtml#f0320)a）中按回车键一切安好，但在“放弃更改？”对话框（[图 3.63](#Chp003_93-160_B9780443140969000099.xhtml#f0320)b）中做出相同反应则酿成大祸。信息丢失了。Cooper [\[87, p. 14\]](#Chp003_93-160_B9780443140969000099.xhtml#br0435) 所述的这一场景，是一个严重的 UI 设计缺陷。细心的读者会立即反驳：是的，但如果“放弃更改？”对话框默认为“否”，信息就是安全的。但这偏离了重点。重点在于用户预期被打破了。被打破的预期迟早会导致错误。
