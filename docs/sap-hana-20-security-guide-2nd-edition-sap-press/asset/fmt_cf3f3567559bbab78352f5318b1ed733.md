
For secure access, the following examples should help you construct the correct URL:

*   `https://<sap_hana_host>:43<instance_number>/sap/hana/ide/security`

*   `https://sap-hana.myhost.com:4300/sap/hana/ide/security`

Once you have access to the SAP HANA Web-Based Development Workbench security manager, expand the Security node on the right. Expand Roles to reveal a list of standard roles defined in the system. Double-click a role to open the management interface for the given role. With the selected role management window open, you can begin granting and revoking privileges.

###### Note

To perform the same action for an individual user account, expand the Users node and double-click the desired user account.

As mentioned earlier, we recommend you use repository-based roles to support an SAP HANA security model. However, in this section, we’ll simply highlight the basic workflow if you chose to manage security with standard roles or directly on individual user accounts.

With the GUI management interface open for a given grantee, you can add an analytic privilege in the following way. Click the Analytic Privileges tab. Click the plus sign (`+`) button, which will open the Find Analytic Privileges window where you can search for a specific analytic privilege. Select the desired analytic privileges and click OK to add them to the list.

To save your changes, press (`Ctrl`)+(`S`), or click the disk icon at the top left to save and activate the privilege. To revoke an analytic privilege, select it in the list and click the red X. Once again, save the changes to make them active within the database system.

If any activation issues arise, warning messages will appear in the status frame at the bottom of the user management window. The status frame has a dark background. Error messages will appear in red text. Errors are only generated during an attempted activation or saving of changes.

### 10.8.4 Granting Analytic Privileges with Repository Roles

When SAP HANA was initially released, assigning analytic privileges to standard roles was the best available option. Multiple GUIs and SQL statements were created to help organizations manage granting and revoking privileges to standard role. As SAP HANA evolved, repository roles were introduced to aid in application development. Because of their numerous benefits, we highly recommend that repository roles be used to generate a security model. Now, let’s review the process for granting analytic privileges to and revoking analytic privileges from repository-based roles.

#### Script-Based Repository Roles

In [Chapter 6](#06_001.html#h6), we introduced you to repository roles and outlined the workflows required to create and manage repository roles. In this section, we’ll again review the syntax necessary to assign analytic privileges to design-time repository-based role scripts. If you require more information about this process, please see [Chapter 6](#06_001.html#h6).

When defining analytic privileges within design-time repository-based role scripts, you must start each line with `analytic privilege:`. After the colon, you can provide a comma-separated list of analytic privileges. At the end of the list, include a semicolon to finish the line. If you don’t want to include a comma-separated list, you can explicitly list each privilege on its own line, with each line beginning with `analytic privilege:`.

The following example grants the `ap_sales_reporting_region` analytic privilege, stored in the `e-corp.sales.security` package. Remember that repository package and object names are case sensitive:

```
analytic privilege:     
  e-corp.security:ap_sales_reporting_region.analyticprivilege;
```

In a final example, we’ll grant the `_SYS_BI_CP_ALL` system analytic privilege. This special catalog analytic privilege, when granted, gives full access to all information views defined within the repository:

```
catalog analytic privilege : "_SYS_BI_CP_ALL";
```

#### SAP HANA Web-Based Development Workbench Editor

The SAP HANA Web-Based Development Workbench editor, hosted within the XS engine, provides an interface that you can use to build and test development artifacts. From a security perspective, you can use this interface to create and manage repository-based roles. This interface offers all the advantages of repository-based roles without the need to use scripts and SAP HANA domain-specific language to create these roles. However, you can use this same interface to either edit the role via a GUI or open the role file in the text editor.

You can access the SAP HANA Web-Based Development Workbench editor via a supported Internet browser. The following URLs can be customized to match the details of your environment:

*   `http://sap-hana.myhost.com:8000/sap/hana/ide/editor`

*   `http://<sap_hana_host>:80<instance_number>/sap/hana/ide/editor`

Replace `<sap_hana_host>` with the host name of the SAP HANA system in your environment. Replace `<instance_number>` with the two-digit instance corresponding to your SAP HANA system.

For secure access, the following examples should help you construct the correct URL:

*   `https://<sap_hana_host>:43<instance_number>/sap/hana/ide/editor`

*   `https://sap-hana.myhost.com:4300/sap/hana/ide/editor`
