
| `SELECT` || This privilege allows the grantee to issue SQL `SELECT` statements against any applicable object defined within the referenced schema. This statement is typically used to query tables and views but also allows access to a sequence. |

| `INSERT` || This privilege allows the insertion of data into any table defined within the specified schema. |

| `UPDATE` || This privilege allows data to be updated within any table defined in the specified schema. |

| `DELETE` || This privilege allows data to be deleted within any table defined in the specified schema and applies to both the `DELETE` and `TRUNCATE` SQL actions. |

| `INDEX` || This privilege governs the ability to create, change, or remove an index for any table defined within the specified schema. |

| `TRIGGER` || This privilege governs the ability to create triggers associated with any table defined within the specified schema. |

| `DEBUG` || This privilege authorizes the debug functionality for any applicable object defined within the schema. |

| `REFERENCES` || This privilege allows the grantee to retrieve the name of the schema and its objects when using SAP HANA Studio, when using the SAP HANA database explorer, or when querying system views that contain basic table metadata. For example, the schema’s referenced table names will return when the granted user queries the system view tables using the SQL statement `SELECT * FROM SYS.TABLES`. |

| `CREATE TEMPORARY TABLE` || This privilege allows the grantee to create a temporary local table used by stored procedures. This privilege is independent from the `CREATE ANY` privilege to limit users from creating any type of object in a schema. |

| `CREATE VIRTUAL PACKAGE` || This privilege allows the grantee to create virtual packages. A virtual package is a file that contains Java libraries and resource files. This file is an archived (ZIP) file that can be referenced in virtual procedures and functions. For example, custom Spark procedures are virtual procedures that are used to access a Spark remote source via SAP HANA smart data access. |

| `SELECT CDS METADATA` || This privilege grants access to all core data services (CDS) metadata stored in the catalog for a given CDS table. |

| `UNMASKED` || This privilege grants access to masked data stored in a table and allows the grantee to query the table or view and view the actual data stored within. |

## Catalog Tables

[Table 8.2](#08_001.html#t8.2) lists the frequently used SQL actions related to tables that can be granted to a user or role. In [Table 8.2](#08_001.html#t8.2), we briefly describe how each action relates to tables in general.

| Grantable Privileges for Catalog Tables || Description of SQL Action |

| --- | --- |

| `ALTER` || This privilege allows the grantee to make DDL changes to tables, for example, to add or delete a column. |

| --- | --- |

| `DROP` || This privilege allows the grantee to remove a table from the system. |

| `SELECT` || This privilege allows the grantee to use `SELECT` in SQL statements to retrieve data from a table. |

| `INSERT` || This privilege allows the grantee to use `INSERT` in SQL statements to add additional data to the table. |

| `UPDATE` || This privilege allows the grantee to use `UPDATE` in SQL statements to update existing rows within a table. |

| `DELETE` || This privilege allows the grantee to use `DELETE` in SQL statements to delete or truncate one or more rows within a table. This action supports both `DELETE` and `TRUNCATE` SQL statements. |

| `TRIGGER` || This privilege allows the grantee to govern the ability to create triggers associated with the table. |

| `REFERENCES` || This privilege allows the grantee to grant limited access to any table referenced by a foreign key constraint. For example, say you’re securing a table named transactions that has a foreign key constraint or reference to a table named customers. Granting `REFERENCES` to table transactions also grants limited access to table customers. |

| `UNMASKED` || This privilege grants access to masked data stored in a table and allows the grantee to query the table or view and view the actual data stored within. |

## Catalog Views

[Table 8.3](#08_001.html#t8.3) lists the frequently used SQL actions related to catalog views. These actions can be granted to a user or roles. In [Table 8.3](#08_001.html#t8.3), we briefly describe how each action relates to the view and the objects referenced by the view.

| Grantable Privileges for Catalog Views || Description of SQL Action |

| --- | --- |

| `ALTER` || This privilege allows the grantee to make changes to the definition of a view. |

| --- | --- |

| `DROP` || This privilege allows the view to be deleted or dropped from the system. |

| `SELECT` || This privilege allows the grantee to use SQL `SELECT` statements against a view. Note that objects referenced within the definition of the view are granted as well. |

| `INSERT` || This privilege allows data to be inserted into the view’s underlying table. There are limitations to the types of catalog views that support these operations. | `UPDATE` || This privilege allows data to be updated within the view’s underlying table. There are limitations to the types of catalog views that support these operations. Based on our testing, you can only `UPDATE` data into a view if that view references a single table and if no formulas or functions are applied to the columns defined within the view. |

| `DELETE` || This privilege allows data to be deleted within the view’s underlying table. There are limitations to the types of catalog views that support these operations. Based on our testing, you can only `DELETE` data from a view if that view references a single table. |

## Catalog Stored Procedures and Functions

[Table 8.4](#08_001.html#t8.4) lists the frequently used SQL actions related to catalog stored procedures and to functions. Because these two catalog objects have the same privileges and related actions, we’ve combined them into a single table. These actions can be granted to a user or role. In [Table 8.4](#08_001.html#t8.4), we briefly describe how each action relates to the stored procedure or function and the objects referenced by each.

| Grantable Privileges for Procedures or Functions || Description of SQL Action |

| --- | --- |

| `ALTER` || This privilege allows for changes to the definition of the stored procedure or function using the `ALTER` SQL syntax. |

| --- | --- |

| `DROP` || This privilege allows the stored procedure or function to be deleted or dropped from the system. |

| `EXECUTE` || This privilege allows the stored procedure or function to be executed. Actions that can be executed directly depend on the SQL or SQLScript code defined within the procedure or function. In definer mode, objects referenced within the definition of the stored procedure or function don’t need to be explicitly granted to the user executing the stored procedure or function. Those objects are accessible by the creator of the procedure or function. However, objects referenced with the invoker mode enabled must be explicitly granted to the user executing the procedure or function. |

| `DEBUG` || This privilege allows for the debugging of the stored procedure or function. |
