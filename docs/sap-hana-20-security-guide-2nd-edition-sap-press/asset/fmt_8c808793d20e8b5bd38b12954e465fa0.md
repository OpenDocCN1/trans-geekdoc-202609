
# Listing 18.4 Required SYSTEM.hdbsynonym File for External Catalog Object References

The synonym is created in the HDI schema `MYPROJ_HDI_DB_1` and is required when objects within an HDI container must reference objects outside the HDI container. Again, the `#OO` user must have access to this object, or the project will fail to build.

In addition, you’ll need to create a `.hdbroleconfig` file that describes a reference to the external schema `SYSTEM`. [Listing 18.5](#18_004.html#l18.5) shows an example of the file that is required. This JSON file requires that you map the HDI container role, by name, to an external schema reference or alias. You’ll then use the reference name `"REF_SYSTEM"` within the definition of your `.hdbrole` file.

```
{ 
  "MyProj.db.roles::TABLE_READ_ONLY_ACCESS":{ 
    "REF_SYSTEM":{ 
      "schema":"SYSTEM" 
    }
  } 
}
```

# Listing 18.5 Required ROLEREF.hdbroleconfig File for External Schema References

Now that we’ve reviewed the example file, let’s look at some other syntax values that you can use. An `.hdbrole` file can reference existing roles in the HDI container within the `"global_roles"` value array. The following code is an example of the value string used to reference existing roles:

```
"global_roles":[ 
    "HDI_ROLE_1", 
    "HDI_ROLE_2" 
]
```

System privileges can be configured using the `"system_privileges"` value array. In the following example, we are referencing two system privileges:

```
"system_privileges":[  
   "BACKUP ADMIN",
   "USER ADMIN"
 ]
```

Analytics privileges or structured privileges can be referenced using the `"schema_analytic_privileges"` value array. The syntax required depends on the referenced object. If you’re referencing an analytic privilege that is within your HDI container, you would use the following syntax:

```
"schema_analytic_privileges":[
{
"privileges": ["MyProj.db.aps::AP_CUSTOMER"]
} 
```

In this case, you’ll only need the namespace or package folder structure and the name of the analytic privilege entered into the `"privileges"` value string. If you’re referring to an external structured privilege that has a schema, you would use the syntax shown in [Listing 18.6](#18_004.html#l18.6).

```
"schema_analytic_privileges":[
   {
     "schema_reference":"APSchemaRef1",
     "privileges": ["AP1", "AP2"] }
 ]
```

## Additional Information on the Syntax of the .hdbrole File

For additional information on the complete syntax of the `.hdbrole` file, refer to the “SAP HDI Artifact Types and Build Plugins Reference” section in the SAP HANA Development Infrastructure Reference Guide for SAP HANA 2.0 SPS 04, available at [http://s-prs.co/v498223](http://s-prs.co/v498223).

Recall from [Chapter 6](#06_001.html#h6) that repository-based roles in the SAP HANA XS platform could not be directly granted to a grantee using `GRANT` or `REVOKE` statements. You had to execute a stored procedure and provide input parameters to grant repository roles. This limitation is because only the owner `_SYS_REPO` can grant the role as no other user has the `WITH GRANT OPTION`. However, most of the GUI interfaces would automatically execute the procedures when you selected repository roles within the GUI workflow. HDI roles have a similar reequipment. Only system-managed technical users can grant HDI container roles out of the box. With the SAP HANA XS repository roles, you simply need to grant `EXECUTE` on the `_SYS_REPO` schema to security administrators, allowing them to perform the action. That process was easy to execute because the `SYSTEM` account had these privileges including the `WITH GRANT OPTION`. You could also include them in repository roles without much effort.

Within the HDI platform, only the `_SYS_DI` user and a few other technical users have these privileges directly by default. Therefore, you only have two options for granting these privileges:

*   You can use the SAP HANA database explorer based on a service connection of the HDI container. Within that connection, you can right-click and select `Open SQL Console (Admin)`, which will open the SQL console that impersonates a user that has `EXECUTE` access to the procedures.

*   You can leverage the stored procedure in the `_SYS_DI` schema called `GRANT_CONTAINER_API_PRIVILEGES_WITH_GRANT_OPTION`. By default, the `SYSTEM` account has `EXECUTE` privileges on this procedure. However, running this procedure is not straightforward since you must run a series of other SQL statements in the correct sequence to use this procedure properly.

Let’s look at each of these options in more detail starting with the first option.

## Granting HDI Roles with the SAP HANA Database Explorer

To grant an HDI role using SAP Web IDE for SAP HANA, you must first access the SAP HANA database explorer. In [Section 18.3](#18_003.html#h18.3), we provided details for accessing the SAP Web IDE for SAP HANA application. Once logged into the application, you’ll notice three icons on the vertical bar on the left side, as shown in [Figure 18.12](#18_004.html#f18.12). The icon that appears as a set of stacked cubes or boxes is the icon used to launch the SAP HANA database explorer view. You can also use the file menu option `Tools • Database Explorer` to launch the SAP HANA database explorer interface.

[![SAP HANA Database Explorer in SAP Web IDE for SAP HANA](bilderklein/klein18_012.png)](img-f18.12.html) 

**Figure 18.12** SAP HANA Database Explorer in SAP Web IDE for SAP HANA

Before you can launch the `Open SQL Console (Admin)` option, you’ll need to create the correct type of connection to the database. To create the connection, locate the large plus sign (`+`) above the pane that contains the existing database connections shown in [Figure 18.12](#18_004.html#f18.12). If this is the first time you’re accessing the SAP HANA database explorer, you won’t have an existing connection. Once you click the plus sign (`+`), the `Add Database` window will appear. Choose the Database Type of `HDI container`. Search for your current container. In our environment, the correct container was prefixed with the current logon user’s name followed by a serial code, and then our project name was suffixed with `hdi_db`, as shown in [Figure 18.13](#18_004.html#f18.13).

[![Adding a Database from an HDI Container Connection](bilderklein/klein18_013.png)](img-f18.13.html) 

**Figure 18.13** Adding a Database from an HDI Container Connection

This connection will show you all the catalog objects in the HDI’s database schema. To access the SQL console as an admin, right-click the connection’s top node and choose `Open SQL Console (Admin)`, as shown in [Figure 18.14](#18_004.html#f18.14).

The SQL console will open on the right, where you can execute a series of SQL statements that will grant HDI container roles to a specified user. The SQL that must be executed is somewhat complex. You must run five different statements to grant the role. In addition, you’ll need the technical name of the HDI container.

[![Accessing the SQL Console as an HDI Container Administrator](bilderklein/klein18_014.png)](img-f18.14.html) 

**Figure 18.14** Accessing the SQL Console as an HDI Container Administrator

If you need the technical name of the HDI container, you can run a SQL statement to view the name, but you’ll need to use a different SQL console. The Admin user does not have the correct access to show the technical container name, so you’ll need to run the SQL statement in a SQL console connected with a user with `SELECT` access on the `_SYS_DI` schema. For example, the `SYSTEM` user has this access by default. The following statement will show you the technical name of the HDI container:

```
SELECT * FROM "_SYS_DI".M_ALL_CONTAINERS WHERE CONTAINER_NAME like 'MYPROJ%';
```
