
# 系统权限说明

## CREATE SCHEMA

The CREATE SCHEMA system privilege grants the ability to execute the `CREATE SCHEMA` SQL command. The system usually creates a user schema for each standard user. However, if a user expects to create additional standard catalog schemas, he must be granted this system privilege.

## Data Admin

The DATA ADMIN system privilege governs access to several items. Like the catalog read system privilege, this privilege grants full read-only access to all system views stored in the `SYS` schema.

This privilege also allows the execution of any Data Definition Language (DDL) statement. For example, the `CREATE COLUMN TABLE` command is considered a DDL statement. DDL statements can be issued towards objects in any schema, even if the grantee doesn’t have `CREATE ANY` privilege access for the schema. However, this privilege doesn’t grant the grantee access to issue Data Manipulation Language (DML) statements against catalog objects that it doesn’t own or otherwise have DML access to.

In addition to allowing the execution of any DDL statement, the DATA ADMIN system privilege also grants the ability to delete any table in the system regardless of any other granted privileges. For reference, you could delete system-related tables when granted this privilege. Grantees can delete a table even if they don’t own it or otherwise have the `DELETE` privilege granted. Therefore, this privilege should only be granted on an extremely limited basis.

## Database Admin

The DATABASE ADMIN system privilege grants access to all SQL commands related to the tenant database, including tenant database SQL commands such as `CREATE`, `DROP`, `ALTER`, `RENAME`, `BACKUP`, and `RECOVERY`. In addition to specific SQL commands, this privilege also grants access to any SAP HANA-related GUI that issues the same statements on behalf of a user.

## Export

The EXPORT system privilege governs the ability to export catalog objects and data using the `EXPORT` SQL command or GUIs, such as the SAP HANA database explorer, that provide options to export catalog objects to the SAP HANA database file system. Based on our testing, this privilege only applies to the issuing of the SQL command in the SQL console or when the export location is the SAP HANA database filesystem. In addition to the EXPORT system privilege, the grantee will also need the `SELECT` privilege for the catalog objects being exported.

Note that this privilege doesn’t govern access to the export catalog object wizard in the SAP HANA database explorer in the SAP HANA cockpit, where the export location is local computer. To perform a catalog export using this GUI interface, the grantee only requires the `SELECT` privilege on the schemas or tables being exported.

## Extended Storage Admin

The EXTENDED STORAGE ADMIN system privilege grants the ability to manage SAP HANA extended storage and to issue SQL commands such as `CREATE EXTENDED STORAGE`, `ALTER EXTENDED STORAGE`, and `DROP EXTENDED STORAGE`. This privilege also governs read-only data access to extended storage system views such as `SYS.M_ES_DBSPACES`, `SYS.M_ES_DELTA_MEMORY`, and others. In addition to specific SQL commands, this privilege also grants access to any SAP HANA-related GUI that issues the same statements on behalf of a user.

## Import

The IMPORT system privilege governs the ability to import data into catalog tables using the `IMPORT` SQL command or GUIs, such as the SAP HANA database explorer, that provide options for importing catalog objects from the SAP HANA database file system. Based on our testing, this privilege only applies to the issuing of the SQL command in the SQL console or when the import location is the SAP HANA database file system. In addition to the import system privilege, grantees will also need the `INSERT` privilege on the target catalog table.

Note that this privilege doesn’t govern access to the import catalog object wizard in the SAP HANA cockpit’s SAP HANA database explorer, where the import location is local computer. To perform a catalog import using this GUI interface, the grantee also needs the `INSERT`, `UPDATE`, `DROP`, and `CREATE ANY` privileges on the target schema. If the schema doesn’t exist, the `SCHEMA ADMIN` system privilege will be required as well.

## INIFILE Admin

The INIFILE ADMIN system privilege governs access to changes within the system settings. With this privilege, the system configuration can be changed by issuing `ALTER SYSTEM ALTER CONFIGURATION` SQL statements in the SQL console.

## License Admin

The LICENSE ADMIN system privilege governs access to GUIs and SQL statements for installing and removing license keys. SQL statements such as `SET SYSTEM LICENSE` can only be issued in the SQL console once the license admin system privilege is granted.

## Log Admin

The LOG ADMIN system privilege governs access to the SQL command `ALTER SYSTEM LOGGING`. This command allows the redo logging mechanism to be enabled or disabled. When the redo logging mechanism is disabled, the relational database management system (RDBMS) can’t properly recover after an index server outage. Therefore, this privilege only should be granted as needed.

## Optimizer Admin

The OPTIMIZER ADMIN system privilege governs access to `ALTER SYSTEM` SQL commands, such as `ALTER SYSTEM CLEAR SQL PLAN CACHE`. These commands can influence the query optimizer.

## Resource Admin

The RESOURCE ADMIN system privilege governs access to a variety of SQL commands and GUIs used to affect system resources, table distribution, page file data encryption keys, and table partitioning. SQL commands such as `ALTER SYSTEM RECLAIM DATAVOLUME` and `ALTER SYSTEM RESET MONITORING VIEW` are managed by this system privilege. GUIs that reset memory statistics are also allowed when this system privilege is granted.

## Savepoint Admin

The SAVEPOINT ADMIN system privilege governs access to the `ALTER SYSTEM SAVEPOINT` SQL command. Executing this command will commit all in-memory data to the data volume within the persistent storage layers of SAP HANA. By default, SAP HANA savepoints are executed automatically by the system every 5 minutes.

## Scenario Admin

The SCENARIO ADMIN system privilege governs access to all calculation scenario-related activities, including the ability to create calculation scenarios. SAP hasn’t published significant information about calculation scenarios, but we do know that they’re fundamental to the creation of SAP HANA calculation views. Calculation scenarios normally are created by the `_SYS_REPO` account when SAP HANA information views are created.

## Service Admin

The SERVICE ADMIN system privilege governs access to the SQL commands and GUIs used to start, stop, kill, cancel, and reconfigure SAP HANA system services, such as `indexserver`, `compileserver`, `nameserver`, and `xsengine`.

## Session Admin

The SESSION ADMIN system privilege governs access to GUIs and SQL statements for canceling or changing a user session. SQL commands such as `ALTER SYSTEM CANCEL SESSION` and `ALTER SYSTEM ALTER SESSION` can’t be executed without this system privilege.

## Tenant Admin

According to the documentation, the TENANT ADMIN system privilege governs GUIs and SQL statements for resuming and suspending a tenant database. Unfortunately, the SAP HANA documentation doesn’t provide any example SQL statements that you can use to suspend or resume a tenant database, so we weren’t able to fully test this functionality. We did attempt to execute `ALTER SYSTEM SUSPEND TENANT <TENANT DATABASE>`, but an error was returned: Alter Tenant deprecated and Was Never Fully Implemented.

## Table Admin

The TABLE ADMIN system privilege governs GUIs and SQL statements used to unload columnar tables into memory, unload columnar tables from memory, and perform delta merges on columnar tables. Users granted this system privilege don’t require ownership of the table or schema, nor do they require any SQL object privileges to perform these actions.
