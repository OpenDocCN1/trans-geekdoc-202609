## 10.9 Summary

Most organizations will need to secure access to the data hosted in their SAP HANA systems. When this need arises, analytic privileges offer multiple solutions to manage access. Analytic privileges govern access to data made available through SAP HANA’s information views. Going forward, SQL-based analytic privileges will replace the legacy XML-based analytic privileges. SQL-based analytic privileges offer the ability to implement complex filter logic using subquery statements or complex filter condition statements. Like all privileges, SQL-based analytic privileges must be granted to a grantee before they go into effect. Ideally, you’ll assign analytic privileges to repository-based roles and then grant repository roles to users.

# 11 Application Privileges

In this chapter, we’ll discuss application privileges and how they relate to the security model and applications developed within the SAP HANA development platform.

Application privileges define custom levels of access to applications developed in the SAP HANA extended application services, classic model engine (`XS engine`) or the SAP HANA extended application services, advanced model engine (`XSA engine`). SAP HANA is an application development platform in which web-based applications can be developed and hosted. These applications sometimes need their own unique privileges to govern actions unique to the application. Take, for example, a web-based application that allows a user to respond to a series of questions. Some users need access to simply answer each question, and these users shouldn’t have the ability to see the results of other questionnaires given to other users. However, administrative users might need the ability to see the answers given by all users. Application privileges can be developed to facilitate these custom application-level security requirements. Application privileges then can be granted to roles within the security model.

In this chapter, we’ll provide an overview of application privileges within SAP HANA and describe how they’re created and granted to roles using a variety of options. We’ll also provide a brief summary of Privileges on Users and how it’s used to grant the `ATTACH DEBUGGER` privilege to another grantee.

## 11.1 What Are Application Privileges?

In principle, application privileges aren’t native to the SAP HANA relational database management system (`RDBMS`). These privileges don’t exist in SAP HANA unless they’re developed natively or imported from a delivery unit that supports an externally developed SAP HANA application. However, when an SAP HANA system is initially deployed, the installation engine will import several SAP-developed delivery units, which represent applications hosted in the `XS engine`. Many of these imported applications have associated application privileges and repository-based roles.

In most cases, these default application privileges are delivered with corresponding repository-based roles. You would typically grant the corresponding repository-based roles to other grantees and avoid directly granting these default application privileges. Most SAP-delivered application privileges are also not documented, but their corresponding repository-based roles are. Because these privileges aren’t well documented, what permissions they grant within the SAP-delivered `XS engine` applications is not always clear.

Starting with SAP HANA 1.0 SPS 11 and continuing in SAP HANA 2.0, most of SAP-delivered `XS engine`-based applications are in the process of transitioning to the SAP HANA cockpit or SAP Web IDE for SAP HANA. These web-based applications are hosted in the `XSA engine`. The advanced `XSA engine` runtime has its own role management interface based on `XSA engine` application-specific roles and doesn’t leverage classic SAP HANA 1.0 application privileges. Therefore, though we’ll discuss application privileges in this chapter, keep in mind that they’ll become obsolete in the future and that the content in this chapter applies to application privileges within the `XS engine`.

## 11.2 Creating Application Privileges

Application privileges are defined within specific files that are stored in the SAP HANA `XS package repository`. These privileges must be stored in a package in which the corresponding application code resides and are defined based on a domain-specific language using a text editor. The process is similar to the process of defining repository roles within design-time scripts.

Two different types of script files must be created within the `XS engine` application package hierarchy. The first script file has the `.xsprivileges` file extension and doesn’t require a file name. This file, called the application-privileges file, defines one or more application privileges for the associated application. The application-privileges file is stored at the top of the application’s specific package hierarchy node to encompass the full scope of all subsidiary application access definitions. The application-privileges script is programmed as a catalog, list, or definition of all subsidiary authorization privileges specific to the application. The script shown in [Listing 11.1](#11_002.html#l11.1) illustrates how three example authorizations, `QEdit`, `QAdmin`, and `QView`, are defined.

```
{
 "privileges" :
  [
   { "name" : "QEdit", "description" : "Edit Questions" },
   { "name" : "QAdmin", "description" : "Full Access"},
   { "name" : "QView", "description" : "View Questions"},
  ]
}
```
