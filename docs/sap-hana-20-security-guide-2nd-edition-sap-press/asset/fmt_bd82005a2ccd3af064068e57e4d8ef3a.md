
The `TRACE ADMIN` system privilege enables a role to configure traces within the SAP HANA system. This privilege also authorizes the ability to delete trace files from the system.

### Version Admin

The `VERSION ADMIN` system privilege governs access to SQL statements used to manage the row-store garbage collector, for example, `ALTER SYSTEM RECLAIM VERSION SPACE`.

### Workload Admin

The `WORKLOAD ADMIN` system privilege governs access to SQL statements used to `CREATE`, `ALTER`, and `DROP` workload mappings and workload classes. Workloads and workload classes are used to govern statement execution priority, statement memory limits, or statement thread limits based on user- or application-specific information.

## 7.2.4 Environment Monitoring-Related System Privileges

Individuals that monitor the SAP HANA system will typically require the following privileges. Thus, for example, the `CATALOG READ` system privilege is included with the `MONITORING` default role.

### Catalog Read

The `CATALOG READ` system privilege provides full read-only data access to all catalog views within the `SYS` schema. No filter restrictions will be applied to the view, and no further privileges are required to access system view data.

### Monitor Admin

The `MONITOR ADMIN` system privilege governs access to `ALTER SYSTEM` SQL commands specific to event management.

## 7.2.5 Environment Performance-Related System Privileges

For individuals using workload-related tools to capture, compare, or test the performance of a particular workflow, the following system privileges will likely be required.

### Workload Analyze Admin

The `WORKLOAD ANALYZE ADMIN` system privilege governs access to workload analysis, capture, and replay actions within the SAP HANA system.

### Workload Capture Admin

The `WORKLOAD CAPTURE ADMIN` system privilege governs data access to the `SYS.M_WORKLOAD_CAPTURES` system view and grants the `EXECUTE` privilege on the `SYS.WORKLOAD_CAPTURE` stored procedure. Capturing and replaying workloads allows administrators to view performance impacts after changes are made in SAP HANA configuration or hardware.

### Workload Replay Admin

The `WORKLOAD REPLAY ADMIN` system privilege governs data access to the `SYS.M_WORKLOAD_REPLAY_PREPROCESSES` and `SYS.M_WORKLOAD_REPLAYS` system views. This privilege also grants the `EXECUTE` privilege on the `SYS.WORKLOAD_REPLAY` stored procedure. Capturing and replaying workloads allows administrators to view performance impacts after changes are made in SAP HANA configuration or hardware.

## 7.3 Granting System Privileges

In this section, we’ll review the various options available to grant and revoke system privileges: SQL commands, the SAP HANA cockpit, the SAP HANA Web-Based Development Workbench security manager, and repository-based role scripts or the repository-based role editor GUI.

### 7.3.1 Granting System Privileges with SQL

Using the SQL console and SQL statements, you can both grant and revoke privileges to roles or users. Let’s look at a series of example SQL statements used to grant system privileges to both users and roles.

With system privileges, the grantee can be either a user account or a role. A sound security model will grant privileges to roles and avoid directly granting individual privileges to individual users. Technically, you can grant system privileges to a grantee using the `GRANT` SQL syntax. However, as we’ve discussed, using repository-based roles, which don’t use SQL to grant system privileges, is best; we’ll review this benefit again in [Section 7.3.4](#07_003.html#h7.3.4). With that said, reviewing the process for granting system privileges to standard users or roles is still important. Although we’ve provided SQL script examples in several chapters, let’s take a moment to review the SQL statement for granting system privileges to a grantee. Note that a semicolon marks the end of each of the following SQL statements:

```
GRANT <SYSTEM_PRIVILEGE> TO <GRANTEE>;    
GRANT <SYSTEM_PRIVILEGE> TO <GRANTEE> WITH ADMIN OPTION;    
GRANT DATA ADMIN, EXPORT, IMPORT TO ROLE_SEC_ADMIN WITH ADMIN OPTION;
```

The first statement provides the general syntax, with variables indicated by text within angle brackets (`<>`). The variables must be replaced with items unique to your environment. The `<SYSTEM_PRIVILEGES>` variable can be replaced with a comma-separated list of system privileges, as shown in the third statement. The `<GRANTEE>` variable will be replaced with the name of an activated role or user account within the system.

The second SQL statement includes the `WITH ADMIN OPTION` at the end, which allows the grantee of the role to subsequently grant the same privilege to another user or role. This option is typically reserved for user grantees that manage security models.

The final statement provides a complete example in which system privileges are granted to the `ROLE_SEC_ADMIN` role. This statement includes the `WITH ADMIN OPTION`, allowing the role grantee to grant the same privileges to other users or roles.

You can also revoke system privileges using the `REVOKE` SQL syntax, as follows:

```
REVOKE <SYSTEM_PRIVILEGE> FROM <GRANTEE>;    
REVOKE DATA ADMIN, EXPORT, IMPORT FROM ROLE_SEC_ADMIN;
```

The first statement provides the general syntax, and the second SQL statement provides a full example, in which the listed system privileges are removed from the `ROLE_SEC_ADMIN` role.

### 7.3.2 Granting System Privileges with the SAP HANA Cockpit

Let’s review the workflows for granting and revoking system privileges with the SAP HANA cockpit. As an alternative to using SQL statements, you can use the SAP HANA cockpit links `Assign Privileges` or `Manage Roles`. Each interface allows you to both grant and revoke system privileges for a given user account or for a given role. Most users will find using the SAP HANA cockpit easier than memorizing and entering in SQL statements.

To access the `Assign Privileges` or `Manage Roles` area, start at the SAP HANA cockpit Home screen and locate an SAP HANA system in the Resource Directory. Connect to the desired tenant database or `SYSTEMDB`, which will take you to the System Overview window. Using the `Filter by Area` dropdown list, choose the option `Security`. Locate the `Assign Privileges` or `Manage Roles` in the User & Role Management tile.

[Section 7.1](#07_001.html#h7.1) shows the `Assign Privileges` interface within the SAP HANA cockpit for the `TEST_01` user account. In this window, you’ll see several tabs, one for each privilege category, starting with `System Privileges`, `Object Privileges`, `Analytic Privileges`, `Application Privileges`, `Package Privileges`, and `Privileges on Users`. You’ll find a similar interface when working with roles. However, the `Role Details` GUI has an additional link called `Roles` where you can grant existing roles to the selected role.
