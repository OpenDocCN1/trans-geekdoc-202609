
# 数据定义

The data definition category includes almost all CREATE, ALTER, DROP, and RENAME SQL actions that can be performed against a catalog object. Catalog objects include tables, views, schemas, indexes, and triggers, among others. The actions listed in this category are specific to particular catalog objects. For example, you’ll find CREATE TABLE, CREATE VIEW, CREATE PROCEDURE, and CREATE actions for most catalog objects in this category. Policies with these actions do not have to be assigned to specific users.

# 数据预配置

## 9. Data provisioning

The data provisioning category includes ALTER, CREATE, DROP, and PROCESS REMOTE SUBSCRIPTION EXCEPTION commands related to external adapters, agents, and remote subscriptions. Policies with these actions do not have to be assigned to specific users.

# 数据查询和操作

## 10. Data query and manipulation

The data query and manipulation category includes all SQL actions performed against a specific target catalog object. These actions are related to SQL commands such as DELETE, EXECUTE, INSERT, SELECT, and UPDATE. For example, you can record actions when a user issues a SELECT statement against a specific table or all objects in a schema. Basing the rules on a schema is beneficial for auditing all catalog objects within the schema. The actions selected are not specific to any particular catalog object type, but you must specify the target object and target user when defining the policy. To avoid any negative performance impacts, audit policies based on these rules should be limited.

# 卷加密

## 11. Volume encryption

The data volume encryption category includes all SQL actions related to the ALTER command against application, data, and log encryption. This category also includes the ALTER command used to change the root key backup password. Policies with these actions do not have to be assigned to specific users.

# 授予和撤销授权

## 12. Granting and revoking authorizations

The granting and revoking authorizations category contains actions specific to the use of SQL commands such as GRANT and REVOKE. These commands are used to grant or revoke privileges to users or roles. The system will only capture instances in which a user is the grantee of the privilege. Policies with these actions do not have to be assigned to specific users or target objects.

Note that most organizations use repository-based roles within their security model. Actions in this category won’t capture granting and revoking repository-based roles. Organizations will need to set up policies that monitor the execution of the stored procedures within the `_SYS_REPO` schema. For example, a data and query manipulation action must be set up to monitor the execution of the `_SYS_REPO.GRANT_ACTIVATED_ROLE` stored procedure.

# 许可证删除

## 13. License deletion

The license deletion category contains one action, which can be used to audit instances in which the SAP HANA license key is removed from the system. For example, if a user executes the SQL statement UNSET SYSTEM LICENSE within the SQL console or uses the SAP HANA Studio GUI to delete the license key, this action will be recorded as an event. Policies with this action do not have to be assigned to specific users or target objects.

# 许可证安装

## 14. License installation

The license installation category contains one action, which can be used to audit instances in which an SAP HANA system license key is added to the system. For example, if a user executes the SQL statement SET SYSTEM LICENSE within the SQL console or uses the SAP HANA Studio GUI to install a new license key, this action will be recorded as an event. Policies with this action do not have to be assigned to specific users or target objects.

# 多租户数据库容器操作

## 15. Operations on multitenant database containers

The operations on multitenant database containers category records activities within the system database related to tenant databases. Actions such as ALTER, CREATE, DROP, RENAME, START, and STOP can all be recorded.

# 存储库内容操作

## 16. Repository content operations

The repository content operations category contains actions specific to importing, exporting, and activating development artifacts within the SAP HANA repository. Policies using these actions must specify one or more user accounts to either include or exclude from the policy. It’s important to limit the scope of these actions because they might negatively affect the performance of the system.

# SAP HANA 动态分层

## 17. SAP HANA dynamic tiering

The SAP HANA dynamic tiering category contains actions specific to the management of dynamic tiering. These policies are only necessary when dynamic tiering is installed and enabled within the SAP HANA cluster. Policies with these actions do not have to be assigned to specific users or target objects.

# 会话管理和系统配置

## 18. Session management and system configuration

The session management and system configuration category contains actions related to session management, stopping services, and system configuration changes. In most cases, these actions should be included in any audit policy. For example, you’ll need to record any system configuration changes and any instances in which a user’s session is terminated. Note that configuration changes related to auditing do not require a policy defined with these actions. Audit changes are system-mandatory and always will be recorded. Policies with these actions do not have to be assigned to specific users or target objects.

# 结构化权限管理

## 19. Structured privileges management

The structured privileges management category contains actions specific to the management of repository analytic privileges and catalog structured privileges. Structured privileges are catalog objects used to restrict access to information views and catalog views. When restricting an SAP HANA information view, these privileges are called analytic privileges, but they are still technically structured privileges.

Note that the system account `_SYS_REPO` will be recorded in the audit logs as the action user when a repository analytic privilege is changed or created. To properly audit repository-based analytic privileges, you’ll also need to enable actions within the repository content operations category using a separate policy rule. Both actions will have the same timestamp, which can be used to correlate the two events. Policies with these actions do not have to be assigned to specific users or target objects.

# 用户和角色管理

## 20. User and role management

The user and role management category contains actions specific to actions that alter, drop, or create a user account or standard role. For example, when a user is created, these events can be included in a policy to capture the action within the audit logs.

Note that these actions do not audit repository-based roles. Organizations will need to enable actions within the repository content operations category using a separate policy rule to monitor the creation of repository-based roles. Policies with this action do not have to be assigned to specific users or target objects.

# 审计操作状态

## Audited Action Status

In an ideal scenario, organizations would audit all actions within the SAP HANA system. Unfortunately, auditing all actions can affect the performance of the system negatively and can lead to a significant increase in memory consumption based on the growth of the audit log table. Therefore, audit rules must be defined based on necessity. Fortunately, you can specify several conditions when defining audit policies; one such condition is the audit action status.
