## 12.2 SAP HANA and LDAP Authentication

Starting with SAP HANA 2.0 SPS 03, LDAP-based users can now be provisioned within SAP HANA, and their LDAP-managed passwords can be used for authentication. When an SAP HANA user is set up for LDAP authentication, standard local password authentication is disabled. Thus, the user can only authenticate via one of the supported SSO providers or using their LDAP credentials. For example, if your Active Directory account is configured as an LDAP account in SAP HANA, you could access SAP HANA Studio using your Active Directory-managed password. You could not set up a locally managed SAP HANA password for that same account.

Before you can create LDAP users, SAP HANA must also be preconfigured with an LDAP provider, and SAP standard roles should be mapped to LDAP groups. Based on the configuration of the LDAP provider, LDAP users can be automatically created in SAP HANA. In addition, you can use the `CREATE USER <USER_NAME> WITH IDENTITY FOR LDAP PROVIDER` SQL statement to create an LDAP user manually, and the SAP HANA cockpit provides an option, when creating a user, for you to choose the authentication password mode (Local or LDAP). Note that user accounts can be changed from local to LDAP password authentication within the SAP HANA cockpit or with SQL by first running `ALTER USER <USER_NAME> DISABLE PASSWORD` and then `ALTER USER <USER_NAME> ENABLE LDAP`.

Again, before you can use LDAP authentication or authorization, you must first create an LDAP provider, which any administrator with the LDAP ADMIN system privilege can do via the SQL console.

Prior to configuring an LDAP provider, you must fulfill the following prerequisites:

*   The LDAP source must be LDAP v3 compliant.
*   You must have the system privilege LDAP ADMIN, which allows you to configure the LDAP provider.
*   You must create a certificate collection with purpose LDAP and import the certificate from the LDAP server into this collection. Without this certificate, SAP HANA and LDAP will not have secure communications.
*   You must verify that the `[authentication]` parameter with key `authentication_methods` in the `global.ini` configuration file has `ldap` included in the comma-separated list of providers.
*   You must identify LDAP groups that will be mapped to SAP HANA roles.

Again, you’ll create the LDAP provider using SQL. [Listing 12.2](#12_002.html#l12.2) shows an example of how you would create an LDAP provider against an Active Directory LDAP. Assume that the Active Directory domain name is `ecorp.local` and that SSL is required for communication. We’re also assuming that the LDAP provider can automatically create LDAP-based users within the SAP HANA database.

```
CREATE LDAP PROVIDER ldap_ecorp
CREDENTIAL TYPE 'PASSWORD' USING 'user=CN=HDBLDAP,OU=Service Accounts,DC=ecorp,DC=local;password=N0tIt2018'
USER LOOKUP URL 'ldap://ecorp.local:389/CN=Users,DC=ecorp,DC=local??sub?(&(objectClass=user)(sAMAccountName=*))'
NESTED GROUP LOOKUP URL 'ldap:// ecorp.local:389/DC=ecorp,DC=local??sub?(member:1.2.840.113556.1.4.1941:=*)'
ATTRIBUTE DN 'distinguishedName'
ATTRIBUTE MEMBER_OF 'memberOf'
SSL ON
DEFAULT ON
ENABLE PROVIDER 
ENABLE USER CREATION FOR LDAP;
```

Next, you’ll create a certificate personal security environment (PSE) and set its purpose to LDAP in SAP HANA. In the SAP HANA database, you’ll use the PSE to organize and store SSL certificates. To create the required LDAP PSE, execute the following SQL statements:

```
CREATE PSE LDAP_PSE; 
SET PSE LDAP_PSE PURPOSE LDAP;
```

You’ll then assign the imported certificate to this PSE, which is a two-step process. First, find the certificate ID of the certificate you just imported. You can run the following example SQL to identify the system-generated ID. Look for the comment we added when importing the certificate to properly identify it:

```
SELECT * FROM CERTIFICATES; /*Get Certificate ID*/
```

With the ID identified, you’ll then run the following example SQL to assign the certificate to the PSE collection:

```
ALTER PSE LDAP_PSE ADD CERTIFICATE 378500; /*Use Certificate ID from above*/
```

If everything is set up properly, you can validate the LDAP provider and authentication for a specific user, for example, `JONATHHAU99`, using the following example SQL statements:

```
VALIDATE LDAP PROVIDER ldap_ecorp CHECK USER JONATHHAU99 PASSWORD "NeverG0ing2Get!t"; 
```

If the user does not already exist in SAP HANA, you can validate that the LDAP provider would automatically create a missing user, for example, `JIMGTO88` using the following example SQL:

```
VALIDATE LDAP PROVIDER ldap_edcorp CHECK USER CREATION FOR LDAP USER JIMGOT88 ;
```

## 12.3 Supported Third-Party Authentication Providers

SAP HANA supports several well-established, third-party authentication mechanisms for the purposes of SSO. This support simplifies the process of authentication within SAP HANA from trusted third-party applications. However, unlike with LDAP authentication, users cannot directly authenticate with their third-party passwords when using SSO. With third-party authentication, users aren’t required to manually reenter their user name and password each time they access resources within the SAP HANA platform. Instead, the SAP HANA system will trust that the external system has already properly authenticated the user and will therefore securely trust requests for the user from the external system. SAP HANA supports third-party system access via the HTTP, HTTPS, ODBC, and JDBC protocols, which allow for access to both web-based applications and data hosted in the SAP HANA platform. In this section, we’ll discuss several third-party authentication mechanisms, namely, Kerberos, SAML, X.509, SAP logon tickets, and SAP assertion tickets, and JWT identity providers, starting with Kerberos authentication.
