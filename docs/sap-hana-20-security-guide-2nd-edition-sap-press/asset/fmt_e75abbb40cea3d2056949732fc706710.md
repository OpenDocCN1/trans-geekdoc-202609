
# SAP HANA Architecture Overview

The core service of the platform is the index server, responsible for all database, data storage, and data processing tasks. When stored in-memory, data resides within the index server process. This data includes data stored in row or columnar store tables. When a SQL or Multidimensional Expression (MDX) query is executed by a business intelligence application, the index server processes the query and returns the results. The index servicer is responsible for queries executed in the OLAP engine, the calculation engine, the join engine, and the row engine, making it the most important service in the platform.

The index server manages many objects within the security model, such as users, roles, authentication, audits, catalog objects, and development repositories, and thus is responsible for most of the security within SAP HANA.

## XS Engine

The XS engine acts as a web application server and manages and processes application code deployed to the SAP HANA platform. Applications like the SAP HANA Web-Based Development Workbench editor reside in the XS engine. Developers can also create custom applications using JavaScript and HTML5 and operate these applications in the XS engine.

The XS engine hosts many applications for managing security within SAP HANA and also provides applications to help you with the lifecycle management of SAP HANA. However, SAP has indicated that, in the long term, the XS engine and its application development will be replaced with the SAP HANA XSA platform. As of SAP HANA 2.0 SPS 04, the XS engine, the `_SYS_REPO` repository, and some SAP HANA XS applications are still available and usable.

## XSA Engine

Introduced in SAP HANA 1.0 SPS 11, the XSA engine is a robust web application server that you can use to manage and process application code. However, its overall architecture is quite different from the XS engine. Applications like the SAP HANA cockpit and SAP Web IDE for SAP HANA are hosted within this service. The XSA engine can be installed with your SAP HANA instance or on SAP HANA, express edition, where it can run as a standalone application server. Each SAP HANA XSA application is assigned a child process and a TCP/IP connectivity port. Thus, an individual application can crash without crashing the entire SAP HANA XS runtime. SAP HANA XSA also supports advanced programing languages, which enables you to create more sophisticated applications.

You can also use applications like the SAP HANA cockpit and SAP Web IDE for SAP HANA to manage many aspects of the SAP HANA security model.

## Name Server

The name server is responsible for managing the topology of the SAP HANA architecture. With an SAP HANA scale out, the name server tracks which services are active and where data tables reside in the cluster.

The name server configuration file contains the configuration of the global password policy, which defines how SAP HANA manages password authentication throughout a scale-out landscape.

## Preprocessor Server

The preprocessor server helps the index server process text-based searches. This server includes features such as sentiment analysis, text analysis, full-text search, and fuzzy search of both structured and unstructured text. This service does not play a major role in securing SAP HANA.

## Compile Server

The compile server is responsible for helping the index server compile L language-based procedures. This server was removed from the index server in SAP HANA SPS 06 to prevent compiling tasks from crashing the index server. However, the exact reason why the compile server was isolated from the index server have never been officially published by SAP. This service does not play a major role in securing SAP HANA.

## Script Server

The script server is responsible for helping SAP HANA process operations that require the Application Function Library (AFL), which includes the BFL and the PAL. Developers or applications using SAP HANA for predictive modeling will use this service. This service does not play a major role in securing SAP HANA.

Outside of its core services, several external applications can also access SAP HANA. [Figure 3](#00_002.html#f0.3) shows a few common clients and their communication protocols. The communications between these clients and the core SAP HANA server is particularly important in the realm of security. SAP HANA supports secure communication with all client applications. SAP HANA Studio, the SAP HANA cockpit, and SAP Web IDE for SAP HANA can use Open Database Connectivity (ODBC), Java Database Connectivity (JDBC), or Hypertext Transfer Protocol (HTTP) to communicate with the SAP HANA system. Each of these communication paths supports strong encryption. Many business intelligence applications also support ODBC and JDBC connectivity. For applications hosted in the XS engine, SAP HANA supports secure communication over HTTP or secure HTTPS.

# Introduction to SAP HANA Security

At its core, SAP HANA security consists of users, roles, and privileges. User accounts are created and assigned one or more roles, and roles are created and assigned one or more privileges. The combination of roles and privileges determines what a user account is authorized to do within the SAP HANA platform. [Figure 4](#00_002.html#f0.4) shows a high-level overview of the relationships among users, roles, and privileges.

[![Overview of Users, Roles, and Privileges](bilderklein/klein00_004.png)](img-f0.4.html)

**Figure 4** Overview of Users, Roles, and Privileges

Privileges are categorized into system, package, application, analytic, and object categories. Each category controls a specific area within the SAP HANA architecture. However, a user account can’t interact with the SAP HANA system until the account is authenticated. Typically, a password is provided for authentication, but SAP HANA also supports several third-party authentication mechanisms.

Outside of the core areas of users, roles, and privileges, security administrators must also focus on encryption, audit policies, user provisioning, lifecycle management, and security model troubleshooting. Throughout this book, we’ll introduce these key concepts and immerse you in the knowledge necessary for mastering the SAP HANA security model.

# Importance of Securing Your SAP HANA System

As mentioned in the Overview of SAP HANA section, SAP HANA often hosts critical data for the organization. SAP HANA also often operates applications that are vital to the organization. Databases like SAP HANA often contain master sources of data, such as customer, product, and financial data; sales orders; and bills of materials (BOMs). If the integrity of these systems are compromised, your organizations could suffer substantial financial loss or lose competitive advantage.

Therefore, your organization must implement a proper security model within its SAP HANA systems. Of equal importance is for an organization to invest in training and resources for managing the security model and accessing the system. SAP HANA can only be secure when its administrators and users can adhere to all aspects of the security model.

Four key reasons that your organization needs to secure its SAP HANA systems include the following:

* Organizations should provide privacy to protect data that is stored and accessed within the SAP HANA system. This protection includes the use of encryption to secure both in-memory data and data on disk as well as encryption to secure the communication of data between a client and the SAP HANA server. Authorization and authentication also play an important role in maintaining the privacy of data. In general, only authorized individuals should be granted access to your organization’s data.
