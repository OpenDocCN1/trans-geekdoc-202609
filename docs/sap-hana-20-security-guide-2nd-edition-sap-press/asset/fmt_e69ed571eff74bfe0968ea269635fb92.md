
Before the SAP HANA administrator can import the CSV file into the SAP HANA system, he must create a table to store the data. Based on advice from the E-Corporation security consultant, the administrator will create a new repository schema and a new repository-based table to facilitate the imported LDAP user list. Using a dedicated schema and table to host security-related data and programs simplifies the process of restricting access to the schema, table, procedures, and future support objects.

In this case study, we’ll walk you through the technical aspects of the solution. We’ll start by reviewing the processes needed to import the LDAP user list into an SAP HANA table; then, we’ll review the processes necessary to create repository-based stored procedures that will programmatically provision, deactivate, and delete user accounts imported from the LDAP system.

### 4.5.1 Creating a Repository Schema

Before creating a repository schema, the administrator decided to create a few new package hierarchy levels to store the new development objects for his user-provisioning program. E-Corporation already has a root package named Security. The new program will require a schema, table, and series of stored procedures. The repository schema development artifact will be stored in a subpackage named Schemas, the repository stored procedure development artifacts will be stored in a subpackage named Provisioning, and the repository table development artifacts will be stored in a subpackage named Tables. [Figure 4.18](#04_005.html#f4.18) shows how the completed package hierarchy should be configured within the SAP HANA Web-Based Development Workbench editor.

[![Package Hierarchy to Store Security-Related Development Content](bilderklein/klein04_018.png)](img-f4.18.html)

**Figure 4.18** Package Hierarchy to Store Security-Related Development Content

To create the package hierarchy, log on to the SAP HANA Web-Based Development Workbench editor. On the left side, expand Content. Expand the package hierarchy to reveal the root-level package node named Security. Then, right-click the Security node and choose New • Package to define each subpackage shown in [Figure 4.18](#04_005.html#f4.18). For example, enter “Tables” in the Package Name field to create a new Tables subpackage.

To create a repository schema within the package hierarchy, right-click the Schemas package and choose New. In the popup window, choose File. Enter the file name “security_tables.hdbschema.” A new empty file will appear where you can define the repository schema syntax.

Define the repository schema that will be used to stored repository-based catalog objects related to managing SAP HANA security using the following syntax:

```
//To define the HDB schema, use the following code:     
schema_name = "security_tables";
```

Activate the design-time script by clicking the save icon (floppy disk). [Figure 4.19](#04_005.html#f4.19) shows an example of `security_tables.hdbschema` file and its definition within the SAP HANA Web-Based Development Workbench editor.

[![Defining the security_tables Schema in the Repository](bilderklein/klein04_019.png)](img-f4.19.html)

**Figure 4.19** Defining the security_tables Schema in the Repository

### 4.5.2 Creating a Repository Table

With the `security_tables` schema defined, you can now create a repository-based table to host the LDAP data imported from the CSV file. To create a repository table, right-click the `Security.Tables` package and choose New • File. Name the file “adusers.hdbtable” and click Create.

Using the repository table’s definition syntax, define a table containing four columns: `USER_NAME`, `AD_USER_NAME`, `EMAIL_ADDRESS`, and `ACCOUNT_STATUS`. [Listing 4.9](#04_005.html#l4.9) shows the syntax required to define the repository table. Activate the design-time script by clicking the save icon.

```
table.schemaName = "security_tables";
table.tableType = COLUMNSTORE;

table.columns =
 [
    {name = "USER_NAME";  sqlType = NVARCHAR;  length = 256; 
comment = "User Name in SAP HANA System"; },
    {name = "AD_USER_NAME";  sqlType = NVARCHAR;  length = 256; 
comment = "User Name in AD System"; },
    {name = "EMAIL_ADDRESS";  sqlType = NVARCHAR;  length = 256; 
comment = "Email address from AD System"; },
    {name = "ACCOUNT_STATUS";  sqlType = NVARCHAR;  length = 1; 
comment = "A for Active, D for Disabled"; }     

];    

table.primaryKey.pkcolumns = ["USER_NAME"];
```

**Listing 4.9** Repository Table Syntax

Once the repository table script is activated, table `Security.Tables::adusers` will appear in the `security_tables` schema. We’re now ready to load our CSV data into this table.

### 4.5.3 Importing a CSV File into a Table

Recall that our LDAP system administrator provided a CSV file containing a list of over 5,000 users. You now need to add the contents of this CSV file into the repository.

The SAP HANA repository can store files of just about any type, including `.csv` files. To validate the design of the solution, let’s say our SAP HANA developers have decided to store the `.csv` in the repository and then define a table import repository object to load the contents of the `.csv` into the `Security.Tables::adusers` table, which we designed in [Section 4.5.2](#04_005.html#h4.5.2). To create the `.csv`, right-click the package `Security.Tables` and choose New • File. Enter the name of the file as “user_list.csv” and click Create. An empty file tab will appear. Copy and paste the contents of the provided `.csv` file into the `user_list.csv` file hosted in the repository. Once you’ve placed the contents in the file, click the save icon to activate the file in the repository. [Figure 4.20](#04_005.html#f4.20) shows an example of this file in the repository.

[![Defining the user_list.csv File in the Repository](bilderklein/klein04_020.png)](img-f4.20.html)

**Figure 4.20** Defining the user_list.csv File in the Repository

Next, you’ll need to define a table import configuration file to import the `.csv` file into the `Security.Tables::adusers` table. Table import configuration files use a specific keyword and value pair syntax to define the source `.csv` file and the target table. These files have the `.hdbti` extension, and once saved and activated, the contents of the source `.csv` file will be imported into the target table.

To create the `.hdbti` file, right-click the package `Security.Tables` and choose New • File. Enter the name of the file as “user_list.hdbti” and click Create. An empty file tab will appear. Enter the syntax shown in [Listing 4.10](#04_005.html#l4.10).

```
import = [
{
hdbtable = "Security.Tables::adusers";                   
file = "Security.Tables:user_list.csv";    
header = true;
delimField = ",";
} 
];
```

**Listing 4.10** The user_list.hdbti File Syntax

Click the save icon to save and activate the `.hdbti` file. Once saved, the contents of the `.csv` file will be imported into the table `Security.Tables::adusers`.

### 4.5.4 Creating a Repository Role to Access the Table

Before developers and administrators can view the contents of the `Security.Tables::adusers` table, the security team must define roles that will give these users access to view the table contents at runtime. To accommodate this requirement, our developers opened a request with the security team asking for a new repository role to be defined and then for the repository role to be granted to the developers.

The security team defined a role named `SCHEMA_ADMIN_SECURITY_TABLES` and placed it in the `Security.Roles` package. [Figure 4.21](#04_005.html#f4.21) shows an example of how this role was defined in the SAP HANA Web-Based Development Workbench editor.
