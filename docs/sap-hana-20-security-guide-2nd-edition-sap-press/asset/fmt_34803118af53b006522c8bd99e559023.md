
This package privilege grants edit privileges to design-time objects within a package. This privilege only applies to imported objects or those imported from a delivery unit.

`REPO.ACTIVATE_IMPORTED_OBJECTS`

This package grants that ability to create, activate or reactivate design-time objects within a package. This privilege only applies to imported objects or those imported from a delivery unit.

`REPO.MAINTAIN_IMPORTED_PACKAGES`

This package privilege grants the ability to edit and create packages and subpackages. This privilege only applies to imported packages or those imported from a delivery unit.

## 9.3 Granting Package Privileges

In this section, we’ll review four options available for granting package privileges: via SQL commands, the SAP HANA cockpit, the SAP HANA Web-Based Development Workbench security manager, and repository-based role scripts/the repository-based role editor.

### 9.3.1 Granting Package Privileges with SQL

Using the SQL console, you can grant access to a package in the SAP HANA repository using the following SQL syntax:

```
GRANT <PACKAGE_PRIVILEGE> ON <"package.subpackage"> TO <GRANTEE> WITH GRANT OPTION;
```

The `<PACKAGE_PRIVILEGE>` variable can be replaced with a comma-separated array of package privileges. The `<"package.subpackage">` variable can be replaced by the case-sensitive name of the package and subpackage hierarchy. When constructing a complete package name, each node of the package hierarchy should be separated by a period. The `WITH GRANT OPTION` allows the grantee to grant the same privileges to other users. The `<GRANTEE>` can either be a role or a user account. For example, you can use the following SQL statement:

```
GRANT REPO.READ, REPO.EDIT_NATIVE_OBJECTS ON "e-corp" TO JONATHAN WITH GRANT OPTION;
```

To remove package privileges, use the `REVOKE` SQL statement. The following SQL statement will remove the privileges specified in the `<PACKAGE_PRIVILEGES>` variable array:

```
REVOKE <PACKAGE_PRIVILEGE> ON <"package.subpackage"> FROM <GRANTEE>;
```

The following statement is a more concrete example:

```
REVOKE REPO.EDIT_NATIVE_OBJECTS ON "e-corp" FROM JONATHAN;
```

### 9.3.2 Granting Package Privileges with the SAP HANA Cockpit

Let’s review the workflows necessary to grant and revoke package privileges with the SAP HANA cockpit. As an alternative to using SQL statements, you can use the SAP HANA cockpit options called Assign Privileges or Manage Roles. Each interface allows you to both grant and revoke package privileges for a given user account or for a given role. Most users will find using the SAP HANA cockpit easier than memorizing and entering in SQL statements.

To access the Assign Privileges or Manage Roles interfaces, start at the SAP HANA cockpit Home screen, locate an SAP HANA system in the Resource Directory. Connect to the desired tenant database or `SYSTEMDB`, which will take you to the System Overview window. Using the Filter by Area dropdown list, choose the option Security. Locate the Assign Privileges or Manage Roles in the User & Role Management tile.

[Section 9.3](#09_003.html#h9.3) shows the Assign Privileges interface within the SAP HANA cockpit for the `TEST_01` user account. In the windows, you’ll see several tabs representing privilege categories, such as the System Privileges, Object Privileges, Analytic Privileges, Application Privileges, Package Privileges, and Privileges on Users tabs. You’ll find a similar interface when working with roles. However, the Role Details GUI has an additional link labeled Roles where you can grant existing roles to the selected role.

[![Managing Package Privileges Assigned to a User Account in the SAP HANA Cockpit](bilderklein/klein09_003.png)](img-f9.3.html)

**Figure 9.3** Managing Package Privileges Assigned to a User Account in the SAP HANA Cockpit

The fifth tab in the Assign Privileges window is named Package Privileges. Use this tab to list, grant, or revoke package privileges for a given grantee. As shown in [Section 9.3](#09_003.html#h9.3), the packages and privileges listed in this interface have already been granted to the grantee. If the list is blank, nothing is currently granted. To grant a Package Privilege, click the Edit button located on the far-right side of the interface near the Search field. Once you click the Edit button, new buttons labeled Cancel, add Package, Change Privileges, and Remove Package will appear. Click the Add Package button to open the Select Packages popup window. Within this window, you’ll see a search bar and a list of existing packages within the repository. Use the search bar to filter the list based on the entered text. Then, scroll through the list and select the package you want to configure.

Click the desired package, and the Add Package with Privileges window will appear. In this window, you’ll see a list of possible package privileges that can be assigned. Select the checkbox beside each privilege you want to grant. In addition, for each privilege, you can use the Yes/No Grantable to Others slider to allow the privilege to be granted to other users. Click the OK button located at the bottom right of the interface to continue.

You should now see the selected packages and the privileges you assigned listed in the Package Privileges tab, as shown in [Section 9.3](#09_003.html#h9.3).

To revoke a package privilege, click an assigned package and its assigned privilege from the list and then click the Remove Package button to revoke the privilege. To make the changes active, click the Save button or continue making other changes if necessary. Note that, once the Save button is clicked, you’ll be returned to the list of privileges and be required to click the Edit button again to make further changes.

To change assigned package privileges, while in Edit mode, click an assigned object and its assigned privilege from the list and then click the Change Privileges button to open a new popup window with the title Change Privileges of concatenated with the name of the package. A list of assigned and unassigned privileges for the package will appear. Select the checkbox to grant the privilege or deselect the checkbox to revoke the privilege. Use the Yes/No Grantable to Others slider button to manage the grantable to others privilege. Click the OK button at the bottom right of the window to apply your changes. Again, to make these changes active, click the Save button or continue making other changes if necessary until you’re ready to activate all changes.

### 9.3.3 Granting Package Privileges with the SAP HANA Web-Based Development Workbench

The SAP HANA Web-Based Development Workbench security manager, hosted within the XS engine, provides an interface that you can use to create users, create roles, or manage security for standard roles. This interface provides another web-based alternative to the SAP HANA cockpit and also serves as an alternative to issuing `GRANT` and `REVOKE` statements with SQL.

You can access the SAP HANA Web-Based Development Workbench via a supported Internet browser. The following two URLs can be customized to match the details of your environment:

*   `http://sap-hana.myhost.com:8000/sap/hana/ide/security`
*   `http://<sap_hana_host>:80<instance_number>/sap/hana/ide/security`

In the last example, replace `<sap_hana_host>` with the host name of the SAP HANA system in your environment. Replace `<instance_number>` with the two-digit instance number corresponding to your SAP HANA system.

For secure access, the following examples should help you construct the correct URL:

*   `https://<sap_hana_host>:43<instance_number>/sap/hana/ide/security`
*   `https://sap-hana.myhost.com:4300/sap/hana/ide/security`
