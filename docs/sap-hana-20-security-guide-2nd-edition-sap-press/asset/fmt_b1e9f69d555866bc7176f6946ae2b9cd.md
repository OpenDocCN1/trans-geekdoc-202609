
Organizations must ensure the integrity of the data hosted within the SAP HANA system. When financial transactions are recorded, these records should be protected from unauthorized changes. Data integrity is protected by allowing only authorized individuals to make changes to the data and through auditing, encryption, and strong password authentication policies.

Organizations must also ensure the availability of the SAP HANA system. Security is an important component in maintaining a system’s availability. Both authorized and unauthorized users can lead to poor database availability. A security model can govern access among trusted users, those that have been explicitly granted privileges within the database. However, organizations must ensure that user access is limited to only their areas of responsibility. You must also ensure that users are well trained for their level of access. Unauthorized users are users outside your organization that are not explicitly granted privileges within the SAP HANA system. These users often gain access through unscrupulous or unauthorized means and intend to steal data or disrupt the operations of your database. The security model can both govern authorized access and prevent unauthorized access.

When collecting sensitive data from customers, organizations must protect that data. Organizations that fail to protect customer data often have their reputations tarnished. If customers can’t trust your organization with their sensitive data, they might choose to conduct business with your competitors. Your organization could also be subject to major fines if sensitive customer data isn’t secured.

Thus, your organization should prioritize, emphasize, and scrutinize its SAP HANA security models for several reasons. Throughout this book, we’ll teach you how to implement a security model, identify risky privileges, and follow best practices when possible.

# 1 Managing Security with the SAP HANA Cockpit

In this chapter, we’ll introduce you to the SAP HANA cockpit and many of the workflows necessary for managing security settings and security models.

Since its inception, most of the SAP HANA security model has been developed and maintained using SAP HANA Studio, a client tool installed on an SAP HANA developer or administrator workstation. However, in November 2016, SAP announced and released SAP HANA 2.0, including a new administration tool called the SAP HANA cockpit.

The SAP HANA cockpit provides monitoring, configuration, performance optimization, security, platform lifecycle management, and other administration capabilities. Unlike SAP HANA Studio, the SAP HANA cockpit does not provide application or content development tools. These tools have been migrated to SAP Web IDE for SAP HANA, another independent, web-based development tool in the SAP HANA 2.0 portfolio.

The SAP HANA cockpit is a standalone, web-based HTML5 application server, not a desktop-based client tool. It operates in SAP HANA extended application services, advanced model (SAP HANA XSA) and also requires an SAP HANA 2.0, express edition, database or an SAP HANA 2.0 tenant database to operate. The architecture of the SAP HANA cockpit is designed to centralize and simplify the management and administration of SAP HANA throughout an IT landscape. Given its importance in the realm of SAP HANA security, the goal of this chapter is to introduce you to the various security workflows and security options that you can manage in the SAP HANA cockpit. However, this chapter is not intended as a comprehensive guide to using the SAP HANA cockpit.

###### Other Web-Based Administration Tools

As of SAP HANA 2.0 SPS 04, some aspect of the security model can still be managed with the SAP HANA Web-Based Development Workbench. This tool is hosted in the legacy SAP HANA extended application services, classic model (SAP HANA XS) engine (XS engine).

References to the SAP HANA cockpit will be prominent throughout this book, so you’ll require a basic understanding of it and its security-related interfaces. ## 1.1 What Is the SAP HANA Cockpit?

In this section, we’ll provide an overview of the architecture of the SAP HANA cockpit, show you how to access it the first time, review the SAP HANA cockpit manager, and walk you through the steps required for registering SAP HANA databases within the SAP HANA cockpit.

### 1.1.1 SAP HANA Cockpit Architecture

Architecturally, the SAP HANA cockpit is an SAP HANA XSA multi-target application (MTA) that requires an SAP HANA database to operate. SAP provides several deployment options, as shown in [Figure 1.1](#01_001.html#f1.1).

As shown in [Figure 1.1](#01_001.html#f1.1), you can deploy the SAP HANA cockpit on a supported standalone server using SAP HANA, express edition. The SAP HANA cockpit can also be installed alongside your existing SAP HANA instance or within an existing instance by using separate tenant databases sharing the same instance. In all cases, the software must be deployed to a supported Linux operating system (OS). Be sure you size your hardware properly based on the deployment option you choose.

Both a standalone installation and an installation as a separate instance require the use of SAP HANA, express edition. Fortunately, the installation media for the SAP HANA cockpit includes every required component and deploys the entire architecture for you. The installation media can also deploy the SAP HANA cockpit to an existing SAP HANA database, SAP HANA XSA application, and a dedicated tenant if you choose that option.
