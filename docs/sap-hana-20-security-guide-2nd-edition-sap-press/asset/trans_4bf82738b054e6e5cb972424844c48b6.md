

# 15.2.3 在 SAP HANA Cockpit 中查看审计日志

定义审计规则时，其审计级别可分为 `Emergency`、`Critical`、`Alert`、`Warning` 或 `Info`。我们将在 [第 15.3.1 节](#15_003.html#h15.3.1) 中进一步讨论这些级别。但是，被分类为 `Emergency`、`Critical` 或 `Alert` 的事件可以定向到一个或多个目标。要配置这些备用目标位置，您需要配置 Configuration 选项卡中找到的选项。[图 15.2](#15_002.html#f15.2) 显示了这些选项，位于连接的系统数据库的 Overall Audit Trail Target 字段下方。

对于列出的每个警报级别，您可以使用提供的复选框定义一个或多个目标。如果您选择不定义此部分，警报将根据为每个审计策略配置的选项进行记录，或者将默认为 Overall Audit Trail Target 设置。

[![Audit Level Trail Targets Configured in Configuration Section](bilderklein/klein15_002.png)](img-f15.2.html)

**图 15.2** Configuration 部分中配置的审计级别跟踪目标

当您需要将重要事件记录到多个目标位置时，此选项特别有用。例如，某些组织可能希望将事件记录到审计表和 syslog，因为它们使用第三方软件来监控 Linux syslog。您可以为所有三个可能的目标位置配置警报、紧急和严重事件。例如，您可以将紧急警报配置为写入审计表、syslog 和操作系统上的 CSV 文件。

Audit Trail 选项卡将打开一个界面，您可以在其中查看针对 SAP HANA 审计选项 Database Table 记录的审计策略事件。界面列出了记录的事件，如 [图 15.3](#15_002.html#f15.3) 所示。本节不会列出记录到 CSV、syslog 或内核跟踪的审计事件。

[![使用 SAP HANA Cockpit 在审计表中查看审计事件](bilderklein/klein15_003.png)](img-f15.3.html)

**图 15.3** 使用 SAP HANA Cockpit 在审计表中查看审计事件

您还可以使用此界面来截断或删除记录的审计事件。如 [图 15.3](#15_002.html#f15.3) 右上角所示，您将看到一个名为 Delete Audit Events 的链接。单击此链接后，将出现 Delete Audit Events 窗口。要截断审计表，您有三个选项：使用 Older than 选项删除早于提供的 Days 字段中输入的天数的事件。使用 Before 选项删除在提供的字段中输入的日期之前记录的审计事件。使用 All Entries 选项删除所有审计事件历史记录。请注意，用户必须被授予 `AUDIT OPERATOR` 系统权限才能执行此操作。

指定所需选项后，按 Delete 按钮删除审计事件。使用 Cancel 按钮放弃您的更改。

现在我们已经回顾了在 SAP HANA Cockpit 中启用审计和定义审计目标所需的选项和工作流程，让我们简要回顾一下这些选项如何在 SAP HANA Web-Based Development Workbench 安全管理器中配置，该管理器托管在 SAP HANA 扩展应用程序服务经典模型引擎（XS 引擎）中。

# 15.2.4 使用 SAP HANA Web-Based Development Workbench 启用审计

托管在 XS 引擎中的 SAP HANA Web-Based Development Workbench 安全管理器提供了一个用于配置 SAP HANA 审计的界面。

您可以通过受支持的 Internet 浏览器访问 SAP HANA Web-Based Development Workbench。要使用此工具，用户至少必须拥有 `sap.hana.xs.ide.roles::SecurityAdmin` 角色。以下两个 URL 可以自定义以匹配您环境的详细信息：

*   `http://sap-hana.myhost.com:8000/sap/hana/ide/security`
*   `http://<sap_hana_host>:80<instance_number>/sap/hana/ide/security`

在最后一个示例中，将 `<sap_hana_host>` 替换为您环境中 SAP HANA 系统的主机名，并将 `<instance_number>` 替换为与您的 SAP HANA 系统对应的两位数实例号。

为了安全访问，以下示例应帮助您构建正确的 URL：

*   `https://<sap_hana_host>:43<instance_number>/sap/hana/ide/security`
*   `https://sap-hana.myhost.com:4300/sap/hana/ide/security`

一旦您可以访问 SAP HANA Web-Based Development Workbench 安全管理器，您将看到位于 GUI 功能区左上角的一系列按钮。描绘垂直密钥和服务器的图标打开安全控制台；单击此图标以打开右侧的 Security Console 选项卡。单击 Auditing 选项卡以显示审计配置选项。选项和界面与 SAP HANA Studio 中的选项几乎相同，只有少数例外。[图 15.4](#15_002.html#f15.4) 显示了安全控制台的示例，其中可见审计选项。

要启用审计，请使用 Auditing Status 下拉列表并选择 Enable。使用下拉列表指定 Audit Trail Target。根据我们使用 SAP HANA 1.0 SPS 12 和 SAP HANA 2.0 SPS 04 进行的测试，Audit Level Trail Target 设置在 SAP HANA Web-Based Development Workbench 中不起作用；这些设置将需要使用 SAP HANA Cockpit（[第 15.2.1 节](#15_002.html#h15.2.1)）进行维护。

SAP HANA Web-Based Development Workbench 与 SAP HANA Cockpit 有几个不同之处。首先，截断数据库表审计跟踪图标（粉色橡皮擦）位于 Audit Policy 设置下方的图标栏中。单击该图标以打开一个弹出窗口，您可以在其中指定审计事件截断的结束日期。另外，在此图标栏中，请注意日志截断按钮右侧的表格图标。单击时，表格图标将打开一个新窗口，启动 SAP HANA Web-Based Development Workbench 目录界面及其基于 Web 的 SQL 控制台。控制台将预填充一个查询审计日志表的 SQL 语句。请注意，尽管可用，但此选项在我们测试的 SAP HANA 2.0 SPS 04 中不起作用。在 [第 15.3.1 节](#15_003.html#h15.3.1) 中，我们还将讨论如何为审计策略单独配置特定的审计跟踪目标。例如，您可以指定特定的审计策略应将信息输出到 CSV 文件。

# 15.2.5 使用 SQL 启用审计

除了使用 GUI 之外，拥有 `INIFILE ADMIN` 系统权限的用户还可以使用 `ALTER SYSTEM ALTER CONFIGURATION` SQL 脚本来配置 SAP HANA 中的审计机制。如果您需要确保环境中所有 SAP HANA 系统使用相同的设置，使用脚本很有帮助。

要启用审计，您需要更新 `global.ini` 文件中启用审计配置（`global_auditing_state`）的设置。执行以下 SQL 代码将值设置为 true：

```
ALTER SYSTEM ALTER CONFIGURATION ('global.ini', 'SYSTEM') 
   SET ('auditing configuration', 'global_auditing_state') = 
'TRUE' WITH RECONFIGURE ;
```

要指定审计跟踪类型，您需要更新 `global.ini` 文件中指定审计跟踪类型（`default_audit_trail_type`）的设置。该设置名称有三个选项：`CSTABLE`、`SYSLOGPROTOCOL` 和 `CSVTEXTFILE`。要使用系统数据库表，执行以下 SQL 代码：

```
ALTER SYSTEM ALTER CONFIGURATION ('global.ini', 'SYSTEM') 
   SET ('auditing configuration', 'default_audit_trail_type') = 
'CSTABLE' WITH RECONFIGURE ;
```

要将事件写入 Linux syslog，请使用 `SYSLOGPROTOCOL` 选项，要使用 CSV 文件作为目标，请使用 `CSVTEXTFILE` 选项。
