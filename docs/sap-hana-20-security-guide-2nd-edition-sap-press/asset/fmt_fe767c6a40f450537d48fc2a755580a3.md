
# Kerberos 网络身份验证协议

Kerberos 是一种基于 MIT 早期网络计算工作的网络身份验证协议。该协议旨在作为一种强大的协议，防止多种形式的未经授权的访问。该协议使用强加密，使其难以被攻破。由于 MIT 公开发布了该协议的可用实现，并且因其强大性，Kerberos 多年来已集成到许多计算系统中。Kerberos 的一个关键集成是其包含在 Microsoft 的流行 Active Directory 解决方案中。因此，在几乎每个使用 Microsoft Windows 的商业环境中，当你登录桌面时，很可能正在使用一种 Kerberos 身份验证形式。

Kerberos 依赖于公钥/私钥加密原理来实现其强大的身份信息交换，并依赖于一个中央机构来管理凭据。这个中央系统称为密钥分发中心（KDC）。从高层次来看，受支持的客户端应用程序从 KDC 请求票据，然后将其发送到 SAP HANA 作为一种身份验证形式。[Figure 12.7](#12_003.html#f12.7) 显示了通过 SSO 促进身份验证的 Kerberos 票据交换过程的高级概述。在此示例中，你可以假设客户端是运行在用户桌面上的 SAP HANA Studio 应用程序。

你可以假设 [Figure 12.7](#12_003.html#f12.7) 中显示的客户端已经与支持 Kerberos 身份验证的主源进行了身份验证。当尝试访问 SAP HANA 资源时，客户端从 KDC 获取加密的 Kerberos 票据。然后，该票据被路由到客户端，使用客户端凭据解密，并连同其他信息一起发送到 SAP HANA 系统，用于身份验证。SAP HANA 系统接受票据并定位具有匹配 Kerberos 身份的 SAP HANA 用户。当客户端与 SAP HANA 系统交互时，分配给此 SAP HANA 用户帐户的所有有效权限都会得到验证。

在当今的大多数实现中，KDC 由 Microsoft Active Directory 服务提供。这种对外部中央机构的依赖可能使端到端 Kerberos 解决方案的配置变得有些繁琐。Kerberos 是在桌面软件时代开发的，因此它与 SAP HANA Studio 等桌面工具以及 ODBC 和 JDBC 等协议配合良好。但是，为基于 Java 的应用程序和基于 Web 的应用程序配置 Kerberos 可能会很困难。

你还可以通过几个将 Kerberos 集成到 Web 浏览器中的其他标准，使用 Kerberos 进行基于 Web 的 SSO。这些标准虽然最初由 Microsoft Internet Explorer 引入，但后来被大多数现代 Web 浏览器采用。XS 引擈及其基于 Web 的应用程序可以利用大多数现代浏览器中可用的 Simple and Protected GSSAPI Negotiation Mechanism (SPNEGO) 使用 Kerberos。例如，客户端可以登录到个人计算机，然后，当客户端访问受信任的 Web 应用程序时，浏览器将使用初始登录凭据，获取票据，并将凭据发送到 Web 应用程序进行身份验证。

你可以通过 SAP HANA 用户管理选项或通过 SQL 命令为用户配置 Kerberos 身份。例如，要在 SAP HANA cockpit 中为用户配置 Kerberos 身份，请打开用户管理界面，在列表中选择用户，并为给定用户选择 Edit 选项。在 SAP HANA cockpit 的用户管理选项卡中，单击 Authentication Mode 选项卡，如 [Figure 12.8](#12_003.html#f12.8) 所示，要启用 Kerberos SSO，请选择 Kerberos 复选框。然后，在 External ID 字段中提供外部 Kerberos 身份。此身份的格式应与外部用户 Kerberos 系统用户帐户的用户主体名称（UPN）属性匹配。此属性通常采用 [user@domain.com](mailto:user@domain.com) 格式，其中用户部分替换为外部系统的用户名，domain.com 替换为外部系统的域名。

你还可以使用 SQL 语句将 Kerberos 身份添加到用户，并为给定用户帐户启用 Kerberos 支持，如下所示：

```
ALTER USER <USER_NAME> ADD IDENTITY 'user@domain.com' FOR KERBEROS;
ALTER USER <USER_NAME> ENABLE KERBEROS;
```

`<USER_NAME>` 变量应替换为 SAP HANA 系统中现有用户帐户的名称。IDENTITY 语句后面的字符串值应与外部系统的 UPN 匹配；也就是说，`'user@domain.com'` 字符串值将包含特定于单个用户 UPN 属性的值，该属性在外部系统中。你现在应该对 Kerberos 在 SAP HANA 系统中的支持有基本了解。接下来，让我们看看如何以类似的方式利用 SAML 身份验证。

## 12.3.2 SAML Authentication

SAML 是一种来自名为 OASIS 的开源标准组织的身份验证标准。SAML 的一个关键优势是，身份验证和安全数据的传输通过简单的 XML 消息进行，这使得在应用程序中实现 SAML 支持非常简单。

SAML 与 Kerberos 有些不同，因为 SAML 具有更分散的架构。这种身份验证解决方案通常被称为联合身份系统。该解决方案被称为“联合”，是因为多个系统的松散耦合相互合作，通过交换身份验证和授权数据。与 Kerberos 中由单个集中式系统管理所有身份信息不同，SAML 可以支持多个身份提供者，这些提供者管理来自各方的用户身份验证。
