
E-Corporation requires that all unsuccessful actions be recorded to the audit logs. Users with a high number of unsuccessful actions within a given day are to be questioned immediately. A high number of unsuccessful actions often indicates that someone is trying to compromise the system’s security using their own account or someone else’s account.

## Solution

The security consultant recommends that an audit policy named `ALL FAILED ACTIONS` be created to record this activity to table `AUDIT_LOG` within SAP HANA. The policy will be configured to record all `UNSUCCESSFUL` actions performed within the system.

The policy will be defined using the SQL code shown in [Listing 15.6](#15_005.html#l15.6).

```sql
CREATE AUDIT POLICY "ALL FAILED ACTIONS" 
AUDITING UNSUCCESSFUL ACTIONS 
EXCEPT FOR 
_SYS_DI, _SYS_AFL, _SYS_XB, _SYS_WORKLOAD_REPLAY, 
_SYS_TASK, _SYS_STATISTICS, _SYS_SQL_ANALYZER, 
_SYS_REPO, _SYS_ES, _SYS_EPM, _SYS_DI_TO, _SYS_DI_SU, 
_SYS_DI_SEARCH_CATALOG, _SYS_DI_CDS_CATALOG, _SYS_DI_CATALOG, 
_SYS_DI_BI_CATALOG 
LEVEL INFO;
```

To activate the policy, the following SQL statement must be executed:

```sql
ALTER AUDIT POLICY "ALL FAILED ACTIONS" ENABLE;
```

## 15.5.5 System Change Auditing

### Requirements

E-Corporation requires that all system configuration changes be recorded to the audit logs. These events should also be set up using the `EMERGENCY` level so that they’re easily identified within the audit logs. In addition, these events should be written to a CSV file stored in a secure directory in the operating system.

### Solution

The security consultant recommends that an audit policy titled `ALTER SYSTEM` be created to record this activity to table `AUDIT_LOG` table and a CSV file within SAP HANA. The policy will be defined using the following SQL code:

```sql
CREATE AUDIT POLICY "ALTER SYSTEM" 
AUDITING ALL SYSTEM CONFIGURATION CHANGE 
LEVEL EMERGENCY
TRAIL TYPE CSV, TABLE;
```

Note that the SQL code uses a `LEVEL` of `EMERGENCY` and a `TRAIL TYPE` of both `CSV` and `TABLE`. To activate the policy, the following SQL statement must be executed:

```sql
ALTER AUDIT POLICY "ALTER SYSTEM" ENABLE;
```

Because the policy will record such events to a CSV file, the system needs to be configured with a new default audit trail CSV file path. A directory was created within the path `/usr/sap/HB5/HDB00/auditlog/`, which will store audit trail files containing system configuration changes. No other audit rules within the system will use the CSV file option. To configure the CSV file path within SAP HANA, the following SQL statement must be executed:

```sql
ALTER SYSTEM ALTER CONFIGURATION ('global.ini', 'SYSTEM') 
   SET ('auditing configuration', 'default_audit_trail_path') = 
'/usr/sap/HB5/HDB00/auditlog/' WITH RECONFIGURE ;
```

## 15.5.6 Security Management Task Auditing

### Requirements

E-Corporation requires that all security-related activities be recorded to the audit log, including the management of users, roles, and repository roles, as well as granting and revoking of privileges and roles to other users.

### Solution

The security consultant recommends that a series of audit policies be created to record this activity to table `AUDIT_LOG` within SAP HANA. The audit policies `MANAGE ROLE`, `MANAGE USER`, `GRANT OR REVOKE REPOSITORY OBJECTS`, `GRANT OR REVOKE PRIVILEGES`, `ANALYTIC PRIVILEGES`, and `ACTIVATE REPOSITORY OBJECTS` will be created.

The `MANAGE ROLE` policy will record all attempts to create, alter, or drop roles within the SAP HANA system. E-Corporation’s standard policy is to create repository-based roles, and such roles would not be covered using this policy. However, this policy will identify security administrators that are not following policy. In addition, their actions related to standard roles will be recorded. To create the policy, the following SQL code must be executed:

```sql
CREATE AUDIT POLICY "MANAGE ROLE" 
AUDITING ALL CREATE ROLE, ALTER ROLE, DROP ROLE
LEVEL INFO;
```

The `MANAGE USER` policy will record all attempts to create, alter, or drop users within the SAP HANA system. E-Corporation allows security administrators to create users within the system. To create the policy, the following SQL code must be executed:

```sql
CREATE AUDIT POLICY "MANAGE USER" 
AUDITING ALL CREATE USER, ALTER USER, DROP USER
LEVEL INFO;
```

The `GRANT OR REVOKE REPOSITORY OBJECTS` policy is designed to record the use of stored procedures within the `_SYS_REPO` schema. These procedures are used by security administrators and give them the ability to grant privileges to repository-based objects, including repository-based roles. These procedures should be closely monitored because repository object privileges are always granted by `_SYS_REPO` regardless of the user executing these procedures. To create the policy, the SQL code shown in [Listing 15.7](#15_005.html#l15.7) must be executed.

```sql
CREATE AUDIT POLICY "GRANT OR REVOKE REPOSITORY OBJECTS" 
AUDITING ALL 
EXECUTE ON 
"_SYS_REPO"."*"
LEVEL INFO;
```

Listing 15.7 SQL Code to Create Policy Named GRANT OR REVOKE REPOSITORY OBJECTS

The `GRANT OR REVOKE PRIVILEGES` policy will record all attempts to grant or revoke privileges within the SAP HANA system. E-Corporation’s standard policy is to create repository-based roles, and privileges within repository-based roles are granted or revoked by the system account `_SYS_REPO`. However, this policy will identify security administrators that are not following policy. In addition, their actions related to the granting and revoking of privileges will be recorded. To create the policy, the following SQL code must be executed:

```sql
CREATE AUDIT POLICY "GRANT OR REVOKE PRIVILEGES" 
AUDITING ALL GRANT ANY, REVOKE ANY 
LEVEL INFO;
```

The `ANALYTIC PRIVILEGES` policy will record any attempts to create, alter, or drop structured privileges within the SAP HANA system. Because these privileges provide data-level security, auditing these privileges is important. Note that classic repository-based analytic privileges will be created, altered, and dropped by the system account `_SYS_REPO`. To create the policy, the SQL code shown in [Listing 15.8](#15_005.html#l15.8) must be executed.

```sql
CREATE AUDIT POLICY "ANALYTIC PRIVILEGES" 
AUDITING ALL 
ALTER STRUCTURED PRIVILEGE, 
CREATE STRUCTURED PRIVILEGE, 
DROP STRUCTURED PRIVILEGE 
LEVEL INFO;
CREATE AUDIT POLICY "ACTIVATE REPOSITORY OBJECTS" 
AUDITING ALL ACTIVATE REPOSITORY CONTENT 
LEVEL INFO;
```

Listing 15.8 Two SQL Statements to Create ACTIVATE REPOSITORY OBJECTS and ANALYTIC PRIVILEGES Policies

The `ACTIVATE REPOSITORY OBJECTS` policy is required to capture the true source of changes related to repository roles and other repository-based objects. When a repository object is activated, many auditing events will record that the `_SYS_REPO` user performed a series of actions. To properly correlate those actions to an actual user, you must ensure that all repository activations are also audited. In this way, you can know the identity of the user that initiated the actions carried out by the `_SYS_REPO` user. To create the policy, the following SQL code must be executed:

```sql
CREATE AUDIT POLICY "ACTIVATE REPOSITORY OBJECTS" 
AUDITING ALL ACTIVATE REPOSITORY CONTENT 
LEVEL INFO;
```

Once created, the policies will need to be activated. To activate these policies, the SQL shown in [Listing 15.9](#15_005.html#l15.9) must be executed.

```sql
ALTER AUDIT POLICY "MANAGE ROLE" ENABLE;
ALTER AUDIT POLICY "ANALYTIC PRIVILEGES" ENABLE;
ALTER AUDIT POLICY "ACTIVATE REPOSITORY OBJECTS" ENABLE;
ALTER AUDIT POLICY "GRANT OR REVOKE PRIVILEGES" ENABLE;
ALTER AUDIT POLICY "MANAGE USER" ENABLE;
ALTER AUDIT POLICY "GRANT OR REVOKE REPOSITORY OBJECTS" ENABLE;
ALTER AUDIT POLICY "ACTIVATE REPOSITORY OBJECTS" ENABLE;
```
