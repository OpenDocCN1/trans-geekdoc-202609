
# After getting the technical name

After getting the technical name, make sure you’re in the SQL console connected as the HDI container admin before proceeding with the next steps. The first statement you’ll need to run sets the default schema used for your temporary tables:

```
SET SCHEMA "MYPROJ_HDI_DB_1#DI";
```

The second statement will create a local temporary column table in the schema. You’ll use this temporary table to store role grant information used as an input parameter in the stored procedure:

```
CREATE LOCAL TEMPORARY COLUMN TABLE #ROLES LIKE _SYS_DI.TT_SCHEMA_ROLES;
```

The third statement will insert the role name information and target user into the temporary table named `#ROLES`. To grant the role `MyProj.db.roles::TABLE_READ_ONLY_ACCESS` (input parameter 1) to the user `SYSTEM` (input parameter 3), you’ll need to adjust the following statement to match your use case:

```
INSERT INTO #ROLES ( ROLE_NAME, PRINCIPAL_SCHEMA_NAME, PRINCIPAL_NAME ) 
VALUES ( 'MyProj.db.roles::TABLE_READ_ONLY_ACCESS', '', 'SYSTEM' );
```

The fourth statement will call the stored procedure in the `MYPROJ_HDI_DB_1#DI` schema. When crafting this statement, make sure you update the schema name to match the name of the `#DI` schema supporting your HDI container:

```
CALL MYPROJ_HDI_DB_1#DI.GRANT_CONTAINER_SCHEMA_ROLES(#ROLES, _SYS_DI.T_NO_PARAMETERS, ?, ?, ?);
```

The output of this procedure will include multiple tabs of results. Look at the Results 1 tab to see a verbose message about the actions that were executed and to validate that the role was granted properly to the user.

Finally, you’ll drop the temporary table because it is no longer needed, as follows:

```
DROP TABLE #ROLES;
```

After running each of these statements correctly, your target user will be granted the HDI container role. Now let’s look at the second option in more detail.

## Granting HDI Roles with a Database User

As a second option, you can also use a standard SAP HANA database user to grant the statements outlined above and effectively grant an HDI container role to a database user. However, the standard user must first be set up with the same privileges that the HDI container admin possesses. Fortunately, the `_SYS_DI` schema provides a procedure that you can use to grant the correct privileges to another user.

By default, only the `SYSTEM` account has the access necessary to execute the procedures in the `_SYS_DI` schema. Therefore, you’ll need to start by connecting to the SQL console as the `SYSTEM` user.

The first statement you’ll need to execute will set the default schema used in the example. Run the following SQL statement:

```
SET SCHEMA SYSTEM;
```

Next, you’ll temporarily move your HDI container to the `_SYS_DI` container group. This step is required because the procedure in the `_SYS_DI` container is hard-coded to reference this group and will not work on HDI containers in other groups. When we’re done, you’ll move the HDI container back to its original group. Before you move the `MYPROJ_HDI_DB_1` HDI container, you’ll need to query the database to capture its current container group with the following statement:

```
SELECT * FROM "_SYS_DI".M_ALL_CONTAINERS WHERE CONTAINER_NAME like 'MYPROJ%';
```

Look for the value in the `CONTAINER_GROUP_NAME` column. In our example, our column was named `CG_SYS_XS_HANA_BROKER_2`. Again, we’ll move this container back to this group when we’re done granting the privileges.

Now, you can execute the SQL to temporarily move the HDI container into the required container group `_SYS_DI` with the following statement:

```
CALL _SYS_DI.MOVE_CONTAINER_TO_GROUP('MYPROJ_HDI_DB_1', '_SYS_DI', _SYS_DI.T_NO_PARAMETERS, ?, ?, ?);
```

Next, you’ll create a local temporary table in the `SYSTEM` schema named `#PRIVILEGES` with the following statement:

```
CREATE LOCAL TEMPORARY COLUMN TABLE #PRIVILEGES LIKE _SYS_DI.TT_API_PRIVILEGES;
```

Next, you’ll insert all the API privileges into the temporary table. This array is required as an input for the stored procedure. In the following script, replace the target user name `JHAUN` with your target user account name:

```
INSERT INTO #PRIVILEGES (PRINCIPAL_NAME, PRIVILEGE_NAME, OBJECT_NAME) SELECT 'JHAUN', PRIVILEGE_NAME, OBJECT_NAME FROM _SYS_DI.T_DEFAULT_CONTAINER_ADMIN_PRIVILEGES; 
```

Next, execute the stored procedure in the `_SYS_DI` schema that grants the array of privileges in the `#PRIVILEGES` temporary table. The name of the procedure is `GRANT_CONTAINER_API_PRIVILEGES_WITH_GRANT_OPTION`, which will grant all the API privileges to the user and include the `WITH GRANT OPTION` so that the user can selectively grant the same privileges to other users in the future. In your script, you’ll need to update the value for the first parameter to match the technical name of your HDI container, as follows:

```
CALL _SYS_DI.GRANT_CONTAINER_API_PRIVILEGES_WITH_GRANT_OPTION('MYPROJ_HDI_DB_1', #PRIVILEGES, _SYS_DI.T_NO_PARAMETERS, ?, ?, ?);
```

The results of this procedure include multiple output tabs. Review the first tab, which will contain a verbose information about each grant action.

Next, you’ll need to drop the temporary table `#PRIVILEGES`. Run the following SQL:

```
DROP TABLE #PRIVILEGES;
```

Finally, you’ll need to return our HDI container back to its original HDI container group. This step is critical and can’t be skipped.

```
CALL _SYS_DI.MOVE_CONTAINER_TO_GROUP('MYPROJ_HDI_DB_1', 'CG_SYS_XS_HANA_BROKER_2', _SYS_DI.T_NO_PARAMETERS, ?, ?, ?);
```

At this point, you can now log on to the SQL console as the target user and run the following statements. These examples are the same statements used in the previous section. Therefore, we’ll assume that you already understand each step and won’t go into detail about each step. Run the statements shown in [Listing 18.7](#18_004.html#l18.7), adjusting the syntax for your specific environment.

```
SET SCHEMA "MYPROJ_HDI_DB_1#DI";
CREATE LOCAL TEMPORARY COLUMN TABLE #ROLES LIKE _SYS_DI.TT_SCHEMA_ROLES;
INSERT INTO #ROLES ( ROLE_NAME, PRINCIPAL_SCHEMA_NAME, PRINCIPAL_NAME ) 
VALUES ( 'MyProj.db.roles::TABLE_READ_ONLY_ACCESS', '', 'SYSTEM' );
CALL MYPROJ_HDI_DB_1#DI.GRANT_CONTAINER_SCHEMA_ROLES(#ROLES, _SYS_DI.T_NO_PARAMETERS, ?, ?, ?);
DROP TABLE #ROLES; 
```

## 18.4.3 Granting the HDI Container Access to External Objects

When working within an HDI container using SAP Web IDE for SAP HANA, two security considerations must be addressed: First, developers might need access to runtime catalog objects that are outside of the HDI container as well as access to objects in other HDI containers. By default, developers will only have access to catalog objects within the HDI container or project workspace.
