### 9.3.4 Granting Package Privileges within Repository-Based Roles

In [Chapter 6](#06_001.html#h6), we discussed the importance of using repository-based roles as the foundation for your security model. We also thoroughly discussed the workflows for creating repository-based roles. For a complete review of repository roles, refer to [Chapter 6](#06_001.html#h6). In this section, we’ll provide a summary of the workflows used to grant or revoke package privileges within repository-based roles, either via design-time scripts or via the role management options in the SAP HANA Web-Based Development Workbench repository.

#### Granting and Revoking Privileges with Design-Time Scripts

When defining package privileges within repository-based role scripts, you must start the line with the term `package`, then include the name of the package hierarchy node. After the package name, include a single colon. After the colon, include a comma-separated list of package privileges. At the end of the statement, include a semicolon to finish the line.

The following example is a single line of code that grants multiple privileges to the `e-corp.sales` package:

```
Package e-corp.sales: REPO.READ, REPO.ACTIVATE_NATIVE_OBJECTS, REPO.MAINTAIN_NATIVE_PACKAGES, REPO.EDIT_IMPORTED_OBJECTS;
```

The following example is a single line of code that grants a single privilege to a single package:

```
Package e-corp.sales: REPO.READ;
```

To grant the root package privilege, use the system-defined package name value, `.REPO_PACKAGE_ROOT`, to represent privileges that will be applied to all packages, as in the following statement:

```
package .REPO_PACKAGE_ROOT: REPO.READ;
```

#### Using the SAP HANA Web-Based Development Workbench GUI

The SAP HANA Web-Based Development Workbench editor, hosted within the XS engine, provides an interface to manage and create repository roles. The interface looks a lot like the standard role management options in SAP HANA Studio, but the role objects it creates are profoundly different: The editor creates repository-based roles. The objects created in the editor also can be opened in the SAP HANA Studio developer perspective, which means that you can use either the SAP HANA Studio interface or the script editor to manage repository roles.

You can access SAP HANA Web-Based Development Workbench via a supported Internet browser. The following two URLs can be customized to match the details of your environment:

*   `http://sap-hana.myhost.com:8000/sap/hana/ide/editor`
*   `http://<sap_hana_host>:80<instance_number>/sap/hana/ide/editor`

In the last example, replace `<sap_hana_host>` with the host name of the SAP HANA system in your environment and `<instance_number>` with the two-digit instance number corresponding to your SAP HANA system.

For secure access, the following examples should help you construct the correct URL:

*   `https://<sap_hana_host>:43<instance_number>/sap/hana/ide/editor`
*   `https://sap-hana.myhost.com:4300/sap/hana/ide/editor`
