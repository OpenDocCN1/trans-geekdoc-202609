### 4.5.5 Creating Repository Stored Procedures

With the data imported into table `Security.Tables::adusers`, you’re now ready to develop a stored procedure to provision the user accounts listed in our table.

Note the following basic requirements for the stored procedure and for the process needed to create users programmatically at E-Corporation:

*   The procedure will create a user account with an account name based on the value in the `USER_NAME` column in the table.
*   The account password will need to be complex and randomly generated.
*   Users will never use the combination of the user name and password to manually authenticate with the SAP HANA system. Therefore, they will never need to know their passwords.
*   User accounts will be authenticated using a configured SAML provider and SAML identity.
*   The user account password will be set to never expire. However, an additional stored procedure will be created to randomly reset the user account password. The procedure will be executed every 90 days.
*   You’ll need to configure and enable SAML for each user account listed in the table.
*   You’ll need to add user email addresses to the user properties. This information helps administrators contact users and allows the system to send emails to individual users when applicable.

Based on these requirements, you’ll need to create two independent repository-based stored procedures. The first procedure will be named `CREATE_AD_USERS` and will provision users listed in the table, add SAML identities, enable SAML, and add email addresses.

To create the first repository-based stored procedure using the SAP HANA Web-Based Development Workbench editor, right-click the `Security.Provisioning` package and choose New • File. Name the file “`CREATE_AD_USERS.hdbprocedure`” and click Create. A new empty file table will appear, allowing you to define the stored procedure.

Define the `CREATE_AD_USERS` repository-based stored procedure using the syntax shown in [Listing 4.11](#04_005.html#l4.11). Activate the design-time script by clicking the save icon.

```
PROCEDURE "security_tables"."Security.Provisioning::CREATE_AD_USERS" () 
  LANGUAGE SQLSCRIPT
  /* Procedure invoker must have privileges to create users */
  SQL SECURITY INVOKER
  AS
   BEGIN
/*Use a Cursor for future use. The following only 
loops one time based on each record from SQL statement */

 DECLARE CURSOR c_users_list FOR
/* Get Active Users from table that are not currently 
provisioned in HANA */
/* We need to escape the single quote mark around 
SAMUSER and EMAILADDRESS with three single quote 
marks ''' a total of 4 are needed */

SELECT 
UT.AD_USER_NAME, 
upper(UT.USER_NAME) as HANAUSER, 
'''' || UT.AD_USER_NAME || '''' as SAMUSER, 
CAST(ROUND(RAND() * 100000000,0) as NVARCHAR(50)) as RAN_NUMBER,
'''' || UT.EMAIL_ADDRESS || '''' as EMAILADDRESS
FROM  "security_tables"."Security.Tables::adusers" UT
WHERE upper(UT.USER_NAME) NOT IN 
    (SELECT upper(USER_NAME) FROM "SYS"."USERS") 
    and UT.ACCOUNT_STATUS = 'A';

 FOR cur_row as c_users_list DO
    --- Create Users with generic complex random password
    EXEC 'CREATE USER ' || cur_row.HANAUSER 
        || ' PASSWORD "asdfSAD!' || cur_row.RAN_NUMBER || '"';
    --- Update user account so the password will not expire
    EXEC 'ALTER USER ' || cur_row.HANAUSER || ' DISABLE PASSWORD LIFETIME' ;
    --- Add SAML identity to user account
    EXEC 'ALTER USER ' || cur_row.HANAUSER || ' ADD IDENTITY ' 
        || cur_row.SAMUSER || ' FOR SAML PROVIDER TEST_SAML_PROVIDER';
    --- Enable SAML Authentication for the user account
    EXEC 'ALTER USER ' || cur_row.HANAUSER ||' ENABLE SAML';
    --- Add Email Addres to user account
    EXEC 'ALTER USER ' || cur_row.HANAUSER 
        || ' SET PARAMETER EMAIL ADDRESS = ' || cur_row.EMAILADDRESS ;    
   
 END FOR;

END;
```

**Listing 4.11** Syntax of Stored Procedure to Create Users

Repeat the process to create another stored procedure, `UPDATE_USER_PASSWORDS`. This procedure can be executed periodically to change all the passwords of the users listed in the table. The password will be different for each user because you’ll append a random number generator to the end of each password string, as shown in [Listing 4.12](#04_005.html#l4.12).

```
PROCEDURE "security_tables"."Security.Provisioning::UPDATE_USER_PASSWORDS" ( ) 
  LANGUAGE SQLSCRIPT

  SQL SECURITY INVOKER
  AS
   BEGIN
/*Use a Cursor for future use. The following only 
loops one time based on each record from SQL statement */

 DECLARE CURSOR c_users_list FOR
/* Get Active Users from table that are currently 
provisioned in HANA */
/* We need to escape the single quote mark around 
SAMUSER and EMAILADDRESS with three single quote 
marks ''' a total of 4 are needed */

SELECT 
UT.AD_USER_NAME, 
upper(UT.USER_NAME) as HANAUSER, 
'''' || UT.AD_USER_NAME || '''' as SAMUSER,

 END FOR;

END;
```

### 4.5.6 Executing the Repository Stored Procedure

To execute the stored procedure, open the SQL console. If your account has the `USER ADMIN` system privilege, you can execute the procedure to programmatically create or update users based on user records imported into the table from a CSV file. The syntax necessary to execute the two procedures is provided in the following two SQL statements:

```
CALL "security_tables"."Security.Provisioning::CREATE_AD_USERS"; CALL "security_tables"."Security.Provisioning::UPDATE_USER_PASSWORDS";
```

To validate that the users have been created, execute the SQL code shown in [Listing 4.13](#04_005.html#l4.13).

```
SELECT 
CASE WHEN U.USER_NAME is null 
    THEN 'Not Created' ELSE 'Created' 
    END as CREATION_STATUS,
UT.USER_NAME as REQUESTED_HANAUSER,
U.USER_NAME as PROVISIONED_HANAUSER

FROM  "security_tables"."Security.Tables::adusers" UT
LEFT OUTER JOIN "SYS"."USERS" U 
    on (upper(UT.USER_NAME) = upper(U.USER_NAME));
```

You’ll also see user accounts listed in the SAP HANA cockpit’s Manage Users area or in the SAP HANA Web-Based Development Workbench security manager.
