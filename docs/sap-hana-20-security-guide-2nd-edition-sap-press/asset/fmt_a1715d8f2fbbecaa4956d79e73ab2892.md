Enter the name of a user account into the User field. The field supports search ahead capabilities, meaning that the system will start displaying one or more user accounts that match the entered text as you start typing. Choose or enter the requested user to reveal a new GUI where you can assign individual privileges to the user account.

### 4.4.4 Effective Roles System View

Periodically, you’ll need to query the system to view the roles that have been granted to a specific user. This database view is included in the `SYS` schema and is called `EFFECTIVE_ROLES`. This view lists all the roles currently granted directly and indirectly to a specified user account. The view must be filtered to a single user account before it can execute. [Listing 4.8](#04_004.html#l4.8) shows an example of the SQL required to query this view.

```
SELECT
"USER_NAME", "GRANTEE", "GRANTEE_TYPE", "GRANTOR", "ROLE_NAME", "IS_GRANTABLE"
FROM "SYS"."EFFECTIVE_ROLES" 
WHERE ("USER_NAME" = '<USER_NAME>');
```

**Listing 4.8** SQL Code Executed against the `EFECTIVE_ROLES` View

The variable `<USER_NAME>` should be replaced with an active user account name. The view won’t execute unless the WHERE clause contains a filter on `USER_NAME` column. For a complete list of additional filters, refer to the SAP HANA Reference Guide available at [https://help.sap.com/hana/SAP_HANA_SQL_and_System_Views_Reference_en.pdf](https://help.sap.com/hana/SAP_HANA_SQL_and_System_Views_Reference_en.pdf).

In conclusion, the workflows and steps necessary to grant and revoke roles using the SAP HANA Web-Based Development Workbench security manager is quite similar to the processes used in the SAP HANA cockpit. One advantage of using the SAP HANA Web-Based Development Workbench is that administrators won’t need to install the SAP HANA cockpit to grant or revoke roles. ## 4.5 Case Study: Provisioning Users with SQL Scripts and Stored Procedures

Let’s say E-Corporation has designed a sales analytics data mart. The data mart is hosting data that must be restricted on a user-by-user basis. E-Corporation has already created SAP HANA information views, has set up analytic privileges to facilitate part of this requirement, and has configured SAML authentication within SAP HANA. However, for the solution to work on a user-by-user basis, each user accessing SAP HANA will need his own individual user account and SAML identity. In our example, E-Corporation will need to provision and configure over 5,000 individual user accounts to accommodate this requirement.

The administration team has determined that manually creating 5,000 user accounts isn’t feasible. Therefore, the team needs a solution to programmatically create these accounts and maintain their properties. They currently have a Lightweight Directory Access Protocol (LDAP)-based user directory system that contains all the user accounts that require access to the SAP HANA system. The LDAP system administrator extracted basic user account information from the LDAP system into a comma-separated values (CSV) flat file.

The SAP HANA administrator now has a list of 5,000 users and their basic attributes. He can use this list to programmatically provision and configure the accounts to support SAML authentication.
