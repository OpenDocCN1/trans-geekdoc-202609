
System privileges play an important role in the development of any SAP HANA security model. These privileges govern specific actions within the SAP HANA platform: in some cases, actions specific to administrators; in other cases, actions performed by developers. Throughout this chapter, we’ll explore the various system privileges that SAP HANA provides and the types of activities that they govern. We’ll also review the system privileges included with SAP HANA 2.0 and demonstrate how system privileges are granted using SQL, the SAP HANA cockpit, the SAP HANA Web-Based Development Workbench security manager, and within repository-based roles. We’ll close the chapter with a case study outlining several commonly used administrative roles and their required system privileges.

## 7.1 What Are System Privileges?

System privileges govern various activities or actions that can be executed within the SAP HANA platform. Administrators must be granted system privileges to perform activities such as backups, license key management, audit management, Secure Sockets Layer (SSL) management, system configuration settings, user creation, and role creation. Developers must be granted system privileges to perform imports and exports of catalog objects and repository objects. Several system privileges also govern access to actions performed within the SAP HANA development repository.

System privileges are predefined and delivered with the SAP HANA system. System privileges can’t be created or customized as of SAP HANA 2.0 SPS 00. To clarify the role that system privileges play in a security model, let’s review each default system privilege and categorize them.

## 7.2 Default System Privileges

SAP HANA is delivered with multiple system privileges. To better explain how system privileges might be used within a security model, we’ve organized them into five broad categories: developer, security admin, system admin, environment monitoring, and environment performance. We defined these categories based on our experience, but they don’t exist natively within SAP HANA. Placing system privileges into categories will hopefully help you understand how to use them with the repository roles you’ll devise to support your security model.

### 7.2.1 Developer-Related System Privileges

The following system privileges are typically required by developers. In general, these privileges only grant access to areas within SAP HANA related to the development of content. For example, a developer creating SAP HANA information views would likely need many of these system privileges in the development environment.

#### Create R Script

The create R script system privilege grants roles the ability to create a stored procedure using the R language.

#### `REPO.EXPORT`

The `REPO.EXPORT` system privilege governs access to interfaces for exporting a delivery unit from an SAP HANA system to a delivery unit export file. Delivery units are logical organizational units that contain one or more SAP HANA development artifacts. Typically, delivery units are exported and then imported into another SAP HANA system to transport code between systems.

#### `REPO.IMPORT`

The `REPO.IMPORT` system privilege governs access to interfaces for importing a delivery unit file into an SAP HANA system.

#### `REPO.MAINTAIN_DELIVERY_UNITS`

The `REPO.MAINTAIN_DELIVERY_UNITS` system privilege governs access to interfaces for defining a delivery unit within the SAP HANA repository.

#### `REPO.WORK_IN_FOREIGN_WORKSPACE`

The `REPO.WORK_IN_FOREIGN_WORKSPACE` system privilege grants a role the ability to take ownership of inactive development artifact versions hosted in another user’s workspace.

#### `REPO.CONFIGURE`

The `REPO.CONFIGURE` system privilege is used within SAP HANA application lifecycle management. Specifically, this system privilege allows the grantee to configure change recording when enabled.

#### `REPO.MODIFY_CHANGE`

The `REPO.MODIFY_CHANGE` system privilege is used within SAP HANA application lifecycle management. Specifically, this system privilege allows the grantee to assign objects to a change list when change recording is enabled.

#### `REPO.MODIFY_OWN_CONTRIBUTION`

The `REPO.MODIFY_OWN_CONTRIBUTION` system privilege is used within SAP HANA application lifecycle management. Specifically, this system privilege allows the grantee to assign objects to a change list when change recording is enabled.

#### `REPO.MODIFY_FOREIGN_CONTRIBUTION`

The `REPO.MODIFY_FOREIGN_CONTRIBUTION` system privilege is used within SAP HANA application lifecycle management. Specifically, this system privilege allows the grantee to modify objects to a change list when change recording is enabled. The grantee can perform the action even if it doesn’t own the change list assignment.

### 7.2.2 Security Admin-Related System Privileges

Security administrators typically require the following system privileges. In general, these privileges grant access to actions within SAP HANA related to the management and maintenance of users, roles, auditing, and encryption.

#### Audit Admin

The `AUDIT ADMIN` system privilege governs the execution of auditing-related SQL commands and actions performed using the various options within SAP HANA Studio or the SAP HANA cockpit. SQL commands such as `CREATE AUDIT POLICY`, `DROP AUDIT POLICY`, `ALTER AUDIT POLICY`, and `SELECT * FROM SYS.AUDIT_LOG` can’t be executed unless a user inherently has the `AUDIT ADMIN` system privilege. This rule also applies to graphical user interfaces (GUIs) because they execute the same SQL commands in the background when a user attempts to make changes to the various activities being audited.

#### Audit Operator

The `AUDIT OPERATOR` system privilege governs access to commands that can clear the audit logs when auditing is enabled. For example, with this privilege, the SQL command `ALTER SYSTEM CLEAR AUDIT LOG ALL` can be executed. This rule also applies to similar GUI options that allow the audit log to be cleared. Note that the act of clearing the audit log is always recorded to the audit log, a MandatoryAuditPolicy within the SAP HANA system. In other words, this audit policy is always active and can’t be circumvented. This system privilege also provides read access to the system audit log and the execution of `SELECT * FROM SYS.AUDIT_LOG` SQL statement.

#### Certificate Admin

The `CERTIFICATE ADMIN` system privilege governs access to SQL commands and GUIs for managing certificates within the SAP HANA in-database certificate store. This privilege provides data access when executing `SELECT * FROM SYS.CERTIFICATES` or `SELECT * FROM SYS.PSE_CERTIFICATES` and allows for the execution of `CREATE CERTIFICATE`, `DROP CERTIFICATE`, and other related in-database certificate management commands.

#### Create Structured Privilege

The `CREATE STRUCTURED PRIVILEGE` system privilege grants access to the execution of the SQL command `CREATE STRUCTURED PRIVILEGE`. Structured privileges can be implemented to restrict data-level access to catalog views and column views.

Note that this system privilege is included in the `MODELING` and `CONTENT_ADMIN` default roles. You might conclude that this privilege is required for all roles or users creating SAP HANA analytic privileges, a type of structured privilege. However, custom roles don’t need this privilege to activate analytic privileges created using SAP HANA Studio or SAP Web IDE for SAP HANA. The activation of SAP HANA analytic privileges is controlled using package privileges, and the navigation of the package hierarchy is controlled using the `SYS.REPOSITORY_REST` stored procedure. The runtime object type of an SAP HANA analytic privilege artifacts is a special type of structured privilege but created by the system account `_SYS_REPO`. Therefore, only the `_SYS_REPO` system account requires the `CREATE STRUCTURED PRIVILEGE` system privilege.
