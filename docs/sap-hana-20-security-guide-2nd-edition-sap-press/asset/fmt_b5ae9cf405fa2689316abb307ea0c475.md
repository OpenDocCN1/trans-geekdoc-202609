Now, let’s look at the various roles that can be granted to users. Note that roles are not cumulative, meaning that one role does not build upon another. Instead, each role is explicit, and each role only provides access to one area directly. Users will need all roles granted to have full access to the SAP HANA cockpit and SAP HANA cockpit manager.

The following list outlines each role and provides additional information about the permissions each role grants a user:

*   `Cockpit Administrator Role`

    This role only provides administration access to SAP HANA cockpit settings. This role is not a master role and only provides access to change settings; no other access is included.

*   `Cockpit Resource Administrator Role`

    This role will grant a user access to register SAP HANA databases, create resource groups, and manage resource group assignments. Users with this role will have access to all registered resources regardless of their assigned SAP HANA cockpit group.

*   `Cockpit User Administrator Role`

    This role will grant a user the ability to create and manage other users in the SAP HANA cockpit manager and the underlying SAP HANA cockpit database. At the database level, this role grants the `ROLE ADMIN` and `USER ADMIN` system privileges. At the SAP HANA cockpit manager application level, this role grants similar access.

*   `Cockpit User Role`

    This standard role is required for a user to access the SAP HANA cockpit. A user must have this role to access the SAP HANA cockpit homepage. Two additional options for this role will grant a standard SAP HANA cockpit user limited but additional privileges. Let’s look at these options in more detail:

    *   `Register resources through the Cockpit Manager`

        This subrole option grants the user limited access to the SAP HANA cockpit manager to create and register SAP HANA server resources. Resources will be created without groups, and access is limited only to members of the `Cockpit Resource Administrator` role and to itself.

    *   `System configuration template administrator role`

        This subrole allows the user access to the SAP HANA cockpit Configuration Templates tile. Configuration templates contain SAP HANA database `.ini` file settings and can be stored and applied to SAP HANA databases.

*   `Cockpit Troubleshooting Role`

    This role grants a user access to view the SAP HANA XSA logs area of the SAP HANA cockpit manager. Users must be an SAP HANA XSA organization manager to use this functionality. You can grant this access to the SAP HANA cockpit admin using the SAP HANA XSA cockpit graphical user interface (`GUI`) or using the SAP HANA XSA command line by running the following command: `xs set-org-role COCKPIT_ADMIN HANACockpit OrgManager`.

In the next section, we’ll explore SAP HANA cockpit groups in more detail and show you how to create groups in the SAP HANA cockpit manager.

### Creating SAP HANA Cockpit Resource Groups

SAP HANA cockpit uses resource groups to organize and secure registered SAP HANA databases. SAP HANA cockpit users can be assigned to one or more groups. For standard SAP HANA cockpit users, you can use groups to limit the registered systems they see in the SAP HANA cockpit. However, if users are granted the `Administrators` or `Resource Administrators` role, they will see all resource groups regardless of their assigned groups.

Resource groups are created using the SAP HANA cockpit manager. From the SAP HANA cockpit manager homepage, click the `Resource Groups` menu option to access the resource group management interface. The interface is organized into two panes. On the left is a list of existing resource groups within the `Resource Groups` pane. On the right is the `Resource Group Details` pane, as shown in [Figure 1.6](#01_001.html#f1.6). When you click on a resource group on the left, its registered resources or SAP HANA databases will appear on the right.

[![SAP HANA Cockpit Manager Resource Group Management Interface](bilderklein/klein01_006.png)](img-f1.6.html)

**Figure 1.6** SAP HANA Cockpit Manager Resource Group Management Interface

To create a group, locate the `Create Group` button at the bottom of the resource group list. Click the button to launch the three-step `Create Group` wizard. In the first step, `1. General information`, enter the resource `Group name` and `Description` in the provided fields. Click the `Step 2` button to continue. In the second step, `2. Resource`, assign existing registered SAP HANA systems to the group. Click the `Step 3` button to continue. In the third step, `3. Cockpit Users`, assign one or more user to the group. Click the `Create Group` button to finish the wizard.

You can alter an existing group by selecting a group on the right side of the SAP HANA cockpit manager, toggling between the `Resource` and `Cockpit Users` tabs found above the resource or users listed in the left in the `Resource Group Details` pane. You can also use this interface to delete or remove registered resource or users from the resource groups.

Users assigned to a group will now see the corresponding registered resource when they log on to the SAP HANA cockpit. In the next section, we’ll explore the purpose of registered resources and how you’ll use the SAP HANA cockpit manager to register them.

### Registering SAP HANA Databases and Tenants

Before you can interact with an SAP HANA system, you must first add or configure a connection to the SAP HANA system and store this connection within the SAP HANA cockpit.

To register resources or SAP HANA databases, click the `Registered Resources` button located on the SAP HANA cockpit manager homepage to access the registered resources management interface. This interface is organized into two panes. On the left is a list of existing registered resources or SAP HANA servers within the `Registered Resources` pane. On the right is the `Resource Details` pane, as shown in [Figure 1.7](#01_001.html#f1.7). When you click on a resource group on the left, details about the registered resources or SAP HANA databases will appear on the right.
