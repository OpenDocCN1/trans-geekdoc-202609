
The script acts as a catalog. For each authorization, you’ll add a line that includes the authorization name and description. Subsidiary application privilege objects will look for a corresponding entry in the file and won’t be activated unless a corresponding entry is found.

The second file has an extension of `.xsaccess` and also has no file name specified. This file, called the application-access file, defines the level of access that will be granted to application code hosted in the corresponding subpackage. Each application-access file must be stored in the subpackage corresponding to the application code it governs. The application code will take precedence over application-access files hosted in the same subpackage or closest parent package. The script shown in [Listing 11.2](#11_002.html#l11.2) illustrates how application privileges can be associated with application code hosted in the subpackage `e-corp.apps.survey.results`.

```
{
    "prevent_xsrf": true, // Prevent cross-site request forgery
    "exposed": true,      // Expose data via HTTP
    "authentication": {
        "method": "Form"
    },
    "force_ssl": true,    // Accept only HTTPS requests
    "authorization": [
       "e-corp.apps.survey::QView",
       " e-corp.apps.survey::QEdit",
       " e-corp.apps.survey::QAdmin"
     ]
}
```

**Listing 11.2** Script to Associate Application Privileges with Custom Application Code

The script language includes a variety of keywords that enable or disable various levels of access to the package and its corresponding application code. The specified application privileges listed in brackets next to the keyword `authorization` represent the application privileges that will be applied to the subpackage node and its code. Similar `.xsaccess` files are then added to other subpackages to define a complete application specific security model.

Once defined, application privileges must be granted to roles, and those roles must then be granted to users. In most cases, repository-based roles are created specifically for access to an application. These roles are then extended or granted to other security model-specific repository-based roles.

## 11.3 Granting Application Privileges

In this section, we’ll review the various options available to grant application privileges to and revoke them from grantees: SQL commands, the SAP HANA cockpit, the SAP HANA Web-Based Development Workbench security manager, and repository-based role scripts or a repository-based role editor graphical user interface (GUI).

### 11.3.1 Granting Application Privileges with SQL

When you create an application privilege, that privilege is owned by the system user `_SYS_REPO`. To grant or revoke application privileges, you must use a specific stored procedure. The SQL statements shown in [Listing 11.3](#11_003.html#l11.3) provide a generic example of how to use a stored procedure to grant an application privilege to a grantee. Grantees can be either user accounts or existing roles.

```
CALL "_SYS_REPO"."GRANT_APPLICATION_PRIVILEGE"
('<APPLICATION_PRIVILEGE_NAME>','<GRANTEE>');
CALL "_SYS_REPO"."GRANT_APPLICATION_PRIVILEGE"
('"sap.hana.admin::Administrator"','Security.roles::ADMIN_ROLE');
```

**Listing 11.3** SQL Syntax to Grant Application Privileges

[Listing 11.4](#11_003.html#l11.4) provides the syntax used to revoke an application privilege.

```
CALL "_SYS_REPO"."REVOKE_APPLICATION_PRIVILEGE"
('<APPLICATION_PRIVILEGE_NAME>','<GRANTEE>');
CALL "_SYS_REPO"."REVOKE_APPLICATION_PRIVILEGE"('"sap.hana.admin::Administrator"','ADMIN_ROLE');
```

### 11.3.2 Granting Application Privileges with the SAP HANA Cockpit

Let’s review the workflows necessary for granting and revoking application privileges with the SAP HANA cockpit. As an alternative to using SQL statements, you can use the SAP HANA cockpit GUI action called Assign Privileges or Manage Roles. Each interface allows you to both grant and revoke application privileges for a given user account or for a given role. Most users will find using the SAP HANA cockpit easier than memorizing and entering in SQL statements.

To access the Assign Privileges or Manage Roles area, start at the SAP HANA cockpit Home screen, locate an SAP HANA system in the Resource Directory. Connect to the desired tenant database or `SYSTEMDB`, which will take you to the System Overview window. Using the Filter by Area dropdown list, choose the option Security. Locate the Assign Privileges or Manage Roles in the User & Role Management tile.

[Section 11.1](#11_001.html#h11.1) shows the Assign Privileges interface within the SAP HANA cockpit Role Details for the `TEST_ROLE` grantee. In the window, you’ll see several tabs for the various privilege categories starting with the System Privileges, Object Privileges, Analytic Privileges, Application Privileges, Package Privileges, and Privileges on Users tabs. You’ll find a similar interface when working with user accounts. However, the Role Details GUI has an additional link called Roles where you can grant existing roles to the selected role.

[![Managing Privileges Assigned to Standard Roles in the SAP HANA Cockpit](bilderklein/klein11_001.png)](img-f11.1.html)

**Figure 11.1** Managing Privileges Assigned to Standard Roles in the SAP HANA Cockpit

The third tab in the Role Details window is named Application Privileges. Use this tab to list, grant, or revoke application privileges for a given grantee.

Privileges listed in this interface are have already been granted to the user or role. If the list is blank, nothing is currently granted. To grant an application privilege, click the Edit button located on the far-right side of the interface near the Search field. Once you click the Edit button, new buttons labeled Save, Cancel, Add, and Remove will appear. Click the Add button to open the Select application Privileges popup window. Within this window, you’ll see a search bar and a list of application privileges with check boxes to their left. Use the search bar to filter the list based on the entered text. Then, scroll through the list and select the checkbox beside the application privilege you want to grant. With one or more application privileges selected, click the OK button to add the desired items to the user. Your selected application privileges should now appear in the Application Privileges section.

To revoke an application privilege, start by clicking the Edit button again, then select the checkbox beside each system privilege in the list, and click the Remove button to revoke the privileges. Repeat the process for each application privilege you want to revoke. Once you’ve removed all the desired application privileges, click the Save button. The removed privileges will be revoked, and the grantee will be updated.

During the process of adding or removing privileges, click the Cancel button to discard any unsaved changes. Clicking the Cancel button will deactivate the Add, Cancel, and Remove buttons and return you to a read-only list of currently granted application privileges.
