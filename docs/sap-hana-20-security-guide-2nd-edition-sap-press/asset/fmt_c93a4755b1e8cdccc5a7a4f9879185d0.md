To view a complete list of roles that have been directly and indirectly granted to a given user, the `EFFECTIVE_ROLES` view can be used.
```
SELECT * FROM "SYS"."EFFECTIVE_ROLES" 
WHERE USER_NAME = '<USER_NAME>';
```

## 16.3 Case Study: Identifying Deficiencies in Information View Access

E-Corporation has developed numerous information views within its SAP HANA environment. E-Corporation also has several users complaining that they can’t query the views. The E-Corporation security team members believe that they’ve set up the privileges properly but cannot determine why users can’t access information views. To help E-Corporation identify the missing privileges, the company has contracted a security consultant.

E-Corporation has provided the following information to the security consultant to help him properly identify the problem with the missing privileges:

*   `HAUNJON` is the name of one of the user accounts experiencing the access issue.
*   The name of the information view is `ecorp.sales.view/CV_SALES`.

In the following sections, we’ll walk through the steps the security consultant will take to identify the issue.

### 16.3.1 Troubleshooting the Problem

To start the troubleshooting process, the security consultant has requested that E-Corporation execute the SQL statements shown in [Listing 16.5](#16_003.html#l16.5) and [Listing 16.6](#16_003.html#l16.6) to help identify why the user can’t query the information view.

```
SELECT * 
FROM "SYS"."EFFECTIVE_PRIVILEGES" 
WHERE 
USER_NAME = 'HAUNJON' 
AND SCHEMA_NAME = '_SYS_BIC'
AND PRIVILEGE = 'SELECT'
AND IS_VALID = 'TRUE'
AND (OBJECT_NAME IS NULL OR OBJECT_NAME = 'ecorp.sales.view/CV_SALES');
```

**Listing 16.5 SQL Code for Querying EFFECTIVE_PRIVILEGES System View**

The code shown in [Listing 16.5](#16_003.html#l16.5) will validate that the user has SELECT privileges on the `_SYS_BIC` schema. Information views are published as column views into the `_SYS_BIC` schema, so users must have the SELECT privilege on the schema or on the column views containing the `ecorp.sales.view/CV_SALES` prefix. If the user has access to the schema or to the individual column view, records will appear when the view is queried.

```
SELECT * 
FROM "SYS"."EFFECTIVE_STRUCTURED_PRIVILEGES"
WHERE ROOT_SCHEMA_NAME = '_SYS_BIC' 
AND ROOT_OBJECT_NAME = 'ecorp.sales.view/CV_SALES'
AND USER_NAME = 'HAUNJON';
```

**Listing 16.6 Example SQL for Querying the EFFECTIVE-STRUCTURED_PRIVILEGES System View**

The code shown in [Listing 16.6](#16_003.html#l16.6) will validate that the user has the appropriate analytic privileges for the information view. In addition to requiring the SELECT object privilege on the `_SYS_BIC` schema, the user must also have an analytic privilege. In the SQL output, the `STRUCTURED_PRIVILEGES_STATUS` column will indicate the status as either NOT AUTHORIZED or APPLIED. When the status is APPLIED, you can assume that the user has an analytic privilege.

### 16.3.2 Reviewing the Results

E-Corporation’s SAP HANA security administrators executed the two SQL statements. When executing the first statement, written against the `EFFECTIVE_PRIVILEGES` view, several records were returned. Based on the results, the user does have SELECT privileges on the `_SYS_BIC` schema and should be able to query the information view. However, the results of the second SQL statement, written against the `EFFECTIVE_STRUCTURED_PRIVILEGES` view, indicated that the user wasn’t authorized to access the view.

### 16.3.3 Reviewing the Solution

After the security consultant reviewed the results, he provided a solution. Because the `EFFECTIVE_STRUCTURED_PRIVILEGES` view indicated that the user account wasn’t authorized, the user doesn’t have the required analytic privileges. The consultant recommended that E-Corporation grant the required analytic privileges to a role that’s also granted to the user.

When the E-Corporation security team members received the recommendation from the security consultant, they didn’t initially agree with the recommendations. The security team was under the impression that users only need analytic privileges when the data requires row-level restrictions. The security consultant explained that all users must have an analytic privilege that references the information view they need, even if they don’t require restrictions. SAP HANA requires that each user have both an object privilege and analytic privilege when querying an information view.

The E-Corporation security team now understands the issue. To resolve the issue, the team members created a new analytic privilege that references the information view. After granting this analytic privilege to one of the user’s roles, the user successfully queried the information view.

## 16.4 Summary

Using a user-specific trace to record authorization debug information is an excellent way to determine the permissions that a user is lacking when attempting to perform an action that isn’t authorized. In addition to security tracing, security administrators can also use several security-related views within the `SYS` schema to list the explicit and effective security for a given user, role, or grantee.

## 17.1 Password Authentication Settings

SAP HANA provides an internal user and password authentication mechanism. Any user with an enabled password should comply with industry and organizational password standards, so now, let’s review recommendations related to standard user password policies and service accounts.

### 17.1.1 Standard User Password Policies

Standard users are users related to actual people that log on to the SAP HANA system using an SAP HANA-managed user name and password. Out of the box, SAP password authentication requires only a single token for authentication: That token comes in the form of a password. Therefore, security administrators must implement measures to strengthen the passwords used by users.
