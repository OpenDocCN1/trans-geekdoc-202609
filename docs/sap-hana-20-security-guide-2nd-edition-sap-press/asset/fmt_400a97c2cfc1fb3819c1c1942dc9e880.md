
# CREDENTIAL ADMIN

The `CREDENTIAL ADMIN` system privilege governs access to the `CREATE CREDENTIAL`, `ALTER CREDENTIAL`, and `DROP CREDENTIAL` SQL commands. Credentials are objects that store authentication information for remote sources used by SAP HANA smart data access and SAP HANA smart data integration.

# ENCRYPTION ROOT KEY ADMIN

The `ENCRYPTION ROOT KEY ADMIN` system privilege grants access to all SQL commands related to the management of root keys used to encrypt data, logs, and applications. SQL commands such as `ALTER SYSTEM APPLICATION ENCRYPTION`, `ALTER SYSTEM PERSISTENCE ENCRYPTION`, and `ALTER SYSTEM LOG ENCRYPTION`, which are governed by this system privilege. In addition to specific SQL commands, this privilege also grants access to any SAP HANA-related GUI that issues the same statements on behalf of a user.

# LDAP ADMIN

The `LDAP ADMIN` system privilege governs the use of SQL statements that manage an SAP HANA Lightweight Directory Access Protocol (LDAP) provider, such as `CREATE`, `ALTER`, `DROP`, and `VALIDATE LDAP PROVIDER`.

# ROLE ADMIN

The `ROLE ADMIN` system privilege governs access to GUI interfaces and SQL commands that `CREATE`, `ALTER`, or `DROP` standard roles within the system. This privilege also governs interfaces and SQL statements that `GRANT` or `REVOKE` roles. The `ROLE ADMIN` system privilege is only applicable to standard catalog roles and doesn’t grant the same privileges to repository-based roles.

Although commonly granted to security administrators, this privilege isn’t necessarily required when repository-based roles are the basis of your security model. Repository roles are granted using special stored procedures, and security administrators only need `EXECUTE` access for those procedures.

# SSL ADMIN

The `SSL ADMIN` system privilege governs access to SQL commands that establish the purpose of an SSL certificate, such as `SET <STORE_NAME> PURPOSE SSL`. This privilege also grants data access to the `SYS.PSES` personal security environment (PSE) system view.

# STRUCTUREDPRIVILEGE ADMIN

The `STRUCTUREDPRIVILEGE ADMIN` system privilege grants the grantee the ability to `CREATE`, `ALTER`, and `DROP` any structured privileges defined in the system. Roles with this privilege don’t need to be the owner of the structured privilege to perform the `DROP` or `ALTER` actions.

# TRUST ADMIN

The `TRUST ADMIN` system privilege governs access to GUIs and commands that manage SSL certificates within the trust store or certificate store. This privilege grants access to the `CREATE PSE` SQL command used to create a certificate store for in-database certificate management.

# USER ADMIN

The `USER ADMIN` system privilege governs access to GUIs and SQL statements used to `CREATE`, `ALTER`, and `DELETE` user accounts within the SAP HANA system.

# 7.2.3 System Admin-Related System Privileges

System administrators typically require many of the following privileges. Some of these privileges might seem related to other areas, which might be true in some cases. However, these privileges typically grant the ability to perform actions that have a profound impact on the stability and reliability of the SAP HANA system. Because these privileges deserve a higher level of scrutiny, we recommend limiting these privileges to only high-level system administrators. Also, system auditing and other critical rules must be enabled before these privileges are granted to administrators.

# ADAPTER ADMIN

The `ADAPTER ADMIN` system privilege should be assigned to roles that manage the SAP HANA smart data integration adapter framework. This privilege must be granted to roles that will be responsible for issuing SQL statements such as `CREATE ADAPTER`, `DROP ADAPTER`, and `ALTER ADAPTER`. This privilege also provides data access to system views such as `SYS.ADAPTERS`, `SYS.ADAPTER_CAPABILITIES`, and `SYS.ADAPTER_LOCATION`.

# AGENT ADMIN

The `BACKUP ADMIN` system privilege should be assigned to roles that manage the SAP HANA smart data integration data provisioning agent framework. This privilege must be granted to roles that will be responsible for issuing SQL statements such as `CREATE AGENT`, `DROP AGENT`, and `ALTER AGENT`. This privilege also provides data access to system views such as `SYS.AGENTS`, `SYS.AGENT_CONFIGURATION`, and `SYS.AGENT_GROUPS`.

# BACKUP ADMIN

The `BACKUP ADMIN` system privilege governs access to commands and GUIs that initiate backup and restoration activities related to the SAP HANA system. This privilege grants the ability to alter system configuration parameters related to the backup and recovery of the system and allows for the truncation of the backup catalog and its associated files. This privilege also grants access to query backup-related system views in the `SYS` schema, such as with `SELECT * FROM SYS.M_BACKUP_CATALOG`.

On its own, this privilege doesn’t provide access to the backup console in SAP HANA Studio or interfaces within the SAP HANA cockpit. During our testing, we identified that the `CATALOG READ` system privilege was also required to use the backup console. However, with both privileges granted, such roles would be able to fully manage the backup and restore processes within SAP HANA.

# BACKUP OPERATOR

The `BACKUP OPERATOR` system privilege governs access to SQL commands that initiate system backups or that provide read access to backup-specific system views. However, this privilege doesn’t provide the ability to change backup settings, restore the system, or execute commands that manage the backup catalog. This privilege is most often granted to service accounts that initiate a system backup from the command line, for example, SAP HANA accounts that initiate scheduled backup jobs from a Linux cron scheduling engine.

# CREATE REMOTE SOURCE

The `CREATE REMOTE SOURCE` system privilege governs access to SQL commands and GUIs used to create remote sources used by SAP HANA smart data access or SAP HANA smart data integration. This privilege also provides read-only data access to system views such as `SYS.REMOTE_SOURCES` and `SYS.REMOTE_SOURCE_OBJECTS`.

# CREATE SCENARIO

The `CREATE SCENARIO` system privilege governs access to the execution of the `CREATE CALCULATION SCENARIO` SQL statement. Calculation scenarios are specialized catalog objects used by SAP HANA calculation views. SAP hasn’t published significant information about calculation scenarios, but we do know that they are fundamental to the creation of SAP HANA calculation views. The `_SYS_REPO` system account normally creates calculation scenarios in the `_SYS_BIC` schema on behalf of a developer activating a calculation view, so most roles don’t necessarily need this privilege.

However, if an application or highly skilled user is creating calculation views and storing calculation scenarios in a custom schema, this system privilege will be required. For example, the SAP Business Warehouse (SAP BW) service account creates calculation scenarios and column views within the SAP HANA service account schema. Therefore, the SAP BW service account requires this privilege.

Note that this system privilege is included in the `MODELING` and `CONTENT_ADMIN` default roles. You might conclude that this privilege is required for all roles or users creating SAP HANA information views, but custom roles don’t need this privilege to activate SAP HANA information views using SAP HANA Studio or SAP Web IDE for SAP HANA. The activation of SAP HANA information views is controlled using package privileges and the navigation of the package hierarchy is controlled using the `SYS.REPOSITORY_REST` stored procedure. Runtime SAP HANA information view artifacts are created by the `_SYS_REPO` system account. Therefore, only the `_SYS_REPO` system account requires the create scenario system privilege.
