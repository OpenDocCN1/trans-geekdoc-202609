

## MD5 安全局限性

MD5 实现了额外的安全特性，但会显著降低消息摘要的生成速度。不幸的是，最近的密码分析攻击表明 MD5 协议容易发生碰撞，这使其无法用于确保消息完整性。具体而言，Arjen Lenstra 等人在 2005 年证明了可以从不同的公钥创建两个具有相同 MD5 哈希值的数字证书。

## 数字签名

一旦你选择了一个密码学上可靠的哈希算法，就可以用它来实现*数字签名*系统。数字签名基础设施有两个不同的目标：

*   数字签名消息向接收者保证消息确实来自声称的发送者。它们强制执行**不可抵赖性**（即防止发送者事后声称消息是伪造的）。
*   数字签名消息向接收者保证消息在发送者和接收者之间传输时未被篡改。这可以防止恶意修改（第三方更改消息含义）和无意修改（由于通信过程中的故障，如电气干扰）。

数字签名算法依赖于本章已介绍的两个主要概念的组合——公钥密码学和哈希函数。

如果 Alice 想要对发送给 Bob 的消息进行数字签名，她会执行以下操作：

1.  Alice 使用一种密码学上可靠的哈希算法（如 `SHA3-512`）生成原始明文消息的消息摘要。
2.  Alice 然后仅使用她的私钥加密该消息摘要。这个加密后的消息摘要就是数字签名。
3.  Alice 将签名后的消息摘要附加到明文消息后。
4.  Alice 将附加后的消息发送给 Bob。

当 Bob 接收到数字签名消息时，他会反向执行该过程，步骤如下：

1.  Bob 使用 Alice 的公钥解密数字签名。
2.  Bob 使用相同的哈希函数基于从 Alice 接收到的完整明文消息创建一个消息摘要。
3.  Bob 然后将从 Alice 处收到的解密后的消息摘要与他自己计算的消息摘要进行比较。如果两个摘要匹配，他可以确信收到的消息是由 Alice 发送的。如果不匹配，则消息不是由 Alice 发送的，或者消息在传输过程中被修改过。

请注意，数字签名过程本身并不提供任何保密性。它仅确保满足完整性、认证和不可抵赖性这些密码学目标。然而，如果 Alice 想要确保她发给 Bob 的消息的保密性，她可以在消息创建过程中增加一个步骤。在将签名后的消息摘要附加到明文消息后，Alice 可以使用 Bob 的公钥加密整个消息。当 Bob 收到消息时，他会先用自己的私钥解密，然后再执行上述步骤。

### HMAC

哈希消息认证码 (HMAC) 算法实现了一种部分数字签名——它保证消息在传输过程中的完整性，但不提供不可抵赖性。

HMAC 可以通过使用共享密钥与任何标准消息摘要生成算法（如 `SHA-3`）结合使用。因此，只有知道该密钥的通信双方才能生成或验证数字签名。如果接收者解密消息摘要但无法将其与从明文消息生成的消息摘要成功比较，则意味着消息在传输过程中被篡改了。

因为 HMAC 依赖于共享密钥，所以它不提供任何不可抵赖性功能（如前所述）。然而，它的运行效率比下一节描述的数字签名标准更高，可能适用于对称密钥密码学适用的场景。简而言之，它代表了未加密使用消息摘要算法与基于公钥密码学的计算成本高昂的数字签名算法之间的一个折中点。

### 数字签名标准

美国国家标准与技术研究院在联邦信息处理标准 (FIPS) 186-4 中规定了联邦政府可用的数字签名算法，该标准也称为数字签名标准 (DSS)。该文档规定，所有联邦批准的数字签名算法必须使用 SHA-3 哈希函数。

DSS 还规定了可用于支持数字签名基础设施的加密算法。目前有三种批准的标准加密算法：

*   FIPS 186-4 中规定的数字签名算法 (DSA)
*   ANSI X9.31 中规定的 Rivest–Shamir–Adleman (RSA) 算法
*   ANSI X9.62 中规定的椭圆曲线 DSA (ECDSA)

## 公钥基础设施

公钥加密的主要优势在于其能够促进相互未知的各方之间的通信。这得益于*公钥基础设施 (PKI)* 信任关系层级。这些信任关系允许将非对称密码学与对称密码学相结合，并配合哈希和数字证书，从而实现混合密码学。

在以下章节中，你将学习公钥基础设施的基本组件以及使全球安全通信成为可能的密码学概念。你将了解数字证书的组成、证书颁发机构的角色，以及生成和销毁证书的过程。

### 证书

数字*证书*为通信双方提供保证，确认他们正在通信的人确实是他们声称的那个人。数字证书本质上是个人公钥的背书副本。当用户验证证书是由受信任的证书颁发机构 (CA) 签名时，他们就知道该公钥是合法的。

数字证书包含特定的标识信息，其构建遵循一项国际标准——X.509。符合 X.509 标准的证书包含以下数据：

*   证书遵循的 X.509 版本
*   序列号（来自证书创建者）
*   签名算法标识符（指定证书颁发机构用于对证书内容进行数字签名的技术）
*   颁发者名称（颁发证书的证书颁发机构的标识）
*   有效期（指定证书有效期间的日期和时间——开始日期/时间和结束日期/时间）
*   主体名称（包含拥有证书中公钥的实体的可分辨名称，即 DN）
*   主体公钥（证书的核心——证书所有者用于建立安全通信的实际公钥）

当前版本的 X.509（版本 3）支持证书扩展——由证书颁发机构插入证书中以支持证书跟踪或各种应用的包含数据的自定义变量。
