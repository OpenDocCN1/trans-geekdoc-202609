

# POTS 和 PSTN

POTS 和 PSTN 是指传统的固定电话连接。在高速、高性价比且普及的接入方式出现之前，POTS/PSTN 连接曾是许多企业唯一或主要的远程网络链路。随着宽带和无线服务的广泛普及，POTS/PSTN 在家庭用户互联网接入方面的使用也随之减少。当宽带方案失效时，POTS/PSTN 连接有时仍被用作远程连接的备份选项，用作农村互联网和远程连接，以及在 ISDN、VoIP 或宽带方案不可用或不具成本效益时，用作标准语音线路。

# 远程访问安全注意事项

在任何环境中部署远程访问功能时，必须考虑并实施安全措施，以保护专用网络免受远程访问带来的复杂问题影响：

*   远程访问用户在获得访问权限前应经过严格认证。
*   只有那些因分配的工作任务而特别需要远程访问的用户，才应被授予建立远程连接的权限。
*   所有远程通信都应受到保护，防止被拦截和窃听。这通常需要一种加密解决方案，为认证流量以及所有数据传输提供强有力的保护。

在传输敏感、有价值或个人信息之前，建立安全通信通道至关重要。如果缺乏充分的保护和监控，远程访问可能会带来多种潜在的安全隐患：

*   如果任何拥有远程连接的人都能尝试突破组织的安全防线，物理安全的效益就会降低。
*   远程办公人员可能使用不安全或安全性较低的远程系统来访问敏感数据，从而使其面临更大的丢失、泄露或暴露风险。
*   远程系统可能暴露于恶意代码，并被用作将恶意软件带入专用局域网的载体。
*   远程系统的物理安全性可能较差，因此面临被未授权实体使用或被盗的风险。
*   远程系统可能更难排查故障，特别是当问题围绕远程连接本身时。
*   由于远程系统可能连接不频繁或吞吐量链路较慢，因此可能不易进行升级或打补丁。不过，当存在高速可靠的宽带链路时，此问题会有所缓解。

## 规划远程访问安全

在制定远程访问安全管理策略时，务必解决以下问题：

### 远程连接技术

每种连接类型都有其独特的安全问题。必须全面审视连接选项的各个方面。这可能包括蜂窝/移动服务、调制解调器、`数字用户线路 (DSL)`、`综合业务数字网 (ISDN)`、无线网络、卫星和有线调制解调器。

### 传输保护

存在多种加密协议、加密连接系统以及加密网络服务或应用程序。应针对远程连接需求使用适当的安全服务组合。这可能包括 `VPN`、`SSL`、`TLS`、`安全外壳协议 (SSH)`、`IPsec` 和 `第 2 层隧道协议 (L2TP)`。

### 认证保护

除了保护数据流量外，还必须确保所有登录凭据得到妥善保护。这要求使用认证协议，并可能强制要求使用集中式远程访问认证系统。这可能包括 `密码认证协议 (PAP)`、`质询握手认证协议 (CHAP)`、`可扩展认证协议 (EAP，或其扩展 PEAP 或 LEAP)`、`远程认证拨入用户服务 (RADIUS)` 和 `终端访问控制器访问控制系统 Plus (TACACS+)`。

### 远程用户协助

远程访问用户可能会定期需要技术协助。必须建立一种机制，以尽可能高效地提供这种协助。这可能包括（例如）解决软硬件问题和用户培训问题。如果组织无法为远程用户技术支持提供合理的解决方案，可能会导致生产力损失、远程系统受损或组织整体安全遭到破坏。

如果难以或无法在远程系统上维护与专用局域网相同级别的安全性，则应考虑到其代表的安全风险，重新评估远程访问方案。`网络准入控制 (NAC)` 可对此提供帮助，但可能会因大量更新和补丁传输而给较慢的连接带来负担。

使用远程访问或建立远程连接的能力应受到严格控制。可以通过基于用户身份、工作站身份、协议、应用程序、内容和时间段的过滤器、规则或访问控制来控制和限制远程连接的使用。

为将远程访问限制为仅授权用户，可以使用回拨和来电显示。回拨是一种机制，它在初次联系时断开远程用户的连接，然后使用预定义的电话号码（即用户账户安全数据库中定义的号码）立即尝试重新连接。回拨确实有一种用户定义模式。然而，该模式并非用于安全目的；而是用于将话费由公司承担，而非向远程客户端收费。来电显示验证可用于与回拨相同的目的——通过电话号码潜在地验证授权用户的物理位置。

安全策略中应包含一项标准规定：不得在任何连接到专用网络的系统上存在未授权的调制解调器。可能还需要进一步明确该策略，规定携带便携式系统的人员必须在连接到网络前移除其调制解调器，或使用禁用调制解调器设备驱动程序的硬件配置文件启动。

## 拨号协议

建立远程连接链路时，必须使用一种协议来管辖链路的实际创建方式，并建立一个通用的通信基础，以便其他协议能在其上运行。只要可能，选择支持安全性的协议非常重要。至少需要一种保护认证的方法，但最好也具备数据加密选项。两种主要的拨号协议示例 `PPP` 和 `SLIP` 提供链路管辖，不仅适用于真正的拨号链路，也适用于某些 VPN 链路：

### 点对点协议 (PPP)

这是一种全双工协议，用于通过各种非局域网连接（如调制解调器、`ISDN`、VPN、帧中继等）传输 `TCP/IP` 数据包。`PPP` 应用广泛，是拨号互联网连接的首选传输协议。`PPP` 认证通过使用各种协议（如 `CHAP` 和 `PAP`）得到保护。`PPP` 是 `SLIP` 的替代品，可支持任何局域网协议，而不仅仅是 `TCP/IP`。

### 串行线路互联网协议 (SLIP)

这是一种较早的技术，旨在支持通过异步串行连接（如串行电缆或调制解调器拨号）进行 `TCP/IP` 通信。`SLIP` 很少使用，但许多系统仍支持它。它仅支持 `IP`，需要静态 IP 地址，不提供错误检测或纠正，也不支持压缩。
