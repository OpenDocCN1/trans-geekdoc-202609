

# Blowfish

安全专家 Bruce Schneier 开发了 **Blowfish** 作为 DES 的一种可能替代方案。它可以使用 32 位到 448 位的密钥长度，是一种强加密协议。Linux 系统使用 `bcrypt` 来加密密码，而 `bcrypt` 基于 **Blowfish**。`bcrypt` 增加了 128 个额外的位作为盐值，以防止彩虹表攻击。

## 使用传输加密保护数据

传输加密方法在数据传输前对其进行加密，为传输中的数据提供保护。通过网络发送未加密数据的主要风险是嗅探攻击。攻击者可以使用嗅探器或协议分析器来捕获通过网络发送的流量。嗅探器允许攻击者读取以明文发送的所有数据。然而，攻击者无法读取使用强加密协议加密的数据。

例如，Web 浏览器使用超文本传输安全协议 (HTTPS) 来加密电子商务交易。这可以防止攻击者捕获数据并利用信用卡信息进行欺诈消费。相比之下，超文本传输协议 (HTTP) 以明文传输数据。

几乎所有的 HTTPS 传输都使用传输层安全协议 (TLS 1.1) 作为底层加密协议。安全套接字层 (SSL) 是 TLS 的前身。Netscape 于 1995 年创建并发布了 SSL。后来，互联网工程任务组 (IETF) 发布了 TLS 作为替代方案。2014 年，Google 发现 SSL 易受 POODLE 攻击（降级遗留加密填充 oracle 攻击）。因此，许多组织已在其应用程序中禁用了 SSL。

组织通常会启用远程访问解决方案，例如虚拟专用网络 (VPN)。VPN 允许员工从家中或出差途中访问组织的内部网络。VPN 流量通过公共网络（如互联网）传输，因此加密非常重要。VPN 使用 TLS 和 Internet 协议安全 (IPsec) 等加密协议。

IPsec 常与第 2 层隧道协议 (L2TP) 结合用于 VPN。L2TP 以明文传输数据，但 L2TP/IPsec 对数据进行加密，并使用隧道模式通过互联网发送，以保护其在传输过程中的安全。IPsec 包含一个认证头 (AH)，提供认证和完整性；以及封装安全载荷 (ESP) 以提供机密性。

在内部网络上传输敏感数据之前对其进行加密也是适当的。IPsec 和安全外壳协议 (SSH) 常用于保护内部网络上传输中的数据。SSH 是一种强加密协议，包含在其他协议中，如安全复制 (SCP) 和 SSH 文件传输协议 (SFTP)。SCP 和 SFTP 都是用于通过网络传输加密文件的安全协议。文件传输协议 (FTP) 等协议以明文传输数据，因此不适合通过网络传输敏感数据。

许多管理员在管理远程服务器时使用 SSH。其明显的好处是 SSH 加密所有流量，包括管理员的凭据。历史上，许多管理员使用 Telnet 来管理远程服务器。然而，Telnet 以明文在网络上发送流量，这就是为什么管理员明白今天不应再使用它的原因。有人建议在加密的 VPN 隧道中使用 Telnet 是可以接受的，但事实并非如此。是的，从客户端到 VPN 服务器的流量是加密的。然而，从 VPN 服务器到 Telnet 服务器的流量却是以明文发送的。

## 确定所有权

组织内的许多人管理、处理和使用数据，根据其角色不同，他们有不同的需求。不同的文档对这些角色的称呼略有不同。您可能看到的一些术语与某些 NIST 文档中使用的术语相符，而其他术语则与欧盟 (EU) 通用数据保护条例 (GDPR) 中使用的部分术语相符。在适当的情况下，我们列出了来源，以便您在需要时能更深入地了解这些术语。

这里最重要的概念之一是确保人员知道谁拥有信息和资产的所有权。所有者有保护数据和资产的主要责任。

### 数据所有者

`data owner`（数据所有者）是对数据承担最终组织责任的人。所有者通常是首席运营官 (CEO)、总裁或部门主管 (DH)。数据所有者确定数据的分类并确保其正确标记。他们还确保根据分类和组织的安全策略要求，数据拥有足够的安全控制措施。如果所有者未能尽职建立和执行安全策略以保护和维护敏感数据，他们可能因疏忽而承担责任。

NIST SP 800-18 概述了信息所有者的以下职责，这可以理解为与数据所有者相同。

*   制定主体数据/信息的适当使用和保护规则（行为规则）
*   就信息系统的安全需求和安全控制向信息系统所有者提供意见，这些信息系统是信息所在之处
*   决定谁有权访问信息系统，以及拥有何种类型的特权或访问权限
*   协助识别和评估信息所在之处的通用安全控制。

### 资产所有者

资产所有者（或系统所有者）是拥有处理敏感数据的资产或系统的人。NIST SP 800-18 概述了系统所有者的以下职责：

*   与信息所有者、系统管理员和功能最终用户协调制定系统安全计划
*   维护系统安全计划，并确保系统按照商定的安全要求进行部署和运行
*   确保系统用户和支持人员接受适当的安全培训，例如行为规则（或 AUP）方面的指导
*   每当发生重大变更时更新系统安全计划
*   协助识别、实施和评估通用安全控制

系统所有者通常与数据所有者是同一人，但有时也可能是不同的人，例如不同的部门主管 (DH)。例如，考虑一台用于电子商务并与后端数据库服务器交互的 Web 服务器。软件开发部门可能会为数据库和数据库服务器执行数据库开发和数据库管理，但 IT 部门维护 Web 服务器。在这种情况下，软件开发部门主管是数据库服务器的系统所有者，而 IT 部门主管是 Web 服务器的系统所有者。然而，由一人（如单个部门主管）控制这两台服务器的情况更为常见，此人将成为两个系统的系统所有者。

系统所有者负责确保系统上处理的数据保持安全。这包括识别系统处理的最高级别数据。然后，系统所有者确保系统标记准确，并采取适当的安全控制措施来保护数据。系统所有者与数据所有者交互，以确保数据在系统上静止时、在系统间传输时以及在系统上运行的应用程序使用时均受到保护。

### 业务/任务所有者

不同组织对业务/任务所有者角色的看法不同。NIST SP 800-18 将业务/任务所有者称为项目经理或信息系统所有者。因此，业务/任务所有者的职责可能与系统所有者的职责重叠，或为同一角色。
