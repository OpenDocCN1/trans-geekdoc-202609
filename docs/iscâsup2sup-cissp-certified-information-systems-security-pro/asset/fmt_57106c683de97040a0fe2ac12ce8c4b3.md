
计算机科学家和数学家认为，即使已知 *P* 和 *Q*，找到 *x* 也极其困难。这个被称为椭圆曲线离散对数问题的难题，构成了椭圆曲线密码学的基础。人们普遍认为，该问题比 RSA 密码系统所依赖的大整数分解难题，以及 Diffie-Hellman 和 El Gamal 所利用的标准离散对数问题更难求解。侧边栏“密钥长度的重要性”中的表格数据直观地说明了这一点：1,024 位的 RSA 密钥在密码学强度上等同于 160 位的椭圆曲线密码系统密钥。

## 哈希函数

本章后面将介绍密码系统如何实现数字签名，以证明消息源自特定用户，并确保消息在双方传输过程中未被篡改。在完全理解该概念之前，我们必须先解释*哈希函数*的概念。我们将探讨哈希函数的基础知识，并了解现代数字签名算法中使用的几种常见哈希函数。

哈希函数的目的非常简单——它们接收一个可能很长的消息，并根据消息内容生成一个唯一的输出值。该值通常称为*消息摘要*。消息发送者可以生成消息摘要，并将其与完整消息一起传输给接收者，主要出于以下两个原因。

首先，接收者可以使用相同的哈希函数，从完整消息中重新计算消息摘要。然后将计算出的摘要与传输的摘要进行比较，以确保发送者发送的消息与接收者收到的消息完全一致。如果两个摘要不匹配，则意味着消息在传输过程中被篡改。重要的是，消息必须*完全*相同，摘要才会匹配。如果消息在空格、标点或内容上哪怕只有细微差别，摘要值也会完全不同。无法通过比较摘要来判断两条消息的差异程度。即使是微小的差异，也会生成完全不同的摘要值。

其次，消息摘要可用于实现数字签名算法。本章后面的“数字签名”部分将介绍这一概念。

在大多数情况下，消息摘要为 128 位或更长。不过，单个数字值可用于执行奇偶校验功能，这是一种低级的或单数字的校验和值，用于提供单个验证点。在大多数情况下，消息摘要越长，其完整性验证就越可靠。

根据 RSA Security 的说法，加密哈希函数有五项基本要求：

*   输入可以是任意长度。
*   输出具有固定长度。
*   对于任何输入，哈希函数计算相对容易。
*   哈希函数是单向的（即在给定输出的情况下，极难确定输入）。单向函数及其在密码学中的用途将在第 6 章中介绍。
*   哈希函数无冲突（即极难找到产生相同哈希值的两条消息）。

在以下章节中，我们将介绍四种常见的哈希算法：安全哈希算法（SHA）、消息摘要算法 2（MD2）、消息摘要算法 4（MD4）和消息摘要算法 5（MD5）。本章后面还将讨论基于哈希的消息认证码（HMAC）。

### SHA

安全哈希算法（SHA）及其后继者 SHA-1、SHA-2 和 SHA-3，是由美国国家标准与技术研究院（NIST）推广的政府标准哈希函数，并在一份官方政府出版物——安全哈希标准（SHS），也称为联邦信息处理标准（FIPS）180 中规定。

SHA-1 接受几乎任意长度的输入（实际上，该算法的上限约为 2,097,152 TB），并生成 160 位的消息摘要。SHA-1 算法以 512 位分块处理消息。因此，如果消息长度不是 512 的倍数，SHA 算法会用额外数据填充消息，直到长度达到下一个 512 的倍数。

密码分析攻击表明 SHA-1 算法存在弱点。这促使了 SHA-2 的诞生，SHA-2 有四个变体：

*   SHA-256 使用 512 位分块大小，生成 256 位消息摘要。
*   SHA-224 使用 SHA-256 哈希的截断版本，配合 512 位分块大小，生成 224 位消息摘要。
*   SHA-512 使用 1,024 位分块大小，生成 512 位消息摘要。
*   SHA-384 使用 SHA-512 哈希的截断版本，配合 1,024 位分块大小，生成 384 位摘要。

密码学界普遍认为 SHA-2 算法是安全的，但它们理论上存在与 SHA-1 相同的弱点。2015 年，联邦政府发布了 Keccak 算法作为 SHA-3 标准。SHA-3 套件的开发旨在作为 SHA-2 哈希函数的直接替代品，使用更安全的算法提供相同的变体和哈希长度。

### MD2

消息摘要算法 2（MD2）由 Ronald Rivest（RSA 中的 Rivest）于 1989 年开发，旨在为 8 位处理器提供安全的哈希函数。MD2 对消息进行填充，使其长度成为 16 字节的倍数。然后计算一个 16 字节的校验和并将其追加到消息末尾。最后使用原始消息连同追加的校验和生成 128 位消息摘要。

针对 MD2 算法存在密码分析攻击。具体而言，Nathalie Rogier 和 Pascal Chauvaud 发现，如果在摘要计算前未将校验和追加到消息中，可能会发生冲突。Frederic Mueller 后来证明 MD2 不是单向函数。因此，不应再使用该算法。

### MD4

1990 年，Rivest 改进了其消息摘要算法以支持 32 位处理器并提高安全级别。该增强算法称为 MD4。它首先填充消息，确保消息长度比 512 位的倍数小 64 位。例如，16 位消息将填充 432 位额外数据，使其成为 448 位，比 512 位消息小 64 位。

MD4 算法随后在三轮计算中处理消息的 512 位分块。最终输出为 128 位消息摘要。

多位数学家发表论文记录了完整版 MD4 以及错误实现的 MD4 存在的缺陷。特别是 Hans Dobbertin 于 1996 年发表论文，阐述了如何利用现代个人电脑在一分钟内找到 MD4 摘要的冲突。因此，MD4 不再被视为安全的哈希算法，如果可能，应避免使用。

### MD5

1991 年，Rivest 发布了其消息摘要算法的下一个版本，称为 MD5。它同样处理消息的 512 位分块，但使用四轮不同的计算生成摘要，长度与 MD2 和 MD4 相同（128 位）。MD5 的填充要求与 MD4 相同——消息长度必须比 512 位的倍数少 64 位。
