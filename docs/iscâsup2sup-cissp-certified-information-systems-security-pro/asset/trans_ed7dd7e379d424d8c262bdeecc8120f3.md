

# 设计安全计算系统

设计安全计算系统是一项复杂的任务，许多安全工程师将其整个职业生涯都致力于理解信息系统的内部运作，并确保它们支持在当前环境中安全运行所需的核心安全功能。许多安全专业人员不一定需要深入了解这些原则，但他们至少应对驱动该过程以增强其自身组织安全性的基本原理有广泛的理解。

这种理解始于对硬件、软件和固件的调查，以及这些组件如何融入安全拼图中。理解通用计算机和网络组织、架构及设计的原则非常重要，包括寻址（物理寻址和符号寻址）、地址空间与内存空间的区别，以及机器类型（实机、虚拟机、多状态、多任务、多道程序、多处理、多处理器和多用户）。

此外，安全专业人员必须对操作状态（单状态、多状态）、操作模式（用户态、监督态、特权态）、存储类型（主存、辅存、实存、虚拟存、易失性、非易失性、随机存取、顺序存取）以及保护机制（分层、抽象、数据隐藏、进程隔离、硬件分段、最小权限原则、特权分离、问责制）有扎实的理解。

无论安全模型多么复杂，都存在攻击者可利用的缺陷。某些缺陷（如缓冲区溢出和维护钩子）是由程序员引入的，而其他缺陷（如隐蔽信道）则是架构设计问题。理解此类问题的影响并在适当的时候修改安全架构以进行补偿非常重要。

## 考试要点

**能够解释多任务、多线程、多处理和多道程序之间的区别。** 多任务是指在一台计算机上同时执行多个应用程序，由操作系统管理。多线程允许在单个进程内执行多个并发任务。多处理是指使用多个处理器来增加计算能力。多道程序与多任务类似，但在大型机系统上进行，并需要特定的编程。

**理解单状态处理器和多状态处理器之间的区别。** 单状态处理器一次只能在一个安全级别下运行，而多状态处理器可以同时在多个安全级别下运行。

**描述联邦政府批准的用于处理机密信息的四种安全模式。** 专用模式要求所有用户对系统上存储的所有信息都具有适当的许可、访问权限和知悉必要性。系统高模式去除了知悉必要性的要求。分区模式去除了知悉必要性要求和访问权限要求。多级模式去除了所有三项要求。

**解释大多数现代处理器使用的两种分层操作模式。** 用户应用程序在称为用户模式的受限指令集环境中运行。操作系统在特权模式下执行受控操作，特权模式也称为系统模式、内核模式和监督模式。

**描述计算机使用的不同类型的内存。** `ROM` 是非易失性的，最终用户无法向其写入数据。最终用户只能向 `PROM` 芯片写入一次数据。`EPROM`/`UVEPROM` 芯片可通过紫外线擦除，然后写入新数据。`EEPROM` 芯片可通过电流擦除，然后写入新数据。`RAM` 芯片是易失性的，计算机断电时会丢失其内容。

**了解内存组件相关的安全问题。** 内存组件存在一些安全问题：断电后数据可能残留在芯片上，以及在多用户系统中对内存访问的控制。

**描述计算机使用的存储设备的不同特性。** 主存储器即内存。辅助存储器由磁性、闪存和光学介质组成，数据必须先读入主存储器，CPU 才能使用。随机存取存储设备可在任意点读取，而顺序存取设备需要扫描物理存储在前面的所有数据才能到达目标位置。

**了解辅助存储设备相关的安全问题。** 辅助存储设备存在三个主要安全问题：可移动介质可被用来窃取数据，必须应用访问控制和加密来保护数据，以及数据即使在文件删除或介质格式化后仍可能残留在介质上。

**理解输入和输出设备可能带来的安全风险。** 输入/输出设备可能遭受窃听和监听，被用来将数据偷运出组织，或被用来创建未经授权的、不安全的入口点进入组织的系统和网络。要做好识别和缓解此类漏洞的准备。

**了解固件的用途。** 固件是存储在 `ROM` 芯片上的软件。在计算机层面，它包含启动计算机所需的基本指令。固件还用于在打印机等外围设备中提供操作指令。

**能够描述进程隔离、分层、抽象、数据隐藏和硬件分段。** 进程隔离确保各个进程只能访问自己的数据。分层在进程内创建不同的安全领域并限制它们之间的通信。抽象为程序员创建“黑盒”接口，使其无需了解算法或设备的内部工作原理即可使用。数据隐藏防止信息从不同安全级别被读取。硬件分段通过物理控制强制执行进程隔离。

**理解安全策略如何驱动系统设计、实施、测试和部署。** 安全策略的作用是指导和规范特定系统的设计、开发、实施、测试和维护。

**理解云计算。** 云计算是一个通用术语，指一种计算概念，即处理和存储通过网络连接在别处执行，而非在本地。云计算通常被认为是基于互联网的计算。

**理解云计算和虚拟化相关的风险。** 云计算和虚拟化，尤其是两者结合时，存在严重的相关风险。一旦敏感、机密或专有数据离开组织的范围，也就离开了组织安全策略及其所产生的基础设施施加的保护。云服务及其人员可能不遵守与贵组织相同的安全标准。

**理解管理程序。** 管理程序，也称为虚拟机监视器（`VMM`），是虚拟化中负责创建、管理和运行虚拟机的组件。

**了解 I 型管理程序。** I 型管理程序是原生或裸金属管理程序。在此配置中，没有宿主操作系统；相反，管理程序直接安装在硬件上，即宿主操作系统通常驻留的位置。

**了解 II 型管理程序。** II 型管理程序是宿主型管理程序。在此配置中，硬件上存在标准的常规操作系统，然后将管理程序作为另一个软件应用程序安装。

**定义 CASB。** 云访问安全代理（`CASB`）是一种安全策略执行解决方案，可以本地部署，也可以基于云部署。
