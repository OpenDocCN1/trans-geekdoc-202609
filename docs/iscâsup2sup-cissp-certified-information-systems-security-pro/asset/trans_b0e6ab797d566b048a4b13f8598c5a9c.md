
此外，这三台 Web 服务器配置在一个网络负载均衡集群中。负载均衡器可以基于硬件或软件，它将客户端负载分散到这三台服务器上。这使得添加额外的 Web 服务器以应对增加的负载变得容易，同时也能在所有服务器之间平衡负载。如果任何一台服务器发生故障，负载均衡器能感知到该故障并停止向该服务器发送流量。虽然网络负载均衡主要用于提高系统的可扩展性以便处理更多流量，但它也提供了一定程度的容错能力。

如果你在云中运行服务器，可能可以利用云服务商提供的容错服务。例如，许多 IaaS 提供商提供负载均衡服务，可根据需求自动扩展资源。这些服务还包含健康检查功能，可自动重启运行不正常的服务器。

同样，在设计云环境时，请务必考虑世界不同地区数据中心的可用性。如果你已经在对多台服务器进行负载均衡，可能可以将这些服务器放置在不同的地理区域及这些区域内的不同可用区中，以在可扩展性之外增加弹性。

## 保护电源

可以通过 `uninterruptible power supply`（UPS，不间断电源）、发电机或两者结合来为电源增加容错能力。一般来说，UPS 可提供 5 到 30 分钟的电池供电，而发电机提供长期供电。UPS 的目标是提供足够长的电力以完成系统的逻辑关机，或维持到发电机启动并提供稳定电力为止。

理想情况下，电力应持续稳定且无任何波动，但现实中，商用电力存在各种各样的问题。`spike`（尖峰/电压尖峰）是电压瞬间升高的情况，而 `sag`（跌落/电压跌落）是电压瞬间降低的情况。如果电压长时间保持在高位，称为 `surge`（浪涌/电压浪涌）而非尖峰。如果长时间保持在低位，称为 `brownout`（电压不足/欠压）。偶尔，电力线上会出现称为 `transients`（瞬态/电压瞬变）的噪声，来源多种多样。所有这些问题都可能给电气设备带来麻烦。

最基本的 UPS（也称为离线或备用 UPS）提供浪涌防护和电池备份。它插在商用电源上，关键系统插在 UPS 系统上。如果电源故障，电池备份将在短时间内为系统提供持续供电。线互动式 UPS 正变得流行，它们提供基本 UPS 之外的额外服务。它们包含一个可变电压变压器，可在不消耗电池电量的情况下调节过压和欠压事件。当电源丢失时，电池将为系统供电一小段时间。

发电机在长期停电期间为系统供电。发电机供电的时长取决于燃料，只要有燃料且发电机保持功能正常，现场就有可能长期依靠发电机供电。在 2017 年飓风“厄玛”袭击波多黎各后的漫长恢复期中，发电机被要求长时间运行，并在连续运行数周数月后开始出现故障。

发电机还需要稳定的燃料供应——通常使用柴油、天然气或丙烷。除了确保手头有足够的燃料外，还应采取措施确保在发生长期紧急情况时能定期获得燃料供应。请记住，如果灾难范围广泛，有限的燃料供应将面临巨大需求。如果你与供应商签订了合同，就更有可能及时获得燃料。

## 可信恢复

可信恢复确保系统在发生故障或崩溃后，其安全性与故障或崩溃发生前一样。根据故障类型，恢复可能是自动的，也可能需要管理员进行手动干预。然而，无论哪种情况，系统都可以设计为支持可信恢复。

系统可以设计为在故障时进入故障安全状态或故障开放状态。`fail-secure`（故障安全）系统在发生故障时将默认进入安全状态，阻止所有访问。`fail-open`（故障开放）系统将在开放状态下故障，允许所有访问。选择取决于故障发生后安全性还是可用性更重要。

例如，防火墙通过控制进出网络的访问提供大量安全性。它们配置为隐式拒绝策略，仅根据规则显式允许的流量通过。防火墙通常设计为故障安全，支持隐式拒绝策略。如果防火墙故障，所有流量都会被阻断。虽然这消除了通过防火墙的通信可用性，但却是安全的。相反，如果流量的可用性比安全性更重要，防火墙可配置为故障开放状态，允许所有流量通过。这不安全，但网络不会失去流量可用性。

恢复过程的两个要素被用于实现可信解决方案。第一个要素是故障准备。这包括系统弹性和容错方法，以及可靠的备份解决方案。第二个要素是系统恢复过程。系统应被强制重启进入单用户、非特权状态。这意味着系统应重启到可使用普通用户账户登录的程度，且系统不授予用户未经授权的访问权限。系统恢复还包括恢复故障或崩溃时系统上正在活跃使用的所有受影响文件和服务。任何丢失或损坏的文件将被恢复，分类标签的任何更改将被纠正，然后验证所有安全关键文件上的设置。

通用准则（在第 8 章“安全模型、设计和能力原则”中介绍）包含与系统弹性和容错相关的可信恢复部分。具体而言，它定义了四种类型的可信恢复：

**手动恢复** 如果系统故障，它不会进入安全状态。相反，需要管理员在故障或系统崩溃后手动执行实施安全或可信恢复所需的操作。

**自动恢复** 系统能够执行可信恢复活动，以针对至少一种故障类型恢复自身。例如，硬件 RAID 提供针对硬盘故障的自动恢复，但不提供针对整个服务器故障的恢复。某些类型的故障将需要手动恢复。

**无过度损失的自动恢复** 这类似于自动恢复，即系统能针对至少一种故障类型自行恢复。然而，它包含确保特定对象受到保护以防止其丢失的机制。一种防止过度损失的自动恢复方法将包括恢复数据或其他对象的步骤。它可能包含额外的保护机制来恢复损坏的文件、从事务日志重建数据，并验证关键系统和安全组件的完整性。

**功能恢复** 支持功能恢复的系统能够自动恢复特定功能。此状态确保系统能成功完成功能恢复，或能回滚更改以返回安全状态。
