

# 远程访问安全

随着远程访问成为组织业务功能的关键要素，在远程客户端与私有网络之间增加安全层往往显得至关重要。集中式远程认证服务（如 `RADIUS` 和 `TACACS+`）提供了这一额外的保护层。这些机制将远程客户端的认证和授权进程与局域网或本地客户端的进程分离开来。这种分离对安全性很重要，因为如果 `RADIUS` 或 `TACACS+` 服务器遭到破坏，则仅会影响远程连接，而不会影响网络的其余部分。

## 远程认证拨号用户服务 (RADIUS)

它用于集中管理远程拨号连接的认证。采用 `RADIUS` 服务器的网络会被配置为：远程访问服务器将拨号用户的登录凭据传递给 `RADIUS` 服务器进行认证。此过程类似于域客户端将登录凭据发送给域控制器进行认证的过程。`RADIUS` 在多个端口上运行；你应该识别出原始的 `UDP 1812` 端口，以及 `RADIUS` over `TLS` 所使用的 `TCP 2083` 端口。`RADIUS` 的 `TCP` 版本设计于 2012 年，旨在利用 `TLS` 加密（参见 RFC 6614，网址：<https://tools.ietf.org/html/rfc6614>）。

## 终端访问控制器访问控制系统 (TACACS+)

这是 `RADIUS` 的一种替代方案。`TACACS` 有三个版本：原始 `TACACS`、扩展 `TACACS` (`XTACACS`) 和 `TACACS+`。`TACACS` 将认证和授权进程集成在一起。`XTACACS` 将认证、授权和审计进程分开。`TACACS+` 通过增加双因素认证改进了 `XTACACS`。`TACACS+` 是该产品线中最新且最相关的版本。`TACACS+` 的主要端口是 `TCP 49`。

# 虚拟专用网络

`虚拟专用网络 (VPN)` 是一种通信隧道，它在中间不受信任的网络上提供认证流量和数据流量的点对点传输。大多数 `VPN` 使用加密来保护封装的流量，但加密并非 `VPN` 连接的必要条件。

`VPN` 最常与通过互联网在两个远程网络之间建立安全通信路径联系在一起。然而，它们可以存在于任何地方，包括私有网络内部，或连接到 `ISP` 的终端用户系统之间。`VPN` 可以连接两个网络或两个独立系统。它们可以连接客户端、服务器、路由器、防火墙和交换机。`VPN` 对于为依赖高风险或易受攻击的通信协议或方法的遗留应用程序提供安全性也很有帮助，尤其是在跨网络通信时。

`VPN` 可以在不安全或不受信任的中间网络上提供机密性和完整性。它们不提供或保证可用性。`VPN` 也被相对广泛地用于绕过 `Netflix` 和 `Hulu` 等服务的地区限制，从而提供一定程度的（有时存疑的）匿名性。

## 隧道技术

在真正理解 `VPN` 之前，必须先理解隧道技术。`隧道技术` 是一种网络通信过程，它通过将协议数据包封装在另一种协议的数据包中来保护其内容。这种封装在不可信的中间网络上创造了通信隧道的逻辑假象。此虚拟路径存在于通信两端的封装实体和解封装实体之间。

事实上，给祖母寄一封平信就涉及隧道系统的使用。你写好私人信件（主要内容协议数据包）并将其放入信封（隧道协议）中。信封通过邮政服务（不可信的中间网络）投递给预期收件人。你可以在许多情况下使用隧道技术，例如绕过防火墙、网关、代理或其他流量控制设备。绕过是通过将受限内容封装在被授权传输的数据包内来实现的。隧道过程阻止流量控制设备阻断或丢弃通信，因为这些设备不知道数据包实际包含什么。

隧道技术常用于实现原本不连通的系统之间的通信。如果两个系统因缺乏网络连接而分离，可以通过调制解调器拨号链路或其他远程访问或广域网 (`WAN`) 网络服务建立通信链路。实际的 `LAN` 流量被封装在临时连接所使用的任何通信协议中，例如调制解调器拨号情况下的 `点对点协议`。如果两个网络由采用不同协议的网络连接，分离网络的协议通常可以封装在中间网络的协议内以提供通信路径。

无论实际情况如何，隧道技术通过将内部协议和流量数据包置入（或包裹在）中间网络或连接所使用的授权协议中来保护其内容。如果主协议不可路由，或者为了将网络上支持的协议总数保持在最低限度，可以使用隧道技术。

如果封装协议的行为涉及加密，隧道技术可以提供一种手段，在不担心丢失机密性和完整性的情况下，跨不受信任的中间网络传输敏感数据。

隧道技术并非没有问题。它通常是一种低效的通信方式，因为大多数协议都包含自己的错误检测、错误处理、确认和会话管理功能，因此同时使用多个协议会增加传输单条消息所需的开销。此外，隧道技术会产生更大的数据包或额外的数据包，从而消耗额外的网络带宽。如果带宽不足，隧道技术会迅速使网络饱和。另外，隧道技术是一种点对点通信机制，并非设计用于处理广播流量。在某些情况下，隧道技术也使得监控流量内容变得困难，甚至不可能，给安全从业者带来了问题。

## VPN 如何工作

`VPN` 链路可以在任何其他网络通信连接上建立。这可以是典型的 `LAN` 电缆连接、无线 `LAN` 连接、远程访问拨号连接、`WAN` 链路，甚至是客户端使用互联网连接访问办公室 `LAN`。`VPN` 链路的表现就像典型的直接 `LAN` 电缆连接；唯一可能的区别在于基于中间网络以及客户端系统与服务器系统之间的连接类型的速度差异。通过 `VPN` 链路，客户端可以执行相同的活动并访问相同的资源，就像直接通过 `LAN` 电缆连接一样。

`VPN` 可以连接两个独立系统或两个完整网络。唯一的区别在于，传输的数据仅在 `VPN` 隧道内受到保护。网络边界上的远程访问服务器或防火墙充当 `VPN` 的起点和终点。因此，流量在源 `LAN` 内不受保护，在边界 `VPN` 服务器之间受保护，到达目标 `LAN` 后再次变为不受保护。

用于连接远程网络的通过互联网的 `VPN` 链路通常是专线或租用线路的低成本替代方案。两条连接到本地 `ISP` 的高速互联网链路以支持 `VPN` 的成本，通常远低于任何其他可用连接方式的成本。
