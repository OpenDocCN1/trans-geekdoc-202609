

# CIA 三要素：安全原则

安全控制通常根据其解决这三大核心信息安全原则的效果来评估。总体而言，完整的安全解决方案应充分解决这些原则中的每一个。漏洞和风险也是根据它们对 CIA 三要素原则中的一个或多个构成的威胁来评估的。因此，熟悉这些原则并将其作为判断所有安全相关事务的指南是个好主意。

这三个原则被认为是安全领域中最重要的。然而，每个特定原则对特定组织的重要程度取决于该组织的安全目标和要求，以及组织安全可能受到威胁的程度。

## 机密性

CIA 三要素的第一原则是机密性。`机密性` 是指用于确保数据、对象或资源的秘密性得到保护的措施概念。机密性保护的目标是防止或最小化对数据的未授权访问。机密性将安全措施的重点放在确保除预期接收者外，无人能收到或读取消息。机密性保护为授权用户提供访问和交互资源的途径，但会主动阻止未授权用户这样做。广泛的安全控制可为机密性提供保护，包括但不限于加密、访问控制和隐写术。

如果安全机制提供机密性，则它能提供高度保证，即数据、对象或资源受限于未授权主体。如果存在针对机密性的威胁，可能会发生未授权披露。对象是安全关系中的被动元素，如文件、计算机、网络连接和应用程序。主体是安全关系中的主动元素，如用户、程序和计算机。主体作用于对象或针对对象采取行动。主体和对象之间关系的管理称为访问控制。

一般来说，要在网络上维持机密性，数据在存储、处理和传输过程中都必须受到保护，防止未授权访问、使用或披露。维持机密性需要针对数据、资源和对象的这些状态，分别采用独特且特定的安全控制。

许多攻击专注于违反机密性。这些攻击包括捕获网络流量、窃取密码文件，以及社会工程学、端口扫描、肩窥、窃听、嗅探、权限提升等。

机密性违规不仅限于有针对性的故意攻击。许多敏感或机密信息未授权披露的实例是人为错误、疏忽或无能的结果。导致机密性泄露的事件包括：未能正确加密传输、在传输数据前未能完全认证远程系统、留下原本受保护的访问点敞开、访问打开后门的恶意代码、传真发错位置、文档遗留在打印机上，甚至在数据显示在显示器上时离开访问终端。机密性违规可能源于最终用户或系统管理员的行为，也可能源于安全策略的疏漏或安全控制的错误配置。

许多对策有助于确保机密性以抵御潜在威胁。这些包括加密、网络流量填充、严格的访问控制、严格的认证程序、数据分类和广泛的人员培训。

机密性和完整性相互依赖。没有对象完整性（换句话说，未经许可无法修改对象），就无法维持机密性。与机密性相关的其他概念、条件和方面包括以下内容：

### 敏感性
`敏感性` 是指信息的一种属性，一旦披露可能造成危害或损失。维护敏感信息的机密性有助于防止危害或损失。

### 裁量权
`裁量权` 是一种决策行为，操作员可通过影响或控制披露来将危害或损失降至最低。

### 关键性
信息对任务的关键程度即为其 `关键性` 的衡量标准。关键性级别越高，越有可能需要维护该信息的机密性。高关键性级别对组织的运作或职能至关重要。

### 隐藏
`隐藏` 是隐瞒或防止披露的行为。隐藏常被视为一种掩护、混淆或转移注意力的手段。与隐藏相关的概念是靠隐蔽求安全，即试图通过隐藏、沉默或保密来获得保护的概念。虽然靠隐蔽求安全通常不被视为有效的安全措施，但在某些情况下仍可能有价值。

### 保密
`保密` 是保守秘密或防止信息泄露的行为。

### 隐私
`隐私` 是指保护可识别个人身份的信息，或一旦泄露可能对某人造成伤害、尴尬或耻辱的信息保持机密。

### 隔离存放
`隔离存放` 涉及将某物存放在偏僻的位置。该位置也可提供严格的访问控制。隔离存放有助于执行机密性保护。

### 隔离
`隔离` 是将某物与其他事物分离的行为。隔离可用于防止信息混合或信息泄露。

每个组织都需要评估其希望实施的机密性细微差别。实现一种形式机密性的工具和技术可能不支持或不允许其他形式。

## 完整性

CIA 三要素的第二原则是完整性。`完整性` 是保护数据可靠性和正确性的概念。完整性保护防止对数据的未授权修改。它确保数据保持正确、未被篡改且得以保存。正确实施的完整性保护为授权更改提供途径，同时防范蓄意和恶意的未授权活动（如病毒和入侵）以及授权用户的错误（如失误或疏忽）。

为维持完整性，对象必须保持其真实性，且仅由授权主体有意修改。如果安全机制提供完整性，则它能提供高度保证，即数据、对象和资源未从其原始受保护状态被篡改。无论对象处于存储、传输还是处理状态，均不应发生篡改。因此，维护完整性意味着对象本身未被篡改，且管理和操作该对象的操作系统和编程实体未被攻破。

完整性可从三个角度进行审视：

*   防止未授权主体进行修改
*   防止授权主体进行未授权修改，如失误
*   维护对象的内部和外部一致性，使其数据能正确、真实地反映现实世界，且与任何子对象、对等对象或父对象的关系均为有效、一致且可验证的

为在系统上维持完整性，必须实施控制以限制对数据、对象和资源的访问。此外，应采用活动日志记录，以确保只有授权用户才能访问其各自的资源。跨存储、传输和处理维护和验证对象完整性需要多种变体的控制和监督。
