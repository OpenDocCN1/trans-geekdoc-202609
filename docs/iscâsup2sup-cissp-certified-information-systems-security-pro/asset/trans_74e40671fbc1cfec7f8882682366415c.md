
**不需要预先存在的通信链路。** 两个个体可以从开始通信的那一刻起就进行安全通信。非对称加密不需要预先存在的关系即可为数据交换提供安全机制。

公钥加密的主要弱点是其运行速度缓慢。因此，许多需要安全传输大量数据的应用程序使用公钥加密来建立连接，然后交换一个对称密钥。会话的其余部分随后使用对称加密。[表 6.1](#c06.xhtml#table6-1) 对比了对称和非对称加密系统。仔细查看该表可发现，一个系统的弱点恰好被另一个系统的优势所弥补。

### 哈希算法

在上一节中，你了解到公钥密码系统在与消息摘要结合使用时可以提供数字签名功能。消息摘要是由哈希算法生成的消息内容摘要（类似于文件校验和）。从理想的哈希函数中推导出原始消息极其困难，甚至不可能，且两条不同消息产生相同哈希值的可能性极低。哈希函数为两个不同输入产生相同值的情况称为 `collisions`（碰撞），碰撞的存在通常会导致该哈希算法被弃用。

第 7 章将详细介绍当代哈希算法，并解释它们如何用于提供数字签名功能，这有助于实现完整性和不可抵赖性这两个加密目标。

## 对称加密

你已经了解了对称密钥加密、非对称密钥加密和哈希函数的基本概念。在接下来的章节中，我们将深入探讨几种常见的对称密码系统：数据加密标准（`DES`）、三重 DES（`3DES`）、国际数据加密算法（`IDEA`）、Blowfish、Skipjack 和高级加密标准（`AES`）。

### 数据加密标准

美国政府于 1977 年发布了数据加密标准，作为所有政府通信的拟议标准密码系统。由于算法存在缺陷，密码学家和联邦政府不再认为 `DES` 是安全的。人们普遍认为情报机构会例行解密 `DES` 加密的信息。`DES` 于 2001 年 12 月被高级加密标准取代。理解 `DES` 仍然很重要，因为它是三重 DES（`3DES`）的基础构建模块，后者是下一节将讨论的一种强加密算法。

`DES` 是一种 64 位分组密码，具有五种操作模式：电子密码本（`ECB`）模式、密码分组链接（`CBC`）模式、密码反馈（`CFB`）模式、输出反馈（`OFB`）模式和计数器（`CTR`）模式。这些模式将在以下章节中解释。所有 `DES` 模式一次对 64 位明文进行操作，以生成 64 位密文分组。`DES` 使用的密钥长度为 56 位。

`DES` 使用一长串异或（`XOR`）操作来生成密文。该过程在每次加密/解密操作中重复 16 次。每次重复通常称为一轮 `round` 加密，这解释了为什么说 `DES` 执行 16 轮加密。

#### 电子密码本模式

电子密码本（`ECB`）模式是最容易理解但安全性最低的模式。每当算法处理一个 64 位分组时，它只是使用选定的密钥加密该分组。这意味着如果算法多次遇到相同的分组，它将产生相同的加密分组。如果窃听者正在监听通信，他们可以简单地建立所有可能加密值的“密码本”。收集到足够数量的分组后，即可使用密码分析技术破译部分分组并破解加密方案。

这种漏洞使得 `ECB` 模式除极短传输外均不切实际。在日常使用中，`ECB` 仅用于交换少量数据，例如用于启动其他 `DES` 模式的密钥和参数，以及数据库中的单元格。

#### 密码分组链接模式

在密码分组链接（`CBC`）模式中，每个未加密文本分组在使用 `DES` 算法加密前，都会与其前一个密文分组进行 `XOR` 运算。解密过程只需解密密文并反向执行 `XOR` 操作。`CBC` 实现了一个 `IV`（初始化向量）并将其与消息的第一个分组进行 `XOR` 运算，使每次操作都产生唯一的输出。`IV` 必须发送给接收者，可能是将 `IV` 以明文形式附加在完成的密文前面，或者使用与消息相同的密钥通过 `ECB` 模式加密来保护它。使用 `CBC` 模式时一个重要考量是错误会传播——如果传输过程中某个分组损坏，将无法解密该分组和下一个分组。

#### 密码反馈模式

密码反馈（`CFB`）模式是 `CBC` 的流密码版本。换句话说，`CFB` 针对实时产生的数据进行操作。然而，它不将消息分成分组，而是使用与分组大小相同的内存缓冲区。当缓冲区填满时，对其进行加密并发送给接收者。然后系统等待下一个缓冲区在新数据生成时填满，随后依次加密并传输。除了从预存数据变为实时数据这一变化外，`CFB` 的操作方式与 `CBC` 相同。它使用 `IV`，并采用链接机制。

#### 输出反馈模式

在输出反馈（`OFB`）模式下，`DES` 的操作方式与 `CFB` 模式几乎相同。然而，`DES` 不是将明文与前一个密文分组的加密版本进行 `XOR` 运算，而是将明文与一个种子值进行 `XOR` 运算。对于第一个加密分组，使用初始化向量来创建种子值。未来的种子值通过在前一个种子值上运行 `DES` 算法得出。`OFB` 模式的主要优势是没有链接功能，且传输错误不会传播以影响未来分组的解密。

#### 计数器模式

在计数器（`CTR`）模式下运行的 `DES` 使用类似于 `CFB` 和 `OFB` 模式的流密码。然而，它不是从前一个种子值的结果中创建每次加密/解密操作的种子值，而是使用一个简单的计数器，每次操作递增一次。与 `OFB` 模式一样，错误不会在 `CTR` 模式中传播。

### 三重 DES

如前几节所述，面对现代密码分析技术和超级计算能力，数据加密标准（`DES`）的 56 位密钥不再被认为足够安全。然而，`DES` 的一个改进版本——三重 DES（`3DES`）——使用相同的算法产生更安全的加密。

`3DES` 有四个版本。第一个版本仅使用三个不同的密钥：`K[1]`、`K[2]` 和 `K[3]` 对明文加密三次。它被称为 `DES-EEE3` 模式（`E` 表示有三次加密操作，数字 3 表示使用三个不同的密钥）。`DES-EEE3` 可用以下符号表示，其中 `E(K,P)` 表示用密钥 `K` 加密明文 `P`：

```
E(K1,E(K2,E(K3,P)))
```

`DES-EEE3` 的有效密钥长度为 168 位。
