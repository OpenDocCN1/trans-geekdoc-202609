
# 高带宽数字内容保护 (HDCP)

为通过数字连接（包括 HDMI、DisplayPort 和 DVI 接口）发送的内容提供 DRM 保护。虽然该技术仍广泛应用于许多实现中，但黑客于 2010 年发布了 HDCP 主密钥，使该保护完全失效。

# 高级访问内容系统 (AACS)

保护存储在蓝光和 HD DVD 媒体上的内容。黑客已演示了检索 AACS 加密密钥并将其发布到互联网上的攻击手段。

行业出版商与黑客之间的“猫鼠游戏”至今仍在继续；媒体公司试图保护其内容，而黑客则寻求持续获取未加密副本的途径。

## 电子书 DRM

或许 DRM 技术最成功的部署领域在于图书和文档出版。如今提供的大多数电子书都采用某种形式的 DRM，这些技术也保护具有 DRM 功能的企业所生产的敏感文档。

Adobe Systems 提供 Adobe 数字体验保护技术 (ADEPT)，为以多种格式销售的电子书提供 DRM 技术。ADEPT 结合使用 AES 技术加密媒体内容和 RSA 加密保护 AES 密钥。除 Amazon Kindle 外，许多电子书阅读器都使用此技术来保护其内容。Amazon 的 Kindle 电子阅读器使用多种格式进行图书分发，每种格式都包含其自身的加密技术。

## 视频游戏 DRM

许多视频游戏实施的 DRM 技术依赖于游戏机使用活动的互联网连接，通过基于云的服务验证游戏许可证。这些技术（如 Ubisoft 的 Uplay）曾通常需要持续的互联网连接以支持游戏运行。如果玩家失去连接，游戏将停止运行。

2010 年 3 月，Uplay 系统遭受拒绝服务攻击，全球 Uplay 启用游戏的玩家均无法玩那些原本运行正常的游戏，因为他们的游戏机无法访问 Uplay 服务器。这引发了公众强烈抗议，Ubisoft 随后取消了“始终在线”要求，转而采用仅需在游戏机上进行初始激活，随后允许无限制使用的 DRM 方案。

## 文档 DRM

尽管 DRM 技术最常见的用途是保护娱乐内容，组织也可使用 DRM 来保护存储在 PDF 文件、办公文档和其他格式中的敏感信息安全。商业 DRM 产品（如 Vitrium 和 FileOpen）使用加密保护源内容，并使组织能够精细控制文档权限。

以下是文档 DRM 解决方案常见的受限权限：

*   阅读文件
*   修改文件内容
*   从文件中移除水印
*   下载/保存文件
*   打印文件
*   对文件内容截屏

DRM 解决方案允许组织在需要时授予这些权限、在不再需要时撤销权限，甚至在指定时间段后自动使权限过期。

# 网络

本章将探讨的密码学最终应用是使用密码算法提供安全网络服务。在以下章节中，我们将简要介绍两种用于保护通信电路的方法。我们还将了解 IPsec 和互联网安全关联与密钥管理协议 (ISAKMP)，以及无线网络安全相关的一些问题。

## 电路加密

安全管理员使用两种加密技术来保护网络上传输的数据：

*   **链路加密** 通过使用硬件解决方案或软件解决方案在两点之间创建安全隧道，加密进入隧道一端的所有流量并在另一端解密所有流量，从而保护整个通信电路。例如，通过数据电路连接的两个办公室的公司可能会使用链路加密来防范位于两办公室中间位置的攻击者进行监控。

*   **端到端加密** 保护双方（例如客户端和服务器）之间的通信，独立于链路加密执行。端到端加密的一个例子是使用 TLS 保护用户与 Web 服务器之间的通信。这可以防范可能监控加密链路安全一侧流量或非加密链路上传输流量的入侵者。

链路加密与端到端加密的关键区别在于：在链路加密中，包括报头、报尾、地址和路由数据在内的所有数据也会被加密。因此，每个数据包必须在每一跳进行解密以便正确路由到下一跳，然后再重新加密后才能继续发送，这会降低路由速度。端到端加密不加密报头、报尾、地址和路由数据，因此点-to-point 传输更快，但更容易受到嗅探器和窃听者的攻击。

当加密发生在 OSI 模型的高层时，通常是端到端加密；如果加密在 OSI 模型的低层进行，通常是链路加密。

安全外壳协议 (SSH) 是端到端加密技术的一个很好的例子。这套程序为常见的互联网应用程序（如文件传输协议 (FTP)、Telnet 和 rlogin）提供了加密替代方案。SSH 实际上有两个版本。SSH1（现已被认为不安全）支持数据加密标准 (DES)、三重 DES (3DES)、国际数据加密算法 (IDEA) 和 Blowfish 算法。SSH2 取消了对 DES 和 IDEA 的支持，但增加了对其他多种算法的支持。

## IPsec

目前有多种安全架构在使用，每种都旨在解决不同环境中的安全问题。支持安全通信的一种架构是互联网协议安全 (IPsec) 标准。IPsec 是互联网工程任务组 (IETF) 制定的标准架构，用于建立安全通道以在两个实体之间交换信息。

通过 IPsec 通信的实体可以是两个系统、两个路由器、两个网关，或任意实体组合。虽然通常用于连接两个网络，但 IPsec 也可用于连接单个计算机，例如服务器和工作站或一对工作站（可能是发送方和接收方）。IPsec 并未规定所有实现细节，而是一个开放的模块化框架，允许多个制造商和软件开发商开发能与其他供应商产品良好协作的 IPsec 解决方案。

IPsec 使用公钥密码学提供加密、访问控制、不可抵赖性和消息认证，均基于基于 IP 的协议。IPsec 的主要用途是虚拟专用网络 (VPN)，因此 IPsec 可以在传输模式或隧道模式下运行。IPsec 通常与第 2 层隧道协议 (L2TP) 配对使用，即 L2TP/IPsec。

IP 安全 (IPsec) 协议为安全网络通信提供了完整的基础设施。IPsec 已获得广泛认可，现已在许多商业操作系统中开箱即用。IPsec 依赖安全关联，主要包含两个组件：

*   **认证头 (AH)** 提供消息完整性和不可抵赖性保证。AH 还提供认证和访问控制，并防止重放攻击。

*   **封装安全载荷 (ESP)** 提供数据包内容的机密性和完整性。它提供加密和有限的认证，并防止重放攻击。
