
# 基于 TPM 的全盘加密

当使用基于 TPM 的全盘加密时，用户/操作员必须向计算机提供密码或物理通用串行总线 (USB) 令牌设备，以进行身份验证并允许 TPM 芯片将硬盘加密密钥释放到内存中。虽然这看起来与软件实现相似，但关键区别在于：如果硬盘从其原始系统中移除，则无法解密。只有配合原始的 TPM 芯片，才能解密并访问加密数据。而对于仅靠软件的硬盘加密，硬盘可以移动到另一台计算机上，没有任何访问或使用限制。

# 硬件安全模块 (HSM)

`硬件安全模块 (HSM)` 是一种密码处理器，用于管理/存储数字加密密钥、加速加密操作、支持更快的数字签名并改进身份验证。HSM 通常是一个附加适配器或外设，也可以是一个传输控制协议/互联网协议 (TCP/IP) 网络设备。HSM 包含防篡改保护，即使攻击者获得了物理访问权限，也能防止其被滥用。TPM 只是 HSM 的一个例子。

HSM 为大型（2,048+ 位）非对称加密计算提供加速解决方案，并为密钥存储提供安全保管库。许多证书颁发机构系统使用 HSM 存储证书；ATM 和 POS 银行终端通常采用专有 HSM；硬件 SSL 加速器可包含 HSM 支持；域名系统安全扩展 (DNSSEC) 兼容的域名系统 (DNS) 服务器使用 HSM 进行密钥和区域文件存储。

## 接口

`受限或限制性接口` 在应用程序内实现，根据用户的权限限制其能做什么或看到什么。拥有完全权限的用户可以访问应用程序的所有功能。受限权限的用户只有有限的访问权。

应用程序使用不同的方法来限制界面。一种常见方法是，如果用户没有使用某功能的权限，则隐藏该功能。命令可能通过菜单或右键单击项目提供给管理员，但如果普通用户没有权限，该命令将不显示。其他时候，命令会显示但变灰或禁用。普通用户可以看到它，但无法使用它。

受限接口的目的是限制或约束授权和未授权用户的行为。使用此类接口是克拉克-威尔逊安全模型的一种实际实现。

## 容错

`容错` 是指系统在发生故障时仍能继续运行的能力。通过添加冗余组件（如廉价冗余磁盘阵列 (RAID) 阵列中的额外磁盘，或故障转移集群配置中的额外服务器）来实现容错。容错是安全设计的基本要素。它也被视为避免单点故障和实施冗余的一部分。有关容错、冗余服务器、RAID 和故障转移解决方案的更多详细信息，请参阅第 18 章“灾难恢复规划”。

# 摘要

安全系统不仅仅是组装而成的；它们是为支持安全而设计的。必须保证安全的系统，将根据其支持和强制执行安全策略的能力进行评判。评估计算机系统有效性的这一过程称为认证。认证过程是对系统满足其设计目标能力的技术评估。一旦系统满意地通过了技术评估，组织的管理层便开始对系统进行正式验收。正式验收过程称为认可。

整个认证和认可过程依赖于标准评估准则。存在多种用于评估计算机安全系统的准则。最早的 TCSEC 由美国国防部开发。TCSEC 也称为《橙皮书》，提供了评估系统安全组件功能性和保证性的准则。ITSEC 是 TCSEC 准则的替代方案，在欧洲国家使用更多。2005 年，TCSEC 被通用准则取代。无论使用哪种准则，评估过程都包括审查每个安全控制措施对安全策略的合规性。系统强制主体对客体访问的良好行为程度越高，安全等级就越高。

在设计安全系统时，创建一个安全模型来表示系统将用于实施安全策略的方法，这通常很有帮助。本章讨论了几种安全模型。贝尔-拉帕杜拉模型仅支持数据机密性。它是为军事设计的，满足军事关注点。比巴模型和克拉克-威尔逊模型以不同方式解决数据完整性问题。这些模型在为商业应用设计安全基础设施时，常被用作基础之一。

所有这些理解必须最终汇聚为一种有效的系统安全实施，体现在预防性、检测性和纠正性控制方面。这就是为什么你还必须了解访问控制模型及其功能。这包括状态机模型、贝尔-拉帕杜拉、比巴、克拉克-威尔逊、信息流模型、非干扰模型、获取-授予模型、访问控制矩阵模型以及布鲁尔-纳什模型。

# 考试要点

**了解每种访问控制模型的细节。** 了解访问控制模型及其功能。状态机模型确保主体访问客体的所有实例都是安全的。信息流模型旨在防止未经授权、不安全或受限的信息流。非干扰模型防止一个主体的行为影响系统状态或另一个主体的行为。获取-授予模型规定了权限如何从一个主体传递给另一个主体，或从主体传递给客体。访问控制矩阵是一个主体和客体的表格，指示每个主体可以在每个客体上执行的动作或功能。贝尔-拉帕杜拉模型中的主体具有许可级别，仅允许其访问具有相应分类级别的客体。这强制执行了机密性。比巴模型阻止较低安全级别的主体写入较高安全级别的客体。克拉克-威尔逊是一种完整性模型，依靠审计来确保未授权主体无法访问客体，且授权用户正确访问客体。比巴和克拉克-威尔逊强制执行完整性。戈根-梅塞格尔和萨瑟兰关注完整性。格雷厄姆-德宁侧重于主体和客体的安全创建和删除。

**了解认证和认可的定义。** 认证是对计算机系统的每个部分进行技术评估，以评估其与安全标准的一致性。认可是指定机构正式接受经过认证的配置的过程。

**能够描述开放系统和封闭系统。** 开放系统是使用行业标准设计的，通常易于与其他开放系统集成。封闭系统通常是专有硬件和/或软件。其规范通常不公开，且通常较难与其他系统集成。

**了解限制、边界和隔离。** 限制将进程限制在只能读取和写入特定内存位置。边界是进程在读取或写入时不能超过的内存限制。隔离是进程在通过内存边界进行限制时运行的模式。

**能够从访问角度定义 `对象` 和 `主体`。** 主体是发出请求以访问资源的用户或进程。客体是用户或进程想要访问的资源。
