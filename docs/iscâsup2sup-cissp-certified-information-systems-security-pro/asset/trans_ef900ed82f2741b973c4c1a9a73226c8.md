
安全性始终在变化。因此，任何已实施的安全解决方案都需要随着时间的推移进行更新和变更。如果所选对策未提供持续改进路径，则应将其替换为提供可扩展安全性改进的对策。

## 风险框架

`风险框架` 是关于如何评估、解决和监控风险的指南或配方。CISSP 考试引用的风险框架的主要示例是 NIST 在特别出版物 800-37 ([http://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-37r1.pdf](http://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-37r1.pdf)) 中定义的框架。我们鼓励您完整阅读该出版物，但以下是与 CISSP 相关的几段摘录：

> 本出版物提供了将 `风险管理框架 (RMF)` 应用于联邦信息系统的指南。六步 RMF 包括安全分类、安全控制选择、安全控制实施、安全控制评估、信息系统授权和安全控制监控。RMF 通过实施稳健的持续监控流程，推广近实时风险管理和持续信息系统授权的概念，为高级领导提供必要信息，以便就支持其核心任务和业务职能的组织信息系统做出具有成本效益、基于风险的决策，并将信息安全集成到企业架构和系统开发生命周期 (SDLC) 中。在企业内应用 RMF 通过风险执行（职能）将信息系统层面的风险管理流程与组织层面的风险管理流程联系起来，并确立了在组织信息系统中部署并由这些系统继承（即通用控制）的安全控制的责任和问责制。RMF 具有以下特征：
>
> *   通过实施稳健的持续监控流程，推广近实时风险管理和持续信息系统授权的概念；
> *   鼓励使用自动化为高级领导提供必要信息，以便就支持其核心任务和业务职能的组织信息系统做出具有成本效益、基于风险的决策；
> *   将信息安全集成到企业架构和 SDLC 中；
> *   强调安全控制的选择、实施、评估和监控，以及信息系统的授权；
> *   通过风险执行（职能）将信息系统层面的风险管理流程与组织层面的风险管理流程联系起来；以及
> *   确立对部署在组织信息系统中并由这些系统继承（即通用控制）的安全控制的责任和问责制
>
> RMF 步骤包括 [(参见图 2.7)]：
>
> *   **分类** 信息系统以及由该系统处理、存储和传输的信息，依据为影响分析。
> *   **选择** 信息系统的一组初始基线安全控制，依据为安全分类；根据组织风险评估和本地条件，根据需要调整和补充安全控制基线。
> *   **实施** 安全控制，并描述控制如何在信息系统及其运行环境中采用。
> *   **评估** 安全控制，使用适当的评估程序确定控制实施的正确程度、是否按预期运行，以及是否产生了满足系统安全要求方面的预期结果。
> *   **授权** 信息系统运行，依据为对组织运营和资产、个人、其他组织以及国家因信息系统运行而产生的风险的判断，并决定该风险是可接受的。
> *   **监控** 信息系统中的安全控制，持续进行，包括评估控制有效性、记录系统或其运行环境的变更、对相关变更进行安全影响分析，并向指定的组织官员报告系统的安全状态。
>
> ***[源自 NIST SP 800-37]***

## 建立并维护安全意识、教育和培训计划

安全解决方案的成功实施需要改变用户行为。这些变化主要包含为遵守安全策略强制规定的标准、指南和程序而对正常工作活动进行的调整。`行为矫正` 涉及用户一定程度的学习。为了开发和管理安全教育、培训和意识，必须明确确定所有相关的知识传递项目，并设计演示、接触、协同和实施计划。

安全培训的前提是 `意识`。建立意识的目标是将安全置于首要位置，使其成为用户公认的实体。意识在整个组织中建立了安全理解的通用基线或基础，重点关注所有员工必须理解和领会的与安全相关的关键或基本主题和问题。意识的建立不仅限于课堂类型的练习，还通过工作环境进行。可以使用许多工具来建立意识，例如海报、通告、时事通讯文章、屏幕保护程序、T 恤、管理层的动员讲话、公告、演示、鼠标垫、办公用品和备忘录，以及传统的讲师授课培训课程。

意识建立了安全理解的最低标准共同分母或基础。所有人员都应充分了解其安全责任和义务。他们应接受培训，知道该做什么和不该做什么。
