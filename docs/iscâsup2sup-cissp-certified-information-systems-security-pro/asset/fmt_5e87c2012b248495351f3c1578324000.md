
# ARP 缓存与广播机制

ARP 使用缓存和广播来执行其操作。将 IP 地址解析为 MAC 地址（或反之）的第一步是检查本地 ARP 缓存。如果所需信息已存在于 ARP 缓存中，则直接使用。此活动有时会被一种称为 **ARP 缓存投毒** 的技术滥用，攻击者会将虚假信息插入 ARP 缓存。如果 ARP 缓存不包含必要信息，则会以广播形式发送 ARP 请求。如果被查询地址的所有者在本地子网中，它可以响应必要信息。如果不在，系统将默认使用其默认网关来传输通信。然后，默认网关（即路由器）需要执行其自己的 ARP 过程。

# 常见应用层协议

在 TCP/IP 模型的应用层（包含 OSI 模型的会话层、表示层和应用层）中存在许多特定于应用程序或服务的协议。了解这些协议及其相关服务端口对于 CISSP 考试很重要：

*   **Telnet**，`TCP` 端口 `23`：这是一个终端仿真网络应用程序，支持远程连接以执行命令和运行应用程序，但不支持文件传输。
*   **文件传输协议 (FTP)**，`TCP` 端口 `20`（被动数据）/ 临时端口（主动数据）和 `21`（控制连接）：这是一个支持文件交换的网络应用程序，需要匿名或特定身份验证。
*   **简单文件传输协议 (TFTP)**，`UDP` 端口 `69`：这是一个支持文件交换的网络应用程序，不需要身份验证。
*   **简单邮件传输协议 (SMTP)**，`TCP` 端口 `25`：这是一种用于将电子邮件从客户端传输到电子邮件服务器，以及从一个电子邮件服务器传输到另一个电子邮件服务器的协议。
*   **邮局协议 (POP3)**，`TCP` 端口 `110`：这是一种用于将电子邮件服务器收件箱中的电子邮件拉取到电子邮件客户端的协议。
*   **互联网消息访问协议 (IMAP)**，`TCP` 端口 `143`：这是一种用于将电子邮件服务器收件箱中的电子邮件拉取到电子邮件客户端的协议。IMAP 比 POP3 更安全，并提供从电子邮件服务器拉取邮件头以及直接在电子邮件服务器上删除消息的功能，而无需先下载到本地客户端。
*   **动态主机配置协议 (DHCP)**，`UDP` 端口 `67` 和 `68`：DHCP 使用端口 `67` 作为服务器上的目标端口以接收客户端通信，使用端口 `68` 作为客户端请求的源端口。它用于在系统启动时分配 TCP/IP 配置设置。DHCP 实现了网络寻址的集中控制。
*   **超文本传输协议 (HTTP)**，`TCP` 端口 `80`：这是用于将网页元素从 Web 服务器传输到 Web 浏览器的协议。
*   **安全套接字层 (SSL)**，`TCP` 端口 `443`（用于 HTTP 加密）：这是一种在传输层运行的类 VPN 安全协议。SSL 最初设计用于支持安全的 Web 通信 (HTTPS)，但能够保护任何应用层协议通信。
*   **行式打印机守护进程 (LPD)**，`TCP` 端口 `515`：这是一种用于打印作业缓存和将打印作业发送到打印机的网络服务。
*   **X Window**，`TCP` 端口 `6000–6063`：这是命令行操作系统的 GUI API。
*   **网络文件系统 (NFS)**，`TCP` 端口 `2049`：这是一种用于支持异构系统间文件共享的网络服务。
*   **简单网络管理协议 (SNMP)**，`UDP` 端口 `161`（`UDP` 端口 `162` 用于 Trap 消息）：这是一种通过从中央监控站轮询监控设备来收集网络健康和状态信息的网络服务。

# 多层协议的影响

从前面几节可以看出，TCP/IP 作为一个协议套件，包含分布在各个协议栈层中的数十个单独协议。因此，TCP/IP 是一个 **多层协议**。TCP/IP 从其多层设计中获得了几项益处，特别是与其封装机制有关。例如，当通过典型网络连接在 Web 服务器和 Web 浏览器之间通信时，`HTTP` 封装在 `TCP` 中，后者又封装在 `IP` 中，后者又封装在 `Ethernet` 中。这可以表示如下：

```
[ Ethernet [ IP [ TCP [ HTTP ] ] ] ]
```

然而，这并不是 TCP/IP 封装支持的全部。还可以添加额外的封装层。例如，向通信添加 `SSL/TLS` 加密会在 `HTTP` 和 `TCP` 之间插入一个新的封装：

```
[ Ethernet [ IP [ TCP [ SSL [ HTTP ] ] ] ] ]
```

这反过来还可以进一步用网络层加密（如 `IPSec`）进行封装：

```
[ Ethernet [ IPSec [ IP [ TCP [ SSL [ HTTP ] ] ] ] ] ]
```

然而，封装并不总是用于良性目的。有许多隐蔽信道通信机制利用封装来隐藏或隔离另一个授权协议内部的未授权协议。例如，如果网络阻止使用 `FTP` 但允许 `HTTP`，则可以使用 `HTTP Tunnel` 等工具绕过此限制。这可能导致如下的封装结构：

```
[ Ethernet [ IP [ TCP [ HTTP [ FTP ] ] ] ] ]
```

通常，`HTTP` 承载其自身的 Web 相关负载，但使用 `HTTP Tunnel` 工具时，标准负载会被替换为替代协议。这种虚假封装甚至可能发生在协议栈的较低层。例如，`ICMP` 通常用于网络健康测试，而非一般通信。然而，使用 `Loki` 等实用程序，`ICMP` 可转换为隧道协议以支持 `TCP` 通信。`Loki` 的封装结构如下：

```
[ Ethernet [ IP [ ICMP [ TCP [ HTTP ] ] ] ] ]
```

由无界封装支持引起的另一个关注领域是跨虚拟局域网 (VLAN) 跳转的能力。VLAN 是通过标签逻辑分离的网段。这种攻击称为 **VLAN 跳转**，通过创建双重封装的 **IEEE 802.1Q VLAN 标签** 来执行：

```
[ Ethernet [ VLAN1 [ VLAN2 [ IP [ TCP [ HTTP ] ] ] ] ] ]
```

通过这种双重封装，第一个遇到的交换机将剥离第一个 VLAN 标签，然后下一个交换机会被内部的 VLAN 标签欺骗，将流量移动到另一个 VLAN。

多层�提供下列益处：

*   可以在高层使用各种协议。
*   可以在各层加入加密。
*   支持复杂网络结构中的灵活性和弹性。

多层协议有几个缺点：

*   允许隐蔽信道。
*   过滤器可被绕过。
*   逻辑施加的网络段边界可能被跨越。

# TCP/IP 漏洞

TCP/IP 的漏洞众多。各种操作系统中实现不当的 TCP/IP 协议栈容易受到缓冲区溢出、`SYN` 洪水攻击、各种拒绝服务 (DoS) 攻击、碎片攻击、超大数据包攻击、欺骗攻击、中间人攻击、劫持攻击和编码错误攻击。

TCP/IP（以及大多数协议）还容易受到通过监控或嗅探进行的被动攻击。网络监控是监控流量模式以获取网络信息的行为。数据包嗅探是从网络捕获数据包，希望从数据包内容中提取有用信息的行为。有效的数据包嗅探器可以提取用户名、密码、电子邮件地址、加密密钥、信用卡号、IP 地址、系统名称等。

数据包嗅探和其他攻击将在第 13 章中详细讨论。
