

# 安全架构与设计

## 分层

通过对进程进行`layering`（分层），你可以实现一种类似于用于操作模式的环模型（本章前面已讨论过）的结构，并将其应用于每个操作系统进程。它将进程中最敏感的功能置于核心位置，周围环绕着一系列同心圆，圆环越大，敏感度相应越低（采用略有不同的方法，这有时也用上层和下层来解释，即当从下层向上层攀爬时，安全性和特权逐渐降低）。在操作系统架构的讨论中，受保护环的概念很常见，但并非唯一。还有其他方式用层级而非环来表示相同的基本思想。在这样的系统中，最高层级拥有最高特权，而最低层级特权最低。

层间通信仅通过定义明确的特定接口进行，以提供必要的安全性。来自外层（敏感度较低）的所有入站请求，在被允许继续之前，都要经过严格的身份验证和授权检查（如果检查失败则被拒绝）。将分层用于安全，类似于使用安全域和基于格的安全模型，即某些主体和客体上的安全性和访问控制与特定层和特权相关联，并且随着从外层向内层移动，访问权限增加。

事实上，独立的层只能通过旨在维护系统安全性和完整性的特定接口相互通信。尽管安全性较低的外层依赖于更安全的内层的服务和数据，但它们只知道如何与这些层进行接口交互，而不知晓这些内层的内部结构、特性或其他细节。为维护层的完整性，内层既不知晓也不依赖外层。无论任意两层之间存在何种安全关系，双方均无法篡改对方（从而使每一层都免受任何其他层的篡改）。最后，外层无法违反或覆盖内层强制执行的任何安全策略。

## 抽象

`Abstraction`（抽象）是被称为`object-oriented programming`（面向对象编程）领域背后的基本原则之一。它是“黑盒”原则，即对象（或操作系统组件）的使用者不必知道对象如何工作的细节；他们只需知道使用对象的正确语法以及将返回的数据类型（即如何发送输入和接收输出）。这非常类似于对数据或服务的中介访问，例如用户模式应用程序使用系统调用来请求管理员模式的服务或数据（此类请求可能会根据请求者的凭证和权限被授予或拒绝），而不是获得直接的、非中介的访问。

抽象应用于安全的另一种方式是引入对象组，有时称为`classes`（类），即将访问控制和操作权限分配给对象组，而非逐个对象分配。这种方法允许安全管理员轻松定义和命名组（名称通常与工作角色或职责相关），并有助于简化权限和特权的管理（当你将一个对象添加到一个类时，你就赋予了它权利和特权，而不必单独管理每个对象的权利和特权）。

## 数据隐藏

`Data hiding`（数据隐藏）是多级安全系统的一项重要特征。它确保存在于某一安全级别的数据对运行在不同安全级别的进程不可见。数据隐藏背后的关键概念是：确保那些无需知晓在某一级别访问和处理数据的细节的人，无法通过隐蔽或非法手段获知或观察这些细节。从安全角度来看，数据隐藏依赖于将对象放置在与主体所处的安全容器不同的安全容器中，以向那些无需知情者隐藏对象细节。

## 进程隔离

`Process isolation`（进程隔离）要求操作系统为每个进程的指令和数据提供独立的内存空间。它还要求操作系统强制执行这些边界，防止一个进程读取或写入属于另一个进程的数据。使用此技术有两大优势：

*   它防止未经授权的数据访问。进程隔离是多级安全模式系统的基本要求之一。
*   它保护进程的完整性。没有此类控制，设计不良的进程可能会失控，并将数据写入分配给其他进程的内存空间，导致整个系统变得不稳定，而不仅仅是影响该失控进程的执行。从更恶意的角度来看，进程可能会尝试（甚至可能成功）读取或写入其作用域之外的内存空间，从而侵入或攻击其他进程。

许多现代操作系统通过在每用户或每进程的基础上实现虚拟机来满足进程隔离的需求。虚拟机为用户或进程呈现一个处理环境——包括内存、地址空间和其他关键系统资源及服务——使该用户或进程表现得就像拥有对整台计算机的唯一、独占访问权一样。这使得每个用户或进程能够独立运行，而无需考虑可能同时在同一台机器上活动的其他用户或进程。作为操作系统提供的对系统中介访问的一部分，它将用户模式下的虚拟资源和访问进行映射，以便它们使用监督模式调用来访问相应的真实资源。这不仅使程序员的工作更轻松，还保护了各个用户和进程免受彼此干扰。

## 硬件分段

`Hardware segmentation`（硬件分段）在目的上类似于进程隔离——它防止访问属于不同进程/安全级别的信息。主要区别在于，硬件分段通过使用物理硬件控制来强制执行这些要求，而不是由操作系统施加的逻辑进程隔离控制。此类实现很少见，通常仅限于国家安全实现，在这些场景中，额外的成本和复杂性会被所涉及信息的敏感性以及未经授权访问或泄露固有的风险所抵消。

## 安全策略与计算机架构

正如安全策略指导组织的日常安全操作、流程和程序一样，它在系统设计和实施中也发挥着重要作用。无论系统是完全基于硬件、完全基于软件，还是两者的结合，这一点都同样适用。在这种情况下，安全策略的作用是指导和规范特定系统的设计、开发、实施、测试和维护。因此，这种安全策略紧密聚焦于单一的实施工作。（尽管它可能改编自其他类似的工作，但应尽可能准确、完整地反映目标系统。）
