
## 基本流程

所有这些机制的基本流程都涉及场景的创建。**场景** 是对单一主要威胁的书面描述。该描述侧重于威胁如何被引发，以及其发生可能对组织、IT 基础设施和特定资产产生什么影响。通常，场景限制在一页文本以内，以保持其可管理性。对于每个场景，都会描述一种或多种防护措施，这些措施可以完全或部分地防范场景中讨论的主要威胁。分析参与者随后为场景分配威胁级别、损失潜力以及每种防护措施的优势。这些分配可以非常简单——例如高、中、低，或基本的 1 到 10 数字等级——也可以是详细的论述式回答。所有参与者的回答随后被汇编成一份单一报告，提交给高层管理人员。有关参考评级和级别的示例，请参阅美国国家标准与技术研究院 (NIST) 特别出版物 (SP) 800-30 中的表 3-6 和表 3-7：

[http://csrc.nist.gov/publications/nistpubs/800-30/sp800-30.pdf](http://csrc.nist.gov/publications/nistpubs/800-30/sp800-30.pdf)

定性风险分析的有效性和效度会随着参与评估的人员数量和多样性的增加而提高。只要可能，应包含组织层级中每个层面的一名或多名人员，从高层管理人员到最终用户。同样重要的是，要包含每个主要部门、处、办公室或分支机构的横截面人员。

### Delphi 技术

Delphi 技术可能是前面列表中唯一一种不能立即被识别和理解的机制。**Delphi 技术** 只是一种匿名的反馈与响应过程，用于使群体达成匿名共识。其主要目的是引出所有参与者诚实且不受影响的回答。参与者通常聚集在一个会议室中。针对每次反馈请求，每位参与者匿名在纸上写下他们的回答。结果被汇总并呈现给小组进行评估。该过程重复进行，直到达成共识。

定量和定性风险分析机制都能提供有用的结果。然而，每种技术都涉及评估同一组资产和风险的独特方法。审慎的应有注意义务要求同时采用这两种方法。[表 2.2](#c02.xhtml#table2-2) 描述了这两种系统的优缺点。

**表 2.2 定量与定性风险分析的比较**

| 特征 | 定性 | 定量 |
| :--- | :--- | :--- |

| 使用成本/效益分析 | 否 | 是 |

## 风险响应

风险分析的结果有很多：

*   所有资产的完整详细估值
*   详尽的威胁和风险清单、发生率以及实现时的损失程度
*   特定威胁的防护措施和对策清单，标识其有效性和 ALE
*   每种防护措施的成本/效益分析

这些信息对于管理层做出关于防护措施实施和安全策略变更的明智、理智的决策至关重要。

一旦风险分析完成，管理层必须处理每个特定风险。对风险有几种可能的响应：

*   降低或缓解
*   转移或分担
*   接受
*   威慑
*   规避
*   拒绝或忽略

您需要了解以下关于可能风险响应的信息：

### 风险缓解

**降低风险**，或 **风险缓解**，是实施防护措施和对策以消除漏洞或阻断威胁。选择最具成本效益或最有益的对策是风险管理的一部分，但不是风险评估的要素。事实上，对策选择是风险评估后或风险分析后的活动。风险缓解的另一种潜在变体是风险规避。通过消除风险原因来规避风险。一个简单的例子是从服务器中移除文件传输协议 (FTP) 以避免 FTP 攻击，一个更大的例子是搬到内陆位置以避免飓风风险。

### 风险转移

**分配风险** 或 **转移风险** 是将风险所代表的损失成本转嫁给另一个实体或组织。购买保险和外包是分配或转移风险的常见形式。

### 风险接受

**接受风险**、风险容忍度或风险接受，是成本/效益分析显示对策成本会超过因风险导致的可能损失成本后的结果。这也意味着管理层已同意在风险实现时承担后果和损失。在大多数情况下，接受风险需要一份清晰的书面声明，说明为何未实施防护措施、谁对该决策负责，以及风险实现时谁将对损失负责，通常以免责函的形式呈现。组织接受风险的决定基于其风险容忍度。这也称为风险容忍度或风险偏好，即组织吸收已实现风险相关损失的能力。

### 风险威慑

**风险威慑** 是实施威慑措施以阻止潜在的安全和策略违规者的过程。示例包括实施审计、安全摄像头、保安、指示标牌、警告横幅、运动探测器、强认证，以及让人知晓组织愿意与当局合作并起诉参与网络犯罪的人员。

### 风险规避

**风险规避** 是选择风险较低的替代方案或活动，而非默认、常见、权宜或廉价的选项。例如，选择飞往目的地而不是开车前往，就是一种风险规避。另一个例子是将企业选址在亚利桑那州而非佛罗里达州，以避免飓风。

### 风险拒绝

对风险的最后一种但不可接受的可能响应是 **拒绝风险** 或 **忽略风险**。否认风险存在并希望它永远不会实现，都不是对风险有效或审慎的应有注意义务响应。

一旦实施了对策，剩余的风险称为剩余风险。**剩余风险** 包含高层管理人员选择不实施防护措施的针对特定资产的威胁。换句话说，剩余风险是管理层选择接受而非缓解的风险。在大多数情况下，剩余风险的存在表明成本/效益分析显示可用的防护措施不是具有成本效益的威慑手段。

**总风险** 是组织在未实施任何防护措施时将面临的风险总量。总风险的公式如下：

```
威胁 * 漏洞 * 资产价值 = 总风险
```
(注意，此处的 `*` 并不意味着乘法，而是组合函数；这不是一个真正的数学公式。) 总风险与剩余风险之间的差额称为控制差距。控制差距是通过实施防护措施所降低的风险量。剩余风险的公式如下：

```
总风险 - 控制差距 = 剩余风险
```
