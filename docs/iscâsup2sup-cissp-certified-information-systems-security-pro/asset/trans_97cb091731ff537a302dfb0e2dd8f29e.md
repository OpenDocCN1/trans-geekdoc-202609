

# 威胁

任何可能导致组织或特定资产产生不良或意外结果的潜在事件都是*威胁*。威胁是指任何可能导致资产损坏、破坏、篡改、丢失或泄露，或者可能阻断访问或妨碍资产维护的行为或不作为。威胁可以是大是小，导致的后果也可以是大是小。它们可以是有意的，也可以是意外的。它们可能源于人员、组织、硬件、网络、结构或自然。威胁主体会有意地利用漏洞。威胁主体通常是人员，但也可能是程序、硬件或系统。威胁事件是对漏洞的意外和有意利用。它们也可以是自然的或人为的。威胁事件包括火灾、地震、洪水、系统故障、人为错误（由于缺乏培训或疏忽）和停电。

# 漏洞

资产中的弱点，或防护措施/对策的缺失或薄弱，即为*漏洞*。

换句话说，漏洞是 IT 基础设施或组织任何其他方面存在的缺陷、漏洞、疏忽、错误、局限性、脆弱性或易感性。如果漏洞被利用，可能会导致资产损失或损坏。

# 暴露

*暴露*是指因威胁而易遭受资产损失；存在漏洞被威胁主体或事件利用的可能性。暴露并不意味着已实现的威胁（导致损失的事件）正在实际发生（对已实现威胁的暴露称为经历暴露）。它只是意味着如果存在漏洞且有能利用它的威胁，就存在威胁事件或潜在暴露发生的可能性。理解暴露的另一种方式是回答“最坏的结果会是什么？”这个问题。你并不是陈述危害已经发生或必将发生，而只是说明存在危害的可能性，以及这种危害可能有多广泛或严重。定量风险分析中的暴露因子（EF）值即源于此概念。

# 风险

*风险*是威胁利用漏洞对资产造成危害的可能性或几率。它是对概率、可能性或机会的评估。威胁事件发生的可能性越大，风险就越高。每一个暴露实例都是一种风险。用公式表示时，风险可定义为：

```
risk = threat * vulnerability
```

因此，减少威胁主体或漏洞中的任何一个都会直接导致风险降低。

当风险成为现实时，*威胁主体*、*威胁行为体*或*威胁事件*已利用漏洞，导致一个或多个资产遭受损害或泄露。安全的全部目的是通过消除漏洞、阻断威胁主体和威胁事件对资产的危害，防止风险成为现实。作为一种风险管理工具，安全是防护措施的实施。

# 防护措施

*防护措施*、*安全控制*或*对策*是指任何能消除或减少漏洞、或针对一个或多个特定威胁提供保护的事物。防护措施可以是安装软件补丁、进行配置变更、雇佣安保人员、变更基础设施、修改流程、完善安全策略、更有效地培训人员、给周界围栏通电、安装照明等。它是指组织内任何能通过消除或减轻威胁或漏洞来降低风险的行动或产品。防护措施是缓解或消除风险的唯一手段。重要的是要记住，防护措施、安全控制或对策不一定非要购买新产品；重新配置现有元素，甚至从基础设施中移除元素，也是有效的防护措施。

# 攻击

*攻击*是威胁主体对漏洞的利用。换句话说，攻击是指任何试图利用组织安全基础设施漏洞以造成资产损坏、丢失或泄露的有意行为。攻击也可以被视为任何违反或未能遵守组织安全策略的行为。

# 违规

*违规*是指安全机制被威胁主体绕过或挫败的事件。当违规与攻击相结合时，可能导致渗透或入侵。渗透是指威胁主体通过绕过安全控制获得了对组织基础设施的访问权限，并能直接威胁资产的状态。

资产、威胁、漏洞、暴露、风险和防护措施这些要素是相互关联的，如[图 2.4](#c02.xhtml#figure2-4)所示。威胁利用漏洞，从而导致暴露。暴露即风险，风险通过防护措施来缓解。防护措施保护受威胁危害的资产。

## 识别威胁和漏洞

风险管理的一个基本部分是识别和检查威胁。这涉及为组织已识别的资产创建一份详尽的所有可能威胁清单。该清单应包括威胁主体和威胁事件。重要的是要记住，威胁可能来自任何地方。IT 威胁不局限于 IT 来源。在编制威胁清单时，请务必考虑以下因素：

*   病毒
*   级联错误（一系列不断升级的错误）和依赖性故障（由依赖不存在的事件或项目引起）
*   授权用户的犯罪活动（间谍活动、知识产权窃取、挪用公款等）
*   移动（振动、震动等）
*   故意攻击
*   重组
*   授权用户患病或流行病
*   恶意黑客
*   不满的员工
*   用户错误
*   自然灾害（地震、洪水、火灾、火山、飓风、龙卷风、海啸等）
*   物理损坏（挤压、抛射物、电缆切断等）
*   数据、资源或服务的滥用
*   数据分类或安全策略的变更或妥协
*   政府、政治或军事的入侵或限制
*   处理错误、缓冲区溢出
*   人员特权滥用
*   温度极端
*   能量异常（静电、电磁脉冲、射频 [RF]、断电、电压浪涌等）
*   数据丢失
*   信息战
*   破产或业务活动的变更/中断
*   编码/编程错误
*   入侵者（物理和逻辑）
*   环境因素（气体、液体、生物体的存在等）
*   设备故障
*   物理盗窃
*   社会工程学

在大多数情况下，风险评估和分析应由团队而非单个个人执行。此外，团队成员应来自组织内的不同部门。通常不要求所有团队成员都是安全专业人员，甚至不要求是网络/系统管理员。基于组织人口统计特征的团队多样性将有助于详尽地识别和应对所有可能的威胁和风险。

## 风险评估/分析

风险管理/分析主要是高层管理人员的工作。他们有责任通过定义工作的范围和目的，发起并支持风险分析和评估。执行风险分析的实际过程通常委托给安全专业人员或评估团队。然而，所有风险评估、结果、决策和结果都必须被高层管理人员理解并批准，作为提供审慎应有照顾的一个要素。
