

## 5. 计划并实施变更

变更会被安排计划，以便以对系统和系统客户影响最小的方式实施。这可能要求在非值班时间或非高峰时段安排变更。

## 6. 记录变更

最后一步是记录变更，以确保所有相关方知情。这通常需要更新配置管理文档。如果发生无关灾难，要求管理员重建系统，变更管理文档将为他们提供变更信息。这确保他们能将系统恢复到变更前的状态。

有时可能需要紧急变更。例如，如果攻击或恶意软件感染导致一个或多个系统瘫痪，管理员可能需要对系统或网络进行变更以遏制事件。在这种情况下，管理员仍需记录这些变更。这确保变更审查委员会可以审查变更的潜在问题。此外，记录紧急变更可确保受影响的系统在需要重建时包含新配置。

当强制执行变更管理流程时，它会为系统的所有变更创建文档。如果人员需要撤销变更，这提供了信息追踪。如果人员需要在其他系统上实施相同的变更，文档也提供了可遵循的路线图或程序。

变更管理控制是 ISO 通用准则中某些安全保证要求（SAR）的强制性要素。然而，许多不要求遵守 ISO 通用准则的组织也实施了变更管理控制。它通过防止导致意外损失的未授权变更，提高了环境的安全性。

## 版本控制

版本控制通常指软件配置管理中使用的版本控制。标签或编号系统用于区分跨多台机器或单台机器在不同时间点的不同软件集和配置。例如，应用程序的第一个版本可能标记为 `1.0`。第一个小版本更新将标记为 `1.1`，第一个大版本更新将是 `2.0`。这有助于跟踪已部署软件随时间发生的变更。

虽然大多数成熟的软件开发人员认识到版本控制和修订控制在应用程序中的重要性，但许多新晋 Web 开发人员并不认识到其重要性。这些 Web 开发人员学习了一些用于创建很棒网站的优秀技能，但并不总是认识到底层原则（如版本控制）的重要性。如果他们不通过某种版本控制系统来控制变更，可能会实施一个实际上导致网站瘫痪的变更。

## 配置文档

配置文档标识系统的当前配置。它标识系统负责人和系统用途，并列出应用于基线的所有变更。多年前，许多组织使用简单的纸质笔记本记录服务器的此类信息，但如今将这些信息存储在文件或数据库中要普遍得多。当然，将文档存储在数据文件中的挑战在于，在停机期间可能无法访问。

# 管理补丁与减少漏洞

补丁管理和漏洞管理流程协同工作，帮助保护组织免受新兴威胁的侵害。操作系统和应用程序中会定期发现 Bug 和安全漏洞。发现后，供应商会编写并测试补丁以消除漏洞。补丁管理确保应用适当的补丁，漏洞管理有助于验证系统不易受已知威胁的影响。

## 管理的系统

值得强调的是，补丁和漏洞管理不仅适用于工作站和服务器。它也适用于任何带有操作系统的计算设备。网络基础设施系统（如路由器、交换机、防火墙、设备（如统一威胁管理设备）和打印机）都包含某种类型的操作系统。有些基于 Cisco，有些基于 Microsoft，还有些基于 Linux。

嵌入式系统是指具有中央处理单元（CPU）、运行操作系统，并拥有一个或多个旨在执行一个或多个功能的应用程序的设备。示例包括摄像头系统、智能电视、家用电器（如防盗报警系统、无线恒温器和冰箱）、汽车、医疗设备等。这些设备有时被称为物联网（IoT）。

这些设备可能存在需要补丁的漏洞。例如，2016 年底针对域名系统（DNS）服务器的大规模*分布式拒绝服务*攻击，通过阻止用户访问数十个网站，实际上导致了互联网瘫痪。据报道，攻击者使用 Mirai 恶意软件控制物联网设备（如互联网协议 [IP] 摄像头、婴儿监视器和打印机）并将它们加入*僵尸网络*。数千万台设备向 DNS 服务器发送 DNS 查找请求，有效地使其过载。显然，这些设备应打补丁以防止此类攻击重演，但许多制造商、组织和所有者并不给物联网设备打补丁。更糟的是，许多供应商甚至不发布补丁。

最后，如果组织允许员工在组织网络内使用移动设备（如智能手机和平板电脑），这些设备也应纳入管理。

## 补丁管理

补丁是一个统称，指为修正 Bug 或漏洞或改进现有软件性能而编写的任何类型的代码。软件可以是操作系统，也可以是应用程序。补丁有时被称为更新、快速修复和热修复。在安全语境下，管理员主要关注安全补丁，即影响系统漏洞的补丁。

尽管供应商定期编写并发布补丁，但这些补丁只有在应用后才有用。这似乎显而易见，但许多安全事件发生的原因仅仅是组织未实施补丁管理策略。例如，第 14 章讨论了 2017 年对 Equifax 的多次攻击。2017 年 5 月的攻击利用了 Apache Struts Web 应用程序中的一个漏洞，本可以在 2017 年 3 月修补。

一个有效的*补丁管理*计划确保系统通过最新补丁保持最新状态。有效补丁管理计划中的常见步骤如下：

### 评估补丁

当供应商宣布或发布补丁时，管理员会对其进行评估，以确定它们是否适用于其系统。例如，修复配置为域名系统（DNS）服务器的 Unix 系统漏洞的补丁，与运行 Windows 版 DNS 的服务器无关。同样，如果功能未安装，则不需要修复 Windows 系统上运行功能的补丁。

### 测试补丁

只要可能，管理员会在隔离的非生产系统上测试补丁，以确定补丁是否会导致任何不良副作用。最坏的情况是应用补丁后系统将无法启动。例如，补丁偶尔会导致系统开始无限重启循环。它们启动进入停止错误，并不断尝试重启以从错误中恢复。如果测试在单个系统上显示此问题，则仅影响一台系统。然而，如果组织在测试前将补丁应用到一千台计算机，可能会造成灾难性后果。
