##### 常见日志类型

有许多不同类型的日志。以下是 IT 环境中可用的常见日志简要列表。

**安全日志** 安全日志记录对资源（如文件、文件夹、打印机等）的访问。例如，它们可以记录用户何时访问、修改或删除了文件，如前文 [图 17.5](#c17.xhtml#figure17-5) 所示。许多系统会自动记录对关键系统文件的访问，但要求管理员在其他资源上启用审核后才记录访问。例如，管理员可能会为专有数据配置日志记录，但不对网站上发布的公共数据进行记录。

**系统日志** 系统日志记录系统事件，例如系统何时启动或关闭，或服务何时启动或停止。如果攻击者能够关闭系统并使用 CD 或 USB 闪存驱动器重新启动，他们可以在没有任何数据访问记录的情况下窃取系统数据。同样，如果攻击者能够停止监控系统的服务，他们可能会在日志未记录其行为的情况下访问系统。记录系统重启或服务停止时间的日志可以帮助管理员发现潜在的恶意活动。

**应用程序日志** 这些日志记录特定应用程序的信息。应用程序开发人员选择在应用程序日志中记录什么内容。例如，数据库开发人员可以选择记录任何人何时访问特定的数据对象，如表或视图。

**防火墙日志** 防火墙日志可以记录与到达防火墙的任何流量相关的事件。这包括防火墙允许的流量和防火墙阻止的流量。这些日志通常记录关键数据包信息，如源和目标 IP 地址、源和目标端口，但不记录数据包的实际内容。

**代理日志** 代理服务器可以提高用户的互联网访问性能，并能控制用户可以访问的网站。代理日志包括记录详细信息的能力，例如特定用户访问了哪些网站以及在这些网站上花费了多少时间。它们还可以记录用户何时尝试访问已知的禁止网站。

**变更日志** 变更日志记录变更请求、批准以及作为整体变更管理过程一部分的系统实际变更。变更日志可以手动创建，也可以通过内部网页在人员记录与变更相关的活动时创建。变更日志可用于跟踪已批准的变更。它们作为灾难恢复计划的一部分也很有帮助。例如，灾难发生后，管理员和技术人员可以使用变更日志将系统恢复到最后已知状态，包括所有已应用的变更。

日志记录通常是操作系统以及大多数应用程序和服务的原生功能。这使得管理员和技术人员配置系统以记录特定类型的事件变得相对容易。应在任何日志记录计划中包含来自管理员和 root 用户账户等特权账户的事件。这有助于防止恶意内部人员的攻击，并在必要时为起诉记录活动。

##### 保护日志数据

组织内部人员可以使用日志重现事件发生前和发生期间的情况，但前提是日志未被修改。如果攻击者可以修改日志，他们可以抹除自己的活动，从而有效地使数据失去价值。这些文件可能不再包含准确信息，并且可能无法作为起诉攻击者的可采纳证据。考虑到这一点，防止未经授权的访问和未经授权的修改来保护日志文件非常重要。

通常会在中央系统（如 `SIEM`）上存储日志副本以保护它们。即使攻击修改或损坏了原始文件，人员仍可使用副本查看事件。保护日志文件的一种方法是分配权限以限制其访问。

组织通常有严格的政策，强制要求备份日志文件。此外，这些政策还定义了保留时间。例如，组织可能会保留归档日志文件一年、三年或任何其他时长。某些政府法规要求组织无限期保留归档日志。安全控制措施（如将日志设置为只读、分配权限和实施物理安全控制）可保护归档日志免受未经授权的访问和修改。在日志不再需要时销毁它们很重要。

美国国家标准与技术研究院（`NIST`）发布了大量关于 IT 安全的信息，包括*联邦信息处理标准（`FIPS`）出版物*。*联邦信息和信息系统的最低安全要求（`FIPS 200`）* 将以下内容指定为审计数据的最低安全要求：

> 创建、保护和保留信息系统审计记录，程度应足以支持对非法、未经授权或不当的信息系统活动进行监控、分析、调查和报告。

> 确保能将各个信息系统用户的行为唯一地追溯到这些用户，以便让他们对自己的行为负责。

#### 监控的作用

监控为组织提供多种益处，包括增加问责性、协助调查和基本故障排除。以下部分将更深入地描述这些益处。

##### 审计跟踪

*审计跟踪* 是当有关事件和发生情况的信息存储在一个或多个数据库或日志文件中时创建的记录。它们提供系统活动的记录，并可重现安全事件发生前和发生期间的活动。安全专业人员从审计跟踪中提取有关事件的信息，以证明或反驳过错等。审计跟踪允许安全专业人员按正序或逆序检查和追踪事件。这种灵活性在追踪问题、性能问题、攻击、入侵、安全漏洞、编码错误和其他潜在策略违规时很有帮助。

使用审计跟踪是一种被动的侦察型安全控制。它们的威慑作用方式与闭路电视（`CCTV`）或保安相同。如果人员知道他们正被监视且其活动正被记录，他们就不太可能从事非法、未经授权或恶意活动——至少在理论上是这样。有些罪犯过于粗心或无知，导致这并不总是一致适用。然而，越来越多的高级攻击者会花时间定位并删除可能记录其活动的日志。这已成为许多高级持续性威胁的标准做法。

审计跟踪作为起诉罪犯的证据也至关重要。它们提供资源、系统和资产状态的前后对比图景。这反过来有助于确定某项更改或变更是用户、操作系统（`OS`）或软件的行为导致的，还是由其他来源（如硬件故障）导致的。由于审计跟踪中的数据非常有价值，因此确保日志受到保护以防止修改或删除非常重要。
