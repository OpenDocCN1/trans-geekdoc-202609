

# 安全角色与框架

## 安全角色

`security role`（安全角色）是指个人在组织内部安全实施和管理的整体方案中所扮演的角色。安全角色不一定在职位描述中规定，因为它们并不总是截然不同或静态的。熟悉安全角色将有助于在组织内建立通信和支持结构。该结构将实现安全策略的部署和执行。以下六个角色按其在安全环境中出现的逻辑顺序呈现：

### 高级管理者

组织所有者（`senior manager`，高级管理者）角色分配给对组织维护的安全负最终责任、且最应关注其资产保护的人员。高级管理者必须对所有策略问题签署批准。事实上，所有活动必须经高级管理者批准并签署后方可执行。如果高级管理者不授权和支持，就不存在有效的安全策略。高级管理者对安全策略的背书表明组织接受所实施安全的所有权。高级管理者是对安全解决方案的整体成败负责的人员，并负责在为组织建立安全时履行应有的注意义务和尽职调查。

尽管高级管理者对安全负最终责任，但他们很少亲自实施安全解决方案。在大多数情况下，该责任委派给组织内的安全专业人员。

### 安全专业人员

`security professional`（安全专业人员）、`information security (InfoSec) officer`（信息安全官）或 `computer incident response team (CIRT)`（计算机事件响应小组）角色分配给受过培训且经验丰富的网络、系统和安全工程师，他们负责遵循高级管理层授权的指令。安全专业人员对安全负有职能责任，包括编写安全策略并实施它。安全专业人员的角色可被标记为 IS/IT 职能角色。安全专业人员角色通常由一个团队担任，负责根据批准的安全策略设计和实施安全解决方案。安全专业人员不是决策者；他们是执行者。所有决策必须留给高级管理者。

### 数据所有者

`data owner`（数据所有者）角色分配给负责对信息进行分类，以便在安全解决方案中进行放置和保护的人员。数据所有者通常是高层管理人员，对数据保护负最终责任。然而，数据所有者通常将实际数据管理任务的责任委派给数据管理员。

### 数据管理员

`data custodian`（数据管理员）角色分配给负责实施安全策略和高级管理层规定的保护措施的用户。数据管理员执行所有必要的活动，以充分保护数据的 CIA 三要素（机密性、完整性和可用性），并履行上级管理层委派的要求和职责。这些活动可以包括执行和测试备份、验证数据完整性、部署安全解决方案以及根据分类管理数据存储。

### 用户

`user`（用户，`end user` 最终用户或 `operator` 操作员）角色分配给任何有权访问受保护系统的人员。用户的访问权限与其工作任务相关联，并受到限制，使其仅拥有执行其职位所需任务所必需的访问权限（最小权限原则）。用户负责理解并维护组织的安全策略，方法是遵循规定的操作程序并在定义的安全参数内操作。

### 审计员

`auditor`（审计员）负责审查和验证安全策略是否正确实施，以及衍生的安全解决方案是否充分。审计员角色可分配给安全专业人员或受过培训的用户。审计员生成合规性和有效性报告，由高级管理者审查。通过这些报告发现的问题将转化为由高级管理者分配给安全专业人员或数据管理员的新指令。然而，审计员被列为最后一个角色，因为审计员需要一个活动源头（即在环境中工作的用户或操作员）来进行审计或监控。

所有这些角色在安全环境中都发挥着重要作用。它们对于识别责任和义务，以及识别分层管理和委派方案非常有用。

## 安全控制框架

为组织制定安全立场通常不仅仅是写下几个崇高的理想。在大多数情况下，制定可靠的安全策略需要大量的规划。许多《呆伯特》漫画的粉丝可能认识“开会计划开会，为未来的开会做准备”这一看似荒诞的概念。但事实证明，安全规划必须从“计划规划”开始，然后转入标准和合规规划，最后进入实际的计划开发和设计。跳过这些“计划规划”中的任何步骤，都可能在组织的安全解决方案启动之前就使其偏离轨道。

最重要的安全规划步骤之一是考虑组织期望的安全解决方案的整体 `security control framework`（安全控制框架）或结构。关于安全概念基础设施，您可以从多个选项中进行选择；然而，更广泛使用的安全控制框架之一是 **Control Objectives for Information and Related Technology (COBIT，信息及相关技术控制目标)**。COBIT 是由 **Information Systems Audit and Control Association (ISACA，信息系统审计与控制协会)** 制定的一套记录在案的 IT 安全最佳实践。它规定了安全控制的目标和要求，并鼓励将 IT 安全理想映射到业务目标。COBIT 5 基于企业 IT 治理和管理的五大核心原则：

*   **原则 1**：满足利益相关者需求
*   **原则 2**：覆盖企业端到端
*   **原则 3**：应用单一集成框架
*   **原则 4**：实现整体方法
*   **原则 5**：将治理与管理分离

COBIT 不仅用于规划组织的 IT 安全，还作为审计员的指南。COBIT 是一个广泛认可和受尊重的安全控制框架。

幸运的是，考试中仅适度引用 COBIT，因此无需了解更多细节。但是，如果您对这一概念感兴趣，请访问 ISACA 网站（[www.isaca.org](http://www.isaca.org)），或者如果您想要一个总体概览，请阅读维基百科上的 COBIT 条目。

还有许多其他 IT 安全标准和指南。其中一些包括：

*   **开源安全测试方法手册 (OSSTMM)**（[www.isecom.org/research/](http://www.isecom.org/research/)）：一份经过同行评审的指南，用于安全基础设施的测试和分析
*   **ISO/IEC 27002**（取代了 ISO 17799）（[https://www.iso.org/standard/54533.html](https://www.iso.org/standard/54533.html)）：一项国际标准，可作为实施组织安全和相关管理实践的基础
*   **信息技术基础设施库 (ITIL)**（[www.itlibrary.org](http://www.itlibrary.org)）：最初由英国政府制定，ITIL 是一套核心 IT 安全和运营流程的推荐最佳实践，常被用作定制 IT 安全解决方案的起点
