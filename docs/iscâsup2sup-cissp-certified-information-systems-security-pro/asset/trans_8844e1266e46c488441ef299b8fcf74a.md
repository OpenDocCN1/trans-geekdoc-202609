

# TCP 端口与传输控制协议

## 熟知端口（0–1,023）

这前 1,024 个端口（0–1,023）被称为*熟知端口*或*服务端口*。这是因为它们具有标准化的分配，对应其所支持的服务。例如，端口 80 是 Web（HTTP）流量的标准端口，端口 23 是 Telnet 的标准端口，端口 25 是 SMTP 的标准端口。这些端口保留专供服务器使用（换句话说，它们不能被请求客户端用作源端口）。您可以在本章后面的“常见应用层协议”部分找到考试值得了解的端口列表。

## 注册软件端口（1,024–49,151）

端口 1,024 到 49,151 称为*注册软件端口*。这些端口有一个或多个网络软件产品专门向国际互联网号码分配局（IANA, `www.iana.org`）注册，以便为试图连接其产品的客户端提供标准化的端口编号系统。

## 动态/临时端口（49,152–65,535）

端口 49,152 到 65,535 称为*随机、动态或临时端口*，因为它们经常被客户端随机且临时地用作源端口。当在初始服务端口或注册端口之外，在客户端和服务器之间协商数据传输管道时，这些随机端口也被多种网络服务使用，例如常见的 FTP 所执行的操作。

## 传输控制协议 (TCP)

传输控制协议 (TCP) 在 OSI 模型的第 4 层（传输层）运行。它支持全双工通信，面向连接，并采用可靠会话。TCP 之所以面向连接，是因为它采用两个系统之间的握手过程来建立通信会话。完成此握手过程后，即建立了一个可支持客户端和服务器之间数据传输的通信会话。

### 三次握手

三次握手过程（**图 11.7**）如下：

1.  客户端向服务器发送一个标记了 `SYN`（同步）标志的数据包。
2.  服务器响应一个标记了 `SYN/ACK`（同步和确认）标志的数据包回复给客户端。
3.  客户端响应一个标记了 `ACK`（确认）标志的数据包回复给服务器。

### 会话终止

当通信会话完成时，有两种方法可以断开 TCP 会话：

1.  **FIN（完成）标志数据包**：最常用的方法。每一方在其所有数据传输完毕后发送一个标记了 `FIN` 标志的数据包，触发对方用一个标记了 `ACK` 标志的确认数据包进行确认。因此，优雅地拆除一个 TCP 会话需要四个数据包。
2.  **RST（复位）标志数据包**：导致会话立即且突然地终止。（请参阅本节后面关于 TCP 头部标志的讨论。）

### 排序、确认与流量控制

TCP 传输的段被标记上序列号。这使得接收方能够通过将接收到的段重新排序回其正确的排列来重建原始通信，而不管它们的接收顺序如何。

通过 TCP 会话传输的数据会定期通过确认进行验证。确认由接收方发回发送方，方法是将 TCP 头部的确认序列值设置为在传输窗口内从发送方接收到的最后一个序列号。在发送确认数据包之前传输的数据包数量称为**传输窗口**。

数据流通过一种称为**滑动窗口**的机制进行控制。TCP 能够在发送确认之前使用不同大小的窗口（换句话说，不同数量的传输数据包）。

- **较大的窗口**：允许更快的数据传输，但应仅用于丢失或损坏数据极少的可靠连接上。
- **较小的窗口**：应在通信连接不可靠时使用。

当需要数据交付时应采用 TCP。滑动窗口允许此大小动态变化，因为 TCP 会话的可靠性在使用过程中会发生变化。如果传输窗口的所有数据包未全部被接收，则不发送确认。超时后，发送方将重新发送整个传输窗口的数据包集合。

## TCP 头部结构

与另一种常见的传输层协议 UDP 相比，TCP 头部相对复杂。TCP 头部长度为 20 到 60 字节。该头部划分为多个部分或字段，详见**表 11.1**。

[**表 11.1**](#c11.xhtml#tableanchor11-1) **TCP 头部构造（按头部开始到结束顺序）**

| 位大小 | 字段 |
| :--- | :--- |
| 16 | 源端口 |
| 16 | 目的端口 |
| 32 | 序列号 |
| 4 | 数据偏移 |
| 4 | 保留供将来使用 |
| 8 | 标志（见**表 11.2**） |
| 16 | 窗口大小 |
| 16 | 校验和 |
| 16 | 紧急指针 |
| 可变 | 各种选项；必须是 32 位的倍数 |

所有这些字段都有独特的参数和要求，其中大多数超出了 CISSP 考试的范围。但是，您应该熟悉标志字段的详细信息。标志字段可以包含一个或多个标志（或控制位）的指定。这些标志指示 TCP 数据包的功能，并请求接收方以特定方式响应。标志字段长 8 位。每个位位置代表单个标志或控制设置。每个位置可以设置为 1（开）或 0（关）。在某些条件下，可以同时启用多个标志（例如，TCP 三次握手中的第二个数据包，此时 `SYN` 和 `ACK` 标志均被设置）。**表 11.2** 详细列出了标志控制位。

[**表 11.2**](#c11.xhtml#tableanchor11-2) **TCP 头部标志字段值**

| 标志位指示符 | 名称 | 描述 |
| :--- | :--- | :--- |
| CWR | 拥塞窗口减小 | 用于管理拥塞链路上的传输；见 RFC 3168 |
| ECE | ECN 回显（显式拥塞通知） | 用于管理拥塞链路上的传输；见 RFC 3168 |
| URG | 紧急 | 指示紧急数据 |
| ACK | 确认 | 确认同步或关闭请求 |
| PSH | 推送 | 指示需立即将数据推送给应用程序 |
| RST | 复位 | 导致 TCP 会话立即断开 |
| SYN | 同步 | 请求使用新序列号进行同步 |
| FIN | 完成 | 请求优雅关闭 TCP 会话 |

## IP 头部协议字段

一个额外的重要细节是，TCP 的 IP 头部协议字段值为 `6` (`0x06`)。协议字段值是每个 IP 数据包头部中发现的标签或标志，它告诉接收系统数据包的类型。IP 头部的协议字段指示下一个封装协议的标识（换句话说，当前协议层载荷中包含的协议，如 ICMP 或 IGMP，或上一层协议，如 TCP 或 UDP）。可以把它想象成你从冰箱里拿出的、用白纸包裹的神秘肉包装上的标签。没有标签，你必须打开并检查才能弄清它是什么。但有了标签，你就可以快速搜索或筛选以找到感兴趣的项目。有关其他协议字段值的列表，请访问 `www.iana.org/assignments/protocol-numbers`。
