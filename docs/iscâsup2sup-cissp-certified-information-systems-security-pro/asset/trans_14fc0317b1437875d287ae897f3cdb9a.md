
# 隐性拒绝

访问控制的一项基本原则是*隐性拒绝*，大多数授权机制都采用该原则。隐性拒绝原则确保除非已明确授予主体访问权限，否则将拒绝对对象的访问。例如，设想管理员明确授予 Jeff 对某文件的“完全控制”权限，但未明确授予其他任何人权限。即使管理员未明确拒绝 Mary 的访问，Mary 也无法访问该文件。相反，隐性拒绝原则会拒绝除 Jeff 之外的 Mary 及其他所有人的访问。

# 访问控制矩阵

*访问控制矩阵*是一个包含主体、对象和分配特权的表格。当主体尝试执行某项操作时，系统会检查访问控制矩阵，以确定该主体是否拥有执行该操作所需的适当特权。例如，访问控制矩阵可以包含一组文件作为对象，一组用户作为主体。它将显示每个用户针对每个文件被授权的确切权限。请注意，这涵盖的范围远不止单个*访问控制列表*（ACL）。在该示例中，矩阵中列出的每个文件都有一个单独的 ACL，其中列出了授权用户及其分配的权限。

# 能力表

*能力表*是标识分配给主体特权的另一种方式。它们与 ACL 的区别在于，能力表关注的是主体（如用户、组或角色）。例如，为会计角色创建的能力表将包含会计角色可访问的所有对象列表，并包含分配给会计角色针对这些对象的特定特权。相反，ACL 关注的是对象。某文件的 ACL 将列出所有被授权访问该文件的用户和/或组，以及授予每个用户/组的具体访问权限。

# 受限界面

应用程序使用*受限界面*或受限制界面，根据用户的特权限制其能执行的操作或查看的内容。拥有完全特权的用户可以访问应用程序的所有功能。拥有受限特权的用户只有有限的访问权限。应用程序通过不同方法来约束界面。一种常见方法是：如果用户没有使用某功能的权限，则隐藏该功能。例如，命令可能通过菜单或右键单击项目提供给管理员，但如果普通用户没有权限，该命令将不显示。其他时候，应用程序会显示菜单项但将其显示为灰色或禁用状态。普通用户可以看到菜单项，但无法使用它。

# 基于内容的控制

*基于内容的访问控制*根据对象内的内容限制对数据的访问。数据库视图是一种基于内容的控制。视图从一个或多个表中检索特定列，创建一个虚拟表。例如，数据库中的客户表可能包含客户姓名、电子邮件地址、电话号码和信用卡数据。基于客户的视图可能仅显示客户姓名和电子邮件地址，而不显示其他内容。被授予视图访问权限的用户可以查看客户姓名和电子邮件地址，但无法访问底层表中的数据。

# 基于上下文的控制

*基于上下文的访问控制*在授予用户访问权限前要求特定的活动。例如，考虑在线销售数字产品的交易数据流程。用户将产品加入购物车并开始结账流程。结账流程的第一页显示购物车中的产品，下一页收集信用卡数据，最后一页确认购买并提供下载数字产品的说明。如果用户未先完成购买流程，系统将拒绝其访问下载页面。也可以使用日期和时间控制作为基于上下文的控制。例如，可以根据当前日期和/或时间限制对计算机和应用程序的访问。如果用户尝试在允许时间范围之外访问资源，系统将拒绝其访问。

# 需知原则

该原则确保主体仅被授予其工作任务和职能所*需知*的内容访问权限。主体可能拥有访问机密或受限数据的许可，但除非他们实际需要这些数据来执行工作，否则不会被授予对该数据的授权。

# 最小权限

*最小权限原则*确保主体仅被授予执行其工作任务和职能所需的特权。这有时会与需知原则归为一类。唯一的区别在于，最小权限还包括对系统执行操作的权利。

# 职责分离

*职责分离*原则确保敏感职能被拆分为由两名或更多员工执行的任务。它通过建立制衡机制来帮助防止欺诈和错误。

# 使用安全策略定义需求

*安全策略*是定义组织安全需求的文档。它标识需要保护的资产，以及安全解决方案应在何种程度上保护它们。一些组织创建单一的安全策略文档，而其他组织创建多个安全策略，每个策略专注于一个单独的领域。

策略是访问控制的重要要素，因为它们帮助组织内部人员了解哪些安全需求很重要。高级领导批准安全策略，并以此提供组织安全需求的广泛概述。然而，安全策略通常不会详细说明如何满足安全需求或如何实施策略。例如，它可能声明需要实施并强制执行职责分离和最小权限原则，但不会说明如何做到这一点。组织内的专业人员将安全策略作为指南来实施安全需求。

# 实施纵深防御

组织使用*纵深防御*策略实施访问控制。这使用多层或多级访问控制来提供分层安全。例如，请参考[图 14.1](#c14.xhtml#figure14-1)。它显示了两台服务器和两个磁盘，代表组织想要保护的资产。入侵者或攻击者需要克服多层防御才能到达这些受保护的资产。

[**图 14.1**](#c14.xhtml#figureanchor14-1) 具有分层安全的纵深防御

组织使用多种方法实施控制。不能仅依赖技术来提供安全；还必须使用物理访问控制和管理访问控制。例如，如果服务器具有强身份验证但放置在无人看管的桌子上，小偷可以轻易将其偷走并花时间破解系统。同样，用户可能有强密码，但社会工程师可以欺骗未受教育的用户交出密码。

纵深防御的概念强调了几个重要点：

*   组织的安全策略（属于管理访问控制之一）通过定义安全需求，为资产提供了一层防御。
*   人员是防御的关键组成部分。然而，他们需要适当的培训和教育，以实施、遵守并支持组织安全策略中定义的安全要素。
*   管理、技术和物理访问控制的组合提供了强得多的防御。仅使用管理、仅使用技术或仅使用物理控制会导致弱点，攻击者可发现并利用这些弱点。
