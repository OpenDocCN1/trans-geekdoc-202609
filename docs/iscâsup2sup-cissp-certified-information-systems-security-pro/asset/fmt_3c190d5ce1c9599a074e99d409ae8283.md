# 第 16 章：管理安全运营

## 1. C
“需知”原则是指执行特定工作任务所需的访问权限、知识获取或数据持有，且不得超出此范围。`最小权限原则` 包括权利和权限，但“最小许可原则”在 IT 安全中不是有效术语。`职责分离` 确保单个人不控制流程的所有要素。`基于角色的访问控制（RBAC）` 根据角色授予资源访问权限。

## 2. D
默认访问级别应为无访问权限。`最小权限原则` 规定用户应仅被授予其工作所需的访问级别，题目未表明新用户需要任何数据库访问权限。读取访问、修改访问和完全访问都会授予用户一定级别的访问权限，这违反了最小权限原则。

## 3. C
`职责分离` 策略防止单个人控制流程的所有要素，应用于安全设置时，可防止个人在无协助情况下进行重大安全更改。`工作轮换` 有助于确保多人能胜任同一工作，并在单个人离职时防止组织信息流失。让员工专注于特长与职责分离无关。

## 4. B
`工作轮换` 和 `职责分离` 策略有助于防止欺诈。`串通` 是指多人达成协议实施未经授权或非法行为，实施这些策略无法防止串通，也不会鼓励员工串通对抗组织。它们有助于威慑和预防事件，但无法纠正事件。

## 5. A
`工作轮换` 策略让员工轮换工作或职责，有助于发现串通和欺诈事件。`职责分离` 策略确保单个人不控制特定功能的所有要素。`强制休假` 策略确保员工长时间离岗，由他人履行其职责，从而增加发现欺诈的可能性。`最小权限` 确保用户仅拥有执行工作所需的权限，不多不少。

## 6. B
`强制休假` 策略有助于发现欺诈。它要求员工长时间离岗，由他人履行其职责，从而增加发现欺诈的可能性。它不轮换工作职责。虽然强制休假可能帮助员工降低整体压力水平，进而提高生产力，但这些不是强制休假策略的主要原因。

## 7. A, B, C
`工作轮换`、`职责分离` 和 `强制休假` 策略都有助于减少欺诈。`基线化` 用于配置管理，无助于减少串通或欺诈。

## 8. B
不应平等地向管理员和操作员授予特殊权限。相反，人员应仅被授予执行其工作所需的特权。`特殊权限` 是指需要特殊访问或提升权限来执行管理和敏感工作任务的活动。这些特权的分配和使用应受到监控，且仅授予受信任的员工。

## 9. A
`服务级别协议（SLA）` 标识第三方（如供应商）的责任，并可在供应商未履行规定责任时包含金钱罚则。`谅解备忘录（MOU）` 是非正式协议，不包含金钱罚则。`互连安全协议（ISA）` 定义建立、维护和断开连接的要求。`SaaS` 是云服务模型之一，不规定供应商责任。

## 10. C
系统在生命周期结束时应进行清理，以确保不包含任何敏感数据。移除 CD 和 DVD 是清理过程的一部分，但系统的其他要素（如磁盘驱动器）也应检查以确保不包含敏感信息。除非组织的清理流程要求，否则移除软件许可证或安装原始软件并非必须。

## 11. A
贵重资产需要多层物理安全防护，将数据中心置于建筑物中心有助于提供这些额外的安全层。将贵重资产放置在外墙旁（包括建筑物后部）会消除某些安全层。

## 12. D
VM 需要单独更新，就像它们运行在物理服务器上一样。物理服务器的更新不会更新托管的 VM。同样，更新一个 VM 不会更新所有 VM。

## 13. A
租用基础设施即服务（IaaS）云资源时，组织对维护和安全承担最大责任。云服务提供商在平台即服务（PaaS）模型中承担更多责任，在软件即服务（SaaS）模型中承担最多责任。`混合云` 指云部署模型（而非服务模型），表示使用两种或多种部署模型（如私有云、公有云和/或社区云）。

## 14. C
`社区云` 部署模型向两个或多个组织提供基于云的资产。`公有云` 模型包含可供任何消费者租赁或租用的资产。`私有云` 部署模型包含专属于单个组织的基于云的资产。`混合模型` 包含两种或多种部署模型的组合。无论是软件即服务（SaaS）模型还是其他服务模型均不影响此分类。

## 15. B
应对磁带进行清除，确保数据无法通过任何已知手段恢复。即使磁带已达生命周期末期，它们仍可能保存数据，在丢弃前应进行清除。擦除无法从介质中移除所有可用数据，但清除可以。如果磁带已达生命周期末期，无需存储。
