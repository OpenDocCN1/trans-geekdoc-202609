

# 理解问责制的重要性

只有保持问责制，组织的安全策略才能得到正确实施。换句话说，只有对主体的行为进行问责，才能维护安全。有效的问责依赖于证明主体身份并追踪其活动的能力。

# 能够解释不可抵赖性

不可抵赖性确保活动或事件的主体无法否认该事件的发生。它防止主体声称未发送消息、未执行某项操作，或不是导致某事件的原因。

# 理解安全管理规划

安全管理基于三类计划：战略、战术和操作。战略计划是一项相当稳定的长期计划。它定义了组织的目标、使命和目的。战术计划是一项中短期计划，旨在为完成战略计划中设定的目标提供更多细节。操作计划是基于战略和战术计划的短期、高度详细的计划。

# 掌握正式安全策略结构的要素

要制定全面的安全计划，需要具备以下要素：安全策略、标准、基线、指南和程序。此类文档明确陈述了安全要求，并使相关责任方履行应尽的注意义务。

# 理解关键安全角色

主要安全角色包括高级经理、组织所有者、高层管理人员、安全专业人员、用户、数据所有者、数据管理员和审计员。通过建立安全角色层级，可以从总体上限制风险。

# 掌握如何实施安全意识培训

在实际培训开始之前，必须先为用户建立对安全作为一个公认实体的意识。一旦完成这一点，培训——即教授员工执行其工作任务并遵守安全策略——便可以开始。所有新员工都需要一定程度的培训，以便他们能够遵守安全策略强制规定的所有标准、指南和程序。教育是一项更详细的工作，学生/用户学到的知识远超其执行工作任务所需。教育通常与追求认证或寻求晋升的用户相关联。

# 理解分层如何简化安全

分层是指串联使用多种控制措施。采用多层解决方案可使众多控制措施协同防御威胁。

# 能够解释抽象的概念

抽象用于将相似元素收集到组、类或角色中，并将安全控制、限制或权限作为一个整体分配给它们。它提高了执行安全计划的效率。

# 理解数据隐藏

数据隐藏正如其名：防止数据被主体发现或访问。它通常是安全控制以及编程中的关键要素。

# 理解加密的必要性

加密是隐藏通信含义或意图、使非预期接收者无法理解的艺术与科学。它可以采取多种形式，并应用于各类电子通信，包括文本、音频和视频文件，以及程序本身。加密是安全控制中的重要要素，特别是在系统间数据传输方面。

# 能够解释变更控制和变更管理的概念

安全环境中的变更可能引入漏洞、重叠、缺失对象和疏忽，从而导致新的脆弱性。面对变更，维护安全的唯一途径是系统地管理变更。

# 了解为何以及如何对数据进行分类

对数据进行分类是为了简化将安全控制分配给对象组而非单个对象的过程。两种常见的分类方案是政府/军事分类和商业/私营部门分类。了解政府/军事分类的五个级别和商业/私营部门分类的四个级别。

# 理解解密的重要性

一旦资产不再需要其当前分配的分类或敏感级别所提供的保护，就需要进行解密。

# 掌握 COBIT 基础知识

信息及相关技术控制目标（COBIT）是一种安全概念基础设施，用于组织公司复杂的安全解决方案。

# 掌握威胁建模基础知识

威胁建模是识别、分类和分析潜在威胁的安全过程。威胁建模可在设计和开发阶段作为主动措施执行，也可在产品部署后作为被动措施执行。关键概念包括资产/攻击者/软件、STRIDE、PASTA、Trike、VAST、绘图、简化/分解以及 DREAD。

# 理解将基于风险的管理概念应用于供应链的必要性

将基于风险的管理概念应用于供应链，是确保各种规模组织拥有更稳健、更成功的安全策略的一种手段。如果在采购和收购时未考虑安全因素，这些产品固有的风险将贯穿其整个部署生命周期。
