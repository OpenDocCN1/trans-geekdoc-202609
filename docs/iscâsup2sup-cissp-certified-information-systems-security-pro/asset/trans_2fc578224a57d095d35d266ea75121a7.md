# 管理事件响应

任何安全计划的主要目标之一是预防安全事件。然而，尽管信息技术 (IT) 和安全专业人员竭尽全力，事件仍会发生。一旦发生，组织必须能够做出响应以限制或遏制事件。事件响应的主要目标是将对组织的影响降至最低。

## 定义事件

在深入探讨事件响应之前，了解事件的定义非常重要。虽然这看似简单，但你会发现根据上下文不同，存在不同的定义。

`事件` 是指对组织资产的机密性、完整性或可用性产生负面影响的任何事件。信息技术基础设施库第 3 版 (ITILv3) 将事件定义为“IT 服务的非计划中断或 IT 服务质量的下降”。请注意，这些定义涵盖的事件类型多种多样，包括直接攻击、自然灾害（如飓风或地震），甚至意外事故（如有人意外切断了活动网络的电缆）。

相比之下，`计算机安全事件`（有时简称为 `安全事件`）通常指由攻击引起的事件，或由用户恶意或故意行为导致的事件。例如，征求意见稿 (RFC) 2350《计算机安全事件响应期望》将安全事件和计算机安全事件均定义为“危及计算机或网络安全某方面的任何不利事件”。美国国家标准与技术研究院 (NIST) 特别出版物 (SP) 800-61《计算机安全事件处理指南》将计算机安全事件定义为“违反或即将违反计算机安全策略、可接受使用策略或标准安全实践的行为。”（NIST 文档，包括 SP 800-61，可从 NIST 出版物页面访问：[https://csrc.nist.gov/Publications](https://csrc.nist.gov/Publications)）。

在事件响应的语境中，事件是指计算机安全事件。不过，你经常会看到它仅被列为事件。例如，在 CISSP 安全运营领域中，“实施事件管理”目标显然是指计算机安全事件。

组织通常在其安全策略或事件响应计划中定义计算机安全事件的含义。该定义通常为一两句话，并包含组织归类为安全事件的常见事件示例，例如：

*   任何企图的网络入侵
*   任何企图的拒绝服务攻击
*   任何恶意软件的检测
*   任何未经授权的数据访问
*   任何违反安全策略的行为

必须强调的是，事件响应不包括对攻击者的反击。对他人发动攻击适得其反且通常是非法的。如果技术人员能识别攻击者并发动攻击，极有可能导致攻击者升级攻击。换句话说，攻击者可能将其视为私人恩怨，并定期发动报复性攻击。此外，攻击者很可能隐藏在一个或多个无辜受害者背后。攻击者常使用欺骗手段隐藏身份，或利用僵尸网络中的僵尸主机发动攻击。反击可能针对的是无辜受害者，而非攻击者。

### 检测

IT 环境包含多种检测潜在事件的方法。以下列表列出了许多用于检测潜在事件的常用方法，并说明了这些方法如何报告事件：

*   入侵检测和防御系统（本章后面介绍）在发生关注事件时向管理员发送警报。
*   反恶意软件在检测到恶意软件时通常会显示弹出窗口进行指示。
*   许多自动化工具定期扫描审计日志，查找预定义事件，例如特权的使用。当它们检测到特定事件时，通常会向管理员发送警报。
*   最终用户有时会检测到异常活动，并联系技术人员或管理员寻求帮助。当用户报告无法访问网络资源或更新系统等事件时，会提醒 IT 人员注意潜在事件。

请注意，仅仅因为 IT 专业人员收到自动化工具的警报或用户的投诉，并不总意味着事件已发生。入侵检测和防御系统经常发出误报，最终用户也容易犯简单的操作错误。IT 人员会调查这些事件以确定它们是否为事件。

许多 IT 专业人员被归类为事件的首批响应者。他们是最先到达现场的人员，并具备将典型 IT 问题与安全事件区分开来的知识。他们类似于医疗急救人员，后者拥有出色的技能和能力，可在事故现场提供医疗援助，并在必要时帮助将患者送往医疗机构。医疗急救人员接受过特定培训，以帮助他们判断轻伤与重伤的区别。此外，他们知道遇到重伤时该怎么做。同样，IT 专业人员需要特定培训，以便判断需要排查的典型问题与需要升级处理的安全事件之间的区别。

在调查事件并确定其为安全事件后，IT 人员将进入下一步：响应。在许多情况下，进行初步调查的个人会升级事件，引入其他 IT 专业人员进行响应。
