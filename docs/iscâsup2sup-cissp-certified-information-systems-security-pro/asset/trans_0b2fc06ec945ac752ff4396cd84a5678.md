

# 民用数据分类与保护

民用组织无需使用任何特定的分类标签。然而，以某种方式对数据进行分类并确保人员理解这些分类至关重要。无论组织使用何种标签，它仍有义务保护敏感信息。

对数据分类后，组织会根据其分类采取额外步骤对其进行管理。对敏感信息的未授权访问可能给组织造成重大损失。然而，基本的安全实践——如根据分类正确标记、处理、存储和销毁数据及硬件资产——有助于防止损失。

## 定义资产分类

资产分类应与数据分类相匹配。换句话说，如果一台计算机正在处理绝密数据，该计算机也应被分类为绝密资产。同样，如果内部或外部驱动器等介质存放着绝密数据，该介质也应被分类为绝密。

在硬件资产上使用清晰的标记很常见，以便提醒人员该资产上可处理或存储的数据。例如，如果一台计算机用于处理绝密数据，则该计算机和显示器上将贴有清晰醒目的标签，提醒用户该计算机上可处理的数据分类。

## 确定数据安全控制

定义数据和资产分类后，定义安全需求并确定实施这些安全需求的安全控制非常重要。设想一个组织已决定采用如前所述的机密/专有、私密、敏感和公开数据标签。管理层随后制定数据安全策略，规定使用特定安全控制来保护这些类别中的数据。该策略可能会涉及存储在文件中、数据库中、服务器上（包括电子邮件服务器）、用户系统上、通过电子邮件发送以及存储在云中的数据。

在此示例中，我们将数据类型仅限于电子邮件。该组织已定义如何保护每个数据类别中的电子邮件。他们决定公开类别中的任何电子邮件都无需加密。然而，所有其他类别（机密/专有、私密、敏感）中的电子邮件在发送时（传输中数据）和存储在电子邮件服务器上时（静态数据）都必须加密。

加密将明文数据转换为乱码密文，使其更难阅读。使用强加密方法（如`采用 256 位加密密钥的高级加密标准 (AES 256)`）几乎使未授权人员无法读取文本。

[表 5.1](#c05.xhtml#table5-1) 显示了管理层在其数据安全策略中为电子邮件定义的其他安全需求。请注意，最高分类级别（机密/专有）的数据在安全策略中定义了最多的安全需求。

[**表 5.1**](#c05.xhtml#tableanchor5-1) **保护电子邮件数据**

| 分类 | 电子邮件的安全需求 |
| --- | --- |
| 机密/专有（对任何数据的最高保护级别） | 电子邮件及附件必须使用 AES 256 加密。<br>电子邮件及附件除查看时外始终保持加密状态。<br>电子邮件只能发送给组织内部收件人。<br>电子邮件只能由收件人打开和查看（转发的邮件无法打开）。<br>附件可打开和查看，但不能保存。<br>电子邮件内容不能复制粘贴到其他文档中。<br>电子邮件不能打印。 |
| 私密（示例包括 PII 和 PHI） | 电子邮件及附件必须使用 AES 256 加密。<br>电子邮件及附件除查看时外始终保持加密状态。<br>只能发送给组织内部收件人。 |
| 敏感（受分类数据的最低保护级别） | 电子邮件及附件必须使用 AES 256 加密。 |
| 公开 | 电子邮件及附件可明文发送。 |

安全管理员使用安全策略中定义的需求来确定安全控制。对于[表 5.1](#c05.xhtml#table5-1)，主要安全控制是使用 AES 256 的强加密。管理员将确定使员工易于满足这些需求的方法。

尽管可以满足[表 5.1](#c05.xhtml#table5-1) 中的所有需求，但这需要实施其他解决方案。例如，软件公司 Boldon James 销售多种产品，组织可用其自动执行这些任务。用户在发送电子邮件前应用相关标签（如机密、私密、敏感和公开）。这些邮件会通过`数据丢失防护 (DLP)`服务器，该服务器检测标签并应用所需的保护。

[表 5.1](#c05.xhtml#table5-1) 显示了组织可能想要应用于电子邮件的可能需求。然而，组织不会止步于此。组织想要保护的任何类型数据都需要类似的安全定义。例如，组织会为存储在服务器等资产上的数据、存储在异地和异地的数据备份以及专有数据定义需求。

此外，`身份与访问管理 (IAM)`安全控制有助于确保只有授权人员才能访问资源。第 13 章“管理身份与认证”和第 14 章“控制与监控访问”将更深入地介绍 `IAM` 安全控制。

## 理解数据状态

保护所有`数据状态`下的数据非常重要，包括静态、传输中和使用中。

### 静态数据

`静态数据`是指存储在介质上的任何数据，如系统硬盘、外部 USB 驱动器、存储区域网络 (`SANs`) 和备份磁带。

### 传输中数据

`传输中数据`（有时称为动态数据）是指通过网络传输的任何数据。这包括使用有线或无线方法在内部网络上传输的数据，以及在互联网等公共网络上传输的数据。

### 使用中数据

`使用中数据`是指应用程序使用时处于内存或临时存储缓冲区中的数据。因为应用程序无法处理加密数据，所以必须在内存中对其进行解密。

保护数据机密性的最佳方法是使用强加密协议，本章稍后将讨论。此外，强认证和授权控制有助于防止未授权访问。

例如，考虑一个 Web 应用程序，它在用户许可下检索信用卡数据以便在电子商务交易中快速访问和重用。信用卡数据存储在单独的数据库服务器上，并在静态、传输中和使用时受到保护。

数据库管理员采取措施加密存储在数据库服务器上的敏感数据（静态数据）。例如，他们会加密存放信用卡数据等敏感数据的列。此外，他们会实施强认证和授权控制，以防止未授权实体访问数据库。

当 Web 应用程序从 Web 服务器发送数据请求时，数据库服务器会验证 Web 应用程序是否被授权检索数据，如果是，则发送数据。然而，这涉及多个步骤。例如，数据库管理系统首先检索并解密数据，并将其格式化为 Web 应用程序可读的方式。然后数据库服务器使用传输加密算法在传输前加密数据。这确保了传输中数据的安全。
