

# SDH 和 SONET 拓扑

SDH 和 SONET 均支持网状和环状拓扑。这些光纤解决方案通常作为电信服务的骨干网实施，并将容量的划分或部分租赁给客户。SDH 和 SONET 的互连点或节点通常是加/析复用器（ADM），它允许将低速比特流连接或产品添加到主干线中或从中移除。

## 专用协议

某些 WAN 连接技术需要额外的专用协议来支持各种类型的专用系统或设备。其中三种协议是 SDLC、HDLC 和 HSSI：

### 同步数据链路控制（SDLC）

**同步数据链路控制**用于专用租用线的永久物理连接，为大型主机（如 IBM 系统网络架构 [SNA] 系统）提供连接。SDLC 使用轮询，工作在 OSI 第 2 层（数据链路层），是一种面向比特的同步协议。

### 高级数据链路控制（HDLC）

**高级数据链路控制**是 SDLC 的改进版本，专为串行同步连接设计。HDLC 支持全双工通信，并支持点对点和多点连接。与 SDLC 一样，HDLC 使用轮询并工作在 OSI 第 2 层（数据链路层）。HDLC 提供流量控制，并包含错误检测和纠正功能。

## 拨号封装协议

点对点协议（PPP）是一种封装协议，旨在支持 IP 流量通过拨号或点对点链路传输。PPP 允许支持串行链路的 WAN 设备实现多厂商互操作性。所有拨号连接和大多数点对点连接本质上都是串行的（而非并行）。PPP 包含广泛的通信服务，包括 IP 地址的分配和管理、同步通信的管理、标准化封装、复用、链路配置、链路质量测试、错误检测，以及功能或选项协商（如压缩）。

PPP 最初设计用于支持 CHAP 和 PAP 进行认证。然而，PPP 的新版本还支持 MS-CHAP、EAP 和 SPAP。PPP 还可用于支持 Internetwork Packet Exchange（IPX）和 DECnet 协议。PPP 是一项记录在 RFC 1661 中的互联网标准。它取代了串行线路互联网协议（SLIP）。SLIP 不提供认证、仅支持半双工通信、无错误检测能力，且需要手动建立和拆除链路。

# 杂项安全控制特性

当您为网络通信选择或部署安全控制时，需要结合您的环境、能力和安全策略评估众多特性。我们将在以下章节讨论这些问题。

## 透明性

顾名思义，*透明性*是服务、安全控制或访问机制的一种特性，确保其对用户不可见。透明性通常是安全控制的理想特性。安全机制越透明，用户绕过它甚至察觉其存在的可能性就越小。透明性意味着缺乏直接证据证明某项功能、服务或限制的存在，且其对性能的影响微乎其微。

在某些情况下，透明性可能需要作为可配置功能而非永久运行特性发挥作用，例如管理员在排查故障、评估或调整系统配置时。

## 验证完整性

要验证传输的完整性，可以使用称为哈希总和的校验和。在消息或数据包通过通信路径发送前，对其执行哈希函数。获得的哈希总和被添加到消息末尾，称为消息摘要。消息接收后，目标系统执行哈希函数，并将结果与原始哈希总和进行比较。如果两个哈希总和匹配，则可以高度确定消息在传输过程中未被篡改或损坏。哈希总和与循环冗余校验（CRC）类似，二者均作为完整性工具。在大多数安全事务系统中，使用哈希函数来保证通信完整性。

记录序列检查类似于哈希总和检查；不过，它验证的是数据包或消息序列的完整性，而非内容完整性。许多通信服务采用记录序列检查，以验证消息的任何部分均未丢失，且消息的所有元素均按正确顺序排列。

## 传输机制

传输日志记录是一种专注于通信的审计形式。传输日志记录记录有关源、目的地、时间戳、识别码、传输状态、数据包数量、消息大小等详细信息。这些信息可用于排查故障、追踪未经授权的通信，或被用作提取系统运作数据的手段。

传输错误纠正是内置于面向连接或面向会话的协议和服务中的一项能力。如果确定消息（整体或部分）已损坏、篡改或丢失，可请求源端重发全部或部分消息。重传控制决定在传输错误纠正系统发现通信问题时，是重发全部还是部分消息。重传控制还可决定是否发送多份哈希总和或 CRC 值，以及是否采用多条数据路径或通信通道。

# 安全边界

*安全边界*是指具有不同安全要求或需求的任意两个区域、子网或环境之间的交界线。安全边界存在于高安全区域和低安全区域之间，例如 LAN 和互联网之间。识别网络和物理世界中的安全边界至关重要。一旦识别出安全边界，就需要部署机制来控制跨越这些边界的信息流。

安全区域之间的划分可以采取多种形式。例如，对象可能具有不同的分类。每个分类定义了哪些主体可以对哪些对象执行哪些功能。分类之间的区别即构成安全边界。

安全边界也存在于物理环境和逻辑环境之间。为提供逻辑安全，必须提供不同于物理安全所用的安全机制。两者均须到位以提供完整的安全架构，且均须在安全策略中予以阐述。然而，二者不同，必须作为安全解决方案的独立要素进行评估。

安全边界（如受保护区域与非受保护区域之间的边界）应始终清晰定义。在安全策略中说明控制开始或结束的点，并在物理和逻辑环境中标识该点非常重要。逻辑安全边界是电子通信与贵组织依法负责的设备或服务进行接口的点。在大多数情况下，该接口有明确标识，并告知未经授权的主体其无访问权限，且尝试获取访问权将导致起诉。
