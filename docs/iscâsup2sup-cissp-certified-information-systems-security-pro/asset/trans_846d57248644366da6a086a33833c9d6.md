
# 缓冲区溢出漏洞

当开发人员未能正确验证用户输入以确保其大小合适时，就会存在*缓冲区溢出*漏洞。过大的输入可能会“溢出”数据结构，从而影响计算机内存中存储的其他数据。例如，如果一个 Web 表单包含一个字段，该字段关联到一个允许 10 个字符的后端变量，但表单处理器未验证输入的长度，操作系统可能会尝试直接将数据写入该变量预留内存空间的末尾之后，从而可能破坏内存中存储的其他数据。在最坏的情况下，这些数据可被用于覆盖系统命令，允许攻击者利用缓冲区溢出漏洞在服务器上执行任意命令。

在创建软件时，开发人员必须特别注意允许用户输入的变量。许多编程语言本身并不强制限制变量的大小——它们依赖程序员在代码中执行边界检查。这是一种固有的漏洞，因为许多程序员认为参数检查是一种不必要的负担，会拖慢开发进程。作为安全从业者，你有责任确保组织中的开发人员了解缓冲区溢出漏洞带来的风险，并采取适当措施保护代码免受此类攻击。

每当程序变量允许用户输入时，程序员都应采取措施确保满足以下每个条件：

*   用户无法输入长度超过将容纳该输入的任何缓冲区大小的值（例如，将一个 10 字母的单词输入到一个 5 字母的字符串变量中）。
*   用户无法输入将容纳该输入的变量类型所不允许的无效值（例如，向数字变量输入字母）。
*   用户无法输入会导致程序在其指定参数之外运行的值（例如，对一个“是”或“否”的问题回答“也许”）。

未能执行简单的检查以确保满足这些条件，可能会导致缓冲区溢出漏洞，这可能导致系统崩溃，甚至允许用户执行 Shell 命令并获取系统访问权限。缓冲区溢出漏洞在使用 `Common Gateway Interface (CGI)` 或其他允许非熟练程序员快速创建交互式网页的语言快速开发的 Web 代码中尤为普遍。大多数缓冲区溢出漏洞可通过软件和操作系统供应商提供的补丁来缓解，这凸显了保持系统和软件最新的重要性。

## 检查时间到使用时间

*检查时间到使用时间 (TOCTOU or TOC/TOU)* 问题是一种时序漏洞，当程序在资源请求发生前过早地检查访问权限时就会发生。例如，如果操作系统在用户登录时构建一份详尽的访问权限列表，然后在整个登录会话期间查阅该列表，则存在 TOCTOU 漏洞。如果系统管理员撤销了特定权限，该限制直到用户下次登录时才会生效。如果用户在访问权限被撤销时已登录，他们将无限期地保留对该资源的访问权。用户只需保持会话打开数天，新的限制就永远不会被应用。

## 后门

*后门* 是未记录的命令序列，允许知晓后门的人绕过正常的访问限制。它们通常在开发和调试过程中使用，以加快工作流程，避免强制开发人员持续向系统进行身份验证。有时，开发人员会在系统达到生产状态后意外地或为了能在系统处理他们本不应有权访问的敏感数据时“窥探一下”而将这些后门留在系统中。除了开发人员植入的后门外，许多类型的恶意代码会在受感染系统上创建后门，允许恶意代码的开发者远程访问受感染系统。

无论它们以何种方式出现在系统上，后门的未记录性质使其成为任何包含它们的系统安全的重大威胁。知晓后门的个人可能利用它访问系统、检索机密信息、监控用户活动或从事其他邪恶行为。

## 权限提升和 Rootkit

一旦攻击者在系统上站稳脚跟，他们通常会迅速转向第二个目标——将访问权限从可能已被攻破的普通用户账户扩展到更全面的管理访问权限。他们通过实施*权限提升攻击*来实现这一点。

攻击者发动权限提升攻击最常见的方式之一是通过使用*Rootkit*。Rootkit 在互联网上免费提供，并利用各种操作系统中的已知漏洞。攻击者通常通过密码攻击或社会工程学获得标准系统用户账户的访问权限，然后使用 Rootkit 将其访问权限提升到 root（或管理员）级别。这种从标准权限到管理权限的访问权限增加被称为权限提升攻击。

管理员可以采取一个简单的预防措施来保护其系统免受权限提升攻击，这并非什么新鲜事。管理员必须及时了解其环境中使用的操作系统发布的新安全补丁，并始如一地应用这些补救措施。这一简单直接的步骤将使网络能够抵御几乎所有的 Rootkit 攻击以及大量其他潜在漏洞。

# Web 应用程序安全

Web 让你足不出户就能购买机票、查收邮件、支付账单和购买股票。如今几乎每个企业都运营着一个网站，许多网站允许你通过该站点进行敏感交易。

除了 Web 应用程序带来的便利性优势外，还伴随着一系列新的漏洞，这些漏洞可能使支持 Web 的组织面临安全风险。在接下来的几节中，我们将介绍一些常见的 Web 应用程序攻击。关于 Web 应用程序安全的更多详细信息，请参阅第 9 章“安全漏洞、威胁和对策”。

## 跨站脚本

当 Web 应用程序包含某种类型的*反射输入*时，会发生*跨站脚本 (XSS) 攻击*。例如，考虑一个简单的 Web 应用程序，它包含一个文本框，要求用户输入姓名。当用户点击提交时，Web 应用程序加载一个新页面，显示“Hello, *name*。”

在正常情况下，此 Web 应用程序按设计运行。然而，恶意个人可能利用此 Web 应用程序欺骗不知情的第三方。正如你所知，可以通过使用超文本标记语言 (HTML) 标签 `<SCRIPT>` 和 `</SCRIPT>` 在网页中嵌入脚本。假设你不在“姓名”字段中输入 *Mike*，而是输入以下文本：

```
Mike<SCRIPT>alert('hello')</SCRIPT>
```

当 Web 应用程序以网页形式“反射”此输入时，你的浏览器会像处理任何其他网页一样处理它：显示网页的文本部分并执行脚本部分。在本例中，脚本只是打开一个弹出窗口，其中显示“hello”。然而，你可以更恶意地包含一个更复杂的脚本，要求用户提供密码并将其传输给恶意第三方。
