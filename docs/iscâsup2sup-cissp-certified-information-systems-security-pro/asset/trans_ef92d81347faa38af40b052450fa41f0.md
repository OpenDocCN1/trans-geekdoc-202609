
自 2011 年以来，大多数系统制造商已将其主板上的传统 BIOS 系统替换为统一可扩展固件接口 (UEFI)。UEFI 是硬件与操作系统之间更高级的接口，它保持对传统 BIOS 服务的支持。

### 设备固件

许多硬件设备（如打印机和调制解调器）也需要一定的有限处理能力来完成其任务，同时将对操作系统本身造成的负担降至最低。在许多情况下，这些“微型”操作系统完全包含在其所服务设备上的固件芯片中。与计算机的 BIOS 类似，设备固件通常存储在 EEPROM 设备上，以便在必要时进行更新。

## 基于客户端的系统

基于客户端的漏洞将用户、其数据及其系统置于被攻破和破坏的风险之中。客户端攻击是指任何能够危害客户端的攻击。通常在讨论攻击时，默认主要目标是服务器或服务器端组件。客户端攻击或以客户端为中心的攻击，是指客户端本身或客户端上的某个进程成为目标。客户端攻击的一个常见例子是：恶意网站将恶意移动代码（如小程序）传输到客户端上运行的易受攻击的浏览器中。客户端攻击可通过任何通信协议发生，不仅限于超文本传输协议 (HTTP)。另一个基于客户端的潜在漏洞是本地缓存投毒的风险。

### 小程序

回顾一下，代理是从用户系统发送的代码对象，用于查询和处理存储在远程系统上的数据。`Applets` 执行相反的功能；这些代码对象从服务器发送到客户端以执行某些操作。事实上，小程序实际上是独立的微型程序，独立于发送它们的服务器而执行。万维网领域正处于持续变化之中。如今小程序的使用不如 2010 年代初期那样普遍。然而，小程序并未从网络中消失，大多数浏览器仍然支持它们（或仍安装有支持它们的插件）。因此，即使您的组织在内部或公共网页设计中不使用小程序，您的网页浏览器在浏览公共网络时仍可能遇到它们。

设想一台向网络用户提供各种金融工具的 Web 服务器。其中一种工具可能是抵押贷款计算器，它处理用户的财务信息，并根据贷款本金、期限和借款人的信用信息提供每月抵押贷款付款额。远程 Web 服务器不是处理这些数据并将结果返回给客户端系统，而是可能向本地系统发送一个小程序，使其能够自行执行这些计算。这为远程服务器和最终用户都提供了许多好处：

*   处理负担转移给了客户端，释放了 Web 服务器上的资源以处理来自更多用户的请求。
*   客户端能够使用本地资源生成数据，而无需等待远程服务器的响应。在许多情况下，这会使对输入数据变化的响应更快。
*   在编写得当的小程序中，Web 服务器不会接收提供给小程序作为输入的任何数据，从而保持用户财务数据的安全性和隐私性。

然而，正如代理一样，小程序也引入了许多安全顾虑。它们允许远程系统发送代码到本地系统执行。安全管理员必须采取措施，确保发送到其网络上系统的代码是安全的，并经过适当筛查以防恶意活动。此外，除非逐行分析代码，否则最终用户永远无法确定小程序不包含特洛伊木马组件。例如，抵押贷款计算器可能确实会在最终用户不知情或未经同意的情况下，将敏感财务信息传输给 Web 服务器。

小程序类型的两个历史示例是 Java 小程序和 ActiveX 控件。

#### Java 小程序

`Java` 是由 Sun Microsystems（现归 Oracle 所有）开发的一种与平台无关的编程语言。Java 在很大程度上已被现代应用程序取代，且在大多数浏览器中不再直接受支持。然而，您仍应对 Java 有基本的了解，因为它可能仍在内部使用，或受贵组织实施的特定浏览器支持。虽然现代网页设计已摒弃 Java，但这并不意味着 Java 已从互联网上彻底清除。大多数编程语言使用编译器生成针对特定操作系统定制的应用程序。这需要使用多个编译器为单个应用程序生成不同版本，以支持每个平台。Java 通过引入 `Java 虚拟机 (JVM)` 克服了这一限制。每个运行 Java 代码的系统都会下载其操作系统支持的 JVM 版本。然后 JVM 获取 Java 代码并将其转换为该特定系统可执行的格式。这种安排的巨大好处是代码可以在操作系统之间共享而无需修改。Java 小程序就是通过互联网传输的简短 Java 程序，用于在远程系统上执行操作。

安全性是 Java 平台设计期间的重中之重，Sun 的开发团队创建了“沙箱”概念，对 Java 代码施加权限限制。沙箱将 Java 代码对象与操作系统的其余部分隔离开来，并强制执行关于这些对象可访问资源的严格规则。例如，沙箱会禁止 Java 小程序从未专门分配给它的内存区域检索信息，防止小程序窃取该信息。不幸的是，虽然沙箱减少了可通过 Java 发起的恶意事件形式，但仍有许多其他漏洞被广泛利用。

#### ActiveX 控件

`ActiveX` 控件是微软针对 Sun 的 Java 小程序推出的对应产品。它们的运作方式类似，但使用多种语言实现，包括 Visual Basic、C、C++ 和 Java。Java 小程序和 ActiveX 控件之间有两个关键区别。首先，ActiveX 控件使用微软专有技术，因此只能在运行微软浏览器的系统上执行。其次，ActiveX 控件不受 Java 小程序所受沙箱限制的约束。它们拥有对 Windows 操作环境的完全访问权，并可执行许多特权操作。因此，在决定下载和执行哪些 ActiveX 控件时，必须采取特别预防措施。一些安全管理员采取了相当严厉的立场，禁止从极少数受信任站点之外的任何站点下载 ActiveX 内容。

ActiveX 仍受 Internet Explorer 11 支持，但随 Windows 10 发布的微软最新浏览器 Edge 不包含对 ActiveX 的支持。这表明微软正在逐步淘汰 ActiveX。
