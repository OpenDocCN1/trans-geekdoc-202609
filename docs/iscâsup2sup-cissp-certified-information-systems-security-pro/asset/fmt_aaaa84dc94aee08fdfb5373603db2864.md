
# DNS 攻击与防御

## 部署流氓 DNS 服务器（DNS 欺骗/药水攻击）

**部署流氓 DNS 服务器（也称为 DNS 欺骗或 DNS 药水攻击）。** *流氓 DNS* 服务器可以监听网络流量中的任何 DNS 查询或与目标站点相关的特定 DNS 查询。然后，流氓 DNS 服务器向客户端发送包含虚假 IP 信息的 DNS 响应。此攻击要求流氓 DNS 服务器在真实 DNS 服务器响应之前将其响应返回给客户端。一旦客户端收到来自流氓 DNS 服务器的响应，客户端就会关闭 DNS 查询会话，这会导致来自真实 DNS 服务器的响应被丢弃并作为会话外数据包被忽略。

DNS 查询未经过身份验证，但它们确实包含一个称为 *查询 ID* (QID) 的 16 位值。DNS 响应必须包含与查询相同的 QID 才会被接受。因此，流氓 DNS 服务器必须在虚假回复中包含请求的 QID。

## 执行 DNS 投毒

**执行 DNS 投毒。** *DNS 投毒* 涉及攻击真实 DNS 服务器并在其区域文件中放置不正确的信息。这会导致真实 DNS 服务器向客户端发回虚假数据。

## 篡改 HOSTS 文件

**篡改 HOSTS 文件。** 通过在客户端的 HOSTS 文件中放置虚假 DNS 数据来修改该文件，可将用户重定向到虚假位置。

## 损坏 IP 配置

**损坏 IP 配置。** 损坏 IP 配置可能导致客户端拥有虚假的 DNS 服务器定义。这可以直接在客户端上完成，也可以在网络的 DHCP 服务器上完成。

## 使用代理伪造

**使用代理伪造。** 此方法仅对 Web 通信有效。此攻击在客户端浏览器中植入虚假 Web 代理数据，然后攻击者运行流氓代理服务器。流氓代理服务器可以修改 HTTP 流量数据包，将请求重定向到黑客想要的任何站点。

尽管存在多种 DNS 投毒方法，但以下是一些基本安全措施，可大大降低其威胁：

*   限制从内部 DNS 服务器到外部 DNS 服务器的区域传送。这通过阻止入站 TCP 端口 53（区域传送请求）和 UDP 端口 53（查询）来实现。
*   限制内部 DNS 服务器拉取区域传送的外部 DNS 服务器。
*   部署 *网络入侵检测系统 (NIDS)* 以监视异常 DNS 流量。
*   妥善加固专用网络中的所有 DNS、服务器和客户端系统。
*   使用 DNSSEC 保护 DNS 基础设施。
*   要求内部客户端通过内部 DNS 解析所有域名。这将要求您阻止出站 UDP 端口 53（用于查询），同时保持出站 TCP 端口 53（用于区域传送）开放。

*与 DNS 投毒和/或 DNS 欺骗密切相关的另一种攻击是 DNS 药水攻击。* *药水攻击* 是将有效网站的 URL 或 IP 地址恶意重定向到托管原始有效站点虚假版本的假网站。这通常是网络钓鱼攻击的一部分，攻击者试图诱骗受害者泄露其登录凭据。如果潜在受害者不小心或不注意，他们可能会被诱骗向虚假的药水网站提供其登录信息。药水攻击通常通过修改系统上的本地 HOSTS 文件，或通过投毒或欺骗 DNS 解析来发生。药水攻击是一个日益严重的问题，因为黑客已经发现了利用 DNS 漏洞对大量目标用户进行各种域名药水攻击的方法。

## 域名劫持

*域名劫持*，或 *域名盗窃*，是指未经合法所有者授权，恶意更改域名注册信息的行为。这可以通过窃取所有者的登录凭据、使用 XSRF、劫持会话、使用 MitM（有关这些攻击的介绍，请参见第 21 章“恶意代码和应用程序攻击”），或利用域名注册商系统中的缺陷来实现。

有时，当另一个人在原所有者注册过期后立即注册该域名时，这被称为 *域名劫持*，但这并不准确。这是一种潜在的不道德行为，但并非实际的黑客攻击或攻击。这是利用了原所有者未能手动延长注册或配置自动续费的疏忽。如果原所有者因未能维护注册而失去域名，通常别无选择，只能联系新所有者并询问能否重新获得控制权。许多注册商对过期注册采取“先到先得”政策。

当组织失去域名且其他人接管控制权时，这对组织及其客户和访问者来说都是毁灭性的事件。原网站或在线内容将不再可用（或至少无法在同一域名下访问）。新所有者可能会托管完全不同的内容，或托管前一个站点的虚假副本。这种后一种活动可能会欺骗访问者，类似于网络钓鱼攻击，从而提取和收集个人身份信息 (PII)。

域名劫持的一个例子是 2017 年 9 月 Fox-IT.com 域名被盗；您可以在 [https://www.fox-it.com/en/insights/blogs/blog/fox-hit-cyber-attack/](https://www.fox-it.com/en/insights/blogs/blog/fox-hit-cyber-attack/) 阅读有关此次攻击的信息。

# 融合协议

*融合协议* 是将专用或专有协议与标准协议（如 TCP/IP 套件中的协议）合并。融合协议的主要优势是能够使用现有的支持 TCP/IP 的网络基础设施来托管特殊或专有服务，而无需部署替代网络硬件的独特部署。这可以带来显著的成本节约。然而，并非所有融合协议都能提供与其专有实现相同级别的吞吐量或可靠性。此处介绍了一些常见的融合协议示例：

## 以太网光纤通道 (FCoE)

**以太网光纤通道 (FCoE)** *光纤通道* 是一种网络数据存储解决方案（*存储区域网络 [SAN]* 或 *网络附属存储 [NAS]*），允许高达 128 Gbps 以上的高速文件传输。它设计为在光纤电缆上运行；后来增加了对铜缆的支持以提供成本较低的选项。光纤通道通常需要自己的专用基础设施（单独的电缆）。但是，可以使用 *以太网光纤通道 (FCoE)* 在现有网络基础设施上支持它。FCoE 用于在以太网网络上封装光纤通道通信。它通常需要 10 Gbps 以太网才能支持光纤通道协议。使用此技术，光纤通道作为网络层或 OSI 第 3 层协议运行，取代 IP 作为标准以太网网络的有效载荷。

## MPLS (多协议标签交换)

**MPLS (多协议标签交换)** *MPLS (多协议标签交换)* 是一种高吞吐量、高性能的网络技术，它根据短路径标签而非较长的网络地址跨网络传输数据。与可能非常复杂的传统基于 IP 的路由过程相比，此技术可节省大量时间。此外，MPLS 设计用于通过封装处理各种协议。因此，网络不限于 TCP/IP 和兼容协议。这使得许多其他网络技术得以使用，包括 T1/E1、ATM、帧中继、SONET 和数字用户线路 (DSL)。

## 互联网小型计算机系统接口 (iSCSI)

**互联网小型计算机系统接口 (iSCSI)** *互联网小型计算机系统接口 (iSCSI)* 是一种基于 IP 的网络存储标准。此技术可用于在 LAN、WAN 或公共互联网连接上实现位置无关的文件存储、传输和检索。iSCSI 通常被视为光纤通道的低成本替代方案。
