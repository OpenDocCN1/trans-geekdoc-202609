
[图 20.7](#c20.xhtml#figure20-7) 中的层次模型是一个公司组织架构图。请注意，一对多的数据模型在此例中成立。每位员工仅有一位经理（即一对多中的“一”），但每位经理可能有一名或多名（即一对多中的“多”）员工。层次数据模型的其他示例包括 NCAA 疯狂三月锦标赛系统，以及互联网上用于域名系统 (DNS) 记录的层次化分发。层次数据库以这种层次化方式存储数据，适用于符合该模型的专业应用。例如，生物学家可能会使用层次数据库，根据该领域使用的界/门/纲/目/科/属/种层次模型来存储标本数据。

分布式数据模型将数据存储在多个数据库中，但这些数据库在逻辑上是相连的。用户将数据库视为一个单一实体，尽管它由通过网络互联的众多部分组成。每个字段可以有多个子项，也可以有多个父项。因此，分布式数据库的数据映射关系是多对多。

### 关系数据库

关系数据库由由行和列组成的扁平二维表构成。事实上，每个表看起来类似于电子表格文件。行和列的结构提供了一对一的数据映射关系。关系数据库的主要构建模块是表（也称为*关系*）。每个表包含一组相关记录。例如，销售数据库可能包含以下表：

*   **客户表**，包含组织所有客户的联系信息
*   **销售代表表**，包含组织销售团队的身份信息
*   **订单表**，包含每位客户下达的订单记录

每个表包含若干属性，或称为*字段*。每个属性对应表中的一列。例如，**客户表**可能包含公司名称、地址、城市、州、邮政编码和电话号码等列。每位客户都有自己的记录，或称为*元组*，由表中的一行表示。关系中的行数称为*基数*，列数称为*度*。属性的*域*是该属性可取的允许值集合。[图 20.8](#c20.xhtml#figure20-8) 展示了一个来自关系数据库的**客户表示例**。

![图 20.8 来自关系数据库的客户表 ](images/c20f008.jpg)

[**图 20.8**](#c20.xhtml#figureanchor20-8) 来自关系数据库的客户表

在此例中，该表的基数为 3（对应表中的三行），度为 8（对应八列）。在正常业务过程中，表的基数发生变化是常见的，例如当销售代表添加新客户时。表的度通常不会频繁变化，且通常需要数据库管理员介入。

表之间的关系被定义用于识别相关记录。在此例中，**客户表**和**销售代表表**之间存在关系，因为每位客户被分配一位销售代表，而每位销售代表被分配给一位或多位客户。该关系体现在[图 20.8](#c20.xhtml#figure20-8) 所示的**客户表**中的**销售代表**字段/列中。该列中的值引用了**销售代表表**（未显示）中包含的**销售代表 ID** 字段。此外，**客户表**和**订单表**之间也可能存在关系，因为每个订单必须与一位客户关联，而每位客户与一个或多个产品订单关联。**订单表**（未显示）可能包含一个**客户**字段，其中包含[图 20.8](#c20.xhtml#figure20-8) 中所示的**客户 ID** 值之一。

记录通过各种键来识别。简单来说，*键*是表字段的一个子集，用于唯一标识记录。它们也用于在需要交叉引用信息时连接表。你应该熟悉三种类型的键：

**候选键** *候选键*是可用于唯一标识表中任意记录的属性子集。同一表中的任意两条记录，其组成候选键的所有属性值绝不会完全相同。每个表可能有一个或多个候选键，这些候选键从列标题中选出。

**主键** *主键*是从表的候选键集合中选出，用于唯一标识表中记录的键。每个表仅有一个主键，由数据库设计者从候选键集合中选定。RDBMS 通过禁止插入具有相同主键的多条记录来强制主键的唯一性。在[图 20.8](#c20.xhtml#figure20-8) 所示的**客户表**中，**客户 ID** 很可能是主键。

**外键** *外键*用于强制执行两个表之间的关系，也称为*参照完整性*。参照完整性确保如果一个表包含外键，它对应于关系中另一个表中仍然存在的主键。它确保没有记录/元组/行包含对不存在的记录/元组/行的主键的引用。在前面描述的示例中，[图 20.8](#c20.xhtml#figure20-8) 中所示的**销售代表**字段是引用**销售代表表**主键的外键。

所有关系数据库都使用标准语言结构化查询语言 (SQL)，为用户提供一致的接口，用于数据的存储、检索和修改，以及对 DBMS 的管理控制。每个 DBMS 供应商实现的 SQL 版本略有不同（如 Microsoft 的 Transact-SQL 和 Oracle 的 PL/SQL），但都支持一组核心功能。SQL 的主要安全特性是其授权的粒度。这意味着 SQL 允许你在非常精细的层面上设置权限。你可以按表、行、列，甚至在某些情况下限制到单个单元格来限制用户访问。

SQL 为管理员、开发人员和最终用户提供了与数据库交互所需的完整功能。事实上，当今流行的图形化数据库界面仅仅是在标准 SQL 接口外包装了一些额外的花哨功能来连接 DBMS。SQL 本身分为两个不同的组件：数据定义语言 (DDL)，允许创建和修改数据库的结构（称为*模式*）；以及数据操作语言 (DML)，允许用户与该模式中包含的数据进行交互。

### 数据库事务

关系数据库支持显式和隐式使用事务以确保数据完整性。每个事务是一组离散的 SQL 指令，将作为一个整体要么成功要么失败。事务的某一部分成功而另一部分失败是不可能的。考虑银行两个账户之间转账的例子。你可能会使用以下 SQL 代码，先给账户 1001 增加 250 美元，然后从账户 2002 扣除 250 美元：

```
BEGIN TRANSACTION
UPDATE accounts
SET balance = balance + 250
WHERE account_number = 1001;

UPDATE accounts
SET balance = balance – 250
WHERE account_number = 2002

END TRANSACTION
```
