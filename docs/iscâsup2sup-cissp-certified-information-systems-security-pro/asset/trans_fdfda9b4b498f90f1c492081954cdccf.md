静态驻留在存储设备上的数据相当容易保护。只要维持物理访问控制并实施合理的逻辑访问控制，存储的文件就能保持机密性、保持完整性，并可供授权用户使用。然而，一旦数据被应用程序使用或通过网络连接传输，保护它的过程就会变得困难得多。

通信安全涵盖了与电子信息从一处传输到另一处相关的广泛问题。这种传输可能发生在星球两端的系统之间，也可能发生在同一企业网络上的系统之间。一旦涉及任何传输手段，数据就会面临大量针对其机密性、完整性和可用性的威胁。幸运的是，通过适当的对策，可以减少或消除许多此类威胁。

通信安全旨在检测、预防甚至纠正数据传输错误（即提供完整性保护以及机密性）。这是为了在支持数据交换和共享需求的同时维持网络安全。本章涵盖了通信安全的多种形式、漏洞和对策。

CISSP 认证考试的通信与网络安全领域涉及与网络组件（即网络设备和协议）相关的主题，具体包括它们如何工作以及它们与安全的相关性。本领域在本章和第 11 章“安全网络架构与网络组件安全”中进行了讨论。请务必阅读并学习这两章的内容，以确保全面覆盖 CISSP 认证考试所需的核心材料。

## 网络与协议安全机制

`传输控制协议/互联网协议 (TCP/IP)` 是大多数网络和互联网上使用的主要协议套件。它是一个健壮的协议套件，但存在许多安全缺陷。为了改进 `TCP/IP` 的安全性，已经开发了许多子协议、机制或应用程序，以保护传输数据的机密性、完整性和可用性。重要的是要记住，即使有了 `TCP/IP` 这个基础协议套件，互联网上仍在使用成百上千个单独的协议、机制和应用程序。其中一些旨在提供安全服务。一些保护完整性，另一些保护机密性，还有一些提供认证和访问控制。在接下来的章节中，我们将讨论一些更常见的网络和协议安全机制。

### 安全通信协议

为特定应用程序通信信道提供安全服务的协议称为安全通信协议。以下列表包含部分可用选项：

*   **`IPsec`**：互联网协议安全 (`IPsec`) 使用公钥密码学来提供加密、访问控制、不可抵赖性和消息认证，所有这些均使用基于 IP 的协议。`IPsec` 的主要用途是虚拟专用网络 (`VPNs`)，因此 `IPsec` 可以在传输模式或隧道模式下运行。`IPsec` 在第 7 章“PKI 与密码学应用”中有进一步讨论。
*   **`Kerberos`**：`Kerberos` 为用户提供单点登录解决方案，并为登录凭据提供保护。现代 `Kerberos` 实现使用混合加密来提供可靠的认证保护。`Kerberos` 在第 13 章“密码学与对称密钥算法”中有进一步讨论。
*   **`SSH`**：安全外壳 (`SSH`) 是端到端加密技术的一个很好的例子。此安全工具可用于加密多种明文实用程序（如 `rcp`、`rlogin`、`rexec`），充当协议加密器（如用于 `SFTP`），并可用作 `VPN`。
*   **`Signal 协议`**：这是一种加密协议，为语音通信、视频会议和文本消息服务提供端到端加密。`Signal 协议` 是非联邦制的，是名为 Signal 的即时通讯应用的核心要素。
*   **`安全远程过程调用 (S-RPC)`**：这是一种认证服务，仅仅是一种防止在远程系统上未经授权执行代码的手段。
*   **`安全套接字层 (SSL)`**：这是由 Netscape 开发的一种加密协议，用于保护 Web 服务器和 Web 浏览器之间的通信。`SSL` 可用于保护 Web、电子邮件、文件传输协议 (`FTP`) 甚至 Telnet 流量。它是一种面向会话的协议，提供机密性和完整性。`SSL` 使用 40 位密钥或 128 位密钥部署。`SSL` 已被传输层安全 (`TLS`) 取代。
*   **`传输层安全 (TLS)`**：`TLS` 的运作方式与 `SSL` 大体相同，但它使用更强的认证和加密协议。

`SSL` 和 `TLS` 都具有以下特性：

*   支持跨不安全网络的安全客户端-服务器通信，同时防止篡改、欺骗和窃听。
*   支持单向认证。
*   支持使用数字证书的双向认证。
*   通常作为 `TCP` 数据包的初始载荷实现，允许其封装所有高层协议载荷。
*   可在较低层实现，如第 3 层（网络层）以作为 `VPN` 运行。这种实现称为 `OpenVPN`。

此外，`TLS` 可用于加密用户数据报协议 (`UDP`) 和会话发起协议 (`SIP`) 连接。(`SIP` 是与 IP 语音 [`VoIP`] 相关的协议。)
