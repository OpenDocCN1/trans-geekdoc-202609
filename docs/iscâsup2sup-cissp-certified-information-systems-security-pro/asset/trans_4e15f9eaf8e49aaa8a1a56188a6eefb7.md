
端口列表的最后一行 `443/tcp closed https` 表明存在一条防火墙规则允许访问 443 端口，但没有服务在该端口上监听。443 端口由超文本传输安全协议（HTTPS）用于接受加密的 Web 服务器连接。

从这些结果中我们能学到什么？被扫描的系统很可能是一台 Web 服务器，它公开接受来自扫描系统的连接请求。扫描器与该系统之间的防火墙配置为允许安全（443 端口）和不安全（80 端口）连接，但服务器并未设置为实际执行加密事务。该服务器还开放了一个管理端口，可能允许命令行连接。

阅读这些结果的攻击者可能会对系统做出一些观察，从而进行进一步探测：

*   将 Web 浏览器指向该服务器，很可能会很好地了解服务器的功能及其运营者。只需在浏览器地址栏输入 `http://52.4.85.159` 即可能揭示有用信息。[图 15.2](#c15.xhtml#figure15-2) 显示了执行此操作的结果：该站点运行的是 Apache Web 服务器的默认安装版本。
*   与该服务器的连接未加密。如果可能，窃听这些连接可能会泄露敏感信息。
*   开放的 SSH 端口是一个有趣的发现。攻击者可能会尝试针对该端口上的管理账户进行暴力破解密码攻击，以获取系统访问权限。

### 网络漏洞扫描

*网络漏洞扫描* 比发现扫描更深入。它们不仅检测开放端口，还会继续探测目标系统或网络是否存在已知漏洞。这些工具包含数千个已知漏洞的数据库，以及可用于识别系统是否易受数据库中每个漏洞影响的测试。

当扫描器测试系统漏洞时，它使用数据库中的测试来确定系统是否可能包含该漏洞。在某些情况下，扫描器可能没有足够的信息来确定性地判断漏洞是否存在，从而在实际上不存在问题时报告漏洞。这种情况称为*误报*，有时被系统管理员视为麻烦。更危险的是，漏洞扫描器遗漏了漏洞，未能提醒管理员存在危险情况。这种错误称为*漏报*。

默认情况下，网络漏洞扫描器运行未认证扫描。它们在没有密码或其他授予扫描器特殊权限的特殊信息的情况下测试目标系统。这使扫描能够从攻击者的角度运行，但也限制了扫描器全面评估可能漏洞的能力。提高扫描准确性并减少误报和漏报的一种方法是对系统执行*认证扫描*。在这种方法中，扫描器拥有对被扫描服务器的只读访问权限，并可利用此访问权限从目标系统读取配置信息，在分析漏洞测试结果时使用这些信息。

![FIGURE 15.4 Network vulnerability scan of the same web server that was port scanned in Figure 15.1](images/c15f004.jpg)

[**图 15.4**](#c15.xhtml#figureanchor15-4) 图 15.1 中端口扫描的同一 Web 服务器的网络漏洞扫描

[图 15.4](#c15.xhtml#figure15-4) 所示的扫描结果非常干净，代表了一个维护良好的系统。没有严重漏洞，只有两个与扫描系统上运行的 SSH 服务相关的低风险漏洞。虽然系统管理员可能希望调整 SSH 加密设置以消除这些低风险漏洞，但这对管理员来说是一份非常好的报告，确信系统管理得当。

Nessus 是常用的漏洞扫描器，但也有许多其他可用工具。其他流行的商业扫描器包括 Qualys 的 QualysGuard 和 Rapid7 的 NeXpose。开源的 OpenVAS 扫描器也拥有不断壮大的用户社区。

组织还可能对无线网络进行专门的漏洞评估。Aircrack 是常用于执行这些评估的工具，通过测试无线网络的加密和其他安全参数。它可结合被动监控技术使用，后者可能识别网络上的流氓设备。

### Web 漏洞扫描

Web 应用程序对企业安全构成重大风险。由于其本质，运行许多 Web 应用程序的服务器必须向互联网用户暴露服务。防火墙和其他安全设备通常包含允许 Web 流量无阻碍地通过到 Web 服务器的规则。Web 服务器上运行的应用程序复杂，且通常对底层数据库拥有特权访问。攻击者经常试图利用这些情况，使用结构化查询语言（SQL）注入和其他针对 Web 应用程序安全设计缺陷的攻击。

*Web 漏洞扫描器* 是专门用于搜寻 Web 应用程序已知漏洞的特殊工具。它们在任何安全测试计划中都发挥着重要作用，因为它们可能发现网络漏洞扫描器不可见的缺陷。当管理员运行 Web 应用程序扫描时，该工具使用自动化技术探测 Web 应用程序，通过操纵输入和其他参数来识别 Web 漏洞。然后该工具提供其发现的报告，通常包括建议的漏洞修复技术。[图 15.5](#c15.xhtml#figure15-5) 显示了使用 Nessus 漏洞扫描工具执行 Web 漏洞扫描的示例。此扫描针对运行在同一服务器上的 Web 应用程序，该服务器曾在[图 15.1](#c15.xhtml#figure15-1) 中接受网络发现扫描，在[图 15.4](#c15.xhtml#figure15-4) 中接受网络漏洞扫描。当你阅读[图 15.5](#c15.xhtml#figure15-5) 中的扫描报告时，请注意它检测到了网络漏洞扫描中未显示的漏洞。
