

# 软件设计师使用进程限制

软件设计师使用进程限制来限制程序的行为。简单来说，进程 `confinement` 允许进程仅对特定的内存位置和资源进行读写。这也被称为 `sandboxing`（沙箱隔离）。操作系统或其他安全组件会禁止非法的读/写请求。如果进程尝试发起超出其授权权限的操作，该操作将被拒绝。此外，还可能采取进一步的措施，例如记录违规尝试。必须符合更高安全等级的系统通常会记录所有违规行为，并以某种切实的方式做出响应。通常，违规进程会被终止。限制可以在操作系统本身中实现（例如通过进程隔离和内存保护），通过使用限制应用程序或服务来实现（例如 `www.sandboxie.com` 上的 Sandboxie），或者通过虚拟化或 Hypervisor 解决方案来实现（例如 VMware 或 Oracle 的 VirtualBox）。

## 边界

在系统上运行的每个进程都会被分配一个授权级别。授权级别告诉操作系统该进程可以做什么。在简单的系统中，可能只有两个授权级别：用户和内核。授权级别告诉操作系统如何为进程设置边界。进程的 `bounds`（边界）由对其可访问的内存地址和资源设置的限制组成。边界规定了进程被限制或包含在其中的区域。在大多数系统中，这些边界为每个进程划分出逻辑内存区域供其使用。操作系统负责强制执行这些逻辑边界，并禁止访问其他进程。更安全的系统可能需要物理边界的进程。物理边界要求每个受限进程在物理上与其他受限进程分离的内存区域中运行，而不仅仅是在同一内存空间中逻辑上受限。物理边界内存成本可能非常高，但它也比逻辑边界更安全。

## 隔离

当进程通过强制执行访问边界而被限制时，该进程将在隔离环境中运行。进程隔离确保任何行为仅影响与该隔离进程相关的内存和资源。`Isolation`（隔离）用于保护操作环境、操作系统（OS）内核以及其他独立应用程序。隔离是稳定操作系统的基本组成部分。无论出于善意还是恶意，隔离都能防止应用程序访问另一个应用程序的内存或资源。操作系统可能提供中介服务，例如剪切粘贴和资源共享（如键盘、网络接口和存储设备访问）。

这三个概念（限制、边界和隔离）使设计安全程序和操作系统变得更加困难，但它们也使实施更安全的系统成为可能。

## 控制

为确保系统安全，你需要允许主体仅访问授权的客体。`control`（控制）使用访问规则来限制主体对客体的访问。访问规则规定了哪些客体对每个主体是有效的。此外，一个客体可能对一种访问类型有效，但对另一种访问类型无效。一种常见的控制是文件访问控制。可以通过将文件设置为大多数用户只读、仅对拥有修改权限的一小部分用户可读写，来保护文件免遭修改。

既有强制访问控制，也有自主访问控制，通常分别称为强制访问控制（MAC）和自主访问控制（DAC）（有关访问控制的深入讨论，请参见第 14 章“控制和监控访问”）。对于强制控制，会考虑主体和客体的静态属性来确定访问的允许性。每个主体拥有定义其访问资源的许可或权限的属性。每个客体拥有定义其分类的属性。不同类型的安全方法以不同方式对资源进行分类。例如，如果安全系统能找到一条规则，允许具有主体 A 许可的主体访问具有客体 B 分类的客体，则授予主体 A 访问客体 B 的权限。

自主控制与强制控制的不同之处在于，主体有一定能力定义要访问的客体。在限制范围内，自主访问控制允许主体根据需要定义要访问的客体列表。此访问控制列表充当主体可修改的动态访问规则集。施加在修改上的约束通常与主体的身份有关。基于身份，主体可能被允许添加或修改定义对客体访问的规则。

强制和自主访问控制都通过主体限制对客体的访问。控制的主要目标是通过禁止授权或未授权主体的未授权访问，来确保数据的机密性和完整性。

## 信任与保证

适当的安全概念、控制和机制必须在设计和架构阶段之前及期间集成，以生成可靠的安全产品。安全问题不应作为事后补充添加；这会导致疏忽、成本增加和可靠性降低。一旦安全集成到设计中，就必须对其进行工程化、实施、测试、审计、评估、认证，最后授权。

`trusted system`（可信系统）是指所有保护机制协同工作，为多类用户处理敏感数据，同时保持稳定安全的计算环境的系统。`Assurance`（保证）简单定义为对安全需求满足程度的信心度。保证必须持续维护、更新和重新验证。如果可信系统经历已知变更，或已过相当长一段时间，均属实。无论哪种情况，都发生了某种层面的变更。变更往往是安全的对立面；它常会削弱安全。因此，每当发生变更时，都需要重新评估系统，以验证其先前提供的安全级别是否仍然完好。保证因系统而异，必须在单个系统上建立。然而，可以跨同类型的众多系统、支持相同服务的系统或部署在相同地理位置的系统，建立保证等级或级别。因此，信任可以通过实施特定安全功能构建到系统中，而保证则是在现实场景中对这些安全功能的可靠性和可用性的评估。

# 理解安全模型的基本概念

在信息安全领域，模型提供了一种将安全策略形式化的方法。此类模型可以是抽象的或直观的（有些是明确数学化的），但所有模型旨在提供一组显式规则，计算机可遵循这些规则来实现构成安全策略的基本安全概念、过程和程序。这些模型提供了一种途径，加深你对计算机操作系统应如何设计和开发以支持特定安全策略的理解。

`security model`（安全模型）为设计师提供了一种将抽象陈述映射为安全策略的方法，该策略规定了构建硬件和软件所需的算法和数据结构。因此，安全模型给软件设计师提供了一个衡量其设计和实现的标准。当然，该模型必须支持安全策略的每个部分。这样，开发人员可以确信其安全实现支持安全策略。
