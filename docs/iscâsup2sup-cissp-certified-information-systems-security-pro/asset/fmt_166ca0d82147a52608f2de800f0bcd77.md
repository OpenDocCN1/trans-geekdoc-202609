
# 信息流模型

**信息流模型**侧重于信息的流动。信息流模型基于状态机模型。本章稍后将详细讨论的 **Bell-LaPadula** 和 **Biba** 模型都是信息流模型。Bell-LaPadula 关注防止信息从高安全级别流向低安全级别。Biba 关注防止信息从低安全级别流向高安全级别。信息流模型不仅处理信息流动的方向，还可以处理流动的类型。

信息流模型旨在防止未经授权、不安全或受限的信息流动，通常发生在不同安全级别之间（这些通常被称为多级模型）。信息流可以发生在相同分类级别的主体和客体之间，也可以发生在不同分类级别的主体和客体之间。信息流模型允许所有授权的信息流，无论是在同一分类级别内还是跨分类级别。它阻止所有未经授权的信息流，无论是在同一分类级别内还是跨分类级别。

信息流模型的另一个有趣视角是，它用于建立同一对象在不同时间点存在的两个版本或状态之间的关系。因此，信息流决定了对象从一个时间点的一个状态转换到另一个时间点的另一个状态。信息流模型还通过明确排除所有未定义的流路径来解决隐蔽信道问题。

## 非干扰模型

**非干扰模型**大致基于信息流模型。然而，非干扰模型关注的不是信息流动，而是高安全级别主体的行为如何影响系统状态或低安全级别主体的行为。基本上，主体 A（高）的行为不应影响主体 B（低）的行为，甚至不应被主体 B 察觉。真正的关注点是防止高安全分类级别的主体 A 的行为影响较低级别的系统状态。如果发生这种情况，主体 B 可能会被置于不安全状态，或能够推断出关于更高分类级别的信息。这是一种信息泄露，并隐式地创建了一个隐蔽信道。因此，可以实施非干扰模型，以提供一种防止木马等恶意程序造成损害的保护形式。

## Take-Grant 模型

**Take-Grant 模型**采用有向图（[图 8.2](#c08.xhtml#figure8-2)）来规定权限如何从一个主体传递给另一个主体，或从主体传递给客体。简单来说，拥有 `grant` 权限的主体可以将其拥有的任何其他权限授予另一个主体或客体。同样，拥有 `take` 权限的主体可以从另一个主体获取权限。除了这两条主要规则外，Take-Grant 模型还可以采用 `create` 规则和 `remove` 规则来生成或删除权限。该模型的关键在于，使用这些规则可以推断出系统中权限何时会发生变化，以及泄露（即权限的非预期分发）可能发生在何处。

![图 8.2 Take-Grant 模型的有向图](images/c08f002.jpg)

**[图 8.2](#c08.xhtml#figureanchor8-2)** Take-Grant 模型的有向图

| 规则 | 说明 |
| --- | --- |
| Take 规则 | 允许主体获取对客体的权限 |
| Grant 规则 | 允许主体授予客体权限 |
| Create 规则 | 允许主体创建新权限 |
| Remove 规则 | 允许主体移除其拥有的权限 |

## 访问控制矩阵

**访问控制矩阵**是一个主体和客体的表格，指示每个主体可以在每个客体上执行的操作或功能。矩阵的每一列是一个访问控制列表（ACL）。矩阵的每一行是一个**能力列表**。ACL 与客体绑定；它列出了每个主体可以执行的有效操作。能力列表与主体绑定；它列出了可以在每个客体上采取的有效操作。从管理角度来看，仅使用能力列表进行访问控制是一场管理噩梦。基于能力列表的访问控制方法可以通过在每个主体上存储其对每个客体拥有的权限列表来实现。这实际上为每个用户提供了一串钥匙，包含对安全域内对象的访问权限。要移除对特定客体的访问，必须单独操作每个拥有访问权限的用户（主体）。因此，在每个用户账户上管理访问比在每个客体上管理访问（即通过 ACL）要困难得多。

实施访问控制矩阵模型通常涉及以下步骤：

*   构建一个可以创建和管理主体及客体列表的环境
*   编写一个函数，该函数能返回作为输入提供给该函数的任何客体相关联的类型（这很重要，因为客体的类型决定了可以对其应用什么样的操作）

[表 8.1](#c08.xhtml#table8-1) 中所示的访问控制矩阵用于自主访问控制系统。只需将主体名称替换为分类或角色，即可构建强制或基于规则的矩阵。系统使用访问控制矩阵快速确定主体对客体请求的操作是否被授权。

## Bell-LaPadula 模型

美国国防部（DoD）在 20 世纪 70 年代开发了 **Bell-LaPadula 模型**，以解决保护机密信息的问题。DoD 管理多级机密资源，Bell-LaPadula 多级模型源自 DoD 的多级安全策略。DoD 使用的分类众多；然而，CISSP 通用知识体系（CBK）中对分类的讨论通常仅限于非机密、敏感但非机密、机密、秘密和绝密。多级安全策略规定，具有任何级别许可的主体可以访问其许可级别或以下的资源。然而，在较高许可级别内，访问仅基于“需知”原则授予。换句话说，仅当特定工作任务需要时，才向机密级别授予对特定客体的访问权限。例如，任何拥有秘密安全许可的人都可以访问秘密、机密、敏感但非机密和非机密文档，但不能访问绝密文档。此外，要访问秘密级别的文档，寻求访问的人员还必须对该文档有“需知”需求。
