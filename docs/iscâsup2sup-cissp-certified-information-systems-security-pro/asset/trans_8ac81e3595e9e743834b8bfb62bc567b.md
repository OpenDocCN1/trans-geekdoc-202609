

# 安全治理

安全治理通常由治理委员会或至少由董事会管理。这是一群有影响力的知识专家，其主要任务是监督和指导组织的安全与运营行动。安全是一项复杂的任务。组织通常规模庞大，从单一视角难以全面理解。让一群专家共同朝着可靠安全治理的目标努力，是一项可靠的策略。

存在许多安全框架和治理指南，包括 `NIST 800-53` 或 `NIST 800-100`。虽然 NIST 指南侧重于政府和军事用途，但也可被其他类型的组织采纳和调整。许多组织采用安全框架，旨在标准化和组织可能变得复杂且令人困惑不已的活动，即尝试实施合理的安全治理。

## 安全职能与业务战略、目标、使命和客观的对齐

安全管理规划确保 `安全策略` 的正确创建、实施和强制执行。安全管理规划将安全职能与组织的战略、目标、使命和客观相对齐。这包括基于业务案例、预算限制或资源稀缺性来设计和实施安全。`业务案例` 通常是一种有文档记录的论证或陈述立场，旨在定义需求以做出决策或采取某种形式的行动。制作业务案例是为了证明修改现有流程或选择某种业务任务方法的业务特定需求。业务案例通常用于证明启动新项目（尤其是与安全相关的项目）的合理性。考虑可分配给基于业务需求的安全项目的预算也很重要。安全可能成本高昂，但通常比缺乏安全的成本要低。因此，安全成为可靠且长期业务运营的基本要素。在大多数组织中，资金和资源（如人员、技术和场地）都是有限的。鉴于这些资源限制，需要从任何工作中获得最大收益。

解决安全管理规划最有效的方法之一是采用 `自上而下的方法`。高层或资深管理层负责发起并定义组织的策略。安全策略为组织层级的所有层面提供方向。中层管理层的责任是将安全策略细化为标准、基线、指南和程序。运营管理人员或安全专业人员随后必须实施安全管理文档中规定的配置。最后，最终用户必须遵守组织的所有安全策略。

安全管理是高层管理的责任，而非 IT 员工的责任，被视为业务运营问题而非 IT 管理问题。组织内负责安全的团队或部门应当是自主的。`信息安全团队` 应由指定的首席信息安全官（CISO）领导，且 CISO 必须直接向高层管理汇报。将 CISO 及其团队的自主权置于组织典型的层级结构之外，可以改善整个组织的安全管理。这也有助于避免跨部门和内部政治问题。`首席安全官（CSO）` 一词有时用作 `CISO` 的替代称呼，但在许多组织中，CSO 职位是 CISO 下的从属职位，专注于物理安全。CISO 的另一个潜在术语是 `信息安全官（ISO）`，但这也可能被用作 CISO 下的从属职位。

安全管理规划的要素包括：定义安全角色；规定安全如何管理、谁负责安全以及如何测试安全有效性；制定安全策略；执行风险分析；以及要求员工接受安全教育。这些工作通过制定管理计划来指导。

最好的安全计划若缺少一个关键因素也将毫无用处：`高层管理的批准`。没有高层管理对安全策略的批准和承诺，该策略将不会成功。策略开发团队有责任对高层管理进行充分教育，使其理解即使部署了策略中规定的安全措施，仍然存在的风险、责任和暴露。制定和实施安全策略是高层管理尽到应有注意义务和应有勤勉义务的证据。如果公司不履行应有注意义务和应有勤勉义务，管理者可能因疏忽被追究责任，并对资产和财务损失负责。

### 战略计划

`战略计划` 是一项相当稳定的长期计划。它定义了组织的安全目的。它还有助于理解安全职能，并将其与组织的目标、使命和客观相对齐。如果每年维护和更新一次，其有效期约为五年。战略计划也作为规划远景。战略计划中讨论了长期目标和未来愿景。战略计划应包含风险评估。

### 战术计划

`战术计划` 是一项中短期计划，旨在为战略计划中设定的目标提供更多实现细节，或可根据不可预见的事件临时制定。战术计划通常有效期约为一年，且通常规定并安排实现组织目标所需的任务。战术计划的例子包括项目计划、采购计划、招聘计划、预算计划、维护计划、支持计划和系统开发计划。

### 操作计划

`操作计划` 是一项基于战略和战术计划的短期、高度详细的计划。其有效或有用时间较短。操作计划必须经常更新（如每月或每季度），以保持与战术计划的合规性。操作计划详细说明如何实现组织的各项目标。它们包括资源分配、预算要求、人员安排、进度安排以及分步或实施程序。操作计划包含实施过程如何符合组织安全策略的细节。操作计划的例子包括培训计划、系统部署计划和产品设计计划。

安全是一个持续的过程。因此，安全管理规划活动可能有一个明确的起点，但其任务和工作永远不会完全完成。有效的安全计划将关注点集中在具体且可实现的目标上，预测变化和潜在问题，并作为整个组织决策的基础。安全文档应具体、定义明确且表述清晰。为了使安全计划有效，必须对其进行开发、维护并实际使用。
