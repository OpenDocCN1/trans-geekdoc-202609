| EAL4 || 系统地设计、测试和评审 || 适用于采用严格、积极的安全工程和良好的商业开发实践时。这不需要大量的专业知识、技能或资源。它涉及对所有 TOE 安全功能的独立测试。 |

| EAL5 || 半形式化设计和测试 || 采用严格的安全工程和商业开发实践，包括专业的安全工程技术，用于半形式化测试。这适用于开发人员或用户在计划开发方法中需要高级别的独立保证安全性，随后进行严格开发的情况。 |

| EAL6 || 半形式化验证、设计和测试 || 在设计、开发和测试的所有阶段使用直接、严格的安全工程技术，以生产优质 TOE。这适用于高风险情况下所需的 TOE，此时受保护资产的价值足以证明额外成本的合理性。广泛的测试降低了渗透风险、隐蔽信道的可能性以及受攻击的脆弱性。 |

| EAL7 || 形式化验证、设计和测试 || 仅用于最高风险情况或涉及高价值资产的场合。这仅限于安全功能紧密聚焦、需接受大量形式化分析和测试的 TOE。 |

尽管 CC 准则足够灵活和包容，能够涵盖大多数安全需求和要求，但它们绝非完美。与其他评估标准一样，CC 准则无法确保用户对数据的操作也是安全的。CC 准则也不涉及安全特定职权范围之外的管理问题。与其他评估标准一样，CC 准则不包括对安全性的*实地*评估——即它们不涉及与人员、组织实践和程序或物理安全相关的控制。同样，电磁辐射控制未被涉及，密码算法强度评级的标准也未明确规定。尽管如此，CC 准则代表了对系统进行安全性评级的最佳技术之一。为结束对安全评估标准的讨论，[表 8.4](#c08.xhtml#table8-4) 总结了 TCSEC、ITSEC 和 CC 各项评级的对比情况。[表 8.4](#c08.xhtml#table8-4) 显示，每个标准的评级具有相似但不完全相同的评估标准。

### 行业与国际安全实施指南

除了通用准则等整体安全访问模型外，还有许多其他更具体或更聚焦的安全标准，适用于存储、通信、事务等各个方面。其中有两个标准你应该熟悉，它们是 `Payment Card Industry Data Security Standard (PCI DSS)` 和 `International Organization for Standardization (ISO)`。

`PCI DSS` 是一套旨在提高电子支付交易安全性的要求集合。这些标准由 `PCI Security Standards Council` 成员定义，成员主要为信用卡银行和金融机构。`PCI DSS` 定义了安全管理、策略、程序、网络架构、软件设计及其他关键防护措施的要求。有关 `PCI DSS` 的更多信息，请访问 [www.pcisecuritystandards.org](http://www.pcisecuritystandards.org)。

`ISO` 是一个由各国标准组织代表组成的全球标准制定团体。`ISO` 为工业和商业设备、软件、协议、管理等制定标准。它发布六大主要产品：国际标准、技术报告、技术规范、公开可用规范、技术勘误和指南。`ISO` 标准被广泛接受于许多行业，甚至被各国政府采纳为要求或法律。有关 `ISO` 的更多信息，请访问 [www.iso.org](http://www.iso.org)。

### 认证与认可

需要安全系统的组织需要一种或多种方法来评估系统在多大程度上满足其安全要求。正式评估过程分为两个阶段，称为 `certification`（认证）和 `accreditation`（认可）。每个阶段所需的实际步骤取决于组织选择的评估标准。`CISSP` 候选人必须理解每个阶段的必要性以及评估系统常用的标准。接下来两节将讨论这两个评估阶段，随后我们将介绍评估系统安全性时必须解决的各种评估标准和考量因素。认证和认可过程用于评估应用安全性、操作系统安全性以及硬件安全性的有效性。

评估过程提供了一种方法，用以评判系统在多大程度上达到期望的安全级别。由于每个系统的安全级别取决于许多因素，评估期间必须将所有因素纳入考量。即使系统最初被描述为安全，安装过程、物理环境和通用配置细节都会影响其真实的整体安全性。由于配置或安装差异，两个相同的系统可能被评估为不同的安全级别。

认证和认可是软件和 IT 系统开发过程中的额外步骤，通常是国防承包商和在军事环境中工作的人员所必需的。这些术语的官方定义（由美国政府使用）源自国防部指令 5200.40，附件 2。

#### 认证

完整评估过程的第一阶段是 `certification`（认证）。认证是对 IT 系统的技术和非技术安全特性及其他防护措施进行的全面评估，旨在支持认可过程，以确定特定设计和实现满足一组特定安全要求的程度。

系统认证是对计算机系统各部分进行的技术评估，以判定其与安全标准的一致性。首先，你必须选择评估标准（我们将在后续章节介绍备选标准）。一旦选定使用的标准，你就需分析每个系统组件，以确定其是否满足期望的安全目标。认证分析包括测试系统的硬件、软件和配置。此阶段评估所有控制措施，包括管理控制、技术控制和物理控制。
