
# 理解并应用机密性、完整性和可用性概念：保护机制

理解并应用机密性、完整性和可用性概念的另一个方面是**保护机制**（Protection Mechanisms）或**保护控制**（Protection Controls）的概念。保护机制是安全控制的共同特征。并非所有`security controls`都必须具备它们，但许多控制通过使用这些机制来为机密性、完整性和可用性提供保护。一些常见示例包括使用多层或多级访问、采用抽象、隐藏数据以及使用加密。

## 分层

**分层**（Layering），也称为**纵深防御**（Defense in Depth），简单来说就是串联使用多种控制。没有任何单一控制能防范所有可能的威胁。使用多层解决方案可使众多不同的控制防范可能发生的任何威胁。当安全解决方案采用分层设计时，单个控制的失效不应导致系统或数据暴露。

采用串联而非并联的方式使用层非常重要。以串联方式执行安全限制意味着按线性方式依次执行。只有通过串联配置，每次攻击才会被每个安全控制扫描、评估或缓解。在串联配置中，单个安全控制的失效不会导致整个解决方案失效。如果安全控制以并联方式实施，威胁可能通过单个未针对其特定恶意活动进行防范的检查点。

串联配置非常窄但非常深，而并联配置非常宽但非常浅。并联系统在分布式计算应用中很有用，但并行性在安全领域通常不是一个有用的概念。

请设想建筑物的物理入口。购物中心采用并联配置，在商场整个周边的许多位置设有许多门。银行或机场最可能采用串联配置。仅提供单一入口，而该入口实际上是必须按顺序通过的若干关口或检查点，才能进入建筑物的活动区域。

分层还包含这样一个概念：网络由许多独立实体组成，每个实体都有其自己独特的安全控制和漏洞。在有效的安全解决方案中，所有联网系统之间存在协同效应，从而形成单一的安全前沿。使用独立的安全系统可创建分层安全解决方案。

## 抽象

**抽象**（Abstraction）用于提高效率。将相似元素放入组、类或角色中，并将安全控制、限制或权限作为一个整体分配给它们。因此，在对对象进行分类或向主体分配角色时，会用到抽象概念。抽象概念还包括对象和主体类型的定义，或对象本身的定义（即用于定义一类实体模板的数据结构）。抽象用于定义对象可包含的数据类型、可在该对象上或由该对象执行的函数类型，以及该对象拥有的能力。抽象通过使您能够将安全控制分配给按类型或功能收集的一组对象，从而简化了安全性。

## 数据隐藏

**数据隐藏**（Data Hiding）顾名思义，就是通过将数据置于主体无法访问或看不见的逻辑存储区中，防止数据被主体发现或访问。数据隐藏的形式包括：防止未经授权的访问者访问数据库，限制较低分级的主体访问较高分级的数据。阻止应用程序直接访问硬件也是一种数据隐藏形式。数据隐藏通常是安全控制以及编程中的关键要素。

术语**通过隐匿实现安全**（Security through Obscurity）在此处可能看起来相关。然而，该概念是不同的。数据隐藏是有意定位数据，使其对未经授权的主体不可见或不可访问；而通过隐匿实现安全是指不告知主体某对象的存在，从而希望主体不会发现该对象。通过隐匿实现安全并未真正实施任何形式的保护，它只是试图通过保守秘密来希望重要事物不被发现。通过隐匿实现安全的一个例子是：程序员知道其软件代码中存在缺陷，但仍发布产品，希望没人发现并利用该问题。

## 加密

**加密**（Encryption）是向非预期接收者隐藏通信含义或意图的艺术与科学。加密可以采取多种形式，并可应用于每种类型的电子通信，包括文本、音频和视频文件以及应用程序本身。加密是安全控制中的重要元素，特别是在系统间数据传输方面。加密有多种强度，每种强度均为特定用途或目的而设计和/或适用。弱或差的加密可被视为仅是混淆，甚至可能是通过隐匿实现安全。加密将在第 6 章“密码学和对称密钥算法”和第 7 章“PKI 和密码学应用”中详细讨论。

# 评估并应用安全治理原则

**安全治理**（Security Governance）是与支持、定义和指导组织安全工作相关的实践集合。安全治理原则通常与企业治理和 IT 治理密切相关且交织在一起。这三种治理议程的目标通常相同或相互关联。例如，组织治理的一个共同目标是确保组织持续存在并随时间增长或扩展。因此，治理的共同目标是在追求增长和弹性的同时维持业务流程。

治理的某些方面因立法和法规遵从性需求而被强加给组织，而其他方面则由行业指南或许可要求强加。所有形式的治理（包括安全治理）都必须不时进行评估和验证。由于政府法规或行业最佳实践，可能存在各种审计和验证要求。治理合规问题往往因行业和国家而异。随着许多组织扩展并适应全球市场，治理问题变得更加复杂。当不同国家的法律存在差异甚至冲突时，这尤其成问题。组织作为一个整体，应获得方向、指导和工具，以提供充分的监督和管理，重点消除停机时间，将潜在损失或损害降至最低。

正如您所见，安全治理的定义通常相当生硬且高层。归根结底，安全治理是紧密互联的安全解决方案和管理方法的实施。安全治理直接监督并介入安全的所有层面。安全不应也不能仅被视为 IT 问题。相反，安全影响组织的各个方面。它不再仅仅是 IT 员工能自行处理的事情。安全是业务运营问题。安全是组织流程，而不仅仅是 IT 极客在幕后做的事。使用“安全治理”一词旨在强调这一观点，即安全需要在整个组织中进行管理和治理，而不仅仅是在 IT 部门。
