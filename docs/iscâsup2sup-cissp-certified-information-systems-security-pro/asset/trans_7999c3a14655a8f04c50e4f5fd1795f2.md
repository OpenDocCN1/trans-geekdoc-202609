

# 为什么计划安全如此重要？

其中一个原因是对 `due care`（应有注意）和 `due diligence`（应有勤勉）的要求。`Due care` 是指运用合理的注意来保护组织的利益。`Due diligence` 是指执行维持应有注意工作的活动。例如，应有注意是开发一个包含安全策略、标准、基线、指南和程序的正式安全架构。应有勤勉是将这一安全架构持续应用到组织的 IT 基础设施上。运营安全是组织内所有责任方对应有注意和应有勤勉的持续维护。

在当今的商业环境中，审慎是强制性的。展示应有注意和应有勤勉是发生损失时证明无过失的唯一途径。高级管理层必须展示应有注意和应有勤勉，以在损失发生时降低其责任和法律义务。

# 制定、记录并实施安全策略、标准、程序和指南

对于大多数组织而言，维护安全是持续业务的重要组成部分。如果其安全受到严重威胁，许多组织将面临倒闭。为了降低安全故障的可能性，实施安全的过程已通过文档的层级化组织而某种程度上正式化。每一层级侧重于特定类型或类别的信息和问题。制定并实施文档化的安全策略、标准、程序和指南，可构建可靠坚实的安全基础设施。这种正式化极大地减少了为 IT 基础设施设计和实施安全解决方案时的混乱与复杂性。

## 安全策略

正式化的顶层称为安全策略。`security policy`（安全策略）是一份定义组织所需安全范围的文档，论述需要保护的资产，以及安全解决方案为提供必要保护应达到的程度。安全策略是组织安全需求的概览或概括。它定义了主要安全目标，并概述了组织的安全框架。它还确定了数据处理的主要功能领域，并阐明和定义了所有相关术语。它应明确界定安全为何重要以及哪些资产有价值。它是实施安全的战略计划。它应广泛概述为保护组织关键利益而应采用的安全目标和实践。该文档论述了安全对日常业务运营各方面的重要性，以及高级管理层对安全实施的支持的重要性。安全策略用于分配职责、定义角色、指定审计要求、概述执行流程、表明合规要求，并定义可接受的风险级别。该文档常作为高级管理层已履行应有注意义务、保护自身免受入侵、攻击和灾害的证据。安全策略是强制性的。

许多组织采用多种类型的安全策略来定义或概述其整体安全战略。`organizational security policy`（组织安全策略）关注与组织各方面相关的问题。`issue-specific security policy`（特定议题安全策略）关注某个特定的网络服务、部门、职能或其他有别于整个组织的方面。`system-specific security policy`（特定系统安全策略）关注单个系统或系统类型，规定批准的硬件和软件，概述系统加固方法，甚至强制要求防火墙或其他特定安全控制。

除了这些聚焦类型的安全策略外，还有三大总体类别的安全策略：监管类、建议类和信息类。`regulatory policy`（监管策略）在行业或法律标准适用于您的组织时是必需的。该策略论述必须遵守的法规，并概述用于实现合规的程序。`advisory policy`（建议策略）论述可接受的行为和活动，并定义违规后果。它解释了高级管理层对组织内安全与合规的期望。大多数策略属于建议类。`informative policy`（信息策略）旨在提供关于特定主题的信息或知识，例如公司目标、使命宣言，或组织如何与合作伙伴和客户互动。信息策略提供与整体策略特定要素相关的支持、研究或背景信息。

从安全策略中衍生出许多其他文档或子要素，这些是完整安全解决方案所必需的。策略是宽泛的概览，而标准、基线、指南和程序则包含关于实际安全解决方案更具体、更详细的信息。标准是安全策略的下一层级。

## 安全标准、基线和指南

一旦确定了主要安全策略，其余安全文档即可在策略指导下编写。`Standards`（标准）定义了硬件、软件、技术和安全控制统一使用的强制性要求。它们提供了一种行动方针，使技术和程序在整个组织中统一实施。标准是战术文档，定义了为实现安全策略所定目标和总体方向而采取的步骤或方法。

下一层级是基线。`baseline`（基线）定义了组织内每个系统必须达到的最低安全级别。所有不符合基线的系统应停止投入生产，直到其达到基线要求。基线建立了一个通用的基础安全状态，所有额外的、更严格的安全措施均可在此基础上构建。基线通常针对特定系统，且常参考行业或政府标准，如可信计算机系统评价标准（TCSEC）、信息技术安全评估标准（ITSEC）或美国国家标准与技术研究院（NIST）标准。

指南是正式化安全策略结构的下一个要素。`guideline`（指南）提供关于如何实施标准和基线的建议，并作为安全专业人员和用户的操作指南。指南具有灵活性，可针对每个独特的系统或条件进行定制，并可用于创建新程序。它们陈述应部署哪些安全机制，而非规定特定产品或控制及详细配置设置。它们概述方法论，包含建议行动，且非强制性。

## 安全程序

程序是正式化安全策略结构的最后要素。`procedure`（程序）或 `standard operating procedure (SOP)`（标准操作程序）是一份详细的分步操作指南文档，描述实施特定安全机制、控制或解决方案所需的确切行动。程序可以论述整个系统部署操作，也可以聚焦于单个产品或方面，例如部署防火墙或更新病毒定义。在大多数情况下，程序针对特定系统和软件。随着系统软硬件的演进，程序必须更新。程序的目的是确保业务流程的完整性。如果所有工作都遵循详细程序执行，则所有活动应符合策略、标准和指南。程序有助于确保所有系统安全的标准化。
