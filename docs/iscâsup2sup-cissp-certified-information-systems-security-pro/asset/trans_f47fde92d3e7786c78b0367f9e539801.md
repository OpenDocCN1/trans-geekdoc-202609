

# 用户数据报协议 (UDP)

用户数据报协议 (UDP) 也工作在 OSI 模型的第 4 层（传输层）。它是一种无连接的“尽力而为”通信协议。它不提供错误检测或纠正，不使用排序，不使用流量控制机制，不使用预建立的会话，因此被认为是不可靠的。UDP 开销极低，因此可以快速传输数据。然而，UDP 应仅在数据交付非关键时使用。UDP 常被实时或流式通信用于音频和/或视频。UDP 的 IP 头部协议字段值为 17 (0x11)。

如前所述，与 TCP 头部相比，UDP 头部相对简单。UDP 头部长 8 字节（64 位）。该头部分为四个部分，或字段（每个长 16 位）：

*   `Source port`（源端口）
*   `Destination port`（目标端口）
*   `Message length`（消息长度）
*   `Checksum`（校验和）

## 网络层协议和 IP 网络基础

TCP/IP 协议套件中的另一个重要协议工作在 OSI 模型的网络层，即互联网协议 (IP)。IP 为数据包提供路由寻址。正是这种路由寻址构成了全球互联网通信的基础，因为它提供了一种标识手段并规定了传输路径。与 UDP 类似，IP 是无连接的，是一种不可靠的数据报服务。IP 不保证数据包会被交付，不保证数据包会按正确顺序交付，也不保证数据包仅被交付一次。因此，必须在 IP 上使用 TCP 以获得可靠且受控的通信会话。

### IP 类别

IP 寻址和 IP 类别的基础知识是任何安全专业人员的必修课。如果你对寻址、子网划分、类别及其他相关主题生疏了，请花时间复习一下。[表 11.3](#c11.xhtml#table11-3) 和 [表 11.4](#c11.xhtml#table11-4) 提供了类别和默认子网关键细节的快速概览。完整的 A 类子网支持 16,777,214 台主机；完整的 B 类子网支持 65,534 台主机；完整的 C 类子网支持 254 台主机。D 类用于组播，而 E 类保留供将来使用。

**表 11.3** **IP 类别**

| 类别 | 首位二进制数字 | 首个八位字节的十进制范围 |
| --- | --- | --- |
| A | 0 | 1–126 |
| B | 10 | 128–191 |
| C | 110 | 192–223 |
| D | 1110 | 224–239 |
| E | 1111 | 240–255 |

**表 11.4** **IP 类别的默认子网掩码**

| 类别 | 默认子网掩码 | CIDR 等效值 |
| --- | --- | --- |
| A | 255.0.0.0 | /8 |
| B | 255.255.0.0 | /16 |
| C | 255.255.255.0 | /24 |

请注意，整个 127 类 A 网络被预留用于 `loopback address`（回环地址），尽管实际上仅需一个地址即可实现该目的。

子网划分的另一种选择是使用 `Classless Inter-Domain Routing (CIDR)`（无类别域间路由）表示法。CIDR 使用掩码位而非完整的点分十进制子网掩码表示法。因此，CIDR 会在 IP 地址后加上斜杠，例如 `172.16.1.1/16`，而不是使用 255.255.0.0。CIDR 相较于传统子网掩码技术的一个显著优势是能够将多个不连续的地址集合合并为单个子网。例如，可以将多个 C 类子网合并为一个更大的子网组。如果你对 CIDR 感兴趣，请参阅维基百科上的 CIDR 条目，或访问 IETF 的 CIDR RFC 文档：[http://tools.ietf.org/html/rfc4632](http://tools.ietf.org/html/rfc4632)。

ICMP 和 IGMP 是 OSI 模型网络层的其他协议：

**ICMP** `Internet Control Message Protocol (ICMP)`（互联网控制消息协议）用于确定网络或特定链路的健康状况。`ping`、`traceroute`、`pathping` 和其他网络管理工具均使用 ICMP。`ping` 实用程序使用 ICMP 回显数据包并将其反弹至远程系统。因此，你可以使用 `ping` 来确定远程系统是否在线、远程系统是否及时响应、中间系统是否支持通信，以及中间系统通信的性能效率水平。`ping` 实用程序包含重定向功能，允许将回显响应发送到不同于源系统的目标。

不幸的是，ICMP 的特性常被利用于各种基于带宽的拒绝服务 (DoS) 攻击，例如死亡之 Ping、Smurf 攻击和 Ping 洪水攻击。这一事实塑造了当今网络处理 ICMP 流量的方式，导致许多网络限制 ICMP 的使用，或至少限制其吞吐率。死亡之 Ping 发送一个大于 65,535 字节（大于最大 IPv4 数据包大小）的畸形 Ping 给计算机，试图使其崩溃。Smurf 攻击通过伪造广播 Ping 在目标网络上产生巨大流量，而 Ping 洪水则是一种基本的 DoS 攻击，依赖于耗尽目标可用的所有带宽。

你应该了解关于 ICMP 的几个重要细节。首先，ICMP 的 IP 头部协议字段值为 1 (0x01)。其次，ICMP 头部中的类型字段定义了 ICMP 有效载荷中所含消息的类型或用途。已定义了 40 多种类型，但只有 7 种常用（见 [表 11.5](#c11.xhtml#table11-5)）。你可以在 [www.iana.org/assignments/icmp-parameters](http://www.iana.org/assignments/icmp-parameters) 找到 ICMP 类型字段值的完整列表。值得注意的是，列出的许多类型可能也支持代码。代码只是提供关于 ICMP 消息有效载荷功能或用途的更多细节的额外数据参数。会导致 ICMP 响应的一个事件示例是：尝试连接到一个 UDP 服务端口，但该服务和端口实际上并未在目标服务器上使用；这将导致向源发送 ICMP 类型 3 响应。由于 UDP 没有发回错误的机制，协议栈会为此目的切换到 ICMP。

**表 11.5** **常见 ICMP 类型字段值**

| 类型 | 功能 |
| --- | --- |
| 0 | 回显应答 |
| 3 | 目标不可达 |
| 5 | 重定向 |
| 8 | 回显请求 |
| 9 | 路由器通告 |
| 10 | 路由器请求 |
| 11 | 超时 |

**IGMP** `Internet Group Management Protocol (IGMP)`（互联网组管理协议）允许系统支持组播。组播是将数据传输给多个特定接收者。（RFC 1112 讨论了执行 IGMP 组播的要求。）IGMP 由 IP 主机用于注册其动态组播组成员身份。连接的路由器也使用它来发现这些组。通过使用 IGMP 组播，服务器可以为整个组最初仅传输单个数据信号，而不是为每个预期接收者分别传输初始数据信号。使用 IGMP 时，如果存在通往预期接收者的分歧路径，单个初始信号会在路由器处被复制。IGMP 的 IP 头部协议字段值为 2 (0x02)。

**ARP** `Address Resolution Protocol (ARP)`（地址解析协议）对于逻辑和物理寻址方案的互操作性至关重要。ARP 用于将 IP 地址（用于逻辑寻址的 32 位二进制数）解析为媒体访问控制 (MAC) 地址（用于物理寻址的 48 位二进制数）——或 EUI-48 甚至 EUI-64。网段上的流量（例如，跨集线器的电缆）使用 MAC 地址从源系统定向到目标系统。
