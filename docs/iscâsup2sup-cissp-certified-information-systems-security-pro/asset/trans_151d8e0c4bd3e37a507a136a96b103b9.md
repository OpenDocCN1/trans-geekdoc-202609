
如前所述，许多 MDM 系统使用上下文感知身份验证方法来识别设备。它们通常与网络访问控制 (NAC) 系统配合工作，以检查设备的健康状况，并根据 NAC 系统中配置的要求授予或限制访问权限。

802.1x 是另一种用于设备身份验证的方法。它可用于某些路由器和交换机上的基于端口的身份验证。此外，它常与无线系统配合使用，强制用户在获得网络访问权限前使用账户登录。最近，一些 802.1x 解决方案已与 MDM 和/或 NAC 解决方案结合实施，以控制来自移动设备的访问。如果设备或用户无法通过 802.1x 系统进行身份验证，则不会被授予网络访问权限。

## 服务身份验证

许多服务也需要身份验证，它们通常使用用户名和密码。服务账户就是为服务而非个人创建的用户账户。

例如，为监视 Microsoft Exchange Server 中电子邮件的第三方工具创建服务账户是一种常见做法。这些第三方工具通常需要权限来扫描所有邮箱，查找垃圾邮件、恶意软件、潜在的数据渗漏尝试等。管理员通常会创建一个 Microsoft 域账户，并赋予该账户执行任务所需的特权。

通常会设置账户属性，使密码永不过期。对于普通用户，你会将最长使用期限设置为 45 天左右。密码过期时，用户会收到必须更改密码的通知，并由用户自行更改。然而，服务无法响应此类消息，只会被锁定。

由于服务账户拥有高级别的特权，因此会为其配置强复杂密码，且比普通用户更频繁地更换。管理员需要手动更改这些密码。密码保持不变的时间越长，被泄露的可能性就越大。另一种选择是将账户配置为非交互式，这可以防止用户使用传统登录方法登录该账户。

服务可配置为使用基于证书的身份验证。证书颁发给运行服务的设备，并在服务访问资源时由服务呈现。基于 Web 的服务通常使用应用程序编程接口 (API) 方法在系统间交换信息。这些 API 方法因基于 Web 的服务而异。例如，Google 和 Facebook 提供 Web 开发人员使用的基于 Web 的服务，但它们的实现方式不同。

## 实施身份管理

身份管理技术通常分为两类：集中式和分散式/分布式。

*   **集中式访问控制** 意味着系统内的所有授权验证均由单个实体执行。
*   **分散式访问控制**（也称为 **分布式访问控制**） 意味着系统中分布的各个实体执行授权验证。

集中式和分散式访问控制方法提供了任何集中式或分散式系统中所具有的相同优缺点。一个小团队或个人即可管理集中式访问控制。管理开销较低，因为所有更改都在单一位置进行，且单次更改即可影响整个系统。

分散式访问控制通常需要多个团队或多名个人。管理开销较高，因为更改必须在众多位置实施。随着访问控制点数量的增加，维护系统间的一致性变得更加困难。对任何单个访问控制点所做的更改都需要在每个访问点重复执行。

### 单点登录

**单点登录 (SSO)** 是一种集中式访问控制技术，允许主体在系统上经过一次身份验证后，无需再次验证即可访问多个资源。例如，用户可以在网络上进行一次身份验证，然后访问整个网络中的资源，而无需再次接受身份验证提示。

SSO 对用户非常方便，但也能提高安全性。当用户必须记住多个用户名和密码时，他们往往会将其记录下来，最终削弱安全性。用户不太可能记录单个密码。SSO 还通过减少主体所需的账户数量来简化管理。

SSO 的主要缺点是一旦账户被攻破，攻击者将获得对所有授权资源的无限制访问权限。然而，大多数 SSO 系统都包含保护用户凭据的方法。以下几节将讨论几种常见的 SSO 机制。

#### LDAP 和集中式访问控制

在单个组织内，通常使用集中式访问控制系统。例如，**目录服务** 是一个集中式数据库，包含有关主体和对象的信息。许多目录服务基于轻量级目录访问协议 (LDAP)。例如，Microsoft Active Directory 域服务基于 LDAP。

你可以将 LDAP 目录视为网络服务和资产的电话簿。用户、客户端和进程可以搜索目录服务，以查找所需系统或资源所在的位置。主体在执行查询和查找活动前，必须向目录服务进行身份验证。即使经过身份验证，目录服务也仅根据主体分配的特权向其透露特定信息。

多域和信任关系常用于访问控制系统。安全域是共享通用安全策略的主体和对象的集合，各个域可以独立于其他域运行。域之间建立 **信任关系** 以创建安全桥接，允许一个域中的用户访问另一个域中的资源。信任关系可以是单向的，也可以是双向的。

#### LDAP 和 PKI

公钥基础设施 (PKI) 在将数字证书集成到传输中时会使用 LDAP。第 7 章将更深入地介绍 PKI，简而言之，PKI 是一组用于在证书生命周期内管理数字证书的技术。客户端经常需要查询证书颁发机构 (CA) 以获取证书信息，LDAP 是使用的协议之一。

LDAP 和集中式访问控制系统可用于支持单点登录功能。

#### Kerberos

票据身份验证是一种采用第三方实体来证明身份并提供身份验证的机制。最常见且最知名的票据系统是 **Kerberos**。

Kerberos 为用户提供单点登录解决方案，并保护登录凭据。当前版本 Kerberos 5 依赖对称密钥加密（也称为密钥加密），使用高级加密标准 (AES) 对称加密协议。Kerberos 通过端到端安全为身份验证流量提供机密性和完整性，并有助于防范窃听和重放攻击。它使用几个不同的重要元素：

**密钥分发中心** **密钥分发中心 (KDC)** 是提供身份验证服务的受信任第三方。Kerberos 使用对称密钥加密将客户端向服务器进行身份验证。所有客户端和服务器均向 KDC 注册，KDC 维护所有网络成员的密钥。
