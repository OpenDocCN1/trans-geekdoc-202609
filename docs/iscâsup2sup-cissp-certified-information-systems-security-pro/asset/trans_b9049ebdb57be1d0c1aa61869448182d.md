
# 安全模型概述

您将在以下章节中探索多种安全模型；所有这些模型都能阐明安全性是如何融入计算机体系结构和操作系统设计中的：

*   可信计算基
*   状态机模型
*   信息流模型
*   非干扰模型
*   Take-Grant 模型
*   访问控制矩阵
*   Bell-LaPadula 模型
*   Biba 模型
*   Clark-Wilson 模型
*   Brewer 和 Nash 模型（也称为中墙模型）
*   Goguen-Meseguer 模型
*   Sutherland 模型
*   Graham-Denning 模型

尽管不存在绝对安全的系统，但我们可以设计和构建合理安全的系统。事实上，如果一个安全系统符合一组特定的安全标准，就可以说它表现出一定级别的信任度。因此，信任可以构建到系统中，随后进行评估、认证和授权。但在讨论每个安全模型之前，我们必须建立一个大多数安全模型赖以构建的基础。这个基础就是可信计算基。

## 可信计算基

美国国防部的一项旧标准，俗称橙皮书/可信计算机系统评价标准（`TCSEC`）（DoD 标准 5200.28，本章后面“彩虹系列”部分将详细介绍）将*可信计算基（`TCB`）*描述为硬件、软件和控制措施的组合，它们协同工作以形成一个可信基础，从而强制执行您的安全策略。`TCB` 是完整信息系统的一个子集。它应尽可能小，以便通过详细分析合理地确保系统满足设计规范和要求。`TCB` 是该系统中唯一可被信任以遵循并强制执行安全策略的部分。系统的每个组件不一定都要受信。但每当您从安全角度考虑系统时，评估都应包括定义该系统 `TCB` 的所有受信组件。

一般来说，系统中的 `TCB` 组件负责控制对系统的访问。`TCB` 必须提供方法来访问 `TCB` 内部和外部的资源。`TCB` 组件通常限制 `TCB` 外部组件的活动。`TCB` 组件有责任确保系统在所有情况下都能正常运行，并在任何情况下都遵守安全策略。

### 安全边界

系统的*安全边界*是一条虚构的边界，它将 `TCB` 与系统的其余部分分隔开（[图 8.1](#c08.xhtml#figure8-1)）。该边界确保 `TCB` 与计算机系统其余元素之间不发生不安全的通信或交互。为了使 `TCB` 与系统其余部分通信，它必须创建安全通道，也称为*可信路径*。可信路径是按严格标准建立的通道，允许必要的通信发生，同时不将 `TCB` 暴露于安全漏洞之下。可信路径还保护系统用户（有时称为主体）免受 `TCB` 交互导致的妥协。正如您稍后在本章中将了解到的关于正式安全准则和评估标准的内容，可信路径是寻求为用户提供高级别安全性的系统所必需的。根据 `TCSEC` 准则，高信任级别的系统（如 `TCSEC` 的 B2 级或更高级别）需要可信路径。

### 参考监视器和内核

当需要实施安全系统时，开发 `TCB` 的某部分以对系统资产和资源（有时称为客体）实施访问控制至关重要。`TCB` 中在授予访问请求前验证对每个资源访问的部分称为*参考监视器*（[图 8.1](#c08.xhtml#figure8-1)）。参考监视器位于每个主体和客体之间，在允许任何请求继续之前，验证请求主体的凭据是否满足客体的访问要求。如果不满足此类访问要求，则拒绝访问请求。实际上，参考监视器是 `TCB` 的访问控制执行者。因此，授权且安全的动作和活动被允许发生，而未授权和不安全的活动和动作被拒绝并阻止发生。参考监视器根据期望的安全模型（无论是自主的、强制的、基于角色的，还是其他形式的访问控制）来强制执行访问控制或授权。参考监视器可以是 `TCB` 的一个概念部分；它不需要是一个实际的、独立的或单独工作的系统组件。

`TCB` 中协同工作以实现参考监视器功能的组件集合称为*安全内核*。参考监视器是一个概念或理论，通过在软件和硬件中实现安全内核付诸实践。安全内核的目的是启动适当的组件以强制执行参考监视器功能，并抵御所有已知攻击。安全内核使用可信路径与主体通信。它还中介所有资源访问请求，仅授予符合系统所用适当访问规则的请求。

参考监视器需要其所保护的每个资源的描述性信息。此类信息通常包括其分类和标识。当主体请求访问客体时，参考监视器会查阅客体的描述性信息，以判断应授予还是拒绝访问（有关其工作原理的更多信息，请参阅侧边栏“令牌、能力和标签”）。

## 状态机模型

*状态机模型*描述了一个无论处于何种状态始终是安全的系统。它基于计算机科学中*有限状态机（`FSM`）*的定义。`FSM` 将外部输入与内部机器状态相结合，以建模各种复杂系统，包括解析器、解码器和解释器。给定一个输入和一个状态，`FSM` 会转换到另一个状态并可能产生输出。从数学上讲，下一个状态是当前状态和输入的函数；即 `next state = F(input, current state)`。同样，输出也是输入和当前状态的函数；即 `output = F(input, current state)`。

许多安全模型基于安全状态概念。根据状态机模型，*状态*是系统在特定时刻的快照。如果状态的所有方面都满足安全策略的要求，则该状态被视为安全。转换发生在接受输入或产生输出时。转换总是导致一个新状态（也称为*状态转换*）。必须评估所有状态转换。如果每个可能的状态转换都导致另一个安全状态，则该系统可称为*安全状态机*。安全状态机模型系统总是启动进入安全状态，在所有转换中保持安全状态，并且仅允许主体以符合安全策略的安全方式访问资源。安全状态机模型是许多其他安全模型的基础。
