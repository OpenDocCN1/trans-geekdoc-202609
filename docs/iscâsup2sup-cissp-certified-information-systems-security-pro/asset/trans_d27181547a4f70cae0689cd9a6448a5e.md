
# 监控

监控是一项必要的功能，旨在确保主体（如用户和员工）对其行为和活动负责。用户声明身份（如使用用户名）并证明其身份（通过认证），审计追踪记录他们在登录期间的活动。监控和审查审计追踪日志可为这些用户提供问责制。

这直接促进了积极的用户行为和对组织安全策略的遵守。知晓日志正在记录其 IT 活动的用户，不太可能试图绕过安全控制或执行未经授权或受限的活动。

一旦发生安全策略违规或违规事件，应确定违规的来源。如果能够识别出责任人，应根据组织的安全策略追究其责任。严重案例可能导致解雇或法律起诉。

立法通常要求特定的监控和问责实践。这包括《2002 年萨班斯-奥克斯利法案》、《健康保险流通与责任法案》（HIPAA）以及许多组织必须遵守的欧盟（EU）隐私法。

## 监控与调查

审计追踪赋予调查人员在事件发生很久之后重构事件的能力。它们可以记录访问滥用、特权违规、入侵尝试以及多种不同类型的攻击。在检测到安全违规后，安全专业人员可以通过仔细检查审计追踪，重构事件发生前、发生期间和发生后的条件及系统状态。

一个重要的考量因素是确保日志具有准确的时间戳，并且这些时间戳在整个环境中保持一致。一种常用方法是设置一个内部网络时间协议（NTP）服务器，并将其与受信任的时间源（如公共 NTP 服务器）同步。然后，其他系统可以与此内部 NTP 服务器同步。

NIST 运营多台支持认证的时间服务器。一旦 NTP 服务器正确配置，NIST 服务器将响应加密且经过认证的时间消息。该认证提供了响应来自 NIST 服务器的保证。

## 监控与问题识别

审计追踪提供了关于已记录事件的详细信息，这对管理员很有用。除了恶意攻击外，它们还可以记录系统故障、操作系统漏洞和软件错误。某些日志文件甚至可以在应用程序或系统崩溃时捕获内存内容。这些信息有助于确定事件原因，并排除其作为可能攻击的嫌疑。例如，如果系统因内存故障频繁崩溃，转储文件有助于诊断问题。

将日志文件用于此目的通常称为问题识别。一旦识别出问题，执行问题解决所涉及的工作仅仅是跟进所披露的信息。

## 监控技术

**监控**是审查信息日志以查找特定内容的过程。人员可以手动审查日志，或使用工具实现自动化。监控对于检测主体的恶意行为、入侵尝试和系统故障至关重要。它有助于重构事件、为起诉提供证据并创建分析报告。

重要的是要理解监控是一个持续的过程。持续监控确保记录所有事件，以便日后必要时进行调查。许多组织在发生事件或疑似事件后会增加日志记录，以收集关于攻击者的更多情报。

**日志分析**是一种详细且系统的监控形式，其中对记录的信息进行分析以发现趋势和模式，以及异常、未经授权、非法和违反策略的活动。日志分析不一定是对事件的响应，而是一项定期任务，可检测潜在问题。

在手动分析日志时，管理员只需打开日志文件并查找相关数据。这可能非常繁琐且耗时。例如，即使使用内置搜索工具，在 10 个不同的归档日志中搜索特定事件或 ID 代码也需要一些时间。

在许多情况下，日志会产生大量信息，导致重要细节淹没在海量数据中，因此管理员通常使用自动化工具分析日志数据。例如，入侵检测系统（IDS）主动监控多个日志，以实时检测恶意入侵并做出响应。IDS 可帮助检测和追踪来自外部攻击者的攻击，向管理员发送警报，并记录攻击者对资源的访问。

多家供应商销售运维管理软件，该软件主动监控网络中各系统的安全性、健康状况和性能。该软件自动查找表明存在问题（如攻击或未经授权的访问）的可疑或异常活动。

### 安全信息与事件管理

许多组织使用集中式应用程序来自动监控网络上的系统。有多个术语用于描述这些工具，包括安全信息与事件管理（SIEM）、安全事件管理（SEM）和安全信息管理（SIM）。这些工具提供对组织内各系统发生事件的实时分析。它们包括安装在远程系统上的代理，用于监控称为警报触发器的特定事件。触发器发生时代理将事件报告回中央监控软件。

例如，SIEM 可以监控一组邮件服务器。每当某台邮件服务器记录一个事件，SIEM 代理就会检查该事件以确定其是否为关注项。如果是，SIEM 代理会将事件转发给中央 SIEM 服务器，并根据事件类型，可为管理员触发警报。例如，如果邮件服务器的发送队列开始积压，SIEM 应用程序可在问题变得严重之前检测到该问题并提醒管理员。

大多数 SIEM 可配置，允许组织内部人员指定哪些项目是关注项并需要转发给 SIEM 服务器。SIEM 几乎为任何类型的服务器或网络设备提供代理，在某些情况下，它们还监控网络流量以进行流量和趋势分析。这些工具还可以收集目标系统的所有日志，并使用数据挖掘技术检索相关数据。安全专业人员随后可以创建报告并分析数据。

SIEM 通常包含复杂的关联引擎。这些引擎是收集数据并对其进行聚合以查找共同属性的软件组件。然后，它们使用高级分析工具检测异常并向安全管理员发送警报。

某些监控工具也用于资产清单和状态监控。例如，工具可以查询所有可用系统并记录详细信息，如系统名称、IP 地址、操作系统、已安装的补丁、更新和已安装的软件。然后，这些工具可根据组织需求创建任意系统的报告。例如，它们可以识别有多少系统处于活动状态、识别缺少补丁的系统，并标记安装了未经授权软件的系统。

软件监控会留意未经批准软件的尝试或成功安装、未经授权软件的使用，或对已批准软件的未经授权使用。这降低了用户无意中安装病毒或特洛伊木马的风险。
