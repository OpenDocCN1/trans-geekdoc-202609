

# CIA 三要素原则

## 完整性

CIA 三要素中的第二个原则是**完整性**，即对象保持其真实性，且仅由授权主体有意修改的原则。提供完整性的安全机制能高度保证数据、对象和资源未从其原始受保护状态被篡改。这包括对象在存储、传输或处理过程中发生的篡改。维护完整性意味着对象本身未被篡改，且管理和操作该对象的操作系统和编程实体未被攻破。

## 可用性

CIA 三要素中的第三个原则是**可用性**，即授权主体被授予及时且不间断的对象访问权的原则。提供可用性的安全机制能高度保证数据、对象和资源可被授权主体访问。可用性包括对对象的高效不间断访问以及防止拒绝服务攻击。它还意味着支持基础设施功能正常，并允许授权用户获得授权访问。

# 其他安全概念

设计安全策略和部署安全解决方案时，应考虑并解决其他与安全相关的概念和原则，包括**隐私**、**标识**、**认证**、**授权**、**审计追踪**、**不可否认性**和**审计**。

安全解决方案概念和原则的其他方面是保护机制的要素：**分层**、**抽象**、**数据隐藏**和**加密**。这些是安全控制的常见特征，虽然并非所有安全控制都必须具备它们，但许多控制利用这些机制来保护机密性、完整性和可用性。

# 安全角色

安全角色决定了谁对组织资产的安全负责。

- **高级管理层**：对任何资产损失承担最终责任和法律责任；定义安全策略。
- **安全专业人员**：负责实施安全策略。
- **用户**：负责遵守安全策略。
- **数据所有者**：负责对信息进行分类。
- **数据管理员**：负责维护安全环境和备份数据。
- **审计员**：负责确保安全环境妥善保护资产。

# 安全策略结构

正式的安全策略结构由**策略**、**标准**、**基线**、**指南**和**程序**组成。这些单独的文档是任何环境中安全设计和实施的基本要素。

# 变更管理

变更的控制或管理是安全管理实践的一个重要方面。当安全环境发生变更时，漏洞、重叠、缺失对象和疏忽可能导致新的漏洞。然而，您可以通过系统地管理变更来维护安全。这通常涉及与安全控制和安全机制相关的活动的大量日志记录、审计和监控。生成的数据随后用于识别变更因素，无论是对象、主体、程序、通信路径，甚至是网络本身。

# 数据分类

数据分类是根据数据的机密性、敏感性或保密性来保护数据的主要手段。因为某些数据项比其他数据项需要更多的安全性，所以在设计和实施安全系统时，将所有数据同等对待是低效的。如果所有内容都在低安全级别下受到保护，敏感数据很容易被访问；但如果所有内容都在高安全级别下受到保护，成本太高且会限制对非机密、非关键数据的访问。数据分类用于确定分配多少精力、资金和资源来保护数据并控制对其的访问。

# 安全管理规划

安全管理规划的一个重要方面是安全策略的正确实施。要有效，安全管理的方法必须是**自上而下的方法**。

- **高级管理层**：负责发起和定义安全策略。
- **中层管理层**：将安全策略细化为标准、基线、指南和程序。
- **运营管理者/安全专业人员**：实施安全管理文档中规定的配置。
- **最终用户**：遵守组织的所有安全策略。

安全管理规划包括定义安全角色、制定安全策略、执行风险分析，并要求员工接受安全教育。这些职责由管理计划的发展指导。安全管理团队应制定**战略**、**战术**和**操作计划**。

# 威胁建模

**威胁建模**是识别、分类和分析潜在威胁的安全过程。威胁建模可以在设计和开发期间作为主动措施执行，也可以在产品部署后作为被动措施执行。无论哪种情况，该过程都会识别潜在危害、发生概率、关注优先级，以及消除或减轻威胁的手段。

# 供应链集成

将网络安全风险管理与供应链、采购策略和业务实践相结合，是确保各种规模组织拥有更强大、更成功的安全策略的一种途径。如果在采购时不考虑安全因素，这些产品固有的风险将贯穿其整个部署生命周期。

# 考试要点

## 理解 CIA 三要素

**机密性**：对象不向未授权主体披露的原则。
**完整性**：对象保持其真实性，且仅由授权主体有意修改的原则。
**可用性**：授权主体被授予及时且不间断的对象访问权的原则。

了解这些为何重要、支持它们的机制、针对每一项的攻击以及有效的对策。

## 解释标识

**标识**是主体声称身份并启动问责制的过程。主体必须向系统提供身份，以启动认证、授权和问责的过程。

## 理解认证

**认证**是验证或测试所声称身份是否有效的过程。认证要求主体提供的信息必须与所指示的身份完全对应。

## 了解授权

主体经过认证后，必须对其访问进行授权。**授权**过程确保根据分配给已认证身份的权利和特权，请求的活动或对象访问是可行的。

## 理解安全治理

**安全治理**是与支持、定义和指导组织安全工作相关的实践集合。

## 解释审计

**审计**（或监控）是主体在系统上认证期间对其行为负责的程序化手段。审计也是检测系统上未授权或异常活动的过程。审计对于检测主体的恶意行为、入侵尝试和系统故障、重建事件、为起诉提供证据以及生成问题报告和分析至关重要。
