

# Clark-Wilson 模型

格式良好的事务采用程序的形式。主体只能通过使用程序、接口或访问门户来访问对象（[图 8.5](#c08.xhtml#figure8-5)）。每个程序都对其能对对象（如数据库或其他资源）执行的操作和不能执行的操作有特定的限制。这实际上限制了主体的能力。这被称为**受限接口**。如果程序设计得当，那么这种三元关系提供了一种保护对象完整性的手段。

[**图 8.5**](#c08.xhtml#figureanchor8-5) Clark-Wilson 模型

Clark-Wilson 定义了以下项目和过程：

*   **受限数据项（CDI）** 是指其完整性受安全模型保护的任何数据项。
*   **非受限数据项（UDI）** 是指不受安全模型控制的任何数据项。任何待输入且未经验证的数据，或任何输出数据，都将被视为非受限数据项。
*   **完整性验证程序（IVP）** 是一种扫描数据项并确认其完整性的程序。
*   **转换过程（TP）** 是被允许修改 CDI 的唯一过程。通过 TP 对 CDI 的有限访问构成了 Clark-Wilson 完整性模型的骨干。

Clark-Wilson 模型使用安全标签来授予对对象的访问权限，但仅限通过转换过程和**受限接口模型**。受限接口模型利用基于分类的限制，仅提供特定主体授权的信息和功能。处于某一分类级别的主体将看到一组数据并有权访问一组功能，而处于不同分类级别的另一个主体将看到不同的数据集并有权访问不同的功能集。向不同级别或类别的用户提供不同功能，可以通过向所有用户显示所有功能但禁用特定用户未获授权的功能来实现，也可以通过仅显示授予特定用户的功能来实现。通过这些机制，Clark-Wilson 模型确保数据免受任何用户的未授权更改。实际上，Clark-Wilson 模型强制实施了职责分离。Clark-Wilson 的设计使其成为商业应用的常用模型。

## Brewer 和 Nash 模型（又称中墙模型）

**Brewer 和 Nash 模型**的创建是为了允许访问控制根据用户的先前活动动态变化（这也使其成为一种状态机模型）。该模型适用于单个集成数据库；它旨在创建对利益冲突概念敏感的安全域（例如，在 C 公司工作且有权访问 A 公司专有数据的人，如果 A 公司和 B 公司相互竞争，则不应被允许访问 B 公司的类似数据）。该模型被称为**中墙模型**，因为它创建了一类数据，用于定义哪些安全域可能存在冲突，并防止任何有权访问属于特定冲突类的一个域的主体访问属于同一冲突类的任何其他域。从隐喻上讲，这在任何冲突类中的所有其他信息周围筑起了一道墙。因此，该模型还利用每个冲突类内部的数据隔离原则，使用户免受潜在的利益冲突情况影响（例如公司数据集的管理）。由于公司关系不断变化，对冲突类成员及定义的动态更新非常重要。

审视或思考 Brewer 和 Nash 模型的另一种方式是：管理员根据其分配的工作职责和任务，拥有对系统中广泛数据的完全控制访问权。然而，在对任何数据项采取行动的那一刻，管理员对任何冲突数据项的访问将被暂时阻断。在操作期间，只能访问与初始数据项相关的数据项。任务完成后，管理员的访问权限恢复为完全控制。

## Goguen-Meseguer 模型

**Goguen-Meseguer 模型**是一种完整性模型，虽然不如 Biba 和其他模型知名。事实上，该模型被认为是非干扰概念理论的基础。通常当有人提到非干扰模型时，实际上指的就是 Goguen-Meseguer 模型。

Goguen-Meseguer 模型基于预先确定主体可访问的对象集合或域——即列表。该模型基于自动化理论和域分离。这意味着主体只被允许对预定对象执行预定操作。当相似用户被分组到他们自己的域（即集合）中时，一个主体域的成员无法干扰另一个主体域的成员。因此，主体无法相互干扰彼此的活动。

## Sutherland 模型

**Sutherland 模型**是一种完整性模型。它专注于防止干扰以支持完整性。它正式基于状态机模型和信息流模型。然而，它并不直接指示保护完整性的具体机制。相反，该模型基于定义一组系统状态、初始状态和状态转换的思想。通过仅使用这些预定的安全状态，可维护完整性并禁止干扰。

Sutherland 模型的一个常见示例是用于防止隐蔽信道被用来影响过程或活动的结果。（关于隐蔽信道的讨论，请参见第 9 章。）

## Graham-Denning 模型

**Graham-Denning 模型**专注于主体和对象的安全创建与删除。Graham-Denning 是一组八条主要保护规则或动作的集合，它们定义了某些安全动作的边界：

*   安全地创建对象。
*   安全地创建主体。
*   安全地删除对象。
*   安全地删除主体。
*   安全地提供读访问权限。
*   安全地提供授予访问权限。
*   安全地提供删除访问权限。
*   安全地提供转移访问权限。

通常，主体对一组对象的具体能力或权限是在访问矩阵（又称访问控制矩阵）中定义的。

# 基于系统安全需求选择控制措施

那些为特定类型的应用采购信息系统的人——例如，考虑一下国家安全机构，那里的敏感信息可能极其宝贵（或落入坏人手中极其危险），又如中央银行或证券交易商，某些数据可能价值数十亿美元——通常希望了解其安全优势和劣势。此类买方通常只愿考虑那些经过正式评估流程并获得某种安全评级的系统。买方想知道他们买的是什么，以及通常需要采取哪些步骤来使此类系统尽可能安全。

当进行正式评估时，系统通常要经过两步流程：

1.  对系统进行测试并执行技术评估，以确保系统的安全能力满足其预期用途规定的标准。
2.  将系统的设计和安全标准与其实际能力和性能进行正式比较，负责此类系统安全性和真实性的个人必须决定是采纳它们、拒绝它们，还是修改其标准并重试。
