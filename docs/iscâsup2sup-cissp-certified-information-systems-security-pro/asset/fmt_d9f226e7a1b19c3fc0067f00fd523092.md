
如果计算机未运行，它只是一块惰性的塑料、硅和金属，什么也不做。当计算机运行时，它会操作一个运行时环境，该环境代表操作系统以及可能处于活动状态的任何应用程序的组合。运行时，计算机还具备访问文件和其他数据的能力，前提是用户的安全权限允许。在该运行时环境中，必须集成安全信息和控制，以保护操作系统本身的完整性，管理允许哪些用户访问特定数据项，授权或拒绝针对此类数据的操作请求，等等。运行中的计算机在运行时实现和处理安全的方式，可以广泛地描述为一组保护机制的集合。以下将描述各种保护机制，如保护环、操作状态和安全模式。

## 保护环

环保护方案由来已久但依然有效。它可以追溯到 Multics 操作系统的研究工作。这个实验性操作系统于 1963 年至 1969 年间由贝尔实验室、麻省理工学院和通用电气公司合作设计和构建。它在霍尼韦尔的实现中得到了商业应用。Multics 在计算界留下了两大不朽遗产。首先，它激发了一个更简单、结构更清晰的操作系统 Unix（谐音 *multics*）的诞生；其次，它将保护环的概念引入了操作系统设计。

从安全角度来看，**保护环** 将操作系统中的代码和组件（以及在操作系统控制下运行的应用程序、实用程序或其他代码）组织成同心环，如 [图 9.1](#c09.xhtml#figure9-1) 所示。越靠近圆心，占据特定环的代码所关联的特权级别越高。虽然最初的 Multics 实现允许多达七个环（编号 0 到 6），但大多数现代操作系统使用四环模型（编号 0 到 3）。

作为最内层的环，环 0 拥有最高特权，基本上可以访问任何资源、文件或内存位置。操作系统中始终驻留在内存中的部分（以便随时按需运行）称为 **内核**。它占据环 0，并可以抢占在任何其他环运行的代码。操作系统的其余部分——随着各种任务被请求、操作被执行、进程被切换等而来去不定——占据环 1。环 2 也具有一定特权，I/O 驱动程序和系统实用程序驻留于此；它们能够访问外围设备、特殊文件等，而应用程序和其他程序无法直接访问这些资源。那些应用程序和程序占据最外层的环，即环 3。

环模型的本质在于优先级、特权和内存分段。任何想要执行的进程都必须排队（待处理进程队列）。关联环号最低的进程总是比关联较高编号环的进程先运行。较低编号环中的进程可以访问更多资源，并比较高编号环中的进程更直接地与操作系统交互。运行在较高编号环中的进程通常必须向较低编号环中的处理程序或驱动程序请求所需服务；这有时称为 **中介访问模型**。在其最严格的实现中，每个环都有其关联的内存段。因此，来自较高编号环的进程对较低编号环中地址的任何请求，都必须调用与该地址关联的环中的辅助进程。在实践中，许多现代操作系统仅将内存分为两个段：一个用于系统级访问（环 0 到 2），通常称为 **内核模式** 或 **特权模式**；另一个用于用户级程序和应用程序（环 3），通常称为 **用户模式**。

从安全角度来看，环模型使操作系统能够保护并隔离自己，防止用户和应用程序的侵害。它还允许在高度特权的操作系统组件（如内核）和较低特权的操作系统部分（如操作系统的其他部分、驱动程序和实用程序）之间强制执行严格的边界。在此模型中，仅在特定环内才能直接访问特定资源；同样，某些操作（如进程切换、终止和调度）也仅允许在特定环内进行。

进程所占据的环决定了其对系统资源的访问级别（并决定了它必须从较低编号、更高特权的环中的进程请求哪些类型的资源）。进程只有在资源驻留在其自己的环内，或驻留在其当前边界之外的某个环内（按数字术语，例如，环 1 的进程可以直接访问其自己的资源，以及与环 2 和 3 关联的资源，但无法访问仅与环 0 关联的资源）时，才能直接访问对象。实现中介访问的机制——即前面提到的驱动程序或处理程序请求——通常称为 **系统调用**，通常涉及调用特定的系统或编程接口，旨在将请求传递给内层环以获取服务。然而，在任何此类请求得到满足之前，被调用的环必须检查以确保调用进程拥有正确的凭据和授权，以访问数据并执行满足请求所涉及的操作。

## 进程状态

也称为 **操作状态**，**进程状态** 是进程可能运行的各种执行形式。就操作系统而言，在任何给定时刻，它可以处于两种模式之一：在称为 **管理员状态** 的特权全访问模式下运行，或在称为 **问题状态** 的用户模式下运行，在该模式下特权较低，所有访问请求在被授予或拒绝前都必须根据凭据进行授权检查。之所以称后者为问题状态，并非因为问题一定会发生，而是因为用户访问的非特权性质意味着问题可能发生，系统必须采取适当措施来保护安全性、完整性和机密性。

进程在操作系统的处理队列中排队等待执行，当处理器可用时，它们将被调度运行。由于许多操作系统仅允许进程以固定增量或块消耗处理器时间，当创建新进程时，它首次进入处理队列；如果进程在未完成的情况下消耗了其整个处理时间块（称为 **时间片**），它将在下一次轮到它时返回处理队列以获取另一个时间片。此外，进程调度程序通常选择最高优先级的进程执行，因此排到队首并不总能保证获得 CPU 访问权（因为进程可能在最后一刻被另一个优先级更高的进程抢占）。
