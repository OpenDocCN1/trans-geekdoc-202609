

# 业务所有者与系统所有权

业务所有者可能拥有使用由其他实体管理的系统的流程。例如，销售部门可能是业务所有者，但 IT 部门和软件开发部门可能是销售流程所用系统的系统所有者。假设销售部门专注于使用电子商务网站进行在线销售，且该网站访问后端数据库服务器。与前面的示例一样，IT 部门作为系统所有者管理 Web 服务器，软件开发部门作为系统所有者管理数据库服务器。尽管销售部门不拥有这些系统，但它确实拥有利用这些系统产生销售的业务流程。

在企业中，业务所有者负责确保系统为组织提供价值。这听起来显而易见。然而，IT 部门有时会过度热心，在未考虑对业务或其使命的影响的情况下实施安全控制。

许多企业中一个潜在的冲突领域是成本中心与利润中心的对比。IT 部门不产生收入。相反，它是一个产生成本的成本中心。相比之下，业务部门作为利润中心产生收入。IT 部门产生的成本会吞噬业务部门产生的利润。此外，IT 部门实施的许多安全控制为了安全起见降低了系统的易用性。如果将这些因素结合起来，你会发现业务部门有时认为 IT 部门在花钱、减少利润，并使业务更难产生利润。

组织通常会实施 IT 治理方法，例如《信息及相关技术控制目标》（COBIT）。这些方法有助于业务所有者和使命所有者在安全控制要求与业务或使命需求之间取得平衡。

## 数据处理者

一般来说，数据处理者是指用于处理数据的任何系统。然而，在 GDPR（通用数据保护条例）的语境下，`data processor` 具有更具体的含义。GDPR 将数据处理者定义为：“代表数据控制者单独处理个人数据的自然人或法人、公共机构、机关或其他实体。”在此语境下，`data controller`（数据控制者）是控制数据处理的个人或实体。

例如，一家为薪资发放收集员工个人信息的公司是数据控制者。如果他们将这些信息传递给第三方公司处理薪资，则薪资公司是数据处理者。在此示例中，薪资公司（数据处理者）不得将数据用于数据控制者指示的薪资处理以外的任何用途。

GDPR 限制向欧盟以外国家的数据传输。组织必须遵守 GDPR 中的所有要求。违反 GDPR 隐私规则的公司可能面临高达其全球收入 4% 的罚款。不幸的是，GDPR 充满了法律术语，给组织带来了许多挑战。例如，第 107 条款包含以下声明：

> “因此，除非满足本条例中关于在适当保障措施下进行的传输的要求，包括具有约束力的企业规则，以及针对特定情况的豁免，否则应禁止向该第三国或国际组织传输个人数据。”

欧盟委员会和美国政府开发了 EU-US Privacy Shield（欧美隐私盾）计划，以取代之前的 Safe Harbor（安全港）计划。同样，瑞士和美国官员共同创建了 Swiss-US Privacy Shield（瑞美隐私盾）框架。这两个计划均由美国商务部国际贸易管理局（ITA）管理。

组织可以自我认证，通过美国商务部表明其遵守隐私盾原则。自我认证过程包括回答一份冗长的问卷。组织官员提供组织详细信息，重点关注组织的隐私政策，包括组织承诺遵守七项主要隐私盾原则和 16 项隐私盾补充原则。

隐私盾原则内容深度很大，但作为摘要，它们如下：

*   **通知**：组织必须告知个人收集和使用其信息的目的。
*   **选择**：组织必须为个人提供选择退出的机会。
*   **后续传输责任**：组织只能将数据传输给遵守通知和选择原则的其他组织。
*   **安全**：组织必须采取合理预防措施保护个人数据。
*   **数据完整性和目的限制**：组织应仅收集通知原则中确定的处理目的所需的数据。组织还负责采取合理步骤确保个人数据准确、完整且最新。
*   **访问**：个人必须能够访问组织持有的关于他们的个人信息。当信息不准确时，个人还必须有权更正、修改或删除信息。
*   **救济、执行和责任**：组织必须实施机制以确保遵守原则，并提供处理个人投诉的机制。

### 假名化

组织可以实施的两项技术安全控制是加密和假名化。如前所述，传输中的所有敏感数据和静态敏感数据都应加密。当有效执行假名化时，可以减少 GDPR 项下原本适用的严格要求。

假名是别名。例如，《哈利·波特》作者 J. K. 罗琳以罗伯特·加尔布雷斯的假名出版了《布谷鸟的呼唤》一书。如果你知道这个假名，你就会知道未来所有由罗伯特·加尔布雷斯撰写的书都是 J. K. 罗琳写的。

`Pseudonymization`（假名化）是指使用假名来代表其他数据的过程。它可以防止数据直接识别实体（如个人）。例如，考虑医生办公室持有的一份病历。病历中不包含患者姓名、地址和电话号码等个人信息，而只将患者称为“患者 23456”。医生办公室仍然需要这些个人信息，可以将其保存在另一个数据库中，并将其链接到患者假名（患者 23456）。

请注意，在该示例中，假名（患者 23456）指代该人的多条信息。也可以为单条信息使用假名。例如，你可以为名使用一个假名，为姓使用另一个假名。关键是要有另一个资源（如另一个数据库），允许你使用假名识别原始数据。

GDPR 将假名化称为用 `artificial identifiers`（人工标识符）替换数据。这些人工标识符即假名。

### 匿名化

如果你不需要个人数据，另一种选择是使用匿名化。`Anonymization`（匿名化）是移除所有相关数据的过程，使得无法识别原始主体或个人。如果有效执行，GDPR 不再适用于匿名化数据。然而，真正实现数据匿名化可能很困难。即使移除了个人数据，数据推断技术仍可能识别出个人。
