
尽管功能测试是商业代码和应用程序的常规做法，但针对安全问题的单独测试仅在过去几年才开始受到关注并获得认可，这要归功于广泛宣传的病毒和蠕虫攻击、SQL 注入攻击、跨站脚本攻击，以及广泛使用的公共在线站点偶尔遭到篡改或中断。您可以参考 OWASP Top 10 Web Application Security Risks 报告，网址为 `https://www.owasp.org/images/7/72/OWASP_Top_10-2017_%28en%29.pdf.pdf`。

在后续章节中，我们将介绍常见的攻击源或安全架构漏洞，这些漏洞可归因于设计失败、实现失败、发布前代码清理失败或彻头彻尾的编码错误。虽然这些缺陷是可以避免的，但发现和修复此类缺陷要求从开发项目一开始就进行严格的安全意识设计，并在测试和分析上投入额外的时间和精力。这有助于解释软件安全常常令人遗憾的现状，但绝不为其开脱！

人类永远无法编写完全安全（无瑕疵）的代码。在整个应用开发生命周期中实施源代码分析工具将最大程度地减少生产版本中的缺陷数量，而在生产发布前发现的缺陷，其修复成本要低得多。代码审查和测试的概念在第 15 章“安全评估与测试”中介绍。

### 可信恢复

当未做好准备的系统崩溃并随后恢复时，可能会出现两个危及其安全控制的机会。许多系统会在关机过程中卸载安全控制。`可信恢复` 确保在发生崩溃时所有安全控制保持完好。在可信恢复期间，系统确保在安全控制被禁用时不存在访问机会。即使是恢复阶段，也在所有控制完好无损的情况下运行。

例如，假设系统在将数据库事务写入磁盘时崩溃，该数据库被分类为绝密级。无防护的系统可能允许未授权用户在数据写入磁盘前访问该临时数据。支持可信恢复的系统确保即使在崩溃期间也不会发生数据机密性违规。此过程需要周密的计划和处理系统故障的详细程序。尽管自动恢复程序可能构成整个恢复过程的一部分，但仍可能需要人工干预。显然，如果需要此类人工操作，对执行恢复的人员进行适当的身份标识和认证同样至关重要。

### 输入和参数检查

最臭名昭著的安全违规之一是 `缓冲区溢出`。当程序员未能充分验证输入数据时，特别是当他们未对软件接受的输入数据量施加限制时，就会发生此违规。由于此类数据通常存储在输入缓冲区中，当超过缓冲区的正常最大尺寸时，多余的数据称为溢出。因此，当有人试图将恶意指令或代码作为程序输入的一部分提供时，由此产生的攻击类型称为缓冲区溢出。不幸的是，在许多系统中，此类溢出数据通常会在高权限级别下，或以接受此类输入的进程所附带的任何权限级别，直接被受攻击系统执行。对于几乎所有类型的操作系统（包括 Windows、Unix、Linux 等），缓冲区溢出暴露了任何已知安全漏洞中最明显、最深刻的妥协和攻击机会。

导致缓冲区溢出漏洞的责任方始终是允许未清理或未消毒输入的程序员的代码。程序员的尽职调查可以彻底根除缓冲区溢出，但前提是程序员在将所有输入和参数存储到任何数据结构之前对其进行检查（并限制可作为输入提供的数据量）。适当的数据验证是消除缓冲区溢出的唯一途径。否则，缓冲区溢出的发现会导致一个熟悉的模式：必须向受影响的系统应用关键安全更新以关闭攻击入口。

### 维护钩子和特权程序

`维护钩子` 是仅系统开发人员知晓的系统入口点。此类入口点也称为 `后门`。尽管维护钩子的存在明显违反安全策略，但它们仍出现在许多系统中。后门的初衷是为维护原因或常规访问意外禁用时提供对系统的保证访问。问题在于，这种访问方式绕过了所有安全控制，并向知晓后门存在的任何人提供自由访问。必须明确禁止此类入口点，并监控审计日志以发现可能表明未授权管理员访问的任何活动。

另一个常见的系统漏洞是在执行期间以提升的安全级别运行程序。此类程序必须经过仔细编写和测试，以确保它们不允许任何会使主体保留更高安全级别的退出和/或入口点。确保所有在高安全级别下运行的程序仅对适当用户可访问，并已针对滥用进行加固。一个很好的例子是 Unix/Linux 操作系统环境中 root 拥有的全局可写可执行脚本。这一重大安全缺陷经常被忽视。任何人都可以修改该脚本，它将在 root 上下文中执行，允许创建用户，从而导致后门访问。

### 增量攻击

某些攻击形式是以缓慢、渐进的增量发生的，而非通过明显或可识别的企图来破坏系统安全或完整性。此类攻击的两种形式是数据篡改和萨拉米攻击。

`数据篡改` 是指攻击者获得系统访问权限，在存储、处理、输入、输出或事务过程中对数据进行微小的、随机的或增量的更改，而不是明显地更改文件内容或损坏/删除整个文件。除非文件和数据受到加密保护，或者每次读写文件时都例行执行并应用某种完整性检查（如校验和或消息摘要），否则此类更改很难被检测到。加密文件系统、文件级加密技术或某种形式的文件监控（包括由 Tripwire 等应用程序和其他文件完整性监控 [FIM] 工具执行的完整性检查）通常能提供充分保证，确保没有正在进行的数据篡改。数据篡改通常被认为是内部人员而非外部人员（即外部入侵者）更常实施的攻击。显而易见，既然数据篡改是一种更改数据的攻击，它就被视为一种主动攻击。
