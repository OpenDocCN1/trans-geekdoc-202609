
# 编程语言与面向对象编程

程序员不希望用机器语言或汇编语言编写代码。他们更倾向于使用高级语言，如 `Python`、`C++`、`Ruby`、`R`、`Java` 和 `Visual Basic`。这些语言允许程序员编写更接近人类交流的指令，减少开发应用程序所需的时间，可能减少项目所需的程序员数量，并且允许在不同操作系统和硬件平台之间实现一定的可移植性。一旦程序员准备好执行程序，有两个选项可供选择：编译和解释。

## 编译型语言

某些语言（如 `C`、`Java` 和 `FORTRAN`）是编译型语言。使用编译型语言时，程序员使用称为**编译器**的工具将高级语言转换为专为特定操作系统设计的可执行文件。然后将此可执行文件分发给最终用户，由他们自行决定如何使用。一般来说，无法直接查看或修改可执行文件中的软件指令。然而，逆向工程领域的专家可能借助称为**反编译器**的工具逆转编译过程。当进行恶意软件分析或竞争情报分析且无法访问底层源代码时，这对于确定可执行文件的工作原理特别有用。

## 解释型语言

其他语言（如 `Python`、`R`、`JavaScript` 和 `VBScript`）是解释型语言。使用这些语言时，程序员分发包含高级语言指令的源代码。最终用户随后使用解释器在其系统上执行该源代码。他们能够查看程序员编写的原始指令。

每种方法都有安全优势和劣势。编译后的代码通常不太容易被第三方篡改。然而，恶意（或不熟练）的程序员也更容易在代码中植入后门和其他安全缺陷并逃避检测，因为最终用户无法查看原始指令。然而，解释型代码不太容易受到原始程序员未被发现的恶意代码插入的影响，因为最终用户可以查看代码并检查其准确性。另一方面，接触软件的每个人都有能力修改程序员的原始指令，并可能在解释型软件中植入恶意代码。您将在第 21 章“恶意代码和应用程序攻击”的“应用程序攻击”部分了解更多攻击者用于破坏软件的漏洞利用。

## 面向对象编程

许多现代编程语言，如 `C++`、`Java` 和 `.NET` 语言，支持面向对象编程（OOP）的概念。较旧的编程风格（如函数式编程）关注程序本身的流程，并试图将期望的行为建模为一系列步骤。面向对象编程关注交互中涉及的对象。您可以将其视为一组对象，它们可以被请求执行特定操作或表现出特定行为。对象协同工作以提供系统的功能或能力。OOP 有潜力做到更可靠，并能减少程序变更错误的传播。作为一种编程方法，它更适合对现实世界进行建模或模拟。例如，银行程序可能有三个对象类，分别对应账户、账户持有人和员工。当向系统添加新账户时，会创建相应对象的新实例（或副本）以包含该账户的详细信息。

OOP 模型中的每个对象都有对应于可对该对象执行的特定操作的方法。例如，账户对象可以有添加资金、扣除资金、关闭账户和转移所有权的方法。

对象也可以是其他对象的子类，并从其父类继承方法。例如，账户对象可能有对应特定账户类型的子类，如储蓄、支票、抵押贷款和汽车贷款。子类可以使用父类的所有方法，并拥有额外的特定类方法。例如，支票对象可能有一个名为 `write_check()` 的方法，而其他子类则没有。

从安全角度来看，面向对象编程为抽象提供了一种黑盒方法。用户需要知道对象接口的细节（通常是对应于对象每个方法的输入、输出和操作），但不一定需要知道对象的内部工作原理即可有效使用它。为了提供面向对象系统所需的特性，对象被封装（自包含），并且只能通过特定消息（即输入）访问。对象还可以表现出替换属性，允许提供兼容操作的不同对象相互替换。

以下是您在工作中可能遇到的一些常见面向对象编程术语：

**消息** 消息是发送给对象的通信或输入。

**方法** 方法是定义对象响应消息所执行操作的内部代码。

**行为** 对象表现出的结果或输出是一种行为。行为是消息通过方法处理后的结果。

**类** 一组对象的公共方法的集合，定义了这些对象的行为，称为类。

**实例** 对象是包含其方法的类的实例或示例。

**继承** 当一个类（父类或超类）的方法被另一个子类（子类）继承时，就会发生继承。

**委托** 委托是对象将请求转发给另一个对象或代理。如果对象没有处理消息的方法，它就会进行委托。

**多态** 多态是对象的一种特性，允许它因外部条件的变化而对同一消息或方法做出不同行为的响应。

**内聚** 内聚描述同一类中各方法目的之间关系的强度。

**耦合** 耦合是对象之间交互的程度。耦合度越低意味着交互越少。耦合度越低提供更好的软件设计，因为对象更独立。耦合度越低越容易排查故障和更新。内聚度低的对象需要其他对象的大量协助来执行任务，并且具有高耦合。

## 保证

为确保内置于新应用程序中的安全控制机制在系统的整个生命周期中正确实施安全策略，管理员使用**保证程序**。保证程序只是将信任构建到系统生命周期中的正式化过程。通用准则提供了一种在政府环境中使用的标准化保证方法。

## 避免和缓解系统故障

无论您的开发团队多么先进，您的系统在某个时间点可能会发生故障。在部署软件和硬件控制时，您应该为这种类型的故障做计划，确保系统做出适当的响应。您可以采用许多方法来避免故障，包括使用输入验证和创建故障安全或故障开放程序。让我们更详细地讨论这些内容。
