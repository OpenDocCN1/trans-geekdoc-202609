

# 审计与评估标准

在进行审计或评估时，执行审查的团队应明确他们用于评估组织的标准。该标准提供了应满足的控制目标描述，随后审计或评估旨在确保组织已正确实施控制以满足这些目标。

用于进行审计和评估的一个常见框架是*信息及相关技术控制目标*。COBIT 描述了组织在其信息系统周围应建立的通用要求。

国际标准化组织 (ISO) 还发布了一套与信息安全相关的标准。`ISO 27001` 描述了建立信息安全管理体系的标准方法，而 `ISO 27002` 则更详细地阐述了信息安全控制的具体细节。这些国际公认的标准在安全领域被广泛使用，组织可以选择正式认证为符合 `ISO 27001`。

# 执行漏洞评估

漏洞评估是信息安全专业人员工具箱中最重要的测试工具之一。漏洞扫描和渗透测试为安全专业人员提供了关于系统或应用程序技术控制中弱点的视角。

## 描述漏洞

安全社区依赖一套通用标准，为描述和评估漏洞提供通用语言。NIST 为社区提供了*安全内容自动化协议* 以满足这一需求。SCAP 提供了这一通用讨论框架，并促进了不同安全系统之间交互的自动化。SCAP 的组件包括以下内容：

*   *通用漏洞披露* 提供了一套描述安全漏洞的命名系统。
*   *通用漏洞评分系统* 提供了一套描述安全漏洞严重程度的标准化评分系统。
*   *通用配置枚举* 提供了一套描述系统配置问题的命名系统。
*   *通用平台枚举* 提供了一套描述操作系统、应用程序和设备的命名系统。
*   *可扩展配置清单描述格式* 提供了一种指定安全清单的语言。
*   *开放漏洞与评估语言* 提供了一种描述安全测试过程的语言。

## 漏洞扫描

*漏洞扫描* 会自动探测系统、应用程序和网络，寻找攻击者可能利用的弱点。这些测试中使用的扫描工具提供快速的“点击式”测试，无需人工干预即可执行原本繁琐的任务。大多数工具允许按周期安排定期扫描，并提供报告显示不同日期执行的扫描之间的差异，为管理员提供了了解其安全风险环境变化的视角。

漏洞扫描主要有四大类：网络发现扫描、网络漏洞扫描、Web 应用程序漏洞扫描和数据库漏洞扫描。各种各样的工具可执行这些类型的扫描。

### 网络发现扫描

网络发现扫描使用多种技术扫描一系列 IP 地址，搜索具有开放网络端口的系统。网络发现扫描器实际上并不探测系统的漏洞，而是提供一份报告，显示网络上检测到的系统以及网络和服务器防火墙（位于扫描器与被扫描系统之间的网络路径上）所暴露的端口列表。

网络发现扫描器使用许多不同的技术来识别远程系统上的开放端口。一些较常见的技术如下：

**TCP SYN 扫描** 向每个被扫描端口发送一个设置了 SYN 标志的单个数据包。这表示请求打开一个新连接。如果扫描器收到的响应同时设置了 SYN 和 ACK 标志，则表明系统正在进入三次 TCP 握手的第二阶段，且该端口是开放的。TCP SYN 扫描也称为“半开放”扫描。

**TCP Connect 扫描** 在指定端口上与远程系统建立完整连接。当运行扫描的用户没有运行半开放扫描所需的权限时，会使用此扫描类型。大多数其他扫描类型都需要发送原始数据包的能力，而用户可能会受到操作系统限制而无法发送手工制作的数据包。

**TCP ACK 扫描** 发送一个设置了 ACK 标志的数据包，表明它是开放连接的一部分。此类扫描可能旨在确定防火墙强制执行的规则和防火墙方法。

**Xmas 扫描** 发送一个同时设置了 FIN、PSH 和 URG 标志的数据包。设置了如此多标志的数据包被称为“像圣诞树一样亮起来”，因此得名。

用于网络发现扫描的最常用工具是一个名为 `nmap` 的开源工具。`nmap` 最初于 1997 年发布，令人惊讶的是它至今仍在维护并普遍使用。它仍然是最流行的网络安全工具之一，几乎每个安全专业人员要么定期使用 `nmap`，要么在其职业生涯的某个阶段使用过它。您可以在 <http://nmap.org> 下载 `nmap` 的免费副本或了解更多关于该工具的信息。

当 `nmap` 扫描系统时，它会识别系统上每个网络端口的当前状态。对于检测到结果的端口，它会提供该端口的当前状态：

**开放** 该端口在远程系统上是开放的，且有应用程序正在该端口上主动接受连接。

**关闭** 该端口在远程系统上是可访问的，意味着防火墙允许访问，但没有应用程序在该端口上接受连接。

**被过滤** 由于防火墙干扰了连接尝试，`nmap` 无法确定端口是开放还是关闭。

[图 15.1](#c15.xhtml#figure15-1) 展示了 `nmap` 运行的示例。用户在 Linux 提示符下输入了以下命令：

```
nmap –vv 52.4.85.159
```

![图 15.1 从 Linux 系统运行的 Web 服务器 Nmap 扫描](images/c15f001.jpg)

[**图 15.1**](#c15.xhtml#figureanchor15-1) 从 Linux 系统运行的 Web 服务器 Nmap 扫描

`nmap` 软件随即开始对 IP 地址为 `52.4.85.159` 的系统进行端口扫描。命令中指定的 `–vv` 标志只是告诉 `nmap` 使用详细模式，报告其结果的详细输出。[图 15.1](#c15.xhtml#figure15-1) 底部附近出现的扫描结果表明，`nmap` 在该系统上发现了三个活动端口：`22`、`80` 和 `443`。端口 `22` 和 `80` 是开放的，表明系统正在主动接受这些端口上的连接请求。端口 `443` 是关闭的，意味着防火墙包含允许该端口连接尝试的规则，但系统未运行配置为接受这些连接的应用程序。

要解读这些结果，您必须了解常见网络端口的用途，这在第 12 章“安全通信与网络攻击”中已讨论过。让我们演练一下此 `nmap` 扫描的结果：

*   端口列表的第一行 `22/tcp open ssh` 表明系统接受 TCP 端口 `22` 上的连接。安全外壳 (SSH) 服务使用此端口允许对服务器进行管理连接。
*   端口列表的第二行 `80/tcp open http` 表明系统正在接受端口 `80` 上的连接请求，该端口由超文本传输协议 (HTTP) 用于传送网页。
