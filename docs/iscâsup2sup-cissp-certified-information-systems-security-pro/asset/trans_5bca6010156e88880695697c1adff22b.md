

VPN 可以使用软件或硬件解决方案来实现。无论哪种情况，都有四种常见的 VPN 协议：`PPTP`、`L2F`、`L2TP` 和 `IPsec`。`PPTP`、`L2F` 和 `L2TP` 在 OSI 模型的数据链路层（第 2 层）运行。`PPTP` 和 `IPsec` 仅限于在 IP 网络上使用，而 `L2F` 和 `L2TP` 可用于封装任何 LAN 协议。

### 点对点隧道协议

**点对点隧道协议 (PPTP)** 是一种从拨号点对点协议开发而来的封装协议。它在 OSI 模型的数据链路层（第 2 层）运行，并用于 IP 网络。`PPTP` 在两个系统之间创建点对点隧道并封装 `PPP` 数据包。它通过 `PPP` 支持的相同认证协议为认证流量提供保护：

*   Microsoft 质询握手认证协议 (`MS-CHAP`)
*   质询握手认证协议 (`CHAP`)
*   密码认证协议 (`PAP`)
*   可扩展认证协议 (`EAP`)
*   Shiva 密码认证协议 (`SPAP`)

`PPTP` 使用的初始隧道协商过程未加密。因此，包含发送方和接收方 IP 地址的会话建立数据包——可能还包括用户名和哈希密码——可能会被第三方拦截。`PPTP` 用于 VPN，但通常会被 `L2TP` 取代，后者可以使用 `IPsec` 为 VPN 提供流量加密。大多数现代 `PPTP` 用法都采用了 Microsoft 定制实现，该实现支持使用 Microsoft 点对点加密 (`MPPE`) 进行数据加密，并支持各种安全认证选项。

`PPTP` 不支持 `TACACS+` 和 `RADIUS`。

### 第 2 层转发协议和第 2 层隧道协议

Cisco 开发了自己的 VPN 协议，称为第 2 层转发 (`L2F`)，这是一种相互认证隧道机制。然而，`L2F` 不提供加密。`L2F` 未被广泛部署，很快就被 `L2TP` 取代了。顾名思义，两者都在第 2 层运行。两者都可以封装任何 LAN 协议。

**第 2 层隧道协议 (L2TP)** 是通过结合 `PPTP` 和 `L2F` 的元素而衍生出来的。`L2TP` 在通信端点之间创建点对点隧道。它缺乏内置加密方案，但通常依赖 `IPsec` 作为其安全机制。`L2TP` 还支持 `TACACS+` 和 `RADIUS`。`IPsec` 通常用作 `L2TP` 的安全机制。

### IP 安全协议

目前最常用的 VPN 协议是 `IPsec`。**IP 安全 (IPsec)** 既是一种独立的 VPN 协议，也是 `L2TP` 的安全机制，并且只能用于 IP 流量。`IPsec` 由 `IPv6` 的安全元素组成，被打包成 `IPv4` 的附加包。`IPsec` 仅在 IP 网络上工作，并提供安全认证以及加密数据传输。`IPsec` 有两个主要组件或功能：

#### 认证头 (AH)

`AH` 提供认证、完整性和不可抵赖性。

#### 封装安全载荷 (ESP)

`ESP` 提供加密以保护传输数据的机密性，但也可以执行有限的认证。它在网络层（第 3 层）运行，可用于传输模式或隧道模式。在传输模式下，IP 数据包的数据被加密，但数据包的头部不被加密。在隧道模式下，整个 IP 数据包被加密，并向数据包添加新头部以控制通过隧道的传输。

VPN 设备是一种网络附加设备，用于独立于服务器或客户端操作系统创建 VPN 隧道。VPN 设备的使用对网络系统是透明的。

### 虚拟局域网

**虚拟局域网 (VLAN)** 是由交换机创建的硬件强制网络分段。默认情况下，交换机上的所有端口都属于 `VLAN 1`。但随着交换机管理员逐端口更改 `VLAN` 分配，各个端口可以被分组在一起，并与其他 `VLAN` 端口指定区分开。`VLAN` 也可以基于设备 `MAC` 地址分配或创建，镜像 IP 子网划分，围绕指定协议，或基于认证。`VLAN` 管理最常用于区分用户流量和管理流量。而 `VLAN 1` 通常被指定为管理流量 `VLAN`。

`VLAN` 用于流量管理。同一 `VLAN` 成员之间的通信无障碍进行，但 `VLAN` 之间的通信需要路由功能，该功能可由外部路由器或交换机的内部软件提供（这是 **L3 交换机** 和 **多层交换机** 术语出现的原因之一）。`VLAN` 被视为子网，但不是子网。`VLAN` 由交换机创建。子网由 IP 地址和子网掩码分配创建。

**VLAN 管理** 是利用 `VLAN` 出于安全或性能原因控制流量。`VLAN` 可用于隔离网络段之间的流量。这可以通过不定义不同 `VLAN` 之间的路由，或通过在特定 `VLAN` 之间（或 `VLAN` 的特定成员之间）指定拒绝过滤器来实现。任何不需要与另一个网段通信以完成工作任务/功能的网段都不应能够这样做。使用 `VLAN` 允许必要的内容，并阻止/拒绝任何不必要的内容。请记住，“默认拒绝；例外允许”不仅是防火墙规则的指导原则，也是安全的一般原则。

`VLAN` 的运作方式与传统子网非常相似。为了使通信从一个 `VLAN` 传输到另一个 `VLAN`，交换机执行路由功能以控制和过滤其 `VLAN` 之间的流量。

`VLAN` 用于在不改变物理拓扑的情况下对网络进行逻辑分段。它们易于实施，管理开销小，且是基于硬件的解决方案（具体来说是第 3 层交换机）。随着网络在虚拟环境或云中构建，通常会使用软件交换机。在这些情况下，`VLAN` 不是基于硬件的，而是基于交换机软件的实现。

`VLAN` 让你能够控制和限制广播流量，并降低网络对嗅探器的脆弱性，因为交换机将每个 `VLAN` 视为一个单独的网络分区。要在段之间通信，交换机必须提供路由功能。正是路由功能阻止了子网和 `VLAN` 之间的广播，因为路由器（或任何执行第 3 层路由功能的设备，如第 3 层交换机）不会转发第 2 层以太网广播。交换机的这一特性阻止了 `VLAN` 之间的以太网广播，从而有助于防止广播风暴。**广播风暴** 是不需要的以太网广播网络流量的洪流。
