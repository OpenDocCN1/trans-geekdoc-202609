

# 配置审计

应定期进行配置审计，以确保实际生产环境与会计记录一致，且未发生未经授权的配置变更。

变更管理和配置管理技术共同构成了软件工程师武器库的重要组成部分，并保护组织免受开发相关的安全问题影响。

## DevOps 方法

最近，许多技术专业人员认识到软件开发、质量保证和技术运维这三大主要 IT 职能之间存在脱节。这些职能通常由截然不同类型的人员组成，且位于独立的组织孤岛中，彼此经常发生冲突。这种冲突导致代码创建、测试和部署到生产系统的过程出现漫长延迟。当问题出现时，团队往往不是协作解决问题，而是将问题“扔过墙头”甩给对方，导致官僚主义的来回推诿。

DevOps 方法旨在通过将这三大职能融合在一个统一的运营模型中来解决这些问题。*DevOps* 一词是 Development（开发）和 Operations（运维）的组合，象征着这些职能必须融合协作以满足业务需求。[图 20.6](#c20.xhtml#figure20-6) 中的模型展示了软件开发、质量保证和 IT 运维的重叠性质。

DevOps 模型与敏捷开发方法紧密契合，旨在大幅缩短开发、测试和部署软件变更所需的时间。虽然传统方法通常导致主要软件部署非常不频繁（可能一年一次），但使用 DevOps 模型的组织通常每天部署代码数次。有些组织甚至以持续部署为目标，代码每天可能推出数十次甚至数百次。

## 应用程序编程接口

虽然早期的 Web 应用程序通常是独立系统，处理用户请求并提供输出，但现代 Web 应用程序要复杂得多。它们通常包含多个不同 Web 服务之间的交互。例如，零售网站可能会使用外部信用卡处理服务，允许用户在社交媒体上分享购买记录，与物流提供商网站集成，并在其他网站上提供推荐计划。

为了使这些跨站点功能正常工作，网站之间必须相互交互。许多组织为此提供*应用程序编程接口 (API)*。API 允许应用程序开发人员绕过传统网页，通过函数调用直接与底层服务交互。例如，社交媒体 API 可能包含以下一些 API 函数调用：

*   `Post status`（发布状态）
*   `Follow user`（关注用户）
*   `Unfollow user`（取消关注用户）
*   `Like/Favorite a post`（点赞/收藏帖子）

提供和使用 API 为服务提供商创造了巨大的机遇，但也带来了一些安全风险。开发人员在创建和使用 API 时必须意识到这些挑战并加以解决。

首先，开发人员必须考虑身份验证要求。某些 API（如允许查询天气预报或产品库存的 API）可能面向公众开放，使用时不需要任何身份验证。其他 API（如允许修改信息、下单或访问敏感信息的 API）可能仅限特定用户使用，并依赖安全的身份验证。API 开发人员必须知道何时需要身份验证，并确保验证每次 API 调用的凭据和授权。这种身份验证通常通过向授权 API 用户提供复杂的 API 密钥来实现，该密钥随每次 API 调用传递。后端系统在处理请求前验证此 API 密钥，确保发起请求的系统已获授权进行特定的 API 调用。

API 还必须像任何 Web 应用程序一样经过彻底的安全缺陷测试。您将在下一节了解更多相关内容。

## 软件测试

作为开发过程的一部分，您的组织应在内部分发软件（或将其发布到市场）之前对其进行彻底测试。解决测试问题的最佳时机是在模块设计阶段。换句话说，您用于测试产品的机制和用于探索产品的数据集，应与产品本身并行设计。您的编程团队应开发特殊的测试数据套件，以最大程度地覆盖软件的所有路径，并预先知道正确的输出结果。

您应执行的测试之一是*合理性检查*。合理性检查确保软件返回的值符合指定标准，且在合理范围内。例如，一个计算人类最佳体重的程序如果返回 612 磅的值，肯定无法通过合理性检查！

此外，在进行软件测试时，您应检查产品如何处理正常有效的输入数据、错误的数据类型、超范围值以及其他边界和/或条件。实际工作负载提供了最佳的压力测试。但是，您不应使用实时或实际现场数据进行测试，尤其是在早期开发阶段，因为缺陷或错误可能导致测试数据的完整性或机密性遭到破坏。

测试软件时，您应适用与组织其他方面相同的职责分离规则。换句话说，您应将软件测试分配给开发代码的程序员以外的人员，以避免利益冲突，并确保成品更安全、功能更完善。当第三方测试您的软件时，您更有可能获得客观、无偏见的审查。第三方测试允许进行更广泛、更彻底的测试，并防止程序员的偏见和倾向影响测试结果。

您可以使用三种软件测试方法：

### 白盒测试

白盒测试检查程序的内部逻辑结构，逐行分析代码，以发现潜在错误。

### 黑盒测试

黑盒测试从用户角度检查程序，通过提供各种输入场景并检查输出来进行。黑盒测试人员无法访问内部代码。交付前进行的最终验收测试是黑盒测试的常见示例。

### 灰盒测试

灰盒测试结合了上述两种方法，常用于软件验证。在此方法中，测试人员从用户角度检查软件，分析输入和输出。他们也可以访问源代码，并利用它来帮助设计测试。然而，他们在测试过程中并不分析程序的内部运作。
