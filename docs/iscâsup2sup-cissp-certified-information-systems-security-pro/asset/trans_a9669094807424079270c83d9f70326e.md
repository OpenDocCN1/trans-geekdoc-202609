

### 安全模式要求

*   部分用户没有有效的安全许可来访问系统处理的所有信息。因此，访问控制取决于主体的许可级别是否主导客体的敏感度标签。
*   每个用户必须拥有其将在系统上访问的所有信息的访问批准。
*   每个用户必须拥有其将在系统上访问的所有信息的有效“知悉必要性”。

当你浏览联邦政府批准的各种操作模式的要求时，你会注意到，随着从专用系统过渡到多级系统，控制访问系统的用户类型的管理要求会减少。然而，这并不降低限制个人访问的重要性，以便用户只能获取他们合法有权访问的信息。正如上一节所讨论的，这只是将执行这些要求的负担从行政人员（他们物理上限制对计算机的访问）转移到硬件和软件（它们控制多用户系统中每个用户可以访问的信息）的问题。

[表 9.1](#c09.xhtml#table9-1) 根据所需的安全许可、“知悉必要性”以及处理来自多个许可级别数据的能力（简写为 PDMCL）总结并比较了这四种安全模式。在比较所有四种安全模式时，通常认为多级模式面临最高级别的风险。

[**表 9.1**](#c09.xhtml#tableanchor9-1) **安全模式比较**

| 模式 | 许可 | 知悉必要性 | PDMCL |
| --- | --- | --- | --- |
| 专用 | 相同 | 无 | 无 |
| 系统高 | 相同 | 是 | 无 |
| 分区 | 相同 | 是 | 是 |
| 多级 | 不同 | 是 | 是 |

如果所有用户必须具有相同的安全许可，则许可为**相同**；否则为**不同**。

如果“知悉必要性”不适用且未被使用，或者虽然被使用但所有用户都有知悉系统上所有数据的必要性，则为**无**；如果访问受“知悉必要性”限制，则为**是**。

如果使用了 CMW 实现，则适用 PDMCL（**是**）；否则 PDMCL 为**无**。

### 操作模式

现代处理器和操作系统旨在支持多用户环境，在这种环境中，单个计算机用户可能不会被授予访问系统所有组件或存储在其中的所有信息的权限。因此，处理器本身支持两种操作模式：用户模式和特权模式。

#### 用户模式

**用户模式** *用户模式*是 CPU 在执行用户应用程序时使用的基本模式。在此模式下，CPU 仅允许执行其完整指令集的一部分。这旨在防止用户因执行设计不良的代码或无意中误用代码而意外损坏系统。它还可以保护系统及其数据免受恶意用户的侵害，后者可能会尝试执行旨在绕过操作系统安全措施的指令，或错误地执行可能导致未经授权的访问或对系统或有价值的信息资产造成损害的操作。

通常，用户模式下的进程在称为*虚拟机 (VM)* 的受控环境中执行。虚拟机是由操作系统创建的模拟环境，为程序执行提供安全高效的场所。每个 VM 都与所有其他 VM 隔离，并且每个 VM 都有自己的分配内存地址空间，可供托管的应用程序使用。特权模式（又称内核模式）中的元素负责创建和支持 VM，并防止一个 VM 中的进程干扰其他 VM 中的进程。

#### 特权模式

**特权模式** CPU 还支持*特权模式*，旨在授予操作系统访问 CPU 支持的完整指令范围的权限。此模式有多种名称，具体术语因 CPU 制造商而异。一些更常见的名称包括在以下列表中：

*   特权模式
*   监督模式
*   系统模式
*   内核模式

无论使用哪个术语，基本概念保持不变——此模式授予在 CPU 上执行的进程广泛的权限。因此，设计良好的操作系统不允许任何用户应用程序在特权模式下执行。出于安全性和系统完整性的目的，只有操作系统本身的组件进程才被允许在此模式下执行。

### 内存

系统的第二个主要硬件组件是*内存*，即计算机需要保持随时可用的信息的存储库。有许多不同种类的内存，每种都适用于不同的目的，我们将在后续章节中逐一介绍。

#### 只读存储器

*只读存储器 (ROM)* 顾名思义——它是 PC 可以读取但无法更改的内存（不允许写入）。标准 ROM 芯片的内容在出厂时被“烧录”进去，最终用户根本无法更改。ROM 芯片通常包含计算机在从磁盘加载操作系统之前启动时使用的“引导”信息。这包括熟悉的*加电自检 (POST)* 诊断系列，每次启动 PC 时都会运行。

ROM 的主要优势在于它无法被修改。用户或管理员错误绝无可能意外擦除或修改此类芯片的内容。这一属性使 ROM 成为协调计算机最内部工作原理的极佳选择。

有一种 ROM 管理员可以在一定程度上修改。它称为可编程只读存储器 (PROM)，其几种子类型将在下文描述：

##### 可编程只读存储器 (PROM)

**可编程只读存储器 (PROM)** 基本的*可编程只读存储器 (PROM)* 芯片在功能上类似于 ROM 芯片，但有一个例外。在制造过程中，PROM 芯片的内容不像标准 ROM 芯片那样在工厂被“烧录”。相反，PROM 结合了特殊功能，允许最终用户稍后烧录芯片的内容。然而，烧录过程有着类似的结果——一旦数据被写入 PROM 芯片，就无法进行进一步更改。烧录后，PROM 芯片基本上就像 ROM 芯片一样运行。

PROM 芯片为软件开发人员提供了在高速、定制化内存芯片上永久存储信息的机会。PROM 常用于需要某些自定义功能但一旦编程后很少更改的硬件应用中。

##### 可擦除可编程只读存储器 (EPROM)

**可擦除可编程只读存储器 (EPROM)** 将 PROM 芯片相对较高的成本与软件开发人员编写代码后不可避免地想要修改代码的愿望相结合，便得出了开发*可擦除 PROM (EPROM)* 的基本原理。EPROM 有两个主要子类别，即 UVEPROM 和 EEPROM（见下一项）。*紫外线 EPROM (UVEPROM)* 可以用光擦除。这些芯片有一个小窗口，当用特殊的紫外线照射时，会导致芯片内容被擦除。此过程完成后，最终用户可以将新信息烧录到 UVEPROM 中，就像它从未被编程过一样。

##### 电可擦除可编程只读存储器 (EEPROM)

**电可擦除可编程只读存储器 (EEPROM)** 一种比 UVEPROM 更灵活、更友好的替代方案是*电可擦除 PROM (EEPROM)*，它利用传送到芯片引脚的电压来强制擦除。
