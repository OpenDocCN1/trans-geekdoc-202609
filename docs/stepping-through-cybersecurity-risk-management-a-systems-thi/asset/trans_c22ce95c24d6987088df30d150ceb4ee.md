

虽然 [图 6.1](#c06.xhtml#c6-fig-0001) 中的图表并非详细的技术分析，但它提供了足够的关于攻击工作原理的细节，足以让负责构建修复计划的技术团队了解情况。第一步可以通过至少三种方式来阻止。第一种是阻止 Web 服务器的所有出站网络连接，以便 Web 服务器无法访问黑客网站。第二种是确保所有输入字段都扫描括号，并自动解析包含括号的任何数据字段，拒绝任何与 `jndi` 命令模式匹配的字段。第三种是将 `jndi` 日志代码升级到已修补漏洞的版本，并确保从 Web 服务器中删除所有早期易受攻击的 `jndi` 代码（同时配备适当的检测程序，以确保不存在此类情况）。所有这些措施都是良好网络安全卫生习惯的示例。第一个选项是实施起来最快、最简单的，但如果 Web 服务器出于其他原因需要出站访问，它可能会干扰 Web 服务器功能，因此需要进行一些研究和规划。第二个选项对运营的影响较小，但可能需要一些时间和测试，因为 Web 服务器可能有数百个数据字段。第三个选项看起来最安全，唯一的风险是来自仓促测试的新版本的意外日志功能。网络安全风险分析师将与问题负责人讨论这些选项，并帮助决定问题修复的最佳短期和长期方法。然后，分析师将帮助应用团队制定计划，在短期内实施至少一种修复措施，并在长期内实施所有三种措施。请注意，短期计划解决的是近因，即当前漏洞，而长期计划旨在降低常见根本原因的风险，即目前未知的利用类似系统性弱点的漏洞。

尽管可能存在关于是否将某情况标记为网络安全风险问题的争论，并且在问题被识别时，该问题是否与控制决策相关可能尚未确定，但企业将某情况标记为网络安全风险问题这一事实本身，就是在分析网络安全风险时需要考虑的事项存在的证据。它明显与风险层次结构中某处的事件原因相关，即使这些事件的完整集合并未被充分理解。因此，虽然“问题”似乎是一个模糊的术语，但当它被“风险”一词修饰时，其意义就非常明确。

## 6.2 分类

即使是小型公司也可能有数十个网络安全风险问题需要解决。保持对这些问题的最新信息并跟踪其完成情况的重要性不容低估。优先级标签旨在传达紧迫性，例如：`critical`、`significant`、`important`。选择是通过估计问题被威胁行为者利用的可能性，以及此类事件的预期频率和影响来做出的。推测，未被提升到重要性级别的问题不值得进行正式的风险跟踪，尽管一些组织会包含一个传达无紧迫性的类别，例如 `Notable`。在问题跟踪系统中包含时，这个类别更像是一个 `opportunity for improvement` 类别，用于跟踪类似于可有可无的效率控制的想法。

问题分类需要一个有组织的数据集，以便快速进行状态报告。问题通常不仅按优先级分类，还按类型、状态、来源和组织分类。[Figure 6.2](#c06.xhtml#c6-fig-0002) 显示了跟踪系统中记录的示例问题，其中包含这些分类的下拉选择。尽管类别通常是自定义的，但一般来说，问题类型将指代技术环境，在此情况下，为内部、云或第三方。状态将包括草稿、打开和关闭。来源将指示组织如何了解该问题。常见的来源是内部和外部审计，因为识别风险问题是他们的工作。但来源也可能包括监管机构、客户以及内部或外包的评估。如果问题在 CISO 组织内部被发现，来源通常会显示为“self‐identified”，以将其与安全计划外部的来源区分开来。

[Figure 6.2](#c06.xhtml#c6-fig-0002) 中每个下拉选择的顶部是字段的默认值，如果在创建时未做选择，将设置为该值。此值表明问题类型和优先级应保持明显的“Not set”，除非由网络安全分析师明确识别。状态将为“Draft”，以防止在数据输入完成前出现在报告中。如果未选择标准来源，将被视为“Other”，推测是一个小集合。组织通常是企业中分配修复活动的部门，联系人将是该组织中负责修复实施的人员。但是，除非正式分配到其他地方，否则责任可能默认保留在 CISO。当修复需要多个部门按顺序协作（如设计、开发和部署）时，组织可以在企业人员层次结构的更高级别指定，联系人可能会随问题的生命周期而变化。

当风险跟踪系统与风险层次结构集成时，这些分类允许按风险快速搜索和报告风险问题，以及总体风险修复状态的一目了然的状态报告。[Figure 6.3](#c06.xhtml#c6-fig-0003) 是一个示例，说明如何为每个问题标记风险类别或子类别可以提供信息。网络安全专业人员经常使用红绿灯类比来显示每个事件类别中需要解决的问题的相对优先级，如本插图所示。图右侧的饼图使用了切片的有序红绿灯颜色范围，并标记了重要、显著和关键网络安全风险问题的类型。图左侧是网络安全风险层次结构，列出了事件类别及其下方的缩进子类别。当饼图中计数的风险问题与网络安全风险类别或其子类别之一匹配时，匹配的那些在图左侧会被放大。

风险层次结构还以字体大小有序地表示重要、显著和关键的严重程度措施。没有实际事件的类别和子类别字体最小。有重要事件的略大一些。有显著事件的比那些略大，而有关键事件的类别字体最大。请注意，当两种风险子类别映射到不同严重程度的事件时，最高严重程度会向上冒泡到更高级别的类别。顶层网络安全风险继承其类别的最高优先级。请注意，这不是风险的直接度量，因为风险是以概率来衡量的，它只是一个信息图，可以与其他风险指标结合使用，以便在估计风险概率时使用。
