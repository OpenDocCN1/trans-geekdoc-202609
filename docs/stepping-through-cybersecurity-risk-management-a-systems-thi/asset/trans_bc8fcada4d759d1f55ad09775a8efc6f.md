

软件漏洞行业包含许多专业和犯罪功能，工作流程的不同方面由不同人群完成。[图 2.13](#c02.xhtml#c2-fig-0013) 显示了零日市场中漏洞的生命周期。如果发现或购买漏洞的人决定不亲自利用它发起网络攻击，则可以将其出售给漏洞利用市场中的软件开发者，后者又会将他们创建的漏洞利用软件出售给更多商业恶意软件提供商，这些提供商会将漏洞利用代码整合到带有窗口和下拉框以及各种存储结果功能的易于使用的“漏洞利用工具包”中。漏洞利用工具包制作商反过来可能会将工具包出售给某人，该人会像任何其他企业托管软件即服务（SaaS）操作一样在云端托管这些工具包。或者，他们可能会为工具包补充说明并直接将产品交付给客户，此配置可针对特定买家进行定制。

如果工具包包含勒索软件和 DDoS 等明显的恶意用例，网络犯罪市场制定者会通过电子邮件和暗网聊天联系潜在客户，商定价格并出售不仅是软件，还有犯罪软件服务。他们从事市场交付服务，代表买家（例如签订 DDoS 合同的赌博网站运营商）操作恶意软件。如果软件仅用于扫描漏洞，其客户将包括网络安全防御者和威胁行为者。

## 2.3 威胁向量

虽然某些威胁相对容易执行，但要成功攻击一个有防护的目标，需要大量的研究和规划。威胁行为者会花费大量时间和精力进行*侦察*，以识别目标系统中的漏洞。即使发现了漏洞，也可能需要数月或数年才能弄清楚这些漏洞以何种方式暴露目标资产，从而使其能够进行操纵。随后，他们需要制定战术、技术和程序（TTPs）来利用漏洞，以影响或操纵资产以实现其目标。威胁行为者实现目标的方法各不相同。网络安全专业人员将这种情况称为“攻击者的优势和防御者的困境”。防御者需要在所有战线上保持警惕。威胁行为者只需要一个漏洞就能突破防御者的防线。尽管如此，尽管威胁网络从事发起网络攻击的活动种类繁多，但也存在经验丰富的网络安全分析师可以识别的明确攻击模式。

[图 2.14](#c02.xhtml#c2-fig-0014) 是威胁行为者战术列表，包括侦察，按其在攻击中通常出现的顺序排列（MITRE 2015–[2023](#c02.xhtml#c2-bib-0014））。这些战术大多是渐进的。例如，必须先访问目标系统或网络，才能在其系统上执行代码。在网络攻击过程中按顺序执行的一系列活动称为“威胁向量”。

通常将简单的网络安全威胁向量显示为序列箭头，更复杂的向量可以使用任何流程图方法绘制。[图 2.15](#c02.xhtml#c2-fig-0015) 显示了与[图 2.9](#c02.xhtml#c2-fig-0009)中绘制的攻击路径相对应的威胁向量。针对面向公众网站的攻击有四个步骤，其中只有一个步骤是黑客执行的活动。其余步骤由受害者执行。针对内部网站的攻击有六个步骤，其中两个步骤由受害者（无意中）执行。然而，步骤分解的解释力比数字更重要。其理念是，这些向量可用于培训利益相关者，使其理解自己对攻击者活动的脆弱性。还要注意，内部攻击向量将 `DBMS` 向黑客返回数据的活动与 `web server` 从 DBMS 向黑客返回数据的活动分开，将外部攻击的两个步骤合并为内部攻击中的一个步骤，并将 Web 服务器和 DBMS 指定为业务应用程序。尽管这种描述对于预期受众和企业漏洞分析可能完全合理，但也使得在不同环境中比较同一攻击的漏洞变得困难。例如，一个环境在网站应如何验证从数据库请求的数据是否符合预期方面可能比另一个环境有更多的保障措施。

不同组织可能使用不同技术粒度级别呈现相同攻击路径的观察，在网络安全运营领域是常见现象。由于技术发展迅速，难以达成共同模式。这一现象可以追溯到计算机病毒的早期。当时，销售安全软件的公司会同时独立发现新攻击，并分别以不同名称发布，这些供应商似乎都反对标准化，各自声称其产品独一无二，阻碍了网络安全分析师将其归入明确定义的类别的努力。杀毒软件供应商为同一病毒赋予不同名称，并各自声称最先发现它。一篇著名的论文将这种情况称为“漏洞巴别塔”（参见[图 2.16](#c02.xhtml#c2-fig-0016)）（Martin [2001](#c02.xhtml#c2-bib-0012)）。

为回应这种混乱，美国国防高级研究计划署与 NIST 共同赞助了一次会议，讨论制定漏洞标记标准。该工作与 MITRE 约在同一时期发起的通用漏洞和披露（CVE）计划合并。源自该计划的持续工作促成了 NVD 的创建，NVD 还标准化了通用平台枚举（CPE）产品名称，并创建了通用漏洞评分系统（CVSS）以帮助传达与漏洞相关的威胁等级。美国国土安全部网络与基础设施安全局（CISA）也利用 CVE 在已知漏洞利用正在被主动寻求和利用时向公众发出警告。他们广播了已知被利用漏洞（KEV）的存在。软件开发社区内部还启动了一项平行工作，试图从一开始就避免创建漏洞，这就是通用弱点枚举（CWE），这是由开发者错误（例如未检查 Web 输入字段中的 SQL 代码）创建的软件和硬件弱点共享列表。这些数据有助于为通用攻击模式枚举和分类（CAPEC）研究提供信息，CAPEC 记录了常见的攻击者技术，例如 SQL 注入。这些存储库经常相互引用，共同为独立从事威胁分析、检测、响应和缓解各个方面的网络安全专业人员产生共同词汇。它们通过使供应商能够将标准术语中的多样化威胁情报整合到其产品中，减轻了巴别塔问题。[图 2.17](#c02.xhtml#c2-fig-0017) 显示了这些标准之间的关系。
