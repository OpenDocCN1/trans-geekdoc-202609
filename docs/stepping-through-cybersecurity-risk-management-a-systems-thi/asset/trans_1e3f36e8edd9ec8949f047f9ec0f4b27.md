此类卡片通常会在另一面印有审计员的照片，包含有关审计员在组织结构中所处位置的信息，以及审计员及其主管的联系方式。尽管此类对信息请求的全面批准通常不会扩展到风险分析师，但如果这种情况也发生（无论是正式还是非正式），那么这将使他们的工作比原本更容易得多。

研究不仅限于可复现的报告，还可以使用任何类型的媒体或可信的观察来协助风险沟通。关键在于关注研究问题的答案，并确保企业内所有可用的相关信息都被提供，以服务于制定答案。例如，在风险补救中经常辩论的话题是：是使用安全工具来补救应用程序安全漏洞，还是更改应用程序代码本身以消除它。在像 log4j 这样的漏洞情况下，可以使用 Web 应用程序防火墙（`WAFW`）来拦截所有用户输入，扫描其中可能被 Java log4j 漏洞代码解析为恶意命令的带有花括号的模式，并在发现任何此类模式时终止网络连接。高管有时会质疑为什么还需要另一个安全工具，而 DevOps 团队可能有自己的时间优先级，因此更倾向于购买工具而不是更改代码。风险分析师可能不会带来数据来回答问题，而是带来一些图表，如 [图 10.3](#c10.xhtml#c10-fig-0003) 和 [图 10.4](#c10.xhtml#c10-fig-0004) 中所示。[图 10.3](#c10.xhtml#c10-fig-0003) 是 `WAFW` 在网络中位置的简化图，以帮助解释它的功能和工作原理。例如，讨论将包括介绍 `WAFW` 本身是可编程的，并且其正确配置和运行是获得预期控制改进的关键。

## 图 10.4 主控制与补偿控制

[图 10.4](#c10.xhtml#c10-fig-0004) 包含三个图表。第一个图表显示一个标记为 *Application* 的圆圈和其中一个较小的标记为 Vulnerabilities 的圆圈。*Vulnerabilities* 圆圈与另一个标记为 *Known Exploits* 的圆圈重叠。它说明应用程序漏洞是应用程序的一部分，并且可能存在比我们了解的已被利用的漏洞更多的漏洞，以及该应用程序中的一些漏洞已知会被利用。那些已知会被利用的漏洞被标记为 *Target for Application Input Validation (AIV) or Compensating Controls (`WAFW`)*。`AIV` 是一种强制执行输入字段正确语法（例如，SSN、日期、电子邮件）以及这些值在应用程序上下文中的正确性的方法（例如，预期范围内的货币值，仅限字母和破折号的姓名）。如果它是软件本身代码的一部分，那么 `WAFW` 的该功能就不需要用来关闭已知被利用的漏洞。因此，该图将它们作为消除漏洞的替代方案呈现。

第二个图表说明，`AIV` 的替代方案会使漏洞圆圈变小，因为如果应用程序有一种方法来检查所有字段的有效输入，那么它整体上对任何类型的输入伪造攻击的脆弱性就会降低，因为它易受攻击的攻击面显著减少。与已知利用重叠的区域被着色，以显示该解决方案将完全补救应用程序漏洞问题。

该图中的第三个图表有助于解释 `WAFW` 可以通过筛选输入中的恶意模式来保护漏洞的程度。它故意将部分攻击面留白，以显示即使有 `WAFW`，不提供应用程序输入验证的代码仍然可能存在一些漏洞暴露。这是因为很难确保每一种可能的利用模式都包含在 `WAFW` 筛选的模式中。此外，随着零日漏洞的暴露，SecOps 将不得不非常快速地编写 `WAFW` 模式，这种在压力下进行的编码容易出错。

## 10.2 安全类比

另一种有效的高管网络安全沟通类比是将软件架构与土木工程进行比较。例如，用通俗易懂的语言传达网络安全问题，并与土木工程进行类比是有帮助的。在 [图 10.5](#c10.xhtml#c10-fig-0005) 的示例中，一座桥梁存在以下工程和安全问题：

1.  用于建造桥梁的钢材、缆绳和混凝土充满了结构缺陷。

2.  工程师得出结论，如果这些有缺陷的部件不能尽快修补，桥梁可能会倒塌。

3.  桥梁表面严重受损，所需的重新装修有时会削弱整体结构。

4.  桥梁操作员使用一个通知系统，提供关于可能倒塌的任何桥梁的实时信息。（Amoroso，[2007](#c10.xhtml#c10-bib-0001)，第 112 页）

不需要太多想象力就能理解，不识别和修复漏洞可能对安全产生严重影响。结构缺陷既包括旧版软件，也包括零日漏洞。削弱整体结构的重新装修类似于旨在提高代码质量的持续软件更新，但这些更新通常会引入新的漏洞。通知系统是已知被利用漏洞目录（`CISA n.d.`）。此外，嵌入到桥梁等物理系统中的软件数量之多，使得即使是桥梁也容易受到软件故障的影响。尽管类比在桥梁等基础设施项目和自动化电网运营等软件项目之间成立，但该类比并不扩展到基础设施工程师和软件工程师的原则和实践。
