## 2.1.3 Hacker

单词“hacker”过去是指那些长时间编写计算机代码、怀有单一目标并通过长时间高度专注最终成功实现目标的人。优秀的黑客可以解决任何能够由计算机解决的问题，并编写程序来解决它。只有在一些人精通破坏性技术编程之后，“hacker”一词才带上了对手实现目标的负面含义。如今，“hacker”通常被理解为指任何试图或已获得信息系统访问权限的未经授权用户。STIX 标准将 hacker 定义为“倾向于为了刺激或挑战而闯入网络的个人；黑客可能使用高级技能或下载的简单攻击脚本。”

2022 年对已确认网络攻击的最全面研究显示，网站黑客在超过 70% 的所有网络攻击中发挥了作用。该研究将黑客行为定义为“未经（或超出）授权，通过绕过或挫败逻辑安全机制，故意访问或损害信息资产的行为”（Verizon [2022](#c02.xhtml#c2-bib-0030））。如果你将组织的网站视为其在互联网上的“前门”，那么在“后门”添加黑客攻击，意味着试图绕过员工用于远程访问的安全措施，或企业用于自动共享数据的安全措施。后门黑客攻击会增加可归因于黑客的事件数量几个百分点，扫描并利用暴露在互联网上的已知系统级漏洞也是如此。

2021 年，出现了一个大规模的 Web 应用程序漏洞，表明数千家公司的数据极易通过后门漏洞被威胁行为者访问（NIST‐CVE [2021](#c02.xhtml#c2-bib-0020））。该软件名为“log4j”，因为它为 Java 应用程序提供日志记录功能。由于其用途的性质，它能够检查 Web 应用程序可访问的操作系统的任何方面，并能将文件写入操作系统磁盘。它极其隐蔽，以至于美国联邦贸易委员会（FTC）发出了以下警告（FTC [2022](#c02.xhtml#c2-bib-0008））：

> Log4j 是一种无处不在的软件，用于记录消费者面向产品和服务中广泛系统的活动。最近，流行的 Java 日志记录包 log4j（CVE‐2021‐44228）中存在一个严重漏洞被披露，对数百万消费者产品到企业软件和 Web 应用程序构成严重风险。该漏洞正被不断增加的攻击者广泛利用。

请注意，FTC 警告中的“CVE”指的是 MITRE 通用漏洞枚举，该漏洞于 2021 年 8 月在国家漏洞数据库（NVD）中发布。它在 2021 年 11 月被如此广泛地利用，以至于研究人员在 2021 年 12 月匆忙对 NVD 进行了几次更新，然后 FTC 警告才在 2022 年 1 月出现。

理解这一点非常重要：这个漏洞是由一名黑客发现的。这是一个典型的 Web 黑客攻击，因为它利用了流行 Web 服务器中的漏洞（注意，该技术被称为“Web 服务器”，因为它将网站内容传递给互联网用户）。黑客利用了这个漏洞，并且该漏洞利用被公开报告。公开报告为各种经验不足的威胁行为者提供了知识，使他们能够利用黑客的发现并自行利用该漏洞。[Figure 2.8](#c02.xhtml#c2-fig-0008) 是 log4j 攻击的消息序列。它展示了威胁行为者如何利用网站功能来解析其预期处理的变量，同时创建日志条目以向 Web 服务器发送命令。在第一条消息中，它发送命令将其自己的互联网连接数据库添加到网站代码库的可信代码源列表中。这在 Web 服务器上植入了恶意软件（“恶意软件”）。[Figure 2.8](#c02.xhtml#c2-fig-0008) 显示，在威胁行为者植入恶意软件后，他们可以向被攻破的网站发送包含解析为恶意命令的变量的标准 Web 查询，从而扫描内部系统并收集 Web 服务器可访问的任何数据。如果网络允许出站访问，威胁行为者还可以将数据外泄回其自身服务器。

在目标系统上执行任意命令的能力被称为“命令和控制”或“C&C”。它为黑客提供了与被攻破系统的授权用户相同的能力。Log4j 对黑客来说是个大奖。

## 2.1.4 Competitors

竞争对手威胁是指寻求在商业上获得优势的人。即使在计算机出现之前，竞争对手就已知会从竞争对手组织窃取知识产权、商业秘密、战略计划或其他商业数据。他们也曾知会对彼此发动拒绝服务攻击。竞争对手很少亲自参与黑客攻击，而是依赖于拥有实现其目标所需技能的犯罪网络。一个著名的例子是，在线赌博行业在高调体育赛事期间经常进行分布式拒绝服务（DDoS）攻击，将用户从竞争对手网站上踢下线，以便只有他们的网站可供下注（Menn, [2010](#c02.xhtml#c2-bib-0013)）。

在互联网上，一个设备通过简单的请求与另一个设备在网络会话中“同步”，计算机科学家将其称为“SYN”网络“数据包”。接收方用确认响应，即“SYN ACK”数据包。第一个设备必须发送“ACK”回来以完成会话。在这个“握手”之后，两个设备就开始交换信息。[Figure 2.9](#c02.xhtml#c2-fig-0009) 左侧的图示说明了这一概念。连接设备被标记为“CLIENT”，接受连接的设备被标记为“SERVER”。[Figure 2.9](#c02.xhtml#c2-fig-0009) 左侧图示中的前三个箭头说明了连接，这发生在它们之间任何实际通信发生之前。标记为“FIN”的箭头说明了协议的优雅断开连接握手。
