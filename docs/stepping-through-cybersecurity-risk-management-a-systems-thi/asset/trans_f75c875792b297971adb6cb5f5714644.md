

例如，如果渗透测试发现目前已知在类似企业中被利用的漏洞，则该漏洞可能被不准确地声明为风险。该漏洞的明显补救措施是安装其供应商为此目的提供的软件安全 `patch`。此补救措施修复了已知漏洞，但并未解决构成真正风险的底层事件集的根本原因。风险是一组具有相似根本原因和发生概率的事件。消除一个漏洞并不能解决企业允许其系统中存在已公开漏洞这一事实。通常，解决根本原因比解决单个问题要困难得多。根本原因通常是底层的系统性情况，其补救措施需要在人员、流程和技术方面同时进行组合变更。常见的根本原因包括设计缺陷、推迟维护、经济压力、进度限制、培训不足、对程序的疏忽、缺乏计划和准备、沟通失败、傲慢以及压制性的政治议程（Abkowitz [2008](#c06.xhtml#c6-bib-0001)，[第 1 章](#c01.xhtml)）。将问题误认为风险不仅仅是沟通差距，而是风险治理逻辑的崩溃。在已公开漏洞的示例中，根本原因是推迟维护，补救措施应是建立漏洞管理流程，以防止此类情况再次发生。这将包括频繁扫描现有的已公开漏洞、系统性地消除它们、监控宣布新漏洞的出版物、检查这些漏洞是否存在于系统中，以及如果发现，则将其消除。

考虑如何使用 CISO 等式来识别风险问题。首先从常规漏洞扫描中识别出漏洞的情况开始。回到 [图 3.4](#c03.xhtml#c3-fig-0004)，CISO 等式告诉我们，漏洞本身并不意味着会发生导致损害的网络安全事件的概率。必须存在可用的漏洞利用，并且必须存在未被阻止的威胁。此外，该漏洞利用必须能够造成足以影响企业的重大损害。

无论是在情景研讨会中进行，还是由审计师或网络安全风险分析师独立进行，研究漏洞利用、映射到企业系统、评估预防控制措施和估算损害的过程都是网络安全风险分析的一部分。风险问题是此类风险分析的产物。将“网络安全风险”这一形容词应用于“问题”的过程通常受到严格控制，并从尽职调查的角度进行彻底审查。尽职调查应确保重大风险得到充分考虑，并管理偏见。（例如，对特定技术控制供应商的个人偏好不应不当影响由这些产品之一处理的风险的估计概率。）只有在围绕问题（讨论话题）的情况分析完成后，该情况才会被声明为风险证据（`实际`问题）。对情况的描述成为 `风险问题`。基于此，它会被添加到问题跟踪列表中。将问题列入列表并不意味着它会自动获得高优先级的补救，但这意味着其优先级应正式分配，并跟踪其补救情况。它已被识别为重要。问题跟踪系统的一般理念是，列表中的事项已获得管理层的同意，应按优先顺序进行补救，视时间和资源而定。

简单来说，如果问题提供证据表明网络安全风险类别中的事件比没有该问题时更可能发生，则该问题是网络安全风险问题。一个简单的例子是系统漏洞，该漏洞已知是常见威胁向量的一部分（例如，[第 2 章](#c02.xhtml)中讨论的 log4j 漏洞）。假设漏洞评估显示多个服务器存在该漏洞。该漏洞一直被持续利用，因此自 CISA‐KEV 发布以来，它就出现在了 CISA 已知被利用漏洞目录中（[2023](#c06.xhtml#c6-bib-0002））。该目录中存在如此高效的漏洞利用，加上面向互联网的服务器上存在该漏洞，使得企业遭受网络攻击的可能性远高于没有该漏洞时的可能性。还假设该漏洞已在类似于该企业的组织中被利用。因此，即使概率无法以数字精度说明，该情况（即面向互联网的 log4j 漏洞存在这一问题）也应给予企业最高优先级（例如，严重）。仅凭这些信息，网络安全风险分析师就有理由开立风险问题并分配问题负责人，该负责人通常是负责 Web 服务器的应用程序团队经理。

然而，不应期望问题负责人会自动将风险问题视为优先事项，因此，除了论证可能发生网络攻击之外，网络风险分析师还应在尽可能低的技术细节层面研究漏洞，以识别中断相应威胁向量的技术方法。在 log4j 案例中，该漏洞可以通过构建一个看起来像无害变量的字符串来利用，该字符串对 Java 解释器来说是无害的，但实际上会返回代码，这些代码将被纳入目标 Web 服务器的运行时环境并由其执行。[图 6.1](#c06.xhtml#c6-fig-0001) 是 log4j 攻击中威胁向量的一个示例。它展示了黑客如何利用网站的功能，将其自己的互联网连接数据库添加到网站代码库的可信代码源列表中，从而扩展 log4j 执行代码的能力，以执行任何与目标系统兼容的恶意软件（“恶意软件”）。在 [图 6.1](#c06.xhtml#c6-fig-0001) 的威胁向量中，步骤 1 是找到一个 Web 服务器数据输入字段，该字段将由 Web 服务器的日志记录进程解析。登录字段是一个很好的猜测，因为大多数服务器都会记录成功和失败的访问尝试。这发生在步骤 2 中。在步骤 3 中，黑客提出另一个要解析的变量，该变量调用步骤 2 中加载的恶意代码。在这种情况下，恶意代码将 Web 服务器的配置和代码库发送给黑客。黑客分析这些数据以创建自定义数据库攻击。这被放入另一个变量中并由服务器执行。数据库中的数据随后被发送回黑客服务器。
