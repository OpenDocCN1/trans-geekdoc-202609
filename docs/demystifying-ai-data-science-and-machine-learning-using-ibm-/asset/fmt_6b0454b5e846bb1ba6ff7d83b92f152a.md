
# Lift Chart

In the Lift chart, the x-axis represents percentiles, and the y-axis represents lift values. For any given number of cases (X-value), the lift value indicates the expected number of positives that would be predicted. The baseline, or no model, is represented by a horizontal line intersecting the y-axis at 1. For example, selecting 10% of the data without a predictive model would predict 10% of the positives, representing **no lift** (Lift = 1), meaning cases are selected randomly without the model's influence.

The **Lift curve** illustrates how building a predictive model allows us to predict a higher number of positive cases, demonstrating the model's effectiveness. [Figure 6.11](#chapter6.xhtml#fig6_11) provides an example of a Lift chart, showing that if we select 20% of the cases using the model, we can predict 50% of the positive cases (2.5 times more than without a model), as the Lift value is 2.5. The higher the Lift value, the better the model. To determine which model performs best, the Lift chart should be compared with other models.

## Gini Coefficient

![](images/ufig6_36.jpg)

203\. The **Gini coefficient** measures a model's discriminatory power or its effectiveness in distinguishing between positives and negatives. In machine learning, the Gini coefficient indicates how evenly positive rates are distributed across the attributes of a characteristic. The Gini coefficient ranges from 0 to 1, with higher values indicating better model performance. Essentially, the Gini coefficient shows how close the model is to being perfect and how far it is from being random.

There are several ways to calculate the Gini coefficient, but a common method is using the **Area Under the ROC Curve (AUROC)**. Most software provides the AUROC value, and once it's determined, the Gini coefficient (also called **Somers’ D Gini**) can be calculated as follows. **Somers’ D** is named after Robert H. Somers, who proposed the metric in 1962:

```
Gini = 2 * AUROC – 1
```

While there is no standard cutoff for the Gini coefficient, a **rule of thumb** is that a Gini coefficient of 0.6 or higher indicates a good model fit.

# Cost Sensitive Learning (CSL)

As introduced in [**Chapter 3**](#chapter3.xhtml), **Cost-Sensitive Learning (CSL)** is a popular method that allows us to evaluate and select a model based on the costs of misclassification. It is particularly effective in improving a model's performance when dealing with imbalanced datasets. In business decision-making, relying solely on the misclassification rate may not be sufficient for selecting a predictive model. Instead, we must consider the costs of misclassification because, in most cases, the cost of false negatives and false positives is not equal.

For instance, consider a predictive model for detecting **fraudulent credit card transactions**. The cost of correctly classifying a transaction is zero (the model performs as expected). However, the cost of misclassification differs between **false negatives** and **false positives**. Missing a fraudulent transaction (false negative) can result in direct customer loss, further fraudulent uses, and reputational damage to the company. On the contrary, blocking legitimate transactions (false positives) causes customer inconvenience and incurs unnecessary investigation costs. Typically, the cost of false negatives is higher than the cost of false positives.

![](images/ufig6_38.jpg)

It's important to note that misclassification costs are not always measured in monetary terms. For example, in **terminal disease prediction**, a false negative may result in serious health consequences for the patient, while a false positive may lead to unnecessary treatment and medical expenses. Therefore, it is crucial for decision-makers to properly define and quantify misclassification costs to build useful predictive models. These costs are represented in a **cost matrix**.

Once the misclassification costs for all levels are defined in a table (known as a **decision matrix**), we can train and select the model that minimizes the total cost. [Table 6.9](#chapter6.xhtml#tbl6_9) explains the decision matrix using misclassification costs.

**TABLE 6.9** Decision Matrix—Costs of Misclassification [Return to text.⏎](#chapter6.xhtml#b6tbl6_9)

| | Predicted Event | Predicted Non-event |
| --- | --- | --- |
| Actual event | True positive<br>Cost = 0 | False negative<br>Cost = `C(FN)` |
| Actual non-event | False positive<br>Cost = `C(FP)` | True negative<br>Cost = 0 |

`Total cost = C(FP) × FP + C(FN) × FN`

204\. Where **C(FP)** is the cost of a false positive and **C(FN)** is the cost of a false negative. Keep in mind that **C(FN)** is often higher than **C(FP)**. Most software includes a feature that allows you to input the decision matrix and set total cost minimization as the model selection metric. In later chapters, I will demonstrate how to perform CSL in SAS Enterprise Miner.

In cases of imbalanced datasets with very low response rates, where the cost of false negatives is much higher than false positives, misclassifications of the minority class (rare cases) will be heavily penalized. When comparing models, the one with the **lowest total cost** will be selected, rather than simply the one with the lowest misclassification rate. **CSL** adjusts the decision boundaries during training to account for these costs, improving generalization on the minority class.

On the contrary, we can also focus on **profits** from accurate predictions. For example, accurately predicting customer purchasing decisions can optimize supply chain, distribution, logistics, and shipment strategies, reducing operational costs and increasing revenue. In this scenario, the profit from true positives (buying) is generally higher than from true negatives (not buying). Of course, there are no profits from misclassification.

If focusing on profits, you can define a decision matrix detailing profits for accurate predictions. When comparing models, the one that maximizes total profit is selected. [Table 6.10](#chapter6.xhtml#tbl6_10) presents a decision matrix for profits from accurate classifications.

**TABLE 6.10** Decision Matrix—Profits of Accurate Classification [Return to text.⏎](#chapter6.xhtml#b6tbl6_10)

| | Predicted Event | Predicted Non-event |
| --- | --- | --- |
| Actual event | True positive<br>Profit = `P(TP)` | False negative<br>Profit = 0 |
| Actual non-event | False positive<br>Profit = 0 | True negative<br>Profit = `P(TN)` |

`Total profit = P(TP) × TP + P(TN) × TN`

Where **P(TP)** is the profit from a true positive, and **P(TN)** is the profit from a true negative. Typically, **P(TP)** is higher than **P(TN)**.

What if we want to include both **profits** and **costs**? For example, in the case of purchasing decisions, misclassifications could result in increased operational costs due to poor planning. In this case, a decision matrix can combine both profits from accurate classifications and costs from misclassifications. A recommended approach is to define the matrix in terms of profits, assigning negative profit margins for misclassification costs. This way, the objective remains to maximize total profit when selecting the best model. [Table 6.11](#chapter6.xhtml#tbl6_11) illustrates such a matrix.

**TABLE 6.11** Decision Matrix with Profits and Costs [Return to text.⏎](#chapter6.xhtml#b6tbl6_11)

| | Predicted Event | Predicted Non-event |
| --- | --- | --- |
| Actual event | True positive<br>Profit = `P(TP)` | False negative<br>Profit = `−C(FN)` |
| Actual non-event | False positive<br>Profit = `−C(FP)` | True negative<br>Profit = `P(TN)` |
