
When more variables are included in the model, the explanatory power of the model often decreases. I will explore the concept of explanatory power in more detail in [Chapter 6](#chapter6.xhtml), but essentially, it refers to the model's ability to explain the variance in the target variable based on the variance in the predictors. As we add more variables, the model's explanatory power may diminish. To maintain explanatory power with a large number of variables, we require more data points for training the model, which means a larger sample size. Additionally, data partitioning for validation purposes further increases the need for a larger sample size.

So, how large a sample size is sufficient for data mining projects? This is a challenging question, as there is no definitive answer. Some authors suggest that “the more, the better,” while others claim that 10,000 data points are sufficient. I found no consistent guidelines on this topic. The required sample size also depends on the data source, as we cannot use more data than what is available. For instance, some data providers may offer millions of records from hourly operational data, while others, such as those collecting accident data, may only provide thousands of records. Ultimately, we need enough data to train and validate models and ensure the generalizability of the results. However, we must also consider the computing power needed to process very large datasets, as training complex models, such as neural networks, with vast amounts of data can be time-consuming. Based on my experience with data mining projects, I will offer my recommendations.

### Imbalance Ratio

Another important factor in sampling is the imbalance ratio (IR), which is the rate of the events we want to predict. For example, if our target variable is flight delays, the imbalance ratio is the proportion of delayed flights to the total number of flights. The events in this case are delayed flights, while non-events are on-time flights. A balanced dataset is crucial for developing a valid and generalized predictive model. An imbalanced dataset, where the imbalance ratio is too low or too high, can lead to inaccurate predictions. For instance, if the imbalance ratio is 0.1, meaning 10% of the data are events and 90% are non-events, the model may inaccurately predict that all cases are non-events, resulting in a high rate of false negatives. Although the overall prediction accuracy may appear high (90%), the model fails to predict the events (flight delays), rendering it invalid and unusable. Conversely, if the imbalance ratio is too high, with a large number of events compared to non-events, the model may have a high rate of false positives, leading to similar issues. One common solution for an imbalanced dataset is to resample the data to achieve a more manageable response ratio, a topic we will explore later in this chapter.

![](images/ufig3_16.jpg)

73. In conclusion, when selecting a sample size for data mining, it is essential to consider both the number of records and the imbalance ratio. For example, a sample size of 100,000 records with an imbalance ratio of 0.4–0.6 is generally sufficient, whereas a sample size of 1 million cases with an imbalance ratio of 0.03 may still be inadequate. Ideally, an imbalance ratio of 0.5 represents a perfect balance between events and non-events. However, achieving this perfect balance in practice is rare. My recommendation is to aim for a sample size of at least 100,000 cases with an imbalance ratio between 0.4 and 0.6.

## Example: Sampling

![](images/ufig3_17.jpg)

In this section, we will learn how to sample data using SPSS Modeler. Suppose you have a very large dataset for data mining purposes and do not intend to use all the data points. The main reason for this is that such a large dataset may be unnecessary for modeling and could slow down the computing process, affecting model training time. For example, if you have a dataset with 10 million data points but decide to use 100,000 data points for modeling, how do you sample these 100,000 data points from the total 10 million without sacrificing data quality and generalizability? I will demonstrate how to do this using SPSS Modeler.

The first step is to choose the appropriate sampling method. As previously mentioned, probability sampling methods are recommended for data mining projects. SPSS Modeler provides several sampling methods to choose from. In most cases, when dealing with a balanced dataset, random sampling is the preferred method unless there is a specific reason to select another method. Random sampling allows you to draw a sample randomly while maintaining the imbalance ratio. For example, if your full dataset has an imbalance ratio of 0.45 and you want to sample 10% of the data, random sampling will provide you with 10% of the data while preserving the 0.45 imbalance ratio.

Once you have selected the appropriate sampling method, drawing a sample from the full dataset is quite straightforward. Most data mining software applications have built-in sampling features that make this process easy. I will now demonstrate how to perform data sampling in SPSS Modeler. Suppose you decide to use the random sampling method. In SPSS Modeler, there are two ways to perform sampling: when creating a new data source or by using the `Sample` node. I will show you how to use the `Sample` node, as it offers more configuration options, allowing you to customize your sampling process and adjust the settings as needed.

![](images/ufig3_18.jpg)

We will use the example dataset, `AirlineRecommendation`, which we explored in detail in [Chapter 3](#chapter3.xhtml). For the sampling step, we will focus on the target variable, `recommendation`, which indicates whether passengers would recommend the airline for air travel. This is a binary variable 74. with two levels: `Yes` (recommend the airline—events) and `No` (not recommend the airline—non-events). The total dataset contains 124,464 data points, with an imbalance ratio of 0.475 (or 47.5%), which is considered balanced. Our goal is to sample 50% of the data using random sampling.

Follow the steps below to set up the `Sample` node:

1.  Open SPSS Modeler.
2.  Create a new stream and name it “Airline_Sample.”
3.  From the **Sources** group in the Node Pallet, double-click the **Statistics File** node to add it to the stream.
4.  Double-click the **Statistics File** node to open the settings window for this node.
5.  Click the ellipsis button (three-dot button) and select the `AirlineRecommendation.sav` file from your computer.
6.  From the **Field Ops** group, add a **Type** node to the stream and connect it to the data node. This node is used to view and modify the measurement scales and roles of fields.
7.  Double-click the **Type** node to open its settings window.
8.  Check the measurement scales of all fields as listed below. For the field `recommendation`, change the role to **Target**.

    ![](images/ufig3_19.jpg)

9.  From the **Records** group in the Node Pallet, add the **Sample** node to the stream and connect it to the **Type** node.

    ![](images/ufig3_20.jpg)

10. Double-click the **Sample** node to open its settings window.
11. 75. Under the Settings tab, select **Complex** for the Sample method. Choose **Random** for the Sample type and **Proportions** for the Sample units. To sample 50% of the data, set the **Fixed** value to **0.5** for the Sample size.

     ![](images/ufig3_21.jpg)

12. Click **Apply**, and then click **OK**.

This process will prompt SPSS Modeler to randomly sample 50% of the data, as intended. To view the sampled data, add a **Data Audit** node to the `Sample` node and run it. As mentioned earlier, the **Data Audit** node will generate graphical results along with descriptive statistics for our sampled data.
