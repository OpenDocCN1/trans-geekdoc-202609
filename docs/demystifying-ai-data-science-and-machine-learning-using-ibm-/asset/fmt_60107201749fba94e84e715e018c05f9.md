
# Boston Housing Dataset Analysis

The objective of this analysis is to predict the median housing values in Boston, making linear regression the appropriate method for this task.

We have completed three important steps in the data mining process for the Boston dataset: **Data Exploration**, **Transformation**, and **Sampling**. Since these steps were thoroughly covered in [Chapters 3](#chapter3.xhtml), [4](#chapter4.xhtml), and [5](#chapter5.xhtml), I won’t repeat the procedures or results here. However, I will summarize these tasks and present them in the stream for easier reference.

## Data Exploration

In this step, the **Data Audit 1** node is used to generate histograms for all continuous fields and produces descriptive statistics. The data exploration results show that the dataset contains **506** records. The target field (`Imv`) has 54 missing values, but the predictors do not have any missing values. Since linear regression performs better with a complete dataset, it is necessary to impute those missing values.

Additionally, most fields do not follow normal distributions based on their skewness and kurtosis values (these values should ideally be between −0.5 and 0.5 for data to be considered normally distributed). The histograms reveal that some fields, including `Imv`, `Age`, and `Tax`, are slightly skewed, with a few outliers. Other fields exhibit significant skewness and will require normalization (for more details, refer to the Boston dataset example in [Chapter 3](#chapter3.xhtml)).

![Data Exploration Results](images/ufig7_19.jpg)

## Data Sampling

Typically, the next step is sampling. The dataset contains 506 records, and since this is relatively small, we will use all the records for analysis. Therefore, no data sampling is performed at this stage. The primary task in this step is data partitioning, but we will address that after data modification.

## Data Modification

As mentioned earlier, most input fields exhibit non-normal distributions, and the target field (`Imv`) contains missing values. In this step, we perform **data imputation** and **normalization**.

*   **Data imputation**: Using the Quality tab from the Data Audit 1 output, we generate a SuperNode labeled “Missing Value Imputation,” which replaces missing values in the `Imv` field with the mean value.
*   **Data normalization**: To normalize the data, we apply the Transform node to select appropriate transformation functions. This generates a SuperNode called `Supernode_Transform`, which normalizes most input fields except for `Imv`, `Age`, and `Tax`, as they already exhibit near-normal distributions (see the Boston example in [Chapter 5](#chapter5.xhtml) for more details).

![Data Modification Stream](images/ufig7_20.jpg)

## Data Partition

Before building the regression model, it is essential to partition the data. Since the sample size is smaller than 1,000, as recommended in [Chapter 4](#chapter4.xhtml), we partition the data into training and test samples using a 60-40 split ratio. No validation sample is created in this case. The **Partition node** follows the `Super_Transform node` in the workflow.

![Data Partition Node](images/ufig7_21.jpg)

You can set up a data partition using the following selection. This process divides the data into two sub-samples: The **training sample** (60% of the data) will be used to train the model while the **test sample** (40% of the data) will be used to evaluate the model's performance.

![Data Partition Settings](images/ufig7_22.jpg)

### How to Set Up the Regression 1 Model

1.  Open SPSS Modeler.
2.  Create a new stream and name it “**Boston_Regression**.”
3.  Add the data source `Boston.sav` to the stream.
4.  Add a **Type** node to the stream and connect it to the data source. Open the **Type** node settings.
5.  Double-check field names, measurements, and roles.
6.  Set the role for the field `Imv` as **Target**. All other fields should be set as **Input**.
