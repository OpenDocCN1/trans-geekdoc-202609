
*   **Dependency on k-nearest neighbors (k-NN)**: SMOTE relies on the `k-NN` algorithm to generate synthetic samples. The choice of the `k` parameter can impact the quality of synthetic samples, and an inappropriate choice may lead to suboptimal results.

In summary, while SMOTE is a valuable tool for addressing data imbalance, its application should be done carefully, considering the specific characteristics of the dataset and the potential impact on model performance. It is essential to evaluate the trade-offs and monitor the model's behavior when using SMOTE in a data mining project.

## Example: Resampling Data

I will demonstrate how to perform data resampling using SPSS Modeler. For this example, let's consider the **Credit Card Fraud** dataset. The dataset is highly imbalanced, with an imbalance ratio of 0.2%, meaning that only 0.2% of the records are fraud cases, while 99.8% are not ([Table 3.4](#chapter3.xhtml#tbl3_4)).

**TABLE 3.4** Hypothetical Imbalanced Dataset [Return to text.⏎](#chapter3.xhtml#b3tbl3_4)

| Variable | Formatted Value | Frequency Count | Percent |
| --- | --- | --- | --- |
| Class | True (1) | 492 | 0.2 |
| Class | False (0) | 284,315 | 99.8 |

*   **Dataset:** `CreditFraud.sav`
*   **Target variable:** `Class` (Flag: True-1; False-0)

We apply three different resampling approaches: undersampling, oversampling, and SMOTE.

### Undersampling Strategy

Before running the software, we need to calculate the factor that will be used to set the record balancing directives. In undersampling, the goal is to reduce the size of the majority class to match the size of the minority class. The factor is calculated as follows:

$$Factor = \frac{Minority~Class~Size}{Majority~Class~Size} = \frac{True}{False} = \frac{492}{284,315} = 0.00173$$

Thus, in this case, we use a factor of 0.0018 to balance the dataset.

Follow the steps below to perform the undersampling strategy.

1.  Open SPSS Modeler.
2.  Create a new stream and name it `Credit_Fraud`.
3.  From the **Sources** group in the Node Pallet, double-click the **Statistics File** node to add it to the stream.
4.  Double-click the **Statistics File** node to open its settings window.
5.  Click the ellipsis button (three-dot button) and select the `CreditFraud.sav` file from your computer.
6.  From the **Field Ops** group, add a **Type** node to the stream and connect it to the data node. This node allows you to view and change the measurement scales and roles of fields.
7.  Double-click the **Type** node to open its settings window.
8.  Check the measurement scales of all fields. For the field **Class**, change the role to **Target**.
9.  From the **Records** group in the Node Pallet, add a **Balancing** node to the stream and connect it to the **Type** node. Rename it to **Undersampling**.
10.  Double-click the **Undersampling** node to open its settings window.
11.  Under the Settings tab, set **Condition**: **Class=0; Factor=0.002** (this setting reduces the number of negative cases to match the size of the positive cases, balancing the data).
     
     ![](images/ufig3_28.jpg)
12.  Click **Apply**, and then click **OK**.

You could use the **Data Audit** node to obtain the full statistical results. However, in this case, I used the **Distribution Chart** node to view the resampling results ([Table 3.5](#chapter3.xhtml#tbl3_5)). As you can see, the Balance node produces a balanced dataset with 50.62% fraud cases and 49.38% non-fraud cases, which is very close to the ideal 50% response, indicating a balanced dataset. The total number of records is now 972 cases. The output of this node is the newly balanced dataset, which can be used to train models. However, it's important to note that the dataset is now much smaller, which may result in information loss. This example demonstrates how to balance data using undersampling in SPSS Modeler.

### Oversampling Strategy

In oversampling, the goal is to increase the size of the minority class to match the size of the majority class. The factor is calculated as follows:

$$Factor = \frac{Majority~Class~Size}{Minority~Class~Size} = \frac{False}{True} = \frac{284315}{492} = 577.88$$

Accordingly, we use a factor of 580 to balance the dataset.

Follow the same steps (1–8) as with the undersampling approach. Then, continue with the following steps:

9.  From the **Records** group in the Node Pallet, add a second **Balancing** node to the stream and connect it to the Type node. Rename it to **Oversampling**.
10.  Double-click the **Oversampling** node to open its settings window.
11.  Under the Settings tab, set **Condition**: **Class=1; Factor=580** (this setting increases the number of positive cases to match the size of the negative cases, balancing the data).
     
     ![](images/ufig3_29.jpg)
12.  Click **Apply**, and then click **OK**.

[Table 3.6](#chapter3.xhtml#tbl3_6) shows the resampling results. As you can see, we now have a balanced dataset with 50.09% fraud cases and 49.91% non-fraud cases. The total number of records is now 569,675, which is significantly larger than the original sample size. The output of this node is the new balanced dataset, which can be used to train the models. However, because many duplicated positive cases have been added, the data may be prone to overfitting. Additionally, the increased dataset size may require more time and computing power during the modeling step.

| --- | --- | --- | --- | --- |

### SMOTE

As mentioned earlier, SMOTE is a more advanced resampling technique that uses the k-nearest neighbor method to select cases that are close in the feature space. By augmenting the minority class with synthetic samples, SMOTE can enhance model generalizability and reduce the risk of overfitting on the majority class.

Follow the same steps (1–8) as with the undersampling approach. Then, continue with the following steps.

9.  From the **Records** group in the Node Pallet, add a **SMOTE** node to the stream and connect it to the Type node. Rename it to **Oversampling**.
10.  Open the settings window of this node.
11.  Under the Settings tab, select **Class** for Target Field, set **Over Sample Ratio** to **Auto**, select **Regular** for **Algorithm Kind**, and set **K Neighbour** to **5** (for **Sample Rules**).
     
     ![](images/ufig3_30.jpg)
12.  Click **Apply**, and then click **OK**.

[Table 3.7](#chapter3.xhtml#tbl3_7) shows the SMOTE results, indicating a balanced dataset with 50% fraud cases and 50% non-fraud cases. The total number of records is now 568,630. Although we still end up with a much larger dataset, the data are more generalizable compared to the simple oversampling technique. Consequently, the models are less prone to overfitting.
