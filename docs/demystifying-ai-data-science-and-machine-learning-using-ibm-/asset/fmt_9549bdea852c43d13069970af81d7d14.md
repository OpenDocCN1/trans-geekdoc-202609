# Model Execution and Comparison

To run each of the random forest nodes separately and produce model nuggets, follow the same steps described in [Chapter 7](#chapter7.xhtml):

1.  **Run each node separately**: After configuring the four random forest models (Random Forest 1, Random Forest 2, Random Forest 3, and Random Forest 4) with the specified settings, execute each of the nodes separately. This will generate the corresponding model nuggets for each.
2.  **Connect model nuggets**: Since all models use the same input data with identical field names, you can use the approach described in [Chapter 7](#chapter7.xhtml) to connect all the model nuggets for comparison. Follow the same steps outlined in [Chapter 7](#chapter7.xhtml) under the section “How to run the analysis node with multiple models?”
3.  **Add filter node**: Add a filter node to the stream and connect it to the model nugget for Random Forest 4. Rename the model nuggets to the selected names (Random Forest 1, Random Forest 2, etc.) (see the detailed instructions below).
4.  **Add analysis node**: After renaming the model nuggets, use an Analysis node to compare the performance of the models. The Analysis node will compare the models based on key performance metrics.
5.  **Add evaluation graph node**: Use an Evaluation Graph node to produce ROC charts and Lift charts for all the models. This will provide a graphical representation of model performance.
6.  **Run the diagram**: Run the entire diagram to generate the comparison results for each random forest model.

By following these steps, you’ll have a diagram as below, including model comparison through the Analysis node and graphical evaluation with the ROC and Lift charts.

## Filter Node Configuration

To configure the **Filter node** settings to change the model names for each of the random forest models, follow these steps:

1.  **Open the filter node**: After connecting the model nuggets (Random Forest 1, Random Forest 2, Random Forest 3, and Random Forest 4) to the Filter node, open the settings of the Filter node.
2.  **Rename models**: Select the field to rename each model as follows:
    *   Rename the field `$R-Recommend the airline` to `Random Forest 1`.
    *   Rename the field `$R1-Recommend the airline` to `Random Forest 2`.
    *   Rename the field `$R2-Recommend the airline` to `Random Forest 3`.
    *   Rename the field `$R3-Recommend the airline` to `Random Forest 4`.
3.  **Apply the changes**: After setting the model names, click **Apply** to save the changes. The models should now appear with their new names in the stream.

This process ensures that each random forest model is clearly labeled in the final analysis, making it easier to differentiate between the results when comparing performance.

# Reliability of the Champion Model

To assess the reliability of the champion model, we compared the fit metrics across the testing, training, and validation samples. The results indicate a high degree of consistency with differences in the model performance metrics across the three samples being less than 10% (see [Table 14.4](#chapter14.xhtml#tbl14_4)). This consistency suggests that the model generalizes well to unseen data and is not overly tuned to the training sample.

**TABLE 14.4** Reliability Evaluation of the Champion Model—Random Forest 2 [Return to text.⏎](#chapter14.xhtml#b14tbl14_4)

| Metrics | Testing | Training | Validation |
| :--- | :---: | :---: | :---: |
| ACC | 79.30% | 82.96% | 79.82% |
| MR | 20.70% | 17.04% | 20.18% |
| Sensitivity or TPR | 0.935 | 0.963 | 0.936 |
| Specificity or TNR | 0.633 | 0.681 | 0.644 |
| F1 | 0.827 | 0.856 | 0.830 |
| Gini | 0.647 | 0.753 | 0.649 |
| AUC (ROC index) | 0.824 | 0.877 | 0.825 |

As the discrepancies between the sample metrics are minimal, we conclude that the model's reliability is acceptable, and there is no evidence of overfitting.

# Validity of the Champion Model

To assess the validity of the champion model, we evaluated the model fit metrics specifically for the validation sample, as presented in [Table 14.5](#chapter14.xhtml#tbl14_5). The prediction accuracy (ACC), at just below 80%, falls short of the generally acceptable threshold, suggesting room for improvement. However, the sensitivity (true positive prediction rate) is notably strong at 0.936, indicating the model's high ability to correctly identify positive cases.
