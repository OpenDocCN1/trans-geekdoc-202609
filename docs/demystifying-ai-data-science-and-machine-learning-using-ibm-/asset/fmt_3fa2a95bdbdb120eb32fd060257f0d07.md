## Imbalanced Dataset

![](images/ufig3_23.jpg)

As previously discussed, a balanced dataset is crucial for producing a valid and useful predictive model. An imbalanced dataset poses a high risk of prediction error. A balanced dataset typically has an imbalance ratio close to 0.5, meaning there is a similar number of events (positives) and non-events (negatives). [Figure 3.4](#chapter3.xhtml#fig3_4) illustrates the difference between a balanced dataset and an imbalanced dataset.

![FIGURE 3.4 Balanced vs. imbalanced datasets. Return to text.⏎](images/fig3_4.jpg)

FIGURE 3.4 Balanced vs. imbalanced datasets. [Return to text.⏎](#chapter3.xhtml#b3fig3_4)

In the balanced dataset, 50% of the data represents events, and 50% represents non-events, resulting in an imbalance ratio of 50%. Conversely, the imbalanced dataset consists of 5% events and 95% non-events, leading to an imbalance ratio of 5%. In the context of the imbalanced dataset, the events are referred to as the `minority class` (comprising only 5% of the data), while the non-events are referred to as the `majority class` (comprising 95% of the data).

Why does a highly imbalanced dataset become a problem in predictive modeling? Consider a dataset where 5% of the data represent events (positives) and 95% represent non-events (negatives). When we train our model with this dataset, the imbalance causes the algorithm to treat all cases as non-events because it aims to achieve the highest prediction accuracy. Remember, the algorithm cannot understand the meaning of the variables or data; it only processes the numbers and tries to fit them into a model. In this scenario, the model might achieve an overall prediction accuracy of 95%, which seems very high. However, upon closer inspection, we realize that the model fails to predict any events (positives), rendering it practically useless, especially if our goal is to predict those specific events.

Why does this happen? When we break down the predictions into positive and negative categories, we find that the true positive rate is 0%, while the false negative rate is 100%. This occurs because the algorithm classifies all cases as non-events (negatives) to maximize overall accuracy. As a result, the overall prediction accuracy can be misleading. To accurately evaluate model performance, we must also consider other metrics, such as specificity, sensitivity, F1-score, Gini coefficient, ROC curve, and Lift chart, which we will discuss in detail in [Chapter 6](#chapter6.xhtml). In this case, due to the highly imbalanced dataset with a very low imbalance ratio, the model is invalid.

Understanding why an imbalanced dataset poses a significant risk to modeling is crucial. It's also important to know how to address this issue because it is more common than you might think. For example, in projects like predicting credit fraud, aviation accidents, or cyberattacks, the events are typically very rare (a very low imbalance ratio), yet predicting these risks is critical. If our model fails to predict the target variable of interest, it becomes useless. Fortunately, there are several approaches to address this issue, which we will explore next.

### Using Multiple Model Fit Metrics

![](images/ufig3_24.jpg)

As demonstrated in the example above, training a good model with an imbalanced dataset is challenging. Often, a model may exhibit high overall prediction accuracy but still be invalid. Therefore, it is crucial not to rely solely on prediction accuracy or the misclassification rate when evaluating model performance, as these can be misleading. Note that the misclassification rate is simply one minus the prediction accuracy. To thoroughly evaluate models, it is important to use multiple model fit metrics. In addition to prediction accuracy and misclassification rate, common metrics include sensitivity, specificity, F1-score, Lift chart, ROC curve, and Gini coefficient. By employing multiple metrics, we can assess the model's performance from various perspectives, providing a comprehensive view of its effectiveness. We will explore these metrics in detail in [Chapter 6](#chapter6.xhtml).

### Data Partitioning and Model Validation

One primary concern in predictive modeling is overfitting, where a model is overly trained on the training data, leading to high prediction accuracy for that specific dataset but poor performance on new data. This lack of generalizability renders the model unusable. To mitigate this risk, in addition to using multiple model fit metrics, it is essential to partition the data into training and validation samples. The training sample is used to build the model, while the validation sample is used to test its performance. This approach helps detect any issues with the model by comparing results from the training and validation samples. Model validation is especially crucial when dealing with imbalanced datasets. We will discuss the details of data partitioning later in this chapter.

### Cost-Sensitive Learning

Another approach to addressing imbalanced datasets is cost-sensitive learning (CSL). Rather than comparing models based solely on prediction accuracy or misclassification rate, CSL considers the costs associated with misclassification. The goal is to develop a model that minimizes the total cost of misclassification. To achieve this, a payoff table, or decision matrix, is created for the target profile, outlining the costs of misclassification for each class.
