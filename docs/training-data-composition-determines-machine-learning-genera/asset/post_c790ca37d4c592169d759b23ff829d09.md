
PyTorch’s transformer building blocks, with the code available on GitHub. The used training loop was identical to that used for SN10. For the protein language model (PLM)-based SN10, we utilized the ESM2b protein language model<sup>74</sup> to generate 1,280-dimensional embeddings of the CDRH3s, as well as AntiBERTa2 (referred to as AntiBERTa2) to generate 1,024-dimensional embeddings<sup>75,76</sup>. Implementation-wise, the EmbedAIRR tool developed by our laboratory was utilized (https://github.com/csi-greifflab/embedairr). These embeddings were used as inputs to SN10, transforming its architecture into a feed-forward neural network with an input dimensionality of 1,280, 10 hidden units and 1 output unit – last 2 layers as in the original SN10 design. After confirming that the training protocol for SN10 did not cause overfitting for the PLM-based SN10 models, we applied the same training protocol as described above. Summarized results based on transformers and PLM-based SN10 are presented in Supplementary Tables 4 and 5.

## Information-theory-based calculations

JSD is a measure of dissimilarity between two probability distributions. It is derived from the Kullback–Leibler (KL) divergence and calculated using the following formulas:

JSD(P||N) = sqrt( [KL(P||M) + KL(N||M)] / 2 ),

KL(P||M) = sum_{x in X} P(x) log [ P(x) / M(x) ],

M = (P + N) / 2.

In our study, P and N represent the probability distributions for the positive and negative data sequences, respectively. As a measure of the total differences in marginal distributions for positive versus negative data sequences (that is, excluding differences in statistical interactions), we utilized PWMs that represent the probabilities of each amino acid occurring at specific positions within binder or non-binder sequences. Here, X refers to the set of PWM positions, and x corresponds to a single column of the PWM, representing a particular sequence position. The JSD in our setting is the sum of JSDs across each position. The JSD was computed using the scipy.spatial.distance package. PWMs were calculated using the bio.motifs package from Biopython<sup>77</sup>.

## Attribution analysis

To better understand the rules learned by SN10, we used interpretability techniques and applied them to testing set examples to gauge the importance of input features for each sequence; importance, in this case, implies contribution to prediction. We used the DeepLIFT<sup>48</sup> implementation from the Captum library v. 0.5.0 (ref. 78) as a fast method that approximates integrated gradients<sup>79</sup>. The computation requires baseline sequences, which were obtained by randomly reordering input sequences, a technique known in the literature as the shuffling approach<sup>80</sup>. Although using a zero input vector as a baseline is common and plausible in certain applications, in the case of sequences, it is problematic since a zero input vector does not represent any sequence, that is, there is no sequence that would be one-hot encoded as a zero input vector. The shuffling approach is based on random sequences and has been the preferred approach for biological sequences in recent literature<sup>80,81</sup>.

We generated ten shuffled versions for each CDRH3 sequence and ran DeepLIFT ten times per sequence, once for each of the shuffled baselines, respectively. The final attribution values were obtained by averaging the results from these ten runs. The attributions were estimated with respect to the predicted logits, not outputs. We used local attributions<sup>82</sup>, since we were interested in the impact to the prediction of each amino acid in each sequence. The implementation of this calculation in Captum<sup>78</sup> involved setting multiply_by_inputs to ‘True’. Attribution analysis was applied to synthetic and experimental data. However, since there was no binding energy data per amino acid in the experimental dataset, we could compare attributions with ground-truth per-residue energies only in the synthetic dataset. Attributions were computed across all replicates except for ‘vs1’, where due to the much larger number of datasets, we restricted the computation to once per dataset.

## Epitope-based analysis

For the epitope-based analysis, we generated new datasets and restricted, in each case, the positive datasets to consist only of sequences that bind to the major, that is, most frequent, epitope of an antigen. For this analysis, we selected the antigens that contain a sufficient number of epitope-specific sequences to allow for a training set size with the same size as in the antigen-based analysis (Ntrain = 30,000). However, the testing set size, due to the lower availability of sequences, had to be reduced with respect to antigen-based analysis (Ntest = 6,000). Due to the training size restriction, we had to limit the epitope-based analysis to three antigens: 1HOD, 1WEJ and 1OBL. In all our workflows and results, to distinguish between antigen- and epitope-based analyses, we depicted the epitope-based datasets with the same antigen ID, followed by ‘E1’ (indicating the most frequent epitope): 1HODE1, 1WEJE1 and 1OBLE1. To generate the training and testing sets, we filtered and adjusted the positive datasets by keeping the sequences that bind only to the major epitope and kept the same negative datasets as for the corresponding antigen-based analyses. After generating the corresponding datasets, we performed identical computations as for the antigen-based analyses that were shown in the main text.

## Absolut! binding energy calculations

We refer the reader to Absolut!<sup>77</sup> for a detailed explanation of the computation of binding energies. Briefly, in the three-dimensional lattice, only non-covalently bound neighbouring amino acids are considered to interact. The binding energies are then computed by summing the Miyazawa–Jernigan potential for each interacting pair of residues. By summing the Miyazawa–Jernigan potential for all interactions in which a CDRH3 residue is involved, the energy contribution of that residue to CDRH3–antigen binding energy is computed.

## Experimental antibody–antigen binding datasets

### Experimental dataset

We identified a publicly available experimental dataset<sup>49</sup>, generated for high-throughput antibody discovery using next-generation sequencing, ribosome display and affinity screening techniques, referred to throughout the text as the ‘Porebski dataset’ or ‘experimental dataset’. The technique generates binding kinetics data for an antibody library, which can be used to derive the measures of antibody affinity and, thus, to perform screening. Fluorescently labelled antigen accumulates around higher-affinity binders and images acquired at different antigen concentrations are processed to derive a per-sequence spatially integrated signal based on the fluorescence intensity, which is associated with affinity. The authors of the study performed the screening of two anti-HER2 antibody libraries, one library (HER2affmat) generated through the affinity maturation of G98A (a low-affinity anti-HER2 scFv), and another library (HER2mllib) with higher-affinity antibodies generated using a protein language model trained on the HER2affmat. To operate on higher-affinity antibodies, we used HER2mllib.
