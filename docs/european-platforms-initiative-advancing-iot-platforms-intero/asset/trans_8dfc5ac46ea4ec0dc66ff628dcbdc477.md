## 4.3.3. 互操作性方面

解决与这些模式相关的互操作性问题需要使用通用信息模型，例如通过语义网技术提供。这些通用信息模型需要允许对服务进行描述，以便其消费者（例如服务或应用程序）可以使用它们，即使它们来自不同的域或系统。

BIG IoT 核心模型定义了创建服务描述所需的核心词汇。服务描述依赖于 W3C Web of Things (WoT) 小组的工作，特别是事物描述 (TD) 格式 [21]，并且也将映射到 W3C SSN/SOSA。语义进一步通过领域无关和领域相关模型得到丰富。领域相关模型用于对服务描述的元数据、服务类别和输入/输出数据进行语义注释。BIG IoT 语义应用领域模型是使用 BIG IoT 语义核心模型、领域无关和/或领域模型创建的。该模型建立了核心模型与领域模型之间的关系。除了服务分类和数据建模之外，领域模型还定义了用于对服务领域相关特征进行语义注释的词汇。例如，类 “mobility:ParkingSpace” 可用于注释停车位及其特征，例如停车位 ID 或停车位位置。

为了对服务描述进行语义注释，例如定义输入、输出和服务类别的语义，需要一个定义良好的领域术语词汇表。该词汇表应被广泛共享和认可，以便所有物联网平台的消费者和提供者都可依赖。进一步，它应在开放的社区流程中演进，以允许生态系统利益相关者的积极参与。我们选择 schema.org 作为领域模型的基础，因为它为结构化数据提供了厂商中立、社区开发的词汇表。

生态系统的核心支柱是 Marketplace。在这里，提供者（例如物联网平台）通过上传服务描述（第 3.2 节）来注册其资源。为了便于提供者在生态系统中通过 BIG IoT API 提供其资源，可以利用 Provider Library（Lib）。它可用于建立到实际资源的网关，并实现 BIG IoT API 以及各种交互和工作流程（第 3.4 节）。该库对提供者进行 Marketplace 身份验证并注册其服务。它还提供 Web API 以授予对资源的访问权限。

除了提供对物联网平台访问的这些机制之外，Marketplace 还通过资源消费货币化的可能性丰富了生态系统。因此，消费者和提供者双方都会向 Marketplace 报告会计数据（例如获得/提供的资源记录数量）。这是计费和结算的基础，也是生态系统周围商业机会的基础。

上述描述的物联网生态系统是平台规模无关的。即，物联网平台可以在云级（例如服务器、数据中心）、雾级（例如网关、蜂窝通信基站）或设备级（例如 Raspberry PI、智能手机）运行。在最后一种情况下，物联网平台可以代表一个物联网“事物”。BIG IoT API 的使用独立于平台的此种规模。

## 4.3.4. 方法的独特性与具体特征

BIG IoT 方法包含以下目标：首先，它公开定义了所谓的 BIG IoT API，即一种通用、基于 Web 的应用程序编程接口（API），供智能对象平台采用。

其次，开放市场是 BIG IoT 生态系统的核心。一旦 BIG IoT API 提供了构建块，实现语法和语义互操作的物联网以及跨平台连接和交换得以实现，市场就为平台和服务生态系统奠定了基础。市场能够对基于 BIG IoT API 开发的应用程序和服务进行广告宣传、质量控制和货币化。可以为特定领域设置市场，例如由行业或能源领域的利益相关者，或由智慧城市为出行或建筑领域设置。

第三，BIG IoT 通过提供专用软件基础设施来支持应用程序和服务的发展。此外，它还提供发现和编排服务的功能。该功能基于语义服务描述，并将通过语义推理器实现自动服务链。这些功能促进了现有服务的重复使用。

第四，BIG IoT 项目参与当前标准化倡议以获取输入，今后我们将以项目中阐述的结果为基础为这些标准化活动做出贡献。

最后，与 BIG IoT API 和 Marketplace 相关的核心技术将在 Eclipse 下作为开源提供。BIG IoT 提案已获批准，并创建了 Eclipse Bridge.IoT 项目（https://projects.eclipse.org/proposals/eclipse-bridge.iot）

## 4.4. bloTope

bloTope 的主要目标是使公司能够轻松创建新的物联网系统，并利用先进的系统之系统（SoS）能力快速利用可用信息，用于连接的智能对象。这种 SoS 方法意味着图 3.2 中的全部五个互操作性模式都是通过开放标准实现的，这些标准可以以不同的方式组合和共同使用。bloTope 采用的 SoS 方法与大多数其他提出的物联网系统架构不同之处在于，关于通信系统的物理尺寸或计算能力，没有分层架构。通过这种 SoS 方法，图 3.2 中的模式 I-III 是默认实现的基本要求。任何实现必要物联网标准的系统都可以直接与任何实现并理解相同标准的其他系统通信，如图 4.3 所示。此功能实现了图 3.2 中的模式 IV）“平台规模独立性”。
