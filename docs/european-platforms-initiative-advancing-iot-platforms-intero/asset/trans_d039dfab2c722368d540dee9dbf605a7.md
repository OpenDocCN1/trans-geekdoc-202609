## 推进物联网平台互操作性

IoT-EPI 在提供物联网平台互操作性框架方面的努力已经提供了新的先进物联网平台互操作性机制和方法。在此背景下，已经识别出若干互操作性差距，需要进一步研究和未来研究工作。

物联网 (IoT) 环境相当复杂，具有支持各种通信协议的异构物理设备，同时它们可能连接到中间网关，然后连接到在不同平台上运行的虚拟表示（即服务）。因此，可以使用其不同的接口和表示以多种方式与单个 IoT 设备交互。

物联网平台需要在多个层面上实现互操作性，这意味着找到每一层的特征功能并定义可以映射到平台中使用的元协议（即在语法互操作性层面，特征功能是资源访问）。资源访问通过不同的协议实现，例如 O-MI、基于 REST 且基于 JavaScript 对象表示法 (JSON) 的 W3C Web of Things (WoT) 描述、类似 OData 等。虽然协议提供的功能基本上相同（例如通过某种标识符标识的资源 get/set/update/subscribe

到资源），资源发现功能必须跨协议解决。

需要对分层方法进行研究，以解决在 IoT 系统的所有层（设备、网络、中间件、应用程序、数据和语义）提供更紧密的互操作性问题，并重点保证此互操作性中的信任、隐私和安全方面。这种互操作性方法还提供涵盖服务质量 (QoS) 和设备管理、服务集成、外部系统服务、存储和虚拟化的模块。

关于语义互操作性，当前工作重点是在给定域中定义和标准化通用词汇表（例如 iot.schema.org）。有趣的方向也是朝着任何 IoT 对象的领域无关方面努力，遵循 WoT 方法（具有交互模式、链接和安全）。然而，模型的标准化并不总是可行的选择。因此，研究还应重点关注即使使用不同的信息模型也能实现语义互操作性的技术，如语义映射。

互操作性的分层方法允许利益相关者或平台运营商选择最佳的互操作性机制。对此类选项的管理提供层间协调，增强协作解决方案（例如网关和网络）并实现安全管理。

关于网关互操作性，基于软件定义网络 (SDN)/网络功能虚拟化 (NFV) 的可编程网络层的纳入对于合并物联网和 5G 并遵循现有架构至关重要。使用可编程网络有两个优点：移动性管理以及大规模物联网管理的 QoS 管理。

物联网互操作性通用框架最有前景的方面是找到资源访问、资源发现以及语义互操作性的通用方法。

需要进一步研究以解决系统-of-系统视图中的互操作性问题，在该视图中，所有设备、‘事物’和其他信息系统都应能够在互联网协议（TCP/IP 等）级别甚至在万维网 (WWW) 级别（HTTP、WebSockets 等）上互操作。这意味着低层协议（Zigbee、LoRa 等）在使用有限的物联网标准的一组‘包装器’和服务后面被抽象掉。

所有物联网应用都需要应对物联网中互操作性的复杂性和可持续性要求。为此，需要一个可持续互操作性框架，尤其针对物联网的特定特征和约束。

物联网中可持续互操作性的可能框架应能够解决以下方面：

- 物联网中互操作性的可扩展性管理：为了正确支持物联网中的互操作性，互操作性资源必须得到高效有效地管理。
- 物联网中互操作性测量的能力：为了正确管理和执行物联网中的互操作性，必须达到量化/定性互操作性本身的方法。
- 物联网的动态互操作性技术和方法：为了实现复杂物联网生态系统中持久的互操作性，‘事物’必须被允许进入并在无需大量修改的情况下动态互操作。

验证方面在互操作性中非常重要，对物联网而言更是如此。测试和验证断言互操作性方法、协议等能够应对物联网的特定性质和要求。我们需要提供高效准确的测试套件和相关的互操作性测试方法论，有助于彻底测试互连接的‘事物’、机器和智能对象所使用的底层协议，以及嵌入式服务和应用程序。在此观点中，我们必须考虑到对于大多数现有测试方法，物联网中的互联‘资源’本质上是分布式的。由于它们是分布式的，单一集中式测试系统处理所有这些组件和测试执行的通常经典方法不再
