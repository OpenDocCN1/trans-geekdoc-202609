
包括 GPS 在内的多个传感器，以及进一步的有线传感器连接选项。该项目还提供了代码，帮助开发者在名为 Node-Red 的基于 Web 的可视化应用开发环境中可视化并最终使用这些功能。这些工具的易用性使没有软件/硬件技能的人能够在快速原型环境中组装所需的解决方案，该环境也可用于测试目的和大规模生产之前。

在软件方面，AGILE 项目的目标是通过 Eclipse 基金会向物联网软件开发者/创客社区发布开源代码，帮助他们根据设备或网关将要加入的平台环境轻松配置设备或网关。该代码在设计时考虑了网关平台互操作性，最小化依赖关系，从而不仅支持项目内部开发的两种网关硬件平台变体，还支持市场上其他平台。为此，使用 Docker 容器化（https://www.docker.com/）将软件组件彼此分离，并与底层 HW/OS 分离。事实上，Docker 是软件容器的领先容器化技术，软件容器是包含软件二进制可执行文件、运行时以及所有相关依赖项的包。

为了进一步促进硬件支持，该项目还为基于 Linux Yocto 的 ResinOS 操作系统的开发做出贡献，该系统专门针对可适应大量物联网网关平台的基于 Docker 的多容器部署进行了调优。

因此，通过创建物联网应用生态系统可以更轻松地促进平台互操作性，该生态系统可供用户和开发者在利用 Docker 容器生态系统等现有计划的基础上共享。用户能够通过 Docker 应用市场以安全的方式发现、安装/管理并共享为互操作性目的而开发的组件。

## 4.3. BIG IoT

BIG IoT 项目的目标是通过利用智能对象平台的能力，通过建立开放的 BIG IoT API 和 BIG IoT 市场实现句法和语义互操作性，从而消除物联网服务和应用提供商的技术市场准入壁垒，以实现跨标准、跨平台和跨领域的物联网服务和应用。因此，该项目正在为物联网生态系统定义一个全面的架构 [17]，包括坚实的安全设计 [18] 和服务组合方法 [19]，同时提供维持生态系统的商业模式 [20]。

同时得到提供方和消费者以及市场（资源在此交易）的支持。这些接口包括以下基本交互：

这些接口是实现互操作性和实现模式 I – V（第 4.1.1 节）的基础。因此，实现模式 II、III 和 V 的关键挑战例如：

- 提供方和消费者来自不同的应用领域（II）；
- 物联网提供托管在不同的物联网平台上，例如位于不同区域（III）；
- 物联网提供位于不同的提供系统上，例如物联网平台或服务（V）。

该图中同样重要的是 BIG IoT 消费者和提供方库的概念。例如，提供方库实现了 Register 接口（M2）用于将提供的描述上传到市场，并提供 Access 接口（A1）以向消费者提供信息。这些库的好处在于，平台、服务和应用的开发者在市场中宣传其提供或使用市场发现和访问它们时得到支持。他们只需实现一次提供方（P1）或消费者（P2）接口，并且可以轻松更新库以便在底层消息格式和交互的细节发生变化时进一步符合要求。对于通过 Register 接口（M2）进行的注册过程，使用了一种称为提供描述的语义描述，并依赖于资源描述框架（RDF）。

### 4.3.2. 物联网平台互操作性方法

BIG IoT 架构的核心目标是通过 BIG IoT 生态系统促进物联网平台的集成。目标包括基础设施以及设备级平台。从架构角度来看，特别是考虑到 BIG IoT API 的实现和与市场的集成，我们已确定以下类型的物联网平台：

Type 1: 假设为“始终在线”且可随时通过互联网被应用程序或服务访问的服务器基础设施或基于云的物联网平台。

Type 2: 设备级物联网平台，托管在相对于通信、计算和内存资源不受约束⁴的设备上，假设为“始终在线”，其中连接和通信资源被假设按“固定费率”计划收费。

Type 3: 设备级物联网平台，托管在相对于通信、计算和内存资源不受约束的设备上，但“并非始终在线”。

Type 4: 设备级物联网平台，托管在相对于通信、计算和内存资源不受约束的设备上，但通过“按使用付费”计划连接到互联网，类型 4 设备通常也是类型 3。

Type 5: 设备级物联网平台，托管在相对于通信、计算和/或内存资源受约束⁵的设备上。

4. 在此上下文中，不受约束意味着设备能够实现/使用 BIG IoT API，该 API 将基于典型的 Web/互联网技术（例如 HTTP、WebSockets）。不受约束设备的示例是 Raspberry Pi。此外，能够运行 Linux 并支持典型 Web/互联网技术的其他设备在此上下文中也被视为不受约束。基于微控制器的传感器不被视为不受约束。

5. 在此上下文中，受约束是指相对于 BIG IoT API 的实现，该 API 将基于典型的 Web/互联网技术（例如 HTTP、WebSockets）。受约束设备的示例是使用微控制器的低成本传感器。Raspberry Pi 不被视为受约束设备。
