## 4.7. TagItSmart

TagItSmart 架构组件的全面视图在图 4.12 中呈现。TagItSmart 设计为一组松耦合的组件，可在不同环境（物联网平台）中以及跨环境集成。为此，提供特定 TagItSmart 功能（如智能标签编码、解码等）的组件自带自己的 API，而更通用的物联网功能则从所使用的底层物联网平台中复用。这种方法使在不同环境中使用 TagItSmart 功能变得相当直接，并降低了开发人员的学习曲线。

从功能角度来看，***用户/开发者层*** 提供了前端功能，使能够访问不同的 TagItSmart 组件。此外，在该层，TagItSmart SDK 使智能标签解码功能能够集成到第三方（智能手机）应用程序中。

### 图 4.12. TagItSmart 平台功能架构

在 **_服务层_** 中，我们可以找到以下功能块：

- *安全* 组件处理诸如对其他组件的身份验证、授权和访问控制之类的方面。安全性在多个层面得到解决：智能标签的安全性通过 Ciphertext Policy Attribute Based Encryption（CP-ABE）得到保证，通过在加密标签中嵌入策略来强制执行与不同用户相关联的访问控制策略；Web 平台和 API 的安全性通过基于凭据的身份管理和身份验证机制得到保证；可信性和数据完整性则依赖于分布式账本技术。

- *服务执行* 组件包括那些能够执行平台中注册的服务以及用于触发工作流动态创建的服务模板。整体流程允许平台用户发出服务请求，然后由平台处理，解决需要“粘合”在一起以支持整体服务请求的子服务，并随后执行。为了实现这一点，一系列存储库被利用，首先公开平台中可用的服务，以便它们可以被发现、配置、触发和适当重用。此外，还涉及一个拦截服务请求并能够将其分解为所需服务的组件（服务管理器）。服务模板指导了识别服务请求在子服务以及用户信息方面的需求的过程。后者既用于确保只有授权用户才能访问平台并发出服务请求以及通过平台获得服务（例如，FC 扫描仪用户能够使用托管在 TagItSmart 平台中的解码或流处理组件），也用于根据所有权、位置和其他可用性标准识别在服务请求执行期间需要涉及的适当资源。最终，服务的运行时执行由工作流执行器承担，它充当组件之间的“中间人”，适当地在组件之间传递信息并处理错误，以便其他组件可以完全专注于其功能操作。

以上述架构为起点，这里描述了如何在实践中实现 TagItSmart 功能：

**使用 TagItSmart 的物联网平台完整实现**：此场景从头构建架构中定义的 TagItSmart 的所有组件，功能集成在同一代码库中。支持平台所需的基础设施由实施提供方提供。

**_托管在第三方物联网平台中：_** 此场景将 TagItSmart 功能集成到已有的物联网平台中。组件实现可能需要一些调整以符合现有平台，但它们应通过遵循相应 API 实现互操作性。基础设施需求由第三方物联网平台提供方设置。

**_共享并外部托管：_** 此场景将 TagItSmart 视为一组独立的服务集合，公开开放 API，可同时从不同平台访问。部署和基础设施需求独立于物联网平台处理。
