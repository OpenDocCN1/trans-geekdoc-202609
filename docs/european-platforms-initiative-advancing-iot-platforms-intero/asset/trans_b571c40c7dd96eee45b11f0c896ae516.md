
适用。所测试组件的分布式特性要求转向分布式测试方法。

物联网研究社区必须就用于评估物联网平台摄取性能的数据集达成一致，并就用于评估物联网平台消化性能的实时查询集达成一致。测试/实验序列必须明确、透明且基于共识，以确保公平和无偏的基准测试过程。

互操作性解决方案的实施应以开源方法为目标，采用不同的商业模式。这些解决方案需要在项目结束后仍然保持可持续性。进一步的研究应聚焦于平台之间 API 均质化和联合认证的关键方面。这应允许灵活的跨域/跨平台业务流程创建。

利用物联网（平台）技术处理自动化复杂系统是未来的关键挑战。在此背景下，复杂系统是指由丰富的感知能力（例如雷达、视觉）和先进的执行机构（例如控制机械臂）大量组成的系统。这些复杂系统的自动化需要智能传感器数据处理和推理，以有意义地控制执行机构。物联网平台技术通过成为复杂系统内部和系统之间以及自动化之间的互操作接口，有潜力显著促进和增强系统的创建。传感器、执行器和‘事物’描述格式、物联网社区定义的通信协议和 API 需要使用一种通用语言来支持此类智能处理和推理。

物联网平台技术可提供巨大开发推动的此类自动化复杂系统的例子，从联网机器人和机器人生态系统，到与物流链集成的自动化生产线，再到自动化车辆（船舶、飞机、火车、卡车、汽车）和车队。

借助物联网平台技术，将组件和系统连接到更复杂的系统成为可能。因此，此类复杂系统内部和系统之间的智能和自动化协作将成为核心挑战。通过从现有组件池（通过存储库填充）自动创建物联网组件组合将增加经济影响，因为在多个组合中重复使用组件会增加产生的收入。与其集中控制组合，它将通过智能编排以分散方式组织。

未来，甚至可能即时创建复杂服务，例如当汽车到达新城市并需要城市物联网生态系统的特定服务时。如何高效实现此类基于上下文的服务组合是需要进一步研究的核心理论课题之一。

物联网背景下语义互操作性的当前工作侧重于‘通过标准化的互操作性’，试图定义可被多个平台使用的标准化词汇，从而建立语义互操作性。然而，总会有标准化不被期望甚至不可能的场景。为了在这些情况下提供语义互操作性，需要其他语义互操作性方法。最突出且最有前景的是基于平台使用的不同信息模型之间语义映射的数据和查询转换。然而，由于语义映射技术并非平凡的工具，需要能够显著简化该过程的工具。

跨所有平台的‘事物’的唯一身份仍然是一个未解决的问题。例如，一辆汽车可以通过序列号或车辆识别号（VIN）、车牌号、保险号码或其他标识符来识别。最合适的标识符可能取决于使用上下文，因此该特性应成为任何物联网信息系统的要求。

尽管有多种方式为每个单独的‘事物’和每个单独的项目分配身份，但对齐这些不同的身份方法并使其能够映射以便在不同环境中轻松使用同一‘事物’的工作必须继续。

关于通用物联网互操作性框架的研究工作需要继续进行，并需要对不同的互操作性级别及其协议进行详细而广泛的分析，同时配合深入的科学研究和标准化工作。

关于互操作性的路线图与物联网生态系统的创建相关，主要与现有解决方案（即 IoT-EPI）周围的开发人员相关。互操作性解决方案的功能必须扩展，包括用于控制执行机构的 self-* 机制，尤其是在未来的物联网自主系统中。
