在 bloTope 中，“物联网标准”指代标准格局“腰部”周围的一组有限的适当标准，如图 4.4 所示。如果物联网有望成为与万维网（WWW）类似的成功案例，它将需要一个类似的基础，拥有简单、定义明确、通用且强大的标准集。WWW 最初以 HTTP 和 HTML 作为核心标准起步。随着时间的推移，其他标准引入了补充功能，增强了 WWW 应用的能力，但基本构建块和原则仍然相同。

bloTope 充分利用了由 The Open Group 开发并正式发布的消息标准，尤其是开放消息接口（O-MI）和开放数据格式（O-DF）标准¹³

[22] [23]。这些标准源于过去的欧盟 FP6-FP7 项目，其中真实的工业应用需要对涉及重型和个人车辆、家用设备等多个领域的产品实例级信息进行收集和管理。基于这些实际应用的需求，并且没有现有的标准可以在不进行大量修改或扩展的情况下满足这些要求，合作伙伴联合体开始制定新的物联网互操作性标准。O-MI 主要在图 2.1 的栈中提供技术互操作性，提供实现通用物联网系统所需的必要功能，而这些功能是 HTTP 等协议所不提供的。O-MI 可用于实现 RESTful 物联网信息系统，也可使用除 HTTP 之外的其他底层协议，如图 4.5 所示。

O-DF 为物联网中的对象提供通用内容描述模型，可通过更具体的词汇表（例如使用领域特定本体词汇表）进行扩展。O-DF 目前使用 XML 作为底层语法，但它提供了一组最小化的通用语义用于标注物联网（及其他）数据。由于 O-DF 能够以平台无关、领域无关和规模无关的方式引用外部分类法、本体和词汇表，因此可以认为它在图 4.5 中架起了第 2 级（语法互操作性）和第 3 级（语义互操作性）之间的桥梁。

bloTope 架构深受微服务架构（MSA）思想的影响，其中不同的“小型”标准可以根据应用需求以最佳方式联合使用。MSA 是在图 3.2 中实现模式 V)“更高层服务外观”的通用方法。对 MSA 的支持是 O-MI 和 O-DF 的基本设计原则，意味着任何规模的服务都可以发布和消费，无论是请求当前传感器值的简单请求，还是请求汽车当前位置附近可用停车位的请求。

这种 MSA 方法在系统灵活性和精益软件原则方面提供了多项优势，因为新的符合物联网标准服务可以由更小、现有的服务组成。它还在当前竞争激烈的物联网标准化格局中提供了风险管理优势，因为不同的符合标准的软件组件和包装器可以被调整以支持新的或“获胜”的标准，而不会影响整个系统架构。
