
# 16.3.2 Elementwise flows

Since linear flows are not sufficiently expressive, we must turn to nonlinear flows. The simplest of these are elementwise flows, which apply a pointwise nonlinear function `f[•, ϕ]` with parameters `ϕ` to each element of the input so that:

The function `f[•, ϕ]` could be a fixed invertible nonlinearity like the leaky ReLU (figure 3.13), in which case there are no parameters, or it may be any parameterized invertible one-to-one mapping. A simple example is a piecewise linear function with `K` regions ([figure 16.5](#c016.xhtml#c16-fig-0005)) which maps `[0, 1]` to `[0, 1]` as:

![c16-fig-5014.jpg](images/c16-fig-5014.jpg)

 (16.12)

where the parameters `ϕ[1], ϕ[2], …, ϕ[K]` are positive and sum to `K`, and `b = ⌊K[h]⌋` is the index of the bin that contains `h`. The first term is the sum of all the preceding bins, and the second term represents the proportion of the way through the current bin that `h` lies. This function is easy to invert, and its gradient can be calculated almost everywhere. There are many similar schemes for creating smooth functions, often using splines with parameters that ensure the function is monotonic and hence invertible.

Elementwise flows are nonlinear but don't mix input dimensions, so they can't create correlations between variables. When alternated with linear flows (which do mix dimensions), more complex transformations can be modeled. However, in practice, elementwise flows are used as components of more complex layers like *coupling flows*.

# 16.3.3 Coupling flows

[Figure 16.6](#c016.xhtml#c16-fig-0006a) Coupling flows. a) The input (orange vector) is divided into `h[1]` and `h[2]`. The first part `h'[1] = h[1]` of the output (cyan vector) is a copy of `h[1]`. The output `h'[2]` is created by applying an invertible transformation `g[, ϕ]` to `h[2]`, where the parameters `ϕ` are themselves a (not necessarily invertible) function of `h[1]`. b) In the inverse mapping, `h[1] = h'[1]`. This allows us to calculate the parameters `ϕ[h[1]]` and then apply the inverse `g⁻¹[h'[2], ϕ]` to retrieve `h[2]`.

If the function `g[•, ϕ]` is an elementwise flow, the Jacobian will be diagonal with the identity matrix in the top-left quadrant and the derivatives of the elementwise transformation in the bottom right. Its determinant is the product of these diagonal values.

The inverse and Jacobian can be computed efficiently, but this approach only transforms the second half of the parameters in a way that depends on the first half. To make a more general transformation, the elements of `h` are randomly shuffled using permutation matrices between layers, so every variable is ultimately transformed by every other. In practice, these permutation matrices are difficult to learn. Hence, they are initialized randomly and then frozen. For structured data like images, the channels are divided into two halves `h[1]` and `h[2]` and permuted between layers using 1×1 convolutions.
