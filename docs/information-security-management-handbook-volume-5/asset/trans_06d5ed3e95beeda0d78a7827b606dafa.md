

管理和监控变更常常被视为一项价值不大的文书工作。事实并非如此。通过系统变更，可以获取大量可操作的情报，这些情报对管理人员和安全人员都有益处。

# 应对挑战

变更是不可避免的。现代信息技术（IT）是人造系统中持续变动的极端案例。新技术似乎每天都在涌现。用户不断表现出对新应用和改进应用的无尽需求。同样，新漏洞也以快速的速度被发现。攻击者继续寻找巧妙的方法，让 IT 管理人员保持偏执和忙碌。新技术发布的速度和新威胁的出现继续加速。因此，系统变更是不可避免的，需要适当的规划和管理来实现可接受的稳定性水平。

系统可以由管理人员对其组件和设置的影响来定义。系统组件包括构成系统基线的硬件和软件项目。基线是系统的组成部分。单个系统组件构成其基本功能。然而，这种功能必须以有意义的方式组合在一起。将这些部分随意堆叠在一起不会证明有效。系统组件必须以特定的方式组合，以实现所需的功能。硬件和软件的顺序和设置定义了系统的配置。总体 IT 系统管理策略是根据特定配置将部分组合成一个整体，以实现所需的功能。如果 IT 系统设计和维护如此简单就好了。

新解决方案的不断扩张与令人畏惧的缺陷发现相结合，保证了终身的管理活动。市场上不断涌现新工具。其中一些工具使用最近开发的技术和协议，旨在改善用户体验和/或效率。偶尔，新工具会取供应商因技术或经济原因不再支持的旧工具。与大多数软件工具一样，只是时间问题，光鲜的外表会褪色，缺陷会显现出来。随着时间的推移，漏洞会出现。这些发现有时会伴随一阵忙碌的工作来修复问题。无论如何，IT 管理人员都陷入了系统变更的无休止循环中。

变更活动最好通过一个流程来加以约束，以便以最不痛苦的方式发生。没有人欣赏系统可用性的中断。计划不周或协调不力的中断会在最糟糕的时间给最重要的用户带来不便。因此，IT 管理人员以有组织的方式将变更发布到系统中，以最大限度地减少中断，并希望消除不愉快的意外。

管理系统变更主要被视为操作活动。安全专业人员通常在需要评估风险或进行安全测试时才参与系统变更。然而，这种有限的观点低估了配置、变更和发布管理（`CCRM`）作为安全管理活动的重要性。`CCRM` 是一种核心防御措施，可以有效地用于应对内部和外部威胁。

# 安全作为推动者

理想情况下，安全是业务推动者。安全控制应使组织能够在敌对环境中运行，对系统用户几乎或完全不造成不便。组织的目标和宗旨不应受到所采用控制的影响。不幸的是，我们往往不得不选择不便的权衡，以在安全性方面达到正确的平衡。有时所使用的工具会影响性能或难以使用。这可能会让用户感到沮丧，并阻碍组织目标的实现。在这些情况下，安全通常被视为障碍。当工具阻碍用户时，安全作为推动者的崇高目标就很难实现。

一些计算机专业人士可能不认同安全作为推动者的理念。他们会说，安全的问题在于它施加了限制和约束。这些控制似乎与系统管理人员的目标相悖，他们希望系统对用户尽可能灵活。僵化的流程往往意味着大量无用的文书工作，并将生产力拖慢到蜗牛的速度。

考虑一个中等规模的系统，包括 200 台工作站、10 台文件服务器和 5 台由 3 个数据库支持的自主开发的基于 Web 的应用程序服务器。这样的系统会有组织内部和外部客户作为用户。企业内各个部门可能存在数十个独特的应用程序。一些办公室可能还需要专用硬件。现在想象一下，如果整个系统被自然灾害摧毁。服务器备份在大多数组织中是常见做法，但工作站镜像并不总是更新。然而，仅靠备份不足以高效地重建如此规模的系统。如果没有关于所有独特组件及其如何组合在一起的充分系统文档，恢复将是一项艰巨的任务。拥有全面 `CCRM` 流程的组织可能能够毫不费力地从这个问题中恢复过来。

# 现有方法

存在许多用于实施 `CCRM` 的流程。其中一些已经存在多年，而另一些才刚刚出现。值得安全专业人员进一步研究的知名组织和方法包括：

![](OEBPS/images/box.jpg) `Information Technology Infrastructure Library (ITIL)`：这是由英国政府开发的一套 IT 管理最佳实践。截至撰写本文时，ITIL v3 是该库的最新版本，包含五卷。ITIL v2 的服务支持中表达的一些观点已融入本章。

![](OEBPS/images/box.jpg) `Capability Maturity Model Integration (CMMI)` 是一些组织用于改进其软件开发活动的模型。成熟度等级从 1（最低）到 5（最高）。`CMMI` 主要关注展示改进，而不是指定特定流程。`CMMI` 由卡内基梅隆大学软件工程学院维护。

![](OEBPS/images/box.jpg) `National Institute of Standards and Technology (NIST)`：`NIST` 不断制定指导方针，以协助美国联邦政府满足安全要求。最近起草的特别出版物 `800-128`，信息系统安全配置管理指南，提供了一个精简的 `CCRM` 流程，旨在利用安全内容自动化协议（`SCAP`）。目标是通过安全监控自动化实现安全运营效率和改进。

标准组织也制定了与 `CCRM` 相关的指导方针。国际标准化组织（`ISO`）制定了 `ISO 10007 配置管理`，而电气和电子工程师学会（`IEEE`）发布了 `1042-1987 软件配置管理指南`。
