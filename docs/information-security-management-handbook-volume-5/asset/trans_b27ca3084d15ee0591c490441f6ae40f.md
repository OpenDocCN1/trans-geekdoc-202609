

此外，如果访问评审由技术人员执行，他们不了解也不熟悉访问的业务要求。同样，业务人员可能没有足够的知识来充分理解所识别访问的范围。因此，简化流程有利于组织。

使用集中式解决方案通常并非常态，因为组织依赖于自主访问控制等非结构化解决方案来确定用户能做什么。访问问题并非新鲜事，可以追溯到最早的多用户计算机的发展，这导致了 `ACF2` 和资源访问控制设施（`RACF`）等访问控制系统的出现。

如果组织要实施集中式解决方案，应该从哪里开始？访问管理和始终需要的访问评审的重要方面有哪些，是他们必须考虑的？在回答这个问题之前，让我们先看看 [图 19.1](#9781466508507_epub_c19_r1.htm#fig_19.1) 中所示的关系。

在 [图 19.2](#9781466508507_epub_c19_r1.htm#fig_19.2) 所示的示例中，用户与他们感兴趣的特定资源进行交互，但该资源随后会查询集中式访问管理系统，以确定用户是否已通过身份验证并获得访问该资源的授权。

这听起来很简单，在某些环境中确实如此，而在其他环境中则极其困难和复杂。如果环境是异构的，包括 Microsoft Windows、大型机和 UNIX，那么寻找像 [图 19.2](#9781466508507_epub_c19_r1.htm#fig_19.2) 这样的解决方案将需要定制编程来提供必要的服务。不过，每个系统本身都提供差异和优势。

以大型机计算平台为例。由于平台的性质，用户使用诸如 `RACF` 之类的技术被分配特权和角色。这并非新鲜事，因为 `RACF` 和类似的系统自 20 世纪 70 年代中期以来就已存在。

大型机平台之所以成功，是因为 `RACF` 在大型机平台及其运行的应用程序中以集成的方式运行。然而，在 UNIX 和 Microsoft Windows 等分布式系统上实现这一点要困难得多。当然，环境越同构，就越容易。困难归困难，问题是如何从旧概念中汲取经验，以建立新的范式和机会。

如果我们借鉴 `RACF` 的经验，用户拥有包含特权和角色的配置文件。集中式系统中的每个用户都有一个包含每个角色和特权的配置文件。由于信息的性质及其增长速度，强烈建议使用 eXtensible Markup Language (`XML`) 等数据表示格式，因为可以轻松地将新特权添加到配置文件中，而无需更改数据库结构。一种可能的框架可以如 [图 19.3](#9781466508507_epub_c19_r1.htm#fig_19.3) 所示来表达。

使用基于 XML 的表示的主要原因是纯文本表示以及能够使用类似英语的结构，这使其易于阅读。

不幸的是，构建或购买集中式目录方法并不难，难的是让各种基础设施使用它。例如，Microsoft Windows 想要查询 Active Directory 林以获取其身份验证和授权信息，Mac OS 使用 Open Directory，而 UNIX 对符合轻量级目录访问协议（`LDAP`）的目录感到十分满意。

组织可以选择构建自己的身份验证和授权环境，也可以利用 eTrust 和 Siteminder 等商业产品。这两款产品都提供集中式身份验证和授权，尽管用途不同。

如果用户配置文件和访问控制并非新鲜事，那么组织为什么在执行 CoBIT 规定的定期访问评审时会遇到困难呢？问题的一部分在于人力。访问评审实际上是一种侦测控制，意味着它们会发现问题的存在，因为有人发现了它。

侦测控制本身并不坏，但将访问评审纳入持续监控框架，由系统完成常规工作，可以减少围绕该任务的人工劳动，并可用于向审计人员证明问题已被识别并迅速得到补救。

侦测控制在预防系统未能捕获错误时发现错误。因此，侦测控制的设计和实施成本更高，因为它们不仅评估预防控制的有效性，还必须用于识别可能存在错误的数据，这些数据无法通过预防有效控制。侦测控制包括评审和比较、审计、银行及其他账户对账、库存清点、密码、生物识别、输入编辑检查、校验和和消息摘要。

预防控制建立机制以防止不良活动的发生。预防控制被认为是预防-侦测-纠正循环中最具成本效益的方法。当预防控制嵌入系统时，控制可防止错误并最大限度地减少侦测和纠正技术的使用。预防控制包括值得信赖的受过培训的人员、职责分离、适当授权、充分文档、适当的记录保存和物理控制。

**图 19.4 访问评审流程。**

执行该流程假设两件非常重要的事情。首先，来自 HR 系统的“黄金”用户或员工来源可用。如果没有，那么存在一个更根本的问题，需要采取行动。假设有，第二是系统（应用程序、数据库等）列表以及从该系统获取用户列表以进行比较的流程。在许多情况下，此步骤将需要 IT 人员进行定制。

一旦系统提供了用户列表，就变成了简单地确定用户是否在 HR 文件中且是活跃员工。如果他们不在 HR 文件中或不再是活跃员工，则移除其访问权限。
