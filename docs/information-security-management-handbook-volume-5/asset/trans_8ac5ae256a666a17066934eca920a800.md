# Conclusion

使用安全外包时需牢记的几个关键事项如下：

![](OEBPS/images/box.jpg) 了解企业正在外包的内容。

![](OEBPS/images/box.jpg) 评估内部控制和政策，并决定需要将哪个级别的风险管理扩展到外包流程。

![](OEBPS/images/box.jpg) 了解风险和依赖关系，并了解法规和合规控制。

![](OEBPS/images/box.jpg) 评估安全外包商的风险管理水平。

![](OEBPS/images/box.jpg) 评估安全外包商员工的经验水平。

![](OEBPS/images/box.jpg) 确保数据得到适当保护。

![](OEBPS/images/box.jpg) 制定清晰明确的服务等级协议（SLA），并对其进行法律审查。

![](OEBPS/images/box.jpg) 保留“审计权”（物理/逻辑）条款、升级路径和变更流程，并量化数据丢失或服务停机的补偿。

如果企业聘用外包供应商是为了免除监管合规责任，或希望将混乱的环境交给安全外包商来修复，那么使用安全外包并非良好理由。企业必须记住，他们仍需对保护重要资产负责。如果企业环境混乱或不安全，安全外包商没有动力去修复，反而可能使情况更糟。企业应仔细对安全外包商进行尽职调查。企业需要评估其安全架构是否可以在孤岛环境中运行，而非像城堡式安全架构那样依赖坚固的护城河。当且仅当决定选择安全外包商时，企业需要定义方式，让安全外包商对其活动负责。

# Chris Hare

安全从业者面临的一大挑战是需要持续进行访问审查和审计。持续关注的原因在于审计师检查访问管理的频率。从系统到应用程序，审计师喜欢访问管理，因为它构成了限制授权连接到系统的基本控制，并且是 CoBIT 中确定的关键控制。

CoBIT，[^(\*)](#9781466508507_epub_c19_r1.htm#ch19-ftn1) 或信息技术共同目标，是信息系统审计和控制协会（ISACA）的产品，也是识别和分类 IT 控制的公认标准。与访问审查特别相关的 CoBIT 控制是 DS5，确保系统安全。该控制的目标是识别访问控制故障，例如不当访问、休眠账户或已终止用户。

什么是访问审查？访问审查必须是一个可重复的过程，并按照 CoBIT 的要求定期进行。该过程必须确定接受审查的用户是否应拥有该访问权限。当今许多组织面临的问题是缺乏集中式解决方案。

目录技术的进步为将访问信息和用户配置文件存储在目录中创造了机会。话虽如此，访问权限通常由系统或应用程序管理员保留。这使得进行访问审查变得困难，因为存在大量的权限和角色，而且很难向审计师证明访问审查正在进行。
