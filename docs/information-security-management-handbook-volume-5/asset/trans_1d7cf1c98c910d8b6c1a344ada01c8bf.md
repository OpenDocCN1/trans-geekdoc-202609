

通常，虚拟机（VM）的备份方式主要有两种。第一种是在 VM 内部进行备份，该方式使用 VM 的网络连接。第二种是通过外部方式进行备份，即使用 `COS`（VMware Consolidated Backup）。无论哪种情况，遍历网络的备份数据都应使用强加密进行加密，并且备份服务器应通过使用强身份验证和文件访问的访问控制列表（`ACL`）来充分保障安全。

# 数据安全

虚拟化环境中的数据需要以与数据中心相同的方式进行保护。尽管每个 VM 都是独立且不同的，但服务 `COS` 是 VM Server 的一部分，并且可以访问关键数据。正确配置 `ACL` 并应用最小权限原则，都将最大限度地降低数据安全漏洞的可能性。

# 补丁和更新

确保最近的补丁和更新得到及时测试，如果合适则安装，是保障虚拟化（以及传统）环境安全的重要组成部分。此外，还需要确保离线 VM 和“VM 设备”镜像的补丁和签名更新保持最新。这包括对 VM 设备进行补丁管理和安全配置管理，在这些设备中，底层操作系统和配置不可访问。防止篡改也是必不可少的。

# 审计

最后，确保在 VM 服务器服务控制台上启用并持续运行足够的审计（以及要求定期和系统地检查审计日志输出的程序）非常重要。网络监控也是必要的。因此，最终目标应该是在提供所需的预防性保护的同时，尽可能减少对系统应用程序运行的影响，以允许对操作系统进行审计和监控。

# 其他控制措施

此外，认识到最终会出现更多种类的攻击（其中一些可能会成功）在虚拟化环境中至关重要；必须进行必要的调整，并且必须不断考虑必要的额外安全控制措施，如果在成本与效益方面合理，则应实施这些措施，以最大限度地降低这些环境中成功攻击的可能性。候选控制措施包括（但不限于）网络防火墙、应用程序防火墙、强身份验证、防病毒/反间谍工具、通过容错或其他机制提供的拒绝服务（`DoS`）保护、取证工具、远程日志记录、定期漏洞扫描和补丁管理。

# 结论

信息安全管理人员以及其他信息安全专业人员需要从信息安全、信息技术和业务角度彻底理解虚拟化及其优缺点。他们还需要跟上虚拟化的变化。随着虚拟化日益普及，有一点是确定的——虚拟化和计算将在未来继续融合。不幸的是，虚拟化也可能为攻击者和恶意代码提供不成比例地增加的目标。因此，信息安全管理人员在管理与虚拟化相关的安全风险时，应尽可能采取主动措施。
