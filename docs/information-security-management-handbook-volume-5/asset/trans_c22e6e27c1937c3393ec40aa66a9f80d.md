# 安全部署

如前所述，SaaS 解决方案可以由 SaaS 供应商托管，也可以部署在公共云上。在自托管部署中，SaaS 供应商需要确保采取足够的防护措施来应对网络渗透和 DoS 攻击。亚马逊和谷歌等专用云提供商通过提供有助于确保数据安全、网络安全、数据隔离等的基础设施服务，帮助构建安全的 SaaS 应用程序。部署在这些公共云上的 SaaS 应用程序应确保加固其应用程序安全设置，以符合公共云供应商推荐的最佳实践。

# 治理与法规合规性审计

第三方治理和法规合规性（GRC）审计可以帮助验证 SaaS 供应商对政府法规和行业标准（如 ISO27001、SOX、GLBA、HIPAA 和 PCI-DSS）的符合性。此外，它们还可以验证适当的业务连续性（BC）和灾难恢复（DR）计划是否已到位并被严格遵循。

GRC 审计帮助 SaaS 供应商识别并修正任何偏离法规的情况，以确保符合行业标准。它们还帮助 SaaS 提供商缓解客户对企业数据安全性、隐私性和可用性的担忧，并有助于建立信誉。建议 SaaS 供应商定期进行第三方 GRC 审计，以确保合规性。

# 第三方 SaaS 安全评估

第三方 SaaS 安全评估有助于验证 SaaS 应用程序及其部署的安全性和完整性。建议 SaaS 供应商定期进行 SaaS 安全评估，以确保其解决方案的安全性。

由开放 Web 应用程序安全项目（OWASP）记录的用于 Web 应用程序漏洞评估（VA）的标准工具和技术，并未为 SaaS 特定概念（如多租户、数据隔离等）提供足够的覆盖范围。云安全联盟（CSA）在其 CSA 安全指南中捕捉了 SaaS 应用程序的关键领域。专门针对 SaaS 解决方案并包含这些关键领域的安全评估对于检测安全漏洞并在恶意黑客利用之前修复它们至关重要。

SaaS 安全评估应包括应用程序 VA 和网络 VA，以实现完整覆盖。[图 20.2](#9781466508507_epub_c20_r1.htm#fig_20.2) 概述了安全评估中应涵盖的安全威胁和漏洞。
