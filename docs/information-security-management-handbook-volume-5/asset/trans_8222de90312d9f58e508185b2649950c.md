

在许多组织中，无论大小，将 IS 与历史性 IT 单元分离的需求变得越来越明显。IS 越来越多地承担着从组织角度而非仅技术角度解决安全问题的角色，因为组织内部越来越认识到信息安全面临的挑战。越来越多的 IS 单元承担起安全战略规划的角色，正如财务审计不（不应该！）向组织财务单元汇报一样，IS 单元也不应属于 IT 部门。虽然存在明显的协作，但 IS 单元正在演变为信息安全规划和评估职能，而 IT 单元则实施和管理安全的技术方面。有些 IS 单元与更大的风险/隐私/审计单元合并，但 IS 的角色是独特的，因为隐私/审计单元确定哪些数据是私有的，而 IS 为私有信息设计最有效的保护结构。基于此，IT 单元确定并实施保护结构所需的适当技术。因此，IS 职能已成为组织内其他业务单元协作的催化剂。

许多大型组织拥有 PS/S 单元，负责处理物理结构——建筑物和财产——在入口点建立访问控制，并为火灾和紧急情况实施安全措施。一些大型制造或化工生产组织拥有强大的 PS/S 单元，既处理人员危害防护，也处理访问控制。在存在此类单元的情况下，IS 和 IT 单元可以就结构访问控制进行协作，以确保与组织网络和系统访问控制的一致性。在危机响应管理中，IS 和 IT 单元将与 PS/S 单元扮演协作但从属的角色。

IS 单元通过以下方式为风险管理做出贡献：

![](OEBPS/images/box.jpg) 规划针对业务流程和业务规则确定的信息保护响应；并与隐私单元和隐私法规协作，确定组织对信息安全法规的合规责任。

![](OEBPS/images/box.jpg) 在政策和标准文档中阐述信息安全策略，并为组织员工提供培训。

![](OEBPS/images/box.jpg) 参与针对信息安全漏洞影响的硬件和软件采购/设计及变更管理工作；记录和监控漏洞控制工作。

![](OEBPS/images/box.jpg) 与 IT 和 PS/S 单元合作，追踪来自所有来源的威胁——互联网、危害、天气和/或外部人类活动；确定漏洞和漏洞控制；参与内部和外部事件响应。

![](OEBPS/images/box.jpg) 与 IT 和 PS/S 单元合作，为重大服务中断或重大危机事件的应急响应和业务恢复做好准备。

![](OEBPS/images/box.jpg) 业务单元经理`授权用户`访问单元内的系统和服务，并随时间`监控系统访问`。

![](OEBPS/images/box.jpg) 针对组织和业务流程漏洞的控制和对策由行政和风险管理单元通过定义的流程、政策、标准和意识培训来解决。

取决于组织的规模和复杂性，上述各种描述的角色和努力从来都不像陈述的那样明确划分。尽管如此，此列表开始表明组织单元之间的职责差异。从汇总的威胁和漏洞集合，加上资产损失的估值，可以得出整体组织风险概况。上述图景开始在关注领域提供清晰度。

# 风险评估

`Discipline` 是任何旨在产生特定性格或行为模式的训练，尤其是产生特定方向道德或心智发展的训练。（维基百科，2005）

基于对不同单元识别风险组成部分方法的理解，协作模型允许组织单元分别识别适当的威胁和漏洞，并将结果贡献给风险管理单元，该单元将各单元的结果与估值相结合，以确定整体风险概况。

# 经典风险评估

在经典的自上而下风险评估场景中，风险管理单元将指导组织范围内的努力，以识别威胁、漏洞、资产估值和对策。该单元制定计划并定义所有术语和流程。
