# SCAP 设计、目的与流程

Daniel Schmidt 写道：

“如前所述，漏洞和威胁的数量以及典型企业 IT 架构的多样性，已超出人类按威胁、按资产逐一管理的能力。以可被自动消耗和关联的方式，近乎实时地统一描述资产、漏洞和威胁数据的机器可消费标准，是唯一现实的选择。首先，所有硬件和软件资产必须共享一个通用命名方案。这通过开发通用平台枚举（CPE）规范和 CPE 字典实现，该字典目前托管在 NVD 中，面向全球社区开放。”[^(\*)](#9781466508507_epub_c06_r1.htm#ch6-ftn6)

Daniel 在一段简短的文字中提出了许多有道理的观点。我们知道威胁态势，情况并不乐观。我们也知道资源并未增加，尤其是从安全角度来看。终端节点在激增，而不幸的是，软件开发并没有变得多么出色（甚至可能更糟），而模糊测试技术显然正在利用僵尸网络和网格/并行概念迅速发展。面对所有这些压力，为了“数字生态系统”的生存，我们需要：

1\. 以统一的方式识别漏洞。

2\. 必须在每个漏洞的原生环境中自动评估其所带来的风险。

3\. 资产必须由一组 CPE 统一识别。

4\. 平台枚举必须能够为每个单独的软件和硬件组件唯一标识软件缺陷（CVE）和配置设置（CCE）。

5\. 特定平台（CPE）的配置（CCE）必须能够进行测试（OVAL），并打包成可由管理平台的 SCAP 验证工具消耗的检查清单（XCCDF）。

6\. 必须发生数据的消耗和关联，以满足合规性要求。

7\. 必须创建基于标准的数据馈送，以自动填充认证和认可活动，并迭代进行。

# 可扩展配置检查清单描述格式（XCCDF）1.1.4

XCCDF 是一种用于表达安全配置检查清单、漏洞警报及其他相关文档的规范语言。该规范旨在支持信息交换、文档生成、组织和情境定制、自动化合规性测试以及合规性评分。XCCDF 文档代表了一组针对某些目标系统的系统评估规则的结构化集合。该规范还定义了存储评估 XCCDF 基准结果的数据模型和格式。XCCDF 的意图是为表达安全检查清单及检查清单评估结果提供一种统一的手段。[^(\*)](#9781466508507_epub_c06_r1.htm#ch6-ftn8)

# 开放漏洞评估语言（OVAL）5.6

OVAL 用于表达可用于评估系统状态的标准化、机器可读规则。在 SCAP 下，OVAL 通常用于确定漏洞和不安全配置的存在。用于检查安全问题（例如错误的最小密码长度设置）的一组指令称为 OVAL 定义。包含一个或多个 OVAL 定义（通常是数百个甚至数千个）的文件称为 OVAL 定义文件。[^†](#9781466508507_epub_c06_r1.htm#ch6-ftn9)
