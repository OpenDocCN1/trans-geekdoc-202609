# 需要澄清！

`security based on risk management, risk reduction, and risk assessment is a failed concept.` Donn Parker, 2006, my emphasis

在资源充足、多年惯性、行业同行强化以及政府机构强力鼓励的情况下，组织正在积极构建和完善风险管理和治理结构。与大多数 IS 专业人士一样，我也曾陷入风险评估和分析的同样热情与汗水中！我在信息安全咨询中的目标始终是寻求并推荐 IT 基础设施使用的效率。我一直认为，效率的基础是仔细的 IT 风险管理，包括初始和持续的评估、分析、控制审计和纠正性缓解。我还参与过各种组织中大大小小的多次评估工作。

然而，尽管资源充足且势头强劲，我在评估机会中观察到，不同的组织单元在风险管理的领导和管理方面存在分歧。在过去十年里，无论好坏，风险治理已与回应《萨班斯-奥克斯利法案》的合规活动联系在一起，该法案在上个十年中期要求投入意想不到的时间和资源来满足要求（Claburn, 2007），通常每年需要花费数月时间来收集必要的审计证据。许多人质疑如此高昂支出的必要性，并质疑该工作的总体效益（O’Sullivan, 2006）。

我自己对这一问题的挣扎始于试图从业务风险的整体概念中推断 IT 和 IS 风险的各个方面。我长期以来认为 IS 风险管理与业务风险管理不同，但仍然是其子集。然而，我一直努力澄清这种关系，尤其是在面对其他非 IT/IS 专业人士时，他们倾向于将所有风险视为业务决策及其成功或失败概率的整体主题的变体。即使在同一组织内部，我也观察到组织群体——高管、审计人员、安全专业人员、IT 管理人员和员工以及普通用户社区——在角色和职责的定义和文档中缺乏一致性。不幸的是，参考框架和术语定义之间的差异并不总是得到承认，这导致了对那些似乎不太符合 IT 环境的组织风险管理工作缺乏认可。可以理解的是，Donn Parker 在本节开头引用的近期建议确实引起了我的注意。

我认为，术语使用的这种不一致和不精确导致了对 IS 风险与业务风险之间区别缺乏认可。并且我认为，这种困境在很大程度上导致了 IS 和 IT 风险管理的低效率（在时间和金钱方面），以及将 IT 支出与整体业务支出联系起来的困难，正如 Parker（2006）和 Carr \[9\] 所指出的，他们质疑如此高额 IT 支出的必要性。

# 风险定义的历史

我从未试图挑战业务和金融风险专家群体之间的定义，他们在这个过程中已经参与了几十年。我只是寻求适用于 IT 和 IS 环境的定义和适当术语，以期为更好的沟通奠定基础。我开始寻找风险本身及其相关术语的清晰定义，并发现我并非孤身进行此次搜索，也不是唯一关注定义混乱的人。在讨论金融活动时，Holton（2004）表达了担忧：

实际应用……都取决于风险的测量。在没有风险定义的情况下，不清楚这些测量反映的究竟是什么……对金融文献的搜索会产生许多关于风险的讨论，但很少有定义。

最近，Saner \[10\] 代表加拿大治理研究所写道：

关于风险管理的成功讨论的关键在于术语的谨慎处理——既不应忽视语义的重要性，也不应被其束缚住。

并且

如果将额外的标准纳入比较，情况会变得更糟。这种程度的语义分歧可能成为有效分析和沟通的严重障碍……在任何时候（尤其是在比较框架或跨部门沟通时）都必须对含义保持精确。

Parker（2006）也说：

关于安全风险的争论之所以模糊不清且令人困惑，是因为支持者将非风险的风险和确定性混为一谈。

在本章中，不可能涵盖所有可用的术语和概念定义，但我提供了一些定义供比较和讨论，并突出了一些不一致和精度问题。为了方便阅读和随后对本章的讨论，我按顺序对本章中风险及其他相关术语的定义进行了编号。

我从我最喜欢的风险定义开始，来自 Neumann \[11\]：

**1.** 风险。直觉上，如果漏洞被利用或威胁成为现实，可能产生的不利影响。在某些语境下，风险是不利影响发生概率的度量，或者是发生概率与量化后果的乘积。`There is no standard definition`。（my emphasis）

尽管 Neumann 断言如此，但确实存在许多标准定义，这正是问题的一部分。风险和风险管理的历史可以追溯到几个世纪以前，经历了关于赌博、数论、初步统计分析、保险和投资的讨论而不断发展。风险历史的准确且有年代的视角超出了本章的范围，然而，Bernstein（1998）的著作《风险之神：风险的非凡故事》（*Against the Gods: The Remarkable Story of Risk*）是一本极其优秀且引人入胜的评论，适合所有组织层面和角色的风险承担者和评估者。本书为以下历史视角提供了大量内容。
