# 战术

战术计划提供广泛的举措，以支持和实现战略计划中规定的目标。这些举措可能包括诸如建立电子策略开发和分发流程、为服务器环境实施强大的变更控制、降低服务器上存在漏洞的可能性、实施“热站点”灾难恢复计划，或实施身份管理解决方案等部署。这些计划更加具体，可能包含多个项目来完成工作。战术计划的时间较短，例如 6–18 个月，以解决公司的特定安全弱点。

# 运营/项目计划

具有里程碑、日期和责任人的具体计划提供沟通和方向，以确保各个项目正在完成。例如，建立策略开发和沟通流程可能涉及多个项目和许多任务：

![](OEBPS/images/box.jpg) `Conduct security risk assessment`

![](OEBPS/images/box.jpg) `Develop security policies and approval processes`

![](OEBPS/images/box.jpg) `Develop technical infrastructure to deploy policies and track compliance`

![](OEBPS/images/box.jpg) `Train end users on policies`

![](OEBPS/images/box.jpg) `Monitor compliance`

根据工作的规模和范围，这些举措可能是单一计划的一部分任务步骤，也可能是通过多个项目管理的多个计划。这些工作的持续时间较短，旨在工作完成时提供离散功能。传统的“瀑布”式项目实施方法花费大量时间来详细说明实施完整项目所需的具体步骤。当今的高管更关注在实现一些短期或至少是中期结果方面，以在过程中展示投资的价值。在过程中展示价值可以保持组织对该工作的兴趣和可见度，增加获得更长期资金支持的可能性。如果高层管理无法实现这些早期收益，可能会变得不耐烦。

# 董事会的作用

董事会在信息安全治理方面的主要作用是设定正确的方向。董事会了解组织的风险偏好。例如，金融机构可能在实施安全控制方面遵循非常保守、规避风险的方法，要求对信息访问提出更细致的请求并限制本地管理员权限，而创意营销公司可能希望其平面设计师拥有更开放的访问权限，并能够将某些类型的软件下载到其开发机器上。或者，一个组织可能是技术领导者或早期采用者，允许项目在新的、未经验证的、经过 beta 测试的软件上承担风险，而另一个组织可能更倾向于在新软件经过市场验证、多个版本发布并首先被大型企业采用后再实施。这些决策是基于董事会设定的“高层基调”做出的。

内部审计部门通常与审计委员会有虚线关系，审计委员会反过来向董事会提供必要的信息。这可以为董事会提供有关公司面临的内部和外部审计问题水平的宝贵见解，其中一些问题直接反映了正在执行的信息安全治理活动。是否有许多审计发现？它们是否得到及时关闭？这些审计发现本可以避免吗？审计发现的数量是否表明缺乏良好的信息安全治理计划？这些都是董事会应该提出的问题，以便他们可以设定方向，确保风险得到适当评估和管理，政策和标准得到实施以降低风险，并通过标准化的定期衡量来实现一定的问责制。

信息安全官员应确保董事会了解当前的安全状态以及影响业务的适用外部法律法规的合规情况。这可以通过直接联系、通过审计委员会，或由另一位 C 级高管传递信息来实现。信息应处于足够高的层次，使董事会能够非常快速地掌握问题和建议的解决方案，而无需深入了解信息安全实践。董事会非常忙碌，解释什么是 443 端口或 Adobe 的最新漏洞很可能不是他们时间的良好用途。解释实施身份管理系统可能如何使组织受益，或虚拟专用网络投资如何大幅降低设施成本，将更符合董事会的兴趣。

近年来，由于法律法规数量不断增加、新闻中对企业声誉的损害、事件成本以及巨额罚款或刑事起诉的潜在风险，董事会对信息安全的关注度大大提高。董事会不一定想要“最好的”安全，除非它能提供某种竞争优势。与许多其他商业决策一样，他们通常想要“足够”的安全，即边际回报 = 边际收益。他们关心竞争对手在安全方面的支出，因为支出较少可能意味着投入不足，从而使我们的系统更容易受到攻击；支出较多可能意味着花费过多，这些资金本可用于公司其他领域的部署。
