# Pradnyesh Rane

软件即服务（`SaaS`）正迅速成为满足企业 IT 服务需求的主导交付模式。然而，大多数企业对 `SaaS` 模式仍感到不安，原因是缺乏对其数据存储和保护方式的可见性。根据 Forrester 的研究《企业软件现状：2009》，安全顾虑是企业对 `SaaS` 不感兴趣的最常见原因。因此，解决企业安全顾虑已成为采用 `SaaS` 应用程序的最大挑战。

本章着重于在架构 `SaaS` 应用程序时的安全考量，以及应对安全挑战的缓解策略。采用这些安全实践可以帮助 `SaaS` 提供商通过消除安全漏洞并确保敏感数据安全，向企业注入一定程度的安全信心。

# SaaS 概述

`SaaS` 是一种软件部署模型，其中应用程序由应用程序或服务提供商远程托管，并通过互联网按需提供给客户。企业可以利用 `SaaS` 模式降低与传统本地应用程序相关的 IT 成本，如硬件、补丁管理、升级等。按需许可可以帮助客户采用“按需付费/按需增长”模式，降低 IT 采购的前期支出。

`SaaS` 允许软件供应商控制和限制使用，禁止复制和分发，并便于控制其软件的所有衍生版本。`SaaS` 的集中控制通常允许供应商与多个企业（租户）和用户建立持续的收入流。租户获得一个受保护的沙箱式应用程序视图，与其他租户隔离。每个租户都可以调整应用程序的元数据，为其用户提供定制的外观和体验。

`SaaS` 软件供应商可以在其自身的私有服务器场上托管应用程序，或将其部署在第三方提供商（例如 Amazon、Google 等）提供的云计算基础设施服务上。云计算与按需付费（按需增长）方法的结合，帮助应用程序服务提供商减少基础设施服务投资，并使其能够专注于为客户提供更好的服务。

# SaaS 的安全挑战

在过去十年中，计算机在企业内已广泛普及，而 IT 服务和计算已成为一种商品。当今企业将数据和业务流程（交易、记录、定价信息等）本身视为战略资产，并通过访问控制和合规性政策加以保护。

然而，在 `SaaS` 模式中，企业数据存储在 `SaaS` 提供商的数据中心，与其他企业的数据一起存放。此外，如果 `SaaS` 提供商利用公共云计算服务，企业数据可能与其他不相关的 `SaaS` 应用程序的数据一起存储。云提供商还可能为了保持高可用性，在多个国家的多个位置复制数据。

大多数企业熟悉传统的本地模式，其中数据继续存储在企业边界内，并受其政策约束。因此，企业对 `SaaS` 模式中数据存储和保护方式缺乏控制和了解感到非常不安。关于数据泄露、应用程序漏洞以及可能导致财务和法律责任的可用性问题，存在强烈的担忧。

# SaaS 部署模型

`SaaS` 安全挑战取决于供应商使用的部署模型。`SaaS` 供应商可以选择使用公共云供应商或自行托管来部署解决方案。像 Amazon 这样的专用公共云提供商通过提供有助于确保边界和环境安全的基础设施服务，帮助构建安全的 `SaaS` 解决方案。这涉及使用防火墙、入侵检测系统等。然而，自托管的 `SaaS` 部署要求供应商构建这些服务并评估其安全漏洞。

# 数据安全

在传统的本地应用程序部署模型中，每个企业的敏感数据继续存储在企业边界内，并受其物理、逻辑和人员安全及访问控制政策约束。然而，在 `SaaS` 模式中，企业数据存储在企业边界之外，即 `SaaS` 供应商端。因此，`SaaS` 供应商必须采取额外的安全检查，以确保数据安全，并防止因应用程序中的安全漏洞或恶意员工导致的数据泄露。这涉及使用强大的加密技术保障数据安全，并使用细粒度授权来控制对数据的访问。
