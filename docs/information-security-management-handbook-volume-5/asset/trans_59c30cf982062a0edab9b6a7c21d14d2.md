

该过程始于组织业务关键性/影响分析，以确定每个关键业务流程的损失金额和其他成本，以及恢复或替换该流程的成本，包括流程之间对业务整体持续运行的优先级衡量。对于每个流程，需要识别威胁（包括概率）和漏洞，以及针对每个漏洞和相关威胁的控制措施或对策。由此，可以确定单个和集体风险。如果控制措施或对策不完整，则差距分析将解决不完整性并导致缓解计划。理想情况下，这应成为一项年度工作，记录关键性，评估威胁、漏洞和控制措施，填补控制措施中的差距，并重新确定风险。每个组织单位被指导在单位范围内评估风险，确定威胁、漏洞、资产价值和控制措施，推导风险，并识别缓解计划——这是一个贯穿整个组织的宏大递归方案。这意味着 IS 和 IT 单位将遵循脚本，并在技术基础设施内确定风险组成部分并推导风险。

汇总的风险报告提供了所付出努力的衡量标准，但正如 Parker（2006）所观察到的，增强数据保护的整体结果值得怀疑。从汇总的报告中，控制措施中的差距将逻辑上为持续管理已识别且未受控制的风险提供基础。根据文档的详细程度和数量，整体风险管理工作变成了对控制措施和对策差距的追求，有时脱离了管理技术和信息安全的上下文。之前关于协作风险管理的介绍应该开始为效率提升和增强数据保护提供线索。基于 Bernstein 的引文（第二部分开头），我建议每个主要贡献的组织单位专注于“控制领域”，具体来说，就是解决单位特定风险组成部分的努力。执行单位可以提供资产和私有数据损失的成本估算。风险/审计/隐私单位可以协调风险管理流程，并记录监管合规和组织政策声明领域的威胁和漏洞。业务单位经理可以管理访问控制实践，并跟踪其领域内系统的保护情况。员工可以更加意识到并积极防止意外事件，并观察和报告潜在的故意事件。IS 和 IT 单位可以专注于信息的内部和外部威胁，以及允许威胁成为现实的技术漏洞。PS/S 单位可以专注于对物理结构和人身安全的外部威胁。

融合概念为协作模型提供了额外的视角。最初，融合解决了 IS（包括 IT）和 PS/S 之间的关系，强调两组在安全问题上协作的必要性。为了使融合最有效，它需要 `context`。简单地将两个单位合并为一个并不能实现预期目标；事实上，这种武断的合并可能会削弱各单位的重要努力和流程。IS 和 PS/S 可以通过结合建筑入口控制技术与数据中心管理的服务器和数据库（跟踪个人进入建筑物及随后进入数据系统的授权访问）来在访问控制的上下文中融合。两组访问日志中访问模式的差异可能表明信息资源面临威胁。融合的另一个上下文是事件管理，包括危机响应和业务连续性。安全和安全专业人员接受培训，在危机响应期间将人身安全作为最高优先级，两个单位可以在危机响应期间的疏散计划和员工核查方面相互协助。在强调安全和危害预防的组织中，例如制造或化学加工组织，PS/S 单位通常拥有强大的员工培训和意识计划。IS 和 IT 可以从与这些计划的协作中受益，并将其扩展到包括信息安全意识。融合上下文还可以在 IS 与隐私/审计单位之间建立，用于跟踪和规划对法规和行业标准倡议的响应，这些倡议通常包括重叠的隐私、安全和审计要求。

# 信息安全风险评估的上下文

希望，IS 单位在风险评估中的主要角色——识别面向信息的威胁以及提供潜在利用机会的漏洞——现在更加清晰了。从特征和历史上看，这一直是 IS 和 IT 单位日常所做的工作，并且至今仍然如此。显然，随着执行单位和风险/隐私/审计单位跨越风险管理的门槛，IS 和 IT 单位早已在那里。基于执行单位和风险/隐私/审计单位的指导，IS 和 IT 管理提供数据和信息保护以及控制数据和信息访问的技术和流程。尽管如此，IS 和 IT 单位及管理层理解如何与其他单位协作，而不是孤立地，在企业风险管理和治理策略的上下文中定位自己是很重要的。当 IS 的流程和实践得到适当评估、记录和管理时，结果可以被制定为与任何监管要求和组织对风险评估的期望保持一致。

在现实中，并非所有 IS/IT 单位都有条件参与组织风险管理流程。值得称赞的是，大多数 IS/IT 单位为数据访问和保护提供了合理的服务，但许多单位仍然孤立地行动，创建的技术环境往往成为目的而非手段，并且与组织决策过程分离运行。许多单位没有意识到直接影响更大组织的数据分类和监管要求。不幸的是，许多单位仍然以零散的方式进行管理，大多数问题在出现时才处理，除非被更严重的问题打断。许多人正确地断言，信息安全不仅仅是一组重复的任务，而是一个过程，意味着它随时间持续。我建议，高效的信息安全管理是一种 `discipline`，而不仅仅是任务和定义的流程，它需要一种有纪律的方法来应对威胁、漏洞、技术和业务方向的变化。对于这个上下文，discipline 的最佳定义是本节开头引用的那个。

在 IS 的情况下，组织和 IS 专业人员正在寻求基于文档化的政策和标准的一致行为模式，以朝着数据和信息保护的方向发展。即使是有纪律的方法也需要一个在其中运行的结构或框架。我建议以下模型，基于 Col. John R. Boyd, USAF (1927–1997) \[28\] 的研究，它提供了管理 IS 涉及的活动的独特视角。这种有纪律的方法将使 IS 单位能够与其他单位在上下文中融合，特别是与中央风险/隐私/审计工作，以提供组织治理和风险管理。
