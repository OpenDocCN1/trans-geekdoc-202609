# 重新审视“集中式分布式计算”、“威胁状态数据库”以及“安全领域的SETI”

你会惊讶于关于“集中式分布式计算模型”这一简单想法的评论在过去五年多里发生了多大的变化。不久之前，运营成本仍占据主导地位，安全仍被视为事后考虑的因素。这种管理理念所推动的是单一的同质化供应商解决方案，表面上看，这是一条更具成本效益、更适合企业的路径。攻击向量的快速变化以及纯商业解决方案似乎无法填补巨大且快速演变的差距，这真正创造了一个环境，在消费者社区的支持下，创新可以重新引入这个方程式。这并不像围绕某些代码或开源项目形成的社区那样，在其中我们看到了真正的群体力量。我们得到了一个迹象，即当返工被最小化且开放协作倡议得到真正支持时，有什么可能。从技术和社会两个方面来真正开始利用这种力量的唯一真正方法，是在中心拥有松耦合但可能紧密集成的控制，同时将权力留在边缘。这将允许添加到GIG中的每个后续内容，都有可能为系统负荷做出贡献，以减少风险，从而可能避免在快速增多的节点重压下崩溃。

去年，在《信息安全手册》第6版、第4卷中，我写道：

“部署防护措施，并与从我们日益复杂的环境中返回的信息进行关联，这在未来几乎是成败的关键。在之前的一章中，该章发表在《信息安全管理手册》第6版第3卷中，我以相当通用的方式提及并定义了灵活的“端点和流点”概念。这种灵活防御概念可以随你适应，以尝试在未来几年对抗日益激烈的威胁和攻击向量演变。密西西比河类比在这里依然成立，因为信息的巨大规模和压倒性洪流会压倒大多数，如果不是全部，典型的城堡和护城河式防御。你无法筑坝拦住密西西比河，但你可以筑坝拦住一些支流，同时观察密西西比河，这种对刺激的响应开始在问题最初迹象时捕获更多信息。传统和非传统端点在其周围安全环境中的参与度增加，将通过`IF-MAP`，使该行业有可能毕业到“威胁状态数据库”作为一种表现形式。`IF-MAP`是这种概念的基石，但只是工具箱中的一种工具。随着诸如`Common Uniform Driver Architecture`之类的东西的发展，像`SETI`这样的项目可以被模仿，目标是数千个单独的客户端参与网格，致力于更安全生态系统的分布式任务。服务于各种功能的开源客户端都将启用`IF-MAP`，然后可能扮演双重角色：既订阅信息以加强其整体态势，又发布它们周围看到的内容。有效地，它们各自成为各自权利的单独传感器。这反过来允许对输入进行加权，并可能进一步完善进入存储库的信息审查。这在某种程度上是一种分布式同行评审，虽然输入必须经过审查以确定信任级别，但它可能是存储在`MAP`中的另一个指标，它能提供额外线索，以了解网络的状态，更多地基于单个客户端周围看到的内容，而不是基于它们告诉网络关于自己的内容。这种输入的加权可以根据需要进行调整，并可能产生方程式中的一个重要部分。“联合安全”的概念并不新鲜，但其实现性在一段时间内确实有点像空中楼阁。不仅对你的企业，而且对对你重要的合作伙伴企业的部分，拥有一个真正全面的图景，是防御的潜在力量倍增器。实时信息流向基于开放标准的存储库，使你能够快速集中精力和资源，可能在某个区域成为问题之前。这种即时调整在几年前的异构网络中根本无法想象，然而随着`IF-MAP`和可信计算组最新的`TNC`规范，我们似乎终于处于真正的`OODA`或博伊德循环交互决策周期的边缘，基于对每个行动和决策的及时反馈。[^(\*)](#9781466508507_epub_c06_r1.htm#ch6-ftn2)
