

C级（CEO、CIO、CFO、CTO等）高管是确保安全计划长期有效的关键人物。如果他们没有被明确地纳入安全部门的角色中，并对“安全是必要之恶”这一观念给予默许支持或公开表态，安全官员将难以获得其他高管的支持。另一方面，C级高管可以成为推动计划前进的巨大资源。他们凭借职位权力以及影响力，能够召集不同业务部门的高管，这些高管可能在是否需要更强安全控制方面存在分歧。与董事会一样，安全官员必须认识到C级高管时间有限，并且“期望”安全官员将安全作为一项业务来管理，并实施完成工作所需的最低限度措施。

# 高级/中层管理角色

高级/中层管理层对信息资产的保护负有整体责任。业务运营依赖于信息的可用性、准确性，以及防止未经授权的个人获取。如果信息的机密性、完整性或可用性受到破坏，可能会导致财务损失。他们必须意识到自己为组织所接受的风险，无论是通过明确的决策，还是由于未能做出决策或未能理解信息系统现有运营中固有的风险而接受的风险。

这一层级通过其行动来传达对计划的支持。如果他们不支持安全政策，那么他们的中层和一线管理人员很可能也不会觉得有必要遵守安全政策。当利益冲突时，决策往往会倾向于业务实施的必要性，从而可能绕过被视为“由安全部门发布”的规则。正如董事会和C级高管在展示“从上而下的基调”，这些高管在其日常行动中也是如此。

参与信息安全实践的安全高管确保风险在其所有重大项目中得到适当识别，安全在整个组织中得到整合，并且业务案例包含安全要求。高级管理层经常依赖中层管理团队的判断和反馈。如果中层管理层不支持安全变革，高级管理层就很难接受安全部门的安全实践。这对安全计划的长期支持可能是危险的。建立支持的一种方式是通过设立安全委员会。

安全政策应仅由公司的高级管理层/C级高管发布，或者如果由安全官员发布，则应获得这些层级的认可。这样，政策就不再被视为仅仅是安全部门的愿望，而是被解读为公司管理层的意图。随后可以在考虑已批准的公司安全政策的前提下做出投资决策。

# 指导委员会/安全委员会角色

安全委员会或安全指导委员会通常由公司不同业务和职能部门的管理和技术代表组成。委员会由信息安全官担任主席，可能包括法律、人力资源、信息技术、内部审计、风险管理、合规、物理安全/设施以及市场、财务、运营等业务部门的代表。委员会的角色是审查安全政策、投资和状态，并达成一致。一旦委员会对政策进行了审核，然后，且只有在此时，才应将政策提交给高级管理层批准。为什么？委员会建立了“草根支持”，这对于影响高级管理层接受政策非常有益。另一个好处是，中层/一线管理人员通常会更好地理解为什么安全政策是必要的，因为他们参与了建议的制定。委员会还可能在拟议的安全政策或投资的早期阶段发现问题，从而为组织节省大量资源和返工。一旦该流程在公司内作为关键的信息安全治理角色得到良好建立，各部门将开始向委员会代表反映问题以供提交，提供业务投入。随着时间的推移，高级管理层可以开始信任委员会的集体决策过程，从而加快高级管理层的审批流程。由于决策已获得安全委员会的审查和广泛支持以及随后的高级管理层批准，因此这些决策更有可能在长期内得到支持。

# 最终用户的安全角色

组织内许多不同的个人贡献者都为成功的信息保护做出贡献。正如常说的陈词滥调，安全是公司内每个人的责任。每个最终用户都有责任了解适用于其特定职能的政策和程序，并遵守安全控制期望。用户必须了解职责，并接受足以降低损失风险的培训。虽然个人的具体职称和职责范围可能因组织而异，但以下角色支持安全控制的实施。当为组织定义流程时，个人可能会承担多个角色，具体取决于限制和组织结构。为指定员工分配各种安全职能的明确任务和问责制非常重要，以确保任务得到执行。通过分发政策、职位描述、培训和管理方向来传达每个职能的职责，为员工执行安全控制奠定了基础。

![](OEBPS/images/box.jpg) `End User`: 最终用户负责通过遵守已传达的安全政策，在日常工作中保护信息资产。最终用户代表着组织的许多“窗口”，通过他们的行为，安全可以通过合规得到加强，也可能因他们的行为而受到破坏。例如，下载未经授权的软件、打开未知发件人的附件并成为网络钓鱼攻击的受害者，或访问恶意网站，都可能将后门或木马引入环境中。最终用户还应充当组织的一线眼睛和耳朵，报告安全事件以供调查。建立这种文化要求该角色和职责得到清晰传达，并为所有人所理解。最终用户可能被分配多个角色，继承先前讨论的角色配置文件的安全属性。因此，“最终用户”一词对提供给最终用户的角色是一种过度简化。在此语境下，最终用户代表一类广泛的个人，目的是确保他们具备（1）足够的信息安全一般理解（系统访问前培训、年度复习培训以及针对特定主题的临时培训），（2）知道如何识别事件，（3）知道在哪里报告事件，（4）获得其工作所需的适当访问权限，（5）遵守适当的安全政策。
