# 系统清单

一个常见的问题，不仅存在于安全产品中，也存在于任何试图对计算机系统进行某种评估的产品中，即确定该系统的属性（例如，操作系统、补丁级别、已安装的应用程序等），并能够清晰且一致地传达这些属性。目前，没有普遍接受的从系统收集属性的方法，也没有一种常见的方式来表达这些属性，以便其他应用程序可以轻松消费。对该功能的需求已得到广泛认可，其使用将非常普遍。

# IF-MAP：纽带

# “平等主义胜过专制主义”

去年我写道：

“在最基本的层面上，IF-MAP 是一个基于开放标准的关于各种主题的信息存储库。具体来说，它提供了一种标准协议，用于实时共享有关网络用户和设备以及其状态和活动的信息。该规范最初表示了三种不同的功能，包括 IF-MAP Publish、IF-MAP Subscribe、IF-MAP Poll 和 IF-MAP Search。这些功能通过 Simple Object Access Protocol (SOAP) 在线运行，针对 IF-MAP 服务器（MAP），后者存放但不验证来自所有具有发布功能的设备的信息。为网络设备定义的初始元数据规范包括 IP-to-MAC 绑定、第 2 层位置、安全事件、设备属性、身份验证信息和访问请求信息。它们最初在 Trusted Network Connect (TNC) IF-MAP binding for SOAP 规范 1.0 修订版 25 中定义和发布。单独来看，它们有些重要，但当你开始将它们组合在一起时，它们会变得更加引人注目。”[^(\*)](#9781466508507_epub_c06_r1.htm#ch6-ftn31)

作为简要的历史更新，可信计算组在 2008 年 4 月发布了 IF-MAP v1.0 标准，然后在 2009 年 5 月发布了 IF-MAP v1.1。版本 1.1 的发布与 Interop’09 同时发生，并进行了多厂商协作演示。Interop’09 演示的用例主要集中在远程用户访问、安全工业控制、物理访问安全和数据中心管理等基本用例上。与此同时，IETF NEA-WG 取得了重大进展，并发布了与 IF-TNCCS 和 IF-M 兼容的 RFC（标准）。

由于我是重用的大力倡导者，不喜欢重复造轮子，因此我支持创建和推广一种较新的协议，而不是使用现有选项（例如，关系数据库或目录），这个问题是合理的。答案在于网络系统数据的本质与每种可能方法的优缺点之间的对比。网络系统中的绝大多数协调数据结构松散且经常变化。同时，基础设施元素通常对不同的属性和模式感兴趣，这些属性和模式不一定适合当前的功能。IF-MAP 是一种可扩展且高度可扩展的发布/订阅（pub/sub）架构，专门用于异步搜索，旨在适应安全协调用例，包括大量的实时数据写入、非结构化关系、对当前状态变化的多样化兴趣以及分布式数据生产者和消费者。该设计还基于这样一个假设：你永远无法找到一个单一的数据关系模式来满足所有需求。此外，标识符是隐式存在的，在附加元数据之前没有意义，并且与元数据一起在 XML 模式中定义。

首先，从上下文角度来看，网络安全元数据描述网络数据流及其关联主体的属性。元数据是关于其他数据的数据，因此文件的名称、大小或描述是关于文件数据（文件内容）的元数据。例如，“一张建筑物的图片”是关于包含建筑物图像的文件的描述性元数据。因此，有效地，IF-MAP 可以回答任何数量的问题，例如：“谁”与什么数据流相关联？使用了什么凭据？做出了什么策略决策？是否有任何最近的“异常”行为？

# “松散耦合，紧密集成”

# IF-MAP 基于四种主要操作

Publish 的属性：

用于创建、更新或删除关于网络元素的信息

客户端将元数据存储在元数据访问点（MAP）中供其他人查看

包含创建、修改和删除功能

Search 的属性：

用于立即从数据库中检索关于网络元素的信息

客户端检索与特定标识符及其关联标识符相关的已发布元数据

受链接匹配和结果过滤条件限制

受最大深度和大小条件限制

Subscribe 的属性：

用于维护 IF-MAP 客户端希望接收通知的搜索列表

包括客户端请求异步结果的搜索实例，当其他人发布新元数据时匹配

客户端的订阅由一个或多个搜索组成

客户端为其搜索命名，以便异步结果明确无误

Poll 的属性：

由 IF-MAP 客户端用于确认已准备好接收订阅的结果
