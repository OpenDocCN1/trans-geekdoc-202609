

# 执行单元

该组由组织决策者组成，负责代表组织在适当方向上花费时间和金钱。该单元定义所选行业领域内的核心业务价值，基于此，高管还定义用于营销和产生收入的服务或产品。该单元对组织完整性、监管和法律合规性以及风险造成的损失后果负有最终责任。作为风险治理过程的主要协作者，执行单元在协作模型中做出三项主要决策：

![](OEBPS/images/box.jpg) 将组织风险管理委托给适当的单元，通常具有最高级别的汇报状态。该单元将领导流程和规划，并汇总所有其他业务单元的所有贡献并生成相应报告。

![](OEBPS/images/box.jpg) 定义业务流程并授权业务规则，以根据产品和服务的决策来制定流程。这既适用于现有活动，也适用于涉及方向或增长的重大新业务决策。尽管某些详细流程可能会被委托，但责任和启动权在于该单元。

![](OEBPS/images/box.jpg) 确定各种组织资产的总体价值，以当前账面价值和重置成本为准：实体结构、资本设备、专有信息存储、声誉，以及（最重要的是）人员。这是确定风险（尤其是组织层面的风险）的基础。该单元是价值和成本的财务终止点，即使某些资产费用被委托给其他单元。

# 风险管理单元

该单元可以是单一目的实体，也可以与几个相关的组织范围管理工作相结合，例如隐私、监管合规、内部审计和/或质量控制，主要取决于组织规模和行业领域。这是设计治理和风险管理结构，并为组织协作制定计划的团队。它是参与评估和确定组织风险的数据和报告的最终收集点和存储库。该单元在组织内部启动定期（每年或其他周期）流程，并根据分配的风险职责与所有其他单元交互。在风险管理方面，该单元

![](OEBPS/images/box.jpg) 根据行业领域和监管要求安排内部评估和外部审计。该单元能够向内部审查人员，尤其是向外部审计师和其他监管机构提供组织范围的风险态势。

# 一般业务单元

这些单元是为解决执行单元设定的主要业务流程而建立的。这些高级流程根据组织方向和行业定义的服务、产品或对其他单元的支持工作进行定制。在大多数组织中，这些单元的董事/经理被指定为与其组织职能相关的信息领域的数据所有者。董事/经理通过以下方式解决内部威胁和漏洞：

![](OEBPS/images/box.jpg) 确定业务流程的业务规则和信息资源要求——外部数据、软件产品、系统要求。这需要与执行单元紧密协作，以确保业务流程得到正确定义和阐述，并得到正确信息的支持。

![](OEBPS/images/box.jpg) 雇佣经验丰富的员工，并确保所有人都接受培训并了解个人职责，包括工作任务和保护数据。

![](OEBPS/images/box.jpg) 批准和授权员工访问组织系统和应用程序。经理还必须在员工被组织解雇后立即启动访问停用。

![](OEBPS/images/box.jpg) 审查与单元基础系统和应用程序相关的访问和其他活动报告，并转发任何可能导致系统中断和/或数据丢失的潜在事件报告。

![](OEBPS/images/box.jpg) 审查和授权对单元基础生产数据系统所做的更改。

业务单元内的用户不仅是组织信息资源威胁和漏洞的最大来源，而且可能是解决方案中最大的一部分。不难理解，如果员工能够拥有部分解决方案，他们将对其控制范围内的情况更加小心和负责。作为信息安全（作为风险的主要组成部分）员工培训的一部分，用户可以被赋予以下能力：

![](OEBPS/images/box.jpg) 了解无人看管的开放工作站以及可见的工作相关文件和档案的后果，并了解故意不当行为的个人后果和制裁。

![](OEBPS/images/box.jpg) 对在工作空间内接近陌生人或无人看管的访客感到自信。

![](OEBPS/images/box.jpg) 识别并报告可能导致危机的情况，例如办公室异常烟雾、即将到来的天气变化以及与恶意软件相关的异常工作站行为。

# 信息安全/信息技术/物理安全

许多中小型组织没有单独的 IS、IT 和 PS/S 单元的奢侈。尽管如此，这些单元代表的为风险管理做出贡献的角色需要澄清，因为存在一些重要的区别，如前面章节中所提及。IT 单元是大型组织的支柱。该单元根据执行单元的授权和决定，获取、实施和管理架构和基础设施。威胁增加、技术快速变化以及对按需信息的需求，开始为稳定的中央 IT 单元提供理由，这些单元参与而非仅仅响应业务决策，因为组织试图在技术成本方面获得效率。
