

| VMX31 | 不要将主机性能信息发送给来宾 |

恶意人员可能会将性能信息作为攻击典型侦察阶段的一部分来利用。

| VMX51 | 限制对 VMsafe CPU/内存 API 的访问 |

恶意人员可能会利用 VMsafe 内省通道，对连接到该通道的所有虚拟机发起攻击。

| VMX52 | 通过 VMsafe CPU/内存 API 控制对虚拟机的访问 |

VMsafe 内省通道可能会促进虚拟机的被攻破。如果给定的虚拟机未使用 VMsafe 产品，则不应在相应的 VMX 文件中启用对 VMsafe 内省通道的访问。

| VMX54 | 限制对 VMsafe 网络 API 的访问 |

恶意人员可能会攻击连接到内省通道的所有虚拟机。

| VMX55 | 通过 VMsafe 网络 API 控制对虚拟机的访问 |

利用 VMsafe 的过滤功能来过滤和控制对 VMsafe 内省通道的访问。不控制对 VMsafe 内省通道的访问，会为恶意人员留下可乘之机。

| VMP01 | 保护虚拟机，如同保护物理服务器一样 |

将服务器迁移到虚拟环境，并不消除遵循保护物理服务器所需的相同行业最佳实践的必要性。

| VMP02 | 禁用虚拟机内不必要或多余的功能 |

在虚拟机中，就像在物理服务器中一样，减少威胁面的最佳方法之一是移除或禁用不必要的功能。保留不必要的功能或服务，会为恶意人员留下可乘之机。

| VMP03 | 尽可能使用模板部署虚拟机 |

VMware 的诸多优势之一，是能够构建“黄金主机”虚拟机，它代表了对给定虚拟机进行加固和锁定的最佳努力。该虚拟机可以转换为模板，然后使用该模板部署新虚拟机，新虚拟机将以原始虚拟机上的工作作为基准，来部署更多虚拟机。

| VMP04 | 防止虚拟机独占资源 |

在物理服务器领域，我们倾向于将所有可用资源分配给每台独立的物理服务器——“越多越好”的理念是常态。在虚拟领域，通过设置限制和共享来仔细管理共享资源至关重要，仅为每台虚拟服务器的必要性能提供所需资源。不配置共享和限制，可能会导致资源耗尽，影响在相应物理硬件上运行的所有虚拟机的性能。

| VMP05 | 尽量减少虚拟机控制台的使用 |

仅在绝对必要时才授予虚拟机控制台访问权限。拥有虚拟机控制台访问权限的恶意用户，可能会在虚拟环境中造成严重破坏，因为他/她可以使用虚拟机控制台的电源管理和设备管理功能，直接关闭虚拟机。更令人担忧的是，每个虚拟机控制台都会占用服务控制台资源，因此同时打开多个虚拟机控制台，可能会耗尽所有可用的服务控制台资源，从而导致拒绝服务（DoS）。

| VMP06 | 安装前验证软件的完整性 |

在当前环境中，恶意人员将不需要的功能（如 rootkit 或其他恶意软件）添加到流行的软件分发版中，然后将修改后但看似合法的软件在公共互联网上提供下载，这并不罕见。不仅要仅从供应商网站下载软件，还要将下载软件的 SHA1 与软件供应商提供的哈希值进行验证，以验证软件下载的完整性，这一点非常重要。

| HST01 | 确保为 iSCSI 流量启用双向 CHAP 身份验证 |

不实施双向 CHAP 可能会使您面临中间人攻击的风险，该攻击可能使恶意人员窃取数据。它内置且易于实施——请充分利用 VMware 中提供的风险缓解措施。

| HST02 | 确保 CHAP 身份验证密钥的唯一性 |

不幸的是，管理员倾向于在多个主机之间共享相互身份验证密钥。如果单个主机的共享密钥被发现，则所有主机都面临风险。应遵循的良好做法是，为每个向主机进行身份验证的客户端创建唯一的共享密钥。

| HST03 | 适当掩码和分区 SAN 资源 |

分区可以帮助促进部门数据的隔离，掩码可以确保只有具有特定需求连接到 SAN 资源的虚拟机，才能首先实际看到该 SAN 资源。

| HCM01 | 不要对 ESX/ESXi 通信使用自签名证书 |

VMware 随附的自签名证书的使用，可能会大大方便那些希望执行中间人攻击的恶意人员。使用商业证书颁发机构或组织证书颁发机构（两者均具有完整的吊销功能），可以在很大程度上缓解中间人攻击的风险。

| HCM02 | 禁用托管对象浏览器 |

托管对象浏览器主要用于调试 vSphere SDK 的诊断，通常不用于常规操作。拥有托管对象浏览器访问权限的恶意人员，可能会对主机进行未经授权的更改或操作。

| HCM03 | 禁用 Web 访问（仅限 ESX） |

VMware Web 访问实现中之前发现过漏洞，而且任何 Web 界面实现本身都存在固有风险。管理虚拟机的首选方法是通过更安全的 vCenter Server 使用 vSphere Client。

| HCM04 | 确保 ESX 配置为加密所有会话 |

不加密客户端会话，会为恶意人员打开大门，使其能够实施中间人攻击，从而可能获得可用于发起进一步攻击的宝贵信息。

| HLG01 | 配置远程 syslog |

恶意人员在成功攻击后通常采取的第一步行动之一，就是删除或修改日志文件以隐藏攻击痕迹。如果攻击者已获得虚拟服务器的管理控制权，删除或修改本地存储的日志文件将是一件轻而易举的事。启用远程日志记录后，您会让攻击者更难得逞，因为他需要获得另一台服务器（syslog 服务器）的管理权限，才能修改或删除日志文件。
