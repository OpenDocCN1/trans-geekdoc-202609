
# ESXi 安全配置指南

## 日志持久化配置

ESXi 的日志存储在内存中，因此重启会擦除日志，这使得攻击者可以通过简单重启服务器来掩盖痕迹。此外，默认情况下仅存储一天的日志，在排查复杂的运营问题时可能不够充分。最佳做法是启用持久日志记录，并将日志存储在远程数据存储上。

## HLG03：配置 NTP 时间同步

在虚拟环境中，所有服务器和虚拟机之间的时间同步是必需的，这能显著简化问题排查和事件响应，并提高准确性。如果不使用时间同步，甚至可能导致你完全未意识到事件已经发生。此外，多项 VMware 操作（例如 `vMotion`）要求相关主机/客户机之间的时间准确同步，操作才能成功完成。

## HMT01：通过 CIM 硬件监控工具控制访问

必须在使用 CIM 监控工具时强制执行最小权限原则。如果以 root 或管理员权限运行的 CIM 应用程序被攻破，可能导致整个虚拟环境被完全攻陷。请记住，当攻击者攻破应用程序时，实际上获得了该应用程序的运行权限。通过降低分配给应用程序的权限级别，可以有效限制攻击者在应用程序被攻破时的能力。

## HMT02：确保正确配置 SNMP（仅限 ESXi）

ESX 支持 SNMP 版本 1、2C 和最安全的当前版本 3，而 ESXi 仅支持 SNMP 版本 1 和 2C。这两个版本的 SNMP 均不提供加密。因此，通过 ESXi（或运行非版本 3 SNMP 的 ESX）拦截未加密的 SNMP 陷阱可能导致信息泄露。ESXi 上的 SNMP 仅支持具有有限 MIB 功能的陷阱操作，这减轻了远程修改配置的风险。建议仅通过受信任路径发送 SNMP。ESXi 上的 SNMP 实现同样仅支持有限 MIB 功能中的陷阱操作。保护 SNMP 的常规注意事项（例如更改默认的 `public` 和 `private` 社区字符串）仍然适用。

## HMT03：建立并维护配置文件完整性（ESXi）

ESXi 的文件访问 API 允许直接修改以下配置文件：

- `esx.conf`
- `hostAgentConfig.xml`
- `hosts`
- `license.cfg`
- `motd`
- `openwsman.conf`
- `proxy.xml`
- `snmp.xml`
- `ssl_cert`
- `ssl_key`
- `syslog.conf`
- `vmware_config`
- `vmware_configrules`
- `vmware.lic`
- `vpxa.cfg`

修改上述文件可能导致未经授权访问主机配置及相关虚拟机。通过同时使用自动化文件完整性监控解决方案，并在变更控制程序中跟踪授权变更，可以持续验证 vSphere API 在 ESXi 中暴露的文件是否未发生未经授权的更改。

## HMT10：防止意外使用 VMsafe CPU/内存 API

为减少威胁面，如果未使用专门利用 VMsafe Network API 的产品，应将其禁用。

## HMT11：防止意外使用 VMsafe 网络 API

为减少威胁面，如果未使用专门利用 VMsafe Network API 的产品，应将其禁用。

## HCN01：确保仅授权用户可访问 DCUI

直接控制台用户界面（DCUI）是 ESXi 控制台上可用的界面，提供基本主机配置、网络设置、root 密码设置，以及重启代理和重启主机等维护操作。

应强制执行最小权限原则：仅授予那些为完成特定工作任务和职责而需要访问权限的用户访问 DCUI 的权限。

## HCN02：启用锁定模式以限制 root 访问

当 ESXi 主机通过 vCenter 管理时，启用锁定模式可以减少威胁面，防止远程 root 访问 ESXi 主机，除非通过 vSphere Client 或 vCLI 命令连接到 vCenter Server、通过 vSphere Client 或 vCLI 命令直接连接到 ESXi，或通过 DCUI 访问。

## HCN03：避免将 root 用户添加到本地组

将 root 用户添加到本地组可能会覆盖锁定模式。

## HCN04：禁用技术支持模式

登录到技术支持模式的用户可以完全控制主机。技术支持模式通常仅在 VMware 支持顾问的指导下使用，禁用它可以减少威胁面。但是，禁用后会大大降低诊断和支持主机的能力，重新启用技术支持模式可能需要重启主机。

## NAR01：确保 vSphere 管理流量位于受限网络

管理网络包括 ESX 上的服务控制台接口和 ESXi 上的管理 vmkernel 接口。将此流量与生产流量共享可能会在攻击的侦察阶段向攻击者暴露有价值的管理信息。此外，如果未经授权的用户获得网络访问权限，可能会为攻击者提供特权访问。公认的良好做法是使用独立交换机和接口或通过 VLAN 对流量进行分段。

## NAR02：确保 vMotion 流量隔离

在 vMotion 期间，虚拟机的内存内容以未加密方式发送，可能被在网络上嗅探的恶意用户暴露，从而泄露敏感或个人身份信息。vMotion 流量应使用独立交换机和接口或 VLAN 进行隔离。

## NAR03：确保基于 IP 的存储流量隔离

基于 IP 的存储通常未加密，可能被在网络上嗅探的恶意用户暴露，从而泄露敏感或个人身份信息。基于 IP 的存储流量应使用独立交换机和接口或 VLAN 进行隔离。

## NAR04：严格控制对管理网络的访问

如果攻击者未经授权访问管理网络，可将其用作进一步攻击和渗透的跳板。客户端系统不应位于管理网络上，仅应由受信任的管理员使用专用机器或仅通过 VPN 进行远程访问。
