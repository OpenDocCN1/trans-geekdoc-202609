

![](OEBPS/images/box.jpg) `Conduct Regular and Ongoing Testing`: 最后但同样重要的是定期和持续测试这一话题。至少每年对危机和业务连续性计划进行一次测试或演练是绝对必要的。组织的员工和管理层必须定期练习计划中所写的内容。定期和持续测试具有多种用途。测试有助于强化危机管理计划中上下定义的沟通渠道的重要性。测试也是识别过时的计划活动和任务、呼叫列表、清单、异地安排等的基础。最后，也是最重要的是，测试有助于培训员工并提高整体管理层和员工的意识。测试强化了对灾难发生后立即需要采取的精确措施的理解，并且如果做得当，能让每个人停下来，环顾四周，思考在危机情况下会是什么样子，以及如何最好地履行他们在帮助组织生存方面的角色。

虽然较小组织的管理者可以采取其他措施来提高整体危机管理和业务连续性规划基础设施的有效性，但考虑并深思熟虑地采纳上述主要建议将有助于显著降低灾难的潜在影响。

# Summary

老话说“鸡蛋不要放在一个篮子里”，不幸的是，这对往往没有或几乎没有选择的小型组织管理者来说非常相关。

小型组织面临的挑战很多，优先事项在其他地方，导致资源从协调的准备工作中抽离，而这些准备工作有助于确保企业的生存能力。危机管理和业务连续性规划任务往往是非正式的，或者被更紧迫的事情搁置一旁。而且，小型组织管理者似乎最不需要的就是又一项待办事项。

灾难确实会发生，而且每天都在发生，随意看一眼晨报或新闻网站就能证实这一点。通常，小型组织管理者没有充分认识到，由于缺乏相对雄厚的资金，小型组织往往比大型组织遭受的损失更大。小型组织的重要 IT 需求也往往集中化，缺乏更复杂的物理、环境和信息安全防护，使其更容易遭受突发性灾难性损失。

本章讨论了大型组织和小型组织在处理危机管理和业务连续性规划时的三个主要区别。这些区别包括管理层有必要认识到其组织相对的需求水平，以及人员配备和预算/资源可用性问题。讨论了几项建议，包括进行正式的威胁和业务影响分析、正式设立内部协调员职位，或许还要正式设立危机管理和业务连续性规划计划。还建议管理层考虑评估外部援助的需求，包括使用顾问、服务提供商和其他外包援助。建议还包括确保数据和软件备份实践尽可能可靠，并重新评估保险覆盖理念。从企业整体角度来看，管理层应更仔细地审视如何将危机管理和业务连续性规划计划相互对齐，并与整体风险管理流程对齐，最后进行定期和持续的测试，并提高意识和培训。

根据所涉及组织的规模，这些建议可能适用，也可能不适用。底线是，小型组织有很多东西需要失去，而缺乏舒适的缓冲。考虑到所有这些因素，管理层最好认真考虑这些建议。归根结底，如果你被迫把所有鸡蛋放在一个篮子里，那么你一定要非常确定地盯着那个篮子！

# 风险的代价：金融行业风险评估与信息安全的考察

![](OEBPS/images/chline.jpg)

# Seth Kinnett

自萨班斯-奥克斯利法案出台以来，公众的注意力越来越多地转向金融行业的监管话题。许多群体对金融机构采用的结果和流程有所关注：政府有监管义务，消费者越来越多地就隐私问题表达担忧。这些消费者期望公司采取措施来降低对资产和个人信息的风险。本章探讨了在金融服务公司背景下的风险评估和信息安全，包括关键考虑因素、行业差异化因素以及减轻该垂直领域中存在风险的方法。

“金融服务公司”一词将主要用于涵盖以某种方式参与证券交易的公司，例如共同基金。有必要做出这一区分，因为例如进行估值的公司，其基本关注点将与基于交易的公司不同。确实，交易过程——以及支持和促进该过程所需的系统——对健全的信息安全计划构成最大威胁，因为这些系统遭受的损失至少可能导致法律、声誉和财务问题。“银行”一词将主要指投资银行，尽管零售银行不会被排除在此讨论之外，并且在必要时会特别说明所指的银行类型。
