

对于密码实现，良好的工程要求可以在 `FIPS 140-2` 和通用准则中找到。提供密码服务的组件、子组件和完整设备应根据适当的标准进行独立评估。那些必须依赖密码服务的人很少有能力（也很少具备专业知识）来评估底层的密码系统。

# 实现

最严谨、形式化证明的密码数学，具有“完美安全性”和密码系统所期望的所有其他最佳数学特性，也可能因工程不佳而付诸东流。通过严格测试并依赖最佳算法的认证设备在投入使用时也可能失败。数学支持预期的安全功能是必要的，但不充分。此外，产品工程产生可认证的可信密码系统以保护数学的“良好性”也是必要的，但不充分。最后，密码系统的实现和操作不得导致工程产品被破坏。

实现中最重要的方面是密码密钥管理。做得好，它支持良好的工程和强大的算法。做得差，它会使其他一切都无效。密码密钥管理的若干优秀论述已出现在本手册的早期版本中 \[5\]。

# 摘要

从历史上看，当密码分析的进步发现缺陷、当新的数学方法取得进展、当计算能力提高以降低暴力攻击的工作因素成本时，密码算法可能并且已经失败。实现者需要预料到这只是密码算法生命周期的自然部分。过渡到未来算法的需求是不可避免的 \[6\]。然而，由经过适当培训的人员在认证设备中使用经过充分验证的算法，并遵循由合格评估员定期独立评估的适当安全实践，最能保护您组织在密码安全方面的投资，并确保密码安全有最好的可能性来保护依赖于它的信息资产。数学、工程和实现都在密码学中发挥着至关重要的作用。

# 密码消息语法

密码消息语法（CMS）是一种数据格式方案，通过该方案，一个数据对象可以被封装在另一个数据对象中，以应用各种密码方法来实现数据机密性、数据完整性和数据真实性。CMS 本质上是一个工具包，使设计师能够定义可用于开发消息协议的受保护数据对象。开发者随后可以创建系统来生成、处理和验证 CMS 对象。最终用户随后可以依赖消息协议来保护应用程序数据，无论其是什么。CMS 在过去二十年中不断发展，并由少数几个标准组织制定的若干标准所定义。当今许多使用的消息协议和数据保护方案都依赖于 CMS。对 CMS 的基本理解使用户和专业从业者能够理解密码学的复杂多样性及其在保护日常信息和保障系统安全方面的当前和未来重要性。

# 简介

CMS 描述了一种用于使用密码方法保护数据对象的“封装”语法。封装结构使用抽象语法记号一（`ASN.1`）或可扩展标记语言（`XML`）定义。密码方法包括加密、消息认证、数字签名以及相关的密钥管理方法。有三个主要小组在开发 CMS 标准：

![](OEBPS/images/box.jpg) RSA Data Security 开发了一系列公钥密码学标准（`PKCS`），其中包括 `PKCS #7` CMS 标准。如今，RSA 是 EMC 的安全部门。

![](OEBPS/images/box.jpg) 互联网工程任务组（`IETF`）开发了一系列征求意见稿（`RFC`）规范，其中包括 CMS 和相关文档。

认可标准委员会（`ASC`）X9 开发了若干美国国家标准，以支持金融服务行业的 CMS。`ASC X9` 由美国国家标准学会（`ANSI`）认可，以（i）为金融服务行业制定标准，（ii）作为美国（`U.S.`）技术咨询组（`TAG`）参与 ISO 技术委员会 68 金融服务，（iii）担任 ISO TC68 秘书处。

[图 23.1](#9781466508507_epub_c23_r1.htm#fig_23.1) 展示了 CMS 的发展历史。`PKCS #7` 于 20 世纪 90 年代初开发，`IETF` 在 2000 年代基本上开发了一系列连续的 CMS 规范，X9 在同一时间段内开发了若干 CMS 标准。ISO 于 2008 年后期开始开发一种 CMS 类型的标准，X9 作为美国 TAG 进行联络，但 ISO 草案最终因缺乏 ISO 成员支持而被放弃，因为支持该工作的国家数量不足。因此，美国国家标准 X9.73 进行了修订，以与当前的 `IETF` 规范 `RFC 3852` 重新对齐，包括来自 X9.96 的 XML，并纳入了被放弃的 ISO 22895 草案国际标准中所取得的工作。请注意，尽管 `RFC 4853` 是在三年后发布的，但它在存在多个数字签名时对 `RFC 3852` 提供了澄清，因此 `RFC 3852` 被视为当前的 `IETF` CMS 规范。
