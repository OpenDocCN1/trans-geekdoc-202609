虚拟化还可用于创建和运行“低交互蜜罐”，即不具有真实系统“外观和感觉”的蜜罐。

`Honeyd` 是众多使用虚拟化的蜜罐工具之一。`Honeyd` 是一种在网络上创建虚拟机的小型服务。它可以配置为运行任意服务，响应 ping 和 traceroute，看起来像是在运行某些操作系统和服务，将代理服务请求发送到其他系统，在单个平台上拥有多个 IP 地址，允许或拒绝扫描，欺骗他人使其看起来正在使用某些网络路由而实际上并非如此，并创建大量蜜网（honeynets），即用于蜜罐的虚拟网络，使网络流量看起来像是真实的。`honeyd` 使用名为 `systrace` 的功能提供沙箱，以防止攻击者利用 `honeyd` 脚本中的漏洞。

# 云计算支持

虚拟化的另一个好处是它支持云计算。对于“云计算”这一术语的确切含义，并没有普遍共识。维基百科提供了一个尽可能好的定义，将云计算定义为“通过互联网以公用事业为基础提供动态可扩展且通常是虚拟化的资源作为服务。用户无需了解、具备或控制支持他们的‘云’中的技术基础设施。”云计算和虚拟化密不可分。云服务器通常高度分布式且虚拟化，例如，Amazon Elastic Computer Cloud (`EC2`) 拥有大规模的数据中心虚拟化。虚拟化存储是另一种通常依赖虚拟化的云服务。

# 其他优势

虚拟化的其他显著优势包括故障转移功能、无需停机即可维护系统的能力、汇集计算资源的能力、拥有自定义虚拟机（每个虚拟机都作为应用程序交付容器）的能力，以及许多其他优势。

# 虚拟化相关的安全风险

虚拟化也会带来许多安全风险，其中一些风险比较严重。本节将讨论这些风险。

# 同一物理机上虚拟机之间的交互风险

安全隔离，即将程序限制在虚拟化环境中，理论上应保证虚拟机内执行的任何操作都不会干扰托管它的系统，这是虚拟化的基础。因此，当与敌对或危险程序隔离至关重要时，虚拟机已得到快速采用。然而，如果物理主机服务器的安全性受到破坏，则驻留在该特定主机服务器上的所有虚拟机和应用程序都会受到影响。此外，受损的虚拟机也可能对物理服务器造成破坏，进而可能对运行在同一机器上的所有其他虚拟机产生不利影响。

# 其他交互风险

在虚拟化环境中，交互风险往往被单纯视为基于主机（`VM`）的风险。当存在虚拟化服务器和虚拟化网络时，也会发生交互风险。在这种情况下，总风险超过了各个单独风险的总和。任何虚拟化操作系统或应用程序中的漏洞都可能成为导致虚拟化组件多次受损的薄弱环节。

# 虚拟机劫持

另一个与安全相关的风险是“虚拟机劫持”（hyperjacking），即攻击者创建并运行一个非常薄的虚拟机监控程序，从而完全控制底层操作系统。安全研究人员 Joanna Rutkowska 开发的 Blue Pill rootkit 很好地说明了这种风险可能如何表现。Rootkit 是一种木马程序，旨在向系统管理员以及其他寻找系统异常和安全漏洞的人隐藏其存在的所有证据。Blue Pill rootkit 绕过了 Vista 完整性检查过程，用于将未签名代码加载到 Vista 操作系统的内核中。该代码使用 Advanced Micro Devices (`AMD`) 的安全虚拟机（旨在增强安全性）来伪装自身以避免被检测，并成为虚拟机监控程序，在系统管理员和其他人未察觉其存在的情况下接管操作系统。

# 嗅探相关风险

虚拟环境与传统环境一样，容易受到未经授权的嗅探。例如，可以通过以特定方式配置网络接口卡来捕获网络第 2 层的数据。

# 网络防御控制可能无法按预期工作

信息安全管理人员假设已到位的网络防御控制在虚拟环境中可能无法正常工作。虚拟网络中的网络流量可能不受物理网络中常用的屏障（例如防火墙）的保护。边界安全设备通常无法看到虚拟机之间的流量，虚拟化环境中的流量流通常与传统网络环境不同（涉及同一物理机上虚拟机之间的桥接连接）。虚拟化导致对虚拟机之间流量的视图受限，这一事实加剧了这一问题。

# 虚拟化产品中的漏洞

在虚拟化软件（即使虚拟机和虚拟应用程序能够运行的软件）中已发现惊人的大量漏洞。示例包括允许未经授权的用户从虚拟机逃逸以获取物理机超级用户访问权限的漏洞、允许攻击者从来宾操作系统未经授权访问主机操作系统的漏洞、允许攻击者在 SSL 加密的远程管理会话中输入特定字符序列以获取来宾和所有主机操作系统的未经授权超级用户访问权限的漏洞，以及大量与缓冲区溢出条件相关的漏洞。

虚拟化产品中存在如此多漏洞所造成的问题，因这些产品的供应商并不总是坦诚和及时地承认和修复其产品中的漏洞而变得更加严重。近年来，以虚拟服务器中的漏洞为重点的攻击类型出现了惊人的增长。此外，由于先前讨论过的虚拟网络与传统网络之间的差异，虚拟网络中的入侵检测技术可能只能识别较低比例的攻击。缺乏对为虚拟机之间通信而创建的内部虚拟网络的可见性和控制，也使现有的安全策略执行机制失明。

# 恶意代码

黑帽社区越来越多地将注意力转向虚拟化环境中的漏洞和利用。因此，运行在虚拟化环境中的恶意代码正变得越来越复杂。先前讨论过的 Blue Pill rootkit 是最佳示例之一。创建自己的虚拟机监控程序的恶意代码（恶意软件）构成最大风险。恶意软件可以利用虚拟化产品中的漏洞，导致缓冲区溢出、篡改控制功耗的代码的能力等。此外，恶意软件作者现在可以检测虚拟机软件，并在其运行于该软件时更改恶意代码以伪装其目的。
