# 集成 IPsec

本文多次提到，IPv6 需要 IPsec。在 IPv6 中，有两个 IPsec 头部：认证头部（AH）和封装安全载荷（ESP）头部（Beijnum, 2006）。AH 保护整个头部，并提供身份验证（Beijnum, 2006）。ESP 头部“提供身份验证、加密或两者兼有”（Beijnum, 2006, 200）。重要的是，ESP 头部仅保护 ESP 扩展头部之后的数据。

作为提醒，IPv6 头部具有固定长度，因此“选项字段”无法像以前在 IPv4 中那样标记到 IP 头部中。然而，这并不排除使用扩展头部。AH 和 ESP 扩展头部是 IPsec 的一部分（Beijnum, 2006）。其他扩展头部（例如，逐跳、目的地等）位于 IPv6 头部（即，第 3 层）和 TCP 及 UDP（即，第 4 层传输层）头部之间（Beijnum, 2006）。其意义在于，扩展头部没有标准格式（Beijnum, 2006）。

# 有状态和无状态自动配置

动态主机配置协议（DHCP）“是一种通信协议，允许网络管理员集中管理和自动分配组织网络中的互联网 IP 地址”([Whatis.com](http://Whatis.com), 2008, para 1)。如果没有 DHCP，网络管理员将不得不手动为组织中的每台主机计算机配置 IP 地址，这将非常费力，并且从管理角度来看几乎是不可能的。

IPv6 最有用的方面之一是其能够自动配置自身，即使不使用有状态配置（例如 IPv6 的 DHCPv6）。IPv6 主机默认执行无状态地址自动配置，并根据邻近路由器发送的路由器通告消息中的以下字段执行有状态地址自动配置。（Microsoft, 2008, 74）

在 IPv6 中，“路由器”承担着更重要的角色和更关键的功能。无状态自动配置生效，为了获得 IP 地址，主机监听路由器的路由器通告（RA）（Beijnum, 2006）。RA 通告前 64 位（即，地址空间），对于连接到同一子网的主机，后 64 位基于 EUI-64 派生（即，MAC）值（Beijnum, 2006）。“即使在没有路由器的情况下，同一链路（即，子网）上的主机也可以自动配置自身 \[邻居发现\] 并使用链路本地地址进行通信，无需手动配置”（Microsoft, 2008, 3）。主机可以请求路由器请求，这在互联网控制消息协议（ICMP）下由 IPv6 中的 ICMPv6 支持。最后，RA 可以告知主机使用哪个路由器来访问互联网（Beijnum, 2006）。

# 重新编号

想象一下 Time Warner 收购 America Online 时，可怜的系统管理员们的处境，当时那是世界上最大的商业合并（Guinness, 2006）。人们只能想象将两个网络合并为一个网络（即，在 IPv4 下）的艰巨任务。在 IPv6 下，路由器只需停止通告其旧前缀，并简单地通告新前缀（Beijnum, 2006）。通信中断被最小化，因为新创建的会话（使用新 IP 地址的主机和路由器）以及切换后的现有通信会话被允许继续，直到现有通信会话自然终止（Beijnum, 2006）。

# IPv6 安全问题前言

IPv6 带来了多种新功能、优势以及尚未出现的未来创新。不幸的是，它仍然容易受到许多困扰 IPv4 的高层协议攻击（OSI 模型）方法。具有讽刺意味的是，IPv6 通常被认为比 IPv4 更安全，但根据前面的讨论，知情人士可以合理地认为 IPv6 可能被认为比 IPv4 不安全。然而，更明智的说法可能是 IPv6 既不比 IPv4 更安全也不比 IPv4 不安全。

“作为一个地区，亚洲控制着大约 9% 的分配 IPv4 地址，却拥有世界上超过一半的人口”（GAO, 2005, 8）。在不久的将来，由于全球化力量，IPv4 地址空间将耗尽，IPv6 将不得不得到支持。“长期解决方案是部署 IPv6。IPv6 与 IPv4 不向后兼容”（NIST, 2010, 6-1）。这里的重点不是确定 IPv4 地址空间是否会在 2011 年耗尽，而是提醒个人，同时运行两种 IP 会使相关组织在过渡过程中因运行两种协议而易受漏洞影响。

在地址空间部分，任播（一对一“最近”通信）和多播（一对多）术语被快速提及，并承诺稍后讨论相关的安全问题。请原谅这个委婉说法，但现在是时候“付账”了。任播地址不能用作源地址，并保留给路由器使用。问题是，没有定义的方法、注册或验证流程。有人可能正在冒充任播服务器（NIST, 2010）。

多播可能被用于拒绝服务攻击向量。IPv6 当前的多播实现方法未包含 IPsec 或互联网密钥交换，因此未得到完全保护（IPsec 是在两个特定点之间，如单播通信中，但由于多播的一对多通信，此概念无效）（NIST, 2010）。关于多播的担忧是，它实际上支持“足迹分析”，该内容在 IPv4 的常见攻击小标题下讨论过。多播“可以使对手识别网络上的关键资源并攻击它们”（Convery & Miller, 2004, 6）。此外，路由器和 DHCP 服务器具有站点特定地址（分别为 FF05::2 和 FF05::3）（Convery & Miller, 2004）。具体来说，通过监听多播，个人可以更容易地通过默认站点地址前缀识别关键资源。

在改进 QoS 部分讨论过的流标签，其使用存在安全问题。问题是，流标签可能被用于建立后门通道。Beijnum (2006, 153) 关于流标签值写道：“使会话易于识别，而无需深入查看数据包”。由于流标签是新的，尚不清楚路由供应商是否有统一的代码或标准，也未发现任何文档来确定是否进行了任何测试以验证任何供应商的声明（即，包括防火墙供应商检查此区域的能力）。
