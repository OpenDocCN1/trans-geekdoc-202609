

信息技术（IT）专业人员，尤其是信息系统（IS）专业人员，长期以来一直从事数据和信息的保护及访问控制工作 [5]。在本世纪，IT 和 IS 专业人员面临着接受治理理念，并在组织环境和治理结构内构建风险管理流程的挑战。这必然会影响 IT 变更管理的战术和战略规划，因为信息安全和技术实践及流程不再能孤立地制定和实施。信息技术（IT）基础设施的使用（获取、实施、维护和处置）效率的基础 [6] 已成为谨慎的 IT 风险管理，包括初始和持续的评估、分析、控制实施、审计和纠正性缓解。幸运的是，资源并不缺乏——国际标准组织的白皮书和标准文档；以及来自广泛行业类别的组织和个人的经验咨询公司（[表 16.1](#9781466508507_epub_c16_r1.htm#table_16.1) [7]）。

面对这种资源丰富的局面，IT 和 IS 专业人员的挑战实际上是如何打破历史性的孤立，将 IT 风险工作纳入组织治理结构。困难在于，尽管“每个人都了解风险管理”，但在风险及其相关术语和概念的定义上存在令人困惑甚至令人担忧的不一致。随着治理成为组织结构的一部分，业务管理群体开始为风险管理定调。不幸的是，特定标准组织的许多倡导者往往似乎假设，他们的定义和用法已被其他所有人理解和接受，而没有意识到其中的差异。大部分风险治理来自商业财务会计和审计领域，重点组织如信息系统审计与控制协会 (ISACA)（参见 [表 16.1](#9781466508507_epub_c16_r1.htm#table_16.1)）。

在制造、化工以及使用或产生有害（对人类和环境）材料的某些研究组织中，安全和物理安全组织开始在其工业环境中适当地识别应急管理和风险治理。所有组织中的 IT 和 IS 专业人员开始围绕信息保护以及重大危机后信息流程的恢复，开发负责任的流程和实践。所有这些都导致了对风险评估和管理实施的不同看法（即使只是略有不同），并导致了在解决问题方面相互冲突，甚至是冗余的努力。

IS 专业人员还面临着回应日益增长的相关概念——融合——的挑战，该概念证明并定义了与组织物理安全/安全（PS/S）单位的协作与合作 [8]。融合概念可以通过为消除障碍和在组织单位之间建立关系提供背景，为组织风险管理的整体讨论带来一些清晰度。

# 章节预览

在本章中，我将解释融合概念实际上代表了向适当的情境理解迈出的积极一步，以理解不仅 IS 和 PS/S 专业人员，而且组织的其他参与者——高管、隐私/监管专业人员、审计师、软件开发人员、IT 专业人员——在治理和风险管理中的角色和职责。我计划描述，澄清背景将如何导致对参与者的更好理解——并最终提高风险管理流程的效率和效果。我打算在本章中从信息安全的角度介绍治理和风险管理，并将探讨 IS 专业人员如何有效地为整体组织结构做出贡献。通过本章，IS 专业人员应更好地理解术语和参考框架，并能够向组织其他人员识别和描述 IS 战术和战略信息管理实践对于组织风险管理最佳效率的重要性。

为了本章的进一步讨论，我认为 IT 风险和 IS 风险高度一致，可以视为同义词，并可能频繁互换这两个概念。尽管风险本身可能是同义词，但 IS 和 IT 专业人员在整体风险管理中拥有不同但协作的职责，正如我将解释的那样。

在本章介绍之后的第一部分中，我将简要回顾风险的历史及其用法和参考框架的演变，并将展示定义中的一些冲突、风险度量的挑战，以及它们如何从 IS/IT 角度干扰组织流程。为此，我将提供解决一些误解的建议，以实现更好的组织协作，从而实现更高效的治理。本节并非旨在对整个风险行业进行评估或批评，而是试图为在 IT 中管理风险以及 IT 对组织风险管理的贡献所面临的挑战带来背景。
