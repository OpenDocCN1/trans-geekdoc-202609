

系统由许多离散的物理和逻辑项目组成。硬件、软件和设置构成了这些项目的大部分，并构成了系统的配置。对这些项目进行适当管理需要知道每个项目的位置和状态。物理项目，例如硬件，相对更容易定位和识别，因为它们是有形的。但是，在地理上分散的组织中准确跟踪成千上万件硬件并非易事。逻辑项目，例如软件和设置，很容易超过硬件组件的数量。自动化工具对于识别和跟踪所有软件组件和系统设置至关重要。但是，当存在大量未在组织内标准化的软件和/或设置时，跟踪这些项目也可能是一项艰巨的挑战。在这方面，配置管理是旨在识别和跟踪系统中每个物理和逻辑项目的位置和状态的活动。

很容易认为配置管理只是库存管理的另一个术语。事实上，配置管理也需要库存。但是，配置管理远不止是对系统硬件和软件进行库存管理。良好的库存系统根据少数属性（如序列号、制造商、尺寸，甚至可能是位置）来识别唯一项目或项目类别。库存系统的主要重点是跟踪项目或类别的数量。另一方面，配置管理超越了这种计数。全面的配置管理包括更多属性以及项目的历史记录。项目的状态，例如其特定设置，可能在组织中有所不同。例如，组织可能为工作站启用了打印后台处理程序服务，但为服务器禁用了该服务。软件组件和设置可能会频繁更改。跟踪组件的历史记录对于排查系统错误是必要的。典型的库存系统要么将更改后的项目视为新项目，要么在主要属性相同时忽略更改。配置管理包含库存管理，但它远不止于此。

系统组件的位置和状态是一个视角问题。服务器既有物理位置也有逻辑位置。软件可能驻留在特定主机上，并在每个主机的不同目录中。状态主要指可以唯一跟踪的设置。正如软件的逻辑位置可以从一台主机变到另一台主机一样，状态也可能变化。因此，在跟踪位置和状态时必须小心，以避免使配置管理过程过于复杂。

配置管理中跟踪的每个项目都称为配置项（CI）。每个 CI 都分配了一个唯一标识符，并包括描述项目的属性列表。CI 可以指特定事物或一类事物。假设 CI 指特定软件设置。此 CI 可能适用于所有服务器，也可能仅适用于某一特定服务器。CI 的属性应引用特定事物（或类别）、位置、状态和其他可区分的特征。

区分配置管理与库存管理的重要 CI 属性是版本控制。系统更改，例如安全更新，非常普遍。正如更新的软件模块通常通过版本来区分一样，更改后的 CI 也应如此。为每个 CI 使用增量版本控制方案可实现对更改的历史跟踪。CI 版本控制是配置管理的关键要素。

配置管理应广泛应用于系统管理和运营活动。除了硬件和软件之外，还有许多领域可以从配置管理中受益。典型系统开发生命周期的许多活动和产出都是组织配置管理的配置项候选项。这些领域包括以下内容：

![](OEBPS/images/box.jpg) `Requirements`: 系统根据需求存在。系统的设计受组织使命以及各种政策和标准的影响。用户的运营需求也会影响系统架构及其管理方式。系统的每个元素都应与一个或多个需求具有可追溯性。需求也会随时间变化，这可能会影响系统的各个方面。因此，应像其他硬件和软件一样跟踪需求，以支持系统治理。

![](OEBPS/images/box.jpg) `Baselines`: 构成系统的实际硬件和软件组件构成其基线。基线中的大多数配置项倾向于是一个类别。假设一个拥有 1,000 台 Windows XP 工作站的系统需要托管 calc.exe。与其为每个实例指定 1,000 个配置项，不如建立一个配置项，将其标识为适用于系统中每台 Windows XP 工作站的类别。

![](OEBPS/images/box.jpg) `Inventories`: 资产问责最好通过库存来实现。配置管理也可用于管理离散资产。库存通常识别广泛基线类别中发现的单个项目。在这种情况下，库存中的每个配置项都代表组织中的特定资产。

![](OEBPS/images/box.jpg) `Configurations`: 系统中设置的类型和数量可能非常惊人。错误的设置可能导致系统故障或被攻破。管理相关设置对于系统运行和安全至关重要。设置通常有多个值，每个值建立特定状态。此类别中的配置项通常是一个类别，因为设备之间的相同设置很常见。

![](OEBPS/images/box.jpg) `Documentation`: 大量系统运营流程需要文档。应急计划、系统备份程序、管理指南和账户管理计划只是指导系统管理所需的众多文档中的几个。此类文档也应像系统的任何其他方面一样，通过配置管理进行控制。

![](OEBPS/images/box.jpg) `Interfaces`: 图形用户界面（GUI）可能有非常特定的要求。组织可能对内部 GUI（例如网页）的布局和功能有特定需求。可用性是任何 GUI 的关键因素。用户对特定 GUI 的接受需要持续关注其设计和呈现方式。管理 GUI 需求对于高效汇聚设计、开发和用户接受是必要的。

![](OEBPS/images/box.jpg) `Data exchanges`: 应用程序通常与组织内部和外部的其他应用程序进行接口。交换可能以数据共享的形式或支持事务处理的形式进行。需要这些连接的详细信息，以确保更改能够适应且不会中断这些交换。理想情况下，所有使用的协议都应与授权使用它们的应用程序和服务相匹配。

# 变更管理

保持系统配置的最新需要有纪律的变更管理。即插即用和自动软件更新等技术使得绕过管理流程变得容易。虽然现代系统的这些自动化方面简化了我们的生活，但它们也阻碍了控制和跟踪更改的能力。除非系统配置项的更改得到适当批准和测试，否则不应进行更改。
