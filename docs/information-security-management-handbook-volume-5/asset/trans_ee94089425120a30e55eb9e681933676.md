

首席信息安全官（`CISO`）、信息安全官、信息安全总监、信息安全经理，或授予负责信息保障的个人的任何头衔，都应被视为组织信息安全的“促进者”。安全官的职责是识别风险、获取风险影响，并指导组织管理层做出明智的决策，确定应进行哪些安全投资以缓解风险。组织的业务管理层是唯一真正能够接受组织内部风险的人。如果没有一个明确定义董事会、C 级高管（首席执行官、首席信息官、首席财务官、首席运营官、首席合规官、首席技术官等）、高级管理层（业务部门副总裁）、中层管理层（总监/经理）、一线管理层（主管/组长）以及非管理层最终用户期望的信息安全治理模型，就不清楚谁实际上应该接受风险。高管每天都会接受各种风险，包括财务、运营、技术、外部及其他业务风险。通过 `CISO` 促进的安全风险评估所识别的风险，只是高级管理层必须处理的另一组风险。无论信息安全官是否清晰地传达风险，组织都会在正常业务过程中隐含地“接受”风险。因此，更好的方法是让信息安全官主动与相关各方讨论风险。

在促进的背景下，信息安全官可以被比作交响乐团指挥，将公司中所有乐器（每种乐器都有其独特的声音和产生声音的不同方法）汇聚在一起，奏出一曲统一的优美交响乐。或者，它可能听起来像三年级的小提琴组，每个部分都试图以最佳水平演奏。公认的是，第一场小学音乐会会充满尖叫声、不协调的声音，以及乐队“会随着时间的推移而变好”的认知。两个乐团都在尝试奏出同样的音乐，主要区别在于方法的复杂性和团队的经验。公司也不太不同：随着信息安全治理的成熟，它们会变得更加结构化，明确谁负责根据预定义程序执行和批准哪些活动。

信息安全官的治理角色是构建信息安全策略以满足业务需求，制定和实施信息安全政策，制定适当的管理、技术和运营控制措施，确保通过监控计划持续提供安全，并将安全控制措施的失败情况传达给高级管理层。典型的安全组织将管理安全政策和管理的功能或某些方面、业务连续性和灾难恢复、安全运营、身份和访问管理、审计/风险管理联络以及安全架构。组织可能只有少数人员在 `CISO` 职能中向业务线管理层汇报，同时有一个 IT 安全组件向首席信息官（`CIO`）汇报，或者采用所有功能向一名安全官汇报的综合模式，或其他变体。安全官使用的信息安全治理工具包括政策本身、标准操作程序、风险评估、系统安全计划、纠正行动计划、审计、日志和监控、漏洞扫描、渗透测试、安全意识以及身份管理系统等。利用这些工具进行主动规划可以识别需要加强关注以保护信息资产的领域。信息安全官必须能够将这些活动发现的当前状态和问题“翻译”成易于理解的术语，以便所面对的任何受众都能理解。所认为必要的详细程度或信息量将因管理层和技术团队以及组织内个人的层级而异。

# 安全官汇报关系

信息安全部门或其职责范围不存在“一劳永逸”的模式。安全组织应向哪里汇报的位置也在不断演变。在许多组织中，信息安全官仍然向 `CIO` 或负责组织信息技术活动的个人汇报。这是因为许多组织仍然将信息安全职能视为信息技术问题，而非核心业务问题。

或者，这种理由可能源于需要使用信息技术专业人员理解的技术语言进行沟通，而业务通常不太理解这种语言。无论放置的理由如何，将负责信息安全的个人置于信息技术组织内部可能代表利益冲突，因为 IT 部门有动力按时、在预算内并以高质量交付项目。如果安全职能向做出这些决策的个人汇报，可能会为了满足这些约束而对安全要求采取捷径。让安全职能向 `CIO` 汇报的好处是，安全部门更有可能参与 IT 部门的活动，并了解即将开展的项目和安全挑战。

一个日益增长的趋势是将安全职能视为风险管理职能，因此将其置于 IT 组织之外。这提供了更大的独立性，并将重点放在风险管理上，而不是管理用户 ID、密码重置和访问授权。将汇报关系置于 IT 组织之外，还为预期执行的安全活动引入了一套不同的制衡机制。安全职能可以向首席运营官、首席执行官、总法律顾问、内部审计、法务、合规、行政服务或信息技术以外的其他职能汇报。该职能应尽可能在组织中高层汇报，最好是向高管级别的个人汇报。这确保了向高级管理层传达正确的信息，公司员工能看到部门的适当权威，并且在做出资金决策时可以考虑公司各方面的需求。

# 安全规划

战略、战术和运营计划相互关联，每个计划都提供不同的侧重点来增强组织的安全性。规划降低了组织对安全需求采取被动反应的可能性。通过适当的规划，可以就项目是否支持长期或短期目标以及是否具有值得分配更多安全资源的优先级来做出决策。
