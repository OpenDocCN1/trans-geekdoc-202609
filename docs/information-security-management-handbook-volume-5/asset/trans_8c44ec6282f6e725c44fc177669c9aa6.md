# 制定方法

在了解组织中虚拟化的当前使用情况以及当前安全控制如何应用于虚拟化相关风险的基本问题之后，下一个良好步骤是为保护虚拟化环境制定方法。在大多数组织中，为保护虚拟环境所采用的方法是使用过去用于保护任何操作系统、网络设备或应用程序的当前配置标准和工具。虽然这种方法有一些优点，但它未能解决在同一台物理机器上运行多个平台所带来的安全影响。例如，仅仅应用用于保护物理服务器的相同控制措施，并不能为虚拟机提供足够的保护。保护虚拟机必须在虚拟机部署之前开始，理想情况下，在选择供应商和产品之前就开始，以便将安全性和可安全性纳入控制评估和选择过程。因此，首要关注点应为物理安全。如果任何人都可以走进数据中心并从任何机器上窃取磁盘驱动器，那么虚拟化环境可以拥有的所有逻辑保护都将徒劳无功。如果服务控制台没有获得强有力的物理保护，这种情况很容易发生。

# 虚拟化环境的政策和标准

虚拟化环境的政策和标准大部分不应与传统环境的政策和标准有根本不同。虚拟化环境中的职责分离、备份、审计和监控、业务连续性以及灾难恢复规划等领域，应在组织的信息安全政策中高层次地加以阐述，并在信息安全标准中以更具技术特定性的方式（包括所需参数和配置设置）加以阐述。虚拟化环境标准中还应涵盖的领域包括基线配置、特殊安全措施（包括用于管理虚拟机的控制台的物理和逻辑控制，以及针对移动虚拟机的特殊控制）、补丁管理、变更管理（特别是关于虚拟机创建）、防火墙的放置和配置、所需的入侵检测，以及可能的入侵预防机制和每种机制所需的配置，反恶意软件以及其他控制措施。最后，标准还应要求创建可信虚拟服务器构建库，并将其存放在安全的地方。

# 控制措施的选择与实施

在对信息安全政策和标准进行必要的更改、批准和实施后，应选择并实施技术控制措施。应考虑一个重要的注意事项——许多安全、系统和网络管理工具在传统计算和网络环境中使用时存在重大局限性（包括无法充分降低安全风险）。在虚拟化环境中使用它们只会加剧这些问题。

健全的控制措施选择和实施流程将有助于确保到位一套合适的控制措施。必须仔细考虑虚拟化环境的以下所有组件。

# 虚拟机操作系统

虚拟机操作系统必须根据信息安全组织为相关操作系统采用的标准进行保护。未能保护虚拟机操作系统不仅会使其被攻破变得轻而易举，还会大大增加网络被攻破的可能性。原因是，一旦被攻破，虚拟机操作系统很容易成为针对网络发起攻击的跳板。

# 虚拟机

虚拟机的安全性取决于操作系统，并应遵循信息安全实践为这些操作系统已开发的相同流程，就像每个虚拟机都是物理主机一样。从安全角度来看，虚拟机和物理服务器没有区别。除了使用服务控制台访问虚拟机文件系统（VMFS）之外，访问另一个虚拟机的唯一其他方式是通过其网络连接。因此，保护网络至关重要。因为控制台操作系统（COS）虚拟机监控程序可以访问虚拟机磁盘文件，保护服务控制台更为重要。

# 虚拟机网络

所有由外部发起的虚拟机网络连接都应由配置得当且维护良好的防火墙进行屏蔽。此外，如前所述，虚拟机中的操作系统必须得到适当保护。

# VMkernel

VMkernel 从本质上来说比虚拟化环境中的任何其他组件都更安全。由于没有公开可访问的应用程序编程接口（API），黑客或破解此关键软件的可能方式几乎为零。然而，这并不意味着无法攻破此软件。根据组织的信息安全政策和标准，定期使用供应商更新为 VMkernel 打补丁，对于避免 VMkernel 被攻破至关重要。

# 虚拟机服务器到虚拟机服务器流量和 VMkernel 流量

服务器之间的通信（即 VMware VMotion）在虚拟机服务器之间传递内存数据，以帮助管理每个虚拟机主机并促进性能负载均衡。VMkernel 网络还用于执行 NFS 挂载和 Internet 小型计算机系统接口（iSCSI）访问。数据以未加密的方式传递；因此，传递这些数据的网络访问应随时得到充分控制。

# 控制台操作系统

控制台操作系统可以访问 VMkernel 可以访问的所有内容，即硬件以及虚拟机磁盘文件的数据存储。因此，控制台操作系统是另一个关键的安全考虑因素。至少，为了限制可能的攻击源点，未用于系统和网络管理的虚拟机不应有权访问控制台操作系统网络。此外，将控制台操作系统正确放置在组织网络中是必要的。至少，应将控制台操作系统置于非非军事区（DMZ）中，以免其更容易受到外部发起的攻击。从安全角度来看，将其放置在网络中由防火墙屏蔽此类攻击的位置要好得多。

# 虚拟机部署

有许多不同的工具可用于使用控制台操作系统网络连接部署虚拟机。通常，这些工具会向目标虚拟机服务器发送未加密的信息。因此，通过确保此类流量使用强加密（例如高级加密标准加密）来保护部署网络，是任何健全的纵深防御解决方案的必要部分。
