## 3. 桌面虚拟化

a. 允许在桌面环境中共享硬件资源，使用户在使用虚拟化软件时可以在底层主机操作系统之上运行多个操作系统环境。与运行在虚拟化监控程序之上的服务器虚拟化不同，桌面虚拟化软件运行在主机操作系统之上。需要注意的是，虽然桌面虚拟化在某些方面与服务器虚拟化相似，但简单的事实是虚拟化软件运行在完整的操作系统之上，而不是更小且更高效的虚拟化监控程序之上，这使得桌面虚拟化的操作效率低于服务器虚拟化。

## 4. 存储虚拟化

a. 单个物理存储设备的抽象有效地使其位置独立，使得许多物理存储设备看起来像是一个单一的虚拟存储对象。存储虚拟化的主要好处之一是，它可以允许将虚拟存储对象轻松迁移到其他物理存储设备，而不会中断正在使用存储对象的进程对存储对象的使用。

# 当今虚拟化市场的主要参与者是谁？

在 Wikipedia 上快速查看虚拟化平台，列出了 70 多种不同的虚拟化产品（[http://en.wikipedia.org/wiki/Comparison\_of\_platform\_virtual\_machines](http://en.wikipedia.org/wiki/Comparison_of_platform_virtual_machines)）。在考虑市场份额时，三家供应商的产品明显脱颖而出：

1. VMware
2. Citrix
3. Microsoft

在作者看来，VMware 提供了当今最强大且功能最丰富的虚拟化平台。然而，Microsoft 不能简单地被排除在外，因为他们正在快速且持续地添加更多产品功能，并积极定价以获取市场份额。事实上，就在发布 Hyper-V 产品一年后，Microsoft 就声称从 VMware 那里夺取了 24% 的市场份额（[http://communities.VMware.com/blogs/VMSpotlight/2009/08/04/microsoft-claims-hyperv-has-24-virtualization-market-share](http://communities.VMware.com/blogs/VMSpotlight/2009/08/04/microsoft-claims-hyperv-has-24-virtualization-market-share)）。

出于本章的目的，我们将重点关注 VMware。这绝不是对 VMware 产品存在任何固有不安全性的反映，而是为了向虚拟化社区中最大的细分群体提供信息，而且无人能否认 VMware 在这方面显然是领导者。

# 安全顾虑是否正在阻碍虚拟化的增长？

虽然无可否认虚拟化可以为企业带来巨大的成本降低，但安全顾虑已成为其整体接受度的重大障碍。虽然虚拟化已经存在多年，但根据 Neil McDonald 来自 Gartner 的最近报告（[http://www.outlookseries.com/N6/Security/2825_Neil_MacDonald_Gartner_virtualized_workloads_deployed_insecurely_Neil_MacDonald.htm](http://www.outlookseries.com/N6/Security/2825_Neil_MacDonald_Gartner_virtualized_workloads_deployed_insecurely_Neil_MacDonald.htm)），到 2009 年底，只有 18% 的企业数据中心工作负载（本可以被虚拟化的）已被虚拟化。此外，该报告还预测，到 2012 年，该数字将增长到 50% 或更多。同时，该报告指出，到 2010 年，60% 的虚拟化服务器将比它们替换的物理服务器安全性更低。Gartner 的调查数据指出了六个具体的关注领域，总结如下：

1. 信息安全最初未参与虚拟化项目。
2. 虚拟化层被攻破可能导致所有托管工作负载被攻破。
3. 为虚拟机（VM）之间的通信创建的内部虚拟网络缺乏可见性和控制，使现有的安全策略执行机制失明。
4. 不同信任级别的工作负载被整合到单个物理服务器上，缺乏足够的隔离。
5. 对虚拟化监控程序/VMM 层和管理工具的管理访问缺乏足够的控制。
6. 网络和安全控制的职责分离可能会丧失。

# 虚拟化的固有风险

大多数虚拟化产品供应商会告诉潜在客户，他们的产品将使其本质上更安全，因为他们实际上在操作系统和底层硬件之间添加了一个隔离层。虽然这听起来很棒，但只需查看 x86 特权级别即可看到虚拟化的潜在风险（[Figure 24.1](#9781466508507_epub_c24_r1.htm#fig_24.1)）。

![](OEBPS/images/fig_24.1.jpg)

![](OEBPS/images/line-2.jpg)

**Figure 24.1 在 x86 处理器的保护环中，有 4 个特权级别，编号为 0（特权最高）到 3（特权最低）。**

在 x86 处理器的保护环中，有四个特权级别，编号为 0（特权最高）到 3（特权最低）。环 0 通常被称为主管模式，大多数内核操作系统功能（如访问内存和 I/O）在环 0 发生。环 3 通常被称为用户模式，不直接访问内存和 I/O。

无需过度简化，但考虑到保护环，需要注意的是桌面虚拟化产品通常在环 3 运行，因此特权有限，风险有限。然而，服务器虚拟化产品通常在环 0 运行，并为虚拟环境中运行的来宾操作系统提供虚拟化的环 0，以便它们可以执行操作系统功能。在环 0 运行的服务器虚拟化产品被攻破，可能会将底层内存和 I/O 暴露给恶意软件。此外，需要注意的是，如果服务器虚拟化产品被攻破，运行在服务器虚拟化产品之上的每个操作系统也可能暴露给恶意软件。

用最简单的话来说，服务器虚拟化产品中的漏洞可能会创建一种场景，其中底层内存、I/O 和运行在虚拟化产品之上的每个来宾也变得易受攻击，并面临被攻破的风险。

做出笼统的陈述，即虚拟化本身因为在硬件和操作系统之间放置了额外层而使您更安全，这显然会导致危险的虚假安全感。任何虚拟化产品都应该像企业环境中运行的任何其他应用程序一样对待，并且必须得到妥善保护。此外，虚拟化软件并没有消除或降低对运行在服务器虚拟化产品之上的操作系统以及运行在该操作系统之上的相应应用程序及其插件进行适当加固的必要性。
