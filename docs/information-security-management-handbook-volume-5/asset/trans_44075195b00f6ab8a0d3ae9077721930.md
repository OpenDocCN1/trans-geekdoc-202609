

# 其他安全和运营注意事项

官方 vSphere 强化指南是开始强化虚拟领域初始配置的好地方。但是，有几个领域超出了 vSphere 强化指南的范围：

- 虚拟机内运行的软件的安全性，例如操作系统和应用程序，或通过虚拟机网络传输的流量的安全性。
- 任何其他附加产品的安全性，例如 SRM。
- 与维护安全相关的详细操作程序，例如事件监控、审计和权限管理。指南提供了执行这些重要任务的一般领域的指导，但关于如何具体执行这些任务的细节超出了指南的范围。

有关典型 SANS 实操格式的额外宝贵安全指导，可以在 SANS 课程 `SEC577 Virtualization Security Fundamentals` 中找到。更多信息可以在 [http://www.sans.org/security-training/virtualization-security-fundamentals-3807-tid](http://www.sans.org/security-training/virtualization-security-fundamentals-3807-tid) 找到。

虽然 `SEC577 Virtualization Security Fundamentals` 课程涵盖了 vSphere 强化指南的许多建议，但它还提供了官方 vSphere 强化指南未涵盖的许多领域的见解。在作者看来，它是一个宝贵且强烈推荐的资源。

## 密码策略建议

### COP03: 为密码历史记录建立密码策略

使用和强制执行密码策略可以在很大程度上降低密码被猜测或以其他方式破解的风险。

重复重用旧密码会增加密码被猜测或破解的可能性。密码策略应通过跟踪密码历史记录来解决密码重用问题。

### COP04: 建立最大密码使用期限策略

使用控制来建立密码在更改前可以使用的时间长短，可以在很大程度上降低密码被猜测或以其他方式破解的风险。

### COP05: 建立密码更改前最少天数的密码策略

用户经常使用的一个技巧是快速多次更改新密码，以便覆盖典型的密码重用约束。这通常发生在强制要求更改密码后，用户随后快速多次更改密码并返回到他们熟悉的密码。设置密码更改前的最短时间段可以缓解此问题。

### COP06: 确保 vCenter 中的 purser 自动密码更改符合策略

`vpxuser` 密码默认每 30 天自动更改一次。请确保此策略确实符合您的密码策略要求。

## 日志配置

### COL01: 配置 syslog 日志记录

使用远程 syslog 日志记录可以减少管理负担，并降低攻击者在攻破特定机器后，通过删除或修改本地受攻破机器上的日志来轻易掩盖其踪迹的风险。

### COL02: 配置 NTP 时间同步

在作者看来，虚拟环境中所有系统之间的时间同步是必需的，并且使故障排除和事件响应变得更加容易和准确。不使用时间同步实际上可能会导致您根本无法发现事件的发生。最后，几个 VMware 操作，例如 `vMotion`，要求在相应的主机/来宾之间准确同步时间，以便操作成功完成。

## 文件系统完整性

### COH01: 分区磁盘以防止根文件系统填满

与大多数 Linux 衍生版一样，如果 ESX 上的根文件系统填满，可能会降低管理其的能力，最坏的情况是使其无响应，从而造成拒绝服务 (DoS)。

### COH03: 建立并维护文件系统完整性

监控配置文件的完整性可能是安全事件的第一个迹象。

### COH04: 确保重要文件和实用程序命令的权限未从默认值更改

文件权限应作为整体文件完整性检查的一部分，由彻底的文件完整性系统进行检查。更改文件权限可能会影响其功能，并可能导致拒绝服务 (DoS)。

## 访问控制

### COA01: 防止引导时被篡改

ESX 中的服务控制台，与大多数其他 Linux 衍生版一样，可能允许用户在引导过程中输入内核选项，例如引导至单用户模式。建议设置 grub 密码，以降低未经授权的人员在引导过程中向内核传递选项的风险。

### COA02: 要求单用户模式进行身份验证

可以通过还要求输入密码才能进入单用户模式，为 COA01 提供额外的安全层。

### COA03: 确保通过 SSH 禁用 root 访问

当用户通过 SSH 以 root 身份登录时，您根本无法审计具体是谁在发出命令或执行任务。禁用 root 登录 SSH 迫使用户先使用自己的帐户登录，创建审计跟踪，然后使用 `su` 或 `sudo` 提升其权限级别。

### COA04: 禁止控制台 root 登录

与 COA03 中的 SSH 类似，当用户使用连接的屏幕和键盘通过本地控制台以 root 身份登录时，您根本无法审计具体是谁在发出命令或执行任务。禁用 root 在本地控制台登录迫使用户先使用自己的帐户登录，创建审计跟踪，然后使用 `su` 或 `sudo` 提升其权限级别。

### COA05: 限制对 su 命令的访问

使用 `su` 命令会显著提高给定登录用户的权限级别，应仔细控制。

### COA06: 配置和使用 sudo 来控制管理访问

使用 `sudo` 实用程序可以显著提高给定登录用户的权限级别，应仔细控制。sudo 用户的配置文件可以配置为细粒度且明确地指定用户在使用 `sudo` 时可以执行哪些特权命令。
