预测过程涉及从新漏洞中获取特定信息并将其输入查询引擎，然后查询引擎处理收集的数据，以识别可能受漏洞影响或启用了特定服务的系统。

如果需要，可以针对数据库识别的系统进行有针对性的扫描，以确定问题是否为真阳性。此外，在进行额外查询或扫描环境以寻找新信息的同时，可以对已识别的系统立即激活修复措施。

无论如何，必须经常扫描环境并定期扫描，以保持当前数据的新鲜度，并使其对决策、漏洞修复和事件响应过程具有价值。

# 数据库

分析器的核心是一个高速 SQL 数据库，用于存储扫描和分析的数据。数据库需要处理预计收集的海量数据，并在需要用于分析目的时快速检索这些数据。

# 与故障单系统的接口

Remedium 是基于 Remedy Action Request 系统的故障单系统。执行扫描是要完成的工作中容易的部分。较难的部分是分析数据，这可以通过分析器在一定程度上自动化，然后修复问题。随着分析器处理报告，它会通过 Remedium 为每个需要修复的项目生成一个故障单。

# 来自系统和应用程序清单数据库的接口

分析器连接到 SAGE 数据库以获取机器信息。这些信息可以帮助路由工单，因为它识别了系统的支持级别以及谁支持它。

# 来自网络清单数据库的接口

同样，NetID 网络数据库也可以提供系统的物理位置信息。这对于识别可能对特定配置或扫描中识别的项目具有较高出现率的区域很有用。

# 摘要

预测漏洞分析的目标是帮助组织在宣布新漏洞时快速确定其风险足迹的范围。通过获取收集的清单数据以及确定机器是否可能存在漏洞的要求，组织可以快速找到其潜在受影响系统的位置。一旦知道，安全团队可以根据对组织的风险、基于清单数据、系统在网络中的位置以及系统对业务的重要性，决定首先修补哪些系统等。
