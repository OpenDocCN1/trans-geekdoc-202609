当新漏洞公开时，安全分析师可以查看有关特定漏洞或利用的已知信息，然后将其与已知系统配置文件进行比较。[表 17.1](#9781466508507_epub_c17_r1.htm#table_17.1)中显示的信息也必须可用于已知弱点或漏洞，以确定系统是否可能易受攻击。

基于已知系统集和已知漏洞要素集，安全分析师可以将两个集合合并在一起。只要两个集合之间存在共同点，就存在潜在易受攻击的系统。

举例有助于说明预测性漏洞分析的概念。考虑针对微软操作系统的最新远程过程调用漏洞利用，如 CERT 建议 CA-2003-19 所报告。建议文本中说：

“受影响的系统

Microsoft Windows NT 4.0

Microsoft Windows NT 4.0 终端服务版

Microsoft Windows 2000

Microsoft Windows XP

Microsoft Windows Server 2003

…

已知漏洞利用针对 TCP 端口 135，并在成功攻破的主机上创建特权后门命令行界面。某些版本的漏洞利用使用 TCP 端口 4444 作为后门，其他版本使用入侵者在运行时指定的 TCP 端口号。”

根据 CERT 建议中的信息，[^(\*)](#9781466508507_epub_c17_r1.htm#ch17-ftn4) 安全分析师可以在预测模型中建立查询，以确定哪些系统可能面临风险。可以说，这不是最佳示例，因为大多数微软 Windows 操作系统平台都易受攻击。但是，环境中的系统可能已经应用了最新补丁，使其免受此特定攻击的影响。此外，由于可见于互联网的系统可能是更容易攻击的目标，安全分析师可以将搜索范围缩小到仅针对这些特定系统。结果是一份可能易受漏洞利用攻击并可能需要关注的系统列表。如果企业必须对系统进行漏洞评估，漏洞利用可能已经发生，给企业造成财务、生产力以及潜在声誉损失。

虽然许多安全专业人员基于其对配置的了解对环境进行表面评估，但预测性漏洞评估的真正解决方案和实施是使用自动化工具来收集和管理企业将积累的大量数据。

预测性漏洞评估解决方案必须考虑企业网络的所有要素：

![](OEBPS/images/box.jpg)    研发系统

![](OEBPS/images/box.jpg)    关键任务应用系统

![](OEBPS/images/box.jpg)    未受网络安全工具保护的互联网上的系统

前一列表中的每个系统都有其自身特定且独特的漏洞问题。

大多数组织实施特定的网络安全控制，以减轻将企业网络连接到互联网所带来的风险。此类控制包括路由器过滤器、防火墙、非军事区（DMZ）网络、服务网络以及其他用于执行协议和数据包分析与过滤的设备。最终结果是尽量减少入侵者获取组织系统、网络和数据访问权限的可能攻击向量数量。

许多组织的高级管理层也认为，一旦这些对策到位，他们就“受到保护”，免受攻击。然而，诸如“纵深防御”等安全管理策略表明，端节点——系统——的安全和维护是整体网络安全的重要元素。

# 手动预测分析

全球安全专业人员每天都在不知不觉中进行手动预测分析。当从 NIPC 或 CERT™ 等报告机构收到报告时，安全分析师会审查报告并确定必须采取什么行动来最大限度地减少漏洞的威胁。但是，安全分析师必须针对企业处理一般性和总体行动。这是因为安全分析师无法了解每台机器的复杂性、其补丁级别、系统上运行的应用程序，或该系统缓解漏洞的任何其他控制措施。手动方法基本上遵循 [图 17.2](#9781466508507_epub_c17_r1.htm#fig_17.2) 中所示的过程。

使用此手动流程，除非为企业中的每台机器和应用程序实例重复该过程，否则安全分析师只能处理一般性问题。因此，安全分析师被迫做出笼统的陈述，包括“修补每个系统”、“切断网络的那一部分”以及“实施这些过滤器以阻止该流量”，而不知道这些行动是否合理。在许多情况下，自动化预测分析系统的最终结果确实可能导致在普遍漏洞情况下出现相同的指令。但是，在其他情况下，自动化系统可能能够依靠现有信息和已实施的安全控制来识别特定问题区域。

# 自动化预测分析

另一方面，自动化预测分析是可能的且高效的。如 [第 3 章](#9781466508507_epub_c03_r1.htm) 中讨论的，有大量数据需要收集和整理，但安全分析师最终可以快速提出关于与整个企业相关的深远行动的建议，并识别在其他情况下可能易受攻击的特定系统。
