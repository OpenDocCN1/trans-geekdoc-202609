

虽然我通常关注价值链的消费端，但我知道，对于商业实体而言，事情必须从商业角度讲得通。如果从供应商的角度来看，基于开放标准的结构化漏洞信息格式使他们能够快速从多个来源消费数据，从而潜在地发挥其所长。这种对问题中更多琐碎方面的商品化，随后允许重新调整和集中资源于产品功能，这可能会加快技术创新的步伐。

消费者，尤其是不精通安全领域的从业者，有着不同的观点，而标准内容格式对他们来说，额外的好处是揭示了通常晦涩难懂的漏洞评估过程。同时，对产品功能和能力进行真正客观的比较变得更加实际。如前所述，这些倡议的社区方面至关重要，因此，一份文档完善的开放标准格式为社区提供了他们需要的信息，以便能够理解问题的细节，并确定特定产品是如何运作的。它还通过允许从业者生成他们自己的检查并用任何允许此类操作的产品来解释这些检查，来鼓励参与。测试结果变得更加确定性，这反过来允许在产品给出不同结果时进行更线性的故障排除。这反过来又消除了消费者使局面公平化的负担，使他们能够将更多资源用于选择功能最能满足其需求的产品，而较少用于哪个产品能正确检测漏洞这一更困难的问题。

OVAL 功能已被定义为创建逻辑功能分组，以便为试图合规的组织提供最大灵活性。这确保只使用对产品最有意义的 OVAL 部分，而不需要参与者试图一次性消化一份庞大而繁琐的功能列表。它还使 OVAL 能够被更广泛的安全产品所使用/消费，从而增强渗透率。OVAL 功能映射到用例，以确认其在整个实施中的有效性，以确保行业内更大的互操作性。对功能的清晰定义还使社区成员能够更好地理解任何“合规”产品如何使用 OVAL 语言，这反过来帮助他们正确满足业务需求。

# OVAL 功能

*创作工具*—供应商可以使用创作工具来协助开发提供给客户的漏洞内容。最终用户可以使用创作工具来协助开发他们自己的检查。

*定义仓库*—确定漏洞存在所需的逻辑可以在 OVAL 定义中表达，该定义是机器可读的，并在漏洞被发现后尽快与原始安全公告一起发布在定义仓库中。以结构化格式提供漏洞检测信息，允许最终用户更快地评估其系统并根据需要采取行动。

*定义评估器*—实现定义评估器功能的产品可以从许多定义仓库中消费漏洞检查。这将显著减少供应商内容团队的规模，并减少将漏洞检查发布给最终用户所需的时间。此外，最终用户可以向定义评估器提供自定义开发的 OVAL 定义。

*系统特征生成器*—基于系统详细信息生成有效 OVAL 系统特征文件的产品。

*结果消费者*—接受 OVAL 结果文档作为输入的产品，并向用户显示结果，或使用结果执行某些操作。OVAL 主要关注金标准测试，这些测试可以确定指定的软件漏洞、配置问题、程序或补丁是否存在于系统上。[^(\*)](#9781466508507_epub_c06_r1.htm#ch6-ftn25)

高级摘要包括以下内容：“存在易受攻击的软件”，它说明了特定的操作系统 (OS)、包含漏洞的文件名、应用程序版本和补丁状态；以及“易受攻击的配置”，它指示服务是否运行、特定的配置设置和变通方案。定义的详细部分提供了用于检查系统特征以指示存在易受攻击软件的逻辑，以及用于指示存在易受攻击配置的配置属性。每个定义由唯一标识符区分。这些标识符称为 `OVAL-IDs`，并使用标准格式。值得注意的是，`OVAL-ID` 格式扩展到 OVAL 语言中所有全球可重用组件，包括定义、对象、状态、测试和变量。

# 格式

`oval:Organization DNS Name:ID Type:ID Value`

*DNS 名称*

语法：`org.mitre.oval`；

*ID 类型表示 ID 被应用的实体*

可接受值：`def` - 定义，`obj` - 对象，`ste` - 状态，`tst` - 测试，或 `var` - 变量)；

*ID 值是一个整数，它是其前面的 DNS 名称和 ID 类型对所独有的*

例如，`oval:org.mitre.oval:def:1115`。[^†](#9781466508507_epub_c06_r1.htm#ch6-ftn26)

那么这些部分如何相互补充？通用漏洞和披露 (CVE) 是一份出版物，为已知的信息安全漏洞和暴露提供通用名称。CVE 使用通用名称，以便更容易在 CVE 兼容的独立网络安全数据库和工具之间共享数据。OVAL 仓库是 CVE 兼容的。这意味着 OVAL 实际上使用 CVE 列表中公开已知的漏洞作为其漏洞定义的基础。同样，社区参与至关重要，他们（OVAL 仓库社区）是实际针对这些漏洞、配置问题和补丁编写定义的人，这些定义随后被提交并在发布前接受公众评论和审查。以下是 OVAL 定义类及其简短定义，随后是发布在 MITRE 网站上的一个示例用例。还包含了链接。

# OVAL 定义类

*OVAL 漏洞定义*—用于确定系统上是否存在漏洞的测试。

*OVAL 合规性定义*—用于确定系统的配置设置是否符合安全策略的测试。

*OVAL 清单定义*—用于确定特定软件是否已安装在系统上的测试。

*OVAL 补丁定义*—用于确定特定补丁是否适合系统的测试。[^(\*)](#9781466508507_epub_c06_r1.htm#ch6-ftn27)
