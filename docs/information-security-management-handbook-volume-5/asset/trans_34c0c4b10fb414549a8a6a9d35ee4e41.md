视频也分为实时视频和预录制视频。实时视频显然对延迟敏感，服务质量（QoS）对于维护实时视频流的完整性非常重要。在大多数情况下，传输通常使用 UDP（尽力而为）。预录制视频不受延迟的不利影响，录制视频流的回顾可以安排或临时进行。通常，传输基于 TCP，录制设备的位置对于了解信息应从哪里检索非常重要。

*性能和存储注意事项*：在处理视频性能时，分辨率和帧率等参数直接影响带宽和存储需求。例如，如果我们考虑双流等视频采集实践，其中需要促进本地和远程的实时观看，那么本地实时观看最好使用高分辨率和帧率，而远程观看可以根据可用带宽调整为较低的帧率。此外，特别是对于捕获视频流的存储，主要有以下两种方法。

![](OEBPS/images/box.jpg) *集中式存储*：集中式存储通常部署在单个环境受控的设施中，靠近提供监控和存储系统技术支持和管理的人员。通常，这些集中式存储模型提供的优势是可能降低运营成本，因为视频只存储在一个位置。但是，为了将视频传输到其他位置，或从多个位置收集视频到中央存储设施，WAN 链路上可能会有更多视频（数据）流动。

![](OEBPS/images/box.jpg) *分布式存储*：视频监控流的分布式存储模型将存储定位在事件发生的地方，并靠近可以实时监控和响应事件的本地监控团队。可通过使用多个较小的系统来实现可扩展性，并且没有单点故障。分布式存储还减少了 LAN 和 WAN 链路上的带宽需求，但也存在规模经济等缺点——使用多个较小系统时，每小时存储成本可能更高。此外，由于需要维护更多设备，整体运营成本可能更高。

**多播：** 简要回顾如下：

![](OEBPS/images/box.jpg) *单播*：一个源地址与一个目标主机地址之间的通信。

![](OEBPS/images/box.jpg) *广播*：从一个主机地址发出的通信，通常发送到网络段上的所有主机或广播目标地址。

![](OEBPS/images/box.jpg) *多播*：一台主机发送每个数据包的一个副本到一个特殊地址，然后由几个有兴趣接收此信息的主机使用。接收主机是指定多播组的成员，可以动态加入或离开组，可以是一个或多个组的成员，并且可以位于网络上的任何位置。

多播通常对于 IP 视频监控应用很有用，因为可以实现更高的效率。例如，通常会观察到较低的 CPU 利用率，因为发送方和接收方只接收请求的数据。显然，与复制多个流相比，网络利用率是最优的。但是，多播的性质依赖于 UDP 而不是 TCP 进行传输，因此可能会发生丢包，并且通常预期会发生丢包，因为没有内置的收据机制或拥塞避免机制。

*服务质量和网络设计原则*：QoS 是一项关键技术，必须采用该技术来维护 IP 视频监控的完整性和有效性。在 IP 网络中使用 QoS 时，系统管理员可以优先保护视频监控流量，使其免受网络中所有其他类型流量的影响。此外，正确部署 QoS 可防止服务降级事件，如丢包、延迟和抖动，这些事件代表了流量拥塞管理不善的影响，通常会导致视频质量差，有时甚至会完全丢失视频。让我们考虑这些拥塞事件对 IP 视频监控的一些影响。

![](OEBPS/images/box.jpg) *延迟*：延迟度量代表编码、传输、缓冲和解码视频所需的时间。对于云台/俯仰/变焦（PTZ）摄像机，这种延迟敏感性可能更为关键，因为它们会移动。一个流行的最佳实践指标是将总端到端延迟优化到小于 500 毫秒，编码和解码最好在 250 毫秒以下，为 LAN 传输留出 1–50 毫秒，为 WAN 传输留出 100–150 毫秒。

![](OEBPS/images/box.jpg) *抖动*：表示为延迟变化，考虑给定视频监控流中 IP 数据包的端到端延迟差异。数据包可能会超过或未能利用可用的缓冲区空间，影响播放质量。这种效应可能导致解码器缓冲区中存储更多帧，可能重新排序帧序列并引入延迟，并可能导致数据包丢失。建议尽可能将抖动保持在 10 毫秒以下。

IP 视频监控流量的 QoS 实现需要分类、标记、排队和调度机制。接入层定义了网络的边缘，即入口点，流量必须在此处进行分类和标记，以便在架构中进行进一步处理。边缘设备可能能够依赖可配置的差分服务代码点（DiffServ Code Point，或 DSCP）标记，这些标记源自终端设备本身，即视频监控摄像机。接入层交换机随后配置为信任这些标记并在入口时保留它们。

在查看实际的分类和标记时，标记数据包的首选方法是服务类别（CoS）标记，它在 OSI 模型的第 2 层执行，以及差分服务代码点（DSCP）标记，它在第 3 层执行。让我们简要检查第 2 层的 CoS 标记（[图 33.4](#9781466508507_epub_c33_r1.htm#fig_33.4)）。

在这里，我们看到信息被写入服务类型（ToS）字节。ToS 字节的三个最高有效位称为 IP 优先级（IPP）。ToS 字节的六个最高有效位称为 DSCP，剩余两位留给流量控制。IPP 值定义了八个标记级别，有些人认为这过于限制，更喜欢 6 位/64 值的 DSCP 模型。
