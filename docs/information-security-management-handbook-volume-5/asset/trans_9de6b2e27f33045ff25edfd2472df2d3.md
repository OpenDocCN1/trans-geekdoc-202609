

在云供应商（如 Amazon）中，弹性计算云 `EC2` 管理员无法访问客户实例，也无法登录到来宾操作系统（OS）。`EC2` 管理员若有业务需求，必须使用其个人加密强度高的安全外壳（SSH）密钥才能访问主机。所有此类访问均会被记录并定期审计。虽然简单存储服务（S3）中的静态数据默认未加密，但用户可以在将数据上传到 Amazon S3 之前对其进行加密，以防止任何未经授权的第三方访问或篡改数据。

# 网络安全

在 SaaS 部署模型中，敏感数据从企业获取，由 SaaS 应用程序处理，并存储在 SaaS 供应商端。所有通过网络传输的数据都需要得到保护，以防止敏感信息泄露。这涉及使用强大的网络流量加密技术，例如安全套接层（SSL）和传输层安全（TLS）协议，以确保安全。

以 Amazon Web Services（AWS）为例，网络层可针对传统网络安全问题（例如中间人（MITM）攻击、IP 欺骗、端口扫描、数据包嗅探等）提供显著保护。为了实现最大安全性，Amazon S3 可通过 SSL 加密端点访问。这些加密端点既可从互联网访问，也可从 Amazon EC2 内部访问，确保数据在 AWS 内部以及与 AWS 外部来源之间传输时均安全。

# 法规合规性

SaaS 部署需要定期评估其是否符合法规和行业标准。SAS 70 标准包括数据中心和服务提供商的物理及边界安全操作程序。对敏感数据的访问、存储和处理需要受到仔细控制，并受 ISO-27001、《萨班斯-奥克斯利法案》（SOX）、《格拉姆-莱奇-布利利法案》（GLBA）、《健康保险可移植性与责任法案》（HIPAA）等法规，以及支付卡行业数据安全标准（PCI-DSS）等行业标准的约束。

数据隐私已成为另一重大挑战。不同国家对数据如何保护和存储有各自的隐私法规。当一个国家的企业数据存储在另一个国家的数据中心时，可能会导致冲突。

# 数据隔离

在成熟的多租户 SaaS 架构中，应用程序实例和数据存储可能在多个企业之间共享。这使 SaaS 供应商能够更高效地利用资源，并有助于降低成本。同时，需要采取足够的安全检查，以确保数据安全，并防止其他租户的用户未经授权访问某个租户的数据。这涉及对数据存储和应用程序进行加固，以确保数据隔离。

如果 SaaS 应用程序部署在第三方云供应商处，则需要采取额外的防护措施，以确保应用程序租户的数据不可被其他应用程序访问。

以 Amazon 为例，S3 应用程序编程接口（API）提供桶级和对象级访问控制，默认仅允许桶和/或对象创建者进行经过身份验证的访问。写入和删除权限由与桶关联的访问控制列表（ACL）控制。修改桶 ACL 的权限本身也由 ACL 控制，默认仅限创建者访问。因此，客户可以完全控制谁有权访问其数据。Amazon S3 访问权限可基于 AWS 账户 ID、DevPay 产品 ID 授予，或向所有人开放。

# 可用性

SaaS 应用程序需要确保为企业提供全天候服务。这涉及在应用程序和基础架构层面进行架构变更，以增加可扩展性和高可用性。需要采用多层架构，并由负载均衡的应用程序实例场支持，这些实例运行在数量可变的服务器上。应用程序需要从根本上构建对硬件/软件故障以及拒绝服务攻击的恢复能力。

同时，还需要为任何未计划的紧急情况制定适当的业务连续性（BC）和灾难恢复（DR）行动计划。这对于确保企业数据安全和最大限度减少企业停机时间至关重要。

以 Amazon 为例，AWS API 端点托管在与支持 Amazon.com 零售网站相同的互联网级、世界级基础架构上。使用标准分布式拒绝服务（DDoS）缓解技术，例如 SYN Cookie 和连接限制。为了进一步缓解潜在 DDoS 攻击的影响，Amazon 维护的内部带宽超过其供应商提供的互联网带宽。

# 备份

SaaS 供应商需要确保所有敏感企业数据定期备份，以便在发生灾难时能够快速恢复。同时，建议使用强大的加密方案来保护备份数据，以防止敏感信息意外泄露。

以 Amazon 等云供应商为例，S3 中的静态数据默认未加密。用户需要单独对其数据和备份进行加密，以防止未经授权的第三方访问或篡改。

# 身份管理（IdM）和登录流程

SaaS 供应商可以使用以下任何一种模型来支持身份管理和登录服务。

## 独立 IdM 堆栈

SaaS 供应商提供完整的身份管理和登录服务堆栈。与用户账户、密码等相关的所有信息均完全由 SaaS 供应商端维护。

## 凭据同步

SaaS 供应商支持在企业和 SaaS 应用程序之间复制用户账户信息和凭据。用户账户信息的创建由企业边界内的每个租户单独完成，以符合其法规要求。相关的用户账户信息部分会复制到 SaaS 供应商，以提供登录和访问控制功能。身份验证在 SaaS 供应商端使用复制的凭据进行。

## 联合 IdM

包括凭据在内的完整用户账户信息由每个租户独立管理和存储。用户身份验证在企业边界内进行。用户身份以及某些用户属性会按需通过联合身份传播到 SaaS 供应商，以允许登录和访问控制。

# 安全产品工程

产品供应商总是急于赶上市场发布截止日期。因此，产品安全性往往被赋予较低的优先级。这可能导致易受安全漏洞影响的有缺陷的软件。众所周知，由于安全漏洞导致的敏感数据泄露可能会给企业造成重大财务损失，并使 SaaS 供应商面临潜在的责任问题以及信誉受损。
