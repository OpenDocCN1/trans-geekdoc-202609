

白名单显然最适合对端点配置和使用具有成熟控制的环境。当最终用户被允许控制自己系统上安装的内容时，其配置将偏离原始部署定义。其中一些偏差相对无害（例如向网络浏览器添加有效的搜索栏），而另一些则更危险（免费屏幕保护程序，谁想要呢？）。无论如何，它们都会增加白名单解决方案的复杂性和难度，无论是在部署期间还是部署后立即。在这样的环境中，用户行为需要发生根本性转变。标准用户登录不得被允许更改端点策略配置。如果可以，那么任何执行的恶意软件都将在该用户的上下文中执行，因此将被允许更改端点。这完全抵消了白名单的意义，并使其完全无用。即使对于高级用户，他们可以（或出于业务原因需要）被信任安装新应用程序的能力，也需要一个备用登录供其使用，以便他们确切地知道何时（更重要的是，何时不是）正在将新的已批准可执行文件添加到其桌面配置中。值得注意的是，这种方法与大多数基于文件的白名单配合良好，但不适用于基于调用的系统。

# 部署白名单时的挑战

白名单的部署可以提供关于环境当前状态的非凡洞察，因为与预期标准的偏差几乎总是在令人惊讶的地方被发现。因此，在推出过程中的异常处理过程中，必须区分无害的（但未记录的）可执行文件和恶意的可执行文件，否则执行推出的人员将简单地将任何病毒或特洛伊木马与其他将被允许在网络上存在的应用程序归为一类。这种方法在具有标准桌面构建的环境中效果最好，尤其是在最终用户没有本地管理员权限的环境中，原因显而易见。应对现有有效应用程序的附加组件（如浏览器，既包含良好的也包含不良的搜索栏和助手，还包含 Flash 等附加组件，在任何环境中都会存在多个版本）进行核算。应在推出期间决定是暂时接受旧版本还是强制更新将成为正常操作程序。

另一方面，如果策略将为每个系统自动生成，则需要事先确保每个系统都没有恶意内容。计划事后手动检查策略以寻找任何看起来异常的内容很诱人；这种方法注定会失败。基于文件的白名单策略至少会有数千个条目；每个 `.exe`、每个 `.dll`、每个驱动程序都会列在那里。检查这样的策略会让人迅速意识到自己对驱动任何桌面或服务器的底层软件了解多么少，而且根本不可能有人类方式能以任何程度的把握发现恶意文件。查看基于调用的白名单策略时情况更糟，因为你看到的不是文件列表，而是特定细粒度行为列表。未来，可能会出现分析工具来确定多个系统之间的差异，以找出特定形式桌面的共同标准是什么和不是什么，但在此之前，系统必须在自动生成白名单策略之前被证明是干净的。显然，鉴于其他反恶意软件方法的不足，这对于已经使用一段时间的端点（特别是桌面）来说是一个挑战。因此，在新系统推出、切换到虚拟桌面/瘦客户端或建立/实施标准核心桌面部署期间部署白名单有一个额外的好处。在这些情况下，端点是从“已知良好”映像或定义中新部署的，可以假设其不含有害内容。但是，在这种情况下，必须更加小心以确保部署得到妥善规划，否则白名单可能会在推出和初始测试期间造成复杂情况（或被错误地归咎于源于其他原因的问题）。尽管如此，这只是用一种保证（确保策略生成前端点是干净的）换取另一种保证（规划一个干净且得到良好支持的白名单推出），而后者形式的保证无论如何都应该以相当程度的方式执行。

# 部署后白名单面临的挑战

一旦白名单解决方案完全部署，活动将转向维护解决方案，这包含四件事。一，端点上的策略将随时间变化，因为新应用程序被部署，现有应用程序被更新/修补。二，围绕白名单解决方案的流程和程序将需要随着用户行为和权限的例外情况以及特定业务目的的特殊要求被发现而加以完善。（关于这一点将在后面详述。）三，必须对白名单解决方案的中央管理点进行更新，并且要以保持解决方案连续性的方式进行。四，还必须对端点代理进行更新。白名单是一项相对较新的技术，因此供应商倾向于进行频繁且有效的改进，导致一年内有许多软件更新。更重要的是，这些更新提供了显著的改进，由供应商客户群的观察和经验所驱动。

端点上的策略将出于多种原因需要更新，但最频繁的变化将由应用程序和操作系统的补丁引起。至少，“补丁星期二”将导致许多更改，因为基于 Windows 的设备上的 `.dlls` 和 `.exes` 被替换。对于基于文件的白名单，需要有一种方法来识别更改的来源并将其识别为可信来源。对于大多数应用程序，这可以通过识别正在实施补丁的服务（当使用自动补丁时）或使用有权更改白名单策略的凭据进行补丁来完成。第一种方法通常被称为“可信代理”，而第二种方法被称为“可信用户”。对于基于调用的白名单，应用程序行为的变化必须被列举并添加到端点策略中，然后才能部署补丁，或者此类变化必须由白名单供应商提前提供（他们已为其客户群完成了指纹识别）。第一种方法耗时且必须在补丁的正常测试周期之前进行（从而延长了补丁周期），而第二种方法使环境面临供应商在指纹识别方面出错的风险，或者受制于与供应商测试系统之间的任何细微差异。这是基于文件的白名单比基于调用的白名单被更快接受的另一个原因。
