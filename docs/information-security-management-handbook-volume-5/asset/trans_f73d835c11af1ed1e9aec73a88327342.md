

RFID 读取器通常通过模块化驱动程序与中间件连接，这很像 Windows 使用设备驱动程序与显卡通信。这样可以在不修改中间件的情况下，使用不同的读取器与中间件配合。除了事件处理，中间件还处理不同类型的用户界面。通常会提供一个用于系统管理的用户界面，例如用于修改事件传递所经过的一系列过滤器。还会有允许普通用户访问系统并使用它的用户界面。例如，在超市配送中心，会有一个提供当前库存水平信息的用户界面。

中间件还与实现应用程序业务逻辑的其他软件系统通信。以超市为例，超市 RFID 系统很可能连接到库存管理系统，该系统会在库存耗尽前从供应商处订购新库存。在考虑更广泛的 RFID 架构时，会想到新的安全风险和应对措施：

# 后台的标签携带攻击

可以预见，通过存储在标签上的信息，对后台发起攻击，这一点最近由几名荷兰学生证明。基本上有三种 RFID 恶意软件，按实现复杂度递增排列如下：

1. `RFID exploits`：就像其他软件一样，RFID 系统容易受到缓冲区溢出、代码插入和 SQL 注入的攻击。

2. `RFID worms`：蠕虫基本上是一种会下载并执行远程恶意软件的 RFID 漏洞利用。蠕虫可以通过网络或通过标签传播。

3. `RFID viruses`：RFID 病毒始于标签上的恶意内容。当标签被读取时，这会启动一个恶意 SQL 查询，从而干扰后台数据库。尽管此类攻击尚未在实践中发生，但这种威胁不能排除。

# 网关接口的滥用

未经授权的个人可能会滥用网关的用户界面，以攻击过滤器的完整性并误导产品管理系统。

# 驱动程序损坏

RFID 读取器用于与中间件通信的驱动程序可能会被损坏。这可以通过修改合法读取器的驱动程序，或者用带有损坏驱动程序的假读取器替换合法读取器来实现。损坏的驱动程序可用于攻击和误导网关。

# 攻击读取器-网关通信

读取器与网关之间的通信可能会被窃听或修改。

# 标签的安全措施

# 防止未经授权修改标签数据（内容和 ID）的安全措施

防止标签数据被修改的一个明显安全措施是使用只读标签，因为未经授权的修改在本质上是不可能的。另一种有效措施（也出于数据管理的原因被推荐）是将除 ID 之外的所有数据转移到后端。某些类型的标签配备了身份验证方法（例如 ISO-9798 标准），通过该方法，标签可以对读取器进行身份验证，这样只有授权的读取器才能修改标签内容。

# 停用的安全措施

可以通过使用身份验证方法（如果可用）来防止未经授权应用删除命令或杀死命令。

# 物理破坏的安全措施

防止标签物理破坏的应对措施是，在标签与被标记物品之间建立紧密的机械连接，使得在不损坏物品的情况下难以破坏标签。为了防止主动标签的电池耗尽，可以在标签中实现睡眠模式。

# 标签分离的安全措施

防止标签与被标记物品分离的应对措施是，在标签与被标记物品之间建立紧密的机械连接，以确保移除标签也会损坏产品。对于主动标签，可以设想一种报警功能：传感器确定标签已被操纵，并在标签进入读取器范围时立即将报警传输到读取器。对于高价值物品，一个选择是手动检查标签是否附着在正确的物品上。

# 无线接口的安全措施

# 防止窃听的安全措施

减少窃听影响的有效措施是将所有数据转移到后端。更高级的标签有一个模块来加密与读取器的通信，这也防止了窃听。此类高级标签无法被入侵者读取，并且仍可用于合法用途。另一种措施是设计 RFID 系统，使标签在足够小的范围内使用，刚好足够合法读取器使用（从而排除一类未经授权的读取器）。

# 防止阻断的安全措施

没有技术措施可以防止使用阻断标签，但一个解决方案是在业务标准条款和条件中禁止其使用。

# 防止干扰的安全措施

可以通过执行随机测量或使用永久安装的场强探测器来检测干扰发射器。

# 防止中继攻击的安全措施

防止中继攻击的一种方法是在标签未使用时对其进行屏蔽，例如，将带有标签的卡片放入类似法拉第笼的容器中。另一种方法是要求用户执行额外操作（按按钮、输入 PIN 码或使用指纹）来激活带有标签的卡片，尽管这种解决方案消除了非接触式系统的一些便利性。

# 读取器的安全措施

# 防止读取器 ID 伪造的安全措施

为了防止读取器伪造其 ID 以获取未经授权的标签访问权限，可以使用身份验证方法（如果标签可用）来对读取器向标签进行身份验证。当读取器在身份验证过程中需要访问后端（例如，以检索加密密钥）时，此风险可以进一步降低。请注意，这些措施旨在确保即将与标签通信的读取器的完整性。对于屏蔽等措施（防止未经授权的读取器通信），请参阅“防止窃听的安全措施”。

# RFID 系统其他部分的安全措施

# 防止后台标签携带攻击的安全措施

为了避免此类攻击，应由读取器检查标签的内容，并应采取常规安全措施来保护网关。防止 RFID 病毒的典型应对措施是改进网关中的软件，使其能够区分常规标签 ID 和 SQL 查询，从而防止这些攻击进入数据库。

# 防止网关接口滥用的安全措施

为了防止此类攻击，用户界面应提供某种身份验证机制，这样只有授权用户才能访问网关。另一种措施是将网关和用户界面放在物理受保护的房间中，这样只有有权进入该房间的授权员工才能访问用户界面。

# 防止驱动程序损坏的安全措施

解决此问题的一个可能方案是仅使用经过签名的驱动程序，即每个合法驱动程序都应经过数字签名，以便网关可以检查通信读取器是否包含合法驱动程序。使用驱动程序使得不同的读取器可以用于与网关通信。从安全角度来看，应鼓励使用不同的读取器，因为攻击可能特定于一种读取器类型或一种驱动程序类型，因此类型多样化可以降低可能攻击的影响。

# 防止攻击读取器-网关通信的安全措施

读取器与网关之间的通信可能会被窃听或修改。
