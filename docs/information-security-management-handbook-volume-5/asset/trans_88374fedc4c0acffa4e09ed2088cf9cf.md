# 扫描管理器

扫描管理器提供大部分后端处理，并能够管理多个漏洞扫描器和数据收集点。扫描从扫描管理器排队，作业根据扫描管理器控制文件中的配置分发到可用的扫描器。扫描可以配置为定期运行，并具有额外功能，可针对特定目标系统提供临时扫描和分析。扫描完成后，扫描管理器接受数据，处理作业以完成扫描，并对传入数据执行所需的任何处理，以将其标准化为数据库格式。最后，扫描管理器将数据上传到数据库中进行分析（[图 17.5](#9781466508507_epub_c17_r1.htm#fig_17.5)）。

![](OEBPS/images/fig_17.5.jpg)

![](OEBPS/images/line-2.jpg)

**图 17.5 扫描管理器。**

扫描管理器是一个软件控制器，接受扫描请求，将其分发到各个扫描器，监控设备，并接受生成的输出。扫描管理器还接收扫描输出，将其标准化为数据库格式，并将数据上传到数据库。

# 网络、主机和应用程序漏洞扫描器

预测漏洞分析需要两件事：了解当前环境和了解漏洞。由于大多数安全团队使用漏洞扫描器定期进行网络漏洞评估，因此将此数据纳入分析非常重要。

扫描器技术面临的很大挑战是将扫描器的数据转换为机器可读格式。能否做到这一点取决于所涉及的扫描器。理想情况下，扫描引擎将数据发送回扫描管理器以进行进一步处理（[图 17.6](#9781466508507_epub_c17_r1.htm#fig_17.6)）。

# 分析器

当扫描管理器接收到扫描数据时，数据会上传到数据库，并向分析器引擎发送命令以启动对传入数据的分析。分析器采取的操作是可配置的。这些操作包括：

![](OEBPS/images/box.jpg) 如果这是给定主机的新漏洞，将其分类为新漏洞并打开故障单进行处理。

![](OEBPS/images/box.jpg) 如果这是未修复的漏洞且故障单已打开，则提高故障单的严重级别。

![](OEBPS/images/box.jpg) 生成系统特定、区域特定、风险特定和趋势报告。

分析器的多功能性和收集的数据种类使得分析问题的数量和种类随时间改进（[图 17.7](#9781466508507_epub_c17_r1.htm#fig_17.7)）。

![](OEBPS/images/fig_17.7.jpg)

![](OEBPS/images/line-2.jpg)

**图 17.7 分析器。**

在扫描管理器将新数据加载到数据库后，启动分析器。使用提供的参数，使用配置的规则集对新导入的数据进行分析。规则根据传入数据定义要采取的操作。例如，如果扫描的系统存在以前从未为此系统创建过故障单的新漏洞，则从服务器应用程序清单（如果是服务器）中提取相应的系统数据，并从网络清单数据库中提取相关子网信息。然后使用这些数据在企业帮助台系统中创建故障单以进行修复。如果问题已有打开的故障单，则故障单的严重级别提高一级。

按问题而非纯粹按系统进行跟踪，意味着在趋势分析和识别环境中的一致性问题方面可以实现更高的粒度。
