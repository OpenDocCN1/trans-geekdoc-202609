

组织或个人愿意接受的风险水平各不相同。由于任何连接到互联网的 IT 系统都无法做到绝对安全，因此总会存在某种形式的风险、威胁或漏洞暴露。只要个人了解具体情况和风险，就可以做出知情且负责任的决策。本节将讨论几种常见的缓解策略，以应对先前讨论过的安全问题（绝非旨在穷尽所有策略）。

在先前讨论的三种过渡过程（即 DSTM、隧道或翻译）中，DSTM 或“双栈”是过渡到 IPv6 时首选的方法（Convery & Miller, 2004）。建议阻止所有自动隧道服务，因为隧道会绕过整个网络安全边界防御且难以检测。如果使用隧道，则建议使用 `6to4` 静态路由。这使网络管理员能够在保持出站和入站安全配置策略的同时，与端点建立信任（Convery & Miller, 2004）。如果使用隧道，强烈建议使用 DMZ 在中立区域通过有状态检测来检查流量，而不是允许隧道简单地终止于关键资产并绕过防火墙。此外，建议在原生 IPv4 网络的防火墙上阻止以下端口：

- `Port 47`（即 GRE）
- `Port 41`（即 6 over 4）
- `Port 3544`（即 Teredo）
- 阻止所有 UDP 流量（DNS 端口 `53` 除外）
- 仅对授权静态隧道的目标端点进行出站过滤

# 路由/协议建议

路由器特别容易受到攻击。以下是建议执行的操作列表（Convery & Miller, 2004），用于配置路由器：

1. 对 BGP 和 IS-IS 使用身份验证。
2. 使用 IPsec 保护协议（AH & ESP）。
3. 使用 IPv6 跃点限制（将同一子网上的内部主机设置为使用 255，防止域外的 SNMP 被伪造）。
4. 筛选 ICMPv6（阻止入站互联网流量的回显和回显应答）。
5. 允许下列 ICMPv6 流量（如果运行 IPv6 并需要使用功能）。

   a. ICMPv6 类型 1 代码 0：无路由到目标
   b. ICMPv6 类型 3：时间超时
   c. ICMPv6 类型 128 和类型 129：回显请求和回显应答（内部到边界路由器）
   d. ICMPv6 类型 2：数据包过大，用于路径 MTU 发现功能
   e. ICMPv6 类型 4：参数问题——这是向 IPv6 节点发送信息性消息所必需的
   f. ICMP 类型 130-132：多播侦听器消息
   g. ICMPv6 类型 133/134：路由器请求和路由器通告
   h. ICMPv6 类型 135/136：邻居请求和邻居通告

6. 入站过滤多播并检查源身份验证（通过 AH）（Convery & Smith, 2004）。同时过滤 SYN 和 ACK 位清除的入站 TCP 头部（Beijnum, 2006）。无法从外部建立到内部的 TCP 会话，这些会话将由内部边界路由器发起（Beijnum, 2006）。
7. 阻止任播地址，除非用于 DNS 或 NTP 目的，然后使用 IPsec 和 AH 进行过滤。
8. 丢弃小于 1280 的片段，最后一位除外。原因是 IPv6 的最小 MTU 大小为 1280 位，此问题在本文前文中未涉及（Convery & Miller, 2004）。
9. 出站过滤内部本地链路或站点特定地址，防止其离开网络边界前往互联网（Convery & Smith, 2004）。
10. 使用 IPsec 保护协议，并在目标隧道末端使用 IDS 监控流量，并使用 DMZ 开放流量以供检查。

IPv4 中存在的许多应用程序威胁在 IPv6 中也存在（即，现有策略、补丁管理、加固配置等）。使用主机和网络 IDS 对 IPv6 至关重要，尽管作者目前不知晓任何适用于 IPv6 的主机 IDS 软件。网络管理员应采用最佳实践，例如为主机请求使用代理（例如 Apache 2.0 作为 Web 代理 \[Beijnum, 2006\]）和有状态检测防火墙。此外，网络管理员应使用最小权限原则，并确定哪些节点需要“全球单播地址”（即，与互联网通信），以便所有其他节点分配站点本地地址或链路本地地址（即，子网）（Convery & Smith, 2004）。最后，应对所有 IT 资产（是的，这包括软件）进行清点，包括支持每个资产所需的特定协议。然后，个人可以简单地仅使用支持业务需求所需的那些协议。

# 提供培训

如果到目前为止还不明显，在执行任何 IPv6 过渡之前，强烈建议网络管理员和安全管理人员接受 IPv6 培训。IPv6 引入了许多新的变化和挑战。为了理解这些挑战、变化和优势，用户必须了解该技术及其局限性，以便妥善支持组织。

# 软硬件支持建议

IPv6 的应用程序和硬件支持最多只能说是“零星”的。本文研究发现，传统的流行 IPv4 网络监控工具，HP 的“Openview”和 Aprisma 的“Spectrum”，不支持 SNMPv3，管理路由器的唯一方法是远程使用安全外壳（Gunsch & Beech, 2005）。Windows 2003 Server Active Directory 与 IPv6 不兼容（即，允许主机注册到 Active Directory 域）（Gunsch & Beech, 2005）。DNS 和 DHCPv6 至今仍未完全解决。在寻找支持 IPv6 的 IDS 时，收到了相互冲突的信息。

# 推荐的拟议实施

除非组织计划将某些信息放在可通过 IPv6 访问的 Web 服务器上，否则在 DNS 和一些额外的网络监控工具进一步成熟以支持业务运营之前，不建议继续推进 IPv6 过渡。Windows 2003 Server 不支持 Active Directory，而要运行 Exchange 2003，则需要 Active Directory 才能工作。Windows Vista、7 和 Server 2008 默认启用双 TCP/IP 通信栈（Microsoft, 2008）。在进行额外研究以确定配置管理和风险（例如，Windows Server 2008 目前正在接受通用标准测试），以及行业提供一些 IA 工具来验证某些推荐设置（例如，过滤出站互联网流量）之前，目前不建议推进 IPv6 迁移。遵循美国联邦政府的其余部分，为未来做计划，继续购买支持 IPv6 的产品，并继续禁用 IPv4 是明智之举。“当前 Windows 操作系统缺乏支持 IPv6 网络的许多基本功能。许多网络硬件设备可以支持基本的 IPv6 操作，但缺乏管理和安全等功能”（Gunsch & Beech, 2005, 4）。除非个人有幸在“早期采用者”组织工作（即，运行 Windows 7 和/或 Server 2008，后者仍未完成其通用标准测试），否则可以安全地假设 Gunsch 和 Beech 的工作仍然相关且有效。
