

**23.** `Breach`: 未经授权访问并获取未加密且未编辑的包含个人信息的记录或数据的事件，其中个人信息的非法使用已经发生或合理可能发生，或会对消费者造成实质性伤害风险。

此定义不涉及对组件的任何量化，包括资产估值。换句话说，“`breach`”是负面结果的实际发生。对于政府目的（以及 IT 和 IS）而言，“`risk`”必然是一种具有负面（而非偶尔为正面）后果的活动。

总结，我建议针对 IS/IT 语境下 `risk` 的最合适定义可从定义 22 简化为：

**24.** `Risk` 是与信息资产相关的货币损失的概率。

这个简单的定义确实突显了衡量 `risk` 的固有问题：它是一门不精确的科学！由于威胁的（不断增加的）概率、针对漏洞的控制或对策的不可预测可靠性，以及为资产分配价值和为其替换分配成本的挑战，要对组件产生任何精确测量，进而对 `risk` 本身进行精确测量，可能性极低。Donn Parker（2006）在其主要结论中表达了我的困境：

“无论多么精密……`risk` 评估方法论，……都没有足够有效的频率和影响数据来使结果有效。”

对 `risk` 组件的测量最好被视为不精确且相对的，尤其是在尝试在组织内部或组织之间进行比较时。

# 协作式风险管理

“*风险管理的精髓在于最大化我们对结果有一定控制的领域，同时最小化我们对结果完全没有控制且因果关系对我们隐藏的领域。*”（P. L. Bernstein, 1998, 197，作者强调）

经典的 `risk` 管理流程一直是由高层授权小组主导的集中式工作，负责从商业角度记录 `risks`，从业务单元收集数据，随时间汇编一份摘要文件，识别 `risks` 和活跃控制，并就未来几个月缓解控制提出建议。过去十年的挑战将这一流程推向了聚光灯下，更加关注管理数据（以及管理不善的责任）的责任。该流程面临着年度频率的要求，往往导致大型组织全年几乎不间断地进行 `risk` 管理流程。许多人质疑此类努力的必要性或整体效益 \[27\]。

我们确实生活在这样一个世界：组织资产对组织的长期生存至关重要，技术持续存在缺陷或不完善，个人和组织之间的完全信任是不完整的（甚至是危险的）。鉴于日益增长的保护组织财务数据免受欺诈以及保护个人可识别数据（尤其是医疗数据）的需求，管理围绕业务流程底层数据的 `risks` 的需求显而易见。这使得高效的 `risk` 管理成为强制性要求。为了实现这一点，我建议采用协作流程，而非自上而下的流程。协作式 `risk` 管理概念的灵感来自本节开头引用的 Bernstein 的话。Bernstein 实际上是在谈论关注组织责任并将外部因素置于次要地位的需求。然而，我认为该陈述在组织内部解决 `risk` 问题时非常有意义，因为协作者之间可以建立“链接”。在经典的自上而下方案中，位于中心的单元（例如，`risk` 管理办公室）推动整个流程，为评估其他单元中的“`risks`”规定一个共同的框架和背景，生成披露组织各个层级“`risks`”的报告。结果是一套可比较的文件，但代价是时间和效率存疑。

在协作方案中，区别在于，尽管基于高管的单元可能推动工作——制定计划和流程——但每个其他业务单元都可以以情境化的方式为 `risk` 组件的测量做出贡献，从而可能减少冗余并提高效率。这就是每个组织单元“最大化我们对结果有一定控制的领域，同时最小化我们对结果完全没有控制的领域”的地方。“结果”是组织的治理和 `risk` 管理态势。引入协作概念的背景始于组织的人为因素。

# 人为因素

信息无疑是最重要的组织资源，是经济健康的基础。尽管组织销售产品和/或服务，但没有信息资源，就不会有任何东西被创造或销售。尽管信息至关重要，但人类仍然是任何组织最重要的资源。人类收集、解释、存储和利用信息，以生产组织的产品或服务。人类还将服务或产品传达给适当的市场，并完成使经济增长成为可能的交易。在组织单元内，人类对 `risk` 管理流程的贡献各不相同，从做出支出决策的高管到实施技术解决方案的专家，以及介于两者之间的所有人，他们基于高管领导的决策，利用手头的技术资源和信息，对产品和服务做出嵌套的商业决策。

人类也是威胁和漏洞最主要的来源。在内部，意外和故意的行为可能通过合法且授权的路径利用信息资源。合法的外部人类活动可能成为获取组织数据和信息的非法路径。日益危险的互联网“威胁空间”背后每个威胁都有一个人类。信息的物理或技术保护中的漏洞可能源于结构或基础设施设计中的人为错误，或源于在建立结构和基础设施时的人为遗漏或作为。协作式 `risk` 管理工作的终极挑战是认识到人为因素在 `risk` 组件的原因和解决方案中的作用。

# 组织责任

`risk` 管理的责任（与 IS 管理一样）遍布整个组织：从上到下。每个单元，以及单元中的每个工人，都有责任通过在单元内采取适当措施并与其他单元协作，以实现适当治理的完整结果，从而降低 `risk`（作为资产财务损失的可能性）。

每个组织可能对以下单元有不同的名称，并且根据规模，某些单元可能会合并或以其他方式重新定位。每个单元都有责任为保护信息和数据做出贡献。组织高管单元启动流程。
