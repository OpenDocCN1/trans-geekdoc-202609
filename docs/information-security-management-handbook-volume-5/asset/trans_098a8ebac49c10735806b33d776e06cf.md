我建议，这一概念对于 IT 或 IS 风险来说是有问题的。当历史上单一事件的风险概念被抽象地看待时，选择单一事件的结果只能有两种后果：积极或消极（成功或失败）。如上所述，历史风险评估是试图确定消极结果的概率。如果给定的结果只能有两种后果，那么一种的概率就是另一种的反概率，因此追求成功和失败的概率是多余的。

尽管如此，这一定义在一般商业风险背景下是有意义的，尤其是当它与 SWOT 概念相关联时。从严格的项目管理角度来看，将任何商业评估工作或重大决策（其结果可能是积极或消极的）放在同一项目管理框架下是有意义的，从而在一段时间内提供一致性和可比性。此外，在所有业务流程的广度范围内，可以设想某个特定的流程、决策或冒险可能有许多可能的成功或不成功的结果，因此确定所有可能的成功和失败是很重要的。这让人想起伯恩斯坦（上文）描述的关于投资商船航行的原始风险概念，希望获得积极、成功的回报，同时通过购买保险来保护可能的损失。然而，就衡量或评估结果而言，有人可能会认为每个单独的结果都与特定的成功-失败比率相关联，因此在对潜在结果进行逐个评估时，上述的冗余论证同样适用。

# 信息安全风险

随着企业对 IT 解决方案的依赖度越来越高，商业风险和风险管理的概念与实践开始被应用于 IT 资源的管理（参见上文 [表 16.1](#9781466508507_epub_c16_r1.htm#table_16.1) 中的几个来源，例如 ISACA、ITGI）。在过去二十年中，IT 风险管理受到了越来越多的关注，随着各行各业为 Y2K 做准备的工作逐渐平息以及对金融欺诈的应对激增，这一领域愈发受到重视。在这个新世纪，IT 和 IS 专业人员沮丧地目睹了网络威胁 \[25\] 的急剧增加，而保护资源的能力（以及不幸的是，意愿）却滞后于此。近在眼前的是医疗信息共享 \[26\] 的迫在眉睫的期望，这将带来加强的法规，以惩罚个人医疗信息的丢失或泄露，并对数据保护进行适当的加强审查。这些活动凸显了 IT 和 IS 流程之间的紧密关系，虽然它们通常被视为不同甚至相互竞争的责任领域，但实际上是互补的，尤其是在风险管理方面。几个重要的国际标准组织已为 IT 和 IS 风险管理制作了文档和实施细节（参见 [表 16.1](#9781466508507_epub_c16_r1.htm#table_16.1)）。随着风险范围在 IT 及其各种 IT 子流程（例如，信息风险、应用程序风险、连续性风险、访问风险）中扩大，风险的定义继续演变；尽管这些概念源于面向业务的风险管理部门，可能与 IT 风险没有直接关系。

正如我上面所描述的，风险显然不是一个独立的术语，而是一个基于概率、不确定性、背景、选择和结果的测量或评估的*派生*概念。与其他历史商业风险概念相关，IT 领域的风险是在 IT 管理技术和基础设施的*背景*下，并继续考虑*概率*和*选择*。虽然一般商业风险描述也包括商业决策背景下的“威胁”和“漏洞”概念，但很明显，这一对概念最优且明确地描述了 IT 风险。

在 IS 和 IT 中，“威胁”和“漏洞”是在*提供对数据和信息的保护和控制访问*的背景下理解的（如上所述）。IS 威胁显然已与源自烦扰性探索并演变为出于金钱利益窃取数据的敌对基于互联网的恶意软件工具相关联。对组织物理结构的其他威胁也很重要，因为它们影响组织信息的存储库。IS 漏洞可以与组织网络和基础设施的开放性相关联，这些开放性源于遗漏错误以及安装和管理不善。网络和基础设施加固方案针对完整的网络，而不仅仅是包含私人信息的特定组件。关于资产价值的决策由组织的高层管理层做出，超出了 IT 部门的范围，除了了解技术资源的更换成本之外。对威胁概率的评估也必须考虑攻击者（伯恩斯坦 \[1998\] 描述的“他人的意图”）。随着黑市价值的增加，基于身份的信息是一个突出的目标。

我确实建议，上述定义（19）包含中性或可能积极的结果，最多只是对追求最大效率的 IT 风险评估和管理的一种干扰。简单地说，在 IS/IT 环境中评估风险仅涉及防止信息资产的损失（直接推断财务损失）。重述公式 2：

`20.` 后果是威胁渗透漏洞影响特定资产的结果（好或坏）。

对后果的这一定义本质上与许多对风险本身的定义相同，如重述公式 1 所示：

`21.` 风险是威胁渗透漏洞影响特定资产的结果。
