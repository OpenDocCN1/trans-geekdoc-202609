

虚拟化存储带来了另一组风险，其中“数据混杂”是最严重的风险之一。数据混杂是指硬盘包含不同组织的数据，以至于一个扇区可能存储公司 A 的数据，而相邻扇区可能存储该公司竞争对手的数据。此外，还存在允许恶意虚拟机访问其他虚拟机所使用磁盘空间的漏洞。

# 拒绝服务相关风险

拒绝服务攻击是虚拟化环境中另一大风险来源。拒绝服务相关风险尤其令人担忧，因为多个虚拟机通常运行在单台物理机上。如果针对该物理机的拒绝服务攻击成功，所有虚拟机都将不可用。多个虚拟机之间共享 IP 地址会增加网络流量泛滥攻击成功的可能性。某主流虚拟化产品中的一个漏洞允许客户操作系统上的恶意用户在主机和客户操作系统上都导致拒绝服务。

# 物理安全风险

物理盗窃或物理损坏托管多个虚拟机的硬件可能会造成灾难性后果。与传统计算环境（一个操作系统运行在一台物理机上）不同，托管多个虚拟机和/或虚拟化应用程序的物理机丢失可能会严重扰乱业务和其他运营。

# 补丁障碍

在许多虚拟化产品中，虚拟机状态变化不断发生。某一时刻在线的虚拟机可能很快离线，然后在某个时间点再次上线。补丁管理工具无法对离线虚拟机打补丁。此外，虚拟机克隆可能导致补丁管理工具不知情的虚拟机。结果是虚拟机在补丁方面无法保持最新状态。

# 虚拟机迁移风险

虚拟机迁移（即将虚拟机从一台物理机移动到另一台物理机）会引入多个漏洞。尽管最根本的问题是许多虚拟化产品缺乏固有的迁移安全机制，但中间人（MITM）攻击（攻击者能够在虚拟机迁移期间捕获两台物理机之间的流量）是一个特别令人担忧的问题。此外，任何在迁移期间能够访问虚拟机的人都可能完全访问虚拟机所处的任何状态。

# 时间同步相关风险

虚拟机之间的时间同步是一个潜在的重大安全问题。时钟漂移在非虚拟化环境中可能是一个重大问题。在虚拟化环境中，虚拟机用于计时的定时器滴答可能会延迟、突然一次性全部送达，或者完全丢失。虚拟机时钟漂移加上正常时钟漂移可能导致任务（包括安全任务）在错误的时间运行、日志条目的时间错误，以及登录限制（例如，日期/时间限制）无法按预期工作。

# 物理设备控制

虚拟化层允许每个单独的虚拟机直接或间接控制计算系统上的物理设备，例如 CD-ROM。此功能可以为每个虚拟机配置，并且通常可以在虚拟机运行时对其进行更改。如果在启动过程中有多个虚拟机请求访问设备，其余虚拟机可能会进入休眠状态，直到第一个虚拟机释放设备，从而不必要地延迟启动过程。

# 机制缺乏统一性

虚拟化环境通常以极大的多样性为特征，这可能会干扰 IT 标准化、变更控制和合规性工作。例如，考虑 Java 小程序环境中的虚拟化。虽然 Java 小程序通常作为网页的一部分运行，但它们可以下载并在本地作为文件独立于沙箱限制运行。沙箱也不总是按预期工作。例如，小程序可以将执行它们的计算机上的信息发送到其他网络连接的系统，从而大大增加存储数据和程序未经授权披露或被盗的风险。

# 风险缓解方法

考虑到前面提到的所有因素和漏洞，确定利用安全虚拟化的最佳和最安全的方法可能令人望而生畏。那么，使用虚拟化的组织如何缓解虚拟化相关风险呢？与信息安全中的其他一切一样，风险必须与收益进行权衡。从安全风险角度来看，在 Macintosh 上使用 Parallels 在虚拟机环境中运行 Windows 应用程序通常是非常合理的，因为收益远大于风险。在教学环境中，运行具有已知漏洞的虚拟机来展示真实攻击者攻击系统有多容易以及执行授予攻击者对目标系统完全控制权的程序需要多少技能是完全可以接受的，但在主流 IT 运营环境中则不可接受。在恶意代码研究中，分析风险收益比并不像看起来那么容易。恶意代码 `can` 逃出虚拟机并破坏物理机的操作系统。攻击者随后可以开始构建能够逃出隔离环境的恶意代码。因此，现实地分析虚拟化环境中可能出现的风险，并避免对虚拟化产生虚假的安全感，是极其紧迫的。

购买更多冗余硬件并在共享硬件平台上运行多个虚拟机的组织，也需要对驻留在单台物理机上的特定类型服务器格外谨慎。例如，将防火墙、入侵检测系统、公共 Web 服务器和数据库服务器全部放在一台共享物理机上是个坏主意。在虚拟机世界中，如果一个虚拟机被攻破，同一台物理机上的所有虚拟机通常都更容易被攻破。事实上，在这个假设的案例中，攻破多个虚拟机会更容易，因为每个虚拟机使用的硬件都在同一平台上。即使所有虚拟机对攻击都同样安全，风险仍然会升级，因为虚拟机可以相互通信而无需通过网络层传递信息。结论是，谨慎对待所使用的架构以及在同一物理平台上混合的虚拟机是明智的。

最后，如果组织拥有承载不同分类信息（例如，专有信息和非专有信息）的气隙网络，那么为了使用户更容易访问这两类信息而将存储这些信息的机器迁移到虚拟化环境，从风险管理的角度来看是非常不明智的。使用 KVM（键盘、视频和鼠标）切换器会好得多。

# 保护虚拟化环境

保护虚拟化环境，尤其是虚拟机，必须在虚拟机部署之前开始，理想情况下是在选择供应商和产品之前。原因是安全性和可安全性必须纳入评估和选择过程；否则，虚拟化环境中的安全性必须事后补救，这可能不仅导致未识别的风险，而且随着时间的推移还会导致实际困难和成本不断上升。部署前应询问并回答的问题包括以下内容：
