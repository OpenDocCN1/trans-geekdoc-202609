# 13.3.2 Phonetic algorithms for privacy preserving matching

A phonetic algorithm is an algorithm that maps a word to its phonetic equivalent. Such methods have been broadly used in the past for supporting approximate matching on names [28]. Their operation is quite straightforward: for each word to be encoded, rules for grouping similar sounds are applied, resulting in a reduced character string stands for the pronunciation of the respective word. For instance, for the Soundex algorithm, this reduction consists of a capital letter followed by three digits. For example, word "Cooper", in Soundex is converted into C160.

An interesting property of all phonetic codes is that of information suppression. That is, phonetic code comprises a lossy representation of its input. This lossy representation usually contains a string of a shorter length compared to the input string and more. As a result, the same output string may be derived from different input strings. For instance, the string "Copper" also has the same Soundex code with "Cooper," i.e., C160. Thus, phonetic encoding algorithms do not provide one-to-one mappings, and it is impossible to determine the input of the encoding algorithm from its output.

This information suppression property makes phonetic algorithms appropriate for approximate matching as it provides fault tolerance against typographical errors. As mentioned with our example above, "Copper" could be the result of an error when typing "Cooper" yields the same phonetic code. Thus, a matching comparing the phonetic codes instead of the original strings would yield a match. Note that in this case, no distance or similarity measure is required. The problem of approximate matching between the original strings is reduced to performing exact matching between their phonetic encodings. An advantage of this property is that one does not have to calibrate a distance measure by setting appropriate thresholds.
