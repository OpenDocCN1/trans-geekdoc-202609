To validate the benefits brought by exploiting temporal information and spatial smoothing based on the spatial pyramid, we compare our model with simplified versions of ST-SAGE.

ST-SAGE1 is the first simplified version of the ST-SAGE model, and it does not consider the temporal information. This means that $o^{native}$ and $o^{tourist}$ in this version are $|R| \times |T|$ vectors. For each user activity, the topic index $z$ is sampled according to the equation used in (9.3). This simplified version is equal to the Geo-Sage model proposed in [28].

```
$P(z_{u,j}|S_{u,j},u_{u,j},o^{0}_{u,j},o^{native}_{u,j},o^{tourist}_{u,j}) = P(z_{u,j}|u_{u,j}) + (1-S_{u,j}) \times o^{native}_{u,j} + S_{u,j} \times o^{tourist}_{u,j}$
```

ST-SAGES2 is the second simplified version, and it models the temporal information without omitting the proposed spatial pyramid. More specifically, the topic index $z$ is sampled according to the following equation:

```
$P(z_{u,j}|S_{u,j},u_{u,j},o^{0}_{u,j},o^{native}_{u,j},o^{tourist}_{u,j}) = P(z_{u,j}|u_{u,j}) + (1-S_{u,j}) \times o^{native}_{u,j} + S_{u,j} \times o^{tourist}_{u,j}$
```

ST-SAGE3 is the third simplified version of ST-SAGE which does not exploit the geographical correlation in the spatial pyramid. Thus, the model cannot deal with the informed temporal native preference and temporal tourist preference for location $l$ at time $t$ are not reliable when there are few or even no activity records in the corresponding region.

# 9.5.1 Evaluation methods

We aim to evaluate the effectiveness and efficiency of the proposed ST-SAGE. For the efficiency part, both the model training and the online recommendation efficiency are to be evaluated.

Recommendation effectiveness. Since our ST-SAGE model is designed for hometown recommendation and out-of-town recommendation, we evaluate the recommendation effectiveness of our model under each of the scenarios. Given a user profile containing a collection of user activities, we divide these activities into a training set and a test set. For the hometown recommendation scenario, we randomly select 30% of the activity records occurring at the hometown as the test set, and use the remaining activity records as the training set. Similarly, for the scenario of outoftown recommendation, we randomly select 30% of the activity records generated by the user he/she travels out of town as the test set and use the remaining records as the training set. To decide whether an activity record occurs in his/her hometown elsewhere, we measure the location distance between the user's hometown and the spatial item (e.g., $|l_u - l_i|$). If the distance is greater than 100 km, we assume the activity occurs when the user is out-of-town. The threshold $d = 100$ km is selected because a distance of around 100 km is the radius of “human reach,” which takes 1–2 h to drive.
