## 9.3.4 Spatial smoothing

To combat the data-sparsity problem when considering the temporal native preferences and temporal tourist preferences, we adopt a quad tree structure called spatial pyramid, proposed in [13], to partition and index the corresponding geographic area. The spatial pyramid is constructed by partitioning locations into spatial regions of varying sizes at hierarchies. More specifically, the spatial pyramid decomposes the space into H levels. Level 0 has only one grid cell. For a given level $h$, the space is partitioned into four grid cells of each area. Thus, the space is partitioned recursively into numerous cells at different levels with different granularity. The graphical representation of the spatial pyramid is shown in Figure 9.2.

The proposed spatial pyramid structure can encode one important assumption in spatial data mining. The assumption is that everything is related to everything else, but nearby things are more related than distant things and has been proposed in [37] as the first law of geography also known as the "spatial autocorrelation." The spatial pyramid structure can encode this law in an effective manner. Specifically, each location $l$ in the spatial pyramid can be represented by a path from the root to its corresponding leaf node. A vector is used to describe the path, $(l_1, l_2, ..., l_h, ..., l_l)$, where $l_i$ is a grid at level $i$ that contains the location $l$. The proximity between two locations can be computed with the vector representation of locations. The basic idea is that, if two locations in the spatial pyramid share more ancestors, then these two locations are more proximate.

If user activity data at location $l$ and time $t$ are very sparse, the temporal native preference $\theta_{l}^{native}$ and the temporal tourist preference $\theta_{l}^{tourist}$ may not be estimated accurately. To address this issue, we exploit geographical correlation to enhance the prior knowledge about the model parameters $\theta_{l}^{native}$ and $\theta_{l}^{tourist}$. Intuitively, if two locations $l$ and $l'$ have a proximate geographical distance, their associated $\theta_{l,j}^{native}$ and $\theta_{l',j}^{native}$ should be similar to each other. Similarly, this intuition can also be applied to the temporal tourist preferences $\theta_{l,t}^{tourist}$ and $\theta_{l',t}^{tourist}$. As a result, given a location $l$ and time $t$, we propose an additive framework [18,19] to compute temporal native preference $\theta_{l,t}^{native}$ and tourist preference $\theta_{l,t}^{tourist}$ based on the path vertex representation. Specifically, given a location $l$, its native preference and tourist preference at time $t$ are represented as follows:

$$\theta_{l,t}^{native} = \sum_{h=1}^{H} \theta_{h,t}^{native}, \quad \theta_{l,t}^{tourist} = \sum_{h=1}^{H} \theta_{h,t}^{tourist} \quad (9.14)$$

According to both equations, the temporal native preferences and the temporal tourist preferences of a location depend on all of its ancestors up to the root. The advantage of this representation method is three-fold. First, this representation method is able to integrate the geographical correlation into our ST-SAGE by enabling neighboring locations to share similar preferences as desired (i.e., preferences are smoothed over the spatial pyramid). Second, this method is able to solve the data-sparsity problem, as if there are few or activities at a location, we can still infer its preference by its ancestors. Once temporal native preferences and tourist preferences for each level are learned, this modeling makes the switch between various granularity fast and convenient by changing the lowest level in the model without retraining the parameters.

9.3 demonstrates a detailed application scenario of ST-SAGE where the input consists of four elements: the current location, the current time, the number of the recommendations and the scale of the target region (e.g., zoom in/out on Google Map [1]). Most mobile phones are able to capture both the location and time automatically.

As mentioned, by indexing the geographical space using a spatial tree structure, our model supports users to change the scale of the target region efficiently by switching between different levels in the tree structure. Although the previous work in [16] allows the change of scale granularity, it has to retain all parameters for the new granularity while our model does not. The application in Figure 9.3 as an example. Assume that the current location corresponds to "Level 3" of the spatial pyramid. If the querying user zooms out on the map, the map becomes smaller and the granularity of the regions becomes coarser. ST-SAGE will automatically change the scale from "Level 3" to "Level 2" or above based on the new granularity. As the model parameters for all levels have been pretrained and the parameters for the new "level" can be retrieved directly, the model does not need to retain the parameters for "zooming out." Similarly, if the user zooms in on the map, ST-SAGE simply switches the scale from the upper level into one lower level without any parameter retraining.

## 9.3.5 Parallel implementation

We proposed a two-step inference algorithm to train ST-SAGE: Gibbs EM algorithm containing Gibbs sampling and gradient descent learning. This two-step algorithm is implemented in a parallel framework to improve efficiency. We use a Gibbs EM algorithm containing Gibbs sampling and gradient descent learning. This two-step process allows us to handle large-scale data. In the E-step, we use Gibbs sampling to estimate the latent variables and transition probabilities. In the M-step, we use gradient descent to update the model parameters. The entire process is parallelized across multiple nodes to reduce the computation time.

The proposed parallel implementation is based on a distributed framework like Spark. The data is partitioned across the cluster, and each node processes a local subset of the data. The results are then aggregated to update the global model. This approach allows ST-SAGE to scale to very large geo-social networking datasets.
