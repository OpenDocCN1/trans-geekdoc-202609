## 13.5.2 Experimental results

We will now discuss the performance of the proposed methodology with respect to matching accuracy and time performance. To assess matching accuracy, we consider precision and recall defined as the information retrieval community. Precision is defined as the proportion of the number of relevant records retrieved, Recall refers to the total number of relevant records retrieved divided by the total number of existing relevant records. With respect to time performance, we include a comparison with the sequential counterpart of our algorithm implemented as outlined above.

## 13.5.2.1 Algorithm combination selection

The first set of experiments is targeted toward selecting the most suitable phonetic encoding combination, which elevates matching performance. For this purpose, we examine the behavior of the two most widely used phonetic encoding algorithms [8], namely, Soundex and NYSIIS. A common issue of these algorithms is the fact that, alterations in the first letter of the encoded string have an impact on the resulting encoding. To this end, we consider various configurations of both forward and reversed inputs for Soundex and NYSIIS. For this case, we do not consider the injection of fake records; these are randomly generated, a fact could refrain us from resulting into safe conclusions. The reported experiments were run on the 200K records dataset.

The results of this evaluation are illustrated in Figure 13.3(a). The horizontal axis hosts the evaluated method, with SND indicating Soundex and NYS standing for NYIIS. An “R.” prefix means that the input string has been reversed. The vertical axis is linearly scaled and scales for precision and recall. The highest performance is achieved when using classical Soundex in combination with reverse NYIIS. This way errors occurring in the first letter of a word do not affect the phonetic algorithm with the reversed input, compensating the failure of the normal input. In all cases, precision is very high, reaching 1. Based on the matching quality of Soundex and reverse input NYIIS, we use this combination for the rest of our evaluation.

## 13.5.2.2 Matching accuracy

We have measured precision and recall for two different cases: (i) without any noise addition and (ii) with the addition of noise. In this first case, we have all available datasets, while in the second, we measure precision for various configurations for the 200K dataset. For simplicity in the second case, we have only employed Soundex like fake records.

The results for this case are illustrated in Figure 13.3(b). The horizontal axis holds the size of dataset, while the vertical one is scaled from zero to one and stands for precision and recall. We can easily see in this that the drop in precision and recall are minimal, In particular, precision is in the area of 0.99, while recall ranges between 0.72 for the smallest dataset to 0.708 for the largest one. Thus, we deduce that the dataset size has a minimal impact on our method's matching accuracy.

Figure 13.3(c) illustrates the effect of injecting fake records on matching performance. The horizontal axis designates the percentage of fake records inserted in the 200K, for example, 100% means that another 200K records were inserted by each part. The vertical axis, again, stands for precision and recall. It is evident that the addition of noise does not affect either precision or recall. Both measures maintain stable values regardless of the amount of noise.

## 13.5.2.3 Time performance

Let us observe the behavior of the sequential and parallel algorithms in terms of time performance starting with a setup where there is no generation of fake records. We measure the performance of the private method with respect to different datasets, excluding the overhead of generating the fake records. We measure the speedup achieved by each parallel setup, defined as the ratio of sequential execution time to parallel execution time for the 50K–400 datasets (Figure 13.3(d)) and execution times for the parallel setup for all datasets (Figure 13.3(e)). In both cases, the vertical axis is linearly scaled.

As we see in Figure 13.3(d), an increase in the input dataset sizes leads to an increasing speedup when the parallel version is employed. Sequential execution time, in this case, starts at 176.27 s for matching 50K against 50 records and reaches 1040.35 s, when matching 400K against 400 records. The corresponding times for the parallel implementation are illustrated in Figure 13.3(e). Both the parallelized algorithms, and its sequential version, which exploits the use of the databases, exhibit linear behavior with respect to the dataset size. However, the sequential algorithm has a steeper gradient, a fact that explains the speedup achieved by the parallel framework.

In the next set of experiments, we study the behavior of the parallel algorithm when fake records are injected. For illustration purposes, Figure 13.3(f)(g) includes results, with 200K dataset and three workers, for speedup and execution times. The horizontal axis stands for the percentage of fake records generated with the dataset size. The vertical axes represent speedup and time. The parallel algorithm outperforms the sequential one in this case as well. However, we can also see that the speedup decreases as the amount of fake records increases. This is due to the fact that new records are generated and to be transferred within the cluster nodes, which is quite inherently expensive operation. To address this and improve performance, as we said earlier, the fake datasets could be precomputed and distributed through a distributed file system. However, to illustrate the worst case scenario in terms of performance, we have decided to exhibit a scenario where all calculations take on-the-fly.

Finally, we performed a set of experiments to further investigate the behavior of our parallel method with respect to the workers in the cluster (Figure 13.3(h)). For this purpose, we have also employed an additional, fourth node. We use the 200K dataset and examine time in cases there is no noise and with the injection of 100% fake records. We employ four setups for each of these settings: first, we utilize only a single worker, then two and finally four workers, comparing with the behavior of the sequential versions, which are illustrated as a light gray bar for the line of no fake additions and as a dark gray bar for the case of noise addition. The horizontal axis holds the number of nodes used in each case, while the vertical axis represents execution time in seconds. As we may, utilizing more workers confers a clearly positive impact to the PPRL process in execution time. Furthermore, in the case of noise absence, there is a greater speedup, even when a single worker is used. When noise is injected, more than two workers are required to achieve reduced execution time due to the transfer of the generated datasets within the cluster.

## 13.6 Conclusions and future work

In this chapter, we have presented a cost-efficient parallel protocol for performing qualitative approximate PPM based on the use of multiple phonetic encoders, binding the Soundex and the NYSIIS phonetic algorithms. Furthermore, we proposed using the first algorithm to encode the original text and the second for its reverse. As we have experimentally shown using the Apache Spark platform, our algorithm efficiently handles large volumes of data while improving the quality of the matching results compared to approaches using a single encoding algorithm.
