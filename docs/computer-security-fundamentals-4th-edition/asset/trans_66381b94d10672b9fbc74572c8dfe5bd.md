
数字签名并非用于确保消息的机密性，而是用于保证消息的发送者是谁。这被称为`nonrepudiation`。基本上，nonrepudiation意味着证明发送者是谁。数字签名实际上相当简单，但它们是巧妙的。它们只是逆向了非对称加密的过程。请回顾，在非对称加密中，公钥（任何人都可以获取）用于加密消息以发送给接收方，而私钥（保持安全和私密）用于解密。对于数字签名，发送者使用自己的私钥对某些内容进行加密。如果接收方能够使用发送者的公钥解密，那么消息必定是由声称发送该消息的人所发送。此过程如下图[`Figure 8.6`](#ch08.xhtml#ch08fig06)所示。

### Hashing

`hashing`是一种加密算法，具有特定的特征。首先，它是单向的，即你无法“反向”解密（unhash）某事物。其次，无论输入是什么，输出都是固定长度的。第三，不存在碰撞（collisions）。碰撞是指两个不同的输入在同一个哈希算法下产生相同的输出（称为`[hash](#glossary.xhtml#gloss44)`或`*digest`）。理想情况下我们希望没有碰撞。但现实是，由于固定长度输出，碰撞是可能的。因此，目标是让碰撞的可能性变得极低，几乎不需要考虑。

哈希正是Windows存储密码的方式。例如，如果你的密码是`password`，Windows会先对其进行哈希，生成类似下面的结果：

`0BD181063899C9239016320B50D3E896693A96DF`

Windows随后将该哈希值存储在SAM（Security Accounts Manager）文件中，该文件位于Windows系统目录。当你登录时，Windows无法反向解密你的密码（因为它是单向的）。因此，Windows的做法是：当你输入密码时，它会对输入的密码进行哈希，然后与SAM文件中的哈希值进行比较。如果完全匹配，则允许登录。

存储Windows密码只是哈希的一个应用场景。还有其他用途。例如，在计算机取证中，通常会在开始取证检查之前对磁盘进行哈希。随后可以再次哈希以查看是否有任何更改（无论是意外还是故意）。如果第二次哈希与第一次匹配，则表示没有任何更改。

有多种哈希算法。其中最常见的两种是MD5和SHA。（最初是SHA-1，但此后更常见的版本，如SHA-256，已取代其地位。）

#### MD5

`[MD5](#glossary.xhtml#gloss56)`是一种128位的哈希，指定于RFC 1321。它由Ron Rivest于1991年设计，用于取代早期的哈希函数MD4。MD5生成128位的哈希或消息摘要（digest）。它的抗碰撞能力不如SHA。

#### SHA

`Secure Hash Algorithm`（`[SHA](#glossary.xhtml#gloss72)`）可能是当今最广泛使用的哈希算法。目前有多个SHA版本，所有版本都被认为是安全且抗碰撞的：

*   **SHA-1:** 这是一个160位的哈希函数，类似于早期的MD5算法。它由NSA设计，用于数字签名算法（DSA）。

*   **SHA-2:** 这实际上是两个相似的哈希函数，具有不同的块大小，分别称为SHA-256和SHA-512。它们的区别在于字长；SHA-256使用32字节（256位）字，而SHA-512使用64字节（512位）字。此外，还存在每个标准化版本的截断形式，即SHA-224和SHA-384。这些也由NSA设计。

*   **SHA-3:** 这是SHA的最新版本，于2012年10月被采用。

#### RIPEMD

`RACE Integrity Primitives Evaluation Message Digest`（`RIPEMD`）是一种160位的哈希算法，由Hans Dobbertin、Antoon Bosselaers和Bart Preneel开发。该算法有128位、256位和320位的变体，分别称为RIPEMD-128、RIPEMD-256和RIPEMD-320。这些变体都取代了原始的RIPEMD，因为原始版本被发现存在碰撞问题。

### MAC and HMAC

哈希用于多种安全相关功能。其中之一是存储密码，我们在此已经讨论过（本章后面还会看到更多）。

消息的哈希可以在传输过程中用于检测意外的篡改。如果消息在传输过程中被篡改，接收方可以将接收到的哈希与发送方计算的哈希进行比较，从而检测传输错误。但如果是恶意的篡改呢？如果有人故意修改消息，删除原始哈希，并重新计算一个新的哈希，普通哈希算法无法应对这种情况。

使用`消息认证码`（`MAC`）是一种检测消息意图篡改的方法。MAC也常被称为`keyed cryptographic hash function`（有密钥的密码散列函数）。这个名字应该能让你理解其工作原理。一种实现方式是`消息认证码`（HMAC）。假设你使用MD5来验证消息完整性。为了检测恶意方意图篡改消息，发送方和接收方必须事先共享一个适当大小的密钥（在此例中为128位）。发送方会对消息进行哈希，然后将该哈希与密钥进行异或（XOR）运算。接收方会对接收到的内容进行哈希，然后将计算出的哈希与密钥进行异或。随后两者交换。如果拦截方仅仅重新计算哈希，他将没有密钥来与之异或（并且可能甚至不知道需要异或），因此他生成的哈希与接收方计算的不一致，篡改行为将被检测到。

概念还有其他变体。一些方法使用对称密码在CBC（密码块链接模式）中，然后仅使用最后一个块作为MAC。这些变体被称为CBC-MAC。

#### Rainbow Tables

由于Windows和许多其他系统将密码存储为哈希值，许多人对如何破解哈希感兴趣。正如我们所提到的，由于哈希不可逆，无法“反向”解密任何内容。1980年，Martin Hellman描述了一种利用预计算数据存储在内存中的技术，以减少密码分析的时间。在1982年之前，Rivest对该技术进行了改进。基本上，这类密码破解工具使用预计算的所有可能密码（在特定字符集范围内，如a–z或a–zA–z或a–zA–Z0–9等）的哈希值，这称为`rainbow table`。如果你在rainbow table中查找某个哈希，找到的明文即为输入该哈希算法的原始文本。

显然，这样的rainbow table会非常大且增长迅速。假设密码必须限制在键盘字符上，那么就有52个字母（26大写+26小写），10个数字，以及大约10个符号，总共约72个字符。正如你所想象，即使是6位密码也有极大的组合数。这意味着rainbow table的规模也有限，因此更长的密码比更短的密码更安全。

自rainbow table的出现以来，已有许多方法设计用于防御此类攻击。最常见的是`salting`，即在哈希前添加随机位，以进一步增强安全性。这在防止rainbow table攻击时最常见。

基本上，`salt`是与要哈希的消息混合的随机位。考虑一个例子。假设你有一个密码：

pass001

其二进制表示为：

01110000 01100001 01110011 01110011 00110000 00110000 00110001
