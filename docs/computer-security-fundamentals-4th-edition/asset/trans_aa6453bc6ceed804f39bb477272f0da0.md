
Windows 应用程序要求用户输入密码，然后再对其进行哈希处理。通常可以通过类似 LsaLogonUser 的 API 完成，将密码转换为 LM 哈希或 NT 哈希。传递哈希值会跳过应用程序，直接发送哈希值。

### Net User 脚本

此特定漏洞首先需要至少具有客户端级权限对目标机器进行访问。它基于这样一个事实：许多组织将技术支持人员加入到域管理员组中。

攻击者编写以下两行脚本（显然，单词 *localaccountname* 已被替换为实际的本地账户名称）：

[点击此处查看代码图片](Images/ch06_images.xhtml#p170pro01)

```
net user /domain /add localaccountname password
net group /domain "Domain Admins" /add Domain
```

攻击者将此脚本保存在所有用户的启动文件夹中。下一次具有域管理员权限的用户登录该机器时，脚本将执行，`localaccountname` 将成为域管理员。唯一的问题是，可能需要很长时间才有人具有此类权限登录该机器。为了加快进程，攻击者会制造系统问题，迫使技术支持人员进行修复，例如禁用网卡。下一个登录的用户将无法访问网络或 Internet，并会联系技术支持。技术支持人员很可能是域管理员组的成员。当该人员登录计算机以修复问题时，脚本会在不知情的情况下执行。

此特定漏洞阐明了两个不同的安全问题。第一个是最小权限概念，即仅为完成工作提供最小必要权限。该概念在 [第 1 章](#ch01.xhtml#ch01)，“[计算机安全入门](#ch01.xhtml#ch01)。” 中简要讨论过。技术支持人员不应加入域管理员组，如果他们不在该组中，则此 net user 脚本攻击将不会成功。

第二个问题是，对您的所有机器的访问应受到控制。此漏洞仅需要攻击者拥有客户端级访问权限，且仅需几分钟时间。从最小的访问权限出发，技术熟练的攻击者可以进一步提升权限至域管理员。

### 以系统身份登录

“以系统身份登录”攻击需要对网络中的一台机器进行物理访问，不需要域或计算机登录凭据。要理解此攻击，请回想您上次登录任何 Windows 计算机（甚至 Windows 服务器）的情形。在登录文本框（用户名和密码）旁边，有一个可用性按钮，用于启动各种辅助残障人士的工具。例如，您可以启动放大镜以放大文本。

在本攻击中，攻击者会先使用任何 Linux 系统映像光盘启动系统。然后，使用 FDISK 实用程序定位 Windows 分区。进入 Windows\\System32 目录后，攻击者首先备份 magnify.exe，可能将其命名为 magnify.bak。随后，她将 command.exe（命令提示符）重命名为 magnify.exe。

攻击者随后重新启动 Windows。当登录界面出现时，攻击者点击可用性选项并选择放大镜。由于 command.exe 已被重命名为 magnify.exe，攻击者实际上是启动命令提示符。此时尚未有用户登录，因此命令提示符会以系统权限运行。此时，攻击者仅受限于其在命令提示符中可执行的命令知识。

此特定攻击凸显了物理安全的必要性。如果攻击者仅拥有 Windows 计算机 10 分钟的独处时间，她很可能会找到 breaching（入侵）网络的方法。

### 渗透测试

如前所述，本章介绍的技术可以作为渗透测试的一部分进行。然而，渗透测试并非随意应用各种黑客技术的简单组合。通常，渗透测试是在或之后进行漏洞评估之后完成的。（我们将在第 11 章 [中](#ch11.xhtml#ch11) 详细讨论漏洞评估。）

渗透测试是对目标网络进行系统性探测，以识别网络中的弱点。渗透测试的理论是，唯一客观判断给定网络安全水平的方法是让有能力的渗透测试人员尝试突破安全防护。正如本节所述，可用于指导渗透测试的多种标准存在。

#### NIST 800-115

NIST 800-115 是国家标准技术研究院（NIST）针对联邦信息系统安全评估的指南，其中包含渗透测试。NIST 800-115 描述了安全评估，并包含四个阶段：

*   **规划**：在此期间，测试人员需设定具体的测试目标，这些目标通常与之前的风险评估结果相关。

*   **发现**：此阶段使用多种工具（包括端口扫描仪、漏洞扫描仪和手动技术）来识别目标网络中的任何问题。

*   **攻击**：攻击者利用在发现阶段发现的漏洞，尝试入侵目标网络。在此阶段，渗透测试人员会应用本章讨论的黑客技术。

*   **报告**：最后一步是编写详细报告并交付给委托方。报告应详细说明被利用的漏洞、利用方式以及建议的修复措施。

尽管该方法仅包含四个阶段，但这些阶段范围较广，包含众多子步骤。我们在此不需要深入探讨 NIST 800-115 的所有细节。不过，这些宽泛的步骤为渗透测试提供了框架。请注意，在攻击阶段之前有两个步骤：规划和发现，它们在其他渗透测试标准中也同样重要。

#### NSA 信息评估方法论

国家安全局（NSA）负责美国联邦政府的信息安全。NSA 制定了一套方法论，可应用于任何包含安全审计、漏洞测试和渗透测试的信息系统评估。该方法论简要描述如下：

*   **前评估**

    *   确定并管理客户的期望。

    *   了解组织信息的重要性。

    *   确定客户的目标和目的。

    *   确定系统边界。

    *   与客户协调。

    *   请求文档。

*   **现场评估**

    *   召开启动会议。

    *   通过面谈、系统演示和文档审查收集并验证系统信息。

    *   分析评估信息。

    *   制定初步建议。

    *   进行出站简报。

*   **后评估**

    *   对文档进行再次审查。

    *   获取对所学内容的帮助理解。

    *   协调并编写报告。

这一步骤总结的特点很有趣。管理客户期望是关键步骤。确保客户了解渗透测试的可行范围和局限性非常重要。前评估阶段的核心是决定将执行什么操作以及客户的预期。
