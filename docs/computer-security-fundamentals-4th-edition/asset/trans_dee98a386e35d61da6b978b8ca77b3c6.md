
这些网络类别在本书后期将变得更为重要（或者如果你决定更深入研究网络）。请仔细观察[Table 2.4](#ch02.xhtml#ch02tab04)，你可能会发现127的IP范围未被列出。这一省略是因为该范围保留用于测试。127.0.0.1的IP地址指代你正在使用的机器，无论该机器的实际IP地址是什么。该地址常被称为*loopback address*。我们将在本章稍后的“[Basic Network Utilities](#ch02.xhtml#ch02lev1sec5)”节中进一步探讨其用途。

这些类别告知你地址中哪部分代表网络，哪部分代表节点。例如，在Class A地址中，第一个字节代表网络，剩余三个字节代表节点；在Class B地址中，前两个字节代表网络，后两个字节代表节点；在Class C地址中，前三个字节代表网络，最后一个字节代表节点。

此外，还有若干特定的IP地址和IP地址范围需要注意。首先，如前所述，127.0.0.1（即loopback address）是指代你所在机器的网络接口卡。

私有IP地址是另一类需要关注的内容。某些IP地址范围被指定用于内部网络，不能作为公共IP地址，但可用于内部工作站和服务器。这些私有IP地址包括：

*   `10.0.0.10` 到 `10.255.255.255`

*   `172.16.0.0` 到 `172.31.255.255`

*   `192.168.0.0` 到 `192.168.255.255`

新手在理解公共IP地址和私有IP地址时常有困难。一个好的类比是办公楼：在同一栋大楼内，每个办公室编号必须唯一，例如只能有一个办公室`305`。在同一栋大楼内提到办公室`305`，即可明确指代。但其他大楼也可能有办公室`305`。你可以把私有IP地址视为办公室编号，它们必须在各自网络内唯一，但不同网络之间可能共享相同的私有IP地址。

公共IP地址则类似于传统的邮寄地址：它们必须在全球范围内唯一。在同一网络内部通信可以使用私有IP地址，但要与网络外的任何计算机通信，必须使用公共IP地址。

网关路由器的一个重要角色是执行网络地址转换（NAT），它会在发出的数据包上将私有IP地址替换为网关路由器的公共IP地址，以便该数据包能够通过互联网路由。

### Subnetting

我们已经讨论了IPv4网络地址，现在转向子网划分（subnetting）。如果你已经熟悉此主题，可以跳过本节。由于某种原因，该主题常让网络学生感到困扰，因此我们从概念性理解开始。`Subnetting` 简单来说就是将一个网络划分为更小的部分。例如，如果你有一个使用`192.168.1.x`（其中x是特定计算机地址）的网络，那么你已分配了255个可能的IP地址。如果你想将其分为两个独立的子网络，子网划分就是实现这一点的方法。

更技术地说，子网掩码是一个32位的数值，为每个主机分配，用于通过二进制AND运算将32位二进制IP地址划分为网络和节点两部分。你不能随意输入任何数值。子网掩码的第一个值必须是255；其余三个值可以是255、254、252、248、240或224。你的计算机会使用网络IP地址和子网掩码进行二进制AND运算，从而组合它们。

你可能会惊讶地发现，即使你没有进行子网划分，也已经拥有一个子网掩码。如果你拥有Class C IP地址，那么你的网络子网掩码是`255.255.255.0`；如果是Class B IP地址，子网掩码是`255.255.0.0`；如果是Class A，子网掩码是`255.0.0.0`。

现在请思考这些数值与二进制数的关系。十进制值255转换为二进制是`11111111`。因此，你实际上是在“掩码”用于定义网络的IP地址部分，而剩余部分用于定义单个节点。如果你希望子网中节点数少于255，则需要像`255.255.255.240`这样的子网掩码。将240转换为二进制是`11110000`，这意味着前三个字节以及最后一个字节的前4位定义网络，最后4位定义节点。这意味着该子网络最多可容纳`1111`（二进制）或15（十进制）个节点。这就是子网划分的基本原理。

### CIDR

子网划分只允许使用特定的、有限的子网。另一种方法是CIDR（Classless Inter-Domain Routing）。与其定义子网掩码不同，CIDR在IP地址后跟一个斜杠和一个数字，该数字可为0到32之间的任意值，例如：

`192.168.1.10/24`（基本上是一个Class C IP地址）

`192.168.1.10/31`（类似于Class C IP地址但子网掩码不同）

使用CIDR时，而不是使用类与子网的概念，我们使用可变长度子网掩码（VLSM）来提供无类别的IP地址。这已是当今定义网络IP地址的最常见方式。

### IPv6

你可能已经听说过IP版本6（IPv6），它是IPv4的扩展。本质上，IPv4的地址空间被限制在42亿个地址。即使使用私有IP地址，我们也将耗尽可用地址。想象一下所有连接互联网的计算机、打印机、路由器、服务器、智能手机、平板电脑等。IPv6设计的目的正是为了解决这个问题。如果你查看上一节描述的网络设置，很可能看到可以启用IPv6的选项。IPv6使用128位地址（而非32位），因此在可预见的未来不会出现地址耗尽的情况。IPv6还采用十六进制编号方式，以避免诸如`132.64.34.26.64.156.143.57.1.3.7.44.122.111.201.5`这样冗长的地址。一个IPv6十六进制地址示例是`3FFE:B00:800:2::C`。

IPv6不像IPv4那样进行子网划分，但它使用CIDR。网络部分通过斜杠后跟地址中分配给网络部分的位数表示，例如：

`/48`

`/64`

IPv6的循环地址为`::/128`。IPv4与IPv6的其他区别包括：

*   **Link/machine-local address:** 这是IPv6版本的IPv4的APIPA（Automatic Private IP Addressing）地址。如果机器配置为自动获取地址且无法与DHCP服务器通信，它会为自己分配一个通用IP地址。DHCP（Dynamic Host Configuration Protocol）用于在网络内动态分配IP地址。IPv6的link/machine-local地址均以`fe80::`开头。如果你的计算机拥有此地址，意味着它无法获取DHCP服务器分配的地址，因此自行生成了一个通用地址。
