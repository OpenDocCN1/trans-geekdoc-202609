destruct. The self-destruct design pattern is used by smart contract developers in order to clean contracts’ data and move contracts’ funds to a special address which is defined by contract logic. The self-destruct (address) function removes all bytecode from the contract address and sends all ether stored to the specified address. If this specified address is also a contract, no functions (including the fall back) get called. In other words, an attacker can create a contract with a self-destruct function, send ether to it, call self-destruct (target) and force ether to be sent to a target. Such a smart contract should avoid being dependent on the exact values of the balance of the contract because it can be artificially manipulated. If exact values of deposited ether are required, a self-defined variable should be used that gets incremented in payable functions, to safely track the deposited ether. Hence the data still exists in the blockchain history even if the contract would not exist anymore in the latest block.
