

## 用户界面 (UI) Bug

UI bug 会导致设计偏差或应用程序功能出现缺陷，从而导致糟糕的用户体验。UI bug 的一个例子是 **Parity Multisig（多签）** bug，该 bug 导致作为所有 Parity 多签钱包共享组件部署的智能合约库代码中存在漏洞。在一次事件中，该 bug 暴露了一个漏洞，由于 Solidity 的默认公开策略，允许用户将自己设为库合约的所有者。随后，该用户使用 `kill()` 命令销毁了整个库，这冻结并封锁了 587 个钱包的资金，当时总计高达 513,774.16 个以太币（约合 1.6 亿美元）[[25](#ch18.xhtml#r384)]。

## 以太坊智能合约中的 Bug

作为最大的智能合约区块链平台，以太坊过去曾面临多个与 bug 相关的智能合约问题。不幸的是，由于目前缺乏成熟的框架和分类体系，很难识别智能合约中的 bug。现有工具仅有助于解决一小部分 bug 问题。对于新开发者来说，要完全理解 bug 造成的所有影响具有挑战性。正因如此，设计新的 bug 检测和解决方法变得更加困难。Bug 分类可采用适用的 NIST 框架执行；然而，在所有已识别的 bug 中，只有少数被归类为定义明确的类别，其余均归类为“其他类别”。Bug 检测标准是一个脆弱的过程，这使得开发者难以设计检测 bug 的工具和算法。为了解决这些局限性，以太坊开发者正持续发现和分析各种 bug 行为。

有时，当收集和分析智能合约 bug 时，开发者会发现一些本质相同但名称不同的 bug，因为没有遵循的 bug 命名约定。因此，根据 bug 造成后果的性质，将重复的 bug 合并在一起。

两个值得注意的智能合约分析工具包括 **Slither**，它是检测 bug 的较有效分析工具之一，具有可接受的精确率。该工具可通过名为 `pip3` 的 Python 包轻松安装，并可在 [https://github.com/crytic/slither](https://github.com/crytic/slither) 下载。**Remix** 是另一个用于 bug 检测且具有高精确率的分析工具。Remix 可通过 Remix IDE 平台安装，并可在 [https://remix-wide.readthedocs.io/](https://remix-wide.readthedocs.io) 访问 [[32](#ch18.xhtml#r391)]。

除上述工具外，还有其他一些工具推荐用于 bug 分析和智能合约分析，如 [表 10.1](#ch18.xhtml#t18) 所示。
