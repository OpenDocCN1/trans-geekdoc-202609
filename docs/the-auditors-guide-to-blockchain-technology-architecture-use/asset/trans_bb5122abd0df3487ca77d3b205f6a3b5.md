

# 节点测试

区块链的威力在于共享分布式账本在链的每个节点上都拥有相同的交易序列集合。因此，需要进行节点测试，以确保交易具有顺畅的一致性，并且与其他验证节点保持同步 [[1](#ch18.xhtml#r360)]。为了测试交易的一致性，需要测试共识协议，以确保即使某些节点发生故障，交易也能被正确排序。在测试节点时，还需要测试弹性。这可以通过验证网络上重启或重新加入的任何节点是否与其他验证节点同步来完成 [[22](#ch18.xhtml#r381)]。

# 区块链缺陷管理考量

缺陷可被归类为：与应用程序指定需求的任何偏差，或与预期行为的任何偏差（此类偏差可能给环境带来潜在威胁）[[11](#ch18.xhtml#r370)]。软件测试不仅关乎区块链应用的质量保证、控制和验证，还有其他因素需要考量。拥有有效的质量保证和缺陷管理方法，对于确保区块链应用在发布前达到高标准至关重要 [[9](#ch18.xhtml#r368)]。

缺陷管理的基本目标是识别和检测系统中的缺陷，但这只是成功的一半。缺陷管理的关键步骤包括记录发现的缺陷、登记并跟踪缺陷，以及尽快组织和解决问题。建议在软件开发生命周期（SDLC）的早期阶段识别并修正系统中的任何安全或性能缺陷，因为这不仅能提供质量保证，还能节省大量资金、时间和精力。此外，在 SDLC 后期发现缺陷会使缺陷检测变得更加困难，解决起来也更具挑战性 [[11](#ch18.xhtml#r370)]。

## 四步缺陷管理策略

缺陷管理应被视为企业的优先事项，因为它不仅融入企业文化，还影响客户满意度。

以下是识别差距并更接近零缺陷目标的四步策略。

*   **缺陷可见性**：缺陷管理的这一部分围绕已发现的缺陷展开，旨在了解为有效的产品交付应做出何种决策。获得清晰可见性的标准是质量、时间、质量和特性。
*   **缺陷优先级排序**：一旦确认清晰可见性，优先级排序就是下一步。数据质量和获取正确信息对于缺陷优先级排序至关重要。发现的缺陷应根据其严重程度进行优先级排序，严重程度通过所获取的信息（如风险等级、缺陷范围及其分类）来衡量。
*   **缺陷解决**：在获得清晰可见性并获取准确信息后，可在 SDLC 过程中更早地做出及时且更快的决策，从而节省时间和金钱。团队可根据商定的方法，协作制定步骤以解决缺陷。
*   **缺陷分析**：完成上述步骤后，将进行分析过程，其中会考虑所有已识别缺陷的输入。通过此过程，团队将更接近实现零缺陷的“涅槃”目标。

通过步骤 1-3，所有关键缺陷信息和纠正措施实施均被记录并收集，用于未来的缺陷预防。这些包括但不限于经验教训、根因分析方法及结果。系统具备记录缺陷分析过程以实现历史追溯的能力，对于更接近零缺陷目标至关重要 [[10](#ch18.xhtml#r369)]。

## 区块链缺陷类别

区块链系统的可靠性深受缺陷影响。因此，研究和理解缺陷特征有助于设计高效工具，以预防、缓解和检测区块链系统上的缺陷。对缺陷进行分类有助于识别区块链应用环境中存在的弱点和漏洞。

以下是区块链系统和应用中普遍存在的各类缺陷：

*   **并发缺陷**：并发缺陷是由程序中并发线程或进程之间引起的。基本上，此类缺陷导致同步问题。与 Mozilla 和 Apache 相比，此类缺陷通常在 Linux 内核中被识别出来。
*   **环境与配置缺陷**：环境与配置缺陷是以第三方库的形式隐藏在操作系统中或配置文件中的缺陷。此类缺陷的发生率排名第二。通常需要数月时间来修复此类缺陷。
*   **硬分叉缺陷**：此类缺陷在突然的协议变更导致先前有效的交易变为无效交易（或反之亦然）时引发问题。这种系统行为的变化也会影响区块链协议中的共识 [[29](#ch18.xhtml#r388)]。
*   **性能缺陷**：性能缺陷是可能导致性能下降的错误，最终损害软件性能和质量。这可能导致用户体验差、应用响应能力下降、系统吞吐量降低和计算资源浪费 [[16](#ch18.xhtml#r375)]。性能缺陷的一个例子是在比特币中发现的一个高严重性性能缺陷。比特币区块链上的远程节点未能从其内存中移除无效交易。这导致了拒绝服务漏洞，因为远程节点无法清理交易，从而用被称为“失控资源消耗”的陈旧数据淹没受害者节点，最终可能导致节点关闭，从而降低区块链网络的性能 [[5](#ch18.xhtml#r364)]。
*   **回归缺陷**：在执行软件测试时，会识别出缺陷并随后采取修复措施。缺陷修复后，会进行回归测试，以确保近期的缺陷修复没有导致功能中断。通过此类测试发现的缺陷称为回归缺陷。回归缺陷难以处理，但必须在发布前解决。这些缺陷会增加项目成本、造成时间复杂性并降低项目的整体敏捷速度 [[2](#ch18.xhtml#r361)]。
*   **安全缺陷**：安全缺陷是软件弱点或漏洞，例如应用程序中的设计缺陷，威胁主体可能利用这些缺陷通过暴露漏洞来攻击整个区块链架构 [[6](#ch18.xhtml#r365)]。区块链可能存在特定于应用的安全缺陷，如时序攻击和 DDOS 攻击，或缺失安全检查。安全缺陷通常需要最长时间来解决。
*   **语义缺陷**：语义缺陷是由于程序员对系统缺乏透彻理解而发生的。这类缺陷难以识别，因为它们特定于应用程序。语义缺陷有时被称为主要运行时缺陷，因为超过 70% 的报告缺陷属于语义缺陷；其中 23.9% 是由缺失用例（也称为疏忽条件缺陷）引起的。其他原因包括不正确的处理过程、异常处理、缺失功能、不正确的控制流或输入/输出问题 [[29](#ch18.xhtml#r388)]。
