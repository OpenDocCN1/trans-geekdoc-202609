

# 有效的测试策略需要充分的规划

规划是项目的一个基本方面，应在区块链开发的早期阶段予以考虑。这种方法使测试环境向前迈进了一大步，从而产出高质量的最终产品和有效的测试程序。为了实施高效的测试方法，拥有详细信息非常重要。这些信息应包括测试范围、覆盖率、限制、持续时间和所用工具的详细情况。这些信息将在项目的每个测试阶段发挥关键作用，并帮助团队高效地构建和监督测试流程。适当的文档记录是测试策略的一部分，它帮助团队在测试区块链应用时遵循既定顺序。根据测试场景，测试方法论由组织酌情设计。

在开始项目前分析和理解项目需求也很重要。同样，测试也始于需求，这些需求必须经过仔细分析，以便推进各个测试阶段。对应用有深入了解的测试人员能更精确地测试区块链应用所需的特性。因此，拥有针对不同区块链应用平台的工具和技术的广泛技能组合的测试人员是宝贵的组织资产。此外，当前部署的大多数区块链应用使用 API 协议作为编程接口，这要求测试人员也要具备足够的 API 测试技能 [[27](#ch18.xhtml#r386)]。

## 改进测试策略的机会

测试是一个重复的过程，涉及尽最大可能发现缺陷和漏洞。每次测试都能提供更好的输出，然后多次迭代以达到预期结果。改进测试策略取决于考虑导致故障的各种输入事件。由输入事件引起的故障需要被跟踪和监控，以获得更好的测试性能。对于给定的测试场景，可能存在多个输入事件。在测试区块链应用时，这些输入事件应被视为关键考量因素。

*   **服务启动**：有时应用在测试的早期阶段启动服务时就会失败。换句话说，应用无法调用待测试的服务。这是一个重要的输入事件，需要足够的测试范围，即确保具有长时间运行服务的应用在重启服务时不会失败。
*   **节点不可达**：这是在网络和单个站点上都常见的场景。不可达的节点会导致测试失败。导致此类故障的原因可能多种多样。因此，应部署使用导致故障的网络错误输入进行测试。同时也应熟练使用适当的工具以达到预期输出。
*   **应用配置变更**：基于系统需求，任何应用的配置变更都非常频繁。事实上，先进的系统可以自动检测配置变更。这种类型的测试事件要求测试有效和无效的配置，以最终获得稳定且功能完善的应用。
*   **节点添加**：对于区块链应用，任何节点添加都会产生一个触发器。作为测试范围的一部分，测试向网络添加节点至关重要。测试应重点关注节点添加方面的正向和负向测试场景 [[14](#ch18.xhtml#r373), [31](#ch18.xhtml#r390)]。

## 回归测试

回归测试要求重新执行功能和非功能测试，以帮助确保先前开发的软件模块在变更后仍能按预期工作。这需要自动化工具和软件来运行测试套件。这些工具也用于维护和处理应用的功能。选择作为回归套件一部分执行的测试用例需要时间。测试用例分析完成后，会形成用于测试的测试子集顺序。开发回归套件的目的是优化应用中常用的功能。由于其迭代过程，回归测试的输出是高效的。应用可能包含广泛的测试场景，但优先考虑以业务为中心的测试场景对于通过回归测试获得最佳结果非常重要。

如前所述，测试人员的角色是尽最大可能发现故障。测试人员的重点是在回归测试的早期阶段跟踪和监控发现的故障。任何待测试的应用都需要测试人员对其功能有敏锐的了解。因此，测试人员探索应用功能以了解所需的测试场景覆盖率至关重要。报告故障和错误是有效测试过程的基本要素。因此，高严重级别的故障应立即报告。

## 自动化测试

自动化测试确保区块链开发中的持续交付流程，允许开发人员将变更部署到生产环境中。对于大多数项目而言，时间表是重中之重，自动化测试有助于将项目发布和推向实时环境。考虑到项目的时间敏感性，高质量测试套件的快速实施提高了开发人员的生产力。

每个团队成员应根据各种业务功能的需要执行代码变更。代码变更直接影响测试过程，尤其是在自动化测试方面。代码和版本变更需要在一个适应性强且经常变化的业务流程中实现自动化。持续集成 (CI) 对开发和测试周期中的所有团队都至关重要。持续集成的原因是确保开发和测试团队都了解项目的进度，以保持在同一轨道上。自动化对开发团队是一大福音，因为代码审查所需的时间显著减少。因此，可以投入更多时间开发额外功能。简而言之，自动化测试有助为开发人员和测试人员创建一个强有力的基线，以构建和实施稳健的区块链应用 [[19](#ch18.xhtml#r378), [20](#ch18.xhtml#r379)]。
