

# 去中心化系统中的数据存储

在去中心化系统中，数据分布存储于网络各处，而非由中心节点收集汇总，旨在消除单点故障风险。临时消息传递和远程网络可用于在去中心化系统中传输数据。去中心化系统采用公钥加密方法提供可靠的认证机制。公钥对系统中所有用户可见，用于加密信息。去中心化系统中的每个节点或矿工都拥有数据的副本，这保证了数据平等，同时所有用户在去中心化环境中也受到平等对待。交易通过 `DApp` 广播至网络。消息在指定周期内实时传输，确保在必要时会重试传输消息 [[15](#ch16.xhtml#r302)]。

# 区块链与去中心化应用的因素与特征

与区块链和去中心化应用相关的因素与特征如下：

*   **开放访问**：中心化系统在其运营的某个阶段，会在技术上或逻辑上被控制方（第三方）锁定，对用户关闭。这意味着用户需要获得中央权限才能访问中心化应用。相反，由于去中心化应用具备开放访问能力且无中央权限控制，去中心化网络随时向用户和开发者开放 [[9](#ch16.xhtml#r296)]。去中心化应用的管理应当独立，任何修改应由区块链用户的共识来管理 [[15](#ch16.xhtml#r302)]。

*   **非层级化**：借助区块链技术，基于非层级模式，每个用户拥有平等的权威与控制权。例如工作量证明挖矿系统，其中所有矿工在区块链上本质上是平等成员，但其贡献与网络算力成正比。

*   **透明性**：透明性确保每个用户在区块链上获取相同数量和层级的信息。[第 7 章](#ch15.xhtml#c7)讨论了一个例外，即 `Hyperledger Fabric` 等区块链，根据各类隐私法律和最佳实践，具备向参与者隐藏信息的能力 [[9](#ch16.xhtml#r296)]。

# 整体式还是模块化？

模块化架构是指将问题的复杂性分解为更小、更易管理组件的方法。模块化架构包含一些准则、原则和模式，是一种设计风格，允许开发者将系统视为一组更小的物理组件。模块帮助开发者在设计和运行时阶段理解、扩展和控制系统。此外，模块具有清晰的业务结构，并通过公共接口传达其作用域。应用的物理组成是模块化架构的核心主题 [[19](#ch16.xhtml#r306)]。

组织通常倾向于选择模块化系统，而非紧耦合系统——即整体式应用。整体式应用拥有单一代码库，涵盖多个模块。模块分为业务或技术两类。整体式方法提供单一构建机制，包含整个系统及其依赖项。

一般来说，模块化流程可按以下方式执行。第一步是划分应用的功能。在划分功能并识别相应模块后，下一步是隔离模块以保持其独立性。接下来，重要的是在隔离模块后，将各项功能尽可能靠近其所需信息放置，以减少模块间通信。最后一步是消除模块间的直接通信 [[4](#ch16.xhtml#r291)]。

# 用户画像

用户画像是基于用户类别分析构建的虚构角色，旨在反映可能以相似方式使用服务、产品、网站或应用的各类用户类型。用户画像用于构建关键用户群体的可信、准确形象以供参考。在理解和开发用户画像时，会评估定性和定量因素以及网络分析数据。创建用户画像有助于理解用户的期望、视角、行为和目标。

## 用户画像示例 1

Shaun 教授是加拿大某大学的系主任。Shaun 负责协助管理学生的课程注册流程和数据。作为系主任，Shaun 没有时间手动核查和验证学生手工填写的所有纸质注册表。此外，他在批准每位学生的申请前，还必须检查所有课程注册资格要求。他觉得这一过程极其耗时，因此效率极低。

## 用户画像示例 2

Anika 是加拿大阿尔伯塔省一家医疗诊所的医生。作为医疗专业人员，她负责处理患者数据。每位医生每天平均接诊 20 位患者，医生们面临的一个大问题是难以识别患者，尤其是当老患者返院复诊时，医生不得不查找记录所有患者健康状况的具体文档。

# 用户故事

用户故事是从最终用户角度出发，对应用功能的一种非正式、概括性描述。旨在解释应用功能如何为用户带来价值。`DApps` 可能面向不止一种用户。用户故事通过特定最终用户的视角审视产品能力，以反映某一客户群体的利益和诉求。

## Shaun 教授的用户故事

Shaun 对新的课程注册电子表单系统感到满意。他可以通过访问平台开始一天的工作，查看所有包含所需信息的课程注册申请电子表单（如学生的绩点、成绩、课程先修要求等），从而快速批准/拒绝注册申请。Shaun 认为，这种方法比以前需要学生手工填写、他审核签字、再人工送至注册部门的纸质系统要高效得多。

## Anika 医生的用户故事

Anika 很高兴地发现，新的区块链 `DApp` 能有效保存每位患者的数据，且无需纸质病历。此外，`DApp` 还能为患者数据提供强有力的安全保障。每位医生均由系主任验证，只有他们（系主任和指定医生）拥有检索患者数据的访问权限。一旦医生批准新的患者数据，这些数据将作为一个区块存储在区块链驱动的平台上。

# 功能需求

功能规范定义了应用在特定情况下的行为表现。这有助于确定 `DApp` 开发者必须纳入解决方案的所需设计特性和功能。主要的区块链功能需求决策包括：区块链是否需要是私有、公开、开放或封闭的，以及确定验证每个区块的最佳共识方法 [[6](#ch16.xhtml#r293)]。
