
*   **透明度**：点对点软件允许数据管理者与其他货运投资者共享透明的记录，使他们能够针对重要里程碑快速采取行动，并保持货物在供应链中流动。
*   **标准的数字基线**：一个被广泛接受、值得信赖且全面的数字模型为高度协作的计划和商业智能提供了基础 [[16](#ch23.xhtml#r535)]。

## 提出的 BaaS 平台

为了解决商业区块链即服务系统固有的一些缺陷，研究人员引入了下文所述的 BaaS 系统。所有这些提出的 BaaS 系统有一个共同目标——保持区块链的主要属性：不可篡改性、去中心化、持久性和可审计性 [[31](#ch23.xhtml#r550), [40](#ch23.xhtml#r559)]。

### 功能区块链即服务

*功能即服务*（FaaS），也称为无服务器计算，是一种快速且灵活地将应用程序部署到云端的方式。功能区块链即服务模型基于功能即服务。与传统 BaaS 模型相比，功能 BaaS 模型是一种无服务器架构，具有多项优势。此外，功能即服务（FaaS）模型的稳健性和层级特性可以轻松适配 FBaaS 模型。该架构由基础设施层、组件层、服务层和业务逻辑层组成：基础设施层由操作系统和构建于 AWS 之上的物理集群组成，且不使用 Amazon Lambda 函数；组件层实现认证和授权等基本功能；服务层实现存储和交易等主要功能；业务逻辑层提供广泛且复杂的服务 [[9](#ch23.xhtml#r528)]。

### NutBaaS

NutBaaS 平台通过云计算环境提供区块链相关服务。这些服务包括监控和网络部署、智能合约测试和智能合约分析。NutBaaS 系统使开发者能够专注于业务逻辑。“Nut”（坚果）这个名字指的是提供一个“坚硬”的屏障（如坚果壳般）来保护区块链开发者的应用程序。NutBaaS 由资源层、服务应用层和业务层组成。区块链服务的实现通常需要实现资源层；即存储、数据库和网络。NutBaaS 架构的核心是 NutBaaS 服务层，它实现了绝大多数基于区块链的基础和复杂服务。虽然应用层为技术带来了构建单个应用程序的可能性，但业务层侧重于探索更多适合利用该技术创造额外业务成果的场景 [[40](#ch23.xhtml#r559)]。

### 全谱区块链即服务

FSBaaS 集成了私有链和联盟链，构建于 *Blockchain Lite*（一种中心化的基于私有云的区块链平台）和 Hyperledger Fabric（一种分布式、开放且安全的区块链基础设施）之上。FSBaaS 不将用户限制于仅使用一种类型的区块链系统，而是允许用户结合私有区块链系统和大型联盟网络的最佳特性。全谱 BaaS 架构由区块链租户、区块链节点、业务网络和业务网络解决方案组成。该平台为租户提供了一种灵活的方式，通过统一的编程原则接口和 RESTful API 访问两种区块链运行时 [[31](#ch23.xhtml#r550)]。

### 新型区块链即服务

*新型 BaaS*（NBaaS）是一个旨在改进基于 PaaS 的 BaaS 相关局限性的提出模型。NBaaS 中有几个不同的区块链组件，包括节点、网络成员、由排序节点进行的交易排序，以及区块链的客户端部分（用户在网络上操作的地方）。定义可部署组件对于连接区块链实例至关重要 [[31](#ch23.xhtml#r550)]。作为 NBaaS 的一部分，可部署组件可以以一种促进可审计性和去中心化的方式进行部署，然而，NBaaS 无法防止租户和提供商之间的串通 [[40](#ch23.xhtml#r559)]。

### 统一区块链即服务

uBaaS 解决方案是厂商中立的，意味着它们不绑定任何特定的云基础设施提供商。通过使用一个与后端服务通过应用程序编程接口（API）网关通信的前端用户界面，用户可以构建和配置基于区块链的应用程序。此外，uBaaS 支持部署即服务，消除了锁定特定云平台的需求；支持设计模式，有助于设计智能合约；并支持数据管理，以应对区块链的可扩展性和安全性挑战 [[31](#ch23.xhtml#r550)]。

### 公共区块链即服务

作为一个旨在提供安全环境、专注于隐私和分布式平等的平台，*Versus* 开发了公共区块链即服务（PBaaS）。通过使用 PBaaS，任何项目都可以通过支付报价金额（而非公证费用）来启动其区块链组件，从而拥有算力和跨链交易。每条链都是独立的且可定制的。跨链交易是发展整个网络的重要组成部分，因为它们允许活动在链之间自由流动以减少拥堵。要创建一条链，必须拥有 *VersusID*。Versus 的多条区块链将允许流行货币和代币的兑换，从而使能力不局限于单一区块链 [[34](#ch23.xhtml#r553)]。

尽管上述提出的 BaaS 系统具有相似的目标，但它们所解决的挑战没有重叠。这些研究的主要目标是使 BaaS 系统通用化和通用化，而非为了其性能 [[31](#ch23.xhtml#r550)]。

## BaaS 治理

当参与方较少时，治理问题应该更容易解决。BaaS 环境下治理的一个关键方面与参与者有关，如下节所述。

### 许可链

BaaS 应用程序通常涉及私有区块链（专用于特定用途或应用）和/或许可区块链（限制为一组参与者）。分布式账本技术并非总是必要的，特别是在活动更加中心化或某些实体拥有更多管理权限的情况下。数据库可能就足够了，因为审计数据库日志可以提供可接受的保证。通过不可变性和完整性约束可以提供进一步的保证——例如，`secure audit34` 和 `forward integrity35` 已为仅追加数据存储开发，足以满足审计和跟踪应用程序的需求。

在涉及许多参与者的情况下（如大型商业网络），使用分布式账本技术（DLT）更有意义。当各方计划监督彼此的活动，或各方希望拥有一定程度的自主权（如定义个人利益和功能）时，分布式账本（DL）可能很有用。根据参与者的风险偏好、信任顾虑和权力平衡，DLT 可能是合适的，也可能是不合适的。主要云服务提供商除了提供更通用的云服务外，还提供 BaaS 组件。
