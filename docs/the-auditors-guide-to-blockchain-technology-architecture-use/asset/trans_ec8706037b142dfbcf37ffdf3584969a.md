

### 第 5 阶段：实施区块链改进项目

| 阶段目标 | | | 实施区块链改进项目。监控、衡量并报告项目进度。 |
| --- | --- | --- | --- |
| 阶段描述 | | | 经批准的区块链项目可构建/采购并集成到企业中。通过项目管理治理，将项目融入常规开发生命周期。项目应与项目定义和变更计划改进保持一致。尽管这是耗时最长的阶段，但该阶段应是可控的，且其效益应在特定时间框架内交付。应监控区块链实施项目的绩效，并向相关利益相关者报告其进度。 |
| 持续改进 (CI) 任务 | | | **区块链改进实施：**<br>1. 制定区块链实施所需的全范围活动。例如：技能、程序、组织架构等。<br>2. 利用良好或最佳实践来调整和采纳指南，以最适配企业的政策和程序。<br>3. 实时测试区块链解决方案的实用性和可持续性。 |
| 变更赋能 (CE) 任务 | | | **赋能区块链的运行和使用：**<br>1. 利用通过识别快速获胜所获得的势头，稍后再引入复杂的变更方面。<br>2. 沟通快速获胜的成果，并认可/奖励团队。<br>3. 实施变更响应计划。<br>4. 确保角色执行者拥有正确的技能组合和资源。获得所有利益相关者的支持和承诺。<br>5. 沟通角色和职责。<br>6. 确保所有变更要求均已满足。<br>7. 监控变更赋能过程，并在必要时采取纠正措施。 |
| 项目组管理 (PM) 任务 | | | **执行区块链项目：**<br>1. 执行过程应依赖于项目的综合计划。<br>2. 指导和监控项目对各个项目组的贡献，以确保交付预期成果。<br>3. 及时、定期地向利益相关者提供报告。<br>4. 记录风险和问题，并集思广益制定补救措施。<br>5. 批准每个主要项目的启动，并告知利益相关者。<br>6. 批准项目组和项目计划的重大变更。 |
| 输入 | | | 1. 改进项目定义。<br>2. 变更响应计划定义。<br>3. 快速获胜文档。<br>4. 未批准项目记录。<br>5. 含资源分配的项目组计划。<br>6. 成功度量指标。<br>7. 项目定义、甘特图、变更响应计划、变更策略。<br>8. 集成的项目组和项目计划。 |
| 输出 | | | 1. 已实施的改进。<br>2. 已实施的变更响应计划。<br>3. 已实现的快速获胜。<br>4. 成功沟通。<br>5. 效益跟踪至实现 |

### 第 6 阶段：我们到达目标了吗？

本阶段应聚焦于区块链改进在治理和管理方面的可持续过渡。应重新评估第 3 阶段，以验证所有目标是否已达成。应使用绩效指标来监控已达成的目标。通过将新活动规范化为常规业务流程、程序和企业标准，整合区块链实施。应保持沟通渠道，以维持对新改进的认知（**表 11.11** 和 **表 11.12**）。

**表 11.11** 第 6 阶段：目标、描述、任务、输入、资源和输出

| **第 6 阶段描述 – 我们到达目标了吗？** |
| --- |
| 阶段目标 | | | 将区块链绩效指标和区块链实施的输出效益整合到绩效管理体系中。 |
| 阶段描述 | | | 利用平衡计分卡 (BSC) 等工具，通过 IT 和流程目标来监控项目（区块链实施）中的改进，这非常重要。还应维护效益登记册，以证明区块链实施后预期目标已达成。对于每个指标，都需要设定目标，并在实施期间持续与实时检查结果进行比较。绩效管理体系 (PMS) 的正面和负面结果都必须记录在案，以实现利益相关者透明度，建立信任，并在必要时采取纠正措施。应监控项目是否偏离里程碑，并在偏离轨道时及时指出。 |
| 持续改进 (CI) 任务 | | | **运行和衡量：**<br>1. 应为区块链实施的每个绩效指标设定目标并规定时限。应监控这些目标以确定区块链实施是否成功。<br>2. 记录指标数据。<br>3. 将目标与实际测量值对比，比较偏差。<br>4. 向利益相关者传达绩效管理的正面和负面结果，并记录纠正措施。 |
| 变更赋能 (CE) 任务 | | | **内化区块链实施的新方法：**<br>1. 确保区块链成为组织工作文化中运行的一部分，以产出更好的结果。<br>2. 从项目过渡到日常业务层面，组织在此纳入新变更，如修订后的职位描述、绩效标准、KPI 和操作程序。所有这些都应通过变更赋能计划来实施。<br>3. 监控已承担的新角色。<br>4. 监控变更并分析有效达成目标和目的的变更响应计划，例如通过反馈调查等。<br>5. 继续部门间沟通，以提高认知度并庆祝快速获胜。<br>6. 记录区块链实施过程中获得的变更赋能经验教训，以备将来参考。 |
| 项目组管理 (PM) 任务 | | | **实现区块链实施后的效益：**<br>1. 将区块链实施项目组的绩效与业务目标进行比较。<br>2. 观察成本与预算的对比以及通过实施实现的效益。<br>3. 记录实施过程中的经验教训，以备将来参考。 |
| 输入 | | | 1. 已实施的建议改进。<br>2. 变更响应计划。<br>3. 已识别的快速获胜。<br>4. 区块链项目变更日志。<br>5. 区块链业务论证效益。<br>6. 变更响应日志。 |
| 输出 | | | 1. 区块链项目组记分卡。<br>2. 因区块链实施产生的变更赋能措施。 |
