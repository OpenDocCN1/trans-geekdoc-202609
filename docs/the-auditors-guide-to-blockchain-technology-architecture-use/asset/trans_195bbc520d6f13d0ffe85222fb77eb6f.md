

### 第四阶段：需要完成什么？

本阶段提出实施区块链解决方案的适当方法。应在本阶段制定切实可行的区块链实施方案。这应通过定义由业务用例和变更计划支持的项目来实现。应通过产出可靠的业务用例进行持续监控。应制定变更响应计划，以赋能所有角色参与者。在构建拟议的区块链改进时，应识别关键角色参与者。

这些响应计划可能涵盖各种因素，如组织设计变更、团队结构、流程流和人员管理等变更。应识别区块链实施中的角色参与者，以实现快速见效。应制定清晰的区块链项目计划（参见[表 11.7](#ch19.xhtml#t27)和[表 11.8](#ch19.xhtml#t28)）。

| 持续改进 (CI) 任务 | **设计并构建区块链实施带来的改进：** 1. 考虑实施的收益和难度级别。 2. 根据收益和实施难易度编制机会网格，列出优先行动。 3. 将难以实施的改进分解为较小的项目。 4. 对改进进行优先级排序和选择。 5. 基于方法、交付物、资源等分析选定的项目，并细化改进需求。 |

| 变更赋能 (CE) 任务 | **赋能角色参与者并识别快速见效项：** 1. 通过研讨会和评审流程获得团队承诺并收集反馈。 2. 制定变更响应计划，以在整个区块链实施过程中进行跟踪和参与。 3. 挑选出见效项，表明区块链实施对环境的积极影响。 4. 识别区块链实施第二阶段的优势，避免用全新的实施重塑已识别的优势。相反，应将优势与当前改进相结合。 |
| --- | --- |

| 项目群管理 (PM) 任务 | **制定区块链实施项目群计划：** 1. 按顺序组织潜在项目群。 2. 采用投资组合管理技术，确保项目群符合战略目标。 3. 识别区块链实施对 IT 和业务的影响，并了解如何保持势头。 4. 制定包含迁移、测试、流程等在内的变更计划，纳入区块链实施项目群。 5. 根据原始成功因素确定绩效指标。 6. 协助分配流程和资源的优先级，以执行并实现项目群计划。 7. 建立项目计划和报告程序，以跟踪区块链实施项目的进度。 |
| --- | --- |

| 输入 | 1. 选定区块链流程的目标成熟度等级。 2. 改进流程的描述。 3. 风险响应文档。 4. CE 计划和目标。 5. 通过区块链实施的 4P（愿景、目的、计划和角色）传达愿景。 6. 详细的区块链业务用例。 7. 机会工作表、良好实践、外部评估和技术评估。 8. 上一阶段的优势。 |

| --- | --- |

### 第五阶段：如何达成目标？

本阶段实施拟议的区块链解决方案。这应通过日常活动以及建立措施来完成，以确保业务目标与区块链实施流程保持一致，并对其绩效进行衡量。

区块链在核心持续改进周期中实施，变更响应计划也随之实施。在区块链解决方案实施期间，对团队进行指导和辅导对于实现对愿景的承诺非常重要。

如果已达到目标，最初设定的区块链需求和目标应予以修订和分析。通过提高意识、参与、沟通以及管理层对区块链实施愿景的承诺来维持成功（参见[表 11.9](#ch19.xhtml#t29)和[表 11.10](#ch19.xhtml#t30)）。
