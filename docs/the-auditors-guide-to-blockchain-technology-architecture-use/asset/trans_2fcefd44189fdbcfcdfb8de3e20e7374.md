

# SHA-256

**SHA-256**：SHA-256 由美国国家安全局（NSA）开发。缩写“SHA”代表安全哈希算法，“256”代表 256 位输出，即 32 字节 [[75](#ch10.xhtml#r118)]。SHA-256 将长度短于 2^(64) 位的输入消息转换为 256 位输出 [[61](#ch10.xhtml#r104)]。它是对数字数据执行的一种数学函数。为了确认数据完整性，需将计算出的哈希值与预期的哈希值进行比较 [[75](#ch10.xhtml#r118)]。该哈希函数的主要特性是抗碰撞性，要找到一次碰撞，该算法大约需要运行 2^(128) 次 [[81](#ch10.xhtml#r124)]。然而，MD4 和 MD5 均不具备抗碰撞性 [[76](#ch10.xhtml#r119)]。

SHA-256 被用于许多区块链实现中 [[81](#ch10.xhtml#r124)]。它用于比特币协议的各种功能，如比特币挖矿、默克尔树和比特币地址生成 [[75](#ch10.xhtml#r118)]。

## 比特币挖矿

当区块创建者必须生成前一个区块哈希时，会使用 SHA-256 [[74](#ch10.xhtml#r117)]。为了生成前一个区块哈希，矿工使用以下公式 [[75](#ch10.xhtml#r118)]：

```
Previous Block Hash = SHA-256 (SHA-256 (Block Header))
```

## 比特币地址生成

公钥是比特币地址的基础。该密钥先由 SHA-256 哈希，再由 RIPEMD160（160 位竞赛完整性原语评估消息摘要）哈希。创建比特币地址的公式为 [[75](#ch10.xhtml#r118)]：

```
Bitcoin Address = RIPEMD160 (SHA256 (Public Key))
```

SHA-256 还用于创建安全套接字层（SSL）证书。这些证书用于建立和验证网站及在线服务的安全通信。在 SSL 证书中，加密组件由 SHA-256 创建。服务器与互联网服务提供商（ISP）之间的安全连接称为“SSL 握手”。信用卡号、登录详情及其他机密数据通过该链接受到 SHA-256 的保护。在该过程中，SHA-256 对所有用户信息进行哈希运算 [[75](#ch10.xhtml#r118)]。

# 默克尔树

默克尔树由拉尔夫·默克尔构想 [[82](#ch10.xhtml#r125)]。罗伯特·默克尔于 1979 年为默克尔树申请了专利。默克尔树通过为整组交易创建数字指纹，记录区块中的所有交易 [[64](#ch10.xhtml#r107)]。默克尔树类似于书籍的索引部分，因为它们允许用户检查某笔交易是否包含在区块中。使用默克尔树的一些哈希函数示例包括 SHA-0、SHA-1、SHA-2、RIPEMD 和 RIPEMD-160 [[6](#ch10.xhtml#r049)]。

## 默克尔树的工作原理

默克尔根或根哈希是通过持续哈希成对节点以生成默克尔树而留下的哈希值 [[64](#ch10.xhtml#r107)]。默克尔树中的每个节点都是一个哈希值 [[82](#ch10.xhtml#r125)]。节点分为两类：叶子节点和非叶子节点。叶子节点是单笔交易的哈希值，非叶子节点是前一个哈希值的哈希值。因为默克尔树是二叉的，所以需要相等数量的叶子节点。如果交易数量为奇数，则最后一个哈希值会被复制，直到产生偶数个叶子节点 [[64](#ch10.xhtml#r107)]。

在 [图 2.4](#ch10.xhtml#f10) 的一个区块中有四笔交易：A、B、C 和 D。每笔交易被哈希后存储在叶子节点中，分别为哈希 A、哈希 B、哈希 C 和哈希 D。通过分别哈希哈希 A 和哈希 B、哈希 C 和哈希 D，顺序成对的叶子节点被汇总，从而产生哈希 AB 和哈希 CD。哈希 AB 和哈希 CD 称为父节点。然后通过哈希哈希 AB 和哈希 CD（称为哈希 ABCD）来创建默克尔根。默克尔根随后存储在区块头中，用于检测交易数据是否被修改，从而维护数据完整性 [[82](#ch10.xhtml#r125)]。如果进行了任何修改，默克尔根也会随之改变 [[64](#ch10.xhtml#r107)]。

## 默克尔树的优势

默克尔树减少了对大量内存空间的需求；通过认证数据来证明完整性，且计算快速简便。区块链矿工/验证者在从其他成员接收交易时，可以稳定地计算哈希值。此外，区块链用户可以验证区块中的交易。因此，默克尔树管理只需在网络中分发少量信息 [[64](#ch10.xhtml#r107)]。

# 数字签名

数字签名是传统手写签名的电子表示形式。数字签名用于证明数据已由声称的“签名人”签署，并可用于确定数据在签署后是否被修改。该签名由计算机中的一系列比特组成，可针对传输的数据或从存储中恢复的数据创建。

- **声称签名人**：在签名信息经过认证、确认签名人真实身份之前，签名人被称为声称签名人。
- **密钥对持有者**：签名人也称为密钥对持有者，因为他们拥有一对公钥和私钥。
- **预期签名人**：打算在未来生成签名的个人或组织称为预期签名人 [[29](#ch10.xhtml#r072)]。

## 数字签名生成

密钥对持有者使用私钥生成数字签名。在数字签名生成过程之前，使用哈希函数创建消息摘要。消息摘要是待签名数据的简洁版本，用作生成数字签名的输入。生成消息摘要后，选择一种数字签名算法，并获取与该算法相关的其他信息（例如椭圆曲线数字签名算法）。预期签名人使用私钥、消息摘要、数字签名算法和其他详细信息生成数字签名。签名人可使用公钥验证签名，以识别数字签名生成过程中的计算错误 [[29](#ch10.xhtml#r072)]（[图 2.5](#ch10.xhtml#f11)）。

## 数字签名验证与确认

验证者执行数字签名验证和确认过程。验证者使用声称签名人的公钥来验证数字签名。签名生成过程中使用的数字签名算法的域参数从声称签名人或证书颁发机构（CA）获取。为了检查和验证数字签名，需生成一个消息摘要。该消息摘要使用与数字签名生成中相同的哈希函数创建。使用数字签名算法、域参数、公钥和新的消息摘要来验证数字签名。

在批准已验证的数字签名之前，验证者必须对以下几点有保证：

1. 签名人声称的身份。
2. ECDSA（椭圆曲线数字签名算法）域参数的真实性。
3. 公钥的有效性。
4. 私钥持有者即为声称签名人。

获取上述四项保证的所有方法均详见 SP（特别出版物）800-89。
