

# 延迟工作量证明

**延迟工作量证明** 是针对双重支付问题的另一种控制技术；这是由 **Komodo** 提供的一种安全解决方案，也是 dPoW 共识方法开发的催化剂。为了防御针对 Komodo 区块链的 51% 攻击，Komodo 链授权整个链来监管恶意活动。进一步解释，增加了一层额外的安全性，从而防止攻击者执行 51% 攻击，因为该安全链的关键属性是它不识别最长链规则。此外，还利用公证节点来验证哈希值对于网络是否安全。作为 dPoW 实施的一部分，全球选出 64 个特殊节点来执行所需任务 [[18](#ch21.xhtml#r464)]。

# PirlGuard 系统

**PirlGuard 系统** 是为 Pirl 区块链开发的一种安全协议，旨在解决 51% 攻击问题。该系统受 Horizen 惩罚系统启发，一旦攻击者通过私下挖矿过程创建了一条替代的更长链，并将其提交给处理节点，PirlGuard 系统将检测到欺诈尝试并丢弃恶意节点。然后，恶意对等节点将受到惩罚，被要求挖掘一定数量的惩罚区块。惩罚区块的数量根据攻击者通过私下挖矿创建的区块数量来确定。负责公证区块链的 Pirl 主节点也充当此类惩罚的执行者，以维护 Pirl 区块链上公平客观的共识机制。

# ChainLocks

**ChainLocks** 是为 DASH 加密货币开发的一种安全技术，旨在提供针对双重支付攻击的保护，同时提供即时交易确认。为了扩展活跃链，每个参与者都需要对广播的区块进行签名。独特的区块由大多数参与者（60% 或以上）验证，并生成 P2P 消息（**CLSIG**），以通知网络中每一个其他节点有关该事件。除非有足够数量的成员确认其有效性，否则无法生成 **CLSIG**。因此，有效的真实性签名包含在消息中，网络中的所有节点都可以验证签名。一旦达到确认，交易就无法作废或撤销。除了 51% 攻击，ChainLock 技术还有助于缓解各种安全问题，例如自私挖矿。

# 合并挖矿

**合并挖矿** 是另一种对低算力加密货币有益的技术。此类加密货币的算力可以通过将其引导至具有更高算力的其他一种或多种货币来增加。这种合并过程有助于缓解 51% 攻击。该过程涉及将区块链分类为父链和辅助链，其中两个网络是顺序进行的。此外，另一个好处是矿工能够同时挖掘多个区块，同时增强网络安全性。重申一下，使用合并挖矿技术构建了额外的安全性，因为两种加密货币的所有矿工都为总算力做出了贡献。中本聪原则的假设是区块链网络将始终包含大多数诚实节点。然而，这一假设被证明是错误的，因为除了矿池之外，单个攻击者也可能实现超过一半的网络算力 [[30](#ch21.xhtml#r476)]。

## DoS 攻击

在区块链上执行 DoS 攻击极其困难，因为区块链没有单点故障。这种类型的攻击只有在网络中存在可促进攻击的瓶颈时才会发生 [[1](#ch21.xhtml#r447)]。通常，区块链在特定大小范围内并以特定速率创建区块。攻击者可以创建大量垃圾交易，从而可能削弱网络。交易容量可能成为故障点，从而招致可能的 DoS 攻击。下文讨论的 DoS 攻击类别包括交易洪水攻击、出块者 DoS 攻击、许可链 MSP DoS 攻击和人为难度增加攻击。

*   **交易洪水攻击** 围绕向网络发送大量交易，从而增加等待添加到区块的交易队列大小。

*   **人为难度增加** 基于攻击者试图通过投入额外计算资源暂时增加区块链上工作量证明共识的难度级别，以推高所有其他节点的 PoW 难度，然后在 PoW 难度增加后移除额外计算资源，从而在区块链上制造流量拥堵。

*   **出块者 DoS 攻击** 涉及对权益证明区块链上的下一个出块者执行传统的 DoS 攻击，以阻止区块被添加到链上。

*   **许可链成员服务提供商 DoS 攻击**，顾名思义，是指对许可链 MSP 发起 DoS 攻击，以导致用户被拒绝访问区块链。

针对各种类型 DoS 攻击的缓解措施因其实施方式而异。对于交易洪水攻击，用户应尝试通过故意创建额外区块或等待攻击结束来清除队列中的洪水交易。对于人为难度增加，应持续监控并相应调整难度级别，以尽量减少攻击的影响。对于许可链成员服务提供商 DoS 攻击，可以对节点应用传统的 DoS 保护技术。此类传统做法包括构建更强大的网络基础设施，或更加重视更强的网络安全 [[32](#ch21.xhtml#r478), [24](#ch21.xhtml#r470)]。

## 日食攻击

在日食攻击中，单个节点与网络的其余部分隔离。因此，日食攻击助长了双重支付 [[24](#ch21.xhtml#r470)]。攻击者使用虚假的连接请求，强制连接重启，从而显著增加开销。在这种类型的攻击中，攻击者设法完全控制节点对分布式账本和网络操作的视图 [[7](#ch21.xhtml#r453)]。攻击者通常会对隔离节点执行双重支付攻击，或者可能执行拒绝服务攻击。攻击者也可能选择利用该节点的计算资源为自己的利益服务，这与区块链的共识算法有关。为了执行有效的日食攻击，攻击者可能需要适当的位置、额外的算力、规模或恶意软件。位置在日食攻击中很有帮助，因为攻击者可能有能力在用户消息到达区块链网络的其余部分之前，使用 WiFi 网络或物理电缆拦截这些消息。
