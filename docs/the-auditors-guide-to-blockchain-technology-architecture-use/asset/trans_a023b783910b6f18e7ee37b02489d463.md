

# 竞态条件攻击与区块链安全最佳实践

## 竞态条件漏洞

黑客利用系统竞态条件从在线银行、经纪公司、加密货币交易所，甚至免费的星巴克咖啡中窃取资金！在计算和区块链术语中，竞态条件是指最初应按顺序执行的两段代码以乱序方式执行的任何情况。进一步解释，在此类攻击中，调度算法能够在线程执行之间切换，因此难以预测执行序列将是什么样子。当竞态条件影响攻击者利用的安全组件，从而在适当的控制完成之前创建出执行敏感事件的情况时，竞态条件被视为一种漏洞。由于这一事实，竞态条件漏洞有时被称为 `time of check/time of use`（检查时间/使用时间）漏洞。换一种说法，为了绕过访问限制，可以采用竞态条件攻击。黑客经常对金融机构网站发起竞态条件攻击。如果在资金转账、现金提取或信用卡支付等关键功能上发现竞态条件，黑客可能会获取大量资金 [[19]](#ch21.xhtml#r465)。

## Lisk 漏洞

`Lisk 漏洞` 涉及一起竞态条件攻击。Lisk 是一种容易遭受攻击的代币，该攻击利用了两个内置功能。进一步展开，Lisk 使用用户公钥 SHA-256 哈希的最后 64 位作为其区块链地址。在用户执行交易之前，该地址不会在区块链上链接到特定的公钥。由于向账户汇款不会将地址链接到公钥，因此该系统变得脆弱。一些仅有正余额的账户保持未被触动状态。找到可链接到特定地址的公钥最多需要 2 的 64 次方次操作，“错误”可能允许黑客认领一个单独的地址。

在发现该问题后，Lisk 开发人员发布了通知，概述了该问题并鼓励个人采取措施将其账户地址链接到公钥。然而，Lisk 仍然容易遭受此类利用，包括竞态条件，即攻击者试图在为其提供资金的首笔交易和发送价值以认领它的交易之间获取地址 [[26]](#ch21.xhtml#r472)。

## 缓解措施

应锁定资源，以确保两个进程同时发生，并且不会因乱序执行而引发问题。此外，遵守安全编码和安全原则（如最小权限原则），并定期检查代码，将降低软件被攻破的几率 [[19]](#ch21.xhtml#r465)。

## 区块链安全最佳实践

各种攻击及其最佳实践列在 [表 13.1–13.4](#ch21.xhtml#t39) 中。

### 表 13.1 基于用户的攻击和最佳实践

| **基于用户的攻击** | **适用攻击** | **最佳实践** |
| --- | --- | --- |
|  | 私钥丢失 | • 可使用钱包来解决私钥安全问题，因为钱包可用于存储私钥。<br>• 应采用密钥轮换策略来解决私钥丢失问题 [[33]](#ch21.xhtml#r479)。 |
|  | 恶意软件 | • 当恶意软件被激活时，它会伴随需要删除的文件出现，相关进程应被终止并杀掉。<br>• 应定期检查和评估密码策略 [[8]](#ch21.xhtml#r454)。 |
|  | 未能更新区块链软件 | • 应定期修订更新策略。<br>• 所需的软件补丁应迅速应用，以保持软件最新。<br>• 应实施防病毒软件的使用以及电子邮件过滤 [[38]](#ch21.xhtml#r484)。 |

### 表 13.2 节点级攻击和最佳实践

| **节点级攻击** | **适用攻击** | **最佳实践** |
| --- | --- | --- |
|  | 共享漏洞 | • 检查点机制旨在通过要求节点定期在公认链上存储区块并拒绝接受不包含此类区块的任何分叉链来对抗此类攻击 [[26]](#ch21.xhtml#r472)。建议方法的主要概念是通过引入休会期（AP）使网络节点退出所有操作 [[31]](#ch21.xhtml#r477)。 |
|  | 成员服务提供商配置错误漏洞 | • SGX 的远程佐证功能有助于识别区块链上的每个节点为可信节点 [[13]]。<br>• 信任列表方法有助于区分黑名单和白名单节点 [[34]](#ch21.xhtml#r480)。 |

### 表 13.3 网络级攻击和最佳实践

| **网络级攻击** | **适用攻击** | **最佳实践** |
| --- | --- | --- |
|  | 51% 攻击（多数攻击） | • 延迟区块提交的惩罚制度将要求任何用户为延迟区块提交支付罚款。会考虑区块被隐藏的时间长短，并据此处以罚款。<br>• 延迟工作量证明：Komodo 区块链采用了延迟工作量证明（dPoW）安全解决方案。该解决方案的主要属性是它不遵循最长链规则；从而增加了一层额外的安全性，以防止恶意用户执行 51% 攻击。<br>• PirlGuard：修改共识算法以防御此类攻击。<br>• ChainLocks：ChainLocks 使用涉及“首次见到”策略的网络范围投票过程。所有参与者都需要签署注意到的区块以延长活跃链。<br>• 合并挖矿：允许多种加密货币合并其挖矿活动 [[30]](#ch21.xhtml#r476)。 |
|  | DoS 和 DDoS 攻击 | • 缓解 DoS 的传统做法包括适当的网络基础设施和网络安全，以及所需的系统冗余。<br>• 应通过创建区块将洪水交易从队列中移除 [[26]](#ch21.xhtml#r472)。 |
|  | 女巫攻击 | • 对现有和新成员进行直接和间接验证。直接验证验证区块链的即将加入的成员，而间接验证允许现有成员授予授权权利 [[1]](#ch21.xhtml#r447)。 |
|  | 重放攻击 | • 应在交易中加入 ChainID。未启用此钱包功能的用户将保持脆弱 [[29]](#ch21.xhtml#r475)。 |
