

## Hyperledger 特性

*   **模块化与可扩展框架** 旨在实现由可复用构建块组成的模块化和可扩展框架。这种模块化允许开发人员在开发阶段检查各个组件并做出相应更改。模块化策略允许多个开发人员在不同模块上工作而互不干扰。这样，模块就可以在不同项目中复用。

*   **可扩展性** 允许区块链网络交互并共享信息，以建立更复杂、更稳健的网络。为满足这一需求，Hyperledger 智能合约和应用程序必须能在多个区块链网络间扩展。这种高水平的互操作性将使满足对区块链和分布式账本技术日益增长的需求变得更加容易。

*   **定义良好的 API 集** 是 Hyperledger 项目的另一特性，从而增强了所有系统间的互操作性。这组定义良好的 API 允许外部客户端和应用程序简单、轻松地与 Hyperledger 的核心分布式账本基础设施进行交互。

## Hyperledger 工具

Hyperledger 生产并支持面向多种业务的区块链技术，包括提供工具和实用库。Hyperledger 方法促进了标准构建块的复用，推动了组件的快速修改，并鼓励项目间的互操作性。

**Hyperledger Caliper** 是一款区块链基准测试工具，通过将任意区块链实现与一组预定义用例进行比较来衡量其性能。Hyperledger Caliper 生成的报告将资源利用率、交易延迟和每秒交易数（TPS）列为其众多性能指标中的几项。Hyperledger Caliper 是基于一组客观且普遍接受的规则，首个用于评估各种区块链解决方案性能的通用工具。Hyperledger Caliper 并非旨在发布基准测试结果，而是设计为内部参考工具，以帮助选择组织应实施的、满足其特定需求的区块链技术。

**Hyperledger Composer** 是一个开放的开发工具集，支持对业务网络（包括参与者、资产和交易）进行建模。该模型使生成智能合约和区块链应用程序变得容易，允许在现有系统中快速集成——将部署时间从数月缩短至数周。Composer 还支持对现有业务网络进行快速建模，并将现有数据和系统集成到区块链应用程序中。Composer 协助现有的 Hyperledger Fabric 基础设施。

**Hyperledger Cello** 为区块链生态系统带来了按需部署和管理模块。Cello 通过提供创建、管理和终止区块链的自动化方式，帮助企业快速采用区块链技术。Cello 为用户提供实时仪表板，允许他们检查区块链系统状态、查看统计数据，并通过创建、配置或删除区块链来控制它们。Cello 主要支持的区块链实现是 Hyperledger Fabric；但它未来也旨在支持 Hyperledger Sawtooth 等其他框架。

**Hyperledger Explorer** 提供了一个可概览区块链网络的仪表板。它允许用户生成区块查询，以查看其中包含的详细信息。它还提供了网络活动的透明视图。借助 Explorer，用户可以识别、排查并快速解决生产问题。用户可以将 Explorer 与任何保证认证或授权的平台（无论是商业还是开源）协同使用。这种协作允许用户使用与其权限相关的功能。

Hyperledger Composer、Cello 和 Explorer 协同工作，为使用 Hyperledger Fabric 部署解决方案提供了端到端的工具包，长期目标是支持所有其他 Hyperledger 框架。

**Hyperledger Quilt** 是一款旨在为所有 Hyperledger 项目提供账本互操作性解决方案的工具，从而使 Hyperledger 成员的分布式账本解决方案、金融机构的私有账本、物联网公司的钱包以及供应链系统能够成功相互连接，以执行分布式原子交易 [[2]](#ch15.xhtml#r268)。

## Hyperledger 智能合约

智能合约任务可以像更新数据一样基础，也可以像完成带有多个约束的协议一样复杂。例如，智能合约可用于更新账户余额，也可用于验证账户中是否存在提款所需的资金。Hyperledger 框架使用两种智能合约：已安装智能合约和链上智能合约。

*   **已安装智能合约** 协助在网络启动前成功将业务逻辑安装到网络验证节点上。
*   **链上智能合约** 以交易的形式使用业务逻辑，该交易被提交到区块链，随后由后续交易调用。使用链上智能合约时，定义业务逻辑的代码被视为账本的一部分。

在五个 Hyperledger 框架中，只有一个不支持智能合约。支持智能合约的四个框架是 Hyperledger Burrow、Hyperledger Fabric、Hyperledger Iroha 和 Hyperledger Sawtooth。在所有四个框架中，交易请求均由智能合约层处理。该层还负责验证请求，这是通过执行业务逻辑来实现的 [[12]](#ch15.xhtml#r278)。

## Hyperledger 架构

如前所述，Hyperledger 项目基于一种强调模块化方法、互操作性、高度安全解决方案、无原生加密货币的代币无关方法，以及开发丰富且易用的应用程序编程接口（API）的设计理念。Hyperledger 架构的组件包括：

*   **共识层** 负责就请求达成一致，验证交易区块的有效性。
*   **智能合约层** 管理交易处理请求，并实施业务逻辑以确定交易是否准确。
*   **通信层** 处理参与共享账本实例的节点间的点对点消息传输。
*   **数据存储抽象** 允许其他模块访问和使用不同的数据存储。
*   **加密抽象** 允许以不影响其他模块的方式替换不同的加密算法或模块。
*   **身份服务** 有助于在区块链实例设置期间创建可信根，在网络中的任何活动期间准入和注册身份或系统实体，以及管理删除、添加和终止等变更。它还提供认证和授权。
*   **策略服务** 负责管理系统中列出的不同策略。这些策略包括背书策略、共识策略或组管理策略。它与其他模块交互并依赖它们以成功实施这些策略。
*   **API** 允许客户端和应用程序建立到区块链的链接。
*   **互操作** 允许各种区块链实例之间的互操作性 [[14]](#ch15.xhtml#r280)。
