

# 共识机制

## Proof of Importance (PoI)

与权益证明算法不同，PoI 不仅依赖用户在区块链网络中的质押量。相反，它通过密切监控代币的流动和使用情况来建立信任和重要性。因为它决定了网络中哪些节点有资格向区块链添加新区块，所以它与权益证明非常相似。然而，重要性证明还通过使用图论来确定每个节点的评级，从而考虑节点的重要性 [[79](#ch10.xhtml#r122)]。

## Proof of Storage (PoS)

存储证明机制衍生出了多种变体，如空间证明、时空证明、复制证明等。它允许将存储容量外包作为参与网络的条件 [[15](#ch10.xhtml#r058)]。

## Proof of Authority (PoA)

权威证明主要设计用于许可网络，根据验证者在区块链中的声誉和身份来选择交易验证者。有意向的验证者必须提供必要的文件以披露其身份和声誉 [[50](#ch10.xhtml#r093)]。

## Proof of Activity (PoACT)

活动证明通过结合工作量证明和权益证明算法，以统一但伪随机的方式选择利益相关者，以实现最大安全性。这种混合组合也确保了能源效率。

## Proof of Deposit (PoD)

存款证明简单指其他想要参与区块链的节点所作支付的证据 [[8](#ch10.xhtml#r051)]。存款证明支付被称为保证金，在任何节点创建新区块之前需要缴纳 [[3](#ch10.xhtml#r046)]。

## Ordering-based Consensus (OBC)

基于排序的共识与权威证明概念相似，因为基于排序的共识机制也主要用于许可网络。然而，它根据节点的身份服务来选择参与网络的节点 [[21](#ch10.xhtml#r064)]。身份服务指一种系统，其中处理节点因作为经过验证机构的成员而被识别并被视为可靠。

## Proof of Capacity (PoC)

容量证明也称为硬盘挖矿，因为它利用硬盘空间进行挖矿。PoC 是一种共识机制，允许网络中的处理节点验证交易，并根据可用硬盘空间确定挖矿权利。拥有更多闲置硬盘空间的节点可以挖掘可用的加密货币 [[13](#ch10.xhtml#r056)]。

## Practical Byzantine Fault Tolerance (PBFT)

实用拜占庭容错最早由 Miguel Castro 和 Barbara Liskov 提出，旨在通过投票机制在分布式系统中实现共识，如果状态发生变化，则提供安全性和活性 [[63](#ch10.xhtml#r106)]。然而，由于需要发送的消息数量会随着网络增长呈指数级增加，因此它不可扩展。该算法适用于异步系统（如互联网），并对系统进行优化，使其更高效、更有效 [[21](#ch10.xhtml#r064)]。

最大消息数计算如下：

```
M = 1 + 3F + 3F + (2F) (3F + 1) + 3F + 1
```

```
F = (n - 1) / 3
```

其中：

- `M` = 最大消息数
- `F` = 最大允许故障节点数
- `N` = 活跃共识节点数

PBFT 应与企业组织联盟一起使用，其中每个组织代表网络上的一个节点。在 PBFT 中，区块创建者可能不是任何特殊矿工，但提交给链的提议区块将是最受认可的区块 [[47](#ch10.xhtml#r090)]。

## Simplified Byzantine Fault Tolerance (SBFT)

简化拜占庭容错是对实用拜占庭容错 (PBFT) 的改进。它所需的消息量约为 PBFT 的三分之一，并能更快地达成共识——通常在 0.2 秒内。SBFT 共识中的每个节点都可以自主行动，无需与其他节点通信 [[62](#ch10.xhtml#r105)]。

SBFT 的消息计数计算如下：

```
M = (3f + 1) (2f + 1) + 1
```

其中：

- `M` = 最大消息数
- `F` = 允许故障节点数

## Delegated Byzantine Fault Tolerance (DBFT)

委托拜占庭容错由一种名为 NEO 的加密货币推广。它使用“记账人”——一组节点——通过代理投票达成共识，以在网络中生成更多区块。通过代理达成共识是指一种机制，其中被选为发言人的记账人提议其区块进行验证。发言人随后将区块发送给网络中的其他代表，以确认该区块有效。当三分之二的代表确认其有效性时，该区块将被添加到网络中。一旦共识确认，极少被撤销。交易生成速度也非常高——约每秒 1,000 笔交易 [[63](#ch10.xhtml#r106)]。

其容错计算如下：

```
F = (n - 1) / 3
```

其中：

- `F` = 允许故障节点数

## Federated Byzantine Fault Tolerance

联邦拜占庭容错用于国家间的关键金融交易。该协议中的节点保留一组公开受信的对等节点，并仅传播那些由最受信任节点验证的交易 [[13](#ch10.xhtml#r056)]。

# 密码学入门

密码学是在第三方（称为对手）存在的情况下保护信息的科学。密码学的主要目标是通过提供机密性、完整性、认证和抗抵赖性来确保数据安全 [[11](#ch10.xhtml#r054)]。如果双方（Alice 和 Bob）想要通信，Alice（此处称为发送者）使用不安全的通信信道向接收者 Bob 发送消息。该信道可以是计算机网络或电话线。如果消息包含机密信息，它可能被窃听者拦截并读取，或者更糟，消息可能被对手篡改，而 Bob（接收者）可能无法检测到这种操纵。密码学的目标之一是提供防止此类攻击发生的方法。

读者应熟悉以下密码学相关术语和概念：

- **Cryptosystem（密码系统）**：指加密和解密过程中所用密钥及技术的完整规范 [[49](#ch10.xhtml#r092)]。
- **Cryptoanalysis（密码分析）**：攻击者试图破解密码系统时使用的技术。成功的攻击可能从密文中恢复明文（或部分明文），然后用原始消息的部分内容替换，或伪造数字签名。Cryptology（密码学）常被用作指代密码分析的通用术语 [[49](#ch10.xhtml#r092)]。
- **Confidentiality（机密性）**：只有拥有密钥的人才能访问消息。如果消息在传输过程中被拦截，应受到保护，不被未授权方访问。机密性可使用高级加密标准 (AES) 和 RC4 等算法实现 [[37](#ch10.xhtml#r080)]。
- **Data integrity（数据完整性）**：消息接收者应能确认消息在传输过程中未被损坏、更改或截断，无论是故意还是意外。任何人都不应能用虚假消息更改原始消息或其部分内容。
- **Data authentication（数据认证）**：消息的来源应可由接收者验证。不应有人冒充发送者 (Alice) 向接收者 (Bob) 发送消息。发送者和接收者在发起通信时应能相互识别（实体认证）。消息认证码 (MAC) 算法可用于实现数据完整性和认证 [[37](#ch10.xhtml#r080)]。
