**摘要**——漏洞为我们提供了从元数据中提取信息的机会。从角度来看，应用元数据中缺失的信息可能是可疑活动的迹象，可以对其进行广泛分析。利用用户评论对此类不一致性的分析也有帮助。除了研究如何通过权限和元数据发现此类不一致性外，本研究提出了一种基于自然语言处理和循环神经网络的方法。

*索引术语*——摘要、描述-权限保真度、深度学习、自然语言处理、循环神经网络。

在语言处理（`NLP`）中，为了从 Android 应用的元数据中提取有意义的安全相关数据。

在本研究中，采用了一种基于 `NLP` 和循环神经网络（`RNN`）的新方法来寻找应用请求的权限与其元数据之间的不一致性。这个问题在文献中被称为“描述-保真问题” [3]。权限 [4] 是 Android 引入的重要安全机制之一，或者用户在使用之前必须授予权限。虽然权限要求在安装时授予，但在最近的 Android 版本（例如 Android 6.0）中，它们被要求在运行时授予。

我们期望 Android 开发者能够从元数据（如描述和策略）中获得更多关于权限使用的信息。此类可疑活动迹象的缺失可用于进一步的自动分析。这是本研究以及以往针对描述-保真度问题提出的研究的主要假设。在本研究中，使用循环神经网络来检测特定应用是否需要权限。作为比较，`LSTM` 模型利用了长短期记忆（`LSTM`）网络。我们对这些不一致性的主题总结如下。

## I. 引言

移动设备已成为我们生活中不可或缺的一部分。通过应用程序，它们提供了许多功能，如撰写/读取电子邮件、移动银行、寻找让生活更便利的功能。虽然 Android 以约 75% 的市场份额领先成为移动操作系统 [1]，但它是 [2] 使用的最流行的平台之一。

检测有两种主要技术：静态分析和动态分析。在设备或仿真器上运行应用以观察其运行时行为，而在静态分析中不运行应用，而是分析其代码。在应用包中使用静态方法分析文件。这两种技术都有其优缺点，可能会被规避技术绕过。除了应用的动态行为，Android 平台还提供了元数据让我们从安全角度分析应用：市场商店中的元数据，如描述、用户评论和评分、策略。在过去的五年里，我们开始看到自然语言处理（`NLP`）的应用。

首先，提出了一种使用深度神经网络的模型来检测请求权限与元数据之间的不一致性。第三节介绍了针对该问题的基于 `LSTM` 方法。第四节给出并讨论了所提方法在 `Ac-Net` 数据集 [5] 上的实验结果。本节还讨论了用户评论对结果的影响。第五节总结全文。

Google Pay、Android 官方市场和其他市场商店为用户搜索和下载应用提供了平台。这些平台也被攻击者用于分发恶意应用。在市场商店中，除了应用包，还有关于描述、评分、用户评论等其他应用信息。此类信息主要基于文本。在这里，我们总结了用于 Android 并针对权限-描述保真度问题提出的方法。

`Wyper` [6] 是自动分析应用描述到权限保真度的有效方法之一。我们利用自然语言处理方法来识别涉及特定权限并描述其所需的应用。为此，权限的一阶逻辑描述被转换为句子，使用基于关键词的方法与权限的语义组进行匹配，以实现描述到权限的保真度，并与 `Wyper` [6] 取得了相当的结果。其主要优势之一是它可以很容易应用到其他语言中。

`Cu` 等人提出的 `AutoConfig` 基于显式语义分析（`ESA`），该分析提供文本组的向量表示，给出文本中含义的表示。该模型使用应用描述的向量表示来评估应用是否需要某些权限。可以说 `AutoConfig` 优于 `Wyper`。`Feng` [5] 最近的一项研究是少数在我们之前应用自然语言技术来预测权限-描述保真度的研究之一。在这项研究中，`AC-Net` 使用了基于序列的神经网络——门控循环单元（`GRU`）。`GRU` [8] 是循环神经网络（`RNN`）的一种，用于建模序列数据。在当前研究中，我们使用序列数据来证明预测独立于基于 `LSTM` 的模型 `AC-Net`。此外，与 `AC-NET` 不同，这些研究的效果是显而易见的。

`Wang` 等人 [12] 提出了一种基于数据的方法来解释应用为何申请某些权限。我们利用语义分析来为他们的机器学习分类器提取相关特征，分类器输出一个类别的权限组。还有基于自动标准描述生成的方法 [12], [13]。`NLP` 也必须用于恶意软件检测。`Yu` 等人 [14] 提出了一种基于隐私策略和安全上下文的恶意软件检测系统。`Zhang` 等 [15] 的另一项研究使用自然语言生成根据权限组生成以安全为中心的描述。

其他研究检查了应用安全和隐私特征的影响 [91]。`Kong` 等 [9] 提出了系统 `AUTOBER`，从用户应用中推断隐私相关行为。`AUTOBER` 是一种机器学习算法，用于关联评论与隐私相关行为之间的关系。`Nguyen` 的一项研究使用了基于语言的模型将用户分类为安全隐私相关（`SPR`）或非 `SPR`。他们显示评论与隐私相关的应用更新之间存在强相关性。在最近的一项研究中，我们利用用户评论来理解应用为何请求权限。基于 `SmartPI` [11] 框架的建议 `NLP` 检测与功能的用户评论。

## III. 模型

所提方法的整体架构如图 1 所示，位于图 1 的右侧，标记的应用描述（即句子）经过预处理，然后基于训练的嵌入构建特征向量，并进入长期记忆（`LSTM`）。为每个权限构建基于 `LSTM` 的预测模型。在测试中（位于图 1 的左侧），新描述首先经过预处理，然后特征向量输入每个权限的预测模型。权限的预测评分用于判断该权限是否被识别为正确权限。

对于标记描述，本研究采用了 `AC-Net` [5] 数据集。该数据集的 1417 个应用的描述被手动标记为权限组。每个描述如果与相关权限组，则标记为 1；否则标记为 0。文献中的以往研究 [3], [6], `AC-Net` 将应用描述标记到比单个权限更大的权限组。这些权限组中有 9 个属于危险权限组。危险权限，2 个权限组属于签名和普通权限，表 1 显示了 `AC-NET` 数据集中使用的权限组、这些权限组对应的权限以及每组中的应用数量。在这里，还显示了句子总数和标记为 1 的权限句子数量。

`LSTMs` [16] 在记忆过去信息的同时过滤掉无关信息，同时也提供了此类网络来克服梯度消失问题。在我们的方法中，利用 `LSTM` 来处理本质上由序列和属性组成的应用描述。

首先，对应用描述进行预处理并输入到 `LSTM` 中。预处理任务包括句子提取、分词、标点符号移除、停用词消除、非字母字符移除以及词干提取；然后从预训练的词嵌入中获取嵌入，并将这些嵌入输入 `LSTM`。每个 `LSTM` 的输出是输入句子的复合表示，用以识别其语义。我们使用了双向 `LSTM`（`bidirectional LSTM`），其中一个 `LSTM` 按正向顺序处理单词，另一个 `LSTM` 按反向顺序处理单词；

```
$s_i = BiLSTM(x_{t,i})
```

在这里，$s_i = (x_{t,i})$ 是数据中的句子，$y_j$ 是句子中第 $j$ 个单词的嵌入。我们使用 $s_i$ 作为句子的复合表示。两个 `LSTM` 的最终隐藏向量拼接在一起形成句子表示 $s_i$。每个句子的复合表示从双向 `LSTM` 中获得，每个句子通过下述带有 `sigmoid` 激活函数的多层感知器进行分类：

```
$\alpha_i = sigmoid(MLP(s_i))$
```

其中 $\alpha_i$ 是预测值，被称为权限评分（`permission score`）。它是一个介于 0 和 1 之间的值，用于判断相应的权限是否在给定的输入中。如果它大于 0.5，则输出分类结果；否则输出为 0，因此句子中未说明该权限。

我们的任务是一个二分类问题。为每个权限类别都生成一个不同的 `LSTM`。

```
$-\ell = (y * \log(y)) + (1 - y) * \log(1 - y)$
```

在这里，$y$ 指目标，$\hat{y}$ 指预测输出。模型的架构如图 2 所示。

模型在 `DeepTorch2` 中实现。每个 `LSTM` 的输入维度为 300，隐藏层大小为 128。`MLP` 具有一个 128 神经元的隐藏层和 1 个输出层，输出为 1 表示句子中说明了权限，输出为 0 表示给定的句子描述中未提到该权限。我们随机初始化模型。
