

# NIST 网络安全框架与 IoT 监管

NIST，另一方面，作为商务部的一部分，在 2013 年国情咨文中，时任总统奥巴马宣布一项行政令，指示该机构开展网络安全和隐私框架的开发工作时，采取了行动。[^(80)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-552) 最初的设想是，NIST 与行业合作伙伴合作，制定一份自愿性的“网络安全框架”，供企业采用，以更好地保护关键基础设施。[^(81)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-553) 框架 1.0 版，即《改善关键基础设施网络安全框架》（NIST CSF），于 2014 年 2 月发布，旨在协调“共识标准和行业最佳实践，其支持者认为，这是一种灵活且成本效益高的增强网络安全的方法，协助关键基础设施的所有者和运营商评估和管理网络风险”。[^(82)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-554) 该框架由三个主要组成部分组成（框架核心、配置文件和等级），[^(83)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-555) NIST CSF 已被证明很受欢迎，自首次发布以来下载量已超过五十万次，[^(84)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-556) 并且在澄清美国及国外的网络安全注意义务标准方面具有影响力，帮助组织“识别、实施和改进网络安全实践，并为内部和外部沟通网络安全问题创建一种共同语言”。[^(85)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-557) 的确，NIST CSF 在理论上越来越“自愿”，但在实践中却越来越被要求，这一点可从特朗普政府 2017 年规定所有联邦机构必须使用它中看出。[^(86)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-558) 从英特尔到芝加哥大学等各种不同的组织都利用 NIST CSF 创建企业级热力图，解决已知风险，并确保持续的问责制。[^(87)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-559) 即使是交通部也利用 NIST CSF 评估车辆网络安全，尽管他们发现该框架必须进行重大调整，才能在开发适用于车辆的有用安全控制方面发挥作用。

此类案例凸显了 NIST CSF 的灵活性和影响力，这促使 NIST 于 2018 年 4 月发布了 NIST CSF 1.1 版。商务部长威尔伯·罗斯认为，这“应该是每家公司的第一道防线”。[^(88)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-560) 新版本拥有重大改进，包括在身份验证、供应链网络安全和漏洞披露方面，尽管它仍最好被视为网络安全的底线而非上限。[^(89)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-561) 例如，它并不特别关注 IoT 问题，这是许多（包括美国商会）希望 NIST 在其《物理系统网络安全框架》之外更详细地解决的领域，而该框架在 IoT 方面产生与 NIST CSF 对关键基础设施保护相同影响的可能性不大，或者说不够具体（或用户友好）。[^(90)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-562) 回应这一呼吁，NIST 发布了一份 IoT 网络安全基线草案，并在撰写本文时正在征求反馈意见。

即使这些机构通力合作，它们也没有权力解决 IoT 面临的全部网络威胁，即使利用现有的普通法索赔，如过失、违约和侵犯隐私也是如此。[^(91)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-563) 联邦层面的改革提案层出不穷，尽管长期以来一直存在一些角落对 IoT 特定立法的抵制。[^(92)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-564) 前 FTC 主席伊迪丝·拉米雷斯似乎特别支持“物联网”是事物自我监管的代名词这一观点。[^(93)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-565) 然而，FTC 已鼓励国会制定旨在激励采用隐私和安全最佳实践的自我监管计划。这些做法将保护个人信息和设备功能免受未经授权的访问，这些做法是“强大、灵活且技术中立”的，但包括关于公司如何就数据收集和使用实践向消费者提供选择的明确规则。[^(94)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-566) FTC 还领导了一项最初与奥巴马政府合作的推动，为信息作为更广泛的《消费者隐私权利法案》修订的一部分而被泄露的消费者提供联邦数据泄露通知法规。[^(95)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-567) 其他改革提案包括 2017 年《物联网网络安全法案》，该法案将要求向美国政府销售产品的供应商：(1) 确保其设备“可补丁”，(2) 不包含“已知漏洞”，(3) “依赖标准协议”，(4) 不包含“硬编码密码”。[^(96)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-568) 然而，该法案并未对监管像 IoT 这样广阔的领域采取一刀切的方法。的确，如果行业提供“等效或更严格的设备安全要求”，则可以使用这些要求来替代前述要求。[^(97)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-569) 该法案未能通过，但其两党赞助人，包括弗吉尼亚州的马克·沃纳，拒绝放弃，提出了 2019 年《物联网（IoT）网络安全改进法案》，该法案在撰写本文时尚未颁布，但值得注意的是，它缩小了“IoT 设备”的定义（例如，排除了智能手机和个人电脑），并从制定最低标准转变为指导 NIST 为“由联邦政府拥有或控制”的 IoT 产品的“适当使用和管理”提出建议，以纳入最低标准。[^(98)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-570)

其他法案也已提出以改善 IoT 安全，包括 2017 年《IoT 消费者 TIPS 法案》，旨在帮助 FTC 提升消费者网络卫生，以及《SMART IoT 法案》，该法案将要求美国商务部“对行业现状进行研究”。后者法案以一致票数通过了众议院，但未被参议院审议。[^(99)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-571) 美国政府问责局（GAO）建议美国政府进一步减少漏洞，包括：(1) 制定和执行更全面的国家和全球网络空间战略，(2) 缓解全球供应链风险，(3) 确保新兴技术的安全。[^(100)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-572) GAO 还支持为美国建立类似 GDPR 的隐私制度。[^(101)](#17_Notes.xhtml#actrade-9780190943813-miscMatter-10-note-573)
