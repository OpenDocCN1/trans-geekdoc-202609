
## Listing 3.4.

Real-life data are loaded from tab-delimited files. The files are saved on the author's ResearchGate site (https://www.researchgate.net/publication/360568958_SIV_overall and https://www.researchgate.net/publication/360568853_SIV_results). Once downloaded on a local directory, files can be loaded into the R environment using `read.table`. This function takes a pointer to the file in the form of a complete path to the local directory (absolute). Otherwise, unless the local directory where the files have been downloaded is R's default directory, it is possible to set the working directory using `setwd` and access the files from there avoiding to write the whole (relative) path. In the listing, not knowing the local directory, the current directory has been determined with the function `getwd` and passed as an argument to `setwd`. This procedure, essentially, simplifies R’s default directory as the working directory. In real life, the user can set the preferred directory and avoid writing down the whole path to the downloaded files. Alternatively, `read.table` takes a complete URL. Moreover, `read.table` is a generic function where the different parameters are as generic as possible. Other related functions such as `read.csv` and `read.delim` are specifically designed to read comma separated values (csv) and tab separated values (tsv) by setting the argument `sep` to comma (",") and tabulator ("\t"), respectively. The file `SIV_overall.tsv` contains the amplification data obtained from the thermal-cycler whereas `SIV_results.tsv` contains the quantitative cycles of all reactions. Each reaction is identified by a unique index. The `SIV_overall.tsv` file is loaded into the object *amplification* and `SIV_results.tsv` file is loaded into the object *validation*.

## Listing 3.6.

The amplification data cleaned from entries missing data, stored in the file amplificationCleaned.tsv in listing 3.5, is re-loaded into the R environment. The function callingShots allows the operator to visually inspect the amplification plot of a given reaction, input a coded label to it as either positive (1), negative (0), or uncertain (-1) and then move to the next sample. The implementation of the function is as follows. It is possible to choose the reaction number from where to start; thus, allowing the operator to screen the data in multiple sessions. The number of reactions from where to start is obtained from the terminal as direct input with the readline function and stored in the variable set_start. If set_start is empty, it is assumed that the operator wants to begin anew and the variable Start is set to one, otherwise Start takes the value stored in set_start. The vector that will contain the labels provided by the operator (shot_calling) is instantiated and the variable stopper will allow the operator to stop the function at will. The variables k and M are counters, with the latter being set to the number of reactions known to be present in the data set (120).

The data frame validation has a new set of columns derived from the results provided by the raters (rater_1, rater_2, in this case). A new column agreed is created by comparing the values of the different raters. If all the ratings across the different rating columns are the same, a label of value equal to the agreed rate (1 or 0) is given, otherwise -1. The data with the agreement label 1 are plotted and those with label 0 are drawn on top of them. The entries are stratified by factor.

## Listing 3.7.

A new directory data is created to store in an ordered way the files that will be required for the k-means classification. The analysis is limited to the reactions where the raters agreed, which is obtained by indexing the data frame so that the uncertain reactions are excluded (df$label != "Uncertain"). The k-means validation is obtained by generating 10 sets of data frames, stored in the new folder data. Each set contains a training data frame with 80% of the reactions and a testing data frame with 20% of the data. These sets contain the identification numbers of each reaction (index). The data sets are saved as RDS objects as an alternative to textual files and to reduce space in the hard disk.

Since the column label originally contained three levels (positive, negative, and uncertain) but now only has two levels (positive, and negative), the factors are overwritten with only two levels.

To give an example of the procedure, only the first set of data I loaded into memory using the variable i. The reactions with the index included in the testing data set are selected and stored in a new data frame (train_set); the same is done for the testing set. A new column is made by assigning 'negative' to the reactions without fluorescent signal, otherwise 'positive'; the classification is stratified by label.
