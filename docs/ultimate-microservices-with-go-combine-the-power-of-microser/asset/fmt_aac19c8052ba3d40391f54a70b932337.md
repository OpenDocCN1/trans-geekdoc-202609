
我们声明了一个名为 `PrintInterface` 的接口，包含 `Print()` 签名。当我们声明 `PrintableObject` 时，这是可行的，因为 `Person` 结构体实现了 `Print` 方法。另一方面，当我们尝试声明 `PrintableObject2` 时，会导致编译错误，因为 `DogPerson` 结构体不满足 `PrintInterface` 接口。

Go 语言中一个至关重要且广泛使用的接口是“空接口”。“空接口”是一种指定零个方法的类型，如下所示：`interface{}`

```go
var i interface{}
```

或者

```go
var myName interface{}
```

空接口之所以独特，是因为它可以容纳任何类型的值（每种类型至少实现了 0 个方法）。其主要用途是处理未知情况，我们将在本书中多次遇到此类情况。

# 函数选项模式

之所以决定专门关注此模式而非其他设计模式，主要有两个原因。第一个原因是，此设计模式在 Go 语言环境中相对独特，也是我们能想到的最常用的设计模式之一（也许单例模式或适配器模式更流行）。

该模式有助于清晰、精确地构建 `struct`。这是因为 Go 不支持重载（重载会创建同名但签名不同的函数）。此外，Go 的函数中没有可选参数。

这两个事实（不支持重载和可选参数）会使构建 `struct` 变得非常困难。构建结构体时，如果有许多配置（通常表示为可选参数），代码会变得一团糟。函数选项模式允许我们创建一个单一的结构体构造函数，它接收必需参数和一个可选参数列表。使用此模式的步骤如下：

1.  创建你想要的 `struct`。
2.  创建一个类型，其名称为结构体名称加上 `Option` 后缀（`{structName}Option`），定义为 `func(*{structName})`。
3.  创建构造函数 `New{structName}`，包含必需参数，并添加 `options …{structName}Option`，返回 `*{structName}`。
4.  为每个选项创建一个自定义函数。惯例是用 `With` 作为前缀命名这些函数。

让我们通过示例说明这些步骤；我们创建了一个购物客户端结构体，如下所示：

```go
type ShoppingClient struct {
    endpoint    string
    apiKey      string
    userId      string
    shouldRetry bool
    timeout     time.Duration
}
```

第二步是创建选项类型：

```go
type ShoppingClientOption func(*ShoppingClient)
```

现在，我们可以编写构造函数，如下所示：

```go
func NewShoppingClient(endpoint string, options ...ShoppingClientOption) *ShoppingClient {
    client := &ShoppingClient{
        endpoint: endpoint,
    }
    for _, option := range options {
        option(client)
    }
    return client
}
```

请注意，如果我们不提供任何选项，字段将获得其默认值，除了 `endpoint`（这是必需字段）。剩下的就是创建选项函数。

```go
func WithApiKey(key string) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.apiKey = key
    }
}

func WithUserId(id string) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.userId = id
    }
}

func WithTimeout(timeout time.Duration) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.timeout = timeout
    }
}

func WithRetry(shouldRetry bool) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.shouldRetry = shouldRetry
    }
}
```

让我们演示该模式的两种用法：

```go
client := NewShoppingClient("https://api.shopping.com/v1",
    WithApiKey("my-api-key"),
    WithTimeout(10*time.Second),
)
fmt.Printf("%+v\n", client) // &{endpoint:https://api.shopping.com/v1 apiKey:my-api-key userId: shouldRetry:false timeout:10000000000}

clientV2 := NewShoppingClient("https://api.shopping.com/v2",
    WithRetry(true),
    WithUserId("my-user-id"),
)
fmt.Printf("%+v\n", clientV2) // &{endpoint:https://api.shopping.com/v2 apiKey: userId:my-user-id shouldRetry:true timeout:0}
```

在示例中，我们创建了两个具有不同配置的客户端。我们在每个示例中仅应用了所需的配置，这就是该模式的优势。请记住这一重要的设计模式，因为它在本书后续内容中将变得非常实用。
