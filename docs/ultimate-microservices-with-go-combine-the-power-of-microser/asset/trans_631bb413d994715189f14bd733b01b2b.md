

# Goroutines 和 Channels

Goroutines 和 channels 是我们在 Go 中用于实现并发的核心概念。在本节中，我们将探索演示 Goroutine 执行的代码示例，研究运行 Goroutine 的限制，并讨论 Goroutine 泄漏的影响。

```go
func main() {
    go printHello() // Hello

    go func() {
        fmt.Println("Hello from anonymous function")
    }() // Hello from anonymous function

    time.Sleep(1 * time.Second)
}

func printHello() {
    fmt.Println("Hello")
}
```

就这么简单：只需使用关键字 `go` 然后调用一个函数。该函数可以像 `printHello` 这样声明，也可以是一个匿名函数。从我们执行它们的那一刻起，Go 调度器将管理这些 Goroutines。调度器负责分配新的 goroutine、将它们分配给线程、执行它们、在需要时暂停、处理它们之间的通信以及释放 goroutine。

一个普遍的问题是我们在 Go 中最多可以运行多少个 goroutine。答案是：视情况而定。回顾一下 [第 2 章，Go 的易用性](#c02.xhtml) —— 在幕后，我们有由 Go 调度器管理的线程。`GOMAXPROCS` 配置线程的数量；默认且推荐的值是我们运行程序的机器的核心数。假设上，我们可以运行任意数量的 goroutine，但我们必须考虑两个因素：内存使用和垃圾回收性能。

**内存使用** —— 每个 goroutine 使用 2KB，这意味着 1GB 内存的机器最多可容纳约 250K 个 goroutine。我们需要为运行程序的每台机器计算最大 goroutine 数量。

**GC 性能** —— 拥有的 goroutine 越多，垃圾回收会变得越来越慢。

关于最大 goroutine 数量的一个经验法则是介于 1,000 到 10,000 之间。

那么，什么是 goroutine 泄漏？Goroutine 泄漏是指垃圾永远不会被回收，因为它通过 channel 发送或等待接收数据。让我们先讨论 channels，再看看 goroutine 泄漏的实际案例。

## Channels - 有缓冲 vs. 无缓冲

描述 channels 最好的方式是将它们比作队列。它们的行为类似于队列 —— 我们可以向其中发送和接收项目。队列和 channels 的区别在于 channels 旨在促进 goroutine 通信。Channels 是 goroutine 之间通信、发送和接收数据的方式。

下面是一个示例，我们在其中创建一个 channel，向该 channel 发送数据，然后在主 goroutine 中从同一个 channel 接收数据：

```go
func main() {
    messages := make(chan string)

    go func() {
        messages <- "ping"
    }()

    msg := <-messages
    println(msg)
}
```

我们使用 `chan` 关键字来声明一个 channel。请注意，每个 channel 都有一个类型。在示例中，channel 的类型是 `string`，这意味着我们只能向其发送 `string` 类型的项目。使用语法 `<-`，我们将字符串 `ping` 发送到 channel 中。我们使用赋值语法 `:=` 和 `<-` 语法从 channel 接收数据。

在前面的示例中，我们使用了一个无缓冲 channel。

Golang 中有两种类型的 channels：有缓冲和无缓冲 channels。让我们来研究一下它们的区别。

```go
func main() {
    messages := make(chan string, 2)

    messages <- "ping"
    messages <- "pong"

    println(<-messages) // ping
    println(<-messages) // pong
}
```

要声明一个有缓冲 channel，我们应该使用以下语法：`make(chan type, int)`。`int` 是 channel 的大小。正如我们所见，channels 就像队列。Channel 的大小就是队列的大小，这意味着除非另一端有接收者，否则我们不能向 channel 发送超过其大小的项目。请注意，输出顺序像队列一样，而不是栈顺序（先进先出 FIFO，而非后进先出 LIFO）。

如果我们尝试向已满的 channel 发送项目，代码将会阻塞。除非有一个接收者 goroutine —— 它将解除发送者 goroutine 的阻塞。如果所有其他 goroutine 都保持阻塞状态，我们将进入死锁，Go 会通知我们。

```go
func main() {
    messages := make(chan string, 1)

    messages <- "ping"
    messages <- "pong"

    println(<-messages)
    println(<-messages)
}
```

我们唯一改变的是 channel 的大小。然而，如果我们尝试运行这段代码，将会得到以下错误：

```
fatal error: all goroutines are asleep - deadlock!
```

我们得到这个错误是因为我们尝试向已满的 channel 发送项目，而没有 goroutine 运行接收者来解除主代码的阻塞。现在，让我们看一个无缓冲 channel 的示例。

```go
func main() {
    messages := make(chan string)

    go func() {
        messages <- "ping"
    }()

    msg := <-messages
    println(msg)
}
```

声明无缓冲 channel 的方式与有缓冲 channel 完全相同，只是不声明大小。它们的区别在于无缓冲 channel 的长度为 0。在使用无缓冲 channels 和已满的有缓冲 channels 时，如果没有相应的接收者 (`<- chan`)，我们无法向 channel 发送项目 (`chan <-`)。

## 关闭 Channel

当我们创建 channels 时，它们默认是打开的。我们可以使用 `close(channel)` 语法来关闭 channel。关闭 channel 意味着我们不能再向 channel 发送数据，但仍然可以接收数据。

```go
func main() {
    ch := make(chan int)
    close(ch)
    ch <- 1 // panic: send on closed channel
}
```

关闭 channel 的目的是通知接收者发送者已完成工作，不会再发送任何项目。请注意，关闭 channel 必须仅从发送者一方进行，而不能从接收者一方进行。我们将在后面的章节更详细地讨论关闭 channel 的原则。

## Range 遍历 Channel

我们已经见过 `range` 语法的用法。我们可以使用相同的语法来遍历从 channel 接收的值，例如在接收者一方。

```go
func main() {
    ch := make(chan int, 3)

    for i := 0; i < 3; i++ {
        ch <- i
    }

    close(ch) // 如果你不关闭 channel，将会发生死锁！

    for i := range ch {
        fmt.Printf("%d ", i) // 0 1 2
    }
}
```

在示例中，我们向 channel 发送三个项目，然后通过 `range` 语法遍历接收到的值。

请注意两点：

1.  我们必须关闭 channel；否则，会导致死锁！如果我们不关闭 channel，`range` `for` 循环将永远卡住。发送者没有通知接收者他们已完成发送项目。
2.  关闭 channel 可防止数据被发送到 channel。它并不阻止从 channel 接收数据，就像我们在示例最后三行所做的那样。

## Select 选择 Channel

我们已经见过 `select` 语法的用法。我们可以使用相同的语法从多个 channels 接收数据。

```go
func main() {
    c1 := make(chan int)
    c2 := make(chan int)

    go func() {
        c1 <- 1
    }()

    go func() {
        c2 <- 2
    }()

    go func() {
        for {
            select {
            case <-c1:
                println("c1")
            case <-c2:
                println("c2")
            }
        }
    }()

    time.Sleep(1 * time.Second)
}
```

这两个 goroutine 可以随时通过各自的 channel 发送数据。我们需要另一端有一个单一机制，能够知道从多个 channels 接收数据。`select` 语法就是该用例的解决方案。我们可以在示例中看到如何利用它。

## Channels 方向

在将 channels 用作函数参数时，我们可以指定 channel 的方向。

```go
func main() {
    ch := make(chan int, 1)
    send(ch)
    recv(ch)
}

func send(ch chan<- int) {
    ch <- 1
}

func recv(ch <-chan int) {
    fmt.Println(<-ch) // 1
}
```

我们使用语法 `chan<-` 来指定我们可以接收一个 channel 作为参数，但只能向该 channel 发送数据。
