
尽管如此，必须注意 Go 语言可能并不符合这一情况，因为它偏离了这种常量扩展的模式。

查阅 Go 语言的发布说明后会发现，大多数更新主要集中在编译增强、性能改进和准确性优化上。虽然确实引入了一些新特性和功能（一个显著的例子是泛型），但它们并不构成变更的主体。这种对简洁性的强调正是 Go 语言的追求。他们希望保持 Go 语言**枯燥**（boring）。

Go 语言简洁性和极简主义的一个例子是语言的关键字数量。下图展示了关键字数量的对比。

如果一种编程语言拥有许多关键字，并不一定意味着它是一门糟糕的语言。反之，关键字数量少也并不自动意味着它是一门优秀的编程语言。编程语言的质量和有效性取决于许多因素，而不仅仅是它拥有的关键字数量。

但可以肯定地说，关键字越少，越容易记忆和使用。我们可以看到 Go 语言是关键字最少的语言之一。

## 隐藏的复杂性

语言内部包含许多概念，为了在打造一门强大的编程语言的同时保持语言的简洁，投入了大量精力。

并发模型是隐藏复杂性的绝佳例子。我们将在本章后面详细讨论并发模型。它仅需三个按键即可实现并发——'`g`'、'`o`', '` `'——这令人惊叹。

另一个极致简洁的例子是访问修饰符。共有两种场景：函数/变量/常量可以是私有的或公有的。在 Go 语言中，要使某个标识符公开，只需做两件事：

*   它需要声明在最高作用域。
*   它需要以大写字母开头。

仅此而已；无需额外的关键字。

Go 语言中的其他一些简洁特性：

*   垃圾回收
*   常量
*   接口
*   包

所有这些示例背后都隐藏着巨大的复杂性。

总结本节，Go 语言不在功能上竞争。“*至于 Go 1.0，语言规范已冻结。*”

# 适合云环境的快速语言

> *“Go 语言快速、有趣且高效。”* —— Ken Thompson。

这是发明这门语言的核心原因之一：提供一门可以在云端并发运行的快速语言。

我们将详细阐述使 Go 语言如此快速的三个方面：

*   编译速度快
*   类似 C 语言
*   并发模型

## 编译速度快

Go 语言不仅旨在运行时快速，还极其重视编译速度，这类似于敏捷方法论的理念，即显著提高发布频率。

那么是什么让它编译得如此之快？是什么让二制制文件如此精简？原因如下：

*   避免循环依赖
*   编译设计
*   未使用的导入和声明
*   Go 语言的简洁性

### 避免循环依赖

如果我们尝试以循环方式导入包，将会遇到编译错误。如果存在循环依赖，Go 语言无法编译。所有依赖都可以表示为一个 DAG（即有向无环图）。由于这种包结构，只有当树中的所有包都已编译完成后，每个包节点才能被编译。

在该示例中，包 A 和 B 已经编译完成，我们可以并发编译 C、D 和 E。

### 编译设计

引用 Golang FAQ 中对“为什么要创建一门新语言？”的回答：

> *“最后，使用 Go 语言旨在追求速度：在单台计算机上构建大型可执行文件最多应只需几秒钟。实现这些目标需要解决许多语言层面的问题：表达能力强但轻量级的类型系统；并发和垃圾回收；严格的依赖规范；等等。这些无法通过库或工具很好地解决；因此需要一门新语言。”*

正如我们所见，创建 Go 语言的主要原因之一是开发一门易于使用的快速语言。这种理念始终存在于 Go 团队的脑海中。

### 未使用的导入和声明

在 Go 语言中，我们不能导入未使用的包，也不能声明未使用的变量。这两种情况都会导致编译错误。Go 语言仅编译必要的依赖，从而实现精确编译，避免编译未使用的依赖。

### Go 语言的简洁性

如前所述，Go 语言以其简洁性著称。它仅包含约 25 个关键字，这使得编译过程更加直接。这种简洁性在编译时间上带来了显著的回报。

## 类似 C 语言

有人可能会将 Go 语言描述为 C 语言的现代版本。虽然许多其他语言通常使用类和继承，但 Go 语言采取了不同的方法，利用结构体和接口配合组合。Go 语言从 C 和 C++ 继承了各种元素，例如数据结构、指针、按引用或按值传递的能力等。

C 和 C++ 以速度著称，Go 语言旨在达到类似的性能水平。然而，它也力求成为一门现代且用户友好的语言，使编写代码更加容易，从而提高生产力。

## 并发模型

并发是 Go 语言的首要任务。通过 Goroutine 和 Channel，Go 语言使并发编程变得简单高效。Goroutine 是由 Go 运行时管理的轻量级线程，允许多个任务独立运行。Channel 是 Goroutine 之间通信的方式，实现了安全且同步的数据交换，从而构建更快、更具扩展性的应用程序。

Goroutine 和 Channel 是一等公民。并发是 Go 语言旨在建立并做好的核心概念之一。我们将简要探索 Go 语言独特的并发模型。

Go 语言是一门多线程语言。然而，Go 语言与其他语言不同，作为开发者，我们无法直接访问线程。这是基于“线程是操作系统的资源”这一理念实现的。在 Go 语言中，我们不应关心线程。当然，也有需要担心的地方，比如不同 Goroutine 对同一对象的访问（`sync` 核心库应通过锁、唯一对象等帮助解决这一问题）。

另一个担忧是 Goroutine 泄漏。我们将在后续章节中解决这两个问题。

那么，什么是 Goroutine？Go 团队通过 Goroutine 封装了传统线程。它们在资源使用和初始化方面极具成本效益。

关于内存占用，初始化 Goroutine 栈仅需 2 KB，而默认线程栈为 8 KB。这轻量了 4 倍！Goroutine 内存轻量的直接效果是，分配和释放它们比线程快得多。

Goroutine 具有革命性，完全由 Go 运行时管理而非操作系统。它们拥有便捷的通信机制、轻量级内存、快速初始化，且不依赖硬件。

为了解释 Goroutine 的工作原理，让我们谈谈 Go 调度器。它是 Go 运行时中的一个组件，拥有对内核的直接访问权，负责管理我们执行的每一个 Goroutine。

Goroutine 被调度在线程上，调度器负责将它们分配到线程上。
