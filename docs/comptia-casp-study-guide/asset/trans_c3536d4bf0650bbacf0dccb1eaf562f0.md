
# 如果存在一种漏洞，允许恶意代码从沙箱外部的隔离环境中执行，强制运行代码或实现某个功能，会怎样？

2020年9月，谷歌向两名研究人员颁发了20,000美元的漏洞赏金，因为他们在Chrome网络浏览器中发现了一个`sandbox escape`（沙箱逃逸）漏洞。该漏洞编号为CVE-2020-6573，被描述为高严重级别。在该特定案例中，多个漏洞的组合导致了远程代码执行，并在浏览器的渲染进程中启动了任意代码。在沙箱逃逸漏洞中，攻击者可以从环境外部的沙箱执行恶意代码，强制设备在其中运行代码。

## 不当的错误处理

安全的很大一部分在于建立良好的控制来检查所有输入数据（输入验证）、处理后的数据和输出数据。然而，即使做对了这些，你仍然必须处理潜在的错误。有时应用程序开发人员就会在这里遇到麻烦，因为他们向用户提供了过多的信息。例如，如果我们访问一个处理身份验证的网页并输入错误的密码，应用程序是响应“密码错误”，还是响应更模糊的错误“用户名/密码错误”，后者会让入侵者稍微难一些？以下是此类问题的几个例子。首先是`httpd.conf`文件：

```
<location /server-status>
SetHandler server-status
</Location>
```

此配置文件允许任何人查看服务器状态页面，其中包含关于Web服务器当前使用情况的详细信息。另一个例子是许多Web服务器上都能找到的`php.ini`文件。启用后，该文件会提供冗长的错误消息：

```
display_error = on
log_errors = on
Error_log = syslog
ignore_repeated_errors = Off
```

必须始终测试应用程序的极限，以查看返回什么响应以及显示什么错误消息。

## 地理标记

`Geolocation`（地理定位）和基于位置的服务是CASP+的另一个关注点。这项技术包括给照片添加地理位置标记的能力。大多数智能手机和平板电脑用户在激活设备时会开启此功能，但他们从未意识到该信息会用在他们拍摄的每一张照片中。大多数人没有意识到智能手机上的`geotagging`（地理标记）处于激活状态，要么是因为它默认启用且未作为选项暴露给用户，要么是因为他们被要求启用它随后就立刻忘记了。结果，个人经常分享过多信息，甚至精确到他们的具体位置。

安全顾虑在于，黑客或其他人可能有能力追踪特定个人的位置。如果你觉得这听起来有点毛骨悚然，那确实如此！有一个名为Creepy（`www.geocreepy.com`）的应用程序，允许用户利用个人在网上发布的照片来追踪其行踪。Creepy从社交网络站点收集地理位置相关信息，并使用Google Maps展示结果。

许多应用程序也利用这项技术来识别用户的确切位置。其理念是你可以通过位置来识别用户，以提供服务或获取收益。例子包括附近咖啡店和餐厅的优惠券。

## 拦截/劫持

`Interception`（拦截）被Merriam Webster定义为“阻止某人或某物继续前往目的地的行为或事实”。攻击者拦截我们信息的方式有很多，且难以检测。拦截可以针对传输中的数据或静止的数据实施。

消息拦截攻击利用网络中的弱点。如果你能拦截消息，想想数据包嗅探或按键记录，你就能获得有价值的信息。

会话劫持是拦截和注入的结合。它允许攻击者在身份验证完成后接管现有连接，从而绕过密码保护。

BGP用于交换路由信息，但被认为已过时且不强制使用加密。边界网关协议（BGP）劫持，有时称为`prefix hijacking`（前缀劫持）或`IP hijacking`（IP劫持），发生在攻击者将Web流量从其预期目的地重定向时。相反，它将传入请求发送到攻击者自己控制的IP地址。网络犯罪分子很容易冒充受害者的IP地址，并冒充受害者进行网络钓鱼和垃圾邮件发送。

尽管电子邮件有许多很棒的功能，并提供了以前不可能的通信水平，但它也并非没有问题。现在，在我们过多指责它之前，你必须记住电子邮件是在不同的时代设计的。几十年前，安全性不像可用性那样是主要驱动因素。默认情况下，电子邮件以明文发送信息，因此容易受到窃听和拦截。电子邮件很容易被伪造，从而掩盖发件人的真实身份。电子邮件也是垃圾邮件、网络钓鱼和病毒的主要渠道。垃圾邮件是未经请求的批量邮件。

## 点击劫持

`Clickjacking`（点击劫持），或UI redressing（UI重绘/界面伪装），在Wikipedia中被描述为“一种恶意技术，诱骗Web用户在点击看似无害的网页时泄露机密信息或让攻击者控制其计算机。”这种攻击通过控制用户访问网页时所看到的内容来实现。攻击者构建页面的方式使得他们能控制用户能看到哪些链接或按钮。受害者点击一个可见的链接，但实际上他们选择的是另一个对他们不可见的链接。这得益于攻击者设计网页的方式。本质上，攻击者构建了一个页面，用户所看到并点击的内容并不反映该点击实际执行的操作。

点击劫持针对状态管理。状态管理指对图形用户界面中一个或多个用户界面控件（如按钮、图标或选择选项）的状态进行管理。如果攻击者能遮挡受害者选择的项目，用户就无法知道按钮是否处于启用状态，或是否已做出有效选择。在许多情况下，安全专业人员可能无法控制应用程序的开发，只能寻找防御漏洞的方法。为了防御基于Flash的漏洞，请在Flash Player插件的全局隐私设置中设置“Always Deny”（始终拒绝）选项。其他防御措施包括禁用插件和使用诸如NoScript（`noscript.net/`）之类的工具。

## 会话管理

当攻击者破解Web应用程序的会话管理机制以绕过身份验证控制并冒充合法用户时，就会发生`Session management`（会话管理）攻击。通常使用两种会话管理技术：

*   会话令牌预测
*   会话令牌嗅探和篡改

当令牌遵循可预测的模式或按数字递增时，会发生`Session token prediction attacks`（会话令牌预测攻击）。如果攻击者能发起大量请求，可能更容易确定Web应用程序使用的模式。

在某些情况下，令牌可能未加密，甚至可能使用弱编码，如十六进制编码或Base64。攻击者也可能尝试使用Wireshark或Burp Proxy等工具直接嗅探有效令牌。

如果使用了HTTP Cookie且未设置安全标志，攻击者可以尝试重放Cookie以获得未经授权的访问。其他会话管理问题包括：

*   **会话ID放在URL中** 某些网站对会话ID进行编码并将其放在页面的URL中。
*   **超时利用** 如果受害者使用公共电脑且只是关闭了浏览器，网站可能不会注销用户，从而允许攻击者重新打开站点并获得完全访问权限。
