

### 8.2.1 计算智能算法开发的萌芽平台

在所述领域，研究重点是通过发现新型 CI 系统平台、CI 系统硬件元素、基础设施以及根据 CI 系统需求的可扩展网络，来实现对数据密集型应用的可靠低延迟数据处理。雾计算和云计算被用于实现高效的数据处理管理以及降低大规模应用的架构限制。通常在数据密集型系统中，数据是由传感器和物联网设备组成和产生的。这些由物联网设备组成或产生的数据是海量数据，要积累这些数据组织必须需要额外的存储。这种存储和处理如此庞大数据量的设施由数据中心提供。通过虚拟化，基于云的设施提供软件资源。一旦传感器或智能设备不断产生或收集数据，就需要额外的网络带宽，并且在数据传输到云或存储服务器时会出现更多延迟。在这些场景中，数据由边缘设备在网络边缘附近进行过滤，并且仅通过网络将经过过滤的有用数据传输到云或服务器，这种状态称为主动存储或雾计算或物联网应用中的边缘计算。它是云-IoT 融合的继任者。边缘计算在从边缘设备向云服务器或存储服务器传输数据的阶段是有益的。然而在将数据从存储单元传输到计算单元（可能是服务器，联邦系统利用存储单元中存储的数据）的情况下，传统上完整的整个数据集需要作为输入提供给应用程序，而不管数据集大小如何，而不是仅将有用的数据集从存储发送到处理单元。这是不合理的，因为它放大了延迟并占用了相对更大的网络带宽。

为击败这一问题，NDP 进入视野。在 NDP 系统中，部分数据处理在原位运行，这意味着在数据存储单元内部/附近运行。它在 8.2.4 节中得到了更详细的阐述。

### 8.2.2 安全

在原位存储处理的情况下，在数据、硬件框架、处理器上下文切换和操作系统（OS）等各个阶段需要额外的安全保障。需要进行安全检查后存储的数据用于数据集中 ML 应用。之前曾采用一些安全方式，如加密、基于角色的身份验证或随机标记化和控制。然而，提到的安全方法对 ML 应用没有帮助。对于 ML 应用中敏感数据的保护，各种方法可能有所帮助，即消除敏感数据、覆盖或伪装数据，或数据粗化（降低数据粒度或数据精度，目的是使识别相应数据集中包含的敏感数据变得困难）（Google cloud，线上 [https://cloud.google.com/solutions/sensitive-data-and-ml-datasets](https://cloud.google.com/solutions/sensitive-data-and-ml-datasets)）。

大量对 ML 应用等应用有用的数据通常存储在数据中心。数据中心的安全可以通过将物理安全与逻辑/数字安全相结合来实现。这里，逻辑安全与数据相关。国际标准化组织（ISO）已创建了专门用于信息安全的模型 ISO 27001。信息安全是 ISO 27001 预先考虑用于各种基础设施或框架中，尽管它没有提供数据中心安全的任何具体标准（[Achmadi et al., 2018](#bodymatter-008.xhtml#b_9783110648195-008_ref_009)）。新的安全标准在 [Lontsikh et al., 2016](#bodymatter-008.xhtml#b_9783110648195-008_ref_029) 中设计，即信息安全管理体系（ISMS）。ISMS 组成主要旨在管理数据中心框架的数据完整性、数据可用性和数据隐私。与其他 ISO 标准化类似，它涉及运行流程和技术框架以保护存储在数据中心中的信息安全。

提供了一些高度先进的解决方案，例如去中心化数据中心（DDC）。为了克服传统方法数据中心中的主要安全问题，可以使用 DDC 概念通过区块链技术和智能合约将数据中心虚拟化（[Rygula et al., 2017](#bodymatter-008.xhtml#b_9783110648195-008_ref_028)）。区块链可以被描述为一种数据结构或分布式账本技术，它生成关于合同的数字防篡改记录。国际商业机器公司私人有限公司（IBM）中提出的另一种方法为可信虚拟数据中心（TVDc）。TVDc 由 IBM 设计和创建，以满足数据可靠性以及数据远程性的需求，必要时在虚拟环境中提供更多安全性（[Perez et al., 2008](#bodymatter-008.xhtml#b_9783110648195-008_ref_033)）。

### 8.2.3 满足数据爆炸

在这些日子里，在社会领域，物联网应用也被实施和使用。这些实时应用以前用于延迟问题不存在的应用领域，或者在应用中未占用大量数据，如操作路灯、显示一些广告等。然而由于数据需求增加，功能难度增大，并且与大数据生产和编译成正比。例如类似人类健康监测和预测或 DSS，即决策支持系统，需要额外的数据需求用于分析目的。如此大量的数据需要积累在数据中心或用于存储的任何云服务器上。对如此庞大数据进行的计算可能对组织而言在安全和网络带宽等方面代价高昂，因为数据通过网络传输。对于智能或智能应用，先决条件 ML 可能会与 EH 配对。上述领域也进行了活跃的研究。数据中心主要旨在积累大量和分散的数据。NDP 将适合击败这一问题。在 NDP 系统中，部分数据处理在原位运行，这意味着在数据存储节点内部/附近运行。NDP 通过缩小网络带宽限制来改善系统性能。

### 8.2.4 近数据处理（NDP）/原位处理数据

由于 ML 或数据密集型系统中使用的数据是巨大的，从存储系统向主机处理单元传输数据的发生是一个日益增长的关注点。原位处理或 NDP 是硬件系统和软件栈的结合，取决于与存储节点和计算单元的集合。有 NDP 的子类型，即内存中处理和存储中处理。
