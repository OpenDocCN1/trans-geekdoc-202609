
All the work done in this domain marks that the medical domain utilizes a large corpus of words from the clinical/medicinal domain such as radiology, dental science, and pediatrics. A specialized corpus for development of S2S in the medical domain has to be created. We define the pipeline architecture used for S2S system to provide translation from Hindi to English and vice versa. The system discussed here works for speech translation between the patient’s language and that of the medical practitioners. The system provides end-to-end translation but has the facility at each intermediate level for evaluation and correction by human interpreters. This feature helps in identifying the error patterns and directs for further improvements. With time, when the errors are rectified, we look forward to removing the provision for human interventions. This can only be achieved when all the three models: `ASR`, `MT`, and `TTS` are tuned to perform perfectly.

### 4.5.1 Medical corpus creation

In the initial phase, we have avoided the fully conversational speech due to disfluencies, fillers, and other factors that make it difficult. The question–answer corpus mainly consists of queries that are raised by patients to be answered by medical practitioners and also questions based on history and symptoms queried by doctors and replied by patients. ### 4.5.2 Experimental setup

The pipeline architecture of the system starts with the `ASR` module that receives input for training the system. The `ASR` module of this system is built using `Sphinx3`, an HMM-based speech recognizer. The `SphinxTrain` module is provided with the phone list, mapping dictionary, filler dictionary, phonetic transcript of the wave files, and speech recording files. The trainer uses these files to learn the parameters and the decoder of the `Sphinx` that produces the most appropriate sequence of words for the test input. The bilingual `MT` module is built using `NLTK` toolkit. The module is implemented using rule-based translation for English to Hindi and Example-based translation for Hindi to English. The challenging `TTS` module has been built using `Festival` and `Festvox` framework. To produce a human-like speech, the HMM-based `TTS` module receives the input text produced by the `MT`, and the phonetic representation is further marked into prosodic units. `WaveSurfer` is used at this level for manual alignment of labels and phones. [Figure 4.8](#bodymatter-004.xhtml#b_9783110648195-004_fig_008) represents the manual labelling performed on English sentence using `WaveSurfer`. The prosodic unit is used to produce natural speech for the input text. The overall architecture demands a list of phone sets for both the languages used in the system.

### 4.5.3 Performance evaluation

Each component of the translation system is evaluated separately. Since the overall performance of the system is dependent on the performance by each unit of the pipelined components, we have evaluated the component performance individually. This evaluation also helps in identifying the component, which requires more attention to further improvements. The `ASR` component performance is evaluated in terms of `WER%`, which takes into account the count of inserted, deleted, and substituted words. The performance of the `MT` component reliability is judged using `METEOR`, a method that is highly correlated with human evaluation. It takes into account the precision and recall, assigning more weights to recall. `TTS` component was evaluated using a perception test. Ten listeners were identified, and the speech synthesizer for the input samples was played for them. They were asked to judge the sample on a three-point measuring scale that ranged from unclear speech, difficult to comprehend, and understandable speech.

A randomly selected 30 question–answer-based samples and 50 phrasal sentences were used for testing the data for both the languages. The evaluation was done in six iterations with each iteration of same sample size and sample selection were done on random basis. [Figure 4.9](#bodymatter-004.xhtml#b_9783110648195-004_fig_009) presents the performance of each of the `ASR`, `MT`, and `TTS` component in all the six iterations. The average `WER` of the `ASR` module turned out to be 0.6743, that is, the average accuracy of the `ASR` system is 67.43% for Hindi speech recognition and for English it was obtained as 72%. This low performance may be attributed to ambient noise or also to the device microphone quality as the recordings were done using mobile phones.
