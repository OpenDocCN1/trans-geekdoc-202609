### 16.5.2 Redirecting after image

The last bug we are going to address before getting back to production setup is one found after upload images. Whenever we upload images, our code will currently render the edit view again, but our code never refreshes the list of images for that gallery. As a result, we will see a “success” alert after submitting the form, but we won’t see any images. Realistically, we should be doing after a successful upload is redirecting back to the edit page. The downside is that we don’t have a way to redirect a user and show an alert message. We won’t be introducing this until the next chapter, but we are going to update our code to redirect a user rather than displaying an alert, as this is much more usable version of the code.

Note: If you are following the screencasts you may already be doing this. Open up your galleries controller file.

```go
controllers/galleries.go
```

Find the ImageUpload method and update the code at the end to redirect a user to the edit page after successfully uploading.

```go
func (g *Galleries) ImageUpload(w http.ResponseWriter, r *http.Request) {
    // ... this is unchanged
    // Remove the code used to create a success alert and
    // render the EditView and replace it with the following.
    url, err := g.r.Get(EditGallery).URL("id", fmt.Sprintf("%v", gallery.ID))
    if err != nil {
        http.Redirect(w, r, "/galleries", http.StatusFound)

    }
```

## 16.6 Configuring our application

Up until now we have been hard-coding quite few configuration variables into our application. While this is faster when getting started with an application it isn't a great idea long term. We don't want to rebuild our entire application just to change a single configuration value, and it is a bad idea to store secret keys in source code where any developer has access. We also don't want to make development harder than necessary, so it is a good idea to provide a viable set of configuration values to run in development.

In the next subsection we will focus on finding all of the variables in our application that need to be pulled out and provided via configuration variables and providing default values for each of these to use in development.

In the second subsection we will explore functional options and see how we can use them to make providing configuration variables to nested portion of our application much easier.

In the final subsection we will see how to use a JSON file to provide alternative configurations and how to load that with our Go code.

### 16.6.1 Finding variables that need provided

When introducing configuration variables to an application I find it often easier to go through your application looking for any variables that need to be provided and jotting them down. Doing this all upfront will help us figure out what variables we need to account for but will also help us get a mental map of what we are about to code. package main

```go
import "fmt"

type PostgresConfig struct {
    Host     string `json:"host"`
    Port     int    `json:"port"`
    User     string `json:"user"`
    Password string `json:"password"`
    Name     string `json:"name"`
}

func (c PostgresConfig) Dialect() string {
    return "postgres"
}

func (c PostgresConfig) ConnectionInfo() string {
    // We are going to provide two connection info
    // strings based on whether a password is present
    if c.Password == ""
        return fmt.Sprintf("host=%s port=%d user=%s dbname=%s&sslmode=disable", c.Host, c.Port, c.Name)
    }
    return fmt.Sprintf("host=%s port=%d user=%s password=%s&dbname=%s sslmode=disable", c.Host, c.Port, c.Password, c.Name)
}
```
