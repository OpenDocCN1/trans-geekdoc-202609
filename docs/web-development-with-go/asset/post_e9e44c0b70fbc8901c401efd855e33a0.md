# Listing 2.3: Creating a simple web application

```go
package main

import (
	"fmt"
	"net/http"
)

func handlerFunc(w http.ResponseWriter, r *http.Request) {
	fmt.Fprint(w, "<html>Welcome to my awesome site!</html>")
}

func main() {
	http.HandleFunc("/", handlerFunc)
	http.ListenAndServe(":3000", nil)
}
```

Finally, we run the app.

## 2.2 Demystifying our app

Now you are probably asking yourself, what exactly is going on? To answer this question, we are going to go through our code one section at a time exploring what the code does. As we progress we will introduce new concepts and take a minute to explore each of them. For our first program we want to make sure you have a strong foundation to work from. Starting with the first line:

```go
package main
```

If you have written any code in Go, this should be obvious. This simply declares what package this code is part of. In our case, we are declaring it as part of the main package because our application starts by running the main() function. Next up are imports:

```go
import (
  "fmt"
  "net/http"
)
```

tell the compiler which packages you intend to use in your code. As we expand our application we will start to create our own packages so that we can test and reuse code easily, but for now we are just using two packages from Go’s standard library.

The first is fmt package. Putting it simply, this is the package used to format strings and write them to different places. For example, you could use the fmt.Println(...) function to print "Hello, World!" to the terminal. We will cover how we use this in our code shortly.

The last package we import is net/http. This package is used to create an application capable of responding to web requests, as well as making web requests to other servers. We use this library quite a bit in our simple server, and it is the foundation that our web application is built on.

# Box 2.2. What are standard libraries?

Standard libraries are basically sets of functions, variables, structs written and officially maintained by the creators of Go. These generally tend to include code that is very commonly used by developers, as code to print strings to the terminal, and are included with every installation of Go due to how frequently developers use them. You can think of them as code to make your life simpler.

That said, you don't have to use standard libraries to create a web server. If you really wanted to, you could write your own http package and use it instead of the standard library for your web server, but that is a lot of work and you would be missing out on all the testing and standardization provided by using the net/http package.

Next up we have handlerFunc(...).

```go
func handlerFunc(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintf(w, "<h1>Welcome to my awesome site!</h1>")
}
```

This is the function that we use to process incoming requests. Every time someone visits your website, the code in handlerFunc(...) gets run and determines what to return to the visitor. In the future we will have different handlers for when users visit different pages on our application, but for now we only have one.

All handlers take the same two arguments. The first is an http.ResponseWriter, declared as w in our current code, and a pointer to an http.Request, declared r in our current code. While we don't currently use both of these in our code, it is worth going over what each is used now.

# Box 2.3. A brief introduction to web requests

Whenever you click on a link or type a website into your browser, your browser will send a message to the web application asking for some specific page or set of data. This is called a web request. Once the server receives a web request, it will determine how to process it, and then send a response. The browser decides how to show the resulting data - typically rendering it as HTML.

Understanding the components of a web request and response aren't really required now, but some of you will want to understand what is going behind the scenes. So for all of you curious souls, a web request is a message to a web application specifying what type of data it wants in response. For our purposes we will be focusing on three parts of a web request - the URL the request is being sent to, headers, and a body.
