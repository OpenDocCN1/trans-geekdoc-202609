# 14.6. REQUIRING USERS VIA MIDDLEWARE

```
myKeyStr, ok := myKey.(string)
if !ok {
    // type conversion failed!
}
// otherwise myKeyStr will have a string representation of
    // the value in myKey
```

This lack of type safety is one of the sources of controversy involved with the context package. By storing values in our context we lose some of the compile-time type safety we have to expect. For example, if we stored an integer in our context instead of a string in the example the type assertion trying to turn it into a string would fail and our code would then have to recover from this manually, and that often isn't possible because we don't know how to proceed with invalid data.

```
newCtx := context.WithValue(ctx, "my-key", 123)
myKey := newCtx.Value("my-key")
if myKeyStr, ok := myKey.(string); !ok {
    // we have an issue here because myKey is an int, not a
    // string! We now have to try to recover in our code
    // instead of the compiler catching this for us!
    // The only way to proceed here is often with an error
}
```

Luckily, there is a way to combat this which involves creating your context package that wraps some of the existing context package's functions and uses private keys. This is much easier to understand if we have code to go along with, so we will be writing our own context package moving forward. We will start by creating the directory for the package and a source file.

```
$ mkdir context
$ atom context/context.go
```
