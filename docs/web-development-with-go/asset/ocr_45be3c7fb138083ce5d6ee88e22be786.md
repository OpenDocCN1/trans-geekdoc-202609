# 14.1. DEFINING THE GALLERY MODEL

After that we need a way to track which user owns the gallery. The easiest way to do this is to store the ID of whatever user owns the gallery in the model. That way we can easily lookup the user with their ID, and we can also find all of a specific user's galleries by running a query, like “Select all of the galleries where the user_id is 123."

User IDs are always unsigned integers (uint), so we will name this field UserID and give it the type uint. We want to require this field, and as discussed earlier we will likely be querying for galleries based on the user ID, so we will add the “not-null” and “index” tags to inform GORM that we require this field to have a value and we want to index the field to make our queries by UserID.

```
type Gallery struct {
  gorm.Model
  UserID uint `gorm:"not_null;index""
}
```

The title field can be stored in a string field, and the only special rule we want here is to require the field to have a value. A gallery wouldn't be very useful without at least having a title.

```
type Gallery struct {
  gorm.Model
  UserID uint `gorm:"not_null;index"\n  Title string `gorm:"not_null"
}
```

While we will eventually want a way to link images to our gallery, we don't have any image resources yet so we are going to skip that for now. Once our users can create galleries with a Title and share then we will look at adding images to our galleries.
