# 9.4 Querying by email and DRYing up our code

Typically, I wouldn't recommend adding more methods to a service that you immediately need. Doing so is an easy way to end up with “fat” service that has several legacy methods that rarely (if ever) get used, yet they end up needing supported because everyone is afraid of removing them. Not to mention the fact that nobody really needed to write them in the first place.

Despite that, I know for a fact that we are going to need a method to query users by their email address in the future because we will need this in order to let users log in, so we are going to go ahead and write that method next. While we are at it, we are going to DRY up our code a bit so we can avoid writing the same bits of code too frequently.

Note: DRY is an acronym discussed in Section 7.4.5, but is often used as a verb meaning to refactor your code in order to make it less repetitive.
