# Box 2.6. What are interfaces?

Interfaces in Go are a way of describing a set of methods that an object needs to implement for it to be valid. For example, I might have a function that takes in a parameter, let's call it a Book, and when showing the book on the website we call book.Price() to show the price. But what happens when we want to list a toy on our website? Our function only accepts the Book type!

It turns out that our function really doesn't care if it is passed a Book, a Toy, or even a Computer. All it really cares out that whatever it is passed a Price() method that it can use to display the price. This is what interfaces are good for - they allow us say what type of methods we care about, and as long as the object we are passed those methods our code works.

You don't need to worry about writing your own interfaces for now. We will go over those in more detail when they come up in the book.

If you are coming from another language, like Java, it is worth noting that interfaces in Go are quite different than what you are used to. Primarily, in Java it is required to explicitly state that an object implements an interface, but that is not required in Go. If an object implements all of the methods of an interface, it is considered an implementation of the interface without explicitly stating that it is.
