### 7.4.3 Parsing a POST form

We are finally ready to start learning how to parse the sign up form so that we can use the submitted data to create a new user.

When a form is submitted to your web application it will be included in the web request that the user is making. Or in Go terms, it will be part of the http.Request parameter passed into your handler function.

### 7.4. PROCESSING THE SIGN FORM

Before you can access the form, you first need to tell your code to parse it. This isn’t done by default forms aren't always included in web requests, so it would be pretty pointless to try to parse a form when one isn’t most of the time. You can parse a form in Go by calling the ParseForm method on the http.Request that is passed into your handler function.

If you were to read the docs for the ParseForm function they might seem pretty daunting at. There is a lot of talk about HTTP methods, row queries, and MaxBytesReader, all of which probably doesn’t mean much to you at this point. All of this information is there because parsing data in a web request can be complicated, and the docs need to outline every edge case.

Luckily, our case happens to be fairly standard. When we call ParseForm within our Create method it will parse the HTML form that was submitted and store the data in the PostForm field of the http.Request.

Open up our users controller and we will test this out.

```
$ atom controllers/users.go
```

We are going to parse our form, check for errors, then print out the two fields we expect to be in our HTML form. The code for this is shown in Listing 7.21. We will discuss the PostForm portion of the code after writing.

# Listing 7.21: Accessing r.PostForm data

```
func (u *Users) Create(w http.ResponseWriter, r *http.Request) {
	if err := r.ParseForm(); err != nil {
	panic(err)
	}
	fmt.Fprintln(w, r.PostForm["email"])
	fmt.Fprintln(w, r.PostForm["password"])
}
```

Our PostForm is really just a map behind the scenes, which means that we can access fields stored in the PostForm in the same way we would access fields in a map - by using the ["key"] syntax. That is what we are doing in Listing 7.21 when we write the code:

We are telling our code that we want whatever value is stored in our PostForm map with the key "email".

### 7.4.4 Parsing forms with gorilla/schema

We have seen how to parse a form and access the data manually, parsing data this way can be tedious. We need to write code to pull out each field of our form, convert it to the correct type, and assign it to whatever structure we want to work with.

Rather than writing all of this code and potentially introducing a bug into our code, we are going to take advantage of another library in the Gorilla toolkit¹⁰ - the schema package¹.

> ¹⁰http://www.gorillatkit.org/
¹¹http://www.gorillatkit.org/pkg/schema

The schema package was designed to make it easier to convert form values into a struct. Not only will it handle moving the data from our PostForm into our struct, but it will also handle most common type conversions for us. For example, if our struct field had a type of int then the gorilla/schema package would convert the form value into an integer before assigning it to the struct.

Gorilla’s schema package is a third party package, so we will first need to get it.

```
$ go get -u github.com/gorilla/schema
```

Note: The -u flag is used to get an updated version of the package.

We know our form is going to be used for the sign up page, so we will name the form SignupForm for now. In the future we might want to create a shared UserForm type, but for now we don't know for sure that will be shared so we start off with a very specific name.

We also know what input fields we have in our sign up form. One is for the user’s email address, and another is for their password. We want to store both of these after parsing our form so we need to add fields for each to our SignupForm type.
