### 7.4.2 HTTP request methods and gorilla/mux

We talked about HTTP request methods like GET and POST earlier in this chapter, but up until this point we haven't had a reason to actually use them in our code. All of our pages are unique, and none of our pages have created, updated, or destroyed data, so it hasn't been a major concern.

Now we want to allow users to create accounts, so we need to update our code to reflect this. Specifically, we want to map any POST requests to the /signup path to the Create method because this means that a form has been submitted to create new users. We also want a GET to the /signup path to show the sign up form like it currently does.

To do this we need to update our router and inform it of which methods to accept for each handler function. Rather than just telling you what method is, I want you to try and find it on your own.

Head over to the Gorilla mux docs and look at the api that lists all of the methods and functions made by the package.

Does anything look like it would help us? Does anything mention HTTP methods or verbs?

To answer this question, we first need to look at our existing code. In main.go we have the following code:

```go
r := mux.NewRouter()
r.HandleFunc("/", home)
r.HandleFunc("/contact", contact)
r.HandleFunc("/signup", userC.New)
```

If you look at the docs means for [HandleFunc] you will notice that this method turns a *mux.Route. That means we could access the return value by doing something like:

```go
route := r.HandleFunc("/signup", userC.New)
// or we could chain our method calls
r.HandleFunc("/signup", userC.New).SomeRouteMethod()
```

Knowing that we have a Route to work with, we should check out the Methods method on that type first.
