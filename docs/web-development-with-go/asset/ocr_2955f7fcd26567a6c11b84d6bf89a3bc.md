**Box 2.3. A brief introduction to web requests**

Whenever you click on a link or type a website into your browser, your browser will send a message to the web application asking for some specific page or set of data. This is called a web request. Once the server receives a web request, it will determine how to process it, and then send a response. The browser decides how to show the resulting data - typically rendering it as HTML.

Understanding the components of a web request and response aren't really required now, but some of you will want to understand what is going behind the scenes. So for all of you curious souls, a web request is a message to a web application specifying what type of data it wants in response. For our purposes we will be focusing on three parts of a web request - the URL the request is being sent to, headers, and a body.

The URL is something most people are familiar with. It is composed of a few parts, but the one we will be focusing on most is the path. This is the part after the site name. For example, given the url `http://www.lenslocked.com/signup` the path would be the `/signup` portion. We focus on this part of a URL because this is how we determine what the user is trying to do. For example, if the path is `/signup` then we know to run our code that handles users trying to sign up. If instead the path is `/news` then we know to run our code that handles displaying news.

Headers are used to store things like metadata, cookies, and other data that is generally useful for all web requests. For example, after logging into your account many web applications store this data in a cookie, and in the headers of your requests. This allows the website to determine both that you are logged in, and which user you are.

The body is used to store user submitted data. For example, if you filled out a sign up form and hit the submit button, the browser would include the data you typed into the form as part of the body so that the web application can process it.
