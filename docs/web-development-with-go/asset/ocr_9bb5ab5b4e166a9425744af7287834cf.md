```
// User middleware will look up the current user via their
// remember_token cookie using the UserService. If the user
// is found, they will be set on the request context.
// Otherwise, the next handler is always called.
type User struct {
    models.UserService
}

func (mw *User) Apply(next http.Handler) http.HandlerFunc {
    return mw.ApplyFn(next.ServeHTTP)
}

func (mw *User) ApplyFn(next http.Handler) http.HandlerFunc {
    return http.Handler(func(w http.ResponseWriter, r *http.Request) {
        cookie, err := r.Cookie("remember_token")
        if err != nil {
            next(w, r)
            return
        }

        user, err := mw.UserService.ByRemember(cookie.Value)
        if err != nil {
            next(w, r)
            return
        }
        ctx := r.Context()
        ctx = context.WithUser(ctx, user)
        next(w, r)
    })
})
```

All of this code should look familiar, because it is a subset of the code that we used for ourRequireUser middleware. The only real difference is that we remove the two lines of code that would redirect a user if they weren't signed in.

Now we can come on to writing the new version of our RequireUser middleware. Know that if we run the User middleware first that a user will already be set in the request context, so we can drastically simplify our code. We no longer need to look up the user in our database, but instead simply check to see if a user was ever assigned in the request context. If not, we can assume the user is not signed in and redirect them to the login page.
