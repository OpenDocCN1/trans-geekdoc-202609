Back to the db.Query() results - if the error object returned is nil means we are safe to start using the first object to scan the data that we returned from our SQL query.

sql.Rows object returned by db.Query() starts pointing to a location just before the first row, so we must call rows.Next() before we can call rows.Scan(), but this actually works out in our favor because it is easier to write for our loop. Instead of needing to scan once and then start our loop we can instead call rows.Next() on the first pass of our loop and then access the row of data.

After each call rows.Next() we can use the sql.Rows object pretty much the same way we would use an sql.Row object. We use the Scan() method to retrieve the data from query and tell the method parameters we want to store in data. In this case we are scanning for an ID, name, and email address and storing them in the same variables as before.

Once we have the data we print it out and then let the for loop iterate to the next row by calling the rows.Next() method. When there isn't a new row to deal with the rows.Next() method will return false which will terminate our loop, but when there is a new row to the rows.Next() tells our rows object that we are ready to move on to the next row.
