# ### 16.5.1 URL encoding image paths

The first bug we need to look at is one that are unlikely to catch yourself. If a user uploads an image with certain special characters, our application will currently fail to handle it correctly.

We can see this in creating a file with a name that includes forward slashes or question marks in it.

```
# Some operating systems may not like this filename either
/asfjalf/_!@&?.jpg
```

What makes this filename interesting is that it has special characters in it that even in a terminal could be problematic. As a result, it is unlikely that users will have filenames with slashes in them, but they might have question marks or other problematic characters in their filenames. These characters have special meanings in URL paths, so we need to encode them before creating the `src` tag of our `<img ...>` HTML.
