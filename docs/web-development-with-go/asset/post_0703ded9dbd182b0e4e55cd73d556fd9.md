Most password emails will now include a link that has the token embedded in it via URL query parameters. Then when a user clicks it, the form will auto-populate the reset token field so the user has never to fill out.

In order to do that with Go we are going to use the net/url package8. Specifically, we will be using the Values type9 which was designed specifically for query parameters.

The simplest way to build the encoded query parameters is to construct a url.Values object then combine the output of its Encode method10 with the base URL you want to use.

```
v := url.Values()
v.Set("token", "encode-me-!#(&&)")
resetURL := "https://lenslocked.com/reset?" + v.Encode()
// resetURL is
// https://lenslocked.com/reset?token=encode-me-%21%23%40%28%29%26
```

With that knowledge, we can use the url.Values type to construct our reset password while adding a ResetPw method to our email client.

```go
const resetBaseURL = "https://www.lenslocked.com/reset"
func (c *Client) ResetPwToEmail(email, token string) error {
	v := url.Values()
	v.Set("token", token)
	resetURL := resetBaseURL + "?" + v.Encode()
	resetText := fmt.Sprintf(resetTextTemplate, resetURL, token)
	message := mailgun.NewMessage(from, resetSubject, resetText, email)
	resetHTML := fmt.Sprintf(resetHTMLTemplate, resetURL, resetURL, token)
	message.SetHTML(resetHTML)
	err := c.Send(message)
	return err
}
```

## 18.1. USING INTERFACES IN GO

To make this work in our rock and geode example, we would first start off by creating an interface type.

```go
type Dense interface {
    Density() int
}
```

Both the Geode and the Rock type have a Density() method, so they are both implementations of the Dense interface by default. No extra code is necessary to implement an interface in Go.

After creating our interface we would go and update IsTDenser() function to accept parameters of the Dense type instead of the Rock type.

With those changes we would then be able to compare both rocks and geodes in our IsTDenser() function without having to worry about the type of each. The only thing our IsTDenser() function would care about is that the arguments passed both implement the Dense interface.

How that interface gets implemented is irrelevant; in this example the Density() method is actually delegated to the Rock object that is nested inside of the Geode object, but it doesn't have to be. We could just easily write a Density() method on the Geode type and our code would work.

```go
package main

import "fmt"

type Rock struct {
    Mass int
    Volume int
}

func (r Rock) Density() int {
    return r.Mass / r.Volume
}

func IsTDenser(a, b Dense) bool {
    return a.Density() > b.Density()
}
```

```go
type Geode struct {
  Rock
}

func (g Geode) Density() int {
  return 100
}

type Dense interface {
  Density() int
}

func main() {
  r := Rock(10, 1)
  g := Geode(Rock(2, 1))
  // Returns true because Geode's Density method always
  // returns 100
  fmt.Println(IsTDenser(g, r))
}
```
