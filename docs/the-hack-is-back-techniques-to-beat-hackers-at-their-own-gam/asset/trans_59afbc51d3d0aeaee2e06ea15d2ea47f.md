## API 网关

近年来，许多云服务提供商开始允许我们通过各种方式将流量重定向到其API网关。这对于我们利用这些LOTS网站，同时将目标流量重定向到我们的C2服务器来说，是一种便捷的方式。API网关作为一种服务，设计用于在应用程序和后端服务之间充当中介——我们可以利用这一功能，选择云服务应将特定载荷引导至何处，以路由流量。

## 代理技术

代理用于代表我们自身掩蔽并执行请求，使我们能够有效隐藏自己的位置。在付费渗透测试项目中，渗透测试人员通常利用各种代理来确保所有测试流量都来自已知位置。与此同时，恶意个人也会将代理用作一次性位置来掩盖其真实位置。我们可以利用这项技术来确保自己的位置得到适当保护。

重要的是要理解，使用这项技术本身并不违法或不道德。如何使用该技术则完全是另一回事，恶意利用技术欺骗他人才是一种非法且不道德的活动。我们将学习如何有效利用它来保护自己，并为他人提供安全服务。

### SOCKS 代理

Socket Secure（SOCKS）代理是互联网上最简单、最常见的代理服务器形式之一。它们可以轻松创建，并通过SSH连接进行隧道传输，从而提供安全受保护的互联网连接。此外，各种免费和付费提供商还提供可在互联网上使用的SOCKS代理。

使用代理的理念是让互联网上的另一台服务器接收你的请求并代为发送。通过处理该请求，目标网站不会知道原始的请求身份是谁。相反，服务器只看到直接发送请求的中间代理服务器。

我们可以使用SSH命令连接到我们控制的服务器来建立SOCKS代理。这个用于SOCKS代理的SSH隧道会在我们的本地主机上打开一个端口，我们可以将工具和浏览器指向该端口，以将流量导向互联网。建立SOCKS连接非常简单，可以使用类似下面的命令完成：

```
ssh -D 9123 m4lwhere@myserver.lol
```

此命令的作用是为服务器**myserver.lol**上的用户名m4lwhere建立SSH连接。**-D 9123**开关告诉SSH在我机器上打开本地TCP端口9123，以便通过**myserver.lol**发送流量。登录到服务器后，SSH工具将在客户端（即我们的机器）上打开本地端口9123，以允许SOCKS连接通过SSH连接进行隧道传输。这假设你拥有该服务器上的账户访问权限，否则SOCKS连接将无法建立。

一旦建立了SOCKS代理，我们可以通过将浏览器指向正确的位置来连接它。大多数主流浏览器都在其设置中提供SOCKS代理配置，我们可以使用这些配置来指定已打开的本地端口9123。

SOCKS代理的另一个主要优势是，它们可用于在内部环境中进行内网横向移动。如果DMZ资产被攻破，被攻破的服务器很可能能够直接与网络上的其他内部服务器通信。通过在DMZ主机上建立SOCKS代理，攻击者可以将其请求从自己的机器直接隧穿到内部网络，以进行进一步侦察。

### ProxyChains

有些程序原生支持使用SOCKS代理来重定向流量，而其他程序则没有内置该支持。**proxychains**工具可以强制不支持代理的程序使用特定的代理或代理链，从而有效隐藏其来源点。^3^

请记住，虽然SOCKS代理是进行横向移动和访问内部资源的有效方式，但它们并不适合大规模的扫描侦察。轻量扫描和Web侦察（例如使用Burp浏览内部服务）是有效利用这项技术的方式。对于更深入、更广泛的扫描，要么在现有主机上使用本机自带二进制文件（Live-off-the-Land），要么使用类似于Metasploit的Meterpreter路由功能^4^来通过主机路由流量。

要使用proxychains工具，我们必须为其创建一个配置文件供**proxychains**程序读取。默认情况下，程序按以下顺序搜索名为**proxychains.conf**的配置文件：

```
file listed in environment variable PROXYCHAINS_CONF_FILE or provided as
a -f argument to proxychains script or binary.
./proxychains.conf
$(HOME)/.proxychains/proxychains.conf
/etc/proxychains.conf
/etc/proxychains4.conf
```

这意味着程序将查找**proxychains.conf**文件，并使用它找到的第一个配置。示例配置文件的副本位于**/etc/proxychains4.conf**，可以将其复制到上述位置之一，然后根据我们的配置目的进行编辑。
