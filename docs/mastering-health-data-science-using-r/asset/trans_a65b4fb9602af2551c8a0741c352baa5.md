microbenchmark(first expression, second expression, unit = "ms",

## 20.1 使用快速和向量化函数

R 以较慢的编程语言而闻名。部分原因是，R 牺牲计算时间以使其对新程序员更友好。然而，R 并非全部实际上都是用 R 编写的。base R 中的许多函数实际上是用 C 或 Fortran 编写的。这些函数比我们自己编写要快得多。在可能的情况下，我们应该使用 base R 函数，而不是编写自己的函数。让我们来看看编写自己的求和函数与使用 sum() 函数之间的时间差异。

```r
my_sum <- function(x) {
  out <- 0
  for (i in 1:length(x)) {
    out <- out + x[i]
  }
  return(out)
}
```

```r
x <- 1:100000
microbenchmark(sum_function = my_sum(x),
               builtin_sum = sum(x),
               unit = "ms")
#> Unit: milliseconds
#> expr          min      lq     mean   median       uq      max neval
#> sum_function 2.182020 2.2e+00 2.298618 2.252089 2.292556 3.61021 100
#> builtin_sum  0.000041 8.2e-05 0.000474 0.000082 0.000246 0.00459 100
```

这也将我们的代码简化为一行。回顾我们的第一个示例，我们也可以简化代码。我们不需要遍历数据。相反，我们应该使用向量化方法，该方法检查所有观察中的疼痛改善情况，然后对 TRUE/FALSE 值求和。

```r
microbenchmark({
  vector_pain = sum(pain$PAIN_INTENSITY_AVERAGE <=
                      pain$PAIN_INTENSITY_AVERAGE.FOLLOW_UP)
}, unit = "ms")
#> Unit: milliseconds
#> expr                                                              min    lq   mean median    uq   max neval
#> { vector_pain = sum(pain$PAIN_INTENSITY_AVERAGE <= pain$PAIN_INTENSITY_AVERAGE.FOLLOW_UP) } 0.0155 0.0156 0.0168 0.0157 0.0159 0.0459 100
```

这快得多。循环在 R 中以速度慢而臭名昭著，因此你经常听到避免循环的建议。使用 apply() 和 sapply() 等 apply 函数是隐藏循环的函数。使用这些函数而不是显式循环并不会提高我们代码的效率，只是通过这些函数，我们通常会在重写代码时作为副产品简化代码。

真正能比循环提高效率的函数是向量化函数，它们可以对一组值进行求值。向量化我们的代码意味着我们考虑的是向量方法，而不是为向量的每个元素计算某个东西并遍历这些值。向量化函数返回与输入具有相同维度的输出，并以高效的方式对这些元素进行操作。

以下代码块显示了一个简单示例，比较对每个单独元素求平方根或调用 sqrt() 函数（这是一个向量化函数）。向量化函数仍然需要对每个元素进行操作，但该循环通常是用 C 或 Fortran 而不是 R 编写的，因此速度快得多，所以这是一个我们可以利用某些函数速度的特殊情况。

```r
microbenchmark(loop_sqrt = {
  for (i in 1:length(x)) {
    x[i] <- sqrt(x[i])
  }
}, sqrt = sqrt(x), unit = "ms")
#> Unit: milliseconds
#>        expr   min   lq  mean median   uq   max neval
#> loop_sqrt 4.427 4.55 4.946 4.659 4.978 11.98 100
#>       sqrt 0.099 0.14 0.159 0.151 0.165 0.41 100
```

## 20.2 避免副本和重复

有一个矩阵 m。然后我们创建一个等于 m 的矩阵 n。最后，我们通过对所有元素取对数加一来更新 n，从而将其与 m 区分开。R 在修改时会创建副本。这意味着当我们初始化 n 时，我们实际上并没有在内存中创建第二个矩阵。相反，我们为同一个矩阵有两个名称。在第三行，我们想要更新 n，因此我们需要实际创建一个与 m 不同的第二个矩阵。

```r
m <- matrix(rpois(100000, 6), ncol = 1000)
n <- m
n <- log(n + 1)
```

这与随后更新 m 本身的代码不同。在这种情况下，R 可以通过遍历每个元素并更新其值来就地修改矩阵，而不是创建新矩阵。随着我们数据规模的增长，创建副本可能代价高昂。想象一下，m 是一个带有 RNA 测序数据的大型基因数据集。首先，这个对象可能占用大量内存，因此创建副本可能意味着我们会内存不足。其次，复制所有这些信息代价高昂。

```r
m <- log(m + 1)
```

让我们考虑另一种情况。在以下代码中，我们有两个函数，它们都查找 PROMIS 仪器变量中在均值 1、2 和 >2 个标准差以内的人的比例。当我们将 pain 作为参数输入第一个函数时，我们不会创建它的副本，因为我们没有修改数据框。但是，一旦我们创建一个新列，这意味着我们必须复制整个数据框。第二个函数则接收一个单列，只要求我们复制这些信息。执行时间的差异显示第二种方法略占优势，但差异很小。这表明，实际计算这个新列并找到比例所花的时间比复制更多。

```r
code_promis1 <- function(df){
    # create new column with categories
    df$PAIN_PHYSICAL_FUNCTION_CUT <- case_when(
      abs(df$PROMIS_PHYSICAL_FUNCTION - 50) <= 10 ~ "<= 1SD",
      abs(df$PROMIS_PHYSICAL_FUNCTION - 50) <= 20 ~ "<= 2 SD",
      TRUE ~ "> 2SD")

    # get proportions
    res <- prop.table(table(df$PAIN_PHYSICAL_FUNCTION_CUT))
    return(res)
}
```

```r
code_promis2 <- function(v){
  # create new column with categories
  v <- case_when(
    abs(v - 50) <= 10 ~ "≤ 1SD",
    abs(v - 50) <= 20 ~ "≤ 2 SD",
    TRUE ~ "> 2SD")

  # get proportions
  res <- prop.table(table(v))
  return(res)
}

microbenchmark(code_promis1(pain),
               code_promis2(pain$PROMIS_PHYSICAL_FUNCTION),
               unit = "ms")
#> Unit: milliseconds
#>                                                    expr   min   lq  mean median   uq  max neval
#>                              code_promis1(pain) 0.644 0.693 0.813  0.715 0.756 3.77  100
#> code_promis2(pain$PROMIS_PHYSICAL_FUNCTION) 0.619 0.665 0.770  0.685 0.708 3.93  100
```

创建对象副本的另一个时候是当我们修改它们的大小时。`cbind()`、`rbind()` 和 `c()` 等函数会创建一个新对象，该对象需要复制信息以创建一个向量、矩阵或数据框。如果我们知道最终向量、矩阵或数据框的大小，我们可以预先分配该空间并填充值。这意味着计算机不必反复查找更多空间。例如，请查看以下代码块中模拟一维随机游走的两种方法。在第一种方法中，向量 `v` 的长度在循环的每次迭代中都会改变，而在第二种方法中，`v` 始终具有长度 n。

```r
rw1 <- function(n){
  v <- c(0)
  for (i in 2:n) {
    v[i] <- v[i - 1] + rbinom(1, 1, 0.5)
  }
  return(v)
}
