Similar to estimating weights, ABC-Net estimates real value activations ($R$) by deploying a linear combination of $N$ binary activations $A_i = 0:N$ as shown in (5.11):

$W \approx \beta_1A_1 + \beta_2A_2 + \dots + \beta_NA_N \quad$ (5.11)

where $A = H_l(R)$. Therefore, convolution can be calculated by (5.12),

$Conv(W, R) \approx \sum_{m=1}^M \sum_{n=1}^N \beta_n Conv(B_m, A_n) \quad$ (5.12)

$M \times N$ binary convolution can be calculated in parallel. Figure 5.11 shows ABC-Net with $M=N=3$ that consists of 9 BinConvs which are calculated concurrently.

Similar to XNOR-Net, ABC-Net has changed the layer's order in the CNN block but it locates pooling layers after convolutions. Therefore, the original activation chain of (1) convolution, (2) pooling, (3) BN, and (4) activations has been reordered to asdots. Furthermore, ABC-Net has deployed a full-precision pretrained model in order to have a perfect initialization.

By using these techniques, they have achieved the classification accuracy very close to a full-precision CNN counterpart. The results on ImageNet show that the classification accuracy is within 4% of the full-precision model for $M=N=5$.

# 5.4 Hardware implementation of BNNs

As mentioned above, BNNs keep the weights and/or activations by 1 bit. Thus, memory storage and accesses are reduced considerably. The fact that XNOR-bitcount and MUX-addition are used instead of MAC operations in BNNs in the advent of many hardware accelerators for embedded BNNs. In particular, in [33], it has been shown due to bit-level logic operations, custom hardware is a more appropriate option than GPUs and CPUs to implement BNN.
