Lower on_chip_bw would mean that off_chip_bw is used and there is room for memory performance improvement. On the other hand, higher on_chip_bw would mean that performance is memory bound and is restricted by off_chip_bw. As the architecture scales, on_chip_bw requirement subsequently surpasses off_chip_bw and the DRAM bandwidth becomes the bottleneck. FICCaffe's architecture optimizer considers impacts of this unmatched off_chip_bw and on_chip_bw and tries to adjust the design parameters accordingly. We express (8.7)-(8.10) into a single expression as follows:

```
num_cycles = num_data_elem \times DW\nmin(off_chip_bw, on_chip_bw) \times freq\n= num_data_elem \times avg_cycles_per_elem  (8.12)
```

where we represent the factor avg_cycles_per_elem as ACPE for brevity. This is calculated accordingly with on_chip_bw of the buffers as it is used for, represented as ACPE$_i$, ACPE$_o$ and ACPE$_w$ for IFM, OFM and weight buffers, respectively.

# 8.6.3 Analyzing runtime

We categorize runtime cycles, total_cycles, and into the following five stages:

+   1. ifm_pl_cycles: number of cycles to preload the very first IFM file
2. wt_ld_cycles: total weight latency cycles
3. conv_cycles: total number of cycles taken by convolution
4. mem_ld_cycles: total number of load/store cycles required to transfer subsequent IFM files and OFM partial sums
5. ofm_ps_cycles: number of cycles required to store the last OFM tile after computation

Cycles contributed by stages 1, 2, 4 and 5 are memory overheads that need to be minimized. The rest of this section is dedicated to model these variables in term of layer parameters.
Before computation starts, the first IFM and the weight filters are loaded. IFM columns N_C and IFM rows, determined by the weight filter dimension and Tr as shown here, are loaded:

```
ifm_pl_cycles = N_C \times (K_R + S \times (min(Tr, M_R))\n= Tn \times ACPE$_i$  (8.13)
```

Weight filters are completely loaded onto chip-buffers and discarded before a new tile processing begins. But weights are reloaded to a different row in the same set of OFMs for partial reuse in case C$_{23}$. Thus, we see a factor of R_itr in total weight data traffic:

```
wt_ld_cycles = K_C \times K_R \times (N_itr \times Tn) \times (M_itr \times Tm)\n\times R_itr \times ACPE$_w$ + bias_cycles  (8.14)\nbias_cycles = M_itr \times Tm \times ACPE$_o$  (8.15)
```
