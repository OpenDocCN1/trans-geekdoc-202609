# 6.4.5 Supporting sparsity

In modern DNNs and CNNs, a large fraction of activation outputs are due to the unique property of ReLU. In this section, we discuss four architectures that leverage output sparsity.

# 6.4.5.1 SnaPEA

SnaPEA [31] takes advantage of this important stat to cut computations further. One technique uses statically reordering the weights based on their signs so that the convolution operation, positive weights are always processed before negative weights. There is an additional index buffer added to each PE to hold the original weight indexes to associate the right input activation for each reordered weight. Since activations are nonnegative, when the partial sum becomes zero or negative during the computation, the computation can be stopped, so the ReLU'd output will definitely be zero. This technique terminates unnecessary computations without altering the true results, hence referred to as the "exact mode.\ Built on top of exact mode, another mode is to aggressively predict whether a particular window will end with negative or zero result. To do this, a MAC operation step (n) and threshold (th) pairs are generated off-line by a greedy algorithm and stored The predictive activation step compares run time to the actual partial sums at each MAC operation step to perform sparsity speculation. These speculation parameters are also knobs to trade-off accuracy for desired speed. In determining the parameters, a greedy algorithm iteratively searches through the design space with a cost function minimizing operations while maintaining accuracy. In SnaPEA architecture, PE's are organized in a 2D array as shown in Figure 6.13 to facilitate hardware parallelism. The input activation is broadcast along the horizontal direction, whereas the same weights are broadcast in the vertical direction. To other sparsity schemes, parallelism slows down performance obtained by one PE due to the partitioning. Faster PE's have to wait for the slower ones in the same horizontal group. In this case, idle PE's are power gated to save power. Note that in both modes, computation is also accompanied by skipped input/weight buffer reads. This chapter reported on average 1.3x speedup and 1.6x energy reduction over Eervis in exact mode. With 3% accuracy loss in the predictive mode, the average speedup and energy saving are 2.02x and 1.89x, respectively.
