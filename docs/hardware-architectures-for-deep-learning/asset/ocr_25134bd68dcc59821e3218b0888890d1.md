Once a packet reaches the head of the queue, the route computation unit makes the routing decision to specify the output port to which the packet should be sent.

Many routing policies have been presented for NoCs. Among them, the routing decision in ClosN is implemented with the aim of minimizing the queuing time (blocking time) of packets in the middle-stage switches and balancing the network load. To end this, we need a congestion metric: the number of free buffer slots of the downstream input ports in the middle-stage switches. When a packet has to be sent from switch x in the input stage to a switch in the middle stage, the routing unit at x selects the switch with the smallest number of queued packets in its input port that comes from x. By using the credit-based flow control mechanism, the buffer occupancy status of middle-stage switches is available to the route computation unit without overhead, since this information is already kept and used in each upstream switch. This stage takes one cycle.

In ClosN, only input-stage switches are responsible for the routing decision. After that, packets have a single path toward the destination, so no routing flexibility in the subsequent stages. The fact that the links are unidirectional ClosN deadlock-free, since is no cycle loop in this design.

Input-stage arbitration. The arbitration stage guarantees at most one packet is sent to each output port at cycle. To request arbitration, the packets that pass the routing stage send a request for the selected output port to the arbiter. The arbitration processes the requests by some arbitration algorithm (e.g., round robin) and for each output port sends back a grant signal to one of the requesting packets. This stage takes one cycle. After arbitration, the winner packet passes through the internal خواست of the middle-stage switch. In the case of unsuccessful arbitration request, packets will continue to request in the subsequent stages.

Middle-stage and output-stage broadcast/multicast. To broadcast, the middle-stage and output-stage switches send the received packets through all downstream ports. Consequently, there is no routing stage in these stages. The arbitration request is also straightforward as each request targets all output ports. Consequently, instead of a separate arbitration for each output port, a single arbiter processes all requests. During this stage, the process is done in a single cycle. Since there is no need for routing in these stages, the packets can pass these stages in a single cycle at the ideal zero load situation, where there is no blocking penalty. Broadcasting is needed when a packet carries the output of a neuron n and all output ports are connected to PEs that host neurons from layer n+1. In some cases, parts of the output ports are allocated to neurons of layer n+ 1. In this case, there is no need for a broadcast, but the packet should be sent to a subset of outputs. This very likely scenario will happen when two or more NNs are running on a single ClosN simultaneously and the packets generated by each neuron must be delivered to the same NN.
