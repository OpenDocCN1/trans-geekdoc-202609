In this case, a single middle-stage switch is used at each cycle to broadcast data, while the others are idle. Therefore, there is a wasted bandwidth between inputs and outputs to the unused middle-stage switches. In other words, the output-stage switches are the bandwidth bottleneck of the entire system. In a $(m, n, r)$ ClosNN, each output-stage switch can receive up to $m$ packets per cycle, from each one of the middle-stage switches, while it should select only one packet and send multiple copies to that of all the PEs connected to it (see Figure 3.2). Consequently, the input buffers of output-stage switches will become fully occupied and prevent the mid-stage and input-stage switches to work with the maximum bandwidth.

To remove this inefficiency, we propose crossbars with output speed of 2 or more in the output-stage switches. The output speed of a switch is the ratio of its output bandwidth to its input bandwidth. A crossbar with output speed of $p$ has $p$ times as many output ports as many input ports. Therefore, in the output stage, by connecting each PE to output ports of its corresponding switch, each PE can receive $p$ distinct packets at each cycle (Figure 3.4).

In the case of output-stage switches with output speedup of $p$, to provide sufficient data for the output layer, ClosNN can now use fully middle-stage switches, since output-stage switches are able to send $p$ distinct packets to the PEs. As shown in Figure 3.4, the structure of middle-stage switches is intact and there still one link between each middle-stage and output-stage switch. However, the size of output-stage switches is increased.

As a result, this approach introduces a trade-off between the throughput and area. To explore this trade-off, we compare the area and throughput of a $128 \times 128$ ClosNN $(m, b, 16)$ when $m$ (the speedup of the output-stage switches) changes from 1 to 12 (Figure 3.5(a)). As shown in the figure, area grows more rapidly than throughput when the output speed increases.
