
# TRUDA中的FL聚合与认证

针对FL聚合，TRUDA强制要求通过SEV实现加密隔离。聚合器运行在EVM上。每个EVM的内存都使用唯一的临时VM加密密钥（`VEK`）进行加密。这样，TRUDA可以防止服务器管理员和特权应用等窥探者窃取模型聚合的秘密。可以利用AMD提供的认证原语来确认SEV硬件和固件的有效性。为了在去中心化FL环境中快速建立各方与聚合器之间的信任，TRUDA采用了一种基于这些原语构建的新型认证协议。该FL认证过程分为两个阶段：

## 阶段1：启动可信聚合器

安全启动与聚合器关联的SEV EVM是迈向TRUDA的初始阶段。为确保EVM的安全，必须：

1.  验证硬件平台是真正的支持AMD SEV且具备所需安全特性的硬件。
2.  验证用于启动EVM的开放虚拟机固件（`OVMF`）镜像是真实的。

远程认证完成后，TRUDA将连同EVM一起发送聚合器的密钥。在阶段2的聚合器认证完成之前，该密钥始终隐藏在EVM加密的物理内存中。可使用有效的AMD根证书来验证整个证书链的真实性。认证报告除包含完整的证书链外，还包含原始`OVMF`镜像的摘要。

报告经过认证后，将被传输至已配置必要AMD根证书的认证服务器。通过验证证书链，认证服务器可判断`OVMF`固件是否被篡改，以及特定硬件平台是否真实。认证服务器生成启动二进制大对象和客户所有者Diffie-Hellman公钥（`GODH`）认证，以验证宿主机器的身份。聚合器的机器向SP提交DHKE请求以获取传输加密密钥（`TEK`）和传输完整性密钥（`TIK`）后不久，EVM便开始处理数据。

TRUDA可在启动时暂停EVM，从SP获取`OVMF`运行时度量值。为进行验证，该度量值连同SEV API版本和EVM部署方法一起传输给宿主系统。作为打包密钥的一部分，认证服务器生成一个ECDSA `prime251v1`密钥，以确保度量值的准确性。为了揭示可信聚合器的身份，必须启动EVM，此时管理程序必须将密钥注入EVM的物理内存区域。

## 阶段2：聚合器认证

FL参与方必须仅与使用安全运行时内存加密的已识别聚合器协作，这至关重要。在EVM部署的第一阶段，认证服务器秘密地向聚合器提供一个ECDSA密钥，以便其进行认证。该密钥对质询请求的签名验证了请求源自可信聚合器。参与方在参与FL前，需要进行质询-响应协议聚合器认证。通信发送方有时会在消息中附加一个随机生成的nonce。聚合器使用自己的ECDSA密钥对该nonce进行签名，并将其发送回请求方。为确保nonce是用正确的ECDSA密钥签名的，请求方验证其签名。验证通过后，加入FL的下一步是向聚合器注册。每个聚合器轮流完成此过程。

注册后，聚合器与参与模型更新交换的各方可通过端到端加密信道进行通信。TRUDA使TLS能够与需要双向认证的聚合器配合工作。因此，所有模型变更在EVM内部和传输过程中均处于安全状态。

# 实验评估

在本章中，作者将三种Mystiko算法与SPDZ（一种领先的可靠多方计算协议）以及通过引入统计噪声实现差分隐私（DP）的策略进行了比较。研究人员使用多种不同规模的神经网络模型和数据集进行图像处理：作者从一个在MNIST数据集上训练的1MB 5层CNN开始。以下是所用的四个模型：

1.  Resnet-18（中型，50MB），在SVHN数据集（60万张街景数字图像）上训练。
2.  Resnet-50（中型，110MB），基于CIFAR-100数据集（6万张彩色图像，100个类别）。
3.  VGG16（大型，600MB），在Imagenet-1K数据集上训练。
4.  AlexNet（小型，10MB），在MNIST数据集（1420万张图像，1000个类别）上训练。

作者利用一个包含40台计算机的集群，以2到40人的分组进行实验，以测试和比较所有算法。每台计算机上从未安排超过一个工作节点运行，每台计算机配备8个Intel Xeon E5–4110（2.10 GHz）处理器核心、64 GB内存、单个NVIDIA V100图形处理单元和10千兆以太网连接。所有机器分布在四个不同的数据中心，且在每次测试中，参与者均匀分布在所有四个数据中心中。在每个实验中，数据集在参与者之间均匀随机分布。一个数据中心提供单台机器用于执行Mystiko。接下来，作者将对10次独立试验的结果取平均，以得出每个新数据点。

## MYSTIKO与SPDZ的比较

在联邦学习中，每个学习者（或本地聚合器）在共享训练数据并协同更新模型之前，都会进行固定次数的迭代单独训练。MYSTIKO和SPDZ等系统在梯度聚合阶段以威胁隐私的方式介入。为此，作者将利用以下两个标准来评估MYSTIKO和SPDZ：

时间同步有两种类型：均可用秒和毫秒来衡量两个设备同步得有多好。同步过程的两个部分构成了总时间：

1.  对梯度进行机密调整所需的时间（MYSTIKO的Paillier加密、SPDZ的份额生成等）。
2.  将更新后的梯度广播给联邦成员所需的时间。

在[图7](#ch4.xhtml#fig4_7)中，作者使用所有模型/数据集组合的散点图，比较了联邦范围内的总同步和通信时间与联邦成员总数的关系。正如[图7](#ch4.xhtml#fig4_7)所示，All-Reduce是随着用户数量增长最具扩展性的选项。得益于协议固有的并行性，每个学习者/LA只需持续广播梯度数组的一个子集，从而大幅减少了传输的总数据量。由于其顺序性质，基本环形协议是扩展性最差的网络拓扑。
