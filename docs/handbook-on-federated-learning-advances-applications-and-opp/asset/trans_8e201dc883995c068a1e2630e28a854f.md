

# 集中式与联邦式环境中的 ML/DL

ML/DL 在各种应用领域均展现出良好的效果，尤其是当海量数据汇聚在一个位置时，例如数据中心或云服务 [[1](#ch4.xhtml#ref4_1)]。但如果数据由（第三方）云服务集中收集和存储，一旦发生数据泄露，公司（云服务客户）可能面临巨大的法律责任 [[2](#ch4.xhtml#ref4_2), [3](#ch4.xhtml#ref4_3)]。在处理人们的健康信息、对话、私人住宅录像、资金转账及其他此类事务时，这一点尤为重要 [[4](#ch4.xhtml#ref4_4)]。数据上传后，“失控”是集中式数据收集的常见问题。云服务是否按宣传方式使用数据？这是一个常见问题，却令人沮丧。文件真的会在声称删除时被擦除吗？由于政府法规，即使未被隐私泄露和失控风险说服的企业，也限制了与外部提供商共享的数据量（如 HIPAA 和 GDPR）。

FL 的目标是在最小化 ML/DL 模型缺点的同时提升其质量。FL 任务的参与设备规模跨度极大，从单个智能手机或手表，到拥有多数据中心的全球性企业 [[5](#ch4.xhtml#ref4_5), [6](#ch4.xhtml#ref4_6)]。当需要在来自多个“本地”实体的数据上训练单个 ML/DL 模型时，FL 便显得必要。该过程生成一组“本地模型”，随后通过仅交换少量参数（如神经网络中的模型权重）即可将其整合，实现极小的数据损耗 [[7](#ch4.xhtml#ref4_7)]。FL 算法主要分为两大类：集中式和去中心化。同样，需要一个协调者将众多区域模型的信息汇编成统一的全局模型（覆盖式组播、广播等） [[8](#ch4.xhtml#ref4_8), [9](#ch4.xhtml#ref4_9)]。

最初人们认为，随着 FL 交互的进行，仅有极少量关于原始训练数据的信息会延续至后续的模型更新中 [[10](#ch4.xhtml#ref4_10)]。基于此，认为模型更新的传播具有“隐私保护”性。无论如何，模型更新中仍残留着训练数据的痕迹，即便这并不显而易见。近期研究表明，利用模型变化即可推断私有特征并重构大量训练数据，这让 FL 的隐私保证受到质疑。即使面对诚实但好奇的聚合服务器，此情况依然成立。

## 2. 假设与关注点

常见的联邦学习部署有两种：跨设备和跨孤岛 [[11](#ch4.xhtml#ref4_11)]。在跨设备场景中，参与者众多（超过一千），但每个参与者仅拥有少量数据点、有限的算力和有限的可用能量（如智能手机和物联网设备） [[12](#ch4.xhtml#ref4_12), [13](#ch4.xhtml#ref4_13)]。它们极不可预测，总是游离群体之外又重新加入。例如，大型公司可受益于员工个人设备上存储的知识，设备制造商可利用其数百万自有设备上私密保存的数据训练模型 [[14](#ch4.xhtml#ref4_14)]。跨设备训练时，拥有一个收集数据并监管后勤的中央联系点会很有帮助 [[15](#ch4.xhtml#ref4_15)]。相比之下，跨孤岛场景参与者虽少，但均拥有海量数据和强大的计算资源（如持续供电或硬件 ML 加速器） [[16](#ch4.xhtml#ref4_16), [17](#ch4.xhtml#ref4_17)]。每个参与者在 FL 训练全程均在线且活跃，但敏感信息更易遭泄露 [[18](#ch4.xhtml#ref4_18)]。应用示例包括多家医院利用 X 光片训练肿瘤检测模型、不同银行训练信用卡欺诈检测模型等。跨孤岛场景中不存在显而易见的首选可靠来源 [[19](#ch4.xhtml#ref4_19)]。训练者与受训者之间无层级之分。由一方提供公共云托管或基础设施供给是此类部署的常见组成部分。本章专注于跨孤岛私有参数聚合 [[20](#ch4.xhtml#ref4_20)]。

作者假设所有参与者均认同联邦学习有益，因为它能提升准确性和鲁棒性 [[21](#ch4.xhtml#ref4_21), [22](#ch4.xhtml#ref4_22)]。作者指出，通过展示联邦学习可能带来的假设性性能提升来说服人们协作，仍是一个未解的研究问题。我们关注的核心是“诚实但好奇”信任模型 [[23](#ch4.xhtml#ref4_23)]。然而，参与者可能为窥探他人数据而被激励去复现模型参数。关于参与者的个人信息，作者假设协调者不仅可信，而且确实好奇。应尽量减少对协调者的依赖，参与者希望实现这一点。作者还假设无人故意引入虚假权重以扭曲全局模型结果。当成员因法律或法规限制（如欧盟数据保护指南、FedRAMP）而被禁止共享信息或调整彼此模型参数时，该信任模型得以简化。

换言之，全球最大金融机构 BankA 在全球设有多个分支机构（BankA 印度、BankA 美国、BankA 英国等），却无法利用任何子公司的数据训练欺诈检测模型 [[24](#ch4.xhtml#ref4_24), [25](#ch4.xhtml#ref4_25) and [26](#ch4.xhtml#ref4_26)]。该信任范式的常见应用之一是职场联邦学习。区域数据中心服务于各子公司，全球数据中心可能部署协调者。医院间互不信任，不愿向中心化服务提供数据，却仍想合作训练肿瘤检测模型 [[27](#ch4.xhtml#ref4_27)]。也可能多家（竞争关系的）云托管 ML 服务（如 Azure ML）企业客户互不信任，但信任云服务具备安全开展 FL 的能力。

## 3. 私有联邦学习

差分隐私框架关注在共享数据集上计算或查询的结果时，限制私有信息的泄露 [[28](#ch4.xhtml#ref4_28), [29](#ch4.xhtml#ref4_29) and [30](#ch4.xhtml#ref4_30)]。若一项计算能确保外部观察者仅通过查看其在数据集上产生的结果，无法判断使用了哪个个体的数据，则称其为差分隐私 [[31](#ch4.xhtml#ref4_31)]。差分隐私通常被理解为因披露任意数据集衍生物而导致的隐私损失的数学刻画。
