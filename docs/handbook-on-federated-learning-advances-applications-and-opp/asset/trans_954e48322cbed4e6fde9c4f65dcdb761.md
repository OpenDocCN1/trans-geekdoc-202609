
# 互操作性

当许多人在一个高度专业化的环境中工作，且数据贡献需要穿透其中以造福系统（在最佳情况下实现实时）时，互操作性至关重要。互操作性是指从多个来源访问和处理数据而不丢失含义，并将这些数据集成用于制图、可视化以及其他形式的表达和分析的能力。互操作性使人们能够查找、探索并理解数据集的结构和内容 [[58](#ch2.xhtml#ref2_58)]。在澳大利亚及矿业领域，沃尔沃 [[59](#ch2.xhtml#ref2_59)]、萨博 [[60](#ch2.xhtml#ref2_60)]、ABB [[61](#ch2.xhtml#ref2_61)]、阿特拉斯·科普柯 [[62](#ch2.xhtml#ref2_62)]、山特维克 [[63](#ch2.xhtml#ref2_63)]、小松 [[64](#ch2.xhtml#ref2_64)]、卡特彼勒 [[65](#ch2.xhtml#ref2_65)] 等公司都需要让所有这些数据模型为地理定位及其运营和经济效益做出贡献。联邦学习在偏远地区作业、甚至有时无法在线连接时显得更为关键。这创造了一种操作模式：数据模型被迫在边缘设备上训练，且不会因无法时刻连接云端而失去收益。

## 6.1 计算与语义

计算语义学研究如何自动化构建自然语言表达的意义表示并进行推理的过程。因此，它在自然语言处理和计算语言学 [[66](#ch2.xhtml#ref2_66)] 中发挥着重要作用，同时也解释了没有语义的计算意味着什么 [[67](#ch2.xhtml#ref2_67)] 以及联邦学习的互操作性视角 [[68](#ch2.xhtml#ref2_68)]。

### 6.1.1 联邦计算

联邦是一组计算或网络提供商，它们共同商定运营标准。该术语可用于描述两个截然不同、形式上断开的电信网络的互操作，这两个网络可能具有不同的内部结构 [[69](#ch2.xhtml#ref2_69)]。问题在于我们*如何*计算，而不是*为什么*计算 [[70](#ch2.xhtml#ref2_70)]。

### 6.1.2 联邦语义

如果我们共享数据，目的是为了相互理解：语义互操作性。这是联邦项目中的一个主要问题。自 2019 年以来，联邦在语义方面做了大量工作，即联邦语义模型。其重要性在于使任何物流利益相关者能够通过联邦桥接器访问各种（基于标准的）数据孤岛 [[71](#ch2.xhtml#ref2_71), [72](#ch2.xhtml#ref2_72)]。

#### 6.1.2.1 数据融合

数据融合是从多个来源获取数据以构建更复杂的模型并更深入地了解项目的过程。这通常意味着获取单一主题的组合数据并将其结合起来进行集中分析 [[73](#ch2.xhtml#ref2_73)]。数据融合也指对多个相互关联的数据集进行联合分析，这些数据集提供了同一现象的互补视角。关联和融合来自多个来源的信息的过程，通常比单一数据集的分析能得出更准确的推断。数据融合是一个多层面的概念，具有明显的优势，但同时也面临着许多需要仔细解决的挑战 [[74](#ch2.xhtml#ref2_74)]。联合分析可以包括从地图、制图、地形数据、文本文件、CAD 文件、影像、卫星影像、3D 激光雷达扫描、描述、时序数据、导航数据等所有内容。这对员工和人员提出了巨大要求，需要他们理解如何融合数据以不丢失精度，首要的是不丢失知识。知识局限以及不知道如何融合而不再创建另一个孤岛是一个挑战。

#### 6.1.2.2 联邦融合

我们可以问为什么联邦融合有趣，这是有原因的。集中训练学习模型需要一个拥有极其强大计算能力和存储容量的中央云。标准机器学习模型不易直接应用于大规模物联网网络，也无法利用分布式计算的可用性。这呼唤一种新的学习模型，将训练数据分布在各个物联网设备上，而不是集中化。谷歌发明了联邦学习（FL）的概念，用于设备端学习和数据隐私保护；采用 FL 方法，每个物联网设备都可以基于本地收集的数据训练其模型 [[75](#ch2.xhtml#ref2_75)]。

#### 6.1.2.3 数据索引

为了能够融合数据并进行交叉关联，数据标准对于对齐数据全景至关重要，这样我们所有人都能从所有人的努力中受益。当我们审视索引时，最可能设想的是数据库及其索引。索引是将无序表排序为一种顺序的方式，以在搜索时最大化查询效率。当表未建立索引时，行的顺序很可能无法被查询以任何优化方式辨别，因此查询将不得不线性地搜索各行。换句话说，查询将不得不搜索每一行以找到匹配条件的行，这一过程无疑非常耗时 [[76](#ch2.xhtml#ref2_76)]。

#### 6.1.2.4 联邦索引

通过单次查询同时进行查询并访问多个数据源，是我们的目标。联邦器从一个或多个搜索引擎收集结果，然后在单一用户界面中呈现所有结果 [[77](#ch2.xhtml#ref2_77)]。

# 7. 数据模式识别

掌握并分析所有数据后，目的是发现数据中的模式和趋势，以便我们理解超出肉眼所见的内容。模式识别是利用计算机算法识别数据规律和模式的过程。这种识别可在各种输入类型上进行，如生物识别、颜色识别、图像识别和人脸识别。它已应用于图像分析、计算机视觉、医疗保健和地震分析等多个领域 [[78](#ch2.xhtml#ref2_78)]。

## 7.1 数据记录

没有数据，我们就无法读取或揭示任何模式，因此我们必须获得有价值的数据才能从中得出结论。数据是重要的来源，但有时由于机密性、完整性等原因，获取数据可能非常困难。数据记录是指在一段时间内收集和存储数据，以分析特定趋势或记录系统、网络或 IT 环境基于数据的事件/操作的过程。它支持跟踪数据、文件或应用程序在存储设备或应用程序上被存储、访问或修改的所有交互 [[79](#ch2.xhtml#ref2_79)]。

### 7.1.1 算法理解

算法理解有两方面。当我们分析数据时，我们可以看到如何在算法层面构建算法，计算机也可以。当人类首次要转化数据发现时，需要通过编程将其转换为代码，以便计算机理解如何对传入数据执行算法或进行预测。算法是一组命令，计算机必须遵循这些命令以执行计算或其他问题解决操作。根据其正式定义，算法是一组有限的指令，按特定顺序执行以完成特定任务 [[80](#ch2.xhtml#ref2_80)]。

## 7.2 转向/控制

转向机器人或车辆以获取算法可能执行操作所需的特定数据，以便机器人上的夹具能夹取并拾取我们要求的典型物体或矿物。转向数据当然可用于纯导航 [[81](#ch2.xhtml#ref2_81)]、数据阈值，以及特定事件或操作的频率。
