

## 2.7 结论

区块链技术的成功不仅仅局限于架构所提供的不可篡改性。还因为它提供了多种共识模型。本章探讨了其中一种模型——PoS（权益证明），它确保交易只能由拥有足够“权益”的节点执行。权益赋予了等同于权威的地位，随着交易的进行，这种权威在区块链中转移。这一概念经过改造，通过类似的共识机制确保了 IIoT 实现的分布式可靠性。

在该实现中，共识是通过查看每个节点携带的权益来达成的，该权益最初被预设为一个通用值。随着节点生成可靠值，权益要么保持一致，要么增加。如果值变得不可靠，节点最终会失去其权益，没有足够权益的节点无法向系统贡献值。该算法还为行为不当的节点恢复贡献者角色提供了充分的条件。

所提出的模型假设 IIoT 生态系统处于一个无菌环境中，并忽略了所有安全和隐私考量。当使用“节点”一词时，这些因素已被抽象掉。Pavithran 等人 [[23]](#C_007_c2.xhtml#r2_23) 提出了一种基于边缘的解决方案，Saxena 等人 [[24]](#C_007_c2.xhtml#r2_24) 探索了更多选项。

## 案例研究：传感器读数分析

| 指标 | 传感器 1 | 传感器 2 | 传感器 3 | 传感器 4 | 传感器 5 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| 接收读数 (`r`) | 124 | 123 | 89 | 95 | 83 |
| 贡献者？(`s > min_stake`) | True | True | True | True | False |
| 平均读数 (`avg`) | 107.75 | 107.75 | 107.75 | 107.75 | 107.75 |
| 偏差 (`d`) = `\|avg - r\|` | 16.25 | 15.25 | 18.75 | 12.75 | 24.75 |
| 接受读数 | 停止 | 停止 | 停止 | 停止 | 停止 |
| 在偏差限制内？(`d < dev_limit`) | 否 | 否 | 否 | 否 | 否 |
| 用于转移的权益 (10%) | 停止 | 停止 | 停止 | 停止 | 停止 |
| 用于费用的权益 (5%) | 停止 | 停止 | 停止 | 停止 | 停止 |
| 修订后权益 | 停止 | 停止 | 停止 | 停止 | 停止 |

由于没有贡献者能生成在偏差限制内的值，系统被假定为已失败。这种情况仅在传感器给出截然不同的值时发生，这总是被视为一种警报。因此，系统在完成原本设计的 20 次迭代配额之前就关闭了。

[图 2.9](#C_007_c2.xhtml#f2_9) 中的图表显示了权益方面高度不稳定的行为，且有两个传感器跌破了最小阈值。但算法表现出的行为使其能够恢复其中一个传感器的贡献特权，因为它开始给出正确的读数。当故障传感器被替换时，也可以做到这一点。随着新传感器开始给出正确读数，其权益将得到恢复。
