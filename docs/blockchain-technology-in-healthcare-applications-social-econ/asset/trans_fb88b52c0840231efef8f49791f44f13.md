

# 贡献者/验证者选择与权益转移机制

每当所有传感器传来新的读数时，算法会检查所有传感器是否都剩余最低数量的权益。拥有最低可用权益的节点将被命名为“贡献者”，而其他节点则保持为“验证者”。原则上，这种区分不会改变任何节点的行为。只有在读数被接受时才会产生差异。这种划分受权益证明（PoS）概念的启发，即只有当节点拥有足够的权益时，才能执行以太坊交易。这由[图 2.4](#C_007_c2.xhtml#f2_4)中的流程图描述。

![图 2.4 贡献者/验证者选择模块。](images/Fig02_04.jpg)

[**图 2.4**](#C_007_c2.xhtml#f2_4b) 贡献者/验证者选择模块。

一旦选出贡献者，将对其读数求平均以估算原始值可能是什么。此操作还有一个额外优势，即利用该指标易于识别不一致性。如果读数分布方差很高，意味着传感器捕获了相当多的噪声（同一生态系统极不可能包含差异巨大的读数）。考虑到这一点，每个读数都会与平均值进行交叉核对以计算偏差。偏差超过设定阈值的读数将被排除在外，假设它们是错误的。最接近平均值的读数将被采纳为接受值。

在取平均值时，可能存在实际值位于离群值附近的情况。为了防范此情况，会记录超出阈值的违规次数，如果没有任何读数落在阈值内，算法将报错并停止。这将处理因所有读数都偏向极端值而产生的问题。在任何其他情况下，方差都足够小，足以解释实际值与预期值之间的误差。根据应用的关键性，阈值可适当调整，那些需要严格质量控制的应用可设置更严格的阈值。但应注意，更严格的阈值会增加系统故障次数，这总比未检测到故障的后果要好。[图 2.5](#C_007_c2.xhtml#f2_5)总结了该过程。

![图 2.5 偏差测试模块。](images/Fig02_05.jpg)

[**图 2.5**](#C_007_c2.xhtml#f2_5b) 偏差测试模块。

记录完违规集合后，每个违规者将上缴固定比例的权益，然后均匀分配给给出正确读数的节点。这将使可靠的传感器受益，同时惩罚其他传感器。验证者集合不受这些变化影响。

权益转移完成后，将检查验证者集合中落在阈值内的读数（尽管平均值计算未考虑这些值）。如果任何验证者能够生成可靠读数，它们可以向贡献者收取“费用”，贡献者随后捐出其可用权益的固定比例，均匀分配给所有合格的验证者。这使得验证者一旦开始生成良好读数，最终就能恢复为贡献者状态。不合格节点将保持其原有权益，等待恢复生成正确读数。这相当于收取“Gas 费”，由节点在执行时上缴。[图 2.6](#C_007_c2.xhtml#f2_6)和[图 2.7](#C_007_c2.xhtml#f2_7)深入解释了该过程。

最终结果是一个始终保持总权益一致的系统，根据节点的可靠性将权益适当分配给不同节点。即使某节点被标记为不可靠并失去贡献特权，它仍有机会恢复其角色。

## 2.6 仿真与结果

该算法使用 `Python` 进行仿真。输入随机值以测试算法的鲁棒性及其在不同条件下的表现。考虑两种情况——一种是算法允许系统正常运行，另一种是算法因巨大错配而终止操作。

### 情况 1：系统完成正常操作

本实验的参数如下：

*   传感器数量 = 5，每个传感器的初始权益 = 100
*   贡献所需的最低权益 (`min_stake`) = 75
*   仿真迭代次数 = 20
*   偏差限制 (`dev_limit`) = 10，权益惩罚 = 10%，验证费用 = 5%

读数取为 90–110 范围内的随机数。这是为了确保读数超出 `dev_limit` 边界的可能性较小。它模拟了一个理想场景。[表 2.2](#C_007_c2.xhtml#t2_2)、[表 2.3](#C_007_c2.xhtml#t2_3)、[表 2.4](#C_007_c2.xhtml#t2_4)、[表 2.5](#C_007_c2.xhtml#t2_5)、[表 2.6](#C_007_c2.xhtml#t2_6)、[表 2.7](#C_007_c2.xhtml#t2_7)和[表 2.8](#C_007_c2.xhtml#t2_8)总结了所提模型在每次迭代中的工作情况。
