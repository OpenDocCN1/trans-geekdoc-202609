

# 理解区块链

首先，让我们尝试理解什么是区块链，它是如何运作的，以及它的显著特征是什么。简单来说，区块链是最流行的DLT（分布式账本技术）类型，其中所有的交易记录和数据（价值数据）都被存储、共享并同步到P2P网络中所有节点上 [[5](#C_014_c9.xhtml#r9_5)]。这一记录集合或数据库被称为`digital ledger`（数字账本）。P2P网络中的节点是参与的机器，它们贡献自己的计算和存储能力来建立和维护区块链设施。此外，由于区块链中的数字账本是共享的；因此，它在所有节点上被复制，从而形成一个分布式账本。这意味着P2P区块链网络中的所有节点都在本地存储了整个数据库（即数字账本）的精确副本。由任何节点执行的账本中的任何合法更新都会被广播，以便每个节点在分布式数字账本的当前状态方面保持同步。

区块链与其他类型DLT的区别在于它用于分布式账本的数据结构。从数据结构的角度来看，区块链是一个按时间顺序连接的记录（又称区块）链表 [[6](#C_014_c9.xhtml#r9_6)]。每个记录或区块将一组在时间窗口内发生的有效交易打包在一起（使用加密技术）。此外，每个区块都存储前一个区块的指针（即哈希值）。在给定的时间窗口过后，会创建一个新区块，并使用基于加密哈希的链在逻辑上与前一个区块相连。因此，该技术被称为`blockchain`（区块链）。随着时间的推移，会创建更多的区块，加上时间戳，并追加到现有的区块链中。因此，区块链的大小随时间增长，新区块以纯追加模式添加。值得注意的是，区块链广泛使用加密技术来保护账本（即数据库）的安全，因为它保存在P2P网络中的各个（不受信的）节点上。此外，需要共识算法来就区块链中要执行的每次更新在节点间建立一致。

## 9.2.1 区块结构

现在，是时候了解区块链中区块的结构了。区块只是一个用于存储一组有效交易和数据的容器。虽然典型的区块结构可能因需求、平台和应用而异，但为了理解基本概念，我们讨论比特币区块链中区块的结构。从概念上讲，一个区块分为两部分：区块头和区块体。比特币区块头的结构有六个字段，总大小为80字节 [[1](#C_014_c9.xhtml#r9_1)]。区块体大小可变，存储一组交易以及交易计数器。此外，平均而言，一笔比特币交易的大小至少为250字节，平均交易大小为500字节 [[7](#C_014_c9.xhtml#r9_7),[8](#C_014_c9.xhtml#r9_8)]。此外，每个区块的比特币交易数量通常超过500笔，平均每个区块约2,000笔交易 [[7](#C_014_c9.xhtml#r9_7),[8](#C_014_c9.xhtml#r9_8)]。任何区块链的第一个区块被称为创世区块，它没有指向的前一个/父区块。[图 9.1](#C_014_c9.xhtml#f9_1) 展示了区块的结构。

### 9.2.1.1 区块头

[表 9.1](#C_014_c9.xhtml#t9_1) 简要描述了比特币区块头中的六个字段。`version`（版本）字段基本上用于跟踪区块链（软件）升级。`timestamp`（时间戳）字段记录矿工开始挖掘新区块时的Unix纪元时间。为了将每个区块与其前一个区块相连，使用了`previous block hash`（前一个区块哈希）字段。该字段为32字节，存储前一个区块的加密哈希值（通常为SHA256哈希 [[9](#C_014_c9.xhtml#r9_9)])。

**表 9.1** 区块链中区块头的字段 [[12](#C_014_c9.xhtml#r9_12)]

| 字段 | 字段大小 | 数据类型 | 简要说明 |
| --- | --- | --- | --- |
| Version（版本） | 4字节 | Int32 | 指示当前区块需遵循的验证规则集。 |
| Timestamp（时间戳） | 4字节 | Unit32 | 存储矿工开始挖掘过程时的Unix纪元时间（自1970-01-01 00:00:00 UTC以来经过的秒数 [[13](#C_014_c9.xhtml#r9_13)])。 |
| Previous block hash（前一个区块哈希） | 32字节 | Char | 存储前一个区块的双重SHA-256哈希值，使所有区块在逻辑上链接在一起。 |
| Difficulty/nBits（难度/位数） | 4字节 | Unit32 | 目标阈值的编码版本。 |
| Nonce（随机数） | 4字节 | Unit32 | 矿工添加到区块头的任意数字，以便计算区块哈希时，获得的值小于或等于目标阈值。 |
| Merkle Root（梅克尔根） | 32字节 | Char | 包含通过梅克尔树哈希获得的最终（根）哈希值。在该树中，所有叶子节点基本上是当前区块中所有交易的哈希值。 |

`nbits`字段只是目标哈希值（一个256位数字）的编码和紧凑表示，用于挖掘新区块 [[10](#C_014_c9.xhtml#r9_10)]。`nonce`是挖矿节点不断更改的字段，以计算当前区块头的哈希值，使得获得的值小于等于目标值。换句话说，矿工通过为`nonce`字段尝试随机数不断对区块头进行哈希运算，直到区块哈希值小于等于目标值时停止。目标哈希值根据当前难度级别设定 [[10](#C_014_c9.xhtml#r9_10)]。

`difficulty`（难度）基本上是挖掘新区块以找到可接受的区块哈希值所需的相对计算量（工作量）。创世区块的难度被认为是1。如果当前难度级别为2，则意味着挖掘新区块所需的计算工作量是挖掘创世区块所需计算量的两倍。

在挖掘一组2016个区块后，难度会被重新计算，这随后设定目标值，并相应地决定`nbits`字段的值。改变难度级别的原因是为了确保区块间挖掘时间保持大致恒定，即比特币中的约10分钟 [[11](#C_014_c9.xhtml#r9_11)]。值得注意的是，上述解释假设使用的是工作量证明（PoW）共识算法。

为了计算`Merkle Root`（梅克尔根）字段的值，将当前区块中所有交易的加密哈希值作为梅克尔树的叶子节点。然后通过哈希子节点的连接（哈希）值来计算非叶子节点。在二叉梅克尔树的情况下，每个非叶子节点有两个子节点。计算非叶子节点值的过程持续进行，直到获得根哈希值。因此，`Merkle root hash`（梅克尔根哈希）字段提供了一种紧凑表示（即固定大小位）当前区块中所有交易的方法。该字段允许任何实体验证给定区块中打包交易的合法性 [[14](#C_014_c9.xhtml#r9_14)]。
