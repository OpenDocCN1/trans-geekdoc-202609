A leaf is the end point of any branch, which represents a group assigned a particular label or numeric value. They’re often displayed as rectangles. The rectangles labeled “Spam” or “Not Spam” in the figure are leaves. The paths going from one node to another or to a leaf are shown as a single line. The answer to each node’s question is shown next to the relevant path line. In the case of the tree in the figure, all of the questions are binary, so they all say “True” or “False”. There is also a special node—the first one, at the top, called the root node (or the root). The root node in the figure is the top one “Sender is unknown.” We call the complete path from the root node to any leaf branch. Note that the same “question” can appear in different branches of the tree, as “Contains flagged words” in the figure.

This is an intuitive display. To understand how to use a constructed decision tree on a new record is to first ask and answer the question in the root node based on the values the record has and go down the left path if the answer is True and the right path if it’s False. Then you ask that new node’s question and follow the correct path based on the answer. And so on, until you hit a leaf and can’t go any further. That leaf is the label or value that will be assigned to that record.

That’s how to use an existing tree, but how do you create it? As mentioned above, there are actually several different algorithms for training a decision tree. They have a lot in common, but I’ll describe the general approach. The basic concept is that for a given batch of data, you decide what the most effective split will be. What means is that the goal is to find a question that perfectly splits the data into one leaf where the records have one label and another leaf where all records have a target label different from that in the first leaf.
