There’s one exception to the known output and determinism in traditional programming, and that we’ve coded anything using randomness. Programming languages can generate random numbers, which can be used to direct different behavior determined by which numbers were generated in the case. Imagine you want to randomly generate a Dungeons & Dragons character based on different numbers for their characteristics. A character is defined by a particular set of basic identities (like race and job) and numbers representing a variety of things like skills and abilities. For instance, if there are nine possible character races, you want it to randomly pick one, and you want to randomly pick a number for the character’s dexterity between the min and max possible. The output you want from this program is different and unknown every time you run it. However, you’d know the parameters of the output—all the ability and skill scores will be between defined mins and maxes, and you know what possible races, professions, and backgrounds they can have because it’s one of a specific list. Another use of randomness is in simulation, where scientists might want to define a starting point and see how things play out over time, which would be at least partially driven by random events. Chaos theory came out of weather simulations run this way.
