# CHAPTER 8 KEEPING EVERYONE SAFE: DATA SECURITY AND PRIVACY

On their own, things like account number and country aren’t necessarily PII, but it is relative and contextual, too. For instance, if we think of zip code or post code in someone’s address, there are many people who have each one, so instinctively it seems like it wouldn't reveal anything personal. But one of the most important aspects of PII is that you have to consider how it could be used, not just what’s in an isolated dataset. If you're a small company selling medical supplies and medicine and you have a table with the total amount of insulin purchased by zip code, that seems not at all related to personal info. But if there are other tables that contain PII like the zip code, people could join the different tables together. If there’s only one person in a zip code, we know that person is buying insulin. There are plenty of people within the company who should have access to that data, but likely not everyone needs access to it, so the company should consider how to keep that info available only to the right people.

It is exactly these kinds of vulnerabilities that bad actors exploit and regular people never ever think of possible. Most of the time, the kinds of risks aren’t really known, because most people using the data every day aren’t sneaking around tables willy-nilly to see what sort of sensitive info they can uncover. This is why it’s important to keep privacy in mind any new data is being stored. The people responsible need to consider not only the new data but existing tables and how they relate to the new data.
