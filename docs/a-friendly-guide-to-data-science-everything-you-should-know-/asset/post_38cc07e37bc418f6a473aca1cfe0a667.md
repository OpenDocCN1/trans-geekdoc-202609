## Logistic Regression

Logistic regression uses a particular statistical function called the logit model as the foundation of the regression. You don't need to fully understand that to do logistic regression, but the basic way it works is if you take a linear combination of features (basically the right of the regression formula shown above, like $X_0 + m_1X_1 + m_2X_2 + ... + m_nX_n + e$), that value will equal the natural log of a particular fraction involving the target variable. I won't show you the math, but that results in the regression generating a curve between two binary values.

Like other techniques, there are some requirements for and assumptions made by logistic regression. We're talking about binary logistic regression here, so the data must be binary. Another is that the dataset shouldn't be too small (this varies depending on your data, usually a few hundred records with a handful of features is fine). The features need to be independent of each other.

Logistic regression operates somewhat like linear regression in that it determines a decision barrier between one target value or the other by minimizing a function with a particular technique. It uses some additional math to calculate the coefficients on the formula, $logit(Y) = X_0 + m_1X_1 + m_2X_2 + e$. The model assigns probabilities that each record is of class 1 and class 2 (which is just 1 minus the class 1 probability) and then uses a threshold (by default, 0.5) to apply the appropriate label. Above 0.5 goes with class 1.

## Nonlinear Regression

Nonlinear regression is a regression that generates a nonlinear function that combines the model parameters in nonlinear combination. Some data may not lie in a straight line, but it still fits a recognizable pattern. There are several types of nonlinear regression, as the fitted function could be anything, as long as it fits the data. A common technique to linearize a nonlinear function is to take the natural log of both sides of the function. Don’t worry about fully understanding this, even though most of regression is likely to be linear.

## Trees

Trees are another very popular, versatile, and useful class of supervised learning algorithms. They don't require linear data and can be used for both classification and regression. And even better, they can handle categorical features. Algorithms split the data repeatedly with if-then-else scenarios, starting at the top with all data, then splitting into multiple groups based on a rule, and then continuing down each branch until it gets to stopping point and gives the current data a label (in classification) or assigns it a number (in regression). The logic that is generated is extremely intuitive in a visualization that looks like a tree. I will first talk about the simplest algorithm, simply called decision tree. Technically, there are few algorithms that considered decision trees, so I will talk about the most common one. After discussing decision trees, I’ll talk about random forest, which is an extension of the decision tree by making many of them and combining all different results to come up with a single result.

## Decision Trees

Decision trees are probably the most intuitive machine learning. Linear regression is easily explainable, but still requires thinking about math, which will make some stakeholders down. A decision tree can be drawn and be understood by anyone. A couple of other reasons it's so useful that it doesn't require the data to be linear and can handle categorical features. I am going to show a basic decision representing a simple spam filter (technically, a spam label) as a reference (Figure 15-10).

![](img/df37a23523ff92247f9125691.png)

A decision tree is composed of nodes and leaves. A node represents a split being applied to a group of data, so we have a batch of data and apply if-then-else question to the node and send the data down two (or more) paths depending on the answer. It is often represented as oval. In Figure 15-10, all the ovals are nodes, and each contains the question being asked at that point to split the data into two different groups. A leaf is the end point of any branch, which represents a group assigned a particular label or numeric value. They’re often displayed as rectangles. The rectangles labeled “Spam” or “Not Spam” in the figure are leaves. The paths going from one node to another or to a leaf are shown as a single line. The answer to each node’s question is shown next to the relevant path line. In the case of the tree in the figure, all of the questions are binary, so they all say “True” or “False”. There is also a special node—the first one, at the top, called the root node (or the root). The root node in the figure is the top one “Sender is unknown.” We call the complete path from the root node to any leaf branch. Note that the same “question” can appear in different branches of the tree, as “Contains flagged words” in the figure.

This is an intuitive display. To understand how to use a constructed decision tree on a new record is to first ask and answer the question in the root node based on the values the record has and go down the left path if the answer is True and the right path if it’s False. Then you ask that new node’s question and follow the correct path based on the answer. And so on, until you hit a leaf and can’t go any further. That leaf is the label or value that will be assigned to that record.

That’s how to use an existing tree, but how do you create it? As mentioned above, there are actually several different algorithms for training a decision tree. They have a lot in common, but I’ll describe the general approach. The basic concept is that for a given batch of data, you decide what the most effective split will be. What means is that the goal is to find a question that perfectly splits the data into one leaf where the records have one label and another leaf where all records have a target label different from that in the first leaf.
