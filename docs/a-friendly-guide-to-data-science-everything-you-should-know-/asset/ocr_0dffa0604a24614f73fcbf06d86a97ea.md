# DevOps and MLOps

"DevOps" is another buzzword you'll hear a lot in tech. DevOps is not rigidly defined, but it is basically both a philosophy and a methodology that came from an Agile mentality and encourages collaboration with everyone involved in deploying software, from developers to testers, to those managing the code repository, and to those doing the actual deployment. It emphasizes automation, lean principles, measurement, collaboration, and a shared culture. This isn't always something data scientists will have to worry about, but it helps to understand what's going on, and sometimes it is something you'll have to deal with.

Automation plays a huge role in DevOps. Software testing is usually automated, along with builds and releases (when the software will be finalized in the state it will be deployed and then actually deployed). Other aspects related to development are also automated, such as creating environments for development and everything else that is prone to human error and can be automated. It ties in with another acronym, CI/CD (continuous integration/continuous deployment), both of which require the automation just mentioned. CI refers to regular code integration and CD to code being deployed reliably and through the correct environments.

All of this amounts to faster development and production releases—and quicker user feedback. A lot of major companies are serious about this velocity, and Amazon supposedly has every new software engineer make a real change to the codebase and have deployed it on their first day. But it isn't only faster, it's supposedly better—more reliable and more secure. Communication and collaboration between the dev side and the ops (operations) side is critical to this methodology.
