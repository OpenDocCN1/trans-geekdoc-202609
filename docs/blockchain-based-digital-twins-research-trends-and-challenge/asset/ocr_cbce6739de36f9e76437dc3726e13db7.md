The utilization of bandwidth can be optimized with the support of edge computing by transmitting only the long-term storage to the processing center. The longer latency problem of traditional cloud architecturebased IoT applications is also addressed in edge computing by making the response time faster. In DT-based predictive maintenance, the data sensed from the machine ends to be communicated to the cloud for the construction of blocks. Then the data from the block is fed into an analytical model to make decisions about maintenance. The communication of data from the origin to cloud infrastructure faces two major challenges including bandwidth consumption and security problems.

+   1. **Bandwidth Consumption**: To make the DT imitate the functioning of the real-time machine and to do predictive maintenance analysis, the data sensed from the machines is communicated to the destination frequently. This frequent communication consumes a large amount of communication bandwidth due to its huge size and frequency. This can be addressed by aggregating the continuous stream of data [8] and communicating only this aggregated data to the blockchain architecture over the cloud, which results in a notable reduction in the communication load.

+   2. **Security**: The vital reason for integrating blockchain technology in DT-based predictive maintenance is to ensure the security of the data common for multiple stakeholders who are the manufacturers of different parts of the machine. If the node from the cloud infrastructure is deputed with the responsibility of creating the block, then the raw data from the source end needs to be communicated over the network to the node. This makes the data exposed to security attacks. By bringing the block creation process close to the source end, the traveling of data in raw format over the network can be avoided, and hence security risk can be minimized.
