## 10.3.3 BLOCKCHAIN CONSTRUCTION PHASE

Integration of DTs with blockchain guarantees vital features like data integrity, tracking, immutability, and security. All the data related to the construction, policies, rules, and operation of DT can be maintained securely in Blockchain. The architecture of blockchain is classified into three categories: private, public, and consortium blockchain. Access permission, consensus determination, and level of immutability are determined based on the kind of architecture adopted. In our proposed framework for DT-based predictive maintenance, the status information of different machine parts needs to be tracked by different organizations. Hence, consortium-based architecture is considered to be more suitable.

Consortium blockchain is a hybrid form of private and public blockchain. The sensor data which exhibits the current status of the real-time machine parts and DT need to be maintained in the blockchain for predictive maintenance. It can ensure data accountability, security, and transparency among the members of different organizations who are involved in the predictive maintenance process. In the proposed framework, two different blockchains are constructed in order to improve the efficiency of the learning model: Digital Twin Blockchain (DTBC) and Real-time Machine Blockchain (RBC). RMBC carries a chain of blocks with data obtained from the real-time physical entity to be maintained whereas DTBC includes blocks that carry information obtained from the DT.

### 10.3.3.1 CONSTRUCTION OF RMBC

In this section, the steps for creating a blockchain are discussed.

- **Step 1**: Creation of Aggregate Data Structure: Each block in the blockchain carries the data used for tracking the state of individual parts of the machine to be maintained. The data stream generated by the sensing devices that are fixed in the machine equipment is to minimize the cost of storage and communication, the number of blocks in the blockchain is to be reduced. This can be achieved by aggregating the stream of data which is generated by the sensing devices. For each major part, the virtual entities used to describe the state of the part are collected by edge computing devices that act as aggregators. The aggregator computes the aggregate representation of all the virtual entities. These aggregates are grouped based on the parts to which they belong. Depending on the block size, either a separate block for each part can be created, or aggregates of multiple parts can be stored in a single block along with part identification and time. This information helps to track the status of machine parts at different times. The possible aggregate functions are SUMMATION, AVERAGE, COUNT, MAXIMUM, or MINIMUM. The description of the aggregation function is provided in Table 10.1. Depending on the kind of virtual entity and the parts to which it belongs, different aggregation functions can be applied. Hence, information regarding the kind of aggregate function has to be stored along with the aggregate. The major applications of the hash function in Blockchain are listed as follows:

- 1. **Integrity**: By keeping the root hash inside the block header, the integrity of the block header as well as the transactions can be protected. Because no Merkle trees with the same root hash are impracticable.

- 2. **Authentication**: By generating the hash using the node-specific secret key, it can act as a digital signature which ensures the authentication of the blocks.

- 3. **Confidentiality**: The transactional data communicated to the blockchain network from the edge computing device is encrypted. Adopting asymmetric privacy homomorphism which allows the computation over the cipher data end-to-end.

- 4. 10.9 Chain of Blocks: The hash is generated by applying the hash algorithm over the hash of the previous block, transaction data, and nonce. The inclusion of the previous block hash creates a virtual chain link between blocks.

The most commonly used hash functions in blockchain technology are:

- i. **SHA-256 Algorithm**: This algorithm deterministically generates the hash output for the given amount of data. The output hash is 64 characters long.

- ii. **ETHASH Algorithm**: It is an algorithm responsible for controlling the mining process of Ethereum Proof of Work. The utilization of DAG for mining makes it a memory-hard function. The memory cost is so high that mining is possible with a GPU (Graphical Processing Unit).

- iii. **Script Algorithm**: It is considered to be an optimized hashing algorithm as it can support huge volumes of data, guarantee integrity based on cryptography, and support the recovery of data.
