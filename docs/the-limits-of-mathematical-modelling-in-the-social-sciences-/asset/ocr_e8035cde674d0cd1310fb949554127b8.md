# The Perfect Language

AIT is concerned with particularly efficient ways for $U$ to be universal. Turing's original notion of universality was not this demanding. The fact that you can just add a fixed number of bits to a program for $C$ to get one for $U$ is not completely trivial. Let me tell you why. After you put $\pi_C$ and $p$ together, you have to know where the prefix ends and the program that being begins. There are many ways to do this. A very simple way to make the prefix $\pi_C$ self-delimiting is to have it a sequence of 0's followed by a 1:

$\pi_C = 0^k1$

The number $k$ of 0's tells us which machine $C$ to simulate. That's a very wonderful way to indicate this.

The prefix $\pi_C$ is actually an interpreter for the programming language $C$. AIT's universal languages $U$ have the property that you give $U$ an interpreter plus the program $p$ in this other language $C$, and $U$ will run the interpreter to see what $p$ does.

If you think of this $\pi_C$ as an arbitrary string of bits, one way to make it self-delimiting is to double all the bits. It goes to 00, 1 goes to 11, and you put a pair of unique bits 01 as punctuation at the end.

$\pi_C : 0 	o 00, 1 	o 11, 01 at the end.

This is a better way to have a self-delimiting prefix that you can concatenate with $p$. It only doubles the size, whereas the $0^k1$ trick increases the size exponentially. And there are more efficient ways to make the prefix self-delimiting. For example, you can put the size of the prefix in front of the prefix. It's sort of Russian dolls, because if you put the size $|\pi_C|$ in front of $\pi_C$, $|\pi_C|$ also has to be self-delimiting:

$U(\dots ||\pi_C ||\pi_C p) = C(p).
