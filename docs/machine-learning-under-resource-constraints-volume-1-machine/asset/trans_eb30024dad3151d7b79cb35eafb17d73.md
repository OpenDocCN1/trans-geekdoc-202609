### 7.3.8 实验讨论

实验展示了三种架构间的差异与相似之处。此处，我们希望结合特定架构的属性以及实验所用的特定 CPU 型号来讨论这些现象。我们注意到，X86、ARM 和 PPC 之间主要的架构差异之一在于可用指令。由于 `native` 树仅使用少量热代码，因此 CPU 架构间的差异在此处可能影响不大。然而，在观察 `if-else` 树时，我们预期会有更大的差异。为进一步探究 CPU 架构与代码大小之间的相互作用，我们参考 [表 7.9](#9783110785937_078254.xhtml#b_9783110785944-007_tab_1001) [^(48)](#fn48)

与 X86 架构类似，我们发现 `if-else` 树在 PPC 架构上也表现良好，但程度较轻。PPC CPU 架构属于精简指令集计算机（RISC），并针对高性能计算进行了性能增强。RISC 不像 CISC 那样提供专用操作的指令。因此，编译器必须主要依靠（相对）简单指令的组合来实现 `if-else` 树。这反过来导致代码体积变大，不太可能完全放入指令缓存。对比 [表 7.9](#9783110785937_078254.xhtml#b_9783110785944-007_tab_1001) 中 PPC 与 X86 的指令大小，我们发现 PPC 架构确实比 X86 需要更多指令。有趣的是，对于整数特征，这种情况不那么严重，这是由于该指令集架构的增强所致。考虑到实验中使用的 T4240 处理器的缓存大小，我们看到它只有 32 KiB 指令缓存，但也配备了 2 MiB 共享 L2 缓存，甚至比 Intel Core i7-6700 CPU 的还要大。对于深度 5−10 左右的较小树，缓存大小仍足以容纳所有树，因此 `if-else` 树仍是最快的选择。如果树变大（深度 10 或更深），指令缓存不足以容纳所有树，我们必须依赖更大的 L2 缓存。然而，该缓存较慢，这与较大的代码体积相结合，解释了大树性能下降的原因。

最后，我们讨论 ARM 架构的碎片化行为。与其 PPC 对应物类似，ARM 也采用 RISC 架构。然而，ARM 的 RISC 不附带针对高性能计算的专用指令，因此编译器必须完全依赖简单指令的组合来实现 `if-else`。这反过来导致整数特征的代码体积甚至更大，如 [表 7.9](#9783110785937_078254.xhtml#b_9783110785944-007_tab_1001) 所示，不太可能放入指令缓存。有趣的是，对于浮点特征，我们发现 ARM CPU 使用的指令比 PPC CPU 少，这归因于实验中使用的特定 CPU 型号。T4240 处理器针对低功耗嵌入式计算环境（如网络应用）中的高性能计算进行了优化，因此针对整数运算进行了优化。相比之下，树莓派 2 的 ARMv7 CPU 是面向普通用户需求的通用 CPU，因此与 T4240 处理器相比，它更侧重于浮点运算。它拥有 32 KiB 指令缓存，配合明显更小的 512 KiB L2 共享缓存。与其他 CPU 相比，这意味着 ARM CPU 可用的 L2/L3 缓存少了 2−16 倍。对于深度 5−10 左右的较小树，缓存大小仍足以容纳所有树，因此 `if-else` 树仍是最快的选择。然而，对于更大的树深度，指令缓存不足，使用数据缓存的 `native` 结构变得更快。然而，由于数据缓存也很小，两个缓存都会迅速填满至最大值。有趣的是，如果我们同时优化 `if-else` 和 `native` 树，最终性能大致相同。

### 7.3.9 结论

决策树构成现代机器学习的基础构建块之一，决策树集成是最成功的分类器之一，在现实应用中经常达到最先进的性能。决策树通常被视为“简单”的分类器，甚至可以在最微小的硬件上执行。然而，一棵树轻易就包含多达数百万个决策节点，必须存储和管理这些节点，即使对于大型服务器硬件也可能是一个挑战。缓存存储在当今的冯·诺依曼计算架构中被普遍采用，用于隐藏主存与处理器之间的长延迟。因此，给定树集成的高效实现必须尊重这种内存层次结构，并为决策节点提供合适的内存布局以实现最优性能。在每种现代编程语言中，实现决策树至少有两种方法：要么将树分解为其 if-else 结构，要么使用 while 循环迭代连续的节点数组。这两种方法提供不同的缓存行为，可通过本文讨论的树框架方法进一步增强。这些方法的核心在于决策树没有确定性的运行时间，其执行时间可能因当前样本而异。因此，决策树执行的概率视图估计树中最可能的路径，并对树进行框架划分，使这些路径可能保留在缓存中。实验评估显示，在三种不同的硬件架构和多种数据集上，速度提升约为 2−4 倍，且没有任何准确率损失。

# 8 通信感知

连接设备和并行计算平台的普及，对机器学习算法的高效可靠执行提出了挑战。如果机器学习工作负载仅在本地执行，系统并不总能拥有足够的资源以足够快的速度执行必要操作。此外，在较小规模下，如今多个硬件组件通过片上或片间网络互连，以创建多核系统。因此，通信、同步和卸载已成为在通信和资源约束下设计嵌入式系统的关键要素。
