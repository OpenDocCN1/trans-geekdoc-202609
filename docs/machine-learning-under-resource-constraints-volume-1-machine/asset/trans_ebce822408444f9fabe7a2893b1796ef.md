
类似于操作系统（OS）内核中常用的标准虚拟内存方案。为便于实现，它完全在用户空间实现。这种用户空间实现的缺点是，它需要复制操作系统中已存在的某些数据结构（例如，用于将虚拟内存映射到物理内存），因为这些操作系统内核数据结构未充分暴露给用户空间。通过在操作系统内核中实现该优化可以避免这种复制（参见 [\[383\]](#backmatter-001.xhtml#b_9783110785944-010_ref_383)），但这具有显著的侵入性，且不适用于许多用户无法控制操作系统内核的环境。由于用户空间无法直接访问物理内存，因此使用位于 RAM 磁盘上的单个文件（参见 [Figure 7.2](#9783110785937_078254.xhtml#b_9783110785944-007_fig_002) 中的 *custom heap*）。

从该文件分配物理内存通过一个基于简单空闲位图的分配器实现。如有需要，该文件可以动态扩大。将物理页面映射到 R 解释器的虚拟地址空间，可以通过利用 `mmap` Unix 系统调用来完成。要更改这些物理页面的访问权限，则采用修改处理器内存管理单元设置的 `mprotect` 系统调用。除了这些系统调用外，还需要一个额外的页表来实现从虚拟地址到物理地址的映射。为求简单，实现了一个具有与处理器相同四级结构的分级页表。为了实现页面共享，用户空间内存管理系统需要将同一个物理页面映射到虚拟内存中的多个位置。因此，每个物理页面都需要一个引用计数器。引用计数器大于 1 表示该页面在多个对象之间共享，或在一个对象内被多次共享。

为避免分配的大向量对象进行零初始化，使用了一个 *global shared zeroed page*。这也确保了内存仅为稍后实际被写入的页面分配。[Figure 7.3](#9783110785937_078254.xhtml#b_9783110785944-007_fig_003) 举例说明了这种优化的 R 对象分配。在此，自定义内存分配器被要求分配一个总大小为五个页面的对象。虽然该对象在虚拟内存中具有请求的五个页面大小（虚线，左上部分），但物理上它仅由两个页面组成（左下部分）。这两个页面分别是：开头标记为 *H*（header）的单个非共享页面，以及一个标记为 ***0*** 的共享页面，称为全局零页。物理页面下方小字的数字是 *reference counters*。零页的引用计数器为 4，因为它在分配的对象内被共享了四次（映射到虚拟内存四次）。共享零页填充了零字节。预准备零页的概念已在操作系统内核中实现。然而，标准 R 解释器无法从这一概念中受益，因为它会立即写入其为初始化而分配的所有内存。非共享的初始页面 *H* 是必需的，因为它不仅包含数据，还包含对象头。R 解释器将此对象头写入分配区域的前端。由于它会频繁更新（例如，在垃圾回收期间），因此不在多个对象之间共享。由于头页面 *H* 仅映射一次，其引用计数为 1。

R 解释器现在产生了一种错觉，即它分配了五个页面的内存，尽管物理上仅分配了两个页面。为了维持这种错觉，优化的分配机制必须确保能够检测并处理对指向共享物理页面的虚拟页面的任何写访问。如果此类写访问未被正确处理，它不仅会影响预期的虚拟页面，还会影响共享同一物理页面的所有虚拟地址。因此，引用计数器大于 1 的所有页面均被标记为 *read-only*，确保写访问触发段错误。该错误由 *signal handler* 捕获，后者执行受影响页面的取消共享。为了确定受影响的物理页面，处理程序使用写访问的虚拟地址。然后它分配一个新页面，将原始页面的内容复制到新页面，并用新页面替换导致段错误的页面。结果情况如 [Figure 7.3](#9783110785937_078254.xhtml#b_9783110785944-007_fig_003) 右侧所示：被写入的零页实例之一被替换为一个标记为 *X* 的新页面。这会更新零页和新分配页面的引用计数。由于新页面仅映射一次，现在可将其标记为 read-write，因此后续访问不再需要特殊处理。

如前所述，R 解释器只能在对象级别进行复制。因此，如果一个对象由多个页面组成，复制的部分可能最终与原始对象具有相同的内容（参见 [Figure 7.1](#9783110785937_078254.xhtml#b_9783110785944-007_fig_001)）。为避免这种情况，通过将复制粒度从对象级别提升到页面级别，优化了解释器的 *duplicate mechanism*。

虽然分配优化通过使用全局零页避免了页面的即时分配，但复制优化允许重用原始对象中已分配的页面，而不是分配新页面。[Figure 7.4](#9783110785937_078254.xhtml#b_9783110785944-007_fig_004) 展示了复制优化的一个示例。

左侧显示了复制前的情况：一个对象占据五个虚拟页面，其中两个引用全局零页。与原始 R 解释器需要为该对象的副本分配五个新页面不同，优化版本将其减少为单个分配的物理页面。这在右侧显示，顶部为原始对象，底部为其副本。此处，不创建包含对象头的第一个页面的 *virtual-only copy*，因为副本的头会在复制后立即由 R 解释器更新。否则这会触发该页面的取消共享。为避免此事件的开销，优化的复制会立即创建头页面的物理副本。原始对象的大多数页面现在在虚拟内存中映射了两次，且其引用计数器已更新。原始对象和副本均被标记为 read-only，以允许在写访问时取消共享。
