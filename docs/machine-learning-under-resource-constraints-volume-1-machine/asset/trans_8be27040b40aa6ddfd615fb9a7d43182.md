
# 调查能源效率

调查能源效率需要测量能耗。直接测量真实能耗很困难，因为存在噪声采样，且传感本身需要使用最少的资源。硬件集成的传感仪器通常不够精确，无法确定嵌入式系统上运行的软件所消耗的能量。人们已经开发出了一种易于使用的直接能量传感系统，以及一种基于线性回归的 ARM 处理器能量模型 [105, 106]。物流中使用的超低功耗设备（例如附着在集装箱上的设备）受到极大限制。基于可靠的测量，可以实现带有光伏元件的设备的能量采集，从而延长运行时间。本书的[第 2.2 节](#9783110785937_002446.xhtml#b_9783110785944-002_s_002)展示了用于能量中性传感器网络的 PhyNet 测试平台。[第 2.3 节](#9783110785937_002446.xhtml#b_9783110785944-002_s_003)介绍了一个无电池系统、其室内光能采集以及能量测量。其中甚至包括了轻量级深度学习算法的实现。预测通信网络中的功耗具有特殊的挑战性。[第 9.2 节](#9783110785937_093138.xhtml#b_9783110785944-009_s_002)介绍了针对不同无线通信技术的嵌入式设备功耗建模方法，包括一种基于机器学习的方法，用于根据可用的性能指标（如接收信号的强度和质量）来估算发射功率。

## 1.2.2 不同的处理器

不同处理器的能耗差异巨大。以进化算法（EA）实现的二次无约束二进制优化（QUBO）为例，显示了在不同数据集和参数设置下，能耗呈现稳定的数量级 [[510]](#backmatter-001.xhtml#b_9783110785944-010_ref_510)。我们在此列出这些数字，因为通常科学论文在机器学习方面需要提供此类信息。此外，QUBO 实验中发现的瓦特数值显示了典型的数量级模式：

*   **现场可编程门阵列（FPGA）**：`10⁰W`
*   **CPU（Intel Core i7-9700K）**：`10¹W`
*   **GPU（Nvidia GEFORCE RTX 2080 Ti）**：`10²W`
*   **QA（量子退火机，IBM）**：`10⁴W`

我们的计算集群平均消耗 `6.25 kWh`，数量级约为 `10³W`。当然，具体的能耗还取决于变量数量（此处为：`1024`）和 EA 的参数，例如每代的子代数量。然而，仅凭这些数字就已经可以估算出 FPGA 的优势。由于计算集群消耗的能量是 FPGA 的 `10³` 倍，它需要在更短的时间内解决学习问题——此处数量级为 `10^(−9)` 秒——才能消耗大致相同的能量，这并不现实。另一个例子研究了应用学习到的决策树（DT）模型的不同实现 [[110]](#backmatter-001.xhtml#b_9783110785944-010_ref_110)。分类以两种不同方式实现。一种按原样实现算法，另一种将树展开为 if-else 结构，即编译。随后测量了 FPGA（Xilinx Artix-7 Z-7020 FPGA，具有 `53 200` 个查找表，总共 `106 400` 个触发器（FF），结合 `4.9 MB` 块 RAM 和 `220` 个 DSP 单元）和 ARM 处理器（Cortex-A9，`666 MHz`，`512 MB` DDR RAM 和 `512 kB` 缓存）的能耗。每棵学习到的树平均包含 `1349` 个节点，以及约 `675` 条从根节点到叶节点的不同路径。吞吐量以每毫秒元素数衡量，能耗以每元素纳焦耳衡量。FPGA 上的原生实现分类每元素使用 `0.008 W` 或 `6.84 纳焦耳`，ARM 处理器上分类每元素使用 `1.53 W` 或 `105.5 纳焦耳`。展开的树在 FPGA 上分类每元素使用 `0.068 W` 或 `45.95 纳焦耳`，在 ARM 处理器上分类每元素使用 `1.53 W` 或 `52.76 纳焦耳`。

这种能耗数量级的总体排名使 FPGA 对机器学习具有吸引力。本书中，[第 6.1 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_001)研究了 FPGA 上的可重构多层感知机训练，并将其与 PyTorch 实现进行了比较。此外，[第 6.1 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_001)还探讨了多层感知机（MLP，一种用于机器学习的基本神经网络结构）的 FPGA 实现。FPGA 特别适合深度学习，因为它们支持自定义数据类型，而 GPU 仅支持有限数量的数据类型。

## 1.2.3 缩短运行时间与实时处理

许多降低机器学习能耗的方法都是通过缩短学习方法的运行时间来实现的。我们不仅从时间复杂度，还从实时能力的角度来考虑学习程序和学习模型的执行。由于许多嵌入式系统集成在与物理世界交互的大型产品中，及时性是一个重要问题。如果结果交付得太晚，它们可能已经变得毫无用处。[第 3.1 节](#9783110785937_007154.xhtml#b_9783110785944-003_s_001)中介绍的“即时”计算摘要旨在节省内存和能量。一般来说，数据流算法需要快速计算和内存减少，我们将在下文讨论。

[第 4.3 节](#9783110785937_013188.xhtml#b_9783110785944-004_s_003)中图深度学习的方法将通用消息传递扩展到任意大的图，这清楚地说明了能量与内存减少之间的联系。[第 5.1 节](#9783110785937_041148.xhtml#b_9783110785944-005_s_001)中演示的聚类运行时间显著加快，当然也节省了能量。[第 6.2 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_002)利用并行性（即使对于非均匀工作负载）作为减少运行时间和增加数据库查询执行数据吞吐量的关键。[第 6.3 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_003)描述了极端多核计算，它利用了为数千个标签进行训练的独立性。它使用数千个核心，每个核心学习预测众多类别中的一个，采用一对其余（one-versus-all）的方式训练每个类别。随着核心数量的增加，硬件感知的并行训练求解器加速直到达到饱和，此后加速比仅呈亚线性增长。

通过自适应调度缩短运行时间，将多核计算架构与机器学习结合在了一起。[第 6.4 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_004)研究了在多核架构上并行执行多种机器学习算法的优化。优化本身也使用了机器学习，即基于贝叶斯模型的优化。资源感知型基于模型的优化（RAMBO）框架通过缩短运行时间来节省能量。
