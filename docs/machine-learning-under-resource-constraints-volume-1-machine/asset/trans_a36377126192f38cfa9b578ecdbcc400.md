
这些是缓存设计的一般假设，但请注意，确切了解缓存的行为是困难的，甚至是不可能的。缓存作为CPU制造商封闭IP的一部分被制造出来，因此缓存的确切设计是未知的。此外，由于通常有多个竞争进程在单个CPU上运行，因此很难确定性地预测缓存行为。在本文中，我们假设缓存行为的设计无法更改。我们要解决的问题是：**如何在保持给定DT功能行为不变的前提下，实现对缓存友好的执行？**

首先，我们分析了DT两种常见实现方式的内存使用情况，即原生树和If-else树，它们在执行过程中均未利用DT结构的内存局部性。然后我们讨论如何使这两种实现更加对缓存友好。

## 原生树

原生树实现使用`while`循环来遍历存储在连续数据结构（例如一维数组）中的各个树节点。示例代码见清单7.1。虽然使用简单循环和少量代码行保留了时间局部性，但对DT节点的访问不具备空间局部性。节点通常根据索引顺序分配，而这些索引可能未考虑DT的执行过程，例如，同一路径上的节点可能并未顺序分配。此外，如果路径上每个节点之间的距离大于一个缓存组可容纳的节点数，某些节点将被加载到缓存中却完全不被使用，导致大量*容量缺失和冲突缺失*。

```cpp
struct Node {
    bool isLeaf;
    unsigned int prediction; // 预测标签
    unsigned char feature; // 目标特征
    float split; // 阈值
    unsigned short leftChild, rightChild;
};
Node tree[] = {{0,0,0,8191,1,2},{0,0,1,2048,3,4},..]};
bool predict(short const x[3]){
    unsigned int i = 0;
    while(!tree[i].isLeaf) {
        if (x[tree[i].feature] <= tree[i].split) {
            i = tree[i].leftChild;
        } else {
            i = tree[i].rightChild;
        }
    }
    return tree[i].prediction;
}
```

## If-Else树

另一种选择是If-else树，它将节点的分裂值静态编码在指令中。这种实现本质上避免了原生树所需的间接内存访问，通常能显著提高运行时效率。示例代码见清单7.2。然而，指令缓存中时间局部性的优势可能会完全丧失。由于DT天然由许多分支组成，某些编码指令可能被预取到指令缓存中却不被使用。此外，如果一个DT的指令大小大于指令缓存的大小，缓存的指令可能会因加载其他指令而被驱逐，导致*容量缺失和冲突缺失*。

```cpp
bool predict(short const x[3]){
    if(x[0] <= 8191){
        if(x[1] <= 2048){
            return true;
        } else {
            return false;
        }
    } else {
        if(x[2] <= 512){
            return true;
        } else {
            return false;
        }
    }
}
```

### 7.3.5 内存布局优化

下文中，我们将分析这两种不同实现的缓存行为，并相应地提出我们的树框架算法，以在应用层优化内存布局。

## 原生树

如清单7.1所示，DT可以通过在一维数组中顺序分配树节点来实现，一个简单的循环可以根据特征与分裂值的比较来访问它们。我们首先观察到，实际上树中有一半的节点是存储预测值的叶子节点。然而，这种朴素实现假设每个节点具有相同的数据类型，从而导致不必要的内存使用。其次，DT的访问模式为每个输入数据形成一条从根到叶的唯一路径，但节点通常根据广度优先搜索（BFS）顺序在数组中顺序分配。[^46]

当一个节点被加载时，数组中后续的节点会被顺序预取到数据缓存中。如果每个节点的内存大小可以减小，一次性加载到缓存中的节点就越多，从而减少整体的强制缺失。为了减少内存消耗，我们可以完全移除`isLeaf`和`prediction`字段，并通过编码带有指示符的节点类型，将子节点的预测标签直接存储在相应的字段中，即通过增加一个无符号短整型来移除一个布尔变量和两个无符号短整型。

如前所述，存储节点的顺序与树执行过程中的访问模式不一致，因此无法充分利用缓存的优势。一个合理的解决方案是利用DT执行的概率视角，识别出可能连续执行的节点，并据此将它们放置在内存中。设`τ`为缓存组大小，`A`为存放`𝒯`中所有节点的数组。此外，设`𝒞`为`𝒯`中尚未放入`A`的候选节点列表，`𝒮`表示应放置在同一缓存组中的节点。对于每个节点，我们贪婪地选择当前路径上概率最高的子节点并将其放入`𝒮`。一旦`𝒮`包含`τ` − 1个元素（即已满），我们将`𝒮`中的所有节点追加到数组`A`，清空`𝒮`，并为下一个组重复上述过程。详情总结在算法6中。
