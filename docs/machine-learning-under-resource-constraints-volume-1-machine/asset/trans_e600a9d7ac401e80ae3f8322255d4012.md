

# 基于背包的调度

要将 0-1 多重背包算法应用于异构架构上的调度，需要扩展 [第 6.4.3 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_004_s_003) 中的原始公式。现在代表作业 `J` 的项目具有不同的权重，由每种处理器类型 `k` 不同的运行时间估计 `t̂[jk]` 表示。由于 CPU 核心的容量现在是异构的，因此需要重新构建公式。为此，引入了一个比率变量，表示不同处理器类型产生的运行时间差异的近似比率。

为了最小化使用最有希望的候选者的结果进行模型更新的延迟，优先级最高的作业 `j* := argmax[j] p[j]` 现在总是被放置在能为 `j*` 带来最短估计运行时间的 CPU 核心 `k* := argmin[k] t̂[kj*]` 上。剩余 CPU 的容量（从而也是每次 MBO 迭代的时间界限）相应地由最高优先级作业的最短估计运行时间 `t̂[k*j*]` 定义。我们引入比率变量 `t̂[k*j*]/t̂[kj*]`，表示最高优先级作业在剩余 `k` 个 CPU 核心上的运行时间差异。

不同 CPU 类型上的运行时间相差一个常数因子这一假设，源自 Pinedo 描述的统一处理器模型，这是真实硬件的一个简化模型 [[579]](#backmatter-001.xhtml#b_9783110785944-010_ref_579)。例如，某个 CPU 可能提供一些作业受益的向量指令，而其他作业则完全不使用它们。我们不依赖静态预计算的比率（例如源自 CPU 频率比的比率），而是在给定的 MBO 迭代中，使用选定的作业 `j*` 作为比较 CPU 速度的“基准”，假设在此迭代中 CPU `k` 上的速度与 `k*` 上的速度相差一个因子 `t̂[k*j*]/t̂[kj*]`。因此，剩余 CPU 核心容量限制的公式如下，而背包算法的其余部分保持 [第 6.4.3 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_004_s_003) 中所述不变：

(6.28) `${\\hat{t}}_{k^{\\star}j^{\\star}}\\frac{{\\hat{t}}_{k^{\\star}j^{\\star}}}{{\\hat{t}}_{kj^{\\star}}} \\geq {\\sum\\limits_{j \\in J}{\\hat{t}}_{k^{\\star}j}}c_{kj}\\forall k \\in K.` (6.28)

这里，方程 6.28 右侧剩余候选者在最快 CPU 核心 `t̂[k*j]` 上的估计执行时间，预期近似等于作业在剩余 CPU 核心 `t̂[kj]` 上的估计运行时间乘以比率变量：

(6.29) `${\\hat{t}}_{k^{\\star}j} \\approx {\\hat{t}}_{kj}\\frac{{\\hat{t}}_{k^{\\star}j^{\\star}}}{{\\hat{t}}_{kj^{\\star}}}\\forall k \\in K,\\forall j \\in J.` (6.29)

这种公式化是必要的，旨在将每个项目 `j` 的权重数量（每种 CPU 类型的运行时间估计数量）减少为单个权重 `t̂[k*j]`，以便应用原始的背包算法。

# 评估

异构 RAMBO 方法的有效性通过针对 ARM big.LITTLE 架构[^(43)](#fn43) 进行评估。

实验设置由 [第 6.4.3 节](#9783110785937_066530.xhtml#b_9783110785944-006_s_004_s_003) 中描述的设置的一个子集组成。RAMBO 与使用 `qLCB` 多点填充准则的传统同步 MBO 方法，以及旨在利用所有可用 CPU 时间并行求解优化问题并使用 Kriging 置信准则 [[254]](#backmatter-001.xhtml#b_9783110785944-010_ref_254) 的异步 MBO 方法进行比较。所有 MBO 方法均在合成函数的 2 维版本上进行评估，并在 4 个 CPU 核心上执行。目标函数的运行时间先前通过休眠给定时间来模拟，该时间由一个额外的合成函数确定，该函数代表相应目标函数的运行时间行为。对于功耗测量，需要真实的计算。这是通过反复执行一个提取随机数的函数来实现的。该真实计算的运行时间仍通过一个额外的合成函数控制，该函数定义重复次数并模拟计算目标值所需的时间。对于模拟目标函数运行时间的合成函数，使用了 `rosenbrock(d)` 函数，因为它比 `rastrigin(d)` 提供更可靠的运行时间估计（参见 [图 6.20](#9783110785937_066530.xhtml#b_9783110785944-006_fig_020)[)](#9783110785937_066530.xhtml#b_9783110785944-006)。`rosenbrock(2)` 函数的输出被缩放为返回 5 分钟到 50 分钟的值。MBO 方法在 `m = 4` 个 CPU 核心上运行 2 小时，并包含所有计算开销和 CPU 空闲时间。初始集的生成方式与同构实验相同，使用拉丁超立方采样 [[481]](#backmatter-001.xhtml#b_9783110785944-010_ref_481)，配置数 `n = 4 * d`。所有方法在所有 10 次重复中都从相同的初始集开始。

基准测试表明，新的基于背包的异构系统算法具有总体优势，尤其是在最高准确度水平 0.01 时。平均而言，`rambo` 在达到这三个准确度水平中的每一个时都是最快的，因此在 2 小时的时间预算内收敛到最优解的速度更快。与 `rambo` 相比，传统的同步 MBO 方法 `qLCB` 在所有 10 次重复中均无法为 `rastrigin(2)` 和 `ackley(2)` 函数达到 0.01 的准确度水平（参见 [图 6.24](#9783110785937_066530.xhtml#b_9783110785944-006_fig_024)）。对于 `bohachevsky(2)` 和 `rastrigin(2)` 函数，异步 MBO 方法 `asy.ei.bel` 也存在同样的情况。
