

### 5.1.4 设施选址问题与电网仿真

设施选址问题（FL）的目标函数为：

$$ \sum_{j \in M} c(j) + \sum_{i=1}^{N} d(i, m(i)) $$

其中 `c(j)` 为开设设施的成本，`d(i, m(i))` 为消费者 `i` 与其分配中心 `m(i)` 之间的距离。FL 与 `k`-medoids 的目标函数有很强的相似性。我们将设施视为电力变电站，将消费者视为需求点。**图 5.3** 展示了使用 Faster-PAM 对生成的 Witten Stockum 图进行聚类的结果，设定 `k` = 4 个变电站。我们可以观察到，簇分配遵循道路网络，消费者不一定被分配给“直线距离”最近的中心。

即使有 FasterPAM 的改进，运行时复杂度仍为 `O(N²i)`，其中 `N` 为图中的节点数，`i` 为优化过程的迭代次数。底层的 OSM planet 文件包含约 1.2 TB 数据。尽管我们只对建模世界较小区域感兴趣，但仍需降低复杂度，以便在可接受的运行时间内解决整个城市或地区的任务，因为这些区域仍包含数千栋房屋。我们利用典型电网的一些特性。我们仅将至少有 3 条出边的节点视为可能的最优变电站位置（孤立点除外）。单条边上的最优位置易于计算，此处忽略不计。因此，将其表述为非对称问题（需求点与设施位置不再是同一集合）是有益的。距离矩阵不再需要为所有节点对计算，而只需为所有需求点和变电站位置连接计算。这将复杂度降低至 `O(Nmi)`，其中 `N` 为消费者数量，`m` 为可能的变电站位置数量，且 `m < N`。如果我们进一步限制消费者与变电站之间的最大距离（以限制功率损耗），该距离矩阵变为**稀疏**，即我们有缺失值，可视为无穷大。如果不存储这些缺失值并使用适当的稀疏数据结构进行迭代，可望将运行时间进一步降低至 `O((e + N + m) · i)`，其中 `e` 为边数。假设房屋和道路密度处处相似，我们预期边数 `e` 与我们处理的地图**面积**近似成线性关系。

### 5.1.5 稀疏 `k`-Medoids

要将 `k`-medoids 聚类用于具有非对称和稀疏输入数据的问题，我们必须调整 `k`-medoids 的目标函数。我们仍希望最小化所有数据点 `{x[1], ..., x[N]}` 相对于当前 medoids 集合 `M ⊆ {y[1], ..., y[m]}` 的“总偏差”，但不再像传统 `k`-medoids 那样假设 `M ⊂ X`。此外，对于某些点，当前可能不存在最近的可达 medoid `m(x[i])`，且该 `x[i]` 到所有 medoids `m[i] ∈ M` 的距离均未定义。在这种情况下，我们必须在损失 `ℓ` 中引入惩罚 `π(x[i])`：

$$ \mathcal{l} := \sum_{i = 1}^{N} \begin{cases} \pi(i) & \text{if } m(x_i) = \text{undefined} \\ d(x_i, m(x_i)) & \text{otherwise} \end{cases} \quad (5.3) $$

注意，我们允许集合 `M` 的大小发生变化。惩罚 `π(i)` 可用于权衡未覆盖所有可能数据点的损失与拥有更大距离的情况。我们不再进一步考虑调整此参数，而是使用 `π(i) = π = const → ∞` 以强制完全覆盖。由于此类极端值可能导致数值问题，我们的实现始终使用数对 `(i, d)` 来存储损失（及损失变化）：整数 `i` 计算未分配点的数量，`d` 为已分配点距离之和，使得数学上 `ℓ = i · π + d`，但避免了数值问题。

基于该目标函数，我们引入 **DynBUILD**（动态非对称 BUILD 初始化），作为 Kaufman 和 Rousseeuw 的 BUILD 算法针对非对称稀疏输入数据集的改编。如果在选择 `k` 个 medoids 后，某些对象（仍）无法被当前 medoids 集合到达，贪婪 BUILD 方法将通过动态增加 `k` 来补充。因此，该算法始终至少选择 `k` 个 medoids 并覆盖所有消费者。作为基线，记为 **Random** 的策略仅使用给定百分比的点作为初始簇中心，因此可能产生违反约束的初始解，但我们改进的 **DynSWAP** 过程将在优化分配时修复这些违规。**Sparse++** 是将著名的 `k`-means++ 方法改编为稀疏数据，按簇中心覆盖的点数比例选择中心（同样，我们继续选择额外中心直到满足所有约束）。

我们引入 **DynSWAP**（面向非对称稀疏数据的动态 SWAP），作为基于 FasterPAM 的动态 SWAP 算法，改编用于在高效处理非对称和稀疏输入数据的同时动态减少 `k`。DynSWAP 与 FasterPAM 的 SWAP 有两点不同：为根据约束动态改变 `k`，我们在每次交换后检查是否可在不违反约束的情况下减少 `k`（第 30 行）；如果当前对象不适合交换但作为新 medoid 添加（第 34 行）可减少违反约束的数量，则将其作为额外 medoid。我们刻意选择仅在执行交换时才减少 `k`，以在优化现有 medoids 与学习簇数 `k` 之间交替。这两种检查实现起来非常高效，因为我们已经知道所有 medoids 的移除损失变化（`Δℓ^(−m[1]), …, Δℓ^(−m[k])`，这也是 FastPAM 改进 PAM 所需的），并且在 `Δℓ^+` 中也有添加新 medoid 时的损失变化。如果 `π` 分量为零：`Δℓ[π]^(−m[i]) = 0`，则可在不破坏任何约束的情况下移除 medoid `m[i]`；如果当前候选 `y[j]` 的 `Δℓ[π]^+ < 0`，则将其作为新 medoid 是有益的。每当添加、移除或交换 medoid 时，我们需要为所有数据点 `x[o]` 更新最近 medoid `n[1](o)`、到最近 medoid 的距离 `d[n[1]](o)` 以及到第二近 medoid 的距离 `d[n[2]](o)`。这可以通过更新先前值更高效地完成，完全同 FasterPAM。基于此信息，我们也可以高效更新 `Δℓ^(−m[1]), …, Δℓ^(−m[k])`（即移除每个 medoid 的损失变化）：对于每个对象，移除最近 medoid 会导致损失变化为 `(0, d[n[2]](o) − d[n[1]](o))`（若存在第二近 medoid），否则为 `(π(o), −d[n[1]](o))`。移除除最近 medoid 以外的其他 medoid 不会导致损失变化。
