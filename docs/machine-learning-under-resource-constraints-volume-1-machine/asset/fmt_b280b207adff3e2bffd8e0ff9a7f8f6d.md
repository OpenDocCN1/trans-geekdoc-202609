
## Datasets

为了验证算法，我们需要足够大的测试数据集，并选择约束条件以获得稀疏距离矩阵。在本工作中，我们专注于由 `OSMOGrid` 生成的能量网格的处理和评估。对于质量评估，我们选择 OSM 中记录了许多变电站的区域。[图 5.4](#9783110785937_041148.xhtml#b_9783110785944-005_fig_004) 显示了 `OSMOGrid` 为维滕市生成的电网剖面图，使用了来自 OSM 的 127 个变电站位置（尽管这很可能不完整，如 [图 5.5](#9783110785937_041148.xhtml#b_9783110785944-005_fig_005) 所示）。然后我们可以将计算模型的质量与基于真实变电站的模型进行比较，但我们需要记住，OSM 中可能缺少额外的变电站，并且真实电网是历史演变而来的，必须满足额外的约束条件，因此并非最优。为了生成“现实”的网络，期望达到可比的质量，而不必过拟合到我们拥有的示例数据。在该数据集上，我们评估选择 `k` 的动态方法。“最优” `k` 取决于约束条件，从而取决于距离矩阵的稀疏性。[图 5.5](#9783110785937_041148.xhtml#b_9783110785944-005_fig_005) 显示了满足电网中最大电缆长度约束的最小 `k`。随着电缆长度增加，矩阵中缺失距离的数量减少，但最佳变电站数量下降得快得多。

## Dynamic `k`

为了评估可变 `k` 的质量，我们将算法找到的解与所有运行中已知的最佳解进行比较。我们还比较了不同的初始化算法和动态 `SWAP` 的变体。我们测量解的 `k`、初始化和 `SWAP` 的运行时间，以及结果是否满足所有约束。汇总结果见 [表 5.1](#9783110785937_041148.xhtml#b_9783110785944-005_tab_001)。只有不带动态增加 `k` 的 `Random⁵` 初始化无法满足约束。这是意料之中的，因为它仅使用 5% 的可能变电站作为类心，但似乎不存在仅使用这么少聚类的解。由于 `DynBUILD` 是确定性的，它在初始化后总是产生 `k` = 93 个聚类。经过 `SWAP` 阶段后，平均 `k` 为 76.2，比已知最佳 `k` = 74 多 2.2（我们在 `SWAP` 中按随机顺序迭代以避免依赖输入数据顺序）。由于初始解已经满足所有约束，且 `SWAP` 保持这一属性，`k` 只能减少。在随机初始化中，带 `DynSWAP^(↓↑)` 的 `Random⁵` 平均找到了最佳结果。`SWAP` 阶段后 `k` = 77.9，站点数量平均比最佳 `k` 大 3.9 倍。最后，`DynBUILD` 后的 `SWAP` 平均需要随机初始化后 `SWAP` 运行时间的 48.4%。由于随机初始化，`SWAP` 期间类心变更的平均数量从 141 显著增加到 310，表明与随机采样和 `Sparse++` 相比，`DynBUILD` 具有更优越的起始条件。

## Runtime Speedup

为了评估不同方法的运行时间，我们对不同的约束条件和 `k` 值进行实验。[图 5.6](#9783110785937_041148.xhtml#b_9783110785944-005_fig_006) 显示了 `DynBUILD`、`Random⁵`、`Random^(10)` 和 `Sparse++` 初始化的总运行时间（初始化和 `SWAP`）。我们再次使用维滕数据集，并选择距离约束，使所有方法都能达到所需的 `k`。我们将运行时间与带随机初始化的 `FasterPAM` 实现进行比较（这是 `FasterPAM` 的推荐方式）。对于 `DynBUILD`，我们评估动态减少 `k` 的 `SWAP`（`Dyn^↓`），对于所有随机初始化，评估动态增加和减少 `k` 的 `SWAP`（`Dyn^(↓↑)`）。我们在此图上使用对数刻度，因为差异巨大：所有初始化上的稀疏性优化 `DynSWAP` 平均仅使用带随机初始化的原始 `FasterPAM` 运行时间的 7%；`DynBUILD` 和 `DynSWAP^↓` 组合平均仅使用 4%。这是预期的，因为 `FasterPAM` 必须处理大得多的稠密矩阵。随着 `k` 增加，我们可以使用更稀疏的矩阵，这就是 `DynSWAP` 方法变快而 `FasterPAM` 因聚类数量增加而变慢的原因。各种随机初始化在运行时间上仅略有差异，但平均需要约 `DynBUILD` 两倍的时间。除了快速运行时间外，`DynBUILD` 配合 `Dyn^↓ SWAP` 相比已知最佳 `k` 产生的额外聚类数量最少，平均比已知最佳 `k` = 74 多 2.2 个站点。
