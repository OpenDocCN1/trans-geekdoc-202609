## 数据源的多实例

关系模型很容易扩展到数据源的多个实例，例如多个网络接口。从建模角度来看，这只是在相应的关系或流中增加一个标识列。因此，`Packets` 查询（[清单 2.1](#9783110785937_002446.xhtml#b_9783110785944-002)）和后续的聚合（[清单 2.2](#9783110785937_002446.xhtml#b_9783110785944-002)）仍然有效，甚至可以通过按网络接口聚合来扩展。

### 2.1.4 实现

kCQL 架构概览见 [图 2.2](#9783110785937_002446.xhtml#b_9783110785944-002_fig_002)。我们区分客户端和 kCQL 核心。客户端向核心提交查询，并持续接收数据，直到显式撤销查询。核心生成查询执行计划，并根据正在运行的查询处理数据。然而，必要的数据源也是由（其他）客户端提供的。在这方面，客户端类似于 DTrace 的提供者。由于客户端可以在内核空间和任何用户进程中运行，数据必须跨地址空间传输。查询计划被划分为多个部分，以尽量减少地址空间之间的数据流，而不是将数据移动到一个中心位置进行处理，然后将查询结果分发给客户端。因此，每个地址空间都有自己的 DSMS 引擎实例，每个实例处理查询的不同部分。

#### 2.1.4.1 DSMS 引擎

kCQL 的核心，其 DSMS 引擎，基于斯坦福的数据流管理系统 STREAM [\[21\]](#backmatter-001.xhtml#b_9783110785944-010_ref_021)。它负责查询计划生成和查询执行。STREAM 是为从按需生成新元组的同步数据源拉取数据而构建的。相比之下，kCQL 使用异步操作系统事件。必要的修改在 [第 2.1.4.2 节](#9783110785937_002446.xhtml#b_9783110785944-002_s_001_s_004_s_002) 中描述。

时变关系表示为更新流，包含带有时间戳和插入或删除标记的元组。这不仅适用于查询输出（如 [表 2.2](#9783110785937_002446.xhtml#b_9783110785944-002_tab_002) 所示），也适用于查询输入（数据源）和由关系算子（例如连接）生成的中间关系。因此，基于实际操作系统数据的关系（如进程表）也必须转换为这种更新流。

**查询计划生成** 在解析查询和数据源描述后，STREAM 从数据源到查询输出生成一个有向无环的关系算子数据流图。此时，我们引入一个步骤，将该图划分到参与的地址空间中。之后，向查询计划添加辅助结构，然后将其实例化以供执行。引擎实例包含以下元素：

*   **摘要** 提供当前与算子相关或包含在关系中的所有元组的视图。它们还维护索引，以便使用谓词高效地扫描它们（例如，查找连接伙伴）。
*   **算子** 执行关系操作或流与关系之间的转换。对于某些算子（如连接），流形式的关系表示是不够的，因为它们需要在处理当前输入元组时，查看包含在关系中的所有元组。它们通过*摘要*来实现这一点。*源算子*和输出算子在客户端和引擎实例之间建立接口。对于 kCQL，我们添加了发送器和接收器，以跨地址空间传输流和关系。
*   **队列** 缓冲算子之间的元组流。队列元素包含元组的时间戳，对于关系，还包含类型（插入或删除）。为了避免复制元组内容，队列元素不包含内容，而是指向共享存储中的位置。
*   **存储** 包含实际的元组内容，并在通信算子之间共享。它们由算子及其摘要使用。元组内容通过引用计数等元信息进行扩展。

除了查询计划的基本优化（如将合并、过滤和投影融入其他算子）外，STREAM 还在适当的地方用纯流算子替换关系算子。对于 [清单 2.1](#9783110785937_002446.xhtml#b_9783110785944-002) 中的 `Packets` 查询，STREAM 不从数据包流生成实际窗口；而是直接将流元组与关系连接。过滤和投影也是如此。

**通过时间单调性保证一致性** 如果我们将来自流（例如数据包）的元组与关系（例如进程列表）进行连接，连接伙伴（例如进程）可能在实际的操作系统数据结构中不再存在（例如，因为进程可能已经终止）。使用 STREAM，这不会导致不一致，因为算子按时间戳顺序逐个出队并处理元素。这意味着连接总是先从流中出队元素，并将其与其摘要中的元组连接。只有在此之后，它才处理关系中的删除并更新其摘要。这样，也确保了所有其他算子（包括纯关系连接和窗口）的一致性。

然而，这要求所有队列都按时间戳排序：算子不得在出队时间戳为 `t`[1] 的元组后，再入队时间戳为 `t`[0] 的元组（其中 `t`[1] > `t`[0]）。对于处理算子，这意味着输出元组的时间戳总是其所基于的元组时间戳的最大值。对于关系 `R` 和 `S` 的全连接，这意味着：如果带有时间戳 `t` 的元组 `x` 被插入 `R`，那么生成的输出元组（即将 `{x}` 与 `S` 连接的结果）具有时间戳 `t`。
