

## 复合内核

内核融合将归约操作（例如前缀和）作为边界推到了聚光灯下。此前，我们在两个生成的内核*之间*计算前缀和以获取写入位置。我们现在不再生成两个独立的内核，而是仅生成一个集成了前缀和计算的*复合内核*（参见[图 8.14](#9783110785937_085767.xhtml#b_9783110785944-008_fig_014)），这消除了多次遍历。在生成的内核*内部*计算写入位置，使得无需中间物化即可在一次遍历中处理流水线。这样，每个融合算子都由单个复合内核执行。在下文中，我们将探讨实现归约操作的策略，以实现全流水线处理。

## 原子前缀和

带有中间物化的多个归约内核的分离阻碍了流水线处理。为了引入流水线实现，让我们首先看一个非常简单的顺序前缀和：

```
for(i=0; i<n; i++)
if(flags[i]) prefix_sum[i] = sum++;
```

顺序前缀和遍历数组 `flags`，同时为每个有效条目写入*并*递增 `sum`。[图 8.15](#9783110785937_085767.xhtml#b_9783110785944-008_fig_015)a 展示了利用前缀和对选定输入元素进行密集写入的过程。当并行化 `for` 循环时，该实现会遇到许多线程尝试同时递增 `sum` 的问题。为了解决这种并行依赖，可以使用原子操作来隔离对同一内存地址的并行修改。原子操作确保状态一致，但以未定义的顺序执行。以下代码执行*原子前缀和*以计算无序、密集的写入位置：

![Fig. 8.15 为将选定元素写入密集数组而计算前缀和 (a) 可使用原子操作并行化 (b)。](graphic/b_9783110785944-008_fig_015.png)

图 8.15 为将选定元素写入密集数组而计算前缀和 (a) 可使用原子操作并行化 (b)。

```
if(is_selected) wp = atom_add(&sum, 1);
```

线程通过有条件地执行表达式，向地址 `&sum` 处的 sum 贡献 1 的偏移量。每个 `atomic_add(..)` 返回 `sum` 的先前状态。因此，线程立即在寄存器中获得一个唯一的全局写入偏移量 `wp`。这在[图 8.15b](#9783110785937_085767.xhtml#b_9783110785944-008_fig_015) 中进行了说明。

原子操作的使用打破了前缀和的语义，因为结果*没有定义的顺序*。然而，对于关系语义而言，输出位置的*唯一性*至关重要。输出排列会导致非对齐的 GPU 全局内存访问，即相邻线程不写入相邻的内存地址。然而，对写入吞吐量的影响是有限的，因为过滤语义也会导致单独前缀和的非对齐访问。

### 8.2.7.1 内存访问与局限性

复合内核微执行模型进一步将 GPU 全局内存访问减少了 2.4 倍，降至 1.8 GB（参见[图 8.13](#9783110785937_085767.xhtml#b_9783110785944-008_fig_013) 和 [8.16](#9783110785937_085767.xhtml#b_9783110785944-008_fig_016)）。与逐个算子执行相比，这是 4.7 倍的减少。流水线化前缀和避免了三阶段微执行模型中必需的 GPU 全局内存往返。复合内核仅具有用于输入、输出和哈希表访问的最小 GPU 全局内存访问量。现在，当将每个内存量与可用带宽相关联时，片上流量与 GPU 全局内存流量实现了平衡。

所述方法严重依赖原子操作。这有一个缺点，即导致并行性的局限性。尽管执行顺序未定义，但操作*确实*被串行化了，归约 *n* 个值需要 *O*(*n*) 个并行步骤。然而，Egielski 等人 [\[195\]](#backmatter-001.xhtml#b_9783110785944-010_ref_195) 表明，最近的硬件支持使原子操作具有与并行算法竞争的性能。尽管如此，集成前缀和仍给原子功能单元带来了巨大压力，这阻碍了流水线内核利用满 GPU 全局内存带宽。在下文中，我们将解决这个问题，并展示如何提高复合内核中并行归约的效率。

## 8.2.8 高效流水线归约

我们展示了一种使用原子操作在生成的内核中流水线化归约的方法。这有利于内存效率，但也暴露了 GPU 的原子功能单元是一个瓶颈。这尤为关键，因为复合内核中组合的多个操作也依赖原子隔离。具体而言，哈希连接和哈希聚合的最先进实现 [\[358\]](#backmatter-001.xhtml#b_9783110785944-010_ref_358) 使用原子操作来隔离哈希表插入。

本节解决利用原子归约来流水线化关系算子时出现的性能瓶颈。我们展示了一种称为*局部解析，全局传播*的新技术，该技术被 *HorseQC* 用于高效地流水线化前缀和、单元组聚合和分组聚合。该方法降低了对原子功能单元的压力，并提供了关于硬件和线程组粒度的可调性。我们在下文中描述该方法。

### 8.2.8.1 局部解析，全局传播

与 CUB [\[489\]](#backmatter-001.xhtml#b_9783110785944-010_ref_489) 等其他高效 GPU 实现一样，局部解析与全局传播包含两级归约。然而，与其他技术不同的是，它在*两个*层级上始终使用流水线技术。局部解析是由局部线程组计算的额外预归约步骤，而全局传播则是[第 8.2.7 节](#9783110785937_085767.xhtml#b_9783110785944-008_s_002_s_007)中描述的相同原子归约。我们使用术语*协作线程阵列*（CTA）来表示局部解析中的线程组。CTA 可以匹配 GPU 内核的工作组（AMD）或线程块（NVIDIA）大小，也可以在更细的粒度上工作。

以下代码（如[图 8.17](#9783110785937_085767.xhtml#b_9783110785944-008_fig_017) 所示）使用局部解析、全局传播执行原子前缀和：

```
l_os = cta_prfx(flags, &cta_total); //局部解析

if(cta_thread_idx == 0)
g_os = atom_add(&sum, cta_total); //全局传播

wp = l_os + g_os;
```

首先，每个 CTA 执行 `cta_prfx` 以在 `flags` 上计算局部前缀和。这是局部解析步骤。我们使用 SIMD 归约实现 `cta_prfx`（参见 Sengupta 等人 [\[622\]](#backmatter-001.xhtml#b_9783110785944-010_ref_622) 的 Warp 内扫描算法）。该函数返回局部偏移量 `l_os` 和分配给 CTA 的所有标志之和 `cta_total`。其次，每个 CTA 的一个线程将 `cta_total` 原子地加到全局计数器 `sum` 上。这是全局传播步骤。
