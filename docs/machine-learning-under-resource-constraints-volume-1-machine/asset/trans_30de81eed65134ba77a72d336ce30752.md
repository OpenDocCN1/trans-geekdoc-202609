
我们利用诸如 `METIS` [175, 361] 之类的图划分方法来实现这一目标。其旨在构建图中节点的划分，使得簇内的链接（intra-links）出现频率远高于不同簇之间的链接（inter-links）。直观上，这导致节点的邻居位于同一簇中的概率很高。值得注意的是，现代图聚类方法既快速又可扩展，其时间复杂度为 `𝒪(|ℰ|)`，且仅需应用一次，从而在预处理阶段产生微不足道的计算开销。然而，这种方法能加速训练，因为位于 `ℬ` 之外的邻居数量大幅减少，且将信息推送到历史记录中可实现连续内存传输。

### 4.3.4.2 快速历史嵌入

我们的方法通过访问历史记录来处理当前 mini-batch 之外的任何数据，这需要频繁地在 GPU 之间传输数据。因此，优化从历史记录中拉取（pulling）和推送（pushing）数据显得尤为重要。我们通过利用*非阻塞*设备传输来实现这一点。具体而言，我们在每个优化步骤开始时立即异步拉取每一层的历史嵌入，这确保了 GPU 在等待内存传输完成时不会空闲。一个单独的工作线程将历史信息收集到多个锁页 CPU 内存缓冲区（记为 `PULL`）中的一个，随后可通过 `CUDA` 流将其传输至 GPU，而不会阻塞任何 CPU 或 `CUDA` 执行。同步通过在将传输数据输入 `GNN` 层前同步相应的 `CUDA` 流来完成。相同的策略也适用于将信息推送到历史记录。考虑到 `${\\overline{H}}^{(\\mathcal{l} - 1)}` 的设备传输速度快于 `*f*[*θ*]^((𝓁))` 的执行速度，利用历史嵌入时该方案不会带来任何运行时开销，且速度可比其串行非重叠对应方案快两倍（参见 [图 4.12](#9783110785937_013188.xhtml#b_9783110785944-004_fig_012)）。我们使用自定义 `C++`/`CUDA` 代码实现了非阻塞传输方案，以避免 `Python` 的全局解释器锁。

### 4.3.4.3 实验评估

对于大规模 `GNNs` 的训练，GPU 内存消耗直接决定了给定方法的可扩展性。在 Fey 等人 [[224]](#backmatter-001.xhtml#b_9783110785944-010_ref_224) 中，我们证实了通过 `GAS` 训练的 `GNNs` 能够学习到富有表达力的节点表示，其性能与非扩展版本非常接近，并在大规模图上达到了最先进的性能。在此，我们展示 `GAS` 如何在保持低 GPU 内存占用的同时，与其他可扩展性方法不同，利用数据中存在的所有信息。我们直接对比了三个大规模数据集 [320, 731] 上 `GCN`+`GAS` 训练、全批次 `GCN` [[375]](#backmatter-001.xhtml#b_9783110785944-010_ref_375)、mini-batch `GRAPHSAGE` [[292]](#backmatter-001.xhtml#b_9783110785944-010_ref_292) 以及 `CLUSTER-GCN` [[137]](#backmatter-001.xhtml#b_9783110785944-010_ref_137) 训练的内存使用情况（[表 4.2](#9783110785937_013188.xhtml#b_9783110785944-004_tab_002)）。值得注意的是，`GAS` 能轻松将所需数据放入 GPU，且内存消耗仅随层数线性增长。虽然 `CLUSTER-GCN` 的总体内存占用低于 `GAS`，但它仅利用了可用信息的一小部分，即平均约 23%。

我们现在分析 `GAS` 如何通过快速 mini-batch 执行实现大规模训练。具体而言，我们关注的是我们的并发内存传输方案如何减少从离线存储访问历史嵌入所带来的开销。为此，我们在合成图数据上评估了 4 层 `GIN` 模型的运行时间，这允许对簇内连接节点与簇间连接节点的比例进行细粒度控制（[图 4.13](#9783110785937_013188.xhtml#b_9783110785944-004_fig_013)[)](#9783110785937_013188.xhtml#b_9783110785944-004_tab_002)。此处，给定的 mini-batch 由恰好 4000 个节点组成，这些节点随机内连至 60 个其他节点。我们通过添加随机连接到批次内 60 个节点的批次外节点来改变簇间连接的数量（与批次外节点的连接）。值得注意的是，朴素的串行内存传输使运行时间增加高达 250%，这表明频繁的历史访问可能导致严重的 `I/O` 瓶颈。相比之下，我们的并发访问模式*完全*没有 `I/O` 开销，执行时间的开销仅由消息传播期间聚合更多消息的计算开销解释。考虑到可用的额外数据量增加，这种开销是微不足道的，特别是因为大多数真实世界数据集的簇间/簇内连接比在 0.1 到 2.5 之间 [[224]](#backmatter-001.xhtml#b_9783110785944-010_ref_224)。此外，预处理阶段计算 `METIS` 划分的额外开销可以忽略不计。计算一个拥有 200 万节点的图的划分仅需约 20-50 秒（取决于簇的数量）。
