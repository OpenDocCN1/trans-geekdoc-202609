**摘要** 在日常生活中，我们依赖制造者提供的信息来做出正确选择，例如食物的营养成分、药品警告、建筑道路的衡量标准等；但当涉及到 AI 时，目前缺乏关于机器学习模型的提供信息。这些模型在发布时，人们并未充分了解其工作原理、在何种条件下表现最佳、是否公平或存在偏见，以及它们溯源于何处。

开发者可以使用这些工具来设计应用程序，强调模型的优势，同时避免或告知终端用户其局限性。像用户一样，分析师和记者也可能提供见解，使某些技术更容易向普通大众解释，并帮助倡议团体更好地理解 AI 对社会的影响。

模型卡片是必要的工具，也是研究的热点。在机器学习（ML）中，模型卡片的透明度具有相关性，因为它涵盖了从健康到金融、职业等广泛领域。本研究展示了模型卡片和透明度的重要性。

模型卡片工具包（MCT）提供了一个 JSON 架构，展示了图中所示的模型细节：

1. 模型溯源信息存储在机器学习元数据（MLMD）中，并以 JSON 格式填充相关信息。还提供了一个反向过程的 API，用于获取存储的信息并以卡片语法的形式进行可视化。
2. 模型卡片创建者可以选择在最终卡片中显示的图表和指标，还可以创建局限性、权衡、预期使用场景等信息。这对于开发者进行选择至关重要。MCT 包含了标准的用户界面（UI）模板，但用户也可以用 HTML 创建模板，以帮助信息密度视觉化。

*索引术语* 模型描述、分层评估、AI 公平性、机器学习评估、数据集。

目前，MCT 已作为开源软件提供给 TensorFlow 扩展用户，同时未使用 TensorFlow 的 Google 云平台用户也可以通过模板引擎生成模型卡片。

模型卡片是研究领域中提出的一种方案，旨在以结构化的方式处理机器学习的本质事实。

在机器学习中，卡片透明度非常重要，因为它影响了从健康到就业的广泛领域。下游用户所需的信息可以轻松使用，且往往超过了所用模型的意图。如果通过建立模型的基本事实来保持透明度，用户就可以选择合适的模型进行使用。

大多数成熟的行业已经开发了在各种条件下对许多系统进行基准测试的标准方法。例如，如 [1] 所示，硬件行业使用数据集以及组件在各种条件下的性能。相比之下，由于机器学习模型广泛的应用和影响力，目前不存在针对机器学习模型的标准化测试。

多年来，模型卡片的使用日益增加，例如创建计算机视觉模型状态的 MediaPipe 已经在其仓库中包含了模型卡片。这些卡片集包含了大量的时间和精力，通常需要对性能进行详细分析，这可能是一项枯燥的任务。模型创建者可能希望以用户更容易理解的方式说明模型的局限性或用例。

为了简化这些模型卡片的创建，引入了共享卡片工具包（MCT），它是一系列帮助开发者收集模型卡片可能所需信息的工具集 [15]。

提高机器学习模型的透明度可以使专家和非专家共同受益。

专家已经提出了归一化结构，用于对应 AI 中的归属数据集 [2,1,3]，以帮助客户理解数据集创建时的设置。我们提出了一种归一化技术，重点关注：

## 模型卡片

- **模型细节**。关于模型的基本信息。
  - 开发模型的个人或组织
  - 模型版本
  - 模型类型
  - 关于训练算法、参数、公平性约束或其他应用方法及特征的信息
  - 用于获取更多信息的论文或其他资源
  - 引用详情
  - 许可协议
  - 关于模型的提问或意见的反馈接收处

- **预期用途**。开发期间使用的用例：
  - 主要预期用途
  - 次要预期用途
  - 范围之外的用途

- **因素**。考虑人口统计或表型群体、环境条件、技术属性或其他的因素
  - 因素列表

- **评估因素**

- **指标**。选择的指标应反映真实性能
  - 模型性能
  - 决策阈值

- **评估数据**。可能的情况下，此部分应包含所用数据集的数据
  - 定量分析
  - 预处理
  - 伦理考量
  - 建议
  - 交叉分析结果

随着机器学习技术的快速增长，那些希望在特定场景下使用机器学习模型的人之间，存在着日益扩大的鸿沟。

模型卡片首次是为了规范伦理实践，并让用户-利益相关者在模型部署到特定用途之前对其进行沟通。这是为了确保决策的安全，并帮助用户在 AI 市场中找到适合自己的模型，以确保模型卡片的输出准确且无歧义。

评估两组评估集至关重要：一组协调工作环境-人口，另一组则包含对模型可能更有意义的人（例如，年轻人、老年人以及工作环境之外的人员）。这可能包含在正常测试中显而易见的目标。针对不同类型的利益相关者，我们可能有：

通过关于准备信息的逐点数据。例如，这些信息可能是排他的或不相关的安排。在这些情况下，我们主张考虑信息中聚集分散的根本性见解，无论其他人可能对他们可能编码的分类包含所解决的负面划分。

1. AI 和 ML 从业者可以更好地理解模型如何运行，并在各种用例中监控其执行情况。
2. 系统开发人员可以将实验结果与相同领域的其他模型进行比较，并决定是否训练它们。
3. 负责管理的软件工程师应该利用模型预期来决定他们的计划和用法。
4. 政策制定者应该看到 AI 模型在许多不同实例中的证明或失败。
5. 公司将评估有关引入 AI 的新的执行情况。
6. ML 精通者可以简要说明选择模型、微调或额外的差异，并帮助在没有专业知识的情况下为预期用例改进模型。
7. 体验模型影响的个人可以帮助澄清我们如何为了护理或评估模型。

这种方法不仅增强了稳健性并有助于为相关利益相关者简化决策流程，还促进了前瞻性的模型方法。例如，将数据切分为不同的类别可能会揭示可能出现在个体频率中的问题，这与其他正义的概念相符（因为经常出现在图 1 的模型卡中）。社区监控过程允许成员在特定环境中评估 ML 算法，应用报告是一种开放的方法，这还导致 ML 训练输入和小组可能也包含关于为什么的信息，并将未来的关注点放在上述哪些版本适用于他们的特定目的。通过监控模型，利益相关者可以充分了解各种模型。此外，运行独立数据集的发现可能使潜在消费者受益，使用评估数据集进行测试和研究可能涉及开发可靠的评估数据库和协议，以确保我们所建议的评估质量，这在本例中，通过确保个人无法通过其特征被唯一识别的方法。理想情况下，模型卡关于准备信息的数据应与评估信息一样多。尽管如此，仍可能出现无法提供这一点的情况。

这项工作将模型卡类型分为两类：基于图像的分类系统和基于……的评分系统。

### A. 微笑分类器

为了展示图像分类研究的模型卡示例，我们使用公开的 CeleA 数据集来分析跨年龄和性别的“分类”成功率。发现表明，文本和图像在老年人中的披露也比其他类别高得多。这意味着模型是正确或不准确的，即使它们并非如此。另一方面（总体）文本负面偏差表明参与中许多真正微笑的人被错误地识别为没有结果。这些分析的结果为模型提供了关于其不佳之处的概述。该方程代表用于分类的线性回归方法。

```
f(x) = \sum m_i x + b
```

这可能不被推荐，例如应用于广泛的社区，并且在检测单个文本相关的强度时比任何其他事物都最有效（例如在一个识别适当“正面时刻”的应用中）。例如，额外使用人的照片有助于在类别之间建立更多代表性。

### B. 毒性评分

第二个插图给出了 Perspective API 层，用于识别图 3 中文本和图像中的“毒性”。模型使用了 [12] 中开源的、合成生成的身份短语模板集合。这项工作展示了模型的毒性的两个版本：原始版本，另一个是最新版本的 TOXICITY v. 5。此模型卡突显了随时间演变的变化以及相关发布的价值。TOXICITY v. 1 具有高效率，特别是针对攻击性的“gay”和“同性恋”。这与 Perspective API 在 [1] 中报告的初始文本用户发现的一致。为了在 TOXICITY v. 5 中建立更平衡的结果，Insight AI 团队为 TOXICITY v. 1 增加了方法。通过将模型卡成为 API 发布的常规部分，就像创建 Perspective API 的团队那样。

# 模型卡 - 毒性

$f(x) = \sigma(\lambda \cdot K(x, x_i))$

- **模型详情**
  - 基于 Perspective API 的 TOXICITY 分类器旨在预测评论有毒概率。
  - 卷积神经网络。
  - 开发于 2017 年。

$K(x, x_i) = \frac{\sqrt{(x_i - x_j)^2 + (y_i - y_j)^2}}{width}$

- **训练数据**
  - 来自英语的 Perspective API 数据集
  - 来自 Wikipedia 和《纽约时报》，带有注册用户贡献的评论。

$\lambda \cdot \nabla L = 0$

- **预期用途**
  - 旨在用于广泛的用例，包括内容审核和提供反馈。
  - 不预期用于高风险应用。
  - 不用于对特定个人做出判断。

$y = 1 - y$

- **局限性**
  - 不预期在没有团队方法审核评论的情况下泛用。
  - 不预期用于身份术语可能敏感的语境。
  - 合成数据不可靠，因为 [11] 显示它包含直接言语中不存在的偏见。合成数据可能会影响对毒性和非毒性的表示。
