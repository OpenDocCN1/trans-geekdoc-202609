# 11 关系映射

## 摘要

本章讨论如何指定关系数据库模式，然后详细说明将对象角色建模概念模式映射到关系数据库模式的过程。特别关注避免冗余、映射 1:1 关联、映射外部唯一性约束、映射对象化以及映射子类型。

### 关键词

关系数据库模式；ORM；将 ORM 模式映射到关系模式；约束映射；子类型映射

## 章节大纲

*   11.1 **实现概念模式**
*   11.2 **关系模式**
*   11.3 **关系映射过程**
*   11.4 **高级映射方面**
*   11.5 **小结**

## 11.1 实现概念模式

大多数数据库建模工具允许您使用一种或多种高层表示法（例如 ER、IDEF1X、ORM 或 UML）以及逻辑层表示法（例如关系模型）来录入数据模型。通常，高层（概念或半概念）模式必须映射到逻辑模式，然后再映射到物理模式，以便对数据库进行填充和查询。假设您首先在概念层进行建模，实现数据模型的主要步骤如下。

*   设计概念模式
*   根据需要使用映射选择标注概念模式
*   将设计映射到逻辑模式（例如关系或对象-关系）
*   根据需要微调逻辑模式（例如重命名或重排某些列）
*   生成物理模式（例如在 Microsoft SQL Server 或 IBM DB2 中）
*   创建外部模式（例如窗体、报表）
*   根据需要实施安全级别
*   填充数据库
*   发出查询和更新
*   根据需要更新模式

前几章讨论了如何设计概念模式。本章重点介绍将概念模型映射到逻辑模型。由于关系数据库系统被广泛使用，因此关系模型被用作逻辑模式。[第 1 章](#Ch001_1-25_B9780443237904000062.xhtml) 和 [第 2 章](#Ch002_27-57_B9780443237904000128.xhtml) 介绍了关于关系数据库的基本概念。[第 11.2 节](#Ch011_481-537_B9780443237904000141.xhtml#s0015) 总结了这些要点并简要加以扩展。[第 11.3 节](#Ch011_481-537_B9780443237904000141.xhtml#s0025) 讨论了将 ORM 模式映射到关系模式的基本过程。这可以很容易地调整以涵盖从其他表示法（如 ER 或 UML）的映射。正如 [第 8 章](#Ch008_309-346_B9780443237904000177.xhtml) 所讨论的，从 IDEF1X 到关系模型的映射是微不足道的。

[第 11.4 节](#Ch011_481-537_B9780443237904000141.xhtml#s0055) 讨论了关系映射的高级方面，包括使用概念标注来覆盖默认映射选择（例如，控制子类型如何映射）。自动映射完成后，可能需要对表名和列名进行一些微调以满足命名标准，并可能需要对列重新排序以提高性能。

一旦确定了逻辑模式（如果不是在此之前），就会选择目标数据库管理系统 (DBMS)。然后为该特定平台生成物理模式。调整物理模型以提高性能的某些方面将在后面的 [第 14 章](#Ch014_681-771_B9780443237904000189.xhtml) 中介绍（例如索引选择和反规范化）。

更新和查询倾向于在逻辑查询语言（例如 SQL 或 QBE）中进行，或通过定义在逻辑模式之上的外部窗体和报表界面进行。外部模式设计的某些方面将在后面的章节中介绍。对于多用户应用程序，不同用户组对表、窗体和报表的访问权限应由数据库管理员强制执行。[第 12 章](#Ch012_539-646_B9780443237904000268_1.xhtml) 和 [第 13 章](#Ch013_647-679_B9780443237904000049.xhtml) 指出了如何在 SQL 中声明表更新、查询和访问权限。

所有主要的关系 DBMS 要么直接支持 SQL，要么提供与 SQL 互译的工具。一些更高层的查询语言允许用户直接用维度（用于数据仓库）甚至概念模式构造来构建查询。其中一些将在后面的章节中讨论。

下一节将使用通用表示法总结关系数据库模式中的基本构造。随后的两节将讨论概念模式到关系模式的基本和高级映射。最后一节提供本章小结。

## 11.2 关系模式
