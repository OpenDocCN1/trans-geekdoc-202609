# 前言

Gordon C. Everest，博士，美国明尼苏达大学卡尔森管理学院 MIS 与“数据”建模荣誉退休教授。

我很高兴并深感荣幸能再次撰写前言，这次是为本书的第三版。这给了我另一个机会，来说服数据建模领域的人们：有一种更好的方法。我深信，对象角色建模（ORM）是进行数据建模的更好方式。我的目标是充分激发您的兴趣，使您认真学习 ORM。本书是目前可用的最佳资源。

希腊哲学家苏格拉底建议“认识你自己”，以过上有价值的生活。同样，我们可以说“认识你的世界”，即你生活、运作和做决策的现实。因为任何一个人都不可能了解关于其世界的一切，所以我们需要那个世界的一种*表征*，一种能捕捉该世界中事物、关系、活动/过程和规则信息的*模型*。这种表征由两部分组成：结构和格式的定义，称为*模式*，以及与其定义一致的实际存储数据。信息“数据库”的集合成为该世界的重要*替身*。

我们基于构建的替身数据库，在我们的世界中并关于我们的世界做出决策。这是一项令人敬畏的责任，因此要求我们的数据存储具有高度的完整性、质量和可用性。这需要一种能够捕捉丰富语义集的数据建模方案，而 ORM 是当今所有方案中最好的。

“数据建模”一词的使用往往具有误导性。它暗示我们在建模数据，而实际上我们是在建模某个用户关注领域中的事物和关系（关系中的对象和角色）——即*在数据中建模*，使用数据构造，一旦模型填充了数据，最终就会成为一个“数据”模型。

数据建模是信息系统开发的基础——如果数据库设计不“正确”，那么构建的系统就会像纸牌屋一样，在未来不可避免的增强、集成和质量改进压力下崩溃。因此，我们需要一种方案来指导我们的数据建模工作，以产生清晰、准确地代表用户论述领域、并促进人际沟通、共同理解和质量控制验证的数据模型。生活在并了解用户领域的人员必须直接参与建模过程，由理解设计方法论的数据建模专家提供支持。

对于任何认真对待数据建模的人来说，本书都是必读之作，但有个提醒：你必须投入足够的时间和精力才能真正理解 ORM。幸运的是，我有一整个学期的学生作为固定受众——时间足够长，让他们学习和实践 ORM，并确信这是一种更好的方法。有了 ORM，你可以将数据建模技能提升到一个全新的水平。

本书还考察了基于记录的建模方案：UML、基于 Ted Codd 关系模型的 SQL，以及 Peter Chen 的实体关系（ER）图及其众多变体——Oracle 使用的 Barker 表示法、Finkelstein 的信息工程（IE）和 IDEF1X（如 ERwin 中所用），并新增了关于 XML、JSON 和 NoSQL 中数据结构表示的内容。从 ORM 视角审视这些熟悉的建模方法，能提供对其底层本质更丰富的理解。

**基于记录的建模方案**使用*三种*构造：实体、属性和关系。它们最多只能直接表示二元、一对多关系。但将属性聚类到实体记录中，才是我们数据建模中许多问题的根源。规范化是检验我们是否聚类过度的测试，而记录分解是纠正违反范式的补救措施。

**规范化**是数据建模的阿喀琉斯之踵。能完全避免规范化该多好？这个建议本身就足以引起数据建模学习者和从业者的兴趣。好吧，使用 ORM 你就可以做到。问题源于当我们将东西（属性）扔进实体记录或表时，缺乏对关系清晰完整的定义，导致记录内部结构被隐式地定义或假设。ORM 强迫你单独考虑并显式定义你领域中所有相关对象域之间的关系和约束。

**ORM** 仅基于*两种*构造：对象和关系（分别对应句子中作为主语或宾语的名词概念，以及作为谓语的动词概念）。实体和属性（在关系建模方案中）都基于 ORM 中的对象（不要与面向对象技术中的对象混淆）和角色。对象在与其他对象的关系中扮演角色。因此，对象因在与其他对象的关系中扮演的角色，而隐式地拥有属性（描述符或特性）。

在基于记录的建模中，有两种关系：记录间关系（显式定义并使用外键表示），以及记录内属性之间的关系（未显式定义任何关系的特征，这也是我们需要强制执行规范化规则的原因）。在 ORM 中，所有关系都用单一构造以相同方式表示。当 ORM 模型是对被建模世界的有效表征时，函数依赖和多值依赖被显式定义，因此“记录”（在关系表中）的生成可以自动化，并能保证结果符合范式（达到 5NF）。这对数据建模者来说是个好消息。

ORM 并不取代 ER 图或关系数据库设计；相反，它是一个前置阶段。它能赋能、启发并指导我们对 ER/关系数据模型的开发和理解。我们构建记录更多是为了系统效率，而非人类的便利或理解。过早引入记录概念（一组属性域加上一个标识符来代表实体）妨碍了良好的数据建模。ORM 不涉及记录、表或属性。因此，我们不会陷入“表思维”（参见 <https://tdan.com/recognizing-and-treating-tableitis/26060>）的泥沼。使用 ORM，不需要显式的规范化过程。

第三版更加聚焦于数据在信息系统中的核心地位，以及语义的重要性。从用户（集体）知道的比我们在数据模型中所能捕捉的更多这一认识出发，我们必须使用一种能捕捉尽可能广泛语义范围、并以图形化方式表达这种含义的数据建模方案。语义至上，ORM 在图形化描绘语义方面远远超越了任何基于记录的建模方案。
