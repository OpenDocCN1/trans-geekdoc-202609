## 5.4 案例研究：一家激光唱片零售商

以下小型案例研究旨在巩固 CSDP 步骤 1-5 的主要思想。为了获得最大收益，你应该尝试自己解决该问题，然后再查看解决方案。该业务领域涉及一家激光唱片（CD）零售商，其使用信息系统来协助账户和库存控制，并为寻求特定音乐作品和艺术家信息的客户提供专门服务。

[图 5.32](#Ch005_159-209_B9780443237904000098.xhtml#f0165) 说明了激光唱片所需的音乐信息类型（部分数据为虚构）。每张唱片包含若干个单独的音乐项目，称为“曲目”。虽然激光唱片通常有约 20 个曲目，但此示例中仅列出了少数曲目。

![图 5.32 关于四张激光唱片的音乐详情。](images/B9780443237904000098/f05-32-9780443237904.jpg)

[图 5.32](#Ch005_159-209_B9780443237904000098.xhtml#B-f0165) 关于四张激光唱片的音乐详情。

在继续阅读之前，尝试将 [图 5.32](#Ch005_159-209_B9780443237904000098.xhtml#f0165) 中的信息口头化为基本事实。特别注意所涉及的参照方案。

每张激光唱片以 CD 编号作为其首选标识符。虽然此处未显示，但不同唱片可能具有相同的名称。此处，“CD”用于通用意义上，类似于目录库存项。零售商库存中可能有许多张 CD `654321-2`，但就我们的目的而言，这些都被视为同一张 CD。在某些应用中（如汽车销售），你确实需要区分同一型号的不同副本，但对于我们的应用，这不是要求。

艺术家是一个人或一群人。对于给定的 CD，当且仅当该唱片上的大多数曲目都是由该艺术家演奏时，才列出主要艺术家（此约束由数据录入员强制执行，而非系统）。假设每个艺术家都有一个标识名称，我们使用事实类型 `CompactDisc(CDNr) has main- Artist(.Name)`；否则我们必须用 `ArtistName` 替换 `Artist`，即 `CompactDisc(CDNr) has main- ArtistName()`。

必须记录发行该唱片的唱片公司。

该应用程序一个具有挑战性的方面是理解“曲目”的含义并确定其标识方案。为了澄清术语，你通常需要咨询领域专家。“曲目”一词通常有两种含义：激光唱片上的 `物理曲目` 和录制在该曲目上的音乐作品或 `作品`。

在给定 CD 的上下文中，曲目由其曲目编号或在唱片上的顺序位置来标识。但该领域中有许多 CD，因此我们需要 CD 编号和曲目编号两者来标识一个曲目。使用“曲目”的物理意义，第一张 CD 报表中涉及“Maya’s Dance”的事实可以这样口头化：

|  |
| --- |
| `CD 编号为 ‘654,321–2’ 的激光唱片上的、曲目编号为 1 的曲目` |
| `存储一个标题为 ‘Maya’s Dance’ 的作品。` |

这使用了复合参照方案：`Track(is on CompactDisc, has TrackNr)`。请注意，事实谓词说的是“*一个*该标题的作品”，而不是“*该*作品”。不同的音乐作品可能具有相同的标题。虽然物理曲目仅出现在一张 CD 上，但同一作品可能出现在许多唱片上。例如，CD `654321-2` 的曲目 5 和 CD `925838-2` 的曲目 2 具有相同的标题，且很可能是同一作品。也有两个标题为“Sultans of Swing”的曲目，但它们的时长不同，因此不是同一作品。在极少数情况下，同一张 CD 上可能出现两个标题相同的曲目（此处未显示）。

之前的口头化未将 `Work` 作为实体类型包含在内。我们应该包含它吗？我们需要知道一张唱片上的作品是否与另一张唱片上的作品完全相同吗？只有领域专家能告诉我们他/她是否想知道这一点。对于我们的解决方案，假设该问题的答案为“否”。

然而，如果答案是“是”，我们将需要 `Work` 的 1:1 标识方案。`Work` 的自然参照方案很难找到（即使标题、艺术家和时长的组合可能也不够）。我们可能会使用人工标识符（如 `WorkNr`），但这可能难以强制执行，因为人类负责强制执行首选参照方案中的约束。

曲目的时长是指播放所需的时间。每个曲目恰好有一个时长，以秒为单位。大多数曲目有一个或多个歌手。某些曲目可能没有歌手（这些是器乐曲目而非声乐曲目）。
