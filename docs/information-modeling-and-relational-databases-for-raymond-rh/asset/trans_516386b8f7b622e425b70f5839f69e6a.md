

## 6.3 值约束与独立类型

[图 6.4](#Ch006_211-271_B9780443237904000025.xhtml#B-f0025) 三种集合形成操作的 Venn 图。

与 Euler 图不同，Venn 图椭圆总是重叠。与 HED 类似，Venn 图采用假设视角。作为这些操作的示例，如果 `A = {1, 2}` 且 `B = {2, 4}`，则 `A ∪ B = {1, 2, 4}`，`A ∩ B = {2}`，`A − B = {1}`，且 `B − A = {4}`。

Venn 图有时用于讨论两个集合之间的比较。例如，[图 6.5](#Ch006_211-271_B9780443237904000025.xhtml#f0030)(a) 使用线填充和“*”分别表示空区域和非空区域，指示 `A ⊂ B`。然而，一旦集合数量超过三个，Venn 图就会变得极其难以驾驭——请考虑 [图 6.5](#Ch006_211-271_B9780443237904000025.xhtml#f0030)(b) 中四个集合的 Venn 图。Euler 图有类似的可扩展性问题。[第 6.5 节](#Ch006_211-271_B9780443237904000025.xhtml#s0040) 引入了一种用于绘制子类型连接的有向图表示法，它能够关联许多兼容的对象类型，而不会产生 Euler 图和 Venn 图在这类情况下的线条交叉混乱。

![图 6.5 (a) A 是 B 的真子集，以及 (b) 四个集合的 Venn 图。](images/B9780443237904000025/f06-05-9780443237904.jpg)

[图 6.5](#Ch006_211-271_B9780443237904000025.xhtml#B-f0030) (a) A 是 B 的真子集，以及 (b) 四个集合的 Venn 图。

**值约束** 指示值类型或角色中允许的值，有时称为“域约束”。只有当值列表至少相当 *稳定* 时，才应声明值约束；否则，随着值列表的变化，我们将需要不断更改约束，从而更改模式。

值类型可以通过将其外延（可能值的集合）声明为一个或多个用大括号（花括号）括起来的枚举或范围来定义。在模式图上，*对象类型值约束* 通过在值类型本身或由该值类型引用的实体类型旁边显示外延来声明。

[图 6.6](#Ch006_211-271_B9780443237904000025.xhtml#f0035) 显示了几个示例。如果我们列出或枚举所有可能的值，这就是一个 *枚举*，如 [图 6.6](#Ch006_211-271_B9780443237904000025.xhtml#f0035)(a) 所示。如果这些值可以从第一个到最后一个按连续列表（无间隙）排序，我们只需在首尾值之间用“..”列出即可，因为我们知道如何填充中间值（见 [图 6.6](#Ch006_211-271_B9780443237904000025.xhtml#f0035)(b) 中的前两个示例）。这称为 *范围*。

![图 6.6 对象值约束列出值类型的可能值。](images/B9780443237904000025/f06-06-9780443237904.jpg)

[图 6.6](#Ch006_211-271_B9780443237904000025.xhtml#B-f0035) 对象值约束列出值类型的可能值。

如果范围在一端是 *无界* 的，则该端不出现值。例如，如果我们以整年数来度量 Age，则值约束为 `{0..}`。默认情况下，范围假定为闭区间，因此包含端点值。例如，`{50..100}` 包括 50 和 100 以及它们之间的数字。*在起始值前插入左括号“(”可排除该值*，*在结束值后追加右括号“)”可排除该值*。如果需要，可使用方括号显式表示包含（默认情况）。例如，“`(0..100`”和“`(0..100]`”均表示大于 0 且小于等于 100 的正数范围。也可以将枚举和/或范围组合成单个约束，如 [图 6.6](#Ch006_211-271_B9780443237904000025.xhtml#f0035)(c) 所示。

如果值约束表达式较短，可在图上完整显示。如果值列表很长，我们可以在对象角色建模（ORM）工具中输入所有值，但选择仅显示部分前导值。尾部的省略号“…”则表示后续值的显示被抑制。例如，对于对象类型 WeekDay，我们可能指定值列表 `{"Sunday", "Monday", "Tuesday", "Wednesday", "Thursday", "Friday", "Saturday"}`，但选择仅显示前两个（见 [图 6.7](#Ch006_211-271_B9780443237904000025.xhtml#f0040)）。虽然列表在图上被压缩了，但需要时仍可完整以文本形式显示（例如，通过访问对象类型的属性表）。

![图 6.7 后续值的显示被抑制。](images/B9780443237904000025/f06-07-9780443237904.jpg)

[图 6.7](#Ch006_211-271_B9780443237904000025.xhtml#B-f0040) 后续值的显示被抑制。

现在考虑 [图 6.8](#Ch006_211-271_B9780443237904000025.xhtml#f0045)，这是之前讨论的奥运会示例的修改版，连同 1988 年在韩国首尔举行的第 24 届夏季奥运会最终结果的样本数据（按国家按字母顺序排序）。对于此应用，仅允许三种奖牌：金、银、铜，分别用代码“G”、“S”和“B”表示。该约束通过在实体类型 MedalKind 旁列出可能值集合 `{"G", "S", "B"}` 来指定。

![图 6.8 为 MedalKind 和 Quantity 角色声明了值约束。](images/B9780443237904000025/f06-08-9780443237904.jpg)

[图 6.8](#Ch006_211-271_B9780443237904000025.xhtml#B-f0045) 为 MedalKind 和 Quantity 角色声明了值约束。

在 1988 年奥运会上，共有 237 个项目，每个项目颁发一枚金、银、铜牌（假设无并列）。同一国家赢得某类奖牌的所有奖牌是可能的（尽管极不可能）。因此，此处 Quantity 所扮演的角色（我们可以将此角色命名为“奖牌种类数量”）的最大可能值为 237，假设我们将其他运动会（可能有更多项目）排除在域之外。

奖牌种类数量的最小可能值是多少？如果我们想记录某国家未赢得某类奖牌，则最低奖牌种类数量为 0。为减小数据库规模，我们可以仅存储实际获奖的事实——我们的样本数据建议采用这种方法。在这种情况下，奖牌种类数量的下限为 1。采取封闭世界假设，某国家赢得 0 枚金牌这一事实，则可从该国赢得一些金牌的断言事实不存在这一情况推导得出。因此，此值约束的值范围为 `{1..237}`。

由于 Quantity 很可能在全局模式中扮演其他角色，`{1..237}` 值约束仅适用于 Quantity 在该事实类型中的角色，而非 Quantity 本身。我们称之为 *角色值约束* 而非对象类型值约束。角色值约束通过虚线连接到其适用的角色上显示，如 [图 6.8](#Ch006_211-271_B9780443237904000025.xhtml#f0045) 中 `{1..237}` 所示。

另一种方法是引入更具体的对象类型（例如 MedalKindQuantity）并将值约束放在其上；然而，这种做法可能导致口语化表达别扭，因此角色值约束非常方便。

作为一个细节，显示在带有参照模式的实体类型旁边的对象值约束，实际上是值类型所扮演的参照角色上的角色值约束。在 NORMA 工具中，您可以通过将 `ExpandRefMode` 切换为 True 来以这种方式显式显示。
