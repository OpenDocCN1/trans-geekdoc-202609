

# OLAP 方法

OLAP 有三种主要方法。每种方法都使用基础数据以及聚合数据（例如，销售数字可能会在不同层级上求和并分组）。

*   **多维 OLAP (MOLAP)** 将基础数据和聚合数据都存储在多维结构中，而不是表中。
*   **关系 OLAP (ROLAP)** 将基础数据和聚合数据都存储在关系表中。
*   **混合 OLAP (HOLAP)** 将基础数据存储在关系表中，将聚合数据存储在多维结构中。

某些 DBMS（如 Microsoft SQL Server）支持所有三种 OLAP。

## 立方体

用于 OLAP 的多维结构通常被称为**立方体**。在几何学中，立方体是一种三维盒状结构。在 OLAP 理论中，立方体可以拥有任意数量的维度。立方体提供了一种直观的方式来可视化和浏览数据，并能快速访问聚合数据。

OLAP 立方体可能比这个例子复杂得多。对于任意一组独立维度，可能存在多个度量（例如，销售单位数和收入）。这些不同的度量通常统称为**度量维度**。此外，每个独立维度通常都有一个**层级**的**级别**。例如，位置维度的顶层可能是区域，第二层由州组成，第三层是城市，第四层是门店。同样，时间维度可以分解为年、季度、月和日。最后，商品维度可以分解为类别和具体商品。

因此，我们的数据集市示例可以用来构建一个具有三个独立层级维度（位置、时间和商品）以及一个用于 UnitsSold 和 Revenue 度量的因变维度的立方体。立方体结构的妙处在于，它能够高效地存储和访问层级中所有级别的度量聚合值。

## 立方体操作

在分析立方体时，你可以选择合并或**上卷**这些聚合值（例如，将城市的销售数字上卷为区域销售数字）。你也可以**下钻**到更细粒度的级别。此外，你可以通过获取其子立方体，以任何你喜欢的方式对立方体进行**切片和切块**。例如，如果你将 [图 18.4](#Ch018_935-1005_B9780443237904000104.xhtml#f0025) 中的商品类别限制为软件，你将得到立方体的前部切片。

由于这些优势，数据集市中的星型模式常被用于创建各种立方体以便于分析。SQL Server 提供了向导来简化立方体创建任务，并支持用于查询立方体的**多维表达式 (MDX)** 语言。

## MDX 查询语言

在 MDX 中，**select** 语句指定一个结果集，该结果集包含从立方体返回的多维数据的一个子集。select 子句指定查询轴（允许 0 到 128 个轴），from 子句确定将查询哪个立方体，可选的 where 子句确定在切片轴上使用哪些成员或元组来限制返回的数据。

作为一个简单的例子，假设 `SalesCube` 基于前面讨论的层级位置、时间和商品维度。以下 MDX 查询将生成一个二维网格，列出 2020 年前三个季度华盛顿州的软件销售单位数和收入。

```
select { [Measures].[UnitsSold], [Measures].[Revenue] } on columns,
       { [Time].[2020].[Q1] : [Time].[2020].[Q3] } on rows
from SalesCube
where ( [Item].[SW], [Location].[N].[WA] )
```

在 MDX 中，大括号用于定界序列，方括号可用于定界标识符或值。点符号用于向下遍历层级。请注意，时间下钻到了季度，位置下钻到了州。冒号 `:` 用于表示范围（类似于英语中的 `..`）。上述查询的结果网格有两列（销售单位数和收入）和三行（2020 年前三个季度）。

不同的 OLAP 工具工作方式不同。SQL:1999 及以后版本包含对立方体和上卷的支持，因此希望未来某些 OLAP 功能能变得更加标准化。全面介绍 MDX 还需要一两章的篇幅，因此此处不再深入。有关 SQL Server 2022 MDX 的详细介绍，请参阅 [MDX Language Reference (MDX) - SQL Server | Microsoft Learn](https://learn.microsoft.com/en-us/sql/mdx/mdx-language-reference-mdx?view=sql-server-ver16)。

MDX 查询可能非常复杂，Microsoft SQL Server 提供了一种称为**英语查询**的高级语言，最终用户可用它来生成 MDX 查询。基于自然语言的查询将在下一节讨论。

# 18.3 概念查询语言

信息系统可以在四个层级中的任意一个进行建模：概念、逻辑、物理和外部。原则上，也可以在任意这些层级对其进行**查询**。然而在实践中，虽然概念建模被广泛使用，但系统在概念层级被查询的情况却相对较少。相反，查询通常是在外部层级使用表单、在逻辑层级使用 SQL 等语言、或在物理层级使用编程语言来构建的。

在外部层级，**表单查询 (QBF)** 允许用户通过在表单字段中输入适当的值或条件，直接在屏幕表单上输入查询。这种基于表单的界面非常适合简单查询，即查询范围可见于单个表单且不涉及复杂操作的场景。然而，它无法用于表达复杂查询。此外，随着外部接口的演进，已保存的 QBF 查询可能会迅速过时。出于这些原因，QBF 对于严肃的工作来说过于受限。
