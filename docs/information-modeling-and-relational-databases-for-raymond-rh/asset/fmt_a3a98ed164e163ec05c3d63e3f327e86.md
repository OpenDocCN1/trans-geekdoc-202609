大多数 SQL 方言现在都支持交叉连接和限定连接（包括外连接）的新语法，但有些尚不支持自然连接的新语法。现在让我们逐一考察这些新的连接符号。

对于*交叉连接*，可以使用**`cross join`**语法代替逗号。这种语法最好保留给无限制连接（完全笛卡尔积）使用。例如，[图 12.41](#Ch012_539-646_B9780443237904000268_1.xhtml#f0210)展示了男性和女性网球运动员的详细信息。该查询列出了混合双打队伍可能的男女搭配。交叉连接在实践中相当罕见。

条件连接更为常见。新语法在**`from`**子句中包含连接运算符，在**`on`**子句中包含连接条件。[图 12.42](#Ch012_539-646_B9780443237904000268_1.xhtml#f0215)展示了一个关系模式、示例数据和一个条件连接查询，用于检索每位女性员工及其部门的名称。为了提高可读性，最好缩进**`on`**子句，如图所示。查询中提到的每个列只出现在其中一个表中，因此无需用表名限定列名。在这种情况下，连接沿[图 12.42](#Ch012_539-646_B9780443237904000268_1.xhtml#f0215)所示的外键引用进行。虽然连接通常涉及外键引用，但这并非必须。我们只需要被连接的列基于同一个域。

![图 12.42 条件连接在 on 子句中指定连接条件。](images/B9780443237904000268/f12-42-9780443237904.jpg)

列表连接匹配两个表中具有相同本地名称的指定列中的值。新语法在**`from`**子句中使用**`join`**关键字，在**`using`**子句中列出相关列。例如，考虑以下模式。这在语义上等同于前一个模式，但某些列名的选择不同。部门代码在两个表中均表示为“deptCode”，本地标识符“name”同时用于部门名称和员工名称。

![](images/B9780443237904000268/u12-07-9780443237904.jpg)

现在，考虑前一个查询：列出每位女性的姓名及其部门名称。如何为这个新模式构建该查询？这两个表有两个公共的本地列名：“deptCode”和“name”。这里，我们只想对部分同名列（仅“deptCode”，而非“name”）执行等值连接。用于连接的公共列名在**`using`**子句中列出，如下所示。连接仅使用一列。为了消除歧义，**`select`**列表中的列名由其表名限定。

```
select Employee.name, Department.name
from  Employee join Department
using (deptCode)
where gender = ‘F’
```

正如您可能意识到的，前两个模式中的列命名选择并不理想。如果不同表中的两列意图表示同一事物，最好在这些表中给这些列相同的名称（只要可能）。虽然这非正式，但它使表之间预期的语义联系更易于察觉，尤其是那些没有外键引用的表。对于讨论中的模式，“deptCode”可统一用于部门代码，员工姓名和部门名称可区分为“empName”和“deptName”，如下所示：

![](images/B9780443237904000268/u12-08-9780443237904.jpg)

使用这个新模式，前面考虑的条件连接查询需要限定连接中使用的列名，因为它们的非限定名称出现在两个表中。这给出：

*   ```
    select empName, deptName
    ```

*   ```
    from   Employee join Department
    ```

*   ```
    on Employee.deptCode = Department.deptCode
    ```

*   ```
    where gender = ‘F’
    ```

对于新模式，列表查询不需要对列名进行任何限定，如下所示。

*   ```
    select empName, deptName
    ```

*   ```
    from    Employee join Department
    ```

*   ```
    using (deptCode)
    ```

*   ```
    where gender = ‘F’
    ```

正如您可能注意到的，前两个查询中的底层连接操作现在是*自然连接*，因为我们在*所有*同名列上进行等值连接（在本例中只有一个这样的列：deptCode）。

正如关系代数中所讨论的，*自然内连接*执行等值连接以匹配所有具有相同本地名称的列，然后移除这些列的额外副本。在 SQL-89 中，自然内连接通过首先形成（**`from`**子句中列出的表的）笛卡尔积，然后在**`where`**子句中指定连接条件，使用**`select`**列表过滤掉不需要的重复列来指定。在 SQL-92（及更高版本）中，自然内连接可以通过在**`from`**子句中的**`join`**前插入**`natural`**或**`natural inner`**来简单声明（限定连接和自然连接默认为内连接）。

新符号有三个主要优势：它更具描述性；**`natural join`**运算符直接支持关系代数的**`natural inner join`**运算符（⨝）；并且通常更简洁。例如，刚才考虑的查询可以更简洁地重新表述为：

*   ```
    select empName, deptName
    ```

*   ```
    from    Employee natural join Department
    ```

*   ```
    where gender = ‘F’
    ```

无需显式声明连接条件 `Employee.deptCode = Department.deptCode`，因为这由**`natural`**的使用以及“deptCode”是**`from`**子句中列出的表的唯一公共列名这一事实隐含。随着查询中自然连接数量的增加，这种新符号的紧凑性变得更加明显。例如，考虑以下关系模式。
