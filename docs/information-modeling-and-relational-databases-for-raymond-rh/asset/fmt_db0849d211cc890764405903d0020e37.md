
The result of `A` ÷ `B` is formed by restricting the result to those `X` entries in `A` whose associated `Y` entries in `A` include *all* the row entries of `B`. The expression `A` ÷ `B` may also be written as `A` **divide-by** `B`. [Fig. 12.26](#Ch012_539-646_B9780443237904000268_1.xhtml#f0135) shows a trivial example, where the attribute domains are denoted by `X1`, `X2`, `Y1`.

![Fig. 12.26 A simple example used to explain relational division.](images/B9780443237904000268/f12-26-9780443237904.jpg)

[Fig. 12.26](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0135) A simple example used to explain relational division.

Although not used very often, the division operation can be useful in listing rows that are associated with at least *all* rows of another table expression (e.g., who can supply all the items on our stock list?).

As a practical example, suppose the table `Speaks` (country, language) stores facts about which countries speak (i.e., use) which languages. A sample population is shown in the large table within [Fig. 12.27](#Ch012_539-646_B9780443237904000268_1.xhtml#f0140). Now consider the query: Which countries speak *all* the languages spoken in Canada? To answer this, we first find all the languages spoken in Canada, using the expression `Speaks` **where** country = ‘Canada’ *\[*language*\]*. This returns the table {English, French}. We then divide the `Speaks` table by this result, as shown, to obtain the final answer {Canada, Dominica}.

### Renaming

Recall [Fig. 12.7](#Ch012_539-646_B9780443237904000268_1.xhtml#f0040), where we defined an alias for a table name. Relational assignment can also be used to provide a new table name, but it cannot be used to *change the attribute names*. For that, we need the ***rename*** operator. A relational algebra expression may include any of the relational operations discussed earlier (union, projection, selection, join, etc.) and is essentially a query that returns a table. In general, *the rename operator applied to a relational expression returns a table with the same rows* (same data population) *but different names for the table or columns*.

The formal syntax for the rename operator uses the Greek letter “***ρ***” (*rho*). If `Rexp` is a relational expression that returns a table with the table scheme `R`(`a`[1], …, `a`[*n*]), the following expression returns a table with the table scheme `S`(`b`[1], …, `b`[*n*]). The expression below it uses our alternative syntax.

*    `ρ``S`(`b`[1], …, `b`[*n*]) `Rexp`
*    **define** `S`(`b`[1], …, `b`[*n*]) **as** `Rexp`

If the attribute list (`b`[1], …, `b`[*n*]) is omitted, the operation simply provides a new table name. In that case, if `Rexp` is simply a table name, it is more natural to use the define alias notation (e.g., **define alias** `Person2` **for** `Person`), as in [Fig. 12.7](#Ch012_539-646_B9780443237904000268_1.xhtml#f0040).

As a simple example, consider the table schemes `Person` (personName, age, genderCode) and `Drives` (personName, carRegNr) where `Drives.personName` is a foreign key to the `Person` table. The following declaration may be used to define a `WomanDriver` table using simply “name” instead of “personName” for the person name attribute.

```
define WomanDriver   ( name, carRegNr ) as
    Employee ⨝ Drives
where age >= 18 and genderCode = ‘F’
[personName, carRegNr]
```

Once defined, the `WomanDriver` table may be used in subsequent queries, just like any other table. This is similar to a *view* in SQL (see later chapter).

### Query Strategies

That completes all the main operators in relational algebra. [Table 12.2](#Ch012_539-646_B9780443237904000268_1.xhtml#t0015) indicates the operator precedence adopted in this book. The comparison operators have top (and equal) priority, so are evaluated first. The logical operators are evaluated next (first **not**, then **and**, then **or**). Then the relational selection and projection operations are evaluated (equal priority). Finally, the other six relational operators (union, intersection, difference, Cartesian product, natural join, and division) are evaluated (equal priority). Operators with equal priority are evaluated left to right. Expressions in parentheses are evaluated first. Some systems adopt a different priority convention for the relational operators.

To help formulate queries in relational algebra, the following *query strategies* are useful:

*   • Phrase the query in natural language, and understand what it means.
*   • Ask which tables hold the information.
*   • If you have table data, answer the query yourself and then retrace your mental steps.
*   • Divide the query up into steps or subproblems.
*   • If the result columns come from different tables, declare joins between the tables.
*   • If you need to relate two rows of the same table, use an alias or rename definition to perform a self-join.
*   • To change any table or column names in a result, use a rename definition.

Our first move is to formulate the query in natural language, ensuring that we understand what the query means. Next, determine what tables hold the information needed to answer our query. The information might be in a single table or be spread over two or more tables. If the columns to be listed come from different tables (or different copies of the same table), then we must normally specify joins between these tables. These joins might be of any kind: inner or outer joins, natural or theta joins, or cross joins (Cartesian products).

Apart from some cases involving ∪, ∩, or -, relational algebra requires joins whenever different tables must be accessed to determine the result, even if the result columns come from the same table. SQL introduced subqueries, which can be used instead of joins when the result columns come from the same table.

Before formulating this in relational algebra, we should ensure that we understand what the natural language query means. In some cases, we may need to clarify the meaning by asking the person who originally posed the query. For example, do we want just the client number for the relevant clients or do we want their name as well? Let’s assume that we want the client name as well.
