
目前，大多数 SQL 方言（包括 SQL Server）不支持自然连接语法。相反，通常使用条件连接语法来处理自然连接。例如，[图 12.43](#Ch012_539-646_B9780443237904000268_1.xhtml#f0220) 中的查询可以重新表述如下：

```
select Employee.empNr, empName, carModel
```

```
from   Employee join Drives
```

```
on Employee.empNr = Drives.empNr
```

```
join Car
```

```
on Drives.carRegNr = Car.carRegNr
```

或者，也可以使用 SQL-89 语法，如下所示：

```
select Employee.empNr, empName, carModel
```

```
from      Employee, Drives, Car
```

```
where Employee.empNr = Drives.empNr
```

```
and Drives.carRegNr = Car.carRegNr
```

当使用自然连接运算符时，`select` 列表中的任何连接列必须用其局部（非限定）名称表示。如果使用其他语法（例如条件连接或 SQL-89 语法）指定自然连接，则连接列必须限定。

虽然实践中大多数连接都是自然内连接，但有时应避免使用自然连接。自然连接操作不能用于连接名称不同的列。例如，它无法在 [图 12.42](#Ch012_539-646_B9780443237904000268_1.xhtml#f0215) 的查询中连接 `dept.` 和 `deptCode`。此外，如果 `from` 子句中的不同表包含同名但不应等同的列，则不得使用自然连接操作。例如，考虑我们列表连接示例的表模式：*Department* (deptCode, name)；*Employee* (empNr, name, deptCode, gender)。

*Department* 和 *Employee* 之间的自然连接不仅会等同 `deptCode`，还会等同 `name`。结果中的任何行都会将员工姓名与部门名称等同，这毫无意义。

有时，我们确实希望在多个列上自然连接两个表。例如，回顾关系代数部分讨论的以下模式。

![](images/B9780443237904000268/u12-10-9780443237904.jpg)

要列出所有账户的余额和客户详细信息，需要在 `account`（复合标识符）上进行复合连接，在 `client` 上进行简单连接。这可以用自然连接语法指定为：

```
select * from Account natural join AcUser natural join Client
```

或者作为条件连接：

```
select  Account.branchNr, Account.accountNr, balance,
```

```
          Client.clientNr, clientName
```

```
from  Account join AcUser
```

```
on Account.branchNr = AcUser.branchNr
```

```
and Account.accountNr = AcUser.accountNr
```

```
join Client
```

```
on AcUser.clientNr = Client.clientNr
```

对于条件连接、列列表连接和自然连接，除非显式指定外连接（见后文），否则 `join` 默认指内连接。在这些情况下，可以显式声明 `inner`（例如 `inner join` 或 `natural inner join`）。如果声明了 `natural`，则不得使用 `on` 子句或 `using` 子句。如果连接表达式中包含三个或更多表，连接通常按从左到右的顺序求值。也可以通过插入括号来控制连接顺序。因为自然内连接具有结合性，所以其顺序不影响实际结果。

作为一个更复杂的例子，考虑 [图 12.44](#Ch012_539-646_B9780443237904000268_1.xhtml#f0225) 中的关系模式。在第一个表中，`mgrEmpNr` 表示部门经理的员工编号（如果有经理）。成对子集约束表示员工只有在该部门工作时才能管理该部门。该约束上的 (2,1) 项列表标记用于指示在与 `(empNr, deptCode)` 比较之前，将值对重新排序为 `(mgrEmpNr, deptCode)`。

现在考虑以下查询：对于每个有经理的部门，列出其代码和名称，以及其经理的员工编号和姓名。

我们必须在 *Department* 和 *Employee* 表之间匹配员工编号。部门代码也必须匹配，但我们需要指定这一点吗？不需要，因为如果部门表中引用的经理与 *Employee* 表中的员工相同，则部门代码的匹配由模式中的约束隐含（为什么？）。该查询可以用以下条件连接来表述。自然连接不起作用，因为连接列名称不同。

```
select Department.deptCode, deptName, mgrEmpNr, empName
```

```
from   Department join Employee
```

```
on mgrEmpNr = empNr
```

到目前为止，我们已经讨论了 [表 12.8](#Ch012_539-646_B9780443237904000268_1.xhtml#t0045) 中列出的八种连接中的四种。还有三种外连接，以及一种联合连接。联合连接很少使用，不再进一步讨论。*外连接*可以是*左*、*右*或*全*外连接。左外连接和右外连接在商业应用中经常遇到。给定两个表 *A* 和 *B*，它们的左/右/全外连接是通过先计算它们的内连接，然后添加左/右/两个表中在内连接中没有匹配的行，并用 null 填充结果表中的额外列来形成的。

[图 12.45](#Ch012_539-646_B9780443237904000268_1.xhtml#f0230) 提供了一个自然左外连接的简单示例。该查询列出所有员工（包括不开车的员工）的员工编号、姓名和汽车登记号（如果有）。所示的两种表述在 SQL-92（及更高版本）中都是合法的。第一种使用自然连接语法，但大多数 SQL 方言尚不支持。第二种表述使用条件外连接语法，通常受支持。

![图 12.45 自然左外连接的两种等价表述。](images/B9780443237904000268/f12-45-9780443237904.jpg)

[图 12.45](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0230) 自然左外连接的两种等价表述。

自然内连接产生两个驾驶员（员工 001 和 003）的三行结果。员工 002 和 004 在 *Drives* 表中没有匹配项。左外连接添加它们的行，并用 `carRegNr` 的 null 值填充。我们将 null 值显示为“？”。某些系统将其显示为空白或“NULL”。许多系统允许您选择如何显示 null 值。

虽然条件连接语法要求连接列使用限定列名，但当显示结果表时，某些系统（如 SQL Server）足够智能，可以从列标题中省略表限定（如 [图 12.45](#Ch012_539-646_B9780443237904000268_1.xhtml#f0230) 所示）。某些系统支持在外连接成为 SQL-92 标准一部分之前引入的替代外连接语法。这种语法通常具有不同的语义，除非不支持标准语法，否则绝不应使用。

SQL-92 及更高版本是*正交*的。任何合法值的地方，返回该值的任何表达式也合法。这使语言更易于使用，并增加了单个查询的表达能力。然而，许多商业系统并非完全正交，且经常对外连接查询施加限制（例如，最多允许一个外连接，或外连接后不允许其他连接）。对于此类系统，有时有必要将单个标准查询表述为一系列使用中间表存储中间结果的查询。
