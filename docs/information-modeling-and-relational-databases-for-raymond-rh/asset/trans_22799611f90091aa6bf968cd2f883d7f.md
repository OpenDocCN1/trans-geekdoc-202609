

# SQL 集合运算与子查询

## 不相交操作数的 Union 运算

当 `union` 运算符的操作数是不相交的（即互斥的）时，即使只涉及一个基表，`union` 运算符有时也会被用来为输出添加描述。作为一个例子，请考虑 [图 12.51](#Ch012_539-646_B9780443237904000268_1.xhtml#f0260) 中的 Expert 和 Novice 表。假设我们想要列出柔道运动员的姓名，以及一个标签来指示谁是专家、谁是新手。为了获取姓名，我们可以将一个针对柔道专家的 `select` 查询与另一个针对柔道新手的 `select` 查询进行 union 运算。然后，我们可以通过在相关的 `select` 列表中包含字符串“expert judoka”和“novice judoka”来标识专家和新手柔道运动员。

![图 12.51 常量可与 union 结合使用以指示行的来源。](images/B9780443237904000268/f12-51-9780443237904.jpg)

[图 12.51](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0260) 常量可与 union 结合使用以指示行的来源。

我们可以通过引入“judo level”作为标签的别名来改进这一点。这为标签提供了一个有意义的列标题，并允许我们将标签缩短为仅“expert”和“novice”，如图所示。请注意“judo level”中使用双引号以允许嵌入空格。

虽然在操作数不相交时，在 union 中添加描述性字符串的技术很方便，但如果它们重叠则用处不大。当字符串值被添加到行中时（因为这些值不同），原本重叠的行会变得不相交。因此，这些行会在 union 结果中出现多次。

## Intersect 和 Except 运算符

在 SQL-92 中（但不在 SQL-89 中），提供了用于*集合交集*的 `intersect` 运算符和用于处理*集合差*的 `except` 运算符。它们的工作方式类似于 `union` 运算符。它们仅允许在返回 union 兼容表的 `select` 查询之间使用。除非指定了 `all` 选项，否则会从结果中移除重复项。

请回顾 [图 12.50](#Ch012_539-646_B9780443237904000268_1.xhtml#f0255) 中的表 `Person`(shortName, nationality) 和 `Drives`(driver, carModel)。现在考虑查询：哪些美国人开福特车？这意味着，谁是美国人**并且**开福特车？因为国籍事实和 carModel 事实在单独的表中，这个逻辑“**与**”运算符自然可以通过表交集运算符来实现，如下所示，产生结果 {“Lance”}。

```
select shortName from Person
where nationality = ‘American’
intersect
select driver from Drives
where carModel = ‘Ford’
```

类似地，查询“哪些美国人不开福特车？”可以表述为集合差，如下所示，产生结果 {“JimO”, “Walter”}。

```
select shortName from Person
where nationality = ‘American’
except
select driver from Drives
where carModel = ‘Ford’
```

与 union 和 intersection 不同，差运算符**不**满足交换律。例如，反转前一个查询中操作数的顺序会产生 {“Colleen”}，因为反转后的查询含义不同：“哪些福特车车主不是美国人？”

如果在 `intersect` 或 `except` 后使用 `all` 选项，它分别返回包交集或包差。一般来说，如果一行在一个表中出现 *m* 次，在另一个表中出现 *n* 次，那么它在包交集中出现 min(*m, n*) 次，在包差中出现 max(*m* - *n*, 0) 次。

虽然所有主流商业 SQL 方言都支持 `union` 运算符，但有几种尚不支持 `intersect` 和 `except` 运算符。正如我们现在要讨论的，这两个运算符可以使用子查询来模拟，因此它们的缺失并不意味着功能的丧失。

## SQL 子查询

SQL *子查询* 类似于关系代数中嵌套公式内的组件查询。虽然 SQL 子查询本身就是查询，但它们必须用括号括起来（这与进行 union 运算的 `select` 查询不同），并且对其使用有一些限制。理想情况下，一种语言应该是正交的——在任何合法使用值或结果的地方，返回该值或结果的表达式也应该是合法的。然而在 SQL-89 中，子查询仅允许在其结果合法的少数几个地方使用。虽然 SQL-92 移除了这些限制，但鲜有商业 SQL 完全实现正交性。

子查询是嵌入在另一个查询中的带括号的 `select` 查询。设 Θ 表示比较运算符之一 (=, <>, <, >, <=, >=)。在 SQL-89 中，子查询仅在以下三种上下文中合法：

```
expression [not] in (subquery)                                            -- 成员资格子查询
```

```
expression Θ [all | some | any] (subquery)         -- [量化] 比较子查询
```

```
exists (subquery)                                                                                -- 存在性子查询
```

### 成员资格子查询

*成员资格子查询* 紧跟在 `in` 运算符之后。在 SQL-89 中，成员资格子查询必须是*单例查询*（即必须返回单个列）。这与 `in` 运算符配合值包（一列只是垂直显示的值包）的用法一致。在 SQL-92 中，`in` 运算符前面可以是行值表达式，在这种情况下子查询可以返回多列表。

### 比较子查询

*比较子查询* 紧跟在比较器（例如 =）之后。如果比较器由量词 `all`、`some` 或 `any` 之一修饰，这就是*量化比较*。在 SQL-89 中，比较子查询必须返回单个列；如果比较未量化，子查询必须返回单个值。这与比较运算符的正常用法一致。在 SQL-92 中，比较器前面可以是行值表达式，在这种情况下子查询可以返回多列表，或者如果未量化，则返回行值。*存在性子查询* 出现在 `exists` 量词之后，可以返回任何表。

### SQL-92 扩展

在 SQL-92 中，子查询可以用在其他地方（例如 `from` 子句和 `check` 子句），只要它们的结果表在那里讲得通（正交性）。`From` 子句子查询要求为派生表指定别名，即使不需要别名也是如此。语法是：

```
… from (subquery) [as] alias
```

SQL Server 支持 `from` 子句中的子查询，但不支持 `check` 子句中的子查询。一些 SQL 方言将其子查询支持限制在 SQL-89 的三种情况中，每种情况都将子查询嵌入在外部查询的 where 子句中，如下所示：

```
select …                    -- 外部查询
from …
where …
           (select …          -- 子查询
from … )
```

如果子查询是自包含的（即它不引用外部查询），则称之为*非相关子查询*。在这种情况下，它会首先被求值，并被其结果（例如值包）替换，然后再处理外部查询。相反，*相关子查询* 引用其外部查询。本节仅考虑简单的、非相关的成员资格和比较子查询。存在性子查询和相关子查询将在后面介绍。

### 成员资格子查询求值

现在让我们考虑*成员资格子查询*。条件 *expression* `in` (*subquery*) 当且仅当表达式的值包含在子查询结果中时返回 True。如果子查询返回空集，该条件求值为 unknown。外部查询结果仅包含条件求值为 True 的行。
