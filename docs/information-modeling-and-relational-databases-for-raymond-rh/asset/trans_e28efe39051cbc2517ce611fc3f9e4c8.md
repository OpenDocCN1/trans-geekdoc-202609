

# 概念模式与关系映射

概念模式通常通过将其映射到逻辑模式（例如关系模式）、对其进行细化，然后生成内部和外部模式（包括访问权限）来实现。随后可对数据库和模式执行更新和查询。

*关系（数据库）模式*是一组表定义（存储的基本表或派生视图）、约束和派生规则。*表模式*是一组命名的*属性*（列），其取值来自*域*。每个列，或由最小唯一性约束跨越的列集，都是一个*候选键*。键以下划线标识。每个表行由其*主键*标识（若存在其他键则双下划线）。*实体完整性*规则要求主键不能有空值。可选列允许空值，并用方括号括起。例如：`Employee( empNr, empName, address, gender, [phone] )`。

强制角色映射到非可选列，且子集约束从包含该对象类型事实的任何其他表运行而来。*参照完整性约束*是从外键到某个主键的子集约束。表之间的子集约束显示为虚线箭头。也使用其他约束符号。

关系映射过程（`Rmap`）使用两个基本思想将每个事实类型分组到单个表中：具有复合唯一性约束的每个事实类型（例如 *m:n* 关联或三元关联）映射到单独的表；附加到同一对象类型上的功能角色的事实类型分组到同一个表中，以该对象类型的标识符为键。

*基本 Rmap 过程*可总结如下。将子类型吸收到其顶层超类型中。在脑海中擦除所有显式首选标识方案，将复合标识的对象类型视为“黑盒”。将每个具有复合 UC 的事实类型映射到单独的表。将附加到同一对象类型上的功能事实角色的事实类型分组到同一个表中，以该对象类型的标识符为键。将 1:1 情况映射到单个表，通常倾向于减少空值。将每个没有功能事实角色的独立对象类型映射到单独的表。将每个“黑盒列”解包为其组成属性。映射所有其他约束和派生规则。功能角色上的子类型约束映射到限定可选列，而非功能角色上的子类型约束映射到限定子集约束。

如果某对象类型的总体实例包含在一个表中，这称为该对象类型的*总表*。更多详情请参见*总表过程*。

*Rmap 步骤 0 过程*中的高级映射方面可总结如下。转换相反的一元事实类型，然后根据其开放/封闭世界语义映射一元事实类型。在脑海中擦除所有引用（首选标识）谓词。将复合标识的对象类型视为“黑盒”。指示任何吸收覆盖（例如分离或分区）以用于子类型。识别任何必须存储的派生事实类型。指示对称 1:1 情况的映射选择。考虑通过使用人工标识符或连接标识符或强制默认值来替换任何析取引用方案。在需要时，指示任何没有跨越唯一性约束的对象化关联的映射选择。

## 12.1 SQL：关系代数

前几章讨论了如何设计概念模式并将其映射到关系模式。本章讨论如何在关系数据库管理系统（`DBMS`）中实现关系模式，然后用数据填充其表。为了从生成的数据库中检索信息，我们需要发出查询。在实践中，最流行的查询语言是 `SQL`（通俗但不准确地称为“结构化查询语言”）和 `QBE`（示例查询）。这两种语言至少部分基于一种称为*关系代数*的形式化查询语言，本节将讨论该语言。首先学习这种代数可以阐明基本查询操作，而不会被商业查询语言的特定语法所干扰。

掌握了关系代数后，我们可以定义“关系数据库系统”一词的真正含义。随后几节将深入介绍 SQL，从基础开始，逐步深入到中级和高级概念。虽然我们的重点是 SQL 标准，但也会包含一些关于 SQL 商业方言的额外细节。我们从关系代数开始。

在数据的关系模型中，所有事实都存储在*表*（或*关系*）中。通过应用关系代数运算，可以从现有表形成新表。这些运算产生的表可通过关系赋值进行命名和存储。Codd 定义的原始关系代数包含八个*关系运算符*：四个基于传统集合运算（*并*、*交*、*差*和*笛卡尔积*），四个特殊运算（*选择*、*投影*、*连接*和*除*）。关系代数现在包含一个*重命名*运算符，用于为查询结果的表模式定义别名。这九个关系运算符中的每一个都是作用于表的成表运算符。例如，两个表的并集本身就是一个表。
