

## OLTP 系统、数据仓库和数据集市

**OLTP** 系统用于涉及频繁更新和查询的典型数据库应用。**数据仓库**仅按计划从在线源更新，并以只读模式供管理层进行企业级趋势分析。**数据集市**是从数据仓库派生出的部门级子集，但专注于单一主题领域。数据集市通常为性能原因而反规范化，且常基于**星型模式**结构，包含一张中央**事实**表，由维度表引用。数据仓库和数据集市用于 **OLAP** 和数据挖掘。通常使用星型模式来构建多维结构，或称**立方体**，其中包含可跨各维度（包括时间）访问的基础度量和聚合度量。

## 概念查询语言

正如信息系统可在不同层级建模，也可在不同层级查询。概念查询语言允许以自然语言（如 English Query）或通过在概念模式上选择和约束路径（如 ConQuer）来构建查询。概念查询工具自动将这些高层查询转换为 SQL 等低层语言查询。基于无属性模型（如 ORM）的概念查询在模式演化时稳定性高得多。

## 抽象机制

对于大型复杂模式，需要**抽象机制**来隐藏暂时不相关的细节。模块化将全局模式划分为大小适中的子模式。约束层和文本规则可根据需要开启或关闭。我们可以放大或缩小选定的对象类型，指定要显示其邻域的多少。

主要对象类型可通过其在全局模式中的重要性来识别（例如，因具有显式强制角色），并可抑制**次要事实类型**（不包含由主要对象类型扮演的两个角色的事实类型）的显示。此视图可通过聚焦于其主要事实类型进一步细化，依此类推。这种自底向上的抽象可逆转为自顶向下的细化。

次要事实类型也可按主要对象类型的属性来显示。在这种情况下，ER 图和 UML 类图可作为 ORM 图的抽象生成。虽然此类抽象适合紧凑的概览，但详细的 ORM 图最适合开发、转换和演化概念模式。

## 过程模型与外部接口设计

虽然数据模型是任何信息系统应用的基础，但也需要指定**过程模型**以指明数据上允许的**操作**，并设计**外部接口**。为此，可使用各种图表和符号来补充数据模型图。

早期阶段，非正式图表（如漫画）有助于阐明 UoD，**功能树**和 UML **用例图**可用于提供系统需求概览。**数据流图**也可用于描绘进程、代理和信息存储之间的信息流。然而，在某个阶段需要在过程和数据之间建立正式联系。为此，可使用**数据用例**来确定过程可绑定的数据模型（例如，通过定义**主要对象类型上的操作**）。这也可用于生成外部接口默认屏幕表单的内容（操作）。可对这些屏幕的格式和用法做出一些默认决策。

## 人机交互 (HCI) 设计

HCI 设计通常需要人工精心规划。不同用户组的访问权限需受控。用户能力水平也可能不同。为使**用户界面** (UI) 易学易用，界面应保持一致、简洁、结构化、高效，并适应用户。大多数情况下，首选 GUI。**菜单**设计需提供高效导航，并需要各级在线和离线帮助.

## 本体与语义 Web

在信息建模中，**本体** 一词指专为与其他模型共享而设计的概念模型。**语义 Web** 一词指面向未来的增强型 Web，其中互联网上的文档以结构化方式组织，使自动化代理能提取其语义。语义 Web 应用通常构建在 **OWL** 之上，OWL 又构建在 RDF 和 RDF Schema 之上，使用 XML Schema 进行标记文本表示和数据类型定义。

RDF 将信息分解为可表示为简单（主语、谓语、宾语）三元组的原子单元，表示二元关系，使用 **URIrefs** 为实例化三元组中主语、谓语和宾语节点的资源提供全局标识符。宾语节点也可由字面值（无类型或有类型）实例化。

RDF 和 RDFS 表达能力弱（能捕获的约束极少），但也过于宽松，允许有问题的断言（如：一个类可以是其自身的实例）。因 Web 信息常不完整，OWL 采用**开放世界假设**。OWL Lite 和 OWL DL 基于描述逻辑，处于一阶逻辑的可判定片段中，计算高效。OWL Full 具有与 RDFS 相同的宽松性。

2009 年，W3C 推荐了 OWL 语言的重大升级，称为 **OWL 2**。2012 年，推荐了 OWL 2 的第二版，仍为当前版本（见 <https://www.w3.org/TR/owl-overview/>）。OWL 2 能表达 ORM 模型的大多数方面，但不足以捕获某些 ORM 特性，如涉及多角色参数的集合比较约束、非环形约束和道义约束。

OWL 模型可用多种语法文本化表达（如 RDF/XML、OWL/XML、Manchester 语法、函数式语法和 Turtle），但缺乏图形符号。为充分利用 OWL，最好先用 ORM 等概念语言捕获本体，再映射到 OWL 或更合适的描述逻辑，并记录映射中丢失的约束。

## 元建模

通过将概念模式视为样本数据库状态，可用 CSDP 开发概念**元模式**。CASE 工具可用它确保仅输入有效的概念模式。**元建模**活动，即对模型建模，也有助于澄清不同形式化方法间的关系并进行转换。
