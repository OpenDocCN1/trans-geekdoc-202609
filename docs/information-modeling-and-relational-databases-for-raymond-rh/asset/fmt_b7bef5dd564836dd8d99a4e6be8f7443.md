A PIB file of this kind (probably expressed in XML or JSON) is a useful resource in its own right. It provides traceability between process and information at a conceptual level. The structure can be used to answer queries such as which activities rely on a given relation, or which activities create instances of a given fact type. This can help to ensure that systems designs are coherent before embarking on implementation.

## 15.10 Decision Model and Notation

Simple decisions can be defined in BPMN using appropriate gateway constructs, but this becomes infeasible for more complex decisions, such as evaluating the many factors influencing the approval of a loan application. To address this need, a new standard called Decision Model and Notation (DMN) was created by OMG. The first version of the standard was proposed in 2015, but it has undergone several revisions and is expected to evolve further over time. DMN is intended to be used in conjunction with BPMN in processes involving complex decisions.

The basis of a decision is the evaluation of some given input data against predefined business logic. A decision involving many factors may be broken down into a set of subdecisions combined to give the final result. DMN provides a graphical notation to show the linking of data (including intermediate results) and decision logic blocks. Here, diagrams only show how the logic is organized for human convenience. The real definition of the decision lies in the business logic contained in the blocks. DMN provides two means of expressing this logic: decision tables and a special expression language.

A decision table shows a list of input/output conditions indicating the output that results from a specific set of inputs. The table contains all possible combinations of input values. A row of the table contains columns for input values, corresponding outputs, and optional annotations. If more convenient, the orientation of the table can be changed by switching rows and columns.

As an alternative, DMN provides a language for defining business logic called Friendly Enough Expression Language (FEEL). This is claimed to be “friendly enough” for nontechnical business people to understand. It provides a collection of operators and functions that can be used to specify how a conclusion can be reached from a combination of input data. These are organized into “boxed expressions” that can be nested in complex cases.

The decision logic is invoked from BPMN through a special “Business Rule” activity type. Although the logic may be complex, the result is often very simple, for example, just a “yes” or “no” value. Activities that follow later in the process can use the decision result to influence the path taken, possibly using an appropriate gateway element.

Because DMN is an adjunct to BPMN, it requires no additional treatment from a conceptual modeling perspective. A general approach to combining ORM, BPMN, and DMN is outlined in [Fig. 15.44](#Ch015_773-830_B9780443237904000190.xhtml#f0225).

![Fig. 15.44 Outline of DMN application.](images/B9780443237904000190/f15-44-9780443237904.jpg)

[Fig. 15.44](#Ch015_773-830_B9780443237904000190.xhtml#B-f0225) Outline of DMN application.

Broadly speaking, the relevant information from an ORM model is marshaled together using the Process-Information bridge approach discussed above. A Business Rule activity invokes the decision at the appropriate point in the process. The decision logic to be applied at that point is expressed in DMN, referring to the available information used as inputs to the decision and defining the decision outcome (which may or may not be stored persistently). DMN is still a relatively young standard, and further revisions can be expected in the future.
