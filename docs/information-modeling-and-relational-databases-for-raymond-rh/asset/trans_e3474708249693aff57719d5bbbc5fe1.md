# 13.1 SQL：整体概览

在上一章中，我们介绍了用于检索数据（**select**…）和修改数据（**insert**…、**update**…、**delete**…）的结构化查询语言（SQL）语句。这组语句传统上称为*数据操作语言*（DML）。现在我们将关注 SQL 的其他方面。我们将介绍用于定义数据库模式各种元素的语句，这些语句使用 SQL 的一个子集，传统上称为*数据定义语言*（DDL）。

表当然是任何模式的基础，但我们还将讨论其他几种数据库对象及其在概念模式实现中的作用。特别是*视图*（views）和*触发器*（triggers）等数据库对象常用于实现最初可能在概念层面定义的约束和派生规则。

可扩展标记语言（XML）的广泛采用主要得益于其在结构化数据交换中的应用。然而，这也产生了关系数据与 XML 数据之间更好集成的相应需求。后续章节将讨论 SQL 标准如何被调整和扩展以增加 XML 相关功能，以及非 SQL 数据操作（如 XQuery）如何在关系框架中得到支持。

# 13.2 SQL：定义表

## 创建表

*基表*（base table）的数据驻留在数据库中（这与结果表和视图不同，我们稍后将介绍）。基表必须在填充数据前创建。从 SQL-92 开始，基表（及数据库的其他方面）是在使用 **create schema** 语句创建的*数据库模式*（database schema）的作用域内定义的。模式可使用 **drop schema** 语句删除。商业 SQL 通常提供不同的语法来创建新数据库（例如 **create database**）。

在 SQL 标准中，表是使用 **create table** 语句创建的。此外，大多数数据库管理系统（DBMS）还提供图形界面，供用户通过输入文本和选择选项来创建表。表定义的主要部分是列列表，标识每列的列名、数据类型，以及该列是否禁止 *nulls*（即该列是否为强制列）。也可为某些列声明约束。

SQL-89 **create table** 语句的语法可概括如下。此处，*literal* 表示数字或字符串常量，*col-list* 表示用逗号分隔的一个或多个列名列表，*unique-col-list* 表示已集体声明为主键或唯一键的列列表。如果约束适用于单个列，可在列定义末尾声明。多列约束必须在表定义末尾声明。**Check** 子句仅限于涉及表中单行的条件。

```
create table tablename (colname      data-type [ not null ]                  [ default { literal | null | user } ]                  [ primary key | unique ]                  [ references tablename ]                  [ check (col-condition-on-same-row) ]   [,…]   [, primary key (col-list) ]   [, unique (col-list) ]   [, foreign key (col-list) references tablename [ (unique-col-list) ] [,…] ]   [, check (table-condition-on-same-row) [,…] ] )
```

SQL-92 扩展了此语法。可通过在约束定义开头插入 **constraint** *constraint-name* 来为约束命名。这有助于生成有意义的错误消息和删除约束。**Check** 子句条件可跨越多行或多表。可使用 **create assertion** 声明通用约束（主要用于表间约束）。

外键约束可包含完全/部分匹配条件和参照动作。约束可声明为即时或延迟。受约束的数据类型宏可使用 **create domain** 语句声明。

SQL:1999 进一步扩展，例如，可使用 **of** 子句声明表为用户定义类型，该类型此前已使用 **create type** 语句声明为行类型。可使用 **under** 子句引用超表来定义子表。

商业 SQL 方言通常支持所有 SQL-89 功能，但语法可能不同。它们倾向于仅支持最新标准版本（如 SQL:2019 和 SQL:2023）中部分新语法。约束名称和参照动作得到广泛支持，但断言和无限制的 **check** 子句很少被支持。大多数厂商还提供自己的额外功能和语法。
