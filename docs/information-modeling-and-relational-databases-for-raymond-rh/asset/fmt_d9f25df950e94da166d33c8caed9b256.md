
为了阐明这一点，请计算示例中 *B* ⨉ *A*（参见[图 12.5](#Ch012_539-646_B9780443237904000268_1.xhtml#f0030)）。尽管生成的表按 *b1, a1, a2* 的顺序显示列，且值也按此顺序排列，但信息与 *A* ⨉ *B* 相同，因为每个值都可以链接到其列名。例如，*B* × *A* 的第一行可表示为 {(b1, 7), (a1, 1), (a2, 2)}，这等同于 {(a1, 1), (a2, 2), (b1, 7)}，即表示 *A* ⨉ *B* 的第一行。一旦列被唯一命名，其物理顺序就没有语义意义。

与标准集合论一样，并、交和笛卡尔积运算具有*结合性*。例如，*A* ∪ (*B* ∪ *C*) = (*A* ∪ *B*) ∪ *C*。因为不会产生歧义，在这种情况下可以省略括号。例如，表达式“*A* ∪ *B* ∪ *C*”是允许的。在目前考虑的四种表运算中，差运算是唯一不具有结合性的；即 *A* − (*B* − *C*) 可能不等于 (*A* − *B*) − *C*。作为练习，请使用文氏图验证这些断言。

回想一下，表的列名必须唯一。如果 *A* 和 *B* 没有共同的列名，则 *A* ⨉ *B* 使用 *A* 和 *B* 的简单列名。如果 *A* 和 *B* 不同但有一些共同的列名，则 *A* ⨉ *B* 中对应的列通过使用*限定名*（带前缀“`A`.”或“`B`.”）来唯一引用。但是，如果 *A* 和 *B* 相同（即我们希望形成一个表与自身的笛卡尔积）怎么办？

考虑[图 12.6](#Ch012_539-646_B9780443237904000268_1.xhtml#f0035)中的 `Person` ⨉ `Person` 表。这打破了表中列名必须唯一的规则。在这种情况下，仅使用限定列名也无法解决问题，因为我们将会有两个名为“`Person.firstname`”的列和两个名为“`Person.gender`”的列。

![图 12.6 这个笛卡尔积有什么问题？](images/B9780443237904000268/f12-06-9780443237904.jpg)

[图 12.6](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0035) 这个笛卡尔积有什么问题？

这个问题可以通过为表定义**别名**来解决。例如，我们可以使用“`Person2`”作为该表的替代名称，并按[图 12.7](#Ch012_539-646_B9780443237904000268_1.xhtml#f0040)所示形成乘积。如果需要，我们可以使用两个别名“`Person1`”和“`Person2`”来指定乘积 `Person1` ⨉ `Person2`。当我们需要比较不同行上的值时，可能会出现将表与自身相乘的需求。别名也可以简单地用于节省书写（通过引入更短的名称）。稍后将讨论，我们的**定义别名**表示法是关系代数中**重命名**运算符简单情况的替代语法。

### 关系选择

我们现在考虑 Codd 引入的四种表运算。第一种是选择（或*限制*）。不要将其与 SQL 的 **`select`** 命令混淆。在关系代数中，选择运算仅选取满足指定条件的那些行。直观上，我们可以将该运算描绘为返回一个*水平*或*行*子集，因为它从原表返回零行或多行（参见[图 12.8](#Ch012_539-646_B9780443237904000268_1.xhtml#f0045)）。

![图 12.8 关系代数中的选择运算。](images/B9780443237904000268/f12-08-9780443237904.jpg)

[图 12.8](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0045) 关系代数中的选择运算。

选择运算可以使用 `T` **`where`** `c` 形式的表达式来指定。这里，`T` 表示一个*表表达式*（即值为表的表达式），`c` 表示一个*条件*。选择运算仅返回条件评估为 True 的那些行，过滤掉条件评估为 False 或 Unknown 的行。“**`where`** `c`”部分称为 *`where` 子句*。

这种表示法鼓励自顶向下的思维（先找到相关表，再担心行），并与 SQL 语法一致。另一种表示法 `σ`[`c`](`T`) 常用于学术期刊。“`σ`”是西格玛，希腊字母“`s`”（“selection”的首字母）。

在[图 12.9](#Ch012_539-646_B9780443237904000268_1.xhtml#f0050)中，`Player` 表存储了关于网球运动员的详细信息。要列出仅男性网球运动员的详细信息，我们可以按图示制定此选择，得到所示结果。这里，选择条件只是等式：`gender` = ‘M’。对“M”使用单引号表示该值字面上是字符 ‘M’。引用字符串值（如 ‘David’）时也使用单引号。数值不应加引号。尽管选择产生的表未命名，但其列与原表同名。

![图 12.9 选择运算选取满足条件的那些行。](images/B9780443237904000268/f12-09-9780443237904.jpg)

[图 12.9](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0050) 选择运算选取满足条件的那些行。

条件 `c` 可包含六种*比较运算符*中的任意一种：`=`（等于）；`<>`（不等于）；`<`（小于）；`>`（大于）；`<=`（小于或等于）；和 `>=`（大于或等于）。有时表运算的结果是一个空表（参见空集）。例如，没有行满足 `Player` **`where`** `height` > 180 中的条件。

如果条件不涉及与空值的比较，它们就是布尔表达式——评估结果为 True 或 False。如果条件确实包含与空值的比较，则改用三值逻辑，因此条件可能评估为 True、False 或 Unknown。这也是 SQL 中发生的情况。无论哪种情况，选择运算仅返回条件为 true 的那些行。条件评估为 false 或 unknown 的任何行都会被过滤掉。

除了比较运算符，条件还可包含三种*逻辑运算符*：**`and`**、**`or`**、**`not`**。像往常一样，**`or`** 运算符是包含性的。作为练习，制定一个查询来列出身高低于 170 cm 的女性详细信息。参考 `Player` 表，看看你能否陈述结果，然后与[图 12.10](#Ch012_539-646_B9780443237904000268_1.xhtml#f0055)核对答案。为了提高可读性，保留字采用粗体显示。

![图 12.10 这个查询需要括号吗？](images/B9780443237904000268/f12-10-9780443237904.jpg)

[图 12.10](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0055) 这个查询需要括号吗？

[图 12.10](#Ch012_539-646_B9780443237904000268_1.xhtml#f0055) 中的查询使用括号来阐明运算顺序。然而，对于复杂表达式，大量的括号会使事情看起来非常混乱（参见 LISP）。与几种编程语言（如 Pascal）不同，大多数查询语言（如 SQL）赋予*比较运算符比逻辑运算符更高的优先级*。因此，出于评估目的，运算符 `=`, `<>`, `<`, `>`, `<=`, `>=` 的优先级高于 **`not`**、**`and`** 和 **`or`**。我们在关系代数中做出相同的选择，因为这减少了复杂表达式所需的括号数量。理解这一点后，[图 12.10](#Ch012_539-646_B9780443237904000268_1.xhtml#f0055) 中的查询可以更简洁地重写为：

```
Player where gender = ‘F’ and height < 170
```
