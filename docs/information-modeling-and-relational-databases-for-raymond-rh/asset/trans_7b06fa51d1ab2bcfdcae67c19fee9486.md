
`A` ÷ `B` 的结果是通过将结果限制为 `A` 中那些 `X` 条目来形成的，这些条目在 `A` 中关联的 `Y` 条目包含 `B` 的*所有*行条目。表达式 `A` ÷ `B` 也可以写作 `A` **divide-by** `B`。[图 12.26](#Ch012_539-646_B9780443237904000268_1.xhtml#f0135) 显示了一个简单示例，其中属性域用 `X1`、`X2`、`Y1` 表示。

![Fig. 12.26 A simple example used to explain relational division.](images/B9780443237904000268/f12-26-9780443237904.jpg)

[图 12.26](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0135) 用于解释关系除法的简单示例。

虽然不常用，但除法运算在列出与另一个表表达式的*至少所有*行相关联的行时很有用（例如，谁能供应我们库存清单上的所有物品？）。

作为一个实际示例，假设表 `Speaks`（country, language）存储了关于哪些国家说（即使用）哪些语言的事实。[图 12.27](#Ch012_539-646_B9780443237904000268_1.xhtml#f0140) 中的大表显示了一个样本数据。现在考虑查询：哪些国家说加拿大所说的*所有*语言？要回答这个问题，我们首先使用表达式 `Speaks` **where** country = ‘Canada’ *\[*language*\]* 找出加拿大所说的所有语言。这将返回表 {English, French}。然后我们如图所示将 `Speaks` 表除以此结果，以获得最终答案 {Canada, Dominica}。

### 重命名

回顾 [图 12.7](#Ch012_539-646_B9780443237904000268_1.xhtml#f0040)，我们在那里为表名定义了别名。关系赋值也可用于提供新表名，但不能用于*更改属性名*。为此，我们需要 ***rename***（重命名）算子。关系代数表达式可以包含前面讨论的任何关系运算（并、投影、选择、连接等），本质上是一个返回表的查询。通常，*对关系表达式应用重命名算子将返回一个具有相同行*（相同数据内容）*但表或列名不同的表*。

重命名算子的正式语法使用希腊字母“***ρ***”（*rho*）。如果 `Rexp` 是一个返回具有表模式 `R`(`a`[1], …, `a`[*n*]) 的表的关系表达式，则以下表达式返回一个具有表模式 `S`(`b`[1], …, `b`[*n*]) 的表。其下方的表达式使用了我们的替代语法。

*    `ρ``S`(`b`[1], …, `b`[*n*]) `Rexp`
*    **define** `S`(`b`[1], …, `b`[*n*]) **as** `Rexp`

如果省略属性列表 (`b`[1], …, `b`[*n*])，该操作仅提供一个新表名。在这种情况下，如果 `Rexp` 只是一个表名，使用定义别名表示法（例如，**define alias** `Person2` **for** `Person`）会更自然，如 [图 12.7](#Ch012_539-646_B9780443237904000268_1.xhtml#f0040) 所示。

作为一个简单示例，考虑表模式 `Person` (personName, age, genderCode) 和 `Drives` (personName, carRegNr)，其中 `Drives.personName` 是指向 `Person` 表的外键。以下声明可用于定义一个 `WomanDriver` 表，仅将人名属性用“name”代替“personName”。

```
define WomanDriver   ( name, carRegNr ) as
    Employee ⨝ Drives
where age >= 18 and genderCode = ‘F’
[personName, carRegNr]
```

一旦定义，`WomanDriver` 表可像其他任何表一样在后续查询中使用。这类似于 SQL 中的*视图*（见后续章节）。

### 查询策略

这完成了关系代数中所有主要算子的介绍。[表 12.2](#Ch012_539-646_B9780443237904000268_1.xhtml#t0015) 列出了本书采用的算子优先级。比较算子具有最高（且相同）优先级，因此最先求值。逻辑算子其次（先 **not**，后 **and**，最后 **or**）。然后求值关系选择和投影运算（优先级相同）。最后，求值其他六个关系算子（并、交、差、笛卡尔积、自然连接和除法）（优先级相同）。优先级相同的算子从左到右求值。括号中的表达式最先求值。某些系统对关系算子采用不同的优先级约定。

为了帮助用关系代数构建查询，以下*查询策略*很有用：

*   • 用自然语言表述查询，并理解其含义。
*   • 询问哪些表持有该信息。
*   • 如果你有表数据，自己回答查询，然后回溯你的思维步骤。
*   • 将查询分解为步骤或子问题。
*   • 如果结果列来自不同的表，声明表之间的连接。
*   • 如果你需要关联同一表的两行，使用别名或重命名定义来执行自连接。
*   • 要更改结果中的任何表或列名，使用重命名定义。

我们的第一步是用自然语言表述查询，确保我们理解查询的含义。接下来，确定哪些表持有回答查询所需的信息。信息可能在单个表中，也可能分布在两个或更多表中。如果要列出的列来自不同的表（或同一表的不同副本），则通常必须指定这些表之间的连接。这些连接可以是任何类型：内连接或外连接、自然连接或 θ 连接，或交叉连接（笛卡尔积）。

除了涉及 ∪、∩ 或 - 的某些情况外，无论结果列是否来自同一表，只要必须访问不同的表来确定结果，关系代数就要求使用连接。SQL 引入了子查询，当结果列来自同一表时，可以用子查询代替连接。

让我们看一个使用银行账户数据库的示例。为减少翻页，数据库在 [图 12.28](#Ch012_539-646_B9780443237904000268_1.xhtml#f0145) 中重现。现在考虑查询：哪些客户拥有余额超过 700 美元的账户？在用关系代数表述之前，我们应确保理解自然语言查询的含义。在某些情况下，我们可能需要通过询问最初提出查询的人来澄清含义。例如，我们是否只想要相关客户的客户编号，还是也想要他们的姓名？假设我们也想要客户姓名。
