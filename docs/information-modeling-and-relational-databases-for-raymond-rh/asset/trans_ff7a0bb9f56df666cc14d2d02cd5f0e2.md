
虽然 SQL 没有提供关系除法运算符，但我们可以通过如图所示的分组来达到相同的效果。第一个子查询产生（“英语”，“法语”），因此 `where` 子句在形成分组之前就过滤掉了荷兰语和西班牙语行。

由于 `Speaks` 上的唯一性约束，一个国家所说的加拿大语言数量现在就是该国家分组中的行数。因此，`having` 条件中的左侧 `count(*)` 分别为澳大利亚、比利时、加拿大和多米尼克返回值 1、1、2 和 2。第二个子查询的值为 2，因此整体查询返回加拿大和多米尼克。

当相关列关联不唯一时，可以通过使用 `distinct` 选项来调整此方法以处理此类情况。例如，考虑关系模式 `Localization` (productCode, “language”) 和 `LanguageUse` (“language”, country, nrSpeakers)。查询“哪些产品被本地化为某个国家所讲的所有语言，且该语言在该国至少有 1000 万人使用？”要求在 `having` 子句的子查询中使用 `count(distinct(“language”))` 而不是 `count(*)`。正如稍后讨论的那样，这种分组方法可以扩展以适应涉及集合比较的查询，而不仅限于关系除法所涵盖的情况。

我们现在已经介绍了 SQL `select` 语句大部分基本工作原理。迄今为止涵盖的 BNF 语法可总结如下。与此处显示的语法不同，SQL 标准实际上允许没有 `group by` 子句的 `having` 子句（实际上意味着“group by no columns”），但其语义有问题，因此我们将忽略此选项。

*   ```
    select [all | distinct ] * | expression [ [ as ] column-alias ] [,…]
    ```

*   ```
    from table [ [ as ] alias ]
    ```

*   ```
                   [,| cross join table [ [as ] alias ]
    ```

*   ```
                     | natural [ inner | { left | right | full }[ outer ] ] join table [ [as ] alias ]
    ```

*   ```
                     | [ inner | { left | right | full } [ outer ] ] join table [ [as ] alias ]
    ```

*   ```
                            { on condition | using ( col-list ) }
    ```

*   ```
                     | union join table [ [as ] alias ]
    ```

*   ```
                                                               [,...] ]
    ```

*   ```
       [ where col-condition ]
    ```

*   ```
       [ group by colname [,...]
    ```

*   ```
                [having group-condition ] ]
    ```

*   ```
       [ union | intersect | except ... ]
    ```

*   ```
       [ order by col  [ asc | desc] [,...] ]
    ```

在关系代数的九种表操作中，我们已经讨论了五种（投影、选择、笛卡尔积、Θ-连接和并集）的一般情况对应的 SQL 表述，以及三种（交集、差集和除法）特殊情况的对应表述。关系代数的重命名操作通过视图处理（见后续章节）。交集、差集和除法的一般情况可以使用连接来处理，也可以使用相关子查询和存在量词子查询来处理，这将在下一节讨论。

## 12.11 SQL：相关子查询和存在量词子查询

本节通过考虑相关子查询和存在量词子查询，扩展了[第 12.8 节](#Ch012_539-646_B9780443237904000268_1.xhtml#s0110)中的子查询工作。前面讨论的子查询是简单的、非相关子查询。非相关子查询计算一次，由其结果替换，然后运行外部查询。相反，*相关子查询*将其搜索条件与外部查询中命名的表的每一行相关联，并实际上为每一外部行重新计算一次（见图 12.58）。

![图 12.58 相关子查询将其条件与外部查询的每一行相关联。](images/B9780443237904000268/f12-58-9780443237904.jpg)

[图 12.58](#Ch012_539-646_B9780443237904000268_2.xhtml#B-f0295) 相关子查询将其条件与外部查询的每一行相关联。

由于重复计算，相关子查询有时运行速度较慢。然而，它们显著扩展了可表示为单个 SQL 查询的查询范围，非常值得掌握。让我们将相关子查询内部的条件称为相关条件。此条件通常采用以下形式：

*a* *Θ* *b*

![公式](images/B9780443237904000268/si1_e.png)

其中 *a* 是*内部列*（列在子查询的 `from` 子句中），*b* 是*外部列*（列在外部查询的 `from` 子句中），Θ 是*比较器*（例如 =, >）。

为避免歧义，*a* 或 *b* 的列名可能需要用表名限定。基本情况总结在[表 12.15](#Ch012_539-646_B9780443237904000268_2.xhtml#t0080)中。默认假定局部作用域，因此我们通常可以不限定 *a*（除非它出现在两个内部表中）。但是，如果 *a* 和 *b* 具有相同的非限定名称，我们需要通过用其外部表名限定 *b* 来区分它。如果外部表与内部表同名，则为其引入别名以将其与内部表区分开。
