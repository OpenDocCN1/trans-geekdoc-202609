

# SQL/XML 操作：xmlparse、xmlserialize、xmlconcat 和发布函数

## xmlparse 和 xmlserialize

我们将要查看的前两个 SQL/XML 操作 `xmlparse` 和 `xmlserialize`，用于在 XML 的*结构化*表示和*字符串*表示之间进行相互转换。

`xmlparse` 操作接受一个 SQL 字符串表达式并生成等效的 XML 结构。一个参数用于定义字符串表达式预期表示的是文档还是内容。基本语法自 SQL:2003 以来一直保持一致。

```
xmlparse ( { document | content } stringexpression [ { preserve | strip } whitespace ] )
```

操作的结果可以赋给 `xml` 类型的变量，或存储在 `xml` 列中。`xmlparse` 处理空白字符的确切方式受详细规则约束，此处不予讨论。

`xmlserialize` 操作执行 `xmlparse` 的逆操作，生成给定 XML 表达式的字符串版本。SQL 标准并未强制规定结果字符串的确切格式，但要求对 `xmlserialize` 生成的字符串进行后续的 `xmlparse` 应能还原出原始的 XML 表达式。换句话说，给定一个名为 `myXmlData` 的 XML 文档，以下结构：

```
xmlparse ( document ( xmlserialize ( document myXmlData as varchar ( max ) ) ) )
```

应产生等同于 `myXmlData` 的结果。`xmlserialize` 原始的 SQL:2003 语法在 SQL/XML:2006 中得到了扩展。

```
xmlserialize ( { document | content } xmlexpression as SQLdatatype   [ version string ]   [ including xmldeclaration | excluding xmldeclaration ] )
```

结果的 SQL 数据类型可以是任何 SQL 字符串类型（如 `char`、`varchar`），但序列化后的 XML 往往很长，因此字符大对象（`clob`）类型可能是常见的选择。可选地，`including xmldeclaration` 会在结果前添加 XML 声明 `<?xml version="1.0" encoding="UTF-8"?>`；默认为 `excluding xmldeclaration`。XML 版本也可单独指定；目前这将限制为 "1.0"。

## xmlconcat

SQL:2003 中引入的 `xmlconcat` 操作在 SQL:2006 中得以保留。它只是简单地连接一组 XML 表达式，生成一个新的 XML 表达式。

```
xmlconcat ( xmlexpression [, …]  [ returning { content | sequence } ] )
```

可选的 `returning` 子句是在 SQL/XML:2006 中添加的。如果省略此子句，则由实现定义隐式返回 content 还是 sequence。

## 发布函数

SQL:2003 标准定义了多个“发布”函数，用于从 SQL 表达式生成 XML 表达式。这些函数在 SQL/XML:2006 中得到了扩展，并新增了函数。此处我们仅介绍 SQL/XML:2006 中这些函数的定义。

### xmlelement

`xmlelement` 函数用于根据给定的一组参数创建一个 XML 元素。回顾一下，XML 元素具有基本形式：

```
<tagname optionalAttributes>  optionalElementContent </tagname>
```

因此，例如，一个表示客户的元素可能如下所示：

```
<cust custid = "1234"> Widgets Inc </cust>
```

如果需要，标签名可以通过添加命名空间前缀来进一步限定，在这种情况下也必须指定命名空间 URI。`xmlelement` 函数根据提供的参数构建单个 XML 元素，并将其作为 `xml` 值返回。此处展示了字符串的基本语法。还存在一个用于二进制字符串的变体，我们不予讨论。

嵌入的 `xmlnamespaces` 和 `xmlattributes` 函数可选择性地用于给定元素的上下文中，以向元素添加所需的命名空间声明或属性。元素内容由一个表达式列表定义，该列表是可选的，因此可以创建空元素。`returning` 子句也是可选的，我们之前已经见过。

```
xmlelement ( name xmlelementname   [ , xmlnamespaces (namespace-declaration-item [,…] ) ]   [ , xmlattributes ( attributevalue [as attributename ] [,…] )  [ , elementcontent [,…]  [ option { null on null | empty on null | absent on null | nil on null | nil on no content } ] ]  [ returning { content | sequence } ] )
```

内容选项需要更多解释。在 SQL 中，缺失的可选值显式标记为 `null`。这不是 XML 中识别的值，尽管 `null` 对 SQL `xml` 数据类型是合法的。根据期望的结果，缺失值可以在 XML 中通过简单地省略相关元素来表示，或者通过包含不含值的元素开始/结束标签来表示。如果需要显式的等同于 `null` 的指示符，另一种选择是“XML Schema For Instances”命名空间中指定的“nil”机制。该命名空间通常通过如下声明引入：

```
xmlns:xsi = "http://www.w3.org/2001/XMLSchema-instance"
```

`xsi` 前缀按惯例使用，但也可替换为其他前缀。一旦定义了该命名空间，XMLSchema-instance 中定义的 `nil` 属性即可设置为 True。

```
<myElement xsi:nil = "true"></myElement>
```

以这种方式标记的元素不能有任何元素内容，但仍可携带其他属性。SQL:2003 标准承认了 `xsi:nil` 选项，但未规定如何将其与 `xmlelement` 等操作结合指定。SQL/XML:2006 对这些选择提供了精细控制，如表 16.4 所示。

### xmlforest

`xmlforest` 函数是将 `xmlconcat` 应用于一系列 `xmlelement` 结果的便捷方式：它从表达式列表生成一系列元素。这些元素可以显式或隐式命名。与 `xmlelement` 一样，对 `xmlforest` 的调用也可以嵌套。基本语法如下：

```
xmlforest ( [ xmlnamespaces (namespace-declaration-item , ), ]elementvalue [ as elementname ] [,…] [ option { null on null | empty on null | absent on null | nil on null | nil on no content } ] ] [ returning { content | sequence } ] )
```

参数的使用方式与 `xmlelement` 相同。例如，

```
select o.orderId, xmlelement ( name "order",  xmlforest ( o.custName as "customer", o.date ) ) as Xorder from Orders as o where orderid > 9800
```

如果保留 SQL 名称中的大小写很重要，则应将它们作为分隔标识符进行别名化。常规标识符在某些实现中可能会映射为全大写。例如，上述示例中的 *date* 元素可能显示为 `<DATE> … </DATE>` 而不是 `<date> … </date>`。

在 SQL Server 中，可通过以下方式生成等效的结果表：

```
select o.orderId, (select o.custName 'customer', o.date 'date' from orders as o for xml path ('order'), type) as Xorder from orders as o where orderid > 9800
```
