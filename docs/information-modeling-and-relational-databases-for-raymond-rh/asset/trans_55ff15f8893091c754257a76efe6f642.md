

## 导出规则示例

*   ```
    Article retails for MoneyAmount1 and Article wholesales for MoneyAmount2 and
    ```

*   ```
    MoneyAmount = MoneyAmount1 – MoneyAmount2.
    ```

为简洁起见，关系式风格假定规则头部的变量为全称量化，而规则体中引入的变量为存在量化。因此该规则可明确表述为：**对于每个** `Article` **和** `MoneyAmount`，`Article` 的加价为 `MoneyAmount` **当且仅当** `Article` 零售价为 **某个** `MoneyAmount1` **且** `Article` 批发价为 **某个** `MoneyAmount2` **且** `MoneyAmount = MoneyAmount1 – MoneyAmount2`。

严格来说，等式 `markup = retailPrice – wholesalePrice` 是加价、零售价和批发价这三个事实类型之间的一个*约束*，具有一个自由度。这三个中的任意一个均可由其他两个导出。有时我们可能希望录入零售价和批发价，让系统导出加价；有时可能希望录入批发价和加价以导出零售价；也可能录入零售价和加价以导出批发价。

若希望系统支持所有这些选择，则这三个事实类型均为*半导出*（实例可断言或导出），其谓词标记为“^+”（直观上理解为半个星号）而非“\*”。这在实践中有时很有用（例如基于利率和还款期限探索贷款方案）。

但在大多数导出场景中，我们会预先决定由某个特定事实类型始终作为导出对象。此时，导出规则可明确指定为*定义*（而非仅是等式或双条件），即使用“define … as …”以其他事实类型定义导出事实类型。例如：

```
For each Article, define markup as retailPrice – wholesalePrice.
```

在该定义中，导出事实类型为*被定义项*（需被定义的对象）。*原语*事实类型（即不以其他类型定义者）称为*断言*事实类型或*基础*事实类型。*导出*事实类型以其他事实类型（断言或导出）定义。对于算术导出规则（如本例），属性风格通常更紧凑、可读性更强，因而更受青睐；对于逻辑导出规则（参见[第 5.5 节](#Ch005_159-209_B9780443237904000098.xhtml#s0045)），关系风格往往更合适。

最后三列的值均为数字。高度和宽度可进行有意义的比较，因为二者均为长度：5 cm 的长度既可作为高度实例，也可作为宽度实例。因此 `Height` 和 `Width` 可合并为实体类型 `Length`。`Width` 和 `Area` 是否因为都包含值 20 而重叠？并不！面积以平方厘米为单位，与厘米不同。然而，20 cm 的长度并不等同于 20 cm² 的面积。若最后一列标题为“Perimeter(cm)”，则可像之前那样将三个标题合并为一个实体类型。但因 `Area` 本质上属于不同量纲，必须将其单独保留，如[图 3.29](#Ch003_59-110_B9780443237904000037.xhtml#f0150)(a)所示。

作为替代方案，高度和宽度事实类型可建模为 `Window(.nr) has Height(cm:)` 和 `Window(.nr) has Width(cm:)`，其中厘米单位基于长度量纲。

[图 3.29](#Ch003_59-110_B9780443237904000037.xhtml#f0150)(a) 中面积的导出规则前缀单星号，表示其为导出且不存储。规则体中的另一星号在此上下文中表示乘法。原则上，面积、高度、宽度任一均可由其他两个导出。但在许多情况下，根本不存在选择哪个事实类型作为导出的余地。例如，求和与平均事实可由个别案例事实导出，但除平凡情况外，无法从汇总数据反推个别事实。

不存储的导出事实类型为*查询时导出*（*惰性求值*），即仅在请求信息时计算导出信息。例如，若 `Window` 模式映射到关系数据库，`Window` 基表中不包含面积列。计算面积的规则可包含在视图定义或存储查询中，仅在查询视图或执行存储查询时调用。大多数情况下首选惰性求值（如根据出生日期和当前日期计算年龄）。

完全导出且存储的事实类型为*更新时导出*（*急切求值*）。有时为追求性能而采用急切求值（如计算账户余额）。此时信息在定义事实录入即刻存储，并在定义事实更新时同步更新。完全导出并存储的事实类型标记为*双星号*“\*\*”，如[图 3.29](#Ch003_59-110_B9780443237904000037.xhtml#f0150)(b)所示。映射到关系数据库时，将为导出事实类型创建列，并将计算规则指定为触发器或计算列规则，在定义列更新（含插入/删除）时触发。

然而，假设这些实体类型互斥（即无人可同时担任多个职位）。即便如此，我们仍需考虑是否合并实体类型，因为为每种类型记录的*同类信息*（性别）相同。

此类情况下，应自问：*我们是否曾希望在同一查询中列出不同实体类型的同类信息？* 例如，是否需要“列出所有从业人员及其性别”？若需要，则通常应按[图 3.31](#Ch003_59-110_B9780443237904000037.xhtml#f0160)所示合并实体类型。若不需要，则可能有理由保持模式不变。[第 6.6 节](#Ch006_211-271_B9780443237904000025.xhtml#s0050)将详细探讨此问题。
