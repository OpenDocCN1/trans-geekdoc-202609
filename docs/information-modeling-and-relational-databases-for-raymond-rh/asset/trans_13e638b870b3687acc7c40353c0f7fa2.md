
# Rmap 过程概述

考虑到这些标准，**Rmap** (*R*elational *map*ping) 过程保证了无冗余的关系设计，并包含限制表数量的策略。Rmap 扩展并改进了一个称为“最优范式” (ONF) 算法的旧映射过程。Rmap 的完整版本包括将所有图形概念约束完全映射的细节，超出了本书的范围。然而，该过程的核心步骤将在本节和下一节中介绍。

正如后续章节所讨论的，如果在应用 Rmap 之前，概念模式经过优化算法的转换，可能会产生表更少、效率更高的关系设计；有时为了满足关键性能要求，可能需要使用受控冗余进行低级优化。

即使没有进一步的优化，Rmap 过程也极其宝贵，因为它保证了一种安全、合理高效、规范化的设计。幸运的是，该过程的基本步骤很简单。

**冗余是原子事实的重复**。原子事实通常是基本的（例如：名为“Einstein”的科学家出生于名为“Germany”的国家），但在极少数情况下可能是存在性的（例如：存在一个名为“Germany”的国家）。如果我们的概念事实类型是原子的，我们就可以轻松避免关系表中的冗余。

通常，关系表的每一行存储一个或多个基本事实。否则，表行存储单个引用或存在性事实（例如：国家名称查找表）。我们可以通过确保*每个事实类型仅映射到一个表，且其实例仅出现一次*来自动*避免表中的冗余*。

为此，有两条基本规则，如下所示。作为练习，请说服自己：按这种方式分组事实会使任何事实都无法被复制。

1.  每个具有复合内部唯一性约束的事实类型单独映射到一个独立的表，并以该唯一性约束为键。
2.  连接到同一对象类型的函数角色的事实类型被分组到同一个表中，并以该对象类型的标识符为键。

这两条规则展示了如何将事实类型分组为表模式。第一条规则在 [图 11.7](#Ch011_481-537_B9780443237904000141.xhtml#f0040) 中进行了说明。任何具有跨越两个或多个角色的唯一性约束的非对象化谓词必须单独映射到一个表。因此，概念模式上的 *m:n* 二元事实类型和所有 *n* 元事实类型（*n* ≥ 3）都映射到单独的表（除非它们是对象化关联，稍后讨论）。

![图 11.7 每个具有复合内部唯一性约束的事实类型单独映射到一个表](images/B9780443237904000141/f11-07-9780443237904.jpg)

[图 11.7](#Ch011_481-537_B9780443237904000141.xhtml#B-f0040) 每个具有复合内部唯一性约束的事实类型单独映射到一个表。

每个对象类型根据其引用模式中的组件数量映射到一个或多个属性。如果谓词只有一个唯一性约束，则该表的主键是由该约束跨越的属性（或属性集）。否则，其中一个唯一性约束跨越主键，其他约束跨越备用键。ORM 工具允许您在映射前指定首选用作主键的约束。

在映射概念模式时，应注意*选择有意义的表名和列名*。在 [图 11.7](#Ch011_481-537_B9780443237904000141.xhtml#f0040) 的情况下，该表用于存储概念关系类型的实例，因此通常给予一个类似于概念谓词读法的名称。如果涉及的对象类型不同，它们的名称或其值类型的名称，或对象类型名称与值类型名称的连接，常被用作列名。例如：`Drives(empNr, carRegNr)`。

当同一对象的信息分布在多个表中时，通常最好一致地为该对象使用相同的列名，除非这会丢失所涉及不同角色语义之间的重要区别（例如：`empNr` 也在 `Employee` 表中用于引用员工）。除了帮助设计者看到关联外，这种做法还可以简化 SQL 标准中自然连接的构建。

然而，如果同一谓词的不同角色由同一对象类型扮演，则必须选择不同的列名以反映所涉及的不同角色。例如：`Contains(superpart, subpart, quantity)`。

第二条分组规则的一个典型示例如 [图 11.8](#Ch011_481-537_B9780443237904000141.xhtml#f0045) 所示。回顾一下，函数角色具有简单的唯一性约束。这里，两个函数角色连接到对象类型 *A*。该规则在只有一个函数角色或两个以上函数角色时也适用。

![图 11.8 同一对象类型的函数事实类型被分组在一起](images/B9780443237904000141/f11-08-9780443237904.jpg)

[图 11.8](#Ch011_481-537_B9780443237904000141.xhtml#B-f0045) 同一对象类型的函数事实类型被分组在一起。

[图 11.8](#Ch011_481-537_B9780443237904000141.xhtml#f0045) 以我们通常的方式描绘了强制角色和可选角色（可选列用方括号标记）。*A*、*B* 和 *C* 的标识方案未在此显示，但可以是简单的或复合的。这些事实类型被分组到一个表中，以 *A* 的标识符作为主键（此处显示为 *a*）。

通常选择 *A* 的名称作为表名。为避免混淆，最好永远不要对表和列使用相同的名称，因此 *A* 的值类型名称常被选为 *a* 的名称。*B* 和 *C* 的名称（或其值类型或角色名）常被选为其他列名（此处为 *b* 和 *c*）。例如：`Employee(empNr, gender, [phone], salary, [tax])`。

一旦确定了表分组，划线标记主键，用方括号标记可选列，并将其他约束（如子集约束、值列表）映射下去，任何派生规则也会被映射，如前一节所述。

为了帮助理解 Rmap 过程，考虑几个例子会有所帮助。在我们的初始示例中，所有实体类型都有简单标识符，且不存在子类型或对象化关联。

考虑 [图 11.9](#Ch011_481-537_B9780443237904000141.xhtml#f0050) 中的概念模式。多对多事实类型映射到一个单独的表（使用规则 1）。一元事实类型是函数的，因为它具有隐含的唯一性约束。函数事实类型映射到一个以 `Employee` 的标识符为键的表（使用规则 2）。

![图 11.9 一个简单的关系映射](images/B9780443237904000141/f11-09-9780443237904.jpg)

[图 11.9](#Ch011_481-537_B9780443237904000141.xhtml#B-f0050) 一个简单的关系映射。

主键用下划线标记，`mobileNr` 的可选性用方括号表示。在闭世界假设 (CWA) 语义下，一元事实类型 `Employee is tenured` 映射到一个强制布尔列；目前，NORMA 将所有一元事实类型映射到可选布尔列；不过，NORMA 未来计划区分 CWA、开放世界假设 (OWA) 和带否定的开放世界 (OWN) 语义。虚线箭头描绘了*子集约束*，即 `Drives` 表中引用的每个员工也在 `Employee` 表的主键中被引用（参照完整性）。
