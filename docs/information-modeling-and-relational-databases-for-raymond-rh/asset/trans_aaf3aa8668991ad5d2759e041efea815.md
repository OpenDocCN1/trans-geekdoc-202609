

## SQL 分组查询：WHERE、HAVING 与关系除法

在 `select` 语句中，可以包含 `where` 子句，在分组形成和函数应用之前过滤掉不需要的行。合理地，`where` 子句必须放在 `group by` 子句之前。例如，以下查询列出了每个家族及其不带电粒子的平均质量。为了适配 SQL Server 等会截断平均值的方言，质量通过乘以 `1.0` 强制转换为 real 类型，并使用 `cast` 函数仅显示小数点后两位。请注意，将标量函数应用于聚合函数（例如 `cast(avg(...))`）是合法的。但是，将聚合函数应用于聚合函数（例如 `min(avg(...))`）是非法的。

```sql
select family, cast (avg (1.0*mass) as decimal (6,2)) as avgUnchargedMass
from   Particle
where charge = 0
group by family
```

**结果：**

| family | avgUnchargedMass |
| :--- | :--- |
| baryon | 2232.25 |
| lepton | 0.00 |
| meson | 770.65 |

有时，我们希望将注意力限制在仅满足特定条件的那些组上。正如 `where` 子句可用于对单个行施加搜索条件一样，`having` 子句可用于对单个组施加搜索条件。在这种情况下，`having` 子句必须紧跟在它逻辑上关联的 `group by` 子句之后。语法如下：

```sql
group by col-name [, ...]
having group-condition
```

搜索条件的常规规则适用。逻辑运算符和比较运算符可以包含在条件中。每个比较将组的某个属性（如 `min(mass)`）与常量或另一个组属性进行比较。（虽然罕见，但可以在没有关联 `group by` 子句的情况下包含 `having` 子句；在这种情况下，整个表被视为一个组。）作为一个简单的例子，以下查询列出了粒子数超过四个的家族，以及每个家族的粒子数。虽然在 `having` 子句中允许别名（如 `tally`）讲得通，但在许多 SQL 实现中（如 SQL Server）这是不允许的。

```sql
select family, count (*) as tally
from Particle
group by family
having count (*) > 4
```

**结果：**

| family | tally |
| :--- | :--- |
| baryon | 8 |
| meson | 7 |

下一个示例更难。为了帮助阐明其工作原理，添加了数字 1 到 6 以指示查询行的处理顺序。这些数字不是查询的一部分。请自行跟踪步骤以确保你遵循此顺序。关于 `having` 子句，请注意：带电轻子被包含在内（不带电且质量为零的轻子被 `where` 子句过滤掉了），而带电重子被排除在外（它们的最大质量超过 2000）。

> **需求：** 仅考虑带电粒子，按相同的家族名称形成组，其中该组最轻粒子的质量大于 0 且最重粒子的质量小于 2000。列出每个组的家族名称、粒子数量和最大质量，成员较多的组优先显示。

```sql
      5      select family, count (*) as chargedTally, max(mass) as maxChargedMass
      1      from Particle
      2      where charge <> 0
      3      group by family
      4      having min (mass) > 0 and max (mass) < 2000
      6      order by chargedTally desc
```

**结果：**

| family | chargedTally | maxChargedMass |
| :--- | :--- | :--- |
| meson | 4 | 966 |
| lepton | 2 | 207 |

分组的一个简单用途仅仅是避免重复。例如，以下查询可用作 `select distinct family from Particle` 的替代方案：

```sql
select family from Particle
group by family
```

**结果：**

| family |
| :--- |
| baryon |
| lepton |
| meson |

现在假设我们发出以下查询。结果将是什么？

```sql
select family from Particle
group by family
having count (*) = 4
```

将其与前一个查询进行比较，你可能会觉得每个家族的计数将是 1，因此不会返回任何行（即结果为空集）。不对！当 `group by` 子句完成工作时，每个组仍然拥有其所有成员（当然它们都具有相同的分组值）。`having` 子句现在过滤掉那些不满足其搜索条件的组。最后，`select` 列表决定列出哪些组属性。这些组首先被分为三个家族，其中两个家族被消除（重子和介子），最后仅列出剩余组（四个轻子）的家族名称“lepton”。
