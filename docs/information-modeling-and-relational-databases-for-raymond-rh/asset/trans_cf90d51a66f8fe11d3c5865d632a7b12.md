## 14.9 数据迁移与查询转换

数据迁移是重构的第四阶段，有时可能具有挑战性。当原始数据库填充了海量数据时，通常不切实际去手动转换并重新录入数据到新的数据库模式中。虽然大多数 DBMS 都提供了协助数据迁移的工具，但这些工具通常只能处理简单的数据转换，因此对于更复杂的情况，你需要编写自己的转换程序。此类数据转换通常用 SQL 编写，不过如果数据以 XML 形式提供，也可以使用 XSLT。

数据迁移完成后，原数据库上的任何存储查询都需要重新编码，以便在新数据库上执行等效的查询。本节通过一个小型重构示例来说明数据迁移和查询转换的任务。本节末尾的练习提供了一个更大的示例供你自行尝试。

[图 14.82](#Ch014_681-771_B9780443237904000189.xhtml#f0415)(a) 显示了一个关于武术俱乐部的关系模式片段。在武术（如柔道和空手道）中，段位严格分为两种：段（黑带等级）和级（黑带以下）。`ClubNrRankedPlayers` 表存储关于特定俱乐部拥有多少段和级选手的事实。例如，元组（“KDK”，段，300）和（“KDK”，级，250）意味着俱乐部代码为“KDK”的俱乐部拥有 300 个段位选手和 250 个级位选手。

![图 14.82 (a) 原始关系模式和 (b) 重构后的关系模式。](images/B9780443237904000189/f14-82-9780443237904.jpg)

[图 14.82](#Ch014_681-771_B9780443237904000189.xhtml#B-f0415) (a) 原始关系模式和 (b) 重构后的关系模式。

假设原始数据库有一个存储查询，用于列出每个俱乐部的代码和名称，以及黑带选手的数量（如果已知）。该查询可用 SQL 表示为查询 Q1。

```
Q1: select Club.clubCode, clubName, nrPlayers as nrDanGrades
from Club left outer join ClubNrRankedPlayers
on Club.clubCode = ClubNrRankedPlayers.clubCode
and ClubNrRankedPlayers.rankType = 'dan'
```

现在假设在重构原始数据库时，这两个表模式被 [图 14.82](#Ch014_681-771_B9780443237904000189.xhtml#f0415)(b) 中所示的等效单表模式所取代。这种优化基于 [第 14.2 节](#Ch014_681-771_B9780443237904000189.xhtml#s0015) 中讨论的谓词特化变换。

假设原始模式称为 `MartialArts1`，新模式称为 `MartialArts2`。我们现在可以使用以下 SQL 命令将数据从原始的两个表迁移到新表中。

```
insert into MartialArts2.Club
select Club.clubCode, clubName, cityname, ClubDans.nrPlayers, ClubKyus.nrPlayers
from MartialArts1.Club left outer join MartialArts1.ClubNrRankedPlayers as ClubDans
on Club.clubCode = ClubDans.clubCode
and ClubDans.rankType = 'dan'
left outer join MartialArts1.ClubNrRankedPlayers as ClubKyus
on Club.clubCode = ClubKyus.clubCode
and ClubKyus.rankType = 'kyu'
```

原始查询 Q1 现在可以重新表述以适配新数据库，如 Q2 所示。

```
Q2: select clubCode, clubName, nrDanGrades
from Club
```

即使在这个简单的例子中，你也可以看到编写数据迁移代码可能需要一些思考。在实践中，这可能比这困难得多。以下涵盖了数据重构过程大多数方面的练习，包含几个更具挑战性的数据迁移任务。该练习的答案（以及所有奇数编号问题的答案）可在线获取。
