
特定论域（UoD）的数据结构可以通过模式来定义。XML Schema 标准提供了一种定义 XML 文档的结构、内容和语义的方法。它取代了早期用于定义结构的文档类型定义（DTD）。可以针对模式验证 XML 文档，以确保其结构一致。与 SQL 一样，XML 定义了多种数据类型，尽管这些类型并不完全对应。SQL 规范（第 14 部分）定义了 XML Schema 与 SQL 数据类型之间的映射，但 XML Schema 是一个复杂的主题，我们将不会在本章中详细探讨。

大多数操作系统的目录结构提供了一个熟悉的层级示例。即使在图形界面中，我们也习惯了一种“文件夹”系统，它可以包含其他“文件夹”和称为“文件”的叶节点的组合。文件系统类比在此处特别相关，因为用于导航 XML 结构的 XPath/XQuery 表达式类似于用于在非基于图形用户界面（GUI）的环境中导航目录结构的文本命令。基本的层级概念如 [图 16.2](#Ch016_831-873_B9780443237904000207.xhtml#f0015) 所示。

我们将从节点 Q 开始导航，它为我们的路径表达式提供了“上下文”。节点 Q 可能位于我们所考虑的层级结构的顶部，在这种情况下，它可以代表我们整个 XML 文档。除了这种特殊情况外，我们总是可以从 Q 向上一级到达节点 P，即 Q 的 `parent`（父节点）。如果 Q 有 `siblings`（兄弟节点，即也具有父节点 P 的节点），我们可以横向导航。如果 Q 有 `children`（子节点），则可以向下导航。向上/横向/向下移动的某些组合可以将我们带到一个新节点。一旦到达那里，新选中的节点可以成为其他导航的上下文。

大多数情况下，我们关心的是 XML 元素之间的关系，因此，例如，我们可能想了解所有“包含在”元素 Q 中的元素（即节点 Q 的后代节点）。但我们可能也想了解所有具有特定属性的元素、与特定命名空间相关的所有元素，等等。在 XPath/XQuery 中，所有这些可能的维度被称为 `axes`（轴），这些语言提供了复杂的符号，用于精确定义沿各种轴组合进行导航。遗憾的是，完整的符号有点繁琐。幸运的是，存在涵盖主要可能性的简写符号，我们将重点关注这些简写形式。

在 XML 中，节点或“元素”通过一对命名标签（开始标签和结束标签）来标识。节点可以有零个或多个属性，这些属性列在开始标签中。每个开始标签必须在该标签的所有内容列出后最终被关闭。以下 XML 表达式显示了一个示例：

```
<movie movieNr=“1”> <title> Cosmology </title> </movie>
```

这里，我们有一个名为“movie”的标签，带有一个包含数据的属性 `movieNr`。它包含另一个名为 `title` 的标签，后者本身包含一些数据。结束标签重复标签名称，前面加上一个*斜杠*字符。可选地，不包含其他元素的元素可以仅用一个紧跟在任何属性后的斜杠字符来关闭，如下所示。

```
<movie movieNr=“1” />
```

关于选择属性还是元素内容作为数据位置的指导原则有点模糊。广义上讲，属性应该用于节点的内在属性，但这留有解释空间。可以肯定的是，以下表示在语法上与第一种同样有效。

```
<movie title=“Cosmology”> <movieNr> 1 </movieNr> </movie>
```

在许多情况下，找到通往相关节点或节点的路径就是从 XML 中提取相关数据所需的一切。所需路径可以使用 XPath 表达式指定。为了提供一些具体示例，我们将回到 [第 1 章](#Ch001_1-25_B9780443237904000062.xhtml) 中的 *Movies* 示例。在那里，我们看到了如何将报告的内容捕获为关系表。[清单 16.1](#Ch016_831-873_B9780443237904000207.xhtml#f0035) 显示了类似的信息（数据与 [第 1 章](#Ch001_1-25_B9780443237904000062.xhtml) 中的示例略有不同）。初始标签仅标识这是一个 XML 文档。该清单比 CSV 文件等效渲染冗长得多，但这是为了实现表示复杂数据结构所需的表达能力而必须付出的代价。

导航是相对于 XPath 序列中的给定节点进行的。基本导航符号类似于传统文件系统。一个*句点*或*全角句号*“ . ”表示“当前节点”，“ .. ”表示“当前节点的父节点”。一个不带进一步限定的*斜杠*或*实心斜杠*字符“ / ”表示“向下一级”；“ // ”表示向下任意级数。名称被视为指代元素，除非以“@”为前缀，在这种情况下它们指代属性。在路径的任何步骤中，可以在方括号中引入谓词。这将过滤结果节点，因此仅包含谓词为“真”的节点。[表 16.2](#Ch016_831-873_B9780443237904000207.xhtml#t0015) 显示了一些使用这些概念的典型表达式。
