[图 4.33](#Ch004_111-158_B9780443237904000232.xhtml#f0170) 中表的全外连接包含行 (a2, b2, ?) 和 (?, b4, c4)。外连接常用于概念层面和关系层面的查询中。由于 ORM 中断言的事实类型是基本的，因此它们的事实表不能包含空值。我们将外连接的进一步讨论推迟到 [第 10 章](#Ch010_401-479_B9780443237904000244.xhtml)。

第 1 行的信息可以口头表述为两个基本事实：

```
编号为‘001’的学生的学生姓名为‘Adams J’。编号为‘001’的学生在代码为‘11A’的班级中。
```

第一个事实关联一个实体和一个值。第二个事实是两个实体之间的关系。在该 UoD 中，学生由其学生编号标识。正如第 2 行和第 3 行所示，两个不同的学生可能拥有相同的学生姓名（例如，“Brown C”）。[图 4.35](#Ch004_111-158_B9780443237904000232.xhtml#f0180) 显示了一个填充了实例的模式图。

![图 4.35 表 4.2 的填充模式（草稿版）。](images/B9780443237904000232/f04-35-9780443237904.jpg)

[图 4.35](#Ch004_111-158_B9780443237904000232.xhtml#B-f0180) [表 4.2](#Ch004_111-158_B9780443237904000232.xhtml#t0015) 的填充模式（草稿版）。

我们约定所提供的实例是有代表性的。由此可知，每个学生最多有一个姓名，且每个学生最多在一个班级中。这些唯一性约束已在模式图上标记。然而，还有一个缺失的 UC。它是什么？

输出报告在 [表 4.3](#Ch004_111-158_B9780443237904000232.xhtml#t0020) 中重现，并在相关列上方标记了 UC。请注意，姓名和班级的组合是唯一的。假设这具有代表性。虽然学生的姓名在高中里不必唯一，但在该学生的班级内却是唯一的。虽然有两个名为“Brown C”的学生，但在班级 12B 中只能有一个叫这个名字的学生，在班级 11A 中也只能有一个叫这个名字的学生。

如果另一个名为“Brown C”的学生加入了这些班级中的一个，则至少需要修改其中一个姓名，以保持它们在该班级内的唯一性。例如，我们可以添加额外的首字母缩写或数字（例如，“Brown CT”、“Brown C2”）。

报告的每一行拆分为两个基本事实，一个用于姓名，一个用于班级。要在模式上指定姓名-班级 UC，我们需要两个事实类型。该 UC 所应用的角色框通过虚线连接到一个*带圈的唯一性条*，如 [图 4.36](#Ch004_111-158_B9780443237904000232.xhtml#f0185) 所示。

![图 4.36 已添加一个外部唯一性约束。](images/B9780443237904000232/f04-36-9780443237904.jpg)

[图 4.36](#Ch004_111-158_B9780443237904000232.xhtml#B-f0185) 已添加一个外部唯一性约束。

因为该 UC 涉及来自不同谓词的角色，所以它是*外部约束*或谓词间约束的一个例子。单个谓词上的约束是*内部*或谓词内约束。因此，UC 有两种：内部唯一性和外部唯一性。

在本例中，外部 UC 表明对于每个学生，学生姓名和班级的*组合*是唯一的。该约束口头表述为：“**给定任意**学生姓名**和**班级，**至多有一个**学生拥有**该**学生姓名**并**在**该**班级中”。例如，给定“Adams J”和“11A”，只有一个学生编号同时与两者共享行（“001”）。给定“Adams J”和“12B”，则没有学生编号同时与两者配对。

理解该约束的一个简单方法是：如果我们对两个事实表执行概念（内）*连接*操作，则生成的表在（姓名、班级）列对上具有 UC。请注意，当我们连接这两个事实表时，会得到原始报告中的表（[表 4.3](#Ch004_111-158_B9780443237904000232.xhtml#t0020)）。

外部 UC 等价于由连接路径形成的派生三元事实类型的第一个和最后一个角色上的内部 UC：学生姓名属于**那个**在班级中的学生。参见 [图 4.37](#Ch004_111-158_B9780443237904000232.xhtml#f0190)。对象类型 Student 是个人类型，因此我们倾向于使用人称代词“**谁**”而不是“**那个**”。

![图 4.37 派生连接事实类型上的等价约束（基础模型中非法）。](images/B9780443237904000232/f04-37-9780443237904.jpg)

[图 4.37](#Ch004_111-158_B9780443237904000232.xhtml#B-f0190) 派生连接事实类型上的等价约束（基础模型中非法）。

连接事实类型的中间角色具有简单 UC。这等价于两个二元事实类型上的简单 UC。虽然连接事实类型可以为了讨论目的而包含在模式图上，但它们在基础 ORM 模型中是非法的，因为它们是复合事实类型，而非基本事实类型。

正如稍后讨论的，三元事实类型上存在简单 UC 会使其不符合基本事实类型的资格。所以，不要觉得在正常建模中这样做是可以的。

假设我们向当前实例添加以下事实：学生‘004’的学生姓名为‘Adams J’；学生‘004’在班级‘11A’中。如果接受此更新，新的实例将如 [图 4.38](#Ch004_111-158_B9780443237904000232.xhtml#f0195)(a) 所示。为了测试你的理解，请在继续阅读前解释为什么这会违反外部 UC。

![图 4.38 此更新将违反外部唯一性约束。](images/B9780443237904000232/f04-38-9780443237904.jpg)

[图 4.38](#Ch004_111-158_B9780443237904000232.xhtml#B-f0195) 此更新将违反外部唯一性约束。

添加到每个表中的额外行为该约束提供了一个反例，因为对于“Adams J”和“11A”，有两个学生编号条目（001 和 004）与这些条目配对。这打破了学生姓名在给定班级内唯一的规则。在班级 11A 中，两个学生（001、004）拥有相同的姓名（“Adams J”）。

如果我们按学生编号连接这些表（虚线指示用于连接的匹配项），我们将得到 [图 4.38](#Ch004_111-158_B9780443237904000232.xhtml#f0195)(b) 中的三元表，该表明显违反了学生姓名和班级列上的等价复合 UC。

一般情况总结在 [图 4.39](#Ch004_111-158_B9780443237904000232.xhtml#f0200) 中，其中 *A*、*B* 和 *C* 为任意对象类型，*R* 和 *S* 为谓词。外部 UC 可以应用于来自引用类型的角色，而不仅仅是事实类型。这是复合引用方案的基础，将在后面的章节中讨论。
