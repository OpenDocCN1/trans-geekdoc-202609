
当没有混淆的可能时，对象项在列出种群时可以缩写为常量。基于此理解，在[图 5.2](#Ch005_159-209_B9780443237904000098.xhtml#f0015)中，`pop(r1) = {US, JP}`，`pop(r2) = {G, S, B}`，`pop(r3) = {1}`。角色种群用于确定*对象类型种群*。以我们当前的示例为例，如果数据库中引用的每个国家都必须扮演 `r1`，那么在第一个事件后，`pop(Country)` 从 `{ }` 变为 `{US, JP}`，而 `pop(CountryCode)` 从 `{ }` 变为 `{"US", "JP"}`。假设论域仅关于奥运会，实体类型 `Country` 是可能参加奥运会的所有国家的集合。

谓词出现在基本事实类型或引用类型（又称存在事实类型）中。引用类型通常缩写为带括号的引用模式。引用类型中的角色称为*引用角色*。基本事实类型中的角色称为“*事实角色*”。在一个完成的概念模式中，每个实体类型至少扮演一个引用角色，并且除非它被声明为独立（参见[第 6.3 节](#Ch006_211-271_B9780443237904000025.xhtml#s0020)），否则至少扮演一个事实角色。通常，*实体类型的种群等于其角色种群的并集*。除非实体类型是独立的，否则其种群是其事实角色种群的并集。

例如，[图 5.3](#Ch005_159-209_B9780443237904000098.xhtml#f0020) 中的已填充模式显示了截至 2020 年测量的某些国家的面积（以平方公里为单位）和二氧化碳排放量（占全球排放量的百分比）。`Country` 实体*类型*可能包含许多国家（例如从阿富汗到津巴布韦），但此数据库状态仅列出了四个国家。数据库中 `Country` 种群的每个实例都扮演角色 `r1`、`r2` 或两者兼有。因此，`Country` 当前的*种群*是 `r1` 列或 `r2` 列中引用的所有实例的集合。

![图 5.3 pop(Country) = pop(r1) ∪ pop(r2)。](images/B9780443237904000098/f05-03-9780443237904.jpg)

[图 5.3](#Ch005_159-209_B9780443237904000098.xhtml#B-f0020) `pop(Country) = pop(r1) ∪ pop(r2)`。

我们可以将其列出如下：

| `pop(Country)` | = `pop(r1) ∪ pop(r2)` |
| --- | --- |
| | = `{AU, FR, US} ∪ {AU, CN, US}` |
| | `= {AU, CN, FR, US}` |

这里，“∪”是集合并集的运算符。两个集合的并集是两个集合中所有元素的集合。例如，`{1,2} ∪ {2, 3, 4} = {1, 2, 3, 4}`。在上述情况下，澳大利亚和美国同时出现在两个角色种群中，而中国和法国仅出现在一个中。

## 5.2 强制角色与可选角色

考虑[表 5.1](#Ch005_159-209_B9780443237904000098.xhtml#t0010) 的输出报告。患者由患者编号标识。问号“?”表示*空值*，表明未记录实际值。例如，患者 002 可能有电话但未记录，或者他/她可能根本没有电话。不同患者可能有相同的姓名甚至相同的电话号码，因此表种群不具备显著性。

在设计过程的第 5 步中，每个角色被分类为强制或可选。**当且仅当对于数据库的所有状态，该角色必须由其对象类型种群的每个成员扮演时，该角色才是强制的**；否则，该角色是**可选的**。强制角色也称为*全角色*，因为它由其对象类型的全体种群扮演。

[图 5.4](#Ch005_159-209_B9780443237904000098.xhtml#f0025) 中的四个角色哪些是强制的，哪些是可选的？如果该图包含论域的所有事实类型，且其样本种群具有显著性，我们可以轻松确定哪些角色是强制的。

然而在实践中，我们大多使用子模式而非完整的或全局模式；且样本种群很少具有显著性。在这种情况下，我们应咨询领域专家，以确定相关信息是否必须为对象类型的所有实例记录（例如，我们是否必须记录每个患者的姓名？）。

考虑 `Patient` 扮演的两个事实角色。对于所示的数据库状态，这些角色的种群分别为 `{001,003}` 和 `{001,002,003}`。如果这些是 `Patient` 唯一的事实角色，则 `pop(Patient) = {001, 002, 003}`。拥有姓名的角色由所有记录在案的患者扮演，而拥有电话号码的角色仅由部分患者扮演。假设种群在这一方面具有显著性，则姓名角色是强制的，电话号码角色是可选的。

为了明确指示角色是强制的，我们在连接角色与其对象类型的线上添加一个**强制角色点**。该点可放置在角色线的任一端。在[图 5.5](#Ch005_159-209_B9780443237904000098.xhtml#f0030)(a) 中，该点放置在对象类型一端。这强化了约束的*全局*性质，因为它适用于对象类型的种群。如果我们向强制 `Patient` 角色的种群添加一个患者实例，则必须也将该实例包含在为 `Patient` 声明的每个其他强制角色的种群中。

![图 5.5 强制角色约束显示为角色线任一端的点。](images/B9780443237904000098/f05-05-9780443237904.jpg)

[图 5.5](#Ch005_159-209_B9780443237904000098.xhtml#B-f0030) 强制角色约束显示为角色线任一端的点。

从这个意义上说，强制角色约束的影响可能超出其谓词。相反，唯一性约束在本质上是*局部*的，仅约束其角色的种群，不影响其他谓词。

在[图 5.5](#Ch005_159-209_B9780443237904000098.xhtml#f0030)(b) 中，强制点放置在角色一端。当对象类型的角色线非常靠近以至于在对象类型一端添加点会导致不清晰哪个角色是预期时，这种方式最好。当对象类型在同一模式页面上显示大量角色时，可能会出现这种情况。

在[图 5.5](#Ch005_159-209_B9780443237904000098.xhtml#f0030) 中，顶部谓词的第一个角色是强制且唯一的。强制角色约束可以口语化为“**每个** Patient **至少有一个** PatientName”，或“**每个** Patient **有一些** PatientName”。唯一性约束口语化为“**每个** Patient **至多有一个** PatientName”。组合起来，这些约束口语化为“**每个** Patient **恰好有一个** PatientName”（即每个记录在案的患者有且仅有一个记录在案的姓名）。通常，*至少一个 + 至多一个 = 恰好一个*。

在模式中，*如果同一对象类型扮演两个或多个事实角色，则这些角色单独来看是可选的，除非标记为强制*。例如，在[图 5.5](#Ch005_159-209_B9780443237904000098.xhtml#f0030) 中，`Patient has PhoneNr` 的第一个角色是可选的。因此，我们可以向数据库种群添加患者，而无需为该患者添加电话号码。
