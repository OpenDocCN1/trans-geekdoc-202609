

## 历史与发展

Robert Meersman 增加了子类型，并与 Falkenberg 和 Nijssen 一起对 RIDL 查询语言做出了重大贡献。该方法更名为“aN Information Analysis Method”（NIAM），并在 [Verheijen and van Bekkum (1982)](#Ch003_59-110_B9780443237904000037.xhtml#bb1285) 的论文中进行了总结。在后来的岁月里，“NIAM” 这个首字母缩略词被赋予了不同的扩展含义，现在称为“natural language information analysis method”。开发了两种用于子类型的矩阵方法：一种（角色-角色矩阵）由 Dirk [Vermeir (1983)](#Ch003_59-110_B9780443237904000037.xhtml#bb1290) 开发，另一种由 Falkenberg 和其他人开发。

在 1980 年代，Falkenberg 和 Nijssen 共同致力于设计程序，并移师昆士兰大学，在那里该方法得到了进一步增强。Terry Halpin 在那里提供了该方法的首个完整形式化（Halpin 1989），包括模式等价证明，并做出了若干改进和扩展。1989 年，Nijssen 和 Halpin 合著了一本关于该方法的书。另一本早期的相关书籍由 [Wintraecken (1990)](#Ch003_59-110_B9780443237904000037.xhtml#bb1320) 编写。

在 1990 年代初期，Halpin 开发了 NIAM 的一个扩展版本，称为 Formal ORM (FORM)，最初在 ServerWare 的 InfoDesigner 建模工具中得到支持。该产品后来演变为 InfoModeler（在 Asymetrix Corp. 然后是 InfoModelers Inc.），接着是 VisioModeler（在 Visio Corp.）。这项 ORM 技术随后被重写以在 Visio 引擎上运行，首次出现在 Visio Enterprise 中。Anthony Bloesch 和 Terry Halpin 设计了一种相关的查询语言 ConQuer（[Bloesch and Halpin, 1997](#Ch003_59-110_B9780443237904000037.xhtml#bb0115)），在 ActiveQuery 工具中得到支持。Microsoft 于 2000 年收购了 Visio，并修改其 ORM 解决方案用于 Visual Studio。

许多研究人员为 ORM 方法做出了贡献，完整的历史将包括此处未列出的许多人。如今，该方法存在各种版本，但都遵循基本的对象-角色框架。尽管大多数 ORM 支持者青睐 `n`-ary 关系，但一些人更喜欢二元关系建模（BRM），例如 [Shoval and Shreiber (1993)](#Ch003_59-110_B9780443237904000037.xhtml#bb1165)。[Habrias (1993)](#Ch003_59-110_B9780443237904000037.xhtml#bb0525) 开发了一个面向对象的版本，称为规范化面向对象方法（MOON）。谓词集模型（PSM）主要由 Arthur ter Hofstede、Erik Proper 和 Theo van der Weide 开发（[ter Hofstede et al., 1993](#Ch003_59-110_B9780443237904000037.xhtml#bb1240)），并包含复杂对象构造器。[De Troyer and Meersman (1995)](#Ch003_59-110_B9780443237904000037.xhtml#bb0335) 开发了另一个带有构造器的版本，称为自然对象关系模型（NORM）。Harm van der Lek 和其他人（[Bakema et al., 1994](#Ch003_59-110_B9780443237904000037.xhtml#bb0030)）允许将实体类型视为对象化谓词，从而产生完全面向通信的信息建模（FCO-IM）。

独立于主流 ORM 运动，Dave Embley 和其他人认为在概念建模中使用属性是个坏主意，因此他们开发了面向对象系统分析（OSA），其中包含一个无属性的“对象-关系模型”组件，这与 ORM 有很多共同点（[Embley et al., 1992](#Ch003_59-110_B9780443237904000037.xhtml#bb0375)；[Embley, 1998](#Ch003_59-110_B9780443237904000037.xhtml#bb0370)）。对象管理组织于 2007 年采用的业务词汇与业务规则语义（SBVR）方法是面向事实家族的最新成员，与 ORM 2 有很多共同之处，支持道义规则以及真理规则。撰写时最新版本的 SBVR 规范可在 [www.omg.org/spec/SBVR/1.5](http://www.omg.org/spec/SBVR/1.5) 访问。

## 软件工具

各种 `software tools` 已被开发以支持面向事实方法的不同流派。Nijssen、Meersman 和其他人在 Control Data 开发的最早工具（例如 IAST、RIDL*）不再可用。Bloesch、Halpin 和其他人开发了 VisioModeler（已停止但可免费获取）、ActiveQuery（目前不可用）以及用于 Microsoft Visio for Enterprise Architects 的 ORM 建模解决方案（[Halpin et al., 2003](#Ch003_59-110_B9780443237904000037.xhtml#bb0790)）。FCO-IM 版本由商业工具 CaseTalk 支持（[*www.casetalk.com*](http://www.casetalk.com)）。Nijssen 在 PNA 的小组开发了基于 CogNIAM（认知增强 NIAM）的工具，包括各种 iKnow 工具（[www.pna-group.com](http://www.pna-group.com)）。Meersman 和其他人开发了用于指定本体的学术 ORM 工具，如 Dogma Modeler 和 T-Lex（[Trog et al., 2006](#Ch003_59-110_B9780443237904000037.xhtml#bb1265)）。

NORMA（[Curland and Halpin, 2010](#Ch003_59-110_B9780443237904000037.xhtml#bb0265)）是一个开源插件，用于 Microsoft Visual Studio，为 ORM 2（下一代 ORM）提供深度支持，可从 [https://ormsolutions.com/](https://ormsolutions.com/) 或 [https://sourceforge.net/projects/orm](https://sourceforge.net/projects/orm) 下载。有关安装和使用 NORMA 的详细信息，请参阅 [www.orm.net/resources](http://www.orm.net/resources)。

Clifford Heath 开发了 ActiveFacts（[http://dataconstellation.com/ActiveFacts/](http://dataconstellation.com/ActiveFacts/)），另一套旨在支持 ORM 2 的工具套件。

Victor Morgante（[https://victormorgante.medium.com/](https://victormorgante.medium.com/)）是多种工具的主要开发者，如 Boston 和 FactEngine，它们包含对 ORM 2 和其他建模方法的支持（[https://www.factengine.ai/](https://www.factengine.ai/)）。
