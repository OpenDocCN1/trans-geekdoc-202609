
*行或列的顺序无关紧要*。例如，[表 2.1](#Ch002_27-57_B9780443237904000128.xhtml#t0010) 重新排列了 Employee 表的列和行，但其含义保持不变（仍然包含相同的六个事实）。行的顺序无关紧要，因为每个事实完全包含在单个行中。列的顺序无关紧要的原因是每个列都有名称，因此我们知道其值的含义。从某种意义上说，列是“按其名称排序”，而不是按其位置。

尽管在逻辑层面行和列的顺序无关紧要，但在物理层面顺序确实存在，在为高效访问调优数据库时需要考虑这一点。

查询结果也是表，但它们是未命名的，并且可能包含重复行。在构建查询时，您可以指定数据的显示顺序，而不管用于在基表中存储数据的实际顺序如何。

我们可以将基表视为一组行，将每一行视为数据值的序列或*元组*（更严格地说，是属性-值对的元组）。从这个意义上说，表是一组元组。因为数学关系被定义为一组元组，所以每个表都是一个*关系*——因此得名“关系型数据库”。

我们已经看到，概念事实在关系模式中被分组到表中。那*约束*呢？关系系统通常只提供少数内置的声明性约束类型。列可以被指定为其表的*强制性*或可选列。在我们的示例中，Employee 表的所有列都是强制性的（每个条目必须是实际值，不能为 null）。这在一定程度上捕捉了这样一些约束：每个员工由 `empNr` 标识，至少有一个姓名，且至少属于一种性别。我们还要求 `Speaks` 表中列出的每个员工也必须列在 `Employee` 表中（这是一个*子集*或*参照完整性*约束）。

为了将每个员工限制为最多一个姓名和最多一种性别，`Employee` 表 `empNr` 列中的条目必须是*唯一*的（即不允许重复）。这是通过将 `empNr` 声明为 `Employee` 表的*主键*来强制执行的。

*键*是不允许重复的最小列组合。在关系模型中，每个表都有一个主键，它提供了访问其行的主要方式。最后，对性别值的约束可以通过简单的*检查子句*来强制执行。

关系模式在 [图 2.7](#Ch002_27-57_B9780443237904000128.xhtml#f0040) 中紧凑地列出。列名放在表名后的圆括号中，*键带有下划线*。在这种表示法中，默认情况下假定列对其表是强制性的。虚线箭头表示前面提到的子集约束。性别代码的可能值放在大括号（花括号）中。为简单起见，省略了域。这种表示法是逻辑层面的，而非物理层面。声明表和约束的具体语法取决于所使用的关系数据库语言（通常是结构化查询语言 SQL 的一种方言）。

声明模式的过程通常称为数据定义，专门为此任务设计的语言组件称为*数据定义语言*（DDL）。我们的示例足够简单，关系模式可以在标准 SQL 的 DDL 组件中完全指定。然而，通常有些约束必须单独编码。

关系模式可能包含表定义、约束和派生规则。概念模式中的大多数派生规则可以通过在关系 DBMS 中定义视图（虚拟表）或计算列，或通过编写触发器或存储过程来指定。如果某类查询常用且需要派生，则会在概念模式的派生规则部分显式包含它。相比之下，临时查询则通过在查询语言本身中包含派生函数和运算符来处理，以便用户可以在查询构建本身中表达所需的派生规则。

在 SQL 等关系数据库语言中，表达许多数学和逻辑派生规则相当容易（例如，平均值，或从父母关系派生的祖父母关系）。一些难以在 SQL 中表达的派生规则可以用其他语言轻松表达。例如，以下 Prolog 规则以父母关系为基础递归地定义了祖先关系：

```
X is an ancestor of Y if X is a parent of Y. X is an ancestor of Y if X is a parent of Z and Z is an ancestor of Y.
```

SQL 标准支持递归查询，但商业 SQL 产品对该特性的支持程度各异。不直接支持递归的商业 SQL 产品通常支持从 SQL 调用其他语言（如 C# 或 Prolog）以执行所需的递归或其他期望任务。

Prolog 等语言用于某些 AI 应用。过去，AI 系统倾向于处理大量复杂事实类型的小规模总体，而数据库系统处理少量简单事实类型的大规模总体。下一代技术的目标之一是将强大的推理能力与高效的数据库管理相结合。

一旦定义了模式，就可以开始*数据操作*。最初为空的表将填充数据（即*插入*行）。随后可以*删除*或*修改*行。如果一行的一个或多个值发生变化，则该行被修改：在 SQL 的上下文中这有时称为“更新”，但我们笼统地使用“更新”一词来包含插入、删除和修改操作。这三种操作统称为*数据维护*。如果约束指定得当，当发生维护操作时，DBMS 会自动强制执行它们。

从概念上讲，关系型 DBMS 的行修改操作只是添加或删除基本事实。例如，将 [图 2.6](#Ch002_27-57_B9780443237904000128.xhtml#f0035) 中 `Employee` 表第三行的“Adams, Ann”改为“Smith, Ann”，只是删除了员工 006 名为“Adams, Ann”这一事实，并添加了员工 006 名为“Smith, Ann”这一事实。当然，在外部层面，用户只需修改表单的屏幕版本（如 [图 2.5](#Ch002_27-57_B9780443237904000128.xhtml#f0030) 所示）或表行（如 [图 2.6](#Ch002_27-57_B9780443237904000128.xhtml#f0035) 所示）中的值。

数据操作的另一个方面是*数据检索*。这通常涉及三个步骤：用户请求信息；系统搜索数据库和/或模式以定位相关信息并利用它获得所需结果；然后系统输出该结果。第二阶段可能涉及对数据进行排序和/或派生结果（例如平均值）。与维护操作不同，检索操作不会改变数据库。

*数据呈现*是指在屏幕上显示信息（屏幕显示）或生成格式化打印输出（报表编写）的特殊技术。我们笼统地使用“*输出报表*”一词来包括屏幕报表和硬拷贝报表。
