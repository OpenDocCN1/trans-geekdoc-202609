
# 高级建模主题

本章探讨若干高级建模主题，并假设读者熟悉对象角色建模（`ORM`）、Barker 实体关系（`ER`）建模以及统一建模语言（`UML`）类图的基础知识。虽然主要关注点在于 `ORM`，但也会对其他方法给予一定关注。即使 `ER` 和 `UML` 无法为所讨论的特性提供内置支持，许多思想至少可作为扩展应用于这些方法中。

## 连接约束

本节考察*连接约束*，首先考虑单一连接路径上的连接约束，然后是涉及连接的集合比较约束。虽然这些约束的考量实际上属于*概念模式设计过程（CSDP）*步骤 7 的一部分，但由于其高级性质，我们将其详细讨论推迟至今。

概念连接的概念在[第 4.4 节](#Ch004_111-158_B9780443237904000232.xhtml#s0035)中引入，并在[第 9.7 节](#Ch009_347-399_B9780443237904000013.xhtml#s0040)中进一步阐述。通过跨两个或多个角色的*概念内连接*，同一对象扮演所有这些角色。在[图 10.1](#Ch010_401-479_B9780443237904000244.xhtml#f0010)(a)中，存在一条单一连接路径：Building contains Room **that** has RoomNr。从语言学角度来看，该路径表达式中的代词“**that**”声明了该连接，表明是同一个房间在扮演这两个连接角色（此处为讨论目的而着色）。

![图 10.1 (a) ORM、(b) Barker ER 和 (c) UML 中的简单概念连接。](images/B9780443237904000244/f10-01-9780443237904.jpg)

[图 10.1](#Ch010_401-479_B9780443237904000244.xhtml#B-f0010) (a) ORM、(b) Barker ER 和 (c) UML 中的简单概念连接。

外部唯一性约束声明了每个建筑、房间号组合最多适用于一个房间。这等价于在实例化该概念连接路径的（建筑、房间、房间号）元组集合上，施加一个针对建筑、房间号的内部唯一性约束。

[图 10.1](#Ch010_401-479_B9780443237904000244.xhtml#f0010)(b) 以 Barker ER 符号展示了相同的模式。外部唯一性约束通过结合 "`#`" 和 "`|`" 来捕获。[图 10.1](#Ch010_401-479_B9780443237904000244.xhtml#f0010)(c) 展示了 UML 版本，外部唯一性约束通过结合两个 `{id}` 标记来捕获。

在房间示例中，参与概念连接的两个角色对于连接对象类型（Room）均是强制的。这确保了概念连接为内连接。然而，如果参与概念连接的一个或多个角色是可选的，则使用外部唯一性约束需要特别小心。例如，考虑[图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#f0015) 中所示的三个 ORM 模式。

![图 10.2 可选角色可能涉及内连接 (a) 或外连接 (b)、(c)。](images/B9780443237904000244/f10-02-9780443237904.jpg)

[图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#B-f0015) 可选角色可能涉及内连接 (a) 或外连接 (b)、(c)。

[图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#f0015)(a) 中的 ORM 模式是 ORM 元模式的一个片段。`ORM` 要求每个谓词至少有一种读法，但角色是否被赋予名称则是可选的。在图中，`RoleName` 扮演的角色被命名为 "name"，但其他角色未命名。外部唯一性约束表明，角色名称在给定谓词内是唯一的。一个谓词可能有许多未命名的角色，但如果一个角色被命名，它就可以通过其名称与其谓词的组合来识别。

这种情况要求对外部唯一性约束底层连接路径采用*内连接解释*。让我们将关联 `Role is in Predicate` 的谓词标识为 `P1`，其左、右角色分别标识为 `r1` 和 `r2`。同样，将关联 `Role has RoleName` 的谓词标识为 `P2`，其左、右角色分别标识为 `r3` 和 `r4`。这两个事实类型的内连接产生一个复合三元事实类型，等价于以下关系表模式。

```
Role( roleId, predicateId, [roleName] )       r4     P2      name
```

此关系符号下划线标识唯一性约束；若存在多个，主键以双下划线标识。可选列用方括号标记。外部唯一性约束表现为复合内部唯一性约束。因为我们仅要求角色在被命名时才在谓词内拥有唯一名称，所以 [图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#f0015)(a) 中 `Role` 角色之间的概念连接是内连接，从而产生如图所示的单行填充。

使用 "`?`" 表示空值，外连接结果将包含四个元组：(`r1`, `P1`, `?`)、(`r2`, `P1`, `?`)、(`r3`, `P2`, `?`) 和 (`r4`, `P2`, `name`)。前两个元组将违反复合唯一性约束，因此不应在此示例中使用外连接语义。

[图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#f0015)(b) 和 (c) 中的外部唯一性约束在唯一性横杠上标有一个*内部的 "o"*。这表明该外部唯一性约束具有*外连接语义*，并附带一个条件：*外连接产生的空值被视为实际值*。

因此，每门课程恰好可由以下模式之一引用：课程标题与其院系的组合（课程由某院系开设）；或仅其课程标题（课程不由任何院系开设，例如由客座讲师开设的课程）。

此类外部唯一性约束用两句话表达，一句针对内连接语义，另一句针对外连接的额外语义。[图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#f0015)(b) 中的外部唯一性约束表达如下：

```
对于每个 CourseTitle 和 Department，至多有一个 Course 拥有该 CourseTitle 并由该 Department 开设。
对于每个 CourseTitle，至多有一个 Course 拥有该 CourseTitle 且不由任何 Department 开设。
```

考虑一个包含三门课程 `C1`、`C2` 和 `C3` 的示例填充，它们拥有相同的标题，一门由物理系开设，一门由数学系开设，一门不由任何院系开设。标题和院系事实类型的连接产生一个复合三元事实类型，等价于以下关系表模式。外部唯一性约束表现为跨越 courseTitle 和 departmentCode 的内部唯一性约束。

*   ```
    Course( courseCode, courseTitle, [departmentCode] )
    ```

*   ```
                              C1                            Mechanics            PY
    ```

*   ```
                              C2                            Mechanics            MA
    ```

*   ```
                              C3                            Mechanics            ?
    ```

*   ```
    C4 Mechanics            ?                        - - 违反约束
    ```

第四行（`C4`、`Mechanics`、`?`）被拒绝，因为在第 3 行存在的情况下，它违反了无院系课程必须拥有不同标题的约束。为确定约束满足情况，第 3 行和第 4 行上的空值被视为普通值，因此被等同对待。这实际上应用了*外连接语义*。

即使离散标识方案是识别课程的唯一手段，外连接语义也可能适用，如[图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#f0015)(c) 所示。

仅当该实体类型在受约束关系中承载的共角色为强制时，具有内连接语义的外部约束才可用作实体类型的首选标识方案，如[图 10.2](#Ch010_401-479_B9780443237904000244.xhtml#f0015)(a) 所示。
