
尽管硬件成本的下降使得最小化存储空间的重要性降低了，但在数据量非常大的情况下，存储空间仍可能成为重要因素。某些 NoSQL 方法提供了压缩数据和以高效方式存储稀疏数据的途径，既可减少存储空间，又可提高性能。然而，这必须权衡因缺乏规范化而不可避免产生的重复数据所需的额外存储空间。

处理大型数据库也引发了性能问题。这始终是任何类型数据库的关注点，但一种在小型数据库中可能提供可接受性能的方法，在大型系统中可能完全不可接受。在分布式系统中横向扩展的需求也为提高性能提供了机会。例如，通过将一定比例的查询导向持有相同数据副本的其他服务器，可以减轻某台服务器的负载。

在关系型系统中，为提高特定类型查询的性能而对数据库进行反规范化是相当常见的，主要是为了避免表间连接的性能损耗。在大多数 NoSQL 系统中，这是一项标准功能，尽管称其结构为“反规范化”具有误导性，因为它最初可能从未经过规范化。

当然，了解预期流量对于最大化性能至关重要，特别是读取数据库与写入数据库的相对频率。NoSQL 系统通常面向读取比例大但写入较少的场景。数据库记录可能通过某种形式的批量加载相对静态的数据来录入。这也缓解了一致性问题：如果没有写入，数据库就不可能变得不一致！

NoSQL 数据库声称的另一个效率优势是系统管理的简化（及成本降低）。这可能归因于各种管理任务的内置自动化，而这些任务传统上需要专门的专业知识和复杂的手动程序。示例包括自动分片、数据分发和复制、更简便的部署以及更简便的系统配置。

敏捷开发方法论在系统开发的各个领域都已流行开来。它们承诺快速交付初始可工作系统，能够在开发过程中及时响应变更，并通过尽早识别问题来降低风险。

一些 NoSQL 产品将数据库模式定义为繁重的开销，并将无模式宣传为主要的敏捷性优势。通常引用的例子是向现有数据库临时添加新数据元素。然而，这并不像看起来那样独特。使用以下命令扩展关系型数据库也很简单：

*   `create table MyNewTable …`
*   
```
alter table MyOldTable add myNewColumn …
```

当我们考虑删除或修改现有结构时，情况会更加困难。其影响取决于数据库是旨在支持单个应用程序（如移动电话应用），还是多个应用程序（有时称为集成数据库）。

在应用数据库中，应用程序开发人员和数据库开发人员通常是同一个人。这使得应用程序的变更易于体现为数据库结构的相应变更，反之亦然。然而，对于集成数据库，情况可能没那么简单，因为为适应某个应用程序而进行的数据库变更可能要求对其他应用程序进行变更。如果没有某种模式，管理数据库完整性就会变得非常困难。缺乏对数据结构的权威参考也会使通用应用程序开发变得不必要地困难且容易出错。

NoSQL 数据库通常以直接匹配其外部用法的形式存储数据，例如使用业务文档的结构。这通常以 [第 16 章](#Ch016_831-873_B9780443237904000207.xhtml) 中描述的交换格式相同的方式编码，`JSON` 是常见的选择。面向对象的应用程序代码与关系型数据库之间的接口通常通过某种对象-关系映射层来实现，而在某些 NoSQL 系统中，可以消除这种所谓的“阻抗失配”。

关系表的定义要求为每一列分配特定的数据类型。NoSQL 数据库常用于涉及非结构化或临时数据，或数据变异性高的情况，因此动态类型可能更可取。

### NoSQL 数据库的潜在缺点

NoSQL 数据库因其在特定用例下的灵活性和可扩展性而广受欢迎。然而，它们也有一些需要考虑的缺点。以下是与 NoSQL 数据库相关的一些常见缺点：

*   **缺乏标准化的查询语言**：与使用 `SQL` 作为标准化查询语言的关系型数据库不同，每个 NoSQL 数据库都有其自己独特的查询语言或应用程序编程接口（`API`）。这使得在不同 NoSQL 数据库之间切换或将其与现有系统集成变得困难。缺乏标准化导致用户社区比 `SQL` 数据库小，这可能使得寻找支持和资源更具挑战性。

*   **数据重复与反规范化**：NoSQL 数据库通常对数据进行反规范化以提高性能并实现水平可扩展性。这意味着数据可能跨多个记录或集合重复，导致存储需求增加。更重要的是，跨反规范化结构维护数据一致性可能涉及额外的复杂性。

*   **缺乏数据完整性约束**：与通过主键、外键和唯一索引等约束来强制数据完整性的关系型数据库不同，NoSQL 数据库通常缺乏确保数据一致性和强制数据实体间关系的内置机制。这使得开发人员负责在应用层面处理数据完整性。

*   **工具和生态系统不够成熟**：尽管 NoSQL 数据库已存在一段时间，但与关系型数据库相比，它们通常拥有不那么成熟的工具和生态系统。这可能导致社区支持较小、开发框架有限以及第三方集成较少。

*   **学习曲线与开发人员专业知识**：使用 NoSQL 数据库可能要求开发人员学习新概念、查询语言和数据建模技术。这会增加学习曲线和对专业技能的需求，尤其是在从关系型数据库环境迁移时。

*   **有限的事务一致性保证**：一些 NoSQL 数据库遵循 `CAP` 定理，牺牲强一致性保证以换取高可用性和分区容错性。这意味着在某些故障场景下，所做的权衡可能导致最终一致性或数据陈旧。由于某些 NoSQL 数据库使用最终一致性模型，也存在数据不一致的更高风险。
