

# 用户界面设计原则

一般来说，用户界面应该*易于学习*且*易于使用*。为实现这一目标，界面应具备一致性、简洁性、结构化、高效性，并能适应用户。下面我们逐一探讨这些原则。

## 一致性

界面的*一致性*意味着所有组件在显示格式和操作方面均采用相同的基本约定。这有助于正向迁移（学会使用一个屏幕有助于使用其他屏幕），并避免负向迁移。一致性可在不同层面实现，例如单个屏幕内部、应用程序内部、同一公司开发的不同应用程序之间，以及与外部标准的一致性。例如，如今许多 Windows 应用程序的开发均遵循微软的用户界面指南。

## 简洁性

界面的*简洁性*意味着其使用直观，用户付出的精力最少。每个屏幕应提供适量的相关信息（例如，限制一次显示的菜单选项数量）。不要让屏幕显得杂乱。为允许从同一屏幕直接执行许多操作，应从永久屏幕显示中移除除主要选项外的所有选项，允许用户根据需要切换额外选项的显示。例如，使用下拉菜单、弹出窗口（如用于查找代码）和状态栏帮助（及弹出式详细帮助）。为便于在屏幕内部及屏幕之间导航，可考虑使用方向键进行移动，并允许窗口和菜单以层叠或平铺方式排列。

## 高效性

界面的*高效性*意味着选项可被快速且直观地选择。*图形用户界面*（*GUI*）提供了更直观的操作方式，尤其是在涉及图形或复杂布局时；此时，“所见即所得”（WYSIWYG）至关重要。不过，基于按键的快捷方式（如热键）有时更快，应为经验丰富的用户提供。

菜单设计对高效性有重大影响。菜单形式多样（全屏、下拉、弹出、环形、按钮栏等）。它们提供了应用程序绝大多数（甚至全部）操作。同一菜单上的选项应在语义上相关。

菜单或屏幕之间的导航需要规划（状态图在此有帮助），特别是对于使用超链接从一处导航到另一处的基于 Web 的应用程序。[图 18.18](#Ch018_935-1005_B9780443237904000104.xhtml#f0095) 展示了一些导航模式。超链接访问通常是循环的。

此外，还应遵守以下原则：

- 按使用频率递减的顺序排列菜单选项。
- 变化颜色和字体，但切勿过度。
- 对于选项，使用直观的图标或简洁明了的文字描述，文字描述多为小写。
- 允许通过鼠标点击或热键选择选项，并支持撤销操作。

## 适应性

按如下方式使界面*适应*用户：

- 仅显示与用户相关的内容。
- 为普通用户提供简单流程，为经验丰富的用户提供快捷方式。
- 允许用户根据自己的喜好配置环境。
- 提供分级的上下文敏感帮助：状态栏上的简短消息，弹出窗口中的详细帮助。
- 尽早捕获错误，并给出简短和详细的错误消息。
- 提供在线教程、用户手册、技术支持和培训课程。

如果你使用某些觉得特别直观的软件包，请仔细观察其界面设计，看看能否将其优点应用到你自己的设计中（前提是不侵犯版权！）。一旦开发出原型界面，让典型用户测试，并利用他们的反馈进行润色。

以上快速浏览了几个主题，每个主题本身都足以写成一本书。确实，有许多专著专门论述界面设计；针对建模过程存在许多改进方法，包括一些非常技术性的方法，试图将这些模型与数据模型正式集成。章节注释中引用了一些这方面的有趣工作。对于项目管理（如甘特图和 PERT 图）、测试、性能度量、文档和版本控制等相关任务，也有各种常用的方法和工具。

# 18.6 本体与语义网

从词源学上讲，“本体论”一词意味着对存在的研究。在哲学中，本体论是形而上学的一个分支，关注存在的基本性质，探讨诸如“非物质事物存在吗？”、“事物在变化时是否保持与自身同一？”等深刻问题。信息学界后来采用了“本体”这一术语，通常用其指代关于某个业务领域的概念模型，该模型通过遵循某组标准构造，促进该领域信息的共享。

随着互联网的兴起，数百万文档现可通过万维网轻松访问。2001 年，为简化不同 Web 文档中信息的共享或组合，互联网创始人蒂姆·伯纳斯-李爵士提出了*语义网*的新愿景，作为当前 Web 的延伸，“在其中信息被赋予明确定义的含义，从而更好地使计算机和人能够协同工作”([Berners-Lee 等, 2001](#Ch018_935-1005_B9780443237904000104.xhtml#bb0095))。主要思想是为文档添加全局标识符和结构（例如使用统一资源标识符和嵌入式标签），以一种自动化代理可访问的方式揭示待共享内容的底层语义。

1999 年，万维网联盟 (W3C) 发布了*资源描述框架* (RDF) 语言的第一个版本，作为构建在 XML 之上的标准，用于捕获 Web 资源的元数据（例如，谁编写了某个 Web 文档）。美国国防高级研究计划局 (DARPA) 通过标记标签为语言添加自动可访问含义的其他工作，产生了 DARPA 代理标记语言 (DAML)。怀着类似目标，欧盟 (EU) 的研究人员开发了本体推理层 (OIL)。2001 年，美国和欧盟的联合工作将 OIL 的许多概念合并到 DAML 中，形成了 DAML+OIL 语言，并于 2002 年底提交给 W3C。

2004 年，W3C 采纳了*RDF 模式* (RDFS)，它将 RDF 扩展为一种简单的本体语言，并推荐了*Web 本体语言* (OWL)，该语言融合了 DAML+OIL 和 RDFS 的许多方面，具有基于描述逻辑的更清晰的形式语义，现已成为在语义网上开发本体的最流行语言。[图 18.19](#Ch018_935-1005_B9780443237904000104.xhtml#f0100) 总结了各层之间的依赖关系，上层依赖于下层。

## RDF 和 RDFS

RDF 模型本质上是有向图，其中每个节点要么是资源，要么是字面值，每条有向弧表示节点之间的二元关系。资源基本上是一个实体实例或一个逻辑谓词。
