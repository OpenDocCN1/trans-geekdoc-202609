
使用这种表示法，[图 6.31](#Ch006_211-271_B9780443237904000025.xhtml#f0160)(b) 的欧拉图中所示的复杂子类型模式可以建模为 [图 6.33](#Ch006_211-271_B9780443237904000025.xhtml#f0170) 所示。此处，`A` 是 `B`、`C` 和 `D` 的 `公共超类型`，而 `E` 是 `C` 和 `D` 的 `公共子类型`。一般来说，公共超类型至少是其子类型的并集；如果它是其子类型的并集，则称其子类型 `穷尽` 它。在我们的例子中，`B`、`C` 和 `D` 不穷尽 `A`。请注意，[图 6.33](#Ch006_211-271_B9780443237904000025.xhtml#f0170)(a) 仅描绘了子类型连接。

![图 6.33 这是对图 6.31b 中子类型连接的另一种建模方式。](images/B9780443237904000025/f06-33-9780443237904.jpg)

[图 6.33](#Ch006_211-271_B9780443237904000025.xhtml#B-f0170) 这是对[图 6.31b](#Ch006_211-271_B9780443237904000025.xhtml#f0160)中子类型连接的另一种建模方式。

[图 6.31](#Ch006_211-271_B9780443237904000025.xhtml#f0160)(b) 包含额外信息：`B` 与 `C` 重叠，`C` 与 `D` 重叠，而 `B` 和 `D` 互斥。因此，如果使用子类型箭头表示法，必须用其他某种方式来传达子类型是否互斥。在 ORM 中实现这一点的一种方法是通过虚线将 `排除` 符号“⨂”附加到相关的子类型链接上。

没有排除符号表示这些类型的总体可能重叠。有了这个附加符号，[图 6.33](#Ch006_211-271_B9780443237904000025.xhtml#f0170)(b) 现在传达了[图 6.31](#Ch006_211-271_B9780443237904000025.xhtml#f0160)(b)中欧拉图的排除/重叠信息。

要表明两个或多个子类型对其超类型是 `穷尽` 的（即它们的并集等于该超类型），需用虚线将 `包含性或` 约束符号“⨀”连接到相关的子类型链接上，如 [图 6.34](#Ch006_211-271_B9780443237904000025.xhtml#f0175)(b) 所示。此约束既适用于总体也适用于类型。超类型总体中的每个实例必须出现在至少一个子类型的总体中。

![图 6.34 B 和 C 互斥 (a)、穷尽 (b) 或两者兼具 (c)。](images/B9780443237904000025/f06-34-9780443237904.jpg)

[图 6.34](#Ch006_211-271_B9780443237904000025.xhtml#B-f0175) `B` 和 `C` 互斥 (a)、穷尽 (b) 或两者兼具 (c)。

如果我们结合这两个约束，就会得到一个 `异或` 约束，表明超类型被 `划分` 为其子类型，如 [图 6.34](#Ch006_211-271_B9780443237904000025.xhtml#f0175)(c) 所示。

隐含地，每个子类型箭头下面都有一个派生的、实例级的 1:1 二元关联“is/is”。子类型排除约束和穷尽约束分别对应于超类型在这些关联中所扮演角色上的排除约束和包含性或（析取性强制）约束——因此选择这些符号来表示这些约束。

从这个角度来看，[图 6.34](#Ch006_211-271_B9780443237904000025.xhtml#f0175) 中的约束可以分别口头化为：**没有** `A` **同时** 是 `B` **和** `C`；**每个** `A` **是某个** `B` **或** `C`；**每个** `A` **恰好是** `B` **或** `C` **之一**。

子类型之间可能重叠，特别是当它们基于不同的分类方案时。例如，在[图 6.35](#Ch006_211-271_B9780443237904000025.xhtml#f0180)中，子类型 Australian 和 Female 重叠。因为重叠的子类型拥有共同元素，所以可以从它们交集中的一个或多个元素形成一个公共子类型。例如，子类型 FemaleAustralian 既是 Australian 的子类型，也是 Female 的子类型。

![图 6.35 间接子类型连接是隐含的，因此应省略。](images/B9780443237904000025/f06-35-9780443237904.jpg)

[图 6.35](#Ch006_211-271_B9780443237904000025.xhtml#B-f0180) 间接子类型连接是隐含的，因此应省略。

子类型关系具有 `传递性`：如果 `A` 是 `B` 的子类型，且 `B` 是 `C` 的子类型，则 `A` 是 `C` 的子类型。在这种情况下，称 `A` 是 `C` 的 `间接子类型`。例如在[图 6.35](#Ch006_211-271_B9780443237904000025.xhtml#f0180)中，FemaleAustralian 是 Australian 的直接子类型，而 Australian 是 Person 的直接子类型。因此，FemaleAustralian 是 Person 的间接子类型。为了说明目的，该间接链接在图中用星号标记以显示其派生性质。然而，为了避免混乱，间接子类型链接应从图中省略，因为它们是传递隐含的。

如果一个子类型有两个或更多直接超类型，这称为 `多重继承`。例如，在[图 6.35](#Ch006_211-271_B9780443237904000025.xhtml#f0180)中，FemaleAustralian 同时继承自 Australian 和 FemalePerson。一般来说，一个子类型至多是其超类型的交集。如果一个子类型只有一个直接超类型，这称为 `单一继承`。

一个超类型可以有多个直接子类型，一个子类型也可以有多个直接超类型，因此一般来说我们得到的是一个 `子类型图` 而不是树。超类型和子类型被称为图的 `节点`。因为箭头提供了方向，所以我们得到的是一个有向图。

因为没有类型可以是其自身的真子类型，所以不允许存在任何环或循环，无论循环的长度如何（[图 6.36](#Ch006_211-271_B9780443237904000025.xhtml#f0185) 显示了两个非法循环）。因此，任何类型-子类型关系模式都形成一个 `有向无环图`。

![图 6.36 子类型图中不允许有环。](images/B9780443237904000025/f06-36-9780443237904.jpg)

[图 6.36](#Ch006_211-271_B9780443237904000025.xhtml#B-f0185) 子类型图中不允许有环。

在模式中，不作为任何其他实体类型的真子类型的实体类型被称为该模式的 `原始实体类型`。例如在[图 6.30](#Ch006_211-271_B9780443237904000025.xhtml#f0155)中，Person、Gender 和 Country 是原始实体类型。单个概念模式可能有多个子类型图（例如，一个基于 Person，一个基于 Vehicle）。每个子类型图必须恰好源自一个原始实体类型（它可以是一个对象化关联），该类型是公共超类型，或该图的 `根` 节点（或 `顶点`）。

子类型图只有一个根，因为原始实体类型是互斥的。相反，图中的子类型必然与其超类型重叠，甚至可能彼此重叠（例如 Australian 和 Female）。因为根实体类型是互斥的，所以来自不同子类型图的实体子类型之间没有重叠。为了加深对这些关于子类型的一般概念的理解，您可能希望在继续之前尝试本节练习的第 1 题。

子类型图可能通过 `特化` 一个对象类型为子类型（子类型引入）以自顶向下的方式产生，如[图 6.37](#Ch006_211-271_B9780443237904000025.xhtml#f0190)(a)所示。子类型图也可能通过 `泛化` 对象类型为公共超类型并保留子类型以获取具体细节（超类型引入）以自底向上的方式产生，如[图 6.37](#Ch006_211-271_B9780443237904000025.xhtml#f0190)(b)所示。有时子类型图源于特化和泛化的结合。本节其余部分讨论特化过程，下一节处理泛化过程。

![图 6.37 子类型图可能通过 (a) 特化或 (b) 泛化产生。](images/B9780443237904000025/f06-37-9780443237904.jpg)
