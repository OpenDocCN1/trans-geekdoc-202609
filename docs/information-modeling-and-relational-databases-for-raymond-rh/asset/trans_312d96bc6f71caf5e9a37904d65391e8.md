[第 6.6 节](#Ch006_211-271_B9780443237904000025.xhtml#s0060) 讨论了*上下文相关引用方案*的棘手情况，即子类型可能拥有与其超类型不同的首选标识方案。让我们简要讨论如何映射此类情况。

回想一下，子类型的*直接*超类型是直接连接到该子类型的超类型（即连接路径上没有中间子类型）。每个子类型有一个或多个直接超类型。子类型与其直接超类型之间的连接显示为*实心箭头*（如果它提供了一条通往子类型首选标识符的路径）。如果子类型连接显示为*虚线箭头*，则该子类型要么引入其自己的首选引用方案（这称为*上下文相关引用*），要么通过通往另一个超类型的子类型连接获得其标识方案。

在映射中，附加到对象类型的所有特定角色都要求该对象类型由其首选引用方案标识。这一要求避免了在实践中可能出现的一些极其复杂的引用约束。

如果两个重叠的子类型具有相同的首选引用方案，且其中一个不是另一个的子类型，则它们必须有一个具有该首选引用方案的公共超类型（如果没有，则创建它）。这是为了避免后续的冗余。

例如，假设我们允许 `FemaleStudent(StudentNr)` 和 `PostGradStudent(StudentNr)` 作为 `Person(.nr)` 的直接子类型。将 personNr 向下映射到两个子类型的表中，会导致子类型交集中关联 personNr 和 studentNr 的事实冗余。因此不允许这种模式。相反，我们插入中间超类型 `Student(.nr)` 作为 `Person(.nr)` 的子类型以及 `FemaleStudent` 和 `PostGradStudent` 的超类型，后两者现在从 `Student` 继承其标识方案（该方案用于建立 personNr 和 studentNr 之间的对应关系）。

我们在此将讨论局限于子类型分离选项（为每个子类型特有的函数式角色创建单独的表），并假设所有引用方案都是简单的（非复合的）。对于每个首选引用模式与根不同的子类型，我们按以下“总表过程”定义其“*总表*”（如果有）。

```
总表过程：
如果对象类型具有一个或多个函数式角色的强制析取
    且它们全部映射到同一个表
则其函数式角色映射到的表即为其总表
否则如果它有一个强制非函数式角色
则任意选择其中一个角色；
    该角色映射到的表即为其总表
否则 { 所有角色均为可选 }
如果对象类型是独立的或是采用分离映射选项的子类型
则其表即为总表
否则如果对象类型仅扮演函数式角色或仅扮演一个角色
    且它们全部映射到同一个表
则该表即为其总表
否则该对象类型没有总表。
```

基本思想是，对象类型的总表包含其总体实例（即包含该对象类型实例总体中的所有实例）。如果对象类型确实有总表，此过程将找到它。在下文中，只要总表存在，我们基本上就忽略该对象类型的其他表（其他表通过外键以正常方式链接到主表）。

根超类型表按常规方式计算。将根超类型的首选引用作为额外属性复制到每个“引入”了不同首选引用方案的子类型的总表中；如果引入子类型没有总表，则为其创建一个引用表（仅存储连接该对象类型实例总体的两个标识符的事实）。

在关系层面指定具有不同主引用方案的对象类型之间的子类型链接时，使用根引用方案；如果对象类型具有相同的引用方案，则使用该公共引用方案。
