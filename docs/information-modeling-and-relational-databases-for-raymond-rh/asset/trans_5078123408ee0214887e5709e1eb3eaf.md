
# 选择列

首先，让我们看看如何**选择列**。考虑一个小型的论域（UoD），其中人员通过名字来识别。[表 12.5](#Ch012_539-646_B9780443237904000268_1.xhtml#t0030) 提供了表模式 `Person` (firstname, gender, starsign, birthyr) 的样本数据。

## 表 12.5 存储个人详细信息的关系表

![t12-01-9780443237904](images/B9780443237904000268/t12-01-9780443237904.jpg)

可以通过在所有列上投影来检索整个表。在关系代数中，这可以表述为 `Person` 或 `Person [firstname, gender, starsign, birthyr]`。在 SQL 中，这表示如下：

```
select * from Person
```

这里，星号 `*` 意味着“所有列”，可以读作“everything”或“all”。`from` 后面指定的表名表示从中检索数据的表。执行此命令时，结果是一个**未命名**表，具有与原始 `Person` 表相同的列名和内容。

如果只需要部分列，则应列出相关列（用逗号分隔）代替 `*`。如果列包含键，则结果中不会出现重复行，因此结果对应于这些列上的关系投影（例如，参见 [图 12.32](#Ch012_539-646_B9780443237904000268_1.xhtml#f0165)）。为了提高可读性，SQL 查询通常分布在多行上（例如，新行用于开始 `from` 子句）。除限定（带引号）标识符或字符串常量外，字母的大小写（大写或小写）没有意义。我们大多使用小写，但表名以大写字母开头。许多组织都有自己关于大小写使用的详细标准。

## 图 12.32 在包含键的列上投影

![Fig. 12.32 Projecting on columns that include a key.](images/B9780443237904000268/f12-32-9780443237904.jpg)

如果所选列不包含键，则结果中可能出现重复行。例如，[图 12.33](#Ch012_539-646_B9780443237904000268_1.xhtml#f0170)(a) 中的查询返回一个包（多重集）而非集合，因为 (“M”, “Gemini”) 出现了两次。此操作可称为**包投影**。有时包含重复行很有用（例如，列出体操比赛中裁判给出的所有分数）。可以通过在 `select` 列表前使用限定符 `all` 显式请求包含重复行，但这在 SQL 中反正是默认行为。因此，`select all a,b,… from T` 形式的查询等同于 `select a,b,… from T`。

## 图 12.33 distinct 限定符可用于删除重复行

![Fig. 12.33 The distinct qualifier may be used to remove duplicate rows.](images/B9780443237904000268/f12-33-9780443237904.jpg)

要消除重复，请在 `select` 列表前包含限定符 `distinct`。这可确保显示的行是唯一的，从而提供关系投影。因此，`distinct` 限定符将行包转换为行集。例如，[图 12.33](#Ch012_539-646_B9780443237904000268_1.xhtml#f0170)(b) 中的查询消除了重复的 (“M”, “Gemini”) 行。

列按 `select` 列表中指定的顺序显示。如果使用 `*`，则所有列按与原始表相同的顺序显示。因此，命令 `select * from Person` 仅仅是 `select firstname, gender, starsign, birthyr from Person` 的简写。

一般来说，关系代数的关系投影 `T[a, b,...]` 可以用以下形式的 SQL 语句表示：

```
select distinct a,b,… from T
```

我们可以用以下扩展巴科斯-诺尔范式（EBNF）表示法总结迄今为止涵盖的 `select` 语句部分。符号 `::=` 可读作“is defined as”。这里，方括号中的项目是可选的。表达式 `[,...]` 表示前一个构造可以重复任意次数，其出现之间用逗号分隔。竖线 `|` 用于分隔备选项。默认情况下，`|` 具有最小作用域（即，它仅适用于紧邻它的项）。关键字以粗体显示。此处显示的 `select` 查询的最后一行称为 `from` 子句。从逻辑角度来看，最好在选择列表之前指定 `from` 子句，但该语言的语法不允许这样做。

```
select-list  ::=  columnname [,...]
select-query ::=  select [all | distinct ] select-list | * from tablename
```

# 选择行

现在，让我们看看如何在 SQL 中**选择行**。关系**选择**（或限制）是选择满足指定条件的那些行的操作。在 SQL 中，此操作的语法基本上与本章前面使用的关系代数语法相同。`where` 子句添加在 `select` 语句中紧随 `from` 子句之后，指定的条件称为*搜索条件*。

不要将关系选择操作与 `select` 语句本身混淆，后者用于执行其他操作。[表 12.6](#Ch012_539-646_B9780443237904000268_1.xhtml#t0035) 中列出的关系代数和 SQL 表述是等价的。例如，[图 12.34](#Ch012_539-646_B9780443237904000268_1.xhtml#f0175) 中的查询可用于列出我们之前的 `Person` 表中提到的水瓶座人员的详细信息。

## 图 12.34 使用 where 子句仅选择水瓶座

![Fig. 12.34 A where clause is used to select just the Aquarians.](images/B9780443237904000268/f12-34-9780443237904.jpg)

请注意，字符串 “Aquarius” 包含大小写混合的字符。假设这是它在表中存储的方式，但查询中的 starsign 为大写，即：

```
select * from Person
where starsign = ‘AQUARIUS’
```

除非系统已配置为在比较前将字符串转换为相同的大小写，否则不会匹配，因为字符串 “AQUARIUS” 与 “Aquarius” 不同。要在 SQL-92 及更高版本中使字符串比较不区分大小写，可以声明一个按此方式操作的排序规则集，或使用字符串函数转换大小写。例如，给定字符串表达式 `s`，折叠函数 `upper(s)` 和 `lower(s)` 返回 `s` 的大写和小写版本。因此，以下查询将检索水瓶座人员，无论列条目中 “Aquarius” 字母使用何种大小写：

```
select * from Person
where upper(starsign) = ‘AQUARIUS’
```

虽然许多商业 SQL 方言（如 SQL Server）支持标准的 `upper` 和 `lower` 字符串函数，但某些方言提供了控制字符串常量大小写敏感性的其他方法。

[图 12.35](#Ch012_539-646_B9780443237904000268_1.xhtml#f0180) 中的示例演示了三个新特性。表模式 `Actor` (surname, firstname, gender) 的样本数据包含姓氏 “D’Abot”，其中包含单引号作为其字符之一。如前所述，字符串常量由单引号限定。要在这样的字符串中嵌入单引号，我们需要通知 SQL 该引号是字符串的一部分，而不是结束它。为此，我们**使用两个相邻的单引号来表示嵌入的单引号**。
