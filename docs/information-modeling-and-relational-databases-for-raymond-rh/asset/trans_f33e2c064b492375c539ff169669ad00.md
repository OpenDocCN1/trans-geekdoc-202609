

# SQL Server XML 构造与 SQL/XML 函数

## FOR XML 构造

SQL Server 使用各种 `for xml` … 构造将关系数据转换为 XML。`for xml path` 变体可按列逐列地完全控制 XML 结构的生成方式。`type` 参数指定结果应为 `xml` 类型，而非其字符串等价物。

## XML 聚合函数

回到 SQL/XML，`xmlagg` 函数是一种聚合函数，类似于 SQL 的 `sum`、`avg` 等。它从给定的一组值中返回单个值，这些值必须是 `xml` 类型表达式的结果。生成的 `xml` 值会被连接以产生单个 `xml` 值。可选择使用 `order by` 子句在连接前对结果进行排序，其语法类似于 SQL。连接前会丢弃任何 `null` 值。如果表达式的所有结果均为 `null`，或该组为空，则 `xmlagg` 函数的结果为 `null` 值。基本语法如下：

```
xmlagg ( XML-value-expression [ order by sort-specification ] [ returning { content | sequence } ] )
```

作为 `xmlagg` 函数的示例，假设我们有一个“Orders”表，并希望按客户分组，为每个客户显示其下单的每个订单的一个元素。为简单起见，我们假设订单和客户均由简单的 ID 值表示。我们可以按如下方式构造结果：

```
select xmlelement ( name “Customer”, xmlattributes ( o.custId as “customerId” ), xmlagg ( xmlelement ( name “order”, o.orderId ) order by o.orderId ) ) as XcustOrders from Orders as o group by o.custId
```

## XML 构造函数

`xmlpi` 函数生成单个 XQuery 处理指令节点，如下所示：

```
xmlpi ( name target [ , string-expression ] [ returning { content | sequence } ] )
```

目标标识符（`name`）不能为 ‘xml’（任何大小写组合），且字符串表达式不能包含子字符串 ‘?>’。`xmlcomment` 和 `xmltext` 函数也很简单，各自仅生成相应类型的节点。以下是这些函数用法的一些示例。

* `xmlpi` ( `name` “Warning”, “Turn off now” ) 生成 `<?Warning Turn off now?>`
* `xmlcomment` ( “This is my comment” ) 生成 `<!-- This is my comment -->`
* `xmltext` ( “Here is my text” ) 生成 `Here is my text`

`xmldocument` 函数返回一个文档节点（按 XQuery 数据模型定义），其内容为给定的 XML 值。这对于将任意 XQuery 序列转换为 XML 文档很有用。

```
xmldocument ( xmlvalue [ returning { content | sequence } ] )
```

## XML 转换与验证

提供了单独的转换函数 `xmlcast`，用于在 XML 值与其他类型之间进行转换。其工作方式与标准 SQL `cast` 函数相同，不同之处在于涉及的数据类型中至少有一个必须是 `xml`。在遵守特定规则（此处不详述）的前提下，也可在 `xml` 的子类型之间进行转换。请注意，XML 值与字符串之间的相互转换，与使用 `xmlparse` 和 `xmlserialize` 函数并不相同。

与 `valid` 谓词类似，`xmlvalidate` 函数确保给定的 XML 表达式根据相关模式定义是有效的。与 `valid` 谓词一样，模式可选择显式指定。然而，与 `valid` 谓词不同的是，`xmlvalidate` 函数还会持久地用类型信息标注 XML 表达式。语法如下：

```
xmlvalidate( { document | content | sequence } xmlexpression [ according to xmlschema { uri | registered-name } ] [ valid-element-clause ] )
```

## XML 命名空间

我们之前看到过 `xmlnamespaces` 函数如何在 `xmlelement` 和 `xmlforest` 函数的上下文中使用。`xmlnamespaces` 更完整的语法为：

```
xmlnamespaces ( { XML-namespace-URI as namespace-prefix | default XML-namespace-URI | no default } [,...] )
```

`default` 选项将命名空间定义应用于任何嵌套元素，除非被较低层级的 `no default` 覆盖。同样，`no default` 选项可被较低层级的 `default` 覆盖。`default` 和 `no default` 选项在 `xmlnamespaces` 参数列表中最多只能各指定一次。

## SQL 到 XML 的映射规则

SQL:2003 标准引入了一套广泛的映射规则，以定义 SQL 实体如何从 SQL 映射到 XML（以及反向映射）。规则规范相当广泛，且某些方面取决于实现，因此我们不在此涵盖所有细节。广义上讲，SQL 数据类型映射到 XML Schema 中定义的最接近的等价类型。可使用 XML Schema 侧面和注释来指示某些区别。例如，基本 XML Schema 不区分 `character varying` 和 `character large object`，它们在 SQL 中是不同的类型。SQL 中的分隔标识符按定义映射，保留字符的大小写。常规标识符的大小写不保证会被保留。

对于会导致 XML 中非法名称的字符，会给予特殊处理。通用技术是将该字符替换为 `_xNNNN_` 或 `_xNNNNNN_`，其中 N 为十六进制数字，NNNN 或 NNNNNN 为该字符的 Unicode 表示。标识符映射有两种变体：*部分转义* 和 *完全转义*。两者的关键区别在于对非初始冒号以及以字母“xml”开头（任何大小写组合）的标识符的处理。这些差异总结在 [表 16.5](#Ch016_831-873_B9780443237904000207.xhtml#t0030) 的示例中。

## 使用 XQuery

SQL/XML:2006 引入的最重要方面之一，是将 XQuery 集成到成熟的关系数据库框架中——这是将 SQL/XML 迁移到 XQuery 数据模型的关键动因。需注意一点：如果您有 SQL 背景，请记住与 SQL 不同，XQuery **区分大小写**，因此在指定表达式时需格外小心。同样重要的是要记住，在 SQL/XML 中，我们操作的是 XML 值而非其序列化表示。因此，例如，我们并非试图文本处理“尖括号”，尽管这些对于表示人类可读的结构可能很有用。

最后，我们将介绍 SQL/XML 中提供的一些机制，它们有助于将 XQuery 集成到关系框架中。其中最重要的是 `xmlquery` 函数，它允许在 SQL 上下文中评估 XQuery 表达式。单独的 SQL 无法操作 XML 文档的各个部分：整个文档被视为单个值。借助 `xmlquery` 函数，可以查询 XML 文档内部，使 XML 数据能参与 SQL 查询，并将 SQL 处理应用于返回的 XML 值（例如，使用 `order by` 对结果排序）。`xmlquery` 的基本语法如下。参数的使用方式与我们在其他函数中已见到的等价物类似。

```
xmlquery ( XQuery-expression [ passing [ { by ref | by value } ] XML-query-argument [,...] ] [ returning { content | sequence } ] [ { by ref | by value } ] [ { null on empty | empty on empty } ] )
```
