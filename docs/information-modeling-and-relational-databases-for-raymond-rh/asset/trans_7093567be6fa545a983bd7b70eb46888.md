

# 元建模

元建模并不局限于概念模式。任何定义良好的形式化体系都可以进行元建模。除了用于管理给定的形式化体系外，元模型还可以开发用于允许不同形式化体系之间的转换（例如 ER、ORM 和 UML）。这有时被称为元元建模。

由于 ORM 具有更强的表达能力，因此在 ORM 中捕获 UML 或 ER 中的数据模型相对简单直接。尽管不太方便，但反向操作也是可能的。首先，UML 的图形约束符号可以通过所选语言（如 OCL）中的文本约束来补充。此外，UML 元模型本身具有内置的可扩展性，允许在基于 UML 的存储库中捕获许多特定于 ORM 的约束。

例如，[图 18.33](#Ch018_935-1005_B9780443237904000104.xhtml#f0170)(a) 中的 ORM 模型包含四个约束，`C[1]..C[4]`。虽然唯一性约束在 UML 中很容易表示为多重性约束，但子集约束和排除约束在 UML 中没有图形对应物。[图 18.33](#Ch018_935-1005_B9780443237904000104.xhtml#f0170)(b) 所示的 UML 元模型片段通过 `constraintNr`、`constraintType` 和 `elementNr` 属性，以及带有 `argLength` 属性的 `SetCompConstraint` 子类型，扩展了标准 UML 元模型。

![图 18.33 在 ORM 和扩展 UML 中建模 ORM 集合比较约束。](images/B9780443237904000104/f18-33-9780443237904.jpg)

[图 18.33](#Ch018_935-1005_B9780443237904000104.xhtml#B-f0170) 在 ORM 和扩展 UML 中建模 ORM 集合比较约束。

完整的 UML 元模型非常庞大，因此我们只包含了与示例相关的片段。属性 `constraintType` 存储约束类型（子集、排除、强制等）。`SetCompConstraint` 表示集合比较约束（子集、相等或排除），`argLength` 是参数长度或约束每一端的角色（关联端）数量。

这个元模型片段用 ORM 来理解可能最容易。

[图 18.33](#Ch018_935-1005_B9780443237904000104.xhtml#f0170)(c) 显示了一个基于[图 18.33](#Ch018_935-1005_B9780443237904000104.xhtml#f0170)(a) 的 ORM 元模型片段及其示例实例数据。这四个 ORM 约束现在可以作为[表 18.5](#Ch018_935-1005_B9780443237904000104.xhtml#t0030) 所示的对象-关系来存储。子集（SS）和排除（X）约束记录了它们的参数长度。现在可以通过用这个数字“划分”角色列表来推导出这两个约束的实际参数。因此，子集约束的参数是简单角色 `r[4]` 和 `r[2]`，而排除约束的参数是角色对 (`r[1]`, `r[2]`) 和 (`r[3]`, `r[4]`)。现在可以使用约束类型来确定适当的语义。

    为简化的 UML 类图指定一个采用 ORM 符号的元模式，该类图仅限于以下特性。类仅具有属性（例如，无操作）。属性具有可见性（`+` = 公共，`#` = 受保护，`−` = 私有，`~` = 包级）和多重性（`*` = 0 或多个，`0..1` = 0 或 1，`1..*` = 1 或多个，`1` = 正好 1）。关联可以是二元或 `n` 元。不允许关联类或限定关联。关联端具有多重性（`*` = 0 或多个，`0..1` = 0 或 1，`1..*` = 1 或多个，`1` = 正好 1）。角色名称是强制的（无论是否显示）。可添加到子类化方案中的唯一约束是不相交和完整。不允许派生属性或派生关联。不允许注释。不允许聚合。
