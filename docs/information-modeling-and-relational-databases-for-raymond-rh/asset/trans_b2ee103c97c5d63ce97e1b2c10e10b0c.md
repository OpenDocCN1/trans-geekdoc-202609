

# 关系代数

关系代数包含六个*比较运算符*（`=`、`<>`、`<`、`>`、`<=`、`>=`）。这些是作用于项的命题形成运算符。例如，`x <> 0` 断言 `x` 不等于零。它还包含三个*逻辑运算符*（`and`、`or`、`not`）。这些是作用于命题的命题形成运算符（例如，`x > 0 and x < 8`）。因为该代数不包含算术运算符（例如 `+`）或函数（例如 `count`），所以它的表达能力不如 SQL。这里忽略了将这些及其他运算符纳入代数的建议扩展。

存在许多不同的符号表示法来表达关系代数。我们的表示法与一种常见的学术表示法的比较将在后面给出。为简化讨论，我们将经常使用非正式术语代替严格的关系术语（例如，用“表”和“行”代替“关系”和“元组”）。

## 并、交与差

当且仅当两个表具有相同数量的列，且它们对应的列基于同一个域（列名可以不同）时，这两个表是*并兼容*的。将表视为行的集合，传统的集合运算——并、交和差——可以在并兼容的表之间定义。

请考虑 [图 12.1](#Ch012_539-646_B9780443237904000268_1.xhtml#f0010) 中的概念模式。为简单起见，假设在这个小的论域（UoD）中，人员由其名字标识。我们记录人们吃的食物以及他们喜欢的食物的事实。关系模式包含所示的两个表。这些表的数据集合可以适当地重叠，甚至可以是不相交的。因此，关系模式中没有表间约束——这种情况相当罕见。

[图 12.1](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0010) 概念模式映射到两个表。

[图 12.2](#Ch012_539-646_B9780443237904000268_1.xhtml#f0015) 包含示例数据。表 `A` 和 `B` 的**并**是属于 `A` 或 `B`（或两者皆有）的所有行的集合。我们将其写为 `A ∪ B` 或 `A union B`。假设我们想将每个人与他们吃或喜欢的食物配对。这可以简单地指定为这两个表的并，即 `Eats ∪ Likes`。[图 12.2](#Ch012_539-646_B9780443237904000268_1.xhtml#f0015) 包含该查询表达式及生成的（未命名）表，该表包含 Eats 表中的所有行以及 Likes 表中的所有行。与任何表一样，重复行被排除，因此同时存在于 Eats 表和 Likes 表中的行在结果中仅出现一次。

![图 12.2 两个表的并是出现在任一表（或两者）中的行的集合。](images/B9780443237904000268/f12-02-9780443237904.jpg)

[图 12.2](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0015) 两个表的并是出现在任一表（或两者）中的行的集合。

请注意，`Eats ∪ Likes` 是一个描述如何根据数据库中存储的表（即基本表）推导结果的表达式；它不是一个表名。我们可以将查询结果称为结果表、答案表或派生表。表中行的顺序无关紧要，因为我们处理的是集合。SQL 等实际查询语言提供了按任何首选顺序显示行的方法。

表 `A` 和 `B` 的**交**是 `A` 和 `B` 共有的行的集合。我们将其写为 `A ∩ B` 或 `A intersect B`。例如，要列出人们既吃又喜欢的食物的事实，我们可以将其指定为两个基本表的交，即 `Eats ∩ Likes`（参见 [图 12.3](#Ch012_539-646_B9780443237904000268_1.xhtml#f0020)）。

![图 12.3 两个表的交是两者共有的行的集合。](images/B9780443237904000268/f12-03-9780443237904.jpg)

[图 12.3](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0020) 两个表的交是两者共有的行的集合。

我们定义表之间的**差**运算如下。`A − B` 是属于 `A` 但不属于 `B` 的行的集合。我们也可以将其写为 `A minus B` 或 `A except B`。例如，表达式 `Eats − Likes` 返回关于吃自己不喜欢的食物的人的详细信息（参见 [图 12.4](#Ch012_539-646_B9780443237904000268_1.xhtml#f0025)(a)）。

![图 12.4 (a) A − B 是在 A 中但不在 B 中的行的集合；(b) B − A。](images/B9780443237904000268/f12-04-9780443237904.jpg)

[图 12.4](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0025) (a) `A − B` 是在 `A` 中但不在 `B` 中的行的集合；(b) `B − A`。

正如在普通集合论中一样，并运算是可交换的（即操作数的顺序无关紧要）。因此，给定任意表 `A` 和 `B`，`A ∪ B = B ∪ A` 为真。同样，交运算也是可交换的，即 `A ∩ B = B ∩ A`。然而，差运算不可交换，因此 `A − B` 可能不等于 `B − A`。例如，`Likes − Eats` 返回关于喜欢某种食物但不吃它的人的事实（参见 [图 12.4](#Ch012_539-646_B9780443237904000268_1.xhtml#f0025)(b)）。将其与前一个结果进行比较。

## 笛卡尔积（无限制连接）

在数学中，集合 `A` 和 `B` 的**笛卡尔积**定义为所有有序对 `(x, y)` 的集合，使得 `x` 属于 `A` 且 `y` 属于 `B`。例如，如果 `A = {1,2}` 且 `B = {3, 4, 5}`，则 `A` 和 `B` 的笛卡尔积为 `{(1,3), (1, 4), (1, 5), (2,3), (2, 4), (2, 5)}`。我们将此积写为 `A ⨉ B`（读作 `A cross B`）。此定义也适用于表，尽管行的有序对 `(x, y)` 被视为积表的单行，并继承相应的列名。

因此，如果 `A` 和 `B` 是表，`A ⨉ B` 是通过将 *A 的每一行与 B 的每一行配对* 形成的。这里的“配对”意味着“前置到”。表达式 `A ⨉ B` 也可以写为 `A times B`。笛卡尔积也称为“交叉连接”或“无限制连接”。

因为 `A ⨉ B` 将 `A` 的每一行与 `B` 的所有行配对，如果 `A` 有 `n` 行而 `B` 有 `m` 行，则表 `A ⨉ B` 有 `n × m` 行。因此，*A ⨉ B 中的行数是 A 和 B 行数的乘积*。因为配对的行被连接成单行，*A ⨉ B 中的列数是 A 和 B 列数的总和*。

让我们看一个简单的例子。在 [图 12.5](#Ch012_539-646_B9780443237904000268_1.xhtml#f0030) 中，`A` 是一个 `3 × 2` 表（即 3 行 × 2 列），`B` 是一个 `2 × 1` 表。因此，`A ⨉ B` 有六行（`3 × 2`），三列（`2 + 1`）。包含列名 `a1, a2, b1` 的表头行不计入此计算。在该示例中，行之间用虚线分隔以提高可读性。请注意，对于任意表 `A` 和 `B`，笛卡尔积 `A ⨉ B` 都存在；`A` 和 `B` 无需并兼容。

![图 12.5 A × B 将 A 的每一行与 B 的每一行配对。](images/B9780443237904000268/f12-05-9780443237904.jpg)

[图 12.5](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0030) `A × B` 将 `A` 的每一行与 `B` 的每一行配对。

如果我们将笛卡尔积定义为视为有序值序列的元组，则 `⨉` 运算符不可交换（即 `A ⨉ B` 不一定等于 `B ⨉ A`）。这是数学中的常规处理方式。然而，在关系数据库中，每一列都有唯一的名称，因此元组可以被视为（无序的）属性-值对集合（行中的每个值都与其列名关联）。从这个意义上说，列被称为“按名称排序”。在这种元组视图下，`⨉` 运算符是可交换的。
