

# SQL 标准演进

## 早期标准

1992 年，下一个标准 SQL-92 获得 ANSI 和 ISO 双方批准。由于其规模庞大（超过 600 页），它被定义为三个级别：入门级、中间级和完整级。

SQL:1999 于 1999 年 12 月 8 日获批。SQL:1999 在引入面向对象特性（如对象标识符和引用、数组值字段、过程控制结构）方面与早期版本有显著不同。SQL 现在是对象-关系型的，而不再是纯关系型的。由于规模庞大，SQL:1999 标准（ANSI 1999）被分为五个独立部分：

- 框架
- 基础
- 调用级接口
- 持久存储模块
- 主语言绑定

仅基础部分就包含 1151 页。

## SQL:2003 与 XML 集成

标准的下一个版本 SQL:2003 于 2003 年发布。一个重大增补是首次出现对 XML 的支持，但也包含对许多其他领域的增强。到那时，标准已增长到九个部分，仅基础部分就超过 1300 页。

在 SQL:2003 的开发过程中，XML 领域也在不断演进。为了反映最新的 XML 概念，SQL 标准中单独处理 XML 的部分（有时称为 "SQL/XML"）于 2006 年进行了修订，允许用户导入、存储和操作 XML 数据；它还支持 XML 查询语言 XQuery 的使用，而其他部分保持在 2003 年的修订版本。

## 后续修订

2008 年，SQL 标准修订为支持游标定义之外的 `ORDER BY` 子句（而非触发器）、`TRUNCATE` 语句和 `FETCH` 子句。

2011 年的进一步修订增加了对时态数据（如 `PERIOD`）的支持，并增强了窗口函数和 fetch 子句。

2016 年，SQL 标准修订为支持行模式匹配、多态表函数，以及对存储在字符字符串字段中的 JSON 数据的操作。

2019 年，SQL 标准修订为增加第 15 部分：多维数组（MDarray 类型和运算符）。

## SQL:2023

最新版 SQL 标准（ISO/IEC 9075:2023）于 2023 年 6 月正式采纳（[https://www.iso.org/standard/76584.html](https://www.iso.org/standard/76584.html)）。此修订增加了许多可选特性（唯一约束中的空值、字符串填充函数等）、对 JSON 的更深层支持，以及第 16 部分：属性图查询（SQL/PGQ）。关于 SQL:2023 的更多细节，另请参阅 [SQL:2023 - Wikipedia](https://en.wikipedia.org/wiki/SQL:2023)。

## 商业实现

目前，大多数商业 DBMS 已实现 SQL:1999 中增加的许多特性（如触发器、行类型和大对象），以及后续版本中增加的一些特性。然而，任何商业系统完全实现 SQL:2023 的可能性极低。商业方言对标准中实现的某些特性使用自己的非标准语法，也有自己的扩展特性未包含在标准中。

商业 SQL 系统正缓慢地用标准语法替换其大部分非标准语法，同时为向后兼容保留了大部分替代语法。当某特性同时支持标准和非标准语法时，应使用标准语法。这会使你的 SQL 代码更具可移植性，也更易于其他 SQL 用户理解。

# 12.4 SQL：标识符与数据类型

对于给定模式，某些数据库对象（如基本表、视图、域、触发器、规则和约束）由名称标识。列通过将其（局部）名称附加到其表的名称后，使用“点符号”来标识。这区分了不同表中具有相同局部名称的列。

例如，表 `Subject`（subjectCode, title, credit）和 `Book`（isbn, title）的第二列分别标识为 `Subject.title` 和 `Book.title`。

在 SQL 中，所有名称（包括局部名称）都称为*标识符*，尽管局部名称仅在有限上下文中提供标识。

## 标识符规则演进

在 SQL-89 中，标识符限制为最多 18 个字符，且所有字母必须大写。

从 SQL-92 起，标识符分为常规标识符或分隔标识符。

*常规标识符*是一个最多 128 个字符的字符串，其首字符必须是字母（"a".."z", "A".."Z"）。后续每个字符必须是字母、数字（"0".."9"）或下划线（"_"）。此外，**保留字不得用作常规标识符**。但你可以将保留字作为标识符的一部分使用。例如，"note" 可作为标识符，尽管它包含保留字 `NOT`。

Microsoft SQL Server 允许最多 128 个字符的标识符，但也允许首字符为 "_"、"#" 或 "@"，后续字符为 "#"、"@" 或 "$"。它使用 "#" 开头命名临时对象，用 "@" 开头命名变量名。一些商业系统允许最多 255 个字符的标识符。

由于保留字列表随每个新标准增长，现有应用程序中的标识符可能在后期变得非法。例如，[表 12.3](#Ch012_539-646_B9780443237904000268_1.xhtml#t0020) 显示许多单词在 SQL-92、SQL:1999 和 SQL:2003 中首次成为保留字。不同 SQL 方言可能从其保留字列表中省略其中一些单词，同时添加其他单词，这使得方言之间的可移植性更难。部分为避免此类问题，SQL-92 标准引入了分隔标识符。
