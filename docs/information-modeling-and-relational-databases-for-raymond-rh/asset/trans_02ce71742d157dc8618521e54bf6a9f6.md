
# 分布式系统

分布式系统在现代计算中发挥着至关重要的作用。分布式数据库系统并非将数据仅存储在单个节点上，而是同时使用多台物理或虚拟机器。这些分布式机器共享同一状态并并发运行。

分布式系统提供三项重要特性：可扩展性、可用性和容错性。这些关注点之间存在一定重叠，但可扩展性尤其成为 NoSQL 运动的关键驱动因素之一。

可扩展性的两种主要方法可概括为**垂直扩展**或**水平扩展**。前者随着需求增加使用性能逐步更强的服务器；后者将数据库拆分为不同部分，可随着需求增加挂载到越来越多的服务器上。

垂直扩展的一种方式是将数据库迁移到更强大的机器上，但这显然存在限度。另一种选择是使用共享公共数据存储的服务器集群。这显然会引入额外的复杂性，且迟早也会达到无法进一步扩展的临界点。

NoSQL 数据库更侧重于水平扩展策略，这能应对比垂直扩展大得多的数据库。关键步骤是确定一种合适的数据库分区方法。分区可通过两种方式实现：垂直分区或水平分区。请参考 [图 17.1](#Ch017_875-933_B9780443237904000050.xhtml#f0010) 所示示例。

垂直分区实际上将不同的表列分配给不同的服务器。这能带来一些优势。首先，相对变化缓慢的数据可与动态数据分离。变化缓慢的数据适合由应用程序缓存在低性能存储中。其次，敏感数据可存储在具有额外安全控制的独立分区中。最后，垂直分区可减少所需的并发访问量。可能的结果如 [图 17.2](#Ch017_875-933_B9780443237904000050.xhtml#f0015) 所示。

![图 17.2 垂直分区的员工数据](images/B9780443237904000050/f17-02-9780443237904.jpg)

[图 17.2](#Ch017_875-933_B9780443237904000050.xhtml#B-f0015) 垂直分区的员工数据。

垂直分区可在同一服务器内使用。水平分区（也称为**分片**）用于将数据拆分到多台服务器上。这引入了额外的难度，因为应用程序现在需要知道哪台服务器包含相关分区。这可以通过多种方式实现，例如：

*   **按范围**：每台服务器包含一组已知范围的键值。
*   **按查找**：辅助表包含键与服务器之间的交叉引用。
*   **按哈希**：对键使用哈希函数以识别相关服务器。

分发策略还可能考虑其他因素，如地理位置。如果数据流量主要由本地化关注点驱动，可将其定向到物理上接近信息创建或消费位置的服务器。[图 17.3](#Ch017_875-933_B9780443237904000050.xhtml#f0020) 展示了一个简单的水平分区，将数据拆分到两台服务器上。

## CAP 定理

CAP 定理由 Brewer 于 2000 年首次提出，是分布式系统设计中广泛使用的概念（[Gilbert and Lynch, 2002](#Ch017_875-933_B9780443237904000050.xhtml#bb0480)）。其核心在于理解构建分布式系统时必须做出的权衡。具体而言，它指出分布式系统不可能同时提供以下三项保证：

*   **一致性**：分布式系统中的每个节点在同一时间看到相同的数据，意味着每次读操作必须返回最近一次写操作的数据值。
*   **可用性**：对系统发出的每个请求都能在合理时间内收到响应，无论系统中的节点是否故障或遇到问题。
*   **分区容错性**：即使发生网络分区（由于网络故障或其他问题导致系统中的节点相互分离），分布式系统也应继续运行。

换句话说，CAP 定理表明在任意时刻只能满足三项保证中的两项。这意味着：高可用且分区容错的系统必须牺牲一致性；高一致且分区容错的系统必须牺牲可用性；高可用且高一致的系统必须牺牲分区容错性。

如果数据库未分区，则可以同时具备一致性和可用性（有时称为 CA 数据库）。这正是采用大型中央服务器（即单节点系统）的传统数据库的情况。如果数据库已分区，则可优先保证一致性（CP）或优先保证可用性（AP）。请考虑 [图 17.4](#Ch017_875-933_B9780443237904000050.xhtml#f0025) 所示的分布式系统；仅两个节点即足以说明问题。

![图 17.4 简单分布式系统](images/B9780443237904000050/f17-04-9780443237904.jpg)

[图 17.4](#Ch017_875-933_B9780443237904000050.xhtml#B-f0025) 简单分布式系统。

在一个节点上进行的更新可通过网络连接以一定延迟传输到另一个节点。两组用户最终都能看到一致的数据。但如果发生故障（如节点 1 和节点 2 之间的网络连接丢失），则有两种可能性：

1.  **防止访问其中一个节点**。这保证了工作节点上的一致性，但移除了另一节点上用户的可用性（CP 选项）。
2.  **允许访问两个节点**。系统对所有用户保持可用，但一个节点上的更新无法到达另一个节点，从而丧失一致性（AP 选项）。

此示例显然很简单，但说明了分布式系统中必须考虑的平衡。没有唯一的正确答案，因为选择取决于应用程序的预期用途。金融系统可能倾向于一致性，而社交媒体平台可能倾向于可用性。不同的分布式系统可能会在牺牲部分一致性与牺牲部分可用性之间探索不同的折中方案。

## ACID 与 BASE

传统数据库通常遵循一组称为 ACID 的原则，该首字母缩写源自 Atomic（原子性）、Consistent（一致性）、Isolated（隔离性）和 Durable（持久性）四个术语（[Gray and Reuter, 1993](#Ch017_875-933_B9780443237904000050.xhtml#bb0495)）。

*   **原子性**：事务中的所有操作必须要么全部成功完成，要么全部不执行。如果事务执行期间任何操作失败，整个事务将中止并回滚到其之前的状态。
*   **一致性**：每次成功事务后，数据库必须从一个一致状态转换到另一个一致状态。所有数据完整性约束必须在每次事务前后均得到维护。
*   **隔离性**：并发事务互不干扰彼此的执行。每个事务应表现得如同独立执行，不影响其他正在进行的事务。
*   **持久性**：一旦事务成功完成（“提交”），对数据库所做的任何更改应持久保存，即使发生系统故障也是如此。
