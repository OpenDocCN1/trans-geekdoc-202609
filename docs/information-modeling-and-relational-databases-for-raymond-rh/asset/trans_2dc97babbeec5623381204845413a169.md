
# 模式转换与优化

为了帮助您从如此多样的不同设计中进行选择，本章探讨了模式转换以提供备选方案的各种方法，随后给出了优化选择的指导原则。在此过程中，我们将介绍一些关于模式转换和规范化的理论，以确保对底层概念有正确的理解。我们将从概念层面入手，然后深入到逻辑层和物理层。示例将说明这些思想如何也可用于重构那些被证明不令人满意的现有应用程序。

## 模式转换与优化简介

本节其余部分通过一个示例，为模式转换和优化提供一个简单的介绍。前几章介绍了一些建模选择。例如，我们可以用扁平形式或嵌套形式来建模一个三元事实类型。基本上，如果且仅当一个概念模式中能建模的任何 UoD 状态或转换也能在另一个中建模时，这两个概念模式才是**等价**的。

作为一个简单的例子，请考虑 [表 14.1](#Ch014_681-771_B9780443237904000189.xhtml#t0010) 中所示的医疗报告。此处，相应列中的勾选标记表示患者是否吸烟或饮酒。由于这些“恶习”会损害健康，医生通常对该信息感兴趣。请尝试在查看提供的解决方案之前，自行为 [表 14.1](#Ch014_681-771_B9780443237904000189.xhtml#t0010) 绘制模式。

对该领域建模的另一种方法是将吸烟和饮酒谓词泛化为单个二元谓词，引入对象类型 `Vice {S = Smoking, D = Drinking}` 以保持区别，如 [图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(b) 所示。直观上，大多数人会认为 [图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010) 中的两个模式是等价的。形式上，可以通过向 [图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(a) 的模式引入“虚拟对象类型”`Vice`，并指定两者谓词如何相互翻译，来证实这一直觉。例如，第一个模型中表示的事实可使用以下翻译在第二个模型中表示：

```
患者吸烟 当且仅当 患者沉溺于恶习 'S'
患者饮酒  当且仅当 患者沉溺于恶习 'D'
```

而第二个模型中的事实可使用以下翻译在第一个模型中表示。与模式一样，这些翻译可映射为谓词逻辑公式。然后可使用形式逻辑来证明模式等价性。

```
患者沉溺于恶习 当且仅当 患者吸烟 且 恶习具有恶习代码 'S'
或             患者饮酒 且 恶习具有恶习代码 'D'
```

刚才考虑的等价性是*上下文等价性*的一个例子，因为它为原始模式添加了定义上下文。它还要求正式承认“虚拟对象类型”（例如，`Vice` 在第一个模式中隐式存在）。这一概念称为“*对象相对性*”，因为它实际上允许“对象在于观察者的眼中”。这使得经典逻辑证明技术可应用于此类情况。

## 模式等价性定理

接下来的几节讨论了一些定理，可帮助我们判断两个模式是否等价。这些定理还可帮助我们将一个模式转换为另一个等价的模式，或者至少是可以接受的接近等价的模式（有时我们可能希望通过添加或删除信息来稍微加强或削弱模式）。这种重塑模式的行为被称为**概念模式转换**。

虽然概念转换是在对象角色建模（ORM）中指定的，但它们可以转换为其他建模符号。例如，前面的等价性（减去定义上下文）可以用统一建模语言（UML）表示，如 [图 14.2](#Ch014_681-771_B9780443237904000189.xhtml#f0015) 所示，使用“![Image 1](images/B9780443237904000189/u14-01-9780443237904.jpg)”表示“等价于”。使用 ORM 可以在图形上捕获更多复杂的转换，而无需用文本约束补充图表。但如果您想使用非 ORM 符号，应该能够毫无困难地将转换定理翻译成您首选的符号。

## 模式转换的应用

对模式转换的了解有助于我们看到可能的不同设计选择。此外，如果两个独立开发的模式需要完全或部分集成，我们通常需要解决每个模式对共同 UoD 特征建模方式的差异。为此，我们需要知道一种表示是否可以转换为另一种，以及如果可以，如何转换。

概念模式转换的另一个用途是将原始概念模式重塑为直接映射到更高效实现的模式。此过程称为**概念模式优化**。例如，[图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(a) 中的概念模式映射到单个表。采用封闭世界解释，我们可以使用 [图 14.3](#Ch014_681-771_B9780443237904000189.xhtml#f0020)(a) 所示的表模式。为便于讨论，包含了样本数据的数据量。然而，由于沉溺事实类型是 *m:n* 的，[图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(b) 中的模式映射到两个表，如 [图 14.3](#Ch014_681-771_B9780443237904000189.xhtml#f0020)(b) 所示。同样，也包含了样本数据量。

![图 14.3 基于图 14.1 中概念模型的关系模型。](images/B9780443237904000189/f14-03-9780443237904.jpg)

[图 14.3](#Ch014_681-771_B9780443237904000189.xhtml#B-f0020) 基于 [图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010) 中概念模型的关系模型。

对于许多应用程序，单表解决方案更高效。它使我们能够列出关于患者的所有信息，而无需表连接。它还避免了强制执行子集约束所需的任何表间访问（例如，添加恶习事实或删除患者时）。因此，在将 [图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(b) 的模式传递给正常的 Rmap 过程之前，可以通过将其转换为 [图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(a) 的模式来进行优化。
