# 13.6 更多数据库对象

## 序列

在 SQL 中，序列是一种自动生成一系列值的数据库对象；请注意，这与 XQuery 中“sequence”（序列）一词的用法含义完全不同，稍后我们将看到。序列对象最早于 SQL:2003 中引入，当需要生成唯一键值时非常有用。在数据库内部生成唯一值，而不是在外部应用程序中生成，可以减少在性能和并发等领域出现问题的可能性。某些 SQL 实现可能会预先计算序列中的下一个值并将其缓存，以便立即使用。

在某些方面，序列类似于表中的标识列。然而，与标识列不同，序列不绑定到某个特定表，并且序列值在数据库范围内唯一，而非仅在表范围内唯一。可以使用以下语法创建序列。

```
create sequence sequence-name  [ as data-type | start with start-value |increment by increment-value |maxvalue value | no maxvalueminvalue value | no minvalue |cycle | no cycle [ ,… ] ]
```

数据类型必须是标度为零的数值类型（例如 `integer`）。这些选项与前面讨论的标识列选项类似。序列的一个额外功能是，某些实现还允许零增量，使序列实际上成为一个全局常量值。

从序列获取下一个值的标准语法是：

```
next value for sequence-name
```

但某些实现可能对此有变体。它们也可能提供某种方式来访问最后生成的序列号而不生成新序列号，例如：

```
previous value for sequence-name
```

SQL 还定义了 `drop sequence` 和 `alter sequence` 命令，但因为这些命令的工作方式显而易见，我们在此不再讨论。

## 索引

*索引* 通常是键值的有序二叉树，带有指向存储数据的完整记录位置的指针。因为索引仅与物理建模相关，而与逻辑建模无关，所以 SQL 标准从未提及它们。然而，大多数商业系统允许用户使用诸如 `create [ unique ] index indexname on tablename ( index-column [ asc | desc ] [,...] )` 和 `drop index indexname` 之类的语法显式地创建和删除索引。优化器使用索引来提高性能，并可能自行创建和删除索引。如果受支持，唯一索引选项提供了一种强制唯一性约束的方法。然而，大多数唯一性约束最好使用 `primary key` 或 `unique` 声明来定义，尽管可选列上的唯一性约束通常需要触发器。索引通常会为主键和外键自动创建。

索引可以显著提高查询性能，尤其是对于大表，因为索引通常允许在主存中随机访问，而不是顺序磁盘访问。某些商业系统还可能允许将选定的索引指定为 *clustered*（聚集）。这会在索引列的值的逻辑顺序与行的物理存储顺序之间创建对齐，从而可能提高检索行数据的性能。显然，如果一个表有多个索引，只能选择一个作为聚集的基础；通常这将是主键列上的索引。

虽然索引可以提高查询效率（从而可能提高约束强制执行的性能），但也需要付出代价。索引可能会降低表的更新速度，因为对数据的任何更改不仅涉及基本表的更改，还涉及已定义的任何索引的更改。不过，根据具体情况，这种权衡可能仍然是可以接受的。各个 DBMS 可能提供多种不同类型的索引，选择索引的策略也可能因 DBMS 而异。由于本书主要关注概念和逻辑建模，因此不再进一步讨论索引策略。

## 游标

游标本质上是一种机制，用于为预先指定的 `select` 语句的结果提供逐行访问。只要正在使用游标（在此期间游标被称为 *open*（打开）），结果就会被保留。使用游标是一个四阶段过程。

1.  游标被 *声明*，这定义了 `select` 语句和游标的操作模式。
2.  游标被 *打开*，此时执行关联的 `select` 语句并形成临时结果表。
3.  应用程序浏览结果表，通常逐行进行，以 *提取* 任何所需操作所需的数据。
4.  当应用程序完成工作时，游标被 *关闭*，这将导致原始 `select` 语句的结果被删除。

直接从应用程序控制这些步骤是相当常见的做法。这是游标以运行迟缓著称的原因之一，稍后将更详细地讨论。

大多数供应商支持用于游标声明的基本 SQL-92 语法，如下所示。后续版本的标准中添加了一些细节，但这些并未影响基本的 SQL 游标概念。

*   ```
    declare cursor-name [ sensitive | insensitive ] [ scroll | no scroll ] cursor
    ```
*   ```
    for select_statement
    ```
*   ```
                  [ for { read only | update [ of column_name [ ,... ] ] } ]
    ```

可选地，游标可以声明为 `for read only`（如果不需要更新，这能提高性能）或 `for update`，并可限制为特定列。声明为 `insensitive` 的游标会创建所用数据的临时副本，所有数据请求都从该临时表中应答。因此无法对基本表进行修改。如果省略 `insensitive` 或选择了 `sensitive` 选项，则对底层表所做的更改可能会反映在后续的提取中。`scroll` 选项指定应为游标启用一系列导航操作。如果省略，或选择了 `no scroll` 选项，则游标仅限于提取结果的下一行。一旦定义了游标，就可以将其打开。语法简直再简单不过了：

*   ```
    open cursor-name
    ```

open 子句没有更改 `select` 语句的选项；它只是执行关联游标声明中已定义的语句。它还将游标定位在结果集第一行之前。给定一个打开的游标，可以从 `select` 语句产生的结果中提取数据。
