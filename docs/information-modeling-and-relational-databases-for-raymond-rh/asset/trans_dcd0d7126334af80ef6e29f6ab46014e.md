

## N/CR 定理与嵌套/扁平化等价性

一般定理称为 **N/CR** (*nest/coreference*)，详见 [Fig. 14.24](#Ch014_681-771_B9780443237904000189.xhtml#f0125)。此处，对象化谓词 *R* 具有 *n* 个角色，其中 *n* 至少为 2。对象类型 *A*[1]…*A*[*n*] 不一定互异。虽然图中未显示，但我们假设嵌套和共引用的对象类型至少有一个附加角色。

![Fig. 14.24 N/CR: The nested version is equivalent to the coreferenced version.](images/B9780443237904000189/f14-24-9780443237904.jpg)

[Fig. 14.24](#Ch014_681-771_B9780443237904000189.xhtml#B-f0125) N/CR: 嵌套版本等价于共引用版本。

如果对象类型的事实角色析取是可选的，则该对象类型是独立的。如果是独立的，则必须通过在其名称后附加 “!” 来显式标记。例如，回顾 [Fig. 14.21](#Ch014_681-771_B9780443237904000189.xhtml#f0110)(b) 和 (c)，假设在已知任何结果之前就记录了注册信息。现在必须从评分关联中移除强制角色约束，并将 Enrollment 对象类型重命名为 “Enrollment !”。稍后将展示，为了维持扁平化方法，需要对 [Fig. 14.21](#Ch014_681-771_B9780443237904000189.xhtml#f0110)(a) 中的模式进行更彻底的更改。

只要嵌套或共引用的对象类型仅扮演一个事实角色，且该角色是强制的，我们就可以转换为单一的扁平化事实类型。回顾 [Fig. 14.21](#Ch014_681-771_B9780443237904000189.xhtml#f0110) 中的示例。在这种情况下，通常建议采用扁平化方法，因为它提供了更简单的图表，更易于口语化表达，并且有时可以避免关于对象化谓词哪一部分的任意决定。

当一个三元或更长的谓词仅有一个唯一性约束，且该约束跨越了除一个角色之外的所有角色时，由此 UC 跨越的子谓词提供了对象化的最佳选择。这是我们在 [Fig. 14.21](#Ch014_681-771_B9780443237904000189.xhtml#f0110) 中的选择。原则上，我们可以选择任意子谓词进行对象化。例如，假设在 [Fig. 14.25](#Ch014_681-771_B9780443237904000189.xhtml#f0130)(a) 中，我们对象化包含第一和第三角色的子谓词，而不是前两个角色。这将产生 [Fig. 14.25](#Ch014_681-771_B9780443237904000189.xhtml#f0130)(b) 中所示的别扭模式。

![Fig. 14.25 A poor choice for nesting (the UC spans other roles).](images/B9780443237904000189/f14-25-9780443237904.jpg)

[Fig. 14.25](#Ch014_681-771_B9780443237904000189.xhtml#B-f0130) 嵌套的不佳选择（UC 跨越了其他角色）。

需要外部 UC 来捕获扁平化版本中的 UC（即每个学生每门科目最多获得一个评分）。另请注意，外层谓词上的 UC 是复合的。尽管它映射到与其他版本相同的关系模式，但 [Fig. 14.25](#Ch014_681-771_B9780443237904000189.xhtml#f0130)(b) 对人类来说更难理解。

如果三元或更长的谓词具有重叠的 UC，则任何对象化最好基于其中之一。扁平化版本中的每个其他 UC 则由外部 UC 捕获。请参阅 [Figs. 4.40](#Ch004_111-158_B9780443237904000232.xhtml#f0205) 和 [4.41](#Ch004_111-158_B9780443237904000232.xhtml#f0210) 中的早期示例。

对于重叠的 UC，存在不止一个“自然”的子谓词对象化选择。如果三元或更长的谓词具有跨越性 UC（如 Lecturer visits Country in Year），情况也是如此。在此，我们可以对象化三个角色对中的任意一个：角色 1 和 2；角色 1 和 3；或角色 2 和 3。除非关于子谓词有额外的事实，否则扁平化事实类型提供了更简单的方法。

[Fig. 14.26](#Ch014_681-771_B9780443237904000189.xhtml#f0135) 展示了 **N/F** (*nest/flatten*) 等价定理的三元版本。此处 *A*、*B* 和 *C* 不必互异。假设嵌套对象类型 *S* 中的角色上有一个跨越性 UC。通常，UC 跨越 *R* 中的 *A* 和 *B* 角色；这等价于 *T* 第一个角色上的 UC。对于等价性，谓词必须通过 where 子句中所示的条件正式关联。

![Fig. 14.26 N/F: The nested version is equivalent to the flattened version.](images/B9780443237904000189/f14-26-9780443237904.jpg)

[Fig. 14.26](#Ch014_681-771_B9780443237904000189.xhtml#B-f0135) N/F: 嵌套版本等价于扁平化版本。

在 [Fig. 14.26](#Ch014_681-771_B9780443237904000189.xhtml#f0135) 中，如果 UC 跨越 *R* 的所有角色，则 UC 跨越 *T* 的两个角色。我们不在图中陈述这一推论，因为每个谓词都隐含一个跨越其全长的 UC。请回顾，为了通用性，用于描绘定理的模式可能会省略与转换无关的约束。

我们的等价定理陈述了不同版本中谓词之间的正式联系，但未指定一个模式中使用的谓词名称如何帮助选择另一个模式中使用的不同谓词名称。计算机辅助软件工程 (CASE) 工具可以生成建议名称，但人类通常能提供更自然的名称（参见关系映射中表名的生成）。

在选择标识符时，我们应确保其背景含义与转换规则所要求的正式联系一致。这仍留有许多可能性。例如，在 [Fig. 14.25](#Ch014_681-771_B9780443237904000189.xhtml#f0130)(a) 中，我们可以使用 “… enrolled in … obtaining …” 代替 “… for … scored …”。

请注意，因为嵌套总是可以用共引用替代，所以我们可以指定类似于任何 N/F 定理的 **CR/F** (*coreference/flatten*) 等价定理。例如，考虑在 [Fig. 14.21](#Ch014_681-771_B9780443237904000189.xhtml#f0110) 中的两个模式之间进行转换。然而，为了节省空间，我们将展开讨论限制在嵌套方面。

三元嵌套/扁平化等价性可以推广到元数大于二的任何扁平化事实类型。请注意，嵌套总是引入一个额外的角色（由对象化关联扮演）。如果我们对象化一个 *n* 元谓词的 *m* 个角色，外层谓词将有 *n* – *m* + 1 个角色。这在 [Fig. 14.27](#Ch014_681-771_B9780443237904000189.xhtml#f0140)(a) 中有所示，为简单起见，省略了其他对象类型和角色连接器。

![Fig. 14.27 (a) Nesting ternaries and beyond; (b) nesting on a UC.](images/B9780443237904000189/f14-27-9780443237904.jpg)

[Fig. 14.27](#Ch014_681-771_B9780443237904000189.xhtml#B-f0140) (a) 嵌套三元及更高元数；(b) 基于 UC 的嵌套。

回顾一下，基本谓词的每个 UC 至少必须跨越除一个角色之外的所有角色。如果 UC 精确跨越了谓词的除一个角色之外的所有角色，且我们基于此 UC 进行对象化，则嵌套版本中的外层谓词有两个角色，其第一个角色上有一个简单 UC（[Fig. 14.27](#Ch014_681-771_B9780443237904000189.xhtml#f0140)(b)）。

对于长谓词，嵌套可以应用多次，如 [Fig. 14.28](#Ch014_681-771_B9780443237904000189.xhtml#f0145) 所示，其中四元谓词分两阶段二元化。为简单起见，省略了其他对象类型和角色链接。我们之前已经看到如何将一元转换为二元。嵌套或共引用可用于将 *n* 元谓词转换为二元谓词。因此，原则上，任何领域都可以仅用二元谓词建模。然而，非二元谓词通常能以更自然、更方便的方式对应用进行建模。

[Fig. 14.28](#Ch014_681-771_B9780443237904000189.xhtml#B-f0145) 通过嵌套将四元谓词二元化。
