使用实体图标，引用类型“文件在文件夹中”和“文件具有文件名”填充如图所示。在“文件具有大小”事实表中，文件条目作为值对出现。虽然图中未显示，但这些值对按添加引用类型到模式时的相同顺序排序（文件夹，文件名）——ORM 工具可根据要求显示此顺序。

如果引用谓词包含在文件的确定性描述中，则可以使用任何顺序。例如，“位于文件夹‘MyDocs’中且文件名为‘flag.vsd’的文件”等同于“文件名为‘flag.vsd’且位于文件夹‘MyDocs’中的文件”。通常，复合引用方案涉及对象到两个或多个值组成的元组的强制性 1:1 映射。

在文本上，对象类型 `A` 的复合引用方案可以通过列出引用类型（去掉开头的 `A`）并在 `A` 后用括号括起来来声明。假定引用谓词上相关的唯一性和强制性约束，如果先声明引用方案，则事实可以用简短形式陈述。例如，示例模型可以按如下方式用文本指定：

```
引用方案：
文件夹 (.name)；文件 (在文件夹中, 具有文件名)；大小 (kB:)
```

```
事实类型：
文件具有大小
```

```
约束：
每个文件至多具有一个大小。
每个文件至少具有一个大小。
```

```
事实实例：
文件 (‘MyDocs’, ‘flag.vsd’) 具有大小 35。
文件 (‘MyDocs’, ‘orm1.doc’) 具有大小 1324。
文件 (‘OzWork’, ‘flag.vsd’) 具有大小 40。
```

原则上，我们可以通过将文件夹名称和本地文件名用分隔符（例如“\\”）连接成一个字符串，使用简单引用方案来建模文件。例如，文件随后可以简单地命名为“MyDocs\\flag.vsd”、“MyDocs\\orm1.doc”和“OzWork\\flag.vsd”。这种方法通常是不可取的，因为它需要额外的派生工作来提取和分组组件以生成各种报表。我们稍后将详细讨论这个问题。确实，如果我们也希望针对文件扩展名（例如“vsd”、“doc”）发出查询，则三部分引用方案（使用文件夹名称、简单名称和文件扩展名）是可取的。

识别方案相对于特定的 UoD（论述域）是 `相对的`。通常，在局部上下文中有效的简单方案在更广泛范围的 UoD 中会失效。在将模式合并为更大的模式时，记住这一概念很重要。例如，假设在给定的大学系内，该系提供的每门学科都可以用其标题来识别。例如，考虑 [表 5.5](#Ch005_159-209_B9780443237904000098.xhtml#t0030) 中的输出报表，它指示了物理系在哪些学期提供哪些学科。
