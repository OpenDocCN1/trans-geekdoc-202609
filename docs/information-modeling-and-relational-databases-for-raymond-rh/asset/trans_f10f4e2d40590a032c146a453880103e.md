

# 关系

关系通常仅限于二元关联，显示为连接实体类型的命名线。关系名称从左向右、从上向下阅读。与 Barker 表示法一样，半线或线端对应 ORM 中的角色。

可选性和基数设置通过标注线端来指示。要指示角色是*可选*的，在线的另一端放置一个圆圈“◯”，表示最小参与频率为 0。要指示角色是*强制*的，在线的另一端放置一个竖线“|”，表示最小参与频率为 1。在尝试了不同的“*多*”基数表示法后，Finkelstein 采用了 Gordon Everest 博士建议的直观鸭掌符号（crow’s foot）。

结合最小频率 0 或 1，竖线“|”常用于指示最大频率为 1。在这种安排下，组合“◯|”表示“*至多一个*”，组合“||”表示“*恰好一个*”。本节采用此约定。然而，存在不同的 IE 约定。例如，一些约定假设如果未使用鸭掌符号，则最大基数为 1，因此仅使用单个“|”表示“恰好一个”。Clive Finkelstein 使用组合“◯|”表示“可选但将变为强制”，这实际上是动态而非静态约束；这可以与鸭掌符号结合使用。一些约定允许鸭掌符号意味着最小（因此也是最大）频率为多。使用某个版本的 IE 时，请检查这些约定中的哪一个适用。

[图 8.20](#Ch008_309-346_B9780443237904000177.xhtml#f0105) 展示了一个简单的 IE 图及其等价的 ORM 图。使用 IE 时，当你从左向右阅读一个关联时，你要口头表达右侧端点的约束符号。在此，每位员工恰好占用一个（至少 1 个且至多 1 个）房间。IE 并不总是支持逆向谓词，但你可以自行提供它们以获得反方向的口语化表达，例如，“每个房间由零名或多名员工占用”。与 Barker 表示法一样，引入实体类型名称的复数形式来处理多的情况。

IE 表示法与 Barker 表示法相似，都是通过标记另一端的角色来显示角色的最大频率。但与 Barker 表示法不同，IE 表示法也在另一端显示可选性/强制性设置。从这个意义上说，IE 类似于 UML（尽管使用的符号不同）。如前所述，二元关联上可选性和基数共有 16 种可能的约束模式。[图 8.21](#Ch008_309-346_B9780443237904000177.xhtml#f0110) 展示了这些情况在 IE 表示法中的样子，以及等价的 ORM 情况。

[图 8.21](#Ch008_309-346_B9780443237904000177.xhtml#B-f0110) IE 和 ORM 中等价的约束模式。

[图 8.22](#Ch008_309-346_B9780443237904000177.xhtml#f0115) 展示了一个使用 Finkelstein 版 IE 不同表示法的示例。关联左端的单竖线表示每台计算机确切位于一个办公室中。右侧角色上的圆圈、竖线和鸭掌符号共同表示每个办公室最终必须容纳一台或多台计算机。虽然这种“可选变强制”约束在 ORM 中没有对应概念，且大多数 IE 建模工具不支持它，但它可用于细化如何将事实类型分组为实现结构的决策。

一些建模工具支持 IE 表示法用于 *n*:1、1:*n* 和 1:1 关联，但不支持 *m:n*（多对多）关联。对于此类工具，[图 8.21](#Ch008_309-346_B9780443237904000177.xhtml#f0110) 中的 16 种情况有 4 种无法直接表示。在这种情况下，你可以通过引入一个带有指向原始实体类型的强制 *n*:1 关联的“*交集实体类型*”来间接建模 *m:n* 情况。例如，[图 8.23](#Ch008_309-346_B9780443237904000177.xhtml#f0120) 所示，通过引入对象类型 *C*，可以处理两个角色均为可选的 *m:n* 情况。

![图 8.23 一个 m:n 关联重建模为带有 n:1 关联的实体类型。](images/B9780443237904000177/f08-23-9780443237904.jpg)

[图 8.23](#Ch008_309-346_B9780443237904000177.xhtml#B-f0120) 一个 *m:n* 关联重建模为带有 *n*:1 关联的实体类型。

在 IE 中，这种转换会丢失每个 *A*\- *B* 组合最多只与一个 *C* 相关的约束（除非我们降到关系层面，通过为 *C* 的主键使用两个外键来实现；稍后见 IDEF1X）。在 ORM 中，该约束在概念层面被捕获为外部唯一性，使 *C* 成为*同一引用*对象类型——该转换是一种扁平化/同一引用等价（见[第 14 章](#Ch014_681-771_B9780443237904000189.xhtml)）。

举个例子，*m:n* 关联“Person plays Sport”（人参与运动）可以转换为带有唯一约束的强制 *n*:1 关联“Play is by Person”（参与由人发起）；“Play is of Sport”（参与属于运动）。然而，这种转换通常非常不自然，特别是如果没有其他内容记录关于该同一引用对象类型的信息时。因此，任何真正的概念方法都必须允许直接建模 *m:n* 关联。

一些版本的 IE 支持*异或约束*，显示为连接到备选项的黑点。[图 8.24](#Ch008_309-346_B9780443237904000177.xhtml#f0125)(a) 描绘了这样一种情况：每位员工被分配一张公交卡或一个停车位，但不能两者兼得。等价的 ORM 模式显示在[图 8.24](#Ch008_309-346_B9780443237904000177.xhtml#f0125)(b) 中。与 ORM 不同，IE 不支持同或约束。也不支持简单或复合排斥约束。

![图 8.24 (a) IE 和 (b) ORM 中的异或约束。](images/B9780443237904000177/f08-24-9780443237904.jpg)

[图 8.24](#Ch008_309-346_B9780443237904000177.xhtml#B-f0125) (a) IE 和 (b) ORM 中的异或约束。

IE 的子类型方案各异。有时使用欧拉图，如有需要可添加空隔间表示“其他”。有时使用 DAG（有向无环图），可能包含子类型关系名称和可选性/基数约束。

尽管表达能力远不如 ORM，IE 在覆盖基本约束方面做得很好。其创始人 Clive Finkelstein 是一位和蔼的澳大利亚人，仍积极从事 IE 领域的工作。他开发了一套配合该表示法的建模过程，将 IE 扩展到企业工程，并结合了可扩展标记语言（XML）的工作。
