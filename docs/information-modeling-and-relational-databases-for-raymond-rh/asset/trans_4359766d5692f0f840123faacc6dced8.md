

# 概念模式图上的唯一性约束

本章讨论如何在概念模式图上指定 UC。每个基本事实类型必须至少分配一个 UC。鉴于基本事实类型上的约束，派生事实类型上的约束通常由派生规则隐含。例如，如果一扇窗户最多有一个高度和最多一个宽度，那么派生规则 `area = height * width` 就意味着每扇窗户最多有一个面积（这就是派生事实类型“窗户拥有面积”上的 UC）。

本章其余部分讨论 CSDP 步骤 4。首先，我们讨论如何在一元和二元谓词上标记 UC。然后我们考虑更长谓词上的 UC。之后，我们检查外部 UC（这些适用于不同谓词之间）。最后，我们讨论检查事实类型是否具有正确元数（角色数量）的方法。

## 4.2 一元和二元谓词上的唯一性约束

一元事实类型是最简单的，所以我们先看它们。假设作为健身应用程序的一部分，我们记录哪些人是慢跑者。这可以用一元事实类型来处理，如 [图 4.2](#Ch004_111-158_B9780443237904000232.xhtml#f0015) 所示。

![图 4.2 带有示例实例的单元事实类型。](images/B9780443237904000232/f04-02-9780443237904.jpg)

[图 4.2](#Ch004_111-158_B9780443237904000232.xhtml#B-f0015) 带有示例实例的单元事实类型。

为简单起见，我们再次假设可以仅通过姓氏来识别人。其中包含了一个示例实例。从概念角度来看，事实实例是包含以下事实的集合：

```
姓氏为 'Adams' 的人慢跑。姓氏为 'Brown' 的人慢跑。姓氏为 'Collins' 的人慢跑。
```

假设记录这些事实后，我们又看到 Adams 跑过。忘记了我们已经记录了他的慢跑，我们现在尝试以下更新：

```
添加：姓氏为 'Adams' 的人慢跑。
```

如果被接受，此更新可以如 [图 4.3](#Ch004_111-158_B9780443237904000232.xhtml#f0020) 所示。数据库是一个变量，其在任何状态下的实例都是事实的*集合*。因为 Adams 慢跑这一事实已经存在，如果再次添加此事实，实例将保持不变，因为集合对重复不敏感。例如，集合 {Adams 慢跑, Adams 慢跑} 与集合 {Adams 慢跑} 相同。集合仅由其成员资格定义，即使我们多次显示一个成员（即使这很不寻常），集合也不会改变。因此，如果我们将 [图 4.3](#Ch004_111-158_B9780443237904000232.xhtml#f0020) 中显示的两个事实表视为实例集合，它们是等价的。因此，接受该更新没有问题。

![图 4.3 允许此更新吗？](images/B9780443237904000232/f04-03-9780443237904.jpg)

[图 4.3](#Ch004_111-158_B9780443237904000232.xhtml#B-f0020) 允许此更新吗？

然而，从内部角度来看，当事实被添加到数据库时，它通常存储在先前未分配的空间中。因此，接受此更新将导致 Adams 慢跑这一事实被存储两次，位于不同的位置。这是 `redundancy`（冗余）的一个例子。如果发生冗余，数据库就是事实的*包*而不是事实的*集合*。包或*多重集*就像集合，只是其成员的重复是有意义的。例如，虽然集合 {1} 和 {1, 1} 相等，但包 [1] 和 [1, 1] 是不同的。

避免数据库中的冗余有助于通过简化更新的正确处理来维护其完整性。例如，假设 Adams 慢跑这一事实在数据库中存储了两次。如果我们稍后想要删除或更改此事实，则需要小心地对其两个记录实例都执行此操作。以这种方式控制冗余可能是一件麻烦事，而不受控制的冗余可能导致不一致。避免冗余的第二个原因是节省空间（计算机的存储能力是有限的）。

在实践中，为了更高效地检索信息，我们有时允许在*逻辑*模式层面上存在受控冗余。然而，对于*概念*模式设计，*概念数据库中不得发生冗余*。冗余是基本事实或存在性事实的重复。因为概念事实表的每一行对应一个事实，所以*概念事实表的任何行都不得重复*。因此，[图 4.3](#Ch004_111-158_B9780443237904000232.xhtml#f0020)(b) 中的事实表是非法的，因为 Adams 那一行重复了。

在这里，对于数据库的任何给定状态，每个人最多只能被记录一次为慢跑者。因此，事实表列中的每个条目都是*唯一*的（此列中不得出现重复项）。我们可以通过在事实角色上方或下方放置一个*横杠*来显式表示此*UC*，如 [图 4.4](#Ch004_111-158_B9780443237904000232.xhtml#f0025) 所示。

![图 4.4 唯一性约束确保条目唯一（无重复）。](images/B9780443237904000232/f04-04-9780443237904.jpg)

[图 4.4](#Ch004_111-158_B9780443237904000232.xhtml#B-f0025) 唯一性约束确保条目唯一（无重复）。

因为事实角色对应事实列，角色上的 UC 意味着事实列中的条目是唯一的。我们可以通过省略事实表，仅在概念模式图上显示约束。

每个对象角色建模（ORM）断言事实类型都有一个跨越它的隐含 UC，因为对于概念数据库的每个状态，每个断言事实实例都是唯一的。因为每个一元谓词只有一个角色，所以只能对其应用一个内部 UC。因此，断言一元谓词上的 UC 横杠是隐含的，因此可以作为显示选项省略，如 [图 4.5](#Ch004_111-158_B9780443237904000232.xhtml#f0030)(b) 所示。然而，因为二元或更长的谓词有多个角色，所以可能有多种 UC 模式适用于该谓词。因此，对于非一元谓词，需要显式声明 UC。

![图 4.5 一元基本谓词上隐含的唯一性约束可以省略。](images/B9780443237904000232/f04-05-9780443237904.jpg)

[图 4.5](#Ch004_111-158_B9780443237904000232.xhtml#B-f0030) 一元基本谓词上隐含的唯一性约束可以省略。

对于*二元*谓词，最常见的情况是在仅一个角色上有一个 UC，如 [图 4.6](#Ch004_111-158_B9780443237904000232.xhtml#f0035) 所示。这表示*该角色的事实列中的每个条目必须唯一*。另一列中允许重复条目。这里，相关政客由其姓名标识，国家由其两位字母的 ISO 代码标识（例如，“AU”代表澳大利亚）。

![图 4.6 第一角色上的唯一性约束：该列的条目必须唯一。](images/B9780443237904000232/f04-06-9780443237904.jpg)

[图 4.6](#Ch004_111-158_B9780443237904000232.xhtml#B-f0035) 第一角色上的唯一性约束：该列的条目必须唯一。

在示例事实表中，政客列中的每个值只出现一次，但国家列中的 "US" 值重复了。该约束表示对于所有可能的实例，政客列中的值是唯一的。因为每个政客在该列中最多只被引用一次，所以他或她在此事实类型中最多只与一个国家相关联。

换句话说：**每个**政客出生于**至多一个**国家。这就是该约束以*正面形式*正式*口头化*的方式。同一约束可用*负面形式*口头化为：**不可能****同一个**政客出生于**多于一个**国家。另一角色上没有 UC 可口头化为：**可能****同一个**国家是**多于一个**政客的出生地。
