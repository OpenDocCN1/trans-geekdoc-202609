
# SQL 标识符、关键字和数据类型

## 定界标识符

*定界标识符* 是一个最多包含 128 个字符的字符串，由双引号界定（即括在双引号内）。双引号内可使用任何字符，包括保留字。例如，以下均为合法的定界标识符：“customer nr”、“speed (km/h)”、“&ˆ%!!”、“date”、“group”。与常规标识符不同，定界标识符**区分大小写**（即大写字母不等同于小写字母）。例如，定界标识符 “invoiceNr”、“InvoiceNr” 和 “INVOICENR” 互不相等，但常规标识符 `InvoiceNr` 和 `INVOICENR` 是相等的。

## 字符串常量与定界标识符

在 SQL 中，字符串常量由*单*引号界定。例如，‘USA’ 可能是 `countryCode` 列中的一个值。某些商业 SQL 允许使用双引号代替，例如，“USA”。**不应提倡**这种做法，因为它与双引号用于定界标识符的现行标准用法相冲突。

在 Microsoft SQL Server 中，命令 `set quoted_identifer on` 可确保双引号仅用于定界标识符，禁止其用于界定字符串常量。SQL Server 还允许使用方括号（`[…]`）作为双引号（“…”）的替代方案。

## 保留字和关键字

在早期版本中被保留的字，在后续版本中可能不再保留。例如，名称 `avg`、`between`、`exists` 和 `sum` 在 SQL:1999 中从保留词降级为非保留关键字。*关键字* 是具有预定义含义的单词。*保留字* 是不能用作常规标识符的关键字。

如前所述，保留字可以嵌入标识符中。假设某列要存储辅导组的名称。因为 `group` 是保留字，所以我们不能直接将其（不加引号）用作列名。但是，我们可以加上引号使其成为定界标识符，或者将 “group” 包含在较长的常规标识符中（例如，“group”、`TuteGroup`、`GroupName`）。

通过检查某 SQL 方言的关键字列表，尤其是其保留字列表，可以初步了解该方言与标准的对比情况。在本书涉及 SQL 的地方，关键字通常通过**粗体**显示来区分。其他系统常使用大写，例如 “SELECT”。

## 标准数据类型

表列中输入的值属于为该列声明的*数据类型*。[表 12.4](#Ch012_539-646_B9780443237904000268_1.xhtml#t0025) 列出了某些旧版 SQL 标准的标准数据类型。此处，方括号表示可选组件。所有 SQL 方言至少支持字符串和数值类型。

### SQL:2016 和 SQL:2023 新增内容

SQL:2016 和 SQL:2023 新增了更多数据类型，例如 `tinyint` (0.0.255)、`datetime` (yyyy-mm-dd hh:mi:ss 格式)、`text` (长度可变、最大 2 GB 的字符串)、`ntext` (最大 1 GB) 和 `JSON` (JavaScript Object Notation) 数据。

### 字符串类型

在标准中，`char(n)` 表示值作为固定长度为 *n* 个字符的字符串存储。如果值不足 *n* 个字符，则追加空格以补齐长度。如果未指定大小 (*n*)，则视为仅包含一个字符的字符串。`varchar(n)` 类型的值作为最多 *n* 个字符的字符串存储。如果值较短，则不添加额外空格直接存储。`varchar(n)` 字符串还有一个“字符串结束”标记，其大小因实现而异。在估算所需存储空间时必须考虑这一点。对于长度变化不大的短字符串，`char(n)` 可能是首选。

### 国家字符集

SQL-92 允许声明各种国家字符集。使用 `nchar` 或等效的语法变体，表明字符选自指定的国家字符集。这意味着字符编码使用 *Unicode*，通常每个字符需要两字节存储，而编码标准英文字符和符号（常称为 *ASCII* 码，源自标准机构名称）过去通常每字符只需一字节。

### 数值类型

对于 `numeric` 数据类型，精度 *p* 是数字中包含的最大位数，标度 *s* 是小数点后的位数。例如，声明为 `numeric(6, 2)` 的列允许的值范围为 -9999.99 到 +9999.99。`decimal` 类型类似于 numeric 类型，只是实现有时可能提供大于 *p* 的精度。许多系统将 `numeric` 和 `decimal` 实现为同一类型。`integer`（包括 `smallint` 和 `bigint`）数据类型仅允许整数（无小数部分）。三种近似数值数据类型允许将极大或极小的数字按指定精度，以尾数乘以 10 的指数形式存储。缩写 `char`、`dec`、`int` 和 `nchar` 可分别展开为 `character`、`decimal`、`integer` 和 `national character`。

### 时间和位串类型

SQL-92 及后续标准为位串以及时间点和时间间隔提供了直接支持。除非指定 `with time zone` 选项，否则时间为本地时间。该选项包含相对于 UTC（协调世界时，旧称格林威治标准时间 (GMT)）的偏移量。提供了各种时间运算符（例如，通过用一个时间点减去另一个时间点来计算间隔）。

### SQL:1999 预定义类型和用户定义类型

在 SQL:1999 中，所有前述数据类型称为*预定义类型*。正如[表 12.4](#Ch012_539-646_B9780443237904000268_1.xhtml#t0025) 所示，SQL:1999 新增了四种预定义类型：字符大对象、国家字符大对象、二进制大对象和布尔类型（真或假）。此外，SQL:1999 还允许行类型、用户定义类型 (UDT)、*引用类型* 和 *集合类型*。行类型基本上是一系列字段的序列，可用作定义表的基础。UDT 由其名称标识，并可能包含方法规范列表。如果基于单一预定义类型，则称为*独特类型*。如果指定为属性定义列表，则称为*结构化类型*。SQL:1999 允许的唯一集合类型构造器是数组。SQL:2003 标准新增了对 `multiset`（包）作为集合类型、大整数 (`bigint`) 的支持，以及重要的是，将 `xml` 作为 SQL 中公认的数据类型（我们将在后续章节回到 `xml` 类型）。

### 商业 SQL 支持与差异

目前，大多数商业 SQL 支持所有 SQL-89 数据类型；几乎支持所有额外的 SQL-92 数据类型；支持部分 SQL:1999、SQL:2003、SQL:2016 和 SQL:2023 新增数据类型；并支持一些非标准数据类型。

存在许多差异。例如，Oracle 将 `varchar` 视为 `char`，并使用 `varchar2` 表示标准 `varchar`。SQL Server 包含许多额外数据类型，如 `money`、`smallmoney` 和 `uniqueidentifier`。大多数标准类型的范围通常由实现定义而非标准化。例如，`smallint` 的范围通常（但不总是）为 −32,768..32,767。
