关于该查询要注意的第二点是，*我们可以将常量作为* `select` *项包含在内*。此处 `select` 列表包含字符串常量“This isn”t hard”。请再次注意使用两个单引号来嵌入单引号。包含在 `select` 列表中作为项目的任何常量都将包含在查询返回的每一行中。在本例中，返回了两行。

该示例说明的第三个方面是，关键字“`as`”*可用于为* `select` *项引入别名*。该别名将作为结果表中该项列的名称出现。示例为添加到 `select` 列表中的字符串常量引入了别名“comment”。在实践中，`select` 项的别名主要用于为更复杂的表达式提供简单的名称，稍后将讨论这一点。

搜索条件可能包含项、*比较运算符* (`=`, `<>`, `<`, `>`, `<=`, `>=`) 和*逻辑运算符* (`not`, `and`, `or`)。某些 SQL 方言允许使用“<>”以外的符号表示“不等于”（例如，“ˆ=”、“!=”）。SQL Server 还包含用于“不小于”的“!<”和用于“不大于”的“!>”，它们分别等同于“>=”和“<=”。为保证可移植性，应避免使用此类非标准符号。采用与关系代数相同的优先级约定。因此，除非括号另有规定，否则*先计算比较运算符，再计算逻辑运算符*，逻辑运算符按 `not`、`and`、`or` 的顺序计算。

涉及空值时，SQL 基于*三值逻辑*运行。条件的求值结果可能为真、假或未知。更准确地说，条件是“已知为真”、“已知为假”或“未知”。*项之间的比较，如果其中一项为空，则求值结果始终为未知*。这适用于任何比较运算符（`=`, `<>`, `<` 等）。请看员工 1002 那一行，carType 记录了空值（此处显示为“？”）。对于 [Fig. 12.37](#Ch012_539-646_B9780443237904000268_1.xhtml#f0190)(a) 中的查询，条件为“null = Ford”；对于 [Fig. 12.37](#Ch012_539-646_B9780443237904000268_1.xhtml#f0190)(b) 中的查询，条件为“null <> Ford”。在这两种情况下，条件求值结果均为未知。

`where` 子句执行的选择操作*仅返回求值为真（即已知为真）的行*。求值为假或未知的行将被过滤掉。因此，员工 1002 和 1005（Jones 和 Dennis）的行在两个查询中均被过滤掉。过滤掉未知值有助于避免无根据的假设。稍后将讨论，SQL 提供了用于检测空值的特殊函数。

现在，让我们讨论如何控制结果表中列和行的*排序*。列按其在 `select` 列表中出现的顺序显示。因此，如果想要不同的列顺序，只需重新排列 `select` 列表即可。但是，显示*行*的顺序可以通过 `order by` 子句来控制。如果使用，`order by` 子句必须位于 `select` 语句的末尾。`select` 列表中的一个或多个列（按名称或按在 `select` 列表中的位置标识）可用作排序标准。

排序默认为升序。你也可以通过在列标识符后附加 `asc` 来显式指定升序。要指定降序，必须附加 `desc`。对于数值，“升序”意味着较小的数字排在前面。例如，1 < 3 < 7，因此 1、3、7 为升序。对于字符串值，“升序”意味着在排序序列中靠前的字符串排在前面。粗略地说，按字母顺序靠前的单词通常排在前面。

作为一个简单示例，[Fig. 12.38](#Ch012_539-646_B9780443237904000268_1.xhtml#f0195) 中的每个查询均可用于按员工姓名的字母顺序列出员工。虽然极不推荐，但此处 `order by` 子句中可以用“2”代替“empName”，因为 empName 是 `select` 列表中的第二项（它不必是基表的第二列）。如果稍后修改 `select` 列表，这种位置编号的用法会造成问题，使查询更难理解，并且是 SQL 标准中已弃用的特性（即可能在后续版本中移除）。因为如果需要，可以使用 `as` 来引入结果列名，所以永远不需要求助于位置编号进行排序。因此不要使用它们。

字符串按字符排序序列进行排序。例如，如果使用 ASCII，则空格（“ ”）排在数字（0..9）之前，数字排在大写字母（A..Z）之前，大写字母排在小写字母（a..z）之前。例如，在 ASCII 中，“M2” < “MY” < “Ma” < “Ma Kettle” < “MacTavish” < “Zen” < “apple”。不过，其他排序序列可能与此不同。例如，在 EBCDIC 中，小写字母排在大写字母之前，大写字母排在数字之前。
