Apart from the methods discussed, an online appendix discusses two matrix algorithms to deduce the configuration of a subtype graph from a population significant in this regard. ## 6.6 Generalization of Object Types

The previous section discussed a specialization procedure in which subtypes of a more general object type are introduced to declare that specific roles are recorded only for these subtypes. Apart from this top-down procedure, a subtype graph may also arise in a bottom-up way when we need to introduce a supertype of object types that already occur in the model.

The process of introducing a supertype for object types that already exist is known as object type *generalization*. Hence, generalization is the reverse of specialization. A supertype is a more general form of its subtypes, and a subtype is a special form of its supertype(s).

Step 3 of the CSDP outlined the main reasons for generalizing existing object types (e.g., `Doctor`, `Physiotherapist`, `Pharmacist`) into a more general type (e.g., `Practitioner`). If the original object types have specific roles not played by the generalized type, we need to retain them as subtypes. For example, consider [Fig. 6.55](#Ch006_211-271_B9780443237904000025.xhtml#f0280). Here, name and gender are recorded for each kind of practitioner. In this case, a practitioner type is already suggested by the common identification scheme (`PractitionerId`), but this type has not yet been introduced.

![Fig. 6.55 A schema before generalization has been applied.](images/B9780443237904000025/f06-55-9780443237904.jpg)

[Fig. 6.55](#Ch006_211-271_B9780443237904000025.xhtml#B-f0280) A schema before generalization has been applied.

If we want to list all the practitioners together in a query, then we should introduce a `Practitioner` supertype, attach the common roles to it, and add a fact type to retain the classification scheme (see [Fig. 6.56](#Ch006_211-271_B9780443237904000025.xhtml#f0285)). This assumes pharmacists, physiotherapists, and doctors are mutually exclusive. If a global identifier for the supertype does not already exist, (e.g., `PractionerId`), then we should introduce one.

![Fig. 6.56 The schema after generalization has been applied.](images/B9780443237904000025/f06-56-9780443237904.jpg)

[Fig. 6.56](#Ch006_211-271_B9780443237904000025.xhtml#B-f0285) The schema after generalization has been applied.

The original schema shows that prescriptions are prescribed only by doctors, and dispensed only by pharmacists. These constraints are retained in the new schema by using `Doctor` and `Pharmacist` subtypes for the prescription predicate. Here, physiotherapists have no specific role, so we don't introduce a subtype for them.

`Doctor`, `pharmacist`, and `physiotherapist` are mutually exclusive, but were generalized partly because of their common roles (having a gender and a name). In practice, further common information would normally be recorded (e.g., phone number, address, birth date), making this generalization more worthwhile.
