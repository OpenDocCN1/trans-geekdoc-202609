

## 17.2 键值存储

键值数据存储是一种 NoSQL 数据库，因其灵活性和可扩展性而日益流行。与传统的关系型数据库不同，键值存储不对大多数数据使用固定模式。相反，数据以键值对集合的形式存储，其中键用于唯一标识数据，值则是实际数据。这种类型的数据存储对于需要快速、高效的数据访问和检索的应用程序特别有用。

如今市场上有许多商业键值数据存储可供选择，此外还有一些虽然不以键值存储为卖点，但提供类似功能的产品。`Redis` 是一种内存数据结构存储，用于数据库缓存、消息代理和实时分析。它以速度快和用途广泛著称，常被用作分布式缓存。`RiakKV` 是一种高可用性分布式键值数据存储，设计为容错且可扩展。`Apache HBase` 是一种开源、分布式的键值存储，构建在 Hadoop 分布式文件系统 (`HDFS`) 之上。它专为大规模、随机读/写访问大数据而设计，并以 Google 的 BigTable 方法为蓝本。`Amazon DynamoDB` 是由 Amazon Web Services (`AWS`) 提供的全托管键值数据存储。它提供数据复制、静态加密和灵活的索引选项等功能。

键值存储的主要特性是其概念上的简单性。它们建立在众所周知的 `哈希` 技术之上，提供了一种访问数据值的一致方式，这些数据值不一定具有规则格式。值保存在一种专用结构中，用户可以暂时忽略其内部细节。值与唯一键关联，该键提供了一种在结构中定位值的方法。使用哈希函数，给定一个键，即可直接或间接（使用某种形式的指针）访问相关的值。

许多编程语言都支持此类结构。术语因语言而异，这些结构可能被称为哈希映射、哈希表、字典、关联数组等。术语的使用也不一致，因此精确的定义仅在特定语言的上下文中才相关。例如，`Python` 使用术语 `dictionary` 来指代包含键值对的结构。在较新版本的 `Python` 中，项按键值排序，但这在其他语言的等效结构中不一定成立。`JavaScript` 可以简单地使用 JSON 风格的 Object 实现相同目的。尽管语法不同，所有这些编程方法都支持大致相当范围的操作，例如：

*   插入项 (`key`, `value`)
*   更新值 (`key`, `new value`)
*   删除项 (`key`)
*   检索值 (`key`)
*   测试是否存在 (`key`)

大多数语言允许存储的值类型为该语言中可表达的任何内容，范围从简单类型（数字、字符串等）到具有自身内部结构的项，如对象、列表，甚至可能是进一步的字典。虽然这些结构可在程序内部使用，但无法直接从程序外部访问，如有需要必须以某种形式导出，例如 `JSON`。

程序内的数据显然会在程序终止时消失，因此键值存储在持久化存储中提供了等效功能。这也使得数据可从许多不同的程序访问（假设有合适的语言绑定）。

我们可以使用关系型数据库来近似一个键值数据库，只需定义一个类似于以下 SQL 片段的单表：

```
create table myKV (  theKey varchar(20) primary key,  theValue BLOB )
```

此处假设键是最多 20 个字符的字符串，但也可使用任何 SQL 数据类型。此处的值是 `BLOB` 数据类型，用于包含未经数据库解析的未分化二进制数据。在某些 SQL 方言中，`BLOB` 可替换为 `varbinary()` 等其他类型。

键值存储与关系型数据库的区别在于，它们仅专注于完整数据单元的高效存储和检索。数据存储可以忽略数据单元的内部结构，将其视为单个项目。这消除了对复杂查询的支持需求，因为仅需的基本操作是写入和读取单个数据单元。数据存储不再负责理解信息的内部值、数据类型和结构。该责任现下放给使用它的应用程序。对内部数据结构的任何更改、添加或删除值，对数据存储没有影响，尽管显然会影响任何相关应用程序。

除了使存储和检索更高效外，这种扁平结构还极大地简化了数据存储的设计和实现，因为其模式可以非常简单。但重要的是要记住，对详细模式的需求并未完全消失——它只是从数据存储转移到了应用程序。

虽然键值存储擅长快速检索数据单元，但某些存储也提供在单元内部操作数据值的特定方式，例如向字符串追加内容、向列表推入元素、获取有序集合中排名最高的成员。如果数据单元的内容以某种结构化形式（如 `JSON` 或 `XML`）编码，则可提供相应设施以适当方式查询内容。

键值存储非常适合分布式部署，其流行度的上升与云计算作为可行平台的出现同步，这恐怕并非巧合。通过跨许多服务器进行水平分区，每个服务器处理自己的键值子集，数据存储几乎可以无限扩展。通过复制，可在不同服务器上保存多个副本并通过适当的负载均衡机制访问，从而提高弹性和性能。

分布式并不适用于所有情况；一些键值存储设计为驻留内存，以提供最快的检索速度。固态硬盘比旧式硬盘快约 100 倍，但 `RAM` 还要快几个数量级。分布式对内存存储而言问题更大，但可以找到混合解决方案。例如，可使用内存存储在基于应用程序的键和基于服务器的键之间提供查找，后者可用于访问分布式键值存储。
