
The `select` list chooses the result columns, the `from` clause declares the source tables and joins, the `where` clause is used to filter out rows, the `group by` clause forms groups of rows, the `having` clause is used to filter out groups, and the `order by` clause determines the order of rows.

A *subquery* is a parenthesized `select` query inside an outer query. If the subquery has a condition that refers to the outer query, it is a *correlated* subquery. A subquery after an `exists` quantifier is an existential subquery. An `exists` condition is true if the subquery returns a row, and false otherwise. The three most common forms of conditions with an embedded subquery are as shown, where Θ is a comparison operator.

*   ```
    expression [not] in (subquery)                                            - - membership subquery
    ```

*   ```
    expression Θ [all | some | any] (subquery)         - - [quantified] comparison subquery
    ```

*   ```
    exists (subquery)                                                                                - - existential subquery
    ```

Table populations may be changed using `insert`, `update`, and `delete` statements, with the following basic syntax.

*   ```
    insert into tablename [ (col-list) ]
    ```

*   ```
           {values (constant-list) | select-query}
    ```

*   ```
    update tablename
    ```

*   ```
    set colname = expression   [, …]
    ```

*   ```
          [where condition]
    ```

*   ```
    delete from tablename
    ```

*   ```
       [ where condition ]
    ```

### Chapter Notes

Relational algebra is covered in most database texts, e.g., [Elmasri and Navathe (1994)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0365), [Date (2000)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0300). Arithmetic operators, set functions, semijoin and other operators have been proposed to extend the relational algebra, e.g., [Date (2000)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0300), sec. 6.7. As an alternative to the relational algebra, the relational calculus may be used, e.g., [Date (2000)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0300), [ch. 7](#Ch007_273-308_B978044323790400013X.xhtml). [Codd (1990)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0235) proposed version 2 of the relational model, with 333 rules, but this has not achieved any significant adoption.

The SQL standard is published by the International Standards Organization ([*www.iso.org*](http://www.iso.org)), At the time this book was published, the current version (SQL:2023) is ISO/IEC 9075-2:2023); see [https://www.iso.org/standard/76584.html](https://www.iso.org/standard/76584.html), and press the Preview button to browse the publicly available informative sections. For a clear, thorough account of the SQL-92 standard, see [Date and Darwen (1997)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0305), and for SQL:1999 see [Melton and Simon (2002)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0990).

The original SEQUEL language, described in [Chamberlin and Boyce (1974)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0205), was itself based on an earlier relational language called “SQUARE”. [Chamberlin (1998)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0200) provides very readable coverage of DB2, with Section 1.3 sketching an authoritative, early history of SQL, including an explanation for why SQL permits duplicate rows in base tables.

For a readable and practical discussion of many kinds of advanced queries in SQL, see the series of books by [Celko (1999](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0180), [2000](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0185), [2004](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0190), [2005)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0195). An in-depth critique of SQL and an alternative theoretical foundation for object-relational databases are provided by [Date and Darwen (1998)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0310).

For recent coverage of SQL fundamentals as well as how to use SQL with different DBMSs such as Oracle, MySQL, PostgreSQL, and SQL Server, see [Taylor (2018)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb1220) and [Zhao (2021)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb1335). For comprehensive coverage of Oracle up to version 11 g, see [Greenwald et al. (2013)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0500).

SQL Server is covered in many books, such as [Syverson and Murach (2023)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb1215). *SQL Server Pro Magazine* (formerly called *“SQL Server Magazine”*) is a good source of technical articles on SQL Server ([www.sqlmag.com](http://www.sqlmag.com)).
