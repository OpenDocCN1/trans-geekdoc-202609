
在之前的示例中，外部唯一性约束底层的连接路径仅涉及一次连接。但在实践中，*连接路径*可能涉及多个内连接或外连接。[图 10.3](#Ch010_401-479_B9780443237904000244.xhtml#f0020) 总结了*连接路径歧义*问题。要找到外部唯一性约束底层的连接路径，我们需要找到一条连接角色 r2 和 r9 的路径，从 r2 向右移动，从 r9 向左移动。

![图 10.3 连接路径可能需要显式声明连接角色。](images/B9780443237904000244/f10-03-9780443237904.jpg)

[图 10.3](#Ch010_401-4780443237904000244.xhtml#B-f0020) 连接路径可能需要显式声明连接角色。

我们的选择已加阴影标出，但在 *B* 和 *C* 之间存在三条可能的路径。我们可以遍历顶部谓词，执行连接 `r2 = r3` 和 `r4 = r9`。我们可以遍历隐含在子类型连接下的中间谓词，执行连接 `r2 = r5` 和 `r6 = r9`，或者我们可以遍历底部谓词，执行连接 `r2 = r7` 和 `r8 = r9`。

ORM 不会以图形方式高亮显示相关连接（此处通过阴影演示）。一般来说，阴影标注是不够的，因为路径可能会多次遍历同一个谓词。一种通用的图形解决方案是对用于执行连接的角色进行编号，但这可能导致图表混乱。工具可以提示用户选择连接角色列表，然后在用户控制下切换连接的显示/隐藏。另一种替代方案是使用文本语言来制定具有多个候选连接路径的约束。NORMA 专业版提供了对连接路径的正式支持。

对于非 ORM 方法，需要基本的外部唯一性支持，然后连接路径可以像 ORM 一样以图形方式消除歧义，或者如果该方法包含足够强大的形式化查询语言，则以文本方式消除歧义。UML 可以使用对象约束语言（OCL）进行此类规范，尽管 OCL 表达式对非技术领域专家来说通常显得晦涩难懂。

正如外部唯一性约束一样，外部频率约束也有底层的连接路径。如果连接涉及可选角色，则假定为内连接。例如，[图 10.4](#Ch010_401-479_B9780443237904000244.xhtml#f0025) 中的外部频率约束仅适用于作为共同摄政王的政治家，因此其语言化表述为：**对于每个** Country，**至多有** 2 **个** Politician 实例，**使得该** Politician **是** 共同摄政王 **并且** 在 **该** Country 的政府中任职。

![图 10.4 涉及一元事实类型的外部频率约束。](images/B9780443237904000244/f10-04-9780443237904.jpg)

[图 10.4](#Ch010_401-479_B9780443237904000244.xhtml#B-f0025) 涉及一元事实类型的外部频率约束。

回顾一下，ORM *集合比较约束*在兼容的角色序列之间应用子集、等值或排斥约束。有时这些角色序列中的一个或多个是从连接路径投影而来的。作为一个简单示例，[图 10.5](#Ch010_401-479_B9780443237904000244.xhtml#f0030)(a) 中的连接子集约束从组成“Advisor serves in Country”事实类型的角色对，运行到组成“Advisor speaks Language”和“Country uses Language”事实类型的第一角色的角色对。

![图 10.5 (a)、(c) ORM 和 (b)、(d) UML 中的连接子集约束。](images/B9780443237904000244/f10-05-9780443237904.jpg)

[图 10.5](#Ch010_401-479_B9780443237904000244.xhtml#B-f0030) (a)、(c) ORM 和 (b)、(d) UML 中的连接子集约束。

该约束意味着填充“serves-in”谓词的顾问-国家对集合，必须是通过在连接路径“Advisor speaks Language **that** is used by Country”上投影顾问和国家角色获得的顾问-国家对集合的子集。

[图 10.5](#Ch010_401-479_B9780443237904000244.xhtml#f0030)(a) 中的连接路径在 Language 上涉及一个概念性的内连接，将扮演其两个角色的实例等同起来。换句话说，如果一位顾问在某个国家任职，则该顾问必须会说该国家使用的至少一种语言。该约束可以在 ORM 中正式语言化为：**每个** 在 **某个** Country 任职的 Advisor **也** 会说 **某个** 被 **该** Country 使用的 Language。

像 ER 一样，UML 没有用于表达连接子集约束的图形符号，但确实允许将约束以文本形式表达在附加到相关模型元素（在本例中为三个关联）的注释中，如[图 10.5](#Ch010_401-479_B9780443237904000244.xhtml#f0030)(b) 所示。ER 也可以改编为允许此类注释用法。

[图 10.5](#Ch010_401-479_B9780443237904000244.xhtml#f0030)(c) 显示了本书前面讨论的另一个示例。该约束可以在 ORM 中这样语言化：**如果某个** Employee **拥有某个** 受限于 **某个** Gender 的 PersonTitle，**则该** Employee **属于** 该 Gender。示例种群说明了头衔-性别限制。

如果将 personTitle 建模为属性，则无法在 UML 中表达头衔-性别限制。但是，如果我们将 PersonTitle 建模为类并为该限制附加注释，则可以在 UML 中建模，如[图 10.5](#Ch010_401-479_B9780443237904000244.xhtml#f0030)(d) 所示。附加到 Employee 类的注释用 OCL 正式捕获了头衔-性别限制。

连接子集约束在实际应用中经常出现。关于涉及三元事实类型的更复杂的连接子集，请回顾[图 9.42](#Ch009_347-399_B9780443237904000013.xhtml#f0215) 中的会议室设施示例。

*连接等值约束*较少见。[图 10.6](#Ch010_401-479_B9780443237904000244.xhtml#f0035) 中的 ORM 模式包含角色三元组之间的等值约束，其中第一个三元组涉及对象化关联上的连接。此处显示角色编号是为了阐明约束参数（NORMA 工具仅在输入或选择约束时显示这些编号）。该约束捕获了这样一条规则：小费必须针对赚取小费的那些服务进行报告，且仅针对那些服务。

![图 10.6 连接等值约束。](images/B9780443237904000244/f10-06-9780443237904.jpg)

[图 10.6](#Ch010_401-479_B9780443237904000244.xhtml#B-f0035) 连接等值约束。

[图 10.6](#Ch010_401-479_B9780443237904000244.xhtml#f0035) 中的连接等值约束捕获了这样一条规则：任何人都不能评审来自自己机构的人员撰写的论文，这条规则在学术会议中通常被强制执行。为了避免图表杂乱，NORMA 工具仅在输入或选择约束时显示角色编号。约束语言化也可用于阐明约束的含义。

[图 10.7](#Ch010_401-479_B9780443237904000244.xhtml#f0040) 中的 ORM 模式包含两个角色对之间的*连接排斥约束*。每个角色对都从涉及 Person 上连接的路径投影而来。角色对编号为 1.1、1.2 和 2.1、2.2。由于 Institute 扮演的角色出现在两个角色对中，因此它被编号了两次。

[图 10.7](#Ch010_401-479_B9780443237904000244.xhtml#B-f0040) 连接排斥约束。

针对集合比较约束中涉及的每个连接路径，都可以提出与外部唯一性和频率约束底层连接路径相同的考量。虽然我们已经建模了许多涉及连接集合比较约束的业务领域，但连接类型始终是内连接。外部环约束以及值比较约束也可能涉及连接。对于值比较约束，连接类型始终是内连接。
