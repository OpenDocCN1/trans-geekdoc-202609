
然而，如果我们想要记录的恶习集合经常发生变化，两表方案可能更可取，因为它无需更改模式本身即可适应此类变化。关于执行此类优化的指南将在本章后面给出。如果优化后的概念模式仍无法提供高效的映射，则可能需要进行一些反规范化，如[第 14.7 节](#Ch014_681-771_B9780443237904000189.xhtml#s0070)所述。

在重构工程中，优化是应用于现有数据库的。因此，在模式本身转换之后，我们还有将存储在原始数据库中的信息迁移到新模式中的*数据迁移*这一额外任务。如果没有自动化工具的协助，这项任务可能既漫长又繁琐。

下面是将[图 14.3](#Ch014_681-771_B9780443237904000189.xhtml#f0020)(b) 中填充的两表模型转换为[图 14.3](#Ch014_681-771_B9780443237904000189.xhtml#f0020)(a) 中单表模型的一种基本方法，假设使用的是结构化查询语言 (SQL) 数据库。首先，使用以下语句向 `Patient` 表添加一个可选的 `isSmoker` 列：

```
alter table Patientadd column isSmoker char check (isSmoker in (‘Y’,’N’))
```

此时，`isSmoker` 列填充的是空值。检查约束未被违反，因为其计算结果为 unknown（未知）（而不是 false）。现在，添加适当的“Y”或“N”值以指示谁吸烟：

```
update Patientset isSmoker = casewhen patientNr in      (select patientNr from Indulges where vice = ‘S’)then ‘Y’else ‘N’end
```

现在，使 `isSmoker` 列成为强制性的：

```
alter table Patientadd constraint isSmokerNonNull check (isSmoker is not null)
```

同样，向 `Patient` 表添加 `isDrinker` 列，更新其填充数据，最后删除 `Indulges` 表。在实践中，迁移数据的最高效方式可能取决于所使用的数据库管理系统 (DBMS)。与刚才讨论的简单示例相反，更典型的做法是保持原始数据库不变，创建一个新模式，将数据迁移到新模式，然后删除原始数据库（参见[第 14.9 节](#Ch014_681-771_B9780443237904000189.xhtml#s0090)）。

这完成了我们对模式等价和优化基本概念的高层介绍。以下章节将进一步展开这些概念，同时也简要阐述规范化理论。

## 14.2 谓词特化与泛化

上一节指出了相同的 UoD 结构如何能用不同的等价模式来描述，并讨论了将一种模式重塑为另一种模式的转换。本节讨论一类称为**谓词特化**的模式转换，以及其逆操作**谓词泛化**。

如果两个或多个谓词可被视为一个更泛化谓词的特殊情况，则我们可以用该更泛化的谓词来替换它们，只要原来的区别能以某种方式保留下来即可。例如，如果我们将[图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(a) 的模式转换为[图 14.1](#Ch014_681-771_B9780443237904000189.xhtml#f0010)(b) 的模式，我们就将吸烟和饮酒*泛化*为沉溺于恶习，其中恶习有两种特定情况。如果我们按相反方向转换，则将沉溺于恶习*特化*为两个谓词，每个情况对应一个。

谓词特化和泛化与对象类型特化和泛化是相似的概念，不同之处在于很少在谓词之间指定任何子类型联系（为此谓词必须被对象化）。

如果*值约束*或*频率约束*表明某谓词具有有限数量的情况，则该谓词可以被特化。带有值约束的示例更常见，因此我们首先考察这些示例。吸烟者-饮酒者示例提供了一个说明，其中 `Vice` 具有值约束 {“S”, “D”}。作为另一个示例，回顾[图 14.4](#Ch014_681-771_B9780443237904000189.xhtml#f0025)(a) 中复现的奥林匹克运动会模式。

![Fig. 14.4 The ternary is specialized into three binaries by absorbing MedalKind.](images/B9780443237904000189/f14-04-9780443237904.jpg)

[图 14.4](#Ch014_681-771_B9780443237904000189.xhtml#B-f0025) 通过吸收 `MedalKind`，三元谓词被特化为三个二元谓词。

奖牌恰好有三种，因此如[图 14.4](#Ch014_681-771_B9780443237904000189.xhtml#f0025)(b) 所示，三元谓词可被特化为三个二元谓词，每种奖牌一种。您可以将从模式 (a) 到模式 (b) 的转换可视化为将对象类型 `MedalKind` *吸收* 进三元谓词，以将其划分（或特化）为三个二元谓词。因此，这种转换也称为*对象类型吸收*。

从 (b) 到 (a) 的逆向转换通过提取对象类型 `MedalKind` 将三个二元谓词泛化为三元谓词——这可称为*对象类型提取*。在恶习示例中，一个二元谓词被特化为一元谓词。在运动会示例中，一个三元谓词被特化为二元谓词。一般来说，当一个 *n* 值对象类型被吸收进一个谓词时，产生的 *n* 个特化谓词每个都比原谓词少一个角色（因为对象类型已被吸收）。

虽然等价关系是以图表形式列出以辅助理解，但存在将图表形式映射为谓词逻辑的形式化映射，实际的等价证明是在其中进行的（[Halpin, 1989b](#Ch014_681-771_B9780443237904000189.xhtml#bb0535)）。从这个意义上说，这些结果可称为定理。这一通用结果列于[图 14.5](#Ch014_681-771_B9780443237904000189.xhtml#f0030)。

![Fig. 14.5 PSG1: R may be specialized into S1 … Sn by absorbing B.](images/B9780443237904000189/f14-05-9780443237904.jpg)

[图 14.5](#Ch014_681-771_B9780443237904000189.xhtml#B-f0030) PSG1：通过吸收 *B*，*R* 可被特化为 *S*[1] … *S*[*n*]。

[图 14.5](#Ch014_681-771_B9780443237904000189.xhtml#f0030) 中的模式等价称为*谓词特化/泛化定理 1* (PSG1)。谓词 *R* 和 *S* 分别具有 *m* + 1 个角色和 *m* 个角色，其中 *m* ≥ 1。对象类型 *A*[1] … *A*[*m*] 和 *B* 不一定是不同的。*B* 的值类型具有 *n* 个值 *b*[1], …, *b*[*n*]。如果 *m* = 1，则是在二元谓词与 *n* 个一元谓词之间转换；如果 *m* = 2，则是在三元谓词与 *n* 个二元谓词之间转换；以此类推。从左向右转换通过吸收对象类型 *B* 将谓词 *R* 特化为 *n* 个谓词 *S*[1] … *S*[*n*]。从右向左的逆向转换通过提取 *B* 将较短的谓词泛化为较长的谓词。作为练习，绘制 *m* = 1、2 和 3 时的图表。

无论添加什么额外约束，定理 PSG1 都成立。但是，*添加到其中一个模式的任何约束都必须转换为另一个模式上等价的额外约束*。例如，[图 14.4](#Ch014_681-771_B9780443237904000189.xhtml#f0025)(a) 中的唯一性约束转换为[图 14.4](#Ch014_681-771_B9780443237904000189.xhtml#f0025)(b) 中的三个较短的唯一性约束。这是 PSG1 的以下推论的一个实例（使用“UC”代表“唯一性约束”，并将“spans”读作“精确跨越”）。

*   如果 *R* 中的一个 UC 跨越了 *B* 的角色与其他角色的组合，则 *S*[1] … *S*[*n*] 中这些其他角色的特化上跨越一个 UC；反之亦然。
