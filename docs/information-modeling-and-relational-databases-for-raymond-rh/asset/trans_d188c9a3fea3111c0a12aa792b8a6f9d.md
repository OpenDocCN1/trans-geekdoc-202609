
# 1.4 相关技能

由于关系数据库系统仍占主导地位，它们是我们实现讨论的主要焦点，同时也会对 XML 和其他系统给予一定关注。尽管面向数据库的概念接口仍处于起步阶段，但在这种更高层级上开发模型效率更高，且能避免浪费时间去获取将迅速过时的知识和技能。请考虑电子计算器对学校数学课程的影响（例如，通用开平方算法的移除）。

从根本上说，与信息系统交互始终需要两项核心技能。这两项技能都涉及就我们的特定应用领域与系统进行*沟通*。回顾一下，应用领域在技术上被称为 *UoD*。这两项要求是：

*   **描述** UoD
*   **查询** 关于 UoD 的系统

第一项技能包含描述 UoD 的*结构*或*设计*，以及描述其*内容*或*实例数据*：结构方面是唯一具有挑战性的部分。如果您希望向系统添加模型，清晰描述应用领域的能力至关重要。复杂的模型通常应由专家建模人员与领域专家合作编制。本书的主要目的是介绍信息建模的基础知识。如果您掌握了书中讨论的方法，您将顺利踏上成为信息系统建模专家的道路。

使用 `4GL` 发出查询通常很容易，但复杂查询的构思仍然可能很困难。偶尔，理解系统给出的某些答案需要了解系统的工作原理，特别是其局限性。本书为理解关系结构和查询提供了概念基础，解释了关系查询语言背后的代数原理，并包含了可靠的 `SQL` 入门介绍。

无论信息系统多么复杂，如果我们给它提供了错误的 UoD 图景，就不能指望从中获得多少有意义的输出。这是垃圾进垃圾出（`GIGO`）原则的一个方面。数据库应用程序的大多数问题源于糟糕的数据库设计。本书展示了如何使用自然概念在极高层级上对信息进行建模。在充分关注 `ER` 和 `UML` 等流行数据建模方法的同时，它还深入探讨了更高层级的 `ORM` 方法。

概念模式可以映射到当今数据库系统使用的低层级结构上。这种映射可以使用适当的 `CASE` 工具自动执行，也可以使用适当的过程手动执行。本书讨论了如何将概念模型映射到关系数据库系统和其他一些结构（例如 `XML` 模式），以及如何使用查询语言从这些系统中检索数据。它还讨论了其他方法和现代趋势。

# 1.5 概要

本章为概念建模提供了动机，并简要介绍了信息系统的历史和结构概览。`DBMSs` 广泛应用于以信息为导向的企业，是主要的生产力工具。为了有效使用数据库，其数据应当正确、完整且可高效访问。这要求数据库设计良好。

设计数据库涉及构建业务领域或 UoD 的形式化模型。要正确做到这一点，需要对 UoD 有良好的理解，并有一种清晰、无歧义地指定这种理解的方法。`ORM` 通过使用自然语言、直观的图表和示例，并从简单的*基本事实*角度审视信息，简化了分析和设计过程。通过用诸如*对象*和*角色*等自然概念来表达模型，这种面向事实的方法提供了一种真正*概念化*的建模途径。

其他有价值的建模方法包括 `ER` 建模和面向对象建模。在实践中，`ER` 仍然是数据库设计最流行的高层方法。虽然存在许多流行的 `ER` 版本，但 `UML` 无疑是最具影响力的面向对象方法。

尽管 `ER` 和 `UML` 模型通常比 `ORM` 模型更紧凑，但它们在构思、转换或演进概念信息模型方面，可以说不如 `ORM` 合适。`ER` 模型和 `UML` 类图离自然语言更远，缺乏基于角色的约束符号的表达力和简洁性，面对领域演进时稳定性较差，用事实实例填充更困难，并且可能隐藏将模型粘合在一起的语义域信息。然而，`ER` 和 `UML` 模型通过将当前不太重要的特征表示为属性，能更好地突出所建模领域的主要特征。
