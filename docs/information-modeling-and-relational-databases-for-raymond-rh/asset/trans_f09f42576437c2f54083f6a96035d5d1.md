

## 18.5 进一步的设计层面

另一种抽象机制是*对象类型缩放*。在此，建模者选择一个感兴趣的对象类型，使显示聚焦于该对象类型及其直接*邻域*。对象类型将连同其所有事实类型一起显示。通过为缩放指定*逻辑半径*（例如，以谓词单位计），邻域可扩展以包含第一级缩放中对象类型的事实类型，依此类推。

ActiveQuery 使用此机制逐步向用户展开视野，为当前高亮的对象类型显示一谓词半径的邻域。NORMA 工具也为此提供了一个上下文窗口，允许扩展至三个谓词长度。

一个简单的例子将有助于说明抽象的一些基本方式。[图 18.8](#Ch018_935-1005_B9780443237904000104.xhtml#f0045) 描绘了一个小型应用的 ORM 模式。在此，电影由编号标识，尽管其标题和导演的组合也是唯一的。有些电影基于另一部电影。例如，西部片《豪勇七蛟龙》基于早期的日本电影《七武士》。

![图 18.8 一个小型但详细的 ORM 模式。](images/B9780443237904000104/f18-08-9780443237904.jpg)

[图 18.8](#Ch018_935-1005_B9780443237904000104.xhtml#B-f0045) 一个小型但详细的 ORM 模式。

如果有电影票房收入数据，则予以记录；如果净利润已知，也一并记录。该应用中唯一感兴趣的人员是电影导演和电影明星。我们记录他们的出生国，以及已知的出生日期。电影的制作国家以及其出口国家也会被记录。

作为一个思维练习，想象逐个关闭[图 18.8](#Ch018_935-1005_B9780443237904000104.xhtml#f0045) 上约束类型的显示（环状约束、集合比较约束、强制角色约束、唯一性约束），以通过剥离约束层来直观感受抽象。

[图 18.9](#Ch018_935-1005_B9780443237904000104.xhtml#f0050) 描绘了对象类型 Person 的缩放视图，逻辑半径为 1，因此仅显示直接连接到 Person 的事实类型。为突出缩放的对象类型，对其使用了较粗的线条。请自行想象对 Country 进行缩放的情形；这将显示三个事实类型，其中一个也包含在 Person 的缩放视图中。

另一种在大型 ORM 模式中特别有用的抽象机制是基于*主要对象类型*的*细化层级*。这可以结合*属性抽象*使用，以提供 ER 模式或 UML 类图。

在开发概念模式时，平等对待所有对象类型很有用，因为对象类型的相对重要性取决于它在全局模式中扮演的所有角色。然而，一旦模式完成，该信息即可获得，并可用于确定哪些是最重要的或*主要对象类型*。[Campbell 和 Halpin (1993)](#Ch018_935-1005_B9780443237904000104.xhtml#bb0140) 开发了一种确定 ORM 模式中主要对象类型的程序，并将其作为生成外部用户界面默认屏幕窗体的基础（因为应用屏幕基本上使用户能够对主要对象执行操作）。

一旦确定了主要对象类型，ORM 图即可提升到更高的抽象层级。例如，我们可以选择仅显示*主要事实类型*（即至少有两个角色由主要对象类型扮演的事实类型）。对于大型模式，此图本身可接受相同的程序，产生更高层级的抽象，依此类推，直到获得顶层视图。只要完整的详细模式可访问，这种自底向上的抽象即可逆转，允许顶层视图逐步细化至详细的底层。

[图 18.8](#Ch018_935-1005_B9780443237904000104.xhtml#f0045) 中的详细模式图有六个对象类型：Movie、MovieTitle、Person、MoneyAmount、Country 和 Date。直观上，这些在该领域中并非同等重要。哪些是主要对象类型？除了凭直觉判断，你还可以利用约束模式来辅助决定。特别是强制角色约束和唯一性约束相关。如果一个对象类型具有*显式*强制角色，则它是主要的。通常，扮演函数角色的对象类型也是主要的，但这并不总是成立（例如，即使 MovieTitle 的角色是函数式的，它仍是次要对象类型；其角色仍只是隐式强制的）。

确定主要对象类型有一些更细微的要点，但以上足以掌握基本概念。基于前述推理，[图 18.8](#Ch018_935-1005_B9780443237904000104.xhtml#f0045) 只有两个主要对象类型：Movie 和 Person。[图 18.10](#Ch018_935-1005_B9780443237904000104.xhtml#f0055) 通过仅显示主要事实类型，提供了应用的一个概览。

![图 18.10 仅显示主要事实类型。](images/B9780443237904000104/f18-10-9780443237904.jpg)

[图 18.10](#Ch018_935-1005_B9780443237904000104.xhtml#B-f0055) 仅显示主要事实类型。

如果需要，次要事实类型可以不被隐藏，而是以主要对象类型的*属性*形式查看。尽管这种属性视角隐藏了结构信息（例如，域和某些约束），但获得的 ER 或 UML 图提供了一个紧凑的图景，便于快速概览。[图 18.11](#Ch018_935-1005_B9780443237904000104.xhtml#f0060) 显示了当前示例的 UML 类图。与大多数 ER 表示法不同，UML 允许在需要时指定属性域，并且缺失的约束（此处为析取强制、子集、排除、外部唯一性和非对称约束）可以在备注中记录，尽管这会牺牲紧凑性。

![图 18.11 从图 18.8 抽象出的 UML 类图。](images/B9780443237904000104/f18-11-9780443237904.jpg)

[图 18.11](#Ch018_935-1005_B9780443237904000104.xhtml#B-f0060) 从[图 18.8](#Ch018_935-1005_B9780443237904000104.xhtml#f0045) 抽象出的 UML 类图。

请注意，此处国家信息以属性（单值和多值）形式显示，而非作为与 Country 类的关联。这是因为 Country 在原始 ORM 模式中是次要对象类型。如果相反，Country 扮演显式强制角色或未被吸收的函数角色，它将成为主要对象类型，我们将把它显示为一个类。这通常是成立的（例如，我们通常存储国家的代码和名称）。

基于属性的图可通过隐藏所有属性变得更紧凑。例如，[图 18.12](#Ch018_935-1005_B9780443237904000104.xhtml#f0065) 以 UML 和 Barker ER 表示法仅显示主要事实类型。同样，一些 ORM 约束缺失（包含或约束和非对称约束）。通过使用 ORM 实际生成此类图表，或详细的 UML 和 ER 图表，我们可以保留 ORM 的优势（例如，用于验证和完整性），并在需要时仍拥有紧凑的视图。
