角色上的*双唯一性标记*表示扮演相邻角色的实体类型的*首选引用方案*（指示*首选标识符*或*主标识符*）。在本例中，姓氏是识别人的首选方式，厘米值是引用长度的首选方式。

在本例中，引用给定实体类型的实例只有一种方式。然而，一般而言，对象角色建模（ORM）允许同一实体类型有多种引用方案；在这种情况下，最终需要选择其中一种作为首选引用方案。

本书讨论的第二代 ORM 在显示基于单位的引用模式时会附加一个冒号“:”（例如 `cm:`），并要求每个单位都有一个*单位维度*（例如 Length）。

由于基于单位的引用模式总是可以访问单位维度，因此在列出事实类型时，可以使用对应于单位维度所扮演角色的特定对象类型，而不使用底层的单位维度。例如，我们当前的示例可以重新建模为 [图 5.17](#Ch005_159-209_B9780443237904000098.xhtml#f0090)(a) 所示。ORM 工具对单位维度的显示可以随意切换开/关。开启切换的选择显示在 [图 5.17](#Ch005_159-209_B9780443237904000098.xhtml#f0090)(b) 中。

与顶层实体类型不同，值类型之间可能相互重叠。例如，此处 Surname 和 CityName 的取值集发生重叠，因为两者都包含字符串“Brisbane”。

假设 [表 5.3](#Ch005_159-209_B9780443237904000098.xhtml#t0020) 中的数据和一种适当的查询语言，请考虑用户与 CIP 之间的以下对话。

|  |  |
| --- | --- |
| `User:` | `Which person lives in a city with the same name as his/her surname?` |
| `CIP:` | `Darwin.` |
| `User:` | `Which person is a city?` |
| `CIP:` | `None: Entity types Person and City are mutually exclusive.` |

比较 Person 和 City 的名称是有意义的，因为它们都是字符串。但比较人和城市则讲不通——它们是完全不同类型的实体。虽然 IQ、质量和长度的值类型都是数值型的，但质量和长度有不同的单位，而 IQ 是无量纲的（即没有单位）。概念上，两个数值引用的实体只有在具有相同单位（或都没有单位）时才能进行比较或相加。因此，以下查询讲不通：

|  |
| --- |
| `List persons whose mass equals their IQ.` |
| `List persons whose height is more than twice their mass.` |
| `List height + mass for each person.` |

当然，数字本身总是可以比较的。此外，身高和胸围都基于相同的域和单位，所以它们是兼容的。因此，以下查询是可以接受的。

|  |
| --- |
| `List persons whose mass number equals their IQ number.` |
| `List persons whose height number is more than twice their mass number.` |
| `List height + chest size for each person.` |

大多数当前的数据库系统很少或根本不支持实体与其值之间的区别。查询中指定的操作被解释为直接应用于值。例如，假设 [表 5.3](#Ch005_159-209_B9780443237904000098.xhtml#t0020) 的数据作为表 `Athlete`（person, city, height, chest, mass, IQ）存储在关系数据库中，以下结构化查询语言（SQL）查询完全合法：

|  |
| --- |
| `select person from Athlete` |
| `where person = city` |
| `and mass = iq and chest + mass > height` |

对于 [表 5.3](#Ch005_159-209_B9780443237904000098.xhtml#t0020) 中的数据，该查询返回“Darwin”，尽管从字面上看该查询是胡扯。查询中评估的比较是在值之间进行的，而非实体之间。我们可以通过更好的列名选择来澄清这一点（例如，使用“Surname”和“Cityname”代替“Person”和“City”）。

值是具有预定义解释的常量，因此不需要显式引用方案。例如，“Brisbane”指代其本身（即字符串“Brisbane”），当不加引号书写时，数字“77”表示数字 77（假设采用阿拉伯十进制记数法）。有人可能会声称，不加引号书写的常量（如“Brisbane”）足以标识单个实体。然而，总是需要某些上下文（至少是隐式的）。即使在 [表 5.3](#Ch005_159-209_B9780443237904000098.xhtml#t0020) 中，“Brisbane”也被用来同时指代一个人和一座城市。

在本书前面，我们看到实体是通过确定性描述来引用的（例如，“名为‘Brisbane’的那个 City”）。在引用类型的上下文中，如果一个值仅与该类型的一个实体相关联，则可以宽松地说该值是该实体的标识符。

如果确定性描述中仅使用一个值，则我们有一个简单的 1:1 引用方案。然而，有时可能需要两个或更多值。在这种情况下，我们有一个*复合引用方案*。作为一个例子，考虑 [表 5.4](#Ch005_159-209_B9780443237904000098.xhtml#t0025) 中计算机文件是如何被识别的。在给定文件夹中，文件可以通过其本地文件名来识别，例如“flag.vsd”。但当涉及许多文件夹时，我们需要将文件夹名称与本地文件名结合起来，才能知道我们在谈论哪个文件。
