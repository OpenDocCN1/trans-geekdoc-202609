
# 命题与事实状态

一个**命题**（例如：员工 101 访问过比利时）必须为真或为假（因此是**真值承载者**）。一个**事实状态**（例如：员工 101 访问比利时）是实际的（发生或存在于现实世界中）或非实际的。事实状态可能是可能的或不可能的。某些可能的事实状态可能是实际的（发生在现实世界中）。因此，**事实状态**是**真值制造者**，因为真命题关乎实际的事实状态。顺应真理的对应论，我们认为命题与事实状态之间的关系是对应而非同一。

定义性事实仅在平凡意义上（如果有的话）对应于事实状态；因为它们没有时间维度，在这方面不需要特别关注。相反，一次性事实和可重复事实对应于要么是单一事件（一次性）要么是事件集（可重复）的事实状态。**对于模型中的每个一次性或可重复事实类型，我们需要确定需要什么（如果有的话）时间信息。**

## 一次性事实类型

首先考虑一次性事实类型。如果一个事实类型是一次性的，并且我们希望为其至少某些事实实例记录使该事实实例为真的底层事件发生的时间，那么（如果模型中尚不存在）添加一个函数事实类型来记录事件发生的时间。为此，将原始事实类型的“键”关联到所需时间粒度的时间对象类型。这里，“事实类型的键”是指在该事实类型中扮演强制性、函数角色的对象类型。函数角色受简单唯一性约束约束。如果我们希望为每个原始事实实例记录事件，则该键在时间事实类型中的角色通常应为强制性的。

例如，考虑一次性事实类型“员工出生于国家”。假设对于该事实类型的每个实例，我们都想知道底层出生事件发生的时间，精度为 1 天。键对象类型是 Employee（其角色是强制性且函数的），因此添加强制性、函数事实类型“员工出生于日期”。

此示例包含一个时间事实类型（涉及如 Date 等时间对象类型）和一个非时间事实类型（本例中为空间事实类型）。这两个事实类型对员工均为强制性的。在其他情况下，这两个事实类型中的任意一个或两个对员工均可能是可选的，相关的 UML 多重性约束变为 `0..1`。

我们用“事件”一词涵盖**点事件**（发生在单一时间瞬间，例如：赛马获胜）和**时期事件**（发生在非零时间段内，例如：摇滚音乐会）。如果一次性事实中描述的事件是时期事件，并且我们希望记录该时期的开始和/或结束，则添加所需时间粒度的时间事实类型。

例如，假设事实类型“员工首次访问国家”用于记录人们首次访问各国的事件，并且假设我们总是知道此类访问开始的日期，但只可选地知道其结束时间。例如，这可以记录您首次访问比利时、首次访问日本等的详细信息。

ORM 目前允许对任何事实类型进行对象化。这对一元事实类型没问题，因为它具有跨越唯一性约束（断言或隐含）。然而，最好避免对没有跨越唯一性约束的二元或更长事实类型进行对象化。例如，这可能导致非原子事实类型，并引起尴尬或困惑（[Halpin, 2020](#Ch010_401-479_B9780443237904000244.xhtml#bb0730)）。此外，为避免此类对象化而进行的重建通常能产生更好的模式。例如，[图 10.19](#Ch010_401-479_B9780443237904000244.xhtml#f0100)(c) 可以说比 [图 10.19](#Ch010_401-479_B9780443237904000244.xhtml#f0100)(a) 更简单。该模式也更容易在不允许此类对象化的建模方法（如 Barker ER）中模拟，如 [图 10.19](#Ch010_401-479_B9780443237904000244.xhtml#f0100)(d) 所示。
