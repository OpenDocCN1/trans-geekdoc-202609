
OWL 采用开放世界假设，因此如果一个事实既未被断言也未被蕴含，则它是未知的。Hercule Poirot、Captain Hastings 和 Inspector Japp 是阿加莎·克里斯蒂小说中的人物。*Unary facts*（例如，Poirot smokes）及其*否定*（例如，Hastings does not smoke）在 OWL 中必须重新建模为二元关系，将主语关联到一个对象，该对象要么是布尔值（true 或 false），要么是具有两种可能性的状态值（例如，“Smoker”、“NonSmoker”）。

例如，以下 OWL 声明断言 Poirot 吸烟，Hastings 不吸烟，并将 Japp 是否吸烟留作*未知*。在 ORM 中，此示例将使用一元事实类型 Person smokes 在开放世界假设下并带有否定语义进行建模。

```
DataProperty: isaSmoker  Domain: Person  Range: xsd:boolean
```

```
Characteristics: Functional Individual: Poirot  Facts: isaSmoker true Individual: Hastings  Facts: isaSmoker false Individual: Japp  Types: Person
```

### 外部唯一性约束的连接语义

具有*内连接*语义的外部唯一性约束可以在 OWL 中通过简单地在被引用类上使用复合 `HasKey` 属性来声明。回顾 [Fig. 18.25](#Ch018_935-1005_B9780443237904000104.xhtml#f0130)，其中每个房间通过将其本地房间号与其建筑物相结合来标识，并使用了此 OWL 代码作为复合引用方案。

```
Class: Room  SubClassOf: isInBuilding exactly 1  SubClassOf: hasRoomNr exactly 1  HasKey: isInBuilding, hasRoomNr
```

在 OWL 中捕获具有*外连接语义*的外部唯一性约束需要更多工作。通常，这将涉及*为不扮演相关可选角色的实例引入一个子类，然后为该子类声明一个 HasKey 属性*。为了确保 `HasKey` 声明生效，必须*为被引用实例包含 IRI*。

[Fig. 18.28](#Ch018_935-1005_B9780443237904000104.xhtml#f0145) 再现了 [Section 10.1](#Ch010_401-479_B9780443237904000244.xhtml#s0010) 中的一个示例。该外部唯一性约束具有*外连接语义*，并附带一个条件：*外连接产生的空值被视为实际值*。因此，除了由其课程代码标识外，每个由部门开设的课程还可以由其课程标题和部门的组合来引用，例如 (Mechanics, PY) 和 (Mechanics, MA)。每个未由任何部门开设的课程可以由其代码或标题来标识。

添加课程 NDC4，其标题与课程 ND3 相同均为 "Mechanics"，将违反外部唯一性约束。假设对象属性和数据属性以常规方式声明，该外部唯一性约束的外连接语义可以用 Manchester 语法捕获，如下所示。添加了子类 `NonDepartmentalCourse` 用于未由任何部门开设的课程，并为其声明 `hasCourseTitle` 为 `HasKey` 属性。

```
Class: Course  SubClassOf: hasCourseTitle exactly 1 xsd:string, hasCourseCode exactly 1 xsd:string  HasKey: hasCourseCode Class: Department  SubClassOf: hasDepartmentCode exactly 1 xsd:string  HasKey: hasDepartmentCode Class: NonDepartmentalCourse  EquivalentTo: Course and (isOfferedBy max 0 Department)  HasKey: hasCourseTitle
```

### ORM 到 OWL 的映射

最近的研究工作调查了从 ORM、UML 和 ER 中的概念模型到 OWL 以及其他基于描述逻辑的语言的映射。OWL 2 的直接形式语义基于描述逻辑 SROIQ (D)。ORM 的大部分内容可以干净地映射到这些描述逻辑，从而促进了基于 DL 的高效定理证明器用于 ORM 模式的一致性检查，以及与其他语义 Web 应用程序的互操作性。与 OWL 2 不同，ORM 具有整洁的一阶形式化，因此避免了关于类型作为实例的问题。然而，一些 ORM 结构和约束无法在 OWL 中捕获。这既有好处也有坏处。

从好的方面来看，ORM 能够以自然的方式捕获现实中几个常见于业务领域但无法在流行的描述逻辑中捕获的复杂方面。因此，ORM 能够实现典型业务领域的高保真建模。

从负面来看，ORM 表达能力太强，以至于其底层逻辑稍微超出了可判定的一阶逻辑片段。这使得难以高效地自动检查诸如模式可满足性等方面（例如，在包含数百万个约束的超大模式中，检查没有任何约束相互矛盾）。

这又是表达能力与可处理性之间权衡的另一个例子。语言越具表达力，就越难高效地验证用该语言表达的模型的逻辑一致性。因为我们应该确保模型准确反映其旨在建模的业务领域，所以似乎合理的做法是：在 ORM 等语言中捕获预期语义，在可能的情况下应用高效的自动检查，并对其余部分使用启发式技术。

无法转换为 SROIQ (D)（因此也无法转换为 OWL DL）的 ORM 特性示例包括：跨越多个角色（同一关系或不同关系）的唯一性约束和频率约束、涉及多角色参数的集合比较约束、非循环环约束以及道义约束。`𝒟ℒℛ[*i**f**d*]` 描述逻辑增加了对标识符和函数依赖约束的支持，因此它可以捕获跨越多个角色的内部唯一性约束以及外部唯一性约束。

与 ER 和 UML 不同，ORM 是无属性的，因此更容易与 RDF、RDFS、OWL 和描述逻辑相关联，后者也以关系的形式表示所有事实。虽然 RDF 和 OWL 仅使用二元关系，但正如前几章所讨论的，将一元和 *n* 元事实类型转换为二元形式是微不足道的。因此，二元 ORM 中的事实和事实类型到这些语义 Web 语言有相当明显的映射。

映射中唯一丢失的方面是那些在目标语言底层逻辑中没有对应项的 ORM 约束和推导规则。这些可以作为无歧义的口头化表述映射到辅助注释中。

ORM 中的原子事实类型为在不同模型间共享语义提供了理想的语义单元。这样的单元是无约束的，允许不同模型应用不同的约束而不改变事实类型的语义。例如，事实类型 Person drives Car 在一个模型中可能是可选的且为 *m:n*，但在另一个模型中可能是强制的且为 *n*:1。使用基于事实的方法而不是基于属性的方法促进了这种交换。这也是 OMG 的 SBVR 方法用于交换业务规则语义且面向事实的原因之一。
