
在概念模式图上，*角色*（关系部分）由对象扮演，显式地显示为*框*。角色可以选择性地给定一个名称，在这种情况下，*角色名称*会显示在角色框旁边的方括号中，例如，图 3.9(a) 中的“[driver]”。每个*谓词*被描绘为一个*命名的、连续的一个或多个角色框序列*（“连续”意味着框相邻，中间没有间隙）。

谓词通常从一端排序到另一端，其读法显示在谓词形状旁边。对于二元关系（两个角色），正向和逆向谓词读法都可以显示，用斜杠“/”分隔，如图 3.9(a) 所示。

每个谓词必须至少显示一种读法。如果只显示一种谓词读法，默认情况下，水平谓词从左向右读，垂直谓词从上向下读。*箭头尖*可以添加到谓词读法上以指示读法方向。例如，“◄”表示谓词读法是从右向左，“▴”表示读法方向是向上。

每个角色通过一条*线*连接到恰好一个对象类型，表明该角色仅由该类型的对象扮演。一个完整的概念模式图包含相关的约束。我们稍后将看到如何添加这些约束。

用于实体首选标识方案中的关系称为*引用*或*存在事实*（例如，存在一辆汽车，其车辆登记号为“235PZN”）。

所有其他概念模式关系称为*基本事实*（例如，名为“Adams B”的人驾驶车辆登记号为“235PZN”的汽车）。

通常，基本事实是实体之间的关系，而引用是实体与值之间的关系。引用在实体世界和值世界之间提供了桥梁。简单引用和基本事实都是*原子事实*的例子。

这在图 3.10(a) 中清晰地展示出来，其中添加了实例来填充每个关系。人和汽车之间的关系（用图标描绘）是一个基本事实。姓名“Adams B”与人之间的关系是一个引用或存在事实，登记号“235PZN”与汽车之间的关系也是如此。

尽管这两个引用谓词都有“has”这一读法，但它们是不同的谓词。在内部，计算机辅助软件工程（CASE）工具可能通过其事实类型、使用代理名称（例如，“P2”、“P3”）或扩展名称（例如，“PersonHasPersonName”、“CarHasRegNr”）来标识谓词。

虽然谓词读法“has”可用于事实类型，但如果存在更具描述性、更自然的替代方案，最好避免使用。例如，如果准确，“Person drives Car”比“Person has Car”更好，后者可能意味着很多事情（例如，Person owns Car）。

对于这个例子，每个人恰好有一个名字，每个人名最多指代一个人。每辆车恰好有一个车辆登记号，每个车辆登记号最多指代一辆车。这种情况在前面的实例图（图 3.8）中看得很清楚。这两种引用类型中的每一种都被称为提供*简单 1:1 引用方案*。我们将“1:1”读作“一对一”。稍后，我们将看到如何在概念模式图上使用唯一性和强制角色约束来指定这一点。

当存在简单的 1:1 命名约定时，我们通过将*引用模式*的名称用*括号*附加到实体类型的名称后面来指示它，然后使用值本身在相关的*事实表*中描绘对象实例。忽略其他约束，图 3.10(a) 的填充模式可以通过图 3.10(b) 简洁地显示。除非我们想显式地说明引用方案，否则首选这种简洁形式，因为它更接近我们口头表达事实的方式，并简化了图表。如果我们只想显示模式，则省略事实表。

引用模式指示对象（通常是值）引用实体的模式或方式。使用引用模式减少了显式显示值类型的需要。然而，为了理解缩写方案，我们需要知道如何在引用模式和值类型之间进行转换。不同版本的 ORM 有不同的方法。下面概述了用于 ORM 2 的 NORMA 工具中的方法。

令符号“*E (r)* → *V*”表示“带有引用模式 *r* 的实体类型 *E* 生成值类型 *V*”。引用模式可以是通用的、基于单位的（度量）或一般的。一组初始的*通用引用模式*在 NORMA 中预定义，包括 Name、name、Code、code、Nr、nr、Id、id 和 #。当加上括号时，通用引用模式前面带有一个*点*“.”。要获得值类型名称，将通用引用模式名称附加到其实体类型的名称后面，例如，`Product(.Name)` → `ProductName`；`Country(.Code)` → `CountryCode`；`Song(.Title)` → `SongTitle`；`Country(.code)` → `Countrycode`。NORMA 的口语化浏览器自动显示引用类型，例如，Product has ProductName。使用格式字符串可以实现更精细的控制。

前身工具 VisioModeler 用于 ORM，它在将引用模式名称附加到实体类型名称之前，会将首字母（如果有）大写，例如，`Country(.code)` → `CountryCode`。用于在 Microsoft Visio 中绘制 ORM 图的 Visio 形状库允许你为引用模式选择任何名称，但它不口语化引用类型。

对应于通用引用模式的值类型仅标识一种实体类型。例如，`CountryCode` 仅标识国家，`GenderCode` 仅标识性别。

*基于单位*（或*度量*）*引用模式*包含一个内置的物理单位列表（例如，cm、kg、mile）和货币单位（例如，USD、EUR），用户可以扩展该列表。当加上括号时，基于单位的引用模式后面跟一个*冒号*“:”。值类型名称通过将基于单位的引用模式中的冒号替换为“Value”来生成。例如：`(kg:)` → `kgValue`；`(USD:)` → `USDValue`。

每个单位基于一种*单位类型*（或*维度*），该类型可以选择性地显示在冒号之后。有时，不同的单位基于相同的维度。例如：`(kg: Mass)`、`(lb: Mass)`、`(USD: Money)`、`(EUR: Money)`。

*一般引用模式*没有添加标点符号，其名称与其值类型名称相同。例如：`(ISBN)` → `ISBN`；`(URL)` → `URL`。这些值类型可以标识多种实体类型（例如，`URL` 可用于标识 Link 和 Website）。

对于 *Date* 实体类型，基本日期格式用于引用模式。例如，“Date(mdy)”表示日期值按月在日前、日在年前的顺序显示，这在美国很常见，不同于澳大利亚（dmy）和日本（ymd）。

作为检查，我们应该通过为每种事实类型添加一个**事实表**并在相关列中输入值，用一些事实实例来填充图表上的每种事实类型。在 ORM 中，事实表就是用于显示事实类型实例的表。“事实表”一词在数据仓库中有不同的用法（稍后讨论）。包含模式和示例数据库的图表称为*知识库图*。
