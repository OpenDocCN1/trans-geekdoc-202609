
除了通过定义创建表（如刚才所示）外，表也可以**像**另一个表一样创建，或**作为**select查询的结果创建。其他SQL语句用于修改和删除表等任务，其他类型的数据库对象也有相应的alter或drop语句。

视图可以使用*create-view语句*创建，语法如下：

```
create view viewname [ ( col-list ) ] asselect-query [ with check option ]
```

视图定义用于将针对视图的查询转换为针对基表的等效查询。某些视图是不可更新的（例如涉及连接的视图）。

触发器用于响应给定表或视图上下文中的特定事件。当检测到指定事件时，将执行触发器中的代码主体。触发器可以检查导致事件的数据，以确定适当的处理方式。创建触发器的基本语法是：

*   ```
    create trigger triggername
    ```

*   ```
    { before | after } { insert | delete | update [ of col-list ] } on tablename
    ```

*   ```
    [ referencing { old | new } [row] [ as ] correlation-name |
    ```

*   ```
    { old | new } table [ as ] table-alias [, …] ]
    ```

*   ```
    [ for each { row | statement } ]
    ```

*   ```
    [ when ( condition ) ]
    ```

*   ```
    triggered-SQL-statement
    ```

例程是显式*调用*的代码主体，这与本质上由事件驱动的触发器形成对比。UDF返回标量或表结果。创建函数的基本语法是：

```
create function functionname ( [ parameter-list ] ) returns { data-type | table col-name data-type [,…] } function-body
```

存储过程能够执行比函数更广泛的活动，例如更新表，是封装SQL代码的标准方式。存储过程常用于将数据库与可能造成损害的用户操作“隔离”开。创建存储过程的基本语法是：

```
create procedure procedurename ( [ { in | out | inout } parmname parmtype [,…] ] ) procedure-body
```

数据库模式可能包含其他类型的对象。*序列*提供标识符的自动唯一生成。*索引*可用于提高查询性能。*游标*可用于提供逐行处理。

实际的数据库系统包含处理并发的措施，通常基于资源的选择性锁定以避免事务间的干扰。可以在语句级或连接级指定更多隔离与更多吞吐量之间的首选平衡点。

数据库安全围绕两个主要概念。用户根据指定的凭据进行身份验证以确认其身份。权限——执行特定类型操作的权利——可以授予或保留给特定个人或组。

元数据——关于数据库系统本身的信息——存储在各种表中供系统内部使用。这些信息也可以被查询，尽管标准做法是不鼓励直接访问这些表，而是使用系统视图。

本章完成了我们对现代关系型数据库系统主要特性的基本介绍。本书其他地方将在相关主题的背景下考虑SQL的其他方面。更高级的SQL方面包含在在线附录C中，章节注释提供了更多细节。虽然相关SQL标准的知识提供了极好的基础，但学习该语言最简单的方法是使用它，这意味着要发现你选择的SQL方言与标准有何不同。幸运的是，大多数商业DBMS提供了广泛的在线资源来协助你在这方面的学习。

## 14.1 模式等价性与优化

前几章讨论了如何用概念模式对应用程序结构建模，然后将其映射为用于关系数据库系统实现的逻辑模式。虽然大部分设计和映射可以自动化，但人类必须执行概念模式设计过程（CSDP）步骤1，因为用语言表达关于现实世界的相关事实涉及人类理解。考虑到建模论述域（UoD）这一初始步骤的非正式性质，人们往往会想出不同的方式来描述同一现实，这并不令人惊讶。

因此，同一业务领域可以用多个概念模式建模。此外，同一概念模式可以通过不同方式映射到逻辑模式，要么选择不同类型的逻辑模型（例如面向对象关系型），要么覆盖默认映射选择（例如选择单独的子类型表或反规范化）。最后，同一逻辑模式可以通过多种方式在物理模式中实现（例如不同的索引选择）。
