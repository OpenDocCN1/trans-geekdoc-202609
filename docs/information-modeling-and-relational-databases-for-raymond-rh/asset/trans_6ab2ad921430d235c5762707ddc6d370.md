

# 概念模式

概念模式旨在实现清晰的沟通，特别是建模人员与领域专家之间的沟通。虽然它们能清晰地描述 UoD（关注域），但通常会被转换为较低层级的结构以实现高效实现。对于给定的应用，会选择一个合适的逻辑数据模型（例如关系型、面向对象），并将概念模式映射为用该数据模型支持的抽象数据结构和操作来表示的 `logical schema`（逻辑模式）。例如，在关系模式中，事实存储在表中，约束通过主键和外键声明等来表示。

逻辑模式现在可以在特定的数据库管理系统（DBMS）中实现为 `physical schema`（物理模式），例如关系模式可能在 Microsoft SQL Server 或 IBM 的 DB2 中实现。物理模式包含关于所用物理存储和访问结构的细节（索引、文件聚簇等）。对于同一个 DBMS 可以做出不同的物理选择，不同的 DBMS 通常在可能的选择上也有差异，因此对于同一个逻辑模式可能会选择不同的物理模式。外部层的操作由系统转换为物理层的操作。逻辑模式和物理模式位于 `internal level`（内部层）。

概念层的一个优势是它是所有层级中最 `stable`（稳定）的。它不受用户界面或存储和访问技术变更的影响。假设一个概念模式在关系型 DBMS 中实现，后来我们希望改用对象数据库。除非 UoD 发生了变化，否则概念模式可以保持不变。我们只需应用不同的映射过程，然后迁移数据即可。

如果一种语言是研究的对象，则称之为 `object language`（对象语言）。用于研究它的语言则称为 `metalanguage`（元语言）。例如，你可能用英语作为元语言来研究作为对象语言的日语。对象语言可以是它自己的元语言，例如，英语可以用来学习英语。任何概念模式都可以表示为一组句子，因此本身可以被视为一个数据库。

这使我们能够构建一个 `metaschema`（元模式）来谈论概念模式。这种元概念模式规定了任何概念模式必须遵守的设计规则（例如，每个角色恰好由一个对象类型扮演）。计算机辅助软件工程（CASE）工具被用来协助设计此类元模式的概念模式，以确保建模人员输入的模式是 well formed（格式良好）或“语法正确”的。

关于语法，让我们约定接受“schemas”和“schemata”作为“schema”的复数形式。虽然“data”是“datum”的复数，但我们将采用通用做法，允许“data”既作单数也作复数使用。本书的第一个练习如下所示。练习答案包含在在线补充材料中。

## 2.2 概念层

在概念层，人与信息系统之间的所有通信由 CIP 处理。这种通信可分为三个主要阶段：

1. 建模人员将 UoD 的概念模式输入系统。当且仅当该模式与元概念模式一致时，CIP 才接受它。
2. 用户通过添加或删除特定事实来更新数据库。当且仅当该更新与概念模式一致时，CIP 才接受它。
3. 用户向系统查询关于 UoD 的信息，并由 CIP 回答。只要 CIP 存储了相关信息或能推导出该信息，它就可以提供关于概念模式或数据库的信息。

在这些阶段中，CIP 分别扮演 `design filter`（设计过滤器）、`data filter`（数据过滤器）和 `information supplier`（信息提供者）的角色。为处理更新和查询请求，CIP 访问概念模式，后者包含如 [图 2.4](#Ch002_27-57_B9780443237904000128.xhtml#f0025) 所示的三个主要部分。

`fact`（事实或事实实例）是业务视为真实的命题。`fact types`（事实类型）部分列出了可在数据库中表示的事实种类。事实类型指明了 UoD 中允许哪些类型的 `object`（对象）（例如 Employee 员工、Country 国家），这些对象如何在数据库中通过值被 `referenced`（引用/标识）（例如 SSN、CountryCode），以及它们的 `relationships`（关系）（例如 was born in 出生于、lives in 居住于）。

`constraints`（约束）部分列出了对事实类型实例集的约束或限制。`Static constraints`（静态约束）适用于数据库的每一个状态。例如，假设数据库存储关于国家及其人口的信息。虽然一个国家的人口可能随时间变化，但在任何给定时间，每个国家最多只有一个值被记录为其当前人口。`Dynamic constraints`（动态约束）决定了数据库状态之间允许的转换。例如，一个人的年龄状态可能从儿童变为成年人，但不能反向变化。

约束也称为 `validation rules`（验证规则）或 `integrity rules`（完整性规则）。当数据库与所建模的 UoD 一致时，称该数据库具有完整性。虽然大多数数据库约束可以在概念模式图上用图形表示，但某些约束可能需要用其他方式表示（例如使用概念句子、公式、表格、图表或程序代码）。

`derivation rules`（推导规则）部分包含从其他事实推导出新事实的规则。非 `derived fact`（推导事实）的事实称为 `asserted fact`（断言事实，也称为原始事实或基本事实）。推导规则可能涉及 `mathematical calculation`（数学计算）或 `logical inference`（逻辑推理）。例如，平均分可以通过将各个分数相加再除以其数量来推导。为各种数据类型定义了许多运算符和函数。这使得无需记录每个推导即可进行多种可能的查询。典型的数学工具包括算术运算符，如 `+`、`−`、`*`（乘）、`/`（除）；集合运算符如 `∪`（并集）；以及用于计数、求和和计算平均值、最大值和最小值的函数。

除了这种通用的推导工具外，已知需要的特定 `derived fact types`（推导事实类型）可通过推导规则在模式中定义。数学计算得出的事实类型和几乎所有通过逻辑推理得出的事实类型都属于这一类。通过逻辑推理推导的事实类型通常涉及使用逻辑运算符（如 `and` 或 `if`）的规则。

虽然可推导的事实可以存储在数据库中，但通常最好避免这样做。除了节省存储空间外，从存储数据中省略推导事实的做法通常使处理更新变得容易得多。例如，假设我们想定期获取班级中学生的个人年龄（以年为单位），有时还需要获取班级的平均年龄。如果我们在数据库中存储了平均年龄，每当有学生加入或离开班级，以及班级中任何人的年龄增长时，都必须安排重新计算该平均年龄。
