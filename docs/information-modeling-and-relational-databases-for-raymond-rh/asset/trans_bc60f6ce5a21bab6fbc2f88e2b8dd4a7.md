
很少会出现由单一显式引用类型标识的对象类型。要映射这种情况，首先在脑海中抹去引用类型，只留下三个事实类型以便分组到表中。作为练习，请尝试自行映射，然后参考[图 11.36](#Ch011_481-537_B9780443237904000141.xhtml#f0185)所示的解决方案核对答案。

默认情况下，为映射目的，子类型会被吸收到其根超类型中。尽管子类型约束仍会被映射（作为可选列上的限定或表间子集约束），但吸收通常会导致子类型的函数角色与根超类型的函数角色归为一组。在步骤 0.3 中，我们可能希望覆盖此默认行为。让我们通过一些示例来了解，首先从子类型继承其顶层超类型的首选引用方案这一常见情况开始。

[图 11.37](#Ch011_481-537_B9780443237904000141.xhtml#f0190) 描绘了一个包含函数角色的简单子类型图。为简化起见，省略了引用方案和子类型定义。正如上一节所讨论的，与节点关联的函数事实类型可分组为表的三种基本方式为：*吸收*、*分离* 和 *分区*。

![图 11.37 我们如何映射由子类型扮演的函数事实类型？](images/B9780443237904000141/f11-37-9780443237904.jpg)

[图 11.37](#Ch011_481-537_B9780443237904000141.xhtml#B-f0190) 我们如何映射由子类型扮演的函数事实类型？

第一种选项 *吸收* 在分组前将子类型吸收回超类型。例如，假设 *A*、*B* 和 *C* 扮演的所有角色均为函数角色（即具有简单唯一性约束）。在这种情况下，我们只生成一张表（子类型约束表示为可选子类型属性上的限定）。这种吸收默认值有两个主要优势：查询如果需要来自多个节点的属性（无需连接），性能会更好；且子类型约束通常易于指定且执行成本低廉（无需连接）。

子类型吸收的主要缺点如下：属于单一子类型的对象需要空值；超类型的函数表更大（列更多）；针对单一子类型的查询需要限制；且仅查看子类型不太方便（需要投影和限制）。通常，优势大于劣势。请注意，子类型的任何非函数角色都映射到单独的表中，因此不受我们子类型映射选择的影响。

第二种选项 *分离* 将直接附加到每个对象类型节点的函数角色分组到单独的表中，每个节点一张表。在此方案中，*A* 的函数谓词映射到一张表（公共属性），*B* 特有的属性映射到另一张表，*C* 特有的属性映射到第三张表。分离的主要优势在于它将空值最小化，且针对每个子类型的查询速度很快。其主要弱点是：需要来自多个节点属性的查询较慢（需要连接），且向子类型表插入数据较慢（子类型约束现在指定为限定子集约束，因此需要访问超表来强制执行它们）。

第三种选项是水平 *分区* *A* 的实例。通常只有当 *B* 和 *C* 构成 *A* 的一个分区时（即它们互斥且穷尽：*B* ∩ *C* = { }；*B* ∪ *C* = *A*），才应考虑此选项。在这种情况下，一张表保存 *B* 的所有函数谓词（包括附加到 *A* 的那些），另一张表保存 *C* 的所有函数谓词。然而，如果 *B* 和 *C* 不穷尽 *A*，则需要一张单独的表来存放 *A* - (*B* ∪ *C*)。

如果 *B* 和 *C* 重叠，则 *B* ∩ *C* 的事实会产生冗余，必须加以控制。这种分区选项偏离了将每个事实类型仅分组到一张表的常规做法，通常仅在分布式或联邦数据库设置中有用。

分区超类型的主要优势如下：它将空值最小化；关于 *B*（或 *C*）所有属性的查询很快；且子类型约束通常无需编码（因为隐含）或易于编码（例如，无/有性别字段的 Man 和 Woman 表）。其主要缺点如下：它会降低关于所有 *A* 或 *B* 和 *C* 的查询速度（需要连接）；除非 *B* 和 *C* 构成 *A* 的一个分区，否则非常别扭；且如果 *B* 和 *C* 互斥，强制执行此约束通常需要表间访问。

上述讨论的标准可帮助我们决定是否覆盖默认的吸收选项。覆盖决策可从 CASE 工具的选项列表中选择。对于较大的子类型图，映射选择会急剧增加，因为可能会混合使用这三种选项。

为了阐明前面的讨论，让我们看一些示例。[图 11.38](#Ch011_481-537_B9780443237904000141.xhtml#f0195) 中的 ORM 模式回顾了前几节讨论的患者示例。[图 11.38](#Ch011_481-537_B9780443237904000141.xhtml#f0195) 底部展示了三种基本映射选择。采用吸收时，所有事实类型分组到单张表中，子类型约束显示为可选列上的限定（**only if** 条件捕获子类型约束，**iff** 条件同时捕获子类型约束和强制角色约束）。

![图 11.38 吸收、分离和分区映射选项。](images/B9780443237904000141/f11-38-9780443237904.jpg)

[图 11.38](#Ch011_481-537_B9780443237904000141.xhtml#B-f0195) 吸收、分离和分区映射选项。

采用分离时，公共事实类型分组到 Patient 超表中，子类型特有的事实类型分组到单独的子类型表中，总共三张表。子类型约束显示为子集约束上的限定（在本例中为外键引用）。在子集约束限定中，**only where** 子句仅捕获子类型约束，而 **exactly where** 子句同时涵盖子类型约束和强制角色约束。

采用分区时，公共事实类型被下推到子类型表中，这些表也包含这些子类型特有的事实类型。表键之间的排斥约束确保每个患者仅映射到其中一张表。视图定义通过联合两张表的键来列出所有患者。性别信息现在非正式地体现在表名中。如果需要，可创建视图形成包含所有 Patient 详细信息的单张表，从表名推导性别。

虽然上述讨论的三种选择通常是唯一使用的，但也可以混合匹配这些选项，例如，为男性患者吸收前列腺事实类型，但为女性患者保留单独的怀孕次数表。

如果我们添加前文[图 11.26](#Ch011_481-537_B9780443237904000141.xhtml#f0135)中考虑的 *m:n* 产前诊所出席事实类型，无论选择上述三种子类型映射选项中的哪一种，它都会映射到自己的单独表中。回顾一下，吸收选择仅吸收对子类型而言是函数的事实类型。

现在考虑[图 11.39](#Ch011_481-537_B9780443237904000141.xhtml#f0200)中的概念模式。此处，教职员工具有三个级别之一（L = Lecturer 讲师，SL = Senior Lecturer 高级讲师，P = Professor 教授）。学生只能由高级讲师辅导，系主任职位仅由教授担任。因为子类型不构成 Academic 的一个分区，我们通常会选择吸收或分离来映射它们。作为练习，请在继续阅读前自行尝试这两种选项。
