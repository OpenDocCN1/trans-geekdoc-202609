
# ACID 与 BASE

ACID 观点非常看重一致性，使其非常适合对数据可靠性要求至关重要的传统事务型数据库系统。分布式系统的兴起促进了对另一种观点的关注，即 BASE，该首字母缩写词源自 **基本可用**、**软状态** 和 **最终一致性** 这三个术语（[Pritchett, 2008](#Ch017_875-933_B9780443237904000050.xhtml#bb1080)）。

*   **基本可用** 意味着系统应始终可用于处理请求，即使系统正经历某种故障或中断。
*   **软状态** 指的是数据的不同副本不需要在所有时间都处于完全一致的状态。
*   **最终一致性** 意味着给予足够时间后，数据的差异最终会得到协调。

BASE 观点通过允许数据副本之间存在临时不一致，强烈倾向于可用性而非一致性。这显然比 ACID 要求宽松，但对于分布式系统更具相关性。

# CP 数据库中的一致性机制

数据库可以通过采用各种技术和机制来同步分布式系统中多个节点间的数据，从而确保一致性。CP 数据库常用的方法包括以下几种：

*   **共识协议**：CP 数据库通常利用共识协议（如 `Paxos` 或 `Raft`）就数据更新的顺序和有效性在节点间达成一致。这些协议通过在提交更改前要求多数派或一致同意，确保系统中所有节点达到一致状态。
*   **两阶段提交**：在分布式事务中，可使用两阶段提交协议来协调跨多个节点的更改提交或回滚。它确保所有参与节点同意提交事务或中止事务，从而保证系统范围内的一致性。
*   **法定人数与副本**：CP 数据库通常使用复制在不同节点间维护数据的多个副本。法定人数用于确定读或写操作所需达成一致的最小节点数，以确保一致性。通过要求一定数量的副本参与操作，CP 数据库可在返回结果前确保所有副本保持一致。
*   **同步与锁定**：CP 数据库可能使用同步机制（如分布式锁或乐观并发控制）来防止对共享数据的并发访问和修改。这些技术确保冲突的更改被串行化并按一致的顺序应用。
*   **数据版本控制与冲突解决**：CP 数据库通常采用数据版本控制或时间戳来跟踪更改，并在发生并发更新时解决冲突。通过为数据分配唯一版本或时间戳，可基于预定义的规则或策略检测并解决冲突。

当然，实现一致性可能会引入延迟并降低可用性，尤其是在网络分区或故障期间。CP 数据库采用的具体机制和权衡取决于其设计以及应用程序所需的一致性级别。

# 可用性

分布式系统中的可用性是指系统响应客户端请求的能力，即使系统的某些部分已经发生故障。这很重要，因为采用分布式架构的主要原因之一就是提高可用性和容错能力。

在分布式数据库中，可以采用多种方法来提供高可用性，确保系统即使在发生故障或网络分区时仍保持运行和可访问。以下是实现高可用性的一些常用技术：

*   **复制**，涉及在分布式数据库的不同节点间创建数据的多个副本。通过在不同位置拥有副本，即使某些节点发生故障，系统仍可继续提供读写请求服务。复制还能提高容错能力，因为即使一个或多个节点变得不可用，数据副本仍然可用。
*   **数据分区**，或分片，涉及将数据集划分为较小的子集并分布到多个节点上。每个节点负责特定的数据分区。通过分发数据，系统可以并行处理更大量的请求，从而提高可用性和可扩展性。
*   **负载均衡** 技术将传入请求分发到分布式数据库的多个节点上，确保工作负载均匀分布。这有助于防止任何单个节点因请求过多而不堪重负，通过避免瓶颈和优化资源利用率来提高可用性。
*   **故障检测与恢复** 机制对高可用性至关重要。节点可以定期检查其他节点的健康状况并检测故障。检测到故障后，系统可采取适当措施，如提升副本以替换故障节点或重新分发数据。自动故障检测和恢复可将停机时间降至最低，确保持续可用。
*   **冗余与故障转移**：冗余涉及拥有多个可执行相同功能的节点或组件。发生故障时，故障转移机制可将请求重定向到健康节点或激活备用副本。冗余和故障转移策略通过最大限度地减少故障对系统运行的影响，提供容错能力并提高可用性。

通过组合这些技术，分布式数据库可以通过确保持续访问数据和不间断运行来实现高可用性，即使面临故障或网络中断。具体使用的方法取决于数据库系统的设计、需求和期望的可用性级别。

# NoSQL 的优势

在比较来自不同供应商的关系型数据库系统时，很明显它们有许多共同点。考虑到它们都基于同一个基本逻辑概念，这并不令人惊讶。但 NoSQL 数据库则不然。每个 NoSQL 数据库都是为填补特定利基市场而设计的，导致不同系统之间存在广泛的差异。正如我们稍后将看到的，这些数据库可以归类为大的家族，但它们都共享一组共同的存在动机。这些动机主要分为三类：应对大量数据、提升性能，以及实现更敏捷的数据库开发流程。

正如我们已经注意到的，数据库规模不断增大是一致的趋势。出于实际原因，这意味着实施“横向扩展”策略，在多台计算机上支持数据库，从而引发上述所有分布式系统问题。

对于关系型数据库而言，分发并非易事，许多 NoSQL 方法旨在提供利用相对廉价的商用硬件进行扩展的方式，通常通过以某种方式对数据库进行分区来实现。这也使得云计算架构非常适合大数据系统，所有云服务提供商都提供托管的 NoSQL 解决方案。

NoSQL 系统通常提供调整一致性与可用性之间权衡边界的选项，使系统在预期应用类型的条件下尽可能保持一致，同时也尽可能保持可用。特定的应用领域可能提供特殊功能，可在该特定上下文中被利用以提高一致性或可用性。
