
我发现 ORM 提供了一种强大、精确且易于理解的概念建模方法，以及本书以精确且易懂的方式呈现 ORM，这让我着迷。正如预期的那样，与 ORM 相关的面向事实的建模方法论在书中得到了清晰而详尽的阐述，构成了本书的另一大支柱。它指导读者理解数据语义，并设计能够真实、正确地反映业务现实与需求的数据结构。本书还相当大篇幅地关注概念模型与其在某些数据库结构中的实现之间的关系，在强调正确性和有效性的同时，也不忘现实世界中 SQL 的复杂性。

书中前几版所阐述的面向事实的建模方法论对我许多研究产生了深远影响。确实，正是在初读此书后，我开始致力于基于经典逻辑的知识表示与 ORM 及其面向事实的建模方法论的交叉研究。书中讨论的 ORM 语言的文本版本（FORML）也对我产生了影响。我曾与 Terry Halpin 会面讨论我的研究成果，结果却意识到在此之前我还有太多东西需要学习！Terry 是一位谦逊的科学家，每次讨论后，他似乎总是对的。

Terry Halpin 和 Tony Morgan 毕生致力于开发企业建模概念，这充分证明了这项工作的重要性。更新和扩展的内容，以及嵌入各章的大量练习，增强了本书的价值。本书紧跟最新版本和趋势，确保读者能获取该领域最新的发展成果。涵盖 ORM、ER、UML、SQL 和 OWL 的内容均经过了全面更新，融入了它们的最新迭代版本。本版新增了针对 NoSQL 技术的章节，如键值、面向列和图数据库。还新增了一章涵盖当代流行的数据文件格式，如 XML 和 JSON。所有其他章节都进行了大幅修订，加深了对众多主题的覆盖深度。

# 前言

Herman Balsters，博士，^()NorthChain 合伙人，荷兰格罗宁根。

我于 2005 年在塞浦路斯举行的 ORM 研讨会上首次接触 ORM，该研讨会是 OTM 联合国际研讨会和会议的一部分。我刚在 OODB 会议上发表了一篇关于数据联邦的论文，出于纯粹的好奇，我短暂地访问了 ORM 研讨会，想多了解一些关于 ORM 语言的情况。当我走进去时，Terry Halpin 正在做演讲。我对演讲期间热烈的讨论感到惊讶，不仅研讨会参与者的热情让我惊讶，他们评论和提问的高质量也让我惊讶。我没有只是短暂停留，而是在塞浦路斯逗留的剩余时间里一直待在 ORM 研讨会，从此成为了 ORM 的忠实拥趸。

在格罗宁根大学担任研究员和副教授期间，我深度参与了统一建模语言（UML）和业务流程模型和标记法（BPMN）等语言的工作，试图捕捉信息建模的本质。我一直在与这些被视为最先进的语言作斗争，因为我就是无法完全掌握用这些语言编写的模型到底意味着什么。我拥有纯数学（特别是数理逻辑）和计算机科学背景，我希望能清楚地了解我试图指定的数据和流程模型的语义和完整性。我也想看到模型与模型实现之间清晰的联系。在这两方面，我对当时主流的建模语言都感到不安。这种缺乏精确性和完整性的感觉不仅存在于研究中，也存在于教学中。没有什么比老师自己都不完全理解的东西更难向学生解释了。

这一切从我走进塞浦路斯那个 ORM 研讨会的那天起就改变了。我花了一段时间才掌握 ORM 的所有细节，但在那之后，我能够真正以完全的理解和极高的精确度编写模型，使模型能够直接与实现挂钩。即使在今天，我仍怀着深深的敬意和满足感使用 ORM。

ORM 是一种所谓的面向事实的数据建模语言。在 ORM 中，你编写关于我们周围世界的事实。这意味着你指定对象及其之间的关系，从而得出关于世界的某些陈述。ORM 以这样一种方式做到这一点：即使是非技术领域的专家也能建模其专业领域内的事实。这得益于 ORM 与描述我们周围世界的自然语言规范有着紧密的相似性。然而，ORM 也能以一种极高细节和（数学）精度来建模事实的方式来做到这一点。ORM 是一种图形化语言，具有直观易懂的符号。ORM 还配备了一个强大的工具（NORMA），允许对 ORM 模型进行图形化编辑和验证检查。ORM 的另一个吸引人的方面是可以将 ORM 模型直接编译为关系数据模型，然后再编译为 SQL。因此，在 ORM 中，你可以直接从建模走向实现。

2008 年，作者 Terry Halpin 和 Tony Morgan 发布了这本精彩书籍的第二版。我自那时起一直在使用它。多年来，我已向数百名学生教授 ORM，并指导硕士和博士生进行涉及 ORM 的研究。本书以其简洁明了的写作风格脱颖而出，涵盖了信息建模几乎所有的主题。此外，大量解释使用 ORM 进行建模的理论与实践的案例，使本书成为任何想要理解信息建模所有细节的人的必读之作。

这本书既技术又哲学。它是技术性的，因为它提供了大量材料，涉及理论、符号、案例和工具，以应对信息建模师面临的几乎所有挑战。作为额外收获，我们还看到了如何将这些模型在技术上实现为关系数据库。但在某种意义上，这本书也是哲学的，因为它将你带入一个充满挑战性问题的领域，这些问题关乎我们对周围世界的表征。ORM 的核心在于使用语言来捕捉那个世界，以及完成这项工作的最佳语言应是什么样子。

作为一名大学教授，我有幸用 ORM 教授学生建模、撰写研究论文，并指导信息建模领域的硕士和博士生。自 2018 年离开学界以来，我一直在工业层面从事信息建模工作，面临一些实际中极具挑战性的建模问题。在这些涉及数据、业务规则和业务流程建模问题的复杂情境中，ORM 提供了解决方案，我确信如果没有 ORM，我是找不到这些解决方案的。
