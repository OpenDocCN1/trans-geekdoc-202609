
虽然 SQL-89 和 SQL-92 仅允许一种空值，但 [Codd (1990)](#Ch012_539-646_B9780443237904000268_2.xhtml#bb0235) 在关系模型的“版本 2”中提出了一种四值逻辑，以允许两种未知值（适用和不适用），但这并未获得广泛认可。

下面给出了本节介绍的四个运算符的 SQL-89 语法摘要。此处，“expn”表示一个表达式，如列名或常量（或由算术运算符 `+`、`−`、`*`、`/` 等连接的这些内容的组合……稍后讨论）。

*   ```
    expn [not] in (constant-list)
    ```

*   ```
    expn [not] between expn and expn
    ```

*   ```
    char-col [not] like quoted-string [escape quoted-char]
    ```

*   ```
    colis [not] null
    ```

此外，SQL-89 允许将 `in` 运算符与子查询一起使用，并允许在搜索条件中使用量化比较和 `exists` 量词（稍后讨论）。SQL-92（及更高版本）显著扩展了搜索条件中允许的表达式和运算符种类。

例如，SQL-92 允许将*行值表达式*（例如，一个值元组）作为任何比较器（例如 `=`、`in`）的左参数，并包含 `unique`、`match` 和 `overlaps` 谓词。`Unique` 用于检查子查询返回的每个非空行是否唯一，`match` 用于检查某行是否与子查询返回的某行匹配，`overlaps` 用于测试两个日期时间段是否重叠。

SQL:1999 更进一步，增加了用于搜索条件的 `similar`、`distinct` 和 `type` 谓词。`Similar` 允许通过正则表达式比较字符串，`distinct` 测试两个行值是否不同，`type` 测试用户定义类型值表达式是否符合用户定义类型规范。SQL 方言对这些标准谓词的支持各不相同。然而，所有 SQL 方言现在都支持本节讨论的 SQL-89 语法。

## 12.8 SQL：并集与简单子查询

本节讨论 `select` 查询作为较大 `select` 查询内部组件的两种用法。首先，我们将探讨如何在 SQL 中指定并集、交集和差集运算。接下来，我们将了解 SQL 中的基本子查询。让我们从并集运算开始。基本语法如下所示。保留字“union”仅允许出现在 `select` 查询之间，而不允许出现在表名之间。

*   ```
    select-query
    ```

*   ```
    union [ all ]
    ```

*   ```
    select-query
    ```

*   ```
              …
    ```

这些 `select` 查询必须是**并集兼容**的（即，列数相同，且对应列基于兼容的数据类型）。默认情况下，返回的集合是各个 `select` 查询返回表的并集，并消除了任何重复行。要返回包（允许重复），请指定 `all` 以包含重复行。请注意，这与 SQL `select` 列表语法相反，后者默认返回包，并使用 `distinct` 来消除重复项。

SQL:1999 允许在 `union` 后显式声明 `distinct` 选项；如果省略，则默认假定为该选项。SQL Server 支持“`union all`”语法，但不支持“`union distinct`”语法，因为除非添加 `all`，否则它总是从 `union` 中移除重复项（因此添加“`distinct`”即使可能阐明默认行为也是多余的）。

例如，[图 12.50](#Ch012_539-646_B9780443237904000268_1.xhtml#f0255) 中的查询列出了每个是美国人或驾驶福特车的人。第一个 `select` 查找美国人（“JimO”、“Lance”），第二个 `select` 查找福特车驾驶员（“Colleen”、“Lance”），而 `union` 包含了这两个中间结果中任一或两者中的任何人。尽管 Lance 出现在两个表中，但他仅在最终并集中出现一次，因为默认情况下会移除重复项。

![图 12.50 默认情况下，并集消除重复项。](images/B9780443237904000268/f12-50-9780443237904.jpg)

[图 12.50](#Ch012_539-646_B9780443237904000268_1.xhtml#B-f0255) 默认情况下，并集消除重复项。

如果需要*重复项*，则必须在 `union` 后指定 `all` 选项，从而生成一个包。例如，前一个查询中的 `union all` 将导致 Lance 在结果中出现两次。通常，如果某行在一个结果表中出现 *m* 次，在另一个结果表中出现 *n* 次，则它在两个结果的包并集中将出现 *m* + *n* 次。

由于最终结果中的列标题取自并集中的第一个查询，因此此处出现标题“shortName”。虽然此查询可以用其他方式表述（稍后见子查询），但并集运算提供了从兼容结果表合并结果的最自然方法。

由于基表很少是并集兼容的，因此并集运算符主要用于通过投影使其并集兼容的派生表，如此例所示。`union` 运算可在一个查询中多次应用。如果使用 `order by` 子句，它必须位于并集中最后一个查询之后。例如，追加子句 `order by` shortName 将结果排序为“Colleen”、“JimO”、“Lance”、“Walter”。

在 SQL-92（及更高版本）中，可添加 `corresponding` 选项以指定用于并集的公共列。例如，如果 [图 12.50](#Ch012_539-646_B9780443237904000268_1.xhtml#f0255) 中的 driver 列改名为“shortName”，则该查询可声明为 `select` * `from` Person `union corresponding` Drives 或 `select * from` Person `union corresponding by` (shortName) Drives。大多数 SQL（包括 SQL Server）尚不支持此选项。

现在考虑查询：谁驾驶福特、霍顿或本田（即谁至少驾驶这些车型中的一种）？虽然我们可以使用两个并集来表述此查询，但只需扫描一次 Drives 表的行即可回答该查询。因此，使用 `or` 运算符更简单（且更高效），如下所示：

*   ```
    select driver from Drives
    ```

*   ```
    where carModel = ‘Ford’ or carModel = Holden’ or carModel = ‘Honda’
    ```
