# Bootstrap

The bootstrap file for PHPUnit is `tests/Bootstrap.php`. It is executed once before running test cases. It has three parts:

1. A nearly complete copy of CodeIgniter's index.php file.
2. Initialization of the Monkey Patch library.
3. Calls the PHPUnitTest::init() method.

PHPUnitTest::init() method registers the autoloader, which loads new functions as well as the replaced classes and functions. It also executes CodeIgniter's core/CodeIgniter.php, but not all of it. You can see the replaced version of it in `replacing/core/CodeIgniter.php`.

# Autoloader

The file `tests/autoloader.php` registers the autoloader. The PHPUnitTest-Autoloader::load() method provides the autoloader's functionality. It autloads ci-phpunit-test classes like controllers, models, and libraries.

# Replaced Classes and Functions

Some CodeIgniter classes and functions are replaced by ci-phpunit-test to make it easier to write tests. You can see all of replaced function and class names in How to Write Tests. Most of functions and classes replaced by ci-phpunit-test were replaced for two reasons:

1. To reset the CodeIgniter super object
2. To provide behavior only for testing

https://github.com/kenjis/ci-phpunit-test/blob/docs/ToWriteTests.md#can-and

The first is required primarily because the CodeIgniter super object is a form of singleton. Singleton is a design pattern that restricts the instantiation of a class to one. In fact, under normal circumstances it is expected that only one instance will exist. Singletons can be very difficult to test unless you reset them to a known state (for various parts of test). So, ci-phpunit test has the capacity to reset CodeIgniter's super object. Some functions which were replaced to make this `load_class()` and `is_loaded()` possible.

The second is necessary in part because portions of CodeIgniter code do things which would prevent the tests from running. For example `redirect()`, `show404()` and `show_error()` call `exit()`, so ci-phpunit replaces them with versions which do not call `exit()`.

Another example is `CI_load`. When we run tests, we can call more than one controller, and may load a library multiple times. The `CI_load` class has code to prevent more than once, so we need to debug that code.

If you install CodeIgniter and ci-phpunit via Composer, you can check differences in the CI_Load class using the following commands:

```
$ cd vendor/kenjis/ci-phpunit-test
$ bin/check-diff.sh
```

In another example of replacing classes to provide behavior only for testing, `set_header()` is replaced to allow it to function when run from the CLI, and to save the status in the `CI_Output` object, giving ci-phpunit better access to the information.

# New Functions

New functions are needed for the same reasons:

- To reset the CodeIgniter super object
- To provide behavior only for testing

The `reset_instance()` function resets the CodeIgniter super object.

The `load_class_instance()` function provides behavior which is only needed for testing. By injecting a CodeIgniter instance directly into the `load_class()` function, it can manipulate the state of the function. The `set_is_cli()` function allows ci-phpunit to change the return value of CodeIgniter's `is_cli()` function.

# TestCase classes

The PHPUnitTestCase is the base class of the TestCase class. The TestCase class is intended to allow user customization, so it has no logic by default.

The PHPUnitTestCase provides many methods for testing, including assertions, setup, and teardown. It also transfers methods to other objects (e.g. PHPRequest and UnitTestDouble).

# Request related classes

The PHPUnitTestRequest provides the `$this->request()` method. It emulates an HTTP request to a controller or a URI string. If you pass a URI string to `$this->request()`, the PHPUnitTestRequest object resolves the route using the PHPRouter object.

The PHPUnitTestGlobal object sets the super global variables for the request. After phpunit-v0.10.1, it will also be used to set global variables for the CodeIgniter core objects.

# Helper classes

There are two helper classes. One is PHPUnitTestDouble, which helps create the PHPUnit Mock and verify invocations. The other is PHPUnitTestReflection, which helps access private methods/properties using PHP Reflection.

Helper classes provide only helper methods or shortcuts. The `$this->getDouble()` and `$this->verifyInvoked()` methods are transferred to the PHPUnitTestDouble object.

The PHPUnitTestReflection class can be used as a ReflectionHelper class. This setup is an alias which can be found in the ci_phpunit_test/alias directory.

# Monkey Patch library

The Monkey Patch library provides the monkey patching functionality by ci-phpunit-test. It can be used as a standalone library, but I recommend using it only for testing.

It provides three patchers:

- ExitPatcher ... converts exit() to an exception
- FunctionPatcher ... patches functions
- MethodPatcher ... patches methods in user-defined classes
