## 第4章 初识自定义泛型

### 

在自定义泛型世界中，类型可以被声明为泛型类型，函数可以被声明为泛型函数。此外，泛型类型是定义类型，因此它们可以拥有方法。

泛型类型、泛型函数或泛型类型的方法的声明包含一个类型参数列表部分，这是与普通类型、函数或方法的主要区别。

### 4.1 一个泛型类型示例

首先，让我们看一个示例来展示泛型类型的样子。它可能不是一个完美的示例，但它确实展示了自定义泛型类型的实用性。

```go
package main

import "sync"

type Lockable[T any] struct {
    sync.Mutex
    Data T
}

func main() {
    var n Lockable[uint32]
    n.Lock()
    n.Data++
    n.Unlock()

    var f Lockable[float64]
    f.Lock()
    f.Data += 1.23
    f.Unlock()

    var b Lockable[bool]
    b.Lock()
    b.Data = !b.Data
    b.Unlock()
}
```

```go
type LockableUint32 struct {
    sync.Mutex
    Data uint32
}

type LockableFloat64 struct {
    sync.Mutex
    Data float64
}

type LockableBool struct {
    sync.Mutex
    Data bool
}

type LockableBytes struct {
    sync.Mutex
    Data []byte
}

func main() {
    var n LockableUint32
    n.Lock()
    n.Data++
    n.Unlock()

    var f LockableFloat64
    f.Lock()
    f.Data += 1.23
    f.Unlock()

    var b LockableBool
    b.Lock()
    b.Data = !b.Data
    b.Unlock()

    var bs LockableBytes
    bs.Lock()
    bs.Data = append(bs.Data, "Go"...)
    bs.Unlock()
}
```

非泛型代码包含许多代码重复，可以通过使用上述演示的泛型类型来避免。

### 4.2 泛型类型方法的示例

有些人可能不喜欢上述泛型类型的实现。相反，他们更倾向于使用如下代码所示的不同实现。与上一节中的 Lockable 实现相比，新的实现对外部包用户隐藏了结构体字段。

```go
package main
```

```go
println(NoDiff[bool]())  // true

// _ = NoDiff() // error: cannot infer V

// error: *** does not implement comparable
// _ = NoDiff([]int{}, []int{})
// _ = NoDiff(map[string]int{})
// _ = NoDiff(any(1), any(1))
}
```

在上面的示例中，NoDiff 是一个泛型函数。与非泛型函数不同，与泛型类型类似，泛型函数的声明中有一个额外部分，即类型参数列表。这里，NoDiff 泛型函数的类型参数列表是 [V comparable]，其中 V 是类型参数名称，comparable 是 V 的约束。

comparable 是 Go 1.18 中引入的一个新的预声明标识符。它表示一个由所有可比较类型实现的接口。下一章将更详细地解释它。

这里，类型参数 V 被用作可变（值）参数的类型。

记号 NoDiff[string]、NoDiff[int] 和 NoDiff[bool] 被称为（泛型函数 NoDiff 的）实例化函数。与实例化类型类似，在这些记号中，[string]、[int] 和 [bool] 被称为类型实参列表。在这些列表中，string、int 和 bool 被称为类型实参，它们都被传递给类型参数 V。

如果所有类型实参都可以从值实参中推断出来，那么在实例化函数表达式中可以完全省略整个类型实参列表。这就是为什么在上面的示例中，对 NoDiff 泛型函数的一些调用没有类型实参列表的原因。

- 在调用 NoDiff("Go", "Go", "Go") 中，类型实参被推断为 string，即值实参的默认类型。
- 在调用 NoDiff(123, 123, 123, 123) 中，类型实参被推断为 int，即值实参的默认类型。
- 在以 A{} 和 A{1, 2} 作为值实参的两个调用中，类型实参被推断为 [2]int，即值实参的类型。
- 在以 new(int) 作为值实参的两个调用中，类型实参被推断为 *int，即值实参的类型。

请注意，所有这些类型实参都实现了 comparable 接口。不可比较的类型，例如 []int 和 map[string]int，不能作为 NoDiff 泛型函数调用的类型实参传递。另外请注意，虽然 any 是可比较的（值）类型，但它并不实现 comparable，因此它也不是合格的类型实参。这将在下一章详细讨论。

上面的示例展示了泛型如何避免函数声明中的代码重复。如果没有自定义泛型，我们需要为示例中使用的每个类型实参声明一个函数。这些函数声明的函数体几乎相同。

### 4.4 泛型函数可视为泛型类型方法的简化形式

上一节中展示的泛型函数可以看作泛型类型方法的简化形式，如下代码所示。





```go
~map[int]string
~chan struct{}
~struct{x int}

// unions of terms
uint8 | uint16 | uint32 | uint64
~[]byte | ~string
map[int]int | []int | [16]int | any
chan struct{} | ~struct{x int}
```

我们知道，在 Go 1.18 之前，接口类型可以嵌入

- 任意数量的方法规范（方法元素，即一种接口元素）；
- 任意数量的类型名称（类型元素，即另一种接口元素），但这些类型名称必须表示接口类型。

Go 1.18 放宽了类型元素的限制，因此现在接口类型可以嵌入以下类型元素：

- 任意类型字面量或类型名称，无论是否表示接口类型，但它们不得表示类型参数。
- 波浪线形式。
- 项联合。

接口类型中嵌入的接口元素的顺序并不重要。

下面的代码片段展示了一些接口类型声明，其中 N 和 O 的声明中的接口类型字面量仅在 Go 1.18 之后才合法。

```go
type L interface {
    Run() error
    Stop()
}

type M interface {
    L
    Step() error
}

type N interface {
    M
    interface{ Resume() }
    ~map[int]bool
    ~[]byte | string
}

type O interface {
    Pause()
    N
    string
    int64 | ~chan int | any
}
```

将一个接口类型嵌入另一个接口类型等价于（递归地）将前者的元素展开到后者中。在上面的例子中，M、N 和 O 的声明等价于下面的声明：

```go
type M interface {
    Run() error
    Stop()
    Step() error
}

type N interface {
    Run() error
    Stop()
    Step() error
    Resume()
    ~map[int]bool
    ~[]byte | string
}

type O interface {
    Run() error
    Stop()
    Step() error
    Pause()
    Resume()
    ~map[int]bool
    ~[]byte | string
    string
    int64 | ~chan int | any
}
```

我们可以将单个类型字面量、类型名称或波浪线形式视为只有一个项的项联合。所以简单地说，自 Go 1.18 起，接口类型可以指定一些方法并嵌入一些项联合。

没有任何嵌入元素的接口类型称为空接口。例如，预声明的 any 类型别名表示一个空接口类型。

### 5.2 类型集合和方法集合

在 Go 1.18 之前，接口类型被定义为一个方法集合。自 Go 1.18 起，接口类型被定义为一个类型集合。类型集合只包含非接口类型。

- 非接口类型字面量或类型名称的类型集合只包含该类型字面量或类型名称所表示的类型。
- 如上文所述，波浪线形式 ~T 的类型集合是那些底层类型为 T 的类型组成的集合。理论上，这是一个无限集合。
- 方法规范的类型集合是那些方法集合中包含该方法的非接口类型的集合。理论上，这是一个无限集合。
- 空接口的类型集合是所有非接口类型的集合。理论上，这是一个无限集合。
- 项联合 T1 | T2 | ... | Tn 的类型集合是各项类型集合的并集。
- 非空接口的类型集合是其接口元素类型集合的交集。

由于空接口类型（例如预声明的 any）的类型集合包含所有非接口类型，所以类型 S 的类型集合是空的。上面代码片段中所示的类型 S 的接口类型和底层类型实际上是相同的。

```go
interface {~string; string; M();}
interface {~string; string; M()}
interface {
    ~string
    string
    M()
}
```

如果某个类型 X 的类型集合是接口类型 Y 的子集，我们就说 X 实现了（或满足）Y。这里，X 可以是接口类型或非接口类型。

因为空接口类型的类型集合是任何类型集合的超集，所以所有类型都实现空接口类型。

在上面的例子中，

- 接口类型 S 的类型集合为空，它实现了所有接口类型。
- 所有类型都实现接口类型 Z，这实际上是一个空接口类型。

接口类型指定的方法列表称为该接口类型的方法集合。如果接口类型 X 实现了另一个接口类型 Y，那么 X 的方法集合必须是 Y 的超集。

如果一个接口类型的类型集合可以完全由一个（可能为空的）方法集合定义，则该接口类型称为基本接口类型。在 1.18 之前，Go 只支持基本接口类型。基本接口既可以用作值类型，也可以用作类型约束；但非基本接口只能用作类型约束（截至 Go 1.19）。

在上面的例子中，L、M、U、Z 和 any 都是基本接口类型。

在下面的代码中，x 和 y 的声明行都可以编译通过，但声明 z 的那一行无法编译。

```go
var x any
var y interface {M()}

// error: interface contains type constraints
var z interface {~[]byte}
```

未来 Go 版本是否会支持将非基本接口类型用作值类型，目前还不清楚。

注意，在 Go 工具链 1.19 之前，不支持非基本接口类型的别名。以下类型别名声明自 Go 工具链 1.19 起才合法。

```go
type C[T any] interface{~int; M() T}
type C1 = C[bool]
type C2 = comparable
type C3 = interface {~[]byte | ~string}
```

### 5.3 关于预声明的 comparable 约束的更多内容

如前所述，除了 any，Go 1.18 还引入了另一个新的预声明标识符 comparable，它表示一个由所有可比较类型实现的接口类型。

```go
type G[S ~[]E, E int] struct{}
```

请注意，

- 正如上一节提到的，尽管 E 是一个类型参数类型，[]E 仍然是一个普通（切片）类型。
- S 的底层类型是 interface{~[]E}，而不是 []E。
- E 的底层类型是 interface{int}，而不是 int。

按照 Go 规范，以下代码中的函数和方法声明都无法编译通过。

```go
type C any
func foo1[C C]() {}    // error: C redeclared
func foo2[T C](T T) {} // error: T redeclared
```

```go
type G[G any] struct{x G} // okay
func (E G[E]) Bar1() {}    // error: E redeclared
```

下面的 Bar2 方法声明本应可以编译通过，但当前（Go 工具链 1.19）不能。这是一个将在 Go 工具链 1.20 中修复的 bug。

```go
type G[G any] struct{x G} // okay
func (v G[G]) Bar2() {}    // error: G is not a generic type
```

### 5.10 更多关于泛型类型和函数声明的说明

在上一章中，我们已经见过了泛型类型声明和一些泛型函数声明。与普通类型和函数声明不同，每个泛型声明都有一个类型参数列表部分。

本书不打算进一步讨论泛型类型和函数声明的语法。

泛型类型声明的源类型部分必须是普通类型。因此它可能是

- 复合类型字面量。如上所述，复合类型字面量总是表示普通类型。
- 表示普通类型的类型名称。
- 实例化类型。类型实例化将在下一章中详细解释。目前，我们只需要知道每个实例化类型都是命名普通类型。

下面的代码展示了一些具有各种源类型的泛型类型声明。所有这些声明都是有效的。

```go
// The source types are ordinary type names.
type (
    Fake1[T any] int
    Fake2[_ any] []bool
)
```

```go
// The source type is an unnamed type (composite type).
type MyData [A any, B ~bool, C comparable] struct {
    x A
    y B
    z C
}
```

## 第6章 泛型实例化和类型实参推断

在最后两章中，我们已经使用了几处泛型类型和函数的实例化。本章将对实例化类型和函数作正式介绍。

### 6.1 泛型类型/函数实例化

泛型类型必须被实例化后才能用作值的类型，泛型函数必须被实例化后才能被调用或用作函数值。

通过用类型实参列表替换其声明（规范）中的类型参数列表，泛型函数（类型）即被实例化。（完整）类型实参列表的长度与类型参数列表相同。每个类型实参被传递给对应的类型参数。类型实参必须是非接口类型或基本接口类型，并且只有当它满足（实现）其对应类型参数的约束时才有效。

实例化函数是非泛型函数。实例化类型是命名的普通值类型。

与类型参数列表一样，类型实参列表也括在方括号中，类型实参在类型实参列表中也是用逗号分隔的。类型实参列表的逗号插入规则也与类型参数列表相同。

如果两个类型实参列表的长度相等，并且它们所有对应的类型都相同，则这两个类型实参列表是相同的。如果两个实例化类型是从同一个泛型类型并以相同的类型实参列表实例化出来的，则它们是相同的。

在下面的程序中，泛型类型 Data 被实例化了四次。四个实例化中有三个具有相同的类型实参列表（请注意，预声明的 byte 是预声明的 uint8 类型的别名）。因此，变量 x 的类型、别名 Z 所表示的类型以及定义类型 W 的底层类型是相同的类型。

```go
package main

import (
    "fmt"
    "reflect"
)
```





```go
type Getter[T any] interface {
    Get() T
}

type Age[T uint8 | int16] struct {
    n T
}

func (a Age[T]) Get() T {
    return a.n
}

func doSomething[T any](g Getter[T]) T {
    return g.Get()
}

// The two lines fail to compile.
var z = doSomething(Age[uint8]{255}) // error
var w = doSomething(Age[int16]{256}) // error

// The two lines compile okay.
var x = doSomething[uint8](Age[uint8]{255})
var y = doSomething[int16](Age[int16]{256})
```

### 6.4 将基本接口类型作为类型实参传递

上面提到，如果基本接口类型满足（实现）类型参数的约束，则可以作为类型实参传递给类型参数。下面的代码展示了这样的一个例子。

```go
package main

type Base[T any] []T

type _ Base[any]
type _ Base[error]

func Gf[T any](x T) {}

var _ = Gf[any]
var _ = Gf[error]

func main() {
    Gf[any](123)
    Gf[any](true)
    Gf[error](nil)
}
```

根据当前规范（Go 1.19），对于涉及类型参数的赋值：

- 如果目标类型是类型参数，且源值是一个未类型化的值，那么仅当该未类型化的值可赋值给目标类型参数类型集合中的每个类型时，赋值才有效。
- 如果目标类型是类型参数，但源类型是普通类型，那么仅当源普通类型是未命名的，且其值可赋值给目标类型参数类型集合中的每个类型时，赋值才有效。
- 如果源类型是类型参数，但目标类型是普通类型，那么仅当目标普通类型是未命名的，且源类型参数类型集合中的每个类型的值都可赋值给目标普通类型时，赋值才有效。
- 如果目标类型和源类型都是类型参数，那么赋值无效。

从这些规则中，我们可以得知，一个命名类型的值不能赋值给另一个命名类型。

在下面的代码片段中，有四个无效的赋值。

```go
func dat[T ~int | ~float64, S *int | []bool]() {
    var _ T = 123 // okay
    var _ S = nil // okay
}
```

```go
func zum[T []byte](x []byte) {
    var t T = x // okay
    type Bytes []byte
    var y Bytes = x // okay (both are ordinary types)
    x = t // okay
    x = y // okay

    // Both are named types.
    t = y // error
    y = t // error

    // To make the above two assignments valid,
    // the sources in them must be converted.
    t = T(y)     // okay
    y = Bytes(t) // okay
}
```

```go
func pet[A, B []byte](x A, y B) {
    // Both are type parameters.
    x = y // error: cannot use y as type A in assignment
    y = x // error: cannot use x as type B in assignment
}
```

目前尚不清楚未来 Go 版本是否会放宽这些赋值规则。看起来可能性很小。

```go
func MyNew[T any]() *T {
    var t T
    return &t
```

### 7.14 调用预声明的 make 函数要求其第一个参数（容器类型）具有核心类型

目前（Go 1.19），在下面的代码片段中，函数 `voc` 和 `ted` 都无法编译，而另外两个可以编译。原因是调用预声明的 `make` 函数的第一个参数必须具有核心类型。`voc` 和 `ted` 这两个函数都不满足此要求，而另外两个函数都满足此要求。

```go
func voc[T chan bool | chan int]() {
    _ = make(T) // error: invalid argument: no core type
}
```

```go
func ted[T chan<- int | <-chan int]() {
    _ = make(T) // error: invalid argument: no core type
}
```

```go
type Stream chan int
type Queue Stream
```

```go
func fat[T Stream | chan int | Queue | chan<- int]() {
    _ = make(T) // okay
}
```

```go
func nub[T Stream | chan int | Queue | <-chan int]() {
    _ = make(T) // okay
}
```

根据我的理解，这个要求是为了确保对制作出的容器（在上面的例子中是通道）进行的后续操作始终合法。例如，确保从制作出的通道接收到的值具有指定类型（无论是类型参数还是普通类型）。

就我个人而言，我认为这一要求过于严格。毕竟，在某些情况下，预想的后续操作并不会发生。

要在泛型函数中使用没有核心类型的类型参数的值，我们可以将这些值作为值实参传递给函数，如下面的代码所示。

```go
func doSomething(any) {}
```

```go
func voc2[T chan bool | chan int](x T) {
    doSomething(x)
}
```

```go
func ted2[T chan<- int | <-chan int](x T) {
    doSomething(x)
}
```

由于同样的要求，下面两个函数都无法编译。

```go
func zig[T ~[]int | map[int]int](c T) {
    _ = make(T) // error: invalid argument: no core type
}
```

```go
func rat[T ~[]int | ~[]bool](c T) {
    _ = make(T) // error: invalid argument: no core type
}
```

对预声明的 `new` 函数的调用没有此要求。

### 7.18 关于空类型集合的约束

某些接口类型的类型集合可能为空。空类型集合的接口类型实现任何接口类型，包括其自身。

空类型集合的接口类型在实践中完全无用，但从理论角度看，它们可能会影响实现的完美性。

当前官方标准 Go 编译器（v1.19）的实现中确实存在几个不完美之处。

例如，下面的函数是否应该编译？在最新的官方标准 Go 编译器（v1.19）中，它可以编译。然而，前面的一节提到过，`make` 调用要求其参数具有核心类型。下面代码中声明的约束 `C` 的类型集合为空，因此它没有核心类型，那么 `foo` 函数内的 `make` 调用就不应该编译。

```go
// This is an empty-type-set interface type.
type C interface {
    map[int]int
    M()
}

func foo[T C]() {
    var _ = make(T)
}
```

下面是另一个例子，其中函数 `g` 中的所有函数调用都应该编译通过。然而，在最新的官方标准 Go 编译器（v1.19）中，其中两个调用无法编译。

```go
func f1[T any](x T) {}
func f2[T comparable](x T) {}
func f3[T []int](x T) {}
func f4[T int](x T) {}
```

```go
// This is an empty-type-set interface type.
type C interface {
    []int
    m()
}

func g[V C](v V) {
    f1(v) // okay
    f2(v) // error: V does not implement comparable
    f3(v) // okay
    f4(v) // error: V does not implement int
}
```

当前 Go 规范特别指出：

> 实现限制：如果操作数的类型是一个具有空类型集合的类型参数，编译器可以不报告错误。带有此类类型参数的函数无法被实例化；任何尝试都会在实例化点导致错误。

因此，上述展现出的不完美之处并非官方标准 Go 编译器的缺陷。




```go
func F14[T S1 | S4](v T) {
    _ = v.x // error: v.x undefined
}

func main() {}
```

有一个提案要移除这个限制。一种临时（相当冗长）的变通方法是为涉及的约束和具体类型指定/声明一些 getter 和 setter 方法。

### 8.7 类型参数值的字段不可访问

目前（Go 1.19），即使类型参数具有核心结构体类型，仍然不能通过类型参数的值访问核心结构体类型的字段。例如，以下代码无法编译。

```go
type S struct{x, y, z int}
```

```go
func mod[T S](v *T) {
    v.x = 1 // error: v.x undefined
}
```

上一节提到的限制实际上是本节所述限制的一个特例。

本节所述的限制是在 Go 1.18 发布之前刚刚添加的。它可能会在未来的 Go 版本中被移除。

### 8.8 目前不支持对类型参数的值进行类型切换（type switch）

前面已经提到，从语义角度看，类型参数是一种接口类型。另一方面，类型参数具有波粒二象性。在某些情况下，它表现为其类型集合中的类型。

到目前为止（Go 1.19），不能对类型参数的值做类型断言。以下两个函数都无法编译。

```go
func tab[T any](x T) {
    if n, ok := x.(int); ok { // error
        _ = n
    }
}
```

```go
func kol[T any]() {
    var x T
    switch x.(type) { // error
    case int:
    case []bool:
    default:
    }
}
```

### 8.11 无法构造这样的约束：允许涉及非特定底层类型的转换

而且也不存在像下面假定的 convertibleTo 和 convertibleFrom 这样的预声明约束。

```go
// This function doesn't compile.
func x2y[Tx convertibleTo[Ty], Ty convertibleFrom[Tx],
    // The second value argument is
    // for type inference purpose.
](xs []Tx, _ Ty) []Ty {
    if xs == nil {
        return nil
    }
    ys := make([]Ty, len(xs))
    for i := range xs {
        ys[i] = Ty(xs[i])
    }
    return ys
}
```

```go
var bs = []byte{61, 62, 63, 64, 65, 66}
var ss = x2y(bs, "")
var is = x2y(bs, 0)
var fs = x2y(bs, .0)
```

目前，有一种不优雅的变通实现：

```go
func x2y[Tx any, Ty any](xs []Tx, f func(Tx) Ty) []Ty {
    if xs == nil {
        return nil
    }
    ys := make([]Ty, len(xs))
    for i := range xs {
        ys[i] = f(xs[i])
    }
    return ys
}
```

```go
var bs = []byte{61, 62, 63, 64, 65, 66}
var ss = x2y(bs, func(x byte) string {
    return string(x)
})
var is = x2y(bs, func(x byte) int {
    return int(x)
})
var fs = x2y(bs, func(x byte) float64 {
    return float64(x)
})
```

这种变通方法需要一个回调函数，这使得代码冗长且效率低得多，尽管我承认它有更多的使用场景。
