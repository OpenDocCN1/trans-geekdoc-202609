
```go
func F14[T S1 | S4](v T) {
    _ = v.x // error: v.x undefined
}

func main() {}
```

有一个提案要移除这个限制。一种临时（相当冗长）的变通方法是为涉及的约束和具体类型指定/声明一些 getter 和 setter 方法。

## 8.7 类型参数值的字段不可访问

目前（Go 1.19），即使类型参数具有核心结构体类型，仍然不能通过类型参数的值访问核心结构体类型的字段。例如，以下代码无法编译。

```go
type S struct{x, y, z int}
```

```go
func mod[T S](v *T) {
    v.x = 1 // error: v.x undefined
}
```

上一节提到的限制实际上是本节所述限制的一个特例。

本节所述的限制是在 Go 1.18 发布之前刚刚添加的。它可能会在未来的 Go 版本中被移除。

## 8.8 目前不支持对类型参数的值进行类型切换（type switch）

前面已经提到，从语义角度看，类型参数是一种接口类型。另一方面，类型参数具有波粒二象性。在某些情况下，它表现为其类型集合中的类型。

到目前为止（Go 1.19），不能对类型参数的值做类型断言。以下两个函数都无法编译。

```go
func tab[T any](x T) {
    if n, ok := x.(int); ok { // error
        _ = n
    }
}
```

```go
func kol[T any]() {
    var x T
    switch x.(type) { // error
    case int:
    case []bool:
    default:
    }
}
```

## 8.10 无法构造这样的约束：允许涉及非特定底层类型的赋值

而且也不存在像下面假定的 assignableTo 和 assignableFrom 这样的预声明约束。

```go
// This function doesn't compile.
func yex[Tx assignableTo[Ty], Ty assignableFrom[Tx]](x Tx, y Ty) {
    y = x
}
```

## 8.11 无法构造这样的约束：允许涉及非特定底层类型的转换

而且也不存在像下面假定的 convertibleTo 和 convertibleFrom 这样的预声明约束。

```go
// This function doesn't compile.
func x2y[Tx convertibleTo[Ty], Ty convertibleFrom[Tx],
    // The second value argument is
    // for type inference purpose.
](xs []Tx, _ Ty) []Ty {
    if xs == nil {
        return nil
    }
    ys := make([]Ty, len(xs))
    for i := range xs {
        ys[i] = Ty(xs[i])
    }
    return ys
}
```

```go
var bs = []byte{61, 62, 63, 64, 65, 66}
var ss = x2y(bs, "")
var is = x2y(bs, 0)
var fs = x2y(bs, .0)
```

目前，有一种不优雅的变通实现：

```go
func x2y[Tx any, Ty any](xs []Tx, f func(Tx) Ty) []Ty {
    if xs == nil {
        return nil
    }
    ys := make([]Ty, len(xs))
    for i := range xs {
        ys[i] = f(xs[i])
    }
    return ys
}
```

```go
var bs = []byte{61, 62, 63, 64, 65, 66}
var ss = x2y(bs, func(x byte) string {
    return string(x)
})
var is = x2y(bs, func(x byte) int {
    return int(x)
})
var fs = x2y(bs, func(x byte) float64 {
    return float64(x)
})
```

这种变通方法需要一个回调函数，这使得代码冗长且效率低得多，尽管我承认它有更多的使用场景。
