## 第2章

### 关于 Go 泛型 101

从1.18版本（当前最新版本）开始，Go 支持自定义泛型。

本书讨论 Go 编程语言的自定义泛型特性。本书内容包括：

- 自定义泛型语法
- 类型约束和类型参数
- 类型实参和类型推断
- 如何编写有效的自定义泛型代码
- 当前的实现/设计限制

读者需要熟悉一般的 Go 编程才能阅读本书。特别是，本书的读者应该熟悉 Go 类型系统，包括 Go 内置泛型。内置泛型和 Go 自定义泛型是两个不同的系统。

目前，本书主要关注自定义泛型的语法和概念。当我获得更多使用自定义泛型的经验时，将提供更多实用示例。

## 第4章

### 初识自定义泛型

在自定义泛型世界中，类型可以被声明为泛型类型，函数可以被声明为泛型函数。此外，泛型类型是定义类型，因此它们可以拥有方法。

泛型类型、泛型函数或泛型类型的方法的声明包含一个类型参数列表部分，这是与普通类型、函数或方法的主要区别。

#### 4.1 一个泛型类型示例

首先，让我们看一个示例来展示泛型类型的样子。它可能不是一个完美的示例，但它确实展示了自定义泛型类型的实用性。

```go
package main

import "sync"

type Lockable[T any] struct {
    sync.Mutex
    Data T
}

func main() {
    var n Lockable[uint32]
    n.Lock()
    n.Data++
    n.Unlock()

    var f Lockable[float64]
    f.Lock()
    f.Data += 1.23
    f.Unlock()

    var b Lockable[bool]
    b.Lock()
    b.Data = !b.Data
    b.Unlock()
}
```

```go
type LockableUint32 struct {
    sync.Mutex
    Data uint32
}

type LockableFloat64 struct {
    sync.Mutex
    Data float64
}

type LockableBool struct {
    sync.Mutex
    Data bool
}

type LockableBytes struct {
    sync.Mutex
    Data []byte
}

func main() {
    var n LockableUint32
    n.Lock()
    n.Data++
    n.Unlock()

    var f LockableFloat64
    f.Lock()
    f.Data += 1.23
    f.Unlock()

    var b LockableBool
    b.Lock()
    b.Data = !b.Data
    b.Unlock()

    var bs LockableBytes
    bs.Lock()
    bs.Data = append(bs.Data, "Go"...)
    bs.Unlock()
}
```

非泛型代码包含许多代码重复，可以通过使用上述演示的泛型类型来避免。

#### 4.2 泛型类型方法的示例

有些人可能不喜欢上述泛型类型的实现。相反，他们更倾向于使用如下代码所示的不同实现。与上一节中的 Lockable 实现相比，新的实现对外部包用户隐藏了结构体字段。

```go
package main
```

```go
println(NoDiff[bool]())  // true

// _ = NoDiff() // error: cannot infer V

// error: *** does not implement comparable
// _ = NoDiff([]int{}, []int{})
// _ = NoDiff(map[string]int{})
// _ = NoDiff(any(1), any(1))
}
```

在上面的示例中，NoDiff 是一个泛型函数。与非泛型函数不同，与泛型类型类似，泛型函数的声明中有一个额外部分，即类型参数列表。这里，NoDiff 泛型函数的类型参数列表是 [V comparable]，其中 V 是类型参数名称，comparable 是 V 的约束。

comparable 是 Go 1.18 中引入的一个新的预声明标识符。它表示一个由所有可比较类型实现的接口。下一章将更详细地解释它。

这里，类型参数 V 被用作可变（值）参数的类型。

记号 NoDiff[string]、NoDiff[int] 和 NoDiff[bool] 被称为（泛型函数 NoDiff 的）实例化函数。与实例化类型类似，在这些记号中，[string]、[int] 和 [bool] 被称为类型实参列表。在这些列表中，string、int 和 bool 被称为类型实参，它们都被传递给类型参数 V。

如果所有类型实参都可以从值实参中推断出来，那么在实例化函数表达式中可以完全省略整个类型实参列表。这就是为什么在上面的示例中，对 NoDiff 泛型函数的一些调用没有类型实参列表的原因。

- 在调用 NoDiff("Go", "Go", "Go") 中，类型实参被推断为 string，即值实参的默认类型。
- 在调用 NoDiff(123, 123, 123, 123) 中，类型实参被推断为 int，即值实参的默认类型。
- 在以 A{} 和 A{1, 2} 作为值实参的两个调用中，类型实参被推断为 [2]int，即值实参的类型。
- 在以 new(int) 作为值实参的两个调用中，类型实参被推断为 *int，即值实参的类型。

请注意，所有这些类型实参都实现了 comparable 接口。不可比较的类型，例如 []int 和 map[string]int，不能作为 NoDiff 泛型函数调用的类型实参传递。另外请注意，虽然 any 是可比较的（值）类型，但它并不实现 comparable，因此它也不是合格的类型实参。这将在下一章详细讨论。

上面的示例展示了泛型如何避免函数声明中的代码重复。如果没有自定义泛型，我们需要为示例中使用的每个类型实参声明一个函数。这些函数声明的函数体几乎相同。
