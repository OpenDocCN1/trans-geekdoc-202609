

```go
~map[int]string
~chan struct{}
~struct{x int}

// unions of terms
uint8 | uint16 | uint32 | uint64
~[]byte | ~string
map[int]int | []int | [16]int | any
chan struct{} | ~struct{x int}
```

我们知道，在 Go 1.18 之前，接口类型可以嵌入

- 任意数量的方法规范（方法元素，即一种接口元素）；
- 任意数量的类型名称（类型元素，即另一种接口元素），但这些类型名称必须表示接口类型。

Go 1.18 放宽了类型元素的限制，因此现在接口类型可以嵌入以下类型元素：

- 任意类型字面量或类型名称，无论是否表示接口类型，但它们不得表示类型参数。
- 波浪线形式。
- 项联合。

接口类型中嵌入的接口元素的顺序并不重要。

下面的代码片段展示了一些接口类型声明，其中 N 和 O 的声明中的接口类型字面量仅在 Go 1.18 之后才合法。

```go
type L interface {
    Run() error
    Stop()
}

type M interface {
    L
    Step() error
}

type N interface {
    M
    interface{ Resume() }
    ~map[int]bool
    ~[]byte | string
}

type O interface {
    Pause()
    N
    string
    int64 | ~chan int | any
}
```

将一个接口类型嵌入另一个接口类型等价于（递归地）将前者的元素展开到后者中。在上面的例子中，M、N 和 O 的声明等价于下面的声明：

```go
type M interface {
    Run() error
    Stop()
    Step() error
}

type N interface {
    Run() error
    Stop()
    Step() error
    Resume()
    ~map[int]bool
    ~[]byte | string
}

type O interface {
    Run() error
    Stop()
    Step() error
    Pause()
    Resume()
    ~map[int]bool
    ~[]byte | string
    string
    int64 | ~chan int | any
}
```

我们可以将单个类型字面量、类型名称或波浪线形式视为只有一个项的项联合。所以简单地说，自 Go 1.18 起，接口类型可以指定一些方法并嵌入一些项联合。

没有任何嵌入元素的接口类型称为空接口。例如，预声明的 any 类型别名表示一个空接口类型。

### 5.2 类型集合和方法集合

在 Go 1.18 之前，接口类型被定义为一个方法集合。自 Go 1.18 起，接口类型被定义为一个类型集合。类型集合只包含非接口类型。

- 非接口类型字面量或类型名称的类型集合只包含该类型字面量或类型名称所表示的类型。
- 如上文所述，波浪线形式 ~T 的类型集合是那些底层类型为 T 的类型组成的集合。理论上，这是一个无限集合。
- 方法规范的类型集合是那些方法集合中包含该方法的非接口类型的集合。理论上，这是一个无限集合。
- 空接口的类型集合是所有非接口类型的集合。理论上，这是一个无限集合。
- 项联合 T1 | T2 | ... | Tn 的类型集合是各项类型集合的并集。
- 非空接口的类型集合是其接口元素类型集合的交集。

由于空接口类型（例如预声明的 any）的类型集合包含所有非接口类型，所以类型 S 的类型集合是空的。上面代码片段中所示的类型 S 的接口类型和底层类型实际上是相同的。

```go
interface {~string; string; M();}
interface {~string; string; M()}
interface {
    ~string
    string
    M()
}
```

如果某个类型 X 的类型集合是接口类型 Y 的子集，我们就说 X 实现了（或满足）Y。这里，X 可以是接口类型或非接口类型。

因为空接口类型的类型集合是任何类型集合的超集，所以所有类型都实现空接口类型。

在上面的例子中，

- 接口类型 S 的类型集合为空，它实现了所有接口类型。
- 所有类型都实现接口类型 Z，这实际上是一个空接口类型。

接口类型指定的方法列表称为该接口类型的方法集合。如果接口类型 X 实现了另一个接口类型 Y，那么 X 的方法集合必须是 Y 的超集。

如果一个接口类型的类型集合可以完全由一个（可能为空的）方法集合定义，则该接口类型称为基本接口类型。在 1.18 之前，Go 只支持基本接口类型。基本接口既可以用作值类型，也可以用作类型约束；但非基本接口只能用作类型约束（截至 Go 1.19）。

在上面的例子中，L、M、U、Z 和 any 都是基本接口类型。

在下面的代码中，x 和 y 的声明行都可以编译通过，但声明 z 的那一行无法编译。

```go
var x any
var y interface {M()}

// error: interface contains type constraints
var z interface {~[]byte}
```

未来 Go 版本是否会支持将非基本接口类型用作值类型，目前还不清楚。

注意，在 Go 工具链 1.19 之前，不支持非基本接口类型的别名。以下类型别名声明自 Go 工具链 1.19 起才合法。

```go
type C[T any] interface{~int; M() T}
type C1 = C[bool]
type C2 = comparable
type C3 = interface {~[]byte | ~string}
```

### 5.3 关于预声明的 comparable 约束的更多内容

如前所述，除了 any，Go 1.18 还引入了另一个新的预声明标识符 comparable，它表示一个由所有可比较类型实现的接口类型。

```go
type G[S ~[]E, E int] struct{}
```

请注意，

- 正如上一节提到的，尽管 E 是一个类型参数类型，[]E 仍然是一个普通（切片）类型。
- S 的底层类型是 interface{~[]E}，而不是 []E。
- E 的底层类型是 interface{int}，而不是 int。

按照 Go 规范，以下代码中的函数和方法声明都无法编译通过。

```go
type C any
func foo1[C C]() {}    // error: C redeclared
func foo2[T C](T T) {} // error: T redeclared
```

```go
type G[G any] struct{x G} // okay
func (E G[E]) Bar1() {}    // error: E redeclared
```

下面的 Bar2 方法声明本应可以编译通过，但当前（Go 工具链 1.19）不能。这是一个将在 Go 工具链 1.20 中修复的 bug。

```go
type G[G any] struct{x G} // okay
func (v G[G]) Bar2() {}    // error: G is not a generic type
```

### 5.10 更多关于泛型类型和函数声明的说明

在上一章中，我们已经见过了泛型类型声明和一些泛型函数声明。与普通类型和函数声明不同，每个泛型声明都有一个类型参数列表部分。

本书不打算进一步讨论泛型类型和函数声明的语法。

泛型类型声明的源类型部分必须是普通类型。因此它可能是

- 复合类型字面量。如上所述，复合类型字面量总是表示普通类型。
- 表示普通类型的类型名称。
- 实例化类型。类型实例化将在下一章中详细解释。目前，我们只需要知道每个实例化类型都是命名普通类型。

下面的代码展示了一些具有各种源类型的泛型类型声明。所有这些声明都是有效的。

```go
// The source types are ordinary type names.
type (
    Fake1[T any] int
    Fake2[_ any] []bool
)
```

```go
// The source type is an unnamed type (composite type).
type MyData [A any, B ~bool, C comparable] struct {
    x A
    y B
    z C
}
```

## 第6章 泛型实例化和类型实参推断

在最后两章中，我们已经使用了几处泛型类型和函数的实例化。本章将对实例化类型和函数作正式介绍。

### 6.1 泛型类型/函数实例化

泛型类型必须被实例化后才能用作值的类型，泛型函数必须被实例化后才能被调用或用作函数值。

通过用类型实参列表替换其声明（规范）中的类型参数列表，泛型函数（类型）即被实例化。（完整）类型实参列表的长度与类型参数列表相同。每个类型实参被传递给对应的类型参数。类型实参必须是非接口类型或基本接口类型，并且只有当它满足（实现）其对应类型参数的约束时才有效。

实例化函数是非泛型函数。实例化类型是命名的普通值类型。

与类型参数列表一样，类型实参列表也括在方括号中，类型实参在类型实参列表中也是用逗号分隔的。类型实参列表的逗号插入规则也与类型参数列表相同。

如果两个类型实参列表的长度相等，并且它们所有对应的类型都相同，则这两个类型实参列表是相同的。如果两个实例化类型是从同一个泛型类型并以相同的类型实参列表实例化出来的，则它们是相同的。
