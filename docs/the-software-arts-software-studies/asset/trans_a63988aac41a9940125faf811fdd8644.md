

# 沃尔夫拉姆将他在执行轨迹中看到的模式称为“行为”，仿佛一小块黑白方格能以这样或那样的方式“行为”。

这是一个“借命名为论证”的例子。在展示规则集 110、124、137 和 193 结果的图片中，垂直条纹状的小三角形是沃尔夫拉姆所谓的“可以永久持续的结构”。对角线则是沃尔夫拉姆所谓的“会移动的结构”。我们将通过观察规则集 110 来更仔细地审视这些“结构”。

## 规则集 110

规则集 110 的规则如[图 6.11](#chapter_6.xhtml#fig6_11)所示。如前所述，可以将其视为一个计算机程序：如果以某组数据作为初始状态（编码为一系列黑白方格）启动它，它就会处理这些数据并计算出一系列潜在的无限结果，每个结果都编码为一系列状态中的黑白方格。[图 6.12](#chapter_6.xhtml#fig6_12) 包含一个示例，其中初始状态——即输入数据——是一个巨大的随机二进制数。它展示了在初始状态之后，将规则集 110 的规则串行应用于 250 个状态后的计算过程。

![Figure 6.11 ¶ Rule set 110.](images/030_9495_006_fig_011.png)

[图 6.11](#chapter_6.xhtml#fig6-11) ¶ 规则集 110。

![Figure 6.12 ¶ Rule set 110 with a random series of black and white squares as input.](images/031_9495_006_fig_012.png)

[图 6.12](#chapter_6.xhtml#fig6-12) ¶ 以随机黑白方格序列为输入的规则集 110。

在[图 6.12](#chapter_6.xhtml#fig6_12)中，你能看到沃尔夫拉姆所谓的以三角形柱状形式出现的“持久结构”，以及以由小黑白方格组成的对角线形式出现的“移动结构”吗？其中一些对角线“向左移动”，另一些则“向右移动”？在图中，存在一种“背景模式”：持久结构和移动结构似乎都写在这些小三角形之上。结果表明，如果我们用[图 6.13](#chapter_6.xhtml#fig6_13)所示的背景模式填充初始状态——即十四位二进制数 `11111000100110`（十进制 15910）重复书写——就能让规则集 110 表现得像一个 2 类系统。

![Figure 6.13 ¶ The background pattern for rule set 110.](images/032_9495_006_fig_013.png)

[图 6.13](#chapter_6.xhtml#fig6-13) ¶ 规则集 110 的背景模式。

沃尔夫拉姆及其同事花费数年时间才找到这个背景模式，以及可以写在其上的持久结构和移动结构。他们为规则集 110 发明/发现了二十八种这样的结构。^([136](#chapter_6.xhtml#chapter6-136)) 他们称移动的结构为“滑翔机”，沿用了最初为约翰·康威的“生命游戏”（一种二维元胞自动机）开发的标准术语。^([137](#chapter_6.xhtml#chapter6-137))

一些“滑翔机”从左向右移动。[图 6.14](#chapter_6.xhtml#fig6_14) 展示了四个此类滑翔机的示例。我们姑且称它们为 A1、A2、A3 和 A4，以便通过各自的宽度加以区分。

![Figure 6.14 ¶ Gliders A1, A2, A3, and A4 move from left to right.](images/033_9495_006_fig_014.png)

[图 6.14](#chapter_6.xhtml#fig6-14) ¶ 滑翔机 A1、A2、A3 和 A4 从左向右移动。

其他滑翔机沿对角线向相反方向移动，即从右向左，或者根本不移动，而是继续从一个状态“垂直”延伸到下一个状态。[图 6.15](#chapter_6.xhtml#fig6_15) 从左到右展示了三个滑翔机，我们将它们分别称为 C（垂直）、E（杂乱对角线）和 B1（单宽度对角线）。

![Figure 6.15 ¶ Glider C moves vertically. Gliders E and B1 move from right to left.](images/034_9495_006_fig_015.png)

[图 6.15](#chapter_6.xhtml#fig6-15) ¶ 滑翔机 C 垂直移动。滑翔机 E 和 B1 从右向左移动。

所有这些滑翔机当然也只是黑白方格序列，或者换个说法，就是二进制数：`A1 = 100110`；`A2 = 111000100110`；`A3 = 111110001110100110`；`A4 = 111110001110111000100110`；`B1 = 11111000`；`C = 11111010011100110`；`E = 110000010011000100110`。

我们可以设置这些滑翔机使它们相互“碰撞”。例如，在[图 6.16](#chapter_6.xhtml#fig6_16)中，一个 A2 滑翔机被放置在初始状态的左端，一个 B1 滑翔机被放置在初始状态的右端，中间夹着背景模式。在某个时刻，它们相交了，在“碰撞”之后，B1 滑翔机消失了，而 A2 滑翔机变成了 A1 滑翔机。

![Figure 6.16 ¶ Gliders A2 and B1 collide.](images/035_9495_006_fig_016.png)

[图 6.16](#chapter_6.xhtml#fig6-16) ¶ 滑翔机 A2 和 B1 碰撞。

看到这一现象，可以推测 B1 滑翔机会将 A4 滑翔机变为 A3 滑翔机，并完全抵消 A1 滑翔机。因此，如果我们称背景模式为 Ø，我们或许可以用一种算术符号写出这些可能的碰撞，如下所示：`A4 + B1 = A3`；`A3 + B1 = A2`；`A2 + B1 = A1`；`A1 + B1 = Ø`。

既然已知有二十八种滑翔机可以写在背景模式中，那么就可以安排许多不同种类的碰撞，这些碰撞不仅涉及滑翔机 A1 和 B1，还涉及 C、E 等。这组可能的碰撞形成了一套复杂的“算术”，可用于计算。

我们还需要考虑规则集 110 的另一种结构，它被称为“滑翔机枪”（同样，该术语源自康威的“生命游戏”），因为它会生成一系列 A1 和 B1 滑翔机。滑翔机枪如[图 6.17](#chapter_6.xhtml#fig6_17)所示。

![Figure 6.17 ¶ A glider gun for rule set 110.](images/036_9495_006_fig_017.png)

[图 6.17](#chapter_6.xhtml#fig6-17) ¶ 规则集 110 的滑翔机枪。

在[图 6.17](#chapter_6.xhtml#fig6_17)中，滑翔机枪（二进制表示为 `11111000101100011101110011100011000100110`）被置于初始状态的中间，两侧被多个背景模式副本包围。随着每个后续状态的计算，滑翔机枪向左漂移，并且每隔几次迭代就会向左发射一个 B1 滑翔机，以及较低频率地向右发射一个 A1 滑翔机。

令人惊叹的是，至少从程序员的角度来看，了解了这些“持久”（如 C）和“移动”（如 A1 和 B1）结构及其可能碰撞的“算术”后，我们现在可以通过将一系列滑翔机编码在初始状态中来编写计算机程序。我们在[图 6.16](#chapter_6.xhtml#fig6_16)所示的 A2 和 B1 的碰撞中，看到了最简单的此类程序之一，其中通过 A2 和 B1 滑翔机的“加法”计算出了一个新的 A1 类型滑翔机。

这一洞见不仅让我们理解规则集 110 如何被视为一个计算机程序，还让我们理解构成初始状态的一系列黑白方格如何被写下来以执行计算——换句话说——成为一个计算机程序。通过这种方式，我们可以将数字或数据理解为程序，将程序理解为数据。例如，编码 A2 和 B1 的二进制数不仅仅是数字，它们还是可以碰撞以创造其他数字、其他数据的“移动结构”，而这些数据反过来又可能与其他数据碰撞。数据即程序、程序即数据，这是二十世纪计算学最有力的洞见之一。
