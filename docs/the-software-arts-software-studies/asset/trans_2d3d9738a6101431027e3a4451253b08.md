

利用这种特定用途的编程语言，同样可以定义并模拟前文讨论过的其他一些电路，例如半加器。但我要再次强调，电路模拟器的软件既不等同于实际电路（除其他原因外，还因为前文列举的抽象和简化），也不等同于其模仿对象——布尔逻辑（同样因为，例如电路模拟器中存在布尔逻辑中没有的时间抽象）。用迈克尔·马霍尼的话转述一下：软件既非逻辑也非电路，但软件技艺提供了一种在两者之间不完美转译的手段。

## 逻辑编程

定理证明器可被视为一种高级断言式或声明式语言——逻辑——的“解释器”。^([54](#chapter_5.xhtml#chapter5-54))

几十年来，一些计算机科学家梦想将逻辑用作编程语言。1972年，法国计算机科学家阿兰·科尔默劳尔和菲利普·鲁塞尔在包括罗伯特·科瓦尔斯基在内的多位专家的关键协助下，开发了 `Prolog` 编程语言。^([55](#chapter_5.xhtml#chapter5-55))^([56](#chapter_5.xhtml#chapter5-56)) “Prolog”代表“programming in logic”（逻辑编程）。根据科瓦尔斯基的说法，“逻辑编程背后的驱动力在于这样一个理念：单一形式化体系足以同时涵盖逻辑与计算，且逻辑包含计算。”^([57](#chapter_5.xhtml#chapter5-57))

科瓦尔斯基在一篇1979年论文的标题中，点出了实现这一愿景所固有的困难：“算法 = 逻辑 + 控制。”^([58](#chapter_5.xhtml#chapter5-58)) 若要用稍微不那么简练的方式表达这一思想，可以这样说：虽然逻辑可用于解释输入与输出之间成立的关系，但要编写计算机程序，仍然需要控制——一种指定输入将如何转化为输出的手段。

我们可以重写科瓦尔斯基的标题/等式，通过重新排列使其变为 `逻辑 = 算法 − 控制`，从而更清晰地展现逻辑与算法的主要区别。梦想是要实现 `逻辑 = 算法`，而怀揣此梦想的几代计算机科学家的工作，就是将控制放入逻辑中。显然，要做到这一点，需要改变算法的定义、改变逻辑的定义，或两者兼改。

可以说，正如计算理论中所阐述的算法、以及专业逻辑学家所定义的逻辑，两者都因相互回应而发生了变化。但在该梦想伊始——或许对某些人而言，甚至直到今天——逻辑被定义为谓词逻辑。^([59](#chapter_5.xhtml#chapter5-59)) 回顾前一节关于逻辑与电路模拟的内容，当时所关注的逻辑是乔治·布尔对亚里士多德逻辑的转译。但谓词逻辑则是另一回事。

### 一阶谓词逻辑

直到布尔时代前后，逻辑主要关注亚里士多德的三段论。正如第4章所述，布尔通过将亚里士多德三段论的例子转译为他的新符号系统来开展工作。随后，在接下来的一个世纪（19世纪中叶至20世纪中叶），在乔治·布尔、戈特洛布·弗雷格、查尔斯·桑德斯·皮尔士、大卫·希尔伯特、阿尔弗雷德·诺斯·怀特海、库尔特·哥德尔、鲁道夫·卡尔纳普等人的著作推动下，逻辑发生了根本性变化。根据逻辑学家、哲学家、历史学家何塞·费雷罗什讲述的一部引人入胜的逻辑史，其结果是逻辑扩展以涵盖广泛得多的领域，随后又相对迅速地收敛并聚焦于一阶谓词逻辑。费雷罗什写道：“简要概括我们快速历史回顾的结果，我们可以说1900年前后，逻辑被构想为句子、集合与关系的理论；一战后直至1930年，现代逻辑的典范是高阶系统、简单类型论；直到1940–1950年前后，逻辑学家群体作为一个整体才达成共识，认为范式逻辑系统是FOL（一阶谓词逻辑）。”^([60](#chapter_5.xhtml#chapter5-60))

费雷罗什的历史阐释了当代对逻辑的理解在历史上和语境上是如何具有偶然性的：“人们倾向于认为逻辑具有某种特别清晰和晶体般纯净的本质，但这更多是一种欺骗性的形象而非证据。我预期前述论证可能已使（至少）这一结论变得合理：FOL并非自然的统一，这引发了一种印象，即逻辑的概念涉及某种晦涩或不确定性。但如果是这样，我们为何以及如何走向了现代一阶逻辑？显而易见，当第一性原理不足时，我们必须转向历史语境与传统。”^([61](#chapter_5.xhtml#chapter5-61)) 换言之，今天，当逻辑学家、数学家、哲学家和计算机科学家谈论“逻辑”时，他们指的是20世纪初一种非常具体且相对较新的发明。^([62](#chapter_5.xhtml#chapter5-62))

### 变量与量词

19世纪末，弗雷格和皮尔士独立发明了区分现代逻辑与其亚里士多德前身的两个最重要方面：带变量的谓词和量词。^([63](#chapter_5.xhtml#chapter5-63))

为何带变量的谓词在逻辑中如此重要？请考虑在命题逻辑中，可以写出类似“如果A则B”这样的内容。A和B代表命题。或许A代表“苏格拉底是人”，B代表“苏格拉底是凡人”。因此，“如果A则B”代表“如果苏格拉底是人，则苏格拉底是凡人”。

如果我们只关心关于苏格拉底的推论，这很好；但如果我们关心关于柏拉图、阿尔西比亚德——许多人的推论，而不仅仅是苏格拉底，该怎么办？带变量谓词的引入允许陈述更普遍的规则，如：“如果 `man(x)` 则 `mortal(x)`。”当自由变量 `x` 绑定到苏格拉底时，该普遍规则的一个具体实例如下：“如果 `man(苏格拉底)` 则 `mortal(苏格拉底)`。”带变量的谓词允许陈述此类普遍规则，这在命题逻辑中无法简洁地表达。

量化问题之所以出现在皮尔士和弗雷格各自的谓词演算中，是因为一旦陈述了带变量的谓词，就必须考虑什么可以绑定到谓词的变量上。例如，该谓词是否适用于所有人？也许吧，但想象你是基督徒。这听起来对吗：“如果 `man(耶稣)` 则 `mortal(耶稣)`”？神学问题暂且不论，弗雷格和皮尔士各自都看到了引入全称量词和存在量词的必要性，以解决普遍性与特殊性问题。

如今，全称量词通常写作倒置的“A”，表示“对所有（ALL）”。因此，可以这样写所有人都是凡人：“`∀x(如果 man(x) 则 mortal(x))`。”

如今，存在量词通常写作旋转的“E”，表示“存在（EXISTS）”。因此，可以这样写存在某个凡人：“`∃x(如果 man(x) 则 mortal(x))`。”带有存在量化变量的谓词，是关于某个特定的人，而非所有人。

### Prolog编程

回到前文引用的科瓦尔斯基的驱动动机，开发逻辑编程的人旨在用逻辑的符号系统编写语句，并让这些语句作为计算机程序运行。在 `Prolog` 编程语言中，可以像这样编写谓词和断言：^([64](#chapter_5.xhtml#chapter5-64))

```
man(socrates).

man(plato).

mortal(X):- man(X). % This means X is mortal if X is a man.
```

`Prolog` 解释器允许我们查询数据库中直接断言的语句，也允许我们查询可从数据库中的语句（通常称为断言）和谓词推导出的语句。因此，像这样的查询

```
?- man(Who)
```
