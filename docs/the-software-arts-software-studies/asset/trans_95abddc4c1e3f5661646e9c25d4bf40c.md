
# 一个人可以通过看到克努斯为一个具有非常受限且历史上偶然的词源学的术语提供了当代翻译，来理解克努斯对“算法”定义中固有的歧义。

克努斯对算法的定义是自相矛盾的，因为他既认为算法依赖于计算机编程语言的编码，又认为算法完全独立于编码。他的定义是循环论证的，因为算法是用有效方法定义的，而有效方法又是用算法定义的。他的定义是高度受限的，因为算法应该是有限的——在有限步骤后终止——然而我们今天使用计算机做的大多数事情涉及的系统被设计为无限运行、永不终止，因此根据克努斯的说法它们不是算法。最后，克努斯对“算法”的定义偷偷引入了一种高度受限但又模棱两可的人类主观性形式，因为他将其与一个未定义的人用铅笔和纸能做的事情联系起来。

尽管他频繁使用历史例子，克努斯的定义却是非历史的。克努斯在书的开头讨论了“欧几里得算法”，这是一种寻找两个数最大公约数的迭代方法。它出现在欧几里得的《几何原本》第七卷，命题1和2中。古希腊数学家欧几里得生活在公元前四世纪中叶，但归功于他的算法可以很容易地用一行现代编程语言（如 JavaScript）来编写：

```
function gcd(m,n) {if (n == 0) return(m); else return(gcd(n,m%n));}
```

欧几里得的方法被称为“算法”已经很长时间了，早在克努斯开始写书之前就已经这样称呼了。然而，当欧几里得设计出这个方法时，它肯定不叫算法，因为“algorithm”这个词在古希腊语中不存在。^([10](#chapter_4.xhtml#chapter4-10))

**algorithm**, *n*.

起源：源自拉丁语借词。词源：拉丁语 *algorithmus*。

词源学：后古典拉丁语 *algorithmus*（15世纪），*algorismus* 的变体^([11](#chapter_4.xhtml#chapter4-11))

根据《牛津英语词典》，古希腊语中最接近的术语是“ἀριθμός”，意为数字。古希腊人也有表示有理近似和计算的词汇，但“algorithm”源自后古典拉丁语。因此，称欧几里得的方法为算法是时代错乱的。我们之所以能那样称呼它，唯一的方式是忘记所有最终将欧几里得文本第七卷命题1和2转录和翻译成一种可与我们现在所谓的算法相提并论、并能如此简单地用一行代码写出的形式的工作。

类比而言，我们可以称十八世纪的马车为“早期汽车”，但要这样做，我们需要承认使这种对十八世纪车辆的高度特异性解读成为可能的历史和技术背景。但也许最重要的是，通过用一个新名字称呼一种旧技术或技艺，我们需要承认我们这样做冒着将我们时代的目的论、一套价值观和意图输出给它的风险。

我提议我们研究较旧的方法如何能够或已经被翻译成算法，此外，还要研究“算法”的定义本身是如何随时间变化的。这一提议旨在与克努斯有缺陷但仍具影响力的定义以及对“算法”一词的时代错乱应用形成对比。克努斯对“算法”的公理化消解了历史、语境和解释的混乱性。

克努斯的努力旨在试图使算法成为一种数学或逻辑。但是，先验地讲，算法不是数学，所以，毫不奇怪，算法分析是一门非常困难的学科。

## 算法即食谱

那么，如果算法不是数学或逻辑，那它们是什么？正如科学史学家帕梅拉·朗所描述的，算法与关于机械技艺的著作的悠久历史密不可分，包括“与技术生产相关的古代著作，如希腊化时期的工程书籍，以及与政治和军事实践相关的著作，包括色诺芬的《经济篇》和罗马农业著作。”^([12](#chapter_4.xhtml#chapter4-12)) 这一传统包括中世纪行会规章，并延续至今的专利法语言和操作指南，至关重要的是，这一机械技艺传统还包括食谱和烹饪书。

克努斯认识到这种与技艺的直接联系，但并未严谨地深入探讨。在《计算机程序设计艺术》第一卷第一章中，克努斯将算法比作食谱，断言“计算机程序员通过研究一本好的食谱书可以学到很多东西”，然后承认“作者几乎忍不住想把这卷书命名为‘程序员的食谱’。也许有一天他会尝试写一本叫‘厨房算法’的书。”^([13](#chapter_4.xhtml#chapter4-13))

将算法比作食谱的做法，克努斯绝非孤例。这种做法至今仍是惯用语。普林斯顿大学计算机科学教授、算法分析专家伯纳德·沙泽尔在其 2006 年的文章《算法：现代科学的成语》中写道：“算法常被比作食谱。就陈词滥调而言，这或许有点陈旧，但请记住：没有一个能引起食欲的隐喻是真正糟糕的。此外，这种文学类比非常贴切。算法是——并且应该被理解为——文学作品。”^([14](#chapter_4.xhtml#chapter4-14))

数学与机械技艺之间的这种角力，克努斯尝试的算法公理与食谱烹饪书之间的角力，象征着我在这本书中叙述的几乎所有争议。通常，就像这里克努斯和沙泽尔的著作一样，争议的双方都是由同一位著名计算机科学家撰写的。在理性层面上，他们试图将软件纳入数理逻辑。在诗性层面上，他们将其拉回厨房、车间或机械技艺的工作室。然而，正如这里的引文所示，当计算机科学家称计算为一门艺术时，通常是在开玩笑，或者至少是轻率地、不严谨地进行的。但如果我们认真对待这些轻率的俏皮话会怎样？如果软件确实是一门艺术，那它是什么？

在第3章关于语言的内容中，我通过考察十八世纪法国的技艺“食谱”来探讨这个问题，但让我们重温这一见解，同时牢记克努斯的算法特征。

首先，考虑确定性条件。假设你第一次光临一家餐厅，对主厨的招牌菜一见钟情（爱在第一口）。你在伦敦的 Le Gavroche，主厨是米歇尔·鲁，招牌菜是他的瑞士奶酪舒芙蕾。你询问侍者是否有可能当面向主厨致意。鲁先生在厨房抽空了一分钟，所以你有幸与他交谈。在极力感谢之后，你大胆地向他索要食谱。令你惊讶的是，鲁先生说：“这道菜没有秘密！它只是一个烤在双层奶油上的奶酪舒芙蕾。你可以在我的《Le Gavroche 食谱》中找到完整食谱，那是我 2001 年出版的。”
