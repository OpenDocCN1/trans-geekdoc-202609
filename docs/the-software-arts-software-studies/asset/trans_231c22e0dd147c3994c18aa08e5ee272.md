

# 1997 年，彼得·韦格纳在《ACM 通讯》上发表题为“为什么交互比算法更强大”的文章，向计算机科学家同行阐述了这一观点。^([21](#chapter_8.xhtml#chapter8-21))

韦格纳首先批判了图灵机（从而也批判了算法）：“图灵机是一个封闭的、非交互式的系统，在计算过程中将外部世界拒之门外。”^([22](#chapter_8.xhtml#chapter8-22)) 随后，他引入了一个称为“交互机”的构造，并证明了图灵机无法捕捉交互机的行为，从而表明交互机比算法和图灵机更强大。

韦格纳论文中最简单的交互机是“恒等机”，它永不终止，只是将输入的任何内容作为输出反射回去。一台既能录制又能在预览窗口中同步播放录像的摄像机，就是这种恒等机的绝佳例子。通过与机器外部的世界（通过不断变化的视频流）持续耦合，该机器的构造超越了图灵机的功能，后者需要固定的输入并计算单一的输出。

韦格纳提出的此类论证经常直接或间接地引用乔姆斯基层级（见第 7 章讨论）。该层级建立在某些机器比其他机器更简单这一观念之上，因此人们认为将更复杂的机器转译为乔姆斯基层级中较低层级的机器类型是不可能的。回顾一下，通用图灵机（UTM，或 0 型文法）位于乔姆斯基层级的顶端，而有限状态自动机（FSA，或 3 型文法）位于底端。计算机科学教育中的传统教学法告诉我们 UTM 是最强大的，但韦格纳本质上是在论证——米尔纳也是如此——与机器外部世界交互的机器比 UTM 更强大。^([23](#chapter_8.xhtml#chapter8-23))

## 数学世界观与交互世界观

作为一名学习计算机科学的大学生，人们很可能会在计算理论导论课上遇到这样一种观念：UTM 是最强大的计算模型。但在计算机科学课程中侧重于系统的课程——操作系统、界面设计、软件工程等——乔姆斯基层级经常被忽略，因为在系统课程中，人们必须定期设计和实现交互机、选择机，而这些无法被指定为数学函数或算法。例如，构建一个包含按钮的界面，需要编写用户点击鼠标时会发生什么的代码。界面、操作系统——事实上，所有类型的软件系统——都是为处理中断和交互而设计的。

韦格纳的观点，即交互机比算法更强大，是大多数软件从业者的常识。尽管如此，图灵机和算法仍然占据着计算机科学教育的核心地位。韦格纳称之为“数学世界观”，并将其与“交互世界观”形成对比，在后者中，人们可以理解并非所有软件系统都是算法或图灵机。^([24](#chapter_8.xhtml#chapter8-24))

正是数学世界观支撑了斯蒂芬·沃尔弗拉姆等人的主张（见第 6 章探讨）——这种观点继续重视乔姆斯基层级并将图灵机置于其顶端。沃尔弗拉姆等人论证称，某些规则集（如规则 110 的规则集）能够模拟任何图灵机，因此具有图灵完备性。一旦确立了图灵完备性，论证就会基于这样一个预设继续进行：UTM 是所有可能机器中最强大的，因此能够复现任何和所有其他过程的行为——因此，它们的图灵完备形式化体系（例如一维元胞自动机）是一种通用的（因而完美的）语言，宇宙中一切的动力学无异于该形式化体系的执行。

鉴于韦格纳、米尔纳等人展示了图灵机的局限性，沃尔弗拉姆关于他所谓的“计算等价性”的演示（其枢纽在于图灵完备性）便成了夸大之词。请记住，如果沃尔弗拉姆的自动机仅与 UTM 一样强大，他甚至无法用他的形式化体系渲染李教授的洗碗机！

谜题不在于沃尔弗拉姆是否正确。他并不正确。相反，正如第 6 章所探讨的，问题是，为什么他一开始会被认为令人信服？并且，对于谁来说，他的归纳演示修辞——其枢纽在于假设的图灵机全能性——被视为一种制胜的论证风格？

我们在乔姆斯基及其追随者身上面临着一个类似的谜题。为什么他的自动机和文法层级被认为如此重要，以至于要教给所有计算机科学专业的本科生？为什么如此多不同领域的专家觉得他的转换生成文法如此引人入胜？也许更切中要害的是，为什么将语法艺术——在其鼎盛时期，不亚于诠释艺术——重构为计算问题会如此引人入胜？正是由于这项工作，乔姆斯基成为 20 世纪被引用最多的作者之一。

数学世界观在计算机科学中——以及现在在许多将计算机科学视为基础的其他研究领域中——依然占据主导地位。但用迈克尔·马洪尼的话说：“如果计算机和程序‘本质上是数学对象’，那么与实际关切相关的计算机和程序的数学迄今为止被证明是难以捉摸的。虽然编程语言借用了数学符号的外衣，但它们并不容易转化为能够捕捉计算中最受关注行为的数学结构。……因此，计算机科学仍然是数学理论、工程实践和技艺技能的混合体。”^([25](#chapter_8.xhtml#chapter8-25))

## 计算机科学的议程

作为理解数学世界观如何能在计算领域占据霸权地位（即使它并非全能）的一步，我们可以求助于马洪尼的“议程”概念：

在追溯一门学科的出现时，用其议程来思考是很有用的，即该学科的从业者一致认为应该做什么，关于该领域问题的共识、它们的重要性或优先顺序、解决它们的手段，以及也许最重要的是，什么构成了解决方案。……学科内部的冲突往往归结为对议程的分歧。……无法调和的冲突可能会以独立议程的形式导致新学科的出现。……正如共同的拉丁词根所示，议程关乎行动：该做什么？^([26](#chapter_8.xhtml#chapter8-26))

因此，即使我们像马洪尼那样将计算视为数学理论、工程实践和技艺技能的混合体，查看 ACM/IEEE《计算机科学课程 2013》，我们也可以看到，数学在“算法”的标签下，依然位于议程的顶端。
