# Appendix A

# Managing Security Center at scale

BY TIANDER TURPLIN, SENIOR PROGRAM MANAGER, CxE SECURITY

In this fast-evolving world where threats are equally fast evolving, any security solution must be able to support a Continuous Integration/Continuous Deployment (CI/CD) pipeline with a management-at-scale vision. Microsoft Azure has three important cornerstones to support this: Azure Resource Manager (ARM) templates, Azure Policy, and Azure management groups. This appendix covers the main considerations regarding managing Security Center in scale.

# The importance of management at scale

Limiteless cloud speed and scale allows you to create as many subscriptions in Azure as you like. However, this introduces manageability and compliance challenges. How can you enforce and achieve compliance across your tenants—and potentially, across hundreds of subscriptions—in an efficient and automated way? Key concepts to achieve that are management groups, ARM Templates, and Azure Policy.

# The three templates

With ARM templates, you declare your deployment in the form of a JSON file, which contains the objects you want. It contains the type of resources, names, and properties. The JSON file can be checked into a source control solution, supports versioning, and enables you to deploy Azure “infrastructure as code.\ The two deployment types, incremental and complete, enable you to only deploy what is declared in the template (complete) or to add/update additional resources (incremental). The complete deployment deletes all the resources that are not specified in the template. Therefore, incremental is the default deployment type. An ARM template is idempotent, meaning that either a resource will be created if it does not exist, or an existing resource will be updated.
