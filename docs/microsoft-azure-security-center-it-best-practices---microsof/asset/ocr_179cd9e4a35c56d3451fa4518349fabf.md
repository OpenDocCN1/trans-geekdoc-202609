# Using threat hunting to find undetected attacks

> an evolving threat landscape, it is inevitable that some attacks will slip through the cracks. Mature security organizations use threat hunting to identify and respond to such attacks. When threat hunting, security analysts must sort through mountains of log data. Microsoft has built tools into Azure Sentinel to streamline this process and help analysts take advantage of Microsoft experience.

Azure Sentinel is built on Log Analytics, which provides a rich KQL experience for filtering, summarizing, and joining data sets to zero in suspicious behaviors. The Microsoft Threat Intelligence Center provides baked in hunting queries based on years of experience. These queries can be run as for immediate results with minimal time investment. Alternatively, these queries can be customized to target specific threats and adapt to the specific needs of your environment.

Once an analyst has found an interesting result, analysts can create Hunting Bookmarks to preserve and share queries and query results with teammates. Analysts can also record contextual observations by adding notes and tags. All bookmarked data can be investigated using the Azure Sentinel investigation experience, which lets analysts explore the relationships between entities, as IP addresses, hosts, and accounts, in a graphical user interface. This interface is also great for visually communicating findings to those not intimately involved in data analysis.

Azure Sentinel supports Jupyter notebooks, which enables analysts to tap into the community of data scientists and security analysts using ML and customized visuals to identify threats. Azure Sentinel comes preloaded with purpose-built Jupyter notebooks with self-contained hunting workflows. Visualizations are included in each notebook for faster data exploration.
