## File integrity monitoring

File Integrity Monitoring (FIM), helps to protect the integrity of your system and applications as Security Center will be continuously monitoring the behavior of your registry and configuration files. If some abnormal change to the files or a malicious behavior is detected, Security Center will track this change, allowing you to stay in control of your files. FIM leverages Azure Change Tracking solution to track and identify changes in your VMs. When File Integrity Monitoring is enabled, you have a Change Tracking resource of type Solution. If you remove the Change Tracking resource, the File Integrity Monitoring feature in Security Center will be automatically disabled.

To enable FIM in your workflow, follow the steps below:

- 1. In Security Center dashboard, under Advanced Cloud Defense, click File Integrity Monitoring. The File Integrity Monitoring blade appears with the list of workspaces that you can select to monitor. If this is the first time you are using this feature, you will see the Enable beside the workspace as shown in Figure 5-9.

![](img/4b11e95292819ab1a383a41ef73aedb4_119_0.png)

- 2. Click the Enable button, and in the Enable File Integrity Monitoring blade, confirm that you have Windows Files, Registry, and Linux Files selected. Click the Enable File Integrity Monitoring button to commit the changes.

It may take some time for FIM to identify the total amount of computers that are in the workspace, make sure to use the Refresh button to see if all computers are already there. In the example above, there are only three computers in this workspace. When you enable FIM before onboarding computers, the Total Computers column will appear as zero, as in Figure 5-9.

## Customizing your settings

Although Security Center will suggest which files and registry keys you should monitor, you can still customize and add your own preferences. Follow the steps below to perform this customization:

- 1. In Security Center dashboard, under Advanced Cloud Defense, click File Integrity Monitoring. The File Integrity Monitoring blade appears; the workspace in which you want to make the changes.

- 2. In the File Integrity Monitoring blade, click the Settings button, as shown in Figure-5-11, and the Workspace Configuration blade appears as shown in Figure 5-11.

![](img/4b11e95292819ab1a383a41ef73aedb4_120_0.png)

![](img/4b11e95292819ab1a383a41ef73aedb4_120_1.png)

- 3. The first tab that you see is the Windows Registry tab, which contains all registry keys that are available to monitor. Notice that some are set to False (in the Enabled column), which means they are not being monitored, and others are True, which means it is currently monitoring that key. To add a new registry key, click Add and the Add Windows Registry for Change Tracking dialog box appears, as shown in Figure 5-12.

![](img/4b11e95292819ab1a383a41ef73aedb4_120_2.png)

- 4. In the Item Name field, type a friendly name for this registry key.

- 5. In the **Windows Registry Key** field, type the registry path (for example: HKEY_LOCAL_MACHINE\Software\Windows\CurrentVersion\Run).

- 6. Click the **Save** button to commit your changes.

While the addition of a new registry key to monitor is very straightforward, there are more options to configure for Windows files. To see the options available, click the **Windows Files** tab and click the **Add** button. The **Add Windows File for Change Tracking** page appears, as shown in Figure 5-13.

![](img/4b11e95292819ab1a383a41ef73aedb4_121_0.png)

**Figure 5-13** Adding new files to track changes

In addition to the **Item Name** and **Enter Path** boxes, you also have the **Recursion** option that can be set to On or Off. Recursion allows you to specify wildcards to simplify tracking across directories and environment variables to allow you to track files across environments with multiple or dynamic drive names. If you use wildcards, keep in mind that you may only use them in the last segment of a path (For example, wildcards could be used like this: `c:\folder\*file` or `/etc/*.conf`). The second option is **Upload File Content**, which can be set to either of the following settings:

- **True**. Choosing this option tracks when files are uploaded to this folder.

- **False**. Choosing this option means files uploaded to this folder will not monitored.

For Linux files, click **Linux Files** > **Add**. The **Add Linux File for Change Tracking** page appears, as shown in Figure 5-14.

![](img/4b11e95292819ab1a383a41ef73aedb4_122_0.png)

In the **Path Type** field, you can select whether you want to monitor a file or a directory. The **Use Sudo** option can be set to On, which means Sudo will be used when checking the item, or it can be set to Off. The Link field determines how symbolic links are dealt with:

- **Ignore**: This option ignores symbolic links, and it will not include directories.

- **Follow**: This option follows symbolic links during recursion.

- **Manage**: This option follows symbolic links and allows altering content.

The Content tab (shown in Figure 5-15) has the relevant settings to enable this capability, which requires a storage account.

![](img/4b11e95292819ab1a383a41ef73aedb4_123_0.png)

**FIGURE 5-15** Configuring File Content settings

To connect an existing storage account to this feature, click the Link button.
