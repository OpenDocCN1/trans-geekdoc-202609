From the Azure subscription-owner perspective, it is important to control the user's identity and roles. You can securely publish resources that are available in your VM, such as a web server, and have access to these resources using access control lists (ACLs). You can also isolate VMs in the cloud by creating different virtual networks (VNets) and controlling traffic between VNets using security groups (NSGs).

One thing in Azure that might be different from what you use on-premises is how it isolates one customer's network from another's. On-premises, you might use different virtual switches to separate different networks from each other. That's perfectly reasonable. You can do that because you control the entire network stack and the IP addressing scheme on your network, as well as the entire routing infrastructure. Azure can't give each customer that level of control because it needs to reuse the same IP address space among all the different customers, and it can't tell each customer what segment of the private IP address space to use for their VMs. It can, however, apply isolation between tenants to better manage the IP space.

Network access control is as important on Azure virtual networks as it is on-premises. The principle of least privilege applies both on-premises and in the cloud. One way to enforce network access controls in Azure is by taking advantage of NSGs. An NSG is equivalent to a simple stateful packet-filtering firewall or router, which is similar to the type of firewalling done in the 1990s (I say this not to be negative about NSGs, but to make it clear that some techniques for network access control have survived the test of time).

## Leveraging machine learning and cloud scale to protect against DDoS attacks

Sophistication and frequency of DDoS attacks continue to increase, hitting nearly two in five businesses. DDoS attacks are the prevalent cause of service outages and due to an ever-growing problem. More importantly, DDoS attacks are often used as a "smokescreen", masking more malicious and harmful infiltration. The technology to create DDoS attacks continues to increase in sophistication while the cost and ability to instigate these attacks gets more accessible. Therefore, the ease and frequency at which criminals can wreak havoc on businesses and is driven up.

Azure DDoS Protection leverages machine learning to automatically build adaptive and customized protection policies for each protected application. As the traffic flows through the network, Azure's proprietary machine-learning algorithm picks up anomalies in the protected applications are being accessed and initiates mitigation instantaneously. This is made possible by creating unique DDoS protection policies for each protected application and protocol (TCP, TCPSYN, and UDP) combination, based on the ML algorithms. The service accomplishes this customization using two insights:

- Automatic learning of per-customer (per-IP) traffic patterns for Layer 3 and 4.
- Minimizing false positives, considering that the scale of Azure allows it to absorb a significant amount of traffic.

When an anomaly is detected in the network pattern (with high enough confidence), we send the traffic to our mitigation pipeline for further inspection; there, we drop malicious flow and pass only good traffic to the backend application, maintaining its availability and performance. We also enrich our algorithms with insights gained from other environments in Azure, including our first-party services, such as Xbox and Office 365.
