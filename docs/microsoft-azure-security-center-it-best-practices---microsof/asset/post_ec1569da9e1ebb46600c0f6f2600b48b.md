
This control—which is enabled through Azure network capabilities rather than through any feature or on the VM itself—is exerted over incoming connections from the Internet. The Azure Security Center JIT VM access feature is fairly simple. Here are the key points:

- The primary goal of Azure Security Center JIT is to protect VM management ports, such as RDP, SSH, and remote PowerShell ports.
- JIT limits the amount of time a port is open. The port will be open only for as long as is needed to get the work done. (You define the duration).
- Network security group (NSG) rules control access to the management ports defined in the JIT policy.
- Only ARM VMs support Azure Security Center JIT VM access.
- We recommend that you use JIT on all VMs that support it. Indeed, the times we do not recommend using JIT when there is no NSG associated with the VM or when the VM is a classic VM.
- Sometimes, when a VM might be a candidate for JIT VM access, Azure Security Center doesn't issue a recommendation to that effect. This occurs when the JIT solution is disabled by a security policy set at the subscription or resource-group level, when the VM doesn't have a public IP address, and when the VM is not associated with an NSG.
- JIT VM access provides a collection of default management ports that you can use to enable access. You can also create new ports and remove existing ports.
- An administrator sets the JIT policy, which defines which ports can be used. When a user requests access to JIT, he or she can use only those ports defined in the policy. To increase security, the user can remove all ports except the one required to gain remote administrative access.
- You can use PowerShell to configure JIT policy as well as to request access.
- When users request JIT access, Azure Security Center checks their RBAC permissions. If the user has right access to the VM, JIT access will be granted. At that point, Azure Security Center will dynamically create NSG rules to allow inbound management traffic. When JIT access expires, the NSG rules will be removed. Note that connections are not actively reset, so a user who is connected will remain until the connection is dropped by the user or for some other reason.

To explore this feature, select **Azure Security Center** in the left pane of the Azure Portal. Then select **Just-In-Time Access**. The main screen for JIT VM access explains what the feature is and how it works. It also contains main tabs under a Virtual Machines heading, as shown in Figure 5-1.

If a JIT access request is approved for a VM behind an Azure Firewall, then Security Center automatically changes both the NSG and firewall rules.

## What is just in time VM access?

Just in time VM access enables you to lock down VMs in the network level by blocking inbound traffic to specific ports. It enables you to control the access and reduce the attack surface on the VMs, by allowing access only upon a specific need.

## How does it work?

Upon a user request, on Azure RBAC, Security Center will decide whether to grant access. If a request is approved, Security Center automatically configures the NSGs to allow inbound traffic to these ports, for the requested amount of time, after which it restores the NSGs to their previous states.

## Configuring JIT

You can use the Security Center dashboard or PowerShell to configure JIT. However, before you start configuring, make sure that you have the proper level of permission to configure JIT policy, as shown in Table 5-1.

TABLE 5-1 JIT policy permissions

| Scope | path | Permission |
|---|---|---|
| Subscription or Resource Group where the VM is located | Microsoft.Security/locations/jitNetworkAccessPolicies | Write |
| Subscription, Resource Group, or VM | Microsoft.Compute/virtualMachines | Write |

Once you get the proper level of permission, follow the steps below to configure JIT VM using Security Center dashboard:

1. In the **Recommended** tab, select the VMs you want to configure for JIT access.
2. Click the **Enable JIT** button. The JIT configuration page opens, as shown in Figure 5-4.

3. The JIT access configuration specifies the ports and protocols to which JIT applies. The default ports are:
- 22 (SSH)
- 3389 (RDP)
- 5985 (PowerShell)
- 5986 (Remote PowerShell)

4. Do one of the following:
- If these are all the ports you want for JIT, click Save.
- If you want to omit any ports from the list, click the entry and click Delete.
- If you want to add a port, click Add.

5. Clicking Add opens the port configuration page (see Figure 5-5). Here you configure the following settings:
- Port: This is the port used by the protocol.
- Protocol: Typically, you'll choose TCP or UDP, but you can also choose Any.
- Allowed IPs: You have two options for this setting: Per request or CIDR block. If you choose Per request, whatever IP address is currently assigned to the client will be allowed. If you choose CIDR block, you can define a collection of IP addresses that client systems must have before they can connect to the resource.
- Max request time: This is the maximum amount of time the user can request. The default value is 3 hours, but you can allow the user to ask for more (or less) time.

6. Click OK and click Save to commit your changes. This VM will now appear in the Recommended tab, as shown in Figure 5-6.
