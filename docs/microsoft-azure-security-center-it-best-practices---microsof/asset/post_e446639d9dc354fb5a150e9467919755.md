## Integration with Splunk

The configuration process isn't trivial. There are a lot of steps, and you need to make sure to get one right. Figure 8-8 provides a high-level view of the overall architecture of the solution. The key enabling features for the solution include Azure Event Hub, Azure Monitor, and a Security incident and event management (SIEM) connector add-on that enables the SIEM to poll the event hub to bring the information into the on-premises SIEM.

![](img/4b11e95292819ab1a383a41ef73aedb4_173_0.png)

FIGURE 8-8 Security alert for an IoT device

Splunk integration involves the following processes:
1. Confirm that are accessible logs in Azure Monitor.
2. Configure required permissions in a subscription for the SIEM pipe.
3. Create and configure a resource group for the SIEM pipe.
4. Set up an Azure AD application to provide an access control identity.
5. Create a key vault to contain credentials.
6. Put the app password into the key vault.
7. Make an event hub.
8. Create a shared access key for event hub access control.
9. Put the event hub shared access key in Azure Key Vault.
10. Hook up the event hub to Azure Monitor.
11. Spin up the virtual machine that hosts the Splunk enterprise VM.
12. Install and configure the Azure Monitor add-on for Splunk.

Before you can begin, you need to be sure you have the prerequisites for integration. The required components are as follows:

- An Azure subscription (with administrative access)
- Resource groups to contain the required resources
- An Azure Active Directory (AAD) application for service access
- A key vault in which to store required credentials
- An event hub namespace (event hubs will be created automatically as needed)
- A Splunk server (in the cloud or on-premises)
- Microsoft’s Splunk add-on to read logs from event hubs

## Configuring the subscription for the Splunk SIEM pipe

If you have an existing subscription, make sure you have Owner, Administrator, or Co-Administrator access. If not, request access to that subscription to create the pipe. In this example, the subscription is named ContosoSub.

## Creating and configuring a resource group for the Splunk SIEM pipe

To create and configure a resource group for the Splunk SIEM pipe, follow these steps:

1. Open the Azure Portal **ResourceGroup** blade. Confirm that the subscription for the SIEM pipe is selected in the filter at the top (ContosoSub, in this example).
2. Click the Add button at the top of the screen (see Figure 8-10). A new blade will open and enable you to configure the resource group (see Figure 8-11).
3. Enter a unique resource group name (for example, SiemPipeRG).
4. Click the Subscription drop-down menu and select the desired subscription (in this case, ContosoSub).

![](img/4b11e95292819ab1a383a41ef73aedb4_174_1.png)

**FIGURE 8-10** Click the Add button in the Resource Group blade.

5. Click the Resource group location drop-down menu and select a location for your resource group. (We recommend that you place all the resources in this example in the same location.)
6. Click the Create button at the bottom to save the changes.

## Setting up an Azure AD application to provide an access control

You must set up an Azure Directory (AAD) application to provide an identity that can be used for the solution. Follow these steps:

1. Open the Azure portal's Active Directory blade and click App registrations (see Figure 8-1).

![](img/4b11e95292819ab1a383a41ef73aedb4_175_1.png)

2. Click New registration at the top (see Figure 8-2).

3. In the Create blade, enter the name of your application—for example, contoso.example.
4. Select Web/API in the Type drop-down menu.
5. In the Sign-on URL, type https://contoso.example.
6. Click the Create button at the bottom to create the application.
