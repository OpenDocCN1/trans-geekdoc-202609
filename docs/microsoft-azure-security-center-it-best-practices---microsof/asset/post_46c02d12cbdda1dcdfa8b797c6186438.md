To enable Azure Sentinel, you need an Azure Subscription, a Log Analytics Workspace, contributor permissions on the subscription which the Azure Sentinel resides, and either contributor or viewer permissions on the resource group that the workspace belongs to.

If you are using the default workspace created by Security Center, this workspace will not appear in the list when you try to enable Azure Sentinel. The rationale behind this is that default workspaces are managed by the service that created it (in this case, Security Center). Microsoft wants customers to have full control on their workspaces, including managing their retention periods and locations for their Azure Sentinel installation.

## Integration with Azure Sentinel

When you configure Security Center integration with Azure Sentinel, all security alerts generated in Security Center are streamed to Azure Sentinel. To configure this integration, Security Center must be enabled with the Standard tier in the target subscription. Also, you need to be logged in with a user who has global administrator or security administrator permissions on each subscription that you want to connect. Follow the steps below to configure this integration:

1. Using Azure Portal, click All Services on the left navigation pane and type Azure Sentinel.
2. The Azure Sentinel Workspaces blade appears for you to either select an existing workspace or create a new one. Because there is an assumption that Azure Sentinel has been already configured, so select the integration with Security Center, there select the workspace that you are currently using.
3. The Azure Sentinel Overview page appears; in the left pane, under the Configuration section, click Data connectors, as shown in Figure 8-2.

![](img/4b11e95292819ab1a383a41ef73aedb4_168_0.png)

FIGURE 8-2 Configuration section in Azure Sentinel

4. The Azure Sentinel – Data connectors blades appear. In the list of connectors, click Azure Security Center, and click Open connector page, and the Azure Security Center connector blades appear as shown in Figure 8-3:

FIGURE 8-3 Azure Security Center connector blade

5. Under Configuration section, click Connect besides the subscription that you want to enable.

## Using threat hunting to find undetected attacks

> an evolving threat landscape, it is inevitable that some attacks will slip through the cracks. Mature security organizations use threat hunting to identify and respond to such attacks. When threat hunting, security analysts must sort through mountains of log data. Microsoft has built tools into Azure Sentinel to streamline this process and help analysts take advantage of Microsoft experience.

Azure Sentinel is built on Log Analytics, which provides a rich KQL experience for filtering, summarizing, and joining data sets to identify suspicious behaviors. The Microsoft Threat Intelligence Center provides baked in hunting queries based on years of experience. These queries can be run for immediate results with minimal time investment. Alternatively, these queries can be customized to target specific threats and adapt to the specific needs of your environment.

Once an analyst has found an interesting result, analysts can create Hunting Bookmarks to preserve and share queries and query results with teammates. Analysts can also record contextual observations by adding notes and tags. All bookmarked data can be investigated using the Azure Sentinel investigation experience, which lets analysts explore the relationships between entities, as IP addresses, hosts, and accounts, in a graphical interface. This interface is also great for visually communicating findings to those not intimately involved in data analysis.

Azure Sentinel supports Jupyter notebooks, which enables analysts to tap into the community of data scientists and security analysts using ML and customized visuals to identify threats. Azure Sentinel comes preloaded with purpose-built Jupyter notebooks with self-contained hunting workflows. Visualizations are included in each notebook for faster data exploration.
