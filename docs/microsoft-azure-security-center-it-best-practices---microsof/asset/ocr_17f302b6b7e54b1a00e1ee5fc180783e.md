# Best practices for managing Security Center at scale

Research and define compliance conditions that apply to your organization, group them in an Azure Policy initiative, and assign them at the highest level in your management group hierarchy. Inheritance ensures that these conditions apply to lower-level management groups and subscriptions. Also, you should follow the general best practices below:

+   * Tailor the Security Center default initiative to your needs.
* Create custom Azure Policy definitions according to your compliance needs.
* Target exceptions at your lower management groups, such as dev and test environments.
* Deploy and maintain Azure Policy definitions and initiatives using ARM Templates as Infrastructure as Code (IaC).
* Don't be tempted to “manually” configure ASC. Instead, you should leverage Azure Policy and/or ARM Templates where possible.
* Ask yourself if you can provision a new tenant or subscription with automation only.
* First, test with auditifNotExists Azure Policies before using deny policies.
