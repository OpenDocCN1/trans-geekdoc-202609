## Onboard resources using PowerShell

In large deployments, you may consider using Security Center PowerShell modules to help you quickly perform onboarding operations. To prepare the environment you must first install the Az.Security module using the commands below:

```
Set-ExecutionPolicy -Policy AllSigned
Install-Module -Name Az.Security -Force
```

When you finish, use the Connect-AzAccount PowerShell command to log in to your Azure account. Next step is to register your subscriptions to the Security Resource Provider.

Run the commands below, and make sure to replace the <subscription ID> field with your subscription number, which can be obtained using the command Get-AzSubscription.

```
Set-AzContext -Subscription "subscription ID"
Register-AzResourceProvider -ProviderNamespace 'Microsoft.Security'
```

At this point you can start performing operations that you need to onboard Security Center in your subscription. Usually the first one is to upgrade from Free to Standard tier. You will set the context for the subscription that you want to upgrade, and then you perform the upgrade using the following commands:

```
Set-AzContext -Subscription "subscription ID"
Set-AzSecurityPricing -Name "default" -PricingTier "Standard"
```

You can use Get-AzSecurityPricing to verify if your subscription was correctly upgraded to standard. If you already have a workspace and want to connect Security Center to this workspace, use Set-AzSecurityWorkspaceSetting command. You will need the Workspace ID to perform this operation, and you can retrieve this ID using Get-AzSecurityWorkspaceSetting. Another common operation to perform at this stage is to enable auto provisioning, for that use the following command:

```
Set-AzAutoProvisioningSetting -Name "default" -EnableAutoProvisioning
Set-AzSecurityContact -Name "YourName" -Email "youremailaddress" -Phone "yourphone" -AlertAdmin -NotifyOnChange
```

To verify if the auto provisioning was correctly enabled, use the Get-AzAutoProvisioningSetting command. Last operation that is recommended to do is to configure the security contact information for email notifications. To configure this option, use the command below:

You can use Get-AzSecurityContact to verify if your settings were configured properly. There are many ways to monitor your Azure tenant for the inclusion of new subscriptions and automatically onboard these subscriptions using PowerShell. Security policy in Azure Security Center reflects directly on the security recommendations that will be triggered according to your Azure workloads. ## Integration with Azure Policy

It's well-known in all areas of IT (enterprise, small business, and even start up) that policy-based management streamlines and increases the effectiveness of IT operations. This is especially true with security, where the combination of technologies and processes become a potent weapon. In fact many know that if the right policies are in place—and those policies are carried out assiduously—then even less optimal technology can effectively protect the organization.

With this in mind, Azure Policy was introduced. Azure Policy allows you to create, assign, and manage a variety of policy definitions. Security Center Policies are driven by overarching Azure Policies, which improves the overall reach and management of your Security Center policies. Policy definitions can be compared with your current configuration, and any resources that do not meet the requirements of your policy are determined to be out of compliance. You can then focus on the out-of-compliance assets and bring them into compliance.

A policy assignment is a policy definition that has been assigned to take place within a specific scope. A scope might range from an Azure management group to a resource group. A management group enables you to manage access, policy, costs, and compliance across subscriptions. The term “scope” refers to all the resource groups, subscriptions, and management groups to which the policy definition is assigned. Policy assignments are inherited by all child resources.
