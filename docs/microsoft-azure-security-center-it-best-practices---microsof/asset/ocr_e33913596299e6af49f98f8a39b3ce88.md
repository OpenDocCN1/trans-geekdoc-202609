The internals are somewhat complex, the fact is you won't have to worry about them. Security Center uses machine learning to learn about the processes running in the virtual machines and their behavior. This learning process usually takes two weeks, and after that period, Security Center suggests that apps should be whitelisted.

At this point, you can review this list and choose some or all the recommendations. There will be a lot of recommendations, which are comprised of a list of file names that you want to allow to run on the virtual machines.

Finally, you decide if you want to monitor for whitelisting violations and actively block them. In most cases, users will monitor for a period of time. After they become confident in the whitelisted collection and disabling processes outside of the whitelisted group will not interfere with normal function of applications, they stop monitoring them. In Figure 5-19, you can see there are three tabs:

If you expand these subscriptions, you see the Group names and the mode of operation for application whitelisting, which can be set to Audit or Enforcement. If you choose Audit, it will only trigger an alert when an app that was not in the whitelist was executed. However, if you choose Enforcement, it will alert and block the apps that are not whitelisted. These groups will contain the VMs/Computers that have similar application patterns and should have the same set of whitelisted apps.
