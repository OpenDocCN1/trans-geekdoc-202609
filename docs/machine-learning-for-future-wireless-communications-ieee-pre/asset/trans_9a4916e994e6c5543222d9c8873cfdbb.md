
本节介绍了一种用于移动网络实时无线资源分配的去中心化学习方法。尽管网络范围的决策在集中计算时是最优的，但所需类型的协调在实践中不可行，这是由于移动网络的去中心化特性，其受通信延迟和通信线路上潜在故障的影响。因此，去中心化控制解决方案更适合此类问题。因此，本工作采用多智能体系统（`MAS`）范式作为其功能框架。`MAS` 代表了一种适合移动网络的方法，因为网络架构中的许多元素可以建模为智能体（例如 `eNodeBs`、移动管理实体、网关等）。

我们进一步描述移动网络资源分配的多智能体解决方案。该解决方案采用两种不同类型的智能体，主要是基底层小区智能体，以及更高层的协调智能体，后者简化决策任务并在网络层面提供更高效率。虽然完全去中心化的方法也是可能的，但这种分层结构通过在协调智能体层面聚合信息，确保性能更接近最优。这是协调元素的主要作用，其目标是最大化全局网络指标。

架构的关键元素是小区智能体，它们使用函数逼近来决定对用户最合适的 `BS` 配置。实际上，由于动作取决于受噪声、路径损耗、干扰和用户几何等非线性因素影响的本地环境信息，小区智能体采用 `DNNs` 来执行智能体决策过程所需的推理过程。具体而言，`DNNs` 使用小区环境信息（例如用户几何）以及可用动作列表和协调智能体施加的约束，以决定哪种小区配置有助于在网络层面为用户实现最佳性能。

### 4.4.1 多智能体系统架构

在本小节中，我们进一步详细介绍多智能体架构及其底层智能体的设计。该架构通过分层多智能体框架表示。在这里，基层智能体对一组执行器（例如 `BS` 参数）具有完全控制权，而更高层智能体（即协调器）可以对基智能体的另一组执行器施加约束。该架构在 [图 4.7](#c04.xhtml#c04-fig-0007) 中进行了说明，从 `LTE` 网络的角度来看，其中基层智能体是 `eNodeBs`（`eNBs`）小区。虽然在图中进行了抽象，但此处的协调智能体可以是另一个 `eNB` 小区或网络层次结构中更高层的实体，例如移动性管理实体（`MME`）。

![图 4.7 多智能体系统架构.](`images/c04f007.jpg`)

[图 4.7](#c04.xhtml#R_c04-fig-0007) 多智能体系统架构。

两种类型的智能体针对不同的性能指标。在 `eNB` 智能体层面，智能体试图最大化本地性能指标，该指标是其覆盖范围内用户的函数；在协调智能体层面，智能体试图最大化全局性能指标，涉及其控制下的 `eNB` 智能体覆盖的所有用户。

多智能体系统按三步过程运行：
1. `eNB` 智能体计算在协调智能体可能施加的每种约束类型下的本地可实现性能，并将最大可实现性能转发给协调智能体。
2. 协调智能体利用这些信息计算在该约束下全局性能最大化的最合适的约束，并将此约束施加于底层智能体。
3. `eNB` 智能体选择在所施加约束下使其性能指标最大化的本地动作。
