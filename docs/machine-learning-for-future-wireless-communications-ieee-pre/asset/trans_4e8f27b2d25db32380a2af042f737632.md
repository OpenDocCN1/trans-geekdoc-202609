
在本章中，我们重点关注基于 DRL 方法的边缘缓存策略。对于小型基站和 UE 的边缘缓存，缓存策略由内容流行度驱动。因此，了解内容流行度是解决缓存问题的关键。在以往的工作中，内容流行度要么被假设为内容服务器已知，如 Wang 等人 ([2018](#c21.xhtml#c21-bib-0033))、ElBamby 等人 ([2014](#c21.xhtml#c21-bib-0007)) 所示，要么在缓存操作前进行估计，如 Zhu 等人 ([2018](#c21.xhtml#c21-bib-0042))、Li 等人 ([2018b](#c21.xhtml#c21-bib-0023)) 所提出。前一种假设在内容流行度随时间变化时使框架实用性降低，而频繁估计内容流行度或用户请求的到达强度将导致大量资源和时间的消耗。为避免此类缺点，引入了 ML 方法来确定高效的缓存策略。例如，Lei 等人 ([2017](#c21.xhtml#c21-bib-0018)) 训练了一个深度神经网络以识别最优缓存算法。并且使用不同的 DRL 算法来寻找能够更好地适应变化环境的缓存策略。Sadeghi 等人 ([2018](#c21.xhtml#c21-bib-0026)) 实现了一个 Q-learning 算法以找到最优缓存策略。在 Zhong 等人 ([2018](#c21.xhtml#c21-bib-0040)) 和 Wei 等人 ([2018](#c21.xhtml#c21-bib-0034)) 的研究中，重点是使用 actor-critic DRL 框架进行缓存。对于去中心化缓存网络中的协作缓存策略，Sung 等人 ([2016](#c21.xhtml#c21-bib-0029)) 和 Jiang 等人 ([2018](#c21.xhtml#c21-bib-0012)) 研究了多智能体 Q-learning 解决方案。Song 等人 ([2017](#c21.xhtml#c21-bib-0028)) 和 Sengupta 等人 ([2014](#c21.xhtml#c21-bib-0027)) 提出了两种不同的基于多臂老虎机的缓存方案。

如前述研究所示，内容流行度分布在解决内容缓存问题中始终至关重要。在 DRL 算法中，智能体需要观察环境的足够特征以确保其决策的准确性。为更好地解决这一问题，本章提出了一种用于协作边缘缓存的深度 actor-critic 强化学习（RL）多智能体框架（参见例如 Lowe 等人 ([2017](#c21.xhtml#c21-bib-0025))、Foerster 等人 ([2016](#c21.xhtml#c21-bib-0008))、Gupta 等人 ([2017](#c21.xhtml#c21-bib-0009)) 关于多智能体 DRL 的研究）。然而，在介绍该多智能体框架的细节之前，我们首先提供相关的系统模型和问题表述。

## 21.2 系统模型

我们考虑以下小节中描述的两种不同的网络模型。

### 21.2.1 多小区网络模型

如图 [图 21.1](#c21.xhtml#c21-fig-0001) 所示，本小节介绍一个包含云数据中心和 `N` 个基站的通信网络。假设数据中心有足够的存储空间缓存所有内容文件，而每个基站具有固定的缓存容量 `C`。所有基站都可以与云数据中心连接并从中请求文件。并且每个基站决定是否缓存一个文件。假设一个基站覆盖一个固定的圆形蜂窝区域，基站位于中心。我们假设小区半径固定，且小区内的所有用户都可以访问对应的基站。系统中随机分布着 `U` 个用户，并且它们位于至少一个基站覆盖的蜂窝区域内以确保服务。我们假设在给定的时间槽内，用户的位置不变，且位于重叠区域的用户可以由任意一个对应的基站服务。用户对内容有各自的偏好，并且在每个时间槽内每个用户只能请求一个内容文件。我们用 `M` 表示内容文件的总数，并使用内容 ID 表示对应内容的请求。此外，在每个操作周期中，用户根据自己的偏好请求内容。请求发送到所有可以与用户连接的基站，而传输延迟最小的基站最终将内容文件传输给用户。与此同时，所有基站将根据用户请求更新其缓存以最小化平均传输延迟。在做出缓存决策时，基站之间会相互竞争以获得传输机会，同时也会相互合作以降低整体传输延迟。
