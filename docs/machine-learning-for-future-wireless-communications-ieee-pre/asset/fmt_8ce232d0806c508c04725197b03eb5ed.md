This is the so‐called support vector expansion, where ![images](images/c17-i0323.png)<math xmlns="http://www.w3.org/1998/Math/MathML" display="inline" overflow="scroll"><mrow><mi mathvariant="bold-italic">w</mi></mrow></math> can be described as a linear combination of the training patterns ![images](images/c17-i0324.png)<math xmlns="http://www.w3.org/1998/Math/MathML" display="inline" overflow="scroll"><mrow><msub><mi>x</mi><mi>i</mi></msub></mrow></math>. As explained in Smola and Schölkopf ([2004](#c17.xhtml#c17-bib-0103)), note that the complexity of a function's representation by support is independent of the dimensionality of the input space and depends only on the number of support vectors. In addition, the complete algorithm can be described in terms of dot products between the data and, even for evaluating ![images](images/c17-i0325.png)<math xmlns="http://www.w3.org/1998/Math/MathML" display="inline" overflow="scroll"><mrow><mi>f</mi><mo stretchy="false">(</mo><mi mathvariant="bold-italic">x</mi><mo stretchy="false">)</mo></mrow></math>, it is not necessary to explicitly compute ![images](images/c17-i0326.png)<math xmlns="http://www.w3.org/1998/Math/MathML" display="inline" overflow="scroll"><mrow><mi mathvariant="bold-italic">w</mi></mrow></math>.
