
### 21.2.2 具有 D2D 通信能力的单小区模型

在本小节中，我们介绍具有 D2D 通信能力的单小区模型。为减轻基站的数据流量负担，假设 UE 配备有缓存。在此设置中，我们考虑一个由一个基站和 `U` 个用户组成的通信网络，每个用户都配备有一台启用缓存的移动设备。为区分用户和缓存节点，我们将本地缓存节点的数量定义为 `N`，在这种情况下我们有 `N = U`。如[图 21.2](#c21.xhtml#c21-fig-0002)所示，用户随机分布在基站覆盖的蜂窝区域内。蜂窝区域由一个以基站为中心的圆来描述，小区的半径为 `d_b`。在该系统中，所有用户都能够与基站通信，每个用户还可以在距离 `d_u` 范围内的其他用户之间以 D2D 模式通信，且 `d_u < d_b`。我们假设每个 UE 具有固定的缓存大小 `C`，该缓存大小可以根据用户对内容的需求进行更新。因此，为了最小化流向基站的数据流量，当用户请求内容时，首先会检查其自身设备的缓存。如果请求的 content 已被缓存，用户可以直接为自己提供服务且不会产生流量。否则，如果内容未被用户自身缓存，则会检查所有能够与该用户以 D2D 模式通信的其他用户的缓存，如果内容可以通过 D2D 模式传输，则数据流量将由相应的用户产生。如果没有任何 D2D 发送方缓存了该内容，用户将向基站请求内容。我们假设在给定的时隙内，用户位置不变，并且能够与多个用户以 D2D 模式通信的用户可以由任意一个相应的 D2D 发送方提供服务。用户对内容有各自的偏好，并且在每个时隙内用户只能请求一个内容文件。再次记总内容文件数为 `M`，并使用内容 ID 表示对相应内容的请求。在每个操作周期中，用户根据自身偏好请求内容。请求发送给所有可以与用户连接的 D2D 发送方，并且所有用户更新其缓存。在做出缓存决策时，用户需要考虑自身的偏好以及与 D2D 模式下其他用户潜在的协作文件交换，以最大化缓存命中率。

### 21.2.3 动作空间

此后，为了统一对所描述的两种蜂窝网络模型的描述和分析，在多小区网络模型中我们将基站视为本地内容服务器，将云数据中心视为上层服务器。相应地，在具有 D2D 通信的单小区网络模型中，我们将启用缓存的 UE 视为本地内容服务器，将模型中的单个基站视为上层服务器。
