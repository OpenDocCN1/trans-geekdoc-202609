
We start by introducing the architecture of the `DQN` used in `DQSA` in [Section 1.3.5.1](#c01.xhtml#c01-sec-0019). The offline and online phases of the algorithm are described in [Section 1.3.5.2](#c01.xhtml#c01-sec-0020). The training is done offline at a central unit, whereas the spectrum access is done online in a fully distributed manner (after each user has updated its `DQN`). More details of the specific setting of the objective function and the design principles of the training phase can be found in (Naparstek and Cohen, [2018](#c01.xhtml#c01-bib-0065)).

2. *LSTM layer:* The complex network model that we handle involves partially observed network states by the users, and non‐Markovian dynamics determined by the interactions between the multiple users. Therefore, classical `DQNs` do not perform well in these cases. To tackle this problem, we add an `LSTM` layer ((Hausknecht and Stone, [2015](#c01.xhtml#c01-bib-0040))) to the `DQN` that maintains an internal state and aggregates observations over time. The `LSTM` layer is responsible for learning how to aggregate experiences over time, which makes it possible to infer the true network state based on the history of the process.
