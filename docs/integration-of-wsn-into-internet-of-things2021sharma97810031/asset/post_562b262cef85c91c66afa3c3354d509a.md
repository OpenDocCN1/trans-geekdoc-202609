## 10.4 SECURITY CHALLENGES AND SOLUTIONS IN WSNs, IOT, AND CPS

### 10.4.1 Security Challenges and Solutions in WSNs

In this section, we discuss attacks on WSNs' layers of architecture one by one and then provide preventive measures for the same. WSNs have more security risks and vulnerability due to their nature of being deployed in a hostile or open environment [30]. Due to restrictive resources, it is very hard to have a security mechanism implemented as well. Therefore, knowing what to and how to protect is crucial when doing risk assessments. The wireless communications are susceptible to threats as well. More of these threats and attacks per layer of architecture are described below.

The solution for having a secure WSN is to incorporate confidentiality, value integrity, apply authentication, use strict authorization, and have an assessment of risk. In Table 10.4, there are some of the solutions for each layer of the WSN node architecture.

TABLE 10.4 Attacks and Preventions for WSNs

| Layer | Attacks | Solutions |
| --- | --- | --- |
| Application | Data corruption, repudiation, DoS, malicious access, etc. | Utilize cryptographic methods and validation to allow access and understand the data. |
| Sensor | Unauthorized access | A strict set of protocols for accessing and modifying. The PoLPs will benefit the network. |
| Wireless | Data confidentiality, jamming, eavesdropping, hijacking, flooding, interruption, etc. | The wireless connectivity should use encryption when transferring data through wireless mediums. This will ensure that the data are not eavesdropped upon. The checks for integrity should also be considered to ensure that there is no unauthorized modification. |
| Transport | Congestion, flooding, SYN attack, DoS, disruptions [31] | Use a session-based service for handling requests. This way, once the session is expired, the request cannot be retransmitted or entertained. |
| Network | Sinkhole, selective forwarding, wormhole, node replication, unauthorized access, etc. | Use session-based handling of requests with time frames, that is, a window of time allowed per connection. The time frames will allow the network to be cleared of congestion if there is inactivity. Consider session-based handling to filter out spam requests and only entertain fresh requests. |
| Access control | Data hijacking, replay, power depletion, mislead flow of data, etc. | |
| Physical | Jamming, DoS, replication, theft of keys and schematics, along with other malicious uses | Utilize cryptographic methods, where there is not a need for storing keys locally such as Diffie–Hellman key exchange [32], to communicate. The nodes should also use authentication mechanisms when exchanging data. |

## 10.4.2 SECURITY CHALLENGES AND SOLUTIONS IN IOT

In this section, we discuss attacks on IoT layers of architecture one by one and then provide preventive measures for the same.

Each layer of the IoT architecture is susceptible to security threats and attacks, which can be active or passive. They can originate from either the external or internal network. An active attack is defined as an attack that is intended for stopping the service while the passive category tends to monitor the information that flows through the network.

To eliminate the chances or keep the damage of attack as minimum as possible, we have discussed in Table 10.5 some precautionary measures that should prevent attacks based on the layers of IoT architecture described.

TABLE 10.5 Attacks and Preventions for IoT

| Layer | Attacks | Solutions |
|---|---|---|
| Business | Vulnerabilities in structure, insider attacks, etc. | The business layer should behave as an entry guard for everything related to the security in the architecture. This layer should be equipped with firewalls and resources to protect the layers beneath. Breach of this layer opens up vulnerabilities for other layers that attackers can take advantage of. |
| Application | Virus, defenselessness, phishing, worms, malware, etc. can be compromised due to various reasons by virus, defenselessness, phishing, worms, malware, weak protections, and measurements put in place to protect the application, validations, permission mismatch, inadequate risk assessments, etc. [33] | The application should have strong user validation to protect integrity and privacy. Strong encryption mechanisms are also recommended to protect from breaches and unauthorized access to the environment. Special policies and permission should be utilized for users with privileges, and PoLPs should also be implemented. The quality of service checks should include risk assessments and preventions to know where the security of the system stands. |
| Processing | Susceptible to cloud attacks, third-party attacks, infrastructure security, etc. | The processing layer is used to process the data. This processing does not happen locally, as it will be resource inefficient the data are sent somewhere, typically a cloud resource, to process the data. The data may contain classified information and could be sensitive. Therefore, the utilization of cryptography is needed if the data are stored or sent to the cloud. All of the data at a single point is also an issue. If there was a breach on that specific cloud, the whole data is compromised. The use of fragmentation and redundancy scattering can help with having data stored in different parts of the cloud. |
| Transport | Compromised integrity, confidentiality, and transmission. DoS, man-in-the-middle attack, spoofing, authorization, etc. | The data while on transit are at risk the most as data leave the system through some medium which may be compromised. We need to make sure that the data stay intact by verifying the integrity and applying measures for the confidentiality of data. Also, the routing should be secure to transfer the data while on transit; if unprotected, the data are exposed to the attacker. Therefore, the utilization of cryptographic methods is a must. |
| Perception | Generally, hardware attacks such as jamming, DoS, false information, noise in the data, malicious code insertion, etc. | This layer deals with the physical things in the IoT network. Therefore, an attacker should have access to these to cause harm. However, an attacker can gain access while not being physically present via remote connectivity. Therefore, we need to protect access to these devices by implementing authentication of the devices and enforcing this standard throughout the system. As an attacker can also compromise the integrity, we need to utilize measures to ensure the integrity of data. |
