+   - Source IP Address: This field defines the IP address of the source from where a route is arriving.

+   - Hop Count: This field counts the number of hops from the original IP address.

+   ii. DSR: This is a type of reactive protocol in which a route is discovered on demand, that is, whenever it is being required. Based on demand for any particular route, nodes initiate the route discovery [50]. For available routes from the source to destination, the route cache is checked. There are two main components in the entire process: route discovery and route maintenance.

+   - Route Discovery
+   On demand basis, source nodes initiate route discovery. Availability of free path is checked in the cache. If no such route is found in the cache, route discovery is being initiated [51], Figure 6.6 shows the route between source and destination.

+   - Route Maintenance-
+   As the topology change is the main concern, there are many possibilities of link breakage or failure. But due to acknowledgment mechanism, route maintenance is possible [52]. Figure 6.6 shows the link breakage between the path S-B-E-D. Therefore, an alternate path to source and destination would be S-A-G-F-D.

+   iii. DSDV: This is a type of table-driven routing protocol. Every node manages a routing table having entries of its neighboring nodes. This protocol is based on Bellman-Ford algorithm with some updates [53]. Each table entry has a unique sequence number associated with the destination node. Any change in the topology results in the updating of the routing table. Updates can be transmitted either by a broadcast or by a multicast message [54]. With the help of this, adjacent nodes know about the changes that have resulted in the network. Routing updates can be done by sending either the entire table to neighboring nodes or only that part of the table that has to be updated.
