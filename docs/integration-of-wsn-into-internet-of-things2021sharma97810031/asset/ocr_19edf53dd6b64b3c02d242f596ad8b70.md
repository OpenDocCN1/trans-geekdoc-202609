So, every existing algorithm (and nonexisting algorithm today) could be tested fast with this methodology to further ensure the security of the referent algorithm. Based on the obtained results, this chapter proves the efficiency of the proposed methodology. Besides having AES and DES as reference algorithms, this methodology could be applied to real-world algorithms.

Conversely, if one wants to try to exploit some known algorithm, it is still easy to apply the proposed methodology. Modifications for this purpose consist of changing the reference algorithm, choosing the right neural network architecture (or another relevant algorithm), and initializing the training process. All of the mentioned changes are easy and fast to setup. At the end of the training process, one will have saved an algorithm checkpoint that could be used to gather pieces of information about real-world communication. For example, using this methodology and the end exported model, an adversary only needs to gather cypher messages encrypted by the referent algorithm and use the model to gather information about the secret key.

Having the secret key, one can easily read the entire conversation between two (or more) persons. As mentioned, the absolute proof of this methodology represents the SC algorithm, which scored over 99.9% accuracy in most dataset cases. However, this algorithm is not used in the real world, so this is not proof that it could be applied to any other algorithm. But to confirm real-world use of the methodology, AES and DES were used as they represent today the most used encryption algorithms. In the end, results on AES do not show any significant accuracy of the model, but when DES comes into the picture, the model scores about 70% accuracy. This result proves the real-world applications of this methodology. Regarding the DES algorithm, there is a possibility to get much greater accuracy, but this requires a more complex network architecture to find more complex correlations between the secret key and cypher messages.

In general, future steps should be based on testing stronger and by that more complex architectures. For example, trying experiments with deep learning models that can find much tougher patterns in data. Besides different neural network architectures, even classical machine learning algorithms, like random forest and SVM, could be tested. Besides pure changes in the network architecture and overall algorithms, future work should be focused on creating another pipeline to determine the full secret key from the cypher, not only a single bit of key. By this, during the test, the whole secret key could be extracted with certain confidence for each bit. Therefore, the entire communication between two or more entities in the network could be revealed.
