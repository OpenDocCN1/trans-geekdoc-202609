## 2.2.4 WIRELESS SENSOR NETWORK LAYERS

The open systems interconnection (OSI) reference model is one of the popular systems for defining layers in networks [30]. WSNs have also adopted this standard. WSN layers are briefly described below [31]:

### 2.2.4.1 Application layer

This layer deals with system behavior while interacting. It also facilitates designers and developers for preparing a programming model. Industrial automation applications provide safety through regular and rigorous monitoring [32]. In this layer, message-passing communication is used. Moreover, early-stage memory access is performed along with synchronization, storage, and complex channel requirements [33]. The lower layer must be appropriately designed and configured to get the most use of the system. Various properties of data and the operational and environmental lifetimes are dealt with in this layer [34].

### 2.2.4.2 Transport Layer

This layer uses logical link addresses and transducers. It is responsible for transmitting messages end to end. The goal is congestion and flow control, fair allocation of bandwidth, reliability, packet-loss recovery, energy efficiency, and application support. There are many transport protocols, but they cannot be compared as each of them is tested in different simulation environments [35]. Illicit congestion detection can potentially degrade network throughput. This is related to data buffering. It fixes the buffer size by making it smaller to optimum capacity. Along with this task, synchronization needed is also performed for this purpose [36]. End-to-end reliability imposes strict energy requirements. There is a lack of reliable transport protocol in low-power and lossy networks. For this reason, the use of user datagram protocol (UDP) and retransmission control mechanisms at the application layer is an essential trade-off between energy cost and reliability [37]. Some well-known protocols in this layer are

- sensor transmission control protocol (STCP)
- price-oriented reliable transport protocol (PORT)
- pump slow fetch quick (PSFQ)

### 2.2.4.3 Network Layer

The major functionalities of this network are establishing routing communications. As there is no traditional IP address that belongs to a sensor device, the WSN does not follow conventional routing techniques to develop communications. That is why several routing protocols and standards are involved in this layer [29,38]. A network administrator must set up the routes and the frequency hopping. The network protocol of the ZigBee standard does not support the use of redundant paths. So, the redundant routes can also be used in radios that are compliant with the IEEE 802.15.4 standard.

Four kinds of routing methods are used by WirelessHART, namely graph, source, superframe, and proxy routing. In graph routing, a table is created by the network manager to establish a connection to the devices [39,40]. In source routing, the network manager puts into the packet all the necessary information for routing, but this can only be used for network diagnosis because if a node fails, the packet will be lost. Superframe routing is like graph routing, but the difference is the links can only be used to establish superframes. The proxy routing is a graph routing that is used by the device when they are put in a network. In the absence of security keys, the proxy routing will be used.

### 2.2.4.4 Data Link Layer

The data link layer performs several tasks related to the multiplexing of data. In the media access control (MAC) layer, there is a specific problem called _co-channel interference_. This problem is solved at this level using the MAC protocol. Error handling is included here. On the other hand, there is another issue in the physical layer named multipath fading and shadowing. This one is also fixed in this layer [41]. MAC protocols have some essential characteristics like scalability and stability. On the other hand, this protocol is not optimally developed for energy efficiency. In terms of energy, the protocol might not be feasible, but there are other different characteristics of the MAC protocol that are important for the WSN [42]. The design of MAC protocols has been dominated by scalability, stability, and fairness [43].

### 2.2.4.5 Physical Layer

This one is the first layer of the sensor network. After this layer, the device is connected to the physical world for data collection. In this layer, data encryption is used so that the intercepted data are not understandable for the attacker without the key. Carrier frequency is selected for the modulation so that the data can be sent to other nodes. The IEEE 802.15.4 standard is recommended at this layer. ## 2.3 WIRELESS SENSOR NETWORK SECURITY

Their low cost is one of the reasons sensors have become popular. For this reason, extra hardware resources and advanced protocols cannot be used in sensor nodes. This is a crucial factor in ensuring security. As mentioned in Section 2.2.1, low cost prevents installing new state-of-the-art hardware. For this reason, the sensors are not threat proof. These nodes and the networks are prone to data interception. Potential harmful instructions can be injected into the node for malicious activities. Sensor devices are not tamperproof for jamming attacks.

Moreover, advanced protocols cannot be installed due to their small size, low cost, and energy efficiency. Low power will cause potential in energy drains, and nodes will starve. The WSN node is highly resource constrained. It comprises a processor size of 4–8MHz, 4 KB of RAM, and 28 KB of memory. Besides, the 916 radiofrequency of a sensor node will cause potential limitation in the transmission capability. Though low power is one of the essential characteristics behind the adoption of WSNs, it is a significant vulnerability. Considering the above-mentioned limitations, various routing protocols that are optimized for energy efficiency for sensor nodes have been proposed. In this section, the WSN security requirements, data security of WSNs, multiple threats, and countermeasures are discussed.

### 2.3.1 Security Requirements for WSNs

A brief overview of the security requirements of the WSNs is given as follows [50]:

- Confidentiality: In the case of network security, confidentiality means that the information is “for your eyes only,” that is, the data have to be protected for the intended user. In WSNs, the confidentiality of the system means the data captured and processed by the node should not be leaked to any unauthorized nodes or stations. For this reason, data can be encrypted with secure encryption and a private key. Besides, secure routing protocols can be used for this.
- Integrity: Integrity is to ensure that the data do not get corrupted by any means over their lifetime. If the data get altered through their transit, get deleted accidentally by someone, or get modified by any unauthorized entity, then they become flawed, which is called breaching of integrity. Ensuring that information remains authentic, trustworthy, and consistent is integrity. In WSNs, whenever the data are sent to the BS or the user, they need to be unaltered; that is, integrity has to be protected.
- Authenticity: One of the essential properties of data for users is that they need to be authentic. Whenever two parties communicate, it is imperative that they have the trust of each other. For traditional data authenticity, message authentication code is used. In the case of WSNs, it is vital that the data that will be processed at the end need to be authentic.
