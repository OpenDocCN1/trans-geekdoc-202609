## 2.3.3.3 Network Layer Attacks and Countermeasures

Sinkhole: This attack tries to capture almost all the traffic toward the affected node. This type of attack makes one node the “sinkhole,” that is, pulls in all transmissions on the channel toward it and disrupts the network. Networks are particularly vulnerable to sinkholes for specific patterns in the communication links. If the routing topology involves simply advertised information like end-to-end reliability estimate or other fields, then proper verification is not possible to prevent such attacks.

An effective and potential countermeasure can be using the geo-routing protocol. The routing system is modified to allow geo-routing, and thus directing the traffic through physical locations of nodes to prevent misdirecting signals into sinkholes [62–64].

Hello Flood: Hello packets are required in some protocols so that the neighboring node can identify it. An attacker uses a laptop class device to send these types of packets to all sensor nodes. When adjacent nodes believe the affected node, they send data packets to an imaginary identity. “Hello flood” attacker nodes will falsely appear to be in short-range, and attackers may also make it appear to be in a low-cost route. They can be defined as a single-way broadcast wormhole. Localized information-dependent WSNs are particularly vulnerable to hello flood attacks. Node Capture: This type of attack is performed by gaining access to the node. This node can be used to acquire illegitimate privilege of the network such as information retrieval and active or passive control over the network. So, if the perpetrator can gain access to a single node, they can effectively expand control over the entire WSN.

Selective Forwarding: Also known as the black hole attack, this type of attack is primarily carried out by making a node act like a “black hole,” where data get in, but do not get out [67]. WSNs are mainly multihop networks. So, the system is made to transmit messages from node to node. But if sometimes malicious nodes refuse to forward the message and drop it, which creates a black hole. This means nodes will receive and then drop transmission of other nodes, and the WSN loses data. The malicious nodes can also drop only some data while forwarding others, still causing data loss. To counter this issue, a protocol-based approach can be used. Multipath routing will reduce the shared link, and hence, the implicit receipt of information can be reduced.

Sybil Attack: Though the same type of attack is present in the data link layer, the in-network layer, the effect is different. A malicious node can create multiple identities for the other nodes. It creates multipath and separation among the nodes in the network. To counter this issue, each node should have a unique shared symmetric key with the BS. Wormhole Attacks: In this attack, tunnel messages pass from one part of a network to another part of the network over a low delay link. Then, the message goes out of bounds to the attacker. Although different from black hole attacks, wormhole attacks are on a similar plane. Wormhole attacks can threaten a WSN that is encrypted and adopts authentication. It can also transform into a sinkhole if the attacker can alter routing information on their end of the wormhole to lure in data by making other routes appear costlier. Wormholes are challenging to detect and could be added with Sybil attacks of selective forwarding [68,69]. Optimum time synchronization in nodal communications and a geographically shortest route can be used to counter the attack. A minimum hop routing algorithm might help counter this attack [70].

## 2.3.3.4 Transport Layer Attacks and their Countermeasures

Flooding: In this attack, the infected node repeatedly tries to connect with different nodes. For connection creation, a node needs some resources such as bandwidth and power. If a flooding attack attacks a node, the resources are exhausted due to repetitive connection creation requests. Flooding attacks can be prevented through a client-side puzzle that deters attacking entities. More so, placing a limit for connections from each node prevents exhaustion caused by flooding attacks. Various resource optimization algorithms can also be used as a countermeasure against this attack [71].

Desynchronization Attacks: Synced communication between nodes is at the heart of WSNs. Attackers may attempt to destabilize this by transmitting missed frame signals between two nodes, thereby causing garbage communication and energy wastage. The attacker sends a missed frame message to one or both ends to transfer it to the whole network. The network falls in a loop to synchronize the recovery protocol and drains energy. Transmission of control messages to test synchronization between nodes, packet encryption, and packet-wise authentication can resolve this threat. In addition, for the missed frame, the number of repetitive requests can be limited to prevent it.

## 2.3.3.5 Application Layer Attacks and Countermeasures

Overwhelm Attack: Attacker tries to overwhelm network nodes to pass large amounts of data to the BS. As a result, the network bandwidth and energy drains away. The perpetrator may attempt to generate overwhelming sensor stimuli for nodes in a WSN, thereby leading to an enormous amount of false BS traffic. For this reason, the energy is drained.

To efficiently counter the attack, a rate limiter can be used along with data aggregators. Moreover, fine-tuning the sensor nodes can be a useful strategy. The tuning should include designing the node’s instruction set so that it reacts to only the effective and authentic stimuli.

Path-Based DoS Attack: As this is a DoS type of attack, the attacker will try to make the devices unavailable. As in this attack, the connection path between the nodes and the BS is unavailable. The attacker targets the leaf nodes and injects replayed packets. Due to repetitive injection, the path to the BS becomes occupied, and all the other nodes cannot connect the base.

As data are sent as packets, the authentication mechanism can be applied at the packet level. On the other hand, replay packets can also be secured with antireplay protection to counter this attack. This can be defended by using a combination of both.

Deluge attack: This is also known as a reprogramming attack. It attacks the programming codes of the nodes. In the case of remote maintenance, the attacker can gain access to the node and control a small to considerable portion of the network by reprogramming the nodes. Better administrative authentication and increased security at entry points into the nodal software would defend against deluge attacks. A secure communication scheme using a secure protocol and secure coding can be used to counter this type of attack.
