| Phase | Details |
| :--- | :--- |
| Phase-1 | Convert each ciphertext character to binary ASCII and concatenate all of them to form a long binary string. Divide the binary string into b bits each represented by C'i. Only remaining bits are used in last step.<br>C'1 ⊕ Y = C1<br>C'2 ⊕ C'1 = C2 ...<br>C'i ⊕ C'i-1 = Ci<br>Input: Ciphertext, Output: Bi<br>Concatenate all C'i values to form the long binary string L. | Phase-2 | Ai = Bi - { xj, j = n if i|n ; i mod n otherwise }<br>Input: Bi, output: Ai (1 <= i <= r) |

# 1.8.1 ALGORITHM STRENGTH ANALYSIS

To analyze the strength of the algorithm, the brute-force efforts of each phase is computed separately. The value of the part one of the key, which is used in phase one, is<br>2^(p-1) <=> X < 2^p - 255 (p > 9). Therefore, the brute-force attempts for X is in order of 2^p. As discussed before, the total number of possible values for n elements existing in phase 2 is 2^(p-1) - 255. Therefore, the order of 2^(n*(p-1)) brute-force attempts is necessary for brute force. Regarding the third phase, any value of Y falls in the [2^(b-1), 2^b] interval; therefore, the brute-force attempts of finding the Y is in order of 2^b. Table 1.5 shows the calculation of total strength of the algorithm.

# TABLE 1.5 Total Strength of Algorithm

| Phases | Complexities |
| :--- | :--- |
| First | O(2^p) |
| Second | O(2^(n*(p-1))) |
| Third | O(2^p) |
| Total strength of algorithm | O(2^p) * O(2^(n*(p-1))) * O(2^b) = O(2^((n+1) * p + b - n)) |
