Typically, WSNs consist of many devices with the ability to sense, process, monitor, and communicate. Security of the data generated by WSNs is pivotal. The nodes in WSNs are resource-constrained and can only perform limited tasks due to the same. The constraints are energy consumption, memory limitations, communication reliability, unattended operations, latency, etc. [8]. These constraints play a major role in having reliable security or a lack thereof. Therefore, it is also crucial to implement a sufficient amount of security depending upon the importance of data you are trying to protect, similar to as proposed in Ref [9].

The security of a WSN can be classified under two types where one can find vulnerabilities and prevent them from being exploited. These are known as node specific and network specific.

- Node Specific: There are three crucial functions that a node performs, that is, data collection, data passage, and data routing. These functions carry sensitive data, and exposure of these data might damage the integrity and confidentiality, hence breaking security. This can be done by tamper with data, node hijacking, relay attacks, etc. However, these exploits can be avoided if taken care of. The solutions are to perform integrity checks of nodes and data, have correct and latest standards of authentication suitable for the operation, use session-based time-stamping, encrypt the stream of data, use hash-based message authentication code (HMAC), etc.

- Network Specific: The data are shared across the nodes on the network. Having control over the whole network means having control over the nodes and their data and, as we discussed, the nodes have critical information that cannot be exposed. Someone with access to the network can add a malicious node, which can share and receive data with other nodes. Therefore, we must protect the network from illegitimate usage to prevent a network-wide attack.

Various attacks can happen on different levels on a WSN. These attacks can be classified based upon the weak point exploited. For example, the physical layer, which is responsible for handling the interaction with the real-world such as detection, encryption, and modulation [10], is often exposed to the hostile or insecure environment and hence easier to be taken advantage of. The attacker can perform various types of attacks on the physical layer such as jamming and tampering. These attacks need to be taken into consideration when deploying a WSN.

- Denial of Service (DoS): This attack consists of attempting to block legitimate users from using the service by various techniques. It diminishes the network's capacity to perform the function it can normally [11]. The attack can happen on different layers of the network and needs special instructions to counter it. Therefore, it is computationally costlier to counter every type of attack, and since the WSN's resources are scarce, it is not feasible. Different types of attacks exposed to layers of the network are as follows:
  - Physical Layer: jamming and tampering;
  - Access Control Layer: collision, exhaustion, and unfairness;
  - Network Layer: sinkhole, Sybil, Hello flood, and acknowledgment flooding;
  - Transport Layer: flooding and desynchronization;
  - Wireless Layer: eavesdropping, hijacking, and blocking;
  - Sensor Layer: false information forwarding and stealing information;
  - Application Layer: corruption and repudiation.

- Node Replication: This type of attack is done by copying (replicating) an existing node's identifier to create a new node, which will then imitate a legitimate node. The possibilities of this practice are endless in terms of exploitations as it can lead packets to wrong destinations, read correct information but send wrong information to the server while sending the correct packets elsewhere, corrupt the network, etc.

- Privacy Violation: The WSNs collect data through the deployment of sensors, and privacy management in WSNs is particularly hard [12] as they carry sensitive information that should not be exposed. Since the networks are managed wirelessly, an attacker with remote access will instantly have access to the whole network and an enormous amount of sensitive data as, being remotely accessed, the attacker's presence at a node is not required. These attacks may include the following:
  - Eavesdropping: the act of listening to communication without authorization.
  - Traffic Analysis and Passive Monitoring: analyzing the traffic that goes through a network and storing it for future processing.
  - Camouflage: using a compromised node to reroute the traffic and masquerade as a normal node (topic touched in node replication).

From the above discussion, it is clear that attackers can attack using various known techniques, and the networks are vulnerable to attacks on all of the layers. Moreover, the authors in Ref [13] argue that there may be some possibilities of other types of attacks in use by attackers, which are yet to be discovered.

## 10.3 SECURITY PARADIGMS

### 10.3.1 SECURITY PARADIGM: WSNs

A lot of interest has been attracted to WSNs. There are numerous WSN applications, and they are ever growing. However, as we discussed earlier, the networks are often deployed in a hostile environment, and they are prone to attacks due to their distributed nature. The attacks can have devastating attacks on the network as a whole and might get overlooked if not careful. A lot of attacks are, as discussed, a result of compromised security requirements and resource constraints. These security requirements consist of the balance of confidentiality of data, data integrity, data freshness, etc. [17]. We also discuss a general architecture of the WSNs, the attacks going on, and the solutions that may be beneficial for protection from these attacks.

### 10.3.1.1 Security Requirements

The requirements are simple—to secure a thing, you need a balance of the basic measures and to apply logical frameworks which can efficiently protect the thing given the constraints. The balance, in the context of WSNs, is needed the most as the resources are limited with limited power and computation. The requirements for WSN security are as follows:

- Data Confidentiality: here, confidentiality implies that the data collected from the sensors under all circumstances shall be kept with the utmost secrecy and is not subjected to any exposure other than the beneficiary. In simpler terms, the data are not to be seen by anyone except the ones it is intended for.
- Data Integrity: the data must be transferred to the intended beneficiary without any tampering, thereby ensuring the content has not been modified. There are numerous ways to ensure this, such as encrypting the content and using HMACs.
- Data Freshness: freshness implies that the data transferred are current data and not from an event that already happened. This protects from the attacks such as an attacker retransmit already transmitted data which are then reprocessed. This is not good for the networks as it would take the computational power of that resource-scarce unit.
