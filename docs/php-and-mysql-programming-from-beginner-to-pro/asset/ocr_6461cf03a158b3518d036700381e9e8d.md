CREATE TABLE employees (

    team_id INT,

)

    PARTITION p_dev VALUES IN (100, 200, 300),

In this case, employees are grouped by `team_id`, facilitating queries that filter by particular teams.

# Key Considerations for Sharding and Partitioning

+   • Balanced Data Distribution: Ensuring a uniform distribution of data across shards or partitions is essential to prevent overloading specific areas.

+   • Limiting Cross-Shard Interactions: Keeping queries confined to single shards or partitions is crucial, as operations that span multiple shards can diminish the advantages of these strategies.
