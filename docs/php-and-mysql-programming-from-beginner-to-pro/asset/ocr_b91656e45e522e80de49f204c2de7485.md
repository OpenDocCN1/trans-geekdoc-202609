Normalization in database design is a structured approach to organizing data, aimed at segregating larger tables into smaller, related ones to minimize data redundancy and clarify dependencies. The primary objectives of normalization include the elimination of duplicate data, the rationalization of data dependencies, and the simplification of the database structure.

+   • First Normal Form (1NF): This initial stage ensures that each table attribute holds only single, indivisible values and that each record within a table is unique. It sets the stage for deeper normalization by removing repetitive columns within the same table and segregating related data into distinct entities.

+   • Second Normal Form (2NF): Extending from 1NF, 2NF addresses the segregation of data subsets that apply to various rows of a table into distinct tables, emphasizing that each record in a table should depend entirely on the primary key.

+   • Third Normal Form (3NF): Progressing further, 3NF mandates that all attributes within a table are directly dependent on the primary key alone, excluding fields in a table that rely on non-primary attributes, thereby enhancing data integrity.

+   • Boyce-Codd Normal Form (BCNF): An advanced iteration of 3NF, BCNF deals with certain anomalies that 3NF does not, ensuring that every determinant in a table is a candidate key, further diminishing redundancy and dependency issues.
