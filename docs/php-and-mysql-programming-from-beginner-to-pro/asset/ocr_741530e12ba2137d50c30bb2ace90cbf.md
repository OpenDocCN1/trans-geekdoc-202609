+   • Primary-Secondary Replication: In this model, a single node (the primary) manages all write operations, while several secondary nodes handle reads. This setup can improve read efficiency but may complicate data consistency maintenance.

+   • Peer-to-Peer Replication: Every node can serve as both a primary and secondary, allowing more flexible read and write operations but necessitating advanced conflict resolution mechanisms.

# Models of Consistency

Ensuring consistency in distributed settings is challenging due to potential data conflicts and latency. Various consistency frameworks can be applied:

+   • Eventual Consistency: This framework permits temporary discrepancies among replicas, with the assurance that all copies will ultimately synchronize. It suits applications where immediate consistency is not paramount.

+   • Strict Consistency: This framework guarantees that any read operation retrieves the most recent write, ensuring data uniformity at the potential cost of performance.
