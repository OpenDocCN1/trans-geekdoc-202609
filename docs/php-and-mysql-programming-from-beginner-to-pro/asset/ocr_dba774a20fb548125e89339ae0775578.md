+   • Durability: Ensures the permanence of a transaction's effects post-commitment, safeguarding against data loss due to system failures, typically achieved through transaction logs.

Transactions are typically initiated with a statement such as `BEGIN TRANSACTION`, marking the commencement, and are concluded with either `COMMIT` to solidify changes or `ROLLBACK` to negate them in case of complications.

# Regulating Concurrent Access Through Locking

Locking schemes are implemented to orchestrate concurrent data access, ensuring controlled and coherent data modifications. The primary categories of locks include:

+   • Shared Locks: Allow concurrent read operations on a data element while precluding modifications, ensuring the element remains unaltered until all shared locks are relinquished.

+   • Exclusive Locks: Impede both read and write operations by other transactions, reserving exclusive modification privileges.

Astute lock management, taking into account factors like lock granularity and escalation, is pivotal for optimizing database throughput and concurrency.
