
# Pre-setup and Optimisations

We'll definitely require some basic packages to be present, and some packages might use snap. Therefore, we can create three variables; one to hold the apt packages (`pre_setup_packages`), and the last two to hold the snap packages (`pre_setup_snap` and `pre_setup_snap_classic`).

[Assuming we’ll use Let’s Encrypt](https://letsencrypt.org/) and Ubuntu 18.04. we will need the `ppa:certbot/certbot` repository to be added. In our case, Ubuntu 20.04, we shall use snap to install certbot.

---

## defaults file for common

```yaml
pre_setup_snap:
pre_setup_snap_classic:
  - certbot
pre_setup_packages:
  - wget
  - curl
  - zsh
  - software-properties-common
  - build-essential
  - g++
  - gcc
  - git
  - vim
  - nscd
  - supervisor
  - unzip
  - acl
  - unattended-upgrades
  - ufw
```

Switch back to the `pre_setup` subtask and add the tasks for installing the desired packages.

---

## pre_setup tasks

```yaml
- name: Update the system
  apt:
    update_cache: yes
    cache_valid_time: 86400
    upgrade: 'dist'

- name: Install packages
  apt:
    name: "{{ pre_setup_packages | default([], true) | list }}"
    state: latest

- name: Install Snap Packages
  snap:
    name: "{{ pre_setup_snap | default([], true) | list }}"
    state: present

- name: Install Classic Snap Packages
  snap:
    name: "{{ pre_setup_snap_classic | default([], true) | list }}"
    classic: true
    state: present
```

## Unattended Upgrades

Unattended upgrades only runs using origins that have been enabled. We can either create a file and store it under the files directory or use variables to enable the origins we need. We’ll go for the latter. Let’s add some default variables into the `common/default/main.yml` file.

```yaml
unattended_upgrades_security: true
unattended_upgrades_esm: true
unattended_upgrades_updates: true
unattended_upgrades_proposed: false
unattended_upgrades_backports: false
unattended_upgrades_blacklisted: []
unattended_upgrades_remove_dependencies: false
unattended_upgrades_auto_reboot: true,
unattended_upgrades_auto_reboot_time: "00:00"
unattended_upgrades_update_period: 1
unattended_upgrades_upgrade_period: 1
unattended_upgrades_auto_clean_period: 7
unattended_upgrades_unattended_upgrade_period: 1
```

Feel free to add any more variables as required. Take a copy of `/etc/apt/apt.conf.d/50unattended-upgrades` and use it as a template, saving it as `common/templates/50unattended-upgrades.j2` and then replace the values with variables.

[Ansible uses Jinja as the templating engine. You can read more about it on](https://jinja.palletsprojects.com) the [documentation site](https://jinja.palletsprojects.com).

```jinja
Unattended-Upgrade::Allowed-Origins {
  "${distro_id}:${distro_codename}";

  {% if unattended_upgrades_security %}
  "${distro_id}:${distro_codename}-security";
  {% endif %}

  {% if unattended_upgrades_esm %}
  "${distro_id}ESMApps:${distro_codename}-apps-security";
  "${distro_id}ESM:${distro_codename}-infra-security";
  {% endif %}

  {% if unattended_upgrades_updates %}
  "${distro_id}:${distro_codename}-updates";
  {% endif %}

  {% if unattended_upgrades_proposed %}
  "${distro_id}:${distro_codename}-proposed";
  {% endif %}

  {% if unattended_upgrades_backports %}
  "${distro_id}:${distro_codename}-backports";
  {% endif %}
};

Unattended-Upgrade::Package-Blacklist {
  {% for item in unattended_upgrades_blacklisted %}
  "{{ item }}";
  {% endfor %}
};

Unattended-Upgrade::MinimalSteps "true";
Unattended-Upgrade::InstallOnShutdown "false";
Unattended-Upgrade::Remove-Unused-Dependencies "{% if unattended_upgrades_remove_dependencies %}true{% else %}false{% endif %}";
Unattended-Upgrade::Automatic-Reboot "{% if unattended_upgrades_auto_reboot %}true{% else %}false{% endif %}";
Unattended-Upgrade::Automatic-Reboot-Time "{{ unattended_upgrades_auto_reboot_time }}";
```

Create a task under `pre_setup.yml` that will be used to replace the variables and deploy the template to the server. If the Ansible tasks are written well, re-running them on a system that is already setup will not break anything and should simply update what needs to be changed.

```yaml
- name: Configure Unattended Upgrades
  template:
    dest: /etc/apt/apt.conf.d/50unattended-upgrades
    src: 50unattended-upgrades.j2
```

Add the second template; `common/templates/20auto-upgrades.j2`; with the following content. This file determines how frequent the auto upgrade will be performed.

```jinja
APT::Periodic::Update-Package-Lists "{{ unattended_upgrades_update_period }}";
APT::Periodic::Download-Upgradeable-Packages "{{ unattended_upgrades_upgrade_period }}";
APT::Periodic::AutocleanInterval "{{ unattended_upgrades_auto_clean_period }}";
APT::Periodic::Unattended-Upgrade "{{ unattended_upgrades_unattended_upgrade_period }}";
```

All that’s left now is to set up the task that will copy over the template:

```yaml
- name: Configure Unattended Upgrades Frequency
  template:
    dest: /etc/apt/apt.conf.d/20auto-upgrades
    src: 20auto-upgrades.j2
    owner: root
    group: root
    mode: 0644
```

That’s it! We’ve successfully created two template files, added some variables and created tasks that will render the templates and deploy them to the server. To run the playbook, we’ll use the same command as before: `$ ansible-playbook -i ./hosts site.yml`

## Optimisations Subtask

As per our `main.yml` task file, the next item in the queue is optimisations (`optimisations.yml`). In order to get the most out of our server, we will need to increase some default values. `Somaxconn` defines the size of the kernel queue for accepting new connections. The lower the value the lower the maximum concurrent users.

By default, the value is set to 128, giving a max of 128 concurrent users. We’ll set this value to 100000. Open up `optimisations.yml` and add the first task:

```yaml
---
- name: Update the maximum concurrent connections
  sysctl:
    name: net.core.somaxconn
    value: "100000"
    state: present
```

The `ip_local_port_range` defines the available and usable ports which is usually set to 32768 - 61000 by default. We shall increase this range and offer port 10000 to port 65535.

```yaml
- name: Update available port range
  sysctl:
    name: net.ipv4.ip_local_port_range
    value: "1024 65535"
    state: present
```

The TCP protocol offers a wait state which keeps a socket open for up to 4 minutes after the connection has been closed. This can be problematic on a busy server as it will run out of sockets and ports. We can instruct the system to reuse sockets when it’s safe to do so without waiting for the 4 minutes to elapse.

```yaml
- name: Allow socket reuse
  sysctl:
    name: net.ipv4.tcp_tw_reuse
    value: 1
    reload: yes
    state: present
```
