
## 14.3.3.3 Next-Generation Firewalls (NGF)

NGF are the type of firewalls that combine the functions of conventional firewalls and additionally employ a range of additional technologies to counter threats at different levels of the OSI Model. Some notable features of NGFW are as follows:

- Deep Packet Inspection (DPI): Unlike conventional firewalls, NGFs perform significantly more in-depth examination of packets. This detailed analysis can reveal packet payloads and which application is generating the traffic. This allows the firewall to apply more coarse-grained filtering rules.
- App Cognizance: Enabling this feature makes the firewall aware of which applications are running and which ports they are using. This can protect against particular types of malware that aim to complete a sequence of processes and subsequently take over a port.
- Distinctive Cognizance: This allows a firewall to implement rules based on identity, for example, which user is logged in, which computer is being used, etc.
- Sandboxing: Firewalls can isolate suspicious code and execute it in a ‘sandbox’ environment to ensure it is not running maliciously. The results of this sandbox test can be used as criteria when deciding whether to allow packets into the system or not.

## 14.3.3.4 Web Application Firewalls (WAF)

While traditional firewalls help protect private systems from harmful web apps, Web Application Firewalls help protect web apps from malicious actors. A Web Application Firewall protects web apps by analyzing and detecting HTTP traffic between a web app and the Internet. It typically protects web apps from attacks such as cross-site scripting (XSS), SQL injection, file inclusion, and cross-site request forgery, as shown in Figures 14.11, 14.12, and 14.13.

By deploying a Web Application Firewall in front of a web application, a protective shield is placed between the web app and the Internet. While a proxy-based firewall protects a client machine by acting as an intermediary, a Web Application Firewall is a reverse proxy protecting the server from exposure by requiring users to pass through the Web Application Firewall before reaching the server.

A Web Application Firewall operates under a set of rules, commonly called policies. These policies create secure environments against potential threats by filtering out malicious traffic. The effectiveness of a WAF lies in the speed and ease with which policy changes can be implemented, allowing faster response to new attack vectors. During a DDoS attack, rate limiting can be enforced instantly by configuring WAF rules. Commercial WAF products, such as Cloudflare WAF, protect numerous web applications from attacks every hour.

Every request to the WAF is checked against threat intelligence and a rule engine built from over twenty-five million websites. Suspicious requests can be blocked, challenged, or logged as needed, while legitimate requests proceed directly to the endpoint. Analytics and Cloudflare logs provide visibility into security metrics for the user.

## 14.3.3.6 How Web Application Firewalls (WAF) Work

WAF security protects web apps from malicious endpoints and essentially works as a reverse proxy, defending devices from malicious applications. Web Application Firewalls are developed as server-side software modules, hardware appliances, or FWaaS.

To ensure security, WAFs restrict and inspect all HTTP requests. Malicious traffic is blocked or challenged with CAPTCHA tests designed to stop bots and malicious programs.

The implementation of a WAF depends on security methodologies based on best practices that address the most critical web application security vulnerabilities documented by the Open Web Application Security Project (OWASP). Typically, these policies are comprehensive, requiring designated personnel to configure the WAF according to the organization's security strategy. These personnel are responsible for deploying, configuring, managing, and monitoring WAFs to ensure maximum security.

## 14.3.3.7 Attacks that Web Application Firewalls Prevent

Web Application Firewall security can prevent numerous attacks, including:

- Cross-site Scripting: Attackers inject client-side scripts into websites that can be accessed by other users.
- SQL Injection: Malicious code is injected into a web form field, allowing attackers to compromise the application and backend databases.
- Cookie Theft: Tampering with a cookie to gain unauthorized data about the client for purposes such as identity theft.

- Invalidating Data: Attackers modify HTTP requests (including URL and form fields) to bypass the system's security mechanisms.

## 14.3.3.8 Cloud WAF

A cloud WAF, also known as cloud-based WAF, provides modern web application security at a lower cost than traditional appliance-based WAFs, while offering several key advantages. The customization and flexibility of this cloud WAF service saves administrators from manual configuration of security software or hardware, enables proactive rather than reactive threat detection, supports continuous application of security insights and visibility, and ensures consistency, while unifying application security across multi-cloud, hybrid cloud, or on-premises environments.

Cloud-based WAF management offers more flexible, adaptable, and responsive application security based on predefined policies that scale and respond consistently to threats per application or tenant.

## 14.4 WAF Deployment

- 1. Reverse Proxy
The WAF acts as a proxy for the application server. In this way, client traffic goes directly to the WAF.

- 2. Transparent Reverse Proxy
A Transparent Reverse Proxy is a reverse proxy operating in transparent mode. Thus, the WAF independently forwards traffic to web applications. Consequently, the IP header hides the application server's location. If inactive, this can cause issues during traffic processing.

- 3. Transparent Bridge
HTTP traffic flows directly from the client to the web application.
This places the WAF between the client and the server.

## 14.4.1 Web Application Firewall (WAF) Security Models

Web Application Firewalls consist of a positive security model and a negative security model or sometimes a mixture of both models. A positive security model WAF (“whitelist”) rejects every operation without explicit authorization, whereas a negative security model (“deny list”) consists of a list of blocked items, permitting everything not on that list.

Both positive and negative WAF security models are useful in various application security scenarios. For example:

- 1. Positive Security Model

When performing input validation, the positive WAF model specifies allowed inputs rather than filtering out bad inputs. The advantage is that new attacks not anticipated by developers are blocked.

When performing input validation, the positive model directs you to accept permitted input rather than filtering bad input sources. The benefit of a positive security model is that new cyber threats not foreseen by engineers are pre-empted.

- 2. Negative Security Model

The negative WAF model is simpler to implement, but you can never be certain all aspects are covered. You end up with a long list of negative entries to block what must be stopped. Initially, the negative model permits all traffic despite many across-the-board restrictions. Through this approach, organizations that frequently make system changes gain time so the system does not get blocked.

## 14.4.2 Firewall-as-a-Service (FWaaS)

Firewall-as-a-Service, or FWaaS, is another term for cloud firewalls. Like other “as-a-Service” models such as SaaS or PaaS, FWaaS runs in the cloud, and third-party vendors offer it as a service that they update and maintain.
