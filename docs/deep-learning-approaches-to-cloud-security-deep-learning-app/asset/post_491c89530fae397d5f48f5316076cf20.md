

## 10.7.1 Quantum Isochronous Parallel

For distributed training, Deep Learning commonly utilizes the QIP model, that is, Spark and Graph. The computing process includes a series of supersteps of duration (T) separated by a synchronous barrier. Supersteps utilize a sequence of activities within two synchronous barrier intervals. In every step, all computing nodes perform iterative computation simultaneously. In each superstep, all computing nodes perform iterative computations simultaneously.

After completing the current iteration, each node transfers the updated local parameters to the parameter server, and then enters the synchronization barrier and pauses. Once all computing nodes complete the computation and submit the results, the parameter server refreshes the global model parameters and sends them to all computing nodes; then the synchronization barriers are released so that all processing nodes proceed to the next superstep together. This synchronization mechanism allows the QIP model's parallel Deep Learning computation to be serialized, ensuring global consistency of parameter updates and correct computation execution [16].

The time cost analysis for QIP is defined by the following formula:

$T_{superstep} = \max \{w1/r1, w2/r2, wn/rn\} + \max\{x1, x2, xn\} * K + L$ (10.6)

$T_{superstep}$ indicates the time required for supersteps, where $x_i$ shows the number of CPU cycles expected for the current iteration of node i, and $r_i$ describes the processing speed of the CPU, $a_i$ describes the message size sent or received by a process, $K$ represents the inverse of the bandwidth, and $L$ shows the startup time of the synchronous barrier.

Straggler time is the time it takes for a high-performance computing node to wait for a low-performance computing node.

The straggler time of each node is:

$\max(t_1, t_2, ..., t_n) - t_i$ (10.7)

## 10.7.2 Phase Isochronous Parallel

To address the straggler problem in QIP, a Phase Isochronous parallel processing model is proposed. PIP utilizes the fault tolerance of iterative computation to construct a progressively more flexible consistency synchronization method. Accordingly, effectively alleviating the straggler problem is commonly used in Deep Learning systems based on PIP.

PIP permits each processing node to perform multiple iterations of training using a local model instead of a global model. However, when the number of cycles of another computing node exceeds s times that of the slowest node (where s is defined as the staleness threshold), the synchronization barrier will force the processing node to wait for the slowest node to complete the iteration. Global model parameters are then collected to update the local model parameters.

The frequency of synchronization barrier occurrences is reduced, reducing the time cost of training the PIP model. At the same time, by setting the staleness threshold (s), we can ensure that the local model replica (M) contains updates from all other nodes during cycle times in [0, C-s-1] and partial updates during iteration times in [C-s, C-1], where C represents the current cycle number, thereby ensuring the convergence of parallel Deep Learning computation as shown in Figure 10.6 and Figure 10.7 [19].

This study shows that PIP can effectively alleviate the straggler problem, but it still has the following issues:

- a. In a test environment with similar cluster node performance, PIP will be too slack due to the synchronization mechanism, which will delay node synchronization. Thus, the model update is severely outdated, and the convergence speed and final accuracy of the model are significantly reduced.
- b. The invariance of the staleness threshold (s) makes PIP unable to adapt well to real-time changes in node performance during the model training process.

## 10.7.3 Dynamic Isochronous Coordinate Strategy

To address the two issues mentioned above, a dynamic synchronous parallel model is proposed. Based on PIP, DIC has made targeted improvements. For the issue of PIP being unsuitable for similar node performance, DIC proposes the concept of a weak threshold (w), which specifies that when the cycle number of the slowest computing node reaches w every iteration, the boundary is forced to be updated in synchronization.

This mechanism effectively controls the staleness level of model parameter updates among nodes, and even when the performance of each node is very close, the synchronization condition can be reached relatively quickly. For the issue of the invariance of the staleness threshold (s) in PIP, DIC performs real-time performance monitoring on each computing node by adding a performance monitoring module, and then dynamically adjusts the staleness threshold (ds) according to the performance differences of each computing node. In this way, it can effectively adapt to real-time changes in node performance due to uncontrolled factors in the model training process, such as external interference.

## 10.8.1 Adaptive Quick Reassignment (AdaptQR)

To effectively address the straggler problem caused by highly unequal cluster load in distributed Deep Learning model training, this paper proposes a load balancing method based on remaining workload for dynamic redistribution: AdaptQR. AdaptQR can reduce load differences between nodes by effectively adjusting the workload of each node in each cycle according to the different computation performance in the cluster.
