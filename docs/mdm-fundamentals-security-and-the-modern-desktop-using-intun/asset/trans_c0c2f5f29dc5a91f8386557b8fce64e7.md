

## 添加 UPN 后缀后的后续步骤

运行后，你将首先看到欢迎屏幕。下一个屏幕如 [图 2.44](#c02.xhtml#figure2-44) 所示，解释了“快速设置”。

也就是说，为了避免我深入探讨该工具的每一个细节，并能让你通过示例快速上路，快速设置对于我们的用例来说已经足够。

### 更改用户的后缀

但是，等等！同步发生后，来自本地 AD 的同步用户的用户名中将没有漂亮的 `fabrikam1000.com`，而是仍然有难看的 `fabrikam1000.onmicrosoft.com` 作为其用户名的一部分。

为什么会这样？因为你的本地 AD 用户需要已经明确地在使用该后缀，*只有那样*你才会在同步后看到它。

要更改它，对于单个用户，请使用“Active Directory 用户和计算机”，找到一个账户，如 EastSalesUser1，如 [图 2.50](#c02.xhtml#figure2-50) 所示。然后点击“帐户”选项卡，以便执行两个步骤：

*   **步骤 1：** 实际上在“用户登录名”字段中输入一个名称。通常这将是他们已在使用、熟知且喜爱的名称。
*   **步骤 2：** 下拉并选择你之前在“Active Directory 域和信任关系”中指定的自定义域名。在我的例子中，是 `Fabrikam1000.com`。

![Figure 2.50 Each user needs to have the correct suffix in on-prem AD for it to be synchronized to Azure AD.](images/c02f050.jpg)

**[图 2.50](#c02.xhtml#figureanchor2-50)** 每个用户都需要在本地 AD 中拥有正确的后缀，以便同步到 Azure AD。

你可以等待一段时间，更改将自然发生。

或者你可以实时查看更改发生。要查看它们，请找到 Azure AD Connect 文件夹并启动同步服务，如 [图 2.51](#c02.xhtml#figure2-51) 所示。

![Figure 2.51 Launching the Synchronization Service](images/c02f051.jpg)

**[图 2.51](#c02.xhtml#figureanchor2-51)** 启动同步服务

然后，该工具本身似乎没有一个大大的“点击此处同步”按钮。但有一种 PowerShell 方法可以做到。

你应该能够仅推送更改，即增量。该命令是：

```
Start-AdSyncSyncCycle -policytype delta
```

如果这不起作用，请等待第一个命令完成，然后尝试再次推送所有内容。该命令是：

```
Start-AdSyncSyncCycle -policytype initial
```

你可以在 [图 2.52](#c02.xhtml#figure2-52) 中看到这两个命令运行的结果。

![Figure 2.52 Using PowerShell to force an AD to AAD sync](images/c02f052.jpg)

**[图 2.52](#c02.xhtml#figureanchor2-52)** 使用 PowerShell 强制执行 AD 到 AAD 同步

完成后，刷新 Azure AD 并再次查看所有用户。仔细注意，你指定的那个用户现在拥有了正确的用户名：[EastSalesUser1@fabrikam1000.com](mailto://EastSalesUser1@fabrikam1000.com)，而不再是 `onmicrosoft.com` 那个，如 [图 2.53](#c02.xhtml#figure2-53) 所示。

![Figure 2.53 See that your one user has successfully come over from on-prem AD to Azure AD.](images/c02f053.jpg)

**[图 2.53](#c02.xhtml#figureanchor2-53)** 看到你的那个用户已成功从本地 AD 迁移到 Azure AD。

### 批量更新本地 AD 的 UPN（而不是逐个点击用户）

当然，你不想花费整个周末手动逐个更新每个用户的 UPN 名称，只为让它正确同步到 Azure AD。

批量更新所有用户 UPN 名称的秘诀在一篇博客文章中得以快速揭示：

`https://blogs.technet.microsoft.com/heyscriptingguy/2013/08/13/add-user-principal-names-in-active-directory-via-powershell/`

如果你将本地域命名为 `fabrikam.com`，而你的自定义 Azure 名称是 `Fabrikam.com`，那么这一行脚本应该能瞬间填充每个用户的 UPN 属性。在我的例子中，具体是在 Sales OU 中。

```
Get-ADUser -Filter * -SearchBase 'ou=Sales,dc=fabrikam,dc=com'
-Properties userPrincipalName | foreach
{ Set-ADUser $_ -UserPrincipalName
("{0}@{1}" -f $_.name,"fabrikam1000.com")}
```

然后，使用前面的技术重新同步本地 AD 到 Azure AD，搞定。

现在每个人在 Azure AD 中都拥有了从本地 AD 填充的完全正确的用户名，如 [图 2.54](#c02.xhtml#figure2-54) 所示。

![Figure 2.54 After the on-prem AD PowerShell command, then a sync to Azure AD, all accounts now show your custom domain name.](images/c02f054.jpg)

**[图 2.54](#c02.xhtml#figureanchor2-54)** 执行本地 AD PowerShell 命令后，再同步到 Azure AD，所有账户现在都显示你的自定义域名。
