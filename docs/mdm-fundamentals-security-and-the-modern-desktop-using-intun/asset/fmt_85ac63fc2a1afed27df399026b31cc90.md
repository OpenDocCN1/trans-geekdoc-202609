
## 尝试删除同步用户

出于兴趣，在 Azure AD 管理中心内，尝试点击一个现有的 Windows Server AD 用户，然后从菜单命令栏中点击 **Delete user**。

**剧透警告：你无法删除。**

同步用户在本地 AD 中诞生、存在并终结，仅同步至此。你可以亲自尝试：在本地 Active Directory 用户和计算机中创建一个新用户。稍等片刻，bingo！你应该能在 Azure AD 中看到它。

同步过程从不出错。绝不。咳咳。所以，如果你真的陷入困境，我学到了一个小 PowerShell 技巧，可以清除 Azure AD 内的记录。命令如下：

```
Install-Module msonline
Connect-MSolService
```

这将提示你输入 Azure 管理员凭据；在本例中为 `Frank@fabrikam1000.onmicrosoft.com`。

```
Remove-MsolUser -userprincipalname yourguy@fabrikam1000.com
```

结果可见 [图 2.55](#c02.xhtml#figure2-55)。

![图 2.55 如何清除从本地 AD 同步的用户](images/c02f055.jpg)

**[图 2.55](#c02.xhtml#figureanchor2-55)** 如何清除从本地 AD 同步的用户

随后刷新 Azure AD，将显示该用户已被清除，但仍保留在本地 AD 中。

关于删除从本地 AD 同步的对象的优秀文章见此处：

`https://support.microsoft.com/en-us/help/2619062/you-can-t-manage-or-remove-objects-that-were-synchronized-through-the`

没错，这个 URL 就是以单词 *the* 结尾的。

#### 让 Windows 10 自动加入 Azure AD（混合 Azure AD 加入设备）

同样，本节所有步骤均为可选，但从长远来看，你可能需要考虑这个有趣的想法：你可以让本地 AD 同步所有现有的 Windows 10 账户，并将它们推送到 Azure AD。

**超级大警告：** 虽然这能让所有 Windows 10 电脑注册到 Azure AD，但它**不会**神奇地让它们同时注册到你的 MDM 服务。别担心：我们在 [第 4 章](#c04.xhtml) 中设置该功能（具有讽刺意味的是，我们使用组策略来实现）。

说到组策略，你可以用它来预先阻止某些 Windows 10 电脑从本地 AD 同步到 Azure AD。该策略设置位于：`Computer` ➢ `Policies` ➢ `Admin Templates` ➢ `Windows Components` ➢ `Device Registration` ➢ **Register domain-joined computers as devices**（如 [图 2.56](#c02.xhtml#figure2-56) 所示）。当你将此策略设置为 **Disabled**（是的，是禁用）时，获取该策略的电脑将忽略我们即将执行的“魔法”。

因此，建议你在执行后续步骤**之前**，将 **Register domain-joined computers as devices** 组策略设置预先分发到你想要排除的机器上。（再做个无耻广告：如果你想知道并验证该设置是否已到达所有目标机器，可以使用 PolicyPak 组策略合规性报告器的付费版，它会告诉你哪些本地机器获得了哪些 GPO 和设置，从而消除猜测……但我跑题了。）

![图 2.56 使用“Register domain-joined computers as devices”策略防止 Windows 10 电脑从本地 AD 同步到 Azure AD](images/c02f056.jpg)

**[图 2.56](#c02.xhtml#figureanchor2-56)** 使用 **Register domain-joined computers as devices** 策略防止 Windows 10 电脑从本地 AD 同步到 Azure AD

无论如何，当你准备好开始在本地 Azure AD 和 Azure AD 之间进行“瓦肯心灵融合”时，请在运行 Azure AD Connect 程序的机器上逐行输入以下每个 PowerShell 命令。

如果你想复制粘贴而不是手动输入，我会告诉你来源，也就是这个 URL（稍后我会再提一次）：`https://docs.microsoft.com/en-us/azure/active-directory/devices/hybrid-azuread-join-manual-steps`。

以下是 PowerShell 代码行：

```
Import-Module -Name "C:\Program Files\Microsoft Azure Active Directory Connect\AdPrep\AdSyncPrep.psm1"
$aadAdminCred = Get-Credential
Initialize-ADSyncDomainJoinedComputerSync –AdConnectorAccount frank@fabrikam1000.com -AzureADCredentials $aadAdminCred
```

这些 PowerShell 命令的结果可见 [图 2.57](#c02.xhtml#figure2-57) 的第一部分。接着，如果你想验证是否真正生效，可以运行以下验证检查 PowerShell 命令（这些行也在上述微软 URL 中）：

```
$scp = New-Object System.DirectoryServices.DirectoryEntry
$scp.Path = "LDAP://CN=62a0ff2e-97b9-4513-943f-0d221bd30080,CN=Device Registration Configuration,CN=Services,CN=Configuration,DC=fabrikam,DC=com"
$scp.Keywords
```

![图 2.57 你需要专门设置 Azure AD 以同步 Windows 10 电脑](images/c02f057.jpg)

**[图 2.57](#c02.xhtml#figureanchor2-57)** 你需要专门设置 Azure AD 以同步 Windows 10 电脑

你可以在 [图 2.57](#c02.xhtml#figure2-57) 的第二个代码块中看到结果，它会输出一些内容，包括我的域名 `fabrikam1000.onmicrosoft.com`！

现在，你网络上的 Windows 10 机器（1607 及更高版本）将自动收到通知并自我注册到 Azure AD……无论是新加入域的，还是现有的 Windows 10 机器，在重启和/或登录时均会如此。

你也可以见证这一过程。在 Windows 10 系统重启后，且 Azure AD Connect 自然发生几次同步后，当你检查所有设备时，应该能看到新的 Windows 10 电脑弹出到 Azure AD 中，如 [图 2.58](#c02.xhtml#figure2-58) 所示的 W10-1703-PRO-64 电脑。如果你查看 Join Type，它会显示“Hybrid Azure AD joined”。

**[图 2.58](#c02.xhtml#figureanchor2-58)** 如何查看混合 Azure AD 加入的机器

随后，过一段时间后，Windows 10 机器上会发生变化。

你可以在 [图 2.60](#c02.xhtml#figure2-60) 中看到该变化，随着你不断运行 `dsregcmd /status`。该命令会显示大量你不关心的信息。但关键是第一行：`AzureADJoined` 设置为 `YES`，如 [图 2.60](#c02.xhtml#figure2-60) 所示。

![图 2.60 机器自动 Azure AD 加入后的状态](images/c02f060.jpg)

**[图 2.60](#c02.xhtml#figureanchor2-60)** 机器自动 Azure AD 加入后的状态

同样，这只有在 Azure AD 同步发生一两次后才会发生。如果你想催促它，请参阅前面关于如何运行增量同步的命令。这对我“加速”进程很有效。

此外，如果你想查看所有已加入 Azure AD 的电脑，可以使用以下几个 PowerShell 命令。

*   `Install-Module msonline`
*   `Connect-msolservice`，随后在提示时输入 Frank 的管理员凭据。
*   `Get-MSoLDevice -all` 将显示已加入 Azure AD 的机器。
*   或使用 `Get-MSOLDevice -all | Select displayname, objectid` 获取更美观的视图，如 [图 2.61](#c02.xhtml#figure2-61) 所示。
