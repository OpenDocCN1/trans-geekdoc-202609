

![image](images/warning.jpg) 如果你查看 Microsoft 文档，可能会说要将 `EnterpriseEnrollment.company_domain.com` 放入 CNAME 主机字段。这完全是错误的。这比你需要放入字段的内容要多。因为在 GoDaddy（或其他域名服务商）中，你已经在编辑域名本身，比如 `Fabrikam1000.com`。所以你不需要将 `EnterpriseEnrollment.fabirkam1000.com` 的完整 FQDN 输入到 CNAME 主机字段中；只需输入 `EnterpriseEnrollment` 即可。同理，关于要求输入 `EnterpriseRegistration.company_domain.com` 的指导也是错误的。只需将 `EnterpriseRegistration` 放入 CNAME 主机字段。不理解这一点让我在第一次设置时浪费了好几个小时。

你可能需要等待几分钟让其生效，但我发现一旦设置正确，它会立即生效。然后你就可以开始测试了。

## 自动将本地 AD 同步到 Azure AD

如果你已经在使用 Office 365 并且也有本地 AD，那么你很可能知道我即将谈论的这个工具。目标很简单：如果你在本地 AD 中有大量本地用户，如何为他们在 Azure AD 中自动生成帐户（以便你可以对他们执行操作，如设置管理或向他们提供 Office 365 等）？

很简单：使用 Azure AD Connect 执行同步。

并且如果出现问题，了解这些同步的运行状况/状态。

### Azure AD Connect

同样，你要找的工具叫做 Azure AD Connect。

该工具经历了许多迭代，有多个版本和名称变更。但这就是现在的工具：Azure AD Connect。换句话说，如果你拥有或曾经拥有旧版 DirSync 或 Azure AD Sync……那些工具已经过时了，现在只有 Azure AD Connect。好消息是，如果你曾使用过这些旧工具，可以从它们升级到 Azure AD Connect。

该工具的基础知识可在 `https://docs.microsoft.com/en-us/azure/active-directory/connect/active-directory-aadconnect` 找到，其中包括针对从旧工具升级用户的建议。

在本示例中，我将假设你有一个单一的本地域，名为 `Fabrikam.com`（正如我在本书开头页面推荐的）。如果你在现实生活中拥有更复杂的环境，那也没关系；你可以使用上述 URL 找到你的场景并尝试操作。

**不要**首先下载 Azure AD Connect 工具。不，不要。不要从那里开始。相反，在你的本地 AD 中，运行“Active Directory 域和信任关系”工具。然后右键点击根节点并选择“属性”。然后在“UPN 后缀”选项卡中，添加你（现已验证）的 Azure AD 域名。在 [图 2.43](#c02.xhtml#figure2-43) 中，我添加了 `fabrikam1000.com` 并点击了“确定”。

![Figure 2.43 You need to add the name of your verified Azure AD domain here in on-prem AD Domains and Trusts. It took me eight hours to figure this out, and I could find no documentation on this. So, I hope this step saves you those eight hours.](images/c02f043.jpg)

[**图 2.43**](#c02.xhtml#figureanchor2-43) 你需要在此处的本地 AD 域和信任关系中添加你已验证的 Azure AD 域名。我花了八个小时才弄明白这一点，且找不到任何相关文档。所以，我希望这一步能为你节省那八个小时。

或者，你也可以添加你的 `onmicrosoft.com` 名称，如 `fabrikam1000.onmicrosoft.com`。那也行得通，但既然我费心购买并验证了 `Fabrikam1000.com`，我就使用这个。
