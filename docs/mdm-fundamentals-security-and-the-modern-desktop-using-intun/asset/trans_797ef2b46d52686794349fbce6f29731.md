
Adobe Reader的策略支持简直糟糕透顶。我无法理解，但它只有极少数策略，我测试的几个完全无法按预期工作，而且许多所谓的策略实际上只是首选项。因此UI无法锁定，所以我不会在这里使用它。

Microsoft Office有一些策略可以锁定，其他的则不行。此外，ADMX文件到处都是，对于一个简单的示例来说过于复杂。

你可能想知道MDM引擎如何知道接受什么、丢弃什么。答案其实非常简单优雅。如果你查看Microsoft随操作系统附带的ADMX项目，所有策略设置都会写入类似`HKLM or HKCU / Software / Policies / Microsoft / <something>`的注册表项。

Adobe、Chrome、Firefox、Office、PolicyPak等都附带ADMX文件来对其产品进行最终调整，但正如你所料，它们不会将值写入Microsoft操作系统子键。因此，所有这些设置都会被MDM写入并遵守，因为MDM系统并不负责策划这些设置。

对于我们的工作示例，我选择了Foxit Reader及其ADMX文件。如果你想跟着测试，在你的Windows 10终端上手动安装最新版Foxit Reader（撰写本文时为9.2版）。只需访问`www.foxitsoftware.com/pdf-reader/`下载标准版并安装。同样，在由MDM管理的Windows 10终端上安装，并采用所有默认设置（未展示）。

安装后在Windows 10机器上运行Foxit Reader，花一点时间查看自动更新状态：依次转到“文件” ➢ “首选项”，然后点击“更新程序”。你应该能看到[图3.25](#c03.xhtml#figure3-25)所示内容，程序设置为下载更新并让用户选择是否安装。

[**图3.25**](#c03.xhtml#figureanchor3-25) Foxit Reader的默认更新行为

我们将使用MDM服务将其设置为“不自动下载或安装更新”，并将其锁定，使其用户无法更改。

接下来，在你的管理站上下载并准备好Foxit ADMX文件。最后检查时，可在此处找到：`https://help.foxitsoftware.com/kb/available-gpo-templates.php`。

如果我要使用组策略管理Foxit Reader（我不会），它看起来会像[图3.26](#c03.xhtml#figure3-26)所示。我可能想用的设置是**禁用自动更新**策略设置，也见于[图3.26](#c03.xhtml#figure3-26)。

![Figure 3.26 How you would use Group Policy to set Foxit Reader to stop automatic updates](images/c03f026.jpg)

[**图3.26**](#c03.xhtml#figureanchor3-26) 如何使用组策略设置Foxit Reader停止自动更新

因此，要通过MDM实现此目的，请先用记事本打开Foxit ADMX文件并准备好。然后使用Intune等MDM服务创建一个新配置文件，再创建一个自定义OMA-URI策略，就像我们之前做的那样；只是这次要清楚表明你在为Foxit Reader做配置。

在OMA-URI字段中，你需要指定一个特殊语法，表示你即将提供一个完整的ADMX文件。语法如下：

```
./Device/Vendor/MSFT/Policy/ConfigOperations/ADMXInstall/{AppName}/
{SettingType}/{FileUid or AdmxFileName}
```

好吧，这给我们出了个小难题。我们需要找出并填入以下值：

*   `AppName`：可以是任何名称，但最好用能描述我们正在做什么的名称。我将其命名为`FoxitReader`。
*   `SettingType`：尽管这看起来可能是不同的关键字，但在实践中，引入ADMX时，这必须始终是单词`Policy`。
*   `FileUid`或`AdmxFileName`：也可以是任何名称，但建议命名为你正在使用的ADMX文件名。所以我将使用值`FoxitReaderADMX`。

将所有内容组合在一起（并决定在用户端执行）将得到如下OMA-URI：

```
./Device/Vendor/MSFT/Policy/ConfigOperations/ADMXInstall/FoxitReader/
Policy/FoxitReaderAMX
```

太棒了！

![image](images/warning.jpg) 无论稍后你想分发用户还是计算机（设备）策略，ADMX文件本身必须用`./Device`（如上所示）描述，而非`./User`。同样，稍后你将决定分发用户还是计算机设置；但ADMX文件本身必须指定为`./Device`。

[**图3.27**](#c03.xhtml#figureanchor3-27) 使用自定义类型创建Foxit策略配置文件。

然后，在OMA-URI设置视图中，给它一个名称，粘贴你10秒前制作的OMA-URI，提供字符串数据类型，然后是有趣的部分……将*所有*Foxit ADMX内容粘贴到“值”字段中（见[图3.28](#c03.xhtml#figure3-28)），然后点击“确定”（未显示）。这会将整个ADMX文件保存到配置文件中。

随后，所有这些可能的ADMX定义都会被分发到终端。（这是一个有趣且鲜为人知的点，几页后将变得非常重要。详见侧边栏“替换终端上的现有ADMX设置”。）

[**图3.28**](#c03.xhtml#figureanchor3-28) 作为自定义OMA-URI添加ADMX文件。整个ADMX文件将下载到客户端。

接下来，你需要深入ADMX文件内部找到要分发的值。在[图3.29](#c03.xhtml#figure3-29)中，我认为我找到了正确的项，因为其名称包含“Disable”和“Updater”字样。所以我相当确定`PREF_DisableUpdater`就是正确的项。

![Figure 3.29 Find the policy setting within the ADMX you want to deliver.](images/c03f029.jpg)

[**图3.29**](#c03.xhtml#figureanchor3-29) 在ADMX中查找要分发的策略设置。

我们需要将其转换为MDM格式。表达所需内容的方式如下：

```
./Device/Vendor/MSFT/Policy/Config/
{AppName}∼{SettingType}∼{CategoryPathFromADMX}/{SettingFromADMX}
```

或

```
./User/Vendor/MSFT/Policy/Config/
{AppName}∼{SettingType}∼{CategoryPathFromADMX}/{SettingFromADMX}
```

很好，又是一个需要拼凑的谜题。各部分如下：

*   `AppName`：应与配置ADMX文件引入时使用的应用名称相同。记得我用的是`FoxitReaderADMX`。
*   `SettingType`：同样，这始终只是单词`Policy`。
*   `CategoryPathFromADMX`：在[图3.29](#c03.xhtml#figure3-29)中，我高亮了两个区域。一个是策略名称，另一个是`parentCategory`。这就是这里要填的内容；在我们的例子中称为`PREFERENCES`。但这还不够，因为任何设置可能有一个或多个`parentCategory`（或完全没有`parentCategory`）。我花了一段时间追踪Foxit ADMX文件，第一次甚至弄错了。但有两个父类别：一个是[图3.29](#c03.xhtml#figure3-29)中高亮的，还有一个（未显示）在文件顶部称为`FOXIT`。
*   `SettingFromADMX`：这是我们要配置的设置，也见于[图3.29](#c03.xhtml#figure3-29)。在我们的例子中是`PREF_DisableUpdater`。

将所有内容组合在一起，我们得到：

```
./User/Vendor/MSFT/Policy/Config/
FoxitReader∼Policy∼FOXIT∼PREFERENCES/PREF_DisableUpdater
```

或

```
./Device/Vendor/MSFT/Policy/Config/
FoxitReader∼Policy∼FOXIT∼PREFERENCES/PREF_DisableUpdater
```
