

# MDM 服务中的组管理

MDM 服务还允许你创建特定的**Assigned（已分配）**组和 **Dynamic（动态）**组。

- **Assigned 组**：你直接指定将特定用户或计算机放入其中。
- **Dynamic 组**：你设置条件，当条件适用时，用户或计算机会自动被评估并包含在组内。

在 Intune 中，你可以通过主 Intune 刀片上的 **Groups** 节点来创建组，如 [图 3.35](#c03.xhtml#figure3-35) 所示。

![Figure 3.35 How to start to create groups in Intune](images/c03f035.jpg)

**[图 3.35](#c03.xhtml#figureanchor3-35)** How to start to create groups in Intune

## 创建 Assigned 组

Assigned 组的含义就是你直接指定哪些用户或计算机在组内。这些类似于本地 AD 安全组，但主要用于定位 Intune 配置文件的应用目标。

要创建 Assigned 组，只需将组类型下拉为 **Security**，提供组名称和可选描述，然后将成员身份类型指定为 **Assigned**，如 [图 3.36](#c03.xhtml#figure3-36) 所示。接着，选择要添加到组的成员即可。

再简单不过了。

![Figure 3.36 Creating Assigned groups (containing users)](images/c03f036.jpg)

**[图 3.36](#c03.xhtml#figureanchor3-36)** Creating Assigned groups (containing users)

## 创建 Dynamic 组

Dynamic 组则另当别论。

如前 [图 3.36](#c03.xhtml#figure3-36) 所示，你必须指定组类型（为 Security）和组名称，提供可选描述，然后指定 **Dynamic User** 或 **Dynamic Device**，如下图所示。

![](images/c03uf004.jpg)

规则分为两种类型：**Simple（简单）** 和 **Advanced（高级）**。

Simple 规则功能有限，通常很容易理解其逻辑。在 [图 3.37](#c03.xhtml#figure3-37) 中，我正在为设备创建一个 Dynamic 组，条件为 `displayName Contains Computer`。

![Figure 3.37 Creating a Dynamic computer or user group](images/c03f037.jpg)

**[图 3.37](#c03.xhtml#figureanchor3-37)** Creating a Dynamic computer or user group

如果 Intune 能直接显示哪些计算机（或用户）会被添加就好了；但它做不到。相反，你必须返回 **Groups - All groups**，然后选择刚创建的 Dynamic 组。

接着，你可以一眼看到该组包含的设备（或用户）数量，或通过点击 **Members** 查看实际成员（两者均见 [图 3.38](#c03.xhtml#figure3-38)）。

#### 一个稍深入的 Dynamic 组示例

以防你需要，这里提供一个常见的动态查询示例。例如，如何查找所有 Windows 10 1809 设备。规则的第一部分是确保仅查询 Windows 设备。第二部分将仅包含版本号以 `10.0.17758` 开头的 Windows 10 设备。实际的 Windows 10 版本类似 `10.0.buildnumber.hotfix-level`。但我们省略了 hotfix-level 部分，仅检查版本是否“Starts With” `10.0.17758`。

目标查询如下：

```
(device.deviceOSType -eq “Windows”) -and
(device.deviceOSVersion -startsWith “10.0.17758”)
```

你可以在 [图 3.40](#c03.xhtml#figure3-40) 中看到该查询。

![Figure 3.40 Use this query to find only Windows 1809 machines.](images/c03f040.jpg)

#### 检查 Dynamic 组成员资格最后更新时间

因为 Dynamic 组嘛，顾名思义是动态的，这意味着成员资格会不断评估新的匹配项。这可能需要一点时间。

在 [图 3.42](#c03.xhtml#figure3-42) 中，你可以看到 **“Membership last updated”** 值。当它更新时，你可以合理地确信你正确编写的查询会找到并纳入新计算机。

#### Dynamic 组故障排除

如果你在 Dynamic 组方面遇到麻烦，可以在以下地址找到很好的故障排除问答：`https://docs.microsoft.com/en-us/azure/active-directory/users-groups-roles/groups-troubleshooting`。

该文档的关键发现包括：目录越小，变更生效越快。大型目录可能需要长达 30 分钟来填充。

因此，随着你添加越来越多的计算机，可能需要一点耐心。

# 结语

本章所有示例均使用 Intune 演示。但这些概念应能很好地迁移到任何 MDM 系统。如果我必须为所有这些概念复制或三倍数量地截图以考察其他 MDM 服务，本书篇幅将过于冗长。

正如我在本书导读中所表达的，我有理由相信此处的大多数概念将长期保持有效。但用户界面肯定会在某些地方发生变化，因为微软人员会改变主意，调整按钮、图标、下拉菜单等的位置。

更不用说他们可能会改变主意，以层次结构显示 Administrative Template 设置（也许？），以及通过某种尚未交付的精美界面引入自定义和第三方 ADMX 文件。

话说回来，有个小注记：你始终可以在 `https://docs.microsoft.com/en-us/intune/whats-new` 查看 Intune 的最新动态。
