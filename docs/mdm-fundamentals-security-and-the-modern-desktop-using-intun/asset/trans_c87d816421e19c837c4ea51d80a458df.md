### 为混合 Azure AD 加入准备 Active Directory

混合 Azure AD 加入涉及一些赛前准备工作。

[第 2 章](#c02.xhtml) 中的可选步骤之一是使用 Azure AD Connect 工具设置 AAD 同步。如果你没有执行此操作，但想让本地 AD 与 Azure AD “联姻”，那么你可以翻回 [第 2 章](#c02.xhtml) 查看标题为“自动将本地 AD 同步到 Azure AD”的部分。

然后，在此之后，你首先需要告诉本地 Active Directory，允许网络上的*某台计算机*将*其他* *计算机*加入你的域。

本地 Active Directory 通常不是这样工作的；通常是*人*将计算机加入 Active Directory。但你可以委婉地向 Active Directory 解释，是的，允许另一台*计算机*创建计算机记录并执行其他计算机的加入操作确实没问题。

真的没问题，Active Directory。

要让 Active Directory 了解这一点，你将委派创建计算机对象以及管理其属性和权限的能力。在大多数 Active Directory 中，计算机加入域后神奇出现的位置是 Computers 容器（是的，我是指容器……它不是 OU）。

这通常是你开始委派的地方。也有可能这不是你的默认位置（可以通过古老但依然好用的命令 `redircmp` 来更改）。如果你不确定 Computers 文件夹是否是将计算机加入 Active Directory 时的出现位置，那就加入一台试试。然后找到它。一旦你知道了默认位置，右键单击它并选择“委派控制”，如 [图 8.51](#c08.xhtml#figure8-51) 所示。

![Figure 8.51 Delegate Control over your known default location. If it’s not the Computers folder, then be sure to do it on your redirected location.](images/c08f051.jpg)

[**图 8.51**](#c08.xhtml#figureanchor8-51) 对已知默认位置委派控制。如果不是 Computers 文件夹，请务必在重定向的位置上执行此操作。

然后，在“委派控制向导”内部，你需要更改视图，以便它允许你查找计算机。（同样，这对 Active Directory 来说很不寻常，所以默认情况下它不显示计算机。）在 [图 8.52](#c08.xhtml#figure8-52) 所示的屏幕中，你将单击“对象类型”，然后勾选“计算机”。

![Figure 8.52 Enable Computers as an Object Type.](images/c08f052.jpg)

[**图 8.52**](#c08.xhtml#figureanchor8-52) 启用计算机作为对象类型。

然后，如 [图 8.53](#c08.xhtml#figure8-53) 所示，搜索你计划安装 Intune Connector for Active Directory 的那台计算机的名称。这可以是 Active Directory 中的域控制器或成员服务器。我选的是我的 DC。

![Figure 8.53 Specify the computer where you plan to install the Intune Connector for Active Directory.](images/c08f053.jpg)

[**图 8.53**](#c08.xhtml#figureanchor8-53) 指定计划安装 Intune Connector for Active Directory 的计算机。

然后，在“委派控制向导”中，选择“计算机对象”，如 [图 8.54](#c08.xhtml#figure8-54) 所示，同时勾选“在该文件夹中创建选定的对象”和“在该文件夹中删除选定的对象”，然后单击“下一步”。

![Figure 8.54 Specify that the computer can perform the selected delegated items.](images/c08f054.jpg)

[**图 8.54**](#c08.xhtml#figureanchor8-54) 指定该计算机可以执行选定的委派项目。

最后，你将指定该计算机可以操作权限。在向导的下一页中，选择“完全控制”，如 [图 8.55](#c08.xhtml#figure8-55) 所示。这将自动勾选所有其他复选框。

![Figure 8.55 Select Full Control on the Permission page.](images/c08f055.jpg)

[**图 8.55**](#c08.xhtml#figureanchor8-55) 在权限页面选择“完全控制”。

最后一页是向导的复查。单击“完成”，一切就绪。

### 安装 Intune Connector for Active Directory

现在，让我们回到 Intune。在这里你将找到并下载 Intune Connector for Active Directory。转到 Intune ➢ 设备注册 ➢ Windows 注册 ➢ Intune Connector for Active Directory。然后单击步骤 2 中的链接，如 [图 8.56](#c08.xhtml#figure8-56) 所示。

![Figure 8.56 Downloading the Intune Connector for Active Directory](images/c08f056.jpg)

[**图 8.56**](#c08.xhtml#figureanchor8-56) 下载 Intune Connector for Active Directory

回到本地服务器上，是时候安装它了。你可以在 DC 或成员服务器上执行此操作。这是一个简单的 MSI，不需要太长时间。你可以在 [图 8.57](#c08.xhtml#figure8-57) 中看到 MSI 和打开屏幕。

![Figure 8.57 Installing the Intune Connector for Active Directory](images/c08f057.jpg)

[**图 8.57**](#c08.xhtml#figureanchor8-57) 安装 Intune Connector for Active Directory

单击完成安装后，你应该会看到一条“安装成功完成”消息（未显示）和一个“立即配置”按钮（也未显示）。此外，如果需要，开始菜单中也有一个项目供你重新访问。

只需单击登录按钮（见 [图 8.58](#c08.xhtml#figure8-58)），然后提供主全局 Azure 管理员 Frank Rizzo 的凭据（他还需要一个 Intune 许可证才能使其工作）。完成后，你应该会看到 [图 8.58](#c08.xhtml#figure8-58) 所示的内容。

![Figure 8.58 After you give the Global Admin’s credentials, you will get a success message from the connector.](images/c08f058.jpg)

[**图 8.58**](#c08.xhtml#figureanchor8-58) 提供全局管理员的凭据后，你将从连接器收到成功消息。

此时，我们几乎准备好尝试了。

### 验证 Intune Connector for Active Directory 的安装

安装 Intune Connector 后，正如我们刚才所做的，你可以花点时间查看 Windows 的服务，确认它存在且正在运行。它称为 Intune ODJConnector Service，可在 [图 8.59](#c08.xhtml#figure8-59) 中看到。

![Figure 8.59 Inspecting the Intune ODJConnector Service](images/c08f059.jpg)

[**图 8.59**](#c08.xhtml#figureanchor8-59) 检查 Intune ODJConnector Service

你也可以在同一台计算机上查看 ODJConnector Service 的日志。你需要查看 Windows 的事件查看器 ➢ 应用程序和服务日志，然后是 ODJ Connector Service，如 [图 8.60](#c08.xhtml#figure8-60) 所示。

你可以看到来自 ODJ Connector Service 的有趣事件日志，如 [图 8.61](#c08.xhtml#figure8-61) 所示，以防你需要进行故障排除。

最后，回到 Intune 中，你最终应该会看到你正在使用的计算机被标记为正在执行同步，如 [图 8.62](#c08.xhtml#figure8-62) 所示。这花了我大约 10 分钟，而且“刷新”按钮实际上并没有为我刷新。我不得不按 F5 刷新实际页面。
