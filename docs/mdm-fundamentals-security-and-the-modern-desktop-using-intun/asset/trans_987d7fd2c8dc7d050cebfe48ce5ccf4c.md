

# 使用 Intune

使用 Intune，点击 **设备配置**，然后点击 **配置文件**。在 **设备配置 - 配置文件** 窗格中，点击 **创建配置文件**。你可以在 [图 3.4](#c03.xhtml#figure3-4) 中看到我正在创建一个更改 Edge 主页的配置文件。请注意可供你选择的大量配置文件类型。现在，点击 **设备限制**。

![图 3.4 点击配置文件类型以查看该配置文件类型中的策略类型。](images/c03f004.jpg)

[**图 3.4**](#c03.xhtml#figureanchor3-4) 点击配置文件类型以查看该配置文件类型中的策略类型。

当你选择 **设备限制** 下拉菜单时，将出现一个名为 **设备限制** 的新窗格，其中包含许多选项。只需关注 [图 3.5](#c03.xhtml#figure3-5) 中所示的 **Microsoft Edge 浏览器**。然后找到名为 **启动页面** 的策略，输入你的域名（或任何有效的 URL），如 `http://www.fabrikam1000.com`，然后点击 **确定**（也可见于 [图 3.5](#c03.xhtml#figure3-5)）。

![图 3.5 创建你的第一个设备限制策略以管理 Microsoft Edge 浏览器](images/c03f005.jpg)

[**图 3.5**](#c03.xhtml#figureanchor3-5) 创建你的第一个设备限制策略以管理 Microsoft Edge 浏览器

再次点击 **确定** 以保存配置文件，你将收到如下所示的通知，这实际上是两条消息。

![](images/c03uf001.jpg)

这两条消息分别是：嘿，你做到了。你已保存你的第一个策略。但是，它尚未分配到任何位置以实际生效。

就像在组策略领域，你需要将 GPO“链接”到某个位置；在 MDM 领域，你需要将其*分配*给一个组。

在 MDM 领域，有一个方便的 **所有** 组。这就是我们要首先面向的目标：**所有**。具体来说是 **所有设备**。要执行此操作，请点击 **分配**，然后指定 **所有设备**，如 [图 3.6](#c03.xhtml#figure3-6) 所示。然后点击 **保存** 以保存它。

![图 3.6 使用分配窗格将你的策略分配给所有设备。](images/c03f006.jpg)

[**图 3.6**](#c03.xhtml#figureanchor3-6) 使用分配窗格将你的策略分配给所有设备。

现在是时候与你的 MDM 服务同步了。（记得我说过我会提到这一点吗？）启动 Edge 浏览器，看看你的 URL 是否已成为主页。

而且，这是最棒的部分。你将其设为设备限制。因此，这些设备上的所有用户都将获得相同的设置。试试看！以 MDM 注册的 Windows 10 计算机上的任何其他用户身份登录。每个人都将获得相同的 Edge 主页设置。在 [图 3.7](#c03.xhtml#figure3-7) 中，你可以看到一次 MDM 同步，然后我打开 Microsoft Edge。它就在那里！

![图 3.7 你的第一个 MDM 策略将 Windows Edge 主页设置为你选择的值！成功！](images/c03f007.jpg)

[**图 3.7**](#c03.xhtml#figureanchor3-7) 你的第一个 MDM 策略将 Windows Edge 主页设置为你选择的值！成功！

## 什么构成了 MDM 策略？

因此，前面在 [图 3.5](#c03.xhtml#figure3-5) 中，你看到了一大堆可供选择的策略设置。这些来自哪里？

嗯，同样，微软的 MDM 团队决定哪些策略设置可供使用，并使其可供所有 MDM 提供商（Intune、Workspace ONE、MobileIron 等）使用。

有一个巨大的、不断变化但通常保持最新的列表，可在以下位置获取：

`https://docs.microsoft.com/en-us/windows/client-management/mdm/configuration-service-provider-reference`

在那里，你将看到 MDM 领域的所有可能性。花一分钟将其加入浏览器书签以备将来参考；你很可能会一次又一次地回来这里，获取关于在终结点上配置什么的想法。

### 调查和发现 CSP

我们在 [第 1 章](#c01.xhtml)“企业移动性和 MDM 基础知识”的“CSP：配置服务提供程序”部分讨论过这个概念。

我们从 MDM 服务获得的编辑器和视图，只是用来配置实际核心移动部件——终结点上的 CSP——的漂亮窗口装饰（如果你允许我用这个双关语的话）。

你可以查看 MDM 可以配置的事物的巨大列表；内容太详尽，无法逐一介绍所有领域。但你会看到用于配置 CSP 项的 CSP，例如：

*   `BitLocker CSP`
*   `AppLocker CSP`
*   `BrowserFavorite CSP`

根据它们的名称很容易理解其目标。还有一些名称不那么清晰，如下所示：

*   `PXLogical CSP`
*   `DevDetail CSP`
*   `SUPL CSP`

如果不查阅此处的文档，你可能完全不知道这些 CSP 是做什么的。但同样，文档有助于了解 MDM 领域的可能性。

但请记住，仅仅因为你看到列出了某个 CSP，并不意味着其文档和设置是针对 Windows 10 的。例如，你可能会想：“哦，`BrowserFavorite CSP`……那肯定是用于 Windows 10 的 Edge 及其浏览器收藏夹！”你完全错了。请看 [图 3.9](#c03.xhtml#figure3-9)。

![图 3.9 别被骗了：并非每个名称熟悉的 CSP 都能按预期在 Windows 10 上工作。](images/c03f009.jpg)

[**图 3.9**](#c03.xhtml#figureanchor3-9) 别被骗了：并非每个名称熟悉的 CSP 都能按预期在 Windows 10 上工作。

确实，有一种方法可以使用 MDM 告诉 Edge 填充哪些收藏夹，但这些设置位于另一个 CSP 中，即 `PolicyCSP` 下的 `Browser/ProvisionFavorites` 类别。

关键是，不要仅凭 CSP 的显示标题判断其功能：请查阅文档，确保你想要设置的内容确实存在于某个 CSP 中。

因此，优秀 MDM 系统的工作是抽象这些设置，并为你提供一个漂亮的 GUI 来点击这些设置。在业内，这被称为在 MDM 系统中“呈现”设置；即将这种低级 CSP 功能以漂亮的可点击 UI 按钮、复选框或其他形式呈现在表面。我还听过这些被称为“一流”设置。

有时 MDM 系统不会呈现某个可能的 CSP 设置，这真是令人扫兴。当这种情况发生时（或者更准确地说，不发生时），我们作为 MDM 系统的 IT 管理员就必须全副武装，执行所谓的“自定义 URI”，我们稍后会尝试一下。我听过此类设置被称为“三流设置”。也就是说，Windows 10 上的 MDM 系统会执行该操作，但只是没有简单、轻松的点击方式来完成这件简单的事。

还有一个非常重要的点。还记得前面我们设置浏览器主页时吗？而在 [图 3.6](#c03.xhtml#figure3-6) 中，我们必须决定此设置是应用于用户、设备，还是两者皆应用。了解你的设置是适用于用户、设备（或两者）的唯一方法是查阅文档。

在 [图 3.10](#c03.xhtml#figure3-10) 中，你可以看到 `Browser/HomePages` 设置的文档，其作用域列为用户和设备均可。

![图 3.10 某些 MDM 策略适用于用户和设备两者。](images/c03f010.jpg)
