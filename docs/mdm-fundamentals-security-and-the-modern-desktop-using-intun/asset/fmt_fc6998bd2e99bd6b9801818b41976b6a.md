
在以下章节中，我们将简要了解基线的核心概念。基线内部包含数十项设置，我并不打算逐一深入探讨。确实，我不会建议你直接说“就这样部署吧！”，因为这在现实环境中可能会引入破坏性变更。不过，对于本书及你的测试实验室示例来说，部署测试基线以了解其运作方式是相对安全的。但在现实世界中，你需要逐项检查每个条目，并自问：“这适用于我吗？这能让我更安全（且不破坏任何东西）吗？”

此外，与安全基线相关的是安全配置框架。安全配置框架是基线中建议的一个子集，可用于特定机器。其基本思路是将最重要的安全设置应用到合适的机器类型上。有“普通用户机器”？部署 Level 5 框架。有可能被用于网络恶意行为的管理员工作站？部署 Level 1 框架。介于两者之间？那就是 Level 2-4。

此时，你可以逐一查看每个设置，数量可能很多。同样，保留启用的设置越多，安全性越高。将设置从“是”改为“未配置”的越多，安全性越低，但用户抱怨也越少。为了明确，我并非建议你为了减少麻烦而降低安全性。

## 将安全基线分配给组

## 测试基线

许多安全基线设置难以直观查看或立即测试。但有少数可以。最简单的或许是查看是否真正为 Edge 启用了 SmartScreen，这在 **Figure 10.4** 中已展示。仔细观察，**Figure 10.4** 中有一项已启用的设置名为“要求 Microsoft Edge 使用 SmartScreen”。

SmartScreen 的职责是，嗯……在用户尝试下载和/或运行内容时，智能拦截恶意内容。好，让我们看看实际效果。

使用 Edge 尝试浏览并下载以下（安全但伪装成恶意的）文件：`https://secure.eicar.org/eicar.com.txt`。

![image](images/tip.jpg) 如果你没听说过 EICAR 标准，其大意是：这些是已知安全但伪装成恶意的文件，安全和防病毒程序会识别它们。这样你就能用测试文件触发测试，而无需使用真实病毒或恶意软件。在 `https://en.wikipedia.org/wiki/EICAR_test_file` 了解更多关于 EICAR 的信息。

在 **Figure 10.8** 中，可以看到 Edge 遵循 SmartScreen 设置，阻止了伪装成恶意的文件下载。

![Figure 10.8 See that Edge has been configured to honor SmartScreen via the security baselines.](images/c10f008.jpg)

**Figure 10.8** See that Edge has been configured to honor SmartScreen via the security baselines.
