
164. D. 集中式密钥管理方案不授予用户对私钥的完全控制权。事实上，由于中央 CA 生成公钥和私钥，CA 会在托管中保留私钥的副本。随时，CA 的当局都可以使用私钥访问任何加密数据，无需最终用户的配合。集中式密钥管理方案生成公钥和私钥，对通信环境提供高级别控制，并需要大量基础设施来支持该解决方案。

165. B. 数字签名（非对称加密系统中的私钥）是提供不可否认性的最明显手段。只有一个人持有其私钥。如果发现一条带有其数字签名的消息，那么他们是唯一可能创建和传输该消息的用户。公钥用于限制投递，例如将其用作数字信封，但它们不提供不可否认性。哈希值保护完整性，而共享密钥不提供真正的不可否认性，因为两个实体持有共享密钥的副本。

166. B. 任何时候的任何哈希（包括数字签名中的哈希）都提供数据完整性。使用私钥对消息签名提供不可否认性。数字签名活动作为一个整体不提供机密性保护，因为原始消息以明文形式发送。没有任何形式的加密提供可用性保护。

167. A. RC5 是一种分组密码，支持可变位长度的密钥和可变位块大小。RC4 是一种流密码。RC2 仅限于 64 位块。RSA 不是 Rivest 密码；它是由同一组织开发的非对称加密系统。

168. A. AES 是最佳选择，因为它是一种对称加密算法。El-Gamal 和 Diffie-Hellman 都是非对称算法，而 SHA-1 是一种哈希算法。

169. D. 电子码本（ECB）反复使用生成的密文来加密由块组成的消息。AES ECB 可用于一系列加密功能，如哈希生成、数字签名以及用于数据加密/解密的密钥流生成。ECB 加密块支持 128 位 AES 加密（仅加密，不解密）。

170. B. 消息认证码（MAC，也称为消息完整性码 MIC）确保消息的完整性。MAC 向单向哈希函数添加认证功能。MAC 有两种基本类型：Hash-MAC（HMAC）和密码块链（CBC）MAC。在 HMAC 中，一个对称密钥会附加到仅授权接收者知晓的消息中。HMAC 提供数据源认证和数据完整性。在 CBC-MAC 中，消息使用对称块密码加密。CBC-MAC 提供消息完整性，将块密码作为基元，前提是满足以下条件之一：消息大小固定或密钥未被重用。

171. B. 保持密钥安全将是最大的挑战。私钥加密中没有证书颁发机构，只有公钥加密中有。任务是实现而不是评估，因此计算 ROI 不会成为挑战，且对称加密不需要用户认证。

172. D. 在仅密文攻击中，攻击者只能访问若干加密消息。他们不知道明文数据或密钥是什么。目标是尽可能恢复大量明文消息，或（最好是）猜出密钥。一旦攻击者发现加密密钥，就有可能破解所有使用该密钥加密的其他消息。

173. C. 椭圆曲线密码学（ECC）相对于 Rivest、Shamir 和 Adleman（RSA）算法的优势在于其效率更高，且所需资源比 RSA 更少。ECC 的每位强度高于 RSA。ECC 是一种用于实现公钥（非对称）加密的方法。ECC 作为 RSA 算法的替代方案，提供类似的功能。与其他系统相比，无线设备、智能卡和手机的处理能力、存储、电源、内存和带宽有限。为了确保资源高效利用，ECC 通过使用更短的密钥长度来提供加密。更短的密钥长度并不意味着系统安全性更低。因此，ECC 通过使用更短的密钥提供与 RSA 相同的安全级别，使资源受限设备能够更轻松地进行处理。

174. B. Diffie–Hellman 是非对称加密的一个示例。Diffie–Hellman 允许两台计算机在无需先前关系的情况下安全地接收对称密钥。它是第一个公钥算法。非对称算法包括 Diffie–Hellman、RSA 和椭圆曲线密码学（ECC）。对称算法包括数据加密标准（DES）、三重 DES（3DES）、高级加密标准（AES）、国际数据加密算法（IDEA）、Blowfish、RC4、RC5 和 RC6。

175. D. 消息认证码（MAC）防止冒充攻击。冒充或欺骗是一种流行的技巧，攻击者拦截网络数据包，将数据包头中的源地址替换为授权主机的地址，并重新插入发送给接收方的信息。此类攻击涉及修改数据包内容。MAC 防止数据包被修改，以确保数据完整性。逻辑炸弹是指一种恶意程序，它在网络中保持休眠状态，直到用户执行特定操作或经过一定时间间隔后被触发。在 SYN 洪水攻击中，攻击者向目标发送大量伪造的 IP 数据包，导致其冻结或崩溃。DoS 攻击向目标系统发送大量不需要的请求，导致用户服务中断。

176. B. 非对称 RSA 加密算法使用素数生成密钥。素数是恰好有两个因数的数：1 和该数本身。加密算法确保数据的机密性。只有当素数足够大时，RSA 才被认为是安全的，因此建议 RSA 密钥长度至少为 2,048 位。对称算法对加密和解密使用相同的密钥。合数具有两个以上的因数，这意味着除了能被 1 和自身整除外，还能被至少一个整数整除。

177. D. 密钥托管的目的是在需要时使可信第三方能够访问敏感数据。托管代理将持有加密密钥，并在提供证明或合法访问加密数据（如法院命令）后，将这些密钥提供给调查实体。

178. B. 截至 2020 年初，Zoom 使用 128 位 AES 密钥和 ECB（电子码本）。ECB 已被证明是不安全的。Zoom 已升级为 256 位 AES 与 Galois/计数器模式（GCM）。GCM 非常适合视频会议，因为它是流密码而非分组密码。

179. A. 计数器（CTR）模式是一种基于计数器的简单分组密码实现。每次对计数器初始化的值进行加密，并作为输入与明文进行 XOR 运算，结果即为一个密文块。CTR 模式不依赖反馈，因此可以并行实现。电子码本（ECB）是操作最简便的分组密码模式。之所以更简单，是因为对输入明文的每个块直接加密，输出形式为加密密文块。它也不是很安全。密码块链（CBC）是在 ECB 基础上改进的模式。在 CBC 中，前一个密文块在与原始明文块进行 XOR 运算后，作为输入提供给下一个加密算法。密码反馈（CFB）模式使用初始化向量进行第一次加密，然后进行 XOR 运算以生成结果。

180. D. 输出反馈（OFB）模式将分组密码转换为同步流密码。OFB 生成密钥流块，然后将其与明文块进行 XOR 运算以得到密文。由于 XOR 运算的平衡特性，加密和解密完全相同。

181. B. 椭圆曲线密码学（ECC）是一种基于有限域上椭圆曲线代数结构的现代公钥加密体系族。ECC 密码学被视为 RSA 加密体系的后继者，因为 ECC 在相同安全级别下使用的密钥和签名比 RSA 更小，并提供快速的密钥生成、密钥协商和签名。ECC 加密算法可以使用不同的底层椭圆曲线。不同的曲线提供不同级别的安全性、性能和密钥长度，可能涉及不同的算法。ECC 密钥长度直接取决于底层曲线。在大多数应用程序（如 OpenSSL、OpenSSH 和 Bitcoin）中，ECC 私钥的默认密钥长度为 256 位。

182. C. ECC 中使用的各种椭圆曲线具有不同的特性。P-384 是 NSA 建议所有人在后量子方法标准化之前使用的椭圆曲线。它提供 192 位安全性，而更常用的曲线提供 128 位安全性。对于想要绘制该曲线的人，P-384 曲线的方程为 y² = x³ + ax + b。

183. A. 前向保密（FS），也称为完美前向保密（PFS），是特定密钥协商协议的一种特性，可确保会话密钥不会被泄露。FS 加密系统会频繁且自动更改用于加密和解密信息的密钥。这一持续过程确保了即使最近的密钥被泄露，也只会暴露少量敏感数据。

184. A. 带关联数据的认证加密（AEAD）提供认证加密（机密性和认证）以及检查以明文发送的其他认证数据（AAD）的完整性和认证的功能。内置了消息认证码，用于对密文和已认证但未加密的数据进行完整性检查。TLS v1.2 中的 AEAD 密码套件使用 AES-GCM 和 ChaCha20-Poly1305 算法。未来，这些将是 TLS v1.3 支持的唯一选项，但目前对于大多数企业系统而言，这不是一个可行的选项。
