# 5.1 Grouping Different Types of Data

It's important to remember that in Go the concepts of sub-typing or sub-classing really don't exist and these design patterns should be avoided.

The following is an anti-pattern I shouldn't follow or implement.

Listing 5.1

```
type Animal struct {
    Name string
    IsMammal bool
}
```

The Animal type is being declared as a base type that tries to define data that is common to all animals. I also attempt to provide some common behavior to an animal as well.

Listing 5.2

```
func (a *Animal) Speak() {
    fmt.Println("UGH!")
    "My name is,", a.Name, ", it is,", a.IsMammal, "I am a mammal"
}
```

Most animals have the ability to speak in one way or the other. However, trying to apply this common behavior to just an animal doesn't make any sense. At this point, I have no idea what sound makes, so I wrote UGH.

Listing 5.3

```
type Dog struct {
    Animal
    PackFactor int
}
```

The real problems begin. I'm attempting to use embedding to make a Dog everything an Animal is plus more. On the surface this will seem to work, but there will be problems. With that being said, a Dog does have a specific way they speak.
