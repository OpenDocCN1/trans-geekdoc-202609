# Listing 6.5

```
func main() {
    var wg sync.WaitGroup
    wg.Add(2)

    go func() {
        lowercase()
        wg.Done()
    }()

    ...
}
```

An important part of this orchestration pattern is keeping the Add and Done calls in the same line of sight. Try not to make the WaitGroup as a function parameter where the calls get lost. This will help to reduce bugs.

When I build and run this program, I see this program runs concurrently. The second Goroutine created was scheduled first. It got to finish its work and then the other Goroutine ran. The next time I run this program, there is no guarantee I see the same output. The only guarantee in this program is that the program won't terminate until the last Goroutines are done.

Even if I run this program 100 times and see the same output, there is no guarantee it will happen again. It might be highly probable, but not guaranteed. Especially not guaranteed across different versions, operating systems and architectures.
