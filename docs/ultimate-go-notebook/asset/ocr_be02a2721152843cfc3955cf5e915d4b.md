Then a for loop is used to create all 2000 child Goroutines and each child Goroutine finds itself in a send operation (sem <- true) against the semaphore channel. Here is where the rubber hits the road. A GOMAXPROCS number of child Goroutines can perform this without blocking. The other 2000 - GOMAXPROCS child will block until the running Goroutines get to receive operation (-sem). At the end of the function, the parent Goroutine will receive work from all 2000 child Goroutines. For each piece of work received, the children variable is decremented until it gets to zero. Just like the original fan/in pattern.

# 6.11.8 Bounded Work Pooling

The bounded work pooling pattern uses a pool of Goroutines to perform a fixed amount of known work.

# 6.42

```
func boundedWorkPooling() {
	work := []string{"paper", "paper", "paper", "paper", 2000: "paper"}
	g := runtime.GOMAXPROCS(0)
	var wg sync.WaitGroup
	wg.Add(g)

	ch := make(chan string, g)

	for c := 0; c < g; c++ {
		go func(child int) {
			defer wg.Done()
		for wrk := range ch {
				fmt.Printf("child %d: %s\n", child, wrk)
		}
		fmt.Printf("child %d: recvd shutdown signal\n", child)
	}
}

	for _, wrk := range work {
		ch <- wrk
	}
	close(ch)
	wg.Wait()

	time.Sleep(time.Second)
	fmt.Println("-----------------------------------------------------------------")
}
```

Right from the start, the function defines 2000 arbitrary pieces of work to perform. Then the GOMAXPROCS function is used to define the number of child Goroutines to use in the pool and the WaitGroup is constructed to make sure the parent Goroutine can be to wait until all 2000 pieces of work are completed.
