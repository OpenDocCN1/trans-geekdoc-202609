**Waiting**: This means the Goroutine is stopped and waiting for something in order to continue. This could be for reasons like waiting for the operating system (system calls) or synchronization calls (atomic and mutex operations). These types of latencies are a root cause for bad performance.

**Runable**: This means the Goroutine wants time on an M so it can execute its assigned instructions. If you have a lot of Goroutines that want time, then Goroutines have to wait longer to get time. Also, the individual amount of time any given Goroutine gets shortened as more Goroutines compete for time. This type of scheduling latency can also be a cause of bad performance.

**Running**: This means the Goroutine has been placed on an M and is executing its instructions. The work related to the application is getting done. This is what everyone waits.

# Context Switching

The Go scheduler requires well-defined user-space events that occur at safe points in the code to context switch. These events and safe points manifest themselves within function calls or in between instructions.

There are several classes of events that occur in your Go programs that allow the scheduler to make scheduling decisions. This doesn't mean it will always happen on one of these events. It means the scheduler gets the opportunity.

These events are:

+   * The use of the keyword go
* Garbage collection
* System calls
* Synchronization and Orchestration

# The use of the keyword go

The keyword go is how you create Goroutines. Once a new Goroutine is created, gives the scheduler an opportunity to make a scheduling decision.
