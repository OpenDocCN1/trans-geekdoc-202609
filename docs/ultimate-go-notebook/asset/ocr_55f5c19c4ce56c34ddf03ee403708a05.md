It would be a waste of time to clean up the memory of the returning function's frame because you don't know if memory will ever be needed again. So the memory is left the it is. It's during each function call, when the frame is taken, that stack memory for that frame is wiped clean. This is done through the initialization of any values that are placed in the frame. Because all values are initialized to at least their "zero value", stacks clean themselves properly on every function call.

# Sharing Values

What if it important for the increment function to operate directly on the count variable that exists inside the frame for the main? This is where pointers come in. Pointers serve one purpose, to share a value with a function the function can read and write to that value even though the value does not exist inside its own frame.

If the word "share" doesn't come out of your mouth, you don't need to use a pointer. When learning about pointers, it's important to think using a clear vocabulary and not operators or syntax. Remember, pointers are for sharing. You should replace the & operator for the word "sharing" as you read code.

# Pointer Types

For every type that is declared, either by you or the language itself, you get for free a complement type you can use for sharing. There already exists a built-in type named int so there is a complement type called *int. If you declare a type named User, you get for free a pointer type called *User.

All pointer types have the same two characteristics. First, they start with the character *. Second, they all have the same memory size and representation, which is 4 or 8 bytes that represent an address. On 32bit architectures (like the playground), pointers require 4 bytes of memory and on 64 bit architectures (like your machine), they require 8 bytes of memory.

In the spec, pointer types are considered to be type literals, which means they are unnamed types composed from an existing type.
