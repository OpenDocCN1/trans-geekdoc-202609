# Listing 9.1

```
func print[T any](slice []T) {
    fmt.Print("Generic: ")
    for _, v := range slice {
        fmt.Print(v, " ")
    }
    fmt.Print("\n")
}
```

This is an implementation of a single print function that can output a slice of any given type using the new generics. What's nice about this syntax is that the code inside the function can use syntax and built-in functions that would work with a concrete type. This is not the case when I use the empty interface to write generic code.

I need a way to tell the compiler that I won't be declaring T explicitly, but it has to be determined by the compiler at compile time. The new syntax use square brackets for this. The brackets define a list of generic type identifiers that represent specific to the function that need to be determined at compile time. How I tell the compiler that types with these names will not be declared before the program is compiled. These types need to be figured out at compile time.

> Note: I can have multiple type identifiers defined inside the brackets the current example is only using one. Ex. [T, S, R any]

I can name these identifiers anything I want to help with the readability of the code. In this case, I'm using the capital T to describe a slice of some type T (to be determined at compile time) will like the use of single capitalized letters when it comes to collections and it's also a convention that goes back to older programming languages like C++ and Java.

There is the constraint on what type T can be. The compiler requires that all generic types have a well defined constraint. The any is predeclared by the compiler and states there are no constraints on what type T can be.
