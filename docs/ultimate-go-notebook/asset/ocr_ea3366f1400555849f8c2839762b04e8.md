```
32

```

The syntax is hiding what is really happening in this code. The variable declared on line 28 represents a value of type user. Construction in Go doesn't tell you whether a value lives in memory, it's not until the return statement on line 34, whether you know the value will need to escape. This means, even though u represents a value of type user, access to this user value must be happening through a pointer underneath the covers.
