```

gc 4                   : The 4th GC run since the program started
@95.976s               : 95.976 seconds since the program started
0%                     : Zero percent of the times has spent in GC
```

```
// Wall Clock: [0.048+0.47+0.016 ms clock] Write Barrier on
0.048ms               : STW                  - Mark Up
0.47ms                : Concurrent           - Marking
0.016ms               : STW                  - Mark Termination off / Clean Up
```

```
// CPU Clock: [0.78+0.13/1.0+0.25 ms cpu]
0.78ms                : STW                  - Mark Up
0.13ms                : Concurrent           - Mark Assist Time
1.0ms                 : Concurrent           - Background GC time
1.3ms                 : Concurrent           - Idle GC time
0.25ms                : STW                  - Mark Termination
```

```
// Memory              : [4-<2> MB]
4MB                   : Heap memory in-use before the Marking started
4MB                   : Heap memory in-use after the Marking finished
2MB                   : Heap memory marked as live after the Marking finished
```

```
// Goal                : [5 MB goal]
5MB                   : Collection goal for heap memory-use after Marking finished
```

```
// Threads             : [16 P]
16P                   : Number of logical P's or threads used to run Goroutines
```

The comments explain what of the different numbers mean. For my purpose evaluating potential memory leaks and if the GC is overwhelming, the memory numbers and the percent of time in GC is what I will evaluate.

# 11.3 Generating Load And Evaluation

To apply load on the program, I will use a tool named hey. The tool can be found on Github at https://github.com/rakayll/hey.

With the service already started in one terminal, I will run the hey tool in a second terminal to send 10k requests over 100 concurrent connections.

# Listing 11.6

```
$ hey -m POST -c 100 -n 1000 "http://localhost:5000/search?term=biden&cnn-on&bbc=on&nyt=on"
```

Once the load is sent into the program, I will see GC traces. After the last request is processed, the hey tooling provides the results.
