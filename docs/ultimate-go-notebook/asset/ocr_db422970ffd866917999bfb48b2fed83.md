# Listing 2.11

```
type example2 struct {
    flag bool      // 0x000100020 <- Starting Address
    byte          // 0x000100021 - 1 byte padding
    counter int16  // 0x000100022 - 2 byte alignment
    flag2 byte     // 0x000100024 - 1 byte alignment
    byte          // 0x000100025 - 1 byte padding
    byte          // 0x000100026 - 1 byte padding
    byte          // 0x000100027 - 1 byte padding
    pi float32    // 0x000100028 - 4 byte alignment
}
```

This is how alignment and padding play out a value of type example2 starts at address 0xc000100020. The flag field represents the starting address and is only 1 byte in size. Since the counter field requires 2 bytes of allocation, it must be placed in memory on a 2-byte alignment, meaning it needs to fall on an address that is a multiple of 2. This requires the counter field to start at address 0x000100022. This creates a 1-byte gap between the flag and counter fields.

# Figure 2.2

| Flag | | Counter | | Flag2 | | | | |

| 0 | 1 | | 4 | 5 | 6 | 7 | 8 | | 12 |

The flag2 field is a bool and can fall at the next address 0xc000100024. The final field is pi and requires 4 bytes of allocation as it needs to fall on a 4-byte alignment. The next address for a 4 byte value is at 0xc000100028. That means 3 padding bytes are needed to maintain a proper alignment. This results in a value of type example2 requiring 12 bytes of total memory allocation.

The largest field in a struct represents the alignment boundary for the entire struct. In this case, the largest field is 4 bytes so the starting address for this struct value must be a multiple of 4. I can see the address 0xc000100020 is a multiple of 4.

If I need to minimize the amount of padding bytes, I must lay out the fields from highest to lowest allocation. This will push any necessary padding bytes down to the bottom of the struct and reduce the total number of padding bytes necessary.
