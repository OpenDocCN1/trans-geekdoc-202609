Another important aspect of benchmarking the compiler. The compiler will build this code into a binary to run the benchmark. It's important that the code inside the loop is accurate to how it runs in production. If I don't capture the return value from the call to Sprint, it's possible that the compiler could throw the function call out of the compiled binary. The function is useless without capturing the return since the behavior of code alone wouldn't change the behavior of the program. If the compiler chooses to throw the call to Sprint away, the benchmark would just spin an empty loop, providing an inaccurate result.
