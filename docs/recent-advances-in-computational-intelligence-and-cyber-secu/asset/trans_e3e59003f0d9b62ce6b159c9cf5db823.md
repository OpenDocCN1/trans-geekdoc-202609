

随着时间的推移，软件系统能够非常轻松高效地解决日常事件，它们变得越来越庞大和复杂。维护如此复杂的系统对软件专业人员来说变得越来越困难。由于维持现有系统占用了软件公司大部分资源，一些公司可能无法启动新项目。因此，在软件开发过程的早期，在设计阶段，软件可维护性预测 `SMP` 将重点放在创建和开发用于预测软件可维护性的预测模型上 \[[1](#ch24.xhtml#ref24_1)\]。提前选择更重要的参数可以提高 `SMP` 模型的预测准确性 \[[2](#ch24.xhtml#ref24_2)\]。高维记录中存在重复特征可能会对预测可维护性造成问题，因为这可能导致机器学习 `ML` 算法表现不佳。特征选择 `FS` 技术有效地克服了这一差距 \[[6](#ch24.xhtml#ref24_6), [7](#ch24.xhtml#ref24_7)\]。这提供了在预算范围内按时交付的优秀软件产品，且可维护性非常高。本研究在学习 `SMP` 模型之前使用了一系列数据特征排序算法，以提高和有效性能，解决了参数选择在 `SMP` 中的重要性。本研究发现面向对象 `OO` 指标与软件可维护性之间存在强相关性，这些指标描述了程序的各个方面，包括继承、耦合和内聚。这使得研究变得重要，因为它通过确定影响软件可维护性甚于其他特性的特征来解决高效 `SMP` 模型的创建问题。通过适当的方式将资源分配给这些类，有助于提高软件产品的质量。我们的提案有助于：
* 确定软件系统可维护性的根本点。
* 评估并统计验证所创建的 `SMP` 模型的预测能力。
* 评估多种基于特征选择的排序策略与支持向量机 `SVMs`。

为了满足上述研究目标，我们创建了使用软件可维护性作为响应变量和 `OO` 指标作为预测变量的 `SMP` 模型。取自开源软件的五个数据集。我们借助特征选择算法选择的顶级关键参数来预测可维护性。然后使用混淆矩阵和接收器操作特征 `ROC` 曲线评估 `SMP` 模型。

## 2. 相关工作

2014年，Wong等人，\[[10](#ch24.xhtml#ref24_10)\] 提出了一种基于自动学习的 methodology，该方法使用实际平均维护工作量来训练可维护性预测器。Kumar等人于2017年讨论了各种维度中各种重要的特征选择相关性。这些数学函数有助于找到准确的 `SMP` 模型。Kumar等人，\[[7](#ch24.xhtml#ref24_7)\] 提出了用于变更值预测的混合技术。2017年，Reddy等人，\[[5](#ch24.xhtml#ref24_5)\] 使用了基于支持向量的回归、多层感知器、多线性回归和 `M5P` 回归树。Malhotra等人，\[[8](#ch24.xhtml#ref24_8)\] 于2020年提出了基于类相关组的维护性。数据采样和重采样是主要基础，用于更好的预测 \[[9](#ch24.xhtml#ref24_9)\]。此外，为处理不平衡数据集和预测软件可维护性，使用了安全水平——合成少数类过采样技术。2020年，Gupta等人，\[[3](#ch24.xhtml#ref24_3)\] 提出了一个使用最小二乘的模型，并展示了它们的相关比较以获得更好的结果。他们还在2020年提出了增强随机森林方法 \[[4](#ch24.xhtml#ref24_4)\] 来估计开源软件的可维护性。

### 3.1 数据集

我们使用了以下基于 Java 编程的数据集：
* Ant: Ant 是一种命令行工具，用于自动化构建文件中表示的扩展点和目标中的任务。Ant 包含用于构建、测试、编译和运行 Java 程序的多个任务。
* Camel: 以企业集成模式为核心构建。Camel 是一个开源网络框架。
* Ckjmml: 软件 ckjm 通过检查字节码和编译的 Java 程序来生成面向对象的指标，如 Chidamber 和 Kemerer。
* Ivy: Ivy 是一个用于控制项目依赖关系（记录、监控、解析和汇总）的系统。

### 3.2 预测变量

由于研究是针对用 Java 开发的 `OO` 系统进行的，我们在预测模型中使用 `OO` 指标作为预测变量。我们列出了源代码行数 `LOC`、类响应 `RFC`、继承树深度 `DIT`、每个类的加权方法数 `WMC`、聚合度量 `MOA`、类的子节点数 `NOC`、对象间耦合 `CBO`、继承耦合 `IC`、数据访问度量 `DAM`、功能抽象度量 `MFA`、公共方法数 `NPM`、外向耦合 `Ce`、内向耦合 `Ca`、类方法间耦合 `CBM`、平均方法复杂度 `AMC`、类方法间的内聚 `CAM`，以及 `LCOM3` 作为输入变量。`LCOM` 的变体称为 `LCOM3`（[Table 24.1](#ch24.xhtml#tab24_1)）。

[Table 24.1 Description of predictors](#ch24.xhtml#R_tab24_1)

| Metric suit || Set of metric selected |
| --- | --- |
| CKJM suit \[[11](#ch24.xhtml#ref24_11)\] || `CBO`, `NPM`, `RFC`, `LCOM`, `DIT`, `WMC` |
| --- | --- |
| QMOOD suit \[[12](#ch24.xhtml#ref24_12)\] || `NPM`, `DAM`, `MOA`, `CAM`, `MFA` |
| Martins's metrics \[[13](#ch24.xhtml#ref24_13)\] || `Ca`, `Ce` |
| Henderson-Sellers \[[14](#ch24.xhtml#ref24_14)\] || `LOC`, `LCOM3`, `AMC`, `IC`, `CBM` |

这些指标解释了 `OO` 系统的众多方面，包括耦合、内聚、大小、继承、组合和封装。`WMC`、`NPM`、`LOC`、`DAM` 和 `AMC` 的指标都显示了类的大小。`IC`、`CBM`、`RFC`、`Ca`、`Ce` 和 `CBO` 度量用于量化耦合。`NOC`、`DIT` 和 `MFC` 用于识别继承的属性。类内聚指标包括 `LCOM`、`CAM` 和 `LCOM3`，而组合则由 `MOA` 衡量。这些选定的指标已在预测建模中进行了广泛研究。

### 3.3 响应变量

我们的工作使用圈复杂度来确定可维护性，因为研究中使用圈复杂度来形成因变量，即每个软件类的可维护性值 `MV`。高和低分别代表最大和低可维护性。在圈复杂度中则相反。可维护性高意味着类的圈复杂度小于 1，而可维护性低则指类的圈复杂度大于或等于 1。确定因变量所实现的逻辑如下。

```
if (CC<=1)
{
MV = 1;
}
Else
{
MV = 0;
}
```
