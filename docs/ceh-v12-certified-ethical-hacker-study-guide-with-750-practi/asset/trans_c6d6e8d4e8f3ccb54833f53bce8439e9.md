
-   [新的获取接口地址信息的方式](https://example.org/ip_a) 也不能显示接口是否处于混 promiscuous 模式。对获取接口链路状态的 `ip link` 也是如此。当然，Windows 上的 `ipconfig` 与 Unix 类系统上的 `ipconfig` 功能略有不同。它仅提供 IP 配置，而非接口配置，因此同样看不到接口是否处于混 promiscuous 模式。

-   你不必在机器上才能判断设备是否处于混 promiscuous 模式，但需要能够访问本地网络以某种方式查看数据包。网络管理员或负责 DNS 服务器的系统管理员可能会识别出正在抓包的设备。像 Wireshark 和 `tcpdump` 这样的工具默认会进行主机名解析，因此每个新出现的 IP 地址都会在运行数据包捕获的操作系统上触发一次 DNS 查询。这并不保证有人真的在设备上捕获数据包，但它可能是一个有用的指示。

-   当设备处于混 promiscuous 模式时，所有到达接口的流量都会转发给操作系统。这可能导致异常或意外的行为。例如，如果你使用 packETH 或其他工具构造数据包，并向你怀疑的捕获设备发送 ICMP 回显请求，你会设置正确的 IP 地址但错误的 MAC 地址。如果该设备的接口不在混 promiscuous 模式下，它不会收到该消息；若收到，则会发现 IP 地址正确并做出响应。但在交换环境中，该消息根本到达不了设备，需要像 ARP 欺骗这样的攻击技术才能让它到达。因此，这种技术在交换环境下可能不够可靠。

-   最后，你可以观察到 ARP 欺骗等欺骗攻击。入侵检测系统以及其他网络监控工具（如查看交换机的 packETH）也会注意到这种情况。如果在网络中看到大量 ARP 报文，尤其是 ARP 回复而没有对应的请求，则可以确定正在发生 ARP 欺骗攻击。这可能表明有人在网络上捕获数据包。

**数据包分析**

最终，数据包分析可能是你最初捕获数据包的主要原因。获取数据包后，你会希望更深入地检查它们，包括过滤、跟随通信流以及查看统计信息和其他可视化内容。这里 Wireshark 表现出色，能够帮助你完成这些任务。正如前面所述，Wireshark 完全理解协议，这意味着它不仅能够解码协议，还能指出可能的协议违规之处。还有其他许多地方，Wireshark 能让阅读数据包捕获内容更加轻松。

Wireshark 会自动进行计算，让你的工作更轻松。当 TCP 连接建立时，会生成序列号，为了防止欺骗，TCP 连接的初始序列号应为随机。序列号为 4 字节，因此数值很大。序列号根据传输的字节数递增。如果你自己手动进行此加法运算，需要花费时间跟踪序列号和确认号。相反，Wireshark 为你提供相对序列号，使其更易于使用。根据 Wireshark，第一个序列号为 1。相对序列号随后按预期递增。[Figure 9.8](#c09.xhtml#c09-fig-0008) 展示了带有相对序列号的 TCP 头部。

属于同一对话的数据包（帧）可能在数据包捕获中分散排列。如果在对话中有大量帧在中间穿插，你可能会发现很难在对话之间切换。Wireshark 允许你跟随流。可以通过右键单击属于该对话的帧来打开上下文菜单，选择“Follow TCP Stream”（例如），Wireshark 会为你创建显示过滤器，仅显示属于该对话的帧。此外，Wireshark 还会从负载中提取数据并将其呈现给你。例如，在 HTTP 对话中，你会看到客户端和服务器之间的 HTTP 消息文本。[Figure 9.9](#c09.xhtml#c09-fig-0009) 展示了一个弹出窗口，显示 HTTP 对话的文本。客户端消息背景为粉红色、文字为红色，服务器消息为蓝色，背景为淡紫色或淡紫红色。底部会显示“Save and show data as”以及选中“ASCII”。还有其他选项，包括原始数据、C 语言数组和 YAML。

Wireshark 还具备展示数据包捕获统计信息的强大功能。Statistics 菜单包含众多选项，其中 Protocol Hierarchy（协议层次结构）是其中之一。它按协议之间的关联关系展示捕获中识别出的所有协议的层次结构。例如，如 [Figure 9.10](#c09.xhtml#c09-fig-0010) 所示，所有帧都是以 Ethernet 为基础的，这些帧全部是 IP 数据包。在这些 Ethernet 帧中，5.5% 为 UDP 数据报。SSDP、MDNS 和 DNS 都是利用 UDP 作为传输层协议的协议。大多数捕获的数据包是 TCP 段，其中大部分是 SSL，实际上它们都是 TLS（SSL 的后继协议）。

另一个值得关注的 Statistics 菜单项是 Conversations 视图。它显示数据包捕获中所有端点之间的对话。每一层的对话集合不同，因为层 2 的对话与 IP 地址对话不同。任何从本地网络向外部传出的 IP 对话都会在本地网关上产生层 2 对话。这意味着你可能会看到的以太网对话少于 IP 对话。此外，TCP 对话与 IP 对话也不同，可能会有多个端口对之间的多组对话。这在本地浏览器向 web 服务器建立多个连接以请求图像、HTML 页面和其他资源时尤为常见，这些资源共同参与页面渲染。[Figure 9.11](#c09.xhtml#c09-fig-0011) 展示了数据包捕获中的 Conversations 统计信息。
