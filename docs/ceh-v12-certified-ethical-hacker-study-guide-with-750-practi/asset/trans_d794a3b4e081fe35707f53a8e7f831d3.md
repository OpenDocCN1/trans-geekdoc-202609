
一个SNMP的优势是它最常用于网络设备（如路由器和交换机）。这些设备可能没有传统的访问方式，也没有传统的用户概念，使用SNMP来获取这些设备的信息可以是一个很好的入口点。正如往常一样，SNMP协议通常会被防火墙禁用。换句话说，你通常需要先通过防火墙或访问控制列表获得对网络设备的特定访问权限，才能开始请求网络设备的MIB数据。正确实现和配置的SNMP代理不应向任何请求它的人员提供敏感的系统信息。

### Countermeasures

针对SNMP的最简单的对策就是直接禁用它。但这取决于网络的管理方式，可能并不总是可行。除此之外，务必升级到SNMPv3，因为SNMPv1已经被多年弃用，它不仅容易受到攻击，而且无法加密数据，所有信息都是明文的。SNMPv1的认证机制也很弱，依赖于community字符串，而实现往往使用众所周知的字符串。保护SNMP实现的措施如下：

*   **Upgrade to SNMPv3** 移除SNMPv1和SNMPv2。

*   **Require Authentication** 禁用仅使用community字符串进行认证的做法。

*   **Require Encryption** 确保所有SNMP通信都经过加密。

*   **Use Firewalls** 结合网络层和主机层防火墙，确保只有授权的主机之间进行通信。SNMP不应在未受限制的网络中随意使用。

## Simple Mail Transfer Protocol

与许多其他协议一样，SMTP使用一系列动词（verbs）与服务器交互。客户端发送一个动词以及必要的参数给SMTP服务器。根据动词的不同，服务器知道如何处理收到的参数。与其他更简单的协议不同，SMTP的交互是一整套对话。在开始之前，你必须先向服务器问候，这告诉服务器你将使用何种SMTP版本。随后，你告知服务器你想执行的操作。根据你要完成的功能，可能需要提供额外的信息，例如提供凭证。下面给出一个简短的SMTP对话示例，这是纯手动的，你可以看到在协议层面的交流以及如何与SMTP服务器交互。如果你连接的不是本地服务器或SMTP服务器未认识的用户，可能会收到错误。

**SMTP Conversation**

```
 root@quiche:~# nc 192.168.86.52 25
 220 bobbie.lan ESMTP Postfix (Ubuntu)
 EHLO blah.com
 250-bobbie.lan
 250-PIPELINING
 250-SIZE 10240000
 250-VRFY
 250-ETRN
 250-STARTTLS
 250-ENHANCEDSTATUSCODES
 250-8BITMIME
 250-DSN
 250 SMTPUTF8
 MAIL From: foo@foo.com
 250 2.1.0 Ok
 RCPT To: wubble@wubble.com
 250 2.1.5 Ok
 DATA
 354 End data with <CR><LF>.<CR><LF>
 From: Goober
 To: Someone
 Date: today
 Subject: Hi
 
 Nothing really to say.
 
 .
 250 2.0.0 Ok: queued as 33471301389
 
```

发起对话时使用 `HELO` 或 `EHLO`，服务器会返回它所支持的功能列表。SMTP协议中有几个功能可以用于枚举用户或至少电子邮件地址。其中之一是 `VRFY`，用于验证用户。并非所有邮件服务器都开启此功能，因为它可以用来识别合法用户或邮箱地址，进而被攻击者或垃圾邮件发送者利用。下面是一个在默认开启 `VRFY` 的本地 Postfix 服务器上的 `VRFY` 示例。

**Testing VRFY**

```
 root@quiche:~# nc 192.168.86.52 25
 220 bobbie.lan ESMTP Postfix (Ubuntu)
 EHLO blah.com
 250-bobbie.lan
 250-PIPELINING
 250-SIZE 10240000
 250-VRFY
 250-ETRN
 250-STARTTLS
 250-ENHANCEDSTATUSCODES
 250-8BITMIME
 250-DSN
 250 SMTPUTF8
 VRFY root@localhost
 252 2.0.0 root@localhost
 VRFY kilroy@localhost
 252 2.0.0 kilroy@localhost
 VRFY root
 252 2.0.0 root
 
```

我们只收到状态码，没有具体的服务器反馈信息。252 表示地址无法验证，但服务器仍会尝试投递。即使 `VRFY` 已启用，也并未提供太多有用信息，手动遍历非常耗时。
