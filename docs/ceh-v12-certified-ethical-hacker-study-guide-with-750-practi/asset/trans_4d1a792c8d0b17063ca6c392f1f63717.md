
-   [Wireshark](https://wiki.example.org/feynmans_learning_method) 不仅会给出你捕获的帧列表，让你看到谁在与谁通信，还提供了完整的协议解码。[Figure 9.2](#c09.xhtml#c09-fig-0002) 中的两个协议已展开。Wireshark 知道如何解码几乎所有你能想象的协议。[Figure 9.2](#c09.xhtml#c09-fig-0002) 中你能看到的只是针对两个常见协议（IP 和 TCP）的简单解码。每个字段都已拆分，除了提供字段名称和值外，还提供了其含义。例如，如果仅查看包含 IP 版本和头部长度的字节，你会看到 0x45。这只是字节值，但该字节在两个 nibble（4 字节值）中包含两个独立的数据。第一个是版本，为 4。第二个是头部长度，显示为 5，如果不熟悉 IP 协议，可能会误以为长度是 5。Wireshark 知道需要将该值乘以 4，因为该字段实际表示 32 位（4 字节）双字的数量。因此，Wireshark 会显示头部长度为 20。

这让你更容易理解所看到的内容。Wireshark 还知道许多其他协议，甚至可以帮助你理解加密通信，程度上如此。如果你查看帧列表，就能看到用于设置 TLS 会话加密的不同帧。在 Wireshark 窗口中间的解码面板中打开相应的协议，你可以看到具体内容，如[Figure 9.3](#c09.xhtml#c09-fig-0003) 所示。你可以看到正在使用的 TLS 版本以及正在发送的具体消息。这是因为消息尚未完全加密，仅凭头部信息即可判断。

加密在数据包捕获中始终是个问题。加密的目的在于只有发送方和接收方才能阅读消息。会话密钥（如 TLS 加密网页消息使用的密钥）在会话建立时即派生。通过使用证书（包含公钥和私钥）来实现，这些密钥用于在派生对称密钥的同时共享信息。要解密任何信息，你需要会话密钥，这意味着你需要证书信息，以便能够“中间人”位置获取密钥。

Wireshark 具备使用 RSA（Rivest、Shamir、Adleman，算法创始人姓名）密钥解密 TLS 加密消息的能力。[Figure 9.4](#c09.xhtml#c09-fig-0004) 展示了偏好视图，你可以在此添加 RSA 密钥。这可能让你能够解密 TLS 消息。你也可以看到输入预共享密钥的位置。在某些情况下，你可能会看到使用预共享密钥的加密，这基本上是双方已经事先知道的密码。该密钥在双方之间提前共享（pre‑shared）。

### Berkeley Packet Filter

我们迄今所观察的数据包捕获工具均可使用 Berkeley Packet Filter（BPF）。BPF 是系统数据链路层的接口，广泛用于 `tcpdump`、`tshark` 和 Wireshark 等系统和应用。编写 BPF 由 `host`、`ether`、`net`、`proto` 等原语组成，并可使用 `src`、`dst` 等修饰符对每个原语进行修饰。这意味着你可以基于 `src host` 或 `dst host` 进行过滤。同时，你可以通过 `ip4` 和 `ip6` 修饰符过滤 IPv4 或 IPv6。将过滤器追加到 `tcpdump` 命令行后，`tcpdump` 会只捕获并显示通过该过滤器的数据包。

例如，前文提到的 `tcpdump` 示例实际上是在一个 Linux 系统上（我有一个简单的提示符，说实话）通过 SSH 连接到该系统时捕获的。当你通过 SSH 连接到系统并运行数据包捕获时，绝大多数数据包都是 SSH 数据包。你真正关心的流量会被 SSH 流量淹没。想一想：你运行 `tcpdump` 后，它会向你发送一个消息表明正在运行，`tcpdump` 捕获一个数据包并将其显示。显示时，SSH 数据包中包含要发送给你的显示文本，这段文本被捕获并发送给你。如此往复。要捕获有意义的流量而非全部 SSH 包，实际使用的命令应为 `tcpdump not port 22`。
