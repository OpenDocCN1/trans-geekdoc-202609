#### Disassembly

在不运行程序的情况下，观察程序将要做什么的最有效方法是查看代码。我们无法查看源代码，但可以对可执行文件进行反汇编。反汇编的过程是将 CPU 理解的操作码（opcodes）形式的可执行代码转换为人类更易理解的汇编语言。当然，汇编语言并不是最易阅读的语言。最好的情况是，它比单纯的数字更易理解。反汇编会将操作码转换为助记符（mnemonic）。助记符是一种记忆辅助技术。通常你会看到一句话，其每个单词的首字母对应需要记住的内容。这是一种助记符的形式。在我们的例子中，每条指令用三到四个字母表示其功能。

在 [Figure 8.7](#c08.xhtml#c08-fig-0007) 中，你可以看到一段已反汇编的程序片段。有很多程序可以执行反汇编。我们正在使用 Cutter 中的反汇编视图。这只是程序的只读视图。Cutter 不提供执行程序或以任何方式修改程序的能力。还有其他程序可以进行反汇编并提供对程序运行的控制。由于我们进行的是静态分析，实际上不想运行程序，所以从 Cutter 获得的内容非常合适。

![FIGURE 8.7 Program disassembly in Cutter](images/c08f007.png)

[**FIGURE 8.7**](#c08.xhtml#R_c08-fig-0007) Program disassembly in Cutter

这里变得复杂了。要理解正在发生的事情，我们需要能够阅读汇编语言，这需要一些练习。高级编程语言为我们提供变量，而汇编语言为我们提供内存。任何操作数（operand）需要操作的数据都存储在寄存器（register）中。寄存器是固定长度的内存位置，存储在 CPU 上，访问速度非常快。我们需要将数据加载到寄存器中，这意味着我们需要诸如 `mov` 操作这样的指令。正如你可能猜测的，`mov` 用于将信息从一个位置移动到另一个位置。在 [Figure 8.8](#c08.xhtml#c08-fig-0008) 的第二行代码中，你可以看到一个 `mov`，它将数据从内存位置移动到寄存器。

![FIGURE 8.8 Properties on executable](images/c08f008.png)

[**FIGURE 8.8**](#c08.xhtml#R_c08-fig-0008) Properties on executable

有些寄存器具有特定功能。这里指的是 Figure 8.7。例如，第二行代码中的 `mov esi, 0x405000` 使用名为 `esi` 的寄存器。这是一个通用寄存器，常用于存储内存地址，具体来说是源地址。`edi` 寄存器用于存储目的地址。第三行代码展示了 `lea` 操作，即加载有效地址的缩写。这使得 `edi` 寄存器包含一个计算结果，结果以方括号内的形式显示。对 `esi` 的引用返回该寄存器的内容，即一个内存地址。hexadecimal 值 `0x4000` 被从该内存地址中减去，结果加载到 `edi` 寄存器中。该寄存器的值随后被压栈。将值压栈的一个原因是为函数调用做准备。这通常使用 `call` 助记符，但也可以使用某种跳转指令。跳转用于将执行转移到不同的内存位置。

跳转指令有多种形式。有些指令是配合 `cmp`（比较）使用的，用于在寄存器值不为零时进行跳转。在查看反汇编时，你还会看到许多算术操作，包括 `add` 和 `sub`（减法）。你还会看到 `inc`，即递增的助记符，表示我们在加一。区别在于你不需要分多步取出值、加一、存储结果，再把结果移回原来的寄存器。

通过跟踪代码进行静态分析是耗时的，尤其是当你不想运行程序时。运行潜在的恶意软件样本是危险的。你可能会损坏系统上的文件，或者感染网络中的其他系统。如前所述，静态分析耗时且需要对不同操作码行为有扎实的理解。

#### Properties

除了查看程序文件内部，我们还可以查看与其相关的元数据。例如，编译日期和时间。一些数据不仅特定于可执行文件，而且适用于所有文件。获取文件属性可以显示创建、访问和修改的日期和时间。这可能会给你关于恶意软件以及系统上发生了什么的信息。当你查看可执行文件的属性时，会出现名为“Details”（详细信息）的选项卡。在可执行文件中，你可以看到产品名称、版权信息等。这在 [Figure 8.8](#c08.xhtml#c08-fig-0008) 中有所体现。
