
# 命令和控制
请记住，攻击者希望尽可能长时间地保持对系统的访问。毕竟，如果他们针对你的组织，你拥有他们想要的东西。无论是知识产权、客户信息、用户名和密码，还是信用卡数据，你都会继续创建他们想要的东西。没有意义在入侵后离开，浪费这个机会。这意味着他们需要对整个环境保持远程控制。在这一阶段，他们会在环境中的系统上设置远程访问。攻击者可能会利用常用协议（如超文本传输协议 HTTP）并通过在其受控服务器与你环境中的系统之间嵌入命令来滥用该协议。他们也可以滥用其他协议，如域名系统（DNS）或Internet控制消息协议（ICMP）。

# 数据外传
即使他们继续留在环境中，他们仍想将收集到的数据取出。这就是数据外传阶段。他们同样可能使用常用协议，因为这些协议不太可能被怀疑。目标始终是尽可能规避检测。即使使用常用协议，你也可以通过遵循框架提供的TTP（技术、战术和程序）来发现攻击者的存在。例如，如果攻击者通过DNS发送数据，消息的大小往往会异常大，因此查找这些异常大的消息可以让你在攻击者进行数据外传时将其捕获。

# 影响
这是攻击者可能决定“烧毁房子”的阶段。一些攻击者在得到他们想要的东西后，会在离开时一锤定音，摧毁一切。另一些攻击者在被发现时也会如此。当你试图将他们从你的网络和系统中赶出时，他们在离开的路上会尽可能多地破坏东西。这可能包括数据破坏、磁盘擦除、数据加密（这意味着勒索软件攻击属于此类），拒绝服务攻击或其他类似的破坏性行为。

文中提到的TTP（技术、战术和程序）在MITRE网站（https://attack.mitre.org/matrices/enterprise/）的矩阵中可找到，并且会定期更新，随着更多已知技术而更新。每个TTP都有相应的细节，MITRE会提供缓解措施，以防止攻击成功。你也可以获得关于如何判断攻击者是否使用该TTP的建议。

## 安全技术
安全程序必然需要某种技术来实现。企业内部可使用的技术解决方案数量不断增长。保护企业的最佳方式不再是仅在网络前部部署防火墙并认为自己已安全，即使这在过去曾被视为事实。今天，攻击向量与十年前有了巨大变化。当前的技术解决方案是多层的，并不完全专注于防止攻击。

当前的假设是，如果期望100%成功地拦截所有攻击，则防止攻击是不可能的。因此，检测至关重要。即使是检测解决方案也是多层的，因为网络有众多入口点。由于检测是被动的努力，它需要随后进行主动响应。这可以是 incident response（事件响应），而事件响应可能需要自动收集取证 artifacts（取证数据）。所有这些可能需要不同的技术解决方案。

### 防火墙
防火墙是传统的网络安全设备。仅仅说防火墙已部署并不能真正说明其作用，因为网络堆栈上存在多种类型的防火墙。防火墙最初的含义是用来限制火灾蔓延的墙体。你实施防火墙是为了将火灾限制在建筑的特定区域。汽车中的防火墙同样用于限制火灾，防止其蔓延到乘客舱。该术语在20世纪80年代末被用于描述早期用于保护网络的技术。

#### 数据包过滤器
在基本层面上，防火墙是数据包过滤器。许多设备提供数据包过滤功能，有时通过访问控制列表（ACL）实现。路由器和交换机通常具备数据包过滤能力。数据包过滤是根据协议、端口和地址来决定数据包的去向。源地址和目的地址都可以基于进行过滤。

数据包可以被丢弃，意味着它们不会转发到目的地，并且不会向发送方发送任何响应。它们也可以被拒绝，这意味着它们不会转发到目的地，但如果设备遵循协议规范，会向发送方发送ICMP错误消息，指示目的地不可达。这种做法既礼貌，又符合协议规范。但在系统安全方面，丢弃消息可能更合理。如果消息被丢弃，发送系统无法知道发生了什么，目标系统陷入“黑洞”状态。

当然，数据包也可以被接受。这可以是基于规则的做法，也可以是策略性的。数据包过滤器可能有一条策略规则，决定过滤器的行为。这意味着默认规则适用于所有流量，除非有例外。默认拒绝策略是最安全的实现方式，即除非明确允许，否则丢弃所有流量。你也可以采用默认接受策略，即所有流量默认放行，除非明确阻止。

如果你使用 Linux 系统，可能会接触到数据包过滤器。虽然大多数 Linux 发行版自带的主机防火墙功能更强大，但它也可以作为基本的数据包过滤器工作。你可以在 Linux 内核的 iptables 防火墙上为不同的链设置策略。例如，下面的命令会在 INPUT、OUTPUT 和 FORWARD 链上设置默认拒绝策略：

``` 
[iptables Policy Settings]
iptables -P INPUT DROP
iptables -P OUTPUT DROP
iptables -P FORWARD DROP
```

数据包过滤功能简单直接。虽然这些过滤器可以用于入站流量或限制内部用户访问特定端口或 IP 地址，但它们不擅长更复杂的过滤，例如允许响应内部发起的入站流量。为此，我们需要跟踪出站连接，因此需要比单纯的数据包过滤更强大的机制。

#### 状态检测
在最初的数据包过滤器出现后不久，便发展出状态检测防火墙。第一个状态防火墙出现在20世纪80年代末，与数据包过滤器同期问世。这些防火墙已经存在约三十年，但这并不意味着它们一直在持续使用。
