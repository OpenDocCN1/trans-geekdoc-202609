
除分段之外，还需要考虑网络地理。曾经，所有内容可能都在一家公司的网络上。但这已不再如此，因为有服务提供商可以提供计算资源。这使得应用架构的可能性变得非常广阔。即使是应用的构建方式也发生了改变。我们不再拥有必然运行应用的系统。云服务提供商 —  — 系统位于服务提供商的 premises 并以虚拟方式消费 —  — 正在改变应用的架构方式。

经典的应用架构是 n‑tier 设计模型。多年来，应用开发人员一直在使用这种设计。然而，这正在改变。面向服务的架构（SOA）将单体设计的概念拆分为独立的服务。这些服务之间相互交互。最终结果相同。不同之处在于数据的处理方式以及应用的构建方式。尤其是结合前文，数据库的考虑因素也在发生变化。

## n‑tier Application Design

n‑tier 设计是一种分层应用模型。在某些情况下，它也被称为模型‑视图‑控制器（MVC）设计，尽管这些多层结构中可能包含其他元素。这些层也被称为表示层、应用层、业务层和数据访问层。下图展示了该设计的示例：[Figure 14.2](#c14.xhtml#c14-fig-0002)。

Presentation 层（即视图）位于客户端，如图中所示的笔记本电脑。下一层是 Application 层，逻辑在此层实现。可编程功能居住在 Application 层。有时该层会进一步划分为 Application 与 Business Logic 层。

![FIGURE 14.2 Multitier application design](images/c14f002.png)

[**FIGURE 14.2**](#c14.xhtml#R_c14-fig-0002) Multitier application design

在四层模型中，Application 层与 Business Logic 层被分离，Application 层负责服务控制。简言之，Application 层决定适用哪些规则，并调用相应的业务逻辑规则。业务逻辑规则由业务需求决定，说明应用应如何处理提供的数据。业务逻辑正是应用的核心。其余部分仅负责输入输出的处理。Application 层（或 Application 与 Business Logic 层）相当于 MVC 设计中的控制器层。

应用服务器通常与语言绑定。应用服务器为应用提供向用户提供服务的框架，通常通过超文本传输协议（HTTP）实现。应用服务器甚至可能提供 Web 服务器的框架。Web 请求进入应用服务器，随后根据请求将请求路由到相应的应用代码。Java 是常用的应用服务器语言。此外，.NET 语言（如 Visual Basic 和 C#）也在应用服务器中使用，这些服务器随 Microsoft 的 Internet Information Server（IIS）一起提供。[Figure 14.3](#c14.xhtml#c14-fig-0003) 展示了在 Windows Server 上添加角色以提供 Web 服务器的过程。Windows Server 2022 已内置 .NET Framework，因此不再需要在 IIS 安装时单独安装它。

![FIGURE 14.3 IIS application server](images/c14f003.png)

[**FIGURE 14.3**](#c14.xhtml#R_c14-fig-0003) IIS application server

数据层是 MVC 设计中的模型。它负责数据的组织与连接方式。通常该元素是数据库。关系型数据库常作为 Web 应用的后端。关系型数据库有助于定义数据对象之间的关系，即通过定义这些对象之间的关联来构建数据模型。该定义（即模式）为应用提供了对数据模型的可视化视图。结构化查询语言（SQL）用于创建数据库及其表格，以及插入和检索数据。对数据库的操作通过所谓的查询（SQL 语句）来完成。

关系型数据库采用实体‑关系模型。实体例如表和字段。表是数据库中的组成部分，用于定义一组相关数据。可以把表中的列想象为电子表格的列，这些列描述表的组成部分，而每一行则是表中的数据实例。在关系型数据库中，一个表中的字段可以与另一个表中的字段建立关联。下图展示了一个简易的实体‑关系图，说明了数据库表之间的关联：[Figure 14.4](#c14.xhtml#c14-fig-0004)。这类图被称为 *entity‑relationship diagram*，用于展示数据库表之间的关系。

![FIGURE 14.4 Entity‑relationship diagram](images/c14f004.png)

[**FIGURE 14.4**](#c14.xhtml#R_c14-fig-0004) Entity‑relationship diagram

这些关联能够在不需要单一巨型表且重复数据的情况下，将关联数据保持在一起。例如，在[Figure 14.4](#c14.xhtml#c14-fig-0004)中可以看到有一个定义宠物的表，该表包含唯一标识字段、名称、性别和品种。随后有一个访问表，其中记录访问日期。由于每只宠物会有多次访问，需要一种方式将这两行数据关联起来。可以通过第三张表实现，在该表中加入其他两张表的关键标识字段。该表负责维护这两个数据结构之间的映射。实体‑关系图是一种思维模型，其实现形式即为多层架构中的数据层。

## Service‑Oriented Architecture

面向服务的架构（SOA）对应用的视角与传统方式不同。它不从端到端（用户到数据存储）思考应用，而是关注实现应用所需的各个功能。这些功能可以实现为微服务。应用的架构是这些服务之间的连接，用以实现最终用户或应用消费者所需的全部特性。这些服务通常是抽象的，即作为黑盒工作。使用服务的程序员可能并不了解其内部工作原理，只知道如何以有用的方式消费该服务。

这意味着通信协议已经得到明确定义。它们可能使用远程方法调用（RMI）、远程过程调用（RPC）或表示式状态转移（REST）等协议。这些现有的通信协议使得程序员无需自行创建新协议，即可在服务之间进行通信。服务通过库调用这些协议与其他服务交互，而无需自行实现全新的通信方式。
