
```yaml
services:
  web-fe:             <----- Service name. Containers will
  deploy:
    replicas: 1          <----- Deploy a single container for
    build:               <----- Build from the Dockerfile in
    command: python app.py <----- Execute this command when starting
    ports:
      target: 8080       <----- Map port in the container
      published: 5001 <----- ...to port 5001 on the Docker host
  networks:
    counter-net          <----- Attach containers to the "counter" network
  volumes:
    type: volume
    source: counter-vol <----- Mount the "counter-vol" volume
    target: /app         <----- ...to "/app" in the container
```

Let's step through it.

- **web-fe:** is the service’s name, and all containers created as part of this service will have “web-fe” in their names.
- **deploy.replicas: 1** tells Docker to deploy a single container for this service. You can specify a different number of replicas to deploy multiple identical containers for the service. However, this won’t work on Docker installations as you only have a single Docker host, and only one container can use port 5001 on the Docker Desktop host. You’ll learn how to deploy multiple replicas for this service in the **Deploying apps with Docker stacks** chapter.

- **build:** tells Docker to build the image for this service’s container from the Dockerfile in the current directory.
- **command: python app.py** is the command Docker will execute inside every container it creates for this service. **app.py** file must exist in the image, and the image must have Python installed. The Dockerfile takes care of both of these requirements.
- **ports:** is where you map network ports from the service’s containers to the Docker host. This example maps port 5001 inside the container.
- **networks:** tells Docker to attach this service’s containers to the **counter-net** network. The network should already exist or be defined in the **networks** top-level key.
- **volumes:** tells Docker to mount the **counter-vol** volume to the `/app` directory inside all of the service’s containers. The volume should already exist or be defined in the **volumes** top-level key.

In summary, Compose will instruct Docker to deploy a single container for the **web-fe** service. It will build a new image from the Dockerfile in the same directory and start the container from that image. When it starts, the container will have **web-fe** in its name and run the **python app.py** command. It will attach to the **counter-net** network, expose the web service on the host’s port 5001, and mount the counter-vol volume to /app. If you defined multiple replicas (containers) they would all be identical.

**Note:** You don't need to specify the `command: python app.py` option in the Compose file as it's already defined in the Dockerfile. However, I've shown it here so you know how it works. You can also use Compose to override instructions in Dockerfiles.
