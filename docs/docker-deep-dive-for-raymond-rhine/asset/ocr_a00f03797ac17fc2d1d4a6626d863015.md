You can also use the **docker service logs** command to inspect service logs. If you pass it the service name or ID, you'll get the logs for all service replicas. If you pass it a specific replica name or ID, you'll only get the logs for that replica.

The following example shows the logs for all replicas in the **ddd_web-fe** service.

| docker service logs ddd_web-fe ddd_web-fe.9.i23pu71kq12@node2 ddd_web-fe.5.z4otpnjrvc58@node2 <Snip> \ | * Serving Flask app 'app' | ddd_web-fe.6.novrixi5iuxy@node2 ddd_web-fe.6.novrixi5iuxy@node2 ddd_web-fe.6.novrixi5iuxy@node2 | * Debug mode: on * Debugger is active! * Debugger PIN: 127-233-15 |

You can follow logs (**--follow**), tail them and can sometimes get extra details (**--details**).

So far, you've used Docker commands to prove the stack is up and running. However, you can also test it with your browser.

Run a **docker stack services** command to discover the port the **web-fe** service is published on.
