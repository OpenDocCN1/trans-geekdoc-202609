

# 系统性创新应对AI挑战

为了克服挑战并缓解如[图 3.4](#chap3.xhtml#fig3-4)所示的AI风险，金融机构可采用全组织的系统性创新，在整体考量下实现AI行业带来的效益。单点技术创新仅能解决局部问题，而非组织层面的重大命题。一种可能的系统性方法如下：

*   为全组织制定清晰的AI战略（如“AI优先”）和数据资产战略，并夯实技术核心；
*   构建统一的数据基础（如数据中台或数据网格），并与技术池集成；
*   开发专门的AI风险管理与控制框架，明确界定AI或ML风险；指派专人负责AI模型验证、审计和管理；
*   建立灵活高效的AI开发与运营框架，例如以`MLOps`（`ML` + `DevOps`；见[第14章](#chap14.xhtml)）方式运营的AI中台，明确各角色在AI开发与运营中的职责；
*   使AI采纳更稳健、更普惠。例如，可将自动（辅助）编程技术或利用AI的自动进化技术引入`MLOps`。OpenAI与Github的近期试点项目`Copilot`，为自动编程时代打开了大门。^([12](#chap3.xhtml#rfn12))

## 3.6 趋势探讨

毫无疑问，强AI或通用AI仍处于起步阶段，我们必须解放思想，争取“百花齐放、百家争鸣”。对于弱AI，我们应毫不犹豫地大力开发和推广，拓展更多场景，将AI技术融入数字经济和智慧社会。

### 3.6.1 MLOps 与 AIOps 对比

`MLOps`和`AIOps`是两个不同的概念。前者将`DevOps`（见[第12章](#chap12.xhtml)）应用于ML生命周期，使整个生命周期易于管理和交付；后者则利用AI技术增强IT `DevOps`能力。详见[表 3.5](#chap3.xhtml#tab3-5)对比。我们将在[第14章](#chap14.xhtml)详细讨论`MLOps`。

根据Gartner定义，`AIOps`平台通过自动化和智能化，从大数据、现代ML及其他高级分析技术中获得主动、定制化和动态的洞察，直接或间接改善IT运维（如监控、维护、诊断和服务台），如[图 3.6](#chap3.xhtml#fig3-6)所示。

**表 3.5 MLOps 与 AIOps 对比**

| | **MLOps** | **AIOps** |
| --- | --- | --- |
| **主要职责** | 利用`DevOps`实现一定程度的自动化，标准化ML生命周期 | 利用AI技术实现IT运维和系统的自动化 |
| **主要收益** | 提升团队协作、效率与生产力；自动化并复现ML实验；降低ML风险与偏见等 | 自动化重复流程；轻松实现异常检测、预测性运维和根因分析/解决；支持数据驱动决策等 |
| **工具** | Azure ML, Amazon SageMaker, Kubeflow, MLflow, DataRobot, Databricks | Splunk, IBM Watson AIOps, ServiceNow, BMC Helix, AppDynamics, Dynatrace, Moogsoft |

传统IT是被动响应的，如同僵尸大军的战斗。只有问题发生时，我们才试图解决。最好的预期结果也是0:0平局。`AIOps`是一种主动方法，它能提前预测数步，快速生成相关洞察，并迅速采取行动预防同类问题及其蔓延，从而实现强有力的IT进攻。

除IT运维（可能也在`DevOps`框架下）外，`AIOps`还能支持服务台和信息安全团队的工作，同时服务于业务领导者和操作人员。

`AIOps`的第一层级是利用IT系统的物理与软件拓扑，结合AI技术聚合告警，简单地检测异常和例外、关联事件分组，并在同一时期减少误报。

下一层级是应用因果分析找出系统错误的根因。部分功能由`AIOps`工具提供，如`BMC`、`Moogsoft`、`Splunk`和`ELK`（`ElasticSearch`、`Logstash`、`Kibana`）。这通常用统计ML或图计算实现。可通过多种方法查看拓扑信息，找出拓扑中最可能发生重要事件的节点。然而，从因果分析（找出问题根因）到主动诊断（主动修复问题）仍存在巨大鸿沟，即概念构想与实际有效落地在近期内仍有差距。我们应制定循序渐进的计划并设定合理的切入目标，同时提升`AIOps`平台能力。在金融机构应用`AIOps`时，其他挑战还包括数据监管、ROI（投资回报率）成本考量、过多遗留IT系统供AI学习等。

根据Gartner预测，到2023年，约30%的大型企业将在其非遗留IT资产中采用`AIOps`平台和数字体验监测技术。特别是COVID-19大流行，使人们更广泛地认识到`AIOps`的必要性；IT运维中更多手工和例行工作将被自动化的`AIOps`取代。随着近期AI技术（如`NLP`、因果推理等）的进步，我们可期待更快的事件响应、增强的安全性，以及面向远程和自动化IT运维的预防性预后。

`AIOps`和`MLOps`实际上都暗示了AI工程化的一个重要趋势，这使AI在各领域的采纳更容易，对最终用户更便捷。

### 3.6.2 低代码/无代码与 AutoML

低代码通常是基于图形用户界面（`GUI`）的编程/开发方法，仅需极少人工编码即可加快应用交付。无代码更进一步，即开发过程几乎完全无需人工编码。

低代码/无代码平台通常构建于云架构（如`AWS`、`Microsoft Azure`、`GCP`）之上，具备像`Kubernetes`和`Docker`这样的自动弹性伸缩容器化能力。这些平台通过支持业务与IT紧密协作的快速解决方案构建，在一定程度上实现了应用开发的民主化。这些平台通常基于模型驱动概念，通过拖拽式界面开发端到端的企业级应用，便于与现有系统的定制和集成。通过向公民开发者屏蔽底层复杂性（如AI模型、数据库、`UX`、安全、集成等），平台能更快构建和交付“革命性”解决方案。值得注意的是，底层的`AutoML`（自动化ML）支持在无深厚数据科学知识的情况下构建高质量AI模型。因此，这些平台能激发AI创新、提升用户体验、推进数字化转型，并为应用带来更多个性化。

金融机构在考虑采纳这些平台时，必须考量成本与`ROI`（投资回报率）、基础设施、开发者资源、安全性等因素。平台必须与数据平台集成并建立合适的数据管道，以便无缝输入高质量数据。`DevOps`（`MLOps`）可能是平台的一部分，以实现快速交付。典型平台包括`Salesforce`、`Mendix`、`OutSystems`、`Microsoft Power Apps`、`Appian`、`ServiceNow`、`Google App Maker`等。这些平台已在金融机构的部分应用中使用。[表 3.6](#chap3.xhtml#tab3-6)列举了一些示例。
