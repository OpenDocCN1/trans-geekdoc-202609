
# One such framework for automatic sensitive data tracing and policy enforcement is the Data Capsule paradigm [[4]](#chap9.xhtml#rref4)

In this paradigm, the combination of data and associated policy form a capsule, and after the capsule is processed by an analysis program (e.g., data aggregation, cleaning, extraction, transformation, and Machine Learning model), the policy is automatically updated accordingly based on the set of data operations in the analysis program. The resulting updated policy (residual policy) is then combined with the output of the analysis program to form a new capsule. In this way, data privacy policies are encapsulated with the data from the very beginning and are automatically cascaded to the downstream data processing and model runs. `PrivGuard`, the data capsule manager, maintains the data capsule graph (data and analysis workflow), propagates privacy policies and metadata, and calculates residual policies on analysis programs. Even if the data are copied or transformed multiple times, `PrivGuard` can track all dependencies and automatically perform the policy actions (e.g., consent-based access, automatic notification, retrieval, modification, or deletion of subject data, automatic anonymization, declassification or release of data, etc.) on all copies. Although `PrivGuard` can be deployed alongside the existing data infrastructure (on Cloud or on-premises), on-Cloud deployment can enjoy the benefit of Cloud-distributed computing and metadata management services to process large data and metadata volumes at the enterprise scale.

## For sensitive data processing

In addition to the common privacy enhancement techniques such as anonymization, encryption, and differential privacy, two alternative privacy-preserving computing approaches are worth mentioning for the most critical sensitive data, especially when such data are both secretive and at the same time requiring high computational accuracy. In such situations, anonymization and differential privacy may not be fully protective, and they will also lead to loss of computational accuracy, while standard encryption may leave the encrypted data useless for computing.

### One such alternative is cryptographic computing

In which plaintext data is mapped (encrypted) into an encrypted space via homomorphic encryption. Computations (not the same numerical operations in the plaintext world) can be performed on the ciphertext data in the encrypted space, and then the result is mapped back (decrypted) to the plaintext space. In this way, even staff members performing the cryptographic computing do not need to see the plaintext input or the final plaintext output, ensuring both complete secret protection and high computational accuracy. `Google Private Join and Compute` [[5]](#chap9.xhtml#rref5) (open-source release June 2019) is a secure 2-party computation tool employing homomorphic encryption to help teams within and across organizations work together with confidential data sets. `HEAWS` [[6]](#chap9.xhtml#rref6) is an accelerator for homomorphic encryption on `AWS FPGA` (reprogrammable hardware devices that can implement any logic function) that can help configure the user's own hardware for optimal execution of cryptographic computing. `CrypTFlow` [[7]](#chap9.xhtml#rref7) is Microsoft's open-source system that converts `Tensorflow` and `ONNX` models into Secure Multi-party Computation (`MPC`) protocols for Machine Learning inference. Of course, cryptographic computing does not come for free. It can be highly compute intensive and even prohibitive (for large-scale deep neural network training, for example) with on-premises compute infrastructure, and this is where Cloud computing can come to the rescue, and indeed, distributed Cloud computing is better suited for cryptographic computing. Nonetheless, Cloud computing at its current state is not a panacea for cryptographic computing, as the Cloud cryptographic computing cost (with respect to compute time) may still be too overwhelming for Big Data problems.

### A more cost effective and efficient privacy-preserving computing approach is trusted execution environments (`TEE`) or secure enclaves

In an enclave approach, encrypted data are sent into the `TEE` from different sources (Cloud or on-premises partitions). Only the enclave can decrypt the data within a secure processor and perform plaintext calculations for data processing, analytics, and model training. As soon as any data leaves the secure processor, it will be encrypted before being released to memory. In addition to the use of single large `TEE`, there can be distributed `TEEs` to cope with distributed data storage and processing (a good solution for data residence compliance). While there are still vulnerabilities being discovered and remediated with `TEEs`, there have already been some industry applications with Cloud-based `TEE` solutions, such as `Google Confidential VM` [[8]](#chap9.xhtml#rref8), `Amazon Nitro Enclaves` [[9]](#chap9.xhtml#rref9), and `Azure Confidential Computing` [[10]](#chap9.xhtml#rref10).

### Other open-source secure computing solutions implementable on Cloud

Include `Oblivious Coopetitive Queries (OCQ)` [[11]](#chap9.xhtml#rref11), `Coopetitive XGBoost`, `HELEN` [[12]](#chap9.xhtml#rref12) and `Cerebro` [[13]](#chap9.xhtml#rref13), all from the `UC Berkeley RISE Lab`. `OCQ` is a general framework for coopetitive (collaborative + competitive) analytics based on hardware enclaves. It can allow organizations to leverage each other's confidential data for privacy-protected large-scale secure analytics without sharing the actual databases of any parties or intermediate results in the query execution. `Coopetitive XGBoost` is a secure enclave implementation of `XGBoost` (a popular Machine Learning algorithm) that allows parties to jointly develop Machine Learning models without sharing plaintext data. `HELEN` facilitates maliciously secure coopetitive learning with linear models, and `Cerebro` allows customizable compute policies and security policies to handle a variety of machine learning algorithms. Both `HELEN` and `Cerebro` are based on cryptographic computing.

Although many sensitive data identification, tracing, and processing tasks can also be performed within on-premises systems, Cloud implementation can make the underlying tools more accessible and execution of these solutions much more efficient and effective at large scale. Utilizing Cloud computing for sensitive data handling can help us to strike a better balance between privacy, efficiency, and data usability.

# 9.5 Strategy Considerations for Cloud Data Migration, Data Integration, and Managing Sensitive Data in the Cloud

Now that we have a high-level view of the features of Cloud data integration services and related technologies, we can discuss some implications to building and executing a sound and efficient strategy for Cloud data migration, data integration, and sensitive data management. Although the discussion here focuses only on the handling of data in the Cloud, firms should take into account other considerations and requirements related to infrastructure migration, application migration, business process migration, and compliance when developing an overall Cloud migration strategy.

While Cloud platforms provide convenient services to ingest data from various sources both on-premises and from other Cloud platforms, data onboarding to the Cloud is more than just data ingestion and needs to be carefully planned and carried out. Before any data migration, firms need to establish proper Cloud data governance frameworks, which should cover policies and procedures, roles and responsibilities, data cataloging, data usage, data security, data privacy, and data integrity.
