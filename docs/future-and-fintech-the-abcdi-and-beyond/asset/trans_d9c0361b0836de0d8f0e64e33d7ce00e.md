### 10.2.2 安全与隐私

安全与隐私是当前物联网生态系统中的两大主要问题 [[9](#chap10.xhtml#rref9), [10](#chap10.xhtml#rref10)]。据报道，2017 年有超过 50 万台物联网设备被攻破。物联网安全目标列于 [表 10.3](#chap10.xhtml#tab10-3) [[19](#chap10.xhtml#rref19)]。例如，认证通常与对象或服务注册相关，即建立连接的第一步；而授权意味着用户需要权限才能使用服务。

隐私在概念上不同于安全。例如，如果一个存储无用数据的物联网设备被盗或被攻破，这是一个安全问题，但不是隐私问题，因为它不包含任何机密内容。一些隐私设计的通用目标列于 [表 10.4](#chap10.xhtml#tab10-4)。智能家居的隐私本质上与个人活动、位置和时间戳相关 [[18](#chap10.xhtml#rref18)]。从面向数据的角度来看，它包含感知数据的聚合和传输（例如个人的私人数据）；从面向上下文的角度来看，它指与位置和时间相关的机制，即保护用户生成数据的位置和时间免遭不必要的暴露。我们应当注意，最终用户和服务提供商通常持有不同的观点。

**表 10.3.** 物联网安全目标

| **目标** | **说明** |
| --- | --- |
| 认证或真实性 | 验证所提供凭证或属性的真实性或来源的行为。 |
| 授权 | 指定对相关资源的访问权限/许可的过程。例如，资源可能是包含个人信息的数据表。 |
| 问责制 | 追溯相关资源历史活动的能力。 |
| 机密性 | 限制对相关资源访问的行为或规则。例如，确保数据仅可由预期目的地读取。 |
| 完整性 | 保证相关资源准确、完整且可信。 |
| 可用性或可访问性 | 为授权人员提供可靠、稳健的相关资源访问。 |
| 不可抵赖性 | 对特定合同或交易承担完全义务的含义。 |
| 新鲜性 | 保持数据和密钥新鲜度的能力。 |

由于受限的计算和存储资源，大多数物联网设备无法使用全栈实现，这增加了实现高等级安全和隐私保护的难度。[表 10.5](#chap10.xhtml#tab10-5) 列出了维持高安全标准面临的一些挑战。例如，许多组织在推广各自的标准，使得制定通用标准变得困难。

**表 10.4.** 隐私目标

| **目标** | **说明** |
| --- | --- |
| 透明性 | 在数据访问和处理过程中，对人员和活动理解的一致性，例如访问时长、操作员、权限等。 |
| 用户主导 | 用户对自己数据的完全控制，即对其在网络中共享数据的全面且细粒度的访问控制。 |
| 匿名性 | 在物联网应用中不披露用户身份。 |
| 假名性 | 匿名性（隐私）与问责制之间的折衷。个人行为与假名或随机标识符相关，而非真实身份。 |
| 不可关联性 | 假名性的一种程度，即同一个人的具体行为不应相互关联，从而在一定程度上防止物联网中的个人画像分析。 |
| 不可观测性 | 资源或服务的访问历史不允许被未授权人员观测的能力，即未授权用户和/或主体无法判断某操作是否正在执行。 |
| 去中心化 | P2P 共享，即网络中的每个节点直接与其他节点共享数据，无需任何第三方或可信实体的干预。 |

### 10.2.3 信任评估

系统设计完成后，我们应评估其是否可信 [[11](#chap10.xhtml#rref11), [12](#chap10.xhtml#rref12)]。信任被定义为建立可靠性、可信度和设备间连接性的关键属性，以确保服务和应用的安全与防护。[表 10.6](#chap10.xhtml#tab10-6) 列举了一些评估指标。例如，系统应总体上具备鲁棒性和自适应性。

### 10.3 金融服务

金融服务涵盖多个方面，例如：发起和接收支付（国内及跨境）；储蓄、消费或稍后投资；当前借贷以消费或投资；管理与收入、储蓄和交易相关的风险；以及就上述所有方面提供咨询等。对于消费银行而言，其日常业务包括储蓄账户、活期账户、抵押贷款、贷款、信用卡和借记卡。部分服务可通过网上银行或手机银行办理。

**表 10.5.** 物联网安全挑战

| **项目** | **说明** |
| --- | --- |
| 受限资源 | 特别是有限的计算和内存资源对系统设计施加了约束。 |
| 异构设备 | 由于物联网的异构本质，不同设备间采取不同的安全措施。 |
| QoS | 允许差异化交付并确保服务质量。 |
| 信任管理 | 保持隐私机密。 |
| 轻量级认证/授权 | 在资源受限设备中的实现。 |
| 密钥与身份管理 | 不存在绝对的保险箱。应应用多重加密规则。 |
