
# 区块链安全风险

哈希和用于交易签名的公钥加密是构成区块链基础的两种密码学原语。大多数区块链使用的哈希算法是 `SHA-256`，使用 `Grover’s approach` 在量子计算机上破解需要 `2^128` 次操作。虽然这使得 `SHA-256` 对量子攻击具有鲁棒性，但可能使用的公钥加密算法不具备此特性。当足够强大的量子计算机被制造出来时，椭圆曲线数字签名算法（`ECDSA`）将被攻破，使得几乎所有区块链都变得脆弱。尽管区块链在管理和存储私人数据方面提供了许多优势，但它也存在一些缺点。由于信息以公共账本的形式维护，区块链在隐私和保密性方面仍然存在问题。基于匿名化或加密的各种技术可用于保护信息的保密性。交易隐私是区块链数据隐私的一个众所周知的问题。许多公司和个人担心交易和 `SC` 操作在网络上传播后可能被追踪。区块链技术最具挑战性的困难之一是交易隐私。因此，一些技术如 `mixing services` 和 `zero-knowledge proof` 已被提出以增强区块链匿名性。在使用 `mixing services` 时，将资金从 `N` 个输入地址转移到 `M` 个输出地址，目标是提供交易匿名性，同时防止消费者持续使用同一地址。实践中此类技术的例子包括 `Mixcoin`，它还能够检测不诚实的交易行为，以及通过第三方洗牌输出地址的 `Coinjoin` 或 `CoinShuffle` \[[16](#ch3.xhtml#ref3_16)\]。

## 钱包风险

加密货币并不像传统（法币）货币（如美元或英镑）那样存在，实际的硬币或纸币被保存在口袋或钱包中。对于加密货币，私钥或公钥，或两者结合，保护这些资产。私钥使用 `Base58` 编码以创建 `Wallet Import Format` 私钥，这是一种使私钥更易于复制的方法。`SHA-256` 和 `RIPEMD-160` 哈希算法用于对公钥进行哈希处理。`RIPEMD` 是因为它产生的哈希最短，其唯一性仍然得到充分保证。这使得比特币地址更短。比特币使用公钥的哈希可能由于 `RIPEMD` 和 `ECDSA`（公钥签名算法）之间的交互而导致独特特征。然而，许多攻击方法有可能使这种加密资产更脆弱。硬件钱包是一个相对较新的概念，通过将私钥离线存储在 `cold storage` 中来增强用户比特币持有的安全性。硬件钱包执行交易签名，如果没有漏洞，交易就会安全地保存在用户的钱包中。攻击可能将特定网络中的特定节点集群隔离。攻击者可以重新路由并禁用目标节点集与其他节点之间的连接。侧信道分析和采用各种测试框架可以揭示各种问题，从不安全的网络界面，到缺乏传输加密，到缺乏固件更新或缺乏数据泄露测试 \[[17](#ch3.xhtml#ref3_17)\]。

## 共识风险

共识算法是区块链技术的基石。根据用于创建它的平台组织，区块链技术中已采用多种用于交易验证的共识方法。这些算法是确保系统正确运行的指南 \[[18](#ch3.xhtml#ref3_18)\]。设计和建模错误会导致软件故障，这类错误可能导致崩溃和遗漏。遗漏故障是一种模型，定义了特定时间单位 `T`，所有消息必须在 `T` 时间后交付。如果在此时间范围内未到达，则假定从未到达。它代表网络中可能出现的问题。然而，遗漏故障是由传输问题引起的，例如发射器故障、碰撞或缓冲区溢出。

[表3.2](#ch3.xhtml#table3_2) 显示了各种共识算法及其属性的比较。对于每种共识方法，必须考虑的三个基本性能因素是延迟、吞吐量和带宽。`Sybil attack`，即单个攻击者通过设置各种IP地址、虚拟机和用户身份来控制多个网络节点，对 `Ripple` 尤其危险；`Ripple` 是一种基于区块链的数字支付网络和协议，拥有自己的加密货币 `XRP`。而不是挖矿区块链，`Ripple` 依赖于通过一组银行拥有的服务器实现的共识机制）\[[19](#ch3.xhtml#ref3_19), [20](#ch3.xhtml#ref3_20)\]。

## 安全故障

区块链技术有能力改变组织开展业务的方式；但就像任何新技术一样，它也带来了一些风险。`DAO`（也在 [第2章](#ch2.xhtml) 中讨论过）是一个基于以太坊区块链的管理数字资产的平台。2016年5月15日，黑客在一次交易中提取了约价值6000万美元的 `ETH` \[[21](#ch3.xhtml#ref3_21)\]。
