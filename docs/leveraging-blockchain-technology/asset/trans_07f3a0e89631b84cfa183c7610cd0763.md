
## 共识层
*共识层* 是区块链平台功能不可或缺的组成部分，无论使用的是哪种特定的区块链技术（例如，Ethereum、Hyperledger）。该层在区块链中承担着排序、验证和确保区块正确顺序的核心作用 \[[10](#ch1.xhtml#ref1_10)\]。交易认证是区块链中最关键的功能之一，由共识层执行。没有这一层，系统将无法有效运行，因为交易验证将缺乏。
共识层执行协议，该协议要求特定数量的节点验证单笔交易。这种去中心化的方法涉及多个节点独立处理每笔交易，所有节点最终就将其接受为合法达成一致结论。这种分布式特性，即共识机制，保持了区块链的去中心化特征。虽然各种节点同时创建多个区块可能导致区块链暂时分叉，但共识层确保此类冲突得到解决，确保单一链区块更新占优 \[[9](#ch1.xhtml#ref1_9)\]。
此外，数字签名不仅保护数据，还保护发送者或所有者的身份。签名对签署人具有法律约束力，增强了交易的整体安全性，并确保与签名关联的身份无可否认 \[[10](#ch1.xhtml#ref1_10)\]。

## 应用和展示层
*应用和展示层* 在区块链架构中包含一系列关键组件，包括智能合约、链码和去中心化应用（DApps）。在应用层协议层面进一步细分。
在与区块链网络用户交互的最前沿；并且，如前所述，应用层包括智能合约、链码和 DApps。该层扩展到各种应用层协议。它是通过用户界面、框架、应用程序编程接口（APIs）和脚本使终端用户与区块链网络交互的软件层。支持这些应用的后端技术植根于区块链网络，交互通过 API 促进。值得注意的是，应用程序指导执行层。
另一方面，展示层关注用户界面，塑造终端用户与区块链网络交互的方式。它涉及区块链应用程序的视觉和图形方面，增强用户体验和可访问性。

## 执行层
*执行层* 与应用层不同，包含链码、智能合约和底层逻辑。当交易从应用层遍历到执行层时，批准和执行发生在语义层。应用程序通过发出命令并维护区块链的确定性来指导执行层。该层在将用户发起的高级交易翻译成区块链网络中的可执行代码方面发挥着关键作用（[表1.3](#ch1.xhtml#table1_3)） \[[10](#ch1.xhtml#ref1_10)\]。

### 区块链数据类型和数据结构
*数据类型* 由规定变量可能包含的值类型的分类规则定义。它还规定了可以在该值上执行而不出现错误的数学、逻辑或关系操作 \[[11](#ch1.xhtml#ref1_11)\]。区块链领域正在进行的研究旨在开发一种数据类型，在执行超越传统标准数据类型能力的高精度计算的同时最小化内存使用。
*交易数据模型* 概述了交易在网络中如何组织和记录。下面是区块链中交易数据模型的典型组件：
* `Input` 指的是交易的来源，例如发送资金的钱包或地址。
* `Output` 表示交易的去向，例如接收资金的钱包或地址。
* `Amount` 表示交易的值，通常以区块链的原生货币计价。
* `Transaction ID` 是网络分配给交易的唯一标识符，便于跟踪和验证。
* `Timestamp` 显示交易发起的日期和时间。
费用是指发送者支付的交易成本，以激励网络验证者将交易纳入区块链。
* `digital signature` 是由发送者创建的交易授权证明。
了解这些组件可以深入了解交易的结构，并确保区块链网络的完整性和安全性 \[[12](#ch1.xhtml#ref1_12)\]。

### 交易数据模型中的扩展组件
除了前面概述的核心组件外，某些区块链网络可能包含额外的字段，例如元数据或智能合约代码。这些补充元素为交易提供增强的上下文或功能。全面的交易数据模型对区块链运营至关重要，提供记录和验证交易的标准化格式。这确保了网络的整体完整性和安全性 \[[12](#ch1.xhtml#ref1_12)\]。
一种替代交易模型，被称为 *基于账户的模型*，在以太坊中被显著采用。在此模型中，资产表示为账户中的余额，类似于传统银行账户。基于账户的模型使用两种不同的账户类型：
* `Private Key-Controlled User Account`，也称为外部拥有账户（`EOA`），由用户通过私钥直接控制。每个账户地址均从可共享于区块链网络的公钥派生。对这些账户的访问由私钥保护，通常被视为 PIN，必须保密且仅为账户所有者所知 \[[13](#ch1.xhtml#ref1_13)\]。
* 另一方面，`Contract Code-Controlled User Account` 依赖智能合约代码来管理其操作。智能合约本质上是一组特定代码，旨在在满足预定条件时执行 \[[14](#ch1.xhtml#ref1_14)\]。交易不能直接从这些账户发起。相反，当交易发送到合约代码控制账户时，账户会触发其他合约中的各种功能。
