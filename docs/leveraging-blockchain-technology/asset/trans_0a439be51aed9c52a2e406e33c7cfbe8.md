
# 区块链技术与安全概述

## 历史发展与市场采用

区块链技术始于1991年，最初仅用于金融（加密货币）交易。2014年，探索了其他选项，最近的进步和潜力在其他金融和跨组织领域得以体现。在过去几年中，区块链的使用在各个行业中已呈倍数增长，用于各种部署和用例。目前，企业使用区块链技术管理分布式数据库、数字交易、网络安全和医疗保健，为客户创建基于区块链的解决方案。如前几章所述，使用区块链技术的主要优势在于其密码学、去中心化和基于共识的特性保证了交易安全。根据最近的一份报告，预计到2024年全球区块链市场将增长至200亿美元。目前，69%的银行正在研究各种区块链技术选项，以提高服务的安全性、一致性和简易性。虽然区块链的采用为全球企业带来了诸多益处，但该技术也吸引了大量想要入侵系统并对公司造成损害的攻击者。在网络攻击和入侵尝试的领域，区块链安全已成为帮助组织和企业保障运营的关键程序组成部分 \[[1](#ch5.xhtml#ref5_1)\]。

## 数据结构与密码学基础

区块链技术创建的数据结构包含内置安全功能。这些结构建立在密码学、去中心化和共识机制之上，保证了交易的完整性。数据在区块链或 `Distributed Ledger Technologies (DLT)` 中以区块组织。每个区块包含一笔交易或一组交易。在密码学链中，每个新区块都与之前的所有区块相连，使得篡改区块几乎不可能。共识机制验证并接受区块中包含的每笔交易，确保每笔交易准确无误 \[[2](#ch5.xhtml#ref5_2)\]。

## 区块链中的 CIA 三要素

区块链技术依赖于 CIA 支柱：保密性、完整性和可用性。保密性提供多种能力以确保用户的匿名性。公钥和私钥是用户与其数据之间的唯一链接。某些区块链网络使用非交互式零知识证明来最大化用户的保密性。完整性是指链上每个区块都使用密码学哈希函数与其他区块相连。一旦交易被记录在区块链上，就无法修改或删除。任何更改或修改都必须作为新交易处理。可用性是指区块链上的众多节点即使在某些节点不可用时也能确保弹性。即使存在被攻破的节点，正确的区块链仍可供其他用户访问。这是因为网络中的每个节点都拥有分布式账本的副本 \[[3](#ch5.xhtml#ref5_3)\]。

## OWASP 与区块链安全态势

`Open Web Application Security Project (OWASP)` 是一个致力于提升软件安全的非营利组织。OWASP 项目旨在通过向开发者提供信息来改进安全，包括常见漏洞的详细列表以及资源，例如测试工具和易受攻击的应用，以帮助开发者了解编写代码中可能存在的各种安全风险。区块链技术正迅速流行，但目前与 `OWASP` 列表类似的相关工具或安全标准并不多。`Decentralized Application Security Project (DASP)` 制作的类似十大列表专注于智能合约漏洞，并未考虑整个区块链生态系统 \[[4](#ch5.xhtml#ref5_4)\]。

## OWASP 十大风险 2017

2017年，OWASP 发布了网络应用漏洞十大风险列表，其中包含十个影响应用安全的常见漏洞。常见漏洞包括 `Injection`、`Broken Authentication`、`Sensitive Data Exposure`、`XML External Entities (XXE)`、`Broken Access Control`、`Security Misconfiguration, Cross-Site Scripting (XSS)`、`Insecure Deserialization`、`Using Components with Known Vulnerabilities`、`and Insufficient Logging and Monitoring`。该列表用于网络应用，但许多漏洞也与区块链技术相关 \[[4](#ch5.xhtml#ref5_4)\]。

## OWASP 十大风险 2021

OWASP 十大风险列表于2021年更新，常见漏洞有所变化，仍影响应用安全。漏洞列表现包括破坏访问控制、加密失败、注入、不安全设计、安全配置错误、易受攻击且过时的组件、身份识别与身份验证失败、软件和数据完整性失败、安全日志记录和监控失败以及服务器端请求伪造（SSRF） \[[5](#ch5.xhtml#ref5_5)\]，如 [表 5.1](#ch5.xhtml#table5_1) 所示。

[表 5.1 2021 OWASP 十大漏洞](#ch5.xhtml#R_table5_1)

| 漏洞 || 描述 |
| --- | --- |
| A01 破坏访问控制 || 通过执行政策和法规，访问控制确保用户在指定权限范围内。故障通常由于未经授权的访问、信息泄露、数据修改或删除，或在用户范围之外执行业务操作而导致 \[[6](#ch5.xhtml#ref5_6)\]。 |
| --- | --- |
| A02 加密失败 || 识别传输中和静态数据的保护需求至关重要。密码、信用卡、健康记录和个人信息需要额外保护，特别是如果数据受隐私法如 `General Data Protection Regulation (GDPR)` 或规则如 `PCI Data Security Standard (PCI DSS)` 覆盖 \[[7](#ch5.xhtml#ref5_7)\]。 |
| A03 注入 || 如果应用程序未检查、过滤或清理用户提供的数据，则应用程序会暴露于攻击。对象关系映射（ORM）搜索参数与恶意数据结合使用以检索更敏感的记录。动态查询和命令包含有害数据结构 \[[8](#ch5.xhtml#ref5_8)\]。 |
| A04 不安全设计 || 缺失或无效的控制设计是指一系列被称为不安全设计的缺陷。正确实现的安全设计仍可能存在可被利用的缺陷。然而，完美的实现无法修复不安全的设计，因为开发者尚未创建并实施必要的保护措施以抵御攻击 \[[9](#ch5.xhtml#ref5_9)\]。 |
| A05 安全配置错误 || 如果缺少适当的安全加固、权限未正确配置、不必要的功能已安装以及最新的安全功能被禁用或未安全配置，则应用程序可能存在漏洞 \[[10](#ch5.xhtml#ref5_10)\]。 |
| A06 易受攻击且过时的组件 || 如果客户端和服务器端的组件版本未知、软件未更新且不受支持，以及平台和框架未定期修复和升级，则系统存在漏洞 \[[11](#ch5.xhtml#ref5_11)\]。 |
| A07 身份识别与身份验证失败 || 确认用户身份、验证用户信息以及监控和管理会话对于防范与身份验证相关的威胁至关重要。身份验证弱点源于暴力破解、类似凭证填充的自动化攻击、弱密码以及无效的多因素身份验证 \[[12](#ch5.xhtml#ref5_12)\]。 |
| A08 软件和数据完整性失败 || 未能防止完整性违规的代码和架构与软件和数据完整性失败相关。例如，自动更新功能构成威胁，因为更新在未经充分验证的情况下下载并应用于受信任的应用程序 \[[13](#ch5.xhtml#ref5_13)\]。 |
