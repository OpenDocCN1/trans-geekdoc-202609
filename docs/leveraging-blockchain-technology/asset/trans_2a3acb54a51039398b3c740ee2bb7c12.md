
## 公共区块链

公共区块链因其在开放和去中心化网络上的运行而成为主要类型之一。在此系统中，所有交易都记录在公开且透明、任何人均可访问的公共账本上。与私有区块链不同，公共区块链不受限制，允许建立分布式账本，用户无需任何许可即可访问信息。公共区块链中常用的共识机制包括工作量证明和权益证明，确保参与者对交易的验证和达成一致。

在公共区块链中，历史和当代的交易记录对用户公开可供验证。这种类型的区块链在挖矿操作和加密货币交易中发挥重要作用。公共区块链的著名示例包括 `Bitcoin` 和 `Ethereum`，它们被广泛用于各种交易。公共区块链的关键优势在于其去中心化特性，使得任何单一实体或团体控制网络变得困难。这种固有的去中心化增强了安全性以及对审查和其他形式的攻击的抵抗力。

虽然公共区块链传统上与加密货币交易相关联，但其应用正在扩展。智能合约、去中心化应用（dApps）和供应链管理是公共区块链的新兴用途。公共区块链的显著特征包括高度安全和隐私、开放灵活的环境、匿名交易、缺乏严格监管以及完全透明 \[[2](#ch1.xhtml#ref1_2), [3](#ch1.xhtml#ref1_3)\]。

### 混合区块链

混合区块链代表了公共区块链和私有区块链各自优势的融合。这种类型的区块链结合了公共和私有元素，将公共区块链的透明性和去中心化与私有区块链受控的安全特性相结合。

在混合区块链的公共方面，交易记录在去中心化账本上，反映了传统公共区块链的特征。这个透明且不可变的账本允许任何人参与网络并查看交易。相反，混合区块链的私有方面引入了更受控和更安全的环境。对私有区块链的访问仅限于有限的参与者群体，这些参与者经过精心挑选并获准加入网络。这种受限访问增强了对参与者纳入以及区块链上记录的交易的控制 \[[3](#ch1.xhtml#ref1_3), [4](#ch1.xhtml#ref1_4)\]。

混合区块链的架构允许与公共区块链无缝集成。交易通常首先在网络内部进行验证，用户随后可以将其发布到开放区块链上以供验证。这种双层方法通过采用增强的哈希并使用额外的节点进行确认，有助于提高整个区块链网络的安全性和透明度 \[[5](#ch1.xhtml#ref1_5)\]。

### 联盟区块链

联盟区块链代表了一种半去中心化的区块链技术形式，由一组组织或实体共同拥有和运营。与允许开放参与的公共区块链不同，联盟区块链是许可制的，需要联盟批准个人或组织才能加入网络。

在联盟区块链中，参与组织共同分担网络维护和交易验证的责任。这种结构与公共区块链相比在保留去中心化和透明度优势的同时提供了更大的控制和隐私。联盟区块链在协作和多组织间信息共享至关重要的行业中具有实际用途，例如供应链管理、金融和医疗保健。

通过利用联盟区块链，这些组织可以在无需依赖中介或第三方验证者的情况下安全透明地共享数据。联盟区块链在公共区块链的去中心化和透明特性与私有区块链的受控和私有特性之间取得了平衡。这使得它们成为寻求利用区块链技术能力同时满足特定隐私和控制要求的组织的首选 \[[3](#ch1.xhtml#ref1_3), [5](#ch1.xhtml#ref1_5)\]。

`Ripple`，一种知名的加密货币，是许可型区块链的例证。与作为无许可网络运行的 Bitcoin 和 Ethereum 不同，Ripple 为其网络参与者采用基于许可的框架。

与无许可区块链（如 Bitcoin 和 Ethereum）相关的缺点主要集中在性能问题上。无许可区块链面临的关键挑战是共识过程所需的庞大能源和计算能力。共识机制的资源密集型特性构成了重大障碍。

必须澄清，“公共”与“私有”区块链之间的区别与这些术语的传统理解并不一致。在区块链的背景下，无许可区块链被视为公共，而许可区块链被视为私有。然而，在此上下文中，“公共”的定义是指可供使用而非可供读取交易历史。需要注意的是，“私有区块链”可以“公开查看”而不“公开使用”。这种区别凸显了区块链可访问性和使用的细微差别（[表 1.2](#ch1.xhtml#table1_2)）\[[7](#ch1.xhtml#ref1_7), [8](#ch1.xhtml#ref1_8)\]。

[表 1.2 许可型与非许可型区块链](#ch1.xhtml#R_table1_2)

| 非许可型区块链 || 许可型区块链 |
| --- | --- |
| 开放网络配置。任何人都可以加入网络。 || 关闭网络配置。只有获许可的成员才能加入并交互。 |
| --- | --- |
| 也称为公有。 || 也称为私有。 |
| 提供交易透明度。 || 根据组织控制交易透明度。 |
| 可使用开源工具开发。 || 可由私人实体开发。 |
| 大多匿名。 || 不匿名。 |
| 隐私取决于技术限制。 || 隐私取决于治理决策。 |
| 由于无需许可，安全性较低。 || 由于需要访问许可，安全性更高。 |
| 支持点对点架构。 || 支持企业对企业架构。 |
| 可用于数字交易、捐赠和众筹。 || 可用于供应链追踪系统、身份验证和理赔结算。 |

### 区块链技术层

在区块链技术的领域中，信息安全地存储在分布式账本上。该账本受预定协议管辖，依赖于涉及网络中多个节点的共识机制来验证交易数据。区块链技术的分层设计促进了交易认证 \[[9](#ch1.xhtml#ref1_9)\]。
