

# Chapter Objectives

This chapter aims to lay the foundation for you to confidently understand and use the Python packages that implement the algorithms described here. The chapter characterizes the nature of the input data set as: a column vector of outcomes to be predicted, and a table of attributes for prediction. [Chapter 3](#c03.xhtml) demonstrated that predictive models need to adjust their complexity to achieve optimal performance for a given problem complexity and data set size. [Chapter 3](#c03.xhtml) also showed some ways to introduce tuning parameters into linear regression. This chapter builds on that context by introducing several minimization problems in which a tunable coefficient penalty is added to the error penalty of least squares regression. As demonstrated, this tunable penalty on the magnitude of linear coefficients suppresses coefficients to a greater or lesser extent, thereby adding complexity adjustment. You saw how to use error on out-of-sample data to tune the complexity of the generated model to achieve optimal performance.

The chapter describes the workings of two modern algorithms for solving penalized regression minimization problems, and the Python code implementing the main features of these algorithms, so that you have concrete instances of the algorithmic cores to make the workings clearer. The ordinary regression problem (numeric features and numeric target) serves as the exemplar for in-depth coverage of the algorithms. The chapter shows several extensions to broaden use cases to cover binary classification problems, multi-class classification problems, problems with non-linear relationships between attributes and outcomes, and problems containing non-numeric features.

[Chapter 5](#c05.xhtml) will use the Python packages implementing these algorithms to run a series of examples chosen to exercise a variety of different problem characteristics to solidify these concepts. Based on what you learn in this chapter, the various parameters and methods in the Python packages will become easy to understand.

# Chapter 5 Building Predictive Models with Penalized Linear Methods

[Chapter 2](#c02.xhtml) looked at many different data sets with the aim of understanding the data sets, the relationships between the various attributes and the labels, and the nature of the problems faced. This chapter selects those data sets again to demonstrate, through case studies, the process of building predictive models using the penalized linear methods you saw in [Chapter 4](#c04.xhtml) "Penalized Linear Regression". Typically, model building will be divided into two or more parts.

You may recall from [Chapter 4](#c04.xhtml) that building a model using penalized linear regression involves two steps. The first step is to run cross-validation to determine the best achievable out-of-sample performance and identify the model that achieves that performance. Determining achievable performance contains the hard design work, and in many examples in this chapter, only this step is shown. The second step is to train on the entire data set to depict the coefficient paths. The purpose of training on the entire data set is to obtain the best estimate of the model coefficients. But this does not change your estimate of error, which is the measure of performance.

This chapter exercises many different types of problems: regression problems, classification problems, problems with categorical attributes, and problems where the label has a non-linear dependence on the attributes. It examines basis expansions to see if they can improve predictive performance. In each case, the goal is to complete the steps you need to take to obtain a deployable linear model, and to consider some alternative paths to ensure you have squeezed out all potential performance.

## Python Packages for Penalized Linear Regression

The examples in [Chapter 4](#c04.xhtml) used Python versions of the training algorithms involved: `LARS` and Coordinate Descent with `ElasticNet` penalty. The purpose of using Python code in [Chapter 4](#c04.xhtml) was to show how the algorithms work to deepen your understanding of them. Fortunately, you do not have to rewrite these algorithms every time you want to use them.

`scikit-learn` has packages implementing `Lasso`, `LARS`, and `ElasticNet` regression. There are several advantages to using these packages. One is reducing the lines of code you need to write and debug. Another huge advantage is that they are much faster than the code in [Chapter 4](#c04.xhtml). The `scikit-learn` packages leverage practices such as not computing correlations for unused attributes to reduce computation. You will find they execute very fast when running these packages.

You can find the packages used in this chapter in `sklearn.linear_model`. The link `http://scikit-learn.org/stable/modules/classes.html#module-sklearn.linear_model` lists the models used here. Note that several models have two forms. For example, there is both `linear_model.ElasticNet` and `linear_model.ElasticNetCV`. These two models correspond to the two tasks discussed at the beginning of this chapter. The Python package `linear_model.ElasticNet` is used to compute coefficient paths on the entire data set, while `linear_model.ElasticNetCV` performs cross-validation runs to generate out-of-sample performance estimates. Having both forms is very convenient.

These two versions basically use the same input objects (two NumPy arrays—one attribute array, one label array). In some cases, you cannot use the cross-validation version because you need very specific control over the contents of the training and test sets for each fold:

*   If your problem has a categorical attribute with a value that occurs very infrequently, you may need to control sampling so that attribute is evenly distributed across folds.
*   If you want an error metric other than the *Mean Squared Error* (`MSE`) provided by the CV packages, you may also need access to individual fold data to compile error statistics tailored to your problem. You might prefer *Mean Absolute Error* (`MAE`) because it better matches the penalty you will pay for errors in the real problem.
*   Another example needing per-fold access to error statistics is using linear regression to solve classification problems. As described in [Chapter 3](#c03.xhtml) "Building Predictive Models: Balancing Performance, Complexity, and Big Data", standard error metrics for classification problems include misclassification error rate or *Area Under the ROC Curve* (`AUC`). You will see this specifically in the "Rocks vs. Mines" and "Glass Classification" case studies in this chapter.
