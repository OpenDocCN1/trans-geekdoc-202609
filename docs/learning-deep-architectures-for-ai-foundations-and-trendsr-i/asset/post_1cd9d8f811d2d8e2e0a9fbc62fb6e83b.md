# 3
Local vs Non-Local Generalization

### 3.1 The Limits of Matching Local Templates

How a learning algorithm compactly represent a "complicated" function of the input, i.e., one that has many more variations than the number of available training examples? This question is both connected to the depth question and the question of locality of estimators. We argue that local estimators are inappropriate to learn highly varying functions, even though they can potentially be represented efficiently with deep architectures. An estimator that is local in input space obtains good generalization for a new input x by mostly exploiting training examples in the neighborhood of x. For example, the k neighbors of the test point x, among the training examples, vote for the prediction at x. Local estimators implicitly or explicitly partition the input space in regions (possibly in a soft than hard way) and require different parameters or degrees of freedom to account for the possible shape of the target function in each of the regions. When many regions are necessary because the function is highly varying, the number of required parameters will be also large, and thus the number of examples needed to achieve good generalization.

# Local vs Non-Local Generalization

The local generalization issue is directly connected to the literature on the curse of dimensionality, but the results we cite show what matters for generalization is not dimensionality, but instead the number of “variations” of the function we wish to obtain after learning. For example, if the function represented by the model is piecewise-constant (e.g., decision trees), then the question is the number of pieces required to approximate properly the target function. There are connections between the number of variations and the input dimension: one can readily design families of target functions for which the number of variations is exponential in the input dimension, such as the parity function with d inputs.

Architectures based on matching templates can be thought of having two levels. The first level is a set of templates which can be matched to the input. A template unit will output a value that indicates the degree of matching. The second level combines these values, typically with a simple linear combination (an OR-like operation), in order to estimate the desired output. One can think of this linear combination as performing a kind of interpolation in order to produce an answer in the region of input space that is between the templates.

The prototypical example of architectures based on matching templates is the kernel machine [66]

```
$f(x) = b + \sum \alpha_i K(x, x_i),
```

$b$ and $\alpha_i$ form the second level, while on the first level, the kernel function $K(x,x_i)$ matches the input to $x_i$. In the above equation, $f(x)$ could be for example, the discriminant of a classifier, or the output of a regression predictor. A kernel is local when $K(\mathbf{x},\mathbf{x}_i) > \rho$ is true for $\mathbf{x}$ in some region around $\mathbf{x}_i$. The size of that region can usually be controlled by a hyper-parameter of the kernel. An example of local kernel is the Gaussian kernel $K(\mathbf{x},\mathbf{x}_i) = e^{-|\mathbf{x}-\mathbf{x}_i|^2/\sigma^2}$, where $\sigma$ controls the size of the region. We can see the Gaussian kernel as computing a soft conjunction, because

Well-known examples of kernel machines include not only Support Vector Machines (SVMs) [24, 39] and Gaussian processes [203] for classification and regression, but also classical non-parametric algorithms for classification, regression and density estimation, such as the $k$-nearest neighbor algorithm, Nadaraya-Watson or Parzen windows, etc. Below, we discuss *manifold learning algorithms* and LLE which can also be seen as local kernel machines, as well as semi-supervised learning algorithms based on the construction of a *neighborhood graph* (with one node per example and edges between neighboring examples).

Kernel machines with a local kernel yield generalization by what could be called *smoothness prior*: the assumption that the target function is smooth or can be well approximated with a smooth function. In supervised learning, if we train an example $(\mathbf{x}_i, y_i)$, then it makes sense to construct a predictor $f(\mathbf{x})$ which will output something close to $y_i$ when $\mathbf{x}$ is close to $\mathbf{x}_i$. Note how this prior requires defining a notion of proximity in input space. This is a useful prior, but one of the claims made [13] and [19] is that such a prior is insufficient to generalize when the target function is highly varying in input space.

However, if we lack sufficient prior knowledge for designing an appropriate kernel, can we learn it? This also motivated much research [40, 96, 196], and deep architectures can be viewed as a promising development in this direction.
