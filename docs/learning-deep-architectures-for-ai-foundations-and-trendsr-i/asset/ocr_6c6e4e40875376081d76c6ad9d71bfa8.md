# 7.1.1 Why a Sparse Representation?

We argue that if one is going to go fixed-size representations, then sparse representations are more efficient (than non-sparse ones) in an information-theoretic sense, allowing for varying the effective number of bits per example. According to learning theory [117, 193], to obtain good generalization it is enough that the total number of bits needed to encode the whole training set be small, compared to the size of the training set. In many domains of interest different examples require different number of bits when compressed.

On the other hand, dimensionality reduction algorithms, whether linear as PCA and ICA, or non-linear as LLE and Isomap, map each example to the same low-dimensional space. In light of the above argument, it would be more efficient to map each example to a variable-length representation. To simplify the argument, assume that this representation is a binary vector. If we are required to map each example to a fixed-length representation, a good solution would be to choose that representation to have enough degrees of freedom to represent the vast majority of the examples, while at the same allowing to compress fixed-length vector to a smaller variable-size code for most of the examples. We now have two representations: the fixed-length one, which we might use as input to make predictions and make decisions, and a smaller, variable-size one, which in principle be obtained from the fixed-length one through a compression step. For example, if the bits in our fixed-length representation vector have a high probability of being 0 (i.e., a sparsity condition), then for most examples it is easy to compress the fixed-length vector (in average by the amount of sparsity). For a given level of sparsity, the number of configurations of sparse vectors is much smaller than when less sparsity (or not at all) is imposed, so the entropy of sparse codes is smaller.
