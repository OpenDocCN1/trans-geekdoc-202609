
Wi‑Fi 以 ad‑hoc（或点对点）模式进行设置，使无线客户端可以直接相互通信，而无需经过接入点 (AP)。此类 Wi‑Fi 规避了常规的无线安全控制，可能导致超出 802.11 标准漏洞的严重安全问题。

你可以使用几乎任何无线网络分析器来查找网络上未经授权的 ad‑hoc 设备。如果发现网络中有大量 ad‑hoc 系统，例如在 CommView for WiFi 的 Type 列中显示为 STA（即 *station*）的设备（见 [Figure 10-15](#c10.xhtml#c10-fig-0015)），则说明有人在运行未受保护的无线系统，或至少已启用了 ad‑hoc 无线。这些系统通常是打印机等看似无害的网络设备，但也可能是工作站、移动设备或日益增长的物联网 (IoT) 组件。无论如何，它们都可能对你的网络和信息构成风险，值得检查。

[FIGURE 10-15:](#c10.xhtml#rc10-fig-0015)  CommView for WiFi 显示多个未经授权的 ad‑hoc 客户端。

你也可以使用手持式数字热点探测器（如本章前文“[Choosing Your Tools](#c10.xhtml#c10-sec-0003)”中提到的）来搜寻 ad‑hoc 启用的系统，或使用无线入侵防御系统搜寻 ESS 字段不等于 1 的信标帧。

步行到建筑物或校园（即 *warwalk*，若有此称）进行此测试，看看能发现什么。实地寻找不属于该环境的设备，并记住，位置恰当的 AP 或已关闭的 Wi‑Fi 客户端在网络分析工具中不会出现。请在建筑物外围或任何公共可进入区域附近进行搜索。检查会议室和高层管理人员的办公室，看是否有未经授权的设备。这些地方虽然可能受限制，但正因如此才需要检查是否存在 rogue AP。

在查找网络中的未经授权无线设备时，请记住你可能会捕获到邻近办公室或家庭的信号。因此，如果你发现了某个设备，不要立即认定它是 rogue 设备。判断该设备是否位于附近办公室或家庭的一种方法是检查检测到的信号强度。位于办公室外的设备 *应该* 信号比在办公室内的设备更弱。使用无线网络分析器以此方式可以缩小位置范围，避免因检测到合法的邻居无线设备而产生误报。

![remember](images/remember.png)了解你的网络环境很有价值。知道周围应有什么样的情况，能更容易发现潜在问题。

判断你发现的 AP 是否已连接到有线网络的一个好方法是执行反向 ARP（RARP），将 IP 地址映射到 MAC 地址。你可以在命令行中使用 `arp -a` 命令并将 IP 地址与对应的 MAC 地址进行比对，看是否有匹配。

另外要记住，Wi‑Fi 认证的是无线设备而非用户。黑客可以利用这一点，通过远程访问软件（如 Telnet 或 SSH）或利用已知的应用程序或操作系统漏洞，获得对无线客户端的访问，进而可能获得对整个网络的完整控制，而你可能仍不知情。

### 防范恶意无线设备的措施

检测网络中恶意 AP 和无线主机的唯一方法是主动（实时）监控你的无线网络，寻找表明存在无线客户端或恶意 AP 的指标。无线入侵防御系统非常适合此类监控。但如果恶意 AP 或客户端未被检测到，并不意味着你安全无虞。你可能还需要使用无线网络分析器或其他网络管理应用进行检查。

![tip](images/tip.png)在所有无线主机上使用个人防火墙软件（如 Windows 防火墙），以防止未经授权的远程访问，进而保护你的网络。

最后，别忘了用户教育。虽然教育并非万能，但它可以提供额外的防御层。确保安全始终在每个人的注意之首。[Chapter 19](#c19.xhtml) 包含关于用户认知与培训的更多信息。

### MAC 地址伪装

无线网络的常见防护措施是 MAC 地址控制。该控制方式要求 AP 仅允许已知 MAC 地址的无线客户端连接。因此，MAC 地址伪装是针对无线网络的常见攻击手段。

不法分子可以轻松在 Linux 中使用 `ifconfig` 命令，在 Windows 中使用 SMAC 实用程序来伪装 MAC 地址，如我在 [Chapter 9](#c09.xhtml) 中所述。与 WEP 和 WPA 类似，基于 MAC 地址的访问控制只是一种附加的保护层，好过于没有保护。如果有人伪装了你的 MAC 地址，唯一能够发现恶意行为的方法是通过上下文感知——即在无线局域网中发现同一 MAC 地址在多个位置被使用，这往往很棘手。

![tip](images/tip.png)判断 AP 是否启用了 MAC 地址控制的简单方法是尝试与其关联并通过 DHCP 获取 IP 地址。如果你能够获取 IP 地址，则说明该 AP 未启用 MAC 地址控制。

下面的步骤说明如何测试 MAC 地址控制以及它们有多容易被绕过：

1. **找到要连接的 AP。**

   你可以直接加载 NetStumbler，如 [Figure 10-16](#c10.xhtml#c10-fig-0016) 所示。

   在本测试网络中，SSID 为 *doh!* 的 AP 是我要测试的目标。请记录该 AP 的 MAC 地址。该地址将帮助你在后续步骤中确认正确的数据包。虽然为了隐私，我已隐藏大部分 MAC 地址，假设该 AP 的 MAC 地址是 `00:40:96:FF:FF:FF`。同时，[Figure 10-16](#c10.xhtml#c10-fig-0016) 中 NetStumbler 能够确定该 AP 的 IP 地址。获得 IP 地址有助于确认你正在正确的无线网络上。

2. **使用无线局域网分析器，查找无线客户端发送的探测请求帧（发送到广播地址）或 AP 回复的探测响应帧。**

   你可以在分析器中设置过滤器以捕获此类帧，或捕获数据包后浏览，寻找你在第一步记录的 AP MAC 地址。[Figure 10-17](#c10.xhtml#c10-fig-0017) 展示了探测请求和探测响应帧的样子。

   注意：为隐私起见，假设无线客户端的完整 MAC 地址是 `00:09:5B:FF:FF:FF`，它首先在第 98 号数据包中向广播地址 `FF:FF:FF:FF:FF:FF` 发送探测请求。AP（MAC 地址为我所关注的）随后向 `00:09:5B:FF:FF:FF` 发送探测响应，确认这是网络上正在测试 MAC 地址控制的客户端。

3. **将你的测试计算机的 MAC 地址更改为步骤 2 中发现的无线客户端的 MAC 地址。**

   在 Unix 和 Linux 系统中，可以通过 `ifconfig` 命令轻松更改 MAC 地址，方法如下：

   1. *以 root 登录并禁用网络接口。*

      插入你想要禁用的网络接口编号（通常为 `wlan0` 或 `ath0`），例如：

      `[root@localhost root]# ifconfig wlan0 down`

   2. *输入新的伪造 MAC 地址和接口编号。*

      例如：

      `[root@localhost root]# ifconfig wlan0 hw ether 01:23:45:67:89:ab`
