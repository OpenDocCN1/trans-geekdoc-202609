
即使在大型公司，或如果你使用 G Suite 或 Office 365 等云端邮件服务，也很可能没有理由在短时间内需要数千封入站邮件。

![warning](images/warning.png)邮件服务器可以被编程为向服务发送邮件以执行自动化功能，例如 `当该账户收到消息时创建此电子商务订单`。如果系统中未内置 DoS 防护，攻击者可以使服务器和接收这些消息的应用程序崩溃，从而可能导致电子商务责任和损失。这种攻击在电子商务网站上更容易发生，尤其是当表单未使用 CAPTCHA（即完全自动化图灵测试以区分计算机与人类）时。当你针对后端与电子邮件地址关联的 Web 表单进行 Web 漏洞扫描时，这会带来问题。这种情况可能会产生数千甚至数百万封邮件。做好准备并让相关人员知晓风险是有价值的。我在 [第 15 章](#c15.xhtml) 中讨论了 Web 应用安全。

#### 自动化邮件安全控制

你可以将以下措施作为额外的邮件系统安全层实施：

*   **Tarpitting**：`Tarpitting` 会检测发往未知用户的入站消息。如果你的邮件服务器支持 Tarpitting，它可以帮助防止针对你的服务器的垃圾邮件或 DoS 攻击。如果超过预定阈值（例如一分钟内超过 100 条消息），Tarpitting 功能会在一定时间内有效地屏蔽发送 IP 的流量。

*   **邮件防火墙**：Symantec、Barracuda Networks 等供应商的邮件防火墙和内容过滤应用可以大幅降低各类邮件攻击的风险。这些工具几乎可以保护邮件系统的每个方面。

*   **边界防护**：虽然不是专门针对邮件，但许多防火墙和入侵防御系统能够实时检测各种邮件攻击并立即阻断攻击者，这在攻击期间非常有用。

*   **CAPTCHA**：在基于 Web 的邮件表单上使用 CAPTCHA 可以帮助降低自动化攻击的影响，减少邮件洪水和 DoS 的风险，即使在执行看似无害的 Web 漏洞扫描时也适用。这些好处在测试你的网站和应用时尤为有用，我在 [第 15 章](#c15.xhtml) 中进行了讨论。

### Banners

当黑客入侵邮件服务器时，第一步通常是进行基本的 **Banner 抓取**，以确认能否发现正在运行的邮件服务器软件。这一步是发现 SMTP、POP3 和 IMAP 服务器信息的最关键测试。

#### 收集信息

[Figure 14-2](#c14.xhtml#c14-fig-0002) 展示了通过在服务器 25 端口（SMTP）进行基本 Telnet 连接时显示的邮件服务器 Banner。在命令行中，只需输入 **`telnet *ip or_hostname_of_your_server* 25`** 即可打开一个 Telnet 会话，连接到 TCP 端口 25。

[FIGURE 14-2:](#c14.xhtml#rc14-fig-0002)  一个显示服务器版本信息的 SMTP Banner。

邮件软件类型和服务器版本通常非常明显，能够给攻击者提供可能的攻击思路，尤其是当他们在漏洞数据库中搜索该版本已知漏洞时。[Figure 14-3](#c14.xhtml#c14-fig-0003) 展示了同一邮件服务器，但其 SMTP Banner 已从默认（即之前的那个）改为隐藏版本信息。

![ FIGURE 14-3:  An SMTP banner that disguises the version information.](images/9781119485476-fg1403.png)

![tip](images/tip.png)你可以通过 Telnet 到 110 端口（POP3）或 143 端口（IMAP）来获取 POP3 和 IMAP 邮件服务的信息。

![warning](images/warning.png)如果你更改了默认的 SMTP Banner，并不意味着没有人能够确定版本。通用漏洞扫描工具通常能够识别你邮件服务器的版本。一个基于 Linux 的工具 `smtpscan`（[`www.freshports.org/security/smtpscan`](http://www.freshports.org/security/smtpscan)）根据服务器对 malformed SMTP 请求的响应来判断邮件服务器版本。[Figure 14-4](#c14.xhtml#c14-fig-0004) 展示了 smtpscan 对前文所示服务器（即 [Figure 14-3](#c14.xhtml#c14-fig-0003)）的扫描结果。smtpscan 工具能够在 Banner 隐藏的情况下检测到邮件服务器的产品和版本号。

#### 对 Banner 攻击的防范措施

没有 100% 保险的方法可以隐藏 Banner 信息。我建议针对 SMTP、POP3 和 IMAP 服务器的 Banner 安全措施：

*   将默认 Banner 改为隐藏细节。

*   始终保持最新的软件补丁。

*   尽可能硬化服务器，参考中心化安全组织（Center for Internet Security）[`https://www.cisecurity.org`](https://www.cisecurity.org) 和 NIST（[`https://csrc.nist.gov`](https://csrc.nist.gov)）的最佳实践。

### SMTP 攻击

一些攻击利用 SMTP 弱点。该邮件通信协议已超过三十年历史，设计初衷是功能而非安全。

#### 账户枚举

攻击者可以通过 Telnet 到服务器 25 端口并执行 `VRFY` 命令来验证邮件账户是否存在。`VRFY`（即 *verify*）命令让服务器检查特定用户 ID 是否存在。垃圾邮件发送者常自动化此方法，进行目录收割攻击（DHA），即从服务器或域中获取有效邮箱地址，以便向目标发送垃圾邮件、钓鱼或携带恶意软件的消息。

#### 利用账户枚举的攻击

[Figure 14-5](#c14.xhtml#c14-fig-0005) 展示了使用启用 `VRFY` 的情况下，如何轻松验证邮箱地址是否存在。脚本化此攻击可一次测试成千上万的邮箱组合。

![ FIGURE 14-5:  Using VRFY to verify that an email address exists.](images/9781119485476-fg1405.png)

[FIGURE 14-5:](#c14.xhtml#rc14-fig-0005)  使用 VRFY 验证邮箱地址是否存在。

SMTP 命令 `EXPN`（即 *expand*）可能允许攻击者验证服务器上存在的邮件列表。你可以在 25 端口 Telnet 到邮件服务器，如果你知道有哪些列表，则尝试 `EXPN`。[Figure 14-6](#c14.xhtml#c14-fig-0006) 显示了可能的返回结果。脚本化此攻击并测试成千上万的列表组合同样简单。

![ FIGURE 14-6:  Using EXPN to verify that a mailing list exists.](images/9781119485476-fg1406.png)

[FIGURE 14-6:](#c14.xhtml#rc14-fig-0006)  使用 EXPN 验证邮件列表是否存在。

![warning](images/warning.png)在这些测试中，你可能会收到错误信息。某些 SMTP 服务器（如 Microsoft Exchange）不支持 `VRFY` 和 `EXPN` 命令，而某些邮件防火墙会忽略它们或返回错误信息。

另一种稍微自动化的做法是使用 TamoSoft 的 Essential NetTools 中的 EmailVerify 程序（[`https://www.tamos.com/products/nettools`](https://www.tamos.com/products/nettools)），如 [Figure 14-7](#c14.xhtml#c14-fig-0007) 所示，输入邮箱地址后点击 **Start**；EmailVerify 会连接到服务器并假装发送邮件。
