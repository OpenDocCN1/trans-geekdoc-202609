

机器学习可能较少被人们意识到，但对于向人们传达信息却至关重要。

不出所料，关于人类解释的文献一致认为，解释必须符合上下文 [VF+80]；不同的上下文需要不同的属性和不同的解释。话虽如此，人类解释也是社会建构，通常包括事后合理化和其他偏差。我们应该关注有助于用户实现目标的属性，而不是仅仅因为“人们有时会这样做”的属性。

下面列出了其中的几个属性。

- **可靠性** (例如，如 [Kul+13] 所述)。解释应当仅包含其所描述内容的真实情况，而不应包含其他内容。可靠性对应上述的 *紧凑性* 和 *忠实性*。

- **完整性** (例如，如 [Kul+13] 所述)。解释应当包含其所描述内容的全部真实情况。完整性对应上述的 *完整性* 和 *忠实性*。

- **普遍性** (例如，如 [Mil19] 所述)。总体而言，人们理解某一上下文中的解释可能不适用于另一个上下文。话虽如此，人们期望解释应反映某些底层机制或原理，因此会适用于类似情况——无论一个人心智模型中的相似性概念是什么。不能推广到类似情况的解释可能会被误解。普遍性对应上述的 *稳定性*。

- **简洁性** (例如，如 [Mil19] 所述)。在其他条件均相同的情况下，通常更倾向于更简单的解释。简洁性与上述的 *稀疏性* 和 *复杂性* 相关。

- **对比性** (例如，如 [Mil19] 所述)。对比性解释提供某事物与备选决策或预测不同之处的信息。例如，它可能不提供推荐特定药物的特征列表，而是提供解释为何推荐一种药物而非另一种的特征列表。对比性与上述的 *可操作性* 相关，更广泛地，还包括包含 *反事实* 的解释类型。

最后，认知科学文献还指出，解释通常是目标导向的。这与机器学习中将解释定义为帮助个人提升其终端任务表现的信息相一致。不同的信息可能有助于不同的目标，因此人类解释有多种形式。示例包括演绎-律则形式（即逻辑证明）[HO48]、提供底层机制感知的形式 [BA05; Gle02; CO06] 以及传达理解的形式 [Kei06]。了解这些形式可以帮助我们在不同的可解释机器学习方法集合中考虑哪些选项可能最好。

## 33.4 可解释机器学习模型的评估

在未指定上下文、终端任务和下游性能指标的情况下，无法将可解释性概念形式化 [VF+80]。如果一种解释相比另一种解释能够赋能人类在其终端任务上获得更好的性能，那么它更有用。尽管可解释机器学习的宏大挑战在于发展对不同上下文中不同终端任务良好下游性能所需属性的普遍理解，但本节将重点放在一个上下文内的严谨评估上 [DVK17]。

具体而言，我们描述了评估可解释机器学习方法的两大类别：

- **属性的计算评估（无需人员参与）。** 关于解释是否具有所需属性的计算评估不涉及用户研究。例如，可以计算测量特定解释在不同训练和测试数据分布下是否满足忠实性的定义，或者一种解释的输出是否比另一种更稀疏。当已知某些属性可能对某些上下文很重要时，此类措施很有价值。计算评估还作为中间评估和健全性检查，以在更昂贵的基于用户研究的评估之前识别不希望的解释行为。

- **用户研究（需人员参与）。** 最终，需要用户研究来衡量可解释机器学习方法在特定上下文中使用户完成其终端任务的效果。在真实上下文中进行严谨且设计良好的用户研究需要大量工作——远比在基准数据集上计算测试似然性要复杂得多。它不仅对研究人员，也对目标用户提出了很高的要求。不同上下文的方法也会面临不同的评估挑战：例如，旨在协助优化音乐推荐的系统可能可以在广大人群中进行测试，而旨在帮助粒子物理学家识别新型相互作用的系统可能只能由一两名物理学家进行测试，因为具备该专业知识的人很难找到。在所有情况下，只要仔细关注实验设计，评估都可以严谨进行。

### 33.4.1 计算评估：该方法是否具有所需属性？

虽然可解释性的最终衡量标准是该方法是否成功赋能用户执行其任务，但属性可以作为一种有价值的抽象。检查解释是否具有正确的计算属性和所需属性，可以确保方法按预期工作（例如，无实现错误，无明显的奇怪行为）。在进行昂贵的人体实验之前，可以针对新颖且计算效率高的方法进行迭代，以优化属性的定量形式化。计算检查还可以确保适用于一种模型的属性在应用于另一种模型时是否继续成立。最后，检查特定属性还可以帮助定位解释不足的具体方面，而这从用户研究中可能不那么清楚，因为存在混淆因素。

在某些情况下，可能能够从数学上证明解释具有某些属性，而在其他情况下，测试必须是实证的。对于实证测试，一种总体策略是使用基于假设的健全性检查：如果我们认为现象 X 永远不应发生（假设），则可以测试我们是否能创建出 X 可能发生的情况。如果发生了，则该方法未通过此健全性检查。另一种总体策略是创建具有已知特征或基准真值解释的数据集。这些可能是纯合成构造（例如，生成具有故意相关特征的表格）、半合成方法（例如，故意更改图像数据集上的标签），或是从真实数据集中取切片（例如，仅选择室外环境的真实图像、标签对以引入故意偏差）。请注意，这些测试只能告诉我们是否存在问题；如果方法通过了检查，仍可能存在未被发现的盲点。

**健全性检查示例。** 一种策略是提出“如果此解释正在工作，那么现象 X 不应发生”形式的陈述，然后尝试创建现象 X 发生的情况。如果成功，则健全性检查失败。通过询问意外现象，该策略可以揭示解释方法的一些令人惊讶的失败模式。

例如，[Ade+20a] 的假设是忠实解释应是模型预测的函数。假设是，在比较训练模型与未训练模型（预测是随机的）时，解释应发生显著变化。他们表明许多现有方法未能通过此健全性检查（Figure 33.4）。

在另一个示例中，[Kin+19] 假设忠实解释应对不影响模型预测或权重的输入变换保持不变（例如，所有输入加 10 的常数偏移）。此假设可视为对忠实性和稳定性属性的测试。他们的工作表明，某些方法未能通过此健全性检查。

对解释的对抗性攻击也属于此类。例如，[GAZ19] 表明，两个感知上不可区分且具有相同预测标签的输入可以被分配非常不同的解释。
