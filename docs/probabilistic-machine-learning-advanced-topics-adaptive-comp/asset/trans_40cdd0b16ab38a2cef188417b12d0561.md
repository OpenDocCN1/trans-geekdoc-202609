## 19.7.3 类增量学习

A very widely studied form of continual learning focuses on the setting in which new class labels are “revealed” over time. That is, there is assumed to be a true static prediction function \(f : \mathcal{X} \rightarrow \mathcal{Y}\), but at step \(t\), the learner only sees samples from \((\mathcal{X}_t, \mathcal{Y}_t)\), where \(\mathcal{Y}_t \subset \mathcal{Y}\). For example, consider the problem of digit classification from images. \(\mathcal{Y}_1\) might be \(\{0, 1\}\), and \(\mathcal{Y}_2\) might be \(\{2, \dots, 9\}\). Learning to classify with an increasing number of categories is called **class incremental learning** (see e.g., [Mas+20]). See Figure 19.18 for an illustration.

一种非常广泛研究的持续学习形式关注于新类标签随时间“揭示”的场景。也就是说，假设存在一个真实的静态预测函数 \(f : \mathcal{X} \rightarrow \mathcal{Y}\)，但在步骤 \(t\) 时，学习者只能看到来自 \((\mathcal{X}_t, \mathcal{Y}_t)\) 的样本，其中 \(\mathcal{Y}_t \subset \mathcal{Y}\)。例如，考虑从图像中进行数字分类的问题。\(\mathcal{Y}_1\) 可能是 \(\{0, 1\}\)，而 \(\mathcal{Y}_2\) 可能是 \(\{2, \dots, 9\}\)。学习随着类别数量增加进行分类称为 **类增量学习**（例如，参见 [Mas+20]）。请参见图 19.18 以获取示意图。

The problem of class incremental learning has been studied under a variety of different assumptions, as discussed in [Hsu+18; VT18; FG18; Del+21]. The most common scenarios are shown in Figure 19.19. If we assume there are no well defined boundaries between tasks, we have **continuous task-agnostic learning** (see e.g., [SKM21; Zen+21]). If there are well defined boundaries (i.e., discontinuous changes of the training distribution), then we can distinguish two subcases. If the boundaries are not known during training (similar to detecting distribution shift), we have **discrete task-agnostic learning**. Finally, if the boundaries are given to the training algorithm, we have a **task-aware learning** problem.

类增量学习的问题已在各种不同假设下进行研究，如 [Hsu+18; VT18; FG18; Del+21] 中所讨论。最常见的场景如图 19.19 所示。如果我们假设任务之间没有明确定义的边界，则具有 **连续任务无关学习**（例如，参见 [SKM21; Zen+21]）。如果存在明确定义的边界（即训练分布的不连续变化），则可以区分两种子情况。如果在训练期间不知道边界（类似于检测分布漂移），则具有 **离散任务无关学习**。最后，如果边界提供给训练算法，则具有 **任务感知学习** 问题。

A common experimental setup in the task-aware setting is to define each task to be a different version of the MNIST dataset, e.g., with all 10 classes present but with the pixels randomly permuted (this is called **permuted MNIST**) or with a subset of 2 classes present at each step (this is called **split MNIST**)\(^5\). In the task-aware setting, the task label may or may not be known at test time.

在任务感知设置中，一种常见的实验设置是将每个任务定义为 MNIST 数据集的不同版本，例如，包含所有 10 个类别但像素随机排列（这称为 **排列 MNIST**）或每个步骤中存在 2 个类别的子集（这称为 **分割 MNIST**）\(^5\)。在任务感知设置中，任务标签在测试时可能已知也可能未知。

If it is, the problem is essentially equivalent to multi-task learning (see Section 19.6.1). If it is not, the model must predict the task and corresponding class label within that task (which is a standard supervised problem with a hierarchical label space); this is commonly done by using a multi-headed DNN, with CT outputs, where C is the number of classes, and T is the number of tasks.

如果是，该问题基本上等同于多任务学习（参见第 19.6.1 节）。如果不是，模型必须预测任务及该任务中的相应类标签（这是一个具有层次标签空间的标准监督学习问题）；这通常通过使用具有 CT 输出的多头 DNN 来完成，其中 C 是类别数量，T 是任务数量。

In the multi-headed approach, the number of “heads” is usually specified as input to the algorithm, because the softmax imposes a sum-to-one constraint that prevents incremental estimation of the output weights in the open-class setting. An alternative approach is to wait until a new class label is encountered for the first time, and then train the model with an enlarged output head. This requires storing past data from each class, as well as data for the new class (see e.g., [PTD20]). Alternatively, we can use generative classifiers where we do not need to worry about “output heads”. If we use a “deep” nearest neighbor classifier, with a shared feature extractor (embedding function), the main challenge is to efficiently update the stored prototypes for past classes as the feature extractor parameters change (see e.g., [DLT21]). If we fit a separate generative model per class (e.g., a VAE, as in [VLT21]), then online learning becomes easier, but the method may be less sample efficient.

在多头方法中，“头”的数量通常作为算法的输入指定，因为 softmax 强加了和为一的约束，防止在开放类别设置中增量估计输出权重。另一种方法是等待直到首次遇到新类标签，然后使用扩大的输出头训练模型。这需要存储每个类别的过去数据，以及新类别的数据（例如，参见 [PTD20]）。或者，我们可以使用生成式分类器，不必担心“输出头”。如果我们使用一个“深度”最近邻分类器，带有共享特征提取器（嵌入函数），主要挑战是在特征提取器参数变化时，高效更新过去类别的存储原型（例如，参见 [DLT21]）。如果为每个类别单独拟合生成式模型（例如，如 [VLT21] 中的 VAE），那么在线学习变得更容易，但该方法的样本效率可能较低。

At the time of writing, most of the CL literature focuses on the task-aware setting. However, from a practical point of view, the assumption that task boundaries are provided at training or test time is very unrealistic. For example, consider the problem of training a robot to perform various activities: The data just streams in, and the robot must learn what to do, without anyone telling it that it is now being given an example from a new task or distribution (see e.g., [Fon+21; Wol+21]). Thus future research should focus on the task-agnostic setting, with either discrete or continuous changes.

在撰写本文时，大部分持续学习文献关注任务感知设置。然而，从实际角度来看，训练或测试时提供任务边界的假设非常不现实。例如，考虑训练机器人执行各种活动的问题：数据只是流式输入，机器人必须学习该做什么，而没有人告诉它现在正在从新任务或分布中获得示例（例如，参见 [Fon+21; Wol+21]）。因此，未来研究应关注任务无关设置，无论是离散还是连续变化。

So the “meaning” of the output label depends on what task we are solving. Thus the output space is really hierarchical, namely the cross product of task id and class label.

因此，“输出标签”的含义取决于我们正在解决什么任务。因此，输出空间实际上是层次结构，即任务 ID 和类标签的笛卡尔积。

## 19.7.4 灾难性遗忘

In the class incremental learning literature, it is common to train on a sequence of tasks, but to test (at each step) on all tasks. In this scenario, there are two main possible failure modes. The first possible problem is called “catastrophic forgetting” (see e.g., [Rob95b; Fre99; Kir+17]). This refers to the phenomenon in which performance on a previous task drops when trained on a new task (see Figure 19.20(a)). Another possible problem is that only the first task is learned, and the model does not adapt to new tasks (see Figure 19.20(b)).

在类增量学习文献中，通常在一系列任务上训练，但在每个步骤上对所有任务进行测试。在这种情况下，有两种主要的可能失败模式。第一个可能的问题称为“灾难性遗忘”（例如，参见 [Rob95b; Fre99; Kir+17]）。这指的是在新任务上训练时，以前任务的性能下降的现象（参见图 19.20(a)）。另一个可能的问题是只学习了第一个任务，模型不适应新任务（参见图 19.20(b)）。

If we avoid these problems, we should expect to see the performance profile in Figure 19.21(a), if performance of incremental training is equal to training on each task separately. However, we might hope to do better by virtue of the fact that we are training on multiple tasks, which are often assumed to be related. In particular, we might hope to see forwards transfer, in which training on past tasks improves performance on future tasks beyond what would have been obtained by training from scratch (see Figure 19.21(b)). Additionally, we might hope to see backwards transfer, in which training on future tasks improves performance on past tasks (see Figure 19.21(c)).

如果我们避免这些问题，我们应该期望看到图 19.21(a) 中的性能剖面，如果增量训练的性能等于分别对每个任务进行训练。然而，我们可能希望通过我们正在训练多个任务（通常假设它们是相关的）来做得更好。特别是，我们可能希望看到前向迁移，即训练过去任务提高了未来任务的性能，超过从零开始训练所能获得的性能（参见图 19.21(b)）。此外，我们可能希望看到后向迁移，即训练未来任务提高了过去任务的性能（参见图 19.21(c)）。

There are many methods that have been devised to overcome the problem of catastrophic forgetting, but we can group them into three main types. The first is **regularization methods**, which add a loss to preserve information that is relevant to old tasks. (For example, online Bayesian inference is of this type, since the posterior for the parameters is derived from the new data and the past prior; see e.g., the **elastic weight consolidation** method discussed in Section 17.5.1, or the **variational continual learning** method discussed in Supplementary Section 10.2). The second is **memory methods**, which rely on some kind of **experience replay** or **rehearsal** of past data (see e.g., [Hen+21]), or some kind of generative model of past data. The third is **architectural methods**, that add capacity to the network whenever a task boundary is encountered, such as a new class label (see e.g., [Rus+16]). Of course, these techniques can be combined. For example, we can create a semi-parametric model, in which we store some past data (exemplars) while also learning parameters online in a Bayesian (regularized) way (see e.g., [Kur+20]). The “right” method depends, as usual, on what inductive bias you want to use, and want your computational budget is in terms of time and memory.

已经提出了许多克服灾难性遗忘问题的方法，但我们可以将它们分为三种主要类型。第一种是 **正则化方法**，它们添加损失以保留与旧任务相关的信息。（例如，在线贝叶斯推理属于此类，因为参数的后验分布是从新数据和过去先验分布中推导出来的；例如，参见第 17.5.1 节中讨论的 **弹性权重巩固** 方法，或补充部分第 10.2 节中讨论的 **变分持续学习** 方法）。第二种是 **记忆方法**，它们依赖于某种 **经验回放** 或 **复演** 过去数据（例如，参见 [Hen+21]），或某种过去数据的生成模型。第三种是 **架构方法**，每当遇到任务边界时（例如新类标签）向网络添加容量（例如，参见 [Rus+16]）。当然，这些技术可以组合。例如，我们可以创建一个半参数模型，在其中存储一些过去数据（示例），同时以贝叶斯（正则化）方式在线学习参数（例如，参见 [Kur+20]）。“正确”的方法，与往常一样，取决于你想要使用什么归纳偏差，以及你在时间和内存方面的计算预算是多少。
