

## 33.1.1 可解释性的作用：未知与欠规范

如上所述，确保模型按预期行为具有挑战性。在某些情况下，期望的行为可以通过设计来保证，例如通过差分隐私学习算法实现的某些隐私概念，或某些选定的数学公平性度量。在其他情况下，跟踪各种指标（如不良事件或亚组错误率）可能是识别问题的适当且充分的方式。这本教材的大部分内容涉及不确定性量化：第 3 章的基本模型，第 17 章的贝叶斯神经网络，第 18 章的高斯过程。当能够计算校准良好的不确定性时，它们可能提供足够的警示，表明模型的输出可能不可信。然而，在许多情况下，最终目标可能根本无法完全指定，因此也无法形式化。例如，第 20.4.8 节讨论了评估生成模型样本质量的挑战。在这种情况下，对机器学习模型进行人工检查可能是必要的。下面我们描述几个例子。

盲点发现。检查可能会揭示我们建模、目标或数据中的盲点 [Bad+18; Zec+18b; Gur+18]。例如，假设一家公司已训练一个用于信用评分的机器学习系统。该模型是在相对富裕、中年人群上训练的，而现在公司正在考虑将其用于不同的、大学年龄段的人群。假设对模型的检查显示，它高度依赖申请人的按揭付款。这不仅可能暗示该模型可能无法很好地迁移到大学生群体，还可能鼓励我们检查现有申请中的偏见，因为我们知道历史偏见已阻止某些人群实现住房所有权（这是纯定量的公平性定义可能无法识别的）。确实，可解释性在工业环境中最常见的应用是工程师调试模型并做出部署决策 [Pai]。

新见解。检查可能催化新见解的发现。例如，假设一个算法确定手术程序分为三个集群。其中一个患者集群的手术似乎始终比预期时间长。检查这些集群的人可能会发现，延迟集群中的共同因素是这些手术发生在医院的不同部分，这是原始数据集中没有的特征。这一见解可能带来改善按时手术绩效的想法。

人机协作。检查可能赋能有效的人机交互与协作。例如，假设一个焦虑治疗推荐算法显示，患者合并失眠限制了其推荐。如果患者报告说不再有睡眠困难，可以移除该约束重新运行算法，以获得额外的治疗方案。更广泛地说，检查可以揭示人们可能希望调整模型的地方，例如纠正不正确的输入或假设。它还可以帮助人们在自己的决策中仅使用模型的一部分，例如使用模型计算的哪些治疗不安全与哪些治疗最佳。通过这些方式，人机团队可能能够产生比单独任何一方更好的综合性能（例如，[Ame+19; Kam16]）。

个体级补救。检查可以帮助确定特定伤害或错误是否发生在特定情境中。例如，如果贷款申请人知道用于拒绝其贷款的特征，他们就有了起点来争辩可能出现了错误，或者算法不公正地拒绝了他们。出于这个原因，可检查性有时是法律要求 [Zer+19; GF17; Cou16]。

当我们观察上面的例子时，我们会发现一个共同点：*当我们需要将人类洞察与机器学习算法结合以实现最终目标时，需要可解释性。* 然而，观察上面的列表也强调，除了这个非常基本的共同点之外，*每个应用和任务都有非常不同的需求。* 一位寻求从分子聚类中获取见解的科学家可能对全局模式感兴趣——例如，具有某些环状结构的所有分子都更稳定——并且愿意花几个小时研究模型的输出。相比之下，一位寻求做出特定治疗决策的临床医生可能只关心与特定患者相关的模型方面；他们还必须在门诊就诊的时间压力下做出决策。这将我们带到了最重要的观点：最佳的解释形式取决于*情境*；可解释性是达成目的的手段。

## 33.1.2 术语与框架

大致而言，“解释意味着以可理解的术语进行说明或呈现” [Mer]。理解，进而，涉及心智模型的对齐。在可解释机器学习中，这种对齐是在机器学习模型（或许只是其一部分）正在做什么与用户认为模型正在做什么之间。

因此，可解释机器学习生态系统不仅包括标准机器学习（例如，预测任务），还包括向人类用户提供什么信息、在什么情境下提供，以及用户的最终目标。更广泛的*社会技术系统*——人类、社会、组织和技术（硬件和软件）因素之间的相互作用集合——不可忽视 [Sel+19]。可解释机器学习的目标是帮助用户完成*他们的*任务，发挥*他们的*认知优势和劣势，应对*他们的*专注与分心 [Mil19]。下面我们定义这个扩展生态系统的关键术语，并描述它们之间的关系。不过，在继续之前，我们指出可解释机器学习是一个相对较新的领域，术语共识仍在演变中。因此，定义术语始终很重要。

可解释机器学习中两个核心的**社会或人类因素**元素是*情境*和*最终任务*。

### 情境。

我们使用术语*情境*来描述可解释机器学习系统将被使用的环境。用户是谁？他们拥有什么信息？他们的时间、认知或注意力上存在什么限制？我们将使用情境和应用这两个术语互换 [Sta]。

### 最终任务。

我们使用术语*最终任务*来指代用户的最终目标。他们最终试图实现什么？我们将使用最终任务和下游任务这两个术语互换。

可解释机器学习中三个核心的**技术**元素是*方法*、*指标*和方法的*属性*。

- 我们强调，可解释性不同于操纵或说服，后者的目的是故意欺骗或说服用户接受预设的选择。

### 方法。

可解释性如何发生？我们使用术语*解释*来指代方法向用户提供的输出：可解释机器学习*方法*向用户提供*解释*。如果解释就是模型本身，我们将该方法称为*天然可解释*或*通过设计可解释*。在其他情况下，模型可能太复杂，人类无法完整检查：也许是一个大型神经网络，没有人能指望理解；也许是一个中型决策树，如果有二十分钟可以检查，但如果需要在两分钟内做出决策就不行。在这种情况下，解释可能是模型的*部分视图*，一种在给定情境下理想地适合执行最终任务的视图。最后，我们注意到即使是天然可解释的模型也不揭示一切：人们可能能够完全检查函数（例如，一个两节点决策树），但不知道它在哪些数据上训练，或者哪些数据点最具影响力。

### 指标。

如何评估可解释性方法？评估是可解释机器学习中最基本、最具挑战性的方面之一，因为我们关心的是提供解释时*人类*的**最终任务**表现。我们称之为*下游性能*。正如 ML 中不同的目标需要不同的指标（例如，阳性预测值、对数似然、AUC），不同的**情境**和**最终任务**也会有不同的指标。例如，预测性能最好的模型（例如，对数似然损失）可能不是产生最佳下游性能的模型。

### 属性。

解释相对于模型、情境和最终任务具有哪些特征？不同的**情境**和不同的**最终任务**可能需要不同的属性。例如，假设一个解释被用来识别被拒绝贷款的申请人可以改进其申请的方式。那么，解释可能只应包含那些如果改变就会改变结果的因素很重要。相比之下，假设解释被用来确定拒绝是否公平。那么，解释不遗漏任何相关因素可能很重要。通过这种方式，属性充当了可解释性方法、情境和最终任务之间的粘合剂：属性允许我们指定和量化与我们最终任务目标相关的解释方面。然后，我们可以确保我们的可解释性方法具有这些属性。

它们之间如何关联。制定可解释机器学习问题通常始于指定情境和最终任务。情境和最终任务共同暗示了评估最终任务下游性能的适当指标，并暗示解释中哪些属性将很重要。同时，情境也决定了 ML 模型的数据和训练指标。解释方法的适当选择将取决于模型和期望的属性，并将根据最终任务指标进行评估以确定下游性能。图 33.1 显示了这些关系。可解释机器学习涉及许多挑战，从计算解释和优化可解释模型以及创建具有特定属性的解释到理解相关的人类因素。话虽如此，最大的挑战是（1）理解不同情境和最终任务需要哪些属性，以及（2）识别和创建具有这些属性的可解释机器学习方法。
