假设我们的情境是拥有一个柠檬水摊，我们的最终任务是了解摊位在何时最成功，以便确定哪些日子值得摆摊。（我们听说有时机器学习模型会抓住错误的机制，因此在使用模型来指导我们的业务策略之前，我们想先检查模型。）我们用于下游性能的指标是我们是否正确判断模型是否可信；这可以量化为在繁忙日子开张、在安静日子关门所获得的利润金额。

为训练模型，我们收集两个输入特征的数据——当天的平均气温（以华氏度为单位）以及摊位附近人行道的清洁度（以人行道中无垃圾的比例衡量，介于 0 和 1 之间）——以及输出特征：当天是否盈利。有两个模型似乎都能同样好地拟合数据：

### 模型 1:

```
p(profit) = .9 * (temperature > 75) + .1(howCleanSidewalk) (33.1)
```

### 模型 2:

```
p(profit) = σ(.9(temperature - 75)/maxTemperature + .1(howCleanSidewalk - .5)) (33.2)
```

这些模型在图 33.2 中有所说明。这两个模型本质上都是可解释的，因为它们易于检查和理解。虽然我们并未明确寻找因果模型（关于此，见第 36 章），但两者大多依赖温度，这似乎是合理的。

就本示例而言，假设上述模型是黑盒，我们只能请求其部分视图。我们决定要求模型提供最重要的特征。让我们看看当我们考虑两种不同的计算重要特征的方式时会发生什么。²

图 33.2：简单示例中描述的模型。这两个模型具有相同的定性特征，但不同的解释方法将以截然不同的方式描述这些模型，可能导致混淆。

我们第一种（基于特征的）解释方法计算，对于每个训练点，单独将每个特征更改为其最大值或最小值是否会改变预测。重要特征是那些会改变许多训练点预测的特征。可以将这种解释方法视为基于特征对生成预测的联盟的重要性来计算特征重要性的一种变体。在这种情况下，两个模型都会报告温度是主导特征。如果我们使用这种解释来审查我们的模型，我们将正确得出结论：两个模型以合理的方式使用特征（因此可能值得考虑用于决定何时开设柠檬水摊）。

我们第二种（基于特征的）解释方法计算每个训练点输出相对于输入的导数的大小。重要特征是那些在整个训练集上具有较大绝对导数之和的特征。可以将这种解释方法视为基于局部几何计算特征重要性的一种变体。在这种情况下，模型 2 仍将报告温度具有更高的导数。然而，模型 1（其行为与模型 2 非常相似）将报告人行道清洁度是主导特征，因为相对于温度的导数在几乎所有地方都为零。如果我们使用这种解释来审查我们的模型，我们将错误地得出结论：模型 1 依赖于不重要的特征（并且模型 1 和 2 依赖于不同的特征）。

发生了什么？不同的解释具有不同的属性。第一种解释具有与识别那些（如果更改）会影响预测的特征相关的忠实性属性，而第二种解释则具有正确识别具有最多局部曲率的特征的属性。在此示例中，第一种属性对于确定我们的模型是否可用于制定业务策略的任务更为重要。³

## 33.2 可解释机器学习的方法

可解释机器学习存在许多方法。每种方法都有不同的属性，正确的选择将取决于上下文和最终任务。正如我们在第 33.1.2 节中所述，可解释机器学习的重大挑战是确定什么样的属性适用于什么样的上下文，以及哪些解释方法满足这些属性。因此，应将本节视为可解释机器学习方法快速变化选项的高层次快照，人们可能希望为可解释机器学习选择这些方法。

### 33.2.1 本质可解释模型：模型即其自身解释

我们认为某些类别的模型本质上是可解释的：一个人可以检查完整模型，并经过合理的努力，理解输入如何变成输出。⁴ 具体地说，我们将本质可解释模型定义为那些不需要额外过程或先验知识即可作为最终任务解释的模型。例如，假设一个模型由一组相对较小的规则组成。那么，这些规则可能足以作为不涉及极端时间压力的最终任务的解释。（注意：以这种方式，一个模型可能对某个最终任务本质可解释，而对另一个则不是。）

本质可解释模型分为两大类：稀疏（或更紧凑）模型和基于逻辑的模型。

**紧凑或稀疏**的基于特征的模型包括各种稀疏回归。早些时候，在本教科书中，我们讨论了简单模型，如 HMM（第 29.2 节）、广义线性模型（第 15 章）和各种隐变量模型（第 28 章）。当足够小时，这些通常本质上是可解释的。此类别中更高级的模型包括超稀疏线性整数模型和其他清单模型 [DMV15; UTR14]。

在功能上虽简单，但稀疏在检查和解释方面有其缺点。例如，如果模型从几个相关特征中只选择一个，可能更难识别实际驱动预测的信号。模型还可能给相关特征分配不同的符号，这些符号最终相互抵消，使权重的解释变得毫无意义。

为了解决这些问题，并表达更复杂的函数，此类别中的一些模型强加层次结构或模块化结构，其中每个组件仍然相对紧凑且可以检查。示例包括主题模型（例如，[BNJ03b]）、（小型）离散时间序列模型（例如，[FHDV20]）、广义可加模型（例如，[HT17]）和强制单调性模型（例如，[Gup+16]）。

**基于逻辑**的模型使用逻辑语句作为基础。此类别中的模型包括决策树 [Bre+17]、决策列表 [Riv87; WR15; Let+15a; Ang+18; DMV15]、决策表 [Hau+10; Wan+17a; LBL16; Mal+17; Bén+21] 和逻辑编程 [MDR94]。更广泛的讨论以及关于这些方法的用户研究综述，可见 [Fre14]。基于逻辑的模型可以轻松建模非线性关系，但在建模输入和输出之间的连续关系（例如，表示线性函数与阶梯状常数函数）方面可能会遇到困难。与紧凑模型一样，层次结构和其他形式的模块化可以用于扩展模型的表达性，同时保持其可由人类检查。例如，可以根据某些文字定义一个新概念，然后使用该新概念来构建更复杂的规则。

使用本质可解释模型时，需要做出三个关键决策：模型类的选择、如何处理不可解释的输入特征，以及优化方法的选择。
