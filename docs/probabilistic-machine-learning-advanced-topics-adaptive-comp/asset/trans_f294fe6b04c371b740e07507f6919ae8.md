Global explanations can take many forms. One choice is to fit a simpler model (e.g., an inherently interpretable model) that approximates the original model (e.g., [HVD14]). One can also identify concepts or features that affect decisions across many inputs (e.g., [Kim+18b]). Another approach is to provide a carefully chosen set of representative examples [Yeh+18]. These examples might be chosen to be somehow characteristic of, or providing coverage of, a class (e.g., [AA18]), to draw attention to decision boundaries (e.g., [Zhu+18]), or to identify inputs particularly influential in training the model.

全局解释可以采取多种形式。一种选择是拟合一个更简单的模型（例如，固有可解释模型）来近似原始模型（例如，[HVD14]）。也可以识别影响许多输入决策的概念或特征（例如，[Kim+18b]）。另一种方法是提供一组精心挑选的有代表性的示例 [Yeh+18]。这些示例可能被选择为在某种程度上代表某个类，或覆盖某个类（例如，[AA18]），以引起对决策边界的注意（例如，[Zhu+18]），或者识别在模型训练中特别有影响力的输入。

Decision: determining what properties the context needs. Different forms of explanations have different levels of expressivity. For example, an explanation listing important features, or fitting a local linear model around a particular input, does not expose interactions—but fitting a local decision tree would. For each form, there will also be many ways to compute an explanation of that form (more on this in Section 33.2.3.2). How do we choose amongst all of these different ways to compute the explanation? We suggest that the first step in determining the form and computation of an explanation should be to determine what properties are needed from it.

决策：确定上下文需要哪些属性。不同形式的解释具有不同的表达能力。例如，列出重要特征的解释，或在特定输入周围拟合局部线性模型，不会揭示交互作用——但拟合局部决策树会。对于每种形式，也会有多种计算该形式解释的方法（更多内容请参见第 33.2.3.2 节）。我们在所有这些不同的计算解释方式中如何选择？我们建议，确定解释形式和计算的第一步应该是确定从解释中需要哪些属性。

Specifying properties is especially important because not only may different forms of explanations have different intrinsic properties—e.g., can it model interactions?—but the properties may depend on the model being explained. For example, if the model is relatively smooth, then a feature-based explanation relying on local gradients may be fairly faithful to the original model. However if the model has spiky contours, the same explanation may not adequately capture the model's behavior. Once the desired properties are determined, one can determine what kind of computation is necessary to achieve them. We will list commonly desirable properties in Section 33.3.

指定属性尤为重要，因为不同形式的解释不仅可能具有不同的内在属性——例如，它是否可以建模交互作用？——而且这些属性可能取决于被解释的模型。例如，如果模型相对平滑，那么基于局部梯度的特征解释可能对原始模型相当忠实。但是，如果模型具有尖峰状轮廓，则相同的解释可能无法充分捕捉模型的行为。一旦确定所需属性，就可以确定实现这些属性所需的计算类型。我们将在第 33.3 节列出通常可取的属性。

## 33.2.3.2 解释是如何计算的

Another set of decisions has to do with how the explanation is computed.

另一组决策涉及解释是如何计算的。

### Decision: computation of explanation.

### 决策：解释的计算。

Once we make the decisions above, we must decide how the explanation will actually be computed. This choice will have a large impact on the explanation's properties. Thus, it is crucial to carefully choose a computational approach that provides the properties needed for the context and end-task.

一旦做出上述决策，我们就必须决定实际如何计算解释。这种选择将对解释的属性产生重大影响。因此，仔细选择一种为上下文和 end-task 提供所需属性的计算方法至关重要。

For example, suppose one is seeking to identify the most “important” input features that change a prediction. Different computations correspond to different definitions of importance. One definition of importance might be the smallest region in an image that, when changed, changes the prediction—a perturbation-based analysis. Even within this definition, we would need to specify how perturbation will be computed: Do we keep the pixel values within the training distribution? Do we preserve correlations between pixels? Different works take different approaches [SVZ13; DG17; FV17; DSZ16; Adl+18; Bac+15a].

例如，假设有人试图识别改变预测的最“重要”输入特征。不同的计算对应于重要性的不同定义。重要性的一个定义可能是图像中当改变时会改变预测的最小区域——一种基于扰动的分析。即使在这个定义范围内，我们也需要指定如何计算扰动：我们是否保持像素值在训练分布范围内？我们是否保留像素之间的相关性？不同的研究采用不同的方法 [SVZ13; DG17; FV17; DSZ16; Adl+18; Bac+15a]。

A related approach is to define importance in terms of sensitivity (e.g., largest gradients of the output with respect to the input feature). Even then, there are many computational decisions to be made [STY17; Smi+17; Sel+17; Erh+09; Shr+16]. Yet another common definition of importance is how often the input feature is part of a “winning coalition” that drives the prediction, e.g., a Shapley or Banzhaf score [LL17]. Each of these definitions have different properties, as well as require different amounts of computation.

相关的方法是从敏感性角度定义重要性（例如，输出相对于输入特征的最大梯度）。即便如此，仍有许多计算决策需要做出 [STY17; Smi+17; Sel+17; Erh+09; Shr+16]。另一种常见的重要性定义是输入特征成为推动预测的“获胜联盟”的一部分的频率，例如 Shapley 或 Banzhaf 分数 [LL17]。这些定义各自具有不同的属性，并需要不同数量的计算。

Similar issues come up with other forms of explanations. For example, for an example-based explanation, one has to define what it means to be similar or otherwise representative: Is it the cosine similarity between activations? A uniform L2 ball of a certain size between inputs? Likewise, there are many different ways to obtain counterfactuals. One can rely on distance functions to identify nearby inputs that with a different outputs [WMR17; LHR20], causal frameworks [Kus+18], or SAT formulations [Kar+20a], among other choices.

其他形式的解释也会出现类似问题。例如，对于基于示例的解释，必须定义什么是相似或具有代表性：是激活之间的余弦相似度吗？输入之间特定大小的均匀 L2 球吗？同样，有许多不同的方法可以获得反事实。可以依赖距离函数来识别具有不同输出的附近输入 [WMR17; LHR20]、因果框架 [Kus+18] 或 SAT 公式 [Kar+20a]，以及其他选择。

### Decision: joint training vs. post-hoc application.

### 决策：联合训练与事后应用。

So far, we have described our partial explanation techniques as extracting some information from an already-trained model. This approach is called deriving a post-hoc explanation. As noted above, post-hoc, partial explanations may have some limitations: for example, an explanation based on a local linear approximation may be great if the model is generally smooth, but provide little insight if the model has high curvature. Note that this limitation is not because the partial explanation is wrong, but because the view that local gradients provide isn’t sufficient if the true decision boundary is curvy.

到目前为止，我们将部分解释技术描述为从已经训练好的模型中提取一些信息。这种方法称为推导事后解释。如上所述，事后的部分解释可能有一些局限性：例如，基于局部线性近似的解释如果模型通常平滑，则很好，但如果模型具有高曲率，则提供的洞察很少。请注意，这种局限性并非因为部分解释是错误的，而是因为局部梯度提供的视图不足以应对真正的决策边界是曲线的情况。

One approach to getting explanations to have desired properties is to train the model and the explanation jointly. For example, a regularizer that penalizes violations of desired properties can help steer the overall optimization process towards learning models that both perform well and are amenable to the desired explanation [Plu+20]. It is often possible to find such a model because most complex model classes have multiple high-performing optima [Bre01].

获得具有所需属性的解释的一种方法是联合训练模型和解释。例如，一个惩罚违反所需属性的正则化器可以帮助引导整体优化过程，以学习既表现良好又适合所需解释的模型 [Plu+20]。通常可以找到这样的模型，因为大多数复杂模型类具有多个高性能极值 [Bre01]。

The choice of regularization will depend on the desired properties, the form of the explanation, and its computation. For example, in some settings, we may desire the explanation use the same features that people do for the task (e.g., lower frequency vs. higher frequency features in image classifiers [Wan+20b]) — and still be faithful to the model. In other settings, we may want to control the input dimensions used or not used in the explanation, or for the explanation to be somehow compact (e.g., a small decision tree) while still being faithful to the underlying model, [RHDV17; Shu+19a; Vel+17; Nei+18; Wu+19b; Plu+20]. (Certain attention models fall into this category [JW19; WP19].) We may also have constraints on the properties of concepts or other intermediate features [AMJ18b; Koh+20a; Hen+16; BH20; CBR20; Don+17b]. In all of these cases, these desired properties could be included as a regularizer when training the model.

正则化的选择将取决于所需属性、解释的形式及其计算。例如，在某些环境中，我们可能希望解释使用与人们执行任务相同的特征（例如，图像分类器中较低频率与较高频率特征 [Wan+20b]）——同时仍忠实于模型。在其他环境中，我们可能希望控制解释中使用或不使用的输入维度，或者使解释在某种程度上紧凑（例如，小决策树），同时仍忠实于基础模型 [RHDV17; Shu+19a; Vel+17; Nei+18; Wu+19b; Plu+20]。（某些注意力模型属于这一类别 [JW19; WP19]。）我们也可能对概念或其他中间特征的属性有约束 [AMJ18b; Koh+20a; Hen+16; BH20; CBR20; Don+17b]。在所有这些情况下，这些所需属性都可以在训练模型时作为正则化器包含在内。

When choosing between a post-hoc explanation or joint training, one key consideration is that joint training assumes that one can re-train the model or the system of interest. In many cases in practice, this may not be possible. Replacing a complex and well-validated system in deployment for a decade may not be possible or take a prohibitively long time. In that case, one can still extract approximated explanations using post-hoc methods. Finally, a joint optimization, even when it can be performed, is not a panacea: optimization for some properties may result in unexpected violations of other (unspecified but desired) properties. For this reason, explanations from jointly trained models are still partial.

在事后解释与联合训练之间进行选择时，一个关键考虑是联合训练假设可以重新训练模型或感兴趣的系统。在许多实际情况下，这可能不可能。替换已部署十年的复杂且经过充分验证的系统可能不可能，或者需要极长的时间。在这种情况下，仍可以使用事后方法提取近似解释。最后，联合优化即使可行，也不是万能药：针对某些属性的优化可能导致违反其他（未指定但可取的）属性。出于此原因，联合训练模型的解释仍然是部分的。

### When might we want to consider post-hoc methods, and when not?

### 我们何时可能希望考虑事后方法，何时不希望？

The advantage of post-hoc interpretability methods is that they can be applied to any model. This family of methods is especially useful in real-world scenarios where one needs to work with a system that contains many models as its parts, where one cannot expect to replace the whole system with one model. These approaches can also provide at least some broader knowledge about the model to identify unexpected concerns.

事后可解释性方法的优势在于它们可以应用于任何模型。这一类方法在现实场景中特别有用，在这些场景中，需要处理包含许多模型作为其组成部分的系统，而不能期望用一个模型替换整个系统。这些方法还可以提供关于模型的至少一些更广泛的知识，以识别意外的问题。

That said, post-hoc explanations, as approximations of the true model, may not be fully faithful to the model nor cover the model completely. As such, an explanation method tailored for one context may not be transferable in another; even in the intended context, there may be blindspots about the model that the explanation misses completely. For these reasons, in high stakes situations, one should attempt to use an inherently interpretable model first if possible [Rud19]. In all situations when post-hoc explanations are used, one must keep in mind that they are only one tool in a broader accountability toolkit and warn users appropriately.

话虽如此，作为真实模型近似的事后解释可能无法完全忠实于模型，也不能完全覆盖模型。因此，为一种情境定制的解释方法在另一种情境中可能不可移植；即使在预期情境中，也可能存在解释完全遗漏的关于模型的盲点。出于这些原因，在高风险情况下，如果可能，应首先尝试使用固有可解释模型 [Rud19]。在所有使用事后解释的情况下，必须牢记它们只是更广泛问责工具包中的一种工具，并适当警告用户。

## 33.2.4 透明度与可视化

The scope of interpretable machine learning is around methods that expose the process by which a trained model makes a decision. However, the behavior of a model also depends on the objective function, the training data, how the training data were collected and processed, and how the model was trained and tested. Conveying to a human these other aspects of what goes into the creation of a model can be as important as explaining the trained model itself. While a full discussion of transparency and visualization is outside the scope of this chapter, we provide a brief discussion here to describe these important adjacent concepts.

可解释机器学习的范围围绕揭示训练模型做出决策过程的方法展开。然而，模型的行为还取决于目标函数、训练数据、训练数据的收集和处理方式，以及模型的训练和测试方式。将构建模型的其他方面传达给人类，可能与解释训练后的模型本身一样重要。虽然透明度和可视化的完整讨论超出了本章的范围，但我们在此简要讨论以描述这些重要的相邻概念。

Transparency is an umbrella term for the many things that one could expose about the modeling process and its context. Interpreting models is one aspect. However, one could also be transparent about other aspects, such as the data collection process or the training process (e.g., [Geb+21; Mit+19; Dnp]). There are also situations in which a trained model is released (whether or not it is inherently interpretable), and thus the software can be inspected and run directly.

透明度是一个总称，指可以关于建模过程及其背景揭示的许多事物。解释模型是其中一个方面。然而，也可以就其他方面保持透明，例如数据收集过程或训练过程（例如，[Geb+21; Mit+19; Dnp]）。还有某些情况下，发布训练好的模型（无论其是否固有可解释），因此软件可以被检查并直接运行。

Visualization is one way to create transparency. One can visualize the data directly or various aspects of the model’s process (e.g., [Str+17]). Interactive visualizations can convey more than text or code descriptions [ZF14; OMS17; MOT15; Ngu+16; Hoh+20]. Finally, in the specific context of interpretable machine learning, how the explanation is presented — the visualization — can make a large difference in how easily users can consume it. Even something as simple as a rule list has many choices of layout, highlighting, and other organization.

可视化是创造透明度的一种方式。可以直接可视化数据或模型过程的各个方面（例如，[Str+17]）。交互式可视化可以比文本或代码描述传达更多信息 [ZF14; OMS17; MOT15; Ngu+16; Hoh+20]。最后，在可解释机器学习的特定背景下，解释的呈现方式——即可视化——会极大地影响用户消费信息的难易程度。即使是简单的规则列表，也有许多布局、高亮显示和其他组织方式的选择。

When might we want to consider transparency and visualization? When not? In many cases, the trouble with a model comes not from the model itself, but parts of its training pipeline. The problem might be the training data. For example, since policing data contain historical bias, predictions of crime hot spots based on that data will be biased. Similarly, if clinicians only order tests when they are concerned about a patient’s condition, then a model trained to predict risk based on tests ordered will only recapitulate what the clinicians already know. Transparency about the properties of the data, and how training and testing were performed, can help identify these issues.

我们何时可能希望考虑透明度和可视化？何时不希望？在许多情况下，模型的问题不来自模型本身，而来自其训练流程的部分环节。问题可能在于训练数据。例如，由于警务数据包含历史偏见，基于该数据的犯罪热点预测会有偏见。同样，如果临床医生仅在担心患者病情时才安排检查，那么基于已下单检查训练的风险预测模型只会重申临床医生已经知道的内容。关于数据属性以及训练和测试执行方式的透明度，可以帮助识别这些问题。

Of course, inspecting the data and the model generation process is something that takes time and attention. Thus, visualizations of this kind and other descriptions to increase transparency are best-suited to situations in which a human inspector is not under time pressure to sift through potentially complex patterns for sources of trouble. These methods are not well-suited to situations in which a specific decision must be made in a relatively short amount of time, e.g., providing decision-support to a clinician at the bedside.

当然，检查数据和模型生成过程是需要时间和精力的。因此，这种可视化和其他增加透明度的描述最适合人类检查员不需要在时间压力下筛选可能复杂的模式来寻找问题根源的情况。这些方法不适合需要在相对短时间内做出特定决策的情况，例如为床边临床医生提供决策支持。
