### 6.9.4.3 次模子函数最小化

在多构体函数的情况下，无约束最小化再次是平凡的。然而，即使在无约束情况下，对任意（即不一定是单调的）次模子函数 min_{X \subseteq V} f(X) 进行最小化可能看起来是无法处理的。无约束次模子最大化是 NP-难的（尽管可近似），这并不令人惊讶，因为需要考虑的指数数量的集合。值得指出的是，次模子最小化不需要指数计算，并且不是 NP-难的；事实上，有多项式时间算法可以做到这一点，这根本不明显。这是次模子函数与凸函数共享的重要特征之一，即它们共同易于最小化。从20世纪60年代末开始，由 Jack Edmonds [Edm70] 等人牵头，离散数学界进行了协调努力，寻找要么一个能在多项式时间内最小化次模子函数的算法，要么证明这样的问题是 NP-难的。这个难题终于在一篇关于椭球算法的经典论文 [GLS81] 中被攻破，该论文给出了次模子函数最小化（SFM）的多项式时间算法。虽然该算法是多项式的，但它是一个连续算法，而且不实用，因此继续寻找纯组合的强多项式时间算法。Queyranne [Que98] 然后证明，算法 [NI92] 可以解决这个问题，当集合函数还满足对称性条件（即，\forall X \subseteq V, f(X) = f(V \setminus X)）时，这只需要 O(n^3) 时间。最终结果在 2000 年左右出现，使用了两种主要独立的方法 [IFF00; Sch00]。然而，这些算法也不实用，因为尽管它们是多项式时间，但具有不切实际的高多项式次数（即，对于 [Sch00] 为 \tilde{O}(|V|^7 * \gamma + |V|^8)，对于 [IFF00] 为 \tilde{O}(|V|^7 * \gamma））。这导致了针对 SFM 的组合算法的额外工作，从而产生了可以在时间 \tilde{O}(|V|^5 \gamma + |V|^6) 内执行 SFM 的算法 [IO09]。SFM 的两个实用算法包括 Fujishige-Wolfe 程序 [Fuj05; Wol76] 以及 Frank-Wolfe 程序，它们都最小化与次模子函数 f 关联的多面体 B_f 上的 2-范数（如下定义）（还应注意的是，Frank-Wolfe 算法也可以用于最小化该函数的凸扩展，这可以通过 Lovász 扩展 [Lov83] 相对容易地计算）。SFM 的更近期工作也在某种形式上基于该问题的连续松弛，导致了具有强多项式运行时间 [LSW15] 的算法，为 O(|V|^3 log^2 |V|)，对于该算法可以丢弃对数因子，从而在 [Jia21] 中达到 O(|V|^3) 的复杂度，弱多项式运行时间 [LSW15] 为 \tilde{O}(|V|^2 log M)（其中 M >= max_{S \subseteq V} |f(S)|），伪多项式运行时间 [ALS20; Cha+17] 为 \tilde{O}(|V|M^2)，以及具有线性运行时间的 \epsilon-近似最小化 [ALS20] 为 \tilde{O}(|V|/\epsilon^2)。还有其他努力利用并行性来进一步改进 SFM [BS20]。

## 6.9.5 次模子在机器学习和人工智能中的应用

次模子性在机器学习和人工智能应用中自然出现，但其效用仍未像其他技术那样被广泛认识和利用。例如，虽然熵和互信息等信息论概念在机器学习中被极其广泛地使用（例如，分类中的交叉熵损失无处不在），但熵的次模子性属性远没有被广泛探索。

尽管如此，在过去几十年中，次模子性在机器学习领域中被越来越多地研究和利用。下面我们将开始对受次模子性影响的机器学习中一些主要子领域进行简要调查。该列表并非旨在详尽，甚至不详尽。希望下面至少能对次模子性在机器学习和人工智能中如何有用以及如何继续有用提供合理的介绍。

## 6.9.6 素描、核心集、蒸馏以及数据子集和特征选择

摘要是对一组数据的简洁表示，可以作为该数据的有效高效替代品。有多种类型的摘要，有些极其简单。例如，数字列表的均值或中位数总结了该列表的一些属性（中心趋势）。随机子集也是一种摘要形式。

然而，任何给定的摘要都不能保证能很好地服务于所有目的。此外，摘要通常相对于原始数据至少涉及一定程度的近似和保真度损失，不同的摘要以不同方式且针对不同任务对原始数据保持忠实。出于这些和其他原因，摘要化领域丰富多样，摘要化程序通常非常专业化。

在过去几十年中，摘要化使用了几个不同的名称，包括“素描”、“核心集”、“（在自然语言处理领域中）“摘要”和“蒸馏”。

素描 [Cor17; CY20; Cor+12] 源于计算机科学领域，基于这样一个认识：数据通常太大，无法装入内存，也太大，无法在给定机器上运行算法，而数据的一个更小但仍然具有代表性且可证明近似的表示使得这一切成为可能。

核心集与素描类似，有一些属性更常与核心集相关联而不是与素描，但有时区别有点模糊。核心集的概念 [BHPI02; AHP+05; BC08] 来自计算几何领域，其中人们有兴趣基于 R^d 中的一组点来解决某些几何问题。对于任何几何问题和一组点，核心集问题通常涉及找到最小的加权点子集，这样当在加权子集上运行算法时，它会产生与在原始大数据集上运行时近似相同的答案。例如，给定一组点，人们可能希望找到集合的直径、最小外接球的半径、包含点的最窄环形（圆环），或者一组点的 k-中心聚类与整体的 k-中心聚类近似相同 [BHPI02]。

文档摘要在 20 世纪 90 年代成为自然语言处理（NLP）中最重要的问题之一，尽管计算文本摘要的想法可以追溯到 20 世纪 50 年代 [Luh58; Edm69]，也巧合地大约在 CliffsNotes [Wik21] 组织开始的同时。文档摘要有两种主要形式 [YWX17]。与 *提取式* 摘要 [NM12] 一样，从需要摘要的文档中提取一组句子（或短语），生成的句子子集（可能适当排序）构成摘要。另一方面，与抽象式摘要 [LN19] 不同，目标是生成文档的“摘要”，不限制摘要中的任何句子必须对应原始文档中的任何句子。因此，与抽象式摘要的目标是合成一小组新的伪句子来代表原始文档。例如，CliffsNotes 是所代表文献的抽象式摘要。另一种最近在机器学习社区中变得流行的摘要形式是数据蒸馏 [SG06b; Wan+20c; Suc+20; BYH20; NCL20; SS21; Ngu+21]，或者等价地称为数据集压缩 [ZMB21; ZB21]。使用数据蒸馏10，目标是生成一小组合成伪样本，例如可用于训练模型。关键在于，在缩减数据集中，样本不必与原始数据集相同或是其子集。上述所有内容都应与数据压缩形成对比，在某些意义上，数据压缩是最极端的数据缩减方法。无论是有损还是无损压缩，人们都不再有义务让数据的缩减形式必须可供解码器或非解压算法之外的任何算法或实体使用，甚至识别。

## 6.9.6.1 摘要算法设计选择

作者认为，摘要化、核心集、素描和蒸馏的概念当然是类比的，而且很可能是同义词，它们都与压缩不同。摘要化的不同名称仅仅是同一语言游戏的不同术语。重要的是不是你叫它什么，而是设计摘要化程序时所做的选择。的确，有很多选择。

次模子性本质上提供了无限多种方法来执行数据素描和核心集计算。当我们将次模子函数视为信息函数（如我们在第 6.9.7 节中讨论的）时，其中 f(X) 是集合 X 包含的信息，f(V) 是最大可用信息，找到最大化 f(X) 的小 X（即，X* ∈ argmax{f(X) : |X| ≤ k}）是一种由函数 f 参数化的核心集计算形式，因为 f 生活在一个 2^n 维锥中，因此 f 有 2^n 个参数。执行此最大化将最小化关于摘要 V \ X 中不存在的任何内容的残余信息 f(V \ X|X)，因为 f(V) = f(X ∪ V \ X) = f(V \ X|X) + f(X)，所以最大化 f(X) 将最小化 f(V \ X|X)。此外，对于每个 f，都可以使用相同的算法（例如，贪心算法）来生成摘要，在每种情况下，都有一个相对于当前 f 的近似保证，如前面各节所述，只要 f 保持次模子。因此，次模子性为摘要化、核心集和素描提供了一个通用框架，前提是次模子函数空间本身足够多样化并跨越不同的核心集问题。
