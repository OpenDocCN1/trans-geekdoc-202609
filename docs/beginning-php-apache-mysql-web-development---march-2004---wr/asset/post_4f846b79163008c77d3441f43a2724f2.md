# User Administration

Users require a similar treatment, although this treatment is a bit different from the $admin array.

The first thing we need is to gather all of the access levels, along with their names. That is done with the following code, which results in a numerical array of Access Levels:

```php
$sql = 'SELECT access_lvl, access_name FROM forum_access_levels ORDER BY access_lvl DESC;';
$result = mysql_query($sql) or die(mysql_error());
while ($row = mysql_fetch_array($result)) {
  $users[$row['access_lvl']] = $row['access_name'];
}
```

Next, we create an HTML select field, dynamically building it up with the options. Using the access level we've created, we can also use the optgroup tag to categorize the select list by access level. (Aren't we clever?)

```php
<select id='userlist' name='userlist'>
<?php
foreach ($users as $key => $value) {
  echo '<optgroup label="' . $value . '">\n';
  userOptionList($key);
  echo '</optgroup>\n';
}
?>
</select>
```

Note that you create the list of users by calling the userOptionList() function. This function resides in functions.php and is called once for each access level. A list of <option> tags is output, containing the appropriate user information.

```php
function userOptionList($level) {
  $sql = 'SELECT id, name, access_lvl FROM forum_users WHERE access_lvl=' . $level . '" ORDER BY name;';
  $result = mysql_query($sql) or die(mysql_error());

  while ($row = mysql_fetch_array($result)) {
    echo "<option value='" . $row['id'] . "'>" . htmlspecialchars($row['name']) . "</option>";
  }
}
```

That's really all that it is. When the appropriate user is chosen, his or her ID is passed to the transact-admin.php transaction page, where the admin user is redirected to the useraccount.php page for that user.

# Regular Expressions

If you are not familiar with regular expressions, one looks at a regular expression might prompt you to wonder what you would consider "regular". However, just like any language, you learn the syntax means, regular expressions are not that difficult. With the right combination of commands, regular expressions can be powerful.

A regular expression (often abbreviated "regex" or "regexp") is a pattern of symbols and letters to match. Once a match is found, it can be displayed, erased, or replaced with something else. If you have used *.php to list all PHP files in a directory, then you have used a regular expression.

So, how do regular expressions apply to an application like this? Good question. Imagine this site catered (as it might, in fact, because many children are comic fans?) You might want to prevent the use of obscene words on your site, so that is a friendly place that parents appreciate and allow their children to visit. By using regular expressions, you can scan a post before it is displayed on the screen and replace any vulgarities with cleaner prose.

The topic of regular expressions could easily fill a book by itself. Indeed, there are many places to learn about regular expressions you will learn in this chapter. You can start with the PHP manual by visiting www.php.net/pcre.

# The two types of regex functions

In PHP, there are two basic types of regular expression functions: POSIX and PCRE.

POSIX stands for Portable Operating System Interface (don't ask about the X; we think geeks just to use X however they can). POSIX is a set of standard operating interfaces based on the UNIX operating system. The POSIX term, does not actually refer to the regular expressions themselves, but describes the source of the regular syntax. It is more proper to refer to them as POSIX-style regular expressions. POSIX-style regular expressions are implemented in PHP using the ere() functions, such as ere_match() and preg_replace(), and ere_replace().

PCRE stands for Perl Compatible Regular Expressions. They are usually faster than POSIX-style regular expressions, and for reason along with the fact that PCRE regular expressions are usually more powerful, most developers choose to use PCRE functions as preg_match() and preg_replace().

Chapter 7 briefly introduced you to a POSIX-style regular expression. Here we show PCRE. It is ultimately up to you which one to choose. However, for a thorough understanding of both styles, make sure you read the PHP manual.

# How to write a PCRE regex

So, does a regex look like we? We will demonstrate different regex patterns using the preg_replace() function takes three arguments: the needle, the replacement pattern, and the text to be searched (the haystack). The regex pattern is contained in :needle:

```php
$result = preg_replace($needle, $replacement, $haystack);
```

When creating your pattern, you must use delimiters to define the boundaries. The simplest is forward slash (/). There are many ways to designate character within pattern, the following are legal:

| Pattern | Description |
| :--- | :--- |
| `.` | Matches any character except newlines |
| `^` | Matches the start of the string |
| `$` | Matches the end of the string |
| `*` | Matches 0 or more of the preceding element |
| `+` | Matches 1 or more of the preceding element |
| `?` | Matches 0 or 1 of the preceding element |
| `{x}` | Matches exactly x times of the preceding element |
| `{x,y}` | Matches between x and y times of the preceding element |
| `{x,}` | Matches x or more times of the preceding element |
| `[]` | Matches any character inside the brackets |
| `[^ ]` | Matches any character not inside the brackets |
| `|` | Acts as an OR (altern) |
| `()` | Groups multiple tokens together |
| ` \ ` | Escapes a special character |

In addition to pattern matching, there are modifiers that change the "rules" of your pattern. These go on the right side of the delimiter. For now, here is a partial list:

- `i` | Case-insensitive: Pattern matches any uppercase and lowercase |
- `s` | (.) matches all characters, including newlines |
- `e` | Very powerful! After pattern matching, evaluates the result as PHP |
