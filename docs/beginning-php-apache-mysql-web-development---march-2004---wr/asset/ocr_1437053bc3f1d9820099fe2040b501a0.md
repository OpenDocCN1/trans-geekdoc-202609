# Handling and Avoiding Errors

The previous snippet we created a fatal error, which is why the E_ERROR case was called in the switch statement. This sort of handler is nice to use to trap any of error and perform different actions on the error. The output should look similar to Figure 8-4.

![](bbox=[0.158, 0.155, 0.941, 0.626])

Figure 8-4

Even though you can trap the errors and display whatever you want to display, you may not want the user to see the error message we have created previously. You can create an error message that says there was an error on the page. Then you can apologize for the inconvenience and allow the user to go to another page. Finally, you can write the error to a log file, write it to a database, or send it to the Webmaster or administrator via e-mail so they can further review the error.

We personally prefer the e-mail method because it requires that the person be notified of the problem right away, and it doesn't require him or her to check the database or log files periodically. The only problem with this method is if there are a lot of requests to the page where the error is occurring: in that case the admin will be bombarded with e-mails.
