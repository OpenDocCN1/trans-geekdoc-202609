charlist.php page has an optional parameter that can be passed: ?o=x, where x is 1, 2, or 3. The code retrieves that variable if it exists, and converts it to the appropriate value if needed. If smart-alice o=4 in the browser, the char return 3. If no value or a bad value is passed, it will default to 1. The value is stored in ord.

```
$ord = $_GET['o'];
if (is_numeric($ord)) {
  $ord = round(max($ord, 1));
} else {
  $ord = 1;
}
$order = array(
  1 => alias ASC,
  2 => 'name ASC,
  3 => 'align ASC, alias ASC'
);
```

This value determines might which column our char display is sorted: 1 is by alias, 2 by name, and 3 is by alignment and then. We will use the $ord as the key to our order array, which will be appended to the appropriate SQL statement.

Ah... our first JOIN. This select statement might look confusing to the inexperienced, but it is not that complicated. First, let's look at the JOIN statements. We are joining three tables, using the char_power_link to link the char_power table and the char_main table. This is a many-to-many (M:N) relationship. We define how using the ON statement. As you can see, we are linking the char table to the link using the character id, and we're linking the power table to the link table using the power id. With that link established, we can see that we are getting the character's id and the powers assigned to each character.

Notice our use of aliases for the labels. The character table is c, the link table is pk, and the power table is p. We use this to refer to the appropriate columns with a shorter syntax (for example pk.char_id instead of char_power_link). It is not necessary to use column syntax across all tables. column name is unique across all tables. However, it is a good practice to keep so that you are aware of which data you are accessing. It is required, of course, for column names that are duplicated across multiple tables (such as id). Some might recommend that you always use unique names for all of your fields, but we prefer the practice of naming all keys "id" using proper table.column syntax in our SQL queries.
