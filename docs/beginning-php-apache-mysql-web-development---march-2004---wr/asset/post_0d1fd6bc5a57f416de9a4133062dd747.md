# How It Works

You can see that several things are accomplished in this script. We now have a new database called “ecommerce” with four tables in it. The first table is named products and contains the list of products available.

| Fieldname | Type | Description of What It Stores |
| --- | --- | --- |
| prodnum | CHAR (5) | The individual product number assigned to each product. |
| name | VARCHAR(20) | A brief title for the product, such as “CBA Logo T-shirt.” |
| proddesc | TEXT | A longer description we can use on the individual page for that product. May contain HTML code. |
| price | DEC (6,2) | Price of the product up to 999.99. |
| dateadded | DATE | Date the product was added to the site. |

The next table is named customers and contains the list of customers and their information.

| Fieldname | Type | Description of What It Stores |
| --- | --- | --- |
| custnum | INT (6) | The individual customer number assigned to each customer. This will increment. |
| firstname | VARCHAR(15) | Customer’s first name. |
| lastname | VARCHAR(50) | Customer’s last name. |
| add1 | VARCHAR(50) | Customer’s address: line 1. |
| add2 | VARCHAR(50) | Customer’s address: line 2 (can be null). |
| city | VARCHAR(50) | Customer’s city. |
| state | CHAR (2) | Customer’s state. |
| zip | CHAR (5) | Customer’s zip code. |
| phone | CHAR (12) | Customer’s phone number (in xxx-xxx-xxxx format). |
| fax | CHAR (12) | Customer’s fax number (same format as phone number, can be null). |
| email | VARCHAR(50) | Customer’s e-mail address. |

The next table you create is called ordemain and contains the main order information.

| Fieldname | Type | Description of What It Stores |
| --- | --- | --- |
| ordernum | INT (6) | The individual number assigned to each order. This will auto-increment and is the primary key. |
| orderdate | DATE | Date the order was placed. |
| custname | INT (6) | Number of the customer who placed the order. |
| subtotal | DEC (7,2) | Subtotal of the order before tax and shipping, up to 9999.99. |
| shipping | DEC (6,2) | Shipping costs for the order, up to 999.99. |
| tax | DEC (6,2) | Tax on the order, up to 999.99. |
| total | DEC (7,2) | Total of the order, up to 9999.99. |
| shipfirst | VARCHAR (15) | First name of the shipping contact for this order. |
| shiplast | VARCHAR (50) | Last name of the shipping contact. |
| shipaddl | VARCHAR (50) | Shipping contact's address: line 1. |
| shipadd2 | VARCHAR (50) | Shipping contact's address: line 2 (can be null). |
| shipcity | VARCHAR (50) | Shipping contact's city. |
| shipstate | CHAR (2) | Shipping contact's state. |
| shipzip | CHAR (5) | Shipping contact's zip code. |
| shipphone | CHAR (12) | Shipping contact's phone number (in xxx-xxx-xxxx format). |
| shipmail | VARCHAR (50) | Shipping contact's e-mail address. |

The fourth and final name is called orderdet and contains a detailed list of the products in each order.

| Fieldname | Type | Description of What It Stores |
| --- | --- | --- |
| ordernum | INT (6) | The order number (note this is designated a “key” and not “primary key”). |
| qty | INT (3) | How many of the item the customer wants. |
| productname | CHAR (5) | The product associated with this order. |

We now have a mechanism set up so that we can store all our products, all our customers, and all the information associated with the orders they place.

## How It Works

We started our script with a connection to the MySQL server; then we made sure our database was the “active” one. We then inserted each of our products into the products table, while keeping the values in the order as we used when creating the table:

- prodnum
- name
- prodesc
- price
- dated

You'll notice although we assigned sequential numbers to our products, we are not using the auto-increment feature, because in the real world, you may wish to assign product numbers based on category, distributor/manufacturer, or other numbering scheme; the products may include letters and numbers. Because we had no errors and our query didn't die, we should have seen the “Products added successfully” statement, and our products should now be in the database.
