We might add the alignment column to illustrate a point. If you are in the middle of the normalization process, and discover there is some other data you need to add, it isn't difficult to do so. You could add a completely new table if you need to. That is the geist thing about relational design.

The City and State fields are not only duplicates, but they are redundant with the ZIP Code (which is in itself a representation of the City/State). City and State are also not directly related to the lairs (because other lairs exist in the same city). ## Building Databases

You may have noticed that we have created a many-to-many (M:N) relationship between the characters and their powers (a character can have multiple powers, and many characters may have the same power). There are two tables with primary keys, and a linking table between them has foreign keys, one for each of the tables. The combination of the foreign keys is a primary key for the char_power table. This enables the M:N relationship.
