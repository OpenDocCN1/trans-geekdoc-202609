You should always assume that register_globals is turned OFF to make your application portable, and for this reason, we assume that we have access to the posted variables through the $_POST array only. What we are doing is looping through $_POST and setting each variable as username as $_POST['username'], then it will now be accessible as $username, regardless of the register_globals setting.

```
foreach($_POST as $key => $value) {
  $key = $value;
}
```

Remember that each button is named action and each one has a different value. In the code that follows, we determine which button was clicked, and run the appropriate code. For example, if the Delete Character was clicked, we want to run the SQL commands only for removing character.

The switch is a fancy way of providing a multiple choice. It is easier to read than a complex if...else statement. The only "gotcha" you need to be aware of is to use break; at the end of each case to prevent the rest of the other case blocks from executing.

The INSERT query that follows is relatively simple. In plain English: "Insert the $zip, $city, and $state into the columns id, city, and state in the char_zipcode table. The IGNORE keyword is a cool option that allows you to do an insert without first a SELECT to see if the data is already there. In this case, you know there might be a record for this Zip code. So, IGNORE tells you if you use this Zip code in the database, don't the INSERT."

```
case Create Character:
$sql = "INSERT IGNORE INTO char_zipcode (id, city, state)
nVALUES ('$zip', '$city', '$state');
$result = mysql_query($sql) or die(mysql_error());
```

Note that the IGNORE statement compares primary keys only. However, if any Zip code is in the database with the same name, the INSERT still takes place. Where the primary key is automatically incremented has no at all; the INSERT will always happen in that case. This might seem obvious to you, but just keep that in mind with some complex tables it won't be intuitive.

In the INSERT that follows, you use the use of NULL for the first value. When you NULL into a column, MySQL handles the following: If the column allows NULL values, it sets the NULL to the default value. If a default value has not been determined, the standard default for the datatype is inserted (empty for var/char, 0 for integer, and so on). If it is the case here, the column is set to auto_increment, then the next available integer for that column is inserted. In our case, it is the primary key, so this is what we want to happen.
