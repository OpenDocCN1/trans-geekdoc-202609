By using an internal file system, MySQL can jump to the approximate location of your data more quickly. It does through the use of indexes, also known as keys. In our preceding "receipt" example, you decided to group your receipts by year, so if your receipts were stored in a database, an index entry would be "year." You also decided to further group your receipts by category, so another index would be "category."

MySQL requires at least one index on every table, so that it has something to go by. Normally, you use a primary key, or unique identifier that keeps the data stable. This field must be "null" and "unique"; example you could have a customer ID to keep your customers separate. (You could easily have two "John Smiths," so you need to easily tell the difference.) In your "receipts" table, you created a primary key and assign each receipt its own identifying number so you can tell each apart.

MySQL also provides a feature that allows a value in a field to be automatically incremented by one. This auto_increment parameter is useful for making your primary key is being populated with unique numbers.

# Unique

We all like to think we're unique, but when this parameter is turned on, MySQL makes sure that absolutely no duplicates exist for a particular. Typically, this is used for the primary key in your table, but it can be used with any field.

For example, if you run a contest in which only the first person from every state you visited allowed to join your Web site? You could use the unique parameter; then anyone who tries to insert data into your database from a state where someone has already filled the slot will get an error message.

# Auto Increment

Say you have a field that will automatically increase by one whenever a new record is added. This can be a quite useful function when assigning IDs numbers. You don't have to worry about what the last ID number was; the field automatically tracks for you.

You can designate a field to be auto incremented by simply adding this command when setting up your table. You can also determine what the first number in the count will be, if you don't want it to be 1. You will see this in action later in the chapter.
