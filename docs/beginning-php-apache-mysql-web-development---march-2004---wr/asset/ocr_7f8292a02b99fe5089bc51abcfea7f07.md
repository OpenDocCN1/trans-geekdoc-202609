# How It Works

Because we've already written the functions to get the director’s and actor’s names, we “borrowed” this from the table2.php file. Then we've changed the query to return everything in each record, as opposed to only a few fields. It does mean that we are returning one field that we are not actually using. The query now contains a WHERE clause. This determines which record we are going to retrieve the data from.

Take a look at the WHERE clause (it’s not daunting as it first seems).

We have used $_GET['movie_id'] in the WHERE clause. The ID of the movie that was passed from the hyperlink in table3.php.

We've also created the $movie_table_headings to contain the headings for the fields that we'll be using.

The rest of the code is very similar to the code in table3.php. We added four extra fields to the while control loop.

Didn’t we say previously that returning fields you don’t need is not good practice? Yes, we did. However, in this case we are returning only one more field than we need, as opposed to returning many redundant. So are we gaining against our own device? Well, to 100 percent truthful, yes. However, as we are using the majority of fields in each record, PHP will not suffer from this tradeoff and it is worth it. You would not want to do this, for example, when you want the values of (say) 5 fields and the record contains 50 fields. If you did this in instance, PHP would be “wasting” resources to return the other 45 fields.
