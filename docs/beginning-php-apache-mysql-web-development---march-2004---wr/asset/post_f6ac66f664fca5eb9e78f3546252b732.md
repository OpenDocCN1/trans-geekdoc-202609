```php
function bbcode($data) {
  $sql = 'SELECT * FROM forum_table';
  $result = mysql_query($sql);
  if (mysql_num_rows($result) > 0) {
    while($row = mysql_fetch_array($result)) {
      $bbcode['tpl'][] = '*' . html_entity_decode($row['template'], ENT_QUOTES) . ' *';
      $bbcode['rep'][] = html_entity_decode($row['replacement'], ENT_QUOTES);
    }
  }

  $data = preg_replace($bbcode['tpl'], $bbcode['rep'], $data);
  $count = 1;
  while ($data != $data && ($count < 4)) {
    $data = $data;
    $count++;
  }
  $data = preg_replace($bbcode['tpl'], $bbcode['rep'], $data);

  return $data;
}
```

Because regex uses many characters in the pattern, before storing the data in our table MySQL can safely store. For that reason, when retrieving the data, we must perform html_entity_decode(). Note the use of the $ character as a delimiter because it is not used in regex patterns, a perfect delimiter. To use the character, make sure your num is enabled, hold down Alt key, and type 067. Alternatively, you could use a different non-alphanumeric character as your delimiter.

Also note the use of the / modifier after the right-hand modifier. This specifies that we do not care about upper or lower case. If you want to use case matching, free to remove from this modifier.

As you can see from the code, $row['template'] contains the regex pattern. The array variable $row['replacement'] contains the replacement pattern. Now, let's look at some of the pattern/replacement pairs you entered earlier:

The last pattern deserves a bit of explanation, as it introduces a couple of new concepts. The parentheses are there so we can use what we call back references. Note the $1 in the replacement pattern. This tells the function “Take whatever you found in the first set of parentheses and put it here.” If we had a more complex pattern with a second set of parentheses, we would refer to the data matched within those using $2.

Within those parentheses, we are matching any character at except a left square bracket. [^] tells the expression to match from 1 to any number of characters. If you wanted the expression to match 0 or more, use * instead of -.

The ? can be confusing, especially for those not familiar with regular expressions. Because it is immediately preceded by a quantifier (+), it does not mean 0 characters or 1 character as it usually does. In this case, it is telling the regex not to be greedy

Imagine the following text:

Hello, [b]George[/b], how are [b]you[/b] doing today?

If we ran the regex %[b]\[.+\]\[/b]$/i against that text (the lack of?), the regex would be “greedy” and match the maximum size it could find. The result is that the preceding text would look like so:

Hello, <b>George[/b], how are [b]you</b></b> doing today?

This isn't good in this particular case because we are trying to style “George” and “you” in boldface. We use the ? in our pattern after the + to tell the regex pattern to ungreedy, so that it finds the smallest matches. By in the ?, the result would be

Hello, <b>George</b>, how are <b>you</b> doing today?

which of course is the intended result.

We know regular expressions can be a bit confusing. Take the time to learn them, though. If you understand them, they can be your biggest ally. You will be surprised at the sort of patterns you can match with regex.

# Searching

A bulletin board would not be much less unless you had the ability to search for old posts. Any visit board you might be familiar with, and most likely you will find a search function there.

There are many types of searches. The simplest requires that you enter text into an input field, and when you hit the Search button, it looks for any of the text you entered. That is the search we created for this application.

Searches can get very complicated, too. You might want to search by the date they were entered, or by author. You might want to find a range of dates. You might even want to be able to designate how the result is sorted. These capabilities are not currently available in CBA, but if you feel ambitious, free to up your search.

The actual mechanism is simple. You have a single text field with a Search button that matches your form. The search.php page captures the search term, and builds a relatively SQL statement that is designed to return matching rows. We then iterate through those rows and display the data on the screen. It's not much different from displaying thread on the page. The only real difference is the SQL statement.

The bulk of search happens in the database. It stands to say, the more efficient our database is, the faster we will be retrieved. To maximize the efficiency, we create an index for fields to be searched. In this case, we index the subject and body columns of our forum_posts table. You can see how this works in the CREATE TABLE command.

```sql
CREATE TABLE forum_posts (
  id int(11) NOT NULL,
  topic_id int(11) NOT NULL,
  forum_id int(11) NOT NULL,
  author_id int(11) NOT NULL,
  update_id int(11) NOT NULL,
  date_created datetime NOT NULL DEFAULT '0000-00-00 00:00:00',
  date_updated datetime NOT NULL DEFAULT '0000-00-00 00:00:00',
  subject varchar(255) NOT NULL,
  body text NOT NULL,
  PRIMARY KEY (id),
  FULLTEXT (forum_id, topic_id, author_id, date_posted)
);
```

Note that after creating each of the columns, we set the Primary Key, a Fulltext index. We discuss Primary Keys in Chapter 9. These help us track unique records. The KEY is another term for INDEX. As you can see, we have created index for forum_id, topic_id, author_id, and date_posted. An index makes searching for rows much faster.

For more information on keys (indexes), visit www.mysql.com/doc/en/MySQL_indexes.html.

# Creating a Bulletin Board System

As you can see from the last line of the SQL query, we create a Fulltext index with the subject and body columns. This allows us to quickly find the records we are searching for.

Let's take a look at the SQL statement that does the actual search. Let's assume you are looking for the word "Board".

```sql
SELECT *, MATCH (subject,body) AGAINST ('Board') AS score
FROM forum_posts
WHERE MATCH(subject,body) AGAINST ('Board')
ORDER BY score DESC
```

In order to understand how this returns records, you must understand the MATCH command. MATCH returns a value that rates how well the match was for each row. According to the MySQL method, it is based on the number of words in the row; the number of unique words in that row, the total number of words in the collection, and the number of documents (rows) that contain a particular word.

Note that the MATCH command is used twice. Frankly, the MySQL optimizer caches the results of the MATCH command the first time it runs, and will not run it twice. Because the MATCH command returns a zero (0) for rows that do not match, putting MATCH in the WHERE clause prevents those rows from returning. If you do not put in the WHERE clause, all rows will be returned, and they will not be sorted.

Using MATCH in the WHERE clause causes the rows to be returned by relevance. This is not intuitive to all users, however, so we like to put in ORDER BY score DESC for good measure, although it is not required.

For more information on Full Indexes, visit www.mysql.com/doc/en/Fulltext_Search.html.
