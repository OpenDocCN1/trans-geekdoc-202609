We also have left out the id from the insert, and inserted values into the zip_id and lair_addr columns only. MySQL treats ignored columns as if you had attempted to insert NULL into them. We need to specify every column when doing an insert. If you need to modify your SQL statement, having all the columns in the INSERT query gives you a nice placeholder so all you have to modify the insert.

The following is a little function. Assuming the insert worked properly ($result returned), the mysql_insert_id() function will return the value of the last auto_increment from the last query. This only works after running a query on a table with an auto_increment column. In this case we just inserted into the char_id table. We will need that value to insert into the char_main table.

```
if ($result) $laidid = mysql_insert_id($conn);
```

The connection is optional, but we think it's a good idea to always include it. If you omit it, it will use the most recently opened connection. In a simple application like ours, that's not a problem; in a more complex application where you might have more than one connection, it could get confusing.

Again, the use of NULL for the primary key, and the use of mysql_insert_id() to return the primary key of the row:

```
$sql = "INSERT INTO char_main (id, lair_id, alias, real_name, align)\nVALUES (NULL, '$laidid', '$alias', '$name', '$align');";
$result = mysql_query($sql) or die(mysql_error());
if ($result) $charid = mysql_insert_id($conn);
```

We are always interested in minimizing the number of times we run a query on the database. Each hit takes precious time, which can be noticeable in a more complex application. At this point, we need to figure out how to insert all rows with only one SQL command:

```
if ($powers != "") {
$val = "";
foreach ($powers as $key => $id) {
$val[] = "'$charid', '$id";
}
$values = implode(", '", $val);
$sql = "INSERT IGNORE INTO char_power_link (char_id, power_id)\nVALUES $values";
$result = mysql_query($sql) or die(mysql_error());
}
```

There are a couple of concerns here. First, if there is already a power for this user (there shouldn't be; a new character, but always be prepared), we need not to insert the row. We already know how to take care of this by using the IGNORE keyword.

Second, we insert multiple rows of data with one query. Easy enough; all we have to do is supply a comma-separated list of value groupings that matches up to the column grouping in the query. For example:

```
INSERT INTO table (col1, col2) VALUES (val1, val2), (val3, val4)
```
