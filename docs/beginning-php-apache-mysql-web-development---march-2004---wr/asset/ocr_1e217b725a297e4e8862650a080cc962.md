# How It Works

When using cookies, remember the following:

+   - Like sessions, cookies must be placed at the very tip-top of the page, before your first <HTML> line. Otherwise, you get the ol 'headers already set' error.
- If you didn't notice, we changed the username from Joe12345 when we were using sessions, to Joe we were using cookies. This was to double-check that the information was coming from the cookie and not the session.
- We set the expire time to cookie 60 seconds so we could play and test our cookies without having to wait around them to kick off. For a normal application storing usernames, it would be logical to set this higher.
- Unlike sessions, cookie information can't be accessed in the current page where the cookies have been set. You have to move to the next page for the cookie to be set and accessible to your program.

# Passing Through Forms

Up until now, we've passed information among pages successfully, but we've been the ones to supply all information, not the visitor. While it would be a great world if we really knew much about what Web sites visit, it might get a little labor-intensive on our part. What do you say let us supply information for a change?

If you've never filled out a form line, then you have probably been living in a cave with no Internet access. The forms are great Venus Traps just lying to gobble up information from Web visitors. Allow your form to be truly interactive; they take the data from the user and send it off somewhere it gets massaged, manipulated, perhaps stored, and then some result is sent back to the user. While we discuss forms in greater detail in Chapter 5, we will briefly touch on them here with a basic understanding of how they work.

# Fast Primer on Forms

In case you are a bit unsure of the syntax of forms, or if you just need a quick reference, here is a quick, down-and-dirty dissection of forms.

Forms are coded in HTML and stay in HTML.

A form is made of four parts:

+   - Opening line, indicated by <FORM> tag. This tag line must include an action and a method. An action gives you a URL or path to another program that will take the data included in the form and carry it from there. (GET or POST) tells the form how the data is to be carried (POST is, generally speaking, the preferred method because it's more secure).

+   - Content of the form, including input fields. Input fields are the areas where the user types in the information (or selects in the case of a checkbox or radio button). An input field must include a type and a name, and can include other parameters, such as maxlength.
