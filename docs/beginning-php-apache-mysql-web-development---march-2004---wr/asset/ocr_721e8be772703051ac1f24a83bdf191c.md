# Building Databases

```
CREATE TABLE IF NOT EXISTS char_main (
  id int(11) NOT NULL auto_increment,
  alias varchar(40) NOT NULL default '',
  real_name varchar(80) NOT NULL default '',
  lair_id int(11) NOT NULL default 0,
  align enum('good','evil') NOT NULL default 'good',
  PRIMARY KEY (id)
)
```

The syntax for creating a table in SQL is the following:

```
CREATE [TEMPORARY] TABLE [IF NOT EXISTS] tbl_name
[[create_definition,...]] [table_options] [select_statement];
```

Obviously, we are not using the TEMPORARY keyword. We want this table to be permanent and exist after our connection with the database. We are using the IF NOT EXISTS keyword, way if this page is loaded twice. If you attempt to load the page again, MySQL will not attempt to re-create the tables, and will not generate an error.

Our name in this case is char_main. The columns we create are id, alias, real_name, lair_id, and alias, which we make up with earlier.

Let's look at each:

+   - int (11) NOT NULL auto_increment: The id is set as integer, with 11 maximum places. An integer datatype can contain the values -2147483648 to 2147483647. A sharp observer would note that the max value is only ten digits. The eleventh digit is for negative values.

+   - NOT NULL will force a value into the column. With some exceptions, numeric columns will default to 0, and string columns will default to an empty string (''). Rarely will we allow a column to carry a NULL value.

+   - The code auto_increment causes the column to increase the highest value in the table by 1, and store it in it. A column set to auto_increment does not have a default value.

+   - varchar (40) NOT NULL default '': the alias is set as a varchar datatype, a string of 0 to 255 characters. We are allotting 40 characters, which should be enough for us to name a character. A varchar differs from a char datatype by the way that space is allotted for the column.

+   - varchar datatype occupies only the space it needs, filling up the space by adding spaces at the end. The only time you really need to use the datatype for strings of less than three characters (such as the State column in the char_code table).

+   - real_name varchar (80) NOT NULL default '':Similar to alias. We are allotting 80 characters, which should be enough for our needs.

Note that we did not separate the real_name column into first and last columns. If you wanted to do that, you certainly could, but in this small application it isn't necessary. On the other hand, in a human resources application for your company, separate columns for first and last name is almost a requirement, so that you can do things as greet employees by their first names in a company memo.
