

## 第 9 章

我们在插入时去掉了 `id`，并且仅向 `zip_id` 和 `lair_addr` 列插入了值。MySQL 处理被忽略的列的方式，就像你尝试向它们插入 `NULL` 一样。在执行插入时，我们需要指定每一个列。如果你需要修改 SQL 语句，在 `INSERT` 查询中包含所有列可以为你提供一个很好的占位符，这样你只需要修改插入的部分。

下面是一个小函数。假设插入成功（$result 返回了），`mysql_insert_id()` 函数将返回上一个查询中最后一个 `auto_increment` 的值。这只有在带有 `auto_increment` 列的表上运行查询后才有效。在这种情况下，我们刚刚向 `char_id` 表插入了数据。我们需要那个值来插入到 `char_main` 表。

```php
if ($result) $laidid = mysql_insert_id($conn);
```

连接参数是可选的，但我们认为始终包含它是个好主意。如果你省略了它，它将使用最近打开的连接。在像我们这样简单的应用程序中，这并不是问题；但在可能有多个连接的复杂应用程序中，可能会引起混淆。

再次，对主键使用 `NULL` 以及使用 `mysql_insert_id()` 返回该行的主键：

```php
$sql = "INSERT INTO char_main (id, lair_id, alias, real_name, align)\nVALUES (NULL, '$laidid', '$alias', '$name', '$align');";
$result = mysql_query($sql) or die(mysql_error());
if ($result) $charid = mysql_insert_id($conn);
```

我们总是致力于减少对数据库运行查询的次数。每一次命中都会花费宝贵的时间，这在更复杂的应用程序中尤为明显。此时，我们需要弄清楚如何通过一条 SQL 命令插入所有行：

```php
if ($powers != "") {
    $val = "";
    foreach ($powers as $key => $id) {
        $val[] = "'$charid', '$id";
    }
    $values = implode(", '", $val);
    $sql = "INSERT IGNORE INTO char_power_link (char_id, power_id)\nVALUES $values";
    $result = mysql_query($sql) or die(mysql_error());
}
```

这里有几个需要考虑的地方。首先，如果该用户已经有一个技能（本应该没有；因为是新角色，但要做好准备），我们不需要插入该行。我们已经知道如何通过使用 `IGNORE` 关键字来处理。

其次，我们通过一个查询插入多行数据。这很容易；我们要做的只是提供一个逗号分隔的值分组列表，并使其与查询中的列分组匹配。例如：

```sql
INSERT INTO table (col1, col2) VALUES (val1, val2), (val3, val4)
```

# 构建数据库

我们通过遍历 `$powers` 数组并将角色 ID 和技能 ID 的值放入一个新数组来实现。然后我们用逗号作为分隔符连接数组，完成！这就是你要插入的多行数据。

我们对 `$enemies` 数组的操作与处理 `$powers` 时是一的。然而，这一次我们根据角色是好人还是坏人向相应的列插入数据。哪个列获取数据其实并不重要，但大多数情况下，我们希望将恶角色的 ID 放在 `$bad_id` 列中。

```php
$enemies = '';
$val = '';
foreach ($enemies as $key => $id) {
  $val[] = '$charid', '$id';
}
$values = implode(',', $val);
if ($align == 'good') {
  $cols = 'good_id, bad_id';
} else {
  $cols = 'bad_id, good_id';
}
$sql = "INSERT IGNORE INTO char_good_bad_link ($cols) 
VALUES ($values)";
$result = mysql_query($sql) or die(mysql_error());
```

涉及到 `char_good_bad_link` 时，我们有一点需要处理的完整性问题。我们不希望 `good_id/bad_id` 组合匹配 `bad_id/good_id` 组合。对于关系型数据库来说这不大，但对于我们的目的这是一个重复。我们在更新角色时会处理这种意外，因为这是一个新角色（带有新的 `id`），我们现在不需要担心。我们正在插入新角色数据，所以现在设置要加载的页面并跳出 switch 语句。

```php
$redirect = 'charlist.php';
break;
```

当删除角色时，我们简单地从所有相关表中删除它的实例。为了从 `char_lair` 表删除相关数据，我们必须通过匹配 `id` 将其连接到 `char_main` 表。然后删除匹配的角色 ID 的行。

```php
Delete Character:
$sql = "DELETE FROM char_main m, char_lair l WHERE m.id = l.id AND m.id = $cid";
$result = mysql_query($sql) or die(mysql_error());

$sql = "DELETE FROM char_power_link WHERE char_id = $cid";
$result = mysql_query($sql) or die(mysql_error());
```

我们并不真的需要 `mysql_query` 的结果放在一个变量里。出于习惯，如果以后需要返回值，我们喜欢这样做。在 `DELETE` 的情况下，你不会得到结果集，而是得到一个 `TRUE` 或 `FALSE` 的返回值。

记得我们的 `char_good_bad_link` 需要维护我们所谓的“反向”完整性（匹配关系），我们删除任一列中包含角色 ID 的行：

```php
$sql = "DELETE FROM char_good_bad_link WHERE good_id = $cid or bad_id = '$cid'";
$result = mysql_query($sql) or die(mysql_error());
```

更新角色时情况变得有趣起来。首先，我们可以简单地对代码表执行 `INSERT IGNORE`。如果代码表发生了变化，我们并不需要删除旧数据，因为它可能被其他角色使用——留下旧数据是可以的。

我们总是致力于减少对数据库运行查询的次数。每一次命中都会花费宝贵的时间，这在更复杂的应用程序中尤为明显。此时，我们需要弄清楚如何通过一条 SQL 命令插入所有行：

```php
if ($powers != "") {

```

更新角色时情况变得有趣起来。首先，我们可以简单地对代码表执行 `INSERT IGNORE`。（重复……）

再次，对主键使用 `NULL` 以及使用 `mysql_insert_id()` 返回该行的主键：


这让我们来到了“敌人”（Enemies），在那里，我们不仅必须维护完整性，还要担心更新我们的 ID 可能出现在两列中任一列行。我们必须维护自己的“反向”完整性。

我们是如何处理完整性的？事实证明，当我们遵循更新 `char_power_link` 表时采用的方法时，它会自动处理。通过简单地运行我们在删除角色时执行的 `DELETE` 查询，然后在创建新角色时立即运行 `INSERT` 查询，我们确保每个角色敌人只匹配到一组行。这既简单、优雅又有效！

到为止，查询对你来说应该非常熟悉了。`DELETE` 查询是 SQL 语句中最简单的之一。在 `DELETE` 查询中，我们需要删除在“添加/删除技能”页面选择的每一个技能。我们不仅在 `char_power` 表中这样做，在 `char_power_link` 表中也这样做（在我们的应用程序中，如果一个技能被删除，我们从角色中删除该技能）。为了对多行执行 `DELETE`，我们使用 `IN` 关键字，将提供的逗号分隔技能 ID 列表中的每个 ID 与 id 进行匹配，并删除每个匹配的行。

```php
case 'Delete Powers':
if ($powers) != '') {
    $powerlist = implode(',', $powers);
```

```php
$sql = 'DELETE FROM char_power WHERE id IN ($powerlist)';
$result = mysql_query($sql) or die(mysql_error());
```

```php
$sql = 'DELETE FROM char_power_link\nWHERE power_id IN ($powerlist)';
$result = mysql_query($sql) or die(mysql_error());
}
```
