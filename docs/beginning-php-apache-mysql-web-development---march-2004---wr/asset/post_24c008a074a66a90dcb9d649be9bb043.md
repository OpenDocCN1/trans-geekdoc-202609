## How It Works

The value "5" is assigned to the variable movierate, and it is assigned as an integer value instead of a string. The following line of code would cause the value of "5" to be seen as a string:

```php
$movierate="5";
```

By keeping this as an integer, you can then perform mathematical calculations on this number later on (such as giving the viewer the average movie rate), as in this example:

```php
<?php
$bsomsmovierate=5;
$joesmovierate=7;
$grahamsmovierate=2;
$zabbysmovierate=1;
$avgmovierate=($bsomsmovierate+$joesmovierate+$grahamsmovierate+$zabbysmovierate)/4;
echo "The average movie rating for this movie is: ";
echo $avgmovierate;
?>
```

## Passing Variables Between Pages

We've talked about how to use variables in code, but wouldn't it be great if you could move the variable value from page to page? There are three ways to accomplish this task, and the method you choose is based on the situation and what fits your needs at the time.

## A Word About register_globals

Before deciding the three methods of parsing pages, it is important to understand a level concept like register_globals. This is a configuration setting in your php.ini file that, when turned off, prevents the variable value from being falsely inserted by an outside source (because PHP doesn't require it to "on", ever since version 4.2 the default has been switched to "off"). This was the cause of many programmer's sleepless nights, as you must refer to your variables differently if register_globals is turned off, or else find all your variables coming up empty.

While many-party Web hosts have turned on register_globals, for security reasons not everyone does; the decision was made to make the assumption that register_globals is off for the purposes of our tutorial. Coding with the assumption that register_globals has been turned off is the safest way to code because your program will work regardless of the server's setting.

Instead of calling variables by the standard $varname, where register_globals is "off" and you need to pass variables across pages, in the receiving page you only need to refer to them in a different way. You will see this in the next "Try It Out" section, but the various ways to refer to variables depend on how they are being sent.

| Syntax | When to Use It |
| --- | --- |
| $_GET['varname'] | When the method of passing the variable is the "GET" method in HTML forms |
| $_POST['varname'] | When the method of passing the variable is the "POST" method in HTML forms |

| Syntax | When to Use It |
| --- | --- |
| $_SESSION['varname'] | When the variable has been assigned the value from a particular session |
| $_COOKIE['varname'] | When the variable has been assigned the value from a cookie |
| $_REQUEST['varname'] | When it doesn't matter ($_REQUEST includes variables passed from any of the methods) |
| $_SERVER['varname'] | When the variable has been assigned the value from the server |
| $_FILES['varname'] | When the variable has been assigned the value from a file upload |
| $_ENV['varname'] | When the variable has been assigned the value from the operating environment |

## Passing Variables Through a URL

The first method of passing variables between pages is through the page's URL. You've undoubtedly seen URLs such as this:

```
http://www.mydomain.com/news/articles/showart.php?id=2345
```

This is an example of passing variable values through the URL. In the preceding example, we are requesting the article with ID "2345" for showart.php. The text after the URL is called the `query string`.

You can also combine variables in a URL using an ampersand (&), as in this example:

```
http://www.mydomain.com/news/articles/showart.php?id=2345&lang=en
```

This asks to retrieve the file with ID "2345" and language equal to "en". There are a few disadvantages to passing variables through a URL:

- Everyone can see the values of variables, so passing sensitive information isn't secure using this method.
- The user can change the variable value in the URL, leaving your site potentially open to something you'd rather not.
- A user might also pull up inaccurate information using a URL with variables embedded in it.

## Try It Out Using URL Variables

Let's modify your program to show URL variables in action.

1. Modify your moviesite.php file as follows (changes are in bold):

```html
<HTML>
<HEAD>
<TITLE>My Movie Site - <?php echo $favmovie ?></TITLE>
</HEAD>
<body>
<?php
// delete this line: define("favmovie", "The Life of Brian")
echo "My favorite movie is ";
echo "<br>";
$movierate=5;
echo "My movie rating for this movie is:
echo $favmovie;
?>
</body>
</HTML>
```

2. Save your moviesite.php file and start a new document in your text editor.

3. Type the following code:

```html
<HTML>
<HEAD>
<TITLE>Find my Movie!</TITLE>
</HEAD>
<body>
<?php
echo "<a href='http://localhost/moviesite.php?favmovie=Stripes'>";
echo "Click here to see information about my movie!";
echo "</a>";
?>
</body>
</HTML>
```

4. Save this file as movie1.php and open it in your browser. Your screen should look like the one in Figure 2-5.

5. Now click the link and see what you get (see Figure 2-6).

![](img/7b817c5b51395b5dcaba58e6a2bc6daa_70_0.png)

You see the value for $favmovie as "Stripes" in the URL, as shown in Figure 2-6, but notice there is nothing shown for the value in the body of your page, not in the title as it's supposed to be.

What went wrong? You guessed correctly if you said "register_globals". This is a prime example of how not retrieving the variables in the correct way can leave your pages not working and you perplexed. Let's modify the moviesite.php file to fix the mistake.

1. Edit the following lines in your program (as shown in bold):

```html
<html>
<head>
<title>My Movie Site - <?php echo $_REQUEST['favmovie'] ?></title>
</head>
<body>
```

```php
<?php
echo "My favorite movie is ";
echo $_REQUEST['favmovie'];
echo "<br>";
$movierate=5;
echo "My movie rating for this movie is: ";
echo $movierate;
?>

<BODY>
<HTML>
```

2. Now save your file and reopen movie1.php. The link should now work fine, and your screen should look like the one in Figure 2-7.

## How It Works

A few notes about your program we should point out:

- As you can see from the “Title” section of your program, PHP code can be inserted in a straight line in the midst of your HTML code. This is helpful when you need to insert one tidbit of information grabbed from PHP.
- Also from that line, you can insert PHP information anywhere in your HTML program, including the title.
- You saw firsthand the effects of not taking into account register_globals when accessing a variable from another page, but did you notice that we referred to $favmovie, we did not include the register_globals syntax? This is because we kept the variable's value within our page and did not get the information from another page or source.
- We chose $_REQUEST for our variable syntax because it really didn't matter to us in our example where the value for $favmovie came from. We were not trying to validate anything or prevent an unauthorized user from entering this page of the site: We simply wanted to pass the value across.
