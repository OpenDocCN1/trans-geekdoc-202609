# How It Works

The commit.php code is very much the same as what you saw already, but there is an interesting twist in movie.php. Let's look at it in some detail.

First, look at what the start of the script. We defined a switch on a query string parameter action. If the action is edit, we query the database for a record corresponding to the id specified in the id query string parameter and set some variables. These variables are set to void if action is not edit.

```php
switch($_GET['action']) {
    case "edit":
        $movies = "SELECT
            *
            FROM
                'movie'
            WHERE
                'movie'.movie_id = ''.$_GET['id'].'";
        $result = mysql_query($movies)
        or die("Invalid query: " . mysql_error());
        $row = mysql_fetch_array($result , MYSQL_ASSOC );
```

Editing a text field is pretty straightforward. Editing a value in a list is another story. You can't just display the list and hope it will reset to the original when he or she edits the record. You need to reload the whole list and make the previously set value as a default in the list so the user can just forget it if he or she doesn't want to edit.

How do you do this? The script holds the solution:

# Summary

As you've learned in this chapter, there are three basic actions in modifying the content of the database:

- Insert
- Delete
- Update

These actions are performed by the database itself through SQL queries PHP executes on MySQL. Read up on the SQL statements used in this database to get a good feel for how far they can take you and at what level you feel comfortable using these commands.

Often, using MySQL revolves around the same few PHP functions. The SQL executed through those commands on the database changes the way the system reacts. Don't hesitate to learn more about SQL to enhance your PHP systems.

And finally, always, remember that testing your query alone in phpMyAdmin saves you a lot of time debugging it when working in a PHP script.

# Validating User Input

Accepting user inputs means being prepared to react to human error and human habit. The fact is that users acquire habits pretty fast. If a person uses an application often enough, the brain starts creating well-known application paths. user habits will have a bearing on the changes you make. Try switching two fields on a form.

In this chapter, we cover:

- Validating simple values
- Validating integer values
- Validating text

Let's consider an example: Why? Because all systems use ISO8601 YYYY-MM-DD. If you fail to implement the correct format, you can end up with corrupted data. In some cases, these are made on purpose. In fact, these attempts to find cracks in the walls around your system are quite frequent. You need to design your system so it can react to such errors or malicious attempts to corrupt the database.

Sometimes, when a user enters data in a form, he she forgets to fill in a field. When this happens, the system has to react so that the insertion of the invalid or incomplete data will not corrupt the database.
