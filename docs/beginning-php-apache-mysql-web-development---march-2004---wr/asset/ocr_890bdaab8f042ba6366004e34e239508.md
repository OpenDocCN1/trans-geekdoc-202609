The information in the error log is pretty self-explanatory. It is free-form and descriptive, but typically most error logs capture the date/time, the error severity, the client IP address, the error message, and the object client was requesting.

Because the error message is also contained in the Apache access log, it makes more sense to pull the data out of the access log. For example, the preceding error will show up in the access log with access code 404.

# PHP

PHP also keeps logs of errors for, but as we discussed in Chapter 1, the default setting for this feature is to set “off” in your php.ini file. You have to turn it on to enable error logging, which we highly recommend. Also, don't forget to check your php.ini file where you want the error log to be saved.

The typical error log looks like this:

```
[01-Sep-2003 18:42:03] PHP error: parse error, expected '' in C:\Program Files\Apache2\test\deleteme.php on line 14
```

In the other logs we have looked at, the logs themselves are relatively straightforward, and their purpose is to keep track of all of the errors that occurred when your PHP pages were being accessed.

In the preceding example, you can see that there was a parse error in the deleteme.php on line 14, which merits our attention. Anyone attempting to see the contents of this file will see only the parse error until we get it fixed.

A regular check of the PHP error log should be on your “to-do” list, just to make sure there aren’t any errors in your code.

# MySQL

As that's not enough, MySQL also logs queries and errors that pertain to database transactions. By default, the error log is stored as hostname.err in the data directory (in Windows and UNIX both). You can specify where the error log is saved by using the following command from the command prompt

```
mysqld -log-error=[filename].
```

Here is a typical entry in the error log:

```
030812 0:28:02 InnoDB Started
MySql: ready for connections. ''
Version: '4.0.14-max-debug' '' : port: 3306
```
