# Chapter 9

When adding a power, we first check to make sure a value was passed (no need to run a query if there is nothing to add) and then attempt to insert the value into the power table. Once, we use the IGNORE keyword in what follows to avoid duplication of power. We have mentioned that you really use IGNORE only on tables that have a primary key that is not autogenerated. There is an exception. IGNORE will not allow any duplicate data in any column that is defined as UNIQUE. In char_power table, the power column is a UNIQUE column, so attempting to insert a duplicate value would result in an error. The IGNORE keyword prevents the insertion, so we don't get an error returned. The power already exists, we simply return to the poweredit.php page and await further instructions.

```
case "Add Power":
if ($newpower == '') {
    $sql = "INSERT IGNORE INTO char_power(id, power)\n    VALUES (NULL, '$newpower');";
    $result = mysql_query($sql) or die(mysql_error());
}
```

You should have a default: in your case statements. You don't need to do anything, but it is good programming practice to include it. In this case, we are simply going to redirect the user to the charlist.php page.

```
default:
$redirect = 'charlist.php';
break;
```

Finally, we reach the last command of char_transact.php. In order to use the header() function, no data has been previously sent to the client. If it has, you will get an error. In our case, char_transact.php has no data sent to the client, so our header() function will work as advertised.

```
header("Location: $redirect");
```

Each case sets a destination page after running its queries. This command will now send the user to that destination.

One tremendous advantage of using a transaction page in this manner is that, because no data was sent to the client browser, once the browser gets to the destination page the history has no memory of this page. If the user refreshes his or her browser, it won't re-execute the transaction.. This makes for a clean application.

For example, let a user starts on the Character List page. He or she clicks the Edits Powers link. From the Edits Powers page, the user enters a new power and adds Add Power. The user might do this five times, adding new powers. Each time, the PHP server submits the form to the transaction page and redirects the user back to the power page. However, if the user clicks Back on his or her browser, the user is taken back to the Character List page, as if he or she just came from there. This is almost intuitive to the average user, and is what applications should do.
