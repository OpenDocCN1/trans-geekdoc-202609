# What Is a Cookie?

Cookies are tiny bits of information stored on your Web site visitor's computer. There appears to be some of paranoia about cookies; thus, many people choose to disable this feature in their browsers. While cookies can walk, in theory, be intercepted to gain information such as a person's IP address and operating system, cookies are primarily used for storing information only. There are also a few campaigns that have developed technology to track your browsing history, and many people see this as an invasion of privacy. Also, because cookies are stored in a commonly named directory, anyone with access to else's computer (either via a hack or physical location) can potentially open files and glean information about the owner. Because of these possibilities it's not a good idea to store any private information on a cookie.

For more information on cookies and the potential security risks (however minute), you are encouraged to visit the W3 Security FAQ Web site at www.w3.org/Security/faq/wssf2.html.

All being said, because your visitors may have turned off or physically delete cookies from their computers, relying on cookie information from a Web development standpoint won't be the brightest idea.

So why do developers use cookies, anyway? The advantage of storing information in a cookie is longevity. Sessions alone can store information for the length of the time the browser is open. Like the elusive and mean-spirited video game that has all high scores when it's unplugged, once a browser closes, all session information is lost. Cookies, on the other hand, can live on a person's computer until the developer has decided it is long enough and they automatically "die." It is because of longevity that cookies are fabulous for storing information as a user's username or language preferences. These are the pieces of information that users won't have to repeat every time they visit your site, but if for some reason they not get wind of the information, it wouldn't be the end of the world.

We mentioned earlier that sessions alone store information for very long. However, we can alter this limit if we use sessions in conjunction with cookies. If your sessions are paroles using cookies, you can set the life of cookies to longer than the life of the browser using the session.cookie_lifetime configuration in php.ini file. Keep in mind, however, that not only will the session information be stored on the person's computer; the session ID will be stored, and can cause problems later on.

To set a cookie, use the appropriately named setcookie() function. When setting a cookie, you can determine that the following information is set along with:

+   - Cookie name (this is mandatory).

+   - Value of the cookie (such as the person's username).

+   - Time in seconds when the cookie will expire. (Based on a Unix timestamp, you can set it using the following syntax: time()+60*60*24*365 keeps the cookie alive for a year. This is optional, but if it is not set, the cookie will expire when browser is closed.)

+   - Path (the directory where the cookie will be saved—usually sufficient; this is optional).

+   - Domain (domains that may access this cookie—this is optional).

+   - Whether a cookie must have a secure connection to it (defaults to 0; this enables this feature set this to 1).
