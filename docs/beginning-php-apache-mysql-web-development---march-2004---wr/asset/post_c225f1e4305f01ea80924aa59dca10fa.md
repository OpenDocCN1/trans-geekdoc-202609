# The my.cnf File

The my.cnf file, which can be edited with any text editor, such as Notepad, is the main file MySQL uses to read configuration options you have set up in your installation. You may alter this file at any time to tweak your configuration down the road.

By default, the installation of MySQL provides us with sample my.cnf configuration files to use as examples: my-small.cnf, my-medium.cnf, my-large.cnf, and my-huge.cnf. If you used the default directory during installation, these were all saved in the c:\mysql directory.

The difference in these files is presumably the amount of space you have on your computer dedicated to processing requests and so on. For the purposes of the Web sites used in this book, the my-medium.cnf file will suffice, so you should save it to your root c:\ directory so it can be accessed by the MySQL server. Be sure to rename your my.cnf so the server can find it.

While you can find a complete reference of configuration at the source (www.mysql.com), the beginner will be most concerned with. To set any of these options, simply type the appropriate line in my.cnf file. First, let's discuss the local-infile option, which can be found in my.cnf as follows:

```
[mysqld]
local-infile = 1
```

This allows you to load large amounts of data from a tab-delimited file or .csv file directly into your database. While this option can be very helpful if you are running your own site, or if you are the only one accessing MySQL, third-party hosts have this set to 0 to block their hosts from accessing this command, primarily for security reasons. If you are having your site hosted by a third party and need this feature, you may want to enable it to save some headaches later, as having to manually input large amounts of data bit at a time. If you haven't chosen your third-party host yet, this will be an important point.

# Setting Up Users and Privileges

Hackers (or malicious users) can be quite crafty in the ways they break into your system if you are directly connected to the Internet. MySQL allows you to pick and choose what user is allowed to perform based on privileges. All user information is stored in a database, which is located by default in your c:\mysql\data directory.

If you are the only accessing the MySQL database, you may not have to worry about updates. However, what if you have, say a hacker to help you out? You want them to be able to go into the tables and even insert some information. You probably don't want them to delete your entire database. By restricting them as a user, you will help to protect your data.

# Try It Out Setting Privileges

In order to set up the initial privileges, you need to make sure you're logged on as root. Then you're going to GRANT some privileges as a new user, so type this following:

```
mysql> GRANT SELECT, INSERT, UPDATE ON *.* TO user@localhost IDENTIFIED BY 'mysqlpass'
```

# How It Works

You have established that the user is a valid user who will be allowed to access your MySQL system, provided two things:

- She attempts connection from the "localhost" host—not a different connection from else.
- She supplies the correct password: "mysqlpass".

Your user will now be allowed to select information from the database, insert new information in the database, and update old information in the database. By giving access to all the tables in the database (via the use of ON *.*), we allowed them to modify any table in existence.

Before getting online and searching for help, you may try looking for answers to your problems within the programs themselves.

In Apache, the manual was installed with the standard installation and can be accessed in c:\program files\apache2\manual. A check of your error log will be most helpful as well.

In MySQL, you can enter this realm by typing the following at your DOS prompt:

```
c:\mysql\bin\mysql -help
```

This provides a multitude of commands that will help you find what you need, or at the very least, provide a valuable "cheat sheet" for administering your MySQL server. In addition, this will allow you to see the current settings for your server at a glance so you potentially troubleshoot any problems.
