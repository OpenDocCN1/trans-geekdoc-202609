# How It Works

Now we'll explain how a typical run through an admin (we'll call him Joe) works. Some of the pages you keyed in dont really need explaining so we won't discuss this.

When an administrator goes to the admin area, Joe is told whether he is not logged in. If he is, he can go to his personal administration area where he is able to do whatever he is allowed to.

The authorization is the same as the previous example so you can refer to previous figures for examples of how those pages look. We will show what screens look like when administrators with different log levels in and go to the admin area.

You keyed in all the code needed to do every aspect of the admin section, but this functionality is very similar to the update aspects of the user section so we won't cover those.

When an admin with a privilege level of 2 logs in, the screen should look like the one in Figure 11-17.

Notice in Figure 11-17 that the admin logged in is able to update the user but not allowed to delete the user because we did a check with the first statement to see what the admin's level is. Joe should log in a level of 1, he would see something similar to Figure 11-18.

Depending on how he chooses and whether he has high enough admin level, the admin will be able to update or delete the user's account. To guard against an admin of lower level navigating to the delete page and supply a user ID through the query string, we inserted a line of code that checks the admin level and notifies the admin that he or she doesn't have privileges to delete a user's account. We provide a link back to the admin area.
