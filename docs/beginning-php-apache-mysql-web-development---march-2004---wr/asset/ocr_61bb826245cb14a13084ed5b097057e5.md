The PRIMARY KEY, which comes from Chapter 9, is what ensures that each row is unique because it is the unique identifier for each row in the table.

The keyword KEY is similar to PRIMARY KEY, and it can be substituted for PRIMARY KEY in most cases. In this particular case, we are using KEY as a synonym for INDEX, which allows subsequent SQL statements to find data quickly. Because we will be looking for articles by author and by date, the fields used to create the index.

For more information on how MySQL indexes, visit www.mysql.com/doc/en/indexes.html.

We also allow the use of FULLTEXT search on text based in a search string. In order to perform such a search (which we allow for the title and body fields), we use the FULLTEXT KEY when creating our table. This is identical to FULLTEXT INDEX.

When creating the cms_users table, we use the previous keys to create both PRIMARY KEY to uniquely identify data, and UNIQUE KEY to ensure that each user's email address is unique.

```
PRIMARY KEY (user_id),
UNIQUE KEY uniq_email (e-mail)
```
