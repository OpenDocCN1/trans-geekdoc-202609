## Consistent and Valid Variable Names

First you should make sure your variables are appropriate and valid according to the naming rules, outlined in Chapter 2. Make sure you aren't beginning any variable name with a number, or using a predefined variable for variable name such as $php_errormsg. A complete list of these can be found in the PHP manual, http://us2.php.net/manual/en/reserved.variables.php.

Also, check the case when referencing variables, as variable names are case-sensitive. The same holds for database and table names. Make sure you referencing them consistently, and if you change a variable name after the fact, be sure to change all instances instances of the variable name.

It is easier to maintain consistent variables if you pick a naming convention and stick to it throughout your scripts. For example, if you always name your variables with a prefix of $var_, you can easily spot them in the code. This convention ties into the discussion in Chapter 2 regarding good coding practices.

## Open a New Browser

Sometimes you are working with sessions, and you are in the testing phase of your scripts, there may be an extraneous session hanging out there that could be preventing you from obtaining the desired results, and altering your variable values.

You can clear all session variables (provided you haven't changed your files as we discuss in Chapter 2) by simply closing the browser and opening a new one, instead of hitting Refresh or Reload.

If you need to set cookie or session variables within the body of your code, you need to rethink your logic to accommodate limitation. As we discuss in Chapter 2, those variables need to be addressed at the beginning of your code to be parsed correctly by the PHP server.

There are ways to get around this error, using the output buffer to suppress these errors. The output buffer is used to store all HTML output in a buffer until you are ready to send it to the browser. The command ob_start is used to begin the output buffering process, and ob_end_flush will send all of the stored HTML output to the browser, empty the buffer, and end the output processing string. You can let you the session and store cookies in the body of the code, as well as you to use the header("location:*") function in the body of the code. If you would like to learn more about the output buffers, you can find a complete list of them in Appendix C, or visit www.php.net.

## Using echo

Occasionally, you might want to read the server's mind and see what it thinks is going on. One way to do this is to echo variables normally in your code. This will verify that the server is parsing everything correctly.

You can echo in a step-by-step process as you follow the path of your variable, to see how the server is treating the variable throughout the code. This process would help, for example, if you wanted to perform a complex mathematical equation on a variable, and all you could tell from your output that you were getting the wrong answer. You want to find out what point the breakdown occurs, so you must insert echo statements each step of the equation to verify the accuracy of your calculation as it runs through the equation.

The echo command can also be useful in if statements, foreach statements, and so on to ensure that these loops are being called or processed correctly.

Let's see how echo can help us in a very simple example. Assume you have the script:

```php
<?php
$curr_var = 0;

while ($curr_var < 20) {
  $abc = 2 * $curr_var;
  $curr_var++;
}
echo $abc;
?>
```

## Divide and Conquer

Another way to tackle a huge problem is to break it down into baby steps and test each one to make sure you are getting the correct result step of the way. One mistake in the beginning of a complex block of statements can be a snowball effect and completely alter your results at the end. By checking each step by one, you can iron out those small bugs and eventually get the intended results.
