# Chapter 11

The beauty of sessions and keeping track of users is that you don't have to worry about passing information about the users with form data, or passing it through the query string or address bar. All the data is stored temporarily on the server where the site resides. You also don't have to worry about people trying to put parameters into the address bar to fix the identity of another user. The session data is unavailable to users on the site, so only if they have access to the server themselves would they be able to obtain it.

Now we will look at the pages where the user's information is displayed, and where a user can update or delete his account. The display page simply displays the previously entered user information. The update page is straightforward: it shows a form for the user previously entered data and gives the user the ability to update it if or she wishes, or simply cancel the update and return to the previous screen. The delete page asks if the user is sure he wants to delete the account and gives the option of returning to the previous screen. The user's information display page should look something like the one shown in Figure 11-12. When users choose to update their accounts, they will see a screen similar to Figure 11-13.
