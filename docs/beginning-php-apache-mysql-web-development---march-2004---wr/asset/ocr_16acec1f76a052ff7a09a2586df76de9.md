This brings us to the Enemies, where not only do we have to maintain referential integrity, but have to worry about updating rows where our id can be present in either of the two linking columns. We must maintain our own "reverse" referential integrity.

How did we deal with referential integrity? It turns out that it takes care of itself when we follow the same method we employed when updating the char_power_link table. By simply running the DELETE query we ran when deleting a character, and then immediately running the same INSERT query when we are creating a new character, we ensure that only one set of rows matches to each character/her enemy. It's simple, elegant, and it works!

By this time, queries should seem quite familiar to you. The DELETE query is one of the simplest of the SQL statements. In DELETE queries, we need to delete each power that was selected on the Add/Delete Power page. We do this not only in the char_power table but in the char_power_link table as well (In our application, if a power is removed, we remove power from the characters as well). In order to perform a DELETE on multiple rows, we use the IN keyword, which with each id in the supplied comma-separated list of power IDs is matched against the id, and each matching row is deleted.

```
case 'Delete Powers':
if ($powers) != '') {
    $powerlist = implode(',', $powers);
```

```
$sql = 'DELETE FROM char_power WHERE id IN ($powerlist)';
$result = mysql_query($sql) or die(mysql_error());
```

```
$sql = 'DELETE FROM char_power_link\nWHERE power_id IN ($powerlist)';
$result = mysql_query($sql) or die(mysql_error());
}
```
