We do the same with the $enemies array that we did with $powers. This time, however, we insert into the columns based on whether the character is good or evil. It doesn't really matter much which column gets, but for the most part we want evil character id in the $bad_id column.

```
$enemies = '';
$val = '';
foreach ($enemies as $key => $id) {
  $val[] = '$charid', '$id';
}
$values = implode(',', $val);
if ($align == 'good') {
  $cols = 'good_id, bad_id';

  $cols = 'bad_id, good_id';
}
$sql = "INSERT IGNORE INTO char_good_bad_link ($cols) 
VALUES ($values)";
$result = mysql_query($sql) or die(mysql_error());
```

When it comes to the char_good_bad_link link, we have a little bit of referential integrity that we have to handle (what MySQL does for us). We don't want to have a good_id/bad_id combination to match a bad_id/good_id combination. For the purposes of a relational database, that isn't bad, but for our purposes is considered a duplication. We will handle this contingency when updating a character, because this is a new character (with a new id), we don't have to worry about that just yet.

When deleting a character, we simply remove all instances of it from all relevant tables. In order to remove the relevant data from the char_lair table, we have to JOIN it to the char_main table by matching up id's first. Then we delete matching rows where the character id matches.

```
Delete Character':
$sql = "DELETE FROM char_main, char_lair USING char_main m,
char_lair l WHERE m.id = l.id AND m.id = $cid";
$result = mysql_query($sql) or die(mysql_error());

$sql = "DELETE FROM char_power_link WHERE char_id = $cid";
$result = mysql_query($sql) or die(mysql_error());
```

We don't really need to put the results of the mysql_query in a variable. We like to do this as a matter of habit if we need the return value later, then it will be available for use. In the case of a DELETE, you don't get a result set, you get a return value of either TRUE or FALSE.
