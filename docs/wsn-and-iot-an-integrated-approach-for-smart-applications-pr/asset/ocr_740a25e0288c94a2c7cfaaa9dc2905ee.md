Containers, on the other hand, are self-contained units that package software and its dependencies. Similar to VM programs, containers enable multiple programs to share resources on a single server [6]. However, containers virtualize resources on the OS level, providing a lightweight solution with quick deployment and finely grained resource sharing. Organizations increasingly rely on container technologies like Docker and Linux Containers to deploy IoT applications [7]. These containers can be deployed in private data centers or publicized cloud environments.

In recent years, applications have also been deployed in traditional cloud environments. A serverless infrastructure model has emerged, offering the ability to run IoT, or event-driven applications [8]. This serverless delivery enables cloud-based services to users, eliminating the need for providers to manage computing resources. This model, known as function-as-a-service (FaaS), is an alternative to the infrastructure-as-a-service (IaaS) in cloud environments.

Cloud computing has appeared as the leading technology for addressing increasing demands due to its massive storage and processing capabilities [9]. Transferring IoT applications from users' devices to a centralized cloud environment is less advantageous and less suitable for latency-intensive IoT applications [10], such as smart grid and connected vehicles [11], fire detector [12], and content delivery [13]. In a mobile environment, the CDCs are often distributed around the globe and comprise multiple heterogeneous resources [14]. However, executing independent IoT applications over multiple CDCs may increase transition and response time due to the overhead of intercommunication [15, 16].

The fog computing paradigm has been designed as a solution to these disadvantages of the traditional cloud environment. With fog computing, latency-intensive applications can run with minimal delay on local or nearby devices (e.g. network devices, sensors, sink nodes, laptops, desktops, and tablets), increasing the possibilities for IoT resources. Multi-access edge computing (MEC) is a cutting-edge network architecture that addresses some of the challenges associated with cloud computing. In addition enhancing customer experiences, MEC enables computing capabilities to be functional at the edge of the network, resulting in lower latency, more efficient operations, and more efficient service delivery. MEC can address various cloud computing challenges by performing tasks in real time or near real time at the network edge [20]. It is known that latency is a major problem associated with cloud computing as it takes longer to send and receive data, particularly for real-time applications. MEC overcomes this by bringing cloud computing resources closer to end-users, reducing data travel, lowering network congestion, and enhancing responsiveness and efficiency. Local data processing and storage capabilities also help decrease the cost of data transportation to and from the cloud [21]. Moreover, existing literature supports the idea that MEC is a break-through network architecture that can help cloud computing latency, data transportation costs, and network congestion, resulting in better performance and customer service.
