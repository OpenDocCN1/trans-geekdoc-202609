An illustration of the use of the NOT operator is as follows - in this case, we are using it to determine if "val" contains a value (the variable is set to 'X'):

```
select * from t10 where not val in ( select v1 from t20 where v1 like 'X%').
```

In the select you can see:

+   1. The NOT operator on a column (in order to negate it) and
+   2. The equality comparison, also shown in the select.

As you can see, the SQL NOT operator is pretty self-explanatory; perhaps it could be called the "not" operator?

The SQL NOT operator is not always logical, so care must be taken if you want to use it, particularly in JOIN conditions.

SQL NOT operator usage:

The SQL NOT operator should always be placed at the beginning of a WHERE clause or at the end of a set of WHERE clauses.

For example, there are problems with not only using it in the middle of a statement but also with making it part of multiple clauses.

```
USE thetablesample
CREATE PROCEDURE dbo.sp_Example2
BEGMEMBER ( not ( select @x = 1 ) )
RETURN
```

A rule for the SQL NOT operator is that it should be used in conjunction with logical AND and logical OR operators but should NEVER be used alone as an operator - if you want to negate a condition, then you'll need to use another operator like NOT IN or WHERE.

The SQL NOT operator is also used in conjunction with the IS NULL predicate, see:

```
SELECT * FROM t1 WHERE ( t1.col IS NOT NULL )
```

This is actually a good example of the difference between using a NOT operator and using a NULL expression.
