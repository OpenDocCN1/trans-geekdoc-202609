once. In the create() method, notice how we utilise the self() keyword in order to refer to the class:

```
Abstract class object{
Public static function create() {
return new self();
}
}

class Bed extends object {
}

class Chair extends object {
}
class Oven extends object {
}
```

The issue with returning self() as a class reference is that when the sub classes contact the create() method using the scope resolution operator, we receive an error:

```
Bed::create();
Chair::create();
```

# Output:

```
Fatal error: Cannot instantiate abstract class
object
```

This is because we used the self keyword, which refers to the abstract HouseholdObject as the foundation class. When create() function is modified to include the Couch, Table, and Refrigerator classes. It attempts to build a HouseholdObject rather than a Couch, Table, or Refrigerator. The abstract class is referred to in the create() function, not the class that is calling or invoking it. As you may recall, an abstract class cannot be instantiated, which results in an error from the PHP engine.

Let's try it again with late static binding, this time returning a static reference rather than a variable from the create() function.

This static reference will be to the class that calls the create() function, not to the base class. HouseholdObject:

```
Abstract class object{
Public static function create() {
Return new static();
}
}
Class Bed extends object {
}
```
