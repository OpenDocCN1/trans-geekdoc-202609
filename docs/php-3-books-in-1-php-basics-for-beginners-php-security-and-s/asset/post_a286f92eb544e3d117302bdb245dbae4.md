## Assertion Methods

An assertion is a tool for testing your assumptions about a certain system feature. An assertion is typically used to represent a test concerning the outcome of a tested code statement or segment. If the outcome of a test differs from the intended outcome, the test fails, and a warning message is presented. Assertion methods are also useful for documenting how the system under test should behave. Let's replace the example test case above with an assertion method:

```php
<?PHP
class Unit_Test extends PHPUnit_Framework_TestCase {

private $m_x;
private $m_y;

public function Unit_Test_Setup()
{
$this->m_x = 2;
$this->m_y = '2';
}

public function Unit_Test_TestEqual() {
$this->assertTrue($this->m_x == $this->m_y);
}

public function Unit_Test_TestIdentical() {
$this->assertTrue($this->m_x === $this->m_y);
}
public function Unit_Test_TearDown() {
$m_x = "";
$m_y = "";
}
}
?>
```

All assertion methods allow an optional description as a final parameter. This will be used to
label the result that is displayed. When this parameter is omitted, a default message is sent in its place, which is usually sufficient. If you put "% s" within the string, you can still include this default message in your own message. If an assertion works, it returns true; otherwise, it returns false.

Let's test these conditions again using the assertEqual() and assertSame() methods:

## Testing Data from HTML Form Submissions

We used the predefined $_POST variable, which is an array that collects values from a form, to create a form in our restaurant carte application to load carte Product data into the database.

You will need to interface with forms when developing in PHP. As a result, you'll need to test form submissions, specifically the GET and POST methods for sending data from the $_GET and $_POST arrays. Consider the concept of dependency injection. It's better to give your code what it needs rather than expecting it to find it on its own. Here's an example of how to tell the difference:

Example without dependency injection:

```php
function Add_Carte_Product1() {
foreach($_POST as $form_element => $v) {
// code to process $v
}
}

Add_Carte_Product_1();
```

Example with dependency injection:

```php
function Add_Carte_Product2(array &$formData) {
foreach($formData as $form_element => $v) {
// code to process $v
}
}

Add_Carte_Product2($_POST);
```

Do you get what I'm saying? In your PHPUnit test, you can pass an associative array of your choice to AddCarteProduct2(); the dependency has been injected. $_POST is used in conjunction with addCarteProduct1 (). Because $_GET and $_POST are associative arrays, you can use them in production code, but you must hard code certain anticipated values in unit tests.

Unit test example:

```php
function Test_Add_Carte_Product() {
$formData = array ('carteProductname'=>'Coffee', 'carteProductdescription'=>'black coffee',
'carteProductprice'=>'$2.55');
Test_Add_Carte_Product($formData);
// assert something...
}
```

## Mocks and Stubs

The process of substituting an object with a testdouble that returns specified values is known as stubbing.

Mocking is the process of validating behavior by substituting a test double for an object. Mock objects are used in unit testing to imitate the behavior of real objects in test cases. When you utilize them, it is easy to test the functionality of the object you are building. Mock objects are useful when the genuine implementation of one or more of an object's dependencies is still in progress, or when one or more of an object's dependencies is dependent on aspects that are difficult to replicate. Both of these cases are illustrated by testing the interaction between your application and a database. Normally, you'd use a function or another data access object, but what if the database hasn't yet been created?

What if no data was available, or if the database-querying code had not yet been written? A mock data access object simulates the true data access object by returning some pre-defined values. This saves you the time and effort of setting up the database, loading test data, and writing the code to query the database.
