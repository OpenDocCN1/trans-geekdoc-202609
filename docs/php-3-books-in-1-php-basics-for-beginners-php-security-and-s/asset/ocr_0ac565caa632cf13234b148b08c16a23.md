Singletons have a number of advantages. Singletons are frequently used to make data more accessible across an application than global variables. This is the result of a number of factors. For one thing, It's difficult to reuse a global variable-based class from one application to the next sans first, ensuring that the next app utilizes the same global variables. Additionally, global variables frequently waste resources, whereas the Singleton pattern allows for delayed allocation and initialization. Singletons are favored over globals for a third reason: globals consume the global namespace or the enclosing namespace. Later, the namespace functionality will be discussed in further detail.

The Abstract Factory, Builder, Prototype, and Façade design patterns are the Singleton pattern implementations.

The singleton pattern is achieved by creating a class with a function that, when called, sends a value back. If there is no existing instantiation of the class, it builds one. It just gives a reference to an object that already has an instance. To prevent the object from being instantiated in any other way, the constructor is designated private. Additionally, the $instance property is static and private. In this sample class, the $instance property saves and returns the instance of the Singleton object.

```
class SingletonClass {
private static $instance;
private function __construct() { }
public function __clone() { trigger_error('Clone is not allowed.', E_USER_ERROR);
}
public static function init() {
if (!isset(self::$instance)) {
$c = __CLASS__;
self::$instance = new $c;
}
return self::$instance;
}
// other public, dynamic methods for singleton
}

$singleton = SingletonClass::init();
```
