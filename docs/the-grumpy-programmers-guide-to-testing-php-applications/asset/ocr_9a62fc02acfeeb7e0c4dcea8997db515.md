# What’s the Difference?

The previous chapter where I showed you an example of using Test-Driven Development illustrated how much TDD is a design pattern with the side-effect of having tests that prove the code you wrote is behaving as expected. When you already have some code in place, and it’s working to provide business value or otherwise solve a problem, you need to approach the process of testing it differently.
