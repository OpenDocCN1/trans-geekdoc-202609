If the pool tag is unknown, we can use recommendations from Microsoft article KB298102 that explains how to locate the corresponding driver¹⁰⁸. We can also use memory search in WinDbg to locate kernel space addresses and see what modules they correspond to (**Value References** pattern, page 1057).

WinDbg shows the number of failed pool allocations and also shows a message when pool usage is nearly its maximum. Below I put some examples with possible troubleshooting hints.
