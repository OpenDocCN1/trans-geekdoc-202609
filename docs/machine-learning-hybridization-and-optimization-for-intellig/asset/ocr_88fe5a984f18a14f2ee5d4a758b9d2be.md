The IoT edge cloud brings together the best cloud and edge computing systems. Both have unique advantages in IoT based on the use case, data analysis, and storage requirements. The combination of both computing resources provides greater flexibility to users, reduces latency time, and protects data privacy standards. In the CC model, the algorithmic processing of tasks increases latency to allow IoT device applications to complete their tasks.

Edge computing geographically decentralizes resources, and the IoT edge cloud shifts cloud storage and computing closer to the edge source while scaling down the size. A computer at the edge of a network and the hardware and software at that location is called an edge. Cloud computing is when work is done in the cloud, while edge computing is done on devices close to the cloud. Edge computing can be used for anything that involves putting services, data, and intelligence closer to users and devices. As the edge-cloud scenario has grown, scheduling problems have received more attention. In the next section, we look at different issues with scheduling when edge clouds work together.

# 1.2 SCHEDULING

Scheduling is critical for assigning tasks in a virtual world, whether in cloud, edge, or fog computing or any mobile computing environment. The performance of the virtual machine server degrades if tasks are not correctly scheduled. According to [3, 4], the scheduler’s main aim is to allocate appropriate methods to optimize available resources to meet one or more objectives. An excellent job scheduler should be able to connect scheduling methods within a dynamically changing environment and different types of tasks. In the current scenario, optimizing resource problems is indeed a challenging task characterized by non-linear trends and dynamic, complex multi-objectives. There are three layers to cloud computing: 1) virtual resources for end users, 2) physical resource allocation to virtual machines by the scheduler, and 3) physical resource maintenance. The scheduling technique for each layer may differ depending on the type of computation complexity.
