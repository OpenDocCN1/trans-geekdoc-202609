Computer graphics rendering with industry-standard libraries like OpenGL in C/C++ and Pygame in Python is time-consuming and rarely rewarding. This is because the necessary libraries and packages to create games and render textures and graphics are quite outdated, as they were originally developed to create small 2D games for computer devices. Because of this, developing interactive games with such engines is challenging [5]. The development time for games using these engines is longer, and the games themselves typically run poorly on low-end PCs. The lack of support for cross-platform development is another issue when utilising these programmes to create interactive games; this means that they can only be produced and played on a small subset of operating systems, let alone mobile devices. Since simple tasks like texture rendering and character movement require large amounts of code that must be written by hand, this method is no longer considered appropriate for modern game development. The lack of adequate documentation for technologies like OpenGL makes it difficult for newcomers to the field to grasp and apply even the most fundamental features. This issue of a lack of usable materials, such as photographs, textures for items or characters, and models, is also a concern for the game development community [6]. They have to spend a lot of time creating on their own or hiring expert graphic designers for simple designs because they are hard to come by and there is no central location where they can all congregate.
