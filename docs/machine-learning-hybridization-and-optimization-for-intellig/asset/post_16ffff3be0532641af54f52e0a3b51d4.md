As discussed above, it is important for cloud infrastructure to be able to handle real-time resource-intensive applications. However, some applications require a subset of resources and can be handled by a low-configuration device, say a device at the edge of the cloud. This is achieved by edge computing technology through offloading tasks at the edge level. Edge computing was first introduced in the 1990s with the launch of Akamai’s Content Delivery Network (CDN). CDN delivered images and videos to users. In general, IoT devices near the edge devices require moderate computational resources. Some real-time applications such as cloud gaming, smart series, and augmented reality require this infrastructure. Edge computing (EC) acts as a gateway to edge devices (mobiles, smart grids, connected appliances) to compute and store the data source at the edge. It provides solutions to significant infrastructure issues and challenges such as network congestion, higher latency, and bandwidth limitations. EC handles these issues effectively by bringing the cloud closer to the users. EC enables the user to perform and execute a task at the edge and provides the results as fast as possible. As a result, transmission delays and other communication issues are resolved. The benefits of EC are cost-effective solutions, faster response time, and reliable operations with intermittent connectivity and security compliances with computing.

In this chapter, we describe a typical structured view of edge computing. Cloud-deployed high-end services interface directly with devices. Machines learn tasks at the edge, reducing time. Edge-cloud computing delivers low-latency remote cloud services for new IoT devices. This can be used to offload computing processing services from the cloud to the edge to improve a client’s quality of service (QoS) and quality of experience (QoE). The EC model cannot always replace CC since it does not have as substantial a resource capacity as the cloud. Therefore, EC and CC complement each other and are mutually reinforced. Various researchers widely accept the popular three-tier model. The device boundaries, also called a thing-layer or user’s border, are composed of all devices such as mobiles, surveillance cameras, IoT devices, smart devices, drones, and other equipment. Some devices have limited storage capacity and processing capabilities. As per the client’s requirement, these data can be prepared locally or offloaded to the edge and the cloud. The edge boundaries are the middle layer between the device boundary and the cloud layer. The edge boundaries are the center core layer of the three-tier model. This layer involves a lot of network equipment such as sensors, towers, gateway, edge controllers, and many others. This layer enables wireless connectivity to connect smart devices using Radio Access Technology (RAT), Wi-Fi, short-range communication, and other technologies. In this layer, the data is received, processed, and forwarded from the device layer. In the cloud layer, all the infrastructure related to CC, such as storage, data centers, and others, are connected to the edge layer through a central network. Among the three-tier model, the key roles of the cloud layer are computation intensive, storage center, data aggregation and analytics, backup and recovery, scalability and flexibility, and centralized management. While the edge and fog layers focus on low-latency processing and immediate data handling, the cloud layer is the powerhouse for intensive computations and extensive storage supporting the overall infrastructure with its scalability and robust capabilities. In some cases, the advantages of edge computing can be leveraged to offload computing services from the cloud to the edge to improve users’ QoE.

In this section the configuration of cloud versus edge computing is described. It is noticed that an edge server is placed between the handled device and the cloud. As a result, the latency is low in edge computing configuration. CC is a model for providing timely, on-request access to divide infrastructure and allow the user to access resources as a service via a network instead of procuring and operating infrastructure and software. Edge computing is a model where the network and computational abilities are brought closer to the data sources, such as computers, smart devices, mobile phones, and routers that connect to the network. The computation time in CC is longer than that in EC. In EC, the computation process happens on the smart devices (IoT) near the client’s location. In CC, the computational process occurs in the data center. EC provides a shorter computation time and reduces waiting time, which ensures the quality of service to the user. Figure 1.3 explains the difference between cloud computing, edge-cloud, and edge computing features. The CC system’s resources are centralized with high processing and computation capacity. The processing is based on artificial intelligence power and has high latency issues due to remote resources. CC has the most potent storage capacity and is fully cyber-secure.

The IoT edge cloud brings together the best cloud and edge computing systems. Both have unique advantages in IoT based on the use case, data analysis, and storage requirements. The combination of both computing resources provides greater flexibility to users, reduces latency time, and protects data privacy standards. In the CC model, the algorithmic processing of tasks increases latency to allow IoT device applications to complete their tasks.

Edge computing geographically decentralizes resources, and the IoT edge cloud shifts cloud storage and computing closer to the edge source while scaling down the size. A computer at the edge of a network and the hardware and software at that location is called an edge. Cloud computing is when work is done in the cloud, while edge computing is done on devices close to the cloud. Edge computing can be used for anything that involves putting services, data, and intelligence closer to users and devices. As the edge-cloud scenario has grown, scheduling problems have received more attention. In the next section, we look at different issues with scheduling when edge clouds work together.

### 1.2 SCHEDULING

Scheduling is critical for assigning tasks in a virtual world, whether in cloud, edge, or fog computing or any mobile computing environment. The performance of the virtual machine server degrades if tasks are not correctly scheduled. According to [3, 4], the scheduler’s main aim is to allocate appropriate methods to optimize available resources to meet one or more objectives. An excellent job scheduler should be able to connect scheduling methods within a dynamically changing environment and different types of tasks. In the current scenario, optimizing resource problems is indeed a challenging task characterized by non-linear trends and dynamic, complex multi-objectives. There are three layers to cloud computing: 1) virtual resources for end users, 2) physical resource allocation to virtual machines by the scheduler, and 3) physical resource maintenance. The scheduling technique for each layer may differ depending on the type of computation complexity.
