Organizations should establish appropriate segmentation and isolation solutions to overcome inadequate separation in order to lessen the effect of any security incidents. # 7.5.4 VM Sprawl

Virtual machines (VMs) that are created and then left running, using resources even after they are no longer required, are referred to as VM sprawl [18]. This could result in a loss of resources, including CPU time, memory, storage space, and network bandwidth, which could affect how well other virtual machines perform when they share a host or infrastructure. As unused or forgotten VMs may not be adequately patched or secured, leaving them exposed to assaults, VM sprawl can potentially provide security problems. Additionally, abandoned VMs might hold private information that, if unattended, could be accessed or taken. Organizations should adopt VM management rules and procedures, such as tracking and monitoring VM consumption as well as routinely assessing and decommissioning unwanted VMs, to prevent VM sprawl. To find and report on VMs that have been inactive or underutilized for a predetermined amount of time, automated tools and scripts can be employed. Assigning ownership and duties to each VM as well as routinely evaluating and updating access control policies are further guidelines and best practices that businesses should create for VM deployment and usage.
