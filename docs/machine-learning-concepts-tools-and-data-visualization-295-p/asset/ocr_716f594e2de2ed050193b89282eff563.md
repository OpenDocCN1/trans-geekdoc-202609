Let's first look at how the neural networks inside AlphaGo are organized.
First, AlphaGo has a network that “predicts the location of the next stone in the current state” (that is, it not only predicts where the opponent will put the stone in the current state, but also predicts where I should it). In certain papers, this is called a ‘policy network’. Naturally, this policy network takes the form of a CNN, so AlphaGo first needed a large amount of data. As stated previously, a CNN requires a great deal of input data and the corresponding output data. To get the output data, we used Go records from the website “KGS”.

Using these game records, a total of 30 million pieces of data were given about where to place the next playing stone, and these were used to learn the policy network. In addition, we prepared and made AlphaGo learn a network called ‘Rollout policy,’ which can calculate the same problem faster than policy networks.

Policy networks are also highly effective. The policy network was able to win Games against high odds without using MCTS. However, networks cannot outperform AlphaGo. As we saw earlier, the search for MCTS required a “value network,” a v(s) that calculates whether the player can win in the current state. Value networks have CNN similar to policy networks.

However, unlike policy networks, value networks yield only probability distributions from the last position of a stone, given as input at the end. To learn this network, AlphaGo saved the data records from self-play games, collecting the winning and losing states, put them into the value network's learning data, and successfully completed the learning. As such, it is believed that AlphaGo conducted MCTS using Policy Networks, Rollout Policy, and Value Networks.

This can be interpreted as AlphaGo implementing a form of human intuition that could not be implemented by a conventional computer algorithm.
