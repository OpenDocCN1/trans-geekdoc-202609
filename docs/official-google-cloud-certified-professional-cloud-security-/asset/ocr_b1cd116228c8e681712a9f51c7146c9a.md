# Best practices for VPC Service Controls

Now you understand the higher-level details of VPC Service Controls perimeters, let us go over some best practices:

+   - A single large perimeter is the simplest to implement and reduces the total number of moving parts requiring additional operational overhead, which helps to prevent complexity in your allowlist process.

+   - When data sharing is a primary use case for your organization, you can use more than one perimeter. If you produce and share lower-tier data as de-identified patient data, you can use a separate perimeter to facilitate sharing with outside entities.

+   - When possible, enable all protected services when you create a perimeter, which helps to reduce complexity and reduces potential什么样的 filters. Make sure that there isn't a path to the private VIP from any of the VPCs in the perimeter. If you allow a network route to private.googleapis.com, you reduce the VPC Service Controls protection from insider data exfiltration. If you must allow access to a non-supported service, try to isolate the use of unsupported services in a separate project, or move the entire workload off the perimeter.

+   - An enterprise has many projects representing different workloads and applications. It is recommended that you organize these projects into folders.

+   - Allow time to gather data, conduct tests, and analyze violation logs. Make sure stakeholders from your network, operations, and applications team are available for the task.

+   - Configure Private Google Access or Private Service Connect with restricted.googleapis.com.

+   - Move any applications using services not on restricted.googleapis.com to a separate project.

+   - Use dry mode when configuring VPC Service Controls to an existing production environment. Make sure you understand the exceptions and errors produced by the dry run mode and whether they match your expectations. For example, certain service accounts as an organization-level log sink will need to be allowed to collect logs. The dry run mode will catch these exceptions that you may not have considered in your design.

+   - Use the VPC Service Controls troubleshooting tool to analyze VPC Service Controls error codes.

+   - Set VPC-accessible services to restricted services to prevent access to unrestricted services.
