## VM Threat Detection

VM Threat Detection (VMTD) is a built-in feature of SCC Premium that detects threats at the hypervisor level. It is part of the threat detection suite and is meant to work alongside ETD and KTD.

## Threat detection

The service executes scans from the hypervisor into the guest's live memory regularly. VMTD analyzes information about software running on VMs, such as a list of application names, per-process CPU usage, hashes of memory pages, CPU performance counters, and information about executed code.

Because VMTD operates outside the guest VM, it does not require guest agents or specific OS configuration, and it is immune to malware countermeasures. Inside the guest VM, no CPU cycles are used, and network access is not required. Signatures do not need to be updated, and the service does not need to be managed. VMTD is not supported on confidential computing since it operates with hardware encryption of memory.

The capabilities of Google Cloud's hypervisor are required for VMTD; it cannot be used on-premises or in other cloud settings.

Here are the threats it will alert you to:

- Execution: Cryptocurrency Mining Hash: Matches memory hashes of running programs against known memory hashes of cryptocurrency mining software.
- Execution: Cryptocurrency Mining YARA Rule: Matches memory patterns, such as proof-of-work constants, known to be used by cryptocurrency mining software.
- Execution: Cryptocurrency Mining Combined Detection: Combines multiple categories of findings detected within a one-hour period. The threats are rolled into a single finding.

**Anomaly detection** is a built-in feature that uses external behavior signals to detect anomalies. It shows details about security abnormalities found in your projects and VM instances, such as potential credentials and currency mining. When you subscribe to the SCC Standard or Premium tier, anomaly detection is turned on immediately, and the results are displayed on the SCC dashboard.

This feature is available for the Standard and Premium versions of SCC. Here are the findings detected by anomaly detection. They are generated in the following two categories:

- **Potential for compromise:**
    - `account_has_leaked_credentials`: Credentials for a Google Cloud service account are accidentally leaked online or are compromised.
    - `resource_compromised_alert`: Potential compromise of a resource in your organization.
