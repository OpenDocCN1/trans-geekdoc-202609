## SAML-based SSO

With SSO, you can configure your enterprise applications to let users sign in using their Google-managed credentials; in others, Google Workspace will act as an identity provider. There are two different options for you to configure SSO: pre-integrated or custom. With the pre-integrated option, Google supports over 300 pre-configured applications that you can deploy from the Cloud Identity console. The custom Security Assertion Markup Language (SAML) option can be used if you have custom applications or applications that are not pre-configured.

It is assumed that you understand how SAML 2.0 works. In this section, we will only look at how to configure SSO using SAML and not cover the foundational knowledge of how Google implements SAML. If you wish to understand more about how SSO using SAML works on Google Cloud, please refer to the *Further reading* at the end of this chapter.

For the purpose of the exam, we will walk through the steps required to configure SSO using SAML for a custom application.

Before we begin, ensure that you have the **Assertion Consumer Service (ACS)** URL and the entity ID, as they will be required when you configure your external IdP and optionally start a URL. Also, determine at this stage whether your external IdP supports **multi-factor authentication (MFA)**; if it does, you can configure the option to use MFA by external IdP, but if some reason your custom application does not support MFA, you can configure Google Identity to enforce MFA.

Now let's look at the steps required to complete the setup using SAML for a custom application:

- 1. Begin logging in to the admin console at `admin.google.com`.
- 2. Navigate from the main console to **Apps | Web and mobile apps**.
- 3. From there, select **Add app | Add custom SAML app**.

These are Google Identity Provider details that will be required by your service provider. ## Additional security features

There are some additional security features that are available in Cloud Identity that are not part of the exam's scope. Therefore, we will briefly cover them here for the purpose of completeness. There will be links in this section and in the Further reading section on some of these topics, which you need to refer. These features include the following:

- Google cloud security center: The security center provides capabilities as advanced security analytics and visibility into security-related issues, all from a central dashboard. From the security dashboard, you can view reports, as reports on user login attempts, file exposure, DLP events, spam-related information, OAuth grant activity, user reports, and on.

> Note
> You can find a full list of reports that you can view from the dashboard here: https://packt.link/yg

Another key capability of the security center is the security investigation tool, which lets you identify, triage, and take action on security-related events.

> Note
> You can learn more about the security investigation tool here: https://packt.link/ovam0.

Finally, the dashboard also provides you with an overview of your security health, which gives you visibility of the admin console and its related activities.

- Monitor and enforce password requirements: You can enforce strong passwords based on your organization's policy. This includes the length, complexity, and expiration of your passwords. You can also stop password reuse so users cannot reuse previously used passwords. The monitoring function lets you monitor the password strength.
