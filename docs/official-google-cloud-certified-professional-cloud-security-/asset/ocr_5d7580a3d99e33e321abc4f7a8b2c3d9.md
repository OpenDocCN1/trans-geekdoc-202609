# Resource Management

In this example organization structure, the first level of folders represents a company’s departments, such as X and Y. As folders have the capability to go up to 10 levels deep (a hard limit), you can create more folders, which could represent different teams, and then further segment into different products. This gives you ability to define access control and permissions at the department level, team level, or product level. Note the policy inheritance is top-down. There is flexibility in modifying the folder tree and it's also possible to move projects, but you have to be mindful of policy inheritance, as that could potentially impact you moving one project, say Team A to Team B. An important decision criterion is to decide on a folder structure that is in line with your policies should be applied.

# Projects

A project is a base-level object that is required for Google Cloud. Your organizations can contain projects and folders. Project is where all your cloud resources are created. Each project is completely separate from other projects and so are the resources inside it. Projects are useful to group specific resources from a functional and access standpoint. There is no cost associated with creating projects and you can create as many as you want (it important to note that there are limits that may apply based on the account type, such as Enterprise versus Developer). Projects are not bound to geographical location and serve as an IAM enforcement point.

Let’s take a look at the construct of a project and what it consists of using the example snippet:

```
{
  "createTime": "2020-01-07T21:59:43.3142Z",
  "lifecycleState": "ACTIVE",
  "name": "my-project",
  "parent": {
    "id": "634792535758",
    "type": "folder"
  },
  "projectId": "my-project",
  "labels": {
    "my-label": "prod"
  },
  "projectNumber": "464036090314"
}
```

Each project has two identifiers: one is a project ID that you can create, and the other is a project number, which is automatically assigned by Google when a project is created and unique. This project is read-only. You can also add labels to projects as if a project is used for production (represented as prod) or for filtering projects. The lifecycle state is displayed as ACTIVE or DELETE_REQUESTED.
