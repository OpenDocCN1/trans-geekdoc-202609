# Load balancers

Let us start by looking at the different types of load balancers:

+   - Global HTTP(S) load balancer:** This load balancer handles both HTTP and HTTPS traffic is a proxy-based Layer 7 function that caters to your services and is configured behind a single external IP address. It can service traffic to different types of Google Cloud services as backends, such as Google Compute Engine, Google GKE, and Cloud Storage. You can use an external HTTP(S) load balancer to distribute and manage traffic for your hybrid workloads in an on-premises environment as well. This load balancer is implemented on Google Front End (GFE) and is global when using Premium Tier but can be configured to regional using Standard Tier.

+   - Regional TCP/UDP load balancer:** This is also referred as a regional network load balancer and is configured as a pass-through. It balances the traffic for VMs in the same region. This is offered as a managed service and can cater to any client on the internet, using Google Compute Engine (NAT). With an external IP address and clients using Cloud Network Address Translation, this load balancer is not a proxy, and it distributes traffic to the backend VMs at the packet's source and destination IP address and protocol. The traffic is terminated directly to the client and not through the load balancer.

+   - SSL proxy load balancer (global):** This is a reverse proxy load balancer that distributes SSL traffic to the nearest backend VMs. The SSL proxy load balancer terminating the TLS requests and forwards the traffic to the backend VM as TLS or TCP. With the HTTP(S) load balancer, based on the network tier, you can configure the SSL proxy load balancer by using Premium Tier or configure it to be regional if using Standard Tier. Both IPv4 and IPv6 are supported, and the traffic is intelligently routed to the backends based on capacity. Self-managed and Google-managed certificates are supported. You can also control the SSL features on the load balancer by configuring SSL policies.

+   - TCP proxy load balancer (global):** This is a reverse proxy load balancer, and it distributes the traffic to the VMs as globally inside the Google Cloud VPC network. It uses a single external IP address for all users globally. All TCP traffic coming from the external is terminated at the load balancer and can be routed to the VMs as TCP or SSL. With this load balancer, you can have global load balancing if using Premium Tier or regional load balancer if using Standard Tier.

+   - Internal TCP/UDP load balancer:** This load balancer distributes traffic to your internal VMs within the region in a VPC. A typical use case is using internal load balancers in a three-tier web architecture, where they can be deployed with an external load balancer. In this architecture, you will have an external HTTP(S) load balancer in front of your web servers and then have internal load balancers behind the web servers to cater and scale traffic to your VMs, which are private and only accessible within the VPC network.
