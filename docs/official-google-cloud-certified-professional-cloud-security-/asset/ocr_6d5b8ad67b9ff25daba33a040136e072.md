# Inspecting and de-identifying PII data

To de-identify sensitive data, use Cloud DLP's content .deidentify method.

There are three parts to a de-identification API call:

+   - **The data to inspect:** A string or table structure (WidgetItem object) for the API to inspect.
- **What to inspect for:** Configuration information (InspectConfig) such as types of data (or infoTypes) to look for, whether to filter findings that are a certain likelihood threshold, whether to return no more than a certain number of results, and so on. Not specifying exactly one infoType in an Inspect argument is equivalent to specifying all built-in infoTypes. Doing so is not recommended, as it can decrease performance and cost.
- **What to do with the inspection findings:** Configuration information (IdentifyConfig) that defines how you want the sensitive data de-identified. This argument is covered in more detail in the following section.

The API returns the items you gave it, in the same format, but any text identified as containing sensitive information according your criteria is de-identified. Now let us look at various de-identification transformations.

# De-identification transformations

We saw how to inspect data many times you want to inspect and de-identify the data. Now we will see how to do that using transformations supported by DLP. You may specify one or more transformations when you set the de-identification configuration (IdentifyConfig). There are two categories of transformations:

+   - **InfoTransformations:** Transformations that are only applied to values within the submitted text that are identified as a specific infoType.
- **RecordTransformations:** Transformations that are only applied to values within submitted tabular data that are identified as a specific infoType, or on an entire column of tabular data.
