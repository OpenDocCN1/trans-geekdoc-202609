## 7.2.1. Data flow diagram (DFD)

Healthcare applications may vary as per the type of service (i.e. online doctor consultation, ordering medicines online, pathological test, any hospital specific for their patients, etc.). Therefore, the detailed data flow will also vary as per the type of application and entities involved in it.

However, in this section, a generic example has been taken which will be same at high level for all types of healthcare applications. This DFD will be used further in this section to analyze threats and security controls. Figure 7.1 helps us to demonstrate a high-level DFD, which includes an end-user on the left who will access the application user interface by using either smart phones or their computers. Then, based on type of services, the user interaction will connect with the Health Application Service at service provider end. During this interaction, data will also flow bidirectionally. The middle part of this DFD, i.e. Health Application Service is the most complex part where all of the processing of data and storage of data will occur based on the type of application and its functionality, since this is high-level DFD, hence this part is shown in a box, otherwise this itself will actually have multiple layers like a web server, an application server, a database server, cloud services, etc. The lower the level on this part, the better and more detailed threat analysis will be.

The final part is also very important, i.e. with the involvement of third parties, as the market is growing, it has been noted that different application providers are collaborating to expand their business. Let us take an example, healthcare application HA1 whose main functionality was to provide an online consultation by doctors to the patients. Later on, HA1 decided to go into business with another company, and created HA2, whose functionality is to sell medicines online. Nowadays, HA2 is integrated on HA1 as a third party. So as soon as patient consultation is completed, the application HA1 tries to automatically redirect the patient to HA2 from their platform to make them buy medicines from HA2. This means that the patient does not need to create any data on HA2, but the application HA1 will transfer the patient’s details and prescription to HA2 via an API. This whole process makes it very easy for the patient and business is increased for both parties, but at the same time, the question of security controls while transferring patient data to a third party also comes to mind. Not only this but also the question of privacy controls comes to mind because now there is a dependency on the third party which is accessing the sensitive personal data of the patient.

## 7.3. Privacy versus security

Before moving further, it is important to understand the difference between security and privacy. This is important because in many organizations and with many security engineers/managers, it has been observed that once security controls are implemented, it is considered that privacy would be taken care of too; however, this is not the case. People get confused because they use both the words interchangeably and consider both means data protection; however, the truth is that security and privacy are different yet have similar components which creates ambiguity.

Information security is about preservation of confidentiality, integrity and availability. The meaning of confidentiality is to keep data safe from unauthorized access, integrity means preserving the accuracy of data and keeping it reliable, and availability means that data should be accessible by authorized users/services whenever required. However, privacy starts from the control of collection of personal data, the control of use of personal data and goes as far as the control of destruction/disposal of data.

It is important to understand that security can be achieved without privacy, but privacy cannot be achieved without security. Security controls focus on all information while privacy controls focus on PII, i.e. personally identifiable information, personal data or sensitive personal data.

To keep it simple, security preserves integrity, confidentiality and availability of data while privacy preserves the protection of privacy rights with respect to the processing of data and data anonymity.

### 7.3.1. Privacy in Blockchain

Before getting into privacy in Blockchain, let us recall some basic terminologies. A distributed ledger is a kind of database which is spread across various computer devices usually in different geographical locations. Distributed ledger technology is the name given to any technology which helps in storing and updating the distributed ledger (Belotti et al. 2019; Ul Hassan et al. 2020). Blockchain is a distributed ledger system that allows for the sharing of a validated ledger of transactions which are kept in blocks and connected by a chain. The genesis block is the very first block on the Blockchain, and all subsequent blocks are added sequentially onto it. Privacy in Blockchain is achieved by three key principles, i.e. cryptography, decentralization and consensus algorithm (Tian et al. 2019; Sharma and Balamurugan 2020):

- **Cryptography:** hashing is a well-known cryptography terminology; hashing is a mathematical function that creates a value of specific size for any data in this case block, and if there is any change in this data (block), the hash value will change. This means that the hash value assures the integrity of data (block). Each block on a Blockchain contains the hash of the previous block, and along with the hash, each block also consists of a timestamp, a nonce and a record, i.e. transaction data. In the term Blockchain, chain is the hash value because it is a reference to the prior block
