## 9.4. Proposed model

The healthcare industry has grown over the past few years, and software technology plays an important role in the evolution of the healthcare sector. Healthcare is one of the most rapidly growing industries that connects many fields directly, physically, emotionally, mentally and financially. The technology related to healthcare faces many challenges: it needs advanced medical devices; it has not used a proper methodology for developing the software system; it requires clinics; rising medical care costs, etc. All of these challenges affect the quality of medical care. So, it requires an advanced business model for healthcare technology that maintains a proper standard for developing any software in which people may trust support. Many healthcare policies help the best software practices and design principles to secure it (Lalband et al. 2019). In developing any healthcare software system, cost, time, effort, trust and security are the main factors that affect the development process. An effective SDLC helps to reduce these kinds of difficulties. SDLC is defined as a framework based on the project context and is helpful for producing high-quality software. Better life-cycle model-based software improves the quality of care of the patient record. Hence, for better-quality healthcare software used for tracking and processing patient information effectively. It reduces manpower requirement and treatment costs, and easily accesses patient information on time (Katuwal et al. 2018; De Aguiar et al. 2020).

Traditional models do not have better support to develop large and complex software, and hence, fail to provide better quality and accuracy. Therefore, the developer chooses another advanced SDLC model technique that solves the above issues. This advanced SDLC model technique is based on CBSE, in which software systems are developed by selecting reliable and reusable components, and assembling them together with the suitable software architecture. This new approach is different from the conventional approach, where software is not developed from scratch. It consists of two life-cycles that work in parallel, one is a component-based development life-cycle and another one is a system development life-cycle through components (Kaushik et al. 2012; Kumar et al. 2014). This approach increases the software’s productivity and performance, but does not increase its reliability and trust due to the selection of software components, which are not always trustworthy and reliable. Hence, the developer needs to better software development life-cycle with advanced technologies such as Blockchain, cloud computing, AI and IoT that increase the reliability and trust in them (Angraal et al. 2017; Bell et al. 2018).

In the proposed method, we have looked at the impact of the healthcare sector using a new technology called Blockchain. Blockchain is one of the technologies that can be used to secure our data and increase our trust in any application. This technology is becoming popular because of its features such as security, decentralization, immutability and transparency. In this chapter, we have developed a component-based life-cycle model using Blockchain technology and created a Blockchain-based repository that stores software components in the form of blocks. Using Blockchain-based software, we try to keep a patient record in the form of a block, which can be made available securely, and only to authorized users. The doctors may easily access and store the medical history of the patients anytime and anywhere. Hence, this type of software product increases the patient’s trust, and this data cannot be misused by unauthorized persons. The life-cycle of CBSE is different from the traditional way of developing software. It works simultaneously through two development life-cycles, namely a component development life-cycle and a component-based software development life-cycle.

### 9.4.1. Component-based software development life-cycle

The software development life-cycle with components includes all the activities of the software system’s production. In this cycle, the software system is built by using pre-existing components that are stored in a repository. Software developers reuse these components according to the requirement of their applications. It contains the following phases: requirement, system specification, component search and selection, component identification, component adaptation, system implementation by assembling the component, system testing and verification and system deployment, as shown in Figure 9.14. The first phase is the requirement phase, in which all the initial requirements of the users are identified. The developer understands and identifies these requirements for a particular application. After collecting the requirements, the developer analyzes the feasibility of the component on the basis of the requirements. In this phase, the developer also studies the software application’s constraints, functional and non-functional requirements, and prepares a document for the requirement specifications of the system.

In the next step, developers search and select the desired components in an internal reusable repository using various searching techniques (such as keyword-based, faceted, enumerated, attribute value, signature-based techniques, etc.). If the required components are not available in the repository, then the developer needs to implement components via Blockchain technology. Using the component development life-cycle, the developer creates a component in the form of a block, stores it in a Blockchain-based component repository and provides proper indexing. In this phase, the developer decides which component should be reused and should be built from scratch using the system requirements for building the software system. The next phase is the component identification phase, in which the developer identifies the target component and selects the component that satisfies the needs of the software system being developed. Domain engineering (product line engineering) is helpful in this phase. The next phase is the component adaptation phase. After selecting the candidate component, some of the selected components may not fit as per the specifications required by the software. There may be a gap between the component features and features required from the component by the system architect. The component adaptation techniques (such as component wrapping, coordinate, adaptation pattern) help to minimize these mismatches between the component required and component available. In the next phase, if the verified component fits their specific system requirement, then the developer composes the software through these verified components. After constructing the system through the composition of the component, the next phase is system testing and verification. In this phase, the system requirements should be matched with the final implemented system. In this step, the developer follows some standard testing and verification techniques. The developer also checks undesirable effects and errors in the software application. In the last phase, the final software product is delivered to the customer for its use. Before reaching the customer, this product is well examined and corrected for faults, and the adaptation of the system in a changing environment is confirmed.

### 9.4.2. Component development life-cycle

When a component is not found in the repository, the developer creates a new component from scratch, as shown in Figure 9.14. The life-cycle of component development contains the following phases: domain specification of the component, implementation of the component as a block, testing and verification through the consensus algorithm, deployment of the component, component code storage and indexation. The first phase is the domain specification of the component. It provides the information from the domain knowledge of the new component to build a software system. This phase helps the developer to understand the domain knowledge of application and systematic component reuse. After understanding the domain specification of the component, the developer develops a component according to system requirements. This phase aims to develop a component in the form of a block via Blockchain technology. The developer considers every component as a block in Blockchain, and the block is linked by a cryptographic hash. To create a component, the developer firstly initializes the genesis block. It is the first block in the Blockchain to which the other blocks are connected. Then, it creates a new block that stays connected to the genesis block. This new block divides into two parts. The first part is the header that stores the index of the block, timestamp and proof of work. The second part stores the component’s data. Here, the data is stored in JSON format.
