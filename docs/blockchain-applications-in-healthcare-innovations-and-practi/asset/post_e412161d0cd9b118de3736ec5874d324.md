
### 9.3.1.4. Spiral model

The spiral model is one of the most famous models of SDLC, as shown in Figure 9.7. The spiral model looks like a spiral with many loops. Each loop represents a phase of a software process, such as determining objectives, identifying and resolving risks, development and testing, and planning the next iteration (Kumar et al. 2014). To develop the large and complex software, the spiral model is used in a real-time application. This model is helpful for reducing the risk factor of the project because it applies a risk reduction mechanism for analyzing risk at any stage. That is why it is known as a risk-driven process model. This model is used to build a high-quality product.

![](img/9f63232d0022c87774dc3933e40b24aa_185_0.png)

Figure 9.7. Spiral model for software development (Kumar et al. 2014)

### 9.3.1.5. Agile model

The agile model is based on the iterative development approach (Barjtya et al. 2017). In the agile model, the whole software project is divided into smaller iterations and each iteration is considered as a frame, as shown in Figure 9.8. This division helps us to minimize the risk factor of the project and reduces time and cost.

Each iteration goes through phases of the agile model, such as analyze, plan, design, develop, deploy and maintenance. This type of model is used when the customer needs more functional requirements with less time and effort. Hence, it gives more accurate, high-quality, flexible and reliable software products.

![](img/9f63232d0022c87774dc3933e40b24aa_186_0.png)

Figure 9.8. Agile model for software development

## 9.3.2. Modern software development methodologies

Some of the traditional models are based on a predictive approach, but the user needs to use the software life-cycle based on an adaptive approach. It must be flexible to accommodate the changing demands of the customer. Therefore, the developer moves to choose another modern software model that supports adaptive approach. In this section, we have discussed various component-based software development life-cycle models (Kaushik et al. 2012; Kumar et al. 2014).

### 9.3.2.1. V model

The V model is an improved model of the waterfall model, which is also called the verification and validation model (Chaudron et al. 2005). The verification phase exists on one side, and the validation phase exists on the other side, as shown in Figure 9.9. The verification stage locates model design with the help of requirement analysis. On the other hand, the validation phase checks the functionality and bugs with the help of testing. This type of model is suitable when the testing and deployment phases are run in parallel. This model is very useful, but it faces the difficulty that the developer never returns once the task is finished. Before developing the software, it is necessary to create a system test plan. This test plan is based on the functional requirement of the project. This model is suitable for large-scale projects where a lot of planning is involved.

![](img/9f63232d0022c87774dc3933e40b24aa_187_0.png)

Figure 9.9. V model for software development (Chaudron et al. 2005)

### 9.3.2.2. Y model

Capretz et al. (2005) proposed the Y model. This model is based on a component-based development approach, as shown in Figure 9.10. The model's Y form makes it easier to iterate and overlap in appropriate places. Domain engineering, framework, assembly, archiving, system analysis, design, implementation, testing, deployment and maintenance are some of the anticipated phases. This model supports change instability and the reusability concept for developing any software product. This model mainly focuses on software reusability during component-based development and emphasizes reusability when software is developed, evolves and desired reusable components are built on the assumption.

![](img/9f63232d0022c87774dc3933e40b24aa_188_0.png)

Figure 9.10. Y model for software development (Capretz et al. 2005)

### 9.3.2.3. W model

![](img/9f63232d0022c87774dc3933e40b24aa_188_1.png)

Figure 9.11. W model for software development (Lau et al. 2011)

This model is based on the V model, in which two V models are joined and work together, as shown in Figure 9.11. The first V model depicts the component life-cycle, while the second depicts the system life-cycle (Lau et al. 2011). The model is divided into two phases, one for component design and the other for component deployment. In the design phase, according to the domain engineering, software components are identified, designed and implemented. After building the component, it is stored in a repository, whereas in the deployment phase, the product is constructed and deployed using these already developed components.

### 9.3.2.4. X model

Tomar and Gill (2010) proposed the X model, which depicts how reusable components are used in complex and large-scale software projects. This model mainly focuses on reusability for developing software through the use of reusable components. As illustrated in Figure 9.12, the X model's life-cycle is divided into four sub-cycles: component-based software development, development for reuse, development after modification and development without modification. This model supports the overlapping of different phases and increased complexity for developing any software.

![](img/9f63232d0022c87774dc3933e40b24aa_189_0.png)

Figure 9.12. X model for software development (Tomar et al. 2010)

### 9.3.2.5. An improved model

Irshad and Noor proposed this model in 2012 (Khan and Khan 2012). In this model, the component development life-cycle and component-based system development life-cycle work in parallel, as shown in Figure 9.13. In this model, the authors discussed some issues related to component-based development and tried to reduce this issue by merging the traditional software development life-cycle model and component-based software development life-cycle model. This model helps us to resolve the problem related to unsatisfied requirements, repository management and the component's version handling.

![](img/9f63232d0022c87774dc3933e40b24aa_190_0.png)

Figure 9.13. An improved model for software development (Khan et al. 2012)
