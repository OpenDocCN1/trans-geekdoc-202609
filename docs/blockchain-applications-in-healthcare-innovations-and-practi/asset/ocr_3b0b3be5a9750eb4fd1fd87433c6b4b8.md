The life-cycle of CBSE is different from the traditional way of developing software. It works simultaneously through two development life-cycles, namely a component development life-cycle and a component-based software development life-cycle.

# 9.4.1. Component-based software development life-cycle

The software development life-cycle with components includes all the activities of the software system’s production. In this cycle, the software system is built by using pre-existing components that are stored in a repository. Software developers reuse these components according to the requirement of their applications. It contains the following phases: requirement, system specification, component search and selection, component identification, component adaptation, system implementation by assembling the component, system testing and verification and system deployment, as shown in Figure 9.14. The first phase is the requirement phase, in which all the initial requirements of the users are identified. The developer understands and identifies these requirements for a particular application. After collecting the requirements, the developer analyzes the feasibility of the component on the basis of the requirements. In this phase, the developer also studies the software application’s constraints, functional and non-functional requirements, and prepares a document for the requirement specifications of the system.

In the next step, developers search and select the desired components in an internal reusable repository using various searching techniques (such as keyword-based, faceted, enumerated, attribute value, signature-based techniques, etc.). If the required components are not available in the repository, then the developer needs to implement components via Blockchain technology. Using the component development life-cycle, the developer creates a component in the form of a block, stores it in a Blockchain-based component repository and provides proper indexing.
