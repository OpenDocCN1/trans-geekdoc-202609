# 7.2.1. Data flow diagram (DFD)

Healthcare applications may vary as per the type of service (i.e. online doctor consultation, ordering medicines online, pathological test, any hospital specific for their patients, etc.). Therefore, the detailed data flow will also vary as per the type of application and entities involved in it.

However, in this section, a generic example has been taken which will be same at high level for all types of healthcare applications. This DFD will be used further in this section to analyze threats and security controls. Figure 7.1 helps us to demonstrate a high-level DFD, which includes an end-user on the left who will access the application user interface by using either smart phones or their computers. Then, based on type of services, the user interaction will connect with the Health Application Service at service provider end. During this interaction, data will also flow bidirectionally. The middle part of this DFD, i.e. Health Application Service is the most complex part where all of the processing of data and storage of data will occur based on the type of application and its functionality, since this is high-level DFD, hence this part is shown in a box, otherwise this itself will actually have multiple layers like a web server, an application server, a database server, cloud services, etc. The lower the level on this part, the better and more detailed threat analysis will be.

The final part is also very important, i.e. with the involvement of third parties, as the market is growing, it has been noted that different application providers are collaborating to expand their business. Let us take an example, healthcare application HA1 whose main functionality was to provide an online consultation by doctors to the patients. Later on, HA1 decided to go into business with another company, and created HA2, whose functionality is to sell medicines online. Nowadays, HA2 is integrated on HA1 as a third party. So as soon as patient consultation is completed, the application HA1 tries to automatically redirect the patient to HA2 from their platform to make them buy medicines from HA2.
