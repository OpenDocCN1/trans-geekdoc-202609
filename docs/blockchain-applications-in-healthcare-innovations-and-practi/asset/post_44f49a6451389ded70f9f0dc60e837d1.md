## 9.3. Software development models

A software development process generally requires a framework that is used to analyze, plan, control and manage the process of software development. This framework is known as a software development life-cycle model (SDLC). An SDLC model is a systematic process for developing and designing a project from the beginning stage to completion (McMurtrey et al. 2013; Kneuper et al. 2017). A good software developer always chooses the best SDLC model based on the project context and user requirements for developing software. It provides a sequence of activities that helps to process, develop and maintain software products with improved quality and reliability. Different software life-cycle models may suit a project based on the user’s requirement, cost, development time and project risks. In this chapter, we have discussed a comparative study of traditional software development life-cycle models, as well as modern software development life-cycle models based on component-based development. Traditional models do not support rapid changes in the requirements. They only focus on documentation rather than reliability or trust. In comparison, modern models handle these unwanted changes in the requirements successfully. They produce high-quality software in less time and maintain reliability and trust.

The basic software development model contains five stages: requirement analysis, design, implementation, testing and deployment, as shown in Figure 9.3.

![](img/9f63232d0022c87774dc3933e40b24aa_180_0.png)

Figure 9.3. Basic model for software development

- Requirement analysis: the first phase of developing software is the requirement analysis phase, in which developers analyze the need for software products according to the client. This phase collects detailed information about the desired product from the client and analyzes its functionality, development cost, technical issues, etc. After analyzing the desired product requirements, the developer prepares a document for the software product, which is called a software requirements specification (SRS).

- Design: in this phase, the developer designs the basic structural framework of the software system. Developers decide what architecture and programming language are best for product development, which technology should be used, the constraints of the project, and how much time and budget should be used for developing software. This phase also decides how different modules of architecture communicate among them.

- Implementation: in the implementation phase, developers actually start the development process according to SRS. This phase is also known as the building phase. In this phase, the developer follows all the standard guidelines of coding.

- Testing: this phase is the last phase of SDLC before delivering the final software product to the customer. In this phase, the developer tests the final product, tracks where the bug is present in the implementation code and reports it. The testing phase confirms whether the final product meets the customer’s requirement.

- Deployment: once the software system is ready, the developer deploys this product for the user. In this phase, the developer releases the tested software products in the appropriate market. The developer releases their software products in a limited segment and analyzes their acceptance rate. After analyzing the acceptance rate, the product is released in a particular market based on the product’s response.

In this chapter, we have given a brief comparative study of various software development life-cycle models and divided the software development life-cycle model into two categories. The first one is a traditional software development model, and the second one is a modern software development model based on CBSE.

### 9.3.1. Traditional software development methodologies

In this section, we have tried to illustrate some traditional software development models (Kaushik et al. 2012).

### 9.3.1.1. Waterfall model

The waterfall model is the first model, introduced by Royce in 1970 (Despa 2014). Another name for this model is a linear sequence life model, as all of the phases are executed one by one, as shown in Figure 9.4. Hence, the next phase starts only when the previous phase is fully executed. It does not allow us to go back to the previous step. It contains various phases, such as requirement analysis, system design, implementation, testing, deployment and maintenance (Kumar et al. 2014). The first phase in this model is the analysis of the requirements of the project. After analyzing, the next phase is the designing phase, in which the developer designs the framework of system according to the requirements and specifies the overall system architecture. After design, the next phase is the implementation phase, in which the design structure is translated into a programming language. After the development of the final product, the developers apply testing mechanisms, verify whether the product meets all of the user requirements or not, and detect faults and failures. The next step is the deployment phase, in which the product is deployed into the market for client use. The last phase is the maintenance phase. In this phase, the developer checks some issues after deploying the product in the client environment. If a problem occurs, they resolve that problem, increase productivity and release it. This model is used only for small projects and serves as a baseline for other models.

![](img/9f63232d0022c87774dc3933e40b24aa_182_0.png)

**Figure 9.4. Waterfall model for software development**

### 9.3.1.2. Iterative model

The iterative model is approximately similar to the traditional waterfall model, as shown in Figure 9.5. The traditional model follows the step-by-step process for developing a project, but the iterative model follow the cyclic process. The iterative model provides a feedback path in the preceding phase. After completing the project, developers can easily go back to the particular phase where an error has occurred. The feedback paths allow the reworking of the phase where the error was detected. This model contains various phases, such as requirement analysis, system design, implementation, testing, deployment and maintenance (Despa et al. 2014). The process of developing a project starts from a requirement phase. After collecting the product requirements from the client, the developer starts to design the project and finally implements the software product code on the basis of collecting requirements. After completing the coding, the developer applies some test methods to find an error. Once an error is detected, the developer goes back to that particular phase where the error occurred and corrects that error. At the end, it deploys the product in the client working environment. After deploying the product, if any bugs or errors are presented in the software, the developer updates the product with the help of a debugging process. This model is useful for small software applications.

![](img/9f63232d0022c87774dc3933e40b24aa_183_0.png)

Figure 9.5. Iterative model for software development

### 9.3.1.3. Prototyping model

The prototyping model suggests that before developing the actual product, developers propose a working prototype of the software system (Despa et al. 2014). This model is used when the client does not know the exact requirement of the product and technical solutions are unclear to the developer. In this model, developers firstly develop a prototype of the product, then test and refine it on the basis of customer feedback. They repeat this process until the final acceptable prototype is achieved. After accepting the prototype, the developer designs, implements and tests the final product. This model contains various phases, as shown in Figure 9.6, such as requirement gathering, quick decision, build prototype, customer evaluation of prototype, refine requirements based on customer suggestions, design, implementation, test and maintenance. This model is useful in the absence of detailed information about the final product.
