function bid() public payable {
    require(
    now <= AuctionCompleteTime,
    "Auction already ended."
    );
    require(
    msg.value > LargestBid,
    "There already is a higher bid."
    );

    if (LargestBid != 0) {
        pendingReturns[LargestBidder] += LargestBid;
    }

    LargestBidder = msg.sender;
    LargestBid = msg.value;

    emit LargestBidIncreased(msg.sender, msg.value);
}

function withdraw() public returns (bool) {
    uint amount = pendingReturns[msg.sender];

    if (amount > 0) {
        pendingReturns[msg.sender] = 0;

        if (!msg.sender.send(amount)) {
            pendingReturns[msg.sender] = amount;

            return false;
        }

    }

    return true;
}

function auctionEnd() public {
    require(now >= AuctionCompleteTime);
    require(!ended);
    ended = true;
    emit CompleteAuction(LargestBidder, LargestBid);
    beneficiary.transfer(LargestBid);
}

## Smart Contract 2.1.

The function bid() places a bid on the auction using the value supplied. If the auction is not won, the value will be reimbursed. The method withdraw() removes an overbid bid, while the function auctionEnd() closes the auction and delivers the greatest bid to the recipient.

## 2.5.2. Voting

```solidity
pragma solidity ^0.4.22;

contract Ballot {
  struct Balloter {
    bool castedcastvote;
    uint weight;
    address delegate;
    uint castvote;
  }

  struct Selection {
    bytes32 name;
    uint countCastvote;
  }

  address public chief;
  mapping(address => Balloter) public balloter;
  Selection[] public Selections;

  constructor(bytes32[] NameSelection) public {
    chief = msg.sender;
    balloter[chief].weight = 1;
    for (uint i = 0; i < NameSelection.length; i++) {
      Selections.push(Selection({
        name: NameSelection[i],
        countCastvote: 0
      }));
    }
  }

  function Balloterights(address balloter) public {
    require(
      msg.sender == chief,
      "only chief has access to give the castvote."
    );
    require(
      !balloter[balloter].castedcastvote,
      "already castedcastvote."
    );
    require(balloter[balloter].weight == 0);
    balloter[balloter].weight = 1;
  }

  function delegate(address to) public {
    Balloter storage messenger = balloter[msg.sender];
    require(!messenger.castedcastvote, "finish voting.");
    require(to != msg.sender, "Self-delegation is not permitted.");
    to = balloter[to].delegate;
    require(to != msg.sender, "Delegation loop discovered.");
    messenger.castedcastvote = true;
    messenger.delegate = to;
    Balloter storage delegate_ = balloter[to];
    if (delegate_.castedcastvote) {
      Selections[delegate_.castvote].countCastvote += messenger.weight;
    } else {
      delegate_.weight += messenger.weight;
    }
  }

  function castvote(uint Selection) public {
    Balloter storage messenger = balloter[msg.sender];
    require(!messenger.castedcastvote, "finish voting.");
    messenger.castedcastvote = true;
    messenger.castvote = Selection;
    Selections[Selection].countCastvote += messenger.weight;
  }

  function SelectionWin() public view returns (uint SelectionWin_) {
    uint winningCountCastvote = 0;
    for (uint p = 0; p < Selections.length; p++) {
      if (Selections[p].countCastvote > winningCountCastvote) {
        winningCountCastvote = Selections[p].countCastvote;
        SelectionWin_ = p;
      }
    }
  }

  function NameWinner() public view returns (bytes32 NameWinner_) {
    NameWinner_ = Selections[SelectionWin()].name;
  }
}
```

## Smart Contract 2.2.

The function contract ballot declares a new complex type for variables. It symbolizes one balloter. A single Selection is a type of struct Selection. Mapping(address => Balloter) defines a state variable that holds a Balloter struct for each address. The function Balloterights(address balloter) does the following operations: If the initial argument of require responds to false, then operation is terminated and all modifications to the configuration and Ether amounts are reversed. This can be used to utilize all of the gas in prior EVM iterations, but it no longer does. To ensure that services are called correctly, it is usually a good strategy to use require. We may also give an explanation for what went wrong as a second argument. The function delegate() is used to assign a castvote to the balloter. The castvote() function returns the castvote (including castvotes cast) for Selection Selections[Selection].name. The function SelectionWin() calculates the winning Selection by considering the account of all previous castvotes. The NameWinner() function runs the SelectionWin() function to retrieve the winner's index from the Selections array and callback the winner's name.

## 2.6. Challenges related to smart contracts

Smart contracts, being an emerging technology in its early stages, are now afflicted by a plethora of difficulties and roadblocks. This section will describe the issues with smart contracts, as well as current research developments.

### 2.6.1. Contract vulnerabilities

- Transaction-ordering dependence (TOD): each block includes numerous activities, and the miner determines the order that they are completed in. TOD occurs when a large number of reliant actions execute the same contract in a manner in which the miners have influence over the sequence wherein the transactions are performed.

- Timestamp dependence: the miners calculate the date and time for the transaction generated. They may change the timestamp by a few seconds if other miners approve the transaction they provided. The problem comes from the fact that certain smart contracts use a time as a triggering event, such as a payment system, and thus an adversary might be altered.

- Mishandled exceptions: once a contract communicates with another, the present operation pauses for the call to complete before proceeding. The caller may or may not be notified of this exception. To verify that the call was completed, the responder should expressly check the callee's callback function. Nevertheless, if the client refuses to properly examine the callback function, it may lead to potential dangers.

- Re-entrancy vulnerability: once a contract communicates with another, the present operation pauses for the call to complete before proceeding. Also, because the fallback method enables an intruder to re-enter the caller's method, an intruder may take advantage of the sender's initial point to conduct repeated calls, culminating in loops of invocations that get many reimbursements and drain the balance. One of the most well-known re-entry vulnerabilities is the Decentralized Autonomous Organizations (DAO) attack (CoinDesk n.d.).

Some security analysis tools are being developed to address contract issues. Since many contract problems are caused by a lexical mismatch among developers' knowledge of the underlying executing meanings smart contracts, Luu et al. (2016) developed Oyente, a symbolic processing tool, to identify possible security bugs in Ethereum smart contracts. Oyente identified 8,833 Ethereum smart contracts as susceptible out of 19366, including the DAO bug. Its analysis is divided into two steps: first, it symbolically examines the dependency structure of the contract in order to elicit precise linguistic metadata from the program. After this, it analyses violation and different activities to see if they capture enough criteria to determine if a property is valid or not. Many flaws, like transaction reordering, repetitive calls, unsafe code patterns and so on, can be analyzed by Securify. Manticore (GitHub n.d.) seems to be another regular expression technique for evaluating binary and smart contracts. It is capable of capturing a program execution trail for each produced input.
