In the 1960s, there was no method or framework for the development of the software process model. The developer collects all of the information related to software in text form. Hence, it was not able to properly understand what exactly the user wanted. Due to this, developing software was time-consuming and needed more effort. But today, the definition of the software development process is different. They follow standards and methods to create any kind of project. SDLC uses these standards to collect and analyze requirements related to the development process systematically. There are various SDLC methodologies, such as the waterfall model, iterative model, prototyping model, spring model, agile model, etc., which are used for software development. Each SDLC model is different from the other. But these models are older and do not give more functionality to the user or support rapidly changing requirements. Today, due to more expectations of user requirements, the developer is bound to create large and complex software. These traditional models are not fit to develop large and complex software and never give better quality and accuracy. Hence, the developer needs to choose another advanced SDLC model technique that removes the above issues and uses less time, cost and effort to develop software. It also ensures that transparency between the developers is maintained, developing speed is enhanced and the risk factor is minimized. At the end, users get a high-quality product that fulfills user requirements. This advanced SDLC model technique is based on component-based software engineering (CBSE).

CBSE is an advance development approach in which software products are developed by selecting reliable and reusable components, and assembled using the appropriate software architecture (Mahmood et al. 2007; Vale et al. 2016). Here, the component is various software modules, packages, self-unit codes that are executed, verified and deployed independently. The main aim of adopting this technique is to increase productivity, lower cost and time to market, and improve performance and quality. This new concept is different from the traditional approach, where software is not developed from scratch. The CBSE approach consists of two life-cycles that work in parallel, one is a component-based development life-cycle and another is a system development life-cycle through component. When a developer wants to create any software using the CBSE approach, they search for the desired components in the software repository. If the desired components are present in the repository, then they assemble these components and construct a software product. If the desired component is not presented in the repository, then they create it from scratch. The development of an SDLC based on CBSE plays an important role in providing better-quality and cost-effective software (Aoyama 1998; Cai et al. 2000). A better development life-cycle model helps to reduce time, cost and effort and increases the performance and quality of the software. Although this approach increases the software’s productivity and performance, it does not increase reliability and trust in them as the selection of expected software components to develop the software is not always trustworthy and reliable. Hence, the developer needs to improve our software development life-cycle with advance technologies
