The next phase is the component identification phase, in which the developer identifies the target component and selects the component that satisfies the needs of the software system being developed. Domain engineering (product line engineering) is helpful in this phase. The next phase is the component adaptation phase. After selecting the candidate component, some of the selected components may not fit as per the specifications required by the software. There may be a gap between the component features and features required from the component by the system architect. The component adaptation techniques (such as component wrapping, coordinate, adaptation pattern) help to minimize these mismatches between the component required and component available. In the next phase, if the verified component fits their specific system requirement, then the developer composes the software through these verified components. After constructing the system through the composition of the component, the next phase is system testing and verification. In this phase, the system requirements should be matched with the final implemented system. In this step, the developer follows some standard testing and verification techniques. The developer also checks undesirable effects and errors in the software application. In the last phase, the final software product is delivered to the customer for its use. Before reaching the customer, this product is well examined and corrected for faults, and the adaptation of the system in a changing environment is confirmed.

# 9.4.2. Component development life-cycle

When a component is not found in the repository, the developer creates a new component from scratch, as shown in Figure 9.14. The life-cycle of component development contains the following phases: domain specification of the component, implementation of the component as a block, testing and verification through the consensus algorithm, deployment of the component, component code storage and indexation. The first phase is the domain specification of the component. It provides the information from the domain knowledge of the new component to build a software system. This phase helps the developer to understand the domain knowledge of application and systematic component reuse. After understanding the domain specification of the component, the developer develops a component according to system requirements. This phase aims to develop a component in the form of a block via Blockchain technology. The developer considers every component as a block in Blockchain, and the block is linked by a cryptographic hash. To create a component, the developer firstly initializes the genesis block. It is the first block in the Blockchain to which the other blocks are connected. Then, it creates a new block that stays connected to the genesis block. This new block divides into two parts. The first part is the header that stores the index of the block, timestamp and proof of work. The second part stores the component’s data. Here, the data is stored in JSON format.
