| Categories | Models | Advantages | Disadvantages |
| :--- | :--- | :--- | :--- |
| Traditional software development models | Waterfall model | - Simple and easily understandable<br>- Easy to manage<br>- Logical ordering<br>- Simple planning and well-documented | - Risk involvement is high<br>- Cannot go back to any stage after finishing<br>- No accepted flexibility to change<br>- No support for long-term project |
| | Iterative model | - Allows user to give feedback when the requirements are not clear<br>- More flexible when compared to the Waterfall model<br>- Emphasizes design over documentation of the project | - Iteration can be costly<br>- More management is required<br>- No support for long-term projects<br>- Lack of proper documentation |
| | Prototyping model | - Accepts requirement changes rapidly<br>- Reduces risk factor<br>- Able to build a demo version of software<br>- Easily identifies missing functionality | - Developer effort increases<br>- Complexity of project increases<br>- Implementation of prototypes is costly |
| | Spiral model | - Easy to plan and good negotiation<br>- Supports risk management<br>- Supports long-term project<br>- Strong documentation | - More complicated compared to others<br>- Requires high skill developers for analysis and planning<br>- Can be a costly model<br>- No support for small projects |
| | Agile model | - Understandable requirement document<br>- Reduces this factor<br>- Supports small project<br>- Promotes maintainability | - Costly model<br>- End requirement of project is not clear<br>- Highly experienced people needed<br>- Lack of proper documentation |
