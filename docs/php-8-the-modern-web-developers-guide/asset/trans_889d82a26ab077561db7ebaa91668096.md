

SQL 注入是 Web 应用程序中常见的攻击向量。PHP 8 鼓励结合 `PDO` 或 `MySQLi` 使用预处理语句，以安全地执行数据库查询。预处理语句将 SQL 代码与用户输入分离，防止恶意输入改变查询的结构。

```php
// 使用 PDO 预处理语句

$pdo = new PDO("mysql:host=localhost;dbname=mydb", $username, $password);

$stmt = $pdo->prepare("SELECT * FROM users WHERE username = :username");

$stmt->bindParam(':username', $userInput);

$stmt->execute();
```

### 跨站请求伪造 (CSRF) 防护

为了防范 CSRF 攻击，PHP 开发者可以生成并验证 CSRF 令牌。这些令牌对每个用户会话都是唯一的，并包含在表单中。当表单提交时，服务器会验证令牌的有效性，以确保请求源自同一站点。

```php
// 生成和验证 CSRF 令牌

session_start();

if (!isset($_SESSION['csrf_token'])) {
    $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
}

if ($_POST['csrf_token'] === $_SESSION['csrf_token']) {
    // 处理表单
} else {
    // 无效的 CSRF 令牌
    die("CSRF detected. Request denied.");
}
```

### 密码哈希

安全地存储用户密码至关重要。PHP 8 包含 `password_hash()` 函数，用于使用 bcrypt 或其他强算法安全地哈希密码。此外，`password_verify()` 函数可用于在登录期间验证用户输入的密码。

```php
// 哈希和验证密码

$password = $_POST['password'];

$hashedPassword = password_hash($password, PASSWORD_BCRYPT);

if (password_verify($password, $hashedPassword)) {
    // 密码有效
} else {
    // 密码无效
}
```

### 内容安全策略 (CSP)

实施内容安全策略 (CSP) 是减轻跨站脚本 (XSS) 攻击风险的有效方法。PHP 8 Web 应用程序可以发送 CSP 标头，指示浏览器允许执行哪些脚本和资源。这有助于防止注入到页面中的恶意脚本执行。

```php
// 设置内容安全策略标头

header("Content-Security-Policy: default-src 'self'");
```

### 定期更新和安全补丁

保持 PHP 版本、Web 服务器及所有库的最新状态对于安全至关重要。PHP 8 开发者应定期检查安全更新并及时应用，以防范已知漏洞。

### 安全文件上传

如果您的 Web 应用程序允许文件上传，请实施严格的安全措施以安全地验证和存储上传的文件。限制文件类型，执行服务端验证，并使用唯一文件名以防止恶意上传。

```php
// 安全文件上传

$targetDirectory = "uploads/";

$targetFile = $targetDirectory . basename($_FILES["file"]["name"]);

if (move_uploaded_file($_FILES["file"]["tmp_name"], $targetFile)) {
    // 文件上传成功
} else {
    // 文件上传失败
}
```

总之，在构建 PHP 8 Web 应用程序时，安全的 Web 开发实践至关重要。通过遵循这些安全注意事项，例如清理用户输入、使用预处理语句、实施 CSRF 防护以及应用其他安全措施，开发者可以创建能够抵御常见安全威胁和漏洞的 Web 应用程序。定期更新并了解安全最佳实践对于维护 PHP 8 Web 应用程序的安全性至关重要。

## 9.4. PHP 8 中的 RESTful API 开发

表述性状态转移 (REST) 是一种用于设计网络应用程序的架构风格。由于其简洁性和可扩展性，RESTful API 已成为构建 Web 服务的标准。在本节中，我们将探讨如何使用 PHP 8 开发 RESTful API。

### 创建 API 端点

API 端点是客户端用于与您的 RESTful API 交互的 URL。在 PHP 8 中，您可以使用 `Symfony`、`Laravel` 等框架，或通过手动定义路由来创建 API 端点。以下是使用原生 PHP 定义简单 API 端点的示例：

```php
// index.php

if ($_SERVER['REQUEST_METHOD'] === 'GET' && isset($_GET['resource'])) {
    $resource = $_GET['resource'];

    if ($resource === 'items') {
        // 返回项目列表
        $items = ['item1', 'item2', 'item3'];
        echo json_encode($items);
    } elseif ($resource === 'users') {
        // 返回用户列表
        $users = ['user1', 'user2', 'user3'];
        echo json_encode($users);
    } else {
        // 无效资源
        http_response_code(404);
        echo json_encode(['error' => 'Resource not found']);
    }
} else {
    // 无效请求
    http_response_code(400);
    echo json_encode(['error' => 'Invalid request']);
}
```

在本示例中，API 有两个端点：`/index.php?resource=items` 和 `/index.php?resource=users`。当客户端向其中一个端点发起 `GET` 请求时，API 返回 JSON 数据。

### 处理 HTTP 方法

RESTful API 使用 HTTP 方法（`GET`、`POST`、`PUT`、`DELETE` 等）对资源执行操作。PHP 8 允许您使用 `$_SERVER['REQUEST_METHOD']` 变量处理这些方法。以下是处理 `POST` 请求以创建新资源的示例：

```php
// 创建新项目 (POST 请求)

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $data = json_decode(file_get_contents('php://input'), true);

    // 验证并创建新项目
    // ...

    // 返回创建的项目
    echo json_encode(['message' => 'Item created successfully']);
}
```

### RESTful 路由

路由是 RESTful API 开发的关键方面。它将 URL 映射到特定的操作或资源。`Laravel` 和 `Symfony` 等框架提供了路由系统，使定义路由和控制器变得容易。以下是使用 `Laravel` 的简单示例：

```php
// routes/api.php

use Illuminate\Support\Facades\Route;

Route::get('/items', 'ItemController@index');
Route::post('/items', 'ItemController@store');
Route::get('/items/{id}', 'ItemController@show');
Route::put('/items/{id}', 'ItemController@update');
Route::delete('/items/{id}', 'ItemController@destroy');
```

在本示例中，我们为项目的 CRUD（创建、读取、更新、删除）操作定义了路由。这些路由映射到处理相应操作的控制器方法。

### 认证和授权

保护 RESTful API 的安全至关重要。您可以实施认证和授权机制，以限制对特定资源或操作的访问。常用方法包括 API 令牌、`OAuth` 和 `JWT` (JSON Web Tokens)。

```php
// 在 Laravel 中使用 JWT 进行认证

if (!auth()->check()) {
    return response()->json(['error' => 'Unauthorized'], 401);
}

// 授权访问特定资源

if (!$user->can('update', $item)) {
    return response()->json(['error' => 'Access denied'], 403);
}
```

### 版本控制和文档

随着 API 的演进，保持向后兼容性非常重要。一种方法是在 URL 中包含版本号（例如 `/v1/items`）来对 API 进行版本控制。此外，使用 `Swagger` 或 `API Blueprint` 等工具提供清晰的 API 文档，有助于开发者了解如何有效地使用您的 API。

总之，PHP 8 为开发 RESTful API 提供了强大的能力。无论您选择使用 `Laravel` 等框架还是构建自己的自定义 API，遵循 REST 原则、处理 HTTP 方法、保护 API 安全，并提供版本控制和文档，对于为您的应用程序和客户端创建可靠且文档完善的 API 都至关重要。
