Throw 表达式的一个常见用例是与三元运算符结合使用，以便有条件地抛出异常。示例如下：

```php
$age = 15;

// 将 throw 表达式与三元运算符结合使用
$result = $age < 18 ? throw new UnderageException('You must be 18 or older.') : 'Access granted.';
```

在本例中，如果 `$age` 小于 18，则抛出 `UnderageException` 并显示消息。否则，将 `'Access granted.'` 赋值给 `$result`。

### 4.2.5. 错误抑制

值得注意的是，使用 throw 表达式时，无法使用错误抑制运算符（`@`）来抑制异常。尝试使用 `@` 抑制异常将导致解析错误。

### 4.2.6. 使用场景

当你想要有条件地抛出异常，而无需编写大量错误处理代码时，throw 表达式最为实用。它特别适用于验证输入、检查前置条件以及快速处理异常情况。

### 4.2.7. 兼容性

Throw 表达式在 PHP 8 及更高版本中可用。如果你需要维护与旧版 PHP 的兼容性，则需要使用传统的 `try-catch` 块方法进行错误处理。

总之，PHP 8 引入的 throw 表达式是错误处理和异常机制的一项宝贵补充。它简化了错误处理代码，减少了冗余，并使 PHP 应用程序中的错误处理更加简洁和富有表现力，特别适用于简单的错误条件。

## 4.3. 内部函数的一致类型错误

PHP 8 在内部函数的类型错误处理方面引入了重大变更，提高了错误报告的一致性和可预测性。此增强功能影响了内部函数在接收到不正确参数类型时的行为，使识别和诊断类型相关问题变得更加容易。在本节中，我们将深入探讨内部函数一致类型错误的概念及其影响。

### 4.3.1. 一致性的必要性

在早期的 PHP 版本（PHP 8 之前）中，内部函数在遇到不正确参数类型时的行为可能各不相同。某些函数会发出警告，而另一些则会返回意外结果或触发错误。这种不一致性使得在 PHP 应用程序中调试和识别类型相关问题的根本原因变得困难。

例如，考虑 `strpos` 函数，它用于搜索子字符串在字符串中的位置。在 PHP 7 及更早版本中，如果你向 `strpos` 提供不正确的参数类型，它可能会返回 `false`、`0`，甚至触发警告，具体取决于传递的参数。

### 4.3.2. PHP 8 的方法

PHP 8 对内部函数的类型错误采取了更加一致和可预测的方法。当使用不正确的参数类型调用内部函数时，它现在会始终抛出 `TypeError` 异常。这种行为更符合现代编程语言的规范，并有利于更好的错误处理和调试。

例如，在 PHP 8 中，如果你使用不正确的参数类型调用 `strpos`，它将抛出 `TypeError`：

```php
$position = strpos(12345, '3'); // 抛出 TypeError
```

此变更确保类型相关问题作为异常显式报告，使开发人员更容易识别和解决它们。

### 4.3.3. 一致类型错误的优势

PHP 8 中内部函数一致类型错误的引入提供了多项优势：

*   **清晰性**：类型错误现在始终作为 `TypeError` 异常报告，当使用不正确的参数类型时，提供清晰且明确的反馈。
*   **可预测性**：开发人员可以依赖内部函数始终为类型相关问题抛出 `TypeError` 异常，从而更容易编写健壮且容错的代码。
*   **改进调试**：抛出 `TypeError` 时，其中包含有关函数、预期参数类型和提供的参数类型的详细信息，有助于调试和解决问题。
*   **更安全的代码**：一致的类型错误鼓励开发人员编写更严格验证和处理参数类型的代码，从而构建更安全、更可靠的应用程序。

### 4.3.4. 处理 TypeError 异常

要处理内部函数抛出的 `TypeError` 异常，可以使用传统的 `try-catch` 块。示例如下：

```php
try {
    $position = strpos(12345, '3'); // 抛出 TypeError
} catch (TypeError $e) {
    echo 'Type error: ' . $e->getMessage();
}
```

在本例中，我们捕获 `strpos` 抛出的 `TypeError` 异常并显示错误消息。这允许优雅地处理错误，并防止异常突然中止程序。

### 4.3.5. 兼容性

必须注意，此行为变更适用于内部函数和 PHP 扩展提供的函数。用户定义的函数和方法不受此变更影响。因此，升级到 PHP 8 时，重要的是要审查并更新依赖内部函数先前不一致行为的代码。

### 4.3.6. 注意事项

虽然引入一致类型错误是提高代码质量和可预测性的积极举措，但它可能需要调整现有代码库。开发人员应审查其代码中对内部函数先前行为的任何依赖，并相应地进行更新。

总之，PHP 8 对内部函数实现一致类型错误，增强了 PHP 应用程序的代码一致性、可预测性和错误处理。此变更促进了更好的编码实践、更清晰的错误报告和改进的调试，最终带来更健壮、更可靠的 PHP 软件。然而，开发人员在升级到 PHP 8 时应准备好审查和调整其代码，以确保与新行为的兼容性。

## 4.4. 捕获异常：PHP 8 中的最佳实践

异常处理是编写可靠且健壮的 PHP 应用程序的关键方面。PHP 8 为捕获和处理异常引入了一些改进和最佳实践，使编写抗错误代码变得更加容易。在本节中，我们将探讨这些最佳实践以及如何在 PHP 8 中有效捕获异常。

### 4.4.1. 捕获特定异常

在 PHP 中，捕获特定异常而非通用的 `Exception` 类被视为最佳实践。通过捕获特定异常，你可以适当处理不同的错误场景，并根据发生的异常类型提供特定的错误消息或采取特定操作。

例如，如果你正在处理文件操作，并希望分别处理“文件未找到”和“权限被拒绝”错误，可以单独捕获 `FileNotFoundException` 和 `PermissionDeniedException`：

```php

    // 可能抛出异常的代码
} catch (FileNotFoundException $e) {
    echo 'File not found: ' . $e->getMessage();
} catch (PermissionDeniedException $e) {
    echo 'Permission denied: ' . $e->getMessage();
} catch (Exception $e) {
    // 捕获其他异常的兜底块
    echo 'An error occurred: ' . $e->getMessage();
}
```

捕获特定异常允许进行更细粒度的错误处理，并帮助你针对不同的错误场景做出适当响应。
