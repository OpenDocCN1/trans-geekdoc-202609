
• **弱引用**：对象的弱引用不会阻止垃圾回收器回收该对象。当你想临时持有对象引用，又不想在不存在强引用时阻止其被垃圾回收时，这非常有用。

```php
$object = new SomeClass();

$weakReference = WeakReference::create($object);

// ...

$object = null; // 如果没有其他强引用，该对象可能会被回收
```

• **弱映射**：弱映射是一种集合，允许你将弱引用与值关联。当与弱引用关联的对象被回收时，弱映射中对应的条目会自动移除。

```php
$weakMap = new WeakMap();

$object = new SomeClass();

$weakMap[$object] = '与对象关联的值';

// ...

$object = null; // 如果对象被回收，弱映射中的条目可能会被移除
```

这些功能对于以不干扰 PHP 垃圾回收的方式管理对象引用的场景非常有价值。

### 5.4.4. 手动垃圾回收控制

虽然 PHP 的垃圾回收器会自动运行，但 PHP 8 也通过 `gc_collect_cycles()` 函数提供了对垃圾回收周期的手动控制。该函数会强制执行一个垃圾回收周期，尝试立即回收内存。

```php
gc_collect_cycles();
```

虽然在特定情况下手动控制很有用，但对于典型的 PHP 应用程序通常并不需要。PHP 的自动垃圾回收通常足以高效管理内存。

### 5.4.5. 分析与调优

要充分利用 PHP 8 的垃圾回收优化，必须分析应用程序的内存使用情况和垃圾回收行为。`Xdebug` 等分析工具和扩展可以帮助你识别内存瓶颈以及可能需要优化垃圾回收的区域。

考虑以下垃圾回收调优技巧：

• 在不同应用场景下监控并分析内存使用情况，以识别任何内存泄漏或过度内存消耗。

• 调整 `php.ini` 文件中的 `memory_limit` 配置指令，确保 PHP 进程有足够的内存分配。

• 在适当的时候使用弱引用和弱映射，以防止强引用干扰垃圾回收。

• 在希望更多控制垃圾回收发生时机的情况下，尝试使用 `gc_collect_cycles()` 进行手动垃圾回收。

• 保持 PHP 运行时和扩展为最新版本，以获得与垃圾回收相关的性能改进和错误修复。

总体而言，PHP 8 的垃圾回收改进提供了更高效的内存管理，降低了内存相关问题的可能性，并提升了 PHP 应用程序的整体性能。

## 5.5. 预加载：一种性能提升技术

PHP 8 引入了预加载的概念，这是一种旨在通过减少脚本加载和初始化开销来提升 PHP 应用程序性能的技术。在本节中，我们将深入探讨预加载及其如何用于优化 PHP 8 代码。

### 5.5.1. 理解脚本加载开销

在传统的 PHP 执行中，每次执行脚本时，PHP 都必须加载并初始化必要的文件和类。这包括解析 PHP 脚本、包含所需文件以及加载类定义，在大型应用程序中可能导致显著的开销。

### 5.5.2. 什么是预加载？

预加载是 PHP 8 中的一种机制，允许你在需要之前将 PHP 脚本和类加载到内存中，从而有效消除脚本加载和初始化开销。通过预加载频繁使用的脚本和类，可以显著减少 PHP 应用程序的执行时间。

### 5.5.3. 预加载工作流

以下是预加载工作原理的简化工作流：

1.  识别频繁使用且导致应用程序初始化开销的脚本和类。
2.  创建一个预加载脚本（通常是一个 PHP 文件），列出你想要预加载的文件和类。
3.  通过在 `php.ini` 文件中设置 `opcache.preload` 指令，配置 PHP 使用该预加载脚本。
4.  PHP 启动时，会加载预加载脚本并将指定的文件和类初始化到内存中。
5.  执行 PHP 脚本时，它可以立即访问预加载的类和函数，无需额外的加载或解析。

### 5.5.4. 创建预加载脚本

让我们创建一个简单的预加载脚本示例：

```php
// preload.php

// 预加载频繁使用的类
require_once 'app/SomeClass.php';
require_once 'app/AnotherClass.php';

// 预加载频繁使用的函数
require_once 'app/functions.php';
```

在本例中，我们预加载了两个类（`SomeClass` 和 `AnotherClass`）以及一些在应用程序中频繁使用的函数（`functions.php`）。

### 5.5.5. 为预加载配置 PHP

要为 PHP 应用程序启用预加载，你需要通过编辑 `php.ini` 文件来配置 PHP。添加或修改 `opcache.preload` 指令以指定预加载脚本的路径：

```ini
opcache.preload=/path/to/preload.php
```

确保该路径指向预加载脚本的位置。

### 5.5.6. 预加载的优势

预加载为 PHP 应用程序提供了多项优势：

• **显著的性能提升**：通过消除脚本加载和初始化开销，预加载可带来大幅性能改进，尤其是在大型应用程序中。
• **可预测的性能**：预加载确保一致且可预测的执行时间，因为脚本加载的开销已被消除。
• **降低内存使用**：预加载的脚本和类常驻内存，减少了脚本执行期间频繁文件读取和内存分配的需求。
• **针对框架优化**：`Symfony` 和 `Laravel` 等框架提供了生成预加载列表的工具，使在复杂应用程序中实现预加载变得更加容易。

### 5.5.7. 注意事项与最佳实践

虽然预加载能极大地提升性能，但必须考虑以下因素：

• **识别关键代码路径**：专注于预加载应用程序关键代码路径中的脚本和类，以最大化收益。
• **定期更新**：随着应用程序的发展，保持预加载脚本为最新状态。随着代码库的变化，可能需要添加或移除预加载项。
• **测试**：彻底测试预加载对应用程序性能的影响，因为其效果可能因具体用例而异。
• **资源使用**：注意内存使用情况，尤其是在预加载大量脚本和类时。监控内存消耗以确保其保持在可接受范围内。

总之，预加载是 PHP 8 引入的一项强大技术，通过消除脚本加载和初始化开销，显著提升了 PHP 应用程序的性能。通过仔细选择和配置预加载项，你可以在 PHP 8 项目中享受执行速度提升和资源利用率降低的优势。

## 6.1. 新的数组函数和特性

PHP 8 引入了多个新的数组函数和特性，使数组操作更加便捷高效。在本节中，我们将探讨这些增强功能以及如何利用它们有效地操作数组。

### 6.1.1. `array_first()` 和 `array_last()` 函数

引入了两个新函数 `array_first()` 和 `array_last()`，分别用于获取数组的第一个和最后一个元素。

```php
$array = [1, 2, 3, 4, 5];

$firstElement = array_first($array); // 返回 1
$lastElement = array_last($array);   // 返回 5
```
