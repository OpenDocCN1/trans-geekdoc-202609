### 1.4.2.1 HANDLING MISSING VALUES

We saw in Table 1.1 that a lot of features had null values. The number of missing values in any of the columns did not exceed 25%. So, they were to be filled in order to avoid any decay in accuracy or any biased behavior. So, keeping this in mind, the data were divided into two parts based on its outcome "alive" or "dead" which were denoted by "0" and "1," respectively, in the outcome or the target column. Then all the missing feature values of each separated outcome data were handled using Simple Imputer having its strategy attribute fixed to "mean" which means "mean" of their respective feature columns. After handling all the missing values, the datasets were concatenated and finally the outcome or target column was separated from the dataset.

### 1.4.2.2 BALANCING DATA

As we can perceive from the data presented in Figure 1.3, we can see that our data are highly unbalanced with a ratio of approximately 1:6 for death to alive respectively. So, this means that our data are highly imbalanced and there is a need for balancing the data to avoid any chances of model biasing toward the majority class and hence deteriorating the overall performance of the model. This study of the dataset implies that we need to balance our data to achieve prime performance from our model. As we know, there are two ways to perform data balancing procedures one of that is undersampling, which randomly chooses the data of majority class and deletes it until both our data are equal and second technique is oversampling, which increases the data of minority class by making copies of the data present in it and hence increasing it until both data becomes equal. We rejected the undersampling technique because while deleting the data values, it might delete some data which carry meaningful insights toward the result formation of the model so we chose an oversampling technique and balanced our data using SMOTE. After applying SMOTE, the data distribution is presented in Table 1.2.

### 1.4.2.3 SCALING THE DATA

As we can see in our dataset that the data vary very much and the difference between the lowest and the highest values is very huge. So, this could increase the overall model training time or may cause the model to get biased toward the data or the feature that has a huge positive or negative value which in turn would make our model more prone to overfitting, thereby deteriorating the overall model's performance which we do not want to happen. Knowing the consequences that come with the unscaled data we thought of scaling our dataset and then training our model on the scaled data for making our model more robust and reducing the overall training time. Hence, we decided to scale our training and testing data of both unbalanced and balanced dataset using Standard Scaler. After applying Standard Scaler, the feature values of our dataset came in close proximity with each other and started ranging between −1 and 1.

## 1.4.3 MODEL TRAINING

After all the preprocessing steps were done, we trained AB, GB, LGBM, XGB, LR, SVM, HGB, GNB, BNB, KNN, RF, and DT algorithms using the training data and then tested our models on the testing split of both the balanced and unbalanced dataset and then evaluated the performance of each model using seven different performance evaluation metrics such as receiver operating characteristic–area under the curve (ROC–AUC) scores, Cohen kappa, \( F_1 \) score, precision, recall, \( K \)-fold mean accuracy, and standard deviation and stored the output of them in Tables 1.4 and 1.5 for any future reference. While training and evaluating the model on the train and test dataset, we used the \( K \)-fold CV of 10 folds. XGB performed best accuracy of 92.02% on unbalanced dataset and also HGB showed better accuracy of 96.31 on balanced dataset with default hyperparameter tuning.
