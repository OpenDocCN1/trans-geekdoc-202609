## 11.3.2 Migration Algorithm

The migration algorithm allows continuous integration of Equations 11.3 and 11.4 by re-evaluating the parameter and the possibility of task computation based on the dynamic mappings available and rebalances the load on each server; in simpler terms, it can be viewed as a rebalancing agent and the placement algorithm can be demonstrated as a load balancing unit. Placement algorithm is necessary for load distribution in the inception of task allocation. However, the migration technique is a constant running service that rebalances and when needed.

The migration algorithm ensures continuous integration and processing for the cloudlets offloaded to the edge servers. So by optimizing the time benefits, The migration algorithm is an optimization technique that tries to minimize Equation 11.5.

## 11.3.3 Edge Priority Placement Using Multi-Core and Parallel Heap Structures (EP-MCPHS)

EP-MCHPS combines multi-latent processing to benefit from the degeneracy minimum optimization of the heap function. The algorithm is divided into three segments: Parallel heap creation (PhC), Provisioning, and PhC combination with parallel processing.

### 11.3.3.1 Parallel Heap Creation for Priority-Based Resource Allocation

A priority queue is utilized as a provisioning mechanism for the minimum optimization which implements a minimum heap to allow the least resource to be allocated to the cloudlet, ensuring the least wastage of resources. The PhC algorithm uses Equation 11.8. The heap used is a min heap for the edge section based on computational needs.

```
$H_i = Heapify\left(\left(h_{\text{CPU,Memory,Disk}}\right)_{\ell}, e\in ES\right)\forall i\in\{1,2,\dots,n\} (11.8)$
```

Equation 11.8 describes the heap function which is responsible for priority-based allocation. It notes the minimum required edge server that can successfully offload the cloudlet. This allows the edge servers to be optimized, the resource utilization to be maximized, and migration flow rate to be low as edge servers working at maximum capacity. Thus priority-based allocation not only reduces latency and data flow, but maximizes resource optimization and also caters to creating operational edge server based on demand task allocation.

class EdgeServerWrapper:
    def __init__(self, edge_server):
        self.edge_server = edge_server

    def __lt__(self, other):
        # Compare edge servers based on their combined available resources (CPU,
        # memory, disk) 
        return (self.edge_server.cpu, self.edge_server.memory,
        self.edge_server.disk) < \
        other.edge_server.cpu, other.edge_server.memory,
        other.edge_server.disk)

    def provision_service(self, service, edge_server_heap):
        while edge_server_heap:
            edge_server_wrapper = heapq.heappop(edge_server_heap)
            edge_server = edge_server_wrapper.edge_server

            if edge_server.has_capacity_to_host(service):
                service.provision(target_service=edge_server)
                logging.info(f"Service {service.id} provisioned on edge server\n{edge_server.id}")
                return True
        except Exception as e:
            logging.error(f"Error processing service {service.id} on edge server\n{edge_server.id}")
            logging.warning(f"No suitable edge server found for\nservice {service.id}")
            return False

def my_algorithm(parameters):
    services = [service for service in Service.all() if service.server is None and not
    service.being_provisioned]
    edge_servers = [EdgeServerWrapper(edge_server) for
    edge_server in EdgeServer.all()]
    heapq.heappify(edge_servers)

    with ThreadPoolExecutor(max_workers=10) as executor:
        futures = [executor.submit(provision_service, service, edge_servers) for
        service in services]

    for future in futures:
        try:
            future.result()
        except Exception as e:
            logging.error(f"Error in\nprovision process: {e}")
