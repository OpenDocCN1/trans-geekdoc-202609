To compute the silhouette index two are needed: the currently created groups and where the distances between points. Let:

$a(i)$ = average dissimilarity (distance) of point $i$ to all other points in $A$, where $A$ is the cluster to $i$ has been assigned to (Figure 6.7).

$d(i, C)$ = average dissimilarity between $i$ and all points in some cluster $C$.

$b(i) = \min_{C \neq A} d(i, C)$. The cluster $B$ for which the minimum is attained is the neighbor of point $i$. (The second best choice for $i$).

Thus, $s(i)$ (the silhouette index of point $i$) is obtained with the formula:

```
$s(i) = \frac{b(i) - a(i)}{\max\{a(i), b(i)\}} \quad (6.3)$
```

When $s(i)$ is close to 1 it means the *within* dissimilarity $a(i)$ is much smaller than the smallest *between* dissimilarity $b(i)$ thus, $i$ can be considered well-clustered. When $s(i)$ is close to 0 it is not clear whether $i$ belongs to $A$ or $B$. When $s(i)$ is close to $-1$, $a(i)$ is larger than $b(i)$ meaning that $i$ may have been misclassified. The total silhouette index $S$ is the average of all indices $s(i)$ of all points.

In $R$, the **cluster** package has the function `silhouette()` that computes the silhouette index. The following code snippet clusters the student responses into 4 groups and computes the index of each point with the `silhouette()` function. Its first argument is the cluster assignments as returned by `kmeans()`, and the second argument is a `dist` object that contains the distances between each pair of points. We can compute this information from our data frame with the dist() function. The silhouette() returns an object with the silhouette index of each data point. We can compute the total index by taking the average in which this was 0.346.

```
library(cluster) # Load the required package.
```

## 6.3 Mining Association Rules

Association rule mining consists of a set of methods to extract patterns (rules) from transactional data. For example, shopping behavior can be analyzed by finding rules from customers' shopping transactions. A transaction is an event that involves a set of items. For example, when someone buys a soda, a bag of chips, and a chocolate bar the purchase is registered as one transaction containing 3 items. I apologize for using this example for those of you with healthy diets. Based on a database that contains many transactions, it is possible to uncover item relationships. These relationships are usually expressed as implication rules of the form X ⇒ Y where X and Y are sets of items. Both sets are disjoint, this means that items in X are not in Y and vice-versa which can be formally represented as X ∩ Y = ∅, that is, the intersection of the two sets is the empty set. X ⇒ Y is read as: if X then Y. The left-hand-side (lhs) X is called the antecedent and the right-hand-side (rhs) Y is the consequent.

In the unhealthy supermarket example, a rule like {chips, chocolate} ⇒ {soda} can be interpreted as if someone buys chips and then, it is likely that this person will also buy soda. These types of rules are used for targeted advertisements, product placement decisions, etc.

The possible number of rules that can be generated grows exponentially as the number of items increases. Furthermore, not all rules may be interesting. To filter the rules, we use several metrics:

- Support: supp(X) is the proportion of transactions that contain itemset X.
- Confidence: conf(X ⇒ Y) is the probability that Y occurs given X.
- Lift: lift(X ⇒ Y) = supp(X ∪ Y) / (supp(X)supp(Y)) measures the importance of a rule. A lift of 1 means there is no association between X and Y. A lift greater than 1 means that Y is likely to occur if X occurs and a lift less than 1 means that Y is unlikely to occur when X occurs. We compute all metrics using an example. The following table shows an database of transactions. The support of the itemset consisting of a single item 'chocolate' is supp({chocolate})=5/10=0.5 because 'chocolate' appears in 5 out of 10. The support of {chips, soda} is 3/10=0.3.

For example, the confidence of the rule {chocolate, chips} ⇒ {soda} is:

```
conf({chocolate,chips} ⇒ {soda}) = \frac{supp({chocolate, chips, soda})}{supp({chocolate,chips})}\n= (2/10)/(3/10)\n= .66
```

The lift of {soda} \implies {icecream} is:

```
lift({soda}) \implies {icecream}) = \frac{supp({soda, icecream})}{supp({soda})supp({icecream})}\n= (2/10)/((7/10)(3/10))\n= 0.95
```

Association rules mining is unsupervised in the sense that there are no labels or ground truth. Many applications of association rules are targeted to market basket analysis to gain insights into shoppers' behavior and take actions to increase sales.
