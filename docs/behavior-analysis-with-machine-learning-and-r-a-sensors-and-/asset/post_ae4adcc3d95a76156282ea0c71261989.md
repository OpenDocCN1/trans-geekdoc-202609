We will represent each action (file) as a feature vector. The same script also shows the code to extract the feature vectors from each action. To extract the features, a reference point in the skeleton is selected, in this case the spine (joint 3). Then, for each frame, the distance between all joints (excluding the reference point) and the reference point is calculated. Finally, for each joint, the *mean*, *min*, and *max* are computed across all time frames. Since there are 19 joints (excluding the spine), we end up with $19*3=57$ features. Figure 9.3 shows how the final dataset looks like. Only showing the first 4 features out of 57 and user id and labels.

The unique.actions variable stores the names of all actions. We will need to define the levels of the factor object. We generate 10 folds and define some variables to store the performance metrics including the accuracy, recall, and precision. In each iteration cross-validation, we will compute and store those performance metrics.

```r
k <- 10 # Number of folds.
set.seed(1234)
folds <- sample(k, nrow(dataset), replace = TRUE)
accuracies <- NULL; recalls <- NULL; precisions <- NULL
```

In this next snippet, the actual cross-validation is performed. The normalize() function in the auxiliary functions is used to normalize the data by learning the parameters from the train set and applying them to the test set, the actual Random Forest is fitted with the train set. One thing note here is that the userid field is removed: trainset[,-1] since we are not using users' information in the mixed model. Then, predictions on the test set are obtained and the accuracy, recall, and precision are computed during each iteration.

```r
# Perform k-fold cross-validation.
for(i in 1:k){

  trainset <- dataset[which(folds != i,)]
  testset <- dataset[which(folds == i,)]

  #Normalize.
  res <- normalize(trainset, testset)
  trainset <- res$train

  rf <- randomForest(label ~ ., data = trainset[,-1])
  preds <- predict(rf, testset[,-1])
  groundTruth <- factor(testset$label, levels = unique.actions)
  cm <- confusionMatrix(preds, groundTruth)

  accuracies <- c(accuracies, cm$overall["Accuracy"])
  recalls <- c(recalls, cm$overall["Recall"])
  precisions <- c(precisions, cm$overall["Precision"])
}
```

Finally, the average performance across folds is printed.

```r
# Print performance.
mean(accuracies)
# [1] 0.9277258
mean(recalls)
# [1] 0.9372558
mean(precisions)
# [1] 0.9208455
```

## 9.2 User-Independent Models

The user-independent model allows us to estimate the performance of a system on new users. To build this, we just need to make sure that the training data does not contain any information about the test user. For example, assign 70% of the users to the train and remaining to the test. If the dataset is small, one way to optimize it is by performing leave-user-out validation: if the dataset has n users, then n iterations are performed. In each iteration, one user is selected as the test set and the remaining ones used as the train set. Figure 9.4 illustrates the first 2 iterations. By doing this, we guarantee that the model knows anything about the target user.
