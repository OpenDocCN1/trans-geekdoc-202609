## 2.2.1 Confusion Matrix

As briefly introduced in the previous section, the confusion matrix provides a nice way to understand the model's predictions and spot where it makes mistakes. Figure 2.4 shows a confusion matrix for the binary case. The columns represent the true classes and the rows predicted classes. The P stands for the positive cases and the N for the negative ones. Each entry in the matrix corresponds to the TP, TN, FP, and FN. The TP and TN are the correct classifications whereas the FN and FP are the misclassifications.

Figure 2.5 shows a concrete example of a confusion matrix derived from a list of 15 instances with their predictions and their corresponding true values (ground truth). For example, the first element in the list is a P and it was correctly classified as a P. The eighth element is a P but it was misclassified as N. The associated confusion matrix for this ground truth and predicted classes is shown at the bottom.

| Ground truth: | P P P N N P P N N N P |
| Predictions: | P P P N N N N N P P P |

| True class | P | N |
|---|---|---|
| P | 7 | 2 |
| N | 3 | 3 |

Figure 2.5: A concrete example of a confusion matrix for the binary case. P: positives, N: negatives.

There are 7 true positives and 3 true negatives. In total, 10 instances were correctly classified (TP and TN) and 5 were misclassified (FP and FN). From this we can calculate what is the total number of true positives by taking the sum of the first column, 10 in this case. The total number of true negatives is obtained by summing the second column, 5 in this case. Having this information we can compute any of the previous performance metrics: accuracy, recall, specificity, precision, F1-score.

> You need to be aware that there is no standard that defines if the true classes or the predicted classes go in the rows or columns, thus you need to check this everytime you see a confusion matrix from different sources.

Each node in a tree represents a decision based on a single feature. If a node is a leaf, it leads to a final decision. A leaf is simply a terminal node, i.e. it has no children. Given a feature vector representing an instance, the predicted class is obtained by testing the feature and following the tree until a leaf is reached. Figure 2.6 shows an example decision tree and a query instance with weight 2300 and we take the right path. Now, number_wheels is 4 the test is false. Usually, small trees are preferred (small depth) because they are easier to visualize and interpret and are less prone to overfitting. The example tree has a depth of 2. The number of wheels had instead of 4, testing weight would not have been necessary. As shown in the example, decision trees are easy to interpret and the explanation of a result can be obtained by following the path. Now let's see how decision trees are learned from data. Consider the following cinema dataset:

![](img/91c149cc24c3e5af2971580c9dda9d8b_63_0.png)

Figure 2.8: Two example trees with one variable Price (left) and Comedy (right).

The first variables are features and the last column is the class. The class is the decision whether we should go to the movies based on the other variables. In this case variables are binary except Price which has three possible values: low, medium, and high.

- Tired: Indicates if the person is tired or not.
- Rain: Whether it is raining or not.
- Comedy: Indicates if the genre of the movie is comedy.
- Price: Ticket price.
- Go: The decision of whether to go to the movies or not.

The main question when building a tree which feature should be at the root (top). To answer this question, you may need to grow the tree by adding another feature (node) as one of the root's children. To decide which feature to add you need to answer the first question: “What feature should be at the root of this subtree?”. This is a recursive definition! The tree keeps growing until you reach a leaf node, there are no more features to select, or you have reached a predefined depth.

For the cinema dataset we need to find the best variable to be placed at root. Let's suppose we choose between Price and Comedy. Figure 2.8 shows these possibilities.

If select Price, there are three possible subnodes, one for each value: low, medium, and high. If Price is low then four instances fall into this subtree (the first four from the table). For all of them, the value of Go is 1. If Price is high, two instances fall into this category and their Go is 0, if price is high then you should not go to the movies according to this data. There are six instances for Price is medium. From those, two of them have Go=1 and the remaining four have Go=0. For cases the Price is low or high we can arrive at a solution. If the price is low then go to cinema, if the price is high then not. However, if the price is medium it is still not clear what to do since this subdiv is not pure. That is, the types of the instances are mixed: two and four with an output of 0. In this case we can try to use another feature to decide and grow the tree.

![](img/91c149cc24c3e5af2971580c9dda9d8b_64_0.png)

Figure 2.9: Tree splitting example. Left: tree splits. Right: Highlighted instances splitting Comedy.

But first, let's look at what happens if we decide to use Comedy as the first feature at the root. In this case, we end up with two subsets with six instances each. And for each subnode, what decision should we take is still not clear because the output is 'mixed' (Go: 3, Not: 3). At this point we would need to continue growing the tree below each subnode.

Intuitively, it seems like Price is a better feature since its subnodes are more pure. Then we can use another feature to split the instances whose Price is medium. For example, using the Comedy variable. Figure 2.9 shows how this would look like. Since one of the subnodes of Comedy is still not pure we can further split it using the Rain variable, for example. At this point, we can't split any further. Note that the Tired variable was never used.

So far, we have chosen the root variable based on which one looks more pure to automate the process, we need a way to measure the purity in a quantitative manner. One way to do that is by using the entropy. Entropy is a measure of uncertainty from information theory.
