Some people argue that the noise introduced with small batch sizes is good to escape from local minima. Keskar et al. (2016) showed that in practice, big batch sizes can result in degraded models. A good starting point is 32 which is the default in Keras.

**Learning rate.** This is one of the most important hyperparameters. The learning rate specifies how fast gradient 'moves' when trying to find an optimal minimum. However, this doesn't mean the algorithm will learn faster if the learning rate is set to a high value. If it is too high, the loss can start oscillating. If it is too low, the learning will take a lot of time. One way to fine-tune it is to start with the default one. In Keras, the default learning rate for stochastic gradient descent is 0.1. Then, based on the loss plot across epochs, you can decrease/increase it. If learning is taking long, try to increase it. If the loss seems to be oscillating or try reducing it. Typical values are 0.1, 0.01, 0.001, 0.0001, 0.00001. Additionally to stochastic gradient descent, Keras provides implementations of other optimizers⁷ like Adam⁸ which have adaptive learning rates, but still, one needs to specify an initial one.
