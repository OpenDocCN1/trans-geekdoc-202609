The discrepancy between the outputs obtained from Python and `R` could be explained as follows. From the Python output of [Programme 7.17](#c07.xhtml#c07-gra-00018), the parameter estimates for ![omega](images/c07-i0235.png)<math display="inline" overflow="scroll"><mrow><mi>&#969;</mi></mrow></math> and ![beta](images/c07-i0236.png)<math display="inline" overflow="scroll"><mrow><mi>&#946;</mi></mrow></math> have small ![p](images/c07-i0237.png)<math display="inline" overflow="scroll"><mrow><mi>p</mi></mrow></math>\-values below 0.05, thus these two coefficients are significantly different from zero. However, the ![p](images/c07-i0238.png)<math display="inline" overflow="scroll"><mrow><mi>p</mi></mrow></math>\-value for ![alpha](images/c07-i0239.png)<math display="inline" overflow="scroll"><mrow><mi>&#945;</mi></mrow></math> exceeds the threshold of 0.05, meaning that we cannot reject the null hypothesis that ![alpha](images/c07-i0240.png)<math display="inline" overflow="scroll"><mrow><mi>&#945;</mi></mrow></math> is equal to zero. Therefore, based on the Python output, we suspect that the (arithmetic) return of HSBC does not follow a GARCH(![1 comma 1](images/c07-i0241.png)<math display="inline" overflow="scroll"><mn>1</mn><mo>,</mo><mn>1</mn></math>) model; another possibility is that the MLEs obtained in the `arch` library of Python are not accurate enough.

In fact, we can change the optimization method used in Python to a two-step scheme, first using an extension of the `limited-memory Broyden–Fletcher–Goldfarb–Shanno` (L-BFGS) algorithm, called L-BFGS-B for short, followed by the `sequential least squares programming` (SLSQP). The first stage of using L-BFGS-B is often adopted in practice to solve an optimization problem. However, L-BFGS-B only supports bounded constraints for each parameter such as ![omega comma alpha comma beta greater-than 0](images/c07-i0242.png)<math display="inline" overflow="scroll"><mi>&#969;</mi><mo>,</mo><mi>&#945;</mi><mo>,</mo><mi>&#946;</mi><mo>&#62;</mo><mn>0</mn></math> and ![alpha comma beta less-than 1](images/c07-i0243.png)<math display="inline" overflow="scroll"><mi>&#945;</mi><mo>,</mo><mi>&#946;</mi><mo>&#60;</mo><mn>1</mn></math> as required by the GARCH(![1 comma 1](images/c07-i0244.png)<math display="inline" overflow="scroll"><mn>1</mn><mo>,</mo><mn>1</mn></math>) model, while other constraints that involve multiple parameters at once, such as ![alpha plus beta less-than 1](images/c07-i0245.png)<math display="inline" overflow="scroll"><mi>&#945;</mi><mo>+</mo><mi>&#946;</mi><mo>&#60;</mo><mn>1</mn></math>, are not supported. We therefore require a second stage of optimization, namely by SLSQP. By the implementation as shown in [Programme 7.19](#c07.xhtml#c07-gra-00019), the resulting MLEs are close to those obtained by `R` in [Programme 7.16](#c07.xhtml#c07-gra-00016). This also justifies the accuracy of the results obtained by `R`; to this end, in the later development of the various GARCH models, while we still present results via both Python and `R`, we may primarily use the outputs from `R` for demonstration if the results from the two environments do not match.
