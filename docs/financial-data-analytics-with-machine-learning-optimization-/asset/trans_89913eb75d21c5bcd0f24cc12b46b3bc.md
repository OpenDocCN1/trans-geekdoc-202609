

# 10.4.3 基于 PCA 的 K-means 聚类与多元逻辑回归

在小节 10.4.3 中，我们使用 MNIST 数据集在 PCA 降维前后拟合了多元逻辑回归模型。这里将说明在相同数据集上，`K`‐means 聚类中 PCA 的应用。作为基准，我们首先对数据集进行标准直接的 `K`‐means 聚类，训练集大小为 `60,000`，测试集大小为 `10,000`；请参见 [Programme 14.19](#c14.xhtml#c14-sec-3019) 中的 Python 代码和 [Programme 14.20](#c14.xhtml#c14-sec-3020) 中的 `R` 代码。请注意，在本例中我们设置 `K = 10`，因为数据集中有 0 到 9 共 10 个不同的数字。事实上，读者可以自行验证，在合理的约束 `K ≥ 10` 下（受数据集性质启发），`R(K)` 确实在 `K = 10` 时达到最大值。此外，由于 `K`‐means 聚类应当是一种无监督学习算法，得到的预测聚类不应与数字相关联。然而，为了在当前示例中进行性能评估，我们仍通过多数投票方法建立这种联系，即在某个聚类的训练数据点中出现频率最高的数字被选为该聚类的标签。分配给训练聚类的标签在 `pos_dict` 中展示；例如，输出中的 `4: 6` 表示第 `(4 + 1 = 5)` 个聚类的预测标签是数字 6。

在 [Programme 14.19](#c14.xhtml#c14-sec-3019) 通过 Python 获得的输出中，第一个“混淆矩阵”的第 `i` 行实际上是落入对应第 `i` 个训练聚类的测试图像中实际数字的分布，对于每个测试图像，其预测数字被设置为其所属聚类分配的标签。在得到的第二个也是最终的混淆矩阵中，第六行和第十行的条目均为零，表明没有聚类被分配预测标签为 5 或 9，因此没有测试图像被识别为这两个数字之一。解释是，数字 5 与数字 3 和 8 相似，而数字 9 可能容易被误认为 4 或 7，因此混淆矩阵中第六列和第十列分别有较大的条目。`K = 10` 时 `K`‐means 聚类的测试准确率为 0.5943，低于通过 [Programme 6.9](#c14.xhtml#c14-sec-3009) 在 Python 中 EM 算法获得的 0.6784。

在 `R` 中，由于用于 `K`‐means 聚类的内置函数 `kmeans()` 不支持 `predict()` 函数来计算给定新特征矩阵的预测标签，我们需要定义一个额外的函数 `predict.kmeans()` 以实现此目的。这个自定义函数，以及标准 `K`‐means 聚类的代码和输出，均显示在 [Programme 14.20](#c14.xhtml#c14-sec-3020)。我们还指出，混淆矩阵中作为列的实际数字按 `1, ..., 9, 0` 的顺序排列，这与 Python 中的顺序（`0, 1, ..., 9`）不同。最后，`R` 中矩阵的零行被省略。预测准确率为 0.5848，与 Python 中获得的结果接近。

接下来，我们对训练数据集进行 PCA，并选择解释总方差 95% 的主成分数量，即前 154 个主成分（请参见通过 Python 的 [Programme 10.28](#c14.xhtml#c14-sec-3028) 和通过 `R` 的 [Programme 10.29](#c14.xhtml#c14-sec-3029)），然后计算测试数据点对应的主成分，这些主成分作为 `K`‐means 聚类的特征变量。从 [Programme 14.21](#c14.xhtml#c14-sec-3021) 中的 Python 输出和 [Programme 14.22](#c14.xhtml#c14-sec-3022) 中的 `R` 输出中，我们观察到得到的预测准确率仍保持在约 0.585 的水平。此外，这种混合方法在 Python 中的实现耗时少于标准 `K`‐means 聚类，而在 `R` 中则更耗时。
