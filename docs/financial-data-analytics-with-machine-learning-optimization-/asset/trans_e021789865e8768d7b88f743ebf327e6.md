虽然分类树通常是一种有效的分类器，但有时会导致过拟合，尤其是当其深度过大时。我们需要在其复杂性与训练分类误差 `R(T)` 之间取得平衡，该误差在 ([13.14](#c13.xhtml#c13-disp-0046)) 中给出。关于此方面的更详细讨论，例如，使用卡方检验来确定是否应进一步拆分，我们请读者参阅我们的用户指南 [[2](#c13.xhtml#c13-bib-0002)]。

减少树复杂性的第一种方法是 `pre‐pruning`。乍一看，这很直观：如果所选不纯度度量的值超过某个阈值，人们预期后续拆分无法大幅降低训练误差，而随着树的规模增长，生成的树会变得更加复杂，因此最好在当前节点停止。尽管如此，pre‐pruning 本质上是贪心的：树的生成可能会在一个看似不佳的拆分处停止，尽管后续的划分可能极具价值。

另一种方法称为 `post‐pruning`，即我们先构建分类树 `T`，然后移除任何不必要的中间节点，以防止我们被看似无价值的拆分所误导。直观地说，post‐pruning 过程会故意移除那些对降低训练误差贡献很小的分支。主要有两种方法，取决于该过程从何处启动：

1. `bottom‐up pruning` 从任意一个终端节点开始，并沿所选路径递归向上追溯，以确定此回溯路径上每个相应父节点处的拆分是否在预先确定的度量下是“有价值”的；如果一个节点不是“有价值”的，例如，训练误差的降低低于预先指定的水平，则移除该父节点处的拆分，从而使其成为直接的终端节点。

2. `top‐down pruning` 从树的根节点开始。它检查每个节点处拆分的“价值”，并移除那些“贡献的误差降低”低于某个阈值的节点下的子树。这种方法看似与 pre‐pruning 相似，但两者之间存在显著差异：pre‐pruning 在训练阶段停止构建分类树，而 top‐down pruning 仅在构建完整树之后才开始工作。

一种具有代表性的 bottom‐up post‐pruning 方法称为 `(Minimal) Cost Complexity Pruning`。令 `T^(0) = T` 为原始树，`T^(K)` 为仅包含根节点的树。对于 `k = 0, ..., K`，我们旨在构建一棵树序列 `T^(0) ⊇ ... ⊇ T^(K)`，其中 `T^(k+1)` 是通过从 `T^(k)` 中移除一个子树形成的。例如，考虑 [Figure 13.6](#c13.xhtml#c13-fig-0006) 中的分类树。
