Python 与 `R` 输出之间的差异可解释如下。从 [Programme 7.17](#c07.xhtml#c07-gra-00018) 的 Python 输出可知，![omega](images/c07-i0235.png)<math display="inline" overflow="scroll"><mrow><mi>&#969;</mi></mrow></math> 和 ![beta](images/c07-i0236.png)<math display="inline" overflow="scroll"><mrow><mi>&#946;</mi></mrow></math> 的参数估计具有小于 0.05 的 ![p](images/c07-i0237.png)<math display="inline" overflow="scroll"><mrow><mi>p</mi></mrow></math>-值，因此这两个系数与零有显著差异。然而，![alpha](images/c07-i0239.png)<math display="inline" overflow="scroll"><mrow><mi>&#945;</mi></mrow></math> 的 ![p](images/c07-i0238.png)<math display="inline" overflow="scroll"><mrow><mi>p</mi></mrow></math>-值超过了 0.05 的阈值，这意味着我们无法拒绝 ![alpha](images/c07-i0240.png)<math display="inline" overflow="scroll"><mrow><mi>&#945;</mi></mrow></math> 等于零的原假设。因此，基于 Python 输出，我们怀疑 HSBC 的（算术）收益不遵循 GARCH(![1 comma 1](images/c07-i0241.png)<math display="inline" overflow="scroll"><mn>1</mn><mo>,</mo><mn>1</mn></math>) 模型；另一种可能性是，Python `arch` 库中获得的 MLE 不够准确。

事实上，我们可以将 Python 中使用的优化方法改为两步方案，首先使用 `limited-memory Broyden–Fletcher–Goldfarb–Shanno`（L-BFGS）算法的扩展，简称 L-BFGS-B，然后使用 `sequential least squares programming`（SLSQP）。在实践中，第一阶段使用 L-BFGS-B 通常用于求解优化问题。然而，L-BFGS-B 仅支持每个参数的边界约束，例如 GARCH(![1 comma 1](images/c07-i0244.png)<math display="inline" overflow="scroll"><mn>1</mn><mo>,</mo><mn>1</mn></math>) 模型要求的 ![omega comma alpha comma beta greater-than 0](images/c07-i0242.png)<math display="inline" overflow="scroll"><mi>&#969;</mi><mo>,</mo><mi>&#945;</mi><mo>,</mo><mi>&#946;</mi><mo>&#62;</mo><mn>0</mn></math> 和 ![alpha comma beta less-than 1](images/c07-i0243.png)<math display="inline" overflow="scroll"><mi>&#945;</mi><mo>,</mo><mi>&#946;</mi><mo>&#60;</mo><mn>1</mn></math>，而不支持涉及多个参数的其他约束，例如 ![alpha plus beta less-than 1](images/c07-i0245.png)<math display="inline" overflow="scroll"><mi>&#945;</mi><mo>+</mo><mi>&#946;</mi><mo>&#60;</mo><mn>1</mn></math>。因此，我们需要第二阶段优化，即使用 SLSQP。通过 [Programme 7.19](#c07.xhtml#c07-gra-00019) 中所示的实现，得到的 MLE 与 [Programme 7.16](#c07.xhtml#c07-gra-00016) 中 `R` 得到的结果接近。这也证明了 `R` 得到结果的准确性；为此，在后续各种 GARCH 模型的开发中，虽然我们仍将通过 Python 和 `R` 呈现结果，但如果两个环境的结果不一致，我们可能主要使用 `R` 的输出进行演示。
