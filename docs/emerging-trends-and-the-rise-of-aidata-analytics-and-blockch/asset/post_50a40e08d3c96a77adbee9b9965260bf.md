### 3.3 System implementation

Hyperledger's chain code is stored in a database with a storage method that consists of a HashMap method that registers data in pairs of keys and values. LevelDB is applied to match these characteristics; it is chosen because it is designed with a data structure that allows for more flexible changes to database schema compared to relational databases, thus ensuring data scalability. The blockchain chain code configuration for verification is illustrated in Figure 1. To prevent data collision with other chain codes, the prefix “CC1” is used as the identity of the chain code. Specifically, data cross-error could cause a serious problem, so it is typically advantageous to store important data such as personal information and financial information using its own prefix. The data exist on the entire verification peer, and all verification nodes have the same data, thus enabling cross-checking to determine the accuracy of data verification.

An identity inquiry is requested through the chain code, and the result is obtained by searching through the identity information stored in the blockchain. Digital signature and validation based on a private key system will be performed when inquiring mobile ID cards, and the resulting value will be held in the blockchain in the form of HashMap, like the mechanism stored in LevelDB. The design of this distributed identity system based on blockchain is significant in the following ways: First, it supports API and business logic development for this mobile identity project through the API Gateway module application. In authentication/issuance and identity verification, a convenient and stable development environment has been established for API authentication and authorization processing, logging processing and traffic management that involves linking a micro service. Second, when connecting with other systems, such as in an external linkage (e.g. with a police agency or a road transportation corporation), the interface specifications – such as HTTP and HTTPS, the application method, component, database, etc. – of the target system are applied for integration with other systems. Third, Hyperledger Fabric is used to develop the blockchain client server. Specifically, we apply Hyperledger Fabric V1.0 to create a blockchain client server. Hyperledger Fabric is used to support systems requiring high levels of privacy, because it allows members to enroll via a trusted membership service provider. Thus, this distributed ledger platform provides resiliency, scalability, flexibility and confidentiality (Alessandro, 2020). This blockchain-based mobile identification service is also implemented through storage selection (PostgreSQL, MySQL and LDAP) for the storage of user information and the development of Fabric CA Client and REST API. Fourth, Hyperledger’s chain code development secures the flexibility and reliability of the data. Hyperledger chain code is applied with KVS-style LevelDB or CouchDB, which registers data in pairs of keys and values as databases.
