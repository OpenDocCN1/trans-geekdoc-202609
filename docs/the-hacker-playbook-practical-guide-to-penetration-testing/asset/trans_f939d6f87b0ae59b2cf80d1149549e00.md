
我过去经常使用 JtR，但由于 oclHashcat 的 GPU 支持，我已经有一段时间没用了。不过 JtR Jumbo 现在确实支持 CUDA 和 OpenCL。以下是 JtR 哈希格式列表，可帮助您识别正在破解的类型：[http://pentestmonkey.net/cheat-sheet/john-the-ripper-hash-formats](http://pentestmonkey.net/cheat-sheet/john-the-ripper-hash-formats)。

## 破解 MD5 哈希

假设您能够攻破一台 \*nix 系统，或者可能是一个装满密码哈希的数据库。您最有可能遇到 MD5 或 SHA 哈希，但在以下示例中，我们假设它们是非加盐的 MD5 哈希。如果您想破解标准 MD5 哈希，基本命令是：

*   `john -format=raw-md5 -pot=./list.pot md5list.txt`

这将告诉 John the Ripper 在 `md5list.txt` 文件中查找 MD5 哈希，并将破解出的密码写入 `list.pot` 文件。

```
root@kali:~# john —format=raw-md5 —pot=./list.pot md5list.txt

Loaded 3 password hashes with no different salts (Raw MD5 [128/128 SSE2])

test (test)

password (user)

woot (hacker)

guesses: 3 time: 0:00:00:01 DONE (Sun Dec 29 18:32:12 2013)
```

如果您使用的是 JtR Jumbo 包并想利用 GPU 处理：

```
john —format=raw-md5-opencl —wordlist=./Wordlists/all.lst —rules: Single md5list.txt
```

以下是关于使用 JtR 的其他资源：[http://blog.thireus.com/cracking-story-how-i-cracked-over-122-million-sha1-and-md5-hashed-passwords](http://blog.thireus.com/cracking-story-how-i-cracked-over-122-million-sha1-and-md5-hashed-passwords)。

![](images/00220.jpeg)

老实说，这是我破解密码时最常用的工具。众所周知，图形处理单元（GPU）非常适合破解密码，因为它们利用许多不同的内核并行工作。使用 GPU 与 CPU 相比优势显著，这可以通过 oclHashcat 的使用来证明。

在以下示例中，我将介绍破解 WPAv2 和 NTLMv2。这些是我遇到的最常见的哈希类型，实际上也是任何其他类型哈希的基础。如果您想查看 oclHashcat 支持的所有不同哈希类型，请访问他们的网站：[http://hashcat.net/oclhashcat/](http://hashcat.net/oclhashcat/)。

## 破解 WPAv2

在本书开头，我讨论了如何捕获破解密码所需的 WPAv2 握手包。捕获的输出是一个 `.hccap` 文件。这是 oclHashcat 支持的用于暴力破解 WPA 哈希密码的文件格式。

在以下示例中，我将在我的 Windows 主机上使用配备 GeForce GTX 680 的 oclHashcat。虽然我确实更喜欢使用 ATI Radeon 显卡，但实际上对于这个示例来说，区别不大。要开始破解密码，我将使用以下命令：

*   `cudaHashcat-plus64.exe -m 2500 out.hccap list\\rockyou.txt`

![](images/00221.jpeg)

**图 134 - oclHashcat 示例**

这是一个非常直接的示例，意思是针对 `out.hccap` 文件破解 WPAv2 哈希，并使用来自 `rockyou.txt` 的密码列表。

## 破解 NTLMv2

如果您攻破了一台 Windows 主机，或者可能是一个域控制器，您将不得不破解 NTLM 哈希。您可以随时尝试针对 LM 哈希，但由于这越来越少见，我们将坚持使用 NTLM 哈希。

在以下示例中，我们获取一个 NTLM 哈希列表，并使用 rockyou 密码列表。

![](images/00222.jpeg)

**图 135 - oclHashcat NTLM**

从上面的示例中，有 3 个唯一密码，但 oclHashcat 只能破解其中两个。为了增加机会，我将添加 passwordspro 规则集来配合 rockyou 密码列表。如果您想更深入地了解这些规则，请尝试从 oclHashcat 页面开始：[http://hashcat.net/wiki/doku.php?id=rule_based_attack](http://hashcat.net/wiki/doku.php?id=rule_based_attack)。

![](images/00223.jpeg)

**图 136 - 带规则的 oclHashcat**

使用规则实际上并没有找到第 3 个哈希的密码。在更大的密码哈希列表中，这肯定会找到更多密码，但在这种情况下只能找到 3 个密码中的 2 个。为了进一步增加机会，我将尝试一个大得多的密码列表。这当然会增加运行此作业所需的时间，但如果能解出一个密码，就值得。所以我将使用的命令是：

*   `cudaHashcat-plus64.exe -m 1000 NTLM.txt list\\realhuman.txt -r rules\\passwordspro.rule`

![](images/00224.jpeg)

**图 137 - 使用不同密码列表的 oclHashcat**

正如您从结果中看到的，新的密码列表和规则集恢复了第 3 个密码。仅通过尝试不同的密码列表和规则集，您就可以快速发现什么有效，什么只是运行时间太长。这当然都基于您拥有什么类型的 GPU、密码列表有多长以及规则集的复杂程度。

无论您想破解 MD5 哈希、MSSQL 哈希、SHA1 哈希还是其他哈希，都可以通过更改 `-m` 参数来运行相同的查询。有关 oclHashcat 接受和破解的哈希的完整列表，请访问 [https://hashcat.net/wiki/doku.php?id=example_hashes](http://hashcat.net/wiki/doku.php?id=example_hashes)。

## 更聪明地破解

通常，我会使用配备 7990 GPU 的 oclHashcat，配合一个优秀的密码列表和规则集来破解哈希。这是因为我经常只是寻找弱密码作为概念验证，或者我只需要破解几个密码来进入 OWA 账户。有时客户会特别要求您尽可能多地破解哈希。

有两个演示文稿我强烈建议您观看/研究。第一个称为“Cracking Corporate Passwords - Exploiting Password Policy Weaknesses - Minga/Rick Redman”。

[http://www.irongeek.com/i.php?page=videos/derbycon3/1301-cracking-corporate-passwords-exploiting-password-policy-weaknesses-minga-rick-redman](http://www.irongeek.com/i.php?page=videos/derbycon3/1301-cracking-corporate-passwords-exploiting-password-policy-weaknesses-minga-rick-redman)。该演示文稿深入探讨了 GPU 变得如此之快，以至于 8 位字符的密码可以在很短的时间内被暴力破解。然后它深入探讨了密码通常遵循基于密码策略的模式。如果密码策略规定您的密码需要一个特殊字符和一个数字，它通常遵循类似的模式。在大多数情况下，您会发现人们会把数字放在末尾，特殊字符放在末尾，通常是感叹号。如果需要大写字母，最有可能是第一个字母。

第二个演示文稿引用了 PACK（密码分析和破解工具包），这是一组实用程序，旨在帮助分析密码列表并通过智能规则生成增强密码破解。这是由我的一位好朋友制作的，您可以在此查看他的演示文稿：[https://thesprawl.org/media/research/passwords13-smarter-password-cracking-with-pack.pdf](http://thesprawl.org/media/research/passwords13-smarter-password-cracking-with-pack.pdf) 和视频：[http://www.youtube.com/watch?v=8j6fOAH-Sko](http://www.youtube.com/watch?v=8j6fOAH-Sko)。

他在他的网站上也有关于如何使用他的工具以及如何以更聪明、更高效的方式破解密码的很好的描述和演练：[https://thesprawl.org/projects/pack/](http://thesprawl.org/projects/pack/)。
