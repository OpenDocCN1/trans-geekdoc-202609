

# 被动发现

这通常是我开始的第一步。客户联系我进行测试，我可能只会收到一个公网 IP 范围，或者在完全的黑盒测试中，你可能对目标一无所知。这是你发挥创造力和经验、尝试挖掘目标所有信息的时候。在接下来的章节中，我们将使用被动和主动的工具及技术，以识别目标服务器、服务甚至人员的一切信息。

![](images/00016.jpeg)

从**被动发现**开始，它将在从未接触目标主机的情况下，搜索关于目标、网络、客户端等的信息。这非常棒，因为它利用互联网资源，而从未以任何可疑活动惊动目标。你也可以在约定测试前运行所有这些查找，以节省大量时间。有时通过一点 Google Hacking 和 Shodan ([http://www.shodanhq.com/](http://www.shodanhq.com/))，你甚至能在开始测试前就实际发现漏洞，但那是另一个故事了。

浏览 Kali，有许多不同的工具用于被动网络/信息发现，但目的依然是使其尽可能简单直接。你可能会发现需要花费额外时间进行被动发现，但这里是快速上手的简单方法。看下面的图片，我们可以看到在 Kali 的开源情报 (OSINT) 文件夹中有各种工具。逐一学习这些工具并掌握其运行方法会浪费大量不必要的时间。幸运的是，有人已将这些工具整合到一个单一工具中。

![](images/00018.jpeg)

**(以前称为 Backtrack Scripts) (Kali Linux)**

为解决此问题，开发了一个发现框架，用于快速高效地识别关于公司或网络的被动信息。该框架通过一个名为 `Discover-scripts`（以前称为 `Backtrack-scripts`）的工具实现 ([https://github.com/leebaird/discover](https://github.com/leebaird/discover))，作者是 Lee Baird。该工具在一个工具中自动化了许多不同的搜索。例如，它可以搜索该组织内的人员或所有常见收集网站（如 LinkedIn）上的域名，使用常见域名工具（如 `goofile`、`goog-mail`、`theHarvester`、`search_email_collector`、`mydnstools`）并链接到其他第三方工具以执行额外搜索。让我们开始吧。

![](images/00019.jpeg)

**图 2 - Discover 侦察工具**

## 如何运行被动发现

1.  `cd /opt/discover`
2.  `./discover.sh`
3.  输入 `1` 选择 Domain（域名）
4.  输入 `1` 选择 Passive（被动）
5.  输入要搜索的域名
    a.  在此示例中为：`reddit.com`
6.  完成后输入：
    a.  `firefox /root/[domain]/index.htm`

在示例中，我对一个我喜欢的网站进行了上述被动查询。请记住，这是一个完全被动的请求，绝不代表在识别 Reddit 的任何漏洞，而是说明那里有哪些公开信息。

我选择了父域 `reddit.com`，以下示例是结果。扫描完成后，将在 root 文件夹下创建一个包含所有扫描结果的 `index.htm` 文件。这是我所发现的用于此类侦察的最快、最全面的工具之一。该工具将基于域名、IP、文件、邮件、WHOIS 信息、一些 Google Dorks 等查找信息。

查看 Reddit 域名的结果，html 页面以易读的方式布局。顶部横幅栏根据收集到的信息，在每个类别下都有下拉菜单。让我们先看看所有子域名。这些在社会工程学章节的“双生攻击”中将非常重要。我收集了大量已识别的子域名和 IP，它们可能在测试范围内。

正如我们从上述域名拼写错误中看到的，并非所有域名似乎都归母公司所有。这对你的客户来说是很好的信息，因为这可能意味着有人正恶意抢注他们的域名。你也可以从攻击者的角度出发，可能购买这些域名用于社会工程学攻击。

这通常足以开始测试的被动发现阶段，但如果你需要深入挖掘，我建议也看看 `Recon-ng`。`Recon-ng` 可在 [https://bitbucket.org/LaNMaSteR53/recon-ng](https://bitbucket.org/LaNMaSteR53/recon-ng) 找到，它在不同搜索和自动化工具上有更大深度，以获取额外的被动信息。如果你感兴趣，我推荐查看 2013 年 Derbycon 的这个演示：[http://bit.ly/1kZbNcj](http://bit.ly/1kZbNcj)。

# 利用泄露名单查找邮箱地址和凭据

作为渗透测试员的好处在于，你必须发挥创造力并使用各种资源，就像恶意攻击者一样。在过去几个月中，我发现一种非常富有成效的策略是利用已知的凭据泄露进行密码重用攻击。让我详细解释一下。

几个月前，Adobe 系统发生大规模泄露。泄露信息包括邮箱地址、加密密码及其密码提示。^([2](#part0018.html#id_4)) 这个近 10 GB 的大量数据最初在小圈子私下发布，现已公开可用（尝试搜索 Adobe 和 `users.tar.gz`）。从攻击者角度来看，这是一个信息金矿。我通常会解析此文件，识别出我正在测试的目标域名。

当然，重要的是要确认这种测试类型是否在你的约定范围内，以及获取任何密码/泄露名单副本是否违法。如果是完全的黑盒测试，这绝对应该是你攻击方法的一部分。

例如，在下图中，我将使用 Linux `grep` 命令在 Adobe 密码列表中搜索示例域名 `yahoo.com`（记住你应该搜索你正在测试的域名）。我们可以看到有许多用户（我已隐去）的邮箱地址包含 yahoo，并拥有加密密码和密码提示。
