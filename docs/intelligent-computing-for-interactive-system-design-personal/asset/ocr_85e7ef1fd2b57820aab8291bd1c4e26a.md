Based on these categories, we chose each of the following classification problems:

**Enclosed or Out:** whether the phone is out and potentially visible to a user, or if it is put away. Applications for this model include preventing pocket dial, and knowing whether or not visual notification mechanisms (e.g., flashing light or screen) will be noticed.

**On Person or Not:** whether or not the phone is on the user. Applications for this model include dynamic notification preferences (a primary concern from survey respondents, e.g., whether or not to vibrate) and progressive authentication (whether the user has to reauthenticate, based on whether they could have been separated from the phone since last authenticated).

**In Bag, In Pocket, Out, or In Hand:** where the phone is at a finer granularity. This is useful for the *find my phone* functionality (e.g., “your phone has been in a bag since 11:22 am” a concern expressed in survey responses) and for sharing the user/phone’s context to provide social awareness.

# 9.2.2 Q2: What Is the End Goal for this Classifier?

While we can imagine several end goals for this type of classifier, in this project the goal is just to show that this classification is possible, and to begin to characterize how well a phone-placement classifier might work if deployed in a real-world setting.

# 9.2.3 Q3: What Data Do I Need, What Data Do I Want?

When we began this project, we brainstormed data that we thought might be useful for this classification. We decided that *accelerometer data* was essential for our classifier. In practice, this decision was strongly influenced by the fact that we knew that this was the data that we would be able to collect from a deployment.

However, we hypothesized that additional data would also be useful, and after we conducted the in-the-wild data collection, we added the following data sources in our lab study:

**Proximity sensor and light sensor:** These sensors already existed in many of mobile devices. It would have been preferable to collect this data in the field, but a combination of technical limitations for accessing those sensors and the variety of configurations that lacked these sensors on the device made data collection during the ESM study infeasible. In the lab study, we collected the data using a development phone that gave us access to all the sensors on the device.
