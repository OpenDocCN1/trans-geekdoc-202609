+   * medium tie—the middle group (rank 5–19)

+   * weak tie—the remaining contacts

We further decided to explore both binary and ternary classifiers for the tie-strength problem:

+   * 3-class: classifies as strong, medium–strong, or weak

+   * 2-verystrong: binary classifier that combines medium–strong and weak ties into one class

+   * 2-mediumstrong: binary classifier that combines strong and medium–strong ties into one class

# ## 9.3.2 Q2: What Is the End Goal for this Classifier?

Similar to the work described in Section 9.2, the primary goal of this project was research: the plan was not to develop a model or system and deploy this to the wild, but rather to just characterize the problem space and show that it was possible and how well it performed. However, if the work was particularly successful, the classifiers trained here might facilitate additional research to explore some of the hypothesized applications (e.g., following up the previous work we had been doing on the association between these dimensions of relationships and privacy preferences [Wiese et al. 2011]).

# ## 9.3.3 Q3: What Data Do I Need, What Data Do I Want?

To develop these classifiers, our plan was to use call logs, text message logs, and the contact list on phones running the Android operating system. Unfortunately, at the time that we were doing this study there were some limitations to this data. In particular, by default Android (Alphabet Inc., Mountain View, CA, USA) phones limited the call log to the last 500 calls and typically have a default limit of 200 SMS messages per contact. This resulted in broad differences in how many days the logs represented (range: 21–369; median: 80; mean: 108). This represents a serious limitation to the dataset, but it would be difficult to have collected more data without running a longer-term data collection. Another challenge was that contact lists have many fields, but in practice the data in the contact list is fairly sparse. To protect privacy, we did not collect the content of SMS messages. However, we did collect descriptive information such as email domain name, first six digits of phone numbers, and city/state/zip code.
