# Introduction

While I mention the N+1 problem more than once in Modernizing Legacy Applications in PHP¹, I did not address a solution directly. This book remedies it. Here, we will discuss the specifics of the N+1 problem:

+   - what the N+1 problem is,
- how to diagnose and discover the problem in your application,
- why the problem occurs, and
- how to solve the problem in your codebase.

# Example Application

While I cannot present the Slow Reporting Script itself for before-and-after examination, I can do the next best thing and present a generic example. In this book, we will use hypothetical code from naive blogging as our subject. In doing so, we will use the SQL and PHP structures described in the appendix.

This will be a legacy application example, so there is no use of ORMs. (Different ORM implementations have their own N+1 mitigation strategies, which we cannot discuss here.)

Without an ORM, this hypothetical application uses PDO² for its database abstraction. Not all legacy code uses PDO, but the principles regarding N+1 (both the problem and solutions) apply to all database connection libraries. These include mysqli³, mysqli*, as well as usland database abstraction layers.

When fetching query, our application uses the PDO::FETCH_CLASS* mode as much as possible. This causes PDO to return an array instance of a specified entity class, each with its properties already filled with the data from one row. With other systems, you are likely to create the class separately from the database query; we use FETCH_CLASS primarily to reduce the volume of the example code. (The entity classes themselves are plain PHP objects with public properties)

Finally, the naive codebase uses plain PHP arrays for entity collections. More sophisticated systems may use generic class properties, but the principles concerning N+1 regarding collections remain the same.
