# 6. Solving N+1 With Query-And-Stitch

There is an alternative to the single-query solution that is easy to implement and more scalable across any number of associations. This alternative is called "query-and-stitch."

The query-and-stitch approach is as follows:

+   1. Issue one query for the root collection of entities.
2. Issue one additional query per association to get all of the associated entities for all of the root entities at.
3. Stitch the associated entities into the root entities using a PHP loop.

# Tradeoffs In Query-And-Stitch

The key here is that we issue one additional query per relationship, not one per root entity. The increase in the number of queries is thus linear, not exponential.

For example, if there are 10 entities in the root collection and 2 associations ...

+   - Under N+1 we would issue 21 queries (1 for the root collection of 10 entities, and then 10 more queries for each of the associations). Adding a third association would result in a total of 31 queries (i.e., 1 more for each of the 10 root entities).
- With the single-query solution, we might be able to retrieve the data in one query, but the costs of working with the result set are too high, including the inability to effectively LIMIT the results on the SQL side.
- Using query-and-stitch, we issue a total of 3 queries (1 for the root collection, and 1 each of the associations). Adding a third association would result in a total of 4 queries (i.e., 1 query for the relationship).

The query-and-stitch approach represents an effective tradeoff between N+1 and the single-query solution, both for "to-one" and "to-many" relationships.
