# 3. Diagnosing N+1 Problems

There are two methods to diagnose occurrences of the N+1 problem in a codebase. Both methods are a matter of detective work, and are not especially amenable to automation.

# Codebase Examination

First, we can examine the codebase manually to look for queries being executed inside loops. This can be tougher than it sounds, since the loop may be widely separated from the query. For example, this loop looks mostly harmless:

```
<?php
foreach ($posts as $post) {
    $helper->doSomething($post);
}
?>
```

On further examination, if the doSomething() method (or one of the methods it calls in turn) issues a query to the database, then we have an N+1 problem on our hands. As such, it may not be immediately obvious where the problem originates in the codebase.

> What can be really pernicious is when the codebase makes a database call to a stored procedure, and the stored procedure itself is the origin of the N+1 problem. In that case, we will need to review the stored procedure code as well.

# Log/Profile Examination

Alternatively, we can start at the other end of the problem, and review the database query logs (or an application-level query profiler) to look for patterns in the queries. This is easier to achieve with some amount of knowledge of the application and the underlying data, but in simple cases it should be relatively obvious even without detailed application knowledge. Pattern recognition is the key to success with this approach.
