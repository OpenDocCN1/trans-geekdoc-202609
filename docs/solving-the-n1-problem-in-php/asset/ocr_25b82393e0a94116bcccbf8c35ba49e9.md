# Handling “One-To-Many” Relationships

The following is a rewritten version of our earlier posts-comments example using the query-and-stitch technique. The query to fetch the master set of Post entities is identical, but note that we follow it by creating a root collection keyed on the post_id identity values (i.e., instead of sequential keys).

```
<?php
// fetch the sequentially-indexed post entities
$stmt = 'SELECT
FROM posts
ORDER BY datetime DESC
LIMIT 10';
$stmt = $pdo->prepare($stmt);
$stmt->execute();
$post_entities = $stmt->fetchAll(PDO::FETCH_CLASS, 'Post');

// reindex the entities on their primary key values
$posts = array();
foreach ($post_entities as $post) {
    $post_id = $post->post_id;
    $posts[$post_id] = $post;
}
?>
```

Some notes about this code:

+   1. We are back to using PDO::FETCH_CLASS and letting PDO create the entity instances for us.
2. We key a new $posts collection array on the post_id values so that later we can easily look up a specific Post by its primary key. While it's tempting to change the array keys of the original result set we might unintentionally overwrite an existing key, which would be counterproductive and difficult to debug.
3. Instead of using a loop to key the $posts collection on the post_id of each entity, we could use $stmt->setFetchMode(PDO::FETCH_CLASS|PDO::FETCH_UNIQUE, 'Post'). While that would automatically key column on the first column of each returned row, it would also unset column from the row. In turn means each Post would no longer have its post_id value as a property.

Now that we have our collection of Post entities keyed on their identity values, we fetch all the Comment entities for the entire $posts collection in a single query.
