# Why Does The N+1 Problem Occur?

By thinking first about how to build collections of entities, instead of only individual entities, a developer begins to consider different approaches for entity storage and retrieval. Patterns such as TableDataGateway³, TableModule⁴, and even DataMapper⁵ implementations deal with collections of entities as a first-class part of the application. Collections are no longer an afterthought; instead, they are among the earliest considerations.

After treating entity collections as a first-class concern, it becomes relatively easy to build a single entity, one that contains only a single entity. Thus, the process to build one entity becomes identical to the process of building hundreds of them, and obviates the N+1 problem from the start.

Thus, if we can efficiently build a collection of entities, then building a single entity is also reasonably efficient. The reverse is simply not true, as we have seen by example.
