# The Process

The general process for resolving N+1 problems is as follows:

+   1. Diagnose the existence of an N+1 problem and discover its location in the codebase.
2. Determine the nature of the N+1 code:
    - If root collection and the associations are all built together, we should be able to refactor the code in place.
    - On the other hand, if the root collection is built in one location, and the associations are built elsewhere, we must either modify the code in different locations, or collect it into a single location.
3. Once the N+1 problem is resolved, test or spot-check the application to make sure it still works.
4. Commit the changes, push them to the central repository, and notify QA.
5. Diagnose the existence of any remaining N+1 problems, and start the process over again.

Since we have already gone over the diagnosis and discovery techniques for N+1 problems, we can proceed to determining the nature of the discovered N+1 code.

# N+1 In A Single Location

This is the easiest variation of N+1 to resolve. In this case, the root collection of entities and all the associations are built in a single function, method, or class. It will look something like our earlier posts-and-comments examples, and we can apply the single-query solution and/or the query-and-stitch directly on the code as it is.
