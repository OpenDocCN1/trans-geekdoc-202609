# NTP Issues

There are many network applications and services that rely on timestamps to synchronize their operations. For these operations to properly function, the systems must have synchronized clocks. For example, on a network using Active Directory Services, which relies on a complex architecture of time-sensitive clocks, computers more than minutes out of sync with the domain controller will not function properly. Certificates are also reliant on timestamps for their dates of validity, and any application that gathers information from network needs the device time to be synchronized if the logs are going to be any of use troubleshooters.

The Network Time Protocol (NTP) allows devices to synchronize their clocks with time servers on the Internet. Normally, computers have small batteries to keep their internal clocks running, but those batteries can eventually die, which might cause the system to reset to a date and time in another century. An NTP-based service would allow the system to periodically set its clock to an accurate time signal. Every operating system has a command or operation for configuring the time service. For example, in Windows, the W32tm.exe program can display a status like this:

```
Leap Indicator: 0(no warning)
Stratum: 2 (secondary reference) - synced by (SNTP)
Precision: -6 (15.625ms per tick)
Root Delay: 0.1159744s
Root Dispersion: 0.0540637s
Referenced: 0x28770664 (source IP: 40.119.6.228)
Last Successful Sync Time: 1/28/2023 9:59:35 PM
Source: time.windows.com,0x8
Poll Interval: 10 (1024)
```

If the time is not running or if it is to synchronize with an invalid source, there are other commands to specify the name of a server and other settings.
