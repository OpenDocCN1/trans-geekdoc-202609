
# Duplicate IP Address

As with MAC addresses, the IP addresses on a network must be unique. If there are hosts with duplicate IP addresses on the network, they will function intermittently or not at all. Most operating systems test the uniqueness of their IP addresses (at least on the network) by generating an ARP request broadcast to see if any host with that address replies. If one does, an error message typically appears and no access to the network works.

As a result of the ARP test, the host with the duplicate address has the MAC address of the other host in its ARP table. Troubleshooters can use that MAC address to track down the switchport to which the duplicate host is connected.

# Multicast Flooding

Switches need information about the network to function properly. They use incoming traffic to compile a table of the MAC addresses associated with their ports. However, if a switch receives traffic destined for a MAC address it doesn't know, the switch floods it out all of its ports. Multicasts are one-to-many transmissions sent to the members of a designated multicast group. A switch properly configured for multicasts has the ports for the individual group members associated with the multicast address. If a switch is not properly set up for multicasts, the transmissions are flooded to all the hosts on the network. Multicasts are often used for applications such as video feeds that cause a lot of traffic; a multicast flood can conceivably degrade the network's performance significantly. A network traffic analysis can help troubleshooters identify where the multicast transmissions are going, and the IGMP snooping allows switches to listen in the Internet Group Messaging Protocol (IGMP) traffic and use the information to add the multicast group members to their tables.

# Asymmetrical Routing

There are benefits to having redundant routes through an internetwork, especially fault tolerance when one router connection fails. One of the results, however, is a phenomenon called asymmetrical routing, which when traffic takes one router path from the source to its destination and a different router path from its destination back to the source. This can affect network performance if two router paths are running at different speeds, and it also interferes with the fault tolerance of the design. If both router paths are needed to support regular traffic, then a router failure will interrupt the connection to the destination. Asymmetrical routing can be difficult to detect and require careful configuration of the routing tables to prevent.

# Switching Loops

As noted earlier, switching loops occur as the result of a network design that includes redundant switches for fault tolerance purposes. Redundant switches enable the network to tolerate a switch or cable failure without a loss of connectivity. However, a switch connected to two switches is going to send duplicate packets to each one, result in a switching loop. The Spanning Tree Protocol (STP) enables the switches on a network segment to select designated port. The nondesignated ports are blocked from traffic, eliminating the switching loops, until a port is needed to take on the role of the designated port.

# Routing Loops

A routing loop occurs when two routers have contradictory information in their routing tables. Each of the two routers has an entry for a particular destination network in its routing table; however, the Next Hop field in each router contains the address of the other router, so packets bounce back and forth between the routers until their Time to Live (TTL) values reach zero and the packets are discarded.

# Rogue DHCP Server

As explained in Chapter 6, "Network Services, Dynamic Host Configuration Protocol (DHCP) servers provide clients with IP addresses and other TCP/IP configuration settings. A rogue DHCP server is an unauthorized server on the network to provide clients with falsified settings. Apart from the denial of service, attackers can use DHCP to point clients to their own DNS server, instead of the authorized. By loading their DNS server with false information, attackers can direct clients to fraudulent web servers and phishing attacks. Tracking a rogue DHCP server is possible using the information it supplies. Running the ipconfig /all command on an afflicted system displays the IP address of its DHCP server, as follows:


Running ipconfig and then ipconfig /renew on the affected client causes the system to generate new traffic to the DHCP server, which adds its MAC address to the ARP table and disables it. There is also a feature provided on some switches DHCP snooping that allows administrators to designate certain switchports for use. When a rogue DHCP server connects to an unoccupied port, all traffic arriving on that port is silently discarded.

# DHCP Exhaustion

Dynamic Host Configuration Protocol (DHCP) servers allocate IP addresses to clients from a pool called a scope. A scope has a limited number of addresses, and when the DHCP server allocates all of them, it cannot register new clients until the current lease expires. Attempts by clients to obtain an address from a server with an exhausted scope fail, and the clients will configure themselves with a local address that does not provide the correct network. In Windows, the self-configuration process is Automatic Private Addressing (APIPA). APIPA generates addresses on 169.254.0.0 with a subnet mask of 255.255.0 and no default gateway. When a troubleshooter finds a host with these addresses, this is a sure indication that something is wrong with the DHCP process, as scope exhaustion.

# IP Settings Issues

Every interface on a TCP/IP network has IP configuration settings that must be correct for the device to communicate with the network. Depending on how the devices obtain their settings, the chances of incorrect settings vary. On most enterprise networks, devices obtain their IP settings from a DHCP server. If a host has misconfigured IP settings, it is either due to someone manually changing the settings on the host or a misconfiguration of the DHCP server.

If the DHCP server is supplying incorrect settings, then the whole network should be affected, and the troubleshooter should start looking at the DHCP server itself. For an individual host that has misconfigured settings, whether by accident or through tampering, the troubleshooting effort should be directed at the host IP settings:

Let's look at four common issues related to IP settings:

- **Incorrect Gateway** TCP/IP parlance, a gateway is a router, and the default gateway in an interface TCP/IP configuration is the router that provides access to other networks. When the default gateway is missing or incorrect, the host will be able to access the local network, but not any other networks, including the Internet.
- **Incorrect Subnet Mask** As noted in Chapter 4, "IP Addressing," the subnet mask associated with an IP address specifies which bits of the address are network bits and which are host bits. If the subnet mask value is incorrect, the host will not be able to connect because it will be looking for a different network, which does not exist.
- **Incorrect IP Address** On a manually configured client, an incorrect IP address could duplicate that of another host on the network, which would generate an error message. It is more likely, that the incorrect address would be on a different network, which would prevent the host from connecting to the current network.
- **Incorrect DNS Configuration** TCP/IP networks use addresses, not names, to identify on a network. The names are for humans. The Domain Name System (DNS) enables a host to resolve the names specified by users into the IP addresses used by computers. If the DNS server in the IP settings is incorrect or missing, then name resolution cannot occur, and the host cannot communicate with the network.

# Missing Route

In network communications, a missing route means that one of the routers between the source and the destination does not have a routing table specifying where to forward the sending system's packets. Therefore, the path ends at that router, the packets go no further, and the traceroute command might indicate where the path ends, especially if it is on the internal network. A troubleshooter might have to manually add a route to that problem router's table or investigate the state of the routing protocols, the network is using. If the missing route is somewhere on the Internet, there is little the troubleshooter can except report it to the Internet service provider.
