## Classless Inter-Domain Routing (CIDR)

Classless addressing has largely overtaken class addressing because it enables administrators to utilize the addresses allotted to them more efficiently. To simplify the notation of classless addresses, it is more common to use Classless Inter-Domain Routing (CIDR). In CIDR notation, the subnet mask for an address is written by appending a slash to the end of the address and specifying the number of network identifiers, as in the following example: 172.116.20/22.

This example describes a Class B address with a 22-bit network identifier, 6 bits of which function as a subnet identifier, shown in Figure 4.3. This subnet identifier allows administrators to create up to 64 (2⁶) subnets, leaving the remaining 10 bits for the host identifier, which supports up to 1,022 (2¹⁰) per subnet. This is the CIDR equivalent to the network address 172.16.20/22 with a mask of 255.255.240.252.

### Converting Binaries and Decimals

The Network+ exam typically includes questions on subnetting that require students to calculate IP addresses. When calculating addresses manually, the biggest problem is often converting between binary and decimal values. To convert a binary value into a decimal, assign decimal values to each of the binary bits, incrementing them from right to left and doubling them, as follows:

| 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
|---|---|---|---|---|---|---|---|
| 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

Then, plug the bits of the binary value to be converted, in this case 1011000, and add the decimals for each of the 1 bits together, resulting in 172, as follows:

| 1 | 0 | 1 | 1 | 0 | 0 | 0 |
|---|---|---|---|---|---|---|---|
| 128 | 64 | 32 | 16 | 8 | 4 | 2 | |

128 + 32 + 8 = 172

To convert a decimal to binary, subtract each of the incremented values, from left to right, from the number to be converted. For each of the incremented values it is possible to subtract, assign a binary value of 1. For all of the other values, assign a 0. Starting with 172, it is possible to subtract 128, 32, 8, and 4, resulting in a binary value of 1011000, as shown:

## IPv4 vs. IPv6

Internet Protocol version 6 expands the address space from 32 bits to 128 bits, increasing the number of possible IP addresses from 4.2 billion (2³²) to 340 undecillion (2¹²⁸). IPv6 uses hexadecimal notation instead of decimal, and addresses are separated by colons. Instead of IPv4, IPv6 allows shorthand to omit leading zeros and consecutive blocks of ones, as follows:

2001:0db8:85a3:0000:0000:8a2e:0370:7334
2001:db8:85a3::8a2e:370:7334

### IPv6 Types

IPv6 uses three types of addresses: unicast, multicast, and anycast. IPv4 does not use broadcast, but introduces:

- **Global Unicast**: A fully routable address used on the Internet.
- **Link local (fe80::/64)**: An address used within a local segment, not routtable.
- **Multicast**: Used to reach a group of devices, using Internet Management Protocol (IGMP).

- **Loopback**: An address used to test the local software, like 127.0.0.1.

### IPv6 Autoconfiguration

All IPv6 systems assign themselves a local address using stateless address autoconfiguration (SLAAC). To determine the address, the system generates a router solicitation (RS) message as a multicast to all routers. The router responds with a router advertisement (RA) message that contains the network identifier. To generate the host identifier for its link address, the IPv6 system process, in which it takes the 48-bit MAC address of the interface, splits it into 24-bit halves, and inserts the 16-bit value 0xFFFF between the two. This is a 64-bit value called Extended Unique Identifier-64 (EUI-64), which the system uses as the host identifier portion of the address.

## Transitioning to IPv6

IPv6 has existed for more than 20 years, but the Internet and many private networks use IPv4. To provide support for both protocols during the transition from IPv4 to IPv6, several mechanisms are available.

### Dual Stack

A dual stack system is one that has both IPv4 and IPv6 protocol stacks, both of which interface with the link layer protocol. This enables the communicate with IPv4 and IPv6 devices on the network. however, all of the intervening systems between a source and a destination, including routers and Domain Name System (DNS) servers, must support dual stacks as well. Routers do this by using subinterfaces, logical network interfaces created from a single physical interface, which each have their own virtual IP (VIP) addresses.

### Tunneling

Another method that allows IPv6 devices to communicate on IPv4 networks is tunneling. Tunneling is the process of encapsulating one entire packet inside another to facilitate its transmission over the network. It is common to use tunneling for security purposes, but in this case, encapsulating an IPv6 datagram within an IPv4 packet allows IPv6 systems to communicate, even if some or all of the intervening networks only support IPv4. Some of the common tunneling protocols used for IPv6 transition include 6to4, Intra-Site Automatic Tunnel Addressing Protocol (ISATAP), and Teredo, all of which use some to establish IPv4 tunnel endpoints that can carry IPv6 traffic between them.
