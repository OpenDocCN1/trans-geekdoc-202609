Running ipconfig and then ipconfig/renew on the affected client causes the system to generate new traffic to the DHCP server, which adds its MAC address to the ARP table. The part -g command displays the table containing the DHCP server's MAC address, which the troubleshooter can then use to find the switch providing the server's network connection and disable it.
There is also a feature provided on some switches DHCP snooping that allows administrators to designate certain switchports for use by DHCP servers. When a rogue DHCP server connects to an unoccupied port, all DHCP traffic arriving on that port is silently discarded.

# DHCP Scope Exhaustion

Dynamic Host Configuration Protocol (DHCP) servers allocate IP addresses to clients from a pool of addresses called a scope. A scope has a limited number of addresses, and when the DHCP server allocates all of them, it cannot register new clients until the current lease expires. Attempts by DHCP clients to obtain an address from a server with an exhausted scope fail, and the clients will configure themselves with a local address that does not provide the correct network.
In Windows, the self-configuration process is Automatic Private IP Addressing (APIPA). APIPA generates addresses on the 169.254.0.0 network with a subnet mask of 255.255.0.0 and no default gateway address. When a troubleshooter finds a host with these addresses on a DHCP network, this is a sure indication that something is wrong with the DHCP process, as scope exhaustion.
