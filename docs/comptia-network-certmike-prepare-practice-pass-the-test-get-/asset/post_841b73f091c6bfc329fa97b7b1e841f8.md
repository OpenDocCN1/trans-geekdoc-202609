### Channel Overlap

Because the 2.4 GHz band is relatively narrow, there is a lot of overlap between channel frequencies. This can result in interference if there are two devices near each other using adjacent channels. In fact, to avoid interference from adjacent channels altogether on a 2.4 GHz network, only three channels are safe: 1, 6, and 11, as shown in Figure 12.2.

![](img/131506e178f74f7b4704a0aa0fe03dae_175_1.png)

FIGURE 12.2 Nonoverlapping 22 MHz channels in the 2.4 GHz band

Many network administrators have made a standard rule to use only these three channels on their networks, even though every Wi-Fi technology uses the same channel spacing. 802.11g networks use a type of radiofrequency modulation that creates 20 MHz channels instead of 22 MHz. Adjusting the overlap to account for the narrower bandwidth, the non-conflicting channels on an 802.11g network are 1, 5, and 9, as shown in Figure 12.3.

In the 5 GHz band, there are many more channels, and overlap is not as much of a problem in the 2.4 GHz band. The 802.11a standard was the first to use the 5 GHz band, and at the time, it was a high-priced alternative for networks that could not use 2.4 GHz.

Prices eventually came down, however, and beginning with the 802.11n standard, dual-frequency devices became common.

### Channel Bonding

Another feature included in the 802.11n standard is channel bonding, which is the ability to combine the bandwidth of adjacent channels to increase throughput. Two bonded channels provide 40 MHz of bandwidth, which is practical on a 5 GHz network, but not on 2.4 GHz network, which would be monopolized by just one bonded channel.

In the subsequent 802.11ac and 802.11ax standards, the ability to bond channels is expanded, allowing multiple 20 MHz channels to be combined up to a 160 MHz channel throughput. As the bonded channels get larger, however, they consume more of the available bandwidth, so the network supports fewer of them. For example, bonding eight channels creates a 160 MHz connection, but a 5 GHz network can only support two of these connections. The same network could support up to 80 MHz or 12 MHz channels.

### Service Set Identifiers

A service set identifier (SSID) is the name by which a WLAN is identified on the network. Wireless access points advertise their SSIDs by transmitting beacon announcements. When connecting to a wireless network, a device receives the beacon announcements and displays a list of SSIDs identifying all of the WLANs in the area. In addition to SSID, access points have a 48-bit basic set identifier (BSSID). A network can have multiple access points serving the same set of devices with a single SSID, but each WAP has a unique BSSID, which is how they tell each other apart.

SSIDs can be up to 32 bytes long and can also be configured with a null value what the 802.11 standards call a wildcard SSID. A wildcard SSID—sometimes called a nonbroadcast SSID—is still operational but does not appear in the list of advertised WLANs. Some administrators use wildcard SSIDs as a security mechanism, figuring that intruders cannot attack a network if their SSID is not visible, but this is a technique that is only modestly effective.

Three operational modes for wireless networks are defined in the 802.11 standards.

- **Basic Service Set (BSS)**: Also known as infrastructure mode, it requires an access point to connect clients.
- **Extended Service Set (ESS)**: A collection of two or more BSSs, which uses a common SSID to allow roaming between access points.
- **Independent Basic Set (IBSS)**: Also known as ad hoc mode, it allows devices to connect directly to each other without an access point.

### Encryption Standards

The first version of wireless encryption, Wired Equivalent Privacy (WEP), was found to be vulnerable. To replace WEP, the Wi-Fi Alliance introduced Wi-Fi Protected Access (WPA) in 2003. WPA uses Temporal Key Integrity Protocol (TKIP) which is based on WEP but adds a message check.

The similarities between WEP and WPA were deliberate, but Wi-Fi Protected Access 2 (WPA2) was introduced in 2004. WPA2 continues to support TKIP for backward compatibility, but it also Counter Cipher Block Chaining Message Authentication Code (CCMP) with the Advanced Encryption Standard (AES).

WPA and WPA2 both have operational modes:

- **WPA2 Personal**: Also known as WPA2-PSK or Pre-Shared Key, it requires a 32-byte alphanumeric key for encryption, which makes the protocol vulnerable to brute-force attacks.
- **WPA2 Enterprise**: Also known as WPA2-802.1X, it requires a Remote Authentication Dial-In Service (RADIUS) server to authenticate users. Although a more complicated deployment, this provides much greater security than a pre-shared key because it provides centralized authentication, authorization, and accounting (AAA) for individuals.

As the names imply, WPA2 Personal is best suited for residences or small offices in which the users cannot be trusted to share the pre-shared key. On a network with many users, the chances of a pre-shared key being compromised are much higher. When it does happen, changing the key requires that all of the access points and client devices be reconfigured with the new key value, which can be a highly time- and labor-intensive task.

WPA2 Enterprise eliminates the need for a pre-shared key; it provides centralized authentication, authorization, and accounting (AAA) for individual users. Clients connecting to the network must supply their individual credentials before they can access resources. Because it requires an external RADIUS server, WPA2 Enterprise is considerably more complicated and expensive to deploy than WPA2 Personal. Although they did not exist when the WPA2 standard was designed, cloud-based RADIUS servers are now available that can make the WPA2 Enterprise deployment process simpler and less expensive.

## EXAM TIP

There is no standardized of security options for access points and wireless devices, since their configuration interfaces vary. Some products just use the term WPA2 Personal, for example, but others use PSK and might also specify the encryption cipher, as in WPA2-PSK (AES). Candidates for the Network+ exam should be aware of the various components used in the Wi-Fi security protocols and the names used to refer to them.
