## VLANs

As noted earlier, switches create a separate collision domain for each pair of connected devices, eliminating the collisions and the media access control problems that occur on hub-based networks. however, a network connected with switches is still one big broadcast-domain. On a large network with many switches, the propagation of broadcast messages to all the switches and generates a huge amount of traffic throughout the network.

It is possible, however, to segment a switch into multiple broadcast domains by creating virtual local networks (VLANs). This also makes it possible to secure a group of hosts by adding to a VLAN that isolates them from the other VLANs on the network.

By default, switches that support VLANs have a default VLAN, typically called VLAN1. All of the switch's ports frame them by default, resulting in a single broadcast domain. Administrators can then create additional VLANs on the switches, calling them by the VLAN name plus, and add ports to the VLANs as needed. Each new VLAN becomes a separate broadcast domain.

VLANs are virtual, but they are functionally the same as if they were separate physical networks. With physical VLANs, the only way for VLANs to communicate with each other is through routing. The routing can be virtual as well, which is how multilayer switches with routing capabilities built into them work.

## Trunking

A VLAN can have ports from any switch in the network in it, as long as the switches are connected in such a way that the ports in a VLAN can communicate with each other. To make this possible, each switch must have a port dedicated to inter-switch communication called a trunk port. The trunk ports in the switches exchange all traffic, regardless of the VLAN it belongs. The other ports—called access ports—carry only the traffic for the VLANs to which they are assigned.

Trunk ports work with traffic from all of network's VLANs at once, so switches have a means of identifying the VLAN for each packet. This is 802.1Q tagging. IEEE 802.1Q is a standard that defines the format of a 4-byte field that adds to the Ethernet header of each frame they transmit using the trunk port. This field contains a 12-bit VLAN identifier value, which means the network can support up to 4,094 (2¹²-1) VLANs.

Only trunk traffic includes an 802.1Q field in each packet. When a switch receives incoming traffic that is destined for a host in the same VLAN and connected to the switch, it forwards the packets directly to the host using its access port. However, if the destination is in the VLAN but physically connected to another switch, the sending switch adds 802.1Q field to the packets and sends them out to other switches through its trunk port. The switch to the destination host is connected receives the packets over its trunk port, removes the 802.1Q tags, and then forwards the packets to the destination host using its access port.

## Voice VLANs

As a general rule, an access port on a switch can only be associated with one VLAN. However, with most networking rules, there is an exception. On some switches, it is possible to create a VLAN that allows administrators to prioritize VoIP traffic over standard data traffic, leaving the default VLAN in place to accommodate the data traffic. This makes it possible to power a VoIP phone and the computer with a single switch port.

Plugging the phone into the switch port and the computer into the phone's auxiliary jack connects both to the network. The packets carrying VoIP traffic are tagged with a 4-byte field in the Ethernet header, similar to 802.1Q tagging. Ordinary data packets are left untagged. VoIP phones can scan packets for the tags. They process the tagged packets as voice traffic and forward the untagged packets to the computer.

## EXAM TIP

The Network uses the term virtual local area network to refer to regular VLANs and distinguish them from voice VLANs. The term is nonstandard, however, and exam candidates should know that it refers to a normal VLAN.

## Port Configuration Settings

The simplest unmanaged switches, intended for home and small office use, have a row of UTP ports and a power cable. There is nothing to configure. Higher-end managed switches have a variety of settings that administrators can configure, many of which they can set for each port individually.

The administrative interface of a managed switch varies by product and manufacturer. Some switches have a console port, into which it is possible to plug a laptop running a terminal emulation program with a command-line interface. This is called in-band management. Other switches require administrators to access the switch over the network connection. Still other switches include a built-in interface that provides the switch with a graphical configuration interface. These are examples of out-of-band management.

Some of the configurable features often found on managed switches are as follows:

### Duplex

Most switches autodetect the traffic on the network and use full duplex communication by default, which allows hosts to transmit and receive data simultaneously. Older (usually hub-based) networks use half duplex communication, meaning that hosts can transmit or receive data at any one time, but not both. Although it is rarely necessary... duplex communication for a particular port.

The speeds of the Ethernet networks have increased over the years, but the standards are backward compatible. Connecting a Fast Ethernet port to a Gigabit switch causes the switch port to adjust its speed from 1,000 to 100 Mbps. It is also possible to manually configure a switch port to a specific speed, but this is not usually necessary.

### Port Aggregation

A mechanism for combining the bandwidth of two or more ports to create a single aggregated port with increased bandwidth. Many switches use the Link Aggregation Control Protocol (LACP) to manage port aggregations.

## Flow Control

An Ethernet standard for the regulation of transmission based on network congestion. A host can generate an Ethernet Pause frame with a delay value, which causes the switch to stop forwarding traffic to that host until the delay expires or the host sends another frame with a delay value of 0.

## Port Mirroring

Switches forward packets only to the destinations, which makes it difficult for administrators to monitor network traffic for a specific port. Port mirroring, when enabled, creates a relationship between the selected port and another unused port. This allows administrators to connect a protocol analyzer to the mirror port and capture network traffic.

## Port Security

To help prevent intruders from connecting unauthorized devices to the network, administrators can secure individual switch ports by specifying the MAC addresses of the only devices permitted to use them.

## Jumbo Frames

In the IEEE 802.3 standards, the default maximum payload size for an Ethernet frame is 1500 bytes. However, Ethernet equipment manufacturers have for years supporting larger frame sizes, collectively called jumbo frames. Jumbo frame sizes can vary, but a 9,000-byte maximum payload is common. Jumbo frame capability is not defined in any of the 802.3 standards, and administrators can configure switch ports to support it or not. Using jumbo frames on a network, all of the switches and adapters processing the packets must have the feature enabled.

## Power over Ethernet (PoE)

A standard published by the IEEE 802.3 working group defines a method for Ethernet networks to supply power to remote devices over UTP cables. These devices such as Voice over IP (VoIP) phones, wireless access points, and remote video cameras to function on the network without the need for a separate power source. The first PoE standard called for the transmission of 12.95 watts of power. In later standards, Power over Ethernet Plus (PoE+) increased the power to 25.5 watts, and PoE++ increased it further, with power levels of 51 and 71.3 watts.
