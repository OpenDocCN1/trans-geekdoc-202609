# HVAC

供暖、通风和空调（HVAC）是任何运行网络设备场所的关键服务。数据中心可能包含几十个或数百台设备，所有这些设备都会产生大量的热量，并且对温度和湿度非常敏感。大多数人都知道，过热会缩短电气设备的寿命，但过冷会导致水汽凝结，从而造成损坏。同样，湿度过高（结露）或过低（静电）都会导致问题。在规划良好的数据中心，HVAC 是整体设计中不可或缺的一部分，传感器位置和气流路径经过仔细选择，以提供理想的运行环境。

一种常见的设计是面对面和背对背排列设备列。安装的设备从前面吸入冷空气，并从后面排出比之前热得多的空气。在这种设计中，面对面的列是冷通道，背对背的列是热通道。通风系统随后被设计有用于热空气的进气风口。

对于服务器集群和其他中间配线架，HVAC 可能会成为更大的问题，这些设备有时位于并非专门为该目的设计的较小空间内，可能难以加热和冷却。

# 灭火系统

除了调节后的动力源和 HVAC 系统外，数据中心还应该具备某些灭火手段，以限制数据中心对外部火灾的脆弱性，并防止源自数据中心的内部火灾蔓延。有多种类型的灭火系统，其中最有效且昂贵的是向数据中心充入惰性气体，通过排出氧气来窒息火源（以及区域内任何没有呼吸设备的人员）。

惰性气体灭火系统的主要优势是气体对电气设备没有永久性影响。这些系统比使用水或泡沫的系统要贵得多，但更换受水损坏设备的潜在成本远高于灭火系统的成本。

# 冗余与高可用性概念

冗余是网络组件设计以及网络本身设计中的关键概念。对于许多事物，冗余是成本与效率之间的权衡。管理员通常选择安装冗余组件有两个原因：容错能力和高可用性（HA）。接下来将讨论设计和构建冗余系统时涉及的一些概念。

# 主主模式 vs. 主备模式

正如本章前面提到的，冗余系统通常以以下两种方式之一运行：

- **主主（Active-Active）**：设备始终处于完全运行状态，提供容错能力以及负载均衡的机会。

- **主备（Active-Passive）**：一个设备始终运行，另一个处于备用模式，准备在主设备故障时接管。

主主和主备技术在所有层级的冗余系统中都是常见的。然而，在处理企业级冗余时，还有其他高可用性概念需要考虑，例如当企业准备应对导致整个设施无法使用的重大灾难时。

# 冗余数据中心

数据中心冗余的终极形式简单是在不同的位置拥有另一个数据中心。对于无法忍受任何重大停机服务的组织来说，一个可以在公司总部数据中心损坏或毁灭时进行替代的复制数据中心是一个关键需求。

- **冷备场（Cold Site）**：完全不是数据中心，冷备场是拥有所有必要电源、HV 和管道设施的租赁物业，但没有任何设备。冷备场的建设和维护成本最低，但安装和配置所有设备的时间最长。

- **温备场（Warm Site）**：该站点在费用和恢复功能的时间上介于热、冷之间。温备场通常包含所有必要的建筑基础设施以及重建网络所需的部分或全部硬件，因此恢复功能的时间明显短于冷备场，而长于热备场。在某些情况下，组织会将设备转移到温备场。

- **热备场（Hot Site）**：热备场是一个设备完备并准备就绪冗余数据中心，建筑基础设施、服务连接和所有网络硬件均已安装并配置。上线只需要传输最新数据。建设和维护热备场通常是一项巨额支出，但在发生灾难时，替代站点可以在几分钟内上线。

这些冷、温、热备场的定义指的是物理数据中心，但一种日益流行的替代方案是云站（cloud site）。云站是由服务提供商托管的云网络创建的虚拟数据中心。与任何物理站点相比，云站的构建和维护成本要低得多，因为所有设施和基础设施成本都由服务商承担。一些提供商提供了预包的虚拟数据中心供此使用。

# 多 ISP 与 多样路径

对于许多组织而言，互联网连接是它们的命脉；没有它就无法运行，因此冗余可以应用于单个设备或公司网络，外部服务连接也可以是冗余。

互联网冗余（ISP）的一种方法是至少到互联网服务供应商处建立两个独立的连接，最好使用不同的路由器和运营商。这创建了通往互联网的多样化路径，并针对路由器和运营商故障提供了保护。然而，如果 ISP 所有者出现故障，则两个连接都会中断。更好的解决方案是将网络连接到多个 ISP，理想情况下它们不共享相同的上游提供商。甚至可以通过为每个 ISP 安装多个连接来结合这两种方法。
