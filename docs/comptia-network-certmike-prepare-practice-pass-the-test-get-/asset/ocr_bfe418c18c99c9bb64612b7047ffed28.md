# AUTHENTICATION AND AUTHORIZATION CONSIDERATIONS

Many remote access solutions are available with security capabilities that vary widely, but all them suffer from the same fundamental weakness: they open a great big door to your network with flashing lights and a neon WELCOME sign. The nature of the protection that network administrators provide at that door must be a critical part of any remote access server deployment.
*Authentication* is the basic credential check that all remote users undergo before they gain any access to the host network. Many remote access server products are capable of using other services on the network for authentication, such as RADIUS, TACACS+, and Directory. The authentication process for remote access users should be, if anything, more rigorous than that for on-premises users. Multifactor authentication, a practice that seemed extreme just a few years ago, is now commonplace, typically using a username/password and a one-time code sent to a smartphone or email address.

Authorization is the process of controlling access to specific network resources, often employing a system of permissions that enables administrators to precisely tune the access to specified users. The theory of least permissions, in which users are granted the minimum access they need to perform their tasks, applies to remote access even more strenuously than it does for an on-premises user.
