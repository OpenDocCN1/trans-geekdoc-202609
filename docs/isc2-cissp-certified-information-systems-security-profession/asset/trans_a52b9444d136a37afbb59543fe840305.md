
-   [层级模型](#c20.xhtml#figure20-7)是企业组织结构图。请注意，此处的**一对多**数据模型在此示例中成立。每位员工只有**一个**管理者（即“一”），但每位管理者可能有**一个或多个**员工（即“多”）。其他层级数据模型的示例包括NCAA March Madness锦标赛对阵系统以及互联网上用于域名系统（DNS）记录的层级分配。层级数据库以这种层级方式存储数据，适用于符合该模型的专用应用。例如，生物学家可能会使用层级数据库来按**领域/门类/纲类/目类/科类/属类/种类**的层级模型存储标本数据。

-   [分布式数据模型](#)的数据存储在多个数据库中，但这些数据库在逻辑上是相连的。用户将数据库视为一个整体，尽管它由网络上相互连接的多个部分组成。每个字段既可以有**多个子项**，也可以有**多个父项**。因此，分布式数据库的数据映射关系为**多对多**。

### 关系数据库

-   关系数据库由**二维平面表**组成，表由行和列构成。实际上，每张表类似于**表格文件**。行和列结构提供**一对一**数据映射关系。关系数据库的基本构建块是**表**（也称为`relation`）。每张表包含一组相关记录。例如，销售数据库可能包含以下表：

*   `Customers` 表，包含组织所有客户的联系信息

*   `Sales Reps` 表，包含组织销售人员的身份信息

*   `Orders` 表，包含每位客户下的订单记录

-   每张表包含若干**属性**（即`fields`），每个属性对应表中的**列**。例如，`Customers` 表可能包含公司名称、地址、城市、州、邮编和电话号码等列。每位客户通过一条记录（`tuple`，即表中的行）表示。表中的**行数**称为`cardinality`，**列数**称为`degree`。属性的`domain`是该属性允许取值的集合。`![Figure 20.8](#c20.xhtml#figure20-8)` 显示了一个关系数据库中的`Customers` 表示例。

`![FIGURE 20.8](#c20.xhtml#figureanchor20-8) Customers table from a relational database`

-   在此示例中，表的`cardinality` 为 3（对应表中 3 行），`degree` 为 8（对应 8 列）。表的`cardinality` 在正常业务过程中会变化，例如销售人员添加新客户时。表的`degree` 通常变化不频繁，一般需要数据库管理员介入。

-   表之间的**关系**用于标识相关记录。例如，`Customers` 表与 `Sales Reps` 表之间存在关系，因为每位客户被分配一个销售代表，而每位销售代表负责一个或多个客户。该关系体现在`Customers` 表中的`Sales Rep` 字段/列，如`![Figure 20.8](#c20.xhtml#figure20-8)` 所示。该列的值指向`Sales Reps` 表中的 `Sales Rep` ID 字段（图中未显示）。此外，`Customers` 表与 `Orders` 表之间也应存在关系，因为每笔订单必须关联到客户，而每位客户可关联多个产品订单。`Orders` 表（未显示）可能包含`Customer` 字段，其中存储`Customers` 表中的 `Customer` ID 值（如`![Figure 20.8](#c20.xhtml#figure20-8)` 所示）。

-   记录使用多种**键**进行唯一标识。简单来说，`keys` 是表中字段的子集，用于唯一标识记录，同时也用于表间**连接**以交叉引用信息。你应熟悉三种键类型：

**Candidate Keys** `candidate key` 是一组属性的子集，能够唯一标识表中任意记录。同一表中不存在两条记录拥有相同的候选键属性值。每张表可能有**一个或多个**候选键，这些键从列标题中选取。

**Primary Keys** `primary key` 从候选键集合中选出，用于唯一标识表中的记录。每张表仅有一个主键，由数据库设计者从候选键中选定。RDBMS 通过**禁止插入多条相同主键的记录**来强制主键唯一性。在`Customers` 表（如`![Figure 20.8](#c20.xhtml#figure20-8)` 所示）中，`Customer ID` 很可能是主键。

**Foreign Keys** `foreign key` 用于强制两表之间的**关联**，也称为**referential integrity**（引用完整性）。引用完整性确保若一表包含外键，则该外键对应另一表中仍然存在的主键。它保证不存在记录引用不存在的主键记录。如前所述，`Customers` 表中的`Sales Rep` 字段是外键，指向`Sales Reps` 表的主键。

-   所有关系数据库使用标准语言 **Structured Query Language (SQL)** 为用户提供一致的数据存储、检索和修改接口，以及数据库管理系统（DBMS）的管理控制。各 DBMS 供应商实现略有不同的 SQL 版本（如 Microsoft 的 Transact‑SQL 和 Oracle 的 PL/SQL），但均支持核心功能集。SQL 的主要安全特性是**授权的细粒度**。这意味着 SQL 允许在非常细微的粒度上设置权限，例如按表、行、列，甚至单个单元格进行限制。

-   SQL 为管理员、开发人员和最终用户提供了完整的功能，以便与数据库交互。事实上，当前流行的图形化数据库界面仅在标准 SQL 接口之上包装额外的钟表花式。SQL 本身分为两个主要组成部分：**数据定义语言 (DDL)**，用于创建和修改数据库结构（即`schema`），以及**数据操作语言 (DML)**，用于与所在 schema 中的数据进行交互。

### 数据库事务

-   关系数据库支持**显式**和**隐式**事务，以确保数据完整性。每个事务是一组 SQL 指令，要么全部成功，要么全部失败。事务的任何部分不能单独成功。例如，银行两账户之间的转账可能使用以下 SQL 代码：先向账户 1001 添加 250 美元，再从账户 2002 减去 250 美元：

```
BEGIN TRANSACTION
UPDATE accounts
SET balance = balance + 250
WHERE account_number = 1001;
 
UPDATE accounts
SET balance = balance – 250
WHERE account_number = 2002
 
END TRANSACTION
```
