
-   [考虑用于个人交互和团队协作及沟通的几种现代即时通讯解决方案]。一些是公共服务，例如`Twitter`、`Facebook Messenger`和`Snapchat`。另一些是面向私有或内部使用的，例如`Slack`、`Google Hangouts`、`Cisco Spark`、`Workplace by Facebook`和`Skype`。大多数即时通讯服务都以安全为核心设计，通常采用多因素认证和传输加密。

## Manage Email Security

电子邮件是互联网上使用最广泛和最常用的服务。互联网上主要采用的电子邮件基础设施包括使用`Simple Mail Transfer Protocol (SMTP)`的邮件服务器，用于接受客户端提交的消息、将这些消息传输到其他服务器以及存储到用户的服务器端邮箱中。除了邮件服务器，基础设施还包括电子邮件客户端。客户端使用`Post Office Protocol version 3 (POP3)`或`Internet Message Access Protocol (IMAP)`从服务器端邮箱中检索电子邮件。客户端通过`SMTP`与邮件服务器通信。许多面向互联网的电子邮件系统依赖于X.400标准进行地址和消息处理。

`Sendmail`是Unix系统中最常用的SMTP服务器，`Exchange`是Microsoft系统中最常用的SMTP服务器。除了这三款流行产品之外，还有众多替代方案，但它们都共享相同的基本功能并遵循互联网电子邮件标准。

如果部署SMTP服务器，必须正确配置入站和出站邮件的认证。SMTP设计为邮件中继系统，意味着它会将邮件从发送者中继到预定的接收者。然而，你需要避免将SMTP服务器配置为`open relay`（也称为开放中继代理或`relay agent`），即不验证发送者就接受并转发邮件的SMTP服务器。开放中继是垃圾邮件的主要目标，因为它们允许垃圾邮件发送者利用不安全的邮件基础设施发送大量邮件。随着开放中继被加固为受认证或封闭的中继，越来越多的SMTP攻击是通过被盗用的已认证用户账户实施的。

另一种企业电子邮件的选择是SaaS电子邮件解决方案。例如，云端或托管电子邮件包括`Gmail (Google Apps for Business)`和`Outlook/Exchange Online`。SaaS电子邮件使你能够利用一些最大的互联网导向组织的安全经验和管理专业知识来支持公司的通信。SaaS电子邮件的优势包括高可用性、分布式架构、易于访问、标准化配置以及与物理位置无关。然而，使用托管电子邮件解决方案也存在一些潜在风险，包括黑名单问题、速率限制、应用/插件限制以及你可以部署的额外安全机制（如果有的话）。

### Email Security Goals

互联网上基本的电子邮件机制能够高效传输消息，但缺乏提供机密性、完整性或可用性的控制。换句话说，基础电子邮件并不安全。然而，你可以通过多种方式为电子邮件添加安全性，这些方式可能满足以下一个或多个目标：

*   提供不可否认性

*   将消息访问权限限制在其预定义的接收者（即隐私和保密性）

*   维护消息的完整性

*   对消息的来源进行身份验证和确认

*   验证消息的送达

*   对消息内部或附件中的敏感内容进行分类

与任何IT安全方面一样，电子邮件安全始于经上级管理层批准的安全策略。在安全策略中，必须解决以下几个问题：

*   电子邮件的可接受使用政策

*   访问控制

*   隐私

*   电子邮件管理

*   电子邮件备份和保留政策

可接受使用政策定义了在组织的电子邮件基础设施上可以执行和禁止的活动。通常规定可以发送和接收专业、面向业务的电子邮件以及有限的个人电子邮件。具体限制通常针对为其他组织（包括自雇）进行的个人业务，以及发送或接收非法、不道德、冒犯性的通信，以及从事任何可能对生产力、盈利能力或公共关系产生不利影响的其他活动。

访问控制应确保用户仅能访问其特定的收件箱和电子邮件存档数据库。这一规则的延伸意味着，无论是授权用户还是未经授权的用户，都不能访问个人的电子邮件。访问控制应既提供合法访问，也提供一定程度的隐私，至少要防止其他员工和未经授权的入侵者。

实施、维护和管理组织电子邮件的机制和流程应予以明确说明。终端用户可能不需要知道电子邮件管理的具体细节，但他们需要知道电子邮件是否被视为私密通信。电子邮件最近成为众多法院案件的焦点，在这些案件中，存档消息被用作证据——往往让消息的发送者或接收者感到非常不快。如果电子邮件需要保留（即备份并存档以供将来使用），用户必须知晓此事。如果审计人员需要审查电子邮件以查找违规行为，用户也需要被告知。一些公司选择在销毁前仅保留电子邮件存档的最后三个月，而其他公司则选择保留电子邮件多年。根据你所在的国家和行业，通常会有法规规定保留政策。

### Understand Email Security Issues

部署电子邮件安全的第一步是认识到电子邮件特有的漏洞。用于支持电子邮件的标准协议（即SMTP、POP和IMAP）不原生支持加密。因此，所有消息都以提交给邮件服务器时的形式传输，通常是纯文本格式，这使得拦截和窃听变得轻而易举。然而，缺乏原生加密是与电子邮件相关的最不重要的安全问题之一。

电子邮件是病毒、蠕虫、特洛伊木马、带有破坏性宏的文档以及其他恶意代码的常见传播途径。支持多种脚本语言、自动下载功能以及自动执行特性的兴起，使得电子邮件内容中的超链接和附件成为对每个系统的严重威胁。

电子邮件缺乏源验证机制。伪造电子邮件的发件人地址是即使是新手攻击者也能轻松完成的过程。电子邮件头部可以在其源头或传输过程中被修改。此外，还可以直接通过连接到邮件服务器的SMTP端口将电子邮件直接发送到用户的收件箱。关于传输中的修改，电子邮件本身也没有原生完整性检查，无法确保消息在源和目的地之间未被篡改。

此外，电子邮件本身也可以作为攻击手段。当大量消息被指向单个用户的收件箱或特定SMTP服务器时，会导致拒绝服务（DoS）攻击。这种攻击通常被称为邮件洪水攻击（mail-bombing），即通过向系统发送大量消息来实施DoS。DoS的结果可能是存储容量消耗或处理能力利用率提升。无论哪种情况，结果都是一样的：合法消息无法送达。
