**问题 334。** 一个在线银行网站使用了一种系统，在用户无活动 10 分钟后自动注销用户，以确保如果用户忘记注销，其他人无法更改其银行详情。该银行网站最直接针对 CIA 三要素（CIA triad）中的哪种原则？

(A) 机密性 (Confidentiality)
(B) 可用性 (Availability)

(C) 身份认证 (Authentication)
(D) 完整性 (Integrity)

**解释 334. 正确答案：D. 完整性。** CIA 三要素中的完整性维度确保数据的准确性和可靠性。通过在无活动一段时间后注销用户，银行网站旨在防止用户银行详情被未经授权的修改（可能由获取了无人会话的他人进行），从而维护数据的完整性。

**选项 A 错误。** 虽然注销用户确实具有机密性方面，但此场景中的主要目标是防止未经授权的更改，而不是未经授权的查看。

**选项 B 错误。** 可用性确保授权用户在需要时访问数据和系统。此场景没有讨论根据系统运行时间或可访问性提供或限制访问。

**选项 C 错误。** 身份认证确保用户是他们声称的身份。虽然该场景涉及安全措施，但这里的主要关注是防止对数据的未经授权更改，这与完整性相符，而不是身份认证。

**问题 335。** 用户 Amy 想安全地向同事 Bob 发送一份机密文件。Amy 决定加密文件以确保其机密性。Amy 应该使用以下哪项来加密文件，以确保只有 Bob 可以解密？

(A) Amy 的私钥
- (B) Amy 的公钥
- (C) Bob 的私钥
- (D) Bob 的公钥

**解释 335. 正确答案：D. Bob 的公钥。** 在非对称加密中，如果使用个人的公钥加密消息，则只有对应的私钥可以解密。因此，为了确保 Bob 是唯一可以解密文件的人，Amy 应该使用 Bob 的公钥进行加密。

**选项 A 错误。** 使用 Amy 的私钥加密将允许任何拥有 Amy 公钥的人解密，而且它作为数字签名而不是确保机密性。

**选项 B 错误。** 使用 Amy 的公钥没有意义，因为那样只有 Amy 的私钥可以解密。

**选项 C 错误。** 私钥绝不应共享或用于加密。它的主要用途是解密和签名。

**问题 336。** 一家科技初创公司正在开发移动应用程序，由于许可协议，该程序仅向特定国家内的用户提供独家内容。初创公司应该使用哪种方法来确保只有该国家的用户可以访问内容？

- (A) 集成基于时间的一次性密码 (TOTP) 系统
- (B) 使用基于地理位置的访问控制
(C) 启用生物识别认证
(D) 实现 IP 白名单

**解释 336. 正确答案：B. 使用基于地理位置的访问控制。** 基于地理位置的访问控制可以识别用户的地理位置，并根据定义的地理边界允许或拒绝访问，这是最符合初创公司需求的解决方案。

**选项 A 错误。** TOTP 系统提供基于时间的第二因素身份认证，而不是基于地理位置。

**选项 C 错误。** 生物识别认证根据物理或行为特征验证用户身份，但不根据地理位置限制访问。

**选项 D 错误。** IP 白名单仅允许特定 IP 地址访问。虽然它可以提供某种程度的地理限制，但它没有基于地理位置的控制那么精确，并且可能会无意中阻止或允许用户。

**问题 337。** 一个组织的 IT 部门注意到过去 24 小时内网络流量激增。同时，许多员工报告他们的系统运行缓慢，并且他们从同事的邮件收到了一个名为“updatePatch.exe”的文件，尽管同事并没有刻意发送过任何文件。哪种恶意软件最可能是这种行为 true？

- (A) 木马 (Trojan)
- (B) 勒索软件 (Ransomware)
- (C) 广告软件 (Adware)
- (D) 虫病毒 (Worm)

**解释 337. 正确答案：D. Worm。** 虫病毒是一种自我复制并传播到其他设备的恶意软件。网络流量激增以及在发送者不知情的情况下向各种用户分发文件是虫病毒的行为。它们会消耗带宽和系统资源，导致系统缓慢。

**选项 A 错误。** 木马装成合法软件，但不会像病毒那样自我复制或通过电子邮件发送自己。

**选项 B 错误。** 勒索软件加密受害者计算机上的文件并索要解密密钥。它不会像虫病毒那样复制和传播。

**选项 C 错误。** 广告软件主要向用户提供不想要的广告，并且不会自我复制。

**问题 338。** 一家软件开发公司维护着一个共享代码库。该公司希望确保只有开发人员可以对代码进行更改，但测试人员应该查看代码而不修改它。应该实施哪种方法？

- (A) 为所有员工分配只读权限
- (B) 为测试人员提供管理员权限
- (C) 实现基于角色的访问控制 (RBAC)
- (D) 对仓库使用数据加密

**解释 338. 正确答案：C. 实现基于角色的访问控制 (RBAC)。** RBAC 根据组织内的角色分配权限。可以给开发者分配允许修改代码的角色，而给测试人员分配仅允许读取代码的角色。

**选项 A 错误。** 为所有员工分配只读权限将阻止开发者对代码进行必要的更改。

**选项 B 错误。** 为测试人员提供管理员权限将赋予他们额外的权限，可能允许他们修改代码。

**选项 D 错误。** 虽然数据加密确保了数据的机密性，但它没有解决不同用户角色特定权限的需求。
