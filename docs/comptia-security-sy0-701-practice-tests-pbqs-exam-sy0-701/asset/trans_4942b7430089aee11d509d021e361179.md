问题 238。在 IaaS（基础设施即服务）模型中，在标准的云责任矩阵中，以下哪些任务通常是云客户的责任？

- (A) 数据中心的物理安全
- (B) 宿主机操作系统的补丁
- (C) 网络基础设施的维护
- (D) 客户操作系统的补丁

解释 238. 正确答案：D. 客户操作系统的补丁。在 IaaS 模型中，客户通常负责管理自己的虚拟机，这包括对客户操作操作系统进行补丁。云提供商通常负责物理基础设施、网络和宿主机操作系统。

选项 A 错误。数据中心的物理安全是云提供商的责任。客户对云环境中的物理基础设施没有控制权。

选项 B 错误。宿主机操作系统的补丁是云提供商的责任。他们管理底层基础设施，包括宿主机系统。

选项 C 错误。网络基础设施的维护通常由云提供商处理，以确保其提供的资源的连接性和可用性。

问题 239。在云环境中，以下哪个矩阵定义了云提供商与客户之间针对特定云服务模型的共享责任？

- (A) 共享责任矩阵
- (B) 云资源分配表
- (C) 云安全态势矩阵
- (D) 云责任矩阵

解释 239. 正确答案：D. 云责任矩阵。云责任矩阵定义了云环境中云提供商与客户之间的共享责任，划定了提供商将处理哪些安全措施，以及哪些措施是客户的责任。

选项 A 错误。虽然“共享问责矩阵”（Shared Accountability Matrix）这个术语听起来相关，但在云计算中并没有这个命名的标准矩阵。共享责任是一个概念，但在云安全语境下使用的实际术语是“云责任矩阵”（Cloud Responsibility Matrix）。

选项 B 错误。“云资源分配表”（Cloud Resource Allocation Table）不是与划分云责任相关的标准术语。它听起来更关于关于资源（如计算或存储）如何分配的。

选项 C 错误。“云安全态势矩阵”（Cloud Security Posture Matrix）不是定义云环境中共享责任的认可术语。相反，它听起来更像是组织对云安全立场或定位的潜在术语。

问题 240。一家金融机构收集并存储其客户的个人身份信息 (PII)。该公司运营在对此类数据的存储、传输和处理有严格法规限制的管辖区内。以下哪种策略最适合公司确保符合这些法规规定？

- (A) 使用未经验证的开源加密算法
- (B) 仅将客户数据存储在物理本地服务器上
- (C) 实现数据分类和标记程序
- (D) 限制访问数据的管理员数量

解释 240. 正确答案：C. 实现数据分类和标记程序。通过实施分类和标记程序，组织可以识别敏感数据并应用适当的安全控制措施以满足法规规定。

选项 A 错误。使用未经验证的开源加密算法可能无法确保数据得到充分保护。

选项 B 错误。仅将客户数据存储在物理本地服务器上可能无法提供现代数据处理所需的灵活性。

选项 D 错误。限制访问数据的管理员数量是一项良好的安全实践，但可能不是整体数据分类合规的首要策略。

问题 241。在年度审查期间，某公司发现其一个关键系统发生了多次停机。他们希望确保系统的高可用性。在实现高可用性时首要考虑的问题是什么？

- (A) 确保没有单点故障
- (B) 定期对系统打补丁
- (C) 实现多因素身份验证
- (D) 在地理位置拥有备份

解释 241. 正确答案：A. 确保没有单点故障。在高可用 (HA) 架构中，消除单点故障可以确保当一个组件故障时，另一个组件可以接管以保持运行时间。

选项 B 错误。虽然对系统打补丁对于安全和稳定性很重要，但它不是高可用架构的首要考虑问题。

选项 C 错误。多因素身份验证对于安全访问至关重要，但无法解决可用性问题。

选项 D 错误。在地理位置拥有备份与灾难恢复相关，而不是高可用性。

问题 242。在最近的服务中断后，一家医院的 IT 团队正在审查其患者记录系统的可用性。他们希望即使在硬件故障的情况下，系统也能保持运行。以下哪些考虑因素与此最相关？

- (A) 实现数据库镜像
- (B) 定期更新杀病毒软件定义
- (C) 对静态数据使用强加密
- (D) 对系统进行渗透测试

解释 242. 正确答案：A. 实现数据库镜像。数据库镜像是增加数据库可用性的解决方案，确保在发生故障时，数据的镜像副本可用。

选项 B 错误。虽然更新杀病毒定义对于预防感染至关重要，但它与高可用性没有直接关系。

选项 C 错误。加密对于数据安全至关重要，但无法解决系统的可用性需求。

选项 D 错误。渗透测试会识别系统漏洞，但无法为可用性提供解决方案。

问题 243。某企业希望配置其防火墙，当发生故障时，防火墙应自动允许流量以确保业务连续性。应该实施哪种故障模式？

- (A) 故障安全 (Fail-safe)
- (B) 故障转移 (Fail-over)
- (C) 故障关闭 (Fail-closed)
- (D) 故障开启 (Fail-open)

解释 243. 正确答案：D. 故障开启。在故障开启模式下，当系统或设备故障时，它会默认为“开启”状态，允许流量通过。这种模式优先考虑可用性而非严格安全性。

选项 A 错误。“故障安全”（Fail-safe）术语通常是指系统切换到安全状态的能力，但在防火墙语境下，“故障开启”或“故障关闭”是首选术语。

选项 B 错误。“故障转移”（Fail-over）是指在故障时切换到备用系统或组件。
