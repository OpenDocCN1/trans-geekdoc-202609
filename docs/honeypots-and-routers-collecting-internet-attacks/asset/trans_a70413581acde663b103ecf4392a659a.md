
# 路由器

在结束对基本网络概念的回顾之前，有必要在互联网模型和 TCP/IP 协议族的视角下再次审视路由器。路由器是互联网的重要组成部分，互联网是一种基于互联网模型的广域网，因为它们是每个局域网连接到完整广域网的节点；也就是说，某个私有网络中的终端用户设备通过路由器与互联网的其余部分进行通信。这使我们得出了如[图 1.10](#06_Chapter01.xhtml#fig1_10)所述的互联网图景：一个由多个大小不一的互联网络组成的网络，每个网络通过其路由器接入互联网。因此，路由器是本地网络与互联网其余部分之间所有流量的入口/出口。这一事实给路由器带来了大量工作负载，特别是出口/入口路由器，通常称为*出口/入口路由器*，并使其在通信中的重要性成倍增加。起初，路由器的基本任务是识别通信路由并为不同的协议和技术提供互操作性。但凭借在拓扑结构中的这种战略位置，如今的路由器在流量分析和过滤方面也发挥着重要作用。

关于[图 1.10](#06_Chapter01.xhtml#fig1_10)中描述的互联网架构，另一个重要事实是：在核心层，我们有一组设备网格，主要用于提供互联互通。这个核心实际上是由不同级别和规模的多个互联网服务提供商提供的服务基础设施。

## 1.5 常见网络协议

在[第 2 章](#07_Chapter02.xhtml)和[第 3 章](#08_Chapter03.xhtml)中，我们将重点关注信息安全以及用于攻破信息系统安全的方法。IP 协议族是一组广泛应用于计算机网络的公共协议，也是黑客攻击的常见目标。在结束对计算机网络的回顾之前，让读者简要了解一下其中一些重要协议的技术细节将非常有用。

### 1.5.1 超文本传输协议

`HTTP` 是一种应用层协议，用于在系统间共享超媒体消息。它是一种通用协议，不维护通信状态。它是万维网服务的核心。该协议随着时间的推移不断改进，以提供更好的功能并支持技术进步；现有三个可用版本：`HTTP/0.9`、`HTTP/1.0` 和 `HTTP/1.1`，其中 `HTTP/1.1` 为最新版本。

`HTTP` 遵循请求/响应模型，客户端通过向服务器发送请求消息来发起通信。该请求消息中包含的典型项目有：请求方法、统一资源标识符、协议版本、请求修饰符、客户端信息以及可能的主体内容。服务器用响应消息回应该请求，响应消息通常包含状态行、消息的协议版本、成功或错误代码、服务器信息、实体元信息以及可能的实体主体内容。

`HTTP` 通信通过 `TCP/IP` 连接执行，服务器默认在 `TCP` 端口 `80` 监听。然而，使用 `TCP` 并非强制性的，任何提供可靠交付的传输协议均可使用。在 `HTTP/1.0` 中，默认情况下，每次请求/响应交换都使用一个新的传输连接；而在 `HTTP/1.1` 中，可以将一个连接用于一次或多次请求/响应交换，通常称为*持久行为*。

`HTTP` 只有两种消息类型：客户端发送的请求消息和服务器发送的响应消息。这两种消息的通用格式分别显示在[图 1.11](#06_Chapter01.xhtml#fig1_11)和[图 1.12](#06_Chapter01.xhtml#fig1_12)中。

### 1.5.2 传输控制协议

`TCP` 是 IP 协议族中的一项重要核心协议，设计用于传输层，旨在为分组交换计算机通信网络提供可靠的主机到主机服务。它是一种面向连接的端到端协议，支持多网络应用。`TCP` 在运行于连接到互联计算机通信网络的主机计算机上的进程对之间，提供可靠的、有序的、经过错误检查的字节流进程间交付。`TCP` 的其他特性包括流量控制和拥塞控制，但不提供安全性或带宽保证。

`TCP` 是多种算法和过程的组合，可供讨论；然而，我们将在以下回顾中仅限于段结构和连接建立。

#### TCP 段结构

与 `HTTP` 拥有两种独立的消息类型不同，`TCP` 段的用途是通过在段首部中选择标志位来描述的。在 RFC 793 中定义了六个基本标志位：

*   `URG`：紧急指针字段有效
*   `ACK`：确认字段有效
*   `PSH`：推送功能
*   `RST`：重置连接
*   `SYN`：同步序列号
*   `FIN`：发送方无更多数据

![Figure 1.13 TCP segment format.](images/pg22_1.jpg)

**图 1.13** TCP 段格式。

该段（[图 1.13](#06_Chapter01.xhtml#fig1_13)）中的大多数字段都是自描述性且通用的。然而，序列号字段的实现依赖于主机，可能被入侵者利用。每个 `TCP` 段都由发起该段的主机分配一个序列号，以便接收主机能正确排序该主机发送的不同段并移除重复段。初始序列号的选择，即主机生成的第一个段中发送的序列号，通常取决于该主机上 `TCP` 的操作系统实现。这种现象有助于入侵者通过观察初始序列号来推断操作系统类型。

#### TCP 连接建立

`TCP` 使用三次握手过程在开始传输数据段之前建立连接（参见[图 3.4](#08_Chapter03.xhtml#fig3_4)）。该过程由客户端主机发起，发送一个仅设置了 `SYN` 位的段，以表明建立连接的意图。如果服务器感兴趣，将回复一个同时设置了 `SYN` 和 `ACK` 位的段，以确认收到该段并表明建立连接的意图。最后，客户端将发送一个设置了 `ACK` 位的段以确认收到。

### 1.5.3 动态主机配置协议

`DHCP`

使用 `DHCP`，可以通过三种可能的方式为主机分配 IP 地址。首先，可以通过*自动分配*为主机分配一个永久 IP 地址。其次，可以为客户端分配一个为期有限的 IP 地址，称为*动态分配*。最后，在*手动分配*中，分配给客户端的 IP 地址由网络管理员选择，`DHCP` 的工作只是传达这一分配。
