

## 1.5.3 动态主机配置协议

1.  主机通常由用户配置为使用静态 IP 地址，或通过 DHCP 获取自动分配，后者是最常用的选项。客户端通过发送 DHCP 发现消息来启动该过程。由于客户端不知道 DHCP 服务器的 IP 地址，因此该发现消息中的 IP 地址为广播地址，即 `255.255.255.255`，正是由于这一事实，此步骤被称为*发现*。DHCP 服务器配置为监听 UDP 端口 `67`，而客户端需要选择 UDP 端口 `68` 作为源端口。DHCP 服务器可能不在与请求主机相同的子网中。在这种情况下，会在每个子网中放置 DHCP 中继代理。分配 IP 地址的请求在技术上称为 *IP 租约请求*。该请求消息中的另一个重要字段是客户端的 MAC 地址。

    ![Figure 1.15 DHCP IP address allocation process.](images/pg24_1.jpg)

    **图 1.15** DHCP IP 地址分配过程。

2.  一旦服务器收到租约请求，它会向客户端发送 DHCP 提供消息。根据服务器针对客户端 MAC 地址的配置，此请求中提供的 IP 地址遵循三种方法之一进行选择。DHCP 提供消息中的重要项目包括提供的 IP 地址、子网掩码、租约期限以及服务器自身的 IP 地址。此提供消息的目标 IP 地址再次为 `255.255.255.255`，因为客户端迄今仍无 IP 地址；目标端口为前述的 UDP `68`。如果网络中有多个 DHCP 服务器，可能会有多个服务器发出提供。^([⁶](#fn6)) 此处需考虑的另一个重要问题是：如果有多个客户端正在等待 IP 租约提供，当所有提供消息均为广播时，它们如何识别该提供是给谁的。

3.  客户端将接受其中一个提供，并生成一条 DHCP 请求消息，以获取相应服务器提供的 IP 地址。该消息遵循与 DHCP 发现相同的传递配置，即进行广播，因为所有 DHCP 服务器都应被正式告知客户端接受了哪个服务器的提供，以便其他服务器撤回其提供。

4.  最后，DHCP 服务器通过发送 DHCP ACK 消息和其他必要配置来确认租约。

## 1.5.5 地址解析协议

地址解析协议 (ARP)

由于 ARP 提供了网络层和数据链路层之间的联系，它本身工作在网络层之下，因此不可路由。这意味着 ARP 数据包被直接封装在数据链路层帧中，只能在局域网内传输，而不能跨越路由器。

ARP 只有一种数据包格式，通过在操作字段中描述合适的值来指定不同的操作；例如，`1` 代表 ARP 请求，`2` 代表 ARP 应答。另外两个重要字段是硬件类型和协议类型。硬件类型指定硬件标准，ARP 为不同标准提供了代码列表，例如 `0001` 代表以太网。同样，协议类型指定网络层协议的代码，IPv4 的情况为 `0×0800`（[图 1.17](#06_Chapter01.xhtml#fig1_17)）。

*地址解析过程*。网络层数据报被交给数据链路层进行传输，帧头中需要填写相应的硬件地址以便投递。ARP 维护一个缓存或 ARP 表，用于存储已知的网络层地址到物理层地址的映射。如果缓存中没有网络层地址对应的物理层地址，则会在局域网中广播一个 ARP 请求数据包（MAC 地址全为 1），其中包含缺少物理层地址的网络层地址。因为是广播，局域网上的每台主机都会收到该帧，如果被请求的主机存在，它将通过应答消息单独向请求主机回复其物理地址（[图 1.18](#06_Chapter01.xhtml#fig1_18)）。请求主机将此条目存储在 ARP 缓存中以备将来使用。此外，ARP 请求消息有助于网络中的其他主机更新其 ARP 表中关于请求源的条目。
