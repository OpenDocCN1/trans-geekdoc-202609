
## 19.6 Self-supervised learning

In the previous sections, the focus was on transformers and the discussion evolved around the natural language processing (NLP) tasks. We have already pointed out that during pretraining, also known as the pretext task, via the use of unlabeled data, a transformer network can produce an updated efficient contextualized representation of its input. Subsequently, the pretrained transformer can be used in a supervised learning framework for a wide range of specialized tasks, known as downstream tasks.

Learning during pretraining was achieved either via next word prediction or via masking some of the input word embeddings. In the latter case, the involved parameters were optimized for the network to predict the masked words. This type of training, via unlabeled data, is also known as self-supervised learning, for reasons that we will soon discuss.

The question that is now raised is whether such techniques can be used with other modalities other than text, e.g., images, speech, audio, video, etc. In NLP tasks, the involved word embeddings/tokens are sequential and of a discrete nature. This is not the case, for example, in images in computer vision tasks or in speech signals, as well as for many other types of signal modalities. Pixels in images take values in continuous intervals and they are not sequential. Audio signals are of a sequential nature but their amplitude varies within continuous intervals.

Due to the different nature of the involved data modalities, different techniques have been developed for self-supervised learning over the years, which may or may not use transformers. Before we entail in reviewing some basic directions for this type of learning tasks, let us first define what we mean by self-supervision. So far, we used the term in a rather loose way.

### 19.6.1 Unsupervised versus self-supervised learning

Pretraining during the pretext task is preformed via the use of unlabeled data. So far in the book, the term unsupervised learning has been used for such tasks, see, e.g., Section [12.6](#Chp012_583-634_B9780443292385000184.xhtml). In which aspects is self-supervised learning different from unsupervised tasks to "deserve" a different name? As we have already discussed in Chapter [1](#Chp001_1-17_B978044329238500007X.xhtml), typical unsupervised tasks are clustering, manifold learning, probability distribution learning. The goal that is shared by all these tasks is to learn the structure, e.g., hidden regularities and statistical dependencies that underlie the associated input data. Learning of unsupervised tasks is different from supervised learning. In the latter, for `each input example` there exists a corresponding `target` value and the training objective is to optimize the network parameters such that the predicted outputs are close, in some sense, to the corresponding targets.

In `self-supervised learning` (SSL), no labeled data are available but, instead, target values are `constructed` from the available unlabeled examples. Different techniques follow different paths for obtaining targets/labels. For example, recall that in `BERT` the targets are the true word one-hot vector encodings, which correspond to the masked tokens in the input sequence. Thus, one could consider self-supervised learning as a category of learning methods that lies between supervised and unsupervised ones.

The power on training via a vast amount of unlabeled data, compared to supervised learning, springs from the fact that SSL extracts `generic representations` of the available data, which can subsequently be useful `across many tasks`. This is in contrast to supervised learning that tries to focus on the needs of a specific task. For example, in [138], a study is carried out in an effort to relate SSL with the way children acquire basic visual categories, through generic learning mechanisms without substantive inductive bias. Although, at the time the current edition of this book is being compiled, it is still rather early to fully grasp the how's and why's behind SSL, findings point out that the representations of the input data that are learned via SSL tend to be more robust to adversarial examples, label corruption and input perturbations, e.g., [75], [62]. Finally, note that a major drawback of supervised learning is the requirement of annotated data, which is a particularly high cost process, especially when massive data sets are used.

Self-supervised learning is not new in machine learning. Our aim here is not to review all the techniques and paths that have been proposed over the years but to focus on some basic directions of SSL, which seem to be more popular at the time of the current edition. Recent related reviews on SSL methods are provided in, e.g., [13], [49], [96], [117].

### 19.6.2 The pretext task

The first phase in self-supervised learning is the pretext task, whose aim is the training of an `encoder` via unlabeled examples (pretraining) in order to generate an informative encoding/representation of the input data. The goal of this section is to describe a generic scheme that covers most of the methods that have been suggested. Of course, as it is always the case, there may be specific methods that deviate from this general rationale, see, for example, [Remarks 19.11](#Chp019_997-1102_B9780443292385000251.xhtml#enun0085).

A major part in any self-supervised technique is to `create` the output targets/labels from the unlabeled samples. Often, we refer to these constructed targets as `pseudo labels`. In a more formal way, let us assume that the input comprises a set of `N` unlabeled vectors, $\mathcal{X} = \{\mathbf{x}_1, \mathbf{x}_2, \dots, \mathbf{x}_N\}$. For example, in an NLP task these may be the `N` token vectors corresponding to the input sequence of words. In a computer vision problem, they may correspond to the `N` vectorized successive patches that comprise an image. In a speech processing task, these may be the vectors of the time samples in a sequence of `N` successive windows, which result after the segmentation of the corresponding speech signal. When the input data are treated individually as single entities, e.g., each example is a single vector to feed the input of a multilayer perceptron or an image array to feed the input of a convolutional network, then $N = 1$ and the input set, $\mathcal{X}$, is a singleton. Thus, the stage of our discussion covers the more general modeling, where the encoder can be, e.g., a transformer ($N > 1$) or a convolutional neural network or a fully connected feed-forward network.
