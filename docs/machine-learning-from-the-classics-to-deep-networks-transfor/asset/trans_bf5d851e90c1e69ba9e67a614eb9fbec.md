
[算法 18.2](#Chp018_885-995_B978044329238500024X.xhtml#enun0025) 中讨论的方案属于*批量*类型，即参数/权重每轮更新一次，也就是在所有 *N* 个训练样本都已呈现给算法之后进行更新。另一种途径是*逐模式*版本；对于这种情况，每当一个新的训练样本出现在输入端时，权重就会更新一次。有时，此类方案被称为*在线*。然而，我们将避免使用该术语，因为它通常指的是考虑流式数据且观测值持续流入的情况，而不是拥有一个固定大小的训练集，其中数据点会被反复考虑、一轮接一轮。在线算法已在第 [5](#Chp005_177-248_B9780443292385000111.xhtml) 章和第 [8](#Chp008_343-416_B9780443292385000147.xhtml) 章中进行过探讨。另一个近期更常用于描述此类算法的名称是*随机*优化。这让人联想到第 [5](#Chp005_177-248_B9780443292385000111.xhtml) 章介绍的随机逼近法，其中为了最小化期望损失，单个观测值被顺序用于更新未知参数/权重的估计值。当然，请记住，在真正的随机梯度下降中，*不*存在数据复用（即一轮接一轮），且假设数据以流式方式到达，收敛是*渐近*实现的。

当数据中存在冗余或训练样本非常相似时，逐模式版本能更好地利用训练集。批量模式中采用的平均操作会浪费资源，因为对相似模式对梯度的贡献进行平均并不会增加太多信息。相反，在逐模式实现中，所有样本都能得到同等利用，因为每个训练样本都会触发一次更新。

逐模式导致收敛轨迹不够平滑；然而，这种随机性可能有助于算法跳出局部极小值。

#### 小批量方案

一种中间方式，即每 *K* < *N* 个样本执行一次参数更新，也已被考虑在内，这被称为*小批量*或*随机小批量*。然而，此类方案通常简称为随机。小批量大小 *K* 的选择受多种因素影响，且取决于应用、具体数据以及可用的计算能力。

例如，如果批量大小非常小，多核架构将得不到充分利用。此外，当使用 GPU 时，采用 2 的幂次方作为小批量大小可以提供更好的运行时间。对于这种情况，一些典型值范围为 16 到 256，具体取决于训练集的大小。另一方面，使用较小的小批量大小可能具有正则化效果，这是由于在梯度计算中隐式添加了噪声。然而，在这种情况下，出于稳定性原因，必须对步长使用较小的值，这可能会增加总体训练时间。

批量和小批量方案对梯度计算具有平均效应。文献 [186] 建议向训练数据添加一个小的白噪声序列，这可能有助于算法跳出不良的局部极小值。

为了在逐模式/小批量方案中进一步利用随机性，建议在新一轮开始前，将呈现给算法的数据顺序随机化（参见例如 [69]）。这在批量模式中没有意义，因为更新是在所有数据都被考虑之后才进行的。这种数据的随机打乱“打破”了连续样本可能存在的潜在相关性，使得连续的梯度计算相互独立。这种相关性可能是由于生成数据时遵循的特定实验协议造成的。虽然建议每轮都打乱数据，但当使用大型数据集时（例如数十亿量级），这可能不切实际。在这种情况下，即使仅在开始时进行一次数据打乱也是有益的。

如今，在大数据训练集的深度学习背景下，小批量方案似乎是大多数应用的首选。

所有梯度下降方案及其随机变体中的一个主要问题是选择步长或*学习率* *μ*。正如我们从第 [5](#Chp005_177-248_B9780443292385000111.xhtml) 章所知，如果其值较小，学习曲线会很平滑，但收敛可能很慢。相反，如果其值相对较大，学习曲线往往会振荡，但收敛可能更快，前提是该值不会大到导致算法发散。在实践中，时变步长更为合适，且符合随机梯度的基本原理。可以采用各种策略，但这些策略更多是工程上的“技巧”，而非理论分析的结果。建议用户首先参考以往研究者/实践者在类似情况下的做法，并以此经验为起点。

一种可能的策略是开始训练时采用线性递减的步长，然后在若干次迭代后切换为固定步长。例如，可以采用如下规则：

```
μ[i] = (1 − a[i])μ[0] + a[i]μ[I],
```

其中 *a*[*i*] = *i*/*I*，针对某个固定的迭代次数 *I*。在第 *I* 次迭代之后，步长固定。现在的问题是设置参数 *μ*[0]、*μ*[*I*] 和 *I*。在实践中，必须先监控若干次迭代的学习曲线，并相应地调整参数值，以在初始迭代向收敛移动的快慢之间以及防止不稳定性之间做出权衡。
