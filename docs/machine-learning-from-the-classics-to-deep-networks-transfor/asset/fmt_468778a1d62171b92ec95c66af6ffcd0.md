
## Figure 19.24 A typical variant of the U-Net used in diffusion networks

U-Net accepts as input the noisy images, `x_t` (e.g., of dimensions 128 × 128), and outputs predictions, `ϵ_θ(x_t, t)`, of the same dimensions (e.g., 128 × 128). The U-Net consists of a contracting path of residual convolutional layers followed by an expansive one (U-shape). As the size of the feature maps keeps decreasing (increasing) the number of channels keeps increasing (decreasing). Feature maps from the contractive path are copied and concatenated with feature maps in the expansive path (dotted lines). The bottom line indicates the time positional vector embedding, which is passed to the convolutional layers after appropriate projections to match the dimensions of the corresponding computed feature maps.

Each block in the contractive path consists of two successive residual convolutional layers (e.g., 3 × 3 convolutions) followed by an ReLU activation function and a downsampling operation. The latter is performed via a pooling operation (2 × 2 max pooling). At each downsampling step, the size of each dimension of the computed feature maps is halved and we double the number of the feature channels. Thus, for the case of the figure, assume a 128 × 128 input image, and that block #1 computes 16 feature maps (channels) of size 128 × 128. After downsampling, these are reduced in size to 64 × 64 and are provided as input to block #2. Block #2 computes 32 feature maps of size 64 × 64, which after downsampling are reduced to size 32 × 32 and become the input to block #3. Following this rationale, block #3 computes 64 maps of size 32 × 32, block #4 128 maps of size 16 × 16, and the one in the middle, block #5, outputs 256 feature maps of size 8 × 8.

In the expansive path, a reverse operation takes place. The number of channels decreases and the size of the feature maps increases in symmetry to the contractive path. To achieve this, each one of the blocks #6 to #9 comprises an upsampling operation by 2, followed by a 2 × 2 convolution operation that halves the number of channels. The feature maps computed in the contractive path are copied and concatenated with the corresponding feature maps in the expansive path followed by two cascaded residual convolutional layers (e.g., 3 × 3 convolutions). Thus, block #6 computes 128 channels of size 16 × 16, and so on, until the last block that computes 16 channels of 128 × 128. The output 128 × 128 image is formed via an extra 1 × 1 convolution (Section [18.12.2](#Chp018_885-995_B978044329238500024X.xhtml)) that computes a weighted average over the 16 128 × 128 feature maps.

When the U-Net is used in the context of diffusion models, some extra information is required that is related to time. The parameters, `θ`, describing the U-Net are shared by all time steps in the reverse process. However, as we have already discussed before in various places, the outputs of the network (e.g., `ϵ_θ(x_t, t)`) depend explicitly on time, `t`. In diffusion models, time carries important information that is related to the amount of noise degradation of the input. Thus, time information should be provided explicitly to the network. The method of positional embedding, which has been discussed in the context of transformers (Section [19.3.4](#Chp019_997-1102_B9780443292385000251.xhtml#s0090)), is adopted to implement this goal. To this end, time is encoded into a vector of a user-defined dimension, and this information is passed to each one of the U-Net stages. Furthermore, for each block, an extra projection via a linear network is needed to match the time vector embedding dimensions to those of the corresponding U-Net layers. Time information is exploited in an additive way to the corresponding feature maps.

Furthermore, in most diffusion model implementations, an extra attention layer (Section [19.3.5](#Chp019_997-1102_B9780443292385000251.xhtml#s0095)) is employed between two successive residual blocks. For example, in [85], this layer is added after the 16 × 16 feature map resolution of the corresponding U-Net implementation.^([^(144)](#fn144))
