
且 ∥**θ**∥[1, **w**[*n*]] 为加权 ℓ[1] 范数。从第 [6](#Chp006_249-291_B9780443292385000123.xhtml) 章可知，且很容易看出：

*R*[*n*] = *β**R*[*n* − 1] + **x**[*n*]**x**[*n*]^(*T*), **r**[*n*] = *β***r**[*n* − 1] + *y*[*n*]**x**[*n*]。

![Equation](images/B9780443292385000160/si260.png)

对于一般结构的矩阵，上述两种更新的复杂度均达 𝒪(*l*²) 次乘加运算。一种替代方案是更新 *R*[*n*] 和 **r**[*n*]，然后在每个时刻 *n* 利用任意标准算法求解一个凸优化任务。然而，由于其过高的计算成本，这不适用于实时应用。文献 [3] 开发了一种坐标下降算法的时递归版本。正如我们在第 [10.2.2](#Chp010_463-518_B9780443292385000160.xhtml#s0040) 节所见，坐标下降算法在每次迭代步骤中更新一个分量。在文献 [3] 中，迭代步骤与时间更新相关联，这始终是オンライン算法的情况。每当接收到一个新的训练对 (*y*[*n*], **x**[*n*])，未知向量的单个分量就会被更新。因此，在每个时刻，必须求解一个标量优化任务，其解以闭式给出，从而导致一个简单的软阈值操作。坐标技术的缺点之一是每个系数每 *l* 个时刻更新一次，对于较大的 *l* 值，这会减慢收敛速度。文献 [3] 中也讨论了应对这一缺点的基本方案变体，称为在线循环坐标下降时加权 LASSO (OCCD-TWL)。该方案的复杂度为 𝒪(*l*²) 阶。如果输入序列为时间序列，则可节省计算量，并可利用 *R*[*n*] 和 RLS 的快速更新方案。然而，如果并行使用 RLS 类算法，整体方案的收敛可能会减慢，因为 RLS 类算法必须先收敛，才能为权重提供可靠的估计，如前所述。

### 10.4.3 自适应 CoSaMP 算法

文献 [90] 提出了一种 CoSaMP 算法的在线版本，其步骤总结在[算法 10.2](#Chp010_463-518_B9780443292385000160.xhtml#enun0030)中。迭代步骤 *i* 现在与时间更新 *n* 重合，且通用 CSMP 方案步骤 3c 中的 LS 求解器被 LMS 求解器取代。

让我们首先关注 CSMP 方案步骤 3a 中的量 *X*^(*T*)**e**^((*i* − 1))，它用于计算第 *i* 次迭代的支持集。在在线设置中，在（迭代）时刻 *n*，该量现在被“重述”为

```

```
