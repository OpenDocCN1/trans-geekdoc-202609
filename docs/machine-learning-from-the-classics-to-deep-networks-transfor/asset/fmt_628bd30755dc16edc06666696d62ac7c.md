
The respective geometry is shown in [Fig. 14.5](#Chp014_717-754_B9780443292385000202.xhtml#f0030)B. The goal is to draw points in the interval `[0, c*q*(x)]` and then keep only those that lie in the region under the surface `u = ϕ(x)`. The following algorithm does the job.

## Algorithm 14.2: Rejection Sampling

*   **For** `i = 1, 2, …, N`, **Do**
    1.  Draw `x[i] ∼ q(x)`
    2.  Draw `u[i] ∼ 𝒰(0, c*q(x[i]))`
    3.  Retain the sample if
        *   `u[i] ≤ ϕ(x[i])`
*   **End For**

The probability of accepting a point, `x`, is given by

```
Prob{ u ≤ ϕ(x) } = (1 / (c*q(x))) * ϕ(x)
```

and the total probability, over all the possible values of `x`, for accepting samples is equal to

```
Prob{ acceptance } = (1/c) ∫ (ϕ(x)/q(x)) q(x) dx = (1/c) ∫ ϕ(x) dx
```

Hence, if `c` has a large value, only a small percentage of points is finally retained. In order to have a practical algorithm, `c*q(x)` must be chosen in order to be a good fit of `ϕ(x)`. [Fig. 14.6](#Chp014_717-754_B9780443292385000202.xhtml#f0035)A is an example of a bad choice, while [Fig. 14.6](#Chp014_717-754_B9780443292385000202.xhtml#f0035)B corresponds to a good example. This is a reason that rejection sampling *does not scale* well with *dimensionality*. In high dimensions, guaranteeing that `c*q(x) ≥ ϕ(x)` may oblige us to select a `c` with an excessively large value (Problem [14.5](#Chp014_717-754_B9780443292385000202.xhtml#o0030)).
