In [222], it is shown that deep neural networks easily fit *random labels*. In other words, the effective capacity of a neural network is large enough for a brute-force *memorization* of the entire data set. Furthermore, it is pointed out that in contrast with classical convex empirical risk minimization, where explicit regularization is necessary to rule out trivial solutions, in the world of deep neural networks regularization seems to help improve the final test error of a model, yet its absence does not necessarily lead to poor generalization performance. Note that at the over-parameterized regime, there are more than one possible solutions.

An explanation for the double descent curve phenomenon has been attempted via the implicit regularization imposed by the gradient descent algorithm. The simplest example is that of the least-squares solution of an underdetermined model. We know (e.g., Sections [6.4](#Chp006_249-291_B9780443292385000123.xhtml) and [9.5](#Chp009_417-462_B9780443292385000159.xhtml)) that for such a model, with more parameters than equations, the use of the pseudoinverse of the input matrix leads to the minimum norm solution. It can be shown, see, e.g., [4], that for a least-squares task and starting the iterations from zero, the gradient descent algorithm converges to the minimum ℓ₂ norm solution. It turns out that similar arguments hold true for other cost functions and models, when the gradient descent algorithm is used (e.g., [63]) or if its stochastic gradient version is employed (see, e.g., [159]). As it is stated in [191], there are many global minima of the training objective, most of which will not generalize well, but the optimization algorithm (e.g., gradient descent) biases the solution toward a particular minimum that does generalize well. The effect of the batch size on the generalization ability is studied experimentally in [101], where it is pointed out that small batch sizes have a beneficial effect. Some of the arguments posed in this paper are challenged in [39].

In [11], the generalization power of over-parameterized networks is discussed in the context of function smoothness and small norm solutions. Recall that all possible learned predictors in the over-parameterized regime learn the training data (almost) perfectly and correspond to (theoretically) zero training error. In other words, the learned predictors are (near to) perfect interpolators. In [11] the following question is posed: why should some of the predictors, and in particular those from more complex models, have lower test error than others? The answer provided in the paper is that (for the problems studied in the paper) the required inductive bias that seems appropriate is the *regularity* or *smoothness* of a function as measured by a certain function space norm. This is in line with Occam's razor rule (Section [3.9.2](#Chp003_65-117_B9780443292385000093.xhtml)). Choosing the smoothest function that perfectly fits observed data could be seen as the simplest explanation compatible with the observations. Complex models that comprise large numbers of parameters (larger function classes) contain more candidate predictors compatible with the data and, hence, we are able to find interpolating functions that have smaller norm and are thus “simpler.” The issue of function interpolation smoothness comes back in [24]. It is shown that finding a smooth function to fit *l*-dimensional data requires at least *lN* parameters. In other words, over-parameterization by a factor of *l* is necessary for smooth interpolation, suggesting that perhaps the large size of the models used in deep learning is a necessity.

In [12], it is pointed out that key aspects of the double descent curve can, also, be observed with the least-squares/least norm predictor (via the pseudoinverse of the data matrix, Section [6.2](#Chp006_249-291_B9780443292385000123.xhtml)) in two simple random features models. The minimum ℓ₂ norm in high-dimensional least-squares regression is treated in [65]. It is shown that the double descent behavior that has been observed in large scale neural networks is also recovered for these simpler models, which indicates the potential benefits of over-parameterization. The double descent curve phenomenon involving random features in the context of ridge regression is treated in [133].

As said in the beginning, this is a new field of research, and a number of questions and issues are still open and different points of view come to contribute to the discussion (see, e.g., [99], [140]). A brief history of the double descent curve phenomenon is provided in [119].

## 18.12 Convolutional neural networks

In our discussion so far, we have assumed that neural networks are fed to their input layer with *feature vectors*. This is in line with any other classifier/predictor that has been discussed in previous chapters. Feature vectors are generated from the raw data in an effort to compact information that is relevant to the machine learning task at hand. To this end, for many years, a large pool of techniques has been developed to fit the nature of the data in different applications (see, e.g., [204]).

An alternative breakthrough came in the late 1980s, when the feature generation phase was integrated as part of the training of a neural network. The idea was to *learn* the features from the data *together* with the parameters of the neural network and *not* independently. Such networks were called *convolutional neural networks* (CNNs) and their success was first demonstrated in the OCR task in recognizing digits of numbers [111]. The name “convolutional” comes from the fact that the first layers in a neural network perform convolutions instead of inner products, which are the basic operations in the fully connected networks presented in Section [18.3.1](#Chp018_885-995_B978044329238500024X.xhtml#s0025).

### 18.12.1 The need for convolutions

Let us first make sure that we understand the reason of why we cannot, in practice, feed the input of a neural network directly with raw data, e.g., an image array or the samples of a digitized version of a speech segment, and why *preprocessing* is necessary in order to generate features. This is also true for any predictor/learner and not for neural networks only. We have commented on this issue in the introductory chapter, but there it was too early to grasp the true need. In many applications, working directly with raw data makes the task simply unmanageable.
