
正如我所说，为了让 PHP 能够处理文件上传，必须建立某些设置。我将首先讨论为什么或何时需要进行这些调整，然后再引导你完成步骤。

第一个问题是 PHP 本身。PHP 的配置文件 `php.ini` 中有几个设置决定了 PHP 如何处理上传，具体规定了可以上传多大的文件以及上传文件应临时存储在何处（[表 11.1](#ch11.html#ch11table01)）。一般来说，如果出现以下任何情况，你都需要编辑此文件：

*   `file_uploads` 被禁用。
*   PHP 没有可用的临时目录。
*   你将上传非常大的文件（大于 2MB）。

如果你无法访问 `php.ini` 文件——例如你正在使用托管网站——推测主机提供商已经配置 PHP 以允许文件上传。

第二个问题是临时目录的位置和权限。这是 PHP 将上传的文件存储到你的 PHP 脚本将其移动到最终目的地之前的地方。如果你在自己的 Windows 计算机上安装了 PHP，可能需要在此采取措施。Mac OS X 和 Unix 用户无需担心这一点，因为此类用途已存在一个临时目录（即一个名为 `/tmp` 的特殊目录）。

最后，必须创建目标文件夹并在其上建立适当的权限。这是每个人为每个处理文件上传的应用程序都必须采取的步骤。由于此步骤涉及重要的安全问题，请务必阅读并理解侧边栏“[安全文件夹权限](#ch11.html#ch11sb02)”。

考虑到所有这些，让我们逐步进行操作。

### 安全文件夹权限

通常在安全性和便利性之间存在权衡。在这个例子中，将 `uploads` 文件夹放在 Web 文档目录中会更方便（这种便利性体现在上传的图片可以多么容易地在 Web 浏览器中查看），但这样做安全性较低。

为了让 PHP 能够将文件放入 `uploads` 文件夹，它需要对该目录拥有写入权限。在大多数服务器上，PHP 作为与 Web 服务器本身相同的用户运行。在托管服务器上，这意味着托管的所有 *X* 个站点都作为同一用户运行。创建一个 PHP 可写的文件夹意味着创建一个*所有人*都可写的文件夹。字面上讲，服务器上拥有站点的任何人现在都可以移动、复制或写入文件到你的 `uploads` 文件夹（假设他们知道它的存在）。这甚至意味着恶意用户可以将麻烦的 PHP 脚本复制到你的 `uploads` 目录。然而，由于本例中的 `uploads` 目录不在 Web 目录内，因此无法在 Web 浏览器中运行此类 PHP 脚本。这种做法不太方便，但更安全。

如果你必须保持 `uploads` 文件夹公开可访问，并且你正在使用 Apache Web 服务器，你可以使用 `.htaccess` 文件限制对 `uploads` 文件夹的访问。基本上，你会声明该文件夹中只有图像文件可公开查看，这意味着即使 PHP 脚本被放置在那里，也无法执行。或者，因为你将在本章后面学习如何使用*代理脚本*，你可以拒绝对该文件夹的所有外部访问。有关如何使用 `.htaccess` 文件的信息，请参阅 [附录 A](#app01.html#app01)，可从 peachpit.com 免费下载。

有时即使是最保守的程序员也会在安全性上做出让步。重要的是你意识到潜在的担忧，并尽最大努力将危险降到最低。

#### 准备服务器

**1.** 运行 `phpinfo()` 函数以确认你的服务器设置 ![Image](graphics/circle-a.jpg)。

![Image](graphics/11_figure_05_a.jpg)

![Image](graphics/circle-a.jpg) `phpinfo()` 脚本返回关于你的 PHP 设置的所有信息，包括所有文件上传处理相关内容。

`phpinfo()` 函数会打印大量关于你的 PHP 设置的信息。在我看来，它是 PHP 中最重要的函数之一，如果不是最重要的话。搜索 [表 11.1](#ch11.html#ch11table01) 中列出的设置并确认它们的值。确保 `file_uploads` 的值为 `On`，并且 `upload_max_filesize`（默认 2MB）和 `post_max_size`（8MB）的限制不会对你造成限制。如果在 Windows 上运行 PHP，请查看 `upload_tmp_dir` 是否有值。如果没有，那可能是个问题（运行处理文件上传的 PHP 脚本后你就会确定）。对于非 Windows 用户，如果此值显示 `no value`，那完全没问题。

顺便说一句，使用一体化安装程序（如 Windows 的 XAMPP 或 Mac OS X 的 MAMP）的另一个优势是，安装程序也应该能正确配置这些设置。

**2.** 如有必要，在文本编辑器中打开 `php.ini`。

如果你在步骤 1 中看到任何需要更改的内容，或者当你实际使用 PHP 处理文件上传时发生了某些情况，你将需要编辑 `php.ini` 文件。要找到此文件，请参阅 `phpinfo()` 输出中的 *Configuration File (php.ini) path* 值。这准确地指示了该文件在你计算机上的位置（也可下载 [附录 A](#app01.html#app01) 了解更多）。

如果你不被允许编辑 `php.ini` 文件（例如，你正在使用托管服务器），那么推测任何必要的编辑已经完成以允许文件上传。如果没有，你需要向你的托管公司请求这些更改（他们可能同意，也可能不同意）。

**3.** 在 `php.ini` 文件中搜索要更改的配置并进行编辑 ![Image](graphics/circle-b.jpg)。

![Image](graphics/11_figure_06_b.jpg)

![Image](graphics/circle-b.jpg) `php.ini` 文件的文件上传小节。

例如，在文件上传部分，你将看到这三行：

```
file_uploads = On
;upload_tmp_dir =
upload_max_filesize = 2M
```

第一行规定是否允许上传。第二行说明上传的文件应临时存储在何处。在大多数操作系统中，包括 Mac OS X 和 Unix，此设置可以保持注释掉（前面带有分号）而不会有任何问题。

如果你正在运行 Windows 并需要创建临时目录，请将此值设为 `C:\tmp`，确保该行*不*以分号开头。

同样，在 Windows 7 上使用 XAMPP，我不需要创建临时目录，所以你可能也能不用创建。

最后，设置了最大上传文件大小（配置设置中的 *M* 是兆字节的简写）。

**4.** 保存 `php.ini` 文件并重启你的 Web 服务器。

如何重启 Web 服务器取决于所使用的操作系统和 Web 服务应用程序。请参阅 [附录 A](#app01.html#app01) 获取说明。

**5.** 通过重新运行 `phpinfo()` 脚本来确认更改。

在进一步操作之前，通过重复步骤 1 确认必要的更改已生效。

**6.** 如果你正在运行 Windows 并需要创建临时目录，请在 `C:\` 中添加一个 `tmp` 文件夹，并确保每个人都可以写入该目录 ![Image](graphics/circle-c.jpg)。

![Image](graphics/11_figure_07_c.jpg)

![Image](graphics/circle-c.jpg) Windows 用户需要确保 `C:\tmp`（或使用的任何目录）可被 PHP 写入。

PHP 通过你的 Web 服务器将上传的文件临时存储在 `upload_tmp_dir` 中。为了使其工作，Web 用户（如果你的 Web 服务器作为特定用户运行）必须有权限写入该文件夹。
