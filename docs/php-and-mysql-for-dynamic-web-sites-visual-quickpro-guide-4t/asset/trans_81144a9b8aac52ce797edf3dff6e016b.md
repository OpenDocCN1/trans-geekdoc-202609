### 错误类型与基础调试

使用 PHP 和 MySQL 开发 Web 应用程序时，您可能会在四种或更多技术中遇到潜在的 Bug。您可能会遇到 HTML 问题、PHP 问题、SQL 错误或 MySQL 错误。修复任何 Bug 的第一步是找到其源头。

HTML 问题通常破坏性最小，也最容易发现。当您的布局完全乱套时，通常就知道出问题了。下一节将讨论捕获和修复这些问题的一些步骤，以及通用的调试提示。

PHP 错误是您最常看到的错误，因为这种语言将成为您应用程序的核心。PHP 错误分为三大类：

*   语法错误
*   运行时错误
*   逻辑错误

语法错误最常见，也最容易修复。如果您只是遗漏了一个分号，就会看到它们。此类错误会阻止脚本执行，如果 PHP 配置中开启了 `display_errors`，PHP 将显示错误，包括 PHP 认为出错的行号 ![Image](graphics/circle-a.jpg)。如果 `display_errors` 关闭，您将看到一张空白页。（您将在本章后面了解更多关于 `display_errors` 的信息。）

![Image](graphics/08_figure_01_a.jpg)

![Image](graphics/circle-a.jpg) 解析错误——您到目前为止可能已经见过很多次了——是最常见的 PHP 错误类型，尤其是对于初学者程序员。

运行时错误包括那些不会阻止 PHP 脚本执行（像解析错误那样）但会阻止脚本完成其预期功能的错误。示例包括使用错误数量或类型的参数调用函数。发生这些错误时，PHP 通常会显示一条指示确切问题的消息 ![Image](graphics/circle-b.jpg)（同样假设 `display_errors` 已开启）。

![Image](graphics/08_figure_02_b.jpg)

#### 正确的心态

在深入探讨之前，先谈谈错误：它们发生在我们最优秀的人身上。即使是本书的作者，在 Web 开发工作中也会遇到足够多的错误（但请放心，本书中的代码应该没有 Bug）。认为您会达到一个永远不出错的技能水平是痴人说梦，但有技术可以将错误最小化，而知道如何快速捕获、处理和修复错误本身就是一项主要技能。所以尽量不要因为犯错而沮丧；相反，要沉浸在您正在成为一名更好的调试员的知识中！

***

最后一类错误——逻辑错误——实际上是最糟糕的，因为 PHP 不一定会向您报告它们。这些是彻头彻尾的 Bug：不明显且不会阻止脚本执行的问题。解决所有这些 PHP 错误的技巧将在几页后演示。

SQL 错误通常是语法问题，当您尝试在 MySQL 中运行查询时会被报告。例如，我犯这个错误太多次了 ![Image](graphics/circle-c.jpg)：

```
DELETE * FROM tablename
```

![Image](graphics/08_figure_03_c.jpg)

![Image](graphics/circle-c.jpg) MySQL 将报告 SQL 命令语法中发现的任何错误。

该语法完全错误，这是与 `SELECT` 语法（`SELECT * FROM` `tablename`）混淆了。正确的语法是：

```
DELETE FROM tablename
```

同样，当您有 SQL 错误时，MySQL 会发出警报，因此这些错误不难发现和修复。对于现代网站，棘手的是您并不总是拥有静态查询，而是经常由 PHP 动态生成查询。在这种情况下，如果存在 SQL 语法问题，问题很可能出在您的 PHP 代码中。
