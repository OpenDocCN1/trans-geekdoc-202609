## **第 60 .** 在 PHP 中，如果你想编写一个自定义错误处理器来处理用户生成的错误（例如使用 `trigger_error()`），你应该使用哪种错误类型？

-   A. E_USER_ERROR
-   B. E_WARNING
-   C. E_PARSE
-   D. E_COMPILE_ERROR

正确答案：A

解释：E_USER_ERROR 用于 PHP 中的用户生成错误，通常由 `trigger_error()` 触发。这允许开发者手动抛出错误，这些错误应该以处理系统生成的致命错误的方式进行处理。

# **第 61 .** PHP 中用哪个函数来检查变量是否为数组？

-   A. is_object()
-   B. is_array()
-   C. is_numeric()
-   D. is_string()

正确答案：B

解释：PHP 中的 `is_array()` 函数用于检查给定的变量是否为数组。如果变量是数组，则返回 true，否则返回 false。其他选项均无法实现此目的。

# **第 62 .** 哪个错误级别会报告 PHP 中的致命运行时错误（fatal runtime errors）？

-   A. E_WARNING
-   B. E_NOTICE
-   C. E_ERROR
-   D. E_PARSE

正确答案：C

解释：E_ERROR 报告导致脚本执行停止的致命运行时错误。其他级别如 E_WARNING 和 E_NOTICE 只发出警告或通知，而不会停止脚本。

# **第 63 .** PHP 中用哪个函数可以捕获异常（exception）？

-   A. catch()
-   B. try()
-   C. throw()
-   D. try-catch

正确答案：D

解释：在 PHP 中，`try-catch` 块用于处理异常。可能抛出异常的代码放在 `try` 块中，异常在 `catch` 块中被捕获。`catch()` 和 `try()` 等选项在 PHP 中并不作为独立函数存在。

# **第 64 .** 如果 PHP 中的异常没有被捕获，会发生什么？

-   A. PHP 将继续执行下一行。
-   B. 将抛出一个致命错误（fatal error），脚本将停止。
-   C. PHP 将自动重试该操作。
-   D. 异常将被静默忽略。

正确答案：B

解释：如果 PHP 中的异常未被捕获，会导致致命错误，脚本执行停止。当异常未被捕获时，PHP 不会静默忽略或重试操作。

# **第 65 .** PHP 中用哪个函数来生成用户定义的错误？

-   A. throw_error() 
-   B. trigger_error()
-   C. custom_error()
-   D. raise_exception()

正确答案：B

解释：`trigger_error()` 函数用于在 PHP 中生成用户定义的错误。它允许开发者在运行时抛出自定义错误。`throw_error()` 和 `raise_exception()` 等选项在 PHP 中并不。

# **第 67 .** PHP 中的种错误报告级别包含了 E_ERROR、E_WARNING 和 E_NOTICE？

-   A. E_ALL
-   B. E_WARNING
-   C. E_STRICT
-   D. E_USER_ERROR

正确答案：A

解释：E_ALL 包含了 PHP 中所有类型的错误、警告和通知。它通常在开发期间使用，以捕获广泛的问题。其他级别（如 E_WARNING 或 E_USER_ERROR）侧重于特定类型的错误。

# **第 68 .** PHP 错误处理中 `finally` 块的目的是什么？

-   A. 仅在捕获到异常时执行。
-   B. 如果抛出错误则跳过执行。
-   C. 无论是否捕获到异常都会执行代码。
-   D. 仅在没有抛出异常时运行。

正确答案：C

解释：PHP 中的 `finally` 块无论是否抛出或捕获异常总是执行的。它通常用于 `try` 和 `catch` 块之后的清理操作。
