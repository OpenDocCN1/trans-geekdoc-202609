

```solidity
pragma solidity 0.8.6;
contract LittleBear {
    event LogMsg(string message);
    string public storedMsg;
    constructor() {
        storedMsg = "Hello Little Bear (a.k.a. Maddie)!";
        emit LogMsg(storedMsg);
    }
    function updateMsg(string memory newMsg) public {
        storedMsg = newMsg;
        emit LogMsg(storedMsg);
    }
}
```

![Tip](images/tip.png) 为避免拼写错误，你可以直接从 [`www.seoyoungkim.com/nftfdcode.html`](http://www.seoyoungkim.com/nftfdcode.html) 复制并粘贴此代码片段。

![Warning](images/warning.png) Solidity 区分大小写，因此在编译时 `LogMsg` 和 `logmsg` 不会被视为相同标识符。

本节剩余部分将逐块解释代码。

第一行代码是 Solidity 版本编译指令，它指定了编译时允许使用的 Solidity 编译器版本。在本例中，版本编译指令仅允许在 0.8.6 版本下编译源代码：

`pragma solidity 0.8.6;`

接下来，你定义合约 `LittleBear` —— Solidity 是一门*花括号*语言，意味着它使用花括号来开启和关闭代码块：

`contract LittleBear {`

下一行声明了一个事件 `LogMsg`，它接受一个类型为 `string` 的单个参数：

`event LogMsg(string message);`

下一行声明了一个类型为 `string` 的公共状态变量 `storedMsg`。`storedMsg` 的最新内容将保留在合约存储中，即使合约及其函数在调用间隙处于休眠状态：

`string public storedMsg;`

下面的代码块声明了特殊的 `constructor()` 函数，该函数仅在合约初始化时执行一次。该函数的第一行初始化存储在 `storedMsg` 状态变量中的文本；第二行触发 `LogMsg` 事件，将 `storedMsg` 的内容传递给合约的事件日志进行记录：

```solidity
constructor() {
    storedMsg = "Hello Little Bear (a.k.a. Maddie)!";
    emit LogMsg(storedMsg);
}
```

下面的代码块声明了一个公共函数 `updateMsg()`，它接受一个类型为 `string` 的单个参数。该参数在此函数内以 `newMsg` 为名进行定义，并声明为内存变量，这意味着其内容在该函数执行完毕后不会被保留。如果不显式声明关键字 `memory`，函数参数默认为内存变量而非状态变量：

```solidity
function updateMsg(string memory newMsg) public {
    storedMsg = newMsg;
    emit LogMsg(storedMsg);
}
```

此 `updateMsg()` 函数的第一行用调用该函数时传入的文本替换存储在 `storedMsg` 状态变量中的文本。第二行触发 `LogMsg` 事件，以便将 `storedMsg` 的最新内容写入合约的事件日志。

最后，我们用一个右花括号结束合约代码块：

`}`

### 部署

在正式部署之前，请先在本地 Ganache 环境中练习部署此合约（我们在 [第 8 章](#c08.xhtml) 中讨论过）。

1.  **单击左侧导航窗格中的以太坊图标（编译器图标下方的那个图标）。**

    此步骤将打开“部署与运行交易”窗格，如 [图 9-7](#c09.xhtml#c09-fig-0007) 所示。

    ![图 9-6：在 Remix 上访问编译详细信息。](images/9781119843313-fg0906.png)

    [图 9-6：](#c09.xhtml#rc09-fig-0006) 在 Remix 上访问编译详细信息。

    ![图 9-7：Remix 上的部署与运行交易。](images/9781119843313-fg0907.png)

    [图 9-7：](#c09.xhtml#rc09-fig-0007) Remix 上的部署与运行交易。

2.  **从 Environment 下拉菜单中选择 Injected Web3 选项。**

    请务必同时

    1.  单击浏览器工具栏上的狐狸图标，登录 MetaMask 浏览器扩展。（见 [图 9-8](#c09.xhtml#c09-fig-0008)。）

    2.  连接到 Handsomely-Vessel 自定义网络。

    3.  选择你导入的本地 Ganache 账户之一。在本例中，我们选择 Ganache HV1。

    ![Remember](images/remember.png) 你还必须打开并运行 Ganache 桌面应用程序，且运行的是相应的工作区——在本例中为 Handsomely-Vessel 工作区。

3.  **从 Contract 下拉菜单中选择 LittleBear–LittleBear.sol 合约，然后单击 Deploy 按钮。（见** [图 9-8](#c09.xhtml#c09-fig-0008)**。）**
    ![图 9-8：将 LittleBear 合约部署到 Ganache 的 Handsomely-Vessel 工作区。](images/9781119843313-fg0908.png)

    [图 9-8：](#c09.xhtml#rc09-fig-0008) 将 LittleBear 合约部署到 Ganache 的 Handsomely-Vessel 工作区。

4.  **在出现的 MetaMask 通知弹窗中（见** [图 9-9](#c09.xhtml#c09-fig-0009)**），查看交易详情并单击 Confirm。**

    单击 Confirm 将提交一笔包含已编译字节码的交易（不指定目标地址），这将生成一个拥有自己地址的合约账户以供未来访问。如果你意识到尚未准备好部署合约，只需单击 Reject 即可。

    ![图 9-9：在 Handsomely-Vessel 工作区上确认合约账户创建。](images/9781119843313-fg0909.png)

    [图 9-9：](#c09.xhtml#rc09-fig-0009) 在 Handsomely-Vessel 工作区上确认合约账户创建。

    现在你可以在“Deployed Contracts”标题下查看并与该合约交互，如 [图 9-10](#c09.xhtml#c09-fig-0010) 所示：

    *   单击 `storedMsg` 按钮查看当前存储在此状态变量中的内容。
    *   单击 `updateMsg` 按钮调用更新 `storedMsg` 中存储文本的函数，如 [图 9-11](#c09.xhtml#c09-fig-0011) 所示。

    ![图 9-10：在 Remix 上查看已部署合约。](images/9781119843313-fg0910.png)

    [图 9-10：](#c09.xhtml#rc09-fig-0010) 在 Remix 上查看已部署合约。

    ![图 9-11：在 Remix 上与已部署合约交互。](images/9781119843313-fg0911.png)

    [图 9-11：](#c09.xhtml#rc09-fig-0011) 在 Remix 上与已部署合约交互。

    ![Remember](images/remember.png) 执行 `updateMsg` 函数是在 EVM 上的一笔交易，需要消耗 gas，而仅查看 `storedMsg` 变量的内容则不需要 gas。你会注意到每次尝试执行 `updateMsg` 函数时都会弹出 MetaMask 通知窗口，要求确认。
