**图 1.** 使用来自 [2] 的双向 A* 搜索算法可以发现的图模式。$e$ 和 $e'$ 表示双实体查询的实体，并在它们之间搜索路径。带有 ... 的节点是 $n \geq 0$ 个实体序列的占位符。

**算法 1** 来自 [2] 的双向 A* 搜索算法；更详细且使用了改编后的符号。

```text
procedure FINDPATH(e, e', α, β, γ, entityLimit)
    priorityQueue ← {e, e'}
    reachable_source ← {e}
    reachable_target ← {e'}
    visitedEntities ← ∅
    while priorityQueue ≠ ∅ and |visitedEntities| < entityLimit do
        entity ← dequeue(priorityQueue)
        visitedEntities ← visitedEntities ∪ {entity}
        if entity ∈ (reachable_source ∩ reachable_target) then
            return reconstructPath(e, e'), |visitedEntities|
        end if
        for adjacentEntity ∈ getAdjacentEntities(entity) do
            costs ← calculateCosts(e, e', adjacentEntity, α, β, γ)
            enqueue(priorityQueue, adjacentEntity, costs)
            if entity ∈ reachable_source then
                reachable_source ← reachable_source ∪ {adjacentEntity}
            else if entity ∈ reachable_target then
                reachable_target ← reachable_target ∪ {adjacentEntity}
            end if
        end for
    end while
    return ⊥, |visitedEntities|
end procedure
```

如果可以通过当前访问的实体在 $e$ 和 $e'$ 之间建立路径，算法终止，并返回找到的路径和访问实体的数量。否则，检索相邻实体，并根据通往这些实体的路径成本将它们入队。成本通过一个带有超参数 $\alpha$、$\beta$ 和 $\gamma$ 的成本函数进行计算。当优先队列变为空，或者在未找到路径的情况下达到实体限制（即搜索中止前允许访问的最大实体数量）时，算法以失败告终。

通过提供一种对优先队列中的实体进行排序的度量，成本函数（算法 1 中的 $calculateCosts$）引导图遍历，并最终决定算法的性能以及找到路径的特征。因此，接下来需要讨论的是，什么样的成本函数能够满足第 1 节中指出的用户在知识面板语境下期望有意义实体关系的需求。特别是在 Wikidata 中，两个实体之间可以找到许多路径，因此引出了哪条候选路径最有意义的问题。由于“有意义”是一个高度复杂且主观的概念，有不同的方法从不同方向来解决这个问题。例如，[3] 研究了如何从实体关系图中挖掘解释实体之间关系的具有信息量的子图。为此，所提出的方法根据候选节点的信息量对其进行排序，信息量是使用基于实体和关系共现统计的边权重计算的。虽然这种统计方法能产生在结构上对查询实体重要的子图，但它忽略了可用的语义信息（如实体标签）。因此，找到的子图可能容易出现概念漂移 [12]，当查询的语义焦点被偏离时就会发生这种情况。

相比之下，[2] 的作者认为，具有最小概念漂移的路径是有意义的路径。此外，他们提出通过实体之间的语义距离来评估某个实体是否偏离查询的语义焦点。为了计算语义距离，他们使用实体标签的 fastText⁹ 词向量 [13] 之间的余弦距离。fastText 是 Facebook 的一个著名库，它生成单词的静态向量表示，同时对拼写错误具有鲁棒性。相对于 A* 搜索算法 [6] 的一般成本函数 f(p) = g(p) + h(p)，[2] 引入了一个利用语义距离和路径长度来计算包含 n 个实体的路径 p 的成本的函数，如下所示¹⁰ [2]：

```
g(p) := α · \bar{d}(p_{[..n-1]}, e') + β · n
 h(p) := γ · d(v_n, e')
 where p = ⟨e, ..., v_n⟩
 and p_{[..f]} is the sub-path ⟨e, ..., v_f⟩ of p
```

作为 g(p) 的第一部分，公式 \bar{d}(p_{[..n-1]}, e') 计算路径上除最后一个实体外所有实体与 e' 之间的语义距离的平均值。第二部分旨在将路径长度加入成本¹¹。公式 h(p) 通过公式 d(v_n, e')（即路径上最后一个实体与 e' 之间的语义距离）来估计剩余路径的成本。如图所示，成本函数使用三个超参数 α、β 和 γ 进行参数化，这些参数对其各组成部分进行加权。为了计算双向搜索中反向路径（即从 e' 开始以找到通往 e 的路径为目标的路径）的成本，只需在成本函数中交换 e 和 e'。

除了偏好有语义意义的路径外，使用这种成本函数作为搜索启发式还有第二个目的。如 [2] 中所述，一个实体到其他实体的语义距离往往与实体之间的最小跳数正相关。例如，至少相隔五跳的实体通常比相隔两跳的实体具有更高的语义距离。通过优先考虑与目标实体语义距离较低的实体，与广度优先搜索相比，更有可能更早地到达目标实体。

## 表 2. [2] 中使用的超参数 α、β 和 γ 的四种配置。

| 名称 | α | β | γ | 描述 |
|---|---:|---:|---:|---|
| 无信息 | 0 | 1 | 0 | 仅考虑路径长度，类似于广度优先搜索。 |
| 仅语义 | 1 | 0 | 1 | 忽略路径长度，仅考虑语义距离。 |
| 贪婪 | 0 | 0 | 1 | 将总路径成本估计为路径上最后一个实体到 *e′* 的语义距离，具体取决于搜索方向。 |
| 平衡 | 1 | 0.5 | 1 | 在平衡设置中利用成本函数的所有组成部分。 |

近年来，基于 Transformer 的新型方法（如 BERT [15]）取得了优异的结果，从而取代了包括 fastText 在内的先前方法，成为各种自然语言处理任务的最先进技术。BERT 有许多针对特定领域和任务定制的变体。一个例子是 Sentence-BERT 或 SBERT [16]，它能够高效地计算句子的准确向量表示。对于 SBERT，有多种预训练模型可用，这些模型也针对特定任务进行了定制。第 3 节介绍了如何利用实体描述（通常是一个或多个句子）以及实体标签来提高语义距离的准确性。一个针对句子和短段落进行微调的有效模型是 all-mpnet-base-v2¹²，它基于微软的 MPNet [17]。由于新输入的特征及其整体性能，在成本函数的实现中，fastText 被 SBERT 与 all-mpnet-base-v2 的组合所取代。

## 2.2. 超参数优化

在 [2] 中，作者仅使用表 2 中所示的四种直观设定的超参数配置评估了路径查找算法的性能，这留下了改进空间。最近对机器学习的关注推动了超参数优化技术的研究，即自动设置目标函数超参数以优化性能的方法 [18]。一个例子是贝叶斯优化，这是一种用于昂贵黑盒函数全局优化的最先进优化框架，适用于广泛的问题 [19]。贝叶斯优化框架可以分为两个主要组成部分 [19,18]。首先，有一个概率代理模型，它包含一个先验分布，表示对未知目标函数行为的信念。其次，使用一个采集函数，用于衡量一系列查询的最优性。目标是最大限度地减少预期损失，以确定最优查询序列。基于每次查询的输出，先验被修正，从而在目标函数空间上产生一个有信息量的后验分布。由于这种增量式的优化方法，它在超参数质量和效率方面都优于网格搜索等基本的超参数优化技术。

一个相关的替代方案称为 Simple(x) 或简称为 Simple [20]。贝叶斯优化使用计算昂贵的高斯过程来建模目标函数，而 Simple 通过将优化区域划分为单纯形来创建模型。该算法迭代测试每个单纯形内的点，以创建更精确的模型。因此，这种方法将优化任务转化为动态规划问题，允许在不更新整个模型的情况下获取样本。因此，第 3 节中采用 Simple 来优化 α、β 和 γ。
