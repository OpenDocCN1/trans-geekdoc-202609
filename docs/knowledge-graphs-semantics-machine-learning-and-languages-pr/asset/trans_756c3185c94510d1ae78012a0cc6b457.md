
## 4. 数据模型

为了进一步指导对象来源信息的建模，我们以案例研究的形式进行了调查，该案例涉及六件民族志对象，这些对象在荷兰世界文化博物馆（NMVW）⁷发布的两份不同的来源报告“来源#1”[26]和“来源#2”[27]中有所描述，旨在将艺术品的来源信息嵌入其实践和政策中。这些报告描述了通过对这些对象进行广泛来源研究而获取的丰富来源信息。

⁷ [http://wereldculturen.nl/](http://wereldculturen.nl/)

其中一件对象 RV-1148-1 是一根象牙，参与了针对贝宁城藏品的大规模来源研究。该来源研究旨在评估其与1897年2月初英国军队对贝宁城军事行动的关联强度；该研究见报告“来源#2”[27]。其余对象（RV-2584-169a、RV-2334-1、RV-2334-2、RV-2334-3 和 RV-2334-1）来自“来源#1”[26]，其中包含两种不同类型的来源信息。一方面，RV-2584-169a 是一个有趣的案例研究，因为关于该对象的获取和/或来源存在多种可能理论，使研究人员无法以高度确定性得出某一结论。另一方面，ID 为 RV-2334-* 的对象因其复杂的保管链和与不同档案材料的关联而具有启发性。尽管信息多样化，但所有对象的共同点是已发现与重要历史事件或时期可能存在关联，这揭示了对象保管链中不符合伦理的获取行为。信息的多样性、与不同历史事件和时期的可能关联，以及可用的不同档案材料联系，使这些对象成为当前研究的理想案例。这些对象不仅涉及上一节确定的需求，也代表了此类知识的复杂性质。在下一小节中，我们将描述所提数据模型的建模选择。

第一步是重构这些对象的信息，从文本报告中识别与对象来源相关的基本陈述。这些信息被转换为来源数据，以说明表示文物来源所需的关键组成部分。在本研究中，我们考察了 CIDOC-CRM 的使用以确保可复用性。

### 4.1. 对象

我们的需求表明，需要表示关于对象的多种类型的知识。即使详细的来源未知，一级对象信息也是必不可少的。正如一位受访者（R1）提到的，通过了解所用材料或创建/采集日期可以确定来源。CIDOC-CRM 允许以对象为中心和以事件为中心的方法共存，既可以将实例直接连接到对象，也可以不通过中间事件。领域专家要求表示对象的登记号、名称、类别或分类、材料、馆藏和来源。此外，他们还要求能够附加评论和描述性注释。

基于参与者对对象描述的需求，本研究复用了 CIDOC-CRM 指南⁸中提到的用于表达对象馆藏信息的功能规范，并根据用例需求进行了调整。馆藏对象本身是 E24 物理人造物⁹ 的一个实例，具有以下属性（和对象类）。

-   登记号与标题：P1 由（E41 语言称谓 和 E42 标识符）标识
-   对象分类：P2 具有类型（E55 类型）
-   文本描述：P3 有注释（Literal）
-   相关人员或组织：P49 有前任或现任保管者，P52 有当前所有者（E39 行为者）
-   对象尺寸：P43 有维度（E54 维度）
-   材料：P45 由……组成（E57 材料）
-   表现的可视概念：P65 显示视觉项（E36 视觉项）
-   图像：P138i 有表示（IRI）
-   集合名称/群体：P67i 被……引用（E33 语言对象）

额外的对象信息最好通过事件来表示，即 E7 活动、E8 获取、E12 生产或 E10 保管权转移。因此，这些信息与代表性活动相关联，而这些活动本身又与文物连接。例如，P14 由……执行、P7 发生在……、P4 具有时间跨度是 E12 生产事件的属性，其中对象通过属性 P108i 被……生产来连接该活动。另一方面，诸如 P28 由……交出保管权、P29 由……接收保管权、P30 转移……的保管权等属性由于此类信息的复杂性未被提及，而是作为来源信息的一部分进行建模。

### 4.2. 来源信息

除了表示基本对象信息外，领域专家还希望表示具有已知行为者、地点和事件的详细来源信息。对象的来源可以被视为一系列事件，在这些事件中，对象的保管权在不同行为者之间随时间与地点转移。在 CIDOC-CRM 中，对象的来源主要使用两个不同的实体来表示。E8 获取包括法律所有权从一个或多个 E39 行为者实例转移到另一个实例。相比之下，E8 获取指的是法律所有权，因此所有权变更被视为一种法律权利，例如对象被购买。

这里考虑的所有六件对象都有一个共同点：它们的传记中至少有一次保管权转移不被视为法律权利，例如在军事行动期间被掠夺、从非法当局购买或收到可疑的礼物。因此，使用 E8 获取来建模法律权利存疑的不道德获取方式可能不合适。CIDOC-CRM 将法律所有权与实际保管权分开。E10 保管权转移可用于表示非法的获取方式，其中可以声明具体的获取类型，如盗窃、掠夺或赠与。

对于所选对象的当前建模选择，我们使用 E10 保管权转移来表示任何非法所有权转移，使用 E8 获取来表示合法情况。任何此类活动（E8 和 E10）都可以进一步包含其他活动作为子活动，这些子活动位于主要活动的时空体积内。这种子活动是信息提供者在图中进行的断言[22]。在这种情况下，来源研究人员可以识别包含各种陈述的单一知识来源。信息消费者自行决定是否可以信任信息提供者以及信息的可靠性如何。

**PROV-DM** [28] 是一种用于建模来源的概念模型，其中 PROV-O 是到 RDF^12 的映射，已在文化遗产领域得到验证[21,29]。在我们的模型中，它用于将数据来源附加到命名图 URI。PROV-DM 的典型用例是实现数据质量、可追溯性和可信度。**Entity**、**Activity** 和 **Agent** 类是模型的基本构建块。根据该模型，任何物理、数字或概念性事物都可以是 **prov:Entity**，其中 **prov:Activity** 是在一段时间内发生的任何操作，**prov:Agent** 是对该操作负责的任何行为者。因此，在我们的案例中，包含来源研究所有三元组的命名图是 **prov:Entity** 类型，来源研究活动本身是 **prov:Activity** 类型，参与该研究的机构或个人是 **prov:Agent**。表示来源研究和推导出的陈述是我们如何对不同资源和活动生成的不同陈述进行建模的一个例子。在图 2 中，命名图 ex:story#1 包含与对象 RV-2584-169a 相关的所有数据三元组，这些三元组是在研究活动 ex:provenance_research#2 期间生成的。根据 PROV-DM 本体，该活动是 **prov:Activity** 的一个实例，从而能够对生成的三元组进行数据来源追踪。

### 4.4. 多声部建模

数据来源建模和命名图可用于对符合特定获取观点的（CIDOC-CRM）三元组进行分组，并将其与符合另一种观点的其他陈述区分开来。图 2 展示了命名图如何分离代表特定获取观点的不同（CIDOC-CRM）三元组，以及如何使用 PROV-DM 本体指定此类命名图的数据来源。当使用 SPARQL 1.1 查询特定对象的来源时，可以返回陈述对象来源的三元组，而无需区分获取理论。通过使用 GRAPH 关键字，可以仅返回来自指定（来源）图的信息。这允许将来源、位置和/或时间段附加到该观点，并为陈述组附加负责任的行为者/来源。每个命名图或三元组集合表示为一个 **prov:Entity**，通常派生自（*prov:wasDerivedFrom*）另一个 **prov:Entity**（即来源），或由（*prov:wasGeneratedBy*）一个 **prov:Activity**（即领域研究活动）生成。
