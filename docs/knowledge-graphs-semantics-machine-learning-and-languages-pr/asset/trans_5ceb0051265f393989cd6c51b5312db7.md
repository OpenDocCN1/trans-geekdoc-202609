## 3.2. 问题的翻译

翻译过程由两个角色组成：“翻译员”和“评审员”，他们在两个阶段内进行交互：翻译阶段和评审阶段。

翻译员是西班牙语母语者，其主要目标是在将旧翻译归入前述七种情况之一的同时生成新翻译。该角色还需要深入理解 SPARQL 和 QALD-JSON 格式，以便在需要时能够检查问题信息。

评审员是西班牙语母语者，其主要目标是评审新翻译并向翻译员提供反馈，以提高新翻译的质量。

在翻译阶段，翻译员通过检查原始英文问题、其原始 QALD-9 翻译、英文问题关键词和 QALD-9 翻译关键词来评审每个问题。翻译员对描述问题翻译的情况进行标注（见上文），并为英文问题生成翻译。如果问题的翻译正确（情况 7），则保留该翻译。

翻译员总是会查找专有名词的西班牙语版本，以使翻译尽可能自然（例如“Iraq”，在西班牙语中拼写为“Irak”）；这也意味着，如果西班牙语社区以英文名来认识该实体，则不应翻译英文专有名称（例如电视节目“Friends”）。翻译员的目标始终是生成符合自然西班牙语表达的正确翻译（避免语法和重音错误）。

在评审阶段，评审员检查原始英文问题、翻译员生成的翻译以及新翻译中的关键词，以寻找可能的错误。错误被标注并发送给翻译员。翻译员审查这些观察意见，如果翻译员同意更正，则修改问题；会引起对翻译额外关注的更正会被标注并与评审员讨论。评审员解释为什么这些更正是必要的，以便翻译员做出选择；在某些情况下，翻译员会查看问题的 SPARQL 查询和答案以做出适当的选择。这个过程在原始 QALD-9 数据集上执行。生成母语翻译后，利用问题 ID 将它们合并到 QALD_9_plus 中，从而生成我们称之为 QALD-9-ES¹¹ 的数据集。

## 3.4. QALD-9 与 QALD-9-ES 之间的定量分析

结果可在表 3 中观察到。QALD-9-ES 的翻译包含更多单词；每个单词更长且音节更多。QALD-9-ES 还提高了数据集的词汇密度，这意味着数据集包含更多有意义的单词（例如名词、动词、形容词和某些副词）。另一方面，我们发现新翻译呈现较低的类符/形符比（TTR）。这意味着新翻译中的唯一单词少于旧翻译。在分析和比较两种翻译后，我们推测这是因为大多数存在翻译错误的问题（如情况 1 和 3）倾向于添加不正确且无关的单词。与情况 5 相关的问题也会影响该指标，因为某些问题中带有重音错误的单词会被 LinguaF 视为唯一单词。

F1 分数是系统的精确率和召回率之间的调和平均值，如公式 (1) 所示。该指标应用于单个类别；在本例中，我们有多个类别；因此，采用了微平均和宏平均聚合方法。宏 F1 是每个类别所获 F1 分数的未加权平均值，如公式 (2) 所示。微 F1 方法使用正常的 F1 公式计算 F1 分数，但使用真正例 (TP)、假正例 (FP) 和假负例 (FN) 的总数而非单一类别的数值，如公式 (3) 所示。微平均和宏平均指标之间的主要区别在于，微 F1 对每个观测值赋予相同的重要性；因此，对于不平衡数据集，某些类别会显著影响结果。另一方面，宏 F1 对类别 F1 分数赋予相同的重要性，使其即使在不平衡数据集上也能返回客观结果。

$$F1 = \frac{TP}{TP + \frac{1}{2} \times (FP + FN)} \tag{1}$$

$$Macro\ F1 = \frac{\sum F1\ scores}{Number\ of\ classes} \tag{2}$$

$$Micro\ F1 = \frac{\sum TP}{\sum TP + \frac{1}{2} \times (\sum FP + \sum FN)} \tag{3}$$
