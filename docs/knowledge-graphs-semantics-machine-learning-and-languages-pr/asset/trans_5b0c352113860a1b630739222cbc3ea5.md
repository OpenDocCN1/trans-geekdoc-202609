
REQ3：建筑对象及其功能、名称具有高度动态性，并会随时间发生变化。例如，建筑物可能被拆除，街道可能更名，曾经作为药房的房屋可能变成商店等（CQ3.2、CQ4.2-3）。

REQ4：由于信息具有动态性，以及数据存在不确定性和不完整性，事实需要进行来源注释（CQ6.1-2、CQ6.4）。

REQ5：纽伦堡等历史城市中的建筑对象也被视为文化遗产，并且可以通过与其他文化遗产对象建立互联关系来进一步探索（CQ3.2、CQ4.3、CQ5.1）。

针对城市空间语义表示的研究已经开展[1,10,20]，然而，这些本体与 TRANSRAZ 数据模型中的建筑对象模块在主要目标上存在差异——它们用于描述现代城市建筑。此外，这些本体缺少用于表示建筑物各个部分的类和属性（REQ1），因此不足以对 TRANSRAZ 建筑物所需的细节层级进行建模。最后，这些本体不够灵活，也没有考虑动态性（REQ3），因为它们仅面向实时城市空间。

由于缺少用于描述历史城市的本体，因此提供了 CIDOC-CRM 的派生模型，其中 CIDOC-CRM 作为该模块的核心本体。CIDOC-CRM 采用基于事件的方式，这使得能够通过事件表示变化（REQ3）。此外，它还提供了用于以灵活方式表示对象与事件之间互联关系的词汇表（REQ2）。最后，GLAM 机构（画廊、图书馆、档案馆和博物馆）经常使用 CIDOC-CRM 来表示多样化的文化遗产，从而将建筑遗产与相关文化对象联系起来，并置于相应的语境中（REQ5）。

由于 CIDOC-CRM 没有提供足够丰富的语义来对建筑物及其组成部分的结构进行建模，因此通过添加自定义类对模型进行了增强，例如 transraz:BuildingPart。为提高可读性，图 5 仅展示了 TRANSRAZ 建筑模块中的部分元素，完整建模结果已发布在 GitHub17 上。相关信息围绕以下三个主要类进行组织：

- 类 crm:E24 Physical Human-Made Thing 允许定义建筑层次结构中的子类，并描述其组成部分。
- 类 crm:E55 Type 将建筑对象及其组成部分与功能连接起来，例如图书馆、面包店或卧室；或者与其类型连接起来，例如前屋、公园或阳台。功能和类型均由 TOPORAZ 项目期间领域专家开发的一组受控词汇表进行补充。
- 类 crm:E5 Event 及其子类（例如 crm:E12 Production 和 crm:E11 Modification）提供了对建筑过程的描述。例如，建筑物何时建成或改造、由谁完成以及使用了哪些材料。

TRANSRAZ 类被定义为 CIDOC-CRM 的子类，因此继承了用于指定事件时间、建筑对象层级性质、建筑对象类型和功能等信息的全部属性。此外，所有建筑对象都与地理坐标和地址相关联，这些坐标和地址充当将建筑对象与行动者连接起来的桥梁。

## 3.2.2. 历史行动者建模

TRANSRAZ 项目的主要目标之一，是不仅从地理角度描绘历史上的纽伦堡，还要展现其社会语境。因此，有必要对其居民、公司及其社会网络进行语义表示。在分析包含纽伦堡人物和组织信息的复杂异构资源之后（见图 3(a)），确定了以下建模需求：

- REQ1：城市中的行动者通过不同关系相互连接。这些关系对于历史研究和谱系研究具有重要意义，并且必须以语义方式表示（CQ1.1、CQ2.1、CQ2.3、CQ5.2）。
- REQ2：行动者的描述通常从历史资源中提取，因此可能存在不确定、不完整甚至错误的情况。因此，需要进行来源注释（CQ6.1-4）。
- REQ3：行动者的属性，例如地址、姓名、职业等，可能随时间发生变化（CQ1.1、CQ2.1-2、CQ3.1、CQ5.2）。

目前存在若干从不同角度专门描述行动者的本体。然而，这些本体大多侧重于描述行动者在虚拟世界中的存在，例如其在 Web 上的活动[12]，或邮政投递所需的基本信息[19]。在本研究中，行动者充当各个建筑模块之间的连接点，也就是不同领域本体之间的连接点。DBpedia 本体（DBO）受益于与最常见本体的链接，例如 SCHEMA.ORG、Wikidata 和 FOAF。因此，不同词汇表中的属性和类彼此互联，并且可以直接复用。此外，DBO 还包含丰富的社会关系语义表示和层次结构，例如 dbo:mother、dbo:sister、dbo:friend（REQ1）。通过映射到 CIDOC-CRM 的类和属性，例如 CRM 的 E21 Person，可以直接使用 CIDOC-CRM 的事件，从而表示变化（REQ3）（见图 6）。

## 3.2.3. 事件与变化建模

在历史研究中，处理文化数据时，观察实体的发展并追踪其随时间发生的变化十分重要。因此，对时间性事件进行适当的语义表示，是 TRANSRAZ 数据模型的关键。基于对数据及其来源的分析，确定了以下事件建模需求：

- REQ1：TRANSRAZ 模型中的事件既表示社会活动，也表示状态变化。例如，1907 年《Zapfenstreich》的首演、某人的地址变更，或一座建筑物的拆除（CQ1.1、CQ2.4、CQ3.1-2、CQ4.2-3）。
- REQ2：状态变化事件既涵盖实体的语义变化（职业随时间改变其功能），也涵盖术语变化（街道更名）（CQ1.1、CQ2.2、CQ4.3）。
- REQ3：事件可以是连续的，也可以是离散的，因此可以与时间点或时间区间相关联。

REQ4：事件及其属性（例如时间信息）通常从历史资源中提取，因此可能存在不确定、不完整甚至错误的情况。因此，需要进行来源注释（CQ6.1、CQ6.2、CQ6.3、CQ6.4）。

REQ5：事件可以通过时间关系相互连接，例如，*重叠*、*先于*（CQ1.1、CQ2.1-2、CQ3.1-2、CQ4.2）。

基于实体的时间关系表示要么需要对 RDF 进行额外扩展[14,27,15]，要么需要添加大量额外陈述[17]；而基于事件的方法能够弥补这一缺陷，并支持直接表示。在文献[11]中，介绍了一种以时间事件为中心的知识图谱。在该研究中，识别出了 Wikidata 和 DBpedia 类 *wdt:Q1656682*（Event）与 *dbo:Event* 的子类。然而，这些本体所建模的事件旨在表示某些活动，例如讲座、音乐会和节日，并不涵盖表示时间状态和变化的事件（REQ1、REQ2）。EventKG 对简单事件模型（SEM）[28]进行了增强，并提供了用于建模以下类型时间关系的词汇表：实体—实体（例如婚姻）、实体—事件（例如，Margarete Haagen 在《Zapfenstreich》中扮演女孩），但并未直接涵盖事件之间的时间关系。例如，《Frauenkirche》的重建是否与圣洛伦茨教堂的重建相重叠？（REQ5）。

相比之下，CIDOC-CRM 为文化、社会和物理系统中的状态变化提供了语义表示。例如，类 *crm:E11 Modification* 及其子类涵盖对象的变化，类 *crm:E8 Acquisition* 涵盖从一个行动者向另一个行动者转移合法所有权的情况（REQ1）。此外，CIDOC-CRM 的事件通过其有效时间范围以抽象时间延展的形式表示（REQ3），例如明朝的持续时间；并且通过时间关系相互连接（REQ5），例如 *crm:P114 is equal in time to*、*crm:P117 occurs during* 等。
