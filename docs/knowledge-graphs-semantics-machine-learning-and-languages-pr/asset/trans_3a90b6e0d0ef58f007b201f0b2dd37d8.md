
如[22]所述。除城市空间外，多个项目旨在对具有代表性的建筑物进行详细重建。例如，Florence4D¹⁰是一项旨在复兴文艺复兴时期佛罗伦萨著名建筑的倡议。同样，项目“Digital Reconstruction of the Breslau Synagogue”¹¹旨在重建布雷斯劳最大的犹太会堂。将提出一个语义信息模型，将对象与重建所使用的资源相连接。此外，通过将其与人物、法人团体、历史事件等关联，会堂将被置于社会背景中。此外，还有多个项目利用开源 HBIM（Historic Building Information Modeling）软件¹²[7]，包括旨在创建历史建筑开放数据库的 HBIM Wiki Project¹³、记录和保护欧洲各地历史建筑的 OpenHeritage 项目¹⁴、H-BIM 平台¹⁵以及将 HBIM 与遗产管理系统集成的 Arches-HBIM 项目¹⁶。在这些努力的背景下，TRANSRAZ 不仅旨在对 1910 年纽伦堡的整个城市环境进行 3D 重建，还通过将建筑对象与外部资源的知识相连接来增强 VRE。为了实现丰富、互操作性和重用，有形（例如，历史建筑、地点、文献）和无形（例如，节日活动、传统、个人的生命线）文化遗产通过本体得到有意义的表示。

文化遗产对象在媒介类型和属性方面差异很大，然而它们仍然具有语义相似性，并可从交叉连接中受益。近几十年来，语义互联和异构文化遗产数据的表示已成为许多研究项目的关注点。已尝试对韩国[21]、意大利[6]和芬兰[18]的国家遗产数据进行语义建模。作为 Europeana 项目的一部分，欧洲数据模型（EDM）[9]被开发出来，为欧洲 GLAM 机构的文化数据提供共享的本体基础设施。所有这些数据模型在建模性质上相似，因为模型的参考主要为概念模型 CIDOC-CRM [8]，即文化遗产的领域本体。近期德国国家图书馆（DDB）启动了一项倡议，开发 DDB 知识图谱，从而增强 DDB 的前端。这是由于 EDM 建模复杂，负面影响了数据的可用性和探索[25]。尽管 CIDOC-CRM 对于 TRANSRAZ 数据模型的以用户为导向的目的也不完全充分，但出于互操作性的原因，TRANSRAZ 数据模型遵循最佳实践并提供到 CIDOC-CRM 的映射。

TRANSRAZ 空间建模的挑战在于文化遗产数据的异构性，该数据来自大量各种资源，且需要在彼此直接连接中表示。这一挑战可通过利用现有本体和词汇表来解决。有关对特定构建块和设计选择进行建模的相关工作在第 3.2 节中讨论。

## 3. TRANSRAZ 数据模型

本节介绍了本工作的主要贡献，即 TRANSRAZ 数据模型，该模型通过本体将代理、建筑对象、事件和历史文献集成到 3D VRE 中。该任务提出了多样的建模挑战：（i）在 TOPORAZ [24] 中，创建了关系数据库模型和 VRE 的第一个版本。TRANSRAZ 这一正在进行的项目的挑战在于将现有模型转换为语义数据模型，并映射到与文化遗产领域相关的现有本体，如例如 CIDOC-CRM。（ii）从档案馆和博物馆获取的历史文献被分析、半自动标注并与 VRE 相连接。为了实现对城市的科学正确探索，文献标注过程必须完全透明，即数据来源在建模决策中发挥重要作用。（iii）在 VRE 中，用户将能够探索不同的时间段。这意味着实体名称会发生变化，房屋会被拆除和重建，组织所有权会发生变化等，这需要在建模过程中予以考虑。

总体工作流程如图 2 所示。建筑对象、代理和事件基于现有 TOPORAZ 关系数据库和领域专家获取的分析历史文献，在本体基础上进行表示。然后它们被集成到 TRANSRAZ 数据模型中，最终进入 3D VRE。

下面将描述 TRANSRAZ 数据模型的构建块、每个构建块的建模要求以及 resulting ontologies。此外，还提供了使用 CQs 对数据模型进行评估。

### 3.1. 从数据源到构建块

由于数据源及其所含知识的复杂性、多样性和异构性，采用了模块化建模方法来构建数据模型。

因此，模块由四个主要构建块表示，对应于数据模型的不同方面。相应地，TRANSRAZ 数据模型按以下块组织：

- **Historical Documents**用于陈述的来源标注，也作为自动语义标注的基础，引用数据模型中的其他构建块和本体中的类。
- **Architectural Objects**表示城市空间中的所有结构，如街道、街区、建筑物、立面、屋顶、房间等。
- **Agents**指在城市生活、工作或拥有财产的人、俱乐部、组织、协会等，或与之社会联系的人。

![](img/5368dd329bd72fa0bf97ac91d6cef632_181_0.png)

- **Events**表示可与时间点关联的事件。一方面，这包括纽伦堡的社会、文化、政治等活动，如 Oktoberfest 1900。另一方面，事件代表某种持续时间和/或转变，如例如，建筑物的拆除、街道的更名等。

### 3.2. TRANSRAZ 数据模型的本体

遵循本体开发的指导原则，TRANSRAZ 数据模型旨在集成、重用、扩展或映射到已建立的词汇表和本体，以表示所需的类和属性。本节介绍了具体的本体工程需求，这些需求源自第 4.2 节中讨论的 CQs，并考虑了期望数据模型中数据的异构性和概念的异构性。此外，对每个构建块建模的最佳实践进行了分析，并与需求进行比较，提出了设计选择。

### 3.2.1. 城市建筑建模

TOPORAZ 关系数据库是纽伦堡主市场城市实体的丰富资源。然而，这些实体及其关系的表示是多样且不完整的。为了对 TOPORAZ 数据模型中的表以及第 4.1 节所述的进一步来源提供全面的语义表示，需要解决以下要求：

- REQ1: 城市的建筑对象以层次结构表示。例如，城市由街区组成，建筑物由楼层组成。该表示可能包括数十个层级，描述建筑物的每个小部分（CQ4.1-2）。
- REQ2: 建筑对象的属性依赖于历史资源，因此可能不确定或不完整。例如，对于某些建筑物提供了确切高度、屋顶形状、墙面开口（窗户、门）和立面风格元素的信息，而对于其他建筑物仅知道其位置区域。
