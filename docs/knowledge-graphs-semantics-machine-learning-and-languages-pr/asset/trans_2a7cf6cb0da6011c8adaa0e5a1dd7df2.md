
更倾向于使 TS 成为分析并注释各种可用术语的更好工具。

## 4.2 来自 VIBSO 开发的经验教训

在本体工程师与领域专家之间的讨论中，我们了解到，用于浏览本体的工具应以简单、无复杂的方式适用，接近领域专家使用的类似工具。由于仍相当不熟悉 TS 及其用于浏览本体的标准树视图，我们的领域专家要求同时提供一个表格视图，列出可用的 VIBSO 术语以获得更好的概览。作为第一步，我们尝试通过从纯 Protégé 基于的编辑方法切换到使用电子表格和 TSV 文件作为定义新 VIBSO 类的输入格式的方法来解决这一需求。尽管这种方法使得领域专家能够更轻松地使用常见的电子表格编辑器直接查看、评论和编辑现有类或创建新类，但通过 GitHub 访问和更改此 TSV 通常似乎是一个很大的障碍。此外，TSV 仅定义了 VIBSO 的类，而不包括从外部本体导入的类或关系。因此，领域专家没有直接理解后者语义的方式。他们必须使用 TS 来查找这些术语为何在 TSV 中被用作父类或作为 VIBSO 公理化的组成部分。能够直接在 TS 中以表格视图列出本体中的所有类可以避免这些缺点。如果这样的表格视图也可以用于对类列表进行排序和过滤，那么在树视图中更直观地把握或分析某些细节会更容易。通过术语标识符进行排序或过滤，例如，可以更直接地区分导入术语和本地术语，从而快速把握本体外部依赖的程度。我们认为，如果在两种视图之间切换的实现方式能够使用户学会欣赏它们在呈现本体方面的差异，那么这样的类列表视图也能够逐渐提高树视图的接受度和使用率。

当讨论术语定义和元数据或本体相关问题，以及当需要请求新术语时，开源开发中最常见的方法是在维护本体的 Git 基于的存储库中提交问题。必须离开 TS 来执行此操作意味着用户需要额外的工作。这促使我们思考如何将 TS 用作简化此类交互的媒介。能够至少在 TS 内列出外部问题，并在最佳情况下直接从 TS 中读取、编写或评论这些问题会更用户友好。像 VIBSO 的一些领域专家一样，不熟悉此类外部服务的本体用户因此无需学习第二个平台来访问有关本体的更多上下文信息，并向其开发者提供有价值的反馈。与此同时，熟悉所需 Git 工作流程的本体用户和开发者也可以通过不必在上下文之间切换而在日常工作中受益。当然，此类功能最好能与不同的版本控制平台一起使用，例如 GitHub 或 GitLab。幸运的是，这两者都有合适的 API，并且在开放本体开发中被广泛使用。因此，专注于其中之一也可以被认为是一大进步。

我们确定 TS 的另一个有用增强方面是能够添加另一层上下文信息，专为特定用户群体而设。除了在术语或整个本体上提供的元数据注释外，有助于用户更好地理解本体的设计模式和选择方面的进一步文档通常以科学论文或在邮件列表和开发平台上发生的讨论的形式提供。维护良好的本体包含指向这些来源的链接和注释。然而，整理此类链接和注释是一项相当费力的任务，因为整理者必须决定其是否适合包含在源代码中。因此，许多用例或项目特定的注释和讨论可能会被排除或埋藏在外部来源中。此外，在遵循这些链接时通常必须离开 TS，从而有被分心的风险。特别是在以模块化方式使用多个本体时，对于经验不足的用户来说，了解为何必须导入某些术语可能相当具有挑战性，因为从用例角度来看它们似乎是不必要的，但从本体论角度来看它们是必要的，以保持与其公理化一致。TS 中允许其用户对术语和本体级别进行评论的功能将是共享就地见解的一种替代方案。

例如，对于 VIBSO 中导入的 OBI 术语 assay，它是所需振动光谱测定特化的重要超类，我们可以直接为领域专家提供进一步的上下文，说明如何在定义新的此类特化测定时解释断言和推断的公理化以保持与 OBI 设计模式一致，而不必在其他地方的开发文档中提供此信息。通过在其他本体的同一类上也使此类注释及其特定上下文可见，其他 TS 用户也可能从此类见解中受益。

另一方面，通过本体级别的注释，用户可以讨论它们在特定用例中的适用性。为了保持在 VIBSO 的示例中，在 CHMO 上添加注释会非常有帮助，这些注释传达给我们的领域专家我们在 VIBSO 中已识别并需要解决的差距和问题，并链接到其相关问题以获取进一步详细信息。通过这种额外的层，CHMO 开发者以及其他人因此可以更好地跟踪我们的工作，而无需在多个源代码存储库中搜索相关问题。对于未在允许提交问题的开放平台上维护的本体，遗憾的是这种情况仍然相当常见，此类 TS 功能将更加有帮助。我们认为将 TS 用作此类媒介是保持跨多个本体的问题的更好概览的宝贵方式，从而更好地解决调和和映射的复杂问题。

本体专家在 VIBSO 开发和其他 NFDI4Chem 相关本体工作中使用 TS 的经验也导致了对 TS 的改进建议。对于该用户群体而言，TS 的一个主要优势是，在许多不同本体中进行浏览和快速查找时，他们不必将所有这些都加载到 Protégé 中。TS 的另一个优势是能够直接链接到单个术语，这是在许多不同上下文中引用这些术语的重要方式。在基于网络的 TS 中进行查找任务，并在 Protégé 中本地进行开发任务，有助于更好地保持专注，而保持专注在处理形式本体时非常重要。然而，该用户群体习惯于某些通常很小但方便的功能，这些功能简化了他们的日常工作流程。在 TS 中在有意义的地方也提供此类功能是首选。我们本体专家确定有用且可移植到 TS 的此类功能之一是能够使用键盘导航键快速遍历层次树。另一个是能够调整包含树视图和术语详细信息的 GUI 窗格的大小。为了找出还有哪些其他功能也适合移植到 TS，我们将需要进行进一步的用户研究。

## 5. 术语服务

我们术语服务的开发最初是由提供一个强大的服务来搜索、浏览、分析和访问各种社区和场景的本体、术语或词汇表的需要所推动的，例如研究数据的语义注释或数据生成。TIB 术语服务解决了这些需求，并在多个领域提供对本体的整体访问。通过引入集合的概念，我们可以根据学科、领域或项目对本体进行分组，提供定制视图，支持社区不仅识别而且请求新术语。NFDI4Chem 术语服务 [37] 就是这样一个面向对化学本体感兴趣的研究人员的学科特定视图，已在 VIBSO 开发中使用。表 2 总结了迄今为止建立的可用集合。
