
- **符号异质性：**本体描述的是同一事物（例如一把带柄的锋利金属刀片），但人们/用户会根据上下文对其进行不同解释（刀可以是武器也可以是厨房用具）。

- Achichi 等 [25] 从实用角度对数据链接工具设计者遇到的异质性进行了分类：
  - **价值维度：**针对术语层面、所用语言以及数据类型属性与对象属性之间区分的异质性问题。
  - **本体维度：**针对词汇表、结构、属性深度、描述和键的异质性问题。
  - **逻辑维度：**针对类和属性异质性问题。
  - **数据质量维度：**针对违反良好实践、值类型异质性或数据集未更新的问题。

- Assi 等 [26] 讨论了 IM 的问题。他们提出了在大型数据集上进行 IM 时的可扩展性问题。此外，他们将异质性分类为：
  - **价值异质性：**涵盖多语言、数据格式和数据质量的概念。
  - **结构异质性：**涵盖词汇异质性、谓词层级和谓词粒度概念。
  - **逻辑异质性：**涵盖层级变化的概念。

我们发现这些不同的异质性之间存在许多相似之处，无论是在组织层级和细节方面，还是存在许多差异。我们将这种多样性归因于所涵盖的领域不一定相同。例如，实例匹配和本体匹配，并且每个研究的详细程度不同。通过这五篇文章，我们能够识别出 69 种异质性描述（见表 2）。

## 4.3. 迭代方法论

在第 3 节中，我们介绍了四个问题，以评估它们与论文语料库中讨论的各种异质性类型的对应程度。为了将这些异质性纳入我们的新分类中，我们进行了手动聚类迭代。此过程的一个示例如图 5 所示。在每次迭代中，我们根据作者的描述将标记归类到不同的主题中，以完善我们的分类。一些标记在后续迭代中被发现属于多个聚类——例如 Assi 等 [26] 提到“不正确性仅指数据的排版错误”——这会影响谓词的值以及谓词本身。由于第一次迭代的结果，我们无法对一些异质性进行分类，这促使我们建立了第五个主要层级，称为“图级问题”。例如，当 Achichi 等 [25] 讨论键异质性时：“一个属性用于为数据集提供特定的个体标识符，例如两个图书馆中书目条目的标识符。在这两种情况下，这些键属性的值在不同数据集之间是不可比较的。”我们无法将这种异质性问题归类到我们最初的四个问题中。

经过四次迭代后，我们得出了一个最终分类，解决了所有异质性问题，组织成五个主要层级，基于文献中发现的异质性描述。

### 5.1. 链接问题类型 (LPTs) 的分类

### 5.1.1. 谓词值问题

谓词值问题可以分为术语问题和结构问题（图 7）。在术语层面，分类扩展到三个粒度层级，在最精细的层级表达了文献中主要由 Bergman [22] 和 Assi 等 [26] 报告的同义词、歧义词或语言问题。

LPT 1.1.2.5 范围内的问题例如，一对数据集中的数据不一致（例如，纽约市在一侧描述为 8,804,190 居民，另一侧为 8,800,000 居民）。对于 LPT 1.1.3，一个例子是，字面量没有语言标签的数据集对（例如，“barbecue” 而不是 “barbecue@en”），这将阻止自动确定标签语言。对于 LPT 1.2.2，一个例子是，纽约市在一侧由字面量 ”New York”@en 表示为三元组的宾语，另一侧由其 URI https://www.wikidata.org/wiki/Q60 表示，指向相应的 Wikidata 页面。

### 5.1.2. 谓词问题

谓词问题可以分为谓词术语问题、谓词结构问题（如谓词值问题）和谓词词汇问题（见图 8）。

LPT 2.1.5 范围内的一个问题例如，一对数据集中同一谓词有拼写错误（例如，一侧为 hasPopulation，另一侧为 hasPupulation）。对于 LPT 2.2.3，一个例子是，需要插入或删除一个额外节点（可以是空白节点）才能检索相同信息的数据集对（例如，一侧为 New York hasNickName Big Apple，另一侧为 New York isCalled _b1 hasNickName Big Apple；New York isCalled _b1 hasAcronym NYC）。对于 LPT 2.3，一个例子是，使用不同词汇表的谓词表达相同信息的数据集对（例如，一侧为 foaf:name，另一侧为 rdfs:label）。

### 5.1.3. 类问题

类问题可以分为类术语问题和特化/泛化（见图 9）。我们发现术语问题周围存在聚类，这似乎很正常，如果将其视为谓词值问题的特殊情况。另一个分组出现在类域更具体的特化/泛化问题周围，由 Klein [21]、Bergman [22] 和 Achichi 等 [25] 报告。

对于 LPT 3.1.4，一个例子是，同一概念名称存在变化的数据集对（例如，一侧为 Paper，另一侧为 Article）。对于 LPT 3.2 的一个例子是，使用更一般或更具体的概念的数据集对（例如，一侧为 Phone，另一侧为 HomePhone 或 Smartphone）。
