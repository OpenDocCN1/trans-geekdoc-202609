## 2.3. 用例U3：允许数据利他

DGA第25条讨论了“欧洲数据利他同意书”的实施和制定，该同意书应由欧盟委员会（如图1中(R)箭头所示）在咨询GDPR监管机构欧洲数据保护委员会、即将成立的欧洲数据创新委员会以及其他感兴趣的利害关系者后制定。数据利他组织应采用此表格（如(S)箭头所示），以记录数据主体同意共享其个人数据以及数据持有者允许共享其非个人数据。这些表格应同时以人类可读和机器可读的格式保存，因此成为用例U3的焦点，因为诸如ODRL和DPV之类的语义技术可用于创建这些文档的电子版本。

## 3. 相关工作

司法管辖区相关的数据法律，如DGA或数据法案，根据数据的获取、使用和共享的背景、目的和所涉实体来规定义务和要求。为了使系统能够开展、记录和验证合规相关活动（例如维护公共登记册和活动记录），需要表示不同类型的信息：（i）义务和要求；（ii）个人数据、非个人数据和公共数据；（iii）数据使用。以前的工作已经在“法规遵从”和“使用词汇表表达法律元数据”的通用领域内开展并发表[6]，以规定如何将司法管辖区法律转换为用于数据治理的语义模型。在本工作的背景下，我们关注现有的研究和解决方案，仅限于解决第2节中指定用例中所提出的要求，并介绍以下两个小节中进一步描述的（i）用于表达策略和数据活动相关元数据的词汇表，以及（ii）用于指定（个人）数据和元数据处理信息的词汇表方面的最新技术。

### 3.1. 用于表达策略和元数据的词汇表

最近发表了一项调查[7]，其中分析了一组词汇表和策略语言，以评估其表示符合GDPR相关实体义务和权利所需信息的能力。具体而言，该调查得出结论，ODRL是一种成熟的资源，可用于表示与数据保护法律要求相关的策略；它是开源的，有良好的文档支持，并继续由W3C社区小组开发和维护。ODRL信息模型[8]是W3C标准推荐，允许表达灵活而复杂的数字策略，包括表示对资产执行某些操作的许可和禁止，以及使用约束和义务进一步限制这些策略。ODRL还支持扩展开发，即所谓的ODRL配置文件⁴，它提供了一种为ODRL核心词汇表中不存在的特定领域添加更多术语的方法。尽管其他解决方案（如XACML [9]或LegalRuleML [10]）提供了更丰富的表达能力和形式语义来利用这些资源，但ODRL具有便捷的扩展机制，并已被证明可以作为处理GDPR要求的策略语言使用[11,12]。其他通用词汇表，如W3C DCAT推荐标准[13]或DCMI元数据术语（DCT）规范[14]，也将被使用，因为它们提供了与数据集相关的元数据描述术语，包括有关创建和维护数据的实体的信息，或有关数据使用和访问的时间和空间声明。

### 3.2. 用于指定数据及其处理的法律词汇表

需要一种指定法律概念的词汇表，以表达与数据相关法规一致的政策；在本工作中，需要一种能够轻松补充并集成ODRL以及其他先前提到的词汇表，以表达与第2节中指定用例相关的示例。虽然现有技术中没有工作提供处理DGA要求的概念，但已经开发了几种涵盖GDPR概念的词汇表，这些概念可以重用。特别是，正如前面引用的数据保护词汇表调查[7]所确认的那样，DPV [15]的分类法集合提供了最完整的词汇表集，用于表达有关数据、实体、处理活动、目的、法律依据、权利、风险和后果、技术和组织措施、规则或技术的信息。此外，已经有已发表的工作使用DPV为与GDPR处理活动登记册[16]相关的信息表示创建语义模型。因此，DPV将成为本工作开发所基于的基础词汇表。

## 4. 扩展W3C词汇表以覆盖DGA要求

如前几节所述，DGA要求带来的信息表示存在空白，特别是：规定公共数据重用的条件（在第4.1节进一步阐述）、填充数据中介服务提供商和数据利他组织的公共登记册并记录其活动（在第4.2节进一步阐述），以及为数据主体的同意和数据持有者的许可创建通用数据利他表格（在第4.3节进一步阐述）。在以下小节中，我们讨论了可用于表示第2节中描述的某些信息项的现有标准和规范中的术语，并在一个开源专用词汇表中定义了缺失的术语，以覆盖已识别的用例。此外，对于每个用例，我们还提供了示例以证明其适用性。
