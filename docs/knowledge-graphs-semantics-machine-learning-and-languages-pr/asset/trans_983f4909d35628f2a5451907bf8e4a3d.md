## 2.2 本体开发工具

开源本体编辑器（如 Protégé 及其在线版本 WebProtégé [24]）或可视化工具（如 WebVOWL [25]）可用于逐个检查和开发本体。然而，当需要研究多个本体中的术语，或同时比较多个本体时，这些工具缺乏术语服务所提供的灵活性。同时，这些工具面向的是经验丰富的用户。由于其功能广泛且复杂，对于新手用户而言可能相当难以应对。

此外，这类开发工具也不太适合直接查看同一本体不同版本之间的变化。为了确保应用在实现所复用本体的新版本时不会失效，必须让本体用户能够以简单的方式访问并跟踪不同本体版本之间的变化。这意味着所有本体版本都应当能够被浏览和比较。如果希望避免将同一本体的不同版本加载到本体编辑器的多个实例中，通常会采用术语服务。然而，当需要提供多个本体的多个版本时，庞大的数据量以及版本信息经常缺失，可能会带来相当大的挑战。在纯本体层面，DBpedia Archivo 项目已经开展了相关工作。因此，将版本差异集成到一个同时支持浏览本体术语的术语服务中，要么需要大量计算资源，要么需要围绕变化展示方式提出新的方法，例如计划中的知识图谱变更语言（Knowledge Graph Change Language）背后的相关工作 [26]。

除了本体归档和版本管理之外，人们还开展了促进本体开发与维护过程的相关工作。促进本体开发过程的重点主要在于自动化和质量保证标准。例如，ROBOT [27] 根据软件开发标准构建，用于帮助本体开发者自动执行文件转换、错误检查、推理、元数据标注、模块化和发布管理等常见任务。本体开发工具包（Ontology Development Kit，ODK）[28] 使用 Docker，将模板、标准和质量检查与 ROBOT 或 GitHub 等工具以打包方式集成，从而使其更易于在常见的开发工作流中使用。

如前所述，本体开发工具旨在帮助开发者以最佳且精确的方式开展开发工作，同时也帮助开发者更好地理解本体。然而，与术语服务相比，它们并没有提供强大的本体探索方式。另一方面，术语服务主要侧重于浏览，并不试图提供更多与本体开发过程相关的工具。基于这些观察，如果术语服务被用作人们感知和理解本体时所信赖的主要媒介，那么理想的术语服务应提供一些工具，在一定程度上促进开发过程。

## 3. Prolog——寻找恰当的词语

在使用术语进行数据标注，或将术语的一部分导入新的术语体系时，一个主要挑战是必须决定从哪个术语体系中使用哪些术语。为了能够做出适当的决定，用户要么已经了解哪些术语体系和术语适用于特定的科学语境和使用场景，要么（更有可能的是）能够通过浏览可用的术语体系来获取这些知识。带有图形用户界面（GUI）的术语服务就是这样一种资源，它能够让人类理解术语体系，因此应尽可能提供有关术语体系本身及其所包含术语的详细信息。当需要比较多个覆盖相同或相互重叠知识领域的术语体系时，这一点尤为重要。术语用户需要能够了解不同术语体系之间的语义差异、相似性以及相互依赖关系，从而做出明智的决策。因此，直观的术语浏览方式对于评估术语体系的范围及其对使用场景的适用性，以及理解其整体逻辑构成，至关重要。用户应能够轻松遍历术语层级，就像使用文件浏览器，或在文档阅读器中浏览出版物一样。在其他情况下，我们需要能够对术语体系中的术语进行排序和筛选，就像使用电子表格时的习惯一样。在探索术语体系有时非常复杂的语义，或在日常工作流中快速获取所需信息时，都需要这类 GUI 功能来帮助用户保持专注。

## 4. 本体开发

为了更具体地了解协作式本体开发工作流中术语服务需要具备哪些功能，我们分析了 NFDI4Chem 项目 [29] 中一项仍在进行的本体开发工作里，领域专家和本体专家所积累的经验。这里的重点是采用以用户为中心的方法：从早期阶段开始就让本体开发者参与术语服务的开发过程，以收集细粒度的用户故事和需求。

### 4.1 振动光谱学本体（VIBSO）

顾名思义，振动光谱学本体所涵盖的目标领域，是围绕某类特定光谱学的论述；该类光谱学用于分析分子和晶体的振动模式。更准确地说，该本体旨在对领域专家用于描述和共享此类分析所产生的研究数据输出的技术术语进行形式化表示。因此，它必须包含指代实验设置的术语，例如所使用的设备、设备的相关部件及其属性；包含指代实际分析之前和之后相关过程的术语，例如样品制备，或将原始信号转换为可解释光谱图像的数据转换过程；还包含指代这些光谱图像相关特征的术语，例如其维度或分析意义。

遵循本体开发的最佳实践 [30]，VIBSO 的领域覆盖范围在很大程度上依赖于复用现有本体中的大量术语，而不是重新定义这些术语。首先，它依赖基本形式本体（Basic Formal Ontology）[31]，将其作为抽象上层类（如物质实体或过程）的共同基础；同时依赖关系本体（Relation Ontology）[32]，以表示常用关系。生物医学调查本体（Ontology for Biomedical Investigations）[33] 是 VIBSO 的另一个重要且更具体的依赖项，因为它提供了科学调查领域中的许多通用类和一些特定关系，例如分析、设备或协议。最重要的是，VIBSO 的核心依赖化学方法本体（Chemical Methods Ontology）[34] 中的类；该本体已经为主要关注的化学方法——振动光谱学和拉曼光谱学——定义了相应分支，同时还定义了光谱或光谱仪等其他所需的通用类。我们正与 CHMO 的开发者和维护者开展合作。由于 CHMO 与 VIBSO 在领域上存在重叠，未来有可能将 VIBSO 整合到 CHMO 中。不过目前看来，最好仍将二者分开，以处理有关 VIBSO 范围的已识别缺口和问题。

### 4.1.1 开发方法

由于 VIBSO 所依赖的大多数本体都属于 OBO Foundry [35]，为确保互操作性，VIBSO 的开发也遵循该社区的最佳实践和原则 [30]。此外，VIBSO 采用迭代式、版本控制的开发方式，并依赖持续集成，以确保所有变更都得到适当跟踪，同时对发布文件进行质量控制。在这种方法的技术实现方面，我们使用 ODK、ROBOT、Protégé、GitHub 以及术语服务中的 NFDI4Chem 集合。后者在 VIBSO 的开发中发挥着核心作用：它用于浏览 VIBSO 的最新版本，在讨论中链接到其中的术语，在其他相关领域本体中搜索所需术语，以及定期查阅所复用本体的公理化模式和术语详细信息。

在开发方法的概念层面，我们依赖与化学及相关科学领域的领域专家开展合作，因为振动光谱学正应用于这些领域，而这些专家最了解该领域需要哪些概念，以及应如何为这些概念命名和定义。到目前为止，我们受益于来自 NFDI4Chem 项目、CHARISMA 项目 [36]、BASF 以及比萨高等师范学校的科学家的领域知识。这些领域专家提供了一份初始术语列表，我们据此创建了第一个本体草案。此后，人们又提出了更多术语请求，并主要通过定期开放式在线会议，较少通过本体在 GitHub 上的源代码仓库，与领域专家进行讨论。

作为这些开发讨论的一部分，我们还会请领域专家对所使用的工具和工作流提供反馈。随后，我们利用这些反馈来了解如何通过提升术语服务的可用性，更普遍地改进这种协作式本体开发过程。其背后的理念并不是把术语服务变成另一个仅仅更易于使用的本体编辑器。我们也不希望领域专家必须学习所需的专业工具，从而直接参与 VIBSO 的源代码编写。相反，我们希望开发出更简单的方式，就特定术语和术语体系的语义与他们进行交流。我们相信，如果在术语服务中更容易提出新术语以及对其元数据标注（例如标签、定义或同义词）的修改建议，或者能够直接在术语体系或术语所在位置展开讨论，那么领域专家和本体专家就能更充分地受益于彼此的专业知识。因此，我们
