

树状视图有时可能会让一些新手用户感到困惑。此外，某些操作（例如基于术语 ID 的排序）在类别的树状视图中无法实现。

针对这些发现，我们开发了一种分页列表视图，与树状视图并存。这为用户提供了本体中所有类别的全面表格化视角。列表视图非常详细，包含了关于术语的广泛元数据，例如描述、关系和作者评论。

此外，我们在列表视图中加入了“跳转至”功能。用户可以通过搜索术语名称快速导航到列表中的特定术语，从而提升了平台的可用性和效率。

### 5.2.5 用户界面增强

我们实现的最后一部分（基于经验教训）涉及优化前端应用中的各种 UI 相关功能。最常见的反馈与树状视图页面有关，在该页面中，当选择一个术语时，我们会并排展示术语树状视图和术语详情表。

第一个问题涉及仅使用鼠标点击导航树状结构的挑战。为解决这一问题，我们引入了键盘方向键导航功能。用户现在可以使用右方向键和左方向键展开或折叠树中的节点，而上方向键和下方向键则可以在树节点之间移动。

第二项增强解决了详情表的大小问题。反馈指出，对于带有大量元数据的术语而言，详情表显得过小。为改进这一点，我们将视图面板设计为可调整大小。这样用户可以根据需要调整树状视图和详情表的大小，从而增强元数据的可读性和整体的用户体验。

## 6. 讨论

本体论（ontology）这一主题，由于其抽象性质和哲学内涵（ontology 翻译为“存在论”），往往对领域专家来说是一个难以理解的概念。理解术语表或本体是什么，以及它们为何在其各自的研究领域中至关重要，可能是一个复杂的过程。认识到通过本体对知识进行形式化（即并非基于熟悉的经典/自然语言）表示是机器捕获、理解和解释知识的必要条件，通常只有在深入理解之后才能实现。然而，术语表的重要性和实用性可以非常直接地展示，尤其是在通过元数据注释对研究数据进行语义描述的背景下。在这种情况下，术语服务（TS）可以作为一个有效的门户工具，提供可用本体的快速而简单的概览。该工具可以协助领域专家，例如通过提供特定领域的术语集合，帮助他们在各自的用例中搜索和选择合适的术语。进一步简化的功能，如列表视图，可以提供更多支持，增强服务的可用性和效率。

在这项工作中，我们采用了以用户为中心的方法，来确定旨在增强本体开发过程的术语服务在设计和发展中的挑战和需求。我们自始至终将目标用户群体纳入了术语服务开发过程。特别是，我们与诸如 VIBSO 等本体开发团队保持了密切接触，确保他们的观点和见解从最早阶段就融入服务的结构中。

这种合作使我们能够更深入地了解本体开发过程以及一个有效的术语服务所需的功能。我们高度重视本体工程师提供的持续反馈，这些反馈对于塑造我们的服务至关重要。此外，我们努力将数据标注者（本体的主要用户）纳入开发过程，从而确保我们有效满足他们的需求。

我们组织了许多活动和会议，包括会议、研讨会和在线会议，主要有两个目标。首先，我们寻求介绍我们的术语服务，并展示它如何用于数据标注。其次，我们旨在收集反馈和用户需求，以提高本体的质量及其在术语服务中的展示效果。

与用户的这些密切互动有助于我们构想理想的术语服务并确定其基本功能。从这些互动中获得的见解直接转化为我们服务的设计和功能，确保它充分满足用户的需求和期望。

为研究人员提供可用的 FAIR 数据标注，不仅需要提供任意本体，还需要提供高质量的本体。因此，一个理想的术语服务必须满足本体开发者的需求，从而增强开发过程并确保质量。我们的核心发现是将术语服务整合到整个开发过程中的必要性，从开始到结束。这意味着术语服务应在各个阶段满足开发者的需求，例如人工制品浏览和质量检查，通过讨论、反馈和注释来实现。

术语服务提供这些功能的能力为本体开发者带来了多重好处。首先，它通过 Git 问题和术语服务注释促进持续反馈，确保开发出的本体质量。此外，拥有注释和 Git 问题可以让其他术语服务用户和经验较少的开发者随时了解有关本体的最新讨论和主题。这为目标本体添加了新的上下文层次，增强了其可理解性。此外，将这些本体开发工具整合到术语服务中，减少了在不同系统和环境之间的上下文切换，而上下文切换可能对开发者的表现产生负面影响。

最后，我们注意到术语服务用户界面（UI）的可用性对本体开发者至关重要。对于本体，除了提供树状视图外，呈现类别的列表视图的需求很大。鉴于许多本体中术语数量庞大，开发者能够使用键盘方向键快速浏览树状视图至关重要。此外，由于在有限的屏幕空间内阅读大量术语元数据存在挑战，允许术语服务用户调整不同信息框面板的大小以改善可读性也是至关重要的。

## 7. 结论

我们展示了一个以用户为中心的术语服务开发过程，该服务应用于研究数据标注领域，我们从一开始就积极让本体开发者、知识工程师、领域专家和数据标注者参与开发过程。他们在持续进行的本体开发过程中使用该服务时所提供的持续反馈和见解，对确定术语服务的需求起到了重要作用。

通过将术语服务整合到整个本体开发过程中而带来的附加价值是一个核心发现。在术语服务中集成 GitHub 问题追踪、术语请求和本体注释等功能，简化了开发工作流程，减少了上下文切换，并促进了本体开发者和用户之间的协作。

可用性改进是另一个关键焦点。在传统树状视图之外引入增强的列表视图，为用户提供了本体类别的全面概览，提高了效率和导航便捷性。键盘方向键功能和可调整大小的信息面板的加入进一步改善了用户界面，允许更直观的交互。

总之，这项工作展示了术语服务对本体开发者和数据标注者的价值，并证明了其作为本体设计和策展有效工具的潜力。

下一步将包括增强 GitHub 交互功能和术语服务注释系统，将本体策展融入术语服务用户界面，从而将术语服务建成一个集成的本体策展工具。我们将继续以用户为驱动的开发，从一开始就进一步支持策展工作流程。随着本体在知识表示和数据互操作性方面继续发挥关键作用，有效术语服务的开发和改进将有助于促进各个领域的科学理解和协作。
