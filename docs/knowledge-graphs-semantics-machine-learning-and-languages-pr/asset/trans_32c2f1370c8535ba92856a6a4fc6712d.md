
## 迈向一个多功能的术语服务，以赋能FAIR研究数据：跨科学社区实现本体的发现、设计、策展和利用

Philip Strömertᵃ, [0000-0002-1595-3213], Vatsal Limbachiaᵃ[0000-0002-9535-6960], Pooya Oladazimiᵃ[0000-0002-5117-070X], Johannes Hunoldᵃ[0000-0002-4378-6061], and Oliver Koeplerᵃ[0000-0003-3385-4232]

ᵃ德国汉诺威莱布尼茨科学技术信息中心（TIB）[04aj4c181]

**摘要.** 为了充分释放数据的潜力，创建机器可读数据并采用FAIR数据原则对于成功的数据驱动型科学至关重要。本体是生成机器可以理解的、语义丰富的FAIR数据的基础，能够实现跨学科的无缝数据集成和交换。在本文中，我们介绍了一个多功能的术语服务，它支持各种任务，包括发现、提供，以及本体设计和策展。该服务提供对跨学科大量本体的统一访问，鼓励它们的重用、改进和成熟。我们提出了一种用户驱动的服务开发方法，以及一个涉及协作本体设计过程的用例，该过程让领域专家、知识工作者和本体工程师共同参与。这一协作结合了术语服务的应用和评估，以及辅助工具、工作流程和协作模型。我们展示了开发术语服务的可行性、先决条件和持续挑战，这些服务涉及本体利用的多个方面，以生成FAIR、机器可操作的数据。

**关键词.** FAIR数据，本体，术语服务，研究数据，化学

## 1. 引言

诸如 re3data [1] 和 FAIRsharing [2] 之类的资源提供数据存储库、数据库、数据和元数据标准及策略的全面集合。欧洲开放科学云（EOSC）[3]、德国国家研究数据基础设施（NFDI）[4]以及英国物理科学研究数据基础设施（PSDI）[5]等倡议创建并提供服务和基础设施，使研究数据公开可用，并采用FAIR数据原则[6]。开放科学的愿景已获得发展势头，并被越来越多的科学社区付诸实践。

日益庞大的数据可用性使得探索新的数据驱动、跨学科研究问题成为可能。这些方法需要跨学科边界整合和协调机器可操作数据，以解决可发现性、可访问性、互操作性和可重用性问题。机器可操作数据的想法源自 JDDCP [7] 指南，该指南涉及使数据可被机器读取和修改。

机器可操作的FAIR研究数据是通过丰富的元数据标注来实现的。此外，这些元数据本身也需要符合FAIR原则，即用于数据标注的元数据需要能够被人类和机器理解和操作。诸如 DataCite [8] 或都柏林核心元数据（Dublin Core）[9] 之类的通用元数据模式无法表达数据丰富的学科特定描述。这常常导致标注仅限于诸如标题、作者、日期和格式等基本元数据，并以长自由文本的形式提供领域特定元数据，由于缺乏语义而降低了数据的FAIR程度 [10]。

在这里，术语在创建语义丰富的、学科特定的元数据方面发挥着重要作用。它们进一步为实体的共识定义提供了基础，从而确保跨领域的概念一致性，即使术语命名在不同的领域之间有所不同。使用实现标准化术语的元数据模式促进了互操作性和数据集成，因为通过通用术语描述的数据可以在不同的系统和学科中被理解和使用。

术语服务，如本体查找服务（Ontology Lookup Service）[11]、Bioportal 或关联开放词汇表（Linked Open Vocabularies），提供对通用或学科特定的本体、术语或词汇表集合的访问。它们提供诸如浏览、搜索、过滤和下载本体等功能。因此，术语服务在数据标注和FAIR数据创建过程中识别相关本体方面发挥着关键作用。它们的重要性体现在被集成到各种数据标注或数据管理工具中。

CEDAR 工作台支持使用领域特定的元数据模式进行数据标注 [12]。为了创建元数据模板，该工作台集成了来自 Bioportal 术语服务 [13] 的本体术语，用户可以选择这些术语。Dataverse 项目支持集成定制的元数据模式，这些模式可以用来自链接的术语服务的术语填充 [14][15]。电子实验室笔记本 Chemotion 利用术语来标注实验数据 [16]。

随着术语在数据标注中的使用日益增多，术语中的错误和空白不可避免地不仅会被本体工程师发现，也会被标注数据的领域专家发现。这为术语服务开辟了新的应用领域。还有什么比使用那些用于搜索和分析本体的服务来进行策展和开发更自然的呢？

在本文中，我们讨论了协作式本体开发工作流程，以及支持这些工作流程的多功能术语服务的需求。在本体工程师、知识工作者和领域专家组成的团队中，协作设计和策展本体的最佳方法和最佳实践是什么？术语服务需要满足哪些要求才能支持不同专业水平利益相关者的设计和策展工作流程？术语服务如何在本体开发中改进术语的应用和跨知识域重用的协调与对齐？

在下一节中，我们概述有关术语服务和本体开发工具的相关工作。在接下来的部分中，我们简要描述在数据标注中使用术语词汇中的术语，或在新术语词汇中重用现有术语词汇中的术语时面临的挑战。第4节描述了我们的协作式本体开发方法，以及在为派生工作流应用术语服务时获得的经验教训。在第5节中，我们描述我们的术语服务以及我们根据本体开发过程中经验和观察所得需求而开发的增强功能。第6节总结并讨论了对用户驱动开发过程的见解和评估，以将术语服务扩展为本体开发和策展的工具。

## 2. 相关工作

有两类服务和工具旨在促进本体的访问和开发：术语服务（TS）和本体开发工具。在本节中，我们介绍最著名的开源工具和服务，并讨论现有解决方案在构想一个能够同时用于本体开发和数据标注的、良好集成的TS方面的不足和差距。

### 2.1 术语服务（TS）

许多成熟的术语服务和仓库是公开可用的。术语注册表，如基本叙词表、本体和分类注册表（BARTOC），代表了这类服务的最简单形式 [17]。注册表通常列出关于词汇表、术语和本体的全面元数据，并链接到其原始来源，而术语仓库则提供对术语数据本身的访问，通常还通过API提供对这些数据的访问 [18]。

常用的TS框架，如 OntoPortal [19] 和本体查找服务（OLS）[20]，提供扩展功能，如在索引术语中进行搜索和浏览、概念和属性的树形视图以及可视化。OntoPortal 是由 OntoPortal 联盟开发的一种基于本体的门户架构，可定制以提供学科特定的术语服务。它源自 BioPortal，后者提供对生物医学本体和术语集集合的访问 [13]。

本体查找服务由 EMBL 欧洲生物信息学研究所（EBI）开发和托管，提供本体搜索和可视化服务，以及通过API进行的数据访问和搜索。此外，还有 Skosmos，一个专门用于简单知识组织系统（SKOS）词汇表的开源基于Web的浏览器和发布工具 [21]。它提供了浏览和搜索数据的用户界面，以及支持基于术语搜索的API的关联数据访问。

DBpedia Archivo 在网络规模上归档本体，以提供对其不同版本随时间变化的访问。它还提供质量度量 [22]。关联开放词汇表（LOV）门户提供了语义网和关联数据领域词汇表的全面概述，也可以通过SPARQL端点访问 [23]。
