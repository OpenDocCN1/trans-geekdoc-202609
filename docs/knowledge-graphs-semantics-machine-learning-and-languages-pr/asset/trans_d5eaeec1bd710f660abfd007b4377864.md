## 1. 引言

记录和文档化人类和人工智能驱动的规范决策过程极具挑战性。我们关注规范协调的挑战：社区中的利益相关者理解并同意他们遵守何种规范的过程。我们的目标是开发并形式化FLINT语言，该语言允许对规范系统进行高层次描述[1,2]。FLINT使法律专家能够就规范达成一致，同时也作为技术实现的基础。它通过关注规范如何规制行为来实现这一点，因此采取动态视角：它以规范行为及其前置条件和后置条件来表示规范。

尽管这一视角在实践中很有用，但FLINT所使用的概念的形式化仍缺乏。在本文中，我们因此提出了FLINT本体。我们首先在第2节描述了规范表示的相关本体。随后我们在第3节解释我们的方法。第4节展示了本体本身，之后我们在第5节说明如何使用本体。我们在第6节进行总结。

## 2. 现状

在法律领域，已开发出众多词汇表和本体以有效结构化和组织与规范相关的数据[3]。许多解决方案针对特定领域或范围，例如资产规范[4]、知识产权[5]，或隐私和个人数据保护[6,7]。

我们感兴趣的是开发领域中立的本体来表示规范知识。此外，正如我们在方法部分将要论证的，我们感兴趣的是表示规范系统[8,9]。因此，我们关注在所有相关情境下代理可用的完整规范行动空间[10]。在我们看来，这种方法涵盖了规范违规和制裁的考虑。因此，我们的工作与关注义务和禁止或评估情况而非行动的违规的解决方案相距甚远，例如LKIF[11]、LegalRuleML[12]以及Francesconi & Governatori的最新工作[13]。

对于我们的工作而言，最相关的比较可能是UFO-L法律核心本体[14,15]。² UFO-L在统一基础本体UFO[19]的背景下提供了法律关系的正式描述[17,18]。与FLINT类似，UFO-L对权力-责任关系的类别具有丰富的表示，包括识别哪些行动者类别可以在关系内占据哪些法律地位的方式[权力持有者，责任持有者]。在采用制度行为的概念时，UFO-L和FLINT都可以被认为是Searlean[10]。然而，我们认为将法律关系和制度行为的概念解耦是有理由的。词汇表之间的第二个差异是制度事实的表示，制度事实共同表征规范系统的完整状态空间。UFO-L采用事件的概念来表示法律权力的行使。虽然事件因此可以编码行动已经发生，但它们并未提供该行动对规范状态的后果的明确信息。这进一步意味着，代理被允许采取行动的前提条件不能在UFO-L中通过引用某些状态来建模。相反，前提条件必须通过需要发生的一系列事件的析取来表示，以便前提条件成立。我们认为规范状态的明确模型增强了利益相关者之间的规范协调。也就是说，FLINT使利益相关者能够理解行为对规范系统状态的影响。反之，利益相关者可以理解规范系统的状态如何决定行为的义务地位。

## 4. 本体概述

FLINT本体是一个小型本体，仅包含十三个类。参见图1的类图。本体以RDF/OWL实现并以开源方式提供。³ 我们下面详细描述主要概念。

³仓库可在https://gitlab.com/normativesystems/knowledge-modeling/flint-ontology找到。文档请参见https://normativesystems.gitlab.io/knowledge-modeling/documentation-website/docs/。

### 4.1. 行为框架与事实框架

FLINT中的核心概念是框架：捆绑多条信息的容器[21]。FLINT模型完全由这些捆绑及其相互引用组成。在最高层级，我们区分两种框架类型。*事实框架*描述其存在或真值表征规范系统状态的事物。这包括几种不同类型的事物。首先，是命题，可能复杂或原子，相对于状态为真或假。其次，是在规范系统中发挥作用的主体和对象。第三，是行动：主体可以做的事情。

*行为框架*描述主体可能采取并影响规范系统状态即事实的行为。行为框架通过其属性*hasActor, hasRecipient, hasObject, hasAction, hasPrecondition, creates*和*terminates*与事实框架相连。这三个属性中的第一个描述谁可以执行行为、谁可以承受行为以及哪些对象可以被其影响。通过这种方式，行为框架描述了行为者与接收者之间的Hohfeldian权力-责任关系。与行为相关的行动描述了主体为执行行为必须采取的行动。行为的前提条件描述了行为可以合法执行的情况。最后，行为的后置条件以行为通过使事实变为真和假而产生的事实来描述，分别使用属性*creates*和*terminates*。

### 4.2. 义务

尽管一组具有前置条件和后置条件的行为可以完全描述过程中的有效步骤，但编码规范认为期望的行为也很重要。这由*义务*概念捕获。

我们将义务视为一种特殊的事实，因为它们是规范状态的一部分。这意味着义务从不以绝对方式适用——与其他事实一样，它们由行为创设和终止。每个义务应至少有一个创设它的行为[否则它永远不适用]，并且至少有一个终止它的行为[否则它永远无法履行]。由于义务代表两个主体之间的Hohfeldian义务-权利关系，它必须始终具有义务承担者和请求权人。

### 4.3. 类与实例

需要注意的是，*行为*和*事实*类的实例并非被视为具体行为和事实，而是被视为框架：可在情景中找到的具体行为和事实的原型。例如，行为框架可以一般性地描述申请居留许可的申请，但不是某个个人的具体申请。这可能会引发为什么框架被实现为个体而非像UFO-L中的规范关系那样的类的问题。有三个原因。

首先，我们希望在不使用重载的情况下描述行为框架与多个事实框架之间的复杂关系。其次，在规范本身中也需要实例化，而不仅仅是在情景中：例如，我们希望FLINT模型关于图书馆规章表明借出的书籍应被归还。我们需要对个体书籍的引用，而不是书籍的类，以表明借出的书籍和归还的书籍必须是同一本书。第三，虽然情景中的具体行为与行为框架之间存在关系，但我们认为概念上前者不是后者的实例。
