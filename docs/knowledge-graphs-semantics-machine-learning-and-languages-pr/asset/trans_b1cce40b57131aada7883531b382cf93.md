

## 5.1 架构

TIB术语服务采用前后端模式设计，将本体查找服务定位为使用React库开发的前端应用的数据提供后端。后端服务基于EBI开发的本体查找服务（OLS）构建。这种架构结构体现了一种紧密集成的设计，带有用于摄取和索引术语的专用模块。此外，它还整合了有助于这些术语可视化的图形库，并定义了能够在前端展示数据的API方法。这种架构使我们不仅能够利用已有的API，还能利用本体摄取流程，从而简化了我们的开发工作。然而，为了确保该架构能够充分满足所设想的术语服务的独特需求，我们在所采用的系统中引入了新的方法。

React前端应用满足了用户界面中灵活、自主实现功能的需求，与OLS web应用的原始方式解耦。

由于原始的OLS用户界面嵌入在OLS web应用中，而该应用又与OLS后端架构紧密集成，因此为各个社区提供服务将需要运行多个OLS后端实例。这对于单个项目而言成本高昂，且难以维护。

因此，我们决定让TIB术语服务在一个后端中摄取并索引所有本体，同时将本体分配给一个或多个集合，正如我们之前所描述的那样。这些集合由前端提供给相应的社区，以满足它们的个性化需求和偏好。通常，可以通过在TIB TS的搜索或浏览界面中选择筛选视图来访问集合。如果社区有需要，这些集合可以作为高度定制化的独立前端应用提供。此类实例是从TIB术语服务的原始源代码克隆而来，并在部署过程中通过配置设置进一步定制。这种方法促成了诸如NFDI4Chem术语服务等定制化解决方案的开发。此类实例不仅可以在术语集合方面进行定制，还可以通过仅对所选社区可用的定制化组件来增强功能。这些组件集中维护在TIB术语服务的源代码仓库中，并可在定制前端的部署过程中激活。

这种架构设计确保了TIB术语服务能够适应并响应不同用户社区的独特需求，为其提供定制的界面和功能，同时保持一个集中且一致的后端。

## 5.2 用户驱动的实现

实现的主要动机是处理我们在VIBSO开发过程中观察到的经验教训和反馈。因此，我们针对表1中的每一条经验教训都开发了一项新功能。正在开发的功能可以通过术语服务演示服务器（https://service.tib.eu/terminology）访问。源代码可通过GitHub [40]获取。

### 5.2.1 本体的GitHub问题列表

如第4.2节所述，理想的术语服务（TS）应提供必要的工具，以促进高质量、无错误本体的开发和维护。此外，许多本体开发者利用GitHub版本控制系统来优化其开发流程，使其与既定的软件开发标准保持一致。

有鉴于此，让TS用户能够通过TS直接与GitHub交互成为一项基本需求。这种交互既可以是被动的，也可以是主动的。被动交互可能涉及跟踪围绕特定本体的讨论，而主动交互可能涉及参与这些讨论，甚至报告问题。

因此，我们打算以一种能够同时优化术语开发者和终端用户工作流程的方式来提供术语服务。为实现这一目标，我们开发了一项新功能，允许用户直接在术语服务中访问给定本体仓库的问题列表。

该功能帮助用户跟踪本体的进展，并了解本体中正在处理的项目。此外，它还有助于根据最新活动、开放问题的数量和类型来评估本体的质量。它可以促使使用者和开发者采取进一步措施。最后，它减少了与上下文切换相关的认知负担，因为用户无需离开TS即可访问GitHub问题。目前，此功能仅适用于托管和维护在GitHub上的本体。

### 5.2.2 问题报告与术语请求

除了让TS用户能够监控现有仓库问题外，我们还认识到让他们能够报告问题的重要性，这一需求在VIBSO的观察中得到了突出体现。此功能不仅减少了使用者需要在TS与目标本体仓库（如GitHub）之间进行上下文切换的麻烦，还使那些对基于Git的系统不太熟悉的用户能够通过提供有价值的反馈来积极参与开发过程。此外，它为本体开发者提供了通过一个易于访问且建设性的反馈渠道来提高其工作质量的机会。

为了满足这一需求，我们引入了一项功能，允许TS用户在托管在GitHub上的目标本体仓库中创建问题。我们在TS内的本体主页上添加了一个按钮，用户可以利用该按钮打开问题表单，输入问题内容和标题，然后提交。

我们将这些问题分为两类：一般问题和术语请求。之所以这样区分，是因为某些仓库（如VIBSO）在提交新术语请求时使用特定的模板。为了维护该格式的完整性，当用户选择“术语请求”选项时，TS会自动在输入区域填充相应的模板，从而告知用户该模板的存在并鼓励其使用。

### 5.2.3 本体注释

如前所述，在VIBSO的开发过程中，术语服务（TS）支持用户创建或查看本体注释的能力被认为是一项基本功能。此类注释在本体或本体术语之上创建了一个额外的上下文信息层，从而使本体开发者和使用者都受益。这些注释充当一个动态反馈系统，既可在缺少其他跟踪系统的情况下使用，也可在不希望提交问题的情况下使用。同时，它们通过充当另一种文档记录途径，促进对本体的更深入理解。

为了获得这些优势，我们在TS中开发了一项功能，允许用户使用注释对本体进行标注。要使用此功能，用户需要导航到本体概览中新增的“注释”选项卡。在这里，用户可以添加一条新注释，需要提供标题、正文以及目标工件的国际化资源标识符（IRI）。指定目标工件的能力使用户能够将注释应用于类等特定元素。目前，有四种可能的目标工件：本体、类、属性和个体。此外，用户可以在TS的本体页面上的“注释”选项卡下查看现有注释列表。

目前，此功能在我们的演示服务器上还处于原型阶段。对于其首个稳定版本，我们计划通过引入更多功能来增强其实用性。例如，我们将允许用户根据目标工件筛选注释列表。此外，我们将为用户提供对本体相关注释进行评论的能力，从而为讨论创造可能性。
