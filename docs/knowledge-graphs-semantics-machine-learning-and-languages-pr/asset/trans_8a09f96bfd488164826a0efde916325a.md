
除此之外，为了指定数据用户、公共部门机构、主管机构和单一信息点提供者，我们在词汇表中新增了四类实体（作为 `dpv:LegalEntity` 的子类）来表示这些术语，分别是 `DataUser`、`PublicSectorBody`、`DataReuseCompetentBody` 和 `SingleInformationPointProvider`。根据 DGA 第 8 条的规定，欧盟、国家、地区、地方和部门级别的单一信息点提供者也建模为 `SingleInformationPointProviders` 的子类。为了能够对公共部门机构所持有数据的性质进行分类（如第 3.1 条所述），我们还新增了 `dpv:Data` 的四个子类，即 `ConfidentialData`、`CommerciallyConfidentialData`、`StatisticallyConfidentialData` 和 `IntellectualProperty`，分别表示通过商业保密协议或统计保密协议保护的数据以及受知识产权保护的数据。

此外，如第 5 条所述，公共部门机构所持有数据传输的以下法律依据也作为 `dpv:DataTransferLegalBasis` 的子类包含在我们的词汇表中：A5-9 用于传输许可，A5-11 用于示范合同条款，A5-12 用于充分性决定。我们还新增了 `DataReusePolicy`、`DataTransferNotice` 和 `ThirdCountryDataRequestNotice` 概念，作为 DPV 策略和通知概念的子类，用于表示数据再利用的条件以及向上述数据所有者提供的通知。由于未识别出现有的概念来对单一信息点提供者维护的可搜索资产列表以及请求数据集的程序进行建模，因此这两个概念被建模为 `DataAssetList` 和 `DataReuseRequestProcedure`，并作为 `dpv:OrganisationalMeasure` 的子类。

为了展示现有术语和新创建术语的用法，清单 1⁵ 中给出了一个用于重用 http://example.com/dataset_001 数据集的 `DataReusePolicy` 示例，该数据集可在 2023 年底之前用于科学研究目的。它被建模为 ODRL 要约（offer），因为它提出了数据集的使用条款，但并未授予数据用户任何特权。单一信息点提供者可以使用该策略来维护可用资产及其使用条件的最新列表。清单 2 提供了一个由单一信息点提供者发布的 `DataAssetList` 示例，其中使用了现有术语和新创建的术语。该列表包含前面提到的数据集 http://example.com/dataset_001，以及关于其包含的数据类别、管理其使用的策略 http://example.com/policy_001、数据的格式和大小以及数据集发布者所收取费用的附加元数据。
