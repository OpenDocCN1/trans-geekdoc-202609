
“估计相似性（例如，一个人、一种算法）。因此，相似性的概念只有在考虑一个部分的（心理）表示时才有意义，而对象相似性的估计正是基于这一表示”。我们同意这最后一句引文，并且同意，仅仅观察到两个实体之间的共同特征并不足以使它们相似。事实上，如果我们关注两个人，他们的描述表明他们的身高恰好是 1m78，这一特征并不足以让我们断言他们是同一个人。然而，在相似性搜索中，观察实体的特征是至关重要的，因为一个或一组特征可以通过其描述使实体独一无二（例如，社会安全号码，或名字、姓氏、出生日期和地点、眼睛颜色和邮政地址的组合）。观察某些特征也可能使我们的相似性搜索无效（例如，如果两个人的描述显示一个人有蓝眼睛，另一个人有棕色眼睛，我们就不会试图比较他们）。在相似性搜索中对实体特征的这种使用，事实上意味着我们可以以类似的方式比较相同的特征及其值。为了建立 LPTs 分类的目标，我们因此简化地关注两个 RDF 资源的同一特征的比较，这两个资源被假定通过其在两个不同 RDF 数据集中的描述来表示同一个实体，正如我们将看到的，这一点也可能并不明显。

## 4.2. 回顾处理不同异构性问题的文章

我们根据四个问题对文献中发现的不同异构性形式进行分类，以继续我们对 LPTs 的分类。为此，我们手动审查了上述语料库中汇总的关于异构性的文章。这些文章要么涉及实例匹配（IM）（其中考虑断言（实例概念）），要么涉及本体匹配（OM）（其中处理模型的对齐（类概念））。虽然不同，但这两个领域在执行数据链接任务时是互补的。最后，我们根据它们的相关性和对异构性主题的全局视角，选定了以下五篇文章：

- Klein [21] 提出了对独立构建的本体在组合使用中遇到的不同异构性的分类。该工作确定了三大类异构性：
  - 与实践相关的异构性（例如，未应用语言标签、输入错误、重复）。
  - 与表达这些本体所用的语言不匹配相关的异构性。在这一层面上，区分了与语言层面相关的异构性（例如，语法、表示、语义和表达力）和与本体层面相关的异构性（例如，范式、概念描述、模型覆盖范围、同义性）。
  - 与所涉及的一个或多个本体的版本化相关的异构性。

- Bergman [22] 解决了在使用半结构化 XML 语言（主要基于 Pluempi tiwiriwawej 和 Hammer [23] 的工作）以及扩展的 RDF 和 OWL 等本体表示语言的上下文中解决语义异构性的问题。他认为，即使在一个相同的领域内，只要独立团队创建本体，由于半结构化模式的灵活性，总会存在不同的“世界观”。此外，在序列化过程中，XML 文件和本体可能会遇到语法或结构问题。该工作确定了这些异构性的四类原因：
  - 与结构相关的异构性。当表示相关或重叠数据的源的模式不匹配时（例如，名字和姓氏的聚合），就会出现这种情况。
  - 与领域相关的异构性。当数据源的语义不同时（例如，不同的测量尺度和单位），就会出现这种情况。
  - 与数据相关的异构性。当相似或相关数据的值存在差异时（例如，拼写错误），就会出现这种情况。
  - 与语言相关的异构性。当不同语言的编码和使用存在差异时（例如，使用法语和英语），就会出现这种情况。

- Bergman 估计有四十多种独立的异构性类别。由于我们的工作专注于 RDF 数据集，在 XML 使用背景下描述的某些异构性似乎无关紧要（例如，RDF 中不存在的元素顺序概念）。在呈现的四十多种异构性中，我们选择了属于四个主要类别的二十六种。

- Euzenat 和 Shvaiko 的工作 [24] 与 OM 而非 IM 相关；但仍然带来了我们可以应用于数据链接的异构性分析。他们考虑了以下四种主要异构性类型：
  - 句法异构性：本体用不同的表示语言表达。
  - 术语异构性：本体在命名对象上存在差异（car 与 automobile）。
  - 概念异构性：本体对同一领域有不同的建模选择。这些差异可能在于覆盖范围、粒度或视角。
