Users are split into 2 groups: major and secondary actors. The primary user is the person who will have the most direct interaction with the system. The secondary user is the one who will engage with the system in an ambiguous way. The use case diagram of the proposed system, which contains only one player by name „actor“ and uses cases are ‘Ask authorization from the owner,’ ‘Ask access token from resource server,’ ‘Get the token,’ ‘Using the access token to get the required data from protected server.’ The actor is the client application that wants to read a secured piece of information from a secured place (Boyd, 2012).
