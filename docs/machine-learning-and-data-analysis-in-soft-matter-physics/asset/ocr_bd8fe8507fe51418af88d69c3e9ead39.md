# 7.4.3 Testing the Agent with Progressive refinement

The trained agent was tested to validate its accuracy and generalization. The agent was trained to design 6 × 6 topologies to limit the computational cost of running the FEA calculations. However, designing an optimal topology at the coarse 6x6 level does not offer sufficient design detail. For this reason, testing on a finer mesh size will result in a more meaningful evaluation of the agent’s abilities. The RL agent can interact with topologies larger than it is trained on because the value function DNNs are built solely on convolutional filters. Convolutional filters are not size-dependent and can be passed along any input size. Therefore, the agent could interact directly with a larger topology size (e.g., 24 × 24 or beyond) without retraining. However, the computational cost of interacting directly with a larger topology from starting solid block to optimal topology is significantly larger than interacting with the 6×6 size. Therefore, it propose implementing progressive refinement to help improve the computational efficiency of the RL agent.

Progressive refinement is the process of sequentially increasing the complexity of an object from “coarse” to “fine.” Regarding topology design, progressive refinement increases the topology detail over sequential steps instead of all at once . As a result, the number of elements used to define an equivalent topology shape increases through intermediate steps, as seen in Fig. 12. In this work, progressive refinement was carried out from a starting 6x6 topology to an intermediate 12 × 12 topology to a final 24 × 24 topology which was used to define the agent’s proposed optimal topology for each load case.
