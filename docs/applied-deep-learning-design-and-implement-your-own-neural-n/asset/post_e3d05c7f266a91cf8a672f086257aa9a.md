## Setting parameters

Before the training starts, some important parameters are there that need to be set, such as dataroot, which specifies the path to the root of the dataset folder, and the value of workers, which indicates the number of threads for loading the data with Data Loader, so that instead of the main program, data loading is handled by these workers.

```
dataroot = "." #root of the dataset folder
n_workers = 2 # retrieving the data
batch_size = 128 #batch size
image_size = 64
n_channel = 3 # Number of channels for color images.
latent_vec = 100 # Size of z latent vector
gen_fmap = 64 # Size of feature maps in generator
dis_fmap = 64 # Size of feature maps in discriminator
epochs = 20
learning_rate = 0.0002 # Learning rate
beta1 = 0.5 # Beta1 hyperparam for Adam optimizers
n_gpu = 1 # Number of GPUs available.
```

A batch size of 128 is used, meaning that the number of training examples used in one iteration as mentioned in the paper of DCGAN. The dataset has colored images, so nc, that is, the number of channels are three, each for red, green, and blue. The input to the Generator is a latent vector, that is, nz (random vector noise) with size 100. The size of the latent vector can be varied depending on the complexity of the distribution; such as for MNIST, good results can be obtained with 16 variables, and in the case of sophisticated datasets the value can be increased to even 1000.

The size for the feature maps for both Generator and Discriminator is 64. The model is trained for 20 epochs, and it took around 90 minutes to train the model. The learning rate is set to a small value in order to have better learning. Beta1 is a hyperparameter for the Adam optimizer, which computes the moving average of the gradient, and beta1 controls the decay rates of these moving averages. These parameters are described in the DCGAN paper in much detail. The last parameter ngpu tells if GPU is available or not. If this number is greater than zero, then the code will run on GPUs; otherwise, it will run on the CPU.

## Data loader

Here Dataloader and dataset are created. The DataLoader is an object that loads data from a dataset and gives the ability to apply transformations to the images and easy passing of the images through training. Here, the dataset is created by specifying its root and the transformations, which are applied to the data before giving it as input.

```
# Create the dataloader
dataset = dset.ImageFolder(root=dataroot,
    transform=transforms.Compose([
    transforms.Resize(image_size),
    transforms.CenterCrop(image_size),
    transforms.ToTensor(),
    transforms.Normalize((0.5, 0.5, 0.5), (0.5, 0.5, 0.5)), ]))
```

In this example, DCGAN is trained on the face images, and so, for better training, all the images are resized to small and square sizes, which are centered and focused on faces only, not the background. The **dataloader** uses the composite transform to pre-process images. All types of transformations that are applied to the dataset are clubbed together in **transforms.compose()** function. After this processing, PyTorch loads the images from the disk to RAM. So, all the transforms are inside this function and are applied to the input one by one. In this example, the following transforms are applied:

- **transforms.Resize()**: all the input images are resized to 64 × 64 input images.
- **transforms.CenterCrop()**: for cropping the center of the image, that is, the faces.
- **transforms.ToTensor()**: input image is converted to PyTorch tensor.
- **transforms.Normalize()**: to learn better and faster, normalization helps to reduce the skewness of data and get it within a range. The first tuple argument represents the mean, and the second is the standard deviation value for all three channels, that is, red, green, and blue.

```
dataloader = torch.utils.data.DataLoader(dataset, batch_size=batch_size, shuffle=True, num_workers=n_workers)
```

Here, using arguments, information is provided to the **dataloader**, about the dataset, and batch size, to shuffle the dataset between the epochs for better training and the number of workers for multiprocessing.
