
For example, we have an input image of size 6*6; when we apply stride of (1,1) and perform the convolution operation with the filter of size 3*3, the resultant matrix is of size 4*4 as shown in figure 4.46:

![](img/7e519fee1b702b91799cdf1664598392_262_0.png)

Figure 4.47: Convolution with a stride of two

Also, when we apply a stride of (2, 2) on a 7*7 input image, the resulting matrix is of size 3*3, as shown in figure 4.47. In 2D convolution, the output size of a convolution operation is given as follows:

```
Output_{Size} = \frac{N - F}{Stride} + 1
```

where N is the size of the input image, and F is the filter size.

If we apply padding P in our input image, then the equally sized output image as per the input image is as follows:

## Convolution in 2-D

As we know that images are shown in a two-dimensional space (x, y), and these spatial locations are highly correlated with their neighborhood so we cannot flatten the entire two-dimensional spaces into one-dimensional space as shown in the previous section (see figure 4.53). If we flatten the image into one-dimensional space, then the spatial relationships with the neighboring pixels get destroyed, and if we apply 1-D convolution over this flattened image, then a lot of information associated with features gets lost. So, the need for 2-D convolution comes into existence. In figure 4.54, 2-D convolution is applied using a 3-D filter. Though the filter is 3-D, the convolution is 2-D; why? This is because we are moving in x and y direction as the depth is fixed. The depth of our filter should match with the depth of our image. As shown in the right side of figure 4.54 (b), if the size of our image is H × W × C, then the size of filter should be as w × h × C, that is, the depth C’ of filter should match with the depth C of our image. As the depth is fixed, we are only moving in x and y direction. That is why this is a 2-D convolution obtained by applying the 3-D filter. For example, the size of the input image is 224 × 224 × 3, and the size of the filter is 3 × 3. Then, by default, this filter is treated as a 3-D filter such that its depth will get matched with the depth of the considered image during 2-D convolution. So, the size of the 3-D filter that should be applied over 224 × 224 × 3 image is 3 × 3 × 3. You can also apply different-sized filters depending on the fact that what kind of features you want to extract, like fine-level or coarse-level features. Other possible filters can be of the size like 5 × 5 × 3, 7 × 7 × 3, 11 × 11 × 3, and so on. You can check that depth of each and every filter matches with the depth of the input image. For more clarity, say our image is something like 512 × 512 × 32. Then, the size of our 3-D filter can be 3 × 3 × 32 or 5 × 5 × 32 or 7 × 7 × 32 or 11 × 11 × 32, and so on. Furthermore, the number of computations depends on the size of the filter and the number of filters. Suppose our image size is 224 × 224 × 3 and the size of filter is 3 × 3 × 3, then when we do convolution of this filter over the image, then these 27 values produce one single value, as shown in figure 4.54 (a). Similarly, if we move the filter in x and y direction over the entire image, then we get a single feature or activation map of the size 224 × 224 × 1 as shown in figure 4.54 (b). So if we use N such filters of the size 3 × 3 × 3, then N number of activation maps of 224 × 224 size will be retrieved. Finally, for example, if the number of such filters of size 3 × 3 × 3 is N = 64, then the output feature map size is 224 × 224 × 64. Furthermore, it is much more explained in figures 4.55 to 4.57:
