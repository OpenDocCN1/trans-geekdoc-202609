
y_{target} = \begin{bmatrix} 1 \\ b_x \\ b_y \\ b_w \\ b_h \\ 0 \\ 1 \\ 0 \end{bmatrix}

Here, the value of \(p_c = 1\) is because there is an object detected in this grid. Now, for this grid, how to decide values of \(b_x, b_y, b_h\), and \(b_w\). While using the YOLO algorithm, it assigns the coordinates to the grid as follows:

Here \(b_x\) and \(b_y\) are coordinates of x and y for the object's midpoint of this grid. Here, it is about

b_x = 0.40

And

Now, \(b_h\) is defined as the ratio of the height of the bounding box created in this grid with respect to the grid itself, here, say, it is about 0.90

Therefore,

b_h = 0.90

And also \(b_w\) is defined as the ratio of the width of the bounding box with respect to the width of the entire grid. Here, say, it is about 0.50.


The values of b_x and b_y always lies in the range of 0 to 1, because the mid-points will always be in the grid only.

## Intersection over Union (IOU)

Now, we got our bounding box. But how do we decide if the bounding box is giving us good results or not? So, here intersection over union is used. Intersection over union actually determines the intersection over the union of the actual versus predicted bounding box.

![](img/7e519fee1b702b91799cdf1664598392_389_0.png)

Figure 5.31: Actual versus predicted bounding boxes

In figure 5.31, we can observe the actual bounding box as a red box and the predicted bounding box as a blue box. Now, how do we determine if the prediction is good or not?

So, Intersection over Union (IOU) creates a region of the intersection over union for both of the boxes, as shown in figure 5.32:

![](img/7e519fee1b702b91799cdf1664598392_390_0.png)

Figure 5.32: IOU region

$IOU = \frac{Intersection Area}{Union Area}$

$IOU = \frac{Region of yellow box}{Region of green box}$

So, if

$IOU > 0.5$

Then, the prediction is said to be Good. And if

$IOU \le 0.5$

Then, the prediction is said to be Bad. However, we can change the threshold value of 0.5 according to our needs.

## CNN for object detection

We have already discussed CNN in depth in Chapter 4: Convolutional Neural Networks. Now let us understand how CNN can be used for the purpose of object detection. Here, we generally pass an input image to the CNN, where it is passed through various layers of convolutions, pooling, and we get the output as the class of an object.

CNN can also be used to detect multiple objects in an input image, let us discuss it with an example. Consider an input image as shown in figure 5.42:

![](img/7e519fee1b702b91799cdf1664598392_395_0.png)

Figure 5.42: Input image to the CNN for object detection

Now, the input image is divided into four different parts or regions as shown in figure 5.43:

![](img/7e519fee1b702b91799cdf1664598392_395_1.png)

Figure 5.43: Regions of the input image for object detection

Now, all these parts are considered as separate images and are passed through CNN, which classifies them into different classes. Then all the regions are combined further to get the final original input image with the object detection. What is the problem with CNN being used for object detection?

The problem here is when we divide the image into different regions and then perform the detection part, the detected object may have a different spatial location and also aspect ratios. For example, in some regions, the object may cover almost all of the region, whereas in some cases, the objects may cover only a small portion of the image region, and even the shapes of the objects may differ.

To solve this issue, there will be a requirement for more number of regions, which will consume more computational power eventually. Therefore, to solve this issue, we use region-based CNN (RCNN).
