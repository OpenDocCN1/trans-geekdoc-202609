For example, if the depth of the filter is not fully matched, then it may be aggregating the responses generated by the first three filters and may not know what has happened with the rest of the three filters if the total size of the image or activation map is six. As all the responses should be seen at once, this aggregation is possible if and only if the depth of the filter matches with the depth of the image or output activation maps. Further aggregation can be understood as if we are asking 50 questions to the same pixel (x,y). It means that we are applying 50 filters and getting 50 responses in return, as the first convolution layer output acts as the input for the next convolution layer. Now, these 50 responses that are retrieved after the first filter should be seen at once. That is why to aggregate all the 50 responses, the depth of the second filter should be 50. So, in figure 4.63 (b), after applying the first filter, the output activation or feature map size is 28 x 28 x 6. This acts as an input for the next convolution layer. Six responses of size 28 x 28 are generated after the first convolution layer. During the second convolution layer, all these six responses should be seen at once by the filter. So, to aggregate all the responses, the size of the filter must be 5 x 5 x 6. In figure 4.63(b), ten (10) filters of size 5 x 5 x 6 are applied in the next convolutional layer. After applying the second convolution over the output of the first convolution, the output feature or activation map size is 24 x 24 x 10, as shown in figure 4.63 (c). The size of the feature map gets reduced because there is no padding.

```
Output_{Size with padding} = \frac{28 + (2 \times 0) - 5}{1} + 1 = 24
```

Here, N = 28, P = 0, F = 5 and stride = 1.
