## 9.2.1.2 Computation Function of the Application

Any application that can be implemented can be represented as a mathematical function, which is the computation function of the application, and any mathematical function can be represented in Boolean circuits. Computation function is defined by the smart contract metadata along the input and output parameters. This computation function is converted into a Boolean circuit, divided into multiple sub circuits and is sent for garbled circuit construction in off-line phase, and the garbled circuits generated are linked to it.

## 9.2.1.3 Blockchain

The computation function defined by the smart contract metadata is split and distributed to multiple computing nodes/parties by the block producers while generating the blocks. The computing nodes return the result as well as the proof of comput-, and they are also packed into the blocks by the producer. Validity of the block is determined by other nodes, just by verifying the proof, which reduces the complex, redundant computations on each node, and hence the block verification time. A new block is added to the chain once the verification process is completed.

## 9.2.2 OFF-LINE PHASE

The off-line phase or the off-chain computations carry out the complex multiparty computation protocol. Yao's GC construction (Lindel and Pinkas, 2009); Innocent and Sangeeta, 2014a, 2014b) plays a vital role in multiparty computation protocols. The underlying computation is implemented in a Boolean circuit, divided into multiple subcircuits, and are then sent to computing nodes and executed in parallel. Each circuit is sent to computing nodes to maintain certain level of redundancy and availability guarantee. The garbled circuit selects tokens for each wire in the Boolean, encrypts the output token with that input tokens for each gate, the encrypted tokens are garbled by gate, and the garbled circuit is generated (Lindell and Pinkas, 2009); Innocent and Sangeeta, 2014a, 2014b; Bellare et al., 2012). The garbled circuit evaluator uses oblivious protocol and deciphers the garbled circuit to obtain the required result (Lindell and Pinkas, 2009). The components of off-line phase are described in the following sections.

### 9.2.2.1 Garbled Circuit Construction Using FastGarble with Universal Gates

The garbled circuit construction here uses the FastGarble with universal gates framework (Innocent et al., 2019a). Here, instead of different types of gates, any one of the universal gates (NAND/NOR) is used for Boolean circuit generation, and hence for garbled circuit construction. Also the batch-key cipher optimization for garbled circuit construction is used along with point-and-merge (Noar et al., 1999), garbled-reduction (Pinkas et al., 2009), dual-key cipher with fixed-key block cipher with Advanced Encryption Standards-New Instructions (AES-NI) and Simple Circuit Description (SCD) (Bellare et al., 2013) optimizations. The FastGarble with universal gates is proved to be more efficient in terms of time complexity by execution of protocol, and also requires only two ciphertexts per gate for communications (Innocent et al., 2019a). Overall, the use of FastGarble with universal gates framework improves the efficiency of multiparty computation application.

### 9.2.2.1 Universal Gates on Garbled Circuit Construction

The NOR and NAND gates are called the universal gates as the other gates namely, AND, OR, XOR, and NOT can be derived from these gates. FastGarble with universal gates framework is built on FastGarble framework and uses only the universal gates for Boolean circuit construction. Circuit construction with one universal gate comes with the advantage that a single type of gate is used for the circuit construction. This eliminates the need for gate array G in SCD. FastGarble with universal gates framework is built on FastGarble framework and uses only the universal gates for Boolean circuit construction. For an example, AND circuit suitable for SCD construction built with only Gar is shown in Appendix 9.2, and an illustrated example is given by Innocent et al. (2019a). The gate-type G in the SCD format of FastGarble (Bellare et al., 2013) $f_{iG}=(n,q,A,B,G)$ can be removed to form the SCD construction of FastGarble with universal gates 5-tuples as $f=\{n,q,A,B\}$. The storage size required for the application reduces as the gate need not be stored; a constant value corresponding to the gate type used in protocol. Also, checking of respective gate type is not needed for every gate during garbling, which contributes marginally for the improvement of time complexity. FastGarble with universal gates uses the point-and-amble, garbled row reduction of two rows per gate (GRR-2), AES-NI, and BKC. Fast-XOR technique is negated as there are no XOR gates available in the circuit. As batch-key cipher is used, it requires only two complex encryption/decryption calls per batch of gates. Use of the gate type (either NAND and OR) always ensures the encryption of every first gate of the batch with dual-key cipher, and thus new encryption per batch is applied. Also, even though representing the Boolean circuit with universal gates increases the number of gates, usage of batch-key cipher and GRR-2 design makes it approximately 66% faster than the protocols for garbled construction. This makes it a better choice to be used in FGUGChain framework.

## 9.2.2.2 Interlinked Computing Nodes/Parties with Private Data

Interlinked computing nodes are the parties involved in multiparty computation with their private data. With FGUGChain framework, they are able to compute on their private data without revealing it to a trusted third party on a decentralized environment.

## 9.3 CONCLUSION

The FGUGChain framework discussed in this chapter gives a theoretical exposure to the framework, and it can be used to develop various decentralized applications with privacy. The FastGarble with universal gates framework incorporated to include privacy by the use of secure communication is 66% faster than the existing practical implementations on secure computation. As well, it uses only two ciphertexts per gate and is proven to be secure. The blockchain technology provides better decentralization and allows only the honest parties to be part of the computing environment. Thus, we can say that FGUGChain acts as a platform for generating distributed decentralized applications with privacy by intertwining secure computation with blockchain technology.
