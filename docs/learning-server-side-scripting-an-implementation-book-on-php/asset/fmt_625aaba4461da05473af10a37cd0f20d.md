
# Registration and Login Process

## Registration - Redirect to Login

Hope you have the file ready. We will include the code now. We will test it after completing the login process.

You have an `if` block in the top PHP segment:

```php
if($check_insert1 and $check_insert2){
  echo "<script>alert('Registration successful!');</script>";
}
```

We will issue a redirect command via JavaScript in this `echo` statement. Why are we doing so? Since we get the success message via this `alert()`, we have to induce a redirect after this message. If we code in PHP for redirection, this alert message will be missed. For the safer side, we will code in JS.

Change the code as:

```php
if($check_insert1 and $check_insert2){
  echo "<script>alert('Registration successful!');
  window.location.replace('login.php');</script>";
}
```

This code states that the current page has to be replaced with the URL in the parameter.

### Authentication code: login.php

We will include the authentication part at the top of the page as usual.

```php
<?php
session_start();
require('connect.php');
$auth = true;
$hashedpwd = '';
if(isset($_POST['login'])){
  $username = $_POST['txtmail'];
  $password = $_POST['txtpwd'];
  $select_user = mysqli_query($con,"SELECT * FROM userlogin WHERE user_mail='$username'");
  if($user = mysqli_fetch_row($select_user)){
    $hashedpwd = $user[1];
  }
  else{
    $auth = false;
  }
  if(!password_verify($password,$hashedpwd)){
    $auth = false;
  }
  if($auth){
    $_SESSION['usersession'] = $username;
    echo "<script>window.location.replace('dashboard.php')</script>";
  }
  else{
    echo "<script>alert('Invalid username or password!')</script>";
  } 
}
?>
```

We will look at the explanation:

```php
session_start();
```

We will use `session_start()` for this authentication because we have to store the username as the session variable. It means, until the user logs out / closes the session, the session variable will be alive.

```php
$auth = true;
$hashedpwd = '';
```

We initialize two variables. `$auth` will hold `true` till the end of code if username and password match database records. If `$auth` becomes `false` somewhere, it means either username or password does not match, which means authentication fails. `$hashedpwd` will later hold the password field if the username matches.

```php
$select_user = mysqli_query($con,"SELECT * FROM userlogin WHERE user_mail='$username'");
if($user = mysqli_fetch_row($select_user)){
  $hashedpwd = $user[1];
}
else{
  $auth = false;
}
```

We search the record of the `userlogin` table which matches the username.

*   If a user exists with the username, the password field is assigned to the `$hashedpwd` variable.
*   If a user does not exist with the username, the `$auth` variable is set to `false`.

```php
if(!password_verify($password,$hashedpwd)){
  $auth = false;
}
```

We compare the password entered in the form to the hashed password stored in the table. We use the `password_verify()` function designated for this purpose exclusively. In case there is no match between passwords, `$auth` turns to `false`.

```php
if($auth){
  $_SESSION['usersession'] = $username;
  echo "<script>window.location.replace('dashboard.php')</script>";
}
else{
  echo "<script>alert('Invalid username or password!')</script>";
}
```

If `$auth` holds `true` under all those checks, we assign the `$username` value to a session variable `$_SESSION['usersession']`. After this, we redirect to the dashboard page. If `$auth` turns `false` in any of the checks, we print an invalid login message.

### When does $auth turn false?

*   When a username does not exist
*   When the entered password does not match with the hashed password value already stored in the table (checked via `password_verify()` function)

The login part is over here. We will do a few changes in `dashboard.php` so that we can display the session variable value in this page from the login page.

## Session variable: dashboard.php

Change the `title` tag content to "User Dashboard".

Place the following lines at the top of the page:

```php
<?php
session_start();
require('connect.php');
?>
```

It is advisable to place `session_start()` at the beginning of the page.

As usual, replace the `main` tag content with the code:

```php
<main>
  <section>
    <h3> User Dashboard </h3>
    <p>
      <?php 
      $usersession = '';
      if(isset($_SESSION['usersession'])){
        $usersession = $_SESSION['usersession'];
      }
      echo "<p>Hello ".$usersession."</p>";
      ?>
    </p>
  </section>
</main>
```

We have just assigned the session variable value to a variable `$usersession` and printed the same.

## How to redirect to dashboard if a session is running?

We have one more task to do. In case you close a browser's tab unknowingly, but your session is still not expired, we have to redirect the login page to the dashboard without asking for login details once more.

So, we will add this code to the beginning of the **login.php** file:

```php
session_start();
if(isset($_SESSION['usersession'])){
  echo "<script>window.location.replace('dashboard.php')</script>";
}
require('connect.php');
```

*   Execute <http://localhost/onlinecourse/> in 2 tabs of a browser.
*   Try logging in one tab of the browser.
*   Click Login in the other tab of the browser. You will be redirected to `dashboard.php`.

# 8.2 User Dashboard

Dashboard is the place from where you can access all the necessary links.

In the instructor's dashboard, we can place links to create course, edit course, upload / delete content, view enrolled learner's progress reports, change profile and log out.

In the learner's dashboard, we can place links to enrolled courses, access to courses, change profile and log out.

Whatever page we create, we have two options:

*   To place all the links in every page
*   To place all the links in a single page (dashboard) and place the dashboard link in every page
