## 4.2 相关工作

云计算可被视为Web服务及其概念的延续[[16]](#index_split_001.html#p85)。网格计算[[11]](#index_split_001.html#p85)也可被视为云计算的“智力表亲”，以效用计算为基础[[17]](#index_split_001.html#p85)。因此，我们将关于SLA模板的文献综述分为三类：(a) 网格SLA，(b) Web服务SLA和(c) 效用计算SLA。由于云相关的SLA问题仍在涌现，背景可能包括网格和面向服务架构（SOA）的SLA。以下是对当前SLA框架[[18]](#index_split_001.html#p85)的调查，并附带了关于在云场景中定义新SLA范围的讨论。

开放网格论坛[[19]](#index_split_001.html#p86)描述了`WS-Agreement`，这是一种用于发布服务提供商能力、基于模板创建协议以及在运行时跟踪协议执行的语言和协议。它改进了传统的服务发现和使用模型，如通用描述、发现与集成（UDDI），因为它使服务用户能够发现可用服务、使用服务并动态协商服务的效率。最初没有协商过程，但现在`WS-Agreement`可覆盖SLA生命周期的所有五个阶段。应注意，该项目的范围仅限于Web服务和网格计算。

Web服务等级协议（`WSLA`）是Keller等人于2003年建立的一个系统[[2]](#index_split_001.html#p84)，用于定义和跟踪Web服务的服务等级协议。`WSLA`框架包括一种基于XML Schema的可扩展和可扩充语言，以及一个运行时架构，该架构包含许多可外包给第三方以保证完全客观性的SLA监控服务。客户和提供商可以使用`WSLA`来识别广泛的SLA，确定SLA参数及其计算方式，并将它们链接到受控资源检测。一旦接收到SLA规范，`WSLA`监控服务将自动配置以实施SLA。在定义跨组织和组织内部SLA参数到XML方面，`WSLA`具有很大的通用性。然而，它不支持多级SLA。

Lamanna[[3]](#index_split_001.html#p84)提出了一种语言（`SLAng`），用于为应用服务提供场景生成SLA，在该场景中，客户向服务提交请求，服务处理请求并向网络返回响应。`SLAng`将规范分为两组：通用标准和ASP标准。`SLAng`的语义使用基本元对象工具（`EMOF`）进行定义，这是一种类似于UML的建模语言。模型有助于使QoS参数更易理解。SLA元素的存在也限制了模型中可发现的行为类型。对象约束语言用于定义约束。

### WS-Agreement Andrieux[[1]](#index_split_001.html#p84)、Web服务等级协议（WSLA）Keller[[2]](#index_split_001.html#p84)、SLAng Lamanna[[3]](#index_split_001.html#p84)和Web服务提供语言Tosic[[4]](#index_split_001.html#p85)是几个著名的Web服务（WSOL）SLA结构。用于实现的术语、考虑的条件、应用限制的方式以及适配的生命周期各不相同。由于Web服务和云计算都建立在面向服务架构之上，它们在SLA方面有很多共同点。然而，由于云计算服务实现模型的多样性（例如SaaS、PaaS和IaaS），必须考虑许多额外的标准[[5–10]](#index_split_001.html#p85)。

本章组织如下：下一节通过证明SLA的必要性以及可用性和可靠性在云计算中的重要性来奠定基础。[第4.2节](#index_split_001.html#p71)详述了关于云计算中SLA、可用性和可靠性的相关工作。[第4.3节](#index_split_001.html#p74)提供了可用性和可靠性的清晰定义。[第4.4节](#index_split_001.html#p84)总结了本章。

存在许多适用于与云计算概念相似的技术的SLA模板，如Web服务、网格和效用计算。大多数相关技术的模板要么特定于这些技术，要么正在开发中，要么缺少云所需的SLA生命周期的几个特性。确实，这些SLA模板无法以其原始形式应用于云计算环境。[表4.1](#index_split_001.html#p72)给出了三种技术[[10–15]](#index_split_001.html#p85)的比较，即云计算、网格计算和Web服务。这一对比揭示了Web服务提供的服务与云提供的服务截然不同。Web服务是一种应用程序，它暴露了一个可使用标准Web技术访问的功能，并遵循Web服务标准。这意味着Web服务只是云计算服务模型（2010）之一SaaS中的一个小概念。同样，网格计算和云之间也存在差异。这些差异主要与服务模型、多级SLA、虚拟组织、任务规模、可扩展性等有关。因此，当前的SLA模型无法处理云应用的多样性。

此外，它们局限于QoS，具体指成本和性能分析，并未考虑风险、信任或绿色计算等若干非功能性问题。所有这些都增加了对云计算专用SLA模板的需求。

### 表4.1 云计算、网格计算和Web服务的比较

| **考量因素** | **云计算** | **网格计算** | **Web服务** |
| :--- | :--- | :--- | :--- |
| 计算方式 | 独立或并行 | 独立 | 并行 |
| 服务类型 | SaaS、PaaS和IaaS | 通常为基础设施 | B2B服务 |
| SLA | 是 | 有限 | 是 |
| 多级SLA | 是 | 否 | 否 |
| 协议 | TCP/IP、SOAP、REST | MPI、MPI-CHG、GIS、GRAM | SOAP、REST |
| 虚拟化 | 是 | 有限 | 否 |
| 虚拟组织 | 否 | 是 | 否 |
| 互操作性 | 有限 | 是 | 是 |
| 不同服务模型 | 是 | 主要与基础设施需求相关 | 主要为B2B，最终用户不参与 |
| 资源处理 | 集中式和分布式 | 分布式 | 集中式 |
| 任务规模 | 取决于服务模型。从小到大不等 | 单一大型 | 小型 |
| 可扩展性 | 完全 | 有限 | 否 |
| 多租户 | 是 | 是 | 否 |
| 应用应用 | 中小企业和交互式数据检索 | HPC | 仅限于B2B数据检索 |
| 标准化 | 否 | 是 | 是 |
| 软件依赖 | 独立领域 | 依赖应用软件 | 独立 |
| 平台 | 服务模型 | 必须使用符合网格标准的软件 | 独立 |
| 操作系统 | 运行多个操作系统的Hypervisor | 标准操作系统 | 标准操作系统 |
| 故障管理 | 强（虚拟机可迁移） | 有限 | 有限 |
| 用户友好性 | 高 | 低 | 因B2B性质，无与最终用户交互 |
| 安全性 | 必需 | 仅针对非用户需求 | 几乎安全 |
