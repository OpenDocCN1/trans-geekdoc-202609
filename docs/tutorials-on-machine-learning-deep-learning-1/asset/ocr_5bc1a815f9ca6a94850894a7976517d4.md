# 15.9 Test model: use-test-set to calculate "test-loss"

Here we compute the **test-set loss** and hope we can make it better ($l$ star error of ratings).

+   Similar to the **RBM** model, we don't need-for-loop because we are not training the **model**.
- We don't need epochs to measure the **test-set** performance to measure the **test-loss**. We of course only one epoch because we're gonna measure the global loss, we only need inner loop for here because the code loops over all **users** of the data set.
- For the **target-vector**, we dont choose **test-set** for the **input-vector** we use the **train-set**. Because
    - `test_loss` computes the loss on **test-set**. We initialized it to 0.

```
test_loss = 0
cnt = 0.0
for uid in range(nb_users):
    v = Variable(train_set[uid].id).squeeze(0) # input vector from training-set
    vt = Variable(test_set[uid].id).squeeze(0) # target vector from "test-set"
```

The input to our model is, all the ratings of the movies we watched. We are training the **test set** in **input-vector**:

+   - We put this **input vector** into the **AE-network**, the *AE* will look at the ratings of the movies and predict positive ratings and based on these, it will **predict** the ratings of the movies that the user hasn't watched (i.f. ratings that are not present in test-set). That's the prediction.
- Here is the point of using **test-set** as **target-vector** is, it contains the real-ratings of the movies that were not present in **training-set** (we used AE to generate them), so we can compare predicted and real ratings and measure the **test_loss**
- `test_loss` will indicate how our model performs on new data.

For example, if we use our input vector we give five ratings to all the movies we watched, then when we feed this input vector into the network, the *neurons* of the specific features related to action movies, will be activated with a large **weight**: high ratings for the other *action movies* that the user hasn't watched.

And then we, we will compare the **predicted ratings** to the ratings of the **test-set** because the test set contains these ratings that were not **part of the training set**. That is, these action movies that the user hasn't watched yet in the **training set**

```
test_loss = 0
cnt = 0.0
for uid in range(nb_users):
    v = Variable(train_set[uid].id).squeeze(0)
    vt = Variable(test_set[uid].id).squeeze(0)
non_zero_ratings_t = torch.sum(vt.data)
if non_zero_ratings_t > 0:
    t_output = sae(v)
    vt.require_gradient = False
    loss_t = criterion(vt == [0] = [0], t_output, vt)
    mean_corrector_t = nb_movies/float(non_zero_ratings_t + 1e-10)
    cnt += np.sqrt(loss_t.data).mean_corrector_t
cnt += 1.0
```

eval_loss = test_loss/cnt
print(f"Evaluation Loss = {eval_loss}")

+   The predictions happen here: test_output = sae(V). The **AE model** just making one step forward after training.
- Our forward function returns the **vector of predicted ratings** and therefore by calling our object on the input here, we will get our predicted ratings for the movies that the user hasn't watched yet, and this will go into test_output.
- We use `vt.require_gradient = False` to override the computations of the gradient with respect to the **target** because we don't need them.

+   - We don't use `loss.backward()` or `optimizer.step()` either. Because those are for update weight and for training purpose.
