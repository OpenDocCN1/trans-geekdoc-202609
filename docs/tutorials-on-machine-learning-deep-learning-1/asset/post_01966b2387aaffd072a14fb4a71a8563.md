## Model Selection: K-fold Cross Validation, Grid Search

### 11.1 Evaluating & Improving Model Performance

- **Model parameters and Hyper parameters**: In a ML model we have two types of parameters: Model parameters and Hyper parameters.
- **Model parameters**: These are the parameters that the model learns and found optimal values by running the model.
- **Hyper parameters**: This type of parameters are the parameters that we choose ourselves. For example the kernel penalty parameter or even some regularization parameter.

So there is still room to improve the model because we can still choose some optimal values for these parameters. In this chapter we will do two things:

- [1]. **Evaluating our model performance**: To evaluate models in an efficient way, we use K-fold Cross-validation instead of just train-test split. Then to tune Hyper parameters we will use Grid Search.
- [2]. **Improving our model performance**: We'll use the most powerful algorithm in ML, XGBoost.
- **Improving the model performance** can be done with a technique called model selection. That consists of choosing the best parameters of your ML model.
- **Grid Search**: Since the model parameter is learned by the model then we need to figure out a way to choose the optimal values for these Hyper parameters. One of the powerful techniques to tune is Grid Search.
- **K-fold Cross-validation**: We need to optimize a way to evaluate our models before we start grid search. Previously we split the dataset between the training set and a test set. We trained on the training set and we tested its performance on the test set. That's a correct way of evaluating the model performance.
- But that's not the best because we actually have a variance problem.
- The variance problem can be explained by the fact that we have the accuracy on the test set. And if we run the model again and test on another test set, we get a very different accuracy.
- Hence judging our model performance only on one test set is actually not a good idea. That's not the most relevant way to evaluate the model performance.
- **K-fold Cross-validation**: K-fold Cross-validation is a technique that resolves the variance problem by splitting the training set into K-fold.

![](img/0aa092657a6eb1b9f2dd65bbb79055a3_344.png)

# Number of Folds: Most of the time K = 10 and we train a model new fold and test it on the remaining fold.

Number of iterations: Since we have 10 folds, we can make 10 different combinations to train the model. Once we train the model and test on all combinations (10 iterations) of training and test sets, we get 10 different accuracies. We take an average of 10 different accuracies and also compute the standard deviation. This will give us a better idea of our model's performance.

## The Bias-Variance tradeoff

Eventually our analysis will be much more relevant and we'll know which of these categories are:
- Good accuracy (low bias) and small variance - lower left
- Large accuracy and high variance - lower right
- Small accuracy (high bias) & variance - upper left
- Low accuracy and high variance - upper right

![](img/0aa092657a6eb1b9f2dd65bbb79055a3_345.png)

K-fold cross-validation approach divides the input dataset into K groups of equal size. These samples are called folds. For each set, the prediction uses k-folds and the rest of the folds are used for the test set. This approach is popular because it is easy to understand and less biased than other methods.

The steps for k-fold cross-validation are:
1. Split the input dataset into K groups
2. For each group:
    - Take one group as test data
    - Use remaining groups as the training dataset
    - Fit the model on the training set and evaluate the performance using the test set.

Let's take an example of 5-fold cross-validation, so the dataset is grouped into 5 folds. On 1st iteration, the first fold is reserved for the test and used to train the model. On 2nd iteration, the second fold is used to test the model and used to train it. This process will continue until each fold is used for the test.

### 11.2 K-fold cross-validation: Evaluate model performance

Let's start with this K-fold cross-validation, our first technique of model selection. We are going to use one of the models we've built previously and apply k-fold cross-validation on. We use the SVM model from Chapter 3: Classification, where Network_Ads.csv contains information of users from social networking sites to check how many users want to purchase the SUV. Since the model is already built and we have everything, we just copy the code for K-fold cross-validation in a new place.

**Where to apply k-fold cross-validation**: Since that consists of evaluating the model performance, the most relevant location to put it is where we build our SVM model.

**After prediction and confusion matrix**: Getting the predictions of the test results and evaluating the confusion matrix is actually a good way of evaluating our model. Not the best, but we apply K-fold cross-validation. We import `cross_val_score` from `sklearn.model_selection` (the same module used for `train_test_split`).

```python
from sklearn.model_selection import cross_val_score
```

Now we apply k-fold cross-validation on our training set. We get out of `cross_val_score` called `accuracies` (this is actually a vector of accuracies of the model for each one of the 10 combinations created through 10-fold cross-validation (K=10)).

```python
accuracies = cross_val_score(estimator=classifier, X=X_train, y=Y_train, cv=10)
```

**Parameters:**
- **estimator**: The object implementing 'fit' on the data. This is our SVM classifier object, so we set `estimator = classifier`.
- **X**: The data to split. It is our feature matrix of the training sets. So we set `X = X_train`.
- **y**: The target variable (dependent variable vector) to predict in supervised learning. So we set `y = Y_train`.
- **cv**: The cross-validation splitting strategy. It is the number of k-folds. Here we want to apply 10 folds, so we set `cv = 10`.

The most common choice for this CV is actually 10. Most of the time you'll use 10-fold cross-validation where you use 10 accuracies; 10 accuracies is a relevant idea of the model performance.

- **n_jobs (optional)**: Number of jobs to parallel. The estimator (classifier or regressor) and computing the score are parallelized over the cross-validation splits. -1 means 1 unless in parallel backend. It means that you will use all the CPU on your machine and therefore you can run k-fold cross-validation even for a very large dataset.

**Calculating mean of accuracies and standard deviation**: We use `mean()` to return mean, `std()` to return standard deviation.

```python
mean_acc = accuracies.mean()
std_acc = accuracies.std()
```
