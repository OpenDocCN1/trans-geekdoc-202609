# 8.3.1 Why Gradient Descent?

In this section we're talking about **gradient descent**. *We saw in previous section, that an NN learns using back-propagation.* When is, the error/difference or the sum of squared differences between $Y$ and $\hat{Y}$ backpropagated through the neural network and the weights are adjusted? Now how can we learn exactly how these weights are adjusted.

![](bbox=[0.315, 0.217, 0.895, 0.403])

+   - Gradient Descent is kind of similar to some Numerical techniques like Bisection or Regula fisi

Now consider the quite version of a neural work or a PERCEPTRON, a single layer feed-forward NN. We can see here is the whole process in action: we've got some input value, we've got a weight activation function is applied. Then we get predicted value $y$ and we compare it to the actual value $y$, then we calculate the cost function.

![](bbox=[0.115, 0.543, 0.885, 0.703])

Now the question is: **How can we minimize the cost function?**

Well one approach to do it is a Brute Force Approach where we just take all of different possible weights and look at them to see which one looks best.

+   - In this approach we would try out weights, for example: 1000 weights. Then we get something like this:
- For the cost function and this is a chart. On the Y axis we have cost function and on X-axis we have output value $\hat{Y}$. You'd find the *best value* at the *bottom of that curve.*

![](bbox=[0.51, 0.743, 0.885, 0.893])

**Why brute force method is not efficient?** If you have just one weight to optimize this work but as you increase the *number of weights* (i.e. increase the *number of Synapses in your network) you have to face the Curse of Dimensionality.
