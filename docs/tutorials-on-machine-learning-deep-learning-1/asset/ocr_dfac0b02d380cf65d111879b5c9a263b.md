The Stochastic Gradient Descent method helps you to avoid the problem with local extrema or local minima. It helps to find minima

And the reason is that SGD STOCHASTIC GRADIENT DESCENT method has much higher fluctuations, because it is one iteration at a time and the fluctuations are higher and it is much more likely to find the global minimum rather than just the local.

SGD is faster than SGD: Stochastic Gradient Descent has more advantages over the Batch Gradient descent.
At the first impression you might think that Batch Gradient Descent is faster because it's doing all once at a time. In reality Stochastic Gradient Descent is faster because it doesn't have to load all the data into memory and wait until all of those rows are on regulate.

+   - The main advantage is that SGD is a Deterministic algorithm but SGD being a Stochastic algorithm (meaning it is random).
- With SGD as long as you have the same weights for your NN. Every time you run, you will get the same iterations to update weights.
- For SGD you won't get that because it is, in a stochastic manner you're picking rows at random and you are updating your NN in a stochastic manner. SGD even if you have the same at the start you're going to have different iterations to get them.

# 8.3.6 Mini Batch Gradient Descent

There's a method in-between BGD and SGD it is the Mini Batch Gradient Descent (mini BGD) method. Where you are running smaller batches of rows than running batch at once.

+   - From your dataset, all the rows, you set batch size (number of rows). You divide all the rows into groups and you run it through each epoch and update the weight.

And that's the Mini Batch Gradient Descent method if you'd like to learn more about gradient
