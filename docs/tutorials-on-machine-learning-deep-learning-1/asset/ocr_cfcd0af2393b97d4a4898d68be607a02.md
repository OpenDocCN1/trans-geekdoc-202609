In this dataset we can have two categorical variables, country and purchase. These two are categorical variables because they contain categories.

Here are the counts for these variables. France Spain and Germany. And the purchase variable contains two types. Yes and No that's why they're called categorical

But ML models work with numbers, so we need to encode these categories into numerical values. Since machine learning models are based on mathematical equations you can intuitively understand that it would cause some problem if we keep the text and the categorical purchase variable as they are we would only need numbers in the equations.

So why we need to encode the categorical variables. That is to encode the text that we have into numbers.

But for more than two categories, "LabelEncoder" returns 0, 1, 2, 3.... This can cause error. For example country is encoded in 0, 1, 2.

Problem: If there is unwanted numerical-orders. France is 0, Spain is 2 and Germany is 1. But there is no relationship between these three countries France Germany Spain.

So we want to have such an interpretation because that could cause some misinterpreted correlations between the features and the outcome we want to predict

DUMMY-Encoding use OneHotEncoder Dummy variables: Don't use LabelEncoder to transform categorical into numerical, just use OneHotEncoder

Using LabelEncoder introduces a problem of ordering, when your categorical data gets encoded into it's 1,2,3 etc and for this model is a clear 1 < 2 , however in reality with categorical features this is not true. For this reason we need three dummy variables for these categories. 1 represents the occurrence of the country in a row.

So country into three columns, because there are three different countries in this country you know three different countries (countries).

If there are example five countries here we would turn this into five columns and OneHotEncoder consists of creating binary vectors for each of the countries.
