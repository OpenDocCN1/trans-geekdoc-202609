NOTES:

**Brute-Force Search**: In computer science, Brute-Force search or Exhaustive search, also known as Generate And Test, is a very general problem-solving technique and algorithmic paradigm that consists of systematically enumerating all possible candidates for the solution and checking whether each candidate satisfies the problem's statement.

**Brute-Force Algorithms** are exactly what they sound like - methods of solving a problem that rely on sheer computing power and trying every possible rather than advanced techniques to improve efficiency.

For example, imagine you have a small padlock with 4 digits, from 0-9. You forget your combination, but you don't want to buy another padlock. You can remember any of them unless you use a brute-force method to open the lock.

So you set all the numbers back to 0 and then increase by one: 0001, 0002, 0003, and so on until it opens. In the worst case scenario it would take 10!, or 10,000 times to find your combination.

A classic example in computer science is the Traveling Salesman Problem (TSP). Suppose a salesman needs to visit 10 cities across the country. How does one determine the order in which those cities should be visited such that the total distance traveled is minimized?

The brute force is simply to calculate the total distance for every possible route and then find the shortest one. This is not particularly efficient because it is possible to eliminate many routes through clever algorithms.

## 8.3.2 Gradient Descent

It is called gradient descent because we calculate the Gradient every-time and check if it is descending.

- Here is our cost function, and now we are seeing how we can find our best value faster.
- Lets say we start somewhere in the top left, we are going to look at the angle of the tangent drawn at point of our cost function then we calculate the gradient (you have to differentiate).
- You just need to differentiate to find out the slope is in that specific point and find out if the slope is positive or negative.
- If the slope is negative (like in this case), means you're going downhill (so the right is downhill to the left) [sic] uphill, so you need to go right i.e. you need to go downhill (find the best/optimal point). Something like "Finding global minima".
- Lets say we go to right, and again we calculate the gradient and find the slope is positive. That means we need to go left.

- **Non-CONVEX cost-function**: But the problem is, this method requires the cost function to be convex which has only one global minima. What if our cost-function is not CONVEX? What if it looks like this:

![](img/0aa092657a6eb1b9f2dd65bbb79055a3_240_2.png)

This could happen:
- If we choose a cost function which is not the square difference between Y and y. If we choose the cost function as square difference between Y and y but in a multi dimensional space it can actually turn into something that is not convex.

**The local-minima trap**: In these cases if we apply our normal gradient descent method we end up something like following. Which is not the global minima, we'll end up with the local-minima. The best value is the Global-minima.

![](img/0aa092657a6eb1b9f2dd65bbb79055a3_241_0.png)

We could find a local minimum of the cost function rather than the global one.

- **Global-minima** is the best one and we found the wrong one (Local-minimal) and therefore we don't have the correct weight. As a result we failed to find an optimized neural network.

## So how to avoid this trap?

The solution is **Stochastic Gradient descent**. Stochastic gradient descent doesn't require the Cost-function to be convex. Let's have a look at the differences between the normal Gradient Descent and the stochastic gradient descent.

- **Batch Selection in normal gradient descent**: In normal Gradient Descent all of our rows plug into our neural network all at once.

- **Stochastic Gradient Descent**: The stochastic gradient descent method is a bit different. Here we take the rows one by one. We take that row, we use our NN and then adjust the weights.

Then we move to the second row we run our NN again, then adjusted the weights again. Then we move to 3rd row. And so on.

So basically we're adjusting the weights after every single row rather than doing everything at once.
