## 2 LITERATURE SURVEY

Agrawal et al. [17] propose a three-layer design for clients, fog, and cloud and an algorithm to divide processing between fog and cloud. The algorithm determines if the fog node has enough capacity to complete tasks or send to the cloud. It assumes each node in fog and cloud has a manager to oversee collaborations and performance, doesn't fully show execution of dispersed activities.

Aazam & Huh [27] propose a single model for resource management in fog computing using resource development and allocation. It is a solid baseline for IoT and fog computing research and development to adaptative cloud service providers.

Sklart et al. [26] propose a framework for fog resource supply to reduce delays in sensitive computing by formalizing the incentive mechanism. The framework was compared with various models and found to be useful.

Bittencourt et al. [16] propose a resource migration architecture for virtual machine (VM) migration across fog nodes (FN). The objective is to provide management tools for fog operation while maintaining QoS and accuracy of VMs during user movement. The VM includes data and application functions, however heavy load from multiple migrations to the FN is not addressed.

Abedin et al. [19] propose an algorithm that promotes resource sharing among fogs. They define an efficiency measure for fog nodes to consider consideration benefits when sharing resources and use a list of preferred fog node pairings. A node sends a request to its preferred partner and decision to accept or deny is based on preferences and approaches. However, the algorithm has a limitation of only considering communication and not QoS like latency and bandwidth.

Gao et al. [20] propose a hybrid data distribution paradigm using software-defined networks and DTN. The approach follows the FG approach by dividing it into two planes, with fog servers as a data plane using DTN and a control plane for analysing content and managing data flows. The paradigm includes regular cloud and fog server data dissemination, as well as additional low-cost delay-tolerant data dissemination from cloud servers, mobile users, and fog servers.

Peter [28] discussed the real-time uses of fog computing, showing how it manages amounts of IoT data, solves latency and congestion problems, and forms new business models and opportunities by handling the dispersed and dynamic nature of growing IoT infrastructures at the network edge.

Chiang and Zhang [29] reviewed the integration of fog and IoT, discussing challenges in IoT development for new computing, storage and networking architecture. They examined the benefits and potential solutions offered by the fog architecture for IoT problems.

### 3.2 Simulation and evaluation

This section describes the simulation of proposed offloading for a healthcare monitoring system. The scenario involves a smart wearable, fog nodes distributed in hospital departments, and a data center. The fog nodes collect realtime data and perform simple calculations, while the cloud handles processing and storage. Multiple fog nodes are distributed for backup and load distribution.
