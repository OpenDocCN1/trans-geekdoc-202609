# 3.4 Data preprocessing

All categorical attributes were encoded using the ScikitLearn categorical encoder. After this, standard scaling was performed on all attributes, again using ScikitLearn to ensure no numerical biases exist in the dataset [5]. Since location, Restaurant Type, and cuisines seemed to be the most important attributes, these attributes were weighted to the powers of 3, 2, and 3 respectively.

# 3.5 Data modelling

This project uses the data mining algorithm called Apriori to extract frequent itemsets. We also used two machine learning algorithms, both of which are clustering algorithms to generate models [6].

# 3.6 Apriori algorithm

Apriori is an algorithm used to find frequent itemsets and learn association rules over a transactional database. Since the Apriori algorithm is intended for on transactional data, we selected two candidate attributes of the dataset, 'dish_liked' and 'cuisines', to apply the algorithm. The 'dish_liked' column contains a comma-separated list of popular dishes for each restaurant, aggregated based on user reviews on Zomato. Such as Chinese, South Indian, and Italian [7]. We extracted the last word of each dish (e.g: 'Pasta' from 'Afredo Pasta') to prune the number of possible items for easier computation. This resulted in a transactional database with 747 different dishes. For cuisines, we didn't need to limit the number of items as there were only 20 different cuisine labels. The item lists were stacked and transformed into a one-hot encoded matrix of items, for both the dishes and cuisines.

# 3.6.1 Frequent itemset generation

We experimented with different values of min_sup (minimum support) for the dishes attribute, but finally min_sup = 0.05 (5% of the transactions) to get a representative sample of 30 'dishes_liked' itemsets. For 'cuisines' we chose a min_sup of 0.01 and got 15 frequent itemsets, including 1-sets, four 2-sets, and one 3-set (North Indian, Chinese, South Indian) are represented in Figure 2.
