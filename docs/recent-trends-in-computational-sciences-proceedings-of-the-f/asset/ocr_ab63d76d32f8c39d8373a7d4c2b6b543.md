# 3.1 Workflow of proposed system

In the proposed blockchain-based OPTB, the transaction happens in two phases-Registration phase and the Allocation phase. During the registration phase, patients who are suffering from end-stage disease and require an organ (kidney) will be registered using a system application, any of the transplant organizations. The applications of transplant organizations can access the ledger using smart contracts. The transactions will be generated by the agreed enforcement policies of the organizations, which are then written onto the ledger. The registration process automatically triggers the waiting list position determination algorithm. The priority number of the new patient registered to the transplantation organization. The algorithm also updates the waiting list position of all the patients who are part of the waiting list on a need basis. The updated waiting list is shared across the transplantation organization along with the reason for the update. Ledger will be updated for each of these transactions. The priority number of the new registrant is taken into consideration and agreed by the organizations. In the second phase, which is the allocation phase, when the organ is available from a brain-dead patient, the procurement organization registers the available organ details in the OPTB system, using a system application. The donor_Id is returned by the OPTM manager. The system will automatically call the organ allocation to all the transplantation organizations which return the identified recipients.
