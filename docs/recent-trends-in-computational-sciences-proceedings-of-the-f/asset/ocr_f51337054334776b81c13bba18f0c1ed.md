# 5.1 Application layer

Smart contracts make up the application layer. The application layer can be further broken down into the execution layer and the application layer. The applications in the application layer are end users utilize to communicate with the blockchain network. It consists of user interfaces, frameworks, APIs, and scripts. The blockchain network serves as the backend for various applications, which frequently communicate with APIs. The sub layer known as the execution layer is made of compile, smart contracts, and underlying rules. The actual code and rules that are executed are located in this sub layer.

A transaction is validated and executed at the semantic event though it propagates from the application layer to the execution layer (smart contracts and rules). Applications send the command to the execution layer, or chaincode in the Hyperledger fabric, which carries out transactions and upholds the consensus of the blockchain (such as permitted blockchain like hyperledger fabric). Contract layer consists of contracts, which is a certain type job to do. Smart contracts cannot be changed. Written in Solidity, smart contracts for the Ethereum runtime are syntactically correct a compiler is required. The bytecode is executes and more quickly on EVM because it has been compiled. Code running on EVM is completely isolated and does not interact with the disc or network in any way.

Smart contract: A code that contains business logic is located on the EVM and recognized by a special address. When a transaction is made against one of the functions of a smart contract, those functions are executed. A transaction may cause a change in the status of a smart contract, depending on logic. To create a smart contract, developers can use a special compiler to turn their code into bytecodes, which can be uploaded to a blockchain. A distinct address is given to the smart contract once it has been implemented. On the blockchain, any user has the ability to carry out a transaction against that smart contract. # 5.2 Transaction layer

The transaction layer stores transactions that occur in the application layer and the contract layer, and the information in the transaction layer is accessible to the other layers.

The things that give a blockchain purpose are transactions. They are a blockchain system's finest building blocks. An address for the recipient, an address for the sender, and a value make up most transactions. This isn't all unlike from a typical transaction you could see on a credit card bill.
