We will present the methodology for using measurements of low-cost sensors (BH1750 and UV) to estimate the values of solar radiation, which would otherwise be measured with a much more expensive pyranometer.

The network is developed on the experience of designing and prototyping IoT and smart technology systems [9-12]. The network was designed as a model for working environment monitoring in smart manufacturing systems [9] developed around Wemos D1 R2 and NodeMCU platforms. The sensor network is built partially by the experience of learning the platform for Smart City Application [10] with Wemos D1 R2 and NodeMCU platforms. Both platforms use the MQTT protocol for data transfer. The authors' experiences in developing solutions based on Arduino MEGA and LoRa technology in the urban traffic noise monitoring system [11] and investigation of long-range LoRa technology [12] also influenced the design of the preset system.

One additional aspect of edge computing architecture is certainly very important. The IoT security issues are addressed in [13]. The authors reviewed the edge-based IoT security research efforts analyzing the security architecture, distributed firewalls, intrusion detection systems, authentication and authorization algorithms, and preserving mechanisms. The strengths and weaknesses of the presented designs are discussed.

The paper [14] examines and describes security issues in a generic IoT architecture. This paper presents the main communication protocols that are used in the application, transport, network and physical layer; and describes security threats in IoT and edge computing devices and possible solutions in IoT edge security.

Although the security of edge computing devices and the presented sensor network is equally important, security is not considered in this research phase. The reason is the purpose of the sensor network, which is primarily designed for solar data acquisition and for usage in teaching and academic research, and therefore estimated as a system without high-security risks.

## 6 THE APPROACH OF IMPLEMENTATION IN AI EDGE DEVICES

The reason for implementing AI in edge devices in the presented sensor network is to estimate solar radiation without deploying very expensive pyranometers. For example, the research effort is made to estimate solar radiation based on the measured light intensity with low-cost BH1750 and UV sensors. In this example, the AI method is based on k-NN (k-Nearest Neighbor) algorithm, k-nearest neighbors' algorithm (k-NN) is a non-parametric supervised learning method developed by Evelyn Fix and Joseph Hodges (in 1951) and expanded by Thomas Cover. The approach of using k-NN in edge computing is investigated in [15,16]. For this implementation, the modified code [17] is used together with the experiment implementing AI techniques in data analyses [18,19].

The proposed methodology for implementing AI consists of the following steps. The first step is the solar radiation data collection with the wireless sensor nodes, including the pyrometer (1). The second step is analyzing and collecting results (2). The third and fourth steps are a generation of the inputs (training data) for k-NN Arduino code and processing results (5). The input generation is performed externally on a PC running GNU Matlab. The sixth step is building Arduino code to generate k-NN data and collected data processing of BH11750 and UV sensor measurements will be compared with the measured values (7). In the case of low accuracy (8), the process will be turned back to step 2. The process should be repeated until the high accuracy can be reached.

This research first considers the performance of Arduino UNO, MEGA, ESP8266 and ESP32 development boards. The test measures consider the capacity of 6 Arduino clone boards with a maximum number of inputs (training data) for k-NN classification. The time of loading inputs in milliseconds is additionally logged. The results of the tests are in Table 2. The test showed that Arduino UNO could deal with a limited number of inputs (25), while Arduino boards with integrated ESP32 and ESP8266 processors support a much higher number of inputs, reaching up to 900, the ESP8266-based Wemos D12 and NodeMCU boards supporting up to 1,000 inputs. The time needed for loading a response from less than 1 millisecond to 1100 milliseconds for 1000 inputs on ESP8266-based boards.
