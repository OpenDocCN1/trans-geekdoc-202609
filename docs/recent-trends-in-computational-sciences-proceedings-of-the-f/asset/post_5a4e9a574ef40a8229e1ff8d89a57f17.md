
## METHODOLOGY

Used an unsupervised learning approach to cluster restaurants that are similar and recommend to users using the ones they have ordered from the past.

### 3.1 Data

Zomato's catalog of restaurants is one of India's biggest delivery services. The dataset has been restricted to restaurants within Bangalore as the volume of data obtained from India is enormous. We obtained the dataset from Kaggle, a popular platform for hosting and exploring datasets as well as building models, publishing interesting findings, and learning about Machine Learning. There are 51,717 entries and 17 attributes for each restaurant. Redundant attributes have been removed. After removing duplicate entries and entries with null values, the number of entries left 51,042. The attributes were also renamed to online_order, book_table, rate, votes, location, rest_type, cuisines, and cost.

### 3.5 Apriori algorithm

Apriori is an algorithm used to find frequent itemsets and learn association rules over a transactional database. Since the Apriori algorithm is intended for transactional data, we selected two candidate attributes, 'dish_liked' and 'cuisines', to apply the algorithm. The 'dish_liked' column contains a comma-separated list of popular dishes for each restaurant aggregated based on user reviews on Zomato. Such as Chinese, South Indian, and Italian, we extracted the last word of each dish (e.g., 'Pasta') to prune the number of possible items for easier computation. This resulted in a transactional database with 74 different dishes. For cuisines, we didn't need to limit the number of items as there were only 20 different labels. The item lists were stacked and transformed into a one-hot encoded matrix of items for both the dishes and cuisines.

#### 3.6.1 Frequent itemset generation

For 'cuisines' we chose a min_sup of 0.01 and got 15 frequent itemsets, including 1-sets, four 2-sets, and one 3-set (North Indian, Chinese, South Indian) represented in Figure 2.

#### 3.6.2 Association rule mining

We then mine association rules, a rule-based machine learning method for discovering relationships between items in transactional databases [8]. We used the metric of ‘confidence’ to filter out our association rules.

- Rule: X ⇒ Y (i)
- Support: (Frequency (X, Y))/N (ii)
- Confidence: (Frequency (X, Y))/(Frequency(X)) (iii)

The highest confidence rule was (Pasta) -> Pizza, with a confidence of 0.51, closely followed by (Pizza) -> (Pasta) with a confidence of 0.483.

The association rules of (North India, South India) -> (Chinese) and (Chinese, South Indian) -> (North Indian) signify a common trend in many restaurants in Bangalore, to serve snacks/meals from all three cuisines simultaneously. Therefore, if any of the three cuisines are present, there is a high chance that dishes of the third cuisine will also be served in Figure 3.

### 3.16 DBSCAN

DBSCAN stands for Density-Based Spatial Clustering of Applications with Noise. It is used to cluster points that are densely packed and those lying low-density regions are marked as outliers. The advantage of using DBSCAN is that it does not require the user to specify the number of clusters.

### 3.17 DBSCAN parameters

DBSCAN has two main parameters: epsilon and minsamples. Epsilon is the maximum distance between two samples for one to be considered in the neighborhood of the other. Minsamples is the minimum number of samples in a neighborhood for a point to be considered a core point.

### 3.18 DBSCAN implementation

We used DBSCAN to cluster the Zomato dataset. We chose epsilon = 0.5 and minsamples = 5. This resulted in 3 clusters.
