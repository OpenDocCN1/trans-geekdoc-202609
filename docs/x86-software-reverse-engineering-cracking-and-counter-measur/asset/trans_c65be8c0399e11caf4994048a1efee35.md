### IDA: 路径

IDA 展示三种基本块之间的路径类型：

*   **红色**：当条件跳转未被取时的路径

*   **绿色**：当条件跳转被取时的路径

*   **蓝色**：无条件路径（不含条件）

例如，考虑以下包含简单 `if` 语句的代码示例：

```
int main(int argc, char* argv[])
{
       if (argc> 1)
              return 0;
 
       return argc;
}
```

[Figure 11.29](#c11.xhtml#c11-fig-0029) 展示了这段代码在 IDA 中的表现。条件块之后，路径分叉。虽然本书中不显示颜色，但左侧路径（在 IDA 中为红色）表示跳转未被取时的情况。右侧路径（在 IDA 中为绿色）在条件为假时被遵循。

![Figure 11.29: IDA 中的代码路径](images/c11f029.png)

[**Figure 11.29**](#c11.xhtml#R_c11-fig-0029): IDA 中的代码路径

在此之后，若干箭头指示基本块之间的转换。由于这些转换均不涉及条件，它们在 IDA 中全部显示为蓝色。

## IDA 修补

IDA 也是一款可用于修补可执行文件的工具。以下是一个示例代码：

```
printf("please enter the password\n");
scanf("%s", user_entered_password);
if (strcmp(user_entered_password, correct_password) == 0)
{
       printf("SUCCESS\n");
}
else
{
       printf("Failure\n");
}
```

这段代码实现了一个简单的身份验证系统。它提示用户输入密码，并检查答案。如果答案正确，则打印 `SUCCESS`；否则，打印 `Failure`。虽然这是一个简化的例子，但请记住，检查密码并根据结果走不同路径的流程在实际中非常常见。在 IDA 中，你可以修补应用程序以绕过密码验证。

默认情况下，IDA 不会在图形视图中显示机器码。除非你在进行修补，否则它没有太大用处。但当你开始想要修补时，你会希望看到机器码。要显示机器码，请选择“选项 ➪ 一般”，打开如 [Figure 11.30](#c11.xhtml#c11-fig-0030) 所示的窗口。然后，指定在图形视图中显示的字节数（大多数指令不超过 8 字节，因此建议将其设置为 8）。

[Figure 11.31](#c11.xhtml#c11-fig-0031) 展示了 IDA 中密码检查逻辑的实现。如所示，左侧（红色）路径在密码匹配时被取，而右侧（绿色）路径在密码不匹配时被取。

决定哪条路径取决于指令 `jnz`。请记住，`jnz` 代表 “跳转如果不为零”。

绕过密码检查有几种方式。一种是弄清楚需要使其 “不为零” 的内容，即找出它比较的两个值，从而可能生成有效的密钥或破解工具。

更简单的替代方案是利用 x86 知识对应用程序进行修补。目前，应用程序在密码错误时执行 `jnz`（`0x75`），但如果你正好相反操作呢？将 `jnz` 改为 `jz`（`0x74`）会逆转逻辑，导致错误的密码被视为成功，正确的密码被视为失败。

![Figure 11.30: 在 IDA 中显示字节](images/c11f030.png)

[**Figure 11.30**](#c11.xhtml#R_c11-fig-0030): 在 IDA 中显示字节

![Figure 11.31: IDA 中的密码检查代码](images/c11f031.png)

[**Figure 11.31**](#c11.xhtml#R_c11-fig-0031): IDA 中的密码检查代码

要修改指令，请选中它，然后选择“编辑 ➪ 修补程序 ➪ 修改字节”。在如 [Figure 11.32](#c11.xhtml#c11-fig-0032) 所示的 “修补字节” 窗口中，将第一个值从 74 更改为 75。

[Figure 11.33](#c11.xhtml#c11-fig-0033) 展示修补应用后的效果。已更改的那一位在 IDA 中会被高亮显示，且跳转后的两条路径含义相反。现在，应用程序将对除正确密码以外的所有输入都视为成功。
