
由于空间和时间限制，在本书中不可能探索所有这些调试器。选择 Immunity 是因为它在逆向工程和 exploit 开发中很受欢迎。但请记住，所有这些调试器都有相似的功能，在一个调试器中学到的技能通常可以转移到其他调试器中。

要选择一行代码，点击它。选中一行后，Immunity 会提供各种快捷键，包括以下：

*   **;**：为选中的行添加注释。这是逆向工程的最重要部分，它帮助你跟踪工作进度。

*   **ctrl-a**：自动分析程序。Immunity 可以很好地添加注释并猜测函数参数。

*   **<enter>**：跳转到选中的函数。例如，如果你看到汇编中的 `call 0x1234`，并想知道 0x1234 处的函数的作用。

*   **-**：返回到上一个位置。例如，分析完函数 0x1234 后，想要返回到之前的位置。

*   **+**：跳转到下一个位置（在按 **-** 之后）。例如，你已经用 **-** 返回到调用函数，然后想要返回到函数 0x1234。

*   **ctrl-r**：查找选中行的交叉引用。例如，在内存转储窗口中选中一个字符串，想知道谁使用这个字符串；或者在汇编中选中函数顶部，想知道谁调用该函数。

*   **双击地址**：在该地址设置调试断点。

### Immunity: Modules

在 Immunity 中，按 **e** 按钮可以加载可执行模块列表。这显示了你可以调试的所有代码，包括动态加载的库，如 [Figure 10.24](#c10.xhtml#c10-fig-0024) 所示。加载列表后，双击模块可以跳转到该代码。

启动 Immunity 时，查看正在查看的模块，通过检查 **`eip`** 寄存器。几乎总是希望先调试主可执行文件，而不是像 `ntdll` 这样的共享库。你可以使用模块窗口切换到主可执行文件。

### Immunity: Strings

要找出哪段代码使用了特定的字符串，通常很有用。要找出程序使用的所有字符串，右键单击并选择 **Search For ➪ All Referenced Text Strings**，如 [Figure 10.25](#c10.xhtml#c10-fig-0025) 所示。

在字符串窗口中，右键单击并选择 **Search For Text** 来查找特定字符串，如 [Figure 10.26](#c10.xhtml#c10-fig-0026) 所示。然后，右键单击并选择 **Search For Next** 来查找该字符串的下一个引用。你可以双击字符串的地址，跳转到它在汇编中使用的位置。

### Immunity: Exceptions

许多应用程序在正常执行过程中会产生异常。例如，`try {} except {}` 块如果 `try` 块中出错，就会产生异常。作为调试器，像 Immunity 这样的动态分析工具通常会先拦截异常，看看你是否要对其做点什么。

但对于逆向工程，你通常不想干扰正常执行。相反，你希望让应用程序像往常一样处理异常。这意味着你几乎总是希望将异常从调试器传递给应用程序。

如 [Figure 10.30](#c10.xhtml#c10-fig-0030) 所示，异常在 Immunity 窗口的底部报告，但每个调试器略有不同。在 Immunity 中，按 **Shift+F9** 可以传递异常并继续执行。

### Immunity: REwriting the Program

Immunity 具有许多特性，有助于开发软件补丁以修改程序行为。对于软件破解，这包括修改程序以移除关键检查、水印等。

在你的第一次破解中，你会使用“`nop`ing”代码的过程来移除它。这涉及将程序指令替换为 `nop` 指令。

在 Immunity 中，首先选择要移除的指令。然后，右键单击并选择 **Binary ➪ Fill With NOPs**，如 [Figure 10.31](#c10.xhtml#c10-fig-0031) 所示。

这将把选中的指令替换为一系列 `nop`，如 [Figure 10.32](#c10.xhtml#c10-fig-0032) 所示。

![Figure 10.31: noping out code in Immunity debugger](images/c10f031.png)

[**Figure 10.31**](#c10.xhtml#R_c10-fig-0031): `nop`ing out code in Immunity debugger

![Figure 10.32: noped code in Immunity debugger](images/c10f032.png)

[**Figure 10.32**](#c10.xhtml#R_c10-fig-0032): `nop`ed code in Immunity debugger

修改程序后，通过重新运行程序来测试补丁。如果你正确补丁了代码部分，应该能发现水印（关键检查等）消失。

如果补丁导致崩溃或未能移除目标，你可以轻松回滚更改并再次尝试。为此，点击 **patch** 按钮打开补丁窗口。然后，右键单击你的补丁，选择 **Restore Original Code**，如 [Figure 10.33](#c10.xhtml#c10-fig-0033) 所示，恢复原始代码，再尝试。
