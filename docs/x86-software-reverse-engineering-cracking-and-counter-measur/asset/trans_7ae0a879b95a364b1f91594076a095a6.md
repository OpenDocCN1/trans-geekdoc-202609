### 编译器

编译器将代码翻译成处理器可以读取的机器代码。编译器可以通过各种方式（有意或无意）影响反向工程。本节关注无意的改动；有意的技巧如混淆将在 [第 12 章](#c12.xhtml) “Defense”中讨论。

#### 优化

编译器可以根据多种指标（如速度、磁盘空间或不优化）配置优化代码。优化程度会导致代码呈现出截然不同的形式。

考虑以下代码示例，它实现了一个带两个条件的简单 `if` 语句。

```
int main(int argc, char* argv[])
{
       if (argc>= 3 && argc <= 8)
       {
             printf("valid number of args\n");
       }
}
```

[Figure 8.4](#c08.xhtml#c08-fig-0004) 显示在未优化编译时的反编译器（更多内容见 [第 11 章](#c11.xhtml) “Patching and Advanced Tooling”，无需担心）中显示的代码。可以清楚看到对两个条件的比较（与 2 和 8 的值比较）在代码中。

![Figure 8.4: 未优化代码 in 反编译器](images/c08f004.png)

[**Figure 8.4**](#c08.xhtml#R_c08-fig-0004): 未优化代码 in 反编译器

[Figure 8.5](#c08.xhtml#c08-fig-0005) 展示了以速度和空间为优化目标的同一代码。与 2 和 8 的比较不再可见，代码不再像包含两个条件的 `if` 语句。

[Figure 8.6](#c08.xhtml#c08-fig-0006) 展示了仅基于磁盘空间进行优化的代码。同样，两个比较也缺失。

仔细观察代码，你会发现它检查 `(argc-3) > 5`。如果 `argc < 3`，则减法会导致下溢，使 `eax` 中的值变为一个大的正数。如果 `argc > 8`，则 `argc-3 > 5`。在这两种情况下，结果都大于 5，因此优化后的判断等价于原始检查。编译器优化使逻辑等价，但会让代码更难阅读和分析。

大多数编译器提供设置优化级别的选项。学习阶段，如果你在逆向分析自己编写的应用时遇到困难，可以尝试在编译时关闭优化。相反，如果你希望让代码更难以逆向，编译器优化是实现此目的的简便且有效的方法。

#### 去符号（Stripping）

*去符号*（stripping）二进制文件意味着移除所有运行代码所不需要的信息，包括符号表。未去符号的二进制文件保留符号表，而去符号的二进制文件则不保留。

符号对于调试应用非常有用。例如，考虑以下代码：

```
// Declare an external function
extern double bar(double x);
 
// Define a public function
double foo(int count)
{
       double sum = 0.0;
 
       // Sum all the values bar(1) to bar(count)
       for (int i = 1; i <= count; i++)
             sum += bar((double) i);
       return sum; 
}
```

![Figure 8.6: 空间优化代码 in 反编译器](images/c08f006.png)

[**Figure 8.6**](#c08.xhtml#R_c08-fig-0006): 空间优化代码 in 反编译器

如果此代码被编译器处理，它至少会包含 [Figure 8.7](#c08.xhtml#c08-fig-0007) 中所示的符号表条目。符号在调试时极其有用，微软允许你下载其应用的符号以便排查问题！这些额外信息对于理解应用的意图非常有价值。

![Figure 8.7: 应用调试符号](images/c08f007.png)

[**Figure 8.7**](#c08.xhtml#R_c08-fig-0007): 应用调试符号

如果文件被去符号化，打开 `gdb` 时会显示“无调试符号”[Figure 8.1](#c08.xhtml#c08-fig-0001)。这类文件极难逆向工程。

符号可以通过多种方式从应用中去除。一种方式是使用编译器参数，如 `gcc –fno-rtti –s`。另一种方式是使用后期去符号工具，如 Linux 中的 `strip`。

符号使攻击者更容易逆向工程应用，因为它们有助于定位感兴趣区域并理解变量的意图。但也有合法理由保留符号。例如，符号有助于生成崩溃报告和错误日志，并支持合法调试以修复客户端错误。学习阶段，如果你编写自己的代码并编译以练习，请确保保留符号。随着技能提升，再去除符号。在逆向别人的代码时，几乎可以肯定不会发现保留了符号，但偶尔会发生！

### 链接

应用很少是孤立开发的。更常见的是包含提供核心功能的库（如通信、日志、绘图等）。编译使用库的应用时，有两种链接方式：静态链接或动态链接。每种方式都有其优缺点，从软件破解的角度来看亦是如此。

#### 静态链接

静态链接将库直接嵌入应用本身。这提高了执行速度，因为库函数的目标地址在编译时即被固定。静态链接的应用更具可移植性，因为依赖环境的库较少。

然而，静态链接也有缺点。静态链接的应用体积更大，因为即使只使用库中的一个函数，整个库也会被嵌入可执行文件。此外，库更新需要重新编译使用该库的应用。

静态链接导致的文件膨胀可能非常显著。例如，如 [Figure 8.8](#c08.xhtml#c08-fig-0008) 所示，即使是一个简单的“一行 hello world”程序也会链接数十个库。
