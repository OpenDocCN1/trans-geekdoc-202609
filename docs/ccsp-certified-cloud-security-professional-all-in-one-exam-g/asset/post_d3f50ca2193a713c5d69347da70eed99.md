
## CCSP Certified Cloud Security Professional All-in-One Exam Guide

### Backup and Restore Host Configuration

With any kind of data on any system, configuration data is extremely valuable and should be an integral part of any backup and recovery operations. This is area where it is imperative to closely follow the recommendations of hardware vendors. For backups to work optimally with physical devices, need to expose APIs or services to allow for backup systems to capture any time this is exposed to services, a thorough understanding of what can be exposed as well as how it will be secured is essential from hardware vendor. Depending on the cloud service model, exposure of configuration data may also be negotiated between customer and cloud provider. This will always be clearly defined as expectations for any data as well as ensuring that systems are appropriately secured and isolated from other tenants.

### Implementation of Network Security

Much like with traditional data center, network security for cloud data center is also based on layered security and defense-in-depth principles. This is done through the use of variety technologies covering appliances and software implementations.

### Firewalls

Firewalls control the flow of traffic in and out of networks based on rules configured on them. connect between a single IP address, a VLAN, or range of IP addresses. They can be either hardware or software implementations, depending on the needs and capabilities of the environment. Regardless of whether server is physical or virtualized, software-based firewalls operate the same manner as hardware-based device. While host-based firewalls accomplish a high degree of protection, they are not ideal compared to external firewalls. Having firewall running on host will add additional load to host and consume resources that would otherwise be reserved for the application. From a security perspective, you also run risk of compromised host allowing the attacker to disable or alter firewall running on host. Firewalls control traffic flow between trusted and untrusted networks. By having firewall independent from the host, a compromised host cannot be exposed further without segregation.

### IDS (Intrusion Detection System)

An IDS is designed to analyze network packets, compare their contents against a set of configurations and alert personnel if anything is detected that could constitute a threat or otherwise designated for alerting. With deep analysis of network packets, an IDS can detect and alert against a much broader range of threats than firewall, which is simply looking at the origin, destination, protocol, and port of traffic. One of the biggest challenges with IDS is that it can often generate a high number of false positives. This can be reduced to a certain extent with continual process of evaluation and tuning, but this also adds staff resources and requirements. Because of the packet analysis depth that an IDS is capable of, it can in some circumstances be used to assist in troubleshooting network problems. IDS systems are either hosted or network.

### HIDS (Host Intrusion Detection Systems)

An HIDS runs on a single host and only analyzes traffic for that host—both inbound and outbound. Apart from network traffic, HIDS system will typically monitor critical files for modification. This is especially important and valuable on production systems where changes will be minimal and should only occur through a rigorous change process. Essentially, any file modifications detected by HIDS should be reactive and known to administrators before alerts are received. The main drawback of HIDS is like other devices similar to host-based firewalls: if the machine itself is compromised in a way that an attack has achieved administrative control over the system, there is nothing to prevent the attacker from disabling the HIDS or alerting. A common approach to combating this possibility is to have the signatures and configurations for HIDS on either read-only storage or accessed from an external system or memory. The logs from HIDS should also be configured to be immediately sent to the individual host and to a log collector or SIEM system to detect any anomalies or prevent the logs from being altered by an attacker in an attempt to remove traces of their attack from the system.

### NIDS (Network Intrusion Detection Systems)

Whereas a NIDS is dedicated to a single host and does analysis of packets for that host, NIDSs are placed at various points in a network and analyze all network traffic looking for the same types of threats. At this level, a NIDS can watch many systems and alert personnel based on potential threats and attack attempts. If analysis is focused on each host, looking from a holistic network can see the size and breadth of such attempts. The biggest challenge with NIDS is the size of the network and the high volume of traffic that flows through them. Typically, they will be placed around strategic assets or specific subnets with high-value data on them rather than trying to monitor an entire network as a whole. However, with small implementations or where necessary by regulation or policy, larger-scale and more comprehensive monitoring can be employed.

> EXAM TIP Make sure to remember both NIDS and HIDS approaches and what the acronym stands for. Also, study the key challenges and benefits of both compared to the other.

### IPS (Intrusion Prevention System)

An IPS works in the same way as an IDS, with the major stark difference being the reactive nature of an IPS; it can immediately and automatically stop and prevent attacks as they occur, rather than sitting and just alerting of possible issues. Because an IPS is able to do a deep analysis of network packets, it has a variety of methods available to block or terminate whatever it determines to be an attack. It can block specific IP addresses, user sessions, traffic based on characteristics of the packets, or any other facet of the network traffic. With the ability to block based on specific characteristics of the packets, it enables an IPS to be effective at responding to distributed attacks, blocking a large number of IP addresses where desirable. It has the ability to block portions of traffic while allowing the rest through. A prime example of this could be removing certain types of e-mail attachments that contain executable code or match signature attributes, allowing the rest of the e-mail to proceed. In some cases, if configured and allowed by organizational policies, the IPS may be enabled to automatically make configuration changes to firewalls or network routing to prevent or mitigate an ongoing attack.

> CAUTION An IPS and IDS face considerable challenges when dealing with encrypted traffic. With the packet contents encrypted, signature-based analysis is effectively eliminated because the system cannot perform inspection. A careful examination of the specific application or system will need to be performed by the Cloud Security Professional to determine if it is prudent or possible to decrypt all or store traffic at specific points in order to perform IDS/IPS inspection.

### Honeypots

A honeypot is a system, isolated from the production system, that is designed to appear to an attacker to be part of the production system and contain valuable data. However, the data on a honeypot is bogus data, and it is set up on an isolated network so that any compromise of it cannot impact any other systems within the environment. The intent is to lure-attackers into going after the honeypot instead the production system. This allows administrators to set up extensive monitoring and logging the honeypot to watch the types of attacks and the methods employed in an attempt to compromise it. That knowledge can then be used to set up security policies and filters on the actual system.
