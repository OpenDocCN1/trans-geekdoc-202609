# Cloud Development Basics

A major difference between systems and their operations versus a traditional data center is that cloud systems are heavily reliant—or in many cases, solely reliant—APIs (application programming interfaces) for access and functions. Two main types of APIs are commonly used: Representational State Transfer (REST) and Simple Object Access Protocol (SOAP).

REST is a software architectural scheme that applies to the components, connectors, and data conduits for web applications used on the Internet. It relies on the HTTP protocol and supports a variety of data formats, with JSON and XML being the most widely used, and it allows for caching for better performance and scalability.

SOAP is a protocol and standard for exchanging information between web services in a structured format. SOAP encapsulates its information in what is known as a SOAP envelope, and leverages common communications protocols for transmission. The most common and prevalent protocol used is HTTP; but others as FTP are also possible. Unlike REST, SOAP only allows for the use of XML-formatted data, and it does not allow for caching, leading to lower performance and less scalability compared to REST. SOAP is most commonly used when design or technical limitations make the use of REST impossible.

# Common Pitfalls

Developers, management, and Cloud Security Professionals need to be aware of and understand several issues and pitfalls when contemplating cloud development or moving software to a cloud environment. These issues could cause security or operations problems within the cloud environment if not properly accounted for or understood from the onset of any project plan.

# Portability Issues

There is a common misconception that moving services from a traditional data center to a cloud environment is a seamless or transparent process. In many instances, systems and applications have been designed around the security controls and infrastructure for a data center. Many security controls are either supported or complemented by the data center infrastructure and setup, and in some cases the actual data center controls may be a significant part of how the overall security for the system or application is implemented. With a move to a cloud environment, some or all of these controls and configurations might not work or require significant reengineering to get to a comparable level.

When an analysis is undertaken to determine the possibility of moving to a cloud environment, the Cloud Professional should approach it with an overall mindset that an application hosted in a traditional data center was not designed with a cloud environment in mind, so it may have many features that are not transferable to a cloud environment. Cloud environments use newer technologies, and these technologies are rapidly changing and evolving. Many legacy systems from a traditional data center are unlikely to be properly programmed or work within the flexible nature and rapidly changing reality of a cloud environment. It is also unlikely that an application from a traditional data center model can be "forklifted" to a cloud environment, which in this case means a move with very few; if any, code changes.
