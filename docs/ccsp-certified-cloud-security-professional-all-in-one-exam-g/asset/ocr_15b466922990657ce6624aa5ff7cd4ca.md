Because SaaS systems are unique, once a customer decides to use one, they are substantially locked in that system with productivity dependency and lose a large degree of flexibility to move to a different cloud provider like someone using IaaS or even PaaS would have in the event of security problems or exploits. SaaS implementations, being in a cloud environment, also might not be watched successfully with the major IDS/IPS systems and scanning tools that work in a traditional data center model, so extra care in a cloud environment is necessary.

**Data Policies** a provider that offers a SaaS solution must carefully balance data policies and access into account the needs of individual customers it is strange that it not impede the cloud provider's ability to offer a broad solution that many customers can leverage. It is essential for the Cloud Security Professionals to be able to review existing policies on data access and mesh them with the degree of customizable flexibility that is afforded by the cloud provider. In some instances, the customer policies may need to be altered to some degree to fit within the paradigm of flexibility that is afforded by the cloud provider. When an organization is evaluating a SaaS solution, existing policies and any flexibility they may be afforded against what the SaaS provider can provide. With multiple customers (and quite possibly a large number of customers) with a SaaS solution, some degree of data-access customization is likely to be permitted, but certainly to the degree that an organization hosting their own solution would be able to accomplish. It is crucial not only to ensure that customer data is protected from other customers within the same SaaS implementation but also that a single customer can offer granularity of access within their organization that the various departments or audiences of users (for example, HR vs. developers, managers vs. staff) are able to see only the appropriate data for their job role and duties.

**Data Protection and Confidentiality** With multiple customers in the same SaaS environment, it is incredibly important to keep data protected and segregated, as mentioned previously about data policies. With all data in one application and one data store, the urgency to protect against SQL injection attacks and cross-scripting (XSS) problems becomes even more paramount. If either of these types of vulnerabilities exist within a SaaS implementation, potentially every customer's data within the system is exposed and vulnerable. The SaaS provider should build their data models in a way that for each customer is segregated as much as possible, including the use of different data stores for each customer, and very tight access controls provided. Code scanning and penetration testing to make sure accidental exposure and vulnerabilities do not exist for X and SQL injection, as well as other standard attacks to exploit code and expose vulnerabilities, become essential. The Cloud Security Professional must eventually evaluate the security policies and data policies of any SaaS implementation, as well as have tight contractual requirements for application audits and penetration testing, as well as ways for the customer to verify their compliance with the contractual requirements. Regardless of the cloud provider, the customer will ultimately be held responsible for any data breaches or exposure and the resulting negative impact on their reputation or possible legal consequences.
