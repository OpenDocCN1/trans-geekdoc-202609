# ### With traditional data center models, individual servers are utilized that have a close relationship between the hardware and operating system. In a cloud environment, where virtualization is used, the supervisor layer is introduced between physical hardware and member servers. This also introduces another level of security that can be overlooked beyond the physical security and operating system security. If the supervisor is compromised, all hosted virtual servers are now susceptible and vulnerable as well. This type of attack by an attacker would make all hosts under that supervisor vulnerable, spanning multiple systems and likely multiple clusters.

# ### Network Security With a traditional data center, an organization has the option to deploy extensive tools throughout their network for security monitoring and auditing. This included IDS/IPS systems, packet captures, application firewalls, and the ability to physically separate network switches and firewalls in order to segment networks. There could be a physical separation between development and production systems, or zones in the architecture, such as presentation, application, and data. In a cloud environment, both types of issues require special consideration. Most cloud providers offer a selection of tools for their hosted customers, but even cloud environment will not allow access and monitoring of what a customer could do in their own data center. With multitenancy and other customers, a cloud provider simply cannot give broad access and insight into a network. In a private cloud with different departments, cloud administrators have to limit how each system can see into the network layer and the level of abstraction that is required for the cloud system. Without a physical separation between systems and zones, software separation and access controls are utilized within a cloud, and it is incumbent on the cloud provider to ensure they are properly configured and tested.

# ### Virtual Machine Attacks Virtual machines are susceptible to all the same security attacks as a physical server. However, if a virtual machine has been compromised, because it is sharing with other virtual machines, this raises the possibility of attacks across the virtual machines. It is quite possible that the other virtual machines sharing the same host are from a different company or service, so this adds a level of abstraction where a customer is so reliant on the cloud provider to detect and mitigate any attacks, because each customer will only have insight into their own services within the cloud and will be completely unaware of another compromised host within the cloud.

# ### Virtual Switch Attacks Virtual switches are susceptible to the same degree of attacks, especially on Layer 2, as physical switches. In a cloud environment, because virtual switches are part of the same hosting environment as the other services and virtual machines, they are also susceptible to attacks and vectors if one of those hosts were to be compromised.
