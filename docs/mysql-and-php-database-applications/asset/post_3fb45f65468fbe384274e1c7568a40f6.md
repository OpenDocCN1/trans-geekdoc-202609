## Numeric column types

MySQL has seven column types suitable for storing numeric values. Note that the following are synonyms: int and integer; double, double precision, and real; and decimal and numeric.

- int/integer
- tinyint
- mediumint
- bigint
- float
- double/double precision/real
- decimal/numeric

For numeric types the maximum display size is 255. For most numeric types you will have the option to zerill a column —to left-pad it with zeros. For example, if you have an int column that has a display size of 10 and you insert a value of 25 into this column, MySQL will store and display 0000000025. The numeric column types may also be defined as signed or unsigned. Signed is the default definition.

## INT/INTEGER

Usage: (display size) [unsigned] [zerill]
If you use the unsigned flag, this column can store integers from 0 to 4,294,967,295. If the range is from -2,147,483,648 to 2,147,483,647. Int will be used with auto_increment to define the primary key of a table.

```sql
create table my_table (
  table_id int unsigned auto_increment primary key,
  next_column text
);
```

Note that I've used an unsigned column because an auto_increment column has no need for negative values.

## TINYINT

Usage: tinyint(display size) [unsigned] [zerill]
If unsigned, tinyint stores integers between 0 and 255. If signed, the range is from -128 to 127.

## MEDIUMINT

```
Usage: mediumint(display size) [unsigned] [zerofill]
```

If unsigned, mediumint stores integers between -8,388,608 and 8,388,607. If signed, the range is from 0 to 16,777,215.

## BIGINT

```
Usage: bigint(display size) [unsigned] [zerofill]
```

If unsigned, bigint stores integers between -9,223,372,036,854,775,808 to 9,223,372,036,854,775,807. If signed, the range is from 0 to 18,446,744,073,709,551,615.

## FLOAT

```
Usage: FLOAT(precision) [zerofill]
```

In this, float stores a floating-point number and cannot be unsigned. The precision attribute can be <=24 for a single-precision floating-point number and between 25 and 53 for a double-precision floating-point number. Starting in MySQL 3.23, this is a true floating-point value. In earlier MySQL versions, FLOAT(precision) has two decimals.

```sql
Usage: FLOAT([M,D]) [ZEROFILL]
```

This is a small (single-precision) floating-point number and cannot be unsigned. Allowable values are -3.40823466E-38 to -1.175494351E-38, zero, and 1.175494351E+38 to 3.40823466E+38. M is the display width and D is the number of decimals. FLOAT does not allow an argument or with an argument of <= 24 for a single-precision floating-point number.

## DOUBLE/PRECISION/REAL

```
Usage: DOUBLE([M,D]) [ZEROFILL]
```

This is a double-precision floating-point number and cannot be unsigned. Allowable values are -1.7976931348623157E+308 to -2.225073885072104E-308, zero, and 2.225073885072104E+308 to 1.7976931348623157E+308. M is the display width and D is the number of decimals.

```sql
Usage: DECIMAL([M,D]) [ZEROFILL]
```

Numbers in a column are stored as characters. Each number is stored as a string, with one character for each digit of the value. If D is 0, values will have no decimal point. The maximum range of DECIMAL is the same as for DOUBLE, but actual range if M is left out, it is set to 10.

## Date and time types

MySQL has five column types suitable for storing dates and times.

- date
- datetime
- timestamp

MySQL date and time types are flexible, accepting either strings or numbers as part of insert statements. Additionally, MySQL is pretty good at interpreting dates that you give it. For instance, if we create this:

```sql
create table test (
  id int primary key,
  created date
);
```

And then insert a row:

```sql
insert into test values (1, '2023-01-01');
```

MySQL will interpret the date correctly. If we use a numeric format:

```sql
insert into test values (2, 20230101);
```

MySQL will also interpret this correctly. If we use a different format:

```sql
insert into test values (3, '01-01-2023');
```

MySQL is very flexible with date formats. You can even use:

```sql
insert into test values (4, '2023-01-01 12:00:00');
```

Wait, that is for a datetime column. For a date column, it will just be stored as '2023-01-01'.

The various MySQL date and time types are:

- date: YYYY-MM-DD
- datetime: YYYY-MM-DD HH:MM:SS
- timestamp: YYYY-MM-DD HH:MM:SS (UTC)
- time: HH:MM:SS
- year: YYYY

## DATE

Usage: date YYYY-MM-DD
The date type stores dates in the YYYY-MM-DD format.

## DATETIME

Usage: datetime YYYY-MM-DD HH:MM:SS
The datetime type stores dates and times in the YYYY-MM-DD HH:MM:SS format.

## TIMESTAMP

Usage: timestamp YYYY-MM-DD HH:MM:SS
The timestamp type stores dates and times in UTC. It is converted to the current time zone for retrieval and back.

## TIME

Usage: time HH:MM:SS
The time type stores time in HH:MM:SS format.

## YEAR

Usage: year YYYY
The year type stores years in YYYY format.
