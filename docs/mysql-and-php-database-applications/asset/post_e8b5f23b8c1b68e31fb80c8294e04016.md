Now imagine that you need to get a list of the authors of this book and their spouses, if they are married. The equi-join shown in the previous section will not work in this case. Take the following query:

```
select *
from contact, spouses
where contact.spouse_ID = spouses.spouse_ID
```

Only the first row of the contact table will be returned. The null value in the second row ensures nothing can match the criteria in the where clause. In cases like this, we need to preserve one table and the second table when there are matching values, we will make use of the outer join (also known as the left outer join), which looks like this:

```
select
from contact
left join spouses
on contact.spouse_ID = spouses.spouse_ID
```

This statement says, “I want to keep the entire contacts table, and tack on the spouses table when these two fields are equal.” The word left in the term left outer join

Depending on the database package you're using, the syntax of the outer join may vary. Many databases support left, right, and full (both left and right) outer joins. MySQL only has the outer join, but in practice it's usually all you need. You can use the syntax in the previous query, or you can use left outer join.

Outer joins will come frequently out of necessity. It is often good practice to use outer joins even when an inner join will do the trick. It's just a matter of being safe. You'd rather not have important rows of data missing because you forgot to account for null values Throughout the book, you will see occasions when we used outer joins because we wanted to be extra careful.

There may come times when you will need to do more than one outer join. For instance (and for no particular reason), we wanted to store information regarding spouses siblings. We add another table listing the siblings and a column to the spouses table, which maintained the relationship. So, if we wanted to design a query that maintained everyone in the contacts table, and maintained everyone that returned from the spouses table, we'd have to throw in two outer joins:

```
select *
from contact
left join spouses on contact.spouse_ID = spouses.spouse_ID
left join siblings on spouses.sibling_ID = siblings.sibling_ID
```

## self join

As bizarre as it may sound, the time will come when you'll need to join a table to a copy of itself. If we had a sneaking suspicion that there was a bigamist in Table 3-2, how would we search out the two with the same spouse?

You would need to discover if this value in the spouse_id field was repeated (for instance, the number 2 appears more than once). You could do group by, but then there would be no way of getting the names of the people involved. Using group by along with the count() function, you could find the occasions where one person appears more than once, but it would take a second query to find out those people were. With a self join, you could do all in one step. It needs to be a carefully considered step.

You might think that the following query would do the trick. Notice that I again use aliases, so that we have two table names we can

```
select t1.first_name, t1.last_name, t2.first_name, t2.last_name
from contacts t1, contacts t2
where t1.spouse_id = t2.spouse_id
```

But this is going to return more rows than we need. Specifically, each name will match itself, providing duplicates of each returned entry. Given this query, the row for Jay is compared to itself, it will be true and returned in the result. You can eliminate redundancy by ensuring that the contact_id field from the first table is not equal to the ID field in the second table.

```
select t1.first_name, t1.last_name
from contacts t1, contacts t2
where t1.spouse_id = t2.spouse_id
and t1.contact_id != t2.contact_id
```

This is good but not perfect. The example of Elliot and John. A row will be returned when the Elliot is in t1 and John in t2; another will be returned when John is in t1 and Elliot is in t2. The easiest way to address that is to use of the numeric primary key. You know one ID will be greater than the other, and by using that information you can get rid of all duplicates.

```
select t1.first_name, t1.last_name
from contacts t1, contacts t2
where t1.spouse_id = t2.spouse_id
and t1.contact_id < t2.contact_id
```
