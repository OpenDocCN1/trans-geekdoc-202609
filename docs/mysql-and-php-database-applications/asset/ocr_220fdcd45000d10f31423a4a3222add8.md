First, the application is going to have to display your wares; for this you will reuse the code from Chapter 10. Further, users will have able to choose items that they want to buy. Obvious, I know. Note what must happen after a user chooses an item: the each item must be noted, and the user should have the opportunity to continue shopping. The server must remember what has been ordered. As the user continues to browse, the server must keep track of the user and allow him or her to check out with his requested items.

This requires you to use some method for maintaining state. That is, the Web server will need to remember the user who is as/she moves from page to page. Now if you head back to the introduction, the Web and the HTTP protocol that the Web makes use is stateless. That is, after responding to an HTTP request, the server completely forgets what it served. The server takes requested information serially—one at a time as requests come in. There is no persistence, no connection that lasts after a page has been rendered.

In order to visit your site, so that, in this case, the cart can remember who ordered, some information that identifies the user with each page request. On the Web there are exactly three ways to store this information:

+   * You can set a cookie, and each time a request is made, the information stored in the cookie will be sent to the server. Note that the browser stores the cookie information serially in a small text file and sends the information to the server with each request.
