
# Part IV: Not So Simple Applications

This application is going to use the same 401-type authentication used in the previous examples, but here the values for $PHP_AUTH_USER and $PHP_AUTH_PW will also be the values used to log into the database.

$PHP_AUTH_USER and $PHP_AUTH_PW are only available if PHP is installed an Apache module. If you are working on Windows, you will not be able to use this type of authentication.

![](img/245156cc770929860a3ede93c01f9981_330_0.png)

The header.php file, which is included in every page in the content management system, contains the following code:

```php
if ($authentication == "admin")
    include "admin_authenticate.php";
else
    include "authenticate.php";
$this_username = $PHP_AUTH_USER;
```

This if ... else block determines which authentication script will run. In pages that require administrative access you will see a variable assignment like the following prior to the include of header.php.

```php
authentication = "admin";
```

If this does not execute, authenticate.php will be included. Here are the contents of the authenticate.php file.

```php
$realm = "Netsloth Content";
$errmsg = "You must enter a valid name & password to access this function";
if (empty($PHP_AUTH_USER) && $olduser == $PHP_AUTH_USER)
    $what = empty($PHP_AUTH_USER) ? "login" : newuser($newuser,$olduser);
    authenticate($realm,$errmsg.":$what");
```

# content/admin_user.php

This page, like many you have seen, has many purposes. The exact portion of the script that will run depends on the variables that are sent to the page. It will do the following:

- Enable an administrator to create new users.
- The information specific to a single user_id will be displayed, including the stages associated with that user.
- Additional stages can be granted to an existing user.
- Rights to a stage can be revoked by a user.

If the page is accessed without any user information in the querystring or POST, the form elements for user information will be blank. This information must be filled in before the form is submitted. When the form is submitted the admin_user.php page will be called again, this time holding the entered form data and with the $submit variable equal to "Save Changes",

When submitted, the condition in the if statement at the top of the page will test:

```php
if (!empty($submit)) && $submit == "Save Changes"
```

As the same form updates an existing user's information and creates a new user, there is a second condition that must be tested. If the user's information must be updated, the form passes a user_id from a hidden form element; otherwise the $user_id variable is empty. The result of this statement decides whether the script is to perform an update or insert query.

```php
if (empty($user_id)) {
    safe_query("insert into content_users (username, name, email) values ('$username', '$name', '$email')");
    $user_id = mysql_insert_id();
} else {
    safe_query("update content_users username='$username', name='$name', email='$email' where user_id = $user_id");
}
```

Note that when this section of the script is completed, the user_id is known: either it was passed from the form or it was retrieved with the mysql_insert_id() function.
That brings this script to a series of MySQL grant statements that are sent via the safe_query() function. Note the first two queries, which are within blocks. These test whether this is a new user who has previously been granted rights. If a user rights are being updated, she will already have an entry in the user table in the mysql database. If the "grant usage" query enters the person in the mysql table but gives no specific rights to any databases or tables.
