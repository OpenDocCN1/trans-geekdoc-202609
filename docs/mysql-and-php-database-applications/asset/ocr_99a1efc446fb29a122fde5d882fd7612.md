join refers to the fact that when you visualize your database tables, you should visualize the first table, the one that appears in the from clause, on the right-most side, and the joined table on the left.

Depending on the database package you're using, the syntax of the outer join may vary. Many databases support left, right, and full (both left and right) outer joins. MySQL only has the outer join, but in practice it's usually all you need. You can use the syntax in the previous query, or you can use left outer join.

Outer joins will come frequently out of necessity. It is often good practice to use outer joins even when an inner join will do the trick. It's just a matter of being safe. You'd rather not have important rows of data missing because you forgot to account for null values Throughout the book, you will see occasions when we used outer joins because we wanted to be extra careful.

There may come times when you will need to do more than one outer join. For instance (and for no particular reason), we wanted to store information regarding spouses siblings. We add another table listing the siblings and a column to the spouses table, which maintained the relationship. So, if we wanted to design a query that maintained everyone in the contacts table, and maintained everyone that returned from the spouses table, we'd have to throw in two outer joins:

```
select *
from contact
left join spouses on contact.spouse_ID = spouses.spouse_ID
left join on sylings spouses.sybling_ID = syblings.sybling_ID
```
