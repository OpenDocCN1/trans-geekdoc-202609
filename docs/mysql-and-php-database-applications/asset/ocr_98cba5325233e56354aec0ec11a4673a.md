# Chapter 6: PHP’s Built-in Functions

# HEADER()

If you are going to be communicating with the browser or with other HTTP servers,
this is the function to use.

```
int header (string string)
```

Essentially, you can send any header that would be expected over RFC 2616
(ftp://ftp.isi.edu/in-notes/rfc2616.txt). The RFC itself is a handful (and
the sweetest sleep you’re having all year. Here is a common header when
is likely to send.

```
header("Location:http://www.php.net");
```

This is more than a redirect; it sends the browser to a page you specify. If
y have been working with straight HTML and the <META type=refresh> tag or
JavaScript to do your redirects, you will switch to this type of header whenever
possible. It will work for all browsers and the redirection will be totally transparent
to the user.

> **IMPORTANT:** No, make that VERY IMPORTANT. You cannot send a header
after anything — ANYTHING—has been sent to the browser. If you send a
header after a hard return, there will be an error. If there is a hard return
before opening your `php tag, you will get an error. If there is a hard return in
in included file that precedes the `header()` function, you will get an error.
This should not be a problem you encounter frequently; your pages should
be so that most of the logic is handled prior to the display.
However, if you have a situation you just can't work around, take a look at the
output buffering functions.

# SETCOOKIE()

This is basically a specialized function, because a cookie is set by nothing
more than a specific HTTP header.

```
int setcookie (string name [, string value [, , int expire [, , string
path [, string domain [, int secure]]]])
```

The first argument will be the name of the cookie. The second will be the value.
The expire value should be set with the time function. The following is a pretty typ-
ical use of setcookie():

```
setcookie("id".\$id_val.time()+(24*60))."/",".domain.com",0);
```
