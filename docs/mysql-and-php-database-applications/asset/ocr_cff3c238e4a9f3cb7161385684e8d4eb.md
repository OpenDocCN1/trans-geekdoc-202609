# Many-to-many relationship

Many-to-many relationships work a bit differently from the other two. For instance, suppose that the company keeping the data has a variety of newsletters that it sends to its contacts, and it needs to add this information to the database. There's a weekly, a monthly, a bi-monthly, and an annual newsletter, and to keep from annoying clients, the newsletters must only be sent to those who request them.
To start, could add a table that stores the newsletter types (Table 1-10)

# Table 1-10 NEWSLETTERS TABLE

| newsletter_id | newsletter_name |
|---|---|
| 1 | Weekly |
| 2 | Monthly |
| 3 | Bi-monthly |
| 4 | Annual |

Table 1-10 cannot be directly related to another table that stores contact information. The only way to make this work is to add a column that stores the newsletters that each contact receives. Right away, you should notice a problem with the Table 1-11.

# Table 1-11 CONTACTS TABLE

| contact_id | contact_first_name | contact_last_name | newsletters |
|---|---|---|---|
| 1 | Jon | Doe | 1,3,4 |
| 2 | Al | Banks | 2,3,4 |

In this table the Newsletters column contains more than one value. The value looks like an array. As mentioned earlier, this should never occur within your database — we want only atomic values in each column.
