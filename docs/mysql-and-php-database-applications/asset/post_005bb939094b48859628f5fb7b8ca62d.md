**METHOD BASE** This is the constructor method for this class. As you can see it does little but make calls to a method called Construct.

```
function Base ($parent="",$atts="")
{
    $this->Construct(get_object_vars($parent));
    $this->Construct($atts);
}
```

Notice the use of `get_object_vars()`. It is a handy function that turns all of the object properties into an associative array. So if an object is passed to this method (through the first instance), it can be passed to Construct as an array.

**METHOD CONFIRM_DELETE_FORM()** This method prints a form that forces the administrator of the catalog to confirm that they want to continue with a delete. This comes into play when a deletion is indicated for an item that contains related child elements. For example, if the administrator indicates that a category should be deleted but the category still contains products, this form will print.

```
confirm_delete_form($message="",$label="")
```

Notice that the Product object contains an array of related styles. That array, named styles, contains Style objects. METHOD PRODUCT() This is the constructor of the class. It is very brief.

```
function Product($parent="","$atts="")
{
    $this->styles = array();
    $this->Base($parent,$atts);
}
```

Remember that this will be called from the Category class. The styles variable will contain the name of the parent, and $atts will be a row retrieved from the database. Though it's not important to show all of the code that will do this method, you should have an idea of what is needed to create the data in Figure 10-12. Somewhere in the Category class, a query to the database will retrieve a list of all the products associated with category_id, something like `* from products where category_id = category_id`. The result set of this query will be looped through each time and assigned to the second argument in the call to the Product object, when the Product class calls to Styles. Note that this constructor will also run if a product object is instantiated. But before being instantiated, the information with the product_id will not be automatically loaded. The FetchProduct() or LoadProduct() methods will be needed for that. It is the LoadProduct() method that will make the call.

METHOD FETCHPRODUCT() This method grabs the table associated with the given product id. It includes some handling for the event that no product_id or a bad product_id was given. Then, using the Construct method from the Base class, each of the returned fields is turned into a property of the Product object.

```
function FetchProduct ($product_id=0)
{
    if (!empty($product_id))
    {
        $this->product_id = $product_id;
    }
    if (empty($this->error))
    {
        $this->error = "no product_id specified for fetch";
        return FALSE;
    }
    $result = safe_query("select * from products where product_id = $this->product_id");
    if (!$result) {
        return FALSE;
    }
    $row = mysql_fetch_array($result,MYSQL_ASSOC);
    $this->Construct($row);
    return TRUE;
}
```

Notice the use of $this->error. By defining an error in this way, our scripts can do this:

```
$p = new Product;
if (!$p->FetchProduct(1))
{
    echo $p->error;
}else{
    echo "The product name is: $p->product";
}
```

if the fetch didn't work out. The method will return FALSE, and you will have access to a meaningful error message.
