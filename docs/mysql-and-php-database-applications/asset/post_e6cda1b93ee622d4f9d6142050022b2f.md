
# Introduction

If you know Visual Basic, you are probably going to want to stick with NT/2000. Even if this is the case, there's nothing to prevent you from developing with PHP and MySQL. Both products run on Windows 95/98 and Windows NT/2000.

In the real world, almost all PHP/MySQL applications are running off of some version of Unix, whether it be Linux, BSD, IRix, Solaris, HP-UX, or one of the other flavors. For that reason, the applications in this book will work with Unix. If you need to run these on Windows, minor alterations to the PHP scripts may be necessary. Most of the people who created PHP and MySQL are deeply involved with Unix, and most of their development is on Unix machines, so it's not surprising that the software they have created best on Linux, BSD, and other Unix boxes.

The major advantage of Unix is its inherent stability. Boxes with Linux have been known to run months or years without crashing. Linux and BSD also have the advantage of being free and able to run on standard PC hardware. If you have any old 486, you can load it up with Linux, MySQL, PHP, and Apache and have yourself a well-outfitted server. You probably wouldn't want to put this on the Web, where a moderate amount of traffic might overwhelm it, but it will serve merely as a development server, a place where you can test your applications.

# WEB SERVER

The Web server has what seems to be a fairly straightforward job. It sits there, running on top of your operating system, listening for requests that somebody on the Web might make, responds to those requests, and serves out the appropriate Web pages. In reality, it is a bit more complicated than that, and because of the 24/7 nature of the Web, stability of the Web server is a major issue.

There are many Web servers out there, but two Web servers dominate the market. They are Apache and Microsoft's Internet Information Server (IIS).

INTERNET INFORMATION SERVER: IIS is deeply tied to the Windows environment and is a key component of Microsoft's Active Pages. If you've chosen to go the Microsoft way, you'll almost end up using IIS.

There is a certain amount of integration between the programming language and Web server. At this point, PHP 4 integrates with IIS. As of writing, there is some concern about the stability of PHP/IIS under heavy load, but PHP is improving all the time, and by the time you read this it will no longer be a problem.

APACHE: Apache Web server is the most popular Web server there is. It, like Linux, PHP, and MySQL, is an open-source project. Not surprisingly, Apache works best in Unix environments, but also runs fast under Windows.

Apache makes use of third party modules. Anyone with the skill can write code that extends the functionality of Apache. PHP will most often run as an Apache extension, known as an Apache module.

Apache is a great Web server. It is incredibly and amazingly stable. The most frequently stated complaint about Apache is that, like many pieces of Unix software, there are limited graphical tools with which you can manipulate the application. You alter Apache by specifying options on the command line or by altering text files. When you come to Apache for the first time, all this can be a bit opaque.

Though Apache works best on Unix systems, there are also versions that run on Windows operating systems. Nobody, not even the Apache developers, recommends that Apache be on a busy server under Windows. If you have decided to use the Windows platform for serving Web pages, you are better off using IIS.

But there are conditions under which you'll be glad Apache run under Windows. You can run Apache, PHP, and MySQL on a Windows 98 machine and then transfer these applications to Linux with practically no changes to the scripts. This is the easiest way to go if you need to develop locally on Windows but to serve off Unix/Apache server.

# MIDDLEWARE

PHP belongs to a class of languages known as middleware. These languages work closely with the Web server to interpret the requests from the Wide Web, process these requests, interact with other programs on the server to fulfill the requests, and indicate to the server what to serve to the client's browser.

The middleware is where you'll be doing the vast majority of your work. With a little luck, you can have your Web server up and running without a whole lot of effort. And once it is up and running, you won't need to feel with it a whole lot.

But as you are developing your applications, you will spend a lot of time writing code that makes your applications work. In addition to PHP, there are several that perform similar functions. Some of the more popular choices are ASP, Perl, and ColdFusion.

# RELATIONAL DATABASES

Relational Database Management Systems (RDBMSs) provide a great way to store and access complex information. They have been around for quite a while. In fact, they precede the Web, Linux, and Windows NT, so it should be no surprise that there are many RDBMSs to choose from. All of the most popular databases use the Structured Query Language (SQL).

Some of the popular commercial RDBMSs are Oracle, Sybase, Informix, Microsoft's SQL Server, and IBM's db2. In addition to MySQL, there are now two major-source relational databases. Postgres has the major alternative to MySQL in the open-source area. In August 1999, Borland released its Interbase product under an open-source license and allowed free download and use.

# Why these Products?

Given the number of choices out there, you may be asking yourself why you should choose PHP and MySQL. We will answer this question in the following three sections.

# Why PHP?

Programming languages are like shoes. Look good to some people yet look ugly to others. To carry the analogy a little further, some shoes just fit well.

What we mean is this; when it comes to Web programming, all languages do pretty much the same thing; they interact with relational databases; they all work with a filesystem; they all interact with a Web server. The question about which language is best is rarely a matter of a language's inability to perform actions. It is usually a matter of how quickly you can do what you need with the least amount of pain.

# IT'S FAST AND EASY

What about speed? There are three things that we know for sure when it comes to comparing speeds of Web programming. First, applications written in C will be the fastest. Second, programming in C is rather difficult and will take longer than any of the other languages. Third, comparisons between languages are extremely difficult. From everything we know, we feel safe saying that PHP is as fast as anything out there.

More than not choosing a language comes back to the same issues involved in buying shoes. You'll want to go with what feels comfortable. For us, PHP is the perfect mix of power, structure, and ease of use. Again, this is a matter of opinion, but we believe the syntax of PHP is superior to ASP and JSP and we believe it puts power over your fingertips more quickly than ColdFusion and is not as difficult to learn as Perl.

In the end, we believe PHP offers the best opportunity to develop Web applications. In addition, we believe there are other reasons for choosing PHP.

# IT'S CROSS-PLATFORM

In the rundown of Web architecture, we mentioned that PHP will run on Windows 2000/NT and Unix with IIS and Apache. The cross-platform abilities of PHP go far beyond these platforms. If you happen to be using Netscape, Roxen, or just about anything else, it is likely PHP will work with it.

Yes, ASP can run on Linux, and ColdFusion can run on Solaris and Linux, and JSP is adaptable across many platforms. At this point, PHP works as well on a variety of systems as any other available product.

What do you need to access in the course of creating your Web applications? LDAP? IMAP mail? Oracle? Informix? DB2? Or may you need an XML parser or WDDX functions?

Whatever you need to use, it is more likely that PHP has a built-in set of functions that make getting whatever you need very easy. But what if it doesn't have something built in that you'd like? That brings us to our next point.
