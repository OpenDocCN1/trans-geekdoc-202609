# Accessing the filesystem

You have probably noticed that not in this book, all of our data are stored within your MySQL database. But even when you are using MySQL, there are times when you are better off using the filesystem for storage. Images (jpegs, gifs, pngs) are a perfect example. Even if your database supports binary data, there's little advantage in putting an image in a database. You need a database for storing path and querying normalized data. In your database you are much better off storing the path to the image stored in your filesystem. That way it will be easy enough to fill the src attribute in your `<img>` tag.

> Do not store images in a database. Put them on the filesystem.

# Part IV: Not So Simple Applications

When you allow file uploads, someone opens yourself up for denial of service (DoS) attacks. If you're not careful, someone could send many-megabyte files to your system simultaneously, which could bring your machine to a crash-halt. There are two things you can do about this `input` tag. First is to put a hidden field prior to `type="file">`. The hidden field should look like this:

```
<INPUT TYPE="hidden" name="MAX_FILE_SIZE" value="1000">
```

where value is the maximum size allowed, in bytes. This is a reasonable first step, and could be of help in stopping someone who didn't know you had a size limit. However, this will not stop anyone with malicious intent. All they would have to do is look at the source code of your page and make the needed changes. php.ini file contains the upload_max_filesize item. If you have access to your php.ini, you can set this to a number that you think reasonable. By default, php.ini will allow 2 MB uploads.

When a file is specified and this form is submitted, PHP automatically creates a few variables. You would be:

- *$filename: the name of the file as stored in the temporary directory on the server
- *$image_name: the name of the file as it was on the user's machine
- *$image_size: the size of the file, in bytes
- *$image_type: the mime type, in this case image/gif, image/png, image/jpg

The image will be stored in the temp directory specified in the php.ini file; if no temp directory is specified in php.ini, the operating system's default directory will be used.

The Paths and Directories category of the php.ini controls many of the file upload options.

# Accessing outside utilities

For this application, we need thumbnails for each of the images. The application could require the user to include both a full-size image and a thumbnail. But that's really not necessary, because the open-source world has provided all of us developers with a utility that powerfully and easily manipulates images. It's called PBMplus.

![](img/245156cc770929860a3ede93c01f9981_293_0.png)

You can find the PBMplus package on the CD-ROM that accompanies this book.

PBMplus contains several utilities that come in two basic flavors. One of utilities transfers images to and from an intermediary format. So, whether you have a gif, a jpg or a png, it must be converted to the intermediary format, pbm. Another set of utilities alters the pbm files. These utilities do for variety of things: check the README file and the pages that come with PBMplus to learn about. Once you have made the .pbm file, you can convert it to whatever format you need. To use these, you need to run shell commands from your PHP script. For the purposes of this application, the system() function will be the best choice. More on when we get to it in the code.

![](img/245156cc770929860a3ede93c01f9981_293_1.png)

> There is potential danger when using functions that run shell commands. If any information supplied from the user is transported to the shell commands, you should take great care to ensure that damaging commands cannot be executed. The escapeshellcmd() function will help http://www.php.net/manual/function.escapeshellcmd.php examine shell commands. In this application only people who are logged in will reach commands that access the shell.

# Objects in theory

For instance, if we were to tell you about a class named Category, we could just tell you the following:

Class Category:
Inherits Base
Properties:
- products

Methods:
- LoadCategory: Loads all of the categories table into object properties, based on a unique category_id.
- SaveCategory: Writes a new or updated category to the database.
- FetchCategory: Based on a unique category_id, assigns all columns for row to properties.
- DeleteCategory: Removes a Category from the database.
- PrintCategory: Writes out a category to the browser.

Knowing this, and really nothing, we could write a new script that displayed a category. The script below assumes a category_id was passed through the querystring, or via a POST.

```
<?php
$c = new Category;
$c -> LoadCategory($category_id);
$c -> PrintCategory();
```
