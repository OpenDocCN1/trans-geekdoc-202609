# Part II: Working with PHP

For example, say you had a file that contained a function, but that the function relied on another function from an outside file. You'd do something like this:

```
require_helpful_file.php';
another_function();
{
    function_from_helpful_file();
}
```

We name this file short_function.php. If we needed both short_function.php and helpful_file.php in a third file, we could have a problem. All functions in helpful_file.php would be included twice. If we called one of the twice-included functions, PHP would not be able to resolve the ambiguity and spit out an error. In cases like this, use include_once() or require_once(). Note if files are included more than once we might also have a dealing with variables that inadvertently overwrite each other.

Note that include_once() and require_once() inherit behavior from include() and require_once(); require_once() will only be processed once, and include_once() can be executed multiple times within loops.

# User-Defined Functions

In Chapter 6 you saw many of the functions built into the PHP processing engine. If you are a humble person and look at Appendix E or visit the PHP manual, you should be duly impressed by the quantity and power of PHP's built-in functions. But it isn't enough—and no how much work the able developers put into the language, it will never be enough. This is because every developer on the planet has unique needs. We need to accomplish specific tasks, and need to do it in ways that fit our styles and predictions.

User-defined functions allow us to create blocks of code that achieve specific tasks. The great thing about user-defined functions is that the code becomes reusable. Any piece of code that you find yourself writing over and over should be committed to a function. There's little doubt that it will save you time in the long run.
