Say you want to track the activity of your users across a number of pages, as with this shopping cart. You need to remember who has put what in it. To accomplish this, you could use some complex variables via a cookie that hold all of the elements and their prices. But this is kind of messy, and it may expose more of the secrets of your application than you are comfortable exposing. The cookie specification (http://www.netscape.com/newsref/std/cookie_spec.html) allows for only 20 cookies and 4 bytes per cookie.

A better idea is give each person who visits your site a unique identifier, some value that identifies who person is. If the user adds items to the cart, information associated with that unique identifier can be stored on the server. If you were to code a function by hand, you might create a unique string that would be put in a cookie; then, in some directory on the server, you could have a file that has the same name as the user ID. Within that file you could store all the variables associated with the user. For example you might have an array of items that a specific user puts in his or cart.

In fact, this is almost exactly what sessions do. When you indicate in your code (or by settings in php.ini) you'd like to start a session, PHP will create a unique identifier and a file, which is stored on the server (the location is as the user moves from page to page, all the variable information that the user can be stored in the file on the server, and all the scripts need to keep track of the unique identifier.

There are many configuration options when it comes to sessions, but probably the most important decision is where the session id will be propagated, in a URL or a cookie. Most e-commerce sites make use of cookies. However, there is the chance that some of your users will not be able to use your site properly if they have their browsers to reject cookies. For this reason, in PHP it is very easy to add the session id to the querystring. There are two ways to go about it.

The code <?= SID ?> will print the session id. Append the session id to a URL, you would have to manually add it, like this:

```
<a href="mydomain.com?sid=<?php SID?>">
```

This can be for some tedious work if you want to put the session id on every link in your site. However, if you compile PHP with the flag --enable-trans-sid, the session will be automatically appended to every relative link in your pages once a session has been started.
