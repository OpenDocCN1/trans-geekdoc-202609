Each of these tables corresponds to a level of access control. You can create any number of users, and users be allowed access from any variety of hosts. Each user/host combination, you can grant access to an entire database, to specific tables within a database, or to a number of columns within a table. Additionally, these tables grant administrative privileges. Users can be given permission to add and drop tables or permission to grant other permissions.

In practice you will want to grant more permissions than necessary. You want to protect your data from the overzealous and the incompetent. The best way to do with MySQL is to use the proper grant table when assigning rights, keeping the following in mind: Rights are granted in a hierarchical way. Rights granted in the user table will be universal. If a user is granted drop privileges in the user table, the user will be able to drop any table in any database in MySQL installation.

Then there is the db table, which grants privileges on a database-specific basis. Using this table, you can grant rights for an entire database. For any one or set of tables, you may use the tables_priv table. Finally, the columns_priv table allows you to grant rights on specific columns within a table. If you don't need to grant rights to an entire table, see that rights are assigned in the columns_priv table.

Recent releases of MySQL make use of a couple of convenient commands for making users and assigning rights fairly easily. I'll discuss these methods after a first look at the user, db, tables_priv, and columns_priv tables.
