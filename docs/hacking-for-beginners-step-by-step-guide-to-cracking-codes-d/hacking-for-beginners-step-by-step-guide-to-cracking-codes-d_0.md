在对系统进行黑客攻击之前，攻击者的通常做法是进行教育并了解目标系统（如果已经已知的话）。这使得攻击可以针对目标进行定制，并对齐可能存在的任何弱点，以不惜一切地实现成功。根据攻击者的目标和动机，会被攻击的系统类型多种。这些目标系统的范围从在网页和服务器上毫无防备的上网用户到公司和政府。

启发阶段——即实际攻击之前的侦察阶段——可以细分为被动识别和主动启发。通过被动阐明，我们指的是在不直接接触目标系统的情况下收集信息。另一方面，主动启发则试图通过与目标系统的直接交互来收集信息。

在被动启发中，通过足迹追踪（foot-printing），攻击者寻求有关整个目标系统的信息。因此，它试图创建一个粗略的“足迹”。你正在寻找的信息，例如使用的硬件、IP 地址范围、单个计算机的 IP 地址或有关公司员工的信息。主动启发或指纹识别（fingerprinting）试图对系统的单个组件进行画像。因此，会侦查单个计算机以寻找诸如开放端口之类的漏洞。攻击者由此为单个系统组件创建“指纹”，从而尝试发现潜在的入口。

本书的目的是介绍用于准备工作中的技术，并指出适当的应对措施。为了实现这一目的，首先介绍了不同类型的攻击者以及他们的攻击动机和潜在目标选择。随后，详细介绍了使用被动和主动启发技术的澄清阶段。最后，展示了应对措施，涵盖了通用措施以及针对此处阐述启发技术的特定措施。

## 第 1 章 – 攻击者类型

由于攻击者的动机和技术能力存在差异，不同类型的攻击者会攻击不同的系统，并具有不同的攻击意图。根据 Roge 的分类，攻击者可以分为七类。下面将进行简要介绍。

该小组的成员大多是黑客领域的新手，仅具备基础的计算机网络安全技能。因此，他们使用预程序的软件工具包进行攻击。这些软件工具包在互联网上被广泛使用且容易找到。因此，他们的攻击仅限于已有工具包支持的系统。

网络朋克拥有先进的软件、编程和系统知识。他们的犯罪意图具有很强的犯罪性。网络朋克攻击 Web 服务器以重新设计网页（网页破坏），并经常活跃于垃圾邮件和信用卡欺诈。

内部人员小组由前员工和不满的员工组成。他们通常技术高超，能够根据自己以前或现在的工作功能和职责发起攻击。他们的攻击目标是前任或现任雇主，因为他们利用对那里系统的了解。

这一小组拥有广泛的技术知识，能够利用安全漏洞和所谓的程序漏洞（exploits）。

这一小组并不一定追求犯罪意图，而是受第一代黑客黑客伦理的引导。根据 [Raym03]，黑客伦理被定义为：相信信息应该是自由的，并且相信对计算机系统的攻击是符合伦理的。因此，只要不追求犯罪意图，而是为了乐趣和探索的享受，就被认为是合伦理的。从法律上讲，对计算机系统的攻击在伦理上是不正当的，因此会受到惩罚。

这些小组由受过良好训练并装备专业的犯罪分子和前秘书组成。他们主要从事工业间谍活动，因此其目标是网络。关于这一小组为人较少，被认为非常危险。

尽管在目标选择、技术能力和攻击动机存在差异，但所有类型的攻击者在攻击之前都需要对目标系统了如。因此，在每次攻击之前，必须进行说明并收集信息。下节将介绍说明中所使用的技术。

## 第 2 章 – 被动侦察与足迹追踪

被动侦察/足迹追踪类别包括可以在不直接与目标系统交互的情况下收集目标信息的技术。通过使用“第三方”源获取信息，攻击者不会在目标系统上留下任何痕迹，例如以服务器日志条目中的 IP 地址的形式存在。足迹追踪的可能性包括但不限于查看公司网站、可能使用代理来伪装自己的身份和 IP 地址。

通过搜索引擎、网页或新闻进行通用搜索，可以找到关于目的地的通用信息。

目标系统使用的技术可以用于研究职位空缺，因为对网络专员的需求可以推断出所使用的产品。对于攻击者来说，检查员工的个人网页（如果有）并收集即时通讯软件用户名、电子邮件地址和电话号码可能也很重要。通常情况下，关于目标的任何信息在攻击时都是有用的，因此，至少在侦察阶段，这些信息是重要的并且应该被收集。

Google Hacking（谷歌黑客攻击）是一种利用搜索引擎的所谓“高级”操作符在网络上寻找攻击者可以利用进行攻击的信息的技术。这种技术可以用于查找搜索引擎网页爬虫索引的 Web 服务器上的所有文件和信息。这些包括服务器的目录列表、使用的服务器软件的确切版本、公司内网的信息或员工的个人信息。因此，由于 Google Hacking 的利用，私密或安全敏感信息在服务器上被意外泄露，搜索引擎爬虫索引了这些信息，导致攻击者通过搜索查询即可获取它们。

其他可能的 Google Hacking 查询还包括公司的域名、安全漏洞及相关的漏洞、匹配特定漏洞的目标、用户名、密码或源代码。以下操作符代表了 Google Hacking 搜索中使用的部分操作符：

- `intitle:` 将结果限制为标题中包含紧随其表达式的文档。
- `inurl:` 将结果限制为 URL 中包含紧随其表达式的文档。
- `filetype:` 将结果限制为具有相应文件扩展名的文档。此外，必须指定指定的搜索词 `ff`。
- `site:` 将结果限制在指定域内的文档。

这些操作符现在可以几乎任何方式组合成搜索查询，并可以“调出”大量与安全相关的数据。例如，这里有一个 Google Hacking 数据库 [Long07] 的搜索查询，该数据库记录了许多网络安全领域的 Google 请求。

如果服务器权限设置不当且 Google 爬虫可以读取 `/etc/password` 文件夹的内容，攻击者可以使用此搜索查找密码文件。攻击者随后可以尝试通过字典攻击破解找到的密码文件（这些文件通常是加密的），并使用解密后的密码访问发现的系统。攻击者的另一种可能是将密后的“密码”添加到他的字典中以便进一步攻击。

域名系统（DNS）是一个层次化的、分布式的数据库，为域名分配一个或多个 IP 地址。通常，此 IP 地址对用户是隐藏，但可以进行显式查询，从而作为关于组织 IP 地址范围的进一步搜索或 WHOIS 查询的起点。[Mock87]

`NICNAME/WHOIS` 协议用于查询提供注册域名和 IP 地址目录的分布式数据库。最初，标准 [HaSF85] 仅在一个中央服务器上提供一个中央数据库，因为所有域名都由网络信息中心集中管理。随着互联网的增长，该标准进行了更新并切换到分布式数据库系统。[Daig04]。各种顶级域的管理也已交给了几个注册商，每个注册商都维护自己的 WHOIS 数据库。可以使用不同的工具或 Web 界面进行 WHOIS 查询。

DENIC（德国网络信息中心）负责分配和管理 `.de` 域名，其数据库为域名 WHOIS 查询提供以下信息 [DENI07]：

- **Holder**（所有者）：这是域名的所有者，是 DENIC 的签约方。
- **Admin**（管理员）：这是由域名所有者指定的管理员联系人，负责对域名做出决策。
- **Zone**（区域）：管理员是注册域名的技术维护者，负责域名的可用性。对于个人来说，这通常是相同的 Tech 的提供者。
- **Name**（名称）：组织、邮政编码、国家以及时间戳。可选的 Holder 和 Admin 始终有 Tech 和 Zone、电话号码和电子邮件地址。此外，域名截止日期和至少两个名称服务器会显示。攻击者现在可以使用指定的名称服务器作为起点进行搜索。关于管理员联系人的详细信息可以被社会工程学使用，如果执行以 IP 地址为参数的 WHOIS 查询，将输出 IP 地址范围，这对于被动侦察非常有用，因为可以检查响应外部的活跃系统。

主动侦察是指直接与目标系统交互以收集更多目标系统信息的技术。包括通过端口扫描发现服务器上的开放端口，以及通过操作系统指纹识别操作系统。这些技术应用在被动侦察之后。发现的系统信息可以实现更有效的攻击。

### Ping 扫描（Ping Sweeps）

网络扫描通过发现开启并响应 ping 请求的活跃系统。ping 过程本身使用互联网控制消息协议（ICMP）实现，并发送 ICMP 请求包。如果系统是活跃的，它会响应 ICMP Echo 包。可以进一步调查 IP 地址范围。

如果攻击者发现了活跃系统，可以执行端口扫描以寻找开放端口。开放端口是等待传入连接并接受连接的端口。端口扫描向端口发送 TCP 或 UDP 包并关闭端口的状态。根据设置某些标志的响应如下 [Info8b]：

- **TCP SYN Scan**（SYN 扫描）：在这里没有建立连接，仅向目标端口发送 `SYN` 包。如果系统响应 `SYN/ACK`，则该端口是开放的。由于没有建立连接，此扫描不会在服务器日志中显示为连接或连接尝试。攻击者的 IP 地址将不会被检测。
- **UDP scan**（UDP 扫描）：向目标端口发送空 UDP 包。如果答案是 ICMP 端口不可，则端口已关闭；如果没有收到答案，也将视为关闭。使用系统的开放端口，攻击者可以识别接受连接的运行应用程序。通过这些信息，攻击者可以看到系统正在执行的功能，例如对于 Web 服务器，端口 `80` 通常用于 HTTP；对于邮件服务器，端口 `25` 和 `587` 用于 SMTP。有了这些知识，攻击者可以决定是否选择此服务器作为目标，并针对现有应用程序调整其攻击。

通过操作系统指纹识别向目标发送带有特定标志的 TCP/IP 包并分析答案，从而通过与数据库对比得出所使用的操作系统。数据库包含了实验发现的不同操作系统对这些 TCP/IP 包的响应。操作系统指纹利用 TCP/IP 栈签名——不同操作系统之间不同的 TCP/IP 实现。系统可以通过创建“指纹”来响应一系列请求。用于指纹识别的请求类型可以根据使用的包类型进行分类：

- **TCP Requests**：这些请求使用 TCP 包。包包含不同的标志，并分析目标系统对这些标志的反应。
- **FIN sample**：向开放端口发送一个设置了 `FIN` 标志的包。正确的答案是不响应，但许多实现会回传 `RST`。FIN 探测类似于 TCP FIN 扫描，但假设只有关闭的端口返回 `RST`。因此，只有在安全确定请求端口由于其他扫描而开放的情况下，FIN 采样才提供关于实现的信息。
- **TCP ISN Sampling**：在这里尝试确定 TCP 实现的初始序列数以进行绑定请求。取决于操作系统，将使用不同的方法方法较旧的 Unix 系统以 64k 为增量增加，较新的系统随机增加，Linux 系统选择随机数，而微软使用一种时间相关的方法，ISN 在每个时间单位内增加固定量。
- **TCP Timestamp**：在这里检查 TCP 时间戳选项（一个带有发送者当前时间的字段）。某些实现不支持该选项，而另一些则按固定时间增加该值。
- **TCP Options**：在这里，发送的包使用了某些选项。根据答案中是否包含这些选项，可以看到支持哪些选项。
- **TCP Initial Window**：TCP 初始窗口会检查返回包的窗口大小。
- **ACK Value**：响应 `FIN/URG/PSH` 时设置 `ACK` 标志，确认号字段包含根据实现而不同的数字。大多数系统会将接收到的包的初始序列数加 1。

### 分片处理

该技术检查了分片 IP 数据包的重组。特别是，这里观察了重叠分片的重组。被动操作系统指纹识别是所述操作系统指纹识别的一种变体，它不主动发送包，而是观察传入的数据包。攻击者可以通过连接服务器、向服务器发送请求并检查服务器发送的数据包来使用被动操作系统指纹识别。由于 `TCP / IP` 实现不同，对以下字段的观察和分析可以识别操作系统 [PeCh04]：

- `TTL` 初始值 (8 位) (`IP header`)
- `Window size` (16 位) (`TCP header`)
- `Maximum segment size` (16 位) (`TCP header`)
- `Don 't fragment` 标志 (1 位) (`IP header`)
- `sackOK` 选项 (1 位) (`TCP header`)
- `nop` 选项 (1 位) (`IP header`)
- `Window Scaling Option` (8 位) (`TCP header`)
- `Start packet size` (16 位) (`TCP header`)

这些字段共同构成了一个 67 位的签名，并与数据库进行比较。由于只检查了传入的数据包，因此对源主的检查是不而易见的。

### 混合形式

某些技术既是被动的（与目标没有直接交互），也是主动的启示（通过与目标直接交互），被分配给目标，或同时在启示和攻击中使用。在这些混合形式中，最为人知的是社会工程。

### 社会工程

社会工程是一门操纵人类为了符合攻击者的利益而行动艺术。[PeCh04]。它通常用于：

- 获取对受保护资源的物理访问权限
- 获取远程访问权限
- 访问受保护的信息
- 违反其他安全控制措施

如果使用社会工程直接与（例如）目标公司的员工进行交互以获取信息，则可以被归类为主动启示。如果攻击者不与员工直接交互，而是偷听（例如两名员工之间的对话），则应被归类为被动启示。社会工程可以用于。

## 第 3 章 – 应对措施

在本节中，我们将讨论针对上述方法的某些应对措施。首先介绍一些通用应对措施，然后介绍针对被动启示、主动启示和社会工程的特殊技术。

噬 通用应对措施包括适用的安全策略、删除软件等标准文件，以及更改默认设置（如用户名和密码）。教育用户使用安全密码、处理敏感信息以及定期更新软件也是绝对必要的。

作为针对互联网研究和 Google 黑客攻击的应对措施，建议检查自己的网站并删除不需要的发布信息。如果无法做到，隐藏目录至关重要。通过创建一个包含针对各种爬虫控制语句的 `robots.txt`，可以影响搜索引擎的行为。在 HTML 头部中指定 `META` 标签允许爬虫索引搜索引擎缓存中找到的页面。使用 `htaccess` 设置密码保护区域也有助于对爬虫隐藏。可以通过 Google 搜索查询检查页面是否受到了足够的保护。另一方面，攻击者也会使用的 `WHOIS` 和 `DNS` 数据库查询是无法防止的。这是因为 `WHOIS` 条目是法律要求的，而 `DNS` 条目是调用域名所需的。因此，这些信息是公开的，而且由于查询是针对“第三方”管理的数据库，对于潜在攻击者来说，并不清楚是谁请求了这些条目。

无法防止对系统的端口扫描，但可以确保没有不必要的端口处于状态。如果定期分析服务器日志，就可以及早发现端口扫描以及由此产生的攻击准备。如果检测到此类捕获准备，有助于恢复你自己的安全预防措施。另一种主动方案是有意地打开错误的端口以欺骗潜在的攻击者。操作系统指纹识别无法防止，但可以通过服务器日志检测到。作为 `Nmap` 的一种主动应对措施是 `IP Personality`，一个内核模块，它可以通过更改 `TCP header` 中的标志位来模拟不同的系统。

## 第 4 章 – Web 攻击、XSS 与 SQL 注入

在过去的十年里，万维网迅速扩张，并且至今仍在演变。传统系统正在被动态的、可浏览的应用程序取代，这些程序托管在 Web 服务器上并访问巨大的数据库。宽带网络的持续实施为多媒体增强铺平了道路。而如今无线技术的剧烈演变为 WWW 提供了到达任何地方的机会。毫无疑问，万维网的优势在于克服了空间时间的限制。今天，我们可以舒适地坐在家里订购一台刚刚在日本生产的新手机，通过网络订购，或者点击一下就远程申请南美的一份工作。




在商业领域，Web 被利用得越来越频繁，因为它让接触客户和机会变得更加容易。银行服务现在已经在线。购物在网上进行，通过信用卡进行快速方便的支付。越来越多的电子商务公司应运而生。但对于任何在线的 Web 应用程序以及任何运行在服务器群上的电子商务，拥有适当攻击技术的恶意黑客也无处不在。当人们正在适应新技术并构建网络、使带有防火墙的 Web 服务器和防御系统更加安全时，攻击者也变得更加聪明，他们可以破解这些系统和防火墙。Web 技术的快速增长也留下了许多安全漏洞。正如我们之前提到的，本书介绍了广为人知的 Web 应用程序攻击技术，并展示了规避方法。首先，让我们概述一下 Web 应用程序架构。

传统的 HTML 页面是静态的，也就是说，它们最终会被生成，并通过页面的 `URL` 以这种形式存在于 Web 服务器上。当然，动态生成 HTML 页面也是理想的，例如为了影响调用者的近期页面数据。动态页面是由 Web 应用程序在运行时生成的。

Web 应用程序通常分为客户端 Web 应用程序和服务器 Web 应用程序。

**客户端 Web 应用程序**运行在客户端机器上。此类应用程序的已知技术有 `JavaScript`、`VBScript`、`Flash`、`Applet`。

**服务端 Web 应用程序**在服务器上执行，通常用于动态生成数据（例如从数据库）。服务端 Web 应用程序的已知技术有 `Common Gateway Interface (CGI)`、`Server APIs` 以及 `ASP`、`PHP`、`JSP` 等脚本语言。

一个常见的动态 Web 系统由 4 个组件组成：

1. Web 客户端（通常是浏览器）
2. 前端 Web 服务器
3. 服务端应用程序
4. 服务端数据库

前端 Web 服务器充当与外部交互的接口，通过 `HTML` 表单和 `HTTP` 获取 Web 客户端的输入，并以 `HTML` 页面的形式返回应用程序生成的输出。服务端应用程序与数据库配合执行事务。Web 系统的每个组件都有特定的漏洞。

以下是针对每个组件的基本攻击类型简述：

- **Web 客户端**：执行活动内容、客户端软件漏洞利用、跨站脚本（`XSS`）。
- **Web 服务器**：服务器软件安全漏洞利用。
- **Web 应用程序**：针对身份验证、授权、输入验证的攻击。
- **数据库**：通过数据库查询执行特权命令、操纵查询（`SQL Injection`）以获取过多记录。

在这些中，`XSS` 和 `SQL Injection` 被选为基于 Web 工具。

### XSS

跨站脚本（`XSS`）

跨站脚本（`XSS`）利用 Web 应用程序中的漏洞，允许攻击者将恶意脚本注入到其他用户查看的网页中。测试 `XSS` 的简单方法是输入以下内容：

```html
<script>alert(document.cookie)</script>
```

根据位置（客户端或服务端）和持续时间（永久或非永久），跨站脚本攻击分为几种类型。

在 `XSS` 中，恶意脚本被嵌入在 URL 中。例如，这可能是一个这样的链接：

`http://www.example.com/search.cgi?query=<script>alert(document.cookie)</script>`

场景：

1. Alice 经常访问包含 `XSS` 安全漏洞的 A 网站。
2. Alice 点击链接。
3. 恶意脚本在 Alice 的计算机上打开一个 HTML 页面。
4. 该 HTML 页面在 Alice 的计算机上以其权限身份执行。

在这种类型中，被操纵的脚本位于服务端且不是永久的。后续执行脚本没有问题。例如，服务器上的搜索功能在获取搜索词作为输入时未进行过滤，并输出如下内容：

你搜索的：“search term”是 `<script>alert(document.cookie)</script>`

场景：

1. Tom 创建了一了一个被操纵的 A 站 URL 并发送给 Alice。
2. Alice 访问了该操纵后的 URL。
3. URL 中嵌入的脚本将在 Alice 的浏览器中执行，就像直接来自 Web 页面一样。

在 `XSS` 类型 2 中，被操纵的脚本代码被永久写入网页。这是最危险的形式，因为它影响许多用户。这种类型 2 的工作方式与类型 1 类似，只是输出持久地留在页面上。

示例：

1. 再次包含 `XSS` 安全漏洞的 A 网站允许用户发布新闻或其他内容。
2. Tom 在该网站上发布了一条消息：

   “一个非常好的网站！<script>alert(document.cookie)</script>”

3. 当用户查看新闻时，脚本代码在用户机器上运行，因此可以在 Tom 不知情的情况下窃取 cookie 等其他内容。

网站运营者永远不要信任用户输入。所有输入的输入值都必须经过检查和过滤。你应该定义精确的输入表，并仅允许此类输入。

XSS 攻击实际上是在 `<script>` 标签和 `</script>` 标签（或 `<object>`、`<applet>`、`<embeded>`）之间嵌入经过操纵的脚本代码。如果删除了这些标签，恶意脚本代码将不再执行。你可以通过字符串替换来过滤这些标签，例如使用以下 PHP 代码：

```php
function filter ($ input) {
  $ input = ereg_replace ("<script>", "", $input);
  $ input = ereg_replace ("</ script>", "", $input);
  $input = ereg_replace ("<object>", "", $input);
  $input = ereg_replace ("</ objectt>", "", $input);
  $input = ereg_replace ("<apllet>", "", $input);
  $input = ereg_replace ("</ applet>", "", $input);
  $input = ereg_replace ("<embeded>", "", $input);
  $input = ereg_replace ("</ embeded>", "", $input);
  return $input;
}
```

这移除了所有带有危险标签的条目，例如上面的窃取 Cookie。过滤后的脚本代码看起来像这样：`alert (document.cookie);`。当然，它不再有危害了！

在某些情况下，输入应该原样清晰地打印。你可以通过转义用户输入来实现，即将所有特殊字符替换为它们在 HTML 中的对应项——所谓的转义序列。这些转义序列是一系列表示特殊字符的普通字符序列。例如，字符串 `<script>` 将显示为普通字符串 `<script>`，浏览器稍后将其显示为字符串 `<script>`，这不再被识别为标签。

```php
function escaping ($ input) {
  $ input = htmlentities ($input);
  return $input;
}
```

这种方法处理 XSS 的简单且安全的方法。尽管如此，它有一个很大的缺点：所有特殊字符以及所有标签都被阻止了。当然，用户无法使用 HTML 标签来格式化他们的文本。

通过关闭浏览器中的 ActiveScripting，你可以防止客户端的 XSS——没有任何操纵的脚本代码在客户端执行。尽管如此，这无法帮助纯 HTML 注入（例如使用 `<iframe>` 标签……），但它不像真实的 XSS 那样危险。它在任何情况下无法从客户端窃取 Cookie。

## 第 5 章：SQL 注入

SQL 注入是对应用程序中的事务 SQL 查询进行操纵，以引发意外反应。[ScSh02] 通常，Web 应用为用户提供了与数据库通信的接口，当 Web 应用没有妥善过滤用户输入时，此时会出现安全漏洞，黑客可以使用 `SQL` 命令向数据库发送数据、破坏数据，甚至入侵底层系统。

根据攻击方式，SQL 注入通常分为三个主要类：SQL 操纵、代码注入、函数调用注入。将在后续章节中通过示例进行解释。

### SQL 操纵

是指正常运行的数据库查询受到 SQL 语句的影响。通常情况下，攻击者被插入到数据库返回的 SQL 语句的 `where` 子句中。因此，操纵 `where` 子句可以改变整个 SQL 语句。

`http://www.nosecurity.com/mypage.asp?user=hacker&pass= 'hack '` 变成了 Web 应用查询数据库的 SQL 语句：`Select * from table where login = 'hacker ' and password = 'hack '`。在执行此查询后，如果表中存在这样的用户和密码，用户将成功登录。现在密码被赋值为 `' or 1 = 1 -`。Web 应用的 SQL 语句如下：`Select * from table where login = 'hacker ' and password = ' ' or 1 = 1-`。只要存在用户 hacker，就会登录，无论密码是什么。

以下是表单字段中的典型输入，用于判断带有 SQL 注入漏洞的应用程序是否脆弱：

- 删除数据库表：`'; drop table users--`
- 关闭数据库：`'; shutdown--`
- 无需密码验证：`no matter 'or ' a '= ' a '`
- 仅通过用户名验证：`admin ' -`

双连字符（`--`）将后续所有数据转换为注释。因此，其他条件可以忽略不计。

### 代码注入

是指在命令流中注入新的 SQL 命令的过程。如果每个数据库查询支持多个 SQL 命令，那么这种类型的攻击将特别危险。请考虑一个使用 IIS、ASP 和 MSSQL 构建的示例：

## 第 6 章：钓鱼

钓鱼是一种自动化的身份盗用行为。它通过向接收者发送伪造邮件，试图诱骗他们分享私人信息，如信用卡号或银行账户密码。最重要的是，发送至虚假网站的邮件会诱导他们输入隐私数据。为了获得信任，该网站必须与钓鱼者模仿的原站非常相似。“Phishing”一词显然是“password fishing”（密码钓鱼）的变体，因为钓鱼者抛出“鱼钩”，希望有几个受害者上钩。

尽管钓鱼的大概念是让受害者进入虚假网站，但有几种技术使这一想法变为现实。目前介绍了三种最广为人的方法：冒装、转发和弹出窗口。

- **冒装（Impersonation）**：是最简单且最流行的钓鱼方法`[LiVi02]`，其通过一个精心设计的虚假页面让受害者访问。虚假网站包含真实网站的图像，这些图像并不一定复制到钓鱼服务器，只需从原始网站备份即可。如果受害者在输入框中输入数据并点击`Submit`，该数据将通过`Script Handling`脚本发送给输入框中的钓鱼者。该方法的重要部分是编写一封带有虚假页面链接的钓鱼邮件。此类邮件看起来像下方的邮件：关键受害者的邮件语言具有攻击性。虚假页面应与原始页面相同，因此你无法立即看出它们的不同。例如：

  原始：`http://www.securitybank.com/bank/cgi/show?id=45`

  虚假：`http://www.securitybank.net/bank/service/show?prameters=1`

- **转发（Forwarding）**：是一种钓鱼技术，利用邮件获取私人数据，然后引导受害者进入真实网站。这种钓鱼风格在 eBay、PayPal、Amazon 等公司非常流行……它们经常向客户发送邮件分享优惠和新服务。通过这种技术，登录字段（或特定输入字段）会被嵌入邮件中。当受害者输入数据并点击`Submit`时，他们会被带到真实页面，但他们的数据会被发送给钓鱼者。此类邮件看起来如下：登录脚本实际上与`Impersonation Script`相似，只是在将受害者数据发送给钓鱼者后，登录脚本会带你进入真实网站。受害者更容易被这种技术欺骗，因为没有显示虚假 URL。很难发现该 HTML 邮件来自另一个网站。

- **弹出窗口攻击（Popup Attack）**：是一种在将受害者重定向到真实网页期间，为钓鱼服务器打开弹出窗口的技术。弹出窗口的 HTML 代码可以如下制作：

```html
<BODY bgColor = #ffffff onload = "window.open ('phish.html ','popup ',' 'top = 150, left = 250, width = 250, height = 200, toolbar = no, location = no, scrollbars = no, resizable = yes ' ) </BODY>
```

如果受害者点击邮件中的链接，虚假页面会立即变成真实页面。页面会被重定向并打开带有输入字段的弹出窗口，所有输入的内容将发送给钓鱼者。然而，这种技术在今天很少见，因为大多数浏览器都使用了弹出窗口拦截。

由于钓鱼邮件始终包含 HTML 表示，且转发技术仍然涉及脚本，通过关闭邮件程序的 HTML 显示和脚本，可以禁用虚假的 HTML、链接和脚本。所有邮件都将以纯文本形式显示以防范钓鱼。使用钓鱼保护系统，将邮件头与最新的钓鱼者列表进行比较，并检查链接，无论它们是否真实显示。永远不要打开未知来源发送的邮件。安装反垃圾邮件系统来过滤垃圾。

## 第 7 章：垃圾邮件

随着互联网的快速传播以及电子邮件在商业和个人领域的激增，发送不受愿的批量邮件（通常称为垃圾邮件）也变成了一个巨大问题。本报告论文展示了电子邮件系统的哪些基本功能实现了垃圾邮件发送，以及发送者是如何操作的。此外，还介绍了防止发送垃圾邮件的各种方法以及解决当前电子邮件系统问题的努力。

垃圾邮件最广泛使用的国际术语是`Unsolicited Bulk E-mail (UBE)`——德语为“不受愿或未请求的批量邮件”。除了电子邮件垃圾邮件外，其他媒体中也有垃圾邮件，例如即时通讯系统中的垃圾信息、书籍和博客中的评论垃圾邮件，以及通过自动拨打磁带录音公告的电话垃圾邮件。本文专门关注 UBE 意义上的电子邮件垃圾邮件。“Spam”一词最初源于 Hormel 食品公司的垃圾产品`SPAM – 调味猪肉和火腿肉`。该产品自 1936 年以来可用，在 1970 年被英国喜剧剧《蒙提派森的飞行马团》的一个短剧中采用，它作为菜单上每道菜的一部分出现，并受到一组唱歌的维京人的大声支持。`[Merr04]`、`[Pyth70]`。该词在短剧中出现了 132 多次，这解释了它与电子邮件垃圾邮件的联系。

## 引言

虽然垃圾邮件在几年前才出现，但今天如果没有大规模的反垃圾邮件措施，使用电子邮件几乎是不可能的。尽管不受愿的邮件问题已在 1975 年被`Postel[75]`意识到，并在 1982 年被`Denning[82]`意识到，但在当时实践中并不重要。1994 年 4 月 12 日，向成上万个新闻组发送信息是第一个重大商业新闻`[Camp94]`。1997 年，垃圾邮件问题在官方网上得到了关注：美国贸易委员会处理了这一问题，并建立了一个反腐工作组`[Comm97]`。在过去的几年里，垃圾邮件发送激增，到 2005 年占总邮件流量的 80%–85%`[Group96]`。遗憾的是，尽管反垃圾取得了进展，比盖茨的说法并未证实：“两年后垃圾邮件将得到解决。我承诺一个没有垃圾邮件的世界。”（微软 CEO 比盖茨，2004 年 1 月）

垃圾邮件可以分为几类。`[Lab06]`、`[Mars]`

- 成人垃圾邮件：例如促销壮阳药物、色情优惠或约会服务。
- 金融要约：例如贷款、影响股价的广告或据称的中奖利润。
- 旨在获取在线服务身份信息的虚假信息。

## 第 8 章：电子邮件系统的功能

发送垃圾邮件与电子邮件系统的工作原理密切相关。下文将对此进行解释。

当前的电子邮件系统基于 1982 年指定的`[Post82]`以及在 2001 年由`ESES`、`[Klen01]`更新的`SMTP`标准。它就像互联网本身——去中心化，并规定了邮件从一个服务器到另一个服务器的传输。服务器上的服务程序被称为邮件传输代理（`MTA`），负责接收和处理消息。如果它收到的邮件发送给本域域内的接收者，它将其放入对应用户的信箱中。否则，它将通过`SMTP`将邮件发送到相应的电子邮件服务器，该服务器是通过`DNS`确定的。列表 1 显示了通过`SMTP`传输的消息。

### 列表 1：SMTP 对话

```text
220 somehost.net ESMTP Exim 4.63 #1 Mon, 26 Nov 2007 23:10:21 +0100
HELO anotherhost.net
250 somehost.net Hello localhost [127.0.0.1]
MAIL FROM: Bill <bill@Microsoft.com>
250 OK
RCPT TO: Richard@somehost.net
250 Accepted
250 accepts
DATA
354 Enter message, ending with "." on a line by itself
From Steve <steve@Microsoft.com>
To: Richard@somehost.net
Subject: Linux violates our IP
Hello, nothing unusual to say,
250 OK id=1IwmAg-0008ED-LA
QUIT
221 somehost.net closing connection
```



在互联网早期，邮件的交付只需交给本地 `MTA`，这是当时流行的 `UNIX` 系统的标准功能。如今，电子邮件客户端（也称为邮件用户代理，`MUA`）通常将发送邮件发送到提供商的电子邮件服务器，再由其进行进一步传输。它同样使用 `SMTP` 协议，但是允许密码的增强版本 `ESMP`。将 `SMTP` 协议用于两种不同的应用程序——终端用户消息提交（"submission"）和 `MTA` 之间的邮件传输（"transfer"）——使得 `MTA` 的配置变得复杂且易错。因此，根据消息提交规范 [GeKl98]，建议通过不同的 `TCP` 端口和一些协议扩展来将终端用户的消息持久化分离。

中继是指通过 `SMTP` 接受和转发消息。过去，`MTA` 习惯于接受任意消息并在必要时转发。这种配置被称为开放中继（Open Relay）。随着后续实施，这导致了垃圾邮件的发送，因此这种做法在很大程度上被放弃了。现在，`MTA` 通常只接受指向自己域的邮件，除非发送者通过密码验证。向第三方服务器传输消息在故障转移安全方面起着作用。如果无法到达电子邮件服务器，消息可以转发到“邮件交换器”（`MX`，在 `DNS` 中指定），它会被缓存并在负责服务器再次可用时进行投递。

技术上，电子邮件只是一段文本，由头部（`Header`）和消息部分（`Body`）组成。头部包含元信息，如发送者、接收者、传输时间和操作员。消息部分包含消息本身。然而，头部仅作为接收者的额外信息。当通过 `SMTP` 协议发送时，会显式指定发送者和接收者。这些信息被称为信封信息（Envelope Information），消息接收者是不可见的。它们可能与消息头部中的信息不同（另见列表 1）。因此，信封信息包含了消息实际发送的所有电子邮件地址。而在头部中，这些地址的某些可能在“to”字段（接收者），另一些在“CC”字段（抄送），另一些完全不在（密抄，`BCC`）。因此，头部信息可能包含任何值，特别是错误的发送者地址。此外，信封详细信息在传输过程中通常不会经过检查。特别是接收服务器无法对发送者地址验证，因为 `SMTP` 标准并未规定允许哪些服务器为某个域发送邮件。因此，电子邮件消息的真实性并不由电子邮件系统保证。

原则上，如果 `MTA` 接受了消息，它就对该消息负责。如果它无法交付消息，它会向发送者发回退信邮件（bounce message），说明交付失败的原因。例如，可能由于目标主机上的信箱不存在或已满。如果是临时错误（例如目标主机无法访问），它会尝试长期投递消息。

## 第 9 章 – 原因

下文指出了有利于发送垃圾邮件或从根本上使其成为可能的不同原因。

垃圾邮件的发送成本非常低，因为只需要一台连接到互联网的计算机。这使得发送垃圾邮件变得具有吸引力，因为由于发送成本低，只需要极小比例的接收者对消息做出就能盈利。

开放中继使得批量发送消息变得容易，因为垃圾邮件者只需要发送一次带有大量接收者的消息，然后由开放中继处理后续传输。此外，开放中继允许垃圾邮件发送者发送垃圾邮件，即使自己的地址已经被加入黑名单。开放中继也可能由于 `MTA` 配置错误而意外产生。

僵尸电脑是互联网用户使用的计算机系统，它们被木马受到外国控制并形成了大量的所谓的僵尸网络（botnets）（见其他语义论文）。这些电脑经常在所有者不知情的情况下被用于发送垃圾邮件。赛门信安全公司在 6 个月内监控了超过 500 万台被僵尸网络感染的计算机。[Corp07]。除了直接通过 `SMTP` 发送消息外，某些木马还会尝试获取电子邮件提供商服务器的凭据，并在验证后使用它们发送消息。

由于在没有进一步技术措施（如电子签名）的情况下无法检查消息的真实性和者信息的正确性，因此很难区分垃圾邮件和普通消息。垃圾邮件必须手动筛选和删除这一事实是接收者产生成本的主要原因。

由于互联网的国际性质以及缺乏统一的法律依据，针对垃圾邮件者没有统一的方法。虽然一些国家现在制定了反垃圾邮件法，但另一些国家没有起诉垃圾邮件者的法律依据。

由于总是根据 `IP` 地址定位一个或多个服务器，并由公共部门将其下线，垃圾邮件的传输通常由外部计算机执行。以前通常是开放中继，而现在几乎完全是僵尸网络。

## 第 10 章 – 垃圾邮件、钓鱼攻击：应对措施

应对措施可以分为在现有系统内运行的操作以及试图弥补邮件系统弱点的操作。为了避免对预期的邮件流量产生干扰，使用列出的程序配合常规通信伙伴的名单来排除来自他们的消息是有意义的。预设方法通常在邮件服务器上使用，但某些也可以在邮件客户端中实现。

以下许多方法试图将垃圾邮件与合法邮件区分开来。本节解释了如何处理被分类为垃圾邮件的消息。

拒绝分类为垃圾邮件的消息的优点是它们不会给邮件系统和终端用户带来负担。缺点是误分类的消息无法到达接收者。实现这一点有两种方法：

- **接受消息并稍后标记及创建退回邮件（bounce message）**：优点是技术上先接受消息稍后进行垃圾邮件分类更容易。然而，由于退回邮件是发送到（通常是虚假的）发送者地址，这种方法会导致无关方承受巨大的负荷，因此不适用。
- **在 `SMTP` 对话期间拒绝消息（见列表 2）**：这种方法要求发送端在传输过程中进行垃圾邮件检查，因此对技术要求更高。直接拒绝也可以导致邮件地址从垃圾邮件发送者列表中删除，因为显然无法送达给他们。如果是合法消息，发送者将获知问题，发送被拒绝接收的 `MTA` 会生成一条退回邮件。

静默删除消息的益处与拒绝消息相同。然而，如果是一封合法消息，发送者必须假设消息已成功送达，而接收者却从未收到。这就是为什么在实践中静默丢弃消息是没有意义的，特别是由于其实现上更简单之外，它与在 `SMTP time` 拒绝消息相比没有任何优势。

最常见的方法是标记问题消息并将其移动到自己的垃圾邮件文件夹中，以便接收者检查分类结果并删除消息。这种方法的优点是误分类的消息仍然到达接收者。但在实践中，出现了一个问题：收到了大量垃圾邮件，用户经常在不看消息内容的情况下清空垃圾邮件文件夹。那么效果与静默删除相同，即比拒绝消息更糟糕。

通常会将多种程序结合。因此，在一个误报率很低的分类方法中，可以直接拒绝消息，而仅在不那么明确的方法中进行标记。这结合了两种方法的方法的优点。

本节介绍了一些可以在现有邮件系统内部使用的反垃圾邮件措施。

在接收消息时，会对发送者的 `IP` 地址进行扫描或查询。最常见的类型是过去发送过垃圾邮件的服务器的黑名单（通常是开放中继服务器）。还有违反 `SMTP` 标准的服务器黑名单和拨号地址列表。发送垃圾邮件服务器的黑名单通常用于直接拒绝来自这些服务器的消息。这反过来给服务器运营商施加压力，使其控制通过其服务器投递的消息。使用黑名单非常有效，通常误报率较低。然而，黑名单中总是存在运营商误伤目标的陷阱。因此，自 2005 年 8 月以来，所有的 `.de` 域名都列在运营商 `RFC-Ignorant.org` 的列表中。这些黑名单条目可以手动或自动添加，例如通过蜜罐技术（honeypots）。

灰名单是黑名单的一种弱形式。邮件在第一次尝试投递时会被之前未知的发送者拒绝，并缓存在灰名单中，但在稍后的第二次尝试中会被接受，并将发送者保存为已知。该方法基于 `SMTP` 标准，即当目标主机报告临时错误时，以不断增加的间隔重新投递邮件。发送垃圾邮件通常会跳过这第二次尝试。代价是收到新通信伙伴的第一条消息会有延迟，但该过程非常有效。作者在自己的服务器上观察到，灰名单中的消息只有少于 1/3 被再次投递。通常，该过程会与不遵守 `SMTP` 标准或在投递尝试中使用切换服务器的大型提供者的邮件服务器名单结合使用。

除了黑名单外，还有存储垃圾邮件本身哈希值的列表。对于大量提交垃圾邮件的订阅者，“新的”垃圾邮件会被及时投递，并由请求此类列表的邮件服务器进行适当处理。例如“分布式校验和和清理中心”（`DCC`，`[Soft]`）。

垃圾邮件过滤器根据内容对消息进行分类，通常使用评分标准的组合：

- 通常使用一组固定规则，这些规则包含经常出现在垃圾邮件中的加权标签，例如过度使用大写字母、图像与文本的高比例，或潜在推销工具的伪装名称。通过结合大量的规则，识别率非常高，但规则必须始终更新，因为垃圾邮件发送者会刻意保护其消息免受已知垃圾邮件过滤器的检测。
- 学习方法（如贝叶斯过滤器 `[AKCP + 00]`）基于用户反馈。在此过程中，用户将分类错误的消息（包括误报（正常邮件）和未识别的垃圾邮件）传回过滤器，过滤器会逐渐适应。贝叶斯评分可以存储在通用数据库或个人数据库中。这种方法的巨大优点是，与固定规则不同，它能够适应个人。

因此，在一个误报率很低的分类方法中，可以直接拒绝消息，而仅在不那么明确的方法中进行标记。这结合了两种方法的优点。作者在自己的服务器上观察到，灰名单中的消息只有少于 1/3 被再次投递。通常，该过程会与不遵守 `SMTP` 标准或在投递尝试中使用切换服务器的大型提供者的邮件服务器名单结合使用。

垃圾邮件过滤器根据内容对消息进行分类，通常使用评分标准的组合：……[由于逻辑原因省略]……扫描器检测消息中包含的病毒。对于合法消息，检测率很高，且误报率较低。

## 第 11 章 – 立法

在美国，`CAN-SPAM Act`（2003 年控制未经索求的色情和营销攻击法案，`[Cong03]`）已于 2003 年 12 月生效，并导致了一系列定罪，其中包括监禁判决。

在欧盟，垃圾邮件的术语是“未经索求的商业电子邮件”（UCE），因此它排除了非商业性的垃圾邮件信息。2003 年 10 月 31 日，一项关于数据保护的欧盟指令`[Unio02]`生效，该指令规定，只有在收件人事先同意的情况下才能发送电子邮件广告，前提是邮件不是为了维护现有的客户关系。它还禁止使用带有缀的“发送者”和“非法”地址，因为垃圾邮件发送者频繁使用这些地址。

然而，该指令本身并非法律，而是必须首先由成员国将其转化为具体的法律。在德国，这是通过 2007 年的《电信媒体法》（TMG）实现的。该法规定，发送垃圾邮件最高可面临`EUR 50,000`的罚款。然而，2004 年 4 月 1 日更新的《反不正当竞争法》（UGW）中也明确提到了垃圾邮件。但这仅通过消费者保护协会这一迂径为接收者提供了法律依据。与美国不同，垃圾邮件在德国仅在民法中被处理，而不受刑法管辖。

以下判决说明了美国额外的刑事起诉与欧洲民事法之间的区别。

* **美国，2004 年 11 月**：Jeremy Jaynes 根据弗吉尼亚州法被判处 9 年监禁`[Brie06]`。
* **美国，2006 年 9 月**：Daniel Lin 根据`CAN-SPAM Act` 被处 `$ 10,000`罚款并监禁三年。`[Kuri04]`。
* **荷兰，2007 年初**：一名荷兰人因发送垃圾邮件信息被罚款`€ 75,000`。`[Kuri07]`。

近年来，通过利用黑名单打击开放中继服务器和限制从拨号地址发送电子邮件，电子邮件管理已变得更加规范。尽管更先进的技术反措施遭到了垃圾邮件发送者巧妙花招的抵制，但仍然减轻了终端用户的负担。然而，新的标准（如日益普及的 `DKIM` 签名程序）表明，消除现有电子邮件系统的弱点将使在未来极大地增加垃圾邮件投送的难度。

## 第 12 章 – 蜜罐（Honeypots）

这项工作是关于“蜜罐”这一概念的。在过程中，我将首先讨论蜜罐到底是什么，并尝试给出一个恰的定义。之后，我将解释蜜罐可以提供哪些服务，哪些不能提供。在此背景下，我将介绍不同类型蜜罐之间的第一个区别。然后，我解释了它们是如何不断发展的。第三部分将处理蜜罐的类别划分以及每个类别的特征。之后，我将强调使用蜜罐的优缺点，并详细地描述一些蜜罐的示例。

当互联网在 1970 年左右首次投入运行时，人们完全不知道它会向何种方向发展。但随着互联网的引入，人们发现了许多意想不到的可能。今天，没有互联网的生活是不可想象的。你可以与世界各地的人交流、交换数据，以及更多。由于互联网的巨大增长，新的技术正在不断被尝试和开发，以扩展这种媒介的应用范围。与此同时，作为一种简单的通信媒介，互联网已成为私人网络和业务网络共同发展的平台。如今，除了聊天室或电子邮件等私人通信外，银行转账或在线订单等业务交易，以及适当的在线注册和注销也成为可能。

但互联网也带来了许多危险。巨大的增长伴随着对互联网上海量数据流日益增多的的攻击。因此，对数据保护的需求显著增加。这里形成了一场攻击者与互联网安全专家之间的真实竞逐。攻击者总是试图寻找新的方法和手段来获取重要数据，而安全专家则通过开发保护机制来反击。尽管如此，总会有新的方法出现，因此在未来研究新的安全技术也至关重要。蜜罐就是这里重要的辅助。这就是为什么我将在下文中介绍这些内容。

在接下来的章节解释蜜罐的属性之前，首先必须找到蜜罐的一个合适定义，以便确切知道蜜罐是什么以及它们能做什么。从系统角度来说，蜜罐是作为攻击者的“诱饵”的系统。在网络内部，它们不提供有意义的服务，因此不会从系统内部直接访问，所以任何尝试联系它们的行为都会导致攻击者无法获取系统配置。

寻找一个清晰的定义并不容易，因为有很多种。之所以有这么多不同的定义，是因为蜜罐可以应用于许多不同的互联网应用。与互联网上的许多其他安全技术不同，它们不是针对特定问题的，而是试图覆盖尽可能宽的带宽范围。例如，防火墙的设计是为了防止攻击者访问系统。相比之下，蜜罐不仅尝试检测未经授权的系统访问，还尝试检测木马、蠕虫和其他攻击。在这一过程中，蜜罐只收集与计算机攻击直接相关的的数据，并在必要时对其进行评估。因此，蜜罐在攻击及其方法论方面处理的是较少但高度相关的数据，而防火墙和防病毒软件等其他程序则需要处理海量数据，因为它们持续地控制整个数据流，以与已知模式进行匹配，或监控所有程序对系统资源的访问权限。

在 Lance Spitzner 的著作《蜜罐：追踪黑客》（Honeypots Tracking Hackers）中，可以找到一个很好且在我看来非常好的定义。在书中，蜜罐被定义为：蜜罐是一种价值在于被攻击或被破坏的安全资源，而这正是蜜罐与其他安全技术的区别。人们希望通过对蜜罐进行攻击，来学习关于攻击本身以及攻击者自身的新知识。

例如，它们可以检测并分析蠕虫攻击，或者可以在早期识别并指出未经授权的系统访问。尽管应用程序可能的用途如此迥异，蜜罐本身也大不同。你可以大致将蜜罐分为两类：生产蜜罐和研究蜜罐。

**生产蜜罐**（Production honeypots）主要用于公司和私营部门。使用这种蜜罐，通常只能确定攻击的存在。然而这也有优点，即这些蜜罐更容易处理。

**研究蜜罐**（Research honeypots）顾其实名，用于研究目的。使用这类蜜罐不仅可以检测攻击，还能收集并评估大量关于攻击及其攻击者的信息。这是为了获得对攻击者方法和工具的新见解。这些发现随后被用于开发新的安全技术，以在未来更好地保护系统。蜜罐比生产蜜罐复杂得多且难以使用。

除了蜜罐的类型区分外，还可以对所有蜜罐进行分类。总共有三类：低交互、中交互和高交互蜜罐。分类取决于攻击者与蜜罐有多少种交互可能性。将在稍后的章节中对每个类别给出更详细的解释。

在对蜜罐定义和首次介绍之后，现在是时候看看它的起源了。蜜罐的概念已经存在了一段时间。然而，蜜罐的概念当时还未以目前的名称为人知。直到最近，蜜罐的概念才真正流行起来。

1990 年，关于这个主题有两个不同的出版物。第一本是 Clifford Stoll 写的一本名为《金丝雀》（The Cuckoo's Egg）的书。Clifford Stoll 当时正在处理计算机系统，他发现攻击者利用了该系统的数据。但他没有抑制这种行为，而是决定让攻击者继续并进行观察。这给了他收集大量关于攻击者的机会。他观察的系统在当时意义上尚未被称为蜜罐，它是一个具有敏感数据的系统。但这正是蜜罐的早期意义。然而，通过这本书，蜜罐的早期方法和想法才广为人知。

第二次发布来自 Bill Cheswick。这是一篇名为《与黑客诱导、持续并研究的夜晚》（An Evening with a Cracker Which Is Lured, Endured, and Studied）的论文，描述了一个专门设计用来被攻击的系统。Stoll 的书也描述了攻击者如何尝试访问他的系统。蜜罐历史上下一个重要的日期是 1997 年。那一年发布了首个欺骗工具包（DTK），由 Fred Cohen 编写。该蜜罐的主要目的是收集有关攻击者的活动并迷惑他们。在接下来，作为 DTK 的扩展，开发了另一个名为 `CyberCop` 的蜜罐产品。第一个特点是 `CyberCop` 不在 Unix 上运行，而是在 Windows 上。第二个重要的是 `CyberCop` 可以运行各种系统。尽管该产品具有许多优点且易于使用，但它在市场上从未真正成功过。

1998 年，由 Marty Roesch 开发了一个名为 `NetFacade` 的程序。它能够模拟七种不同的应用程序，允许了许多系统。尽管该程序并不广为人知，但它对蜜罐的开发有很多好处。同年开发了 `BackFence`，该程序将在后续章节中进一步阐述，它是易于使用的，尽管其功能有限。第一次出现了蜜罐概念 `Honey`，它允许在没有太多知识的情况下进行下载和应用。

1999 年，最后，蜜罐项目（Honeynet Project）成立了。该项目由志愿者安全专家组成，专注于蜜罐的使用。这些将在后续章节解释。自 2000 年以来，由于攻击的快速增加，蜜罐被使用得越来越多，得益于其良好的结果，并在对抗攻击中变得日益被接受。

在蜜罐的定义中，已经简要介绍了两种蜜罐。这两种类型是生产蜜罐和研究蜜罐。首先，生产蜜罐用于检测和指示入侵，以便在必要使用适当的安全技术进行对抗。另一方面，研究蜜罐不仅用于检测和对抗攻击，还用于了解攻击者及其方法。此外，蜜罐还可以分为三个类别。这些是低交互、中交互和高交互蜜罐。蜜罐的分类顾其实名，取决于与蜜罐交互的强度。通过蜜罐的分类，人们还有在它们之间进行比较。比较选项也有助于选择哪种类型的蜜罐。然而，人们必须清楚用蜜罐做什么。例如，如果你只想检测和监控对系统的未经授权访问，那么低交互蜜罐就足够了。另一方面，如果你想了解一些关于攻击者方法，就必须选择高交互复杂的蜜罐。然而，在选择蜜罐时，应该注意与蜜罐交互的机会越多，安全风险越大。将在后续章节中更详细地描述蜜罐类的不同表达式和属性。

低交互蜜罐的特点是功能更受限制。因此，它们也有易于使用的优点。例如，该类的蜜罐可以用来确定入侵何时发生。此外，人们可以确定攻击者的 IP 地址、端口和攻击目标。然而，低交互蜜罐不提供更多功能。因此，人们获得的关于攻击和攻击者的信息相当少。由于这种“简单性”，该类的蜜罐易于安装，而且非常易于使用。用户界面通常非常直观且易于理解。当然，这些蜜罐的功能限制也很大程度上限制了潜在攻击者可能与系统进行的交互。这具有优点，即安全风险较低，因为攻击者没有机会攻击和接管重要系统。低交互蜜罐主要用于私人用途。

中交互蜜罐类具有更多功能，因此与蜜罐提供了更多的交互可能。由于这个原因，人们可以收集并利用更多攻击者的信息。交互水平的增加也使得处理和安装更加困难。这类蜜罐的复杂性处于低交互和高交互蜜罐之间。然而，交互增加的缺点是也增加了安全风险。这是因为随着交互水平的提高，攻击者面对的是一个几乎真实的系统。如果攻击者破解了蜜罐，该系统就可以被用来攻击其他系统。该类的优点是你可以收集更多关于攻击者的信息。

高交互蜜罐具有最高的复杂性，并代表了许多真实的应用程序。这使得在入侵期间收集大量信息成为可能。它不仅收集攻击攻击的信息，还提供有关攻击者能力的信息。随着交互水平的增加，该类的安全风险非常高。这是因为入侵蜜罐的攻击者可以攻击其他系统并造成巨大损害。操作这种蜜罐需要大量的知识，因为安装和操作都复杂得多。

蜜罐相对于安全技术面临的第一个优点是它们的易用性。为了能够使用它，需要非常熟悉该主题，蜜罐足以安装并进行某些修改。这使得处理比其他技术容易得多。正如在前文中提到的，它需要更多知识。然而，最初一个简单的蜜罐可以在不需要知识的情况下运行。这给了大家与蜜罐交互并观察攻击者的机会。蜜罐的另一个大益处是它们收集的数据量。由于其他技术，收集了大量数据。在这里的问题是它们的恢复。许多收集的数据是没有意义的，因此对于分析是不必要的。尽管如此，安全技术必须告知哪些数据是重要的，哪些是不重要的。这导致了大大减少的数据量，不会影响系统。分析揭示了安全技术中的潜在错误。第三大优点是硬件要求。由于互联网流量日益增加，对硬件有着相应的要求。蜜罐的优点是它们需要的资源更少，因为它们只有在被实际访问时反应。作为第一个示例，我想介绍一个名为 `Back Officer Friendly` 的简单蜜罐。第二个示例将是一个名为 `honeyd` 的更复杂的蜜罐。作为最后一个应用，我们将转向蜜罐（注：原文此处为 `turn to honeynets` 疑似笔误，此处根据语境保持逻辑处理）。

蜜罐的第一个大缺点是它们带来的风险。这种风险存在，如果攻击者入侵了蜜罐，它就可以被用来攻击其他系统。风险和损害取决于蜜罐的交互水平。正如在最后一章所述，蜜罐做得越多，危险就越大。下一个问题，也是蜜罐的另一个缺点，蜜罐不观察周围发生的事情，只影响它自己。因此，即使网络上有攻击，蜜罐也没有反应，因为它本身没有被攻击。蜜罐只有在成为攻击目标时才会反应。另一个主要缺点来自于将系统识别为蜜罐。这可能导致攻击者在未来绕过蜜罐并专注于其他系统。此外，攻击者可能会故意利用蜜罐的存在知识来访问其他系统。例如，攻击者可以用攻击轰炸蜜罐并分散用户的注意力，直到他可以无阻地攻击其他系统。在已经提到的研究蜜罐中，识别会导致错误。这是由于攻击者可以在攻击期间故意留下关于自己和方法的虚假信息。但当通过这些信息得出结论时，会导致错误的结论。如果这些失败进入了下一个版本的安全软件，就会产生巨大的问题。这种方式，它可以被操纵，并且不是保护系统，而是创建新的。

蜜罐的功能现在已经详细解释，是时候看一些实际示例了。当然，今天有很多蜜罐在使用。因此，接下来介绍了三种不同的蜜罐，基于此可以很好看到不同的应用可能性。

我想介绍的第一个示例是名为 `Back Officer Friendly` 的简单蜜罐（简称 `BOF`）。这是目前最简单的蜜罐之一，可以归类为低交互蜜罐。`BOF` 可以很好地用作生产蜜罐，但不适合作为研究蜜罐。原因是该程序的功能非常有限，而且在攻击情况下，也收集很少关于攻击者及其方法的信息。在详细解释功能之前，关于 `BOF` 有几句话。`BOF` 最初被构想为一个蜜罐，但实际上是作为一种防御措施开发的。Marcus Ranum 在 1998 年开发了 `BOF`，他的目标是创建一种揭示此类活动的软件。因此，`BOF` 是巨大的危险，因为攻击者可以在不引起注意的情况下渗透它。`BOF` 的过程描述如下：程序可以监听系统的七个不同的端口。如果尝试连接这些端口之一，`BOF` 实际上会建立一个完整的 TCP 连接，记录该尝试并触发报警。`BOF` 在设置后立即终止连接。尽管 `BOF` 功能非常有限，但它非常适合检测对系统的攻击并找到良好的安全方法。

第二个示例是一个名为 `honeyd` 的更复杂的蜜罐。由 Niels Provos 开发的 `honeyd` 是一种用于 Unix 系统的蜜罐。它是免费的，并且不仅可以收集大量信息，还可以渗透攻击者。由于 `honeyd` 能够模拟真实系统，这使得交互成为可能。`honeyd` 模拟了真实系统，这使得交互成为可能。

## 第 13 章 – 僵尸网络 (Botnets)

僵尸网络是许多互联网威胁（如垃圾邮件和拒绝服务）的基础。本节通过介绍僵尸网络的基本元素、特征，概述了僵尸网络的工作原理。文中还解释了开启、分析和停止生产性僵尸网络的不同方法。

互联网的稳步增长伴随着犯罪和破坏性能量的增加，范围从纯粹的破坏性破坏到有组织犯罪。僵尸网络这一为人知但鲜少探索的领域是许多关键恶意机制的起点，例如垃圾邮件、分布式拒绝服务（`DDoS`）和数据间谍活动。文顿·策夫在 2007 年世界经济论坛上提出，所有连接互联网的 PC 都是恶意僵尸网络的一部分 `[Foru07]`。尽管如此，之前的安全相关方法侧重于预防、过滤和规避僵尸网络引起的攻击。只有少数方法直接处理僵尸网络的基础和运行机制。

僵尸网络是一组在用户不知情的情况下被恶意软件感染并由单个人远程控制的独立计算机系统。受感染的终端系统被称为 `zombie`（僵尸）或 `bot`，较少情况下称为 `drone`（无人）。远程控制僵尸网络的个人被称为 `botmaster`（主）。`C & C` 通道（命令与控制）已成为称为主与僵尸网络之间通信信道的术语 `[RZMT06]`。主与 bot 通过 `C & C` 通道进行的 1:n 通信是僵尸网络的基本特征。此外，“僵尸网络”仅指那些旨在执行有害和犯罪行为的结构。毕竟，僵尸网络只是一个可以但并不一定造成伤害的工具。具有性质的结构（例如“Folding@home”或“Mersenne Prime Search”）是和平且有意义的服务，不被归类为僵尸网络。

今天发现的恶意 bot 演变自 20 世纪 90 年代初经典的 `IRC` bot。`Eggdrop` 是最早支持 `IRC` 用户的 bot 之一，它通过执行数据库查询或提供帮助等功能来服务。基于 `Eggdrop` 的模块化，开发出了第一批可以用于实现恶意意图的 bot 程序。然而，最初的攻击局限于 `IRC` 领域的 `DoS`，例如通过自动“洪水攻击”。这些 bot 时间的推移而演变，但保留了 `egg-drop` 的模块化和对 `IRC` 的控制 `[CoJM06]`。同时，僵尸网络被用于纯粹的破坏（“脚本小子”）以及商业欺诈、勒索、垃圾邮件和钓鱼攻击 `[CoJM06]`。它还识别出一个紧密合作开发和完善恶意软件的社区。如果 bot 的源代码公开可用，它们会以特定场景伪名的形式显示出大量的用户签名。代码经常被重用；源代码包含指明原始代码的注释。通常，这些是预存在的恶意软件，如计算机病毒、蠕虫或木马。

对现有 bot 进行分类非常困难。现有的 Bot 软件经常被重写多次、扩展和修改；有时已知的 bot 变体达 4,000 个（`SDBot` 和 `Agobot`）。以下是最广受关注和目前流行的 bot 组列表：

### Agobot/Phatbot/Forbot/XtremBot

`SDBot` 及其衍生版本用 `C` 编写并在 `GPL` 下发布。源代码短小且简洁，尽管缺乏抽象且没有模块化支持。基础系统中未实现破坏函数，仅提供处理 `C & C` 命令的基础功能。添加恶意功能只需对源代码进行极小的修改。`SDBot` 除了 Windows 操作系统和点对点软件的漏洞外，还利用其他恶意软件留下的后进行主要感染 `[CoJM06]`。已知有超过 4,000 种变体。随后重构的源码可以推断出 100 多名程序员的身份。

Storm 僵尸网络估计占有 100 万个受感染系统，是观测以来最大的僵尸网络。与之相关的 bot 软件 `CME-711` 的构造研究较少，无法明确分配源代码。该电力僵尸网络在 2007 年负责了各种 `DDoS` 攻击，引起了媒体的关注。

Clickbot 是一种商业上可用但非法且有害的僵尸网络系统。2006 年 5 月发现了一个占有 10 万个 bot 的僵尸网络。Google 投入大量精力分析该僵尸网络，以便能够有效过滤点击。bot 作为 `BHO`（浏览器辅助对象）在“Internet Explorer”中实现作为 `C & C` 通道。bot 的传播通过“社交工程”和利用“Internet Explorer”的安全漏洞进行。通过 `PHP` 编写的去中心化管理系统进行了管理 `[DaSt07]`。

bot 系统的生命周期可以分为几个阶段。进入受害者系统（初级感染）、加载实际 bot 软件（二级感染）、通过 `C & C` 通道与主建立联系，随后执行命令。

在僵尸网络环境中，获取新的受害者系统不受控制，通常由主指示现有 bot 寻找并感染受害者系统。僵尸网络的传播机制是网络流量（由恶意软件引起）的主要原因之一，主要位于端口 `445/TCP`、`139/TCP`、`137/UDP` 和 `135/TCP`。根据 Honeynet 项目，测量的网络流量中 80% 由这些端口引起 `[BHKW05]`。连接到这些端口的常见来源也是 Windows 操作系统的漏洞、点对点程序和电子邮件客户端。此外，可以观察到 bot 利用其他恶意软件的功能将其安装到受害者系统 `[CoJM06]`。除了利用漏洞，“社交工程”方法也被用于导出。通常，受感染系统立即执行下载。下载的 URL 直接或间接地地在二进制文件中给出。常用协议包括简单的文件传输协议（`TFTP`）、文件传输协议（`FTP`, `[PoRe85]`）、超文本传输协议（`HTTP`, `[FGMF99]`）或发送 IRC 用户的 `CSend`。后者在 `IRC` 作为 `C & C` 通道的范围内特别有用。用于感染系统的软件通常没有参与僵尸网络的功能 `[RZMT06]`。下载后，二进制文件在操作系统中注册并在系统启动时自动启动。现有 bot 作为这些二进制文件的服务器 `[RZMT06]`；在某些情况下，被破坏的服务器或免费空间提供者也被滥用 `[BHKW05]`。`Agobot` 包含了初级感染后可以远程导出的少数所谓的“命令”。这些命令仅涵盖了通过 `IRC` 通信和下载附加组件。因此，任何破坏函数必须由二级二进制包添加。名为 `Phatbot` 的 `Agobot` 开发也提供了初级感染后导出 `DDoS` 攻击和数据窃取的功能。因此，二进制文件可以预配置为执行有害活动，无需 `C & C` 通道的命令。

多种协议用于 `C & C` 通道来控制 bot。`IRC` 协议被广泛建立。点对点系统的泛滥也可以包含聊天形式的自由定义指令，使得 `e2k`、`Gnutella` 或 `FastTrack` 等协议流行。bot 程序的模块化结构允许访问不同的协议。2003 年的 `SDbot` 不仅可以使用 `IRC`，还可以使用已建立的点对点协议作为 `C & C` 通道 `[CoJM06]`。

尽管近期有所发展，通过 `IRC` 通信仍然是最广泛使用的通信信道。这得于协议的灵活性以及用于编写恶意软件的免费实现。在典型场景中，主在服务器上运行 `IRC` 通道，bot 自动连接到该服务器。`IRC` 通道大多受密码保护。用户名、密码、通道名和服务器地址永久集成到二进制恶意软件中。大多数情况下，使用动态 URI 在需要时更改服务器。要成功连接到 `IRC` 通道，需要根据特殊算法形成用户名，以及通过 `IRC` 特有的 `PASS` 命令正确传输密码 `[RZMT06]`。`IRC` 协议不提供任何加密，因此所有访问数据都可以从网络嗅探中获取。身份验证成功后，`IRC` 服务器分别向 bot 信息 `RPL_ISUPPORT`、`RPL_MOTDSTART`、`RPL_MOTD`、`RPL_ENDOFMOTD` 和 `ERR_NOMOTD` `[OiRe93]`。`RPL_MOTD` 可以在 bot 进入通道之前向其传输命令。例如，可以指定新的通道名或替代服务器。bot 在进入 `RPL_TOPIC` 后解析并执行命令。`RPL_TOPIC` 遵循由方法名和参数组成的简单语法。`RPL_TOPIC` 的形状为 `.advscan lsass 200 5 -r -s` 指令 bot 继续传播自身。在 90 年代初，公共 `IRC` 通道被用作 `C & C` 通道。对于公共 `IRC` 服务器，这种滥用是一个巨大的安全风险。然而，现代观测显示，僵尸网络几乎使用修改过的 `IRC` 服务器。修改过的僵尸网络通常不遵循 `RFC1459` 指定的属性。僵尸网络中的 bot 数量是不可访问的，作为规则，通过 `JOIN`、`PART` 和 `QUIT` 消息输出。性能通过省略 `RPL_ISUPPORT`、`USERS` 等消息实现 `[OiRe93]`。应用层或 `TCP` 上的攻击落后 `[Netw07]`。因此，`DDoS` 是僵尸网络带来的首要威胁。只有僵尸网络（占比 64%）发送垃圾邮件 `[Netw07]`。这通常通过受感染系统上的 `SOCKS v4/v5` 代理 `[LGLK96]`（在 `[BHKW05]`）的 `IRC` 通道。

使用点对点网络作为 `C & C` 通道，与经典的 `IRC` 通道方法不同，追求去中心化策略。`P2P` 系统上的通信通常不会被中断或被破坏。从主的视角来看，其缺点是流量的不确定性和缺乏控制。对于 `P2P` 系统，已经有机制可以匿名化流量 `[CoJM06]`。`P2P` 作为 `C & C` 通道在文献中较少讨论。

特别是针对 `WWW` 上有害操作（如点击广告、操纵赌场和网页游戏）的 bot 使用 `HTTP` 作为 `C & C` 通道。例如 `Clickmaster` 和 `Clickbot.A` `[DaSt07]`。它们通常是 Internet Explorer 的 `BHO`（浏览器辅助对象）。通过与浏览器集成，`BHOs` 即可访问 `WWW` 资源。

遵循现有完全集中 `P2P` 系统的示例，bot 之间也可能在不使用所有协议的情况下进行去中心化的通信。在这种情况下，bot 可以主动扫描其网络中的额外成员，并向发现的成员发送加密消息。延迟非常高。这种系统尚未在生产形式中被观测到 `[CoJM06]`。

“分布式拒绝服务”是僵尸网络带来的最常见威胁。根据`[Netw07]`的调查，71% 的观测到的僵尸网络处于`DoS`攻击中。在这种情况下，主命令所有 bot 向定义目标发送大量的网络流量。受攻击的服务器由于请求过多无法正常提供服务。调查显示，目前僵尸网络的大多数攻击通过`UDP`进行。应用层或`TCP`上的攻击落后于`[Netw07]`。因此，`DDoS`是僵尸网络带来的首要威胁。

### 组合与数据挖掘

所有已知的用于检测僵尸网络的系统都存在高失败率。要么小类僵尸网络可以被检测，要么密度非常低。新方法建议对僵尸网络的属性进行分析。特征包括对未使用的 TCP 端口增加扫描、对缓存的分析以及对二进制文件的分析。这些方法的组合可以用于全面`[CoJM06]`。

尽管过去包含 80,000 到 140,000 个 bot 的僵尸网络被归类为危险，近年来的报告警告包含几百个 bot 的僵尸网络`[Netw07]`。因此，活跃 bot 的估计是评估僵尸网络危险潜力的重要特征。开发小型僵尸网络有几个原因：首先，小僵尸网络更容易被强效的安全软件检测，不像大型僵尸网络那样。此外，移动宽带连接也消除了获取多个 bot 的需求。在平均 1Mbps 的有线互联网连接下，只需要几百个 bot 达到 OC3 (155Mbps) 链路的容量。因此，攻击者的有效`DDoS`攻击对于少于 200 个 bot 已经是可能的。然而，僵尸网络大小的评估仍然当前研究的一个争议性。Dagon 等人调查了所谓的 350,000 个活跃 bot 的僵尸网络`[DaZL06]`。Rajab 认为规模小于 1,000 个 bot 的僵尸网络具有潜在危险`[RZMT06]`。大小是最特征，但对于如何定义这种规模存在通用分歧。确定大部分僵尸网络的一个问题是活跃 bot 和被 bot 之间的区别。活跃 bot 通常占总数的 5-10%`[Netw07]`。僵尸网络的大小参数与所使用的测量方法、相关的副作用以及上下文直接相关。此外，僵尸网络的大小并没有说明僵尸网络带来的危险。此外，被和活跃 bot 的划分没有明确定义，在现有测量方法中难以访问。因此，文献中建立了两种定义。僵尸网络的足迹表示在特定时间点僵尸网络的潜在总量（`Gesamtrobe`）。所有配置为加入观测到的僵尸网络的受感染系统将被计算。该参数提供了关于信息网络分布率以及传播机制有效性的信息。僵尸网络的足迹是随时间变化的，取决于受影响系统的每日传播和对策措施`[RZMT07]`。足迹的替代术语是被和活跃 bot 的数量。第二种定义提供了活跃人口（生存人口）的指示。该参数描述了特定时间通过`C & C`通道检索的可用 bot 数量。因此，僵尸网络不再可控。从攻击的角度来看，这种中心化部署导致低延迟。遵循现有完全集中`P2P`系统的示例，也可能在不使用所有协议的情况下在 bot 之间进行去中心化的通信。在这种情况下，bot 可以主动扫描其网络中的额外成员，并向发现的成员发送加密消息。延迟非常高。这种系统尚未在生产形式中被观测到`[CoJM06]`。

## 第 14 章 – 嗅探与欺骗：针对数据链路层的攻击

本节的目的是说明“嗅探”（sniffing）和“欺骗”（spoofing）方法的关键特征，以及它们与针对第 2 层和第 3 层网络协议攻击的相关性。它还描述了检测此类攻击的方法以及网络管理员可能采取的防御措施。这将使用户能够更好地保护自己免受此类攻击及可能的损害。

计算机网络常用的通信模型是 ISO/OSI 分层模型，这是一种用于异构计算机网络的分层通信模型 [Tane03]。每一层都隐藏了所有下层的信息，并为上层提供一个定义良好的接口，该接口为网络通信提供了方法。如果该模型中的某一层被攻破，上层的完整性也会受到影响。攻击低层数据传输的可能性是多样的，而且有时并不非常复杂。为了能够表示这些攻击并解释可能的防御措施，我们首先简要回顾了`ISO/OSI`模型的结构。此外，还将解释最重要协议的功能，以及分层通信模型的根本缺陷。随后，给出了“嗅探”和“欺骗”的术语。然后，我们描述了攻击者可以用来破坏网络系统安全的特定方法；之后，解释了使用录制数据可以使用哪些后续方法。最后，我们讨论了其他基于嗅探和欺骗技术的进一步方法。

### ISO/OSI 模型中的第 1 到 4 层

### 各协议的功能

### 第 2 层：CSMA/CD (以太网)

`Ethernet`协议的基本思想是所有连接订阅者对公共链路进行持续监控。为了避免冲突，只有在没有其他站正在传输时才传输数据。然而，由于信号传播速度有限，如果两个订阅者同时开始传输，就会发生冲突。`Ethernet`协议现在是计算机网络的准标准，但在电信领域以及照明技术领域也变得流行。`Ethernet`协议中最常见的拓扑结构是总线系统和星型网络。对于现代`Ethernet`网络，需要具有八对扭绞和屏蔽线的双绞电缆。根据速度的不同，仅使用四对中的两对。

在`token-ring`协议中，一次只有一个用户有权以虚拟令牌的形式发送数据，从而避免冲突。每个参与者都有一个前驱（从其那里接收令牌）和一个后继（将令牌传递给后继）。如果需要传输数据，参与者将数据附加到令牌上并将其标记为“忙”。如果令牌到达接收者处，接收者将获取数据并以相同的方式向发送者发送确认。所述原理产生了闭环拓扑结构。

`Internet Protocol` (`IP`) 为网络提供了跨多个站的媒介。这允许多个网络连接，并在未连接到公共介质的计算机之间发送数据包。`Internet Protocol`第 4 版使用 32 位长的 IP 地址，通常由四个十进制字节表示，例如`194.25.2.129`。然而，`Internet Protocol`第 6 版使用 128 位长的地址，其表示法与 MAC 地址相似，例如`2001:6f8:915:0230:feb9:742b`。两个版本的共同点是，除了 IP 地址外，网络掩码通过将 IP 地址分为网络部分和计算机部分来确定目标计算机是否可访问。如果本地无法访问计算机，通常会选择一个后续计算机并将包转发到那里。这一过程被称为“路由”。

在`Address Resolution Protocol` (`ARP`) 的帮助下，`Internet Protocol` (`IP addresses`) 的地址被转换为硬件地址（也称为`MAC addresses`）。`MAC addresses`长度为 48 位，以十六进制形式表示（例如`00:0c:29:4f:8b:ac`）。网络中的每个参与者都以表格形式存储 IP 地址到 MAC 地址的映射。如果本地无法访问计算机，通常会选择一个后续计算机并将包转发给它。在 Linux 计算机上可以使用`arp`命令查看当前的 MAC 表。例如，条目如下：`computer (192.168.1.1) at 00:0c:29:4f:8b:ac`。在这里你可以看到计算机（“computer”）、IP 地址和相应的 MAC 地址。此外，通过哪个网络适配器可以到达计算机（这里是“eth0”）。`ARP`由此建立了第 2 层和第 3 层之间的连接。这是一个非常简单的无状态协议，只有两个数据单元：`arp-request`和`arp-reply`。为了确定关联订阅者的 MAC 地址（例如`192.168.1.1`），会生成`arp-request`包并发送到所有连接到公共介质的站。目标 IP 地址站会将 MAC 地址存入自己的 MAC 表，并发送包含自身 MAC 和 IP 地址的包。这允许发送者正确地找到其他包。

`Internet Control Message Protocol` (`ICMP`) 用于在网络中的通信伙伴之间交换控制信息。在这些协议中，数据单元有“echo-request”和“echo-reply”。通过`echo-request`包，一个参与者向另一个人请求`echo-reply`响应。这通常会有回答，使得`ICMP`成为参与者可用性的常用检查。此外，可以测量响应发生之前的时间，从而获得通信伙伴反应的大致估计，即所谓的“延迟”。为了发送和接收此类包，可以使用每个操作系统都提供的`ping`程序。

`Domain Name System` (`DNS`) 提供了将计算机主机名（例如`www.google.com`）翻译为 IP 地址的方法。它节省了用户在浏览器等程序中输入 IP 地址的麻烦，并已成为该功能的标准。此外，如果配置当，可以使用 DNS 服务器将 IP 地址“反向”为主机名，例如反向 DNS。在计算机网络中，此服务通常由一个或多个 DNS 服务器提供。

`Dynamic Host Protocol` (`DHCP`) 处理连接站的动态自动配置。它为参与者提供参与网络通信所需的信息。这通常包括 IP 地址、网络掩码、默认网关和一个或多个服务器。`DHCP`可能的应用是网络计算机系统的简化自动配置。

分层通信始终将一个定义明确的功能封装在下一层。使用下层服务的进程依赖于它来执行工作。通常情况下，如果某点的通信被攻破，数据和内容（包括上层的控制信息）也会受到影响。如果上层传输的内容未加密或采取其他安全措施，可靠的通信将不再可能。因此显然，整个系统永远没有单个组件更安全。对底层之一的攻击是一个严重威胁。

### 嗅探

在网络安全背景下，`sniffing`指监听数据。因此，它是对网络安全的被动攻击，因为攻击者通常不向网络发送数据。相反，他将尝试通过收集和读取秘密（如用户名和密码以及机制）来获取更多信息。由于其被动性，嗅探攻击很难检测。如果攻击者自己发送数据以获取网络流量，他就会暴露。此外，在某些情况下，可以尝试让治疗者暴露。

嗅探的目的并不总是造成损害、忽略信息或绕过安全。相反，嗅探可以帮助监控网络并及时检测故障、攻击和其他中断。

### 欺骗

在网络和计算机安全背景下，`spoofing`指伪造外部身份。`spoofing`可以发生在`ISO/OSI`模型的每一层。与嗅探攻击不同，层的攻破并不会自动阻止发生的通信：IP 包中的伪造发送者地址并不会导致错误的发送者地址。在本文中，`spoofing`只被视为对底层以及那里如`ARP`和`IP`等协议的攻击。

### 欺骗的积极方面

通过嗅探，也有不影响系统安全的应用案例：
- 在设置了所谓虚拟主机（VirtualHosts）的 Web 服务器上，欺骗为其提供数据的域 Web 服务器身份。
- 在故障转移场景中，MAC 地址的欺骗提供了一种可能性，在主计算机故障时，让客户端在察觉的情况下执行其服务。

### 方法与途径

以下描述了常见的底层组件以及它们的漏洞、原因和可能的防御措施。通常，嗅探和欺骗攻击之间没有明确的区别；两种技术经常被同时使用，特别是当数据需要被重定向以便随后读取时。此外，通过嗅探身份信息（如密码和用户名），你也可以通过欺骗攻击获取地址。

### 电缆与集线器

如果网络中的所有站都通过电缆连接，那么每个参与者都会接收所有包。当站通过集线器连接时也是如此。各个站的网络适配器知道自己的 MAC 地址并过滤指向它们的数据包。

### 无线网络

除了以太网，无线网络（WLAN）在第 2 层的行为就像所有涉及的站通过公共电缆连接一样。毕竟，每个参与者都可以通过天线接收所有数据流量。再次，可以使用杂散模式的网络适配器读取其他参与者的包。与有线网络不同，无线网络经常使用加密传输数据的方法。攻击者必须已经是加密网络的一部分。

### 窃听

获取网络包的另一种方法是字面上对你具有物理访问权的任何有线网络进行“接入”。这一过程被称为窃听或分路；使用的设备被称为 `TAP` 设备。最构可能的 `TAP` 设备由一个网络适配器组成，其接收线连接到要监控的电缆传输线上。然而，当前的以太网传输器会定期发送信号以检查对方是否仍在响应。由于电缆的单侧连接，这种检查会失败，你必须依靠带有 `AUI` 收发器的旧卡。由于这种方法更多像是一种“黑客行为”而非可靠的方法，购买专业的 `TAP` 设备会更好。这些设备透明地转发网络流量，但提供了向连接的订阅者发送副本的机会。现代交换机也有为了监控目的而复制单个端口上所有流量的能力。

### `TAP` 设备的优点

这种 `TAP` 设备的优势是它只被动工作。如果你用它来调查网络攻击和故障，由于其被动性，它只有几个缺点，因此只能被破坏。攻击者无法获取有关系统存在或状态的信息。另一方面，如果攻击者成功在网络上安装了 `TAP` 设备，通过流量分析进行追踪是非常的。

### 检测可能性

取决于攻击者的行为范围，有方法可以在网络上跟踪嗅探器。然而，对于这些大多数可能性，攻击者的防御措施有时出现在攻击者和防御者之间。

- **名称服务器请求**：目前的嗅探程序（如 `tcpdump`）提供了使用反向 DNS 功能显示主机名而非 IP 地址的能力，从而增加了输出的可读性。可以在名称服务器上检测到大量的 DNS 查询。如果你额外配置一个具有网络空间之外 IP 地址的网络节点并让它自动生成网络流量，你可以在名称服务器上检测到对其 IP 地址的请求，并得出你正在使用嗅探器的结论。
- **延迟**：通过测量响应发生之前的时间，从而获得通信伙伴反应的大致估计，即所谓的“延迟”。为了发送和接收此类包，可以使用每个操作系统都提供的 `ping` 程序。
- **故障**：通常，如果某点的通信被攻破，数据和内容（包括上层的控制信息）也会受到影响。如果上层传输的内容未加密或采取其他安全措施，可靠的通信将不再可能。因此显然，整个系统永远没有单个组件更安全。对底层之一的攻击是一个严重威胁。
- **MAC 地址欺骗**：攻击者通过在自己的 MAC 表中存入错误的 MAC 地址来实现。
- **ARP 请求**：由于其被动性，嗅探攻击很难检测。如果攻击者自己发送数据以获取网络流量，他就会暴露。此外，在某些情况下，可以尝试让治疗者（此处可能应为译者）暴露。
- **路由**：如果本地无法访问计算机，通常会选择一个后续计算机并将包转发到那里。
- **ARP 请求**：会生成 `arp-request` 包。
- **ARP 回复**：通常会有回答。

### 攻击期间的检测

要检测此类攻击，可以监控网络是否存在大量的 `arp-replys`。此外，还可以参考 `arp-requests` 与 `arp-replys` 之间的关系。如果响应的数量超过请求的数量，则可能存在 ARP 欺骗攻击。请参考 [CaGo03]。

### 如果攻击成功

如果攻击成功，本质上有两种检测可能：

1. **监控 ARP 表**：通过如 `arpwatch` 等特殊软件，你可以检测 `MAC table` 的变化并触发警报。
2. **延迟监控**：除了上述从中心点测量单个计算机反应时间的可能性外，两台计算机的同步攻击以及相关的延迟网络流量分流，也会导致受害计算机之间数据包的传输时间增加。如果参与者监控其通信伙伴的响应时间，他可能会怀疑流量通过第三台计算机进行了重定向。
