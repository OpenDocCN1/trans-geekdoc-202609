## 何時使用 APC 和 eAccelerator

APC 和 eAccelerator 都是非常有用且非常相似的工具。每個工具的性能相似，並且都提供相同的功能。APC 是一個更開放的項目，可能會吸引想要修改源代碼以提供自定義功能的開發人員；這很容易，因為它基於 PECL。eAccelerator 更受限制，但也是一個活躍的項目，並且是開源的，因此也可以進行修改。

由個別應用程序團隊決定哪種許可證更合適以及哪個系統更容易使用。應用程序絕不應在沒有其中之一的情況下部署到生產環境，因為它們都會顯著提高性能。

還有其他幾個操作碼緩存解決方案提供相同的功能，但要么較不常見，要么不是開源的。本書在可能時選擇使用開源軟件，因此專有閉源解決方案在此未包含。

儘管操作碼緩存的實用性無可否認，但應用程序開發人員需要決定在特定應用程序中何時何地應用用戶緩存技術。

不應使用本地用戶緩存的一種情況是數據經常更改。在這些情況下，跨多台機器使緩存值失效或更改極其困難（如果系統架構允許，則不可能）。結果是一個非常低效的緩存，其中某些服務器可能顯示數據的一個版本，而其他服務器顯示完全不同的版本。

最後，本地用戶緩存的最大缺點是它在多台服務器上產生相同數據的許多副本。如果您有多個 Web 服務器，就不希望使用本地用戶緩存。儘管對於單個 Web 服務器而言，這可能是最有效的方法，因為它保證緩存始終位於本地機器上，但在複雜的應用程序中，通常需要分布式緩存來優化資源分配。這就是 memcached 發揮作用的地方。

## MEMCACHED

本章中已討論的許多緩存更多地與緩存預編譯代碼以加快執行以及優化有關。您想要利用的另一種緩存類型是緩存應用程序通常從數據庫獲取的數據——而無需訪問數據庫。這有助於減輕數據庫的負載，使網站每次需要數據的訪問都不必總是從數據庫獲取數據，而在極其繁忙的網站上，這會對數據庫和網站的整體性能產生不利影響。此外，擁有分布式且共享的緩存可以讓您通過使用商品硬件來提供分布式服務（如緩存）來實現擴展。隨著現在常見的巨大網站，擴展（與傳統的擴容相對）是組織現在應對增長的方式。許多偉大的創新解決方案都是出於必要而誕生的，而其中一種提供分布式緩存的解決方案就是 *memcached*。

### memcached 是什麼？

Memcached 是一個高性能的分布式內存對象緩存系統。它本質上是一個簡單的多線程服務器，分配內存以為應用程序提供鍵/值緩存，用於緩存數據以減輕數據庫負載或減少文件系統訪問。應用程序通過客戶端利用 memcached，該客戶端使用 ASCII 或二進制協議與 memcached 通信。Memcached 由 Brad Fitzpatrick 及其公司 Danga Interactive 創建，用於減輕其極其繁忙的網站 `Livejournal.com` 的壓力數據庫負載。當時，`Livejournal.com` 約有 100 萬用戶，每天有 2000 萬次動態頁面瀏覽。隨著 memcached 的出現，其數據庫負載降至幾乎為零。此後，許多其他網站也採用了 memcached：Facebook、Slashdot.org、Fotolog 和 Digg 等。這些都是極其繁忙的網站，近年來，現在有數千個網站面臨 C10K 問題——即需要在網站上同時為 10,000 個客戶提供服務的需求。使用 memcached 進行應用程序緩存是解決此問題的關鍵組成部分，因為數據庫通常是網站的瓶頸。您也可以利用 memcached 為您的數據庫和網站帶來好處。本章介紹如何將 memcached 與您的 PHP Web 應用程序一起使用。

### memcached 為您做了什麼

Memcached 允許您使用額外的未使用內存並使其可供需要額外內存進行緩存的應用程序使用。它還允許您更好地利用內存，因為它將不同的 memcached 服務器合併為一個內存池。在傳統的緩存系統中，內存在每個服務器上單獨使用，這很浪費，因為考慮到服務器群中內存的總和，這種緩存的容量僅為其可能容量的很小一部分。此外，保持緩存中存儲的數據一致也很複雜。圖 4-1 說明了每台服務器的傳統緩存以及 memcached 為您提供的功能。

### memcached 如何工作？

Memcached 在其核心使用 slab 分配器，提供一個字典或哈希查找表，其中項目緩存在內存中，該內存通過使用 libevent 構建的服務器進行網絡連接，libevent 是一個非阻塞網絡庫，用於實現極快的性能。重要的是要認識到，存儲在 memcached 中的數據不是持久的——意味著它並不是以傳統的磁盤存儲方式真正存儲的，當 memcached 服務器被關閉或重新啟動時就會消失。
