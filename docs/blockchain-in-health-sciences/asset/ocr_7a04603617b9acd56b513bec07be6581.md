# 19.7.5 Reproducibility and Validity

To prove the study's validity in genomics and overall research, it is essential to do a replication. To replicate a study, researchers or auditors need to find the same data, maintained in the same format over several years. It is essential to mention blockchain's use for data interchange in scientific research when off-chain storage is used. This problem surfaces in systems that depend on centralized off-chain storage as many in those that use decentralized off-chain storage, such as IPFS. Consider the possibility that the data may be removed from the cloud provider at a later date [38]. Following the FAIR guidelines for data management does not seem to be a priority for genomic blockchains. When patients are part of many organizations with different assigned IDs, data redundancy is another potential issue. The possibility of duplicate data publication, when identical patient data is available under different anonymous identifiers, is a barrier to the decentralized sharing and analysis of genetic data. This is a major problem since it could affect the reliability of the study, which is especially important when the data is used for research. In an effort to circumvent this, the CG [38] enlisted the help of two reviewers and developed a grading system based on rules. Various methods already exist for detecting duplicate entries in separate databases, such as the methodology described in reference [39]. This method employs secure multi-party computation to achieve privacy-preserving record linkage across multiple databases. Nevertheless, additional investigation is required to tackle this issue in a decentralized blockchain network [39].

# 19.7.6 Verifiability

An obstacle that arises when assigning processing jobs to untrusted parties is the need to authenticate the precision of the outcomes. An effective approach involves delegating the analysis task to numerous analysis nodes and subsequently comparing the findings to verify accuracy. Nevertheless, the expense of this method might be substantial, particularly when the identical work is allocated to a significant number of analysis nodes. Hence, the need for a reliable and scalable verification technique to confirm the accurate execution of outsourced computation/analysis by untrusted nodes in a blockchain network remains an unresolved matter that necessitates additional investigation. Exploration of verified computation improvements in a blockchain system is now underway [40].
