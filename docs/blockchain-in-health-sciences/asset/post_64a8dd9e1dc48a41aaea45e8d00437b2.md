## 18.4 Fog Computing and Cloud Integration

The advantage of IoT-based system is that a patient in rural may still obtain high-quality services without physically visiting hospitals. These systems [8–11, 16, 21] contain only two layers: 1: Sensor layer; 2: Cloud layer. The sensors at the sensor layer are used to collect data and send it to the cloud employing various tools. However, these systems have a few shortcomings. Since enormous amounts of data are constantly being sent to the cloud, there may be a storage bottleneck if user traffic increases significantly. Also, may be unsuitable for real-time health monitoring or critical conditions due to the significant delay in receiving data from the cloud. Additionally, there are issues regarding privacy. To address the constraints of traditional architecture, a fog layer has been introduced in the new design. The layer is positioned between the cloud layer and the sensor layer. The addition of fog nodes pushed the computational capabilities and storage capacity of cloud closer to the sensor nodes. Upon receiving the data, sensor nodes promptly transmit the data to their corresponding fog node. The fog node immediately begins the processing of the newly received data, therefore reducing communication latency. Furthermore, fog nodes store used information or data inside so that it can be retrieved quickly from nearby locations. Also, it is easy to preserve the privacy of data because sensitive information is not sent to the cloud. The new approach offers enhanced reliability and availability by distributing computational power of cloud across several fog nodes. In the literature, numerous researchers have used the notion of fog computing to develop many IoT-based systems [12, 18, 20, 22, 28–31].

## 18.5 Blockchain Applications in Healthcare Systems

Blockchain is a collection of blocks connected together in a chronological order using cryptographic hash values. It is also known as distributed digital ledger it is completely distributed among all of its participants. Each block comprises a set of validated transactions. To update a transaction on the blockchain, participants must come to an agreement. A responsible manager is selected through the consensus procedure with the intention of updating the transaction in a new block in an honest manner. Each participant receives an updated copy of the blockchain subsequent to the update. Furthermore, this participant verifies the correctness of the new copy. Participants will accept the updated copy if they all agree it is accurate; otherwise, they will reject it. If a miner inserts an incorrect or malvolent transaction into a block, he/she may be subject to a penalty. The blockchain is also regarded as immutable due to the fact that it is unfeasible to alter or remove transactions that have already been recorded in a block and appended to the chain.
