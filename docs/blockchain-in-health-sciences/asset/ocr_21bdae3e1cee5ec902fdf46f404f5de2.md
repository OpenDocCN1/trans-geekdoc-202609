**Figure 7.4** Architecture of blockchain [5].

+   1. Application and Presentation layer: End users utilize the applications in the application layer to create blockchain network connectivity. A smart contract, or programmable code that controls state transitions, is the first component of the application layer. It is referred to by different names in different ecosystems, such as “programmes” in Solana and “chaincode” in Hyperledger, and can serve as an escrow, payment-channel, or vault.
2. Consensus layer: This layer validates the authenticity of a block before transmitting it to the network. This procedure is a component of blockchain's fault-tolerant technique for transaction verification. Different types of consensus protocols with different principles and guiding techniques. Some of the techniques are listed below.
   a) Proof of Work (PoW): This is the foundation of the Bitcoin algorithm. The new node in this algorithm requires some computational power. It has to fulfill a difficult assignment to demonstrate its non-malicious nature. The miner can only get rewarded *afterwards* [53].
   b) Proof of Stake (PoS): PoS consumes less energy than PoW. It also indicates that the likelihood of being attacked is higher on nodes with a larger cash valuation [53].
