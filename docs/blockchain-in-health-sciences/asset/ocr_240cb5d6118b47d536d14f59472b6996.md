Each individual node carries a copy of the blocks. Moreover, a single append operation to a block shall be updated across all the nodes.

Tx1, Tx2, . . , Txn represent the bottom-level individual transactions that have been validated by the nodes. As an individual message or a transaction may have larger size than the allowed message size, the split of transactions can be authenticated by digital signature. As illustrated, the ledger is append-only linked-based data structure that stores the transaction history of entire network. This list comprises the blocks that combine the transactions in the Merkle tree. for immutability or tamper proof, the hash pointers provide a link between the blocks. In addition, for verification of a set of transactions, timestamp and nonce fields are included in the block structure. To add a new block in the blockchain, a set of miners verifies the block by computally solving a difficult proof-of-work (PoW) puzzle. A verifier can traverse the blockchain to establish the ownership or the intended entities of a transaction because the blocks are stored in an ordered fashion according to the timestamp field. The structure of the ledger and the hash pointer thwart any tampering attempt as any such attempt would change the hash of the block, which in turn changes the hash of all subsequent blocks, rendering the attack attempt even harder.
