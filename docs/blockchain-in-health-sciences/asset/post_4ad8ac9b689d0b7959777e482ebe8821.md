## 11.3 Background

Our suggested method mainly makes use of bilinear maps, which are a crucial component of our cryptography module. Using multiple cyclic groups, G0 and G1, both of order p, we define the maps. Furthermore, we use a generator g and a bilinear map for G0 that meet the following requirements:

### A. Bilinear Maps
Bilinearity Property:

```
e(ua,vb) = e(u,v)ab (11.1)
```

Equation (11.1) represents the bilinearity property of the bilinear map e, where ua and vb are elements from G0, and u, v, a, and b are elements from Zp.

### Non-degeneracy Property:

```
e(g, g) ≠ 1 (11.2)
```

Equation (11.2) reflects the non-degeneracy property of the bilinear map. It states that if the bilinear map applied to the generator g and itself is not equal to 1, then the map is non-degenerate.

### Monotone Access Structure:

```
If B ∈ A and B ⊆ C, then C ∈ A (11.3)
```

Equation (11.3) describes the property of monotone access. It implies that if set B is a subset of C, then C must be included in A.

## 11.4 Proposed System

### A. System Model
The eight entities that comprise our system:
- Terminals
- Blockchain
- Cloud Service Providers (CSPs)
- Fog Nodes (FNs)
- Internet of Devices
- Trusted Authorities (TA)
- Data Owners (DOs)
- Data Users (DUs)

The system gathers measurement data from patients via an aggregation terminal. The data is encrypted and transmitted to fog nodes, who authenticate the ciphertext. After the fog node decrypts the encrypted value upon successful authentication, the DU uses it to calculate the symmetric key. Figure 11.1 shows the system model.
