## 10.4 Results and Discussions

We implemented and tested our smart contract using the Remix IDE, which is available at http://remix.ethereum.org. The browser-based Remix IDE was used to construct the Solidity-scripted code, which offers powerful features for testing and debugging smart contracts prior to their deployment. Because Remix has a built-in JavaScript EVM (Ethereum Virtual Machine) environment, contracts can be executed and deployed locally.

To incorporate:

- 1. Initialization:
- The process begins with the initiation of the smart contract through the seller using Remix IDE.
- The smart contract is deployed on the Ethereum blockchain using the Remix IDE’s JavaScript EVM.

- 2. Package Check:
- The IoT-enabled container performs a package check, ensuring adherence to specified requirements for the pharmaceutical freight.

- 3. Event Triggering:
- The smart contract initiates an event upon a successful package check, indicating that the system is ready for the next step.

- 4. Consumer Interaction:
- The consumer deposits the purchase amount into the smart contract and receives a secret hash as a verification code.

- 5. Freight Dispatch:
- Upon successful deposit, the smart contract awaits the arrival of the pharmaceutical package at the consumer’s destination.

Code Verification:

- Upon arrival, the consumer furnishes the accurate secret code to expose and report the merchandise.

Error Handling:

- If an incorrect code is provided, the smart contract initiates a 72-hour window for the consumer to rectify the error.

Refund or Termination:

- Should the accurate code not be provided within the stipulated timeframe, the smart contract initiates a refund of half the freight price to the consumer and terminates the shipment.

Default Handling:

- Should the customer fail to fulfil their end of the bargain, the smart contract will transfer half of the payment to the seller in accordance with the parameters that were previously agreed upon.
