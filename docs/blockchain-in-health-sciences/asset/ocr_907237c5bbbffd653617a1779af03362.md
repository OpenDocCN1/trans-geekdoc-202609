In the blockchain network, the peer node needs a consensus process to determine the present state of the ledger. Due to the absence of centralized authority, consensus algorithms help to manage trust in this distributed environment. This mechanism makes sure that every node has equal rights and must take part in the consensus process, so that a consensus is reached. The goal of a consensus algorithm is to reach an agreement that is advantageous to the blockchain network.

Different consensus techniques and their operation are discussed below:

+   a. **Proof of Work (PoW):** Proof of work (PoW) is a consensus technique requiring a significant computational effort among a network of devices. The PoW consensus algorithm, attempts to effectively resolve a challenging conundrum. It is mainly used by Bitcoins. The node that uses the most processing power to solve this challenge fastest wins the privilege to mine the next block [25]. To use this decentralized consensus method, network participants exert effort to decipher an encrypted hexadecimal number.

+   b. **Byzantine Fault Tolerance (PBFT):** In the late 1990s, Miguel Castro and Barbara Liskov created Practical Byzantine Fault Tolerance, a consensus technique. PBFT was designed to work well in asynchronous systems, in which there is no maximum duration for waiting for a response. Its optimisation of overhead time is low. Its objective to resolve the issues that have arisen in the past with Byzantine Fault Tolerance methods [26]. Blockchain and distributed computing are two areas of application. The ability of a distributed network to reach agreement when certain nodes in the network fail to react or reply with misleading information is known as Byzantine Fault Tolerance, or BFT. A BFT mechanism aims to reduce the impact of faulty nodes and guard against system failures by employing collaborative decision-making which includes both proper and faulty nodes.
