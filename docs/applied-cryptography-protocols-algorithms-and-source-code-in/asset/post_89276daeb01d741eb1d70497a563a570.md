## 22.2 STATION-TO-STATION PROTOCOL

Diffie-Hellman key exchange is vulnerable to a man-in-the-middle attack. One way to prevent this problem is to have Alice and Bob send their messages to each other [500]. This protocol assumes that Alice has a certificate with Bob's public key and Bob has Alice's public key. These certificates have been signed by some trusted authority outside this protocol. Here's how Alice and Bob generate a secret key, k.

- (1) Alice generates a random number, x, and sends it to Bob.
- (2) Bob generates a random number, y. Using the Diffie-Hellman protocol he computes their shared key based on x and y; k. He signs x and y, and then sends that, along with y, to Alice. Alice signs the signature using k. E_A(S_B(x,y)).
- (3) Alice also computes k. She decrypts the rest of Bob's message and verifies her signature. She sends Bob a signed message consisting of x and y, encrypted in their shared key. E_B(S_A(x,y)).
- (4) Bob decrypts the message and verifies Alice's signature.

## 22.3 SHAMIR'S THREE-PASS PROTOCOL

This protocol, invented by Adi Shamir but never published, enables Alice and Bob to communicate securely without any advance exchange of secret keys or public keys [1008]. This assumes the existence of a symmetric cipher that is commutative, that is:

```
$E_A(E_B[P]) = E_B(E_A[P])$
```

Alice's secret key is A. Bob's secret key is B. Alice wants to send a message, M, to Bob. Here's the protocol.

- (1) Alice encrypts M with her key and sends Bob $C_1 = E_A(M)$
- (2) Bob encrypts C_1 with his key and sends Alice $C_2 = E_B(E_A[M])$

## 22.4 COMSET

- (3) Alice decrypts $C_2$ with her key and sends Bob $C_3 = D_A(E_B(E_A(M))) = D_A(E_A(E_B(M))) = E_B(M)$
- (4) Bob decrypts $C_3$ with his key to recover $M$.

One-time pads are commutative and have perfect secrecy, but they will not work with this protocol. With a one-time pad, the three ciphertext messages would be:

```
$C_1 = P \oplus A
C_2 = P \oplus A \oplus B
C_3 = P \oplus B$
```

Eve, who can read the three messages as they pass between Alice and Bob, simply XORs them to retrieve the message:

```
$C_1 \oplus C_2 \oplus C_3 = (P \oplus A) \oplus (P \oplus B) \oplus (P \oplus B) = P$
```

This clearly won't. Shamir (and Jim Omura) described an encryption algorithm that will work with this protocol, similar to RSA. Let $p$ be a large prime for which $p-1$ has a large prime factor. Choose an encryption key, $e$, such that $e$ is relatively prime to $p-1$. Calculate $d$ such that $de = 1 \pmod{p-1}$.
To encrypt a message, calculate

```
$C = M^e \pmod p$
```

To decrypt a message, calculate
$M = C^d \pmod p$

There seems to be no way for Eve to recover $M$ without solving the discrete logarithm problem, but this has never been proved.

Diffie-Hellman protocol allows Alice to initiate secure communication with Bob without knowing any of his keys. For Alice to use a public-key algorithm, she must know his public key. With Shamir's three-pass protocol, she just sends him a ciphertext message. The same thing with a public-key algorithm looks like:

- [1] Alice asks Bob (or a KDC) for his public key.
- [2] Bob (or the KDC) sends Alice his public key.
- [3] Alice encrypts $M$ with Bob's public key and sends it to Bob.

Shamir's three-pass protocol will fall to a man-in-the-middle attack. COMSET (Communications Setup) is a mutual identification and key exchange protocol developed for the RIPE project [1305]. Using public-key cryptography, it allows Alice and Bob to identify themselves to each other and also exchange a secret key. The mathematical principle behind COMSET is Rabin's scheme [1283]. The scheme itself was originally proposed in [224]. See for details.

## 22.5 ENCRYPTED KEY EXCHANGE

The Encrypted Key Exchange (EKE) protocol was designed by Steve Bellovin and Michael Merritt. It provides security and authentication using both symmetric and public-key cryptography in a novel way: a shared secret key is used to encrypt a randomly public key. Alice and Bob (two users and a host) share a common password. Using this protocol, they can authenticate each other and generate a session key, K.

- Alice generates a random public key, K'. She encrypts it with the password as the key and sends Bob $E_P(K')$.
- Bob knows the message to obtain K'. Then, he generates a random session key, K, and encrypts it with the public key he received from Alice and the password as the key. He sends Alice $E_K(E_P(K'))$.
- Alice decrypts the message to obtain K. She generates a random string, $R_A$, encrypts it with K, and sends Bob $E_K(R_A)$.
- Bob decrypts the message to obtain $R_A$. He generates another random string, $R_B$, encrypts both strings with K, and sends Alice the result $E_K(R_A, R_B)$.
- Alice decrypts the message to obtain $R_A$ and $R_B$. Assuming the $R_A$ she received from Bob is the same as she sent to Bob in step (3), she encrypts $R_B$ with K and sends it to Bob $E_K(R_B)$.
- Bob decrypts the message to obtain $R_B$. Assuming the $R_B$ he received from Alice is the same as he sent to Alice in step (4), the protocol is complete. Both parties now communicate using K as the session key. At step [3], both Alice and Bob know K' and K. K is the session key and can be used to encrypt all other messages between Alice and Bob. The challenge-response protocol, the steps through (6), provides validation. Steps through (5) prove to Alice that Bob knows $K$; steps (4) through (6) prove to Bob that Alice knows $K$. The Kerberos exchange timestamp accomplishes the same thing. EKE can be implemented with a variety of public-key algorithms: RSA, ElGamal, Diffie-Hellman. There are security problems implementing EKE with a knapsack algorithm (aside from the inherent insecurity of knapsack algorithms): the normal distribution of the ciphertext messages negates the benefits of EKE.

### Implementing EKE with RSA

The RSA algorithm seems perfect for this application, but there are some subtle problems. The authors recommend encrypting only the exponent in step [1] and sending the modulus in clear. An explanation of the reasoning behind this recommendation, as well as other subtleties involved using RSA, is in [109].

### Implementing EKE with ElGamal

EKE with the ElGamal algorithm is straightforward, and there is even a simplification of the basic protocol. Using the notation from Section 19.6, $g$ and $p$ are parts of the public key and are common to all users. The private key is a random number $r$. The public key is $g^r \pmod p$. The message Alice sends to Bob in step (1) becomes:

> Alice, g^r \pmod p$

Note that this public key does not have to be encrypted with $P$. This is not true in general, but it is true for the ElGamal algorithm. Details are in [109].

Bob chooses a random number $r$ (for the ElGamal algorithm and independent of any random numbers for EKE), and the message he sends to Alice in step (2) becomes:

> $E_A(g^r \pmod p, K^r \pmod p)$

### Implementing EKE with Diffie-Hellman

With the Diffie-Hellman protocol, $K$ is generated automatically. The final protocol is simpler. A value for $g$ and $n$ is set for all users on the network.

- (1) Alice picks a random number, $r_A$, and sends Bob:

> $A, g^{r_A} \pmod n$

With Diffie-Hellman, Alice does not have to encrypt her first message $P$.
