# Guillou-Quisquater Identification Scheme

Peggy is a smart card who wants to prove her identity to Victor. Peggy's identity consists of a set of credentials: a data string consisting of the card's name, validity a bank account number, and whatever else the application warrants. This bit string is J. [Actually, the credentials can be a longer string and hashed to a J. This value does not modify the protocol in any way.] This is analogous to the public key. Other public information, shared by all "Pegsys" who could use this application, is an exponent $v$ and a modulus $n$, where $n$ is the product of two secret primes. The private key is $B$, calculated such that $JB' \equiv 1 \pmod{n}$.

Peggy sends her credentials, J. Now, she wants to prove to Victor that her credentials are hers. To do this, she has to convince Victor that she knows B. Here's protocol:

+   (1) Peggy picks a random integer $r$, such that $r$ is between 1 and $n-1$. She computes $T = r^v \pmod{n}$ and sends it to Victor.

+   (2) Victor picks a random integer, $d$, such that $d$ is between zero and $v-1$. He sends $sd$ to Peggy.

+   (3) Peggy computes $D = RB^v \pmod{n}$, and sends it to Victor.

+   (4) Victor computes $T' = D^d \pmod{n}$. If $T = T' \pmod{n}$, then the authentication succeeds.

The math is not complex:

> $T' = (RB^v)^d = r^d B^{vd} = r^d (B^d)^v = r^d (1)^v = T \pmod{n}$

> $JB' = 1 \pmod{n}$

# Guillou-Quisquater Signature Scheme

This identification can be converted to a signature scheme, also suited for smart-card implementation [671, 62].

The public and private key setup is the same as before. Here's the protocol:

+   (1) Peggy picks a random integer $r$, such that $r$ is between 1 and $n-1$. She computes $T = r^v \pmod{n}$.

+   (2) Alice computes $d = H(M,T)$, where $M$ is the message signed and $H(x)$ is a one-way hash function. The $d$ produced by the hash function must be between 0 and $v-1$ [1280]. If the output of the hash function is not within range, it must be reduced modulo $v$.
