# 19.2 KNAPSACK ALGORITHMS

The first algorithm for generalized public-key encryption was the knapsack algo-ith by Ralph Merkle and Martin Hellman [713,1074]. It could only be
used for encryption, although Adi Shamir adapted the system for digital signa-
tures [1413]. Knapsack algorithms get their security from the knapsack problem,
NP-complete problem. Although this algorithm was later found to be insecure, its
NP-complete problem can be
used for public-key cryptography.

The knapsack problem is a simple one. Given a pile of items, each with different
weights, it is possible to put some of them into a knapsack that the kn-
sack weighs a given amount! More formally: Given a set of values $M_1, M_2, ... M_n$
and a sum S, compute the values of b, such that

```
$S = b_1M_1 + b_2M_2 + ... + b_nM_n$
```

Tie values of $b_i$, can be either zero or one. A one indicates that the item is in the
apsack; a zero indicates that it isn't.

For example, the items might have weights of 1, 5, 6, 11, 14, and 20. You could
pack a knapsack that weighs 22; use weights 5, 6, and 11. You could not pack a knap-
sack that weighs 24. In general, the time required to solve this problem seems to
grow exponentially with the number of items in the pile.
