
# LFSR/FCSR Summation/Parity Cascade

The theory is that addition with carry destroys the algebraic properties of LFSRs, and XOR destroys the algebraic properties of FCSRs. This generator combines those, as used in the LFSR/FCSR Summation Generator and the LFSR/FCSR Parity Generator just listed, with the Gollmann cascade.

The generator is a series of arrays of registers, with the clock of each array controlled by the previous array. Figure 17.6 is one using addition with carry. The first array of LFSRs is clocked and the results are combined using addition with carry. If the input of this combining function is 1, then the next [of FCSRs] is clocked and the output of those FCSRs is combined with the previous combining function using XOR. If the output of the first combining function is 0, then the array of FCSRs is not clocked and the output is simply added to the carry from the previous round. If the output of this second combining function is 1, then the third array of LFSRs is clocked, and so on.

This generator uses lot of registers: $n, m$, where $n$ is the number of stages and $m$ is the number of registers per stage. I recommend $n=10$ and $m=5$.

# 17.6 NONLINEAR-FEEDBACK SHIFT REGISTERS

It is easy to imagine a more complicated feedback sequence than the ones used in LFSRs or FCSRs. The problem is there isn't any mathematical theory that can analyze them. You'll get something, but who knows what it is? In particular, there are some problems with nonlinear-feedback shift register sequences.

- There may be biases, as much more than zeros or fewer runs than expected, in the output sequence.
- The maximum period of the sequence may be much lower than expected.
- The period of the sequence may be different for different starting values.
- The sequence may appear random for a while, but then "dead end" into a single value. (This can easily be solved by XORing the nonlinear feedback function with the rightmost bit.)

On the plus side, there is no theory to analyze nonlinear-feedback shift registers for security, there are few tools to cryptanalyze stream ciphers based on them. We can use nonlinear-feedback shift registers in stream-cipher design, but we have to be careful.

In a nonlinear-feedback shift register, the feedback function can be anything you want (see Figure 17.8).

# 17.7 OTHER STREAM CIPHERS

Many other stream ciphers have appeared in the literature here and there. Here are some of them.

less Generator

This generator is designed around the capabilities of J-K flip-flop. Eight LFSRs drive four J-K flip-flops; each flip-flop acts as a nonlinear combiner for two LFSRs. To avoid the problem that knowledge of an output of the flip-flop both the source and value of the next output bit, clock the four flip-flops and then interleave the outputs to yield the final keystream. This algorithm has been cryptanalyzed by attacking each of the four flip-flops independently. Additionally, combining J-K flip-flops is cryptographically weak; generators of this type succumb to correlation attacks.

# Cellular Automaton Generator

In [1608.1609], Steve Wolfram proposed using a one-dimensional pseudo-number generator. Cellular automaton is not the subject of this book, Wolfram's generator consisted of a one-dimensional array of bits, $a_1, a_2, \dots, a_k, \dots, a_n$ and an update function:

```
$a_k = a_{k-1} \oplus a_{k+1}$
```

The bit is extracted from one of $a_k$ values, which really doesn't matter. The generator's behavior appears quite random. However, there is a known plaintext attack against these generators. This attack works on a PC with values of $n$ up to 500 bits. Additionally, Paul proved that the output of a cellular automaton can also be generated by a linear-feedback shift register of equal length and is therefore no more secure.

# /p Generator

This generator was proposed, and then cryptanalyzed, in [193]. If the internal state of the generator at time $t$ is $x_t$,

```
$x_{t+1} = bx_t \pmod p$
```

The output of the generator is the least significant bit of $x/p$, where div is truncated division. For maximum period, the constants $b$ and $p$ should be chosen so that $p$ is prime and $b$ is a primitive root mod $p$. Unfortunately, this generator is not secure. (Note that for $b=2$, an FCSR with connection generator outputs the reverse of this sequence.)

# crypt(1)

The ORIGINAL encryption algorithm, crypt1], is a 256-element, single-rotor substitution cipher with a reflector. Both the rotor and the reflector are generated from the key. This algorithm is far simpler than the World II German Enigma and, for a skilled cryptanalyst, very easy to break [1576,1299]. A public-domain UNIX program, called Crypt Breakers Workbench [CBW], can be used to break files encrypted with crypt1.

# 17.8 SYSTEM-THEORETIC APPROACH TO STREAM-CIPHER DESIGN

In practice, stream-cipher design is a lot block-cipher design. It involves more mathematical theory, but in the end a cryptographer proposes a design and then tries to analyze it.

According to Ruppel, there are four different approaches to the construction of stream ciphers [1360, 1362]:

- System-theoretic approach. Try to make sure that each design creates a difficult and unknown problem for the cryptanalyst, using a set of fundamental design principles and criteria.
- Information-theoretic approach. Try to keep the cryptanalyst in the dark about the plaintext. No matter how much work the cryptanalyst invests, he will never get a unique solution.
- Complexity-theoretic approach. Try to base the cryptystem on, or make it equivalent to some known and difficult problem such as factoring or taking discrete logarithms.
- Randomized approach. Try to generate an unmanageably large problem by forcing the cryptanalyst to examine lots of useless data in his attempts at cryptanalysis.

The approaches differ in their assumptions about the capabilities and opportunities of the cryptanalyst, the definition of cryptographic success, and the notion of security. Most of research in this field is theoretical, but there are some good stream ciphers among the impractical ones.

The system-theoretic approach was used in all the stream ciphers that are practical enough to be used in the real world. A cryptography designs keystream generators that have testable security properties—period, distribution of bit patterns, linear complexity, and so—and not based on mathematical theory. The cryptographer also studies various analytic techniques against these and makes sure the generators are immune to these attacks.

Over the years, the approach has resulted in a set of design criteria for stream ciphers [1432, 1997, 1249]. These were discussed by Ruppel in [1362], in which he details the theory behind them.

- Period, no repetitions.

- Linear complexity criteria—large linear complexity, linear complexity profile, local linear complexity, and so forth.
