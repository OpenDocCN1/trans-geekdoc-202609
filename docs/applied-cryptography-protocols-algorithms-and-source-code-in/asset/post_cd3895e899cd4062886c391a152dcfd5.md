
## 20.1 Digital Signature Algorithm (DSA)

$q = a 160$-bit prime factor of $p-1$.
$g = h^{(p-1)/q} \pmod p$, where $h$ is any number less than $p-1$ such that $h^{(p-1)/q} \pmod p$ is greater than 1.
$x =$ a number less than $q$.
$y = g^x \pmod p$.

The algorithm also uses a one-way hash function: $H(m)$. The standard specifies the Secure Hash Algorithm, discussed in Section 18.7.
The first three parameters, $p, q,$ and $g$, are public and can be common across a network of users. The private key is $x$; the public key is $y$.
To sign a message, $m$:

- (1) Alice generates a random number, $k$, less than $q$.
- (2) Alice generates
  $r = [g^k \pmod p] \pmod q$
  $s = [k^{-1}(H(m) + xr)] \pmod q$
  The parameters $r$ and $s$ are her signature, she sends these to Bob.

- (3) Bob verifies the signature by computing
  $w = s^{-1} \pmod q$
  $u_1 = (H(m) \cdot w) \pmod q$
  $u_2 = (rw) \pmod q$
  $v = ([g^{u1} \cdot y^{u2}] \pmod p) \pmod q$
  If $v = r$, then the signature is verified.

Proofs for the mathematical relationships are found in [1154]. Table 20.1 provides a summary.

## Precomputations

Table 20.2 gives sample software speeds of DSA [918]. Real-world implementations of DSA can be sped up through precomputations. Note that the value $r$ does not depend on the message. You can create a string of $k$ values, and then precompute $r$ values for each of them. You can also precompute $k^{-1}$ for each of those $k$ values. When a message comes along, you can compute $s$ for a given $r$ and $k^{-1}$.

This precomputation speeds up DSA considerably. Table 20.3 is a comparison of DSA and RSA computation times for a particular smart card implementation [1479].

## DSA Prime Generation

Lenstra and Haber pointed out that certain moduli are much easier to crack than others [950]. If someone forced a network to use one of these “cooked” moduli, then their signatures would be easier to forge. This is not a problem for two reasons: moduli are easy to detect and they are so rare that the chances of using one when choosing a modulus randomly are almost negligible—smaller, in fact, the chances of accidentally generating a composite number using a probabilistic generation routine.

[1154] NIST recommended a specific method for generating the two primes, $p$ and $q$, where $q$ divides $p-1$. The prime $p$ is bits long, between 512 and 1024 bits.

**Prime Generation Steps:**
- (1) Choose an arbitrary sequence of at least 160 bits and call it $S$. Let $g$ be the length of $S$ in bits.
- (2) Choose $U = SHA(S) \pmod{2^g}$; SHA is the Secure Hash Algorithm (see Section 18.7).
- (3) Form $q$ by setting the most significant bit and least significant bit of $U$ to 1.
- (4) Check whether $q$ is prime.
- (5) If $q$ is not prime, go back to (1).
- (6) Let $C=0$ and $N=2$.
- (7) For $k=0, 1, \dots, n$, $V_k = SHA(\{S+k\} \pmod{2^g})$.
- (8) Let $W$ be the integer $W = V_0 + 2^{160}V_1 + \dots + 2^{160(n-1)}V_{n-1} + 2^{160n}V_n$ and $X = W+2^{L-1}$. $X$ is an $L$-bit number.
- (9) Let $p = X-[X \pmod{2q}] - 1$. Note that $p$ is congruent to $1 \pmod{2q}$.
- (10) If $p < 2^{L-1}$, go to step (13).
- (11) Check whether $p$ is prime.
- (12) If $p$ is prime, go to step (15).
- (13) Let $C = C+1$ and $N = N+1$.
- (14) If $C = 406$, then go to step (1). Otherwise, go to (7).
- (15) Save the value of $S$ and the value of $C$ used to generate $p$ and $q$.

In [1154], the variable $S$ is called the “seed,” $C$ is called the “counter,” and $N$ the “offset.” The point of this exercise is that there is a public means of generating $p$ and $q$. For all practical purposes, this method prevents cooked values of $p$ and $q$. If someone hands you a $p$ and $q$, you might wonder where that person got them. However, if someone has a value for $S$ and $C$ that generated the $p$ and $q$, you can go through this routine yourself. Using a one-way hash function, SHA in the standard, prevents someone from working backwards from $p$ and $q$ to generate an $S$ and $C$.

This security is better than what you get with RSA. In RSA, the prime numbers are kept secret. Someone could generate a fake prime or one of a special format that makes factoring easier. Unless you know the private key, you won't know that. Even if you don't know a person's private key, you can confirm that $p$ and $q$ have been generated randomly.

## ElGamal Encryption with DSA

There have been allegations that the government likes the DSA because it is only a digital signature algorithm and can't used for encryption. It is, however, possible to use the DSA function to do ElGamal encryption.

Assume the DSA algorithm is implemented with a single function call:
`DSAssign(p,q,g,k,x,r,s)`

You supply the numbers $p, q, g, x$ and $h$, and the function returns the signature parameters: $r$ and $s$.

To ElGamal encryption of message $m$ with public key $y$, choose a random number, $k$, and call:
`DSAssign(p,p,g,k,0,r,s)`

The value of $r$ returned is $a$ in the ElGamal scheme. Throw $away$. Then, call:
`DSAssign(p,p,y,k,0,r,s)`

Rename the value of $r$ to be $u$; throw $away$.
`DSAssign(p,p,m,u,0,r,s)`

Throw $away$. The value of $s$ returned is $b$ in the ElGamal scheme. You now have the ciphertext, $a$ and $b$.

Decryption is just as easy. Using secret key $x$, and ciphertext messages $a$ and $b$, call:
`DSAssign(p,p,a,x,0,0,r)`

## ElGamal Encryption with DSA

The value $r$ is $a^k \pmod p$. Call that $e$. Then call:
`DSAssign(p,p,e,b,0,r,s)`

The value $s$ is returned is the plaintext $m$.
This method will work with all implementations of DSA. This is a way to encrypt using nothing more than signature function.
