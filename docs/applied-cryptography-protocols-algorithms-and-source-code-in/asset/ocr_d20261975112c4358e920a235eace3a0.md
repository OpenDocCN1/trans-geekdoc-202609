# CFB:

Security: + Plaintext patterns are concealed. + Input to the block cipher is randomized. + More than one message can be encrypted with the same key, provided that different IV is used. +/- Plaintext is somewhat difficult to manipulate; blocks can be removed from the beginning and end of the message, bits of the first block can be changed, and repetition allowed correct changes.

Efficiency: + Speed is the same as the block cipher. - Ciphertext is the same size as the plaintext, not counting the IV. +/- Encryption is not parallelizable; decryption is parallelizable and a random-access property. - Some preprocessing is possible before a block; the previous cipher block can be encrypted. +/- Encryption is not parallelizable; decryption is parallelizable and a random-access property.

Fault-tolerance: - A cipher error affects the corresponding bit of plaintext and the next full block. - Synchronization errors of full block sizes are recoverable; 1-bit CFB can be recovered from the addition or loss of single bits.

# OFB/Counter:

Security: + Plaintext patterns are concealed. + Input to the block cipher is randomized. + More than one message can be encrypted with the same key, provided that different IV is used. +/- Plaintext is easy to manipulate; ciphertext affects the plaintext.

Efficiency: + Speed is the same as the block cipher. - Ciphertext is the same size as the plaintext, not counting the IV. + Processing is possible before the message is sent. - OFB processing is not parallelizable, counter processing is parallelizable.

Fault-tolerance: + A cipher error affects only the corresponding bit of plaintext. - Synchronization error is unrecoverable.
