# Theory of Block Cipher Design

Confusion alone is enough for security. An algorithm consisting of a key-dependent lookup table of 64 bits of plaintext to 64 bits of ciphertext is plenty strong. The problem is that large lookup tables require lots of memory to implement: $10^9$ bytes of memory for the table just mentioned. The whole point of block design is to create something that looks like a large lookup table, but with much smaller memory requirements.

The trick is to repeatedly mix [with smaller tables] and diffusion in a single cipher in different combinations. This is called a product cipher. Some times a cipher that incorporates layers of substitution and permutation is called a substitution-permutation network, or an SP network.

Look back function f of DES. The expansion permutation and P-box perform diffusion; the S-boxes perform confusion. The expansion permutation and P-box are linear, the S-boxes are nonlinear. Each operation is pretty simple on its own, together they work well.

# Feistel Networks

Most algorithms are Feistel networks. This idea dates from the early 1970s [552,553]. Take a block of length $n$ and divide it into two halves of length $n/2$; $L$ and $R$. Of course, $n$ must be even. You can define an iterated block cipher where the output of the $i$-th round is determined from the previous round:

```
$L_i = R_{i-1}
R_i = L_{i-1} \oplus f(R_{i-1}, K_i)$
```

$K_i$ is the subkey in the $i$-th round and $f$ is an arbitrary round function.
You've seen this in DES, Lucifer, FEAL, Khufu, Khaftre, LOKI, GOST, CAST, Blowfish, and others. Why is it such a big deal? The function is guaranteed to be reversible. Because XOR is used to combine the left half with the output of the round function, it is nearly true that

```
$L_{i-1} = R_i \oplus f(R_i, K_i) = R_i = L_{i-1}$
```

A cipher that uses this construction is guaranteed to be invertible as long as the inputs to each round can be reconstructed. It doesn't matter what $f$ is need not be invertible. We can design $f$ to be as complicated as we please, and we don't have to implement two different algorithms—one for encryption and decryption. The structure of a Feistel network takes care of all this automatically.
