Politics aside, the internal structure of the LEAF is worth discussing [812,1154, 1594,459,107,462]. The LEAF is a 128-bit string containing enough information to allow law enforcement to recover the session key. $K_s$ assuming the escrow agencies in those key-escrow databases cooperate. The LEAF contains a 32-bit unit identifier, $U$, unlike the Clipper chip. It also contains the 80-bit itself key encrypted with the Clipper's unique unit key, $K_u$, and a 16-bit checksum, called an escrow identifier. This checksum is a function of the session key, the IV, and possibly other information. These three fields are encrypted with a family key, $K_f$, shared by interoperable Clipper chips. The family key, the encryption modes, the details of the checksum, and the exact structure of the LEAF are all secret. It probably looks like this:

```
$E_{K_f}[E_{K_u}(C]]$
```

$K_u$ is programmed into Clipper chips. The key is then split (Section 3.6) and stored in two different-escrow-databases, guarded by two different escrow agencies.

For Eve to recover $K_s$, she first has to decrypt the LEAF with $K_f$ and recover $U$. Then she has to court an order to each escrow agency, Eve XORs the two halves together to recover $K_u$, then she uses $K_u$ to recover $K_s$ and $K_f$ to eavesdrop on the conversation.

The checksum is designed to prevent someone from circumventing this scheme; the receiving Clipper chip will not decrypt the LEAF if the checksum doesn't check. However, there are only $2^{16}$ possible checksum values, and a bogus LEAF with the right checksum but the key can be found in about 42 minutes [187]. This isn't much help for voice conversations. Because the encryption protocol is not part of the Clipper chip, the 42-minute brute-force attack must occur after the key is exchanged, it cannot be done before making the phone call. This attack may work for facsimile transmission or with the Fortezza card [Section 24.17].
