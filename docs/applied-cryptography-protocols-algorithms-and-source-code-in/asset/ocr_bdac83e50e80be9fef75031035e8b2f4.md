# 6.4 Digital Cash

For example, $I_7$ consists of two parts: $I_{37}$ and $I_{38}$. Each part is a bit-committed packet that Alice can be asked to open and whose proper opening can be instantly verified. Any pair (e.g., $I_7$ and $I_{37}$, but not $I_7$ and $I_{38b}$), reveals Alice's identity.

Each of the money orders looks like:

| Amount | |
| Uniqueness String: $X$ |
| Identity Strings: $I_1 = (I_{11}, I_{12}), I_2 = (I_{21}, I_{22})$ |
| ... |
| I_n = (I_{in}, I_{in+1})$ |

+   (2) Alice blinds $n$ money orders, using a blind signature protocol. She gives them all to the bank.

+   (3) The bank asks Alice to unblind $n-1$ of the money orders at random and confirms that they are all well formed. The bank checks the amount, the uniqueness string, and asks Alice to reveal all of the identity strings.

+   (4) If Alice is asked Alice did not make any attempts to cheat, she signs the one blinded order. The bank hands the blinded order back to Alice and deducts the amount from her account.

+   (5) Alice unblinds the money order and spends it with a merchant.

+   (6) The merchant verifies the bank's signature to make sure the money order is legitimate.

+   (7) The merchant asks Alice to randomly either the left half or the right half of identity string on the money order. In effect, the merchant gives Alice a random $n$-bit selector string, $b_1, b_2, \dots, b_n$. Alice opens either the left or right half of $I_i$, depending on whether $b_i$ is a 0 or 1.

+   (8) Alice complies.

+   (9) The merchant takes the money order to the bank.

+   (10) The bank verifies the signature and checks its database to make sure a money order with the same uniqueness string has not been previously deposited. If it hasn't, the bank credits the amount to the merchant's account. The bank records the uniqueness string and all of the identity information in a database.

+   (11) If the uniqueness string is in the database, the bank refuses to accept the money order. Then, it compares the identity string on the money order with the one stored in the database. If it is the same, the bank knows that the person who bought the money order photocopied it. Since the second merchant who accepted the money order handed Alice a different selector string than the first merchant, the bank finds a position where one merchant had Alice the left half and the other merchant had Alice the right half. The bank XORs the two halves together to reveal Alice's identity.
