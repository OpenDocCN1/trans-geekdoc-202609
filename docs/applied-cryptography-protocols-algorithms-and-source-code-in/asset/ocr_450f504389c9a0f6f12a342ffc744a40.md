RC4 has special export status if its key length is 40 bits or under (see Section 13.8). This special status has nothing to do with the secrecy of the algorithm, although RSA Data Security, Inc. has fought it for years that it does. The name is trademarked, so anyone who writes his own code can call it else. Various internal details by RSA Data Security, Inc. have not been made public [1320,1337].

So, what's the deal with RC4? It is no longer a secret, so presumably anyone can use it. However, RSA Data Security, Inc. will almost certainly sue anyone uses unlicensed RC4 in a commercial product. They won't win, but they will certainly make it cheaper for a company to license than fight.

RC4 is in dozens of commercial cryptography products, including Lotus Notes, Apple Computer's AOCE, and Oracle Secure SQL. It is part of the Cellular Packet Data specification [1371].

# 17.2 SEAL

SEAL is a software-efficient stream cipher designed at IBM by Phil Rogaway and Don Coppersmith[1340]. The algorithm optimized for 32-bit processors: To run it well needs 32-bit registers and a cache of a few kilobytes. Using a relatively slow operation, SEAL preprocesses every key operation into a set of tables. These tables are used to speed up encryption and decryption.

# Pseudo-random Function Family

One feature of SEAL is that isn't really a traditional stream cipher: it is a pseudo-random function family. Given a 160-bit key $k$, and a 32-bit $n$, SEAL stretches $n$ into an $L$-bit string $k[n]$. can take any value less than 64 kilobytes. SEAL ensures the property that if $k$ is selected at random, $k[n]$ should be computationally indistinguishable from a random $L$-bit function of $n$.
