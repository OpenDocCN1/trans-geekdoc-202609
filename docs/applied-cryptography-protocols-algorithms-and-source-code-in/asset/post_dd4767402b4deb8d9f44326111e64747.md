
## 20.3 GOST Digital Signature Algorithm 495

- (1) Choose an arbitrary sequence of at least 160 bits and call it S. Let g be the length of S in bits.
- (2) Compute U = SHA(S) ∥ SHA ({S + 1} mod 2^k), where SHA is the Secure Hash Algorithm [see Section 18.7].
- (3) Form q by setting the most significant bit and the least significant bit of q $U$ to 1.
- (4) Check whether q is prime.
- (5) Let p be the concatenation of q, S, C, and SHA[S]. C is set to 32 zero bits.
- (6) p = p - [p mod q] + 1.
- (7) p = p + q.
- (8) If the C is in 0x7ffffff, go to step (1).
- (9) Check whether p is prime.
- (10) If p is composite, go to step (7).

The thing about this variant is that you don't have to store the values of C and S used to generate p and q; they are embedded within p. For applications with a lot of memory, like smart cards, this can be a big deal.

## 20.3 GOST DIGITAL SIGNATURE ALGORITHM

This is a Russian digital signature standard, officially called GOST R 34.10-94 [656]. The algorithm is very similar to DSA, and uses the following parameters

```
p = a prime number, either between 509 and 512 bits long,
q = a 254-bit prime factor of p - 1,
a = any number less than p - 1 such that a^d mod p = 1,
x = a number less than q,
y = a^d mod p.
```

The algorithm also use of a one-way hash function: H[x]. The standard specifies GOST R 34.11-94 [see Section 18.11], a function based on the GOST symmetric algorithm [see Section 14.1] [657].

The first three parameters, p, q, and a, are public and can be common across a network of users. The private key is x; the public key is y. To sign a message, m

- (1) Alice generates a random number, k, less than q
- (2) Alice generates

```
r = (a^k mod p) mod q
s = (xr + k(H(m))) mod q
```

$H(m) \mod q = 0$, then set it equal to 1. If $r=0$, then choose another $k$ and start again. The signature is two numbers: $r$ $2^{256}$ and $s$ $2^{256}$. She sends these to Bob.

- (3) Bob verifies the signature by computing

```
v = H(m)^{s-2} mod q
z_1 = (sv) mod q
z_2 = |(q-r) \cdot v| mod q
v = ((a^{z_1} \cdot y^{z_2}) \mod p)
```

If $u=r$, then the signature is verified.

The difference between this signature and DSA with DSA $s = \{xr + k^{-1}(H(m))\} \mod q$, which leads to a different verification equation. Curious, though, is that $q$ is 256 bits. Most Western cryptographers seem satisfied with a $q$ of around 160 bits. Perhaps this is just a reflection of the Russian tendency to play it ultrasafe.

The standard has been in use since the beginning of 1995, and is not classified "for special use"—whatever that means.

## 20.4 LOGARITHM SIGNATURE SCHEMES

ElGamal, Schnorr (see Section 21.3), and DSA signature schemes are very similar. In fact, they are just three examples of a general digital signature scheme based on the Discrete Logarithm Problem. With thousands of other signature schemes, they are part of the same family [740,741,699,1184].

Choose $p$, a large prime number, and $q$, either $p-1$ or a large prime factor of $p-1$. Then choose $g$, a random number between 1 and $q$ such that $g^q \equiv 1 \mod p$. All these numbers are public, and can be common to a group of users. The private key is $x$, less than $q$. The public key is $y = g^x \mod p$.

To send a message, first choose a random $k$ less and relatively prime to $q$. If $q$ is also prime, $k$ less than $q$ works. First compute

```
$r = g^k \mod p$
```

The generalized signature equation now becomes

```
$ak = b + cx \mod q$
```

The coefficients $a, b$, and $c$ can be any of things. Each line in Table 20.4 gives six signatures.

To verify the signature, the receiver must confirm that

```
$r^a = g^{by}y \mod p$
```

This is called the verification equation.
