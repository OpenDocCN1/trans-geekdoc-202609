# 9.7 SYNCHRONOUS STREAM CIPHERS

In a synchronous cipher the keystream is generated independent of the mes-\sage stream. The military calls this Key Auto-Key (KAK). On the encryption side,
keystream generator spits out keystream bits, one after the other. On the decryption
side, another keystream generator spits out identical keystream bits, one after
the other. This works, as long as the two keystream generators are synchronized. If
of them skips a cycle or if the keystream bit gets lost during transmission, then
every ciphertext character after the error will decrypt incorrectly.

If this happens, the sender and receive must resynchronize their keystream
generator before they can proceed. Matters even further, they must do this
a a way so that no part of the keystream is repeated, so the obvious
resetting the keystream generator to an earlier state won't work.

On the plus side, synchronous ciphers do not propagate transmission errors. If a
bit is garbled during transmission, which is more likely than being lost also-
tether, only the garbled bit will be decrypted incorrectly. All preceding and
subsequent bits will be unaffected.

Since a keystream generator must generate the same output on both the encry-
ryption ends, it must be deterministic. Because it is implemented in a
finite-state machine (i.e., a computer), the sequence will eventually repeat. These
ystream generators are called periodic. Except for one-time pads, all keystream
generators are periodic.

The keystream generator must have a long period, one longer than the number
of bits generated. If the period is less than thentplaintext, then parts of the plaintext repeat—a
severe weakness. If a cryptanalyst knows a piece of the plaintext, he can recover a
piece of the keystream and use that to recover more of the plaintext. If even the an-
lyst only has the ciphertext, he can XOR the sections encrypted with the same
keystream and the XOR of plaintext with plaintext. This is just the simple XOR
alalgorithm with a very long period.

How long a period depends on the application. A keystream generator-
crypt a continuous T-1 link will encrypt 2 bits per day. The keystream
generator's period is of magnitude larger than that, even if the key is
changed daily. If the period is too long, you might only have to change the key
very weekly or monthly.

Synchronous ciphers also protect against any insertions and deletions in
the ciphertext, because these cause a loss of synchronization and will be immedi-
ately detected. They do not, however, fully protect against bit toggling. Like block
ciphers in CFB mode, Mallory can toggle individual bits in the stream. If he knows
t plaintext, he can make these bits decrypt to whatever he wants. Subsequent bits
 decrypt correctly, so in certain applications Mallory still do considerable
damage.
