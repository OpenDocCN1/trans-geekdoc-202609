# Security of RSA

The security of RSA depends wholly on the problem of factoring large numbers. Technically, it's a lie. It is conjectured that the security of RSA depends on the problem of factoring numbers. It has been mathematically proven that you need to factor $n$ from $c$ and $e$. It is conceivable that an entirely different way to analyze RSA might be discovered. However, if this new way allows the cryptanalyst to deduce $d$, it could also be used as a new way to factor large numbers. One would worry much about it.

It is also possible to attack RSA by guessing the value of $\{p-1\}|q-1\}$. This attack is no easier than factoring $n$ $[116]$.

For the ultraskept, some RSA variants have been proved to be as difficult as factoring (see Section 19.5). Also look at [36], which shows that recovering even bits of information from an RSA-encrypted ciphertext is as hard as decrypting the entire message.

Factoring $n$ is the most obvious method of attack. Any adversary will have the public key, $e$, and the modulus. To find the decryption key, $d$ has to factor $n$. Section 11.4 discusses the current state of factoring technology. Currently, a 129-decimal-digit modulus is at the edge of factoring technology. So, $n$ must be larger than that. Read Section 7.2 on public key length.

It is possible for a cryptanalyst to try every $d$ until he stumbles on the correct one. This brute-force attack is even less efficient than factoring $n$.

From time to time, people claim to have found easy ways to break RSA, but no such claim has held up. For example, in 1993 a draft paper by William Payne proposed a method based on Fermat's little theorem [1234]. Unfortunately, this method is slower than factoring the modulus.

# Chosen Ciphertext Attack against RSA

Some attacks work against the implementation of RSA. These are not attacks against the basic algorithm, but the protocol. It's important to realize that it's not enough to use RSA. Details matter.

Scenario 1: Eve, listening in Alice's communications, manages to collect a ciphertext message, $c$, encrypted with RSA in her public key. Eve wants to be able to read the message. Mathematically, she wants $m$, in which

To recover $m$, she first chooses a random number, $r$, such that $r$ is less than $n$. She Alice's public key, $e$. Then she computes

```
x = r^e mod n
y = yc mod n
t = r^{-1} mod n
```

If $x = r^e \mod n$, then $t = x^d \mod n$.

Now Eve asks Alice to sign $y$ with her private key, thereby decrypting $y$. (Alice has to sign the message, not the hash of the message.) Remember, Alice has seen before. Alice sends Eve

```
u = y^d mod n
```

Now, Eve computes

```
tu mod n = r^{-1}y mod n = r^{-1}x^d mod n = c^d mod n = m
```

Eve has $m$.

# Scenario 3: Eve wants Alice to sign $m_3$. She generates two messages, $m_1$ and $m_2$, such that

$m_3 \equiv m_1, m_2 \pmod n$

If Eve can get Alice to sign $m_1$, she can calculate $m_3$:

$m_3^d \equiv m_1^d m_2^d \pmod n$

Moral: Never use RSA to sign a document presented to you by a stranger. Always use a one-way hash function. The RSA 0796 block format prevents this attack.

# Common Modulus Attack on RSA

A possible RSA implementation gives everyone the same $n$, but different values for the exponents $e$ and $d$. Unfortunately, this doesn't work. The most obvious problem is if the same message is encrypted with two different exponents (both having the same modulus), and those two exponents are relatively prime (which they would be), then the plaintext can be recovered without either of the decryption exponents $[1457]$.

Let $m$ be the plaintext message. The two encryption keys are $e_1$ and $e_2$. The common modulus is $n$. The two ciphertexts are:

$c_1 = m^{e_1} \pmod n$
$c_2 = m^{e_2} \pmod n$

The cryptanalyst knows $n, e_1, e_2, c_1$, and $c_2$. Here's how he recovers $m$. Since $e_1$ and $e_2$ are relatively prime, the extended Euclidean algorithm can find $r$ and $s$ such that

$re_1 + se_2 = 1$

# Low Exponent Attack against RSA

RSA encryption and signature are faster if you use a low value for $e$, but that can be insecure $[7704]$. If you share a group of users having the same value of $e$, there is an attack against the system. If there are fewer than many messages, or if the messages are unrelated, there is no problem. The easiest solution is to pad messages with random values.

# Low Decryption Exponent Attack against RSA

Another attack, this one by Wiener, will recover $d$, when $d$ is up to one quarter the size of $n$ and $e$ is less than $n$ $[1596]$. This rarely occurs if $e$ and $d$ are chosen at random, and cannot occur if $e$ has small value.

# Lessons Learned

Judith Moore lists several restrictions on the use of RSA, based on the success of these attacks $[1114,1115]$:

- Knowledge of one encryption/decryption exponent for a given modulus enables an attacker to factor the modulus.
- Knowledge of one encryption/decryption exponent for a given modulus enables an attacker to calculate other encryption/decryption pairs without having to factor $n$.
- A common modulus should not be used in a protocol using RSA in a communications network. (This should be obvious from the previous points.)
- Messages should be padded with random values to prevent attacks on low encryption exponents. The decryption exponent should be large.

Remember, it is not enough to have a secure cryptographic algorithm. The entire cryptystem must be secure, and the cryptographic protocol must be secure. A failure in any of those three areas makes the overall system insecure.
