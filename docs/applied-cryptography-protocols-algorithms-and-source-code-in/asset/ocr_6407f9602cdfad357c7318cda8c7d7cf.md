9.3 Cipher block chaining mode.

# ### Initialization Vector

CBC mode forces identical plaintext blocks to encrypt different ciphertext blocks only when some previous plaintext block is different. Two identical messages will still encrypt to the same ciphertext. Even worse, two messages that begin the same will encrypt the same up to the first difference.

Some messages have a common header: a letterhead, or a “From” line, or whatever. While block replay would still be impossible, this identical beginning might make a cryptanalyst use useful information.

Prevent this by encrypting data as the first block. This block of data is called the initialization vector (IV), initializing variable, or chaining value. The IV has no meaning; it's just there to make each message unique. When the receiver decrypts this block, he just uses it to fill the feedback register and ignores it. A timestamp makes a good IV. Otherwise, use some random bits from somewhere.

With the addition of IVs, identical messages encrypt to different ciphertext messages. Thus, it is impossible for an eavesdropper to attempt block replay, and more difficult to build a code book. While the IV should be unique for each message encrypted with the same key, it is not an absolute requirement.

The IV needs not be secret; it can be transmitted in the clear with the ciphertext. If this seems wrong, consider the following argument. Assume that we have several of blocks: $B_1, B_2, \dots, B_n$ is encrypted with the IV. $B_2$ is encrypted using the ciphertext of $B_1$, the $B_i$ is encrypted using the ciphertext of $B_{i-1}$, and so on. Secret secret. there's no reason to keep the IV secret; if there are $n$ blocks, there are $n-1$ “IVs,” even if the original IV is kept secret; the IV is just a dummy ciphertext block—you can think of it as $B_0$ to start the chaining.
