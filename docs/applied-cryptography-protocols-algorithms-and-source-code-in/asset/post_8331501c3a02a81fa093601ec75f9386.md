## Overview of One-Way Hash Functions

It's not easy to design a function that accepts an arbitrary-length input, let alone make it one-way. In the real world, one-way hash functions are built on the idea of a compression function. This one-way function outputs a hash value of $n$ given an input of some larger length $m$ [1069,414]. The inputs to the compression function are a message and the output of the previous blocks of text (see Figure 18.1). The output is a hash of all blocks up to that point. That is, the hash of block M, is

```
$h_i = f(M_i, h_{i-1})$
```

This hash value, along with the next block, becomes the next input to the compression function. The hash of the entire message is the hash of the last block. The pre-image should contain some kind of binary representation of the length of the entire message. This technique overcomes a potential security problem resulting from messages with different lengths possibly hashing to the same value [1069,414]. This technique is sometimes called MD-strengthening [930].

Various researchers have theorized that if the compression function is secure, then this method of hashing an arbitrary-length message is also secure—but nothing has been proved in [1138,1070,414].

A lot has been written on the design of one-way hash functions. For more mathematical information, consult [1028,793,791,1138,1069,414,91,858,1264]. Bart Prenel's thesis [1262] is probably the most comprehensive treatment of one-way hash functions.

## 18.3 N-Hash

N-Hash is an algorithm invented by researchers at Nippon Telephone and Telegraph, the same people who invented FEAL, in 1990 [1105,1106]. N-Hash uses 128-bit message blocks, a complicated randomizing function similar to FEAL's, and produces a 128-bit hash value.

The hash of each 128-bit block is a function of the block and the hash of the previous block.

$H_0 = I$, where $I$ is a random initial value
$nH_i = g(M_i, H_{i-1}) \oplus M_i \oplus H_{i-1}$

The hash of the entire is the hash of the last block. The random initial value, $I$, can be any value determined by the user (even all zeros).

## 18.4 MD4

MD4 is a one-way-hash function designed by Ron Rivest [1319]. MD stands for Message Digest; it produces a 128-bit hash.

- Speed: MD4 is suitable for high-speed implementations.
- Security: MD4 is not based on any assumption.
- Simplicity and Compactness: MD4 is as simple as possible.
- Favor Little-Endian Architectures: MD4 is optimized for microprocessor.

## 18.5 MD5

MD5 is an improved version of MD4 [1386,1322]. Unlike more complex than MD4, it is similar in design and also produces a 128-bit hash.

## Description of MD5

After some initial processing, MD5 processes the input text in 512-bit blocks. The output of the algorithm is a set of 32-bit blocks, which concatenate to a single 128-bit hash value.

First, the message is padded so that its length is just 64 bits short of being multiple of 512. This padding is a single 1 bit added to the end of the message, followed by as many zeros as required. Then, a 64-bit representation of the message's length (before padding bits added) is appended to the result.

Four 32-bit variables are initialized:

```
A = 0x01234567
B = 0x89abcdef
C = 0xfcedcba9
D = 0x76543210
```

These are chained variables.

Now, the main loop of the algorithm begins. This continues for as many 512-bit blocks as in the message.

The four variables are copied into different variables: a gets A, b gets B, c gets C, and d gets D.
