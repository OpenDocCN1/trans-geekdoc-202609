## Diffie's Randomized Stream Cipher

This scheme was first proposed by Whitfield Diffie [1362]. The data are $2^n$ sequences. The key is $k$, a random $n$-bit string. To encrypt a message, Alice uses the $k$ random string as a one-pad. She then encrypts the ciphertext plus the $2^k$ random strings over $2^k+1$ different communications channels.

Bob, who has $k$, has no choice but to easily choose which one-pad to decrypt the message at time, until he finds the correct one-pad. Any attack must examine an expected number of bits which is $O(2^n)$. Rueppel points out that if you send $n$ random strings instead of $2^n$, and if the key is used to specify a linear combination of random strings, the security is the same.

## Maurer's Randomized Stream Cipher

Ueli Maurer described a scheme based on XORing the plaintext with several large random-bit sequences [1034, 1029, 1030]. The key is the set of starting positions within each sequence. This turns out to be provably secure, with a calculable probability of being broken by how much memory the attacker has at his disposal, without regard to the amount of computing power he has. Maurer claims that this scheme would be practised with about 100 different sequences of $10^{30}$ random bits. Digitizing the face of the moon might be one way to get many bits.

## 17.11 CASCADING MULTIPLE STREAM CIPHERS

If performance is issue, there is no reason not to choose multiple stream ciphers and cascade them. Simply XOR the output of each generator with the plaintext to get the ciphertext. Maurer's result [see Section 15.7] says that if the generators have independent keys, the security of the cascade is at least as secure as the strongest algorithm in the cascade. It is much more secure than that.

Stream ciphers can be combined in all the ways as block ciphers [see Chapter 15]. Stream ciphers can be cascaded [see Section 15.7] with other stream ciphers, or together with block ciphers.

A clever trick is to use one algorithm, either a block or stream algorithm, to frequently rekey a fast stream algorithm (which could even be a block algorithm in OFB mode). The fast algorithm could be weak, since a cryptanalyst would never see much plaintext encrypted with any one key.

There's a trade-off between the size of the fast algorithm's internal state (which may impact security) and how often you can afford to rekey. The rekey needs to be relatively fast; algorithms that have a long key setup routine aren't suitable for this kind of application. And the rekeying should be independent of the internal state of the fast algorithm.

## 17.12 Choosing a Stream Cipher

If the study of ciphers offers lessons, it's that new types of attacks are invented with alarming regularity. Classically, stream ciphers have been based on considerable mathematical theory. This theory can be used to prove good properties about the cipher, but can also be used to find new attacks against a cipher. I worry about any cipher based solely on LFSRs for this reason.

I prefer ciphers that are designed more along the lines of block ciphers: nonlinear transformations, large S-boxes, and so on. RC4 is my favorite, and SEAL is a close second. I would be interested in seeing cryptanalytic results against my generators that combine LFSRs and FCSRs; this seems to be a very fruitful area of stream-cipher research to mean for all designs. Or, you can use a block cipher in OFB or CFB to get a stream cipher.

## 17.13 Generating Multiple Streams from a Single Pseudo-Random-Sequence Generator

If you need to encrypt multiple channels of communications in a single box—a multiplexer, for example—the easy solution is to use a different pseudo-random-sequence generator for each stream. This has two problems: It requires more hardware, and all the different generators have to be synchronized. It would be simpler to use a single generator.

## 17.14 Real Random-Sequence Generators

One solution is to clock the generator multiple times. If you want independent streams, clock the generator three times and send 1 bit into each stream. This technique works, but you may have trouble clock the generator as fast as you would like. If you only clock the generator three times as fast as the data stream, you can create three streams. Another way is to use the sequence for each channel—perhaps a variable time delay. This is insecure.

A clever idea [1489], patented by the NSA, is shown in Figure 17.11. Dump the output of your variable generator into an m-bit shift register. At each clock pulse, shift the register to the right. Then, for each output stream, AND the register with a m-bit bit control vector viewed as a unique identifier for the desired output stream, XOR all the bits together to get the output bit for that stream. If you want several output streams in parallel, you need a separate control vector and XOR/AND logic for each output stream.

There are some things to watch out for. If any of the streams are linear combinations of other streams, the system can be broken. But if you are clever, this is an easy and secure way to solve the problem.

## RAND Tables

Back in 1955, when computers were still new, the Rand Corporation published a book that contained a million random digits [1289]. Their method is described in the book:

The random digits in the book were produced by rerandomization of a basic table generated by an electronic roulette wheel. Briefly, a random frequency source, providing on the average about 100,000 pulses per second, was gated about once per second by a constant frequency pulse. Pulse standardization circuits passed the pulses through a 5-place binary counter. In the machine a 32-place roulette wheel which made, on the average, about 3000 revolutions per trial produced one number per second. A binary-to-decimal converter was used which 20 of the 32 numbers (the other twelve were discarded) and retained only the final digit of two digits; this final digit was fed into IBM to produce a finely punched card of random digits.

The book goes on discuss the results of randomness tests on the data. It also suggests how to use the book to find a random number:

The lines of the table are numbered from 00000 to 99999. In any use of the table, a common procedure for doing this is to first open the book to an unselected page of the table and blindly choose a five-digit number, this number with the first digit reduced modulo 2 determines the starting line; the two digits to the right of the initially selected five-digit number are reduced modulo 50 to determine the starting column in the line.
