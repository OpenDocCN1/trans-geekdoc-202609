# 11.4 Factoring

In a Galois field, addition, subtraction, multiplication, and division by nonzero elements are all well-defined. There is an additive identity, 0, and a multiplicative identity. Every nonzero number has a unique inverse (this would not be true if p were prime). The commutative, associative, and distributive laws are true.

Arithmetic in a Galois field used a great deal in cryptography. All of the number theory works; it keeps a finite size, and division doesn't have rounding errors. Many cryptosystems are based on GF(p), where p is a large prime.

To make matters easier use arithmetic modulo irreducible polynomials of degree n whose coefficients are integers modulo q, where q is prime. These fields are called GF(q). All arithmetic is done modulo p(x), where p(x) is an irreducible polynomial of degree n.

The mathematical theory is far beyond the scope of the book, although I will describe some cryptosystems that use it. If you want to work with, GF(2^n) has the following elements: 0, 1, x, x+1, x², x²+1, x²x+1, x³ and x+1. There is an algorithm for computing inverses in GF(2^n) that is suitable for parallel implementation [421].

When talking about polynomials, the term "prime" is replaced by "irreducible." A polynomial is irreducible if it cannot be expressed as the product of two polynomials (except for 1 and itself). The polynomial x²+x+1 is irreducible over integers it can be expressed as x(x+1)+1.

A polynomial that is a generator in a given field is called primitive; all its coefficients are relatively prime. We will see primitive polynomials when we talk about linear-feedback shift registers (see Section 16.2).

Computation in GF(2^n) can be quickly implemented in hardware with linear-feedback shift registers. For that reason, computation over GF(2^n) is often quicker than computation over GF(p), as exponentiation is much more efficient in GF(2^n), so is calculating logarithms [180,181,368,379]. If you want to learn more about this, [140].

For a Galois field GF(2^n), cryptographers like to use the trinomial p(x)=xⁿ+x+1 as the modulus, because the long string of zeros between the xⁿ and x coefficients makes it easy to implement a fast modular multiplication [183]. The trinomial must be primitive, otherwise the math does not work. Values of n less than 1000 [1649,1648]
