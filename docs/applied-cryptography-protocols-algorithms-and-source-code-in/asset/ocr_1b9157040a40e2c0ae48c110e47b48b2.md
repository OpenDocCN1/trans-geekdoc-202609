# Extended Diffie-Hellman

Diffie-Hellman also works in commutative rings [1253]. Z. Shmuley and Kevin McCurley studied a variant of the algorithm where the modulus is a composite number [1442,1038]. V. S. Miller and Neal Kobitz extended this algorithm to elliptic curves [1095,867]. Taher ElGam used the basic idea to develop an encryption and digital signature algorithm (see Section 19.6).
This algorithm also works in the Galois field GF(2^a) [1442,1038]. Some implementations take this approach [884,1631,1632], because the computation is much quicker. Similarly, syntactic computation is easily fast, so it is important to carefully choose a field large enough to ensure security.

# Hughes

This variant of Diffie-Hellman allows Alice to generate a key and send it to Bob [745].

+   (1) Alice chooses a random integer x and generates
$k = g^x \mod n$
(2) Bob chooses a random integer y and sends Alice
$Y = g^y \mod n$
(3) Alice sends Bob
$X = Y^x \mod n$
(4) Bob computes
$z = y^{-1} \mod n$
k' = X^y \mod n$

If everything goes correctly, $k = k'.
The advantage of this protocol over Diffie-Hellman is that $k$ can be computed before any interaction, and Alice can encrypt a message using $k$ prior to contacting Bob. She can send it to a variety of people and interact with them to exchange the key later.

# Key Exchange Without Exchanging Keys

If you have a community of users, each could publish a public key, $X = g^y \mod n$, in a common database. If Alice wants to communicate with Bob, she just has to retrieve Bob's public key and generate their shared secret key. She could encrypt a message with that key and send it to Bob. Bob would retrieve Alice's public key to generate the shared secret key.

Each pair of users would have a unique secret key, and no prior communication between users is required. The public keys to be certified to prevent spoofing attacks and should be changed regularly, but otherwise this is a pretty clever idea.
