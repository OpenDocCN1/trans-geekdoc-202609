Some keys produce four subkeys, each four times in the algorithm. These **possibly weak** keys are listed in Table 12.13.
Before condemning DES for having weak keys, consider that this list of 64 keys is minuscule to the total set of 72,057,594,037,936 keys. If you select a random key, the odds of picking one of these keys is negligible. If you are truly paranoid, you could always check for weak keys during key generation. Some people don't think it's worth the bother. But since it is so easy to check, there's no reason not to.

There is further analysis on key and semiwak keys in [1116], and additional key patterns have been investigated for weaknesses. None have been found.

# Complement Keys

Take the bitwise complement of a key; that is, replace all the 0s with 1s and the 1s with 0s. If the original key encrypts a block of plaintext, then the complement of the key will encrypt the complement of the plaintext block into the complement of the ciphertext block.

If $x'$ is the complement of $x$, then the identity is as follows:

```
$E_x(P) = C$
$E_{x'}(P') = C'$
```

This isn't anything mysterious. The subkeys are XORed with the right half after the expansion permutation in every round. This **complement property** is a direct result of that fact.
