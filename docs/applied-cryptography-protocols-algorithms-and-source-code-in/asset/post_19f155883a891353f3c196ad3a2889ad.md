There are four nonlinear functions, used in each operation (a one for each round).

$\oplus$ is XOR, $\wedge$ is AND, $\vee$ is OR, and $\neg$ is NOT. These functions are designed so that the corresponding bits of X, Y, and Z are independent and unbiased, and each bit of the result will be independent and unbiased. The function $F$ is the bit-wise conditional: If X then $Y$ else $Z$. The function $H$ is the bit-wise conditional.

If $M$ represents the $i$th sub-block of the message (from 0 to 15), and $<<<$ represents a left circular shift of $s$ bits, the four operations are:

```
FF(a,b,c,d,M,s,t) denotes $a = b + ((a + F(b,c,d) + M_i) + t_i) <<< s)$
GG(a,b,c,d,M,s,t) denotes $b = c + ((b + G(b,c,d) + M_i) + t_i) <<< s)$
HH(a,b,c,d,M,s,t) denotes $c = d + ((c + H(b,c,d) + M_i) + t_i) <<< s)$
II(a,b,c,d,M,s,t) denotes $d = a + ((d + I(b,c,d) + M_i) + t_i) <<< s)$
```

# Security of MD5

Ron Rivest outlined the improvements of MD5 over MD4 [1322]:

- 1. A fourth round now has a unique additive constant.
2. Each step now has a unique constant.
3. The function G in round 2 was changed from [(X ^ Y) ∨ (X ^ Z) ∨ (Y ^ Z)] to [(X ∧ Z) ∨ (Y ~ Z)] to make G less symmetric.
4. Each step now adds the result of the previous step. This promotes a faster avalanche effect.
5. The order in which message sub-blocks are accessed in rounds 2 and 3 is changed, to make these patterns alike.
6. The left circular shift amounts in each round have optimized, to yield a faster avalanche effect. The four shifts used in each round are different from the ones used in other.

# 18.6 MD2

MD2 is another 128-bit one-way hash function designed by Ron Rivest [8,135]. It, with MD5, is used in protocols [see Section 24]. The security of MD2 is dependent on a random permutation. This permutation is fixed, and depends on the digits of $S_0, S_1, \dots, S_{35}$ is the permutation. To hash a message:

- (1) Pad the message with bytes of value $i$ so that the resulting message is a multiple of 16 bytes.
- (2) Append a 48-byte checksum to the message.
- (3) Initialize 48-byte block $X_0, X_1, X_2, \dots, X_{47}$. Set the first 16 bytes of $X$ to be 0, the second 16 bytes of $X$ to be the first 16 bytes of the message, and the third 16 bytes of $X$ to be the first 16 bytes of $X$ and the second 16 bytes of $X$.
- (4) This is the compression function:
```
t = 0
For j = 0 to 17
For k = 0 to 47
t = X_k
t = (t + j) mod 256
```
- (5) Set the first 16 bytes of $X$ to be the second 16 bytes of $X$ to be the XOR of the first 16 bytes of the message, and the second 16 bytes of $X$. Repeat step [4] and [5] with every 16 bytes of the message.
- (6) The output is the first 16 bytes of $X$.

Although no weaknesses in MD2 have been found [see [12]], it is slower than most hash functions.

# 18.7 SECURE HASH ALGORITHM (SHA)

NIST, along with the NSA, designed the Secure Hash Algorithm (SHA) for use with the Digital Signature Standard [see Section 20.2] [15]. (The standard is the Secure Hash Standard (SHS), SHA is the algorithm used in.) According to the Federal Register [53].

A Federal Information Processing Standard (FIPS) for Secure Hash Standard [SHS] is being proposed. This proposed standard specifies a Secure Hash Algorithm [SHA] for use with the proposed Digital Signature. Additionally, for applications not requiring a digital signature, the SHA is to be used whenever a secure hash is required for applications.

This standard specifies a Secure Hash Algorithm (SHA), which is necessary to ensure the security of the Digital Signature Algorithm (DSA). When a message of any length <2^64 bits is input, the SHA produces a 160-bit output called a message digest. The message digest is input to the DSA, which computes the signature for the message. Signing the message digest rather than the message often improves the efficiency of the process, because the message digest is usually much smaller than the message. The same message digest should be obtained by the verifier of the signature when the received version of the message is used as input to SHA. The SHA is secure because it is designed to be computationally infeasible to recover a message corresponding to a given digest, or to find two different messages that produce the same message digest. Any change to a message in transit will, with a very high probability, result in a different message digest, and the signature will fail to verify. The SHA is based on principles similar to those used by Professor Ronald L. Rivest of MIT designing the MD4 message digest algorithm [13], and is closely modeled after that.

SHA produces a 160-bit hash, longer than MD5.
