# Biases and Correlations

A major problem with all these systems is that there could be nonrandomness in the generated sequence. The underlying physical processes might be between the digital part of the computer and the physical process. These instruments could easily introduce problems.
A to eliminate bias, or skew, is to XOR several bits together. If a random bit is biased toward 0 by a factor e, then the probability of 0 can be written as:

```
P(0) = .5 + e
```

XORing two bits together yields:

```
P(0) = |.5 + e|^2 + |.5 - e|^2 = .5 + 2e^2
```

By the same calculation, XORing 4 bits together yields:

```
P(0) = .5 + 8e^4
```

XORing m bits will exponentially converge to an equal probability of 0 and 1. If you know the maximum bias you are willing to accept for your application, you can calculate how many bits you need to XOR in pairs to get random bits below that bias.

An even better method is to look at the bits in pairs. If the 2 bits are different, take the first as the output of the generator and the second at the next pair. This eliminates bias completely. The potential problem with both methods is if there is a correlation between adjacent bits, these methods will increase the bias. One way to correct this is to use multiple random sources. Take four different random sources and XOR them together, or take two random sources, and look at them bits in pairs.
