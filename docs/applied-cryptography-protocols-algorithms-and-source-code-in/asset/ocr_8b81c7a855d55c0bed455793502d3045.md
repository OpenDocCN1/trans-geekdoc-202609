# Broadcasting a Message

Imagine that you have 100 operatives out in the field. You can be able to send messages to subsets of them, but dont which subsets in advance. You can either encrypt the message separately for each person or give out keys for every possible combination of people. The first option requires a lot of messages; the second requires a lot of.

Multiple-key cryptography is much easier. We'll use operatives: Alice, Bob, and Carol. You give Alice $K_A$ and $K_B$, Bob $K_A$ and $K_C$, and Carol $K_B$ and $K_C$. Now you can talk to any subset of them. If you want to send a message so that only Alice can read it, encrypt it with $K_C$. When Alice receives the message, she decrypts with $K_A$ and $K_B$. If you want to send a message so that only Bob can read it, encrypt it with $K_A$ and $K_C$ so that Alice and Bob can both read it, encrypt it with $K_A$ and $K_C$ and so on.

This might not be exciting, but with 100 operatives it is efficient. Individual messages share a shared key with each operative (100 keys total) and each message. Keys for every possible subset means $2^{100}-2$ different keys [messages to all operatives and no operatives are excluded]. This scheme needs only one encrypted message and 100 different keys. The drawback of this scheme is that which subset of operatives can read the message, otherwise each operative would have to try every combination of possible keys looking for the correct one. Even just the names of the intended recipients may be significant. At least for the straightforward implementation of this, everyone gets a really large amount of key data.

There are other techniques for message broadcasting, some of which avoid the previous problem. These are discussed in Section 22.7.
