A naïve variation might double the block size. The algorithm would work just well with 32-bit sub-blocks instead of 16-bit sub-blocks, and a 256-bit key. Encryption would be quicker and security would increase 2³² times. Would would it? The theory behind the algorithm hinges on the fact that 2¹⁶ + 1 is prime; Perhaps the algorithm could be modified to work, but it would have very different security properties. Lai says it would be difficult to make it work [926].

While IDEA appears to be significantly secure than DES, it's always easy to substitute one for the other in an existing application. If your database and templates are hardened to accept a 64-bit key, it may be impossible to implement IDEA's 128-bit key.

For applications, generate a 128-bit key by concatenating the 64-bit key with itself. Remember that IDEA is weakened considerably by this modification.

If you are more concerned with speed than security, you might consider a variant of IDEA with fewer rounds. Currently the best attack against IDEA is faster than brute force for 2.5 rounds or less [1050]; 4 round IDEA would be twice as fast as brute, and far as I know, just as secure.

# Caveat Emper

IDEA is a relatively new algorithm, and many questions remain. Is IDEA a group? (Lai thinks not [926].) Are there still-undiscovered ways of breaking this cipher? IDEA has a theoretical basis, but time and time securing algorithms have fallen to new forms of cryptanalysis. Several academic and military groups have cryptanalized IDEA. None of them have gone public about successes they might have had. One—someday.

# 13.10 MMB

A complaint against IDEA, that it uses a 64-bit encryption block, was addressed by Joao Daemon in an algorithm called MMB (Modular Multiplication-based cipher); MMB is based on the same theory as IDEA: mixing operations of different algebraic groups. MMB is an iterative algorithm that mainly consists of linear steps (XOR and key operations) and the parallel applications of four large nonlinear substitutions. These substitutions are determined by a multiplication modulo 2³⁸ – with constant factors. The result is an algorithm that has both a 128-bit key and a 128-bit block size.

MMB operates on 32-bit sub-blocks of text [X₀, X₁, X₂, X₃] and 32-bit sub-blocks of key [K₀, K₁, K₂, K₃]. This makes the algorithm well suited for implementation on modern, 32-bit processors.
