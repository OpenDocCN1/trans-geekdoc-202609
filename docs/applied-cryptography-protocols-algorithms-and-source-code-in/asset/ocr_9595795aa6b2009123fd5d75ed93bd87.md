Here's how it works. As usual, Alice and Bob want to authenticate each other and generate a common key. They agree on some digital signature scheme where any number can serve as the private key, and the public key is derived from the private key, rather than being generated along with it. The ElGamal and DSA algorithms work with the private key. Alice's password $P$ (or perhaps some simple hash of it) will serve as the private key and as $P'$.

+   (1) Alice picks her random exponent $R_b$ and transmits
$E_P^{R_b} \mod n$

+   (2) Bob, who knows only $P'$ and cannot derive $P$ from it, chooses $R_b$ and sends
$E_P^{R_b} \mod n$

+   (3) Alice and Bob calculate the shared session key $K = g^{A' \cdot b} \mod n$.
Finally, Alice proves that she knows $P$ itself, and not just $P'$, by sending $E_K(S(K))$

Bob, who knows $K$ and $P'$, can decrypt and validate the signature. Only Alice could have sent this message, since she knows $P$; an intruder who obtains a copy of Bob's password file by trying at $P$, but cannot otherwise see the session key.

The A-EKE scheme does not work with the public-key variant of EKE, since in it one party chooses the session key and imposes it on the other. This permits a man-in-the-middle attack by an attacker who has captured $P'$.

# Applications of EKE

Bellovin and Merritt suggest using public telephones using this protocol for secure public telephones [109].

Let us assume use one of these phones, some sorting of key information must be provided. Conventional solutions... require that the caller possess a physical key. This is undesirable in many situations. EKE permits use of a short, keypad-entered password, but uses a much longer key for the call.

EKE would also be useful with cellular phones. Fraud has been a problem in the cellular industry, EKE can defend against [and ensure the privacy of the call] by rendering a phone useless if a PIN has not been entered. Since the PIN is not stored within the phone, it is not possible to retrieve one from a stolen unit.
