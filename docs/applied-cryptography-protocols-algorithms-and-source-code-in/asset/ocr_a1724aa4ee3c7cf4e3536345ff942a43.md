# 2.5 Communications Using Public-Key Cryptography

Think of it as a way of fingerprinting files. If you want to verify that someone has a particular file (that you also have), but you don't want to send it to you, then ask him for the hash value. If he sends you the correct hash value, then it is almost certain that he has that file. This is particularly useful in financial transactions, where you don't want a withdrawal of $100 to turn into a withdrawal of $1000 somewhere in the network. Normally, you would use a one-way hash function without a key, so anyone can verify the hash. If you want only the recipient to be able to verify the hash, then read the next section.

# Message Authentication Codes

A message authentication code (MAC), also known as a data authentication code (DAC), is a one-way hash function with the addition of a secret key (see Section 18.14). The hash value is a function of both the pre-image and the key. The theory is exactly the same as hash functions, except only with the key can verify the hash value. You can create a MAC out of a hash function or a block encryption algorithm; there are also dedicated MACs.

# 2.5 COMMUNICATIONS USING PUBLIC-KEY CRYPTOGRAPHY

Think of a symmetric algorithm as a safe. The key is the combination. Someone with the combination can open the safe, put a document inside and close it. Someone else with the combination can open the safe and take the document out. Anyone without the combination is forced to learn secrecy.

In 1976,field Diffie and Martin Hellman claimed that paradigm of cryptography as early as 1966, but had no proof.[1] They described widely for [46]. They described public-key cryptography. They used two keys—one public and the other private. It is computationally hard to reduce the private key from the public key. Anyone with the private key can encrypt the message. It is as if someone turned the cryptographic safe into a mailbox. Putting the mail in the mailbox is analogous to encrypting with the public key; anyone can do it. Just open the safe and drop it in. Getting out of a mailbox is analogous to decrypting with the private key. Generally it's hard; like welding torches. However, if you have the secret (the physical key to the mailbox), it's easy to get out of a mailbox.

Mathematically, the process is based on the trap-door one-way functions previously discussed. Encryption is the easy direction. Instructions for encryption are the public key, anyone can encrypt a message. Decryption is the hard direction. It is made hard enough that people with Cray computers and thousands (even millions) of years couldn' decrypt the message without the secret. The secret, or trapdoor, is the private key. With that secret, decryption is as easy as encryption.
