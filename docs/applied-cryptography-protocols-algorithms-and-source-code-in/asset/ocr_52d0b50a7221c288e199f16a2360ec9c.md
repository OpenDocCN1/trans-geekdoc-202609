# Random Keys

Good keys are random-bit strings generated by some automatic process. If the key is 64 bits long, every possible 64-bit key must be equally likely. Generate the key from either a reliable random source (see Section 17.14) or a cryptographically secure pseudo-random generator (see Chapters 16 and 17.) If these automatic processes are unavailable, flip a coin or roll dice.

This is important, but don't get caught in arguing about whether random noise audio sources is more random than random noise from radioactive decay. None of these random-noise sources will be perfect, but they will probably be good enough. It is important to use a good random-number generator for key generation, but it is far more important to use good encryption algorithms and key management procedures. If you are worried about the randomness of your keys, use the keycrunching technique described below.

Some encryption algorithms have weak keys: specific keys that are less than the other keys. I advise testing for these weak keys and generating a new one if you discover one. DES has 16 weak keys out of 256, so the odds of generating any of these are incredibly small. It has been argued that a cryptanalyst would have no idea that a weak key is used and therefore gives no advantage from their accidental use. It has also been argued that not using weak keys gives a cryptanalyst information. However, testing for the few keys is so easy that it is prudent not to do so.

Generating keys for public-key cryptography systems is harder, because often the keys have certain mathematical properties (they may have to be prime, a quadratic residue, etc.) Techniques for generating large random prime numbers are discussed in Section 11.5. The important thing to remember from a key management point of view is that the random seed for those generators must be just that: random.
