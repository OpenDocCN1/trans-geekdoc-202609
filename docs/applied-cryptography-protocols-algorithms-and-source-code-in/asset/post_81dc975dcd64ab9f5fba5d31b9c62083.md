## 16.7 Nanoteq

Nanoteq is a South African electronics company. This is their algorithm that has been fielded by the South African police to encrypt their fax transmissions, and presumably suitably for others uses.

The algorithm is designed, more or less, in [902,903]. It uses a 127-bit LFSR with a fixed feedback polynomial, the key is the initial state of the feedback register. The 127 bits of register are reduced to a single keystream by 25 primitive cells. Each cell has five inputs and one output:

```
$f(X_1,X_2,X_3,X_4,X_5) = X_1 + X_3 \oplus [X_2 + X_4] \oplus [X_2 + X_5] \oplus [X_1 + X_4 \oplus X_5]$
```

Each input is XORed with some bit of the key. There is also a secret permutation that depends on the particular implementation, and is detailed in the papers. This algorithm is only available in hardware.

Is this algorithm secure? I doubt it. During the transition to majority rule, harassing faxes from one police station to another would sometimes turn up in liberal newspapers. ## 16.8 Rambutan

Rambutan is a British algorithm, designed by the Communications Electronics Security Group (one of the aliases used by GCHQ). It is only sold as a hardware module and is approved for the protection of classified material up to "Confidential." The algorithm itself, and the chip are not generally commercially available.

Rambutan has a 112-bit key [parity bits] and can operate in three modes: ECB, CBC, and 8-bit CFB. This strongly indicates that it is a block algorithm, but rumors place elsewhere. So, it is a LFSR shift register. Each one of different length around 80 bits. The feedback polynomials are fairly sparse, with only about 10 taps each. Each shift register provides four inputs to a large and complex nonlinear function that eventually spits out a bit.

Why call Rambutan? Perhaps, like the fruit, it's spiny and forbidding on the outset soft and yielding inside. On the other hand, maybe that's not the reason.

## 16.9 Additive Generators

Additive generators (sometimes called Fibonacci generators) are extremely efficient because they produce random words instead of random bits [863]. They are not secure on their own, but can be used as building blocks for secure generators.

The initial state of the generator is an array of n-bit words: 8-bit words, 16-bit words, 32-bit words, whatever: $X_1, X_2, X_b, \dots, X_m$. This initial state is the key. The i-th word of the generator is

```
$X_i = (X_{i-a} + X_{i-b} + X_{i-c} + \dots + X_{i-m}) \bmod 2^n$
```

If the coefficients $a, b, \dots, m$ are chosen at random, the period of this generator is at $2^n-1$. One of the requirements on the coefficients is that the least significant bit forms a maximal-length LFSR.

For example, [55,24,0] is a primitive polynomial mod 2 from Table 16.2. This means that the following additive generator is maximal length.

```
$X_i = (X_{i-55} + X_{i-24}) \bmod 2^n$
```

This works because the primitive polynomial has three coefficients. If it has more than three, you will need some additional requirements to make it maximal length. See [249] for details.

### Fish

Fish is an additive generator based on techniques used in the shrinking generator [190]. It produces a stream of 32-bit words which can be XORed with a plaintext stream to produce ciphertext, or XORed with a ciphertext to produce plaintext. The algorithm is named as it is because it is a Fibonacci shrinking generator. First, use two additive generators. The key is the initial values of these generators.

```
$A_i = (A_{i-55} + A_{i-24}) \bmod 2^{32}$
$B_i = (B_{i-53} + B_{i-10}) \bmod 2^{32}$
```

These sequences are used, as a pair, depending on the least significant bit of $B_i$; if it is 1, use the pair; if it is 0, ignore the pair. The sequence of used words from $A_i$ and $D_i$ is the sequence of used words from $B_i$. These words are used in pairs—$C_{2i}, C_{2i+1}, D_{2i}, D_{2i+1}$—to generate 32-bit output words: $K_{2i}$ and $K_{2i+1}$.

```
$E_{2i} = C_{2i} \oplus (D_{2i} \wedge D_{2i+1})$
$F_{2i} = D_{2i} + 1 \wedge (E_{2i} \oplus C_{2i+1})$
$K_{2i} = E_{2i} \oplus F_{2i}$
$K_{2i+1} = C_{2i+1} \oplus F_{2i}$
```

This algorithm is fast. On 33 megahertz, a C implementation encrypts data at 15 megabytes per second. Unfortunately, it is also insecure; an attack work factor of about $2^{48}$ [45].

### Pike

Pike is a leaner version of Fish, brought by Ross Anderson, the man who broke Fish [45]. It uses three additive generators. for example:

```
$A_i = (A_{i-55} + A_{i-24}) \bmod 2^{32}$
$B_i = (B_{i-57} + B_{i-7}) \bmod 2^{32}$
$C_i = (C_{i-58} + C_{i-19}) \bmod 2^{32}$
```

To generate the keystream, look at addition bits. If all three agree (all are 0 or all are 1), then clock all generators. If they do not, just clock the two generators that agree. Save the carry bits for next time. The final output is the XOR of the three generators. Pike is from Fish, on average 2.75 steps is required per output. It is far too new to trust, but looks good far.

### Mush

$A_i = (A_{i-55} + A_{i-24}) \bmod 2^{32}$
$B_i = (B_{i-52} + B_{i-19}) \bmod 2^{32}$

On average, three iterations are required to produce one word. And if the coefficients of the additive generators are chosen correctly and are relatively prime, the output sequence will be maximal length. I know no successful attacks, remember that this algorithm is very new.

## 16.10 Gifford

David Gifford invented a stream cipher and used it to encrypt reports in the Boston area from 1984 until 1988 [608,607,609]. The algorithm has a single 8-byte register: $b_0, b_1, \dots, b_7$. The key is the initial state of the register. The algorithm works in OFB, the plaintext does not affect the algorithm at all. [See Figure 16.7].

To generate a key $k_i$, concatenate $b_0$ and $b_1$ and concatenate $b_5$ and $b_7$. Multiply the two together to get a 32-bit number. To update the register, take $b_i$ and right shift it 1. This means the leftmost is shifted and remains in place. Take $b_7$ and shift it 1 to the left, there should be a 0 in the rightmost. Take the XOR of the modified $b_1$, and $b_0$. Shift the original register 1 to the right and put this byte in the leftmost position.

This algorithm remained secure throughout its life, but was broken in 1994 [287]. Turns out that the feedback polynomial is not primitive and can be attacked that way—ops.

## 16.11 Algorithm M

The name is from Knuth [863]. It's a method for combining multiple pseudo-random streams that increases their security. One generator's output is used to select a delayed output from the other generator [996,1003]. In C:

```
#define ARR_SIZE (8192) /* for example - the larger better */
static unsigned char delay[ARR_SIZE ];

unsigned char prngA( void );
long prngB( void );

void init_algM( void )
{
  long i;

  for ( i = 0 ; i < ARR_SIZE ; i++ )
    delay[i] = prngA( );
} /* init_algM */

unsigned char algM( void )
{
  long j,v ;
  j = prngB() % ARR_SIZE ;      /* get the delay[] index */
  v = delay[j];               /* get the value to return */
  delay[j] = prngA();        /* replace it */
```

This has strength in that if prngA were truly random, one could not learn anything about prngB and could therefore not crystallize it. If prngA were of the form that it could be crystallized only if its output was available in order (i.e., only if prngB were crystallized first) and otherwise it was effectively truly random, then the combination would be secure.

## 16.12 PKZIP

Roger Schla designed the encryption algorithm built into the PKZIP data program. It's a stream cipher that encrypts data one byte at a time. At least, this is the algorithm in 2.04g. I can't speak for later versions, but unless there is some amount you probably assume that they are identical. The algorithm uses 32-bit variables, initialized as follows:

```
K_0 = 305419896
K_1 = 591751049
K_2 = 878082192
```

It has an 8-bit key, derived from K_2. Here is the algorithm [all symbols are standard C notation]:
C_i = P ^ K_5
K_0 = crc32(K_0 & 0x000000ff)
K_1 = K_1 • 1347758813 + 1
K_2 = crc32([K_2, K_1] >> 24)
K_3 = {[K_2 | 2]} | {(K_2 ^ 1]} >> 8

The function crc32 takes the previous value and a byte, XOR them, and calculates the next value by the CRC polynomial denoted by 0x88320. In practice, a 256-entry table can be precomputed and the crc32 calculation becomes:

```
crc32(a, b) = (a >> 8) ^ table[(a & 0xff) ^ b]
```

The table is precomputed by the original definition of crc32:

```
table[i] = crc32(i, 0)
```
