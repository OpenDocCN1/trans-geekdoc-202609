# 2.8 RANDOM AND PSEUDO-RANDOM-SEQUENCE GENERATION

Why bother with random-number generation in a book on cryptography? There's already a random-number generator built into most compiler, a mere function call. Why not use that? Unfortunately, those random-number generators are almost definitely not secure for cryptography, and probably not even random. Most of them are embarrassingly bad.

Random-number generators are not random because need few random numbers that hardly notice. However, cryptography is extremely sensitive to the properties of random-number generators. Use a poor random-number generator and you start getting weird correlations and string results [1231,1238]. If you are depending on your random-number generator for sequence, weird correlations and strange results are the last things you want.

The problem is that a random-number generator doesn't produce a random sequence. It probably doesn't produce anything that looks remotely like a random sequence. Of course is impossible to produce truly random on a computer. Donald Knight quotes von Neumann as: "Anyone who considers arithmetic methods of producing random digits is, of course, in a state of sin" [863]. Computers are deterministic: State goes in one, completely dictable operations occur inside, and different stuff comes out the end part. The same stuff in two separate occasions and the same stuff comes out both times. The same stuff into two identical computers, and the same stuff comes out of them. A computer can only be in a finite number of states (a large finite number, but a finite number nonetheless), and the stuff that will always be a deterministic function of the state that went in and the computer's current state. It means that any random-number generator on a computer (at least, in a finite-state machine) is, by definition, periodic. And if it is periodic, by definition, dictable. And if dictable, it can't be random. A true random-number generator requires some random input, a computer can't provide that.
