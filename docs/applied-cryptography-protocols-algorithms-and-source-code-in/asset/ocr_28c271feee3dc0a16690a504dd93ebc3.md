Primitive polynomials are fastest in software, unless two bits of the shift register have to be XORed to generate each new bit. Actually, all the feedback polynomials listed in Table 16.2 are sparse, meaning that they only have a few coefficients. Sparseness is a source of weakness, sometimes break the algorithm. It is better to use dense polynomials, those with a lot of coefficients, for cryptographic applications. If you use dense polynomials, and especially if you make them part of the key, you can have shorter LFSRs.

Generating dense polynomials modulo 2 is not easy. In general, to generate primitive polynomials of degree $k$ you need to know the factorization of $2^k-1$. Three good references for finding primitive polynomials are [652,1285,1287].

LFSRs are decent pseudo-random-sequence generators all by themselves, but they have some annoying nonrandom properties. Sequential bits bits are linear, which make them useless for encryption. For an LFSR of length $n$, the internal state is the next $n$ output bits of the generator. If the feedback scheme is unknown, it can be determined from only $2n$ output bits of the generator, by using the highly efficient Berlekamp-Massey algorithm [1082,1083]; See Section 16.3.

Also, large random numbers generated from sequences of this sequence are highly correlated, and for certain types of applications, not very random at all. Even so, LFSRs are often used as building blocks in encryption algorithms.

# LFSRs in Software

LFSRs are slow in software, but they are faster in assembly language than in C. One solution is to run 16 LFSRs (or 32, depending on your computer's word size) in parallel. This scheme uses an array of words that is the length of the LFSR, with each bit position in the words representing a different LFSR. Assuming all the feedback polynomials are the same, this can run quite quickly. In general, the best way to update shift registers is to multiply the current state by suitable binary matrices [9901].

It is also possible to modify the LFSR's feedback scheme, but it still has a maximum period and is easy to implement in software [1272]. Instead of using the bits in the tap sequence to generate the new left-most bit, each bit in the tap sequence is XORed with the output of the generator and replaced; then the output of the generator becomes the new left-most bit (see Figure 16.5). This is sometimes called a Galois configuration.
