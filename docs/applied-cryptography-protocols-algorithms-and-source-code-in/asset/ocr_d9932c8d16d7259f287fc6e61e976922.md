# Diffie's Randomized Stream Cipher

This scheme was first proposed by Whitfield Diffie [1362]. The data are $2^n$ sequences. The key is $k$, a random $n$-bit string. To encrypt a message, Alice uses the $k$ random string as a one-pad. She then encrypts the ciphertext plus the $2^k$ random strings over $2^k+1$ different communications channels.
Bob $k$ has no choice but to easily choose which one-pad to decrypt the message at time until he finds the correct one-pad. Any attack must examine an expected number of bits which is $O(2^n)$. Rueppel points out that if you send $n$ random strings instead of $2^n$, and if the key is used to specify a linear combination of random strings, the security is the same.

# Maurer's Randomized Stream Cipher

Ueli Maurer described a scheme based on XORing the plaintext with several large random-bit sequences [1034, 1029, 1030]. The key is the set of starting positions within each sequence. This turns out to be provably secure, with a calculable probability of being broken by how much memory the attacker has at his disposal, without regard to the amount of computing power he has. Maurer claims that this scheme would be practised with about 100 different sequences of $10^{30}$ random bits. Digitizing the face of the moon might be one way to get many bits.

# 17.11 CASCADING MULTIPLE STREAM CIPHERS

If performance is issue, there is no reason not to choose multiple stream ciphers and cascade them. Simply XOR the output of each generator with the plaintext to get the ciphertext. U Maurer's result [see Section 15.7] says that if the generators have independent keys, the security of the cascade is at least secure as the strongest algorithm in the cascade. It is much more secure than that.

Stream ciphers can be combined in all the ways as block ciphers [see Chapter 15]. Stream ciphers can be cascaded [see Section 15.7] with other stream ciphers, or together with block ciphers.
