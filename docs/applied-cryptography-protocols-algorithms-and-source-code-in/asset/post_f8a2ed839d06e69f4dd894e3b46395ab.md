## 19.7 McEliece

In 1978 Robert McEliece developed a public-key cryptosystem based on algebraic coding theory [1041]. The algorithm makes use of the existence of a class of error-correcting codes, known as Goppa codes. His idea was to construct a Goppa code and disguise it as a general linear code. There is a fast algorithm for decoding Goppa codes, but the general problem of finding a code word of a given weight in a linear binary code is NP-complete. A good description of this algorithm can be found in [1233], also see [1562]. Following is a quick summary.

Let $d_H(x,y)$ denote the Hamming distance between $x$ and $y$. The numbers $n, k,$ and $t$ are system parameters.

The public key has three parts: $G'$ is $k \cdot n$ generator matrix for a Goppa code that can correct $t$ errors. $P$ is an $n \cdot n$ permutation matrix. $S$ is a $a \cdot k$ nonsingular matrix.

Plaintext messages are strings of bits, in the form of $k$-element vectors over GF(2). To encrypt a message, choose a random $n$-element vector over GF(2), $z$, with Hamming distance less than or equal to $t$.

```
$c = MG + z
```

To decrypt the ciphertext, first compute $c' = cP^{-1}$. Then, using the decoding algorithm for the Goppa code, find $m'$ such that $d_H(m',G')$ is less than or equal to $t$. Finally, compute $m = m'S^{-1}$.

In his original paper, McEliece suggested that $n = 1024, t = 50,$ and $k = 524$. These are the minimum values required for security.

Although the algorithm was one of the first public-key algorithms, and there were no successful cryptanalytic results against the algorithm, it has never gained wide acceptance in the cryptographic community. The scheme is two to three orders of magnitude faster than RSA, but the public key is enormous: 2¹⁰ bits long. The data expansion is large: the ciphertext is twice as large as the plaintext.

Some attempts at cryptanalysis of this system can be found in [8,943,155,306]. None of these were successful in the general case, although the similarity between the McEliece algorithm and knapsacks worried some.

In 1991, Russian cryptographers claimed to have broken the McEliece system with some parameters [882]. Their paper contained no evidence to substantiate their claim, and other cryptographers discount the result. Another Russian attack, that cannot be used directly against the McEliece system, is in [1447,1448]. Extensions to McEliece can be found in [424,1227,976].

## Other Algorithms Based on Linear Error-Correcting Codes

The Niederreiter algorithm [1167] is closely related to the McEliece algorithm, and assumes that the public key is a random parity-check matrix of an error-correcting code. The private key is an efficient decoding algorithm for this matrix.

Another algorithm, used for identification and digital signatures, is based on syndrome decoding [1501]; see [306] for comments. An algorithm based on error-correcting codes [1621] is in [698,33,31,3650].

## 19.8 ELLIPTIC CURVE CRYPTOSSYSTEM

Elliptic curves have been studied for years and there is an enormous amount of literature on the subject. In 1985, Neal Koblitz and V. Miller independently proposed them using public-key cryptosystems [867,1095]. They did not invent a new cryptographic algorithm with elliptic curves over finite fields, but they implemented existing public-key algorithms, like Diffie-Hellman, using elliptic curves.

Elliptic curves are interesting because they provide a way of constructing “elements” and “rules of combining” that produce groups. These groups have enough familiar properties to build cryptographic algorithms, but for example, they don't have certain properties that facilitate cryptanalysis. Here, there is no set of small elements in them to “smooth” with elliptic curves. That is, no element has a good chance of being expressed by a single algorithm. Hence, index calculus algorithms do not work. [1095] for more details.

Elliptic curves over the finite field GF(²) are particularly interesting. The arithmetic for the underlying field are easy to construct and are simple to implement for n in the range of 130 to 200. They have the potential to provide faster public-key cryptystems with smaller keys. Many public-key algorithms, like Diffie-Hellman, ElGamal, and Schnorr, can be implemented in elliptic curves over finite fields.

## 19.9 LUC

Some cryptographers have developed generalizations of RSA that use various polynomials instead of exponentiation. A variation Kravitz-Reed, using irreducible polynomials [898], is insecure [451,589]. Winfried Müller and Wilfried Nöbauer Dickson polynomials [1127,1128,965]. Rudolf Lidl and Müller generalized this approach in [966,1126 (a variant called the Révi scheme), and Nöbauer used it at [969,967,968,599]. Despite on prime generation with Lucas functions and all of this prior art, a group of researchers from New Zealand managed to patent this scheme in 1993, calling it LUC [1486,521,1487].

The nth Lucas number, $V_n(P)$, is defined as

```
$V_n(P) = pV_{n-1}(P) - V_{n-2}(P)
```

There's a lot more to Lucas numbers I'm ignoring all of it. A good theoretical treatment of Lucas sequences is in [1307,1308]. A particularly nice description of the mathematics of LUC is in [1494,770].

In any case, to generate a public-key/private-key pair, first choose two large primes, $p$ and $q$. Calculate $n$, the product of $p$ and $q$. The encryption key $e$, is a random number that is relatively prime to $p-1, q-1, p+1$, and $q+1$.

There are four possible cryptystems:

```
$d = e^{-1} \pmod{lcm(p+1, q+1)}$
$d = e^{-1} \pmod{lcm(p+1, q-1)}$
$d = e^{-1} \pmod{lcm(p-1, q+1)}$
$d = e^{-1} \pmod{lcm(p-1, q-1)}$
```

where lcm is the common multiple.

The public key is $d$ and $n$; the private key is $e$ and $n$. Discard $p$ and $q$.
To encrypt a message, $P$ [$P must be less than $n$], calculate

```
$C = V_e(P,1) \pmod n
```

And to decrypt:
$P = V_d(C,1) \pmod n$, with the proper $d$

At least, LUC is no more secure than RSA. And recent, still-unpublished works show how to break LUC in at least some implementations. I just don't trust it.

## 19.10 FINITE AUTOMATON PUBLIC-KEY CRYPTOSYSTEM

Chinese cryptographer Tao Renii has developed a public-key algorithm based on finite automaton [1301,1302,1303,1300,1304,666]. Just as it is hard to factor the product of two large primes, it is also hard to factor the composition of two finite automata. This is especially so if one or both of them is nonlinear.

Much of this research took place in China in the 1980s and was published in Chinese. Renii is starting to write in English. His main result was that certain nonlinear automaton (quasilinear automaton) possess weak inverses, and if only, they have a certain echelon matrix structure. This property disappears if they are composed with an invertible quasilinear automaton and a linear automaton, and in the public-key algorithm, the secret key is an invertible quasilinear automaton and a linear automaton, and the corresponding public key can be derived by multiplying them out by term. Data is encrypted by passing it through the public automaton, and decrypted by passing it through the inverses of its components (in some cases provided they have been set to a suitable state). This system works for both encryption and digital signatures.
