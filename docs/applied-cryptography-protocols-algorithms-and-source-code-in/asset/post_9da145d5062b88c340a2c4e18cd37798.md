# 19.4 Pohlig-HELLMAN

The Pohlig-Hellman encryption scheme [1253] is similar to RSA. It is not a symmetric algorithm, because it is not a public-key scheme, because different keys are used for encryption and decryption. both the encryption and decryption keys must be kept secret.
Like RSA,

```
$C = P^k \pmod n$
$P = C^d \pmod n$
```

where

```
$ed = 1 \pmod{some complicated number}$
```

Unlike RSA, n is not defined in terms of two large primes, it must remain part of the secret key. If someone has $e$ and $n$, they could calculate $d$. Without knowledge of $e$ or $d$, an adversary would be forced to calculate

```
$e = \log_C \pmod n$
```

We have already seen that this is a hard problem.

# Patents

# 19.5 RABIN

Rabin's scheme [1283,1601] gets its security from the difficulty of finding square roots modulo a composite number. This problem is equivalent to factoring. Here is one implementation of this scheme.

First two primes, $p$ and $q$, both congruent to 3 mod 4. These primes are the private key, the product $n = pq$ is the public key.
To encrypt a message, $M$ [must be less than $n$], compute

```
$C = M^2 \pmod n$
```

Decrypting the message is just as easy, but slightly more annoying. Since the receiver knows $p$ and $q$, he can solve the two congruences using the Chinese remainder theorem. Compute

```
$m_1 = C^{1/4} \pmod p$
$m_2 = [p - C^{1/4}] \pmod p$
$m_3 = C^{1/4} \pmod q$
$m_4 = [q - C^{1/4}] \pmod q$
```

Then an integer $a = q(q^{-1} \pmod p)$ and an integer $b = p[p^{-1} \pmod q]$. The four possible solutions are:

```
$m_1 = [am_1 + bm_3] \pmod n$
$m_2 = [am_1 + bm_4] \pmod n$
$m_3 = [am_2 + bm_3] \pmod n$
$m_4 = [am_2 + bm_4] \pmod n$
```

One of those fours, $M_1, M_2, M_3$, or $M_4$, equals $M$. If the message is English, it should be easy to choose the $M_i$. On the other hand, if the message is a random-bit stream (say, for key generation or a digital signature), there is no way to determine which $M_i$ is correct. One way to solve this problem is to add a known header to the message before encrypting.

# Williams

Hugh Williams redefined Rabin's scheme to eliminate these shortcomings [1601]. In his scheme, $p$ and $q$ are selected such that

```
$p = 3 \pmod 8$
$q = 7 \pmod 8$
```

and

```
$N = pq$
```

Also, there is a small integer, $S$. such that $J(S,N) = -1$. ($J$ is the Jacobi symbol—Section 11.3). $N$ and $S$ are prime. The secret key is $k$, such that

```
$k = 1/2 \cdot \{1/4 \cdot (p-1) \cdot (q-1) + 1\}$
```

To encrypt a message $M$, compute $c_1$ such that $J[M,N] = \{-1\}^f$. Then, compute $M' = \{S^1 \cdot M\} \mod N$. Like Rabin's scheme, $C = M'^2 \pmod N$. And $c_2 = M' \mod 2$. The final ciphertext is the triple: $(C, c_1, c_2)$.
To decrypt $C$, the receiver computes $M''$ using $C \equiv \pm M'' \mod N$. The proper sign of $M''$ is given by $c_2$. Finally, $M = \{S^1 \cdot \{-1\}^f \cdot M''\} \mod N$.
Williams refined this scheme further [1603,1604]. Instead of squaring the plaintext, cube it. The large primes must be congruent to 1 mod 3; otherwise the public and private keys are the same. Even better, there is only one unique encryption for each number. Both Rabin and Williams have an advantage over RSA in that they are provably secure as factoring. However, they are completely insecure against chosen ciphertext attack. If you are going to use these schemes in instances where an attacker can choose messages to be signed, be sure to use one-way hash function before signing. Rabin suggested another way of defeating this attack: Append a random string to message before hashing. Unfortunately, once you add one-way hash function to the system it is no longer provably secure as although hashing cannot weaken the system in any practical sense. Rabin variants are [972,906,697,143,989].

# 19.6 ElGamal

The ElGamal scheme [518,519] can be used for both digital signatures and encryption; it gets security from the difficulty of calculating logarithms in a finite field.
To generate a key pair, first choose a prime, $p$, and two random numbers, $g$ and $x$, and ensure that $g$ and $x$ are less than $p$. Then $y = g^x \mod p$. The public key is $y, g$, and $p$. Both $g$ and $p$ can be shared among a group of users. The private key is $x$.

# ElGamal Signatures

To sign a message, $M$, first choose a random number $k$, such that $k$ is relatively prime to $p-1$. Then compute $a = g^k \mod p$ and use the extended Euclidean algorithm to solve for $b$ in the following equation: $M = (ax + kb) \mod (p - 1)$.
The signature is the pair: $a$ and $b$. The random value, $k$, must be secret.
To verify a signature, confirm that $y = g^x \mod p = g^k \mod p$.
Each ElGamal signature or encryption requires a new value of $k$, and that value be chosen. If Eve ever recovers a $k$ that Alice used, she can recover Alice's private key, $x$. If Eve gets two messages signed or encrypted using the same $k$, even if she doesn't know what it is, she can recover $x$. This is summarized in Table 19.5.
For example, choose $p = 11$ and $g = 2$. Choose private key $x = 8$. Calculate $y = g^x \mod p = 2^8 \mod 11 = 3$. The public key is $y = 3, g = 2$, and $p = 11$. Authenticate $M = 5$, first choose a random number $k = 9$. Confirm that $gcd[9,10] = 1$. Compute $a = g^k \mod p = 2^9 \mod 11 = 6$ and use the extended Euclidean algorithm to solve for $b$: $M = (ax + kb) \mod (p - 1)$, $5 = (8 \cdot 6 \cdot 9) \mod 10$. The solution is $b = 3$, and the signature is the pair: $a = 6$ and $b = 3$.

# ElGamal Encryption

A modification of ElGamal can encrypt messages. To encrypt message M, choose a random k, such that k is relatively prime to $p-1$. Then compute

```
$a = g^k \pmod p$
$b = y^k \pmod p$
```

The pair, $a$ and $b$, are the ciphertext. Note that the ciphertext is twice the size of the plaintext.
To decrypt $a$ and $b$, compute

```
$M = b/a^k \pmod p$
```

Since $a = g^k \pmod p$, and $b/a^k = y^kM/g^{km} = M \pmod p$, this works (see Table 19.6). This is really the same as Diffie-Hellman key exchange (see Section 22.1), except that $y$ is part of the key, and the encryption is multiplied by $y^k$.
