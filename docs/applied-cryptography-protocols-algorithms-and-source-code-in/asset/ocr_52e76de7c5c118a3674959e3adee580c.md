Modular arithmetic is just like normal arithmetic: It's commutative, associative, and distributive. Also, reducing each intermediate result modulo $n$ yields the result as during the whole calculation and then reducing the end result modulo $n$.

```
$(a+b) \mod n = ((a \mod n) + (b \mod n)) \mod n$
$(a-b) \mod n = ((a \mod n) - (b \mod n)) \mod n$
$(a^b) \mod n = ((a \mod n)^b) \mod n$
$(a\cdot c) \mod n = (((a\cdot b) \mod n) \cdot (c \mod n)) \mod n$
```

Cryptography uses modulo $n$ because calculating discrete logarithms and square roots mod $n$ can be hard. Modular arithmetic is also easy to work with on computers, because it restricts the range of all intermediate values and the result. For a $k$-bit modulus, $n$, the intermediate results of any addition, subtraction, or multiplication will not be more than $2k$-bits long. So we can perform exponentiation in modular arithmetic without generating huge numbers. Calculating the power of some modulo some number,

```
$a^b \mod n$
```

is just series of multiplications and division, but there are speeds. One kind of speedup aims to minimize the number of modular multiplications, another kind aims to optimize the individual modular multiplications. Because the operations are distributive, it is faster to do as a stream of successive multiplications, taking the modulus every time. It doesn't make much difference now, but it will you're working with 200-bit numbers.

For example, if you want to calculate $a^b \mod n$, don't use the naïve approach and perform seven multiplications and one huge reduction:

```
$a\cdot a\cdot a\cdot a\cdot a\cdot a \mod n$
```

Instead, perform three multiplications and three smaller modular reductions:

```
$((a \mod n)^2 \mod n)^2 \mod n$
```

By the same taken,

```
$a^{16} \mod n = (((a^2 \mod n)^2 \mod n)^2 \mod n$
```
