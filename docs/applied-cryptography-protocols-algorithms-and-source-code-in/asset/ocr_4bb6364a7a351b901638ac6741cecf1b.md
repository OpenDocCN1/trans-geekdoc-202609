# 19.9 LUC

Some cryptographers have developed generalizations of RSA that use various polynomials instead of exponentiation. A variation Kravitz-Reed, using irreducible binary polynomials [898], is insecure [451,589]. Winfried Müller and Wilfried Nöbauer Dickson polynomials [1127,1128,965]. Rudolf Lidl and Müller generalized this approach in [966,1126 (a variant called the Révi scheme), and Nöbauer used it at [969,967,968,599]. Despite on prime generation with Lucas functions and all of this prior art, a group of researchers from New Zealand managed to patent this scheme in 1993, calling it LUC [1486,521,1487].

The nth Lucas number, $V_n(P)$, is defined as

```
$V_n(P) = pV_{n-1}(P) - V_{n-2}(P)$
```

There's a lot more to Lucas: numbers I'm ignoring all of it. A good theoretical treatment of Lucas sequences is in [1307,1308]. A particularly nice description of the mathematics of LUC is in [1494,7708].

In any case, to generate a public-key/private-key pair, first choose two large primes, $p$ and $q$. Calculate $n$, the product of $p$ and $q$. The encryption key $e$, is a random number that is relatively prime to $p-1, q-1, p+1$, and $q+1$.
There are four possible cryptosystems:

```
$d = e^{-1} \pmod{	ext{lcm}(p+1, q+1))}$
$d = e^{-1} \pmod{	ext{lcm}(p+1, q-1)}$
$d = e^{-1} \pmod{	ext{lcm}(p-1, q+1)}$
$d = e^{-1} \pmod{	ext{lcm}(p-1, q-1)}$
```

where lcm is the common multiple.

The public key is $d$ and $n$; the private key is $e$ and $n$. Discard $p$ and $q$.
To encrypt a message, $P$ [$P$ must be less than $n$], calculate

```
$C = V_e(P,1) \pmod n$
```

And to decrypt:
$P = V_d(C,1) \pmod n$, with the proper $d$

At least, LUC is no more secure than RSA. And recent, still-unpublished works show how to break LUC in at least some implementations. I just don't trust it.
