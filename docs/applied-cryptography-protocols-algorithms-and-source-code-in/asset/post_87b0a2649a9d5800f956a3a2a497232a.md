
## 14.5 3-Way

Decryption is the reverse process: the output transformation (with subtraction instead of addition), then reverse rounds. The Inverse PHT (IPHT) is:

```
$a_1 = (b_1 - b_2) \pmod{256}$
$a_2 = (-b_1 + 2b_2) \pmod{256}$
```

Massey recommends 6 rounds, but you can increase that if you want greater security. Generating subkeys is easy. The first subkey, $K_0$, is simply the user key. Subsequent subkeys are generated by the following procedure:

```
$K_i = (K_0 \lll 3i) + C_i$
```

The symbol "<<" is a left circular shift or a right rotation. The rotation is byte by byte, and $c_i$ is a round constant. If $C_0$ is the $j$th round of the $i$th round constant, then you can calculate all of the round constants by the formula

```
$C_{ij} = 45^{5^i(9+j) \pmod{256}} \pmod{256}$
```

Generally, these values are stored in a table.

## SAFER K-128

This alternate key schedule was developed by the Ministry of Home Affairs in Singapore, and then incorporated into SAFER by Massey [1010]. It uses two keys, $K_v$ and $K_b$, each 64-bit long. The trick is to generate two subkeys in parallel, and then alternate subkeys from each sequence. This means that if you choose $K_u = K_b$, then the 128-bit key is compatible with the 64-bit key $K_v$.

## Security of SAFER K-64

Massey showed that SAFER K-64 is immune to differential cryptanalysis against the attack after 8 rounds and adequately secure after 6 rounds. After only 3 rounds linear cryptanalysis is ineffective against this algorithm [1010].

Knudsen found a weakness in the key schedule: For virtually every key, there exists at least one (and as many as nine) other key that encrypts one plaintext to identical ciphertexts [862]. The number of plaintexts to encrypt identical ciphertexts after 6 rounds is anywhere from $2^{22}$ to $2^{28}$. While this attack may not impact SAFER’s security when used as an encryption-way hash function. In any case, Knudsen recommends at least 8 rounds.

SAFER was designed for Cylink, and Cylink was tested by the NSA [80]. I recommend years of intense cryptanalysis before using SAFER in any form.

## 14.5 3-Way

3-Way is a block cipher designed by Joan Daemen [402,410]. It has a 96-bit block length and key length, and is designed to be very efficient in hardware.

3-Way is not a Feistel network, but it is an iterated block cipher. 3-Way can have n rounds, Daemen recommends 11.

## Description of 3-Way

The algorithm is simple to describe. To encrypt a plaintext block, x:

```
For i = 0 to n - 1
x = x XOR K_i
x = theta[x]
x = pi - 1 [x]
x = gamma[x]
x = pi - 2 [x]
x = x ⊕ K_n
x = theta[x]
```

The functions are:

- theta[x] is a linear substitution function—basically a bunch of circuifts and XORs.
- pi-1(x) and pi-2(x) are simple permutations.
- gamma[x] is a nonlinear substitution function. This is the step that gives 3-Way its name; it is the parallel execution of the substitution on 3-bit blocks of the input.

Decryption is similar to encryption, except that the bits of the bits of the input have to be reversed and the bits of the output have been reversed. To implement 3-Way can be found in the back of this book. 

So far, there has been no successful cryptanalysis of 3-Way. The algorithm is unpatented.

## 14.6 CRAB

This algorithm was developed by Burt Kaliski and Matt Robshaw of RSA Laboratories [810]. The idea behind Crab is to use techniques from one-way hash functions to make a fast encryption algorithm. Crab is very similar to MD5, and this section assumes you are familiar with Section 18.5.

Crab has a very large block: 1024 bytes. Since Crab is presented as more a research contribution than a real algorithm, no definitive key-generation routines are pre-presented. The authors suggest a method that could turn an 80-bit key into three requisite subkeys, although the algorithm could easily accept variable-length keys. Crab uses two sets of large subkeys:

- A permutation of the numbers 0 through 255: P₀, P₁, P₂, ..., P₂₅₅
- A 2048-entry array of 32-bit numbers: S₀, S₁, S₂, ..., S₂₀₄�.

## 14.6 Crab

These subkeys must all be calculated before encryption or decryption. To encrypt a 1024-block X:

- (1) Divide X into 256 32-bit sub-blocks: $X_0, X_1, X_2, \dots, X_{255}$.
- (2) Permute the sub-blocks of X according to $P$.
- (3) For $r=0$ to $3r$:
  - $g=0$ to $2r$:
    - $A = X_{(4g)} \lll 2r$
    - $B = X_{(4g+1)} \lll 2r$
    - $C = X_{(4g+2)} \lll 2r$
    - $D = X_{(4g+3)} \lll 2r$
    - $s=0$ to $7$:
    - $A = A \oplus f_i[B,C,D] + S_{5r} + 8g + s$
    - $TEMP = D$
    - $C = B$
    - $B = A \lll 5$
    - $A = TEMP$
    - $X_{(4g)} \lll 2r = A$
    - $X_{(4g+1)} \lll 2r = B$
    - $X_{(4g+2)} \lll 2r = C$
    - $X_{(4g+3)} \lll 2r = D$
- (4) Recombine $X_0, X_1, X_2, \dots, X_{255}$ to form the ciphertext.

The functions $f_i[B,C,D]$ are similar to those used in MD5:
$f_0[B,C,D] = (B \wedge C) \lor (B \wedge D)$
$f_1[B,C,D] = (B \wedge D) \lor (C \wedge D)$
$f_2[B,C,D] = B \oplus C \oplus D$
$f_3[B,C,D] = C \oplus (B \wedge D)$

Decryption is the reverse process. Generating the subkeys is a large task. Here is the permutation array, $P$, could generated from an 80-bit key, $K$.

- (1) Initialize $K_0, K_1, K_2, \dots, K_9$ with 10 bytes of $K$.
- (2) For $i=10$ to $255$: $K_i = K_{i-2} \oplus K_{i-6} \oplus K_{i-7} \oplus K_{i-10}$
- (3) For $i=0$ to $255$, $P_i = i$
- (4) $m = 0$
- (5) For $j = 0$ to $1$:
  - For $i = 256$ to step-1:
    - $m = (K_{256-i} + K_{257-j}) \pmod i$
    - $K_{357-i} = K_{257-j} \lll 3$
    - Swap $P_i$ and $P_{i-1}$

The S-array of 2048 32-bit words could be generated in a similar manner, either from the same 80-bit key or another key. The authors claim that these details should "viewed as motivational, there may well be alternative schemes which are both more efficient and offer improved security" [810].

Crab proposed as a test of new ideas and not as a working algorithm. It uses many of the same techniques as MD5. Biham argued that a very large block size makes an algorithm easier to cryptanalyze [160]. Crab might make efficient use of a very large key. In such a case, "easier to cryptanalyze" might not mean much.

## 14.7 SXAL8/MBAL

This is a 64-bit block algorithm from Japan [769]. SXAL8 is the basic algorithm, MBAL is an expanded version with a block length. Since MBAL does some clever things, the authors claim that they can get adequate security with only a few rounds. With a block length of 1024 bytes, MBAL is about 70 times faster than DES. Unfortunately, [1174] shows that MBAL is susceptible to differential cryptanalysis, and [865] shows that it is susceptible to linear analysis.

## 14.8 RC5

RC5 is a block cipher with a variety of parameters: block size, key size, and number of rounds. It was invented by Ron Rivest and analyzed by RSA Laboratories [1324.1325]. There are three operations: XOR, addition, and rotations. Rotations are constantime on processors and variable rotations are a nonlinear function. These rotations, which depend on both the key and the data, are the interesting operation.

RC5 has a variable-length block, but this example will focus on a 64-bit data block. Encryption uses $2r+2$ key-dependent 32-bit words—$S_0, S_1, S_2, \dots, S_{2r+1}$—where $r$ is the number of rounds later. To encrypt, first the plaintext block into two 32-bit words: $A$ and $B$. (RC5 assumes a little-endian convention for packing bytes into register $A$, etc.) Then:

```
$A = A + S_0$
$B = B + S_1$
```

For $i = 1$ to $r$:

```
$A = (A \oplus B) \lll S_{2i}$
$B = (A \oplus B) \lll S_{2i+1}$
```

Decryption is the reverse process. The output is in registers A and B. To decrypt, just as easy: Divide the ciphertext block into two 32-bit words: $A$ and $B$, then:

For $i = r$ down to 1:

```
$B = (A \oplus B) \ggg S_{2i+1}$
$A = (A \oplus B) \ggg S_{2i}$
```

$A = A - S_0$
$B = B - S_1$

The symbol ">>>" is a right shift. Of course, all addition and subtraction are mod $2^{32}$. Creating the array is more complicated, but also straightforward. First, copy the bytes of the key into array L, padding the final word with zeros if necessary. Then, initialize array S, using a linear congruential generator mod $2^{32}$:

```
$S_0 = P
for $i = 1$ to $2(r+1)-1$:
S_i = (S_{i-1} + Q) \pmod{2^{32}}$
```

Finally, mix L into S:

```
i = 0
A = 0
doo $3n$ times (where $n$ is the maximum of $2(r+1)$ and $c$):
$S_i = (S_i + A + B) \lll B$

i = (i+1) \pmod{2(r+1)}$

```

RC5 is actually a family of algorithms. There is no reason why the same algorithm can't have a 32-bit word size and 64-bit block size or 64-bit/128-bit block size. For $w=64$, $P$ and $Q$ are $0x7e15161328ae2a6b$ and $0x9c3779b77a47c15$, respectively. Rivest designates particular implementations of RC5 as RC5-$w/b$, where $w$ is the word size, $r$ is the number of rounds, and $b$ is the length of the key in bits.
