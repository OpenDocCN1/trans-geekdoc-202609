The major problem with these cryptystems is that nothing can be proven about their security; the design criteria have never been proved to be either necessary or for security. A keystream generator may satisfy all the design principles, but could still turn out to be insecure. Another could turn out to be secure: There is still some magic to the process.

On the other hand, each of these keystream generators is a different problem for a cryptanalyst. If enough different generators are out there, it may not be the cryptanalyst's time to break each one. He may better achieve fame and glory by figuring out better ways to factor large numbers or calculating logarithms.

## 17.9 COMPLEXITY-THEORETIC APPROACH TO STREAM-CIPHER DESIGN

Rueppel delineated a complexity-theoretic approach to stream-cipher design. Here, a cryptographer attempts to use complexity theory to prove that his generators are secure. Consequently, the generators tend to be more complicated, based on the same sorts of hard problems as public-key cryptography. And like public-key algorithms, they tend to be bulky and cumbersome.

## Shamir's Pseudo-Random-Number Generator

Adi Shamir used the RSA algorithm as a pseudo-random-number generator [1417]. While Shamir showed that predicting the output of the pseudo-random-number generator is equivalent to breaking RSA, potential biases in the output were demonstrated in [1401, 200].

## Blum-Micali Generator

This generator gets its security from the difficulty of computing discrete logarithms [200]. Let $g$ be a prime and $p$ be an odd prime. A key $x_0$ starts the process:

```
x_{i+1} = g^{x_i} \pmod p
```

The output of the generator is 1 if $x_i < (p-1)/2$, and 0 otherwise.

$p$ is large enough so that computing discrete logarithms mod $p$ is infeasible, this generator is secure. Additional theoretical results can be found in [1627, 968, 985, 1237, 896, 799].

## RSA

This RSA generator [35,36] is a modification of [200]. The initial parameters of true modulus $N$ which is two large primes $p$ and $q$, an integer $e$ which is relatively prime to $(p-1)(q-1)$, and a random seed $x_0$ where $x_0$ is less than $N$.

```
x_i = x_0^e \pmod N
```

The output of the generator is the least significant bit of $x_i$. The security of this generator is based on the difficulty of breaking RSA. If $N$ is large enough, then the generator is secure. Additional theory can be found in [1569.1570, 1571, 30, 354].

## Blum, Blum, and Shub

The simplest and most efficient complexity-theoretic generator is called the Blum, Blum, and Shub generator, after its inventors. Mercifully, we abbreviate to BBS, although it is sometimes called the quadratic residue generator [193]. The theory behind the BBS generator is to do with quadratic residues modulo $n$ [see Section 11.3]. Here's how it works.

First two prime numbers, $p$ and $q$, which are congruent to 3 modulo 4. The product of these numbers, $n$, is a Blum integer. Another random integer, $x$, which is relatively prime to $n$. Compute

```
x_0 = x^2 \pmod n
```

That's the seed for the generator. Now you can start computing. The $i$th pseudo-random bit is the least significant bit of $x_i$,

```
x_i = x_{i-1}^2 \pmod n
```

The most intriguing property of this generator is that you don't have to iterate through $i-1$ bits to get the $i$th bit. If you know $p$ and $q$, you can compute the $i$th bit directly.

```
b_i = x_0^{(2^{i-1})/\phi(n)} \pmod n
```

This property means you can use this cryptographically strong pseudo-random generator as a cryptsystem for random-access file. The security of this scheme is based on the difficulty of factoring $n$. You can make $n$ public, so anyone can generate bits using the generator. However, unless a cryptanalyst factors $n$, he can never predict the output of the generator—not even with a statement: "The next bit has a 51 percent chance of being a 1."

More strongly, the BBS generator is unpredictable to the left and unpredictable to the right. This means that any given sequence generated by the generator, a cryptanalyst cannot predict the next bit or the previous bit.

## 17.10 Other Approaches to Stream-Cipher Design

In an information-theoretic approach to stream ciphers, the cryptanalyst has unlimited time and computing power. The only practical stream cipher that is secure against an adversary is the one-time pad [see Section 1.5]. Since bits are impractical, this is sometimes called a *one-time tape*. Two tapes, one for encryption and the other at the decryption end, would have the same keystream on them. To simplify, XOR the plaintext with the bits on the other. You never use the same keystream twice. Since the keystream is truly random, no one can predict it.

Another information-theoretic stream cipher, developed by Klaus Schnorr, assumes that the cryptanalyst has only access to a limited number of ciphertext bits [1395]. The results are theoretically have no practical value, at least not yet. For more details, consult [1361.043,1193].

In a randomized stream cipher, the cryptographer tries to ensure that the crypt has an impossibly large problem to solve. The objective is to increase the number of bits the cryptanalyst has to work with, while keeping the secret key small. This can be done by making use of a large public random string for encryption and decryption. The key would specify which parts of the large random string are to be used for encryption and decryption. The cryptanalyst, knowing the key, is forced to pursue a brute-force search through the random string. The security of such cipher can be improved by the average number of bits a cryptanalyst must examine before guessing.

## Rip von Winkle Cipher

James Massey and Inemar Ingmarsson proposed the Rip von Winkle cipher [1011], named because the receiver has 2ⁿ bits of ciphertext before attempting decryption. The algorithm, illustrated in Figure 17.10, is simple to implement, properly secure, and completely impractical. Simply XOR the plaintext with the keystream, and delay the keystream by 0 to 20 years—the exact delay is part of the key. In Massey’s words “One can easily guarantee that the enemy cryptanalyst will need thousands of years to break the cipher, if one is willing to wait millions of years to read the plaintext.” Further work on this idea can be found in [1577.755].
