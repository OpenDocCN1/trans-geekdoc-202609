
## 18.11 Symmetric Block Algorithms

The most obvious method is to encrypt the message with the algorithm in CBC or CFB mode, a fixed key, and IV; the last ciphertext block is the hash value. These methods are described in various standards using DES; both modes in [1143]. CFB in [1145]. CBC in [55,66,54]. This is not enough for one-way hash functions, although it will work for a MAC [see Section 18.14] [29].

A clever approach is to use the block as the key, and the current hash value as the output.

The actual hash functions are even more complex. The block size is usually the key length, and the size of the hash value is the block size. Since most algorithms are 64 bits, several schemes are designed around a hash that is twice the block size.

Assuming the hash function is correct, the security of the scheme is based on the security of the underlying block function. There are exceptions, though. Differential cryptanalysis is easier against block functions in hash functions than against block functions used for encryption: The key is known, so only one pair is needed for security and you can generate as much plaintext as you want. Some work on these lines in [126,858,1313].

What follows is a summary of the various hash functions that have appeared in the literature [92,1465,1262]. Statements about attacks against these schemes that assume the underlying block cipher is secure are, the best attack against them is brute force.

One measure for hash functions based on block functions is the hash rate, or the number of n-bit message blocks, where n is the block size of the algorithm, processed per encryption. The higher the rate, the faster the algorithm. [This measure was given the opposite definition in [1262], but the definition given here is more intuitive and is widely used.]

## Schemes Where the Hash Length Equals the Block Size

The general scheme is as follows (see Figure 18.8):

```
$H_0 = I_H$, where $I_H$ is a random initial value
nH_i = E_A(H_{i-1}) \oplus C
```

where $A, B$, and $C$ can be either $M_i, H_{i-1}, (M_i \oplus H_{i-1})$, or a constant (assumed to be 0). $H_0$ is some random initial value: $I_H$. The message is divided up into block-size chunks, $M_i$ and processed individually. And there is some kind of MD-strengthening, perhaps the same padding procedure used in MD5 and SHA.

Fifteen are trivially weak the result does not depend on one of the inputs. Thirty-seven are secure for more subtle relations. Table 18.1 lists the 12 secure schemes remaining: The first 4 are secure against all attacks (see Figure 18.9) and the last 8 are secure against all but a fixed-point attack, which is not really worth worrying about.

The first scheme was described in [1028]. The third scheme was described in [1555,1105,1106] and proposed as an ISO standard [766]. The fifth scheme was proposed by Carl Meyer, which is commonly called Davies-Meyer in the literature [1606,1607,434,1028]. The tenth scheme was proposed as a hash-function for OKI [273].

The first, second, third, fourth, ninth, and eleventh schemes have a hash rate of l; key equals the block length. The others have a rate of k/n, where k is key length. This means that if the key is shorter than the block length, the message block can only be the length of key. It is not recommended that the message be longer than the key, even if the encryption algorithm's key length is longer than the block length.

If the block algorithm has a DES-like property and weak keys, there is an additional attack that is possible against all these schemes. The attack isn't very dangerous and not really worth about. However, you can solve it by fixing bits 2 and 3 of the key to "01" or "10" [108,1107]. Of course, this reduces the length of k from 56 bits to 54 bits (in DES, for example) and decreases hash rate. The following schemes, proposed in the literature, have been shown to be insecure.

### Davies-Meyer

Lai and Massey modified the Davies-Meyer technique to work with IDEA [93,125]. IDEA is a 64-bit block size and 128-bit key size. Their scheme is
$H_0 = I_0$, where $I_0$ is a random initial value
$H_i = E_{H_{i-1}}[M] \oplus H_{i-1}$

This function hashes the message in blocks of 64 bits and produces a 64-bit value (see Figure 18.10). No known attack on this scheme is easier than brute force.

### Preneel-Bosters-Govaerts

This hash function, first proposed in [266], produces a hash value twice the block length of the encryption algorithm: a 64-bit algorithm produces a 128-bit hash. With a 64-bit block algorithm, the scheme produces two 64-bit hash values, $G_i$ and $H_i$, which are concatenated to produce a 128-bit hash. Two adjacent message blocks, $L_i$ and $R_i$, each the size of the block is 64 bits, are hashed together.

```
$G_0 = I_0$, where $I_0$ is a random initial value
$H_0 = I_H$, where $I_H$ is another random initial value
$G_i = E_{L_i}(H_{i-1}) \oplus R_i \oplus G_{i-1} \oplus H_{i-1}$
$H_i = E_{R_i}(H_{i-1}) \oplus L_i \oplus G_{i-1} \oplus H_{i-1}$
```

Lai demonstrates attacks against this scheme. In some instances, the birthday attack is trivially solvable [925,926]. Preneel [262] and Coppersmith [372] also have successful attacks against this scheme. Do not use it.

### Quisquater-Girault

This scheme, first proposed in [279], generates a hash that is the block length and has a hash of 1. It has two hash values, $G_i$ and $H_i$, and two blocks, $L_i$ and $R_i$, which are hashed together.

```
$G_0 = I_0$, where $I_0$ is a random initial value
$H_0 = I_H$, where $I_H$ is another random initial value
$W_i = E_{L_i}(G_{i-1}) \oplus R_i \oplus H_{i-1}$
$G_i = E_{R_i}(W_{i-1}) \oplus G_{i-1} \oplus H_{i-1} \oplus L_i$
$H_i = W_i \oplus G_{i-1}$
```

This scheme appeared in the 1989 draft standard [764], but was dropped in a later version [765]. Security problems with this scheme were identified in [1107, 925, 262, 373]. [Actually, the version in the proceedings were strengthened after the version presented at the conference was attacked.] In some instances the birthday attack is solvable with a complexity of $2^{64}$, through brute force. Do not use this scheme.

## 18.11 Symmetric Block Algorithms

### LOKI Double-Block

This algorithm is a modification of Quisquater-Girault, specifically designed to work with LOKI [273]. All parameters are as in Quisquater-Girault.

```
$G_0 = I_0$, where $I_G$ is a random initial value
$H_0 = I_H$, where $I_H$ is another random initial value
$W_i = E_B \oplus G_{i-1}, [G_{i-1} \oplus R_i] \oplus H_{i-1}$
$G_i = E_B \oplus H_i, [W_i \oplus L_i] \oplus H_{i-1}$
$H_i = W_i \oplus G_{i-1}$
```

Again, in some instances the birthday attack is trivially solvable [925,926,262,372]. Do not use this scheme.

### Parallel Davies-Meyer

This is another attempt at an algorithm with a hash rate twice the block length [736].

```
$G_0 = I_G$, where $I_G$ is a random initial value
$H_0 = I_H$, where $I_H$ is another random initial value
$G_i = E_B \oplus [G_{i-1} \oplus L_i] \oplus H_{i-1}$
$H_i = E_L[H_{i-1} \oplus R_i] \oplus R \oplus H_{i-1}$
```

Unfortunately, this scheme isn't secure [928,861]. As it turns out, a double-length hash function with a hash rate of 1 cannot be more secure than Davies-Meyer [861].

### Tandem and Davies-Meyer

Another way around the inherent limitations of a block cipher with a 64-bit key uses an algorithm, like IDEA (see Section 13.9), with a 64-bit block and a 128-bit key. These schemes produce a 128-bit hash value and have a hash rate of 1 [930,925].
