If you can put your algorithm in a tamperproof module, here's what you can do. You can require keys of a special and secret form; all other keys will allow the module to encrypt and decrypt a severely weakened algorithm. You can make it so that the odds of someone, knowing this special form but accidentally stumbling on a correct key, are vanishingly small.

This is called a nonlinear keys, because all the keys are not equally strong. The opposite is a linear, or itac, keys.) An easy way to create the key as two parts: the key and some fixed string encrypted with that key. The module decrypts the string with the key, if it gets the string it uses the key normal, if not it uses a default, weak algorithm. If the algorithm has a 128-bit key and a 64-bit block size, the overall key is 192 bits; this gives an effective key of $2^{128}$, but makes the odds of randomly choosing a good one in $2^{64}$.

You can be even subtler. You can design an algorithm such that certain keys are stronger than others. An algorithm can have no weak keys—keys that are obviously very poor—and still have a nonlinear keyspace.

This only works if the algorithm is secret and the enemy can't reverse-engineer it, or if the difference in key strength is subtle enough that the enemy can't figure out. The NSA did this with the secret algorithms in their Overtake modules (see Section 25.1). Did they do the same with Skipjack [see Section 13.12]? No one knows.

# 8.3 TRANSFERRING KEYS

Alice and Bob are going to use a symmetric cryptographic algorithm to communicate securely; they need the same key. Alice generates a key using a random-key generator. Now she has to give it to Bob—securely. If Alice can meet somewhere (a back alley, a windowless room, or one of Jupiter's moons), she can give him a copy of the key. Otherwise they have a problem. Pre-key cryptography techniques are not available (see Section 3.1). Some systems use alternate channels to be secure. Alice could send Bob the key with a trusted messenger. She could send mail or via overnight delivery service. She could set up another communications channel with Bob and no eavesdropping on that.

Alice could send Bob the symmetric key over their communications channel—the one they are going to encrypt. This is foolish; if the channel warrants encryption, sending the encryption key in the clear over the same channel guarantees that anyone can decrypt all communications.

The X.19 standard [55] specifies two types of keys: key-encryption and data keys. Key-Encryption keys encrypt other keys for distribution. Data keys encrypt message traffic. These key-encrypting keys have to be distributed manually (although they can be secured in a tamperproof device, like a smart card), but only seldom. Data keys are distributed frequently. More details are in [75]. This two-tiered concept is used a lot in key distribution.
