# Designing a Block Cipher

It is easy to design a block cipher. If you think of a 64-bit block cipher as a permutation of the 64-numbers, it is clear that all of those permutations are secure. What is difficult to design a block cipher that is not only secure, but can also be easily described and simply implemented.

It's easy to design a block cipher if you have sufficient memory for 48*32 S-boxes. It's hard to design an insecure DES when you iterate it for 128 rounds. If the length of your key is 512 bits, you don't care if there are key-complementation properties.

The real trick—and the reason that real-world block cipher design is very difficult—is to design a block cipher with the smallest possible key, the smallest memory requirement, and the fastest possible running time.

# 14.11 USING ONE-WAY HASH FUNCTIONS

The simplest to encrypt with a one-way function is to hash the previous text block concatenated with the key, then XOR the result with the current plaintext block:

```
$C_i = P_i \oplus H(K_i, C_{i-1})$
$P_i = C_i \oplus H(K_i, C_{i-1})$
```

Set the block length equal to the output of the one-way hash function. This, in effect uses the one-way function as a block cipher in CFB mode. A similar construction can use the one-way function in OFB mode:

```
$C_i = P_i \oplus S_i = H(K_i, C_{i-1})$
$P_i = C_i \oplus S_i = H(K_i, C_{i-1})$
```

The security of this scheme depends on the security of the one-way function.
