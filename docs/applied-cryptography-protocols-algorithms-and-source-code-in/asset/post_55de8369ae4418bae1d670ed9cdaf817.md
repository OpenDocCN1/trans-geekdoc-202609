There is a method to use 48 additional key bits to generate S-boxes that are resistant to both linear and differential cryptanalysis:

(1) Rearrange the DES S-boxes: $2^{463158}$.
(2) Select 16 of the remaining key bits. If the first bit is 1, swap the first two rows of S-box 1 with the last two rows of S-box 1. If the second bit is 1, swap the first eight columns of S-box 1 with the second eight columns of S-box 2. Do the same to S-box 2 with the third and fourth key bits. Do the same with S-boxes 3 through 8.
(3) Take the remaining 32 key bits. XOR the first four with every entry of S-box 1, the next four with every entry of S-box 2, and so on.

The complexity of a differential cryptanalysis attack against this system is $2^{51}$, the complexity of a linear cryptanalysis attack is $2^{47}$. What is neat about this DES variant is that it can be implemented in existing hardware. Several DES vendors sell DES chips with loadable S-boxes. The S-box generation method can be done outside the chip and loaded in. Differential and linear cryptanalysis require so much known plaintext as to be unusable, and a brute-force attack is inconceivable—with no penalties.

## 12.7 How Secure DES TODAY?

The answer is both easy and hard. The easy answer just looks at key length [see Section 7.1]. A brute-force DES-cracking machine can find a key in an average of 3.5 hours costing only $1 million in 1993 [1597]. DES is so widespread that it is naive to pretend that the NSA and its counterparts haven't built such a machine. And remember, that cost will drop by a factor of 2 every 10 years. DES will only become less secure as time goes.

The hard answer tries to estimate cryptanalytic techniques. Differential cryptanalysis was known by the NSA before the mid-1970s, DES before it became a standard. It is naive to pretend that the NSA theorists have been idle since then; they have developed newer cryptanalytic techniques that can be applied against DES. But there are no facts, only rumors.

Winn Schwartz says that the NSA had a massively parallel DES-cracking machine as early as the mid-1980s [1404]. At least one such machine was built by Harris Corp, with a Cray Y-MP as a front end. Supposedly there are a series of algorithms that could reduce the complexity of a DES brute-force search by several orders of magnitude. Context algorithms based on the inner workings of DES, can scrap sets of possible keys based on partial solutions. Statistical algorithms reduce the effective key size by likely keys—words, printable ASCII, and so on (see Section 8.1)—to test. The rumor is that the NSA can crack DES in 3 to 15 minutes, depending on how much processing they can do. And these machines cost only $50,000 each, in quantity.

A different rumor is that if the NSA has a large amount of plaintext and cipher-text, its experts can perform some kind of statistical calculation and then go out to an array of optical disks and retrieve the key.

These are just rumors, but they don't give me a warm, fuzzy feeling about DES. It has just been too big a target for too long. Almost any change to DES will be more annoying; maybe the resultant cipher will be easier to break, but the NSA might not have the resources to devote to the problem.

My recommendation is to use Biham's construction for key-dependent loadable S-boxes. It is easy to implement in software and has no performance penalty over DES.

# CHAPTER 13 Other Block Ciphers

## 13.1 LUCIFER

In the late 1960s, by Horst Feistel and later by Walter Tuckman, IBM initiated a research program in computer cryptography called Lucifer. Lucifer is also the name of a block algorithm that came out of that program in the early 1970s [1482]. In fact, there are at least two different algorithms with that name [552,1492] and [552] leaves some gaps in the specification of the algorithm.

Lucifer is a substitution-permutation network, with building blocks similar to DES. In DES, the output of the function is XORed with the input of the previous round to form the input of the next round. Lucifer's S-boxes are 4-bit inputs and 4-outputs; the input of the S-boxes is the bit-permuted output of the S-boxes of the previous round; the input of the S-boxes of the first round is the permutation. A key is used to choose the actual S-box from two possible S-boxes. Unlike DES, there is no swapping between rounds and no block halves are used. Lucifer has 16 rounds, 128-bit blocks, and a key schedule simpler than DES.
