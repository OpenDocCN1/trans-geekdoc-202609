# 24.8 IBM Common CRYPTOGRAPHIC ARCHITECTURE

The Common Cryptographic Architecture (CCA) was designed and developed by IBM to provide cryptographic primitives for confidentiality, integrity, key management, and personal identification number (PIN) [751,784,1025,940,752]. Keys are managed by control vectors (CVs) [see Section 8.5]. Every key has a CV Xored and it is never separated from the vector inside secure hardware. The CCA is a data structure providing an intuitive understanding of the privileges associated with a particular key.

The individual bits of the CV have specific meanings for using and handling each key by CCA. The CV is carried with the encrypted key in data structures called tokens. Internal keys are used locally and contain keys encrypted under the master key (MK). External keys are used to export and import encrypted keys between systems. Keys in external tokens are encrypted under key-encrypting keys (KEK). The KEKs are managed in internal key tokens. Keys are separated by their permitted uses.

Key length is specified and enforced using bits in the CCA. Single length keys are 56 bits and are used for functions as privacy and message authentication. Double length keys are 112 bits and are used for key management. PIN functions, and other special uses. Keys can be required to be DOUBLE-ONLY in which both the left and right halves of the key must be different, DOUBLE in which the halves are permitted to be equal, SINGLE-REPEATED in which the left and right halves are equal, or SINGLE which contains only 56 bits. The CCA functions specify hardware enforcement of certain key types to be used for some operations.

CCA uses a combination of public-key cryptography and secret-key cryptography for key distribution. The KDC shares a secret master key with each user and encryption session keys using that master key. Master keys are distributed using public-key cryptography.

The system's designers chose this hybrid approach for two reasons. The first is performance. Public-key cryptography is computationally intensive; if session keys are distributed using public-key cryptography, the system might bog down. The second is compatibility compatibility; system can be overlaid on existing secret-key schemes with minimal disruption.

CCA systems are designed to be interoperable. For systems that are non-CCA compliant, a Control Vector Translate (CVXLT) permits keys to be passed between the two implementations.
