The main loop of the algorithm then begins. It processes the message 512 bits at a time and continues for as many 512-bit blocks as are in the message.

The first five variables are copied into different variables: a gets A, b gets B, c gets C, d gets D, and e gets E.

The main loop has four rounds of 20 operations each [MD5 has four rounds of 16 operations each]. Each operation performs a nonlinear function on three of a, b, c, d, and e, and then does shifting and adding similar to MD5.

SHA's set of nonlinear functions:

```
f_0(X,Y,Z) = (X ∧ Y) ∨ (¬ X ∧ Z), for t = 0 to 19.
f_1(X,Y,Z) = X ⊕ Y ⊕ Z, for t = 20 to 39.
f_2(X,Y,Z) = (X ∧ Y) ∨ (X ∧ Z) ∨ (Y ∧ Z), for t = 40 to 59.
f_3(X,Y,Z) = X ⊕ Y ⊕ Z, for t = 60 to 79.
```

First constants are used in the algorithm:

- K_t = 0x5a827999, for t = 0 to 19.
- K_t = 0x66d9eba1, for t = 20 to 39.
- K_t = 0x8f1bbcde, for t = 40 to 59.
- K_t = 0xca62c1d6, for t = 60 to 79.

[If you wonder whose numbers came from: 0x5a827999 = 2^{1/2}, 0x66d9eba1 = 3^{1/2}, 0x8f1bbcde = 5^{1/2}, and 0xca62c1d6 = 10^{1/2}; all times 2^{32}].

The message block is transformed from 16 32-bit words (M_0 to M_{15}) to 80 32-bit words (W_0 to W_{79}) using the following algorithm:

```
W_t = M_t, for t = 0 to 15
W_t = W_{t-3} ⊕ W_{t-8} ⊕ W_{t-14} ⊕ W_{t-16} <<< 1, for t = 16 to 79.
```

> As an interesting aside, the original SHA specification did not have the left circular shift. The "change" corrects a technical flaw that made the standard less secure than had been thought" [543]. The NSA has refused to elaborate on the exact nature of the flaw.

If t is the operation number (from 0 to 79), W_t represents the t-th block of the expanded message, and <<< s represents a left circular shift of s bits, then the main loop looks like:

```
FOR t = 0 to 79
TEMP = {a <<< 5} ⊕ f_i(b,c,d) + e ⊕ W_t + K_t
e = d
d = c
c = b <<< 30
b = a
a = TEMP
```

# Security of SHA

SHA is very similar to MD4, which has a 160-bit hash value. The main changes are the addition of an expansion transformation and the addition of the previous step's output into the next step for a faster avalanche effect. Ron Rivest made public the design decisions for MD5, but SHA's designers did not. Here are Rivest's MD5 improvements to MD4 and how they compare with SHA's:

- 1. "A fourth round has been added." SHA does this too, however, in SHA the fourth round uses the same f function as the second round.
- 2. "Each step has a unique additive constant." SHA keeps the MD4 scheme where it reuses the constants for each group of 20 rounds.
- 3. "The function G in round 2 was changed from (X ∧ Z) ∨ (Y ∧ ¬Z) ∨ (X ∧ Y) to (X ∧ ¬Z) ∨ (Y ∧ Z) to make G more symmetric." SHA uses the MD4 version: ((X ∧ Y) ∨ (X ∧ Z) ∨ (Y ∧ Z)).

# 18.9 HAVAL

- “Each step now adds in the result of the previous step. This promotes a faster avalanche effect.” This change has been made in SHA as well. The difference in SHA is that a fifth variable is added, and not b, c, or d, which is already used in f_i. This subtle change makes the Boer-Bosselaers attack against MD5 impossible against SHA.
- “The order in which message sub-blocks are accessed in rounds 2 and 3 is changed, to make these patterns less alike.” SHA is completely different, since it uses a cyclic error-correcting code.
- “The left shift amounts in each round have approximately optimized, to yield a faster avalanche effect. The four shifts used in each round are different from the ones used in other rounds.” SHA uses a constant shift in each round.

This leads to SHA being MD4 with an expansion transformation, an extra round, and better avalanche effect. There are no known attacks against SHA-1 so far.

# 18.8 RIPE

RIPE-MD was developed by the European Community; it is a variation of MD4. The algorithm divides messages into 512-bit blocks; after each block, the result of the previous block is added to the current. The output is a 128-bit hash. The algorithm is susceptible to birthday attacks.

# 18.9 HAVAL

HAVAL is a one-way hash function based on cellular automata [1608]. It is designed for hardware and processes messages in 1024-bit blocks. It uses a variable number of rounds (three to five) and produces 128, 160, or 256 bits. Boef's and Bosselaers's attack on MD5 [203] did not apply to HAVAL because of the rotation.

# 18.10 One-Way Hash Functions

MD3 is yet another hash function designed by Rivest. It had several flaws and never made it out of the laboratory, although a description was recently published [1335].

A group of researchers at the University of Waterloo have proposed a one-way hash function based on iterated exponentiation in GF(2^99) [22]. In this scheme, a message is divided into 593-bit blocks; each exponent is the result of the computation with the previous block. The output is a one-way hash.

Clauss Schnorr proposed a one-way hash function based on the discrete Fourier transform, called FFT-Hash, in the summer of [1399]; it was broken a few months later by two independent groups [40,84]. Schnorr proposed a revised version, FFT-Hash II (the previous version was named FFT-Hash I [1400]), which was broken in a few weeks [1599]. Schnorr has proposed further modifications [1402,1403] but, as it stands, the algorithm is much slower than the others in this chapter.

Additional theoretical work on constructing one-way hash functions from one-way functions and one-way permutations can be found in [412,1138,1342].
