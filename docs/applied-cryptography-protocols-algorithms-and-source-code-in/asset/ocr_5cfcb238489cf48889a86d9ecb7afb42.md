# 19.2 Knapsack Algorithms

The idea behind the Merkle-Hellman knapsack algorithm is to encode a message
as a solution to a series of knapsack problems. A block of plaintext equal in length
the number of items in the pile would select the items in the knapsack (plaintext
bits corresponding to the $b$ values), and the ciphertext would be the resulting sum.
Figure 19.1 shows a plaintext encrypted with a sample knapsack problem.

The trick is that there are actually two different knapsack problems, one solvable
in linear time and the other believed not to be. The easy knapsack can be modified
to create the hard knapsack. The public key is the hard knapsack, which can easily
used to encrypt but cannot be used to decrypt messages. The private key is the
e knapsack, which gives an easy way to decrypt messages. People who do not
know the private key are forced to solve the hard knapsack problem.

# Superincreasing Knapsacks

What is the easy knapsack problem? If the weights of a superincreasing
sequence, the resulting knapsack problem is easy to solve. A superincreasing
sequence is a sequence in which every term is greater than the sum of all the premi-
s terms. For example, [1,3,6,13,27,52] is a superincreasing sequence, but [1,3,4,
15,25] is not.

The solution to a superincreasing knapsack is easy to find. Take the total weight
and compare it with the largest number in the sequence. If the total weight is less
than the number, then it is not in the knapsack. If the total weight is greater than
to the number, then it is in the knapsack. Reduce the weight of the knapsack
by the value and move to the next number in the sequence. Repeat until fin-
ished. If the total weight has been brought to zero, then there is a solution. If the
total weight has not there, there isn't.

For example, consider a knapsack weight of 70 and a sequence of weights of
[2,3,6,13,27,52]. The largest, 52, is less than 70, so 52 is in the knapsack. Sub-
tracted from 70 leaves 18. The next weight, 27, is greater than 18, so 27 is not in
the knapsack. The next weight, 13, is less than 18, so 13 is in the knapsack-
tracted from 18 leaves 5. The next weight, 6, is greater than 5, so 6 is not in the
knapsack. Continuing this process will show that both 2 and 3 are in the knapsack
and the total weight is brought to 0, which indicates that a solution has been found.
Were this Merkle-Hellman knapsack encryption block, the plaintext that resulted
from a ciphertext value of 70 would be 110101.
