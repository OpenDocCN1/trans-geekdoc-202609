# Bidirectional MAC

This MAC produces a hash twice the length of the block algorithm [978]. First, compute the CBC-MAC of the message. Then, compute the CBC-MAC of the message with the blocks in reverse order. The bidirectional MAC value is simply the concatenation of the two. Unfortunately, this construction is insecure [1097].

# Jueneman's Methods

This MAC is called a quadratic congruential manipulation detection code (QMCDC) [792,789]. First, divide the message into $m$-bit blocks. Then:

```
$H_0 = I_0$, where $I_0$ is the secret key
H_i = [H_{i-1} + M_i]^j \mod p, where $p$ is a prime less than $2^m - 1$
and $+$ denotes integer addition
```

Jueneman suggests $n = 16$ and $2^{31} - 1$. In [792] he also suggests that an additional key be used as $H_2$, with the actual message starting at $H_3$. Because of a variety of birthday-type attacks in conjunction with John Coppersmith, Jueneman suggested computing the QMCDC four times, using the result of one iteration as the IV for the next, and concatenating the results to obtain a 128-bit hash value [793]. This was further strengthened by doing the four iterations in parallel and cross-linking [790,791]. This scheme was broken by Coppersmith [376].

Another variant [432,434] replaced the addition operation with an XOR and used message blocks smaller than $p$. It also was also set, making it a keyless one-way hash function. After this scheme was attacked [612], it was strengthened as part of the European Open Shop Information-TeleTrust project [1221], quoted in CCIT X.509 [304], and adopted in ISO 10118 [764,765]. Unfortunately, Coppersmith has broken this scheme as well [376]. There has been some research using exponents other than 2[603], but none of it has promising.

# RIP-MAC

RIP-MAC was invented by Bart Prenel [1262] and adopted by the RIP project [1305] (is based on ISO 9797 [763]), and uses DES as a block encryption function. RIP-MAC has two flavors: one using normal DES, called

RIPE-MAC1, and another using a triple-DES for even greater security, called RIPE-MAC3. RIPE-MAC1 uses one DES for 64-bit message block; RIPE-MAC3 uses three.

The algorithm consists of three parts. First, the message is expanded to a length that is a multiple of 64 bits. Next, the expanded message is divided into 64-bit blocks. A keyed compression function is used to hash these blocks, under the control of a secret key, into a single block of 64 bits. This is the step that uses either DES or triple-DES. Finally, the output of this compression is subjected to another DES-based encryption with a different key, derived from the key used in the compression. See [1305] for details.

# IBC-Hash

IBC-Hash is another MAC adopted by the RIPE project [1305] [see Section 18.8]. It is interesting because it is provably secure; the chance of successful attack is quantified. Unfortunately, every message must be hashed with a different key. The chosen level of security puts constraints on the maximum message size that can be hashed—no other function in this chapter does this. Given these considerations, the RIPE report recommends IBC-Hash be used only for long, infrequently sent messages.

## Stream MAC

This MAC scheme uses ciphers (see Section 16.2). If the output bit generator $k_i$ is 1, then the current message $m_i$, is routed to the first subst; if it is 0, $m_i$ is routed to the second subst. The substreams are each fed into different LFSR.

Unfortunately, this method is not secure against small changes. # 19. BACKGROUND

The concept of public-key cryptography was invented by Whitfield Diffie and Martin Hellman, and independently by Ralph Merkle. Their contribution to cryptography was the notion that keys could come in pairs—an encryption key and a decryption key—and that it could be infeasible to generate one from the other (see Section 2.5). Diffie and Hellman presented this concept at the 1976 National Computer Conference [495]; a few months later, their seminal paper “New Directions in Cryptography” was published [496]. Due to a glacial publishing process, Merkle's first contribution to the field didn't appear until 1978 [1064].

Since 1996, numerous public-key algorithms have been proposed. Many of these are considered secure, many are impractical. Either they have too large a key or the ciphertext is much larger than the plaintext. Only a few algorithms are both secure and practical. These algorithms are generally based on one of the hard problems discussed in Section 11.2. Of these secure and practical public-key algorithms, some are only suitable for key distribution. Others are suitable for encryption (and by extension for key distribution). Others are only useful for digital signatures. Only three algorithms work for both encryption and digital signatures: RSA, ElGamal, and Rabin. All of these algorithms are secure. They encrypt and decrypt data much more slowly than symmetric algorithms; usually that's too slow to support back data encryption.

Hybrid cryptystems (see Section 2.5) speed things up: A symmetric algorithm with a random session key is used to encrypt the message, and a public-key algorithm is used to encrypt the session key.
