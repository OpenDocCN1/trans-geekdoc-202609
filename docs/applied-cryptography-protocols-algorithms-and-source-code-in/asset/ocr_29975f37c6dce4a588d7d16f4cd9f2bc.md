For a user to send messages, the system first establishes a secure communications path with the Public Key Distribution Center. The user requests a file of all public keys from the Center. If the user passes an identification test using his private key, the Center sends this list to the user's workstation. The list is encrypted using DES to ensure integrity.

The implementation uses DES to encrypt messages. The system generates a random key for file encryption; the user encrypts the file with the DES key and encrypts the DES key with the recipient's public key. Both the DES-encrypted file and the public-key-encrypted key are sent to the recipient

MEMO makes no provision for lost keys. There is some provision for integrity checking of the messages, using checksums. No authentication is built into the system.

The particular implementation used for this system—Diffie-Hellman key exchange over GF(2^{17})—was proven insecure before the system was implemented (see Section 11.6), although it is easy to modify the system to use larger numbers. MEMO was intended mainly for experimental purposes and was never operational on the real MILRETEN system.

# 24.3 ISDN

Bell-North Research developed a prototype Integrated Services Digital Network [ISDN] telephone terminal [499,1192,493,500]. As a telephone, it was never developed prototype. The resulting product was the Packet Data Security Overlay. The terminal uses Diffie-Hellman key exchange, RSA digital signatures, and data encryption; it can transmit and receive voice data at 64 kilobits per second.

# Keys

A long-term public-key/private-key pair is embedded in the phone. The private key is stored in a tamper-resistant area of the phone. The public key serves as the identification of the phone. These keys are part of the phone itself and cannot be altered in any way.

Additionally, two other public keys are stored in the phone. One of these keys is the owner's public key. This key is used to authenticate commands from the owner and can be changed by a command signed by the owner. In this way an owner can transfer ownership to someone else.

The public key of the network is also stored in the phone. This key is used to authenticate commands from the network's key management facility and authenticate from other users on the network. This key can also be changed via a signed command from the owner. This permits the owner to move his phone from one network to another.
