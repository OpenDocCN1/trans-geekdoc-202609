As far as we know, these algorithms have ideal security for a 128-bit hash function: Finding a message that hashes to a given value requires $2^{128}$ attempts, and finding two random messages that hash to the same value requires $2^{64}$ attempts—assuming there is no better way to attack the block algorithm than by using brute force.

# MDC-2 and MDC-4

MDC-2 and MDC-4 were first developed at IBM [1081,1079]. MDC-2, sometimes called Meyer-Schilling, is under consideration as an ANSI and ISO standard [61,765]; a variant was proposed in [762]. MDC-4 is specified for the RIPE project [1305] (see Section 25.7). The specifications use DES as the block function, although in theory any encryption algorithm could be used.

MDC-2 has a hash rate of 1/2 and produces a hash value twice the length of the block size. It is shown in Figure 18.13. MDC-4 also produces a hash value twice the length of the block size, and has a hash rate of 1/4 [see Figure 18.14].

These schemes have been analyzed in [925,1262]. They are secure against current computing power, but they are not as secure as the designers have estimated. If the block algorithm is DES, they have been looked at with respect to differential cryptanalysis [1262].

Both MDC-2 and MDC-4 are patented [223].

# AR Hash Function

The AR hash function was developed by Algorithmic Research, Ltd. and has been developed by the ISO for information purposes only [767]. Its basic structure is a variant of the underlying block cipher [DES in the reference] in CBC mode. The last two ciphertext blocks and a constant are XORed to the current message block and encrypted by the algorithm. The hash is the last two ciphertext blocks. The message is processed twice, with different keys, so the hash function has a hash rate of 1/2. The first key is 0x0000000000000000, the second key is 0x2a4152f44446502a, and c is 0x0123456789abcdef. The result is compressed to a single 128-bit hash value. Sec [750] for the details.

```
$H_i = E_{K_i}(M_i \oplus H_{i-1} \oplus c)$
```

This sounds interesting, but it is insecure. Under considerable preprocessing, it is possible to find collisions for this hash function easily [416].

# GOST Hash Function

This function comes from Russia, and is specified in the standard GOST R 34.11-94 [657]. It uses the GOST block algorithm (see Section 14.1), although in the theory it could use any block algorithm with a 64-bit block size and a 256-bit key. The function produces a 256-bit hash value.

The compression function, $H_i = f\{M_i, H_{i-1}\}$ (both operands are 256-bit quantities) is defined as:

- (1) Generate 4 encryption keys by some linear mixing of $M_i, H_{i-1}$, and some constants.
- (2) Use each key to encrypt a 64 bits copy of $H_{i-1}$ in ECB mode. Store the result 256 bits into a temporary variable, $S$.
- (3) $H_i$ is a complex, although linear, function of $S, M_i$, and $H_{i-1}$.

The final hash of $M$ is not the hash of the last block. There are three chaining variables: $H_i$ is the hash of the last message block, $Z$ is the sum mod $2^{256}$ of all the message blocks, and $L$ is the length of the message. Given these variables and $M'$, the final value is:

$H = f\{Z \oplus M', f\{L, M', H_0\}\}$

The documentation is a bit confusing (and in Russian), but I think all of it is correct. In any case, this hash function is specified for use with the Russian Digital Signature Standard (see Section 20.3).

# 18.12 Using PUBLIC-KEY ALGORITHMS

It is possible to use a public-key encryption algorithm in a block chaining mode as a one-way hash function. If you then throw away the private key, breaking the hash would be as difficult as reading the message without the private key.

Here's an example RSA. If M is the message to be hashed, n is the product of two primes p and q, and e is another large number prime to (p-1)(q-1), then the hash function, H(M), would

```
H(M) = M^e mod n
```

An easier solution would be to use a single strong prime as the modulus p. Then:

```
H(M) = M^e mod p
```

# 18.14 Message Authentication Codes

A message authentication code, or MAC, is a key-dependent one-way hash function. MACs have the same properties as one-way hash functions, but they are used to authenticate files. MACs can be used to determine if files have been altered.

An easy way to turn a one-way hash function into a MAC is to encrypt the hash value with a symmetric algorithm. Any MAC can be turned into a one-way hash function by making the key public.

# CBC-MAC

The simplest way to make a key-dependent one-way hash function is to encrypt a message with a block algorithm in CBC or CFB modes. The hash is the last encrypted block, encrypted once in CBC or CFB modes. The CBC method is specified in ANSI XY.9 [54], ANSI XY.19 [59], ISO 8731-1 [759], ISO 997 [763], and an Australian standard [1996]. Differential cryptanalysis can break this scheme with reduced-round DES or FEAL as the underlying block algorithms [1997].

The potential security problem with this method is that the receiver must have the key, and that allow him to generate messages with the same hash value as a given message by decrypting in the reverse direction. A virus could not do that with a MAC, because the virus does not know the key.

# Message Authenticator Algorithm (MAA)

This algorithm is an ISO standard [760]. It produces a 32-bit hash, and was designed for mainframe computers with a fast multiply instruction [428].
