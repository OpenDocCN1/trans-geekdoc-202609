Assuming that the unit of "time" for our computer is a microsecond, a linear algorithm in a second, and a quadratic algorithm in 11.6 days. It would take 32,000 years to complete a cubic algorithm; not terribly practical, but a computer built to withstand the next age would deliver a solution eventually. Performing the exponential algorithm is futile, no matter how well you extrapolate computing power, parallel processing, or contact with superintelligent agents.

Look at the problem of a brute-force attack against an encryption algorithm. The complexity of this attack is proportional to the number of possible keys, which is an exponential function of the key length. If it is the length of the key, the complexity of a brute-force attack is O(2^k). Section 12.3 discusses the controversy surrounding a 56-bit key for DES instead of a 112-bit key. The complexity of a brute force attack against a 56-bit key is 2^{56}; against a 112-bit key the complexity is 2^{112}. The former is possible; the latter isn't.

## Complexity of Problems

Complexity theory also analyzes the inherent complexity of solve problems (Excellent introductions to this topic are [600,211,1226]; see also [1096,27,739].) The theory looks at the minimum time and space required to solve the hardest instance of a problem on a theoretical computer known as a Turing machine. A Turing machine is a finite state machine with an infinite read-write memory tape. It turns out that a Turing machine is a realistic model of computation.

Problems that can be solved with polynomial-time algorithms are called tractable, because they can be solved in a reasonable amount of time for reasonable inputs. (The exact definition of "reasonable" depends on the circumstance.) Problems that cannot be solved in polynomial time are called intractable, because calculating their solution quickly becomes infeasible. Intractable problems are sometimes called just hard. Problems that can only be solved with algorithms that are superpolynomial are computationally intractable, for relatively small values of n.

It gets worse. Alan Turing proved that some problems are undecidable. It is impossible to devise any algorithm to solve them, regardless of the algorithm's time complexity.

Problems can be divided into complexity classes, which depend on the complexity of their solutions. Figure 11.1 shows the more important complexity classes and their presumed relationships. [Unfortunately, not much about this material has been proved mathematically.]

On the bottom, the class NP consists of all problems that can be solved in polynomial time. time only on a nondeterministic Turing machine: a variant of a normal Turing machine that can make guesses. The machine guesses the solution to the problemeither by making "lucky guesses" or by trying all guesses in parallel—and checks its guess in polynomial time.

NP's relevance to cryptography is this: Many symmetric algorithms and all public algorithms can be cracked in nondeterministic polynomial time. Given a ciphertext, the cryptanalyst simply guesses a plaintext, $X$, and a key, $k$, and in polynomial time runs the encryption algorithm on inputs $X$ and checks whether the result equals to $C$. This is important theoretically, because it puts an upper bound on the complexity of cryptanalysis for these algorithms. In practice, of course, it is a deterministic polynomial-time algorithm that the cryptanalyst seeks. Furthermore, this argument is not applicable to all classes of ciphers; in particular, it is not applicable to one-time pads—for any $C$, there are many $X$, $k$ pairs that yield $C$ when run through the encryption algorithm, but most of these $Xs$ are nonsense, not legitimate plaintexts.

The class NP includes the class P, because any problem solvable in polynomial time on a deterministic Turing machine is also solvable in polynomial time on a nondeterministic Turing machine, the guessing stage can be simply omitted.

If all NP are solvable in polynomial time, then P = NP. It seems obvious that some NP problems are much harder than others (a brute-force attack against an encryption algorithm using a random block of plaintext); it has never been proven that P ≠ NP (or that P = NP). However, most people working in complexity theory believe that they are unequal.

Stranger still, some problems in NP can be proven to be as difficult as possible in the propositional Boolean formula. Steven Cook [365] proved that the Satisfiability problem (given a Boolean formula, is there a way to assign true values to the variables that makes the formula true?) is NP-complete. This means that, if Satisfiability is solvable in polynomial time, then P = NP. Conversely, if any problem in NP can be proven not to have a deterministic polynomial-time algorithm, the proof will show that Satisfiability does not have a deterministic polynomial-time either. No problem is harder than Satisfiability in NP.

Since Cook's seminal paper was published, a huge number of problems have been shown to be equivalent to Satisfiability; hundreds are listed in [600], and some examples follow. By equivalent, I mean that these problems are NP-complete; they are in NP and as hard as any problem in NP. If their solvability in polynomial time were resolved, the previous NP question would be solved. The question of whether P = NP is the central unresolved question of computational complexity theory, and one objective to solve anytime. Whoever shows that P = NP, then most of this would be irrelevant: As previously explained, many classes of ciphers are trivially breakable in nondeterministic polynomial time. If P = NP, then they are breakable by feasible, deterministic algorithms.

## NP-Complete Problems

- Traveling Salesman Problem. A traveling salesman has to visit each city once and return to the starting city. Is there a route with a total distance less than $L$?
- Hamiltonian Cycle. Given a graph, is there a cycle that visits every vertex exactly once?
- Clique Problem. Given a graph and an integer $k$, is there a subset of $k$ vertices such that every two distinct vertices are adjacent?
- Vertex Coloring. Given a graph and an integer $k$, is it possible to color the vertices with $k$ colors such that no two adjacent vertices have the same color?
- Partition Problem. Given a set of integers, can they be partitioned into two subsets with equal sum?

## Modular Arithmetic

You learned modular arithmetic in school; it was called "clock arithmetic." Remember these words? If Mildred says she'll be home by 10:00, and she's 13 hours late, what time does she go home how many years does her get older? That's arithmetic modulo 12. Twenty-three modulo 12 equals 11.

```
(10 + 13) mod 12 = 23 mod 12 = 11
```

Another way of writing is to say that 23 and 11 are equivalent, modulo 12:

23 = 11 [mod 12]

Basically, a = [b mod n] if a = b + kn for integer k. If a is non-negative and b is between 0 and n, you can think of b as the remainder of a when divided by n. Sometimes, b is called the residue of a, modulo n. Sometimes a is congruent to b, modulo n (the triple sign ≡, denotes congruence). These are just different ways of saying the same thing.

The set of integers from 0 to n–1 forms a complete set of residues n. This means that, for every integer a, its residue modulo n is some number from 0 to n–1.

The operation a mod n denotes the residue of a, such that the residue is some integer from 0 to n–1. This operation is modular reduction. For, 5 mod 3 = 2.
