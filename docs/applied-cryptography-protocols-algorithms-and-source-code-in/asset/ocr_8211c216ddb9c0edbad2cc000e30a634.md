The protocol is rife with problems. The CTF has no idea where the votes are
from, so it doesn't even know if the votes are coming from eligible voters. It has no
idea if voters are voting more than once. On the plus side, no one can change
anyone's vote, but no one would bother to modify someone's vote
when it is far easier to vote repeatedly for the result of your choice.

# Simplistic Voting Protocol #2

+   (1) Each voter signs his signed vote with his private key.
(2) Each voter encrypts his signed vote with the CTF's public key.
(3) Each voter sends his vote to a CTF.
(4) The CTF decrypts the votes, checks the signatures, tabulates the votes,
and makes the results public.

This protocol satisfies properties one and two: Only authorized voters can vote
and more than once—the CTF would record votes received in step
[3]. Each vote is signed with the voter's private key, so the CTF knows who voted,
who didn't, and how often each voter voted. If a vote comes isn't signed by
elible voter, or if a second vote comes by a voter who has already
voted, the facility ignores it. No one can change anyone's vote, even if
they intercept it in step [3], because of the digital signature.

The problem with this protocol is that the signature is attached to the vote;
tF knows who for whom. Encrypting the votes with the CTF's public key
prevents anyone from eavesdropping on and figuring out who voted for\whom, but you have to trust the CTF completely. It's analogous to having an elec-
nudge standing over your shoulder in the voting booth.

These examples show how difficult it is to achieve the first three require-
of a secure voting protocol, let the others try.

# Voting with Blind Signatures

We need to somehow deassociate the vote from the voter, while maintaining
authentication. The blind signature protocol does just that.

+   (1) Each voter generates 10 sets of messages, each containing a valid vote
for possible outcome (e.g., if the voter is a "yes" or no question, each message
contains two votes, one for "yes" and other for "no". Each message
also contains a randomly generated identification number, large enough to
avoid duplicates with other voters.
(2) Each voter individually blinds all of the messages [see Section 5.3] and
sends them, with their blinding factors, to the CTF.
(3) The CTF checks its database to make sure the voter has not submitted its
blinded for signature previously. It opens nine of the sets to check that
they are properly formed. Then it individually signs each message in the set.
sends them back to the voter, storing the name of the voter in its database.
