政府还试图通过对销售和分销进行限制，防止加密软件落入“错误的人手中”。在美国，加密产品被定义为“军火”，并像坦克和导弹一样受到出口管制。由此引发了与计算机行业的激烈争论，因为供应商认为这些法规阻碍了他们向跨国公司和其他希望在全球建立安全通信的实体销售可信赖的产品。一些妥协已达成，但这些妥协主要集中在对较弱加密产品的豁免上（可以认为政府能够解密这些产品）。在其他地方，许多国家也纷纷效仿，对密码学的转让和使用施加限制（参见 [第 14.1 节](#ch14.xhtml#ch14_sa2)）。

## 7.5 公司间交易：EFT、EDI 和电子邮件

如果一家企业对其内部网络拥有完全控制权，它就可以完全按照自己的意愿使用密码学和其他安全措施。如果它希望与其它组织安全地交换信息，则并非如此。在这种情况下，它很可能会发现自己的选择受到了其他方的偏好或能力的限制。例如，他们可能无法处理某些加密方法，或希望遵守由外部提供商（如 VAN）设定的标准。

通常，企业对企业链接可分为三类：

1. *电子资金转账*。EFT 消息只需包含与金额、账号等相关的少量基本细节。消息的接收方通常是银行（或者有人会认为，EFT 消息参与了授权 ATM 发放现金）。EFT 消息的构造相当简单，但必须高度重视确保其在传输过程中不会被篡改并且得到完全认证。

“电汇”式的资金转账可追溯到 1871 年，当时美国的 Western Union 公司推出了这项服务。安全性依赖于公司内部使用的授权码系统。电汇的潜在弱点在 1978 年的 Security Pacific Bank 诈骗案中被极其明显地暴露出来，当时一名在银行工作的承包商多次观察到员工使用资金转账程序，并记住了授权码。他利用这些知识向纽约的一个账户转账超过 1000 万美元（Cornwall [1989](#reference.xhtml#ref_r56)）。

今天的系统要复杂得多，并且由计算机驱动。SWIFT 组织提供了一项国际服务，用于银行之间发送金融指令，总部位于比利时的 La Hulpe。（它通常以缩写形式为人所知，但最初首字母缩写代表 Society for Worldwide Interbank Financial Telecommunication，世界银行间金融电信协会。）SWIFT 的成员由全球约 6,500 家精选金融机构组成。对网络的访问受到严格控制，成员必须使用基于 SWIFT 严格制定的标准的加密。

对于日常商业支付，多数国家都有服务可用于涉及相对小额的资金转账。这些通常是“批量”支付，例如在每周或每月末将组织所有员工的工资转入其银行账户。在英国，超过四分之三的劳动力现在以这种方式领取工资。使用此类服务的用户必须注册，并将被要求使用识别码和密码。然而，由于涉及的企业数量众多，管理加密的开销过大，因此加密被排除在外。

2. *电子数据交换*。EDI 为企业对企业消息提供了一套标准格式。例如，销售发票和预订确认等项目的內容和布局都有格式规范。（类似的格式也用于资金转账，因此 EFT 可被视为 EDI 的一个专门子集。）

EDI 起源于 1980 年代的多个不同商业领域，最初每个行业都开发了自己的“方言”——用于汽车制造、航运、建筑、旅游等。欧洲和美国也曾一段时间存在不同的标准。所有这些标准最终都汇聚成了 UN/EDIFACT 规范（行政、商业和运输电子数据交换），该规范现已在全球使用。

EDI 提供的一项效率是，其消息现在被许多商业计算机软件所识别。这意味着，例如，订单的详细信息可以直接传递到订单录入系统，或发货通知可以直接记录到仓库数据库。这种人类干预的缺失无疑加快了业务流程并降低了成本，但也去除了有时至关重要的人能够注意到消息中存在不合理或可疑要素的机会。

3. *电子邮件*。邮件消息完全自由格式。它们可用于传递业务信息和指令，但这些信息必须由人工阅读者（或也许是“智能”计算机程序）来解释。互联网上最常用的电子邮件格式是 SMTP（简单邮件传输协议）。基本的 SMTP 格式比 EFT/EDI 更简单、更通用，并假定其承载的消息仅为文本。然而，SMTP “扩展”此后已被发明，以使其能够承载其他类型的数据（见下文）。

原则上，电子邮件可用于发送从公司的秘密生产计划到最琐碎的小事的任何内容。除非企业愿意常规加密其电子邮件，否则唯一可行的政策是发布禁令，禁止使用电子邮件传输任何敏感信息。在此背景下，应记住不同类型的消息通常是“链式”连接的，例如 [图 7.3](#ch7.xhtml#fig7_3) 所示的案例。在此示例中，一名在家工作的经理向办公室的一名职员发送电子邮件，其指令导致向银行发送了一条 EDI 消息。银行随后根据 *其* 指令作出回应，向供应商进行 EFT 付款。

随着世界越来越依赖电子消息传递，发现这种链式连接——一条消息触发另一条消息——变得司空见惯。从安全角度来看，重要的是链中的所有环节都应获得相似程度的保护。例如，EFT 消息可能因涉及现金转账而受到非常严格的控制。最终，如果一个有心的黑客能够伪造一封令人信服的电子邮件从而引发所有其他事件，这些控制措施就毫无用处了。电子邮件伪造并不特别困难，美国软件公司 Oracle 就为此付出了代价，当时一封据称由 Oracle 经理发送的电子邮件被引用在一项不公平解雇的索赔中。该邮件最终被证明是由提出索赔的前员工伪造的（Savarnejad [1997](#reference.xhtml#ref_r202)）。
