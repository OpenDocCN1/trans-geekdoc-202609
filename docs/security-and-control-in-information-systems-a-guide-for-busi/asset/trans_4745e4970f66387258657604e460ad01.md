

这种来自过去的遗留问题也可能使 IT 系统难以与当前的组织结构和边界非常精确地保持一致。这一点所带来的一些影响已经有所涉及（参见[第 1.6 节](#ch1.xhtml#ch01_sa6)和[第 3.3 节](#ch3.xhtml#ch03_sa3)）。不幸的是，整个访问控制的概念都依赖于能够在被保护的实体和未被保护的实体之间做出明确区分。这迫使必须非常精确地决定系统的边界在哪里，以及谁被允许使用它们。如果以往的做法是设施以非正式方式共享，或者对于一些较老旧或使用频率较低的系统而言“开放访问”一直是常态，那么这可能会证明特别困难。

传统上，访问控制的边界设定在两个层级。第一层标志着*通用控制*的适用点。理想情况下，这些控制涵盖组织中使用的所有 IT 设施。有时，考虑一个较小的单元可能是合适的，例如一个单独的办公地点或一家公司的部门。在第二层级，*应用控制*用于在人们开始使用单个设施（此处的“应用”指基于特定软件的服务，例如会计或计算机辅助设计）后调节访问和使用。许多组织中 IT 的拼凑式演进意味着该模型在实践中往往无法非常完美地契合；然而，它有助于探讨访问控制最好如何以及在何处进行管理的一些问题。

在通用边界上的访问控制可以类比为使用共享办公楼外门的钥匙。这是获得你想要使用的设施访问权限的第一步。给予你这种“通用”访问并不意味着你被允许在建筑物内自由漫游。一旦被准入系统，你会发现自己被限制在被认为与你的需求相关的应用范围内。这可以类比为能够进入一栋办公楼，但被迫使用只能停在你工作楼层的电梯。这种控制模型在[图 4.5](#ch4.xhtml#fig4_5)中有所描述。

在业务系统中，一些应用（如电子邮件）将对几乎每个人开放。其他应用（如研究与开发或市场营销使用的数据库）则包含具有相当商业价值的数据，因此其使用将受到更严格的限制。理想情况下，通用访问控制应为每个人呈现系统的“逻辑”视图，给人一种印象，即除了该用户被授权的应用之外没有其他应用。因此用户 A 和用户 B 在首次登录时可能会看到两套截然不同的选项（参见[图 4.6](#ch4.xhtml#fig4_6)）。以这种方式隐藏应用对用户来说很方便，因为他们不会浪费时间尝试进入被禁止的应用，同时也使有志于黑客攻击和欺诈的人的生活变得更加困难。

需要允许每个用户访问的权限需要在*访问控制表 (ACT)*中定义。这是一个在软件中创建的表格，将用户和应用关联起来。在最基本的形式中，访问控制表将列出所有授权用户，并显示应为每个用户开放的应用（如下图所示[图 4.7](#ch4.xhtml#fig4_7)）。它最好是中央操作系统或网络管理软件的组成部分；由于访问控制对安全至关重要，最好将其设计并构建到软件的核心中。如果认为基本操作系统存在弱点，或为了帮助日常管理对 ACT 的更改，也可以购买专门的安全软件产品来加强控制。

任何能够修改访问控制表的人都处于极其强大的地位。因此，至关重要的是该表本身必须受到严格的访问控制，只有少数高级员工被授权对其进行更改。

## 4.4 应用控制：多重与单点登录

一旦用户获得了对应用的合法访问，是否需要施加进一步的访问控制取决于应用的性质。例如，每个电子邮件用户都需要大致相同的标准功能；使用市场数据库的人希望能够浏览其中包含的所有数据。在这些情况下，对应用的访问意味着可以自由使用而无需任何进一步限制。

在其他情况下，需要引入额外的控制层级。例如，一名初级职员可能被允许访问会计系统，但仅限于录入订单或发票。而他的主管则被允许执行更敏感的任务，例如在系统中录入新客户和核销坏账。同样，对于跟踪仓库货物情况的应用，某些人仅限于查询库存状况，而其他人则被允许在货物进出时记录变更。在医院，初级员工可能能够使用患者管理系统查找患者的所在位置，但不能浏览其他患者详情。应用层级控制的增加在[图 4.8](#ch4.xhtml#fig4_8)中有所说明。

如果以这种方式为应用创建单独的访问控制制度，则存在一些优缺点，如下所示。

### 优点

* *接近性*。如果有某个部门是应用的主要使用者，访问控制的责任可以分配给其高级员工之一。该人员将处于了解应用使用方式的良好位置，因此可以判断部门不同成员可能需要的访问类型。

* *响应性*。将责任移交给驻用户部门的人员意味着用户请求更新和更改，以及报告他们对控制工作方式的任何担忧应该会更容易。

### 缺点

* *登录的复杂性*。以最常见的情况为例，即使用密码，创建完全独立的访问控制制度意味着用户必须先输入一个密码进行通用访问，然后再输入另一个密码进入应用。用户可以理解地不愿使用多个密码。可以安排使用相同的密码用于两种情况（该过程称为*同步*密码）。然而，这意味着本地密码管理员与中心之间需要不断联络。此外，并非总能对不同软件包中的密码格式和用户 ID 应用相同的约定。如果使用任何令牌或生物识别方法，复杂性会倍增。
