

这第二点，引发了关于计算机审计技能究竟有多可转移的问题。诸如 `CISA` 之类的资格认证可以保证某人理解典型计算机系统的基本要素，以及它们应如何管理的原则。它们也可能要求具备大量的审计经验。尽管如此，雇主可能会更优先考虑对企业实际使用的设备、操作系统和应用程序的深入了解。他们更愿意雇用一个由“偷猎者”转变为“护林员”的人。这种情况在计算机审计已得到充分建立的行业中尤为明显，例如金融服务业和公共服务的某些分支。

因此，计算机审计师在满足通常为“职业”所规定的标准方面存在一定的困难。认可方案仍相当初级，并且缺乏其他特征，例如在准入点的监管或某种形式的许可（Freidson [1986](#reference.xhtml#ref_r89)）。相反，它们依赖于不太正式的认可，但这种认可却是真实且即将到来的，因为对他们专业服务的需求。实际上，这意味着计算机审计师只能凭借其技术技能来成败。有关计算机审计的出版物，与有关更成熟职业的出版物不同，主要关注技术问题。鉴于这种技术重点，毫不奇怪地发现计算机审计师经常与组织中其他对信息系统感兴趣的人广泛建立联系。与此同时，他们必须依靠与内部审计和会计等更成熟职能的关联来获得其地位和独立性。[Figure 12.2](#ch12.xhtml#fig12_2) 给出了这一情况的简化视图。阴影区域描绘了一个区域，在该区域内，对 IT 的关注提供了共同纽带。在该区域内保持适当的合作关系并不总是简单的，并且存在各种潜在的冲突领域。

* *Site security*. 保护组织的员工和有形资产的措施越来越多地依赖于技术的使用。有时，可以进行有益的合作，例如如果计算机审计师需要知道员工是否在特定时间在现场，或者有机会将信息系统控制与执行物理访问的控制集成在一起。在军事或政府机构中，信息保密是首要关注的问题，这种安全职能将非常强大，与运行信息系统的人员有牢固的联系。

* *IS security officer (ISSO)*. 许多组织，特别是较小的组织，并没有正式任命的 ISSO。然而，通常情况下，IS 中央服务部门的某个人将负责监督安全。责任可能与管理密码和访问控制表相结合，使该角色非常技术化。设立 ISSO 的一个优点是，可以任命某人对业务的运作方式有更广泛的见解（Kovacich [1997](#reference.xhtml#ref_r145)）。

* *IS central services*. 该部门的成员将负责管理访问控制，并负责执行和应用本书其他地方所述的许多措施。理想情况下，他们将与计算机审计师密切合作，但执行和审计的角色应保持分离。安全管理涉及提供措施和强制执行合规性。审计师的存在是为了充当看门狗，并提供客观的审查和建议。这种关系是否富有成效，将取决于组织内的舆论气候。对美国 300 多名信息系统经理的一项研究显示，通常情况下，他们对 IS 审计师的技术技能评价不高，并且认为无论如何他们都没有足够的资源来实施审计师的发现。他们尽管如此仍感到有强烈的压力去采取行动。绝大多数（85%）拒绝了审计师是合作伙伴或仅仅是顾问的想法，并持更传统的观点，认为审计师具有对抗性的“警察”角色（Hunton and Wright [1995](#reference.xhtml#ref_r122)）。

* *IS local services*. 服务管理是否下放到地方层面，将在很大程度上取决于组织的架构（参见 [section 3.3](#ch3.xhtml#ch03_sa3)）。在这一层面，计算机审计师也可能发现一种 somewhat 对抗性的氛围，特别是如果文化是对“总部”职能普遍不信任的话。这使得激励员工确保合规变得困难。考虑一下 Gordon 在处理她银行时引用的一个事件。Gordon 女士希望更改其账户适用的其中一个条件，并出示了一张已取消的支票以表明账户号码。账户详细信息随后由银行职员修改，Gordon 女士被邀请为电话访问选择新的 PIN 码。Gordon 女士（[1999](#reference.xhtml#ref_r96)）指出：
> … 在任何时候，我都没有被要求出示照片身份证。我以前从未见过这位职员，她也不认识我。我拿出我的护照，上面与我的银行账户姓名不同，并说：“你忘了要求这个。”她瞥了一眼，说：“好的，谢谢！”就这样结束了。
也许 Gordon 女士遇到的职员不知道规则。更可能的是，她知道规则，但并不特别认为它们有什么意义。扭转这种态度需要不断地滴灌式观察和解释。计算机审计师可以采取的一种方法是确保技术人员充分了解安全措施，希望他们会主动向周围的其他员工解释和证明这些措施。

* IS suppliers. 供应商通常向做出采购决策的管理人员销售产品，但如果安全被视为产品的强项，计算机审计师将成为目标。此外，计算机审计师可能会被要求处理供应商提供 IS 安全产品和服务的探索性方法。这是一种收集信息的有用方式，但审计师必须注意不要显得与任何一家供应商结盟，这与审计师独立性的主张并不相符。

尽管在这种以技术为主的领域中运作，计算机审计师也需要警惕审计世界总体上发生的某些地震式转变。例如，在 1992 年，美国会计的发起组织委员会（`COSO`）审查了内部控制的性质和目的。它建议应更多关注组织中人员的总体诚信、道德价值观和能力水平等所谓“软”因素。这反过来又引发了关于内部审计与外部审计之间适当角色的新辩论。另一个美国机构（内部审计师协会研究基金会）最近资助的研究表明，世界各地的企业开始将以前分开的风险管理职能整合在一起，包括内部审计、质量保证和健康与安全。项目主管预测，“风险管理与保证将被视为管理的一个维度。在这种情况下，内部审计消失在管理过程中”（`IIA` [1998](#reference.xhtml#ref_r125)）。内部审计是否真的会被以这种方式吸收，以及计算机审计是否会随之被吸收，还有待观察。
