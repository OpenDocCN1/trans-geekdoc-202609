

一旦消息被加密，其长度将与明文相同；因此不会在网络上产生额外的流量负载。然而，有时需要“即时”加密，例如视频会议或语音通话。如[section 6.5](#ch6.xhtml#ch06_sa5)所述，在这种情况下，使用流加密而非分组加密可能是有利的。无论使用何种加密方法，可用的处理能力必须足以避免在峰值负载下出现减速。这可能意味着需要投资比原本必要更强大的处理器。

以下两种方法可以最大程度地减少常规交易中加密的开销。

* *使用哈希的数字签名*。使用非对称算法和她的私钥，Alice可以加密，从而“数字签名”整个消息。然而，她同样可以准备消息的哈希值并对其进行签名。由于哈希值比原始消息短得多，因此涉及的加密开销要小得多。Bob现在必须解密哈希值，并将其与他从收到的消息计算出的值进行核对。如果这一切都能令人满意地进行，他就可以确信哈希值和消息都来自Alice。此过程在[Figure 6.10](#ch6.xhtml#fig6_10)中进行了说明。

![Figure 6.10 Digital signing using a hash](images/fig6_10_B.jpg)

[Figure 6.10 Digital signing using a hash](#ch6.xhtml#R_fig6_10)

* *先非对称后对称加密*。如果Alice拥有Bob的公钥，她就可以在保密条件下使用该密钥向他发送她选择的另一个密钥。此密钥现在仅Alice和Bob知道。他们随后可以使用此密钥作为后续消息的`one-time key`，在两个方向上使用对称加密。这使他们能够从启动时的一次性非对称加密爆发（开销高）切换到其余数据流量的对称加密（开销低）。

## 6.8 Security on the Internet

将企业连接到互联网，无论是作为网络提供商还是仅用于浏览和使用电子邮件，都会立即使其与全球数百万人进行联系，完全不加区分。企业可以与客户、供应商、监管机构、银行和其他可以预期对其业务目标有共同利益的人进行沟通。与此同时，它也使自己对异议者、无政府主义者、诈骗者以及许多其他利益可能远不如人意的人开放。当然，其他服务，如邮件和电话，也存在同样的普遍连通性。然而，只有互联网能够快速、直接地对企业核心的计算机化功能造成严重损害。

*在将互联网视为通信媒介时，唯一可以安全做出的假设是它完全没有任何安全性*。更糟糕的是，它作为全球松散的网络联合体运行，监督和监管参差不齐且经常不存在。因此，如果远程用户*确实*对企业发动了成功的攻击，获得补救的机会将微乎其微。

不出所料，这种情况催生了一个蓬勃发展的市场，专门提供旨在让企业用户安心的产品和服务。例如，有供应商会建立（在某些情况下还运营）`Virtual Private Network`（VPN）。这是一种网络服务，即使流量实际上是通过不安全的链路，例如互联网传输，也能向所有用户保证一定的安全设施。（这种安全路由的创建有时也被称为`tunnelling`）。还有各种各样的产品称为`firewalls`，旨在在企业与互联网之间创建保护屏障。防火墙保护特定站点，而VPN的保护范围则延伸到多个站点。防火墙和VPN的简化图示见[Figure 6.11](#ch6.xhtml#fig6_11)。

供应商会以他们认为对市场有吸引力的方式将产品打包在一起。对于VPN或防火墙究竟应提供什么，并没有统一的定义。然而，这两种产品往往都工作在`lower`通信层（见[section 6.4](#ch6.xhtml#ch06_sa4)所述）。它们集中于为在网络中路由数据而插入数据的控制信息。它们的目的是检测任何可疑的东西，例如，对某种流量来说不寻常的服务功能请求，或使用不合适的网络地址。其假设是，到达屏障的数据包可能已被熟练的黑客篡改，他们正在寻找进入组织计算设施的途径。

为了使这种检查有效，VPN或防火墙软件必须被告知它应将何种活动视为正确或正常。有时这种情况会发生变化（例如，当有新计算机接入网络时），因此规则需要进行修改。与访问控制表和病毒检查器一样，VPN和防火墙必须不断审查，并在变化发生时尽快更新。

不幸的是，某些类型的攻击无法在较低的通信层中检测到。为了进行真正严格的检查，需要在*所有*层面上应用。一些更昂贵的防火墙试图通过充当所选上层活动的`proxy`来实现这一点。例如，代理防火墙会拦截登录应用程序的请求，并在用户接近真正的应用程序之前*先*进行用户凭证的必要检查。此类预防措施成本极高，因为它们不仅涉及为防火墙提供额外的机器，还需要重新设计应用程序程序，以确保安全元素可以分开处理。代理防火墙的维护成本也很高，因为其软件需要随着应用程序程序的任何修改而升级。代理防火墙如图[Figure 6.12](#ch6.xhtml#fig6_12)所示。

在决定防火墙或VPN对给定组织是否有帮助时，有用的是首先看看互联网将如何使用。并非每个人以相同的方式或出于相同原因连接到互联网。以下是一些关键考虑因素。

* *企业内部的连通性*。如果一台孤立的PC连接到互联网，潜在的损害仅限于该PC。然而，如果该PC还连接到企业内部运行的局域网或内联网，入侵者可能到处去攻击任何东西。对于某些电子商务应用，可能必须具有这种类型的连接（例如，如果公众要在网页上输入预订，并且这些预订要立即传输到中央预订系统）。另一方面，如果只是办公室工作人员偶尔需要查询互联网，最便宜、最有效的屏障可能是使用一台独立的PC，该PC包含最少的软件，包括网络浏览器，但除了其与网络的连接外，绝对没有任何其他网络连接。
