

技术标准的定义和采用涉及全球众多官方和半官方机构。它们大多通过合作协议和交叉代表联系在一起。通常可分为三类：

*   *行业主导*。成员可能来自 IS 货物和服务的供应商，如 ETSI（欧洲电信标准协会），或由严重依赖 IS 的行业部门的代表组成，例如 ECBS（欧洲银行标准委员会）。
*   *专业*。一些在 IS 领域工作的专业人士协会已发展出制定标准的作用。其中最历史悠久的是总部位于美国的电气和电子工程师学会（IEEE）。
*   *“官方”标准制定机构*。其中一些由政府资助，但许多是独立的非营利组织。也许最著名的是 ISO，它是 130 个国家标准组织的联合会。（ISO 的名称并非基于其缩写（它实际上称为国际标准化组织），而是基于希腊语中的“相等”一词）。

一些机构的工作方式涉及上述的混合。美国国家标准协会就是一个例子，它是一个非营利机构，其公开目标是通过标准提高美国工业的竞争力。其成员来自私营部门公司和政府机构的广泛跨界。

有关 IT 标准制定的全面、 albeit 略显过时的概述，读者可参考 Judge（[1991](#reference.xhtml#ref_r134)）和 Cargill（[1989](#reference.xhtml#ref_r47)）。如今，任何 IS 采购商都不可能跟踪全球所有与标准相关的活动，但大多数标准机构现在都有组织良好的网站，并且经常值得检查在营销材料中发现的任何关于标准的引用。（这也可能很有趣，可以向供应商提出一两个关键问题。绝不能认为销售团队对 IS 标准术语的熟悉程度比其客户更高）。

一些主要标准机构网站的详细信息在 [附录 2](#appendix2.xhtml) 中提供。以下两个示例展示了标准如何在产品规格中出现，以及它们可能为何重要。

### 示例 1

以下内容取自一款电子邮件产品的实际规格。

> 消息签名使用美国国家标准与技术研究所（NIST）的数字签名算法（DSA）和安全散列算法（SHA-1）生成；消息使用 FORTEZZA PC 卡上的密码协处理器进行加密
> 
> LJL [2000](#reference.xhtml#ref_r155)

该声明是较好的声明之一，因为它至少解释了所有缩写的含义。然而，对于不熟悉的人来说，这些名称可能仍然意义不大。

NIST 并不是通常意义上的国家标准机构，而是一个美国商务部下属机构。NIST 以 `FIPS`（联邦信息处理标准）的形式发布其标准，任何人都可以自由采用。然而，所有美国政府机构都应尽可能遵守 `FIPS`。数字签名算法是《数字签名标准》中授权使用的两种算法之一，该标准以 `FIPS 186–1`（1998）发布。安全散列算法定义于 `FIPS Publication 180–1`（1995）。所有这些信息都可以在 NIST 网站 `www.nist.gov` 上查到。

`FORTEZZA` 加密卡是由美国国家安全局推广的标准。符合该标准的情况可以使用 NSA 开发的测试进行认证，其详细信息可在 `www.fortezza-support.com` 上找到。

因此，有意购买者可以得出结论，本产品规格中提到的加密、签名和散列功能均基于美国政府官方机构制定的标准。此外，这些标准应在美国政府内部的广泛使用中得到检验。有些人会对此感到安心。另一些人则对美国政府的参与持更负面的看法：例如，有人指责其故意在开发的产品中留下“后门”，以便秘密解密消息。这就是标准规范的 *开放性* 变得重要之处，因为如果它可以完全独立于政府进行实现和测试，就不太可能在其中构建任何不正当的设施。

标准领域的变幻莫测或许可以通过另一系列散列算法标准的例子来说明。罗纳德·里维斯特（RSA 加密的创始人）发明了一系列散列（或消息摘要）算法，称为 `MD2`、`MD4` 和 `MD5`。这些标准的详细信息可以在 RSA Security Inc 的网站上找到，也可以在保存 RFC 目录的多个其他网站上找到。`RFC`（征求意见稿）是发布与互联网上使用的产品相关的规范的一种方式，供人们自愿作为标准使用。此类标准的权威性来自广泛的采用和测试，而非来自官方政府认可。

#### 示例 2

一些营销材料涉及执行访问控制或防止黑客攻击的软件，并声称该产品已获得某一安全级别的认证。提供的保证例如：“X 操作系统已评定为 TCSEC C2 级”，或“此防火墙符合 ITSEC E3 标准”。

同样，普通客户可能会想知道这种胡言乱语在购买决策中的相关性或无关性。就刚刚引用的两个实例而言：

*   `TCSEC` 代表可信计算机安全评估标准。这是其中最古老的安全标准之一，最初由美国国防部于 1983 年开发，被称为“橙皮书”。它集中于“可信计算基”，即在系统中执行安全控制的软件。
    `TCSEC` 一直反映其军事起源，主要关注保密的保存。系统可从 A 到 D 评级。D 是最低类别，提供很少或没有安全性，A 是最高可能等级。一些类别被细分，例如 C2 实际上低于 C1。
*   `ITSEC` 代表 IT 安全评估和认证计划。它由欧洲委员会推广，并在英国由切尔滕纳姆的政府安全和通信机构（CESG）管理。正在努力将 `ITSEC` 与 `TCSEC` 和其他国家计划协调起来，统称为通用标准项目。
    `ITSEC` 将软件产品从 E0 到 E6 分级。E0 不提供任何保护，而 E6 提供广泛的保护以及适当的<|message|> 管理工具。认证级别越高，检查其安全声明所需的文档和测试量就越大。

根据这些计划授予的类别始终应被视为仅表示产品的 *潜在* 安全性。如果产品未正确安装和管理，安全性将被破坏，对优质产品的投资将付诸东流。还应密切注意该计划设定的标准的性质。如果像 `TCSEC` 这种情况，重点是确保保密，这可能对企业组织而言并非最高优先事项。
