

*   `Dual entry`（有时也称为 `dual keying`）。相同的数据由两位不同的人独立输入。系统会比较两个版本，并突出显示任何差异。然后必须有人检查所有发现冲突的情况，并选择正确的版本。这是一种识别和消除录入错误的好方法，但在人员时间方面成本很高。如果目的是防止故意篡改输入数据的行为，则最终阶段（审查数据并解决任何差异）必须由资深且值得信赖的人员处理。
*   `Explicit authorisation`。如果所涉及的数据录入可能促进欺诈，系统可以被编程为在接受数据之前要求某种形式的授权。最常见的做法是要求主管使用更高级别的授权登录，并表示批准该交易（批准可在同一终端上给出，或理想情况下在另一个终端上给出，以降低主管密码被发现的风险）。当向客户退款或注销债务时，可能会遵循此程序。
*   `Control totals`。控制总额主要用于财务数据，但可应用于几乎任何保留有价值项目累计记录的交易。其步骤顺序如下。
    1. 将若干类似交易批量组合在一起。
    2. 人员 A 浏览交易的资料来源（例如一堆纸质发票）并计算所有交易的总值（所有发票应付金额的总和）。
    3. 该总值输入计算机。人员 B 现在输入所有交易的数据。
    4. B 完成数据录入后，计算机自行计算总值，并将其与 A 在开始时输入的值进行比较。
    5. 如果总额匹配，则交易处理继续进行。如果不匹配，系统将拒绝继续，数据录入必须被检查，直到差异得到解释为止。

与校验位一样，控制总额可以成为显示录入错误的有用方法。它们也可能有助于遏制欺诈，前提是 A 和 B 完全相互独立地工作。

### 5.2.5 非标准语法或词汇

即使信息以自由形式输入，如文字处理和电子邮件，企业也可能希望确保材料符合其自身的规范和标准。办公软件包现在提供了一系列用于检查文本的选项，可以在输入时突出显示可能的错误，或随后运行检查。最常见的是，检查器会将文本中的单词与标准拼写列表进行比较，并查询不在列表中的单词。操作员被留下来做出最终决定：由于总会有名称、缩写或另一种语言的引文无法在官方列表中识别的情况，因此这是一个无法完全自动化的过程。

一些检查器更进一步，会查找语法、标点甚至风格上的疏漏。

尽管它们有助于发现写得糟糕或令人困惑的短语，但它们只能应用相对简单的规则，无法考虑上下文。因此，大多数检查器会忽略诸如“payment to be made in ponds sterling”这样的短语，因为它符合所有拼写和语法的规则，尽管不符合常识。

## 5.3 处理数据

一旦数据输入系统，它将以对用户 largely 隐藏的方式进行处理。事实上，即使对技术熟练的人员来说，也不应认为处理逻辑很容易显而易见。这可能是因为相关代码非常旧，而且关于它的文档可能已经丢失，或者因为它是用后来已过时的语言编写的。‘打包’程序也会因不同原因造成问题。在这种情况下，这是因为供应商更喜欢以 `object` 代码形式交付产品。这是可以直接在机器上运行的代码，但不包含原始 `source` 程序中的任何信息，而这些信息对于理解程序逻辑是必需的。许多组织在试图确定其程序是否能够正确处理 2000 年及以后的日期时，都不舒服地熟悉了弄清其系统“幕后”发生了什么的问题。

检测和识别软件异常的潜在困难在两个旧案例中得到体现，一个涉及欺诈，另一个是逻辑错误。在这两种情况下，都需要外部压力才能揭示发生了什么。今天的安装目标应该是建立措施，确保此类异常能够迅速被发现，在其成为尴尬来源之前。这些措施可能包括：
1. `Preventive controls`
    * `Dual processing`。与双重录入类似（参见 [5.2.4](#ch5.xhtml#ch05_sb5)），这取决于做两次。两台计算机相连，交易在两台计算机上同时处理。结果会不断比较。这种安排的主要目的是通常确保系统可用性（例如，在超市收银系统）。然而，对准确性的额外检查是有用的副产品。由于两个处理器运行相同的软件，如果这是由于在两者上都复制的软件缺陷造成的，两个处理器仍可能对错误结果达成一致。
    * `Control totals`。再次，这里使用的原则与输入时相同（参见 [5.2.4](#ch5.xhtml#ch05_sb5)）。该方法只能在所有记录都以相同方式处理的情况下应用（即使用‘批处理’）。例如，如果一家电力供应商正在生成将发送给客户的季度账单，可以为程序预期处理的账单数量创建一个控制总额。或者，可以对电力单位的数量或应计账单总额进行汇总。该总额必须与在批处理中其他地方独立计算的总额相匹配。
2. `Feedback controls`
    * `Test transactions`。这些可以是已预先计算出预期结果的“真实”交易，也可以将“虚拟”交易输入系统，使用专门选择的数据来探测系统是否按规范工作。虚拟交易之后需要取消或折扣——这当然本身就是一个需要谨慎控制的问题。
    * `Transaction logs`。交易进行时，会将所选细节写入计算机文件。理想情况下，该文件位于“一次写入”介质上，例如一次写入多次读取的光盘（或 WORM）。这确保了即使有人成功干扰交易或其输出，日志本身也无法被篡改，有用的线索或证据会保留在“记录”上。从交易日志中应能够确定用户的身份、时间以及有关输入的数据或写入的文件的指示。一些软件供应商将这种日志称为提供计算机化的“审计跟踪”。然而，审计跟踪应始终包括其他佐证证据（参见 [section 13.3](#ch13.xhtml#ch13_sa3)）。
