

安全功能经常在企业软件包的宣传材料中被提及作为卖点。然而，将竞争供应商的安全声明进行比较，比软件的其他方面要困难得多。例如，如果一个文字处理产品被认为提供拼写检查等日常功能，这可以迅速得到测试和验证。另一方面，关于该软件包在其文件系统中提供高度安全的加密设施的说法，可能得到各种标准、命名算法和其他技术数据的支持，但只有技术专家才能对其进行适当核查。

无论如何，供应商最多只能提供实施安全措施的手段。无论其*潜在*多么优秀，任何安全措施在未得到正确配置和激活之前都是毫无用处的。虽然购买一个具有五星级安全功能的软件包可能让人感到安心，但如果对其使用缺乏半心半意的承诺，这样做就毫无意义。事实上，这样的投资可能完全是浪费金钱。顺着这个类比，这就像入住一家五星级酒店，然后走出去在路边的快餐柜台用餐。

选择和安装办公软件中的安全功能变得更加复杂，这主要是由于软件的打包和营销方式。在个人电脑市场尤其如此，市场由一家供应商（Microsoft）主导，该供应商热衷于向每个人销售基于其办公和网络管理软件产品线的集成方法。竞争对手也有类似的雄心。一个结果是，用户发现自己承受着压力，必须建立一个工作组和网络活动都不可分割地交织在一起的系统。这符合供应商的营销策略，他们希望在桌面上“拥有”尽可能多的活动，并通过自己的专有标准将其扩展。安全在这种情况下可能并不总是受益，尤其是如果过分强调共享资源并使其“用户友好”。

## 1. ‘虚拟’文件存储
用户被鼓励认为，保存在自己硬盘上的文件与保存在其他机器或互联网站点上的文件之间没有区别。用于从所有这些不同来源检索文件的机制被故意设计成看起来相同。这意味着人们不必学习任何新的程序来处理远程文件，并为他们开辟了全新的、令人兴奋的工作方式。与此同时，它也创造了一系列全新的安全风险。对安全问题的最佳解决方案往往就是彻底消除它，通过使人们无法访问自己机器之外的文件来实现。然而，软件越来越多地被设计为自我推销；用户会发现它内置了设施扩展方式的演示，以及订阅新产品和服务的邀请。至少，这会产生让用户获得更广泛访问权限的需求。在最坏的情况下，访问权限默认就已可用，甚至可能包括指向可下载全新程序和进一步营销材料的网站的指针。
企业面临的问题是，它不能假定设置新的办公软件包在安全方面必然是“万无一失”的。困境在个人电脑供应商提供预装办公应用的“即用型”系统的情况下尤其尖锐。这无疑节省了大量设置和配置时间。然而，预装软件的人试图使其适应广大客户群体的各种可能需求。由于他们希望客户在尽可能短的时间内开始高效使用个人电脑，因此他们的重点将放在消除障碍，并尽可能轻松地激活应用程序。

## 2. 过于热心的软件
安全与便利之间的冲突可以通过许多其他方式显现。例如，“自动完成功能”是一种非常用户友好的设备，但它会削弱安全性，正如 Schifreen（[1999](#reference.xhtml#ref_r203)）所指出的。自动完成功能会介入以完成它认为识别出的短语或地址。如果你在输入一个很长的网站地址时，自动完成功能会在你输入前几个字符后为你填入剩余地址，这可能很有帮助。但如果它也在请求你的 ID 和密码的面板中主动提供条目呢？Alexander（[1996](#reference.xhtml#ref_r3)）给出了一个更离奇的例子。有一个特别“有帮助”的功能，如果密码输入三次不成功，就会弹出提示询问你是否愿意通过设置一个更容易记住的新密码来重新开始。

## 3. 自行访问控制
供应商面临的一个问题是，在煽动了对完全联网办公的热情后，他们必须提供一种设置授权以限制人们可以看到和做的事情的手段。这意味着创建[第 4 章](#ch4.xhtml)中描述的那种访问控制表。在老式的主机计算机上，这样的表由昂贵的高薪系统程序员设置和管理。供应商面临将此任务简化到可以由中等电脑素养的办公室主管处理的水平。
他们尚未完全成功。可以消除一些技术术语，并用在办公室听起来更熟悉的术语来代替。例如，对文档只有只读访问权限的人被称作“审阅者”，而“拥有”文件的人几乎可以做任何事情。即便如此，面对“发布编辑”与“发布作者”等术语时，有时有必要查看细则以了解每组权利的确切允许和不允许内容。
即使访问控制管理员能够弄清楚所有这些内容，然后就需要确保使用文档的每个人*也*理解限制是如何运作的。在许多情况下，他们需要这种理解，以便他们自己能够为自己创建的文档设置访问限制，并希望他人更新或审阅这些文档。为使其令人满意地运作所需的时间和精力不应被低估。相反，如果访问权限管理不善，人们只会通过在任何可以的地方互相授予不受限制的权限来绕过它们。这就成为一个潜在的“五星级”设施被变成一星服务的典型例子。

## 4. 标准保护，标准对策
办公软件现在常规提供保护文档和文件的方法，通常基于在保存数据时输入密码。这种密码的问题在于，它们可能是临时选择的和输入的，很容易被遗忘。
一个尽责的用户会遵循关于选择晦涩、随机密码并每次更改的规则。这意味着大量业务数据可能最终被锁起来，受保护的密码被私下保存——也许并不系统化。情况与加密保护的文件类似（参见[第 7.4 节](#ch7.xhtml#ch07_sa4)），对于加密，存在一种可能性，即如果加密密钥丢失，可以通过密钥恢复方案检索。
