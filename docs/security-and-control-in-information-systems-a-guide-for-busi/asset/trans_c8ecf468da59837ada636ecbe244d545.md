

在 1980 年代，这一集中化模式开始承受越来越大的压力，许多组织开始寻求管理其信息系统基础设施和服务的新方法。这主要由技术进步驱动，技术现在能够提供更小、更便宜且更具韧性的系统。供应商抓住机会绕过数据处理部门，并开始直接向用户销售其产品。与此同时，董事会层面日益认识到 IT 已步入成熟。它不再仅仅是工厂或办公室中的另一种工具，而必须被视为决定业务成败的潜在关键因素。这进而引发了关于应由何种人负责管理信息系统以带领组织迈向新时代的讨论。人们呼吁需要更多具备“混合”技能的人才，涵盖 IT 和业务的其他方面（Dixon and John [1989](#reference.xhtml#ref_r66)），或呼吁“全面发展”的管理者，能够自如应对 IT 引发的更广泛战略问题（Meiklejohn [1989](#reference.xhtml#ref_r168)）。人们对组织应如何塑造和管理以有效利用信息系统给予了很大关注，例如 Keen（[1991](#reference.xhtml#ref_r136)）和 Scott Morton（[1991](#reference.xhtml#ref_r207)）。

对于大多数组织而言，今天这些问题仍然是高级管理层的关注重点。在关于信息系统管理的更广泛讨论中，信息系统安全与控制问题已成为日益常见的主题。特别是，安全与控制的三个方面经常浮现出来。

* *安全与控制不再是中央技术人员的专属，甚至也不是其主要职责*。在即用型软件包和“即插即用”硬件的世界里，每个人都可以成为“自己动手”的系统构建者。这种新型的 DIY 爱好者主要关心的是让系统运行起来，并不一定会过多关注安全性和完整性问题。因此，可能无意中创造了新的漏洞。因为所有这些现在都可以在不涉及或咨询中央 IT 部门的情况下发生，一个有用的安全网被移除了。过去本会被中央经验丰富的技术人员识别出的威胁现在却未被察觉。

因此，组织不得不更加主动地监控新信息系统是如何以及在何处引入的。这有时导致 IT 部门的权力得到恢复，特别是在跟踪整个组织中安装的 IT 设备以及执行对常用打包软件的标准的方面。

* *安全与控制问题跨越了正常的分界线*。这些问题可能无法 neatly 归入正常的部门边界，例如，A 部门的用户可能希望被允许访问由 B 部门维护的某些数据文件。这将需要*双方*部门共同商定适当的<|message|> 安全措施。如果各个部门都在运行自己的自主系统，对此类跨界安排的需求是不可避免的。如果跨链接的需求只是偶尔发生，可能很容易友好且安全地解决，但如果考虑更大规模的数据交换，安全与控制可能会纠缠于围绕信息地位和所有权而产生的更大政治问题。Davenport（[1994](#reference.xhtml#ref_r60)）简洁地指出：“如果信息就是权力和金钱，人们就不会轻易分享它”。

* *安全与控制的成本和收益分配不均*。几乎没有安全措施是零成本的。即使灌输“良好实践”也需要培训，一个可能的结果是员工必须在处理每笔交易上花费额外的时间。不幸的是，安全成本可能特别沉重地落在某些部门，例如负责大量数据录入的部门，或经常与客户打交道的部门。与此同时，收益通常不会归于该部门，而是归于整个组织。在许多情况下，收益无论如何都将 largely 不可见，至少对于那些承受所有额外压力和开销的人来说是如此。所有这些都加剧了政治紧张，特别是在对高标准安全与控制的要求从组织高层下达，而让各个部门自行寻找实施资源的情况下。

由于所有这些原因，很少有管理者能够避免在某个时候被卷入关于信息应如何被控制、审查或存储的讨论。要找到可行的解决方案，他们需要考虑的不仅是信息系统的安全相关方面，还需要考虑关于系统目的的更一般性问题，以及它们与组织目标的契合程度如何。如果系统提供的功能与组织为自己设定的业务目标之间存在良好匹配，建立良好控制将容易得多。相反，对系统没有被认为特别有用，或其运行方式“与众不同”的系统施加和实施控制可能极其困难。

## 3.3 使控制系统与组织的结构和文化相匹配

信息系统应如何量身定制以满足其所服务的组织的需求？这个问题已受到大量研究和分析。一般认为，在某种意义上，IT 与业务之间必须存在良好的 *fit* 或 *alignment*。Raymond *et al*（[1995](#reference.xhtml#ref_r195)）已表明，正确实现对齐存在业务激励，因为企业随后可以预期在财务和其他指标方面取得更好的成果。然而，关于如何实现良好对齐，甚至如何判断是否已实现，存在不同的观点。

例如，McKersie 和 Walton（[1991](#reference.xhtml#ref_r165)）强调了实现对齐的不同方式：例如，组织是把技术拉入以对应其现有工作方式，还是调整部分工作实践以适应*围绕*技术？技术与组织“拉力”的概念已被 Burn（[1996](#reference.xhtml#ref_r43)）进一步发展为一个模型，他认为 IT 的引入可能在僵化和高度官僚化的组织中受阻，导致信息系统战略沦为“伪创新”。同样，一个在观念和工作方法上更灵活的组织仍可能受阻，因为它缺乏对 IT 潜在应用的真正愿景。Keen（[1993](#reference.xhtml#ref_r137)）认为最终目标应是 IT 被 *fused* 进入组织的情况。实现这种融合状态的组织会发现，每当它们计划和实施运营变更时，技术就会像其他任何问题一样成为议题，并被视为与他们所做的一切完全交织在一起。
