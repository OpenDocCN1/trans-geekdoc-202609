

### 一个或多个你的个人特征

理想的识别方法是不需要用户记住密码或携带令牌。相反，他们只需向计算机系统展示自己，并由其*固有*的某些方面进行识别。系统当然必须对所有可能的用户以及将被检查的特征有记录信息。

这种方法依赖于*生物特征识别*，即对人体的某些预定义且永久的识别特征进行测量。最常见的是这些测量基于声音、手或眼睛。其想法是用户应通过某种快速且自然的动作来识别，例如说出一句话，或将手放在扫描仪上。这消除了与分发和存储密码或令牌相关的许多问题。然而，生物特征方法仅在有限程度上被引入，因为：
* 生物特征识别依赖于对大量数据进行复杂的模式识别。因此运行身份检查需要大量的计算能力和数据存储容量。
* 建立生物特征检查系统往往更复杂。用户必须在受控条件下说出一些示例短语，或允许采集指纹。如果用户都是同一公司在同一建筑物工作的员工，这可能并不太困难，但对于银行客户等分散的用户来说则可行性要低得多。
* 系统与其他系统一样，必须进行调整以尽量减少误报和漏报。必须允许一定的误差范围。例如，如果使用语音识别，就不能期望人们总是以完全相同的方式说出短语，并且诸如嘶哑或胸部感染等状况会改变声音的某些特征。然而，在允许这种误差时，始终存在向[图 4.2](#ch4.xhtml#fig4_2)右侧移动过远并放进误报的危险。

决定生物特征应用的另一个关键因素是对用户而言该方法的可接受性。一种可能非常准确的识别人员的方法涉及使用激光束照向眼睛后部，以检查视网膜中血液毛细血管的图案。虽然这可以在不损伤眼睛的情况下完成，但许多人对接受视网膜扫描感到抗拒，部分原因是他们担心视力会受损，部分原因是盯着特殊传感器看很不自然。

因此，关注点转向了使用虹膜图案作为识别基础的可能性。虹膜位于眼睛外部，并且可以从远处扫描。最终，研究人员希望能够使计算机扫描一个人的面部，并以与人类大致相同的方式识别它。然而，如果机器要能够考虑不同的光照条件、面部角度、化妆的使用等，这将需要相当高的复杂性。

提供指纹进行检查的想法，如同视网膜扫描一样，可能会遇到一些抵制，因为在公众心目中，指纹与警察逮捕嫌疑人时遵循的程序有关。更可接受的替代方案是使用手部几何形状，手部放在平面上并测量其尺寸。还可以使用个人签名，以正常方式书写但在特殊敏感板上。在这种情况下，重要的是记录笔的运动模式，而不仅仅是签名的形状，否则该方法很容易通过传统的伪造而被滥用。

即使使用常规键盘也可以提供一些身份识别的线索，尽管这对于访问控制目的来说并不太实用。因为每个人在键盘上工作都会形成一定的风格和节奏，所以可以通过分析击键记录来识别用户。这在检查已登录的人是否确实是他们声称的人时很有用。

总之，以下方法可用于生物特征识别：
1. 被动测试（用户无需采取任何行动）：
    * 视网膜图案；
    * 虹膜图案；
    * 人脸识别；
2. 主动测试（用户必须以某种方式参与）：
    * 手部几何形状；
    * 指纹；
    * 语音模式；
    * 手写签名；
    * 击键模式

### 4.2.3 适用于所有识别方法的补充措施

无论使用何种识别方法（或方法组合），都可以应用某些措施来加强对用户 ID 滥用的保护。重点可以放在旨在*预防*的控制上，或*反馈*控制上，后者有助于在滥用发生后检测到它。

#### 预防
* *终端超时*。如果用户已登录，但一段设定的时间内未发生任何活动，系统将断开用户连接。这降低了其他人发现终端无人看管并阅读显示内容，或利用终端在无人看管时仍运行的访问权限的风险。类似的效果可以通过使用“屏幕保护程序”来实现，其工作原理大致相同：如果似乎没有人使用计算机，屏幕上的材料将被图案或图片替换，只有输入屏幕保护程序密码后才能移除。
* *访问与工作模式绑定*。通常员工只需要在正常工作时间或从自己工作区域的终端访问系统。如果是这样，系统可以设置为将访问限制为例如某个特定办公室的终端，周一至周五上午 8:00 至下午 6:00。

#### 反馈
* *有关先前登录的信息*。每当用户登录时，系统应回复一条消息，说明该用户 ID 上次使用的时间。这使用户可以检查日期和时间是否与其回忆或其正常工作模式一致。明显的问题示例是，如果系统声称该 ID 在周末凌晨办公室关闭时被使用。用户应立即提醒系统管理员该 ID 很可能已被泄露。
* *对 ID 使用情况的分析*。某些情况明显可疑，例如，如果同一 ID 在同一时间被用于两个不同地点的登录。可以使用分析软件浏览系统登录记录，突出显示任何不应该发生的情况。这种分析也可以在“实时”进行，使可疑登录在发生时被阻止或质询，从而将其从反馈型控制转变为预防型控制。

其他形式的反馈和预防性控制在[第 5.1 节](#ch5.xhtml#ch05_sa1)中讨论。

## 4.3 系统范围的访问控制

许多组织中发现的 IT 格局是多年添加、扩展和修改各种系统混合的结果。随着部门合并，或各自为政地进行 IT 采购，或因无法负担更换而勉强使用过时的软件，结果形成了一片凌乱的 IT 拼凑物。（唯一大家通常能达成一致的是，如果能重新开始，他们几乎肯定会做得不一样）。
