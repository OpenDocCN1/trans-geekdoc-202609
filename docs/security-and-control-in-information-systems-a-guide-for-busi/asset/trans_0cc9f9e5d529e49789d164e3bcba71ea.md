# 第四章 访问控制

DOI: [10.4324/9780203992319-7](https://dx.doi.org/10.4324/9780203992319-7)

## 4.1 引言

如果有人上门到你家并要求进入，你的即时反应就是实施访问控制。你首先会想核实该人的身份。你可能会认为谨慎的做法是透过窗户看一下，*在*开门*之前*确认是否认识来访者。如果是公务人员，你可能会要求查看身份证件，或对其进行盘问以判断其是否真实。一旦进入家中，你会期望对其行为施加一些限制。例如，想查看电表的人会被带到楼梯下的橱柜处，而不会被允许在屋内随意走动。另一方面，亲密的朋友则可能被信任可以随意走动。

信息系统中的访问控制也遵循同样的基本思路。[Figure 4.1](#ch4.xhtml#fig4_1) 是从本书引言中使用的图表（Figure I.3）发展而来的。请注意，即使用户*被*允许访问系统，也会对可使用的功能进行限制（图表中用勾号或叉号标记）。以这种方式强制执行的访问模式将为每个用户量身定制。

## 4.2 用户识别方法的特征

所有访问控制的起点都是对任何试图进入系统的人进行身份核查。由于这必须通过自动化手段完成，该过程通常比家门口的房主更为 impersonal（尽管扫描和识别人脸的技术现在已商业化）。之后，还可能启用其他类型的访问限制，这些将在本章后面描述。

至关重要的是，如果有人在起初就欺骗了系统，并冒充授权用户，后续的所有防线都将彻底失效。因此，不出所料，人们投入了大量精力来设计可靠且万无一失的核查方法，以验证声称有权访问系统的人的凭证。

### 4.2.1 身份核查系统的特征

一个良好的身份核查方法应具有以下特征。

* 不允许出现 *假阳性*。假阳性是指系统判定用户有权访问，而实际上并非如此。例如，黑客入侵系统的目的通常就是说服系统自己是授权用户，从而制造假阳性。
* 不允许出现 *假阴性*。假阴性是指授权用户被误认为是 *未*授权用户而被排除在系统之外。乍一看，这似乎不是什么大问题。如果授权用户偶尔被排除在外，可能被视为不幸，但至少安全没有被破坏。然而，用户往往对假阴性反应强烈，这也是需要考虑的众多人为因素之一（见下文）。
* 使用时必须不会耗时或繁琐。用户不想在系统判断其身份是否真实时被长时间等待，也不愿接受冗长的提问或测试。他们真正感兴趣的只是开始在计算机系统上工作。
* 必须适合其所应用的工作站的类型和位置。对于便携式终端和 PC，以及位于正常办公环境之外的工位，例如工厂或仓库，或从家中拨号接入的人来说，这可能是一个特别的问题。

寻找最佳的身份核查方法必然涉及一定的妥协。如果筛查过于严格和苛刻，会让用户感到恼火，并增加假阴性的风险。如果过于宽松，用户可能会更舒适，但会增加放进冒名者的风险。

结果可以如 [Figure 4.2](#ch4.xhtml#fig4_2) 所示。如果一个组织决心将假阳性降到绝对最低，它会收紧控制并向图表左侧移动。这样做会冒着假阴性增加的风险。另一方面，如果组织对特别不愿得罪的人实施交易安全（例如取款机或家庭银行的客户），它可能担心假阴性会惹恼他们并失去客户。因此它会倾向于向图表右侧移动。在这种情况下，因偶发欺诈而产生的任何成本都可能被认为是为了良好的客户关系而值得接受。理想的访问方法将使曲线收敛于假阳性和假阴性均为零的点上。实际上，要接近这一理想而不投入非常高的费用是困难的（见 [section 4.7](#ch4.xhtml#ch04_sa7)）。

### 4.2.2 用户识别方法

用户识别方法可分为三大主要类型，基于：

* 你所知道的东西（密码）；
* 你所拥有的东西（令牌）；
* 你个人的一个或多个特征（生物特征）。

在实践中，这些方法常被组合使用。例如，要从取款机取款，你需要使用你所拥有的东西（卡）以及你所知道的东西（个人识别号码）。只要它们彼此独立，这种组合就比每种方法单独使用要强得多：例如，不应能从卡上打印的账号等信息推断出你的 PIN 码（当然，持卡人也绝不应将 PIN 码写在卡*上*）。如果我们将 [Figure 4.2](#ch4.xhtml#fig4_2) 应用于现金卡的使用，结果将类似于 [Figure 4.3](#ch4.xhtml#fig4_3)
