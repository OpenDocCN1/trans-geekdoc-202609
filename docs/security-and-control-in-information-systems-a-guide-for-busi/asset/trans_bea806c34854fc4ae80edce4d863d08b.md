

企业可能会发现，安全策略也因使用互联网交换 EDI 消息的做法日益普及而变得复杂。对于希望以低成本进入数据网络的小型和中型企业而言，这是一种越来越有吸引力的选择（Tucker [1997](#reference.xhtml#ref_r225)）。为了确保 EDI 消息在保持其特殊布局的同时送达，它会被“包裹”在电子邮件消息中，使用 SMTP 的特殊 MIME 扩展（其中 MIME 代表多用途互联网邮件扩展）。这使企业能够获得 EDI 的好处（例如，避免将详细信息重新输入其会计系统），同时也能利用互联网的廉价性和连通性。

## 7.6 与公众交易：电子商务

EDI 现在已证明对许多企业不可或缺，并已成为商业环境中被接受的一部分。大多数 EDI 交易都是在彼此知根知底的成熟组织之间进行的。除了能够通过公共注册和目录识别彼此外，各方通常会在安排开始时签署某种正式协议，以确定在 EDI 交易出现问题时各自的责任和义务。

另一方面，互联网商业发展的浪潮则集中在直接向消费者销售。在这种情况下，销售交易可能是双方之间第一次（也可能是唯一一次）接触。供应商希望从互联网获得两大关键优势。首先，它是一种廉价的销售媒介，全天候运行，可覆盖全球客户。其次，客户能够迅速做出并确认购买决定。因此，供应商对那些似乎威胁到这两大优势的安全措施持谨慎态度。例如，如果需要额外步骤来核实客户的资质，或付款方式过于繁琐，在线购物的吸引力就会开始消失。

事实上，若干因素需要有利地结合，互联网销售才具有商业可行性，而且在世界不同地区情况各异。例如，在拉丁美洲，消费者对在线支付系统特别不信任。这源于服务水平不佳的经历，以及企业对咨询和投诉普遍缺乏响应。信用卡服务也备受诟病，因为它们传统上不愿在出现问题时给予客户任何赔偿，例如信用卡被欺诈性使用或货物未送达。除了要与这种不利的舆论环境作斗争外，有意涉足网络交易的企业还必须克服一些技术障碍，因为电信服务昂贵且并不总是可靠，而且互联网服务提供商往往收取高额费用（Davis [1999](#reference.xhtml#ref_r61)）。与此同时，在东南亚的部分地区，虽然已在电信基础设施上投入了大量资金，但互联网服务提供的发展却未必跟上步伐。因此，在印度，一些公司宁愿在美国设立网站，也不愿在本国设立（Chowdhary [1997](#reference.xhtml#ref_r52)）。

就控制和安全而言，互联网上出现的新型面向消费者的服务带来了三个特别的挑战：

* *建立买方和卖方的资质*。信任问题是*双向*的。客户一旦停止浏览在线目录并下订单，供应商就必须信任客户提出的付款方式。与此同时，客户必须相信供应商有意愿和能力交付所订购的商品。双方几乎没有什么可依据的，除了通过互联网传递的信息。
* *在速度与安全之间取得平衡*。通过互联网交易的巨大吸引力在于其即时性和响应性。为了实现这一点，安全程序必须在“实时”进行，交易仍在进行中。任何引入额外检查的尝试，例如补充电话或传真消息，都会破坏这种即时性，并随之带走互联网的大部分吸引力。事实上，甚至一些号称“即时”的交易安全方法也被供应商抵制，认为它们太慢（见下文对 SET 的讨论）。
* *小额交易*。从理论上讲，互联网应该是小额购买的理想媒介，特别是“数字”商品，如简短报告的文本或一段录制音乐。然而，传统的电子支付系统（如借记卡和信用卡）并不适合处理所涉及的小额资金。因此，人们正在寻找使电子支付变得容易的方法，适用于那种在传统购物之旅中会用零钱支付的小额金额。

第一个旨在解决上述至少部分问题的产品之一是 *Secure Socket Layer*（SSL）协议，它作为 Netscape 网络浏览器的功能引入。SSL 通过作为流行互联网浏览器的一部分免费提供，很快确立了事实上的标准地位。自推出以来，它已得到进一步发展，版本 3 不仅提供消息加密，还能使用非对称加密密钥对发送方和接收方的身份进行认证。

随后微软推出了其 *Secure Channel Services* 产品，声称支持多种安全协议，包括 SSL。与此同时，*Secure Electronic Transaction*（SET）协议也在推出，得到了包括 IBM、VISA 和 Mastercard 在内的主要商业公司联盟的支持。所有这些产品都在应用层附近工作，如 [Figure 7.4](#ch7.xhtml#fig7_4) 所示。

所有这些产品都提供类似的设施。它们中任何一个最终成为主导标准在多大程度上，将在很大程度上取决于商业和政治因素，以及它们的技术优点。SET 是这些产品中最专业的，因为它专为在线信用卡交易而设计。乍一看，这似乎让它在主导电子商务的竞争中抢占先机。然而，并非每个人都热衷于看到信用卡成为互联网上占主导地位的支付方式。一些商业利益更希望使用替代方法，或许更独立于现有的银行系统。此外，SET 还必须与为其设计的商户和发卡机构的抵制作斗争。SET 的第一个障碍是，必须说服所有客户在其个人电脑上安装软件，为他们创建“电子钱包”。每个客户随后使用该软件生成一对非对称密钥，公钥由认证机构（通常是发行信用卡的银行）担保。这确保了客户的正确认证，但也增加了营销和启动成本。金融服务业内部也出现了不安，因为单个 SET 交易虽然安全，但处理时间可能过长，令人无法接受（Lambeth [1999](#reference.xhtml#ref_r149)）。
