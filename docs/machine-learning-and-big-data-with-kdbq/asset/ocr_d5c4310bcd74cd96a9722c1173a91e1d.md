Now let us suppose we want to append the following rows to the

```
morequotes : ([]) code:`$symbol$(); date:`$date$(); time:`$time$(); bidprice:
-- float$(); bidsize:`$short$(); askprice:`$float$(); asksize:`$short$();
-- mktflag:`$symbol$();
```

```
`morequotes; ([]) , (;
`(CM16, 2016.04.07; 15:23:21.147; 1241.2; 4h; `E);
`(CM16, 2016.04.07; 15:33:04.535; 1241.7; 17h; 1241.6; 2h; `E])
```

Naïvely, we attempt to run

+   - qt : morequotes;
- Q.dpft[mydb; 2016.04.07; `code`; `qt];
- delete from ;

On restarting the kdb+ instance (we have to do this because we replaced qt with
our temporary table; we wrote to qt image by the in-memory representation is ()
not updated)

```
C:\q\w32q "C:\data\mydb"
```

we find that we did not append to the 2016.04.07 partition of qt but replaced it:

| date code time | bidprice bidsize askprice asksize mktflag |
| 2016.04.07 CM16 | 15:23:21.147 1241.2 | 4 | 1241.3 | 1 | E |
| 2016.04.07 CM16 | 15:33:04.535 1241.7 | 17 | 1241.6 | 2 | E |
| 2016.04.08 CM16 | 10:53:00.002 40.83 | 6 | 40.83 | 66 | E |
| 2016.04.08 CM16 | 13:56:38.070 40.54 | 38 | 40.56 | 58 | E |
| 2016.04.08 CM16 | 15:20:02.000 40.77 | 26 | 40.79 | 44 | E |
| 2016.04.08 CM16 | 15:21:43.786 40.76 | 3 | 40.77 | 28 | E |

This exposes a limitation of Q.dpft: since it does not allow us to append to a-
partition but overwrites it, it requires the partition to be in memory for it to be
written to a table. For some large partitions this is infeasible: they them-
ply not fit in memory. To append to a partition de, we need a modified version of
- Q.dpft.

By looking into the terse of the k implementation of dpft in q we realise
file name to enumerate against (default is `sym). We attempt to add other parame-
ter to this function, o, which is the operation we wish to perform: upsert(o,);

```
k).quant.Q.dpftsAppend:[d;p;dft;t;s;o]
if[~&Q.qm*`.Q.enqs($d;sym); `.\:	'`unmappable];
{[d;t;o]@[d;o;t x][d].Q.par[p;t];r;o];[!r];
[@;d..;r#=f=r!]
[..xasc[f] d;f];*pm];
```
