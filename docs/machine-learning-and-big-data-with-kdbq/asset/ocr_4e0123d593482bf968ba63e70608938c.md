```
quantQ.io.appendSplayedTab:[tabPath;pvar;table;table2Add]
// tabPath -- path directory where to store the table
// pvar -- variable to sort and index on fast querying
// table -- name of the saved table
// table2Add -- table to append
:@;pvar*] pvar xasc (` sv (tabPath;`;table`)) upsert .Q[tabPath]
; table2Add;
```

The last variable is the name of the table passed into our function and thus is called without backtrack (in other words, it is not passed as a global variable reference). An example of using such a function is follows:

```
quantQ.appendSplayedTab[hsym $datadir,"/sdb`;code;`trades;newTrades]
```

Although we have demonstrated that two functions for saving a splayed table and appending more data to it, the two functions are almost identical apart the difference in use of set for the initial save vs upsert for the. Upsert will create a table if it does not exist and, therefore, encapsulate both operations and we can use quantQ.io.appendSplayedTab for both examples above.

# 6.4 PARTITIONED TABLES

In addition to splaying a table, we may partition it: for each distinct value v of a column defines the partition, a distinct directory will be created, where the binary files with serialised columns will be stored, including only those rows with value v in the partition column. The standard .Q.dpft function performs the partitioning. The name of that function stands for its four parameters: directory, partition, sort field, and table name. To store the trades table, we can execute the following code:

```
mydbir: hsym $datadir,"/mydb"
{
 `trd set select from trades where x=
 .Q.dpft[mydbir];x;code;`trd`;
 delete trd from `
} each distinct trades[`date]
```

We will call .Q.dpft once for each of the distinct values in the date table, resulting in the following calls:

```
Q.dpft[mydbir];2016.04.07;code;`trd1;
Q.dpft[mydbir];2016.04.08;code;`trd2;
Q.dpft[mydbir];2016.04.11;code;`trd3];
```
