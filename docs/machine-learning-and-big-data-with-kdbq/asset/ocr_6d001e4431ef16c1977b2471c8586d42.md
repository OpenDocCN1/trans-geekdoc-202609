This is yet another elegant implementation by q. Keeping things simple and generic, a primary key is simply a map (a 'partial function') of its primary keys to its values. It just happens that the primary keys and values are tables with the same length:

```
key kt
```

```

b
c
```

```
value kt
```

```

beta
gamma
```

Tables can have multiple columns, a keyed table with a composite key is merely a dictionary whose key is a table with more than one columns. For clarity, we should stick to the standard table definition syntax when declaring flat and keyed tables. However, knowing that a table is a flip of a dictionary and a keyed table is a dictionary itself, allow us to make full use of the power of q as we will next.

# 2.5 FROM A VECTOR LANGUAGE TO AN ALGEBRAIC LANGUAGE

Up to now, we have seen that q is a vector language. Its native functions apply to either a vector or a scalar. In the most recent sections we saw two new data structures which build upon vectors, the q dictionary and table. We just saw keyed tables are also dictionaries themselves. These data structures combine vectors and the concept of mapping give us a comprehensive set of data structures from which we can build mappings and a time-series database with the power of a functional language like q. In this section, we will see how the concepts we saw with vectors can be applied naturally on dictionaries and tables.

All the native operations around lookups, finding and indexing which we saw in Chapter 1 can be applied to dictionaries and tables, too. Recall table t:
