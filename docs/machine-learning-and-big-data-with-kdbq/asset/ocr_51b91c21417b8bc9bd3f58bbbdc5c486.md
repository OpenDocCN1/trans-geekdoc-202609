We attempt a window join by specifying `~` as a grouping column:

```
wjTabSym: wj[ window; `time`~sym;dataSet1;
  ( data2;
  ( count; `trade2`); ( avg; `trade2 ); ( .quantQ.join.asymmetry
  ; `trade2 ); ( ::; `trade2 ) ) ]
```

which gives you this error:

```
`type
[0] wjTabSym:wj[window;`time`~sym;dataSet1(dataSet2;count;`trade2`);(avg;
  trade2);.(quantQ.join.asymetry`trade2);(::;`trade2))

```

The correct query is:

```
wjTabSym: wj window; `time`~sym;dataSet1;
  ( data2;
  ( count; `trade2`); ( avg; `trade2 ); ( .quantQ.join.asymmetry
  ; `trade2 ); ( ::; `trade2 ) ); )
`time`trade1`~trade2count`trade2as`trade2list xcol wjTabSym
```

If we inspect the outcome, this construction does not provide the correct answer. The window join counts the case without any symbol. In the case with symbols, on the other hand, the join should be restricted to a subset of data.

The reason the window join does not work is in the fact that it should be used on the `psym` lookup table only. To obtain the correct join with symbols, we must first assign attributes to the symbol column. We create new variables for the sake of clarity:

```
dataSet: dataSet1;
dSet2: update `~psym` from `~sym` xasc dataSet2
window: 0 00:01:00 ~+: exec time from dataSet1
```
