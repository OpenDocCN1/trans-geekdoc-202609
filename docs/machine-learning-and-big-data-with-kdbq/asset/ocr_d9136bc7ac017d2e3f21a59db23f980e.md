# Debugging q Code

This will show us the full body of the function, which is useful for multi-statement functions, since we can then envisage the statement which failed and its place in the function body.

Evaluating the function by calling value on it presents us with a plethora of information, and we can parse this to create a dictionary of very useful debugging information:

```
`args_locals globals_constants name='path![x[1 2 3],enlist[4_-5x],2#=-4x]--value=[z.s]`
```

```
args | 'x y
locals | 'addmore
globals | 'z
constants | 50 | 3
name | "..wrongFunction"
path | "/path/to/my/code.q"
```

We add this function as a utility under our namespace in it comes handy later on. We pass in the function we want to inspect as an argument since we will need to pass in the self-reference of the failing function, and not of the utility function itself:

```
quantQ.debug.meta:[func]
// func function to inspect
:`args_locals globals_constants name='path![x[1 2 3],enlist[4_-5x],2#=-4x] value[func]`
;
```

Two other internal variables which get populated during the suspension of execution are:

+   - z.ex the failed operator
- z.ey its arguments

Note in our example above the failure is `+ z` the reference to the variable z itself, but if we replaced the failed code with something like `a + 3`, we would then see the failed primitive and its arguments are:

```
q).z.ex
+
q).z.ey
a
3
```

While debugging mode, we have three options to proceed with:

+   - ''
- '"
- \

The single-quote ' will move up the stack and into the scope of the parent function. The colon : will allow us to return an appropriate value from the current scope and resume execution, e.g. in the example above we can return :

```
q):2
```
