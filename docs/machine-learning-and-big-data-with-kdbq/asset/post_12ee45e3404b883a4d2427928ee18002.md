## 6.5 CONCLUSION

In this section we have shown how to save tables in disc: 3 ways:

- binary files: suitable for "small" (thousands up to a million records) tables with static data.
- played tables: suitable for "medium" size tables, or tables that are wide, i.e. have a large number of columns.
- partitioned tables: suitable for "large" time series tables which span multiple dates, months, or years. This is the main way to save "big data" tables, and we have shown how to save also append to these tables in a memory-efficient way.

One challenge that is found when starting to build huge sets with many partitioned tables is how to maintain them when for example have a schema change and we need to backfill a new column or change its datatype.

## CHAPTER 7 Joins

As we saw in Chapter 2, tables and dictionaries stand at the top of the datatype. The language offers different types of join functions, which allow us to combine the tables, or dictionaries, for example combining two time series, such as a table with market orders and a table with limit orders, which are frequently provided by exchanges as two different data sets. The analysis, however, requires to be equipped with the proper tools to do such operations smoothly and efficiently.

## 7.1 COMMA OPERATOR

We have already covered the join operator , Let us recall how it works on lists:

- a: 1 2 3 4;
- b: 5 6 7 8;

Comma-join can be used to join tables as well. This type of join is vanilla and puts restrictions on the tables to be joined. Let us illustrate the usage of unkeyed tables first. We define two tables of the same structure and join them with the comma operator:

```
t1 = ([]) a: 1 2 3; b: 10 20 30;
t2 = ([]) a: 4 5 6; b: 40 50 60;
t1,t2
```

```
a b
1 10
2 20
3 30
4 40
5 50
6 60
```

Since both of the tables are of the same type, the type of the output table is as expected:

```
meta t1,t2
```

| c | t | f | a |
| :--- | :--- | :--- | :--- |
| a | j | | b |

We now introduce another table which differs from table t2 in the type of column b:

```
t3 = ([]) a: 1 2 3; b: `10`20`30);
```

and join it with the table t1:

```
t1,t3
```

| a | b |
| :--- | :--- |
| 1 | 10 |
| 2 | 20 |
| 3 | 30 |
| 4 | 40 |
| 5 | 50 |
| 6 | 60 |

The output table is well defined; however, column b contains variables of mixed types – this can be seen from the type of column b:

```
meta t1,t3
```

| c | t | f | a |
| :--- | :--- | :--- | :--- |
| a | j | | b |

We need to be cautious here: mixing two different types is allowed since we can join two lists, comma-join simply appends different sets of lists to the end of the first table. This may cause issues later on, for example, to save the table to disk and getting a type error due to the mixed and unwanted nature of that column. In many cases, we do not expect the list to be mixed, and this may be due to a bug which went unnoticed. The upsert function is less forgiving:

```
t1 upsert t3
```

Type checks on a column ensure that they need to be conformant types and the operation above will return a type error. Therefore, advise caution on the usage of comma-join and prefer the safer upsert function.

## Joins

Both , upsert verbs work well on tables which have the same columns. If we define another table, t4, which has different structure compared to table t1, i.e. it does not matching columns, the join will fail:

```
t4 = ([]) a: 4 5 6; b: 40 50 60; c: 400 500 600)
t1,t4
```

The join fails, and the prompt shows that tables cannot be matched due to column mismatch. The same will happen with upsert. Both , and upsert verbs require a perfect match in the tables for which are to be joined. The same is true for keyed tables:

```
t5 = ([a: 4 5 6]; b: 40 50 60)
t1,t5
```

The key in the table, the comma operator works even when the tables are different. The comma operator works on keyed tables:

```
t6 = ([a: 4 5 6]; b: 40 50 60)
```

## DATA OPERATIONS

We note that , was accompanied by the each-both adverb, which makes the join work by row. The following command will fail due to the unequal length of the tables:

```
t1,'t7[ til 2 ]
```

```
'length
```

The join with each-both works even when the two tables have the same names of columns. In such case, the values on the right will replace the columns on the left:

```
t8 = ([]) c: 1 2 3; b: 1000 2000 3000)
t1,'t8
```

| a b c |
| :--- | :--- | :--- |
| 1 | 1000 | |
| 2 | 2000 | |
| 3 | 3000 | |

Finally, with-both adverb can be used on key tables as well. If two tables have the same column as a key, then a sideways join will work since we recall that key tables are dictionaries:

```
t9 = ([a: 1 2 3]; c: 1000 2000 3000);
` a xkey t1`,'t9
```

| a b c |
| :--- | :--- | :--- |
| 1 | 10 | 1000 |
| 2 | 20 | 2000 |
| 3 | 30 | 3000 |

and

```
` a xkey t1`,'2*t9
```

| a b c |
| :--- | :--- | :--- |
| 1 | 10 | 1000 |
| 2 | 20 | 2000 |
