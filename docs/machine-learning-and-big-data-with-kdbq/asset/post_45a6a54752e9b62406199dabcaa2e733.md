Let us run the LAR algorithm altogether. We need to first initialise the bucket with all the variables:

```qql
// set the step
step:0.0001;
// dependent variable
y:tabData first cols tabData;
// independent variables without constant
S:(),tabData1_cols tabData;
// create empty vector with beta
beta:(count flip tabData)-2)@0.0;
// vector in a given iteration
betaDir:(count flip tabData)-2)@0.0;
// used independent variables;
betaUsed:(count flip tabData)-2)@0b;
demanding y, return meanY
y-meanY=avg y;
// define residual variable
r:
// table with entire path
path:[] step:0;beta:enlist beta);
```

and combine all the individual variables into the dictionary:

```qql
bucket: ((`beta`betaUsed`betadir`y`xS`r`path`continue`step)!(beta,betaUsed;
--betadir;y;xS;r;path;step));
```

Having among the variables the flag continue, we can use iteration to run the algorithm until all the dependence in the data is exploited:

```qql
bucketExample:(quantQ.reg.oneStepLAR/)[[{continue}]];bucket;
```

## Linear Regression with Regularisation

The parameters are visually of the same magnitude as those obtained by the standard OLS. We can confirm it by calculating the $L_2$-distance to the true solution:

```qql
sqrt {x*x} each (1; -1.2;0.2;2)-raze (bucketExample[`beta`];meanY)
```

0.3113651

The result is improved compared to the one corresponding to the OLS case. For convenience, we create a table with the estimated path which will be indexed by the arcLength. This stands for the cumulative sum of bucket[`step`] performed during the iteration so far. We extract the extracts from the path table:

```qql
pathLAR: update beta1:`beta[0]`,beta2:`beta[1]`,beta3:`beta[2]` from
  bucketExample[`path`]; pathLAR;
```

then add the arcLength:

```qql
pathLAR: update arcLength: sums abs[deltas[beta1]]+abs[deltas[beta2]]+abs[
  deltas[beta3]] from pathLAR;
```

When we select a subset from the table, we get the full estimation path:

```qql
select arcLength, beta1, beta2, beta3 from pathLAR
```

At this point, we would like to encourage the reader to run the oneStepLAR function with large step and see how the estimation performs. A possible weakness of the oneStepLAR function is that there is no limit on the number of steps function can take. The function in the extreme case can run indefinitely. It is wise to amend the function such that there a a safety feature to prevent this case.

We wrap the algorithm into function. The function will have two arguments: table data, where the first column is the dependent variable, and the remaining columns capture the features in the linear relationship to be estimated. The second argument is the size of the step. To the normalisation, it are arcLength alalgorithm moves in every iteration:

```qql
// quant.reg.LAR:[tab;step]
// tab with data (y,xS)
// step the step of the LAR algorithm
// dependent variable - first column of tab
y:tab first cols tab;
// independent variables - remaining columns
xS:(),tab1_cols tab;
// create empty vector with beta
beta:((count flip tab)-1)*0.0;
// vector with beta in a given iteration
betaDir:((count flip tab)-1)*0.0;
// used independent variables
tailed:((count flip tab)-1)*0b;
// demeaning y. return meanY
y:y-mean=avg y;
// define residual variable
r:
// table with entire path
path:(step[0];beta:elist);
// define bucket
bucket: ((beta`betaUsedbetaDir;y`xS`path`continue`step)!(beta,
-> betaUsed;betaDir;y;xS;r;path;step);
// run the algorithm
bucketResult:(quant.reg.oneStepLAR/[x[continue]]);bucket);
// result is the re-arranged path
pathTab:bucketResult[path];
// create arcLength; add meanY, and individual and return table
// length of piecewise-linear coefficient profile
// amounts to summing the L1 norms of the changes in
// from step to step
// select arcLength: sum each delta beta, beta0:meanY from
-> pathTab);eval(pathTab);0b;{"beta", x each 1+count[xS]!(beta
->x) each count[x]));
```

Following the previous sections, we develop a function which tests the validity of regularisation on the out-of-sample data. The function performs the same regularisation as the LAR function using the in-sample data while the validity of the given regularisation is assessed using the RMSE on the out-of-sample part of the data. The outcome of the function is a table with a regularisation path, where each point of the path is assigned the RMSE value.

```qql
quant_reg_LAR(tab;step;inOutFlag)
// tab table with data, (y,x)
// step step of the LAR algorithm
// inOutFlag = atom/array to form in sample, i=out
// dependent variable - first column of tab
y: tab first cols of tab
// independent variables - remaining columns
x:(tab1_cols) cols;
whereMissing:=raze(where y!=0; raze (where x!=0) each x);
// remove the missing values
y:y[(tile count y) except whereMissing];
S:[:where whereMissing] S([tile count x) except whereMissing])
whereMissing:= each x;
// inOutFlag is atom, in sample is randomly chosen inOutFraction of sample
if(1<count(inOutFlag));
// split sample: OUT
xOUT:flip ceiling([inOutFlag+count y] flip x;
yOUT:ceiling([inOutFlag+count y] - y;
// split sample: IN
xS:flip ceiling([inOutFlag+count y])flip xS;
y:ceiling([inOutFlag+count y])wy
// inOutFlag is Boolean array with 1 being in/0 out
if([1<count[inOutFlag]]):
inOutFlag:inOutFlag([tile count inOutFlag]) except whereMissing);
```
