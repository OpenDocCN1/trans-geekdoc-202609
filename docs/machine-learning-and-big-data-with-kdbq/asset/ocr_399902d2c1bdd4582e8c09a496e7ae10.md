# 1.5 DIFFERENCE BETWEEN STRINGS AND SYMBOLS

In q, we have two types, the string and the symbol, which seemingly do the same job. Imagine we have a database, which contains a timestamp, price and also the name of the asset it belongs to, e.g. IBM, INTC, AAPL. We store the asset names as strings; however, we up having a large number of repeated values, which will be consuming memory. We prevent wasting memory by replacing the names by short integers, for example, and keep a separate lookup table to recover the map between short integers and names, in the form of a dictionary:

```
nameToShortMap(``IBM` `INTC` `AAPL`(`1 2 3`);
```

This is not a very convenient way to work with data and in particular to share our work with others. In order to avoid such troublesome approach, q uses the concept of symbols, which are internalised. Such strings are kept in memory only, i.e each distinct value is kept in memory only, and references to the original string are used internally. Under the surface, q maintains a pool of strings as symbols and every usage of symbol points to the value in this table.

The notion of symbols clearly suggests that we need to use strings repeatedly, symbols are the type of choice. As the pool of strings is maintained in memory, we should constrain the use of symbols with repeated values to avoid blowing up the memory. If we need unique and compiled names, we should stick to characters, i.e strings. Alternatively, if we need to use unique identifiers, like trade IDs, we should use the guide.

Another advantage of symbols is that the comparison is much faster we do not need to check every character, but merely the reference to that string. For instance, queries like

```
where name=`IBM`
```

```
where in=``IBM` `INTC`
```

significantly improve the speed and simplicity of evaluation compared to using character vectors.

# 1.5.1 Enumeration

The q language allows us to go one step further when working with symbols and create enumerates. This should be a familiar concept from other languages (q does contain various features we are used in “common” programming languages). The enumerated list of symbols form a new type — enumerations have a type range of short integers — restrict the values within the existing domain. Any changes to the new type in terms of appending or changing the values are restricted to the provided list.

Let us create an enumerated list out of our three names of assets used above:

```
assetNames=``IBM` `INTC` `AAPL`;
```
