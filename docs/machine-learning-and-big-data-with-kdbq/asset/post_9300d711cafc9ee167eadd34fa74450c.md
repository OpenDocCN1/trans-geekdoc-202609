## 22.3 M-class Classification

The second example involves testing the M-classification, where the dependent variable can take M values. We test our implementation on Fisher's Iris data. recall the meaning of the variables in the data:

- Feature 1: sepal length in cm
- Feature 2: sepal width in cm
- Feature 3: petal length in cm
- Feature 4: petal width in cm
- Dependent variable: class: Iris Setosa, Iris Versicolor, and Iris Virginica

The data has 150 rows. We assume we have the data on the local drive (in root). First, we load the data:

```
irisData:("irisData.csv")
```

and verify the structure of the table with all the names of variables:

| meta IrisData c | t | a |
|---|---|---|---|
| sepalLength | f | | |
| sepalWidth | f | | |
| petalLength | f | | |
| petalWidth | f | | |
| class | s | | |

Further, we split the data set into a training sample with 100 observations, and test sample with 50 observations. Since the data set itself can be sorted based the class, we do the random split of the data:

```
randomDraw100:count irisData;irisDataIN: select from irisData where i in randomDraw100;irisDataOUT: select from irisData where not i in randomDraw100;
```

We verify that all three classes are represented in the training sample:

```
distinctClass:distinct irisDataIN`class;
```

- Iris-setosa
- Iris-versicolor
- Iris-virginica

We train the model using 8 neurons in the hidden layer with learning rate parameter 0.01 and run the algorithm for 1000 steps. We monitor the convergence of the algorithm:

```
modelB:quantQ.nn.modelNN[(flip (irisDataIN`allWidth;irisDataIN`length;irisDataIN`sepalWidth;irisDataIN`length;irisDataIN`petalWidth);quantQ.nn.encoderMulti[distinctClass] irisDataIN`class;8;count;0.01;1;multiClassifier];
```

Figure 22.2 depicts the error during the learning process of the neural network for the iris data set. The learning pattern shows complex episodes during the iterations.

![](img/97f7581128bd0bdf85683d4c69d94242_479_0.png)

FIGURE 22.2 Learning path (errors) for M-class classification of the Iris data set

The improvement is somewhat volatile and shows a brief burst when the error gets worse the overall improvement is apparent. During the final stages of the learning process, the error oscillates around two values, both representing improvement. This suggests that the algorithm cannot rest in the optimum but slightly oscillates around it. This could be prevented by having the learning rate decreasing during the last stages of the iteration process.

The data have been extracted as:

```
select Counter, Error from modelB where i>0
```

Further, we extract model parameters at the training process:

```
pHid2Out: exec last parsHid2Out from modelB;
pIn2HidB: exec last parsIn2Hid from modelB;
```

We arrange the out-sample data into a new table tabB, and add an encoded dependent variable:

```
tabB:update classEnc: ..quantQ.nn.encoderMulti[distinctClass] class from irisDataOUT;
```

Then, we predict the class of the iris using the trained model. The prediction is done by stacking the network:

```
tabB: update classEncPredict: ..quantQ.nn.funcNN['multiClassifier'][(1.0.,;
	quantQ.nn.sigmoid(1.0, 'Flip'(irisDataOUTlength,irisDataOUTsepalWidth,irisDataOUTpetalLength,irisDataOUTpetalWidth))]
mmu pHid2OutB from tabB;
```

The predicted classEncPredict is an encoded array of three values, where each value represents probability that given our observation is a class of the given class with highest probability wins. We can then check the accuracy of our prediction model as:

```
exec sum {(where y=max y)(where x=max x)}[classEncPredict;classEnc] from
tabB
```

enlist 47

The model predicts 47 out of 50 cases, 94% accuracy. Let us further inspect the table itself; we view 10 rows for illustration:
