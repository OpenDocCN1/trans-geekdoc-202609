# Joins

Both , upsert verbs work well on tables which have the same columns. If we define another table, t4, which has different structure compared to table t1, i.e. it does not matching columns, the join will fail:

```
t4: ([]) a: 4 5 6; b: 40 50 60; c: 400 500 600)
t1,t4
```

The join fails, and the prompt shows that tables cannot be matched due to column mismatch. The same will happen with upsert. Both , and upsert verbs require a perfect match in the tables for which are to be joined. The same is true for keyed tables:

```
t5: ([a: 4 5 6]; b: 40 50 60)
t1,t5
```

The key in one of the tables is causing the type error as keyed and unkeyed tables are different types. We can, however, use the comma operator on two keyed tables:

```
t6: ([a: 4 5]; b: 40 50)
t5,t6
```

| a | b |
|---||
| 1 | 10 |
| 2 | 20 |
| 3 | 30 |
| 4 | 40 |
| 5 | 50 |

The join operator correctly joins two keyed tables and will also check for types when the tables are keyed:

```
`a xkey t1`,`a xkey t3
```

Note xkey function explicit column names (or an empty list for no keys) a key table based on the argument on the left. The comma-join operator can also be used to join tables sideways:

```
t7: ([c: 100 200 300; d: 1000 2000 3000)
t1,t7
```

| a | b | c | d |
|---|---|---|---|
| 1 | 10 | 100 | 1000 |
| 2 | 20 | 200 | 2000 |
| 3 | 30 | 300 | 3000 |
