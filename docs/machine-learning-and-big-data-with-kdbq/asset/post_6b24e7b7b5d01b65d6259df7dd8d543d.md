The points identified as outliers lie in the same region; more points are identified, though, for a more strict threshold.

The number of examples presented here suggests that choosing the hyperparameters of the local outlier factors, the size of the neighbourhood and the threshold, is a matter of art. They require fine-tuning, possibly on the in-sample, where we are aware of the true outliers. The selected outliers are aimed to be investigated by some detail, and likely costly, methods or procedures. Good intuition if one needs to use the provided method in production applications, where the algorithm will entirely rely on the outcome of the technique.

The selected method has been illustrated for a few numbers of hyper-parameters as space provided not allow for more. We encourage the reader to go through more hyper-parameter settings. The features to look for are the number of the identified outliers as a function of the threshold and the size of the neighbourhood.

# Simulating Asset Prices

In this chapter, we provide a framework to simulate multivariate volatility process with jumps. We build the framework step by step, and wherever we need to introduce new functions, we build them on the fly. This chapter is motivated by Novotny and Urga (2017). The paper provides a test for co-jumps in asset prices. One section of the paper is a simulation exercise to assess the size and power of tests. In order to do that, we need to simulate a realistic price generating process. The choice was made for stochastic volatility process with price jumps in both the price and volatility. This chapter illustrates that can be naturally used for academic research as well.

## 18.1 STOCHASTIC VOLATILITY PROCESS WITH PRICE JUMPS

We start with a simulation of Stochastic Volatility Model with intraday pattern and price jumps both in the volatility process and price process, proposed by Andersen et al. (2012). The price generating process is defined by the following equations:

```
$d\log F_t^{(i)} = \mu_t^{(i)} dW_t^{(i)} + U_t^{(i)} dJ_t^{(i)}$
$d\sigma_t^{(i)} = \kappa^{(i)}(\bar{\sigma}^{(i)} - \sigma_t^{(i)})dt + \omega^{(i)} dB_t^{(i)} + U_{t,\sigma}^{(i)} dJ_t^{(i)}$
$E[dW_t^{(i)} dB_t^{(i)}] = \rho^{(i)} dt$
$E[dW_t^{(i)} dB_t^{(j)}] = 0, i \neq j$
$E[dW_t^{(i)} dW_t^{(i)}] = \rho^{(i)} dt$
```

where $i = 1, \dots, N$, and

```
$u_t = c_t + c_{open} \exp(-a_{open}(t - t_{open})) + c_{close}\exp(-a_{close}(t - t_{close}))$
```

where $t$ denotes the time in the trading day, $t_{open}$ is the opening time, and $t_{close}$ is the closing time. The model contains a large number of parameters which have to be set according to the underlying process which to be simulated. In order to get specific numbers, we employ the calibration used by Novotny and Urga (2017) with $N=3$ based on Eraker (2004) and Lee (2011). In particular, the intra-day pattern is set as $c_{open} = 0.75, c_{close} = 0.25, a_{open} = 10,$ and $a_{close} = 10$. This ensures that the portfolio has $N$ assets of the same type. The parameters are normalised to $T=1$ day. 

The magnitude of the jump $U_{P,j}^{(i)}$ is set relative to the prevailing level of stochastic volatility as $U_{P,j}^{(i)} = u_j \sigma^{(i)}$, where $\sigma^{(i)}$ is the volatility immediately before the jump occurs, and $u_j$ is the parameter common to all assets, for which we consider $u_1=4, u_2=8,$ and $u_3=12$, respectively. The magnitude of the jumps $U_a^{(i)}$ follows every exponential distribution with mean $\mu_{\zeta}=0.0167$. For every asset $i$, we assume that $U_a^{(i)}$ is drawn independently of each other. For each asset $i$, the arrival process $dN_t^{(i)}$ and $dJ_t^{(i)}$ are assumed to be driven by the stochastic intensity $d\Lambda_t^{(i)}$. In our setup, the price jump arrivals are drawn simultaneously. In the provided specification, we consider positive jumps only on the price jumps. In the case of volatility, the volatility spikes up when the price jump arrives and converges back to the long-term value via the mean-reverting property of the price process.

The data generating process is simulated at a 5-minute frequency; the first tick is at $t_{in}:09:00:00$ and the last tick at $t_{fin}:16:30:00$, with 90 minutes at each day. We further consider that the last tick of a day and the first tick of the following day are identical ticks. This excludes the accumulation of economic events overnight we encourage the reader to extend the provided model by adding overnight tick and explicit price jumps in the price process at the opening tick. Such a change allows us to test consecutive days more realistically.

The parameters are captured in the following dictionary:

```
stochVars: {'day':'tIn','fin':'tFin','open':'aOpen','close':'aClose','kappa':'kappaIn','thetaIn':'thetaIn','omegaIn':'omegaIn','sigmaIn':'sigmaIn,rho1,rho2,rho3,nu1,nu2,nu3,expDist':'09:00:00;16:30:00;0.75;0.25;10.0;10.0;0.0162;0.573;0.58:(neg 0.46);sqrt[0.573];0.2;0.2;0.2;4.0;8.0;0.2;1.25'}
```

Any change of parameters of the data generating process itself is done through the provided parameters dictionary. The parameters further contain some basic setup parameters like the initial and final time of the trading hours.

## 18.2 TOWARDS THE NUMERICAL EXAMPLE

We need to define several functions before we start generating the prices. We start with the intra-day volatility pattern function, which imposes a deterministic shape on the volatility during a trading day:

```
.quantQ.sim.stochVolIntraPat[time,isFlag;params]
// time time tick
// isFlag boolean flag
// params dictionary with parameters
// define intraday time
tintra=f"${j}$time-params['tIn'](1000-f"${j}$params['tFin']-params['tIn'])
// return intraday volatility pattern (point at given time)
$[isFlag=b;params[['copen']=exp[neg params['aopen']+tintra)]
+(params['cClose']+exp[params['aClose']*(1.0 - tintra))];
```
