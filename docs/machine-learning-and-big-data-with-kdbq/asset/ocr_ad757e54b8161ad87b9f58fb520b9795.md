We can see that the first value of dbidsize on the 2016.04.08 partition is incorrect. This requires adding the appropriate map-reduction k delta has been applied to each partition independently. The benefits of parallelisation are still here, yet the result is wrong.
A workaround for this is to add q's bootstrap file q.k to support the function we desire. Under the _ Q.* variables. A good way to do this is by overriding the values in our bootstrap script (or q.q) file, since q.k itself is part of the q distribution and changes from version to version. We leave this as an exercise for the reader.
Alternatively, we can compute the correct deltas in two memory inefficient - steps:

```
map: select bidsize by date from qt where=`CLM16`;
map
```

| date | bidsize |
|---|---|
| 2016.04.07 | 86 7 16 9 |
| 2016.04.08 | 6 38 26 |

```
reduce: select date, bidsize, dbidsize: deltas`from ungroup map;
reduce
```
