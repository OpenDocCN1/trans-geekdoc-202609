The Apriori algorithm is then operating with the binned feature, and the underlying correct numerical values do not play any role for the algorithm itself. We can now safely assume that our underlying features are of the integer type and the Apriori algorithm builds on the integer-valued features. We convert each integer-valued feature into a list of dummies, where for every possible value of the feature there is a separate binary variable. First, we need to create a function which goes over all possible values of a feature and create a dictionary with dummies:

```
.quantQ.apriori.makeDictionary::[[x]
/ x -- list of discrete unique variables
/ x!x:=x
;
;
```

The function works as follows:

```
.quantQ.apriori.makeDictionary[1 2 3]
```

```

```

We create a function which identifies in the underlying data table an i-th feature and creates another table with an additional set of dummy variables by using the function defined in the previous display. The function:

```
.quantQ.apriori.createDummies::[[largeTab,i]
// LargeTab -- table to convert
// index of variable to convert
// get all variables except the first one
listCols: largeTab,
// unique values of selected variable
distTMP: asc distinct largeTab[listCols[i]]
// create dictionary
dictTMP: quantQ.apriori.makeDictionary[distTMP]
// vector of values to convert
tabTMP: largeTab[listCols[i]]
// dummy variables
?:(largeTab);0b;(`raise string listCols[i],"_");string til count
-- distTMP!flip (dictTMP tabTMP]);
;
```

The index of the variable to be split into dummies is 0 as the function assumes the first column is an index variable. The outcome of the function is just a list of dummy columns for the given feature, named suffixes _0, _1, ... for every possible value.

Thus, we pre-process the table with an index and integer-valued features into dummy variables corresponding to every value of every variable. It is essential to admit that when the number of combinations of the features and its possible values is large, the wide table will be very wide, and thus memory-consuming. When data shows this type of behaviour, the Apriori algorithm may not be by its best construction to match the pattern in the data. Before we define the function corresponding to one iteration of the Apriori algorithm, we define a simple utility function checking whether one array is a subset of the other:

```
quantQ.apriori.isin:{xOUT,xTEST}
// xOUT -- unique list of values
// xTEST -- unique list of values to be compared
:count[xOUT]=sum sum xOUT\:xTEST;
;
```

Finally, we define one of the Apriori algorithm as a function which takes as an argument a dictionary with all important variables including the data itself in the wide dummy format, the outcome of the Apriori algorithm after a given iteration as temporary variables, and returns the updated dictionary.

```
.quantQ.apriorioneRun:([bParams])
// dictionary with all data and parameters
// increase counter
bParams['step']=1;
// create set of all combinations -- distinguish first step
$bParams['step1']=zz; distinct each 1_cols bParams['largeTabDummies]; zz:
  -> asc as t
  bParams['step']=count each t; distinct asct bParams[
  bParams['colDummiesStep1]];
// if step1: test whether zz does not have subset from
  colDummiesStepALL
$bParams['step1']=zz; first flip t each 1b=last t::[bParams]; (x;
  -> not max
  quantQ.apriori.isin([each bParams['colDummiesStepALL]])[bParams
  ]; each zz;
// numerical criteria
yy: flip([largeTabDummies]);
  <- sum prod largeTab[whr]largeTabDummies]; each zz;
// temporary variables -- split zz into two-sets
colDummiesStepMP: as each zz bParams['thresh]<(value first yy)
  -> last(yy)]count bParams['largeTabDummies];
colDummiesStepX: as each zz where not in colDummiesStepMP;
$bParams['step1']=1;bParams['colDummiesStep1]:colDummiesStepMP;
// populate bucket
bParams['colDummiesStepMP']=distinct colDummiesStepMP;
bParams['colDummiesStepALL']=distinct bParams['colDummiesStepALL];
bParams['colDummiesStepX']=distinct colDummiesStepX;
bParams['colDummiesStepMP']=distinct bParams['colDummiesStepX'];
// check if further improvement can be done$[count colDummiesStepMP,bParams['canImprove]];
// return bucket
:bParams;
```

# Unsupervised Machine Learning: The Apriori Algorithm

The function reflects the description of Apriori algorithm as above. At every step, the local variable zz is created with all possible and allowed combinations of features to explore at a given iteration. It explicitly checks whether the newly formed candidate does contain sub-elements which have been rejected. The combinations are then tested to be frequent enough – above the threshold – and combinations that are frequent enough are preserved.

The entire algorithm is then run as a sequence of one-step functions. Let us illustrate the function on the set of data. We first create the table with 100 observations, which are already indexed and all features are appropriately named and being of the type.
