# 2.4 KEYED TABLES ARE DICTIONARIES

We just saw that tables and dictionaries are in essence the same thing under the hood, which is very efficient as well as plain handy. They appear to be different to allow us to work with both tables and maps as separate entities and have different data types.
We will now attempt to create a new construct, using both tables and dictionaries. One may ask: What would happen if we created a map to another table? Let us try it:

```
kt:([sym:`a`b`c`]) ! ([name:`alpha`beta`gamma])
```

| | name |
|---||
| a | alpha |
| b | beta |
| c | gamma |

This looks identical to the keyed table example we gave at the start of this chapter. It is:

```
(([sym:`a`b`c`)! ([name:`alpha`beta`gamma`)) ~ ([sym:`a`b`c`] name:`alpha`beta`gamma`])
```

```
b
```

```
keys kt
```

```
`sym
```

So a table with primary keys (aka a keyed table) is a dictionary. Not related to one, or almost identical to one like a flat table, but a bona fide dictionary. We know that we defined it to be one, but we can also confirm it once again:

```
type kt
```

99h
