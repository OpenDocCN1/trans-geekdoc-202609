The significance level used for testing individual hypotheses does not correspond to the significance level at the family level. If we want to impose the confidence level on the family level, we have adjust the confidence level for every individual hypothesis.

The important concept to define is the family-wise error rate, or FWER, which stands for the probability to make at least one error, or Type-I error, in the family of tests. Let us assume that the family contains $m$ individual tests. Further, each test is independent of the other tests. Then, the probability of observing at least one test to show the individual test is $\alpha_{individual}$; $\alpha_{family}$, is:

```
$\alpha_{family} = 1 - (1 - \alpha_{individual})^m. \quad (12.33)$
```

Let us illustrate numerically for $\alpha_{family} = 0.05$ and $m$ ranging from 1 to 100. Figure 12.6 depicts the dependence of the family-wise error rate, $\alpha_{family}$, along the individual error rate, $\alpha_{individual}$; Which is constant. As the size of the family progresses, the family-wise error rate is increasing and reaching towards 1.0. For a family of size 100, the probability of at least one test to fail is 0.9940795, which is a value very close to 1.0. Data for the figure has been generated as:

```
aIndividual:0;
[familySize:1+til100; alphaIndividual:100*aIndividual; alphaFamily:1-(exp((1-aIndividual))]; each i+til100)
```

In the case of individual tests to be perfectly correlated, we would observe:

$$\alpha_{family} = \alpha_{individual}. \quad (12.34)$$

irrespective of the size of the family $m$. If we cannot assume that tests are independent but not perfectly correlated, one often employs Boole's inequality (the union bound) – for any finite set of tests, the probability that at least one of the tests fails is no greater than the sum of the probabilities of the individual error rates:

$$\alpha_{family} \leq \alpha_{individual}. \quad (12.35)$$

In order to resolve the discrepancy between individual error rates and family-wise error rate, we present three possible solutions to resolve it. In every case below, we assume a family of $m$ tests, and null hypothesis being true for each of them. This is a weaker formulation of the problem. For every test, we measure statistics and obtain set of $p$-values, $p_i$, with $i = 1, \dots, m$.

### 12.3.8.1 Bonferroni Correction

The classical solution to family-wise error rate is a Bonferroni correction, introduced in Dunn (1958). The Bonferroni correction is defined as follows: we want to set the significance level for the family of tests as $\alpha_{family}$, we reject the individual test when $p_i$ satisfies:

$$p_i \leq \alpha_{Bonferroni} = \frac{\alpha_{family}}{m}. \quad (12.36)$$

for every $i$. We denote the corrected significance level at which we reject the null hypothesis as $\alpha_{Bonferroni}$. The Bonferroni correction is implemented as:

```
.quantQ.stats.pBonferroni:[alpha;m]
// alpha family-wise alpha
// m size of family
// return Bonferroni alpha
:alpha;
```

giving
.quantQ.stats.pBonferroni[0.05;100]

```
0.0005
```

### 12.3.8.2 Šidák's Correction

Popular alternative to Bonferroni correction is Šidák's correction, introduced in Šidák (1967). The correction is exact when all tests are statistically independent. When individual tests are positively correlated, the outcome is conservative, while for negatively correlated tests, the outcome is less stringent and may not perform well. Given that we want to set the significance level for the family of tests as $\alpha_{family}$, we reject the individual test when $p_i$ satisfies:

$p_i \le \alpha_{\text{Sidak}} = 1 - (1 - \alpha_{family})^m$,

for every $i$. It is implemented as:

```
quantQ.stats.pSidak:[[alpha;m]
// alpha -- family-wise alpha
// m -- size of family
// return Sidak algorithm
// 1-exp[(1-alpha);1.0%m];
```

giving

```
quantQ.stats.pSidak[.0.05;100]
0.0005128014
```

### 12.3.8.3 Holm Method

The Holm's method was introduced in Holm (1979) and provides an algorithm which ensures the family-wise error rate is $\alpha_{family}$. The method works as:

- Sort in ascending order the p-values of all individual hypotheses: $p_{(1)} \le p_{(2)} \le \dots \le p_{(m)}$. The set of indices $i_{(k)}$ orders the hypotheses accordingly, i.e. $H_{i_{(k)}}$ is the one with lowest p-value.
- For every index $i_k$, we define critical value $\alpha_k = \frac{\alpha_{family}}{m + 1 - k}$.
- Find the smallest index such that $p_{(k)} > \alpha_{(k)}$.
- Reject the hypotheses $H_{i_{(1)}}, \dots, H_{i_{(q)}}$. In addition, $H_{i_{(q)}}$ stands for no hypothesis to be rejected. To implement Holm's method, we need to provide an array of $m$ p-values and the family-wise confidence level $\alpha_{family}$. The implementation reads:

```
quantQ.stats.holm:[Array;alpha]
// alpha -- family-wise alpha
// pArray -- m-dimensional array of p-values
// return indices of hypothesis which are rejected
exec index from select (update alphaHol: alpha/(count[pArray]+1-i)) from pArray where pIndividual<=alphaHol);
```

Let us test the prescribed algorithm on two examples. The first example is composed of 100 random draws, where each draw is made from $U[0,0.1]$ corresponding to an individual p-value. The generic example is same but both are made from $U[0,0.05]$. The family-wise confidence level is chosen to be $\alpha = 0.05$. The first example gives:

```
.quantQ.stats.holm[100;0.1;0.05]
```

There is no hypothesis which would be rejected that family-wise confidence level is 0.05.

The second example gives:

```
.quantQ.stats.holm[100;0.01;0.05]
```
```
10, 49, 21, 3, 64, 78
```

There are seven hypotheses rejected altogether, that family-wise confidence level is 0.05. The underlying problem would be to find factors which are correlated with the dependent variable - see the problem at the beginning of this section - we identify seven factors, which are correlated with the dependent variable at 0.05 confidence level.

### 12.3.8.4 Example

Finally, let us illustrate the multiple testing on the following example, which constitutes a moderately large number of features and still shows that multiple testing has to be performed. We have 10 features and 1 dependent variable. We want to make pairwise testing to find out there is a potentially dependent link between the feature(s) and the variable we want to model. We collect 1000 data points in our sample and choose confidence level $\alpha = 0.05$. Further, the true data generation process does not have any link between features and the dependent variable. Thus, all detected dependencies are due to Type-I error. For the set of 10, we calculate $t$, and get the p-values for a two-sided test against the null hypothesis $\rho=0$. The question to answer whether there is a dependence between one or more features and the dependent variable. We perform 1000 realizations of the test.

In the first stage, we collect 1000 draws of size 10 containing the p-values of the individual tests:

```
pValues::x]
dataY:1000?1.0;
dataY:10 1000==1000?1.0;
.quantQ.stats.pValueTwoSided abs .quantQ.stats.tStatsCorr[count dataY]-each cor[dataY]; each dataY] each 1000;
```

For every realisation of the test, we check whether there is at least one case with p-value below or equal to the confidence level chosen, 0.05. We record the number of realizations when at least one of the features shows statistical dependence:

```
sum {0.05>=min} each pValues
```

In 41.3% of cases, we detect features which are significantly connected to the dependent variable. This is, likely we receive false results significantly many times than the significance level we would suggest. Ten features are far from what is usually perceived as a large number, and still, it may lead to a false conclusion quite! Let us repeat the test while making the Bonferroni correction:

```
sum {.quantQ.stats.pBonferroni[0.05;10]>=min} each pValues
```

leads to 15 cases, or 0.15% cases in relative terms when a significant feature has been identified. Sidak’s correction is performed anonymously:

```
sum {.quantQ.stats.pSidak[0.05;10]>=min} each pValues
```

and to the same number of cases when a significant feature has been observed. Finally, Holm’s method has a different functional form to apply, but is still very straightforward:

```
sum {<count .quantQ.holm[x;0.05]} each pValues
```

The number of cases where a significant feature has been detected is the same. The same results across the three methods is a consequence of our map between t-stats and the corresponding p-value. Our implementation through the lookup table is not granular enough to distinguish the nuances that are experienced in the current rate. Nevertheless, all three methods significantly suppress the Type-I error and lead to the correct conclusion more. We encourage readers to employ a more fine resolution of the map between t-statistic and p-values and thus confirm the difference between the methods. Finally, we encourage readers to explore other ways of applying the problem and observing different outcomes in the three methods.
