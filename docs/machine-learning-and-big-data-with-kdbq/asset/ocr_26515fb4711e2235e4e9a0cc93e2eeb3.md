Similarly to tradesdir/code, the file tradesdir/mktflag contains serial enumerated strings containing indices of the actual strings within tradesdir/sym. Each distinct text string, corresponding to each distinct symbol value, is stored in tradesdir/sym. Using the terminology from Java, symbols are interned.
The column comments, whose type is string (rather than symbol), was analysed by two files: tradesdir/comments and tradesdir/comments\. The latter, comments\ contains the actual text found in the strings. The serialisations of the enumerated symbol columns, where distinct values are stored only once, comments\ contains them. If you open this file in a binary viewer, you will see that "NEXYM/CME Group trade", for example, occurs multiple times. The terminology from Java, serialised strings are not intern, whereas serialised symbols are. The file tradesdir/comments indexes into tradesdir/comments\.
To load a played table from a directory, we can use:

```
load first vs tradesdir
```

This will assign the loaded table to the variable name that matches the directory, tradesdir. (In hindsight, we should have named the directory trades rather than tradesdir.)
Now here we did not directly use the value tradesdir to load the directory. When loading the played table, we must omit the final /. We do that by using the "vector from scalar" operator vs, which has a handy use of splitting the scalar filepath into the first part and the variable angle which we play the table.
Finally, we create two useful functions which will allow us to create and append the played table in the future. First, we start with the function to create a played table. The function needs three inputs: the path on where to store the file(s), the variable, and the table itself. The function is defined as:

```
.quantQ.io.savePlayedTab:[tabPath,pvar,table]
// tabPath -- path to store the table
// pvar -- variable to sort and index on fast querying
// table -- name of the table to save
@:[pvar;pm] pvar xasc ('sv {tabPath};table;')) set Q.en[tabPath]
// get table;
;
```

The single line of this function essentially carries out the following operations in order: access the global reference, enumerate the table, set it to disk and apply the parted attribute on pvar column after sorting the table by column.
To use this, we may run, for the following command:

```
.quantQ.io.savePlayedTab[hysm `$adir,"/sdb";code;`trades
```
