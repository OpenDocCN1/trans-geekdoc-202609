The weights in the table will be updated by the AdaBoost algorithm. Beside the table tab, we need to store the weak classifiers – the feature used and the corresponding threshold – as well as corresponding a's. We keep this information in the following table:

```
ada:(i:"j($); alpha:"f($);stump($));));
```

During the algorithm, new weak classifiers will be added one by one into the table. The complete model will be recovered from the table.

Further, we follow the procedure throughout this book and create a dictionary which will contain both tables. The AdaBoost algorithm will then produce the dict- and update it.

```
bucket:(`ada`!tab);
```

Before we implement the algorithm itself, we define the loss function, which is optimised when the weak classifier is being trained. The loss function in plain terms equals to the sum of weights for observations which are not correctly predicted. The function is implemented as follows:

```
.quantQ.ada.weightedError::[tab]; // table with data and current weights
// array of weights:sum tab[`weights`]
```

# MACHINE LEARNING

We have all the components need to implement one iteration of the AdaBoost algorithm outlined above. The function runAdaBoost takes as an input dictionary and identifies the weak classifier stumps and updates it into the existing model. On the way, we update the weights.

```
.quantQ.ada.runAdaBoost([{bucket} // dictionary with tab and ada
tab:ada]; // get names of features and the dependent variable
feature:first 10; // iterate through possible stumps and find the best one
if more than exists, choose randomly one
t:.quantQ.ada.weightedError[tab]: // error of the optimal stump
splitPoint.alpha of the AdaBoost
alpha:0.5*log(1-error) // correction to weights
corr2w:exp(-alpha)+tab; // update weights (corr2w)
ada:alpha; stump(err); // return bucket
```

It is worth making several comments. First explains how the feature for a given stump is chosen, namely we choose a feature randomly. This keeps randomness in the model. The apparent disadvantage is that our implementation of AdaBoost does not allow to use it as a feature selection technique, though the quality of technique is preserved. Given the given feature, the optimal stump is chosen by iterating through all the splitting points – which are the unique values of the feature – and chooses the one with least loss. Finally, all the variables are updated.

Let us use the set we have created so far and run AdaBoost with $L_{max} = 10$, i.e., to add 10 weak classifiers and their boosted committee. The procedure can be:

```
outBucket:quantQ.ada.runAdaBoost([10]);
```

The first ten observations are perfectly predicted. These observations are ones with a straight link between dependent and independent variables. The rest do not show any apparent pattern. Let us create the following table:

```
select i:i, sums isPredicted from quantQ.ada.runAdaBoost
```

which contains i, and the cumulative sum of isPredicted variable as a function of the index. Besides the straight improvement at the beginning of the sample, there are a few episodes where the algorithm picked up the dependent variable successfully. Due to the randomness in the data set, the results thus have to be interpreted carefully. On the end of the sample, the cumulative sum reaches a value of 38. The maximum possible value is 110 and value to 0 corresponds to no predictive power. In this case, the model is visually interpreted as predictive.

In order to understand the results, we finally implement the function which returns the series of useful statistics based on the contingency table. In particular, the function provides a dictionary with the following items:

- truePositive - number of correctly identified cases of y = 1.
- trueNegative - number of correctly identified cases of y = -1.
- falsePositive - number of incorrectly identified cases of y = 1.
- falseNegative - number of incorrectly identified cases of y = -1.
