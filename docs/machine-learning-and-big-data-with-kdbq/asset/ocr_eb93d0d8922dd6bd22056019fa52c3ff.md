The number of iterations is chosen based on available resources. The MCTS algo-

# 28.2.6 Remarks and Extensions

Let us make a couple of remarks about how to extend the MCTS presented above. First,
for some games value of every move/stone can be the number of the stones already
placed. In such a setup, we can control the number of simulations tremendously.
Gilly and Silver (2007) proposed an extension to the algorithm called Rapid Action
Value Estimation, or RAVE. This assumes that the value of a stone is independent of
the state of the game. Then, when we are supposed to update (wi, ni) for nodes contributing to the game, we update
moves across the entire game. if player 1 places a stone at, say, a center and
the game where it resulted in a win, we identify all possible games in the game
tree where player 1 places a move and update the pair (wi, ni) in all of them. How-
ever, it is more convenient to updating in the way as we have introduced
above and preferably adjust the formula for UCT as we will see below.

This extension boosts the statistics gathered by the MCTS. The disadvantage of this
approach is a strong assumption being made on the game. For the game of go,
this assumption is highly unfeasible, given the game to be driven by various patterns.
Further, players are introduced to the game through recognising patterns of varying
complexity. The same holds for the game of chess. Since the usage of the MCTS goes
well beyond the world of games, this is a possible extension. In order to mimic the abs-
lolute of the key assumption, the formula for UCT in the Selection step can be
amended to provide some flexibility:

```
$UCT_i = (1 - \beta) \frac{w_i}{n_i} + \beta \frac{w'_i}{n'_i} + C \cdot \sqrt{\frac{\log s_{parent}}{s_i}},\quad (28.20)$
```

where $w_i$ and $n_i$ are defined and populated as the original MCTS algorithm-
duced above, $w'_i$ and $n'_i$ are the total numbers of wins and the total number of games
containing this given move, i.e.

```
$w'_i = \sum_{nodes} w_i \quad (28.21)$
```

```
$n'_i = \sum_{nodes} n_i, \quad (28.22)$
```

with sum running over trees of which which are the same.
