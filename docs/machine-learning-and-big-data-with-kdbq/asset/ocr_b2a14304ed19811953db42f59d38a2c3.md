Let us illustrate several examples of how the functional select can be used as this is a powerful concept. If we want to turn the qSQL select query into its functional counterpart, we recommend to proceed as follows:

+   - Decompose the original query into the atomic parts. We can do that by building the query step by step.
- Apply parse function on the atomised elements. The parse tree of the simplified queries shows how the components of the full query are converted.
- There is no need to parse every function into the pure functional form. We can keep functions like xbar in its form instead of turning it into the k version. This makes the query more gotten and understandable.
- Since column names are parsed by reference as symbols, we need to be able make a distinction between referring to a column name or a symbol constant: we do this by using enlist on the symbol constants, as we will see in the example below.

The following examples functional queries. All the queries return 1b. We encourage readers to run them on their own and see what the output is.

```
?[tab;);();()] ~ select from tab
```

```
?[tab;((<;b;8);(>;a;b));0b)] ~ select from tab where a>b
```

```
?[tab;((<;b;8);(+;a;c));(>;a;b));0b)] ~ select from tab where a>b, b8
+C
```

```
?[tab;((within;b(1;6));(>;a;b));0b)] ~ select from tab where a>b, b
within (1;6)
```

```
?[tab;);();(enlist a!)!(enlist a)] ~ select a from tab
```

```
?[tab;);b;(enlist newA)!(enlist a)] ~ select newA:a from tab
```

```
?[tab;);0b;(enlist "newA")!(enlist a)] ~ select newA:a from tab
```
