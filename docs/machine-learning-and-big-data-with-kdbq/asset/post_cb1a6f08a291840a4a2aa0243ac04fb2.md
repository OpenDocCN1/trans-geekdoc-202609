# Exploration of first greedy algorithm

Let us implement the greedy algorithm where all the exploration is fully done at the beginning of the iterative process followed by greedy exploitation afterwards. Let us summarise all the variables using our setup:

```
epsilon:0.1;
N:1000;
K:3;
```

where we consider 1000 steps to be performed by the algorithm.

Let us introduce several further variables we need during the lifetime of the algorithm to be preserved across individual iterations: the realised pay-offs, minimum bound for any pay-off in the situation where the bandit’s arm has not been explored yet is to be exploited, the choice of iterations, series of strategies taken, and the multi-armed bandit function itself:

```
payoffs:Kw();
minBound:0.0;
counter:0;
strategy:();
mab::quantQ.mcts.MAB[(1.0;2.0;3.0)];
```

# Towards AI - Monte Carlo Tree Search

The function mabExplorationFirst takes as an input all the variables described above wrapped into a single dictionary, performs one iteration, and updates the same dictionary:

```
.quantQ.mcts.mabExplorationFirstGA:[bucket]
// bucket -- the dictionary with all parameters
$bucket[`counter`]=bucket[`epsilon`]+bucket[`N`];
[
  // decision randomly
  choice: first 1?bucket[`K`];
  [`strategy`]:choice;
  payoffs[`bucket`]:payoffs;
  payoffs[`choice`]:bucket[`max`] choice;
  bucket[`payoffs`]:payoffs
];
// exploitation
  // decision based on the best outcome
  avgReward:bucket[`minBound`]=avg each bucket[`payoffs`];
  choice: first where avgReward=max avgReward;
  bucket[`strategy`]:choice;
  payoffs[`bucket`]:payoffs;
  payoffs[`choice`]:bucket[`max`] choice;
  bucket[`payoffs`]:payoffs
];
// increase counter
bucket[`counter`]+=1;
  // return bucket
  :bucket;
];
```

The algorithm has two phases: the exploration phase and the exploitation phase. It is important to repeat that we allow the algorithm to choose the most optimal option during the exploitation phase. An alternative would be to fix the decision at the end of the exploitation stage and not allow any switch. This may lead to a sub-optimal solution for a small number of draws when suboptimal arm can be chosen during the exploration stage. We stick this into algorithm – and all the following algorithms – the option to choose the arm based on the most favorable expected outcome using up-to-date information. The algorithm learns even during the exploitation stage.

Let us create the dictionary of variables needed to execute the iterations:
bucket:(`N``K``epsilon``max``payoffs``strategy``counter``minBound`!(N;K;epsilon;max;payoffs;strategy;counter;minBound`));

The greedy algorithm itself is the repetitive application of the function bucket[`N`] steps. Since we are interested in the outcome presented in every step of the iteration, we use \ instead of /. The greedy algorithm is applied as:

outcomeMAB1:(quantQ.mcts.mabExplorationFirstGA())[bucket[`N`];bucket];
