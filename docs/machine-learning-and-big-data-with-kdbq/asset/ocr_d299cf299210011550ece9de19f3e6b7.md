# 6.3 SPLAYED TABLES

Instead of saving the table as a single binary file, we could save splayed, i.e. so that each column is saved in a separate binary file. This is particularly useful for medium-sized tables (up to 100 million rows). Queries often refer – should refer in order to be optimised – a small subset of such a table's columns. Storing the columns in separate files allows kdb+ to save time by loading only of them. To achieve this, we would normally call set with a directory path, rather than a file as its argument. However, the following will fail with 'type:

```
hsm[`$datadir//tradesdir/` set trades
```

will disallow to play the table trades since it contains unenumerated columns of type symbol¹. We can remove those columns and save the table in one

```
hsm[`$datadir//tradesdir/` set mktflag _ trades
```

Notice the trailing "/ in the directory path. As a result of this, the tradesdir will be created under datadir. It will contain files with names .d, comments, comments\,date,time, and volume.

We couldn't save the original trades table because the columns of type symbol, namely code and mktflag.
We shall show how to enumerate them. Before proceeding, delete the directory trades with all its contents, in case you create that directory by following the steps outlined above, so we start with a clean slate. To enumerate the symbol columns in trades, we use .Q.en:

```
tradesdir: hsm `$datadir//tradesdir/;
tradesenum: .Q[tradesdir; trades];
```

This will create the directory tradesdir with a single binary file in it, named sym. That file enumerates the values found in the columns of type symbol, named `CLM16`, `VX16`, and `E`.
Once this is, we run

```
tradesdir set tradesenum
```

The directory now contains the files with .d, code, comments\, date, mktflag, price, sym, time, volume. Notice that this time, with the symbol columns enumerated, we were able to save the columns of type symbol successfully.
Note that, unlike the command,

```
tradesdir set trades
```

will fail with 'type', as before.

> ¹The same error would be thrown if the table were keyed. We would need to remove the key with () xkey trades before saving the table.
