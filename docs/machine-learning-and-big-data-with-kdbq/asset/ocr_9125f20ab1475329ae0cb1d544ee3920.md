Further, to enhance the speed of retrieve over the large tables, it is recommended that for the in-memory lookup table the symbol sym is grouped, i.e.`gs#, and within the sym, the time index should be sorted. On the other hand, for on-disk tables, the symbol sym should be partitioned with `p# and the time index should be sorted within the sym. The virtual partitions should be fully avoided.

# 7.2.8 aj0

This is a modified version of aj, which replaces the time index column from the table on the right. If we change the tables at3 and at4 such that the time indices in both of them do not overlap:

```
at5: update t:+0.1 from at3;
at6: update "f$ from at4;
```

and aj returns the time index taken from at5:

```
aj[`symt`; at5; at6`
t sym a b
------
0.1 a 10
5.1 a 20 500
7.1 a 30 700
1.1 b 40 10000
5.1 b 50 50000
6.1 b 60 60000
```

whereas, aj0 gives the actual times from the look-up table:

```
aj0[`symt`; at5; at6`
t sym a b
------
0.1 a 10
5 a 20 500
7 a 30 700
1 b 40 10000
5 b 50 50000
6 b 60 60000
```

The exception is the first row, which corresponds to the case where no “last valid” observation was found and thus the time from table at5 was used.
