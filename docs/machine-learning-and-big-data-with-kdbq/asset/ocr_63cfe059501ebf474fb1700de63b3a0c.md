# 156 DATA OPERATIONS

In order to calculate the average, q will first apply a partial sum operation for each date partition and count the number of elements in each date. By running function avg, q recognises that this operation is run over a partitioned table and employs the map-reduce paradigm. This means that the average is calculated in two steps. First, the number of elements and sum of values for each date is obtained and recorded (map). Then, the sum of sums is divided by the sum of counts (reduce) and the average is returned.

Semantically, the above query can be approximated as follows:

```
map: select cnt: sum null .5 * bidprice + askprice, avgSpread: sum .5
~ * bidprice + askprice
by date from qt where in 2016.04.07 2016.04.07
reduce: select avgSpread: sum[avgSpread ] % sum cnt from map
```

This optimisation is done automatically in the first query and has two benefits:

+   * Memory: it is more efficient since each on-disk partition directory is reduced to a single number, instead of reading all values for all dates into memory first and averaging - the latter being memory inefficient.
* CPU: the above operation is independent for each directory and therefore multiple dates can be mapped in parallel using slaves. q will automatically detect when a query spanning multiple dates is run, and slaves are specified.

Knowledge of the above also motivates us to have a well-thought-partitioning scheme which suits our data needs.

We find that functions have built-in map reduce implemented: count, avg, cor, scor, var, sev, sdev, scov, first, last, max, min, prd, sum, wag, wsum and distinct. It is important to mention that q will only recognise these functions and apply map-reduce on them. Functions outside of this domain will return the result applied individually to each date partition. As an example, observe this oddity:

```
last bidsize sum deltas bidsize from qt where code=`CLM16
```

```
bidsize bidsize1
```

```
3 12
```

We expect bidsize and bidsize1 to be the same number, since summing up the differences of a vector should give the last value of vector. However, removing the sum from the query reveals that map-reduce did not work exactly as expected, since (at the time of writing) deltas is not a function which is supported:

```
select date, bidsize, dbsize: delta bidsize from qt where code=`CLM16
```
