Notice the use of the global assignment : inside our function, since we want to update the global tables. Beside, we want to clean up cache to not contain updates which are not needed for our computation anymore. This is important since cache can rapidly grow in size and cause significant memory usage throughout the day.

This can be achieved by updating the trades tables to only keeping the last N ticks for each of the nested caches:

```
.quant0.upd.trades:{new
// new -- the incoming data sent by the upstream feedhandler or
// -- tickerplant, in table type format
// aggregate the new data by time,volume and price
// then insert each list to each column for each key (record) of the
global cache
trades:: select time,volume,price by sym from new;
// run a 3-tick moving vwap
ret: select sym, (-3*volume) wagq('-3*price') from trades;
trades:: update -3*time,-3*volume,-3*price from trades;
// ret:;
};
```

The advantage of storing incoming data in a single nested cache is that we can run a series of rules, looking at a variable window of data. Our cache can retain the history of observations only up to the maximum window required by our rules.
