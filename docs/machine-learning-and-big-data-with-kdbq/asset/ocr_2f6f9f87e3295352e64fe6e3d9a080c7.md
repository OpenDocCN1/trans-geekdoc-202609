# Splayed and Partitioned Tables

# 6.1 INTRODUCTION

Neither the kdb+ instance, nor the q code, live in isolation. In a kdb+tick setup, the data may be captured straight into a kdb+ instance. In other cases, we may obtain the data as flat files from an external source and choose to use q to process it. it is clear why we may make this choice: the database is an excellent environment for dealing with large volumes of data, more often than not, high-frequency data and q is a powerful tool for analysing this type of data.

q's efficiency extends to dealing with files: while we could use, for example, Python or R, to preprocess the flat files before exporting the data to a kdb+ instance, we will have to take a performance hit compared to kdb+ native methods for reading files. It is true that Python and R offer richer toolkits for dealing with system objects. But the simplicity and speed speak in favour of kdb+.

However, there are situations when we may still choose an external tool to process the data. We may choose to use Python's regular expressions and library functions. Alternatively, we may need to unzip or decompress the files before reading them from kdb+. We may need to call some shell commands. Luckily we can do this without leaving the kdb+ process; q offers us toolkits for calling shell commands and external programs from q scripts.

In this chapter we discuss kdb+'s concepts of splayed and partitioned tables and also show how to load and save data using q. Both types of data, especially partitioned tables, are useful for representing large data sets. Set data occurs in applications often referred to as big data. One of the areas where we encounter big data in high-frequency trading. Even if our goal is merely intraday, rather than high-frequency, chances are we still be dealing with input data captured at millisecond, or even higher frequency.

We shall use the trade in a futures contract. The value in the code column identifies that contract, the date and time columns give the dates and times of the trades as reported by the exchange, the price column contains the trade prices for contract and the volume column contains the number of contracts traded. The name of the column stands for 'market flag', which distinguishes the pit trades (in which case the value in the column is 'P') from the electronic trades (in which case the value is 'E').
