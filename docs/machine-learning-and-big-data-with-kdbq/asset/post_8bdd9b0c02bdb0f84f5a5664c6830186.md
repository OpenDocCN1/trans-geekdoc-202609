We attempt a window join by specifying sym as a grouping column:

```
wjTabSym: wj[ window; `time~sym; dataSet1;
  ( dataSet2;
  ( count; `trade2` ); ( avg; `trade2` ); .quantQ.join.as
  ; `trade2` ); ::; `trade2` ) ]
```

which gives you this error:

```
wjTabSym: wj[window;`time~sym; dataSet1(dataSet2;count;`trade2`);(avg;
  trade2);.(quantQ.join.as`trade2);
```

The correct query is:

```
wjTabSym: wj; `time~sym; dataSet1;
  ( dataSet2;
  ( count; `trade2` ); ( avg; `trade2` ); .quantQ.join.as
  ; `trade2` ); ::; `trade2` ) );
```

If we inspect the outcome, this construction does not provide the correct answer. The window join counts the case without any symbol. In the case with symbols, on the other hand, the join should be restricted to a subset of data.

The reason the window join does not work is in the fact that it should be used on the psym lookup table only. To obtain the correct join with symbols, we must first assign attributes to the symbol column. We create new variables for the sake of clarity:

```
dataSet: dataSet1;
dataSet2: update ~psym from ~sym dataSet2
window: 0 00:01:00 ~+: exec time from dataSet1
```

# 7.3 ADVANCED EXAMPLE: RUNNING TWAP

Let us illustrate the usage of joins with a running TWAP. A running TWAP is a function, which at every tick calculates a time-weighted average of a specified variable, usually price when calculating benchmarks or averaging out high-frequency fluctuations. The TWAP is a well-known execution strategy which targets the execution price equal or better to the time-weighted average over the execution window.

Let us proceed with definition of TWAP: The data consists of a series of: $x_{i-3}, x_{i-2}, x_{i-1}, x_i, x_{i+1}, x_{i+2}, x_{i+3}, \dots$ which are indexed by the time index $t_{i-3}, t_{i-2}, t_{i-1}, t_i, t_{i+1}, t_{i+2}, t_{i+3}, \dots$. Further, we specify the window $\Delta T$, over which the average is calculated. The TWAP is defined as:

$$TWAP_{i:\Delta T} = \sum_{j=1}^{\Delta T} \frac{(max(t_{i-j}, t_i) - max(t_{i-j-1}, t_i))}{\Delta T}$$

where the sum runs over all current and past observations, and the degree of max function is to ensure that average is taken over the observations with $t \in [t_i - \Delta T, t_i]$ with all observations outside the window having a zero weight in the sum.

The previous display provides a TWAP defined as point i among the observations. In order to calculate the TWAP of any time point, we can add a synthetic point into the time series. Such a point will have the time index intended to be the starting point of the TWAP and value equal to the last valid observation. This formulation is not general in a mathematical sense but fits well in our approach when dealing with data.

For a running TWAP we want to calculate the TWAP of every point in the time series. Given the time series $X_{i-1}, X_i, X_{i+1}...$ the time series $TWAP_{i-1:\Delta t}, TWAP_{i:\Delta t}, TWAP_{i+1:\Delta t}...$ is calculated. The implementation assumes that we are working with a table comprising the time index being some numeric format, and a list of values denoted as $x$. Let us generate data such as:

```
data:([[] time: asc "$t*-1000"23:55:59.999; val:neg[1.0]+2+1000(1.0)
```

We generated data uniformly fluctuating in the interval [-1,1]. This data has a zero mean, and time-weighted average over a long enough window converges towards the random mean. The average, in this case, will serve as a filter, which removes the random noise around zero.

Next, let us define the window over which we calculate the TWAP. We set it to 10 minutes: twinAP:00:10:00;

We first calculate the approximate TWAP by using a window as implemented in the following algorithm:

-   Aggregate the table using the window where:
  - Variable time: Apply deltas verb for each aggregated window while removing the first element of the list.
  - Variable val: Apply identity verb while removing the last element of the list.
  - Having the aggregated table, apply the wav on the two aggregated lists row by row to get the weighted average.
  - Report the output.
