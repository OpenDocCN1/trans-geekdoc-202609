# CHAPTER 1
Fundamentals of the q Programming Language

This chapter starts our journey to programming with q. It aims to equip the reader with the basic concepts and ideas needed to code in q. In the subsequent chapters, we will delve deeper into the detail of the language and its features. We will always consider their applications to practical tasks as the primary motivation for our book.

## 1.1 THE (NOT SO VERY) FIRST STEPS IN q

We start with the assumption that the reader already has a working installation of kdb+ on his or her computer. Hence the not so very in this section's title. If the reader is fortunate enough, kdb+ has already been installed by the system administrator. Otherwise, the best strategy is to follow the instructions under “Download” on http://kx.com/.

kdb+ is available for industry-standard 32- and 64-bit architectures (including AMD Opteron, Intel Xeon, and Sun) running Linux, Windows or Solaris. As of the time of writing, KX Systems offer a limited version of kdb+/ for non-commercial use. “Commercial use” is defined as any use for the user's or third party's financial gain or other economic benefits, whether this is production use or beta testing. Developing a proof-of-concept application, in a commercial setting, is not regarded as commercial use. The non-commercial version can also be used for academic research. It is fully suited for exploration of the language presented in this book. This book does not dwell on the nuances of running kdb+ on different architectures and operating systems.

The maximum amount of memory available for a 32-bit application is around 4 GB. This limits the applicability of the 32-bit version of kdb+. The 64-bit version can be used to implement large (multi-TB) in-memory databases that are common in high-frequency trading and big data applications.

To start kdb+, open your favourite shell, change the current directory to the one that contains kdb+ executable (usually named q or q exe), and launch that by typing in q. This executable is the q programming language interpreter – the face of the kdb+ system as seen by the user. By default, it is installed in one of the following directories:

```q
// main linux/mac directory with ~ being home
~/q
// linux executables
~/q/132
// mac executables
~/q/m32
// main windows directory
c:\
// windows executables
c:\\w32
```

For the 64-bit version, "32" in the path is replaced with "64". We recommend that the reader install kdb+ in the default directory. If this is not possible, one can customise the installation using the environment variables (QHOME, QINIT, etc.). In the sequel, we assume that kdb+ is installed in the default directory.

Once kdb+ is running, we will see the prompt

`q)`

This prompt indicates that the q interpreter is awaiting our first commands. From now on, we shall assume that we are always in an open q session and therefore shall omit the prompt (q) from our listings.

Let us experiment with the q language by typing in the expression

```q
1+1
```

We shall see the output

```
2
```

We have just evaluated our first q expression!

Any introduction to a programming language requires the presence of a "hello world" example. We create a script file, named helloWorld.q in the directory we have launched our q session. The file contains the following line:

```q
show "hello world!"
```

From the q session, we launch the script with system command \1:

```q
\1 helloWorld.q
```

produces the output:

```
"hello world!"
```

The system command \1 loads the file helloWorld.q, which applies the show function to its argument, the string "hello world!". The show function outputs its argument to the console.

To close the q session, we use the system command \q.

## 1.2 ATOMS AND LISTS

The most basic element of q is an atom, which can be an integer, a float, a character, a symbol, or a date. A list is a collection of atoms of the same type, or even atoms of different types. To find out the type of an object, we use the `type` function.

```q
type 1
type 1.5
type "a"
type `a
type 2023.01.01
```

The output is

```
2
6
4
9
8
```

The numbers correspond to the types: 2 for integer, 6 for float, 4 for character, 9 for symbol, and 8 for date. A list is denoted by square brackets `[]`.

```q
[1;2;3]
[1.5;2.5;3.5]
["a";b";c"]
```

The type of a list is 0.

```q
type [1;2;3]
0
```

An empty list is represented by `[]`.

```q
type []
0
```

The type of an empty list is also 0. We can explicitly cast an empty list to a different type using a type cast:

```q
type `short$[]
5
```

The type of an empty list cast to `short` is 5.

If we want to construct a list with only one element, we use the `enlist` function.

```q
enlist 1
[1]
```

The type of an enlisted list is still 0.

```q
type enlist 1
0
```

We can also find the type of each element in a list using the `each` adverb:

```q
type each [1;2;3]
2 2 2
```

The output shows the type of each element.

Mixed lists may also contain other lists as their elements:

```q
type [2;1;(1;2;3)]
0
```

The type of a nested list is still 0. We can use the `count` function to find the number of elements in a list.

```q
count [1;2;3]
3
count [2;1;(1;2;3)]
3
```
