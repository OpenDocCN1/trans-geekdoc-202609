# Splayed and Partitioned Tables

What's the matter? It turns out that, while trd has the partitions 2016.04.07. 2016.04.08, and 2016.04.11, qt had only 2016.04.07 and 2016.04.08. Each table in mydb has nearly exactly the same partitions. We remedy things by recreating quotes (by using Listing 6.1) and then storing quotes as qt

```
`qt select from quotes where date=x;
.0q dpt:/mydbdir;x; code; qt];
delete qt from :
each 2016.04.07 2016.04.08 2016.04.11`
```

On quitting kdb+ and then restarting with

```
`C:\w32> q "C:\data\mydb`
```

we see that now both trd and qt are present:

```
`date`sym`trd`
```

We can examine the tables by running

```
select from trd
```

and

```
select from qt
```

Check (by running \cd) the current directory is

```
C:\data\mydb`
```

Notice if we change it, say, with

```
`cd C:/q/w32`
```

our partitioned tables stop “working”:

```
select from trd
```

```
'./2016.04.07/trd/code: The system cannot find the path specified.'
```

Changing the current directory in the presence of partitioned tables wasn't a good move. We fix things by changing it back:

```
`cd C:/data/mydb`
```

Notice that two other variables are present in the restarted kdb+ instance: date, containing the list of the partitions:

```
2016.04.07 2016.04.08 2016.04.11
```

and sym, sym containing the list of enumerated symbols:

```
`CLM16`GCM16`VXK16`
```
