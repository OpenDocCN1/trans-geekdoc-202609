We further utilize the structure of the table tabDataMODEL. In particular, let us create a function which calculates the root-mean-squared error, or RMSE, between the true and the predicted values. The *RMSE* is defined as:

> $RMSE = \sqrt{\frac{1}{N}\sum_{i=1}^{N}(y_i - y_{predicted})^2}, \quad (13.70)$

where $y_i$ stands for the value of the dependent variable, $y_{predicted}$, and there are altogether $N$ observations.

The root-mean-squared error is a popular method to compare the predicted values to true ones. There is a number of alternatives in the literature, e.g., mean absolute error (MAE), which employs the sum of absolute values rather than the sum of squares and square root. The reason for this stems from the sensitivity of *RMSE* to outliers, which are amplified by the squares present in the equation.

The *RMSE* is implemented as a function, which assumes the first two columns in an input table are the relevant ones. In fact, due to the square and square root, the order of true and predicted variables does not matter. Further, the columns beyond the second one are not considered. The function reads

```python
quantols.RMSE[:tabModel] // table where first column is true dependent variable
-- second is estimated one
sqrt:tabModel[cols[:2]]
```

## DATA SCIENCE

The RMSE of results in tabData can then be obtained as:

```python
quantols.RMSE[tabData]
```

0.0982736

The value we have obtained is not saying much when it stands isolated. We need some anchor to judge the RMSE value and how the model performs out-of-sample. The possible application is to run estimation for two more sets, which will be independent variables included in the model. In order to do that, implement an estimation suite which takes three arguments: the dependent variable, the matrix of independent variables, and the flag which determines the in- and out-sample splitting:

```python
quantols.out:(y;x;inFlag)
 // array of dependent variables
 // array of independent variables, constants to be included
 // inFlag:1=out where y<=0; 0=in where x<=0
 // remove the missing values
y[(til count y) except whereMissing];
x[[:whereMissing]] x:(til count x) except whereMissing]]
 // inFlag is randomly chosen fraction of sample
if(1=count[inFlag]); // split: OUT
x:tabModel[inFlag+count y] - x;
y:tabModel[inFlag+count y] - y; // split: IN
x:tabModel[inFlag+count y] * x;
y:tabModel[inFlag+count y] = 0; // inFlag is Boolean array with 1 being In/0
if(1=count[inFlag]); // split: OUT
yPRED:sum[IN]*x; // output bucket
RMSE:avg:y-yPRED;
reg:Observations(count[y]);
x:flip[x] where inOut; // IN sample regression
IN:quantols.fit(y;x);
 // OUT sample
yPRED:sum[IN]*x;
RMSE:avg:y-yPRED;
```

The in and out sample splitting can be done in two ways: if the inFlag variable is a scalar value, which is between 0 and 1. Then it represents the proportion of the data which are taken in training sample. Using the time series approach, the out-of-sample data is conventionally taken as the most recent. Then, the out-of-sample data is remaining piece of the data.

On the other hand, we can specify which data to take as in-sample and to take out-of-sample. In that case, the inFlag variable is an array of boolean indicators, where true stands for being included in training, and false to be out-of-sample. The array is used in conditional evaluation, and thus 0 serves as false while non-zero values are considered as true. Let us show the result with 80% of the data and remaining 20% being the verification sample:

```python
reg1:quantols.inOut[tabData(`y`),tabData(`x1`,`x2`,`x3`const);0.8];
```
