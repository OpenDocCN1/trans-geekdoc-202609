
## Towards AI – Monte Carlo Tree Search

The state of the game is determined by the position of stones on the board, which is visible to both players. We can construct a game tree with all possible moves. Leaves of the tree are then the different ends of the game. Every node of the tree can be assigned a value which reflects the likelihood of ending up in a leaf node. The straightforward strategy to solve such a game is the minimax algorithm.

The minimax algorithm is a strategy for decision-making which is based on selecting an option which minimises the possible loss in a maximum loss scenario. The maximin is an analogous formulation for games. Since its development in the game theory for zero-sum games, it was extended to the situation with uncertainty and complex game rules. Mathematically, the minimax problem is formulated as:

```
$$$V_i^* = \max_{A_i} \min_{A_{-i}} V_i(A_i, A_{-i}) \quad (28.15)$$
```

$v_i$ is a value for a player $i$, and $A_{-i}$ denotes the action of player $i$ and the other player, respectively. In plain language, the player $i$ wants to play the best action given the other player is doing. To be precise, the player $-i$, i.e. not $i$, wants to minimise the value of the game for player $i$.

The minimax algorithm is frequently used backwards from the end of the game. In each iterative step, player $i$ wants to win while player $-i$ is the opposite. The backward iteration can be, and thus it is frequently accompanied by some heuristics. The heuristic rules assign a value to every state of the game. The minimax algorithm does not have to run iteratively but rather serves as a decision how to evolve from one state of the game to another.

The vanilla minimax algorithm as briefly outlined fails when:

- The number of different states in the game is huge. In the case of it, go is ~$3^{170}$
- The game has high branching ratio, where at every given state of the game, there is a large number of possible actions.

The MCTS addresses the shortcomings of the minimax algorithm. Namely:

- MCTS does not need complex heuristics, i.e. to estimate the value of any given state of the game. This can be difficult to achieve in complex games like go.
- MCTS is very good for games with a large branching factor. The nature of the algorithm is asymmetric; it explores the more promising branches. The search mechanism does not need to devote time to branches which are likely to lose in a loss.
- MCTS has a flexible running time. The heuristic-based algorithms need to go through the full tree with all the game options. This may take large amount of time. On the other hand, MCTS can be run in a flexible way and stopped at any time. The bigger the time budget to run can accrue the results of MCTS.

In order to introduce the MCTS algorithm, we need to elaborate more on the decision tree for a game. We consider a two-player game. The decision tree, or game tree, starts at the root node, which is a plain board. The next level of the tree is composed of child nodes of the root node, which contain all the possible moves by player 1. At the second level, the tree consists of all the moves of player 2 conditioned on the previous move of player 1. The third level, consecutively, captures the move of player 1 conditioned on the two previous moves. Switching the moves continue further down the tree by exploiting all combinations. The leaf node of such a game is a game where the game terminates and one of the players, or the game ends in a draw. In the go of game, the game ends when both players pass the move. Then, the player with the higher score wins, where the score is calculated based on the size of territory belonging to each player.

For a go of game, the root has 19x19 child nodes. At the second level, every node has 19x19 child nodes. This gives altogether at the second level (19 - 19) · (19 - 19) options. The branching ratio of the game is huge and suggests the in-numerical sense - dimension of all the possible states of the game. The tree is asymmetric as the difference in a number of moves between the longest and the shortest game can be huge.

When the game tree is not so huge, we can explore the full tree as we explained in the minimax algorithm in the preceding paragraphs. Given the knowledge of the full tree, the tree at every stage of the game can be optimised such that the chance to win is highest. This is not possible for games like go.

If we want to avoid the apparent cause of dimensionality, we have to abandon methods which rely on exploring the entire tree. The Monte Carlo method comes at this point as an alternative method to full exploration. The idea is to start at the current state of the game and play many games out of the current point. Then, we choose the best option from those explored. In order to build the tree, we face the problem which is in nature similar to the multi-armed bandit problem. The arms of the bandit are possible moves – stones to be played at a given state – and the payoff is a likelihood when a given choice has been taken.

A naive approach would be to play a number of randomly simulated playouts. In every playout, the game would start at the current state. The progress of the game would be simulated by playing random playouts by player, starting with the player whose best turn we aim to find. Among the set of allowed moves at a given turn, one move or there is a draw if allowed by rules. After the set of random playouts is finished, the next move is determined. The way to do it is to group the randomly simulated playouts then then for each group, the ratio of won games to all games played is calculated and with the highest ratio chosen.

Playing random games is a highly inefficient approach as we have seen with the multi-armed bandit problem. Thus, the MCTS algorithm uses a more elaborate approach to find the optimal move. The MCTS is based on the iteration of the following steps:

- Selection
- Expansion
- Simulation
- Back propagation

## Towards AI – Monte Carlo Search

In the selection step, the existing tree is used to find the following child nodes down the leaf node. Then, in the expansion step, the existing tree is expanded by one child node. The tree is explicitly gaining a new node. In the simulation step, the game starts at the new node and is simulated until the end of the game, usually using random simulation. Finally, in the propagation step, the information in the newly expanded tree is updated. The nodes which are on the select path include information of the outcome of the game.

In the following section, we elaborate on all the steps in more detail. We assume that the game is at any state, i.e. it can be the empty board or the game can be to the end. Without loss of generality, we assume player 1 is to make a move. The four-step procedure took took l-times, where l can be 0.

Further, every node $i$ of the tree is described by a pair of numbers $(w, n)$ where:

- $w_i -$ the number of simulated games which contains the node $i$ and resulted in a win of the player, who made a move.
- $n_i -$ the number of simulated games which contains the node $i$.

### 2.2.1 Selection Step

There is already a built-up tree. Player 1 wants to find a suitable move to maximise his chances to win. Starting at the root node, the path through the tree is selected. The path ends at the node, where there is at least one move out of the possible moves which do not have an explored node. This corresponds to the case when some – or even all – of the possible options stemming from the node have not been explored.

What path to take? The objective is combine exploration with exploitation. The mechanism to select the path should favour the promising nodes but keep an option to exploit the paths which have been so far perceived as favourable. The multimarmed bandit problem provides a way to solve the dilemma. In Kocsis and Szepesvári (2006) proposed the procedure to employ the Upper Confidence Bound algorithm to solve the multi-armed bandit problems to form the decision to select the path in the tree. When there is a decision to make, i.e. to choose among the child nodes which have been explored and thus each assigned $(w, n)$, the following quantity is calculated for every considered child $i$:

```
$UCT_i = \frac{W_i}{n_i} + C \cdot \sqrt{\frac{\log s_{parent}}{s_i}} \qquad (28.16)$
```
