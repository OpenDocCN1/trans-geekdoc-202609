and the CID, the cryptographic hash of the data, for the certificate we generated. Using this CID, we can get
original certificate from IPFS and, using the "pdf-lib" npm package, obtain all the data fields. If matched, we can
that the certificate is verified, else the certificate is not verified and is not credible.

# 3.4. Sharing Certificate & Other Features

The authenticated users have a Dashboard page on which they can see all their generated certificates, with the
share option. Using it, the users can choose to give access to their documents to a particular user in the system, be it
another user or prover, for a user-defined amount of time. The user that needs the certificate needs to input the email
of of the recipient and the period in days for sharing. After this, the other user can see this certificate on their
dashboard along with their certificates.
Since the CID of the document, stored securely on the Blockchain, is shared with the recipient, not document
elf, this ensures the document's security. To improve user experience, we have implemented a notification system.
Relevant Notifications will be shown to the authenticated users.
