
and the CID, the cryptographic hash of the data, for the certificate we generated. Using this CID, we can get original certificate from IPFS and, using the "pdf-lib" npm package, obtain all the data fields. If matched, we can verify that the certificate is verified, else the certificate is not verified and is not credible.

## 3.4. Sharing Certificate & Other Features

The authenticated users have a Dashboard page on which they can see all their generated certificates, with the share option. Using it, the users can choose to give access to their documents to a particular user in the system, be it another user or prover, for a user-defined amount of time. The user that needs the certificate needs to input the email of the recipient and the period in days for sharing. After this, the other user can see this certificate on their dashboard along with their certificates.

Since the CID of the document, stored securely on the Blockchain, is shared with the recipient, not document itself, this ensures the document's security. To improve user experience, we have implemented a notification system. Relevant Notifications will be shown to the authenticated users.

function shareCertificate(string memory sharerAccName, string memory sharedToAccName, uint typeCert, uint time, string memory timeSharing) public {
    uint userId = accountName[sharerAccName];
    uint viewerId = accountName[sharedToAccName];
    require(userId >= 1, "User not found");
    require(viewerId >= 1, "Viewer not found");
    require(userId != viewerId, "You can't share with yourself");
    SharedCertificate memory b;
    b.sharerAccName = sharerAccName;
    b.timeSharing = timeSharing;
    b.time = time;
    b.typeCert = typeCert;
    userHasAccessCertificate[sharedToAccName].push(b);
}
