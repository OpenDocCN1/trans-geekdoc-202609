## 2.3. Blockchain Platforms

There are many Blockchain platforms that can be used for deploying DApps and smart contracts. Let's look at few of them with pros and cons.

### 2.3.1. Ethereum

Ethereum is an open-source Blockchain, which is widely used to develop and deploy decentralized and reliable applications. Every node in the Ethereum network stores a full copy of the Blockchain, so all the transactions are executed by the nodes must agree upon the transaction.
Without incurring the expenditures of constructing their own, anyone may create a Blockchain-based system and operate on Ethereum's infrastructure. Ether is used by the Ethereum network to reward nodes for computations and move money between accounts/wallets. Downtime, censorship, fraud, or third-party intervention do not affect Ethereum Blockchain applications.

### 2.3.2. Hyperledger Fabric

It is a business Blockchain network hosted by Linux Foundation, using a modular architecture ensuring confidentiality and scalability. The platform allows developers to build all types of private Blockchain apps. It is extremely popular for organizational use [11]. ### 2.3.3. Polygon (Matic)

Polygon (Matic) is an L2 scaling solution developed on top of Ethereum to solve some of the most significant barriers to DApp adoption: scalability, usability, and speed. Since the users on Polygon can create off-chain actions for payments and smart contract interactions, Polygon calls itself the "Ethereum of blockchains." Polygon makes a distinctive approach to L2 scaling by plasma, a L2 scaling solution that generates a tree-like set of "child Blockchains" that utilize the Ethereum as a tree and arbitration layer.
Polygon's new Blockchain is developed as a "commit chain" rather than a "side chain." The main difference is noted that sidechains mostly rely on their validators for security purposes. ## 2. Storing Data and Files

### 2.4.1. MongoDB

MongoDB is an open-source NoSQL relational database management system. MongoDB can store and retrieve document-oriented data. MongoDB works using records that contain data field and value pairs. Groups of documents that operate similarly to a relational database table are known as collections. All collections can hold any kind of data, this data cannot be distributed over many databases [15].

### 2.4.2. BigchainDB

BigchainDB is a scalable database. It was created to bring the advantages of two worlds: "conventional" distributed databases and "traditional" Blockchains. BigchainDB begins with a standard database (original RethinkDB) with the following properties: scale and query ability. From that, we will build Blockchain features such as decentralized, immutable assets.

### 2.4.3. IPFS

The Interetary File System (IPFS) is a distributed file protocol and a peer-to-peer network. Using IPFS, we can store and share information. IPFS takes advantage of a data structure called Directed Acyclic Graphs (DAGs). Specifically, we use Merkle DAGs, where each node has a unique identifier that is a hash of its contents. To identify an individual file in a global namespace that links the content, IPFS uses content-addressing [16]. When you upload a file to IPFS, it is split into smaller chunks of data, which are hashed cryptographically, and then assigned a fingerprint termed Content Identifier (CID). The SHA-256 hashing algorithm guarantees a unique CID for each default. This CID is a permanent record of your file as it exists. When others search for your file, they inquire whether their peers are storing the content referenced by the CID. They cache a copy of your file when they view or download it, and becomes another source of you until their cache is erased.
A node in the network keeps the just as it is concerned, and adding some information to identify which node is storing what. When you upload a new version to IPFS, its cryptographic hash changes, and it obtains a new CID. This indicates that IPFS is resistant to manipulation and censorship – any modifications to a file do not erase the original, and common portions across files may be reused to mean you have to remember a long string of CIDs because IPFS can utilize the IPNS decentralized naming system to locate the latest version of your, and DNSLink can link CIDs to human-readable DNS names [17].

## 2.4. Evaluation of File Storage System

MongoDB is a centralized database. The problem with centralized databases or even decentralized databases like Google Cloud is they are vulnerable to attacks. Also, Distributed systems provide advantages like security, accessibility, accountability, and cost reduction [18].

BigchainDB is a hybrid of distributed databases and Regularchains that combine the best of both worlds [19]. ## 3. Proposed Work

In this research, we aim to build a system that helps to manage, verify and share Documents using Blockchain Technology. The workflow for this system includes starting with a basic template for a specific document and utilizing the same to generate documents with a unique Signature (hash) that will be used to verify the document. It has three parts: generation, verification, and sharing.

## 3.1. Generating Certificate

First, the certificate is created and uploaded on the platform. Then the end users can use these templates as application forms for getting the certificate. Afterward, the approver can verify all the details provided by viewing supporting documents to be shared by the applicant on the approver dashboard, as identity card, and the certificate for the applicant. Also, the details are added to the Blockchain, and the applicant can download the PDF or use the platform service to share the certificate.

### 3.1.1. Creating and Uploading Template

For applicants to apply for a new type of certificate, the document issuer must provide the required fields and documents for approval. Then a template for the form using the pdfLib npm package is created.

### 3.1.2. Getting the data

To provide the data, the applicant has to fill out the form template, available in PDF format. After filling out the form template, the applicant needs to upload the filled form with the required documents as a PDF or use the shared service of the platform.

## 3.2. Verify the data and generate the certificate

Once the form is submitted, the approver completes the verification of all the provided data and approves the certificate. On approval, the details of the certificate holder are added onto the Blockchain, and the certificate is generated and made available for download.

### 3.2.1. Storing the certificate onto the Blockchain

Once the certificate is approved and generated, it is stored in the IPFS, and a unique CID is generated. This CID is saved in the Blockchain along with the owner details.

## 3.3. Verifying Certificate

For verification of the certificate, it needs to be uploaded on the platform. On uploading the certificate, we use the “pdf-lib” npm package to read the content of the certificate, using the “load” method of the “PDFDocument” class, which reads all the data fields in the form of metadata. Now, we search for the same user’s certificate in the Blockchain.
