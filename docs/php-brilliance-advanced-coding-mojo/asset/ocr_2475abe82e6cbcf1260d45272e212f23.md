Putting a name on our spaces.

I subtitled this section with an analogy to directories and files. It's appropriate now to bring that comparison to play. When it comes to mentoring team members about namespaces, we can start with the root of a file system. On a Windows based machine, that's normally referred to as “C:\, but since I'm a linux type of guy I'm going to stick with the terribly simple and "nix like "/”. The root of the filesystem is directly comparable to the global namespace in our code.

We can ask our developers who would find preferable: To drop every file they create into just one root location? Or would they prefer to make use of directories to impose some sanity and order on the layout of the codebase? It's a rhetorical question of course. Anyone with a passion for music might very well hundreds if not thousands of mp3s on machine but they won't be saved into the same '$username/Music/ folder. In all likelihood, they will be organised into folders. By first the name of the artist, then by album title, giving rise to a folder structure that might just look like this.

```
/home/thunder/
Music/
haus/
Crackle/
Iron Slave/
Metallica/
Master of Puppets/
```

This is namespacing at work directly within the filesystem - the logical gathering together of related materials. When the filesystem analogy is considered, it's hard to see a way for not justifying the benefits of sensibly organised folders. More significantly, we already know from experience that we cannot save two files with the same name in the same directory, a fact which only strengthens the analogy.
