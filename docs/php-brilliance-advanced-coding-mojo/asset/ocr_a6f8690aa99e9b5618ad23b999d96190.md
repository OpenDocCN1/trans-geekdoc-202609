Before we finish off this part of the book, it's appropriate to bring back dynamically composed Frankenstein's Monster of an object that we looked at previously. It is, after all, the very reason we're reviewing duck duck typing here in the “Talking Points".

Our skeleton class, the one that scavenged closures out of other models' methods, implements the magic __call() method, the very thing that lets us trigger closures in the first place.

However, the presence of the magic __call() method within a class means that whenever we test an instance to see whether it has a particular callable method (i.e. duck typing), we will always get a boolean true response back simply because we can invoke any method name on a class that has this magic method in place. Whether the anticipated effect is achieved or not is entirely another matter.

$viewData = new ViewData();

});
