Code, but in the abstract sense.

```
$integer = (int) 5;
$float = (float) 3.14;
$boolean = true;
$string = "Hello World";
$vehicle = new Car();
$person = new Person();
```

Hopefully now, you can see the line of thinking that I'm taking when talking about defining classes and objects within an application. Pretty much every case where we use an object as a store of data held as object properties, we could in theory use an associative array. Just like this:

```
$person = array(
  'name' => 'Joe',
  'age' => 26,
  'gender' => 'male'
);
```

Poor Joe! I'm sure he's feeling rather badly used just right now. Nevertheless, the array structure above is perfectly valid of course. Valid yes, but ideal? Highly unlikely, and not when we have the power of objects at our fingertips. Just right now we know we can code a class that will better represent a person in our application. Just right now we can create a Person data type.

So we proceed to create Person class and in doing so, we are clearly defining the attributes, as properties, and characteristics, as methods, that data type will exhibit. This turn informs us of all of the ways in which we can access and manipulate the data held by a variable of that particular type.

Does this make sense? We know from our experience of working with both integers and arrays attempting to use the square brackets accessors on an integer variable doesn't work. It's ludicrous to even consider it.

```
// This makes no sense
$integer = 5;
print $integer[0];
```

It makes no sense because we know how integers work. We have been using the language long enough to understand the scope of their operation. However, using the square bracket accessors on an array variable makes perfect sense.
