To get back to our original question then, where does this abstraction promotes code reuse duplication actually come from? To try and pinpoint a single source would probably be an act of folly, if not speculation. For were we can use all our favourite search engine to locate articles online that pitch this idea in truth, I think the major culprit is under our noses and it's one that I found earlier on.

If it's true that we've all been exposed to at least one of PHP's many MVC-like framework implementations, then we've all surreptitiously exposed to the idea of abstraction as code reuse. The moment that you extend a base model class in order to implement your User model, or Blog model, or Product model then you are, in all likelihood, doing so in order to take advantage of some common, theoretically related code in the parent. It may not be branded as code reuse directly, but there's a very strong implication in promoting the practice. The early players on the scene did this, implementations such as phpCake and CodeIgniter and it's a practice that still promoted in some of the more modern additions to the scene, Phalcon and Laravel included. When the documentation tells you to extend a base model, because the base model's class is already populated with lots of utility methods. These methods will do everything from interfacing with your application's database to providing easy access to model properties and everything between.

The trouble is, these frameworks can be so damned useful!

That though, doesn't excuse them from the great violations of sound programming practice that are going under the hood.
