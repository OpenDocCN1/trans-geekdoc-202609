Many developers see this ability to override parent class methods as a boon; some-
thing empowers the child class specialisation process. After all, what's the point
in providing specialised child classes if you can't override the behaviours written
into the parent. This argument forms the crux of our discussion on inheritance. The
immediate answer is that, yes, of you can override parent methods in order
to provide the specialised behaviour in child classes that your application needs. The way in which you do this is one that requires careful handling. Perhaps some
careful handling that you've used to until now.

For the moment, let's take the case that was introduced in the previous chapter. If
we're providing a blueprint for a new data type by creating an abstract parent class,
then we want all of our child classes to conform to the specification of that new data
type as declared by the parent. Succinctly, the child classes should honour the
promises that the parent class makes.

In the event that we write code into a child class that overrides a method from
the abstract parent, we should take care to ensure that the child's method remains
compatible with the parent's specification.
