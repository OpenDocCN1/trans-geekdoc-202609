Code, but in the abstract sense.

```
abstract public function say();
```

Looking at that line of code, there's clearly nothing there to tell us what we're expected to return when we craft the implementations of this method in the child classes that we derive from this abstract. The original author of this code, the designer of this class has the power to communicate his intent to the developers who will use this blueprint. The author, and indeed should use docblock commenting to indicate the return type, resulting in code that might look like this.

```
/** method description
 * .. other docblock tags
 * @return AnimalSound
 */
abstract public function say();
```

Of course, you should provide the @return tag in the docblock for every method that you create, but I feel that it's especially important for circumstances such as this the method declaration on itself fails to specify the return type. Supporting this idea is the convention that missing the @return tag implies that the return type is void. That being the case, if you're authoring abstract methods you should also provide the @return tag in a docblock whenever your expected return value is intended to be anything other than void.

If you miss the docblock and the child derivations end returning a whole gamut of different types, then it's your fault. You bad person, you.

But if you provide the appropriate docblock and the implementing developer ignores it and chooses to return whatever they like, then that's their fault. In this latter case, it'll be you that gets to home early while they're the ones staying late to fix the bugs. The notion of providing an interface in this way only goes part of conveying a more thorough understanding of the attributes and characteristics of our new data type, but it is a terribly important part of process.

This idea allows me to segue nicely into the final part of our discussion, that of type hinting. I'm reasonably confident that you all know what it is, the clue afterward in the name, but our exploration of abstraction would not be complete if we didn't at least touch on it.
