No matter though, we can fix things by aliasing the imported class and thereby freeing us to declare our own version of the Application class. Aliasing is achieved by adding the keyword like this

```
<?php
namespace Company\AppName;

// Format: "use $fullPath as $localName"
use Symfony\Component\Console\Application as $sfApp;

class Application
{
    private $sfApp;

    public function __construct(sfApp $sfApp)
    {
        $this->sfApp = $sfApp;
    }
}

$myApp = new Application(new sfApp());
```

Job done. We have now only solved our name collision but we've also clarified the intent. Granted, there's not a lot going on in there but at least it doesn't take much effort to determine that our Application instance is meant to compose an instance of Symfonyony's console Application.

I used the word “compose” in that last sentence quite deliberately as this the part of the chapter where I pull the generic notion of namesacing into the realms of PHP Brilliance.
