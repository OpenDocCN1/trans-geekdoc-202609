Putting a name on our spaces.

```
<?php
namespace Vangard\MyApplication\Controller;

use Vangard\MyApplication\Service\BlogService;
use Vangard\MyApplication\Controller\ControllerInterface;
```

```
class PageController implements ControllerInterface
{
}
```

The only thing that has changed there is that I’ve inserted “MyApplication” into the namespace declarations. Should we move all of our code into a new “MyApplication” folder? Well, could if we wanted to. Doing so would make sense if we anticipated that this particular project directory would end containing multiple sub-projects. Otherwise, there would be no need to reorganise the filesystem layout for the project, we just need to tell Composer that the namespace prefix has been changed.

```
{
  "require": {
  },

  "autoloader": {
    "psr-4": {
      "Vangard\\MyApplication\\": "src",
      "Vangard\\MyPackage\\": "lib/mypackage/"
    }
  }
}
```

For the sake of illustrating how we might accommodate a new sub-project, I’ve also added a second entry to the autoloading specification; one maps the namespace “VangardMyPackage” to a new directory. Even if you don’t use Composer to pull in manage outside dependencies, just following these namespace guidelines for your own code and making the appropriate edits to composer.json makes autoloading super easy and entirely hassle free.
