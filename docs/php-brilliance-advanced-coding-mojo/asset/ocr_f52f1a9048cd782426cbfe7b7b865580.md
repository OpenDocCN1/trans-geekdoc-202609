# What are these rules then?

The first rule concerns the input parameters of the overriding method. The number
of input parameters in our child method should be the same as or more than the
number of input parameters expressed in the corresponding method from the parent.
Ideally, we'd keep the quantities of input parameters the same since when we do
that, we reinforce the parent's definition as being the rule of law. However, we do
also need to recognise the fact that since we are coding child classes to cater for
more specialised situations, we may on occasion need to chuck in a bit extra
alongside the data type's defined requirements. It probably doesn't need to be said
rather than missing anything out, let's just note that irrespective of whether the
tities of input parameters remain the same or not, the order of the parameters
s specified in the parent's method should be honoured in the child’s method.

There’s a second facet to the first rule – one that is perhaps of greater importance.
The types of the input parameters in the overriding method should be the same as
or more generic than the types specified in the parent.

lous, indecipherable or both. If we’re to employ a mechanism for providing more
specialised child classes, surely the input parameters of our class’s methods
need to be able to change in accordance to the needs of the child class, not those of
t parent. Not so.
