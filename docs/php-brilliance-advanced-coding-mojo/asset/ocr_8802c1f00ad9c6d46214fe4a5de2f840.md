As you can see, the minimum requirements that Composer imposes upon us to meet PSR-4 standards are quite achievable. Not only that, they're pretty sane too! The only thing left to do is to tell Composer's autoloader how to find properly namespaced classes.

This is achieved by adding an autoload entry to Composer's config file, composer.json. Our simple example above would result in an entry that looks very like this.

```
{
  "require": {
    ...
  },
  "autoloader": {
    "psr-4": {
      "Vanquard\\\": "src/"
    }
  }
}
```

All we've really done here is provide a simple key->value pair that tells' Composer's PSR-4 compliant autoloader that classes beginning with the "Vanquard" namespace can be found under the "src/" directory relative to the composer.json file itself.

However, our work isn't quite over yet. We've only told Composer about our vendor namespace. To remain compliant (and functional!) we still need to consider any sub-namespaces left over after we've stricken the vendor prefix. In our example above, our namespace is "VanquardController". Once we've stricken the "Vanquard" prefix from the list, the only thing left is a single sub-namespace i.e. "Controller". PSR-4 tells us that should map directly to a directory underneath the directory we mapped to the prefix in composer.json. Again, the spelling and capitalisation are important here.
