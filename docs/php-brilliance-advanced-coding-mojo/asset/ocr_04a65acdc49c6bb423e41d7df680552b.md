AsAs you can see, following even the most basic application of the PSR-4 standard leads to a filesystem layout that is not only neat and tidy but also very logical too. For the benefit of further illustration, I also include the path for a class that would be referred to as "VanguardAuthStrategyAcl", simply to show how each-namespace ("Auth" and "Strategy") here corresponds to an identically named directory. Adopting this scheme will mean that the problem of autoloading classes will already be taken care of. As always, never reinventing the wheel is a very smart thing to do.

> There are many options that you can supply to Composer via its composer.json file, but we will cover those later on the book.

Whilst I've presented only a very simple strategy here, a more common case would be to "extend" the namespace prefix that we use to provide a project level degree of separation as well. If the vendor namespace represents you (or your company), then the first sub-namespace can be used to indicate the particular project you're working on.
