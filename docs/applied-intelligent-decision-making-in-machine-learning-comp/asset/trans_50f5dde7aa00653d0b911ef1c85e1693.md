通过使用“洋葱路由”（The Onion Router）服务，可以向查询发送不同 IP 地址的请求。IP地址的修改可以在固定或任意选择的时间间隔内发生，也可以在查询服务器输出错误时发生，这通常意味着爬虫被拒绝了访问。

我们将更改操作设置、随机化待爬取实体、限制 Cookie 并更改 IP。我们不考虑查询之间不同的时间间隔，因为本章开发的爬虫已经能够满足我们的需求，而且延迟查询可能会使处理时间最大化。

## 5.3.2 数据策展

来自多个来源的爬取并集成的数据集通常包含缺失和重复数据，必须对这些数据进行预处理，以避免误导性的学习过程导致不理想的推荐结果集。我们的预处理阶段涉及将爬取的网页 URL 转换为合适的格式，以便为推荐特定领域的科学论文提供高质量数据。具体而言，我们执行了多项预处理任务，包括数据集成、命名实体识别、缺失值处理以及重复值处理（Shobha and Nickolas 2020）。

来自 Google Scholar、Semantic Scholar、Scopus、Web of Science 和 Microsoft Academic 等不同科学网络存档的爬取数据（单日）包含 4,681 篇论文的 URL。这些 URL 是会议论文、期刊论文、海报、书籍和综述文章的链接。这些 URL 经过进一步处理以排除书籍、综述和会议。只有 2,521 个 URL 被重新爬取以检索整个文档。执行的其他预处理步骤说明文所示：

- 1. **处理无关字段：** 爬取数据集中的某些字段对于推荐并非必需，例如 GSrank、CitesPerYear 和论文年龄。这些字段被移除。
- 2. **处理重复字段：** 在爬取过程中，收集了具有不同名称但具有相同值的字段。由于每个网络存储库都维护其自己的论文元数据风格，不同字段名具有相同值的概率很高。在集成来自不同科学网络库的爬取数据时，重复字段的存在可能会导致维度冗余。例如，Estimated Citation Count (ECC) 和 Cites 等字段具有相同的值，形成重复。因此，这些重复项被移除。
- 3. **含有缺失值的记录：** 在爬取的数据中，文章的不同字段（如 URL、DOI 和 ISSN）存在多处缺失值情况。这些缺失实例可以通过人工干预通过手动搜索来处理。
- 4. **处理重复记录：** 由于开发的爬虫和爬取工具是特定领域的，我们根据领域名称爬取数据，例如数据插补、缺失值处理或缺失处理。爬取的特定领域期刊推荐数据可能具有或没有 DOI 这样的唯一标识符。如果没有唯一标识符，在同一阶段很难判断两条记录是否相似。因此，我们同时或分阶段考虑多个字段来处理重复记录。本工作string了以下考量，根据从多个网络存档集成数据后可用字段来删除重复记录：

- a. 基于 DOI 识别重复记录。
- b. 利用 YEAR 字段（出版/接收）来标记重复元素。
- c. 字段融合，例如 Title of page + paging-info，ISSN + Title of the article。
- d. 如果未按照上述规则进行去重，则使用准确率较低的字段，例如出版者名称或作者名称。

## 5.3.21 集成操作的复杂度

在“R”语言中处理来自多个网络存档的爬取数据重复项的简单且基础的方法，是将 R 与 R+i 进行比较（其中 i = 1, 2, 3, ..., n，且 n 为记录总数）。这种方法适用于集成具有两个不同查询的五条出版记录（例如，与特定领域出版相关的查询，即数据插补、缺失值、缺失数据），产生 5 * 3 = 15 个不同的数据集。为了处理这些爬取数据中的重复项，必须执行多次连接程序。对于每个查询，如果网络存储库返回“R”，则类比重复项的总数取决于网络存档中所概述记录列表的重复率。

## 5.3.3 阶段 1：识别候选期刊

在此阶段，我们的目标是识别与种子文档 $S_d$ 相似的候选期刊集。通过训练好的神经网络，我们首先将所有策展文档嵌入线性空间，其中领域核心文档倾向于更加靠近。由于文档的投影与种子文档无关，所有策展文档只需要投影一次即可供后续查询使用。然后，我们将每个文档 $S_d$ 投影到相同的线性空间并识别其 $k$ 个最近邻作为候选文献。对于附近的候选文献，同时考虑出引和入引（Strohman, Croft, and Jensen 2007）。该阶段的结果是文档列表 $S_i$ 及其对应的评分 $sim(S_d, S_i)$，描述为余弦相似度。该阶段产生了数量适中的候选期刊，使得在第二阶段通过将对 $(S_d, Di)$ 输入另一个神经网络来对每个候选 $Di$ 评分变得可行。该阶段的概述如图 5.3 所示。
