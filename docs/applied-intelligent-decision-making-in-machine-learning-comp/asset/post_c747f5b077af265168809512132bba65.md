
## 1.3.2 COUNTING THE FREQUENCY OF ITEMS IN A STREAM

Frequency counting in a stream is the basis of many tasks. For example, if we know the frequency of items, we can compute the mean and variances of them which can be further utilized in downstream tasks such as classification, clustering, and computing similarity. Here, I will present a classic algorithm for counting the frequency of items in a data stream: count-min sketch (Cormode and Muthukrishnan, 2004). A count-min algorithm can be seen as an extension of the bloom filter discussed above. The key idea of the algorithm is to map the domain of the stream from [1,...,n] to [1,...,d] using hash functions.

Hash values are stored in a two-dimensional array called sketches of width $w = [e / \epsilon]$ and height $h = [\log_{1/\delta}]$, where $(e,\delta)$ denote the accuracy in the approximation and confidence level, respectively.

An example of a count-min algorithm is given in Figure 1.5. To understand the algorithm, let us take an example. Imagine the stream looks like:

...A, B, A, C, A, A, C... (1.1)

Initially, the sketch is filled with 0s. The algorithm takes each letter at a time and applies hash functions. For example, letter "A" hashes to columns (0, 1, 3, 4, 2) by the hash functions in the sketch. Corresponding entries in the sketch are incremented by 1. Similarly, all other letters are hashed. During query time, the same hash function is applied to produce the entries in the sketch. The frequency of the letter is given by taking the minimum of these entries. The count-min sketch is guaranteed to never give false negatives. That means the estimate is one of true values or overcounts. Overcounts happen when two or more hash functions map at least two entries at exactly the same locations. That is why the choice of a good random hash function is required for the working of the algorithm. For a more in-depth discussion, the reader can consult the original article (Cormode and Muthukrishnan, 2004).

## 1.3.3 COUNT UNIQUE ITEMS IN A DATA STREAM

Counting the number of unique items in the stream presents an interesting problem. Formally, this problem can be posed as follows. Suppose the domain of the random variable is $\{0, 1, \dots, n\}$ and the stream looks like:

0, 1, 0, 0, 0, 1, 2, 3, 3...

$n = 3$. A trivial solution is to store all new items in a hash map whose size grows like $O(n)$. However, we want a solution which runs only in $O(\log(n))$. One elegant solution is given by Flajolet and Martin (FM) (1985). FM is given in Algorithm 1.1. Let us work through the algorithm step-by-step.

- Initialize a BITMAP to all 0.
- For each item $x$ in the stream, compute a hash value for it. Call it $h(x)$.
- The binary representation of the hash value is $bin(h(x))$.
- The function $p$ gives the position of the least significant set-bit. This also occurs if $p$ returns 0 for the 0 bit.
- Finally set the BITMAP[i] = 1.

```
Algorithm L1: Flajolet and Martin (FM) Algorithm
Input: stream $M$
Output: Cardinality of $M$
1 initialization: BITMAP OF $L$ bits initialized to 0;
2 for each $x$ in $M$ do
  * Calculate hash function $h(x)$;
  * get binary representation of hash output, call it $bin(h(x))$;
  * Calculate index $i$ such that $i = p(bin(h(x)))$, where $p$ is such that it outputs the position of the least significant set-bit, i.e., $i$;
  * set BITMAP[$i] = 1;
3 end
4 Let $R$ denote the largest index such that BITMAP[$i] = 1;
5 Cardinality of $M$ is $2^R/\phi$ where $\phi=0.7735$;
```

The above steps are repeated until the end of the stream. Let $R$ denote the most significant set-bit. Then, the number of unique items is given by $2^R/\phi$ where $\phi \approx 0.7735$ is a correction factor.

The intuition behind the working of the FM algorithm is as follows. The algorithm uses a hash function that maps the strings in the stream to generate random integers in the range $[0, \dots, 2^l-1]$. Thus we expect that:

- 1/2 of the numbers will have their binary representation in 0 (divisible by 2).
- 1/4 of the numbers will have their binary representation in 00 (divisible by 4).
- 1/8 of the numbers will have their binary representation in 000 (divisible by 8).
- In general, $1/2^k$ of the numbers will have their binary representation in $0^k$.

**Exercise:** Try finding the unique numbers in $M = \{5, 10, 15, 20, ...\}$ with any hash function. Then, the number of unique strings will be approximately $2^n$ (because $n$ bits, we can represent $2^n$ integers). A worked example of the FM algorithm is as follows. Assume stream $M = \{..., 1, 2, 3, 1, 4, 2, ...\}$ and the hash function $h(x) = (x + 1) \pmod 5$.

Then

```
h(M) = \{2, 3, 4, 2, 0, 3\}$
```

and

```
p(h(M)) = \{1, 0, 2, 1, 0, 0\}$
```

BITMAP looks like

```
BITMAP = 0|0|0|1|1
```

so that we see the largest index $i=2$. So $R=2$ and the unique integers $2^i/\phi = 5$ approximately (the exact answer is 5). Extensions: loglog and HyperLoglog are improvements over the classic FM algorithm. The interested reader may consult Flajolet et al. (2007).

## 1.4 SAMPLING FROM DATA STREAMS

Due to the unbounded nature of data streams and low memory, need some efficient ways to reduce the data footprint. In the literature, researchers usually use the following techniques to reduce the data load:

- Sampling.
- Sliding window.
- Histogram.
- Wavelets and Fourier transforms.

We have already seen some examples of sliding windows and they find application in places such as DGIM method (Rajarajan and Ullman, 2011) for counting in bits and so on. In this section, we are going to discuss a sampling method from data streams.

There are many ways to sample from a data stream. For example we can use random uniform sampling which is the simplest. However, doing random uniform sampling in a data stream is not straightforward since all items in the stream are not available at once. Hence, there is another algorithm called reservoir sampling used to sample items from a data stream such that the probability of selecting an item is $1/n$ where $n$ is the stream size.

The intuition behind reservoir sampling is as follows. Imagine a swimming pool which can have at most $k$ people in it any time. Swimmers are coming continuously and any new swimmer enters the pool after a previous swimmer has come out. But, how do you decide which swimmer to let in? One solution could be to toss a coin (biased) with probability $p=k/n$ where $n$ is the number of swimmers who have arrived so far. If it comes up heads, let the swimmer in, otherwise deny entry. A reservoir sampling algorithm is given in Algorithm 1.2.

```
Algorithm 1.2: Reservoir Sampling Algorithm
input S: stream of values, k: size of the reservoir
/* Create uniform sample of fixed size */
Insert first k elements of S to the reservoir.
for v ∈ S do
  Let i be the index of v in S
  Generate a random j ∈ [1, i]
  if j < k then
    Insert v into the reservoir
    Delete an item from the reservoir at random
end
```

The algorithm follows the intuition as given above. At the beginning, k items in the stream are inserted into the reservoir. For the other incoming items, a random number is generated between 1 and i where i is the index of the items just arrived. If the random number thus lies in [1,k], we insert the item in the reservoir by deleting it uniformly at random. Otherwise, discard the item. The question that comes up is: What is the probability that the i-th item will replace an old item?

## Theorem 1.1

The probability that the new item will replace the old one is given by P(a ∈ R) = k/n, where R denotes the reservoir size, and n the stream size.

Proof: Note that the i item has probability k/i of being inserted into the reservoir R. (Why?) After that no other item should replace it otherwise it will. Now, the (i+1) item will not replace it, and with probability (1-1/(i+1)); likewise, the (i+2) item will not replace it and with probability (1-1/(i+2)); and so on. Since all of these probabilities are independent, we multiply all of them to get the desired result. P(a ∈ R) = $\frac{k}{i} \cdot \frac{i}{i+1} \cdot \dots \cdot \frac{n-1}{n} = \frac{k}{n}$
