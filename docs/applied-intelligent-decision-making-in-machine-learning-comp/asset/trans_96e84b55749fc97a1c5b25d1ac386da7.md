由于这些问题，为离线数据处理开发的传统算法并不适用于流式数据。具有增量性（incremental）的模型较少，例如 K-最近邻算法（KNN）和朴素贝叶斯（naive Bayes）。但尽管如此，这些模型无法处理流式数据中存在的所有问题。例如，如果数据中存在概念漂移（concept drift），则需要开发专门的概念漂移检测和缓解技术。许多研究人员针对流式数据提出了各种模型来解决这些问题。我们将在接下来的章节中介绍其中一些技术。

如图 1.1 所示，流处理器接收如 0, 1, 0, 1, ...... 等数据流作为输入。处理器可以从流中进行采样并在主内存中进行处理（例如在回答查询时），如果需要，可以将处理结果存储到后端（如硬盘）以供下游任务。后续章节中介绍的大多数算法将基于这一通用模型。

数据挖掘应用于多个领域，例如回答网络查询、传感器数据（Das et al., 2019; Dey et al., 2019）、网络数据包分析、患者健康监测以及监控系统等。由于该领域范围广泛，我将在章节末尾介绍该领域的一些案例研究。

## 1.2 数据流挖掘中的研究问题

由于上一节提到的原因，从数据流中发现知识是一项具有挑战性的任务。最具挑战性的是流的无边界大小、低内存和快速的到达率。因此，文献中提出的技术依赖于以某种方式对数据流进行总结。以下是处理数据流时常用的技术。

- 1. **近似查询处理 (AQP)** 遵循如下规则描述（Chaudhuri et al., 2017）：(a) 查询语言应足够通用，以检索所有相关信息；(b) 应该具有低错误率和高准确性；(c) 工作应在运行时保存；以及 (d) 应为预计算留出额外资源。AQP 方案的这些维度并不是相互独立的，之前的文献大部分在这四个维度上都做了特定的选择。AQP 可以大致分为两大类：(a) 在线聚合，即以在线方式进行采样并使用样本回答查询；(b) 离线摘要生成，基于数据的某些统计信息并回答查询（Li and Li, 2018）。

- 2. **滑动窗口查询处理** 是一种处理数据流的模型，假设最近的项目比较旧的项目更重要。根据定义方式，滑动窗口有两种类型。

- **基于序列的滑动窗口**由决定窗口大小的观测数量定义。这些进一步划分为*地标滑动窗口*（landmark sliding window）和*移动滑动窗口*（moving sliding window），如图 1.2（左）所示。

- **基于时间戳的滑动窗口**：在这种情况下，滑动窗口由给定时间间隔内的观测数量确定，而窗口宽度根据时间确定。它们进一步分类为*自然倾斜时间窗口*（natural-tilted time window）和*对数时间窗口*（logarithmic time window），如图 1.2（右）所示。
