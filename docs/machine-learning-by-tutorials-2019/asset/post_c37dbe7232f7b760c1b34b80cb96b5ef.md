
## Machine Learning Chapter 9: Beyond Classification

The on_epoch_end() method is called by Keras as it completes an epoch of training, i.e., after the generator has run out of batches. Here, on_epoch_end() creates an instance variable, rows that contains the indices of the rows in the DataFrame. Normally self.rows is [0, 1, 2, ...] if shuffle is true, the indices in self.rows get randomly ordered. BoundingGenerator's constructor, __init__ in Python, also calls on_epoch_end() to make sure the rows are properly shuffled before the first epoch.

The method of work happens when __getitem__(). This is called when you next() or when you write train_generator[some_index]. This is where the batch gets put together. __getitem____() does the following:

- 1. Create NumPy arrays to hold the images X, and the targets y_class and y_box for each. These arrays are initially empty.
- 2. Get the indices of the rows to include in this batch. This looks up in self.rows.
- 3. For every row index, grab the corresponding row from the DataFrame. Load the image, preprocess using the standard MobileNet normalization function, and put it into X. Also get the class name, use label2index dictionary to convert it to a number and put it into y_class. Finally, get the bounding box coordinates and put them into y_box.
- 4. Return X, as well y_class and y_box, to the caller.

> Note: __getitem____() returns a tuple of two elements: The first one holds the array with the training images X, the second element holds the targets. But you have two different targets, one for the class and one for the bounding boxes. If you earlier wrote X, (y_class, y_box) = next(train_iter), to unpack this second tuple element into y_class and y_box variables.

To test that the generator works OK, the images and bounding boxes that it returns:

## A simple localization model

You're now going to extend the existing MobileNet snacks classifier so that it has the ability to predict a bounding box as well as a class label.

To create the classifier, you took the MobileNet feature extractor and added a logistic regression on top, made up of a Dense layer, a softmax activation, as well as a Dropout layer for regularization. Guess what: There's no reason why you can't add another bunch of layers that branch off the feature extractor. These new layers will now predict the bounding box coordinates:

![](img/5720be5c3cca252e12448e68d25607b5_320_0.png)

This new model has two outputs: one for the classification results, and one for the bounding box predictions. Both sets of layers are built on the same features from the MobileNet feature extractor, because you train them on different targets they learn to predict different things. The classification portion of the model is still the same as before and outputs a probability distribution over the 20 possible classes.

The bounding box predictor outputs four real-valued numbers: x_min, x_max, y_min and y_max. If you train the model well, four numbers will frame the corners of a proper bounding box.

A quick reminder of the functional API works: You create a layer object, such as GlobalPooling2D(), and then call this layer on a sensor, as base_model.outputs[0], which is the output from the MobileNet feature extractor. Then, it gives a new layer, pool. Then, you create a new layer, Dropout(0.7), apply this to the pool tensor, and after you run this, clf is the new layer that refers to the model's classification output.

To reconstruct the classifier as follows:

```python
num_classes = 20

# The MobileNet feature extractor is the first

# Add a global pooling layer

clf = Dense(num_classes, kernel_regularizer=l2(0.01), name="dense_class")(clf)
clf = Activation("softmax", name="class_prediction")(clf)
```
