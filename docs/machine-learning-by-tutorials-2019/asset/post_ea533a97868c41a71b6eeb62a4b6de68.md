## Using generators

You've seen how to load an image into a tensor and how to plot it in the notebook. That's handy for verifying that the training data is correct. During training, you won't have to load the images by hand. Keras has a helper class called ImageDataGenerator that can automatically load images from folders.

```
from keras.preprocessing.image import ImageDataGenerator
datagen = ImageDataGenerator(
    preprocessing_normalize_pixels)
```

The data generator takes the normalize_pixels function as its preprocessing function so it automatically normalizes the images as it loads. The data generator can do other stuff, as you'll see in the next chapter when we talk about data augmentation. Using this ImageDataGenerator you can create three other generators, one for each subset of images:

```
batch_size = 64
train_generator = datagen.flow_from_directory(
    train_data_dir,
    target_size=(image_width, image_height),
    batch_size=batch_size,
    class_mode="categorical",
    shuffle=True)

val_generator = datagen.flow_from_directory(
    val_data_dir,
    target_size=(image_width, image_height),
    batch_size=batch_size,
    class_mode="categorical",
    shuffle=False)

test_generator = datagen.flow_from_directory(
    test_data_dir,
    target_size=(image_width, image_height),
    batch_size=batch_size,
    class_mode="categorical",
    shuffle=False)
```

The train_generator is for images from the train folder, the val_generator for images from the val folder, and the test_generator for images from the test folder.

A generator in Python is an object that can produce other objects. In this case you're making a generator that can produce images by loading them from the given folder. The reason you need to use generators is that you cannot possibly load all the images into memory all at once, since that would require many gigabytes or even terabytes of RAM — the only way to deal with such data is to load the images on-demand. That's what the Keras generators allow you to do.

The three generators do all the same thing — load images from their respective folders — but train generator shuffle=True while the others have shuffle=False. During training, you want to pick the images at random so that the model doesn't attempt to learn anything about the order of images. During testing, however, you want to pick the images in a fixed order as makes it easier to match to the correct order.

The argument class_mode="categorical" tells Keras that there is a subfolder for each image. Keras will use the name of the subfolder as the class label for the images from that folder. The batch size is 64, so the generator will try to load 64 images at a time. When you run the above code, the Jupyter notebook says:

```
Found 4838 images belonging to 20 classes.
Found 955 images belonging to 20 classes.
Found 952 images belonging to 20 classes.
```

These are the number of training, validation, and test images respectively. To see what a generator outputs, you call next() on it:

```
x, y = next(train_generator)
print(x.shape)
print(y.shape)
```

You won't ever to call next() during training, but it's useful to know that your generators work. It grabs the next batch of images and their corresponding labels y. The shape of the x tensor is (64, 32, 3) because it contains 64 RGB images of 32 pixels. Since you'll train on 64 images at a time, the batch also includes the labels for these images. Recall that these labels, also known as ground-truths, used to compute the loss or how "wrong" the model's predictions are.

Because the model produces 20 output values — one probability for each class — the ground-truth label for a given image needs to have 20 values. This is why the shape of the tensor is (64, 20). Have a look at the first of these labels, y[0]:

When you try this, you'll probably get a different label than whatever is printed, since the training is randomly shuffled. Whatever label you get, it should consist of 19 zeros and a single one. This is a so-called Python dictionary comprehension. It takes all the key-value pairs in the class_indices dictionary and creates a new dictionary that flips the order of the key and value. You can look up the name of the class by the index of the element that is 1 in the one-hot encoded vector for label. To find the name of the class, you do np.argmax(y) to find the index of the 1, and then look up the name in the new dictionary:

```
index2class[np.argmax(y)] will print 'pineapple'.
```

For the y[] from this book, why this trouble? Most machine-learning algorithms can only handle numbers, not strings. The text label 'pineapple' doesn't mean anything to the logistic regression.
