The show(results) method then decides whether to show the composited image or just the segmentation mask. It uses two helper methods (createMaskImage or matteImages) Both of these helper methods follow the same approach:

+   1. Allocate an array of Uint8 that will hold the output pixels. The size of this array is deepLabWidth * deepLabHeight * 4 because it is an RGBA data.

+   2. Loop through each pixel, find the index of the winning class. This is done by looping over the 21 probability values for pixel and finding the largest (argmax).

+   3. To combine the two photos, the color that is used for the output pixel is read from the foreground image if the best class is not 0, the special background class. Otherwise, it is read from the background image. It's easy to change this logic to only consider classes in the image, such as cats and dogs.

+   4. In the other method, where the app is drawing the segmentation mask, you get the color of the output pixel from a lookup table, using the winning class as the index.

+   5. Finally, convert the pixel array into a UIImage.

You'll know how some of these steps work in detail. The MLMultiArray API is a little tricky to work with. For many model types, such as classification and object detection, Vision will hide these details from you, but if your model outputs a multi-array then you have no choice but to get your hands dirty.

In the following code, features is the variable with the MLMultiArray object.

```
let classes = features.shape[0].intValue
let height = features.shape[1].intValue
let width = features.shape[2].intValue
var pixels = [Uint8](repeating: 255, count: width * height * 4)
```

Just like the output description so does the actual MLMultiArray. You use the width and height for this shape to allocate the pixels array.

For this particular model, output dimensions are fixed at 513x513, but in the model description for YOLO you saw that the first output dimension was 0, or unknown. In that case, the actual value of the multi-array object isn't known until runtime and can be different from each invocation of the model to the next.
