## Why not use Keras’s Bidirectional layer?

Keras has a Bidirectional layer that simplifies the creation of bidirectional RNNs. You initialize it with a single recurrent layer, like an LSTM or GRU layer, and it handles duplicating as a reversed layer for you. To use it, you'd write something like this for a LSTM:

```
encoder_lstm = Bidirectional(
LSTM(Latent_dim, return_state=True, recurrent_dropout=0.3),
    name="encoder_lstm")(
encoder_out, fwd_enc_h, fwd_enc_c, rev_enc_h, rev_enc_c = \
    encoder_mask(encoder_mask))
```

Or like this for a GRU:

```
encoder_gru = Bidirectional(
GRU(Latent_dim, return_state=True, recurrent_dropout=0.3),
    name="encoder_gru")(
encoder_out, fwd_enc_h, rev_enc_h = encoder_gru(encoder_mask))
```

Each of these examples set return_state=True so the layers return their hidden and cell states (for LSTM, which have cell states). When you connect the Bidirectional layer to a network, it returns the output along the forward and reverse states. Then you would concatenate the states like this:

```
encoder_h = Concatenate(name="encoder_out")(
    [fwd_enc_h, rev_enc_h]),
encoder_c = Concatenate(name="encoder_out")(
    [fwd_enc_c, rev_enc_c])
```

Finally, you'd pass those concatenated states to the decoder as its initial state. And in Keras all of that works great.

Unfortunately, there are currently multiple issues with the Bidirectional class. First, keras will crash if you use any recurrent layer other than LSTM with the Bidirectional layer, so means you couldn't use GRU like you did here. But using LSTMs isn't a problem, so Bidirectional would still be a reasonable option if that were the only issue.

But there is also a bug in Core ML where bidirectional layers return

![](img/5720be5c3cca252e12448e68d25607b5_531_0.png)

vectors filled with all zeros for their hidden cell states. They still work, correctly passing states between timesteps internally, but they cannot pass their states out of the layer, which is what we need for a sort of work around this, where you train your decoder to ignore the initial cell use and use the LSTM’s instead of their hidden states – remember that the output is identical to the hidden state – but means you are forced to throw away half of the information from your LSTM. Or to put it another, you need to train models twice as large as you want in order to pass the same amount of information from the encoder to the decoder.

So until these issues are resolved, it's a better idea to create bidirectional models like you did here, using multiple recurrent layers explicitly.
