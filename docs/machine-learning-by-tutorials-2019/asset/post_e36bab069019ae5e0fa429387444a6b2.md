
Usually coremltools is the go-package for converting models to Core ML. You used to convert your Keras model in the previous chapter. The bad news is that coremltools does not directly support TensorFlow graphs.

The good news is that Apple and Google have collaborated to bring us tfcoreml, a TensorFlow tool to convert to Core ML. This is an additional Python package that you need to install alongside coremltools.

TensorFlow works at a lower level of abstraction than Core ML and Keras. With TensorFlow, you build computational graphs that consist of primitive operations such as addition, multiplication, matrix math, array annotations and so on.

Core ML and Keras, on the other hand, know only about neural network layers. This is why it's easy to convert from Keras to Core ML. But it's not always possible to convert TensorFlow graphs to Core ML. You can only convert graphs that Core ML supports. The tf-coreml website, github.com/tf-coreml/tf-coreml, lists the supported operations.

> Note: Core ML 5 is more capable in this than its predecessors. Like TensorFlow, it supports many low-level operations in addition to the neural network layers. Thanks to this, it should now be possible to convert more complex TensorFlow models to Core ML.

We recommend that this section you use the kerasenv environment, since it already has coremltools and TensorFlow installed. If you don't already have it installed, you can find kerasenv.yaml in the starter folder. Use conda create -n kerasenv to create the environment, and activate it.

But this environment does not have tfcoreml, so use pip to install the latest version:

```
$ pip install -U tfcoreml
```

You may also need to install the most recent version of coremltools. If using the one from pip gives errors, here's a handy trick for installing the latest version straight from GitHub:

```
$ pip install -U git+https://github.com/apple/coremltools.git
```

Now, create a new text file, convert_deeplab.py, and write the following:

```python
import tfcoreml as tf_converter

input_path = "deeplab_mnv2_pascal_trainval/frozen_inference_graph.pb"
output_path = "Deeplab.mlmodel"
input_name = "ImageTensor:0"
output_tensor = "ResizeBilinear:3:0"

tf_converter.convert(tf_model_path=input_path,
                   model_output_path=output_path,
                   feature_names=[output_tensor],
                   input_name_shape_dict=(input_name: [1, 513, 513, 3]),
                   image_input_names=input_name)
```

That's all you need to convert the model. Pretty simple, right? The trick is getting all the arguments to tf_converter.convert() correct.

Most importantly, you need to tell tfcoreml what the model's input and output tensors are. For DeepLab, those are "ImageTensor:0" and "ResizeBilinear:3:0", respectively. See if you can find these tensors in the graph using Netron.

TensorFlow operators can have multiple outputs and you need to specify which one you want to use. The :0 in the name tells TensorFlow the tensor that you want to use from the operator's first output.

Think of it as special syntax for indexing an array at element 0. It's only a detail but if you forget the :0 in the name, tf-coreml won't be able to find the tensor in the graph.

The input_name_shape_dict argument tells tf-coreml what the shape of the input image will be: 513×513 pixels.

Just like the Keras conversion you've done before, image_input_names is used to inform Core ML it should treat the input as a proper image instead of an array of numbers. Note that tf-coreml renames :0 to __0 in the names of the model's inputs and outputs, so "ImageTensor:0" is now "ImageTensor__0".

Run this script from a Terminal:

```
$ python3 convert_deeplab.py
```

DeepLab's output is a multi-array of size 21*513*513. Multi-array is the term that Core ML uses for tensor. When you need to deal with tensor objects in Core ML, it's always through the MLMultiArray class. You'll get a taste of that shortly.

Notice that Core ML puts the number of channels (21) at the front of the sensor, the outermost dimension. Usually, in this, we've described the size of a tensor as height × width × channels (HWC), but in practice, you'll also see it the other way around: channels × width × height (CHW). It's important to know which format you're working with at any given time.

Here, deepLab is an instance of DeepLab, the class Xcode automatically generates from the .mlmodel file. It has a property for the MLModel. If you don't want to use Vision, you can also use the MLModel instance to make predictions.

More importantly, for our purposes you can ask this object about the configuration of the model. Here you grab the modelDescription, which contains all the info you see in Xcode, and from that outputDescriptionsByName. This is a dictionary describing the model's outputs.

This model has only one output with the name ResizeBilinear__0. Note that this is called "ResizeBilinear:0" in the TensorFlow graph, by tfmodel renamed. That output is of type multi-array, which means you literally get access to the 21x513x5 tensor of output values. Grabbing the multiArrayConstraint property, you can look at the size and datatype of this array. Here, you can obtain the size by the shape property.

Because the Core ML API was designed to work with Swift and Objective-C, using some of these classes can be a little elaborate. For example, shape returns NSNumber objects, and so you need to use .intValue to turn these into integers. The shape array has three values in it: [channels, height, width] and you read the height and width into two properties so you can use them later.

After Vision successfully performs the request, the prediction arrives as an array of VNCoreMLFeatureObservation objects. You get one of these objects for every output that is of type multi-array. The actual predictions are inside an MLMultiArray object. This is how you obtain MLMultiArray from the Vision results:

```swift
func processObservations(for request: VNRequest, error: Error?) {
    if let results = request.results as? [VNCoreMLFeatureValueObservation] {
        !results.isEmpty {
            let multiArray = results[0].featureValue.multiArrayValue {
                DispatchQueue.main.async {
                    self.show(results: multiArray)
                }
            }
        }
    }
}
```
