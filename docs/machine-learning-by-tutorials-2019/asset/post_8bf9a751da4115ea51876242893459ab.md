## Chapter 9: Beyond Classification

Don't forget to set the layers of the MobileNet base model to non-trainable, unless you're interested in fine-tuning the entire model:

```python
for layer in base_model.layers:
  layer.trainable = False
```

You could also set the classifier layers to be non-trainable since they've already trained before, but it's probably a good idea to keep them. The class is now taken from the object in the bounding box, which is not necessarily the class of the entire image.

The model.summary() shows the extra layers, but it can be tricky to understand how they are connected. To get a good idea of the branching structure, it's useful to make a:

```python
from keras.utils import plot_model
plot_model(model, to_file="bbox_model.png")
```

The conv2d layers at the top are part of MobileNet. On the right, it shows the classifier branch, and on the left the new bounding box prediction. Note that the bounding box branch is slightly larger: it has an extra layer between the MobileNet output and global pooling.

> Note: You might be wondering exactly why you added another Conv2d layer. Why not do the same as the classifier branch and just have a Dense layer that follows global pooling? The answer is that adding the convolution gave much better results. This extra layer helps to convert image-level features to features that are more useful for predicting bounding boxes. The downside is that this extra Conv2d layer adds parameters.

Now at this point, there is an important step you shouldn't overlook. Because you reconstructed the model, the weights for these are still initialized with random numbers. If you used this model to make classification, it would predict random class. So before you continue, put the weights back:

```python
layer_dict = {layer.name: i for i, layer in enumerate(model.layers)}

# Get the weights from the classifier model
weights, biases = model.layers[-2].get_weights()

# Put them into the new model
model.layers["dense_class"].set_weights((weights, biases))
```

The layer_dict lets you look up layers in the Keras model by name. That's why we gave the layers names. "dense_class" is the name of the Dense layer in the classification branch. With get_weights() you can grab a layer's weights and biases; with set_weights(), you can change the weights on a layer.

Note: In the original classifier you didn't give the layers names. In that case, Keras automatically chooses names and you can't really depend on having a certain name. That's why to load the weights, you use layers [-2]. In Python notation, a negative index means you're indexing the array from the back, so [-1] would be the last, making [-2] the classification layer. Using indices is fine but giving the layers clear names is better.

## The new loss function

With the definition of the model, you can now compile it:

```python
model.compile(loss=["sparse_categorical_crossentropy", "mse"],
               loss_weights=[1.0, 10.0],
               optimizer=optimizers.Adam(lr=1e-3),
               metrics={"class_prediction": "accuracy"})
```

There are a few things going on here. Previously, you specified a single loss, categorical_crossentropy. Here, you have specified not one but two loss functions: sparse_categorical_crossentropy and mse. The model has two outputs and each predicts something different, so you want to use a different loss for each output.

The cross-entropy loss function is great for classification tasks, but it's not suitable for bounding box prediction.

> Note: The sparse categorical cross-entropy you're using does the same thing as the regular one used in the previous chapters. It compares the predicted probability distribution with the true class label. The difference is one of convenience. Recall that the BBox returns y_class as a list of indices. In Chapter 6, "Taking Control of Training with Keras", you said that such targets need to be one-hot encoded, so y_class really ought to be (batch_size, 20) with the classes as one-hot encoded vectors. But Keras is clever: if you use the sparse_categorical_crossentropy loss function instead of the regular categorical_crossentropy, it will one-hot encode the class labels on-the-fly, saving you the effort of doing it yourself.

The loss function for the bounding box predictions is "mse" or **mean squared error**. This is a typical loss function for regression tasks, i.e., when the output of the model consists of real-valued numbers, such as bounding box coordinates. The math for this loss function looks like this:

```python
mse_loss = sum((truth - prediction)**2) / (4*batch_size)
```

Let's unpack this:

- First, it finds the difference between the ground-truth value and the prediction by subtracting the two numbers: truth - prediction. This is the **mean squared error**.
- Then it takes the square, which in Python is done with **2, so that difference will be a positive number. This also makes larger errors count since the square of a large number is much bigger than the square of a small number.
- Finally, it sums the squared differences and divides by the number of coordinates (4) and the batch size.

The weight of 10.0 versus 1.0 will encourage the model to pay more attention to errors from the bounding box output.

## Sanity checks

At this point, it's a good idea to see what happens when you load an image and make a prediction. This should still work because the classifier portion of the model is exactly as same as the last chapter.

```python
from keras.applications.mobilenet import preprocess_input
from keras.preprocessing import image

img = image.load_img(train_dir + "/salad/2ad0307c5900aac.jpg", target_size=(image_width, image_height))
```

Normalize the image and let the model loose on it:

```python
x = image.img_to_array(img)
x = np.expand_dims(x, axis=0)
x = preprocess_input(x)

preds = model.predict(x)
```

The preds variable is a list containing two arrays: The first array, preds[0], is the 20-element probability distribution from the classifier output. The second array, preds[1], has the numbers for the bounding box.

Right now, the bounding box prediction is completely bogus because those layers haven't trained yet, but the classification result should be reasonable. If not, something is wrong with the model. An easy way is to plot the predicted probabilities as a bar chart:

```python
plt.figure(figsize=(10, 5))
plt.bar(range(num_classes), preds[0].squeeze())
plt.xticks(range(num_classes), labels, rotation=90, fontsize=20)
plt.show()
```
