
Feature engineering is the art of deciding which features are important and useful for solving your problem, and it is an important part of the daily work of a machine-learning practitioner or data scientist.

In the case of machine-learning models that work on images, such as the friend face detector, the inputs to the model are the pixel values from a given photo. It's very useful to consider these pixels to be the "features" of your data as RGB values of individual pixels don't really tell you.

Instead, you want to have features as eye color, skin color, hair style, shape of the chin, shape of the ears, does this person wear glasses, they have an even scar and so on... you could collect this information about your friends and put it into a table, and train a machine-learning model to make a prediction for "person with blue eyes, brown skin, pointy ears." The problem is that such a model would be useless if the input is a photo. The computer has no way to know what's eye color or hair style is because all it sees is an array of RGB values.

You must extract these features from the image somehow. The good news is, you can use machine learning for that, too! A neural network can analyze the pixel data and discover for itself what the useful features are for getting the correct answers. It learns this during the training process from the training images and labels you've provided. It then uses those features to make the final predictions.

From your training photos, the model might have discovered "obvious" features such as eye color and hair style, but usually the features the model detects are more subtle and hard to interpret. Typical features used by image classifiers include edges, color blobs, shapes and the relationships between them. In practice, it doesn't matter what features the model has chosen, as long as you let the model make good predictions.

One of the reasons deep learning is so popular is that teaching a model to find the interesting image features by itself works better than any if-then-else rules humans come up by hand in the past. Even so, deep learning still brings benefits from any hints you can provide about the structure of the training data you're using, so that it doesn't have to figure out everything by itself.

You'll see the term features a lot in this book. For some problems, the features are data points that you directly provide as training data; for other problems, they are data that the model has extracted by itself from more abstract inputs as RGB pixel values.

# The training loop

The training process for supervised learning goes like this:

![](img/5720be5c3cca252e12448e68d25607b5_32_0.png)

The model is a particular algorithm you have chosen, such as a neural network. You supply your training data that consists of the examples, as well as the correct labels for these examples. The model then makes a prediction for each of the training examples.

Initially, these predictions will be completely wrong because the model has not learned anything yet. But you know what the correct answers should be, and so it is possible to calculate how "wrong" the model is by comparing the predicted outputs to the expected outputs (the labels). This measure of "wrongness" is called the loss or the error.

Employing some fancy mathematics called back-propagation, the training process uses this loss value to slightly tweak the parameters of the model so that it will make better predictions next time.

Showing the model all the training examples just once is not enough. You'll need to repeat this process over and over, for hundreds of iterations. In each iteration, the loss will become a little bit lower, meaning that the error between the prediction and the true value becomes smaller and, thus, the model is less wrong than before. And that's a good thing!

If you repeat this enough times, and assuming that the chosen model has enough capacity for learning this task, then gradually the model's predictions become better and better.

Usually people keep training until the model reaches some minimum acceptable accuracy, up to a maximum number of iterations, or until they run out of patience... For neural networks, it's not uncommon to use millions of images and go through thousands of iterations.

Of course, training is a bit more complicated than in practice (it's not always?). For example, it's possible to train for too long, actually making your model worse. But you get the general idea: show the training examples, make predictions, update the model's parameters based on how the predictions are, repeat until the model is good enough.

As you can tell, training machine-learning models is a brute-force and time-consuming process. The algorithm has to figure out how to solve the problem through trial and error. It's no surprise that it takes a lot of processing power. Depending on the complexity of the algorithm you've chosen and the amount of training data, training a model can take anywhere from several minutes to several weeks, on a computer with very fast processors. If you want to do serious training, you can rent time on an Amazon, Google or Microsoft server, or even a cluster of servers, which does the job much faster than your laptop or desktop

# What does the model actually learn?

Exactly what a model learns depends on the algorithm you've chosen. A decision tree, for example, literally learns the kind of if-then-else rules a human would have created. But most other machine-learning algorithms don't learn rules directly, but a set of numbers called the learned parameters, or just "parameters", of the model.

These numbers represent what the algorithm has learned, but they don't always make sense to humans. We can't simply interpret them as if-then-else, the math is more complex than that.

![](img/5720be5c3cca252e12448e68d25607b5_34_0.png)

It's not always obvious what's go' on inside these models, even if they produce perfectly acceptable outcomes. A big neural network can easily have 50 million of parameters, so wrapping your head around that!

It's important to realize that we aren't trying to get the model to memorize the training examples. That's not what the parameters are for. During the training process, the model parameters should capture some kind of meaning from the training examples, not retain the training data. This is done by choosing good examples, good labels and a loss function that is suitable to the problem.

Still, one of the major challenges of machine learning is overfitting, which happens when the model starts to remember specific training examples. Overfitting is hard to avoid, especially with models that have millions of parameters.

For the friends detector, the model's learned parameters somehow encode what human faces like and how to find them in photos, as well which faces belong to which person. The model should be dissuaded from remembering specific pixels from the training images, as would lead to overfitting.

How does the model know what a face is? In the case of a neural network, the model acts as a feature detector and it will literally learn how to tell objects of interest (faces) apart from things that are not of interest (anything else).
