Since the model was trained on 20 different object types, it outputs a probability distribution that looks something like this:

![](img/5720be5c3cca252e12448e68d25607b5_82_0.png)

### The new probability distribution

Where previously there were only two values (healthy/unhealthy), there are now 20 possible outcomes, and the 100 total percentage points are distributed over these twenty possible classes — which is why it's a probability distribution.

The app displays the three predicted classes with the highest probability values. Since there are now 20 classes, the results array contains 20 ClassificationObjects, sorted from a high to low confidence score. The prefix(3) method grabs elements 0, 1, and 2 from this array (the ones with the highest probabilities), and you map to turn them into strings.

For the above probability distribution, this gives:

```
element 0: carrot 72%
element 1: orange 15%
element 2: ice cream 8%
```

The model is fairly confident about this prediction. The first result has a pretty high score, and so you can probably believe that the image really is a carrot.

The second result is often fairly reasonable — if you squint, an orange could look like a carrot — but the third result and anything below it can be way off the mark.

Given these confidence scores, it's OK; the model really didn't think ice cream was a reasonable guess there are at only 8% confidence.

> Note: The percentages of these three choices don't have to add up to 100%, since there are another 17 classes that will make up the remainder.

Notice that, when you made these changes to the code, you removed the if statement that checked whether the confidence was less than 80%.

That check makes sense for a binary classifier, when you have multiple classes, the best confidence will be around the 60% mark. That's still a pretty decent score.

With a binary classifier and two classes, a random guess is correct 50% of the time. With 20 classes, a random guess would be correct 1/20th, or 5%, of the time.

When the multi-class model is very unsure about what is in the image, the probability distribution would look more like this:

![](img/5720be5c3cca252e12448e68d25607b5_83_0.png)

> When the multi-class model is unsure

You could add a kind of "not sure" threshold, but a more reasonable value would be 0.4, or 40%, instead of the 80% that you used with the binary classifier.

Just, like a binary classifier, the predictions from a multi-class model only make sense if you show it the types of objects it has been trained to recognize. If you give the new classifier an image of something that is not one of the 20 kinds it knows about, such as a dachshund, the model may return a very unsure prediction ("it could be anything") or a very confident but totally wrong prediction ("hot dog"). Again, you can ask what happens when an image contains more than one class.

Well, unlike the binary classifier in which predictions became certain or uncertain, a similar thing happens now the probabilities get divided over more classes:

![](img/5720be5c3cca252e12448e68d25607b5_84_0.png)

In this example, the classifier correctly recognizes apples and carrots, and it tries to split the probabilities between them. This is why you're looking at the top results instead of just the best score. In image classification, classifiers are usually scored on how well they do on their best guesses. As long as the correct answer is among the five (or three) guesses, we're happy. The top-one accuracy says, "Did the classifier get the most object right?" while the top-three or top-five accuracy says, "Did it find all of objects?" For example, if an image that scored 70% watermelon, 21% muffin, and 5% orange contained a watermelon and not an orange, it would still be counted as correct classification.

> Note: Don't confuse multi-class with "multi-label." A multi-class classifier's job is to choose a single category for an object. A multi-label classifier's job is to choose as many categories as applicable for the same object. For example, multi-label could classify an apple as "healthy", "fruit", and "red".

### Key points

To recap, doing image classification with Core ML and Vision involves the following steps:

- 1. Obtain a trained .mlmodel file from somewhere. Apple has a few on its website but usually you'll have to build your own. Learn this in the next chapter.
- 2. Add the .mlmodel file to your Xcode.
- 3. Create the VNCoreMLRequest object (just once) and give it a completion handler that looks at the VClassificationObservation objects.
- 4. For every image you want to classify, create a new VImageRequestHandler and tell it to perform the VNCoreMLRequest.

These steps will work for any kind of image classification model. In fact, you can copy the code from this chapter and use it with any classifier.

### Viewing the generated code

The main class in this source file is HealthySnacks (located near the bottom of the file). It has a single property named model, which is an instance of MLModel, the main class in the Core framework. It loads the .model from the bundle.

There are two prediction methods. The first of these takes an object of type HealthySnacksInput and returns a HealthySnacksOutput. The second one is a convenience method that takes a CixelBuffer as object input. Notice that there are no methods that take a CGImage or a CIImage with Vision.

Both HealthySnacksInput and HealthySnacksOutput are classes that implement the MLFeatureProvider protocol. Remember from the previous chapter that “feature is the term we use for learning. An MLFeatureProvider is an object that describes features to Core ML.

In the case of HealthySnacksInput, there is just one feature: an image in the form of a CixelBuffer that is 227 pixels width and 227 pixels high. Actually the model will treat each R/G/B value in this image as a separate feature, so technically speaking, the model has 227 × 227 × 3 input features.

The HealthySnacksOutput class provides two features containing the outputs of the model: a dictionary called labelProbability and a string called label. The label is simply name of the class with the highest probability and is provided for convenience.
