Run the following code in your notebook in order to create dictionaries that map text to integers:

```
# 1
in_token2int = {token : i
    for i, token in enumerate(sorted(in_vocab))}
# 2
out_token2int = {token : i
    for i, token in enumerate(sorted(out_vocab))}
out_int2token = {i : token
    for i, token in out_token2int.items()}
```

Here's how you created your conversion maps:

+   1. This dictionary comprehension — like list comprehensions, but they create objects — maps each character in in_vocab to a unique index. Sorting the vocabulary before assigning the integer values makes the values easier for you to reason about “A” comes before “B", etc. — but it isn't actually necessary for the mapping to work.

+   2. Here, you create two dictionaries, one that maps each character in out_vocab to a unique index, and one that maps from integers to characters. You only needed mapping for the Spanish characters because the model only translates from Spanish, not to it. Remember, you defined the model to use teacher forcing, which requires you to feed the English phrases into the decoder with the output from the encoder. You need to convert English characters to and from integers.

Now you've got Python dictionaries you can use to convert Spanish characters into integers, as well as convert English both to and from integers. For example, out_token2int['A'] returns the value 25, and calling out_int2token[25] gets you back 'A'.

You've got a way to turn text into numbers — so far, so good. But here's more full disclosure: You won't want to use those numbers for machine learning, either.

While neural networks require numeric input, they don't just any numbers. In this case, the numbers are stand-ins for text. But if you use these values as is, it will confuse the network because it appears as though some ordinal relationship exists that doesn't.
