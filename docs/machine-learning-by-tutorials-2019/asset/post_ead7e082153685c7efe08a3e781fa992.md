## What images without annotations?

If you have a dataset that consists of only images — and possibly class labels for the images — but no bounding box annotations, you cannot train an object detector on that dataset. Not gonna happen; ain't no two ways about it.

First, you'll have to create the bounding box annotations for each image. This can be a time-consuming process, especially since you need lots of images, but fortunately there are tools that can help. A few suggestions:

- **RectLabel**, available on the Mac App Store. It is a powerful tool with many options, but it expects the annotations to be provided as a separate XML file for each image. This is not unusual — it's the popular Pascal VOC dataset things — but it won't be to handle our CSV files. If you're getting serious about training your own object detector, definitely get this tool.
- **Labelbox** [labelbox.io](https://labelbox.io) is an online tool for labeling data for many tasks, including object detection. This is a paid service but there is a free tier.
- **Simple Image Annotator** from [github.com/syp715](https://github.com/syp715) is a Python program that runs as a local web service. As its name implies, it's pretty simple to use and offers only basic editing features. The output is a CSV file but it's not 100% compatible with the CSV format we're using.
- **Sloth**, which is available at [sloth.readthedocs.io](https://sloth.readthedocs.io), and is an advanced labeling tool. Requires Linux.
- **CVAT**, or Computer Vision Annotation Tool, which is available at [github.com/opencv/cvat](https://github.com/opencv/cvat).

This is by no means an exhaustive list, and new tools and services are springing up left and right.

There are about 800 images in the snacks dataset that do not have annotations. For the purposes of this book, you're just going to ignore those images and only train on the images that already have annotations, but if you're bored at home on a rainy Sunday afternoon and feel like labeling the remaining images, don't let us stop you.

## Your own generator

Note: We just mentioned that RectLabel uses a different format for storing the annotations (XML) and that Simple Image Annotator does use a CSV file but with different fields. Some of the other tools output JSON files. This is common. Every dataset will store its data in a slightly different way, and you'll find yourself writing small Python scripts to convert data from one to the other. A large part of any machine-learning project consists of finding data, cleaning it up and annotating it. Once the data is in the format you want, doing the actual machine learning is quite straightforward.

Previously, you used ImageDataGenerator and flow_from_directory() to automatically load the images and put them into batches for training. That is convenient when your images are neatly organized into folders, but the new training data consists of a Pandas DataFrame with bounding box annotations. You'll need a way to read the rows from this dataframe into a batch. Fortunately, Keras lets you write your own custom generator.

> Note: Instead of training on images, you'll now train on the combination of an image plus a bounding box annotation. For images that have more than one annotation, it's therefore possible that the same image appears multiple times in the same batch, although each time with a different annotation.

The code for this is in helpers.py. First, let's see the generator in action and then we will describe how it works:

```python
from helpers import BoundingGenerator

train_generator = BoundingGenerator(
    dir='data/snacks',
    height=224,
    width=224,
    batch_size=32,
    shuffle=True
)
```

Now, grab a batch from the generator:

```python
X, y_class, y_bbox = next(train_generator)
```

The shape of X will be (32, 224, 224, 3), the shape of y_class will be (32,), and the shape of y_bbox will be (32, 4). This is because the batch contains 32 images, and each image has up to 4 annotations.

The BoundingGenerator class is a subclass of Keras Sequence, which overrides a couple of methods:

```python
class BoundingGenerator(keras.utils.Sequence):
    def __init__(self, dir, height, width, batch_size=32, shuffle=True):
        self.dir = dir
        self.height = height
        self.width = width
        self.batch_size = batch_size
        self.shuffle = shuffle
        self.on_end()

    def __len__(self):
        return len(self.rows) // self.batch_size
```

The __len__() method determines how many batches this generator can produce: the number of rows in the dataframe, len(df), divided by the size of the batch. The // operator in Python means integer division.

When you use it(train_generator), Python automatically invokes the __len__()method. It should output 220. The generator produces exactly 220 batches because 7,040 rows / 32 rows = 220 batches.
