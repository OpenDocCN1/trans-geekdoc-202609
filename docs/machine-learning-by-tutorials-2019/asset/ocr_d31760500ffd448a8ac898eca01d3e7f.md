# Chapter 14: Natural Language Classification

This code sets the language on the tagger when a language is available, telling the tagger to interpret the text stored in its string property. In this case, you will have a language's two-character code, like "en" for English, and you'll create an NLLanguage object from it. You assign the language for the full range of the text, but you could assign different languages for different sections if necessary.

NLTagger offers another function named orthography, which sets even more information about the language, as its script, but Apple recommends not using unless you are sure of the value. The tagger will determine the orthography itself from the text, and setting the language — if set correctly — essentially guarantees you will end up with the correct orthography anyway.

> If your device's language is not set to English, then your results for the rest of this section may not exactly match what is described in the chapter. In ViewController.swift change Locale.current.languageCode to be just the string "en". This will force the tagger to assume all search terms are English.

Build and run the app, then you out test those searches. How well do they work?

+   * Typing either sing or singing produces the same set of all three reviews that include "singing". Nice!
* Searching for dance or dancing gives the same single result, but we know there are other reviews that contain the word "dancing". Better, but not quite right yet.
* Now, typing bueno or buena each give zero results. Uh oh, things are going in the wrong direction again. Coding is hard!

These errors are caused by two different issues, solving one will solve the other well enough for this chapter's purposes.

The first problem — the one you won't fix here — with the code you wrote earlier in findMatches. passes the language of the language currently on the device. This will not always be correct — for example, when the user's iPhone is set to English but they searching for a Spanish term like "bueno". Now that we are setting the language directly, the NLTagger no longer determines it automatically, so it doesn't recognize it as Spanish and cannot lemmatize it.

A better approach would be first letting the NLTagger try to determine the language and only resorting to the user's default language when that fails. We won't show that
