with over 5,000 for each of the gestures and over 13,000 for rest_it. On the other hand, each of the *incorrect* predictions happened only a small number of times, the finest being rest_it predicted as drive_it only 17 times and the most drive_it predicted as rest_it 184 times. Almost all of the errors involved the rest_it activity, which you would expect. After all, you never know what people did while recording their rest_it — they may have been doing the gestures!

In fact, notice that the only incorrect predictions that *did not* involve the rest_it activity were the 176 chop_it gestures predicted as shake_it. It makes sense that there might be mistakes between these two gestures, chopping is actually quite similar to shaking — if a person chops quickly it might appear similar to a shake, or if the shake is over exaggerated it might look a bit like a chop.

Keep in mind, your model's performance in view may be better than its test results, because if you're still unhappy with the model, you should create another one. Some stickers will tell you not to reuse your training data because it will be leaking data into your model. Technically true, and you should listen to them...unless you have an endless stream of free data available, you probably don't have the luxury of just one per test set. The good news is — in many cases that's probably ok. For example, with a project like this one, the app will perform well, and your test data is just a tool to help you get there. Your model works well on that, so you'll run it on actual devices with live data from real people. Those are real tests, and they are all unique — so you can even tell those stickers you're using a new test set for each! Metrics like test accuracy are great, but it is better to test your app with many people before releasing it, so you know it really works the way you want to.

When you think your model is ready for testing on a device, go ahead and save it with the following code:

```
model.export_coreml("GestureClassifier.mlmodel")
model.save("GestureClassifier")
```

This exports to Core ML for your app, and saves a copy that you can reload in Python in case you want to work with it later.

You've saved your model, trained to analyze iPhone motion data and recognize that data indicates specific gestures have occurred. It performs well, at least when tested against *recorded* motion data. That's a good start, but you want it to work in real time, evaluating motion data as it's *produced on the device*.
