# Machine Learning

# Chapter 7: Going Convolutional

You've seen the Dense and Activation("softmax") layers before. The Flatten layer is gone. This model also has a few new layer types. Let's take a look at Conv2D first. As you probably guessed from the name, these are convolution layers.

A Conv2D layer takes the following arguments:

- **The number of filters.** In the first Conv2D layer this is 32. As in most convnet designs, convolutional layers get more filters (output channels) as you go deeper into the network. The last Conv2D layer in this model has 256 filters. Recall that each filter learns to detect a unique pattern, and so the more filters you have the more patterns the model can detect. The number of filters is often a power of two, but this is not a hard-and-fast rule — feel to break it.

- **The size of the kernel window.** For all Conv2D layers in this model, the kernel is 3×5 pixels. You can write this as (3, 3) but because square kernel windows are common, you can also specify the kernel size as just 3 and Keras understands that you mean a 3×5 window.

- **The padding.** By default, padding in Keras is "valid", which means the pixels at the edges are ignored and the output image shrinks a little. Most of the time you use "same" padding instead, which adds an imaginary border of empty pixels around the edges so the output image keeps the same width and height as the input image.

- **A non-linear activation function.** The activation that's most typically used with convolution layers is ReLU.

The first layer in a Keras model must also specify an input_shape. This tells Keras the size of the images to expect. Height goes before within these tensors.

In between the convolution layers are MaxPooling2D layers. **Pooling** is a technique that makes the data smaller as it flows through the network, also known as subsampling. Most convnets are built from a combination of convolution layers and pooling layers. You'll learn more about pooling later in this chapter.

The output of the first conv layer, named conv2d_1, is a tensor of size (None, 224, 224, 32). Instead of 3 channels, this layer's output now has 32 channels. That's because this convolution layer has 32 filters, and there is one channel in the output for each filter.

> Note: We put "image" in quotes because the output from this layer is no longer something we can properly display on the screen. From now on we'll call these tensors.

The second conv layer, conv2d_2, takes this (None, 224, 224, 32) tensor and produces a new tensor of the same size. Because the second layer also has 32 filters, it also outputs 32 channels.

It's important to note that even though the input tensor and the output tensor for this layer both 32 channels, these are totally unrelated. The number of filters in the layer is independent of the number of channels in the input tensor. It just happens that these two numbers are the same for this particular layer. However, the number of output channels for a layer is always the same as the number of filters it has.

Each filter will reduce all of the 32 channels to a single channel in the output tensor. This is repeated 32 times because this layer has 32 filters, and each filter has its own set of weights and therefore learns to detect its pattern. To detect the pattern, each filter always looks at all of the input channels.

# More about pooling

After the two convolution layers there is a pooling layer, max_pool_2d_1. The job of this layer is to halve the spatial dimensions of the tensor, producing a new tensor that is 112×112 pixels wide and tall. The number of channels stays the same, 32.

The pooling layer simply takes the maximum value of each 2×2 group of pixels and writes it to the output tensor. It does this channel independently, which is why the number of output channels doesn't change.

A pooling layer does not have any learned parameters, it performs this very simple max operation on a 2×2-pixel window:

![](img/57205c3cca252e1244e68d25607b5_255_0.png)

# Max pooling reduces 2×2 pixels to a single number

Because it takes the maximum value, operation is called max pooling. There is also a type called average pooling that takes the average or max of the pixels in that 2×2 window instead—you're actually using one of these average pooling layers at the end of the network. More about this in the next section.

It is standard for pooling layers to use a 2×2 window size. Just like convolution, this window slides over the input image, but with a step size of 2. This step size, stride, what determines the spatial dimensions of the output tensor. A stride of 2 means the width and height get half. Usually, the stride is the same as the window size, but sometimes you'll see other combinations, such as a window size of 3 with a stride of 2, in which successive windows overlap each other a little.

Why these pooling layers? The main reason is to reduce the size of the data you're working with—by keeping the most interesting parts of the image. As you've seen, convolution measures how well parts of the image respond to a learned pattern. Because max pooling only keeps the largest and therefore most important values, it helps to make the predictions less sensitive to small variations in the data. Resizing the input also increases the receptive field, or the portion of the input image that is covered by the convolution layers that follow the pooling layer.
