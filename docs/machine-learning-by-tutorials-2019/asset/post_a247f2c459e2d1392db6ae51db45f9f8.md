There is one more piece of data to gather before you can start training — the name of each class. The images are stored in subdirectories named after the classes — "apple", "hot dog", etc. The SFrame knows the path the image was loaded from, but these paths look like this:

```
snacks/train/hot dog/8ace0a9a1ed2ff6.jpg
```

For the class image 8ace0a9a1ed2ff6.jpg is "hot dog", but it's hidden inside that long path. To make this obvious, you'll need to write some code to extract the class name from the path. Run the following commands to extract the name of the first class's folder:

```python
# Grab the full path of the first training example
path = train_data[0]["path"]
print(path)
```

### Find the class label
```python
import os
os.basename(os.path.split(path)[0])
```

You're getting the full path of the first image, then using the os.path Python package for dealing with names. First, os.path.split() chops the path into two pieces: the name of the file (8ace0da8a912ed2f6.jpg) and everything leading up to it. Then os.path.basename() grabs the name of the last folder, which is the one with the class name. Since the first training image is of an apple, you get ""

> Note: The # character starts a comment in Python. Note that you need to import the os package, or else Python won't know what os.path is.

### Getting the class labels

OK, now you know how to extract the class name for a single image, but there are over 4,800 images in the dataset. As a Swift programmer, your initial instinct might be to use a loop, if you're really Swift-y, you'll be itching to use a map function. SFrame has a apply() method that, like Swift's or forEach, lets you run a function to every row in the frame:

```python
train_data["path"].apply(lambda path: ...do something with path...)
```

In Python, a lambda is similar to a closure in Swift — it's a function without a name. train_data["path"].apply(lambda) performs this on every row in the path column. The lambda above provides code snippet that you need to extract the class name from the path

```python
train_data["Label"] = train_data["path"].apply(lambda path: os.basename(os.path.split(path)[0]))
```

Run the cell and the SFrame will have a new column "label". To verify this, run train_data.head() — do this in a new cell, or scroll up to the fact, and press Control-Enter.

### Let’s do training

Once you have your data in SFrame, training a model with Turi Create takes only a single line of code (OK, it’s three lines, but we have to fit it):

```python
model = tc.image_classifier.create(train_data, target="label", model="VisionPrint_Scene", verbose=True, max_iterations=50)
```

Alternatively, if training takes too long on your Mac, you can just load the Turi Create model from the current folder:

```python
model = tc.load_model("HealthySnacks.model")
```

This command creates a new image classifier from the train_data SFrame. The target parameter tells Turi Create that the class names are in the SFrame's label column. By default, Turi only does 10 iterations, but you increase this to 50, so the logistic regression will train up to 50 iterations.

The first time you run this, Turi downloads a pre-trained neural network. The model parameter contains the name of that neural network, in this case VisionPrint_Scene. This model is used by Apple's Vision framework, and is also the default for Create ML.

At the time of writing, Turi supports three model architectures: The other two are ResNet-50 and SqueezeNet version 1.1. ResNet-50 exports a Core model ~90MB, which is not really suited for use on mobile devices. SqueezeNet exports a Core model ~4.7MB, so it's a better option. VisionPrint_Scene is built into iOS 12, so it produces a much smaller model ~41 KB.
