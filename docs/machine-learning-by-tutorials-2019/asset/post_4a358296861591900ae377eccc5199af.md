Modern hardware comes packed with sensors — depending on the model, you might have access to an accelerometer, gyroscope, speedometer, magnetometer, altimeter or GPS. You may have even access to the user's heart rate!

With so much data available, there are countless possibilities for behaviors you can detect, sporadic actions like standing up on a chair or falling off a ladder, as well as activities that occur over longer durations like jogging or sleeping. And machine learning is the perfect tool to make sense of it all. Before you can fire up neural nets, you'll need a dataset to train them.

## Building a dataset

So you've got an app to power using machine learning. You do the sensible and scour the internet for suitable, freely available dataset that meets your needs. You try to Google Dataset Search, check popular data sites like Kaggle, and exhaust every keyword search you know. If you find something — great, move on to the next section! But if your search for a dataset turns up nothing, all is not lost — you can build your own.

Collecting and labeling data is the kind of thing professors make your graduate students do — time consuming, tedious work that may make you want to cry. When labeling human activity data, it's not uncommon to record video of the activity session, go through manually to decide when specific activities occur, and label the data using timecodes synced between the recordings and the video. That might sound like fun to some, but people are wrong and should never be trusted.

This chapter takes a different approach — the data collection app adds labels. They may not be as exact — manual labeling lets you pinpoint precise when moments test begin or end an activity — but in many cases, they're good enough.

To get started, download the resources for this chapter if you haven't already done so, and open the GestureDataRecorder starter project in Xcode.

Why require a user ID? You'll learn more about this later, but it's important to be able to separate samples in your dataset by their sources. You don't need specific details about people, like their names — in fact, identifying details that are often a bad idea for privacy and ethics reasons — but you need some way to distinguish between samples.

GestureRecorder takes a simple but imperfect approach to this problem: it expects users to provide a unique identifier and saves data for each user in separate files. To do this, the app asks for an ID number and then includes that in the names of the files it saves. If any files using that ID already exist on this device, the app requests confirmation and appends new data to those files. So it trusts users not to append their data to someone else's files on the device, and it's up to you to ensure no two users use the same ID.

You need to tell locationManager how often to produce sensor data. ViewController stores its configuration-related constants in its Config struct, so add the following constant:

```
static let samplesPerSecond = 25.0
```

Here you set samplesPerSecond to 25, which you'll use to specify if you want the device to use 25 sensor updates every second. This number is important because it determines how much data your model looks at how often you perform predictions. That is, if you classify the user's activity per second, this gives you 25 samples per classification; if you do it every four seconds, this rate gives you 100 samples.

But why 25? The sensors in Apple devices are capable of producing updates many times per second — at least 100, according to the docs — so you shouldn't just use the max? After all, aren't people always saying that when it comes to machine learning, more data is always better?

There are a few reasons why you shouldn't necessarily increase the update frequency too high:

- More updates mean more data processing, which means less CPU available for whatever your app needs.
- Faster updates usually mean feeding more data into your model prediction. That requires more ML models, which will run more slowly — maybe too slowly to keep up with those faster updates.
