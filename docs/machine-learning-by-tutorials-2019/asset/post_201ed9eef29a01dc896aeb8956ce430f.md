You should resist the temptation to go back and tweak your model to improve the test performance. You don't want the test set images to influence how the model is trained, making the test set no longer a good representation of unseen images. It's probably fine if you do this a few times, especially if your model isn't very good, but it shouldn't become a habit. Save the test set for last and evaluate on it as few times as possible.

Again, the question: Is 88% correct a good score or a bad score? It means more than one out of 10 images is scored wrong. Obviously, we'd rather see an accuracy score of 99% (only one out of 100 wrong) or better, but whether that is feasible depends on the capacity of your model, the number of classes, and how many training images you have.

Even if 88% correct is not ideal, does it mean your model has actually learned quite a bit. After all, with 20 classes, a totally random guess would be one out of 20 times or 5% on average. So the model is already doing much better than random guesses. But it looks like Create ML isn't going to do any better than this with the current dataset.

Keep in mind, the accuracy score only looks at the top predicted class with the highest probability. If a picture contains an apple, and the most confident prediction is "hot dog," then it's obviously a wrong answer. But if the top prediction is "hot dog" with 40% confidence, while the second highest class is "apple" with 39% confidence, you might still consider this a correct prediction.

SqueezeNet as the feature extractor — it's 5MB. Your new model from Create ML is only 312KB! It's actually a bigger model, but most of it — the VisionFeaturePrint_Screen feature extractor — is already included in the operating system, and so you don't need to distribute that as part of .mlmodel file.

A Core ML model normally combines the feature extractor with the logistic regression classifier into a single model. You still need the feature extractor because, for any new images you want to classify, you also need to compute your feature vectors. With Core ML, the logistic regression is simply another layer in the neural network, i.e., another stage in the pipeline.

However, a VisionFeaturePrint_Screen Core ML model doesn't need to include the feature extractor, because it's part of iOS. So the Core ML model is basically just the logistic regression classifier, and quite small!

> Note: There are few other differences between these two feature extractors. SqueezeNet is a relatively small pre-trained model that expects 227×227 images, and 1,000 features. VisionFeaturePrint_Screen uses 299×299 images, and extracts 2,048 features. The kind of knowledge that is extracted from the image by the Vision is much richer, which is why the model you trained with Create ML actually performs better than the SqueezeNet-based model from the previous chapter, which has only a 67% validation accuracy!

## Recap

In this chapter, you got a taste of training your Core ML model with Create ML. Partly due to the limited dataset, the default settings got only about 90% accuracy. Increasing max iterations increased training accuracy, but validation accuracy was stuck at ~90%, indicating overfitting might be happening. Augmenting the data with flipped images reduced the gap between training and validation accuracies, but you'll need more iterations to increase the accuracies.

More images is better. We use 4,800 images, but 48,000 would have been better, and 4.8 million would have been even better. However, there is a real cost associated with finding and annotating images, and for most projects a few hundred images or at most few few images per class may be all you afford. Use what you've got—you can retrain your model at a later date once you've collected more training data. Data is king in machine learning, and who has the most of it usually ends up with a better model.

Create ML is super easy to use, but lets you tweak only a few aspects of the training process. It is also currently limited to image and text classification models.

Turi Create gives you more task-focused models to customize, and lets you get more hands-on with the training process. It's almost as easy to use as Create ML, but you write Python. The next chapter gets you started with some useful tools, so you can train a model with Turi Create. Then, in Chapter 5, "Digging Deeper Into Turi," you'll get a closer look at the training process, and learn more about the building blocks of neural networks.

## Key points

- You can use macos playgrounds to test out Create ML, and play with the different settings, to create simple machine learning models.
- Create ML allows you to create small models that leverage the built-in Vision feature extractor already installed on iOS 12+ devices.
- Ideally, you want the validation accuracy to be similar to the training accuracy.
- There are several ways to deal with overfitting: include more images, increase training iterations, or augment your data.
- Precision and recall are useful metrics when evaluating your model.
