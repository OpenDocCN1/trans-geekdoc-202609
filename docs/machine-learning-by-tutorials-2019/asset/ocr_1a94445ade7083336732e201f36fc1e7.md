While these methods are essentially updating an array, there are some important things to note:

+   1. The addToBuffer function isolates the NSNumber casts to one line, which keeps the code at // 5 easier to read. Declaring it with @inline(__always) tells the Swift compiler to replace any calls to this function with the contents of the function itself, ensuring your code executes as quickly as possible. Swift is good at inlining these one-line functions on its own, but including this tag marks your intention.

+   2. This list sets a single value inside dataBuffer. That MultiArray is arranged as a 3-dimensional tensor, indexed by [batch, sample, feature]. The model's size is always one, so the first index value is always 0. The sample and feature indices are passed as arguments to this method.

+   3. You'll call bufferMotionData from within processMotionData, which you'll write next. It copies data into the correct locations in the large buffer backing the overlapping prediction windows described earlier.

+   4. For loop enters each value is stored at the position indexed by bufferIndex, as well as a position that is one-span later in the buffer. The continue statement ensures second write is not outside the buffer's bounds, which would crash the app. For more details about how the overlapping windows work, refer to the discussion earlier in this chapter.

+   5. Here you call addToBuffer repeatedly to save the relevant data from the CMDeviceObject object passed to this method. It is extremely important to store only the features that your model expects, and in exactly the order it expects. This was all determined when you trained the model, but you can verify the information by inspecting the .model in Xcode's Project Navigator. Be sure to double check this, because mistakes will make your model function incorrectly—sometimes failing with a crash, sometimes underperforming, and even by appearing to work! That last one might sound ok, but you've just got some lucky input and it's unlikely to work for long.
