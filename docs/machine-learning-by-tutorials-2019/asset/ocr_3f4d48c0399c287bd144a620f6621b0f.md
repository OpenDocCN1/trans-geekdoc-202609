Note: If you're training your own embeddings, you would define your vocabulary differently. You'd most likely start by counting the uses of each token in your training data, and then choosing some of most commonly used terms. Those terms define the vocabulary for which you'd train embeddings.

Once you've settled on the vocabulary you'll support — let's assume it's a set of tokens stored in in_vocab — you need to go through all your training, validation test data and replace any OOV tokens with the appropriate <UNK> token(s). This is different from how you removed OOV from your datasets when you work with characters.

At this point your embeddings are likely in a dictionary keyed off of tokens, and it may contain more embeddings than you actually plan to use in your vocabulary. You'll need to put the embeddings for these individual vocabulary words into a single NumPy array to use with your network, like this:

```
# 1
num_enc_embeddings = in_vocab_size + 1
# 2
pretrained_embeddings = np.zeros(
    (num_enc, embedding_dim), dtype=np.float32)
# 3
for i, t in enumerate(in_vocab):
    pretrained_embeddings[i+1] = es_token_vectors[t]
```

Here's how you'd grab the embeddings for your words in your vocabulary:

+   1. Your encoder will need to embed each token in your vocabulary, plus an additional embedding to act as a padding token during training.

+   2. Create a NumPy array of all zeros, shaped to hold the correct number of embeddings embedding_dim. You can find pre-trained embeddings in various dimensions, especially for English, but it seems 300 is the most common. Embeddings of that size for a reasonably-sized vocabulary may give you models that are too big for mobile devices, so you may need to train your own if you cannot find smaller embeddings for the language you need.

+   3. Notice how each embedding is stored with the index i+1. This leaves zero unassigned, which is the value reserved by Keras's Embedding layer for the padding token. You'll read about the Embedding layer next.
