It takes only five lines to define how many LSTM uses to represent them, but there's a lot to say about them:

+   1. The latent_dim variable defines how many LSTM uses to represent each recurrent step internally. In turn, defines the size of the feature vectors used to store the encoding produced by the encoder. In machine learning, we refer to the process of converting an input into a set of features as mapping it into latent space. Latent dim defines the dimensions in the encoder's space as 256. This value directly affects the size and speed of your model: Larger values produce better, slower models. However, with more dimensions technically can learn more complicated relationships than what might produce better results. That, if you can train them — the larger you model, the more data you need to train it. There are a lot of things involved with finding the right value here, but we chose this value arbitrarily. We encourage you to experiment with other values after you've finished the chapter.

+   2. Here, make an Input layer, which you'll pass batches of sequences during training. You specify two dimensions — None and in_vocab_size. The None tells Keras that you need to support variable length inputs. Then, you'll be able to pass sequences of any length, which is good because sentences can come in any in_vocab_size tells how large the vectors are that hold each character — the same size as how many possible tokens exist in the vocabulary. Essentially, these two dimensions tell Keras that each input sequence will consist of any number of characters, where each character is represented by a vector of length in_vocab_size. This will be more clear after you read about one-hot encoding.

+   3. You pass the input layer through a Masking layer. This layer tells the network to ignore any timestamps in the sequence that are filled with zeros.
