# Machine Learning Chapter 16: Natural Language Transformation, Part 2

This encoder uses a bidirectional RNN with GRU layers. Here's how you set it up:

+   1. The Input and Masking layers are identical to the previous chapter's encoder.

+   2. Rather than creating a recurrent layer, you create two — one that processes the sequence normally and one that processes it in reverse you set go_backwards=True. You feed the same masking layer into both of these layers.

+   3. Finally, you concatenate the outputs from the two GRU layers so the encoder can output them together in a single vector. Notice that, unlike in the previous chapter, you don't use the h states and instead use layer outputs. This wasn't mentioned before, but that works because the hidden states are the outputs. The reason you use for the LSTM was to get the cell states, which are not returned as outputs like the hidden states.

As far the decoder, one important difference is in the size of the inputs it accepts. We define a new variable called decoder_latent_dim, like this:

```
decoder_latent_dim = latent_dim * 2
```

The decoder layer needs as many units as the encoder did because it accepts a vector that contains the concatenated outputs of them — forward and reverse.

The other differences with the decoder are in the following lines:

```
decoder_gru = GRU(
decoder_latent_dim, return_sequences=True,
return_state=True, dropout=0.2, recurrent_dropout=0.3,
name="decoder_gru"
decoder_gru_out, _ = decoder_gru(
decoder_mask, initial_state=decoder_out)
```

Once again, you use a GRU layer instead of an LSTM, but use decoder_latent_dim instead of latent_dim to account for the forward and reverse states coming from the encoder. The GRU only returns hidden states, which you ignore for now assigning them to an underscore variable. This differs from the LSTM you used in the previous chapter, which returned both hidden and cell states.

> Note: One important detail is that the decoder does not implement a bidirectional network like the encoder does. That's because the decoder doesn't actually process whole sequences — it just takes a single character along with state information.
