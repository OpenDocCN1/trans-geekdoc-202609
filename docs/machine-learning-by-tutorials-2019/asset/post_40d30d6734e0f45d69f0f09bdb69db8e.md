# The YOLO model in Core ML

The model description indeed indicates this is an object detector using Darknet and YOLO, with non-maximum suppression.

The type of the model is not a neural network but a pipeline. In machine learning terms, a pipeline is several layers that glued together so that the output of one is used as the input for the next model in the pipeline. In this case, the object detection model is followed by a non-maximum suppression (NMS) model.

Also, note that the Detector has three inputs and two outputs. In addition to the regular image input for a 416×416 color image, there are two inputs named `iouThreshold` and `confidenceThreshold`. These two values are used by NMS to decide which bounding boxes it should keep. The higher you set the confidence threshold, the larger the confidence score on a predicted box has to be in order to keep. The IOU threshold determines when overlapping boxes are too small. A lower value means boxes that only overlap a bit are considered duplicates. Even though you saw earlier that YOLO produces a single tensor of size 13×13×S, the Core ML model actually has two outputs. The Core ML pipeline applies NMS to the predictions from YOLO and outputs the best bounding boxes or a different number of boxes depending on how many objects are in the image. For convenience, Core ML provides the class predictions and coordinates as separate values. However you don't have to worry about these inputs and outputs because you're going to be using this model through the Vision framework. Most of the source code in `ViewController.swift` is exactly the same as in the previous example.

The only thing that's different is the result object returned by Vision. Previously the result objects were of type `VNClassificationObservation`, but now they are `VNRecognizedObjectObservation`. This is a new class that was added to Vision with iOS 12, and your app needs to handle these `VNRecognizedObjectObservation` instances. The fun stuff happens in `processObservations(_:)`, which is called from the completion handler for the Vision request. If the array is empty, no objects were found. In that case the app removes any previous rectangles from the screen.

![](img/5720be5c3cca252e12448e68d25607b5_353_0.png)

The logic for interpreting the Vision results lives inside `showPredictions()`. This simply loops through VNRecognizedObjectObservation instances, converts the predicted coordinates to screen coordinates, and shows rectangles for the detected objects using BoundingBox.

- The `VNRecognizedObjectObservation` has labels of `VNClassificationObservation` instances, sorted from highest probability to lowest, telling the app simply grabs the most likely classes for the object inside the bounding box from the list, and puts its identifier and confidence into the label's.
- There is also a `boundingBox` property, a CGRect that tells you where in the image is located. This uses normalized coordinates again, but with the origin of the CGRect in the lower-left corner. It's a little awkward, but that's how Vision does things. In order to draw a rectangle around the object, you need to transform the normalized coordinates to screen coordinates and also flip the y-axis.

Just an FYI: This picture was taken while pointing the iPhone at a picture on a Mac. This is a quick way of testing the model works — just look up some pictures on Google Images — but be aware that the interaction of the computer display display with the camera's sensor may cause artifacts to appear in the image that can throw off the model. If users pointing their phones at computer screens is going to be a major use case for your apps, then you'll need to train the model to ignore those artifacts and distortions.

One limitation of Vision was that it could only provide a value for the model's image input, as of iOS 13, you can also pass in values for the other inputs to override defaults from the model. See the VCoreML object:

```
if #available(iOS 13.0, *) {
  visionModel.input.featureName = "image"
  visionModel.featureProvider = try MLDictionaryFeatureProvider(
    "iouThreshold": MLFeatureValue(double: 0.45),
    "confidenceThreshold": MLFeatureValue(double: 0.25)
  )
}
```

With a bit of effort, it's possible to make YOLO on iOS 11. In that case, Vision does not give you `VNRecognizedObjectObservation` instances but a `VCoreMLFeatureValueObservation` with the contents of 13×13 grid. You'll have to decode these into actual bounding boxes and perform NMS yourself to find the best. The YOLO models built by Turi Create work with iOS 11, but there are also Keras of YOLO available. For an example of how to run a YOLO model on iOS 11, see github.com/hollance/YOLO-CoreML-MPSNNGraph.
