# # Adding a search feature

In this section, you'll use NLTagger for another task: **lemmatization**. That's the process of identifying the root version of a word. For example, consider the sentences, "I am running" and "I was running." Reducing each to its root, both sentences become: "I be running." Sure, it no longer reads as correct, but it encapsulates *most* of the information contained in both sentences.

Historically, it's been considered necessary to preprocess text by lemmatizing it because it reduces the size of the vocabulary. However, you'll learn more about vocabulary sizes in the next chapter, but intuitively, the larger they are the more difficult they are to support. So rather than needing to understand "run," you would just need to handle "run." As you can see in this example, some important contextual information, such as tense, gets lost in the translation. For some tasks, like machine translation, it is now common to use text without lemmatizing in order to get more accurate results.

> **Note: Stemming versus lemmatization.** You'll probably encounter both of these terms, often seemingly interchangeably. In the case of stemming, the root is called a stem; in the case of lemmatization, it's called a lemma. These are essentially the same thing, but the process for generating them is different. Stemming involves basic rules like removing "ing" and "s" from the ends of words, which is fast and easy to implement but doesn't always produce the best results. On the other hand, lemmatization involves using a specific vocabulary for a language and applying more complex rules. It's more involved but usually better results.

You'll use the SMDB app to support more sophisticated searches. When the user searches terms, the app will find all reviews containing those terms. But rather than only supporting matches, you'll broaden the results by using lemmas. So when a user enters a word like "run," you'll make the app finds reviews using other forms of the word, like "running," too. Convenient!
