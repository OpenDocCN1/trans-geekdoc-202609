+   * **Typing** and **singing** now both give the same results: nothing! Seems like a downgrade.
* **Type dance** and you'll get zero results, while **dancing** gives you the one result that "dance" used to give you. Downgrade number two.

These new errors occur because NLTagger sometimes has lemmatizing short texts. You can test this by typing just the letter "I", which will produce no results. Now continue typing you search for "I sing". You'll find as you starting the second word, regardless of what you type, you'll get all the results that have the word "I" in them.

That's because now NLTagger sees it as a sentence and has a better guess about "I" being a word. Once you get to "I sing", you'll get all the reviews that contain "singing" — even if they do not contain the word "I".

The primary cause of this difficulty is that NLTagger can't always determine the language of texts, and lemmatization requires language-specific knowledge. With longer samples, it's usually no problem, which you saw when you identified the languages for the reviews. With shorter texts it's a good idea to help it if you.

So how do you do it? By telling the tagger what language you're using prior to it to lemmatize the text. Remember unused language parameter in getSearchTerms? Now is time to use it.

Back in NLPHelper.swift, add the following lines inside getSearchTerms, just before the options line :

```
if let language = language {
    tagger.setLanguage(NLLanguage(rawValue: language),
    range: text.startIndex..<text.endIndex)
}
```
