### 简介

编写考试**从来不是一件容易的事**。苏格拉底曾说：“未经审视的人生是不值得过的”，但（尽管他并非真指参加技术测试），我们确信，坐在考场里的大多数人都会乐意与这位传奇哲学家互换位置，喝下他的毒芹汁，也不愿参加考试。

幸运的是，编写考试*不必*成为如此创伤性的经历。只要准备充分且经验丰富，你应该能顺利通过，而不会遇到太大麻烦。Zend 考试的设计初衷有两个目标：第一，测试你对 PHP 的掌握程度；第二，尽可能采取实用的方法来进行测试。

仅测试 PHP 知识这一想法基于一个简单的假设：你作为 PHP 程序员的经验，不应由你对外部技术的了解来衡量。正如我们将在第 9 章重申的那样，你可能一辈子都在用 PHP 开发，却从未需要连接 MySQL 数据库，因此，测试你的 MySQL 知识将是衡量你对 PHP 熟悉程度的不公平方式。此外，MySQL AB（以及大多数其他相关的第三方软件供应商）已有自己的认证计划。

至于问题的实用性，没有一位主题专家（SME）认为优秀的程序员应该是一本会走路的 PHP 参考手册。事实是，PHP 提供了超过 1,500 个不同的函数——了解每一个函数及其所有细微差别，不仅实际上不可能，而且也毫无用处。PHP 手册随时可在世界任何地方在线获取；因此，除非有人把你关在一个没有互联网接入的房间里，否则你无法访问它的可能性微乎其微。尽管如此，如果你每三十秒就要查阅一次手册，就无法编程，因此考试确实包含以非常指导性的方式测试你对某些基本 PHP 功能掌握程度的问题。

然而，在很大程度上，考试测试的是你理解、解读和编写正确 PHP 代码的能力。准备好分析大量代码示例，以弄清它们的作用、工作原理以及是否存在 Bug。有些问题可能看起来有点棘手且过于复杂，但仔细想想，处理不完美的代码（当然是别人写的！）对于曾在现实世界工作过的任何人来说，并不罕见。

#### 为什么要有这本练习题书？

以尽可能充分的准备参加考试总是最好的。你的经验，以及像 SAMS 出版的《Zend PHP 认证学习指南》这样的书籍，将是确保你通过考试的宝贵工具，但坐下来参加考试本身，与你日常工作中可能做的任何事情都截然不同。

本书为你提供了一系列高度结构化的问题，旨在模拟（而非复制）你在考试中将遇到的实际问题。它将帮助你“进入考试状态”，了解问题的措辞方式，以及它们期望你具备哪些能力。

我们努力构建的问题虽接近真题，但通常稍难一些。理由很简单：如果你能答对难题，真实考试就会轻而易举！

#### 本书如何组织？

《Zend PHP 认证练习测试书》旨在作为 SAMS Publishing 出版的《官方 Zend PHP 认证学习指南》（ISBN 0672327090）的配套教材。因此，其章节紧密对应指南的章节，以最大程度便利你的学习过程。你可以先阅读指南的一章，然后翻到练习题书中对应的章节，参加一个专门针对该特定主题的小测验。或者，你也可以结合 PHP 手册，将本书作为测试资源使用。我们的目录将为你提供考试涵盖主题的基本框架，你可以据此直接从手册以及互联网上许多其他资源进行学习。一旦你觉得准备好尝试答题，就可以再次使用本书为此目的服务。

除第 1、2、5、6 章包含二十道题外，每章均包含十五道题。原因在于这些章节讨论 PHP 最基础的方面；因此，我们认为每章增加几道额外题目可能有助于你更好地评估准备情况。你将在每章末尾找到所有问题的答案及解析。

虽然你当然可以随意使用本书，但我们建议一种简单的方法，帮助你最大化其效果。首先，你应该在真正有时间的时候练习测试——预留至少九十分钟答题，再预留三十到六十分钟核对答案。

从每个十五题的章节中答五道题，从二十题的章节中答六道题开始。按顺序完成每章，中途不停下来核对答案。这将累计约六十五道题，非常接近实际考试的七十道题。给自己约八十分钟完成整套题目——这也是真实考试分配的九十分钟的良好模拟。

过程结束后，你可以回过头将你的答案与每章末尾给出的正确答案进行核对。这将让你有机会确定自己在各个不同领域的准备程度，并将学习重点放在成绩不太理想的主题上。

一旦你感觉准备好，可以再次使用相同技巧尝试。这将使你每次都能回答一批新题目，重新检验你的知识。

**19.** 以下哪些表达式将整数变量 `$a` 的值乘以 4？（选择 2 项）

A. `$a *= pow(2, 2);`
B. `$a >>= 2;`

**20.** 脚本如何才能干净地终止？

A. 当调用 `exit()` 时
B. 当执行到达当前文件末尾时
C. 当 PHP 崩溃时
D. 当 Apache 因系统问题终止时

### 答案

**1.** 查看选项，唯一一个让每个空白都讲得通的是 B。PHP 是一种基于 Zend Engine 的脚本语言，通常嵌入在 HTML 代码中。因此，它主要用于开发 HTML 文档，尽管它也可以同样很好地用于开发其他类型的文档，例如 XML。

**2.** 虽然诸如 `<% %>` 和 `<?= ?>` 之类的标签在 PHP 编程中经常被忽略，但它们是界定 PHP 代码块的有效方式。然而，`<!` 和 `!>` 标签无效，因此正确答案是 D。请记住，无论如何，这些标签中的一些并不总是可用的，这取决于 PHP 解释器运行所在的 `php.ini` 文件是如何配置的。

**3.** PHP 变量总是以美元符号开头，并且是拉丁字母表中的字符和数字的序列，加上下划线字符。`${"MyVar"}` 是一个有效的变量名，只是使用了一种稍微不太常见的命名约定，而 `&$something` 是对 `$something` 变量的引用。然而，变量不能以数字开头，这使得 `$10_somethings` 无效，因此答案 D 正确。

**4.** 这里要注意的重要一点是 `$myarray` 数组的键值是在没有引号的情况下被引用的。因此，被访问的键不是字符串 `myvalue`，而是由常量 `myvalue` 所代表的值。因此，这等同于访问 `$myarray[10]`，其值为 `Dog`，答案 A 正确。

**5.** 尽管 `print()` 和 `echo()` 在大多数情况下基本上可以互换，但它们之间存在实质性差异。虽然 `print()` 的行为类似于具有自身返回值的函数（尽管它是一个语言结构），但 `echo()` 实际上是一个没有返回值的语言结构，因此不能用在表达式中。因此，答案 A 正确。

**6.** 除了简单的数学运算外，`%` 运算符是取模运算符，它返回其两个操作数相除后的余数。`<<` 运算符是左移运算符，它实际上将整数乘以 2 的幂。最后，最终答案乘以了一个浮点数，因此其类型会相应改变。然而，结果仍然会在没有任何小数部分的情况下打印出来，因为小数部分为零。最终输出是 256（答案 D）。

**7.** 遵循条件的逻辑，到达 `Hello, World!` 字符串的唯一途径是第一个 `if` 语句的 `else` 分支。因此，`$a` 必须为 `False`。同样，`$b` 必须为 `False`。最后的条件依赖于前两个条件（`$a` 和 `$b`）均为 `False`，但坚持要求 `$c` 为 `True`（答案 D）。

**8.** 正确答案是 C。自 PHP 4.2.0 起，除非需要特定的伪随机数序列，否则无需使用 `srand()` 初始化随机数生成器。此外，即使随机数生成器未被播种，该脚本仍会输出 49 个伪随机字符——每次都是相同的那些。`$array` 变量虽然是一个字符串，但可以作为数组访问，在这种情况下将返回与所用数字索引对应的单个字符。最后，`for` 循环从 1 开始，一直持续到 `$i` 小于 50——总共 49 次。

**9.** 如上所示，一系列检查单一条件的 `if...else if` 代码块是使用 `switch` 语句的完美场所：

```php
<?php
switch ($a) {
    case 'a':
        somefunction();
        break;
    case 'b':
        anotherfunction();
        break;
    case 'c':
        dosomething();
        break;
    default:
        donothing();
}
?>
```

因为有一个兜底的 `else` 条件，所以必须为该情况提供一个 `default` 分支。答案 E 正确。

**10.** 通常，`foreach` 语句是遍历数组最合适的结构。然而，因为我们被要求修改数组中的每个元素，所以此选项不可用，因为 `foreach` 在数组的副本上工作，因此会导致额外的开销。虽然 `while` 循环或 `do...while` 循环可能行得通，但因为数组是顺序索引的，`for` 语句最适合这项任务，因此答案 A 正确：

```php
<?php
$myarray = array("My String", "Another String", "Hi, Mom!");
for ($i = 0; $i < count($myarray); $i++) {
    $myarray[$i] .= " ($i)";
}
?>
```

**11.** 因为只能向提供的代码段添加单行代码，所以唯一讲得通的语句是 `for` 循环，这将选择范围缩小到 C 或 D。为了选择实际产生正确结果的 `for` 循环，我们首先必须重温其结构元素。在 PHP 中，`for` 循环声明如下：

```
for (<初始化语句>; <继续条件语句>; <迭代语句>)
```

其中 `<初始化语句>` 在进入循环之前执行。然后 `for` 循环开始执行其代码块内的代码，直到 `<继续条件语句>` 评估为 `False`。每完成一次循环迭代，就会执行 `<迭代语句>`。

将其应用于我们的代码段，正确的 `for` 语句是：`for ($idx = 1; $idx < STOP_AT; $idx *= 2)`，即答案 C。

**12.** 在五个选项中，只有两个是有效的 PHP 函数声明（A 和 D）。在这两个声明中，只有一个会在未传递参数时提供默认参数——答案 A。

**13.** 这个问题旨在测试你关于 PHP 在处理函数时如何作用域变量的知识。具体来说，你必须理解 `global` 语句如何将全局变量引入局部作用域，以及 `$_GET`、`$_POST`、`$_COOKIE`、`$_REQUEST` 等超全局数组的无作用域特性。在这种情况下，数学计算结果为 5 + 25 - 25 - 10，即 -5，也就是答案 B。

**14.** 可以通过将括号（以及所需的任何参数）附加到包含要调用的函数名称的变量后面，来动态调用函数。因此，对于 A 组，适当的索引组合是 0, 4, 9, 9, 9, 9，其评估结果为字符串 `myfunction`。另一方面，参数是使用 `${}` 结构作为变量动态评估的。这意味着 B 组的适当索引是 7 和 8，它们评估为 `${'a'}` 和 `${'b'}`——分别意味着变量 `$a` 和 `$b`。因此，正确答案是 D。

**15.** 在 PHP 的最新版本中，`require()`（或 `require_once()`）和 `include()`（或 `include_once()`）之间的唯一区别在于，前者在找不到包含文件时只会抛出警告并允许脚本继续执行，而后者会抛出错误并停止脚本。因此，答案 E 正确。

**16.** 当参数被声明为按引用传递时，不能为其指定默认值，因为解释器将期望一个可以在函数内部被修改的变量。因此，答案 C 正确。

**17.** 这里的正确答案是异或（`xor`）运算符。

**18.** 全等运算符通过首先比较其两个操作数的类型，然后比较它们的值来工作。如果两者中任意一个不同，它就返回 `False`——因此，答案 B 正确。
