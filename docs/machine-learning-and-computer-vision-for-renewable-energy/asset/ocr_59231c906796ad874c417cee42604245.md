# Non-Functional Testing

This section pertains to the testing of an application’s non-functional attributes. Non-functional testing involves assessing software against non-functional requirements, such as performance, security, user interface, etc. This type of testing can be conducted at various stages of the software development life cycle

# Unit Testing

Unit testing is a crucial aspect of software development that involves testing the smallest functional units or modules of an application, referred to as “units,” to ensure that they operate correctly and in line with requirements. Unit testing can be performed either manually or automatically. Its main objective is to isolate each component of the software and verify that it operates correctly and meets the expected functionality. Test cases and results are shown in Table 1.

# Integrating Testing

Integration testing is a software testing level that involves testing individual units as a group to identify errors in their interaction. The main objective of this testing is to detect faults in the combined parts of an application. Test drivers and test stubs are used to support Integration Testing. It is performed after unit testing and before validation testing as shown in Table 2. There are two approaches to Integration Testing: Bottom-up integration testing and Top-down integration testing.

# Bottom-Up Integration

In this type of testing, the testing process starts with unit testing, and then gradually moves towards testing of larger combinations of units, which are referred to as modules or builds.

# Top-Down Integration

Top-down integration testing is a testing approach where the highest-level modules of an application are tested first and then the testing proceeds with the lower-level modules.
