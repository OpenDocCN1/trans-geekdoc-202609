### BACKGROUND

Predictive experimentation in the field of ML plays a key role in creating accurate and efficient models. The success of this process depends on the variety and volume of input data that determine the target parameter. The more and more diverse the data, the more competence and accuracy can be achieved in the development of predictive models. In this paper, for the prediction of electricity consumption and production, test data sets are considered, which include:

- Time and date of data entry. Fundamental data collected during a certain period are key to considering the dynamics of electricity consumption and production.

- Energy production by different types of power plants:
  - Nuclear power plant. Information about energy production using nuclear reactors.
  - Thermal power plant. Data on energy supply based on thermal energy.
  - Block thermal power plant. Guidelines for energy production from block thermal power plants.
  - Hydroelectric power station. Data on electricity production using hydropower technologies.

The results of the predictive experiment are the basis for identifying the causes of atypical electricity consumption, and serve as the basis for building a decision-making model for managing energy infrastructure reconstruction programs and projects. In this work, the predictive experiment was developed using the Microsoft Azure Machine Learning (AML) studio. The use of this service is determined by the following factors:

- ease of use – the components of the ML system are represented by blocks with inputs and outputs, respectively, the output data of one block is the input for another; thus, there is no need to write code to create a model;
- wide functionality – the AML studio has a large number of prediction and data classification methods for model training;
- the possibility of adding custom scripts to the model – additional data processing and analysis tools are implemented using scripts in the Python and R programming languages;
- convenience of analyzing the quality of model training – the studio provides the ability to analyze the quality of the model using a few metrics: root mean square error, relative absolute error, coefficient of determination, etc.

Value of final energy consumption by users $Q_{end}$ is suggested to be used as a reference value when determining model constraints. Thus, we accept:

```
$Q_{end} = kQ,$ (1)
```

where $Q$ is the total heat capacity of energy sources, MW; $k$ is the coefficient that considers energy losses during transportation to end users.

Application of the parameter $Q_{end}$ in such a definition will allow to simulate an engineering system, in which generating capacities will be selected in accordance with the volumes of final consumption. This will prevent the occurrence of excessive energy production and minimize the consumption of energy resources for the further functioning of the system. Defining model constraints is a user function, and it is possible to define constraints for both quantitative and qualitative indicators. Thus, for the existing system to be reconstructed within the framework of the implemented program, the existing disturbances of the external environment, it is possible to adapt individual parameters of the model. Possible limitations for generating subsystems of utility power facilities are represented by equations (2)—(5).

```
Q= 4.5, (2)
```

```
Q_{los} \le 0.01, (3)
```

where Q_{los} is the total loss of thermal energy in the subsystem, MW.

```
P_{out} \ge 1.4, (4)
```

where P_{out} is the coolant pressure at the exit from the subsystem, MPa.

```
FCon= 1, (5)
```

where FCon is the presence of a frequency converter.

The list of limitations given above is not exhaustive and may be supplemented as necessary. The operation of the model involves the setting of all parameter values acting as constraints. This is due to the limitations of the machine learning technology used and the Microsoft AML Studio. The input data for training the model is provided as a dataset created in csv format. The data of the dataset is fed to the input of the block that implements the selection of columns used for further training. In this case, the block selects all columns except the first one, which contains the serial numbers of the objects. Columns are selected using the “Column selector” tool, the interface of which is shown in Figure 1. With the help of a script written in the Python programming language, columns of the dataset containing parameters of objects of a type that are not considered in a particular experiment are removed. For example, in the current task there was a deletion from further studies, the columns that related to the production of energy by wind and solar power plants, the analysis of which was transferred to the second stage of studies.

The “Clean Missing Data” block deletes the terms of the dataset in which there are empty values.

The cleaned dataset enters the input of the “Split Data” block, which divides the dataset into data for training the model and data for testing. In this model, 75% of the time is allocated for model training.

Regression using a neural network is used to predict the output values. The neural network approach has advantages over traditional methods in three cases:

- when the task under consideration due to specific features does not lend itself to adequate formalization, as it contains elements of uncertainty that cannot be formalized by traditional mathematical methods;
- when the task under consideration is formalized, but there is currently no apparatus for solving it;
- when there is a suitable mathematical apparatus for the considered, well-formalized problem, but the implementation of calculations with its help on the basis of computer systems does not satisfy the requirements for obtaining solutions in terms of time, size, weight, energy consumption, etc.
