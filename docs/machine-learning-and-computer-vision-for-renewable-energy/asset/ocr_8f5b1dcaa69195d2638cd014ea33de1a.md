# *Electricity Production Prediction by Microsoft Azure*

After training the model using the “Train Model” block and testing it using the “Score Model”, it is evaluated in the “Evaluate Model” block. Also, from the “Score Model” block, data is fed to the six inputs of “Execute Python Script” block, which are responsible for generating graphs of the dependence of the values of the objective function on the values of some basic constraints. The function of generating charts is an element of post-processing of model data and will be described in detail below in the method of practical use of the ML service. After completion of training, testing and evaluation, the web service is set up based on the model using the option “Set Up Web Service” – “Predictive Web Service”. The architecture of the created web service is shown in Figure 2.

To use the prediction model outside the Azure ML web-site service and to get this model ready for deployment, it is needed to convert the training experiment to a predictive one. To get this model ready for deployment. This involves three steps:

+   1. Save the model you’ve trained and then replace our training modules
+   2. Trim the experiment to remove modules that were only needed for training
+   3. Define where the web service will accept input and where it generates the output

One could do this manually, but fortunately all three steps can be accomplished by clicking Set Up Web Service at the bottom of the experiment canvas (and selecting the Predictive Web Service option).

Appropriate simplification of the architecture by removing some blocks and adding a transformed dataset. The simplified architecture of the web service is shown in Figure 3. The service includes: a trained model, a transformed dataset, a model testing block, as well as the input and output of the web service. The transformed dataset is the input dataset to which all data processing operations have been applied. The saved trained model is added back into the experiment. Web service input and Web service output modules are added (these identify where the user’s data will enter the model, and what data is returned, when the web service is accessed).

When the web service is accessed, the user’s data enters through the Web service input module where it’s passed to the Score Model module and scored. The way you’ve set up the predictive experiment, the model expects data in the same format as the original credit risk dataset. The results are returned to the user from the web service through the Web service output module.

After the work on the web service is completed, it is deployed. In the future, it is possible to use it both in the browser and with the help of a Microsoft Excel file with the AML Studio add-on. During model creation and training, AML Studio creates a polynomial that is used to further predict system parameter values based on input data.

Machine Learning Studio makes it easy to call web services directly from Excel without the need to write any code. When entering input data, Microsoft Excel makes a call to this polynomial deployed as a web service, after performing calculations, the output data is returned to the user in numerical and textual form. The interface of the AML Studio add-on is shown in Figure 4. Once macros are enabled, a table is generated. Columns for initial data are required as input into the RRS web service, or PARAMETERS. Note the output of the RRS service, PREDICTED VALUES in separate column. When all columns for a given row are filled, the workbook automatically calls the scoring API, and displays the scored results.
