摘要—已设计多种浏览器内隐私保护技术，以保护最终用户免受第三方追踪。在与这些对策的军备竞赛中，追踪提供商开发了一种名为基于 CNAME 隐藏的追踪的新技术，以规避阻止第三方 Cookie 和请求的浏览器带来的问题。为检测这种追踪技术，浏览器扩展需要按需 DNS 查询 API。然而，此功能仅 Firefox 浏览器支持。

本文提出了一种基于监督机器学习的方法，无需按需 DNS 查询即可检测基于 CNAME 隐藏的追踪。我们的目标是检测与基于 CNAME 隐藏的追踪相关的网站和请求。我们爬取一系列目标网站，并存储所有带有属性的 HTTP/HTTPS 请求。然后，通过查询子域的 CNAME 记录，并基于知名追踪过滤列表应用通配符匹配，自动对所有实例进行标记。提取特征后，我们构建一个监督分类模型，以区分与基于 CNAME 隐藏的追踪相关的网站和请求。评估结果表明，所提方法优于知名追踪过滤列表：网站 F1 分数为 0.790，请求 F1 分数为 0.885。通过分析特征置换重要性，我们证明脚本数量和 XMLHttpRequest 占比对于检测网站具有鉴别性，而 URL 请求长度有助于检测请求。最后，我们使用 2018 年数据集训练模型，在 2020 年数据集上获得合理性能，以分析概念漂移并检测使用基于 CNAME 隐藏的追踪的网站和请求。

## I. 引言

网站追踪用户浏览活动的原因有多种。在某些可接受的情况下，这仅仅是为了使用户浏览体验更快捷、更方便。另一方面，用户的浏览活动也被用于确定用户在网络上的浏览习惯和偏好，以用于广告和分析，这对注重隐私的用户来说可能令人担忧 [1]。

许多实体通过追踪旨在获取用户浏览习惯的经济价值，设计服务来收集用户信息，甚至在未经用户知情或同意的情况下收集 [2] [3] [4]。有一些针对第三方追踪的有效方法，用于保护用户隐私。广告拦截和第三方追踪防护已成功利用黑名单 [5] [6] [7]、基于机器学习的检测 [8] [9] 以及其他方法 [10] [11] [12] 来防范此类追踪器。

然而，第三方网页追踪在与这些对策的军备竞赛中变得越来越复杂。当前趋势之一是利用 DNS 中的规范名称记录或别名 (CNAME) 记录，以绕过浏览器和扩展中的过滤列表。这种技术称为基于 CNAME 隐藏的追踪，它使用 CNAME 将指向第三方追踪器的请求伪装成第一方请求。当前的对策主要针对第三方追踪，且不影响第一方资源。因此，基于 CNAME 隐藏的追踪可以绕过此阻止。

目前已有一些检测基于 CNAME 隐藏的追踪的方法。EasyPrivacy [13]、AdGuard 追踪防护 [14] 以及其他过滤列表会手动将新的第一方子域（作为 CNAME 隐藏的伪装）添加到这些黑名单中。然而，这种方法会大幅增加黑名单的大小，且这些子域需要频繁更新。此外，自版本 1.24.1b0 起，uBlock Origin 会对加载资源的主机名执行 DNS 查询，以确定底层子域是否与 CNAME 隐藏相关。然而，只有 Firefox 允许 uBlock Origin 阻止 CNAME 隐藏，因为其他浏览器不支持 DNS 解析 API [7]。

本文提出了一种机器学习方法，无需动态 DNS 查询即可检测网络上的基于 CNAME 隐藏的追踪。我们的方法包含三个步骤。(1) 我们爬取一系列目标网站，并存储所有带有属性的 HTTP 请求。然后，我们查询子域的 CNAME 记录，并基于知名追踪过滤列表对这些 CNAME 记录应用通配符匹配，从而标记所有实例 (§ III-B)。(2) 接下来，我们提取它们的特征 (§ III-C)。(3) 最后，我们构建一个监督分类模型，以区分使用基于 CNAME 隐藏的追踪的网站和请求 (§ III-D)。

本研究的贡献总结如下：

- 我们提出了一种检测基于 CNAME 隐藏的追踪的有效方法。对于检测基于 CNAME 隐藏的网站，我们获得了 0.790 的 F1 分数；对于请求，获得了 0.885 的 F1 分数 (§ IV-A)。
- 我们引入了用于 CNAME 隐藏检测的与网站相关和与请求相关的特征 (§ III-C)。我们还对特征在基于 CNAME 隐藏的追踪检测中的鉴别能力进行了详细分析 (§ IV-B)。
- 我们表明，通过分析概念漂移，我们的监督模型对新爬取的数据也有效 (§ IV-C)。

## II. 背景与相关工作

### A. 背景

- 1) 基于浏览器的隐私保护技术：已设计多种基于浏览器的隐私保护技术，以保护最终用户免受第三方追踪，例如 Ghostery [5]、Disconnect [6] 和 uBlock Origin [7]。它们能有效检测第三方追踪。

![](img/c2a5bacf959b7153149e0b560c03e8c2_1_0.png)

- 2) 基于 CNAME 隐藏的追踪：DNS CNAME 记录与内容分发网络（CDN）的联合使用日益普遍，以改善网站加载时间、降低带宽成本，并提高内容的可用性和冗余度。CNAME 也已用于用户追踪。追踪提供商要求其客户委托一个子域用于数据收集和追踪，并使用 CNAME DNS 记录将其链接到外部服务器 [15]。它与普通第三方追踪的行为不同，因为它使用第一方子域；浏览器和扩展通常不会影响这些资源。

例如，当最终用户访问网站 example.com 时，该网站嵌入了一个第一方追踪器 a.example.com，它通过 CNAME 指向 metric.tracker.com。追踪提供商 tracker.com 因此追踪最终用户在网站 example.com 上的活动（图 1）。

### B. 术语定义

- 1) 与基于 CNAME 隐藏的追踪相关的请求：子域发出的 HTTP 请求，用于通过基于 CNAME 隐藏的追踪收集和共享特定用户在网络上的活动信息。

- 2) 发生基于 CNAME 隐藏的追踪的网站：网站设置了一个子域，该子域使用 CNAME 记录指向追踪提供商域。

### C. 相关工作

- 1) 反第三方追踪技术：在线网页追踪的隐私危害已被广泛研究。

基于机器学习的追踪检测：Harrass 等人 [9] 开发了一种无监督检测方法，检查 HTTP(S) 请求中的 URL 查询以检测追踪活动。Yamada 等人 [16] 分析网关流量以监控管理网络中的所有追踪网站，并在网站及其访问时间之间构建图以检测追踪网站。Wu 等人 [8] 开发了 DMTrackerDetector，利用结构洞理论和监督机器学习自动离线检测第三方追踪器，以高效生成黑名单。

非基于机器学习的追踪检测：Schelter 和 Kunegis [17] 通过从超过 4100 万个域中提取第三方嵌入，对第三方追踪器进行大规模分析，以研究全球在线追踪。Roesner 等人 [11] 开发了一种客户端方法，根据 Alexa 排名，对 500 个最受欢迎网站和 500 个受欢迎程度较低的网站上的五种第三方追踪器进行检测和分类。为切断第三方网页追踪的追踪链，Pan 等人 [12] 开发了 TrackingFree，将唯一标识符隔离到不同的浏览器主体中，使得标识符仍然存在，但在不同网站之间不再是唯一的。

- 2) 现有的浏览器内基于 CNAME 隐藏的追踪检测技术：为阻止使用 CNAME 记录的第一方追踪器，uBlock Origin 解析 DNS 记录的主机名，以确定底层子域是否与 CNAME 隐藏相关。然而，只有支持 DNS API 的 Firefox 允许 uBlock Origin 阻止 CNAME 隐藏 [7]。此外，知名追踪过滤列表持续努力手动更新作为 CNAME 隐藏伪装的第一方子域，将其添加到这些黑名单中。这使得过滤列表的日常更新变得繁琐且耗时。

## III. 设计与实现

此处，我们描述检测基于 CNAME 隐藏的追踪的方法。

### A. 方法概述

![](img/c2a5bacf959b7153149e0b560c03e8c2_1_1.png)

我们的目标是开发一种使用机器学习的基于 CNAME 隐藏的追踪检测方法。我们的方法标记与基于 CNAME 隐藏的追踪相关的网站和请求。如图 2 所示，该方法包含四个步骤：数据收集、特征提取、模型开发和评估。

- 1) 爬取目标网站，包括有和没有基于 CNAME 隐藏的追踪的网站，并保存所有 HTTP 请求及其属性。然后，我们对所有子域执行 DNS 查询，并通过将知名追踪过滤列表与位于所有子域背后的 CNAME 进行匹配（如 [18] 中所述），自动标记所有实例。
