## B. 特征置换重要性

我们调查了置换重要性 [26] 以讨论所选分类器的特征重要性。图 4(a) 表示与站点检测相关的特征置换重要性。我们观察到，脚本数量 (num_script) 和 XMLHttpRequest 请求的比例 (pct_xhr) 是最有用的特征。此外，跟踪提供商分布在不同类型的站点上 [18]，因此站点类别 (category) 和站点国家 (country) 对检测发生 CNAME 伪装相关跟踪的站点没有帮助。

图 4(b) 显示了用于检测请求的模型的特征置换重要性。结果表明，请求 URL 长度 (len_url) 具有最高重要性。我们假设，几乎所有用于基于 CNAME 伪装的跟踪的子域请求长度都大于用于收集站点内容的请求长度，因为它们包含用户的标识。此外，子域前缀长度 (len_prefix_sub)、XHR 使用请求 (is_xhr) 和 URL 请求的随机性 (entropy_url) 是请求检测的区分特征。除此之外，子域前缀黑名单存在 (prefix_sub_blacklist) 对检测请求无效。这是因为一些发布者也使用相同的子域前缀，该前缀既用于 CNAME 伪装，也用于其他非跟踪资源。

## V. 结论与讨论

最近，Web 上基于 CNAME 伪装的跟踪引起了广泛关注。当前最佳对策是黑名单方法，该方法强烈依赖于实时名称解析。本文提出了一种机器学习方法，用于检测包含基于 CNAME 伪装跟踪的站点和 HTTP 请求。通过全面分析，我们证明了我们方法的有效性。

所提方法补充了用于基于 CNAME 伪装的跟踪检测的现有技术，可以帮助研究人员、浏览器扩展开发人员和黑名单维护者构建针对这种跟踪技术的高效系统。一旦跟踪提供商知道所提检测方法的存在，他们可能会试图规避它。在未来工作中，我们打算添加新功能以提高我们的检测性能。
