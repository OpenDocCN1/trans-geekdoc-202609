
It may come as a shock to non-accountants, but combined balance sheets, all over the world, do not have to balance. Mirror accounting transaction between two parties is a simplified notion of accounting, and definitely not the case with accrual accounting. Take a simple transaction, that of purchase of inventory. While the supplier selling the inventory records a revenue, the buyer records the purchase as inventory, as an asset, and not as an expense. For the buyer the inventory becomes an expense, cost of goods sold, only when it eventually sells those items or goods produced from those items to another customer. The situation gets even more complicated in transactions involving capital lease payments and those involving foreign currency transactions. Even for straightforward transaction of a receivable for one company leading to payable for another, the symmetry is not guaranteed. Accounting rules requires the recording of receivables to undergo an evaluation that the amount is expected to be collected. When in doubt, no receivable is recorded, while the owing company will still have to record the payable.

Despite publications to the contrary, in popular business press, blockchain is not equivalent to triple bottom line accounting,[⁵](#CH003.html#fn5) these nuances of accounting are not fully understood by computer scientist leading to exaggerated claims on the efficacy of blockchain and its ability to replace traditional accounting functions. Moreover, even the term “triple-entry bookkeeping” was coined by a prominent accounting scholar, Yuri Ijiri (1986), a professor at the Carnegie Mellon University. His notion was to quantify the concept that changes in wealth must be equal to income, and added concepts to make that determination palpable. Hence, the use of the term “triple-entry bookkeeping” to describe the functions of blockchain is erroneous.

### 3.4. BLOCKS, HASHES AND MERKLE TREES

Transactions are detailed records of actions of members and interactions between them that are recorded in a `block`. Each participant can access, verify and accept the transactions noted in a block. Once a majority of participants accept the block, it is chained to the block that is the terminal block of the longest chain at the time. The identification of the legitimate block where the new block will be attached is accomplished through a `hash function`.

Blocks maintain the indestructible record of transactions. Hence, whenever there are new transactions, a new block is created. Once created, the block has to be approved by the participants of the network using a pre-determined rule (discussed later) and then appended to the existing chain. After the new block has been appended to the chain, it cannot be removed or amended. These blocks are linked to each other, forming a blockchain. Each block includes a cryptographic hash of the prior block of the chain, which itself is chained through a “hash” with the preceding block, and so on. The first block in the chain is called the `genesis block`, and subsequent blocks are sequentially chained to the genesis block.

The time it takes to create and append a new block is called the `block time`. The block time varies across different blockchain networks. Shorter the block time, the quicker new transactions get recorded and appended to the chain. In 2019, the block time for Ethereum platform was between 12 and 15 seconds, with the highest being about 30 seconds. In contrast, the recent (2018 onwards) block time for Bitcoin has ranged between 10 to 12 minutes.[⁶](#CH003.html#fn6)

The formation of blocks and their addition to the existing chain is illustrated in [Fig. 3.2](#CH003.html#fig2). The first block at the bottom is the genesis block. The next block is added to this block. At some of the points there is a `fork`, where two blocks were processed, however, the one to which the next block gets added first becomes the predominant chain and continues to grow, whereas the offshoot branch does not grow. This is established by the underlying feature of blockchain that the longest chain is the valid chain, hence new blocks are added to the longest chain at the time, thereby stubbing or stumping the offshoots.

The hash function is a mapping algorithm as shows in [Fig. 3.2](#CH003.html#fig2) in that it changes one sequence to another sequence. In other words, it generates a value from a string of text using a mathematical function. Hashing takes on an input of any length and converts it into an output of a fixed length.[⁷](#CH003.html#fn7) Each transformation is unique and reversible. That is, upon knowing the hash function one could reverse engineer to decode the original message. The process of hashing helps make the transmission of message tamper-free.

The hash function ensures that every time the algorithm is executed with the same electronic record as its input it gives the same output or result. This makes it computationally infeasible to derive or reconstruct the original electronic record without the hash result produced by the algorithm. Since each hash function is unique it is impossible that two electronic records using the algorithm can produce the same hash result. This is also known as the deterministic property of the hash function. The hash function is also capable of quick computation to ensure efficiency of the system.

A key property of the hash function is that since it is cryptographically generated, even small changes to the input could result in large differences in the resultant hash function. The immutability quality of blockchain is derived from this property of the hash function, ensuring that any minor changes to the recorded data could result in large changes in the hash function. Another key property of hash is that each and every string of data should have a unique resulting hash, as shown in [Fig. 3.2](#CH003.html#fig2). This is an important property of the hashing function to ensure that the original message would be uniquely retrieved once we have the hash, and it is remote that two or more original messages will be retrieved for a single hash.

The blockchain is a linked list that contains data and hash pointer that points each block to its preceding block as shown in [Fig. 3.3](#CH003.html#fig3). A hash pointer not only contains the address of the previous block but also the hash of the data inside the previous block. This minor feature of the hash pointer led to the key immutability property of blockchain. Maintaining the hash of the data inside the previous block ensures that if the data residing in the previous block is altered, even marginally, it will lead to a different hash function. The resulting hash function will not correspond to that stored in the subsequent block. Hence, for the tampering of data in previous blocks to be successful, it would require mining of every subsequent block that now incorporates the different hash.

The concept of Merkle tree was developed by Ralph Merkle and patented in 1979.[⁸](#CH003.html#fn8) It is fundamentally a data structure tree, an unique organization of the storage of data that makes it easier to retrieve any specific records. In blockchain, each block contains thousands of transactions, hence without a proper retrieval mechanism locating a particular transaction would be extremely time-consuming and cumbersome. Organization of data in a Merkle tree makes it extremely efficient to retrieve the particulars of any transaction stored in a block, hence making it easier to verify the validity and occurrence of each and every historical transaction.
