
The operationalization of the digital solution begins with a timestamp server. The timestamp server takes a hash of a block of items and widely publishes the hash. The data included in the hash indicates that the transaction must have existed at the time. Moreover, since the hash is comprehensive, if a transaction is not included in the hash it implies that the transaction had not taken place at the time. In Nakamoto’s words, “each subsequent timestamp (or block) includes the previous timestamp (block), which forms a chain” – hence blockchain. Therefore, each subsequent block includes the information in the previous block thereby reinforcing all the transactions that have come before it.

When a node receives conflicting solutions from the other nodes, by default they always consider the longest chain to be the correct one and will keep working on extending it. If two nodes, `A` and `B` broadcast different versions of the next block simultaneously, some nodes may receive `A` first and some may receive `B` first. In that case, the nodes work on the first one they received, but save the other branch in case it becomes longer before the other one does. Say node `D` received `A` first but later realized that `B` got longer and was supplanted by a new block sent from `H`. Now `D` will discard the chain `A` and start working with the longer chain from `H`. That way, it is always ensured that the longer chain is the valid one and there are not too many competing chains of the same size. When there are conflicts those are resolved quickly, that is by the next iteration.

After a new block has been formed, it implies much effort has been expended to satisfy the proof of work. Hence, the block cannot be changed without redoing the work. As the blockchain grows by addition of subsequent blocks, the work to change the records not only is limited to redoing that particular block, but redoing the work of each and every subsequent block. Therefore, as new blocks are added to the blockchain, the work needed to alter an earlier block grows exponentially. This feature of blockchain helps maintain its integrity and immutability. That is, once a transaction is added to a block, and accepted by other nodes, it cannot be altered or removed. If the transaction needs to be removed for legitimate reasons, it has to be put forth as a new transaction reversing the previous one. Hence, there will be a permanent record of the transaction having initially taken place and also the record of it being subsequently reversed, which could have different implications than showing that the transaction never occurred in the first place.

In summary, Bitcoin endeavored to create a system that would allow two unknown parties to transact virtually with each other without the need of an intermediary or a trusted third party. This required an electronic payment system that would be based on cryptographic proof. To achieve that it required the network to timestamp transactions by hashing them into an ongoing chain. This forms a ledger of sort, a detailed history of transactions, which is immutable in that it cannot be altered. The longest chain not only serves as proof of the sequence of events witnessed, but also enables the system to maintain integrity.
