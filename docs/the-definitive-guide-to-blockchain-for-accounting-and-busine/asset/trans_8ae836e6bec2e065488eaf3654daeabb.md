
使用区块链的期望可能会因某些区块链属性而降低。在许多区块链中，周期性更新速度较慢。当涉及任何区块链上的大规模交易时，这一点至关重要，因为它会延迟验证过程。这些更新在给定时间内被聚合到区块中。例如，正如[第2章](#CH002.html)所述，以比特币为例，交易区块之间的预期时间目标为10分钟。大多数区块链的区块之间预期时间更短。周期性更新并非精确计时，但通常在目标时间范围内。

区块链中的空间有限。每个区块都必须由区块链网络中的节点处理，因此将区块保持在合理大小是有意义的。在区块链中插入信息的成本可能有所不同。这是因为交易成本通常是区块链模型的一部分。这些交易成本以相关加密货币计价，而加密货币可能非常波动。

区块链验证自主系统的共识，但它们本身并不是数据库系统的替代品。在区块链中保存共识记录是区块链的明确目的，然而，在区块链中保存更一般的记录可能并不理想。特别是，下载整个区块链可能耗时且成本高昂。区块中的空间也有限、成本高昂且记录不可更改。

区块链对业务案例的适用性取决于区块链提供的属性。这些属性必须与任何区块链特有性进行权衡。在本章的剩余部分，我们首先从技术上讨论加密。我们的第一个用例是公钥加密系统。在第7.4节和第7.5节中，我们给出了评估区块链系统用例的框架。我们还制定了评估区块链及其用例的评分卡。该框架在制定评分卡时从自下而上和自上而下应用区块链。接下来，我们讨论区块链中的智能合约。我们深入开发了若干用例。最后，我们在以简要总结结束之前给出区块链的注意事项和风险。

## 7.3. 密码学和加密技术入门

密码学是一门高度技术性且应用性强的学科。家用、工作场所或当地商店的WiFi服务使用密码学。只要我们从网上订购任何东西，我们就在使用密码学。密码学也需要用于将文档放入云端或从云端检索文档。另一个应用密码学的常见用例是无线汽车钥匙。鉴于应用密码学的广度和深度，区块链使用密码学也就不足为奇了。事实上，区块链依赖于公钥加密。因此，第一个示例用例图说明了基本的公钥加密。

对称加密系统只有一个密钥。因此，单个密钥既加密也解密机密数据。由于只有一个密钥同时加密和解密数据，因此存在对称性。大多数机械房屋钥匙是对称密钥。这是因为同一房屋钥匙既能锁门也能开门。

公钥系统是非对称加密系统。这些系统是非对称的，因为一个密钥锁定数据，另一个密钥解锁数据。其中一个密钥是公钥，另一个是密钥。公钥可以对所有感兴趣的人公开。给定公钥，找到密钥是不可行的。

对于非对称加密系统，设 `E` 为加密函数，`D` 为解密函数。假设为这些加密和解密函数生成了公钥 `p` 和密钥 `s`。私有消息 `M` 可以加密为 `c` ← `E[s]`\[`M`\]，其中 `c` 是密文。密文消息可以解密为 `M` ← `D[p]`\[`c`\]。

更广泛地思考，让我们计算 `c'` ← `E[p]`\[`M`\]。也就是说，使用公钥我们可以加密私有消息 `M`。当然，如果 `c'` 可以在没有密钥 `s` 的情况下轻松解密，而是通过简单的解密机制 `F`，那么 `F`\[`c'`\] ← `F`\[`E[p]`\[`M`]\]。现在，由于 `F`\[`c'`\] = `M`，所以必须有 `c` ← `E[s]`，并且一旦我们有了 `c'`，这就很容易计算。因此，加密方案将被击败。

因此，秘密消息 `M`、公钥 `p` 和密钥 `s` 满足

`M` = `E[p]`\[`D[s]`\[`M`]\]

`M` = `D[s]`\[`E[p]`\[`M`]\]

在此用例中，Blue希望向Red发送秘密消息。Red生成公钥 `p` 和密钥 `s`。公钥 `p` 可以公开张贴。理想情况下，公钥由受信任方张贴。密钥 `s` 保持私有。

[图 7.1](#CH007.html#fig1) 显示了一个示例用例图，其中 Blue 安全地向 Red 传输私有消息。首先 Blue 从受信任的密钥存储库 Green 获取 Red 的公钥 `p`。接下来 Blue 使用 Red 的公钥 `p` 加密其私有消息并将加密消息发送给 Red。Red 使用其密钥解密加密消息。就加密和解密而言，Red 的密钥充当 Red 公钥 `p` 的逆。

## 7.4. 评估用例的框架

区块链的有效性取决于对区块中交易有效性的信任。反过来，区块的有效性取决于密码学安全性。这种密码学依赖性确保了通过区块链中区块的进展对其有效性的信任。特别是，信任区块10包含有效交易，要求我们信任区块9的有效性，而这又要求我们信任区块8的有效性，等等。

如果量子计算成为现实，许多区块链密码学将会失效。这是因为根据 Shor 算法，复合整数分解可以在量子计算机上有效运行。因此，很明显加密在区块链信任中发挥着关键作用。区块链还有许多其他属性使该技术具有吸引力，这些属性在审查用例时至关重要。
