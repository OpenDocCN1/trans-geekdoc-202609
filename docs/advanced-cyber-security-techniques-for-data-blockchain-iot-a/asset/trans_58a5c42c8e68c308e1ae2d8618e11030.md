
# 我们要研究的第一个本体是漏洞管理本体（OVM），由 [Wang & Guo (2009)](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor030) 发布。

它包含 NVD（国家漏洞数据库）中的所有现有漏洞（[Booth et al., 2013](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor022)）。诸如漏洞推理、漏洞表征及其影响分析等问题主要由它处理。它是遵循 DL 知识工程方法论构建的。遵循了 [Fenz et al. (2008)](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor023) 提出的设计标准，即本体清晰性、连贯性、可扩展性、最小编码偏见和最小本体论承诺。它建立在 `CVE`（通用漏洞披露）及其相关协议和标准的基础之上，如 `CWE`（通用弱点枚举）、`CPE`（通用平台枚举）和 `CAPEC`（通用攻击模式枚举与分类）。基本的漏洞表征表达被表示为 OVM 架构的高层概念。它包含十二个顶层概念：`Vulnerability`（漏洞）、`Introduction Phase`（引入阶段）、`Active Location`（活动位置）、`IT Product`（IT 产品）、`IT Vendor`（IT 厂商）、`Product Category`（产品类别）、`Attack`（攻击）、`Attack Intent`（攻击意图）、`Attack Method`（攻击方法）、`Attacker`（攻击者）、`Consequence`（后果）和 `Countermeasure`（对策）。这些概念中的每一个都包含一个子系统层级，包含不同的子类和关键概念。OVM 还提供了实用工具和一个集中式存储库，可用于系统安全领域所有参与者之间的共享与通信。

它支持有限的自动化和查询。它是发布在漏洞领域的最早本体之一，并在信息安全自动化计划（ISAP）下发布。总体而言，它可被归类为领域特定本体。

### 3.1.1 OVM 的优点

*   高互操作性和各方间更好的交换
*   结构良好的架构
*   易于融入现有概念
*   增强的自动化

### 3.1.2 OVM 的缺点

*   有限的推理和查询
*   难以融入不存在的概念
*   通用目的的适用范围有限
*   复杂性较高 ([Wang & Cui, 2019](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor029))

## 3.2 结构化威胁信息表达（STIX）

第二个被分析的本体方法是 STIX 标准。虽然根据教科书定义它不是一个本体，但 STIX 尽管类似于一种语言或标准，却遵循系统化方法并以结构化方式表示数据。因此，在本文的范围内，它被视为一个本体。必须注意的是，整篇论文中提到 STIX 时，均指 [Barnum (2012)](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor021) 论文中发布的本体以及 MITRE 公司旗下的本体。STIX 的突出之处在于，它更侧重于一种社区驱动的方法，而非建立一个必须融入新信息的僵化结构。它更侧重于灵活性、表达性、可扩展性、自动化能力和可读性。它为网络威胁信息提供了通用机制和统一架构。它包含一组核心的必需指导原则，即表达性、可集成性、灵活性、可扩展性、自动化能力、可读性和架构。STIX 结构由可观测对象、指标、事件、战术技术与程序（TTP）、活动、威胁行为者、利用目标和行动方案（COA）组成。由于其灵活的方法，它拥有比其他本体更多的用例，以及更长的生命周期。它最常与可信自动化情报信息交换（TAXII）一起使用。尽管两者完全独立，但协同工作时能产生最佳效果。

*   灵活性和可扩展性
*   自动化能力
*   部分实现

### 3.2.2 STIX 的缺点

## 3.3 安全工具箱：攻击与对策本体（STAC）

第三个被研究的本体是 STAC 本体，由 [Gyrard et al. (2013)](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor025) 在第 22 届国际万维网会议论文集中开发。旨在为非安全专家创建一个本体，帮助他们设计安全应用并了解多个领域的安全概念和风险，STAC 融合了 `Application`（应用）、`Requirement`（需求）、`Domain`（领域）、`Attack`（攻击）、`Countermeasures`（对策）、`Feature`（特性）、`SecurityProperty`（安全属性）和 OSI 模型的概念。这些概念之间的关系及其结构在 STAC 中定义明确。除了这些主要概念外，它还包含子概念、方法和属性。它采用 `OWL`（Web 本体语言）框架表示。其 UI 利用以下技术：`Java`、`REST Web Services` (Jersey)、`Google Application Engine` (GAE)、`Jena framework`、`SPARSQL` 语言、`HTML5`、`CSS3`、`Javascript` 和 `AJAX`。STAC 支持的用例包括：针对攻击和对策的领域特定查询、额外信息检索（如对策的优缺点及满足的安全属性）、针对特定 OSI 模型层的攻击和对策搜索。

## 图 4. STAC 本体的顶层部分

![979-8-3693-9225-6.ch001.f04](image/979-8-3693-9225-6.ch001.f04.png)

([Gyrard et al., 2013](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor025))

它融合了来自各种来源的信息。STAC 的构建方式使得第三方难以修改，这使其略显不适合即时添加关于新型网络安全概念、攻击和对策的信息。它的特定目的是帮助新手软件开发人员以更稳健可靠的方式开发安全软件。

### 3.3.1 STAC 的优点

*   域外高度互操作
*   开源框架利用
*   支持领域特定检索

### 3.3.2 STAC 的缺点

*   临时更新过程困难
*   特定范围
*   领域密集型任务的用例有限
*   实现复杂 ([Gong & Tian, 2020](#979-8-3693-9225-6.ch001.bits-pdf.xhtml#_idTextAnchor024))
