# 5.2 Security under unbiased randomness

In this section, we will prove that Plume can meet the security definitions in section 3 while the randomness used to select committee is unbiased. Then, in the next section, we will explain that the biased randomness generated from slow blockchain cannot affect the overall security.

**CLAIM 5.1.** *Plume meets the 5 security definitions, that are unique sequence number, stable finality state, sequence growth, sequence quality and sequence common prefix, when the randomness used to select committee is unbiased.*

**PROOF.** We will prove Plume meets the 5 security definitions respectively.

*Unique sequence number.* In Plume, the sequence number of a fast block is set based on the slot in which the fast block was generated. And we require that there is a fast block can be generated in a slot averagely, but it is possible that there are more than one fast blocks are generated in a slot. We deal with this situation by comparing their hash values where we use the collision-resistant hash algorithm. It is obvious that if an adversary can break the unique sequence number property, he can break the collision-resistance of the hash algorithm.

Because of Slot[\( B_f' \)] < Slot[\( B_f \)], there must be Index[\( B_f' \)] < Index[\( B_f \)] which means the sequence number of \( B_f \) is changed.
