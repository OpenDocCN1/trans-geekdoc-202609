And blocks in Ancestor[$B_f$] that received in time but have not been in candidateSet will be added to candidateSet. If there is a block $B^{Anc}_f$ in Ancestor[$B_f$] belongs to pendingSet or cannot be received in time, we require the party to add every blocks in Child[$B^{Anc}_f$] including $B_f$ to pendingSet. The details is shown in Algorithm. 1.

```
**Algorithm 1 Receive Fast blocks**

**Require:** DAG G, candidateSet, pendingSet, current slot $t$, and the new fast blocks list $\mathcal{L} = \{B^i_f\}$.

**Ensure:** Updated DAG G, candidateSet and pendingSet.

1: **for each** $B^i_f$ in $\mathcal{L}$ **do**
2: 	**if** $B^i_f$ is not valid **then**
3: 		Discard $B^i_f$.
4: 	**else**
5: 		**if** there is a $B^{i,Anc_j}_f$ in Ancestor[$B^i_f$] is not invalid **then**
6: 			Discard $B^{i,Anc_j}_f$ and Density[$B^{i,Anc_j}_f$, Slot[$B^{i,Anc_j}_f$, $t$]].
7: 		**else**
8: 			**if** Ancestor[$B^i_f$] are all received in $\Delta$ slots **then**
9: 				**if** $B^i_f$ is received in $\Delta$ slots **then**
10: 					candidateSet = candidateSet + {$B^i_f$};
11: 				**else**
12: 					pendingSet = pendingSet + {$B^i_f$};
13: 				**end if**
14: 				**for each** $B^{i,Anc_j}_f$ in Ancestor[$B^i_f$] that have not been in candidateSet **do**
15: 					candidateSet = candidateSet + {$B^{i,Anc_j}_f$};
16: 				**end for**
17: 			**else**
18: 				**for each** $B^{i,Anc_j}_f$ in Ancestor[$B^i_f$] that belong to pendingSet **do**
19: 					pendingSet = pendingSet + Child[$B^{i,Anc_j}_f$, Slot[$B^{i,Anc_j}_f$, $t$]];
20: 				**end for**
21: 				**for each** $B^{i,Anc_j}_f$ in Ancestor[$B^i_f$] that cannot be received in time but not in pendingSet **do**
22: 					pendingSet = pendingSet + Child[$B^{i,Anc_j}_f$, Slot[$B^{i,Anc_j}_f$, $t$] + {$B^{i,Anc_j}_f$}];
23: 				**end for**
24: 			**end if**
25: 		**end if**
26: 	**end if**
27: **end for**
28: Update G according candidateSet and pendingSet;
```

Before ordering the fast blocks in DAG G, the party needs to select some fast blocks from candidateSet and pendingSet into

confirmedSet. If a fast block in candidateSet or pendingSet whose child nodes in a period are enough, it can be selected into confirmedSet. In $\Delta$ slots after it was generated, it might not have spread all over the network, because of the maximum network delay $\Delta$ slots. Thus, we just consider the child nodes generated more than $\Delta$ slots later than the fast block. Formally, for a fast block $B_f$ in candidateSet or pendingSet, if the number of Density[$B_f$, Slot[$B_f$] + $\Delta$, Slot[$B_f$] + $\Delta$ + $T$] is larger than the threshold $T$ the party would add $B_f$ into confirmedSet. Then the party needs to give every fast block in confirmedSet a unique sequence number according to the slot value included in the fast block. The larger slot value a fast block has, the larger sequence number it will get. There is the possibility that more than one fast blocks have the same slot value, we order them by comparing their hash values. The details is shown in Algorithm 2.

```
**Algorithm 2 Order Fast blocks**

**Require:** DAG G, candidateSet, pendingSet, confirmedSet and Seq[G].

**Ensure:** Updated DAG G, confirmedSet and Seq[G].

1: Set the largest slot in candidateSet and pendingSet as $t_L$;
2: **for each** $B_f$ in candidateSet and pendingSet **do**
3: 	**if** $t_L$ – Slot[$B^i_f$] < $T + \Delta$ **then**
4: 		waiting;
5: 	**else**
6: 		**if** Density[$B^i_f$, Slot[$B^i_f$] + $\Delta$, Slot[$B^i_f$] + $\Delta$ + $T$] $\geq$ Th **then**
7: 			confirmedSet = confirmedSet + {$B^i_f$};
8: 		**end if**
9: 	**end if**
10: **end for**
11: Sort confirmedSet according to Slot[$B^i_f$];
12: Update Seq[G] according to the sorted confirmedSet;
```
