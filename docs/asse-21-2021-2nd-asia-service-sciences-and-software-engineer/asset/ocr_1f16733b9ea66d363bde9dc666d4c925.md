# ## 6 EXPERIMENT

Due to the limitation of device, we simulated Plume with NS-3. We assumed that the delay of network is 200ms, the degree of which node is 3-5 and the bandwidth is 20Mbps. And, we also fixed the content of fast blocks and the contents of the fast block is show in table 7. Here, compared with bitcoin, we assume the size of transaction is 250 bytes.

Firstly, we consider the throughput of Plume. From table 5, we can find that with rising of generating rate of fast blocks, the throughput improves, and in the case that block size is 100K bytes and time interval between fast blocks is 1 second the throughput is more 400 TPS which is much larger than Bitcoin and Ethereum. We also find that the average parent blocks vary in different conditions. Due to the delay of network, if the creation rate of blocks is fast, before the old block received by most of the nodes a new fast block is also generated. Which is one of the chief force of the width of the DAG. As show in table 5, when the block size is 10K bytes and the time interval of fast blocks is 1 second, the average width of DAG (which is equivalent to the average amount of parent blocks), is similar to a single chain. And with the reduction of time interval between two blocks, the width of DAG increases steadily. From table 5, when the block size changes from 10K bytes to 100 Bytes, throughput becomes 10 times as before, and the width of DAG also extends tremendously. Enlarging the size of block is equivalent to reduce the time interval [17], because with the enlargement of block, the network delay also increase. It should be noted that the width should be limited in size. The wider the DAG is, the more unstable the system is. A wider DAG means more pending blocks, which cause more blocks are deserted.
