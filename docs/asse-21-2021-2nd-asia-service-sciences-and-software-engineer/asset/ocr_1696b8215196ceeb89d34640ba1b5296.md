```
**Algorithm 3** Generate a Fast blocks

**Require:** $DAG \mathbb{G}$, candidateSet, current slot $t$, $(y, \pi)$, randomness $r$, tlist $L_{tx}$ and sign key $sk$.

**Ensure:** $B_{f}^{new}$.
1: Calculate merkle_root based on the tlist;
2: Set reference_number = 0 and reference_hash = {};
3: **for** each leaf node $B_{j}^{leef-j}$ in candidateSet **do**
4: 	**if** $t - Slot[B_{j}^{leef-j}] \le 2\Delta$ **then**
5: 		reference_hash=reference_hash+{hash($B_{j}^{leef-j}$)};
6: 		reference_number=reference_number+1;
7: 	**end if**
8: **end for**
9: Calculate signature $\sigma$ on $(y, \pi)||r||t||merkle_root||reference_number||reference_hash||L_{tx}$ by $sk$;
10: $B_{f}^{new} = (y, \pi)||r||t||merkle_root||reference_number||reference_hash||L_{tx}||\sigma$;
11: Output $B_{f}^{new}$.
```

# 4.5 Storing the current state of DAG in slow blocks for quick start of a new party

If a new party wants to join the network, he needs to download the whole DAG he missed. But adversaries can send him an incorrect DAG that the new party but cannot judge it. So we require the miners of slow chain to store the current state of DAG in their slow blocks. The new party can check the correction of a received DAG according to the states recorded in slow chain. For a new party, he cannot decide which fast block can belong to pendingSet during the downloading of DAG that generated before his joining, because he missed these fast blocks. For the DAG that he has missed, he needs to verify the validity of every fast blocks, and adds valid fast blocks whose child blocks are enough to confirmedSet, then add their valid child fast blocks who need more time to confirm to candidateSet. It is

possible that adversaries give the new party a DAG part that was hidden before. If the part meets our requirement, we regard it valid, otherwise, we need the new party to discard it. For the fast blocks that generated after his joining, we can decide whether these fast blocks belong to pendingSet or candidateSet by Algorithm 1. When he can generate a new fast block, he generates it through Algorithm 3 too. It is obviously that the new party can order DAG as the same as the online parties, so we just describe the process of downloading and dealing with the fast blocks that generated before his joining in Algorithm 4.

```
**Algorithm 4** Download the missed fast blocks

**Require:** states recorded in slow chain.

**Ensure:** DAG $\mathbb{G}$, candidateSet and confirmedSet.
1: Download a DAG $\mathbb{G}$ and check it by the states recorded in slow chain;
2: Set candidateSet={} and confirmedSet={};
3: Set the largest slot in $\mathbb{G}$ as $t_L$;
4: **for** each valid $B_{f}^{'}$ in $\mathbb{G}$ **do** // $\mathbb{G}$ may be updated.
5: 	**if** $T-Slot[B_{f}^{'}] < T+\Delta$ **then**
6: 		candidateSet=candidateSet+$\{B_{f}^{'}\}$;
7: 	**else**
8: 		**if** $Density[B_{f}^{'} , Slot[B_{f}^{'}] + \Delta , Slot[B_{f}^{'}] + \Delta + T] \ge Th$ **then**
9: 			confirmedSet=confirmedSet+$\{B_{f}^{'}\}$;
10: 		**else**
11: 			Discard $Density[B_{f}^{'} , Slot[B_{f}^{'}] + \Delta , Slot[B_{f}^{'}] + \Delta + T]$ and $B_{f}^{'}$;
12: 			Update $\mathbb{G}$;
13: 		**end if**
14: 	**end if**
15: **end for**
```

# 5.1 Setting the threshold

In this section, we will analyze how to set the threshold Th which is based on to decide whether a fast block can be selected into confirmedSet. We need to ensure that if malicious players withhold a part of DAG all the time, they can only exceed the threshold with a small probability. Meanwhile, we also need to guarantee that the number of nodes in the DAG graph generated only by honest players over the same period cannot reach the threshold with a small probability. For an always online party, he can recognize the DAG part that had been withhold all the time, but for a new party, it is possible to accept a hiding part. Thus, the threshold Th is the key to prevent a new party from being cheated. If a new party sees two or more parts, we needs to recognize all the leaf nodes of the parts in which the number of nodes reaches the threshold, and reject the parts that do not conform to requirements as described in Algorithm 4.
