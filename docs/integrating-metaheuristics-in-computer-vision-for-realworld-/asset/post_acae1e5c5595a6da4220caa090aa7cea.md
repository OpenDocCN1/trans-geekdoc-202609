## 15.2 Related Works

Images are shown together with related searches. The assumption in the literature is that there are two major groups into which CBIR approaches can be placed.

### 15.2.1 Conventional-Indexing Techniques

The primary category employs standard indexing techniques. To minimise the research path, the data structure's main concept is to group related objects together. There have been numerous index tree models. Data partitioning techniques are one of them. Among them are the SS-Tree, SR-Tree, R-Tree, R+-Tree, and M-Tree [1–5]. It uses Minimum Bounding Rectangles (MBRs) or Minimum Bounding Spheres (MBSs) to cover neighbor vectors, and they are arranged in a hierarchical tree structure. These techniques might result in overlapping zones.

Other approaches, such as Grid-File, K-D-B-Tree, and LSD-Tree [6–8] divide the data space along specified hyperplanes without respect to how the data is distributed. As a result, there exist two regions that are not connected to one another; their union is the entire space. The concept “optimistic techniques” is used to describe these methods. Despite the fact that various frequently access methods work effectively for low-dimensional areas, it’s generally termed as the number of dimensions increases, their performance will suffer. There are many other alternative approaches. These methods based on the approximation vector method seemed to be able to overcome the dimensionality curse. These are referred to as “pessimistic approaches.” A few examples include LPC-File, GC-Tree, and VA-File [9–11]. Bit strings are used to approximatively represent the data vectors that are included within the cells or regions of the data space after which the cells or regions are partitioned into. During k-NN search a relatively small approximation file for a particular query vector is systematically read rather than the complete data file. A limited amount of the entire database is viewed because only a portion of the original vectors will be used as they are filtered. Unfortunately, when the size of picture databases increases, the performances of the pessimistic approaches deteriorate, just like they do for optimistic ones. These methods incorporate complicated index structure, which is where the “curse of the size” phenomena originate.

Several answers to this challenge are starting to become clear to us, but they still need to be tested on substantial amount of data. ### 15.2.2.1 Parallel Architecture

A parallel architecture is made up of independent nodes, each with a separate CPU; shared-nothing (SN) RAM and discs are designed to scale with the database’s size or its user base, respectively, and are used to divide the data into groups. To speed up query processing, groups are then indexed. This provides the capacity to scale up larger databases, I/O parallelism, and the ability to disperse the processing load across the available CPUs. Kim [11] and associates have created a method based on VA-FILE (Vector Approximation File). The administration of two data sets forms the foundation of VA-FILE: a file containing all basic vectors with another file of “little” size holding geometric vectors. To choose the vectors that are included in the result set, a sequential scan of the approximate file is carried out during a query. The aim of it is to parallelize the search, with the downside where in response time depends on both latency time and execution time. Each machine executes a data partition, and the coordinator decides the overall query outcome. Other additional studies in the same field, as suggest techniques built on a shared nothing machine with data partitioning. With these techniques, parallelism is maximised, and the most effective processing nodes is determined to maximise data consumption. Simplicity of usage and scalability of these methods are two benefits. Limiting the number of processors and increasing cost and complexity are the main drawbacks.
