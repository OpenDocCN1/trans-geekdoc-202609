
The most important property is the fact that, despite the algorithm's heuristic nature, a sufficient condition is known under which the algorithm `A*` is guaranteed to find the optimal solution, if one exists. This is strictly shown in the first paragraph of this section. The second paragraph shows that the algorithm `A*`, figuratively speaking, "remembers well" - the more informed the scoring function provided to the algorithm, the "better" the algorithm behaves. Finally, in the third paragraph of the section, it is shown that if the evaluation function is chosen sensibly and is consistent with the metric properties of the search space, the `A*` algorithm not only finds the optimal solution in the end, but all intermediate states are on the optimal path. In other words, in some cases the `A*` algorithm behaves just perfectly: in the best possible way. In the last paragraph we note that ideal behavior is not always guaranteed: sometimes `A*` leaves a lot to be desired.

### 3.2.1. Consistency Set

Let's give the necessary definitions and introduce the notation. The length of the shortest path from node `d1` to node `d2` is denoted by `s(d1, d2)`. Let `F*(d) = g*(d) + h*(d)` be the exact length of the shortest path from node `d0` to node `dt`, which goes through node `d`. Here `g*(d)` is the length of the shortest path from `d0` to `d`, `h*(d)` is the length of the shortest path from `d` to `dt`, i.e. `g*(d) = s(d0, d)`, `h*(d) = s(d, dt)`.

Using the definitions it can easily be shown that `∀ d F*(d) ≥ s(d0, dt)`.

In fact, a path consisting of two shortest segments passing through a given node `d` cannot be shorter than the shortest path itself. Denote `M = F*(d0) = h*(d0) = s(d0, dt)` is the optimum, the length of the shortest path, without restrictions.

Note that the functions `F*`, `g*`, `h*` and the number `M` in general are unknown to us.

Recall that we consider the evaluation function in the following form:

`F(d) = g(d) + h(d)`,

where the function `g` is already defined by us in the `Open` procedure. During the operation of the `A*` algorithm, `g(d)` has the following estimate: `g(d) ≥ g*(d)` since it is possible that not all paths have been built yet, and when opening nodes and constructing new paths, the estimate `g(d)` can decrease, but not become smaller than `g*(d)`.

The question remains the function `h(d)` - a heuristic estimate of the distance from the current position to the solution. It is clear that in the general case we cannot specify this function mathematically exactly, we can only invent it more or less successfully in individual cases. For example, the function selected in paragraph 0 for playing the 8 has turned out to be very successful. It made it possible to find a solution quickly.

How random is that? What properties should the evaluation function that determines the order in which the nodes are expanded have, so that the algorithm is guaranteed to find a solution? The following theorem gives an answer to these questions.

Search algorithm should be consistent (or partially correct) when it finds an optimal path, assuming such a path exists.

**Theorem.** When `∀d h(d) ≤ h*(d)`, then Algorithm `A*` is consistent.

The proof of the theorem is based on a set of lemmas. All lemmas are proved under the condition that `h ≤ H*`. Lemma 1 and the theorem are proved under the condition that `∀ r ∈ R (r.w > 0)`, i.e. the weight of the application of the rule is strictly positive. It follows that according to the sense of the problem all functions `F*`, `g*`, `h*`, `F`, `g`, `h` and the number `M` are nonnegative.

**Lemma 1.** If algorithm `A*` does not finish its work, the estimate of the augmented node increases indefinitely. That is, `∀ N ∃ k F(dk) > N`.

*Remark.* Here `k` is the step number of the `A*` algorithm and `dk` is the node expanded in this step.

*Proof.* Let `e = min { r ∈ R | r.w } > 0` be the minimum rule weight and `m = |R|` - the number of rules. Let `p` be the depth of node `dk` in the tree. Note that the node has the least depth when all previously opened nodes are on the previous levels of the tree and the levels are completely filled. In the limit, the level `p-1` of an `m`-ary tree contains `1 + m + m^2 + ... + m^(p-1) = (m^p - 1)/(m - 1)` nodes. Hence `k < (m^p - 1)/(m - 1) < m^p` (for `m > 2`). Then `p > log_m k`. Now let's take `k > m^N / e`. We have: `F(dk) > g(dk) > ep > e log_m k > e log_m (m^N / e) = N`.

**Lemma 2.** If there is an optimal path, then the list of open nodes always contains a node belonging to this path whose estimate is not exceeded `M`.

*Proof.* Let `A = <d0, …, dt>` be the optimal path.

Furthermore, induction on the steps of the algorithm.

Basis of induction: `d0 ∈ A` and `F(d0) = h(d0) < h*(d0) = M`.

Inductive transition. Opening a node of `A` leaves an heir at `O`. This means that the list `O` always contains a node of `A`, at least one but there can be more. Now let `d' ∈ O`, `d' ∈ A`, and `d'` is the left node of these nodes (see Fig. 34), i.e. all nodes to the left of `d'` on the path are already open and are in the list `C`. Then `g(d') = g*(d')` since the segment of the optimal path is also optimal. We have `F(d) = g(d') + h(d') = g*(d') + h(d') ≤ g*(d') + h*(d') = F*(d') = M`, because `∀d ∈ A F*(d) = M`.

**Lemma 3.** If there is an optimal path, then a node whose estimate does not exceed `M` is always opened.

*Proof.* By Lemma 2 `∃ d ∈ O F(d) ≤ M`, but the `Select` function always selects the minimum.

**Proof of the Theorem.** Proof by contradiction in three steps.

First step. Let `∃ A` be the optimal path and the algorithm does not finish its work. Then by Lemma 1 `∃ k F(dk) > M`, which contradicts Lemma 3. The algorithm then completes its work.

Second step. The algorithm can end with `fail` or `OK`. The result `error` is only possible if the list `O` is empty. But by Lemma 2, the list `O` is not empty, which means that the algorithm ends with the result `OK`.

Third step. Let the algorithm `A*` end with the result `OK`, but the path `P` found is not the optimal path. Consider the last call to the `Select` function before the algorithm finishes. Leave the selector selected as expandable node `dt`. But `h*(dt) = 0`, so `h(dt) = 0`. So `F(dt) = g(dt) + h(dt) = g(dt) > g*(dt) = F*(dt) = M`, that is, a vertex was chosen with a score greater than `M`, which contradicts Lemma 3.

This proves that algorithm `A*` terminates with the result `OK` and finds the optimal path.

**Corollary 1.** Every node `d ∈ O` for which `F(d) < M` is revealed.

*Proof.* The node `dt` with score `F(dt) = M` is chosen last for expansion, and at each step the node with the minimum score is expanded.

**Corollary 2.** Breadth-first search is consistent.

*Proof.* Breadth-first search: `h = 0`, `F = g`, and consistency condition for `h`: `0 ≤ H*`.

Consider the example of playing at 8 given in paragraph 0. It can be seen that the proposed heuristic function satisfies the consistency condition. In fact, the proposed function `h` —the number of pieces that are out of place—cannot exceed the number of steps required to put all the pieces in place. After all, we don't use more than one stone in one move!
