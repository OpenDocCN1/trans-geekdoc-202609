
## 5. Algorithm A* is unsuitable for the dynamic search case

In fact, if the productions or the goal or the weights of the rules are allowed to change dynamically during the search, [[56]](#part0005.xhtml#_ftn56) all the arguments of the previous three paragraphs become invalid. The consistency of the A* algorithm comes from the fact that choosing another path from a given node does not depend on how we got to that node. This is not the case with dynamic search: the length of the path from the current node to the target node can also differ, depending on how we got to the current node.

What has been said in this section does not mean that algorithm A* is worthless and should not be used. On the contrary, the A* algorithm is the best known solution when there is no additional specific information about the properties of the problem. If there is additional information, A* can and should be modified considering a specific task. One of the most elegant modifications is discussed in the next section.

### 3.3. SEARCH IN GRAPHICS AND/OR

When considering decomposable production systems, the concept of AND/OR graphs was introduced. In such a graph, the nodes are the states of the database or parts of it, which are obtained in two ways: either by applying a rule or by decomposing the database into components. This is exactly a graph and not necessarily just a search tree. The same vertex `d` can also appear as a result of decomposing `d1` and applying the rule to `d2`. AND/OR graphs are widely used in AI. Search algorithms like A* are specialized and refined for use with AND/OR graphs. In addition, even more efficient algorithms are known for certain special cases of hypergraphs.

#### 3.3.1. Count AND/OR

Let's refine the definitions.

The AND/OR graph is a hypergraph, i.e. a pair consisting of a set of vertices `{ d }` and a set of k-arcs, and the k-arc is a pair `d → ( d1 ,…,dk )`, where `d` is the starting node of k-arcs and `{ d1 ,…,dk }` is the set of ending nodes.

In terms of this definition, an ordinary directed graph is a hypergraph in which every arc is a 1-arc. Just as in an ordinary digraph, one can define the notion of a path (hyperpath) in a hypergraph.

A hyperpath in a hypergraph is a sequence of node sets, `<S1 , …, Sn >`, and for every node `d ∈ Si`, `1 ≤ i ≤ n–1` there is exactly one k-arc `d → (d1 , …, dk)` such that `∀ 1 ≤ j ≤ k ( dj ∈ Si+1 )`.

The definition of a hyperpath is a direct generalization of the definition of a path, but a hyperpath in a hypergraph looks more like a diagram than a single alternating sequence of nodes and arcs. Exactly one k-arc is selected from each vertex. Exactly one k-arc is again selected from each vertex obtained, and so on.

Among the various hyperpaths, we are interested in those that begin in the initial state of the database and end in final states.

The decision graph `G(d0 , T)` is a hyperpath from `d0` to the set of terminal nodes `T`.

One can give an equivalent recursive definition of the decision graph `G ( d0 , T )`:

1.  if `d0 ∈ T`, then `G = d0`.
2.  if `d0 ∉ T`, and k-arc `d0 → ( d1 ,…, dk )` starts from `d0`, and there are solution graphs `G1 , G2 , … , Gk` for vertices `d1 , d2 , …, dk`, then `G = d0 → ( d1 ,…, dk ) ∪ G1 ∪ G2 ∪ … ∪ Gk`.

The cost (weight) of the decision graph (i.e. the length of the path in the hypergraph) is determined using the inductive definition: `w ( G (d,T) ) = w ( d → ( d1 ,…,dk )) + Σ w ( G ( di , T ) )`.

Thus the same k arc can be counted many times when calculating the length.

#### 3.3.2. Search algorithm on the AND/OR diagram

To search for paths in a hypergraph, there are algorithms that generalize depth- and breadth-traversals to ordinary graphs. The fundamental difference between generalizing algorithms is that the search procedure does not stop when a separate terminal node is reached. Not only do we need to reach a separate terminal node, but we need to build a decision graph whose branches all end in terminal nodes.

In general, AND/OR graph search algorithms can work without additional information. However, in the presence of a scoring function, heuristic search algorithms can be used.

The heuristic search algorithm for the AND/OR diagram is as follows.

The graph is acyclic, there is an evaluation function `F`, and `h` satisfies the monotony condition (monotonic constraint): `h ( d ) ≤ w ( d, ( d1 ,…,dk )) + Σ h ( di )` and the consistency condition (i.e. is the lower bound for the exact solution): `h ( d ) ≤ h* ( d )`.

Search procedures on AND/OR graphs are defined as follows.

Here `s(d): bool` is the label of the node, indicating whether a hyperpath leading to the terminal nodes was found for this node. If `s(d)= true`, the hyperpath is found, then the node is called resolved.

The selection procedure, based on the constructed search graph, considers a partial decision graph and selects an unexpanded minimum cost node for expansion on that graph.

In fact, with this method, the decision front is traversed again each time from `d0` to the end nodes along the marked k-arcs.
