
We will say that the function `h2(d)` is more informed than `h1(d)` if `∀ d ≠ dt h2(d) > h1(d)`. Let `h2(d)` be a more informed function than `h1(d)`. Then no more nodes are revealed when using `F2` than when using `F1`, i.e., a more informed evaluation function finds a solution more quickly.

As an example, consider the game of eight presented in Section 2.1.4. and 0. In our terminology, `g(d)` is the depth in the game tree, `h(d)` is the estimated function of the number of misplaced pieces. So the chosen function `h(d)` in game 8 is obviously more informed than the function `h(d)` in breadth-first search (`h = 0`).

**Sentence.** If there is an optimal path and the function `F2` is more informed than the function `F1`, then by the end of the search every node extended by `F2` is also extended by `F1`.

**Proof.** Induction on `k` - the depth of the node `d` in the search tree by `F2` (Fig. 35).

**Basis of induction.** The depth is zero (`d0`). In this case, either both algorithms open node `d0`, or both do not open it (for `d0 ≠ dt`).

**Inductive transition.** Let `d` be the node chosen in step `k` for the `F2`-expansion. Let `S1` and `S2` be the sets of nodes opened to `d` by `F1` and `F2`, respectively. By inductive assumption, `S1` contains at least nodes than `S2`, which means that `S1` may have more nodes from which you can get to `d` than `S2` (Fig. 35). So `g1(d) ≤ g2(d)`. Further on the contrary. The algorithm is completed and `d` is not extended by `F1`. By Corollary 1 to the consistency theorem `F1(d) ≥ M`. But at `F2` node `d` is open, so `F2(d) ≤ M`. We have `g1(d) + h1(d) ≥ M ≥ g2(d) + h2(d) ≥ g1(d) + h2(d)`, hence `h1(d) ≥ h2(d)`, which contradicts the condition. Q.E.D.

### 3.2.3. Monotonic Constraint

You say that the function `h` fills the monotony constraint (or triangle inequality) if `h(d) ≤ h(rf(d)) + rw & h(dt) = 0`, where `r` is the rule to go from node `d` to node `rf(d)`.

In other words, the heuristic function is locally consistent with the weight of the arcs (rules).

**Sentence.** If the consistency condition is satisfied, the evaluation function satisfies the monotonic constraint, and there is an optimal path, then algorithm `A*` for expansion always chooses a vertex to which the optimal path has already been found, i.e., `g(d) = g*(d)`.

**Proof.** Induction on the length of the optimal path. Basis of induction: `g(d0) = g*(d0) = 0`.

**Inductive transition.** Let node `d ≠ d0` and let `A = d0, d1, …, di, …, d` be the optimal path. We have `∀i g*(di) + h(di) ≤ g*(di) + w(di, di+1) + h(di+1)` by the monotonic restriction. Next `di, di+1 ∈ A → g*(di) + w(di, di+1) = g*(di+1)`.

We have `∀i g*(di) + h(di) ≤ g*(di+1) + h(di+1)` and by transitivity `∀i g*(di) + h(di) ≤ g*(d) + h(d)`.

Now let `dk` be the first open node on the path `A`, i.e., `dk ∈ A, dk ∈ O & ∀j < k dj ∈ C`. Such a node exists because `d0 ∈ C, d ∈ O`. All nodes on path `A` to the left of `dk`, i.e., all closed nodes before `dk` on path `A` are already open, so `g(dk) = g*(dk)`.

Since the algorithm `A*` when opening the next node consists of two nodes `d` and `dk` choose node `d`, then `F(d) ≤ F(dk)`. So we have:

`g(d) + h(d) = F(d) ≤ F(dk) = g(dk) + h(dk) = g*(dk) + h(dk) ≤ g*(d) + h(d)`.

So `g(d) ≤ g*(d)`. But `∀d g(d) ≥ g*(d)` and therefore `g(d) = g*(d)`. Q.E.D.

**Consequence.** When the scoring function satisfies a monotonic constraint, the sequence of values of the scoring function for the selected nodes does not decrease.

**Proof.** The nodes `d1, d2` are open (in a row). If at the moment of opening the node `d1` is already `d2 ∈ O`, then by constructing `A*` we have `F(d1) ≤ F(d2)`. Otherwise, `d2` must fall in `O` when expanding `d1`. We have: `F(d2) = g(d2) + h(d2) = g*(d2) + h(d2) = g*(d1) + w(d1, d2) + h(d2) = g(d1) + w(d1, d2) + h(d2) ≥ g(d1) + h(d1) = F(d1)`. Q.E.D.

### 3.2.4. Scope of Algorithm A*

For all its merits and virtues, the `A*` algorithm has a number of inherent characteristics that can manifest as disadvantages under certain conditions.

1.  **In the worst case, the `A*` algorithm has exponential time and memory complexity estimates.** Suppose we don't have an informed scoring function that satisfies the consistency condition. In this case you have to use breadth-first search, `h = 0`. Assume (in the worst case!) that all rules hold in each state and give `n` of these rules. Also let the number of arcs in the optimal path from `d0` to `dt` be `s`. Then, as is easy to see, the total number of constructed nodes of the search graph is at least `1 + n + n^2 … + n^(s-1) = (n^s - 1)/(n - 1)`.

2.  **The efficiency of the algorithm crucially depends on the heuristic function `F`.** In fact, we noted above that without heuristics, the worst-case algorithm executes the number of steps that depends exponentially on the number of arcs of the optimal path. If we simultaneously have an extremely informed estimator such that `∀d (h(d) = h*(d))` and additionally a monotonic constraint is satisfied, then the `A*`-algorithm becomes (in the worst case!) `n*s + 1` Construct knots, since according to the theorem of the previous paragraph, in this case, knots are opened one after the other on the optimal path. Thus, in the case of an ideal heuristic, the algorithm `A*` can have a complexity that is linear in the number of arcs of the optimal path.

3.  **Algorithm `A*` does not take into account the structure of the fact base and always uses it in full.** This is extremely memory intensive and proves unacceptable for a great many practical problems. For example, when solving the problem of robot movement in an environment with obstacles, the fact base is very small - the coordinates of the robot's current position, and the `A*` algorithm shows good results. But when `A*` is applied to a large relational database in an expert system, then formally each node in the graph corresponds to a complete snapshot (dump) of the database, and the neighboring ones may differ by only one record.

4.  **Algorithm `A*` does not take into account the structure of the conditions in the rules and re-evaluates conditions that may have already been checked in previous steps.** This is very time consuming. In the example above, when checking the position of the robot, the calculations made for the previous position cannot be reused because the coordinates have changed. However, if you are checking a complex condition in a large relational database, 99% of the work is already done if you check that condition in an earlier state, since most of the data hasn't changed.
