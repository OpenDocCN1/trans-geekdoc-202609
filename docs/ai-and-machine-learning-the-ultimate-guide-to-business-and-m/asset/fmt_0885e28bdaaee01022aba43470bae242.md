
# Heuristic Search and Optimal Route Construction

Recently, considerable attention has been focused on the problem of constructing an optimal route in its most general form. Examples of relevant application areas include logistics (minimizing the transport time of goods between warehouses), administration movement robots (in environments with restrictions and obstacles), and strategic games.

Search graphs for such tasks are "pretty decent"—oriented monopartite digraphs where:
- The node is usually just a name (or a point in space, usually with metric and small dimensions)
- The density is low (far from all nodes are directly connected to each other)
- The degree of a node `d` is always estimated by a bounded constant (`deg(d) < const << n`, where `n` is the number of graph nodes)
- The weight on the arc is determined only by the cost of moving from one node to another
- The source and destination nodes are uniquely determined

It is assumed that the constructed part of the search graph necessary to solve the problem can be placed entirely in the computer's "fast" (operational) memory. The main problem addressed in this chapter is to construct an optimal (resource-minimizing) route from the source node to the destination node.

## 3.1. HEURISTIC SEARCH

Historically, one of the first and most well-known algorithms in AI for finding optimal (in terms of total weight or length) paths in a search space graph is the `A*` algorithm (read as "A-star"). This algorithm was first described in 1968 by Peter Hart, Nils Nilsson, and Bertram Raphael [18]. In their work, it is referred to as "Algorithm A". In the classical version, the `A*` algorithm is applicable in a discrete search space represented by a search graph with charged arcs. This heuristic search sorts the nodes of a graph by the value of a function that evaluates the length of the shortest path passing through a given node from the start node to one of the destination nodes. Thus, this algorithm combines consideration of the lengths of optimal paths from the already explored part of the search graph (from Dijkstra's algorithm) with the steepest descent heuristic [45] for the as-yet-unexplored part of the graph.

### 3.1.1. General Algorithm

For clarity, we repeat the definition of the search graph, make some important remarks, and write the general form of the search algorithm on the graph.

The search graph is a directed graph `G(V, E)` in which the node set `V = { d | d ∈ D }` is the set of possible states of the fact base (in the sense of the previous chapter), and the set of arcs `E` is defined as follows:

```
E = { d1 → d2 | d1, d2 ∈ D & ∃ r ∈ R ( rp(d1) & d2 = rf(d1) ) }
```

In the case where the search graph is essentially finite, it can be explicitly specified using the usual ways of representing graphs in a computer. In such cases, the search graph is often chosen as the mechanism for representing knowledge—marks on spirals are products, there is no need to indicate a set of productions separately.

In the case of an infinite (or very large) graph, we cannot use these simple representations because the entire graph does not fit in the computer's memory. Instead, starting from the initial state of the database `d0`, we generate a part of the search graph using a finite set of rules `R` until either the allocated resources are exhausted or the generated part contains the target state of the database `dt`. Thus, an implicit representation of the graph in the computer is used. A graph can be specified implicitly using the node expansion operation.

Each rule `r` has costs associated with its application, denoted by `r.w` and named the cost or weight of applying the rule. In this case, each arc in the search chart has a weight. In other words, the arcs are loaded, and the loading value can be taken as positive: `r = (p, f, w), w > 0`.

The cost of a path in a graph is defined as the sum of the costs of its arcs. The general graph search algorithm, which computes the cost of paths from the initial node and (under certain conditions!) determines the minimum-cost path [46], is as follows.

**Algorithm 3.9. General search algorithm in a diagram.**

```
GS(d0, R, t)
    O := {d0}; g(d0) := 0
    C := ∅; P(d0) := zero
    while true do
        d := select(O)
        if d = zero then return (Fail) end if
        if t(d) then return (OK) end if
        Open(d)
    end while

proc Open(d)
    for r ∈ R do
        if rp(d) then {rule holds}
            d' := rf(d)
            c' := g(d) + r.w
            if d' ∈ O ∨ d' ∈ C then {old node}
                if c' < g(d') then {better way}
                    g(d') := c'
                    P(d') := d
                end if
            else {new node}
                O := O ∪ {d'}
                g(d') := c'
                P(d') := d
            end if
        end if
    end for
    O := O - {d}
    C := C ∪ {d}
end proc
```

Where `O` is the list of "open" nodes, `C` is the list of "closed" nodes (see Figure 2.2.4).

In addition to the usual parameters and the lists of open and closed nodes already discussed, the method uses two other data structures. The first is `g(d)`—the length of the shortest path from `d0` to `d` of those explored so far. Note that `g(d0) = 0`; for other nodes at the beginning of the work `g(d)` is unknown, and as the algorithm runs, the value of `g(d)` for a given node `d` can only decrease.

`P(d)` deserves special discussion—this structure stores for node `d` the previous node on the found shortest path from `d0` to `d`. This technique allows effective storage of the set of paths leading from node `d0` to all examined nodes at once.

This graph search algorithm has two functions: `Select` and `Open`. Informally speaking, the first is "search" and the second is "on the graph".

The `Select` function somehow determines the next node to expand. If the `Select(O)` function works according to the FIFO principle (First In First Out)—that is, if the list `O` is a queue—then a breadth-first search is performed. This method ensures that a path to the destination node is found if such a path exists. If the `Select(O)` function works according to the LIFO principle (Last In First Out)—that is, if the list `O` is a stack—then a depth-first search is performed; this method is similar to a backtracking search, but not only the current path is saved, but all paths visited.
