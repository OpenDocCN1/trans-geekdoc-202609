
The `timestamps` method adds nullable `created_at` and `updated_at` "TIMESTAMP" columns. The `created_at` column is updated with the current timestamp when a new row is created, while the `updated_at` is updated when the row is updated. Finally, run the `migrate` command from your terminal or git bash.

```
php artisan migrate
```

## Create an Inventory Model & Define The Relationship

Laravel Model represents the logical structure and relationship of the underlying data table it represents. It allows you to query for data in your tables easily, as well as insert new ones. There is a Model to a table which enables you to use the Laravel ORM (Object Relational Database) to interact with such a table.

In order to create a Model, Laravel allows you to do so using the `artisan` command. Run this command on your terminal or git bash:

```
php artisan make:model Inventory
```

Under the `app` directory you would find the `Inventory.php` class there. This is the default location where generated models are stored. You can group them in an `app/Models` directory or wherever you desire, but to keep things simple we would leave it here.

Next, let us define the relationship on this table in our model. Again, Laravel allows us to define different types of relationships on multiple tables. You can define a one-to-many relationship using the `hasMany` method, or one-to-one using the `hasOne` method, or many-to-many using the `belongsToMany` method and several others in your table corresponding Model.

In our own case, a user can create/own multiple inventories and inversely an inventory will belong to a user, so we have a user `hasMany` inventories and an inventory `belongsTo` a user. Let us define that in our model.

> **Note**
>
> To learn more about other available methods for creating different column types in your database, you can checkout the available column types in the [Laravel docs](https://laravel.com/docs/5.4/migrations#creating-columns).

In our `app/User.php` model class, add the method `inventories`.

```php
public function inventories()
{
    return $this->hasMany(Inventory::class);
}
```

Open `app/Inventory.php` model class to define the opposite relationship.

```php
public function ownedBy()
{
    return $this->belongsTo(User::class);
}
```

Additionally, in the inventory model class, add a protected property `guarded` as below.

```php
protected $guarded = ['id'];
```

Don't get confused just yet. The `guarded` property is an inherited protected property already defined by the Laravel `Model` class, which our `Inventory` model class extends. Laravel allows you, using the query builder, to mass assign data into the database, simply by passing an array of data you want to insert, which will be inserted into the database.

Sometimes this can be bad, as a malicious user can guess a field in your table and inject harmful data to be passed into your database. So in order to exempt some important fields from being mass assignable, like the `id` field in our own case (since we don't want someone inserting their own id and destroy our auto increment behaviour), we simply make the field not mass assignable. Lastly, because of the soft delete feature we want to implement, we included the `SoftDeletes` trait for this purpose.

Your entire `Inventory` model class should match below:

```php
<?php

namespace App;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;

class Inventory extends Model
{
    use SoftDeletes;

    protected $guarded = ['id'];

    public function ownedBy()
    {
        return $this->belongsTo(User::class);
    }
}
```

Next, let's create a Form Request Validation to validate the request sent to the `storeInventory` method. We would be defining rules to validate the input of the user entered from the create form we would be creating shortly. One rule of thumb is to never trust user input and always endeavour to validate them. To create our Form Request, run the below command:

```
php artisan make:request StoreInventory
```

A new class `StoreInventory.php` will be created under the `app/Http/Requests` directory. Edit this file. First, under the `authorize` method, change `return false` to `return true`. Now let us define rules for the two input fields `item` and `quantity` that will be in our form.

We want the `item` field to always be a string not more than 255 characters (which is the maxlength of mysql `VARCHAR` to avoid mysql truncating the data) and `quantity` field should be an integer, not more than 100 can be allowed (assuming we do not want to ever create an inventory with over 100 stock). Both fields are required. Replace the empty array returned in the `rules` method with below:

```php
return [
    'item' => 'required|string|max:255',
    'quantity' => 'required|int|max:100'
];
```
