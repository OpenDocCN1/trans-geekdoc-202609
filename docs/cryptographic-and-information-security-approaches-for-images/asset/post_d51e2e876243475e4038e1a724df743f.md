
## 31.6 Completeness of the Biometric Based Authentication Scheme

The biometric based authentication scheme is analysed for newness to avoid replay attacks and man-in-the-middle attacks through GNY logic.

### 31.6.1 Protocol Description

The proposed scheme is transformed into the form of P → Q : X. The private key of the server is denoted as −K and the public key related to the private key is shown as +K. The user is denoted as A and the server is denoted as B for the proposed protocol.

```
A → B : {(ID_A ⊕ N_U), (h(PW_A) ⊕ B_A), ID_B, h(PW_A), {B_A ⊕ ID_A}_x}_{+K}

B → A : {(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}

A → B : {{h(K_S), K_S, h(PW_A), (N_S ⊕ ID_B), CID_A, (h(PW_A) ⊕ B_A), ID_B}_{sign}, N_P}_{N_S}
```

The above equations are parsed through the parser. The parser produces P |~ X and Q ◁ X for each description P → Q : X. The parser scrutinizes all statements of the form P |~ X and P ◁ X for each principal P. For every formula Y in P ◁ X, if Y does not appear in the line P |~ X, the parser will add a star symbol before Y. The parser discards all lines of the form P |~ X. Equation outputs after going through the parser are as follows:

```
B ◁* {(ID_A ⊕ *N_U), *SB_A, ID_B, *h(PW_A), {*B_A ⊕ ID_A}_x}_{+K} ~> A |≡ A ↔^{N_U} B

A ◁* {*(N_S ⊕ ID_B), *h(K_S), K_S}_{N_U} ~> B |≡ A ↔^{N_S} B

B ◁ {{h(K_S), K_S, h(PW_A), (N_S ⊕ ID_B), CID_A, (h(PW_A) ⊕ B_A), ID_B}_{sign}, *N_P}_{N_S} ~> A |≡ A ↔^{N_P} B

{(((h(ID_A) ⊕ N_U ⊕ ID_B)||K_P), CT_init)}_{h_p}
```

## 31.7 Goals

### 31.7.1 Message Content Authentication

- 1. B considers that the message in the first flow is identifiable

  `B |≡ φ({(ID_A ⊕ N_U), (h(PW_A) ⊕ B_A), ID_B, h(PW_A), {B_A ⊕ ID_A}_x}_{+K})`

- 2. A considers that the second flow message is identifiable

  `A |≡ φ({(N_S ⊕ ID_B), h(K_S), K_S}_{N_U})`

- 3. B considers that the third flow message is identifiable

  `B |≡ φ({{h(K_S), K_S, h(PW_A), (N_S ⊕ ID_B), CID_A, (h(PW_A) ⊕ B_A), ID_B}_{sign}, N_P}_{N_S})`

- 4. A considers that the message in the fourth flow is identifiable

  `A |≡ φ({((ID_A ⊕ ID_B) || K_P), CT_init}_{N_P})`

### 31.7.2 Message Origin Authentication

- 1. A considers that B told the message in the second flow

  `A |≡ B |~ {(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}`

- 2. B considers that A told the message in the third flow

  `B |≡ A |~ {{h(K_S), K_S, h(PW_A), (N_S ⊕ ID_B), CID_A, (h(PW_A) ⊕ B_A), ID_B}_{sign}, N_P}_{N_S}`

- 3. A considers that B informed the message in the fourth flow

  `A |≡ B |~ {((ID_A ⊕ ID_B) || K_P), CT_init}_{N_P}`

### 31.7.3 General Identity Authentication

B considers that A holds the hashed password and the original biometric to generate the template

`B |≡ A ⊳ (h(PW_A), SB_A)`

### 31.7.4 Session Key Material Establishment

A considers that B considers that N_U is a secret shared between A & B

`A |≡ B |≡ A ↔^{N_U} B`

A considers that N_U is a secret shared between A & B

`A |≡ A ↔^{N_U} B`

B considers that A possesses N_U

`B |≡ A ⊳ N_U`

B considers that A considers that N_U is a secret shared between A & B

`B |≡ A |≡ A ↔^{N_U} B`

## 31.8 Assumptions List

The assumptions made for the analysis of the proposed scheme are

- The string N_U is generated by A in the scheme so that A possesses N_U and considers N_U is new.

  `A ⊳ N_U, A |≡ #(N_U)`

- Since server’s identity ID_B is public, A considers that ID_B is identifiable.

  `A |≡ φ(ID_B)`

- The string N_U generated by A is a session key generated in the present message. Therefore, it is assumed that A considers that N_U is an apt undisclosed data between A and B.

  `A |≡ A ↔^{N_U} B`

- A considers that the server B is the right authority on getting appropriate session key data N_S shared between A and B

  `A |≡ B |⇒ A ↔^{N_S} B`

- B holds the private key −K, the public key +K and secret key x

  `B ⊃ −K, B ⊃ +K, B ⊃ x`

- The string N_S is generated by B in the scheme so that B possesses N_S and considers N_S is new.

  `B ⊃ N_S, B |≡ #(N_S)`

- The string N_P is generated by A in the scheme so that A possesses N_P and considers N_P is new.

  `A ⊃ N_P, A |≡ #(N_P)`

- The string N_P generated by A is a session key generated in the present message transfer. Therefore, it is assumed that A considers that N_P is an apt secret between A and B.

  `A |≡ A ↔^{N_P} B`

- Since B keeps the ID table, B considers that ID_A is identifiable

  `B |≡ φ(ID_A)`

## 31.9 Logical Analysis

The proposed scheme is analysed in accordance to the logical hypothesize in the GNY logic.

### 31.9.1 The First Flow

`B ◁ {(ID_A ⊕ *N_U), SB_A, ID_B, h(PW_A), {B_A ⊕ ID_A}_x}_{+K}, B ⊃ −K / B ◁ ((ID_A ⊕ *N_U), SB_A, ID_B, h(PW_A), {B_A ⊕ ID_A}_x) (T4)`

If B is told `(ID_A ⊕ *N_U), SB_A, ID_B, h(PW_A), {B_A ⊕ ID_A}_x` with the public key `+K` encrypted, and the server holds the corresponding private key `−K`, then the server is considered to have also been told the decrypted contents of that encrypted formula.

`B ◁ {B_A ⊕ ID_A}_x, B ⊃ x / B ◁ (B_A ⊕ ID_A)`

If B is told encrypted formula `(B_A ⊕ ID_A)` with key `x` the server B possesses, then the server is believed to have been informed the decrypted values of the encrypted equation.

`B |≡ φ(ID_A), B ⊃ x / B |≡ φ({B_A ⊕ ID_A}_x) (R1, R2)`

If B considers that the formula `ID_A` is identifiable and holds the key `x`, then the server B is entitled to believe that the encrypted equation `{B_A ⊕ ID_A}_x`, of which `B_A ⊕ ID_A` is a part, is identifiable. Therefore it is proved that the secret in the smart card is proved by the server.

`B |≡ φ({B_A ⊕ ID_A}_x), B ⊃ +K / B |≡ φ({(ID_A ⊕ *N_U), SB_A, ID_B, h(PW_A), {B_A ⊕ ID_A}_x}_{+K})`

If B considers that the formula `{B_A ⊕ ID_A}_x` is identifiable and holds the public key `+K`, then B is entitled to believe that the encrypted equation `{(ID_A ⊕ *N_U), SB_A, ID_B, h(PW_A), {B_A ⊕ ID_A}_x}_{+K}`, of which `{B_A ⊕ ID_A}_x` is a part, is identifiable. Therefore, it is proved that the server B can identify the communication in the first run of the proposed scheme.

### 31.9.2 The Second Flow

`A ◁ {(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}, A ⊳ N_U`

---

`A ◁ {(N_S ⊕ ID_B), h(K_S), K_S} (T3)`

If A is told a formula `((N_S ⊕ ID_B), h(K_S), K_S)` encrypted with the key `N_U` possessed by A, then A is believed to have been informed the decrypted values of the encrypted equation.

`A |≡ φ(ID_B), A ⊳ N_U`

---

`A |≡ φ({(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}) (R1, R2)`

If A considers that the formula `ID_B` is identifiable and A holds the key `N_U`, then A considers that formula `{(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}`, of which `ID_B` is a part, is identifiable. Therefore, it is proven that A can recognize the equation in the second run of the proposed scheme.

`A |≡ φ(ID_B), A ⊳ N_U, A |≡ #(N_U)`

---

`A |≡ #({(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}) (F1, F7)`

If A considers that the formula `ID_B` is identifiable and A has the key `N_U` and considers that it is new, then A considers that the encrypted equation `{(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}`, of which `ID_B` is a part, is new. Therefore, it is proved that A identifies that the message in the second flow of the proposed scheme is new.

`A ◁* {(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}, A ⊳ N_U, A |≡ A ↔^{N_U} B, A |≡ φ(ID_B, N_S), A |≡ #(N_U)`

---

`A |≡ B |~ {(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}, A |≡ B ⊳ N_U (I1)`

If all of the conditions hold: (1) A receives the formula `(N_S ⊕ ID_B), h(K_S), K_S` encrypted with the key `N_U` and marked with a non-originated mark; (2) A possesses `N_U`; (3) A considers that `N_U` is an apt secret between A and B; (4) A considers that the formula `(N_S ⊕ ID_B), h(K_S), K_S` is identifiable because `ID_B` is identifiable and (5) A considers that `N_U` is new, A considers that B once informed `{(N_S ⊕ ID_B), h(K_S), K_S}_{N_U}` and that B possesses `N_U`.

Therefore, it is proven that: (1) A considers that the second message is from the server in the proposed scheme B and (2) A considers that the server B has the temporal key `N_U`.
