# ## The UNIQUE Constraint

You’ve already seen how you can use the keywords `PRIMARY KEY` to create an index on a column that uniquely identifies each row in a table. The `UNIQUE` constraint is similar to `PRIMARY KEY` in that it creates an index on the column and also ensures that the values in the column must be unique. The main differences are:

+   - You can have as many `UNIQUE` keys as you like in a table, whereas you can have only one `primary key`

+   - The column(s) that make up a `UNIQUE` key can contain `NULL` values; `primary key` columns cannot contain `NULL`s

In the `members` table, you add `UNIQUE` constraints for the `username` and `emailAddress` columns because, although they’re not primary keys, you still don’t want to allow multiple club members to have the same username or email address.

You can also create a unique key for a column (or columns) by using the keywords `UNIQUE KEY` at the end of the table definition. So:

```
```sql
CREATE TABLE members (
    id        SMALLINT UNSIGNED NOT NULL AUTO_INCREMENT,
    username  VARCHAR(30) BINARY NOT NULL UNIQUE,
    ...
    emailAddress  VARCHAR(50) NOT NULL UNIQUE,
    ...
    PRIMARY KEY (id)
);
```
```

has exactly the same effect as:

```
```sql
CREATE TABLE members (
    id        SMALLINT UNSIGNED NOT NULL AUTO_INCREMENT,
    username  VARCHAR(30) BINARY NOT NULL,
    ...
    emailAddress  VARCHAR(50) NOT NULL,
    ...
    PRIMARY KEY (id),
    UNIQUE KEY (username),
    UNIQUE KEY (emailAddress)
);
```
