```python
class PILBase(Image.Image, metaclass=BypassNewMeta):
    _bypass_type = Image.Image
    _show_args = {'cmap': 'viridis'}
    _open_args = {'mode': 'RGB'}

    @classmethod
    def create(cls, fn: (Path, str, Tensor, ndarray, bytes), **kwargs) -> None:
        "Open an `Image` from path `fn`"
        if isinstance(fn, TensorImage):
            fn = fn.permute(1, 2, 0).type(torch.uint8)
        elif isinstance(fn, Tensor):
            fn = fn.numpy()
        if isinstance(fn, ndarray):
            return cls(Image.fromarray(fn))
        if isinstance(fn, bytes):
            fn = io.BytesIO(fn)
        return cls(load_image(fn, **merge(cls._open_args, kwargs)))

    def show(self, ctx=None, **kwargs):
        "Show image using `merge(self._show_args, kwargs)`"
        return show_image(self, ctx=ctx, **merge(self._show_args, kwargs))
```

Well, this one looks better. But what does all this mean?

All of the basic object types we want to use with our processing pipeline should look like this. They all implement a create and a show method. While the create function should prepare the input to convert to a tensor, the show just displays the input.

Let’s step into this class in detail. First thing is this parameter value: Image.Image. This is just an Image from the Pillow class. So we are expecting some sort of Pillow attribute to the class.
