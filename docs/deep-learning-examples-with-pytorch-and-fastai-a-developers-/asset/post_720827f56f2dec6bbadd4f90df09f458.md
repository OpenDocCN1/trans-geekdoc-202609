
## 26.1 Using the fastshap Library

Readers’ Caveat: The fastshap library doesn’t look for real causalities within the model. It provides an insight into how the model behaves, given specific inputs.

First we have to import the library:

```
from fastinference.tabular import *
```

Now we can create a ShapInterpretation object. It expects your Learner along with some test data to look at and any keywords that SHAP can use. If you don’t pass anything in, it will use a subset of your validation data for analyzing.

```
exp = ShapInterpretation(learn, df.iloc[:100])
```

### 26.1.1 Decision Plot

The decision plot will visualize a model’s decision by looking at the “SHAP” values for a particular row. You can think of a “SHAP” value as something like the feature importance from our permutation importance model. If you plot too many samples at once it can make your plot illegible.

We are just focusing on the 10th row of our dataframe:

```
df.iloc[10]
```

As we can see, our y value is ‘<50k’. Let’s look at how the model performed and what could have been influencing our result negatively. In other words we are analyzing how each of the features affected the model’s decision.

```
exp.decision_plot(class_id=0, row_idx=10)
```

We can see that if we pass in a class_id of zero and a row_idx, the model determines that we are using a classification model and it is looking for the score of the class <50k. If we want to use a different class, we only have to change the class_id parameter.

The model uses a gradient color scheme from *blue* to *red*. The more blue, the lower the importance of the feature. The more red, the higher the importance of the feature.

Now we can redo this analysis on the opposite (>50k).

```
exp.decision_plot(class_id=1, row_idx=10)
```

With our learner we can always just print the prediction score:

```
learn.predict(df.iloc[10])
```

From the predict-method we get the final probabilities after squishing through a softmax function. But what we can do with SHAP is to analyze what features influenced the model’s decision on both ways (<50k or >50k). We can visually see what variables were having the largest impact on the model. (Note: it shows the pre-processed datapoints)

### 26.1.2 Dependency Plots

Dependency plots use the same variable on the x axis, with the y axis being the “SHAP” values. We can pass in a variable name and a particular class ID and it will show the dependency plot for all of the test data we passed in. This allows us to recognize the relationship of these variables when they are together. For example, when my relationship is high and my age is high: How does this affect my data? (You can think of it as a kind of cluster analysis).

If we now pass in age into our dependency plot, the figure shows us the most correlated variable. In this case marital-status is the most correlated variable. So if our age-value decreases, how is this affected by the marital-status variable?

```
exp.dependence_plot('age', class_id=0)
```

If we pass in 1 for the class parameter class_id we should see the opposite of the plot.

```
exp.dependence_plot('age', class_id=1)
```

### 26.1.3 Force Plot

The force plot allows us to check how each variable affected the model at a specific value. We can see how each variable at a certain value affects whether it falls into class A or class B. An example in the model below, we can check how age affects education.

```
exp.force_plot(class_id=1)
```

### 26.1.4 Summary Plot

The summary plot should look very familiar to us. It looks like the feature importance plot.

We can see the weight on the dependent variable of each variable on top of the relative importance. For example, marital-status had the most effect of all the variables, yet it affected more on <50k than on >=50k.

```
exp.summary_plot()
```

### 26.1.5 Waterfall Plot

The waterfall plot explains one-row-predictions and how the different variables affected this specific prediction. The waterfall plot is somehow like the decision plot as it provides similar information.

```
exp.waterfall_plot(row_idx=10, class_id='<50k')
```

In this chapter we have seen several analyses of our tabular data model. It’s always important to get a good understanding of your data and how each feature scales on the output of your learner.

TabNet was a paper that was updated early this year: *TabNet: Attentive Interpretable Tabular Learning*: https://arxiv.org/pdf/1908.07442.pdf

The main difference between TabNet and the fully connected model that is used by fastai is the **use of attention mechanism** in TabNet. Therefore with this architecture we can understand what is going on in the model during training.

### Code for visualizing the fastai tabular model

```
from fastdot import *

layers_cat = ['Embedding Matrix', 'Dropout']
inp = ['Input']
cont_bn = ['BatchNorm1d']
lin_bn_drop = ['BatchNorm1d', 'Dropout', 'Linear', 'ReLU']
full_lin = ['LinBnDrop\n(ni, 200)', 'LinBnDrop\n(200,100)',
            'LinBnDrop\n(100,2)']

block1, block2, block3, block4, block5 = ['Preprocessed Input',
'Categorical\nEmbeddings',
'Continuous\nBatch Normalization',
'Fully\nConnected Layers',
'LinBnDrop']

conns = ((block1, block2), (block1, block3), (block2, block4), (block3, block4))

def color(o):
    if o == 'Embedding Matrix': return 'white'
    if o == 'Input': return 'gray'
    if 'Dropout' in o: return 'gold'
    if 'BatchNorm' in o: return 'pink'
    if 'Lin' in o:
        return 'lightblue'
    if 'ReLU' in o: return 'gray'

node_defaults['fillcolor'] = color

model = [seq_cluster(inp, block1), seq_cluster(layers_cat, block2),
         seq_cluster(cont_bn, block3), seq_cluster(full_lin, block4)]
fcc = seq_cluster(lin_bn_drop, block5)
g = graph_items(*model)
g.add_items(fcc)
g.add_items(*object_connections(conns))
```

Now we can print the visualization for our model by just calling `g`.

We see that our input is first pre-processed and then passed to an Embedding Matrix (for categorical data) or to a BatchNorm layer for continuous data. Afterwards it goes through the 3 fully connected linear layers.

This is what the fastai tabular model basically looks like. It is a very lean model (compared to the fast_tab model). Let’s analyze and compare the TabNet Model!

![](img/d5454da46c702784893ef8b0b539e5b9_375_0.png)

The head of the model is the same as with the fastai model. We start by pre-processing and passing the data either to the categorical embeddings or the batch normalization. Afterwards the outputs are concatenated and fed into TabNet. The TabNet model consists of an Attention Transformer, a Feature Transformer and a Mapping (Linear) Layer. We get 4 outputs: Output, Mask_Loss, Mask_Explain and Masks. TabNet operates by putting a mask onto the values. This allows the model to inspect which values affected the output.

Let’s first look at the Feature Transformer:
