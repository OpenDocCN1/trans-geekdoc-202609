
在 C 代码中，我们创建一个变量并将值 42 赋给它。这会分配内存并将值 42 填入该内存位置。随后我们创建一个指针，指针是一个仅包含内存地址的值，但初始时并未分配任何内存位置。这在下一行完成。变量 `var2` 然后被赋值为 `var1` 的地址。这意味着我们现在有两个变量指向同一内存位置。在下一行，我们基本上释放名为 `var1` 的变量。这就是在 Rust 中发生的情况。[Figure 2.2](#c02.xhtml#c02-fig-0002) 展示了这种情况。一旦我们将 `var1` 赋值给 `var2`，只有 `var2` 才能指向该内存位置。名为 `var1` 的变量不再指向任何位置。

![FIGURE 2.2: Assigning variables](images/c02f002.png)

[**FIGURE 2.2**](#c02.xhtml#R_c02-fig-0002): Assigning variables

如果在 `var2 = var1` 这一行之后对 `var1` 进行任何操作，你会收到编译错误，因为编译器知道该内存位置已从一个别名移动（而非复制）到另一个别名。你可能会想知道为什么是移动而不是复制。请记住，Rust 开发中内存安全是一个重要部分。一旦我们有两个不同的别名（即变量名）指向同一内存位置，就可能出现对该内存位置内容的意外修改。

此外，这也简化了语言设计和程序运行时的设计。像 Java 这样的语言使用垃圾回收器。垃圾回收器会遍历内存，将未使用的内存段返回到可分配的内存池中。一些语言使用引用计数技术来在内存不再被使用时知道何时释放。[Figure 2.3](#c02.xhtml#c02-fig-0003) 展示了一个内存位置被四个不同变量指向的情况。该位置关联了一个计数。当这四个变量中的任何一个被释放或指向其他位置时，引用计数（即指向该内存位置的变量数量）会递减。当计数变为 0 时，内存即可被释放供再次使用。

![FIGURE 2.3: Reference counting](images/c02f003.png)

[**FIGURE 2.3**](#c02.xhtml#R_c02-fig-0003): Reference counting

Rust 通过只允许在任意时刻只有一个变量名或别名拥有内存位置来避免引用计数和垃圾回收器的需求。你可以在变量名之间移动所有权，但不能同时有两个变量名指向同一内存地址。这会对编程模式产生影响，因为这不仅限于函数内的两个变量名。你不能在一个函数中拥有变量名指向某内存位置，同时将该变量名（内存位置）传递给另一个函数。

我们通过各种技巧（包括借用）来规避这一限制，但在此我们先不深入讨论所有权。我们可以先转向上一章节中开始的生命游戏程序。
