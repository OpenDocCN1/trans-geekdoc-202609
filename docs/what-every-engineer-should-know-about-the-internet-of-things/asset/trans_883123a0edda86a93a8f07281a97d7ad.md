

# IoT 信任关注点

-1. 响应时间：向系统输入一组输入到实现所需行为之间的时间，包括所有相关输出的可用性。
2. 实时系统：其逻辑正确性基于输出的正确性及其时间线的系统。
3. 硬实时系统：在这种系统中，即使未能满足某一个截止日期（deadline），也会导致系统完全故障或灾难性故障。
4. 固实时系统：在这种系统中，错过截止日期不会导致完全失败，但如果错过多个，则可能导致系统完全故障或灾难性故障。
5. 软实时系统：在这种系统中，未能满足响应时间限制会导致性能下降，但不会被销毁 (Lapante & Ovaska, 2012)。

这些传统的性能衡量标准可以作为下一代 IoT 信任指标的构建模块。例如，通过对一组执行和事件组合的响应时间取加权平均，可以得到一个 IoT 系统的“响应时间”。一旦定义了“响应时间”，就可以分配截止日期满足度的概念，并指定为硬、固或软实时。此外，还应该建立各种类型 IoT 系统、设备和通信通道的性能数据库，用于基准测试以及最终的标准开发。

## 10.19 可用性

IoT 信任的较大关注点之一是可用性——即特定用户在特定背景下，以有效性、效率和满意度实现特定目标的程度，本质上，是指设备是否“易于”使用和学习。这一因素是大多数 IT 系统的重要考虑因素，但对于 IoT 来说可能是一个更大的挑战，因为 IoT 用户界面可能受到有限显示尺寸和功能的严格限制，或者设备只能通过远程手段控制。某些设备类（如智能家居设备）的用户界面通常仅限于一组较小的机载按钮（例如，LED 状态指示器和几个按钮），以及通过计算机或移动设备远程访问的更广泛的显示和控制界面。“智能”家居用品（如灯光或水龙头）与设备没有直接接口，必须通过计算机或智能手机无线地进行管理。

此类接口对用户信任具有重大影响。用户如何知道应该采取什么操作来产生所需的响应，设备又如何发出能够被理解的确认？只有微小显示器或一两个按钮的设备最终需要复杂的交互，这些交互取决于按钮的顺序和按下或其他非活动。因此，基本的安全功能只能通过智能手机等次级设备来实现。例如，如果 IoT 设备只有两个按钮，则更新密码必须通过次级设备完成。由于这个可用性问题，用户变得更不容易更改默认密码，导致设备暴露在攻击之下。这仅仅是可用性与其他信任因素之间相互作用的一个例子。在下文讨论中，我们说明了可用性工程与性能、安全和同步等因素之间的一些复杂交互。

接口的有限在小型设备上可能是不可避免的，但这违背了 19 世纪加密的柯克霍夫法则（Kerckhoffs' rules）（Kerckhoffs, 1883）以及后来扩展到 IT 系统的（Saltzer & Schroeder, 1975）。其中一个原则是：安全系统必须易于使用，且不要求用户记住复杂的任务。IoT 系统从本质上违背了这一原则。今天，设备制造商正在发明用户界面，这些界面往往在不同设备和不同制造商之间存在巨大差异，几乎确保了为特定设备合并正确步骤变得困难。

设计 IoT 可用性的设计的挑战之一是由于设备处理和电池限制所带来的异步操作。设备可能只能定期进行通信，传输之间可能间隔几分钟到几小时；特定时间的情况可能与从设备收到的上次数据不同。由于存在多个设备，决策很可能基于某些当前无效的值，或者在系统等待更新值时操作被延迟。在最坏的情况下，实施不当的 IoT 可能会“让现实世界感觉非常破碎”（Treseler, 2014），即当拨动灯开关时，由于设备正在通信，一段时间内没有任何反应。

为了减少可用性问题，制造商已转向 AI 以允许用户与其设备进行交互。AI 最流行的用途之一是智能音箱，它允许用户只需与设备对话即可控制家电或订购产品。但对于许多 IoT 设备来说，内置这种功能会对其他设备产生重大影响。实现理想的响应能力需要工程权衡，这在本质上限制了内置安全的能力。在一个广为人知的例子中，智能音箱对对话中偶然的单词序列做出了反应，然后对其他人反应（Soper, 2018）。此类系统所需的功能：显而易见的影响是设备必须持续监听，以便在用户无需拨动开启开关的情况下做出响应。由于小型设备没有语音识别的处理能力和数据库，数据必须发送到云或类似服务中更大的处理器。因此，存在一个始终处于监听状态并连接互联网的设备，这显然是一个具有防御挑战的安全风险。此外，还需要防止系统误解它听到的用户指令（考虑两个人之间交流时有时产生误解是多么困难）。显而易见，内置可用性可能会在有效性方面带来真正的挑战。

提高设备可用性的一个建议是提供用户界面之间的一致性。需要开发标准化的方法，类似于 20 世纪 80 年代至 90 年代图形用户界面（GUI）发生的情况。在 20 世纪 80 年之前，计算机接口通常限于键盘和文本。今天的 GUI 具有相当一致的“WIMP”（窗口、图标、菜单和指针）界面，这些界面在不同供应商之间的行为相似，例如桌面比喻、双击打开文件以及操作对象的拖放功能。这种标准化的接口只有在经历了十年或更长时间相互冲突的设计和行业标准后才达成的。对于 IoT 来说，鉴于设备类型的广泛，需要一个类似的过程。

## 10.20 可见性与发现性

与其它说，IoT 代表了信息、技术与物理世界的融合。这是人类与技术关系方式的一种巨大变化，其完全影响将在许多年后才被理解。正如技术的许多方面一样，这种变化是逐渐发生的，但现在已进入指数增长阶段。然而，这种信息与物理世界的融合并不总是显而易见的。30 年前创立“无处不在”（Ubiquitous Computing）的 Mark Weiser 说：“最深刻的技术是那些消失的技术。它们将自己织入日常生活的结构中，直到与它们密不可分”（Weiser, 1991）。今天，这一愿景正在变为现实，因为 IoT 设备渗透到生活的方方面面。根据一项研究，4 年后，每个家庭将拥有超过 500 台 IoT 设备（Gartner），因此它们开始消失。

但这种消失统一是一件好事吗？如果一项技术是不可见的，那么用户将无法意识到它的存在或它正在做什么。与这种新世界相关的信任问题出现在：新闻报告暗示智能电视正在“窃听”用户（Toyukawa, 2015; Chung et al., 2017）。智能电视的语音控制遥控器只有在电视始终“监听”的情况下才能工作，但信任的影响是显而易见的。为了解决此类情况中的担忧，应用程序需要允许用户进行配置，以在便利性与个人安全及隐私需求之间取得平衡，并且设备功能应该是可见的，并对其影响有清晰的解释。

大多数计算机用户熟悉由于系统中更改了软件导致某些业务应用程序或其他软件无法运行，且软件包不再兼容而产生的问题。至少在 PC 和大型机上，人们通常对系统上运行着什么有一个大致的想法。
