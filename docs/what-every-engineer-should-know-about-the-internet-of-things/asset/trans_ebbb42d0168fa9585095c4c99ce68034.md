- 实现性能策略导致了多个组件的创建（例如规则管理器和报警器），这些组件现在依赖于虚拟设备。因此，根据目前的结构，我们可以预测对虚拟设备的某些更改可能会传播到建筑自动化系统的其他几个组件。我们希望尽量减少这些变化的涟漪效应。为了实现这一目标，我们引入了发布-订阅总线。我们将以下职责分配给发布-订阅总线：
    - 传播变化通知

通过当前的系统结构可以看出，每当规则管理器和报警器需要查询现场设备时，它们都需要进行调用，并需要跨越多个组件到达现场设备。

由于组件边界通常会引入计算开销，而现场设备的查询延迟是我们无法控制的约束条件，因此我们分解了虚拟设备并引入了缓存组件来提高设备查询性能。

该缓存为系统提供设备属性值，节省了查询实际现场设备时产生的部分性能成本。当我们减少每次查询跨越的组件和机器边界数量时，就能看到性能的提升。缓存是维护多份数据副本性能策略的应用。我们将以下功能职责分配给缓存：

- 从现场设备检索数据
- 存储现场设备配置

# 12.5 结论

IoT 是一项相对新的技术，为 IoT 系统构建架构面临着挑战。缺乏标准化是其中一个重大挑战。与 IoT 相关的硬件组件以及 IoT 的软件方面还没有一个统一的标准化平台。标准的应用程序编程接口 (API) 和软件服务使得未来的应用程序能够在统一且均衡的环境运行，便于跨系统迁移。互操作性是另一个问题。IoT 应用通过结合来自各种 IoT 设备的数据提供价值。连接性也是 IoT 架构的重要组成部分，因为它在从传感器传输数据方面起着至关重要的作用。此外，还向执行器传输指令。

虽然对于 IoT 架构还没有统一的协议，但根据一些架构师的观点，IoT 架构分为三层。另一些支持四层架构。IoT 在安全和隐私方面的挑战导致了五层架构的提议。无论架构如何，IoT 架构的挑战几乎是相同的。
