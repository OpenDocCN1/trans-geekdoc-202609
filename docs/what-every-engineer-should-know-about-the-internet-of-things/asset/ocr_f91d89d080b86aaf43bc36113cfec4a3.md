# Blockchain Technologies and IoT

In each block, the first transaction contains a “dummy” input, called “coinbase”. The first transaction contains an output, the address of the miner who validated the block, and is therefore a transaction entered by the miner itself.

The coinbase contains a fixed amount of Bitcoin to the output as a “reward” for the validation, plus the commission fees coming from the block transactions. This fixed amount, initially 50 Bitcoins, halves every 4 years.

The Bitcoin protocol provides the possibility of more complex transactions than simply transferring currency to executed. These transactions allow the execution of scripts whose content is linked to the validation of the entire transaction.

Among these, the simplest is the “OP_RETURN” type transaction. It has no output and sends all the Bitcoin to the miner. It is used to record information (equal to 80 bytes) within the transaction itself.

The most obvious form of attack to the Bitcoin system is “Double Spending”. It is an attempt to spend twice or more times the output of a transaction.

The protocol protects itself from this attack by considering valid only the first transaction that spends the output and is recorded in the blockchain. In doing so, the problem is solved in a decentralized way, without the need for a central authority to decide which transaction is the valid.

The purpose of block validation is:

+   - Validate transactions sent to the network
- Prevent fraudulent behavior

Validation is a difficult problem (on purpose), so that no one can validate a block in a short time (power of work).
The mechanism works as follows:

+   1. The users create and send transactions to the network;
2. The miners verify the transactions, and if the fees are sufficient, insert them in their block to be validated;
3. The first miner who validates the block communicates it to the other miners, who insert this block in their blockchain and starting the next block.

Transactions sent to the Bitcoin network for validation are called “unconfirmed transactions”. If a transaction is placed in a block that is validated, it becomes “confirmed”.
The nodes maintain a list of unconfirmed transactions, called unconfirmed transactions’ memory pool or mempool.

To be added to the mempool, a transaction must be validated and not spend inputs already by a transaction already in the mempool. Transactions validated by orphan blocks, but not in the correct blockchain, are put back in the mempool. If a transaction grants a fee that miners consider too low, it remains in the mempool until it is withdrawn or some miners put it in a block which is then validated.

Occasionally, two miners can validate a block almost simultaneously, communicating to the network. In this case, some of the miners accept the first block and some accept the second. This phenomenon is called “fork” of the blockchain.
