# 2.5.4 Not TESTABILITY

A testability metric that applies is titled the Domain Range Ratio (Voas & Miller, 1993). This ratio is the cardinality of the set of all possible test cases to the cardinality of the set of all possible outputs.

To understand this, consider a Not's decision trigger that forces an actual to be one of two states: ('1') or ('0'). This situation occurs in Figures 2.3 and 2.4.) Furthermore, assume that each output state occurs 50% of the time. Because of this minimal output size, a fair coin toss has a 50-50 chance of providing a correct output for any given input, and that's likely less expensive than building a complex Not. Worse, consider the scenario where '1' and '0' are not even distributed, e.g., the specification that for 1 unique test cases only 10 would produce a '1' and the other 999,990 produce a '0'. Here, you could build a Not to compute this function or you could write a piece of code that says for all inputs ('0'). This incorrect software implementation is 99.99% reliable, and you'll almost certainly not discover the defect with a handful of random tests sampled from the 1 million. In short, testing has a minimal probability of detecting the faulty logic because each test has low “detectability” due to the tiny output size and the probability density function for each output.

This shows that because of the decision trigger primitive, specifically proposed Nots may be inherently untestable without well-placed internal self-tests (assertions) upon the other primitives to increase testability.
