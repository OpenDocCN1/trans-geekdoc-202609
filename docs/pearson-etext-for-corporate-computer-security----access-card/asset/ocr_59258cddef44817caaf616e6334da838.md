# 3.7 Message-by-Message Authentication

3.7 Explain how electronic signatures, including digital signatures, digital certificates, and key-hashed message authentication codes (HMACs), work.

After two parties exchange session keys, the initial security negotiation stage is complete. The partners then begin sending many messages back and forth in the ongoing communication stage. Message-by-message authentication can protect these messages against man-in-the-middle and replay attacks.

A man-in-the-middle (MITM) attack is a form of attack in which an attacker intercepts messages being sent between two parties and forwards them on. If implemented correctly, message-by-message authentication will prevent the attacker from reading the messages. However, even if an attacker is unable to read the message, it can be sent again later.

A replay attack occurs when an attacker intercepts an encrypted message and transmits it again later. In poorly designed cryptographic systems, an attacker can record an encrypted set of commands to log in or do something else and then play them back to create the same response. Note that this works even if the message is encrypted for confidentiality and if the attacker cannot read it. These attacks can be thwarted in several ways discussed below.
