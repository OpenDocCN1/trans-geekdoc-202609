
API 和 C&C 中心能有效管理日常的 IoT 运营。由于它们本质上是中心化的，因此存在多个可被利用的弱点，例如：

- 未修补的漏洞：在大多数情况下，设备运行的是过时软件，因为最终用户需要手动下载更新，且存在连接问题。这使得它们容易受到新发现的威胁攻击。
- 弱认证：IoT 设备（如家用路由器）通常拥有易于破解的密码。这使它们成为黑客自动化脚本的易攻击目标。
- 易受攻击的 API：针对 API 的主要威胁包括分布式拒绝服务 (DDoS)、代码注入和中间人攻击 (MITM)。

这些危险可分为两类：对用户的威胁和对他人的威胁。

- 数据窃取：IoT 设备拥有大量数据，在大多数情况下，这些数据是用户独有的。数据可能包括信用卡详情、个人健康信息等。
- 人身伤害：IoT 设备在医疗领域越来越普遍。其中包括除颤器和起搏器。当这些设备受到干扰时，患者的医疗护理可能会受到负面影响。

易受攻击的 IoT 设备可能被渗透并用于僵尸网络。对于肇事者来说，发现无防护的设备并不困难。针对 IoT 设备的威胁变得更加复杂，这导致了大量网络攻击。有数十亿台 IoT 设备，因此其安全性应被高度重视。设备用户应遵循安全实践，例如阻止远程访问（如果不必要）和更改默认密码。

设备制造商和供应商应更加警惕并投资于 IoT 管理工具。他们应采取以下措施：

- 通知用户有关过时软件的信息。
- 强调智能密码管理。
- 禁用不必要的远程访问。
- 确保 API 具有严格的访问控制策略。
- 加强 C&C 中心的安全性。

# 第 19 章：域名服务器 (DNS) 劫持

DNS 劫持（或 DNS 重定向）是一种 DNS 攻击，其中 DNS 查询被错误解析，导致用户意外被重定向到恶意网站。为了实施攻击，攻击者可以在受害者的电脑上安装恶意软件、入侵/拦截 DNS 通信，或接管路由器。攻击者利用 DNS 劫持进行网络钓鱼或域名欺骗。许多 ISP（互联网服务提供商）也利用 DNS 劫持接管用户的 DNS 请求并收集统计数据。政府也利用 DNS 劫持进行审查——用户被重定向到政府授权的网站。

DNS 重定向主要有四种形式：

- **本地 DNS 劫持**：肇事者在受害者的计算机上安装特洛伊木马恶意软件。然后篡改本地 DNS 设置，使受害者被重定向到恶意网站。
- **路由器 DNS 劫持**：大多数路由器存在固件漏洞或默认密码。当攻击者接管路由器时，他可以覆盖 DNS 设置，从而影响所有连接到该路由器的用户。
- **中间人 DNS 攻击**：肇事者拦截 DNS 服务器与用户之间的通信，然后提供另一个指向恶意网站的目标 IP 地址。
- **流氓 DNS 服务器**：肇事者入侵 DNS 服务器并篡改 DNS 记录。结果，DNS 请求被重定向到恶意网站。

当攻击者将流量从合法网站重定向到恶意网站时，就会发生 DNS 欺骗攻击。DNS 欺骗可通过 DNS 重定向实施。例如，通过攻陷 DNS 服务器，攻击者可以欺骗合法网站，然后将用户重定向到其他恶意网站。缓存投毒也可用于执行 DNS 欺骗，而无需依赖 DNS 劫持。攻击者可以放入一个非法的 DNS 条目并投毒 DNS 缓存。该条目包含一个替代目标 IP。在缓存刷新之前，该域名将被解析到被欺骗的网站。

由于 DNS 名称服务器是非常敏感的基础设施，因此需要强有力的安全措施。黑客可能劫持它并用于执行 DDoS 攻击。

- 网络上的解析器：关闭任何不需要的 DNS 解析器。至于合法的解析器，确保它们位于防火墙后面，且无法从外部访问。
- 限制对名称服务器的访问：使用网络安全措施、防火墙、物理安全和多因素访问控制。
- 警惕缓存投毒：域名中的大小写和查询 ID 应随机化，并尝试使用随机源端口。
- 处理已知漏洞：攻击者总是在寻找易受攻击的 DNS 服务器。
- 解析器应与权威名称服务器分离：两者不应运行在同一台服务器上。
- 确保区域传输受到限制。

对于最终用户，安装杀毒软件、更改路由器密码和使用加密 VPN 通道等操作可保护他们免受 DNS 劫持。

## 网站所有者的缓解措施

应采取的步骤：

- DNSSEC
- 客户端锁定
- 安全访问

# 第 20 章：跨站请求伪造 (CSRF) 攻击

CSRF（也称为会话劫持、Sea Surf 或 XSRF）是一种操纵 Web 浏览器在用户已登录的应用程序中执行非预期操作的攻击。当 CSRF 攻击成功时，用户和企业都会受到影响。它可能导致未经授权的资金转移、数据窃取（包括会话 Cookie）、密码篡改或客户关系受损。CSRF 通常通过社会工程学攻击执行，例如诱导用户向服务器发送伪造请求的链接或电子邮件。应用程序在攻击期间对毫无戒心的用户进行身份验证——这使得很难区分伪造请求和合法请求。

## CSRF 攻击示例

攻击者花费一些时间研究应用程序，以便使请求看起来完全像合法请求。以 `GET` 请求为例，假设进行 200 美元的银行转账。它通常如下所示：

```
GET http://netbank.com/transfer.do?acct=PersonB&amount=$200 HTTP/1.1
```

攻击者可能会篡改此脚本，将 200 美元转入自己的账户。恶意请求可能如下所示：

```
GET http://netbank.com/transfer.do?acct=AttackerA&amount=$200 HTTP/1.1
```

然后攻击者可将此请求嵌入到一个看似无害的链接中：

```html
<a href="http://netbank.com/transfer.do?acct=AttackerA&amount=$200">Read more!</a>
```

攻击者的下一步是通过电子邮件将此链接发送给尽可能多的银行客户。任何在登录银行账户时点击该链接的人，都可能无意中向黑客转账 200 美元。如果银行仅使用 `POST` 请求，则使用 `<a>` href 标签执行的恶意请求无法成功。尽管如此，攻击者仍可结合自动执行的嵌入式 JavaScript 使用 `<form>` 标签。

例如：

```html
<body onload="document.forms[0].submit()">
<form action="http://netbank.com/transfer.do" method="POST">
<input type="hidden" name="acct" value="AttackerA"/>
<input type="hidden" name="amount" value="$100"/>
<input type="submit" value="View my pictures!"/>
</form>
</body>
```
