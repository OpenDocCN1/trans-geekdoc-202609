### 2.2.1. Techniques for local interpretability

Local Model-agnostic Explanations (LIME) (Ribeiro et al., 2016) is one of local techniques. LIME learns to interpret each specific prediction. LIME is a linear model, which approximates the importance of each feature and whether the feature has a positive or negative impact on the final prediction. Non-linear (or rule-based) approaches can also take into account the combined effects of features in individual predictions. It is also possible that these techniques do not work well in the case of a binary prediction, but a focus of features together. An example of such a technique is SHAP (Ribeiro et al., 2018). An explanation is an analysis that explains a local prediction, so that changes can be made accordingly. Since SHAP uses rules, it is possible to combine features and is much more powerful compared to LIME, also with some stemming from the comparison of features as to a single angle.

Aquitas (Salinas et al., 2018) focuses on data exploration as output and makes it attractive to both data scientists and decision makers. General, it explores exploration of the system and its role in facilitating and understanding data dependencies. Aquitas focuses on bias and visualisation based on specific demographic groups. The library does not directly interact with the model, but with the results of the model, correct classification of cases. Fairness measures, for example false positive rate, are calculated and visualised in detail, showing the groups with their respective fairness and performance scores.

It is possible, even when a feature is not used in the training of the model, such as race, is present in the training data, the results may be biased against those groups (Okamoto et al., 2018), which has been discussed in the subsection on global interpretability, but also be used to see in rules with regards to ‘predictions’. By observing predicted features, it is possible to determine whether the predicted features are used in the model.

### 2.2.3. Techniques for global interpretability

SHAP (Lundberg & Lee, 2017) can be used to test the explainability, and also be used to estimate global interpretability. With local interpretability, it is possible to see that features have a global impact on the model with a different enter. An instance where secondary features impact the global model by iteratively observing the features in the data set to get certain and assess the impact on the test set. This technique, called BlackBoxAuditing (Adler et al., 2018), can be used for global interpretability by identifying the importance of features in the data set, as well as determine whether a prediction is still impacting the model through its secondary features, monitoring the error rate achieved by the model.

One of the known techniques for explaining machine models is SHAP (Lundberg & Lee, 2017) which uses a cooperative game theory to explain the prediction of a specific instance by how much each feature contributed to the prediction, in the presence of combinations. All predictions result in a matrix of values, which can be compared for the entire model, thus providing global interpretability (Lundberg & Lee, 2017; Molnar).

## 2.4. Fraud matching for insurers

The organisation uses a box-like model in the environment to estimate the risk associated with mortgage application. The model uses basic properties of mortgage indicators as considered in research reports. In total, the model uses 75 features. Each case is assigned a risk score, and the top five cases are passed to manual review. Due to capacity issues, only cases with high risk are disclosed.

A currently, right-driven system generates an explanation for the case risk, before they are forwarded to the reviewers. This explanation is generated using 25 expert-constructed features, which trigger on specific values of individuals, meaning the coverage of rules does not match the 75 features used by the model. The reviewers who are assigned use a maximum of fifteen minutes to verify the generated explanation. Our MLXI system allows for all 75 features used by the model to be present in the explanation for reviewers, and allows for the combination of features that might indicate a high risk of fraud.
