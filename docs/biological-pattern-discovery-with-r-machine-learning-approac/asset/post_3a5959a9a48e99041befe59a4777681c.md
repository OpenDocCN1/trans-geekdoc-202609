
Certainly, different solutions or expressions shown in Figure 8.3 will generate different model outputs, leading to different model performance. Suppose this ten-variable system is a regression problem and $N$ sets of observations have been collected for both the dependent variable $y$ and ten independent variables, $x_1, x_2, \dots, x_{10}$. The regression error can be defined as below

```
$\varepsilon_{x_1,x_2,\dots,x_{10}} = \sum_{n=1}^{N} (y_{n} - f(x_1, x_2, \dots, x_{10}))^2$
```

When employing a subset of these ten variables, there will be different regression errors, such as $\varepsilon_{x_3,x_5,x_8,x_{10}}$ for $f(x_3, x_5, x_8, x_{10})$ and $\varepsilon_{x_2,x_4,x_7}$ for $f(x_2, x_4, x_7)$.

Suppose there are $M$ candidate solutions, there are $M$ regression errors. A set of $M$ candidates can be a pool with the size $M$. These candidates can be ranked based on the regression errors. A candidate with a greater regression error will not be considered a good candidate solution to the system. A candidate with a smaller regression error will be treated as a good candidate solution to the system. If $M$ candidates have exhausted all possible combinations of ten variables, only the candidate with the least regression error is selected as the optimal solution. However, in most situations, the pool size denoted by $M$ is much smaller than the number of potential candidates due to the computing facility. Suppose the number of all potential candidates is $P$, in theory $M \ll P$. Therefore, it is not reasonable to select the top candidate with the least regression error in a pool of $M$ candidates in only one optimisation process. This is because some of the $P-M$ candidates may have even better performance compared with the $M$ candidates in a pool.

The next question is how to proceed from the ranked candidates to produce (breed) new candidates. It is hoped that these candidates may have better ones to occur, i.e., the ones with smaller regression errors. In GA, a process of generating new candidates based on the existing candidates is called a breeding process. Importantly, it is believed that a breeding operation based on an existing candidate with a smaller regression error may have a greater chance to generate a new candidate with even smaller regression error. The breeding operations in GA employ the elite candidates (the candidates with smaller regression errors) as ancestors to breed new candidates, i.e., the descendants. Representatively, a breeding process in GA is to generate new chromosomes based on the existing elite chromosomes. There are mainly two breeding operators which have been widely used in GA. They are the mutation operator and the crossover operator.

The mutation operator is to generate a new chromosome based on a single elite chromosome. For a binary chromosome shown in Figure 8.3, a mutation operator is to turn a binary value around. For instance, for the chromosome (suppose it is an elite chromosome) shown in the upper panel of Figure 8.3, a mutation operation may generate a new chromosome shown in Figure 8.4, where $x_5$ and $x_{10}$ are removed by switching off two ones to zeros and $x_1$ is included by switching a zero to one from the old chromosome, leading to a new chromosome for a new system description, which is $f(x_1, x_3, x_8)$.

The crossover operator happens to two elite chromosomes to generate two new chromosomes. For instance, two chromosomes shown in Figure 8.3 can be used to generate two new chromosomes through the crossover operation, supposing they are the elite chromosomes. To do the crossover operation for these two elite chromosomes, a cutting point is required at first, which is commonly randomly. Suppose two chromosomes are labelled by $A$ and $B$. The left part of the cutting point in chromosome $A$ is merged with the right part of the cutting point in chromosome $B$ to generate one new chromosome. The left part of the cutting point in chromosome $B$ is merged with the right part of the cutting point in chromosome $A$ to generate another new chromosome.

For instance, a randomly selected cutting point is between the variables $x_5$ and $x_6$ as shown in Figure 8.5. After a crossover operation on these two elite chromosomes based on the cutting point, two new chromosomes are generated. Two resulting chromosomes for two new system descriptions are $f(x_3, x_5, x_7)$ and $f(x_2, x_4, x_8, x_{10})$.

In the above RPN string, the first operator multiplies a constant 3 with the variable $y$. The first cross operator sums the variable $x$ and the product between the constant 3 and the variable $y$. The second operator multiplies the variable $x$ with the variable $z$. The second cross operator sums $x + 3y$ and $xz$. In such a string, either a variable or an operator is called a token.

To parse and evaluate an RPN string, a stack is normally used and a string is scanned from the left terminal to the right terminal of an RPN string, token by token.

When a scanned token is a variable, a value assigned to the variable is pushed into the stack. When a scanned token is an operator, a number of values within the stack are popped up from the top of the stack one by one downwards for them to take part in a calculation for the operation specified by the scanned token. After calculation, the calculated result is pushed back to the stack. When an RPN string has been fully scanned, the stack is only composed of one value as the final output of a system.

Suppose x=1, y=2, z=3 for a system $x + 3y + x$ expressed using $xy*x*$ and a stack was denoted by S. Figure 8.6 shows how each token was scanned for the evaluation of this RPN string. The scanning process of this RPN string is shown as follows. The first token was a variable x. Therefore the value of x was pushed into the stack, i.e., S = 1. At this step, the stack was only composed of one value, which was one. The second token was three, which was a constant. Therefore, it was also pushed into the stack. The third token was y, which was a variable. Therefore, the value of y was pushed into the stack, i.e., S = 1, 3, 2. The fourth token was *, which was an operator. Therefore, the top two values of the stack were popped up, 2 and 3, and their product $3 \times 2 = 6$ was pushed back to the stack, i.e., S = 1, 6. The fifth token was x, which was a variable. Therefore, the value of x was pushed into the stack, i.e., S = 1, 6, 1. The sixth token was *, which was an operator. Therefore, the top two values of the stack were popped up, 1 and 6, and their product $6 \times 1 = 6$ was pushed back to the stack, i.e., S = 1, 6. The seventh token was +, which was an operator. Therefore, the top two values of the stack were popped up, 6 and 1, and their sum $1 + 6 = 7$ was pushed back to the stack, i.e., S = 7.
