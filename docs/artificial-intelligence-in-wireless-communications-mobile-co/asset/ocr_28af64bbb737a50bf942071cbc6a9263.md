# Overview and Basics of Software Defined Radios

```
$P = 10 \log_{10} \left( \frac{1}{K} \sum_{i=0}^{K-1} |x_i|^2 - n \right) \quad \text{dBm}$
```

Here the xi are time samples in milliwatts and $n$ is the estimated power in milliwatts. The GNU Radio block that implements the average magnitude squared simply calculates the norm of each complex signal and uses a single-pole infinite impulse response (IIR) filter to average the results.

Path loss and the energy per bit to noise ratio ($E_b/N_0$) are easy to estimate since the radios know the transmitted power and received power, the difference is therefore the path loss, and the radio has already estimated the received noise and power. Both of these values are converted into the energy per bit ($E_b$) and noise density ($N_0$) to accurately reflect the modulation behavior. The simulation calculates $E_b$ from the signal power by dividing it by the bit rate, $R_b = KR_s$ where $k$ is the number of bits per symbol and $R_s$ is the symbol rate. The calculation of the noise comes from dividing the received power by the receiver bandwidth. In this case, the simulation is all in the digital domain, so the noise power reflects the amount of power in the sampling interval, which is represented by the number $N_0 = N/sps$, the noise power divided by the number of samples per symbol.

In our simulation, the BER calculation is a more complicated. Figure 3.5 shows a BER calculation block (gr_ber_calc) with an input from the transmit path and one from the receive path. The BER is not simply a comparison of the transmitted and received bits as a one-to-one comparison because of the delay introduced by the blocks in the flow graph. The received bits are therefore delayed some amount from the transmitted bits. Furthermore, we observed the delay is different for different types of modulations, changes with the symbol rate, and for some types of modulations, the delay is not consistent with runs (GMSK, for instance, would have a delay of 7 or 8 samples during any given run). Consequently, the BER calculation block calculates and compensates for the delay. To do this, it waits to see a particular start code from both the transmitter and receiver and calculates the delay between corresponding samples. To avoid the problem of losing the start code in noise, the start packet is always transmitted with a much higher SNR (near infinite in the simulation by setting the noise voltage to 0).
