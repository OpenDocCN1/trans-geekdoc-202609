A useful message will describe what the commit did. Lastly, running git status will show that the Git staging area is empty and the commit is complete, as in Figure 5.15.

```
Windows PowerShell
PS C:\Users\name\new_project> git status
branch master
nothing to commit, working tree clean
```

FIGURE 5.15: Clean Working Directory

Users to Git frequently ask why separate add and commit commands need to be run. The add command is used to mark files to be committed, which is called staging. It may happen that files are not all staged at once, that some files are removed from staging. Once the user is ready, the commit command will save and track the changes. Using the analogy of a flight, the add command gets people onto the plane, and the commit command is akin to takeoff.
