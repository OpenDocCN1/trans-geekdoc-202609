# 4.6 Data integration

*Data integration* is the process of preparing and combining the ingested data sources. As an example, consider a financial analyst that needs to determine if a company is likely to go bankrupt. There are many potential data sources that might be useful, including news, financial statements, historical stock price data, analyst reports, and videos from Bloomberg. After the various sources are ingested, they will need to be processed and combined. The video data can be translated to text, which may then be converted to numbers. The financial statements might hold tables of numbers, and these numbers need to be stored in more useful structures. Data integration is the process that implements all of this work. To be effective at scale, it needs to be accurate, fast, secure and Following ingestion of data, it needs to be extracted, transformed, and loaded into storage, generally in this order. This sequence is so common that it is given the acronym ETL for Extract, Transform, Load. The object that implements the steps is called the ETL pipeline. The extract step moves the raw, ingested data to a landing zone for staging. The landing zone provides temporary storage until the data is finished and moved to its destination, the landing zone is often deleted.
The transform step applies various functions to make the data more use This might involve reshaping and filtering the data. The load step stores the data into a repository, such as a data warehouse or data lake. ETL pipelines are the workhorses that implement these operations, and they facilitate the operation of systems. We will discuss data transformations and storage options in more detail in the book.
an alternative to ETL is this paradigm, the extracted data is stored first and processed later. This is common when the values and data elements will be determined later. For example, data scientists might load the contents of scraped web pages, parse out elements of interest, and structure them into a table.
