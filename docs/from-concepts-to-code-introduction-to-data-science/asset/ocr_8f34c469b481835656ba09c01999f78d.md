To properly validate a model, it must be effectively challenged. The concep-
t soundness of the overall system and each component must be examined
and understood. The validation process helps understand the assumptions and lim-
ations of the data and the model, as well as the development decisions made.
model development document should capture this information, and it should
be updated over the model lifecycle.

The performance of the model needs to be measured and monitored over
time to ensure it meets expectations. Outcomes analysis will compare pre-
dicted values to actual outcomes. If users find that predictions exhibit
bias, or deviate from actual values in a predictable way, they might override
the complex model. Model users should be interviewed to capture and understand any
overrides, as this presents an opportunity to improve the model.

To make models easier to monitor, they should be observable, and their
line statistics should be captured. The important steps and intermediate
quantities can be logged. If metrics deteriorate, the logs can be searched.
Other layers to investigate are the predictors, processed data, raw data, and
data feeds. The distribution may change over time, and this is
called factor drift. This phenomenon can be modeled as the relationship

Model benchmarking compares the model to an alternative model or met-ic. The benchmarks should be relatively simple approaches or heuristics. A more
complex model should beat these benchmarks to be valuable. Sensitivity analys-
is to slightly changing the model assumptions and measuring
impact to the output. Stress testing is the practice of running the model
on plausible, extreme scenarios to measure its response. This may sur-
faces issues with the model which can be investigated. It is also useful as a
"what if".
