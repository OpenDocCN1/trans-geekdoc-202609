## 安装

### brew.sh¹

我不想在这里列出这些说明，因为它们在不同版本之间经常发生变化。一旦你安装了 Homebrew，就可以安装更新版本的 PHP 了。我建议安装 5.5 版本。你可以使用以下命令来操作：

- `$ brew install php55`

接下来，你需要将此版本 PHP 的路径添加到系统的 PATH 变量中。别担心，只需输入以下内容：

- `$ PATH=$usr/local/Cellar/php55/5.5.13/bin:$PATH`

你可能需要更新版本号，以匹配 Homebrew 在你的系统上安装的 PHP 版本。现在，让我们再次检查一下 PHP 的版本。

- `$ php -v`

希望这次你获得的版本大于 PHP 5.4。如果是，请直接跳到下一章吧。

## Windows

在 Windows 上安装 PHP 稍微困难一点，至少对我来说是这样。我在 Windows 10 机器上测试了下面的说明，但如果你在操作这些步骤时遇到任何困难，请告诉我，我会找一个更精通 Windows 的人来重写这一节。

首先，访问：

http://www.php.net/download

在这里，你需要下载最新的 PHP 5.4 及以上的 zip 压缩包。下载完成后，你需要将其解压到一个合适的位置。我选择将其解压到这里：

- `C:\Users\Dayle\PHP`

你需要一个命令行提示符来执行我们在书中编写的脚本。这里有一种在 Windows 上运行命令行提示符的好方法。

在桌面上或任何文件夹上点击右键，选择“创建快捷方式”。在目标框输入：

¹brew.sh/

- `cmd.exe`

点击“下一步”，并将快捷方式命名为“PHP”。

最后，你需要右键点击快捷方式并点击“属性”。在“快捷方式”选项卡上，将“起始于”字段更改为你解压 PHP 压缩包的位置。点击“确定”即可完成。

双击你的 PHP 快捷方式，你就会看到一个命令行提示符。输入...

- `php -v`

..你就能看到 PHP 版本信息了。确认版本大于或等于 PHP 5.4，然后进入下一章。

再次对这个子小节的粗略描述表示歉意。我已经多年没有用 Windows 作为开发机器了。如果有人有更好的在 Windows 上运行 PHP 的方法，请将你的说明发邮件给我，你就能在本章中获得你的五分钟成名！

## 开发者是机器人。

你为什么决定追求开发？不，等一下！让我猜猜。你看到一个星级的 PHP 开发者从豪华车走出来，进入纽约最火的夜场所，和 Jay-Z 以及 Tupac 的幽灵一起点了 5 瓶水晶香槟。

> 噢，天，那个开发者一定是个机器人。他们知道所有的代码单词、函数以及它们是如何运作的。

没有开发经验的人往往会假设开发者是拥有数学荣誉学学位的天才。也许对于某些开发者来说这是事实，但对我来说绝对不是。我想其他开发者也会同意我的观点。

事实是，我们并不完美。我们甚至离完美还很远。如果你认为开发者能记住所有这些 PHP 函数和代码段，那你就是在自欺欺人，认为自己永远没有能力跟上。

事实并非如此。我们并不背诵所有内容。事实上，我们每天使用的代码大部分都是参考得来的。我们是“Google 战士”。PHP 中有些函数可以对文本行进行最简单的操作，而我几乎每周都会查看一次 PHP 文档，以找到我传递给它们的参数顺序。

当我完全卡住时，我会尝试使用 Google 看看是否有其他开发者遇到过类似的挑战。通常，我会找到另一个开发者发现的合适解决方案，或者足够引导我找到答案的信息。当然，这也是双向的，我会尝试把我的解决方案回馈社区。我会在 Stack Overflow 上发布回答，并参与论坛或讨论。回馈社区是非常重要的。

所以你看，我们不是机器人。我们并不了解这种语言的一切，也不是对每个问题都有解决方案。然而，我们是出色的研究人员。我们是机会主义者。我们是资源丰富的问题的解决者。我们是开发者。

## 插值 (Interpolation)

字符串是程序员对应用程序变量中存储的文本序列的名称。让我们给一个变量赋值一个字符串来复习一下。


好了，我知道第二行是多余的。我把它留在那儿是为了提醒你，有两种不同类型的引号可以包裹字符串值。

那么，既然我们有两个选择，区别在哪里呢？总不能仅仅是为了清晰度吧？我的意思是，在我看来它们看起来都都一样简洁。

嗯，其实是有区别的。包含在双引号中的字符串值要聪明一点点。它们拥有一种单引号兄弟无法做到的技巧，这被称为**字符串插值**（String interpolation）。

这个术语听起来很糟糕，对吧？它非常令人困惑。它简单意味着我们可以在字符串内部嵌入值。让我们来看看它的实际效果。

示例 02：字符串插值。

```php

// 单引号。

// 双引号。
$second = "We love $value";

// 输出。
var_dump($first);
var_dump($second);
```

我们将尝试向两种类型的字符串中通过变量名插入变量。让我们查看输出这两种类型字符串的结果。

示例 03：输出。

```php

string(15) "We love pandas!"
```

如你所见，使用单引号时，变量名就像字符串的一部分一样呈现出来。然而，在双引号字符串中，我们的变量名已经被替换成了变量的值。

哇！这超级有用。不是吗？

我想给你一点小建议。最好将插值包裹在`{ 这种大括号 }`中。这会让插值变得整洁得多，而且你会发现当你开始使用数组时，它的工作效果会更好。

## Else

Else！Else？！抱歉。它听起来就像肥皂剧里那些戏剧性的时刻。你知道的，当有人用“否则（or else!）”威胁别人时。实际上，`else` 只是 `if` 语句的另一个扩展。我们要仔细看看吗？

### 示例 08：带有 else 的 if

```php
$panda = 'Pali';
if ($panda == 'Lushui') {
    echo 'Yey, Lushui time!';
} else {
    echo 'Oh hey there Pali!';
}
```

我们语句的 `else` 部分功能方式与 `if` 部分类似。唯一的区别是 `else` 不需要条件。如果条件求值为 `false`，则大括号内的代码将被执行。

### 示例 13：带有多个 case 的 switch 块

```php
<?php
$panda = _SOMETHING_;
switch ($panda) {
    case 'Lushui':
        echo 'Yey, Lushui time!';
    case 'Pali':
        echo 'Oh there Pali!';
    case 'Jasmina':
        echo 'Looking pretty Jasmina!';
}
```

在这里我们可以看到多个 `case` 语句。但要小心！代码段中有一个陷阱。你会发现，无论匹配哪个 `case` 语句，下方其他 `case` 语句的代码都会被执行。如果我们希望执行它们，这可能会非常有用。

这意味着如果 `$panda` 的值为 `'Lushui'`，那么所有三个 `echo` 语句都将被执行，但现在我们并没有！那么，我们如何确保只执行一个 `echo` 语句呢？很简单！我们需要一个 `break`，或者三个！

### 示例 14：break 语句

```php
<?php
$panda = _SOMETHING_;
switch ($panda) {
    case 'Lushui':
        echo 'Yey, Lushui time!';
        break;
    case 'Pali':
        echo 'Oh there Pali!';
        break;
case 'Jasmina':
    echo 'Looking pretty Jasmina!';
    break;
}
```

如果我们在 `echo` 语句之后的行放置一个 `break` 语句，就可以在该点停止 `switch` 语句的执行。执行流将跳出 `switch` 并在最后的闭合括号 `}` 之后继续执行。

这些 `break` 语句的效果与 `elseif` 和 `else` 语句类似。`break` 是一个会中断当前执行分支执行的关键字。这是一个非常值得记住的用法！

我们的 `switch` 语句还缺少最后一点东西。目前，它类似于一个末尾没有 `else` 的 `elseif` 语句。那么，我们如何实现带有 `else` 的功能呢？很简单，我们只需要提供一个默认值（default）即可！

让我们修改一下示例吧？

### 示例 15：default

```php
<?php
$panda = _SOMETHING_;
switch ($panda) {
    case 'Lushui':
        echo 'Yey, Lushui time!';
        break;
    case 'Pali':
        echo 'Oh hey there Pali!';
        break;
    case 'Jasmina':
        echo 'Looking pretty Jasmina!';
        break;
    default:
        echo 'Sorry, who are you?';
}
```

`default` 语句的工作方式与 `case` 语句类似，不同之处在于不需要提供比较值。如果其他 `case` 语句都没有匹配，将执行 `default` 下方的代码。

`default` 语句不需要 `break`，因为它是 `switch` 语句的最后部分。不过，如果你为了清晰起见添加它，也不会产生任何功能上的区别。

### 示例 06：两个闭包

```php
  return $type($first, $second);
```

如何在我们的类上定义方法呢？很简单。事实上，你已经知道这种格式了！让我们创建一个简单的函数来打招呼。

### 示例 14：创建类方法

```php
<?php
// 定义 Book 类。
class Book {
    // 声明属性。
    var $title;
    var $author;
    var $publisher;

    // 声明方法。

    }
}

// 创建一个新的书籍实例。

// 修改 format 值。
```

## 构造函数

构造函数是特殊的方法。当你创建类的新实例时，它们会被调用。这为你提供了一个极佳的机会，可以将类属性设置为你其他可能无法设置的值，例如函数或方法的结果。

要定义构造函数，我们只需要一个名为`__construct()`的方法。值得注意的是，函数名的开头有两个下划线。遗憾的是，虽然 PHP 是一种极其灵活的语言，但在描述性或方便的函数命名方面往往不尽人意，`__construct()`例外。别担心！它很快就会变成你的本能。

### 示例 22：创建一个类

```php
<?php
// 定义 Panda 类。
class Panda {
    // 大写名称属性
    var $loudName;

    // 构造函数方法。
    function __construct() {
        $this->loudName = $this->makeNameLoud('Lushui');
    }

    // 名称变大方法。
    function makeNameLoud($name) {
        return strtoupper($name);
    }
}
```

我们有一个带有`makeNameLoud()`方法的类，它对字符串进行转换。我们已经发现，不能直接使用函数或方法为类属性设置默认值，相反我们使用构造函数来设置初始值。

## 抽象类 (Abstract Classes)

对于某些类来说，它们的唯一目的是提供公共的属性和方法。它们为此而生。当它们在晚上睡觉时，梦的都是这个。

它们永远无法被实例化，因为它们本身没有意义。考虑以下类，为了清晰起见，我将它们留空了。

**示例 01：类继承。**

虽然`Animal`类可能为`Panda`（熊猫）、`Owl`（猫头鹰）和`Giraffe`（长颈鹿）类提供许多共享特征，但直接实例化是没有意义的。我们的`Animal`类是抽象类的典型例子。让我们把它变成抽象类吧。

## 抽象 (Abstracts)

### 示例 02：抽象类 Animal。

```php
<?php

abstract class Animal {

    /**
     * 动物是否很棒（都是如此）。
     *
     * @var boolean
     */
    private $awesome = true;

    /**
     * 获取 awesome 属性。
     *
     * @return boolean
     */
    public function isAwesome() {
        return $this->awesome;
    }

}
```

在上面的示例中，我们仅通过在类定义开头使用`abstract`关键字将类声明为抽象类。其他所有内容应该看起来都很熟悉。如果我们扩展这个类，我们所有的动物都会继承`isAwesome()`方法。

让我们尝试直接实例化`Animal`类。

### 示例 03：创建一个新的 Animal 实例。

```php
$animal = new Animal();
```

当我们执行代码时会发生什么？

### 示例 04：输出。

```
Fatal error: Cannot instantiate abstract class Animal in <file> on line <line>.
```

现在我们的类被标记为抽象类，它不再可以被实例化。这是符合预期的，因为该类只有一个目的，就是为其他类提供功能。

## 抽象方法 (Abstract Methods)

抽象方法用在抽象类内部。再次，使用`abstract`关键字来定义抽象方法。让我们从一个示例开始。

**示例 05：一个抽象方法。**

```php
<?php

abstract class Animal
{
    abstract public function makeNoise();
}
```

我们在作用域之前使用`abstract`关键字定义了一个名为`makeNoise()`的新方法。你会注意到`makeNoise()`方法没有方法体，而是直接以分号结束。

多么毫无意义的方法！

你说得对。就其本身而言，它确实毫无意义。事实上，抽象方法甚至无法被调用。那么为什么要费心呢？嗯，抽象方法与所有扩展它的类形成了一种类型的“合同”。它在告诉 PHP：“任何扩展此类的类**必须**定义一个`makeNoise()`方法。”让我们通过添加另一个类来演示这一点。

**示例 06：扩展 Animal 类。**

```php
<?php

abstract class Animal
{
    abstract public function makeNoise();
}

class Dog extends Animal
{
}
```

我们在`Dog`类中扩展了基类`Animal`。让我们尝试实例化一个新的`Dog`，好吗？

### 示例 07：创建一个新的 dog 实例。

```php
$dog = new Dog;
```

现在我们只需执行代码然后……哦不不。

### 示例 08：输出。

```
PHP Fatal error: Class Dog contains 1 abstract method and must therefore be declared abstract or implement the remaining methods (Animal::makeNoise) in <file> on line <line>.
```

幸运的是，我一直觉得 PHP 错误很容易理解。PHP 正在告诉我们我们的`Dog`类包含一个来自基类`Animal`的抽象方法`Animal::makeNoise`。

PHP 给了两个选项。首先，我们可以让`Dog`类也变成抽象类，这意味着它同样无法被实例化。这不是我们想要的，因为该类只有一个目的，即为其他类提供功能。第二个选项是实现该方法。让我们通过这种方式来完善。

**示例 09：实现 makeNoise 方法。**

```php
<?php

class Dog extends Animal
{
    public function makeNoise()
    {
        echo "Woof!";
    }
}
```

通过实现方法，该类不再是抽象的。我们现在可以实例化了。

**示例 10：实例化一个 dog。**

```php

    public function poop()
    {
        echo "Pooping...";
    }
```

是时候创建一个新类了。我们将称称为 ZooKeeper（动物园员）。这个类没有继承任何其他类，也没有实现任何接口。

### 示例 09: ZooKeeper 类。

```php
{

     */
    public function care(PandaInterface $panda)

        $panda->poop();
```

`ZooKeeper`类包含一个照顾熊猫的单一方法。我们没有直接对`RedPanda`或`GiantPanda`类进行类型提示，而是对接口本身进行了类型提示。

```php
$keeper->care($giantPanda);
```

首先，我们实例化两个熊猫的实现。接下来，我们创建了一个新的`ZooKeeper`实例。最后，我们调用了两次`care()`方法，传递了两个熊猫实现。

## 静态 (Statics)

没有实例可以进行操作。由于没有实例，`$this` 将解析为无内容。任何尝试使用它的行为都会导致 PHP 致命错误（fatal error）。

这意味着我们无法在类的静态方法中调用其他非静态方法，因为我们必须使用 `$this->otherMethod()` 来实现这一点。

这是否意味着我们的静态方法可以调用其他方法呢？嗯，并不完全。我们的静态方法可以调用其他的静态方法。这里有一个例子。

## 示例 10：链式调用静态方法

```php
class RedPanda {

    public static function eat() {

        return self::eatLeaves();

    }

    private static function eatLeaves() {

        return 'The Panda munches on some tasty leaves.';

    }

}
```

好了，让我们过一遍。我们有一个名为 `eat()` 的公共静态方法，它调用了 `eatLeaves()` 方法并返回结果。注意，`eatLeaves()` 方法是私有的（private），不能直接在类上调用。它只能在类的另一个方法内部被调用。

在上面的示例中，我们使用了 `self` 关键字。它用于指代自身或当前类。因此 `self::eatLeaves()` 意味着：请对该类的 `eatLeaves()` 方法进行静态调用。

当我们运行 `RedPanda::eat()` 时，我们得到了：

```php
<?php

class RedPanda

{

    protected $name;

    public function __construct($name = null)

    public static function make()

    {

        return new self('Hamish');

    }

    public function getName()

}
```

我们还有一个 `make()` 公共静态方法，它通过返回 `new self()` 来创建当前类的新实例并将其返回。它甚至将 `'Hamish'` 作为名称传递，因此我们可以使用 `RedPanda::make()` 快速创建一个新的 Hamish 熊猫实例。

## 晚期静态绑定 (Late Static Binding)

晚期静态绑定是 PHP 5.3 版本引入的一个特性。它的名字非常令人困惑，所以让我们用代码来演示。首先，我们需要两个类，并涉及一点继承。

### 示例 13：带有继承的静态方法

```php
<?php

class Panda

{

    public static function whoAmI()

{

        return self::getType();

    }

    public static function getType()

{

        return 'I am a Giant panda!';

    }

}

class RedPanda extends Panda

{

    public static function getType()

{

        return 'I am a Red panda!';

    }

}
```

这里有两个类。`Panda` 是我们的基类，代表大熊猫。`RedPanda` 继承自 `Panda`，代表红熊猫……显而易见。基类有一个名为 `getType()` 的静态方法，它告诉你是大熊猫。这个方法在 `RedPanda` 类中被重写（overridden），让你知道它是一只红熊猫。

我们可以在两个类上使用静态方法 `whoAmI()` 来找出我们拥有什么种类型的熊猫。我们现在调用它……

### 示例 14：我是谁？

```php
<?php

echo Panda::whoAmI() . PHP_EOL;

echo RedPanda::whoAmI();
```

运行这段代码后，我们得到了以下输出。

### 示例 15：输出

```
1 I am a Giant panda!

2 I am a Giant panda!
```

等等，为什么它们都是大熊猫？！我们在 `RedPanda` 类中重写了 `getType()` 方法，所以 PHP 不应该尊重继承关系吗？实际上，`self` 关键字只会引用基类。如果我们想使用晚期静态绑定，我们需要将 `self` 关键字替换为 `static`。让我们来看看这种转换。

## 示例 16：晚期静态绑定

```php
<?php

{

    public static function whoAmI()

    {

        return static::getType();

    }

    public static function getType()

    {

        return 'I am a Giant panda';

    }

}

class RedPanda extends Panda

{

    public static function getType()

    {

        return 'I am a Red panda';

    }

}
```

你会注意到，我们所做的只是将 `self` 替换为 `static`。现在尝试执行一次代码。

## 24. 特性 (Traits)

### 实现

在 PHP 5.4 中，语言引入了一种名为“trait”（特性）的新结构。通过使用 trait，PHP 类可以从多个源继承方法和属性。这是对单继承问题的直接解决方案。

让我们来看一个 trait 吧，好吗？

**示例 01：我的第一个 trait。**

如你所见的，一个 trait 看起来和类非常相似。相反，它是使用 `trait` 关键字声明的。以 `Trait` 后缀命名 trait 的惯例非常流行，所以这可能是你应该考虑采用的。

与类不同，重要的是需要记住的一点是，你不能在 trait 中添加 `extends` 或 `implements`。你无法实例化一个 trait。它们的唯一目的是支持我们的类，而不是取代它们。

```php
// app/routes.php

$eddard = new Eddard();
```

通过在实例化示例中添加命名空间指令，我们将 PHP 脚本的执行移动到了`Stark`命名空间中。由于我们和放入`Eddard`的在同一个命名空间内，这次我们收到了带命名空间的`Eddard`类。你看到这一切是如何相对的了？

既然我们更改了命名空间，就产生了一个小问题。你能猜到是什么吗？我们如何实例化原始的`Eddard`类？就是那个不在命名空间里的类。

幸运的是，PHP 有一个技巧可以引用位于全局命名空间中的类，我们只需要在它们前面加上反斜杠（`\`）即可。

## 示例 08：创建一个全局 Eddard 实例

```php
<?php

// app/routes.php

$eddard = new \Eddard();
```

有了开头的反斜杠（`\`），PHP 就知道我们引用的是全局命名空间中的`Eddard`，并实例化了它。

发挥一下你的想象力，就像 Barney 向你展示的那样。假设我们有另一个带命名空间的类叫做`Tully\Edmure`。我们想在`Stark`框架内部使用这个类。我们该怎么做呢？

## 示例 09：根命名空间前缀

```php
namespace Stark;

// app/routes.php

$edmure = new \Tully\Edmure();
```

再次，我们需要前缀反斜杠来回到全局命名空间，然后再实例化`Tully`命名空间中的类。
每次都通过完整层次结构来引用其他命名空间中的类可能会很累。幸运的是，我们可以使用一个非常棒的小快捷方法。让我们看看它的效果。

## 示例 10：创建一个 Tully\Edmure 实例

```php
<?php

namespace Stark;

use Tully\Edmure;

// app/routes.php

$edmure = new Edmure();
```

使用`use`语句，我们可以从另一个命名空间将一个类引入到当前命名空间。这将允许我们仅通过名称来实例化它。
让我给你们展示另一个酷技巧。我们可以为导入的类起一些小昵称，就像我们以前在 PHP 游乐场做的那样。我给你们展示。

## 示例 11：命名空间别名

```php
<?php

namespace Stark;

use Tully\Brynden as Blackfish;

// app/routes.php

$Brynden = new Blackfish();
```

通过使用`as`关键字，我们为`Tully\Brynden`类取了`Blackfish`昵号。这将允许我们在当前命名空间中使用新的昵号来识别它。很酷的招吧？如果你需要在同一个命名空间中使用两个命名相似的类，这也非常非常有用。例如：
