
# Chapter 3 Blockchain Technology Explained

Ask 100 people, and I guarantee that most of them have heard of Bitcoin, but few have heard of blockchain. And most of those who have heard of blockchain believe it only has one use – to run Bitcoin. That couldn’t be further from the truth. Yes, Bitcoin is the most famous use of the blockchain, but the technology can do so much more. In fact, it is set to disrupt just about every industry in the world in the next few decades.

## What Is Blockchain?

The simple answer is that a blockchain is a digital method of storing data. All the data is stored in blocks which are then chained together, ensuring the data is immutable, i.e., it cannot be changed. All data entered onto the blockchain is publicly available all the time, and anyone can see it whenever they want, in the exact way it was entered onto the blockchain. That makes it a revolutionary technology because it means records can be kept and tracked for just about anything, including identities, property rights, medical records, and so on, without the risk of those records being tampered with. If I were to go and purchase a house, photograph the property rights and add that photo to a blockchain, I would always have proof that I owned those property rights at some point in time. That information cannot be changed once it goes on the blockchain.

That all sounds great, but how does this blockchain work? It works like this:

### Step One – The Transaction Data

Let’s make this easy and use the Bitcoin blockchain since it was the first one created and the oldest one in use right now. Each block on this blockchain has about a megabyte of data in it. Right now, the Bitcoin blockchain stores approximately 525,000 MB of data, which equates to 525,000 blocks. This data exists in the form of Bitcoin transactional data and is a massive record of every Bitcoin transaction that has ever taken place, right back to the very first one. For the purposes of the rest of this chapter, we will assume that all blockchains store transaction data, although many store other digital assets — however, regardless of what is stored, the principles on how the blockchain works remain the same.

Each block describes up to a megabyte of transactions, and now they need to be chained together. This process is called hashing and will be explained in the next step.

Let's assume there are two transactions in the first block, and both total 1 MB (on the real blockchain, 1 MB of data would be many more transactions.) This block is given a unique signature referencing the string of data in it. Let's say `X32` is the signature – it would look like this:

Now, if one digit in this block were changed, a new signature would be generated, and therein lies the primary reason why transactions cannot be changed. Block 2 contains the signature from block 1, thus linking them and basing block 2 partly on block 1s signature. This goes on throughout the entire chain, with each block linked to the previous one through the signature.

Now, let's say block 1s data is changed. Instead of Daniel sending Gary 100 BTC, the data is changed to read 500 BTC. That means block 1 now contains different data and needs a new signature – we'll call it `W10`. The problem now is that block 2 contains the wrong signature for block 1 – it has `X32`, whereas the new signature is `W10`. As such, the first two blocks are now unchained, which informs the blockchain network that data has been changed. The blockchain is designed to be immutable, so the network doesn't verify the change, rejects it, and goes back to the previous blockchain record, which was chained to block 2. That is why it is so difficult to alter information in the blocks. The only way the change could go ahead undetected is block 1's new signature to replace the one currently in block 2.

What happens if block 2s data changes? It would need a new signature, too – we'll call it `PP4`, whereas it was `9BZ`. The result is that block 2 is no longer chained to block 3 and so on throughout the blockchain. Anyone can see every block on a blockchain, so for a change to stay undetected, every block must be correctly linked together. When a block is altered, every single block that follows it must have a new signature, right through to the end of the blockchain. This is virtually impossible to do but understanding why requires knowing how these signatures get created.

### Step Three – How to Create the Hash (Digital Signature)

Let's look at a new block 1, which has just one transaction in it – Tony sends Donald 100 BTC. The block now needs a signature, created using a cryptographic hash function, a complex formula that turns any input string into a 64-digit output string – completely unique. Try it for yourself using <https://passwordsgenerator.net/sha256-hash-generator/>.

If we input the word "Unicorns" into the hash generator, we get the following output:
`C3BFAD747914BB49344B9477A561CD3E0162CACB3E31B55EBE23C0F14DA7A504`

If we change just one character in that input, even swapping a capital letter for a lowercase, adding a period or a space, you get a totally different output. In this case, we'll change the capital letter at the start of the word to a lowercase letter, and we get this output:
`B660C5090EC2685B8BC11100BA183C0243497D95F91F78AAD987686EFB5F06B5`

Change it back to a capital letter, and get the original output. When you use a cryptographic hash function, it will always provide the same output when the same input is used, but we get a new output when the input is changed. The Bitcoin blockchain uses this hash function, with the block data being the input data and the signature relating to the block being the output.

So, back to our block again – Tony sends Donald 100 BTC.

The data string would look something like this:
```

Donald +100
```

Insert this string into the hash function and the signature is:
`6CC40EDA53664491E8123EFC867A5FC17A8AD946FD190F23E08E56F572FE05E3`

Now that signature gets added to the second block. Now we'll say that Donald sends Simon 100 BTC. Block 2 would look like this:

And when this is input into the hashing function, we get this digital signature for block 2:
`7763361E1940E7FB3C357976D236370E148AD70DF800D9F68DF9BBD0F4078EB9`

The question is, how do these digital signatures prevent a person from inputting a new signature for every block when they alter one? The simple answer is that the blockchain has specific requirements, which are only met via these signatures. This is known as mining and will be explained in the next step.

### Step Four - Who Signs Blocks and When Do Signatures Qualify?

I'll answer the second part of that question first - not every signature will qualify. Blocks can only be accepted onto the blockchain if the digital signature starts with something specific, i.e., a specific number of consecutive zeros, for example, 10. However, each data string is bound to a single unique hash, but what if that hash doesn't have the 10 zeros at the start of it? The only way to ensure that a signature's block matches the requirements the block's string data must be repeatedly changed until the signature starts with the 10 zeros. That said, the transaction data has to stay as it is, as does the metadata (the timestamp, block data, and so on). In that case, a tiny piece of specific data is placed into each block. This data only has one purpose - to be repeatedly changed to find an acceptable signature, and it is called a nonce (number used once). This block nonce is a random string containing only numbers.

So, to summarize, block 1 has three things:

- The transaction data
- The previous block's signature
- A nonce

The process by which the nonce is repeatedly changed and the block's data is hashed to find an acceptable signature is known as mining - this is what blockchain miners do. Miners use computational power in the form of electricity when they repeatedly change the nonce and hash it to get that signature. The higher the amount of computational power, the faster the block compositions (nonce) can be hashed, and the faster the acceptable signature is found in a process that is nothing more than trial and error. Anyone who participates in the blockchain can do this process - all you need to do is download the appropriate mining software and start it. That way, you contribute to the network's computational power to solve the block's nonce.

Now, as mentioned earlier, a hash signature has a specific number of zeros at the start of it - that number is currently 19. It isn't easy to find a hash with that many zeros, and it can take some serious computation power and no small amount of time and luck. Sometimes, a miner will get lucky and quickly find the right signature. One example of that is a recent block on the Bitcoin blockchain. A small miner who only had a small amount of computational power found the right signature when the combined computational power of the rest of the network was 7 trillion times higher than his. To put that in perspective, there is a one in 292 million chance of winning the Powerball Lottery - 24,000 times easier than it was for that one miner to beat an entire network to the right answer. Anyway, the most important takeaway is that it is not easy to find an acceptable signature.

### Step Five - How Does All This Result in an Immutable Blockchain?

As mentioned earlier, when you change a block, it becomes unchained from the blocks that come after it. The network will only accept a changed block if it is chained to subsequent blocks. One change means all other subsequent blocks also need to get new signatures, and they must all meet the specified requirements. To ensure that every block after a changed one has a new signature would take a significant amount of time and computational power. In theory, it can be done, but, in practice, it is virtually impossible, and here's why.

Let's say we have a corrupt miner. He has changed a transaction block and now needs to get new signatures for each subsequent block so that the network accepts the block he changed. Here's the rub - while the corrupt miner is doing this, the network is already getting new signatures for subsequent blocks. That means our corrupt miner will also need to generate new signatures for those and any others added to the chain in the meantime. For his changed block to be accepted, he must ensure that every other block that comes after it remains linked, including every new block added in the meantime. Unless he has significantly more computational power than all the network put together, he cannot hope to catch them up. Right now, the Bitcoin blockchain has millions of miners, and it's safe to assume that one or two corrupt miners have nowhere near the combined computational power of the rest of the network. That means any changes they make will never be accepted, which ensures the blockchain's immutability.

However, as we mentioned earlier, there is an exception. It's called the 51% attack, and it has happened before. A 51% attack is also known as a double-spend attack. One or more miners attempt to make two purchases with their Bitcoins, i.e., they double-spend them. As an example, I purchase a car costing 15 Bitcoin. The car is delivered, and my Bitcoin goes from my wallet to the car seller's wallet - this may take a few days. If I were to carry out a 51% attack, I could potentially reverse the transaction, keeping my 15 Bitcoins and the car. That means I can spend those Bitcoins on something else. A full explanation is beyond the scope of this book, but suffice it to say, it is highly unlikely that it will ever happen again.

### Step Six - How the Blockchain Is Governed and How the Rules Are Determined

All blockchains follow a democratic governance model, and the transactions record is updated based on what the majority of the network agrees on. This is done automatically by the blockchain protocol by following the longest blockchain record, assuming the majority has agreed on this. That means most of the network's computational power is used to take the longest blockchain version and is also how changed blocks are rejected, simply because that block is now not chained to the longest blockchain. As we know, all the transactions and wallet balances on the Bitcoin blockchain are public, and anyone can see any wallet or any transaction that ever happened. However, while we can see anyone's wallet, we cannot know the wallet owners. Their privacy remains secure.

## What about Other Cryptocurrencies?

All other cryptocurrencies are based on Bitcoin and are merely a form of the first digital currency that has been altered. Most have their own blockchain protocols, which may not share the same rules as the Bitcoin blockchain. Bitcoin was designed as a currency, meaning it has only one purpose - to function as money. Monero is another cryptocurrency that shares that function, but there are additional rules on the blockchain protocol that ensure Monero is far more private and transactions cannot be easily traced. However, any cryptocurrency can have any value, dependent entirely on the crypt issuer. Some are called tokens that allow their owners to do something - for example, getting a gaming license, accessing a social media site, accessing water, electricity, etc. No matter what it is, every token transaction is recorded on a blockchain, and a cryptocurrency exchange can be used to exchange them online. In short, they are the internet's money.

One example of an industry that cryptocurrency could disrupt is the stock market. In time, shares and other company property rights will likely be stored on a blockchain as tokens. However, the blockchain is not limited to this. They can also be used to store medical data, history records, identities, tax records, and more. That is why blockchain technology is revolutionary and will have a huge impact on the world as we know it. The next chapter will look at how cryptocurrencies work.
