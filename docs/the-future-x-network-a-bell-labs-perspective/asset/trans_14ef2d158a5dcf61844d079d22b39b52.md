
# 云服务演进与延迟挑战

## 早期企业云服务

1999年秋季，`salesforce.com` 上线，一场革命开始。尽管互联网已进入消费者的日常生活（Netscape 成立于1994年，Amazon 和 eBay 成立于1995年），但通过浏览器向企业交付业务服务的概念尚属未知。随着 `salesforce.com` 的推出，企业不再需要购买和安装设备和软件来支持企业应用；所有内容都可以通过互联网从位于第三方拥有的数据中心中的服务器交付。因此，企业云服务的第一个时代诞生，互联网从杂项信息的存储库转变为可创建和交付具有全球覆盖和规模的高价值服务的平台。然而，创建能够支持全球分布的数千至数百万用户的基础云基础设施是一项非平凡的任务，需要大量前期支出和准备时间，这阻碍了新企业服务的扩展能力。

2006年，Amazon 通过推出 `AWS` 改变了游戏规则，将云计算基础设施带给大众。因此，企业家无需面对建设具有全球覆盖的大型基础设施这一艰巨任务，而是可以简单地将应用程序部署在 `AWS` 基础设施上并按需扩展。这极大地降低了应用提供商的进入门槛。`AWS` 以按需增长的方式提供了即时的全球覆盖和几乎无限的扩展能力。认识到强劲的增长市场，许多其他基础设施提供商随后加入竞争，这促成了可从中推出云服务的全球生态系统的形成。2015年，据估计 Amazon 为其 `AWS` 运营着150万台服务器，而 Microsoft 和 Google 各托管超过100万台服务器。

## 地理分布挑战

虽然云的全球访问至关重要，但云运营商认识到集中式地理冗余架构存在诸多缺陷。首先，延迟是体验质量的重要因素。即使对于不太敏感于延迟的应用，数百毫秒的延迟也会让终端用户感到沮丧，因为只要需要一定程度的实时交互或响应，这些延迟就是可感知的。其次，安全和信任法规通常要求关键应用和数据必须从国内数据中心提供，或至少来自企业或监管政府认为可信的国家。最后，从网络成本角度来看，从少数中心站点提供高容量应用在经济上可能不可行，因为终端用户与数据中心之间传输数据的成本可能会抵消终端用户在服务成本降低和灵活性提高方面的收益。

由于这些缺陷，主要云提供商继续扩大其地理覆盖范围，以提供本地化资源，高效、安全、经济地满足客户需求。今天，Amazon 在全球运营着11个 `AWS` 数据中心（Amazon 2015）。此外，Amazon 在53个地点运行边缘云数据中心，其中20个是在过去两年内新增的。Microsoft 声称在全球运营超过100个数据中心（Microsoft 2015）。因此，云开始变得分布式，但尚未真正本地化。

## 延迟

延迟是全球 `CDN` 提供商面临的主要问题。点播和时移视频已迅速成为终端用户消费视频的主要方式，因为视频已从2000年代初期流式传输到PC小窗口的低质量短片演变为2015年交付的1080p甚至4k全长专业内容流。Netflix 电影流媒体于2008年推出，到2011年拥有2200万流媒体订阅用户，占美国互联网峰值流量的32%以上。这种增长仍在继续，截至今日订阅用户超过6200万（美国以外2000万），占美国峰值流量的近35%（Sandvine 2014）。随着流媒体视频成为主要的娱乐方式，消费者将观看行为转向了高分辨率设备，这些设备需要高质量视频（1080p或更好）。在高度集中的交付架构中，实现和维持交付这些高质量流所需的吞吐量很困难，因为流在穿越网络时会遇到许多跳数和潜在的拥塞点。这是由众所周知的传输控制协议（`TCP`）带宽-延迟乘积直接导致的，该乘积为给定延迟和窗口大小下单个 `TCP` 流可实现的最大吞吐量提供了一个简单的经验法则：

`Maximum throughput (bits/second) = TCP window size (bits)/round-trip latency (seconds)`

对于100 ms的往返时间（`RTT`）和典型的 `TCP` 窗口大小64 kb，这导致最大 `TCP` 吞吐量略高于5 Mb/s。鉴于1080p流的典型带宽为6 Mb/s，4k流超过15 Mb/s，内容提供商在不采用各种 `TCP` 优化技术的情况下交付高质量内容面临挑战。将此延迟降低到20 ms可使最大 `TCP` 吞吐量增加到超过25 Mb/s。此外，从经济角度来看，从附近的缓存交付高带宽单播流比从区域数据中心源发出数百万流（流量必须通过互联网或专用传输网络承载）更有效。出于这些原因，全球内容和 `CDN` 提供商不断扩大其覆盖范围，通过与本地互联网服务提供商（`ISPs`）安排在本地接入点（`PoPs`）的公共和私有网络内部（或直接连接）放置缓存，将 `CDN` 尽可能靠近终端用户。

例如，如[图1](#11-9781315365756_chapter-chap5.xhtml#fig5_1)所示，全球 `CDN` 提供商 Akamai 在102个国家的1,300个公共和私有网络中运营超过170,000个缓存，使其能够为本地用户提供高质量流媒体服务。同样，另一家 `CDN` 提供商 Limelight 在全球运营近20,000个缓存。

近期，大型内容提供商开始直接与本地和区域网络运营商建立商业协议，将自己的 `CDN` 部署在本地网络中以提高性能并降低交付成本。2012年6月，Netflix 宣布了 Netflix Open Connect Network，通过该网络 Netflix 向网络运营商和服务提供商提供名为 Open Connect Appliances（`OCAS`）的 `CDN` 服务器，这些服务器放置在服务提供商网络内的位置（Netflix 2012）。Netflix 报告称在2014年部署了数千台 `OCAs`（Limer 2014）。Google 于2008年启动了类似的计划，名为 Google Global Cache，该计划向 `ISPs` 提供 Google 缓存以零成本放置在其网络中以提供 Google 内容（包括 YouTube）。Google 及其合作伙伴均未公开谈论该计划的规模，但行业专家估计部署从2010年的少数 `ISPs` 增加到2013年7月北美超过80%的 `ISPs`（MacMillan 2013）。
