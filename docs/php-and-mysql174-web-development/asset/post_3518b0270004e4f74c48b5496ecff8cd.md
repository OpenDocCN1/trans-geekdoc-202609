Word boundaries are places where word characters (defined in the previous section) and non-word characters are placed next to one another.

The start and end assertions are similar to the caret (^) and dollar ($) markers except that some configuration options change the behavior of ^ and $, \A, \z, and \Z are unaffected.

The first matching position assertion \G is similar to the start assertion but is used when beginning at an offset, which is possible with some of the regular expressions. For example, if you have an offset of 5, and the first thing you find at position 5 is a match, the \G assertion will be satisfied, but \A may not be, depending on what is found at position 1.

# Putting It Together for the Smart Form

There are at least two possible uses of regular expressions in the Smart Form application. The first use is to detect particular terms in the customer feedback. You can be slightly smarter about using these regular expressions. Using a string, you would perform three different searches if you wanted to match "shop", "customer service", or "retail". With a regular expression, you can match all three:

```
/shop[customer service]|retail/
```

The second use is to validate customer email addresses in the application by encoding the standardized format of an email address in a regular expression. The format includes alphanumeric or punctuation characters, followed by an @ symbol, followed by alphanumeric and hyphen characters, followed by a dot, followed by more alphanumeric and hyphen characters and possibly more dots, until the end of the string, which encodes as follows:

```
/^[a-zA-Z0-9\-]+\@[a-zA-Z0-9\-]+\.[a-zA-Z0-9\-]+$/
```

The subexpression \[a-zA-Z0-9\-]+ means "the string with at least one letter, number, underscore, hyphen, or dot, or some combination of those". Note that when a dot is at the beginning or end of a character class, it loses its wildcard meaning and becomes a literal dot.

The @ symbol matches a literal @.

The subexpression [a-zA-Z0-9\-]+ matches the first part of the hostname including alphanumeric characters and hyphens. Note that you slash out the hyphen because it's a special character inside square brackets.

The \. matches a literal dot (.). We are using a dot outside character classes, we need to escape it to match only a literal dot.

The subexpression [a-zA-Z0-9\-\.]+ matches the rest of a domain name, including letters, numbers, hyphens, and more dots if required, up until the end of the string.

A bit of analysis shows that you can easily produce invalid email addresses that will still match this regular expression. It is almost impossible to catch them all, but this will improve the situation a little. You can refine this expression in many ways. You care when making things more restrictive, though, because valid top-level domains (TLDs). Be a validation function that rejects 1% of valid data is far more annoying than one that allows through 10% of invalid data.

# Finding Substrings with Regular Expressions

Finding substrings is the main application of the regular expressions you just developed.

There are a number of PCRE regular expression functions in PHP. The simplest, preg_match(), is the one we will use in this example. It has the following:

```
int preg_match(string pattern, string subject, array matches, int flags=0, int offset=0)
```

This function searches the subject string, looking for the regular expression in pattern. If a match is found, the full match will be stored in $matches[0], and each of the subsequent array elements will store a match for each matched subprocess.

The only possible value to flag is the constant PREG_OFFSET_CAPTURE. If this is set, the matches array will take a different format. Each element in the array will consist of an array of matched subprocesses, and the offset within the subject string where they were found.

The offset parameter is used to start searching the subject string from the specified offset.

The preg_match() function returns 1 if a match was found, 0 if a match was not found, and FALSE if an error occurred. This means you need to use identity (==) to test what is returned, to avoid confusion between 0 and FALSE.

You can adapt the Smart Form to use regular expressions by adding the following code to the order process:

```php
if (preg_match('/^[a-zA-Z0-9\-\.]+\@[a-zA-Z0-9\-\.]+$/', 
	$email) === 0) {
	echo "That is not a valid email address.</p>";
	echo "Please return to the previous page and try again.</p>";
	exit;
}
$address = 'feedback@example.com'; // the default value
if (preg_match('/shop|customer_service|retail/', $callback)) {
	$address = 'retail@example.com';
} else if (preg_match('/deliver|fulfill/', $feedback)) {
  $toaddress = 'fulfillment@example.com';
} else if (preg_match('/bill|account/', $feedback)) {
  $toaddress = 'accounts@example.com';
}
if (preg_match('/bigcustomer\.com/', $email)) {

}
```

# Replacing Substrings with Regular Expressions

You can also use regular expressions to find and replace substrings in the same way you used str_replace(), using the preg_replace(). This function has the following:
preg_replace(string pattern, string replacement, string subject, int limit=-1, &$count)

This function searches for the regular expression *pattern* in the *subject* and replaces it with the *replacement*.

The *limit* parameter specifies the maximum number of replacements to make. The default is -1, meaning no limit.

The *count* parameter, if supplied, will be filled with the total number of replacements made.

# Splitting Strings with Regular Expressions

Another useful regular expression function is preg_split(), which has the following prototype:
array preg_split(string pattern, string subject, int limit=-1, int flags=0)

This function splits the *subject* into substrings based on the regular expression *pattern* and returns the substrings in an array. The *limit* parameter limits the number of items that can go into the array. (The default value, -1, means no limit).

The *flags* parameter accepts the following constants, which can be combined via OR (|):

- PREG_SPLIT_NO_EMPTY means that only non-empty pieces are returned.
- PREG_SPLIT_DELIM_CAPTURE means that only the delimiters are returned as pieces.
- PREG_SPLIT_OFFSET_CAPTURE means that the location of each piece in the original string will be returned in the same way the preg_match() function does it.

This function can be useful for splitting email addresses, domain names, or dates. For example,

```php
$address = 'username@example.com';
$arr = preg_split('/\.|@|', $address);
while (list($key, $value) = each($arr)) {
    echo '<br />' . $value;
}
```

This example splits the email address into its three components and prints each on a separate line:

```
username
example
com
```

> Note
In general, the regular expression runs less efficiently than the string functions with similar functionality. If your task is simple enough to use a string expression, do so. This may not be true for tasks that can be performed with a single regular expression but multiple string functions.
