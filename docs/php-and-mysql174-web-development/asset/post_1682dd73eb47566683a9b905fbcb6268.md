Let's examine what you do differently in this script.

$db = new PDO($dsn, $user, $pass);

This function accepts a connection string, also called a DSN or data source name, that contains all the parameters to connect to the database. You can see this if you look at the format of the connection string:

```
$dsn = "mysql:host=$host;dbname=$db_name";
```

You will note that the database connection is contained in a try:catch block. If a problem occurs, PDO will throw an exception. Near the bottom of the script you will see the catch block for errors:

```php
catch (PDOException $e) {
    echo "Error: " . $e->getMessage();
    exit;
}
```

The type of exception thrown is a PDOException, and as you can see from the code it includes a message about the type of error that occurred.

Assuming everything has gone well, you set up a query and execute it as follows:

```php
$query = "SELECT ID, Author, Title, Price
FROM BOOKS WHERE $searchtype = :searchterm";
$stmt = $db->prepare($query);
$stmt->bindParam(':searchterm', $searchterm);
$stmt->execute();
```

This is similar to how we set up and executed a prepared statement using the mysqli extension. Here is where we use a named parameter for replacement. (You can use these with mysqli, and can use query-style replacement with PDO).

You can check the number of books returned:

```php
echo "<p>Number of books found: " . $stmt->rowCount() . "</p>";
```

Note that in PDO this is a method rather than an attribute, and as such requires the parentheses().

You retrieve each row as follows:

```php
$result = $stmt->fetch(PDO::FETCH_OBJ)
```

The generic method fetch() can fetch a row in many formats; the parameter PDO::FETCH_OBJ tells you that the row is returned as an anonymous object.

After outputting the returned rows, you finish by freeing the database resource to close the connection:

```php
$db = NULL;
```

As you can see, this PDO example is similar to the first script.

The advantages of using PDO are that you need to remember only one set of database functions and that the code will require minimal changes if you decide to change the database software.

# Understanding the Privilege System in Detail

Chapter 9, “Creating Your Web Database,” described the process of setting up users and granting them. You saw how to do this with the GRANT command. If you're going to administer a MySQL database, understanding exactly what GRANT does and how it works is useful.

When you issue a GRANT statement, it affects tables in the special database called mysql. Privilege information is stored in the mysql database. You can see the tables in mysql by typing:

```sql
SHOW TABLES;
```

Each of these tables vary in their specific function but also serve the general function, to determine what users are and not allowed to do. Each of them contains several types of fields. There are scope fields, which identify the user, host, and part of a database that the privilege refers to; and privilege fields, which identify which actions can be performed by that user. There are also security fields, which contain security-related information, and resource control columns, which constrain the number of resources that may be consumed.

The user table contains details of global user privileges. It determines whether a user is allowed to connect to the MySQL server at all and whether she has global-level privileges—that is, privileges that apply to every database in the system.
