Runtime errors are harder to eliminate syntax errors because the parser cannot signal the error the first time the code is executed. Runtime errors occur in response to a combination of events, they can be hard to detect and solve. The parser cannot automatically tell you that a runtime line will generate an error. Your testing needs to provide one of the situations that create the error.

Handling runtime errors requires a certain amount of foresight—to check for different types of failure that might occur and then take appropriate action. Simulating each class of runtime error that might also takes careful testing.

We do not mean that you need to simulate every different error that might occur. MySQL, for example, can provide hundreds of error numbers and messages. Instead, you should simulate an error in each function call that is likely to result in an error and an error of each type that is handled by a different block of code.

# Logic Errors

Logic errors can be the hardest type of error to find and eliminate. This type of error occurs when perfectly valid code does exactly what it is instructed to do, but was not what the writer intended.

# Chapter 26 Debugging and Logging

Logic errors can be caused by a simple typing error, such as

```php
for ($i = 0; $i < 10; $i++) {
  echo 'doing-something /';
}
```

This snippet of code is perfectly valid. It follows valid PHP syntax. It does not rely on external services, so it is unlikely to fail at runtime. Unless you looked at it carefully, it will probably not do what you think it will, or what the programmer intended it to do.

At a glance, it looks as if you iterate through the loop 10 times, echoing "doing something" each time. The addition of an extraneous semicolon at the end of the first line means that the loop has no effect on the following lines. The loop will iterate 10 times with result, and the echo statement will be executed once.

Because this snippet is perfectly valid, inefficient, to write code to achieve this result, the parser will not. Computers are very good at some things, but they do not have any sense or intelligence. A computer will do exactly as it is told. You need to make sure that you tell it is exactly what you want.

Logic errors are not caused by your sort of failure of code, but merely a failure of the programmer to write code that instructs the computer to do exactly what she wanted. As a result, errors cannot be detected automatically. You are not told that an error has occurred, and you are not given a line number where you can look for the problem. Logic errors are detected only by proper testing.

A logic error such as the previous example is easy to make, but easy to correct because the first time you run your code, you will see output other than what you expected. Most logic errors are more insidious.

// It iterates through that array, creating a

function dump_array($array) {

if(is_array($array)) {
$size = count($array);
$string = "";
if($size) {

    $count = 0;
    $string .= "{";
    // add each element's key and value to the string
    foreach($array as $var => $value) {

        $string .= $var . " = .$value;
        if($count++ < ($size-1)) {
            $string .= ", ";

    // if it is not an array, just return it
    return $array;
}
