Each call function makes to itself makes a new copy of the function code in the server's memory, with a different parameter. It is like pretending that you are actually calling a different function each time. This stops the instances of the function from getting confused.

With each call, the length of the string is tested. When you reach the end of the string (strlen(s)==0), the condition fails. The most recent instance of the function (reverse_r('o')) then goes on and performs the next line of code, which is to echo the first character of the string it passed; in this case, 'o'.

Next, this this instance of function returns to the instance that called it, namely reverse_r('lo'). This function prints the first character in its string—'l'—and returns control to the instance that called.

The process continues—printing and returning to the instance of the function above it in the call order—until control is returned to the main program.

There is something weird and elegant about recursive solutions. In most cases, you are better off using an iterative solution. The code for such solution is also shown in Listing 5.5. The main difference is that the recursive function makes copies of itself in memory and incurs the overhead of multiple function calls.

You might choose to use a recursive solution when the code is shorter and more elegant than the iterative version, but it does not happen often in this application domain.

Although recursion appears more elegant, programmers forget to supply a termination condition for the recursion. This means that the function will run until the server runs out of memory, or until the maximum execution time is exceeded, whichever comes first.
