
# Setting Up a Connection

The basic PHP library for connecting to MySQL is called mysqli. The i stands for improved, as there was an older library called mysql. When using the mysqli library in PHP, you can use either object-oriented or procedural syntax.

You use the following line in the script to connect to the MySQL server:

```php
$db = new mysqli('localhost', 'bookoram', 'bookoram123', 'books');
```

This instantiates the mysqli class and creates a connection to host localhost username bookoram, and password bookoram123. The connection is set up to use the database books.

Using object-oriented approach, you can now invoke methods on this object to access the database. If you prefer a procedural approach, mysqli allows for this. To connect in a procedural function, you use

```php
$db = mysqli_connect('localhost', 'bookoram', 'bookoram123', 'books');
```

This function returns a resource rather than an object. This resource represents the connection to the database, if you are using the procedural approach, you will need to pass the resource in all the other mysqli functions. This is similar to the way file-handling functions, such as fopen().

Most of the functions have an object-oriented interface and a procedural interface. Generally, the differences are the procedural version function names start with mysqli and require you to pass in the resource handle obtained from mysqli_connect(). Database connections are exceptions to this rule because they can be made by the mysqli object's constructor.

The result of your attempt at connection is worth checking because none of the rest of code will work without a database connection. You do this using the following code:

```php
if (mysqli_connect_errno()) {
  echo '<p>Error: Could not connect to database.<br>
  Please try again later.</p>';  exit;
}
```

(This is the code for the object-oriented and procedural versions). The mysqli_errno() function returns an error number on error, or on success.

Note that when you connect to the database, you begin the line of code with the error suppression, @. You can handle any errors gracefully. (This could also be with exceptions, which we have not used in this example).

Bear in mind that there is a limit to the number of MySQL connections that can exist at the same time. The MySQL parameter max_connections determines what this limit is. The purpose of this parameter and the related Apache parameter MaxClients is to let the server reject new connection requests instead of allowing machine resources to be completely used up at busy times or when software crashed.

You can alter both of these parameters from their default values by editing the configuration files. To set MaxClients in Apache, edit the http.conf file on your system. To set max_connections for MySQL, edit the file my.conf.

# Choosing a Database to Use

Remember that when you are using MySQL from a command-line interface, you need to tell it database you plan to use with a command such as

```sql
use books;
```

You also need to do this when connecting from the web. The database to use is specified as a parameter to the mysqli constructor or the mysqli_connect() function. If you want to change the default database, you can do so with the mysqli_select_db() function. It can be accessed as either

```php
$db->select_db(dbname)
```

or as

```php
mysqli_select_db(db_resource, db_name)
```

Here, you can see the similarity between the functions we described before: The procedural version begins with $mysqli_ and requires the extra database handle parameter.

# Querying the Database

To actually perform the query, you can use the mysqli_query() function. Before doing this, however, it's a good idea to set up the query you want to run:

```php
$query = "SELECT ISBN, Author, Title, Price FROM Books WHERE $searchtype = ?";
```

There are two things to notice here. You'll see that we have placed the $searchtype variable directly in the query. Where you might expect the $searchterm variable, you'll instead see a question mark character (?). What's going on?

In some places, you may see queries being created like this:

```php
$query = "SELECT ISBN, Author, Title, Price FROM Book WHERE $searchtype = '$searchterm";
```

# Do not do this

The reason for this is that while you allow user input data to avoid security problems, it's safer if you delegate that responsibility elsewhere.

The class of security issue is SQL injection, and we'll discuss it in plenty of detail in Part III of this book, "Web Application Security." The short version is that users may type something in a form field that ends up interpreted as SQL, which is something we dearly to avoid.

# Querying a Database from the Web

The reason we have a question today is that we are going to use a type of query known as a prepared statement. The question mark is a placeholder. The question mark tells MySQL,
whatever we replace the question mark with should be treated as data only, not code.
We'll cover how to do that in a moment.

You may be asking why we can't use the same approach with the $searchtype variable. This is because these placeholders can only be used for data, and not for column, table, or database names. To be safe, we use a whitelisting to specify valid values for the $searchtype variable. (You may also notice this quite a lot of work.)

Next, let's look at how we use the placeholder query into a real query.

> Tip
> Remember that the query you send to MySQL does not need a semicolon at the end of it, unlike a query.

# Using Prepared Statements

The mysqli library supports prepared statements. They are useful for protecting against SQL injection. The basic concept of a prepared statement is that you provide a template for the query and then bind the variables. For example:

```php
$query = "SELECT ISBN, Author, Title, Price FROM Books WHERE $searchtype = ?";
$stmt = $db->prepare($query);
$stmt->bind_param("s", $searchterm);
$stmt->execute();
$stmt->bind_result($isbn, $author, $title, $price);

while($stmt->fetch()) {
  echo "ISBN: $isbn, Author: $author, Title: $title, Price: $price\n";
}
```

# Retrieving the Query Results

A large variety of functions are available to break the results out in different ways. In this example, we counted the number of rows and retrieved the individual values. As well as binding parameters, you can bind results. For SELECT-type queries, you can use $stmt->bind_result() (or mysqli_stmt_bind_result()) to provide a list of variables that you like the result columns to be filled.
