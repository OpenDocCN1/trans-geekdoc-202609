
## Chapter 16 Implementing Authentication Methods with PHP

### Using Basic Authentication

Fortunately, authenticating users is a common task, so authentication facilities are built into HTTP: Scripts or web servers can request authentication from a web browser. The web browser is responsible for displaying a dialog box or device to obtain required information from the user.

Although the web server requests new authentication details for every user request, the web browser does not need to request the user's details for every page. The browser generally stores these details for as long as the browser window open and automatically resumes them to the web server without user interaction.

This feature of HTTP is called basic authentication. You can trigger basic authentication using PHP or using mechanisms built into your web server. We look first at the PHP method and the Apache method.

When you use basic authentication with SSL and digital certificates, all parts of a web transaction can be protected by strong security.

Basic authentication protects a named realm and requires users to provide a valid username and password. Realms are named so that more than one can be on the same server. Different files or directories on the same server can be part of different realms, all protected by a different set of names and passwords. Named realms also group multiple directories on the one host or virtual host as a realm protect all with one password.

### Using Basic Authentication with Apache’s .htaccess Files

You can achieve similar results to the script in Listing 16.2 without writing a PHP script.

The Apache web server contains a number of different authentication modules that can be used to decide the validity of data entered by a user. To use HTTP Basic authentication, you'll need mod_auth_basic, plus an authentication module corresponding to the password storage mechanism you plan to use. In this section, we'll look at how to store passwords in a file, and in the next section, we'll look at how to store them in a database.

To get the same output as the preceding script, you need to create two separate HTML files: one for the content and one for the rejection page. We skipped HTML elements in the previous examples but really should include `<html>` and `<body>` tags when generating HTML.

Listing 16.3, content.html, contains the content that authorized users see.
Listing 16.4, called rejection.html, contains the rejection page. Having a page to show in case of errors is optional, but it is a nice, professional touch if you put something useful on it. Given that this page will show when a user attempts to enter a protected area it rejection might include instructions on how to register for a password, or how to get a password reset and email if it has been forgotten.

Listing 16.5 htaccess—An .htaccess File Can Set Many Apache Configuration Settings, Activating Authentication

```apache
AuthFile /var/www/.htpass
AuthType Basic
AuthName "Authorization Needed"
AuthBasicProvider file
Require valid-user
ErrorDocument 401 /var/www/pmd53/chapter16/rejection.html
```

Listing 16.5 is an .htaccess file to turn on basic authentication in a directory. Many settings can be made in an .htaccess file, but the lines in this example all relate to authentication.

The line

```
AuthFile /var/www/.htpass
```

tells Apache where to find the file that contains authorized users' passwords. This file is named .htpass, but you can give it any name you prefer. It is not important what you call it, but it is important where you store it. It should not be stored within the web tree—somewhere that can download it via the web server. The sample .htpass file is shown in Listing 16.6.

Because a number of different authentication methods are supported, you need to specify which authentication method you are using. Here, you use Basic authentication, as specified by this directive:

```
AuthType Basic
```

Like the PHP example, to use HTTP Basic authentication, you need to name the realm as follows:

```
AuthName "Authorization Needed"
```

You may choose any realm name you prefer, but bear in mind that the name will be shown to your visitors. We named ours "Authorization Needed".

You need to specify what authentication provider is being used. In this case, we're using a file, and it specifies it as:

```
AuthBasicProvider file
```

You also need to specify who is allowed access. You could specify particular users, particular groups, or as we have, simply allow user access. The Line

```
Require valid-user
```

specifies that any valid user is to allowed access. The line

```
ErrorDocument 401 /var/www/pmd53/chapter16/rejection.html
```

Listing 16.6 htpassword File Stores Usernames and Each encrypted Password

```
user1:$S12DTFUq0ok6JPLkwoYqwTwd.
user2:$S12aAOuccSphrrV4gaah0w1
user3:$S12c2xbFrFs5dI4NGTcn0bRB
user4:$S12svjxonbPfyIn2vcpio1
```

Each line in the .htpass file contains a username, a colon, and that hashed password. The contents of your htpass file will vary. To create it, you use a small program called htpassword that comes in the Apache distribution.

The htpassword program supports a large number of options. Commonly, it's used as follows:

```
htpassword -bc passwordfile username
```

Using the -c switch tells htpassword to create the file. You must use this if exists for the first user you add. Be careful not to use it for other users, because if the file exists, htpassword will delete it and create a new one.

The -b switch tells the program to expect the password as a parameter rather than prompt for it. This feature is useful if you are calling htpassword nonactively as part of a process, but you should not use it if you are calling htpassword from the command line because passwords will be retained in history.

The following commands create the file shown in Listing 16.6:

```
htpassword -b /var/www/.htpassfile user1 pass
htpassword -b /var/www/.htpassfile user2 pass
htpassword -b /var/www/.htpassfile user3 pass
htpassword -b /var/www/.htpassfile user4 pass
```

Note that htpassword may not be in your path: if it is, you may find it in the /usr/local/apache/bin directory.
