
## Understanding Basic Session Functionality

Sessions in PHP are driven by a unique session ID, which is a cryptographically random number. This session ID is generated by PHP and stored on the client side for the lifetime of a session. It can be either stored on a user's computer in a cookie (the most common method) or passed along URLs.

The session ID acts as a key that allows you to register particular variables as so-called session variables. The contents of these variables are stored on the server. The session ID is the only information visible at the client side. If, at the time of a particular connecting to your site, the session ID is visible through either a cookie or the URL, you can access the variables stored on the server for that session. You have probably used websites that store a session ID in the URL. If your URL contains a string of random-looking data, it is likely to be some form of session control.

By default, the session variables are stored in flat files on the server. (You can change this behavior to a database if you are willing to write your own functions; you'll learn more about this topic in the section "Configuring Session Control.")

## What is a Cookie?

Cookies are a different solution to the problem of preserving state across a number of transactions while still having a clean URL. A cookie is a small piece of information that scripts can store on a client-side machine. You can set a cookie on a user's machine by sending an HTTP header containing in the following format:

```
Set-Cookie: name=value;expires=date;[path=path];[domain=domain.name];[secure; HttpOnly]
```

This creates a cookie named name with the value value. The other parameters are optional. If no expiry date is set, the cookie is effectively permanent unless the cookie is no longer relevant; unless the user manually delete it. Together, the path and domain can be used to specify the URL or URLs for which the cookie is relevant. The secure HttpOnly keyword means that the cookie will not be sent over a plain HTTP connection, and will only be accessible via HTTP and not by any client-side scripting languages as JavaScript.

When a browser connects to an URL, it first searches the cookies stored locally. If any of the stored cookies are relevant to the domain and path being connected to, the information stored in the cookie or cookies will be transmitted to the server.

## Setting Cookies from PHP

You can manually set cookies in PHP using the setcookie() function. It has the following prototype:

```
bool setcookie (string name, string value, int expire = 0, string path = "", string domain = "", int secure = false, [, httponly = false])
```

The parameters correspond exactly to the ones in the Set-Cookie header mentioned previously.

If you set a cookie in PHP using

```php
setcookie('mycookie', 'value');
```

then when the users visit the next page in your site (or reloads the current page), you will have access to the data stored in the cookie via $_COOKIE['mycookie'].

You can delete a cookie by calling setcookie() again with the same cookie name and an expiry time in the past. You can also set a cookie manually via the PHP header function and the syntax given previously. One tip is that cookie headers must be sent before any other headers; otherwise, they will not work; this is a requirement for standard use of cookies rather than a PHP limitation.

## Using Cookies with Sessions

Cookies have some associated problems: Some browsers do not accept cookies, and some users might have disabled cookies in their browsers. (This is one of the reasons PHP sessions use a dual cookie/URL method, which we will discuss.)

When you are using sessions, you do not have to manually set any cookies. The session functions take care of this task for you by creating the necessary cookies to match the session being created when the sessions are used.

You can use the function session_get_cookie_params() to see the cookie parameters. It returns an array containing the lifetime, path, domain, secure, and httponly.

```php
session_set_cookie_params($lifetime, $path, $domain, $secure, $httponly);
```

## Storing the Session

By default, PHP stores session data in files on the server. The session ID is used to link the client to the specific file. To start a session, you must call session_start():

```php
session_start();
```

Once the session is started, you can store data in the $_SESSION superglobal array:

```php
$_SESSION["username"] = "JohnDoe";
$_SESSION["role"] = "admin";
```

The session ID is the only information visible at the client side. If the session ID is visible through either a cookie or the URL, you can access the variables stored on the server for that session.

To delete a specific session variable, use unset():

```php
unset($_SESSION["username"]);
```

To destroy the entire session and remove all associated data, use session_destroy():

```php
session_destroy();
```
