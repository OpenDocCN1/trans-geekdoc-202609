$fp = fopen("document_root/../orders/orders.txt", 'rb');

The code is more robust but not perfect. If two scripts tried to acquire a lock at the same time? This would result in a race condition, in which the process competes for locks but it is uncertain which will succeed. Such a condition could cause more problems. # Problems with Using Flat Files

There are a number of problems in working with flat files:

+   When a file grows large, working with a flat file can be very slow.

+   Searching for a particular record or group of records in a flat file is difficult. If the records you are in, you can use some kind of binary search in conjunction with a fixed-width search to a key field. If you want to find patterns of information (for example, you want to find all the customers who live in Sometown), you would have to go through each record and check it individually.

+   Dealing with concurrent access can become problematic. You have seen how to lock files, but locking can cause the race condition we discussed earlier. It can also cause a bottleneck. With enough traffic on a site, large group of users may be waiting for the file to be unlocked before they can place their order. If the wait is too long, people will go elsewhere by.

+   All the file processing you have seen so deals with flat sequential processing; that is, you start from the beginning of the file and read to the end. Inserting records into or deleting records from the middle of the file (random access) is difficult because you end up reading the file into memory, making the changes, and writing the file out again. With a large data file, having no way to go through all these steps becomes a significant overhead.

+   Beyond the limits offered by file permissions, there is no way of enforcing different levels of access to data.
