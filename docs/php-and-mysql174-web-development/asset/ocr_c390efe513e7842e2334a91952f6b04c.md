# Understanding Basic Session Functionality

Sessions in PHP are driven by a unique session ID, which is a cryptographically random number. This session ID is generated by PHP and stored on the client side for the lifetime of a session. It can be either stored on a user's computer in a cookie (the most common method) or passed along URLs.

The session ID acts as a key that allows you to register particular variables as so-called session variables. The contents of these variables are stored on the server. The session ID is the only information visible at the client side. If, at the time of a particular connecting to your site, the session ID is visible through either a cookie or the URL, you can access the variables stored on the server for that session. You have probably used websites that store a session ID in the URL. If your URL contains a string of random-looking data, it is likely to be some form of session control.

By default, the session variables are stored in flat files on the server. (You can change this behavior to a database if you are willing to write your own functions; you'll learn more about this topic in the section "Configuring Session Control.")

# What is a Cookie?

Cookies are a different solution to the problem of preserving state across a number of transactions while still having a clean URL. A cookie is a small piece of information that scripts can store on a client-side machine. You can set a cookie on a user's machine by sending an HTTP header containing in the following format:

```
Set-Cookie: name=value;expires=date;[path=path];[domain=domain.name];[secure; HttpOnly
```

This creates a cookie named name with the value value. The other parameters are optional. If no expiry date is set, the cookie is effectively permanent unless which the cookie is no longer relevant; unless the user manually delete it. Together, the path and domain can be used to specify the URL or URLs for which the cookie is relevant. The secure HttpOnly keyword means that the cookie will not be sent over a plain HTTP connection, and will only be accessible via HTTP and not by any client-side scripting languages as JavaScript.

When a browser connects to an URL, it first searches the cookies stored locally. If any of the stored cookies are relevant to the domain and path being connected to, the information stored in the cookie or cookies will be transmitted to the server.

# Setting Cookies from PHP

You can manually set cookies in PHP using the setcookie() function. It has the following prototype:

```
bool setcookie (string name {, string value {, int expire = 0, string path
{}, string domain {, int secure = false }, [, httponly = false]]])
```
