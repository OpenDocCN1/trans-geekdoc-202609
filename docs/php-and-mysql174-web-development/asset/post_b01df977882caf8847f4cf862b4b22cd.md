# Joining More Two Tables

Joining more two tables is no more difficult than a two-table join. As a general rule, you need to join tables in pairs with join conditions. Think of it as following the relationships from the data table to that table.

For example, if you want to know which customers have ordered books on Java (perhaps you can send them information about a new Java book), you need to trace these relationships through quite a few tables.

Let's look at what that all does:

```
SELECT Customers.Name
FROM Customers, Orders, Order_Items, Books
WHERE Customers.CustomerID = Orders.CustomerID
AND Orders.OrderID = Order_Items.OrderID
AND Order_Items.ISBN = Books.ISBN
AND Books.Title LIKE '%Java%';
```

This rule of thumb can be useful for debugging queries that don't quite work. Check your join conditions and make sure you've followed the path away from what you know to what you want to know.

# Finding Rows That Don't Match

The main type of join that you will use in MySQL is the left join.

In the previous examples, notice that only the rows where a match was found between the tables were included. Sometimes you might want specifically the rows where there's no match—for example, customers who have never placed an order or books that have never been ordered.

One way to answer this type of question in MySQL is to use a left join. This type of join matches rows over a specific join condition between two tables. If no matching rows exists in the right table, a row will be added to the result that contains NULL values in the right columns.

Let's look at an example:

```
SELECT Customers.CustomerID, Customers.Name, Orders.OrderID
FROM Customers LEFT JOIN Orders
ON Customers.CustomerID = Orders.CustomerID;
```

This SQL query uses a left join to join Customers with Orders. Notice that the left join uses a slightly different syntax for the join condition: in this case, the join condition goes in a special clause of the statement.

The result of this query is

| CustomerID | Name | OrderID |
|------------|------|---------|
| 1 | Julie Smith | 2 |
| 2 | Alan Wong | 3 |
| 3 | Michelle Arthur | 1 |
| 3 | Michelle Arthur | 4 |

4 rows in set (0.00 sec)

If you want to see only the customers who haven't ordered anything, you can check for those NULLS in the primary key field of the right table (in this case, OrderID) because should be NULL in any rows:

```
SELECT Customers.CustomerID, Customers.Name
FROM Customers LEFT JOIN Orders
USING (CustomerID)
WHERE Orders.OrderID IS NULL;
```

In this case, the result is that no rows are returned, because all of our customers have placed an order.

Let's add a new customer:

```
INSERT INTO Customers VALUES
(NULL, 'George Napolitano', '177 Melbourne Road', 'Coburg');
```

If we repeat the left join query, the result is

|---|---|
| 4 | George Napolitano |

1 row in set (0.00 sec)

As you would expect, because George is a new customer, he is the only one who has not-not yet placed an order.

# Using Other Names for Tables: Aliases

Being able to refer to tables by names is often handy and essential. Names for tables are called aliases. You can create them at the start of a query. Consider the query you saw earlier, rewritten with aliases:

```
SELECT C.Name
FROM Customers AS C, Orders AS O, Order_Items AS OI, Books AS B
WHERE C.CustomerID = O.CustomerID
AND O.OrderID = OI.OrderID
AND OI.ISBN = B.ISBN
AND B.Title LIKE '%Java%';
```

You need to use aliases when you want to join a table to itself. This task sounds more difficult and esoteric than it is. It is useful, for example, if you want to find customers who live in the same city. Use different aliases:

```
SELECT C1.Name, C2.City
FROM Customers AS C1, Customers AS C2
WHERE C1.City = C2.City
AND C1.Name != C2.Name;
```

What you are basically doing is pretending the table Customers is two tables, C1 and C2, and performing a join on the City column. Notice that you also need the second condition, C1.Name != C2.Name; this is to avoid each customer coming up with a match to herself.

# Summary of Joins

The different types of joins we have described are summarized in Table 10.2. There are a few others, but these are the main ones you will use.

| Table 10.2 Join Types in MySQL |
| Name | Description |
|---|---|
| Cartesian product | All combinations of all the rows in all the tables in the join. Used by specifying a comma between table names, and not specifying a WHERE clause. |
| Full join | Same as preceding. |
| Cross join | Same as above. Can also be used by specifying the CROSS JOIN keywords between the names of the tables joined. |
| Inner join | Semantically equivalent to the comma. Can also specified using the INNER JOIN keywords. Without a WHERE clause, equivalent to a full join. Usually, you specify a WHERE condition as well to make this a true inner join. |
| Equi-join | Uses a conditional expression with = to match rows from the different tables in the join. In SQL, this is a join with a WHERE clause. |
| Left join | Tries to match rows across tables and fills in nonmatching rows with NULLS. Use in SQL with the LEFT JOIN keywords. Used for finding missing values. You can equivalently use RIGHT JOIN. |
