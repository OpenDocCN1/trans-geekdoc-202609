# 388 Chapter 17 Interacting with the File System and the Server

When these configuration options are set, the $SESSION superglobal will contain information about your file uploads. If you were to print all the variables and their values contained in $_SESSION, as part of your file upload, it might contain something like this:

```
[upload_progress_testing] => Array (
  [start_time] => 1424047703
  [content_length] => 43837
  [bytes_processed] => 43837
  [done] => 1
  [files] => Array (
    (
      [field_name] => the_file
      [name] => B912dX8IAAS-GT.png
      [tmp_name] => /tmp/phpPVj0Bbz
      [error] => 0
      [done] => 1
      [start_time] => 1424047703
      [bytes_processed] => 43413
    )
  )
)
```

This output shows a POST request was started at timestamp 1424047703 (that's Mon, 16 Feb 2015 00:48:23 GMT) with a content length of 43837. A total number of bytes was processed 43837 and the value of done is 1 (true) which means the $_SESSION variables were printed after the POST was completed. If the value of done was 0, that would have meant the POST was not yet completed.

An additional array of files exists, and in this case array of uploaded files contains only one set of keys and values representing only one file. In this case, the file in the field the_file, with an original name of B912dX8IAAS-GT.png, was uploaded to a temporary file location as /tmp/phpPVj0Bbz at timestamp 1424047703. The file was uploaded with no errors and a value of done is 1 (true) with a total number of bytes of 43413.

The values for bytes_processed and content_length come into play if you want to create and display a client-side progress bar to your user enabling the progress of the upload toward completion. Because session upload progress is based on a user's session, once that session is started with one script (the script), it can be accessed by another script, such as one that reads the value of bytes_processed and content_length within the current session for a particular uploaded file or files. If the script that reads data is being constantly polled asynchronously, with an AJAX request, then you can perform a simple mathematical function to return the percentage completed of the upload (number of bytes divided by the total content length, times 100).
