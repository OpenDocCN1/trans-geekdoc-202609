# Understanding the Privilege System in Detail 295

Most rows in this table correspond to a set of privileges for a User coming from a Host and logging in with the password. These are the *scope* fields for this table because they describe the scope of the *privilege* fields. The privilege fields end with _priv.

The privileges listed in this table (and the others to follow) correspond to the privileges granted using GRANT in Chapter 9. For example, Select_priv corresponds to the privilege to run a SELECT command.

If a user has a particular privilege, the value in that column will be Y. Conversely, if a user has not granted that privilege, the value will be N.

All the privileges listed in the user table are global; that is, apply to all databases in the system (including the mysql database). Administrators will therefore have all Y in there, but the majority of users should have all N. Normal users should have rights to appropriate databases, not all tables.

The other two sets of fields in this table are the security fields and the resource control fields.

The security fields are ssl_type, ssl_cipher, x5_issuer, x5_subject, plugin, authentication_string, and password_expired. The plugin field is NULL by default but may be set to contain an authentication plugin that will be used to authenticate a particular user account. The authentication_string may be used by plugins. The ssl_type and ssl_cipher are used if you have enabled SSL connections.

# ## The db Table

Most of your average users' privileges are stored in the db table.

The db table determines which users can access which databases from which hosts. The privileges listed in this table apply to which database is in a particular row.

The schema of this table is shown in Table 12.2.
