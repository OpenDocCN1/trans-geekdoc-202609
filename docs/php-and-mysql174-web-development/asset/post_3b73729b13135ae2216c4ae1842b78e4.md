
The first line in the function refers to a variable $var. When this line is executed the function creates a new variable called Var, with function scope, and echoes it. This creates the first line of actual output.

The next line within the function sets the contents of $var to 2. Because you are inside the function, this changes the value of the local $var, not the global one. The second line of output verifies that this change worked.

The function is now finished, the final line of the script is executed. This echo statement demonstrates that the global variable's value has not changed.

If you want a variable created within a function to be global, you can use the keyword global as follows:

```php
function fn() {
global $var;
$var = 'contents';
echo 'inside the function, $var = '.$var;
}
```

```php
fn();
echo 'outside the function, $var = '.$var;
```

In this example, the variable $var is explicitly defined as global, meaning that after the function is called, the variable will exist outside the function as well. The output from this script follows:

```
inside the function, $var = contents
outside the function, $var = contents
```

Note that the variable is in scope from the point in which the line global $var is executed. You could declare the function above or before you call it. (Note that function scope is quite different from variable scope.) The location of the function declaration is inconsequential; what is important is where you call the function and execute the code within it.

You can also use the global keyword at the top of a script when a variable is first used to declare that it is in throughout the script. This is a more common use of the global keyword.

You can see from the preceding examples that it is perfectly legal to rename a variable inside and outside a function without interference between the two. It is generally a bad idea, because without carefully reading the code and thinking about scope, people might assume that the variables are the same.

## Passing by Reference Versus Passing by Value

If you want to write a function increment() that allows you to increment a value, you might be tempted to write it as follows:

```php
function increment($value, $amount = 1) {
    $value = $value + $amount;
}
```

This code is of no use. The output from the following test code will be 10:

```php
$value = 10;
increment ($value);
echo $value;
```

The contents of $value have not changed by the scope rules. This code creates a variable called $value, which contains 10. It then calls the function increment(). The variable $value in the function is created when the function is called. One is added to it, so the value of $value is 11 inside the function, until the function ends; and then you return to the code that it called. In this code, the variable $value is a different variable, with global scope, and remains unchanged.

One way of overcoming this problem is to declare $value in the function as global, but this means that instead of creating a new, the variable you wanted to increment would need to be named $value.

The normal way that function parameters are carried through is an approach dubbed pass by value. When you pass a parameter, a new variable is created containing the value passed in. It is a copy of the original. You are free to modify this value in any way, but the value of the original variable outside the function remains unchanged. (This is actually a slight simplification of what PHP does internally.)

If you need to alter a value, you should pass by reference. Here, when a parameter is passed to a function, instead of creating a new variable, the function receives a reference to the original variable. This reference has a name, beginning with a dollar sign ($), and can be used in exactly the same way as another variable. The difference is that instead of having a value of its own, it merely refers to the reference. Any modifications to the reference will affect the origin.

You specify that a parameter is to use by reference by placing an ampersand (&) before the parameter name in the function's definition. No change is required in the function call.

You can modify the preceding increment() example to have one parameter passed by reference, and it will work correctly:

```php
function increment(&$value, $amount = 1) {
    $value = $value + $amount;
}
```

You have a working function and are free to name the variable inside and outside a function without interference between the two. It is generally a bad idea, because without carefully reading the code and thinking about scope, people might assume that the variables are the same. The output from this script follows:

```
11
```
