# Modification of Data

Although the loss of data could be damaging, modification can be worse. If somebody obtained access to your system and modified files? Although wholesale deletion will probably be noticed and can be remedied from your backup, how long will it take to notice modification?

Modifications to files could include changes to data or executable files. An attacker's motivation for altering data might be to defeat your site or obtain fraudulent benefits. Replacing executable files with sabotaged versions might give an attacker who has gained access on a single occasion a secret backdoor for future visits or a mechanism to gain higher privileges on the system.

You can protect data from modification as it travels over the network by computing a signature. This approach does not stop modifying the data, but if the recipient detects that the signature matches when the file arrives, she will know whether the file has been modified. If the data is encrypted to protect it from unauthorized viewing, the signature will make it very difficult to modify in route without detection.

Protecting files on your server requires modification that you use the file permissions your operating system provides and protect the system from unauthorized access. Using file permissions, users can be authorized to use the system but not be given free rein to modify system files and other users' files.

Detecting modification can be difficult. If, at some point, you realize that your system's security has been breached, how will you know however files have been modified? Some files, such as the data files that store your databases, are intended to change over time. Many others are intended to stay the same as the file you install, unless you deliberately upgrade them. Modification of both programs and data can be insidious, although programs can be restored if you suspect modification, you cannot know which version of your data was "clean".

File integrity assessment software, such as Trip, records information about important files in a known safe state, provides immediately after installation, and can be used at a later time to verify that files are unchanged.

# Loss or Destruction of Data

Every bit as having unauthorized users gain access to sensitive data is if we find that some portion of our data has been deleted or destroyed. If somebody manages to destroy tables in our database, our business could face irrecoverable consequences. If we are an online bank that displays bank account information, and somehow all the information for a particular account is lost, we are not a good bank. Much worse, if the entire table of users is deleted, we will find ourselves spending a large amount of reconstructing databases and finding out who owns what.
