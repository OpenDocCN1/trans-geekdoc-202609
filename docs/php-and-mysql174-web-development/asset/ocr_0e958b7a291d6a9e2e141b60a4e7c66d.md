# File System Considerations

PHP was designed with the capability to work with the local file system in mind. There are two concerns:

+   - Are any files you write to the disk going to be visible by others?

+   - If you expose this functionality to others, they are going to be able to access files they might not want them to access, such as /etc/passwd

You have to be careful not write files with wide open security permissions, or place them in a location where other users in a shared environment could get access to them.

Additionally, you should be extremely careful when let users enter the name of a file they would like to. If you had a directory in your document root with a bunch of files you granting access to, and they input the name of the file they wanted to view, you could get into trouble if they navigated upward toward the directory structure, to something like the following (using Windows filesystem references, for example):

```
../../php.ini
```

This would let them learn about our PHP installation and see whether any obvious weaknesses exist to exploit. Again, to fix this problem is easy: if you use input mark, make sure to filter it aggressively. For the preceding example, removing any instances of ..\ would certainly help prevent this problem, as any attempt at an absolute path such as c:\mysql\my.ini or /etc/my.cnf.
