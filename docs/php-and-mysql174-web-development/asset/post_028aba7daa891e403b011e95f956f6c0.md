# Setting Up Users and Privileges

A MySQL system can have many users. The root user should generally be used for administration purposes only, for security reasons. For each user who needs to use the system, you need to set up an account and password. They do not need to be the same as usernames and passwords outside MySQL (for example, Unix usernames and passwords). The same principle applies to root. Having different passwords for root and for MySQL is a good idea, especially when it comes to the root password.

Setting passwords for users isn't compulsory, but we strongly recommend that you set up passwords for all the users you create. For the purposes of setting up a web database, it's good to set up at least one user per web application. You might ask, “Why would I want to do this?” The answer lies in privileges.

# Introducing MySQL's Privilege System

One of the best features of MySQL is that it supports a sophisticated privilege system. A privilege is the right to perform a particular action on a particular object and associated with a particular user. The concept is similar to file permissions. When you create a user within MySQL, you grant a set of privileges to specify what she can and cannot do within the system.

# Principle of Least Privilege

The principle of least privilege can be used to improve the security of any computer system. It's a basic but important principle that is often overlooked. The principle is as follows:

- A user (or process) should have the lowest level of privilege required to perform his assigned task.

It applies in MySQL as it does elsewhere. For example, run queries from the Web, a user does not need all the privileges to which root has access. You should therefore create another user who has only the necessary privileges to access the database you created.

# User Setup: The CREATE USER and GRANT Commands

The GRANT and REVOKE commands enable you to give rights to and take away from MySQL users at these six levels of privilege:

- Global
- Database
- Table
- Column
- Stored Routine
- Proxy User

# Chapter 9 Creating Your Web Database

We will discuss the first four of these in Chapter 13, “Advanced MySQL Programming.” Proxy user privileges in the section on stored routines are not covered in this book as they are a much less common use case. Please refer to the MySQL manual for more information.

The USER command, surprisingly, creates a user. The general form of this command is as follows:

```
CREATE USER user_info [PASSWORD] password IDENTIFIED BY [auth_plugin] [AS auth_string]
```

The clauses in brackets are optional. There are a number of placeholders in this syntax, too.
The user_info placeholder contains a user_name, optionally followed by a hostname, separated by an @ symbol, in quotes, like the following: `laura@localhost`.

The user_name is the name you want to log in as MySQL. Remember that it does not have to be the same as a system name. The user_info in MySQL also contains a hostname. You can use this to differentiate between, say, laura (interpreted as laura@localhost) and laura@where.com. This capability is quite useful because users from different domains have the same name. It also increases security because you specify where users can connect, and from which tables or databases they access a particular location.

The password placeholder should be the password you want to log in with. The usual rules for selecting passwords apply. We will discuss security later, but a password should not be easily guessable. This means a password should not be a dictionary word or the same as the username. Ideally, it should contain a mixture of upper- and lowercase and nonalphabetic characters.

An alternative to passwords, since MySQL 5.5.7 you have been able to use an authentication plugin. To use this, you would specify the alternate IDENTIFIED WITH [auth_plugin] syntax. We will not cover authentication plugins in this book, but you can read about them in the MySQL manual if you need this. The GRANT command gives a user account if it does not yet exist, skipping straight to GRANT as a shortcut.

The general form of the GRANT command is

```
GRANT privileges [columns]
ON item
to user_info
IDENTIFIED BY password | IDENTIFIED WITH [auth_plugin] [AS auth_string]
[REQUIRE ssl_options]
[ GRANT OPTION | options ]
```

Some of these clauses are the same as in the CREATE USER statement, and work exactly the same way. Let’s look at the new clauses introduced here.

The privileges clause should be a comma-separated list of privileges. MySQL has a defined set of such privileges, which are described in the next section.

The columns placeholder is optional. You can use it to specify privileges on a column-by-column basis. You can use a single column name or a comma-separated list of column names.

The item placeholder is the database or table to which the new privileges apply. You can grant privileges on all the databases by specifying * as the item. This is called granting global privileges. You can also do this by specifying * if you are not using any particular database. More commonly, you can specify all tables in a database as dbname.*, on a single table as dbname.tablename, or on specific columns by specifying dbname.tablename and. These examples represent the three levels of privilege available: database, table, and column, respectively. If you are using a specific database when you issue this command, tableName on its own will be interpreted as a table in the current database.
