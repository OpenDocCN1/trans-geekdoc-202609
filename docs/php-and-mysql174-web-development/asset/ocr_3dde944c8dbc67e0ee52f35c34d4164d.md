Note that in this case, we didn't specify a hostname. You can add this here if you like. The value you add depends on your PHP code is running. If it's the same machine you can add 'localhost', if it's a different machine then you'll want to add the correct hostname or IP.

You can log out of the MySQL monitor by typing quit. You should log back as your web user to test that everything is working correctly. If the GRANT statement you ran executed, but you are denied access when trying to log in, this usually means you have not deleted the anonymous users as part of the installation process. Log back as root and refer Appendix A for instructions on how to delete the anonymous accounts. You should then be able to log in as the web user.

# Using the Right Database

If you've reached this stage, you should be logged in to a user-level MySQL account ready to test the sample code, either because you've just set it up or because your server administrator set it for you.

The first step you need to take when you log in is to specify which database you want to use. You can do this by typing

```
mysql> use dbname;
```

where dbname is the name of your database.

Alternatively, you can avoid the use by specifying the database when you log in, as follows:

```
mysql -D dbname -h hostname -u username -p
```

In this example, you can use the books database:

```
mysql> use books;
```

When you type this command, MySQL should give you a response such as

```
Database changed
```

If you don't select a database before starting work, MySQL will give you an error message as

```
ERROR 1046 (3D000): No Database Selected
```

# Creating Database Tables

The next step in setting up the database is to actually create the tables. You can do this with the SQL command CREATE TABLE. The general form of a CREATE TABLE statement is

```
CREATE TABLE tableName(columns)
```
