This output might look confusing at first, but it can be very useful. Let's look at the columns in this table by one.

The first column, id, gives the ID number of the SELECT statement in the query that it refers to.

The column select_type explains the type of query used. The set of values for this column can have shown in Table 12.8.

# Table 12.8 Possible Select Types As Shown in Output from EXPLAIN

| Type | Description |
|---|---|
| SIMPLE | Plain old SELECT, as in this example |
| PRIMARY | Outer (first) query where subqueries and unions are used |
| UNION | Second or later query in a union |
| DEPENDENT UNION | Second or later query in a union, dependent on the primary query |
| UNION RESULT | The result of a UNION |
| SUBQUERY | Inner searchQuery |
| DEPENDENT SUBQUERY | Inner searchQuery, dependent on the primary query (that is, a correlated subquery) |
| DERIVED | Subquery used in FROM clause |
| MATERIALIZED | Materialized searchQuery |
| UNCACHEABLE SUBQUERY | A query whose result cannot be cached and must be reevaluated for each row |
| UNCACHEABLE UNION | The second or later query in a UNION that belongs to an uncacheable subquery |

The column table lists the tables used to answer the query. Each row in the result gives more information about how that particular table is used in this query. In this case, you can see that the tables used are Orders, Order_Items, Customers, and Books. (You know this already by looking at the query.)
