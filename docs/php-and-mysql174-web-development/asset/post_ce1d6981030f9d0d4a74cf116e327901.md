
## 416 Chapter 18 Using Network and Protocol Functions

The $remotefile variable contains the path to the file you would like to download. In this case, you are downloading and mirroring a local copy of the Apache web server for Unix.

The $localfile variable contains the path to the location where you are going to store the downloaded file on your machine. No matter what directory you place your file into, be sure permissions are set up so that PHP can write a file into it. Regardless of your operating system, you will need to create this directory for the script to work, if the directory does not already exist. Additionally, if your operating system has strong permissions, you will need to make sure that they allow your script to write to. You should be able to change these variables for your purposes.

The basic steps you follow in this script are the same as if you wanted to manually transfer the file by FTP from a command-line interface:

- 1. Connect to the remote FTP server.
- 2. Log in (either as a user or anonymous).
- 3. Check whether the remote file has been updated.
- 4. If it has, download it.
- 5. Close the FTP connection.

Let's consider each of these steps in turn.

## Connecting to the Remote FTP Server

The first step is equivalent to typing

```php
ftp hostname
```

at a command prompt on either a Windows or Unix platform. You accomplish this step in PHP with the following code:

```php
$conn = ftp_connect($host);
if (!$conn)
{
    echo 'Error: Could not connect to '.$host;
    exit;
}
```

```php
echo 'Connected to '.$host.<br>';
```

The function call here is to ftp_connect(). This function takes a hostname as a parameter and returns a handle to a connection or false if a connection could not be established. The function can also take the port number on the host to connect to as an optional second parameter. We did not use this parameter here; if you don't specify a port number, it will default to port 21, which is the default for FTP.

## Logging In to the FTP Server

The next step is to log in as a particular user with a particular password. You can achieve this by using the `ftp_login()` function:

```php
$result = @ftp_login($conn, $user, $pass);
if (!$result)
{
    echo 'Error: Could not log in ''.$user.'.<br />';
    ftp_connect($conn);
    exit;
}
echo 'Logged in as '.$user.<br />';
```

The function takes three parameters: an FTP connection (obtained from `ftp_connect()`), a username, and a password. It returns `true` if the user can be logged in and `false` if she can't.

Notice that we use an @ symbol at the start of the line to suppress errors. We did this because, if the user cannot be logged in, a PHP warning appearing in the browser window. You can catch the error as we have done here by testing `$result` and supplying your own, more user-friendly error message.

Notice that if the login fails, you actually close the FTP connection by using `ftp_pasv()`. We discuss this function much later.

Before moving on working with the remote filesystem, note the use of the `ftp_pasv()` function, in the file:

In this case, we are ensuring that passive mode is true, which means that all data connections will be initiated by the client (script) rather than by the remote FTP server. If you do not turn on passive mode, you may find that your script will not pass the point of login.

## Checking File Updates Times

Given that this script is set to update a local copy of a file, checking whether the file needs updating is sensible because you don't want to have to download the file again, particularly a large one, if it is up to date. This way, you can avoid unnecessary network traffic. Let's look at the code that checks file update times.

File times are the reason that you use the FTP functions rather than a file function. The file functions can easily read, and in some cases, file networks over interfaces, such as `filetime()` do not work.

To begin deciding whether you need to download a file, you check that you have a local copy of the file using `file_exists()` function. If you don't, obviously need to download the file. If it exists, you get the last modified time of the file by using `filetime()` and store it in the `$localtime` variable. If it doesn't exist, you set the `$localtime` variable to 0 so that it will be "older" than any remote file modification time:

```php
echo 'Checking file time...<br />';
if (file_exists($localfile))
```

```php
$localtime = filetime($localfile);
echo 'Local file last updated ';
echo date('G:i j-M-Y', $localtime);
echo '<br />';
else
{
$localtime = 0;
}
```

For reference, you can get a refresh on the file_exists() and filetime() functions in Chapters 2 and 17, "Interacting with the File System and the Server".

After you have sorted out the local time, you need to get the modification time of the remote file. You can get this by using the $ftp_mdtm() function:

```php
$remotetime = ftp_mdtm($conn, $remotefile);
```

This function takes two parameters—the FTP connection handle and the path to the remote file—and returns the Unix timestamp of the file was last modified or -1 if there is an error of some kind. Not all FTP servers support this feature, so you might not get a result from the function. In this case, you can choose to artificially set the $remotetime variable by adding 1 to it. This way, you ensure that an attempt is made to download the file:

```php
if (!($remotetime >= 0)) 
{
// This doesn't mean the file's not there, server may not support mod time
echo 'Can't access remote file time.<br />';
$remotetime=$localtime; // make sure of an update
}
```

```php
else
{
echo 'Remote file last updated ';
echo date('G:i j-M-Y', $remotetime);
echo '<br />';
}
```

When you have both times, can you compare them to see whether you need to download the file:

```php
if (!($remotetime > $localtime)) 
{
echo 'Local copy is up to date.<br />';
exit;
}
```

## Downloading the File

At this stage, you try to download the file from the server...

```php
echo 'Getting file from server...<br>';
$fp = fopen($localfile, 'wb');
if (!$success = ftp_get($conn, $fp, $remotefile, FTP_BINARY)) {
    echo 'Error: ';
    echo 'Could not download file.';
    fclose($fp);
    ftp_close($conn);
    exit;
}
fclose($fp);
echo 'File downloaded successfully.';
```

You open a local file using fopen(), as you learned. After you have done this, you call the function ftp_get(), which attempts to download the file and store it in a local file. This function takes four parameters. The first three are straightforward: the FTP connection, the local file, and the path to the remote file. The fourth parameter is the FTP mode.

The two modes for an FTP transfer are ASCII and binary. The ASCII mode is used for transferring text files (that consists of ASCII characters), and the binary mode is used for everything else. Binary mode modifies a file unmodified, whereas ASCII mode for Unix translates carriage returns and line feeds into the appropriate characters for your system\n on Unix for Windows, and \r for Macintosh.

PHP's FTP library comes with two predefined constants, FTP_ASCII and FTP_BINARY, which represent these two modes. You need to decide which mode fits your file type and pass the corresponding constant to ftp_get() as the fourth parameter. In this case, transferring a zipped file, so use the FTP_BINARY mode.

The ftp_get() function returns true if everything goes well or false if an error is encountered. You store the result in $success and let the user know how it went.

After the download has been attempted, you close the local file using the fclose() function.

An alternative to ftp_get(), ftp_get(), which has the following prototype:

```php
int ftp_get(ftp_connection, string localfile_path, remotfile_path, int mode)
```

This function works in the same way as ftp_get() but does not require the local file to be open. You pass it the filename of the file you would like to write rather than a file handle.

Note that there is no equivalent to the FTP command mget, which can be used to download multiple files. You must instead make multiple calls to ftp_get() or ftp_get().
