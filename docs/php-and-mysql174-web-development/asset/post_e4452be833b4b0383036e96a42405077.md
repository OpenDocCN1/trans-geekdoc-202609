
## Checking Whether a File Is There: file_exists()

If you want to check a file without actually opening it, you can use file_exists(), as follows:

```php
if (file_exists("$document_root/../orders/orders.txt")) {
    echo 'There are orders waiting to be processed.';
} else {
    echo 'There are currently no orders.';
}
```

## Determining How Big a File Is: filesize()

You can check the size of a file by using the filesize() function:
`filesize("$document_root/../orders/orders.txt")`

It returns the size of a file in bytes and can be used in conjunction with read() to read a file (or some fraction of the file) at a time. You can even replace the original script with the following:
```php
$fp = fopen("$document_root/../orders/orders.txt", 'rb');
echo nl2br($fp, filesize("$document_root/../orders/orders.txt"));
close($fp);
```

The nl2br function converts the \n characters in the output to HTML lines like <br />.

## Deleting a File: unlink()

If you want to delete the file after the orders have been processed, you can do so by using unlink(). (There is no such deleted). For example,
`unlink("$document_root/../orders/orders.txt");`

This function returns false if the file could not be deleted. This situation typically occurs if the permissions on the file are insufficient or if the file does not exist.

## Navigating Inside a File: rewind(), fseek(), and ftell()

You can manipulate and decode the position of the file pointer inside a file by using rewind(), fseek().

The rewind() function resets the file pointer to the beginning of the file. The ftell() function reports how far into the file pointer is in bytes. For example, you can add the lines to the bottom of the original script (before the fclose() command):

```php
echo 'Final position of the file pointer is '.ftell($fp).';';
echo '<br />';
rewind($fp);
echo 'After rewind, the position is '.ftell($fp).';';
echo '<br />';
```

You can use the function fseek() to set the file pointer to some point within the file. Its prototype is

```c
int fseek( resource fp, int offset, int whence );
```

A call to fseek() sets the file pointer to a point starting from whence and moving offset into the file. The optional whence parameter defaults to the value SEEK_SET, which is effectively the start of the file. The other possible values are SEEK_CUR (the current location of the file pointer) and SEEK_END (the end of the file).

The rewind() function is equivalent to calling the fseek() function with an offset of zero. For example, you can use fseek() to find the middle record in a file or to perform a binary search. If reach the level of complexity in a data file where you need to do these kinds of things, your life will be much easier if you use a build-purpose database.

## Locking Files

Imagine a situation in which two customers are trying to order a product at the same time. (This situation is not uncommon, especially when your website starts to get any kind of traffic volume) If one customer calls fopen() and begins writing, and then the other customer calls fopen() and begins writing. What will be the final contents of the file? Will it be the first order followed by the second order, or vice versa? Will it be one order or the other?

## Chapter 2 Storing and Retrieving Data

Or will it be something less useful, as the two interleaved somehow? The answer depends on your operating system but is often impossible to know.

To avoid problems like this, you can use file locking. You use this feature in PHP by using the flock() function. This function should be called after a file has been opened before any data is read from or written to the file.

The prototype for flock() is

```php
bool flock(resource fp, int operation, int &wouldblock)
```

You need to pass a pointer to an open file representing the kind of lock you require. Returns true if the lock was successfully acquired and false if it was not. The optional third parameter can contain the value if acquiring the lock could cause the current process to block (that is, to wait).

The possible values for operation are shown in Table 2.2.

Table 2.2 flock() Operation Values
| Value of Operation | Meaning |
|---|---| |
| LOCK_SH | Reading lock. The file can be shared with other readers. |
| LOCK_EX | Writing lock. This operation is exclusive; the file cannot be shared. |
| LOCK_UN | The existing lock is released. |
| LOCK_NB | Blocking is prevented while you are trying to acquire a lock. (Not supported on Windows.) |

If you are going to use flock(), you need to add it to all the scripts that use the file; otherwise, it is worthless.

Note that flock() does not work with NFS or other networked file systems. It does not work with antique file systems that do not support locking, such as FAT. On some operating systems, it is implemented at the process level and does not work correctly if you are using a multithreaded server API.

To use it with example, you can alter processor.php as follows:

```php
$fp = fopen("$document_root/../orders/orders.txt", 'ab');
flock($fp, LOCK_EX);

if (!$fp) {
    echo "<p>Your order could not be processed at this time. Please try again later.</p></body></body></html>";
    exit;
}

fwrite($fp, $outputstring, strlen($outputstring));
```

You can do better by using a database.

## A Better Way: Databases

So far, all the examples we have looked at flat files. In Part II of this book, we look at how to use MySQL, a relational database management system (RDBMS), instead. You might ask, “Why would I bother?”

## Problems with Using Flat Files

There are a number of problems in working with flat files:

- When a file grows large, working with a flat file can be very slow.
- Searching for a particular record or group of records in a flat file is difficult. If the records you are in, you can use some kind of binary search in conjunction with a fixed-width search to a key field. If you want to find patterns of information (for example, you want to find all the customers who live in Sometown), you would have to go through each record and check it individually.
- Dealing with concurrent access can become problematic. You have seen how to lock files, but it can cause a bottleneck. With enough traffic on a site, users may be waiting for the file to be unlocked.
- All the file processing you have seen deals with sequential processing; that is, you start from the beginning of the file and read to the end. Inserting into or deleting records from the middle of the file is difficult because you end up reading the file into memory, making the changes, and writing the file again.
- Beyond the limits offered by file permissions, there is no way of enforcing different levels of access.

## How RDBMSs Solve These Problems

Relational database management systems address all these issues:

- RDBMSs can provide much faster access to data than flat files. And MySQL, the database system we use in this book, has some of the fastest benchmarks of RDBMS.
- RDBMSs can be easily queried to extract sets of data that fit criteria.
- RDBMSs have built-in mechanisms for dealing with concurrent access so that you, as a programmer, you can set up and use MySQL to not worry about it.
- RDBMSs provide random access to your data.
- RDBMSs have built-in privilege systems. MySQL has particular strengths in this area.

Probably the main reason for using an RDBMS is that all (or most) of the functionality you want in a data storage system has already been implemented. You could write your own library of PHP functions, but why reinvent the wheel?

In Part II of this book, "Using MySQL," we discuss how relational databases work generally, and specifically how you use MySQL to create database-backed websites.
