The call $stmt->execute(mysqli_stmt_execute()) in the procedural version actually runs the query. You can then access the number of affected rows and close the statement.

So how is this prepared statement? The clever thing is that you can change the value of the bound variables and re-execute the statement without having to re-prepare. This capability is useful for looping through bulk inserts.

# Retrieving the Query Results

A large variety of functions is available to break the results out in different ways.

In this example, we counted the number of rows returned and retrieved the individual values for each column in each row returned.

As well as binding parameters, you can bind results. For SELECT-type queries, you can use $stmt->bind_result() (or mysqli_stmt_bind_result()) to provide a list of variables that you would like the result columns to be filled. Each time you call $stmt->fetch() (or mysqli_stmt_fetch()), values from the next row are refilled into these variables. For example, in the result script you looked at earlier, you could use

```
$stmt->bind_result($isbn, $author, $title, $price);
```

to bind these four variables to the four columns that will be returned from the query.

After calling

```
$stmt->execute();
```

you can call

```
$stmt->fetch();
```

in the loop. Each time this is called, it fetches the next row into the four bound variables.

We'd like to get a count of the number of rows returned. To do this, we first tell PHP to retrieve and buffer all of the rows from the query:

```
$stmt->store_result();
```

When you use the object-oriented approach, the number of rows returned is stored in the num_rows property of the result object, and you can access it as follows:

```
echo "<p>Number of rows found: " . $stmt->num_rows . "</p>";
```

When you use a procedural approach, the function mysqli_num_rows() gives you the number of rows returned by the query. You should pass the result identifier, like this:

```
$num_results = mysqli_num_rows($result);
```
