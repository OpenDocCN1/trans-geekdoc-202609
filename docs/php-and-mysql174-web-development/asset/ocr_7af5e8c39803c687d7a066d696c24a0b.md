The way you lay out your curly braces is also an issue. The two most common schemes are:

# Scheme 1:

```
if (condition) {

```

# Scheme 2:

```
if (condition) {

}
```

Which one you use is up to you. The scheme you choose should, again, be used consistently throughout a project to avoid confusion. Throughout this book, we tend to use the second scheme.

# Breaking Up Code

Giant monolithic code is awful. Some people create one huge script that does everything in one switch statement. Now, we love switch and they have their place, but it is far better to break the code into functions and/or classes and put related items into include files wherever possible. You can, for example, put all your database-related functions in a file `db_functions.php`.

Reasons for breaking up your code into sensible chunks include the following:

+   * It makes your code easier to read and understand, but for yourself later on, and for anyone who might join your project.
* It makes your code more reusable and minimizes redundancy. For example, with the aforementioned `db_functions.php` file, you could reuse it in every script in which you need to connect to your database. If you need to change the way this works, you have to change it in one place.
* It facilitates teamwork. If the code is broken into components, you can assign responsibility for the individual components to team members. It also means you can avoid the situation in which one programmer is waiting for another to finish working on `GiantScript.php` so that she can go ahead with her own work.
