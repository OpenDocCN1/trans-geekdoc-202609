greatly reduces the overhead needed to maintain such files (which includes collaborating with
transl and other content writers).

We recommend using tools such as Poedit (https://poedit.net/) or POEditor (https://
poedit.com/) for producing and maintaining the files of localized content, but for now we
will simply show you PO file examples typed in plain text. You need one PO file for
e locale, called messages.po.

PO files with some identifying header information, then continue to include message
identifiers and message strings. An example PO file is shown in Listing 20.4, which sets up
two strings for use in the en_US locale.

# Listing 20.4 messages.po file for en_US locale

```
# required empty msgid & msgstr
msgid ""
msgstr ""

"Project-ID-Version: 0.1\n"
"POT-Creation-Date: 2016-04-05 14:00+0500\n"
"Last-Translator: Jane Doe <jane@doe.com>\n"
"Content-Type: text/plain;charset=UTF-8\n"
"Language: en_US\n"

# welcome message
msgid "WELCOME_TEXT"
msgstr "Welcome!\n"

# instruction to choose language
msgid "CHOOSE_LANGUAGE"
msgstr "Choose Language"
```

The format of the file begins with an empty message identifier (msgid) and message
string (msgstr), followed by some identifying information about the file and its creators: this
file is versioned 0.1, created on April 4, 2016, by Jane Doe, and is in the UTF-8 character
set for inside the en_US locale.

After this header information you find the messages and their translations. In this example,
there are two messages identified by their keys: WELCOME_TEXT and CHOOSE_LANGUAGE. These
message keys are similar to the constants used in the simple version of localization shown
erlier this chapter, but are named differently so not to confuse the two examples. After\each message key comes the message string to use in place of that. Comments are used
to introduce each set of message key and string, and you will notice one line of whitespace
between each pair.

Sounds simple, and but there is also a hidden complexity to creating and maintaining
these PO files: the long list of options that are available to use, such as those listed in the
specification at http://www.gnu.org/software/gettext/manual/gettext.html#PO-Files.
