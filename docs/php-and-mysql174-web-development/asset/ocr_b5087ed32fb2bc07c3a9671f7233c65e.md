You can specify PRIMARY KEY after a column name for single column primary keys.
PRIMARY KEY clause at the end of the Order_Items statement is an alternative form. We used
it here because the primary key for this table consists of the two columns together (This also
creates an index on the default columns together).

You can also specify FOREIGN KEY at the end of the table definition, along with the name of
t reference table and column. This constraint means that the specified column must have a
matching value in the reference table. You can specify different semantics for what to do if
t reference data is deleted. For example, ending this line with DELETE CASCADE would
"if the reference is deleted, delete corresponding rows too". In this case we have
chosen to go with the default behavior which is RESTRICT. This means that you are unable to
delete or update rows in the reference table without first making the appropriate changes
in table.

Note that the FOREIGN KEY specification will only have an effect if we are using a storage
engine that supports foreign keys, as the default InnoDB. In older versions of MySQL,
MySQLSAM was the default type, and it does not support foreign keys. We'll talk more about the
different storage engines in Chapter 13.

UNSIGNED after an integer type means that it can only have a zero or positive value.

# Understanding the Column Types

Let's create the first table as an example:

```
CREATE TABLE Customers
( CustomerID UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
Name CHAR(50) NOT NULL,
Address CHAR(100) not null,
City CHAR(30) not null
);
```

When creating a table, you need to make decisions about column types.

The table has four columns as specified in the schema. The first one, CustomerID,
is the primary key, which is specified directly. We decided this will be an integer (data type INT)\mand that these should be UNSIGNED, as we don't plan on having negative CustomerIDs.
We've also taken advantage of the AUTO_INCREMENT facility so that MySQL can manage them
for us; it's less thing to worry about.

The other columns are all going to hold string data. We chose the CHAR for them.
This type specifies fixed-width fields. The width is specified in the brackets, for example,
Name can have up to 50 characters.
