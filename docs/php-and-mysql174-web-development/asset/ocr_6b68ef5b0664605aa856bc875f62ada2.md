In older versions of PHP, it was typical to explicitly use the one-way hash functions. The oldest and least secure is the Unix Crypt algorithm, provided by the function crypt(). Then there's the Message Digest 5 (MD5) algorithm, implemented in the function md5(). More recently people have Secure Hashing Algorithm functions such as sha1() and sha256(), among others.

The problem with specifying a hash function is that time passes, hashing algorithms become insecure. How does this happen? Security researchers find a way to break the hash. This becomes easier as computing powers increase,

As PHP 5.5, and still present in PHP 7, a function called password_hash() applies a string one-way hashing function to it. A prototype for this is

```
string password_hash ( string $password , array $options )
```

Because the reason is so simple, this enables you to change the hashing algorithm by changing configuration instead of code, and by changing it in a single place.

One other thing you might notice here is that there is a constant called PASSWORD_DEFAULT, which you can pass as the name of the hashing algorithm. PHP will update the value of this over versions to keep it at a secure level. The default algorithm is CRYPT_BLOWFISH, which you can also specify by passing PASSWORD_BCRYPT as the $algo parameter.

With PASSWORD_BCRYPT, it will also generate a salt for you. A salt, in this context, is a randomly generated piece of data added to the password before hashing. It makes more difficult to guess a password.

Given the $password and the PASSWORD_BCRYPT function, this will return a 60-character hash. Strings returned by password_hash() contain all the information necessary to reproduce the hash. This includes the algorithm used and the salt.

This salt cannot be decrypted and turned back into the original string by its creator, so it might not seem very useful at first glance. The property that makes such hashing functions useful is that the output is deterministic. Given the same string, it will return the same result every time it run.

Rather than having PHP code

```
if (($username == 'username') &&
    ($password == 'password')) {
    // OK passwords match
}
```

you can have code

```
if (password_verify($password, $hash)) {
    // OK passwords match
}
```

You do not need to know what the password looked like before you used the hashing function on it. You need to know only if the hash of the password typed is the same as the hash of the password that has been set previously.
