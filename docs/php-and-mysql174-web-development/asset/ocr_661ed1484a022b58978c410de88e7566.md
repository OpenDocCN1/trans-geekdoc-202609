Also notice the dot notation used to make it clear which column comes from; that is, Customers.CustomerID refers to the CustomerID from the Customers table, and Orders.CustomerID refers to the CustomerID from the Orders table.

This dot notation is required if the name of a column is ambiguous—that is, if it occurs in more than one table. As an extension, it can also be used to disambiguate column names from different databases. This example uses table.column notation, by which you can specify the database with database.table.column notation, for example, to test a condition such as books.Orders.CustomerID = other_db.Orders.CustomerID

You, however, use the dot for all references in a query. Using this notation can be a good idea, particularly when your queries begin to become complex. MySQL doesn't require it, but it makes your queries much human readable and maintainable. Notice that we followed this convention in the rest of the previous query, for example, with the use of the condition

```
Customers.Name = 'Julie Smith'
```

The column Name occurs only in the table Customers, so we do not need to specify which table it is from. MySQL will not be confused. For humans, though, the column Name on its own is vague, so it makes the meaning of the query when you specify it as Customers.Name.

# Joining More Two Tables

Joining more two tables is no more difficult than a two-table join. As a general rule, you need to join tables in pairs with join conditions. Think of it as following the relationships from the data table to that table.

For example, if you want to know which customers have ordered books on Java (perhaps you can send them information about a new Java book), you need to trace these relationships through quite a few tables.

Let's look at what that all does:

```
SELECT Customers.Name
FROM Customers, Orders, Order_Items, Books
WHERE Customers.CustomerID = Orders.CustomerID
AND Orders.OrderID = Order_Items.OrderID
AND Order_Items.ISBN = Books.ISBN
AND Books.Title LIKE '%Java%';
```
