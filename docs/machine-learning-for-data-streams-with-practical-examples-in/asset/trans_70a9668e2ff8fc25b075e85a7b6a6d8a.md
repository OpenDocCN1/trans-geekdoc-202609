在大多数感兴趣的情况下，都存在 `size`（大小）的概念，即与每个模式相关联的一个自然数。我们假设大小与模式关系兼容，即如果 `p ≺ p′`，则 `p` 的大小小于 `p′`。项集的大小是其基数，序列的大小是其包含的项数，树或图的大小是其边数。通常，给定大小 `n` 的可能模式数量随 `n` 呈指数级增长。

## 10.1.2 频繁模式挖掘的批处理算法

原则上，查找所有频繁模式的一种方法是对数据集进行一次遍历，记录数据集中作为子模式出现的每个模式及其支持度，最后报告支持度大于所需最小支持度的那些模式。然而，数据集中的子模式数量通常随数据集大小增长过快，导致这种方法不可行。因此，需要更高效的方法。

一个最有用的性质是 `antimonotonicity`（反单调性），也称为 `Apriori property`（Apriori 性质）：频繁模式的任何子模式也是频繁的；等价地说，非频繁模式的任何超模式也是非频繁的。这启发了以下方法，即用于频繁项集挖掘的开创性 Apriori 算法 [9] 所体现的方法：

1.  对数据集进行一次遍历，计算大小为 1 的频繁模式集合 `F[1]`。
2.  对于 `k > 1`，给定集合 `F[k−1]`：
    2.1. 计算候选模式集合 `C[k]`，即大小为 `k` 且其所有大小为 `k − 1` 的子模式都在 `F[k−1]` 中的那些模式；
    2.2. 对数据集进行一次遍历，计算 `C[k]` 中每个模式的支持度；令 `F[k]` 为 `C[k]` 中频繁的模式子集。
3.  当 `F[k]` 为空时停止。

请注意，由于反单调性性质，在步骤 2.1 中将搜索限制在 `C[k]` 时，我们不会丢失任何真正频繁的模式。此外，在实践中，`F[k]` 中频繁模式的数量随 `k` 的增加而迅速减少，因此步骤 2.1 会逐渐变快，遍历次数也适中。换句话说，Apriori [9] 对所有频繁模式集合执行 `breadth-first`（广度优先）探索。它还结合了其他策略，使候选生成阶段 2.1 高效，特别是按字典顺序表示项集。

批处理项集挖掘的其他方法在探索策略和为提高效率而添加的数据结构上有所不同。例如，FP-growth 算法 [131] 使用一种称为 `FP-Trees`（FP 树）的巧妙数据结构，通过两次遍历以紧凑形式存储数据集，然后直接从 FP 树中检索频繁项集，从而避免了昂贵的候选生成阶段。Eclat 算法 [256] 可视为执行深度优先搜索：它将观察到的每个项集与一个支持该项集的事务标识符列表相关联，然后递归地交集这些集合以获得更大项集的列表。

这些及类似的思想已被应用于挖掘频繁序列、树和图。参考文献请参见第 10.5 节引用的综述。

上述概述的算法显然是面向批处理的：Apriori 对数据集执行多次遍历；Eclat 和 FP-growth 分别执行一次和两次遍历，但不清楚它们如何以随时可得的方式返回结果，并且它们存储了太多模式，不适合流式设置。在描述适用于流式处理的方法之前，我们引入一些额外的概念，这些概念有助于减少批处理和流式处理两种情况下的内存需求。

## 10.1.3 闭合模式和最大模式

频繁模式挖掘在实践中面临的一个主要问题是，算法获得的模式往往远多于后续可分析或使用的数量；不仅如此，这些模式往往以显而易见或微妙的方式存在冗余或无趣。关于模式挖掘中 `interest measures`（有趣度度量）的提议，请参见 [119]。

一种冗余形式是存在两个频繁模式 `p` 和 `q`，使得 `p ≺ q`，但 `p` 和 `q` 具有相同或几乎相同的支持度。当我们知道 `q` 是频繁时，知道 `p` 是频繁并没有增加太多信息。`closed`（闭合）和 `maximal`（最大）模式的概念有助于减少输出中的冗余，以及批处理和流式挖掘器中的时间和内存使用。

**定义 10.1** 如果一个模式在数据集 `D` 中的支持度高于其所有超模式，则该模式对 `D` 是 `closed`（闭合）的。如果一个模式是频繁的，且其所有超模式都不是频繁的，则该模式是 `maximal`（最大）的。

[图 10.2](#chapter_10.xhtml#fig10-2) 显示了 [图 10.1](#chapter_10.xhtml#fig10-1) 中数据集的频繁闭合项集和频繁最大项集。例如，`ce` 是闭合的，因为它的支持度高于其超集 `ace`、`bce` 和 `cde`，但 `e` 不是，因为它与其超集 `ce` 具有相同的支持度。模式 `ce` 是频繁的但不是最大的，因为其超集 `cde` 也是频繁的。

请注意，每个最大模式都是闭合的。很容易看出（练习 10.1），给定所有频繁闭合模式，我们可以检索所有频繁模式。如果我们此外还知道所有闭合模式的频率，就可以推导出每个模式的频率。数据集中频繁闭合模式的数量通常远少于频繁模式。因此，寻找频繁闭合模式而不计算所有频繁模式的算法，在时间和内存方面可能高效得多，同时提供相同的信息和更少冗余的输出。这在实践中已被反复验证。最大模式仅告知我们频繁与非频繁之间的边界。

CHARM、CLAIM 和 FPClose 是用于挖掘频繁闭合项集的批处理算法。BIDE+、ClaSP 和 CloSPan 是用于频繁闭合序列的批处理挖掘器。CloseGraph 发现频繁闭合子图。参考文献可参见第 10.5 节引用的综述。

# 10.2 数据流中的频繁模式挖掘：方法

从数据流中提取频繁模式的算法可以根据多个标准进行分类，包括：

*   是挖掘所有频繁模式，还是仅挖掘闭合或最大模式。
*   是从流开始处考虑模式频率，还是通过滑动窗口或某种重要性衰减方案，赋予近期项目更高的重要性。
*   是在每个项目到达后更新频繁项集，还是执行批量更新：即收集一批流项目，然后使用该批次更新表示频繁模式的数据结构。`batch size`（批量大小）的选择对性能至关重要。
*   是精确还是近似，即是返回确切满足频率条件的模式集合，还是仅返回该集合的某种近似。近似算法可能产生假阳性（将非频繁模式报告为频繁）、假阴性（未报告频繁模式），或两者兼有。
