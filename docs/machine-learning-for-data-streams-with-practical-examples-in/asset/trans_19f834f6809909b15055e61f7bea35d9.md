
当 Hoeffding Tree 算法的分裂标准在接收到合理数量的样例后，似乎对多个属性的评价相似时，就会引入选项节点。与其任意等待很长时间来打破平局，不如将所有平局属性作为选项添加进去。这样可以缓解有限前瞻和不稳定性的影响，从而得到更准确的模型。

我们省略了文献 [198] 中给出的并已在 MOA 版本的 HOT（即 `HOEFFDINGOPTIONTREE`）中实现的其他一些细节。叶节点间的投票是加权的，而非使用简单的多数投票。需要限制树增长的策略，因为如果不加控制，选项树往往会增长得非常快。用于回归的 HOT 在构建过程中有细微差别，相关内容见文献 [140]。

## 7.6.2 随机森林

Breiman [55] 在批处理设定下提出了随机森林，它是树的集成，这些树在输入端和决策树的内部构建过程中都使用了随机化。输入通过采用自助采样样本进行随机化，这与标准的 Bagging 相同。树的构建通过要求每个节点只能使用随机选择的属性子集进行分裂来实现随机化。该子集通常很小，其大小例如为属性总数的平方根。此外，树在生长过程中不进行剪枝。随机森林通常是在许多批处理任务中表现最好的分类器方法之一。

流式随机森林的实现已由 Abdulsalam 等人 [2] 等人提出，他们并未完全使用 Hoeffding Tree，而是采用了另一种类型的在线树构建器。利用 Hoeffding Tree 并发挥 GPU 算力的实现见文献 [167]。这些以及大多数其他流式随机森林实现都采用“替换失败者”策略来应对概念漂移。

遗憾的是，这些随机森林算法都无法有效地与前述各种基于 Bagging 和 Boosting 的算法竞争。然而，最近 Gomes 等人 [125] 提出了自适应随机森林（ARF）算法，它似乎是一个强有力的竞争者。与之前尝试为数据流学习复制随机森林 [124] 的做法相反，ARF 包含一种有效的重采样方法和自适应算子，能够在无需针对不同数据集进行复杂优化的情况下应对不同类型的概念漂移。文献 [125] 中展示的 ARF 并行实现与串行实现相比，在分类性能方面没有退化，因为树和自适应算子彼此独立。

## 7.6.3 受限 Hoeffding Tree 的感知机堆叠

在机器学习中反复观察到的一个现象是：通常，复杂模型会被那些不试图对属性间复杂交互建模的简单模型所超越。Bifet 等人 [31] 针对 Hoeffding Tree 集成研究了这种可能性。与全 Hoeffding Tree 的随机森林不同，他们提出使用带有感知机算法作为元学习器的堆叠方法，并使用小型树。

更准确地说，他们的算法枚举大小为 *k* 的所有属性子集，并在每个子集上学习一棵 Hoeffding Tree。这些树作为输入提供给一个堆叠算法，该算法使用感知机算法作为元学习器。树的生长很快，因为每棵树都很小，我们期望元学习器最终会给最佳的 *k* 个属性组合分配较大的权重。

由于在 *n* 个属性中有 $\binom{n}{k}$ 个大小为 *k* 的集合，因此对于大多数 *n* 值，只有较小的 *k* 值是可行的。当 *k* = 1 时，该算法退化为感知机，但 *k* = 2 被发现适用于中等规模的数据集。为了应对概念漂移，该方法为每棵树添加了一个 `ADWIN` 变化检测器。当一棵树的错误率发生显著变化时，该树将被重置，并使用该属性组合学习一棵新树。文献 [31] 表明，该方法在简单合成数据集上的表现优于 ADWIN Bagging，这表明在预测关键不在于属性的复杂组合的情况下，该方法可能表现良好。

该方法在 MOA 中作为 `LIMATTCLASSIFIER` 实现。

## 7.6.4 自适应大小 Hoeffding Tree

自适应大小 Hoeffding Tree（ASHT）方法 [38] 在 MOA 中作为 `OZABAGASHT` 实现，它创建一个具有以下限制的 Hoeffding Tree 集成：

*   集成中的每棵树都有一个关联值，代表其可达到的最大内部节点数。
*   在一棵树发生节点分裂后，如果其大小超过其关联值，则该树将被重置为一个叶节点。

如果集成中有 *N* 棵树，分配最大尺寸的一种方法是选择 2 的幂：2, 4, … 直到 $2^k$。该方法背后的直觉是：较小的树能更快地适应变化，而较大的树在变化很少或没有变化的时期表现更好，仅仅是因为它们是用更多数据构建的。大小限制为 *s* 的树重置频率约为大小限制为 2*s* 的树的两倍。这为这组树创建了一系列不同的重置速度，因此总有一部分树能很好地逼近当前的变化率。

集成的输出可以是所有树的多数投票，尽管文献 [38] 通过实验发现，按其误差平方的反比对它们进行加权效果更好。每棵树的误差由 `EWMA` 估计器监控。

重要的是要注意，重置会一直发生，即使在平稳数据集上也是如此，但这种行为不应损害集成的预测性能。

# 7.7 循环概念

在许多场景中，数据流分布的演变方式是：过去出现的分布在未来重新出现。具有明显每日、每周或每年周期性的数据流（如天气、客户销售和道路交通）就是例子，但重现也可能以非周期性的方式发生。

针对这些场景，已提出了*循环*或*反复出现的概念*框架 [112, 127, 143, 219]。提案的细节各异，但主要思想是保存一个过去曾有用但已从集成中移除的分类器库，例如因为它们在某个时刻表现不佳。尽管如此，仍会定期重新检查它们的准确性，以防它们似乎又表现良好，如果是，则将它们重新加入集成。

估计一个分类器的准确性所需的样例远少于从头构建一个新分类器所需的样例，因此这种方案以内存换取训练时间。当库变得太大时，需要额外的规则来丢弃分类器。

Gonçalves 和 de Barros [143] 提出的 RCD 循环概念框架可作为 MOA 扩展获得。
