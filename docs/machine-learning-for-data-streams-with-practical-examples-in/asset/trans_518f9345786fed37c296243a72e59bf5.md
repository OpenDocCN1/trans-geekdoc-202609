

# 使用 CM-Sketch 进行范围求和查询

范围求和查询可以使用 CM-Sketch 实现，方法如下：设 `|I| = 2^n` 为潜在项的数量。对于每个 2 的幂 `2^i`（`0 ≤ i ≤ n`），创建一个 CM-Sketch `C[i]`，用于对大小为 `2^i` 的区间内的项进行范围求和。更准确地说，向 `C[i]` 发出的 `Query(j)` 将返回区间 `[j·2^i … (j + 1)·2^i − 1]` 内项的总计数。或者，我们可以想象在第 `i` 层，每个项 `x` 都属于“超级项” `x mod 2^(n−i)`。特别地，`C[0]` 存储单个项的计数，而 `C[n]` 存储所有计数的总和。然后，我们可以使用以下递归来回答针对 `C[i]` 的范围求和查询 `(x, y)`，其中 `x` 和 `y` 位于同一个大小为 `2^i` 的区间内：

1. 如果 `x` 和 `y` 落在同一个大小为 `2^(i−1)` 的区间内，我们向 `C[i−1]` 查询 `(x, y)` 并返回其答案。
2. 否则，如果存在某个 `j` 使得 `x < j·2^(i−1) ≤ y`（即 `x` 和 `y` 不属于同一个大小为 `2^(i−1)` 的区间），我们向 `C[i−1]` 查询范围求和 `(x, j·2^(i−1) − 1)` 和 `(j·2^(i−1), y)`，然后返回两个答案的总和。

Sketch `C[0]` 是递归的基础。

现在，带参数 `k` 的重击项问题可以通过按深度探索区间集合 `[j·2^i, (j + 1)·2^i − 1]` 来解决。如果区间的权重低于 `F/k`，则其下方的任何叶节点都不可能是重击项，因此返回空列表。否则，将其划分为两个大小相等的区间分别探索，并将返回的列表连接起来。当到达叶节点时，当且仅当它是重击项时（即其权重为 `F/k` 或更多）才返回它。此外，在树的每一层中，权重为 `F/k` 或更多的节点最多有 `k` 个，因此最多探索树的 `k log |I|` 个节点。总而言之，重击项的查找使用 `O((log |I|) ln(1/δ) / ε)` 个内存字。

如前所述，CM-Sketch 可用于高效解决流上的其他几个问题 [81]，包括分位数计算、项频率直方图、相关性以及两个流的内积。然而，对于分位数计算的情况，专用 Sketch FrugalStreaming [163] 被认为是最先进的技术。我们将在第 6.4.3 节描述分类问题中数值属性的管理时介绍另一种分位数摘要。

## 4.6.3 CountSketch

COUNTSKETCH 算法由 Charikar 等人 [64] 提出。与 CM-SKETCH 一样，它支持具有正负权重的更新。它使用 `O(1/ε²)` 的内存，但能找到所谓的 `F[2]`–重击项，这是常规重击项（或 `F[1]`–重击项）的一个有趣的超集。

流的 `F[2]` 范数定义为 `√(∑_x f[x]²)`。如果 `f[x] ≥ ε √(∑_y f[y]²)`，则项 `x` 是阈值为 `ε` 的 `F[2]`–重击项。一些简单的代数运算表明，每个 `F[1]`–重击项也是 `F[2]`–重击项。

在其最简单的形式中，COUNTSKETCH 可以描述如下。它选择两个哈希函数。函数 `h` 将项映射到一组 `w` 个桶 `{0, …, w − 1}`。函数 `σ` 将项映射到 `{−1, +1}`。假设两者都足够随机。特别是 `σ` 的一个重要性质是：对于不同的 `x` 和 `y`，`σ(x)` 和 `σ(y)` 相互独立，这意味着 `Pr[σ(x) = σ(y)] = 1/2`，进而意味着 `E[σ(x) · σ(y)] = 0`。

算法维护一个包含 `w` 个累加器的数组 `A`，初始化为 0。对于流中的每一对 `(x, c)`，它向 `A[h(x)]` 添加值 `σ(x) · c`。注意，给定 `x` 的更新要么全部相加，要么全部相减，取决于 `σ(x)`。当被要求提供 `f[x]` 的估计值时，算法返回 `Query(x) = σ(x) · A[h(x)]`。如果没有其他项 `y` 被映射到 `A` 中与 `x` 相同的单元格，该估计将是精确的，但这种情况很少见。尽管如此，可以证明在哈希函数的随机选择下，其期望是正确的。确实：

```
E[Query(x)] = E[σ(x) · A[h(x)]]
            = E[σ(x) · ∑_y σ(y) · f[y] · I(h(y) = h(x))]
            = ∑_y f[y] · E[σ(x)σ(y)] · Pr[h(y) = h(x)]
            = f[x]
```

因为如前所述，对于 `x ≠ y`，`E[σ(x)σ(y)] = 0`，且 `σ(x)² = 1`。类似的代数运算表明 `Var(Query(x)) ≤ F[2] / w`。

现在我们可以使用类似第 4.9.2 节所述的策略，先提高精度，再提高置信度：取 `w = 12/(5ε²)` 个独立副本的平均值；根据切比雪夫不等式，这以 `5/6` 的概率用加性误差 `ε √(F[2]/w)` 估计每个频率。然后独立地重复此过程 `d = O(ln(1/δ))` 次并返回结果的中位数；霍夫丁不等式表明（见练习 4.9），这将置信度提升至 `1 − δ`。因此，满足 `Query(x) ≥ ε √(F[2])` 的 `x` 的集合以高概率包含每个 `F[2]`–重击项。注意，与 CM-SKETCH 和 SPACESAVING 不同，这里除了假阳性外可能还有假阴性，因为使用的是中位数而非最小值。内存使用为 `O(ln(1/δ) / ε²)` 字。

此时，我们可以将基本算法的 `d` 个副本视为一个类似于 CM-SKETCH 的单一算法：它选择哈希函数 `h[0], …, h[d−1]`、`σ[0], …, σ[d−1]`，并维护一个具有 `d` 行 `w` 列的数组 `A`。伪代码如 [图 4.9](#chapter_4.xhtml#fig4-9) 所示。为了高效地恢复重击项，COUNTSKETCH 还基于估计权重维护一个迄今为止见过的最频繁元素的堆。

## 4.6.4 矩计算

*频率矩* 是项频率的一种推广，能提供关于流中项分布的不同信息。在每个项 `x` 具有绝对频率 `f[x]` 的流中，第 `p` 阶矩定义为

```
F[p] = ∑_x f[x]^p
```

观察可知，`F[1]` 是流的长度，而 `F[0]` 是流包含的不同项的数量（如果我们取 `0⁰` 为 0，且对于任何其他 `f` 有 `f⁰ = 1`）。`F[2]` 尤为重要，因为它可用于计算流中项的方差。极限情况是 `F[∞]`，定义为

```
F[∞] = max_x f[x]
```

即最高频元素的频率。

Alon 等人 [14] 开启了用于计算频率矩近似值的流算法研究。他们针对 `p ≥ 2` 的 Sketch（称为 Alon-Matias-Szegedy 或 AMS Sketch）使用了一种类似于 CM-SKETCH 的技术：选取将每个项映射到 `{−1, +1}` 的哈希函数，利用它们构建一个无偏但高方差的矩估计器，然后对多个副本取平均和中位数，以产生任意精确的估计。

他们的工作已经表明，计算 `p ≤ 2` 时的 `F[p]` 与 `p > 2` 时的 `F[p]` 在内存需求上存在突发性差异。经过一长系列论文的研究，文献 [141] 证明了，考虑相对近似：

*   对于 `p ≤ 2`，`F[p]` 可以在数据流中使用 `O(ε^(−2) (log t + log m) ln(1/δ))` 比特内存进行近似，且
*   对于 `p > 2`，`F[p]` 可以在数据流中使用 `Ω(m^(1−2/p) / (ε² log m))` 比特内存进行近似。
