
# 4.5 不同元素计数

一个更具挑战性的问题是计算迄今为止在流中观察到的*不同*元素的数量（也有些不正确地称为*唯一*元素，也许是类比 Unix 的 `uniq` 命令）。困难在于，一个项目可能只出现一次，而另一个项目出现数百万次，但两者对不同元素计数的贡献相同，都是 1。

作为动机，考虑计算互联网链路所见不同流（源-目的 IP 地址对）数量的问题。潜在项目的数量巨大：IPv6 地址为 64 位，因此有 $2^{128} \simeq 10^{38}$ 个潜在项目，即地址对。直接的解决方案是保留某种关联表，如哈希表，并记录实际已见的地址对。对于繁忙链路，这可能很快变得太大而无法存储。幸运的是，我们通常可以用近似质量换取内存使用量。

## 4.5.1 线性计数

不同元素计数的几种方法都是经典 *Bloom filter*（布隆过滤器）思想的变体。作为示例，我们讨论 **LINEAR COUNTING**（线性计数），由 Whang 等人 [246] 提出，如 [图 4.3](#chapter_4.xhtml#fig4-3) 所示。

LINEAR COUNTING 概要。

初始化中的参数 $D$ 是流中不同元素数量 $d$ 的上界，即我们假设 $d \le D$。两个集合之间的*哈希函数*，直观上讲，将第一个集合中的每个元素 $x$ 映射到第二个集合中的一个“随机”元素。关于这究竟意味着什么，以及如何构建可用少量位存储的“足够好”的哈希函数的技术讨论留待第 4.9.1 节。我们只说明，对于我们的目的足够随机且将 $\{0,\dots,m-1\}$ 映射到自身的哈希函数，可以从 $O(\log m)$ 个真正随机位获得，并用 $O(\log m)$ 位存储。

流中存在的每个项目都将表 $B$ 的一个条目设为 1，无论它出现多少次，设置的都是同一个条目。直观上，一个好的哈希函数确保流中出现的不同项目均匀地分配到 $B$ 的条目中。然后，`Query` 返回的期望值是流中见到的不同值的数量加上一个微小的偏差项，其标准差为 ![](images/pg44-in-1.png)。对于相当大的不同元素数量 ![](images/pg44-in-2.png)，这比 $d$ 本身小得多，这意味着 LINEAR COUNTING 在相对意义上将相当准确。

## 4.5.2 Cohen 的对数计数器

**Cohen 计数器** [74] 基于这一思想，但利用以下观察转移到对数空间。$B$ 中两个连续 1 之间的平均间隔由流中 1 位的数量决定，约为 $s/d$。这对于第一个间隔特别成立，等价地，对于第一个 1 的位置也是如此。方便的是，存储这个第一个位置只需 $\log s$ 位，因为它是观察到的哈希函数值的最小值。概要如 [图 4.4](#chapter_4.xhtml#fig4-4) 所示。Cohen 计数器仅使用 $\log D$ 位来存储 $p$。

![图 4.4 Cohen 计数算法。](images/Fig4-4.png)

可以证明 $p$ 的期望值为 $D/d$，且 `Query` 过程在期望下返回 $d$。其方差较大，约为 $(D/d)^2$。可以通过并行运行多个副本并取平均值来减小方差，但这需要构建多个独立且“良好”的哈希函数，这是有问题的。一种使用单个哈希函数的替代方法将作为下一个概要的一部分呈现。

## 4.5.3 Flajolet-Martin 计数器与 HyperLogLog

一系列算法始于 Flajolet-Martin 计数器 [105]，终于 HyperLogLog [104]，能以更少的位实现相对近似 $\epsilon$，即 $O((\log \log D)/\epsilon^2)$，外加存储哈希函数所需的空间。该方法的直觉如下：设 $D$ 为 $2^k$。在范围 $[0, 2^k - 1]$ 内不重复地均匀随机选择数字；这就是将良好的哈希函数应用于流项目后得到的结果。所有这些数字都可以用二进制的 $k$ 位表示；其中一半的第一位为 0，四分之一有两个前导 0，八分之一以 000 开头，依此类推。一般来说，前导模式 $0^i 1$ 出现的概率为 $2^{-(i+1)}$，因此如果 $0^i 1$ 是迄今为止哈希值中最长的此类模式，则我们可以预期 $d$ 约为 $2^{i+1}$。Durand 和 Flajolet [93] 在改进 Flajolet-Martin 算法时意识到，只需记住 $k$，用 $\log k = \log \log D$ 位，即可跟踪最长模式，即最大的 $i$。带有此改进的基本 Flajolet-Martin 概率计数器以伪码形式给出在 [图 4.5](#chapter_4.xhtml#fig4-5) 中。

![图 4.5 基本 Flajolet-Martin 概率计数器。](images/Fig4-5.png)

[**图 4.5**](#chapter_4.xhtml#rfig4-5)

基本 Flajolet-Martin 概率计数器。

该方法需要一个哈希函数 $h$，将每个项目尽可能随机地转换为 0 到 $L - 1$ 之间的整数。文献 [105] 表明，如果已读取 $d$ 个不同项目，$p$ 的期望值为 $\log(0.77351 d)$，其标准差为 $1.12127\dots$。概要仅需存储 $p$ 的内存，其值最大为 $L = \log D$，因此需要 $\log \log D$ 位。

该方法的主要缺点是估计中的相对较大误差，数量级约为 $d$。如前所述，可以通过平均多个副本来减小误差。但这有两个问题：一是相应地增加了更新操作的计算时间。二是获取多个真正独立的哈希函数很难。

Flajolet 和 Martin 提出了一种他们称为*随机平均*的技术：概念上将流分成 $m = 2^b$ 个子流，每个子流馈送一个不同的计数器副本。对于每个项目 $x$，使用 $h(x)$ 的前 $b = \log m$ 位来决定 $x$ 分配到哪个子流，并用 $h(x)$ 的其余 $m - \log m$ 位来馈送相应的计数器。现在可以使用单个哈希函数，因为不同子流中的项目看到的是同一函数的独立部分，且更新时间本质上与单个计数器相同。内存使用仍乘以 $m$。

上述算法的不同变体在于如何将 $m$ 个副本的结果组合成单一估计。

*   **LogLog** [93] 返回其估计的几何平均数，即其变量 $p$ 的算术平均数的 2 的幂，乘以一个常数。
*   **SuperLogLog** [93] 在执行上述操作前移除排名前 30% 的估计值；这减小了异常值的影响。
*   **HyperLogLog**，由 Flajolet 等人 [104] 提出，则返回 $m$ 个估计值的调和平均数，这同样能平滑较大的异常值。

上述变体实现的标准差分别为 $1.3d/\sqrt{m}$、$1.05d/\sqrt{m}$ 和 $1.04d/\sqrt{m}$，并使用 $O(m \log \log D)$ 内存，外加 $O(\log D)$ 位存储可在所有计数器实例间共享的哈希函数。通过使用切比雪夫不等式，只要 $m = O(1/(\delta \epsilon^2))$，即可获得 $(\epsilon, \delta)$-近似；注意不清楚如何应用霍夫丁界，因为估计值不是平均值。换种说法，取 $\epsilon = O(1/\sqrt{m})$，我们使用 $O((\log \log D)/\epsilon^2)$ 位内存，即可为固定置信度实现相对近似 $\epsilon$。

用更具体的术语来说，根据 [104]，HyperLogLog 可以在 2% 误差内近似高达 $10^9$ 的基数，仅使用 1.5 千字节内存。关于 HyperLogLog 在大规模应用中的实际实现讨论，见 [134]。
