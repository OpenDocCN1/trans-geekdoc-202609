
# Gartner 对大数据的定义

Gartner [200] 在 2012 年对大数据的定义中总结道：“高容量、高速度和高多样性的信息资产，需要具有成本效益的创新形式的信息处理，以增强洞察力和决策能力。”

大数据的应用应使人们能够获得更好的服务、更好的客户体验，并更加健康：

*   **商业**：客户个性化和流失检测（客户从一家公司转移到竞争对手）。
*   **技术**：将处理时间从小时缩短到秒级。
*   **健康**：挖掘人们的医疗记录和基因组数据，以监测和改善他们的健康。
*   **智慧城市**：专注于可持续经济发展和高质量生活的城市，并对自然资源进行明智管理。

作为大数据挖掘实用性的一个例子，我们参考 Global Pulse [236] 的工作，该工作利用大数据改善发展中国家的生活。Global Pulse 是联合国的一项倡议，作为一个创新实验室运作，其策略是挖掘大数据以：

1.  研究分析实时数字数据的创新方法和技术，以检测早期出现的脆弱性。
2.  组装一个免费的开源技术工具包，用于分析实时数据和共享假设。
3.  建立一个集成的全球 Pulse Labs 网络，在国家层面试点该方法。

大数据挖掘革命不仅限于工业化世界，因为移动设备在发展中国家也在普及。据估计，移动电话超过 50 亿部，其中 80% 位于发展中国家。

# 1.1.1 工具：开源革命

大数据现象与开源软件革命密不可分。雅虎、Twitter、LinkedIn、Google 和 Facebook 等大公司既受益于开源项目，也为开源项目做出了贡献。一些例子包括：

*   **Apache Hadoop** [16]：一个用于数据密集型分布式应用的平台，基于 `MapReduce` 编程模型和 `Hadoop Distributed File System (HDFS)`。`Hadoop` 允许我们编写应用程序，在计算节点集群上并行快速处理大量数据。
*   **与 Apache Hadoop 相关的项目** [260]：`Apache Pig`、`Apache Hive`、`Apache HBase`、`Apache ZooKeeper`、`Apache Cassandra`、`Cascading`、`Scribe` 和 `Apache Mahout` [17]（主要基于 `Hadoop` 的可扩展机器学习和数据挖掘开源软件）。
*   **Apache Spark** [253]：一个用于大规模数据处理的引擎，运行在 `Hadoop` 基础设施上。`Spark` 提供了一个库栈，包括 `SQL` 和 `DataFrames`、`MLlib`（用于机器学习）、`GraphX` 和 `Spark Streaming`。这些库可以在同一个应用程序中轻松组合。
*   **Apache Flink** [62]：一个流数据流引擎，为分布式计算提供数据分发、通信和容错。`Flink` 包含多个用于创建应用程序的 API。如果 `Apache Spark` 是一个批处理引擎，可以使用微批次通过 `Spark Streaming` 模拟流处理，那么 `Apache Flink` 就是一个流处理引擎，也可以执行批处理。
*   **Apache Storm** [168]：用于流数据密集型分布式应用的软件，类似于 `Apache S4` 和 `Apache Samza`。
*   **TensorFlow** [1]：一个用于机器学习和深度神经网络的开源包。

# 1.2 大数据挑战

大数据管理和分析的未来面临许多挑战，源于数据的本质：大量、多样和不断演变 [128]。研究人员和从业者在未来几年将不得不面对的一些挑战包括：

*   **分析架构**。目前尚不清楚如何构建最优的分析系统架构，以同时处理历史数据和实时数据。Nathan Marz [169] 提出了 `Lambda` 架构作为首个方案。`Lambda` 架构通过将问题分解为三层来解决实时计算任意数据上任意函数的问题：批处理层、服务层和速度层。它在同一系统中结合了用于批处理层的 `Hadoop` 和用于速度层的 `Storm`。一个较新的提议是 `Kappa` 架构，由 LinkedIn 的 Kreps [152] 提出。它简化了 `Lambda` 架构，移除了批处理系统。
*   **评估**。实现统计学显著结果很重要，不能被随机性误导。如果不妥善处理“多重假设问题”，在海量数据集和数千个同时待答问题面前很容易出错，Efron [95] 对此有解释。此外，避免只关注误差或速度等技术指标而忽视现实世界影响的陷阱也很重要，Wagstaff [242] 讨论了这一点：只有定期发布符合本文中解释的挑战问题合理标准的应用，才能反驳认为大数据全是炒作的观点。
*   **分布式挖掘**。许多数据挖掘技术并非易于并行化。要获得某些方法的分布式版本，需要通过实际实验和理论分析进行大量研究。
*   **时变数据**。数据可能随时间演变，因此大数据挖掘技术能够适应变化，并在某些情况下显式检测变化非常重要。本书中的许多数据流挖掘技术正是由这一需求驱动的 [110]。
*   **压缩**。处理大数据时，存储所需的空间量非常相关。主要有两种方法：压缩（不丢失信息）和采样（选择被认为有代表性的数据）。使用压缩，我们用更多时间换取更少空间，可视为从时间到空间的转换。使用采样，我们丢失信息，但空间收益可能达到数量级。例如 Feldman 等人 [99] 使用核心集来降低大数据问题的复杂度；核心集是数据的一个小子集，可针对给定问题可证明地近似原始数据。
*   **可视化**。大数据分析的一个主要问题是如何可视化结果。以人类可理解的方式呈现来自大量数据的信息是一项挑战。这需要新的技术和框架来讲述故事，如精美书籍 *The Human Face of Big Data* [228] 所涵盖的内容。
*   **隐藏的大数据**。大量有用数据实际上毫无用处，因为它们未标记、基于文件且非结构化。2012 年 IDC 的大数据研究 [117] 解释说，2012 年数字宇宙中 23%（643 EB）的数据如果经过标记和分析将对大数据有用。然而，当时只有 3% 的潜在有用数据被标记，分析的更少。近年来数据可能变得更糟。开放数据和语义 Web 运动的出现，部分是为了让我们意识到并改善这一状况。
