# 频繁模式挖掘

频繁模式挖掘是数据挖掘中的一项重要无监督学习任务，具有多种应用。它可以纯粹作为一种无监督的探索性数据分析方法，也可以作为发现关联规则的基础。此外，它还可用于为分类或聚类寻找判别性特征。

本章介绍构建流模式挖掘算法的技术。我们首先（第 10.1 节）介绍与模式挖掘相关的主要概念、批处理设置中使用的基本技术，以及`closed`模式的概念，这在流设置中尤为重要。然后我们概述（第 10.2 节）如何使用批处理挖掘器构建流挖掘器，以及如何使用`coresets`提高效率。随后，我们重点介绍模式概念的两个实例——项集和图——以及使用通用方法并进行各种优化的算法。第 10.3 节描述了几种频繁项集挖掘算法，特别是 MOA 中实现的 `IncMine` 算法。第 10.4 节描述了频繁子图挖掘算法，包括 MOA 中实现的 `AdaGraphMiner`。第 10.5 节提供了进一步阅读的参考文献。

# 10.1 模式挖掘简介

## 10.1.1 模式：定义与示例

从广义上讲，`patterns`（模式）是指其存在或不存在、或其频率能够指示数据偏离随机性方式的实体。接下来介绍的组合结构，如项集、序列、树和图，被广泛用于体现这一思想。从这个意义上说，所有模式都可以被视为图的子类 [255]。我们的介绍基于`pattern relation`（模式关系）的思想，遵循文献 [34] 的思路；我们认为这能使许多算法思想的表述更加统一。

`Itemsets`（项集）是项集合 *I* = {*i*[1],⋯ *,i*[*n*]} 的子集。在项集中，子模式和超模式的概念分别对应于子集和超集的概念。项集挖掘最常被引用的例子是：*I* 是超市待售产品的集合，而项集是某次特定购买中的产品集合。挖掘频繁项集意味着找出客户经常一起购买的产品集合。

`Sequences`（序列）在其最基本的形式下是项的有序列表，例如 ⟨*i*[3]*, i*[7]*, i*[2]*, i*[10]*, i*[6]⟩；⟨*i*[7]*, i*[10]⟩ 和 ⟨*i*[3]*, i*[7]*, i*[6]⟩ 都是该序列的子序列。一个使用示例是找出某软件用户频繁发出的命令序列。一种推广形式使有序列表的每个元素成为一个项集，例如 *S* = ⟨*I*[1]*, I*[2], . . . , *I*[*n*]⟩，其中每个 *I*[*i*] 是 *I* 的子集。子序列的概念相应地变得更复杂：![](images/pg166-in-1.png)是 *S* 的子序列，如果存在整数 ![](images/pg166-in-2.png) 使得 ![](images/pg166-in-3.png)。

`Trees`（树）是无环图的一种特殊情况；树可能有根也可能无根，节点和边可能有标签也可能无标签。存在几种可能的`subtree`（子树）或树子模式概念。树 *t* 的`induced subtree`（导出子树）是指以 *t* 的某个节点 *v* 为根、其顶点和边是 *t* 的子集的任何树。树 *t* 的`top-down subtree`（自顶向下子树）是包含 *t* 的根的 *t* 的导出子树。树 *t* 的`embedded subtree`（嵌入子树）是指以 *t* 的某个节点 *v* 为根的任何树。示例和讨论请参见文献 [69, 142]。频繁树挖掘的一个实际应用与 XML 查询服务器相关，因为 XML 查询本质上是带标签的有根树。检测频繁子树或子查询可能很有用，例如用于对查询进行分类，或优化、预计算或缓存其答案。

`Graph G`（图 *G*）是由节点集合 *V* 和节点间的边集合 *E* 组成的二元组。可以为节点和边添加标签。*G* = (*V, E*) 是 *G*′ = (*V*′*, E*′) 的`subgraph`（子图）或图子模式的一个常见定义是：*V* ⊆ *V*′ 且 *E* ⊆ (*V* × *V*) ∩ *E*′。在复杂网络分析中，`motifs`（基序）是在较大网络中反复出现的子网络，通常可用于预测或解释较大网络中的行为。在网络中寻找显著基序与挖掘频繁子图密切相关。

现在让我们将这些定义推广为一个统一的定义。模式类是一个带有关系 ≼ 的集合 𝒫，该关系是一种偏序：自反、反对称和传递，可能存在无法通过 ≼ 比较的模式对。对于模式 *p, p*′ ∈ 𝒫，如果 *p* ≼ *p*′，我们称 *p* 是 *p*′ 的子模式，而 *p*′ 是 *p* 的超模式。此外，如果 *p* 是 *p*′ 的真子模式，即 *p* ≼ *p*′ 且 *p* ≠ *p*′，我们记作 *p* ≺ *p*′。

我们的数据挖掘过程的输入是一个数据集（或流，在流设置中）*D*，其中每个事务 *s* ∈ *D* 由一个事务标识符和一个模式组成。我们通常会忽略事务标识符，将 *D* 视为模式的多重集，或等价地视为对 (*p, i*) 的集合，其中 *p* 在 *D* 中出现 *i* 次。

如果模式 *p* 是事务 *t* 中模式的子模式，则称事务 *t supports*（支持）模式 *p*。模式 *p* 在数据集 *D* 中的`absolute support`（绝对支持度），记作 *supp*(*p*)，是数据集 *D* 中支持 *p* 的事务数量。模式 *p* 的`relative support`（相对支持度）为 *σ*(*p*) = *supp*(*p*)/|*D*|，其中 |*D*| 是 *D* 的基数。*数据库中的 `σ-frequent patterns`（σ-频繁模式）是指相对支持度至少为 *σ* 的模式。请注意，大小为 1 的 `σ-frequent itemsets`（σ-频繁项集）在第 4.6 节中被称为 `σ-heavy hitters`（σ-重击者）。

`frequent pattern mining problem`（频繁模式挖掘问题）定义如下：给定一个数据集 *D* 和 [0, 1] 区间内的阈值 *σ*，找出 *D* 中所有的 `σ-frequent patterns`（σ-频繁模式）。
