

忽略对数因子，其中 `t` 是流的长度，`m = |I|` 是项目集合的大小。此外，对于除 0 和 1 以外的每个 `p`，该数量级的内存实际上是*必要*的。后续工作也基本消除了对数间隙。特别是，对于 `F[∞]` 或最大频率，需要流长度级别的线性内存。请注意，对于特殊情况 `p = 0` 和 `p = 1`，我们在前几节中给出的算法使用的内存是 `O(log log t)`，而不是 `O(log t)`。

# 4.7 滑动窗口的指数直方图

通常，流中较新的项目对于分析应被视为更重要。我们将在第 5 章中通过几种方式对这一想法进行建模，但这里我们考虑最简单的模型，即*滑动窗口*：在任何时候，我们只认为最后接收到的 `W` 个项目是相关的，其中 `W` 是窗口大小；所有之前的项目都是无关的。或者，我们固定一个时间持续时间 `T`（如一周、一小时或一分钟），并且只考虑从现在起时间 `T` 内到达的项目。我们将主要考虑第一种模型，但适应第二种模型也很容易。

考虑在实数流中维护最后 `W` 个值的和这一问题。自然的解决方案是使用大小为 `W` 的循环缓冲区；每个到达的元素都加到总和中；它将最旧的元素从缓冲区中逐出，并从总和中减去该元素。该方案具有常数更新时间，但使用内存 `W`。事实上，可以证明任何*精确*解决此问题的流算法必须使用至少 `W` 的内存。

接下来我们将看到一种仅存储 `O(log W)` 个值来维护和的*近似*值的方法。Datar 等人 [83] 提出的*指数直方图*草图维护实数滑动窗口上聚合函数的近似值。我们仅详细描述聚合函数为求和且项目为比特的情况。

该草图将长度为 `W` 的窗口划分为一系列子窗口，并用一个*桶*表示每个子窗口。直观上，桶编码了大小为 `W` 的所需窗口，其中较旧的 1 以越来越低的分辨率表示。每个桶有一个*容量*，它是 2 的幂，并表示一个包含与其容量一样多的 1 的子窗口。它包含一个整数值，即*时间戳*，这是它所代表的子窗口中最近的 1 的时间戳。对于参数 `k > 1`，有 `k` 个容量为 1 的桶，由最近的 `k` 个 1 界定；`k` 个容量为 2 的桶；`k` 个容量为 4 的桶；依此类推，直到容量为 `2^(m)` 的 `k` 个桶，其中 `m` 是确保有足够桶来容纳 `W` 个项目的最小值，即

```
m ≃ log(W/k)
```

注意 `m ≃ log(W/k)`，因此共有 `km ≃ k log(W/k)` 个桶。

该方法的伪代码见[图 4.11](#chapter_4.xhtml#fig4-11)，将滑动窗口划分为桶的示例见[图 4.10](#chapter_4.xhtml#fig4-10)。该示例展示了在某一时刻 `t`，流的最后 29 个比特如何划分为 6 个桶，其中 `k = 2`。每个桶包含的 1 的数量等于其容量。最近的比特在右侧，时间戳为 `t`。最旧的比特在左侧，时间戳为 `t − 28`。每个桶的时间戳是其最近的 1 的时间戳。如果所需的滑动窗口大小 `W` 为 25，则最近 `W` 个比特中 1 的真实计数为 11，因为时间戳在 `t − 24` 和 `t` 之间的 1 有 11 个。草图将报告窗口的和为 12：所有桶中 1 的总数（14），减去最旧桶容量的一半（2）。因此相对误差为 `(12 − 11)/11 ≃ 9%`。

近似中的误差仅由最旧的桶引入。它必须至少包含一个时间戳大于 `t − W` 的 1，否则它就会被丢弃，但也可能包含多达 `2^(m) − 1` 个时间戳至多为 `t − W` 且不应被精确方法计数的 1。因此相对误差至多为最旧桶容量的一半除以所有桶的容量之和。由于经过短暂的过渡期后，除最大桶外，每种大小的桶都有 `k − 1` 或 `k` 个，因此相对误差至多为 `(2^(m)/2)/(2^(m) + (k − 1)(2^(m−1) + ⋯ + 1)) ≃ 1/2k`。

如果期望的近似率为 `𝜖`，则设置 `k = 1/2𝜖` 即可。桶的数量则为 `(log W)/2𝜖`。每个桶包含一个时间戳，原则上这是一个无界数。然而，我们可以通过对 `W` 取模计数，将时间戳缩减到区间 `0…W − 1`，因此一个时间戳有 `log W` 位，总共需要 `O((log W)²/𝜖)` 位内存。如果桶更新的级联影响所有桶，最坏情况下更新时间为 `O(log W)`，但这种情况很少发生；摊还时间为 `O(1)`。一种称为*确定性波*的指数直方图变体实现了最坏情况 `O(1)` 时间 [122]。

该草图可以通过将内存乘以 `log B` 来适应范围 `[0, B]` 内的非负数，也可以维护其他聚合的近似值，如方差、最大值、最小值、不同元素数量和直方图 [83]。

# 4.8 分布式草图：可合并性

到目前为止讨论的大多数草图都具有称为*可合并性*的属性，这使它们适合分布式计算。如果一种草图类型是*可合并的*，则意味着从数据流 `D[1]` 和 `D[2]` 构建的两个草图可以高效地合并为同类型的另一个草图，该草图能正确回答关于 `D[1]` 和 `D[2]` 交织的查询。请注意，对于仅依赖项目频率的问题，所有流交织的答案都是相同的。对于其他问题，可合并性的定义可能更复杂。

作为一个简单的例子，考虑一个由计算流中项目数量的整数组成的“草图”。现在我们从两个流构建两个这样的草图。如果我们将它们的值相加，结果正确地是将原始两个流合并后得到的任何流中的项目数量。

不那么平凡的是，取 OR 运算是线性计数器的正确合并操作。对于 Cohen 和 Flajolet-Martin 计数器及其变体，取其存储值的最小值（如果我们使用多个副本以减少方差，则逐分量取最小值）。对于 CM-sketch，将两个计数器数组逐分量相加。在这些情况下，待合并的两个草图必须使用相同的哈希函数。SPACESAVING 和指数直方图的情况留作练习。

可合并性允许按如下方式进行分布式处理：假设我们有 `k` 个不同的计算节点，每个节点接收不同的流——或者等价地接收一个大型分布式流的某一部分。想要为这个大型隐式流构建草图的中心节点可以定期请求 `k` 个节点发送它们的草图，并将它们合并到自己的全局草图中。

对于 Morris 计数器，Cohen（[75] 第 7 节）提出了一种合并方法；它不像上述方法那样平凡，特别是正确性分析方面。
