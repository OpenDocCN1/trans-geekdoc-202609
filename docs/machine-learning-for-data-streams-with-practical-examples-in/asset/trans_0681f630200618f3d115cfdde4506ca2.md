

## 4.5.4 应用：计算图中的距离函数

让我们提及 Flajolet-Martin 计数器的一个非流式应用，以说明流式算法有时可用于提高非流式问题的时间或内存效率。

Boldi 等人 [47] 在 [192] 的基础上改进，提出了 HyperANF 计数器，它使用 HyperLogLog 来近似图的*邻域函数 N*。对于节点 *v* 和距离 *d*，*N*(*v,d*) 定义为从节点 *v* 出发，通过长度至多为 *d* 的路径可达的节点数量。该概率计数器允许在给定 *N*(*.,d*− 1) 值的情况下，以内存高效的方式近似计算 *N*(*.,d*)，并且只需对图的边进行一次顺序遍历，顺序为它们在磁盘上存储的任意顺序，即无需昂贵的磁盘随机访问。

我们给出实现此目的的直观解释。第一个关键观察是：如果一个顶点要么通过长度至多为 *d* − 1 的路径从 *v* 可达，要么通过长度至多为 *d* − 1 的路径从顶点 *u* 可达（其中 (*v,u*) 是一条边），那么它就通过长度至多为 *d* 的路径从 *v* 可达。第二个关键观察是 HyperLogLog 计数器是可合并的，这是一个我们将在第 4.8 节探讨的概念。这意味着，给定两个 HyperLogLog 计数器 *H*[*A*] 和 *H*[*B*]，它们分别由处理流 *A* 和 *B* 得到，存在一种方法获得一个新的 HyperLogLog 计数器 `merge(H[A], H[B])`，它与处理 *A* 和 *B* 的拼接 *C* 所得到的计数器完全相同。也就是说，它包含 *C* 中不同项目的数量。然后，假设归纳地我们已经为每个顶点 *v* 计算了一个 HyperLogLog 计数器 *H*[*d*−1](*v*)，它（近似地）计算距离 *v* 至多为 *d* − 1 的顶点数量，换句话说，近似 *N*(*v,d* − 1)。然后按如下方式计算 *H*[*d*](*v*)：

1.  *H*[*d*](*v*) ← *H*[*d*−1](*v*)。
2.  对每条边 (*v,u*)（按任意顺序）执行

```
H[d](v) ← merge(H[d](v), H[d-1](u))
```

根据上述第一个关键观察，显然如果计数是精确的，*H*[*d*](*v*) 等于 *N*(*v,d*)；由于近似导致的误差原则上可能随着 *d* 的增加而累积和放大，但 [47] 中的实验并未显示这种效应。一旦计算出 *H*[*d*]，我们就可以丢弃 *H*[*d*−1] 计数器，并重用它们占用的空间。因此，我们可以用 *d* 次边数据库的顺序扫描和 *O*(*n*log log *n*) 内存来近似距离 *d* 以内的邻域函数。

利用这一想法和大量巧妙的优化，Backstrom 等人 [21] 能够解决 Facebook 图中距离的估计问题，该图的节点是 Facebook 用户，边是他们直接的好友关系。该图拥有 7.21 亿用户和 690 亿条链接。值得注意的是，他们在单台机器上仅用几小时就完成了用户间平均距离的计算，结果为 4.74，对应 3.74 个中介或“分隔度”。非正式地说，这证实了 S. Milgram 在 1960 年代著名的实验 [177]，该实验使用实体信件和邮政服务，暗示当时世界上大多数人之间的分隔度不超过六度。

## 4.5.5 讨论：对数 vs. 线性

关于寻找不同元素算法的更多细节可参见 [176]，其中也提供了实证评估。它关注何时值得使用相对复杂的亚线性草图，而不是简单的线性计数。结论是，当需要极高精度时，例如低于 𝜖 = 10^(−4)，线性草图更可取。对数草图通常需要 *O*(1/*𝜖*²) 空间来实现乘法误差 𝜖，对于高精度要求来说，这确实可能很大。

在数据挖掘和机器学习应用中，通常可以接受相对较大的近似误差，例如 𝜖 = 10^(−1) 以内，因为挖掘出的模型是许多统计量的组合，单个统计量本身都不太关键，而且无论如何数据都被视为现实的随机样本。因此，对数空间草图可能是一个有吸引力的选择。

还值得一提的是，[144] 给出了一种更复杂、渐近最优的计算不同元素算法，使用 *O*(𝜖^(−2) + log *d*) 位，即去除了 HyperLogLog 中的 log log *d* 因子。对于实际用途，HyperLogLog 似乎仍然更快且更小。

# 4.6 频率问题

在许多情况下，我们不仅仅想计算流中所有项目的总数，而是分别计算流中不同类型项目的数量。在一般情况下，用亚线性内存估计所有项目的频率是不可能的，但通常只需获得最高频项目的近似计数即可。

对于流的长度为 *t* 的初始片段，项目 *x* 的*绝对频率*是它在该片段中出现的次数，其*相对频率*是绝对频率除以 *t*。我们主要考虑以下问题表述：

**重击者问题。** 给定阈值 𝜖 和对流的访问权限，在从流中读取任意数量的项目后，生成*重击者*集合，即所有相对频率超过 𝜖 的项目。

该问题与数据库领域计算*冰山查询* [97] 的问题密切相关。一个基本观察是：相对频率高于 𝜖 的项目最多只能有 1/*𝜖* 个；否则相对频率之和将超过 1，这是不可能的。

重击者问题的一个初步近似解是使用采样；例如，使用水库采样从流中抽取均匀样本，并始终声明样本中的频繁元素就是流中的频繁元素。这是一个有效的算法，但要达到任何固定的置信度，所需的样本量与 1/*𝜖*² 成正比。在本节中，我们将介绍三种重击者问题的算法，每种都有其自身的优势。第一种是基于计数器的确定性算法；另外两种基于哈希。

综述 [80, 164] 讨论并评估了我们将要介绍的算法及其他几种算法。

在本节中，我们以字（word）为单位衡量内存，假设一个项目、整数、指针等简单变量适合存放在一个内存字中。

## 4.6.1 SPACESAVING 草图

基于计数器的算法历史上是 Boyer 和 Moore [50] 方法的演变，该方法用于在多数元素（频率至少为 1/2 的元素）存在时找到它。Misra 和 Gries [179]、Demaine 等人 [86] 以及 Karp 等人 [145] 独立发现了该方法的一个改进版本。通常称为 FREQUENT，该方法仅用 *O*(1/*𝜖*) 内存就能找到一个保证包含所有 𝜖–重击者的元素列表。

FREQUENT 的一个缺点是它只提供重击者，而无法给出其频率的可靠估计，而频率估计通常很重要。其他提供频率近似值的基于计数器的草图包括 Lossy Counting 和 Sticky Sampling，均由 Manku 和 Motwani [165, 166] 提出，以及 Space Saving，由 Metwally 等人 [175] 提出。我们描述 Space Saving，据 [80, 161, 164] 报道，它在多种重击者算法中性能最好。此外，它简单直观，并对近似质量有严格的保证。
