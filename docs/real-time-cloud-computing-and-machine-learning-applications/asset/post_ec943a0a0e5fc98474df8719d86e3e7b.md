## 4.3.9.5. Programmatically Adding Data onto the Live Graph

- 1. After filling the onCreate() method with the necessary calls related to the live graph, methods in this section are entered inside the MainActivity.java class and therefore outside of onCreate(). The addEntry() method is responsible for adding a data point to the chart whenever called. This is performed inside the mRunnable thread described in Section 4.3.8. The call is made every second, just as printing the parameters String objects onto the layout. This method firstly uses a LineData object which verifies if the graph bears any unique value, as shown in Listing 4.36.

# Listing 4.36. Adding data to live graph every second

```
// Adding a value to the live monitor
private void addEntry(double var) {
// Getting the data, if any, from the graph
LineData data = chart.getData();
// If the graph contains previous data:
if (data != null) {
LineDataSet set = data.getDataByIndex(0);
if (set == null) {
set = SetData();
}
data.addDataSet(set);
}
// Adding data point to graph by setting x, y and index = 0
data.addEntry(new Entry(set.entryCount(), (float) var), 0);
data.notifyDataChanged();
// Notify the chart about its change of data
chart.notifyDataSetChanged();
// Set a fixed number of visible entries
chart.setVisibleXRangeMaximum(130);
// Set the focus on the last entry
chart.moveToX(data.entryCount());
}
```

- 2. This is followed by the SetData() method, which returns characteristics of the chart, of type LineDataSet whereby the printing options and colours of the graph are specified as shown in Listing 4.37.

```
// Setting printing options/colours
private LineDataSet SetDataSet() {
// Creating object to modify each data point:

return set;
}
```

The addEntry(Entry()) method on the LineData object, data, is filled with arguments according to the following syntax, which is further explained below.

data.addEntry(new Entry(x, y), yourDataSetIndex)

- newEntry() takes as input the x and y values that are to be printed on the graph.
- The second argument represents the index of the data set.

## 4.3.10. Performing Analytics Using Cloud Servlet or Local Server

This section describes the processes that occur when the user requests for a prediction or a classification to be made. As mentioned before, this takes place using the prediction.java class which basically, the prediction time and window size variables are firstly fetched from the prediction.xml layout whenever the user clicks on the “Predict” button, before creating a URL to query the servlet. When it comes to the “Classify” button, real-time values are fetched from MainActivity.java and are used to query the servlet, by appended to the servlet’s URL. This occurs when the user selects the “Cloudant” radio button.

However, when the “Local” option is selected, the local server, running on NetBeans is contacted via the specified IP address on the GUI using a client-server paradigm with the Socket class. To enable the local server to determine which type of analytics the Android application is requesting, a JSONObject variable is filled with integers from one to five, acting as request codes as Table 4.3. This allows the local server to perform the described functionality and thus return the corresponding response to the Android application.

# Table 4.3. Request codes for local Android analytics

| JSONObject requestCode | Functionality |
|---|---|
| 1 | Download to .csv by number of samples |
| 2 | Download to .csv by date |
| 3 | Prediction analytics |
| 4 | Classification using Wi-Fi parameters |
| 5 | Classification using LTE parameters |
