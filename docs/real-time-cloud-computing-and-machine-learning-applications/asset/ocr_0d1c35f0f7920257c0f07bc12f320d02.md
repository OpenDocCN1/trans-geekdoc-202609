Figure 2.114. Showing the URL mappings for the CalculateArea project.

Figure 2.115 shows the automatically generated code in the editor, for the CalculateAreaServlet, java class. As observed, it contains the constructor CalculateAreaServlet(), the doGet() and doPost() methods, as well as a notation on line 13, to indicate the previously entered URL mapping of this servlet. This means that the URL mapping can also be changed. If the server was configured to run on the localhost, it could then be accessed via the URL: http://localhost:8080/CalculateArea/ where the part before the / denotes the link for the project. Since the servlet will be launched on the IBM cloud platform it will have the URL: single servlet in the project, no other identifiers have been added after the /. Alternatively if there were two servlets, there could be two links for identifying the servlets for example: https://calcularea.eu-gb.myblueix.net/s1 and https://calcularea.eu-gb.myblueix.net/s2. These mappings would be made on line 13 for each Servlet in Figure 2.115 or at the time of creating each servlet in Figure 2.114. The purpose of the doGet() and doPost() methods are summarized as follows:

+   - doGet(): Parameters can be fetched from a plaintext URL where they are appended to the URL using particular notation normally as a query string ie. after the question mark character in the URL (?). They are then sent with the header information in the server itself. Most of the web servers support only a limited amount of information to be attached to the headers, the size of this header should not exceed 1024 bytes.
- doPost(): Parameters are sent separately. The number of parameters sent along a doPost()request is unlimited in contrast with the doGet() method which has limit of 1024 bytes.
