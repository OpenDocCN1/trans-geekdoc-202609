## 4.4.8.2. Finding Network Interface in Use

The Sigar library [16] works by making use of the following two classes integrated into the library which act upon the Sigar object, sigar which has been declared as a global variable.

- NetInterfaceStat: Getting statistics of the current interface.
- NetInterfaceConfig: Getting configuration information such as the hardware address, of the interface, passed.

The sig object is first used to retrieve a list of network interfaces present on the desktop PC via a loop. By iterating through the list, Listing 4.57 aims to identify the interface used for communication processes as download and upload. This is performed by comparing a String object, defined as "null", with the returned object from the getThwaddr() method which essentially returns the hardware address of the network interface. Therefore, an interface that is in use will not return "null". Moreover, since the process is ongoing, it is bounded by a loop set to true, which is an infinite loop.

# Listing 4.57. Finding the interface in use using the Sigar object

```java
// Initialising the Sigar object:
sigar = new Sigar();
while (true) {
  // Returns a list of available interfaces on the device:
  for (String ni : sigar.getInterfaceList()) {
```

## 4.4.8.3. Getting Initial Parameters

After identifying the currently communicating interface, the computations for fetching network data can be inserted in this specific statement. The NetInterface object, netStat is used along with the following methods:

- getRxBytes(): Returns the number of bytes received at the current time.
- getTxBytes(): Returns the number of bytes sent at the current time.
- getRxPackets(): Returns the number of packets received at the current time.
- getTxPackets(): Returns the number of packets sent at the current time.

These parameters are obtained using the same subtraction principles from the implementation on Android Studio whereby at a particular point in time, the number of data is retrieved using the above methods. The thread is paused for one second, after which the methods are called to get the amount of data one second later. The change can therefore be calculated. The below snippet, Listing 4.58 depicts how this operation takes place.

# Listing 4.58. Retrieving the network parameters

```java
// Get the download/upload speeds and as packets received/sent
currentDownload = netStat.getRxBytes(); // Number of bytes received currently
currentUpload = netStat.getTxBytes(); // Number of bytes sent currently
currentReceived = netStat.getRxPackets(); // Number of packets received currently
currentSent = netStat.getTxPackets(); // Number of packets sent currently
// Skipping the first set of values since it is not obtained directly, i.e. it can only be
obtained by subtraction
if (currentDownload != 0 || currentUpload != 0) {
    // Calculating change in sent by subtracting previous values
    dchange = currentDownload - previousDownload;
    uchange = currentUpload - previousUpload;
    rchange = currentReceived - previousReceived;
    schange = currentSent - previousSent;
    // Setting previous set of values to the current one allow for subsequent subtraction
at the next instant

    previousUpload = currentUpload;
```
