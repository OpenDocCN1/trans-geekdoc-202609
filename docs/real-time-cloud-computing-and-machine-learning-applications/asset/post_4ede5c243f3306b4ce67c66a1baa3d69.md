## 4.4.6. Creating Live Monitor Layout

With JFreeChart imported, the live monitor can now be integrated into the project. Since it is ideal for the graph to appear upon running the application, the codes for creating the layout of the chart are added into the constructor of the netmonitor.java class. This is because constructor methods are called when an object of the class is created, i.e., when it runs. This is also the method where GUI objects are practised and automatically inserted onto the JFrame using the initComponents() method. The constructor bears the same name as the class and therefore, the method that creates the graph is added just after the initialisation of the components as shown in Listing 4.53.

### Listing 4.53. Populating the constructor of netmonitor.java

```java
public netmonitor() {
    // Initialise all components and set them onto the GUI
    initComponents();
    // Method to programmatically create an area for the graph
    createGraphSpace();
    // Disable the toggle for pushing to cloud temporarily
    cloud.setEnabled(false);
    // Setting the focus on the Start button
    startMonitoring.requestFocus();
}
```

As observed above, the toggle for sending the data to the cloud is disabled upon start-up for the same reasons described for the Android phone in Section 4.3.5, i.e., to firstly able to retrieve the index of the last set of values stored on the Cloud database. This is such that the next set of values can take the successive index so that they can be easily retrieved for analytics. To create the graph space the createGraphSpace() method is described in netmonitor.java as follows as a public method.

### Listing 4.54. Creating the space for the live graph

```java
public void createGraphSpace() {
    // Creating a series called "Parameter" to hold data items
    series = new XYSeries("Parameter");
    // Passing the series created into a particular dataset
    XYSeriesCollection dataset = new XYSeriesCollection(series);
    // Initialising the FreeChart variable and passing the dataset
    chart = ChartFactory.createChart("Press button to start monitoring!", "Time (seconds)", "Value", dataset);

    // Creating a chartObject to hold the created chart
    final ChartPanel chartPanel = new ChartPanel(chart);
    // Setting the dimensions manually for the panel
    chartPanel.setPreferredSize(new Dimension(575, 390));
    // Enabling mouse wheel support for the panel
    chartPanel.setMouseWheelEnabled(true);

    // Creating a JPanel which can hold the chartPanel
    JPanel panel = new JPanel();
    // Setting the positioning of the panel onto the JFrame
    panel.setBounds(475, 25, 402);
    // Adding the chart to the JPanel
    panel.add(chartPanel);
    // Adding the chart to a JPanel, which mounts onto the existing JFrame
    add(panel);
}
```

## 4.4.7. Retrieving the Last Index from the Cloud

This section implements the same principles explained for the Android phone, in Section 4.3.5. This means that a connection is first made to the Cloud database, with the values retrieved using a String specified in MongoDB. The last index is obtained and stored. The same block of code can then be used except for the database used since the parameters have the same names. The database created as per Section 4.5, "laptopcloudparameters." The whole process is implemented using a thread since this is performed simultaneously alongside the monitoring process. The thread is thus defined as getNumberOfItems and is implemented as shown in Listing 4.55.

### Listing 4.55. Thread to retrieve the last index from the cloud

```java
// Retrieving the last index of records on the cloud
private Runnable getNumberOfItems = new Runnable() {
    public void run() {
        // Making connection to cloud database
        System.err.println("Making connection to cloud to retrieve number of elements...");
        try {
            // Creating new connection to Cloud Server with
            // the URL of the endpoint
            Client client = ClientBuilder.url(new URL("https://811bf82-4f01-4173-be30-7fe6ffb8e7d7-bluemix.cloud.com/"))
                .username("apikey-5c23ef26874d46cab69a1ca350c71a5") // Setting the username for the client connection
                .password("a82c1648eddef219d777ae070402f86acbdcf9a6") // Setting the password for the client connection
                .build(); // CloudClient based on the endpoint used to construct the client builder along with the set options
            System.err.println("Successful connection made to cloud...");
        } catch (IOException e) {
            System.err.println("Error accessing cloud: " + e);
        }

        // Access the database for cloud parameters:
        Database db = client.database("laptopcloudparameters", false);
        System.err.println("Trying to read all records from database...");
        // Query to retrieve all Keys in descending order:
        String query = "{\"Key\":\"$gt:0},\"sort\":{\"Key\":\"desc\"}}";
        // Making query with QueryResult:
        QueryResult<LinkedTreeMap> queryResult = (QueryResult<LinkedTreeMap>)db.query(query, LinkedTreeMap.class);
        // Getting the result in a List:
        List<LinkedTreeMap> resultList = queryResult.getDocs();

        if (resultList.size() > 0) {
            // Getting the first Key value from the list
            numberOfItems = (double) resultList.get(0).get("Key");
        } else {
            // Setting the number of items to 0 if the database is empty
            numberOfItems = 0.0;
            System.err.println("Number of documents in database is: " + numberOfItems);
            // Following record must have (last + 1) as its key
            idx = (int) numberOfItems + 1;
            System.err.println("Setting index of new record to: " + idx);
            // Enabling the toggle/switch to be clicked after successful fetching
            cloudSwitch.setEnabled(true);
        }
    } catch (Exception e) {
        System.err.println("Problem fetching number of items: " + e.toString());
        numberOfItems = 0.0;
    }
    }
};
```

## 4.4.8. Start Button

This is the button that starts the monitoring process and its functions can be summarised by the following points:

- 1. Fetch the last index from the cloud, i.e., calling the getNumberOfItems thread from Listing 4.55.
- 2. Start a new thread simultaneously for retrieving parameters.
- 3. Fetch the initial number of bytes/packets received and sent by the interface.
- 4. Pause the every second.
- 5. Fetch the final number of bytes/packets received and sent by the interface.
- 6. Calculate the change in these parameters over one second.
- 7. Update the GUI with the calculated values.
- 8. Add the points onto the live graph.
- 9. Push to Local Server if the toggle is enabled.
- 10. Push to Cloudant database if the toggle is enabled.

To add the code for any button, the latter is right-clicked on the GUI and the actionPerformed event is selected as reflected in Figure 4.67. This takes the user to the block code for this specific button.
