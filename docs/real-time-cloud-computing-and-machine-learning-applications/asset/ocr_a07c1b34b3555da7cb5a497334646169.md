# 4.3.6.1. Initialising Components

The aforementioned components declared in the MainActivity.java class and in the XML files are linked through the process of initialisation, which essentially retrieves the components in the UI and can be interacted with programmatically. This is the first operation performed inside the onCreate().

# List 4.17. Initialising components in onCreate() for MainActivity

```
// Mapping the variables to their corresponding layout objects:
ipaddress = findViewById(R.id.EDT1); // Variable to hold the IP address
cloudSwitch = findViewById(R.id.cloudSwitch); // Variable to get the cloud switch
monitorButton = findViewById(R.id.monitorButton); // Variable for monitor button
stopButton = findViewById(R.id.stopButton); // Variable for stop button
algoButton = findViewById(R.id.algo); // Variable for analytics menu
downloadButton = findViewById(R.id.downloadButton); // Variable for download
RX = findViewById(R.id.textView1); // Variable to hold Wi-Fi download speed
TX = findViewById(R.id.textView2); // Variable to hold Wi-Fi upload speed
RXP = findViewById(R.id.textView3); // Variable to hold number of packets received
TXP = findViewById(R.id.textView4); // Variable to hold number of packets sent
WiFiSig = findViewById(R.id.textView5); // Variable to hold Wi-Fi signal in dB
MRX = findViewById(R.id.textView6); // Variable to hold LTE download speed
MTX = findViewById(R.id.textView7); // Variable to hold LTE upload speed
cloudSwitch.setClickable(false); // Temporarily disabling switch upon startup
```

Since the application also contains an option to directly send data to the Cloudant database without passing through the local server on, the database first needs to be queried to retrieve the index of the last registered on it. This is that the next record has the successive index and thus data are registered in sequential order. In turn, it eases the process of parameter retrieval from the cloud since this index is based in the query just before performing analytics. To allocate time for this request to the cloud, the switch is first unavailable when the monitoring process is started. Therefore, upon clicking the "monitor" button, the request is made and the switch is temporarily unavailable until the last index is fetched. Upon obtaining the result, the toggle is made accessible to the user. This is why the setClickable(false) method is used with the Switch object in the snippet listed in 4.17.
