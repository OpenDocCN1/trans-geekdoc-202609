## 4.2. COMPLETE SYSTEM MODEL OF THE NETWORK ANALYTICS SYSTEM

As aforementioned, the aim of the software in Chapters 4 and 5 are related to the classification of real-time network parameters to determine the status of a device which can be "idle," "browsing" or "streaming." Furthermore, the number of packets received at a desired point in time is predicted using regression algorithms. This section gives a brief description of the components that make up the backbone and architecture of the system.

In this system, five user interfaces are designed such that the end-user has the ability to:

- 1. Monitor real-time network parameters on Android and Desktop applications, further referred to as edge devices.
- 2. Perform classification and regression analytics based on the recorded real-time values.
- 3. Download stored values into .csv files.
- 4. Perform functions 1, 2 and 3 on hosted web interfaces as an alternative to the edge devices.
- 5. Perform functions 1, 2 and 3 on a local server.

The described functionalities are coded such that both local and cloud computations are possible and are thus independent. The user has the flexibility of hosting the whole architecture on an online cloud platform as IBM Cloud, or on local Java-capable HTTP servers such as Apache Tomcat, paired with MySQL databases such as XAMPP. The components outlined are further described in the following sections.

- i. Mobile and Desktop Applications
The Android and Desktop applications are considered as the edge devices for live data capture and monitoring. With a graph illustrating the variation of real-time variables with respect to time, the devices are used to visually analyse the behaviour of network and Internet traffic for various parameters. On the same wavelength, the applications are capable of performing classification and regression analytics as well as the downloading functionalities aforementioned, by sending requests to the hosted servlet or the local server.

- ii. Local Server
The local server, built using the NetBeans IDE acts as the heart of the program, bringing in all the other components together whereby it provides architectures to manage monitoring activities from both edge devices. It can push the recorded values from the latter to a Cloudant database or a local one running on localhost. This renders the application versatile in the sense that the system can be easily hosted on either platform. The analytics and downloading functionalities are also available.

- iii. Web Application
Created as web interfaces using HTML and JavaScript, separate web pages are available for both Android and Desktop clients where the monitors fetch values every five seconds from either the Cloudant database or a local one. With the ability to choose from a cloud or locally hosted servlet, analytics and downloading capabilities are possible by connecting to either the Cloudant or local databases to serve the web pages.

- iv. Databases
To store the parameters fetched by the edge devices, databases are created on IBM Cloud Cloudant services as well as on phpMyAdmin using XAMPP. These databases are filled upon request from the edge devices which are coded with the necessary credentials for access. They are then accessed from the edge devices, local server, web applications as well as servlets for analytics and downloading services.

- v. Servlets
The functionalities of the local server are hosted using the Eclipse IDE such that the edge devices, as well as the web applications, can contact either a cloud or local servlet.

In this chapter, only the data capture and client architecture components, i.e., the Mobile and Desktop applications will be developed. The configurations made for the cloud databases are also elaborated. Chapter 5 focuses on the local server implementation as well as the ML algorithms used for the analytics. The development of the web pages and the hosting of the local and cloud servlets, is then also detailed.

## 4.3. MOBILE APPLICATION FOR NETWORK DATA CAPTURE AND ANALYTICS

Used as an edge device in the architecture of the system, a mobile application is developed to capture network parameters that can help optimise networks and perform analytics with algorithms for classification and prediction. With thumping rise in the use of mobile phones throughout the last decade, the Android phone is one of the most owned and used devices in the present mobile operating system market worldwide. This gives rise to the fact that it can easily be employed as the source for network variables which would, in turn, open the door to analytics on the usage of various applications on the Android phone.

To begin with, the network parameters to be used in the algorithms need to be retrieved or calculated through the use of the two classes whose functionalities are defined next.

- 1. TrafficStats: It is a class that includes methods aimed towards providing traffic statistics such as the number of bytes transmitted and received at a particular point in time concerning all interfaces available on the device as well as application-wise, i.e., by a unique user ID (UID). Once obtained, these variables can be exploited to calculate network speeds by adding a time factor. The full documentation can be found in [8].

- 2. WiFi: Since this application also monitors the signal related to Wi-Fi connectivity, this provides an in-depth outlook information around configured networks, which one is best to connect to, enabling/disabling connectivity and thus dynamic information when it comes to the state of the connected network. The full description of the class is available in [9].

The parameters that are investigated and extracted from the above classes and therefore monitored in the Android application are as follows:

- Wi-Fi download speed in Kbps
- Wi-Fi upload speed in Kbps
- LTE download speed in Kbps
- LTE upload speed in Kbps
- Number of packets received per second
- Number of packets sent per second
- Wi-Fi signal strength in dB

This section, therefore, entails the breakdown of the Android software designed to listen for changes in network behaviour every second after which the captured data are either pushed to a local server running on a PC or to a cloud database on IBM Cloud. Another functionality relates to the downloading capability of a set of values in .csv file, by specifying the number of samples or a particular date. On the same wavelength, analytics can be made by triggering the hosted servlet, or the local server application on NetBeans IDE. Both the layouts and the back-end architecture, i.e., how the parameters are acquired, are detailed in this section.
