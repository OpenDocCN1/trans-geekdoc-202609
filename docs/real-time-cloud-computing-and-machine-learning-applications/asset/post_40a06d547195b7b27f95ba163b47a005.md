## # 4.3.7. Getting Network Parameters

This section involves codes that are defined in MainActivity.java and pertain to the fetching of network data for this application. The following methods are created:

- - getTotalSpeeds(): Finding the total download and upload speeds consist of a combination of traffic from the Wi-Fi as well as mobile data, in kilobytes per second (kB/s).
- - getMobileSpeeds(): Calculating the mobile/cellular download and upload speeds, in kilobytes per second (kB/s).
- - getPackets(): Getting the number of packets sent and received per second.
- - getWifiSignalStrength(): Obtaining the Wi-Fi signal strength every second, in dB.

When it comes to fetching network data, the following methods from the TrafficStats class, are used to retrieve network parameters:

- - getTotalRxBytes(): Returns the number of bytes received since the last device boot.
- - getTotalTxBytes(): Returns the number of bytes sent since the last device boot.
- - getTotalRxPackets(): Returns the number of packets received since the last device boot.
- - getTotalTxPackets(): Returns the number of packets sent since the last device boot.

## # 4.3.7.1. Getting Speed Data

To find the download speed at a particular point in time, the number of currently downloaded bytes is used to subtract the previously stored number of bytes, which is preceded by exactly one second, as previously specified by the Handler, divided by the number of seconds. This is shown in Equation 4.1.

| Current number of bytes - Previous number of bytes | |
| :--- | :--- |
| Download Speed = (kB/s) | (4.1) |
| 1 second | |

This means that to get any speed, it only suffices to subtract the previous number of bytes from the current one. With the appropriate conversion to kilobytes per second (KB/s) through a division by 1000 ms, the calculation of the speeds of four variables is performed the same way. These are the download upload speeds as well as the cellular/mobile download and upload speeds. Listing 4.23 gives the codes for these functions.

# Listing 4.23. Getting speed data

```java
// Getting total download and upload speed, which give the Wi-Fi parameters when Wi-Fi is in use
public void getTotalSpeeds() {
    // Getting the Wi-Fi parameters when Wi-Fi is in use
    totalSpeeds = (currentRxBytes - previousRxBytes) / 1000;
    totalSpeeds = (currentTxBytes - previousTxBytes) / 1000;
}
```

## # 4.3.7.3. Getting Wi-Fi Data

The Wi-Fi signal strength of the network that the Android phone is connected to, is obtained every second as well, by making use of the WifiManager class aforementioned, to call getConnectionInfo() method which paves the way to dynamic information about the network. This information is then exploited using the getRSSI() method to get the Received Signal Indication (RSSI), in dB. This is perceived as the power being received from the modem/router. This is shown in Listing 4.25.

# Listing 4.25. Getting Wi-Fi data

```java
// Getting Wi-Fi signal strength in dB
public void getWifiSignalStrength() {
    // Declaring the WifiManager object
    WifiManager WMG = (WifiManager)getApplication().getSystemService(Context.WIFI_SERVICE);
    // Getting the RSSI value in dB
    WIFI_RSSI = WMG.getConnectionInfo().getRSSI();
}
```

## # 4.3.8. Building the Main Thread

As mentioned before, two different classes are used to obtain the parameters. They are the WifiManager and TrafficStats classes. The heart of this program, however, i.e., the logic that brings it all together is the mRunnable thread implemented and mentioned previously, that makes use of a Handler object, mHandler object is fully chosen for this operation since it provides the best choice of liaising the main thread with the background thread. Android favours the user of a Handler since other threads are not allowed to communicate directly with the UI. The layout can thus be updated while the thread keeps running in the background. As a result, safer fetching and printing process is ensured.
