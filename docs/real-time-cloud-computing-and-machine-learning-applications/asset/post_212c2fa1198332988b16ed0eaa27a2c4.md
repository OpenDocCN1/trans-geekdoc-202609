## 6.2. COMPLETE SYSTEM MODEL OF THE WEATHER FORECASTING SYSTEM

This section discusses the complete system of the weather forecasting system. Figure 6.1 shows a diagram detailing the data flow in the entire system.

![](img/2b52fde0e707e8c2f05a10309c3f8982_593_0.png)

Figure 6.1. System Data Flow.

### 6.2.1. MySQL Database

To store the incoming data from the mobile and desktop applications locally, a MySQL database was used. The local database is used to perform prediction locally on the local server without the need to contact the cloud-hosted servlet. More details are given on the MySQL database in Section 7.1.5 in chapter 7.

### 6.2.2. Local Server

The local server is responsible for the following functions:

- 1. Displays a live graph that monitors the current weather conditions.
- 2. Accepts incoming data from mobile and desktop applications and stores them either locally or on the Cloudant platform.
- 3. Performs prediction locally and displays the result to the client.
- 4. Download requested data from either the local server or Cloudant platform.
- 5. Serves request for data or analytics result from the mobile and desktop clients. The local server is explained in more detail in section 7.1 of chapter 7.

### 6.2.3. Mobile and Desktop Application

This block represents the mobile and desktop application responsible for collecting data from the OpenWeather API and sending it to either the Cloudant database or a local server. The local server stores the data in a MySQL database. The mobile and desktop applications can also request data for download from either the local server or directly from the Cloudant database. The mobile client is explained in detail in Section 6.4 and the desktop application is explained in detail in Section 6.3.

### 6.2.4. Cloudant Database

The Cloudant database is a service offered by the IBM cloud platform. It is used in the system to store weather data in the cloud so that the data is accessible globally. Section 6.6 describes how to set up the Cloudant database. Section 6.3.30 to 6.3.33 describes the “DataRetriever” class which is responsible for communicating with the Cloudant database.

### 6.2.5. Cloud Hosted Servlet

The cloud-hosted servlet main function is to serve requests coming from users that visit the webpage. The servlet is responsible for the following functions:

- 1. Updating the live graph on the webpage presented to the user
- 2. Serving requested weather data to the user by fetching data from the Cloudant database
- 3. Performing analytics and returning the result to the user.

More information is given in section 7.4 of chapter 7 that details how the servlet works.

### 6.2.6. Locally Hosted Servlet

The locally hosted servlet performs the same functions as the cloud-hosted servlet except of being hosted on the IBM Cloud platform, it is hosted locally on an Apache Tomcat server. The user must enter the IP Address of the server to be able to connect to the servlet. More details are given in section 7.4 of chapter 7.

### 6.2.7. Web Application

The web application is a webpage that is displayed to the user when they visit the servlet link. The webpage provides a graph that displays the variation of the weather parameters in real-time. The user can also download weather data for a specific date or only the last N readings. The page is also responsible for contacting the servlet for analytics results and displaying it to the server. More details can be obtained in section 7.5 of chapter 7.
