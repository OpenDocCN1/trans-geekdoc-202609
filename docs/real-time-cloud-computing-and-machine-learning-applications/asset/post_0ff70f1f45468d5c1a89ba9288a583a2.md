## 4.5.2. Adding Index to the Database

When pushing data into the IBM cloud, a particular set of values has an automatically-generated index attached to it however does not provide useful ordering and causes the database to store data randomly. Since data pushed by the edge devices are time-related as well as time-sensitive, a particular selector must be manually added such that it can be used upon query to return data in the desired order. The “Key” chosen to represent this selector, is used to push data to the Cloudant database in ascending order and can be used for functions such as determining the number of items in the database, which, in turn, be the highest “Key” value. The table generated based on CouchDB, is mainly used in big data whereby records are stored in serialized (JSON) manner. The following procedure is followed to add selector to the database:

- 1. The “Query” tab is accessed from the Dashboard. In this window, “manage indexes” is selected.

![](img/2b52fde0e707e8c2f05a10309c3f8982_415_0.png)

Figure 4.94. Managing indexes.

- 2. The index is modified as in Figure 4.95 such that the “foo” keyword is changed to the “Key” one. Both “fields” and “name” tags are changed.

```json
{
  "index": {
    "fields": [
      "foo"
    ],
  },
  "name": "foo-index",
  "type": "json"
}
```
Figure 4.95. Original index.

- 3. The “Create index” button is then pressed. This allows a sorting index to be created, it is also stored in the table alongside the values but does not affect the stored parameters since the database has no specific format, i.e., it ultimately a NoSQL database.

```json
{
  "index": {
    "fields": [
      "Key"
    ]
  },
  "name": "Key",
  "type": "json"
}
```
Figure 4.96. Modified index.

![](img/2b52fde0e707e8c2f05a10309c3f8982_416_0.png)

Figure 4.97. Creating the index.

- 4. Finally, a query can be added depending on the parameters stored in the database, such that it yields the results in table-like manner, as well as in ascending order. This is shown in Figure 4.98. The “gte” tag represents “>” which is the syntax the selector uses for fetching.

```json
{
  "selector": {
    "Key": {
      "$gte": 0
    }
  },
  "fields": [
    "Key",
    "DownloadSpeed",
    "UploadSpeed",
    "PacketsReceived",
    "PacketsSent",
    "Timestamp"
  ],
  "sort": [
    "Key": "asc"
  ]
}
```
Figure 4.98. Querying the database, after filling the database.
