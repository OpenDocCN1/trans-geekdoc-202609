## Chapter 1.5: Sessions and Cookies

![](img/a893312ec68b8170fe567f785e95c06e_58_0.png)

HTTP, which forms the foundation of the Web, is not a session-oriented protocol. This means that Web servers cannot determine whether the client accessed the server previously or visited specific pages. Any image or content from the site can be downloaded without downloading other images or content. Consequently, if the user has been authorized to access one page, he or she will have to be authorized to access another page. To achieve this, the user will have to supply the password again. This situation is inconvenient for large applications. As a result, cookies and sessions were introduced.

Cookies are small text files stored on the client computer. When the user tries to access the server that has installed the cookie, the client's browser sends an HTTP header, according to which the server determines that it installed the cookie previously. The cookie files store variable names and, as well as the term of validity for the cookie. This term might range from several seconds to years. The session cookie is stored in the browser's memory instead of the client's hard disk.

Sessions are also small text files; however, they are stored on the server. Only a unique SID is sent to the client. Thus, data never leaves the server, and the server exchanges only the SID with the client. SID validity is limited either by the browser operation time or by the server settings.
