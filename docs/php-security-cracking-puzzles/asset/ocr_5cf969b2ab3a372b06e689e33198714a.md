# II.4.2. SQL Injection into a Numeric Parameter

The code in Listing I.4.3 is vulnerable to an SQL injection because the
GET id_user parameter is not checked for invalid characters.

Consequently, any text string can be supplied as the value for the id_user
parameter in the SELECT * FROM userslist WHERE id_user = 1 query instead
of the expected numeric value. Thus, setting the value of the id user parameter
to some 'some%20text' will make the script issue an error message (Fig. II.4.1), because
an attempt to execute the following query will be made:

```
SELECT * FROM userslist WHERE id_user = 'some text'
```
