To execute multiple SQL queries from the database dump, the contents of the catalog.sql file are read and broken into individual queries using the #;[\s]*\r\n#is regular expression (Listing II.4.39). In a properly performed MySQL database dump, each query is terminated with a semicolon.

+ Listing II.4.39. Downloading data from a database dump

```php
<?php
// Connecting to the database
include "config.php";
// The name of the file with the SQL instructions
$filename = "catalog.sql";
// Opening the instruction file
// and reading it into a buffer
$fp = fopen($filename, "r");
$contents = fread($fp, filesize($filename));
fclose($fp);
// Breaking the file's contents
// at the semicolon boundaries
$quer = preg_split("#;\\s]*\r\n#is", $contents);
// Executing the SQL queries
foreach($quer as $query) {
    if(!$mysql_query($query)) exit(mysql_error());
}
?>
```

### II.5.1. Online Users

HTTP doesn't allow users to establish sessions; consequently, it doesn't allow you to trace the time interval, during which a specific visitor worked with a Web resource. The only thing that could be traced is the time, during which the client accessed the server resources. After this, the visitor can spend several hours reading the loaded page — the Web server won't be able to determine when the visitor stopped working with loaded resources. Therefore, a visitor is considered to leave a specific Web resource if 20 minutes have elapsed since the visitor last loaded a page.

To register the times of visitors' access to resource pages, it is necessary to create a session table in the MySQL database that would store user names and when they last accessed resource pages (Listing II.5.1).

Listing II.5.1. The session table

```sql
CREATE TABLE session (
  id_session tinytext NOT NULL,
  putdate datetime NOT NULL default '0000-00-00 00:00:00',
  user tinytext NOT NULL
) TYPE = MyISAM;
```

This table is made up of three fields:

- id_session — Session identifier
- putdate — Time, at which the visitor last accessed the site's pages
- user — User name

To register currently active visitors, it is necessary to create the script presented in Listing II.5.2.

## II.5.2. Custom Sessions

The custom sessions mechanism can be implemented by registering handlers using the `session_set_save_handler()` function, which has the following syntax:

```
session_set_save_handler(open, close, read, write, destroy, gc);
```

The function accepts six string arguments, which are the names of handler functions. These names have the following meanings:

- open The method that executes at session initialization in the client code by applying the `session_start()` function. The code for establishing the database connection must be placed here.
- close: The method that terminates operations. The code that terminates the database connection will be placed here.
- read: The method that retrieves the data for the current session from the database.
- write: The method that inserts a new record into the database table, provided that this is the first attempt at accessing the session updates the record corresponding to the string.
- destroy: The method that obliterates the session. The code placed here will obliterate the record corresponding to the specified current session.
- gc: The method that collects the garbage. It removes old records that have lost their importance.

The data will be stored in the session table, which has the following fields:

- id_session — Primary key of the table with the AUTO_INCREMENT attribute
- session — Unique session identifier
- putdate — Date, on which the session was last accessed
- value — Session value (array packed using the serialize() function)
