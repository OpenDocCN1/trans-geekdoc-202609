# II.4.5. User Deletion and SQL Injections

The vulnerability in this problem is similar to the vulnerability in the previous one: User-supplied data are not sanitized when used in SQL requests. However, the UNION construction cannot be used to exploit this vulnerability, because it only works with SELECT queries. Here, changing the logic of the WHERE construction will do the trick. An SQL query to delete a user looks as shown in Listing II.4.17.

Listing II.4.17. An SQL query to delete a user

```
DELETE FROM userslist
WHERE pass = 'password' AND
name = 'name'
```

The injection query can be passed using the password or user name by replacing the chosen parameter's value with the string ' OR 1 = '1'.

Listing II.4.18. The injection query

```
DELETE FROM userslist
WHERE pass = 'password' AND
name = '' OR 1 = '1'
```

The WHERE condition doctored in this way always returns true, deleting all records from the userslist (Fig. II.4.11).
