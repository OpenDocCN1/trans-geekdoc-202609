## II.7.8. Protecting User Names

Assume that user names are stored in a field named name in a table named authors. The task is to check whether a name is already used or is similar to already-registered user names. This problem can be solved using the script shown in Listing II.7.16.

- The name of the new user matches one in the authors table after all English letters in the name are replaced with Russian ones.
- The name of the new user matches one in the authors table after all Russian letters in the name are replaced with English ones.

If none of these conditions is met, the new user name is unique to the system and is added to the authors table.

## II.7.9. Session-Based Authorization

If the number of records in the database meeting the login and password criteria is greater than zero, the user is allowed to enter the system: The login and password are stored in a session. The bug in the registration system is that the number of records is stored in the temporary variable $total, which is not initialized. If the register_globals directive in the php.ini configuration file is set to On, it is possible to pass a value directly to the variable using the POST or GET method. This means that all that must be done to enter the system is the value of the total parameter in the URL must be set to 1 (i.e., http://www.mysite.ru/1.php?total=1), the password field must be left blank, and any registered name must be entered into the name field (Fig. II.7.12). The password field must be left empty to keep triggering the if(empty($_POST['name']) && empty($_POST['password'])) check, whose execution will rewrite the $total variable.

![](img/a893312ec68b8170fe567f785e95c06e_301_0.png)

The vulnerability in this example is easy to see. In real-life registration systems, the code is much crafter and vulnerabilities are less obvious.

![](img/a893312ec68b8170fe567f785e95c06e_301_1.png)

Fig. II.7.12. Bypassing session-based authorization

Verifying the complete set of parameters is passed using the GET method is not the best solution, because the total parameter can also be passed using the POST method or even in a cookie. An effective solution would be to set the value of the register_globals variable in the php.ini configuration file or in the .htaccess file to Off(register_globals off and php_flag register_globals off, respectively).

However, these configuration files are not always accessible to site owners on rented servers; therefore, the most appropriate solution is to correct the code itself. This can be done by getting rid of the $total variable, as shown in Listing II.7.17.
