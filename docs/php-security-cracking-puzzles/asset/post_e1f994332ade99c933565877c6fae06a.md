This sequence of actions will assign the PHP Script Interpreter<sup>1</sup> as the interpreter for PHP files (Fig. II.14.4). Now PHP scripts will act like regular executables and can be launched by pressing the <Enter> key or double-clicking the selected file.

Now when the script is triggered by the system as a regular executable it can be launched by cron at the scheduled time. Tasks for execution are scheduled by editing the crontab configuration file.

In Windows, the crontab file can be found in the C:\Program Files directory; in UNIX, it is usually located in the \etc directory. For more detailed information regarding the UNIX crontab file, consult the documentation for the specific operating system.

![](img/a893312ec68b8170fe567f785e95c06e_382_0.png)

Each line in the crontab file describes one scheduled task. In addition to the task lines, the file can contain comments, which start with the pound sign (#). The task line format is the following:

```
minutes day_of_month day_of_week command
```

The parameters can take on the following values:

- minutes—0–59
- hours—0–23
- day_of_month — 1–31
- month — 1–12
- day_of_week — 0–7 (0 and 7 denote Sunday)
- command — The command to be executed, for example, d:/main/reserve.php

The parameters are delimited by a space. The asterisk given as a parameter value denotes the entire range for the particular parameter. For example, consider the following task directive:

```
0 23 * * d:/main/reserve.php
```

It specifies launching the d:/main/reserve.php script every day at 23:00. Several for each parameter can be specified if they are delimited with a comma, Thus, you can have the following task directive:

```
0 8,16 * * d:/main/cleanup.php
```

It specifies that the d:/main/cleanup.php script will be launched every day at 00:00, 8:00, and 16:00.

> ¹ It is possible that the command line interpreter (CLI) will be assigned as the PHP interpreter.

As already mentioned, spaces are used to delimit the parameters; consequently, no spaces are allowed after commas. Thus, the 0 0, 8, 16 * * d:/main/cleanup.php task directive is wrong.

![](img/a893312ec68b8170fe567f785e95c06e_383_0.png)

As another example, consider this task directive:
0,30 18-23 * * * /home/root/check.php

It will run the /home/root/check.php script every half hour between 18:00 and 23:00.

And consider the following task directive:
0/10 * * * /home/root/log.php

It will launch the /home/root/log.php script every ten minutes. The latter operating mode is the most suitable for verifying the link's presence on a remote site.

Host providers do not approve of frequent script executions. Therefore, before scheduling tasks, you should consult the technical support of your host provider regarding any limitations on how many scripts can run and how often.

# II.14.2. Verifying Link Validity

It is not necessary to load the entire document server pointed to by a link to verify that the given link is valid. Instead, inspect only the Web server's reply to the request for the given page. This is because loading a significant number of pages may take considerable time. Create an intermediate function named get_code(). The function accepts two parameters: $hostname and $path, the path to the page relative to the root site. It returns the Web server's reply.

# Listing II.14.5. The get_code() function

```php
<?php
function get_code($hostname, $path) {
  $fp = fsockopen($hostname, 80, $errno, $errstr, 30);
  if (!$fp) {
    // Verifying
    return $errstr;
  }
} else {
    // Constructing the HTTP request
    $headers = "GET $path HTTP/1.1\r\n";
    $headers .= "Host: $hostname\r\n";
    $headers .= "Connection: Close\r\n";
    // Sending to the server
    fwrite($fp, $headers);
    $line = fgets($fp, 1024);
    fclose($fp);
    return $line;
  }
}
```

# Listing II.14.6. Calling get_code()

```php
<?php
// Breaking the contents of the
// file into $links array. Each element of the
// array holds a single line.
$links = file("link");

$fd = fopen("link.log", "a");
if ($fd) {
    foreach ($links as $link) {
        $link = trim($link);
        $arr = parse_url($link);
        $code = get_code($arr['host'], $arr['path']);
        $str = date("d.M.Y H:i:s").": ".trim($code)."$link\r\n";
        fwrite($fd, $str);
    }
    fclose($fd);
}
?>
```

# II.14.3. Watching for New Files

The best way to traverse a directory and its subdirectories is to recursively descend the directory tree. This will be done using the scan_dir() function, which extracts the contents of the current directory and displays the names of files created or modified during the current day. The creation or last modification time of the scripts is checked using the filetime() function. If a function encounters a subdirectory, it calls itself recursively, passing the subdirectory as the argument. Listing II.14.8 shows a script recursively descending the subdirectories in the root catalog of system.

# II.14.8. The script for recursively traversing subdirectories

```php
<?php
// The directory name
$dirname = ".";
// Calling the function that recursively descends
// the subdirectories of the root directory
scan_dir($dirname);

function scan_dir($dirname)
{
    // Opening the current directory
    $dir = opendir($dirname);
    // A loop to read the current directory
    while (($file = readdir($dir)) !== false)
    {
        if ($file == "." || $file == "..") continue;
        if (is_dir($dirname . "/" . $file)) {
            scan_dir($dirname . "/" . $file);
        } else {
            // Process file
        }
    }
    closedir($dir);
}
?>
```
