### Listing II.9.1. Connecting to an FTP server

```php
<?php
// The FTP server's address
$ftp_server = "ftp.server.ru";
// The user name
$ftp_user = "user";
// The password
$ftp_password = "password";
// Setting the script's timeout to 120 seconds
set_time_limit(120);
// Attempting to connect to the FTP server
$link = ftp_connect($ftp_server);
if (!$link) echo("Failure to open a connection to $ftp_server FTP server");
// Registering on the server
$login = ftp_login($link, $ftp_user, $ftp_password);
if (!$login) echo("Failure logging onto the server.
Please check the login data.");

?>
```

The values of the variables $ftp_server, $ftp_user, and $ftp_password are set to the address of the FTP server, user name, and password, respectively.

For further FTP work, the code in Listing II.9.1 may be placed into a separate file named, for example, config.php. The file is then included in scripts with the help of the include instruction. Thus, you avoid writing out the connection code in each script.

### II.9.2. Listing FTP Server Files

A list of the files and subdirectories in the current directory can be obtained with the help of the $ftp_rawlist() function (Listing II.9.3). Its general syntax is the following:

```php
array $ftp_rawlist(resource link, string directory)
```

The function accepts a link identifier as the first parameter and the path to the directory as the second parameter. It returns an array of strings, each of which contains information about a subdirectory or a file.

### Listing II.9.3. Listing files and subdirectories

```php
<?php
// Opening a connection to the FTP server
require_once("config.php");
// Obtaining all files in the root directory
$file_list = ftp_rawlist($link, "/");
// Displaying the $file_list array
foreach($file_list as $line) echo $line."br>";
?>
```

> The ftp_rawlist() function returns information in the format of the UNIX ls utility executed with the -l switch. The ls utility returns the contents of the current directory in the expanded format.

The first substring of each entry is the drwx------ format; it is ten characters long and defines the file type and its access permissions. The first character defines the file type, which can be one of the following:

- - A A regular file
- d A directory
- l A symbolic link
- s A socket
- p A named channel

Only the first two types are encountered in actual FTP operations: directories and regular files.

## Part II: Solutions

The remaining nine characters define the file or directory access permissions. They are divided into three-character subgroups, defining the following:

- - Owner access permissions
- Group members access permissions
- Access permissions for users other than owners or group members

The permissions for each group are the following:

- `r` — Read the file.
- `w` — Write or modify the file.
- `x` — Execute the file if it is a script or program; view the item if it is a directory.

Thus, string `-rw-r--` describes a regular file whose owner has read and write rights, with the group members and other users having only read rights. String `drwx-xr-x` describes a directory whose owner has all rights, with all other users having only read and view rights.

The following substrings indicate the number of blocks in the file, its user owner, its group owner, its size in bytes, the creation date, and its name.

The `ftp_realpath()` function returns superfluous information, so often the `ftp_nlist()` function is used instead, which returns a list of files in the current directory without any additional information. The function's syntax is the following:

```php
array ftp_nlist (resource link, string directory)
```

The function accepts a link identifier and a directory name as the parameters. The name of the current directory can be determined using the `ftp_pwd()` function, which accepts the link identifier as the parameter:

```php
string ftp_pwd (resource link)
```

The current directory is changed with the help of the `ftp_chdir()` function, as shown in Listing II.9.4.

### II.9.3. Uploading and Downloading Files

Files can be added to the current directory by uploading them to the FTP server from the client side. File uploaded is initiated using the ftp_nb_put() function, whose general syntax is the following:

```php
int ftp_nb_put(resource link, string remote_file, string local_file, int mode, int startpos)
```

The function accepts the link identifier of an open connection as the first parameter, link. The second parameter, remote_file, specifies the path, at which the uploaded file will be saved to the FTP server. The third parameter, local_file, is the path to the local file to be uploaded. The fourth parameter, mode, defines the mode to be used for the transfer: FTP_ASCII for text files or FTP_BINARY for binary files. The fifth parameter, startpos, can be used to specify the position in bytes, from which the file transfer should be started.

The function returns one of the following constants:

- FTP_FAILED — When the upload fails
- FTP_FINISHED — When the upload is successful
- FTP_MOREDATA — When the upload is still in progress

Listing II.9.5 shows a script for uploading files to an FTP server. If the function return the FTP_MOREDATA constant, the scripts continues uploading the file using the ftp_nb_continue() function in a while loop to control the process. The function accepts the link identifier returned by the ftp connect() function as its only parameter. The ftp_nb_continue() function returns the same constants as the ftp_nb_put() function.

After the file is uploaded, the ftp_nb_continue() function returns the FTP_FINISHED constant and the script exits the while loop.
