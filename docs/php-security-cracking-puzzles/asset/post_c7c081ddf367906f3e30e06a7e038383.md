## I.7.4. A Dictionary Attack on Passwords

If you carefully considered the previous task and accomplished it, you will have discovered that guessing even the shortest password takes considerable time. However, users rarely make a meaningless password. The password typically is a word, sometimes padded by several digits. This provides rich possibilities for dictionary attacks. A well-chosen dictionary allows someone to discover passwords in a reasonable amount of time. ## I.7.6. Protecting Text Files from Being Viewed in a Browser

Even if you use complex and long passwords subject to irreversible encryption, storing information in text file available for viewing through a browser is a potential security hole. The intruder can study the text file structure, understand the internal organization of your site, and use unprotected and unencrypted information in his or her purposes. For example, it is possible to use email addresses to organize lists.
```php
<?php
// The form handler
if(!empty($_POST))
{
  // Setting connection to database
  require_once("config.php");
  // To protect yourself against SQL injection
  if (!get_magic_quotes())
  {
    $_POST['name'] = mysql_escape_string($_POST['name']);
    // the password
    $_POST['password'] = mysql_escape_string($_POST['password']);
    // Executing the query that will
    $query = "SELECT COUNT(*) FROM users WHERE name = '$_POST['name']}' AND pass = '$_POST['password']']";
    $usr = mysql_query($query);
    // Obtaining the number of records
    $Total = mysql_result($usr, 0);
    if($Total > 0)
    {
      // Authorization was successful.
      // Setting the cookie for 24 hours
      setcookie("user", urlencode($_POST['name']), time() + 3600*24);
      // Reloading to reset data
      echo "<HTML><HEAD>
      <META HTTP-EQUIV='Refresh' CONTENT='0; URL=$_SERVER['PHP_SELF']'>
      </HEAD></HTML>";
    }
  }
}
else {
  // Automatic redirection to the
  // authorization page
  echo "<HTML><HEAD>
  <META HTTP-EQUIV='Refresh' CONTENT='0; URL=1.php'>
  </HEAD></HTML>";
}
?>
```

## I.7.8. Protecting User Names

Even if there no possibility of discovering the user password or bypassing the authorization system to obtain access to the user account, it is possible to discredit an existing user by forging his her name. A name is forged by replacing English letters with characters of national alphabets, or vice versa, that are similar in appearance. For instance, assume that the usernames are made up of English letters. In this case, it is enough to register the same name but replace the English letter with its equivalent from another language (in Cyrillics, for example) and carry out malicious activity, such as flooding or spam, on behalf of that user. This forgery might make the site's administrators nervous, causing them to worry and search for nonexistent security holes if they do not notice the forgery. Develop an algorithm that would check user registration and eliminate the possibility of forged user names.
