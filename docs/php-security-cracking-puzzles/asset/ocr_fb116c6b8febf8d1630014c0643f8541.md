# Listing II.6.5. Protecting an HTML form using a referrer

```
<?php
// Creating the path to the HTML form on the current server
$html = "http://$_SERVER['SERVER_NAME']/test/index.php";
// Checking whether the data have been passed from the current server
if($_SERVER['HTTP_REFERER'] == $html)
{
    if($_POST['name'] == 'admin' && $_POST['pass'] == 'admin')
    {
        echo "<br><br>Message has been sent<br><br>";
        @mail("admin@somewhere.ru", "Statistics", "Message body");
    }
} else {
    echo "The form cannot be processed";
}
?>
```

The browser or firewall might hide the referrer, therefore, this kind of protection can result in the incorrect operation of the Web application for legitimate users. On the other hand, referrers be easily forged, so this technique doesn't ensure reliable protection. Protection techniques using sessions or images are better.

# II.6.3. Falsifying Referrers

To forge the referrer, it is necessary to send an HTTP header appearing as follows:

Referer: http://localhost/test/index.php

Here, the http://localhost/test/index.php string must be replaced by the network path to the HTML form. However, it is impossible to send this HTTP header using the header() function. Instead of this function, you'll have to use sockets (Listing II.6.6).
