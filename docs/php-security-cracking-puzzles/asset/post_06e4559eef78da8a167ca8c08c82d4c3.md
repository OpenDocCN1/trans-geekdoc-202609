### II.4.1. Registering a new User System

Organizing a registration system involves providing an HTML form for users to enter the required information. After the information is entered, it is checked for compliance with the requirements. Finally, a check is performed for whether the given user name is already in use, and if it is not the new user is added to the database. Listing II.4.1 shows an example of a script that can be used to carry out all of these procedures.

Listing II.4.1. Registering a new user in the database

```html
<table>
<form method="post">
<tr><td>Name:</td><td><input type="text" name="name"></td></tr>
<tr><td>Password:</td><td><input type="password" name="pass"></td></tr>
<tr><td>Confirm password:</td><td><input type="password" name="pass_again"></td></tr>
<tr><td>email:</td><td><input type="text" name="email"></td></tr>
<tr><td>URL:</td><td><input type="text" name="url"></td></tr>
<tr><td></td><td><input type="submit" value='Register'></td></tr>
</form>
</table>
```

```php
<?php
// The HTML form handler

//////////////////////////////////////////////////////////////////////
// The data verification block
//////////////////////////////////////////////////////////////////////
// Removing extra spaces
$_POST['name'] = trim($_POST['name']);
$_POST['pass'] = trim($_POST['pass']);
$_POST['pass_again'] = trim($_POST['pass_again']);
// Checking that the $POST array is empty
if(empty($_POST['name'])) exit();
// Checking that the required fields are properly filled
if(empty($_POST['name'])) exit('The 'Name' field is not filled!');
if(empty($_POST['pass'])) exit('Both 'Password' fields must be filled!');
if(empty($_POST['pass_again'])) exit('Both 'Password' fields must be filled!');
if($_POST['pass'] != $_POST['pass_again']) exit('The passwords do not match!');
// If an email address is supplied, checking its format
if(empty($_POST['email'])) {
    if(!preg_match('/^[0-9a-z._%+-]+@[0-9a-z._-]+\.[a-z]{2,6}$/i', $_POST['email'])) {
        exit('The 'email' address must be in the format somebody@somewhere.com.');
    }
}
// If magic quotes are not enabled on the
// server, processing the input data
// with the mysql_escape_string() function
if (!get_magic_quotes_gpc()) {
    $_POST['name'] = mysql_escape_string($_POST['name']);
    $_POST['pass'] = mysql_escape_string($_POST['pass']);
    $_POST['email'] = mysql_escape_string($_POST['email']);
    $_POST['url'] = mysql_escape_string($_POST['url']);
}
```

### II.4.2. SQL Injection into a Numeric Parameter

The code in Listing II4.3 is vulnerable to an SQL injection because the GET iduser parameter is not checked for invalid characters. Consequently, any text string can be supplied as the value for the iduser parameter.

Thus, setting the value of the iduser parameter to 'some text' will make the script issue an error (Fig. II.4.1), because an attempt to execute the following query will be made:

```sql
SELECT * FROM userslist WHERE id_user = 'some text'
```

Code %20 denotes a space. It is not necessary to remember the codes for all prohibited characters, because a URL string can be cleaned up by processing its text with the urlencode() function.

The UNION statement, available as of MySQL 4.0, can be used to combine two queries of the same format (Listing II.4.3).

## Listing II.4.3. Using the UNION statement

```sql
SELECT * FROM userslist WHERE id_user = 1
UNION
SELECT * FROM userslist WHERE id_user = 2
```

The SQL injection code is set in bold. The table produced by this query will contain records from both the first and the second queries. A URL query in this case may look as follows:

```
user.php?id_user=1%20UNION%20SELECT%20
%20FROM%users%20WHERE%20id_user%20=%202
```

Nevertheless, it displays information about the user associated with primary key 1 in the browser window (Fig. II.4.2).

The query from Listing II.4.3 returns two records: one for the user with primary key 1 and the other for the user with primary key 2 (Listing II.4.4).
