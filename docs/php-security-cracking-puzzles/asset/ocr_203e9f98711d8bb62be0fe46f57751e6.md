The data placed into the session will be available only to the user that has called them. Third-party users cannot view this data without knowing the unique session identifier (SID). The data are stored on the server, and the server and the client only exchange information using the unique SID. The SID is passed as a parameter in the address string or using session cookies. Lastly, session cookies have been most common. Because the unique SID is passed through cookies, working with sessions has the same specific features as working with any hypertext transfer protocol (HTTP) headers, which means that headers must be sent before the document body. This means that the call to the session_start() function must take place before any output into the browser window using functions such as echo, print, or any symbols not enclosed in the <$php and > tags.

# II.1.9. Passing an Array Using Cookies

Cookies are small text files located on client computers. Some information stored in cookies is limited, and some users disable cookies in the settings of their browsers. However, in contrast to sessions, the lifetime of cookies is set by the developer. As a rule, sessions exist only until the client exits the browser or for a strictly-defined interval, which usually doesn't exceed a few hours. Cookies are set using the setcookie() function, after which PHP scripts, including scripts located on different pages, would provide the possibility of accessing the saved values using the $_COOKIE superglobal array. Unfortunately, it is difficult to set the array value using the setcookie() function. Therefore, it is expedient to pack the array into the string using the serialize() function. Later, the string obtained using the serialize() function can be expanded into an array using the unserialize() function.

The serialize() and unserialize() functions are especially convenient to use when passing multidimensional arrays. This is because the transmission is reduced to passing a single text string.
