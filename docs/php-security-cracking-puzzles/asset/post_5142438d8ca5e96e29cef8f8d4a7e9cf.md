# # Chapter I.6: User Agents and Referrers

![](img/a893312ec68b8170fe567f785e95c06e_65_0.png)

Every client that accesses the server can identify itself using the `USER_AGENT` agent, according to which it is possible to determine which operating system is installed on the client machine and which browser is used. In general, it is also possible to determine whether this client is a human being or a robot.

Furthermore, using the referrer, it is possible to discover from which the user was redirected to your site. If this was from the search engine, then you'll be able to determine the keywords entered by the user of the search system. The referrer allows you to trace the dynamics of visitors' navigation from external links to your site and their navigation among pages of that site.

However, both the agent and the referrer can be easily falsified. Therefore, you mustn't blindly rely on them. Remember that they can be falsified by a client at any moment.

# I.6.6. Protecting against Downloads Managers

It is often necessary to protect the site's content against downloading using download managers. This is because when the site content is downloaded using a download manager, advertising is not viewed (and site resources mainly exist at the expense of advertising). The site's ranking also doesn't increase, because visits various robots and download managers are not considered efficient hits. This is a serious problem for free hosting, with which the owner must observe a certain ratio between the advertisements viewed and the traffic they generate.

The situation is aggravated by dynamically formed content, in which the resource address appears as follows: http://site.ru?id=01,02. Thus, it is impossible to download the entire site.

The problem that you need to solve in this section is as follows: Ensure that it is impossible to download the content of the site using download manager.

# # Chapter I.7: Authorization and Authentication

![](img/a893312ec68b8170fe567f785e95c06e_69_0.png)

Authorization and authentication play an important role when building Web applications. This is because every site, for which it is necessary to distinguish among users, must authorize visitors using passwords. IP addresses are not constant, and lots of users can connect to the Internet using the same IP address. Thus, to distinguish among visitors, it is necessary to resort to authorization. The value of the user account access in some chat room or forum is not equivalent to that of the user account providing access to private panel. As a rule, user authorization is carried out somewhere in the protected area of the site, where HTTP traffic is transmitted over the secure sockets layer (SSL) protocol, ensuring data encryption and eliminating eavesdropping on passwords (recall that in HTTP passwords are not encrypted). Whether or not SSL is used, careless implementation of the authorization code might result in cracking.

# Chapter I.7: Authorization and Authentication 57

Authentication is the procedure that verifies user identity; in other words, this procedure checks whether the user is actually the one he or she claims to be. The authorization procedure checks whether a specific user has the right to carry out a specific action. If a Web application doesn't implement a multilevel access control system, these concepts match. Thus, further on in this chapter only the authorization term will be used.
