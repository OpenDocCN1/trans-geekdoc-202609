The first line, header 0, is a standard server replying the user that the request was successfully processed (reply code 200). If the requested resource does not exist, reply code 404 is returned (HTTP/1.1 404 Found).

Header 1, Date, provides the date and the document was formed on the server; this information is necessary for the caching mechanism, which is considered later.

Header 2, Server, provides information about the type and version of the server. Thus, the first three headers in Listing II.10.5 tell you that the http://www.php.net portal is run by Apache 1.3.26 Web server to serve back-end pages.

Header 3, X-Powered-By, tells you that the page was generated using PHP 4.3.3.

Header 4, Last-Modified, provides information about when the page was modified. This HTTP header is not pertinent for dynamically generated contents.

Header 5, Content-Language, informs you that the contents sent to the browser are English in this example.

Header 6, Set-Cookie, saves the user's country (Russia in this case) and IP address—RUS, 82.208.77.193—in a cookie named COUNTRY. The cookie is valid for week for the .php.net domain. This information is used in the download section of the .php.net site, where users are offered the download closest to them.

Header 7, Connection, sends a request to the client to close the connection after it receives the reply. The chunked value in header 8, Transfer-Encoding, informs the recipient that the content is broken into fragments. Finally, header 9, Content-Type, provides information about the type and character set of the document being downloaded, text/html and ISO-8859-1, respectively.

### II.10.3. Determining the File Size

This problem can be solved using the script shown in Listing II.10.6. The script employs the custom get_content() function defined in Listing II.10.4, which returns the number of bytes in the file in the HTTP Content-Length header.

### Listing II.10.6. A script for determining remote file size

```php
<?php
$hostname = "www.php.net";
$path = "/files/configs.zip";
// Calling the custom function
$out = get_content($hostname, $path);
// Joining the array elements into a string
$lines = implode(" ", $out);
// Determining the number of bytes in the downloaded file
// with the help of a regular expression
preg_match("/s+([\d]+)/", $lines, $matches);
// Displaying the results
echo $matches[1] . " bytes in the archive";
?>
```

 result of the function's execution is as follows:
26421 bytes in the archive.

## II.10.4. Sending Data Using the POST Method

When accessing a server using the POST method, in addition to the HTTP POST /path HTTP/1.1 header, the Content-Length header containing the number of data bytes must be sent.

Unlike the GET method, the POST method sends data not in the request line but in the data area following the headers. Sending several variables is analogous to doing in the GET method: Groups of var_name = var_value are joined using the ampersand character (&). Because HTML form accepts parameters in the form name = Igor, pass = password, the data string may look like follows:

```
name = Igor & pass = password
```

Keep in mind that the data are sent in the text format; thus, any national characters must be encoded using the urlencode() function.

### II.10.7. Sending data via sockets using the POST method

```php
<?php
$hostname = "localhost";
$path = "/test2/handler.php";
$line = "";
// Establishing a connection with the host
// whose name was passed in the $hostname variable
$fp = fsockopen($hostname, 80, $errno, $errstr, 30);
// Receiving a reply from the server.
while (!feof($fp))
{
    $line .= fgets($fp, 1024);
}
fclose($fp);
echo $line;
?>
```
