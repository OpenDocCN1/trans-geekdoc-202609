# I.14.1. Monitoring a Link on a Remote Page

Develop a script to monitor the presence of a link to a site on a remote page. The check must be performed strictly on schedule, that is, exactly at the specified time. The script must record the link's state in a log file named link.log. If the link is missing, the script must inform you of this by sending an email message once a day.

# I.14.2. Verifying Link Validity

Develop a script that executes at a set time, reads a list of URLs from a text file, and verifies the validity of these URLs. This script can be used to maintain a URL data-base: If a URL is invalid, it is removed from the database.

# I.14.3. Watching for New Files

One of the signs that a site has been broken into appearance of new files in the site's file system. Some sites have a structure with numerous branches, which may have many nodes that have not been checked by the Web developers for years. Malefactors can easily hide their scripts in such nodes, applying minimum effort to disguise them. In this way, crackers often hide their back doors, scripts that give them control over the site. One way to detect such back doors or other malicious software is to search the file system of the virtual host for recently created or modi-f files. Develop a script that will do this.

# I.14.4. Watching for Oversize Files

The defense described in the previous section is not perfect, because the file crea-tion and modification date can be faked. Nevertheless, it is possible to detect alien scripts. As a rule, crackers use so-called PHP shells: scripts for navigating a virtual host and execute SQL instructions. Such scripts are usually 80–100 KB, whereas regular scripts seldom exceed 20 KB. Develop a script to search the virtual host for files larger than 50 KB.
