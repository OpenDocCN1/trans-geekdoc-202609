## I.11.4. Preventing Mass Mailing

Although there are legitimate mass mailings, spamming is a variety of mass mailing whose legality, or at least morality, is highly questionable. Develop a script to prevent users from sending more than one message in 5 minutes. Having to wait 5 minutes before being able to send another email will make the mail service unattractive to spammers. Most legitimate users will hardly be inconvenienced by this antispamming safeguard.

## Chapter I.12: The Whois Service

![](img/a893312ec68b8170fe567f785e95c06e_97_0.png)

Whois is an official service providing public information about currently-registered domain names, domain name system (DNS) servers supporting IP addresses, and owners of IP addresses. The geographical location of a given IP address can also be established with the help of the service. Different Whois services are responsible for different coverage zones. Thus, the main Whois service is the American Registry for Internet Numbers (ARIN) (http://whois.arin.net), and the Réseaux IP Européens (RIPE) Center (http://www.ripe.net) is responsible for the European Internet coverage zone.

## I.12.2. Determining Ownership of European IP Addresses

Often, a necessary IP address is not in the coverage zone of the main Whois service, in this case, run by ARIN, but is covered by one of the regional Whois services. The main database service returns a link to the regional service possessing information about the particular IP address. For example, when an inquiry about the IP address 213.136.52.29, corresponding to http://www.mysql.com, is made with the ARIN Whois service, the reply may look as shown in Fig. I.12.1.

As can be seen in Fig. I.12.1, if the IP is outside the coverage zone of the given Whois service, the latter, in the ReferralServer field, provides the address of the regional Whois service that can process this request. In this case, the service is RIPE Whois.

## Chapter I14: Telltale Scripts

![](img/a893312ec68b8170fe567f785e95c06e_103.png)

All PHP developers make the utmost effort to protect their work. However, the amount of effort the defending party has to protect against break-in is many times that the attacker has to spend. Therefore, it is a good idea to install telltale scripts that react to any anomalies in the system. Developing complexes and their scripts is the subject of this chapter.

## I14.1. Monitoring a Link on a Remote Page

Develop a script to monitor the presence of a link to a remote page. The check must be performed strictly on schedule, that is, exactly at the specified time. The script must record the link's state in a log file named link.log. If the link is missing, the script must inform you of this by sending an email message once a day.

## I14.2. Verifying Link Validity

Develop a script that executes at a set time, reads a list of URLs from a text file, and verifies the validity of these URLs. This script can be used to maintain a URL database.

## I14.3. Watching for New Files

One of the signs that a site has been broken into is appearance of new files in the site's file system. Some sites have a structure with numerous branches, which may have many nodes that have not been checked by the Web developers for years. Malefactors can easily hide their scripts in such nodes, applying minimum effort to disguise them. In this way, crackers often hide their back doors, scripts that give them control over the site. One way to detect such back doors or other malicious software is to search the file system of the virtual host for recently created or modified files.

## I14.4. Watching for Oversize Files

The defense described in the previous section is not perfect, because the file creation and modification date can be faked. Nevertheless, it is possible to detect alien scripts. As a rule, crackers use so-called PHP shells: scripts for navigating a virtual host and execute SQL instructions. Such scripts are usually 80–100 KB, whereas regular scripts seldom exceed 20 KB. Develop a script to search the virtual host for files larger than 50 KB.
