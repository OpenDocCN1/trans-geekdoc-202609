# Listing II.7.17. Fixing the vulnerability by getting rid of thetotal variable

```
<?php
...
// If the number or records is greater than zero,
// saving the user's data in a session
if (mysql_result($usr, 0)) {
    $_SESSION['name'] = $_POST['name'];
    $_SESSION['password'] = $_POST['password'];
}
...
?>
```

This approach, however, is not always suitable for constructive reasons. An alternative implementation of a session-based authorization system is to replace the $total variable with a constant (Listing II.7.18). A constant cannot be forged using external variables.

The complete source code for Listing II.7.18 can be found in the /scripts/7/7.9/3.php file on the accompanying CD-ROM.

# Listing II.7.18. Using a constant to fix the vulnerability

```
<?php
...
// Issuing a query that returns the number
// of records that meet the login and
// password criteria
$query = "SELECT COUNT(*) FROM userslist
WHERE name = '$_POST[name]' AND pass = '$_POST[password]'"
```
