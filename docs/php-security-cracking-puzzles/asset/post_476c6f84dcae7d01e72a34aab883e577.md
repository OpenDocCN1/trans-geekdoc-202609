### II.6.1. Tracing Jumps from External Sites

Jumps by users from external sites are registered by the referrer, access to which can be obtained using the $_SERVER['HTTP_REFERER'] superglobal array element. For example, if the 1.php page contains a link to the 2.php page, <a href=2.php>Link</a>, then it is possible to place the code in in Listing II.6.1 into the 2.php file.

Listing II.6.1. Output the $_SERVER['HTTP_REFERER'] content

```php
<?php
echo "You have navigated to the current page from ".$SERVER['HTTP_REFERER'];";
?>
```

You'll obtain the result shown in Fig. II.6.1.
Now it only remains to create a script that would place the addresses of pages, from which the user was redirected to the current one into the referer table.

![](img/a893312ec68b8170fe567f785e95c06e_263_0.png)

### Listing II.6.2. Creating the referrer table

```sql
CREATE TABLE referer (
  id int(11) NOT NULL auto_increment,
  id_referrer tinytext NOT NULL,
  PRIMARY KEY (id_referrer)
) TYPE = MyISAM;
```

A script might appear as shown in Listing II.6.3.

### Listing II.6.3. The script that registers referers from the pages that refer to the current one

```php
<?php
// If the referrer is not empty, placing it into the database
if(!empty($_SERVER['HTTP_REFERER'])) {
    // Setting the database connection
    require_once("config.php");
    if (!get_magic_quotes_gpc()) {
        $_SERVER['HTTP_REFERER'] = 
            mysql_escape_string($_SERVER['HTTP_REFERER']);
    }
    // Adding a new record
    $query = "INSERT INTO referer VALUE (NULL,
                                         '$_SERVER['HTTP_REFERER']')";
    if(!mysql_query($query)) exit(mysql_error());
}
?>
```

However, the script presented in Listing II.6.3 will register redirections among pages within the same site in addition to the redirections from third-party sites. Such redirections might be numerous, especially if the site contains many pages. At any rate, it would exceed the number of redirections from third-party sites. To exclude registration among internal site pages, it is necessary to add a check that would test whether the domain name is part of the refer to the current site (Listing II.6.4).

Listing II.6.4. Excluding redirections among pages of the current site

```php
<?php
// If the referrer is not empty, placing it into the database
if(!empty($_SERVER['HTTP_REFERER']) &&
    strpos($_SERVER['HTTP_REFERER'], $_SERVER['SERVER_NAME']) == false)
{
    // Establishing the database connection
    require_once("config.php");
    if (!get_magic_quotes_gpc())
{
        $_SERVER['HTTP_REFERER'] = 
            mysql_escape_string($_SERVER['HTTP_REFERER']);
    }
    // Adding a new record
    $query = "INSERT INTO referer VALUE (NULL, $_SERVER['HTTP_REFERER'])";
    if(!mysql_query($query)) exit(mysql_error());
}
?>
```

The domain name of the site can be obtained by accessing the $_SERVER['SERVER_NAME'] superglobal array element.

### II.6.2. Protecting an HTML Form Using a Referrer

To protect HTML forms against being filled in at third-party sites, it is possible to add a check by a refer into the HTML form handler in the handler.php file (Listing II.6.5).

Listing II.6.5. Protecting an HTML form using a referrer

```php
<?php
// Creating the path to the HTML form on the current server
$html = "http://$_SERVER['SERVER_NAME']/test/index.php";
// Checking whether the data have been passed from the current server
if($_SERVER['HTTP_REFERER'] == $html)
{
    if($_POST['name'] == 'admin' && $_POST['pass'] == 'admin')
    {
        echo "<br><br>Message has been sent<br><br>";
        @mail("admin@somewhere.ru", "Statistics", "Message body");
    }
} else {
    echo "The form cannot be processed";
}
?>
```

The browser or firewall might hide the referrer, therefore, this kind of protection can result in the incorrect operation of the Web application for legitimate users. On the other hand, referrers be easily forged, so this technique doesn't ensure reliable protection. Protection techniques using sessions or images are better.

### II.6.3. Falsifying Referrers

To forge the referrer, it is necessary to send an HTTP header appearing as follows:

Referer: http://localhost/test/index.php

Here, the http://localhost/test/index.php string must be replaced by the network path to the HTML form. However, it is impossible to send this HTTP header using the header() function. Instead of this function, you'll have to use sockets (Listing II.6.6).

Listing II.6.6. Sending the referrer using sockets

```php
<?php
$hostname = "localhost";
$path = "/test/handler.php";
$line = "";

// Using the POST method
```

This script sends the data using the POST method. The POST method, in contrast to the GET method, sends the data in the area that follows headers instead of the query string. Passing several parameters is similar to that of the GET method: groups name = values are joined using the ampersand (&) character. Taking into account that the HTML form accepts parameters such as name = admin, pass = admin, and session_id, with the values obtained in first access attempt through sockets, the data string might appear as follows:

```
name = admin & pass = admin\r\n\n
```

When sending the data using the POST method, it is necessary to send the Content-length HTTP header, with the number of bytes in the data string, and to send the following Content-type HTTP header: application/x-www-form-urlencoded. This header specifies the method used to send the data.

A more detailed description of using the POST method is provided in Chapter II.10.

### II.6.5. Checking for a Visit by Search Engine

Each robot of the search system notes its origin in the user agent string, which can be accessed with the $_SERVER['USER_AGENT'] superglobal element.

Part II: Solutions

Before working with user agents, it is advisable to collect the statistics. This can be achieved by setting the string accumulating to the site. Here is the typical content of this string: Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1).

![](img/a893312ec68b8170fe567f785e95c06e_269_0.png)

The presence of the MSIE 6.0 substring means that the visitor views the page using Internet Explorer v 6.0. The Windows NT 5.1 string specifies that the client operating system is Windows XP.

If the pages of the site are visited by bots of search engines, it is possible to determine, to which search engine they belong, using the HTTP_USER_AGENT string returned by the most popular search robots are as follows:

- StackRler/2.0 or StackRamb/2.0 (MSIE incompatible) — Rambler
- Yandex/1.0011 (compatible; Win16; I) — Yandex
- Googlebot/2.1 (http://www.google.com/bot.html) — Google
- Aport

To store user agents, the useragent table will be used. The definition of this is shown in Listing II.6.8.

Listing II.6.8. The useragent table

```sql
CREATE TABLE useragent (
  id_useragent int(11) NOT NULL auto_increment,
  name tintext NOT NULL,
  PRIMARY KEY (id_useragent)
) TYPE = MyISAM;
```

Now it is possible to place information about user agents into the table by inserting the script from Listing II.6.9 into the site's pages. This can be achieved using the include directive.

Listing II.6.9. Registering search bots that visit the site

```php
<?php
$useragent = $_SERVER['HTTP_USER_AGENT'];
// Discovering search engines, to which specific robots belong
$os = '';
if(substr($useragent, 0, 12) == "StackRambler") $os = 'robot_rambler';
```
