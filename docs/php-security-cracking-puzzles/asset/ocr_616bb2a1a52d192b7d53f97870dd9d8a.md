# II.2.8. Verifying Numeric Input

Verifying that inputs meet certain requirements is an important task. Web developers often assume that simply because a number should be entered into a form field, it will be entered. However, instead of a number, text or a mini-program can be input into such fields. This may result in the failed script execution at the best or in a break-in at the worst (see Chapters I.5 and II.5).

An integer can be easily checked: There is a special class, \d, for this purpose. Moreover, the regular expression must be tied to the beginning and end of the target string with the ^ and $ characters. Failing to do this will make it possible to enter anything after one digit is entered: The regular expression will find the digit and ignore everything else. The regular expression for checking that a string is an integer looks as follows:

```
^\d]*$
```

A regular expression for checking a floating-point number has three parts. The part for checking the whole part is the same as the expression for checking integers: [\d]*. The point is denoted by the period character, which must be escaped with a backslash. The part for checking the decimal portion can be described by the \.\d*. Joining these fragments produces the regular expression for checking floating-point numbers: ^[\d]*\.\d]*$. The final touch takes into account different formats of the separator between the whole and decimal parts, for both which the period (e.g., 23.56) and the comma (e.g., 23,56) can be used. The corresponding regular expression is the following: ^[\d]*[.,][]\d]*$. This expression, however, will not match integers. To take care of this, the mark character must be inserted after the [\\.,\] class. The final expression looks as follows:

```
^[\d]*[.,][]?\d]*$
```
