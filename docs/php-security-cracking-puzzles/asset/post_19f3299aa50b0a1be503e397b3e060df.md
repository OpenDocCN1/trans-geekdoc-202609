```php

<?php
if(!empty($_POST)) {
    // Connecting to the database
    require_once("config.php");

    // Checking the contents of the name field
    if(!preg_match('/^[^\'\\\]+$/',$_GET['name'])) {
        exit("Illegal query format");
    }

    // Searching for the user with the name $_POST['name']
    $query = "SELECT * FROM userslist
WHERE name
LIKE '$_POST[name]'
ORDER BY name";
$user = mysql_query($query);
if (!$user) exit("Error - ".mysql_error());
while ($user = mysql_fetch_array($user))
{
    echo "The user name is - $user[name]<br>";
}
?>
```

Although the protection works in this case (Fig. II.4.9), in Web applications the problem often cannot be solved by prohibiting single quotes, if nothing else because legitimate users can employ them.

As noted in Section II.4.1, quotation marks can be escaped using the `mysql_escape_string()` function, but using this function is redundant if the magic-quotes mode is enabled on the server. You can determine whether the magic-quotes mode is enabled by applying the `get_magic_quotes_gpc()` function, which returns `true` if the mode is enabled and `false` otherwise. A script for protecting against SQL injection attacks using the `mysql_escape_string()` function may look like the one shown in Listing II.4.16.

```php
    require_once("config.php");

    // If the magic-quotes mode is not enabled,
    // processing the $_POST['name'] field
    // using the mysql_escape_string() function
    if(!get_magic_quotes_gpc()) {
        $_POST['name'] = mysql_escape_string($_POST['name']);
    }

    // Searching for the user with the name $_POST['name']
    $query = "SELECT * FROM userslist
              WHERE name
              LIKE '$_POST[name]%'
              ORDER BY name";
    $usr = mysql_query($query);
    if(!$usr) exit(mysql_error());
    while($user = mysql_fetch_array($usr)) {
        echo "The user name is - $user[name]<br>";
    }
}
?>
```

Because of the script, the injection query is perceived as a regular string containing part of the name. Therefore, no records will be displayed (Fig. II.4.10).

## II.4.5. User Deletion and SQL Injections

The vulnerability in this problem is similar to the vulnerability in the previous one: User-supplied data are not sanitized when used in SQL requests. However, the UNION construction cannot be used to exploit this vulnerability, because it only works with SELECT queries. Here, changing the logic of the WHERE construction will do the trick. An SQL query to delete a user looks as shown in Listing II.4.17.

Listing II.4.17. An SQL query to delete a user

```sql
DELETE FROM userslist
WHERE pass = 'password' AND
name = 'name'
```

The injection query can be passed using the password or user name by replacing the chosen parameter's value with the string ' OR 1 = '1'.

Listing II.4.18. The injection query

```sql
DELETE FROM userslist
WHERE pass = 'password' AND
name = '' OR 1 = '1'
```

The WHERE condition doctored in this way always returns true, deleting all records from the userslist (Fig. II.4.11).

## II.4.6. Page Navigation

Page navigation in MySQL can be implemented using the LIMIT statement to limit the number of records (Listing II.4.22).

### Listing II.4.22. Page navigation

```php
<?php
// Setting the number of records per page
$number = 3;

// Connecting to the database
require_once("config.php");

// Forming a query to extract
// a list of catalogs
$query = "SELECT * FROM catalogs";
$cat = mysql_query($query);
if (!$cat) exit(mysql_error());
while ($catalog = mysql_fetch_array($cat)) {
  // Displaying the link to a catalog
  echo "<a href=\$SERVER['PHP_SELF']?id_catalog=$catalog['id_catalog']\">$catalog['name']</a><br>";
}
echo "<a href=\$SERVER['PHP_SELF']?id_catalog=0>All items</a><br>";
```
