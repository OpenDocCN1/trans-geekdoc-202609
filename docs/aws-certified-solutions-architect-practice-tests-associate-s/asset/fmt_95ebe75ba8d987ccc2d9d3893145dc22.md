
## AWS Certified Solutions Architect Associate 练习题解析 (246-286)

### 247. C

### 248. D

### 249. B
**解析**：SQS 队列仅**尝试**按顺序投递消息（大致遵循 FIFO 方法），但**不保证**严格的 FIFO。如果需要严格的 FIFO，可选择该选项。选项 B 可确保订单按接收顺序处理。

### 250. C, D
**解析**：除略显怪异的选项外（考试中有时会出现），所有 VPC 均可与中心通信，因此 C 和 D 涵盖了所有选项。

### 251. B, D
**解析**：在中心辐射模型中，任何辐射 VPC 仅能直接与中心通信（选项 B），以及任何其他对等连接的 VPC（选项 D）。

### 252. B, C
**解析**：在中心辐射模型中，任何辐射 VPC 仅能直接与中心通信（选项 B 正确，A 错误）。中心（VPC G）可与所有辐射通信（因此 C 正确，D 错误）。

### 253. C, D
**解析**：在中心辐射模型中，任何辐射 VPC 仅能直接与中心通信。这使得 A 和 B 为真，C 和 D 为假；因此正确答案为 C 和 D。

### 254. B
**解析**：NACL 是**无状态**的——必须为入站和出站分别定义规则。安全组是**有状态**的——允许入站的流量会自动允许出站。

### 255. A
**解析**：NACL 是**无状态**的——必须为入站和出站分别定义规则；安全组是**有状态**的——允许入站的流量会自动允许出站。

### 256. B
**解析**：NACL 是**无状态**的——必须为入站和出站分别定义规则；安全组是**有状态**的——允许入站的流量会自动允许出站。

### 257. B
**解析**：ALB 跨至少两个子网提供冗余。

### 258. A, D
**解析**：这有点棘手。默认 VPC 会自动创建子网，但额外创建的自定义 VPC 不会。你会自动获得安全组、路由表和 NACL，因此此处应选择选项 A 和 D。

### 259. C, D
**解析**：关键在于“默认 VPC”。虽然自定义 VPC 不会自动创建子网，但默认 VPC 会自动获得子网（以及互联网网关）。所有新 VPC 都会获得路由表、NACL 和安全组。

### 260. A, C
**解析**：关键在于“默认 VPC”。虽然自定义 VPC 不会自动创建子网，但默认 VPC 会自动获得互联网网关（以及子网）。所有新 VPC 都会获得路由表、NACL 和安全组。

### 261. A
**解析**：这非常困难，需要纯记忆。默认 VPC 的 CIDR 块为 `/16`，但每个 AZ 中的默认子网为 `/20`。

### 262. B
**解析**：这是死记硬背的考点。默认 VPC 分配 `/16` CIDR 块。

### 263. D
**解析**：自定义 VPC 没有默认 CIDR 块。虽然默认 VPC 拥有 `/16` CIDR 块，但自定义 VPC 必须手动指定。

### 264. B
**解析**：通常，斜杠后的数字越小，CIDR 块越大。`/16` 是最大的有效块，提供 65,536 个 IPv4 地址。

### 265. C, D
**解析**：默认 VPC 拥有默认子网，以及 NACL、安全组、互联网网关和路由表。

### 266. B
**解析**：默认 VPC 拥有互联网网关，且实例会被分配公有 IP 地址，因此选项 B 正确。你不创建默认 VPC（A），安全组控制特定访问，而非 VPC 和实例的公有或私有性质（C）。

### 267. A, B
**解析**：默认 VPC 附加了互联网网关，但自定义 VPC 没有。这是重要考点！

### 268. A, C
**解析**：选项 A 对默认和自定义 VPC 均适用：所有 VPC 都会自动创建 NACL。默认允许所有出站流量（C），但默认限制入站流量（B）——包括入站 HTTP 流量（D）。

### 269. A, D
**解析**：所有 VPC 都会自动创建 NACL、安全组和路由表。然而，只有默认 VPC 同时创建了默认子网和互联网网关。

### 270. B, D
**解析**：所有 VPC 都会自动创建 NACL、安全组和路由表。然而，只有默认 VPC 同时创建了默认子网和互联网网关，这与自定义 VPC 不同。

### 271. B, C
**解析**：默认 VPC 中的所有 EC2 实例同时拥有公有和私有 IP 地址。它们**不**拥有弹性 IP 地址，且默认创建的安全组不允许任何入站流量（除非手动修改）。

### 272. C, D
**解析**：默认 VPC 中的所有 EC2 实例同时拥有公有和私有 IP 地址。因此，要提供 Web 内容，只需通过安全组允许 Web 流量入站即可。

### 273. C, D
**解析**：非默认 VPC 中的实例需通过弹性或公有 IP 设为公有（A），VPC 本身需互联网网关（B）。此外，需通过安全组允许 Web 流量入站（C）。这是“以上皆是”情况，对应选项 C 和 D。

### 274. B, C
**解析**：VPC 终端节点在你的 VPC 与服务（如 S3，选项 B）之间通过 Amazon 网络提供连接。这避免了离开网络并通过公共互联网路由，从而为相关流量提供了更高的安全性（C）。

### 275. D
**解析**：VPC 终端节点连接不需要这些组件；它完全在这些结构之外建立私有连接，这也是其成为 AWS 内部通信极具吸引力的解决方案的原因之一。

### 276. B, C
**解析**：VPC 终端节点是由 AWS 提供冗余的虚拟设备（且自动实现）。这使得选项 B 和 C 正确，A 错误。VPC 终端节点水平扩展，而非垂直扩展。

### 277. B, D
**解析**：VPC 终端节点可连接 S3 和 DynamoDB 以及众多其他 AWS 服务，因此 B 正确。它不需要互联网网关或 VPN 连接，且不通过公共互联网路由流量（D）。

### 278. A, C
**解析**：VPC 终端节点有两种类型：接口终端节点，提供弹性网络接口和私有 IP 地址；网关终端节点，针对路由表中的特定路由。

### 279. A, D
**解析**：这相当困难，可以说处于 CSA Associate 考试范围边界。网关终端节点处理受支持 AWS 服务的所有流量。且非针对该服务的特定部分，故可排除特定 Kinesis 数据流（C）。剩下 A、B、D。A 和 D 合理，而将私有流量路由到 Route 53 不合理。

### 280. A, C
**解析**：另一道难题。接口终端节点为连接特定 AWS 服务的特定入口点提供私有 IP 地址。更通用的服务（如 DynamoDB）不是有效候选。此外，VPN（B）不合理，因 VPN 是完全不同的连接类型。故留下特定 API Gateway 和特定 Kinesis 数据流（A 和 C）。

### 281. C, D
**解析**：利用 VPC 终端节点的实例不需要公有 IP 地址或 NAT 实例。相反，假设它们有到达终端节点的路由（D），它们通过 AWS 网络将流量发送给连接的服务（C）。

### 282. C
**解析**：记忆此点的最佳方式是考虑创建实例的过程：你必须为每个实例选择安全组。因此安全组在**实例级别**运作（C）。

### 283. A
**解析**：安全组仅提供**允许规则**（A）。所有其他流量自动被拒绝，因此允许规则是放行流量的唯一手段。

### 284. A, C
**解析**：除非安全组中有针对该流量的特定允许规则，否则安全组禁止所有流量。

### 285. A
**解析**：安全组在决定如何处理流量前，会评估组上的**所有规则**。

### 286. D
