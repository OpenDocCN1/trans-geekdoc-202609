
# AWS RDS 与负载均衡器考题解析

## 5. B
目前，RDS 中的只读副本仅由 MariaDB、MySQL 和 PostgreSQL 支持。

## 6. A, C
只读副本是根据主实例的快照创建的数据库的只读实例（A）。只读副本可以与主实例位于同一实例中，也可以位于不同实例中（因此 B 错误）。只读副本通过来自主数据库的异步复制进行更新——这是性能最佳的方法。

## 7. C, D
只读副本可以位于与主实例不同的区域（D），并且它们会复制主实例中的所有数据库（C）。对于单个实例，一次最多可拥有五个只读副本（因此 A 错误）。虽然支持 MySQL 和 MariaDB（B），但不支持 Aurora。

## 8. D
根本问题在于只读副本设置仅允许五个只读副本。这不是一个可以由 AWS 提高的限制（因此 C 排除）。选项 A 无法解决问题，选项 B 不准确；此处没有影响该问题的欧盟限制。唯一能导致能够在所需区域中创建实例的答案是 D：通过关闭现有实例，您可以在所需区域中创建一个新的第五个副本。

## 9. C, D
只读副本专注于性能，因此通常可以排除任何与灾难恢复相关的答案——在本例中为 A。只读副本也适用于 RDS 数据库，因此 B 排除；不支持本地数据库。这留下了 C 和 D，两者均有效。

## 10. B, C
不会自动从任何实例（包括主实例）获取备份，因此 A 错误。由于每个只读副本都有自己的数据库实例在运行，因此 B 和 C 均有效。复制是异步的而非同步的（因此 D 错误）。

## 11. A, B
A 错误，因为您可以在与主实例相同的 AZ 中创建只读副本。与 Multi-AZ 设置不同，没有使用多个 AZ 的要求。B 也错误；只读副本不提供灾难恢复选项。C 和 D 均为真。

## 12. A
仅 A 正确。Multi-AZ 设置专注于灾难恢复和容错，而只读副本提供性能和可扩展性。

## 13. D
应用程序与只读副本通信的方式与与非副本实例通信的方式没有区别。事实上，应用程序除了无法进行写入外，“不知道”它们正在与只读副本通信。

## 14. A, D
A 和 D 均为将受益于额外只读实例的解决方案。B 不是有效答案，因为更新记录仍然只能通过主实例进行；只读副本不支持写入。C 不正确，因为只读副本不提供自动故障恢复。

## 15. B
此处需要小心。虽然只读副本未被宣传甚至建议作为灾难恢复的解决方案，但选项 B 确实提供了一种在该方面使用它们的某种手动过程。虽然您无法获得自动备份或故障转移（A 或 C），但如果必须，您可以手动将只读副本实例提升为独立实例。尽管如此，Multi-AZ 设置几乎总是容错的更稳健解决方案。

## 16. A, B
A 和 B 均为只读副本的理想使用场景。C 是常见的错误答案：只读副本不提供自动备份。D 不准确；实际的数据库处理并未改进；您只是为客户端增加了更多的数据读取来源。

## 17. D
AWS 不支持通过 RDS 进行循环复制。虽然 RDS 支持的某些数据库支持此功能，但 RDS 本身不提供对此功能的访问。

## 18. A, C
您可以通过 AWS 控制台（A）、AWS API（C）和 AWS CLI（未提及，但同样适用）创建只读副本。

## 19. B
正如多次所述，只读副本不是备份策略，也不会导致自动备份被设置。但是，您必须为主数据库实例开启自动备份以启用只读副本。

## 20. A
这需要仔细阅读。Amazon RDS 不支持循环复制，这意味着一个数据库从第二个数据库读取，但随后又被该第二个数据库复制回去。然而，一个数据库复制另一个数据库，然后作为第三个数据库的源，这是完全允许的。这使得选项 A 正确。

## 21. D
根据备份窗口更改的方式（API、控制台等），对备份窗口更改的响应没有区别。所有更改立即生效。

## 22. B
这是另一道纯记忆题：Amazon RDS 备份最多可保留 35 天，不能更久。

## 23. C
此问题有两个组成部分：使用 RDS 还是 EC2 托管 Oracle 以及要选择的存储类别。虽然 RDS 在一般情况下是更好的选择，但由于需要自定义插件，在此场景下可能无法使用 RDS。这排除了 A 和 B。假设在 EC2 上安装，那么问题变成哪种存储类别更快：预置 IOPS 还是磁性存储。答案始终是预置 IOPS。

## 24. B, C
选项 C 应为显而易见的首选。任何时候您有自定义插件，很可能需要将数据库安装在 EC2 实例上，而不是使用 RDS。选项 A 和 D 实际上都与数据库周围的网络路由和服务有关，两者均可在不影响 EC2 与 RDS 决策的情况下完成。这留下了 B，这在逻辑上也讲得通：如果您有一个非常大的数据库，并且它会增长（几乎所有数据库都会增长），那么 RDS 上的大小限制可能成为限制因素。

## 25. A, C
如果您有准备，这应该是一道简单的题。虽然很容易忘记 Aurora 和 MariaDB 是否为 RDS 选项——它们是！——但您应该知道 DynamoDB 是 AWS 的 NoSQL 数据库，而 Redshift 是数据仓库解决方案。

## 26. A
只要您理解 Multi-AZ 部署关注的是故障转移而非性能，这并不特别困难。选项 A 正确：Multi-AZ 部署中没有特定的性能提升，除非同时开启了只读副本（题目未指定）。B 错误，因为在 Multi-AZ 部署中只有主数据库响应请求。C 实际上是真实陈述，但与问题主题（性能）无关。D 在问题上下文中根本讲不通！

## 27. A
这有点棘手，因为它需要理解 AWS 设置的默认选项。默认情况下，根卷会在实例删除时终止，默认情况下，附加到实例的额外 EBS 卷不会。这使得选项 A 为真。但请注意这些设置是可以更改的！另请注意选项 D 在任何配置下均不为真。

## 28. B
所有新账户的默认值为允许 100 个 S3 存储桶；这在 AWS 中是一致的，且不因配置而改变（意味着 C 和 D 不正确）。但是，该值可以通过向 AWS 申请例外并提供合理理由来提高，这使得 B 为正确答案。

## 29. B
在 Multi-AZ 设置中，复制从主实例同步发生到辅助实例。异步复制仅发生在只读副本设置中（可在 Multi-AZ 设置之外启用）。

## 30. C
在只读副本设置中，复制从主实例异步发生到各个只读副本。因此，无法保证更新在只读副本上即时生效。同步复制发生在 Multi-AZ 设置中。

## 31. A, B
经典负载均衡器同时支持 IPv4 和 IPv6。它们支持 HTTP/1 和 HTTP/1.1，但只有应用程序负载均衡器支持 HTTP/2。此外，您必须向经典负载均衡器注册单个实例，而不是目标组；注册目标组是仅应用程序负载均衡器可用的功能。
