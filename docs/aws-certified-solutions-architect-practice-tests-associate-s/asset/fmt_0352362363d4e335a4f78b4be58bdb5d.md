
# AWS 认证考试题目解析

## 29. A
通常，SSE-S3 是加密的“入门”选项。这绝不意味着它是一种简单或业余的安全方法，但与 KMS 相比成本较低，且比客户端加密或 SSE-C 加密密钥的开销小得多。

## 30. A, C
此处必须识别出 EU West 和 EU Central 都是 EU 区域，而其他两个选项不是。

## 31. B, C
选项 A 无效，因为 US-West 不是 EU 区域。选项 B 和 C 有效，因为它们都提供 EU 区域，且 S3 和 S3-IA 都能承受可用区的丢失；选项 D 无法承受 AZ 的丢失。

## 32. B
多可用区 RDS 实例使用同步复制来推送更改。

## 33. B
MFA Delete 是在不通过 IAM 角色禁用删除操作的情况下，能提供的最强大的防删除保护。选项 A 不影响对象存储——EBS 是块存储。选项 C 和 D 都无济于事；删除请求无法通过 Lambda 阻止，且 S3 API 上没有“DELETE endpoint”。

## 34. A, B
MFA Delete 是此处的正确选项（B），但 A 是启用 MFA Delete 所需的步骤。选项 C 讲不通，虽然选项 D 在技术上会阻止所有删除，但这不是问题所问：你必须防止意外删除，而不是完全移除删除对象的能力。

## 35. D
必须启用版本控制才能启用 MFA Delete。存储桶的区域对此没有任何影响（B 和 C），且无法禁用 REST API（A），尽管你可以通过 IAM 或移除访问密钥来移除编程访问权限。

## 36. D
AWS Trusted Advisor 同时做这三件事：提升性能、降低成本和提高安全性。

## 37. D
AWS Trusted Advisor 在成本、容错、性能和安全方面提供建议，但不涉及账户组织。

## 38. A, B
这里不合理的是要求背诵 AWS Trusted Advisor 的七项核心检查。相反，应考虑哪些是 Trusted Advisor 可能提出的有效改进。A 和 B 与安全和权限相关，而 C 和 D 则远离成本、安全或性能建议的范畴。

## 39. A, C
这比较棘手。首先，根账户启用 MFA 是标准建议，所以可以选择它。对于剩下的三个答案，最直接属于“常见安全建议”的应该是具有写入权限的 S3 存储桶，这也是正确答案。

## 40. B
这些选项中，唯一无法通过 IAM 实现的是拒绝根账户访问 EC2 实例。这不可能做到——无论通过 IAM 还是任何其他机制。

## 41. B, C
A 为真，D 为真；如果知道这一点，选择 B 和 C 很简单。否则，你需要认识到仅向 S3 提供客户端密钥是不够的；必须启用某种形式的客户端加密或使用客户端密钥的服务端加密。EBS 卷可以在 S3 之外加密并存储，无论 S3 如何加密数据。

## 42. A, B
EBS 卷加密时会加密四类数据：卷上的静态数据、卷与实例之间移动的数据、从卷创建的任何快照、以及从这些快照创建的任何卷。

## 43. B, C
这比较棘手，因为涉及未加密数据的两个答案都有棘手的措辞。首先，B 不是加密的情况；如果数据从未接触加密卷，它不会被自动加密。其次，对于 C，位于实例上但从未移动到加密卷的数据也不会被自动加密。

## 44. D
所有这些都会被加密。移动到卷和从卷移动的数据以及卷上的静态数据都会被加密。

## 45. C
KMS 用作加密服务，但这不是专用于 S3 加密的 S3-KMS。你有时也会看到这个 KMS 被称为 AWS-KMS。

## 46. C
这是纯记忆题。URL 始终是 `http://169.254.169.254`，而你想要的元数据位于 `/latest/meta-data/`。

## 47. A, D
卷的加密会影响该卷的快照和从该快照创建的实例，但不影响其他任何内容。

## 48. A, D
此处仅需两个步骤：将快照复制到新区域（通常通过控制台），然后从中创建新卷。

## 49. D
你无法加密正在运行的实例；必须在创建实例时启用加密。

## 50. D
你无法加密正在运行的 RDS 实例，所以 B 不正确；你也无法访问 RDS 的底层实例，所以 C 也不正确。选项 A 听起来可行，但无法解决数据库本身创建的任何数据（如索引、对数据库中其他数据的引用等）的加密问题。加密 RDS 实例的唯一方法是在创建实例时对其进行加密。

## 51. C
此处唯一的选项是手动操作。你必须在从头创建新实例时设置加密（快照不起作用），然后将数据移入其中，以便这些数据在移入新实例时被加密。

## 52. A
你无法“即时”加密现有卷。你必须创建快照，然后在将该快照复制到另一个加密快照时对其进行加密。然后你可以从该新快照恢复。

## 53. D
这些都不行。对于此类问题，重要的是要记住你必须制作未加密快照的*副本*来应用加密。卷或快照没有原地加密机制。

## 54. B
加密 EBS 卷的唯一方法是在*创建时*对其进行加密。记住这一细节将有助于解决此类许多问题。

## 55. C, D
你无法加密现有的 EBS 卷，所以 A 不正确。你也无法加密未加密的快照，所以 B 不正确。你*可以*加密快照的副本，并将加密快照恢复到加密卷（C 和 D）。

## 56. B, C
加密卷的快照保持加密状态——无论你复制它们（B 和 C）还是从它们创建卷（D）。所以 A 和 D 为真，而 B 和 C 为假。

## 57. B
你可以跨账户复制快照，但默认权限不允许这样做。因此你必须修改这些权限，然后快照就可以复制到任何其他 AWS 账户，无论账户所有者是谁。

## 58. B
你只能从同一区域的快照创建卷。由于期望的实例在 US West 1，必须先在该区域制作快照的副本，所以 B 正确。

## 59. C
你可以将快照复制到不同区域，无需任何特殊考虑。

## 60. A, C
安全组控制允许进入和离开实例的入站和出站流量。

## 61. C
实例必须有一个安全组，但可以有多个。

## 62. A
除了安全组，NACL（网络访问控制列表）可用于进一步细化进出 VPC 的入站和出站路由。安全组附加到实例，NACL 附加到 VPC，共同构建 VPC 及其实例的完整安全图景。

## 63. C
NACL 是虚拟防火墙，它们在子网和 VPC 层面运行，而不是在单个实例层面。另请注意*自定义、用户创建*这些词。默认 NACL 允许所有入站和出站流量；创建的 NACL 则不允许。

## 64. D
IAM 角色和权限控制对 NACL 的访问。

## 65. B, C
安全组仅支持允许规则（A 为假）。它们会评估所有规则（B 为真）并在实例层面运行（C 为真）。D 为假，因为安全组不与子网关联。

## 66. A, D
安全组是有状态的，并与实例（或实例们）关联，所以 A 和 D 为真。它们不是无状态的，并且处理所有规则而不是按顺序处理规则。
