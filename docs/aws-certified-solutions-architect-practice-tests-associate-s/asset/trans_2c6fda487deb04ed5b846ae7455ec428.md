

# 领域 3：指定安全的应用程序和架构

## 225
**D.** 这一点很容易被忽略，也经常被忽略。这三种 S3 存储类别具有相同的首字节延迟：毫秒级。

## 226
**D.** 只要您具有灵活性且应用程序进程可以停止和启动，竞价型实例就能为您提供显著的成本节省。

## 问题

### 1
**B, D。** 选项 A 是错误的，但选项 B 是正确的。默认安全组阻止所有入站流量并允许所有出站流量。选项 C 和 D 涉及安全组是否为有状态：即传入连接是否能自动流出。安全组*是*有状态的，因此 D 正确。如果问题的主体是 NACL，则选项 C 将是正确的，因为 NACL 是无状态的。

### 2
**B。** D 不是一个好的答案，因为依赖 S3 外部的加密并不能最好地解决一致性方面的顾虑。通常最好让 AWS 处理加密，以便在您希望确保数据存储中的所有加密方式相同时实现这一目标。SSE-C、SSE-KMS 和 SSE-S3 都能做到这一点。然而，在这三者中，KMS 是提供清晰审计跟踪的最佳选择。

### 3
**A, C。** 堡垒主机是一个可公开访问的主机，允许流量连接到它。然后，从堡垒主机建立额外的连接进入私有子网及该子网内的主机。因为堡垒主机必须能被公共客户端访问，所以它必须暴露在互联网上 (A)。如果它位于私有子网中 (B)，将无法访问，因此该答案不正确。此外，必须存在从堡垒主机到私有子网的显式路由 (C)；这通常在 NACL 中配置。最后，堡垒主机的安全性*必须*与私有子网中的主机不同。堡垒主机应进行大幅加固，因为它是公开且可访问的；在很多方面，这与私有子网中主机的安全要求恰好*相反*。

### 4
**A, C。** AWS 有时会提出此类问题，以确保您理解根账户确实是根账户，且您无法限制该账户的访问权限。任何涉及移除根账户访问权限的选项永远都是无效的。

### 5
**B。** 这是 AWS 在考试中经常会问的“送分题”。您永远不应将应用程序密钥存储在实例上、AMI 中，或云端的任何其他永久位置——这意味着选项 B 是正确的。此外，D 讲不通；应用程序密钥用于编程访问，而非控制台访问。

### 6
**A, C。** 站点到站点 VPN 连接需要一个虚拟私有网关（在 AWS 端）和一个客户网关（在本地端）。私有子网是可选的，但不是必需的，NAT 实例也是如此。

### 7
**B, D。** 这里有两组成对的答案，您需要在每种情况下选择正确的一对。对于私有子网实例，您需要一条指向 NAT 网关的路由，且该 NAT 网关必须位于公有子网中——否则，它本身将无法提供通往互联网的出站流量访问。这意味着选项 D 正确，选项 B 也正确：0.0.0.0/0 意味着“目标为互联网大部分流量”，大致如此。

### 8
**A, B。** 解决此问题最简单的方法是将 NAT 网关视为本质上的托管服务，将 NAT 实例视为您自行管理的用于网络的实例。这有助于识别 B 为假（您从不为托管服务选择实例类型和大小）和 C 为真（AWS 为托管服务打补丁）。此外，由于 AWS 管理 NAT 网关，它们会自动具备高可用性，且不需要您关联安全组。这意味着 A 是假的——NAT 实例*可以*实现高可用，但离不开您的手动干预——而 D 是真的。

### 9
**A。** 选项 A 正确，如果您知道这一点，这道题很简单。不过，这似乎并不明显，因为所有自定义 NACL 默认都*拒绝*所有入站和出站流量。只有 VPC 的默认 NACL 具有“允许所有”策略。至于 B 和 C，这两者都是颠倒的：NACL 是无状态的（允许独立配置入站和出站流量），而安全组是有状态的。这也解释了为什么 D 是假的：NACL 是无状态的。

### 10
**A。** 对角色的权限更改现在会立即生效，并应用于所有使用该角色的实例。

### 11
**C。** 如果“允许所有”没有拉响警报，对 SSH 的引用应该会。安全组默认不允许任何入站流量。它们要求您显式允许入站流量 (C)；其他选项均为假。且安全组是有状态的——请记住这一点，因为它几乎会在每场考试中出现。

### 12
**C。** 默认情况下，所有出站流量允许流出 VPC，但不允许任何入站流量。

### 13
**C。** EBS 卷在创建时可以加密。所有其他选项通常影响卷的快照，而非卷本身。

### 14
**A, D。** 安全组仅包含允许规则，不包含拒绝规则（且“阻止规则”并非实际的规则类型）。此外，您可以创建入站和出站规则。

### 15
**B, C。** 您为安全组指定允许规则，因此 A 是假的。B 和 C 为真：默认安全组允许所有出站流量，且您需分别指定入站和出站规则。最后，安全组是有状态的，而非无状态的，因此 D 是假的。

### 16
**A, D。** A 是假的，因为安全组不提供拒绝规则。B 和 C 都是真的（因此不是正确答案）。D 是假的，因为如果没有特定的出站规则，不允许任何流量流出。（注意，默认情况下，安全组中有一条允许所有出站流量的规则，尽管该规则可以被移除。）

### 17
**B, C。** 安全组实际上可以没有入站或出站规则，因此 A 和 D 不是必需的。但安全组确实需要名称和描述。

### 18
**B。** 安全组可以附加到多个构造（如 EC2 实例），但最终是与网络接口关联，而网络接口又依次附加到各个实例上。这是一道难题，可能处于考试提问的最边缘地带。

### 19
**A, C。** 解决此题最简单的方法是认识到默认安全组从不允许宽泛的入站流量。这排除了 B 和 D，剩下允许所有出站流量的规则，适用于 IPv4 (A) 和 IPv6 (C) 两种情况。

### 20
**A, D。** 安全组规则包含协议和描述。它们不包含子网，尽管可以包含 CIDR 块或单个 IP 地址。实例可以关联安全组，但安全组本身不引用特定实例。

### 21
**B, C。** 关键不在于端点，而在于访问端点所用的实际协议。在本例中，HTTPS 是安全的，而 HTTP 不安全，因此使用 HTTPS 的答案——B 和 C——是正确的。

### 22
**A。** 客户端加密涉及由客户端（本例中即您）管理整个加密和解密过程。AWS 仅提供存储。

### 23
**C。** 使用服务端加密时，AWS 处理所有对象的加密和解密。

### 24
**B, C。** 对于客户端加密，您需要一个主密钥，它可以是 KMS 托管密钥（选项 B）或客户端主密钥。您还需要一个用于加密客户端数据的 SDK (C)。

### 25
**C。** 您可能只需死记硬背这一条。SSE-S3、SSE-KMS 和 SSE-C 都是有效的 S3 加密方式；SSE-E 是编造的。

### 26
**B。** 单词*审计*应成为您的触发词：看到需要强审计时，始终选择 KMS。SSE-KMS 提供了非常好的审计跟踪和安全性，或许是大多数用例中这些选项里最好的。

### 27
**D。** SSE-C 允许客户（SSE-C 中的 C）管理密钥，但由 S3 处理数据的实际加密。

### 28
**C。** 客户端加密允许客户自行管理密钥并加密数据，然后将已加密的数据存储在 S3 上。这种方法开销很大，但非常适合所述用例。
