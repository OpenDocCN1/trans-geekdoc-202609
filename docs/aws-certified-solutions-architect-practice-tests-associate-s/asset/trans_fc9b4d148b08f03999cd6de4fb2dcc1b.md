

## 174. A, B

AWS 总会问几个与区域和可用区相关的问题。只要仔细阅读，这些应该是容易得分的题目。区域是一个地理区域，通过至少两个可用区实现冗余。选项 A 错误，因为服务不绑定到区域。B 错误，因为区域包含虚拟数据中心；它本身不是虚拟数据中心。

## 175. B, D

可用区是虚拟数据中心（这使得 D 错误，因为可用区不*包含*数据中心），并且彼此隔离，仅通过低延迟网络链路连接。因此 C 为真（即不正确），A 为真，因为可用区确实托管计算资源。剩下 B 和 D。B 没有描述可用区，因为可用区本身不提供冗余。是可用区的*组合*完成了这项工作。

## 176. C, D

弹性 IP 分配给特定可用区中的实例，但发生故障时，该弹性 IP 可重新映射到另一个可用区，因此 A 错误。B 错误，因为区域将包含*至少*两个可用区，而非恰好两个。C 正确，因为不同账户可能将可用区重新映射到不同名称以确保更好的资源分布，D 也正确，尽管许多用户只是接受默认值而不选择特定可用区。

## 177. A, C

这道题有点难，但值得仔细分析。你需要至少熟悉 AWS 区域，并知道有几个主要区域：US、EU 和 AP。还有其他一些（如 CA、SA），但主要的是 US、EU 和 AP。知道这些，你可以发现 A 和 C 可能是有效的。JP（推测为日本）不正确，UK 应识别为 EU。不存在特定于 UK 的区域。

## 178. B, D

这更多是格式问题，而非背诵 AWS 区域列表。区域标识符是区域名称，通常是国家或地区（eu、us 等），然后是地理区域（southeast、west、east 等），最后是一个数字。这使得 B 和 D 正确。A 是“人类可读”名称，C 是可用区，因为末尾附加了字母。

## 179. A

可用区标识符是在区域标识符末尾附加一个字母。区域标识符是区域名称，通常是国家或地区（eu、us 等），然后是地理区域（southeast、west、east 等），最后是一个数字。

## 180. C

EFS（弹性文件系统）提供可从多个计算实例访问的可扩展存储。EBS 是弹性块存储，一次绑定到一个实例，因此不像 NAS（网络附加存储）。DynamoDB 是 NoSQL 数据库，磁带网关是用于与 S3 交互的客户端设备，但在本地而非云端。

## 181. C

此处需谨慎；虽然 ElastiCache 是用于缓存的 AWS 服务，但它使用 memcached 和 redis 进行实际缓存。因此，memcached 是引擎，而非 ElastiCache。

## 182. A, C

ElastiCache 使用两种不同的缓存引擎：memcached 和 redis。

## 183. C

## 184. D

## 185. A, B

首先，你需要知道可以手动强制故障转移（选项 A）。然后，意识到多可用区部署用于灾难恢复，因此需要主可用区故障才会触发故障转移（选项 B）。次要可用区不会导致故障转移（C），特定数量的失败读取也不会（D）。

## 186. A, D

可从两方面入手：了解能做什么，了解不能做什么。你*可以*选择数据库类型和要部署实例的可用区（A 和 D）。你*不能*指定与性能和故障转移相关的极其详细的问题（B 和 C）。

## 187. A, B

这有点棘手。虽然 I/O 可能短暂暂停，但数据库永远不会完全离线（C）。然而，I/O 暂停可能导致延迟增加（A）和响应变慢（B）。不过，网络请求仍会得到满足；它们不会失败（D）。
