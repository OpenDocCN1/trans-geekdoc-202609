### 13. 应用程序如何与只读副本实例通信？

1.  通过 RDS 提供的只读副本 REST API
2.  ELB 和 ALB 会自动将发往只读副本的请求转换为使用 RDS 提供的只读副本 REST API。
3.  每个只读副本提供一个只读副本密钥，允许应用程序像与普通数据库实例一样与该实例通信。
4.  应用程序与只读副本的通信方式与其与非只读副本的通信方式完全相同。

### 14. 以下哪些是使用只读复制的有效理由？（选择两项。）

1.  你拥有一个读取密集型数据库，其流量正处于峰值。
2.  你的当前数据库中，应用程序尝试更新用户条目时报告了大量错误，你希望减少这些错误。
3.  你想要一个自动化的灾难恢复解决方案，以防丢失某个 AZ。
4.  你有大量业务报表查询，目前正干扰客户应用程序的性能。

### 15. 只读副本在创建容错数据库设置方面提供任何帮助吗？

1.  是的，它为只读副本提供自动备份。
2.  是的，如果主实例发生故障，其中一个副本可以被手动提升为独立的数据库实例。
3.  是的，如果主实例发生故障，其中一个副本将自动被提升为独立的数据库实例。
4.  否

### 16. 以下哪些是使用只读复制的有效理由？（选择两项。）

1.  你在距离主实例地理位置遥远的区域拥有客户，并希望在他们访问更靠近他们的区域中托管的应用程序时，提高其读取性能。
2.  你当前的数据库实例在当前流量负载下显示内存饱和。
3.  你的老板要求一个利用 AWS 托管服务的自动化备份解决方案。
4.  你需要执行额外的 OLTP 查询，并希望提高这些查询的性能。

### 19. 自动备份与只读副本有何关联？

1.  它们无关；只读副本和自动备份之间完全没有关系。
2.  只读副本不创建自动备份，但主数据库实例必须启用自动备份才能创建只读副本。
3.  只读副本会导致主数据库实例自动开始备份。
4.  每个只读副本在从主数据库实例进行初始读取后会自动备份。

### 20. 数据库实例可以同时是一个数据库的只读副本，又是另一个只读副本的源实例吗？

1.  可以，只要源数据库和副本数据库不是同一个实例。
2.  不可以，数据库不能同时作为只读副本和源数据库。
3.  可以，只要源数据库和副本数据库在同一个可用区中。
4.  可以，只要你在两个数据库上都启用循环复制。
