

### 157. D
默认 VPC 中默认子网启动的实例可以自动访问公共互联网，因为该 VPC 拥有互联网网关，且实例会获得公有 IPv4 地址。

### 158. A
NAT 设备（网络地址转换）为实例到互联网网关提供路由，但可以阻止不需要的入站流量。

### 159. D
NAT 设备为私有实例提供互联网访问权限——它们允许出站流量而非入站流量。

### 160. B, C
AWS 提供两种 NAT 设备：`NAT instance` 和 `NAT gateway`。

### 161. A, D
实例始终需要 AMI。在本题中，这两个实例分别是 EC2 实例 (A) 和 NAT 实例 (D)。

### 162. B
`NAT gateway` 是 AWS 完全托管的设备。所有其他选项都需要用户维护操作系统级别的补丁和更新。

### 163. B
`NAT instance` 不提供自动扩展，而 DynamoDB 和 `NAT gateway` 是托管服务，提供自动扩展。实际上不存在“SNS 主题扩展”这种说法，尽管 SNS 作为一项服务确实会在后台进行一些扩展以确保满足需求。

### 164. A
在这些选项中，只有堡垒主机和 `NAT instance` 是非托管服务，因此它们是仅有的两个可能答案。堡垒主机通常具有 SSH 路由和对私有实例的权限，因此对其进行适当保护最为重要。虽然 `NAT instance` 通常可供私有实例使用，但流量是从 `NAT instance` 流出，而不是流入私有实例。

### 165. D
`NAT instance` 是堡垒服务器的候选者。其他选项都是托管服务。

### 166. C, D
站点到站点 VPN 连接在 VPC 侧需要 `virtual private gateway` (C)，在本地侧需要 `customer gateway` (D)。

### 167. A, C
站点到站点连接在 AWS 侧需要私有子网 (C)，其中包含私有实例。此外，还需要 `NAT instance` (A) 或类似设备来路由流量并作为静态 IP 持有者接收流量。

### 168. B
`Egress-only internet gateway` 仅用于 IPv6 流量。

### 169. C
`Egress-only internet gateway` 仅用于 IPv6 流量且只允许出站流量。`VPC endpoint` 连接到托管 AWS 服务，而互联网网关（非仅出站）允许入站和出站流量。`NAT gateway` 用于允许来自私有子网而非公有子网的出站流量。

### 170. A, C
`NAT instance` 必须位于公有子网中，以便从互联网访问。它还必须能够访问 VPC 中私有子网内的私有实例。

### 171. B, C
`Egress-only internet gateway` 是有状态的并支持 IPv6 流量。这属于记忆范畴，尽管可以推理：网关（在没有 NACL 的情况下）允许响应返回给使用它与公共互联网通信的实例。

### 172. C
最重要的是记住 `Egress-only internet gateway` 仅适用于 IPv6 地址。这排除了 A 和 B。然后，只有 C 以 IPv6 格式解决了整个公共互联网的访问问题。

### 173. A, D
IPv6 地址默认是公有的 (D) *因为* 它们是全局唯一的。由于范围非常大，不需要私有 IPv6 地址。

### 174. B, C
弹性网络接口是虚拟的，可以拥有多个 IPv4 和 IPv6 地址、安全组、MAC 地址以及源/目标检查标志。

### 175. D
弹性网络接口是虚拟的，可以拥有多个 IPv4 和 IPv6 地址、安全组、MAC 地址以及源/目标检查标志。不过 NACL 应用于子网，而非实例上的网络接口。

### 176. C
实例在所有情况下都有一个主网络接口，但可以附加额外的网络接口，因此答案是 C，一个或多个。

### 177. A
流量跟随网络接口，而不是绑定在特定实例上。因此在这种情况下，流量被重定向到新实例，但仍以弹性网络接口 (A) 为目标。

### 178. C
弹性网络接口一次只能附加到单个实例，但可以从一个实例移动到另一个实例。

### 179. B
实际上无法通过多个接口增加网络吞吐量，因此 B 是错误的。其他三个选项都是将多个接口附加到实例的合法理由。

### 180. C
实例的主网络接口无法分离 (C)，这使其成为正确答案。你可以分离辅助接口 (A)、附加多个接口 (B) 以及移动网络接口 (D)。

### 181. D
弹性网络接口没有路由表，但它们拥有（或可拥有）IPv4 和 IPv6 地址以及源/目标检查标志。

### 182. C
弹性 IP 地址专门用于避免绑定到特定实例，因此 A 和 B 不正确。安全组通常不与特定 IP 地址关联 (D)。这留下了 C，即弹性 IP 地址的一个有效理由：它可以从一个实例（如果该实例故障）移动到另一个实例。

### 183. A
弹性 IP 地址按定义是不会改变的 IP 地址，因此 A 正确——你不能在使用过程中更改 IP 地址。你可以移动弹性 IP (B)，包括跨 VPC 移动 (C)，并且绝对会将其关联到单个实例 (D)。

### 184. B, C
弹性 IP 可以通过将流量透明地移动到另一个正在运行的实例来掩盖实例故障 (B)。它还允许一次性移动所有网络接口属性 (C)。

### 185. A, D
要使用弹性 IP，必须先在 VPC 中分配它供使用，然后将其与该 VPC 中的实例关联 (A 和 D)。Route 53 在此阶段不参与，并且你无法分离实例上的主网络接口。

### 186. D
不存在独立于 AWS API、CLI 和控制台的“EBS 管理工具”。

### 187. C
虽然实例存在于区域和 VPC 中，并可以成为 Auto Scaling 组的一部分，但它们是被预置在特定可用区 (C) 中的。

### 188. A
EBS 快照以增量方式备份到 S3。

### 189. A
IAM 角色的更改立即生效。

### 190. A
你只能为实例分配单个角色。

### 191. B, D
你只能为实例分配单个角色 (D)，但你也可以创建一个结合所需策略的新角色 (B)。

### 192. A, D
你始终需要进行实际的角色更改 (A)。之后这些更改在实例上生效无需执行更多操作。

### 193. B, D
你首先需要创建一个具有所需权限的 IAM 角色 (B)。然后，你可以将该角色附加到正在运行的实例上，以完全避免停机 (D)。注意这是相对较新的功能；旧版 AWS 需要重启实例。

### 194. A
如果快照是已注册 AMI 的根设备，则无法删除它。

### 195. A
加密只能在创建时应用于 EBS 卷，因此 A 正确。

### 196. B
默认情况下，根卷会在关联实例终止时被删除。但是，你可以使用 AWS 控制台或 CLI 将其配置为不删除 (B)。

### 197. C
使用默认设置不是 Well-Architected Framework 的一部分，且通常不是最安全的方法。

### 198. A, C
Well-Architected Framework 建议自动化安全最佳实践和对安全事件的响应。

### 199. A, B
AWS 负责保护云本身，而作为客户的你负责保护云中的资源和数据。

### 200. A, D
AWS 负责保护云本身，这意味着基础设施方面的任何内容，如边缘位置和可用区。

### 201. D
AWS 负责网络，但不负责跨越这些网络的实际流量 (D)。

### 202. A
AWS 作为托管服务管理 DynamoDB。所有其他选项都是作为 AWS 客户的你的责任。
