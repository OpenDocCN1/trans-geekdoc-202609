## 26. Multi-AZ 部署与高性能
**场景**：你是一家公司的新架构师，正在为每分钟接收数千个请求的 Web 应用程序构建大规模数据库部署。前任架构师建议在 RDS 中使用 Multi-AZ 部署，以确保 Web 层的最大响应能力。这对高性能是一个好的方法吗？

1. **不是**，因为 Multi-AZ 部署响应请求的速度不比标准 RDS 部署快。
2. **是**，因为 Multi-AZ 部署中的额外数据库将共享来自 Web 层的请求负载。
3. **是**，因为 Multi-AZ 部署将确保如果主数据库宕机，备用数据库将是最新且可用的。
4. **不是**，因为 Multi-AZ 部署只能处理各自数据库所在可用区的请求。

> **正确答案**：1
> **解析**：Multi-AZ 部署主要提供高可用性（故障转移支持），而非性能提升。备用实例不接受读/写流量，因此不会分担请求负载。

## 27. EC2 实例终止时 EBS 卷的行为
**场景**：你启动了一个附加了两个卷的 EC2 实例：一个根卷和一个额外卷，均使用默认设置创建。当你终止实例时，每个卷会发生什么？

1. 根卷被删除，额外卷被保留。
2. 两个卷都被删除。
3. 两个卷都被保留。
4. 实例无法终止，直到根卷被删除。

> **正确答案**：1
> **解析**：默认情况下，根卷的 `DeleteOnTermination` 属性为 `true`（随实例删除），而额外附加的 EBS 卷默认为 `false`（保留）。

## 28. S3 存储桶数量限制
**问题**：一个账户可以添加多少个 S3 存储桶？

1. 100
2. 默认 100 个，但可通过联系 AWS 增加配额。
3. 取决于 AWS 为新账户设置的默认值。
4. 取决于账户创建时的配置方式。

> **正确答案**：2
> **解析**：AWS 账户默认软限制为 100 个存储桶，可通过服务配额控制台申请提升至更高限制（如 1000 个）。

## 29. Multi-AZ RDS 复制类型
**问题**：Multi-AZ RDS 设置中发生哪种类型的复制？

1. 顺序复制
2. **同步复制**
3. 异步复制
4. 全量备份同步复制，增量备份异步复制

> **正确答案**：2
> **解析**：Multi-AZ 使用同步复制将数据从主实例复制到备用实例，确保零数据丢失（RPO=0）。

## 30. 只读副本 RDS 复制类型
**问题**：只读副本 RDS 设置中发生哪种类型的复制？

1. 顺序复制
2. 同步复制
3. **异步复制**
4. 全量备份同步复制，增量备份异步复制

> **正确答案**：3
> **解析**：只读副本使用异步复制，主实例提交事务后异步发送给副本，可能存在复制延迟。

## 31. 经典负载均衡器支持的协议和路由方式（多选）
**问题**：经典负载均衡器支持以下哪些协议和路由方式？（选择两项。）

1. **IPv4**
2. **IPv6**
3. HTTP/2
4. 将目标注册到目标组并将流量路由到这些组

> **正确答案**：1, 2
> **解析**：经典负载均衡器（CLB）支持 IPv4 和 IPv6。HTTP/2 和基于目标组的路由是应用负载均衡器（ALB）的特性。

## 33. 单个 EC2 实例可附加的 EBS 卷数量
**问题**：单个 EC2 实例可以附加多少个 EBS 卷？

1. 1
2. 2
3. **27**（取决于实例类型，理论最大值通常远高于此，但考试常见选项为 27 或 "取决于实例类型"，此处选项 3 为最佳匹配）
4. 无限制

> **正确答案**：3
> **解析**：虽然实际限制取决于实例类型和操作系统（NVMe 实例支持更多），但在该选项集合中，27 是标准考试答案，代表典型的非 NVMe 实例的设备映射限制（/dev/sdf 到 /dev/sdp 等）。

## 34. 单个 EBS 卷可同时附加的 EC2 实例数量
**问题**：同一时间可以有多少个 EC2 实例附加到单个 EBS 卷？

1. **1**（标准 EBS 卷）
2. 2
3. 27
4. 无限制

> **正确答案**：1
> **解析**：标准 EBS 卷（非多重挂载卷）一次只能挂载到一个实例。支持多重挂载的 `io1`/`io2` Block Express 卷可挂载到最多 16 个实例，但题目未指定卷类型，默认指标准卷。

## 35. 应用负载均衡器支持的协议（多选）
**问题**：应用负载均衡器支持以下哪些协议？（选择两项。）

1. SSH
2. **HTTP**
3. **HTTPS**
4. FTP

> **正确答案**：2, 3
> **解析**：ALB 工作在第 7 层，专门支持 HTTP 和 HTTPS（以及 gRPC、WebSocket）。SSH 和 FTP 是第 4 层协议，由网络负载均衡器（NLB）支持。

## 36. RDS 数据库自动备份方式（多选）
**问题**：以下哪些提供了自动备份 RDS 数据库的方法？（选择两项。）

1. **自动快照**
2. S3 生命周期管理策略
3. **自动备份**
4. Data Pipeline

> **正确答案**：1, 3
> **解析**：RDS 原生提供“自动备份”功能（每日全量快照+事务日志）和“自动快照”（作为自动备份的一部分或手动快照的保留策略）。Data Pipeline 已弃用/维护模式，S3 生命周期管理用于 S3 对象而非 RDS 直接备份。

## 37. 繁忙 EC2 实例的最佳快照时机
**场景**：你有一个运行繁重计算进程的 EC2 实例，不断将数据读写磁盘缓存。如何以及何时拍摄快照以确保最完整的快照？

1. 从 AWS 控制台对实例拍摄快照。
2. **关闭实例并对实例拍摄快照。**
3. 从 AWS CLI 对实例拍摄快照。
4. 分离附加到实例的 EBS 卷，并对 EC2 和 EBS 实例都拍摄快照。

> **正确答案**：2
> **解析**：为了获得应用程序一致性（应用一致性）快照，最佳实践是停止实例（或冻结文件系统/卸载卷），确保所有缓存数据刷新到磁盘，避免数据损坏。

## 38. RDS 读性能优化方案（多选）
**场景**：你的 Web 应用使用大型 RDS 数据存储读写用户配置文件。营销活动使流量增加一个数量级。用户注册后登录时反映长时间延迟。哪些是解决此延迟的有效方法？（选择两项。）

1. 为 RDS 设置 Multi-AZ 配置，并在两个 RDS 实例间轮询请求以分散流量。
2. **使用 ElastiCache 在用户首次访问后缓存用户凭证，减少 Web 应用到数据库的往返。**
3. **为 RDS 设置只读副本配置，并在所有副本间轮询请求以分散流量。**
4. 增加分配给 Auto Scaling 组的 EC2 实例数量，以分散 Web 应用层的流量。

> **正确答案**：2, 3
> **解析**：
> - 选项 1 错误：Multi-AZ 备库不可读，不能用于分担读流量。
> - 选项 2 正确：ElastiCache 缓存热点数据（用户凭证/配置）可大幅降低数据库读压力。
> - 选项 3 正确：只读副本可横向扩展读能力。
> - 选项 4 错误：瓶颈在数据库层（登录延迟），而非 Web 应用层（无状态易扩展）。

## 39. 照片存储最具成本效益的 S3 存储类
**场景**：用户将所有照片存储在云应用中。CloudWatch 指标显示：平均每用户每天写入 5 次，读取 100 次。如果照片丢失，用户通常不介意，只会重新上传或忽略。最具成本效益的 S3 存储类推荐是什么？

1. Standard S3
2. S3-IA (Infrequent Access)
3. **S3 One Zone-IA**
4. S3 RRS (Reduced Redundancy Storage)

> **正确答案**：3
> **解析**：
> - 访问模式：写入少、读取多但非频繁实时访问 -> 适合 IA 类。
> - 耐久性要求：用户可接受丢失 -> 不需要多 AZ 耐久性（Standard/Standard-IA 提供 99.999999999% 耐久性跨 AZ）。
> - 成本最低：S3 One Zone-IA 将数据存储在单一 AZ，成本比 Standard-IA 低 20%，满足“用户不介意丢失”的前提。RRS 已不推荐使用，且耐久性仅 99.99%。

## 40. 大规模数据迁移至 S3 且避免海外延迟
**场景**：咨询一家公司将 85TB 数据存储迁移到 S3。愿意每晚分小批上传，但担心海外客户使用其他应用传输文件到 S3 时遭遇网络延迟。推荐什么解决方案移动数据？

1. 在 S3 上启用传输加速。
2. Direct Connect
3. **Snowball**
4. 设置使用虚拟私有网关的 VPN 传输数据。

> **正确答案**：3
> **解析**：
> - 85TB 数据量大，网络传输耗时极长（即使 1Gbps 专线也需 ~8 天持续传输）。
> - Snowball 设备离线传输是 PB 级数据迁移的标准方案。
> - 传输加速/VPN/Direct Connect 仍走公网/专线上传，无法解决“大量数据初始迁移”的带宽和时间问题，且会占用海外客户带宽。

## 41. 使用 S3 分段上传的有效理由（多选）
**问题**：以下哪些是使用分段上传将对象上传到 S3 的有效理由？（选择两项。）

1. **你需要一个能从网络问题中恢复的解决方案。**
2. 你需要一个上传大于 10 GB 文件的解决方案。
3. 你需要一个增加上传对象安全性的解决方案。
4. **你需要一个减少上传大文件所需时间的解决方案。**

> **正确答案**：1, 4
> **解析**：
> - 分段上传支持并行上传分片（提高吞吐/速度）和单独重试失败分片（网络恢复能力）。
> - 单次 PUT 最大 5GB，分段上传最大 5TB。选项 2 说“大于 10 GB”虽然分段上传支持，但单次 PUT 也支持 5GB，且 5GB-10GB 可选分段也可选单次，非“必须”理由。核心优势是大文件（>100MB 建议，>5GB 必须）的并行和可靠性。

## 42. 推荐使用置放群组的场景
**问题**：在以下哪种情况下你会推荐使用置放群组？

1. 你的 EC2 实例队列需要高磁盘 IO。
2. 你的 EC2 实例队列需要跨两个可用区的高网络吞吐量。
3. **你的 EC2 实例队列需要单个可用区内的高网络吞吐量。**
4. 你的 EC2 实例队列需要对 S3 存储桶的高网络吞吐量。

> **正确答案**：3
> **解析**：集群置放群组将实例放置在同一可用区的底层硬件上，提供低延迟、高吞吐（高达 10 Gbps 单流，更高聚合）的网络性能，适用于 HPC、分布式计算等节点间通信密集型场景。

## 43. 集群置放群组的正确描述（多选）
**问题**：关于集群置放群组，以下哪些陈述是正确的？（选择两项。）

1. **组内所有实例必须位于同一个可用区。**
2. **组内实例在相互通信时将看到更低的网络延迟。**
3. 组内实例在与 S3 通信时将看到改进的磁盘写入性能。
4. 组内实例必须全部属于同一个实例类。

> **正确答案**：1, 2
> **解析**：
> - 集群置放群组不能跨 AZ（规则 1）。
> - 核心优势是实例间低延迟、高带宽网络（规则 2）。
> - 不保证实例类相同（建议相同以获得最佳性能，但非强制）。
> - 与 S3 性能无关，S3 通过 VPC 端点或公网访问。

## 44. 分散置放群组的正确描述（多选）
**问题**：关于分散置放群组，以下哪些陈述是正确的？（选择两项。）

1. 组内所有实例必须位于同一个可用区。
2. 组内实例在相互通信时将看到更低的网络延迟。
3. **你可以在多个可用区中在组内拥有最多七个实例。**
4. **AWS 为该组提供硬件，而不是让你为该组指定不同的硬件。**

> **正确答案**：3, 4
> **解析**：
> - 分散置放组跨 AZ，每个 AZ 最多 7 个实例（规则 3）。
> - AWS 自动将实例分散到不同的底层硬件（机架/主机），用户无法指定硬件（规则 4）。
> - 目标是高可用性（故障隔离），而非低延迟（规则 1、2 错误，描述的是集群置放组）。

## 45. 耐久性最低的存储类
**问题**：以下哪个存储类具有最低的耐久性？

1. S3 Standard
2. S3-IA
3. Glacier
4. **它们都具有相同的耐久性。**

> **正确答案**：4
> **解析**：S3 Standard、S3 Standard-IA、S3 One Zone-IA、S3 Glacier Instant Retrieval、S3 Glacier Flexible Retrieval、S3 Glacier Deep Archive 均设计为 **99.999999999% (11 个 9)** 的耐久性。仅 S3 One Zone-IA 因单 AZ 存储在 AZ 级灾难下面临数据丢失风险，但设计耐久性指标相同。RRS (Reduced Redundancy Storage) 耐久性为 99.99%，但已不推荐使用且通常不在现代考试选项中作为标准存储类对比。

## 46. 可用性最高的存储类
**问题**：以下哪个存储类具有最高的可用性？

1. **S3 Standard**
2. S3-IA
3. Glacier
4. 它们都具有相同的可用性。

> **正确答案**：1
> **解析**：可用性 SLA 不同：
> - S3 Standard: **99.99%**
> - S3 Standard-IA / One Zone-IA: 99.9% / 99.5%
> - S3 Glacier Instant Retrieval: 99.9%
> - S3 Glacier Flexible Retrieval / Deep Archive: 99.99% (但首字节检索时间长达分钟/小时，通常不视为“高可用”访问)。
> Standard 提供最高的可用性 SLA (99.99%) 且无最小存储时长/对象大小限制。

## 47. 支持自动生命周期转换的存储类
**问题**：以下哪些存储类支持自动生命周期转换？

1. S3 Standard
2. S3-IA
3. Glacier
4. **它们都支持生命周期转换。**

> **正确答案**：4
> **解析**：S3 生命周期规则支持在所有存储类之间转换（Standard -> Standard-IA -> One Zone-IA -> Glacier Instant Retrieval -> Glacier Flexible Retrieval -> Glacier Deep Archive），以及过期删除操作。
