
# 74. A
Elastic Beanstalk 可以部署您的代码并处理容量预配、负载均衡以及设置 Auto Scaling 和健康检查，所有这些只需极少的监管。请注意，您仍然需要人员来维护此类应用程序的运行，但 Elastic Beanstalk 可以减少应用程序部署所需的初始资源。

# 75. B
CloudFormation 允许您自动化预配，在本例中，创建标准化的 JSON 脚本，只需稍作修改即可为多个共享通用结构的应用程序启动完整堆栈。

# 76. D
当数据量接近 50 TB 时，Snowball 几乎总是最具成本效益的数据传输方法，甚至在 10 TB 或更多数据量时也有充分的理由考虑使用它。

# 77. A

# 78. C
大量数据应始终让您想到“Snowball”。Snowball 为您提供可靠、可扩展、PB 级的数据传输解决方案。

# 79. D
Redshift 是 AWS 用于 OLAP 和商业智能的托管服务。

# 80. A
EMR (Elastic MapReduce) 是一项面向处理大量数据的 Web 服务。它针对该任务进行了优化，与运行类似进程的 EC2 实例相比，通常能提供成本节约。

# 81. A, D
QuickSight 是一项商业分析服务，而 Redshift 非常适合商业智能和 OLAP。虽然您可以使用 EC2 实例和预配置 IOPS 的 EBS 卷构建高性能应用程序，但像 QuickSight 和 Redshift 这样的托管服务几乎总是更具成本效益。

# 82. D
选项 A 和 B 都将产生显著成本和自定义代码。选项 C 在分析方面不是一个坏选择，但仍可能需要自定义代码来聚合数据源。然而，QuickSight 正是为这一任务而设计的：组合数据源，然后执行分析并提取见解。

# 83. C
Glacier 是 Amazon 的长期数据归档解决方案。

# 84. A
CloudFormation 非常适合在无需人工干预的情况下自动化部署，但实际处理资源*预配*的是 Elastic Beanstalk。

# 85. C

# 86. A
Lambda 允许您“忽略”运行代码所需的底层资源。您只需将代码提供给 Lambda，Lambda 将以可扩展且具成本效益的方式处理资源预配。

# 87. D
CloudWatch 提供应用程序监控，是一种低成本的 AWS 监控解决方案。

# 88. A

# 89. C

# 91. A

# Domain 5: Define Operationally Excellent Architectures

## 1. B
AWS 确实保证所有 SQS 消息*至少*投递一次，但消息*可能*会被投递多次（因此选项 A 不正确）。这与对队列的请求数量或使用队列的应用程序无关；因此 C 和 D 也都不正确。剩下的就是正确答案 B。

## 2. B, C
这是 AWS 常考的一道题，旨在确保您理解像 RDS 和 DynamoDB 这样的托管服务确实是完全*托管*的：您无法访问服务的底层操作系统。这使得 EC2 和 EMR 成为剩余的正确答案。虽然 EMR 提供了大量“开箱即用”的功能，但它仍然允许根级访问，EC2 实例也是如此。

## 3. C
SQS 队列有一个可见性超时，控制队列中的消息在处理期间被标记为“不可见”的时长。这解释了消息“消失”的原因。然后，如果应用程序处理失败——如选项 C 所述——消息会被重新标记为可见，并可再次被处理。选项 A 正确指出了此超时，但减少超时不会导致消息被正确处理。它只会减少消息“不可见”的时间。选项 B 不是队列的工作方式；队列无法要求发送方重新发送消息。选项 D 也不正确，因为队列在消息可见性和超时方面是按预期运行的。

## 4. D
快照可通过控制台使用用户名/密码访问，也可通过 AWS CLI 和 API 使用应用程序密钥访问。

## 5. B
SNS 是 Simple Notification Service（简单通知服务），功能类似邮件程序，发送可被其他应用程序订阅的通知。

## 6. A
SNS 向订阅的监听器发送通知，SWF 在消息到达时推送消息。只有 SQS 会保留消息直到队列被轮询。Redshift 根本不是消息服务，而是数据仓库解决方案。

## 7. B
SNS 和 SWF 采用推送模式运行。SQS 保留消息直到它们被从队列中拉出。S3 不是消息存储。

## 8. D
SWF 和 SQS 都至少投递消息一次，但只有 SWF 保证消息*仅*被投递一次。

## 9. B
SWF 中的消息是任务；SQS 中的消息是消息；SNS 中的消息是通知。S3 是存储解决方案，不是消息解决方案。

## 10. C
SWF 中的消息是任务；SQS 中的消息是消息；SNS 中的消息是通知。S3 根本不是消息解决方案。

## 11. D
SWF 中的消息是任务；SQS 中的消息是消息；SNS 中的消息是通知。S3 不是消息存储。由于 SQS 不是选项，答案是 D，以上都不是。

## 12. C
SWF 不仅仅是一个简单的队列。它自动化工作流，按预定顺序将任务（SWF 称其消息为任务）从一个应用程序组件移动到下一个。

## 13. B
SWF 并非严格意义上的首字母缩略词。它代表 Simple Workflow Service，但不使用 SWS 表示。相反，*WF* 指代 *workflow*。

## 14. A, D
EC2 和 ECS 都提供运行自定义代码的环境，两者都是计算服务。S3 是存储服务，Redshift 是数据仓库解决方案。虽然 Redshift 有助于数据分析，但不适合运行自定义脚本。

## 15. B
在可用选项中，Amazon Lightsail 是快速启动简单应用程序的最简单解决方案。EC2 和 ECS 都复杂得多。虽然 S3 网站托管是一种 Web 托管解决方案，但它确实需要相当多的 AWS 知识（安全性、权限等）。

## 16. B, D
如果 EBS 快照是正在使用的已注册 AMI 的根设备，则无法删除该快照。您需要先取消注册 AMI (B)，然后才能删除 EBS 卷和任何快照并停止使用该 AMI。

## 17. A
EBS 被视为 EC2 功能的一个子集。因此，您使用 `aws ec2` 命令；例如，`aws ec2 delete-snapshot`。
