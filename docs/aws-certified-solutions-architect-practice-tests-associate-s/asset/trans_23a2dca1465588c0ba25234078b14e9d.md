使用分段上传几乎完全取决于所上传文件的大小。AWS 建议将其用于任何大于 100 MB 的文件，而 10 GB 肯定足够大，可以从分段上传中受益。

## 61. A, C
正如最容易想到的答案那样，分段上传非常适合在稳定网络上传输大型对象 (A)。但它也有助于处理不太可靠的网络，因为较小的分段可能会失败，而其他分段能成功传输，从而降低整体失败率 (C)。数据入站没有相关成本 (B)，而 D 完全讲不通！

## 62. A, C
预签名 URL 的创建是为了允许没有 AWS 凭证的用户访问特定资源 (选项 C)。并且是 URL 的创建者 (选项 A) 分配这些权限，而不是用户 (选项 B)。最后，这些凭证与 URL 相关联，但并未加密进 URL 本身。

## 63. D
预签名 URL 不绑定特定的 AWS 服务。它们只是普通的 URL，可以指向普通 URL 能指向的任何内容，不同之处在于创建者可以为 URL 关联权限和超时时间。

## 64. D
预签名 URL 在创建时始终会配置一个有效的生存时间（通常称为 TTL）。此时间可以非常短，也可以相当长。

## 65. B, D
覆盖 PUT 和 DELETE 操作具有最终一致性。新对象的 PUT 操作具有写后读一致性。

## 66. D
这些都符合 S3 的行为。选项 A 可能会在新对象传播到其他 S3 存储桶时发生。B 和 C 可能会因最终一致性导致，即 DELETE 操作不会立即生效。

## 67. C
所有区域对覆盖 PUT 和 DELETE 操作均具有最终一致性。

## 68. A, D

## 69. B

## 70. B
通过 PUT 上传的新对象遵循写后读一致性。覆盖 PUT 使用最终一致性模型。

## 71. C
这一点很重要，因为它反映了 AWS 最近的一项更改。直到 2018 年，S3 每秒 100 次 PUT 的硬性限制，现已提高到每秒 3500 次 PUT。

## 72. B
S3 存储桶名称基于 S3 标识符 (`s3`)、区域 (本例中为 `us-west-1`) 和 `amazonaws.com` 域名。然后，存储桶名称出现在域名*之后*。结果为 B：`https://s3-us-west-1.amazonaws.com/prototypeBucket32`。选项 A 区域不正确，C 和 D 将存储桶名称放在了域名中，这是不正确的。

## 73. A
S3 存储桶名称基于 S3 标识符 (`s3`)、区域 (本例中为 `us-east-1`) 和 `amazonaws.com` 域名。然后，存储桶名称出现在域名*之后*。结果类似 `https://s3-us-east-1.amazonaws.com/prototypeBucket32`。然而，US East 区域的存储桶是特殊情况，应使用特殊的唯一端点 `s3.amazonaws.com` (选项 A)。

## 74. B, C
选项 A 格式不正确；`s3` 应与区域用连字符 (`-`) 分隔。选项 B 有效，选项 C 是 US East (N. Virginia) 的正确唯一 URL。选项 D 格式正确，但 `jp-west-2` 不是 AWS 区域。

## 75. A, D
S3 支持两种存储桶 URL 样式：虚拟托管式和路径式 URL。虚拟托管式 URL 格式为 `http://bucket.s3-aws-region.amazonaws.com`，路径式 URL 是你见过的传统 URL：`https://s3-aws-region.amazonaws.com/bucket-name`。

## 76. B, D
选项 A 不是有效的 S3 URL。选项 B 有效，使用了最常见的 S3 存储桶路径式 URL 格式。选项 C 使用了不存在的区域 (`mx-central-1`)。选项 D 有效，使用了虚拟托管式 URL 格式。

## 77. D

## 78. B

## 79. B, D

## 80. A, D
S3 对新对象的 PUT 操作支持写后读一致性，对覆盖 PUT 和 DELETE 操作支持最终一致性。

## 81. C, D

## 82. C
MFA Delete 是确保对象不被意外删除的绝佳手段。MFA（多因素认证）确保任何对象删除都需要多种形式的身份验证。

## 83. B
所有 Amazon 特定的请求头均以 `x-amz` 开头。这点很重要，有助于排除大量错误答案。这仅留下 `x-amz-mfa`。

## 84. B, C
MFA Delete 适用于删除对象，而非存储桶 (因此选项 A 不正确)。它影响更改存储桶的版本控制状态或永久删除任何对象 (或该对象的某个版本)；这使得 B 和 C 正确。删除对象的元数据而保留对象本身不需要 MFA Delete。

## 85. A
此答案只能死记硬背。MFA Delete 认证码来自硬件或虚拟 MFA 设备，如 iPhone 上的 Google Authenticator。

## 86. D
这很棘手且有些反直觉。只有根账户可以启用 MFA Delete。即使是创建了存储桶的控制台用户——如果不是根用户——也无法在存储桶上启用 MFA Delete。

## 87. B
存储桶拥有者、根账户和存储桶的所有授权 IAM 用户均可启用版本控制。

## 88. A, B
S3 中的每个对象都有名称、值 (数据)、版本 ID 和元数据。除非开启版本控制，否则对象的版本历史不存在，因此它不总是有效答案。

## 89. B
目前 AWS 中的所有元数据均通过标签输入，即控制台可用的键值对。

## 90. D

## 91. D
一旦启用，无法在 S3 存储桶上禁用或关闭版本控制。虽然你可以暂停版本控制，但这并不会真正关闭版本控制，旧版本仍会被保留。

## 92. B, C
CloudFront 旨在从源服务器缓存并分发静态文件给用户或客户端。动态内容也可通过 CloudFront 从 EC2 或其他 Web 服务器分发。基于对象的存储在此语境下讲不通，因为 CloudFront 是分发机制，而非存储设施。

## 93. D
CloudFront 从源服务器分发内容，通常为静态文件和动态响应。这些源服务器通常是用于静态内容的 S3 存储桶和用于动态内容的 EC2 实例。

## 95. B, D
