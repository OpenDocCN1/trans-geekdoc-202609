
# AWS 认证考试题目解析 (133-173)

## 133. A, C
**EC2** 由定义属于服务器驱动型选项。**S3**（通过静态网站托管）和 **Lambda** 均提供无服务器选项以服务内容。**Route 53** 提供 DNS 服务，但自身无法提供网站内容服务。

## 134. B, C
虽然 **S3** 可以服务静态内容，但它不具备处理代码或以其他方式提供动态内容的能力。**EC2** 通过服务器驱动型计算提供动态内容，**Lambda** 通过无服务器计算提供动态内容。

## 135. A, C
**Elastic Beanstalk** 专注于代码部署。它提供该功能，并在过程中提供负载均衡、Auto Scaling、健康监控和容量预置 (C)。

## 136. B, D
**Elastic Beanstalk** 专注于代码部署 (A)。它提供该功能，并在过程中提供负载均衡、Auto Scaling、健康监控 (C) 和容量预置。它不提供安全或日志检查功能。

## 137. A, D
这稍微偏离了常规 AWS 考点，但你应了解 AWS 常用和引用的语言及技术，以及不常用的。通常，**Docker** 和容器始终受支持；**Node.js**、**JavaScript**、**Java**、**PHP** 和 **Perl** 常受支持。**C++** 和 **Scala** 不在该列表中。

## 138. D
解答此题的最佳方法是立即识别常用语言：**Node.js** 和 **Python**。虽然你可能忘记 **Java** 受支持，但一旦识别出两个有效选项，答案必为 D。

## 139. A, B
**Elastic Beanstalk** 支持所有 **RDS** 选项以及 **DynamoDB**。在 **EC2** 上运行的 **Oracle** 属于非标准选项，不适合 Elastic Beanstalk 的自动预置。**Redshift** 也不是一种数据库技术（指 OLTP 事务型数据库）。

## 140. C
你完全可以使用 **Elastic Beanstalk** 部署到生产环境。只需配置不同的 Elastic Beanstalk 环境以使用不同的数据库即可。

## 141. D
**EC2** 和 **ECS** 属于计算服务，但需要了解并操作所需资源。**DynamoDB** 是数据库，无法运行代码。**Lambda** 正确：它运行代码，无需用户管理底层计算资源集合。

## 142. A, D
**Elastic Beanstalk** 和 **Lambda** 是截然不同的服务，但在此语境下，两者均为有效答案。Elastic Beanstalk 是一种“代码部署向导”，Lambda 允许无服务器代码部署。两者均在无需用户干预的情况下处理环境预置。

## 143. A
通过 **Lambda** 部署的代码绝对运行在服务器上；然而，**AWS** 将详细细节从用户管理中抽象掉了。

## 144. A, B
你应了解 AWS 常用和引用的语言及技术，以及不常用的。通常，**Node.js**、**JavaScript**、**Java**、**PHP** 和 **Perl** 相当常见地受支持。**C++** 和 **Scala** 不在该列表中。

## 145. B, C
选项 A 略显无稽。安装 **Oracle** 需要使用 **EC2** 实例，因此不属于 **Lambda** 的用例。B 和 C 均有效：Lambda 非常适合响应来自其他 AWS 服务的触发器或状态变更，且无需用户驱动代码即可很好地处理扩展。D 无效；那是 **EC2** 或 **Elastic Container Service** 的用例。

## 146. A
将文件转换为各种格式属于转码，因此是 **Elastic Transcoder** 的功能。

## 147. B
**QuickSight** 是一项云驱动的商业分析服务。它从多数据源提供可视化和分析。

## 148. B
**SNS** 是简单通知服务，当 AWS 环境中发生特定事件时，提供通知——警报和告警。

## 149. A
**AWS Cognito** 允许你为 Web 应用程序添加用户注册、登录和访问控制，以及单点登录。它还允许使用 **Facebook** 和 **Google** 等身份提供商。

## 150. B
每个区域都是特定的地理区域，但没有一个大到像整个大陆那样。

## 151. D
**VPC** 是虚拟私有云。它是专用于单个 AWS 账户的虚拟网络。

## 152. C
**ECS** 是弹性容器服务。它管理作为计算资源的容器（**Docker**），可快速启动和关闭。

## 153. B
**RDS** 是关系数据库服务，为应用程序提供托管数据库服务。

## 154. D
**Route 53** 是 AWS 托管的 DNS 服务。它提供域管理和注册。

## 155. D
**客户网关** 允许本地站点通过对等 VPN 与 AWS 连接。它是一种虚拟网络设备。

## 156. A
与 **S3** 相关的任何内容均属存储相关。此处，生命周期管理处理数据从一种 S3 存储类向另一种的转换。

## 157. D
**Amazon Lightsail** 是面向 Web 应用程序的计算解决方案，涉及计算、存储和网络，以及所需时的数据库存储。它启动服务器并使用 Web 托管所需服务对其进行配置。注意，虽然 AWS 将 Lightsail 视为计算服务，但它绝对与额外资源交互并控制它们。

## 158. C
**Elastic Beanstalk** 是一项 Amazon 服务，可启动并管理许多其他服务，特别是计算服务。尽管你可以配置其他服务，但 Beanstalk 主要被视为代码部署工具，因此专注于计算服务。

## 159. A
**EFS** 是弹性文件系统，一种关注存储的可扩展文件系统。

## 160. C
**Redshift** 是 AWS 的 OLAP（在线分析处理）工具之一，属于数据库服务。虽然它进行处理，但主要旨在接收大量数据并对其进行操作，类似于数据库（广义上）。

## 161. B
**CloudFront** 是 AWS 的分发网络。它是一个内容缓存系统，归根结底是 AWS 构建中的网络组件。

## 162. D
**Athena** 是一个数据库，可通过 **RDS** 使用，但最终旨在用于分析，很像 **Redshift** 和 **Elastic MapReduce**。

## 163. B
**EMR** 是 Elastic MapReduce，提供大规模数据集的数据处理和分析。

## 164. C
**Cloud9** 是一个开发环境，旨在作为 AWS 开发者的 IDE。

## 165. D
**Direct Connect** 是一项 AWS 服务，用于在本地站点与 AWS 之间创建高速连接。

## 166. D
**Amazon Workspaces** 允许你通过云提供桌面服务。该服务允许世界各地的人们利用可扩展的桌面预置。

## 167. B
**Kinesis** 是一项数据分析服务，能够处理大规模数据流并提供实时洞察。

## 168. C
**Elastic Transcoder** 将视频处理为适用于各种设备、分辨率和格式的格式。

## 169. D
**OpsWorks** 是一项运维管理服务，AWS 常在控制台将其归类为“管理工具”。它允许与 **Puppet** 和 **Chef** 等工具集成。

## 170. A
**Lex** 是用于构建语音识别和对话机器人的 Amazon 服务。

## 171. A
**CloudWatch** 提供设置特定指标（网络吞吐量、请求、磁盘 IO 等）并通过仪表板和报告监控这些指标的能力。

## 172. D
**可用区 (AZ)** 是区域内的虚拟数据中心，与其他 AZ 之间由足以提供灾难冗余的距离隔开。B 不正确，因为 AZ 内部不具备冗余；那是区域的定义。

## 173. B
**区域** 是一个地理区域，通过可用区在其内部具备冗余。每个 AZ（A 和 C 中均有定义）均与其他 AZ 分离，本质上每个都是一个虚拟数据中心。
