## 204

## 207

## 208
**答案：C**
AWS 绝不会主动发起区域间的数据移动。区域中的内容必须由客户移动，或响应客户操作而移动。

## 209
**答案：D**
S3 数据可通过 MFA Delete 和版本控制进行保护，两者均可提供一层防止意外删除的保护。此外，IAM 角色可确保只有*应该*能够删除数据的人*才能*删除数据。

## 210
**答案：A, C**
所有这些选项均有效，但只有两项应在所有环境中执行：在根账户上启用 MFA 和设置密码轮换策略。在 S3 上启用 MFA Delete 是个好主意，但可能不适用于所有情况。此外，并非所有用户都需要 IAM 角色；例如，某些用户使用默认角色即可。

## 211

## 212

## 213

## 214

## 215
**答案：A**

## 216
**答案：C**
AWS 完善架构框架提供五大支柱：运营卓越、安全、可靠性、性能效率和成本优化。组织问题被视为该框架之外的内容 (C)。

## 217
**答案：B**
AWS 完善架构框架提供五大支柱：运营卓越、安全、可靠性、性能效率和成本优化。易用性不是云的关键关注点 (B)，尽管它对于云中托管的应用程序很重要。

## 218
**答案：C**
C 是对正确原则的错误陈述；应在*所有*层应用安全。安全应存在于所有层，而不仅仅是最高层。

## 219
**答案：D**
虽然 A 和 C 都是好主意，但它们比完善架构框架的原则更具体。B 是原则的一部分，但数据应在静止和传输时均受保护。这留下了 D，即人员应远离对数据的直接访问。相反，工具和 API 应在用户和数据之间提供一个层。

## 220

## 221

## 222

## 223
**答案：C, D**
良好的密码策略具有最小长度和复杂性要求。

## 224
**答案：C**

## 225

## 226

## 227

## 228

AWS Organizations 中的 SCP 是服务控制策略，可应用于组织单元 (OU)，以影响该 OU 内的所有用户。它实际上在组织层面应用权限，就像组在用户层面应用权限一样。

## 229
**答案：C**
服务控制策略 (SCP) 应用于 AWS Organizations 中的 OU（组织单元）。

## 230
**答案：A**
服务控制策略 (SCP) 支持跨 AWS 账户工作 (A)。组织单元 (OU) 是账户的分组，IAM 角色应用于用户和组，而非跨账户结构。

## 231
**答案：C**

## 232

## 233

## 241
**答案：C**

## 242
**答案：A**
当 EC2 实例需要访问其他 AWS 服务时，会代入一个 IAM 角色，该角色具有关联的权限。虽然这些权限在策略中正式定义 (B)，但实例用于实际服务访问的是角色。

## 243
**答案：A, D**
正如计算实例 (EC2) 的情况一样，容器中的任务需要一个具有访问 S3 权限的 IAM 角色 (A)，这反过来又需要一个指定允许 ECS 任务访问 S3 权限的策略 (D)。这两者都是确保访问所必需的。安全组适用于网络流量，不会影响 S3 访问，虽然可以使用 VPC 端点 (C)，但这不是必需的。

## 244
**答案：C**
