## 215. 你有一个 Auto Scaling 组，其中的一个实例通过了健康检查但无法正常响应请求。排查该实例的最佳方法是什么？

1.  重启实例。
2.  将实例从 Auto Scaling 组中移除，然后进行排查。
3.  将实例置于 `Standby` 状态并正常排查。
4.  向实例添加 CloudWatch 指标以触发 Auto Scaling。

## 217. 创建 Auto Scaling 组的正确任务顺序是什么？

1.  验证你的组，创建 Auto Scaling 组，创建启动配置。
2.  创建启动配置，创建 Auto Scaling 组，验证你的组。
3.  创建 Auto Scaling 组，创建启动配置，验证你的组。
4.  创建启动配置，验证你的组，创建 Auto Scaling 组。

### 3. 你正在创建一个堡垒主机，以允许通过 SSH 访问组织 VPC 中私有子网内的一组 EC2 实例。配置堡垒主机时应执行以下哪些操作？（选择两项。）

1.  确保堡垒主机直接暴露在互联网上。
2.  将堡垒主机放置在私有子网内。
3.  在子网的 NACL 中添加一条从堡垒主机 IP 到私有子网的路由。
4.  确保堡垒主机与私有子网内的主机位于同一个安全组中。

### 4. 以下哪些是无效的 IAM 操作？（选择两项。）

2.  允许用户账户对所有 EC2 实例的 SSH 访问
3.  移除根账户的控制台访问权限
4.  移除所有非根用户账户的控制台访问权限

### 5. 以下哪项陈述是正确的？

1.  应仅将应用程序密钥存储在应用程序的 `.aws` 文件中。
2.  **永远不应**将应用程序密钥存储在实例上、AMI 中或云端的任何其他永久位置。
3.  应仅将应用程序密钥存储在加密的 AMI 中。
4.  应仅使用应用程序密钥登录 AWS 控制台。
