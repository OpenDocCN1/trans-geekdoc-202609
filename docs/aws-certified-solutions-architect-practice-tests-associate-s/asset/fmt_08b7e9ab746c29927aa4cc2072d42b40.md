
## 50. A, D

Administrators 和 Power Users 的默认策略都提供对大多数 AWS 服务的读写访问权限。Power Users 限制了对 IAM 的访问，但这不会影响对 S3 或 EC2 的访问。

## 51. C

策略是 AWS 用于描述一组权限的文档类型。

## 52. B

`ECS` 是 `Elastic Container Service`（弹性容器服务），是 AWS 用于在容器中运行应用程序并管理这些容器的启动、停止和扩缩容的服务。

## 53. C, D

容器允许您缩短启动时间，因为在大多数情况下，它们是启动到已在运行的实例中的（C）。这也涉及 AWS 管理和预置运行容器的实例的能力（D），这是另一个优势。虽然您可以扩缩容器中的应用程序（A），但您也可以同样轻松地扩缩 EC2 实例上的应用程序。最后，选项 B 纯属错误。

## 54. A

首先要了解这些各种首字母缩略词。`ECR` 是 `Elastic Container Registry`（弹性容器注册表），`ECS` 是 `Elastic Container Service`（弹性容器服务），`EC2` 是 `Elastic Compute Cloud`（弹性计算云），`EMR` 是 `Elastic MapReduce`（弹性 MapReduce），当然 `S3` 是 `Simple Storage Service`（简单存储服务）。鉴于此，只有 A 包含所有必需组件：注册表（`ECR`）、管理服务（`ECS`）以及运行容器的实例（`EC2`）。请注意，即使您可能不会显式地为容器使用 `EC2`，但 `EC2` 或 `Fargate` 将在某个层面上被要求管理实例，即使仅由 AWS 为您管理。

## 55. C

您需要知道这些各种首字母缩略词。`ECR` 是 `Elastic Container Registry`（弹性容器注册表），`ECS` 是 `Elastic Container Service`（弹性容器服务），`EMR` 是 `Elastic MapReduce`（弹性 MapReduce），`S3` 是 `Simple Storage Service`（简单存储服务）。`ECC` 不是 AWS 的首字母缩略词，因此立即排除。在剩下的选项中，`ECR`（弹性容器注册表）与 `ECS` 的关联最为紧密。

## 56. B, C

容器允许您在实例上共置应用程序，并能在没有大量开销的情况下更有效地使用可用实例，因此 B 正确。C 也是类似的道理：容器减少了实例的管理开销。A 不正确，因为容器不会显著改变您的成本结构，D 是错误的，因为容器和实例都可以根据需求进行扩缩容。

## 57. A, D

容器是应用程序（D），根据应用程序负载进行扩缩（A）。相比之下，`Lambda` 运行的是隔离的代码片段，而不是整个应用层。此外，`Lambda` 基于事件启动，而非基于负载。（请注意，您实际上可以在 `CloudWatch` 中设置负载监控器并基于负载触发 `Lambda`，尽管这不像容器那样是自动的。）

# Practice Test

## 1. A, C

首先，具有最快卷类型（预置 IOPS）的更大实例通常会提高整体性能，因此 A 是个好主意。其次，`ElastiCache` 将提供更快的响应并随时间减少数据库读取。A 和 C 都是有效的方法。`Multi-AZ` 设置用于灾难恢复，而分片开销高，并且在该用例中可能会增加响应时间，而不是减少它。

## 2. B

`redis` 和 `memcached` 是 `ElastiCache` 可用的引擎。`reddit` 是一个在线信息网站，`Redshift` 是数据仓库和 OLAP 服务。

## 3. B, C

AWS 允许多种静态数据加密选项。在提供的解决方案中，`AWS Key Management Service`（`KMS`）是 AWS 托管的数据加密解决方案，也允许使用客户提供的密钥。在后一种情况下，客户提供密钥，AWS 使用这些密钥处理数据加密。`ElastiCache for memcached` 不支持加密，而且它不是一种加密数据的解决方案，而是一种缓存服务。`AWS Encryptic` 不是实际的 AWS 服务。

## 4. A, D

`AWS Organizations` 允许在一个地方管理多个账户，并允许跟踪这些单独的账户（D）。此外，在许多情况下，AWS 将允许基于总服务使用量提供折扣，而不是单独对待每个账户（A）。

## 5. B, C

这里最大的问题是所有用户都在使用根账户，这意味着存在共享密码，且用户拥有的权限远超其所需。这两点都可以通过为每个用户创建新的 `IAM` 用户（B）并根据其工作职能将这些用户放入预定义组中（C）来解决。开发人员通常不需要访问 `IAM`，因此 D 不正确，虽然更改根密码是个好主意，但 A 也不正确，因为财务经理（以及可能的支持工程师）可能不需要 `AWS CLI` 作为其访问机制。

## 6. D

对于 I/O 密集型应用程序和数据库，最佳选择是预置 IOPS（D）。另一个可能令人困惑的选项是 B，吞吐量优化 HDD。这些不是 SSD 卷，它们更适合数据仓库，而不是密集型 I/O。

## 7. B, C

这里有两个潜在问题：网络吞吐量和传输失败未重试。解决方案 B 通过增加 `NAT` 实例处理来自多个实例的大量数据的能力来解决吞吐量问题。解决方案 C 通过将传输失败视为应由实例重试的问题来解决失败传输问题。

## 8. A, B

您无法加密现有的 `EBS` 卷（A）。此外，一旦快照被加密，您就无法创建该快照的未加密副本（B）。您可以将加密卷挂载到实例（C），并且可以从未加密的快照创建加密卷（D）。

## 9. C

首先，请意识到当您看到询问写入 `S3` 的问题时，您需要一个未设置为静态网站托管的 URL。这意味着存储桶名称位于尾部斜杠之后，而不是域名本身的一部分。这意味着只有 B 和 C 是有效选项。然后，请记住服务（`s3`）和区域（在本例中为 `eu-west-2`）不是由点分隔符分隔的，而是由连字符分隔的。这使得 C 成为正确答案。

## 10. C

`CloudWatch` 是 AWS 首选的事件监控解决方案。虽然流日志的数据可以由 `RDS` 处理并由 `Redshift` 分析，但这两者都不如 `CloudWatch` 那样是针对监控的靶向解决方案。

## 11. C

`Lambda` 最适合在无需预置 `EC2` 实例开销的情况下编写自定义代码，因此 A 和 C 都是潜在的正确答案。虽然 `SQS` 确实提供代码排队，但 `SWF`（`Simple Workflow Service`，简单工作流服务）为您提供应用层事件和任务的预构建跟踪。将 `Lambda` 连接到此服务，您就拥有了一个开箱即用的事件驱动服务。

## 12. B, D

非默认 `VPC` 没有连接互联网网关，因此 B 提供了该补救措施。将互联网网关连接到 `VPC` 将为公共实例提供通往互联网的路径。解决方案 D 也是正确的；非默认 `VPC` 上的 `NACL` 不允许 HTTP 或 HTTPS 流量进入（安全组也是如此），需要显式允许 HTTP/S 流量进入。

## 13. D

这些答案大多无助于解决问题。`NAT` 实例应该位于公有子网中，因此 A 没用。`NAT` 的 `EBS` 卷可能是个问题，但不在于为连接实例提供互联网访问（B）。包含使用 `NAT` 实例的 `EC2` 实例的子网应该是私有的，因此 C 既不正确又是糟糕的设计决策。这留下了 D：`NAT` 实例必须禁用源/目标检查才能正常工作。

## 14. D

所有 `S3` 存储类共享相同的持久性：11 个 9（99.999999999%）。这通常违反直觉，所以最好记住所有 `S3` 类别的持久性相同，并从 `S3` 到 `S3-IA` 再到 `S3 One Zone-IA` 可用性逐渐降低。
