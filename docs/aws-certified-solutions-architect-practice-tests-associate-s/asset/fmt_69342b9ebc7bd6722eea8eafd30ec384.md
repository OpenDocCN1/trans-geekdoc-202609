
# AWS NACL、VPC 与子网考题解析

## NACL 基础特性

### 67. B, C
NACL 是**无状态**的；必须为进出双向流量指定规则（因此 A 错误，B 正确）。它们还按顺序处理规则（C 正确）。NACL 关联到子网，而非特定实例（因此 D 错误）。

### 68. A, C
NACL 关联到子网（A），且同时支持允许和拒绝规则（C）。B 错误：NACL 和安全组协同工作。D 错误，因为规则是按顺序处理的。

### 69. B
NACL 总是最先被评估，因为它们位于子网边界。安全组附加到实例，因此只有在流量通过 NACL 并进入实例所在子网后才会被处理。

### 70. A, B
安全组和 NACL 都可以（且通常）应用于子网中的多个实例。NACL 适用于关联子网内的所有实例，安全组可以关联多个实例。

### 71. B
NACL 关联到子网。

### 72. A, B
默认 NACL 允许进出所有流量，这有点反直觉。请记住，默认**安全组**禁止入站流量，但默认 NACL 允许该流量进入。

### 73. C, D
与随默认 VPC 附带的默认 NACL 不同，自定义 NACL 默认禁止所有入站和出站流量。

### 74. A
NACL 中的每条规则都有一个编号，规则按编号从低到高进行评估。

### 75. B, D
A 和 C 正确。B 错误：NACL 是无状态的。D 错误，因为一个 NACL 可以关联多个子网。

### 76. B
NACL 关联到子网，而非实例或 VPC。它可以关联单个子网或多个子网。

### 77. A
子网关联一个 NACL。但是，子网同一时间只能关联单个 NACL。

### 78. D
子网关联一个 NACL，但同一时间只能关联单个 NACL。

### 79. B, D
NACL 规则包含规则编号、协议、ALLOW 或 DENY 选择，以及用于入站和出站流量的 CIDR 范围和端口或端口范围。

### 80. A, B
NACL 规则包含规则编号、协议、ALLOW 或 DENY 选择，以及用于入站和出站流量的 CIDR 范围和端口或端口范围。

### 81. B
几乎所有这些细节都不重要。唯一的关键参数是规则编号。NACL 先评估编号最低的规则，因此规则 #100 会最先执行，选项 B。

### 82. D
自定义 NACL 中未显式提及 SSH，因此不允许 SSH。每种协议都必须显式提及。

### 83. A
未显式提及 SSH，但因为问题询问的是**默认** VPC 上的**默认** NACL，除非显式拒绝，否则允许所有流量进入。

### 84. B
此处允许 SSH，但仅限来自特定 CIDR 块的流量。

### 85. D
虽然有一条规则允许来自 CIDR 块 `192.0.2.0/24` 的 SSH，但该规则会在编号较低的规则 110 之后被评估，规则 110 拒绝任何未被编号更低的规则（本例中仅规则 #100）允许进入的流量。

### 86. D
从技术上讲，B 和 C 正确；SSH 是一种 TCP 流量。然而，这不是问题所要求的最具体答案。A 部分正确，但未指出 D 所包含的 CIDR 块限制。因此，D 是最准确的答案。

### 87. B
此处**最准确**的答案包含几个组成部分：TCP 流量类型（HTTP）、允许的源 CIDR 块（整个互联网）和 IPv4。此规则**不**显式允许 IPv6 流量。此外，仅当没有编号更低的规则短路此规则时，此规则才生效。

### 88. B
`0.0.0.0/0` 代表 IPv4 地址，即整个互联网。然而，CIDR 块不代表任何类型的流量（入站或出站）。

### 89. C
`::/0` 代表 IPv6 地址，即整个互联网。然而，CIDR 块不代表任何类型的流量（入站或出站）。

### 90. B
`::/0` 代表 IPv6 地址，因此答案必须是 B 或 D。路由应从所有 IPv6 地址指向 NAT 网关的 ID，即 `nat-123456789`。路由中不应插入中间的 `-> NAT`。

## VPC 与子网

### 91. D
一个 VPC 跨越一个区域内的所有可用区。

### 92. B, C
创建 VPC 时必须始终选择一个区域，且必须始终提供一个 CIDR 块。VPC 跨越区域内的所有 AZ，因此这不是必需的；安全组关联在实例级别，而非 VPC 级别。

### 93. C
对于单个 VPC，可以在该 VPC 内的每个可用区中添加一个或多个子网。

### 94. B
子网不能跨越可用区。它只能添加到单个 AZ。

### 95. B
子网不能跨越可用区。它只能添加到单个 AZ，且只能存在于该单个 AZ 内。

### 96. B
一个 VPC 可以分配一个用于 IPv4 地址的主 CIDR 块和一个可选的 IPv6 CIDR 块。虽然可以添加辅助 IPv4 CIDR 块，但**目前无法**为 IPv6 添加额外的 CIDR 块。

### 97. C
一个 VPC 可以分配一个用于 IPv4 地址的主 CIDR 块和一个可选的 IPv6 CIDR 块。但是，可以向 VPC 添加**额外的**辅助 CIDR 块（最多四个）。

### 98. D
根据定义，任何通过互联网网关路由流量的子网都是公有子网。

### 99. B
公有子网中的实例不会自动可达。它们必须拥有公有 IPv4 或 IPv6 地址（B）或弹性 IP 地址。

### 100. D
公有子网以及现有的可访问互联网的实例表明互联网网关正常工作，因此 C 不正确。A 不是实际的 AWS 选项，B（Auto Scaling）无法解决公共访问问题。这留下了 D，这是正确的：公有子网中打算可通过互联网访问的实例，需要分配公有 IP 地址或弹性 IP 地址。

### 101. A, C
创建 VPC 时，可以指定可选名称、必需的 IPv4 CIDR 块和可选的 IPv6 CIDR 块。

### 102. A, C
创建 VPC 时，可以指定可选名称、必需的 IPv4 CIDR 块和可选的 IPv6 CIDR 块。创建时无法为 VPC 分配标签。

### 103. B, D
公有子网是指流量通过路由表（B）路由到互联网网关（D）的子网。

### 104. B, C
仅 VPN 子网通过虚拟私有网关而非互联网网关路由流量。

### 105. A, B
至少，仅 VPC 子网必须拥有路由流量的路由表和路由流量的目标虚拟私有网关。既不需要弹性 IP 地址，也不需要互联网网关。

### 106. B
默认情况下，每个区域只能创建 5 个 VPC。创建更多需要向 AWS 提交请求。

### 107. D
这是一个很高的数字，但准确：每个 VPC 可以创建 200 个子网。

### 108. B
这是一个非常难的问题，但可能会出现，尽管很少。此限制是指你的主 CIDR 块，外加 4 个辅助 CIDR 块。

### 109. B
除非 AWS 提高默认限制，否则每个区域允许 5 个弹性 IP 地址。

### 110. B, D
子网必须有 CIDR 块（因此 D 错误），且该块必须与其所在 VPC 的 CIDR 块相同或更小（更具体），因此虽然 A 和 C 正确，但 B 错误。

## VPC 对等连接与 VPN

### 111. C
VPC 对等连接通过网络和路由将一个 VPC 连接到另一个 VPC。

### 112. C
VPC VPN 连接将您的本地网络链接到 AWS 云中的一个 VPC。

### 113. A, C
VPC VPN 连接需要客户网关、VPN 连接和虚拟私有网关。

### 114. B, D
客户网关（A）和虚拟私有网关（C）用于 VPN 连接。为了安全，NACL（B）用于子网级别，安全组（D）可用于实例级别。

### 115. B
NACL 最适合在子网或 VPC 级别处理所有流量，因为它关联在子网级别。
