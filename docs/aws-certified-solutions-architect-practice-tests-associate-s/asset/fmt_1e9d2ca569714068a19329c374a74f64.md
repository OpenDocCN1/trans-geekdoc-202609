
# AWS 认证考试题目解析

## 实例定价模型

### 34. C
“Migration only”不是实例的定价模型。此处未提及的唯一模式是专用宿主机。

### 35. B
AWS 建议在 TCO 计算中使用预留实例定价，因为它与本地服务器在“苹果对苹果”的比较中最为接近。

### 36. A
标准预留实例通常比按需实例提供高达 75% 的折扣。

### 37. C
不存在“半预付”付款选项。有效选项为无预付、部分预付和全预付。

### 38. C
全预付是这三种选项中最便宜的，与按需定价相比节省最大。

### 39. B, D
预留实例可购买一年或三年期限。

### 40. A, C
竞价实例 (A) 是有效模型，但竞价市场 (B) 不是；竞价市场是购买竞价实例的地方。专用宿主机 (C) 是另一种有效模型。全预付是付款选项，而非实例的实际定价模型。

### 41. A
竞价实例推荐用于开始和结束时间灵活、需要以低计算价格运行、或可能对大量额外容量有紧急计算需求的应用程序。

### 42. B
当使用模式剧烈波动且无法预测时，按需实例是最佳选择。

### 43. B
按需实例非常适合以不可预测模式剧烈波动的任何使用情况，特别是作业无法中止时。如果使用可预测，长期运行的作业可能受益于预留实例；如果作业可停止，则竞价实例会更好。

### 44. A, D
这有点棘手，因为专用宿主机在购买和付款方面与其他实例类型运作略有不同。重要的是要注意问题问的是购买，而*非*付款（那会引导你回答“全预付”、“部分预付”或“无预付”）。专用宿主机可作为按需实例购买，或作为预留实例购买以获得大幅节省。

### 45. B, C
预留实例是稳态应用程序的最佳选择，且至少需要一年承诺，这指向选项 B 和 C。

### 46. D
竞价实例不适合使用高峰，因为这些实例可能随时被终止。

### 47. B
在此场景中，你需要确保实例保持运行（排除竞价市场）且无长期承诺（排除预留实例）。专用宿主机不合理，因此剩下按需实例。

### 48. A, B
竞价市场提供可随时停止和启动的实例。这些实例上的应用程序可以被停止和重启 (A)。此外，成本显著低于按需定价 (B)。然而，硬件可能频繁变更，使用高峰*不*适合竞价实例。

## 存储与数据传输成本

### 49. D
在纯“每 GB 存储”对比中，Amazon Glacier 是成本最低的存储类别。

### 50. A
S3-SSE 是一种加密解决方案。Standard IA 为低频访问，RRS 为冗余降低（现已弃用），当然 Glacier 是有效的 S3 存储类别。

### 51. C
上传数据是入站流量的教科书式定义，入站流量从不产生相关费用。

### 52. A
将数据移入 CloudFront 始终免费。从 CloudFront 流出可能有成本，但传输到 CloudFront 是零成本的。

## AWS 免费套餐与市场

### 53. B
AWS 免费套餐*仅是 AWS* 但无成本。你可以在 AWS 免费套餐内免费使用多项服务（数据传输、计算、存储等）直到若干限额。

### 54. D
AWS Marketplace 提供免费和付费软件产品，许多运行于 AWS 免费套餐上。你可以找到 AMI 和服务，以及来自第三方的许多试用产品。

### 55. D
AWS 免费套餐提供付费 AWS 几乎所有功能，只是量级较低。

## AWS 支持计划

### 56. D
四种 AWS 支持计划为：基础版、开发者版、商业版和企业版。

### 57. C, D
这很直观：更高级、更面向业务的支持级别提供 7x24 小时支持；本例中为商业版和企业版。

## AWS Trusted Advisor

### 58. B
`AWS Trusted Advisor` 是一项在线资源，帮助你降低成本、提高性能和改善安全性。但它不提供日志记录 (C)，也不影响 Auto Scaling 限制或配置。

### 59. C
有五项核心 `Trusted Advisor` 检查：成本优化、安全、容错、性能和服务限制。注意：某些地方 AWS 称有七项检查，另一些称五项。最新文档显示此处所述的五项检查。

### 60. A, B
`AWS Trusted Advisor` 提供的建议通常适用于所有环境、所有用例。在此组答案中，符合该标准的有两项：为根账户开启 MFA 和避免 S3 存储桶的全球互联网访问。这些建议几乎适用于所有情况。其他两项——C 和 D——针对特定用例，因此不会由 `Trusted Advisor` 建议。

### 61. D
`AWS Trusted Advisor` 会就 S3 存储桶使用、IAM 使用和快照（EBS 和 RDS 皆有）提出建议，但不针对 DNS 提出建议，因此 D 正确。

### 62. B
`AWS Trusted Advisor` 在五大类别中提出建议：成本优化、性能、安全、容错和服务限制。

### 63. A, D
`AWS Trusted Advisor` 在五大类别中提出建议：成本优化、性能、安全、容错和服务限制。

### 64. A, C
首先，C 是容易的选择：根账户 MFA 是最常见的建议之一。然后，考虑 `Trusted Advisor` 可提出绝对建议的领域；DNS 记录利用不足讲不通（如何“利用不足 DNS”？），而确定“正确”的 S3 存储类别涉及理解用例，这是 `Trusted Advisor` 无法做到的。剩下 A，空闲负载均衡器。

## 成本优化建议

### 65. A, B
AWS 提出五项标准建议：调整服务规模以最低成本满足容量需求、通过预留省钱、使用竞价市场、监控和跟踪服务使用情况、使用 `Cost Explorer` 优化节省。

### 66. C
AWS 提出五项标准建议：调整服务规模以最低成本满足容量需求、通过预留省钱、使用竞价市场、监控和跟踪服务使用情况、使用 `Cost Explorer` 优化节省。使用竞价市场 (C) 属于最后一类。其他答案均由用例驱动，不适合通用成本节省建议。

## AWS Cost Explorer 与 Budgets

### 67. C
这很基础：`AWS Cost Explorer` 通过分析提供报告，用于评估你随时间推移的总体 AWS 成本。

### 68. B
这主要取决于识别有效的 AWS 工具——`AWS Trusted Advisor` 和 `AWS Cost Explorer`——然后确定哪个处理成本。本例中是 `AWS Cost Explorer`。

### 69. B
`Cost Explorer` 提供 EC2 月度成本和使用报告，有助于分析实例的月度支出。

### 70. C
虽然 `AWS Cost Explorer` 可提供月度存储成本信息，但 `AWS Budgets` 允许你设置警报并添加自定义编程以减少或停止这些成本。

### 71. D
这是个重要问题。列出的工具均不允许在成本阈值处进行实际“切断”。`AWS Budgets` 允许在达到阈值时发送通知，但*不*允许自行在特定点切断支出。

### 73. A
