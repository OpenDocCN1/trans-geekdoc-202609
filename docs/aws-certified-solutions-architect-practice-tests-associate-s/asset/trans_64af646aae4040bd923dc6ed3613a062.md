

## 18. C
A 记录用于将特定域或子域指向 IP 地址。CNAME 指向不同的 URL，而该 URL 又可由 DNS 进一步解析。在这种情况下，你需要为 `applestoapples.com` 创建一条 CNAME 记录，并将该记录指向 `applestoapples.net`，然后让 DNS 解析该域名。使用 A 记录意味着你必须将记录锁定到特定的 IP 地址，而不是 `applestoapples.net` 的域名。不过，这会带来一个问题，因为随着时间的推移，该域名可能由具有不同 IP 地址的不同资源提供服务，从而导致 A 记录过时且不正确。

## 20. A

## 21. A
AWS 为所有域支持区域顶点记录。区域顶点记录是 DNS 区域根节点（或顶点）处的 DNS 记录。因此 `amazon.com` 是一条顶点记录（有时称为裸域记录）。Route 53 完全支持区域顶点记录，并允许在此级别使用别名记录（A 记录类型）。

## 22. A, D
首先，A 是错误的。区域顶点记录是 DNS 区域根节点（或顶点）处的 DNS 记录。因此 `amazon.com` 是一条顶点记录（有时称为裸域记录）。Route 53 完全支持区域顶点记录，并允许在此级别使用别名记录（A 记录类型）。D 也是错误的；Route 53 同时支持 AWS 和非 AWS 域及服务的区域顶点记录。

## 23. A, D
Route 53 设计上具有可扩展性，因此无需采取任何步骤即可使其高可用；这使得 D 为真。此外，它支持所有 AWS 服务，包括自动扩展，因此 A 为真。

## 24. D
默认情况下，单个账户可以使用 Route 53 管理 50 个域。不过，这是一个默认值，如果你致电 AWS 并说明管理额外域名的需求，AWS 非常乐意提高该限额。

## 25. D
RDS 是由 AWS 管理的系统，不允许对其底层操作系统进行任何访问。

## 26. C, D
VPC 对等连接是两个 VPC 之间的网络连接，但不限于单个区域（因此 A 错误），也不是基于 VPN 或网关的（因此 B 错误）。这留下了 C 和 D，两者均为真：VPC 可用于共享数据，并可跨区域建立对等连接。

## 27. B
AWS 将跨区域的两个 VPC 之间的对等连接称为跨区域 VPC 对等连接。

## 28. C
建立 VPC 对等连接时，每个 VPC 都需要手动添加一条路由，以允许与对等 VPC 通信。

## 29. D
这些陈述大多是错误的：不同区域的 VPC（A）和不同账户的 VPC（B）可以建立对等连接，如果两个 VPC 在同一账户中，它们可以共享安全组（C）。但是，两个对等 VPC *不能* 拥有重叠的 CIDR 块（D）。

## 30. B
一个 VPC 可以有多个子网，因此 VPC 对等关系是两个 VPC 之间的一对一关系（B）。

## 31. C
虽然传递性对等关系不被允许（A）是真的，但你仍然可以将 VPC B 和 VPC C 建立对等连接，以允许流量在两个 VPC 之间流动。

## 32. B, C
具有重叠 CIDR 块的 VPC 不能直接建立对等连接（B），因此必须消除重叠（C）。将任一 VPC 更改为 IPv6 *可能* 是一个可行的解决方案（D），但不是必须的。

## 33. A
无论子网、NACL 或任何其他网络考量如何，同一时间在两个 VPC 之间只能创建一个 VPC 连接。

## 34. B
一个 VPC 可以参与无限数量的 VPC 连接，只要这些连接都是与不同的 VPC 建立的，并且你保持在 AWS 的总体账户限制内。两个特定 VPC 之间只能存在一个对等连接；例如，VPC A 和 VPC B 之间只能存在一个连接。但 VPC A 可以拥有任意数量的对等连接——每个连接对应一个不同的 VPC——最多可与你能连接的 VPC 数量相同。

## 35. C
AWS 中不允许传递性 VPC 关系。这些答案大多完全是胡扯！

## 36. B, D
首先，AWS 不支持 IPv6 跨区域通信。这意味着为了使 IPv6 通信工作，两个 VPC 必须位于同一区域（D）。然后，你必须确保两个 VPC 都具有 IPv6 地址，并且路由已设置为使用这些地址（B）。

## 37. A, C
EC2-Classic 是一个扁平网络，提供的选项非常少。使用 VPC，你可以分配多个 IP 地址以及多个网络接口（A 和 C）。

## 38. A, D
默认 VPC 同时附带 Internet 网关和公有子网。如果你仔细思考，这两者是相辅相成的：公有子网需要 Internet 网关才能作为公有子网发挥作用。

## 39. A, D
默认 VPC 内包含公有子网。此外，它提供了一张默认路由表，为这些实例与公共 Internet 之间的访问提供通道（A）。另外，Internet 网关默认会被添加到 VPC 中（D）。

## 40. C
非默认子网及其实例默认不是公有的。因此，它们被分配私有 IPv4 地址（C），而不是公有地址。

## 41. B, C
非默认子网默认是私有的。因此，你需要在包含的 VPC 上配置 Internet 网关（C），并为实例分配公有 IP 地址（B）。虽然 NAT 实例*可能*有效（D），但它需要位于不同的公有子网中，而不是位于试图访问 Internet 的实例所在的同一子网中。

## 42. D

## 43. C
