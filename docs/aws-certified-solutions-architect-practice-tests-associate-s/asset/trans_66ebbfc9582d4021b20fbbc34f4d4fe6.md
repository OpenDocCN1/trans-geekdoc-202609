

# 试题解析

## 105. C
失效 API 是移除文件或对象的最快方式，尽管通常会产生额外费用。

## 106. A
S3 始终是可用性最高的 S3 存储类。这应该是一个简单的正确答案。

## 107. D
这有点棘手。虽然 S3 可用性更高，但所有基于 S3 的存储类都提供相同的首字节延迟：毫秒级。请记住性能是相同的；可用性则不同。

## 108. D
这是另一个半陷阱问题。除 Glacier 外，从各种 S3 存储类检索数据几乎是相同的（不考虑网络问题）。这些类在可用性上有所不同，但在数据访问速度上没有差异。（它们在数据访问次数收费方面也有所不同。）

## 109. C
使用标准类进行 Glacier 数据检索，平均需要 3–5 小时。

## 110. B
S3 和 S3-IA 的区别在于成本和访问频率（B）。检索速度与 S3 一样快（因此 A 错误），且 S3-IA 中的数据是冗余存储的（C 和 D 错误）。

## 111. C, D
C 和 D 都是错误的。RDS 实例不能作为源服务器，且默认过期时间是 24 小时，而非 12 小时。

## 112. D
CloudFront 允许将所有这些作为源服务器：S3、EC2 实例、ALB 等。

## 113. D
边缘位置的集合称为分发。

## 114. C
RTMP 分发是 Adobe 实时消息传递协议，适合使用 S3 存储桶作为源服务器来提供流媒体服务。

## 115. A, C
CloudFront 支持 Web 分发和 RTMP 分发。媒体分发和边缘分发不是有效的分发类型。

## 116. A, B
您可以直接对边缘位置的对象进行读写。您不能直接删除或更新它们；只有 CloudFront 服务可以处理这些操作。

## 117. A, D
ElastiCache 非常适合高性能和实时处理以及繁重的商业智能。它在离线事务中表现不佳（速度不那么重要），完全不适合长期或记录存储。

## 118. B, D
应将 ElastiCache 视为仅适用于存储瞬态数据。此外，它不是持久存储；因此，它非常适合缓存来自数据库或消息服务的数据。

## 119. A, C
应将 ElastiCache 视为仅适用于存储瞬态数据。此外，它不是持久存储；因此，它非常适合缓存来自消息队列的数据或提供非常快速的临时存储。

## 120. A
ElastiCache 使用分片作为单个 Redis 节点的分组机制。因此，单个节点属于一个分片，而分片又属于一个集群（选项 A）。

## 121. D
使用缓存卷的存储网关将缓存频繁访问的数据，同时将整个数据集存储在 AWS 的 S3 中。

## 122. C
使用存储卷的存储网关将在本地存储所有数据，同时将数据备份到 AWS 的 S3 中。

## 123. C
使用存储卷的存储网关将在本地存储所有数据，而所有其他解决方案都将数据存储在云中。访问本地数据始终比访问云数据快。

## 124. A
使用存储卷的存储网关将在本地存储所有数据，提供对该数据的低延迟访问。此外，整个数据集备份到 S3 以实现灾难恢复。S3 具有持久性和可用性，但访问速度不如本地数据快。VTL 提供磁带备份接口，但不一定提供快速数据访问。

## 125. B
问题在于尝试标记单个文件夹。您可以使用 IAM 进行权限控制，但特定文件夹无法与其他文件夹分开单独标记；只能对整个存储桶进行标记。

## 126. D
使用存储卷的客户网关为文件访问提供最低延迟。缓存卷不适用，因为关注点是大多数文件，而非仅一小部分子集。

## 127. A
在所有区域配置读取副本将为分布在这些相同区域的客户提供最佳读取响应时间（A）。虽然使用多个区域确实提供了一些灾难恢复帮助，但读取副本并不是特别有效的灾难恢复方法。至于选项 C，读取副本不会增加网络吞吐量；它们只是将负载分散到副本上，这可能会也可能不会使相关网络不再饱和。

## 128. C
读取副本最终是为了给客户提供更快的读取访问。如果所有客户都在一个区域，那么向其他区域添加读取副本几乎没有优势。相反，在与客户相同的区域提供副本可为他们提供最快的访问（C）。

## 129. B
有人可能会为选项 A 辩护；如果附近区域有资源，客户不会被路由到不同的区域（因此 C 错误），且 D 在这里讲不通。但是，如果主区域完全故障，您可以将另一个区域中的副本转换为主数据库，这意味着 B 有一定道理。

## 130. A, D
读取副本可以手动备份，当然也可以读取。然而，它们实际上变成了只读实例，因此无法写入。您也无法故障转移到读取副本。您可以将其转换为独立实例，但这是一个手动过程，不属于故障转移。因此，A 和 D 是正确的。

## 131. A, D
这是一个棘手的问题，因为除了知道数据库总体性能不佳外，没有太多背景信息。然而，在给定的选项中，切换到 DynamoDB 和添加 Multi-AZ 对提高性能帮助不大。（注意，切换到 DynamoDB 可能有帮助，因为 DynamoDB 会自动扩展以处理负载，但这仍然不是可用答案中的最佳选择）。添加读取副本和考虑更大的实例是基于此有限背景更稳妥和更好的答案。

## 132. C, D
只有 C 和 D 会产生保证的效果。虽然 S3 可能会更快地交付 PDF，但您仍然会在 AWS 上产生大量网络流量，并且根据此处的信息，无法保证 S3 比 RDS 更快。B 看起来有吸引力，但请注意文件访问不频繁。这意味着缓存无法帮助响应时间，因为文件访问不够频繁，缓存无法生效并发挥作用。最佳选择是设置读取副本并考虑升级数据库实例。

## 133. B, C
考试中通常有很多“数据库不堪重负”的问题，这是其中之一。关键在于理解数据访问不频繁，这意味着缓存解决方案（A 和 D）可能无济于事。此外，员工在现场，这意味着客户网关（C）可能是一个有效的解决方案。最后，至少考虑升级数据库实例几乎总是稳妥的。

## 134. B
此处的关键细节是数据访问不频繁且客户群在地理上分布广泛。这意味着跨全国分布的读取副本是最佳选择（B）。缓存无济于事，因此 A 和 D 排除，存储网关无法帮助不在现场访问数据的客户。

## 135. D
这是一个棘手的问题，因为有几个答案都是有效的。然而，关键考量因素是单个图片每天被访问数千次。与其增加实例性能或读取副本（A 和 B），缓存图片是最佳方法，因为它减少了总体数据库读取。通常，从缓存（D）提取图片比执行数据库读取快得多。

## 136. A, C
Route 53 提供多种不同的路由策略：简单、故障转移、地理位置、地理邻近性、基于延迟、多值回答和加权。

## 137. A, B
Route 53 提供多种不同的路由策略：简单、故障转移、地理位置、地理邻近性、基于延迟、多值回答和加权。
