# Appendix

Answers to Review Questions

## Domain 1: Design Resilient Architectures（设计弹性架构）

1.  **B**. 这是 AWS 考试中的常见问题，考察您对各种 S3 存储类别的理解。S3 和 S3-IA 具有相同的持久性，但 S3 的可用性比 S3-IA 高一个 9。S3 的可用性为 99.99%，而 S3-IA 为 99.9%。Glacier 的首字节延迟比 S3 大得多，因此 C 和 D 都是错误的。

2.  **B**. 只要主要考量是具有本地数据存储的存储——即数据必须存储在本地或被视为存储在本地——Storage Gateway（存储网关）就是最佳选择。这将选项缩小到 B 和 D。B 会将文件存储在 S3 中并提供本地缓存副本，而 D 会将文件存储在本地并将其推送到 S3 作为备份。由于管理层担心主要文件存储在云端，B 是最佳选择；本地文件是主要数据源，同时仍允许公司尝试云存储，而无需“冒险”将数据主要存储在云端。

3.  **B**. 这些答案中有很多在 AWS 允许的范围内讲不通。与 S3 相关的大小限制针对的是对象；单个对象最大可达 5 TB。因此 A 和 C 都没有用（或不可能）。D 提议将最大对象大小增加到 50 GB，但最大对象大小已经是 5 TB。选项 B 是正确的；AWS 建议对所有大于 100 MB 的对象使用 Multipart Upload（分段上传）。

4.  **C, D**. 新对象的 PUT 操作具有写后读一致性。DELETE 和覆盖 PUT 操作在 S3 中具有最终一致性。

5.  **C**. 首先，请注意“on standard class S3”是干扰项，与问题无关。其次，S3 上的对象可以为 0 字节。这相当于对文件使用 `touch` 命令，然后将该 0 字节文件上传到 S3。

6.  **A**. 这需要仔细查看每个 URL。存储桶名称（当不作为网站使用时）总是出现在完全限定域名（FQDN）之后；换句话说，在正斜杠之后。这排除了 C。此外，区域在 FQDN 中总是出现在 `amazonaws.com` 之前，这排除了 D。剩下 A 和 B。两者中，A 正确包含了完整的区域 `us-east-2`。

7.  **C**. 除非您逐段分析 URL 的每一部分，否则这是另一个棘手的问题。第一个线索是这是一个托管在 S3 上的网站，而不是直接访问 S3 存储桶。就网站托管而言，存储桶名称是 FQDN 的*一部分*；而就直接存储桶访问而言，存储桶名称出现在 FQDN *之后*。这是一个关键区别。这意味着 A 和 B 无效。然后，您需要回忆 FQDN 的 `s3-website` 部分总是与区域相连；换句话说，它不是一个子域名。唯一符合这种情况的选项是 C。

8.  **A**. 这又是一个死记硬背的问题。S3 和 S3-IA 具有相同的持久性；然而，S3 的可用性更高（99.99% 对比 S3-IA 的 99.9%）。Glacier 和 S3-IA 都具有与标准 S3 相同的持久性，因此 C 和 D 都是错误的。

9.  **B**. 这是理解 S3 存储类别时的一个重要区别。标准 S3、S3-IA 和 S3 One Zone-IA 具有同等的持久性，尽管在 One Zone-IA 中，如果可用区被破坏，数据将会丢失。但每个类别的可用性不同：S3 为 99.99%，S3-IA 为 99.9%，S3 One Zone-IA 为 99.5%。因此，说它们都具有相同的可用性（B）是错误的。

10. **A, C**. 此问题的措辞至关重要。S3 存储桶是在某个区域中创建的，但 AWS 控制台和您的账户将始终向您显示*所有*区域中的*所有* S3 存储桶。虽然存储桶是在特定区域创建的，但存储桶名称也是全局的。IAM 权限也是全局的，并影响所有区域。RDS 和 EC2 实例是特定于区域的，并且仅在 AWS 控制台中它们被创建的区域中显示。

11. **A, D**. EBS 卷是基于块的存储，因此 A 正确，B 错误。这留下了 C 和 D。默认 EBS 卷是 SSD，所以 C 是错误的。然而，EBS 卷可以是多种类型，包括磁盘和 SSD 选项，所以 D 是正确的。

12. **D**. 无论账户或安全组如何，AMI 都不是跨区域的。这使得 B 和 C 无效。A 是一个有效的选择，但不会保留允许实例连接到 S3 的任何权限或角色。因此，D 是正确选项：需要在 AMI 复制*后*手动配置 AMI，以确保正确操作。

13. **D**. 如果您不小心，这是一个陷阱问题。虽然 S3 允许 0 字节对象并按此收费，但 S3-IA 会按所有对象*至少* 128 KB 的大小收费。因此，虽然您可以在 S3-IA 中存储较小的对象，但出于定价和计费目的，它将被视为 128 KB。

14. **A, D**. Multi-AZ 部署是最简单且最常见的解决方案。开启读取副本（选项 B）不能保证高可用性，因为读取副本不会自动安装在不同的 AZ 或区域中。然而，选项 D 的跨区域副本配置将确保使用多个区域。Storage Gateway（选项 C）由 S3 支持，而非 RDS。

15. **A, D**. Launch configurations（启动配置）主要关注创建新实例，同时抽象掉实例上内容的细节。因此，实例的 AMI 和 IAM 角色是通用配置，适用于所有创建的实例，这是正确的（A 和 D）。延迟的轮询时间与启动新实例无关（尽管它可能是在其他地方配置的触发器）。每个实例关联不同的 EBS 卷，因此为多个实例选择一个 EBS 卷实际上讲不通。

16. **D**. Launch configurations（启动配置）是指定创建（启动）新实例详细信息的地方（选项 D）。安全组更多地与允许进出已启动实例的流量有关。其余两个选项 A 和 C 在此上下文中讲不通。

17. **D**. 默认情况下，EBS 根卷会在关联实例终止时被终止。然而，这只是默认值；因此 A 不正确。选项 B 并未直接解决问题；即使您创建快照，EBS 卷仍会被删除。选项 C 不相关，但选项 D 相关：您可以使用 AWS CLI（或控制台）将根卷设置为在实例终止后保留。

18. **B**. EBS 卷以增量方式备份到 S3。

19. **B**. EBS 卷一次只能挂载到单个实例。其他选项只是干扰项。

20. **A, B**. AWS 中的所有实例和大多数服务都提供标记功能用于元数据。Certificates（证书）与 SSL 相关，有助于定义站点或传输的身份；Policies（策略）与权限和角色相关；Labels（标签）目前不是 AWS 的构造。

21. **A, B**. 此列表中的有效顾虑包括将存储放置在靠近用户的位置以减少网络延迟，以及与运营中心的距离。后者不太明显，但核心在于灾难恢复场景：如果灾难摧毁了您的运营中心，您不会希望您在 AWS 上的存储在地理上位于同一区域。

22. **B**. 每个 EC2 实例都提供指定可用区的选项。虽然您不必指定默认值以外的内容，但实例始终在特定的可用区中预配，这是用户可配置的。
