## 31. SQS 消息顺序问题
你正在调查一个使用 SQS 队列的应用程序。消息能到达队列，但这些消息没有按照被队列接收的顺序进行处理。你想要确保顺序得以保留；应该怎么做？

1.  更新队列以使用标准投递，这样投递总是至少发生一次。
2.  **将队列更改为 FIFO 队列，这将确保顺序得以保留。**
3.  通过 AWS CLI 更新队列以使用“按顺序投递”选项。
4.  将队列更改为 LIFO 队列，这将确保顺序得以保留。

## 37. 提升 RDS MySQL 性能并降低成本

1.  从 RDS 迁移到安装了数据库的 EC2 实例。调整实例大小并为应用程序需求定制数据库安装。
2.  **在 RDS 中从 MySQL 迁移到 Aurora，因为 Aurora 始终显示出比 MySQL 更好的性能。**
3.  在 RDS 中从 MySQL 迁移到 Oracle 并添加所需的 Oracle 许可证以增加整体 RDS 集群大小。
4.  停止 RDS 集群，然后调整所有实例的大小。重启集群，保持 MySQL 数据库完好无损。

## 41. 基因组学非营利组织数据处理成本优化
你最近接手了一家大型基因组学非营利组织的架构工作。目前，该组织每天导入数百 TB 数据，然后需要针对这些数据运行复杂查询。查询可能需要数小时甚至数天才能完成。它们频繁将状态写入 S3，以便查询能从故障中恢复而无需重启。该组织希望最大限度地降低与该处理相关的成本。你可能会建议哪些技术和建议？（选择两项。）

3.  设置一个置放群组，包含可从 SQS 队列读取并针对引用数据运行查询的 EC2 实例。
4.  **设置可从 SQS 队列和 S3 读取并在这些实例上运行查询的 EC2 Spot 实例。**

## 42. 增加 Spot 实例使用率

1.  将按需处理实例转换为 Spot 实例，以便有更多 Spot 实例可用。
2.  将工作节点实例转换为 Spot 实例，以便有更多 Spot 实例可用。
3.  降低 Spot 实例的竞价价格，以确保仅使用低价实例。
4.  **提高 Spot 实例的竞价价格，以便它们在终止前运行更长时间。**
