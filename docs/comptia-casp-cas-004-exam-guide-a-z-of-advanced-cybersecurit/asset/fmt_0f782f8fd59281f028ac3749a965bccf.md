# Whois

**Whois** 是一种协议，通过查询提供互联网资源所有者信息的数据库（如域名、IP 地址块和**自治系统**（`AS`）编号），在互联网上定位私有**边界网关协议**（`BGP`）网络。这些数据是信息金矿，可用于改进网络攻击。Whois 最初是一个命令行界面程序，但现在也可通过基于 Web 的解决方案使用。尽管美国执法机构声称 Whois 是调查垃圾邮件和语音钓鱼的重要工具，但**互联网名称与数字地址分配机构**（`ICANN`）呼吁用一个系统取而代之，该系统对大多数互联网用户隐藏信息，仅因“允许的”理由披露。

为从 Whois 数据库中删除其信息，多家公司采用第三方隐私服务。虽可行，但公众可能会猜测组织在隐瞒什么，从而降低与公司合作的意愿。因此，您应在决策时权衡利弊。*图 12.4* 展示了域名搜索的部分 Whois 输出；可见该工具能提供大量公司信息：

# 路由表

路由发生在 OSI 模型的第 3 层。这也是 IP 运作并携带源、目的 IP 地址路由数据包的层。路由器是一种在不同 IP 网络的系统间收发数据的设备。计算机连接多个 IP 网络时，若无路由器将消息路由至适当网络，则无法通信。路由器使用**路由表**存储通往其他网络的路径信息。填充这些表的方式有多种——管理员可手动录入路由（静态路由），或路由器通过动态路由协议交换路由表和信息。

手动设置（即静态路由）的优势在于消除动态路由协议产生的额外流量，并可精细控制路由行为；但链路故障时需人工干预。动态路由协议会产生流量，但也能在无人工干预下响应链路故障并重定向流量。就安全而言，路由协议存在路由更新流量被拦截的风险，黑客可借此获取网络拓扑的关键知识。此外，思科设备（可能是使用最广泛的网络设备）默认使用专有的第 2 层协议**思科发现协议**（`CDP`）相互通告能力。

捕获 `CDP` 数据包可获取更多信息，有助于攻击前绘制网络地图。黑客还可将流氓路由器接入网络，更新或替换合法企业路由器的路由表。黑客这样做是为了了解网络路由和基本拓扑，并用错误路由污染路由表以辅助攻击。以下是路由表被攻陷前的示例：

```
Source Network Next hop Exit interface
10.110.0.0 [110/5] via 10.120.254.6, 0:01:00, Ethernet2
10.67.10.0 [110/128] via 10.120.254.244, 0:02:22, Ethernet2
10.68.132.0 [110/5] via 10.120.254.6, 0:00:59, Ethernet2
10.130.0.0 [110/5] via 10.120.254.6, 0:00:59, Ethernet2
10.128.0.0 [110/128] via 10.120.254.244, 0:02:22, Ethernet2
10.129.0.0 [110/129] via 10.120.254.240, 0:02:22, Ethernet2
```

路由表显示路由器通往外部网络的路由。本例中第一列显示路由信息来源。该路由器通过**开放最短路径优先**（`OSPF`）协议知晓这些网络。第二列显示远端网络，第三列列出访问该网络的下一跳 IP 地址（另一路由器），第四列列出路由器上的本地出接口。黑客说服本地路由器共享路由信息并污染本地路由表后，路由表变为如下所示：

```
10.110.0.0 [110/5] via 10.120.254.6, 0:01:00, Ethernet2
10.67.10.0 [110/128] via 10.120.254.244, 0:02:22, Ethernet2
10.68.132.0 [110/5] via 10.120.254.6, 0:00:59, Ethernet2
10.130.0.0 [110/5] via 10.120.254.6, 0:00:59, Ethernet2
10.128.0.0 [110/128] via 10.120.254.244, 0:02:22, Ethernet2
10.129.0.0 [110/129] via 10.120.254.178, 0:02:22, Ethernet2
```

观察 `10.129.0.0` 网络的路径。它现在路由至 IP 地址 `10.120.254.178`，即黑客的路由器地址。黑客可将原本发往安全服务器 `10.120.154.180` 的所有流量重定向至其控制的服务器 `10.120.154.181`。随后，黑客可收集真实安全服务器的用户名和密码。

为防止此类攻击，路由器应配置认证，以识别并验证其通信的任何路由器。若连接配置为使用**点对点协议**（`PPP`）封装，路由器可配置为相互认证。`PPP` 是一种第 2 层协议，在路由器接口上用命令 `encapsulation ppp` 即可轻松启用。启用后使用两种认证形式——`PAP` 和 `CHAP`。**密码认证协议**（`PAP`）以明文发送凭证。**质询握手认证协议**（`CHAP`）更优，因为它从不在网络上传输凭证。`CHAP` 流程如下：

**步骤 1**：本地路由器向远程路由器发送质询消息。

**步骤 2**：远程节点用加盐密码的 `MD5` 哈希计算值进行响应。

**步骤 3**：本地路由器用相同密码验证哈希值，从而在不发送密码的情况下确保远程路由器知晓密码。
