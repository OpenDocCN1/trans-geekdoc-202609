# 第3章：组织安全策略和文档

## 简介

在上一章中，我们了解了业务对安全的影响。应实施IT治理文档，以确保组织资产尽可能受到保护。本章解释如何管理流程和策略生命周期，以及如何支持法律合规。它讨论了常用于支持安全的业务文档和合同。它还涵盖了一般隐私原则。最后，它讨论了包含标准安全实践的策略制定。

## 目标

本章将讨论为保护组织资产而实施的IT安全策略和治理程序。本章将呈现安全策略生命周期的创建、实施和管理。利用业务合同建立服务级别协议和项目文档以支持安全也将在本章涵盖。支持安全的业务文档将被详细阐述，其中包括风险评估、BIA、协议、MoU和SLA等。本章还将介绍职责分离、工作轮换、最小权限、应急响应和其他程序等标准安全实践。

## 流程生命周期管理

管理层发起、支持并推动安全计划，采取**自上而下的方法**。员工在获得管理层的指导和帮助之前，采取**自下而上的方式**构建安全计划。因为管理层的支持是安全计划中最关键的组成部分之一，所以自上而下的策略比自下而上的方法要高效得多。自上而下的方法有助于确保公司的政策与其战略目标保持一致。在组织安全的背景下，策略是组织确定的行动准则或原则，而流程是为达到特定目标而进行的一系列活动。流程是按特定顺序或特定方式执行的一组操作。组织内部所有重要的决策和活动都由政策、程序和流程决定，所有组织任务都在政策、程序和流程所施加的边界内运行。策略首先被制定，以指导程序和流程的构建，从而理解三者之间的联系。流程提供了流程内任务的高层视角。程序是完成任务的分步说明，如 **[图 3.1](#c03.xhtml#fig3_1)** 所示。

### 场景

假设一家公司有一套处理**应付账款**的特定程序。接收发票、录入发票、授权付款、打印支票、签署支票和邮寄支票都是围绕该策略制定的流程中必须完成的高层操作示例。流程中每个任务所涉及的每个步骤都将记录在程序中。如 **[图 3.1](#c03.xhtml#fig3_1)** 所示，策略应基于以下生命周期编写：

1.  **制定/设计策略**
2.  **执行建模和质量控制**
3.  **获得策略执行批准**
4.  **发布/执行策略并执行定期监控和检查**
5.  **为优化进行审查，如不再需要或不再适用则归档策略**

公司、技术、风险和环境的变化不断要求进行策略审查，例如采用新技术、兼并收购或发现新的攻击方法。如果员工想要从家中访问商务电子邮件和共享驱动器，或者以前从未授予远程访问权限，但突然因需要提高生产力和快速响应客户请求而需要远程访问，公司应评估该需求以确定其是否合理。如果公司决定启用远程访问，安全专家应基于外部环境具有敌意的假设来规划和设计安全策略。在批准之前应进行质量检查，以确保策略符合所有适用的法律、法规和标准。策略最终确定后，公司必须确保所有受影响的员工得到适当通知。新策略应包含在此人接受的任何培训中。如果需要更改策略，应使用版本控制以确保在整个公司使用最新版本。如果策略不再适用，则应将其归档。策略至少每年审查一次，并应经常性地进行审查。

该生命周期的第一阶段是研究策略，第二阶段是基于策略构建流程。流程部署后，所有参与该流程的员工都应了解新流程如何运作。应定期审查该方法，如果出现问题或主要策略被修订，则进行调整。请记住，策略指导程序的创建。每当实施新策略时，就需要一个新流程。如果策略被修订或废弃，该策略的程序也应被修订或废弃。程序必须在策略和相关流程记录完成后编写。

程序最接近计算机和其他设备，包含员工预期遵循的所有特定活动。程序中常见的是策略和流程执行的分步列表。在组织评估业务、技术、风险和环境变化以建立和更新策略后，必须接下来设计和更新其流程和程序，以反映新的或更新后的策略，以及环境和业务变化。例如，如果业务更换为其采用的最新版本的备份软件，则可能需要调整程序。

大多数软件更新涉及检查现有方法并决定如何更改它们。例如，假设管理层希望聘请更多外部承包商来完成工作。公司可能需要实施一种新方法来评估外部承包商工作的质量。

作为最后一个例子，假设一家公司希望用多台Linux服务器取代其现有的Microsoft文件服务器。虽然高层策略将保持不变，但实施这些规则的方法将需要修订。如果一家公司的市场部门需要与其合作伙伴和客户进行更多实时交互，并决定在多个社交网站上建立形象以共享信息，则该公司需要指派一组受过培训的人员代表公司发布信息，并培训其他员工如何共享信息。变更管理、配置管理、网络访问程序、无线访问程序和数据库管理程序只是需要考虑的几个流程和程序。
