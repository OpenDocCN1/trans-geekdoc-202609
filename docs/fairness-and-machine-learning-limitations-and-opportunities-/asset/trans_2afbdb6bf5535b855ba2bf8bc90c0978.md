
在所有使用保留法（holdout method）的应用中，期望是测试集将作为一份新鲜的样本，为所有模型提供良好的性能估计。核心问题是实践者并非只使用测试数据一次，随后立即弃用；相反，测试数据被逐步用于逐个构建模型，并结合之前从测试数据中获得的反馈。这导致人们担心最终模型会对测试数据产生 `overfit`。这种过拟合有时被称为 `adaptive overfitting` 或 `human-in-the-loop overfitting`。

Richard Duda、Peter Hart 和 David Stork 在其 1973 年的教材 \[[507](#references.xhtml#ref-507)\] 中精辟地概括了这一问题：

在模式识别早期的工作中，实验常常使用非常小的样本数量，同一数据集常被用于设计和测试分类器。这一错误常被称作“在训练数据上进行测试”。一个相关但不太明显的问题出现在分类器经过一系列以同一数据集反复测试的结果为指导的细化时。这种“在测试数据上进行训练”的形式往往在新测试样本获得之前并不被注意到。

近五十年后，Trevor Hastie、Robert Tibshirani 和 Jerome Friedman 仍在 2017 年版的影响力教材 \[[508](#references.xhtml#ref-508)\] 中提醒我们：

理想情况下，测试集应被保存在“保险库”中，仅在数据分析结束时才取出。假设我们反而多次使用测试集，选择测试集错误最小的模型。那么最终选定模型的测试集错误会低估真实测试错误，甚至可能显著低估。

虽然将测试数据保存在“保险库”看似安全，但这与现代实践的现实相去甚远。流行的测试数据集常常会被进行数万次的评估。

然而，适应性过拟合似乎并未普遍发生。回顾 Recht 等人的散点图：图中显示出一条正斜率的清晰线性拟合。换句话说，模型在旧测试集上的表现越好，它在新测试集上的表现也越好。请注意，性能更高的较新模型——即在原始测试集上表现更好的模型——有更多时间可以适应测试集并吸收更多关于它的信息。尽管如此，模型在旧测试集上的表现越好，它在新测试集上的表现也越好。而且，在 CIFAR-10 数据集上，我们可以清楚地看到，随着旧测试集准确率的提升，绝对性能下降幅度会减小。特别是，如果我们的目标是表现好在新测试集上，似乎最佳策略是持续在旧测试集上稳步前进。

关于机器学习实践为何没有导致过拟合的理论解释仍在追赶之中。这里我们强调了众多可能的解释之一，即 `leaderboard principle`。这是一种微妙的效应，出版偏见迫使研究者追求最先进的结果，并且仅在看到相较前人显著提升时才发表模型。这种文化实践可以通过 Avrim Blum 和 Moritz Hardt 的 `Ladder algorithm` 形式化。对于每一个给定的分类器，它将该分类器的保留误差与迄今为止所有遇到的分类器中最小的保留误差进行比较。如果误差在之前的最佳误差之上超过一定 margen，它会宣布当前分类器的保留误差并将其记录为当前看到的最佳。重要的是，如果误差未在 margen 之内更小，算法会释放之前的最佳（而非新误差）。可以证明，Ladder algorithm 能够在错误测量的意义上避免过拟合，即准确测量其上所遇到的最佳分类器的误差 \[[509](#references.xhtml#ref-509)\]。

### 基准实践与文化

上述讨论暗示了文化实践对于全面理解基准数据集的重要性。我们现在来更详细地讨论这些实践，同时突出创建者和使用者的角色。这些实践帮助使以基准为导向的方法取得成功，但也影响了数据相关的危害。我们先从创建者说起。

基准创建者定义任务。这包括，但不限于，选择高层问题、定义目标变量、制定数据抽样程序以及评分函数。如果需要手动标注数据，创建者必须开发代码簿或评分标准（rubric），并在需要时组织众包工作。确保高质量标签的数据清洗通常是必须的。

在定义任务时，基准开发者需要在一个棘手的平衡之间取得平衡：任务如果被认为过于容易，现有技术便不足以激发创新；任务如果被认为过于困难，则可能令人沮丧。找到“甜点”需要专业知识、判断以及一定的运气。只要平衡得到恰当，基准就会推动问题的进步。通过这种方式，基准创建者在机器学习社区中扮演出比例上较大的角色，决定其愿景和 agenda。基准中任务的选择会影响模型的排名，进而影响并偏向社区进步方向 \[[510](#references.xhtml#ref-510)\]。这一效应可能因越来越集中在少数数据集上而变得更为显著 \[[511](#references.xhtml#ref-511)\]。

作为基准开发者必须做出的决策及其对研究方向影响的一个例子是 MNIST。正如前文所述，MNIST 源自之前由 NIST 发布的数据集，其训练集和测试集分别来源于不同的数据源，但 MNIST 消除了这种分布差异。MNIST 创建者认为这是必要的，因为

drawing sensible conclusions from learning experiments requires that the result be independent of the choice of training set and test among the complete set of samples. ([http://yann.lecun.com/exdb/mnist/](http://yann.lecun.com/exdb/mnist/))

换言之，如果一个算法在 NIST 上表现良好，我们无法明确这归功于其学习训练分布的能力，还是归功于其忽视训练集与测试集之间的分布差异。MNIST 让研究者有选择性地关注前者问题。这一做法在 1995 年十分有效。数十年后，当像 MNIST 这样的分类问题已经基本得到解决时，基准数据集创建者的关注点转向了处理分布漂移的方法，而 LeCun 等人理所当然地选择忽视这些方法 \[[512](#references.xhtml#ref-512)\]。

另一个棘手的平衡是：在抽象掉域细节以让广泛的机器学习专家能够入手，同时保留足够的细节使得在基准环境中有效的方法能够迁移到生产环境。 Netflix Prize 的流行部分原因是其数据仅为矩阵形式，且可以在不深入思考数据含义的情况下，通过击败 Netflix 的基准来获得良好表现。不需要（也无法）理解电影或用户心理学。如果问题的表述不同——比如强调可解释性或要求即使评分次数极少的用户也能获得良好表现——则域知识可能是必不可少的。
