

### 5.1.1.4 协议违规攻击

通过耗尽 TCP 状态进行的攻击，也称为协议攻击，比容量攻击更为复杂，并针对某些网络设备，例如防火墙、Web 服务器和/或负载均衡器 \[[14](#ch05.xhtml#ref5_14),[15](#ch05.xhtml#ref5_15)\]。状态耗尽攻击的目标是耗尽目标设备的可用资源并导致其故障。

### 5.1.1.5 分片攻击

数据包分片分为两个区域，例如规避 IDS 检测和 DOS 机制 \[[16](#ch05.xhtml#ref5_16),[17](#ch05.xhtml#ref5_17)\]。在分片过程中重新组装数据包时系统资源被耗尽，从而导致 DOS 攻击。

### 5.1.1.6 网络基础设施攻击

攻击始终会影响互联网的整体运行并损坏整个网络基础设施。这些攻击可能导致全球或区域性的网络中断或减速。针对互联网根域名服务器的近期攻击引发了 FBI 调查。将向根域名服务器运营商发送警告信号，以改进网络基础设施。网络中断是由骨干服务引起的。它们将包括最小现有 RADIUS 和 DNS。网络基础设施内的流量可以分为管理平面、控制平面和数据平面 \[[18](#ch05.xhtml#ref5_18)\]。数据平面包含可能借助路由器发送到另一个位置的数据包。控制平面由路由协议组成，这些协议有助于网络正常且高效地工作。网络元素通过管理平面处理的工具和协议进行管理。管理平面和控制平面转发到路由器的处理引擎。路由器引擎无法处理通过数据平面传输的大量数据。如果没有防御系统，它们很容易使 CPU 过载 \[[19](#ch05.xhtml#ref5_19)\]。

## 5.2 DDoS 攻击的工作原理

网络资源（例如 Web 服务器）能够同时处理的请求数量有限。除了服务器容量限制之外，连接服务器与互联网的通道也具有有限的带宽或容量。当请求数量超过基础设施任何组件的容量限制 \[[20](#ch05.xhtml#ref5_20)\] 时，服务级别可能会以以下几种方式之一受到影响：

*   对请求的响应将比正常情况慢得多。

*   用户的一些（或所有）请求可能会被忽略。

作为一般规则，攻击者的主要意图是完全避免 Web 资源的正常运行，即服务的完全“拒绝”。攻击者还可以要求支付款项以停止攻击。在某些情况下，DDoS 攻击 \[[21](#ch05.xhtml#ref5_21)\] 的目标可能是诋毁或损害竞争对手的业务。

### 5.2.1 使用“僵尸网络”发起 DDoS 攻击

为了向受害者资源发送极大量的请求，网络犯罪分子通常会建立一个被感染计算机的“僵尸网络” \[[22](#ch05.xhtml#ref5_22)\]。由于犯罪分子控制僵尸网络中每台被感染计算机的行为，攻击的大规模性可能会压垮受害者的 Web 资源。

### 5.2.2 DDoS 攻击的预防措施

如今，比以往任何时候都更加，商业组织被要求实施各种安全机制，以最大限度地减少未经授权的访问，并确保其服务和活动的连续性。对于大多数安全计划，缓解 DDoS 攻击的关键是在攻击执行之前管理威胁 \[[23](#ch05.xhtml#ref5_23)\]。

以下建议可帮助商业组织降低与 DDoS 攻击相关的风险。确保公司处于安全状态的最佳方法之一是制定针对 DDoS 攻击的行动计划。该行动计划应包含在发生攻击时需要联系的个人和团队的完整信息。如果企业遭受 DDoS 攻击，还应指明他们的角色和职责。

该 DDoS 行动计划 \[[24](#ch05.xhtml#ref5_24)\] 的一个重要方面是，你应如何根据你的客户、员工以及企业的其他利益相关者来处理当前问题。有效的沟通可以帮助控制与 DDoS 攻击相关的成本，并增强对组织最重要的人群的信心。应定期检查和测试你的 DDoS 行动计划，以确保其涵盖每个事件，并包含最相关且最新的信息。

### 5.2.3 不要高估网络的防御能力

最新的网络策略和安全机制自基础设施组织曾经使用过的以来已有了相当大的发展。安全机制 \[[25](#ch05.xhtml#ref5_25)\] 永远不应被高估，因为如果系统中存在任何漏洞，攻击者就可以发动攻击。

### 5.2.4 创建参考模型以更好地识别活跃攻击

值得注意的是，一些组织在“正常”时期并不了解其网络流量水平。这就是为什么他们也不知道自己是否遭受了 DDoS 攻击。因此，需要监控网络流量和防御参考模型。这样，他们就能够确定网络流量的增加是攻击的结果，还是仅仅是特定时期（月份或年份）通常存在的流量率。还需要知道大部分网络流量位于何处。如果你的公司在某个国家 \[[26](#ch05.xhtml#ref5_26)\] 没有客户和/或网络存在，但你发现来自该国的大量流量，则应发出警报。你越快识别出 DDoS 攻击，减少损害的机会就越大。然而，网络性能低下和网络流量速度缓慢并不总是由 DDoS 攻击引起。这就是为什么尽快识别任何服务降级的首要原因非常重要。

### 5.2.5 应用供应商的最新补丁

使用供应商最新补丁更新的服务器和网络设备是任何 IT 安全计划的关键功能，但在对抗 DDoS 攻击 \[[27](#ch05.xhtml#ref5_27)\] 时尤其重要。当你的组织成为攻击受害者时，你最不希望发现的是供应商不愿帮助你，因为你没有应用最新补丁。随着 DDoS 攻击新方法的不断增加且更加精准，已知安全缺陷（有补丁可用）应优先处理。

### 5.2.6 保护 IoT 设备

如果你的公司特别有远见，并寻求抓住 IoT 设备 \[[28](#ch05.xhtml#ref5_28),[29](#ch05.xhtml#ref5_29),[30](#ch05.xhtml#ref5_30)\] 提供的机会，则必须确保它们都受到远程访问的防护。虽然远程访问有时对于第三方故障排除很重要，但它也提供了一个入口，使黑客能够渗透你的网络并将你的 IoT \[[31](#ch05.xhtml#ref5_31)\] 设备纳入僵尸网络。
