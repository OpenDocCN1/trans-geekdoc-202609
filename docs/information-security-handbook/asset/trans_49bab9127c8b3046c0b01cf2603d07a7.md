### 7.10.4 PDF Scrutinizer

Florian Schmitt 等人 \[15\] 在 2012 年开发了一种名为“PDF Scrutinizer”的动态 PDF 分类器，它不仅能够高效地对 PDF 文档进行分类，还能说明其动态状态背后的原理。作者表示，他们的模型会单独调查所有与其他 .exe 文件捆绑的可疑文档，而不与普通未捆绑文档混在一起。与其他分类器不同，该框架将文档归类为三个类别之一：恶意、良性和可疑类别 \[15\]。PDF Scrutinizer 在评估过程中使用了名为“PDF Box”的接口来处理 PDF 文档 \[15\]。

该图展示了 Florian Schmitt 等人 \[15\] 在 2012 年引入的 PDF Scrutinizer 模型的功能和架构。从 [Figure 7.10](#ch07.xhtml#fig7_10) 可以看出，PDF Scrutinizer 具有多种功能。我们提供给框架的 PDF 文档会经历不同的层级，以检查其中是否存在恶意内容 \[15\]。第一步是发现被审查文档中是否存在 JavaScript 代码 \[15\]。然后，我们注意到其中存在的 shell 代码。基于这些发现，会进行统计分析，将文档归类为恶意、良性或可疑 \[15\]。

### 7.10.5 Lux0R

Igino Corona 等人 \[28\] 在 2014 年开发了一种名为“Lux0R”的动态分类器，代表“Lux on discriminant references”。该模型基于一种“轻量级”技术，通过考虑“编程接口引用”（包括文档中声明的各种函数、变量和其他组件）来调查 JavaScript 代码的性质 \[28\]。Lux0R 选择文档 JavaScript 部分中存在的代码，并提取其“编程接口”组件，借助“AI”算法对其进行分析 \[28\]。这种技术被视为一种有效的程序，用于应对“模仿攻击” \[28\] ([Figure 7.11](#ch07.xhtml#fig7_11))。

## 7.12 Novel Methodologies

作为这项工作的一部分，我们从不同来源收集了恶意和良性 PDF 样本，并创建了一个包含 1,400 个良性 PDF 样本和 1,500 个恶意 PDF 文件样本的数据集。恶意 PDF 文件中的恶意代码被高度混淆，以至于用户打开时无法将其识别为恶意。这些 PDF 文件的基础结构被修改以添加恶意代码，因此持有该文档的用户无法看到或识别该文件。我们基于预先存在的“PlatPal”系统开发了一个修改后的 PDF 分类器系统。该系统使用 Python 2.7 编写，因此我们使用了 Python 2.7 解释器。系统中使用的其他包包括 numpy、pandas、matplotlib、sklearn、scipy、xgboost 和 PyWavelets。我们使用 Anaconda 环境来设计和执行该系统。该系统使用总样本（良性和恶意）的 80% 进行训练，并使用剩余 20% 的样本测试其准确性和精确度。基于学习的框架已被证明易受对抗性信息控制攻击。这些攻击已在以下假设下进行研究：敌人对目标模型内部、其训练数据集，或者它分配给正在检查的样本的分类分数有一定了解 ([Figure 7.15](#ch07.xhtml#fig7_15))。
