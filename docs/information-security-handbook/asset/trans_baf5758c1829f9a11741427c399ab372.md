

为了正常运行，部署高效的安全系统或主动计划以缓解 DDOS 攻击至关重要。此类安全系统能够扫描可疑活动或行为，并提供更大的安心。为进行评估 \[[32](#ch05.xhtml#ref5_32)]，您必须依赖参考模型，该模型指示源数据流、性能、时间段以及缓解攻击的其他关键方面。此类解决方案与您的数据流相关联。它们将网络流量发送到专用清洗中心，过滤恶意流量，并仅允许授权数据实时通过。此类系统必须成为您整体事件响应计划的一部分，以便异常能够被快速识别和解决。

### [5.2.8 减少攻击面](#ch05.xhtml#c_sec5_002_008)

我们应减少攻击面以最大限度地减少 DDOS 攻击，这可以限制攻击者的选择并在一个位置获得保护。

不应暴露预期不会用于通信的协议或应用程序。这有助于减少预期的攻击点 \[[33](#ch05.xhtml#ref5_33)]。

### [5.2.9 规划扩展](#ch05.xhtml#c_sec5_002_009)

在减少大规模容量型 DDOS 攻击方面，有两件重要的事情：服务器和带宽（或传输）容量吸收和防止攻击的能力。在服务器容量方面，DDOS 攻击可能是耗尽受害服务器资源（即 RAM、磁盘和 CPU 利用率增加等）的容量型攻击。减少计算资源很重要。为此，可以生成更大的计算资源或功能，例如改进的网络或支持更大流量的更广泛的网络功能。此外，使用负载均衡器也很常见，用于监控或将负载从一个资源转移到另一个资源，以防止资源过载 \[[34](#ch05.xhtml#ref5_34)]。

在开发应用程序时，请确保您的主机提供商提供充足的冗余互联网连接，以防传输容量不足。

这有助于管理大量数据或流量。由于 DDOS 攻击会停止持续服务或应用程序的可用性，因此有必要将它们放置在靠近大型互联网交换点的位置。

这将帮助用户在互联网流量大量时轻松访问应用程序。

*了解正常流量和异常流量是什么*：

每当互联网流量大量时，主机只会接受其能够轻松管理且不影响服务可用性的数据量。

这称为速率限制。最新的缓解技术仅在单独分析数据包后接受授权的数据量 \[[35](#ch05.xhtml#ref5_35),[36](#ch05.xhtml#ref5_36)]。因此，您需要获取接收方通常接收的数据流量的准确信息。此外，许多其他技术在我们之前的工作中已经进行过实验 \[[37](#ch05.xhtml#ref5_37),[38](#ch05.xhtml#ref5_38),[39](#ch05.xhtml#ref5_39),[40](#ch05.xhtml#ref5_40),[41](#ch05.xhtml#ref5_41),[42](#ch05.xhtml#ref5_42)]。

### [5.2.10 为复杂的应用程序攻击实施防火墙](#ch05.xhtml#c_sec5_002_010)

使用 Web 应用程序防火墙 (`WAF`) 防止 SQL 代码注入等类型的攻击是很好的。此外，在发生攻击时，您必须能够针对恶意应用程序或来自意外来源或无效 IP 地址等的攻击生成定制措施。为了在攻击执行时防止攻击，有时有必要获得特殊支持来分析流量模式并生成个性化的保护措施。作为用户，我们需要审查防火墙或路由器的配置，以检测来自预期攻击者的虚假 IP 地址。通常，我们的互联网服务提供商 (`ISP`) 确保我们的路由器与此配置保持最新。另一方面，提供这些服务的组织必须保护其网络和整个基础设施，以减轻此类攻击对其工作性能及其客户的影响 \[[43](#ch05.xhtml#ref5_43)]。如果公司受到拒绝服务 (`DOS`) 攻击的影响，将失去客户的信任并失去其服务的客户。

## [5.3 方法论](#ch05.xhtml#c_sec5_3)

DDOS 攻击会导致合法用户无法使用服务。它们始于对工作的整体分析。在 DDOS 攻击中，入侵者或攻击者从多个位置而非单一位置执行攻击。一些本地系统由攻击者控制。攻击者最初会攻破并控制这些本地系统。这种被攻破的系统称为主控或处理器。主控随后用于控制进一步被攻破且靠近受害服务器的系统。这些系统称为从属或 DDOS 代理。它们进一步对受害服务器发起多次攻击，如 [图 5.2](#ch05.xhtml#fig5_2) 所示。

### [5.3.1 专家蜜网系统简介](#ch05.xhtml#c_sec5_003_001)

黑客始终在寻找系统中的漏洞以执行攻击。防护不足的系统可能成为黑客的易攻目标。在计算机术语中，蜜罐是一种安全机制，管理员利用它诱捕黑客，使网络攻击徒劳无功 \[[10](#ch05.xhtml#ref5_10)]。蜜罐提供网络服务或应用程序来吸引黑客，并保护生产系统免受可能的损害。在实践中，用户收集服务器端或客户端技术来创建蜜罐 \[12]。

### [5.3.2 蜜罐的创建](#ch05.xhtml#c_sec5_003_002)

蜜罐可以在以下两端创建：

1. 服务器端的蜜罐创建

   服务器端蜜罐的基本理念是引诱攻击者进入计算机系统的独立部分，并将其远离网络中的生产服务器。

2. 客户端的蜜罐创建

   客户端蜜罐模拟使用服务器端服务的应用程序。

### [5.3.3 蜜罐的实现](#ch05.xhtml#c_sec5_003_003)

蜜罐可以在三个区域实现。

1. 防火墙前

   通过将其放置在防火墙前，可以确保我们的内部网络安全不会随时受到威胁，因为我们的防火墙将防止攻击进入我们的内部网络。

2. 防火墙后

   此选项允许我们控制任何类型的内部和外部攻击；此方法的主要问题是它需要特定配置来允许访问 `honey pot`，但不允许访问我们的网络，这会导致流量过滤中可能出现安全故障。

3. 非军事区

   通过将其定位在此处，可以将 `honey pot` 与内部网络和服务器的连接分开，这种可能性允许我们通过对防火墙进行小修改来检测内部和外部攻击。
