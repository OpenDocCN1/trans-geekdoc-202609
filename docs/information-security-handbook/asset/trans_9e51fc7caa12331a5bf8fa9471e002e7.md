## [7.9 Dynamic Classification of PDF Files](#ch07.xhtml#c_sec7_9)

动态标识符同样主要集中在文档的 JavaScript 代码上，因为它们的存在引发了更高的怀疑 \[4\]。但是，这一类标识符不会搜索关键字和不同组件的示例或频率 \[9\]。相反，它会直接提取这些 JavaScript 代码，并尝试在强大的隔离环境中执行它们，以检查其活动 \[31\]。静态查找器中因隐藏策略训练而出现的问题可以通过部署这些类型的检测器来克服 \[28\]。动态检测器与静态检测器不同，不会仅通过评估文档的内部结构来检查文档 \[28\]。它们通过提取 Flash 和脚本代码并执行它们来检查文档的性质，以获取文档的真实性质 \[5\]。尽管这些类型的检测器能够有效地确定恶意代码，但在不支持的条件下可能会失败 \[11\]。部分 JavaScript 代码可能需要其他额外组件支持才能执行其活动 \[16\]。为此，我们需要通过提供文档内容所需的必要条件来模拟其执行过程 \[11\]。另一个缺陷是，当恶意软件嵌入不使用 JavaScript 代码的文档时，动态检测器可能会失败 \[11\] ([Figure 7.8](#ch07.xhtml#fig7_8))。

## [7.10 Dynamic Classification Systems](#ch07.xhtml#c_sec7_10)

### [7.10.1 PlatPal](#ch07.xhtml#c_sec7_010_001)

Meng Xu 和 Taesoo Kim \[11\]，在 2017 年，原型化了一种平台多样性工具“PlatPal”，它附加到“Adobe Reader”应用程序，以在解析过程中检查文档的内部组件，并且还在沙箱中执行文档代码，以确定代码对主机计算机的影响 \[11\]。作者在构建此框架时使用的主要原则是，良性文档在执行时无论使用什么应用程序都会具有可比特征，而恶意文档可能会在不同应用程序处理时表现出不同的行为 \[11\]。该模型非常灵活，可以以减少“误报”响应的方式识别嵌入式恶意软件 \[11\]。

在此过程中，PDF 文档被发送到安装了不同操作系统的各种虚拟机中，以检查其运行时的社会属性。在在这些虚拟机上运行文档后，从这些机器获得的结果会被比较用于分类方法。通过此过程，可以识别文档在不同主机平台上的影响。

### [7.10.2 MDScan](#ch07.xhtml#c_sec7_010_002)

Zacharias Tzermias 等人 \[19\]，在 2011 年，提出了一个能够真实分析代码，并且还组织了档案中包含代码的强大处理，以识别 PDF 文档中存在的恶意软件的框架。在将框架与 PDF 测试的信息索引进行对比时，发现所提出的模型能够识别高度编码的恶意 PDF 文档 \[19\] ([Figure 7.9](#ch07.xhtml#fig7_9))。
