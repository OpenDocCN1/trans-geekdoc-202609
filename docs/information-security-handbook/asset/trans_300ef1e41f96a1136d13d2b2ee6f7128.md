## 7.4 分类 PDF 文件涉及的步骤

“AI”技术几乎在各个领域都被广泛使用 \[1\]。这项技术有助于构建更智能的系统，并使其能够进行动态 \[1,8,9\] 应用。由于其应用范围广泛，它也被用于判定文档中隐藏的恶意内容 \[[10](#ch07.xhtml#ref7_10)\]。在这里，我们将讨论如何通过识别正在调查的 PDF 文档中的威胁代码来有效辅助这项技术 \[11,[12](#ch07.xhtml#ref7_12)\]。在过去十年中，科学家提出了几种自学习框架来分析 PDF 文档 \[2,4,[13](#ch07.xhtml#ref7_13),[14](#ch07.xhtml#ref7_14)\]。在本部分中，我们将探讨基于自学习的恶意 PDF 查找器的架构以及对给定 PDF 文档进行分类的步骤 ([Figure 7.1](#ch07.xhtml#fig7_1))。

### 7.4.1 实际解析前的预处理

这是对选定用于审查目的的 PDF 文档执行的主要交互。在此技术中，内部代码（例如 JavaScript 或 ActionScript 代码）会在隔离条件下的稳定环境中执行，以了解其性质 \[2\]。它在隔离条件下准备，以便其执行不会影响系统 \[[20](#ch07.xhtml#ref7_20)\]。其他基本信息组件，例如内部对象的元数据和关键字，也会从 PDF 文档中提取 \[[11](#ch07.xhtml#ref7_11)\]。

### 7.4.2 特征提取

这是探测器在“预处理”操作完成后执行的下一步操作。此技术使用从前一步骤获得的提供的信息来完成其分析操作 \[3,11,[21](#ch07.xhtml#ref7_21), [22](#ch07.xhtml#ref7_22), [23](#ch07.xhtml#ref7_23), [24](#ch07.xhtml#ref7_24), [25](#ch07.xhtml#ref7_25), [26](#ch07.xhtml#ref7_26), [27](#ch07.xhtml#ref7_27)\]。在此步骤中，从前一阶段提取的信息被转换为向量数字形式，这些向量数字能够传达 PDF 文档中特定组件（例如关键字和“编程接口调用”）的存在情况 \[[28](#ch07.xhtml#ref7_28)\]。

### 7.4.3 分类器

这是在分析前一阶段分离的数据时部署算法的阶段 \[16\]。分类器首先使用测试集进行训练，以构建其关于判断良性和威胁性 PDF 文档之间差异的知识 \[[29](#ch07.xhtml#ref7_29)\]。如果分类器经过高效训练，系统就能在对 PDF 文档进行分类时产生高质量的效率 \[19\]。系统的有效性不仅取决于算法，还取决于训练集。训练过程在系统实际部署用于实时应用之前进行 \[[9](#ch07.xhtml#ref7_9)\]。分类器的基本目标是准确判断给定文档是否为恶意文档 \[2\]。

## 7.5 分类模式

用于检查 PDF 文档的恶意软件指标，通过帮助自学习策略，可分为两大类：静态探测器和动态探测器 \[11\]。静态标识符在不执行文档内部代码的情况下对文档进行静态分析 \[1,8–11,16–20,28,29,[30](#ch07.xhtml#ref7_30)\]。动态查找器通过在稳定环境条件下执行实际代码来进行分析 \[1,8,9,11,11,11,20,28–30\]。我们将在下文详细探讨这两种识别类型。

## 7.6 PDF 文件的静态分类

大部分利用 PDF 文档实施的恶意软件攻击都使用 JavaScript 或 ActionScript 代码 \[11\]。因此，这类标识符主要关注文档中识别出此类代码的区域。但是，我们不能仅通过查看 JavaScript 代码的存在来推断某个特定的 PDF 文档就是恶意的。即使是良性文档也可能包含此类代码 \[11\]。因此，静态标识符会调查特定变量、关键字、功能和编程接口调用的使用模式，以判断文档的性质 \[28\]。PJScan 是一种静态 PDF 查找器，它根据变量、运算符和功能的使用频率来判断 PDF 文档的恶意程度 \[[31](#ch07.xhtml#ref7_31)\]。其他一些查找器依赖于分词和匹配策略 \[28\]。但是，在攻击者在 PDF 文档内部对这些 JavaScript 实体进行大量混淆的情况下，静态分类器可能会因误分类文档而失效 \[1\]。攻击者可以使恶意内容特别隐藏，以便在解析周期中解析器无法识别它，并且该代码可以在运行时动态调用以执行威胁活动。因此，这类探测器的主要缺陷是它们无法被训练来准确分类故意混淆的测试样本 \[2\] ([Figure 7.2](#ch07.xhtml#fig7_2))。

## 7.7 静态分类系统

### 7.7.1 PJScan

Pavel Laskov 和 Nedim Šrndic \[31\] 在 2011 年提出了一种静态恶意软件检测框架，该框架能够识别文档内包含的危险 JavaScript 内容 \[31\]。作者声称，与先前引入的模型相比，他们的模型降低了检查文档所需的训练时间，并且在识别已知和未知恶意类型方面也表现出完美的有效性 \[31\]。由于其审查时间短且效率高，此方法最适合训练大型数据集 \[31\] ([Figure 7.3](#ch07.xhtml#fig7_3))。
