## Fitting Linear Models

Description

lm is used to fit linear models. It can be used for carrying out simple regression analysis of variance and covariance (although R may provide a more convenient interface for these)

Usage

```
lm(formula, data, subset, weights, na.action,
      method = "qr", x = TRUE, y = FALSE, qr = TRUE,
      singular.ok = TRUE, model = NULL, offset = ...)
```

Arguments

- formula: an object of class "formula" or one that can be connected to that class; a symbolic description of the model to be fitted. Details of the model specification are given under 'Details'
- data: an optional data frame, list or environment (which can be coerced to data.frame) containing the variables. If not found, the variables are taken from the environment in which `lm` is called.
- subset: an optional subset of observations to be used in the fitting process
- weights: an optional vector of weights to be used in the fitting process. Should be NULL or a numeric vector; if non-ordinary weights are used, they must be orthogonal.
- na.action: how to handle missing values if the data contains NAs. The default is set by the na.action setting of options, and will fail if it is unset. Another possible value is na.omit, which uses rows with missing values.
- method: the method to be used for fitting the model. Only "qr" is supported; method = "qr" frames the result exactly the same as with method = TRUE; see below
- model: returns the fitted components of the fit (the model formula, the model response, the residuals)
- singular.ok: if false (if the S fit is not a singular fit) it returns an error
- contrasts: an optional list. See the contrasts of model.matrix.default
- offset: an optional vector used to adjust the response variable that will be included in the linear predictor during fitting. This should be numeric or a numeric vector of length equal to the number of cases.

## CRAN tasks.

increase the power of R by improving base R codes and functions by adding new ones.

A package is a suitable way to organize users' work and share it with others if users want to. Typically, a package will include

- code (sometimes not just R codes but codes in other programming languages)
- documentation for the package and its functions inside,
- some tests to check that everything works as it should, and
- data sets.

Users can read more about R packages here.

At the time of writing, the CRAN package repository features 12784 packages. Available R packages are listed on the CRAN Task Views website.

CRAN task views aim to provide guidance which packages on CRAN are relevant for tasks related to a certain topic. They give a brief overview of the included packages and can be automatically installed using the ctv view.

The views are intended to have a sharp focus so that it is sufficiently clear which packages are included (or excluded), and they are not meant to endorse the "best" packages for a given task.

### 2.5 Working Directory

### 2.5.3 Location for dataset

Many data analysts use data stored on their local machines. R will read data and usually store this data in memory. When you read data into RStudio, you will save it in the environment pane. The data read in memory will disappear once you close RStudio. The source dataset will stay in its original location, so there will be no change to your original data unless you save the data frame in the memory and replace the original file. However, we do not recommend you do this.

### 2.5.4 Memory

RAM (random access memory) is the temporary storage where R keeps data while processing. You must know the size of your computer RAM. The bigger the RAM, the larger R can read and store.
