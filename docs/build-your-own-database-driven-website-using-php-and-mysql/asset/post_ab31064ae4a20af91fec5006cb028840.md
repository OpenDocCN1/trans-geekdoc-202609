
One final trick we can add to this code is to allow a file to be downloaded, instead of viewed, if the user so desires. By sending a MIME type of application/octet-stream, you can force some browsers (but not MSIE, unfortunately) to prompt the user to save the file. Here’s the modified code, which checks if the variable $action equals “dnld”, which would indicate that this special file type should be sent:

```
$sql = "SELECT FileName, MimeType, FileData
FROM filestore WHERE ID = 'id'";
$result = @mysql_query($sql);
if (!$result) die("database error: " . mysql_error());

$filename = mysql_result($result,0,"FileName");
$mimetype = mysql_result($result,0,"MimeType");
$filedata = mysql_result($result,0,"FileData");

if ($action == "dnld")
  $mimetype = "application/octet-stream";

header("Content-disposition: filename=$filename");
header("Content-Type: $mimetype");
header("Content-Length: " . strlen($filedata));

echo($filedata);
```

MSIE tries to be smart and will attempt to display a file of type application/octet-stream anyway. If we send it a non-standard MIME type, however (e.g. application/x-download), MSIE dutifully offers to download the file immediately. Other browsers either display an ugly “unrecognized file type” message that we’d like to avoid (Netscape 4), or try to display the non-standard file as a plain text file (Opera 5). To ensure the correct behavior in all browsers, we can detect MSIE by checking the built-in HTTP_USER_AGENT variable, to see if it contains the string “MSIE”. If it does, we send the application/x-download MIME type; otherwise, we send application/octet-stream. Here’s the code:

```
if ($action == "dnld") {
  if (strpos(HTTP_USER_AGENT,"MSIE"))
    $mimetype = "application/x-download";
  else
    $mimetype = "application/octet-stream";
}
```

The only remaining problem now is that, by default, Opera 5 identifies itself as MSIE 5.0. To get around this sticky issue would require that we use some clever JavaScript to check the actual features of the browser, and identify whether it’s really MSIE, or just Opera posing as MSIE. The JavaScript would then send its findings to the PHP script, along with the request to download the file. However, the code involved in this solution is beyond the scope of this book.

## The Complete Script

Below you'll find the complete example script. This combines all the elements given above with some simple code that will list the files in the database and allow them to be deleted. As always, this file is available in the code archive (located at http://www.sitepoint.com/books/).

As you look at the code, you may notice two spots where I’ve used this command:

```
header("Location: $PHP_SELF");
```

As described above, the header function sends an HTTP header to the browser. We’ve seen the content-type, content-length, and content-disposition headers already. The above line sends a location header, which redirects the browser to the specified URL. As it specifies $PHP_SELF as the URL, this line redirects the browser to the same page.

“What’s the point of that?” you might wonder. Well, I use this line after the script adds or deletes a file in the database. In such cases, the action - add or delete - is specified by a query string in the page’s URL. If the script simply took the requested action and immediately displayed the updated list of files, the user could inadvertently repeat that action by refreshing the page! To avoid this kind of error, we instead re-direct the browser after it completes each action to a url that’s identical in every way, except that it doesn’t contain a query string ($PHP_SELF). Thus, the user can refresh the file list that’s produced with no ill effects.


## Advanced Considerations

In systems like that developed above, large files present some unique challenges to the developer. I'll explain these here briefly, but fully-developed solutions to these problems are beyond the scope of this book.

### MySQL Packet Size

By default, MySQL does not accept commands (packets) that are longer than 1MB. This puts a pretty severe limit on the maximum file size you can store, unless you're prepared to write your file data in 1MB chunks (using an INSERT followed by several UPDATEs). You can increase the maximum packet size by setting the max_allowed_packet option in your my.cnf (or my.ini) file. For more information about this issue, see http://www.mysql.com/doc/P/a/Packet_too_large.html.

### PHP Script Timeout

PHP is configured by default to kill PHP scripts that run for more than 30 seconds. For large downloads over slow connections, this limit will be reached fairly quickly! Use PHP's set_time_limit function to set an appropriate limit for the download to occur, or simply set the time limit to zero, which allows the script to run to completion, however long it takes (don't do this unless you're positive your script will always terminate, and not run into an infinite loop!).
