# OPTIMIZE TABLE

```
OPTIMIZE TABLE tbl_name[, tbl_name, ...]
```

Much like a hard disk partition becomes fragmented if old files are deleted or resized, MySQL tables become fragmented over time as you deleted rows and modify variable-length columns (such as VARCHAR or BLOB). This query performs the database equivalent of a ‘defrag’ on the table, reorganizing the data it contains to eliminate wasted space.

It’s important to note that a table is locked while an optimize operation is going on, so if your application relies on a large table being constantly available, that application will grind to a halt while the optimization takes place. In such cases, it’s better to copy the table, optimize the copy, and then replace the old table with the newly-optimized version using a RENAME query. Changes made to the original table in the interim will be lost, so this technique is not appropriate for all applications.

# RENAME TABLE

```
RENAME TABLE tbl_name TO new_table_name[, tbl_name2 TO new_table_name2, ...]
```

Quickly and conveniently renames one or more tables. This query differs from ALTER TABLE tbl_name RENAME in that all the tables being renamed in the query are locked for the duration of the query, so that no other connected clients may access them. As the MySQL Reference Manual explains, this assurance of atomicity lets you replace a table with an empty equivalent (e.g. if you wanted to start a new table once a certain number of entries was reached) safely:

```
CREATE TABLE new_table (...)
RENAME TABLE old_table TO backup_table, new_table TO old_table;
```

You can also move a table from one database to another by specifying the table name as db_name.tbl_name, as long as both tables are stored on the same physical disk (which is usually the case).
