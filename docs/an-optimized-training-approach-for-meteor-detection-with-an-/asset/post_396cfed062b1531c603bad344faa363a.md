## 3.3.1. Model architectures

In our implementation, we used the learned weights trained on the ImageNet dataset from a VGG16 model (Simonyan and Zisserman, 2015). The VGG family outperformed other CNN architectures, such as DenseNet, Inception-V3, and ResNet, for a dataset of 7000 images (Dawson et al., 2023).

From that network, we built two modified versions of the VGG16 architecture, as Fig. 2 depicts. First, we customized the VGG16 using Batch Normalization (BN) (Ioffe and Szegedy, 2015) and Dropout layers (Srivastava et al., 2014). We are aware that combining them may lead to worse performance in many modern neural networks, including CNNs, due to variance shifts (Li et al., 2019). However, these were essential techniques to reduce the computation time and prevent the model from overfitting.

## 3.2.2. Dataset splits

In our study, we considered the split approach of the dataset performed by Dawson et al. (2023). Their work also applied a CNN architecture to classify images with the same dimensions as the meteor dataset but for the carbonate rock problem. Therefore, we split the dataset into 80% training and 20% test data. Finally, we used the training data with stratified cross-validation to create five folds of the 80% training data and the 20% validation data to evaluate the reliability of the prediction. The training and validation sets represent 64% and 16% of the total dataset.

Therefore, we added only one dropout layer before the softmax layer and set the drop ratio at 0.2, as suggested by Li et al. (2019). Next, we placed a BN layer before each max pooling layer and a second Dropout layer with a drop ratio of 0.2 before a single dense layer of 16 units. We also substituted the flattening layer with a Global Average Pooling 2D layer to reduce the feature maps towards easily understood by the single classification layer.

## 3.3.2. Model training

Subsequently, we performed an optimized training approach to leverage all the adding architecture techniques. We used two strategies for training. First, a training phase keeps all layers frozen except for the classification layer and trains both models for ten epochs. Finally, we unfreeze all layers and then train all models for 50 epochs using different batch sizes and learning rate values for fine-tuning.

We considered the AdamW algorithm for the optimizer with a 5 x 10^-4 decoupled weight decay for both training strategies. AdamW stands out as a better generalization method than the common implementation of Adam with L2 regularization (Loshchilov and Hutter, 2019).

Finally, we used optimal batch size and learning rate values for training and fine-tuning. In this sense, increasing the batch size rather than decaying the learning rate usually obtains the same results enabling the efficient use of large batch sizes by significantly reducing the number of parameter updates (Smith et al., 2018). In addition, higher learning rates also require larger batch sizes (Kandel and Castelli, 2020).

We then started with small values of batch size and learning rate. Next, we employed higher values of both for fine-tuning. Masters and Luschi (2018) showed that small batch sizes between 2 and 32 improve generalization performance. ## 3.4. Evaluation

Our work evaluated the performance of the proposed methodology through five statistical measures. From the confusion matrix, we used the accuracy (Acc), sensitivity (Sn), specificity (Sp), true skill statistic (TSS), and false alarm ratio (FAR) to evaluate each training, validation, and test fold for the meteor dataset. We applied Eqs. (1), (2), (3), (4), and (5) for classification evaluation:

```
Acc = \frac{TP + TN}{TP + FP + FN + TN} (1)
Sn = \frac{TP}{TP + FN} (2)
Sp = \frac{TN}{TN + FP} (3)
TSS = \frac{TP}{TP + FN} - \frac{FP}{FP + TN} (4)
FAR = \frac{FP}{FP + TP} (5)
```

where TP and TN are the numbers of true positives and true negatives, respectively; FP and FN are the numbers of false positives and false negatives, respectively.

We evaluated the overall performance of the classifiers with Acc, a common metric used in classification tasks to summarize the performance of a classification model. Since the Acc metric does not distinguish between classes, we cannot assess the classifier's performance to correctly discriminate meteors from other sorts of objects. Therefore, we employed four other metrics (Sn, Sp, TSS, and FAR) to measure the models' robustness further.

We highlight that the term robustness has a range of interpretations in computer vision (Drenkow et al., 2022). In our case, the robustness performance is the ability of the classification model to generalize within the meteor detection domain.

In this case, the Sn and Sp metrics are inversely proportional and indicate the true positive and true negative rates, respectively (Parikh et al., 2008). Furthermore, we also employed TSS as an appropriate metric for assessing robustness because it can measure whether the model correctly discriminates the presence and absence of data (Costa et al., 2023). Additionally, FAR measures the number of false alarms divided by the number of forecasted events, indicating the fraction of meteor forecasts that did not occur (Barnes et al., 2009).

To determine the best robustness of the architecture, we analyzed visual explanations of the predictions using the Gradient-weighted Class Activation Mapping (Grad-CAM) algorithm (Selvaraju et al., 2017). Grad-CAM uses gradients that flow into the final convolutional layer to produce a coarse localization map, highlighting the critical regions in the image to forecast concept.
