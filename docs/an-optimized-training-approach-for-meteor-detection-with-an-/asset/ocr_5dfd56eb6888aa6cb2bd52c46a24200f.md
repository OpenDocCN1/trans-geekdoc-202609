# 3.3.2. Model training

Subsequently, we performed an optimized training approach to leverage all the adding architecture techniques. We used two strategies for training. First, a training phase keeps all layers frozen except for the classification layer and trains both models for ten epochs. Finally, we unfreeze all layers and then train all models for 50 epochs using different batch sizes and learning rate values for fine-tuning.

We considered the AdamW algorithm for the optimizer with a 5 x 10^-4 decoupled weight decay for both training strategies. AdamW stands out as a better generalization method than the common implementation of Adam with L2 regularization (Loshchilov and Hutter, 2019).

Finally, we used optimal batch size and learning rate values for training and fine-tuning. In this sense, increasing the batch size rather than decaying the learning rate usually obtains the same results enabling the efficient use of large batch sizes by significantly reducing the number of parameter updates (Smith et al., 2018). In addition, higher learning rates also require larger batch sizes (Kandel and Castelli, 2020).

We then started with small values of batch size and learning rate. Next, we employed higher values of both for fine-tuning. Masters and Luschi (2018) showed that small batch sizes between 2 and 32 improve generalization performance. Therefore, we arbitrarily used a batch size of 8 and a learning rate of 10^-5 for the training. Next, for fine-tuning a batch size of 32 and a learning rate of 10^-4, as Table 2 shows.

# 3.4. Evaluation

Our work evaluated the performance of the proposed methodology through five statistical measures. From the confusion

matrix, we used the accuracy (Acc), sensitivity (Sn), specificity (Sp), true skill statistic (TSS), and false alarm ratio (FAR) to evaluate each training, validation, and test fold for the meteor dataset. We applied Eqs. (1), (2), (3), (4), and (5) for classification evaluation:

```
Acc = \frac{TP + TN}{TP + FP + FN + TN} (1)
Sn = \frac{TP}{TP + FN} (2)
Sp = \frac{TN}{TN + FP} (3)
TSS = \frac{TP}{TP + FN} - \frac{FP}{FP + TN} (4)
FAR = \frac{FP}{FP + TP} (5)
```

where TP and TN are the numbers of true positives and true negatives, respectively; FP and FN are the numbers of false positives and false negatives, respectively.

We evaluated the overall performance of the classifiers with Acc, a common metric used in classification tasks to summarize the performance of a classification model. Since the Acc metric does not distinguish between classes, we cannot assess the classifier's performance to correctly discriminate meteors from other sorts of objects. Therefore, we employed four other metrics (Sn, Sp, TSS, and FAR) to measure the models' robustness further.

We highlight that the term robustness has a range of interpretations in computer vision (Drenkow et al., 2022). In our case, the robustness performance is the ability of the classification model to generalize within the meteor detection domain.

In this case, the Sn and Sp metrics are inversely proportional and indicate the true positive and true negative rates, respectively (Parikh et al., 2008). Furthermore, we also employed TSS as an appropriate metric for assessing robustness because it can measure whether the model correctly discriminates the presence and absence of data (Costa et al., 2023). Additionally, FAR measures the number of false alarms divided by the number of forecasted events, indicating the fraction of meteor forecasts that did not occur (Barnes et al., 2009).
