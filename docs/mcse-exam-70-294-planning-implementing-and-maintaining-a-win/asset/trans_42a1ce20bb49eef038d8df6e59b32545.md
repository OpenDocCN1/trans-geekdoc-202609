
# 信任关系概述

## 传递性和非传递性信任

除了可以是传递性或非传递性之外，信任还可以是单向或双向的。传递性的双向信任允许所有域中的资源对所有用户共享，而不论其属于哪个域。例如，你在两个域之间创建信任（`Domain X` 和 `Domain Y`）。`Domain X` 中的用户账户可以访问 `Domain Y` 中的资源。反之亦然，`Domain Y` 中的用户账户可以访问 `Domain X` 的资源。这是一个双向信任；信任在两个方向上都有效。现在让我们添加一个新的 `Domain Z` 并与 `Domain Y` 创建信任关系。传递性信任允许 `Domain X` 中的用户账户访问 `Domain Z` 中的资源，反之亦然，而无需在 `Domain X` 和 `Domain Z` 之间创建额外的信任（参见 [图 5.1](#B9781931836944500118.xhtml#f0010)）。这减少了管理员需要创建和维护的信任数量。

![图 5.1 传递信任](images/B9781931836944500118/f05-01-9781931836944.jpg)

图 5.1 传递信任

非传递性信任将关系限制在信任之外的域。它本身并不允许其他域通过其身份验证信息访问信任之外的资源。再次以 `Domain X` 和 `Domain Y` 为例。如果在 `Domain X` 和 `Domain Y` 之间建立了非传递性信任关系，则两个域中的用户账户可以访问对方域中的资源。如果我们现在添加一个新的 `Domain Z` 并在 `Domain Y` 和 `Domain Z` 之间创建信任，`Domain X` 中的用户不会自动获得访问 `Domain Z` 中资源的权限（参见 [图 5.2](#B9781931836944500118.xhtml#f0015)）。

![图 5.2 非传递信任](images/B9781931836944500118/f05-02-9781931836944.jpg)

图 5.2 非传递信任

## 单向和双向信任

我们一直在讨论双向（双向）信任；但信任也可以是单向（单向）的。单向信任是为了允许对哪些用户可以访问资源进行更严格的控制而创建的。例如，在 [图 5.3](#B9781931836944500118.xhtml#f0020) 中，`Domain X` 和 `Domain Y` 之间创建了一个单向信任。`Domain X` 中的用户可以访问 `Domain Y` 中的资源。然而，`Domain Y` 中的用户无法访问 `Domain X` 中的资源。在此定义中，`Domain X` 被称为受信任域，而 `Domain Y` 是信任域。双向信任允许任一域中的用户访问另一域中的资源。

![图 5.3 单向信任](images/B9781931836944500118/f05-03-9781931836944.jpg)

图 5.3 单向信任

单向信任必须指定信任的方向。单向信任可以是传入或传出，具体取决于信任是从信任域还是受信任域创建。传入信任允许在创建信任的域（受信任域）中的用户访问指定域（信任域）中的资源。用户在信任域中不能通过此信任访问受信任域中的资源。（不过，你可以创建第二个反向信任，以实现与双向信任相同的效果。）

传出信任允许指定域（受信任域）中的用户访问源域（信任域）中的资源。源域中的用户无法访问指定域中的资源。

## 隐式和显式信任

关于信任，还有另一个概念和术语需要了解：

- 隐式
- 显式

隐式信任是由森林中域之间内置关系的性质自动创建的信任。这些隐式信任是双向且传递的。隐式信任在每个创建的域与其子域之间自动存在。隐式信任也存在于每个域树的根域与森林中每个其他域树的根域之间。

显式信任是由管理员创建的；它不会自动存在，而必须显式创建。例如，管理员可以在不同域树中的任意两个子域之间创建显式信任（在这种情况下称为 `shortcut trust`），以在它们之间提供直接信任（以及更快的身份验证）。

显式信任还用于在森林之间启用身份验证。当创建 `forest trust` 时，会在两个森林的森林根域之间创建传递性信任。这允许森林中的所有成员与另一个森林交换身份验证信息。森林信任也称为两个森林之间的显式信任。如果在其中一个原始森林和第三个森林之间创建了额外的森林信任，则不会在第三个森林与另一个原始森林之间建立隐式信任。为了使第三个森林与另一个森林建立信任关系，必须在两者之间创建显式森林信任（参见 [图 5.4](#B9781931836944500118.xhtml#f0025)）。

## 新闻与值得注意：信任类型

尽管信任关系背后的概念在 Windows NT 系列中并不是新事物，但所提供的新信任类型和灵活性对于 Windows Server 2003 域来说是新的。“管理工具”菜单中的 `Active Directory Domains and Trusts` 工具为你提供了必要的工具，允许 Active Directory 域中的用户轻松访问其他域中的资源，即使其他域是非 Windows Kerberos 域。

与任何新功能一样，尤其是与安全和访问相关的功能，你可以预期会出现几个关于新术语和概念的新问题。你需要对以下概念有透彻的理解。

## 信任关系类型

两个或多个 Active Directory 域通过信任关系隐式或显式连接。从一个域向其他域发出的身份验证请求使用这些关系。信任提供了森林结构内资源的无缝共存。用户在自己的域中经过身份验证后，才会被授予访问其他域中资源的权限。一旦在自己的域中通过身份验证，他们就可以遍历其他域以访问其资源。

![b05-01-9781931836944](images/B9781931836944500118/b05-01-9781931836944.jpg)

Test Day Tip

在考试当天，你需要复习信任类型以及何时使用每种不同的信任。在考试中，你可能会被给出一个场景，要求你确定最能满足场景要求的信任类型。

因为有几种新的信任类型，你应该确保知道何时适合使用不同的信任。

这些关系的主要优势是管理员不再需要为每个需要在每个域内访问资源的用戶创建多个用户账户。管理员现在可以将其他域的用户添加到其访问控制列表（`ACLs`）中以控制对资源的访问。为了充分利用这些关系，管理员必须了解存在的各种信任类型以及何时使用它们。

### 默认信任

当使用 `Active Directory Installation Wizard` 在现有森林中创建新域时，会创建两个默认信任：`parent and child trust` 和 `tree-root trust`。可以使用 `New Trust Wizard` 或命令行实用程序 `netdom` 创建另外四种信任类型。Windows 2000 和 Windows Server 2003 森林内部的默认信任关系是传递性的双向信任。
