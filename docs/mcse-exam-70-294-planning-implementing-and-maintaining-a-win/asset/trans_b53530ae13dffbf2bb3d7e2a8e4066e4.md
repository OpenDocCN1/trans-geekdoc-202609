### 建立信任关系

如名称所示，信任关系完全是关于共享信息。出于安全目的，在创建新的信任关系之前，您应仔细考虑原因，并了解要实现哪种类型的信任。在 Active Directory 中，快捷方式信任并不会增加更多信任；相反，它可以使您已有的信任更高效。外部信任是 Windows NT 遗留下来的概念，但在与 Windows NT 域或森林之外的任何其他 Windows 域共享资源时仍然是必要的。领域信任允许与非 Windows 的 Kerberos V5（版本 5）领域进行跨平台互操作，例如在 UNIX 系统中常用的那些。最后，您应考虑本章前面讨论的新 Windows Server 2003 森林信任。正如您所见，信任关系在属性和用途上各不相同。在创建信任关系之前需要理解的最重要概念是方向和传递性。始终注意您授予外部用户访问内部资源的范围。

#### 方向和传递性

如名称所示，信任关系是访问森林资源的预定途径。这就像给某人一把你家的钥匙并希望他或她不会滥用你的信任。域控制器执行身份验证，但并非所有域控制器都必然相互信任。这就是您发挥作用的地方，设置域之间的关系以管理信息的流动。

信任的两个主要属性是方向和传递性。信任的方向从信任域流向被信任域，如 [图 4.44](#B9781931836944500106_1.xhtml#f0220) 中箭头所示。 [Cats.com](http://www.Cats.com) 信任 [Dogs.com](http://www.Dogs.com)。访问的方向始终相反； [Dogs.com](http://www.Dogs.com) 访问 [Cats.com](http://www.Cats.com) 中的资源。这是一个单向信任。同样， [Dogs.com](http://www.Dogs.com) 信任 [Fish.com](http://www.Fish.com)，但不信任 [Cats.com](http://www.Cats.com)。两个单向信任可以结合起来模拟单个双向信任。

![图 4.44 非传递性信任](images/B9781931836944500106/f04-44-9781931836944.jpg)

图 4.44 非传递性信任

信任的第二个属性是传递性，即信任延伸的程度。非传递性信任有限制。被信任域，并且只有被信任域，可以通过信任访问信任域中的资源。如 [图 4.44](#B9781931836944500106_1.xhtml#f0220) 所示，如果 [Dogs.com](http://www.Dogs.com) 域对其他域（如 [Fish.com](http://www.Fish.com)）具有信任关系，则这些其他域无法访问 [Cats.com](http://www.Cats.com)，除非它们拥有自己的非传递性信任。信任的第三条腿缺失打破了访问的循环。这是 Windows NT 中所有信任的行为。

相反，传递性信任，如 [图 4.45](#B9781931836944500106_1.xhtml#f0225) 中所示，是访问的主钥匙。信任关系中被信任一侧的任何人都可以进入，包括被信任域所信任的任何人。当用户或进程请求访问另一个域中的资源时，如 [图 4.45](#B9781931836944500106_1.xhtml#f0225) 所示，身份验证过程中会沿信任路径进行一系列交接。当 [Cats.com](http://www.Cats.com) 信任 [Dogs.com](http://www.Dogs.com) 时，它们必须在信任级别上同等信任所有 [Dogs.com](http://www.Dogs.com) 子域。 [图 4.45](#B9781931836944500106_1.xhtml#f0225) 中有两种类型的信任，父子信任和树根信任。所示的所有信任都是双向和传递性的，正如它们在 Windows Server 2003 中默认情况下一样。 [CaHco.cats.com](http://www.CaHco.cats.com) 与 [Yellow.labs.dogs.com](http://www.Yellow.labs.dogs.com) 存在信任关系，因为信任路径延伸穿过所有三个中间域。如果 [Calico.cats.com](http://www.Calico.cats.com) 没有理由信任 [trustYellow.labs.dogs.com](http://www.trustYellow.labs.dogs.com)，那么猫必须对 Hmit 应用权限或阻止访问。

请记住，默认的 Windows Server 2003 信任关系是友好的。Active Directory 中默认且最常见的信任关系，即父子信任和树根信任，都是双向和传递性的，这意味着信任路径延伸到整个森林。您可以用一句老话来记住这种传递性信任：“你的朋友就是我的朋友。”

还存在其他类型的 Windows Server 2003 信任，例如森林、快捷方式、外部和领域信任，每种信任可以是双向或单向，并且具有不同的传递性属性。您在测试站就座后应做的第一件事之一是在草稿纸上写下信任关系及其属性。在开始测试之前就这样做，以免浪费宝贵时间。

#### 信任类型

信任是两个域之间的逻辑身份验证路径。信任路径是在资源请求源和目标之间必须遍历的信任数量。运行 Active Directory 安装向导时，树根信任和父子信任会默认创建。其他四个信任——快捷方式、外部、领域和森林——可以根据需要使用新建信任向导或 `Netdom.exe` 命令行工具创建。

创建这四种信任时，您可以选择创建两个单向关系，以模拟双向功能。与任何密码使用一样，在建立信任时使用长、随机且复杂的密码是安全最佳实践。最佳选择是使用新建信任向导同时创建双方，在这种情况下，向导会为您生成强密码。当然，您必须在两个域中都拥有适当的管理员凭据才能使其工作。
