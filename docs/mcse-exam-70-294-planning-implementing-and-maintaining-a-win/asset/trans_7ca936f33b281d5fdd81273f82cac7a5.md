
## 域

虽然域用作管理和复制的边界，但这并不意味着您应该只使用一个域，直到达到每个域支持的对象数量限制为止。这取决于您的组织结构。您可能出于以下任何原因想要使用多个域：

![Squareb](images/Squareb.png) 去中心化管理

![Squareb](images/Squareb.png) 提高性能

![Squareb](images/Squareb.png) 控制复制

![Squareb](images/Squareb.png) 为每个域使用不同的安全设置和策略

![Squareb](images/Squareb.png) 如果目录中的对象数量很大

例如，您的公司可能在多个国家设有分支机构。如果只有一个域，则目录信息必须在每个国家的 `DCs` 之间复制，或者（如果这些位置没有 `DCs`）用户需要登录到另一个国家的 `DC`。与其在 `WAN` 上复制目录信息并管理网络的不同部分，您可以将网络划分为多个域。例如，您可以为每个国家创建一个域。

创建单独的域并不意味着您网络的这些不同部分之间没有关系。`Active Directory` 允许多个域在层次结构中连接在一起。如 [图 1.8](#B9781931836944500076.xhtml#f0045) 所示，可以在层次结构中现有的域下方创建域。现有的域被称为“父域”，在其下创建的新域被称为“子域”。这样做时，域共享一个公共命名空间。它们还共享架构、配置和 `GC`，与同一森林中的所有域一样，无论它们是否有父子关系（我们将在本章后面更详细地讨论这些元素）。

![图 1.8 域树由同一连续命名空间中的父域和子域组成](images/B9781931836944500076/f01-08-9781931836944.jpg)

图 1.8 域树由同一连续命名空间中的父域和子域组成

如 [图 1.8](#B9781931836944500076.xhtml#f0045) 所见，在这种父子结构中创建并共享命名空间的域属于域树。树遵循 `DNS` 命名方案，因此父域和子域之间的关系是显而易见且易于遵循的。为了符合此命名方案，子域将其名称附加到父域的名称。例如，如果父域使用域名称 `sygress.com`，则位于英国的子域可能具有名称 [uk.syngress.com](http://www.uk.syngress.com)。名称也可以表示域的功能，而不是其地理位置。例如，供开发人员使用的子域可能使用名称 dev.[dev.syngress.com](http://www.dev.syngress.com)。由于域树使用连续命名空间，因此很容易看出哪些域是特定父域的子域。

创建子域时，父域和子域之间会自动创建双向传递信任关系。信任关系允许直通身份验证，因此在受信任域中经过身份验证的用户可以使用信任域中的资源。由于父域和子域之间的信任是双向的，因此两个域相互信任，因此任一域中的用户都可以访问另一个域中的资源（当然，前提是用户对这些资源具有适当的权限）。

父域和子域之间信任关系的另一个特点是它们是传递的。传递关系意味着直通身份验证会传递到相互信任的所有域。例如，在 [图 1.9](#B9781931836944500076.xhtml#f0050) 中，`Domain A` 与 `Domain B` 具有双向传递信任，因此两者相互信任。`Domain B` 与 `Domain C` 具有双向传递信任，因此它们也相互信任，但 `Domain A` 和 `Domain C` 之间没有信任关系。有了双向传递信任，`Domain C` 将信任 `Domain A`（反之亦然），因为两者都信任 `Domain B`。这将允许各个域中的用户访问其他域中的资源。域之间也可以手动设置信任，使其为单向且非传递的，但默认情况下，域树和森林中使用的是双向传递信任。这些信任也是隐式的，这意味着它们在创建域时默认自动存在，而不像必须手动创建的显式信任。

### 森林

正如域可以互连成树一样，树也可以互连成森林。森林是一个或多个共享相同架构、`GC` 和配置信息的域树。与域树的情况一样，同一森林中的域在森林中所有域树的根之间使用双向传递信任（即每棵树中的顶级域），以允许直通身份验证，因此用户可以访问整个森林中域中的资源。如 [图 1.10](#B9781931836944500076.xhtml#f0055) 所示，虽然树需要连续命名空间，但森林可以由使用不同命名方案的多个树组成。这允许您的域在网络上共享资源，即使它们不共享连续命名空间。

![图 1.10 森林允许多个域树连接并共享信息](images/B9781931836944500076/f01-10-9781931836944.jpg)

图 1.10 森林允许多个域树连接并共享信息

每个 `Active Directory` 结构都有一个森林，即使它只由单个域组成。当在网络上安装第一个 `Windows Server 2003` `DC` 时，您创建的第一个域也称为森林根域。然后可以创建属于此森林的附加域，也可以创建多个森林。这使您可以控制哪些树连接并可以在彼此之间共享资源（在同一森林内），以及哪些树被分离，以便用户无法搜索共享 `GC` 的其他域（在单独的森林中）。

### 组织单位

在查看域树时，您可能会认为创建反映公司组织的目录结构的唯一方法是创建多个域。然而，在许多公司中，单个域就足够了。为了在单个域内组织 `Active Directory` 对象，可以使用 `OUs`。

正如我们前面提到的，`OUs` 是容器，允许您存储用户、计算机、组和其他 `OUs`。通过将对象放在不同的 `OUs` 中，您可以设计 `Active Directory` 的布局，使其与公司的逻辑结构形状相同，而无需创建单独的域。如 [图 1.11](#B9781931836944500076.xhtml#f0060) 所示，您可以为业务的不同领域创建 `OUs`，例如部门、职能或位置。然后与每个领域相关的用户、计算机和组可以存储在 `OU` 内，以便您可以将它们作为一个单元找到和管理。

![图 1.11 组织单位可以包含其他 Active Directory 对象](images/B9781931836944500076/f01-11-9781931836944.jpg)

图 1.11 组织单位可以包含其他 Active Directory 对象

`OUs` 是您可以委派管理权限的最小 `Active Directory` 单位。当您委派权限时，您授予特定用户或组管理 `OU` 中的用户和资源的能力。例如，您可以授予部门经理管理该部门内用户的权限，从而减轻您（网络管理员）这样做的需要。
