
# Active Directory 安装向导配置

## NetBIOS 域名确认

`ADIW` 接下来会要求您确认要使用的 `NetBIOS` 域名。尽管 `NetBIOS`（因此 `WINS`）正在逐渐淘汰，但它尚未完全消亡，因此您仍需为旧版客户端提供此名称。如果您处于纯 Windows 2000 及更高版本的环境中，可以禁用 TCP/IP 上的 `NetBIOS`（`NetBT`），但仍需填写此信息。默认值是您的注册域名，去掉了 .biz、.com、.us 等层次标识符。[图 7.7](#B9781931836944500131.xhtml#f0040) 显示了此阶段您所看到的窗口，其中业务名称 `YOURFIRM` 显示在字段中。对于我们的示例，请接受默认值。

## 数据库和日志文件夹位置

在数据收集过程中，`ADIW` 会询问数据库和日志文件的存储位置。建议将它们存储在 `NTFS` 分区上，并且存储在单独的磁盘驱动器上，这些驱动器通过 `SCSI`、`FireWire` 或 `EIDE` 在单独的通道上运行。如果驱动器无法同时访问，将这些文件放在单独的驱动器上毫无意义。[图 7.8](#B9781931836944500131.xhtml#f0045) 显示两个文件都存储在同一驱动器上，因为作者在此练习中只有一台驱动器可用。单击 `Next >` 会调出共享系统卷设置。

![图 7.8 数据库和日志文件夹](images/B9781931836944500131/f07-08-9781931836944.jpg)

图 7.8 数据库和日志文件夹

## 共享系统卷

尽管建议将 Active Directory 数据库和日志文件存储在 `NTFS` 分区上，但 `SYSVOL` 文件夹需要 `NTFS`。`SYSVOL` 存在于每个 `DC` 上，用于在服务器之间共享数据。其中一种应在所有 `DCs` 之间分发的文件是登录脚本。这与 Windows NT 4 中的 `NETLOGON` 共享类似。放置在此文件夹中的文件会自动复制并同步到域中所有其他 `DCs`。这是一个很不错的功能，尤其受到前 Windows NT 管理员的欢迎。如 [图 7.9](#B9781931836944500131.xhtml#f0050) 所示，默认位置是 `C:\\WINDOWS\\SYSVOL` 文件夹。只要它位于 `NTFS` 卷上，请继续接受默认值。

## DNS 注册诊断

按下 `Next` 会启动 DNS 注册诊断；换句话说，您的服务器会查找符合要求的 `DNS` 服务器，以便在该服务器上创建 `SRV` 记录并设置域结构以进行动态更新。如果服务器无法找到上述 `DNS`（请参阅 [图 7.10](#B9781931836944500131.xhtml#f0055)），您可以从三个选项中选择。

![图 7.10 DNS 注册诊断](images/B9781931836944500131/f07-10-9781931836944.jpg)

图 7.10 DNS 注册诊断

■ 修正问题并重试。如果成功注册新域，将出现“DNS 注册成功”窗口。
■ 将此服务器设为 `DNS` 服务器。
■ 稍后修正问题。

![u07-b1-9781931836944](images/B9781931836944500131/u07-b1-9781931836944.jpg)注意

我们强烈建议您在安装 `DC` 之前设置 `DNS`；这可以为您节省许多小时的痛苦和故障排除时间。

就本练习而言，请选择默认选项“在此计算机上安装并配置 `DNS` 服务器以使用此 `DNS` 服务器作为其首选 `DNS` 服务器”，并让 `ADIW` 创建和配置您的 `DNS` 服务器。专家建议您选择“我已修正问题”选项。再次执行 `DNS` 诊断测试。这实际上意味着退出 `ADIW`，修复 `DNS` 服务器问题，然后再次运行 `dcpromo`。在创建 `DC` 之前正确设置 `DNS`，可以避免在连接额外的 `DCs` 以及加入工作站和成员服务器时产生额外的困扰。选项三，“我将通过手动配置 `DNS` 稍后修正问题”，应仅作为最后的手段选择。

## 权限兼容性

现在您已经解决了 `DNS` 危机，您将面临权限困境（请参阅 [图 7.11](#B9781931836944500131.xhtml#f0060)）。一些旧版（又称降级）操作系统（Windows 2000 之前）需要匿名用户帐户才能向 `DCs` 发出查询。如果您需要该“漏洞”来保持这些 Windows 2000 之前的服务器程序运行，请选择第一个选项“与 Windows 2000 之前的服务器操作系统兼容的权限”。需要此功能的服务的最佳示例是 Windows NT 4 远程访问服务（`RAS`）。如果您不确定是否需要此功能，请选择下一个选项“仅与 Windows 2000 或 Windows Server 2003 兼容的权限”。您稍后可以通过将 `Everyone` 组添加到位于 Active Directory 用户和计算机 `MMC` 中 `Builtin` 文件夹的 `Pre-Windows 2000 Compatible Access` 组来修改它。

![图 7.11 权限兼容性](images/B9781931836944500131/f07-11-9781931836944.jpg)

图 7.11 权限兼容性

选择“仅与 Windows 2000 或 Windows Server 2003 兼容的权限”并单击 `Next` 以显示 [图 7.12](#B9781931836944500131.xhtml#f0065) 中的屏幕。

## 目录服务还原模式管理员密码

在让向导执行其操作之前，您还有一个最后的重要决定。Windows 2000 和 Windows Server 2003 在启动时可以选择一些还原功能。为了保护 Active Directory 数据库，您必须为还原管理员分配密码。一些管理员使用最初设置的相同域管理员密码（请参阅 [图 7.12](#B9781931836944500131.xhtml#f0065)），但在生产环境中，切勿使用图中所示的短密码，尤其是对于管理员帐户。

![u07-b1-9781931836944](images/B9781931836944500131/u07-b1-9781931836944.jpg)注意

建议您始终遵循最佳密码实践，创建密码时至少包含八个字符，包括大小写字母、一些数字和一些符号字符，避免使用字典中的单词或容易猜到的短语。

接下来向导将配置 Active Directory。您可以单击取消按钮（显示在 [图 7.14](#B9781931836944500131.xhtml#f0075) 中），但如果现在改变主意，您仍需等待写入过程完成。您仍需重新启动服务器，并再次运行 `dcpromo` 以“擦除” Active Directory 信息。然后，您必须第二次重新启动服务器，并使用“预期”设置运行 `dcpromo`。等待。重新启动——最后，它按您预期的方式完成。每次 `dcpromo` 的迭代需要 20 到 30 分钟，因此请小心不要犯需要重复此过程的错误。当写入过程成功完成时，您会看到完成窗口，[图 7.15](#B9781931836944500131.xhtml#f0080)。
