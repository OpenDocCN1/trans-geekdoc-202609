```
$$\sigma^2 = \frac{n_B}{n_B} \sum_{i=1}^{n_B} (x_i - \mu)^2 \quad (4.14)$
```

```
$x_i \leftarrow \frac{x_i - \mu}{\sigma} \quad (4.15)$
```

Sometimes there is a small number around $\sigma^2$ to prevent the fraction in the last equation becoming too large when $\sigma^2$ is close to 0. Input normalization will often help the speed of learning, and we will discuss this later. If normalization of input data helps, then why not apply it to each layer in the network? This is now common called batch normalization. One problem with this procedure is that by changing the overall scaling and a shift of the data in each batch, then the following network has to unlearn the specific weights. This seems rather counterproductive. Batch normalization therefore includes two separate parameters to absorb the overall effect of the shift and scale,

```
$x_i \leftarrow \gamma x_i + \beta. \quad (4.16)$
```

With these trainable parameters, the training algorithm itself can adjust the right rate of changes.

There are many other tricks and techniques to make deep neural networks work for some applications, and working with such techniques is not always easy. For example, it is not always the case that batch normalization helps and sometimes it could even worsen the training early in the training process. The same holds for dropout and the choice of the learning rule. As we stressed already several times, at the end it depends on the structure of the problem itself whether the specific model proposed through deep learning is appropriate for this application. This is another reason to understand the principles behind such methods, such as regularization in general, which we will consider in the following chapter.
