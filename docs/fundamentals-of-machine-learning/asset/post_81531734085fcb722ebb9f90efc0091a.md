## 10.3.2 TD($\lambda$)

The example of the maze in the previous section has shown that the expectation of rewards backwards in each episode which requires multiple repetitions of the episodes to evaluate the value function. The reason for this is that we only give credit for making a step to a valuable state to the previous step and hence only update the corresponding value function. A different approach is to keep track of states which have been rewarded and assign the credit to each step that was visited. However, because we discount the reward proportional to the time it takes to get to the rewarded state, we also need to take this into account.

To realize this we introduce an eligibility trace we call $e(s, a)$. At the beginning, this eligibility trace is set to $0$ for all states. For each visited state we set the eligibility trace to $1$ for this current state, and we discount the eligibility for all other states by $\gamma$. This is demonstrated in Fig. 10.5. In the figure we indicate the eligibility trace building up during one episode until reaching the rewarded state, at which time the values of all states are updated in the right proportion. This algorithm does therefore only one optimal episode to find the correct value function, at least in case a learning rate of $\alpha = 1$. ```

While this algorithm requires some memory, we see that we need to store an eligibility trace which indirectly sequences the sequence agent took. It is also easy to extend this algorithm to a more general form TD($\lambda$) where we can interpolate the original TD algorithm with no eligibility trace, called TD(0), with the perfect memory of TD(1). An exponential decay of an eligibility trace can be implemented simply by including a factor $\lambda$ in Eq 10.23,

```
$e(s, a) \leftarrow e(s, a)\gamma\lambda \quad \text{for all } s, a. \quad (10.25)$
```

## 10.4.1 Value-function approximation with ANN

Up to this point we have outlined the basic ideas behind reinforcement learning algorithms. We will now move on to an important topic to scale these ideas to real-world applications. The previous method we used tables for the values for functions. For example, the value function in the above programs were look-up tables or arrays. Corresponding, this lead to tables for the policy. Such algorithms are now commonly referred to as tabular RL. The problem with this approach is that can be very big for large state and action. Indeed, the increased computational demand of calculating these quantities in real-world applications is often prohibitive, in particular in stochastic setting where we have to sample in the state-action space. To illustrate this with a point example, let us think tabular RL if we implement learning to play a computer game. Let us discuss the example of Atari 2600 games that have been implemented by Michael Bowling and the University of Alberta. This environment simulates video of 210 × 168 RGB video at 60Hz. The state of each game is equivalent to a state input vector of length 100,800 every 1/60 of a second. Even if each pixel is allowed to have, say 8 bits representation, $2^8$ possible values, and all the pixels are independent, this is impossible to implement with the tabular methods cited earlier. Bellman noticed these practical limitations and coined the phrase “curse of dimensionality.” The principle of using function approximators to represent the functions, and it comes at no surprise that we will specifically use deep neural networks for these function approximations.
