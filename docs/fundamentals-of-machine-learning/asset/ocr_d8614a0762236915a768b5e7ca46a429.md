# 3.3.4 Validation for hyperparameter learning

Thus we have mainly assumed that we have one training set, which we use to learn the parameters of the parameterized hypothesis function (model), and a test set, to evaluate the performance of the resulting model. In practice, there is an important step in applying machine learning methods which have to do with tuning hyperparameters. Algorithmic parameters define the parameters of the hypothesis functions. Such parameters include, for example, the number of neurons in a neural network, or which split criteria in decision trees, discussed later. SVMs have several parameters such as one to tune the softness of the classifier, called C, or the width of the Gaussian kernel $\gamma$. We can even see the number of iterations of some training algorithms. We will later shed light on these parameters, but for now it is important only to know that there are many parameters of the algorithms itself beyond the parameters of the parameterized hypothesis function (model), which can be tuned. To some extent we could think of all these parameters as those of the final model and it is common to make the distinction between the main parameters and the hyperparameters of the algorithms.

The question is how we tune the hyperparameters. In this is a learning problem for which we need a special learning set that we will call a validation set. The name indicates that it is used for some form of validation, although it is most often used to test a specific hyperparameters that can be used to compare different settings and to choose the better one. Choosing the hyperparameters is therefore a type of learning problem, and some form of learning algorithms have been proposed. A simple learning algorithm for hyperparameters would be a grid search where the parameters in constant increments over some ranges of values. Like simulated annealing or genetic algorithms, have also been used. A dominant mode that is itself often effective when used by experienced machine learners is the tuning of parameters. Whatever method we choose, we need a way to evaluate our choice with some of our data.

Therefore we have to split our training data into a set for training the main model parameters and a set for training the hyperparameters. We still call the training set, but the second is commonly called the validation set. Thus, the question arises how to split the original training data into a set for model parameters and the validation set for hyperparameter tuning. Now, by course we use the cross-validation procedure as explained earlier for this. Indeed, it is very common to use cross-validation for hyper tuning, and somewhat the name of the cross-validation coincides with the name of the validation set. But notice that the cross-validation procedure is a method to split data and this can be used for both parameter tuning and evaluating the predicted performance of our final model.

Once more, it is important to stress that the validation error should not be reported as our estimate of the final performance of our model. Using the validation data is a type of learning itself, and the model is tuned to these specific values. Such an error can be arbitrarily small with some form of overfitting. We need a test set that has not been used in any way during the training and model selection, so neither in the training of the primary model parameters nor in the selection of hyper-parameters to estimate a generalization error.
