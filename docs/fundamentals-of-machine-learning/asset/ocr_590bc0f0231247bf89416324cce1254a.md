In particular, an important factor in the original DQN network was the use of experience replay. Experience replay is now a common technique for the following reason. It is common that the learning rate be fairly small during learning to prevent instances from dominating. This means that specific episodes only have a very small contribution and one would need a large amount of episodes. In replay, we memorize a certain action and use min-batches of random samples for training.

Another common problem regarding why we need small learning rates is that Q-values can fluctuate a lot. A second important factor in the practical use of such networks is the use of a target Q-network. In this technique, we freeze the parameters of the Q-network for the estimation of the future reward. Let us consider these weights $w'$. We calculate the temporal difference as

```
$E = (r + \gamma max Q(s', a', w'))^2$
$\frac{\partial E}{\partial w} = (r + \gamma max Q(s', a', w') - Q(s, a, w)) \frac{\partial Q}{\partial w}$
```

The weights of this target network are updated only periodically.

# 10.5.1 Policy search

So far we have focused on finding a value function and we derived from the greedy policy as the action that leads to the largest return. The value function can be seen as a critic to adapt the policy. Another approach, especially when using function approximators, is to consider a parameterized policy directly and to search for good parameters of the policy. Such approach is called an actor. We need to find parameters that maximize the payoff. We illustrated this with a setting in 10.1.1C.
