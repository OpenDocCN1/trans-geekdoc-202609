The third problem is that with an increased number of dimensions the evaluation of the equations becomes more computational. However, there is a useful trick to alleviate the last problem in the case when the calculations always contain dot product between feature vectors. An example of this is the solution of the minimization problem of the dual problem in the earlier discussions of the linear SVM. The problem to be minimized in this formulation, depends only on the dot product between a vector $\mathbf{x}^{(i)}$ of one example and another example $\mathbf{x}^{(j)}$. Also, when predicting for a new input vector $\mathbf{x}$ from Egn 3.24 when adding the feature maps, we only need the resulting values for the dot products $\phi(\mathbf{x}^{(i)})^T\phi(\mathbf{x})$. We now discuss how such dot products can be represented with functions called kernel,

```
$K(\mathbf{x}, \mathbf{z}) = \phi(\mathbf{x})^T\phi(\mathbf{z}).$$
```

Instead of actually specifying a feature map, which is often a guess to start with, we could actually specify a kernel function. For example, let us consider a quadratic kernel between two vectors $\mathbf{x}$ and $z$

```
$K(\mathbf{x}, \mathbf{z}) = (\mathbf{x}^T\mathbf{z} + 1)^2.$
```

We can then write this in the form of Egn 3.38 to find the corresponding feature map. That is,

```
$K(\mathbf{x}, \mathbf{z}) = (\mathbf{x}^T\mathbf{z})^2 + 2\mathbf{x}^T\mathbf{z} + 1\n$= (x_1z_1 + x_2z_2)^2 + 2x_1z_1x_2z_2 + 1\n$= x_1^2z_1^2 + x_2^2z_2^2 + 2x_1z_1x_2z_2 + 2x_1z_1 + 2x_2z_2 + 1\n$= \phi(\mathbf{x})^T\phi(\mathbf{z}),.$
```

Except for the factors of $\sqrt{2}$ that do not matter as these can be absorbed into the definition of the weight parameters, this is the mapping function we discussed earlier. Instead of calculating dot product in mapped space, we can calculate a dot product in the original 3-dimensional space and simply square the result. Also, savings of computational complexity become even more pronounced with higher-order polynomials which we replace calculation of $O(n^2)$ with a fixed calculation in the original attribute space. There is an impressive saving of computations with this kernel trick.
