# 10 Reinforcement learning

In supervised learning we assumed that a teacher supplies detailed information on the desired response of a learner. This was particularly suited to object recognition where we had a large number of labeled examples. A more common learning condition is when an agent, such as a human or a robot, has to learn to make decisions in the environment. The agent in what follows is a machine learner that we implement in software, but it is useful to think about the agent as a system that can act in the world, like a robot or a human.

A good example of such a learning tasks for an agent is that of learning to play tennis. In this case the agent might try out moves and get rewarded by points the agent scores rather than a teacher who specifies every muscle movement we need to follow. Or, in the case of a robot, an engineer designs every sequence of motor activations. One approach that reaches supervised learning is that of a trainer who demonstrates the correct moves. This type of supervised learning is called imitation learning in this context. Much of imitation learning follows the previous discussion; we will concentrate on this chapter on an important learning scenario where the agent only gets feedback after periods of actions in the form of reward or punishment detailing which of the actions has contributed to the outcome. This type of learning scenario is called reinforcement learning (RL).

We formalize the learning problem in a Markov decision process and then discuss a variety of related algorithms for tabular functions. The second part of this chapter will use function approximators with neural networks which have made recent progress as deep RL.

## 10.1.2 The environmental setting of reinforcement learning

There are two more functions we need to describe the environment. The first one is the transition function, which simply the next state depends on the current state and the action taken. We restrict the discussion to the Markov condition, where the next state depends only on the current state and the intended action. This is called the Markov condition. In the probabilistic setting, the transition function is

Transition function: $s_{t+1} = \tau(s_t, a_t)$ (10.2)
$\tau(s_{t+1}|s_t, a_t)$ stochastic.

The second important function encapsulates the assertion of the environment; a teacher provides reward according to

Reward function: $r_{t+1} = \rho(s_t, a_t)$ (10.3)
$\rho(r_{t+1}|s_t, a_t)$ stochastic.

This reward function returns the value of reward when the agent enters state $s_{t+1}$ by taking action $a_t$ from $s_t$. In most cases, the reward only depends on the state it enters, but it depends on the previous state and the action taken from this state. In the probabilistic setting $\rho(s_t, a_t)$ is a probability of receiving reward in state $s_{t+1}$ when taking action $a_t$ from $s_t$.

The environmental functions $\tau$ and $\rho$, together with the specifications of the set of states $S$ and actions $A$, define the environment in which we want to make decisions. Since we restricted our discussion to Markov chains, the corresponding decision process is called a Markov decision process (MDP). We assume that in our notation the agent knows in which state it is. While we will see that this is easy in simulations later, this is a major problem in practice when the state needs to be derived from observations. For example, this is a common occurrence in robotics where we have sensors such as cameras or gyroscopes from which we want to estimate the pose of a robot. This general setting is commonly referred as the partially observable Markov decision process (POMDP). We discuss the basic ideas first in the MDP setting, then later discuss DeepRL which can be applied to POMDP setting.

RL faces several challenges. One is called the credit assignment problem, which includes action (spatial credit assignment) and at which time (temporal assignment) of the state should be given credit for the achievement of reward.
