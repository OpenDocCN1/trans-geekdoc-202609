We restrict the discussion to the common assumption that the transition function depends only on the previous state and the intended action from the corresponding state. This is called the Markov condition. The series of states with transition probabilities is a Markov chain, and for the T-maze example is shown in Fig. 10.1. A non-Markovian condition would be the case in which the next state depends on a series of previous states, and our agent would need a memory to make optimal decisions. The situation described by the Markov condition is natural as many decisions only depend on the current state. The Markov condition is therefore a good scenario and not a real limitation of the reinforcement learning methods we discuss later, but it will simplify some of the notations and discussions.

Reward function: $r_{t+1} = \rho(s_t, a_t)$ \quad (10.3)\n$\rho(r_{t+1}|s_t, a_t)$ stochastic.

This reward functions returns the value of reward when the agent is entering state $s_{t+1}$ by taking action $a_t$ from $s_t$. In most cases, the reward only depends on the state it enters, but it depends on the previous state and the action taken from this state. In the probabilistic setting the reward $\rho(s_t, a_t)$ is a probability of receiving reward in state $s_{t+1}$ when taking action $a_t$ from state $s_t$.

The environmental functions $\tau$ and $\rho$, together with the specifications of the set of states $S$ and actions $A$, define the environment in which we want to make decisions. Since we restricted our discussion to Markov chains, the corresponding decision process is called a Markov decision process (MDP). We assume that in our notation the agent knows in which state it is. While we will see that this is easy in simulations shown later, this is a major problem in practice when the state needs to be derived from observations. For example, this is a common occurrence in robotics where we have sensors such as cameras or gyroscopes from which we want to estimate the pose of a robot. This general setting is commonly referred as the partially observable Markov decision process (POMDP). We discuss the basic ideas first in the MDP setting, then later discuss DeepRL which can be applied to POMDP setting.
