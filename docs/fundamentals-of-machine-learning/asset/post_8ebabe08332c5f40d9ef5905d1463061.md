The Bellman equations are a set of n coupled linear equations for n unknown-values, and we have solved these here with linear algebra function to find an inverse of a matrix. Finding the inverse of a function can be implemented with different alg as Gauss elimination. However, it is more common to use an iterative procedure to solve the Bellman equation. For this iterative algorithm we starts with an estimation of the Q-function, and it by correcting the right-hand side of the Bellman equation.

Dynamic programming: $Q_{t+1}(s,a) \leftarrow \rho(s,a) + \gamma Q_t^\pi(\tau(s,a), \pi(\tau(s,a)))$.$ (10.13)

The fixed-point of this equation, is, the values that do not change with these iterations, are the desired values of $Q^\pi$. Way of thinking about this algorithm is that the Bellman equality is only true for the $Q^\pi$ values. For our guess, the difference between the left- and right-hand side is not 0, but we are minimizing this with the iterative procedure. Their corresponding code is

# Listing 10.10 RL.ipynb (Part 10)

```python
print('_Dynamic_Programming ')
Q = np.zeros([5,2])
for iter in range(3):
  for s in range(0,5):
    for a in range(-1,2,2):
      act = np.int(policy[tau(s,a)])
      Q[s,act]=rho(s,a)+gamma*Q(tau(s,a),act)

print('Q,values:\n',np.transpose(Q))
print('policy:\n',np.transpose(policy))
```

which is, of course, the correct solution as found with the explicit inversion. This iterative method is a much more common implementation and it does not require the explicit coding of the transition matrix. Iterative approaches will be used in all further methods discussed later. Note that we have only used three iterations to converge on the correct solution. Here we will set the number of iterations by hand, in practice we iterate until the changes in the values are sufficiently small.

## 10.2.2 Policy iteration

The goal of the RL is of course to find the policy that maximizes the return. So far we have only used a method to calculate the value for a given policy. However, we can start with an arbitrary policy and use the corresponding value function to improve the policy by defining a new policy which is given by the actions from each state that gives us the best return value,

```python
Policy iteration: $\pi(s) \leftarrow \arg_{a} Q^*(s,a)$. (10.14)
```

For the new policy, we can then calculate the corresponding Q-function and use this Q-function to improve the policy. In the maze we can see that the maximum in each column is the optimal policy. The corresponding code for our example is

Listing 10.11 RL.ipynb (Part 11)

```python
print('-->Policy_iteration')
Q = np.zeros([5,2])
Q.new = np.zeros([5,2])
for iter in range(3):
    for s in range(5):
        for a in range(-1,2):
            maxValue = np.max(Q[tau(s,a),0], Q[tau(s,a),1])
            Q.new[s,id(a)] = rho(s,a) + gamma*maxValue
    Q.copy(Q.new)

policy = calc_policy(Q)
print('Q values:\n' + np.str(transpose(Q))
print('policy:\n' + np.str(transpose(policy)))
```

## 10.2.3 Bellman function for optimal policy

Since we are primarily interested in the optimal policy, we could try to solve the Bellman equation. Here we propose

**Q-iteration:** $Q_{i+1}(s,a) \leftarrow \rho(s, a) + \gamma \max_{a'} Q_i(\tau(s,a), a')$. (10.17)

The corresponding code for our example is

Listing 10.12 RL.ipynb (Part 12)

```python
print('--> Q-iteration')
Q = np.zeros([5,2])
Q.new = np.zeros([5,2])
policy = np.zeros(5)
for iter in range(3):
    for s in range(0,5):
        for a in range(-1,2):
            maxValue = np.max(Q[tau(s,a),0], Q[tau(s,a),1])
            Q.new[s,id(a)] = rho(s,a) + gamma*maxValue
    Q.copy(Q.new)

policy = calc_policy(Q)
print('Q values:\n' + np.str(transpose(Q))
print('policy:\n' + np.str(transpose(policy)))
```
```text
--> Q-iteration
Q values:
[[0. 0.]
[0. 0.5 1.]
[0. 0.5 1. 2. 0.]]
policy:
[-1 1 1]]
```

There is an interesting difference between this value iteration method and the previous policy iteration. In the policy iteration method we followed the policy to calculate the value function. We call such a method **on-policy**. In contrast, in the ($Q$) iteration, we check out all possible actions from this state for the update of the value function. Such a procedure is **off-policy**.
