
## 2. Architecture

### 2.1 Components
- `Kube-controller-manager`: Ensures that the desired state of the cluster is maintained by managing controllers like the Replication Controller and Deployment Controller.
- `Etcd`: A distributed key-value store used for storing configuration data and state.
- `Worker Nodes`: Machines that run the application containers. Each worker node contains:
  - `Kubelet`: An agent that runs on each node, ensuring containers are running as expected.
  - `Kube-proxy`: Manages network routing and load balancing for services.
  - `Container Runtime`: Software for running containers, such as Docker or containerd.

### 2.2 Kubernetes Objects
Kubernetes uses various objects to manage applications and their state:
- `Pod`: The smallest deployable unit, which can contain one or more containers.
- `Service`: Defines how to access a set of pods, typically by creating a load balancer.
- `Deployment`: Manages the deployment of pods and ensures the desired number of replicas.
- `ReplicaSet`: Ensures that a specified number of pod replicas are running.
- `Namespace`: Provides a way to divide resources between multiple users or applications.

## 3. Core Concepts of Kubernetes
To work effectively with Kubernetes, you need to understand several core concepts that define how the platform manages containerized applications.

### 3.1. Pods
A `Pod` is the fundamental unit of deployment in Kubernetes. It encapsulates one or more containers that share the same network namespace and storage resources.

Characteristics of Pods:
- `Single or Multi-Container`: A pod can contain a single container or multiple containers that work together.
- `Shared Resources`: Containers in a pod share the same IP address, port space, and storage volumes.

Example YAML Definition:
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  containers:
  - name: my-container
    image: my-image:latest
    ports:
    - containerPort: 80
```

### 3.2. Services
A `Service` is an abstraction layer that defines a set of pods and provides a way to access them. Services can be exposed in several ways:
- `ClusterIP`: Exposes the service on a cluster-internal IP.
- `NodePort`: Exposes the service on each node's IP at a static port.
- `LoadBalancer`: Creates an external load balancer for the service.
- `ExternalName`: Maps the service to a DNS name.

Example YAML Definition:
```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: my-app
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
  type: LoadBalancer
```

### 3.3. Deployments
A `Deployment` manages the deployment of pods and handles scaling, rolling updates, and rollbacks.

Characteristics of Deployments:
- `Replicas`: Ensures a specified number of pod replicas are running.
- `Rolling Updates`: Allows updating the application with zero downtime.
- `Rollbacks`: Reverts to a previous version of the application if needed.

Example YAML Definition:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: my-container
        image: my-image:latest
        ports:
        - containerPort: 80
```

## 4. Kubernetes Workflow
A typical Kubernetes workflow involves several steps from defining your application to deploying and managing it.

### 4.1. Define Your Application
Create YAML or JSON files that describe the desired state of your application using Kubernetes objects.

### 4.2. Deploy Your Application
Use `kubectl` commands to apply your configuration files to the Kubernetes cluster:
```bash
kubectl apply -f my-deployment.yaml
```

### 4.3. Manage and Monitor Your Application
Monitor your application's status and manage resources using `kubectl` commands:
- Check Pods: `kubectl get pods`
- View Logs: `kubectl logs my-pod`
- Scale Application: `kubectl scale deployment/my-deployment --replicas=5`
- Update Application: `kubectl set image deployment/my-deployment my-container=my-image:v2`

### 4.4. Maintain Your Application
Perform routine maintenance tasks, such as rolling updates and rollbacks, to ensure your application remains healthy and up-to-date.

## 5. Advanced Kubernetes Concepts
Once you are familiar with the basics, you can explore advanced Kubernetes concepts:

### 5.1. Helm Charts
`Helm` is a package manager for Kubernetes that helps you define, install, and upgrade complex Kubernetes applications.

Key Features:
- `Package Management`: Distribute Kubernetes applications as charts.
- `Templating`: Define application configurations using templates.
- `Release Management`: Track and manage application releases.

Example Helm Command:
```bash
helm install my-release my-chart/
```

### 5.2. Operators
`Operators` are software extensions that manage the lifecycle of applications on Kubernetes.

Key Features:
- `Automated Management`: Implement application-specific operational knowledge.
- `Custom Controllers`: Extend Kubernetes capabilities to manage complex applications.

### 5.3. Custom Resource Definitions (CRDs)
`CRDs` allow you to extend Kubernetes with your own custom objects and controllers.

Key Features:
- `Define Resources`: Create new Kubernetes objects.
- `Extend Kubernetes`: Add custom functionality to the Kubernetes API.

Example CRD Definition:
```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: myresources.example.com
spec:
  group: example.com
  names:
    kind: MyResource
    listKind: MyResourceList
    plural: myresources
    singular: myresource
  scope: Namespaced
  versions:
  - name: v1
    served: true
    storage: true
```
