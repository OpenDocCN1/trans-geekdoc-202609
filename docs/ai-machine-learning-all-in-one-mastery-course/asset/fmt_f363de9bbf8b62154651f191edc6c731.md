### 2.2. Cloud Deployment
Cloud Deployment involves deploying the model on cloud services like AWS, Google Cloud, or Azure.

How It Works:
1. Choose Service: Select a cloud platform and deployment service (e.g., `AWS SageMaker`, `Google AI Platform`).
2. Upload Model: Upload the model to the cloud service.
3. Deploy Model: Configure the service for predictions and manage endpoints.

Pros:
● Scalable and reliable.
● Provides managed infrastructure and services.

Cons:
● Can be costly.
● Requires understanding of cloud platforms and services.

Example Code for `AWS SageMaker`:
```python
import sagemaker
from sagemaker.model import Model

# Initialize SageMaker session
sagemaker_session = sagemaker.Session()

model = Model(
    image_uri='your-docker-image-uri',

    role='your-iam-role',

predictor = model.deploy(instance_type='ml.m5.large')
```

### 2.3. Containerized Deployment
Containerized Deployment uses containers (like `Docker`) to package the model and its environment.

How It Works:
1. Create Dockerfile: Define a `Dockerfile` with the model, dependencies, and environment settings.
2. Build Image: Build a Docker image from the `Dockerfile`.
3. Deploy Container: Run the container on a local machine, server, or cloud service.

Pros:
● Consistent environment across different systems.
● Portable and scalable.

Cons:
● Requires knowledge of Docker and container management.

Example Dockerfile:
```dockerfile
# Use a base image with Python
FROM python:3.8-slim

# Set working directory
WORKDIR /app

# Copy model and requirements
COPY model.pkl requirements.txt ./

# Install dependencies
RUN pip install -r requirements.txt

# Copy the application code
COPY app.py ./

# Run the application
CMD ["python", "app.py"]
```

### 2.4. API-Based Deployment
API-Based Deployment exposes the model’s functionality through an Application Programming Interface (API).

How It Works:
1. Develop API: Create an API using frameworks like `Flask`, `FastAPI`, or `Django`.
2. Deploy API: Host the API on a server or cloud service.
3. Serve Requests: Handle incoming requests, run predictions, and return results.

Pros:
● Enables integration with various clients and services.
● Supports real-time and batch processing.

Cons:
● Requires API development and management.

Example Flask API Code:
```python
from flask import Flask, request, jsonify
import joblib

# Load the model
model = joblib.load('model.pkl')

# Initialize Flask app
app = Flask(__name__)

# Define prediction route
@app.route('/predict', methods=['POST'])
def predict():
    data = request.json
    prediction = model.predict([data['input']])
    return jsonify({'prediction': prediction.tolist()})

# Run the app
if __name__ == '__main__':
    app.run(port=5000)
```
