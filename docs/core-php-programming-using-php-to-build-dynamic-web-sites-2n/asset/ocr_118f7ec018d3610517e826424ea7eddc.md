There are two ways a script may halt unexpectedly: when the script runs too long, and when the user clicks the stop button. scripts are limited to a number of seconds specified in php.ini. This is usually 30 seconds, but you can change it. Look for the max_execution time directive. But 30 seconds is a good setting. If you write a script that could run forever, want PHP to stop. Otherwise a few errant scripts could slow your server to a crawl. For example, you usually want to allow users to be able to abort a page request.

There are times when you want a script to run to completion, and you can instruct PHP to ignore time limits and user abort. The set_time_limit function resets PHP's timer. See Chapter 11 for a complete description and example. I've written some scripts that run for an hour or more. Likewise, ignore_user_abort tells PHP to continue even when the user has clicked the stop button.

Instead of letting a script run, you might wish it to halt, but deal with the reason it halted with some code. To do this, you must first tell PHP to execute a special function whenever a script ends. This is done with register_shutdown_function. This function will execute regardless of why the script ended. It executes when the script ends normally. You can test this with the two functions: connection_aborted and connection_timeout. These are described in Chapter 8.

# Writing to the Browser

Three functions in PHP will send text to the browser: echo, print, and printf. Each does the same thing: they take values and print them to the browser. The printf function allows you to specify the format of the output rather than sending values as is. I've used print so far in my examples, mostly out of personal preference. I don't usually need the formatting that printf provides. Many PHP examples you will find on the Web use echo because it exists in PHP2 behaves more like an operator than a function. All three functions are discussed in Chapter 8.

It is important to remember everything you write in the context of a Web browser. Unless you make it otherwise, your output will be treated as HTML. If you send text that is HTML, it will be decoded by the browser into its intended form. I've been sending <BR> via print throughout the book so far, Listing 7.1 is a more dramatic example of this concept.

# Listing 7.1 Sending HTML with print
