At times, you may take advantage of how browsers react to different types of content. For example, text/plain displays in a fixed-width font with no interpretation of HTML. If you use /* for the content, the browser displays a dialog window for saving the file. Perhaps the most interesting use is for launching a helper application.

Listing 18.5 creates a tab-delimited file that may launch Microsoft Excel. Take note that the computer must meet a few qualifications. First, probably needs to be running Windows, and it must have Microsoft Excel. Newer versions of Excel associate the application/vnd.ms-excel content type with .xls files. My experience is that these headers will cause an Excel inside inside MSI or Netscape Navigator on a Windows machine, but your mileage may vary. Other browsers will likely ask the user if the file should be saved.

Notice the header in Listing 18.5. Content-Disposition. This is not part of the HTTP 1.1 standard but is widely implemented. It allows you to suggest a file name. If you add attachment; to the header, the browser may choose to open Excel in a separate window.

Using Content-Type this way is almost black magic, since browsers don't follow a standard when encountering different MIME types. This technique has proven to be most successful for me when writing intranet applications where I had the luxury of serving a narrow set of browsers.
