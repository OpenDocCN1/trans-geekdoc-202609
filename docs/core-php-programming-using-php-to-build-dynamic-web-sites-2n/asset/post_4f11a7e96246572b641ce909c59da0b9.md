Unlike object-oriented languages, such as C++, PHP does not allow properties of classes to be private. Any code may reach the instance and change or read the values of properties.

Accessing methods is similar to accessing properties. The `->` operator is used to point to the instance's method. This is shown in Listing 6.1 in the call to `getLastLogin`. Methods behave exactly as functions defined outside classes.

If a class extends another, the properties and methods of all ancestor classes are available in the child class, despite not being declared explicitly. As mentioned previously, inheritance is very powerful. If you wish to access an inherited property, simply refer to it as you would any other local property.

Three functions allow you to get information about a class as your script runs: `get_class`, `get_parent_class`, and `method_exists`. These functions are described in Chapter 8.

<?php
class classroom {
    var $name;

    //array of rooms
    var $room;

$home = new house();

Ultimately, in order to be useful, a script must communicate with the outside world. We've seen PHP scripts that send text to the browser and get some information from functions like `date`. In this chapter we will examine all the ways a PHP script can exchange data without using special interfaces. This includes reading from local disk drives, connecting to remote machines on the Internet, and receiving input form.

PHP is similar to other programming environments—with one exception: User input comes from HTML forms. The fields in forms are turned into variables. You can't stop your script in the middle and ask the user a question. This situation provides unique challenges. Each time a script runs, it is devoid of context. It is not aware of what has gone on before you make it so.

# HTTP Connections

It will be helpful to review how data travels between a browser and a Web server. I will review it for purposes of illustration, but you may wish to refer to detailed descriptions, such as those found on the W3C Web site <http://www.w3.org/Protocols/.

When you type a URL into the location box of your browser, the first task of the browser is to break it up into important parts, the first of which is the protocol, HTTP. Next is the name of the Web server, which the browser makes a connection. The browser must tell the Web server whose document it wants, and it does so using the HTTP protocol. Before completing the request, the browser may provide lines of extra information called headers. These headers let the server know the brand of the browser, the type of documents the browser can accept, perhaps even the URL of a referring page.

The server places these headers into environment variables to conform with the Common Gateway Interface (CGI). When a PHP script begins, the environment variables are converted into PHP variables. One of the most useful headers describes the brand and version of the Web server. This header is set by the browser as User-agent. The Web server creates an environment variable called HTTP_USER_AGENT that holds the value of the header. You can refer to it using `$`, just as for any other variable. If you are using Apache, you also have the option of using the `getallheaders` function. It returns an array of all headers exchanged between the browser and the server.

As a PHP script begins to execute, the HTTP exchange is the stage where headers have been sent to the browser, but no content has. This is a window of opportunity to send additional headers. You can send headers that cause the browser to ask for authentication, headers that request the browser cache a page, or headers that redirect the browser to another URL. These are just some of the HTTP headers you can send using the `header` function. The most common tasks are described in the section of this book.

Headers are placed on a stack, which is a data structure that resembles a literal stack of dinner plates. Imagine that each plate is a header. Each new line is placed atop the previous one. When it's time to send the headers, they are removed from the top, one at a time. This has the effect of sending the headers to the browser in the reverse of the order in which they were added. Usually this has no effect. HTTP doesn't define any special meaning to the order of headers. However, if you send the header twice, the later header may overwrite the value of the earlier. This means that if you try resending a header, the browser most likely ignore it. My advice is to write your scripts so they send headers only when they are.

There are two ways a script may halt unexpectedly: when the script runs too long, and when the user clicks the stop button. To do this, you must first tell PHP to execute a special function whenever a script ends. This is done with `register_shutdown_function`. This function will execute regardless of why the script ended. You can test this with the two functions: `connection_aborted` and `connection_timeout`. These are described in Chapter 8.

There are times when you want a script to run to completion, and you can instruct PHP to ignore time limits. The `set_time_limit` function resets PHP's timer. See Chapter 11 for a complete description. I've written some scripts that run for an hour. Likewise, `ignore_user_abort` tells PHP to continue even when the user has the stop button.

It is important to remember everything you write in the context of a Web browser. Unless you make it otherwise, your output will be treated as HTML. If you send text that is HTML, it will be decoded by the browser into its intended form. I've been sending `<BR>` via print throughout the book so far, Listing 7.1 is a more dramatic example of this concept.

# Writing to the Browser

Three functions in PHP will send text to the browser: `echo`, `print`, and `printf`. Each does the same thing: they take values and print them to the browser. The `printf` function allows you to specify the format of the output rather than sending values as is. I've used print so far in my examples, mostly out of personal preference. I don't usually need the formatting that printf provides. Many PHP examples you will find on the Web use echo because it exists in PHP2 behaves more like an operator than a function. All three functions are discussed in Chapter 8.

# Listing 7.1 Sending HTML with print

```php
<?php
print("You're using PHP;");
print($HTTP_USER_AGENT);
print("to see this page.<BR>\n");
?>
```
