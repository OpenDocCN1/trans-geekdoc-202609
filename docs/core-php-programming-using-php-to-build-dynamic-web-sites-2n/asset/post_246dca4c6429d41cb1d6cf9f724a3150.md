## Sorting with a Comparison Function

The built-in sort functions are appropriate in the overwhelming majority of situations. If your problem requires a sort that performs better than the one in the built-in functions, you are faced with coding your own. If your problem is that you need to compare complex elements, as objects or multidimensional arrays, the solution is to write a comparison function and plug it into the usort function.

The usort allows you to sort an array using your own comparison function. Your comparison function must accept two values and return an integer. The two arguments are compared, and if a negative values is returned, then the values are considered to be in order. If zero is returned, then the values are equal. A positive number signifies that the numbers are out of order.

In Listing 15.7 I created a multidimensional array with three elements: name, title, and wage. Sometimes I want to be list employees by name, but other I might want to list them by title or how much they make per hour. To solve this problem, the Name function is a simple wrapper for strcmp. The Title function assigns integer value to each title and returns these integers. The Salary function compares the wage element, but if two employees make the same amount per hour, their names are compared.

## Listing 15.7 Using the usort Function

```php
<?php
/*
** compare by name
*/
function byName($a, $b) {
    return strcmp($a[0], $b[0]);
}

/*
** compare by title
*/
function byTitle($a, $b) {
    return strcmp($a[1], $b[1]);
}

/*
** compare by salary
*/
function bySalary($a, $b) {
    return $a[2] - $b[2];

);

usort($employees, "byName");
```

## Indexing

Sorting organizes information into a form that aids in finding the exact piece for. If you need to look up a phone number, it's easy to flip through the pages of a phone book until you find the approximate area where the number might be. With a bit of scanning you can find the number, because all the names are in.

If you want to duplicate this process inside a PHP script, you have to think about each step. The simplest way is to start at the beginning and look at every entry until the one you want. If you get to the end and haven't found it, it must not exist. Dont probably the worst to search, but sometimes this is all you have.

You can dramatically improve your search time by doing a binary search. the requirement is that the data be sorted. Luckily, I've shown this to be relatively simple. the binary search involves repeatedly dividing the list into a half that won't contain the target value and a half that will.

To perform a binary search, start in the middle of the list. If the element in the middle precedes the element you are searching for, can you be sure it is in the half of the list that follows the middle element. You will now half as many elements to search through. If you repeat these steps, you will zero in on your targeted value very quickly. To be precise, the worst case is that it will take log n, or the base-two logarithm of the number elements in the data. If you had 128 numbers, it would take it 7 guesses.
