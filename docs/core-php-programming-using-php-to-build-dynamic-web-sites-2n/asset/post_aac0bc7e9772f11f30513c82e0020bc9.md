## Random Numbers
Closely tied to sorting and searching is the generation of random numbers. Often random numbers are used to put lists out of order. They offer the opportunity to create surprise. They allow you to squeeze more information into a single page by choosing content randomly for each request. You see this every day on the Web in the form of quotes of the day, banner ads and session identifiers.

There are two important qualities of random numbers: their distribution is uniform, and each successive value is independent of the previous value. To have a uniform distribution that no value is generated more often than any other. The idea of independence is that, given a sequence of numbers generated by the generator, you will be unable to guess the next one. Of course, we can't write an algorithm that really generates independent values. We have to some formula, which by its nature is predictable. We can get pretty close using a pseudorandom number generator. We use these mathematical expressions that return returning seemingly random numbers. You provide a starting input called a seed. The first call to the function uses this seed for generating, and subsequent calls use the previous value. Keep in mind that a seed will begin the same sequence of output values any time it's used. One way to keep things seeming different is to use the number of seconds to click to the generator.

The standard C library offers the rand function for generating random numbers, and PHP wraps it in a function of the same name. You pass upper and lower limits and integers. You can seed the generator with the srand function, or just let the system seed it with the current time. Unfortunately, the standard generator on some operating systems can be inadequate. Previously, I implemented my own random generator if you needed better random numbers; however, Pedro Melo added a new set of functions to PHP that use the Mersenne Twister algorithm.

I don't attempt to describe the algorithm behind the Mersenne Twister algorithm because it's out of the scope of this text. You can visit the home page for more information <http://www.math.keio.ac.jp/~matumoto/emt.html>. You can read a careful description to convince yourself of the validity of the algorithm if you wish.

Listing 15.10 is a very simple example that generates 100 random numbers between 1 and 100, using the mt_rand function. It computes the average and the median. If the distribution of numbers is uniform, the average and median will be very close. sample set is really small, though so you will see lots of variance as you rerun the script.

## Random Identifiers
If you need to track users through a site, you will need to assign unique identifiers. In a database you can store all the information you know about the user and pass the identifier from page to page either through links or with cookies. You will have to generate identifiers randomly, otherwise it is too easy for anyone to masquerade as a user. Fortunately, random identifiers are easy to generate.

Listing 15.11 illustrates how this works. A pool of characters to use in the session identifier is defined. Characters are picked randomly from the list to build a session identifier of the specified length. That identifier is used inside a link so that is passed to the next page. This method works for any browser, even Lynx.

It's very important to have random numbers here. Suppose you use the seconds on the clock. For one encore, every session identifier will be the same. And if very many people will be accessing a Web site during a single second. In Listing 15.11, I've used the microsecond clock to seed the random generator, but even this allows the window of opportunity for generating a duplicate session identifier. One way to avoid this situation is to use a lockable resource that holds a seed—for example, a file. Once you lock the file, you can read the seed and write back a new one, at which point you are assured that two concurrent processes get the same seed.
