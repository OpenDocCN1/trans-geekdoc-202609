## Sprinkling PHP within an HTML Document

The first and most obvious approach to using PHP is to build HTML files as you have always done, inserting PHP tags as if they were HTML tags. This could take the form of repeating HTML tags that replace with a call to a PHP function. It could take the form of a large block of PHP code that generates database output. Or it could be a script that processes a form submission. These are all situations where the impact of PHP on the site is slight. This is a good first step for those new to programming. You are able to insert the smallest amount of PHP code as a test. As your experience and confidence grow, so will your reliance on PHP.

Let's examine creating a function to replace repeating HTML. One great aspect of cascading style sheets is that they allow you to redefine how tags behave. Unfortunately, this technology is only available in the latest versions of Navigator and Internet Explorer. You can provide some functionality on the server side with PHP. Suppose we would like all of our headers to be in uppercase letters, size 7, and blue. The solution is to write a function that takes a string and prints it in the proper format.

In Listing 20.1 I've created a function called PrintTitle. This function wraps a given string in tags. In some cases the code is more readable than if I simply written it as static HTML, because each time there is a title, we call the PrintTitle function. This may have more meaning than the collection of tags for which it stands. This is one of the benefits of functions in general: they wrap up functionality into a single name.

## Core PHP Programming

Another benefit is I can be sure each title will be rendered in exactly the same way. Less text to type for each title means less chance of leaving out part of the formula. This is nice to the programmer, who is undoubtedly eager to find a shortcut to typing long segments of identical HTML. A higher degree of quality is ensured. If a call to the function is missed, PHP will display an error. If no errors are displayed, the titles are most likely displayed and in the correct format. If the title turns out not changing, the code must be altered in only one place. This is a good antidote to the painful phrase, "I changed my mind...."

Another similar use of PHP is to dress up what is essentially CGI output: a large block of PHP surrounded by HTML so that the output of the code simply appears in a larger page. This is a similar approach offered by SSI (Server-Side Includes). An SSI tag may call a CGI and insert the output in its pages.

The approach is appropriate in situations where your site is mostly static, but key areas must be dynamic. The advantage is very low on the Web server. PHP is used when absolutely necessary. In Listing 20.2 the code generates information that doesn't change, but it is easy to imagine that code pulls quotes from a database. It eliminates the need to edit the HTML page each time the information changes, but parts that don't change, like the layout of the page, are left as static HTML.

While Listing 20.2 is an example of dynamic output, you are often faced with the opposite situation. Your site may be completely static, but you need to accept catalog requests. PHP is a good solution for accepting forms. The first step is to create an HTML page that asks for name and address. Listing 20.3 demonstrates.

## Using PHP to Output All HTML

## Core PHP Programming

Any of the examples in the previous section is an excellent first step toward introducing PHP into a site. I like to think of sites using PHP-enabled, as they have a single pair of PHP tags. The output comes from the PHP script. Once information is put in a PHP variable, it's easy to add dynamic to it. It also has the advantage of being more readable. As a simple example, compare Listing 20.5 to 20.6. I have found that while this requires extra time, the code is more maintainable. My experience has that having all the HTML inside the PHP script allows quick changes. I don't have to search for the opening and closing tags buried inside the HTML in Listing 20.5. It also allows me to break code into separate lines in the source code that appear as a single line in the output. The output is the header text. It can enhance the readability but not sacrifice the precision. This has become very handy when dealing with tables. Leaving any whitespace between a TD and an image causes an extra pixel to appear.

The usefulness of these techniques, like that of others, increases with the size of the project. I've created 50-page Web applications using both approaches and can attest to the value of putting everything inside the PHP code.
