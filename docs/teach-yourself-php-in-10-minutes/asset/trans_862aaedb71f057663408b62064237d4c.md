

## PHP Shell 脚本在 Linux/Unix 上

在 Linux/Unix 平台上，*shell 脚本*只是一个包含一系列指令的文本文件，这些指令将由特定的语言解释器处理。最简单的 shell 解释器是 Bourne Shell，`sh`，尽管如今它已被 Bourne Again Shell `bash` 所取代，`bash` 与 `sh` 完全兼容，但还包含其他有用功能。

由于大多数命令 shell 中可用的命令语言非常受限，并且通常需要调用外部程序，PHP 不仅是一种更强大的语言，适合于许多任务，而且其内置功能通常也比标准系统工具提供更好的性能。

### PHP 位置

`php` 可执行文件通常安装在 `/usr/local/bin` 或 `/usr/bin`，具体取决于它是从源代码还是二进制包安装的，但您的实际位置可能有所不同。如果您不知道位置，请尝试输入 `which php` 来查找。

所有 shell 脚本都必须以字符 `#!` 开头，后跟要使用的命令解释器路径。对于传统的 shell 脚本，这将如下所示：

```
#!/bin/sh
```

但是，对于 PHP 脚本，第一行将是

```
#!/usr/local/bin/php
```

![](img/2edc6e6954e3485ad7d94117645931d8_226_1.png)

### 哈希奔（Shebang）

 shell 脚本开头字符序列 `#!` 最广泛使用的读音是 "hash bang"，尽管有时它也被称为 "shebang"。

 shell 脚本的文件权限必须允许该文件被执行。要为文件所有者设置执行权限，请使用以下命令：

```
$ chmod u+x myscript.php
```

如果您的脚本要由任何系统用户运行，设置全局执行权限的命令如下：

```
$ chmod a+x myscript.php
```

如果未设置执行位，您仍然可以通过在调用 php 时传递文件名参数，通过 PHP 解释器运行包含一系列 PHP 命令的文件。以下两个命令彼此相同（`-f` 开关可用于清晰度，但不是必需的）：

```
$ php myscript.php
$ php -f myscript.php
```

### 脚本名称

任何类型的 shell 脚本都没有命名要求。但是，保留 .php 扩展名很有用，以便文件名指示这是一个 PHP 脚本。Bourne shell 脚本有时带有 .sh 文件扩展名，但通常是没有任何文件扩展名的命令名。

## Windows 上的 PHP 命令脚本

Windows 不允许在批处理脚本中使用替代命令解释器，因此要在 Windows 下执行 PHP 脚本，必须向 php.exe 传递文件名参数。`-f` 开关是可选的，因此以下两个命令彼此相同：

```
> php.exe myscript.php
> php.exe -f myscript.php
```

### 批处理脚本

如果需要，您可以创建一个简单的批处理脚本，使用正确的文件名参数调用 php.exe，以便您可以使用单个命令运行脚本。

为此，您需要创建一个名为 myscript.bat 的文件，其中包含 php.exe 命令，后跟您的脚本名称。然后，您可以在命令提示符下直接输入 myscript 来运行该脚本。

## 嵌入 PHP 代码

与在 Web 环境中使用时一样，命令脚本中的 PHP 代码也需要嵌入。任何不出现在 `<?php` 标签内的文本都将直接发送到输出。

由于您通常希望创建一个完全由 PHP 代码组成的脚本，因此必须记住每个 PHP shell 脚本都要以 `<?php` 标签开始。然而，由于 PHP 的嵌入式特性，您可以创建一个 PHP 脚本，仅在大部分为静态文本的文件中生成某些元素。

## 为命令行编写脚本

PHP 语言提供了一些特别适合于编写命令行脚本的功能。您在 Web 环境中很少，甚至永远不会使用这些功能，但它们将在以下各节中描述。

### 字符模式输出

在生成 Web 输出时，您使用 `<br>` 标签在输出中产生简单的换行。当它发送到网页时，换行符 `\n` 会在 HTML 源代码中引起换行，但在呈现的网页中不可见。

然而，命令行脚本仅生成文本输出，因此您必须使用换行符来格式化输出。如果脚本产生任何输出，在显示最后一项后，应始终包含 \n。

运行命令行脚本时，您还可以利用固定宽度字符模式——例如，将输出间隔为列。printf 函数允许您使用宽度和对齐格式字符，除非它们包含在 `<PRE>` 标签中，否则对 HTML 输出没有影响。有关更多信息，请参阅第 6 课，“使用字符串。”

### 命令行参数

您可以通过在脚本名称后直接附加参数来向 shell 脚本传递参数。传递的参数数量可以在变量 $argc 中找到，参数本身存储在名为 $argv 的数值索引数组中。

> **参数** 标识符名称 argc 和 argv 出于历史原因而使用。它们起源于 C 语言，现在在许多编程语言中被广泛使用。
>
> 在 PHP 中，$argc 仅为方便而分配；当然，您可以执行 count ($argv) 来查明传递给脚本的参数数量。

$argv 数组将始终至少包含一个元素。即使没有向脚本传递其他参数，$argv[0] 也将包含脚本本身的名称，而 $argc 将为 1。

清单 21.1 中的脚本要求恰好传递两个参数。否则，将出现错误消息，脚本将终止。生成的输出显示两个参数中哪一个更大。

### 清单 21.1. 使用命令行参数

```
#!/usr/local/bin/php
<?php
if ($argc != 3) {
  echo $argv[0] .": Must provide exactly two arguments\n";
  exit;
}
if ($argv[1] < $argv[2]) {
  echo $argv[1] . " is less than ". $argv[2] . "\n";
}
elseif ($argv[1] > $argv[2]) {
  echo $argv[1] . " is greater than ". $argv[2] . "\n";
}
else {
  echo $argv[1] . " is equal to ". $argv[2] . "\n";
}
?>
```

请注意，清单 21.1 中的初始条件检查 $argc 的值是否为 3；必须有两个参数，加上 $argv[0] 中的脚本名称本身。事实上，$argv[0] 作为错误消息的一部分被输出。这是一种有用的技术，可以确保显示实际脚本名称，无论其名称是什么。

## 输入/输出流

尽管在 Web 环境中可以直接读写标准输入、输出和错误流，但在命令行脚本中这样做要有用得多。

流访问使用与文件访问相同的一组函数执行：您只需打开一个指向相应流的文件指针，并以同样的方式操作它。

流标识符看起来像 URL。请记住，PHP 还允许您使用文件访问函数打开 URL，由 php:// 后跟流名称组成。例如，要打开标准输入流进行读取，请使用以下命令：

```
$fp = fopen("php://stdin", "r");
```

但是，由于流访问在命令行脚本中很常见，PHP 提供了一个快捷方式。常量 STDIN、STDOUT 和 STDERR 提供对已打开流的即时访问，无需调用 fopen。

清单 21.2 中的脚本使用了所有三个标准流。它从标准输入读取数据，并使用 strtoupper 将其中的字母大写。如果输入数据包含非字母数字字符，则警告也会发送到标准错误流。

### 清单 21.2. 读写标准流

```
#!/usr/local/bin/php
<?php
while ( !feof(STDIN) ) {
    $line++;
    $data = trim(fgets(STDIN));

    fputs(STDOUT, strtoupper($data)."\n");
    if ( !ereg("^[[:alnum:]]+$", $data) ) {
        fputs(STDERR,
            "Warning: Invalid characters on line $line\n");
    }
}
?>
```

如果从命令行运行此脚本，它会等待您逐行输入数据，并在输入每行后返回大写版本。使用标准输入流的优势是您可以从另一个源重定向输入。

例如，要将文件 myfile 的内容传递给名为 myscript 的脚本，并将输出写入 outfile，您将运行以下命令：

```
$ myscript < myfile > outfile
```

使用清单 21.2 中的示例，outfile 将仅包含大写数据。生成的警告消息将继续显示在屏幕上，除非您还重定向了标准错误。

总之，命令行 PHP 中可用的常量和流标识符如表 21.1 所示。

### 表 21.1. CLI PHP 的流访问

| 常量 | 标识符 | 流 |
|---|---|---|
| STDIN | php://stdin | 标准输入 |
| STDOUT | php://stdout | 标准输出 |
| STDERR | php://stderr | 标准错误 |
