
## 登录身份验证

登录表单的核心只需包含两个字段——用户名和密码——以及一个提交按钮。只要这些元素存在，表单的布局由你决定。目前，你可以保持比较简单，采用简单的表格布局。示例 15.1 展示了基本登录表单。

### 示例 15.1. 基本登录表单

```
<FORM ACTION="login.php" METHOD="POST">
<TABLE BORDER=0>
<TR>
<TD>Username:</TD>
<TD><INPUT TYPE="TEXT" SIZE=10 NAME="username"></TD>
</TR>
<TR>
<TD>Password:</TD>
<TD><INPUT TYPE="PASSWORD" SIZE=10 NAME="password"></TD>
</TR>
</TABLE>
<INPUT TYPE=SUBMIT VALUE="Log in">
</FORM>
```

![](img/2edc6e6954e3485ad7d94117645931d8_165_0.png)

> **密码字段** PASSWORD 类型的输入与 TEXT 类型的工作方式完全相同，但输入的字符在键入时会被隐藏。密码字段的唯一限制是不能为其指定用于默认值的 VALUE 属性。

表单处理脚本 login.php 需要将提交的用户名和密码值与有效用户列表进行核对。在大多数情况下，你会将这些值与用户数据库进行核对。你将在第 19 课“使用 MySQL 数据库”和第 20 课“数据库抽象”中学习 PHP 中的数据库访问，目前你可以只使用一个允许使用该网站的用户简单数组。示例 15.2 展示了如何做到这一点。

### 示例 15.2. 登录处理器脚本

```php
<?php

session_start();

$passwords = array("chris" => "letmein",
"damon" => "thisisme",
"shelley" => "mypassword",
"vanessa" => "opensesame");
if (!$_POST["username"] or !$_POST["password"]) {
    echo "You must enter your username and password";
    exit;
}
if ($_POST["password"] == $passwords[$_POST["username"]]) {
    echo "Login successful";
    $_SESSION["auth_username"] = $_POST["username"];
} else {
    echo "Login incorrect";
}
?>
```

首先，构建一个以用户名为键的密码关联数组。脚本首先检查是否输入了用户名和密码，如果缺少该信息则立即退出。

然后，将提交的密码与键为提交用户名的数组元素进行比较。如果两个密码匹配，用户将登录，并初始化 `auth_username` 会话变量。否则，会显示登录失败的消息。

在用户会话经过验证后，他或她可以查看受保护页面，而 `auth.inc` 不会中断脚本的进度。

## 加密密码

在前面的示例中，密码以明文形式存储。你可能已经怀疑这并不特别安全；任何可以查看此脚本源代码的人都可以看到每个用户的密码。

![](img/2edc6e6954e3485ad7d94117645931d8_166_0.png)

> **窥探的眼睛** 即使你的服务器安全性无懈可击，你能确定没有人在偷看你的屏幕吗？你应该始终尝试防止未加密的密码在屏幕上显示。

PHP 中的 `crypt` 函数提供了一种简单但有效的单向加密算法。`htpasswd` 甚至 Unix 系统密码都使用相同类型的加密。要加密密码，你将密码和 `$salt`（加密所基于的另一个字符串）传递给 `crypt`：

```
$crypt_password = crypt($password, $salt);
```

虽然加密字符串无法解码回原始密码，但每次对相同密码和相同盐值运行 crypt 时，结果都是相同的。基于此，你可以只存储密码的加密版本，并将其与新加密的用户输入进行比较。

> **盐** 如果不指定盐值，将选择一个随机盐值，因此后续对 crypt 的调用会产生不同的结果。Unix 密码文件和 htpasswd 使用的两个字符的盐值就足够了。

使用 crypt 编码的字符串的外观可能因 Web 服务器而异，因为使用了系统级加密库。加密密码在不同系统之间不一定可移植。修订后的 login.php 文件显示在示例 15.3 中，但请注意，显示的加密密码可能对你的系统无效。

### 示例 15.3. 带加密密码的登录处理器脚本

```php
<?php
session_start();
$passwords = array("chris" => "ZXsDiRf.VBlWQ",
    "damon" => "bQLXBRzdBci7M",
    "shelley" => "KkTH39mVsoclc",
    "vanessa" => "69SvRIB9QVukk");
if (!$_POST["username"] or !$_POST["password"]) {
    echo "You must enter your username and password";
    exit;
}
$salt = substr($passwords[$_POST["username"]], 0, 2);
if (crypt($_POST["password"], $salt)
    == $passwords[$_POST["username"]]) {
    echo "Login successful";
    $_SESSION["auth_username"] = $_POST["username"];
} else {
    echo "Login incorrect";
}
?>
```

盐值始终位于加密字符串的前两个字符中，因此你将这两个字符赋值给 $salt 以在对 crypt 的调用中使用。除此之外，该过程与使用明文密码相同。

## 可用性考量

你目前实现的机制相当粗糙。任何登录错误都会导致显示一条消息并结束脚本。即使登录成功，流程也会结束，用户需要直接重新访问受保护页面。

理想的登录机制会中断对受保护 Web 页面的访问并显示其登录表单。然后，在成功验证后，它会将用户转发到他或她最初尝试访问的页面。

添加此增强功能的一种方法是在 auth.inc 中检查用户尝试访问的脚本名称；脚本名称和查询字符串（如果有）可以在 $_SERVER["REQUEST_URI"] 中找到。然后，登录表单将由 auth.inc 本身显示，而不是单独的页面。

如果向登录表单添加以下隐藏输入，登录处理器本身就会知道用户来自哪个脚本，然后你可以将用户发送回他或她正在尝试访问的页面。

```
<INPUT TYPE="HIDDEN" NAME="destination"
       VALUE="<?php print $_SERVER["REQUEST_URI"]; ?>">
```

当身份验证成功时，而不是向屏幕打印消息，你可以使用以下语句将用户转发到其目标页面：

```
header("Location: $_POST["destination"]);
```

## HTTP 标头

从 Web 服务器下载的每个页面都是 HTTP 对话交换的结果。Web 浏览器发送一组指令以指示它想查看哪个页面，服务器则响应一个表示请求成功的响应，以及各种其他不会直接显示在 Web 页面上的信息。

以下 HTTP 标头显示了从启用 PHP 的 Web 服务器发送的典型 Web 页面中随附的一些信息：

```
HTTP/1.1 200 OK
Date: Tue, 14 Dec 2004 21:17:28 GMT
Server: Apache/1.3.29 (Unix) mod_gzip/1.3.26.1a PHP/4.3.9
     mod_ssl/2.8.16 OpenSSL/0.9.7c
X-Powered-By: PHP/4.3.9
Connection: close
Content-Type: text/html; charset=iso-8859-1
```

## 发送自定义标头

发送自定义 HTTP 标头的 PHP 函数是 header。让我们先发送一个不执行任何操作的标头。任何以 X 开头的标头都被认为仅用于信息；例如，X-Powered-By 标头显示 PHP 已启用。要在脚本的 HTTP 标头中盖上你的名字，可以使用以下内容：

```
header("X-PHP-Author: Chris Newman <chris@lightwood.net>");
```

当然，除了极度虚荣之外，你没有理由想要发送这样的标头！浏览网站的普通用户永远也看不到这个标头！

你已经看到如何使用 setcookie 函数将 Cookie 发送到 Web 浏览器。你还知道，调用此函数时实际发送的是 Set-Cookie HTTP 标头。因此，以下两条 PHP 语句是等价的：

```
setcookie("mycookie", "somevalue");
header("Set-Cookie: mycookie=somevalue");
```
