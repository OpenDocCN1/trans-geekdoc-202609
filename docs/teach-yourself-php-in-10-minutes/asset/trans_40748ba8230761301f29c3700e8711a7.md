

## 摘要

在本课中，您学习了如何验证 HTML 表单中的用户输入，以及如何将表单呈现给用户，以便他或她可以纠正任何错误。在下一课中，您将学习 PHP 中的 Cookie 和 Session。

## 第 14 课。Cookie 和 Session

本节将探讨在网站页面之间传递数据的两种方式，而无需从一个页面向另一个页面提交表单：使用 Cookie 和使用 Session。

### Cookie

Cookie 是存储在 Web 浏览器中的小段信息。它们通常包含用于在您查看网站时识别您的数据，以便该网站可以为每位访问者进行定制。

无需使用表单或将数据作为查询字符串中的值传递给脚本，Cookie 会由您的 Web 浏览器自动发送回您的脚本。即使您离开并浏览到另一个网站，当您返回时，它们的值也会被记住。

例如，如果您需要登录才能访问特定网站，您可以让 Cookie 记住您的用户名，这样您每次返回时就不需要再次输入；在这种情况下，您只需输入密码。或者在社区网站上，您的浏览器可能会在 Cookie 中记录您上次访问的日期，以便自上次访问以来发布的任何论坛消息都可以被标记为新消息。

#### Cookie 组成部分

每个 Cookie 都包含一个名称和一个值，就像 PHP 中的普通变量一样。在 Web 浏览器中创建 Cookie 的指令会在 Web 页面传输之前作为 HTTP 头发送；当您的 Web 浏览器看到此头时，它会采取相应的操作。

创建 Cookie 的 HTTP 头是相同的，无论它们是由 PHP 或任何其他与 Web 服务器交互的方式生成的。用于设置名为 email 的 Cookie 的头可能如下所示：

```
Set-Cookie: email=chris@lightwood.net
```

**HTTP 头** 您在 Web 浏览器中永远不会看到实际的 HTTP 头。我们将在第 16 课“与 Web 服务器通信”中查看 PHP 中如何发送不同类型的 HTTP 头。

Cookie 也有过期日期；有些 Cookie 仅在 Web 浏览器打开期间有效，并保存在计算机内存中，而有些则在未来有固定的过期日期，并保存到硬盘中。用于设置将在 2005 年底过期的 email Cookie 的 HTTP 头将如下所示：

```
Set-Cookie: email=chris@lightwood.net;
expires=Sat, 31-Dec-2005 23:59:59 GMT
```

如果在 Set-Cookie 头中未发送 expires 属性，则在关闭 Web 浏览器时 Cookie 将被销毁。

可以设置的其他属性是域名和路径，浏览器将根据这些属性发送回 Cookie。当您再次访问设置了 Cookie 的页面时，其名称和值会被发送到 Web 服务器。

默认行为是将 Cookie 发送回设置它的同一域上的任何页面。通过设置域和路径，您可以指示 Cookie 发送回其他子域，或者仅发送回网站某个部分的脚本中。

以下头将创建一个 email Cookie，该 Cookie 将发送回 lightwood.net 的任何子域，只要请求的页面位于 /scripts 子目录中：

```
Set-Cookie: email=chris@lightwood.net; domain=.lightwood.net;
path=/scripts
```

**子域** 您只能将 Cookie 的域属性设置为最初设置 Cookie 的域的变体，或设置为 .yourdomain.com 以表示所有子域。

这是一种安全措施，用于防止某些网站混淆其他网站。例如，您无法设置一个 Cookie，使其从任何不托管在 php.net 上的网站发送回 www.php.net。

### 访问 Cookie

PHP 中的 $_COOKIE 超全局数组包含已发送到当前脚本的所有 Cookie。Cookie 会在 HTTP 头中发送回 Web 服务器，PHP 根据此信息构建 $_COOKIE 数组。

您可以像引用已发布的表单数据一样访问 Cookie。例如，以下语句显示 email Cookie 的当前值：

```
echo $_COOKIE["email"];
```

如果您觉得自己的 Cookie 有点混乱，可以创建一个脚本将它们全部转储到屏幕上，以便查看发生了什么。这很简单：

```
echo "<PRE>";
print_r( $_COOKIE );
echo "</PRE>";
```

### 使用 PHP 制作 Cookie

虽然您现在已经了解了如何使用 HTTP 头创建 Cookie，但您可能不会再次使用这种方法，因为 PHP 包含一个使 Cookie 设置变得更加容易的函数：

```
setcookie("email", "chris@lightwood.net", time() + 3600);
```

与本课前面头示例中所示的严格格式化的文本日期不同，您在 setcookie 中将过期日期指定为 Unix 时间戳。这样可以轻松设置一个固定时长或直到未来某个日期和时间的 Cookie。

> **过期时间** 过期参数指定存储的 Cookie 将被传输的最晚日期和时间。由于时间比较是在本地计算机上执行的，Cookie 的实际过期由本地系统时钟决定，如果该时钟不正确，则超出您的控制范围。

接下来的两个可选参数用于指定 Cookie 的域和路径。如果您想设置域和路径，但不设置过期时间，则将 NULL 用作第三个参数：

```
setcookie("email", "chris@lightwood.net", NULL,
".lightwood.net", "/scripts");
```

setcookie 的最后一个可选参数是一个标志，它告诉浏览器仅通过 SSL 加密连接将 Cookie 发送回服务器；换句话说，仅适用于地址以 https:// 开头的 Web 页面。

> **密码 Cookie** 虽然将密码存储在 Cookie 中非常方便，这样您再次访问网站时可以自动登录，但这非常危险，即使设置了安全标志也是如此。

Cookie 以纯文本存储，只需查看硬盘上的正确位置即可查看。存在恶意间谍软件程序，它们试图通过搜索您的 Cookie 来窃取您的密码！

### 删除 Cookie

没有 unsetcookie 函数来告诉 Web 浏览器删除 Cookie。为了防止 Cookie 值发送回 Web 服务器，您可以使用 setcookie 配合空值和已过期的过期日期。

以下示例使用一个小时前的过期值来注销 email Cookie：

```
setcookie("email", "", time() - 3600);
```

**覆盖 Cookie** 在注销 Cookie 或使用新值覆盖现有 Cookie 时，必须确保域、路径和仅 SSL 参数与最初创建 Cookie 时完全相同。

### Session

Session 与 Cookie 非常相似，可用于在网站页面之间传递值。但是，值不是存储在每个 Web 浏览器中，而是存储在 Web 服务器上，并使用单个身份 Cookie 来告诉 PHP 哪组值对应于当前用户。

因为在 Web 服务器和浏览器之间来回传输的数据要少得多，当存储较大数量的数据时，Session 比 Cookie 更高效。

#### 创建 Session

要在 PHP 脚本中初始化新 Session，您使用 session_start 函数。您可以使用可选参数来指定 Session 名称，但通常不需要。您网站上启动同一 Session 的每个脚本都将能够访问同一组 Session 变量。

调用 session_start 以创建新 Session 如下所示：

```
session_start();
```

$_SESSION 超全局数组用于存储和检索 Session 变量。与您迄今遇到的其他超全局数组不同，您可以直接将值分配给 $_SESSION，之后它们可用于任何共享 Session 的脚本。

请参阅清单 14.1 中的脚本，该脚本维护两个 Session 变量：查看页面的次数计数和上次访问的时间戳。

### 清单 14.1. 使用 Session 变量跟踪页面访问量

```
<?php

session_start();

if ($_SESSION["last_visit"]) {
    echo "Date of last visit: ";
    echo date("j F Y, H:i:s", $_SESSION["last_visit"]);
    echo "<br>";
    echo "Total visits: ".$_SESSION["num_visits"];
}
else
    echo "This is your first visit";

$_SESSION["last_visit"] = time();
$_SESSION["num_visits"]++;
```
