
你最常发送的头部几乎肯定是`Location`，它指示Web浏览器重定向到另一个URL。你可以使用此头部根据脚本中的事件更改网站的流程。导致用户的浏览器转发到另一个页面很简单，如下所示：

```php
header("Location: anotherpage.php");
```

你可以在`Location`头部中使用相对URL或绝对URL，因此你甚至可以将用户转发到另一个域，如下所示：

```php
header("Location: http://www.somedomain.com/newpage.php");
```

发送`Location`头部后，你应立即使用`exit`停止脚本，以确保不向浏览器发送任何进一步输出。

## 检查是否已发送头部

一旦PHP在脚本中遇到第一个非头部输出，它就会确保所有必要的头部已发送到Web浏览器，并开始处理页面本身。所有HTTP头部必须一次性发送，并且必须在任何网页输出之前发送。

如果脚本的头部已被发送，而你尝试发送另一个，PHP会给出如下错误：

[查看完整宽度]
警告：无法修改头部信息 - 头部已由（输出启动于 `/home/chris/ public_html/header.php:4`）在 `/home/chris/ public_html/header.php` 上

在`Location`头部的情况下，你不需要在页面上显示任何内容，因为浏览器会直接转到新URL。然而，你仍需小心在脚本开始前避免任何HTML输出，尤其是空白字符；即使在开头`<?php`标签之前有一个回车符，也将阻止你发送自定义HTTP头部。

PHP提供了`headers_sent`函数，你可以用它来检测该脚本中HTTP头部是否已发送。如果头部已发送，该函数返回`true`；如果为时未晚，仍可发送其他自定义头部，则返回`FALSE`。

以下条件可确保在尝试执行重定向之前头部尚未发送：

```php
if (!headers_sent()) {
   header("Location: newpage.php");
}
```

当然，如果此条件失败，你的脚本仍需要做其他事情。

`headers_sent`的两个可选参数允许你找出发送头部的脚本名称和行号。如果你的脚本报错，但你认为在该点头部尚未发送，这很有用。

### 清单16.1. 检查是否已发送头部

```php
<?php
$destination = "http://www.lightwood.net/";
if (!headers_sent($filename, $line)) {
    header("Location: $destination");
} else {
    echo "Headers were sent in line $line of $filename <br>";
    echo "<A HREF=\"$destination\">Click here to continue</A>";
}
?>
```

### 显示HTTP头部

如果你想查看已发送或将发送的HTTP头部，请使用`headers_list`函数，该函数在PHP 5及以上版本中可用。此函数返回一个数组，每个元素包含一个头部。

你可以对返回的数组进行循环，逐个获取每个值。但是，在许多情况下，你只想查看正在输出的头部以检查它们，此时，将数组传递给`print_r`即可：

```php
print_r(headers_list());
```

你需要确保在周围加上`<PRE>`标签以提高可读性。以下是典型输出：

```
Array
(
    [0] => X-Powered-By: PHP/5.0.2
    [1] => Set-Cookie: mycookie=somevalue
    [2] => Content-type: text/html
)
```

### 更改缓存设置

你可以使用HTTP头部来更改网页的缓存设置，以确定页面每次加载时是否完全刷新，或者用户的浏览器或其ISP是否会保留本地副本一段时间，以避免再次从你的网站下载。

你使用Cache-Control头部来指定页面使用的缓存方案。此头部的主要控制值如表16.1所示。

| 值 | 说明 |
|-------|-------------|
| public | 可存储在任何Web缓存中。 |
| private | 可保存到浏览器缓存中，但不可存储在共享Web缓存中。 |
| no-cache | 不可在Web服务器和浏览器之间的任何缓存中存储。 |

通常，覆盖默认缓存设置的原因是确保页面每次访问时都完全刷新。

在大多数情况下，Web缓存会检测到生成动态内容的PHP页面需要频繁刷新，但为了绝对确保你的最新内容在全球范围内都能正确显示，你可能希望给它提供一些帮助。

为了绝对确保你的页面不会被缓存，使用以下发送多个头部的语句，通常被认为是防止任何形式缓存的权威方法：

```php
header("Cache-Control: no-store, no-cache, must-revalidate");
header("Cache-Control: post-check=0, pre-check=0", false);
header("Expires: Mon, 26 Jul 1997 05:00:00 GMT");
header("Last-Modified: " . gmdate("D, d M Y H:i:s") . " GMT");
```

此处使用了几个不同的头部。发送了两个Cache-Control头部，包括一条no-cache指令。你可以在www.w3.org/Protocols/rfc2616/rfc2616-sec14.html#sec14.9上找到其他较少见的Cache-Control设置的更多信息。

Expires头部告诉浏览器文档何时过期。如果在此头部中发送一个历史日期，文档将始终被视为过期，并在下次查看时需要刷新。

Last-Modified头部告诉浏览器文档最近一次修改的时间。当你使用date函数时，此头部始终发送当前日期，因此浏览器总是认为文档刚刚修改过，并会完整请求页面的新副本。

### 会话缓存控制

启动PHP会话时，会自动发送`no-cache`头部，以及建立会话的其他HTTP头部。你可以使用`session_cache_limiter`函数，并以表16.1中的值之一作为参数，来使用不同的缓存设置。

## 服务器环境变量

现在让我们来看看PHP允许你从Web服务器获取的信息。

`$_SERVER`超全局数组包含若干元素，可提供当前页面请求期间Web服务器环境的信息。要在脚本上下文中查看完整列表，可随时执行此语句：

```php
print_r($_SERVER);
```

本节中的示例适用于大多数Web服务器。但是，某些服务器可能不支持所有显示的值，或可能使用不同的名称。你始终可以参考上述语句的输出，以检查脚本中哪些值可用。

### 脚本信息

当前脚本的名称可在`$_SERVER["SCRIPT_NAME"]`中找到。如果你想创建一个自提交的表单，但未来可能想更改其文件名，知道此名称很有用。你可以使用以下标记：

```html
<FORM ACTION="<?php print $_SERVER["SCRIPT_NAME"]; ?>"
METHOD=POST>
```

与`SCRIPT_NAME`类似的是`REQUEST_URI`元素，它包含页面请求的完整统一资源标识符。这包括当前脚本的完整路径，以及查询字符串中的问号和值（如果有）。查询字符串不包含在`SCRIPT_NAME`元素中，但你可以单独将其作为`$_SERVER["QUERY_STRING"]`来访问。

如果你想查找脚本运行所在的域名，可以查看`$_SERVER["HTTP_HOST"]`。你的Web服务器可能设置了多个别名域，这提供了一种方法来查看访问者正在哪个域名上查看你的页面。

### 用户信息

`HTTP_USER_AGENT`元素包含一个字符串，用于标识用户的Web浏览器软件和操作系统。它可能如下所示之一：

```
Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1; SV1)
Mozilla/5.0 (Windows; U; Windows NT 5.1; en-US; rv:1.7.5)
 Gecko/20041107 Firefox/1.0
```
