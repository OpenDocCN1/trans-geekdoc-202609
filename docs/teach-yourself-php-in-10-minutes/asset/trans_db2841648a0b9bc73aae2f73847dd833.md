## 第 22 课。错误处理

在本课中，您将学习如何有效地处理 PHP 脚本中的错误，以及如何调试不能按预期工作的代码。

### 错误报告

PHP 具有可配置的错误报告系统，您可以将其设置为对代码尽可能挑剔。默认情况下，最严格的模式未启用，并且在大多数情况下，只有当缺陷很可能影响脚本的预定用途时，您才会收到警告消息。

### 更改错误级别

要更改错误报告级别，您需要使用 error_reporting 函数，并传入由 表 22.1 中显示的常量组成的值。

**表 22.1。错误报告常量**

| 常量 | 描述 |
|---|---|
| E_ERROR | 指示致命运行时错误。脚本执行停止。 |
| E_WARNING | 发出运行时警告。非致命；脚本执行继续。 |
| E_PARSE | 指示编译时解析错误。 |
| E_NOTICE | 发出运行时通知，可能也可能不表示错误。 |
| E_CORE_ERROR | 发出由 PHP 内部生成的致命错误。 |
| E_CORE_WARNING | 发出由 PHP 内部生成的警告。 |
| E_COMPILE_ERROR | 发出由 Zend 引擎生成的致命错误。 |
| E_COMPILE_WARNING | 发出由 Zend 引擎生成的警告。 |
| E_USER_ERROR | 发出用户生成的错误消息，由 trigger_error 触发。 |
| E_USER_WARNING | 发出用户生成的警告，由 trigger_error 触发。 |
| E_USER_NOTICE | 发出用户生成的通知，由 trigger_error 触发。 |
| E_ALL | 发出除 E_STRICT 以外的所有错误和警告。 |
| E_STRICT | 发出所有错误和警告，此外 PHP 还建议代码更改以改善代码兼容性。 |

您通过使用位运算符组合这些常量来创建表示所需级别的位掩码。默认值是 E_ALL & ~E_NOTICE，这意味着将显示所有错误和警告，除了 E_STRICT（E_ALL 未涵盖）和 E_NOTICE。

要设置错误报告级别以显示所有警告和通知，请使用以下命令：

```
error_reporting(E_ALL);
```

默认不显示的通知类型并非致命，也不会影响脚本的正常执行。

E_NOTICE 错误级别在脚本开发期间非常有用，因为它会提醒您注意未定义变量的使用。虽然使用 E_NOTICE 不会导致脚本出错，但看到这些警告通常可以提醒您注意拼写错误的标识符名称，该名称应引用先前声明的值。

当您使用 E_NOTICE 时，您还会收到有关某些编码风格的警告。例如，数组键标识符应括在引号中，但粗心的程序员可能会使用 $array[key]。PHP 首先假设 key 是一个常量，但如果未定义该名称的常量，它还会尝试将其用作字符串键名。启用 E_NOTICE 后，您会被告知这种歧义。

E_STRICT 级别是 PHP 5 中的新功能，如果您想确保代码是最新的，它非常有用。如果您使用已为向后兼容性而保留在 PHP 语言中的弃用函数，它会警告您。

您也可以在 php.ini 文件中，或通过使用 .htaccess 按目录设置错误报告级别，使用 error_reporting 指令。第 23 课“PHP 配置”描述了如何使用这些功能。

### 显示错误

log_errors 和 display_errors 配置指令允许您选择是将错误和警告显示到屏幕还是写入日志文件。

在生产网站上，您应该考虑在屏幕上显示错误消息是否是安全风险，因为它可能会向入侵者或竞争对手透露有关系统的信息。

### 自定义错误处理程序

PHP 允许您定义一个自定义函数，每当遇到错误时都会调用该函数。这将根据您的配置，替代显示错误消息到屏幕或记录到文件的默认操作。

您使用 set_error_handler 函数来声明哪个函数应用作自定义错误处理程序。其第一个参数是函数名称，您可以提供一个可选的第二个参数，其中包含一个位掩码，指定哪个错误级别应由该函数处理。

例如，要使用函数 myhandler 来捕获所有 E_WARNING 和 E_NOTICE 错误，请使用以下命令：

```
set_error_handler("myhandler", E_WARNING & E_NOTICE);
```

用户定义的错误处理程序函数需要两个参数：错误代码编号和字符串错误消息。可以将错误代码值与 表 22.1 中的常量进行比较，以了解发生了什么类型的错误。如果您想要处理传递给函数的信息，可以包含三个额外的可选参数：发生错误时的文件名、行号和上下文。

清单 22.1 中的示例声明了一个自定义错误处理程序函数，该函数将所有错误记录到 MySQL 数据库表中。

### 清单 22.1。编写自定义错误处理程序

```
<?php

function log_errors($errno, $errstr, $errfile, $errline) {
    $db = mysql_connect("localhost", "loguser", "logpassword");
    mysql_select_db("test", $db);
    $errstr = mysql_escape_string($errstr);
    $sql = "insert into php_log
            (errno, errstr, errfile, errline)
            values
            ('$errno', '$errstr', '$errfile', '$errline')";
    $res = mysql_query($sql, $db);
}

set_error_handler("log_errors");

// Assigning an undefined variable will raise a warning
$a = $b;
?>
```

您使用以下 SQL 语句创建记录这些错误所需的数据库表：

```
CREATE TABLE php_log (
    error_timestamp timestamp,
    errno int,
    errstr text,
    errfile text,
    errline int
);
```

请注意，此示例未使用传递上下文的可选第五个参数。上下文作为数组传递，包含发生错误时脚本中的每个变量（包括局部值和系统超全局变量）的内容。

虽然在调试时这些信息有时很有用，但将其存储到日志文件或表中需要存储大量信息。而且，因为传递的值是数组，您需要将 $errorcontext 通过 serialize 函数，才能将其存储到数据库或文本文件中。

**上下文数据** 很可能您只对传递给错误处理程序函数的上下文数据中的一小部分感兴趣，因此您可以让函数提取必要的信息并丢弃其余部分。

### 引发用户错误

您可以使用 trigger_error 函数按需引发错误。如果已定义自定义错误处理程序，则它将处理此用户错误。否则，默认 PHP 错误处理程序将采取适当操作。

您应该向 trigger_error 函数传递一个错误消息字符串，并且可以选择提供一个错误类型常量。如果未给出错误类型，则使用 E_USER_NOTICE。

例如，要引发用户通知类型，请使用此语句：

```
trigger_error("Some kind of error happened");
```

显示的错误消息将类似于以下内容：

```
Notice: Some kind of error happened in /home/chris/error.php on line 3
```

要使用相同的消息文本引发错误，但作为致命错误，请改用此语句：

```
trigger_error("Some kind of error happened", E_USER_ERROR);
```

**错误类型** 对于用户错误，必须使用 E_USER_ERROR 和 E_USER_WARNING 类型，而不是 E_ERROR 和 E_WARNING。但是，E_USER_ERROR 类型错误仍被视为致命错误，脚本执行在发生时立即结束。
