

## 记录错误

可以使用 `error_log` 函数来满足大多数简单的错误日志记录需求。你可以使用该函数将错误消息写入 Web 服务器日志文件或其他本地文件，通过电子邮件发送，或将其传输到远程调试服务。

`error_log` 函数接受以下参数：

```
error_log($message, $message_type, $destination, $extra_headers);
```

只有 `message` 参数是必需的，默认操作是将此消息文本写入通常的 PHP 日志文件。在大多数情况下，这就是你 Web 服务器的日志文件。

`message_type` 参数指定一个数字，用于确定所提供的目标类型。其可能值如表 22.2 所示。

### 表 22.2. error_log 中的 message_type 参数值

| 值 | 说明 |
| :--- | :--- |
| 0 | 消息将写入默认的 Web 服务器日志文件。 |
| 1 | 消息将通过电子邮件发送；`destination` 包含发送地址，`extra_headers` 包含可选的电子邮件标头。 |
| 2 | 消息将发送到远程调试服务；`destination` 包含远程主机名。请注意，远程调试在 PHP 4 及更高版本中不可用。 |
| 3 | 消息将追加到本地文件；`destination` 包含文件名和路径。 |

例如，要通过电子邮件发送错误消息，你可以使用以下语句：

```
error_log("An error occurred in your script", 1, "chris@lightwood.net", "From: PHP Script Error <errors@yoursite.com>");
```

## 抑制错误和警告

PHP 允许你在脚本中抑制警告消息。你可以完全关闭警告，也可以选择单个命令，对于这些命令，任何错误都不会显示。

## 错误抑制运算符

如果只想针对特定语句阻止警告消息出现，可以使用 @ 符号将其静音。你可能希望这样做，以便显示你自定义的错误消息。

例如，连接到 MySQL 数据库时，如果连接失败，PHP 会引发其自身错误。你也可以通过检查是否返回了有效的数据库资源句柄来检测失败。以下代码使用 @ 符号抑制 PHP 错误消息，以便屏幕上仅显示你的消息：

```
$db = @ mysql_connect("localhost", "username", "password");
if (!$db) {
    echo "Database connection failed";
    exit;
}
```

你可以将 @ 符号放在 PHP 中任何表达式之前。它会导致因求值该表达式而生成的任何错误消息被忽略。

在前面的示例中，被静音的表达式是数据库连接尝试。一般来说，如果 PHP 中的某个东西有值，则可以在其前加上 @ 符号。你不能将 @ 符号添加到函数定义或条件语句等语言结构之前。

**解析错误** @ 运算符不会隐藏由脚本中的解析错误引起的错误消息。

以下语句也是有效的，尽管它不明确表明你预期错误消息源自 `mysql_connect`：

```
@ $db = mysql_connect("localhost", "username", "password");
```

**错误抑制** 如果你在脚本中使用 `set_error_handler` 指定了自定义错误处理程序，则 @ 运算符将无效。

## 防止显示错误

可以将配置指令 `display_errors` 在 `php.ini` 中设置为 `Off`，以防止任何错误显示在屏幕上。你将在第 23 课中学习如何更改 `php.ini` 设置的值。

如果选择以这种方式防止整个网站显示错误，则应打开 `log_errors` 设置，以便将错误和警告写入文件；否则，你将无法得知潜在问题。在网站开发期间，不应考虑关闭 `display_errors`。

## 第 23 课。PHP 配置

在本课中，你将学习如何使用 php.ini 文件在运行时配置全局 PHP 设置，以及使用 .htaccess 配置每目录设置。

## 配置设置

PHP 允许你使用一组配置指令来调整其行为的许多方面。这些指令可以对整个 Web 服务器全局生效，也可以进行仅适用于某些脚本的本地更改。

## 使用 php.ini

PHP 的配置文件名为 `php.ini`。其位置在编译时确定；默认情况下，它位于 Linux/Unix 服务器上的 `/usr/local/lib/php.ini` 和 Windows 系统上的 `C:\WINDOWS\php.ini`。

`php.ini` 文件包含一组配置指令及其值，用等号分隔。PHP 发行版中默认的 `php.ini` 文件有详细文档，包含大量注释。任何以分号开头的行都被视为注释，文件的各部分使用方括号中的标题分隔，编译器也会忽略这些标题。

清单 23.1 显示了 PHP 5 未修改的 `php.ini` 文件中的一个摘录，其中包含日志设置。如你所见，对于许多设置更改，你甚至不需要查阅在线文档。

### 清单 23.1. php.ini 的摘录

```
; Print out errors (as a part of the output). For
; production web sites,
; you're strongly encouraged to turn this feature off,
; and use error logging
; instead (see below). Keeping display_errors enabled
; on a production web site
; may reveal security information to end users, such as
; file paths on your Web
; server, your database schema or other information.
display_errors = On

; Even when display_errors is on, errors that occur
; during PHP's startup
; sequence are not displayed. It's strongly recommended
; to keep
; display_startup_errors off, except for when debugging.
display_startup_errors = Off

; Log errors into a log file (server-specific log, stderr,
; or error_log (below))
; As stated above, you're strongly advised to use error
; logging in place of
; error displaying on production web sites.
log_errors = Off

; Set maximum length of log_errors. In error_log information
; about the source is
; added. The default is 1024 and 0 allows to not apply any
; maximum length at all
log_errors_max_len = 1024
```

> **判断题** `php.ini` 中的布尔值可以设置为 `true`（即 `on` 或 `yes`）或 `false`（即 `off`、`no` 或 `none`）。这些值不区分大小写。

当以 Web 服务器模块运行时，`php.ini` 在 Web 服务器进程启动时读取，对配置文件所做的更改要在重新启动 Web 服务器后才会生效。

如果 Web 服务器将 PHP 作为 CGI 二进制文件运行，则每次运行脚本时都会加载 `php.ini` 设置，因为会启动一个新的 `php` 进程。同样，命令行 PHP 每次运行脚本时也会从 `php.ini` 加载设置。

## 备用 php.ini 文件

你可以创建单独的 `php.ini` 文件，以适用于 PHP 运行的不同方式。如果创建名为 `php-SAPI.ini` 的文件（将 `SAPI` 替换为有效的 SAPI 名称），则该文件将读取而非全局 `php.ini`。

例如，要仅为命令行 PHP 提供一组不同的指令，可以使用名为 `php-cli.ini` 的配置文件。对于 Apache Web 服务器模块，文件名将是 `php-apache.ini`。

在 Windows 系统中，Apache 安装目录中的 `php.ini` 文件优先于 `C:\WINDOWS` 中的文件。这允许你在同一台机器上为多个 Web 服务器维护不同的 PHP 设置。

要强制使用特定的配置文件，必须使用 `c` 选项调用 `php`。在 shell 脚本中，你可以将第一行更改为以下内容，以强制仅对该脚本使用自定义配置文件：

```
#!/usr/local/bin/php c /path/to/php.ini
```

## 每目录配置

Apache Web 服务器允许你使用名为 `.htaccess` 的每目录配置文件来提供自定义 Web 服务器指令。PHP 支持使用 `.htaccess` 来覆盖来自 `php.ini` 的全局设置。
