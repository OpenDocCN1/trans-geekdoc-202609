

## 其他安全特性

除了安全模式，PHP 还提供了一系列函数，允许你限制 PHP 可用的功能。

## 隐藏 PHP

你可以在 php.ini 中使用 expose_php 指令，防止 Web 服务器报告 PHP 的存在，如下所示：

```
expose_php = On
```

使用此设置，你可以阻止自动化脚本尝试攻击你的 Web 服务器。通常，HTTP 标头包含如下所示的一行：

```
Server: Apache/1.3.33 (Unix) PHP/5.0.3 mod_ssl/2.8.16 OpenSSL/0.9.7c
```

启用 expose_php 指令后，PHP 版本不会包含在此标头中。

当然，.php 文件扩展名会向访客暴露网站正在使用 PHP。如果你想使用完全不同的文件扩展名，首先需要在 httpd.conf 中找到以下行：

```
AddType application/x-httpd .php
```

然后，你需要将 .php 改为你喜欢的任何文件扩展名。你可以指定任意数量的文件扩展名，用空格分隔。要让 PHP 解析 .html 和 .htm 文件，从而完全不表明正在使用服务器端语言，可以使用以下指令：

```
AddType application/x-httpd .html .htm
```

### 解析 HTML

将 Web 服务器配置为使用 PHP 解析所有 HTML 文件可能很方便，但会带来少量性能损耗，因为即使网页中没有服务器端代码，PHP 解析器也需要启动。

为静态页面使用不同的文件扩展名，可以消除 PHP 在不必要的地方介入的需求。

## 文件系统安全

安全模式仅限制访问脚本所有者拥有的文件，你可以使用 `open_basedir` 指令指定文件必须所在的目录。如果指定了目录，PHP 将拒绝任何尝试访问不在该目录或其子目录树中的文件的操作。`open_basedir` 指令与安全模式独立工作。

要将 Web 服务器上的文件系统访问限制为仅 /tmp 目录，请使用以下指令：

```
open_basedir = /tmp
```

## 函数访问控制

你可以使用 `disable_functions` 指令指定一个逗号分隔的函数名称列表，这些函数将在 PHP 语言中被禁用。此设置与安全模式独立工作。

要在不启用安全模式的情况下禁用 `dl` 函数，请使用以下指令：

```
disable_functions = dl
```

你也可以以同样的方式使用 `disable_classes` 指令禁用对类的访问。

## 数据库安全

你在第 18 课“宿主程序执行”中了解到，恶意用户可能会尝试在你的系统上运行任意宿主命令，并且你可以使用 `escapeshellcmd` 函数来防止这种滥用。

类似的情况也适用于通过 PHP 使用数据库。假设你的脚本包含以下行，以根据表单值执行 MySQL 查询：

```
$sql = "UPDATE mytable SET col1 = " . $_POST["value"] . "
WHERE col2 = 'somevalue'";
$res = mysql_query($sql, $db);
```

你期望 $_POST["value"] 包含一个整数值，用于更新列 coll 的值。然而，恶意用户可以在表单输入字段中输入一个分号，后跟他想要执行的任何 SQL 语句。

例如，假设 $_POST["value"] 的值如下：

```
0; INSERT INTO admin_users (username, password)
VALUES ('me', 'mypassword');
```

然后执行的 SQL 将如下所示（为清晰起见，语句在此分行显示）：

```
UPDATE mytable SET coll = 0;
INSERT INTO admin_users (username, password)
VALUES ('me', 'mypassword');
WHERE col2 = 'somevalue';
```

这显然是一种糟糕的情况！第一条语句更新 mytable 中所有行的 coll 值。这会带来不便，但第二条语句造成了更严重的问题：用户能够执行一条 INSERT 语句，创建一个新的管理员登录。第三条语句是垃圾，但当 SQL 解析器到达该语句并抛出错误时，损害已经造成。这种攻击称为 SQL 注入。

当然，要使 SQL 注入构成严重威胁，用户需要了解一些关于你的数据库结构的信息。在此示例中，攻击者知道你有一个名为 admin_users 的表，其中包含名为 username 和 password 的字段，并且密码以未加密形式存储。

访问你网站的访客通常不会了解你自己构建的数据库的此类信息。但是，如果你的网站包含开源组件，例如你使用了一个免费的讨论板程序，那么你数据库中至少部分表的定义对用户是可见的。

此外，如果你的脚本在每次查询失败时都会输出内容，这可能会泄露数据库结构的重要细节。在生产网站上，你应该考虑将 display_errors 设置为 off，并使用 log_errors 将警告和错误消息写入文件，而不是直接输出。

## 数据库权限

至关重要的是，你的脚本建立的数据库连接应由仅拥有执行工作所需最小权限的数据库用户来完成。

你绝对不应该在脚本中以管理员身份连接。如果这样做，攻击者将能够完全访问你的数据库以及同一服务器上的其他数据库。攻击者还将能够运行 `GRANT` 或 `CREATE USER` 命令，在脚本限制之外授予自己完全访问权限！

为了防止 SQL 注入攻击的可能性，你必须确保构成查询一部分的用户提交数据不能被用来中断你打算执行的 SQL 语句。

上一个示例显示正在更新一个整数值。如果这是一个用单引号括起来的字符串值，攻击者需要在分号之前提交一个结束引号，然后再提交 SQL 语句。但是，当 `magic_quotes_gpc` 开启时，通过 Web 表单提交的引号会被自动转义。

要绝对确定表单提交的值不易受到 SQL 注入攻击，你应始终确保接收到的数据是适当的。如果你的查询期望一个数值，你应该使用 `is_numeric` 测试表单值，或使用 `settype` 将其转换为数字，删除任何旨在欺骗 SQL 的字符。

如果你要在一条 SQL 语句中处理多个用户提交的值，可以使用 `sprintf` 函数构建 SQL 语句字符串，使用指示每个值数据类型的格式字符。以下是一个示例：

```
$sql = sprintf("UPDATE mytable SET coll = %d
WHERE col2 = '%s",
    $_POST["number"],
    mysql_escape_string($_POST["string"]));
```

前面的示例假设使用的是 MySQL 数据库，因此字符串值被传递给 `mysql_escape_string`。对于其他数据库，你应确保引号字符得到适当转义，可以使用 `addslashes` 或其他合适的方法。

## 第 25 课。使用 PEAR

## 介绍 PEAR

PEAR 是一个用于可重用 PHP 包的框架和分发系统。PEAR 由以下部分组成：

- 面向 PHP 开发者的结构化开源代码库
- 用于分发和维护包中代码的系统
- PEAR 编码标准（PCS）
- PHP 基础类（PFC）
- 通过网站和邮件列表为 PEAR 社区提供的在线支持

## PEAR 代码库

PEAR 将许多不同的开源项目汇集在一起，每个项目都被捆绑到自己的包中。每个 PEAR 包都有自己的维护者和开发者，他们决定自己包的更改和发布周期，但所有 PEAR 项目的包结构都保持一致。

你使用随 PHP 附带的 PEAR 安装程序，只需提供包名即可自动下载并安装 PEAR 包。你将在本课后面学习如何使用 PEAR 安装程序。

每个包可能依赖其他 PEAR 包，这在文档中会明确注明，即使包看起来因为名称而相关。

PEAR 内部存在一个包树结构，下划线字符 (_) 分隔层级中的节点。例如，`HTTP` 包包含各种 HTTP 实用工具，而 `HTTP_Header` 专门处理 HTTP 标头请求。

## 包分发和维护

PEAR 包在 http://pear.php.net 的中央数据库中注册。PEAR 网站提供了按包名、类别和发布日期搜索数据库的可搜索界面。

PEAR 包的维护者使用 PEAR 网站管理他们的项目。CVS 服务器允许开发者协作开发源代码，一旦发布达成一致，即可从此中央位置立即提供。
