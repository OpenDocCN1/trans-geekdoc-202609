

# Mao 和 Boyd 逻辑分析

Mao 和 Boyd 逻辑的前提是一种有效的数据完整性和来源验证方法。所提出的协议使用 MAC 和哈希操作来建立数据完整性和来源验证。Mao 和 Boyd 逻辑依赖一组推理规则来证明安全属性。本分析中使用的推理规则集见附录。所提出协议的初始信念集如下：

1.  `$A| \\equiv A\\overset{R^{i}}{\\leftrightarrow}S$` 和 `$S| \\equiv A\\overset{R^{i}}{\\leftrightarrow}S$`：`S` 在其内存中为每个 IoT 设备保存一个 CRP，而 `A` 可以通过使用相应的挑战来生成 `R^i`。
2.  `A| ≡ S^(c) ⊲ ∥N[2]` 和 `S|≡A|≡{S}^(c)⊲∥N[2]`：`N[2]` 由 `A` 生成。
3.  `$A\\overset{R^{i}}{| \\sim} N\_{2}$`：理想化协议中的消息 2。
4.  `A| ≡ #(N[2])`：`A` 每次都生成一个新的 `N[2]`。
5.  `S| ≡ #(N[1])`：`S` 每次都生成一个新的 `N[1]`。
6.  `A| ≡ sup(S)`：关于 `N[1]`，`S` 是超级主体。
7.  `S| ≡ sup(A)`：关于 `N[2]`，`A` 是超级主体。
8.  `$A\\overset{R^{i}}{\\vartriangleleft}N\_{1}{R~} N\_{2}$`：理想化协议中的消息 3。
9.  `$S\\overset{R^{i}}{\\vartriangleleft}N\_{1}{R~} N\_{2}$`：理想化协议中的消息 2。
10. `A| ≡ S| ≡ {A}^(c) ⊲ ∥N[1]` 和 `S|≡A^(c)⊲∥N[1]`：`S` 每次都生成一个新的 `N[1]`。
11. `$S\\overset{R^{i}}{| \\sim} N\_{1}$`：理想化协议中的消息 1。
12. `$A\\overset{R^{i}}{| \\sim} N\_{2}$`：理想化协议中的消息 2。
13. `A| ≡ #(Δ)`：`A` 生成数据。
14. `$A\\overset{R^{i}}{| \\sim}\\Delta$`：理想化协议中的消息 2。
15. `A| ≡ S^(c) ⊲ ∥Δ`：`A` 生成数据。
16. `$S\\overset{R^{i}}{\\vartriangleleft}N\_{1}{R~}\\Delta$`：理想化协议中的消息 2。

[图 4.5](#15_Chapter04.xhtml#fig4_5) 的表格证明了这样一个事实：`A` 相信 `N[2]` 是 `A` 和 `S` 之间的一个良好共享密钥（即 `$A| \\equiv A\\overset{N\_{A}}{\\leftrightarrow}S$`）。现在可以应用来自 (5) 的良好密钥规则。该规则指出，如果 `A` 确信除 `A` 和 `S` 之外没有其他人见过 `N[2]`（`A| ≡ {A, S}^(c) ⊲ ∥N[2]`）且 `N[2]` 是一个新鲜的随机数（`A| ≡ #(N[2])`），那么 `N[2]` 就是 `A` 和 `S` 之间的良好密钥。反过来，可以使用来自 (2) 的保密性规则来证明 `A| ≡ {A, S}^(c) ⊲ ∥N[A]`，为此需要证明 `A` 和 `S` 共享一个良好的密钥 `$R^{i}(A| \\equiv A\\overset{R^{i}}{\\leftrightarrow}S)$`，并且 `A` 将 `N[2]` 发送给 `S` 并用 `R^i` 对其加密 `$(A\\overset{R^{i}}{| \\sim} N\_{2})$`。我们可以在初始信念集中找到这些陈述以及 `A| ≡ #(N[2])`。因此，初始陈述（即 `$A| \\equiv A\\overset{N\_{A}}{\\leftrightarrow}S)$`）得以证明。同样，[图 4.6](#15_Chapter04.xhtml#fig4_6) 确立了 `N[1]` 是 `A` 和 `S` 之间的良好共享密钥这一事实。[图 4.7](#15_Chapter04.xhtml#fig4_7) 和 [4.8](#15_Chapter04.xhtml#fig4_8) 的表格分别展示了主体 `S` 侧关于 `N[2]` 和 `N[1]` 的保密性证明。这些表格也证明了认证属性 [[20]](#15_Chapter04.xhtml#ref4_20)。为了证明数据的来源，对数据 `Δ` 进行了类似的分析，分别见 [图 4.9](#15_Chapter04.xhtml#fig4_9) 和 [4.10](#15_Chapter04.xhtml#fig4_10) 的表格。

## 4.3 结论

IoT 无疑将在不久的将来在全球范围内普及，并在雾计算和边缘计算的发展中发挥关键作用。尽管 IoT 为雾、边缘和云基础设施的集成展示了潜在的好处，但主要关注点之一是其安全性（即如何保护 IoT 环境及其运行）。由于资源限制和硬件局限（即这些协议关注网络层面的威胁而忽略硬件层面的威胁），传统安全技术不适用于广泛的 IoT 设备。因此，必须提出新的协议来保护 IoT 设备。本章提出了一种基于硬件原语的区块链，用于在 IoT 环境中建立数据溯源并保持数据完整性。所使用的硬件原语是 PUF。PUF 的使用赋予每个 IoT 设备一个独特的硬件指纹，该指纹被用于建立溯源。此外，使用区块链进行数据存储和检索的去中心化范式构成了保持完整性的基础。通过结合智能合约使用基于 PUF 的区块链，可以实现一种针对冒充和篡改攻击的防御机制。安全分析表明，基于硬件原语的区块链安全协议不仅能抵御网络层面的威胁，还能抵御物理攻击。然而，区块链技术的一个担忧在于其扩展能力。区块链中链的大小必然会随时间增长；如何有效且高效地对其进行扩展是一个开放的研究问题。解决此问题的一种方法是使用有向无环图（DAG），如 IOTA。[¹](#15_Chapter04.xhtml#fn4_1) IOTA 使用基于 DAG 的区块链，其中新的传入交易可以随时验证其他交易。它使用 `Tangle` [[22]](#15_Chapter04.xhtml#ref4_22)，其操作相对于传入交易的到达率（即，更多的新交易将产生更低的验证时间和更高的吞吐量）。这一想法前景广阔，可被利用来为 IoT 开发可扩展的区块链解决方案，并帮助将雾、边缘和云计算基础设施集成在一起。

## 附录

本节简要介绍了使用 Mao 和 Boyd 逻辑 [[20]](#15_Chapter04.xhtml#ref4_20) 对所提议安全协议的形式化分析。要理解他们的技术，首先需要将协议消息理想化。构造逻辑公式使用三种类型的信息：`M`：消息，`P`：主体，和 `F`：公式。大写字母 `A`、`B`、`P`、`Q`、……的表示法用于表示主体，字母 `K`、`M`、`N`、……用于表示消息，`X`、`Y`、`Z`、……用于表示公式。对于分析，使用以下谓词构造：

- `P| ≡ X`：`P` 相信 `X` 为真并可据此行动。
- `$P\\overset{K}{| \\sim}X$`：`P` 使用密钥 `K` 加密 `X`。
- `$P\\overset{K}{\\vartriangleleft}X$`：`P` 使用解密密钥 `K` 看到 `X`。在没有加密的情况下，我们使用 `P ⊲ X`。
- `$P\\overset{K}{\\leftrightarrow}Q$`：`K` 是 `P` 和 `Q` 的良好共享密钥。
- `#(M)`：`M` 是新鲜的（以前未使用过）。
- `sup(S)`：主体 `S` 是受信任方。
- `P ⊲ ∥M`：消息 `M` 对主体 `P` 不可用。
