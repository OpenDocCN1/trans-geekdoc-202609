**Figure 7.8** 区块链上以交易形式呈现的设备配置文件的会话示例，包含公钥和规则集；规则集包含特定的边缘配置文件。

假设注册过程正确完成，且设备使用真实配置文件进行注册，那么该设备将在区块链的整个生命周期内被保护在会话区块链中。事实上，即使假设攻击者获得了设备及其私钥的访问权限，也永远无法修改已注册的配置文件，因为区块链根据定义是不可变的。

利用这种结构还可以做另一件事，即注册第二个公钥；该公钥将是 `ED25519`，设备将用它对数据进行签名，随后发送给任意会话设备。添加此签名密钥使会话中的设备能够发送未加密的签名数据，这主要用于传感器。大多数边缘传感器将部署在公共场所，当传感器的目标肯定是与边缘共享数据时，隐藏这些数据毫无意义。因此，传感器可以使用签名密钥和边缘会话对数据进行签名，然后发送签名数据（通过所需的网络连接或第三方通道），最后接收设备验证签名并根据边缘会话认证发送传感器。

### 7.4.2 认证

边缘计算作为一种概念，利用大量设备通常通过机器间通信相互连接，以共享数据和资源。这种场景涉及大量设备、异构性和移动性（设备突然加入和退出），需要一种专门针对这些边缘系统约束量身定制的高效认证策略。如前所述，区块链可以成为执行边缘设备间此类认证的一种非常强大的技术。

为此，在属于区块链网络或会话的两个设备之间建立安全连接的过程如下。首先，每个设备可以将 `TLS` 连接的公钥与会话的公钥进行比较，如果该公钥属于该会话，则它将拥有一个关联了配置文件的规则集，如[图 7.9](#18_Chapter07.xhtml#fig7_9)所示。

![Figure 7.9 Device establishing TLS to a second device. The device can verify the identity of the device using the profile. TLS, transport layer security.](images/fig7_9_B.jpg)

**Figure 7.9** 设备向第二个设备建立 TLS 连接。设备可以使用配置文件验证设备身份。TLS，传输层安全性。

![Figure 7.10 Device establishing TLS to a second device. The second device can verify the TLS key against the session. TLS, transport layer security.](images/fig7_10_B.jpg)

**Figure 7.10** 设备向第二个设备建立 TLS 连接。第二个设备可以根据会话验证 TLS 密钥。TLS，传输层安全性。

第二步，将检查规则集配置文件，以验证并了解传入连接是谁，或者谁愿意连接，如[图 7.10](#18_Chapter07.xhtml#fig7_10)所示。

这种方法的主要优势在于验证在本地执行，并在会话设备之间完全分布式进行，无需连接到任何中心化实体来验证数据，从而成为一种高度可扩展的解决方案。

### 7.4.3 边缘提供数据的完整性

谈到边缘数据的完整性，主要有两个领域。第一是指验证任何边缘设备发送的数据的需求。第二涉及验证网关后边缘设备发送的数据，因此这些设备对于边缘来说是未知的。

#### 7.4.3.1 验证

设备中的数据验证过程可采用两种方法：

* 设备可以通过验证 `TLS` 连接来验证接收到的数据。在这种情况下，因为 `TLS` 保证是安全的，且 `TLS` 连接的公钥可以根据会话配置文件中的公钥进行验证，所以数据保证是正确的（参见[图 7.10](#18_Chapter07.xhtml#fig7_10)）。
* 或者，设备可以发送签名但未加密的数据（即传感器向网络广播温度传感器数据）。然后，接收数据的任何设备都能够通过使用会话验证数据签名来验证数据发送者，如[图 7.11](#18_Chapter07.xhtml#fig7_11)所示。

![Figure 7.11 Device sending signed data over the edge, the receiving device can verify the data.](images/fig7_11_B.jpg)

**Figure 7.11** 设备通过边缘发送签名数据，接收设备可以验证数据。

#### 7.4.3.2 网关

使用前面所述的规则集，边缘还可以注册另一种类型的设备，即同时拥有多个设备的设备，称为“网关”。在边缘计算中，大多数传感器都在网关之后，网关为它们提供访问权限。因此，这些传感器无法从网络到达，换句话说，就是无法到达网关之外（参见[图 7.12](#18_Chapter07.xhtml#fig7_12)）。因此，可以考虑网关所连接的不同设备来注册网关，并使用新的规则集。这将告知其他边缘设备设备和传感器存在于网关之后，但这些设备只能通过网关到达——尽管如果网关同时使用规则集注册了这些设备的密钥，则另当别论。因此，所有边缘会话参与者都将能够认证从网关后设备接收到的数据。

![Figure 7.12 Representation of an edge network with a gateway.](images/fig7_12_B.jpg)

**Figure 7.12** 带有网关的边缘网络示意图。

网关提供的数据将使用与任何设备相同的方法进行验证。如前所述，因为唯一的变化是实际的会话信息——让设备知道数据来自设备还是网关——验证仍将使用从网关配置文件中提取的公钥来执行。

网关的会话表示将如[图 7.13](#18_Chapter07.xhtml#fig7_13)所示。网关是一种设备，同时可以注册子设备，带有其自己的密钥和配置文件。因此，在注册会话时，网关会同时注册其子设备。
