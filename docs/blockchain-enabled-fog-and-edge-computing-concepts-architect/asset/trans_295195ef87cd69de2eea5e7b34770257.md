

# 区块链

区块链[[13](#13_Chapter03.xhtml#ref3_13)]最初由中本聪为加密货币比特币引入。作为一种不可篡改且可审计的分布式仅追加账本，区块链证明了其作为可信数据库的价值。复杂的计算、硬件资源的详尽消耗以及数据的分布式副本，在区块链的迅速崛起中发挥了重要作用。基于这些特性，区块链吸引了相关领域的研究人员，将其用于防篡改和可信的数据组织。若干经验证的交易被累积形成一个区块，随后计算该区块的哈希值。每个区块通过前一个区块的哈希值相连，从而形成区块链。

[图 3.2](#13_Chapter03.xhtml#fig3_2) 展示了区块链中交易验证、区块创建和区块添加的工作概览。区块并非直接添加到区块链中；它首先由“节点组——区块链网络”、矿工遵循“共识机制”进行验证。区块链网络可以是许可型（私有）或非许可型（公有）；许可型区块链部署在一组授权节点上，这些节点参与区块链网络中的区块挖掘和验证；而另一方面，任何节点都可以参与非许可型区块链[[14](#13_Chapter03.xhtml#ref3_14)]。

区块链是一种去中心化账本，需要在每个区块链节点上进行详尽的计算。在 CC-IoV 中，RSU 可具备边缘计算功能，为服务/应用提供者与车辆之间的服务请求和数据供给提供服务。在 RSU 上部署分布式区块链可实现频繁的计算和数据存储。在区块链赋能的边缘计算中，RSU 作为边缘计算节点，接收数据或服务请求并相应处理。另一项活动是收集交易并通过计算哈希值将其组装成区块形式，经区块链节点成功验证后合并入区块链。[图 3.3](#13_Chapter03.xhtml#fig3_3) 描绘了区块链赋能的 CC-IoV，其中 RSU 配备了边缘计算功能，最终成为区块链赋能边缘节点（BEN）。

由于数据传输对所有接收实体开放访问，且具备不可篡改性和可审计性，区块链被证明是一种极具潜力的技术，可用于车联网实体之间，以确保不发生恶意数据活动；若发生，也会因区块链特性而被轻易察觉。[图 3.4](#13_Chapter03.xhtml#fig3_4) 阐述了新兴网络技术及其应用。本章稍后将讨论 CCN 和区块链在 IoV 中的应用（参考相关研究），随后基于文献研究讨论研究动机，并提出我们的工作以解决现有工作中未涉及的问题。在结果与讨论部分，我们将基于通过运行仿真并设置一组参数所收集的结果来验证我们的解决方案。

## 3.2 文献综述

本节讨论该领域的现有工作，并将其分为两部分。第一部分涉及基于 CCN 的 IoV。第二部分涉及区块链赋能技术，进一步细分为三部分：第一小节讨论区块链赋能的 CCN，第二小节涉及区块链赋能的 IoV，最后一小节聚焦于区块链赋能的 CC-IoV。

### 3.2.1 面向内容的车联网 (CC-IoV)

文献[[15](#13_Chapter03.xhtml#ref3_15)]中，作者提出了一种基于 CCN 的 VANET 交通违章监控系统。兴趣包和数据包在警车 (CV) 与普通车辆 (OV) 之间传输。OV 根据车载单元 (OBU) 的传感器数据维护违章历史记录。每当 OV 经过 CV 时，数据包会响应 CV 的兴趣包被卸载给 CV。这使得在无巡逻和无覆盖区域监控和管控违章成为可能。但这留下了 CV 与 OV 之间的信任管理、用于交叉验证的违章记录管理，以及因同一违章被另一 CV 重复开具罚单等问题。

文献[[16](#13_Chapter03.xhtml#ref3_16)]中，作者提出了一种结合车载 CCN 概念的主动缓存技术，以最小化时延并应对移动性导致的动态连接需求。汽车通过 RSU 向数据存储 (DS) 发送兴趣包；DS 将请求的数据分割成块，并找出 RSU 及其到消费者的距离。经过这些计算后，DS 将数据块放置在汽车行驶方向上即将到达的 RSU 上。该技术专注于个人数据和 V2I 通信，仍保持中心化模式，且未考虑 DS 的移动性，而这对于智能车辆系统是必要的。

文献[[17](#13_Chapter03.xhtml#ref3_17)]中，作者提出了控制广播风暴和洪泛的内容分发技术。该技术利用地理位置来抑制冗余兴趣包的转发。收到兴趣包后，车辆计算与请求者的距离，距离最远的车辆将设置最低的延迟定时器并优先转发兴趣包。接收到转发节点的兴趣包后，节点将计算转发节点的方向；若朝向请求者移动则停止转发兴趣包的定时器，否则转发兴趣包。这将抑制其他节点转发兴趣包。然而，文中未讨论用于最小化时延和跳数的缓存策略。

文献[[18](#13_Chapter03.xhtml#ref3_18)]中，作者提出了一种面向内容的车载网络缓存方案。车辆根据在某区域停留最长时间形成群组，称为“热点区域”。车辆向 RSU 共享包含其坐标和时间戳的内容。特定热点区域内的车辆缓存邻居车辆的内容，并按需从其内容存储提供内容。同时遵循一种基于内容流行度的缓存替换策略：低流行度内容被新内容替换或更新流行度。这确保了时延最小化并减少了从内容提供者的跳数，但缺乏提供者的信任等级，且可能通过女巫攻击实现缓存污染。
