

# 第8章：物联网、雾/边缘计算与区块链的融合

本章重点关注物联网系统与雾/边缘计算架构及区块链范式的融合，因为这三种技术的结合发挥了各自的优势。本章结构安排如下：[第8.2节](#19_Chapter08.xhtml#sec8_2) 概述物联网、雾/边缘计算与区块链。[第8.3节](#19_Chapter08.xhtml#sec8_3) 详述这些技术各自面临的挑战。然后，[第8.4节](#19_Chapter08.xhtml#sec8_4) 探讨这种融合的优势与问题。[第8.5节](#19_Chapter08.xhtml#sec8_5) 展示文献中多个领域提供的一些解决方案。最后，[第8.6节](#19_Chapter08.xhtml#sec8_6) 总结本章。

## 8.2 背景

物联网、区块链以及边缘和雾计算是当前最流行的三大技术。它们通过允许创建众多技术应用，为增强和便利我们的生活提供了极具前景的解决方案。本节概述这三种范式。

### 8.2.1 物联网概述

电子和无线通信领域的最新技术进步，通过引入微型设备并允许它们参与数据的收集与交换，给物联网带来了一场革命。确实，这些优势使得小型化、高性价比、低功耗和多功能的传感系统得以构建，从而实现通信、监控多种关注现象以及随时间追踪趋势。此类系统如今广泛应用于智能家居、智慧城市、车辆、电子健康、农业等诸多领域，应用清单还在不断延伸。例如，通过实时收集生理健康信息，可以以一种更便捷、侵入性更小的方式远程监测患者健康状况，有助于及早发现潜在的异常健康情况。此外，得益于可添加到家庭中的多种小工具，可以随时随地控制家庭安防（即视频监控）或监控家用设备（如冰箱、空调、电视等）[[8]](#19_Chapter08.xhtml#ref8_8)。源于物联网系统，其他领域也应运而生，如车联网、能源互联网、区块链互联网和医疗健康互联网，它们通过利用环境智能、辅助驾驶、新型服务和先进应用，让生活变得更轻松[[9]](#19_Chapter08.xhtml#ref8_9)，[[10]](#19_Chapter08.xhtml#ref8_10)。

### 8.2.2 区块链概述

区块链是一种防篡改、加密的分布式账本，没有建立信任的中心方。区块链由包含信息的区块链表组成，这些信息被称为“一组交易”。每条区块链都是分布式的；这意味着区块链在区块链参与者的网络中是去中心化的。每个区块通过包含前一个区块的哈希值和加密签名，以加密方式链接到前一个区块。区块链上的参与者使用共识机制验证所有交易，这就是信任得到保证的方式（[图8.1](#19_Chapter08.xhtml#fig8_1) 和 [8.2](#19_Chapter08.xhtml#fig8_2)）。信任由由密码学支持的开源代码进行监控。在工作量证明区块链（一种共识机制类型）中，每笔新交易都必须由网络中的所有参与者进行验证，例如比特币和以太坊。使用另一种共识机制类型——权益证明，验证由网络中选定的参与者执行。这些共识机制使区块链安全且防篡改。

#### 8.2.2.1 区块链版本

区块链的架构从一开始就设计为能够处理多种多样的实现。确实，区块链的三代——即区块链1.0、区块链2.0和区块链3.0——可能彻底改变许多领域。区块链1.0包括加密货币、金融交易，或总体上讲，货币和支付的去中心化。区块链2.0和区块链3.0提供了区块链的增强用法，大约在2015年前后几乎并行爆发式地出现。区块链2.0常用于数字金融，区块链3.0用于数字社会。区块链2.0的核心思想是以分布式方式交换价值，与区块链1.0不同，后者在网络上传输的价值形式是货币，区块链2.0则以智能合约的形式传输可编程交易，智能合约被定义为在满足特定条件时自动执行的程序和规则。智能合约是嵌入区块链的交易，它创建了一个强大且去中心化的计算网络，并包含更复杂的逻辑。它存储自己的数据，并可访问其他资源以分析和评估其当前状态并执行操作。区块链最初的意图是创建一个公共网络，这指的是比特币、以太坊和莱特币的模式，但由于一些局限性（其完全的开放性以及处理交易在资金、时间和能源方面的高成本），私有区块链也应运而生。

#### 8.2.2.2 公有链与私有链

公有链和私有链的区别基于监控谁可以参与网络、参与哪些部分以及谁可以管理账本。私有链被视为封闭网络。加入需要邀请。由于处理节点数量减少，私有链速度更快，交易成本更低。尽管它们在加入区块链的流程上更复杂，因为存在访问控制。还有结合私有链和公有链的混合解决方案，称为“联盟链”[[11]](#19_Chapter08.xhtml#ref8_11)。

### 8.2.3 雾与边缘计算概述

随着连接设备数量和交换信息量的激增，云架构处理所有这些数据变得越来越困难。去中心化方法可能会给连接设备带来延迟和性能问题。为了在可扩展网络中设计高性能架构，提出了一种使用边缘和雾计算的去中心化数据存储系统。

雾和边缘计算是更新的架构，允许将数据处理从中心化的云移动到网络边缘。确实，因为预计连接设备的数量将持续增加，云需要处理的通信量将显著增长。此外，一些应用对延迟敏感；它们需要快速响应和移动性支持，例如医疗保健和智能交通中的交通信号灯系统。对于这些应用，传输数据造成的延迟是不可接受的，因为它们可能引发许多危险问题。因此，云模型的能力应当得到增强[[3]](#19_Chapter08.xhtml#ref8_3)。边缘和雾计算被用来应对这一挑战，通过将更智能的计算资源、网络和存储能力推向更靠近设备的位置，以及提供处理海量数据和更快响应等各种优势，以实现更好的服务质量和体验。[表8.1](#19_Chapter08.xhtml#table8_1) 总结了云、雾和边缘计算之间的差异。
