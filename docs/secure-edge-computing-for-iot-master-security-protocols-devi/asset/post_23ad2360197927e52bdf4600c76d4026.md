## Edge Network Technologies

Edge network technologies play a pivotal role in enabling IoT-ready network infrastructure. The Internet of Things (IoT) is a rapidly growing ecosystem of connected devices and sensors that generate vast amounts of data. Traditional cloud computing network architectures struggle to handle the real-time processing and low-latency requirements of IoT applications. This is where the edge computing network comes into play.

The following are some key edge computing technologies that enable IoT-ready network infrastructure:

- Multi Access Edge Computing (MEC): MEC, known as mobile edge computing, is an architectural network meant for enabling the placement of computational and storage resources within the Radio Access Network (RAN). The benefit of MEC is that it not only increases the efficiency of the network but also delivers content to end-users.
- Fog Computing: Fog computing extends the cloud closer to the edge devices, often within the local network. It enables data processing, analysis, and decision-making to occur at the network edge, reducing latency, and improving overall system efficiency. It also selectively helps with the storage and placement of data and computation in the most logical and efficient places.
- Edge Data Centers: In some cases, edge data centers may be established in strategic locations to support edge computing. These smaller, localized data centers help reduce latency, and support the processing needs of IoT applications. The micro data centers are small and modular reach-level systems that help in installing and managing the edge network computing that can be deployed globally in any environment. Due to their size, they are more suitable than traditional data centers to be used in many places.
- Edge Gateways: Edge gateways are devices that serve as intermediaries between edge devices and the cloud or data center. They aggregate data from multiple IoT devices, preprocess it, and transmit only relevant information to the cloud. Edge gateways can also run analytics locally.
- 5G and Edge: The rollout of 5G networks significantly enhances the capabilities of edge computing by providing high-speed, low-latency connectivity. 5G enables real-time data processing and communication for IoT devices in a way that was previously unattainable with 4G or older networks.
- Cloudlets: Cloudlets are small-scaled cloud data centers with enhanced mobility, located at the edge of a network. They stand as a representation of the second of the three-tiered hierarchy of IoT or edge devices. Cloudlets help in improvising resource-intensive and interactive mobile applications, by lowering the latency rate in mobile devices within nearby geographical proximity.

Cloudlets are the answer to the increase in latency delays associated with the Wide Area Network (WAN) cloud computing. With 5G networks making their presence felt already, cloudlets can help in supporting the resource-intensive applications meant for augmented reality, machine learning, speech recognition, and language processing.

- Security at the Edge: Edge computing requires robust security measures to protect data and devices. Technologies such as secure boot, hardware-based security modules, and identity management are crucial for securing the edge infrastructure.

## Edge Routing Protocols

One of the essential components of an edge computing ecosystem are the network protocols that facilitate communication between devices, edge servers, and the cloud. In this series of pages, we will explore various edge computing network protocols that play a pivotal role in enabling the seamless operation of edge computing environments.

- Message Queuing Telemetry Transport: MQTT, short for Message Queuing Telemetry Transport, is a lightweight and efficient messaging protocol that has gained immense popularity in the realm of edge computing, particularly in the Internet of Things (IoT) ecosystem. It is known for its low overhead, making it perfect for resource-constrained edge devices. MQTT operates on a publish-subscribe model, allowing devices to send and receive messages in a scalable and flexible manner. It is well-suited for scenarios where data needs to be transmitted between edge devices and edge servers, or even from edge to cloud, with minimal delay.

- HTTP/HTTPS (Hypertext Transfer Protocol/Secure): This is commonly used for web-based communication between edge devices and servers, including RESTful APIs.

- HTTP/2 and gRPC: Edge computing demands not only low-latency communication but also high-performance data transfer. HTTP/2 and gRPC (Google Remote Procedure Call) are two protocols that excel in delivering efficient and speedy communication between edge devices and servers.

HTTP/2, the successor to the traditional HTTP/1.1, brings multiplexing, header compression, and other enhancements that significantly improve data transfer efficiency. It is a strong contender for web-based edge applications.

gRPC, on the other hand, is a high-performance, language-agnostic remote procedure call (RPC) framework developed by Google. It is designed to work seamlessly with HTTP/2, and is well-suited for building efficient and robust communication channels in edge computing environments.

- CoAP (Constrained Application Protocol): When it comes to edge computing, not all devices are created equal. Some devices at the edge have limited resources in terms of processing power and memory. This is where the Constrained Application Protocol (CoAP) comes into play. CoAP is a specialized protocol designed to work efficiently in resource-constrained environments, making it a top choice for edge computing applications involving low-power devices.

CoAP offers a simple request-response model for communication, making it lightweight and ideal for scenarios in which edge devices need to communicate with each other, or with edge servers. It is particularly popular in industrial IoT applications, in which energy efficiency is crucial.

- AMQP (Advanced Message Queuing Protocol): While not as lightweight as MQTT or CoAP, AMQP is still a popular messaging protocol that is used for efficient, reliable, and secure communication between devices and services.

- WebSockets: While not inherently lightweight, WebSockets provide a full-duplex, low-latency communication channel over a single, long-lived connection. They can be a good choice for real-time applications in which lightweight data transfer is needed.

- OPC UA (Unified Architecture): This is a standard for industrial communication and data exchange used in industrial IoT (IIoT) and edge computing applications.

- DDS (Data Distribution Service): DDS is a protocol often used in real-time and mission-critical systems. It offers efficient data exchange between distributed applications, and is designed to be scalable and lightweight in certain configurations.

- ZeroMQ: This is a lightweight messaging library that supports various messaging patterns, and is suitable for building custom communication solutions in edge computing.

- AMT (Automatic Multicast Tunneling): This is a protocol used to optimize multicast traffic in edge networks and improve the efficiency of data distribution.

- Bluetooth: This is a wireless communication protocol that is commonly used for short-range communication between edge devices, especially in IoT and wearable applications.
