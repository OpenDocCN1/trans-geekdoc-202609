

## 传统五层网络模型

正如[图 5.2](#08_chapter05.xhtml#ch05_fig_002)所示，互联网上的通信网络通常组织为五个主要层：物理层、数据链路层、网络层、传输层和应用层（Keshav, 1997）。我们已经描述了各种无线物理层、链路层和网络层通信标准如何将数据从低功耗嵌入式传感器移动到本地网关。此外，在网络层，传统的域内和域间互联网协议（`IP`）路由协议被用于通过基于 `IP` 地址的路由机制将数据移动到所需目的地。对于 `IoT` 设备，越来越多地使用更新版本的 `IP`，即 `IPv6`，因为它为多达 `2^128` 个设备提供了足够大的地址空间（这个数字大到没有耗尽终端设备地址的危险，而这是它设计用来替代的先前部署版本 `IPv4` 曾开始面临的问题）。在传输层，互联网上本质上有两种主要选择——用户数据报协议（`UDP`）和传输控制协议（`TCP`）。`UDP` 旨在为容忍丢失且开销较低的数据提供尽力而为的交付，因为它不在互联网上的端点之间建立任何持久连接。另一方面，`TCP` 旨在提供更稳健、可靠、有序的交付，但会产生更高的开销。

## 应用层协议

在应用层，有几种协议和机制可用于跨互联网通信 `IoT` 数据。这些包括下文所述的 `REST` 和 `Pub-Sub` 应用层系统：

### 基于 REST 的 IoT 应用

`REST` 代表表述性状态转移，是一种用于互联网上端到端 Web 服务应用的架构，采用客户端-服务器模型（Fielding and Taylor, 2002）。最容易将其理解为 `HTTP` 的一种泛化，`HTTP` 是用于浏览 Web 的协议。在 `HTTP` 的情况下，客户端是浏览器，服务器是与网站关联的软件。客户端通过简单、统一、无状态的操作/命令/请求与服务器通信，包括 `GET`、`POST`、`PUT`、`UPDATE`、`DELETE` 等（参见[图 5.3](#08_chapter05.xhtml#ch05_fig_003)）。客户端使用这些命令请求和修改位于服务器上的资源。资源通过统一资源链接（`URL`）引用，服务器可用其识别相关信息以提供给浏览器客户端。“无状态性”在于服务器无需维护任何过去请求的记忆；满足给定请求所需的所有信息均包含在该请求本身中。在 `IoT` 感知系统的背景下，基于 `REST` 的应用可以向两个方向开发。第一种要求网关有效地充当服务器，接收来自远程节点（如云计算点或用户移动设备）的请求并相应地为其服务。第二种要求网关连接到基于云的服务器，将其数据进一步发送到该服务器。虽然 `HTTP` 和 `REST` 主要在可靠的 `TCP` 连接上工作，但也存在较新的低开销 `REST` 类通信实现，例如使用简单 `UDP` 的 `CoAP`。

### 用于 IoT 应用的发布-订阅中间件

由于其独特特性，例如数据来自许多潜在面向大量终端消费点的传感器设备，`IoT` 应用通常使用发布-订阅中间件构建，例如消息队列遥测传输（`MQTT`），一种 `ISO` 标准（Banks and Gupta, 2014）。在诸如 `MQTT` 之类的发布-订阅协议中（参见[图 5.4](#08_chapter05.xhtml#ch05_fig_004)），生产或消费信息的终端设备作为连接到充当消息代理的服务器的客户端行事。生产信息的设备（如传感器）向代理“发布”（发送）带有特定主题或通道 ID 的消息。对一个或多个主题感兴趣的任何设备都可以连接到代理并“订阅”这些主题。代理在任何给定主题上收到的任何消息都会转发给该主题的所有订阅者。因此，每个主题都有一个或多个可以发送带有该主题的实时消息流的发布者，以及一个或多个可以接收这些流的订阅者。除了 `MQTT`（在开源 `Mosquitto` 代理和 `RabbitMQ` 中实现）之外，还有其他 `Pub-Sub` 中间件协议和系统，如 `AQMP`、`XMPP`、`DDS` 和 `Apache Kafka`，它们具有不同级别的可扩展性和性能。还有专有的云实时发布-订阅消息服务解决方案，如 `PubNub` 和 `Satori`。`Pub-Sub` 系统通常在服务器上实现消息代理功能，并提供软件应用程序编程接口（`API`）和软件开发工具包（`SDK`），以允许设计可在从低功耗嵌入式设备到移动设备再到服务器的各种设备上运行的发布和订阅客户端。由于其灵活性、可扩展性以及支持广泛动态实时流的能力，此类 `Pub-Sub` 中间件系统开始在 `IoT` 系统背景下被广泛部署。

来自传感器系统的数据可以流式传输并聚合到云计算系统中，在那里它可以被存储、查询、可视化，并用于驱动在线决策系统的分析，包括诊断、异常检测、分类、推理和预测分析。接下来我们描述云计算系统在 `IoT` 和供应链应用数据管理中所起的作用。

## 云计算

“云计算”一词的普及始于 2000 年代，随着亚马逊网络服务（`AWS`）的推出，随后很快出现了来自微软 `Azure`、`Google Cloud Platform`、`IBM Cloud`、`Oracle Cloud`、`DigitalOcean` 等其他主要提供商的类似通用云产品。从本质上讲，云计算（Armbrust *et al*, 2010）是关于允许服务器端代码在大规模数据中心提供的计算服务器上运行，这些服务器可以为客户端应用程序远程进行处理和数据管理。云服务流行的一个原因是移动应用程序的增长，在这些应用中，通常必须以易于扩展的方式从一个或多个功能强大的计算机服务器提供数据存储、管理和其他服务。
