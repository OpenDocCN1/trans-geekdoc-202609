
# Python 机器学习：机器学习领域初学者综合指南

## Python 编程语言概述

### 简介

Python 是人们偏爱的几种多范式编程语言之一。它可用于多种用途，是解释型语言，且易于理解。Python 的工作方式令人惊叹，因为它使用户能够为复杂和简单的设计创建和使用各种程序。这意味着 Python 拥有一些特殊的插件，允许创建可在其他平台上运行的简单代码。因此，掌握 Python 知识，你就能确信自己能够在同一范式内处理不同的语言。

令人惊讶的是，当使用 Python 编码时，它能快速产出结果。尽管 Python 提供了对不同平台的访问，但它能即时给出结果。同样，使用 Python 编写代码变得很简单，就像在说人类语言一样。Python 拥有这种多任务特性，允许用户使用不同的风格实现单一的编程代码。风格可能会影响代码的最终结果；尽管结果肯定相同，只是略有修改。

Python 易于学习，但语法的核心重点是可读性。正因如此，维护风险大幅降低。模块和包是 Python 支持的基本要素；这些实现了代码的重用和程序的模块化。Python 的这些惊人特性使其成为程序员始终会使用并推荐给他人的领先语言之一。

### 核心特性

在编码时，Python 解释器及标准库始终可用。这些非常重要，因为它们确保了通过库免费访问其他外部平台，甚至包括它们的发行版。它们以二进制形式提供，并且无论平台如何，始终与其源代码保持关联。

Python 通过引用计数和循环检测垃圾收集器来管理内存。它具有动态解析功能，基本上在执行项目时绑定并保存方法及其他变量名。这使得编码不仅简单，而且极其实用。

Python 编程语言拥有诸如 `map`、函数归约等过滤器，以增强其在代码执行每个节点的使用。它拥有推导式、列表函数、字典、表达式集合和生成器。其标准库基本上是两个：`itertools` 和 `functools`。这些库负责函数实现，特别是来自其他来源的函数。

该编程语言的核心重点可概括为以下格言：

- **优美胜于丑陋**
- **显式胜于隐式**
- **简单胜于复杂**
- **复杂胜于繁琐**
- **可读性很重要**

许多人不解 Python 为何能以简单方式运行，尽管它处理复杂任务。这是因为它设计有广泛的扩展。这些扩展使得向现有应用程序添加接口变得更容易。Python 强调，拥有简单的语法和语法规则是赋予程序员编码方法论动态性的主要关键。

### 发展历史

在发展过程中，Python 经历了两次显著的发展。20 世纪 80 年代，它最初由 Guido Van Rossum 开发。然而，Python 近期的发展是由 Python 软件基金会主导的。

### 应用

Python 的用途包括：设计网站、游戏开发、数值编程、串口通信等。无论 Python 用于何处，其优雅始终存在，且多样的风格使网页设计非常独特。

### 执行模型

Python 编程语言本质上是解释型的。因此，在启动或运行给定代码之前，需要一次性编译所有编写的代码，以便通过 `print` 命令进行后续解释。同时，使用 Python，你作为程序员可以极大地促进不同软件设计背景的成长。抽象细节的过程是一种机制，作为 Python 的核心焦点，即使是新手也能理解。此外，使用 Python 编码相对简短；代码短但输出体面。

Python 的一个显著问题是，尽管它确保了快速开发，但执行速度略微滞后。Python 会编译代码，但当执行过程与 C 和 C++ 等其他语言相比时，它相对较慢。Python 的工作流程是：编码、调试、接收和执行。它通常包含 Linux 发行版和 macOS 系统以确保其速度。除了确保工作时的速度外，现代计算机相对较快，这也增强了 Python 的运行方式——这对它来说是一个优势。

### 生产力与调试

Python 始终是程序员的选择，因为它在提高生产力方面效率极高。Python 的步骤依次是编辑、测试和调试。有趣的是，Python 代码输入中的错误永远不会导致带有错误的分段故障；这使许多程序员认为它是最容易调试的语言之一。Python 不会通过解释器创建带有错误的分段故障，而是会引发一种异常。如果该异常仍未被捕获，它将作为堆栈跟踪打印出来——只是为了保证万无一失。

Python 编程语言使用调试器来检测编程中的变异性。除此之外，它还在编码时评估任意表达式的情况。有趣的是，这些调试器也是用 Python 语言编写的。这强化了 Python 拥有内省能力的事实。这还会深入代码行，在需要时对其进行必要的评估。

### 行业采用

总之，为了证明 Python 一直以来非常有用，许多其他技术都采用了它。其中包括 YouTube、BitTorrent、Eve Online、Google Search、Maya、iRobot 机器、Google App Engine 等。通过 Python 完成工作的有效性是使用它的一大优势。

## 第 1 章 – 认识 Python

由于本书面向初学者，因此向您介绍如何开始使用 Python 编程语言、它的用处、缺点、为何备受青睐以及更多相关内容至关重要。

总体而言，Python 被视为一种具有高级编程语言功能的开源语言。它诞生于 20 世纪 80 年代，由 Guido van Rossum 开发，后由 Python 软件基金会管理。Guido 受到启发的一个因素是 ABC 语言源自一门塑造了他职业生涯的语言。正如本书简介部分所述，Python 是最强大的语言之一，可用于创建游戏、编写 GUI 以及开发 Web 应用程序。

就 Python 代码的阅读和编写能力而言，它或多或少就像阅读和编写普通的英语语句；实际上它们并非用机器可读语言编写。Python 程序无需在机器运行前进行处理；它们只会被解释执行。此外，Python 是一种解释型语言（它拥有一个解释器）。这意味着每次编码后运行程序时，解释器都会遍历代码并将其翻译成机器可读的字节码。

Python 是一种面向对象的语言，允许用户管理和控制数据结构，因为它拥有庞大的数据结构类型。它也反对创建和运行程序（注：原文 "It has objected to create and run programs too" 疑为笔误，译文直译原意）。因为在 Python 中所做的一切都对程序员和用户有利，所有函数、对象、类、数据类型和方法在 Python 中地位平等。它是一种高级语言。为了充分发挥满足程序员需求的功能，Python 作为一种工具，能高效地开发生活方式、造福整个社会、造福人类的应用程序以及经济。

毫无疑问，Python 让一切变得更好；它提高了生产力、沟通效率和工作效率。任何语言的基本特征之一是它可能消亡并灭绝，从而被更新的语言取代——多年来 Python 证明并非如此。只有极具生命力的语言才能经受住时间的考验。Python 本身经受住了时间的考验，并证明自诞生以来在应用的各个方面都很有用。因为 Python 非常有利可图、简单且高效，所以推荐给所有人，尤其是想以编程为职业的人——没有编程基础的人肯定会觉得这很有趣。

简要介绍了 Python 之后，您想必已对它有所了解。那么，您可能会问，Python 有什么优势？使用 Python 编程语言的优势怎么强调都不为过，主要包括：

### 提高生产力

尽管 Python 编程使用的代码相对较短、更简单，与 C++ 等其他高级编程语言相比并没有多少代码量。同样，Python 拥有旨在产出更高生产力的完善内置功能。此外，它还拥有标准库，以及使用第三方模块和其他源库的机会。这些独特功能使 Python 语言编程更具产出和高效。

### 易于学习

尽管 Python 非常有效，但学习起来相当容易。这就是为什么许多人更喜欢并认为 Python 是学习编程的良好入门语言。事实上，许多程序员会反复向初学者推荐它。这是因为 Python 使用简单的语法以及更短的代码。

### 易于阅读

Python 程序使用精确、清晰且简洁的指令，非常易于阅读。即使没有扎实编程背景的人最终也会发现它非常容易——这是 Python 的优势。由于编辑、运行和调试功能的循环，用 Python 编写的程序易于维护、调试或增强——这就是可读性。

### 广泛支持主流平台

Python 编程跨平台运行于 Windows、macOS、Linux/UNIX 和其他操作系统，甚至适用于小型设备。此外，它还可以在遥控器、家电中使用的微控制器、玩具、嵌入式设备等设备上运行。

### 软件质量

凭借 Python 的可读性功能，代码的可重用性和可维护性使其成为一种杰出的编程语言，而不仅仅是古老的脚本语言。软件质量基于这样一个事实：代码的统一性超越了传统脚本。因此，即使是没有编程预备知识的人也非常容易阅读。Python 设置中连贯性功能的增强也使其具有高质量和独特性。能够重复使用相同代码的机制也是 Python 编程的一个独特属性。

### 少劳多得

程序员偏爱 Python 的原因之一是，较少的编码工作就能产出高生产力。除此之外，程序能即时运行，无需像 Java 或 C++ 等其他语言那样经历编译过程。换句话说，一旦程序正常运行，需要输入、调试或维护的东西就更少了。这鼓励程序员更快地推进工作。

### 程序耐用性

耐用性意味着可以在不同平台上为给定程序运行相同的代码。凭借单一代码串，可在其他平台上执行相同操作，尽管可能存在差异，这可能是因为是在不同平台上运行相同代码。编写优秀图形、用户界面等的多样化选项始终存在。同时，来自 Windows 和 Linux 等其他程序的代码将强烈要求脚本代码，这将导致它们无法在其他平台上使用。

### 组件集成与交互

通过不同的机制，Python 脚本可以轻松与应用程序的其他部分通信。此外，这种集成允许 Python 被用作定制和扩展工具的产品。Python 经历的变革使其代码能够调用 C 和 C++ 库，也能被 C 和 C++ 程序调用。令人惊叹的是，该代码还可以与 Java 和 .NET 组件集成。它可以通过 COM 和 Silverlight 等框架进行通信。由于这种集成，代码可以通过串口与设备接口，并通过 XML-RPC、SOAP 和 CORBA 等接口在网络上交互。

### 允许使用多样化的内置库

Python 的特别之处之一，也是人们偏爱它的原因，是因为它自带一个标准字典（注：原文 "standard dictionary" 疑指 "standard library"，此处直译原文）。该库支持一系列应用级编程任务，从文本模式匹配到网络脚本编写。此外，Python 既可作为内置库的扩展，也可作为大量第三方应用支持软件的扩展。Python 的第三方领域提供用于网站构建、数值编程、串口访问、游戏开发等方面的工具。

### 易于操作

使用 Python 获得的乐趣是人们更喜欢它而非其他语言的另一个因素。这是因为艰巨的任务（编码）被揭秘为或多或少像普通家务一样简单。因此，Python 使用内置工具。虽然考虑到其相关性的层面，这种理由可能显得薄弱，但生产力的提高和软件质量的改善也是与之并列的显著理由。

说了这么多关于 Python 构建方式的内容，问题依然存在：Python 是“脚本语言”吗？还是 Python 与脚本有关？要回答这个问题，请知悉 Python 是一种通用编程语言，常用于脚本角色。此外，Python 通常被定义为面向对象的脚本语言。这是一种支持 OOP 且整体面向脚本角色的定义。如果非要用一句话概括，可以说 Python 更广为人知的是一种通用语言。

要全面了解 Python，请在任意 Python 交互提示符下输入命令 `import this`（您将在本书后续内容中理解这一点）。这将调用 Python 中隐藏的一个“彩蛋”——一组渗透于语言及其用户社区的设计原则。其中，首字母缩略词 EIBTI 现在是“显式优于隐式”这条规则的时髦行话。

## 第 2 章 – Python 实战

### 安装 Python (Windows)

开始使用 Python 的一部分工作是在 Windows 上安装 Python。安装的第一步是从下面的链接下载您首选版本的安装包：

https://www.python.org/downloads/

访问此链接，您将被定向到一个页面。在该页面上，您需要在 Python 2 和 3 的两个最新版本之间进行选择：`Python 3.5.1` 和 `Python 2.7.11`。反之，如果您在寻找特定版本，可以浏览页面以找到早期版本的下载链接。通常，您会选择下载最新版本，即 `Python 3.5.1`（于 2015 年 12 月 7 日发布）——或者下载 Python 2 的最新版本 `2.7.11`。但是，您下载的版本必须取决于您想要进行的项目类型，虽然 Python 3 是该语言的现在和未来，但诸如第三方工具或兼容性之类的问题可能要求您下载 Python 2。

下载完成后，您可以通过点击下载的 `.exe` 文件继续安装。标准安装将包含 `IDLE`、`pip` 和文档。

### 安装 Python (Mac)

如果您使用的是 Mac，可以从以下链接下载安装包：

https://www.python.org/downloads/mac-osx/

学习的进程正进一步深入 Python 编程语言。实际上，Python 是一种适应性强且功能强大的语言，可从多个角度使用。这仅意味着当代码或声明要在逐行的基础上进行尝试，或者当您在探究其特性时，Python 可以被智能地使用。令人难以置信的是，Python 可以用于脚本模式，特别是当您想要解释整个声明文档或应用程序时。然而，使用 Python 需要极度小心——特别是当您正在接触或连接它时。这种谨慎对每种编程语言同样适用。

为了以交互方式使用 Python，可以使用命令行窗口或 `IDLE 开发环境`。既然您是编程或使用 Python 的初学者，将会有不同的步骤来介绍您如何连接和配合 Python 编程语言。以下是与 Python 快速交互的基本操作特性：

### 命令行交互

对于初学者来说，与命令行交互是使用 Python 的最简单方法。通过查看 Python 对在 `>>>` 提示符下输入的每条完成命令的反应，就可以简单地想象 Python 是如何工作的。命令行可能不是与 Python 交互的最受青睐方式，但多年来，它已被证明是初学者探究 Python 如何工作的最简单方法。

#### 使用命令行启动 Python

如果您使用的是 macOS、GNU/Linux 和 UNIX 框架，应运行 `Terminal` 工具以访问命令行。另一方面，如果您使用的是 Windows，可以通过右键点击开始菜单并启动 `Windows PowerShell` 来访问 Python 命令行。

由于编程指令需要输入命令，当您需要 Python 为您做某事时，您将通过输入它知道的命令来指令它，以获得类似的输出。命令的细微调整可能会给出理想的输出；请小心。有了这个，Python 将把这些命令翻译成您的计算机或设备能够理解和执行的指令。

让我们看看一些指南，以了解 Python 是如何工作的。请注意，您可以使用 `print` 命令来打印通用程序 "Heydays, Savants!"。

1.  首先，打开 Python 的命令行。
2.  然后，在 `>>>` 提示符下，输入以下内容（不要在 print 和括号之间留空格）：
    `print ("Heydays, Savants!")`
3.  现在，您应该按回车键，以便告诉 Python 您已完成该命令。

命令行窗口将立即显示 `Heydays, Savants!`。同时，Python 的反应正如它在书面安排中被告知的那样，它可以与之关联。

另一方面，要查看当您要求它使用 `print` 命令的错误语法打印相同字符串时它将如何错误地反应，请在 Python 命令提示符下输入并回车以下命令：

`Print("Heydays, Savants!")`

结果将是：

`Syntax error: invalid language structure`

这是当您使用无效或片段说明时会得到的情况的一个例子。请注意，Python 是一门**大小写敏感**的编程语言，因此每当您收到误解消息时，可能是因为您用大写字母写了 `print`。

显然，除了 print 命令外，您还可以直接在引号内输入您的声明，如下所示：

`"Primes, Savants!"`

请注意，声明是指令发出后您希望显示的词语；不过，能填入的词语不限于此处给出的示例。

#### 如何退出 Python 命令行

要退出 Python，您可以输入以下任一命令：

`quit()` 或 `exit()`。

随后，按住 `Control-Z` 然后按 `Enter`；Python 应该会退出。

您对 Python 编程的熟悉程度现在应该变得有趣了；还有很多部分需要学习，耐心会有回报。

### IDLE 的区域：Python 的集成开发环境 (IDE)

Python 最迷人的部分之一是 `IDLE`（集成开发和学习环境）工具。尽管这个特定工具包含在 Python 的安装包中，但您也可以下载越来越复杂的第三方 IDE。`IDLE` 工具为您提供了一个越来越有效的平台来编写代码并引人入胜地使用 Python。

要访问 `IDLE`，您可以浏览到您找到命令行图标的相同文件夹，或开始菜单（正如您从命令行交互中了解到的）。当您点击 `IDLE` 图标时，您将被引导至 `Python Shell 窗口`。这将带我们进入与 `Python Shell 窗口` 交互的部分。

### 与 Python Shell 窗口连接

当您位于 `Python Shell 窗口` 时，您将看到一个下拉菜单和一个类似于您在命令行窗口中看到的 `>>>` 提示符（讨论的主要连接）。有一个特定的 `IDLE` 编辑功能用于处理过去的命令。现在，您将使用相同的 `IDLE` 编辑菜单来回溯您过去的命令，剪切、复制和粘贴过去的语句，并在所有事情中，进行任何形式的编辑。

显然，`IDLE` 与命令行交互相比更像是一个飞跃。令人难以置信的是，`Python Shell 窗口` 的菜单下拉列表中有以下菜单项：

`File`、`Windows`、`Help`、`Shell`、`Options`、`Edit` 和 `Debug`。



这些菜单中的每一个都有不同的功能。`Shell` 和 `Debug` 菜单在制作大型项目时使用，因为它们为该过程提供获取功能。然而，虽然 `Shell` 菜单让您有机会重启 shell 或查看 shell 的日志以获取最新重置，`Debug Menu` 则有大量有价值的东西用于跟踪异常的源文件并高亮显示出错的行。通过 `Debugger` 选项，您将能够引入一个智能调试器窗口，它将使您能够单步执行并查看 Python 上运行的项目。

窗口的 `Options` 菜单使您能够编辑和设置 `IDLE` 以适应您自己的 Python 工作偏好。此外，在 `Help` 菜单中，您可以选择 `Python Help` 和文档。

### Python 标点符号中使用的引号

### Python 中的声明编写

### 多行声明的语言结构

如前所述，声明被称为指令。这些指令可能跨越多行；因此称为多行声明。在编写代码时，您需要将长声明分成多行。为此，您可以将语句包裹在圆括号、方括号和花括号内。基于编写风格，此过程是处理多行语句的首选风格。

另一方面，还有通过在每行末尾使用斜线（`\`）来显示行继续的方式来包裹多行。当您编写自己的代码时，对多行语法的理想理解变得简单。

### 缩进的句子结构

通常，空格用于表示代码块。这类似于在 `C`、`C++` 等其他编程语言中使用大括号。Python 是按空格排列的。使用 Python，代码块是按空格排列的，而不是按风格或偏好，而是作为一种严格的语言要求。许多开发者得出结论，这一准则结合其他准则使 Python 代码越来越易读和合理。

基于识别和结构，当您查看 Python 程序时，可以轻松识别代码块，因为它们开始于相同的向右距离。如果必须更深嵌套，您可以简单地将另一个块进一步向右缩进。

例如，这里是一个定义鞋子成本的程序片段：

```
def cost_of_shoes($5):
    cost = 5 * $
    if 3 >= 15:
        cost -= 4
    elif days >= 2:
        cost -= 10
    return cost
```

重要的是要注意，您应始终确保缩进空间在块内是一致的。当您使用 `IDLE` 和其他 `IDE` 添加代码时，当您输入需要空格的语句时，Python 会自动在后续行上提供空格。根据 Python 的原则，空格等同于向右 4 个空格；请坚持这一点。

创建缩进后，您可能想知道如何结束它。简单来说，每个缩进的结束就是块的结束。

Python 排除的第三个也是最后一个句法部分，对于大多数其他类 `C` 语言的学习者来说可能看起来是最重要的一点，即不需要在代码中编写任何无关内容来语法上访问括号代码块的开始和结束。您不需要像在类 `C` 语言中那样包含 `start/end`、`then/end if` 或包围括号块：

```
if (x > y) {
    x = 1;
    y = 2;
}
```

在 Python 中，相反，您始终如一地缩进给定单个嵌套块中的所有代码，给予它们相同的向右距离。请注意，Python 使用代码的物理空格来了解块在哪里开始和停止：

```
If a > b:
    a = 1
    b = 2
```

缩进意味着，现在，两个嵌套声明周围的空白字符。Python 不在乎您缩进的程度（您可以使用空格或制表符），也不在乎您如何缩进；您可以选择使用任意数量的空格或制表符。也就是说，一个嵌套块的缩进可能与另一个截然不同。通用的语法规则仅仅是所有缩进语句必须缩进相同的向右距离。这是因为如果不这样做，您将得到一个语法错误，并且您的代码将无法运行，直到您修复其缩进以使其保持一致。在经历执行阶段之前，请检查一切。

### 注释的语言结构

您如何在程序内编写和构建注释是以井号（`#`）符号开始该行。对于 Python 解释器，井号符号告诉 Python 解释器在运行代码时忽略注释。如果您的注释是多行的，可以在每行开头使用井号符号。或者，您也可以用三引号包裹多行注释。

以下是您应该了解的 Python 命名约定：

标识符可以是大写字母、小写字母、下划线和数字（0-9）的组合。因此，以下是有效的标识符：`theMovement`、`my_movement`、`move_1` 和 `print_what_is_world`。

以下是关于 Python 标识符的特别提示：

*   在标识符中，不允许使用特殊字符，例如 `%`、`@` 和 `$`。
*   请注意，`3life` 无效，而 `life3` 有效，因为标识符不应以数字开头。
*   通常，Python 是一门**大小写敏感**的语言。这是标识符的典型特征，这也是为什么 `Happy` 和 `glad` 是 Python 中两个特定的标识符。
*   Python `keywords`（关键字）不能用作标识符。
*   创建 `class`（类）时，`Class` 标识符必须以大写字母开头，但其余标识符小写。
*   标识符中不同单词的分隔符是下划线。
*   您应始终选择即使在很长一段时间后对您仍有意义的标识符。这就是为什么将变量设为 `c = 2` 很容易的原因。
*   为了未来的目的，建议您使用更长但更有意义的变量名，例如 `consider = 2`，这在任何混淆点都会变得更容易。

综上所述，Python 的语法已由 `modules`（模块）管理，您将在需要它们的地方用到。这是因为您将分别获得关于它的所有内容，而不是将其组装在一起。学习时别忘了运行项目。

## 第 5 章 – Python 的变量与数据类型

Python 编程的核心内容现在浮出水面。上一章通过解释 Python 语法的细枝末节——即指导单词串联成指令并进行解释的规则——为编码奠定了基础。在本章中，我们将探讨变量、它们的定义、语法等，以及 Python 中的数据类型。

Python 内部有一个容器；更像是一张可以存储值的**内存卡**；称为**变量**。根据其中存储的信息种类，可以对其进行访问或更改。变量就像是在编码时程序用来定位特定位置的方式。在某种程度上，变量用于追踪编写的程序存储的特定位置，以便进一步使用，如导出到其他平台、合并等。对于 Python 而言，变量可以指示（给出语句）计算机向该内存位置保存或检索数据。

在处理变量和数据类型时，Python 的工作方式与 Java、C 等其他相关语言有显著不同。这主要是因为虽然它们声明并将变量绑定到特定的数据类型，但 Python 却与不同的数据绑定——它只能存储一种唯一的数据类型。简单来说，如果要存储的变量是整数类型，那么在运行程序时，你将只能在该变量中保存整数。简而言之，在处理变量时，Python 没有僵化的处理方式；如果你想使用变量，只需想个名字，通过赋值声明它，如果需要，在程序执行期间也可以更改该值。



### 如何通过赋值声明变量？

```

```

下一行将显示此结果：

```
25
```

如果你想用 `my_variable` 存储字面字符串 “violet”，只需按以下方式将变量设置为 “violet”：

```

```

为了知道 `my_variable` 当前存储的内容，请使用 `print` 命令：


下一行，你将看到：

### Python 中的数据类型

Python 拥有不同的数据类型，以增强其对应用程序开发人员和程序员的重要性，因为提供了足够有效的数据。数据类型包括数字、日期、字符串、时间、布尔值和列表。

#### 数字数据类型

Python 可以在你不声明的情况下区分数字类型；这是使用 Python 最大的优势之一。凭借其内置函数，当你运行语句时，Python 会自动识别一种数据与另一种数据的区别。这些用于数值的内置函数共有四种，即：浮点数、复数、整数和长整数。值得注意的是，你使用的 Python 版本将决定活跃的内置数字函数的数量。然而，对于 Python 3，仅支持三种（浮点数、整数和复数）类型。

##### 浮点数

这些是实数。它们也被称为浮点数。浮点数表示实数。值得注意的是，当你想书写浮点数时，请在其中加入小数点，以将其与分数区分开来。另一种方式，你可以使用科学计数法书写浮点数；大小写均可；其中字母 ‘e’ 相当于 10 的幂。示例如下：

```
>>> 7.4e2
7400.0
>>> 7.4e2
742
```

你可以尝试其他数字序列以增强对浮点数的灵活运用。

##### 整数

与浮点数不同，整数不带小数点书写。它们是正负整数。Python 中的整数很多，下面仅给出少数作为指导，说明其他整数将如何处理；

**二进制整数**

要书写二进制整数，请使用 `0b` 或 `0B` 作为前缀（是数字零，不是字母 `o`）。示例如下：

```
>>> a = 0b3200
>>> print(a)
3200
```

**常规整数**

它们只是普通的数字，无论正负。例如 243、-110、3 等。

**十六进制整数**

它们也称为十六进制。要书写十六进制整数，请使用前缀 `0X` 或 `0x`（数字零和字母 eks）。示例如下：

```
>>> hex_lit = 0xA0B
>>> print(hex_lit)
238
```

**八进制**

这与其他进制一样，也使用 `0o` 或 `0O` 作为前缀表示。示例：

```
>>> c = 0O29
>>> print(c)
29
```

##### 复数

它们类似于实数，因为它们是实数，但总是成对出现。此外，复数也是虚数的集合。在组合中，它们采用浮点数和实数的形式，如下所示：`c + bJ`，其中 `c` 是浮点数，`b` 也是浮点数，`J` 是虚数的平方根。请看下面的例子：

```
>>> x = 5 + 6j
>>> y = 8 - 2j
>>> z = x + y
>>> print(z)
(13+4j)
```

请注意，复数在 Python 中的使用受到限制。

#### 字符串数据类型

字符串是特殊的数据，因为它们是包含字母、符号和数字组合的 Unicode 字符。在定义时，编码时请用“匹配的单引号或双引号”将字符串括起来。请看下面的例子：

字符串以多种方式处理索引或下标数字。请记住，Python 索引从 0（零）开始，而不是 1。因此，任何字符串的第一个字符必须从零开始。为了说明字符串索引在 Python 中如何工作，请在命令行定义字符串 "Hello Python"：

### 逻辑运算符

Python 支持 3 个逻辑运算符：`or`、`and`、`not`。

#### `x or y`

#### `x and y`

#### `not x`

**示例**：


### IF 语句

简单来说，Python `if` 语句选择要执行的活动。连同其外观搭档 `else`，它是 Python 中主要的选择工具，代表了 Python 程序逻辑的重要部分。这也是我们的第一个复合语句。像所有复合 Python 语句一样，`if` 声明可能包含其他语句，包括其他的不确定性（指嵌套 `if`）。事实上，Python 允许你在程序中连续连接声明（以便它们依次执行），并以主观嵌套设计（以便它们仅在特定条件下执行，例如选择和循环）。

#### IF 语句的通用格式

Python `if` 声明是大多数过程式语言中 `if` 语言的典型代表。它表现为一个 `if` 测试，后跟至少一个可选的 `elif` ("else if") 测试和一个最终可选的 `else` 块。测试和 `else` 部分各自都有一个相关的嵌套声明块，缩进在标题行之下。每当 `if` 声明运行时，Python 执行与第一个评估为真的测试相关的代码块，如果所有测试都为假，则执行 `else` 块。`if` 解释的一般形式如下：

```
if test1:                  # if 测试
    statements1            # 关联块
elif test2:                # 可选的 elifs
    statements2
else:                      # 可选的 else
    statements3
```

#### 基本示例

为了说明，我们应该看几个 `if` 声明工作的简单实例。除最初的 `if` 测试及其相关语句外，所有部分均为可选。因此，在最简单的情况下，其他部分被省略，请看：

```
>>> if 1:
...     print('true')
...
true
```

注意当你在基本交互界面中直观地编写时，提示符如何变为 `...` 以表示续行；在 IDLE 中，你只会简单地换行到缩进行（按退格键可回退）。一个空行（按两次 Enter 键可得）结束并运行整个声明。请记住 `1` 是布尔真值（稍后我们将看到，单词 `True` 是其等价物），所以该语句的测试持续成功。要处理假结果，编写 `else` 将是：

```
>>> if not 1:
...     print('true')
... else:
...     print('false')
...
false
```

你必须理解一种将 `if` 和条件语句结合执行的方法。现在这里有一个更复杂的 `if` 声明示例，包含其所有可选部分：

```
>>> x = 'animal kingdom'
>>> if x == 'jack':
...     print("look very well")
... elif x == 'lion':
...     print("How are they?")
... else:
...     print('Run for your dear life!')
...
Run for your dear life!
```

这个多行声明从 `if` 行延伸到 `else` 下嵌套的块。当它运行时，Python 执行第一个为真的测试下嵌套的声明，如果所有测试都为假，则执行 `else` 部分（在本例中，它们都是假）。实际上，`elif` 和 `else` 部分都可以省略，并且每个部分中可以嵌套多条语句。请注意，单词 `if`、`elif` 和 `else` 通过垂直对齐、具有相同的缩进而相关联。如果你用过 C 或 Pascal 等语言，你可能有兴趣知道 Python 中没有 `switch` 或 `case` 语句根据变量的值选择活动。相反，你通常将多路分支编写为一系列 `if`/`elif` 测试，如前面的示例所示，有时通过字典或查找列表。由于字典和列表可以在运行时动态构建，它们有时比脚本中硬编码的 `if` 逻辑更灵活：

```
>>> decision = 'swing'
>>> print({'leave': 5.75,      # 基于字典的 'switch'
...        'swing': 2.00,      # 使用 has_key 或 get 获取默认值
...        'fish': 1.99,
...        'goat': 1.20}[choice])
2.00
```

尽管第一次看到这可能需要几分钟才能领会，但这个字典就是一个多路分支——根据键 `decision` 索引到一组值中的一个，很像 C 语言中的 `switch`。一个功能几乎相等但更冗长的 Python `if` 声明可能如下所示：

```
>>> if decision == 'leave':      # 等效的 if 声明
...     print(5.75)

...     print(2.00)
... elif decision == 'fish':
...     print(1.20)

...     print(3.00)

...     print('unpleasant decision')

1.99
```

## 第 9 章 – Python 中的循环

### While 循环

Python 的 `while` 语句是该语言中最通用的迭代结构。简单来说，只要顶部的测试表达式持续计算为真值，它就会反复执行一块（通常缩进的）语句。之所以称为“循环”，是因为控制流不断回到语句的开头，直到测试变为假。一旦测试变为假，控制流就会传递给 `while` 代码块后面的语句。最终效果是：只要顶部的测试为真，循环体就会反复执行。如果测试一开始就是假，循环体永远不会运行，`while` 语句会被跳过。

#### 通用格式

在其最复杂的形式中，`while` 语句由一个包含测试表达式的头部行、一个包含一条或多条通常缩进语句的循环体，以及一个可选的 `else` 部分组成，该部分在控制流离开循环且未遇到 `break` 语句时执行。Python 会持续计算顶部的测试表达式，并执行嵌套在循环体中的语句，直到测试返回假值：

```
while test:          # 循环测试
    statements       # 循环体
else:                # 可选的 else
    statements       # 如果未通过 break 退出循环则运行
```

#### 示例

为了演示，让我们看几个基本的 `while` 循环实际运行的例子。

第一个例子由一个嵌套在 `while` 循环中的 `print` 语句组成，它会永远打印一条消息。回想一下，`True` 只是整数 `1` 的一个定制版本，始终代表布尔真值；由于测试永远为真，Python 会一直执行循环体，直到你强制停止它的执行。这种行为通常被称为**无限循环**——它并非真正永恒，但你可能需要按 `Ctrl-C` 组合键来强制终止它：

```
>>> while True:
...     print('Type Ctrl-C to stop me!')
```

```
>>> x = 'spam'
>>> while x:              # 当 x 不为空时
...     print(x, end=' ')
...
spam pam am m
```

请注意此处使用的 `end=' '` 关键字参数，它将所有输出放在一行上并用空格分隔。这可能会让你的输入提示符在输出结束时处于奇怪的状态；按 `Enter` 键可重置。Python 2.X 读者：同样请记住，要在这些打印语句中使用尾随逗号代替 `end`。

```

...     a += 1
```

最后，请注意 Python 没有某些语言所谓的“do until”循环语句。不过，我们可以通过在循环体底部放置测试和 `break` 来模拟一个，这样循环体至少会运行一次：

```
while True:
    ...循环体...
    if exitTest(): break
```

要完全理解此结构的工作原理，我们需要进入下一节并了解 `break` 语句。

### break、continue、pass 和循环 else

现在我们已经看到了一些 Python 循环的实际运行，是时候研究两个仅在嵌套在循环内时才有用途的简单语句了——`break` 和 `continue` 语句。在研究这些特性时，我们也将在这里学习循环 `else` 子句，因为它与 `break` 紧密相关，以及 Python 的空占位符语句 `pass`（它本身不专门与循环相关，但属于简单单词语句的一般范畴）。

在 Python 中：

*   `break`：跳出最近的外层循环（越过整个循环语句）。
*   `continue`：跳到最近的外层循环的顶部（即循环的头部行）。
*   `pass`：什么都不做：它是一个空语句占位符。
*   循环 `else` 代码块：仅当循环正常退出时运行（即未遇到 `break`）。

#### 通用循环格式

考虑到 `break` 和 `continue` 语句，`while` 循环的通用格式如下所示：

```
while test:
    statements
    if test: break        # 立即退出循环，跳过 else（如果存在）
    if test: continue     # 立即跳到循环顶部，进行测试
else:
    statements            # 如果我们没有遇到 'break' 则运行
```

`break` 和 `continue` 语句可以出现在 `while`（或 `for`）循环体的任何位置，但通常嵌套在 `if` 测试中进一步编写，以响应某些条件采取行动。让我们看几个简单的例子，了解这些语句在实践中是如何结合在一起的。

#### Pass

首先：`pass` 语句是一个无操作占位符，当语法需要一条语句但你没有什么有用的可说时使用。它常用于为复合语句编写空主体。例如，如果你想编写一个每次循环什么都不做的无限循环，可以用 `pass` 来做：

```
while True: pass
```

由于主体只是一条空语句，Python 会卡在这个循环中。`pass` 对语句的作用大致相当于 `None` 对对象的作用——一个显式的“无”。请注意，这里 `while` 循环的主体与头部在同一行，位于冒号之后；与 `if` 语句一样，这仅在主体不是复合语句时有效。这个示例什么都不做，永远持续下去。这可能不是有史以来最有用的 Python 程序（除非你想在寒冷的冬天给笔记本电脑加热！）；说实话，在本书的这个早期阶段，我想不出更好的 `pass` 例子。稍后我们将看到 `pass` 在其他地方发挥作用——例如，忽略 `try` 语句捕获的异常，以及定义带有属性的空类对象，这些属性的作用类似于其他语言中的“结构体”和“记录”。`pass` 有时也被编写为“稍后填入”，以临时存根函数体：

```
def func1(): pass  # 稍后在此添加真实代码
def func2(): pass
```

我们不能留空主体，否则会得到语法错误，所以我们写 `pass`。

**版本差异说明：** Python 3.X（但不是 2.X）允许编码为 `...`（字面上是三个连续的点）的省略号出现在语句可以出现的任何地方。由于省略号本身不执行任何操作，这可以作为 `pass` 语句的替代品，特别是对于稍后要填入的代码——一种 Python 的“TBD”（待定）：

```
def func1(): ...  # pass 的替代方案
def func2(): ...
func1()           # 调用时什么都不做
```

省略号也可以出现在语句头部的同一行，如果不需要特定类型，可能用于初始化变量名：

```
def func1(): ...  # 在同一行也有效
def func2(): ...
>>> X = ...       # None 的替代方案
>>> X
Ellipsis
```

此功能是 Python 3.X 中新增的——远远超出了 `...` 在切片扩展中的原始用途——因此仍有待观察它是否会普及到足以在这些角色中挑战 `pass` 和 `None`。

#### Continue

`continue` 语句导致立即跳转到循环顶部。它有时可以让你避免语句嵌套。下一个示例使用 `continue` 跳过奇数。这段代码打印每一个小于 10 且大于或等于 0 的偶数。记住，`0` 代表假，`%` 是取模（求余）运算符，所以这个循环向下计数到 0，跳过不是 2 的倍数的数字——它打印 `8 6 4 2 0`：

```
x = 10
while x:
    x = x - 1
    if x % 2 != 0: continue  # 奇数？- 跳过打印
    print(x, end=' ')
```



由于 `continue` 接下来跳到循环顶部，你不必将 `print` 语句嵌套在 `if` 测试中；只有在 `continue` 未运行时才会到达 `print`。如果这听起来像其他语言中的“goto”，那应该是。Python 没有“goto”语句，但既然 `continue` 让你能在程序中跳来跳去，你可能听过的许多关于“goto”的可读性和可维护性警告也适用于此。`continue` 可能应该谨慎使用，尤其是当你刚开始学习 Python 时。例如，如果将 `print` 嵌套在 `if` 下，最后一个示例可能会更清晰：

```
x = 10
while x:
    x = x - 1
    if x % 2 == 0:        # 偶数？- 打印
        print(x, end=' ')
```

### Break

`break` 语句导致立即退出循环。由于如果到达 `break`，循环内后面的代码不会执行，你有时也可以通过使用 `break` 来避免嵌套。例如，这里有一个简单的交互式循环，它使用 `input` 输入数据，并在用户在姓名提示符处输入 "stop" 时退出：

```
>>> while True:
...     name = input('Enter name:')
...     if name == 'stop': break
...     age = input('Enter age: ')
...     print('Hello', name, '=>', int(age) ** 2)
...
Enter name: bob
Enter age: 40
Hello bob => 1600
Enter name: sue
Enter age: 30
Hello sue => 900
Enter name: stop
```

请注意，这段代码在将年龄输入平方之前，使用 `int` 将其转换为整数；正如你所记得的，这是必要的，因为 `input` 将用户输入作为字符串返回。你会注意到 `input` 在文件结束时也会引发异常（例如，如果用户在 Windows 上输入 `Ctrl-Z` 或在 Unix 上输入 `Ctrl-D`）；如果这很重要，请用 `try` 语句包装输入。

### 循环 Else

当与循环 `else` 子句结合使用时，`break` 语句通常可以消除其他语言中使用的搜索状态标志的需求。例如，以下代码通过搜索大于 1 的因子来确定正整数 `y` 是否为质数：

```
x = y // 2
while x > 1:
    if y % x == 0:        # 余数
        print(y, 'has factor', x)
        break             # 跳过 else
    x -= 1
else:                     # 正常退出
    print(y, 'is prime')
```

它不是设置一个标志在循环退出时测试，而是在找到因子的地方插入 `break`。这样，循环 `else` 子句可以假设只有在未找到因子时才会执行；如果你没有遇到 `break`，该数字就是质数。跟踪这段代码看看它是如何工作的。

如果循环体从未执行，循环 `else` 子句也会运行，因为在这种情况下你也不会运行 `break`；在 `while` 循环中，如果头部的测试一开始就是假，就会发生这种情况。因此，在前面的示例中，如果 `x` 最初小于或等于 1（例如，如果 `y` 是 2），你仍然会得到 "is prime" 消息。

此示例确定质数，但只是非正式地。根据严格的数学定义，小于 2 的数不被视为质数。为了完全精确，此代码对于负数也会失败，对于没有小数位的浮点数则会成功。另请注意，由于 `/` 迁移到了“真除法”（我们需要整数除法来截断余数，而不是保留它们！），其代码在 Python 3.X 中必须使用 `//` 而不是 `/`。如果你想尝试这段代码，请务必查看将它包装在函数中以供重用的练习。

## 第 10 章 – Python 编程中的用户自定义函数

## 第 11 章 – Python 中的类与面向对象编程

在本章中，你将了解如何在 Python 中进行“分类”，即对项目进行分组。这至关重要，因为你需要将本应列出的单词进行分组。Python 是一门**面向对象编程语言**，这意味着它操作并处理称为**对象**的数据结构。对象可以是 Python 中可命名的任何事物——数字、函数、浮点数、字符串、类、方法等。这些对象在 Python 中具有同等地位。它们可以用在任何需要对象的地方。你可以将它们赋值给变量、列表或字典。它们也可以作为参数传递。每个 Python 对象都是一个类。类本质上是一种用于组织、管理和创建具有相似属性和方法的对象的方式。在本书中，Python 中的函数远不止是给编译器看的代码生成规范——Python 函数是彻头彻尾的对象，存储在各自独立的内存块中。因此，它们可以在程序中自由传递并间接调用。它们还支持与调用关系不大的操作——属性存储和注释。既然 Python 函数是对象，你就可以编写常规生成它们的程序。函数对象可以赋值给不同的名称、传递给其他函数、嵌入数据结构、从一个函数返回到另一个函数，等等，就像它们是简单的数字或字符串一样。函数对象还碰巧支持一项特殊任务：可以通过在函数表达式后的括号中列出参数来调用它们。即便如此，函数仍与其他对象属于同一大类。这通常被称为**一等对象模型**；它在 Python 中无处不在，也是函数式编程的重要组成部分。我们将在本章和下一章更全面地探讨这种编程模式；因为其主题建立在应用函数的理念之上，所以函数必须被视为数据。我们在前面的示例中已经看到了函数的一些常规用例，但快速回顾一下可以强化对象模型。

例如，`def` 语句中使用的名称实际上没有什么特别之处：它只是当前作用域中赋值的一个变量，就好像它出现在了 `=` 号的左侧。`def` 运行后，函数名只是对一个对象的引用——你可以随意将该对象重新赋值给不同的名称，并通过任何引用来调用它：

```
>>> def echo(message): # 名称 echo 赋值给函数对象
...     print(message)
>>> echo('Direct call') # 通过原始名称调用对象
Direct call
>>> x = echo # 现在 x 也引用该函数
>>> x('Indirect call!') # 通过名称加 () 调用对象
Indirect call!
```

由于参数是通过赋值对象来传递的，将函数作为参数传递给其他函数同样简单。“被调用者”随后只需在括号中加上参数即可调用传入的函数：

```
>>> def indirect(func, arg):
...     func(arg) # 通过加上 () 调用传入的对象
>>> indirect(echo, 'Argument call!') # 将函数传递给另一个函数
Argument call!
```

你甚至可以将函数对象塞进数据结构中，就像它们是整数或字符串一样。例如，以下代码将函数嵌入元组列表中两次，作为一种活动表。由于 Python 的复合类型（如这些）可以包含任何类型的对象，这里也没有特殊情况：

```
>>> schedule = [ (echo, 'Spam!'), (echo, 'Ham!') ]
```

### `__init__()` 方法

### 继承

**继承**是一种 Python 机制，允许一个类采用另一个类的方法和属性。此功能使用户能够创建越来越复杂的类，这些类从其父类或基类继承方法或变量，并使编程更加高效。以下是定义一个继承父类所有变量和函数的类的语法：

### 编写函数

尽管没有正式规定，但我们之前已经有效地使用了一些函数。例如，要创建文件对象，我们调用了内置的 `open()` 函数；类似地，我们使用内置的 `len()` 函数来请求集合对象中的项目数量。在本部分中，我们将探讨如何在 Python 中编写新函数。我们编写的函数表现方式与我们刚才看到的内置函数相同：它们在语句中被调用，被传递值，并返回结果。然而，编写新函数需要使用一些尚未介绍的额外概念。此外，函数在 Python 中的行为与在 C 等编译语言中截然不同。以下是驱动 Python 函数的基本概念的简短介绍，所有这些我们将在本书的这一部分中探讨：

#### `def` 是可执行代码

Python 函数使用另一种语句 `def` 来编写。与 C 等编译语言中的函数不同，`def` 是一条可执行语句——您的函数直到 Python 到达并运行 `def` 时才存在。事实上，将 `def` 语句嵌套在 `if` 语句、`while` 循环甚至其他 `def` 中是合法的（甚至有时很有用）。在典型操作中，`def` 语句编写在模块文件中，并且通常在模块文件首次被导入时运行以生成函数。

#### `def` 创建一个对象并将其赋值给一个名称

当 Python 到达并运行一条 `def` 语句时，它会创建一个新的函数对象并将其赋值给函数的名称。与所有赋值一样，函数名称变成了对函数对象的引用。函数名称没有什么神奇之处——正如您将看到的，函数对象可以被赋值给不同的名称、存储在列表中等。函数对象也可以附加任意用户定义的属性来记录信息。

*   **`lambda`** 创建一个对象但将其作为结果返回。函数也可以用 `lambda` 语句创建，这是一种允许我们在 `def` 语句在语法上无法工作的地方内联函数定义的特性。

*   **`return`** 将结果对象发送回调用者。当函数被调用时，调用者会停止，直到函数完成其工作并将控制权返回给调用者。计算值的函数通过 `return` 语句将其发送回调用者；返回的值成为函数调用的结果。不带值的 `return` 只是返回给调用者（并发回 `None`，即默认结果）。

*   **`yield`** 将结果对象发送回调用者，但会记住最后已知的执行点。被称为生成器的函数也可以使用 `yield` 语句发回一个值并挂起其状态，以便稍后恢复，从而随时间产生一系列结果。这是本书后面将涵盖的另一个高级主题。

*   **`global`** 声明要赋值的模块级变量。默认情况下，函数中赋值的所有名称都局限于该函数，并且仅在函数运行时存在。要在外层模块中赋值一个名称，函数必须在 `global` 语句中声明它。更一般地说，名称总是在作用域中查找——变量存储的地方——而赋值将名称绑定到作用域。

*   **`nonlocal`** 声明要赋值的外层函数变量。同样，Python 3.X 中新增的 `nonlocal` 语句允许函数赋值一个存在于语法上外层 `def` 语句作用域中的名称。这使得外层函数可以作为保存状态的地方——在函数调用之间记住的数据——而无需使用共享的全局名称。

*   **参数通过赋值（对象引用）传递。** 在 Python 中，参数通过赋值传递给函数（正如我们所学，这意味着通过对象引用）。正如您将看到的，在 Python 的模型中，调用者和函数通过引用共享对象，但不存在名称别名。在函数内部更改参数名称不会影响调用者中对应的名称，但更改传入的可变对象可以改变调用者共享的对象，并作为函数结果。

*   **除非另有说明，参数按位置传递。** 您在函数调用中传递的值自然地从左到右与函数定义中的参数名称匹配。为了灵活性，函数调用也可以使用 `name=value` 关键字语法按名称传递参数，并使用 `*pargs` 和 `**kargs` 语法解包并传递任意多个参数。函数定义使用类似的两种结构来指定参数默认值和收集接收到的任意多个参数。

*   **参数、返回值和变量无需声明。** 与 Python 中的所有事物一样，函数没有类型约束。事实上，函数的任何方面都不需要提前声明：您可以传入任何类型的参数，返回任何类型的对象等。作为一个结果，单个函数通常可以应用于各种对象类型——任何拥有兼容接口（方法和表达式）的对象都可以，无论其具体类型如何。

`def` 语句创建一个函数对象并将其赋值给一个名称。其通用格式如下：

与所有复合 Python 语句一样，`def` 由一个标题行后跟一个语句块组成，通常缩进（或冒号后的简单语句）。语句块成为函数的主体——即每次稍后调用函数时 Python 执行的代码。`def` 标题行指定一个函数名，该名称被赋值为函数对象，以及一个包含零个或多个参数（有时称为形参）的列表。

## 第 13 章 – Python 的参数

正如我们所了解的，名称在代码中定义的位置决定了其含义的很大一部分。本章将继续讲述函数的故事，通过探讨 Python 参数传递的概念——即对象如何作为输入发送给函数。正如我们将看到的，参数（也称为形参）被赋值给函数中的名称，但它们与对象引用的关系更大，而非变量作用域。我们还将发现 Python 提供了额外的工具，例如关键字参数、默认值、可变参数收集器和解包器，这些工具允许在向函数传递参数时具有极大的灵活性，我们将在示例中演示它们的用法。在你内化这些概念后，你需要理解参数传递的基础知识。

### 参数传递基础

在本书的这一部分之前，我提到过参数是通过赋值传递的。这有几个对新手并不总是显而易见的含义，我将在本节中详细阐述。以下是向函数传递参数的关键点概述：

*   **参数通过自动将对象赋值给局部变量名来传递。** 函数参数——调用者发送的对象引用——只是 Python 赋值机制工作的另一个实例。由于引用是作为指针实现的，因此所有参数实际上都是按指针传递的。作为参数传递的对象永远不会被自动复制。

*   **在函数内部给参数名赋值不会影响调用者。** 函数头部的参数名在函数运行时成为新的局部名称，其作用域限于该函数。函数参数名与调用者作用域中的变量名之间没有关联。

*   **在函数中更改可变对象参数可能会影响调用者。** 另一方面，由于参数本质上是赋值给传入的对象，函数可以就地修改传入的可变对象，其结果可能会影响调用者。可变参数可以作为函数的输入和输出。

有关引用的更多细节，请参见第 6 章；我们在那里学到的所有内容也适用于函数参数，只是赋值给参数名是自动且隐式的。Python 的按赋值传递方案与 C++ 的引用参数选项并不完全相同，但它在实践中基本类似于 C 语言（及其他语言）的参数传递模型：

*   **不可变参数实际上是“按值传递”**。诸如数字和字符串之类的对象是通过对象引用而非复制来传递的，但由于你无论如何都无法就地更改不可变对象，因此其效果很像创建了一个副本。

*   **可变参数实际上是“按指针传递”**。诸如列表和字典之类的对象也是通过对象引用传递的，这类似于 C 语言将数组作为指针传递的方式——可变对象可以在函数中就地修改，很像 C 数组。

当然，如果你从未使用过 C，Python 的参数传递模式看起来会更简单——它仅涉及将对象赋值给名称，并且无论对象是否可变，其工作方式都相同。

### 参数与共享引用

为了演示参数传递属性的实际效果，请考虑以下代码：

```python
>>> def f(a):          # a 被赋值为（引用）传入的对象
...     a = 33         # 仅改变局部变量 a
...
>>> b = 404
>>> f(b)               # a 和 b 最初都引用同一个对象 404
>>> print(b)           # b 未被改变
404
```

在该模型中，当使用 `f(b)` 调用函数时，变量 `a` 被赋值为对象 `404`，但其生命周期仅存在于被调用函数内部。在函数内部更改 `a` 对函数被调用的位置没有影响；它只是将局部变量 `a` 重置为一个完全不同的对象。这就是所谓的无名称关联——在函数内部给参数名赋值（例如 `a=33`）不会神奇地改变调用者作用域中的变量 `b`。参数名最初可能共享传入的对象（它们本质上是指向这些对象的指针），但仅在函数首次被调用时。一旦参数名被重新赋值，这种关联就结束了。

这仅适用于对参数名本身的赋值情况。每当参数作为列表和字典等可变对象传递时，我们还必须意识到，对这些对象的就地修改可能在函数退出后依然存在，从而影响调用者。以下是一个展示此行为的示例：

```python
>>> def changer(a, b):  # 参数被赋值为对象的引用
...     a = 2           # 仅改变局部名称的值
...     b[0] = 'leave'  # 就地修改共享对象
...
>>> X = 1
>>> L = [1, 2]          # 调用者：
>>> changer(X, L)       # 传入不可变和可变对象
>>> X, L                # X 未改变，L 变了！
(1, ['leave', 2])
```

在这段代码中，`changer` 函数给参数本身赋值，并给参数 `b` 引用的对象的一个分量赋值。这两个函数内部的赋值在语法上只有细微差别，但结果却截然不同：

*   因为 `a` 将成为函数作用域中的局部变量名，第一个赋值对调用者没有影响——它只是将局部变量 `a` 重置为引用一个完全不同的对象，并不会改变调用者作用域中名称 `X` 的绑定。这与前一个示例相同。

*   参数 `b` 也是一个局部变量名，但它被传入了一个可变对象（调用者作用域中 `L` 引用的列表）。由于第二个赋值是一个就地对象修改，函数中对 `b[0]` 的赋值结果会影响函数返回后 `L` 的值。实际上，`changer` 中的第二个赋值语句并没有改变 `b`——它改变了 `b` 当前引用的对象的一部分。这种就地修改仅因为被修改的对象比函数调用存活得更久而影响了调用者。名称 `L` 也没有改变——它仍然引用同一个对象——但由于它引用的值在函数内部被修改了，所以看起来 `L` 在调用后发生了变化。本质上，列表名称 `L` 既作为输入也作为输出传递给了函数。

如果这个示例仍然令人困惑，了解自动赋值传入参数的效果等同于运行一系列简单的赋值语句可能会有所帮助。就第一个参数而言，赋值对调用者没有影响：

```python
>>> X = 1
>>> a = X           # 它们共享同一个对象
```


由于参数是通过赋值传递的，函数中的参数名可能与调用者作用域中的变量共享对象。因此，函数中对可变参数的就地修改可能会影响调用者。在这里，函数中的 `a` 和 `b` 在函数首次被调用时最初引用由变量 `X` 和 `L` 引用的对象。通过变量 `b` 修改列表导致 `L` 在调用返回后看起来不同。如果你回顾一下我们关于共享可变对象的讨论，你会认出正在起作用的现象：就地修改可变对象可能会影响对该对象的其他引用。在这里，其效果是使其中一个参数既像函数的输入又像输出。

## 第 14 章 – Python 中的模块及其应用

本部分开始自顶向下地探讨 Python 模块——最高层级的程序组织单元，它将程序代码和数据打包以供复用，并提供独立的命名空间，从而限制项目间的变量名冲突。具体而言，模块通常对应 Python 程序文件。每个文件都是一个模块，模块通过导入其他模块来使用它们定义的名称。模块也可能对应用外部语言（如 C、Java 或 C#）编写的扩展，甚至包导入中的目录。

模块通过两条语句和一个重要函数进行处理：

*   `import`：允许客户端（导入者）整体获取一个模块。
*   `from`：允许客户端从模块中获取特定的名称。
*   `imp.reload()`（2.X 版本中的 `reload()`）：提供了一种在不停止程序的情况下重新加载模块代码的方法。

我们一直在使用它们。此处的目标是扩展你已熟悉的核心模块概念，并进一步探索更高级的模块用法。本章首先回顾模块基础，并概述模块在整体程序结构中的作用。在后续章节中，我们将深入探讨理论背后的编码细节。在此过程中，我们将充实此前省略的模块细节——你将了解重新加载、`__name__` 和 `__all__` 属性、包导入、相对导入语法、3.3 命名空间包等内容。由于模块和类本质上只是“光荣的”命名空间，我们也将在此正式阐述命名空间概念。

### 为什么要使用模块？

简单来说，模块通过作为称为命名空间的独立变量包，提供了一种将组件组织成系统的简便方式。模块文件顶层定义的所有名称都会成为导入模块对象的属性。正如我们在本书上一部分所见，导入提供了对模块全局作用域中名称的访问。也就是说，模块文件的全局作用域在被导入时会成为模块对象的属性命名空间。归根结底，Python 的模块允许我们将单个文件链接成一个更大的程序系统。

更具体地说，模块至少扮演三种角色：

#### 代码复用

模块让你能永久地将代码保存在文件中。与你在 Python 交互提示符下输入的代码不同，后者在你退出 Python 时就会消失，模块文件中的代码是持久的——它可以根据需要重新加载并重复运行任意次。同样重要的是，模块是定义名称（称为属性）的地方，这些名称可被多个外部客户端引用。如果使用得当，这些特性支持模块化的程序结构，将功能分组为可复用的单元。

#### 系统命名空间划分

模块也是 Python 中最高层级的程序组织单元。虽然它们本质上只是名称的包，但这些包也是独立的——除非你导入另一个文件，否则永远无法看到其中的名称。这很像函数的局部作用域，避免了程序间的名称冲突。事实上，你无法避免这一特性——所有事物都“生活”在模块中；你运行的代码和创建的对象始终隐式地包含在模块中。因此，模块是分组系统组件的天然工具。

#### 实现共享服务或数据

从操作角度来看，模块对于实现跨系统共享、因此只需单一副本的组件也很有用。例如，如果你需要提供一个被多个函数或文件使用的全局对象，可以将其编写在一个模块中，然后由多个客户端导入。

无论如何，以上是理论层面的阐述——要真正理解模块在 Python 系统中的作用，我们需要暂时岔开话题，探讨 Python 程序的总体结构。

### Python 程序架构

到目前为止，在本书中，我对 Python 程序的描述稍微掩盖了一些复杂性。在实践中，程序通常不止涉及一个文件。除最简单的脚本外，你的程序将采用多文件系统的形式——正如前一章的代码计时项目所示。即使你自己编写单个文件也能应付，你也很可能会发现自己在使用别人已经编写好的外部文件。

本节介绍 Python 程序的总体架构——即如何将程序拆分为源文件集合（即模块）并将各部分链接成一个整体。正如我们将看到的，Python 促进了一种模块化的程序结构，以自然且近乎自动的方式将功能分组为逻辑上可复用的单元。在此过程中，我们还将探讨 Python 模块、导入和对象属性的核心概念。

### 如何构建程序结构

从基础层面来看，Python 程序由包含 Python 语句的文本文件组成，包含一个主顶层文件，以及零个或多个称为模块的补充文件。其工作原理如下：

*   **顶层**文件（又称脚本）包含程序的主控制流——这是启动应用程序时运行的文件。
*   **模块**文件是工具库，用于收集顶层文件使用的组件，并可能在其他地方使用。

顶层文件使用模块文件中定义的工具，模块则使用其他模块中定义的工具。虽然它们也是代码文件，但模块文件通常在直接运行时不执行任何操作；相反，它们定义供其他文件使用的工具。

### 导入与属性

让我们具体化一下。以由三个文件组成的 Python 程序结构为例：`a.py`、`b.py` 和 `c.py`。

文件 `a.py` 被选为顶层文件；它将是一个简单的语句脚本文件，启动时从上到下执行。文件 `b.py` 和 `c.py` 是模块；它们也是简单的语句脚本文件，但通常不直接启动。正如前面所述，模块通常由希望使用模块定义工具的其他文件导入。

例如，假设示例中的文件 `b.py` 定义了一个名为 `spam` 的函数供外部使用。正如我们在第四部分学习函数时所知，`b.py` 将包含一个 Python `def` 语句来创建该函数，稍后你可以通过在函数名后的括号中传递零个或多个参数来运行它：

```python
def spam(text): # 文件 b.py
    print(text, 'spam')
```

现在，假设 `a.py` 想要使用 `spam`。为此，它可能包含如下 Python 语句：

```python
import b # 文件 a.py
b.spam('gumby') # 打印 "gumby spam"
```

第一条语句是 Python `import` 语句，它使文件 `a.py` 能够访问文件 `b.py` 中顶层代码定义的所有内容。代码 `import b` 实质上意味着：加载文件 `b.py`（除非已加载），并通过名称 `b` 让我访问其所有属性。

为实现此类目标，`import`（以及稍后你将看到的 `from`）语句按需执行并加载其他文件。更正式地说，在 Python 中，跨文件模块链接直到此类 `import` 语句在运行时执行时才会解析；其净效果是将模块名称（如 `b` 这样的简单变量）赋值给已加载的模块对象。

事实上，`import` 语句中使用的模块名称有两个用途：它标识要加载的外部文件，但也会成为赋值给已加载模块的变量。同样，模块定义的对象也是在导入执行时于运行时创建的：`import` 实际上会逐条运行目标文件中的语句以创建其内容。在此过程中，文件顶层赋值的每个名称都会成为模块的属性，供导入者访问。

例如，`a.py` 中的第二条语句使用对象属性表示法调用模块 `b` 中定义的函数 `spam`——该函数是在导入期间运行其 `def` 语句时创建的。代码 `b.spam` 意味着：获取存在于对象 `b` 内部的名称 `spam` 的值。在我们的示例中，这恰好是一个可调用函数，因此我们在括号中传递一个字符串（`'gumby'`）。

如果你实际创建这些文件，保存它们，并运行 `a.py`，将打印出 "gumby spam"。正如我们所见，对象属性表示法贯穿于 Python 代码中——大多数对象都有有用的属性，通过 `.` 运算符获取。有些引用可调用对象（如函数）以采取行动（例如薪资 PC）。Python 程序架构。程序是模块的集合。它有一个顶层脚本文件（运行以启动程序），和许多模块文件（导入的工具库）。脚本和模块都是包含 Python 语句的文本文件，但模块中的语句通常只是创建供稍后使用的对象。Python 标准库提供了一组预编码模块。基本数据值代表更静态的对象和属性（例如一个人的名字）。

导入的概念在 Python 中也完全无处不在。任何文件都可以从任何其他文件导入工具。例如，文件 `a.py` 可能导入 `b.py` 以调用其函数，但 `b.py` 也可能导入 `c.py` 以使用那里定义的各种工具。导入链可以按你喜欢的深度嵌套：在本例中，模块 `a` 可以导入 `b`，后者可以导入 `c` 及其他模块。

总而言之，你已经了解了如何使用和复用 Python 代码。正如所解释的，这工作得很好。下一章将解答你关于 Python 中有多少包及其功能的好奇心。让我们进入下一章！

## 第 15 章 —— Python 中的包及其应用

到目前为止，当我们导入模块时，实际上是在堆叠文档。这说明了普通的模块用法，这很可能是你在 Python 职业生涯早期编写的大多数导入语句所使用的系统。然而，模块导入的故事比我迄今为止所推断的要丰富一些。除了模块名之外，导入语句还可以指定一个目录路径。Python 代码的目录被称为包，因此这种导入被称为包导入。因此，包导入将你电脑上的一个目录转变为另一个 Python 命名空间，其属性对应该目录所包含的子目录和模块文件。这是一个在一定程度上高级的特性，但它提供的层次结构对于组织大型系统中的文件非常方便，并且通常能简化模块搜索路径设置。正如我们将看到的，当同名的不同程序文件安装在单台机器上时，包导入有时也是解决导入歧义所必需的。由于仅在包中编码很重要，我们也将在此介绍 Python 的相对导入模型和语法。正如我们将看到的，该模型在 3.X 中改变了搜索路径，并在 2.X 和 3.X 中都扩展了用于包内导入的 `from` 语句。该模型可以使此类包内导入越来越明确和简洁，但伴随着一些可能影响你项目的权衡。最后，对于使用 Python 3.3 及更高版本的“读者”，其新的命名空间包模型——允许包跨越多个目录且无需初始化文件——也将在此介绍。这种新式包模型是可选的，可以与最初的（现在称为“常规”）包模型配合使用，但它推翻了原模型的一些基本思想和规则。因此，我们将首先为所有“读者”探讨常规包，最后将命名空间包作为一个可选主题介绍。

### 包导入基础

从基础层面来看，包导入很清晰——在你一直在导入语句中命名简单文件的地方，你可以改为列出一个由句点分隔的名称路径：

```
import dir1.dir2.mod
```

`from` 语句同理：

```
from dir1.dir2.mod import x
```

这些声明中的“点分隔”路径预期对应于你电脑上目录链中的一条路径，指向文件 `mod.py`（或类似文件；扩展名可能不同）。也就是说，上述说明表明你的机器上有一个目录 `dir1`，它有一个子目录 `dir2`，其中包含模块文件 `mod.py`（或类似文件）。此外，这些导入暗示 `dir1` 位于某个容器目录 `dir0` 内，而 `dir0` 是常规 Python 模块搜索路径的一部分。换句话说，这两条导入语句暗示的目录结构看起来类似于这样（显示为 Windows 反斜杠分隔符）：

```
dir0\dir1\dir2\mod.py
### 或 mod.pyc, mod.so 等。
```

除非容器目录 `dir0` 是顶层文件的主目录，否则必须将其添加到你的模块搜索路径中，这就像 `dir1` 是一个简单的模块文件一样。更正式地说，包导入路径中最左边的部分仍然是相对于 `sys.path` 模块中包含的目录的。然而，从那时起，你脚本中的导入语句显式地给出了通向包中模块的目录路径。

### 包与搜索路径设置

如果你使用此元素，请记住，导入语句中的目录路径只能是由句点分隔的因素。你不能在导入语句中使用任何特定于平台的路径语法，例如 `C:\dir1`、`My Documents.dir2` 或 `../dir1` —— 这些在语法上不起作用。相反，请在模块搜索路径设置中使用任何此类特定于平台的语法来命名容器目录。例如，在前面的示例中，`dir0` —— 你添加到模块搜索路径中的目录名 —— 可以是一个任意长且特定于平台的目录路径，通向 `dir1`。你不能使用如下无效声明：

```
import C:\mycode\dir1\dir2\mod  # 错误：非法句法
```

但是，你可以将 `C:\mycode` 添加到 `PYTHONPATH` 变量或 `.pth` 文件中，并在脚本中声明：

```
import dir1.dir2.mod
```

基本上，模块搜索路上的条目提供特定于平台的目录路径前缀，通向 `import` 和 `from` 声明中最左边的名称。这些导入声明本身以平台中立的方式提供目录路径的其余部分。1 就基本文件导入而言，如果容器目录 `dir0` 已经在模块搜索路径中，则无需添加；如果它是顶层文件的主目录、你正在逻辑上工作的目录、标准库目录或 site-packages 第三方安装根目录，则它已经在其中。无论如何，你的模块搜索路径必须包含代码中包导入声明最左边部分所在的所有目录。

### 包的 `__init__.py` 文件

如果你使用包导入，还有一条限制必须遵守：至少直到 Python 3.3 之前，包导入语句路径中命名的每个目录都必须包含一个名为 `__init__.py` 的文件，否则你的包导入将失败。也就是说，在我们一直使用的示例中，`dir1` 和 `dir2` 都必须包含一个名为 `__init__.py` 的文件；容器目录 `dir0` 不需要此类文件，因为它未在 `import` 语句本身中列出。更正式地说，对于如下目录结构：

```
dir0\dir1\dir2\mod.py
```

以及如下形式的 `import` 语句：

```
import dir1.dir2.mod
```

适用以下原则：

*   `dir1` 和 `dir2` 都必须包含 `__init__.py` 文件。
*   `dir0`，即容器，不需要 `__init__.py` 文件；如果存在，该文件基本上会被忽略。
*   `dir0`，而不是 `dir0\dir1`，必须列在模块搜索路径 `sys.path` 上。

为了满足前两条准则，包创建者必须创建我们将在此探讨的类型的文件。为了满足最后一条，`dir0` 必须是自动路径部分（主目录、库或 site-packages 目录），或在 `PYTHONPATH` 或 `.pth` 文件设置或手动 `sys.path` 更改中给出。

> 1. 选择点分隔路径语法部分是为了平台中立性，但也因为导入声明中的路径成为真正的嵌套对象路径。这种语法也意味着，如果你忘记在导入声明中省略 `.py`，可能会得到奇怪的错误消息。例如，`import mod.py` 被认为是一个目录路径导入 —— 它加载 `mod.py`，然后尝试加载 `mod\py.py`，最后发出一个可能令人困惑的“No module named py”错误消息。截至 Python 3.3，此错误消息已改进为“No module named 'm.py'; m isn't a package.”

其净效果是，本示例的目录结构应如下所示，缩进表示目录嵌套：

```
dir0\          # 模块搜索路上的容器
dir1\
    __init__.py
dir2\
    __init__.py
mod.py
```

`__init__.py` 文件可以包含 Python 代码，就像预期的模块文件一样。它们的名称之所以特殊，是因为它们的代码在 Python 程序第一次导入目录时会自动运行，因此主要作为执行包所需初始化步骤的钩子。这些文件也可以完全为空，此外，有时还有额外的作用 —— 正如下一节所述。正如我们将在本章末尾看到的，包必须拥有名为 `__init__.py` 的文件这一要求在 Python 3.3 中已被取消。在该版本及更高版本中，没有此类文件的模块目录可以作为单目录命名空间包导入，其工作方式相同，但不运行初始化时代码文件。然而在 Python 3.3 之前，以及在所有 Python 2.X 中，包仍然需要 `__init__.py` 文件。正如前面所述，在 3.3 及更高版本中，如果使用这些文件，它们还提供初始化优势。

#### 包初始化文件的角色

更详细地说，`__init__.py` 文件作为包初始化时活动的钩子，声明目录为 Python 包，为目录生成模块命名空间，并在使用目录导入时实现 `from *`（即 `from .. import *`）语句的行为：

**包初始化**

Python 程序第一次通过目录导入时，会自动运行该目录 `__init__.py` 文件中的所有代码。因此，这些文件是放置包中文件所需状态初始化代码的常用位置。例如，包可以使用其初始化文件来创建所需的数据文件、打开数据库连接等。通常，`__init__.py` 文件不打算在直接执行时有用；它们在包首次被访问时自动运行。

**模块便利语句**

包的 `__init__.py` 文件也在某种程度上用于声明目录是一个 Python 包。在此角色中，这些文件用于防止具有通用名称的目录无意中隐藏稍后出现在模块搜索路径上的真实模块。如果没有此保护，Python 可能会选中一个与你的代码无关的目录，因为它出现在搜索路径上较早的位置。正如我们稍后将看到的，Python 3.3 的命名空间包阻止了这方面的大部分作用，但通过在路径上向前检查以发现后续文件，以算法方式实现了类似的效果。

在本章中，你已经了解了 Python 模块的入门级知识。你使用 Python 的范围现在将得到加强。这不仅仅是模块中的唯一内容，请确保将之前关于包的讨论与之结合。话虽如此，我们现在将转向 Python 编程中的面向对象编程（OOP）。别担心，什么是 OOP 将伴随其功能和优势一同给出。Python 变得越来越有趣了。请随我进入下一章。

## 第 16 章 – Python 中的 OOP：其结构与用法



到目前为止，在本书中，我们一直在常规地使用“object”（对象）这一表述。极端地说，迄今为止回顾的代码一直是基于对象的——我们在内容中传递问题，在语句中使用它们，调用它们的策略等。然而，要使我们的代码真正符合面向对象（OO）的资格，我们的文章通常还需要参与所谓的继承体系。本节开始对 Python 类的探讨——一种用于在 Python 中实现支持继承的新类型对象的编码结构和工具。类是 Python 的主要面向对象编程（OOP）工具，因此我们将在本书的这一部分一同了解 OOP 的基础知识。OOP 提供了一种不同且通常更强大的编程方法，我们在其中对代码进行分解以限制重复，并通过修改现有代码而非就地转换来编写新程序。在 Python 中，类是用另一种声明创建的：`class`。正如你将看到的，用类定义的对象看起来很像我们在书中前面研究的内置类型。事实上，类实际上只是应用并扩展了我们已经掌握的思想；总体而言，它们是利用和处理内置对象类型的函数包。然而，类旨在创建和管理新对象，并支持继承——这是一种代码定制和复用的机制，远超我们迄今为止所见。提前说明一点：在 Python 中，OOP 完全是可选的，你不必使用类就能开始。你可以用更简单的结构完成大量工作，例如函数，甚至简单的顶层脚本代码。由于有效使用类需要一些前期规划，它们通常对从事战略模式工作（进行长期产品开发）的人比对从事战术模式工作（时间难以寻觅）的人更有吸引力。尽管如此，正如你将在本书这一部分发现的，类被证明是 Python 提供的最有用的工具之一。如果使用得当，类实际上可以大幅缩短开发时间。它们还用于主流 Python 工具，如 `tkinter` GUI API，因此大多数 Python 开发人员多多少少都会发现掌握类的基础知识很有帮助。

### 为什么使用类？

简单来说，类只是定义新类型事物的一种方式，反映程序领域中的真实对象。例如，假设我们决定实现我们用作示例的那个假设的披萨制作机器人。如果我们用类来实现它，就能展现更多其真实的结构和联系。这里有两个 OOP 方面证明是有价值的：

#### 继承

披萨制作机器人是机器人的一种，所以它们拥有典型的机器人属性。用 OOP 术语来说，我们说它们从一般类别中“获得”属性。这些通用属性只需为一般情况实现一次，以后我们构建的各种机器人都可以部分或完全复用它们。

披萨制作机器人实际上是协同工作的组件集合。例如，为了让我们的机器人成功，它可能需要移动面团的手臂、移动到烤箱的电机等。用 OOP 术语来说，我们的机器人是一个组合的例子；它包含其他对象，并激活它们来完成其任务。每个组件都可以编码为一个类，定义其自身的行为和联系。

#### 多实例

类本质上是生产一个或多个对象的工厂。每次我们调用一个类，就会生成一个具有特定命名空间的新对象。从类生成的每个对象都可以访问类的特性，并获得自己的命名空间，用于存储因对象而异的数据。这类似于闭包函数的每次调用状态保持，但在类中是显式且通用的，只是类所做的事情之一。类提供了一套完整的编程方案。

通过提供特殊的协议方法，类可以定义对我们在内置类型上看到的操作类型做出反应的对象。例如，用类创建的对象可以被切片、连接、索引等。Python 提供钩子，类可以用它们来拦截并实现任何内置类型操作。从根本上说，Python 中 OOP 的机制在很大程度上只是两个神奇的部分：函数中的特殊第一个参数（用于获取调用的主体）和继承属性搜索（用于支持通过定制进行编程）。除此之外，该模型主要只是最终处理内置类型的函数。虽然不是非常新颖，但 OOP 增加了一个额外的结构层，支持比平面过程模型更好的编程。连同我们之前遇到的函数式工具，它代表了一个重要的抽象步骤，高于计算机硬件，帮助我们构建越来越复杂的程序。

### 嵌套异常处理器

到目前为止，我们的大多数示例只使用了单个 `try` 来捕获异常，但如果那个 `try` 在物理上嵌套在另一个内部会发生什么？话虽如此，如果一个 `try` 调用的函数运行了另一个 `try` 又意味着什么？实际上，`try` 语句可以嵌套，无论是在语法上还是在代码的运行时控制流方面。我简要提到过这一点，但让我们在这里阐明这个想法。

如果你理解 Python 在运行时会堆叠 `try` 语句，这两种情况都能理解。当引发异常时，Python 会返回到最近进入的、带有匹配 `except` 子句的 `try` 语句。由于每个 `try` 语句都会留下一个标记，Python 可以通过检查堆叠的标记跳回到之前的 `try`。当我们谈论将异常向上传播给“更高层”的处理器时，这种动态处理器的嵌套就是我们所指的意思——这些处理器本质上是在程序执行流中较早进入的 `try` 语句。

`try` 块中的代码量可能很大，并且可能包含调用其他代码的函数调用，这些代码寻找类似的异常。当异常最终被引发时，Python 会跳回到最近进入的、命名了该异常的 `try` 语句，运行该语句的 `except` 子句，然后在该 `try` 之后恢复执行。一旦捕获了异常，它的生命周期就结束了——控制不会跳回到所有命名该异常的匹配 `try`；只有第一个（即最近的）一个有机会处理它。

例如在图 36-1 中，`func2` 函数中的 `raise` 语句将控制权送回给 `func1` 中的处理器，然后程序在 `func1` 内部继续执行。相比之下，当包含仅 `finally` 子句的 `try` 语句嵌套时，发生异常时每个 `finally` 块都会依次运行——Python 继续将异常向上传播给其他的 `try`，并最终可能传播给顶层默认处理器（标准错误消息打印器）。正如所表示的，`finally` 子句不会扼杀异常——它们只是指定在异常传播过程中退出每个 `try` 时要运行的代码。如果在异常发生时有许多 `try/finally` 子句处于活动状态，它们都将被运行，除非 `try/except` 偶然捕获了该异常。

归根结底，当引发异常时程序去向何处，完全取决于它去过哪里——它是脚本运行时控制流的函数，而不仅仅是其语法。异常的传播基本上是按时间倒序回溯到已进入但尚未退出的 `try` 语句。当控制被放宽到匹配的 `except` 子句时，这种传播停止，但当它穿过途中 `finally` 子句时不会停止。当引发异常时（由你或 Python），控制会跳回到最近进入的、带有匹配 `except` 子句的 `try` 语句，程序在该 `try` 语句之后继续执行，但 `except` 子句捕获并停止异常——它们是你在引发异常时处理和恢复异常的地方；当在此处引发异常时，控制返回到最近进入的 `try` 以运行其 `finally` 子句，但随后异常继续传播到所有活动 `try` 语句中的 `finally`，并最终到达默认的顶层处理器，在那里打印错误消息。`finally` 子句阻塞（但不停止）异常——它们用于在“退出途中”执行的操作。

#### 示例：控制流嵌套

让我们转向一个示例，使这种嵌套概念更加具体。以下模块文件 `nestexc.py` 定义了两个函数。`action2` 被编码为触发异常（你不能将数字和序列相加），而 `action1` 将对 `action2` 的调用包装在一个 `try` 处理器中，以捕获该异常：

```
def action2():
    print(1 + []) # 生成 TypeError

def action1():
    try:
        action2()
    except TypeError: # 最近的匹配 try
        print('inner try')

try:
    action1()
except TypeError: # 仅当 action1 重新引发时才到这里
    print('outer try')
```

```
% python nestexc.py
inner try
```

然而请注意，文件底部的顶层模块代码也将对 `action1` 的调用包装在一个 `try` 处理器中。当 `action2` 触发 `TypeError` 异常时，将有两个活动的 `try` 语句——`action1` 中的一个，以及模块文件顶层的一个。Python 选择并仅运行最近的、带有匹配 `except` 的 `try`——在本例中是 `action1` 内部的 `try`。再次强调，异常最终去向何处取决于程序在运行时的控制流。因此，要想知道你将去向何处，你需要知道你从何而来。在这种情况下，异常的处理位置更多地取决于控制流，而不是语句语法。但我们也可以在语法上嵌套异常处理器——我们接下来将转向一个类似的例子。

已经确定语句可以与条件语句混合在同一个 `try` 语句中。这，加上对多个 `except` 子句的支持，使得本节描述的一些语法嵌套变得多余，然而，类似的运行时嵌套在更大的 Python 程序中很常见。此外，语法嵌套至今仍然有效，可能仍出现在你可能遇到的 Python 2.5 之前编写的代码中，可以使 `except` 和 `finally` 的不同角色更加明确，并且可以作为一种在整体上实现替代异常处理实践的技术。

让我们从回顾开始——Python 的 OOP 实现可以用三个想法概括：

*   **继承**：Python 中的继承基于属性查找（在 `X.name` 表达式中）。
*   **多态**：在 `X.method` 中，方法的含义取决于主体对象 `X` 的类型（类）。

到目前为止，你应该对 Python 中继承的含义有很好的感觉。我们已经讨论过 Python 的多态几次了；它源于 Python 缺乏类型声明。由于属性总是在运行时解析，实现相同接口的对象天然可互换；客户端不需要知道实现它们调用的方法的对象是什么类型。封装在 Python 中意味着打包——即在对象接口后隐藏实现细节。它不意味着强制安全，尽管那可以用代码实现。无论如何，封装在 Python 中是可用且有用的：它允许在不影响该对象用户的情况下更改对象接口的实现。

### `try/except/else` 语句

既然我们已经看过基础知识，是时候深入细节了。在接下来的讨论中，我将首先将 `try/except/else` 和 `try/finally` 作为独立的语句呈现，因为在 2.5 之前的 Python 版本中，它们扮演不同的角色且不能合并，而且至今在逻辑上仍可能是截然不同的。根据前面的说明，在 Python 2.5 及更高版本中，`except` 和 `finally` 可以混合在单个 `try` 语句中；在我们单独探讨了这两种不同形式之后，我们将看到这种合并的含义。

从语法上讲，`try` 是一个复合的、多部分的语句。它以 `try` 头行开始，后面跟着一块（大多）缩进的语句；然后是一个或多个 `except` 子句，标识要捕获的异常和处理它们的块；最后是一个可选的 `else` 子句和块。你通过将 `try`、`except` 和 `else` 缩进到同一级别（即垂直对齐）来关联它们。作为参考，这是 Python 3.X 中最通用和最完整的配置：

```
try:
    statements # 首先运行此主要操作
except name1:
    statements # 如果在 try 块中引发 name1 则运行
except (name2, name3):
    statement # 如果发生这些异常中的任何一个则运行
except name4 as var:
    statements # 如果引发 name4 则运行，将引发的实例赋值给 var
except:
    statements # 为引发的所有其他异常运行
else:
    statements # 如果 try 块中未引发异常则运行
```

从语义上讲，此语句中 `try` 头下的块代表语句的主要操作——你试图运行并用错误处理逻辑包装的代码。`except` 子句定义了在 `try` 块期间引发的异常的处理器，而 `else` 子句（如果编写）提供了一个处理器，如果没有发生异常则运行它。这里的 `var` 部分与 `raise` 语句和异常类的特性有关。

#### Try 语句如何工作



# 操作上，`try` 语句的运行方式如下

当进入 `try` 语句时，Python 标记当前程序上下文，以便在发生异常时可以返回。`try` 头下嵌套的语句首先运行。接下来发生的事情取决于 `try` 块的语句运行时是否引发异常，以及它们是否与 `try` 正在查找的异常匹配：

*   如果在 `try` 块的语句运行时发生异常，并且该异常与语句命名的某个异常匹配，Python 会跳回到 `try` 并运行第一个匹配引发异常的 `except` 子句下的语句，在将引发的异常对象赋值给子句中 `as` 关键字后命名的变量之后（如果存在）。`except` 块运行后，控制随即继续在整个 `try` 语句之下（除非 `except` 块本身引发另一个异常，在这种情况下，从代码中的这一点重新开始该过程）。
*   如果在 `try` 块的语句运行时发生异常，但该异常与语句命名的异常不匹配，则该异常向上传播到下一个最近进入的、匹配该异常的 `try` 语句；如果找不到这样的匹配 `try` 语句且搜索达到进程的顶层，Python 会终止程序并打印默认错误消息。
*   如果在 `try` 块的语句运行时没有发生异常，Python 运行 `else` 行下的语句（如果存在），然后控制继续在整个 `try` 语句之下。

换句话说，`except` 子句捕获 `try` 块运行时发生的任何匹配异常，而 `else` 子句仅在 `try` 块运行时未发生异常时运行。引发的异常通过我们将在下一节探讨的超类关系与 `except` 子句中命名的异常匹配，空的 `except` 子句（没有异常名）匹配所有（或所有其他）异常。`except` 子句是聚焦的异常处理器——它们仅捕获发生在相关 `try` 块语句内的异常。然而，由于 `try` 块的语句可以调用程序其他地方编写的函数，异常的来源可能在 `try` 语句本身之外。事实上，`try` 块可能调用任意数量的程序代码——包括可能有自己的 `try` 语句的代码，当异常发生时将首先被搜索。也就是说，`try` 语句可以在运行时嵌套。

## Try 语句子句

当你编写 `try` 语句时，各种子句可以出现在 `try` 头之后。如果你列出了所有潜在形式的大纲之一，你应该列出它。我们已经遇到了其中一些：正如你所知，`except` 子句捕获异常，`finally` 子句在退出时运行，`else` 子句在未遇到异常时运行。正式地，可以有任意数量的 `except` 子句，但只有在有一个 `except` 的情况下才能编写 `else`，并且只能有一个 `else` 和一个 `finally`。在 Python 2.4 及之前，`finally` 子句必须单独出现（没有 `else` 或 `except`）；`try/finally` 实际上是一个不同的语句。从 Python 2.5 开始，`finally` 可以出现在与 `except` 和 `else` 相同的语句中（当我们遇到统一的 `try` 语句时，稍后将详述排序规则）。

| 子句形式 | 解释 |
| :--- | :--- |
| `except:` | 捕获所有（或所有其他）异常类型。 |
| `except name:` | 仅捕获特定的异常。 |
| `except name as value:` | 捕获列出的异常并赋值其实例。 |
| `except (name1, name2):` | 捕获列出的任何异常。 |
| `except (name1, name2) as value:` | 捕获列出的任何异常并赋值其实例。 |
| `else:` | 如果 `try` 块中未引发异常则运行。 |
| `finally:` | 退出时始终执行此块。 |

当我们稍后在本章中遇到 `raise` 语句时，我们将更详细地探讨带有额外 `as value` 部分的条目。它们提供对作为异常引发的对象的访问。

### 捕获所有异常

此处的第一和第四个条目是新的：

*   不列出异常名的 `except` 子句（`except:`）捕获 `try` 语句中先前未列出的所有异常。
*   在括号中列出一组异常的 `except` 子句（`except (e1, e2, e3):`）捕获列出的任何异常。

由于 Python 通过从上到下检查 `except` 子句来在给定的 `try` 中查找匹配项，括号形式的效果与在各自的 `except` 子句中列出每个异常相同，但你只需为每个异常编写一次关联的语句体。这是多个 `except` 子句工作的示例，展示了你的处理器可以有多具体：

```
try:
    action()
except NameError:
    ...
except IndexError:
    ...
except KeyError:
    ...
except (AttributeError, TypeError, SyntaxError):
    ...
else:
    ...
```

在该示例中，如果在 `action` 函数调用运行时引发异常，Python 会返回到 `try` 并搜索第一个命名引发异常的 `except`。它从上到下、从左到右检查 `except` 子句，并在第一个匹配项下运行语句。如果没有匹配项，异常将传播到此 `try` 之外。请注意，`else` 仅在动作中未发生异常时运行——当引发没有匹配 `except` 的异常时，它不运行。

### 捕获所有：空的 `except`

如果你确实想要一个通用的“捕获所有”子句，请使用空的 `except`：

```
try:
    action()
except NameError:
    ... # 处理 NameError
except IndexError:
    ... # 处理 IndexError
except:
    ... # 处理所有其他异常
else:
    ... # 处理无异常情况
```

空的 `except` 子句是一种异常包含形式——因为它能发现一切，它允许你的处理器像你想要的那样通用或具体。在某些情况下，这种形式可能比在 `try` 中列出所有可能的异常更有用。例如，以下代码在不列出任何内容的情况下发现一切：

```
try:
    action()
except:
    ... # 捕获所有可能的异常
```

然而，空的 `except` 也引发了一些结构问题。虽然方便，但它们可能会捕获与你的代码无关的意外系统异常，并可能无意中捕获用于其他处理器的异常。例如，即使在 Python 中系统退出调用和 `Ctrl-C` 组合键也会触发异常，通常你希望这些能通过。更糟糕的是，空的 `except` 也可能捕获真正的编程错误，对于这些错误你很可能想看到错误消息。我们将在本书这一部分的最后作为一个陷阱回到这个问题。目前，我只想说，“谨慎使用。”

Python 3.X 更强烈地支持一种替代方案，解决了其中一个问题——捕获名为 `Exception` 的异常几乎具有与空 `except` 相同的效果，但忽略与系统退出相关的异常：

```
try:
    action()
except Exception:
    ... # 捕获所有可能的异常，除了退出
```
