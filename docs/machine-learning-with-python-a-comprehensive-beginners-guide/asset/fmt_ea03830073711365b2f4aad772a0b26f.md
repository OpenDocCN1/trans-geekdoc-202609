### `def` is Executable Code

Python functions are composed with another announcement, the `def`. Dissimilar to functions in compiled dialects, for example, C, `def` is an executable statement—your function does not exist until Python reaches and runs the `def`. Truth be told, it's lawful (and even once in a while valuable) to nest `def` declarations inside `if` statements, `while` loops, and even other `def`s. In the typical operation, `def` declarations are coded in module files and are normally run to produce functions when the module file they live in is initially imported.

### `def` Creates an Object and Assigns it to a Name

At the point when Python reaches and runs a `def` declaration, it creates another function object and assigns it to the function's name. Likewise, with all assignments, the function name turns into a reference to the function object. There's nothing magical about the name of the function—as you'll see, the function object can be assigned to different names, stored in a list, etc. Function objects may likewise have arbitrary user-defined attributes attached to them to record information.

*   **`lambda`** creates an object but returns it as a result. Functions may likewise be made with the `lambda` statement, an element that enables us to inline function definitions in spots where a `def` statement won't work syntactically.
*   **`return`** sends a result object back to the caller. At the point when a function is called, the caller stops until the function completes its work and returns control to the caller. Functions that compute a value send it back to the caller with a `return` statement; the returned value turns into the result of the function call. A `return` without a value simply returns to the caller (and sends back `None`, the default result).
*   **`yield`** sends a result object back to the caller but remembers the last known point of execution. Functions known as generators may likewise use the `yield` statement to send back a value and suspend their state so that they might be resumed later, to produce a progression of results over time. This is another advanced topic covered later in this piece of the book.
*   **`global`** declares module-level variables that are to be assigned. By default, all names assigned in a function are local to that function and exist only while the function runs. To assign a name in the enclosing module, functions must declare it in a `global` statement. More generally, names always look up in scopes—places where variables are stored—and assignments bind names to scopes.
*   **`nonlocal`** declares enclosing function variables that are to be assigned. Likewise, the `nonlocal` statement added in Python 3.X enables a function to assign a name that exists in the scope of a syntactically enclosing `def` statement. This enables enclosing functions to serve as a place to hold state—data remembered between function calls—without using shared global names.
*   **Arguments are passed by assignment (object reference).** In Python, arguments are passed to functions by assignment (which, as we've learned, implies by object reference). As you'll see, in Python's model the caller and function share objects by references, but there is no name aliasing. Changing an argument name inside a function does not affect the corresponding name in the caller, but changing mutable objects passed in can change objects shared by the caller, and serve as a function result.
*   **Arguments are passed by position, unless you say otherwise.** Values you pass in a function call match argument names in a function's definition from left to right naturally. For flexibility, function calls can likewise pass arguments by name with `name=value` keyword syntax and unpack arbitrarily many arguments to send with `*pargs` and `**kargs` syntax. Function definitions use a similar two structures to specify argument defaults and collect arbitrarily many arguments received.
*   **Arguments, return values, and variables are not declared.** As with everything in Python, there are no type constraints on functions. Truth be told, nothing about a function needs to be declared ahead of time: you can pass in arguments of any type, return any type of object, etc. As one outcome, a single function can often be applied to a variety of object types—any objects that sport a compatible interface (methods and expressions) will do, regardless of their specific types.

## `def` Statements

The `def` statement creates a function object and assigns it to a name. Its general format is as follows:

```
def name(arg1, arg2, ... argN):
    statements
```

Similarly as with all compound Python statements, `def` comprises a header line followed by a block of statements, usually indented (or a simple statement after the colon). The statement block becomes the function's body—that is, the code Python executes each time the function is later called. The `def` header line specifies a function name that is assigned the function object, along with a list of zero or more arguments (sometimes called parameters).
