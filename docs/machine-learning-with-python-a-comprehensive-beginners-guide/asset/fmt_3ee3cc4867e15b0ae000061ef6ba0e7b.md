
# Chapter 9 – Loops in Python

## While Loops

Python's `while` statement is the broadest iteration construct in the language. In straightforward terms, it repeatedly executes a block of (normally indented) statements as long as a test at the top keeps evaluating to a true value. It is known as a "loop" because control keeps looping back to the start of the statement until the test becomes false. Once the test becomes false, control passes to the statement that follows the `while` block. The net effect is that the loop's body is executed repeatedly while the test at the top is true. If the test is false to begin with, the body never runs and the `while` statement is skipped.

### General Format

In its most complex form, the `while` statement consists of a header line with a test expression, a body of one or more normally indented statements, and an optional `else` part that is executed if control leaves the loop without a `break` statement being encountered. Python keeps evaluating the test at the top and executing the statements nested in the body until the test returns a false value:

```
while test:          # Loop test
    statements       # Loop body
else:                # Optional else
    statements       # Run if didn't exit loop with a break
```

### Examples

To illustrate, let's look at a few basic `while` loops in action.

The first, which consists of a `print` statement nested in a `while` loop, just prints a message forever. Recall that `True` is just a custom version of the integer `1` and always stands for a Boolean true value; since the test is always true, Python keeps executing the body forever, or until you stop its execution. This kind of behavior is usually called an **infinite loop**—it's not really eternal, but you may need a `Ctrl-C` key combination to forcefully terminate one:

```
>>> while True:
...     print('Type Ctrl-C to stop me!')
```

The next example keeps slicing off the first character of a string until the string is empty and hence false. It's common to test an object directly like this instead of using the more verbose equivalent (`while x != '':`). Later in this chapter, we'll see other ways to step through the items in a string more directly with a `for` loop.

```
>>> x = 'spam'
>>> while x:              # While x isn't empty
...     print(x, end=' ')
...
spam pam am m
```

Note the `end=' '` keyword argument used here to put all outputs on a single line separated by a space. This may leave your input prompt in an odd state at the end of your output; type `Enter` to reset. Python 2.X readers: likewise remember to use a trailing comma instead of an `end` in the prints this way.

The following code counts from the value of `a` up to, but not including, `b`. We'll also see an easier way to do this with a Python `for` loop and the built-in `range` function later:

```
>>> a=0; b=10
>>> while a < b:          # One way to code counter loops
...     print(a)
...     a += 1
```

Finally, note that Python doesn't have what some languages call a "do until" loop statement. However, we can simulate one with a test and `break` at the bottom of the loop body, so the loop's body is always run at least once:

```
while True:
    ...loop body...
    if exitTest(): break
```

To fully understand how this structure works, we need to move on to the next section and learn about the `break` statement.

## break, continue, pass, and the Loop else

Now that we've seen a few Python loops in action, it's time to investigate two simple statements that have a purpose only when nested inside loops—the `break` and `continue` statements. While we're looking at oddities, we will also study the loop `else` clause here because it is intertwined with `break`, and Python's empty placeholder statement, `pass` (which isn't tied to loops per se, but falls into the general category of simple one-word statements).

In Python:

*   `break`: Jumps out of the closest enclosing loop (past the entire loop statement).
*   `continue`: Jumps to the top of the closest enclosing loop (to the loop's header line).
*   `pass`: Does nothing at all: it's an empty statement placeholder.
*   Loop `else` block: Runs if and only if the loop is exited normally (i.e., without hitting a `break`).

### General Loop Format

Factoring in `break` and `continue` statements, the general format of the `while` loop looks like this:

```
while test:
    statements
    if test: break        # Exit loop now, skip else if present
    if test: continue     # Go to top of loop now, to test
else:
    statements            # Run if we didn't hit a 'break'
```

`break` and `continue` statements can appear anywhere inside the `while` (or `for`) loop's body, but they are usually coded further nested in an `if` test to take action in response to some condition. Let's turn to a few simple examples to see how these statements come together in practice.

### Pass

First things first: the `pass` statement is a no-operation placeholder used when the syntax requires a statement, but you have nothing useful to say. It is often used to code an empty body for a compound statement. For instance, if you want to code an infinite loop that does nothing each time through, do it with a `pass`:

```
while True: pass!
```

Since the body is just an empty statement, Python gets stuck in this loop. `pass` is roughly to statements as `None` is to objects—an explicit nothing. Notice that here the `while` loop's body is on the same line as the header, after the colon; as with `if` statements, this only works if the body isn't a compound statement. This example does nothing forever. It probably isn't the most useful Python program ever written (unless you want to heat up your laptop on a cold winter's day!); to be honest, though, I couldn't think of a better `pass` example this early in the book. We'll see other places where `pass` makes sense later—for instance, to ignore exceptions caught by `try` statements, and to define empty class objects with attributes that act like "structs" and "records" in other languages. A `pass` is also sometimes coded to mean "to be filled in later," to stub out the bodies of functions temporarily:

```
def func1(): pass  # Add real code here later
def func2(): pass
```

We can't leave the body empty without getting a syntax error, so we say `pass`.

**Version skew note:** Python 3.X (but not 2.X) allows ellipses coded as `...` (literally, three consecutive dots) to appear wherever a statement can. Since ellipses do nothing by themselves, this can serve as an alternative to the `pass` statement, especially for code to be filled in later—a kind of Python "TBD":

```
def func1(): ...  # Alternative to pass
def func2(): ...
func1()           # Does nothing when called
```

Ellipses can also appear on the same line as a statement header and might be used to initialize variable names if no specific type is required:

```
def func1(): ...  # Works on the same line too
def func2(): ...
>>> X = ...       # Alternative to None
>>> X
Ellipsis
```

This feature is new in Python 3.X—and goes well beyond the original purpose of `...` in slicing extensions—so it remains to be seen if it becomes widespread enough to challenge `pass` and `None` in these roles.

### Continue

The `continue` statement causes an immediate jump to the top of a loop. It sometimes lets you avoid statement nesting. The next example uses `continue` to skip odd numbers. This code prints every even number less than 10 and greater than or equal to 0. Remember, `0` means false and `%` is the remainder of division (modulus) operator, so this loop counts down to 0, skipping numbers that aren't multiples of 2—it prints `8 6 4 2 0`:

```
x = 10
while x:
    x = x - 1
    if x % 2 != 0: continue  # Odd? - skip print
    print(x, end=' ')
```

Since `continue` jumps to the top of the loop next, you don't have to nest the `print` statement here inside an `if` test; the `print` is only reached if the `continue` isn't run. If this sounds like a "goto" in other languages, it should. Python has no "goto" statement, but since `continue` lets you jump around in a program, many of the warnings about readability and maintainability you may have heard about "goto" apply. `continue` should probably be used sparingly, especially when you're first starting with Python. For instance, the last example might be clearer if the `print` was nested under the `if`:

```
x = 10
while x:
    x = x - 1
    if x % 2 == 0:        # Even? - print
        print(x, end=' ')
```

### Break

The `break` statement causes an immediate exit from a loop. Since the code that follows it inside the loop isn't executed if the `break` is reached, you can also sometimes avoid nesting by using a `break`. For example, here is a simple interactive loop that inputs data with `input` and exits when the user enters "stop" for the name prompt:

```
>>> while True:
...     name = input('Enter name:')
...     if name == 'stop': break
...     age = input('Enter age: ')
...     print('Hello', name, '=>', int(age) ** 2)
...
Enter name: bob
Enter age: 40
Hello bob => 1600
Enter name: sue
Enter age: 30
Hello sue => 900
Enter name: stop
```

Notice how this code converts the age input to an integer with `int` before raising it to the second power; as you'll recall, this is necessary because `input` returns user input as a string. You'll notice that `input` also raises an exception at end-of-file (e.g., if the user types `Ctrl-Z` on Windows or `Ctrl-D` on Unix); if this matters, wrap input in `try` statements.

### Loop else

When combined with the loop `else` clause, the `break` statement can often eliminate the need for the search status flags used in other languages. For instance, the following piece of code determines whether a positive integer `y` is prime by searching for factors greater than 1:

```
x = y // 2
while x > 1:
    if y % x == 0:        # Remainder
        print(y, 'has factor', x)
        break             # Skip else
    x -= 1
else:                     # Normal exit
    print(y, 'is prime')
```

Instead of setting a flag to be tested when the loop is exited, it inserts a `break` where a factor is found. This way, the loop `else` clause can assume it will be executed only if no factor is found; if you don't hit the `break`, the number is prime. Trace through this code to see how this works.

The loop `else` clause is also run if the body of the loop is never executed, as you don't run a `break` in that case either; in a `while` loop, this happens if the test in the header is false to begin with. Thus, in the former example you still get the "is prime" message if `x` is initially less than or equal to 1 (for example, if `y` is 2).

This example determines primes, but only informally so. Numbers less than 2 are not considered prime by the strict mathematical definition. To be perfectly precise, this code also fails for negative numbers and succeeds for floating-point numbers with no decimal digits. Also note that its code must use `//` rather than `/` in Python 3.X due to the migration of `/` to "true division" (we need the integer division to truncate remainders, not keep them!).
