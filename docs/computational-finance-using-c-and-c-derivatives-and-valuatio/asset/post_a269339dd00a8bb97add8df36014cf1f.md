## 8.3 The Text Files

## The Text Files

The application is driven by a portfolio configuration file and also a number of portfolio definition files, each of which is plain text and can easily be edited by the user. The portfolio configuration file specifies the names of the portfolio files which are to be valued, and each portfolio definition file provides the details of the trades contained in a given portfolio. In addition, there is a market data file (also in text format) which provides the market data required to value the trades.

A portfolio configuration file and two portfolio definition files are included in the portfolio definition files, in Exhibit 8.1. It can be seen that it is useful to document the deals contained in the portfolio. It is also possible to ignore a single trade by using // at the beginning of a line. Complete sections of portfolio definition file can also be ignored by using the C style syntax /*..

The syntax of each deal entry in the portfolio definition file is as follows:

```
Trade=DealClass.Reference=DescriptionText.DealClassParam1=Value, ...DealClassParamN=Value
```

Each deal line begins with an assignment to the Trade attribute using the syntax Trade=DealClass, where <DealClass> is the name of the C# class used to represent the given deal, equityOption for an Equity Option. The other deal attributes are properties of DealClass and Deal valuation proceeds by first constructing an empty object of type Deal. The application converts the string representation of the attribute values to the values expected by the DealClass and assignment to the deal object occurs. Once the deal object has been populated with the required market data, the deal.Price() method is run. This retrieves the required market data, computes the deal value, and returns this to this application for output to the portfolio results file. All deals have the reference attribute which is used for the purposes of identification. It is a description (or alpha-numeric code) assigned to the trade, for instance Reference=EQ:LaserComm-1001 or Reference-Text0008_Generic. The portfolio results contain both the value and reference for each deal which has been valued.

The reason for the Volatility attribute will be discussed later. If we explicitly pass all information required by the underlying C++ function black_classes, then the required entry (referred to as E2) would be

```
Trade-EquityOptionCall,Reference-EQ:Web6064,Equity-WebCom,Volatility=0.1,
Strike=95.0,Time_To_Expiry=1.0,OptionType-Put,Exercise-Style=European,European-Spot=100,
FXCurrency=0.565,RiskFreeRate=0.1,DividendYield=0.05
```

The reason that E1 does not require the four attributes EquitySpot=100,FXCurrency=0.5565,RiskFreeRate=0.1,DividendYield=0.05, is that these are stored in market dictionaries and accessed by the C class EquityOptionData before the C++ function black_classes is called.

The market dictionaries are populated as soon as the application starts. Exhibit 8.2 shows an example market data.
