# Exhibit 8.1.

In the C++ derivative pricing functions developed in the earlier part of this book, all the information such as asset price, risk-free interest rate, etc., was passed to the pricing engine.

For instance, we consider the pricing of the simple EquityOption, which is specified in Exhibit 8.1. The entry (which we will refer to as E1 in the portfolio definition file eq-investments) is

```
Trade-EquityOptionCall,Reference-EQ:WebComm-1004A,Equity=WebComm,Volatility=0.1,
Strike=0.9,Time_To_Expiry=1.0,OptionType-Call,Exercise-Style=European,European-Spot=100,
FXCurrency=0.565,RiskFreeRate=0.1,DividendYield=0.05
```

The reason for the Volatility attribute will be discussed later. If we explicitly pass all information required by the underlying C++ function black_classes, then the required entry (referred to as E2) would be

```
Trade-EquityOptionCall,Reference-EQ:WebComm-1004A,Equity=WebComm,Volatility=0.1,
Strike=0.9,Time_To_Expiry=1.0,OptionType-Put,Exercise-Style=European,European-Spot=100,
FXCurrency=0.565,RiskFreeRate=0.1,DividendYield=0.05
```

The reason that E1 does not require the four attributes EquityEquitySpot=100,FXCurrency=0.5565,RiskFreeRate=0.1,DividendYield=0.05, is that these are stored in market dictionaries and accessed by the C class EquityOptionData before the C++ function black_classes is called.

The market dictionaries are populated as soon as the application starts. Exhibit 8.2 shows an example market data. This plain text file provides a common repository for market parameters that are required by the deal classes. For instance, all foreign exchange derivatives will need access to the current FX rates, and all data file can be updated as frequently
