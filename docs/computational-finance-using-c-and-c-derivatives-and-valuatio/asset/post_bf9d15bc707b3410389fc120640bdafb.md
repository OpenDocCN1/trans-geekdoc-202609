## Assign the Asset Values to the Lattice Nodes

We will show that the number of different asset prices, $LS_n$, for an $n$ step recombining lattice is $2n+1$.

The nodes in a recombining lattice can be considered as composed of two kinds: those corresponding to an *even time step* and those corresponding to an *odd time step*.

This is the set of node asset values, $ET$, for an even time step is distinct from the set of node asset values, $OT$, for an odd time step. Although $ET \cap OT = \emptyset$, the elements of $ET$ and $OT$ for any consecutive pair of time steps are related by the simple constant multiplicative factor $d$. Also for an even time step there is a central node corresponding to the asset price $S_0$, and the remaining nodes are symmetrically arranged around this, see Code excerpt 5.6. These features are illustrated in Fig. 5.1, for a standard lattice with six time steps.

The number of distinct asset prices in a lattice is therefore the sum of nodes in the last two time steps. Since the number of nodes in the $ith$ time step, $S_i$, is $i+1$ (see Fig. 5.1), for an $n$ time step, we have:

$S_n = n+1$ and $S_{n-1} = n$.

This means that the number of different asset values in an $n$ time step lattice is:

$LS_n = S_n + S_{n-1} = 2n$.

The number of nodes in an $n$ time step lattice, is

$LN_n = \sum_{i=0}^{n}(i+1) = \frac{(n+1)(n+2)}{2}$

where we have used the fact that $LN_n$ is the sum of an arithmetic progression with first term 1, increment 1, and last term $n+1$.

One might think that, in order to price options, it is necessary to store the asset value of each lattice node, which would entail storing $LN_n$ values.

Storing $LS_n$ values instead of $LN_n$ can result in dramatic economics of storage. For an example, a 100-step lattice $LN_n = 2001 \times 2002 \times 1/2 = 2003001$, while the corresponding value of $LS_n$ is $2 \times 100 + 1 = 2001$.

```
s[0] = 50;
```

## Compute the Option Payoff at the Terminal Nodes

The current value of an option is evaluated by starting at option maturity, the end of the tree, and working backwards. The option values for the terminal nodes of tree are given by the payoff (at maturity) of the option; this is independent of whether the option is an American or European. For a lattice with $n$ time steps, there are $n+1$ terminal nodes, with option values, $f_{n,j} = 0, \dots, n$.

To compute the values of vanilla American and European options, $E$ we will start with the following terminal node values: for put options,

$f_{n,j} = \max(Su^j d^{n-j} - E, 0), \quad j = 0, \dots, n$

and for call options,

$f_{n,j} = \max(E - Su^j d^{n-j}, 0), \quad j = 0, \dots, n$

The computer code to use this is **Code excerpt 5.7**:

