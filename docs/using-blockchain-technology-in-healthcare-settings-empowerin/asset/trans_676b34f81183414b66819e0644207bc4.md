

# IoT 应用面临的安全与隐私挑战

IoT 应用面临的挑战源于其日益增长的普及度，以及缺乏与安全和隐私问题相关的研究。在农业领域，IoT 设备用于传输存储在数据库中的感知数据，因此存在数据完整性问题，这是作者将要解决的问题。\[[11](#index_split_018.html#filepos915034)\] 旨在提出解决当前论文研究中存在的所有问题的方案，其中研究仅关注实现 IoT，而不关注安全和数据完整性。研究人员提出了一种区块链实现，将使用 Ethereum 确保智能灌溉的安全性和完整性。拟议的区块链解决方案中使用的网络类型分为三种：公共网络，即任何人都可以访问；仅授权用户可以访问区块链；以及只有获得许可的人才能访问此网络。该系统由以下组件构建：(i) IoT 传感器：其任务是使用一种称为 MQTT (Message Queuing Telemetry Transport) 的协议将数据传输到区块链。(ii) Ethereum 确保系统的安全性。(iii) 数据存储库用于包含结果并存储它。(iv) 用户。在对私有区块链网络进行不同类型的测试（例如软件单元测试、智能合约测试和数据完整性测试）后得出了结果。

\[[23](#index_split_018.html#filepos920140)\] 的目标是保护在云服务提供商 (CSP) 中收集并存储在云边缘协作存储中的数据收集。这些信息可能导致用户隐私问题。研究人员旨在提供一种基于区块链技术的解决方案，以帮助改善物联网车辆 (IoV) 上的安全性和隐私问题。拟议的解决方案使用了双线性映射，这是一种在线性路径上创建转换的函数；第三方审计 (TPA)，云服务提供商用于存储资源，数据生成器收集关于 IoV 的数据，边缘节点存储从数据生成器收集的数据，数据用户是数据的用户，区块链技术用于验证数据完整性和事务的有效性。系统经过评估并发现：(i) 数据已加密以避免数据被窃取，因此系统可以在一定程度上实现数据隐私。(ii) 第三方审计不可信。(iii) 云服务提供商和边缘节点会产生时间开销以提供数据完整性的证据。(iv) 减少了第三方审计员的时间开销。

随着大数据分析的兴起，存在对存储在云服务器上的数据的信任问题。\[[24](#index_split_018.html#filepos920495)\] 的目标是对基于区块链的系统中的链外交易队列延迟进行评估并保证数据完整性。研究人员阐明了一种用于链外的协议及其如何影响队列模型的性能。拟议的解决方案是一种用于创建证明的排队方法，该方法考虑了链外交易 (OTXs) 处理所需的时间。特别是在定期更新的数据（例如 IoT 数据）的情况下，该模型有助于估计平均 OTX 排队时间并确定实施的链外策略是否成功保证了数据完整性。该研究说明了 OTX 批量大小和 OTX 速率等变量如何影响 OTX 排队延迟，并给出了理论和模拟数据来支持结论的有效性。研究人员评估 OTX 排队延迟以评估排队模型的结果。此外，作者构建了一个比较来比较测试结果的值。评估过程中使用了一个数值参数，例如 OTX 批量大小和 OTX 速率，这些参数会影响 OTX 排队延迟。

存在保护由低功耗 IoT 设备在公共区块链网络上存储和使用的传感器数据完整性的问题。\[[25](#index_split_018.html#filepos920947)\] 还解决了链外选项的缺点以及与链上存储相关的高交易成本。拟议的数据保护协议解决了这些问题，并提供了一种在公共区块链上存储和验证传感器数据的低成本且安全的方法。该研究的目标是提供一种协议，旨在解决与使用公共区块链网络的 IoT 设备延长电池寿命、降低交易费用以及保护记录传感器数据的数据完整性相关的问题。此外，它还为低功耗 IoT 设备提供了一种在公共区块链上安全且经济地存储和验证传感器数据的方法。拟议的解决方案是一种数据安全协议，旨在解决链上和链外存储的缺点，同时结合它们的优势。拟议的解决方案使用智能合约、去中心化 Web 应用程序和公共区块链的不同组合，旨在保护数据安全、节省交易成本并延长电池寿命。协议包括以下操作：(i) 数据收集：收集关于传感器的信息，例如传感器 ID、开始时间、增量时间和数据哈希。(ii) 数据加密：一种对称密钥加密方法来加密收集的数据。(iii) 智能合约实现：为了存储和验证加密数据，将智能合约引入公共区块链。(iv) 数据验证：创建一个去中心化 Web 应用程序来验证在公共区块链上收集的信息。使用 ESP32S2 设备作为概念验证，以确认数据存储机制的评估和有效性。该研究评估和测试了解决方案的能耗、内存利用率和安全性。研究人员发现，如果数据使用 Wi-Fi 传输，低功耗传感器节点可以提及公共区块链的数据完整性。
