
# 引言
在 `Web 2.0` 中，由于数据集合之间没有建立关系，几乎很难发现新信息，导致典型网络挖掘的结果完全不可接受。人们现在正在寻求 `web3.0` 以实现更高效的挖掘。在这种情况下，由于数据的清晰、有序呈现，机器人和人类能够协作。通过使用本体，语义网的数据相互连接，从而实现更高效的发现、自动化和同化方法。这些记录可以被计算机读取和理解，使其适合人类和软件共同协作和分析。语义网建立在多层架构之上 [[2](#ch25.xhtml#ref25_2), [3](#ch25.xhtml#ref25_3)]。用于定义 Web 信息及其本质的语义模型由资源描述框架 (`RDF`) 和 `RDF Schema` 提供 [[4](#ch25.xhtml#ref25_4)]。任何基于 `RDF` 的数据（即使用 `RDFS` 和 `OWL` [[6](#ch25.xhtml#ref25_6)] 的语句）都可以使用 `SPARQL` [[5](#ch25.xhtml#ref25_5)] `RDF` 查询语言进行查询。本体语言层定义了常规知识并阐明了不同类型数据之间的语义联系。因为它提供了可机器处理的语义和可共享的领域，所以本体被视为语义网架构的关键组成部分 [[7](#ch25.xhtml#ref25_7), [8](#ch25.xhtml#ref25_8)]，该架构旨在改善人类与软件之间的通信。`Web 3.0`，即 `Semantic Web`，基于向现有网络添加可机器处理内容这一理念。通过使用可机器处理的信息将其引导至最相关的页面，可以提高搜索引擎的准确率和召回率。`Web Mining` 的主要目标是从网站的上下文和功能中提取有用信息。由于所分析的数据在很大程度上是句法性的，仅凭这些数据无法发现意义。因此，网站语义和导航行为的形式化变得越来越普遍。将 `Semantic Web` 与 `Web Mining` 相结合形成了 `Semantic Web Mining`。网上的大多数数据结构如此松散，以至于只有人类才能理解它们，但数据量如此之大，以至于只有机器人才能高效分析。网络挖掘通过自动获取这些数据中隐藏的重要知识并以可管理的方式使其可访问来解决这个问题的后半部分，而 `Semantic Web` 则通过旨在使数据可被机器阅读来解决前半部分。

## 文献综述
本文分为以下几个部分。`Section 2` 提供了关于网络本体语言 (`OWL`) 及其规范的基本信息。`Section 3` 讨论了与本体编辑器相关信息。`Section 4` 介绍了所提出的语义信息检索模型的 methodology。它涉及通过传统搜索引擎和我们提出的模型处理用户查询。`Section 5` 介绍了结果分析。`Section 6` 总结了研究发现并提出了进一步研究的建议。

### 本体网络语言 (OWL) 及其规范
当档案中的数据除了向人类展示外还必须由应用程序处理时，需要 `OWL`。委派词语的含义及其相互关系是 `OWL` 的一种应用。本体是它的另一个名称 [[9](#ch25.xhtml#ref25_9), [10](#ch25.xhtml#ref25_10)]。因为 `OWL` 比 `XML`、`RDF` 和 `RDF-S` 拥有更多阐明意义和语义学的工具，所以它能够比其他少数语言更好地在网络上展示机器可解释的材料。`OWL` 在线本体语言是 `DAML+OIL` 的改进版本，考虑了从 `DAML+OIL` 设计和征求意见中吸取的明智经验 [[11](#ch25.xhtml#ref25_11), [12](#ch25.xhtml#ref25_12)]。`OWL` 扩展了用于描述类及其属性、基数（如“准确地一个”）、群组关系、特征属性和预期类等事物的词汇。`OWL` 提供了三种逐步创新的子语言，旨在满足不同应用开发人员和终端用户的需求 [[13](#ch25.xhtml#ref25_13), [14](#ch25.xhtml#ref25_14)]。

- 由于其形式复杂性低于 `OWL DL`，`OWL Lite` 是各种分类法之间有用的桥梁。
- 如果你想要计算完备性和可判定性所提供的最高表达能力，`OWL DL` 是最佳选择。
- 那些想要 `RDF` 的计算自由和最大表达性的人可以考虑升级到 `OWL Full`。`OWL Full` 已在我们的模型实现中使用。

### Protégé - 一个本体编辑器
我们的工作使用 `Protégé 4.3` 实现。`Protégé` [[15](#ch25.xhtml#ref25_15), [16](#ch25.xhtml#ref25_16)] 是一个免费的开源框架和本体编辑器。为了在组织建模（我们的大学模型）、生物医学和电子商务等领域构建基于知识的成果，`Protégé` 被大量用户社区使用（如学术、政府和企业）。为了表示将业务支持算法与数据集成联系起来的学术本体，我们选择了 `Protégé 4.3`。我们在服务器之间共享本体的能力有助于跨团队协调工作。此外，`Ontoviz` 插件有助于提供概念图。在研究完成后，本体可能变得公开，并可向任何提出请求的人提供。为了找到与提取的关键词相关联的一组网站，如 [[17](#ch25.xhtml#ref25_17), [18](#ch25.xhtml#ref25_18)] 中所述，作者首先提取某些指示该领域的关键词。在尝试使用此方法对网络记录进行聚类和关联时出现了类似问题。除了 `RDF` 之外，`Protégé` 还支持万维网联盟 (`W3C`) 推迟的 Web 本体语言 (`OWL`) 版本 2 要求。

## 拟议方法
### 拟议语义模型
互联网上的绝大多数数据都是非结构化的，使其在统一框架下聚合变得异常困难。我们同时考虑经典网络挖掘模型和由语义代理启用的语义网络挖掘模型，以实现结构化概念网络与非结构化现实世界网络场景的混合。[`Figure 25.1`](#ch25.xhtml#fig25_1) 描述了我们的建议模型，该模型包括以下阶段。

![图 25.1 拟议方法的步骤](images/fig25_1_B.jpg)

[`Figure 25.1 Steps of the proposed approach`](#ch25.xhtml#R_fig25_1)

1. 用于向处理器提交用户查询的接口。在数据服务器中，负责处理查询的部分称为 `query processor`。
2. 当用户向 `query processor` 提交查询时，它会同时通过 `interface engine` 将请求提交给常规查询引擎 (`GOOGLE`) 和智能代理。搜索查询输入到查询引擎，查询引擎随后处理请求、提供结果，并在必要时请求进一步信息。通过转换客户端的搜索查询并保护它们免受访问底层数据源的繁琐细节，该服务作为两者之间的中介。然后将来自 `RDF database` 的结果传递给 `interface engine`，该引擎基于传统查询引擎的结果。
3. 在基于代理的搜索背景下，有必要建立初始本体。这涉及整合许多与在线项目相关的概念以生成此类本体。本体层将在 `ontology bank` 网络或数据库中维护，以便在未来阶段后续使用。
