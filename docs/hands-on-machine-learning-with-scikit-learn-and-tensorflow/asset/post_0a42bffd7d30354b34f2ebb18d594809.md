
![](img/0684d2da98e09085c0a622d4fd69aaad_274_0.png)

Figure 9-9. Selecting the number of clusters k using the silhouette score

As you can see, this visualization is much richer than the previous one: in particular, although it confirms that k=4 is a very good choice, it underlines the fact that k=5 is quite good as well, and much better than k=6 or 7. This was not visible when comparing inertias.

An even more informative visualization is obtained when you plot every instance's silhouette coefficient, sorted by the cluster they are assigned to and by the value of the coefficient. This is called a silhouette diagram (see Figure 9-10):

![](img/0684d2da98e09085c0a622d4fd69aaad_274_1.png)

Figure 9-10. Silhouette analysis: comparing the silhouette diagrams for various values of k

The vertical dashed lines represent the silhouette score for each number of clusters. When most of the instances in a cluster have a lower coefficient than this score (i.e., if many of the instances stop short of the dashed line, ending to the left of it), then the cluster is rather bad since this means its instances are too close to other clusters. We can see that when k=3 and when k=6, we get bad clusters. But when k=4 or k=5, the clusters look pretty good – instances extend beyond the dashed line, to the right and close to 1.0. When k=4, the cluster at index 1 (the third from the top), is rather big, while k=5, all clusters have similar sizes, even though the over-silhouette score from k=4 is slightly greater than k=5, it seems like a good idea to use k=5 to get clusters of similar sizes.

## Limits of K-Means

Despite its many merits, most notably being fast and scalable, K-Means is not perfect. As we saw, it is necessary to run the algorithm several times to avoid sub-optimal solutions, plus you to specify the number of clusters, which can be quite a hassle. Moreover, K-Means does not behave well when the clusters have varying sizes, different densities, or non-spherical shapes. For example, Figure 9-11 shows how K-Means clusters containing two ellipsoidal clusters of different dimensions, densities and orientations:

![](img/0684d2da98e09085c0a622d4fd69aaad_275_0.png)

Figure 9-11. K-Means fails to cluster these ellipsoidal blobs properly

As you can see, neither of these solutions are good. The solution on the left is better, but it still offs 25% of the middle cluster and assigns it to the right. The solution on the right is just enough, even though its inertia is lower. So depending on the data, different clustering algorithms may perform better. For example, on these types of ellipsoidal clusters, Gaussian mixture models work great.

![](img/0684d2da98e09085c0a622d4fd69aaad_275_1.png)

It is important to scale the input features before you run K-Means, or else the clusters may be very stretched, and K-Means will perform properly. Scaling the features does not guarantee that all the clusters will be nice and spherical, but generally improves things.

## Using clustering for image segmentation

Image segmentation is the task of partitioning an image into multiple segments. In semantic segmentation, all pixels that are part of the same object type assigned to the same segment. For example, in a self-driving car's vision system, all pixels that are part of a pedestrian's image might be assigned to the "pedestrian" segment (there would just be one segment containing all the pedestrians). In instance segmentation, all pixels that are part of the same individual object assigned to the same segment. In this case there would be a different segment for each pedestrian. The state of the art in semantic or instance segmentation today is achieved using complex architectures based on convolutional neural networks (see Chapter 14). Here, we are going to do something simpler: color segmentation. We will simply assign pixels to the same segment if they have a similar color. In such applications, this may be beneficial, for example if you want to analyze satellite images to measure how much forest area there is in a region, color segmentation may be just fine.

First, let's load the image in Figure 9-12 using Matplotlib's read():

```python
>>> from matplotlib.image import imread # you could also use 'imageio.imread'
>>> image = imread(os.path.join("imagesclustering"
```

The image is represented as a 3D array: the first dimension is the height, the second is the width, and the third is the number of channels, in this case red, green and blue (RGB). In other words, for each pixel there is a 3D vector containing the intensities of red, green and blue, between 0.0 and 1.0 (or between 0 and 255 if you use imageto.imread()). Some images may have fewer channels, such as grayscale images (one channel), or more channels, such as images with an additional channel for transparency, or satellite images which contain many frequencies (e.g., infrared). The following code reshapes the array to a long list of RGB colors, then it clusters these using K-Means. For example, it may identify a cluster for all shades of green. Next, for each cluster, it finds the mean color of the pixel. For example, all shades of green may be replaced with the same light color (assuming the mean color of the green cluster is light). Finally it reshapes this list of clusters to get the same shape as the original. And we're done!

```python
X = image.reshape(-1, 3)
kmeans = KMeans(n_clusters=8).fit(X)
segmented_img = kmeans.labels_
segmented_img = segmented_img.reshape(image.shape)
```

This outputs the image shown in the upper right of Figure 9-12. You can experiment with various numbers of clusters, as shown in the figure. When you use less than 8 clusters, notice that the ladybug's color gets a cluster of its own; this is due to the fact that the ladybug is quite small, much than the rest of the image, so though its color is flashy, K-Means fails to dedicate a cluster to it as mentioned earlier, K-Means prefers clusters of similar sizes.

## Using Clustering for Preprocessing

Clustering can be an efficient approach to dimensionality reduction, in particular as a preprocessing step before a supervised learning algorithm. For example, let's tackle the digits dataset which is a simple MNIST-like dataset containing 1797 grayscale 8x8 images representing 0 to 9. First let's load the dataset:

```python
from sklearn.datasets import load_digits
X_digits, y_digits = load_digits(return_X_y=True)
```

Now, let's split it into a training and a test set:

```python
from sklearn.model_selection import train_split
X_train, X_test, y_train, y_test = train_split(X_digits, y_digits)
```

Next, let's fit a Logistic Regression model:

```python
from sklearn.linear_model import LogisticRegression
log_reg = LogisticRegression(random_state=42)
log_reg.fit(X_train, y_train)
```

Let's evaluate its accuracy on the test set:

```python
>>> log_reg.score(X_test, y_test)
0.9666666666666667
```

Okay, that's our baseline: 96.7% accuracy. Let's see if we can do better by using K-Means as a preprocessing step. We will create a pipeline that will first cluster the training set into 50 clusters and replace the distances to these 50 clusters, then apply a logistic regression model.

Although it is tempting to define the number of clusters to 10, since there are 10 different digits, it is unlikely to perform well, because there are several ways ways write each digit.

![](img/0684d2da98e09085c0a622d4fd69aaad_278_0.png)

```python
from sklearn.pipeline import Pipeline
pipeline = Pipeline({
    ('kmeans', KMeans(n_clusters=50)),
    ('log_reg', LogisticRegression())
})
pipeline.fit(X_train, y_train)
```

Now let's evaluate this classification:

```python
>>> pipeline.score(X_test, y_test)
0.9822222222222222
```

How about that? We almost divided the error by a factor of 2!

But we choose the number of clusters completely arbitrarily, we can surely do better. Since K-Means is just a preprocessing step in a classification pipeline, finding a good value for k is much simpler than earlier: there is no need to perform silhouette analysis or minimize the inertia, the best value of k is the one that results in the best classification performance through cross-validation. Let's use GridSearchCV to find the optimal number of clusters:

```python
from sklearn.model_selection import GridSearchCV
param_grid = dict(kmeans__n_clusters=range(2, 106))
grid_clf = GridSearchCV(pipeline, param_grid, cv=3, verbose=2)
grid_clf.fit(X_train, y_train)
```

Let's look at value for k, and the performance of the resulting pipeline:

```python
>>> grid_clf.best_params_
{'kmeans__n_clusters': 90}
>>> grid_clf.score(X_test, y_test)
0.9844444444444444
```

With k=90 clusters, we get a small accuracy boost, reaching 98.4% accuracy on the test set. Cool!
