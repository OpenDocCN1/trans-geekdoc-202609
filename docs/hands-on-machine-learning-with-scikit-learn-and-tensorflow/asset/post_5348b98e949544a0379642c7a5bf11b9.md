One option is to simply try many combinations of hyperparameters and see which one works best on the validation set (or using K-fold cross-validation). For this, one approach is simply use GridSearchCV or RandomizedCV to explore the hyperparameter-space, as we do in Chapter 2. For this, we need to wrap our models in objects that might mimic Scikit-learn regressors. To create a function that will build and compile a Keras model, given a set of hyperparameters:

```python
def build_model(n_hidden, n_neurons=30, learning_rate=3e-3, input_shape=[8]):
    model = keras.models.Sequential()
    options = {"input_shape": input_shape}
    for layer in range(n_hidden):
        model.add(keras.layers.Dense(n_neurons, activation="relu", **options))
        options = {}
    optimizer = keras.optimizers.SGD(learning_rate)
    model.compile(loss="mse", optimizer=optimizer)
    return model
```

This function creates a Sequential model for univariate regression (only one output neuron), with the given input shape and the number of hidden layers and neurons, and it compiles it using an SGD optimizer configured with the given learning rate. The opts dict is used here to ensure that the first layer is properly given the input shape (that if n_hidden=0, the first layer will be the output layer). It is good practice to provide reasonable defaults to as many hyperparameters as you can, as Scikit-Learn does.

Next, let's create a Keras Regressor based on this build_model function:

```python
keras_reg = keras.wrappers.scikit_learn.KerasRegressor(build_fn=build_model, input_shape=[8])
keras_reg.fit(X_train, y_train, epochs=100, validation_data=(X_valid, y_valid), callbacks=[keras.callbacks.EarlyStopping(patience=10])
mse_test = keras_reg.score(X_test, y_test)
y_pred = keras_reg.predict(X_new)
```

The KerasRegressor is a thin wrapper around the Keras model built using build_model(). Since we did not specify any hyperparameter when creating it, it will just use the default hyperparameters we defined. Now we can use this object like a Scikit-Learn regressor: train it using the fit() method, evaluate it using its score() method, and use it to make predictions using its predict() method. Note that any extra parameter pass to the fit() method will simply pass to the underlying Keras model. Also note that the score will be the opposite of the MSE because Scikit-Learn scores, not losses (i.e., higher should be better).

However, do not actually want to train and evaluate a single model like this, we want to train hundreds of variants and see which one performs best on the validation set. Since there are many hyperparameters, it is preferable to use a randomized search rather than grid search (as we discussed in Chapter 2). Let's try to explore the number of hidden layers, the number of neurons and the learning rate:

```python
from scipy import reciprocal
from sklearn.model_selection import RandomizedSearchCV
```

```python
param_distribs = {
    "n_hidden": [0, 1, 3],
    "n_neurons": np.arange(1, 100),
    "learning_rate": reciprocal(3e-4, 3e-2),
}
```

```python
rnd_search_cv = RandomizedSearchCV(keras_reg, param_distribs, n_iter=10, cv=3)
rnd_search_cv.fit(X_train, y_train, epochs=100,
                  validation_data=(X_valid, y_valid),
                  callbacks=[keras.callbacks.EarlyStopping(patience=10)])
```

As you can see, this is identical to what we did in Chapter 2, with the exception that we pass extra parameters to the fit method: they get related to the underlying Keras models. Note that RandomizedSearch uses K-fold cross-validation, so it does not use X_valid and y_valid. These are used for early stopping.

The exploration may last many hours depending on the hardware, the size of the dataset, the complexity of the model and the value of n_iter and cv. When it is over, you can access the best parameters found, and the trained Keras model like this:

```python
>>> rnd_search_cv.best_params
{'learning_rate': 0.00835264152688094, 'n_hidden': 2, 'n_neurons': 2}
>>> rnd_search_cv.best_score_
-0.318952918828931
>>> model = rnd_search_cv.best_estimator__model
```

You can now use this model, evaluate it on the test set, and if you are satisfied with its performance, deploy it to production. Using randomized search is not too hard, and it works for many fairly problems. When training is slow (e.g., for more complex problems with larger datasets), this approach will only explore a tiny portion of the parameter space. You can partially alleviate this by assessing the search process manually: first run a quick search using wide ranges, then another search using smaller ranges of values centered on the best found during the first, and so on. This will hopefully zoom in to a good set of hyperparameters. However, this is time consuming, and probably not the best use of your time.

Fortunately, there are many techniques to explore a search space more efficiently than randomly. Their core idea is simple: when a region of the space turns out to be good, it should be explored more. This takes care of the "zooming" process for and leads you to better solutions in much less time. Here are a few Python libraries you use to optimize hyperparameters:

- Hyperopt: a Python library for optimizing over all sorts of complex search spaces (including real values as the learning rate, or discrete values as the number of layers).
- Hyperas, or Talos: optimizing hyperparameters for Keras model (the first two are based on Hyperopt).
- Scikit-Optimize (skopt): a general-purpose optimization library. The SearchCV class performs Bayesian optimization using an interface similar to GridCV.
- Spearmint: a Bayesian optimization library.
- Sklearn-Deap: a hyperparameter optimization library based on evolutionary algorithms.

## Number of Hidden Layers

For many problems, you can start with one or two hidden layers and it will work fine (e.g., you can easily reach above 97% accuracy on the MNIST dataset using just one hidden layer with a few neurons, and 98% accuracy using two hidden layers with the total amount of neurons, roughly the same amount of training time). For more complex problems, you can gradually ramp up the number of hidden layers, until you start overfitting the training set. Very complex tasks, such as image classification or speech recognition, typically require networks with dozens of layers (or even hundreds, but not fully connected ones, as we will see in Chapter 14), and they need a huge amount of training data.
