+   - If your model self-normalizes:
  - If it overfits the training set, you should add alpha dropout (and always use early stopping as well). Do not use other regularization methods, or else they would break self-normalization.

+   - If your model cannot self-normalize (e.g., it is a recurrent net or it contains skip connections):
  - You can try ELU (or another activation function) instead of sparser zero out may perform better. Make sure to change the initialization method accordingly (e.g., He for ELU or ReLU).
  - If it is a deep network, you should use Batch Normalization after every hidden layer. If it overfits the training set, you can also try using max-norm or $\ell_2$ regularization.
  - If you need a sparse model, you can use $\ell_1$ regularization (and optionally zero out the tiny weights after training). If you need an even sparser model, you can try FTRL instead of Adam optimization, along with $\ell_1$ regularization. In this case, this will break self-normalization, so you will need to switch to BN if your model is deep.
  - If you need a low-latency model (one that performs lightning-predictions), you may need to use less layers, avoid Batch Normalization, and possibly replace the SELU activation function with the leaky ReLU. Having a sparse model will also help. You may also want to reduce the float precision from 32-bits to 16-bit (or even 8-bits) (see ???).
  - If you are building a risk-sensitive application, or inference latency is not important in your application, you can use MC Dropout to boost performance and get more reliable probability estimates, along with uncertainty estimates.

With these guidelines, you are now ready to train very deep nets! I hope you are now convinced that you can go a very long way using Keras. However, there may come a time when you need to have even more control, for example to write a custom loss function or to tweak the algorithm. For such cases, you will need to use TensorFlow's lower-level API, as we will see in the next chapter.
