
It works, although the predictions are not exactly accurate (e.g., the first prediction is off by close to 40%!). Let's measure regression model's RMSE on the whole trainset using Sikit-Learn's mean_squared_error function:

```
>>> from sklearn.metrics import mean_squared_error
>>> housing_predictions = lin_reg.predict(housing_prepared)
>>> lin_mse = mean_squared_error(housing_labels, housing_predictions)
>>> lin_rmse = np.sqrt(lin_mse)
>>> lin_rmse
6828.198194822
```

Okay, this is better than nothing but clearly a great score: most districts' median_housing_values range between $120,000 and $265,000, a typical prediction error of $68,628 is not very satisfying. This is an example of model underfitting the training data. When this happens it can mean that the features do not provide enough information to make good predictions, or that the model is not powerful enough. As we saw in the previous chapter, the main ways to fix underfitting are to select a more powerful model, to tune the training algorithm with better features, or to reduce the constraints on the model. This model is not regularized, so this rules out the last option. You could add more features (e.g., the log of the population), but let's try a more complex model to see how it does.

Let's train a DecisionTreeRegressor. This is a powerful model, capable of finding complex nonlinear relationships in the data (Decision Trees are presented in more detail at Chapter 6). The code should look similar to this:

## Fine-Tune Your Model

When you have no idea what value should have, a simple approach is to try powers of 10 (or a smaller number if you want). Instead, use Scikit-Learn's GridSearchCV to search for all combinations. All you need to do is tell it as shown in this example:

```python
from sklearn.model_selection import GridSearchCV

param_grid = {
  'n_estimators': [3, 10, 30],
  'max_features': [2, 4, 6, 8],
  'bootstrap': [False],
}

forest_reg = RandomForestRegressor()

grid_search = GridSearchCV(forest_reg, param_grid, cv=5,
  scoring='neg_mean_squared_error',
  return_train_score=True)

grid_search.fit(housing_prepared, housing_labels)
```

All in all, the grid search will explore 12 + 6 = 18 combinations of RandomForest, and it will train each model five times (using five-fold validation). In other words, all in all, there will be 18 x 5 = 90 rounds of training! It may take a long time, but when it is done you get the best combination of parameters like this:

```
>>> grid_search.best_params_
{'max_features': 8, 'n_estimators': 30}
```

> 8 and 30 are the maximum values that were evaluated, you should probably try again with higher values, since the score may continue to improve.

You can also get the best estimator directly:

```
>>> grid_search.best_estimator_
RandomForestRegressor(bootstrap=True, criterion='mse', max_depth=None, max_features=8, max_leaves=None, min_impurity_decrease=0.0, min_impurity_split=None, min_samples_leaf=1, min_samples_split=2, min_weight_leaf=0.0,
n_estimators=30, n_jobs=None, oob_score=False, random_state=None,
verbo=0, warm_start=False)
```

If GridSearch is initialized with refit=True (which is the default), then it finds the best estimator using cross-validation, it retrains it on the whole training set. This is usually a good idea feeling that more data will likely improve your performance.
