
# Interleaving Lines From Multiple Files

First, let's suppose you loaded the California housing dataset, you shuffled it (unless it was already), split it into a training set, a validation set and a test set, then you split each into many CSV files that each look like this (each row contains 8 input features plus the target median house value):

| MedInc,HouseAge,AveAoms,AveBedsrms,Pop,AveOcc,Lat,Long,MedianHouseValue |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 3.5214 |15.0349 |8.91065 |14.7 |1.6599 |37.63|-122.43 |1.442 |
| 5.3275 |5.0 |6.9800 |0.9910 |3.463 |3.4433 |33.69|-117.39 |1.687 |
| 3.1290 |7.5423 |1.5915 |1328.0 |2.2508 |38.44|-122.98 |1.621 |

Let's suppose train_filepaths contains the list of file paths (and you also have valid_filepaths and test_filepaths):

```python
>>> train_filepaths
['datasets/housing/my_train_00.csv', 'datasets/housing/my_train_01.csv', ...]
```

Now create a dataset containing only these files:

```python
filepath_dataset = tf.data.Dataset.list_files(train_filepaths, seed=42)
```

By default, the list_files() returns a dataset that shuffles the file paths. In general this is a good thing, but you can set shuffle=False if you do not want that, for some reason.

Next, we can use the interleave() to read from 5 lines at a time and interleave them (skipping the first line of each file, which is the header row), using the skip() method:

```python
n_readers = 5
dataset = filepath_dataset.interleave(
    lambda filepath: tf.data.TextLineDataset(filepath).skip(1),
    cycle_length=n_readers
)
```

The interleave() method will create a dataset that pulls 5 file paths from the filepath_dataset, and for each one it will call the function we give (a lambda in this example) to create a new TextLineDataset. It will cycle through these 5 datasets, reading one line at a time until all datasets are out of items. Then it will get the next 5 file paths from the filepath_dataset, and interleave them same way, and so on until it runs out of paths.

![](img/0684d2da98e09085c0a622d4fd69aaad_433_0.png)

For interleaving to work best, it is preferable to have files of identical length, or else the end of the longest files will not be interleaved.

By default, interleave() does not use parallelism, it reads one line at a time from each file, sequentially. However, if you want it to actually read files in parallel, you can set the num_parallel_calls argument to the number of threads you use. You can set it to tf.data.experimental.AUTOTUNE let TensorFlow choose the right number of threads dynamically based on the available CPU, this is an experimental feature for now). # Preprocessing the Data

Let's implement a small function that will perform this preprocessing:

```python
X_mean, X_std = [..] # mean and scale of each feature in the training set
n_inputs = 8
```

```python
def preprocess(line):
    defs = [0.] * n_inputs + [tf.constant([], dtype=tf.float32)]
    fields = tf.stack(tf.io.decode_csv(line, record_defaults=defs))
    x = tf.stack(fields[:-1])
    y = tf.stack(fields[-1:])
    return (x - X_mean) / X_std

Let's walk through this code:

- First, assume that we have precomputed the mean and standard deviation of each feature in the training set. X_mean and X_std are 1D tensors (or NumPy arrays) containing 8 values, one per input feature.
- The preprocess() function takes one CSV line and parses it. For this, it uses the tf.io.decode_csv() function, which takes two arguments: the first is the line to parse, and the second is an array containing the default value for each column. This tells TensorFlow not only the default for each column, but also the number of columns and the type of each column. In example, we tell it that all features are floats and missing values are handled by providing an empty array tf.float32 as the default value for the last column (the target): this tells TensorFlow that there is no default value, so it will raise an exception if it encounters a missing value.
- The decode_csv() function returns a list of scalar tensors (per column) but we need to return 1D tensors. We call tf.stack() on all tensors except the last one (the target): this will stack tensors into a 1D array. We then do the same for the target value (this makes it 1D tensor, than a scalar tensor).
- Finally, we scale the input features by subtracting the feature means and dividing by the feature deviations, and we return a tuple containing the scaled features and the target.

Let's test this preprocessing function:

```python
>>> preprocess(b'4.2083,44.0,5.3232,0.8171,04.2,2.3770,33.73,-122.2,2.782')

<tf.Tensor: shape=(1,), dtype=float32, array([2.782]), numpy=True)>
```

We can now apply this preprocessing function to the dataset.

# Putting Everything Together

To make the code readable, let's put together everything we have discussed so far into a smaller helper function: it will create and return a dataset that efficiently load California data from multiple CSV files, then shuffle it, and process it (see Figure 13-2):

```python
def csv_reader_dataset(filepaths, repeat=None, n_readers=5,
    n_threads=None, shuffle_buffer_size=10000,
    n_parse_threads=5, batch_size=32):
    dataset = tf.data.list_files(filepaths).repeat(repeat)
    dataset = dataset.interleave(lambda filepath: tf.data.TextLineDataset(filepath).skip(1),
        cycle_length=n_readers, num_parallel_calls=n_threads)
    dataset = dataset.shuffle(shuffle_buffer_size)
    dataset = dataset.map(preprocess, num_parallel_calls=n_parse_threads)
    dataset = dataset.batch(batch_size)
    return dataset.prefetch(1)
```

Everything makes sense in this code, except the very last line (prefetch(1)), which is actually quite important for performance.

# Prefetching

By calling prefetch(1) at the end, we are creating a dataset that will do its best to always be one batch ahead. In other words, while our algorithm is working on one batch, the dataset will already be working in parallel on getting the next batch ready. This can improve performance dramatically. If we also ensure that loading and preprocessing are multithreaded (by setting `num_parallel_calls` when calling `interleave()` and `map()`), we can exploit multiple cores on the CPU and hopefully prepare one batch of data shorter than running a training step on the GPU: this way the GPU will be almost 100% utilized (except for the data transfer time from the CPU to the GPU), and training will run faster.

> In general

# Without prefetching

| CPU | Prepare 1 | Prepare 2 | Prepare |
| :--- | :--- | :--- | :--- |
| GPU | Use 1 | Use 2 | Time |

# With Prefetching

| CPU | Prepare 1 | Prepare 2 | Prepare 3 | Prepare 4 |
| :--- | :--- | :--- | :--- | :--- |
| GPU | Use 1 | Use 2 | Use 3 |

# With Prefetching + Multithreaded Loading & Preprocessing

| CPU Thread 1 | Prep 1 | Prep 2 | Prep 3 | Prep 4 | Prep 5 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| CPU Thread 2 | | | | | |
| GPU | Use 1 | Use 2 | Use 3 | Use 4 |
