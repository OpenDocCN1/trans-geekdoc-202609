
```
[...] # build and compile the model
checkpoint_cb = keras.callbacks.ModelCheckpoint("my_keras_model.h5")
history = model.fit(X_train, y_train, epochs=10, callbacks=[checkpoint_cb])
```

Moreover, if you use a validation during training, you can set save_best_only=True when creating the ModelCheckpoint. In this case, it will only save your model when its performance on the validation set is the best so far. You do not need to worry about training too long and overfitting the training set; simply restore the last model saved after training, and this will be the best model on the validation. This is a simple way to implement early stopping (introduced in Chapter 4):

```
checkpoint_cb = keras.callbacks.ModelCheckpoint("my_keras_model.h5",
save_best_only=True)
history = model.fit(X_train, y_train, epochs=10,
                   validation_data=(X_valid, y_valid),
                   callbacks=[checkpoint_cb])
model = keras.models.load_model("my_keras_model.h5") # rollback to best model
```

Another way to implement early stopping is simple to use the EarlyStopping callback. It will interrupt when it measures no progress on the validation set for a number of epochs (defined by the patience argument), and it will optionally rollback to the best model. You can combine both callbacks to save checkpoints of your model (in case your crashes) and actually interrupt training early when there is no more progress (avoid wasting time and resources):

```
early_stopping_cb = keras.callbacks.EarlyStopping(patience=10,
                              restore_best_weights=True)
history = model.fit(X_train, y_train, epochs=100,
                   validation_data=(X_valid, y_valid),
                   callbacks=[checkpoint_cb, early_stopping_cb])
```

The number of epochs can be set to a large value since training will automatically stop when there is no more progress. Moreover, there is no need to restore the best model saved in this case since the EarlyStopping callback will keep track of the best weights and restore them for you at the end of training.

There are many other callbacks available in the keras.callbacks package. See https://keras.io/callbacks/

![](img/0684d2da98e09085c0a622d4fd69aaad_337_0.png)

If you need extra control, you can easily write your own custom callbacks. The following custom callback will display the ratio between the validation loss and the training loss during training (e.g., to detect overfitting):

```
class PrintTrainRatioCallback(keras.callbacks.Callback):
    def on_train_end(self, epoch, logs):
        print("\ntrain: {:.2f}".format(logs["val_loss"] / logs["loss"]))
```

As you might expect, you can implement train_begin(), on_train_end(), on_epoch_begin(), on_epoch_begin(), on_batch_end() and on_batch_end(). Moreover, callbacks can also be used during evaluation and predictions, should you ever need them (e.g., for debugging). In this case, you should implement on_test_begin(), on_test_end(), on_test_batch_begin(), or on_test_batch_end() (called by evaluate()), or on_predict_begin(), on_predict_end(), on_predict_batch_begin(), or on_predict_batch_end() (called by predict()).

Now let's take a look at one more tool you should definitely have in your toolbox using tf.keras.TensorBoard.

# Visualization Using TensorBoard

TensorBoard is a great interactive visualization tool that you can use to view the learning curves between multiple runs, visualize the computation graph, analyze training statistics, view images generated by your model, visualize complex multidimensional data projected out to 3D and automatically clustered for you, and more! This tool is installed automatically when you install TensorFlow, so you already have it!

To use it, you must modify your program so that it outputs the data you want to visualize in binary logs called event files. Each binary data record is recorded as a summary. The TensorBoard server will monitor the directory, and it will automatically pick up the changes and update the visualizations. this allows you to visualize live data (with a short delay), as well as learning curves during training. In general, you want to point the TensorBoard server to a log directory, and configure your program so that it writes to a different subdirectory every time it runs. This way, the same TensorBoard instance will allow you to visualize and compare data from multiple runs of your program, without getting everything up.

So let's begin by defining the log directory we use for our TensorBoard logs, plus a small function to generate a subdirectory path based on the current date and so, that it is different every run. You might want to include extra information in the log directory name, as hyperparameter values that you are testing, to make it easier to know what you are looking at in TensorBoard:

```
root_logdir = os.path.join(os.curdir, "my_logs")
def get_run_logdir():
    import time
    run_id = time.strftime("run_%Y%m%d-%H_%M-%S")
    return os.path.join(root_logdir, run_id)

```

run_logdir = get_run_logdir() # e.g. './my_logs/run_2019_01_16_11_28_43'
```

Next, the good news is that Keras provides a nice TensorBoard callback:

```
[...] Build and compile model
tensorboard_cb = keras.callbacks.TensorBoard(run_logdir)
history = model.fit(X_train, y_train, epochs=30,
    validation_data=(X_valid, y_valid),
    callbacks=[tensorboard_cb])
```

And that is all there is is! It could hardly be easier to use. If you run this code, the TensorBoard callback will take care of creating the log directory for you (along with its parent directories if needed), and during training it will create event files and summaries to them. After running the program second time (perhaps changing some hyperparameter), you will end up with a directory structure similar to this one:

- - my_logs
  - run_2019_01_16_51_02
    - events.out.tfevents.154728
  - run_2019_01_16_56
    - events.out.tfevents.154729

Next you need to start the TensorBoard server. If your shell cannot find the tensorboard script, then you must update your PATH environment variable so that it contains the directory in which the script is installed (otherwise, you can just replace tensorboard with python3 -m board.main).

```
$ tensorboard --logdir=./my_logs --port=6006 (Press CTRL+C to quit)
TensorBoard 2.0.0 at http://localhost:6006
```

Finally, open a browser to http://localhost:6006. You should see TensorBoard’s interface. Click the SCALARS tab to view the learning curves (see Figure 10-16). Notice that the training loss went down nicely during both, but the second run went down faster. Indeed, we used a larger learning rate by setting optimizer=keras.optimizers.SGD(lr=0.05) instead of optimizer=sgd, which defaults to 0.001.

Unfortunately, at the time of writing, no other data is exported by the TensorBoard callback, but this will probably be fixed by the time you read these lines. In TensorFlow 1, this callback exported the computation graph and many useful statistics: `help(keras.callbacks.TensorBoard)` to see all the options.
