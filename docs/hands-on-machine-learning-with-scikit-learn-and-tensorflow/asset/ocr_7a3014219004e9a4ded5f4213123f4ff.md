Bootstrapping introduces a more diversity in the subsets that is trained on, so bagging ends with a slightly higher bias than pasting, but this also means that predictors end up being less correlated than the ensemble's variance is reduced. Overall, bagging often results in better models, which explains why it is generally preferred. However, if you have spare time and CPU power you can use cross-validation to evaluate both bagging and pasting and select the one that works.

# Out-of-Bag Evaluation

With bagging, some instances may be sampled several times for any given predictor, while others may not be sampled at all. By default BaggingClassifier samples training instances with replacement (bootstrap=True), where m is the size of the training set. This means that only 63% of the training instances are sampled for each predictor. The remaining 37% of the training instances that are not sampled are called out-of-bag (oob) instances. Note that they are not the same 37% for all predictors.

Since a predictor sees the oob instances during training, it can be evaluated on these instances, without the need for a separate validation set. You can evaluate the ensemble by averaging out the oob evaluations of each predictor.

In Scikit-Learn, you can set oob_score=True when creating a BaggingClassifier to request an oob evaluation after training. This code demonstrates how this result is available through the oob_score_ variable:

```
>>> bag_clf = BaggingClassifier(
    DecisionTreeClassifier(), n_estimators=500,
    bootstrap=True, n_jobs=-1, oob_score=True)
...
...
>>> bag_clf.fit(X_train, y_train)
```
