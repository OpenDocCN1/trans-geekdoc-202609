name: "Al"
id: 123
email: "a@b.com"

```
>>> person.name # read a field
"Al"
>>> person.name = "Alice" # modify a field
>>> person.email[0] # repeated fields can be accessed like arrays
"a@b.com"
>>> person.email.append("c@d.com") # add an email address
>>> s = person.SerializeToString() # serialize the object to a byte string
>>> s
b'\x05\x10\x1a\x07@b.com\xa\x07@d.com'
>>> person2 = Person() # create a new Person
>>> person2.ParseFromString(s) # parse the byte string (27 bytes)
27
>>> person == person2 # now they are equal
True
```

In short, we import the class generated by protobuf, we create an instance and play with it, visualizing, reading and writing some fields, then we serialize using the SerializeToString() method. This is the data that is ready to be saved or transmitted over the network. When reading or receiving this binary data, we can parse it using the ParseFromString() method, and we get a copy of the object that was serialized.

We could save the serialized object to a TFRecord file, then we could load and parse it: everything would work fine. SerializeToString() and ParseFromString() are not TensorFlow operations (neither are the other operations in this code), so they cannot be included in a TensorFlow Function (except wrapping them in a .py_function()) which would make the code slower and less portable, as we saw in Chapter 12. Fortunately, TensorFlow does include special tobuf definitions for which provides parsing operations.

# TensorFlow Protobuf

The main protobuf typically used in a TFRecord file is the Example protobuf, which represents one instance in a dataset. It contains a list of named fields, where each feature can be a list of byte strings, a list of floats or a list of integers. Here is the protobuf definition:

```
syntax = "proto3"
message BytesList { repeated bytes value = 1; }
message FloatList { repeated float value = 1 [packed = true]; }
message Int64List { repeated int64 value = 1 [packed = true]; }
```
