
It is a bit ugly due to the different indices, but all it does is calculate the weighted sum of all the inputs, plus the bias term.

Equation 14-1. Computing the output of a neuron in a convolutional layer

```
$z_{i,j,k} = b_k + \sum_{u=0}^{f_h-1} \sum_{v=0}^{f_w-1} f_{u,v,k}' \cdot x_{i+u, j+v,k} \quad \text{with} \quad i' = i \times s_h + u \quad j' = j \times s_w + v$
```

- * $z_{i,j,k}$ is the output of the neuron located in row $i$, column $j$ in convolutional layer (layer $l$).
- * As explained, $s_h$ and $s_w$ are the vertical and horizontal strides, $f_h$ and $f_w$ are the height and width of the receptive field, and $f_r$ is the height of the feature maps in the previous layer (layer $l-1$).
- * $x_{u',v',k}'$ is the output of the neuron located in row $l-1$, column $v'$, feature map $k'$ (or channel $k'$ if the previous layer is the input layer).
- * $b_k$ is the bias term for feature map $k$ (in layer $l$). You can think of it as a knob that tweaks the overall brightness of the feature map $k$.
- * $w_{u,v,k}$ is the connection weight between any neuron in feature map $k$ of the layer $l$ and its input at row $u$, column $v$ (relative to the neuron's receptive field), and feature map $k'$.

# TensorFlow Implementation

In TensorFlow, each image is typically represented as a 3D tensor of shape [height, width, channels]. A mini-batch is represented as a 4D tensor of shape [min-batch-size, height, width, channels]. The weights of a convolutional layer are represented as a 4D tensor of shape $[f_h, f_w, f_{in}, f_{out}]$. The biases of a convolutional layer are simply represented as a 1D tensor of shape $[f_{out}]$.

Let's look at an example. The following code loads two sample images

```python
from sklearn.datasets import load_sample_image

# Load sample images
china = load_sample_image("china.jpg") / 255
flower = load_sample_image("flower.jpg") / 255
images = np.array([china, flower])
batch_size, height, width, channels = images.shape
```

```python
# Create 2 filters
filters = np.zeros((7, 7, channels, 2), dtype=np.float32)
filters[:, :, 3, 0] = 1 # vertical line
filters[:, :, 3, 1] = 1 # horizontal line
```

```python
outputs = tf.nn.conv2d(images, filters, strides=1, padding="SAME")

plt.imshow(outputs[0,:,:,1], cmap='gray') # plot 1 image's 2nd feature map
plt.show()
```

Most of this code is self-explanatory, but the tf.nn.conv2d() line serves a bit of explanation:

- images is the input mini-batch (a 4D tensor, as explained earlier).
- filters is the set of filters to apply (also a 4D tensor, as explained earlier).
- strides is equal to 1, but it could also be a 1D array with 4 elements, where the two central elements are the vertical and horizontal strides ($s_v$ and $s_h$). The first and last elements currently be equal to 1. One day may be used to specify a stride (to skip some instances) and a channel stride (to skip some of the previous layer's feature maps or channels).
- padding must be either "VALID" or "SAME":
    - If set to "VALID", the convolutional layer does not use zero padding, and may ignore some rows and columns at the bottom and right of the input image, depending on the stride, as shown in Figure 14-7 (for simplicity, only the horizontal dimension is shown here, but of course the same logic applies to the vertical dimension).
    - If set to "SAME", the convolutional layer uses zero padding if necessary. In case, the number of output neurons is equal to the number of input neurons divided by the stride, rounded up (in this example, 13/5=2.6, rounded up to 3). Then zeros are added as evenly as possible around the inputs.

In this example, we manually defined the filters, but in a real CNN we would normally define filters as trainable variables, the neural net can learn which filters work best, as explained earlier. Instead of manually creating the variables, you can simply use the keras.layers.Conv2D layer:

```python
conv = keras.layers.Conv2D(filters=32, kernel_size=3, strides=1,
padding="SAME", activation="relu")
```

This code creates a Conv2D layer with 32 filters, $3 \times 3$, with a stride of 1 horizontally and vertically), SAME padding, and applying the ReLU activation function to its outputs. As you can see, convolutional layers have quite a few hyperparameters: you must choose the number of filters, their height and width, the strides, and the padding type. Always, you can use cross-validation to find the right hyperparameters, but this is very time-consuming. We will discuss CNN architectures, to give you some idea of what hyperparameter values work best in practice.

# Memory Requirements

Another problem with CNNs is that the convolutional layers require a huge amount of RAM. This is especially true during training, because the reverse ofpropagation requires all the intermediate values computed during the forward pass.

For example, consider a convolutional layer with $5 \times 5$ filters, outputting 200 feature maps of size $150 \times 100$, with stride 1 and SAME padding. If the input is a $150 \times 100$ RGB image (three channels), then the number of parameters is (5 × 5 × 3 + 1) × 200 = 15,200 (the +1 corresponds to the bias terms), which is fairly small compared to a fully connected layer. However, each of the 200 feature maps contains 150 × 100 neurons, each of these neurons needs to compute a weighted sum of 5 × 5 × 3 = 75: thus is a total of 225 million multiplications. Not as a fully connected layer, but still quite computationally intensive. Moreover, if the feature maps are represented as 32-bit floats, the convolutional layer's output will occupy 200 × 150 × 100 × 32 = 96 million bits (12 MB) of RAM. And that's just for one instance! If a training batch contains 100 instances, this layer will use up 1.2 GB of RAM!

During inference (i.e., when making a prediction for a new instance) the RAM occupied by one layer can be released as soon as the next layer has been computed, so you only need much RAM as required by two consecutive layers. While training everything during the forward pass must be preserved for the reverse pass, the amount of RAM needed is (at least) the total amount of RAM required by all layers. If training crashes because of out-of-memory error, you can try reducing the batch size. Or you can use 16-bit floats instead of 32-bit.

# Pooling Layer

Once you understand how convolutional layers work, pooling layers are quite easy to grasp. Their goal is to subsample (i.e., shrink) the image to reduce computational load, memory usage and the number of parameters. Just like convolutional layers, a pooling layer typically works on every input channel, so the output depth is the same as the input depth.

A common type of pooling is max pooling, which takes the maximum value in each receptive field. Figure 14-8 shows a max pooling layer with $2 \times 2$ kernel, stride 2, no padding. For example, in the lower left receptive field in 14-8, the input values are 1, 5, 3, 2, so only the max value, 5, is propagated to the next layer. Because of the stride of 2, the output image has half the height and half the width of the input image (rounded down since we use no padding).

![](img/0684d2da98e09085c0a622d4fd69aaad_467_0.png)

Figure 14-8. Pooling layer ($2 \times 2$ kernel, stride 2, no padding)

![](img/0684d2da98e09085c0a622d4fd69aaad_468_0.png)

Other than reducing computations, memory usage and the number of parameters, a max pooling layer also introduces some level of *invariance* to small translations, as shown in Figure 14-9. We assume that the bright pixels have a lower value than dark pixels, and we consider 3 images $(A, B, C)$ going through a max pooling layer with a $2 \times 2$ kernel and stride 2. Images B and C are the same as image A, shifted by one and two pixels to the right. As you see, the outputs of the max pooling layer for images A and B are identical. This translation invariance means However for image C, the output is different: it is shifted by one pixel to the right (but there is still 75% invariance). By inserting a max pooling layer every few layers in a CNN, it is possible to get some level of translation invariance at a larger scale. Moreover, max pooling also offers a small amount of rotational invariance and a slight scale invariance. Such invariance (even if it is limited) can be used in cases where the prediction should not depend on these details, such as in classification tasks.

- Other kernels we discussed so far had weights, but pooling kernels do not: they are just stateless sliding windows.
