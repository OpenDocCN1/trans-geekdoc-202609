[...] # Same as above, up to the main output layer
output keras.layers.Dense(1)(concat)
aux_output = keras.layers.Dense(1)(hidden2)
model = keras.models.Model(inputs=[input_A, input_B],
outputs=[output, aux_output])

Each output will need its own loss function, as we compile the model we should pass a list of losses (if we pass a single loss, Keras will assume that the loss must be used for all outputs). By default, Keras will compile all these losses and simply add them up to the final loss for training. However, we care more about the main output than the auxiliary output (which is just used for regularization), so it is possible to give the main output's loss a greater weight. Frequently, when compiling the model:

```
model.compile(loss="mse", loss_weights=[0.9, 0.1], optimizer="sgd")
```

Now we train the model, we need to provide labels for each output. In this example, the main output and the auxiliary output should try to predict the same thing, so they should use the same labels. Instead of passing y_train, we need to pass (y_train, y_train) (and the same for y_valid and y_test):

```
history = model.fit(
[X_train_A, X_train_B], [y_train, y_train], epochs=20,
validation_data=(X_valid_A, X_valid_B], [y_valid, y_valid]))
```

When we evaluate the model, Keras will return the total loss, as well as the individual losses:

```
total_loss, main_loss, aux_loss = model.evaluate(
[X_test_A, X_test_B], [y_test, y_test])
```

Similarly, the predict() method will return predictions for each output:

```
y_pred_main, y_pred_aux = model.predict([X_new_A, X_new_B])
```

As you see, you can build any sort of architecture you want quite easily with the Functional API. Let's look at one last way you can build Keras models.

# Building Dynamic Models Using Subclassing API

Both the Sequential API and the Functional API are declarative: you start by declaring layers you need to use and how they should be connected, and only then you start feeding the model data for training or inference. This has advantages: the model can easily be saved, cloned, shared, its structure can be played and analyzed, the framework can infer shapes and check types, so errors can be caught early (i.e., before any data goes through the model). It is also easy to debug, since the whole model is just a static graph of layers. But the flip side is that: it's static. Some models involve varying shapes, conditional branching, and other dynamic behaviors. For such cases, or simply you prefer a more imperative programming style, the Subclassing API is for you.
