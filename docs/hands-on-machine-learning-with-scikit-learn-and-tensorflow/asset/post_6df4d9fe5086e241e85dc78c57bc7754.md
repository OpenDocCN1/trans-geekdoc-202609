
Notice that NumPy uses 64-bit precision by default, while TensorFlow uses 32-bit. This is because 32-bit precision is generally more enough for neural networks, plus it runs faster and uses less RAM. So when you create a tensor from a NumPy array, make sure to set dtype=tf.float32.

# Type Conversions

Type conversions can significantly hurt performance, and they can easily go unintended when they are done automatically. To avoid this, TensorFlow does not perform any type conversions automatically: it raises an exception if you try to execute an operation on tensors in incompatible types. For example, you cannot add a float tensor and an integer tensor, and you cannot even add a 32-bit float and a 64-bit float:

```
>>> tf.constant(2.0) + tf.constant(40)
Traceback[...InvalidArgumentError: expected to be a float...]
>>> tf.constant(2.0) + tf.constant(40, dtype=tf.float64)
Traceback[...InvalidArgumentError: expected to be a double...]
```

This may be a bit of annoying, but remember that it's for your good cause! And you can use tf.cast() when you need to convert tensors:

```
>>> t2 = tf.constant(40, dtype=tf.float64)
>>> tf.constant(2.0) + tf.cast(t2, tf.float32)
<tf.Tensor: id=136, dtype=float32, numpy=42.0>
```

# Variables

So far, we have used constants: as their name suggests, you cannot modify them. The weights in a neural network need to be tweaked by backpropagation, and other parameters may also need to change over time (e.g., a momentum optimizer tracks grad parameters). What is a variable:

```
>>> v = tf.Variable([[1, 2, 3], [4, 5, 6]])
>>> v
<tf.Variable 'Variable='0' shape=(2, 3) dtype=int32, numpy=array([[1, 2, 3], [4, 5, 6]])>
```

A variable acts much like a constant tensor: you can perform the same operations with it, like with NumPy as it is just like what you picks. It can also be modified in place using the assign() method (or assign_add() or assign_sub()) which increments or decrements the variable by the given value). You can also modify individual cells (or slices), using the cell's (or slice's) assign() method (direct item assignment will not work), or using the scatter_update() and scatter_nd_:

```
v.assign(2 *) # = [[2, 4, 6], [8, 10, 12]]
v[0, 1].assign(42) # = [[2, 42, 6], [8, 10, 12]]
```

![](img/0684d2da98e09085c0a622d4fd69aaad_399_0.png)

```
v[:, 2].assign([0, 1.]) # = [[2., 42., 0.], [8., 10., 1.]]
v.scatter_nd_update(indices=[[0, 0], [1, 2]], updates=[100., 200.])
# = [[100., 42., 0.], [8., 10., 200.]]
```

In practice you will rarely have to create variables manually, since Keras provides an add_weight() method that will take care of it as we see. Moreover, model parameters will generally be updated directly by the optimizers, so you will rarely need to update variables manually.

# Other Data Structures

TensorFlow supports several other data structures, including the following (please see the notebook or ??? for more details):

- Sparse tensors (tf.SparseTensor) efficiently represent tensors containing mostly Os. The tf.sparse package contains operations for sparse tensors.
- Tensor arrays (tf.TensorArray) are lists of tensors. They have a fixed size by default, but can be made dynamic. All tensors must have the same shape and data type.
- Ragged tensors (tf.RaggedTensor) represent lists of lists of tensors, where every tensor has the same shape and data type. The tf.ragged package contains operations for ragged tensors.
- String tensors are regular tensors of tf.string. These actually represent by strings, not Unicode strings, so if you create a string using a Unicode string (e.g., a regular Python 3 string like "café") then it will be encoded to UTF-8 automatically (e.g., b\xc3\xa9"). Alternatively, you can represent Unicode strings using type=int32, where each item represents a Unicode codepoint (e.g., [99, 97, 102, 233]). The tf.string package (with s) consists of byte strings and Unicode strings and to convert into one the other).
- Sets are just represented as regular tensors (or sparse tensors) containing one or more sets, and you can manipulate them using operations from the tf.sets package.
- Queues, including First In, First Out (FIFO) queues (FIFOQueue), queues that can prioritize some items (PriorityQueue), queues that shuffle them (Random ShuffleQueue), and queues that can batch items of different shapes by padding (PaddingQueue). These classes are all in the tf.queue package.

With tensors, operations, variables and various data structures at your disposal, we are now ready to customize your models and training algorithms!

# Customizing Models and Training Algorithms

Let’s start by creating a custom loss function, which is a simple and common use case.

## Custom Loss Functions

Suppose you want to train a regression model, but your training set is a bit noisy. Of course, you might start trying to clean up your dataset by removing or fixing the outliers, but it turns out to be insufficient, the dataset is still noisy. Which loss function should you use? The mean squared error might penalize large errors too much, so your model will end being imprecise. The mean absolute error would not penalize outliers as much, but training might take a while to converge and the trained model might not be very precise. This is probably a good time to use the Huber loss (introduced in Chapter 10 instead of the old MSE. The Huber loss is not currently part of the official Keras API, but it is available in tf.keras (just use an instance of the keras.losses.Huber class). Let’s pretend it’s not there: implementing it is easy as pie! Just create a function that takes the labels and predictions as argument, and use TensorFlow to compute any instance’s:

```
def huber_fn(y_true, y_pred):
    error = y_true - y_pred
    is_small = tf.abs(error) < 1
    squared_loss = tf.square(error) / 2
    linear_loss = tf.abs(error) * 0.5
    return tf.where(is_small, squared_loss, linear_loss)
```

> For better performance, use a vectorized implementation, as in this example. Moreover, if you want to benefit from TensorFlow’s graph features, you should use only TensorFlow operations.

![](img/0684d2da98e09085c0a622d4fd69aaad_401_0.png)

It is also preferable to return a tensor, rather than returning the mean. Next, you can use this loss when you compile:

```python
model.compile(loss=huber_fn, optimizer="nadam")
```

And that’s it! For each batch during training, Keras will call the huber_fn() function, and use it to track the total loss.

# Saving and Loading Models That Contain Custom Components

Saving model containing custom loss actually works fine, as Keras saves the name of the function. However, whenever you load it, you need to provide a dictionary that maps names to the objects. More generally, when you load a model containing custom objects, you need to specify:

With the current implementation, any error between -1 and 1 is considered "small". But if we want a different threshold? One strategy is to create a function that creates a loss function:

```python
def create_huber(threshold=1.0):
    def huber_fn(y_true, y_pred):
        error = y_true - y_pred
        is_small_error = tf.abs(error) < threshold
        squared_loss = tf.square(error) / 2
        linear_loss = threshold * tf.abs(error) - threshold**2 / 2
        return tf.where(is_small_error, squared_loss, linear_loss)
    return huber_fn
```

```python
model.compile(loss=create_huber(2.0), optimizer="nadam")
```

Unfortunately, when you save the model, this will not be saved. This means you will have to specify the threshold when loading the model (note the name to use is "huber_fn", which is the name of the function we give Keras, not the name of the function we created):

```python
model = keras.models.load_model("my_model_with_a_custom_loss.h5")
```

You can do this by subclassing the keras.losses.Loss class, and implementing its get_config() method:

```python
class Huber(keras.losses.Loss):
    def __init__(self, threshold=1.0, **kwargs):
        self.threshold = threshold
        super().__init__(**kwargs)
    def call(self, y_true, y_pred):
        error = y_true - y_pred
        is_small_error = tf.abs(error) < self.threshold
        squared_loss = tf.square(error) / 2
        linear_loss = self.threshold * tf.abs(error) - self.threshold**2 / 2
        return tf.where(is_small_error, squared_loss, linear_loss)
    def get_config(self):
        base_config = super().get_config()
        return {**base_config, "threshold": self.threshold}
```
