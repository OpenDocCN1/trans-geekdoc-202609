# Object Detection

The task of classifying and localizing multiple objects in an image is called object detection. Until a few years ago, a common approach was to use a CNN that was trained to classify and locate a single object, then slide it across the image, as shown in Figure 14-24. In this example, the image was chopped into a 6 × 8 grid, and we show a CNN (the thick black rectangle) sliding across all 3 × 3 regions. The CNN was looking at the top left of the image, it it detected that some rose again when it shifted one step to the right. In the next step, it started detecting part of the top-most rose, and then detected it again when it shifted one more to the right. You would then continue to slide the CNN through the whole image, looking at all 3 × 3 regions. Moreover, since objects can have varying sizes, you would also slide the CNN across regions of different sizes. For example, once you are done with the 3 × 3 regions, you might want to slide the CNN across all 4 × 4 regions as well.

![](img/0684d2da98e09085c0a622d4fd69aaad_497_0.png)

Figure 14-24. Detecting Multiple Objects by Sliding CNN Across the Image

This technique is fairly straightforward, as you can see it will detect the same object multiple times, at slightly different positions. Post-processing will then be needed to get rid of all the unnecessary bounding boxes. A common approach for this is called **non-max suppression**:

- You need to add an *extra oddness* output to your CNN, to estimate the probability that a flower is indeed present in the image (alternatively, you could add a "no-flower" class, but this usually does not work well). It must use the sigmoid activation function and you train it using the *binary_crossentropy* loss. Then get rid of all the bounding boxes for which the oddness score is below some threshold: this will drop all all the bounding boxes that don't actually contain a flower.

- Second, find the bounding box with the highest confidence score, and get rid of all the other bounding boxes that overlap a lot with it (e.g., with an IoU greater than 60%). For example, in **Figure 14-24**, the bounding box with the max score is the thick bounding box over the top-most rose (the oddness score is represented by the thickness of the bounding boxes). The other bounding box over that rose overlaps a lot with the max bounding box, so we will get rid of it.

- Third, repeat step two until there are no bounding boxes to get rid of.

This simple approach to object detection works pretty well, but it requires running the CNN many times, so it is quite slow. Fortunately, there is a much faster way to slide a CNN across an image using a Fully Convolutional Network.

# Fully Convolutional Networks (FCNs)

The idea of FCNs was first introduced in a 2015 paper by Jonathan Long et al., for semantic segmentation (the task of classifying every pixel in an image according to the class it belongs to). They pointed out that you could replace the dense layers at the top of a CNN by convolutional layers. To understand this, let's look at an example: a dense layer with 200 neurons on top of a convolutional layer that outputs 100 feature maps, each of size 7 x 7 (this is the feature map size). Each neuron will compute a weighted sum of all 100 x 7 activations from the convolutional layer (plus a bias term). Now we see what happens if we replace the dense layer with a convolutional layer using 200 filters, 7 x 7, and with VALID padding. This layer will output 200 feature maps, each 1 x 1 (since the kernel is exactly the size of the input and we are VALID padding). In other words, it will output 200 numbers, just like the dense layer, and if you look closely at the computations performed by a convolutional layer, you will notice that these numbers will be precisely the same as the dense layer produced. The only difference is that the dense layer's output was a tensor of shape [batch size, 200] while the convolutional layer will output a tensor of shape [batch size, 1, 200].

To convert a dense layer to a convolutional layer, the number of filters in the convolutional layer must be equal to the number of units in the dense layer, the filter size must be equal to the size of the input feature maps, and you must use VALID padding. The stride may be set to 1 or more, and we will see shortly.

Why is this important? Well, while a dense layer expects a specific input size (since it has one weight per input feature), a convolutional layer will happily process images of any size⁴(however, it does expect its inputs to have a specific number of channels, since each kernel contains a different set of weights for each input channel). Since an FCN contains only convolutional layers can be trained and executed on images of any size!
