# Momentum Optimization

Imagine a bowling rolling down a gentle slope on a smooth surface: it will start slowly, but it will quickly pick up momentum until it reaches terminal velocity (if there is some friction or air resistance). This is the very idea behind Momentum optimization, proposed by Boris Polyak in 1964.{12} In contrast, Gradient Descent will simply take regular steps down the slope, so it will take much time to reach the bottom.

Recall that Gradient Descent simply updates the weights $	heta$ by directly subtracting the gradient of the cost function $j(\theta)$ with regard to the weights $(
abla_{	heta}(j))$ multiplied by the learning rate $\eta$. The equation is: $	heta = \theta - \eta\nabla_{	heta}(j)$. It does not care about what the earlier gradients were. If the local gradient is timid, it goes very.

Momentum optimization carries a great deal about what previous gradients were: at each iteration, it subtracts the local gradient from the momentum vector $\mathbf{m}$ (multiplied by the learning rate $\eta$), and it updates the weights by adding this momentum vector (see Equation 11-4). In other words, the gradient is used for acceleration, not for speed. To simulate some friction mechanism and prevent the momentum from growing too large, the algorithm introduces a new hyperparameter $eta$, simply called *momentum*, which must be set between 0 (high friction) and 1 (no friction). A typical momentum velocity is 0.9.

+   1. $m \leftarrow m - \eta\nabla_{\theta}(j)$
2. $\theta \leftarrow \theta + \mathbf{m}$

You can easily verify that if the gradient remains constant, the terminal velocity (i.e., the maximum size of the weight updates) is equal to that gradient multiplied by the learning rate $\eta$ multiplied by $\beta$ (ignoring the sign). For example, if $\beta = 0.9$, then the terminal velocity is equal to 10 times the learning rate, so Momentum optimization ends up 10 times faster than Gradient Descent! This allows Momentum optimization to escape plateaus much faster than Gradient Descent.
