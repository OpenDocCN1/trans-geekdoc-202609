That wasn't too hard! Let's look at the resulting theta:

array([[4.21509616],
      [2.77011339]])

Hey, that's exactly what the Normal Equation found! Gradient Descent worked perfectly. But if you used a different learning rate eta? Figure 4-8 shows the first 10 steps of Gradient Descent using three different learning rates (the dashed line represents the starting point).

![](bbox=[0.14, 0.25, 0.859, 0.465])

Figure 4-8. Gradient Descent with varying learning rates

On the left, the learning rate is too low: the algorithm eventually reach the solution, but it will take a time. In the middle, the learning rate looks pretty good: just a few iterations, it has already converged to the solution. On the right, the learning rate is too high: the algorithm diverges, jumping all over the place and actually getting further and away from the solution at every step.

To find a good learning rate, you can use grid search (Chapter 2). However, you may want to limit the number of iterations so that grid search can eliminate elements that take too long to converge.

You may wonder how to set the number of iterations. If it is too low, you will still be far away from the optimal solution when the algorithm stops, but if it is too high, you will waste time when the parameters do not change anymore. A simple solution is to set a very large number of iterations but interrupt the algorithm when the gradient vector $e$ becomes tiny—that is, when its norm becomes smaller than a tiny number $\epsilon$ (called the tolerance)—because this happens when Gradient Descent has (almost) reached the minimum.
