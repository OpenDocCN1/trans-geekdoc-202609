There are also many use cases in which you may want to have multiple outputs:

- The task may demand it, for example you may want to locate and classify the main object in a picture. This is both a regression task (finding the coordinates of the object's center, as well as its width and height) and a classification task.
- Similarly, you may have multiple independent tasks to perform based on the same data. Sure, you could train one neural network per task, but in many cases you will get better results on all tasks by training a single neural network with one output per task. This is because the neural network can learn features in the data that are useful across tasks.
- Another use case is as regularization technique (i.e., a training constraint whose objective is to reduce overfitting and improve the model's ability to generalize). For example, you may want to add some auxiliary outputs in a neural network architecture (see Figure 10-15) to ensure that the underlying part of the network learns something useful on its own, without relying on the rest of the network.

# Building Dynamic Models Using Subclassing API

Both the Sequential API and the Functional API are declarative: you start by declaring layers you need to use and how they should be connected, and only then you start feeding the model data for training or inference. This has advantages: the model can easily be saved, cloned, shared, its structure can be played and analyzed, the framework can infer shapes and check types, so errors can be caught early (i.e., before any data goes through the model). It is also easy to debug, since the whole model is just a static graph of layers. But the flip side is that: it's static. Some models involve varying shapes, conditional branching, and other dynamic behaviors. For such cases, or simply you prefer a more imperative programming style, the Subclassing API is for you.

Simply subclass the Model class, create the layers you need in the constructor, and use them to perform the computations you want in the call() method. For example, creating instance of the following WideAndDeepModel class gives us an equivalent model to the one we just built with the Functional API. You can then compile it, use it to make predictions, exactly like we did.

```python
class WideAndDeepModel(keras.models.Model):
    def __init__(self, units=32, activation="relu", **kwargs):
        super().__init__(**kwargs) # Same as above, up to the main output layer
        self.dense1 = keras.layers.Dense(units, activation)
        self.dense2 = keras.layers.Dense(units, activation)
        self.concat = keras.layers.Concatenate()
        self.output = keras.layers.Dense(1)
        self.aux_output = keras.layers.Dense(1)

    def call(self, inputs):
        input_A, input_B = inputs
        hidden1 = self.dense1(input_A)
        hidden2 = self.dense2(input_B)
        concat = self.concat([hidden1, hidden2])
        main_output = self.output(concat)
        aux_output = self.aux_output(hidden2)
        return main_output, aux_output
```

```python
model = WideAndDeepModel()
```

This example looks very much like Functional API, except we do not need to create the layers; we separate the creation of the layers from their usage in the call() method. However, this flexibility comes at a cost: your architecture is hidden within the call() method, so Keras cannot inspect it, it cannot save or clone, and when you call summary() method you only get a list of layers. Unless you really need that flexibility, you should probably stick to the Sequential or Functional API.

Keras models can be used just like regular layers, so you can compose them to build complex architectures.

# Saving and Restoring a Model

Saving a trained Kerash5 is as simple as it gets:

```python
model.save("my_keras_model.h5")
```

Keras will save the model's architecture (including every layer's hyperparameters) and the value of all the model parameters for every layer (e.g., weights and biases), using the HDF5 format. It also saves the optimizer (including its hyperparameters and state it may have).

You will typically have a script that trains a model and saves it, and one or more scripts (or web services) that load the model and use it to make predictions. Loading the model is just as easy as:

```python
model = keras.models.load_model("my_keras_model.h5")
```

> This will work when using the Sequential API, but unfortunately not when using Model subclassing. However, you can use save_weights() and load_weights() to at least save and restore the model parameters (but you will need to save and restore everything yourself).
