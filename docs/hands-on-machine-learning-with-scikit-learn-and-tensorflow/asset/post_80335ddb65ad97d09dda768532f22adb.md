
If you want to regularize a self-normalizing network based on the SELU activation function (as discussed earlier), you should use AlphaDropout: this is a variant of dropout that preserves the mean and standard deviation of its inputs (it was introduced in the same paper as SELU, as regular dropout would break self-normalization).

## Monte-Carlo (MC) Dropout

In 2016, a paper by Yarin Gal and Zoubin Ghahramani added more good reasons to use dropout:

- First, the paper establishes a profound connection between dropout networks (i.e., neural networks using a dropout layer before every layer) and approximate Bayesian inference, giving dropout a solid mathematical justification.
- Second, they introduce a powerful technique called MC Dropout, which can boost the performance of any trained dropout model, without having to retrain or even modify it at all!
- Moreover, MC Dropout also provides a much better measure of the model’s uncertainty.
- Finally, it is amazingly simple to implement. If this sounds like a “one weird trick” advertisement, take a look at the following code. It is the full implementation of MC Dropout, boosting the model we trained earlier, without retraining it:

```
with keras.backend.learning_phase(1): # force training mode = dropout
    y_probas = np.stack([model.predict(x_scaled) for sample in range(100)])
```

We first force training mode on, using a learning_phase(1) context. This turns on dropout within the with block. We make 100 predictions over the test set, and set them. Since dropout is on, all predictions will be different. Recall that predict() returns a matrix with one row per instance, and one column per class. Since there are 10,000 instances in the test set, and this is a matrix of shape [10000, 10]. We stack 100 matrices, so y_probas is an array of shape [100, 10000, 10]. Once we average the first dimension (axis=0), we get y_proba, an array of shape [10000, 10], which we would get with a single prediction. That’s all! Averaging over multiple predictions with dropout we use a Monte Carlo estimate that is generally more reliable than the result of a single prediction with dropout off. For example, let's look at the model's prediction for the first instance in the test set, with dropout off:

```
>>> np.round(model.predict(X_test_scaled[:1]), 2)
array([[0., 0., 0., 0., 0., 0., 0.01, 0., 0.99]], dtype=float32)
```

The model seems almost certain that this image belongs to class 9 (ankle boot). Should you trust it? Is there so little room for doubt? Compare this with the predictions when dropout is activated:

```
>>> np.round(y_probs, :1], 2)
array([[0., 0., 0., 0., 0.14, 0., 0.17, 0., 0.68]],
       [0., 0., 0., 0., 0.16, 0., 0.2, 0., 0.64]],
       [0., 0., 0., 0., 0., 0., 0.01, 0., 0.97]])
```

This tells a very different story: apparently, when we activate dropout, the model is not sure anymore. It seems to prefer class 9, but it hesitates between classes 5 (sneaker) and 7 (sneaker), which makes sense given they're all footwear. We average over the first dimension, get the MC dropout predictions:

```
>>> np.round(y_proba[:1], 2)
array([[0., 0., 0., 0., 0., 0.22, 0.16, 0., 0.62]], dtype=float32)
```

The model still thinks this image belongs to class 9, which seems much more reasonable than 99%. Plus it's useful to know which classes it thinks are. And you can also take a look at the standard deviation of the probability estimates:

```
>>> y_std = y_probs.std(axis=0)
>>> np.round(y_std[:1], 2)
array([[0., 0., 0., 0., 0., 0.28, 0.21, 0.02, 0.32]], dtype=float32)
```

Apparently there's quite a lot of variance in the probability estimates (e.g., a medical or financial system), you should probably treat such an uncertain prediction with extreme caution. You definitely would not treat it like a 99% confident prediction. Moreover, the model's accuracy got a small boost from 86.8 to 86.9.

```
>>> accuracy = np.sum(y_pred == y_test) / len(y_test)
>>> accuracy
0.8694
```

The number of Monte Carlo samples you use (100 in this example) is a hyperparameter you can tweak. The higher it is, the more accurate the predictions and their uncertainty estimates will be. However, if you double it, inference time will also be doubled. Moreover, so a certain number of samples, you will notice little improvement. So your job is to find the right tradeoff between latency and accuracy, depending on your application.

If your model contains other layers that behave in a special way during training (as Batch Normalization layers), you should not force training mode like we just did. Instead, you should replace the Dropout layers with the MCDropout class:

```
class MCDropout(keras.Dropout):
    def call(self, inputs):
        return super().call(inputs, training=True)
```

We subclass the Dropout layer and override the call() method to fix its training argument to True.

## Max-Norm Regularization

Another regularization technique that is quite popular for neural networks is called max-norm regularization: for each neuron, it constrains the weights of the connections $\|w\|_2 \leq r$, where $r$ is the max-norm hyperparameter. Max-norm regularization does not add a regularization term to the loss function. Instead, it is typically implemented by clipping w after each training step. Reducing $r$ increases the amount of regularization and helps overfitting.

To implement max-norm regularization in Keras, just set every hidden layer's nel_constraint to a max_norm(), with the appropriate max value, for example:

```python
keras.layers.Dense(100, activation="elu", kernel_initializer="he_normal", kernel_constraint=keras.constraints.max_norm(1))
```

The max_norm() function has an axis argument that defaults to 0. A Dense layer usually has weights of shape [number of inputs, neurons], so using axis= means that the max norm constraint will independently apply to each neuron's vector. If you want to use max-norm with convolutional layers (see Chapter 14), make sure to set the max_norm() constraint's axis argument appropriately (usually axis=[0, 1, 2]).

As we will see in Chapter 12, you can define your own constraint function if you need to, and use it as the nel_constraint. You can also constrain the bias terms by setting the bias_constraint.
