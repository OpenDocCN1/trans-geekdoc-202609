One issue with this is that ML algorithms will assume that two nearby values are more similar than two distant values. For instance, for ordered categories like "bad", "average", "good", "excellent" it is obviously not the case for order_proximity (for example, categories 0 and 4 are clearly more similar than categories 0 and 1). To fix this issue, a common solution is to create one binary attribute per category: attribute one to 1 when the category is "<IS OCEAN" (and 0 otherwise), another attribute to 1 when the category is "INLAND" (and 0 otherwise), and so on. This is one-hot encoding, because only one attribute will be 1 (hot), while the others will be 0 (cold). The new attributes are sometimes dummy attributes. Scikit-Learn provides a OneHotEncoder to convert categorical values into one-hot vectors

```

>>> housing_cat_hot = cat_encoder.fit_transform(housing_cat)
```
