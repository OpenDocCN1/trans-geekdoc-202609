# TFRecord Format

The TFRecord format is TensorFlow's preferred format for storing large amounts of data and reading it efficiently. It is a very simple binary format that contains a sequence of binary records of varying sizes (each record has a length, a CRC checksum to check that the length was not corrupted, the actual data, and finally you easily create a TFRecord using the tf.io.TFRecordWriter

```python
with tf.io.TFRecordWriter("my_data.tfrecord") as f:
    f.write(b"This is the first record")
    f.write(b"And is the second record")
```

And you can use tf.data.TFRecordDataset to read one or more TFRecord files:

```python
filepaths = ["my_data.tfrecord"]
dataset = tf.data.TFRecordDataset(filepaths)
for item in dataset:
    print(item)
```

This will output:

```
tf.Tensor(b'This is the first record', shape=(), dtype=string)
tf.Tensor(b'And is the second record', shape=(), dtype=string)
```

![](img/0684d2da98e09085c0a622d4fd69aaad_439_1.png)

By default TFRecordDataset will read files one by one, but you can make read multiple files in parallel and interleave their records by setting num_parallel_reads. Alternatively, you could obtain the same result using list_files() and interleave().

# Compressed Files

It can sometimes be useful to compress your TFRecord files, especially if they need to be loaded by a network connection. You can create a compressed TFRecord file by setting options:

```python
options = tf.io.Options(compression_type="GZIP")
with tf.io.TFRecordWriter('compressed.tfrecord', options) as f:
    []
```

When reading a compressed TFRecord file, you need to specify the compression type:

```python
dataset = tf.data.TFRecordDataset(['compressed.tfrecord'], options=options)
```

# A Brief Introduction to Protocol Buffers

Even though each record can use any binary format, TFRecord files usually contain serialized Protocol Buffers (also called protobufs). This is a portable, extensible and efficient binary format developed at Google back in 2001 and open in 2008, and they are now widely used in gRPC, Google’s remote procedure call system. Protocol Buffers are defined using a simple language that looks like:

```proto
syntax = "proto3"
message Person {
  string name = 1;
  int32 id = 2;
  repeated string email = 3;
}
```

This says we are using the protobuf version 3, and an id of int32, each Person object may (optionally) have a name of string, and zero or more fields, each type string. The numbers 1, 2 and 3 are the field identifiers: they will be used in each record’s binary representation. Once you have a definition in a .proto file, you can compile it. requires the protobuf compiler to generate classes in Python (or some other language). Note that for protobuf definitions we have already for TensorFlow, you will not need to use protobuf. All you need to know is how to use classes in Python. To illustrate the basics, let’s look at a simple example that uses the classes generated for the Person protobuf (the code is explained in the comments)

```python
>>> person_pb2 import Person
>>> person = Person(name="Al", id=123, email=['a@b.com']) # create a Person
>>> print(person) # display the Person
```

Since protobuf objects are meant to be serialized and transmitted, they are called messages.

name: "Al"
id: 123
email: "a@b.com"

```python
>>> person.name # read a field
"Al"
>>> person.name = "Alice" # modify a field
>>> person.email[0] # repeated fields can be accessed like arrays
"a@b.com"
>>> person.email.append("c@d.com") # add an email address
>>> s = person.SerializeToString() # serialize the object to a byte string
>>> s
b'\x0a\x02Al\x18\x7b\x12\x09a@b.com\x12\x07c@d.com'
>>> person2 = Person() # create a new Person
>>> person2.ParseFromString(s) # parse the byte string (27 bytes)
>>> person == person2 # now they are equal
True
```

In short, we import the class generated by protobuf, we create an instance and play with it, visualizing, reading and writing some fields, then we serialize using the SerializeToString() method. This is the data that is ready to be saved or transmitted over the network. When reading or receiving this binary data, we can parse it using the ParseFromString() method, and we get a copy of the object that was serialized.

We could save the serialized object to a TFRecord file, then we could load and parse it: everything would work fine. SerializeToString() and ParseFromString() are not TensorFlow operations (neither are the other operations in this code), so they cannot be included in a TensorFlow Function (except wrapping them in a .py_function()) which would make the code slower and less portable, as we saw in Chapter 12. Fortunately, TensorFlow does include special proto definitions for which provides parsing operations.

# TensorFlow Protobuf

The main protobuf typically used in a TFRecord file is the Example protobuf, which represents one instance in a dataset. It contains a list of named fields, where each feature can be a list of byte strings, a list of floats or a list of integers. Here is the protobuf definition:

```proto
syntax = "proto3"
message BytesList { repeated bytes value = 1; }
message FloatList { repeated float value = 1 [packed = true]; }
message Int64List { repeated int64 value = 1 [packed = true]; }
```
