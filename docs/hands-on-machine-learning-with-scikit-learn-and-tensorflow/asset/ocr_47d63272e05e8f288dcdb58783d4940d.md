array([[11., 12., 13.],
             [14., 15., 16.]], dtype=float32)
>>> tf.square(t)

Note that writing t + 10 is equivalent to calling tf.add(t, 10) (indeed, Python calls the method t.__add__(10), which just calls tf.add(t, 10)). Other operators (like -, *, etc.) are also supported. The @ operator was used in Python 3.5, for matrix multiplication: it is equivalent to calling the tf.matmul() function.

You will find all the basic operations that you need (e.g., tf.add(t), tf.multiply(t), tf.square(t), tf.exp(t), tf.sqrt(t)...) and many more operations that you can find in NumPy (e.g., tf.reshape(t), tf.squeeze(t), tf.tile(t)), but sometimes with a different name (e.g., tf.reduce_mean(t), tf.reduce_sum(t), tf.reduce_max(t), tf.math.log(t) are the equivalent of np.mean(t), np.sum(t), np.max(t) and np.log(t)). When the names differ, there is often a good reason for it: for example, in TensorFlow you write tf.transpose(t), you cannot write t.T like in NumPy. The reason is that it does not work exactly the same way: in TensorFlow, a new tensor is created with its own copy of the transposed data, while in NumPy, t.T is just a transposed view on the same data. Similarly, the tf.reduce_sum() operation is named this way because its GPU kernel (i.e., GPU implementation) uses a regular algorithm that does not guarantee the order in which elements are added: because 32-bit floats have limited precision, this means the result may change so slightly every time you call this operation. The same is true of tf.reduce_mean() (but course tf.reduce_max() is deterministic).
