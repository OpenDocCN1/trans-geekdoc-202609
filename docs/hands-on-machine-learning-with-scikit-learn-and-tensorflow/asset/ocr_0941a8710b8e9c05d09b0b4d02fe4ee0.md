# Compressed TFRec Files

It can sometimes be useful to compress your TFRec files, especially if they need to be loaded by a network connection. You can create a compressed TFRec file by setting the options argument:

```
options = tf.io.TFRecOptions(compression_type="GZIP")
with tf.io.TFRecWriter('my_compressed.tfrecord', options) as f:
    []
```

When reading a compressed TFRecord file, you need to specify the compression type:

```
dataset = tf.data.TFRecordDataset(['my_compressed.tfrecord'],
compression_type="GZIP")
```

# A Brief Introduction to Protocol Buffers

Even though each record can use any binary format, TFRec files usually contain serialized Protocol Buffers (also called protobufs). This is a portable, extensible and efficient binary format developed at Google back in 2001 and Open Source in 2008, and they are now widely used, in gRPC, Google’s remote-procedure call system. Protocol Buffers are defined using a simple language that looks like this:

```
syntax = "proto3"
message Person {
  string name = 1;
  int32 id = 2;
  repeated string email = 3;
}
```

This says we are using the protobuf format version 3, and an id of type int32, each Person object may (optionally) have a name of type string, and zero or more fields, each of type string. The numbers 1, 2 and 3 are the field identifiers: they will be used in each record’s binary representation. Once you have a definition in a .proto file, you can compile it. This requires the protobuf compiler, to generate access classes in Python (or some other language). Note that the protobuf definitions we have already been for, and their Python classes are parts of TensorFlow, you will not need to use protobuf. All you need to know is how to use access classes in Python. To illustrate the basics, let’s look at a simple example that uses the access classes generated for the Person protobuf (the code is explained in the comments)

```
>>> from person_pb2 import Person # import the generated access class
>>> person = Person(name="Al", id=123, email=['a@b.com']) # create a Person
>>> print(person) # display the Person
```

Since protobuf objects are meant to be serialized and transmitted, and they are called messages.
