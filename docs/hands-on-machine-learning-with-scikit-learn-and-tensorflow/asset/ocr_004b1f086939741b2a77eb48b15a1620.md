Let's go back to the Features API. Here is how you could encode the ocean_proximity categories as 2D embeddings:

```
ocean_proximity_embed = tf.feature_column.embedding_column(ocean_proximity, dimension=2)
```

Each of the five ocean_proximity categories will now be represented as a 2D vector. These vectors are stored in an *embedding matrix* with one row per category, and one column per embedding dimension, so in this example it is a 5x2 matrix. When an embedding column is a category index as input (say, 3, which corresponds to the category "NEAR BAY"), it performs a lookup in the embedding matrix and returns the corresponding row (say, [0.331, 0.198]). Unfortunately, the embedding matrix can be quite large, especially when you have a large vocabulary: if this is the case, the model can only learn good representations for the categories for which it has sufficient training data. To reduce the size of the embedding matrix, you can try lowering the dimension hyperparameter but if you reduce this parameter too much, the representations may not be good. Another option is to reduce the vocabulary size (e.g., if you are dealing with text, you can try dropping the rare words from the vocabulary, and replace them all with a token "<unknown>" or "<UNK>". If you are using hash buckets, you can also try reducing the hash_bucket_size (but not too much, or else you will get collisions).
