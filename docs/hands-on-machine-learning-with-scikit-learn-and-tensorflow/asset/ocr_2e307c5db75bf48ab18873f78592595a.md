If you call repeat() on a shuffled dataset, by default it will generate a new order at every iteration. This is generally a good idea, but if you prefer the same order at each iteration (e.g., for tests or debugging), you can set shuffle_iteration=False.

For a large dataset that does not fit in memory, this simple shuffling-buffer approach may not be sufficient, since the buffer will be small compared to the dataset. One solution is to shuffle the data itself (for example, on Linux you can shuffle files using the shuffle command). This will definitely improve shuffling a lot! However, even if the data is shuffled, you will usually want to shuffle it more, or else the order will be repeated at each epoch, and the model may end up being biased, due to spurious patterns present in the source data. To shuffle the instances, a common approach is to split the dataset into multiple files, then read them in a random order during training. However, instances located in the same file will still end up close each other. To avoid this you can pick multiple files randomly, and read them simultaneously, interleaving their lines. On top of that you can add a shuffling buffer using the shuffle() method. If this sounds like a lot of work, don't worry: the Data API actually makes this possible in just a few lines of code. Let's see how to do this.

Imagine a sorted deck of cards on your left: suppose you take the top 3 cards and shuffle them, one randomly and put it to your right, keeping the other 2 in your hands. Take another card on your left, shuffle the 3 cards in your hands and pick one of them randomly, and put it on your right. When you are done going through all the cards like this, you will have a deck of cards on your right: do you think it will be perfectly shuffled?
