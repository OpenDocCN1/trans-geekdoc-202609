The LearningScheduler will update the optimizer's learning_rate attribute at the beginning of each epoch. Updating the learning rate once per epoch is usually enough, but if you want it to be updated more often, for example at every step, you need to write your callback (see the notebook for example). This can make sense if there are many steps per epoch.

The schedule function can optionally take the current learning rate as a second argument. For example, the following schedule function just multiplies the learning rate by $0.1^{1/20}$, which results in some exponential decay (except the decay now starts at the beginning of epoch 0 instead of 1). This implementation relies on the optimizer's initial learning rate (contr to the previous implementation), so make sure to set it appropriately.

```
def exponential_decay_fn(epoch, lr):
    return lr * 0.1**(1 / 20)
```

When you save a model, the optimizer and its learning rate get along with it. This means that with this new schedule, you could load a trained model and continue training where it left off, no problem. However, things are not so if your schedule function uses the epoch argument: the epoch does not saved, and it gets reset to 0 every time you call the fit(). This could lead to a very large learning rate when you continue training a model where it left off, which would likely decay your model's weights. One solution is to set the fit() method's `initial_epoch` argument to the epoch at the right value.

For piecewise constant scheduling, you can use a schedule function like the following one (for an example), you can define a more general function if you want, see the notebook to create a LearningScheduler callback with this function and pass it to the fit() method, just like we did for exponential scheduling:

```
def piecewise_constant_fn(epoch):
    if epoch < 5:
        return 0.01
    elif epoch < 15:
        return 0.005
    else:
        return 0.001
```

For performance scheduling, simply use the ReduceLROnPlateau callback. For example, if you pass the following callback to the fit() method), it will multiply the learning rate by 0.5 when the best loss does not improve for 5 consecutive epochs (other options are available, please check the document for more details):

```
lr_scheduler = keras.callbacks.ReduceLROnPlateau(factor=0.5, patience=5)
```
