# Finding the Optimal Number of Clusters

So far, we have set the number of clusters k to 5 because it was obvious by looking at the data that this is - in general, it will not be easy to know how to set k, and the result might be bad if you set it to the wrong value. For example, as you can see in Figure 9-7, setting k to 3 or 8 results in fairly bad models:

You might be thinking that we could pick the model with the lowest inertia, right? Unfortunately, it is not simple. The inertia for k=3 is 653.2, which is much higher than for k=5 (which is 211.6), but with k=8, the inertia is just 119.1. The inertia is not a good performance metric when trying to choose k since it keeps getting lower as we increase k.
