# 第 2 章：会计 ML 项目的数据准备和预处理

## 2.1 了解会计数据类型和结构
在会计领域，数据以各种形式和结构出现。了解这些不同的数据类型对于有效实施机器学习至关重要。以下是你可能会遇到的主要数据类型：
1. 交易数据：这包括单独的财务交易，例如销售、采购和付款。通常包含日期、金额、账户代码和描述等信息。
2. 总账数据：这是按账户组织的全部财务交易的汇总。它构成了财务报表的基石。
3. 财务报表：包括资产负债表、损益表和现金流量表。它们提供了公司财务状况的结构化视图。
4. 元数据：这包括关于数据本身的信息，例如账户层级、成本中心结构或产品分类。
5. 非结构化数据：这可能包括发票、合同或财务报告中的文本。虽然在传统会计分析中并不常用，但像自然语言处理（`NLP`）这样的 ML 技术可以从这些数据中提取有价值的见解。
6. 时间序列数据：会计数据的很大一部分是基于时间的，例如每日销售额或每月账户余额。
7. 分类数据：这包括非数值数据，如账户类型、交易类别或客户细分。

了解这些数据类型至关重要，因为不同的 ML 算法更适合不同类型的数据。例如，时间序列算法适用于根据历史趋势预测未来值，而分类算法可用于对交易进行分类或检测异常。

## 2.2 财务数据集的数据清洗技术
数据清洗是任何 ML 项目的关键步骤，在会计中尤其重要，因为数据准确性至关重要。以下是一些财务数据集的数据清洗技术：
1. 处理缺失值：
   * 对于数值数据，可考虑使用 `mean`、`median` 或 `mode` 插补。
   * 对于分类数据，你可以使用 `mode` 插补或为缺失值创建新类别。
   * 在某些情况下，可能适合删除缺失值的行，但要谨慎，因为这会引入偏差。
2. 处理异常值：
   * 使用统计方法如 `z-score` 或 `Interquartile Range (IQR)` 来识别异常值。
   * 调查异常值以确定它们是真实异常还是数据错误。
   * 考虑对异常值进行上限处理（`winsorization`）而不是删除它们，尤其是在财务数据中极端值可能很重要。
3. 标准化格式：
   * 确保数据集中日期格式一致。
   * 如果处理国际数据，将货币值标准化为单一货币。
   * 规范化文本数据（例如一致的大写、删除多余空格）。
4. 处理重复项：
   * 识别并删除重复交易，同时注意区分真正的重复项和合法的重复交易。
5. 数据类型转换：
   * 确保数据类型适合你的分析（例如日期以日期存储，而不是字符串）。
6. 解决不一致问题：
   * 查找并纠正分类数据中的不一致（例如“Cash” vs. “cash” vs. “CASH”）。
   * 检查并解决账户名称或代码中的不一致。

## 2.3 会计专用 ML 模型的特征工程
特征工程是从现有数据中创建新特征以提高 ML 模型性能的过程。在会计中，这通常涉及创建有意义的财务比率或指标。以下是一些示例：
1. 财务比率：
   * 流动性比率（例如，`Current Ratio = Current Assets / Current Liabilities`）
   * 盈利能力比率（例如，`Net Profit Margin = Net Income / Revenue`）
   * 效率比率（例如，`Inventory Turnover = Cost of Goods Sold / Average Inventory`）
2. 基于时间的特征：
   * 交易数据的星期几、月份或季度
   * 距上次交易的时间
   * 滚动平均值或总和（例如，销售额的 3 个月滚动平均值）
3. 分类编码：
   * 账户类型或交易类别的独热编码
   * 高基数分类变量的目标编码
4. 基于文本的特征：
   * 交易描述中重要词的 `TF-IDF` 得分
   * 文本财务数据的情感得分（例如，来自财务报告）
5. 交互特征：
   * 可能有意义的现有特征组合（例如，`Gross Profit * Inventory Turnover`）
6. 领域特定特征：
   * `Days Sales Outstanding (DSO) = (Accounts Receivable / Total Credit Sales) * Number of Days`
   * 用于预测破产风险的 `Z-score`

记住，特征工程的目标是创建能够捕捉数据中有意义模式的特征。你创建的具体特征将取决于你的特定用例和你希望获得的见解。

## 2.4 欺诈检测场景中不平衡数据集的处理
欺诈检测是会计中 ML 的常见应用，但它带来了一个特定挑战：不平衡数据集。在大多数情况下，欺诈交易相对于合法交易很少，这可能导致 ML 模型偏向多数类。以下是一些应对方法：
1. 过采样少数类：
   * `Random Oversampling`：随机复制少数类实例。
   * 合成少数类过采样技术（`SMOTE`）：创建少数类的合成示例。
2. 欠采样多数类：
   * `Random Undersampling`：随机删除多数类实例。
   * `Tomek Links`：删除接近少数类实例的多数类实例。
3. 组合方法：
   * `SMOTEENN`：将 `SMOTE` 与编辑最近邻结合。
   * `SMOTETomek`：将 `SMOTE` 与 `Tomek Links` 结合。
4. 算法级方法：
   * 使用允许类别加权的算法（例如加权随机森林）。
   * 使用异常检测算法而不是二元分类。
5. 集成方法：
   * 具有适当采样技术的基于 Bagging 的集成。
