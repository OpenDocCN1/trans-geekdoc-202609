# A. Driver layer

The driver layer is the entry point of interaction with the system. The driver may have more than one heterogeneous vehicle (e.g., 2-wheeler, 3-wheeler, 4-wheeler), according to which price is decided. The driver can request the BC parking for reservation by providing vehicle id, vehicle type, arrival date and time, and location. The system identifies and predicts available lots in each parking area as per driver request. The system responds to this predicted information. By analyzing reliable preference, services, and price, the driver can confirm the reservation. Payment is performed using BC-based either, where the driver uses cryptographic wallet. This is encrypted using the private key, cryptography and time stamp. Drivers can make payment to the BC layer, which is validated by performing consensus mechanisms. After validation of payment, the driver can park the vehicle to the located spot

AI layer to perform checking availability and predict prices according to the peak status and vehicle. This application searches for parking lot with the specific time and vehicle type which is processed by the algorithm to determine availability of parking and price based on demand and time. The algorithm will notify the user about the nearest parking area by analyzing the peers (i.e., other users) and rates based on demand and time. Pricing is applied at a data server where parking occupancy occurs. When a driver stays and checks availability for the parking lot, an AI-based algorithm process dataset and checks as per driver request. This dataset consists of vehicles such as date, time, locations, vehicle type, required services. For accurate prediction, the model is trained and tested based on previous data and the fusion matrix. The matrix shows the actual price and predicted price based on a result. Based on availability, system provides the driver with area locations and available lots with predicted price, according to which driver can choose suitable parking location. then the parking slot is represented as free. Also, if the user makes changes for booked parking then changes are increased as changes. Data is saved on the blockchain for future use.

# C. BC Layer

BC layer is involved to enhance the security of system roles and sensitive information. All the service providers are connected to the BN which each parking provider acts as a block and local copy of the public ledger. Using consensus mechanisms, the public ledger is updated with value. For adding a new node, the parking service provider needs to compute the nonce. The parking service provider finds nonce to get a chance to the BN. Each starts a smart contract to change parking status according to the ente.

# D. Parking Service Provider Layer

Each parking area has a parking service provider who acts as a block in BN. The parking service provider can join BN for fair and transparent parking allocation. Parking service provider updates information about unpaid parking. The BC, as reported, can reserve a suitable parking lot, where parking service providers (i.e., people) are responsible to verify and validate each entry and transaction. Each contains copy of the public ledger and smart contract for validation.
