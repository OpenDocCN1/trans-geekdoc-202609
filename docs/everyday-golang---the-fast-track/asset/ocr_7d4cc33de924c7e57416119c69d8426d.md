```
res, err, shared := s.Do(key, func() (any, error) {
    return ISSPosition{Latitude: 40.0, Longitude: -0.31}, nil
})

fmt.Printf("Shared response? %v\n", shared)
if err != nil {
    fmt.Println(err)
    return
}
position := res.(ISSPosition)

fmt.Printf("Position: %s\n", position.String())
}
```

Notice that:

+   - the response is returned as “any” which is the same as writing “interface{}", so any result needs to be unwrapped.
+   - there is a “key” variable, meaning the singleflight group can be used for multiple calls

If the key matches an existing call, you'll get the response of that call when it's ready, if the call doesn't match a key, it'll collect any other requests that come in before it's done.

If you think it's useful, you can also determine whether you had a shared response or were the first caller getting the original copy of the response.

In our example, we'll never get a shared response, so let's build an example with a HTTP server and simulate multiple connections and users.

You'll find the source code in the “singleflight-simple” folder.

Imagine that you were hosting a HTTP server which needed to call another server and return the result, and that the query takes 2 seconds. If you receive 1 request within 2 second, you'll make one call to the upstream server, but if you received 1000 requests, you'd make 1000 calls within that timeframe.

This could be especially problematic if the API call is expensive or could be rate-limited. In Summer 2022, we implemented the singleflight pattern in the OpenFaaS gateway, which dramatically reduced its API calls during scale from zero. Implement Single Flight queries for the backend #1734
