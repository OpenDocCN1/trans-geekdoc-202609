Then `cd ..` back to the top level of your project, where the `bcrypt-fn.yml` file is.

You must always run `go mod` commands alongside your `handler.go` file, and not at the level of the YAML file.

# Building your function

The workflow for building and deploying a function is as follows:

+   - `faas-cli build` creates a container image in your local Docker library
+   - `faas-cli push` pushes the image to your remote container registry
+   - `faas-cli deploy` deploys the function to your OpenFaaS Gateway using a REST API call

The above three commands can be run via the `faas-cli up` command.

And of these commands can be run in CI/CD pipelines.

Set up your OpenFaaS Gateway URL as an environment variable and run `faas-cli up` to try out the function.

```
```sh
export OPENFAAS_URL=http://127.0.0.1:8080

export DOCKER_BUILDKIT=1

faas-cli build --build-arg GO111MODULE=on -f bcrypt-fn.yml
```
```

The `export DOCKER_BUILDKIT=1` step will instruct Docker to use buildkit instead of its legacy approach for building functions. Buildkit can work out much faster because it can cache the layers in a more intelligent way and also run multiple steps in parallel. Ultimately, this means your builds will be quicker.

What will happen next is that the Dockerfile for the function will be executed. This is hidden away from you in the template at: `template/golang-middleware/Dockerfile`. You can read through it now, if you like.

In a separate window, invoke the container:

```
```sh

```
```
