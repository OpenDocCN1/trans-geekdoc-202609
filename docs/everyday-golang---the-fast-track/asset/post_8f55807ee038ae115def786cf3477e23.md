
```go
type APIQuery struct {
	Response map[string]int64
}

func (a *APIQuery) Register(name string, replicas int64) {
	a.Response[name] = replicas
}

func (a *APIQuery) Remove(name string) {
	delete(a.Response, name)
}

func (a *APIQuery) QueryFunctions() map[string]int64 {
	return a.Response
}
```

The API has a map which we will modify through HTTP requests to the /register and /remove endpoints, passing in a query string for the function name and/or replica count. Normally, if this were production code, we’d also want to use a locking mechanism to make sure we have safe concurrent access to the map.

### exporter.go

```go
package main

import (
	"github.com/prometheus/client_golang/prometheus"
)

type Exporter struct {
	ServiceReplicasGauge *prometheus.GaugeVec
	api                  *APIQuery
}

func NewExporter(api *APIQuery) *Exporter {
	return &Exporter{
		api: api,
		ServiceReplicasGauge: prometheus.NewGaugeVec(
			prometheus.GaugeOpts{
				Namespace: "gateway",
				Name:      "service_count",
				Help:      "Current count of replicas for function",
			},
			[]string{"function_name"},
		),
	}
}

// Describe is to describe the metrics for Prometheus
func (e *Exporter) Describe(ch chan<- *prometheus.Desc) {
	e.ServiceReplicasGauge.Describe(ch)
}

// Collect exports the values for each metric to Prometheus
func (e *Exporter) Collect(ch chan<- prometheus.Metric) {
	e.ServiceReplicasGauge.Reset()

	for serviceName, replicas := range e.api.QueryFunctions() {
		e.ServiceReplicasGauge.
			WithLabelValues(serviceName).
			Set(float64(replicas))
	}

	e.ServiceReplicasGauge.Collect(ch)
}
```

In the Describe method, we've told Prometheus about all the various metrics which it needs to hold data for.

### main.go

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"strconv"
	"time"

	"github.com/prometheus/client_golang/prometheus"
	"github.com/prometheus/client_golang/prometheus/promhttp"
)

func main() {
	port := 8080
	readTimeout := time.Millisecond * 500
	writeTimeout := time.Millisecond * 500

	mux := http.NewServeMux()
	api := newAPIQuery()

	e := NewExporter(api)
	prometheus.MustRegister(e)

	mux.Handle("/metrics", promhttp.Handler())
	mux.Handle("/remove", http.HandlerFunc(
		func(w http.ResponseWriter, r *http.Request) {
			name := r.URL.Query().Get("name")
			api.Remove(name)
		}))

	mux.Handle("/register", http.HandlerFunc(
		func(w http.ResponseWriter, r *http.Request) {
			name := r.URL.Query().Get("name")
			replicasV := r.URL.Query().Get("replicas")
			replicas, _ := strconv.ParseInt(replicasV, 10, 64)
			api.Register(name, int64(replicas))
			w.WriteHeader(http.StatusAccepted)
		}))

	s := &http.Server{
		Addr:           fmt.Sprintf(":%d", port),
		ReadTimeout:    readTimeout,
		WriteTimeout:   writeTimeout,
		MaxHeaderBytes: 1 << 20, // Max header of 1MB
		Handler:        mux,
	}
	log.Printf("Listening on: %d", port)
	s.ListenAndServe()
}
```

In the Collect method, we reset the metric, then we add in any items that are present in the API's response. If an item is removed, then it will no longer be exported as part of the service's metrics.

## Building and releasing Go binaries

Whether you've written a CLI or an HTTP server, most of the time Go code can be compiled down to a static binary which is self-contained and can run on the target system you specify.

In an earlier chapter we covered cross-compilation, at this point you should consider whether you need to target one environment such as Windows, Linux or MacOS, or multiple.

### The release-it example

[Release-it](https://github.com/release-it/release-it) repo is an example of a static Go binary that can be built and released through GitHub Actions. It uses a [Makefile](https://github.com/release-it/release-it/blob/main/Makefile), so it can also be run in other CI pipelines or manually as and when you create a new release.

The Makefile has the following properties, all of which were covered in previous chapters already:

- It builds binaries for multiple platforms and Operating Systems
- It injects the Commit and Version from git into the final binary

```makefile
Version := $(shell git describe --tags --dirty)
# Version := "dev"
GitCommit := $(shell git rev-parse HEAD)
LDFLAGS := "-s -w -X main.Version=$(Version) -X main.GitCommit=$(GitCommit)"

.PHONY: all
all: gofmt dist

.PHONY: gofmt
gofmt:
	@test -z $(shell gofmt -l ./ | tee /dev/stderr) || (echo "[WARN] Fix formatting issues with 'make fmt'" && exit 1)

.PHONY: dist
dist:
	mkdir -p bin/
	CGO_ENABLED=0 GOOS=linux go build -mod=vendor -a -ldflags $(LDFLAGS) -o bin/release-it-amd64
	CGO_ENABLED=0 GOOS=darwin go build -mod=vendor -a -ldflags $(LDFLAGS) -o bin/release-it-darwin
	GOARM=7 GOARCH=arm CGO_ENABLED=0 GOOS=linux go build -mod=vendor -a -ldflags $(LDFLAGS) -o bin/release-it-arm
	GOARCH=arm64 CGO_ENABLED=0 GOOS=linux go build -mod=vendor -a -ldflags $(LDFLAGS) -o bin/release-it-arm64
	GOOS=windows CGO_ENABLED=0 go build -mod=vendor -a -ldflags $(LDFLAGS) -o bin/release-it.exe
```

In addition, it runs gofmt for good measure.

If there were any unit tests in the project, then we could add an additional target for them, such as:

```makefile
.PHONY: gotest
gotest:
	go test ./...
```

Then update the all line to `gofmt gotest dist` which would run each of the tasks for us.

Clone the example and build it:

```sh
$ mkdir $GOPATH/src/github.com/alexellis/
$ cd $GOPATH/src/github.com/alexellis/
$ git clone https://github.com/alexellis/release-it
$ cd release-it
$ make
```

By default make will try to run the all target, but you can also run make gofmt if you want to test formatting before committing to a build.

You'll find each binary in the bin/ folder and can run them on your system if it matches the OS/architecture pair, or copy it to another system to run it there.
