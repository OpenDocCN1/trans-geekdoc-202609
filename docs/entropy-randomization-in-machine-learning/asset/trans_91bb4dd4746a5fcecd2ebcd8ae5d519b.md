

`ML` 块由于其任务而“负载”最重，首先是求解优化问题。我们已在本书前几章中讨论了该问题的固有困难。因此，`ML` 块必须包含高效的全局优化算法或能够访问这些算法。

## 3. 模型实现 (MI)

模型实现块产生一个学习后的模型，即配备了前一阶段计算得到的函数 `F[*P*]` 和 `F[*Q*]` 的模型 `M`。模型实现包括生成输出集合（`EG` 块），并在集合分析（`EA`）块中进一步计算其特征。对于模型实现和测试（见前一阶段），集合是通过产生大量随机变量的实现（采样）而生成的，其 `PDFs` 已给定。因此，这些块必须能够访问具有任意 `PDFs` 的随机变量的相应生成算法。

所描述的 `RML` 技术可以以独立的程序模块的形式实现，这些模块以手动模式相互通信或通过更大规模的技术进行通信。此类技术是在为解决特定实际任务而设计的信息系统中实现的。对与信息系统架构相关的所有问题的全面处理超出了本书的范围。我们只会讨论一些理论方面，并以最一般的形式考虑它们。

信息系统（`IS`）通常被定义为集成不同资源（人力、技术、财务）并用于数据存储、检索和处理的系统 [[3](#refbib.xhtml#r3), [39](#refbib.xhtml#r39)]。信息系统的主要组成部分在于软件资源，其可通过类比于计算机系统的架构进行分类。由于系统级软件已标准化且广泛使用，`IS` 中受其任务影响的最重要部分作为应用软件在用户级实现。请注意，用户将以抽象意义来理解，因为信息系统可以由人类或其他系统使用。这种方法在程序系统设计和开发中是常规的 [[59](#refbib.xhtml#r59), [78](#refbib.xhtml#r78)]。

用户通过用户界面与 `IS` 交互（见 [Fig. 9.7](#chapter9.xhtml#f9_7)），该界面将相应地以抽象意义来考虑。该界面确定了系统用户可接受的操作集合，即代表了给定系统的抽象“控制面板”。因此，系统功能与控制功能在逻辑层面上分离，并且通常在物理层面上分离。

[Figure 9.7](#chapter9.xhtml#f9_7b)

用户界面控制程序系统，并显然以所需的用户友好形式展示操作结果。再次，我们将坚持以下抽象考虑。如果用户是人类，则用户友好的界面由图像、图表、数字以适当方式显示组成；这也适用于“控制面板”，它们现在例如通过窗口界面组织，具有诸如推送按钮、复选框、输入字段等控制元素。对于外部系统，不需要窗口界面，但我们仍然具有与人类用户相同的原则：数据以外部系统输入规范所规定的形式表示，控制通过两侧控制元素的链接来实现。

在所述方法下，有必要在逻辑上（并且通常在物理上）将系统的功能分离为松散耦合的模块，以获得更高的可靠性并降低程序系统设计的复杂性。存在几种解决此问题的有效方法，例如 Model-View-Controller (`MVC`) 设计。这种软件架构模式识别了通过相应接口通信的三个抽象子系统（组件），即 Model、View 和 Controller [[99](#refbib.xhtml#r99)]；见 [Fig. 9.7](#chapter9.xhtml#f9_7) 中的图表。这里的主要思想是用户通过 Controller 提供的功能控制程序系统，并通过 View 读取有关系统操作的信息。该架构模式意味着信息表示（视图）和控制设备可能存在多重性，取决于问题的具体性。程序系统的概念功能主要集中在 Model 中。

所述的一般方案在几乎所有与程序系统相关的领域中占主导地位。由于其抽象性，它可以在任何计算机系统上使用软件技术实现。

该方法的一个显著特征是其对系统组件的普遍性。换句话说，该方法对整个系统有效，也对只要以智能方式设计和实现就对其组件有效。特别地，作为程序组件实现的 `RML` 技术可以成为更大系统的组件，通过其控制和视图子系统的接口集成到后者中。

最一般地说，`RML` 组件可以表示为一个对象，其在输入端接收数据和“知识”，然后实现随机化模型（`RM`）。在此上下文中，所有提到的事物都被视为相应抽象对象的程序实现：知识被封装到模型对象中（见 [Fig. 9.6](#chapter9.xhtml#f9_6)），而随机化模型则封装到学习模型对象中，其中最优 `PDFs` 由 `RML` 程序组件定义。

对于 [Fig. 9.6](#chapter9.xhtml#f9_6) 中 `RML` 技术的结构图，最耗资源的运算是

* 优化；
* 生成具有给定 `PDFs` 的随机变量；
* 随机化模型的输出集合分析。

因此，这些运算应使用具有并行计算潜力的高性能计算机系统实现。尽管它们可能由于计算机系统的架构特性而存在结构差异，这决定了用户对其操作的通用方法。我们将相应地分离出计算机系统的基本配置如下：

* 工作站，配备单个多核中央处理器和单个大规模并行加速器（在现代条件下，为图形适配器）；
* 多处理器计算模块或若干此类模块，每个模块包含若干中央处理器并且可能包含若干加速器；
* 超级计算机级的计算机系统，包含数千或数万个计算模块。

这种方法导致了为不同计算机系统配置实现程序模块以实现并行计算潜力的实现问题（见 [Fig. 9.8](#chapter9.xhtml#f9_8)）。通用多线程架构作为解决这些问题的有效算法的基础；此外，在使用系统级软件技术进行智能实现时，它将降低此类算法及相关技术的程序复杂性。
