
The sum for `δ[n]`![Image](images/B9780443218576000163/si72.png) is finite since `p[n](m)` = 0![Image](images/B9780443218576000163/si73.png) if `m` > `n`![Image](images/B9780443218576000163/si74.png). Of course, `Var[S[0]]` = 0![Image](images/B9780443218576000163/si75.png). Also, if `ϵ` = 0![Image](images/B9780443218576000163/si57.png), the sequence is perfectly random: `δ[n]` = 0![Image](images/B9780443218576000163/si76.png), `Var[S[n]]` = `n`![Image](images/B9780443218576000163/si77.png), and `` `$S_n/\\sqrt{n}` ``![Image](images/B9780443218576000163/si78.png) converges to a normal distribution. In turn, the law of the iterated logarithm is satisfied. Conversely, this is violated if `ϵ` > 0![Image](images/B9780443218576000163/si79.png). Formula [(12.3)](#Chp012_229-241_B9780443218576000163.xhtml#deq7), combined with `Hoeffding's inequality` [[Wiki](https://en.wikipedia.org/wiki/Hoeffding%27s_inequality)], may provide some bounds for `Var[S[n]]`![Image](images/B9780443218576000163/si80.png).

[Fig. 12.3](#Chp012_229-241_B9780443218576000163.xhtml#f0020) shows `δ[n]`![Image](images/B9780443218576000163/si72.png) for four types of modified random walks, using the following color scheme:

*   •  Yellow: `g(n)` = 10![Image](images/B9780443218576000163/si81.png), `ϵ` = 0.05![Image](images/B9780443218576000163/si59.png)
*   •  Red: `g(n)` = `n^(β)`![Image](images/B9780443218576000163/si60.png), `β` = 0.50![Image](images/B9780443218576000163/si82.png), `ϵ` = 0.05![Image](images/B9780443218576000163/si59.png)
*   •  Blue: `g(n)` = `n^(β)`![Image](images/B9780443218576000163/si60.png), `β` = 0.45![Image](images/B9780443218576000163/si83.png), `ϵ` = 0.05![Image](images/B9780443218576000163/si59.png)
*   •  Purple: `g(n)` = `n^(β)`![Image](images/B9780443218576000163/si60.png), `β` = 0.55![Image](images/B9780443218576000163/si84.png), `ϵ` = 0.05![Image](images/B9780443218576000163/si59.png)

The curve that coincides with the X-axis (`δ[n]` = 0![Image](images/B9780443218576000163/si76.png)) corresponds to `ϵ` = 0![Image](images/B9780443218576000163/si57.png), that is, to pure randomness regardless of `g(n)`![Image](images/B9780443218576000163/si51.png). It is not colored in [Fig. 12.3](#Chp012_229-241_B9780443218576000163.xhtml#f0020). Finally, the Python code in Section [12.3.1](#Chp012_229-241_B9780443218576000163.xhtml#s0065) computes `Var[S[n]]`![Image](images/B9780443218576000163/si80.png) exactly (not via simulations) using two different methods, proving that formula [(12.3)](#Chp012_229-241_B9780443218576000163.xhtml#deq7) is correct.

### 12.1.3 Random walks with less entropy than pure random signal

In Section [12.1.2](#Chp012_229-241_B9780443218576000163.xhtml#s0020), I focused on creating sequences with higher oscillation rates than dictated by randomness, resulting in lower amplitudes. Doing the opposite – decreasing the oscillation rate – is more difficult. For instance, using `g(n)` = `n^(β)`![Image](images/B9780443218576000163/si60.png) with `` `$\\beta > \\frac{1}{2}` ``![Image](images/B9780443218576000163/si85.png) will not work. You cannot do better than `` `$\\sqrt{n}` ``![Image](images/B9780443218576000163/si52.png) because of the law of the iterated logarithm: boosting `β` beyond the threshold `` `$\\frac{1}{2}` ``![Image](images/B9780443218576000163/si86.png) is useless.

A workaround is to use the following algorithm:

```
 *S* = 0![Image](images/B9780443218576000163/si35.png)
 **For** *n* = 1, 2, …![Image](images/B9780443218576000163/si36.png)
  Generate random deviate *U* on \[0, 1\]![Image](images/B9780443218576000163/si37.png)
  *M* = *g*(*n*)![Image](images/B9780443218576000163/si38.png)
  **If** ( − *M* < *S* < 0![Image](images/B9780443218576000163/si87.png) and $U < \\frac{1}{2} + \\epsilon$![Image](images/B9780443218576000163/si42.png)) or (0 < *S* < *M*![Image](images/B9780443218576000163/si88.png) and $U < \\frac{1}{2} - \\epsilon$![Image](images/B9780443218576000163/si40.png)) or (*S* = 0![Image](images/B9780443218576000163/si35.png) and $U < \\frac{1}{2}$![Image](images/B9780443218576000163/si44.png))
  **Then**
*X*[*n*] =  − 1![Image](images/B9780443218576000163/si45.png)
  **Else**
*X*[*n*] = 1![Image](images/B9780443218576000163/si46.png)
  *S* = *S* + *X*[*n*]![Image](images/B9780443218576000163/si47.png)
  *S*[*n*] = *S*![Image](images/B9780443218576000163/si48.png)
```

The Python code in Section [12.3.2](#Chp012_229-241_B9780443218576000163.xhtml#s0070), with the option deviations='Large', performs this simulation. The yellow time series in [Fig. 12.1](#Chp012_229-241_B9780443218576000163.xhtml#f0010) is a realization of such a modified random walk, in this case with `g(n)` = `α n^(β)`![Image](images/B9780443218576000163/si53.png), with `α` = 0.30![Image](images/B9780443218576000163/si89.png), `β` = 0.54![Image](images/B9780443218576000163/si90.png), and `ϵ` = 0.01![Image](images/B9780443218576000163/si91.png). It is unclear if the yellow curve will ever cross again the horizontal axis after ![Image](images/B9780443218576000163/fx001.jpg)iterations, but it is expected to do so. To the contrary, the other three curves (gray, red, blue) are guaranteed to cross the horizontal axis infinitely many times, even though the random variable `T` measuring the spacing between two crossings (referred to as the `hitting time` in Section [12.1.1](#Chp012_229-241_B9780443218576000163.xhtml#s0015)) has infinite expectation.

For pure random walks (the gray curve in [Fig. 12.1](#Chp012_229-241_B9780443218576000163.xhtml#f0010)), the average number of times that `S[k]` = 0![Image](images/B9780443218576000163/si16.png) when 0 < `k` ≤ 2`n`![Image](images/B9780443218576000163/si92.png) is asymptotically equal to `` `$\\sqrt{4n/\\pi}` ``![Image](images/B9780443218576000163/si93.png), as discussed in Section [12.1.1](#Chp012_229-241_B9780443218576000163.xhtml#s0015). One would expect this value to be about 178 when ![Image](images/B9780443218576000163/fx004.jpg). For the gray curve, the observed value is 243. Keep in mind that huge variations are expected between different realizations of the same random walk, due to the fact that `E[T]` = ∞![Image](images/B9780443218576000163/si28.png). Indeed, averaged over three realizations, the value 243 was down to 185. Also, a faulty pseudorandom number generator could easily lead to results that are off, in this case.

One would expect much larger values for the “nonrandom” red and blue curves. The observed values are respectively 747 and 1783, based on a single realization in each case. Likewise, the yellow curve is expected to have a much smaller value: in [Fig. 12.1](#Chp012_229-241_B9780443218576000163.xhtml#f0010), that value is 105.

## 12.2 Related stochastic processes

There are countless types of random walks or quasi-Brownian motions that are – on purpose and by design – not perfectly random. One could write an encyclopedia on this topic. A good reference is the book by Mörters and Peres [\[8\]](#Chp012_229-241_B9780443218576000163.xhtml#br0040), published in 2010. My goal in this section is to present two examples (one in two dimensions) that are very recent, interesting, and related to the material discussed in Section [12.1](#Chp012_229-241_B9780443218576000163.xhtml#s0010). I built these stochastic processes in the last two years, to address modeling issues with fintech applications in mind.

### 12.2.1 From Brownian motions to clustered Lévy flights

Here I discuss a 2D Brownian motion generated using some specific probability distributions. Depending on the parameters, these distributions may or may not have an infinite expectation or variance. Things start to get interesting when the expectation becomes infinite (and the Brownian motion is no longer Brownian), resulting in a system exhibiting a strong clustering structure.
