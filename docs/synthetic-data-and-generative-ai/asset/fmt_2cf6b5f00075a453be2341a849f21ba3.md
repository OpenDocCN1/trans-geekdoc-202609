
Remember, `U[k]`![Image](images/B9780443218576000059/si105.png) is a row vector, and `θ` is a column vector; the dot product `U[k]θ`![Image](images/B9780443218576000059/si99.png) is a real number. Also, `V[k]`![Image](images/B9780443218576000059/si106.png) is the binary response attached to the `k`th observation, while `U[k]`![Image](images/B9780443218576000059/si105.png) is the corresponding `m`-dimensional feature vector, both in the original (`v`, `u`)![Image](images/B9780443218576000059/si101.png)-space. The empirical distribution `F[θ]`![Image](images/B9780443218576000059/si103.png) is computed as follows: `F[θ](t)`![Image](images/B9780443218576000059/si107.png) is the proportion of observed feature vectors, among `U[1]`, …, `U[n]`![Image](images/B9780443218576000059/si108.png), satisfying `U[k]θ ≤ t`![Image](images/B9780443218576000059/si109.png). Such a method could be called `CDF regression`. You can use the methodology presented here to solve it, but it would be very computer-intensive, because `F[θ]`![Image](images/B9780443218576000059/si103.png) depends on `θ` in a nonobvious way. The predicted value for `V[k]`![Image](images/B9780443218576000059/si106.png), is `F[θ^*](U[k]θ^*)`![Image](images/B9780443218576000059/si110.png) in this case.

### 1.3.2 Ellipsoid and hyperplane fitting

This is a fundamental example, with hyperplanes being a particular case of ellipsoids. I illustrate the methodology with an example based on synthetic data, in a small dimension. The idea is to represent the shape with a quadratic form. In two dimensions, the equation is

`θ[0]x² + θ[1]xy + θ[2]y² + θ[3]x + θ[4]y + θ[5] = 0`.

![Image](images/B9780443218576000059/si111.png)

The trick is to rewrite it with artificial variables `w[0] = x²`![Image](images/B9780443218576000059/si112.png), `w[1] = xy`![Image](images/B9780443218576000059/si113.png), `w[2] = y²`![Image](images/B9780443218576000059/si114.png), `w[3] = x`![Image](images/B9780443218576000059/si115.png), `w[4] = y`![Image](images/B9780443218576000059/si116.png), `w[5] = 1`![Image](images/B9780443218576000059/si117.png), so that we can use the general framework with `g(w, θ) = wθ`![Image](images/B9780443218576000059/si46.png). Again, `wθ` is the dot product. To avoid the trivial solution `θ^* = 0`![Image](images/B9780443218576000059/si118.png), let us add the constraint `θ^T θ = 1`![Image](images/B9780443218576000059/si59.png), that is, `η(θ) = θ^T θ - 1`![Image](images/B9780443218576000059/si43.png). Then, `θ^*`![Image](images/B9780443218576000059/si10.png) is solution of the system

$\\left\\{ \\begin{aligned} {(W^{T}W - \\lambda I)\\theta} & {= 0,} \\\\ {\\theta^{T}\\theta} & {= 1.} \\\\ \\end{aligned} \\right.$

![Image](images/B9780443218576000059/si119.png)(1.6)

The above solution is correct in any dimension. It is a direct application of [(1.2)](#Chp001_1-34_B9780443218576000059.xhtml#deq2). Here `W` is the `n × 6`![Image](images/B9780443218576000059/si120.png) matrix containing the `n` observations. Thus, `W[k0] = X[k]²`![Image](images/B9780443218576000059/si121.png), `W[k1] = X[k]Y[k]`![Image](images/B9780443218576000059/si122.png), `W[k2] = Y[k]²`![Image](images/B9780443218576000059/si123.png), `W[k3] = X[k]`![Image](images/B9780443218576000059/si124.png), `W[k4] = Y[k]`![Image](images/B9780443218576000059/si125.png), `W[k5] = 1`![Image](images/B9780443218576000059/si126.png). The Python code and additional details, for a slightly different version with a slightly different `η(θ)`![Image](images/B9780443218576000059/si87.png), can be found [here](https://scipython.com/blog/direct-linear-least-squares-fitting-of-an-ellipse/). I use it in my own code, available on my GitHub repository, [here](https://github.com/VincentGranville/Machine-Learning/blob/main/Source%20Code/fittingEllipse.py), under the name `fittingEllipse.py`. It is based on Halir's article about fitting ellipses [\[2\]](#Chp001_1-34_B9780443218576000059.xhtml#br0010).

The Python code checks if the fitted shape is actually an ellipse. However, in the spirit of my methodology, it does not matter if it is an ellipse, a parabola, a hyperbola, or even a line. The uniqueness of the solution is unimportant: indeed, if two very different solutions (say, an ellipse and a parabola) yield the same minimum mean squared error and are thus both optimal, it says something about the data set, something interesting to know. However, it would be interesting to compute `R²(θ^*)`![Image](images/B9780443218576000059/si66.png) using formula [(1.4)](#Chp001_1-34_B9780443218576000059.xhtml#deq4), where `θ^*`![Image](images/B9780443218576000059/si67.png) corresponds to a circle. It would tell whether the full model (ellipse) offers a significant improvement over the circle submodel.

Ellipsoid fitting shares some similarities with multivariate polynomial regression [\[7\]](#Chp001_1-34_B9780443218576000059.xhtml#br0035). The differences are:

*   • Ellipse fitting is a “full” model; in the polynomial regression `y = θ[1] + θ[2]x + θ[3]x²`![Image](images/B9780443218576000059/si127.png), the terms `y²`![Image](images/B9780443218576000059/si128.png) and `xy` are always missing.
*   • Polynomial regression fits a curve that is unbounded, such as `y = x²`![Image](images/B9780443218576000059/si129.png), resulting in poor fitting; to the contrary, in ellipse fitting (if the solution is actually an ellipse) the solution is bounded.
*   • To get as many terms in polynomial regression as in ellipse fitting, the only way is to increase the degree of the polynomial, which further increases the instability of the solution.

Finally, Umbach [\[6\]](#Chp001_1-34_B9780443218576000059.xhtml#br0030) proposes a different approach to ellipse fitting. It is significantly more complicated, and indeed, they stopped at the circle. In short, their method directly estimates the center, semiaxis lengths, and rotation angle via least squares, as opposed to estimating the coefficients in the quadratic form that represents the ellipse. More on parametric curves can be found in Chapter [6](#Chp006_103-111_B9780443218576000102.xhtml) on shape recognition.

#### 1.3.2.1 Curve fitting: 250 examples in one video

Ellipse fitting is performed by setting `mode='CurveFitting'` in the Python code. The program automatically creates a number of ellipses, specified by their parameters (center, lengths of semiaxes, and rotation angle), then generates a different training set for each ellipse, and outputs the result of the fitting procedure as an image. The images are then bundled together to produce a video, and an animated gif. Each image features a particular ellipse and training set, as well as the fitted ellipse based on the training set. The ellipse parameters are set by the variable `params` in the code: it is an array with five components. The number of ellipses is set by the parameter `nframes`, which also determines the number of frames in the output video.

Actually, the program does a little more: it works with ellipse arcs. Using the centroid of the training set to estimate the center of the ellipse does not work in this case. So the program retrieves the original, unknown ellipse even if the training set consists of points randomly distributed around a portion of that ellipse. The arc in question is determined by a lower and upper angle in polar coordinates, denoted respectively as `tmin` and `tmax` in the code, with `tmin=0` and `tmax=2π` corresponding to the full ellipse.
