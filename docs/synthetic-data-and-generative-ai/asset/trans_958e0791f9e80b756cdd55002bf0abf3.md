
每颗恒星的位置、速度和质量在每次迭代中都会更新，依据引力定律，基于其他恒星当前的接近度、速度和速度。允许负质量、恒星碰撞、新恒星生成和恒星分组（恒星团）。除了 `pos`、`vel` 和 `mass` 之外，还有一个名为 `col` 的额外数组，用于存储视频显示时每颗恒星的颜色。单个颜色会随时间变化，详见第 [15.2.1](#Chp015_277-292_B9780443218576000199.xhtml#s0020) 节。

### 15.2.1 颜色代码说明

除非用户通过选项 `threeClusters=True` 选择包含多个恒星团的模型，否则质量为正的恒星显示为蓝色，质量为负的恒星显示为红色。如果允许碰撞，恒星在吸收另一颗恒星后会变为橙色并保持该颜色。失败的恒星（被吞噬的那颗）质量被设为零，在视频中将不再可见：视频中恒星的大小在任何给定时间都与其质量成正比。初始化步骤后生成新恒星时，其颜色设为深紫色，无论质量符号如何。同样，如果它与另一颗恒星碰撞，会变为橙色。

如果选择包含三个恒星团的系统，恒星颜色将根据其初始所属的恒星团而为蓝色、绿色或品红色。这些系统目前不允许负质量或新恒星生成，主要是为了避免与配色方案冲突。同样，发生碰撞时，恒星颜色会变为橙色。

### 15.2.2 顶层参数详细说明

现在我将描述我的实现中所有可用的参数和功能，详见 [表 15.1](#Chp015_277-292_B9780443218576000199.xhtml#t0010)。建议阅读此表，因为它展示了 Python 程序提供的所有选项。寻找一组能说明特定系统类型的优秀参数并不容易。在第 [15.2.3](#Chp015_277-292_B9780443218576000199.xhtml#s0030) 节中，我描述了八组精心挑选的参数配置，涵盖了各种各样的情况。经过一点练习和常识判断，根据参数选择预测系统行为会变得更容易。

[表 15.1](#Chp015_277-292_B9780443218576000199.xhtml#cf0015)

恒星团模拟器中使用的顶层参数说明。

| Parameter | Description |
| --- | --- |
| `starBoost` | 如果绝对值大于 1，则在系统中创建一颗大质量恒星。例如，`starBoost=-5` 表示恒星表中位置 0 处的恒星具有负质量，其绝对值是其他任何恒星质量的 5 倍。 |
| `law` | 经典引力定律在其公式中使用 `r/||r||³`，其中 `||r||` 是两个相互作用天体之间的距离。这对应 `law=3`，但你可以尝试其他指数值。 |
| `speed` | 增加或减小恒星的初始速度。它对系统演化有重大影响，高速度可能超过逃逸速度或阻止循环轨道的发生。你可以选择 `speed=0`，意味着所有恒星初始静止。 |
| `zoom` | 指定可视化窗口。例如，`zoom=2` 表示视频中显示的天空区域为 `[-2,2]×[-2,2]`。 |
| `negativeMass` | 设为 `True` 时，恒星质量在生成时遵循高斯分布而非指数分布，且部分质量将为负。 |
| `collisions` | 默认不允许碰撞。设为 `True` 时，靠得非常近的恒星视为发生碰撞：一颗恒星吸收另一颗，其质量相应更新；另一颗恒星质量调整为零。 |
| `collThresh` | 确定两颗恒星多近会导致碰撞。`collThresh` 越小，碰撞越多。最大值为 `collThresh=1`，导致无碰撞。需要 `collisions=True`。 |
| `expand` | 某些配置导致恒星团随时间膨胀，观测窗口内的恒星越来越少。大于 `expand=1` 的值提供缩放效果，观测窗口随时间变大，给人观测点远离恒星团的印象，恒星随时间似乎在收缩，让你尽管恒星团在膨胀也能始终看到完整团块。相反，负值对应放大。 |
| `origin` | 没有“宇宙中心”，即没有绝对原点。设置 `origin='Centroid'` 使视野聚焦于系统移动的质心（在视频中它将是静止的）。如果你用参数 `starBoost` 添加了一颗大质量恒星，将此大恒星视为原点（设置 `origin='Star_0'`）是合理的。另一个选项是 `origin='Zero'`。 |
| `threeClusters` | Python 代码模拟一个恒星团。可通过 `threeClusters=True` 扩展可能性。目前不支持负质量或新恒星生成。 |
| `p`, `Nstars`, `N` | 最初从潜在的 `N` 颗恒星中开始有 `Nstars` 颗活跃恒星。活跃恒星位于恒星表的前列。非活跃恒星质量设为 0。每个新视频帧，以概率 `p` 将一颗非活跃恒星变为活跃，从而增加 `Nstars` 计数器。适合从极少恒星开始，观察系统如何演化直到拥有数百颗恒星，一些发生碰撞，一些吞噬较小恒星后变得越来越大。不支持负质量。对所有恒星间距离的依赖是当前实现的瓶颈。 |
| `dt`, `t`, `tend` | 参数 `dt` 代表时间增量，较大的 `dt` 导致视频播放更快。初始和结束时间分别为 `t` 和 `tend`。生成视频的帧数为 `(tend-t)/dt`。 |
| `G` | 引力参数。默认值为 1。也测试过较小值。 |
| `softening` | 增加两颗恒星间距离以避免距离消失时除以零。 |
| `createVideo` | 如果 `createVideo=True` 可能会减慢模拟速度。测试参数时设为 `False`，直到准备好生成视频。 |
| `saveData` | 输出文件 `nbody.txt` 每帧包含 `N` 行，每行 13 列。文件可能很大且生成缓慢。如果不需要，设置 `saveData=False`。无论如何，汇总碰撞信息（如有）的较小文件 `nbody_graph.py` 总会生成。 |
| `fps`, `my_dpi` | 分别为视频的每秒帧数和每英寸点数。`my_dpi` 超过 240 产生高分辨率但文件更大。`fps` 超过 20 产生的视频比 `fps` 设为 3 短得多。 |
| `adjustVel` | 如果为 `True`，将速度转换为质心系。为兼容原始版本。 |

### 15.2.3 有趣的参数集

为了展示算法的可能性，我创建了一个包含八组参数集的表格，涵盖广泛的情况。这些集合分为以下类别：

- 前两组包含非标准引力定律（`law=0.5`）的宇宙。此外，允许负质量。第一组有一颗大质量红色负质量恒星（`starBoost=-30`）：恒星团规律地膨胀和收缩，振荡更剧烈，并随时间形成子星团。第二组振荡更快，但更可预测。
- 第三组是标准宇宙。开始时很像第二组，但从不收缩。相反，它越来越膨胀，但膨胀速度和恒星速度随时间大幅减慢。
