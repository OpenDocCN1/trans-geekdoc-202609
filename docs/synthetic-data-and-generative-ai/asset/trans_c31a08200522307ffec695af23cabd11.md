
一旦整个状态被分类完毕（即图像上不再留有白色区域），每次后续循环都会在簇边界附近随机重新分配像素标签（即它们所属的簇）。这使得你能够计算位于两个或多个簇边界上的像素属于这些簇中任意一个的后验概率。这使得该方法类似于贝叶斯分类器 [[Wiki](https://en.wikipedia.org/wiki/Bayes_classifier)]。簇之间的边界在统计上随时间保持稳定：算法收敛，至少从随机角度来看是如此。

### 5.3.4 推广到高维空间

本章所有示例均为二维。这使得使用图像处理技术进行分类或聚类变得容易。在三维空间中，图像可被视频替代，仍可使用标准滤波技术。在四维空间中，问题变得更具挑战性。处理高维空间（甚至二维空间）问题的一种方法是使用张量 [[Wiki](https://en.wikipedia.org/wiki/Tensor)]。二维张量是标准矩形矩阵。三维张量是 `p × q × r` 矩阵，换句话说，是一个立方矩阵。三维张量的每个“切片”均可视为一幅图像。滤波器可适配此类数据。

在高维空间中，训练集仅占据整个空间的一小部分。尝试对整个空间进行分类已无意义：在 5 维及以上，这会变得时间成本过高。取而代之的是使用[稀疏张量](https://www.tensorflow.org/guide/sparse_tensor)。它们可表示为图结构，每个点连接到其邻居，再连接到邻居的邻居，以此类推，深度达 4 或 5 层。这仍在进行中。

### 5.3.5 迈向极快的实现

局部滤波窗口的大小 `w` 是瓶颈。使用第 [5.3.1](#Chp005_83-102_B9780443218576000096.xhtml#s0035) 节算法对图像进行滤波时，位置 `(x, y)` 处使用的窗口和位置 `(x + 1, y)` 处的下一个窗口，两者均包含 `(2w + 1)²` 个像素，但这两个窗口有 `(2w + 1)² - 2 × (2w + 1)` 个像素重叠。因此，不必每次访问 `(2w + 1)²` 个像素，而是可将重叠像素保存在一个 `(2w + 1)²` 的缓冲区中。访问一个像素并移动到右侧的下一个像素后，更新缓冲区只需更新缓冲区中的 `2w + 1` 个值：用新的 `2w + 1` 个最右侧像素衍生的值，覆盖对应旧的 `2w + 1` 个最左侧像素的列。

当使用 `method = 0`（快速滤波器）时，这会带来特别高效的实现。此时，`GD_util.py` 中的 `GD_Maps` 函数可进一步优化，因为它仅统计局部滤波窗口中像素（基于其颜色）的数量，而无需计算到窗口中心的距离。无论对于监督分类还是聚类，这都将按与 `w` 成正比的因子加速流程。由于我在代码中使用 `w = 20`（参数 `window`），改进效果显著。

## 5.4 Python 代码

Python 代码使用 `pillow` 和 `moviepy` 库。要安装 Pillow，请在 Windows 命令提示符中输入 `pip install pillow`。第 [5.4.1](#Chp005_83-102_B9780443218576000096.xhtml#s0065) 节中的程序 `PB_clustering_video.py` 是一段独立、简短且自包含的代码。它也是唯一生成视频（`MP4` 文件）的程序。你可能想先看它。参数 `s` 由全局变量 `s` 表示，称为缩放或扩散因子。它决定了簇之间的重叠程度。如果 `s = 0`，所有点均位于晶格上。如果 `s` 很大（例如 `s > 5`），点几乎均匀分布；无论使用何种算法，聚类都变得毫无意义。

第 [5.4.2](#Chp005_83-102_B9780443218576000096.xhtml#s0070) 节中的主程序 `PB_NN.py` 不包含任何视频/图像处理。然而，它需要 `GD_util.py`（见第 [5.4.3](#Chp005_83-102_B9780443218576000096.xhtml#s0075) 节），这是我自制的仅包含一个函数 `GD_Maps` 的小型库。所有图像处理均在该函数中执行。假设 `GD_util.py` 文件与 `PB_NN.py` 在同一文件夹中。`PB_NN.py` 的第 3 部分和第 4 部分处理计算所有类内距离的耗时计算。你不需要它，且它通过全局变量 `NNflag` 设为 `False` 而关闭。它仅为兼容我随机过程著作第一版中的旧 Perl 版本而提供。此 Python 版本在新版中取代了 Perl 代码。

`PB_NN.py` 的输出为 `PNG` 图像，每次迭代生成一张分类图和一张聚类图。输入为第 2 部分创建的合成数据，并在第 2 部分转换为位图（彩色像素数组）。图像滤波（从而进行分类和聚类）发生在第 5 部分：它包含对 `GD_maps` 函数的调用。如前所述，第 3 部分和第 4 部分被跳过。超参数 `window`（即图注中的 `w`）是局部滤波器的大小。要给一个点分配簇（即给像素分配颜色），局部滤波器由一个以该点为中心的 `(2w + 1) × (2w + 1)` 窗口组成。迭代（若为神经网络则称为层）在图注中称为“循环”。迭代次数由代码中的变量 `nloop` 决定。最后，`Nprocess` 是簇的数量，`method` 决定滤波器类型。该方法已在 `method = 1` 下进行广泛测试，若 `w` 很大则耗时较长。注意 `method = 0` 仍能提供令人满意的结果，且可按第 [5.3.5](#Chp005_83-102_B9780443218576000096.xhtml#s0055) 节所述以极高效的方式实现。

对于颜色，我使用 **RGBA** 模型 [[Wiki](https://en.wikipedia.org/wiki/RGBA_color_model)]。不过目前颜色向量的 A 分量或第四个元素（即透明度）尚未使用。未来版本的代码可能会以类似第 [4](#Chp004_61-82_B9780443218576000084.xhtml) 章所述监督分类技术的方式使用它。
