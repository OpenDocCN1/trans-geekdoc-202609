
If the sequence `b[n]`![Image](images/B9780443218576000175/si36.png) converges, the function `f` is continuous and `μ ≠ 0`![Image](images/B9780443218576000175/si37.png), then `b[n]`![Image](images/B9780443218576000175/si38.png) must converge to some `b^*`![Image](images/B9780443218576000175/si39.png) such that `f(b^*) = 0`![Image](images/B9780443218576000175/si40.png), thus `b[n]`![Image](images/B9780443218576000175/si38.png) converges to a root of `f`. You can allow `μ` to depend on `n`, and in one example I successfully used `μ = 1/√(b_n)`![Image](images/B9780443218576000175/si41.png). The function `f` used here is actually the function `f[3]`![Image](images/B9780443218576000175/si29.png) defined in Section [13.2.1](#Chp013_243-258_B9780443218576000175.xhtml#s0025) and pictured in blue (dark gray in print version) in [Fig. 13.3](#Chp013_243-258_B9780443218576000175.xhtml#f0020). This function is not even continuous, and the fixed point iteration does not converge. Other functions are investigated in Section [13.3](#Chp013_243-258_B9780443218576000175.xhtml#s0040). Here, the purpose is to explain how the fixed point iteration can help find a root despite the lack of convergence.

Many of the parameters in the Python code are described in Section [13.2.1](#Chp013_243-258_B9780443218576000175.xhtml#s0025), including offset, slope, and logeps. The parameter eps corresponds to `ϵ` in Section [13.1.1](#Chp013_243-258_B9780443218576000175.xhtml#s0015). The main parameters driving the fixed-point iteration are:

- `mu`, corresponding to `μ` in formula [(13.2)](#Chp013_243-258_B9780443218576000175.xhtml#deq4). A large value results in bigger jumps in the fixed point iteration, allowing you to find a root faster, but with an increased risk of missing all roots when `μ` becomes too large.
- `window`, corresponding to `w` in Section [13.2.1](#Chp013_243-258_B9780443218576000175.xhtml#s0025). A large `w` increases your chances of finding a root. The price to pay is reduced precision. If `b^*`![Image](images/B9780443218576000175/si39.png) is a root and the fixed point iteration succeeds in locating it, it will not find `b^*`![Image](images/B9780443218576000175/si39.png), but instead, it will tell you that there might be a root in the interval `[b^* - w, b^* + w]`![Image](images/B9780443218576000175/si42.png), without knowing what the actual `b^*`![Image](images/B9780443218576000175/si39.png) is. Thus a large `w` is useful to get a rough approximation of where a root is located.

I illustrate these features, as well as how fast this algorithm is compared to brute force, on a real example in Section [13.2.3](#Chp013_243-258_B9780443218576000175.xhtml#s0035). The algorithm does not converge with the type of functions discussed here: the successive iterates `b[n]`![Image](images/B9780443218576000175/si38.png) become larger and larger as `n` increases, or they may oscillate without ever converging. Of course, if the function is smooth enough and with the right parameters, it will converge. But we are not interested in that case.

Since there is no convergence in my examples, how can the algorithm detect a root? Now I explain how it works. First, define `Δ[n] = b[n] - b[n-1]`![Image](images/B9780443218576000175/si43.png). Then let `ρ[n] = Δ[n] / Δ[n-1]`![Image](images/B9780443218576000175/si44.png). The number `ρ[n]`![Image](images/B9780443218576000175/si16.png) is called the `signal` at iteration `n`. Usually, `ρ[n] ≈ 1`![Image](images/B9780443218576000175/si45.png). If `ρ[n]`![Image](images/B9780443218576000175/si16.png) is unusually low or high, we say that the signal is strong. In my examples, a value `ρ[n] > 2`![Image](images/B9780443218576000175/si46.png) usually means that there is a root close to `b[n-1]`![Image](images/B9780443218576000175/si47.png). Details are discussed in Section [13.2.3](#Chp013_243-258_B9780443218576000175.xhtml#s0035).

Finally, the functions investigated here have many values close to zero. The brute force method consisting of testing a very large number of values may not even work. In most cases, finding `b` such that `f[0](b) = 0.001`![Image](images/B9780443218576000175/si48.png) does not mean that there is a `b^*`![Image](images/B9780443218576000175/si39.png) close to `b` such that `f[0](b^*) = 0`![Image](images/B9780443218576000175/si49.png). For the same reason, the efficient but naive `bisection method` [[Wiki](https://en.wikipedia.org/wiki/Bisection_method)] will also fail. Note that my method is empirical: a strong signal does not always correspond to a root, and the absence of strong signal does not mean that there is no root. Testing with different parameter sets helps.

### 13.2.3 Case study: factoring a product of two large primes

The goal here is to find at least one of the two roots of the function `f[0](b)`![Image](images/B9780443218576000175/si50.png) pictured in [Fig. 13.1](#Chp013_243-258_B9780443218576000175.xhtml#f0010), and defined by [(13.1)](#Chp013_243-258_B9780443218576000175.xhtml#deq1). Using the transformations described in Section [13.2.1](#Chp013_243-258_B9780443218576000175.xhtml#s0025), I will actually work with the third transform `f[3](b)`![Image](images/B9780443218576000175/si51.png) in the fixed point iteration (formula [(13.2)](#Chp013_243-258_B9780443218576000175.xhtml#deq4)), starting with `b[0] = 2000`![Image](images/B9780443218576000175/si52.png). The two roots are the two prime factors of `a = 7919 × 3083`![Image](images/B9780443218576000175/si53.png), that is, `b^* = 3083`![Image](images/B9780443218576000175/si54.png) and `b^* = 7919`![Image](images/B9780443218576000175/si55.png). So finding one root makes it straightforward to find the other.

Finding the roots of `f[0]`![Image](images/B9780443218576000175/si20.png) is the same as finding the roots of `g(b) = 2 - cos(2πb) - cos(2πa/b)`![Image](images/B9780443218576000175/si14.png) pictured in [Fig. 13.2](#Chp013_243-258_B9780443218576000175.xhtml#f0015). The parameters values are those in the Python code in Section [13.3.3](#Chp013_243-258_B9780443218576000175.xhtml#s0065). The results are displayed in [Table 13.1](#Chp013_243-258_B9780443218576000175.xhtml#t0010), Fig. [13.4](#Chp013_243-258_B9780443218576000175.xhtml#f0025) and [13.5](#Chp013_243-258_B9780443218576000175.xhtml#f0030). The root `b^* = 3083`![Image](images/B9780443218576000175/si54.png) is detected at iteration `n = 31`![Image](images/B9780443218576000175/si56.png). Since `ρ[31] = 4.72`![Image](images/B9780443218576000175/si57.png) is exceptionally high, there is a strong possibility that the algorithm stepped over a root in the previous iteration (`n = 30`![Image](images/B9780443218576000175/si58.png)). Indeed, `b[30] = 3086.18`![Image](images/B9780443218576000175/si59.png) is close to the root `b^* = 3083`![Image](images/B9780443218576000175/si54.png). What the algorithm tells is that there is probably a root in the interval `[b[30] - w, b[30] + w]`![Image](images/B9780443218576000175/si60.png) where `w` is the size of the window (the parameter `window` in the Python code) set to 5 here.
