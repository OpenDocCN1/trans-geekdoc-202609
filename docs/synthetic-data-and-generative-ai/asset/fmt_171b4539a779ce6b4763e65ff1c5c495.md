### 11.3.1 Fixes to the faulty random function in Python

The default Python function to generate pseudorandom numbers is `random.random()`, available in the `random` library. It is based on the `Mersenne twister` congruential generator [[Wiki](https://en.wikipedia.org/wiki/Mersenne_Twister)], and documented [here](https://docs.python.org/3/library/random.xhtml). As discussed in Section [11.2.2](#Chp011_203-228_B9780443218576000151.xhtml#s0040), it is not suitable for cryptographic and other applications where pure randomness is critical. Indeed, the documentation comes with the following warning: “The pseudorandom generators of this module should not be used for security purposes”.

One way to improve `random.random()` is to avoid particularly bad seeds, such as 200 or 4, in the `random.seed()` call. You may also use binary digits of some `quadratic irrational numbers` [[Wiki](https://en.wikipedia.org/wiki/Quadratic_irrational_number)], using the Python code in Section [11.3.2](#Chp011_203-228_B9780443218576000151.xhtml#s0065). Again, it is a good idea to check, using the prime test proposed in this chapter, which irrational numbers to avoid. Also this method may be slow, as it involves working with very big integers. A workaround is to store large tables of precomputed digits in a secure location. The number of quadratic irrationals you can choose from is infinite. Also, your digit sequence should never start with the first binary digit of such numbers, but rather at a random position, to make hacking more difficult.

For instance, to generate your sequence `d(k)`![Image](images/B9780443218576000151/si17.png), set `d(3*k)`![Image](images/B9780443218576000151/si150.png) to `δ(g[1](k), α[1])`![Image](images/B9780443218576000151/si151.png), set `d(3*k + 1)`![Image](images/B9780443218576000151/si152.png) to `δ(g[2](k), α[2])`![Image](images/B9780443218576000151/si153.png), and set `d(3*k + 2)`![Image](images/B9780443218576000151/si154.png) to `δ(g[3](k), α[3])`![Image](images/B9780443218576000151/si155.png) where

- The numbers `α[1]`, `α[1]`, `α[3]`![Image](images/B9780443218576000151/si156.png) are three quadratic irrationals, say $\sqrt{2},\sqrt{10},\sqrt{41}$![Image](images/B9780443218576000151/si157.png),
- The number `(δ(k, α) + 1)/2`![Image](images/B9780443218576000151/si158.png) is the `k`th binary digit of the quadratic irrational `α`,
- The functions `g[1]`, `g[2]`, `g[3]`![Image](images/B9780443218576000151/si159.png) are used for scrambling: for instance, `g[1](k) = 5 * 10^5 + 2*k`![Image](images/B9780443218576000151/si160.png), `g[2](k) = 3 * 10^5 + 3*k`![Image](images/B9780443218576000151/si161.png), and `g[3](k) = 7 * 10^6 - k`![Image](images/B9780443218576000151/si162.png).

Another solution is to use for your sequence `d(k)`![Image](images/B9780443218576000151/si17.png) a `bitwise XOR` [[Wiki](https://en.wikipedia.org/wiki/Bitwise_operation)] on two pseudorandom sequences: the binary digits of (say) $\sqrt{2}$![Image](images/B9780443218576000151/si111.png) and $\sqrt{41}$![Image](images/B9780443218576000151/si163.png), starting at arbitrary positions.

There are also Python libraries that provide solutions suitable for cryptographic applications. For instance, `os.urandom()` uses the operating system to create random sequences that cannot be seeded, and are thus not replicable. See [here](https://docs.python.org/3/library/os.xhtml#os.urandom) and [here](https://docs.python.org/3/library/secrets.xhtml#module-secrets).

### 11.3.2 Prime test implementation to detect subtle flaws in PRNGs

The code presented here performs the prime test, computing `L[3](n)`![Image](images/B9780443218576000151/si58.png). The variable `nterms` represents `n`, and it is set to ![Image](images/B9780443218576000151/fx007.jpg). Rather than directly computing `L[3](n)`![Image](images/B9780443218576000151/si58.png), the code iteratively computes more granular statistics, namely `minL` and `maxL`; `L[3](n)`![Image](images/B9780443218576000151/si58.png) is the maximum between `-minL` and `maxL`, obtained at the last iteration.

The seeds and the sequences are initialized in the main part, at the bottom. The default category `nonSquare` is used for `L[3]`![Image](images/B9780443218576000151/si164.png). The other categories, `Prime` and `All`, are respectively for `L[1]`![Image](images/B9780443218576000151/si165.png) defined in formula [(11.5)](#Chp011_203-228_B9780443218576000151.xhtml#deq5) and `L[4]`![Image](images/B9780443218576000151/si132.png) defined in formula [(11.6)](#Chp011_203-228_B9780443218576000151.xhtml#deq6). If you use the function `createSignHash()` rather than the default `createSignHash2()`, you can easily compute `L[2]`![Image](images/B9780443218576000151/si166.png). The code is somewhat long only because it covers all the options discussed in Section [11.2.2](#Chp011_203-228_B9780443218576000151.xhtml#s0040), and more. It heavily relies on hash tables (dictionaries in Python) rather than arrays, because the corresponding arrays would be rather sparse, consume a lot of memory, and slow down the computations. In addition, the code can easily handle Beurling primes (noninteger primes) thanks to the hash tables. A lengthier version named `dirichletL.py`, computing the orbit of `L[P](z, χ)`![Image](images/B9780443218576000151/si14.png) for `z` in the complex plane when $\sigma = \Re(z) \geqslant \frac{1}{2}$![Image](images/B9780443218576000151/si167.png) is fixed, for any set of primes `P` (finite or infinite) including Beurling primes, is available on GitHub, [here](https://github.com/VincentGranville/Experimental-Math-Number-Theory/blob/main/Source-Code/dirichletL.py).

The Python code does not use any exotic library other than `primePy`. To install this library, type in the command `pip install primePy` on the Windows command prompt or its Unix equivalent, as you would to install any library. There is a possibility that some older versions of Python would require the `BigNumber` library. The code was tested under Python 3.10. The source code, featured below, is also on GitHub: look for [randomNumbersTesting.py](https://github.com/VincentGranville/Experimental-Math-Number-Theory/blob/main/Source-Code/randomNumbersTesting.py).

### 11.3.3 Special formula to compute 10 million digits of $\sqrt{2}$![Image](images/B9780443218576000151/si111.png)

The purpose of this code is twofold: to show you how to process integers with millions of digits in Python, and to offer a simple mechanism to compute the binary digits of some quadratic irrational numbers such as $\sqrt{2}/2$![Image](images/B9780443218576000151/si124.png). The first problem is solved transparently with no special code or library in Python 3.10. In short, this is a nonissue. With older versions of Python, you might have to install the `BigNumber` library. See documentation [here](https://pypi.org/project/BigNumber/). Nevertheless, it would be a good idea to track the size of the integers that you are working with (`y` and `z` in my code), as eventually their size will become the bottleneck, slowing down the computations.
