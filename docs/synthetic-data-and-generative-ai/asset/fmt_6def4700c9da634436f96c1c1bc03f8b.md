
## 18.5 Keyword Taxonomy and Clustering

The technique allows you to find related keywords or synonyms, and can be combined with using a table of synonyms, to generate text in the context of **natural language generation** [[Wiki](https://en.wikipedia.org/wiki/Natural_language_generation)]. It is one of the core components of many **large language models** [[Wiki](https://en.wikipedia.org/wiki/Language_model)] such as **ChatGPT** [[Wiki](https://en.wikipedia.org/wiki/ChatGPT)]. Here I do not cover basic steps such as cleaning the data using **stop words** [[Wiki](https://en.wikipedia.org/wiki/Stop_word)], **n-gram** permutations [[Wiki](https://en.wikipedia.org/wiki/N-gram)], using a dictionary of synonyms, fixing typos, handling special characters, **text normalization** [[Wiki](https://en.wikipedia.org/wiki/Text_normalization)] using **regular expressions** [[Wiki](https://en.wikipedia.org/wiki/Regular_expression)], and so on. This can be found in any elementary introduction on natural language processing.

### 18.5.1 Designing a keyword taxonomy

Here I discuss an algorithm to perform fast clustering on big data sets, as well as the graphical representation of such complex clustering structures. By fast, I mean a **computational complexity** [[Wiki](https://en.wikipedia.org/wiki/Computational_complexity)] of order `O(n)`![Image](images/B9780443218576000229/si126.png). This is much faster than **hierarchical agglomerative clustering** [[Wiki](https://en.wikipedia.org/wiki/Hierarchical_clustering)] which are typically `O(n²log n)`![Image](images/B9780443218576000229/si127.png). By big data, I mean several millions, possibly billions of observations.

The application in mind is the creation of a keyword, product or document taxonomy. In particular, I want to create a keyword taxonomy from scratch, based on crawling billions of webpages to extract and cluster keywords into categories. This is a typical unsupervised natural language processing (NLP) problem. The proposed algorithm is as follows:

#### Step 1: Preprocessing

You gather billions of keywords over the Internet by crawling (say) Wikipedia or Google results, clean the results, and compute the frequencies for each keyword and for each “keyword pair”. A “keyword pair” is two keywords found on the same webpage, or close to each other on the same web page. Also by keyword, I mean an entity like “California insurance”, so a keyword usually contains more than one token, but rarely more than three. You then can create a keyword table, where each entry is a pair of keywords followed by three counts, such as `A="California insurance"`, `B="home insurance"`, `x=543`![Image](images/B9780443218576000229/si128.png), `y=998`![Image](images/B9780443218576000229/si129.png), `z=11`![Image](images/B9780443218576000229/si130.png) where

*   `x` is the number of occurrences of keyword `A` in all the web pages crawled,
*   `y` is the number of occurrences of keyword `B` in all the web pages crawled,
*   `z` is the number of occurrences where `A` and `B` form a pair (e.g., they are found on a same page).

You can build the keyword table using a distributed architecture. The vast majority of keywords `A` and `B` do not form a “keyword pair”. In other words, `z=0`![Image](images/B9780443218576000229/si131.png) most of the time. So by ignoring these null entries, your final keyword table can be stored in memory as a **hash table** (see Section [18.4.3](#Chp018_361-386_B9780443218576000229.xhtml#s0095)) where the key is `(A, B)`![Image](images/B9780443218576000229/si132.png) and the value attached to a key is `(x, y, z)`![Image](images/B9780443218576000229/si133.png). Let us name this table `Keyword`.

#### Step 2: Clustering

To create a taxonomy, you want to group the keywords into similar clusters. The **cosine distance** [[Wiki](https://en.wikipedia.org/wiki/Cosine_similarity)] measuring the distance between two keywords or web pages, is popular in this context. To perform keyword clustering, I use the following **dissimilarity metric** `d(A, B)`![Image](images/B9780443218576000229/si134.png) to compare two keywords `A`, `B`: `$d(\text{A},\text{B}) = z/\sqrt{xy}$`![Image](images/B9780443218576000229/si135.png), although other choices are possible. This metric is known as the **Otsuka–Ochiai coefficient**. Note that the denominator prevents extremely popular keywords (for instance, “free”) from being close to all the keywords, and from dominating the entire keyword relationship structure: indeed, it favors better keyword bonds, such as “lemon” with “law” or “pie”, rather than “lemon” with “free”. The larger the `d(A, B)`![Image](images/B9780443218576000229/si136.png), the closer the keywords `A` and `B`. I describe the clustering part in Section [18.5.2](#Chp018_361-386_B9780443218576000229.xhtml#s0110).

### 18.5.2 Fast clustering algorithm for keyword data

Here I have `n=10⁷`![Image](images/B9780443218576000229/si137.png) unique keywords and `m=10⁸`![Image](images/B9780443218576000229/si138.png) keyword pairs `{A, B}`![Image](images/B9780443218576000229/si139.png) where `d(A, B)>0`![Image](images/B9780443218576000229/si140.png). That is, an average of `r=10`![Image](images/B9780443218576000229/si141.png) related keywords attached to each keyword. These keyword pairs are stored in the hash table `Keyword` created in the preprocessing step in Section [18.5.1](#Chp018_361-386_B9780443218576000229.xhtml#s0105). The algorithm builds the new hash tables `Hash` (the category table) and `Weight`. It proceeds incrementally as follows:

#### Initialization

The small data (or seeding) step. Select ![Image](images/B9780443218576000229/fx008.jpg)seed keywords, create (say) 100 categories, and create a hash table `Hash` where the key is one of the ![Image](images/B9780443218576000229/fx008.jpg)seed keywords, and the value is a list of categories the keyword is assigned to. For instance, `Hash['cheap car insurance']={'automotive','finance'}`. The choice of the initial ![Image](images/B9780443218576000229/fx008.jpg)seed keywords is very important. I suggest to pick up the top ![Image](images/B9780443218576000229/fx008.jpg)keywords, in terms of number of associations: that is, keywords `A` with many `B`'s where `d(A, B)>0`![Image](images/B9780443218576000229/si142.png). This will speed up the convergence of the algorithm.

#### The big data step

Browse the hash table `Keyword` from the beginning to the end. We now build the tables `Hash` and `Weight`. Let `(A, B)`![Image](images/B9780443218576000229/si132.png) be the current keyword pair in `Keyword`.

```
If Hash[A] exists and Hash[B] does not, do:
    Hash[B] = Hash[A]
    Weight[B] = d(A, B)
Else If Hash[A] does not exist and Hash[B] exists, do:
    Hash[A] = Hash[B]
    Weight[A] = d(A, B)
Else If Hash[A] and Hash[B] exist, recategorize:
    If d(A, B) > Weight[B] do:
        Hash[B] = Hash[A]
        Weight[B] = d(A, B)
    Else If d(A, B) > Weight[A] do:
        Hash[A] = Hash[B]
        Weight[A] = d(A, B)
```

You could replace `Hash[A]=Hash[B]` by `Hash[A]=Concatenate(Hash[A],Hash[B])`, and the other way around. This will increase the number of categories a keyword is assigned to. I did not test that option.

#### The loop

Repeat the “big data step” 6 or 7 times: `Hash` and `Weight` are kept in memory and keep growing at each subsequent iteration of the loop.

### 18.5.2.1 Computational complexity

The computational complexity is asymptotically `(N + 1)*m = O(n)`![Image](images/B9780443218576000229/si143.png), where `N` is the number of iterations in the loop. This is very fast. However, accessing the hash tables slows it down a bit as `Hash` and `Weight` grow bigger at each new iteration.
