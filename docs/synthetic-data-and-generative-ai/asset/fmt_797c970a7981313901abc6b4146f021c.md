
The first example is a YouTube data set with 2 tables, 2735 rows, and 10 columns. The number of rows ranges from 83 to over 6 million, and some data sets have over 300 features. The code in question also loads one data set (`student_placements_pii`), and shows how to use a GAN model based on `Gaussian copulas`. See output in [Fig. 10.1](#Chp010_169-201_B978044321857600014X.xhtml#f0020). The code is on GitHub, [here](https://github.com/VincentGranville/Main/blob/main/GAN_copula_SDV.py). Some of the fields such as the address are anonymized rather than synthesized. This is performed by implicitly calling the Python library `Faker`, described [here](https://pypi.org/project/Faker/). Also, you can choose the option `FAST_ML` for the optimizer (the gradient descent algorithm), for faster processing but with lower accuracy. This is done using the instruction `TabularPreset(name='FAST_ML', metadata=metadata)` as explained [here](https://medium.com/@davide.gazze/sdv-generate-synthetic-data-using-gan-and-python-4c26a1e4b3c2).

`SDV` is a black-box, so to illustrate the various steps of GAN in details, I use an implementation based on the `Keras` library instead. `Keras` is easier to use than `Tensorflow` [[Wiki](https://en.wikipedia.org/wiki/TensorFlow)], though it requires `Tensorflow` to be installed on your system. Another black-box alternative, allowing you to implement GAN for tabular data synthetization with just 3 lines of code, is `TabGAN`, available [here](https://github.com/Diyago/GAN-for-tabular-data). See [[1]](#Chp010_169-201_B978044321857600014X.xhtml#br0005) for a discussion. I had to install the most recent version of `Numpy` to get it to work. More generally, installing these libraries may also require the most recent version of `pip`, which you can get via the command `pip install –upgrade pip`. `TabGAN` uses `LightGBM` [[Wiki](https://en.wikipedia.org/wiki/LightGBM)], a fast version of gradient boosting, and it is thus a bit faster than my step-by-step version in Section [10.7](#Chp010_169-201_B978044321857600014X.xhtml#s0105).

Another implementation very similar to mine and illustrated on time series, is discussed [here](https://towardsdatascience.com/hands-on-generative-adversarial-networks-gan-for-signal-processing-with-python-ff5b8d78bd28). Mine includes a new version of `correlation matrix distance` to assess quality; see [here](https://www.researchgate.net/publication/4194743_Correlation_Matrix_Distance_a_Meaningful_Measure_for_Evaluation_of_Non-Stationary_MIMO_Channels) and [[5]](#Chp010_169-201_B978044321857600014X.xhtml#br0025) for a standard definition. It also uses a `seed` for every single source of randomness in the algorithm, allowing for full replicability, as well as other specific features. If you run the code in GPU, there might be additional sources of randomness that you cannot control. You can run the code (say `mycode.py`) with the following command line in that case, if replicability is important for your application:

```
CUDA_VISIBLE_DEVICES="" PYTHONHASHSEED=0 python mycode.py
```

Finally, there are various libraries to assess the quality of the synthetized data. I use `TableEvaluator` in my code in Section [10.7](#Chp010_169-201_B978044321857600014X.xhtml#s0105), along with home-made metrics that are more useful to me. `TableEvaluator` is described [here](https://pypi.org/project/table-evaluator/). There is not much documentation about it, but you can check out the full source code on GitHub, [here](https://github.com/Baukebrenninkmeijer/table-evaluator/blob/master/table_evaluator/table_evaluator.py). That is how I found out that the output metric called "`Base Statistics`" is a correlation distance between the real versus synthesized data, computed on various bivariate indicators as data points (mean, median, correlation between features, and so on, both for real and synthesized).

Additional reading on the subject includes the book "Synthetic Data for Deep Learning" [[9]](#Chp010_169-201_B978044321857600014X.xhtml#br0045), "Pros and Cons of GAN Evaluation Measures" [[2]](#Chp010_169-201_B978044321857600014X.xhtml#br0010), "Survey on Synthetic Data Generation, Evaluation Methods and GANs" [[3]](#Chp010_169-201_B978044321857600014X.xhtml#br0015), and "Are GANs Created Equal? A Large-Scale Study" by Google Brain [[7]](#Chp010_169-201_B978044321857600014X.xhtml#br0035). See also Lei Xu's master thesis (MIT, 2017) available [here](https://dai.lids.mit.edu/wp-content/uploads/2020/02/Lei_SMThesis_neo.pdf) and the related article on ArXiv [[10]](#Chp010_169-201_B978044321857600014X.xhtml#br0050), as well as [this article](https://www.maskaravivek.com/post/ctgan-tabular-synthetic-data-generation/). ## 10.4.2 Synthesizing medical data with GAN

Here I summarize my implementation of GAN applied to the Kaggle diabetes data set. First, I discuss the hyperparameters, then the main steps in the methodology. The data is processed "as is", without normalization or transformation. Possible transformations (preprocessing) are discussed in Section [10.5.1](#Chp010_169-201_B978044321857600014X.xhtml#s0095). However, I removed all the observations with missing values, for better comparison with the copula method. Anyway, it makes sense to treat these observations separately, as a different segment, by rerunning GAN on them only. Indeed, it produces better results when they are separated from the complete observations. After removing observations with missing values, we are left with 392 rows.

The data set has 9 features. One of them called `Outcome` is the response: it indicates whether or not the patient had cancer. Thus the problem is predicting – based on the remaining 8 features – the chance of getting cancer. It is a supervised classification problem with two groups: cancer versus noncancer.

The first part of the code (Section [10.7.1](#Chp010_169-201_B978044321857600014X.xhtml#s0110)) imports the libraries, reads the data, removes observations with missing values, and then performs the classification with the `random forest` algorithm [[Wiki](https://en.wikipedia.org/wiki/Random_forest)]. It also defines some global variables such as the `learning rate` [[Wiki](https://en.wikipedia.org/wiki/Learning_rate)] in the `Adam gradient descent`, and `seed` which allows for replicability by using the same value in each run. The quality of the classification is displayed on the screen, as the `Base Accuracy` metric.

The last part of the code (Section [10.7.3](#Chp010_169-201_B978044321857600014X.xhtml#s0120)) evaluates the quality of the synthetic data. It also performs the classification on the synthetic data, for comparison with the results obtained on the real data. It would be interesting to augment the real data by adding the synthetic data into it, and see if we get more robust predictions. The augmented data is not expected to increase accuracy; instead it is expected to increase robustness and reduce overfitting.
