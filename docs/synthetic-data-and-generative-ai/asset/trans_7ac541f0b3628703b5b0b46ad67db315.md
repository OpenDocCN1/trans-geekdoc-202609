

### 逼近狄利克雷 η 函数

`η(z)` 的狄利克雷级数![Image](images/B9780443218576000217/si29.png) 收敛非常缓慢且混乱，特别是当 `σ` 很小或 `t` 很大时。加速收敛的一种方法是使用**欧拉变换** [[Wiki](https://en.wikipedia.org/wiki/Series_acceleration)]。另请参阅 [[8]](#Chp017_329-360_B9780443218576000217.xhtml#br0040) 中的练习 25。还有其他近似方法，例如使用狄利克雷多项式 [[7]](#Chp017_329-360_B9780443218576000217.xhtml#br0035)。这里我研究另一种不同类型的近似。照常设 `z = σ + i t`，其中 `σ` 固定，例如 `σ = 0.8`![Image](images/B9780443218576000217/si444.png)。还假设 `η(σ + i k)`![Image](images/B9780443218576000217/si445.png) 的值是已知的，如果 `k` 是正整数，则记为 `η[k](σ)`![Image](images/B9780443218576000217/si446.png)。近似公式如下：

```
\eta(z) \approx \frac{\sin\pi t}{\pi} \cdot \left\lbrack \frac{\eta_{0}(\sigma)}{t} + 2t\sum\limits_{k = 1}^{n}{( - 1)}^{k}\frac{\eta_{k}(\sigma)}{t^{2} - k^{2}} \right\rbrack.
```

![Image](images/B9780443218576000217/si447.png)

展示该近似的效果如何。解答请见第 [8](#Chp008_131-145_B9780443218576000126.xhtml) 章的 [练习 8.2](#Chp008_131-145_B9780443218576000126.xhtml)。

### 17.5.1 计算各种狄利克雷级数的轨道

如果 `Dirichlet variable` 设置为 `True`，下面的代码计算 `η[P](z, χ)`；否则计算 `L[P](z, χ)`。更具体地说，它计算相关函数在 `z = σ + i t` 处的值，其中 `σ = ℜ(z) ≥ 0.5` 固定并由变量 `sig` 确定，以及 `t` 在 `minT` 和 `maxT` 之间取等间距值。间距由变量 `increment` 决定，通常设为 `0.01`。它使用狄利克雷级数展开，项数由 `nterms` 决定（通常设为 `2000`），以在 `σ = 0.5` 或 `t` 很大的最坏情况下获得至少 2 位数字的精度。`primePy` 库中的 `primes.check()` 函数用于测试一个数是否为素数。代码实际上处理了更一般的情况，即 `χ(p)` 被 `χ(p) ⋅ x^(ν(p))` 替代，其中 `ν(p) = 1/p` 如公式 [(17.12)](#Chp017_329-360_B9780443218576000217.xhtml#deq17) 所示，且 `0 < x ≤ 1`。标准情况对应 `x = 1`。代码中的变量 `x` 即代表 `x`。

`η[P](z, χ)` 或 `L[P](z, χ)` 的值是一个复数：其实部和虚部在代码中分别命名为 `etax` 和 `etay`。函数 `χ`，从而集合 `P`，取决于代码中选择的选项，由变量 `method` 决定：`Zeta`（即默认的 `ζ(z)`）、`Eta`、`Dirichlet4`（对应 `χ[4]`）、`Beurling`、`Alternating` 或 `Random`。请参考正文判断级数何时收敛或发散：特别是 `Zeta` 方法仅当 `σ > 1` 时收敛。

输出变量 `minL` 和 `maxL` 有助于判断收敛状态。它们在第 [11.2.1](#Chp011_203-228_B9780443218576000151.xhtml) 节关于伪随机数生成器的内容中有更详细的讨论。参数 `beta` 应设为 `0.5`，除非你想复现第 [17.3.1](#Chp017_329-360_B9780443218576000217.xhtml#s0065) 节讨论的实验，其中 `beta` 由 `β` 表示。同样，保持 `x` 设为 `1`，除非你想复现第 [17.3.2.4](#Chp017_329-360_B9780443218576000217.xhtml#s0090) 节的实验。最后，程序使用哈希表（Python 中的字典）而不是数组，以提高效率：这些数组会相当稀疏。源代码（如下）也在 GitHub 上：查找 [`DirichletL.py`](https://github.com/VincentGranville/Experimental-Math-Number-Theory/blob/main/Source-Code/dirichletL.py)。

### 17.5.2 创建轨道视频

本节的 Python 代码处理可视化方面：生成 `η[P](z, χ)` 三条轨道的数据动画（MP4 视频），其中 `P` 是素数全集，`χ(⋅)` 是常数函数 1。这是标准狄利克雷函数。相关的三条轨道分别对应 `σ = 0.5`、`σ = 0.75` 和 `σ = 1.25`。这三个值在代码中由 `sigma.append()` 指令设置。特别是 `σ = 0.5` 揭示了无限多个零点，而另外两个值显示没有零点。

输出视频可在我的 GitHub 仓库 [`here`](https://github.com/VincentGranville/Visualizations) 获取。视频也在 YouTube 上，[`here`](https://www.youtube.com/c/VincentGranvilleVideos)。为方便起见，Python 代码也包含在本章中。主要变量包括 `ShowOrbit`（若想显示轨道而非仅显示点，设为 `True`）、`dot`（点的大小）、`r`（按时间迭代时，每 `r` 次迭代输出一帧视频）、`width` 和 `height`（图像尺寸）。最终图像最终会因用于去像素化曲线的**抗锯齿**过程而缩小一半。这在代码的 `img.resize` 中执行，使用 `Image.LANCZOS` 参数 [[Wiki](https://en.wikipedia.org/wiki/Lanczos_resampling)]。连接轨道上两个点的线段（以创建平滑曲线轨道的外观）使用 `Pillow` 库及其 `ImageDraw` 函数生成。

减小图像尺寸和每秒帧数 (FPS) 将优化速度和磁盘使用。就速度而言，最大的改进是将所有 `numpy` 调用（`np.log`、`np.cos` 等）替换为 `math` 调用（`math.log`、`math.cos` 等）。如果你用 `numpy` 而非 `Pillow` 进行图像生成，情况可能相反（我未测试）。源代码也在 GitHub 上：查找 [`image3R_orbit_enhanced.py`](https://github.com/VincentGranville/Point-Processes/blob/main/Videos/image3R_orbit_enhanced.py)。
