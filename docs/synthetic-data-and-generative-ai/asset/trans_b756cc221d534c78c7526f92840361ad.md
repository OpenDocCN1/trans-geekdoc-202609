
第一个示例是一个包含 2 个表、2735 行和 10 列的 YouTube 数据集。行数范围从 83 行到 600 多万行不等，有些数据集拥有 300 多个特征。相关代码还加载了一个数据集（`student_placements_pii`），并展示了如何使用基于 `Gaussian copulas`（高斯 copula）的 GAN 模型。输出见 [图 10.1](#Chp010_169-201_B978044321857600014X.xhtml#f0020)。代码在 GitHub 上，[此处](https://github.com/VincentGranville/Main/blob/main/GAN_copula_SDV.py)。某些字段（如地址）是匿名化的，而非合成的。这是通过隐式调用 Python 库 `Faker` 来完成的，详见[此处](https://pypi.org/project/Faker/)。此外，您可以为优化器（梯度下降算法）选择 `FAST_ML` 选项，以加快处理速度，但会降低准确性。这是使用指令 `TabularPreset(name='FAST_ML', metadata=metadata)` 完成的，详情见[此处](https://medium.com/@davide.gazze/sdv-generate-synthetic-data-using-gan-and-python-4c26a1e4b3c2)。

`SDV` 是一个黑盒，因此为了详细说明 GAN 的各个步骤，我改用基于 `Keras` 库的实现。`Keras` 比 `Tensorflow` [[Wiki](https://en.wikipedia.org/wiki/TensorFlow)] 更易于使用，尽管它要求您的系统上已安装 `Tensorflow`。另一个黑盒替代方案是 `TabGAN`，它只需 3 行代码即可让您实现用于表格数据合成的 GAN，可在[此处](https://github.com/Diyago/GAN-for-tabular-data)获取。讨论见 [[1]](#Chp010_169-201_B978044321857600014X.xhtml#br0005)。我必须安装最新版本的 `Numpy` 才能使其工作。更广泛地说，安装这些库可能还需要最新版本的 `pip`，您可以通过命令 `pip install –upgrade pip` 获取。`TabGAN` 使用 `LightGBM` [[Wiki](https://en.wikipedia.org/wiki/LightGBM)]，这是梯度提升的一个快速版本，因此它比第 [10.7](#Chp010_169-201_B978044321857600014X.xhtml#s0105) 节中我的分步版本稍快一些。

另一个与我的实现非常相似且在时间序列上演示的实现，见[此处](https://towardsdatascience.com/hands-on-generative-adversarial-networks-gan-for-signal-processing-with-python-ff5b8d78bd28)讨论。我的实现包含一个新版本的 `correlation matrix distance`（相关矩阵距离）来评估质量；标准定义见[此处](https://www.researchgate.net/publication/4194743_Correlation_Matrix_Distance_a_Meaningful_Measure_for_Evaluation_of_Non-Stationary_MIMO_Channels)和 [[5]](#Chp010_169-201_B978044321857600014X.xhtml#br0025)。它还为算法中每一个随机源使用 `seed`（种子），从而实现完全可复现性，以及其他特定功能。如果您在 GPU 上运行代码，可能会有无法控制的额外随机源。在这种情况下，如果可复现性对您的应用很重要，您可以使用以下命令行运行代码（假设为 `mycode.py`）：

```
CUDA_VISIBLE_DEVICES="" PYTHONHASHSEED=0 python mycode.py
```

最后，有各种库可用于评估合成数据的质量。我在第 [10.7](#Chp010_169-201_B978044321857600014X.xhtml#s0105) 节的代码中使用了 `TableEvaluator`，以及一些对我更有用的自制指标。`TableEvaluator` 的说明见[此处](https://pypi.org/project/table-evaluator/)。关于它的文档不多，但您可以在 GitHub 上查看完整源代码，[此处](https://github.com/Baukebrenninkmeijer/table-evaluator/blob/master/table_evaluator/table_evaluator.py)。正是通过这种方式，我发现名为“`Base Statistics`”（基础统计量）的输出指标是真实数据与合成数据之间的相关距离，基于各种双变量指标作为数据点计算得出（均值、中位数、特征间相关性等，针对真实数据和合成数据均有计算）。

## 10.4.2 使用 GAN 合成医疗数据

这里我总结了将 GAN 应用于 Kaggle 糖尿病数据集的实现。首先，我讨论超参数，然后是方法论的主要步骤。数据按“原样”处理，不进行归一化或转换。可能的转换（预处理）在第 [10.5.1](#Chp010_169-201_B978044321857600014X.xhtml#s0095) 节中讨论。不过，我移除了所有含有缺失值的观测值，以便更好地与 copula 方法进行比较。无论如何，将这些观测值作为一个单独的片段单独处理，仅对它们重新运行 GAN，是合理的。事实上，当它们与完整观测值分开时，会产生更好的结果。移除含缺失值的观测值后，剩下 392 行。

该数据集有 9 个特征。其中一个名为 `Outcome` 的特征是响应变量：它指示患者是否患有癌症。因此，问题是基于剩余的 8 个特征预测患癌症的几率。这是一个包含两组的监督分类问题：癌症组与非癌症组。

代码的第一部分（第 [10.7.1](#Chp010_169-201_B978044321857600014X.xhtml#s0110) 节）导入库、读取数据、移除含缺失值的观测值，然后使用 `random forest`（随机森林）算法 [[Wiki](https://en.wikipedia.org/wiki/Random_forest)] 进行分类。它还定义了一些全局变量，例如 `Adam gradient descent`（Adam 梯度下降）中的 `learning rate`（学习率）[[Wiki](https://en.wikipedia.org/wiki/Learning_rate)]，以及 `seed`（种子），通过在每次运行中使用相同的值来实现可复现性。分类质量以 `Base Accuracy`（基础准确率）指标的形式显示在屏幕上。

代码的最后部分（第 [10.7.3](#Chp010_169-201_B978044321857600014X.xhtml#s0120) 节）评估合成数据的质量。它还在合成数据上执行分类，以便与真实数据上获得的结果进行比较。通过添加合成数据来增强真实数据，看看是否能获得更稳健的预测，这会很有趣。增强后的数据预计不会提高准确性；相反，预计会增加鲁棒性并减少过拟合。
