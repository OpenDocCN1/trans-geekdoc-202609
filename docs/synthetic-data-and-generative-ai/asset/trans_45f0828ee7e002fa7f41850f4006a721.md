
特别是，在我曾工作过的一家公司中，我编写了一个脚本，该脚本接受 SQL 代码作为输入（采用文本文件格式）以针对 Oracle 数据库运行查询，并培训分析师如何使用它来替代他们熟悉的仪表板。他们仍在使用仪表板（本例中为 Toad）生成 SQL 代码，但使用我的脚本运行实际查询。查询运行速度现在快了 10 倍：生产力提升巨大。

总之，Python 是机器学习的首选语言，R 是统计学家的语言，而 SQL 是业务和数据分析师的语言。

### 18.7.2 自动化数据清洗与探索性分析

据说数据科学家将 80% 的时间花在数据清洗和**探索性分析** [[Wiki](https://en.wikipedia.org/wiki/Exploratory_data_analysis)] 上。情况不应如此。对初学者而言，每个新数据集似乎都带来一组新挑战。随着时间的推移，你会意识到潜在问题只有那么几类。自动化数据清洗步骤可以节省大量时间，并消除枯燥、重复的任务。一个优秀的 Python 脚本能让你自动处理大多数问题。在此，我回顾最常见的问题。

首先，你需要为所有单独的特征创建一张汇总表：类型（数值型、分类数据、文本或混合型）。对于每个特征，获取前 5 个值及其频率。这可能会揭示错误或未分配的邮政编码，如 99999。查找其他特殊值，如 NaN（非数字）、N/A、不正确的日期格式、缺失值（空白）或特殊字符。例如，重音字符、逗号、美元符号、百分号等可能导致文本解析和**正则表达式** [[Wiki](https://en.wikipedia.org/wiki/Regular_expression)] 出现问题。计算数值特征的最小值、最大值、中位数及其他百分位数。检查超出范围的值：如果可能，在开始分析前从客户处获取预期范围。如果可能，对信用卡号码或 ID 字段等加密字段使用**校验和** [[Wiki](https://en.wikipedia.org/wiki/Checksum)]。

一些 Python 库可以处理这些工作，特别是 Pandas-Profiling、Sweetviz 和 D-Tale。详见[此处](https://medium.com/@karteekmenda93/exploratory-data-analysis-tools-83ef538c879f)。

下一步是查看特征间的交互。计算所有交叉相关性，并检查可忽略的冗余或重复特征。查找重复或几乎相同的 ID 或键。此外，两个不同的 ID 可能关联同一个个体。这可能揭示数据中的拼写错误。使用常见拼写错误表会有所帮助。此外，尽可能使用网页表单中的预填充字段收集数据，而不是让用户手动输入州、城市、邮政编码或日期等信息。最后，检查字段错位。这在 NLP 问题中频繁发生，例如 URL 等数据被解析并存储在 CSV 文件中，然后上传到数据库。现在你可以标准化数据了。

有时，数据存在超出你控制的问题。当我在富国银行工作时，Tealeaf 软件生成的互联网会话 ID 被拆分为多个小会话，导致用户 ID 错误且互联网会话时间极短。手动模拟此类会话并查看它们在数据库中是如何被跟踪的，有助于解开这个谜团，从而得出正确的分析。有时，最大的人群群体完全缺失于数据库中。例如，在新冠数据中，从未接受检测且自行康复的人（早期占绝大多数人口）未出现在任何数据库中，导致致死率为 6% 而非更准确的 1%，并带来高昂的公共政策后果。运用常识和跳出框架的思维来发现此类问题，并让利益相关者知情。应尽可能使用替代数据源。在本例中，污水数据——一种代理数据集——提供了答案。

### 18.7.3 简单分析示例：营销归因

有时，一个只需几天而非数周工作量、易于理解（如可解释 AI）的简单方案就足够了，且能让所有人满意。在 NBC 工作时，我被要求进行一些**营销归因**分析。该项目也称为营销组合建模 [[Wiki](https://en.wikipedia.org/wiki/Marketing_mix_modeling)]，旨在评估 20 个不同渠道（本例中为特定电视节目）对互联网流量增长的个别影响。

每周约有 12 个电视节目用于提升目标网站流量。收集的数据包括 GRP（综合评价点，衡量特定电视节目的电视受众规模）以及网站的独立用户数和新用户数。选定的电视节目根据库存可用性提前预订，无法单独测试：简而言之，无法使用**实验设计**技术 [[Wiki](https://en.wikipedia.org/wiki/Design_of_experiments)]，如 **A/B 测试** [[Wiki](https://en.wikipedia.org/wiki/A/B_testing)]。

我为每周创建了一个**标志向量**，包含 20 个分量：每个潜在电视节目对应一个。若特定电视节目在当周被使用，其对应分量设为 1，否则设为 0。随后，在排除重大假日周后，我比较了处于相似时间段的周（以避免季节性影响）。我的汇总表包含周对，如周 A 和周 B，以及 A 和 B 之间互联网流量的增减。此外，我选择了电视节目组合相同、仅有一个节目在 A 中缺失但 B 中存在（或反之）的周对 {A, B}。

于是，对于给定的电视节目，可以看出在特定周使用它与流量增长关联的频率是否高于流量下降。这识别出了表现最好和最差的电视节目。最终发现《法律与秩序》是赢家，并在可能的情况下更频繁地使用。
