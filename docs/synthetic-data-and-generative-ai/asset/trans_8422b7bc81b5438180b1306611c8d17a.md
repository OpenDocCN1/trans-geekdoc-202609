

## 18.4 特征子集的预测能力

### 18.4.1 加权与分箱

权重 `P[00]`、`P[01]`、`P[1,0]`、`P[11]`![Image](images/B9780443218576000229/si105.png) 确保了计数低的分箱对 `H` 的影响较小。对于观测值少于 20 个的任何分箱，将 `W(r)`![Image](images/B9780443218576000229/si106.png) 设为 0。例如，分箱“00”的频率是 `(n[1] + n[5])/(n[1] + ... + n[8])`![Image](images/B9780443218576000229/si107.png)，其大小或分箱计数是 `n[1] + n[5]`![Image](images/B9780443218576000229/si108.png)，而该分箱的 `r = P[00] = n[5]/(n[1] + n[5])`![Image](images/B9780443218576000229/si109.png)。如果 `n[1] + n[5] = 0`![Image](images/B9780443218576000229/si110.png)，则将 `P[00]`![Image](images/B9780443218576000229/si111.png) 设为 0，并将 `W(P[00])`![Image](images/B9780443218576000229/si112.png) 设为 0。我实际上建议不仅在 `n[1] + n[5] = 0`![Image](images/B9780443218576000229/si110.png) 时这样做，而且在 `n[1] + n[5] < 20`![Image](images/B9780443218576000229/si113.png) 时也这样做，尤其是在 `p` 很低的情况下。如果 `p` 非常低，例如 `p < 0.01`![Image](images/B9780443218576000229/si114.png)，则在构建训练集时需要对坏交易进行过采样，并相应地调整计数。当然，同样的规则也适用于 `P[01]`、`P[10]`![Image](images/B9780443218576000229/si115.png) 和 `P[11]`![Image](images/B9780443218576000229/si93.png)。

此外，应避免导致大量观测值分散在大量几乎为空的分箱中的特征子集，以及产生大量空分箱的特征子集：训练集之外的观测值很可能属于空或几乎为空的分箱，这会导致高方差预测。为避免这一缺点，请坚持使用二元特征，并尽可能使用少于 20 个特征。最后，`P[i,j]`![Image](images/B9780443218576000229/si116.png) 是概率 `P(A = i, B = j)`![Image](images/B9780443218576000229/si117.png) 的估计器，其中 `i`、`j` = 0, 1![Image](images/B9780443218576000229/si118.png)，用于**朴素贝叶斯分类** [[维基](https://en.wikipedia.org/wiki/Naive_Bayes_classifier)]。

### 18.4.2 H 的泛化与性质

该技术很容易泛化到两个以上的特征，预测能力 `H` 具有有趣的性质：`0 ≤ H ≤ 1`![Image](images/B9780443218576000229/si119.png)，如果特征子集没有预测能力，则 `H = 0`![Image](images/B9780443218576000229/si120.png)；如果具有最大预测能力，则 `H = 1`![Image](images/B9780443218576000229/si121.png)。如果 `p = 0.5`![Image](images/B9780443218576000229/si122.png)，则函数 `W` 的形状像 V 而不是 W。你可以尝试 `p = 0.5`![Image](images/B9780443218576000229/si122.png)，并检查它是否能提供足够好的预测。

### 18.4.3 高效实现

给定 20 个二元特征的一个子集，你可以预先计算任何扩展**标志向量**中的所有分箱计数，并将它们存储在哈希表 `Hash` 中——在 Python 中也称为“关联数组”或“字典”。这种扩展向量有 21 个分量：20 个用于特征，值为 0 或 1；1 个用于响应，值为 G 或 B。

在 Python 中，此**哈希表** [[维基](https://en.wikipedia.org/wiki/Hash_table)] 中的一个条目将类似于 `Hash[(v,y)]=56`，其中（假设）`y = "G"`![Image](images/B9780443218576000229/si123.png) 且 `v = "01101001010110100100"`![Image](images/B9780443218576000229/si124.png)。哈希表由**键值对**组成。在该示例中，值为 56，键为 `(v, y)`![Image](images/B9780443218576000229/si125.png)。这意味着标志向量 `v` 有 56 个响应为 G 的观测值。更准确地说，标志向量是一个二进制字符串，显示触发了哪些规则。这里规则即特征，“触发”意味着相关特征的值等于 1。非二元标志向量或响应此处不作讨论，但它们也被广泛使用。该框架有时被称为**关联规则学习** [[维基](https://en.wikipedia.org/wiki/Association_rule_learning)]。

通过一次性顺序解析训练集来生成哈希表：对于每个观测值，计算标志向量 `v`，检查响应是 Good (G) 还是 Bad (B)，并使用以下指令相应地更新关联的键值对：如果响应为 Good，则 `Hash[(v,G)]++`；如果响应为 Bad，则 `Hash[(v,B)]++`。

然后，每当你需要衡量这 20 个特征子集的预测能力时，就不需要再次解析你的大数据集（可能有数十亿观测值），而是只需访问这个小哈希表：该表包含构建标志向量和计算预测分数所需的一切，适用于前 20 个特征的任何组合子集。你甚至可以做得更好，比如前 30 个。虽然这将创建一个包含 20 亿个键的哈希表，但其中大多数键将对应空分箱，因此不会出现在哈希表中。你的哈希表可能只包含 2 亿个键，可能太大而无法放入内存，但可以使用分布式架构（如 `Map-Reduce`）轻松管理。

甚至更好：为前 40 个特征构建此哈希表。然而现在，你的哈希表可能多达 2 万亿个键。但如果你的数据集只有 1000 亿个观测值，那么当然你的哈希表不可能超过 1000 亿个键。在这种情况下，你创建一个包含 2000 万个观测值的训练集，这样你的哈希表最多将有 2000 万个键（由于空分箱，可能少于 500 万）。因此，它可以放入内存，因为你正在使用**稀疏哈希表**。

现在你可以估算许多不同特征子集的预测能力。为此，解析上一步获得的哈希表。对于该输入哈希表中的每个键 `(v, y)`![Image](images/B9780443218576000229/si125.png)，循环遍历所需的特征子集以创建新的分箱计数：这些计数存储/更新在输出哈希表中。新创建的输出哈希表中的键有两个分量：`subset ID`（代表特征子集的数字）和输入哈希表的键 `(v, y)`![Image](images/B9780443218576000229/si125.png)。创建输出哈希表后，你再循环遍历其键以计算每个特征子集的预测能力。

## 18.5 NLP：分类法创建与文本生成

本节讲述构建非结构化数据。我使用本节所述技术自动增强在线目录，如 Wikipedia、Yelp、Amazon 或 DMOZ [[维基](https://en.wikipedia.org/wiki/DMOZ)]。这涉及大量网络爬取。通过分析在线用户查询获得的一个显著结果是，将“餐厅”类别更好地细分为更有意义的子类别：浪漫餐厅、晚餐、酒吧、市中心或附近的餐厅、有景观或临河的餐厅、便宜的、异国风情的、休闲或高档餐厅、餐厅厨师、食谱、招聘和家具。经典的细分方式是按菜系类型，但这不如用户实际搜索的内容贴切。
