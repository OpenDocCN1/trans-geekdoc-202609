

## 14.2 地形生成与演化过程

当你观看[此处](https://www.youtube.com/watch?v=RE3Lz559aM0)的视频时，你可能会认为顶部的两张图片——尤其是右侧那张——相较于底部的两张并没有发生变化。这是一种视觉错觉，因为当仅发生变形时，过渡非常平滑。底部的演化过渡看起来快得多，因为它们是混沌的，且包含前进和后退的步骤。但归根结底，视频中第一帧和最后一帧之间的变换，对于缓慢移动的场景来说，同样是剧烈的。

现在我来讨论我方法的三个主要组成部分。

### 14.2.1 变形与非线性调色板操作

变形过程很简单。但我的实现方式中有个有趣的地方。它是利用 Python 中的 numpy 数组来完成的，调色板 `M` 和地形 `W` 均使用 numpy 数组。`M` 和 `W` 都是矩阵。`M` 的元素在 0 和 1 之间。变形涉及逐元素操作 [[Wiki](https://en.wikipedia.org/wiki/Hadamard_product_(matrices))]。例如，时间 `t` 的地形仅用一行代码即可计算：`W[t] = (1 - r[t]) * W[0] + r[t] * W[T]`![Image](images/B9780443218576000187/si5.png)，其中 `r[t] = t / T`![Image](images/B9780443218576000187/si6.png)，`W[0]`![Image](images/B9780443218576000187/si7.png) 是对应 `t = 0`![Image](images/B9780443218576000187/si8.png) 的初始地形配置，而 `W[T]`![Image](images/B9780443218576000187/si9.png) 是对应 `t = T`![Image](images/B9780443218576000187/si10.png) 的最终目标配置。

为获得更好的结果，我对调色板使用非线性变形：`M[t] = M[0]^(1 - r[t]) * M[T]^(r[t])`![Image](images/B9780443218576000187/si11.png)。同样得益于 numpy 数组的工作方式，这一逐元素操作也仅需一行代码即可完成。生成的中间调色板 `M[t]`![Image](images/B9780443218576000187/si12.png) 是有效的，所有元素均在 0 和 1 之间。

### 14.2.2 钻石-方形算法

我使用**钻石-方形**算法 [[Wiki](https://en.wikipedia.org/wiki/Diamond-square_algorithm)] 进行地形生成。我的实现改编自 Philipp Janert 于 2022 年发布的一个最新版本，见[此处](https://janert.me/blog/2022/the-diamond-square-algorithm-for-terrain-generation/)。主要区别在于，无论何时在混合方法中需要随机数，我都使用高斯偏差而非均匀偏差。原因是演化过程中的混合方法保留了高斯分布，从而随时间形成**稳定分布** [[Wiki](https://en.wikipedia.org/wiki/Stable_distribution)]，而均匀分布（以及所有方差有限的非高斯分布）不具备这一特性。

钻石-方形算法在不断增加的细节层级上依次填充数组（地形）。最初，只需初始化四个角；随后通过对四个最近的已填充邻居取平均并添加少量随机量来填充数组中剩余的单元格。在每一步中，初始设为 `s` 的随机噪声幅度会按某个因子 `ds` 递减。该因子控制地形的粗糙度。被更新的点数（即随机数生成器的调用次数）随后续每一步呈指数级增长，增长因子接近 4。因此只需很少的步骤即可完成。这里 `s` 和 `ds` 是 Python 代码中的变量名。

改进该算法有两种方法。首先，不再对最近邻的值取平均，而是使用中位数。其次，在演化过程中，不要更新对应小 `s` 的早期步骤中的随机偏差，而仅在最终步骤中更新。这可能消除随时间发生的罕见但突兀的过渡，尤其是在使用混合方法时。除非你确实想要这些罕见、不可预测、振幅各异的“大灾变”（振幅越大越罕见）：毕竟，它们存在于现实生活中，例如地球生命的演化。代码中的参数 `jump` 也控制它们发生的频率。

### 14.2.3 演化过程

时间 `t` 的地形是一幅图像，由一个 `n × n`![Image](images/B9780443218576000187/si13.png) 的像素矩阵 `W[t]`![Image](images/B9780443218576000187/si14.png) 表示，每个像素代表地图上的一个高度或海拔。此处 `n = 1 + 2^9`![Image](images/B9780443218576000187/si15.png)。钻石-方形算法要求 `n` 为 2 的幂加一。时间在代码中由整数变量 `frame` 表示。视频总帧数记为 `Nframes`。地形作为名为 `d` 的 numpy 数组存储。

最初，在时间 `t = 0`![Image](images/B9780443218576000187/si8.png) 时，地形通过几个步骤增量构建，每个后续步骤粒度更细，更新的像素数约为前一步的 4 倍，噪声幅度从一步到下一步呈指数级递减。这由代码中的函数 `make_terrain` 执行。在步骤 `s` 处，令 `W[0](s)`![Image](images/B9780443218576000187/si16.png) 为部分构建的地形。它是某些随机数 `u[0](s, 1)`、`u[0](s, 2)`![Image](images/B9780443218576000187/si17.png) 等的函数，这些随机数根据全局参数 `distribution` 设置为 `'Gaussian'` 还是 `'Uniform'`，分别由函数 `random.gauss(0, s)` 或 `random.uniform(-s, s)` 生成。步骤 `s` 在代码中由变量 `s` 表示。

在时间 `t + 1`![Image](images/B9780443218576000187/si18.png) 时，新地形 `W[t + 1]`![Image](images/B9780443218576000187/si19.png) 是 `W[t]`![Image](images/B9780443218576000187/si14.png) 的函数。唯一被更新的量是在构建 `W[t + 1]`![Image](images/B9780443218576000187/si19.png) 过程中每个步骤 `s` 处的数字 `u[t](s, 1)`、`u[t](s, 2)`![Image](images/B9780443218576000187/si20.png) 等。通过全局参数 `mode` 提供两种更新这些数字的选项。该参数可设为 `'Blending'` 或 `'Mixture'`。现描述这两种选项：

*   **混合选项。** 我们要么以概率 `p` 令 `u[t+1](k, s) = u[t](k, s)`![Image](images/B9780443218576000187/si21.png)，要么以概率 `1 - p`![Image](images/B9780443218576000187/si23.png) 令 `u[t+1](k, s)`![Image](images/B9780443218576000187/si22.png) 为一个新的偏差，该偏差根据参数 `distribution` 从 `Uniform[-s, s]`![Image](images/B9780443218576000187/si24.png) 或 `Normal(0, s)`![Image](images/B9780443218576000187/si25.png) 分布生成，其中 `k = 1, 2`![Image](images/B9780443218576000187/si26.png)，以此类推。通常 `p` 很小，在代码中由全局参数 `jump` 表示。

*   **融合选项。** 仅当代码中 `distribution` 设为 `'Gaussian'` 时允许使用。同样，要么以概率 `p` 令 `u[t+1](k, s) = u[t](k, s)`![Image](images/B9780443218576000187/si21.png) 保持不变，要么以概率 `1 - p`![Image](images/B9780443218576000187/si23.png) 更新 `u[t+1](k, s)`![Image](images/B9780443218576000187/si22.png)。当发生更新时，按如下方式执行：`u[t+1](k, s) = u[t](k, s) + ω * z`![Image](images/B9780443218576000187/si27.png)，其中 `ω` 为权重，`z` 为 `Normal(0, s)`![Image](images/B9780443218576000187/si25.png) 偏差。无论哪种方式，由构造可知，`u[t+1](k, s)`![Image](images/B9780443218576000187/si22.png) 均为零均值的高斯偏差。权重 `ω` 在代码中由全局参数 `weight` 表示。
