### 1.3.3 Nonperiodic sum of periodic time series: ocean tides

In this section I consider the problem of fitting a **nonperiodic trigonometric series** via least squares. One well-known example is the Dirichlet eta function with an infinite number of superimposed periods. Its modulus is pictured in [Fig. 1.3](#Chp001_1-34_B9780443218576000059.xhtml#f0025). Practical applications are also numerous. A good exercise is to download ocean tide data, and use the methodology described in this section to predict low and high tides, at various locations: the tides are influenced mostly by two factors – gravitation from the moon and from the sun – each with its own period. But the combination is not periodic. The fitting technique allows you to quantify the effect of each hidden component (the sun and the moon in this case) and retrieve their respective periods. The tide data is available for free, [here](https://tidesandcurrents.noaa.gov/).

![Figure 1.3 Three nonperiodic time series made of periodic terms (see Section 17.2.2.1).](images/B9780443218576000059/gr010.jpg)

Figure 1.3 Three nonperiodic time series made of periodic terms (see Section [17.2.2.1](#Chp017_329-360_B9780443218576000217.xhtml)).

With my notation, the problem is defined by `w = (y, x)` and

`g(y, x; θ) = y - [θ[1]cos(θ[2]x + θ[3]) + θ[4]cos(θ[5]x + θ[6])]`.

(1.7)

There is no constraint on `θ`, and thus no `η` function and no `λ` in [(1.2)](#Chp001_1-34_B9780443218576000059.xhtml#deq2). Here `y` is the response, and `x` represents the time. For this reason, I also use the notation `y = f[θ](x)`, equivalent to `g(y, x; θ) = 0`. This type of problem is called **curve fitting** [[Wiki](https://en.wikipedia.org/wiki/Curve_fitting)] in scientific computing. There are libraries to solve it: in Python, one can use the `optimize.curve_fit` function from the `Scipy` library. For more details, see the [Python documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.curve_fit.xhtml).

Finally, if you are only interested in predicting `y` given `x`, but not in estimating the parameter vector `θ`, then the following interpolation formula is sometimes useful:

$y = f(x) \approx \frac{\sin\pi x}{\pi} \cdot \left\lbrack \frac{f(0)}{x} + 2x\sum\limits_{k = 1}^{n}{( - 1)}^{k}\frac{f(k)}{x^{2} - k^{2}} \right\rbrack.$

(1.8)

I used it in Exercise [17.9](#Chp017_329-360_B9780443218576000217.xhtml) in Chapter [17](#Chp017_329-360_B9780443218576000217.xhtml) about the Riemann Hypothesis, to get a good approximation of `y = f[θ](x)` when `y` is known (that is, observed) at integer increments `x = 0, 1`, and so on, even though `θ` is not known. I applied it to a function `f[θ](x)` closely related to those pictured in [Fig. 1.3](#Chp001_1-34_B9780443218576000059.xhtml#f0025). The function in question (namely, the real part of the Dirichlet eta function) can be expressed as an infinite sum of cosine terms with different amplitudes and different periods. Thus, in this case, the dimension of the unobserved `θ` is infinite, and `θ` remains an hidden parameter in the prediction experiment, hidden to the experimenter (as in a blind test). Its components are the various period and amplitude coefficients. The approximation formula [(1.8)](#Chp001_1-34_B9780443218576000059.xhtml#deq13) works under certain conditions: see Exercise [17.9](#Chp017_329-360_B9780443218576000217.xhtml) for details.

#### 1.3.3.1 Numerical instability and how to fix it

Consider the simpler case where `θ[3] = θ[6] = 0`: let us drop these two coefficients from the model. Even then, the problem is **ill-conditioned** [[Wiki](https://en.wikipedia.org/wiki/Condition_number)]. In particular, if `θ^* = (θ[1]^*, θ[2]^*, θ[4]^*, θ[5]^*)` is an optimum solution, so is `(θ[4]^*, θ[5]^*, θ[1]^*, θ[2]^*)`. At the very least, without loss of generality, you need to add the constraint `|θ[1]| ≥ |θ[4]|`.

In Python, I used the `curve_fitting` function from `Scipy`. It does a poor job for this problem, even if you specify bounds for the coefficients `θ[1], θ[2], θ[4], θ[5]` and start the algorithm with a vector `θ` close to an optimum `θ^*`. My test involved

- Finding an optimum `θ` if the fitting function is `y = f[θ](x) = θ[1]cos θ[2]x + θ[4]cos θ[5]x`,
- Using a synthetic training set where `y = a[1]cos a[2]x + a[4]cos a[5]x + a[7]cos a[8]x`.

The gray curve in [Fig. 1.4](#Chp001_1-34_B9780443218576000059.xhtml#f0030), called the “model”, is `y = a[1]cos a[2]x + a[4]cos a[5]x`, while the blue one is the fitted curve (not necessarily unique), and the dots represent the observations (training set in red, validation set in orange). The observations points do not lie exactly on the gray curve because I introduced some noise: the third term `a[7]cos a[8]x` between the model and the data. Note that the observations are equally spaced with respect to the X-axis, but absolutely not with respect to the Y-axis. It is possible to use a different sampling mechanism to address this issue. The figure was produced with the Python code in Section [1.3.3.2](#Chp001_1-34_B9780443218576000059.xhtml#s0075). The values of `a[1], ..., a[8]` are prespecified. Evidently, if `a[7] = 0`, then an obvious optimum solution is `θ[i]^* = a[i]` for `i = 1, 2, 4, 5`. It provides a perfect fit. Also, the coefficient `a[7]` specifies the amount of noise in the data.
