

## 18.5 关键词分类法与聚类

该技术允许您查找相关关键词或同义词，并可结合同义词表使用，以在**自然语言生成** [[Wiki](https://en.wikipedia.org/wiki/Natural_language_generation)] 的语境下生成文本。它是许多**大语言模型** [[Wiki](https://en.wikipedia.org/wiki/Language_model)]（如 **ChatGPT** [[Wiki](https://en.wikipedia.org/wiki/ChatGPT)]）的核心组件之一。此处我不涵盖基础步骤，例如使用**停用词** [[Wiki](https://en.wikipedia.org/wiki/Stop_word)] 清洗数据、**n-gram** [[Wiki](https://en.wikipedia.org/wiki/N-gram)] 排列、使用同义词词典、修正拼写错误、处理特殊字符、使用**正则表达式** [[Wiki](https://en.wikipedia.org/wiki/Regular_expression)] 进行**文本规范化** [[Wiki](https://en.wikipedia.org/wiki/Text_normalization)] 等。这些内容可在任何自然语言处理的入门介绍中找到。

### 18.5.1 设计关键词分类法

此处我将讨论一种在大数据集上执行快速聚类的算法，以及此类复杂聚类结构的图形化表示。所谓“快速”，是指**计算复杂度** [[Wiki](https://en.wikipedia.org/wiki/Computational_complexity)] 为 `O(n)`![Image](images/B9780443218576000229/si126.png) 阶。这比**层次凝聚聚类** [[Wiki](https://en.wikipedia.org/wiki/Hierarchical_clustering)] 快得多，后者通常为 `O(n²log n)`![Image](images/B9780443218576000229/si127.png)。所谓“大数据”，是指数百万，甚至数十亿级别的观测值。

设想的应用场景是创建关键词、产品或文档分类法。特别是，我想从零开始创建一个关键词分类法，基于爬取数十亿个网页来提取关键词并将其聚类为不同类别。这是一个典型的无监督自然语言处理（NLP）问题。提出的算法如下：

#### 步骤 1：预处理

您通过爬取（例如）维基百科或 Google 搜索结果，在互联网上收集数十亿个关键词，清洗结果，并计算每个关键词及每个“关键词对”的频率。“关键词对”是指在同一网页上发现的两个关键词，或在同一网页上彼此靠近的两个关键词。此外，这里的关键词是指像“California insurance”（加利福尼亚保险）这样的实体，因此一个关键词通常包含不止一个词元，但很少超过三个。随后您可以创建一个关键词表，其中每个条目是一个关键词对及三个计数，例如 `A="California insurance"`、`B="home insurance"`、`x=543`![Image](images/B9780443218576000229/si128.png)、`y=998`![Image](images/B9780443218576000229/si129.png)、`z=11`![Image](images/B9780443218576000229/si130.png)，其中

*   `x` 是关键词 `A` 在所有爬取网页中出现的次数，
*   `y` 是关键词 `B` 在所有爬取网页中出现的次数，
*   `z` 是 `A` 和 `B` 构成一对的出现次数（例如，它们在同一页面上被发现）。

您可以使用分布式架构构建关键词表。绝大多数关键词 `A` 和 `B` 并不构成“关键词对”。换句话说，`z=0`![Image](images/B9780443218576000229/si131.png) 的情况占绝大多数。因此，通过忽略这些空条目，您的最终关键词表可以作为**哈希表**存储在内存中（参见第 [18.4.3](#Chp018_361-386_B9780443218576000229.xhtml#s0095) 节），其中键为 `(A, B)`![Image](images/B9780443218576000229/si132.png)，键对应的值为 `(x, y, z)`![Image](images/B9780443218576000229/si133.png)。我们将此表命名为 `Keyword`。

#### 步骤 2：聚类

要创建分类法，您需要将关键词分组到相似的簇中。用于衡量两个关键词或网页之间距离的**余弦距离** [[Wiki](https://en.wikipedia.org/wiki/Cosine_similarity)] 在此语境下很常用。为了执行关键词聚类，我使用以下**非相似度度量** `d(A, B)`![Image](images/B9780443218576000229/si134.png) 来比较两个关键词 `A`、`B`：`$d(\text{A},\text{B}) = z/\sqrt{xy}$`![Image](images/B9780443218576000229/si135.png)，当然也可以选择其他度量。该度量被称为**大冢-大千系数**。注意，分母防止了极其流行的关键词（例如，“free”）与所有关键词都接近，并主导整个关键词关系结构：实际上，它更倾向于更好的关键词联系，例如“lemon” 与 “law” 或 “pie” 的联系，而不是 “lemon” 与 “free” 的联系。`d(A, B)`![Image](images/B9780443218576000229/si136.png) 越大，关键词 `A` 和 `B` 越接近。我在第 [18.5.2](#Chp018_361-386_B9780443218576000229.xhtml#s0110) 节中描述聚类部分。

### 18.5.2 关键词数据的快速聚类算法

此处我有 `n=10⁷`![Image](images/B9780443218576000229/si137.png) 个唯一关键词和 `m=10⁸`![Image](images/B9780443218576000229/si138.png) 个关键词对 `{A, B}`![Image](images/B9780443218576000229/si139.png)，其中 `d(A, B)>0`![Image](images/B9780443218576000229/si140.png)。即每个关键词平均附有 `r=10`![Image](images/B9780443218576000229/si141.png) 个相关关键词。这些关键词对存储在第 [18.5.1](#Chp018_361-386_B9780443218576000229.xhtml#s0105) 节预处理步骤中创建的哈希表 `Keyword` 中。该算法构建新的哈希表 `Hash`（类别表）和 `Weight`。它按以下方式增量进行：

#### 初始化

小数据（或种子）步骤。选择 ![Image](images/B9780443218576000229/fx008.jpg) 个种子关键词，创建（例如）100 个类别，并创建一个哈希表 `Hash`，其中键为 ![Image](images/B9780443218576000229/fx008.jpg) 个种子关键词之一，值为该关键词被分配到的类别列表。例如，`Hash['cheap car insurance']={'automotive','finance'}`。初始 ![Image](images/B9780443218576000229/fx008.jpg) 个种子关键词的选择非常重要。我建议挑选关联数量最多的前 ![Image](images/B9780443218576000229/fx008.jpg) 个关键词：即拥有许多 `B` 且满足 `d(A, B)>0`![Image](images/B9780443218576000229/si142.png) 的关键词 `A`。这将加速算法的收敛。

#### 大数据步骤

从头到尾浏览哈希表 `Keyword`。我们现在构建表 `Hash` 和 `Weight`。设 `(A, B)`![Image](images/B9780443218576000229/si132.png) 为 `Keyword` 中当前的关键词对。

```
If Hash[A] exists and Hash[B] does not, do:
    Hash[B] = Hash[A]
    Weight[B] = d(A, B)
Else If Hash[A] does not exist and Hash[B] exists, do:
    Hash[A] = Hash[B]
    Weight[A] = d(A, B)
Else If Hash[A] and Hash[B] exist, recategorize:
    If d(A, B) > Weight[B] do:
        Hash[B] = Hash[A]
        Weight[B] = d(A, B)
    Else If d(A, B) > Weight[A] do:
        Hash[A] = Hash[B]
        Weight[A] = d(A, B)
```

您可以用 `Hash[A]=Concatenate(Hash[A],Hash[B])` 替换 `Hash[A]=Hash[B]`，反之亦然。这将增加关键词被分配到的类别数量。我未测试该选项。

#### 循环

重复“大数据步骤” 6 或 7 次：`Hash` 和 `Weight` 保留在内存中，并在循环的每次后续迭代中持续增长。

### 18.5.2.1 计算复杂度

计算复杂度渐近为 `(N + 1)*m = O(n)`![Image](images/B9780443218576000229/si143.png)，其中 `N` 是循环中的迭代次数。这非常快。然而，随着 `Hash` 和 `Weight` 在每次新迭代中变大，访问哈希表会使其略微减慢。
