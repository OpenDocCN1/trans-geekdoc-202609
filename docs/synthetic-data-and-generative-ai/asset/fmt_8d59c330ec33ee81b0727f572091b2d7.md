
## 13.1 Base Functions

The brackets represent the integer part function, and `ϵ` = 0![Image](images/B9780443218576000175/si6.png). However, in the code, `ϵ` = 10^( − 8)![Image](images/B9780443218576000175/si7.png) to avoid problems caused by numerical precision. Formula [(13.1)](#Chp013_243-258_B9780443218576000175.xhtml#deq1) defines the base function, denoted as `fmod` in the Python code. It is a piecewise constant function, pictured in [Fig. 13.1](#Chp013_243-258_B9780443218576000175.xhtml#f0010) between `b` = 2900![Image](images/B9780443218576000175/si8.png) and `b` = 3200![Image](images/B9780443218576000175/si9.png), using `a` = 3083 × 7919![Image](images/B9780443218576000175/si10.png). Thus the interval `[2900, 3200]`![Image](images/B9780443218576000175/si11.png) contains the root `b` = 3083![Image](images/B9780443218576000175/si12.png). There are no other roots besides 3083 and 7919 since these two integers are prime numbers. Also note that `0 ≤ f(b) < b`![Image](images/B9780443218576000175/si13.png). Optimization methods based on the gradient are guaranteed not to work here.

![Figure 13.1 Function f(b) as a better alternative to g(b) in Fig. 13.2. Root at b = 3083.](images/B9780443218576000175/gr001.jpg)

Figure 13.1 Function `f(b)` as a better alternative to `g(b)` in [Fig. 13.2](#Chp013_243-258_B9780443218576000175.xhtml#f0015). Root at `b` = 3083.

Note that instead of `f(b)`![Image](images/B9780443218576000175/si1.png), I could have used `g(b) = 2 - cos(2πb) - cos(2πa/b)`![Image](images/B9780443218576000175/si14.png). This function is also positive and equal to zero only if `b` is an integer number that divides the integer `a`. In addition, `g` is bounded with `0 ≤ g(b) ≤ 4`![Image](images/B9780443218576000175/si15.png), and infinitely differentiable. Yet it has a very large number of local minima and maxima: the frequency of oscillations is insanely high. For all purposes, `g` is just as chaotic of `f`, indeed worse than `f`, and no standard optimization algorithm could handle it. The function `g` is pictured in [Fig. 13.2](#Chp013_243-258_B9780443218576000175.xhtml#f0015).

## 13.2 Nonconverging fixed-point algorithm

In this section, I start with the function `f(b)`![Image](images/B9780443218576000175/si1.png) defined by formula [(13.1)](#Chp013_243-258_B9780443218576000175.xhtml#deq1). I investigate a larger class of functions in Section [13.3](#Chp013_243-258_B9780443218576000175.xhtml#s0040). The trick is to massively amplify the zero, creating ripple effects that the fixed point iteration can leverage to narrow down on the solution. In the end, instead of looking at convergence (absent here), you look at the strength of a signal `ρ[n]`![Image](images/B9780443218576000175/si16.png) at iterations `n` = 1, 2![Image](images/B9780443218576000175/si17.png), and so on. The value of `ρ[n]`![Image](images/B9780443218576000175/si16.png) is typically close to 1, but high values (above 2) indicate that something unusual is happening. Typically, such high values are created when stepping over a root.

### 13.2.1 Trick leading to intuitive solution

Let us assume that `f` is positive and that its minimum value is zero. If `f` takes on negative values, replace `f(b)`![Image](images/B9780443218576000175/si1.png) by the absolute value `|f(b)|`![Image](images/B9780443218576000175/si18.png) or by the square `f²(b)`![Image](images/B9780443218576000175/si19.png). This works both in root-finding and optimization problems. In optimization, `f` is the derivative of the target function. The base function `f` (or its absolute value or square) is denoted as `f[0]`![Image](images/B9780443218576000175/si20.png).

The goal is to apply successive transformations to make the function `f[0]`![Image](images/B9780443218576000175/si20.png) more amenable to root detection. The first transformation consists of taking the logarithm, thus creating a vertical bottomless abyss in the graph of the function, around any root. In practice, it is implemented as follows: the new function is simply

```
f[1](b) = max[log(f[0](b)), δ]
```

![Image](images/B9780443218576000175/si21.png)

where `δ` is a negative number, large enough in absolute value. In the Python code, `δ` is represented by `logeps`, and set to −10. This parameter controls the depth of the abyss, that now has a bottom. It helps discriminate between a value very close to zero, and a value exactly equal to zero. For instance, if `f[0](b) = 0.01`![Image](images/B9780443218576000175/si22.png), then `f[1](b) = -4.61`![Image](images/B9780443218576000175/si23.png), while if `f[0](b) = 0`![Image](images/B9780443218576000175/si24.png), then `f[1](b) = -10`![Image](images/B9780443218576000175/si25.png).

The second step consists in enlarging the abyss. Its walls will change from vertical to inclined. The width of the abyss, and the slope of its walls, is controlled by the parameter `window` in the Python code, and referred to here as `w`. In a nutshell, this transformation is a **moving average** applied to `f[1]`![Image](images/B9780443218576000175/si26.png). The resulting function is

```
f_2(b) = (1/(2w + 1)) * sum_{k=-w}^{w} f_1(b + kh)
```

![Image](images/B9780443218576000175/si27.png)

The increment `h` is set to 1 as it makes sense in my particular problem. I did not test other values.

The third step is a linear transformation, turning `f[2]`![Image](images/B9780443218576000175/si28.png) into `f[3]`![Image](images/B9780443218576000175/si29.png), with `f[3](b) = p + q*f[2](b)`![Image](images/B9780443218576000175/si30.png). The parameters `p` and `q` are respectively denoted as `offset` and `slope` in the Python code. The functions `f[0]`, `f[1]`![Image](images/B9780443218576000175/si31.png), and `f[3]`![Image](images/B9780443218576000175/si29.png) are respectively denoted as `fmod`, `fmod2`, and `fresidue` in the Python code. The blue curve (dark gray in print version) in [Fig. 13.3](#Chp013_243-258_B9780443218576000175.xhtml#f0020) is the `f[3]`![Image](images/B9780443218576000175/si29.png) transform associated to the `f[0]`![Image](images/B9780443218576000175/si20.png) function pictured in [Fig. 13.1](#Chp013_243-258_B9780443218576000175.xhtml#f0010), with `p` = -100![Image](images/B9780443218576000175/si32.png) and `q` = 20![Image](images/B9780443218576000175/si33.png). Subsequent transformations discussed in Section [13.4](#Chp013_243-258_B9780443218576000175.xhtml#s0070) are done only for embellishment, and are irrelevant to the fixed point algorithm.

### 13.2.2 Root detection: method and parameters

The fixed-point algorithm starts with an initial value `b[0]`![Image](images/B9780443218576000175/si34.png), and then proceeds iteratively as follows:

```
b[n+1] = b[n] + μ*f(b[n])
```
