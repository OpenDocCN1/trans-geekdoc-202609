
## 8.3 Full, nonlinear model in higher dimensions

I now discuss the general model. For the sake of simplicity, I focus on the 2-dimensional case: a response `z`, with two features `x`, `y`. It is an important case, with applications in **geostatistics** [[Wiki](https://en.wikipedia.org/wiki/Geostatistics)]. The `d`-dimensional case is not more complicated, but the notations quickly become cumbersome. The line `L[k]` is now replaced by a spline, also denoted as `L[k]`. But this time, `k = (k[1], …, k[r])` is a vector, with `1 ≤ k[i] ≤ n` (`i = 1, …, r`). Just like a plane is uniquely determined by exactly 3 points, we want the spline `L[k]` to be uniquely determined by exactly `r` points, in this case `(x[k[1]], y[k[1]], z[k[1]]), …, (x[k[r]], y[k[r]], z[k[r]])`. That is, we want

```
z[k[i]] = L[k](x[k[i]], y[k[i]]),  i = 1, …, r.
```

There is very simple type of splines satisfying this property, namely

```
L_k(x,y) = ∑_{i=1}^{r} (z_{k_i}/2) [ ∏_{j≠i} (ψ(x - x_{k_j}) / ψ(x_{k_i} - x_{k_j})) + ∏_{j≠i} (ψ(y - y_{k_j}) / ψ(y_{k_i} - y_{k_j})) ],
```

(8.1)

where `ψ` is any real-valued function satisfying `ψ(0) = 0`. In practice, one can choose the identity function for `ψ`. The resulting splines are then similar to multivariate Lagrange polynomials of degree `r − 1`, used for interpolation [[3]](#Chp008_131-145_B9780443218576000126.xhtml#br0015). I now discuss the various features, issues, capabilities, and potential implementations of this type of regression.

### 8.3.1 Geometric proximity, weights, and numerical stability

From now on, I assume that `ψ` is the identity function. A key concept is the proximity between a location `(x, y)` in the plane, and a spline. When predicting `z`, given `(x, y)`, one has to compute `L[k](x, y)` for each spline `L[k]`. The number of splines quickly increases with `r`. For a specific location `(x, y)`, some splines are more relevant than others. The following metric measures the proximity to `L[k]`:

```
δ_k(x,y) = ( ∏_{i=1}^{r} max(|x - x_{k_i}|, |y - y_{k_i}|) )^{1/r}.
```

(8.2)

It is the geometric mean of `r` Chebyshev distances [[Wiki](https://en.wikipedia.org/wiki/Chebyshev_distance)] in ℝ². In particular, it is zero if any of these distances is zero. This essential property cannot be satisfied with the arithmetic mean, but it is with the geometric mean. The relevance or importance of `L[k]`, relative to `(x, y)`, is then defined as the weight

```
w[k](x, y) = exp[ − s ⋅ δ[k](x, y) ],
```

(8.3)

where `s > 0` is the **smoothing parameter**. It is maximum when `δ[k](x, y) = 0`. On the other side, some splines are always problematic, or may not even exist. These splines are identified by the accuracy metric

```
ε_k = ∏_{i=1}^{r} ∏_{j=i+1}^{r} |x_{k_i} - x_{k_j}| ⋅ |y_{k_i} - y_{k_j}|.
```

(8.4)

In particular, if `ε[k] = 0`, the spline `L[k]` is undefined. It is a good practice to reject or ignore splines with `ε[k] < 10^(−5)`. It increases the numeral stability of the system.

In addition, some splines may produce outlier predictions, depending on the location `(x, y)`. Such abnormal predictions should be ignored to boost performance, when blending the `M` predicted values `L[k](x, y)` – one per spline – to compute the final predicted value and prediction interval at `(x, y)`. This final predicted value is the median or weighted average computed across all splines at `(x, y)`, after rejecting undesirable splines or predictions. Outlier predictions are detected and rejected in the Python code, via the **hyperparameter** `zzdevratio`.
