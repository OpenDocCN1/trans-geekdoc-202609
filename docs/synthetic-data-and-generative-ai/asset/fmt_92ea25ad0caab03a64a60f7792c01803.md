The modulo operator magnifies the cluster structure, which is otherwise invisible to the naked eye. It is defined as `a mod b = a - b⌊a/b⌋`![Image](images/B9780443218576000096/si24.png) where the brackets represent the integer part function. For your own simulations, you can use modulo `1/λ`![Image](images/B9780443218576000096/si25.png), rather than `2/λ`![Image](images/B9780443218576000096/si22.png): this will remove the apparent stochastic duplication in my pictures. The reason I chose `2/λ`![Image](images/B9780443218576000096/si22.png) is due to boundary effects, with clusters extending beyond the window of observations and truncated because of the window, thus making the cluster structure much harder to see if using modulo `1/λ`![Image](images/B9780443218576000096/si25.png). For the mathematically inclined reader, the methodology performs **classification on the torus** [[Wiki](https://en.wikipedia.org/wiki/Periodic_boundary_conditions)] rather than on the plane: this is a standard technique when facing boundary effects. If all your data fits nicely in the observation window, you can ignore the modulo transformation.

### 5.3.1 Supervised classification based on convolution filters

Here the synthetic data set represents the training set. The algorithm consists of filtering the whole bitmap `N` times. Each time, a local filter is applied to each pixel (`x`, `y`)![Image](images/B9780443218576000096/si27.png). Initially, the color `c(x, y)`![Image](images/B9780443218576000096/si28.png) attached to the pixel represents the cluster it belongs to, in the training set (or in other words, the individual point process it originates from in the `m`-mixture): its value is an integer between 0 and `m - 1`![Image](images/B9780443218576000096/si29.png) if it is in the training set, and 255 otherwise. The new color assigned to (`x`, `y`)![Image](images/B9780443218576000096/si27.png) is

```
c^{\prime}(x,y) = \underset{j}{\arg\max}\sum\limits_{u = - w}^{w}\sum\limits_{v = - w}^{w}\frac{\chi\lbrack c(x - u,y - v) = j\rbrack}{\sqrt{1 + u^{2} + v^{2}}}
```

![Image](images/B9780443218576000096/si30.png)(5.3)

that is, the value of `j` that maximizes [(5.3)](#Chp005_83-102_B9780443218576000096.xhtml#deq3). Here `χ[A]`![Image](images/B9780443218576000096/si31.png) is the indicator function [[Wiki](https://en.wikipedia.org/wiki/Indicator_function)]: `χ[A]` = 1![Image](images/B9780443218576000096/si32.png) if `A` is true, and 0 otherwise. The boundary problem (when `x - u`![Image](images/B9780443218576000096/si33.png) or `y - v`![Image](images/B9780443218576000096/si34.png) is outside the bitmap) is handled in the source code.

In the Python code, `N` is the parameter `nloop`, and `w` is the parameter `window`. It is also referred to as `w` and `loops` in the figures. In particular, I used `N = 3`![Image](images/B9780443218576000096/si35.png) and `w = 20`![Image](images/B9780443218576000096/si36.png). Formula [(5.3)](#Chp005_83-102_B9780443218576000096.xhtml#deq3) corresponds to `method = 1` in the Python code. While slow, it provides granular cluster boundaries. A faster version, namely `method = 0`, does not make the division by `sqrt(1 + u^2 + v^2)`![Image](images/B9780443218576000096/si37.png). It is faster not only because it avoids the square-root computations, but also because it can be implemented very efficiently; see Section [5.3.5](#Chp005_83-102_B9780443218576000096.xhtml#s0055). Yet, the loss of accuracy when using the fast method, while noticeable, is smaller than expected. See [Fig. 5.7](#Chp005_83-102_B9780443218576000096.xhtml#f0040) for comparisons.

Note that each cluster, even when the overlap is small, extends to the entire plane. So there is always some degree of overlap. But the overlap is much smaller when the diffusion factor `s` (the variable `s` in the Python code) is small. This is evident when comparing [Fig. 5.2](#Chp005_83-102_B9780443218576000096.xhtml#f0015) with [Fig. 5.4](#Chp005_83-102_B9780443218576000096.xhtml#f0025). Both figures have the same number of clusters, and the same cluster centers; only `s` – and thus the amount of cluster overlap – is different.

After filtering the whole bitmap `N = 3`![Image](images/B9780443218576000096/si35.png) times, thanks to the large size of the local filtering window (`w = 20`![Image](images/B9780443218576000096/si36.png)), all pixels are assigned to a cluster. This means that any future point (not in the training set) can easily and efficiently be classified: first, find its location on the bitmap; then its cluster is the color assigned to that location. It is worth asking whether convergence occurs (and to what solution) if you were to filter the bitmap many times. I studied convergence for a similar type of filter, in my paper “Simulated Annealing: A Proof of Convergence” [[1]](#Chp005_83-102_B9780443218576000096.xhtml#br0005). Empirical evidence suggests that additional loops (increasing `N` beyond `N = 3`![Image](images/B9780443218576000096/si35.png)) barely makes any difference.
