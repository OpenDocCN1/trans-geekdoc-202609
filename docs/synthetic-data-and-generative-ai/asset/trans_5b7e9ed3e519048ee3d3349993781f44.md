## 15.3 恒星碰撞与碰撞图分析

在深入分析恒星碰撞之前，我提供当 `saveData=True` 时由 Python 代码生成的 `nbody.txt` 数据集的详细信息。它包含每颗恒星每个时间帧一行，按以下顺序有 13 个字段：`time`、`star ID`、`mass`、`color`、相关时间该恒星的 `position`、全局恒星团的 `centroid`、以及同一时间的恒星 `velocity`。最后三个特征（`star position`、`centroid` 和 `star velocity`）是三维向量，分量对应 `X`、`Y` 和 `Z` 轴。每个时间帧对应一个视频帧。

这一相当大规模的合成数据集可用于执行各种分析和基准预测算法。它可以按恒星或时间段拆分为多个子集，用于交叉验证。用于训练预测模型的子集称为训练集，而用于测试模型的子集称为验证集。由于恒星系统的混沌本质——它确实是一个 `chaotic dynamical system`——一些特征如单个恒星路径或整个系统的漂移（类似于 `Brownian motion`）可能难以预测，尤其是长期预测。然而，一些一般特征可能更容易预测，如恒星团膨胀率的下降、随时间变化的流浪恒星和双星数量、相邻恒星之间的平均距离，或恒星碰撞率的衰减。恒星丝状结构或恒星聚类等模式可能是可识别的。在大多数情况下，所涉及的随机过程不是 `stationary` [[维基](https://en.wikipedia.org/wiki/Stationary_process)]：它们明显表现出趋势。

在本节中，我专注于恒星碰撞和 `collision graph`，它附属于[表 15.2](#Chp015_277-292_B9780443218576000199.xhtml#t0015)中第七个参数集对应的恒星系统。特别地，最初创建了三个不同的恒星团。该分析所需的所有数据存储在一个名为 `nbody_collisions.txt` 的较小数据集中。它包含以下字段：`collision ID`（该表的键）、`collision time` 或 `video frame`、涉及的两颗恒星的 `IDs`、恒星创建时分配的 `cluster IDs`（由颜色表示）、碰撞涉及的两颗恒星的 `masses`，以及碰撞时刻 `impact location` 与整个系统 `centroid` 之间的 `distance`。碰撞数据集可在我的 GitHub 仓库获取，[此处](https://github.com/VincentGranville/Visualizations/blob/main/Source-Code/nbody_collisions.txt)。本章未分析的较大数据集 `nbody.txt` 可在[此处](https://ln5.sync.com/dl/1db5e57a0/ci7a47dj-5mncatbz-h4uasqtp-ezi7txir)获取（压缩后 87 MB，200 万行）。
