### 2.3.3 Python 代码和数据集

输入数据集 `HDTdata4.txt` 位于我的 GitHub 仓库，[此处](https://github.com/VincentGranville/Machine-Learning/blob/main/Source%20Code/HDTdata4.txt)。Python 程序 `HDT.py` 列在下方，也可在我的 GitHub 仓库找到，[此处](https://github.com/VincentGranville/Machine-Learning/blob/main/Source%20Code/HDT.py)。输出文件 `hdt-out2.txt` 包含对应热门文章的可用键值对（节点），以及这些节点各自的文章 ID 列表。最后，变量 `pv` 代表 `p`，即页面浏览量的对数。二元组合（标题关键词、文章类别）构成哈希表 `list_pv` 的键，而 `pv` 是哈希表的值。关键词要么是单 token，要么是双 token。对于单 token 关键词，第二个 token 标记为 `N/A`。简而言之，关键词是一个二元实体。

至于错误率，既然重点是产出好文章，我只关心将坏文章标记为好文章的数量最小化：即假阳性。为了降低错误率或未分类节点的比例，可以使用更多特征（例如[表 2.1](#Chp002_35-47_B9780443218576000060.xhtml#t0010) 中列出的更多特征）、三 token 关键词、更大的训练集、更好的关键词清洗机制，并微调参数。

当然，如果你在程序中选择选项 `mode='perfect_fit'`，你在训练集上的假阳性率将降至 0%，但这可能会降低验证集上的性能，并可能导致许多节点未分类。从好的方面看，你需要微调的参数少得多：`pv_threshold_good`、`pv_threshold_bad` 和可用节点的最小大小（代码中的变量 `n`）。前两者可分别设为全局平均 `pv` 的 5% 上方和 10% 下方。最小节点大小应设在 2 以上，理想情况下在 5 以上，尽管较大的值会导致更多未分类节点。对于 `mode='robust method'`，定义 `good_node` 和 `bad_node` 的条件语句中的参数是基于平均 `pv` 6.83 手动设定的。这些选择可以自动化。

最终，未分类节点通过电子表格中的回归进行分类（见第 [2.3.2](#Chp002_35-47_B9780443218576000060.xhtml#s0055) 节），但这尚未在 Python 代码中实现。但就我的目的而言（确定是什么让一篇文章变好），我不需要添加回归部分，因为仅迷你决策树（节点）就提供了足够有价值的见解。

## 2.4 无模型置信区间与完美节点

电子表格中的节点 `N-100-000000` 平均 `pv` 为 5.85。它由 10 篇文章组成，其 `pv` 分别为：5.10、5.10、5.56、5.56、5.66、5.69、6.01、6.19、6.80、6.80![Image](images/B9780443218576000060/si8.png)。使用 Excel 的 `Percentile()` 函数计算，第 15 和第 85 百分位数分别为 5.26 和 6.68。因此，`[5.26, 6.68]`![Image](images/B9780443218576000060/si9.png) 是该节点 `pv` 的 70% **置信区间**（CI）。

整个 CI（包括其上界）都低于平均 `pv` 6.83。事实上，该节点对应 2014 年后发布的文章，非博客或论坛问题（可能是视频或活动公告），且标题不包含电子表格中的任何关键词特征（数据选项卡中的 K 到 P 列）。该节点具有最大预测能力，意味着它包含的 100% 文章都是坏的，0% 是好的。如果反过来，好坏互换，也同样成立。这样的节点称为**完美节点**。在 Python 代码中选择选项 `mode='Perfect fit'` 时，该方法仅查看完美节点。**预测能力**的概念将在第 [18.4.2](#Chp018_361-386_B9780443218576000229.xhtml) 节进一步讨论。
