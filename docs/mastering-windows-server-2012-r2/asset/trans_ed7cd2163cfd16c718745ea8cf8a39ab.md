# 共享主目录

我们之前提到过，某些组织选择允许所有者以外的用户访问主目录。你可以通过向 D:\Shares\Home 添加“已验证身份的用户”（Authenticated Users）来轻松地添加该访问权限。此权限将被每个主目录继承。你可以赋予他们“读取和执行”权限以实现只读访问，或者可以赋予他们“更改”权限，以便他们修改他人主目录的内容。

# 第 26 章 高级用户账户管理与用户支持

某些组织选择不配置用户对象的“目录”属性。他们的观点是，使用登录脚本映射驱动器更为简单。登录脚本在用户每次登录时都会运行并执行一组命令。你稍后会查看它们。或者，你可以利用组策略首选项（Group Policy Preferences）进行驱动器映射。如果驱动器移动到另一个服务器，只需更改单个登录脚本命令或组策略，而无需更改成百上千个用户的设置。

相反的观点是，你通过使用 DFS 命名空间来抽象共享的物理位置，从而使你的主目录解决方案变成了动态的。你可以进行共享，一旦你修改了 DFS 命名空间中的单个文件夹映射，所有用户都将保留他们的映射。此外，在设置设置“目录”属性时，可以使用一些关于用户主目录的环境变量：

- HOMEDIVE：代表用于映射主目录的盘器符，例如 Z:
- HOMEPATH：HOMEDIVE 内部包含主目录的路径，例如，路径为 %HOMEDIVE%\HOMEPATH% 或 Z:\
- HOMESHARE：用户主目录的 UNC 路径，例如 \\bigfirm\com\BigShares\Home\Blogs

# 主目录 vs. 本地存储

你为用户提供了一个中心化的存储机制。你应该考虑通知用户，数据应该存储在此驱动器上，而不是设备的本地驱动器上。你可以使用组策略来执行此策略。以下是成功的关键：

- 告知用户主目录会被备份，而设备不会。对于存储在设备上的数据没有服务等级协议（SLA）。
- 在文件服务器上启用卷影复制服务（Volume Shadow Copy Service），并教育用户如何使用“以前版本”客户端来恢复他们的文件。
- 设备上的数据可能是不安全的。教育用户数据安全的需求。
- 在需要的地方使用审计，并使用所需的权限管理服务（Rights Management Services），允许用户在文件级别控制谁可以查看或编辑文件。

你稍后将查看一些自动化机制，这些机制将进一步鼓励用户将数据留在服务器而不是设备上。

本节讨论了如何允许用户无论登录到哪个服务器或设备都能访问其个人数据。现在我们将涵盖漫游配置（roaming profiles），并讨论它们如何对工作环境实现相同的功能。

# 创建漫游配置

配置文件（profile）是一个包含所有用户工作环境设置的文件夹。默认情况下，配置文件存储在 C:\Users 目录下。漫游配置存储在网络上，而不是用户登录机器的本地驱动器上。然而，它默认会在本地缓存。漫游配置的优势是，用户可以登录域中的任何机器并获得一致的工作环境。但是，你必须注意配置文件中包含特定于计算机、应用程序或操作系统的信息，这些信息可能不适用于其他系统。
