In fact, there are a of ways that checkpoints can get you into trouble with Active Directory. The most obvious example is when you have a member server latest 40 days ago. In its local database, it stores two passwords, the current and the previous. If it has changed its password twice, the checkpointed server has no matching password in Active Directory. In other words, it is no longer a member of the domain and needs to be rejoineded. This problem is the same as with regular backups. For domain controllers to replicate, they need some administration that tells them what they've already received from their partners and what they are still missing. Administration depends on the sequence numbers (USNs) that each DC generates each modification of its database. Any change has a unique USN associated with it. The point is that when you restore a snapshot of a DC, you restore the configuration of that time. The problem is that the other DCs do not know this has happened! When they look at the DC that has a snapshot restored, they see that they've already processed the current USN of that DC. So the replication partners of DC see no need to replicate any data. Effectively, DC will not replicate until its USN is higher than its partners' have updated. All data that the affected DC generates in that period will never leave the DC.

This complicated by very serious problem affecting legacy DCs, known as USN rollback, is documented in Microsoft's Knowledge Base article 87549 (http://support.microsoft.com/kb/87549). Luckily, if the DC detects this, it will immediately stop Active Directory activity and log the problem in the Directory Service event log. The point is to make you aware that using checkpoints can lead to unexpected problems, in systems that you know well. The best way to avoid this is to checkpoint the whole group after shutting them down and restore them as a group. You might wonder why these problems occur when you do a regular backup of a DC and restore it. The answer is that Windows restorations are aware of Active Directory replication amplification and reset. When a restored controller comes online after a non-authoritative restore, it signals to its partners that it should be treated as if it has never replicated.
