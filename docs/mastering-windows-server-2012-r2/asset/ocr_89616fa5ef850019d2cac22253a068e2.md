# Creating Organizational Units, Accounts, and Groups

Once you have created your domain, you will want to create your OUs, user accounts, computer accounts, groups, and so on. There are two tools to choose from: either you stay with the legacy Active Directory Users and Computers (ADUC) tool or choose to work with the Active Directory Administrative Center (ADAC). Microsoft will push up new features and management tasks to the ADAC, so it makes sense to start using this new console.

Both tools allow you to create everything with point-and-click ease. However, you can also run the tasks from the command line, preferably with PowerShell. This is very handy in a couple of situations:

+   - You need to create or modify any objects and you want to script the process.

+   - You are running Server Core and you don't want to use the ADUC or ADAC GUI tools.

# CREATING ORGANATIONAL UNITS

Organizational units are used to organize objects within Active Directory. Any object (such as users, computers, groups, and so) can be placed within an OU to make them easier to administer. The two primary reasons why you would create an OU are:

+   - Management through Group Policy

+   - Administrative delegation

# MANAGEMENT THROUGH GROUP POLICY

Group Policies (GPOs) can be created and linked to sites, domains, and OUs. If you want some users to use a specific group policy assigned to them, you can create an OU, place the accounts within the OU, and link the GPO to the OU.

However, if you haven't created any OUs, any way GPOs can be assigned to regular accounts is through the Default Domain Policy that is applied to all users and computers equally. Imagine that you want to deploy a policy to users in the sales department using Group Policy. If you link your GPO to the domain, all in the entire company would get the policy, not just the users in the sales department.

Instead, you could create an OU (let's call it Sales), move the sales department user and computer accounts into this OU, and then link the GPO to the Sales OU. If you have other users that want to apply specific Group Policy objects to them, you would create an OU for them and place their accounts and computers within that OU.

Another way of applying GPOs to some users or objects is to create an Active Directory security group and add it to the group all users who need to get the policy settings. After you have created your group and provisioned, you could add this group to the GPO's Security Filtering section and remove the Default Authenticated Users from the Security Filtering settings. For detailed steps read Chapter 9, "Group Policy: AD's Gauntlet and Active Directory Delegation." It will show you how to accomplish this and more.
