# IMPORTANT! NTFS PERMISSIONS—LEAST PRIVILEGE RULES

If you haven't noticed by now, Central Access Policies work with NTFS permissions. The least privilege prevails in all cases. For example, if you are granted Full Access by a Central Access Policy and the maximum permission available from NTFS for a user is Read-Only, the rights you will see in the Effective Access tab will be Read-only!

The permissions are set as Central Access Policies logical "And" NTFS permissions. Try it out for yourself.

# Classification

First, we'll quickly explain what is meant by classification. I am sure you are all familiar with army movies, and you've seen a file opened with a big stamp on saying "Top Secret." This is classification. Simple, eh? Essentially you are brought front with the contents of a file. In today's enterprise, documents can be classified based on what's important to the company. For example, for hospital, patient information is highly sensitive and may be classified with the tag "Sensitive." A common scale consists of three classifications:

+   - **High Business Information** Information that can damage a company's reputation or business significantly to the point of closure or criminal investigation
- **Medium Business Information** Information that would cause a company great embarrassment or harm the company's future
- **Low Business Information** Information that is generally available or of an insensitive nature

It is extremely important to understand the need to classify documents within an enterprise. Simple put: do you really want information leaking out of the company that could be, for example, expose a trade secret, causing irreparable harm to the company?
Classifying documents gives a company a chance to stop this type of data leakage. For example, with the Rights Management Service, you can detect that a document is top secret using different rules, and you can encrypt its contents or block it from being opened by unauthorized personnel.

The big problem, as you can imagine, how to classify all the documents in an enterprise. Chances are it not has the practice to write such information in the file's properties when an enterprise wants to retrofit classification onto their documents, it is a cost both in time and money.

In Windows Server 2012 you have the ability to automatically classify documents, so you can secure the contents if using RMS or block access with Dynamic Access Control. It is interesting to note that file classification has been available since Windows Server 2008.
