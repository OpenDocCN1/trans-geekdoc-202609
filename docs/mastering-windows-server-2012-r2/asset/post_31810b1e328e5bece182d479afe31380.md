# Understanding Virtual Disks

When you create a virtual machine, you assign virtual disks for network, video, and so on. Your VM also needs a virtual disk, of course. The question is, what type of disk? The physical disks are in use by the host! The solution is simple and obvious: because you are virtualizing and emulating, use a free file and instead of that the VM as a disk. A virtual disk is nothing more than a very large file—don't forget that it can scale up to 64 TB if required!

Hyper-V has multiple flavors of virtual disks to offer you for various scenarios where you might want to use each one:

**Dynamically Expanding Disk** A virtual disk in format will allocate the physical disk space it needs and no more. For instance, you might allocate 127 GB for a Windows Server 2012 VM, which uses less than 10 GB after a basic install. The VM expands. The expanding virtual disk makes the best use of the available disk room on the host. But as you can imagine, there can be a performance cost involved when an expansion is needed, and you run the risk of fragmentation.

Also, a clear disadvantage is that you may run out of disk space on the host when the dynamic virtual disk expands beyond available room. When that happens, Hyper-V freezes all VMs, and the event logs red—not a nice situation to find yourself in! This issue is isolated to Hyper-V and is the same when using provisioned disks in VMware.

**Fixed-size Disk** To get rid of the overhead of expanding disks, you can choose to use a fixed-size disk. The full size of the virtual disk will be allocated when the disk is created, so you can easily track how much physical space you are using for your VMs. This is generally the recommended format for most production.

When you create such a disk, a file is created with the full size. During creation, the file is filled with zeros. This may take some time, depending on the size you specify. A fixed-size disk is highly recommended to be your default for any scenarios.

**Differencing Disk** This is an interesting feature where you have parent-child relation between virtual disks. The parent disk is read-only. The differencing disk (child) stores all changes with respect to the parent. The point of this is to save disk space on the host. However, if the VM using differencing disk is writing a lot of new data, the advantage of saving disk space will disappear. Clearly, this is useful only for test purposes.

**Pass-through Disk** The last favor is pass-through disk, where you assign physical disk to VM. This is possible when you connect VM directly to SAN or SCSI target. If you have a local disk on the host, it must appear as physical disk. Also, to be able to use the disk in VM, it must be offline in Disk Manager. Generally, you'll use pass-through disk in certain scenarios where you need a volume greater than 64 TB or if you don't need to use pass-through, stick with fixed or dynamic virtual disks and the host.

# Virtual Disks and Their Controllers

As you learned in 'The New Hyper-V 2012 R2', you have virtual disk format to work with. In Windows Server 2012, its normal extension is .vhdx, and earlier versions of virtualization products use .vhd format for their virtual disks. Even more important, this structure is freely usable by anyone. From a disk point of view, the specification does not assume any type of file system in the VM. The VM may run Windows with NTFS and FAT32 or Linux with Ext2, or whatever will be developed in the future. The specification of VHDX and VHD files means that they can be used for virtualization from other companies and anyone can write tools to handle them.

Windows accesses disks through controllers and a VM running on Hyper-V presents usual types: IDE and SCSI. In a physical machine, SCSI systems generally perform better. Not only are SCSI disks faster than IDE disks (generally speaking), but the SCSI interface was designed to handle multiple I/O requests at the same time. In a VM, both IDE and SCSI data transfers are quickly translated to requests that depend on the storage system of the host. In fact, .vhd file has no knowledge of its controller. This means that the same .vhd file can be used with IDE and SCSI controller.

# FIXED OR DYNAMIC VHDX: WHICH VIRTUAL DISK TYPE IS?

If you're familiar with Hyper-V, and you've carried out your research on virtual disk types in Windows Server 2012 R2 and can't make your up as whether to use fixed, dynamic, or even pass-through disks, you're not alone. In earlier versions of the legacy VHD format, the general consensus was that you wanted the best performance, then you also had to use fixed VHD. Dynamic VHDs were the cause of performance issues, but when Windows Server 2012 was released, Microsoft was encouraging people to use dynamic disks with their new VHDX format since the performance issues of the past had been resolved.

There's a bit of a divide inside the Hyper-V community as the performance gains or losses between fixed and dynamic VHDX disks and the practicality of using each one. You only have to look at blog post from Irish Hyper-V MVP Aidan Finn, http://www.aidann.com/tp-1238, to see that he says about all else. For a different perspective, see this post from another well-regarded Hyper-V MVP, Thomas Maurer, http://www.thomas-mauer.com/2012/11/windows-server-2012-hyper-v-virtual-disk-vhd-vhdx-recommendations/, who prefers using dynamic VHDX for the majority of instances.

My own preference for Windows 2012 R2 is to use dynamic VHDX disks for low-utilization VMs (such as domain controllers, print servers, and so on) and fixed VHDX disks for any VM that requires a higher level of I/O (such as SQL and Exchange Server). That way, I get the best of both worlds in terms of performance and storage management.
