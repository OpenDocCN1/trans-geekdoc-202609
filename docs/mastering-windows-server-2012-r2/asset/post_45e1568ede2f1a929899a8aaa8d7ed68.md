This is probably a good time to use some terminology for people new to Active Directory and user account management. Every user has two types of names with which they can access resources on the network:

**User Logon Name** is the name that you are probably most familiar with, such as SRed.

**User Principal Name** is a username that looks like an email address. You can see in Figure 8.6 that the UPN for Steve Red is SRed@bigfirm.com. The UPN suffix @bigfirm.com is inherited from the name of the domain by default. Note that you can add UPN suffixes to your Active Directory forest by following the instructions at http://tinyurl.com/3y4zw.

You can see in Figure 8.8 that the user is created and it is located in the \BigFirm\Users OU. That's pretty simple, right? Let's take a look at how you can do the same thing from command line.

![](img/41a83208e6906a3732620203b836cea7_422_0.png)

The first command you'll look at is dsadd. The following command will re-create what you've just done in the GUI:

```
dsadd "CN=Steve Red,OU=Users,OU=BigFirm,DC=bigfirm,DC=com" -samid SRed -upn SRed@bigfirm.com -fn Steve -ln Red -display "Steve Red" -pwd Hydogisblu3-mustchpwd yes
```

Wow! That's quite a command. Here is the syntax:

```
dsadd user <Distinguished Name of the user> -samid <user logon> -upn <principal name> -fn <firstname> -ln <surname> -display <full name> -pwd <password> -mustchpwd the user must change their password on first login: yes no
```

What's with that distinguished name (DN) thing? The DN describes where Active Directory the user object is created and how it is made. The DN in our case is: CN=Steve Red,OU=Users,OU=BigFirm,DC=bigfirm,DC=com. That breaks down as follows:

- Component Name (CN): This is the name of an object. In this case, it is the name of the user account.
- Organization Unit (OU): You have a number of these to define your path of \BigFirm\Users. You have noticed how the DN is working its way backward through the path, and in CN=State DC,OU=Users,OU=BigFirm?
- Domain Component (DC): This describes the name of the domain, as bigfirm.com. Notice that this is not backward the rest of the DN.

You can get more on creating users using the dsadd command by typing dsadd user /. There's a chance that you've seen the net user command has a domain option. Why we haven't chosen to use it here. The reason is that net user does not allow you to specify where in the domain you should create the user account object. You want to create the user in \BigFirm\Users, and dsadd allows you to do this.

Let us open the user account for Steve that is created on the member server, Server01. You should right-click that and choose Properties. This opens the screen in Figure 8.9.

FIGURE 8.9

This dialog box will look pretty familiar. These are the settings defined for the user account when you created it. The grayed-out check box, "Account is locked" will be enabled if the user is locked out. An account will be locked out if the password policy defines that it is locked out after x number of failed password entries within a specified time frame. By default, this is defined in the Default Domain Policy. Notice that you cannot select this box; that's because you cannot use this dialog to lock out a user. The option becomes enabled only when the user is actually locked out.

We mentioned profiles a moment ago. Quite simply, an administrator will create a folder for the user to automatically store their personal data and settings and share the folder on a file server. It will have security permissions placed on it that only the user in question (as well as local system and local administrators) can access the folder. This will allow the user's profile to be stored in this folder when they log out and downloaded when they log in. In example of such a folder might be \DC01\profiles\Sreed.

- DC01 is the file server.
- Profiles is a shared folder.

All authenticated users can read and write to the share. The folder in the file system allows only authenticated users to read the contents. Local administrators will probably have full control permissions on the share and the folder. You might consider considering this share as a hidden share that is not visible when you browse the network by naming the share Profiles$.
