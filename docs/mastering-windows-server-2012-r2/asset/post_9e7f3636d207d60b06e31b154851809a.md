## JOINING A DOMAIN

Follow these steps to join a Windows Server 2012 to a domain. Once the server is joined to a domain, it is referred to as a member server.

1. Log on to the local server.
2. Start Server Manager and click Local Server.
3. In the upper-left click the link right next to Domain.
4. The System Properties dialog will appear. Select the Computer Name tab and click the Change button.
5. Select the Domain radio button, and enter the name of the domain you are joining. Your display will first look similar to Figure 7.23, which shows the WORKGROUP, and in Figure 7.24 we added the domain that we want to join. Click OK.

You will be prompted to provide the credentials of an account that has permission on the domain.

6. Enter the credentials, and click OK.

7. After a moment, you will see a Welcome dialog box. Click OK. You will then be prompted to restart the computer. Click OK.

8. Click Close to the System Properties dialog box.

9. You will receive another reminder the server must be restarted. Click Restart Now.

After the server has rebooted, it will be the name of domain—a member server.

## OFFLINE DOMAIN JOIN

Windows Server 2008 R2 introduced a new feature that allows you to join a Windows 7/8 or Windows Server 2008 R2/2012 system to a domain without contacting a domain controller. It can be useful if the computer doesn't have reliability to the corporate network. Windows Server 2012 also offers this feature but there is still no GUI available to configure. For more details about an offline domain join, check out the article on TechNet at http://technet.microsoft.com/en-us/library/dd392267.aspx, which has been updated for Windows Server 2012.

## DECOMMISSIONING A DC

If it's necessary to take one of the domain controllers out of service, it is imperative that you properly decommission it. When you decommission it, you remove all Active Directory components and return the domain controller to a member server role.

Properly decommissioning the DC is especially important if you need to take the first DC out of service. The first DC in the domain includes several Operations Masters, masters called FSMO roles, which are integral to the proper operation of the domain. If this server fails and you are not able to bring it back up, you are going to have some problems until you properly decommissioned it.

The method of decommissioning a DC is simple to run the PowerShell cmdlet Uninstall-ADDSDomainController. In Windows Server 2008 R2, you are able to run DCPromo to promote a domain controller, but at this Windows Server 2012 version DCPromo is gone. This task will perform very similar to the DCPromo in the past versions. If the domain controller you are promoting to a new domain controller, promote the domain controller, move the computer object from the Domain Controllers OU into the Computers, and take care of other details. The DNS server role will still be installed and running, but if your DNS zones were Active Directory integrated (ADI), they are no longer available.

If this server fails and you are not able to run Uninstall-ADDSDomainController, you will need to remove all the dependencies from the domain, like DC SRV records that pointed to this domain controller and other deleted hidden traces in Active Directory from this domain controller. In previous Windows versions, it was a rather lengthy and tedious process using NTDSUtil; however, if you are using the Active Directory Users and Computers snap-in in Windows Server 2012, you can simply delete the domain controller object in the Domain Controllers OU, and you are finished.

For anyone who has gone through the lengthy process using NTDSUtil, and other tools, this is a great addition:

1. Launch Active Directory Users and Computers, and browse to the Domain Controllers OU.
2. Locate the DC you want to decommission. Right-click it, and select Delete.
3. Verify that you have selected the correct DC, and click Yes in the confirmation dialog box. A dialog box will appear warning that you are trying to delete a DC from AD without using the Active Directory Installation Wizard. own4. Select the check mark where it says "This Domain Controller is permanently offline and no longer be removed..." (see Figure 7.25)
