For troubleshooting, however, all the default parameters will generally be sufficient, and you can use server.example.com to give a rough-and-ready-estimation of whether the server is resolvable and reachable.

# Pinging a Remote Computer with traceroute

tracerert, as Microsoft chose to abbreviate traceroute (does anyone still remember the days when eight-dot-three filenames were all had?), is a tool whose purpose is to trace the route to a destination. With ping, tracerert is not necessarily an indication that a TCP connection to a remote host will work or not. But it's generally going to give you information that you need.

tracerert acts in a similar way to ping, in that it sends an ICMP echo request and waits for an ICMP echo reply. How it differs is that tracerert sets the TTL (hop count) on outgoing requests. If three packets are sent with a hop count of 1, the next three are with a hop count of 2, and so on, to a number you can specify (which defaults to 30).

Since routers decrease the hop count on packets as they pass through, the first three packets will encounter an error at the first router on the way to the destination. Fortunately for tracerert, it reports that the discarded packet, and the tracerert uses this information to display the address of the first router. Similarly, the second three packets will show where the second router is, and so.

Some routers are not configured to respond with this information or are busy that have no time to do so. These replies will be seen as a "time-out" in the tracerert output. This may happen at one or two hops along the route. When you see several time-outs in a row, it usually indicates that the last router before the start of time-outs is unable to forward packets toward your destination or your destination is not responding.

As you can see from the tracerert output in Figure 20.24, the host for www.microsoft.com in this part of the world is lbl.ms.akdns.net. This may be different if you reproduce this test. We know already, from trying to ping this host, that it does not answer to ICMP echo requests, and for reason, packets with hop counts of 14 or more are not replied to, either with echoes or with errors.
