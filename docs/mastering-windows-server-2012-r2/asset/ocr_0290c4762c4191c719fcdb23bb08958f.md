In single Active Directory domain environment, you can leave this alone. DNS servers can use these features to resolve Internet-based namespaces by Sybex when a client requests it. In larger environments, you can remove the root hints on other DNS servers and rely on one for DNS support resolution through the external environment. It would essentially be the caching DNS of the internal structure.

While root hints manage the queries going down the hierarchical structure, delegation manages queries going upward. In our example, the DNS servers that control the .com namespace delegate the control of registered subdomains to Sybex. The delegation .com name server sends the list of servers to a DNS server looking for Sybex.com addresses.

In a Windows environment, you can see delegation in multiple Active Directory domains. If you have an Active Directory domain named Bigfirm.com, you have an associated Bigfirm.com DNS namespace. You can create an Active Directory domain named Ecoast.Bigfirm.com. Instead of delegating all the DNS namespaces on the Bigfirm.com DNS server, you can delegate Ecoast.Bigfirm.com DNS namespace to another DNS server.

Figure 6.9 illustrates this delegation in the DNS management console. The DC1 DNS server supports a forward lookup zone named Bigfirm.com. The Ecoast subdomain, represented by an icon of a gray folder with a text file on top of it, lists only a name server record for EC1.Ecoast.com with its IP address.
