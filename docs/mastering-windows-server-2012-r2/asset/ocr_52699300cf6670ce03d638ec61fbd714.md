Increases Flexibility The feature of identical virtual hardware makes for a high degree of flexibility. You can move VMs from hosts for load distribution or maintenance. If your company is thinking of moving to the cloud (either public or private), then virtualization plays a major role in elasticity.

Joins Legacy Systems Many organizations run a mix of operating systems—not only Windows Server 2012 R2 but also older systems running Windows 2008 or even Windows 2003. Chances are that those systems require little computing power on modern hardware. This makes them ideal candidates for consolidation. One host will have enough power for many operating systems, which will also benefit from the uniform virtual hardware.

In large environments with large storage area network (SAN) deployments, mirrored datacenters, and similar infrastructure, virtualization is an asset for disaster recovery. Not only is server consolidation a benefit, but all virtual machines have the type of virtual hardware. You will have no driver or HAL issues when restarting a virtual machine on a new Hyper-V.

Each technology has its downside and virtualization is no exception. Some of these disadvantages may impact you more than:

Increases Complexity Virtualization adds a layer of complexity to the environment. You need to know whether a server is a VM or a physical server, and there is a host for VMs. For SQL Server administrators previously would be responsible for all aspects of SQL Server: software, hardware, and configuration. If SQL Server is virtualized, they must depend on the administrators of the host to keep their VMs running. The impact on the host will also impact the SQL Server VMs.

Places Demands on Infrastructure A full-blown VM environment will need additional infrastructure: a SAN solution is mandatory in large environments, as dedicated management software and a scalable high-speed IP network.

Can Large-scale Failure If you are not specifically designing for service availability, a host is a single point of failure. If it goes down unexpectedly, for instance, because the CPU overheats and shuts down, it will take all VMs down with it. Think of the phrase “putting all your eggs in one basket!”

Requires Special Maintenance If you have a library of VMs, you will need to do some maintenance of those as well, such as applying patches.

Unique Security Issues There are some security considerations related to virtualization. For instance, in a SAN-environment, you will have two additional groups of administrators who can access data in a VM: the host machines and the SAN administrators. A SQL Server administrator responsible for the VM may not be aware that those administrators can, in principle, access his data at, assuming they have the desire and knowledge to do so.

Another example would be a scenario where multiple security domains are located on the same virtualization infrastructure, such as an organization’s DMZ and LAN located on the same host, or a multi-tenant cloud that runs completely different customer environments.

Requires a Learning Curve When you deploy a new technology, you need to learn it. While you are learning it, you will make mistakes. Some of these will impact your production environment. That’s nothing new, but it’s still a factor to consider.
