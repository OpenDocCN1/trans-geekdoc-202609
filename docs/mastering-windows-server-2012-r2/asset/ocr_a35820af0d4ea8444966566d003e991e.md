# ASK BEFORE YOU SHOOT

Wouldn't it be nice to have some of the future to see what would happen if you did certain things? Let's say you have a domain controller that you would like to promote, but you are not sure if all prerequisites have been met. PowerShell 3.0 is your friend and gives you cmdlets that you can try before you actually do. In your example you could run Test-ADDDSomainControllerUninstallation. This will run an actual check and tell you if all prerequisites for a successful status or failure and other useful information. After running this cmdlet, you will be prompted with a status success or failure. With all other cmdlets, you can run Get-Help or just run Test-ADDSDomainControllerUninstallation to get more options for this cmdlet.

If you are digging about PowerShell 3.0, there are several other "Test" cmdlets, for example, Test-ADDSDomainControllerInstallation, Test-ADDSDomainInstallation, Test-ADDReadOnlyDomainControllerAccountCreation, and so on. Check the TechNet article at http://technet.microsoft.com/en-us/jh974719.aspx for more information on this topic.

# TROUBLESHOOTING AD

A common problem occurs with DNS that records are not created when the server is rebooted. The logon service is responsible for creating these records, and sometimes it seems to hiccup after rebooting the server.

As a reminder, SRV records are used to locate domain controllers in a domain running specific services or holding policies within a domain. After a few examples, within the domain often need to locate a global catalog server, a PDC emulator, a domain controller within a specific site, or simply a domain controller in the domain. Services query DNS for the appropriate SRV records, and as long as they exist, the server can be located. However, occasionally these records aren't created after a reboot. Figure 7.26 shows the DNS Manager console open to show that there are several folders starting with an underscore _misdc, _sites, _tcp, and _udp. Each of these folders includes SRV records.
