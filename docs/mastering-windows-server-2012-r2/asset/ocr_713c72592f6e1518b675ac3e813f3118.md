# FSMOS and GCS

Transferring FSMO roles is very simple via the GUI, you've seen. But there's a catch: you can use the GUI to transfer FSMO role if the current FSMO is up and running. If you disked the computer that was acting as your domain master, then there's no one around to approve" transferring the role to another computer. In that case, you can just transfer the Operations Master role—you must, using your best pirate anchor, "Seize the master! Argh"

If your PDC or infrastructure master goes offline, it's perfectly safe to transfer those FSMO Roles to another computer, and you can actually do it through the GUI. It will tell you that the operations master is offline and you can transfer the role, ignore it and Change anyway.

But to seize RID, domain naming, or schema FSMO, you'll need to use a command-line tool, ntdutil. You can also transfer the FSMO roles with ntdutil, but the GUI is so much easier. You could also use this to administer Server installations. You can start it from the command line by using ntdutil. Then do this:

+   1. **Type roles;** ntdutil will respond by changing the prompt to fsmos maintenance:
2. **Type connections** to point to the computer that you are going to transfer the FSMO role by ntdutil will respond by changing the prompt to server connections::
3. **Type connect to servername,** *servername* is the target domain controller that you want to transfer the FSMO role.
4. **Type quit** to return to FSMO maintenance.

+   5. You can use the question mark to list the possible commands. This will give you the correct spelling of roles.

+   6. **Type transfer schema master.** You'll see a dialog box request for confirmation if ntdutil finds that it cannot contact the current FSMO to get its approval. Confirm that you want to force a transfer.
