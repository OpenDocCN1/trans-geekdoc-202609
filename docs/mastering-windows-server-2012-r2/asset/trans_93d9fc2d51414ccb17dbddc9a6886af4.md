

## 两个 Hyper-V API

Hyper-V 实际上包含两个内置 API。除了 WMI 之外，它还有一个 Hypervisor 接口。Hypervisor API 是一个低级接口，能够配置虚拟机监控程序、管理分区状态、处理分区间通信 (VMBus)、处理调度程序等。Hypervisor 接口实际上是为了编写你自己的 V/VSC 模块以及其他系统级代码而设计的。作为管理员，你可能永远不会直接接触 Hypervisor API。

为了完成管理操作系统（Management OS）分区的概述，你对运行在 Hyper-V 父分区中的服务应该有所了解，它们如表 27.4 所示。

|---|---|---|
| Hyper-V 数据交换服务 | 手动 | 提供在虚拟机与运行在物理计算机上的操作系统之间交换数据的机制。 |
| Hyper-V 客户机服务接口 | 手动 | 为 Hyper-V 主机与虚拟机内部的特定服务的交互提供接口。 |

## 虚拟机（客户机）分区

在介绍了之前的大部分 Hyper-V 架构后，我们只剩下虚拟机分区需要讨论，而且我们实际上已经涵盖了其中的某些元素。图 27.9 中的第一个子分区运行着对虚拟机监控程序感知的操作系统。微软将此类操作系统称为“开明客户机”（enlightened guest），而其他可能称之为“半虚拟化”（paravirtualized）。因此，它拥有 VMBus 接口和虚拟服务客户端（VSC）。问题是，虚拟机最初是如何变得开明的？在管理操作系统中，你安装了 Hyper-V 角色，但显然你需要在客户机中进行某些操作以提供所需的软件组件。虚拟机的 Hyper-V 软件通常称为集成组件（Integration Components），在微软文档中称为虚拟服务客户端（VSCs）。虚拟机的 VSC 版本必须与主机的 Hyper-V 服务器版本匹配。

## 开明有两种类型

开明存在两种变体：一种通用类型和更特定的类型。通常情况下，与 VMBus 接口协作的操作系统被认为是开明客户机。旧系统，如需要先安装 VSC 的 Windows XP 和 Windows 2003，被认为是非开明客户机。特定变体适用于内核：如果内核原生感知虚拟机监控程序，则该操作系统被称为开明内核（enlightened kernel）。这包括任何运行 Windows 2008 或更高版本的服务器客户机操作系统，以及运行 Vista SP1 及更高版本的客户端客户机操作系统。开明内核的优势在于它能够进一步优化对 VMBus 的访问。例如，当 Windows 2012 意识到数据是用于虚拟设备时，它可以跳过某些网络和磁盘访问的内部软件层。

只有运行 Windows 2008 及更高版本的客户机才内置了 VSC 版本，尽管该版本需要升级以匹配你客户机的当前 Hyper-V 版本；在 Windows Server 2012 R2 主机上运行 Windows 2008 客户机虚拟机就是一个例子。对于其他操作系统，你需要显式地安装 VSC。实现此操作的方法之一是将带有 VSC 的 ISO 文件插入虚拟机。该 ISO 文件是随 Hyper-V 捆带的。

VSC 实际上是安装在虚拟机分区 `%systemroot%` 中的一组模块。每个版本的 VSC 更新都有对应的一个 `<version>` 文件夹。查看其功能，你会发现它被分为两个部分。一方面，有用于存储、视频和网络的驱动程序。另一个驱动程序直接与内核集成，以优化其作为虚拟机运行时的性能。另一方面，有一个多用途服务可执行文件 (vmcsc.exe)，它带有四个不同的参数启动，以提供以下功能：

-   **操作系统关机服务**：根据父分区的请求，此服务将以有序的方式关闭虚拟机。

-   **心跳服务**：父分区需要一种方法来告知客户机是否仍然存活。如果父分区无法再听到心跳，可以安全地假设客户机出现了严重问题。

-   **时间同步服务**：子分区无法直接访问硬件时钟。此服务提供替代方案。不要在 Active Directory 域环境中中使用它，因为它有自己的时间同步基础设施。

-   **数据交换服务**：此服务是父分区和子服务中的用户（环 3）进程在常规设备之外进行通信的唯一方式。它通过某些注册表项工作。

-   **备份（卷快）服务**：此服务将与父分区上的备份服务配合，利用 VSS 管理技术为父分区和子分区提供一致的备份。

-   **客户机服务**：这是一个新的 VSC，仅适用于 Windows Server 2012 R2 第二代虚拟机。它默认是禁用的，但当你启用它时，你就有了在不利用网络连接的情况下将文件复制到运行中的虚拟机的能力。

注意的是，VSC 无法从虚拟机进行配置。唯一的（正确）方法是通过操作系统分区，或者使用 Hyper-V 管理控制台、PowerShell 或使用 WMI 接口。

继续讨论虚拟机分区，让我们看看图 27a 中的第二个子分区。它被标记为“非开明客户机”。这意味着操作系统不是开明的。如果未安装或无法使用 VSC，你可以将 Windows 2003 同时作为旧系统和开明系统安装。对于 Windows 2000 或 Windows 2003 等不支持的系统，微软没有编写任何 VSC，尽管理论上需要时可以编写。缺少 VSC 并不意味着虚拟机无法运行，但如果你遇到问题，它永远无法达到高性能或获得支持。另一方面，许多旧操作系统即使在可视化时也能运行良好。该图显示非开明系统没有 VMBus 或 VSC 提供程序，而是使用仿真。

第三种也是最后一种虚拟机分区运行非微软操作系统，例如使用 Linux 虚拟集成服务 (VIS) 的 Linux。这些是内核级驱动程序，提供了与微软虚拟机 VSC 几乎所有相同的功能。这些 Linux 组件是微软专门为该操作系统编写的，因此当你遇到任何困难时都能获得完全支持。你可以预期此类开明系统具有接近原生的性能。
