# Using Microsoft's Free Migration Tool: ADMT

If you're thinking about a migration or domain consolidation, you might need a migration tool, and if you've priced migration tools, you might be reconsidering a domain migration. If you didn't, because Microsoft offers a migration tool to called the Active Directory migration, originally created for Microsoft NetIQ, ADMT v3.2 maintains the ease of use of the original and adds some new features as well.

# Version Incompatibility

At the time of this ADMT 3.2 is not directly supported on Windows Server 2012 for migration. If you want to use ADMT, then you will need to configure a Windows Server 2008 R2 server that can act as the host. You will need to have a Windows Server 2008 R2 domain controller in your new Windows Server 2012 domain. This will allow you to process the ADMT and Password Encryption Service (PES) programs properly.

Once you have migrated and completed all tasks, moving the users and other components to be fully supported in your new Active Directory domain, you can use DPromo to remove the Windows Server 2008 R2 domain controller and move on.

If you have already placed your Windows Server 2012 Active Directory domain in a Windows Server 2012 domain functional level, you will need to utilize the following PowerShell commands to revert:

To set your functional level back to Windows Server 2008 R2, run:

```
Set-ADForestMode -identity oldfirm.com -forestmodeWindows2008 R2Forest
```

To set your domain level back to Windows Server 2008 R2, run:

```
Set-ADDomainMode -identity oldfirm.com -domainmodeWindows2008 R2Domain
```

Considering that ADMT v3.2 is unsupported at this point, we are not going to dive into the steps to make this work. Many options exist in Windows Server 2012 Active Directory to help you clean up your current domain and get great reporting and error checking. It is much better to use the in-place upgrade or swing migration approach to Active Directory to do the Active Directory migration.
