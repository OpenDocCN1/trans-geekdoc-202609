## WAIT ON THE LICENSE SERVER

When experimenting with Remote Desktop sessions to find out how many users will be able to support for each session, do not set up a license server; let the RDS server issue its temporary 120-day licenses for this purpose. Although this sounds counterintuitive, using the temporary licenses prevents you from unwittingly assigning per-device licenses to test equipment. See the “Licensing Mode” section for an explanation of how licensing and license allocation works.

When connecting to an RD Host server via a native RDP client, you’ll most often use a PC with a Windows operating system loaded, a Windows terminal.

## NATIVE RDP CLIENT

In this context, a RDP client means one available from Microsoft and thus implies Windows. Although Microsoft does not support other platforms (except for OS X Macintosh client, available for download at www.microsoft.com/mac/products/remote-desktop/default.msp), Hobsoft sells a cross-platform (Windows, Mac, Linux, DOS) client at www.hobsoft.com/products/connect/jwt.jsp, and there is a free Linux RDP client available at www.rdktop.org.

## WINDOWS TERMINALS

In its narrow definition, a Windows terminal is a network-dependent device running Windows CE that supports one or more display protocols as RDP or Independent Computing Architecture (ICA), the display protocol used to connect to Presentation Server servers. Windows terminals also use some form of terminal emulation.

For this section, a Windows terminal is any terminal device designed to connect to a Windows RD Host server; it can run any operating system that has an RDP client. A Windows-based terminal (WBT) is such a device that is running a Windows operating system locally and follows the Microsoft system requirements for WBTs.

The main thing defining a Windows terminal is its hard profile because the main job of Windows terminals is to run a display protocol, which doesn't need much memory or processing power, and that includes a processor; some amount of memory, network, and video support; and input devices such as a keyboard (or equivalent) and mouse (or equivalent). The terminals generally have CD-ROMs, or DVD players or stand in local memory. Beyond these similarities, Windows terminals range physically from a 'toaster' form to a pad to a small box that attach to the back of a monitor—or even to the monitor itself. Some of Windows terminals are wireless terminals, intended for people (such as doctors and nurses) who would ordinarily use clipboards and folders to store information.

Although Windows terminals are entirely dependent on their RDS server, a small set of them can run applications locally. The devices don't have hard disks; the disks are stored in ROM like the operating system. The types of applications available on the terminal's operating system, since locally stored applications must run instead of being displayed. Generally speaking, it's more common for Windows terminals to depend on RDS server for applications.

Windows terminals are most popular in environments where people are using a single application, where supporting PCs would be logically difficult, or anywhere else PCs aren't a good fit. However, PCs can't depend totally on server-based computing. Companies already have PCs, and unless they're refreshing the desktop entirely, taking away a powerful PC to replace it with a less-powerful terminal doesn't make sense.

## PC CLIENTS

At this point, people are using twice as many PCs as Windows terminals for RDS server client machines. This isn't surprising.

- First, unless they're starting fresh, people already have the PCs. Even though WBTs are a little less expensive than low-end PCs (not much, though), they're an added cost.
- Second, not all applications work well in an RDS server environment. It's often best to run some applications on the RDS server and some locally.

Unless you're buying new hardware and don't anticipate any need to run applications locally, you're likely to have to wire with PCs for at least some of your terminal clients.
To work with Remote Desktop Services, the PCs must be wired to a Windows operating system, have RDP display protocol installed, and a live network connection using TCP/IP and a valid IP address.

## TABLETS

We're not surprised that tablets are so commonplace today, how handy they are. They're a substitute for a laptop—inexpensive, lightweight, and with their power so that travelers can use them during the entire flight without having to give up two hours takeoff.(You can also use one on a plane without worrying that the person in front of you will suddenly reclaim their seat and close your laptop's display) Usually, they run Windows or Android or Apple iOS.
What a tablet looks like depends on who makes it. Some tablets look like a laptop's baby brother, like Microsoft Surface. Others fold into a little portfolio shape or are a flat table. Some are small pocket-sized deals that are too small to work on.—The ones we prefer—have keyboards; others have only styluses. What all this comes down to is a tablet isn't generally in a position to replace a desktop PC, although there are some exceptions the Microsoft Surface Pro, which is a tablet with a keyboard that has the power of a desktop. A tablet is usually used in cooperation with a primary machine which it's partnered in some way, using OneNote or SkyDrive, for example.
