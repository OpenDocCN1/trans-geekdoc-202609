## IPv4: Address Resolution Protocol

This is where the Address Resolution Protocol (ARP) comes in to see the picture. ARP is an Ethernet broadcast. Technically, all Ethernet packets are broadcast across the subnet, but most of them carry a destination address and are discarded by other Ethernet cards when they are received. An Ethernet broadcast packet is meant to be picked up by any Ethernet.

The ARP packet contains the source MAC address of the requester and the IP address it is searching for. Every Ethernet card on this segment will receive this request and has to forward it to its IP. The layer will check whether it owns the IP address being requested. The interface that owns this IP address will respond affirmatively to the owner of the requested address.

The requester receives this response and associates the ARP table address with the Ethernet address. You can view this ARP table in any Windows using a number of different methods. The easiest to remember is probably the command -a, which shows the addresses that have been assigned to network cards, as you can see in Figure 20.2.

## IPv6 Neighbor Discovery

In IPv4, the IP layer of every computer on a subnet needs to know what it is to process incoming requests. If you know how annoying it would be for everyone to stop their work now, but if you are not careful, you can still have nasty broadcast storms that can down your network.

IPv6 replaces broadcast-based—and uses multicast-based instead. Neighbor Discovery (ND), which (among other things) takes the resolution of ARP, which is not supported on IPv6. Rather, the IPv6 layer will cache the last 24 bits of the IP address being queried for will build a multicast entry as the destination address ff02::XXXX. The Neighbor Solicitation message is sent to this address. Because there are more than 16 million possibilities for those last 24 bits, it is almost certain that this message will only interrupt the Ethernet card and interface that this IP address requested—as ARP, but this is in a table that the Neighbor Advertisement message that comes back when sending an IP packet, so as to prevent repeating the same Neighbor Solicitation message.

To show the neighbors for IPv6, can you use the ARP command? No, ARP is strictly for IPv4 only. The only way to get the neighbor discovery table for your IPv6 layer is to run the netsh command, specifically, netsh interface ipv6 show neighbors; a sample output for your Local Area Connection is shown in Figure 20.4.

## FINALLY, You Can Send the PACKET!

Now that you know who is trying to talk to, the computer at interface A can send the data by building an Ethernet packet, whose payload is the IP packet (IP header and payload) and whose header contains the source and destination address, length, and type of protocol (in this case IP). This packet is then handed down to the Ethernet card, which sends it on.

## ETHERNET TRIVIA

Did you know that although IP is an unreliable, "best-effort" protocol, which is free to lose packets of data for pretty much reason, Ethernet itself is a reliable protocol? It's true: Ethernet electrical properties of the wire it runs monitor whether a packet that tried to send might have been confused with any other packet that was on the cable at the same time—if it finds this, it pauses a random length of time and tries again.
