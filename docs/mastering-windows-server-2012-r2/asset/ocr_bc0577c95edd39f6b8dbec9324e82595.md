With a hypervisor, the host operates on the same level as the VMs: atop a hypervisor layer.

Let's take a look at the ring structure. Ring -1 is not a mandatory feature of a hypervisor, but most modern hypervisors use it. This ring is the main feature of the Intel VT and AMD-V CPU virtualization. It is a relatively new level of even higher priority than ring 0. It allows kernels to really run on ring 0 without the tweaking that is required in older hybrid models that don't include a hypervisor. This makes for a cleaner architecture, implementing fewer bugs in code and ideally better performance.

The diagram illustrates that all VMs are created equal but that one is more than the others: Host or Management OS that is responsible for the management and high-level arbitration of all VMs. It's the default owner of all hardware resources and controls the startup and shutdown of the children.

The Hyper-V hypervisor is microkernel. As the term suggests, it was written to be lean and mean as possible. It contains no GUI code and enough intelligence to do its main job: manage memory and access to the hardware. Other (non-Microsoft) hypervisors may take a different approach. In the monolithic approach, the hypervisor contains drivers, and takes more responsibility for inter-VM communication. One advantage of a monolithic hypervisor is that if it delivers a higher maximum performance bonus because of its tighter integration with drivers to access the hardware. On the other hand, if this hypervisor has no drivers for your specific hardware, you are out of luck. For mature products, this shouldn't be a real problem. In the microkernel hypervisor, the drivers actually reside in the parent partition, which in the case of Hyper-V is a Windows 2012 server. The parent partition has the drivers, so if your hardware has drivers for Windows 2012, it can work with Hyper-V.
