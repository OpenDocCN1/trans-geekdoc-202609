# CHAPTER 3 INTRODUCTION TO SERVER CORE

Now let's look at how to configure a printer using PowerShell cmdlets instead of using the older script methods in Server Core. You can use the .vbs scripts you choose, but as we said earlier, Microsoft is pushing hard to have PowerShell as its primary command-prompt administration.

To add a printer, use the Add-Printer cmdlet. This cmdlet can be used for a local printer or network printer. We'll show you both examples.

First, adding a local HP 5150 printer for the Sales department:

```
PS:\> Add-Printer -Name "Sales Printer" -DriverName "HP 5150"
```

Now, add a network printer to the server you set up earlier:

```
PS:\> Add-Printer -ConnectionName \bfsc1.192.168.1.253
```

There may be times when you may not have the driver on the server. Adding a driver to the server is snap with PowerShell using the following cmdlet:

```
PS:\> Add-PrinterDriver -Name "HP 5150"
```

Now you have a printer installed, but you need to configure the print properties, such as color. First, look at the current properties to see what you needs to be changed:

```
PS:\> Get-PrinterConfiguration -PrinterName "HP 5150"
```

| PrinterName | ComputerName | Collate | Color | DuplexingMode |
| --- | --- | --- | --- | --- |
| HP 5150 | | True | True | OneSided |

Now you have the configuration, you can change the Color property to false, as follows:

```
PS:\> Set-PrinterConfiguration -PrinterName "HP 5150" -Color $false
```

# Managing Licenses with the Key Management Service

Microsoft has the Volume Activation 3.0 process with Windows 8 and Windows Server 2012. This differs from the familiar online activation. Windows-licensed installations connect to a central Key Management server over the LAN, which will register an activation "license" for the client with Microsoft over the Internet. This allows Microsoft to control the number of activations under the same volume product key.

By default, the Windows 8 and Windows Server 2012 servers are configured to connect to the KMS server prior to attempting connection. If the server can't find one but does activate, it acts as a KMS server. You might want to control this by getting ahead of it.

When deploying a KMS server in a branch office, there are two key decision points. The first is to secure TCP/IP connectivity. This process is seriously lightweight, so it isn't a tremendous on WAN connections; however, you still need connectivity that the big cloud to centralize activations to one site. The other factor is "25." A KMS server doesn't start communicating with Microsoft until there are 25 licensed licenses to activate. This means 25 Windows 8 installations. A Windows Server 2012 license counts as five Windows 8 installations. So one Windows Server 2012 server and 20 workstations would be enough to trigger communication.
