The tool that fools the computer into thinking that it is actually separate computers is generically called a virtual machine manager (VMM).

You will see, at the start of server computing, most organizations have preferred to have their own particular server—email, AD domain controller, file server, web server, database server—on one. If you needed a domain controller, a web server, and an email server you would commonly buy three separate servers, put a copy of Windows Server on each, and make one a DC, one web server (by enabling Internet Services), R2's built-in web server, and an Exchange Server. The downside of this was that each of those servers would probably run at fairly low levels; it wouldn't be surprising to learn that the DC ran about 5 percent of the CPU's maximum capacity, the web server a bit more and the email server a bit more than that. Running bunches of physical hardware better than their capacity wasting electricity, and not you know? In contrast, buying one physical server and using a VMM (for example) three virtual servers would probably load to a physical server near capacity electricity and cooling needs.

First, let's cover the new technology added in this version. Since there are so many improvements to Hyper-V, we're just briefly touching on each one:

+   - Hyper-V gives desktop Windows Hyper-V technology without the need for installing a OS.

+   - Hyper-V module for Windows PowerShell provides more than 160 cmdlets to manage Hyper-V.

+   - Hyper-V Replica allows you to replicate virtual machines between storage systems, clusters, and datacenters in two sites. This provides business continuity and disaster recovery.

+   - Resource metrics helps track and collect data about network usage and resources on virtual machines.

+   - Simplified authentication groups allows administrators as a local security group. By doing so, fewer users need to be created to access Hyper-V.

+   - Single-root I/O virtualization (SR-IOV) is a new feature that allows you to assign a network directly to a virtual machine.

+   - Storage management allows you to move the virtual hard disks to a different physical storage without the use of a storage area network (SAN).

+   - SMB 3.0 file share is a new feature that provides virtual machines with shared storage, without the use of a storage area network (SAN).

+   - Virtual Fibre Channel allows you to visualize workloads and applications that require direct access to Fibre Channel-based storage. It also makes it possible to configure clustering directly within the guest operating system (sometimes referred to as guest clustering).
