## NETDOM: THE SWISS ARMY KNIFE OF TRUST TOOLS

As we've said, true, under-the-hood meaning of trust relationship extends beyond domain-domain trusts; it includes the connection between domain members and their DCs, meaning that even someone operating a one-domain enterprise deals with trusts. There's a tendency for administrative tools to handle either domain-domain trusts or domain membership; there's only one tool that we know of netdom manages trusts in their entirety. First introduced in the early days of Windows Server, netdom has become more powerful and useful with every version—and 2012 is no exception. The sweet part of Windows Server 2012 R is that it is installed by default. No hunting for the support tools!

Most of netdom's options affect domain membership trusts. We don't want to devote too space to this, because we're mostly interested in discussing domain-domain trusts, but it's worth listing some of the netdom options.

netdom adds a machine account to a domain. It doesn't join the machine to a domain; it creates the machine account on the target domain, and if the domain is an AD domain, you can even tell netdom OU put the machine account in. This is useful because a machine's local administrator can join that machine to a domain, if a domain administrator has already created a machine account for that machine on the domain. Here is what its syntax looks like:

```
netdom add machine /domain:domainname
```
