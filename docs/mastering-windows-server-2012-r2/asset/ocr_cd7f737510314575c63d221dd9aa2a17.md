# OFFLINE DOMAIN JOIN

Windows Server 2008 R2 introduced a new feature that allows you to join a Windows 7/8 or Windows Server 2008 R2/2012 system to a domain without contacting a domain controller. It can be useful if the computer doesn't have reliability to the corporate network. Windows Server 2012 also offer this feature but there is still no GUI available to configure. For more details about an offline domain join, check out the article on TechNet at http://technet.microsoft.com/en-us/library/dd392267.aspx, which has been updated for Windows Server 2012.

# DECOMMISSIONING A DC

If it's necessary to take one of the domain controllers out of service, it is imperative that you properly decommission it. When you decommission it, you remove all Active Directory components and return the domain controller to a member server role.

Properly decommissioning the DC is especially important if you need to take the first DC out of service. The first DC in the domain includes several Operations Masters, masters called FSMO roles, which are integral to the proper operation of the domain. If this server fails and you are not able to bring it back up, you are going to have some problems until you properly de-commsisioned it.

The method of decommissioning a DC is simple to run the PowerShell cmdlet Uninstall-ADDSDomainController. In Windows Server 2008 R2, you are able to run DCPromo to promote a domain controller, but at this Windows Server 2012 version DCPromo is gone. This tasks will perform very similar to the DCPromo in the past versions. If the domain controller you are promoting to a new domain controller, promote the domain controller, move the computer object from the Domain Controllers OU into the Computers, and take care of other details. The DNS server role will be still installed and running, but if your DNS zones were Active Directory integrated (ADI), they are no longer available.
