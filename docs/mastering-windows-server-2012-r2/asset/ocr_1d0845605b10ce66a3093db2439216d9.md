As long the routing table is complete and correct, the computer will always follow this procedure of checking the prefix against the destination address, masking the destination address with the number of bits in the prefix first, and always discarding a less-specific match when a more-specific match is found. The metric is used only as a tiebreaker in case two entries have the same prefixes that are the closest—the one with the lowest metric is.

# COMPLETING THE TABLE

How do you correct an incomplete routing table? More to the point, how do you tell if a router table is incomplete?

You've already seen that the router table is complete for every IPv6 packet. So, a correct and complete router table must be able to tell you the right place to send every packet.

It must have at least one default route, with a prefix of 0.0.0.0/0 (or :: for IPv6 routes), otherwise there will be packets that have no idea what to do. Don't forget that the routing table may have more than one default route; in that case, there are several routes that volunteer for the task. Remember that the one with the lowest metric will win.

Other than that, it must know exactly how to route every destination address that does not go to the default route. In most home environments, this is not a problem. The default route is usually the one that connects to the DSL or cable router, and everything can be sent there.

In an enterprise environment, there are often several routes in your immediate subnet. Each leads to a different portion of your network. If you list the routers and the networks to each leads, you should have a list that matches all the entries in your routing table.

If you need to add a route to your routing table, the that can be done very easily from the command line. There are two basic commands to use—the route add and our good friend netsh. Suppose you want to add a route to the prefix 192.168.0.0/16 with a metric of 100 that leads to the route 10.0.0.1. The command to do this could be any of the following:

```
route add 192.168.0.0/16 mask 255.255.0.0 10.0.0.1 metric 100
route add 192.168.0.0/16 10.0.0.1 metric 100
```

```
netsh interface ipv4 add route 192.168.0.0/16 "Local Area Connection" 10.0.0.1
```

The netsh command requires a little more typing than the route command, if you want to delete it netsh ipv4 add route 192.168.0.0/16 "Local" 10.0.0.1.

Similarly, you can delete a route—though if it is one that is automatically added because of a router advertisement, it will come back as follows:

```
route del 192.168.0.0
netsh interface ipv4 delete route 129.0.0.0/8 "Local Area Connection"
```
