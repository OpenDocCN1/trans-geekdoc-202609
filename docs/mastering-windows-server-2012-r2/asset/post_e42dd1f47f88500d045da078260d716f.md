You can return the properties of a number of users at once by specifying some search criteria:

```hell
PS C:\Users\Administrator> Get-ADUser -Filter 'Name like *' -SearchBase "OU=Users,OU=BigFirm,DC=bigfirm,DC=com"
```

There are two flags:

- -Filter: Here you are specifying any object with a name similar to the wildcard *, in all other objects, unless specified.
- -SearchBase: You've further qualified the search by specifying the \BigFirm\Users OU in the domain.

That command will return the default properties of all user objects in the \BigFirm\Users OU. If you want to modify the properties of a user object, then you will need to run the ADUser cmdlet.

```hell
PS C:\Users\Administrator> Get-ADUser SCors "IT Manager"
```

That command specifies the user, SCors, and that you want to modify the -Description attribute. This example will change this user object to IT Manager, giving Simona a promotion. You can get a list of the attributes to description by modifying this run:

```hell
PS C:\Users\Administrator> Get-Help Set-ADUser
```

It's possible to change the properties of a large number of users at once. In this example, you'll modify every object in \BigFirm\Users. You'll use the Get-ADUser cmdlet that we just discussed to find the users in that OU and feed the results into Set-ADUser using a pipe:

```hell
PS C:\Users\Administrator> Get-ADUser -Filter 'Name like *' -SearchBase "OU=Users,OU=BigFirm,DC=bigfirm,DC=com" | Set-ADUser -Description "Member of IT"
```

## Enabling an Account

Earlier we said you might want to create a user object and enable it only when the human user was ready to use. Here's how to enable a user object for Philip Witschi:

```hell
PS C:\Administrator> Enable-ADAccount -Identity PWitschi
```

## Disabling an Account

We discussed you might want to disable accounts for a certain amount of time before deleting them. Here's how to disable an account:

```hell
PS C:\Administrator> Disable-ADAccount -Identity PWitschi
```

Finally, you go to the point where you want to delete a user account:

```hell
PS C:\Administrator> Remove-ADUser -Identity PWitschi -confirm
```

We've been careful by using the -confirm flag at the end of the Remove-ADUser cmdlet. That will ask whether you want to continue with this action. Doing things from the command line is very quick, so a deletion is something you need to be careful about. If you are writing a script, you will probably not use the -confirm flag because you want the script to execute halfway through without having to interact with it.

That wraps up our coverage on managing users using PowerShell. We'll now move on to group management. To create a group using the New-ADGroup cmdlet, we noticed how similar all these cmdlets are. That's a feature of PowerShell. Set, or New and then something descriptive to identify what the cmdlet does.

```hell
PS C:\Administrator> New-ADGroup -Name "IT Administrators" -SamAccountName "IT Administrators" -GroupCategory Security -GroupScope DomainLocal -DisplayName "IT Administrators" -Path "OU=Groups,OU=bigfig,DC=bigfig,DC=com" -Description "This group is in IT"
```

That command will create a domain local group set to create IT administrators in the \BigFirm OU using these flags:

- -Name: This is the name of the group!
- -SamAccountName: This is the name associated with the pre-Windows 2000 group object attribute.
- -GroupCategory: This will be either Security (or 1) or Distribution (or 0).
- -GroupScope: This will be either DomainLocal (or 0), Global (or 1), or Universal (or 2).

**DisplayName** This is the name for the OU where the group will be located.

**Path** This is the distinguished name of the OU the group will be located.

**Description** This will fill the description field of the object for future reference.

Once you have a group, you'll start adding members to it. You'll be using the Add-ADGroupMember cmdlet to add members. You have lots of ways to do this. You'll start with the simplest one:

```hell
PS C:\Users\Administrator> Add-ADGroupMember "IT Administrators" -Member SRed
```

You can use the -Identify flag to tell PowerShell group you want to edit. You can specify a user using the -Member flag. The previous examples show the SRed user object to the IT Administrators security group.
