Notice that each of these was referred to as a Type 3 – User mode driver. Drivers before Windows 2000 were referred as version 2 Kernel mode drivers. They would interact with the kernel of the operating system and had the potential of crashing the system if something went wrong.

Type 3 drivers work only in user mode and are isolated from the operating system. Itanium is a special 64-bit architecture used in high-servers. x64 indicates a 64-bit architecture, and x86 indicates a 32-bit architecture. The good news is that you can install an x86 Type 3 – User mode driver, and it will work with any 32-bit operating system—at least it should.

Thankfully, you can load all three printer drivers onto a Windows Server 2012 R2 server, and when different systems work, the correct driver will automatically be downloaded. However, you'll still need to ensure the correct drivers are loaded on the server. In other words, if you're supporting 32-bit Windows XP and 64-bit Windows 7, you'll need to ensure you have both x86 and x64.

With the release of Windows Server 2012 R2 comes the new v4 drivers. These drivers are not compatible with operating systems prior to Windows 8 and Windows Server 2012 R2, but roll—you can print the v4 queue from the Windows Server 2012 R2 printer server using the enhanced Point and Print Compatibility driver.

Since the v4 architecture supports the print-class driver framework, users can install printers without having to locate the driver for printer. This addresses security and compatibility concerns found in v3 drivers.

# PRINTER DRIVER HUNTS

Finding the correct print drivers (especially for new operating systems) is often very challenging. In a perfect world, as soon as a new operating system is released, every company would automatically have the correct driver for their hardware will work. However, a lot of things work against this scenario. Companies may create a print driver that works with the release date of an OS so that last-minute changes to the operating system result in their driver no longer working.

Of course, when a company realizes its driver no longer works, it tweaks and reengine. Then they post the new driver on their website as quickly as possible. The driver needs to be tested and validated before the operating system or available through Windows Update.

Meanwhile, users who have upgraded to a new OS realize they can no longer print. They try Windows Update (which includes only drivers that have gone through the lengthy submission and testing process) with no joy. Educated users (and administrators) know the best source in this situation is to go to the manufacturer's website.

They go to the manufacturer's website, which may or may not have the correct driver listed, and often a lengthy game of trial and error is started until the user (or administrator) either finds something that will work or gives up. This was very apparent when Windows Vista came out and resulted in a lot of complaints from users.
