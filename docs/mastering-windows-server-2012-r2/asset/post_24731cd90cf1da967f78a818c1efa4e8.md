
2. Disable inheritance of permissions on the folder, and configure the permissions as shown here (and Figure 26.13):

Why Read Attributes?
Notice that we've added last permission for Read Attributes. It isn't documented in Microsoft documentation that we have read. However, a user's profile will fail to completely save to the file server if this permission is not added to the profile folder.

These permissions will allow a user to create a folder within the share where their roaming profile is stored. There is a downside to this approach. A user could create a folder within this share and store data within it without approval. This is required because, with this approach, the user's rights are used to create their roaming profile. The user, unknown to them, will be setting up their own roaming profile folder on the server when they log in.

# CHECKING FOR ERRORS

Be sure to log in and out a few times as the user. Check for errors in the notification area and in the Application log in Event Viewer. Any errors are typically related to typos or permissions issues.

Hold on a second! How do you know if there's anything in that profile folder? You've probably just recreated this scenario and noticed that administrators have no access to the profile. That actually is the way it meant to work. The user has created their own folder, and as Creator Owner they have full access to it. It's a bit of a pain because it makes things like backup/recovery and helping the user nearly impossible!

It's messy to grant administrators to user profiles. Ideally, there would be a way to grant access as required. You can do this with a Group Policy that you can apply to the computers creating the profiles. However, this solution must be applied before the profiles are created.

- 1. Log into the domain controller, BF2, and launch the Group Policy Management console from Administrative Tools.

- 2. Create and link a new Group Policy object, as shown in Figure 26.21, to the Computers OU where Win8, the workstation resides.

# FIGURE 26.21
The new Group Policy object

![](img/41a83208e6906a3732620203b836cea7_1324_0.png)

The policy that you are enabling applies to the computer that the user will be logging to, the user and not the file server where the profile is created. That's why the policy is linked to Computers, and not Servers, where the file server resides.

The policy that you are enabling "Add the Administrators security group to roaming user profiles" can be found in Computer Configuration\Administrative Templates\System\User Profiles. You can see it in Figure 26.22.

# FIGURE 26.22
Configuring the Group Policy object

![](img/41a83208e6906a3732620203b836cea7_1324_1.png)

- 3. Set it to Enabled, and this policy will grant Administrators Full Control to any newly created profile.

Remember that policies don't apply straightaway. In a production scenario, you will probably wait for the refresh period.
