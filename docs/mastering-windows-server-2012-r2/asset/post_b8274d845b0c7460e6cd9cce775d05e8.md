Windows Server 2012 R2 Hyper-V has several enhancements to live migration. First, you no longer need to wait for VMs to migrate individually because you can do unlimited migrations at the same time. Obviously, this could have an impact on the performance of your host depending on your network and CPU configuration, so it's wise to try to migrate 100 VMs of substantial size at the same time. You can tweak the number of migrations that you can do simultaneously by opening Hyper-V Manager and clicking the Hyper-V Settings link from the Actions pane. Once there, click the Live Migrations option, check the "Enable incoming and outgoing live migration," and then input the number you want to migrate at any given time. Figure 27.5 shows these options.

Microsoft didn't stop there, though, and with Hyper-V 2012 R2, they've introduced (and enabled by default) live migration compression. When you migrate your VMs with compression, you'll get at least twice the speed of migration that you had with earlier versions of Hyper-V. You can leverage live migration compression even if you have the budget for some high-end networking and use the new live migration over SMB function. Essentially, with this you can either SMB Multichannel—where multiple NICs are automatically used to get more overall bandwidth—or SMB Direct—where you have purchased 10 Gbps RDMA NICs and DCB-capable switches for your live migration networks. With SMB Direct, you can reduce the time to migrate a VM from minutes to literally seconds! If you want to configure Live Migration over SMB, then open Hyper-V Manager, click the Hyper-V Settings link, expand the Live Migrations option, and choose the Advanced Features option. # Online Checkpoint Merging

What you knew as snapshots in Hyper-V 2008 R2 are now called checkpoints in Windows Server 2012 (RTM) onward, and they allow you to take a point-in-time checkpoint of your VM while it's running. Hyper-V 2008 created a new differing disk (.avhd) that was linked to the original VHD but was a completely separate file. This was a useful feature, for example, when you wanted to apply a new service package or hotfix to a server and ensure you could quickly roll back to its original state if things went wrong.

The negatives outweighed the benefits, though, and before Windows Server 2012, if you wanted to delete point-in-time checkpoint, you had to shut down the VM and merge the AVHD file back into the parent VHD. This could take a considerable amount of time to complete if the AVHD was large—all down with the VM. You can now perform checkpoint merging with Windows Server 2012 R2, so if you need checkpoints for your VMs, you can safely merge them without any downtime. There will be a small performance overhead on the VM while the checkpoint is being merged, so be aware that this will have an effect on your production systems and must be carried out after business hours.

# Windows Server Gateway

Windows Server Gateway (WSG) is a new addition in Windows Server 2012. It operates as a virtual software router that enables datacenter and cloud service providers to route traffic between their physical and virtual networks as well as the Internet. It integrates into Hyper-V and utilizes the Network Virtual Encapsulation (NVE) standard that allows true datacenter space isolation for multi-tenant environments. Deep into this technology is out of scope for this book, but you can find more information here: http://microsoft.com/en-us/library/dd31301.aspx

# Automatic Machine Activation

With Windows Server 2012 R2 Datacenter edition, you have unlimited virtualization rights for Hyper-V hosts. This means you can run any VMs as you like on each host without the hassle of having to activate the key on each one. Although activating a lot of VMs can get repetitive task, now you have the capability with Automatic Machine Activation (AVMA) to configure the Hyper-V host to automatically activate guest VMs that are running on it. All you need to do to use this feature is to first deploy a guest VM with Windows Server 2012 R2 Datacenter, Standard, or Essentials (any operating system below 2012 won't work with AVMA) and then install the AVMA key inside the guest VM using the following command:

```
slmgr /ipk <AVMA_key>
```

Once you run this command (substituting the <AVMA_key> with the key you get with your Windows Server 2012 R2 Datacenter), the guest VM automatically activates itself.

# Understanding the Hyper-V Architecture

By this time, you should have a feeling for the basic functionality of Hyper-V. You've learned what server virtualization is for and also what's required from a hardware and software perspective to get it up and running. However, to understand what's going on and to troubleshoot problems, you need a deeper understanding of how Hyper-V was designed. In this section, you will learn more about the software architecture of Hyper-V.

CPU capabilities play an essential role in the implementation of server virtualization. The Intel/AMD model for processors has a number of privilege levels, known as rings. In the traditional model, ring 0 has the highest privilege. The Windows kernel and device drivers use this level. Ring 0 allows access to any hardware and system. Ring 1 and 2 are not normally used in current versions of Windows. Ring 3 has the lowest privilege level. It runs normal “user” programs. In practice, this should mean any code that does not require kernel privileges. The trick here is that the CPU forbids any code running in a higher ring to write data or code belonging to a lower ring. In other words, it's a hardware security feature.

When you deploy the Hyper-V role to your computer, you're creating a hypervisor architecture. A hypervisor is a software layer between the hardware and the operating systems running on the host. This is known as the bare-metal approach: virtualization at the lowest level. The main purpose of the hypervisor is to create isolated execution environments
