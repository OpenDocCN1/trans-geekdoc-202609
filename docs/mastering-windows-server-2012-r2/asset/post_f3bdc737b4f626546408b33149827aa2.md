## Forest Functional Levels

When you upgrade DCs in an existing forest or if you create a new forest, 2012 ensures for safety that not all DCs and domains are entirely 2012 based, and so will not stretch your strings to use all the new capabilities that 2012 offers all the domains in the forest are operating at domain functional level of 2012. Unless you are creating a new-forest using Windows Server 2012 R2 organizations will need to go through an upgrade process from 2008 to 2012 R2. After that process, you will need to raise the forest's functional level.

You raise a forest functional level with Active Domains and Trusts (Server Manager ▷ Active Domains and Trusts). Right-click the icon in the left labeled Active Directory Domains and Trusts, and you will see the dialog box in Figure 24.9. Notice that you don't right-click the domain icon. If you right-click the domain icon, you'll see the Raise Forest Level option.

In Figure 24.9, this example, the forest functional level is as high as it can just go with the domain functional level. In addition, you can't lower the functional level.

The nice thing is you can have domains running at a lower operating system functional level in a forest that is operating on a higher operating system functional level. It's uncommon to see a Windows Server 2008 domain in a Windows Server 2012 R2 forest. They work together and on different levels to leave room for migrations and interoperability between operating systems. As long as the functional level is Windows Server 2003 or higher, the domain can be part of a Windows Server 2012 R2 forest.

You can't get the Windows Server 2012 R2 functional level unless every DC in every single domain is running Windows 2012 R2 or higher. But think about that doesn't mean that all your domains will be in 2012 R2 functional level before Domains and Trusts lets you restore the functional level? No, as it turns out:

- 1. When you open the dialog box shown in Figure 24.9, the message can vary depending on the current state of your environment. Since you built this test for Windows Server 2012 R2 notice that the message displayed is operating at the highest possible functional level. If you were to try and raise the functional level to Windows Server 2012 R2 while still running DCs on Windows Server 2008, you'll get a message that says, "You can't go to 2012 R2 level," and tells you exactly which DCs must be upgraded before you can go to 2012 R2 functional level.

- 2. When you right-click AD Domains and Trusts, the forest does a census of its list of DCs.

- If they are all 2012-based DCs, then you get the option to raise the functional level.
- If not, you get the option to which ones will be upgraded.

So, what do you get from this functional level? You get several items that we've discussed elsewhere but we summarize here:

**Windows Server 2003 Functional Level** This contains the following:

**Transitive Forest** One trusts every domain in each of two trusts each other—but only if both are in 2003 functional level.

**More Flexible Group Membership Replication** Server 2000's old problem of “if you change a group's membership and I change that same time, one of them will be lost” goes away in a 2003-level forest.

**Better Internet Routing** Server 2003 saw a massive rewrite of the code that handles site-to- replication, with the result that whereas 2000-based forests would fall apart about 200 sites, 2003-based forests could handle up to 5,000 sites.

**GC Fixes** Any change to the global catalog, as that the type that happens when you install an AD-application,, causes GCs on a 2000-level forest to completely panic; they dump their entire databases and rebuild from scratch, causing massive replication loads over the network. Server 2003-level forests are much smarter, because their GCs focus only on the changes to the database, rather restarting from square one.

**Schema Redef** AS somewhat inflexible schema loosens a bit on a 2003-level forest. You still can't delete or undo schema changes, but the schema manages itself to ensure that you'll never have one AD-aware app accidentally on another AD-aware app's schema changes.

## Windows Server 2012 Functional Level

### Windows Server 2012 Functional Level

These levels include all the features from previous functional levels.

In general, Active Directory tries to carry this notion of decentralized control throughout its structure. In general, all DCs are equal, but to paraphrase George Orwell, some DCs are more than others. These DCs are the ones that serve in five roles called either Operations Master or Flexible Master of Operations; they gets shortened to the acronym FSMO and is known as "fizz-mo". Strictly speaking, FSMOS was the phrase that Microsoft used through most of Windows 2000's development process, and it renamed FSMOS to Operations Masters in the beta process. As a result, you'll hear some people say Operations Master, the FSMOS has such name with many, even now in the days of Windows Server 2012 R2 probably because it's quicker to say "fizz-mo" (and fun). So, for example, the phrases Domain-Naming Operations Master and Domain-Naming FSMOS refer to the same thing.

## FSMOS and GCs

Making AD run also requires knowing about the following:

- **Operations Masters and Global Catalogs** These are particular functions that DCs must assume. Placement of these roles needs to be considered.
- **Time Synchronization** Believe it or not, AD will not run unless the AD masters all agree on what time it is within five minutes. This is controlled by one of the operations masters, the PDC emulator of the forest domain.

## Multimaster vs. Single-Master Replication

As we've mentioned, one of the things that differentiates AD domains and DCs from NT 4 and earlier domains is multimaster replication rather than single-master replication. Any DC can accept changes to the user account, so a local admin could start an administration tool through Active Directory Users and Computers and make a change to a user's account on an available domain controller. Any DC can accept changes, any DC is a "master", which is why it's called multimaster.
