# Upgrading Your Active Directory

Active Directory Server 2012 has arrived and you are anxious to get your current infrastructure up to the latest release because you want to stay with your infrastructure.
Before, we assumed there was no existing network and we were going to build a new network from scratch. This is not the case in many systems. Active Directory has been around for over a decade and many companies have some version of Active Directory. This section title says, we are going to focus on upgrading your domain to Windows Server Active Directory 2012. But before we dive into this, you need to understand the path we are going to take and what the prerequisites might be.

> ARE YOUR SERVERS READY? NT SERVERS ARE NOT INVITED TO THIS PARTY!

There is no way for a Windows NT 4.0 domain controller to live near a Windows Server 2012 domain controller. Since Windows Server 2008 R2, there is no longer any support for NT 4.0 domain trusts, and you can't install a Windows NT 4.0 into a Windows Server 2012 domain. Besides that, Microsoft's support for Windows NT 4.0 ended years ago. Therefore, Windows NT 4.0 is probably the only unsupported system on your platform.

# Upgrade the Schema to Windows Server 2012

In earlier versions of Windows Server, if you planned to upgrade your domain, you had to run a tool called adprep.exe. This tool would prepare and extend your forest schema to support new features, and it would also prepare your domain to create new groups and containers as needed. Additional options like /adprep would prepare the domain to set the Group Policy Objects for replicating to the Windows Server domain controller and /rodcprep would also add support for the Read-only Domain Controller accounts.
We have good news and even better news. In Windows Server 2012 the \support\adprep directory on your Windows Server 2012 sources exists. But there is no 32-bit version of adprep.exe, only the 64-bit version, which you can run on a 64-bit Windows Server
