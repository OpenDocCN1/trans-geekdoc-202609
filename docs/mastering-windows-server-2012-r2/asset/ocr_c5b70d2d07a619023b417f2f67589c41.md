# MANAGING PERMISSIONS

what might have been one entry in the previous screen can become two or more detailed entries, allowing you to see exactly which rights are inherited and from or whether the entries were specially created for this resource hand. For example, notice that the Users group has two entries, both of which are inherited by the volume. You can also see where the permissions flow down by looking at the "Applies to" column. Of course, all these details are great for troubleshooting you finally have all the information in one place (well, almost).

You have the ability to tailor your permissions to the atomic level by choosing an entry and clicking the Edit button. With so many permissions coming from so many different places (and aren't even considering sharing permissions here!), this process can easily become messy to troubleshoot. Try to simplify your resources and users as much as possible, by volume, by group, and by which life will be a lot simpler when dealing with permissions.

To see what rights Users group has you can make sure it has the correct access to the APPS folder, follow these steps:

+   1. Select the entry with Read & Execute permissions.

+   2. Then click the View button on the Advanced Security Settings page.

+   3. Next, click "Advanced permissions," and notice how the options are grayed out here.

If you repeat the same steps on the Database Managers group, why is the View button now an Edit button? Why are the permissions not grayed for Database Managers? The reason is inheritance is applied to the Users group and not the Database Managers group. If you wanted to edit these Users group here, you would have to break inheritance and re-add the group.
