For example, the high-level permission List Folder Contents comprises five lower-level permissions: Traverse Folder/Execute File, List Folder/Read Data, Read Attributes, Extended Attributes, and Read Permissions. You may want to think of them as “molecular” and “atomic” permissions. There are 13 atomic permissions for NTFS. ## ATOMIC PERMISSIONS

We'll start at the atomic level. These permissions are the building blocks of the permissions that we normally speak of, such as Read, Modify, and Full Control. You will probably never see these permissions, much less refer to on their own.

**Traverse Folder/Execute File** The Traverse permission lets you pass by all the locks on the upper levels and essentially "become yourself" right into level 4. Like Execute, it's a useful permission, but it has nothing to do with files. What's happening here is when NTFS is examining a permission, it goes up to level 3. When looking at the first one, it asks itself the question, "is this a file or a folder?” If it's a file, then it interprets that first bit as the Execute File permission. You'll see this in some less-extreme manner on some of the other permissions as well.

**List Folder/Read Data** List Folder permissions allow you to view file and folder names within a folder. Read permissions allow you to view the contents of a file. This atomic right is the core component of Read.

Think of the separation between these two atomic permissions. Is there really much of a difference? Yes, but probably not for long. Remember the days when we called everything files and directories. Now the file and folder terminology has become mainstream. Just when we start getting used to it, another term is coming into play: objects. Everything on your machine is an object—both files and folders. This atomic permission could be rephrased as read object. Regardless of whether this permission applies to a file or folder, this right lets you examine the contents of an object.

**Read Attributes** Basic attributes are file properties such as Read-Only, Hidden, System, and Archive. The atomic-level permission allows you to see these attributes.

**Read Extended Attributes** Certain programs include other attributes for their file types. For example, if you have Microsoft Word installed on your system and you view the file attributes of a DOC file, all sorts of attributes will show up, as Author, Subject, Title, and so on. These are called extended attributes, and they vary from program to program. This atomic permission lets you to view these attributes.

**Create Files/Write Data** The Create Files permission allows you to put new files into a folder. Write allows you to overwrite existing data within a file. This atomic permission will not allow you to add data to an existing file.

**Create Folders/Append Data** Create Folders allows you to create folders within folders. Append allows you to add data to the end of an existing file but not change data within the file.

**Write Attributes** This permission allows you to change the basic attributes of a file.

**Write Extended Attributes** This permission allows you to change the extended attributes of a file.

**Delete Subfolders and Files** This atomic permission is strange. To delete with this: even if you don't have Delete permissions on a subfolder or file. Now could this be possibly? If you were to read ahead to the subfolder, you could delete it. But you need the permission on the parent folder. This is a common point of confusion in NTFS internals.

**Read Permissions** This permission allows you to see the permissions assigned to a file or folder.

**Change Ownership** This permission allows you to change the owner of a file or folder.

**Take Ownership** This permission allows you to take ownership of a file or folder, even if you don't have permissions to access it.
