The previous NewADUser command creates the new user, PWitschi, in the default location for new users, usually the Users container. As we stated earlier, that's not the best place for storing user accounts. It contains a number of special users and groups, so you should treat it as specified. You have a location in \BigFirm\ your user accounts. Say you want to specify a number of configurations for this user. This is what you can:

```
PS C:\Users> New-ADUser "Philipp Witschi" -SamAccountName
PWitschi" -GivenName "Philipp" -Surname "Witschi" -DisplayName "Philipp
Witschi"
-Path "OU=Users,DC=BigFirm,DC=com" -UserPrincipalName
PWitschi@bigfirm.com
```

Let's look at the flags:

+   -SamAccountName is the user logon name (pre-Windows 2000) in the user object properties. In this case, you entered PWitschi, so the user will be able to log in using the domain name BigFirm\PWitschi.

+   -GivenName refers to the first name of the user.

+   -Surname is the last name of the user.

+   -DisplayName is the display name of the user object.

+   -Path refers to the distinguished name of the OU where you want to create the new user object. In this case, it will be the \BigFirm\Users OU in the bigfirm.com domain.

+   -UserPrincipalName the UPN is the user logon name in the user object, that is, the one that takes an email-like form.

If you run this command, you'll find the new user is created in the OU that you have specified. You'll also find that the user is disabled. PowerShell wants to specify that the user should be enabled.

Why would you want to create a user? You might want to run a bulk job to create a lot of user accounts. You won't enable the user accounts until the associated people are ready to use them. At that point, you can set a unique password to the user and then enable the account. PowerShell is flexible.
