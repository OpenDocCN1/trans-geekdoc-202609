# CHAPTER 24 CREATING LARGER ACTIVE DIRECTORY ENVIRONMENTS: BEYOND ONE DOMAIN

The PDC emulators must agree on the time, so they choose one of their numbers to be “source”—the PDC emulator for the first domain in the forest, the forest root. So, again, it’s the PDC Emulator FSMO for the forest root domain that is the ultimate authority.

But who syncs that top dog, don't need to sync the FSMO. All that matters in AD is that all the servers think it's the same time. So, it'd be nice if it was the actual time, but that's not necessary. If your whole enterprise was 10 minutes early, that would constitute no problem for AD, as all the servers are 10 minutes early.

# TIME ZONES AND SYNC

But it's very important that you set the time correctly on all your systems! AD stores and sync time in “universal”, so in its heart of AD is always running Greenwich, England, time. Windows operating systems use the time zone to understand the clock's time and display that to you'll understand. So, if you leave everyone's time zone set to Pacific and just set the sync clocks to the local time, each of those systems would think that the time in universal time was hours different, and synchronization would fail. A situation will drive you crazy, because you'll be looking at a DC and a workstation whose time looks identical—but unknown to you, their time zones are set differently—so, it's a mystery why they won't talk to one another. It wouldn't be if you could see theirs about what the universal time was! You can quickly change a system's time zone by opening a command prompt and typing: w32tm /tz.

But as long as we have this hierarchy, let's do it right and sync that root PDC somewhere. You could purchase a Network Time Protocol appliance that syncs its time with the Global Positioning System (GPS). Or you could buy a back to or just let the Internet sync your time.

The suite of Internet standards allows sharing of time information called the Simple Network Time Protocol (SNTP); see RFC 1269 at https://www.iet.org/rfc/rfc1269.html. Many, many machines on the Internet as NTP servers will provide up-to-date time to any machine running an NTP client. Windows Servers includes an NTP client—in fact, it is the protocol that AD uses to synchronize its members systems. You can tell a Windows Server 2012 R2 machine synchronize its clock from a given Internet server with the w32tm command:

```
w32tm /config:computer:bf1 /update /manualpeerlist:time.windows.com /syncflags:manual /reliable:yes
```

+   /computer The name of the computer. In this case, we would use the name of the forest root PDC emulator.

+   /Reliable Yes, it is a reliable source for other computers.
