# PLANNING FOR SCHEMA CHANGES...AND CONFLICTS

Before leaving the subject of the schema, we will offer a thought about how it will affect your organization. There are very few AD-aware applications. But now let's consider what happens if conflicts arise within the schema. Let's imagine that you are at a university with a lot of independent departments. The university's forest has many domains—Chemistry, English, Microbiology, Astronomy, Music, and Geology—that all live in a single forest and therefore have only one schema. Now imagine that Astronomy just wants to get a new application that will aid its professors in researching, and so they put it in AD. It adds a few things to the schema, including a Magnitude field, which stores a star brightness. When suppose Geology needs to use new application that will help them in seismology research, which also adds a few things to the schema—such as a Magnitude field, where they'd store information on earthquake power. What happens when Geology tries to install an application that wants to create a schema field name already exists? Well, to make a long story, it depends...and not all conflicts are possible.

Our point is this: Geology did not know when it installed its app it would conflict with an existing one. But could Geology have known? Well—and here's the part you won't like—every forest should consider having a test lab and running all the time, with a DC or two that are running but independent of your forest. Prior to rolling out any server-based apps, you should test them on the test lab to see whether they create changes that will make AD beyesha.

What's that say? Astronomy and Geology are used to running independently, not having to ask each other permission to run applications? Yes, we can believe—research and educational institutions have that freedom. But once you decide to stick your organization into a single forest, then your organizational components must communicate a bit more to keep things working. And somebody is going to have to test lab and running all the time, which means staff it and finding space, machines, and software for it. Well, that argument about how Windows lowers total cost of ownership doesn't seem quite compelling when Windows Server 2012 R2 offers Hyper-V. This test gives you a reason to buy it and play around with it.

Basically, in this case, AD is just another piece of software that says, "If you want to use me, you'll have to modify the way that you do, "business," and that seems fairly backward—sort of a mouse manufacturer saying, "Gosh, we're sorry that our revolutionary mouse design doesn't fit your hand. Have you perhaps considered surgery?”
