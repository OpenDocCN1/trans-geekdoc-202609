# Connecting to NFS from the Client Side

In our lab we have Linux Mint deployed, we are able to connect to the share, but we get various errors when we try to browse the share or create a directory. Linux Mint, along with many other distributions, requires you to install the nfs-common package before you can read from an NFS share. Follow these steps to install the package:

+   1. From a terminal window type:

```
sudo apt-get install nfs-common

This will install the necessary items to allow you to browse the share.

Now you can mount the share that you previously created on your test Windows server.
```

+   2. Again from a terminal window type:

```
sudo mount -t nfs 192.168.0.1:/Shares /mnt/share

There is no output; however, you have to browse the directory or mount point (/mnt/share) you specified. Here's an explanation of the syntax:
udo Super (Privileged execution for performing certain tasks)

Mount used to mount varieties of file systems

- t nfs The nfs file system

192.168.0.1:/Shares The remote share you are mounting

/mnt/share The local mount point
```

+   3. Next, browse to the share by typing the following:

```
cd /mnt/share
```

+   4. Now type the following command to list the directory contents:

```
ls

Windows Server you have created a file Readme.txt. You should be able to see this file after you issue the 'ls' command. The Readme.txt file is just an example, try placing some of your own files on the windows server and retry the 'ls' command on the Linux client.
```

# Deduplication: Disk and Network

Windows Server 2012 introduces Data Deduplication as a native storage feature. Data Deduplication is a more efficient way of storing data. With the ever-increasing need for storage in cloud technologies, you can imagine the amount of duplicate files that are stored. Even I have several copies of ISO files or virtual hard disks for USB storage and servers. These files are 3-7 GB each. I'm losing a lot of space by keeping multiple copies and not coming up with a proper library system.

This is a simple example but it brings up another point: files have all same parts and they all take up space. Wouldn't it be cool if you could identify those common pieces, create a single master reference on disk, and then point to it for every other file that has that common? You have this ability in Data Deduplication.
