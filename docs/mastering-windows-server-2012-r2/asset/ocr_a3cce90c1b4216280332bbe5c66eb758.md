Notice that the processing order of this starts with a default of 999999, which is the highest possible number that can be assigned. Although you can assign the processing order directly, you can modify the order, as which policy is processed first, second, and so on.

Policies have four important elements: permissions, constraints, and settings. For a big-picture perspective, here's an overview. In the following pages, we will cover each of these elements in much more detail.

Conditions Each policy must have one or more constraints that must be met for the client to use the policy. If the condition is not met, the policy will not be used. Many conditions can be specified, as being a member of a Windows group or connecting at a certain time of day or week.

If a user meets the condition of a policy, the policy will be used even if the policy prevents a user from accessing the VPN server. No other policies will be used. For example, a VPN server that has five policies. If a user meets the condition of the first policy and access is denied from policy, the other four policies will not be checked.

Permissions Permissions help determine whether a user is granted access or it's denied that they use this policy (by meeting the conditions of the policy). On the surface, permissions sound like they can be Grant Access or Deny Access. However, individual user account settings can override the permission of the policy, and the policy can be set to override the user account setting. As you dig in, you realize it isn' as simple as just Grant or Deny Access.

Constraints Constraints can ensure that clients follow some specific rules for the connection. Constraints include authentication methods, time-outs for the session or idle time, and more. If a user meets the condition and is allowed permission but doesn't meet one of the constraints, the connection will be refused.

Settings Settings are applied if the policy meets the conditions and constraints of a policy. Settings include multilink and bandwidth-allocation options, encryption choices, IP settings, and IP filters.

# POLICY CONDITIONS AND POLICY ORDER

The conditions are very important to set and understand for policies. Consider these basic rules that govern policies:

+   * A user must meet all the conditions of a policy to use a policy.
* A user will use only the first policy where all the conditions are met.
* If a user is denied access from a policy where conditions are met, additional policies are not evaluated.
* If a user doesn't meet the conditions of any policy, conditions cannot be met, and access cannot be granted.
* If there are no policies, conditions cannot be met, and access cannot be granted.
