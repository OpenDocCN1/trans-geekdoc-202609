## BEFORE STARTING ADMT

As previously mentioned, C&P stands for clean and pristine. That means you leave all the old stuff behind and move into a new forest or domain. From our experience, although you leave all the unwanted objects behind you you can reduce your stress factor if you start to clean up your old environment before migration. Clean up your old house even though you're moving into a new home?

Yes, right in terms of your domain migration, we recommend doing a few cleanup steps in your source domain.

First, check to see if you have some old SID history on your accounts. If you are going to migrate your accounts, groups, and computers, you don't want to have old SID on your accounts.

Next, make sure all groups, users and computers you are going to migrate are all objects you really need. Don't migrate old, orphaned groups, users and computers; it doesn't make sense. Therefore, you need to delete all your unused objects before migration.

After you've cleaned up your environment, check the group nesting. Make sure that all your group nesting matches the AG(U)DLP filter. AG(U)DLP means an account is nested into a global group, the group is a member of a universal group (if required), and the universal or global group is a member of a domain local group. This domain local group has been assigned permission on the resources.

These are probably the most important migration steps you need to take, and they will help you to succeed and migrate only those objects you really want.

## Creating a Password Key on the Target

Now, you want your users' passwords to move over with their accounts and ADMT can do with the help of the Password Encryption Service (PES). Before it will migrate passwords, ADMT requires you to create a password encryption key for ADMT01 and then copy that over to DC2003, and DC2003 will use it to be able to send passwords over the wire—encrypted.

To do this, you run ADMT from the command line. The following is an example of the command syntax:

```
admt key /option:create /sourcedomain:otherdomain
/keyfile:c:\temp\password.pes /keypassword:Password
```

This says to prepare a key for OtherDomain.local use to transfer passwords to Bigform (Bigform is not explicitly mentioned because you're working on a Bigform DC). The C:\temp\password.pes file is just where to put the file. If your server has a floppy drive, then A:\ works fine. It doesn't matter where you put it—just understand that you'll have to somewhere transport that file to the OtherDomain.local, DC2003. When it runs properly, ADMT will return a message looking something like this:

The password server encryption key for domain 'otherdomain' was
successfully created and saved to 'c:\temp\password.pes'

You're finished on ADMT01.Bigform.com for the moment. It's time to move to the DC2003.

## Moving Over the PES File

Once you're logged in at DC2003, you need to get that PES file from ADMT01.bigform.com to a local drive; we usually just create a share and copy it across the network. You can alternatively put it on a floppy, a CD-ROM, or whatever you want—but it has to get over to DC2003 one way or another.
