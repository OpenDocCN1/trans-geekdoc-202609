# gpresult

gpresult.exe is a Group Policy troubleshooting and reporting tool that collects the RSOP arsenal by adding command-line batch capabilities. When run without arguments or options, gpresult will generate the following RSOP information for the current user at the local machine:

- The DC that the workstation gets the policies from
- When the policies applied
- Which policies applied
- Which policies were not applied because of filtering
- Group memberships
- User rights information (if used in verbose mode)

# TROUBLESHOOTING GROUP POLICIES

To generate RSOP information for a remote machine, use the /S systemname and /USER arguments. For instance, get RSOP information on the workstation WINDOWSCLIENT1 for the user dmelber, type gpresult /S WINDOWSCLIENT1 /USER dmelber.

You can get more detailed information with options:

- /V says to give more verbose information: gpresult /V.
- /Z says to give even more information; it is the "Z-per-verbose" option: gpresult /Z.
- If you know you're zeroing in a just machine policy, add /SCOPE MACHINE; if you're interested only in user policies, add /SCOPE USER.

So, for example, get the maximum information about the user policies applied to this system, gpresult /S /SCOPE USER. it is also a simple matter to generate a report by redirecting the output of a command to a text file:

```
gpresult /S WINDOWSCLIENT1 /USER dmelber /Z > c:\gpinfo.txt
```

# Using Event Viewer

You can stop shocking now! We're serious! There are times that you need to read Microsoft Group Policy on the back, and now, to the shock of many, the Event Viewer has been completely overhauled, and now, to an entire node dedicated to Group Policy! The Group Policy Operational log is a replacement for the Userenv.log file that was generated by Group Policy in the past. Now, you don't need to set up any verbose or auditing settings; it just happens. To view the Group Policy logs in the new Event Viewer, launch Event Viewer. Once Event Viewer is open, expand the Applications and Services Logs\Microsoft\Windows\ GroupPolicy node. here you will find the Operational log for Group Policy. After clicking the Operational log, you will see the list of events on the right pane. Here are the new environment:

- The Operational log replaces the Userenv.log from previous versions of Windows Group Policy.
- The General and Details tabs provide excellent information for troubleshooting issues.
- Double-clicking the event will launch the event in its own window, allowing a single view of the information.
- Clicking the System + on the Details tab will expose more information about the event.

# Troubleshooting 101: Keep It Simple

We predict that, with the RSOP tool, working with group policies will not be a walk in the park for most. Here are a few suggestions to help minimize troubleshooting time:

- Keep your policy strategy simple. Locate users and computers in OUs if possible, and apply policies at the highest possible level.
- Avoid having multiple GPOs with conflicting policies that apply to the same.
- Minimize the use of Enforce and Block Inheritance settings.

Document your Group Policy strategy. You may want to visually depict your structure and put it on the wall, like your network topology. Test those GPO settings before deployment! This is absolutely essential to conserve your help-desk resources and ensure that applications and services continue to run.

# Active Directory Delegation

Active Directory Delegation is a powerful solution to the old-world style of legacy Windows domains, where you can create multiple domains to separate control over users, groups, and computers. By implementing delegation within a single Active Directory domain, you don't need multiple domains, you can save money by reducing the number of domain controllers, and so.

This feature of Active Directory is so compelling that many companies and enterprises have moved to Active Directory to take full advantage of the benefits that Active Directory provides. One of the most compelling benefits of using delegation is the ability to grant one or more groups the privilege to reset passwords for users. This means you can allow a group of users to reset passwords for a subset of the users. For example, you can allow the HR manager to reset passwords for all the employees in the HR department—no more privilege, less privilege.

# Delegating Group Policy Administration

The ability to delegate creation and configuration of GPOs and their settings to administrative personnel (or others, for matter) is extremely useful, especially in a large organization. In this section, we will explain how to allow persons who are not members of Domain Admins or Enterprise Admins to create and manage GPOs for designated sites, domains, or organizational units.

The GPMC provides a simple distributed array of options to ensure that you are providing the correct delegation to the correct set of administrators. There are five primary delegations that you will want to configure:

- Creating GPOs
- Linking GPOs
- Managing GPOs
- Reading GPOs
