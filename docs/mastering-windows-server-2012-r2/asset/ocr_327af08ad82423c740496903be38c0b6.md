Just remember, though that you have now effectively cloned the old VM. If the old one is still running on another host and you bring this newly imported online, you'll have two identical machines on the network, which will certainly cause you problems!

You may be interested in how Hyper-V keeps track of VM configuration. When you create a VM, you tell it where to put the top-level folder containing the VM configuration. Figure 28.8 shows the configuration of VM on Hyper-V host VMHOSTI-RV.

# Figure 28.8
VM configuration files

![](bbox=[0.295, 0.356, 0.858, 0.623])

The screenshot shows three folders: Snapshots, Virtual Hard Disks, and Virtual Machines. Each has two virtual machines registered here its GUID, which is the real name of the virtual machine. For instance, the folder name 1A105D96-AFCB corresponds to WS2012R2-SRV1. This folder contains the current memory state if you save its state. Each VM also has an XML document, named after the GUID of the VM. This document is fully readable, although you should not edit it manually. If you look through it you will find the entire configuration of the VM. As an illustration, the XML file has all the virtual switches the VM is connected to listed by the GUID of the virtual switch, not by the friendly name.

The Snapshot (this is a the old term used for a checkpoint) folder subfolders, containing state information of each checkpoint: the current configuration of the processes and virtual hardware in a .vsv file and all virtual memory in a .bin file. The difference files of the checkpoints are saved as .avhdx in the Virtual Hard Disk folder.
