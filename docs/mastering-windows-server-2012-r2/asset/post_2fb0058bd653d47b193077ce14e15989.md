## Backing Up to the Cloud

A complementary disaster recovery solution to DPM for your Windows Server 2012 R2 backups is Windows Azure Backup. This add-on provides a route into Microsoft's Azure cloud offering and enables you to back up and restore files, folders, and virtual machines located on Windows Server 2012 R2 computers. It can be used side-by-side with Windows Server Backup or integrated into DPM, and once be launched from inside the same management snap-ins.

You do, of course, need a decent Internet connection—if you're still accessing the Web on a 1 MB DSL line, then forget about cloud backup! Also, you will need to create an Azure online account ID. ## Stopping and Restarting Active Directory

Restartable Active Directory Domain Services (AD DS), introduced in Windows Server 2008, lets you stop AD to perform maintenance on the server without requiring you to restart the server in Active Directory Restore Mode (ADRM). The benefits of being able to stop and restart AD include offline defragmentation and the application of server updates without requiring a restart of the computer. However, performing a system state recovery is not supported without restarting the computer in ADRM.

Once you stop AD on the server, users can continue to log on to the domain other if your domain controllers are controllable. In addition, you will be able to perform tasks on the server if there is another domain administrator controller available to process your login. If you have stopped AD on the domain controller, you must modify the FDSAdminLoginBehavior value to either 1 (the Directory Services Restore Mode administrator account can log on) or 2 (the Directory Services Restore Mode administrator account can always log on to the server). To allow the Directory Services Restore Mode (ADSR) administrator account to log on to the server, whether AD DS is stopped or not, is not a good idea since the credentials are not checked against any password policy. The registry value is located here:

```
HKLM\System\CurrentSet\Control\Lsa\FDSAdminLoginBehavior
```

## Stopping and Restarting AD DS

AD DS is caused exactly the same way as you stop any service in Windows, by using the Services snap-in in Server Manager ➢ Tools or from command line.
You must be a member of the Domain Administrators group to perform these steps:

- Open the Server Manager ➢ Tools menu choose Services.
- Right-click Active Directory Domain Services in the details pane, and click Stop on the context menu.

You will be prompted to approve a list of other services on which AD DS depends.

- Accept the list, and those services will also be stopped.

They will be restarted when you stop AD DS again.

- To start AD DS, right-click Active Directory Domain Services, and then click Start.

## Defragmenting Active Directory Offline

In earlier versions of Windows Server, you had to restart a domain controller in DRMM to perform an offline defragmentation and integrity check of the AD database. Although having to perform an AD defragmentation isn't all common, in certain cases it is useful when you're looking to clean up the AD database file and reclaim disk space on your system drive as well as potentially helping with AD performance in larger environments. Windows Server 2012 R2 gives you the ability to perform these tasks without having to restart the computer and enter DRMM. Instead, you can use dutil.exe from an elevated command prompt to Perform the offline defragmentation and integrity check.

## STOPPING AND RESTARTING ACTIVE DIRECTORY

Before performing an offline defragmentation, it would be wise to back up the system state and critical data of the domain controller to ensure you can recover from any errors that might occur. You should verify that there is ample free space on the volume that contains the AD database (Ndsdit) for temporary space. Microsoft recommends free space up to at least 15 percent of the Ndsdit file size for temporary space needs.

Active Directory performs offline defragmentation to optimize the storage of data within the Ndsdit file of the daily garbage-collection process. This does help optimize the database, but it does nothing to reduce the size of the database file. Offline defragmentation is the only effective way to reduce the size of the database.

## PERFORMING OF OFFLINE DEFRAGMENTATION OF NTDS.DIT

These steps assume you have stopped the Active Directory Domain Services, as discussed earlier, and you are compacting the Ndsdit file to a local folder. If you plan to defagment and compact the database to a shared folder, map a drive to that shared folder before you begin these steps:

- 1. Open an elevated command prompt.
- 2. Type ndsutil and press Enter.
- 3. Activate instance NTDS, and press Enter.
- 4. At the resulting ndsutil prompt, type Files (case sensitive), and then press Enter.
- 5. At the file maintenance prompt, type compact followed by the destination, for example, c:\Windows\NTDS
- 6. Type quit and press Enter.
- 7. Type quit and exit file maintenance mode, and then type quit and press Enter to exit Ndsutil.exe.
- 8. After you have completed these steps, restart AD DS.

## Checking the Integrity of an Active Directory

Active Directory uses the same indexed access manager (ISAM) database engine that is used in Exchange Server, and the version used in Windows Server 2012 is called the Extensible Storage Engine (ESE).

There might be times when you need to check the integrity of your AD database—may rule out corruption issues and also to generate reports on the number of deleted or phantom records. You can check the integrity of the Nt.dit file in two ways: first uses the Files subcommand of Ndsutil.exe, and the second uses the Semantic database analysis subcommand of Ndsutil.exe. Even though Microsoft warns against using Semantic database analysis, each time you use the integrity and recover subcommands under Files, it will prompt you to run Semantic database analysis.

## PERFORMING AN INTEGRITY CHECK OF NTDS.DIT

Using the Files subcommand of Ntutil.exe lets you verify the integrity of the database file and repair any corruption that is found. You should always use the recover command before performing an integrity. The recover command flushes all transactions to the database, ensuring that the file is the most-to-date information. Use the Esent exe to perform a soft recovery of the NTds.dit database.

## USING SEMANTIC DATABASE ANALYSIS

The Files subcommand of Ntutil.exe checks the NTds.dit file for normal file corruption, using the Semantic database analysis subcommand checks the internal structure of Ntds. dit to ensure it complies with the normal semantics of Active Directory and outputs a report of the number of records created in the database, including deleted and phantom records. The report is named dsdit.bmp.x, where x is a number that is incremented each time you run the report.
