The combined effects of the folder and share permissions are as follows:

+   - Users will be able to pass through the HomeS share to folders beneath it, as they have cannot create anything here. This is thanks to the NTFS permissions in the folder.
- The user will be able to modify the contents of anything within HomeS as long as they have permission. This is required so that the user can create and modify files and folders within their home directory. As it stands, users can't do anything on HomeS, but that will change when you create your personal home directories.

Once the wizard is complete, you will need to add the new share to DFS. This can be done through the DFS administration tool or in PowerShell. Shell will be set up with the BigShares namespace with a new name of Home. This share will be available on the network as \bigfirm.com\BigSharesHome. Here's how you can add it to the DFS with PowerShell. You'll be using the new-dfnshare cmdlet

```
new-dfnshare -Path "\bigfirm.com\BigSharesHome" -TargetPath "\F2\Home$" -EnableTargetFallback -Description "Users home directory"
```

Now that the shares have been created, you should verify that the share is accessible. You can do this by browsing to the UNC path of the share within the DFS namespace. Check it with both administrator and non-administrator accounts You could use DFS to set up folder replication if you had a duplicate server in a disaster recovery (DR) site. If you do this and the DR is invoked, users can log into POC or Remote Desktop servers in the DR site, and they'll still use the same UNC paths to browse or connect to their home directories. No user objects or scripts need to be modified.
