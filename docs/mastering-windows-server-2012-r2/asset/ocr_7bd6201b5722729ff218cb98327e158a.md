# CREATING GROUPS

You may also create some groups. The most common reason to create groups is
organize users and then assign permissions to groups. Whenever possible, you could assign permissions to groups
rather than users. You may have heard before the saying "Users come and go, but groups stay forever." Well, you've maybe heard it before we made it up, but it makes sense,\sand it is a good way to remember that you always assign permissions to groups instead of users.

As an example, you could have several users in the sales department. Instead of assigning
permissions to each individual in the sales department, you could create a global security
group G_Sales. Place all the users in the sales department into this group and assigning
to the G_Sales group. If a user leaves, take him out of the G_Sales group and he
wil no longer have the permissions of group. If a user joins the sales team, put her into the
G_Sales group, and she will have the same permissions as everyone else in the group.

That sounds pretty easy, but there is more than one type of group there are several types
of each of them its own purpose. The two types of groups are distribution and security.
Distribution groups are used for email, and security groups are used to assign permissions.
Security groups can also be used for email.

There are three group scopes:

Global groups are used to organize users. This is the most commonly used group\and the one you will create in this chapter. Users will be placed in the global groups, and
permissions can be assigned to the global groups.

DL group strategy where A indicates accounts, G indicates global groups, DL indicates
domain local groups, and P indicates permissions. User accounts are placed in global groups.
