# UNDERSTANDING SERVER VIRTUALIZATION

How does this work, generally speaking? Clearly, you cannot have two operating systems accessing the same hardware at the same time. One has to be charge (that would be the host), and the other (the VM) will need to access hardware through emulation, synthetic drivers, or some other means. In principle, the same goes for the execution of CPU instructions and even memory access.

Modern virtualization systems like Hyper-V go out of their way to use system resources as efficiently as possible. They use real memory and the CPU directly executes the code of the—VM—with some exceptions that we will discuss later. The argument holds for high-performance devices such as network, disk, or video interfaces. Emulation where existing hardware behavior needs to be simulated will cost you performance. Sometimes it is unavoidable, but Hyper-V takes a different route. It uses its own driver architecture for each type of device to reduce overhead as much as possible. This design tightly integrates with the computer architecture.

# What Is Server Virtualization?

Now that you have some idea of what virtualization is, let's discuss what to use it for. Some applications are testing and development, consolidation of servers, and disaster recovery. You benefit from the high degree of flexibility that virtualization offers.

The technology took off in the beginning as a test bed for administrators and consultants in need of hardware for a quick test and who were too happy to use an existing machine with virtualized software to run a couple of VMs. Larger organizations usually have multiple testing environments for various purposes. With virtualization, you can quickly add and remove VMs as needed. When a new application comes along or a new infrastructure component needs to be integrated, a new virtual environment is all you need to deploy for the project to.

Many administrators have a couple of VMs for their own use so they can quickly test and changes before applying them in a production network. For instance, as an Active Directory specialist, you might run four or five DCs on a Windows 8.1 workstation on a normal 8-GB desktop that is running Windows Server 2012 R2 with Hyper-V. You might use this to research the fine points of Active Directory replication or the effects of a Group Policy change on the client.

Similarly, virtualization is great for giving technology demos. Because of the low-performance requirements demands, you can run multiple VMs on a powerful laptop and show how it it clearly.

Away using virtualization for testing and delivering demos, the largest deployments of server virtualization are in datacenters where numerous servers are consolidated for mainline and private cloud service. Also, huge numbers of organizations (big and small) are migrating their physical IT estates to virtual platforms to reap the cost-saving and flexibility benefits. A virtualized environment offers the following advantages:

+   Conserves Resources and Saves Costs One host running multiple saves rack space, electrical power, and cooling capacity. It would not be unreasonable to consolidate 20 or 30 lowly physical machines to one high spec'd physical host.

+   Shares Hardware A host offers the same “virtual” hardware to each VM. In other words, all VMs share common hardware. This makes them predictable and makes the maintenance of drivers easy. Deploying VMs is much easier than deploying physical machines, because drivers are no longer a factor.
