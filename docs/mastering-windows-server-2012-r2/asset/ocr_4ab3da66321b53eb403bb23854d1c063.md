# ROUND-ROBIN AND NETMASK ORDERING

On the Advanced tab in the properties of the DNS server, you will find a number of server options enabled, two of which are:

+   * "Enable round robin"

+   * "Enable netmask ordering"

**Round-robin** This is a "poor man's" network load balancing technique. If you register multiple hosts of the same name with different IP addresses, the DNS server responds sequentially with an IP address for each query, starting with the lowest IP address. Although it doesn't spread the client load evenly or smartly to the available hosts, it still provides balancing between servers.

**Netmask Ordering** Like round-robin this uses multiple hosts of the same name with a different IP address. Rather than picking randomly, the record mathematically shows up being closer is chosen. This is done through a comparison of the subunits. This is good if you have geographically separated hosts and your client needs to contact the one in its own network.

So, using servers that are geographically separated, you decide which method is best. Netmask ordering will keep the response time minimized by use of a shorter route. Round-robin will distribute the load even if the clients are in a concentrated location.

However, a twist in these processes have come about when using Windows Server 2012 R2 or Windows 7 or 8. The TCP/IP stack for IPv6 and IPv4 "when" will perform a similar process to netmask-ordering named, default address selection. Then, it receives the IP addresses from the DNS servers and decides on which one is best.

Like configurations, this can be overridden by a Group Policy object specifying the following registry:

```
Hkey_Local\System\CurrentControlSet\Services\Tcpip\Parameters\OverrideDefaultAddress
```

A value of 1 will turn off default address selection and allow a random choice of the NLB round servers.

You can see the off with this use of round robin for geographically split servers. For example, an environment with a disaster recovery site would like to offer two servers located in different ports to the same service. In this case, two FTP servers could be available to download data. DNS is rigged to provide two IP addresses for the same name, ftp.biggest.com. Round-robin will resolve the records sequentially. If one server goes down, such as in a disaster, the clients will have connectivity to ftp.biggest.com. It will occasionally keep the dead server's IP address, but reconnects are all available to keep the data flowing.

However, if netmask ordering or default address selection is in place, the clients may never get the live FTP server. The DNS server will be making the choice or the client could be. So, gotta scenario tells you to apply the tried-rule: "Test, test, test." Validate that servers are being used in a normal scenario, and validate what happens when a disaster scenario occurs.
