Within each SMTP virtual server, one or more domains must exist to associate the related file system directory for mail delivery to a particular qualified domain name (FQDN). By default, the initially created SMTP server will only have one domain—that of the resident machine's FQDN.

Differing security and delivery limit requirements of additional domains may dictate which domains should be served by SMTP virtual servers. Before deciding which you should know which virtual servers will affect the domains. Each new virtual server will store its configuration settings in IIS 6-compatible database.xml file under a IISSMTPServer element with a Location attribute of /Lm/smtSvc/{number} where a sequential integer is assigned to new virtual servers in creation order. Feel free to create as many virtual servers as be assigned to unique combinations of IP addresses and TCP port numbers supported by the server.

If you find that all email conforms to the same restrictions and limitations can be served by a single virtual server, then using the default SMTP Virtual Server #1 constructed is the easiest way to go. Setup as many domains as be supported for message routing to the Domains folder underneath the default virtual server. You can create a new domain by right-clicking the Domains folder and choosing to create a new domain via the New SMTP Wizard. The Wizard will identify the following:

# Domain Name Remote or aliases

**Domain Name** x400-compliant fully qualified address space of mail to be delivered by the new domain (be sure DNS is configured to resolve)

Upon completing the wizard, the new domain's properties to specify whether it must adhere to directory quota limits set forth in its virtual server's configuration settings. Each new domain will garner its own IISsmtpDomain in the database.xml configuration file.

# SOME CHANGES REQUIRE SERVICESTART

Adding SMTP virtual servers and/or domains to Windows 2012 will not take effect until the SMTP services are stopped and restarted. The Internet Services Information (IIS) 6.0 Manager console offers a quick method of restarting IIS services by right-clicking the computer name at the top of the tree pane, choosing All Tasks, and then restart IIS.

# AUTHENTICATION

SMTP services can be configured to demand authentication from other SMTP hosts attempting to transfer messages to it for security. By default, any anonymous access is permitted, allowing any and all SMTP servers that want to push email messages for supported domain namespaces to flood the directory with items. In a secure environment and for auditing purposes, you may need to enforce an authentication method so that other SMTP hosts are required to identify themselves before being allowed to forward messages to your SMTP service.
