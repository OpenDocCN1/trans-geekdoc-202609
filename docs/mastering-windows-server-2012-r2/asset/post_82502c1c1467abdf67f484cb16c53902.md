You should use a per-user CAL if users will connect to an RD Host server from multiple devices.

A Remote Desktop Services Licensing server needs to be configured to install, issue, and track RDS CALs. Clients won't be able to connect to the RD Host server if RDS CALs haven't been purchased and added to the licensing server after the grace period.

# Remote Desktop Users Group

Users need to be members of the local Remote Desktop Users group in order to connect to the RS Host server. You can add them when you need or later. The Administrators group is added to the Remote Desktop Users group by default.

Two Remote Desktop Users exist: one in the domain and a local group on the RS Host server. You will need to add users and groups into the local group to grant access for them to connect.

It's not uncommon for an administrator to incorrectly add users to the domain Remote Desktop group thinking this will grant access to the RD Session Host server. After a bit of head banging or hair pulling, the little word local is noticed. Once users are added to the local group, things work just as advertised. This can all be avoided through proper planning and placement at installation.

# Adding Applications

Many applications will work automatically in multiuser (such as Paint, Calculator, and Notepad), other applications need to be installed. After the role has been added, you can install any application using .msi file or via the Control Panel's Add/Remove Programs. If the application will install via one of these, that's all necessary.

However, if you have a legacy application that won't install via one of these, you will need to use the Change User command. The three-step process is as follows:

1. Execute the Change User /install command from the command prompt.
This puts the RDS server into installation mode.
2. Install the application.
3. Execute the Change User /execute command from the command prompt.
This returns the RDS server to normal mode.

# Connecting to an RDS Session

After adding the role, clients who are members of the Domain Users group can access desktop sessions on the RD Host server. During configuration, we added the Domain Users group, which in turn added to the Remote Desktop Users group. Be careful if you manually edit this group because the changes are not reflected in the Remote Desktop UI. Now let's connect to the newly created RDS Host and collection.

- 1. Click Start, type MSTSC in the Search box, and press Enter.
This will launch the Remote Desktop Connection console. For a full description of all the options in this tool, you can check out Chapter 17.
2. Click the Options button.
3. Enter the name of the computer hosting RDS in the Computer box, and enter the username of a user in the local Remote Desktop Users group.
Your display will look similar to Figure 29.7.
- 4. Click Connect.
5. Enter the password, and click OK.

A Windows Security screen will appear, and you will be prompted to enter the password for the user.

Security will be negotiated, and after a moment, you will be connected to the desktop. Depending on how MSTSC was configured, the connection may start as a window on the desktop or in full-screen mode. Figure 29.8 shows the connection. Notice it has a Windows 8 look and feel.
