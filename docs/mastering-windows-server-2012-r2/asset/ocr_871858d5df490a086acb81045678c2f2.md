# Policy-Based QoS

Using Group Policy, you can determine an application's QoS by the following settings:

+   * The sending application and directory path
* The destination and source IP addresses and ports
* The protocol, either TCP or UDP
* Active Directory or groups

Working together, these settings will determine the Differentiated Services Code Point (DSCP) value. Use this to inject a value from 0 to 63 into the Type of Service (TOS) field in a TCP IPv4 packet. Note that it also injects the value into the Traffic Class field in an IPv6 packet. Routers on the network then use the DSCP value assigned by an administrator via Group Policy, the routers will prioritize the associated packages.
Policy-Based QoS can be configured using Group Policy or Active Directory domain Group Policy configuration can be created at the computer level, the user level, or both levels if you wish. It's generally recommended to apply your QoS policy at the computer level, because ensures that no matter which users log onto the device, they will all receive the same QoS configuration. Let's look at an example. An administrator needs to prioritize the LOB application when it is being used by sales staff and directors. You know it operates on TCP 3299 and for users in Active Directory for sales. You can build a group policy targeting TCP 3299 and the aforementioned user groups while placing a higher than normal DSCP value of 60 on the application. This value will be injected into all packets on TCP 3299 that are associated with those users in the user groups. The network routers will then interrogate this value in the IPv4 or IPv6 packets and prioritize them as instructed.
