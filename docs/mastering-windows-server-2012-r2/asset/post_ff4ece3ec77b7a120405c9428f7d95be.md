# Upgrading Your Active Directory

Active Directory Server 2012 has arrived and you are anxious to get your current infrastructure up to the latest release because you want to stay with your infrastructure.

Before, we assumed there was no existing network and we were going to build a new network from scratch. This is not the case in many systems. Active Directory has been around for over a decade and many companies have some version of Active Directory. This section title says, we are going to focus on upgrading your domain to Windows Server Active Directory 2012. But before we dive into this, you need to understand the path we are going to take and what the prerequisites might be.

> ARE YOUR SERVERS READY? NT SERVERS ARE NOT INVITED TO THIS PARTY!

There is no way for a Windows NT 4.0 domain controller to live near a Windows Server 2012 domain controller. Since Windows Server 2008 R2, there is no longer any support for NT 4.0 domain trusts, and you can't install a Windows NT 4.0 into a Windows Server 2012 domain. Besides that, Microsoft's support for Windows NT 4.0 ended years ago. Therefore, Windows NT 4.0 is probably the only unsupported system on your platform.

# Upgrade the Schema to Windows Server 2012

In earlier versions of Windows Server, if you planned to upgrade your domain, you had to run a tool called adprep.exe. This tool would prepare and extend your forest schema to support new features, and it would also prepare your domain to create new groups and containers as needed. Additional options like /adprep would prepare the domain to set the Group Policy Objects for replicating to the Windows Server domain controller and /rodcprep would also add support for the Read-only Domain Controller accounts.

We have good news and even better news. In Windows Server 2012 the \support\adprep directory on your Windows Server 2012 sources exists. But there is no 32-bit version of adprep.exe, only the 64-bit version, which you can run on a 64-bit Windows Server 2008 and higher. You don't have to run adprep.exe on a domain controller; you can run remotely on a Windows server that is a member of a domain or a workgroup server. If you execute adprep.exe /help, you get all the available options.

If you need to extend your schema from a 64-bit Windows 2008 server, you need to type the following command:

```
adprep /forest w2kdomain.com /user administrator /userdomain w2kdomain.com /password P@ssword
```

After successfully extending the schema, you can run the following command to extend the domain:

```
adprep /domain /gprep w2kdomain.com /user administrator /userdomain w2kdomain.com /password P@ssword
```

In order to extend your for Read-only Domain Controllers you need to execute the following command:

```
adprep /rodcp /domain w2kdomain.com /user administrator /userdomain w2kdomain.com /password P@ssword
```

The better news is that you don't have to execute adprep.exe manually. In Windows Server 2012 there is a new Active Directory Domain Services Configuration Wizard, which you used earlier in this chapter to promote your first domain controller. This wizard is available after you have the Active Directory Domain Services role installed. The wizard takes care of all necessary steps you need to take to successfully promote your Windows Server 2012 member to a domain controller. Microsoft has integrated adprep.exe into this wizard to make the promotion as comfortable as possible.

If you are going to promote your server and you have provided all the necessary information, once you click Install, the wizard checks the environment and prepares the forest, schema, and domain, as shown in Figure 7.48.
