On the Questions tab, click each question and input the requested information on the computer that the counter logs were generated (Number of Processors, Total Memory, and so on); then click Next.

Choose the Analysis Interval from the Output Options tab (or leave it as AUTO); then click Next.

On the File Output tab, you have a number of choices to make about such things as the output directory for your reports, the report format (either HTML or XML), and the filename.

Click Next to move on when you've made your selections.

The Queue essentially shows you an overview of your selections through the wizard so far and gives you an option to remove items from the running queue.

Click Next.

On the Execute tab, you can choose to execute the analysis immediately, to add more items to the queue, or to execute analysis restarting the window with the same settings for convenience.

Finishing here will kick off the script that works with the counter logs specified to generate your report.

After a few minutes of PowerShell running, you should see your analysis containing material to show that in Figure 30.29.

# PhysicalDisk Read Latency Analysis

> Description: Avg read sec/transfer is the average time, in seconds, of read data to the disk. This analysis determines if any of the physical devices are responding slowly.
If the response times are greater than 0.015 (milliseconds), the disk subsystem is keeping up with demand.
If the response times are greater than 0.025 (milliseconds), the disk subsystem is likely overwhelmed.
