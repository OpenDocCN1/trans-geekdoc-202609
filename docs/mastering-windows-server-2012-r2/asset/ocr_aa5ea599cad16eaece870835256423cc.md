# Parallelized Repair

When a disk in a traditional RAID set, if you have a hot spot (a disk that can instantly take over the job of a failed disk in a RAID set), this hot spot will kick and the RAID array will start rebuilding the data on this disk. A performance impact on the disk subsystem is inevitable during the rebuild because all the data is being written to a single disk. The paralyzed process in Storage Spaces is a different. If a disk fails, the remaining healthy disks that have capability take ownership of the data that was stored on the failed disk and will serve users' requests across all spindles. Since all disks are now helping out, there should be performance impact. The repair process can bring in the hot spot or the administrator can replace the failed disk, and in the background it can be brought back into the storage space.

# Low-level Improvement: Native 4K Sector Support

Originally, hard disks used a 512-byte-per-sector format, and with came limitations in storage size and performance. With ever-increasing demand on capacity and speed, a change was needed, and over the course of a few 4K sector disks became standard. However, software (such as file system utilities, operating systems, and database engines) was not necessarily quick to catch up. Most manufacturers emulated 4K sector disks 512-byte sectors for compatibility. This requires a bit of overhead because the entire 4K sector is read into memory, and then written back. Since there is a degree of manipulation happening, there is also a performance impact, which is acceptable in this case.

With 4K sector support, the data industry no longer emulates 512-byte sectors, which means the performance impact is gone.
