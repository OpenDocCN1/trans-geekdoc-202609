# 828 CHAPTER 16 SHARING PRINTERS ON WINDOWS SERVER 2012 R2 NETWORKS

Most people on your network won't have their own print device on their desk. Instead, users typically print to a network-accessible printer. This printer can be accessible directly on the network or via a print server (the focus of this chapter). Figure 16.1 to see the ways print devices can be configured on a network. Print device 1 is connected directly to a USB port on Sally's computer. This isn't considered a network unless Sally shares it. However, if she shares it, the print device wouldn't be shared by the print server instead by Sally's computer. In this context, Sally's computer is acting as a print server, even if she's running Windows 7

Print device 2 is directly connected to the print server and would be shared by the printer, so it is considered a network printer. Since print devices 3 and 4 are directly connected to the network, they are also considered network printers. Print devices 3 and 4 must have NICs that are assigned IP addresses to be accessible on the network.

What's not clear in Figure 16.1 is whether devices 3 and 4 are being served by the server. One could be, and the other could be a stand-alone network printer. Let's say that the print server is configured to serve print jobs for device 3. All users would send their print jobs to the server, and the print server would manage the queue for print device 3.

On the other hand, let's say that the print server is not configured to serve print jobs individually on each of the systems, and jobs would be sent directly to the print device instead of the server. Print device 4 wouldn't have any of the benefits of the print server, such as, automatically printing jobs, controlling access to permissions or managing queues, this functionality is built into the device's software.

This chapter is focused on using a Windows Server 2012 R2 as devices are connected to the network and not served by a printer, they are on their own. The process of printing with Windows Server 2012 R2 is a bit more complex than it looks from the outside. The printing model uses several components to render application data graphical output, get the data to a printer, and then help the printer manage multiple print jobs. Some of the following information on how printing works is background, but it's also helpful when it comes to troubleshooting.
