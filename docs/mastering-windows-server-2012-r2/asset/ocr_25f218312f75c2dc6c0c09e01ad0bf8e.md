# 32.11  Recovering an object with the AD Recycle Bin

![](bbox=[0.295, 0.323, 0.88, 0.532])

Be careful to maintain appropriate security for your Active Directory backups because they contain complete copies of your domain's objects and credentials. A system backup is the safest way to back up Active Directory. If you ever need to call Microsoft for support on a failed Active Directory environment, then having a working system state is essential.

If you use a third-party backup product to get your system state backed up, you will have to use that third-party vendor for support in recovering it. It's good practice to always have a recent copy of your system state backed up to disk and then use the other non-Microsoft backup product to back up to a remote disk or tape.

# Restoring an Active Directory Backup

There are two types of restore operations for Active Directory: authoritative and nonauthoritative. An authoritative restore allows you to recover objects that have been deleted from Active Directory, but in this case, it won't allow replication to overwrite the restored objects. What happens is the restored objects replicate authoritatively to the other DCs in the domain. With a non-authoritative restore, a DC is restored to the state that it in at the time of the backup. Once it's restored, you then allow replication to update the DC to the current state of rest of Active Directory. In this section we will discuss the non-authoritative restore. Both methods are performed in Directory Services Restore Mode, which require restarting the server computer and using the F8 option to select DSRM.
