
# MANAGING ROAMING PROFILES

Speaking of disk space, you might want to consider how big a roaming profile can get. For example, users could upload their entire Music collection into it. It might be an innocent action where they think they're only consuming local storage. These are roaming profiles; 1000 users doing something like this adds up to terabytes of storage being consumed on the organization's file servers. Should the organization be paying for this?

The solution is to use Group Policy objects to control how roaming profiles behave in this circumstance. We'll now look at how you control roaming profiles on a per-machine basis using Group Policy. Every user logging onto a machine inherits the Group Policy settings that you configure.

## CLEANING UP PROFILES

If you'll find that a locally cached profile is created and kept on the workstation for the Remote Desktop profile, and it probably makes no sense to keep a copy of it in environments where you are using mandatory profiles. Even if you're not using mandatory profiles, you might want some way to clean up older profiles when a computer re. Group Policy gives you some tools to do this (see Table 26.1).

| PATH | ENTRY | DESCRIPTION |
|---|---|---|
| Computer Configuration\Administrative Templates\System\User Profiles | Delete cached copies of roaming profiles | Locally cached copies of a roaming profile will be deleted when user logs out |
| Computer Configuration\Administrative Templates\System\User Profiles | Delete user profiles older than a specified number of days | Profiles older than a specified number of days will be automatically deleted when computer restarts |

## MULTIPLE SETTINGS AND ROAMING PROFILES

What do you do with a user who has a roaming profile that travels between branch offices? By default the user logging in will measure the network speed between itself and the location where the profile is stored. If the link is considered too slow, then the profile will not be downloaded; instead the user will be offered a local profile. However, remember this won't work with mandatory profiles. You can control this process (see Table 26.2).

## TABLE 26.2 Slow Networks and User Profiles

| PATH | ENTRY | DESCRIPTION |
|---|---|---|
| Computer Configuration\Administrative Templates\System\User Profiles | Disable detection of slow network | You can prevent a computer from detecting whether profile download takes too long. Be very careful with this because user login could take a long time over WAN link. |
| Computer Configuration\Administrative Templates\System\User Profiles | Prompt user when slow network connection is detected | If a slow network connection is detected, the user can be prompted. This allows the user to choose their roaming profile despite the issue. Be careful with this. |
| Computer Configuration\Administrative Templates\System\User Profiles | Control slow network connection for user profiles | This allows you to define what “slow” means when measuring the link to the file server hosting the user’s profile. Measured in milliseconds. |
| Computer Configuration\Administrative Templates\System\User Profiles | Wait for remote profile | This directs the system to wait for roaming profile to download. It is ignored if "Disable slow network" is enabled |

This gives a pretty crude mechanism for using roaming profile when users travel to other locations. You have some other ways to make the environment flexible to business needs. If you have a predictable travel pattern, you might be able to take advantage of DFS Replication (DFS-R). Now you're seeing why we like to use DFS for hosting user profiles. You'll find that could get difficult to manage, so you will want to manage things very carefully.

An alternative is to allow users to have different roaming profiles in each site. This would mean their roaming profile wouldn’t actually roam between sites, only within one. You can configure this using the following GPO settings:

**Path:** Computer Configuration\Administrative Templates\System\User Profiles
**Entry:** Set roaming profile path for all users logging onto this computer
**Description:** You can specify a path for roaming profiles for all users logging into the computer. Use the %username% variable to have different profiles for users. This takes precedence over the profile specified in the user object.

# REMOTE DESKTOP SERVICES

There are several complications to consider when dealing with Remote Desktop Services and roaming profiles:

- It is a bad idea to mix a user's desktop roaming profile with the profile that will be used on a Remote Desktop server/virtual desktop because registry settings and shortcuts from different systems will be mixed.
- You may employ the concept of "application silos" in a Remote Desktop server farm; in other words, Server1 and Server2 might have AppApp installed, but Server3 might not. You don't want shortcuts for AppApp to appear when a user is logged into Server3 with a roaming profile.
- A common use for Remote Desktop services is to share applications from client with users in branch offices. You do not want branch-office roaming profiles to load across the WAN, but you do want some roaming profile solution.

You can apply this Group Policy object to disable roaming profiles on the machine:

**Path:** Computer Configuration\Administrative Templates\System\User Profiles
**Entry:** Only allow local user profiles
**Description:** Disable the usage of roaming profiles on this computer This is a crude solution. It turns off the ability to download a roaming profile and returns you to a scenario where the user does not have a consistent working environment. Alternatively, you configure users with specific roaming profiles for farms of machines. For example, when a user logs into a Remote Desktop server farm, they will use a dedicated profile from a Remote Desktop server roaming profile share. When they log into their PC, they will use a dedicated profile from a PC roaming profile share. When they log into their virtual desktop, they will use a dedicated profile from a virtual desktop roaming profile share.

## Table 26.3 Remote Desktop Services Profile GPO

| PATH | ENTRY | DESCRIPTION |
|---|---|---|
| Computer Configuration\Administrative Templates\Windows Components\Remote Desktop Services\Remote Desktop Session\Profiles | Set path for Remote Desktop Services roaming profile | You can specify the profile of a user account when logging in via Remote Desktop. This takes precedence over all profile settings. You can use %username% to allow multiple profiles or simply use one folder for all users. |
| Computer Configuration\Administrative Templates\Windows Components\Remote Desktop Services\Remote Desktop Session\Profiles | Use mandatory profiles on the Remote Desktop session host server | When enabled, this turns the profile specified in the previous GPO setting into a mandatory profile. |

The second set of settings in 26.3 allows you to tell the computer to treat any roaming profile as a mandatory profile, that is, to never save changes made by the user. This is an alternative to the previously described method for creating a mandatory profile. For Windows Server 2012, you will find these GPO settings in Computer Configuration\Administrative Templates\Windows Components\Remote Desktop Services\Remote Session Host\Profiles.

# SPECIFYING A REMOTE DESOP PROFILE

There is an option in the user account to specify a Remote Desktop profile. That's a rather simple solution that implies there will only ever be one profile for all Remote Desktop servers. This might be better for smaller organizations with one or two Remote Desktop servers. We recommend that you think long term and adopt the GPO approach to manage Remote Desktop Services roaming profiles.
