## WORKING WITHOUT A PRINT SERVER

We have spent a lot of time working in organizations that do not use print servers. Instead, print devices are placed directly on the network with an IP address, and each computer needs to be configured to use the print device.

One of the significant drawbacks to this method is that users often have problems connecting to the print device and installing the correct driver. They'd have to learn the printer's IP address to connect, and even then, the wrong driver can be selected, resulting in useless prints. The help-desk professional knows exactly what driver is needed, she often has to go to a driver hunt.

When a print server is used, users just need to use the universal naming convention (UNC) path of the printer(\\server\share) when adding it. The server will then automatically download the correct driver. As an example, a printer could be Laser1 on a server named BF1, and users would only need to connect to \\BF1 to automatically download the correct driver for their operating system. Additionally, if the print device is moved to a different subnet, only the server needs to be reconfigured, not every client.

The trade-off is the cost of the print server and associated maintenance. However, since servers can easily share roles, file servers act as print servers too.

You can be irritated by many users, the print spooler accepts the job and stores it in memory or on the hard drive until the print device can accept it. If you print a document, you can almost de-duplicate the job if the printer is busy. If you print a document, you can almost cancel it before it starts printing.

## The Printer Driver

Print drivers are the software that enables the operating system to communicate with the printer. In recent years, they have been unified into:

- Type 3 - User Mode
- Type 4 - User Mode
- Type 4 - Kernel Mode

With the release of Windows Server 2012 R2 comes the new v4 drivers. These drivers are not compatible with operating systems prior to Windows 8, but they support using the enhanced Point and Print Compatibility driver. Since the v4 architecture supports the print-class driver framework, users can install printers without having to locate the driver. This addresses security and compatibility concerns found in v3 drivers.

## PRINTER DRIVER HUNTS

Finding the correct print drivers (especially for new operating systems) is often very challenging. In a perfect world, as soon as a new operating system is released, every company would automatically have the correct driver for their hardware will work. However, a lot of things work against this scenario.

Of course, when a company realizes its driver no longer works, it tweaks and reengine. Then they post the new driver on their website as quickly as possible. The driver needs to be tested and validated before the operating system or available through Windows Update.

Meanwhile, users who have upgraded to a new OS realize they can no longer print. They try Windows Update (which includes only drivers that have gone through the lengthy submission and testing process) with no joy. Educated users (and administrators) know the best source in this situation is to go to the manufacturer's website.
