# Adding a Second Node to the Cluster

One thing that many people skip before adding the second node in the cluster is validating that the primary node is active and working. So make sure you check the following before moving onto this step:
- 1. Look at Cluster1 and make sure it isn't showing any errors or doesn't have a red mark through it.
- 2. Validate your storage and that you can confirm connections to the servers.
- 3. Validate your networking and that all connections are showing as connected.
- 4. Rerun the validation tests and get a report to review all options.
Some warnings may appear, and you should take the time to evaluate each one and make sure it isn't going to affect your secondary (or more) nodes to this cluster. Each error or warning the report provides you links and more detailed information so that you can successfully take care of any issue that there.

Now onto adding the additional node to your cluster: the important part that may seem obvious is that now you are providing services failover. It is exciting to have your first cluster up and running, but without additional nodes it's just a lonely service running on your server. The best place to start is the Failover Cluster Management; in the Configure section you will see the option Add Node. This is shown in Figure 11.17.

Windows Server 2012 R2 provides an advanced quorum configuration option where you can add or edit quorum vote by node. Out of the box all nodes are assigned a vote. You may decide to remove votes from specific nodes to help with disaster recovery solutions. The most common situation is when you have a geocluster and want to remove the votes from your recovery site; if you consider doing this, refer to Microsoft's guide on quorum considerations for DR found here: http://tinyurl.com/c11ClusterDR.

Setting up cluster infrastructure is usually not complex, although it can depend on your needs and the services you wish to provide. The more services, nodes, and sites you add, the more complex the setup becomes, but they are all worth it. ## Setting Up a Guest-based Cluster

As we have mentioned a few times in this section, guest-based clustering means extending the cluster services inside the virtual machine. The idea is to allow your VMs to have high availability on a clustered set of hosts.

Basically, the Role Health Service will detect a failure and recover by moving the VM to a different node to allow the OS or updates to run. Now you can connect your VMs to different types of storage, so you can connect to a SAN for shared storage via Fiber Channel with virtual adapters.
