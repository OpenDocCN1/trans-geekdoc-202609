
# PERFORMING A BACKUP WITH POWERSHELL

In Chapter 27, “Virtualization with Hyper-V,” you learned to create virtual machines on your Windows Server 2012 R2 host. We're going to discuss how to back up a Hyper-V virtual machine using PowerShell as an alternative to wadmin.exe. You can utilize PowerShell cmdlets for Windows Backup to create your backup policy (New-WBPolicy), specify where you backed it up (New-WBBackupTarget), the virtual machine (Add-WBVirtualMachine), and then configure the schedule you want it to run on (Set-WBSchedule).

- 1. Open an elevated PowerShell window. (You must be a member of either the Administrators or Backup Operators group to perform these steps.)

- 2. Configure your script execution policy to allow untrusted scripts by typing the following and choosing Yes when prompted: `Set-ExecutionPolicy Unrestricted`

- 3. Now input the following PowerShell script while making sure to change the values for New-WBBackupTarget and Get-WBVirtualMachine to something that’s relevant to your environment:
```powershell
# Create a Backup Policy
$BackupPolicy = New-WBPolicy
# Specify a target to your policy
$BackupTarget = New-WBBackupTarget -VolumePath F:
# Add the target to your virtual machine
Add-WBBackupTarget -Policy $BackupPolicy -Target $BackupTarget
# Specify your virtual machine name
$VMs = Get-WBVirtualMachine | where vname -like "ws2012r2*"
Add-WBVirtualMachine -Policy $BackupPolicy -VirtualMachine $VMs
# Configure the schedule
$BackupTime = [datetime] "23:00"
Set-WBSchedule -Policy $BackupPolicy -Schedule $BackupTime
# Activate the policy
Set-WBPolicy -Policy $BackupPolicy -AllowDeleteOldBackups
```

- 4. Once the script runs, your backup policy will be configured to run at the scheduled time, and you can view the job from inside the Windows Server Backup console, as shown in Figure 32.5.

# PERFORMING A FULL RESTORE

You can recover your server using different methods depending on the amount of data that must be recovered and the time you want to spend on the recovery. The worst case scenario of data loss on the server, either from hardware failure or data corruption. In this case, you could choose to reinstall the Windows Server 2012 R2 operating system and perform a full restore using Windows Server Backup. Or you could choose to perform a bare-metal restore using the Windows Server 2012 R2 installation method and the full server backup. This process is targeted at smaller environments and isn't feasible if you're managing a large organization with a number of domain controllers.

The following steps assume that your server computer has suffered data loss and you have resolved the hardware issues, replacing the failed disks. Make sure that the new hard disks are at least equal in capacity to the disks being replaced. Be sure to attach the drive containing the backup that will be restored so that the Windows Setup will be able to locate it. Alternatively, you can access a backup located in a shared folder over the network.

- 1. Boot the computer with your Windows Server 2012 R2 media.
- 2. In the Windows Setup dialog box, select the correct language options, and click Next.
- 3. Now click the “Repair your computer” option at the bottom left.
- 4. At the Choose option, click the Troubleshoot option to continue.
- 5. From the Advanced Options screen, choose the System Image Recovery option, as shown in Figure 32.6.

Windows Setup will attempt to identify any existing Windows installations on the hard disks, and if found, offer to repair them. If you are restoring onto a fresh hard disk, you'll get an error stating that a system image can't be located.

- 6. Click Next.

- 7. In the “Re-image your computer” wizard, select either, “Use the latest available system image” or, “Select a system image.”

If you choose “Select a system image,” you will be shown a list of images the wizard detects can be used to recover your server. Clicking the Advanced button here gives you an option to search for an image on the network as well as allowing you to install a driver for the new computer that may not have been included in the backed-up image.

- 8. Click Next to move on when you've made your selections.

- 9. Choose the available backup set in the “Select the date and time” box.
- 10. In the “Additional restore options” screen, select what you want to restore.
- 11. Click Next.

## Real World Scenario
WHEN THINGS WRONG

As a server administrator, you take steps to protect your data in case something goes wrong. As a case in point, we recently had a client who had everything preparing for data recovery. The domain controller for this small office housed only only Active Directory but also applications and user data, all data were stored on a RAID 5 set five Back..ups were to to run night, with with manual backups once a month to stored off-site.

RAID 5 sets are resilient enough to handle a single disk failure without downtime. You can add a new disk to replace the failed disk and tell the RAID 5 to rebuild all on the fly. The client's domain controller, however, suffered the loss of two physical disks in the set the same night. It was a freak occurrence, but it was something they weren't able to recover from.

After discovering the problem the next morning, the administrator was able to recover the domain controller by replacing the failed disks, establishing a RAID 5 set, and then performing a full server restore. The process included booting the computer using the installation media with the backup attached and then using the backup to perform a bare-metal restore. The server was up and running in a few short hours.

You can recover the server by reinstalling the operating system and using Windows Server Backup to restore the system state. This might be the preferred method if the backup is stored on a domain computer that cannot be accessed through Windows Setup.
