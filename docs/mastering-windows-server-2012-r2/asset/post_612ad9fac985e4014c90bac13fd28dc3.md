
# WHO NEEDS REMOTE DESKTOP SERVICES?

In extreme environments, engineers have designed solutions—but at a cost. When cost is an issue and a thin client will work, Remote Desktop Services can be a good choice.

We've also seen them in health cafes and coffeehouses set up so that the monitor is visible, thus reducing the chances of someone dropping a strawberry-banana smoothie with a shot of wheatgrass juice into the vents. For matter, someone cleans the terminal's vents, then when the applications are installed and running from the RDS server, replacing the device to provide an identical environment is as simple as unplugging the sticky terminal and plugging in a new one. If you drop a computer's vents, restoring an ideal working environment is significantly more complicated.

What about PCs being bad for conditions? Clean rooms where chips and boards are good candidates for Windows terminals. You can't have a clean room, and the fans in a PC pick up dust. Additionally, being sanitized to enter a clean room is neither poor nor inexpensive; you don't want to put devices that need care and feeding from the IT staff there. Another factor applies to many situations, not just clean rooms: anywhere where space is at a premium is a good candidate for a Windows terminal.

Clients can be running thin clients or just about any desktop operating system including Windows, Linux, and Macintosh (though rarely is optimized on Windows Vista or Windows 7/8).

This section isn't to tell you about the idea of Windows terminals to point out that sometimes they're useful enough—and even when you can't use an RDS server.

# POWER STRUGGLES

Another aspect of the environment-unfriendly PC applies to the power a desktop PC uses. Several studies have been published on the cost savings of thin clients versus desktop PCs. With the cost of power these days, the savings can be significant.

One study located at the following URL www.thinclient.net/pdf/Thin_Client_Benefits_Paper.pdf shows some of the possibilities. It is an old study but the principles still stand true for today. For example, a single thin client averaged about 10 watts a day while a desktop PC averaged 69 watts. This doesn't include the monitor, but both thin clients and PCs can use lower-power LCD monitors instead of the power-hungry CRTs of the past.

The study estimated the cost of power at $0.10 per kWh and $0.20 per kWh, which is a good range of power costs within the United States. For 100 clients, this equates to savings of $3,000 and $6,000 annually.

Saving on power isn't the only reason to use Windows terminals, but if you're tossing around the idea of replacing PCs with terminals, it's a compelling argument in favor of.

# Reducing Hardware Refreshes

Does it take a Core i5 2.5 GHz processor with 4 GB of RAM installed to check email, do accounting, and poke around on the Web a bit? Of course, but as of mid-2013 that's not an unusual hardware profile for a desktop computer. Not that these computers are too expensive in absolute terms, but we are amused every time we buy a new computer, we pay less for a system more powerful than the last one we bought.

Still, even though they're not too expensive in absolute terms, the new computers are always worthy because they work when you're not demanding all that from your hardware. Ironically, unless your job is so demanding, such as computer-assisted design, you're more likely to need a powerful computer at home than work because game hardware requirements are so high. It takes more computing power to play a few rounds of the most recent version of Warcraft than it does to write this chapter. (Fingers are hard!)

The trouble is, sometimes you do need more powerful computers if you're planning to keep up with existing software technology. You don't need the fastest computer to do word processing. You may, however, need a faster computer than the one you have if you're going to keep up with the latest and greatest word processing package that everyone is using. If you want to be able to read all these charts and graphs, you can't do it when your word processor is six years old, if it still works. And you can't run now word processor if your computer is six years old.

You must also take into account now available power. Power consumption is paramount in these devices in order to make them light, portable, and last for a certain amount of "use". In order to reduce the power consumption manufacturers also had to reduce the processing power of devices, so in order to perform more intense functions, an RDS server becomes more important. This also holds true if a company adopts a BYOD strategy; for almost every platform a Remote Desktop client is available. This gives users the flexibility of processing and using the devices that they require while the corporate administrators maintain control over the system and desktop applications.

In summary, if you're using Remote Desktop Services with an RD Host server, the client only displays applications running on the RDS server rather than running locally. You don't have to concern yourself with whether the applications will run on the client computer; your concern is the server. If the application will run on the RDS server then the application will display on the client regardless of the platform.

# Simplifying the User Interface

Another potential benefit to Remote Desktop Services is that it can simplify the user interface (UI). Using a computer is not as easy as the marketing world would have you believe. Experienced users find it easy to customize their interface, but those who are less experienced fall into all pitfalls when it comes to using their computers: there are many options that they get confused by and colorful icons with rounded corners do not make a simple UI.

If the people're supporting only a single application, you can save yourself and a lot of grief by providing a connection that runs this application in a remote desktop and nothing else. This is particularly true with Windows-based terminals, which are little more than a monitor, a keyboard, and a mouse.

Or, if you're already running a desktop operating system, you can use RemoteApp applications. RemoteApp applications deployed via RDS are as easy to use as any other applications on the end user's computer. RemoteApp applications can be launched from the Start menu, from a desktop icon (of an .rdp file), or from a web page.

# Providing Help-desk Support

Finally, Remote Desktop Services can make application support easier, not just in terms of installing new applications and fixing them but in terms of helping people learn to use those applications. Remote Desktop Shadowing (previously called Remote Control) lets help-desk personnel or administrators connect to another person's remote session to watch what they're doing or to interact with them. This doesn't happen automatically and requires some sort of input.

When you have remote control of another user's session, you can either watch what they're doing (perhaps over the telephone) or actually interact with them so that you can demonstrate a process. This beats standing over someone's shoulder using a GPU.

# Deploying RDS RemoteApp

RemoteApp programs are applications that are running on the Session Host server but appear to the end user to be running on their. This is often easier for an end user to conceptualize. They don't have to manage multiple desktops but instead can simply launch another application from their main desktop.

Windows Server 2008 introduced RemoteApp programs, and they've improved in every generation of Windows, including 2012 R2. Here are some of the new enhancements in this release:

- RemoteApp Rotation: Faster resolution and rotation on client machines including changing the remote session's resolution.
- Monitor Hot-add/subtract: If you add a monitor, it will allow you to move it and readjust if you need to.
- Click Once App Support: Users can now install apps directly from the browser, rather than having an administrator deploy them as in previous versions.
- Hi-fi RemoteApp: This enables support for apps that use Desktop Window Manager. You can now get transparent notifications with fading effects.

Do take into account that it requires a bit of configuration to support RemoteApp programs. However, once you've configured all the pieces, users can access RemoteApp applications via the following methods:

- Through a Web Browser: If RD Web Access is configured, users can access the web page and click a link to launch the RemoteApp.
- Using a Remote Desktop Protocol File: Users can double-click a properly configured .rdp file to launch the menu or RemoteApp application.
- Through the Start Menu or a Program Icon: RemoteApplications can be installed using traditional Windows (.msi) packages (also called Microsoft Installer packages). Once they're installed, users can launch the applications just like any other installed application. Or they can use the new Click Once deployment method.

You'll learn how to install all the components and deploy RemoteApp applications for each of the methods shown in the section "Adding Remote Desktop Services" later in this chapter.
