## How Many AD FS Servers Should You Deploy?

The following information will help you estimate how many AD FS federation and server proxy servers you will need in your server farm deployment based on how many users will use SSO access to cloud services and partner organizations.

**Up to 1,000 Users** You can get away with domain controllers to host the AD FS role in a small environment if needed. If you have the resources available, it is still a good idea to segregate infrastructure roles and services as you can by building dedicated servers for AD FS even though it is not a requirement. For 1,000 users, it is not necessary to build dedicated federation servers or federation server proxies. However, you will have to utilize NLB between the two domain controllers that are acting as the two federation servers in the federation farm.

**1,000 to 15,000 Users** If your environment consist of a base user ranging from 1,000 to 15,000 users, you will want to build out to two dedicated federation servers on the internal side of the corporate firewall, two federation server proxies on the external side of the corporate firewall (DMZ or extranet), and an NLB configured for each pair to balance the load.

**15,000 to 60,000 Users** For larger organizations you could easily find yourself deploying from three to five dedicated federation servers and at least two federation proxies. Federation servers scale at one additional dedicated server per 15,000 users. Currently the maximum number of federation servers in a single federation server farm is five, or 60,000 users. For really large enterprises it is completely possible for multiple maxed-out federation server farms to provide SSO capabilities for users over the globe.

## Should You Use WID or SQL for Your Deployment?

Traditionally you would want to use a Windows Internal Database for the AD FS configuration database with web SSO. At a certain point you can no longer use WID if the environment grows too large. WID caps out and is limited to five federation servers per farm. At that point configuration of a SQL Server database is required. If you have more than 60,000 users who will require SSO access, you will want to plan and deploy SQL for the configuration database right from the start. A SQL Server configuration for AD FS provides three added benefits to a WID deployment:

- Geographic load-balancing is supported to help provide increases for high traffic based on location.
- Administrators can use and take advantage of the high-availability features provided by SQL Server.
- SQL Server is not limited to five federation servers per farm.

## WHAT TYPE OF NETWORKING REQUIREMENTS WILL BE EXPECTED?

Proper networking is essential to the success of the AD FS deployment. For AD FS to function and as intended, TCP/IP connections must exist between the client, domain controllers, federation servers, the AD FS web agent, and federation server proxies. DNS plays another important role in rolling out AD FS. As part of your implementation, you will likely need to add additional Host A records for servers and clusters that are deployed during implementation. For more in-depth instruction on using and configuring DNS, please refer to Chapter 6, "DNS and Name Resolution in Server 2012 R2."

When you use network load balancing both on the corporate network and externally on a DMZ, for example, DNS servers resolve the cluster DNS name to the client IP address for the NLB cluster you have configured. For example, fb1.test resolves to 172.100.1.3. Keep in mind that a network load balancer is required for proper production deployment as well. An NLB can be a piece of hardware or software that provides load-balancing, high availability, and fault tolerance across multiple devices and machines on a network.

## ARE MULTIPLE BROWSERS SUPPORTED FOR AD FS SSO

You may not be able to sign into the cloud service using integrated Windows authentication from the corporate network with any other than certain versions of Internet Explorer you have Extended Protection for Authentication patches installed. By default, Windows clients are preconfigured with Extended Protection for Authentication. If you want to use other browsers like Chrome, Safari, and Firefox to sign into the cloud service, you may have to remove all of the Extended Protection for Authentication patches from the local machine. This is not supported or recommended by Microsoft for security reasons, but it can be done to get you online with your favorite browser. Please visit http://technet.microsoft.com/en-us/library/ff676834.aspx for more information on AD FS browser requirements.

## COOKIES

One requirement for client computers to use SSO capabilities is that cookies must be enabled on that machine. AD FS creates session and persistent cookies that must be stored locally to each client for proper login access. Please keep in mind that if the client is not configured to accept HTTPS authentication cookies, then AD FS will not function properly.

## Installing the AD FS Roles and Features Using Server Manager

AD FS 2.1 in Windows Server 2012 R2 uses the same great features that were provided in version 2.0, bringing to light new and changed functionality that make this protocol stronger and easier to use than in previous versions. Before Server 2012, you had to download install AD FS software before you could deploy your server infrastructure. Now you can easily use Server Manager to add the AD FS roles and features from the server instead of having to download and install the software as required in previous server editions.

Another nice addition in Windows Server 2012 R is that AD FS can now be used with Active Directory Domains Services to provide extended functionality. AD FS can consume DS user and device claims that are included in Kerberos tickets because domain authentication. This greatly expands the capabilities of AD FS. To top it all off, Microsoft forgot about AD FS with their new and improved PowerShell cmdlets to automate and administer AD FS later through a command-line interface. We will take a look at AD FS PowerShell cmdlets in later chapter.
