# First, the Simple Case: No Routing Required

The simple case is when two computers want to talk to each other are on the same Ethernet segment. Let's begin at the New York site and start some communication from computer A (IP 192.168.0.1, MAC address 00:01:CA:FE:05:01) to computer C (IP address 192.168.0.3, MAC address 00:01:CA:FE:05:03). The procedure is as follows:

+   1. The application, or Network layer, sends an IP packet to the IP layer.

+   2. A's IP layer examines the header for the destination IP address.

+   3. A's IP layer creates MAC address using ARP (IPv4) or ND (IPv6).

+   4. A's IP layer creates an Ethernet packet and sends it.

+   5. C's Ethernet layer recognizes the address, receives the packet, and forwards it to the IP layer.

+   6. C's IP layer examines the header and passes the payload to the protocol's handler.

That list of steps is something you'll refer to later when troubleshooting connectivity problems, but for now it needs explanation.
If an IP packet has *parents*, they would be the source and destination addresses. Every packet has to know where it's starting and where it's going. Getting into your car and not knowing your destination! In IPv4, the packet may also be split into parts by an intermediate router. That way, the receiver will know which parts to put together. Finally, there is a piece of information that tells the receiver how to treat its data (payload), whether it is to be handed to the TCP or UDP stack, or a different protocol, and so on. To IP, it are protocols 1, 2, 47, and so on. Most of the time you do not have to worry about this, but you can use tools like Wireshark or Network Monitor to observe all the information.

When a packet is created, all this information—and perhaps optional options—is placed into the IP header, the header and payload are sent to the IP layer of the network stack for forwarding.

The IP layer on the source computer has to tell the Network layer (in most cases, this would be the Ethernet driver) to put the packet onto the right network card, with the right destination and source address, and to do that it must know the Ethernet address corresponding to each IP address.

From Figure 20.1, it's clear that the MAC address for the source should be 00:01:CA:FE:D5:01 and that the MAC address for the destination should be 00:01:CA:FE:D5:03, but the source computer doesn't have this diagram, and since it's never seen C before, it has no idea of MAC address. All it knows is that the IP address 192.168.0.3 is what this packet needs.
