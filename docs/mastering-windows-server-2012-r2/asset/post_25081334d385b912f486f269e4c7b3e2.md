## A New Way to Secure File Shares

We assume you are reading this chapter that you know the basics of file shares: how to create and manage them. If you don't, stop! And turn back to Chapter 13 where you will learn all this. If you are familiar and ready to proceed, let's go!

Let's dive straight in and look at the share permissions on a file, as shown in Figure 15.1.

## Figure 15.1
File permissions in Windows Server 2012

![](img/41a83208e6906a3732620203b836cea7_795_0.png)

As you can see, no major changes have happened there. The real power in securing file shares is through the security properties, as displayed in Figure 15.2.

## FIGURE 15.2
Security tab for a file share

![](img/41a83208e6906a3732620203b836cea7_796_0.png)

This Security tab dictates the NTFS permissions to not the folder but the files as well. But as you can see from this, it doesn't look much different than in previous versions of Windows.

Since this is most definitely an advanced feature, it is rightly placed under the Advanced button at the bottom of the Security tab; see Figure 15.2.

Figure 15.3 shows the Advanced Security settings for a file share, and it begins where we can begin to configure the basics of DAC.

## FIGURE 15.3
Advanced settings for a file share

![](img/41a83208e6906a3732620203b836cea7_796_1.png)

In this example we have a single folder shared share. It is shared to everyone for read-only access via its share permissions and read-only via NTFS permissions, and we also allow administrators Full Control. You can see from Figure 15.3, however, the Everyone principal has Read & execute access. You can now start to see the granular Advanced Security settings, but this is still not DAC.

Click Add from the Advanced Security Settings screen, and you will be brought to the “Permission Entry for share”, as shown in Figure 15.4.

## FIGURE 15-4 Permission Entry for share

![](img/41a83208e6906a3732620203b836cea7_797_0.png)

In order to progress, you must select a principal. A principal would be, for example, a user account or a group to which you want to assign privileges. If you not select a principal at this stage, all the elements will stay grayed out.

As you can, quite a few options look familiar from previous versions of Windows. However, now there is a new section where you can add a condition. This is where the power of DAC begins: with conditional expressions.

When you click “Add a condition,” you will get the chance to create a condition, as shown in Figure 15.5.

## FIGURE 15-5
Adding condition

![](img/41a83208e6906a3732620203b836cea7_798_0.png)

The first condition to choose from is a device or a user. You can secure data not only down to the user account but also from the device from which they access the resource. You can ensure that they have access to the resources from a corporate device but not their home laptop. That way, you can ensure the security of the data you control the corporate laptop/desktop.

In the example in Figure 15.6, we have allowed John McCabe (johnm@contoso.ie) Read & Execute, List Folder Contents, and Read permissions, but we have now added a condition in order to share the access he needs to be on a computer that is part of the Domain Computers group.

## FIGURE 15.6
"Permission Entry share" dialog adding a condition

![](img/41a83208e6906a3732620203b836cea7_798_1.png)

Now, returning to the "Advanced Security Settings for share" screen, you can see the new principal added but the Condition column for John McCabe is now populated, as shown in Figure 15.7.
