# # Identification and Logging

Once you find a real issue, an online scan of the file system is triggered. This scan is designed to run in conjunction with the operating system and will run only when the system is idle or when utilization is low. If it finds the problem, it logs for offline correction.

# # Precise and Rapid Correction

Because you have logged the issues, you don't have to scan the entire file system again when you begin the offline process. This essentially means that when you do a volume offline to repair the issues, it takes to repair rather than four hours. This fix is called Spotifix. If you are using Cluster Shared Volumes, there is no downtime, giving you always-on volumes.

With these new improvements, the CHDSK runtime is no longer based on the number of files but on the number of corruptions. You can repair many issues online (with CSV always online), CHDSK requires less time. This figure 12.3 shows the options in CHDSK.
