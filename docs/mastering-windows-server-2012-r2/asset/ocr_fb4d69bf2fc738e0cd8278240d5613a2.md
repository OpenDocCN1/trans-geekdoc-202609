Storage Reports Many of the reports have parameters that can be modified. Each parameter that can be modified with a default. You can use this page to modify the default parameters.

Report Locations Reports have default locations on the system drive (which is normally c:\). Three folders are created within the %StorageReports folder. They are Incident (from notifications), Scheduled (from scheduled report tasks), and Interactive (from on-demand reports). You can change the default locations for any of the reports from this page.

File Screen Audit This page has only one option: "Record file activity in an auditing database." If selected, the screening activity will be recorded in a database, which can be reviewed by running a file screen audit.

Automatic Classification It's possible to manage files based on classification rules that you create, in instance of where files are located within a directory tree. If you use classification management (not many people), you can use this to schedule the execution of classification rules and generate reports. If you would like to learn more about file classification, check out this TechNet article: http://technet.microsoft.com/library/dd57865.aspx.

Access-Denied Assistance New with Windows Server 2012, the Access-Denied Assistance tab allows you to customize your own access-denied error message that is displayed to a user who does not have the proper permissions to access a cluster or folder. On top of that, you can enable request assistance directly from the error message by clicking the hyperlink. This is a very useful feature.

Although NTFS is a great file system and has included extras such as NTFS quotas, you can get a lot more capabilities using File Server Resource Manager. If you're managing a file server, these extras are worth digging into.

# Understanding SMB 3.0

Server Block (SMB) is an application-layer network protocol that is used primarily to provide shared access to files, printers, ports, and communication between machines on a network. SMB is commonly referred to as Common Internet File System (CIFS). This protocol is used primarily for Windows operating systems and servers as the basis for Microsoft's Distributed File System implementation.

SMB 3.0 has changed a bit in this server edition. Many new features have made this protocol a high-performance alternative to Fibre Channel and iSCSI appliances. Let's take a look at some of the new features:

SMB Failover This feature allows administrators to perform maintenance on clustered computers without incurring any downtime. In the event of a cluster failover, the SMB 3.0 clients will automatically reconnect to another cluster without losing any access to the files they were using. Clustered file servers eliminate the single point of failure of having only one file server or a nonclustered environment.

SMB Scale Out SMB clients are no longer limited to the bandwidth of a single cluster node. When clustered, the machines load balance between themselves using their aggregate resources. Every server in a file cluster is an active node serving content to clients. SMB scale-out file shares are always configured with the Continuously Available property set.
