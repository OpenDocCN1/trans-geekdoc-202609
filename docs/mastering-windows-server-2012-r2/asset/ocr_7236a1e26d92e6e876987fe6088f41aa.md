# Real World Scenario

# VMS MYSTERIOUSLY RUNNING SLOW

Bigfam has deployed a number of Hyper-V host servers as a test environment. Each server has a RAID 5 configuration 128 GB of internal memory and 12 TB of usable disk space. The Hyper-V hosts are run by the IS department. Other departments use and manage the VMs.

One day, complaints start coming in that certain VMs are slow to respond, although there is no load on the VMs. The IS department takes the complaints and investigates. One of the VMs show any sign of trouble. The CPU usage is normal, all applications are running, the OS is not swapping, and there is no memory pressure. In short, there is no obvious cause. One pattern emerges: 'slow' VMs.

The IS department starts running counters on the host, including the CPU and Logical Disk objects. After an hour of measuring, they note that some counters are consistently high: the counter disk seconds/read averages 30 milliseconds, and the counter disk seconds/write is mostly over 50 milliseconds. The average queue length counter of the disk hosting often peaks at more than 20. Compared to other hosts, these are really high values. The host has trouble delivering the required I/O.

An inspection of the host shows that the disk on the VMs are located a RAID 5 configuration, which is good but reads at slow. The combined disk I/O of all VMs has the host capacity over the limit. The problem is solved by rearranging the disks in a RAID 10 configuration and adding more disks to increase the I/O throughput.

This case illustrates the added complexity of managing a virtualized server environment. The combined VMs may put the host in trouble if the underlying physical disk hardware has not been configured for optimal performance.

# Disk Maintenance

The essential parts of a VM are its disks. Not only do they contain the data, but they determine in large part the performance of the VM. In this section, you will learn how to maintain virtual disks.

When using dynamic and fixed disks, if you create a lot of data and remove it (such as copying large ISO files onto it and then deleting them), you'll leave a lot of empty space on the disk. In other words, the virtual disk is larger than it needs to be. Hyper-V can remove this empty space by an operation called compaction. To do this, the virtual disk must be in the parent partition. If the file system on the disk is NTFS, the parent can inspect its data structures to find where empty space is. It uses this information to reduce the size of the file representing the virtual disk. To compact a virtual disk, the corresponding VM cannot be running. You must shut it down or save its state. Once you've done that, it goes like this:

+   1 From the Actions in the Hyper-V management console, start the Edit Virtual Hard Disk Wizard.

+   2 Locate the virtual disk you want to compact, such as the one you created earlier, and click Next.
