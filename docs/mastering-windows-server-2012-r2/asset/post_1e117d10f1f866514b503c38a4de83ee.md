## THE LIFE OF A PACKET

The simple case is when two computers are on the same segment. In this case, routing is not required. The source computer only needs to know the Ethernet address of the destination. It can find this using ARP (Address Resolution Protocol) in IPv4, or ND (Neighbor Discovery) in IPv6.

In the example, computer A (192.168.0.1) wants to talk to computer C (192.168.0.3) on the same subnet.

1. The application on A sends data to the transport layer.
2. The transport layer (TCP or UDP) adds a header and sends it to the IP layer.
3. The IP layer adds an IP header with the source and destination IP addresses.
4. The network layer (Ethernet) adds an Ethernet header with the source and destination MAC addresses.
5. The packet is sent over the wire.
6. Computer C's network layer receives the Ethernet frame, strips the Ethernet header, and passes the packet to the IP layer.
7. C's IP layer examines the IP header, strips the IP header, and passes the payload to the transport layer.
8. The transport layer processes the data and passes it to the application.

If the computers are on different subnets, a router is required. The source computer sends the packet to its default gateway (the router). The router receives the packet, strips the Ethernet header, examines the IP header, and looks up the destination IP in its routing table. It then creates a new Ethernet header with the router's MAC address as the source and the destination's MAC address as the destination, and forwards the packet. This process continues until the packet reaches its destination.

All it knows is that the IP address 192.168.0.3 is what this packet needs.
