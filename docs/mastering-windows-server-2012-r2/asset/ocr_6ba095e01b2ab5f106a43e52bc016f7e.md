Now it'd be possible for a local administrator to Matterhorn to join Apex.com, and she would not to fail in a domain account/password to share her workstation OS. But what if you wanted to create the machine account and join the machine to the domain? For that, there's netdom. It looks like the following:

```
netdom join machine /domain:domainname
/user:destination-domain-admin-account
/password:destination-domain-admin-password
/user:local-machine-admin-account
/password:local-machine-admin-password
/ou:reboot
```

Most of those options will seem pretty familiar. As before, you need to netdom what to join, what domain to join it to, and what OU in place the machine account in. Because this creates a machine account on the domain, you'll need to present domain-level administrators. But because you're also joining the machine to the domain, you'll need the machine's permission as well, so you'll need to show that you have an account that the machine recognizes as a local administrator account—what's password and userdo (Think of the o at the end as "object," as in "We're joining the domain". For the user and password--they're your account with administrative privileges on the destination domain). Finally, /reboot tells the workstation or member server to reboot to make the changes take. Interestingly, you don't need to be anywhere near the target to do this—it work remotely without a problem! So, for example, suppose you wanted to move a system named Saturn to a domain named Planets.com. The administrator account on the Saturn machine is named satadmin with password hi, and Planets.com has a domain administrator named planetsadmin with password dso. The command would look like:

```
netdom join Saturn /domain:planets.com
/user:satadmin /password:hi
/user:planetsadmin /password:dso
/reboot
```

We told you that netdom could help by letting you move a machine from one domain to another—that's the netdom move command. It'll need three sets of account names and passwords, because to move a machine from domain A to domain B, you'll need to demonstrate administrator credentials on domain A, on domain B, and on the machine that you're moving. As before, if you specify user, userdo, and password. But now you'll need to specify user f password—an account name and password from the former domain. By now, all the options should be familiar:

```
netdom move machine /domain:destination-domainname
/destination-domain-admin-account
```

```
/password:destination-domain-admin-password
/user:local-machine-admin-account
/password:local-machine-admin-password
/user:former-domain-admin-account
/password:former-domain-admin-password
```
