# Fine-Grained Password Policies

One of the most common questions since the initial release of Active Directory has, "How can I have more than one password?" The official Microsoft answer was that you needed more than one domain to do this. Of course, this contradicts the basic design goal of trying to reduce the number of domains in networks. It also muddied the waters when it comes to no longer thinking of the domain as a security boundary—and the forest is a security boundary.

The solution, without using third-party products that Microsoft might not, was to create a domain for every password policy you needed (which could create a lot of domains) or to use a third-party solution that would allow you to have more than one password in a single domain.

The objective of fine-grained password policies is to associate stronger policies with accounts of greater significance, in other words, where they have greater access to systems or to valuable data. What ended happening, however, was that manually defined policy values did not behave and became very time consuming. Windows Server 2012 R2 allows you to manage policies using the Active Directory Administrative Center, which makes the management of password-settings objects easier.

# Rapid Deployment with Cloning

Cloning, by definition, means "making an identical copy of." How is cloning used when AD DS? The answer is you can make an exact replica or clone an existing virtual domain controller in AD DS.

You can promote a virtual domain controller by using the domain controller promotion interface in Server Manager and then deploy additional virtual domain controllers within the same domain, through cloning. First, create a copy of an existing virtual domain controller and authorize the original domain controller to be cloned in AD DS. Using PowerShell cmdlets you can create a configuration file with detailed promotion instructions such as, IP address, and DNS servers. By cloning you can save time by eliminating repetitive tasks of deployment.
