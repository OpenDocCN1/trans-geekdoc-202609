# Rollback Considerations

The greatest advantage to the C&B migration is its natural nature. This also lends itself to gradual rollback plans. Phases of the migration will avoid wrinkles and hiccups. You wantant these to emerge early in the pilots. If issues or obstacles arise, you can avoid performing a show-no-go rollback. Issues can be addressed individually with proper planning, workarounds and intermediate states can be expected.

The migration process involves accounts and groups. Thus, source accounts and groups are still in place and can be reenabled and used as necessary. Only a few security objects require rollback procedures, such as local user profiles.

So, for each migration phase, plan and test the rollback to the state prior to the specific change within the phase.

# The Path to the 2012 Forest Functional Level

Once you decide on which of these methods to use, you will start upgrading or migrating as desired in the respective section.

In a single-domain forest, you will upgrade all of the domain controllers to Windows Server 2012. After all domain controllers have Windows Server 2012 installed, you can raise the domain functional level to Windows Server 2012. Then you can raise the forest functional level to Windows Server 2012.

In a multidomain environment, you can independently upgrade domain controllers within a forest that has multiple domains. For example, you can begin upgrading domain controllers in a child domain before you upgrade domain controllers in the root domain of the forest. As you have upgraded all domain controllers in a domain to Windows Server 2012, you can raise the domain functional level in that domain. Continuing each domain to Windows Server 2012 until all domains in the same forest have a forest functional level of Windows Server 2012. Now you can raise the forest functional level to Windows Server 2012.
