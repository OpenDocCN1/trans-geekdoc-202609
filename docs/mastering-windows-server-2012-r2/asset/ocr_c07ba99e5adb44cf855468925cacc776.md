Although malware scanning is a direct form of protection, keeping up to date with patches is indirect but just. There is no need to tell you that you should patch the VMs and the host—if you don't, you're just asking for trouble. The host may need to reboot, taking all the VMs offline. Planning may cause problems if you cannot shut down VMs reliably. That Integration Services is so important. One of its functions is to initiate the save-state procedure in the VM when the host asks for it. The default action configured on each VM is to stay when the stand-alone host shuts down. More than one will help here, because you could use Shared Live Migration to keep the VMs online.

If you have a Hyper-Failover cluster environment running Windows Server 2012 or higher, you can then leverage the Cluster-Aware Updating (CAU) feature, which will allow you to patch your servers with minimal downtime while they are being deployed. CAU integrates the built-in Windows Update Agent and Windows Server Update Services (WSUS) to download and install the updates. When you want to patch a Hyper-Failover cluster running Windows Server 2012 R2, all you need to do is shut down the host and the Windows Drain feature (discussed earlier in this chapter) which will migrate all your VMs to any other available host. If you're running Windows Server 2012 (not R2), then you will first need to pause using Failover Cluster Manager and choose the Drain option to get the same result. To learn more about CAU, check out this TechNet document: http://tinyurl.com/ws2012cua.

Virtualization is a key pillar of cloud computing, with the evolution of technologies such as Hyper-V, disaster recovery (DR) has become far easier and cheaper to deliver than ever before.
