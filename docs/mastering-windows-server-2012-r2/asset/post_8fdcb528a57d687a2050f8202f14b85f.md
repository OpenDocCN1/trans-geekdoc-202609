
# MULTIPLE HOST REQUIREMENTS FOR CLONING

If you are cloning a DC from one Hyper-V host and placing it on another, then you need to ensure that the virtual network switch names are exactly the same on each node that you will be exporting and importing on. For example, if you have a virtual switch VMEXT on Host1, then you will need to have a virtual switch VMEXT on Host2. Also, if you have different processors, make sure to select the "Migrate to a physical computer with a different processor version" option on the virtual DC you plan to export first.

# CLONING A Virtual DC

Once you have all the prerequisites in place, you're ready to work through the steps in this section and get your first virtual DC cloned:

- 1. Log on the DC hosting the PDC Emulator with a domain administrator account and choose Server Manager Tools > Active Directory Users and Computers.
- 2. Expand the domain root and then click the Users organizational unit.

You should see the Domain Controllers security group, as shown in Figure 28.2.

FIGURE 28.2
Cloneable Domain Controllers security group

![](img/41a83208e6906a3732620203b836cea7_1438_0.png)

This group is managed by the Active Directory team and is used to control which DCs are cloned. In a low-security environment, the Active Directory and virtualization teams would be separate entities, ensuring that authorization to a critical server such as a DC is managed by the AD team. If you don't see this group, then you aren't using a Windows Server 2012 DC as the post-Active Directory emulator, as mentioned.

- 3. Double-click the Cloneable Domain Controllers group, choose the Members tab, and then click the Add button.
- 4. Change the Object Types to search for objects of type Computers; then the name of your template virtual DC (WS2012R2-DC2), and click the Add button.
- 5. Click OK to close the window and confirm that the template virtual DC is added to the group.

With the template virtual DC now authorized for cloning, you must ensure that all instances (if any) that are running on it can be safely cloned.

- 6. To do this, log on to the virtual DC with an account that has administrative permissions and run the Get-ADDCloneExcludedApplicationList cmdlet.
- 7. From the resulting list of applications, check the relevant software vendor to ascertain if they are supported for cloning (if applicable).
- 8. To provide these applications, from an elevated PowerShell prompt, run Get-ADDCloneExcludedApplicationList -generateXML

This creates a new XML file located in %wind%\NTDS\CustomCloneAllowedList.xml, as shown in Figure 28.3.

- 9. Staying with PowerShell on the template virtual DC, you now need to run the New-ADDCloneConfig cmdlet with all relevant parameters required for the new DC (hostname, TCP/IP, and on).

Running this cmdlet will create the CloneConfig.xml file that will be used to trigger and ensure cloning. You can get the full syntax options of this cmdlet: http://technet.microsoft.com/en-us/library/jj15894.

> FIGURE 28-3 Provisioning applications for cloning

![](img/41a83208e6906a3732620203b836cea7_1439_0.png)

- 10. Type the following to create the DCCCloneConfig file (substituting parameters that are specific to your environment):

```
New-ADCCCloneCloneConfig -Static -IPv4Address "192.168.0.210" -IPv4DNSResolver "192.168.0.108" -IPv4SubnetMask "255.255.255.0" -CloneComputerNameWS2012R2-DC3" -IPv4DefaultGateway "192.168.0.254" -STName "DUBLIN"
```

- 11. Now show the virtual template DC (WS2012R2 DC in our example) and delete any checkpoints that you might have made before continuing.
- 12. From Hyper-V Manager, highlight the shutdown virtual template DC, click Export in the Actions pane to open the Export Virtual Machine dialog, choose a location for the VM to, as shown in Figure 28.4, and click the Export button.

When the export process has completed, you can choose to copy the exported files to another Hyper-V host (if you want to deploy the new clone DC there) or simply leave them where if you have only one host to work with.

- 13. Wherever you choose to locate the exported files, on the Hyper-V host, deploy the new clone DC, open Hyper-V Manager, and choose the Import Virtual Machine option from the Actions pane.

FIGURE 28.4
Exporting the virtual template DC

![](img/41a83208e6906a3732620203b836cea7_1440_0.png)

- 14. At the Import Virtual Machine wizard, click Next to move to the Locate dialog box, and then browse to the location of the exported files.
- 15. Click Next.
- 16. In the Select Virtual Machine dialog box, ensure the template virtual DC is selected.
- 17. In the Choose Type dialog box, ensure the virtual machine is selected, then click Next.
- 18. In the Import Settings dialog box, choose a location for the files, as shown in Figure 28.4, and click Next.
- 19. Click Next to move to the Summary page.
- 20. Once the import is complete, click Finish.
