# HYPER-V REPLICA PREREQUISITES

Your source and destination hosts must be running Hyper-V on one of the following
operating systems:

+   - Windows Server 2012 Standard/Datacenter edition
- Windows Server 2012 R2 Standard/Datacenter edition
- Hyper-V Server 2012 (this is the free one)
- Hyper-V Server 2012 R2

Both must have the same version of Hyper-V running for HVR to work, and you
cannot replicate a VM running on a host with Windows Server 2012 R2 to a host with
Windows Server 2012, for example. For authentication purposes, you must ensure that
both the source and destination hosts are in the same Active Directory. If not,
You will need to import X509 v3 certificates with the requirements outlined here:
http://blogs.tech.com/b/virtualization/archive/2012/03/13/hyper-v-replica-certificate-requirements

Once you have met the host requirements for HVR, all you need for the guest VMs is
ensure that they are running an operating system that is supported by Hyper-V 2012.
This means that you are not restricted to Windows Server 2012 or higher VMs for HVR, making
ite very attractive DR feature for older VMs.

# CAPACITY PLANNER FOR HYPER-V REPLICA

Trying to work out the impact of HVR on CPU, IOPS, and bandwidth can be a tricky
exercise without some additional help. Microsoft has released a utility that does just called
t“Capacity Planner for Hyper-Replica” (http://www.microsoft.com/en-us/download/
detetails.aspx?id=39857).

This utility will help you design the server, storage, and network infrastructure required
to maintain a healthy HVR deployment. All you need to do is download and run the tool from a
Windows Server 2012 Hyper-V host, and it will present you with a walk through the
initial configuration. In Figure 28.17, you can see where the wizard prompts you to enter
hostnames for primary and secondary servers or Hyper-V Replica Broker Client
Point (CAP) if you're using a failover cluster. You also need to estimate annWAN bandwidth and collection intervals.

When you've given your HVR host and bandwidth specifics, you select then
temporary location for the planner to create and replicate test VM. This test VM is used
to calculate the network deployment requirements between the primary and replica servers. After
you've entered all your information, the utility will calculate the capacity required and
will present you with a report similar to the one shown in Figure 28.18.

# SUPPORTED SCENARIOS FOR HYPER-V REPLICA

Not only can Hyper-Replica replicate between two non-clustered hosts, but it can also replicate
from a non-clustered host to a node in a Hyper-V cluster and versa. This can be useful if
want to ensure that a specific VM shipped out to a non-clustered host in your DR site.
