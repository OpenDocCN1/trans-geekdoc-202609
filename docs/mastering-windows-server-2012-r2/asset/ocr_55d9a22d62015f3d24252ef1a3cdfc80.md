# HOW IS THE ROUTING TABLE USED?

When an IP packet is assembled by an application and sent to the IP layer, its destination address is checked against the local subnet link address and mask of every network interface to see whether the destination address is local. You've already seen what happens if the address is local—the ARP or NDP is consulted and, if necessary, the packet placed onto the appropriate NIC for transmission to its target.

If the address isn't local, obviously you send it through a router. You will find a router to send the packet, and you will act as if the router's MAC address is the MAC address returned by an ARP query on your destination's IP address. In fact, in some strange instances, it is exactly what routers have been configured to do—respond to every ARP if the router is the host being searched for. That's a sign of a dysfunctional network, so we'll say no more about that.

How do you find the right route in the routing table? There are three simple criteria:

In the real world, this is analogous to saying that if you had two couriers to offer your package and deliver it, you'd skip the one who says, "I can get your package delivered to anyone in England," in favor of the one who says, "I can get your package delivered to anyone in the town of Enfield—the latter will get your package there much faster, because he's already local.

+   If there are two possible routing entries, the one with the lowest metric is chosen:

Metrics are rather arbitrary numbers, and their only purpose is to act as tiebreakers in this step of finding a matching route in the routing table. All that is necessary is to ensure routes to the same destination can be sorted by metric to indicate the network designer's preference for which router should be first.

+   If there is more than one matching entry, the first one in the list is chosen:

That that "the first one in the list" is rather difficult to control accurately. As a result, you should be careful to choose metrics appropriately so that you can always predict which route gets chosen.

Once the IP layer has a routing entry, as we mentioned earlier, it will send the packet to the router listed as the gateway in that entry. Of course, that means the IP layer must use ARP to determine which MAC address corresponds to the IP address of the router. Note that the destination IP address in the IP packet that is eventually sent to the router is the original destination IP address, not that of the router.
