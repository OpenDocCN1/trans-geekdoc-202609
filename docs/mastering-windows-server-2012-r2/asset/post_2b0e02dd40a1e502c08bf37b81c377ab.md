
# XML Paper SPECIFICATION

XML Paper Specification (XPS) is based on Extensible Markup Language (XML), an industry standard that has been steadily creeping into many current technologies including databases, web services, and printing. HTML (used for web pages) is based on XML. XML data is contained in a simple text document that can be read with simple applications such as Notepad, and can be used to hold a significant amount of data and metadata.

# XPS ON THE INTERNET

Microsoft has embraced XPS and has published a lot of material detailing how it is used in Microsoft products. The XPS home page is at www.microsoft.com/whc/xps/default.aspx. Additionally, ECMA is the driving force for standardizing XPS across platforms. You can access details from meetings and available documents at www.ecma-international.org/memento/TC46-N.htm.

Metadata is used to describe the data. For example, metadata within a print document might be used to identify all the data on page 1, 2, and so on. It could also be used to describe how the data should be displayed as the font style or size.

Microsoft has embraced the XPS document format based on the Open Markup Compatibility specifications and Open Packaging Conventions (OPC). The version is for much better efficiency, compatibility with applications, and higher quality when XPSdrv drivers are used.

XPS is similar to the Portable Document Format (PDF) created by Adobe Systems for document exchange. We're betting that you've opened a PDF document during your travels since PDF documents are so widely used. The cool thing is that the person who creates the document can control what it looks like when it prints. Compare this to a simple Word document that may print one by one on one printer but another on another.

You can create XPS documents from Microsoft Office 2012, and these documents can be shared as PDF files. Select As ➢ XPS Document to save your document in this format. Users who have an XPS view can view the documents, as users can view PDF files if they have a matching version of Adobe Reader. In addition to saving files as XPS, the documents can be translated to the XPS format so they can be used by XPSdrv drivers.

# XPSDR: THE NEW PRINTER DRIVER MODEL

Print drivers created advantage of the new XPS format are referred to as XPSdrv drivers. These drivers provide greater flexibility than the older Graphics Device Interface (GDI) graphics processing functions that were used before XPSdrv drivers.

XPSdrv drivers use the XPS document format to provide a better-what-you-see-is-what-you-get (WYSIWYG) output from printers. A greater range of colors can be used, and other graphic outputs such as transparent areas and gradients are possible.

Since the XPSdrv printer uses the XPS format and the XPS format produces smaller spooled files than the GDI, the overall size of spooled printer files is reduced.

# THE GRAPHICS DEVICE INTERFACE

GDI is the portion of the operating system that begins the process of producing visual output, whether that output is to the screen or to the printer. GDI has historically been used to produce WYSIWYG output to both the screen and the printed page. To produce screen output, GDI calls the video driver; to produce printed output, GDI calls the printer driver providing information about the printer device needed and the type of data used.

Although GDI-based printer drivers are being replaced with XPSdrv printer drivers, you may still come across the older GDI-based printer drivers for a while.

# Installing the Print and Document Services Role

The Print and Document Services role is added to your server when you want it to become a print server. When you add this role, you'll have the option of adding several different services depending on what you want the print server to do:

- Print Server: The Print service includes the Print Management console that you use for the majority of management tasks on the print server. You can manage multiple printers and even multiple print servers through this snap. This is the primary service of a print server and is the focus of this chapter.

- LPD Service: If your organization includes Unix-based computers that will need to print devices by your print server, you can add the Line Printer Daemon (LPD) service. The LPD service will allow any clients using the Line Printer Remote (LPR) service to print to printers shared on the print server.

- Internet Printing: The Internet Printing Protocol (IPP) can be used to allow clients that have the Internet Printing client installed to use a web browser to connect and print to printers shared on your server. Adding this service will also create a website where users can manage jobs on the server instead of using the console.

- Distributed Scan Service: This service allows the server to receive scanned documents from scanners on the network and route them to the correct destinations. When you add this service, it will also include the Scan Management snap-in.

# Adding the Print and Document Services Role

The Print and Document Services role is fairly simple to install using Server Manager. The only choice you need to make is what services to add, and this will be based on what the clients are doing. You can use the following steps to add the Print and Document Services role to a Windows Server 2012 R2 server:

- 1. Launch Server Manager by selecting Server Manager from the taskbar.

- 2. Click Add Roles and Features.

- 3. Review the information on the Before You begin page, and click Next.

- 4. Select Role Based Installation and click Next.

- 5. Select the server from the pool and click Next.

- 6. On the Roles page, select Print and Document Services; then Next.

- 7. On the Features page, select Features;

- 8. On the summary page, Print and Document Services as shown in Figure 16.2.

- 9. Click Next.

- 10. On the Confirmation page, click Install.

- 11. If everything was done, click Next.

- 12. When the installation has completed, click Close.

Once you've added the Print and Document Services role, you can access the PMC via Server Manager.

# Working in the Print Management

The Print Management console (PMC) is a great addition to the operating system, allowing you to do anything printer-related from a single console. It allows you to:

- Add new drivers
- View printers using custom filters
- Manage printer settings and drivers
- Monitor printer status and alerts
- Connect to remote servers

With the Print Management Services role added to your server, you can launch the PMC by hitting the Windows key and clicking Print Management.

### Custom Filters

The filters allow you to look at all the printers managed from this console, regardless of which print server they are connected to. If a print server hosts just five devices, this is no big deal. However, if you have hundreds of print devices, the ability to search using custom filters will make your job a lot easier. You'll see later in this chapter, the tool comes with some default filters, but you can also create your own.

### Print Servers

In 16.4, one print server (LabServer) is added. However, if your organization has several print servers, you can manage them all through a single PMC. Each server will have its own drivers, forms, and printers.

### Drivers

You can add drivers that are needed for your printers here. Drivers have been simplified into three types: for high-end servers, x64 for 64-bit operating systems, and x86 for 32-bit operating systems.

### Forms

The forms on a server show the various print layouts the installed printers support. They define the paper size and the printer area margins. The majority of most people use letter-size paper (8.5"x11"), and the letter form defines letter-size paper. However, there are many other forms that can be selected, and you can make your own. The forms are shown on a per-server basis, not a per-printer basis.
