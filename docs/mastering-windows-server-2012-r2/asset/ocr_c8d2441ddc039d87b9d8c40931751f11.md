Attaching domains to existing trees or forests is called grafting, and it can't be, at least not with the tools supplied by Microsoft. Thus, for example, if Exxon has Mobil and Exxon already has a name Exxon.com and Mobil has a name Mobil.com, it's not possible to join them in a tree with the supplied Active Directory tools.

And don't get anxious if you're not finding any third-party grafting tools. Microsoft doesn't support it. One of the biggest dearest from creating a solution that grafts a domain to a forest is the schema. The schema that defines objects within Active Directory can be modified, which we will discuss in the "FSMs and GCs". If two companies have their schemas in different manifolds, it would be impossible to develop a method to merge the differences. Another important reason not to graft a domain to a forest is security concerns. In the example names of the domain share "Test.com," but because they were not created, the security identifiers don't match. If you allowed grafting of .com into EastTest.com, you would have a significant hole in your security.

Pruning can't be done either. If you consolidate one of the forest and its company is off Test.com, the domain can't run independently from the rest of the domains. There's no little box to make this happen, and you would be missing all the security of the tree and hierarchy.

# You Must Be An Enterprise Admin

Another factor to remember is you can't just an average domain administrator to build another domain or two into your forest. You might have thought you could rule superbly with your domain credentials but you are mistaken. You need to be a member of the Enterprise Adm group.

If you create an AD domain named Test.com and want to create a child domain in its tree Eastcoast.Test.com, then you would log into the server that you wanted to be the first DC in Eastcoast.Test.com and create the Eastcoast.com child domain. The process for creating the child domain is similar to the way your original domain was built. You will still use the Active Directory Configuration Wizard for the creation, but you will make a few selections along the way.

Before the wizard lets you add another domain, it demands the name and password of an all-powerful enterprise admin for the Test.com domain. AD configuration will refuse to create a child domain unless it can contact the parent domain right at that moment and get permission. In the same way, if you want to create a second tree in the forest, the wizard will require you to tell it the name and password of an enterprise admin account for the first tree. (What about the third or fourth tree—what account do they need to provide? From the second to the million tree in a forest, you have to provide an enterprise admin account from the first tree in the forest.)
