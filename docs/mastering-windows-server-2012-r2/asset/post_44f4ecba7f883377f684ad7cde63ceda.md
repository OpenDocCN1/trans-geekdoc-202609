
Receive-Side Scaling (RSS) works well with web servers and servers, and it can be used to distribute the receive network traffic across multiple processors so that packets that belong to the same TCP connection are processed on the same logical processor. As NIC speeds increase (10 Gbps is a lot prevalent these days), so will the amount of processing that your CPUs have to handle. Without implementing RSS for very heavy workload servers with high network traffic loads, you run the risk of maxing out your CPU utilization and ultimately having to purchase new hardware. To take advantage of RSS, you, of course, need to have RSS-capable NICs in your servers.

### Server Performance Advisor Tool

If you're looking for something with a bit more than Perfmon.exe, you should take a look at the Microsoft Server Performance Advisor (SPA) tool; download version 3.0 from http://tinyurl.com/ws2012spa (you'll need Windows Live). The goal of this tool is to help system administrators troubleshoot their server issues. SPA provides data reports and recommendations to system administrators about common configuration and performance issues, and it gathers performance-related data from various sources on servers such as performance counters, registry keys, WMI queries, configuration files, and Event Tracing for Windows (ETW). Based on the server performance data it collects, SPA can provide an in-depth look at the current server situation and recommendations about what SPA 3.0 is designed to run on Windows Server 2012 and it is targeted at system administrators who manage fewer than 100 servers in various server roles. It can also be used by support engineers to gather performance data and troubleshoot performance issues for customers.

### SPA 3.0 LIMITATION

The Server Performance Advisor 3.0 tool does not scale well if you are trying to manage performance for more than 100 servers. If you are managing environments larger than this, then you should consider using System Center 2012 R2 Operations as the monitoring and management tool.

### INSTALLING SPA 3.0

SPA 3.0 has the following prerequisites that must be in place before you begin:

- .NET Framework 4
- SQL Server 2008 R2

Once you've met the prerequisites, follow these steps to deploy, configure, and run reports from the SPA 3.0 tool on Windows Server 2012:

1. Download the SPA_amd64.cab file and extract its contents to a location on your hard drive. A good tip would be to use WinRAR or WinZip to extract the cab file. In our experience, using the built-in Explorer to extract the files didn't create the correct folder structure and stopped SPA 3.0 from working properly.
2. From the location where you have extracted the files, locate SpaConsole.exe application, right-click it, and then choose the "Run as administrator" option to begin, as shown in Figure 4.12.
3. Accept the license terms in the Server Performance Agreement dialog box and then click Next.
4. From the Server Performance advisor console, click File on the menu bar and then choose New Project, as shown in Figure 4.13.
5. In the initial Wizard dialog box, click Next.
6. In the Create Project database box, enter your SQL Server name, and type a database name that you wish to assign to the SPA project. Then click Next.
7. Input the server names that you wish to manage with SPA in the Add Servers dialog box.
8. Specify the network share that will be used to store the reports, and then click Finish to complete the project setup, as shown in Figure 4.14.
9. Back at the Server Performance Advisor console, select the check box beside your server name, and then click the Run Analysis button to run the report.
10. Choose the advisor parts that are relevant to the server you are running the report against for Core OS, Hyper-V, or IIS advisor needs; then click OK twice.
11. Once the analysis has finished, you can then view the report contents through the Report Viewer, as shown in Figure 4.15.

The caveat is that IPv4 and IPv6 cannot natively talk to each other, and for the duration of this transitional period a solution is required to address the communication barriers between these two protocols.
