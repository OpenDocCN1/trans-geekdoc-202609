这些权限按照规定为“读取和执行”。不多于此，不少于；这些原子权限构成了“读取和执行”。请将其视为准则。

你可能已经注意到，“用户（Users）”组条目中的“应用于”下拉列表也是不可用的。你无法由于继承而移除它，这是继承的另一个结果。你可以将继承视为一种来自高层级的指令。这些权限将应用到此文件夹、子文件夹和文件，除非你禁用继承并创建自己的自定义权限。你可以直接追溯源头，因为作为管理员，在涉及继承时，你就是规则。如果你打开卷的属性并编辑“用户”组的条目，你可以删除或修改权限，然后通过点击“应用”按钮将它们精确地设置在你所需的整个卷的任何位置。

# 管理权限 72

“用户”组的默认权限包括在卷上创建文件和文件夹的能力，以及对该卷内包含的文件写入数据和追加数据的能力——除非，当然，你专门对卷上的任何特定资源禁止了这些操作。因此，你在这里拥有的是一组介于之前讨论的两个分子组之间的权限。你为“用户”组看到的第一组原子权限构成了“读取和执行”分子权限。如果你添加了这两个权限，该分子权限将落在“读取和执行”和“修改”之间。完整来说，“修改”权限还包括“写入属性”、“写入扩展属性”以及“删除文件和文件夹”权限。

出于两个原因，两种解决方案中更容易的是使用“拒绝（Deny）”函数：

- 第一，你不需要担心来自卷的其他继承权限，其中某些是你需要保留的。移除继承时，你将获得复制继承权限的权利，并可以按意愿进行编辑。
- 第二，通过移除继承，你取消了在全局范围内从卷推发权限的能力，这是一个非常实用的功能。正如我们之前说的，如果你能通过全局范围的操作来简化权限，就可以节省大量的时间和精力。

要禁用“用户”在 APPS 文件夹上创建文件或文件夹或写入追加数据的能力，只需为这两个原子权限条目选择“拒绝”复选框（见图 14.19），并点击“确定”。

# 冲突权限

你可以为文件分配权限，也可以为目录分配权限。正如权限可能与文件和目录权限冲突一样，文件权限也可能与目录权限发生冲突。在共享级冲突中，共享胜出：共享级权限设置了最大允许访问权限，因此如果共享级权限是“读取”而 NTFS 权限是“写入”，那么结果只有“读取”。如果你为目录分配了只读权限，但为目录内的文件分配了更改权限，你仍然能够更改该文件。

# 多重权限

现在是另一个问题。你已经给了“管理员（Administrators）”组对 APPS 文件夹的控制权，而其他人只有“读取和执行”权限。这就是权限可能冲突的地方。每个人都是用户，对吧？即使管理员也是用户。嗯。这是如何运作的？嗯，在多重权限的情况下，只要不涉及共享权限，限制最少的权限占优先。假设我们有一个名为 Bob 的管理员。他是“用户”组的一部分，该组拥有只读权限。Bob 也是“管理员”组的一部分，该组拥有完全控制。在这种情况下，Bob 将获得完全控制，因为它是限制性的。

# 拒绝权限

我们之前讨论过共享的拒绝权限，然后简要讨论了继承权限对于“允许”和“拒绝”的影响。同样的情况适用于文件和目录权限，只是由于安全选项数量增加而变得复杂一点。想象一个你试图保护的公司奖金表格文件。你想让每个人看到文件，但只想让经理能够实际更改。这很合理：赋予“用户”组读取权限，赋予“经理”组完全控制权限。想象在某个地方，低级主管属于这两个组，但在某些方面更像“用户”。如果按照描述设置权限，该主管将获得兼得——完全控制。由于这个原因，你决定不想让用户拥有完全控制。现在怎么办？

很简单：只需拒绝那些多余的权限。你需要确定具体不希望用户拥有的哪些权限，并在“拒绝”列中选择它们；这可以确保用户只获得读取权限。要执行此操作，请遵循以下步骤：

- 1. 右键点击文件。
- 2. 转到“安全”选项卡，然后点击“高级”。记得图 14.15 中的界面吗？
- 3. 从此处，高亮“用户”组条目并点击“编辑”，这将允许你修改表格的原子权限。
- 4. 从“类型”下拉框中选择“拒绝”，然后点击“显示高级权限”按钮。
- 5. 选择图 14.20 中所需条目的属性复选框。
