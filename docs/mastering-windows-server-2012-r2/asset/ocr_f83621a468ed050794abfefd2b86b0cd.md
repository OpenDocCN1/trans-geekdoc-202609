Network Adapter virtual connections are managed by the Network adapter dialog box. For NIC, you can select any virtual switch from the drop-down menu. You can change the binding while the VM is running, which can be quite a hard feature to have. From the VM point of view, this is like pulling the cable from one switch and plugging it into another. One for it is to install the operating system, patch it on Windows Update, and connect it to an another switch for switching.

Expanding the Network Adapter option gives you the following two options, as shown in Figure 27.34:

Hardware Acceleration This is where you can perform different tasks to be offloaded to a physical network adapter. First here is "Virtual machine queue," which binds the MAC address of a virtual NIC to a queue on a physical NIC, optimizing network traffic for your VMs.

Next in the list is "IPSec traffic overloading." This allows you to offload the processing of your IPSec traffic encryption and decryption to hardware to free up resources on the host.

The final (and most intriguing) acceleration option is "Single-root I/O virtualization (SR-IOV). Take advantage of this feature, you will need dedicated hardware, but the rewards are worth if you take the time and money to invest. The idea of SR-IOV is to replace the virtual switch in your VM connectivity and route traffic directly to a special SR-IOV physical NIC connected to the host. This means far greater improvements in CPU utilization, network latency, and network throughput. You can enable SR-IOV, as shown in Figure 27.24, and if you want to learn more, check out this blog post series from Microsoft's John Howard: http://ln/ws2012SRIOV.
