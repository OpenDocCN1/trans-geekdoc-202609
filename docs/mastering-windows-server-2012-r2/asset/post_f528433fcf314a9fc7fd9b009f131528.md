# Understanding Regular Expressions

I promised to give you a quick demonstration of regular expressions. This is something you should ask experienced programmers or telephony engineers because they are wizards at this stuff and usually have a great ability to construct exceptionally complex but useful expressions.

Also, in your favorite search engine for "Regular Expression Cheat Sheets," there are a few cool links available that you can use as reference. With most things, regular expressions won't make sense until you use them for something. Say let's look at a basic example. Say you want to detect a credit card number. First, you should look at what a credit card number has, and the simplest one to start with is that it has 12 numbers. In order to detect a 12-digit number with regular expressions you would have a query like:

```\d{12}```

# CLASSIFICATION 819

If you break this down, very simply \d means "detect a digit" and {12} means "exactly 12 characters long."

Another way of writing this if the credit card number is stored like 1234-1234-1234-1234 is:
\d{4}-\d{4}-\d{4}

Simple won't have many 12-digit numbers that are not credit cards in your environment classified with this basic rule. However, we can get a bit focused. For example, let's say Visa cards start with the number 4 and then use a combination of 11 other digits. What would the regular expression for that look like?

```\d[4]{11}```

Here it is in standard credit card format:

```\d{4}-\d{4}-\d{4}```

Hopefully these pieces of information are protected, and then let's build another regular expression. We will also reuse the example when integrating into our Dynamic Access Control.

# Securing Data Using DAC and File Classification

For the final piece of this chapter let's examine a real example you will come in the workplace. Most businesses deal with credit card numbers at some point and it is the company's responsibility to ensure this data is secure. Hopefully these are stored in encrypted databases in the real world, but in our example company, Contoso, they have been storing them in Word documents.

We need to safeguard not only the company but also the information we share and we don't want engineers logging on the file share and being able to copy the credit card number. That would be disastrous.

With all this in mind here's what we are going to do:

- Create an RTF file with a credit card number in the content.
- Create an RTF file with the word payroll in the content.
- Create an RTF file with the words Intellectual Property in the content.
- Create a classification rule to detect these attributes using regular expressions and a string in the content.
- Create a Dynamic Access Policy that will use the file classification to secure the resource.

Okay, let's go. First, create the three documents you need:
