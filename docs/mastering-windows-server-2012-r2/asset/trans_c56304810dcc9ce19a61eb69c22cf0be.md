

**私有**：通过私有虚拟交换机，虚拟机（VM）之间相互连接，但无法看到主机。实际上，它们完全与物理网络隔离开。这种想法对于测试再次很有用。例如，当你测试 Windows Server 2012 R2 的 DHCP 功能时，你不希望在物理网络上进行尝试。在某些情况下，私有交换机是测试的最安全选择。

虚拟交换机的一个有用特性是你可以更改它们的范围和功能。你可能先创建一个内部交换机，稍后再将其连接到物理外部网卡。

使用虚拟交换机为你的虚拟机带了极大的灵活性，你可以在主机内部生成相当复杂的网络。例如，使用三个虚拟交换机，你可以构建一个经典的 DMZ 设置：一个用于连接到物理网卡的外部接口，一个用于 DMZ 主机，还有一个用于内内部局域网（LAN）。

## 创建虚拟交换机

配置虚拟网络有两种路径：虚拟网卡和虚拟交换机。虚拟网卡通过虚拟机设置窗口管理（我们稍后会讨论），而虚拟交换机则通过虚拟交换机管理器（Virtual Switch Manager）配置。

要创建虚拟交换机，你需要遵循以下步骤：

- 1. 打开 Hyper-V 管理，并在操作面板中点击“虚拟交换机管理器”。
- 2. 如图 27.21 所示，点击选择“新建网络交换机”选项。
- 3. 在“虚拟交换机”部分，选择你想要创建的虚拟交换机类型（外部、内部或私有），然后点击“创建虚拟交换机”按钮。

在图 27.22 中，选择了虚拟交换机 VMEXT1。该交换机是在安装 Hyper-V 角色时创建的，并向向程序指示使用哪些网卡用于虚拟机流量。回图 27.11 以查看这意味着什么。

默认启用的还有“允许管理操作系统与此网络适配器共享”选项。保留此项意味着主机可以访问此交换机，这意味着虚拟机与其主机操作系统之间的流量是共享的。在可能只有一个可用网卡的实验室或非生产环境中，保留此选项应该足够了，但如果你有多个网卡或运行生产 Hyper-V 环境，建议通过取消勾选框并点击“应用”来禁用此选项。

- 4. 如果你想创建一个新的虚拟交换机而不是使用你在 Hyper-V 设置期间创建的那个，在“虚拟交换机属性”面板中更改交换机名称，并从下拉菜单选择你将连接的特定网卡。

如果你有许多物理网卡，这里可能会让你困扰：呈现的是网卡设备名称列表，而不是可能在“网络连接”应用中为网卡提供的初始描述。这使得很难识别你想要分配给新虚拟交换机的是哪个网卡，但如果你在 PowerShell 中使用 `Get-NetAdapter -Format-Table -Autosize` 命令，你可以看到映射到更具描述性的友好名称的网卡设备名称列表。

- 5. 一旦你选择了虚拟交换机类型并对其进行了配置，点击确定按钮完成该过程。

## PowerShell 技巧

你可以使用 PowerShell 中的以下命令创建一个不与管理操作系统共享连接的新型虚拟交换机：
`New-VMSwitch -Name "VMEXT1" -AllowManagementOS $false -NetAdapterName "Local Area Connection 2"`

## 开始使用虚拟机

- 1. 打开 Hyper-V 管理并选择“新建虚拟机”。
- 2. 为虚拟机指定名称。
- 3. 选择代（第 1 代用于旧版 BIOS，第 2 代用于现代 UEFI）。
