# CHAPTER 2 INSTALLING AND UPGRADING TO WINDOWS SERVER 2012 R2

# 64-Bit Support

Windows Server 2012 is available only as a 64-bit product. We'll reinforce that: there are no x86 or 32-bit versions of Windows Server 2012 R2.

Here are some notes on deploying x64 servers:

+   Your hardware support for x64 is not a huge issue: The major vendors have been selling x64 processors for years for your mainstream products. You can do a quick audit of your server hardware and check for 64-bit support.

+   A lot of 32-bit applications should be able to run on the x64-only Windows Server 2012 R2: This is thanks to 32-bit emulation provided by the Windows-on-Windows (WOW32) subsystem. Don't count on this; please check with application vendors, and test in a lab before making plans to upgrade servers from Windows Server 2008 to Windows Server 2012 R2.

+   You cannot upgrade from x86 to x64: This precludes upgrading from an x86 installation of Windows Server 2003 or Windows Server 2008 to Windows Server 2012 R2. Getting your servers from x64 will require a migration plan from one physical server to another.

+   64-bit builds of Windows require signed kernel mode drivers: Sure, the operating system will allow you to install those drivers with a warning, but they will never actually load. Make sure your hardware vendor provides signed x64 drivers for Windows Server 2012 R2. We often see people complaining about driver issues, but this is really something that your hardware vendor is responsible for. Printer drivers do appear to be something in particular to watch out!

As any project, preparation is the key to success. Review the hardware requirements, and check out compatibility before moving forward with any deployment of Windows Server 2012 R2.

# Real World Scenario

# SO, WHAT ARE YOU TO DEPLOY?

Many who deployed Windows Server 2008 know that x86 support from Microsoft in the datacenter was ending. They deployed x64-builds wherever possible. They did the same for their customers. Key products like SQL Server 208 have native x64 editions. When deploying Windows Server 2008, they were already doing an operating system deployment project, they decided this was the best time to make 64-bit jump. Sure, there are times when they have been forced to use x86 builds because of third-party application vendor support supports. That'll mean there will be a migration at some later point.

Check the hardware, drivers, application vendor support, and printers. Everything in a lab. If all is well, then deploy that server as Windows Server 2012 R2 depending on your licensing and your project aims.

For a lab, you might want to look at Microsoft's virtualization solution, Hyper-V. Hyper-V is included as parts of Windows Server 2012 R2; run virtual machines with x64 or x86 operating systems, Xen-enabled Linux. Hyper-V also requires CPU-assisted virtualization and Data Execution Prevention (DEP) to be turned on in the BIOS. We recommend taking advantage of this technology (or even one of the competitors if you prefer them). You can learn more about Hyper-V later in this book.
