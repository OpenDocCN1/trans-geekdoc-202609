Installing the role in this way creates a solitary DNS name server that is only talking with the Internet root servers. It can support a LAN environment for resolving DNS names, but that is about it. The Domain Name System leverages other DNS servers to resolve names throughout the DNS structure. For this reason, you'll have to configure your server to talk with other DNS servers that exist in the network. Although configuring your DNS server in a standalone non-domain configuration has its merits (as deploying in one environment where managing multiple static HOST files across servers becomes a pain), you will really see the power of Windows Server 2012 R2 DNS when you use it with Active Directory.

# Integrating with Other DNS Servers

“Understanding the DNS Server Role,” mentioned that there are different methods for resolving DNS names, such as forwarding, recursion, and delegation. These methods are related to the integration with other DNS servers. Before we get started, remember that iteration is basically client driven. If the DNS server does not have an answer, the client will go to another DNS server. Or the server can be configured for iteration, but only it is the default and is rarely implemented. The other three—forwarding, recursion, and delegation—involving other DNS servers by the queried DNS server.

Recursion is the primary process occurring on the Internet. The DNS query starts at the top and works its way down until it receives from each DNS server it connects to. In Windows DNS servers, the top servers are listed on the Root Hints tab of the DNS server properties, as shown in Figure 6.7. You can display this in the DNS Management snap-in by right-clicking the server icon and selecting Properties. By default, it is powered with “live” Internet DNS servers.

In single Active Directory domain environment, you can leave this alone. DNS servers can use these features to resolve Internet-based namespaces by Sybex when a client requests it. In larger environments, you can remove the root hints on other DNS servers and rely on one for DNS support resolution through the external environment. It would essentially be the caching DNS of the internal structure.

While root hints manage the queries going down the hierarchical structure, delegation manages queries going upward. In our example, the DNS servers that control the .com namespace delegate the control of registered subdomains to Sybex. The delegation .com name server sends the list of servers to a DNS server looking for Sybex.com addresses.

In a Windows environment, you can see delegation in multiple Active Directory domains. If you have an Active Directory domain named Bigfirm.com, you have an associated Bigfirm.com DNS namespace. You can create an Active Directory domain named Ecoast.Bigfirm.com. Instead of delegating all, you can create a delegation.
