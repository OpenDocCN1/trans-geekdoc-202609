# # Administering the DNS Server with the DNS Management Console and PowerShell

To administer DNS servers, we have touched on two tools: the DNS management console, which is an MMC snap-in, and PowerShell, which is, a shell-based command-line tool. PowerShell offers the capability of administering the server like the MMC and offers a little more functionality. For example, as you learned, the DNS management console doesn't offer a method of modifying the query block list or creating directory partitions.

Throughout the chapter, you have seen the DNS management console used to create zones and edit the properties of servers and zones, which are the run-of-mill types of tasks you do with it. You can also take advantage of some diagnostic configurations within the console. These are configured in the properties of the DNS server.

**Event Logging** Separate Event Viewer log is created for the DNS service. It is attached to the DNS management console. In order, the server collects all events by default, which is set via the Event Logging tab.

**Debug Logging** More detailed logging of the actual occurrence on the DNS server can be gathered for inspection. Debug logging is disabled by default but can be enabled from the properties of the DNS server; Figure 6.31 shows the Debug Logging tab. This feature is valuable if the DNS server is not acting reliably. Although most DNS issues are resolved with IP connectivity, you will find this tool useful when IP connectivity is determined not to be the case. On rare occasions, we have had to verify whether specific requests hitting the server, and this provided the information.

**Monitoring** This tab can also be accessed from inside the DNS server properties and is displayed in Figure 6.32. It's the equivalent to the million-dollar machine that says "ping!" It's a blinking light. It can test DNS queries from this server or another server—not a specific server, just any indriminant server you choose.

The output is pass or fail. Basically, if the DNS server is having problems, it's a fail. We've found not comfort or valuable data in resolving DNS issues on this task, and most likely won't tell you anything new. We recommend using something like Microsoft's System Center 2012 R2 Operations Manager for monitoring your DNS servers, and this topic is discussed in Chapter 30.
