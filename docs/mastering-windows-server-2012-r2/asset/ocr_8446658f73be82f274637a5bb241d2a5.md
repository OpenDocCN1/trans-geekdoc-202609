The global migration state is set with the dfsmig command-utility, which is used for setting one of the phases of the migration process. This setting is made in Active Directory and is then replicated to all domain controllers. Each domain controller has its own local migration state. DFS-R on each DC polls Active Directory to determine the global migration state. If the global migration state is different from the local migration state, DFS-R will attempt to move the local state to any one of the transition states. The SYSVOL proceeds through four primary states (usually called stable states) and six temporary states (usually called transition states). The transition states lead a DC to the stable states.

There are four stable states, or phases, to SYSVOL migration from FRS to DFS-R. The states are called start, prepared, redirected, and eliminated. They are also referred by ordinal numbers from 0 to 3,

+   **Start (state 0)** Before the SYSVOL migration begins, FRS replicates the shared SYSVOL folder.

+   **Prepared (state 1)** FRS replicates the shared SYSVOL folder that the domain uses, DFS-R replicates a copy of the shared SYSVOL folder. This copy of SYSVOL is not used to serve requests from other DCs.

+   **Redirected (state 2)** The DFS-R copy of SYSVOL becomes responsible for serving requests from other DCs. FRS continues to replicate the original SYSVOL folder, but DFS-R replicates the production SYSVOL folder that the DCs in in the redirected state.

+   **Eliminated (state 3)** DFS-R continues to handle all the SYSVOL replication. Windows deletes the original SYSVOL folder, and FRS no longer replicates SYSVOL data.
