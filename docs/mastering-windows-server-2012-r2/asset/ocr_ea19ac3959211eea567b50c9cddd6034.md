# CREATING AND MANAGING USER ACCOUNTS

The options here are pretty self-explanatory and work just like those in the local user account. We described them earlier while showing how to create a local user account. A common mistake here is to enter a password that meets your defined complexity requirements. The default settings are defined in the Default Domain Policy. You have customized these with another policy object. You will not be able to complete this wizard without meeting the requirements.

+   8. Finish the wizard to create the user.

You can see in Figure 8.8 that the user is created and it is located in the \BigFirm\Users OU. That's pretty simple, right? Let's take a look at how you can do the same thing from command line.

![](bbox=[0.19, 0.31, 0.855, 0.626])

The first command you'll look at is dsadd. The following command will re-create what you've just done in the GUI:

```
dsadd "CN=Steve Red,OU=Users,OU=BigFirm,DC=bigfirm,DC=com" -samid SRed -upn SRed@bigfirm.com -fn Steve -ln Red -display "Steve Red" -pwd Hydogisblu3-mustchpwd yes
```

Wow! That's quite a command. Here is the syntax:

```
dsadd user <Distinguished Name of the user> -samid <user logon> -upn <principal name> -fn <firstname> -ln <surname> -display <full name> -pwd <password> -mustchpwd the user must change their password on first login: yes no
```

What's with that distinguished name (DN) thing? The DN describes where Active Directory the user object is created and how it is made. The DN in our case is: CN=Steve Red,OU=Users,OU=BigFirm,DC=bigfirm,DC=com. That breaks down as follows:

Component Name (CN) This is the name of an object. In this case, it is the name of the user account.
