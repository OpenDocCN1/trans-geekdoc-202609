The following are the fields on the tab:

**Serial Number** is the revision number of the zone file. This really counts with standard primary zones because the Active Directory replication has its own serial number, so to speak. Secondary zones compare their number with it to see whether their information is up to date. If it isn't, it's time for a zone transfer.

**Primary Server** is this server in the zone which was initially up. You can switch a primary server to a secondary server and vice versa if you want to modify replication updates in your environment.

**Responsible Person** This is supposed to be an email address of the person who administers the zone. Note that the @ is replaced by a dot (.). If you want to make someone really mad, you put their email address here!

**Refresh Interval** is how long the secondary server can wait before attempting to check changes on the primary server. At this point of time, it compares the serial number of the SOA record with its own. By default it is 15 minutes. The value is in seconds within the actual record.

**Retrial Interval** How long the secondary server wait before trying after a failed zone transfer? It is in seconds and defaults to 10 minutes.

**Expires** How long can the secondary server continue to answer requests on after a zone transfer performed? The default is one day. This is also listed in seconds within the record, and the value is 86,400.

**Minimum (Default) TTL** How long should these records be cached or, in other words, the Time's Time To Live (TTL) is an hour, or 3,600 seconds.

# NAME SERVER RECORDS

Name server (NS) records list the servers that can respond to queries for this zone. There will be at least one of these records in the zone. Like the SOA record, this is modified in the properties of the zone on the Name Servers tab, as shown earlier in Figure 6.5. The only value required in the NS record is the FQDN of the server. You will notice a notice at the bottom of the Name Servers tab stating that the IP address is retrieved value.
