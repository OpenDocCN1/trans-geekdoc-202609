As we wrap up with the Active Directory Administrative Center, there are a few remaining things:

+   * ADAC can be installed only on Windows Server 2012 machines and Windows 8 computers running the Remote Server Administrative Tools (RSAT).
* You can manage domains in your forest or in other forests where a trust exists and you have the appropriate permissions.
* In the navigation pane, you can right-click the domain name to connect to different controllers.
* You might do this to work on a domain controller in another site, such as to do some work for local users and get immediate results without waiting for replication.
* Active Directory Web Services (ADWS) must be installed on at least one domain controller in the use of ADAC to manage that domain.

If you install a Windows Server 2012 domain controller, ADWS is installed and started automatically. It provides a web service interface for managing Active Directory tools such as ADAC and PowerShell.

In the ADAC's Getting Started content in the Administrative Center Overview section you will find hyperlinks to online content for ADAC and the new PowerShell modules for Active Directory management using PowerShell.

# PowerShell History Viewer

You may have noticed that there is one section in ADAC called PowerShell History Viewer. It's mostly hidden, and if you are not aware of it you will easily work with ADAC without ever knowing about it. For PowerShell History to show up you will need to click the down-arrow button, as shown in Figure 8.79.

In Figure 8.79 there is a new user Chris Greuter. Immediately after you click OK in your user-creation dialog, the PowerShell History gets filled with PowerShell cmdlets. For example, creating a simple enabled user with the minimal input, five different cmdlets are fired. If you look at these commands, you will see that they take these steps:

+   * New-User sets up the skeleton for the user object without a password. Therefore the account is disabled.
* Set-ADAccountPassword sets the user password.
* Enable-ADAccount enables all account options found on the Account tab of the user object's properties pages. These options are for such things as whether the user can change the password or whether the user's password expires.
* Set-ADAccountControl sets all the AD account options found on the Account tab...
* Set-ADUser sets additional user options such as whether the user needs to change the password at logon or whether smart card login is required.
