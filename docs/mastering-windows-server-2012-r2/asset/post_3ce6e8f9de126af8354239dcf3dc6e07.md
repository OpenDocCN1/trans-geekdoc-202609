## Configuring WSUS for Deployments

Once the installation of the WSUS server role is complete, you can launch Windows Update Services (shown in Figure 31.9) from the Start screen and begin your configuration.

FIGURE 31.9 Windows Server Update Services on your Start screen
![](img/41a83208e6906a373262023b86cea7_1575_0.png)

To begin the configuration of your WSUS, you need to configure the updates required for your environment. Once the Update Services console has opened, you will be presented with the Windows Update Configuration Wizard; this wizard will walk you through the steps to get updates configured for deployment. As the wizard starts, the first screen you see is Begin; this has a couple of items you need to make sure of before starting this process:

- Is this computer configured to allow clients to the server?
- Can this computer connect to the upstream server (such as Microsoft Update)?
- Do you have credentials for proxy server if needed?

After you have validated that you have the appropriate items set up, follow these steps:

1. Begin the initial configuration of Windows Update Services by clicking Next.
2. Once you've decided whether to join the program, click Next to continue.

You will be prompted to join the Microsoft Update Program—you can leave the box unchecked if you desire. You'll need to choose your upstream server, and you will utilize Microsoft Update if this is your first server. Any additional servers you add later can point to this server to synchronize. For this example we will be utilizing Microsoft Update as our synchronization partner.

## DEPLOYING UPDATES AND MIGRATION FOR WINDOWS SERVER UPDATE

You must be running one of the following operating systems to receive updates: Windows 8, Windows 7, Windows Server 2012 R2, Windows Server 2008, or Windows Server 2003. Windows 8 RT is also supported in a limited capacity.

Utilizing Group Policy is the most common approach for managing Windows Update. For this example we are creating a brand-new GPO and applying it to the Workstations Organization Unit in Active Directory, as shown in Figure 31.16.

FIGURE 31.16 Group Policy management
(Note: Image link for 31.16 was missing in OCR text, but context indicates it)

To configure Windows update settings, follow these steps:

1. Right-click the Group Policy object and select Edit to open the Group Policy Management Editor.
2. In the Group Policy Management Editor, navigate to Computer Configuration\Administrative Templates\Windows Components\Windows Update.
3. Double-click Configure Automatic Updates, and then select the Enabled option, as shown in Figure 31.18.
    a. For the "Configure automatic updating" box, select the appropriate setting. The choices are "Notify for download and notify for install," "Auto download and schedule the install," or "Allow admin to choose setting."
    b. If you choose "Auto download and schedule the install," you must enter the day and time for which the updates are scheduled.

FIGURE 31.18 Configuring automatic updates
![](img/41a83208e6906a373262023b86cea7_1581_0.png)

4. Next, choose the "Specify intranet Microsoft update location" option. Here you are going to point the WSUS clients to the WSUS server:
    a. Select the Enabled option.
    b. In the "Set the intranet update service for detecting updates" and "Set the intranet statistics server" boxes, type the name of the WSUS server.
    c. Click OK.
