Advanced Features In the Network Adapter Features shown in Figure 27.35, you have the option to use a dynamic or static MAC address. Hyper-V manages its own pool of MAC addresses, unless you encounter a MAC conflict, you should probably leave this setting at Dynamic:

Then there's the "Enable MAC address spoofing." That sounds like a bad thing, doesn't it? It was the only behavior available when Hyper-V was first released. In one compromised VM could flood flooding the switch or impersonate another VM. Hyper-V is far safer. The virtual switch learns which MAC address belongs to which VM and doesn't allow it to change its MAC address. Usually this isn't a problem, except for those situations where you really need multiple MAC addresses. Can't think of one? Consider network load balancing or failover clustering.

If you have problems in your production environment with administrators deploying unauthorized DHCP servers, then you don't need to tell them it can lead to an administrative nightmare of invalid IP addresses. The "DHCP guard" option comes in. If you enable it, your VM will stop answering DHCP clients through this specific network adapter.

"Router guard," and it will prevent your VMs from sending out rogue redirection to the network from this specific network adapter.

If you're running a Hyper-V failover cluster and enable the "Protected network" option, your VMs will move to another node if they detect a network disconnection, therefore ensuring network availability for your services.
