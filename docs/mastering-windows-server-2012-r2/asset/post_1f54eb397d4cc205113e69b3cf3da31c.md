
## ENABLING HYPERV-REPLICA

Now that you have an understanding of what HVR is, in this section we will walk through configuring a replication of VM between two non-clustered Hyper-V hosts running Windows Server 2012 R2. We will use VMHOST1-SRV as our source server and VMHOST2-SRV as the destination server. Both hosts in this example are part of the same Active Directory forest and can resolve each other's names across the WAN. By default, HVR is disabled, and you will need to enable it on the destination server.

- 1. On the destination server, open Hyper-V Manager with an account that has administrative permissions, right-click the host, and select Hyper-V Settings from the context menu.
- 2. Click Replication Configuration from the Server column; then select the "Enable computer as a Replica server" check box, as shown in Figure 28.19.

Notice the two different authentication options for Kerberos and certificate-based authentication: because we are using Active Directory to authenticate, Kerberos is fine in this case.

## CONFIGURING VM REPLICATION

Once you have enabled Hyper-V, you then need to configure VM replication. This is enabled on an individual VM. When you initiate replication for a VM, you will need to choose how the initial “seed copy” will be created. Since this initial copy will be quite large (depending on the size of the VM being replicated), you have three different synchronization methods to choose from:

**Send Initial Copy over the Network** This is the most straightforward option to choose for your initial copy, but it's dependent on having a pretty good upload link from your production site to the DR site. If you don't have a dedicated WAN connection for replication between sites, this may not be the best option to choose. This method is popular, though, if you are creating the Hyper-V Replica connection while the production and DR hosts are on the same site—possibly as a temporary measure to support your initial process.

**Send Initial Copy Using External Media** With this option, you can create an export of a VM and then store it on external media such as a USB drive. You then bring the media to the DR site and import the copy onto the destination server. This is a great option for organizations that have WAN links with bad upload speeds and would otherwise need to spend weeks copying the replicas to the DR site.

Remember to encrypt your removable drives before creating the copy and transporting them because they will contain very sensitive data that you don't falling into the wrong hands.

**Using an Existing Virtual Machine on the Replica Server** An intriguing final choice for your initial copy is the potential to use an existing VM that might be restored from an offsite backup solution like DPM and import into the destination server. When you enable replication on the restored VM, HVR synchronizes with the source host across the WAN.

Be careful with this option, though, because if you restore a VM from your backups and bring it online at the same time as the original VM in the production site, you'll quickly run into problems.

In the following steps, you'll use the first option to create your initial copy over the network.

- 1. On the source server (VMHOST-SRV), open Hyper-V Manager with an account that has administrative permissions, right-click the VM you want to replicate, and select the Replication option from the menu.
- 2. In the Select Replica Server dialog box, type the name of (or browse for) the destination server that you previously enabled HVR on.
- 3. Choose the authentication type for your VM replica or leave the default settings in place; click Next.
- 4. From the Choose Replication VHDs dialog box shown in Figure 28.1, select the VHDs that you want to be replicated and deselect any that you don't need, as dedicated paging file VHDs; click Next.
- The next dialog box allows you to choose the frequency at which changes will be sent to your destination server. Your options are 30 seconds, 5 minutes, and 15 minutes.
- 5. Click Next when you've made your choice.
- 6. In the Configure Additional Recovery Points dialog box, choose to store only the latest recovery point of the replicated VM, or create additional recovery points to have the option of recovering the VM to an earlier point.
- 7. Click Next to continue.

From this menu, you can perform the failover tasks:

**Unplanned Failover** An unplanned failover is not to be carried out, and it assumes that the production VM cannot be contacted anymore as a result of an unexpected outage or disaster. You can simulate an unplanned failover by turning off the production VM, right-clicking the replica VM on the destination host, and selecting the Failover option. From there you can choose the relevant recovery point.

**Test Failover** A test failover creates a copy of the VM by cloning and storing the clone on a differential disk using the replica VM's storage as its parent. Because it uses the replica's storage, it will save the differential disk in the same volume as the replica; ensure you have enough disk space on this volume if you intend to keep the test VM up and running for an extended period of time. This test process allows you to verify if your recovery points are up to date and when you should need to use them in a DR situation.

**Pause Replication** This option does exactly what it says on the tin. You will use this if you want to pause replication between the destination and source hosts for a particular VM. When you've paused replication, this option changes to Resume Replication, which you can use to restart the process when you're ready.

**View Replication Health** This option will provide you with statistics on the health of your replicated VM, as shown in Figure 28.24. You can get some useful information here including things as data size, latency, errors encountered, and last sync time. It's always a good place to start when troubleshooting HVR replicas.

**Remove Replication** Another obvious option here. If you wish to remove replication for a particular VM, then this is what you need to choose. You must select this option on both the source and destination VMs to fully remove replication.
