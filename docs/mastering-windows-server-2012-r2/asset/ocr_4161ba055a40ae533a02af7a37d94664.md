# Access Control Using Groups and User AD Attributes

As you saw in the previous section we could select a principal (and remember, a principal could be a user or group) and assign a condition, then based on the condition, access will be granted or denied. This leads to an age-old problem of administration of groups.

Think about it. In an enterprise or even a small business, how do folks in Active Directory get dealt out, and how are privileges for the existing user base based to ensure they are still valid? Should someone really be part of the IT group now that they are a truck driver? What if you now, for example, change the Department field in the user account in Active Directory, and it would change the access permissions?

Active Directory stores lots of information with different tags to identify the data, attributes. For example, when you create a user account, the most basic information you would be the first name and last name of the person. This information is stored in an attribute in Active Directory. These attributes can be reviewed and edited (but do careful because it is not pretty if you mess up). Figure 15.9 shows a sample of attributes; in this case we are viewing the given name (first name) for the user David McCormick.

A very useful attribute you can use to help secure information is the Department attribute. As you see in Figure 15.9, our user David is part of the IT group. We contains lots of sensitive information, and we certainly don't want usernames and passwords or sensitive network information falling into the wrong hands.
