For, example, make Apex.com and Test trust each other, let's suppose that Apex .com has a domain name admin apex.com with password @apex.com and Test has a domain name adminTest with password T3$ .com. On the Test domain controller, the following command is:

```
netdom apex.com /domain:Test.com
/User:testAdmin/Password:T3$.com
/User0:apexAdmin/Password:@apex.com
/add /toway /EnableSidhistory
```

Trust relationships can fall apart for various reasons, or if you create a trust, leave it for a few months, and then try to use it by migrate, you might find that it doesn't work. netdom cann“refresh” a trust with the /reset option:

```
netdom apex.com /domain:Test.com
/User:testAdmin/Password:T3$.com
/User0:apexAdmin/Password:@apex.com
/reset
```

It's the same as the command that creates, but instead of adding /add /toway /enablesidhistory, you just use /reset. Or, instead of /reset, use /verify to just check that the trust is working; if not, then use /reset. We strongly recommend that you verify a trust to make sure it working. You can also verify the Apex.com trust like this:

```
netdom query /id:apex.com
/ud:apexAdmin /pd:@apex.com
/verify trust
```

Then, once the trust isn't needed any more, you can break it with this syntax:

```
netdom apex.com /domain:Test.com
/User:testAdmin/Password:T3$.com
/User0:apexAdmin/Password:@apex.com
/remove /toway
```
