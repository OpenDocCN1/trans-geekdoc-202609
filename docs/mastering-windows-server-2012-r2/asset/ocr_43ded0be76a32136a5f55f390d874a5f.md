Events specified by the radio buttons are logged into the event log and can be viewed by Event Viewer. The choices are errors, errors and warnings, all events, or no logging. For more information on how to view the event log, check out Chapter 31.

The "Log additional Routing and Remote Access information (used for debugging)" check box is completely separate from the event log. This check is used only when you are troubleshooting specific problems, but it can be quite valuable to help you find the source of problems.

Any time you across trace or debug logs, you should keep an important consideration in mind—they should be enabled only long enough to troubleshoot a problem and then be immediately turned off. Trace and debug logs have the potential to consume a significant amount of resources, including processing power, memory, and disk space. Yes, they are useful when troubleshooting, they may impact normal operation if left on.

Trace logs are stored in %windir% tracing. By default, this directory is empty, but when you select it, several dozen files will be created in this directory.

```
%WINDIR% = C:\WINDOWS
%windir% is an environment variable that points to where Windows is installed on a system. You don't have to install Windows on the C drive, and in other operating systems, the Windows folder could be called something else. However, the operating system always needs to be locate this directory, so when it boots, it updates the variable %windir% with the actual path to the Windows directory verify the value by typing %windir%. The command line will interpret it as C:\Windows (or wherever Windows is located). C:\Windows isn't a valid command, so it will give an error, the first part of the error will tell you how %windir% is interpreted. You can do this same procedure for any variables, such as %systemroot% or %programfiles%.
```
