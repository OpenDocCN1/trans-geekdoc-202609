A few things to note at this point are that the AD FS Management snap-in should be installed registered alongside the Windows PowerShell cmdlets for administering AD FS from the command line. If you go back into the AD Management snap-in, you will see that many configuration nodes have been added. You will also notice that the AD FS Overview page has a new wizard called "Add a trusted party". This additional configuration is required to manage single-signon for applications and services. We will also add a trusted party in the next section.

Before we continue into the next portion of your, let's take a look at the Windows PowerShell cmdlets that are available to you in Windows Server 2012 R2. With the AD FS snap-in, your execution policy set to remote signed, and running Windows PowerShell as administrator; run the following command: Get-Command *-ADFS*. If you wish to see all the cmdlets available for AD FS, or all the cmdlets that are supported for a particular resource, use this command:

```
Get-Command *-ADFS*object_name*
```

The Help command uses the same principles. To learn more about AD FS in PowerShell, you can always type Get-Help *-ADFS or Get-Help *-ADFS*object_name* for information on a specific cmdlet. Figure 10-9 shows an example of requesting help for a claims provider trust in AD FS:

```
Get-Help Add-ADFSlaimsProviderTrust
```

It is worth the time to learn and understand Windows PowerShell on a regular basis for almost all administrative tasks extending beyond AD FS. The automation of tasks can greatly increase productivity.
