# TROUBLESHOOTING GROUP POLICIES

To generate RSOP information for a remote machine, use the /S systemname and /USER arguments. For instance, get RSOP information on the workstation WINDOWSCLIENT1 for the user dmelber, type gpresult /S WINDOWSCLIENT1 /USER dmelber.

You can get more detailed information with options:

+   - /V says to give more verbose information: gpresult /V.

+   - /Z says to give even more information; it is the "Z-per-verbose" option: gpresult /Z.

+   - If you know you're zeroing in a just machine policy, add /SCOPE MACHINE; if you're interested only in user policies, add /SCOPE USER.

So, for example, get the maximum information about the user policies applied to this system, gpresult /S / SCOPE USER. it is also a simple matter to generate a report by redirecting the output of a command to a text file:

```
gpresult /S WINDOWSCLIENT1 /USER dmelber /Z > c:\gpinfo.txt
```

# Using Event Viewer

You can stop shocking now! We're serious! There are times that you need to read Microsoft Group Policy on the back, and now, to the shock of many, the Event Viewer has been completely overhauled, and now, to an entire node dedicated to Group Policy! The Group Policy Operational log is a replacement for the Userenv.log file that was generated by Group Policy in the past. Now, you don't need to set up any verbose or auditing settings; it just happens. To view the Group Policy logs in the new Event Viewer, launch Event Viewer. Once Event Viewer is open, expand the Applications and Services Logs\Microsoft\Windows\GroupPolicy node. here you will find the Operational log for Group Policy. After clicking the Operational log, you will see the list of events on the right pane. Here are the new environment:

+   - The Operational log replaces the Userenv.log from previous versions of Windows Group Policy.

+   - The General and Details tabs provide excellent information for troubleshooting issues.

+   - Double-clicking the event will launch the event in its own window, allowing a single view of the information.

+   - Clicking the System + on the Details tab will expose more information about the event.

# Troubleshooting 101: Keep It Simple

We predict that, with the RSOP tool, working with group policies will not be a walk in the park for most. Here are a few suggestions to help minimize troubleshooting time:

+   - Keep your policy strategy simple. Locate users and computers in OUs if possible, and apply policies at the highest possible level.

+   - Avoid having multiple GPOs with conflicting policies that apply to the same recipients.

+   - Minimize the use of the Enforce and Block Inheritance settings.
