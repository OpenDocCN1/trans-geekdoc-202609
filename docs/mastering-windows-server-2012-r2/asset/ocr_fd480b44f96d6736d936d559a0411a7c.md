# A WORD ABOUT OS SERVICE CONFIGURATION

The default OS name for the SMTP service is SMPVC (SMTP), and it has a dependency on the IIS Admin service. By default it authenticates as the Local account, is enabled for all hardware profiles, and has no recovery options configured. To SMTP services availability on your websites, consider configuring recovery options as you might miss-critical service.

# WHEN MINIMUM REQUIREMENTS ARE'T REALLY ENOUGH

The minimal installation of only IIS 6.0 Metabase Compatibility and the IIS 6.0 Manager console role services for IIS 8 will not be enough to employ the IIS 8 feature named SMTP E-mail on your websites. In fact, not even a default installation of the Web Server role will provide role services to facilitate configuring SMTP on your sites.

Microsoft's answer is a complete installation of all IIS 8 role services in order to incorporate SMTP into a website. Talk about a security concern! Thankfully, you can disable needless site features in the applicationhost.config, root web.config or site-specific.web config to harden the server.

To install the SMTP Server feature via the Server Manager GUI, simply select roles and features from the Menu list. Should you instead decide to install the SMTP Server feature via PowerShell, use the following syntax to install both the prerequisite Server role services and the SMTP features:

```
Add-WindowsFeature SMTP -Server
```

# Setting Up an SMTP Server

Once it's installed, you can customize the SMTP Server configuration and build additional domain support via the Internet Services (6.0) Manager console. The server itself is maintained in this console, embedding SMTP services into an IIS 8 website takes place elsewhere (we'll look deeper that in a moment). Navigating the Internet Services (6.0) Manager console is a nostalgic trip down because the interface is the same from IIS 6 in Windows Server 2003.
