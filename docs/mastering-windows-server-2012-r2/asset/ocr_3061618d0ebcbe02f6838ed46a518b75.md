Administrators configure and deploy Group Policy objects (GPOs). GPOs are containers for groups of settings (policy settings) that can be applied to user and computer accounts throughout Active Directory. Policy objects are created using the Group Policy Management Editor (GPME), which is invoked by editing a GPO from the GPMC. The same GPO could specify a set of applications to be installed on all users' desktops, implement a strict policy of disk quotas and restrictions on the Explorer shell, and define domain-wide password and account lockout policies. It is possible to create one-encompassing GPO or several different GPOs, one for each type of function.

A GPO is made of two parts:

Computer Configuration Computer configuration policies manage machine-specific settings such as disk quotas, security auditing, and Event Log management.

User Configuration User policies apply user-specific settings such as application configuration, start menu management, and folder redirection.

However, there is a deal of overlap between the two, especially that Group Policy preferences have been introduced (on Group Policy preferences later in this chapter). It is not unusual to find the same policy available in both the User Configuration and Computer Configuration nodes. Be prepared for a certain amount of head scratching as you search for the policy you want to activate and decide whether to employ the user-based policy or the computer policy. Keep in mind that you can create a policy that uses both types of settings, or you can create separate GPOs to control the User and Computer Configuration settings.

Contrary to the name, Group Policy objects aren't oriented at all. They may be called GPOs because a bunch of different configuration settings are grouped in one location. Regardless, you cannot apply them directly to groups. You can apply them locally, to sites, domains and to OU (Microsoft abbrevi these collectively with LSDU in the correct order, which stands for (1) Local, (2) Site, (3) Domain, (4) OU). This act of assigning GPOs to a site, domain or OU is called linking. The GPO-to-LSDU relationship can be many-to-many (many GPOs linked to OU) or one-to-one (one GPO linked to several different OUs). Once linked to an LSDU, user policies affect user accounts within the AD (and sub-OUs), and computer policies affect computer accounts within the AD (and sub-OUs). Both types of policy settings apply at a periodic refresh, which is approximately 90 minutes, for the most.

When GPOs are stored in the AD, that wasn't exact. GPOs are stored in two parts—Group Policy container (GPO) and a Group Policy template (GPT), which is a folder structure. The container is stored in the Active Directory database and contains property information, version, status, and a list of components. The folder path is Windows\SYSVOL\sysvol\<Domainname>\Policies\<GUID>, where GUID is the globally unique identifier for the GPO. This folder contains administrative settings, security settings, information on available applications, registry settings, scripts, and more.
