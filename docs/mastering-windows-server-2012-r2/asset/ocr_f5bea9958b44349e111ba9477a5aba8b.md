# INTRODUCING DIRECTACCESS

Support behind a NAT Device You can deploy DirectAccess either as an edge server in your DMZ or inside your main network and sitting behind a NAT device, as a router or firewall. It is a welcome change to its predecessor, it means that you don't need to have a plethora of NICs and IP addresses if you just want to get up and running quickly.

**Load-Balancing Support** ’Load-Balancing Support Windows' Network Load Balancing (NLB) or third-party load-balancer solutions can be deployed with DirectAccess to provide high availability and scalability.

**Multidomain Support** ’Multidomain-Multidomain Support If you need to deliver remote connectivity to your users across multiple domains, then this functionality comes integrated and out of the box.

**NAP Integration** ’NAP Integration You can integrate DirectAccess with your Network Access Protection (NAP) deployments to ensure that remote clients are in a healthy state (all antivirus updated, Bitocker enabled, and before gaining access to the internal network.

**Monitoring and Diagnostics** ’Monitoring and Diagnostics A Handy Monitoring dashboard is available that shows many connected clients and inbound/outbound traffic metrics. You can also check the health of your DirectAccess deployment from the Operations view in the main console.

**IP-HTTPS Performance Improvements** ’IP-HTTPS Performance Improvements One of the reasons why connecting to your network performs better than your traditional VPN clients is that it uses IPv6 as your core protocol stack for communications. IPv6 is a newer and ultimately faster stack than the older IPv4 stack that you've well accustomed to. One of the transitional technologies of IPv6 is IP-HTTPS, where we have seen significant performance gains in how it scales and reduces overhead.

**Server Core and PowerShell Support** ’Server Core and PowerShell Support Windows Server 2012 R2 DirectAccess will work with Server Core installations of Windows Server 2012 R2 and also provides Windows PowerShell-support—unlike its predecessor, which superior neither.

# REMOTE ACCESS POWERSHELL CMDTS

As part of the new PowerShell support for the Remote Access role, you now have over 60 cmdlets to work with. From a DirectAccess perspective, these new cmdlets allow you to add and remove configuration items, enable multiple deployment, and provide help when troubleshooting. Check the full list of cmdlets and their descriptions here: http://ynurl.com/ws2012racmdlets.

**Multisite Support** If you have responsibility for managing a large enterprise network that spreads across multiple sites and geographic locations, then the new Multisite Support of DirectAccess should appear to you. It allows you to deploy multiple DirectAccess server points across your network to ensure clients get the best remote connectivity performance, regardless of their location.
