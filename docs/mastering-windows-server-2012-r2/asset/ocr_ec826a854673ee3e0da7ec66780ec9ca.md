One notable feature that is not configured per-website is the FTP login attempt restrictions. This new feature will let you set a failed login attempt threshold that will lock the IP address from where the failed logins are coming from or make a note of the attempts in the log file. This setting is only configurable on the server level.

As an alternative to creating a new FTP publishing site, you could use PowerShell. Some benefits of using PowerShell include method scripting, automation, and remote management. For example, to create a new FTP site named FTPTest with default parameters and using a custom port of 2121 with an explicit directory of D:\FTPTest your syntax would look something like this:

```
New-FTPSite -Name FTPTest -Port 2121 -PhysicalPath D:\FTPTest
```

Keep in mind that the new FTP site will be created with the next-available ID number since this syntax does not specify one. Also, the default authentication and authorization entities will be configured.

Remember, FTP is a powerful role in its own right, and there is much to consider when employing it on your web server. Entire chapters and short books have been written on the FTP product! Although a deeper dive into administration and security of FTP falls outside the scope of this chapter, it would be wise to brush up on the protocol before you unintentionally open your websites to potential vulnerabilities.
