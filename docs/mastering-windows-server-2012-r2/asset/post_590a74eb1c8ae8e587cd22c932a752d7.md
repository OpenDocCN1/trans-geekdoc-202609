## ITEM-LEVEL TARGETING

One of the most impressive aspects of GPP is the item-level targeting capabilities. You can now target and apply any GPP setting by querying different aspects of the computer environment, only applying the setting if the environment is what you want it to be. For example, let's say you have the HR department running an application that exists in a Terminal Services environment. When they launch this application, they need to have a mapped drive for the application. The solution most companies use today is to map the drive for the user account, so they have a "Drive" mapping even when they are working on their desktop. GPP item-level targeting allows you to provide the drive mapping only when they are in the Terminal Services environment.

You can obtain this type of control by leveraging one of many different item-level targeting options. The full list of item-level targeting options is as follows:

## Real World Scenario

## ELIMINATING LOGON SCRIPTS USING GROUP POLICY PREFERENCES

Many companies are still using legacy scripts to apply settings to desktops such as drive mappings and printer mappings. Using logon scripts is archaic in comparison to the new and improved capabilities of GPP.

Many other companies have switched to using GPP when possible to eliminate some, if not all, of the settings in their logon scripts. You can use the following preferences in lieu of logon scripts:

- **Mappings** Drive mappings can now be targeted to "just-in-time" mappings that make more sense for users. Item-level targets can be used in conjunction with mappings to only provide access to data based on user having the correct application, and only in a Terminal session.

- **Printers** Printers are often hard to manage for medium and large organizations that have mobile users. When a user goes to a branch office, it can be difficult for the user to find and configure the correct printer. The GPP for printers can be used to map all printers in the company. When a user with an item-level target (such as an IP address or AD site), users will get the printer they need in the branch office.

- **Registry** With the new registry preference, any registry entry can now be placed in a GPO without any ADM template or ADMX file. This includes binary and string values, which were not possible in AD templates.

## The New and Improved GPMC

The GPMC has been around for a while. The first generation of the GPMC was revolutionary and made administration of GPOs much easier. This generation of the GPMC continues to make the administration of GPOs easy, efficient, and stable. No more are the days when you needed to launch the Active Directory Users and Computers to create, link, and manage GPOs. That was archaic to the least. Now, the new GPMC can run on Windows Server 2012 R and Windows 8.

- You will need to install the GPMC because it is not installed by default. For your Windows Server 2012 R computers, you can install the GPMC from Server Manager.

- 1. Launch Server Manager, and select the Features menu.

- 2. From here, you just need to click the Add Features option, which will give you a full list of tools you can install, as shown in Figure 9.28.

- 3. Select the Group Policy Management option, which will take you through some gyrations to get the tool installed.

- 4. After a restart, you will now have the GPMC installed.
