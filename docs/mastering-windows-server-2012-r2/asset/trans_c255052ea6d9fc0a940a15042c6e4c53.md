### 网络适配器中的高级功能
如图 27.35 所示的功能，你可以选择使用动态或静态 MAC 地址。Hyper-V 管理其自己的 MAC 地址池，除非你遇到 MAC 冲突，否则可能应该将此设置留为“动态（Dynamic）”。

然后是“启用 MAC 地址欺骗（Enable MAC address spoofing）”。这听起来像件坏事，对吧？它是 Hyper-V 最初发布时的唯一可用行为。当时，一个受攻击的虚拟机可能会泛洪交换机或冒充另一个虚拟机。Hyper-V 要安全得多。虚拟交换机会学习哪个 MAC 地址属于哪个虚拟机，并且不允许其更改 MAC 地址。通常情况下这不是问题，但在你确实需要多个 MAC 地址的情况下除外。想不出理由吗？考虑网络负载均衡或故障转移集群吧。

如果你在生产环境中遇到管理员部署未经授权的 DHCP 服务器导致的问题，那么你不需要告诉他们这会导致无效 IP 地址的管理噩梦。此时，“DHCP 保护（DHCP guard）”选项派上了用场。启用后，虚拟机将停止通过此特定的网络适配器响应 DHCP 客户端。

“路由器保护（Router guard）”，它可以防止虚拟机通过此特定的网络适配器向网络发送恶意重定向。

如果你正在运行 Hyper-V 故障转移集群并启用了“受保护的网络（Protected network）”选项，虚拟机将在检测到网络连接时移动到另一个节点，从而确保服务的网络可用。

“端口镜像（Port mirroring）”可用于连接到同一虚拟交换机的两个虚拟机之间的网络流量分析。其中一个虚拟机可以使用诊断工具进行分析，而另一个可能是锁定环境的一部分，无法在其中安装分析工具。通过镜像虚拟机的端口，而无需在具有分析所需工具的虚拟机上操作。

这里的最后一个高级选项是“网卡绑定（NIC teaming）”。不要与我们在第 4 章中讨论的主机网卡绑定混淆，“允许此网络适配器成为客户操作系统中团队的一部分”的作用完全如其字面意思！如果你想创建一个在其中一个物理网卡停止工作时仍保持运行的网卡团队，请确保已启用此选项。

继续讨论左侧窗格，我们可以进入“管理（Management）”部分。通常情况下你不需要更改此处的任何设置，因为默认值是合理的。你可以在此处更改虚拟机的名称，配置集成服务（Integration Services）组件（之前在“虚拟机（客户）分区”中讨论过），指定检查点文件（稍后在讨论检查点时介绍）和智能分页文件位置，并决定主机启动或关闭时应该发生什么。

我们还没有讨论完图 27.29 中窗格中的操作。在选中虚拟机后，你有这些额外选项：

- 连接（Connect）：用于启动虚拟控制台。
- 设置（Settings）：用于配置虚拟机，如前面的节所述。
- 启动（Start）：用于启动虚拟机。根据虚拟机的状态，你将看到更多选项，例如“关闭（Shutdown）”。
- 检查点（Checkpoint）：用于创建虚拟机的实时映像。
- 移动（Move）：用于移动虚拟机或其存储。
- 导出（Export）：用于保存整个虚拟机，包括配置和虚拟硬件。
- 重命名（Rename）：为虚拟机提供另一个名称。
- 删除（Delete）：删除虚拟机配置但不删除其硬硬盘。
- 启用复制（Enable Replication）：用于将虚拟机复制到另一个 Hyper-V 主机。

另一个需要注意的是，“操作（Actions）”窗格中的准确项目会随虚拟机的电源状态而变化。之前的选项假设虚拟机仍在运行。当虚拟机运行时，你还有额外的项目来关闭虚拟机、重置、关机等。

# 安装虚拟机

配置虚拟机后，最困难的部分已经完成了。下一步是在虚拟机中安装操作系统。你习惯于处理物理服务器，但在这里虚拟机中安装的细节略有不同。

第一个问题是如何连接到虚拟机的控制台。毕竟，你想看到发生了什么。为此，打开 Hyper-V 管理器，选择你想连接的虚拟机（示例中为 WS2012R2-SRV），并点击右下角的“连接（Connect）”。虚拟连接控制台将打开，如图 27.36 所示。另一种方法是双击底部的缩图。

# 开始使用虚拟机

虚拟控制台有一个菜单栏和一个按钮。大多数功能在你们都熟悉的 Hyper-V 管理控制台中都有重复。显示名为 WS2012R2-SRV 的虚拟机已关闭的黑屏就是你的虚拟屏幕。虚拟机将向你显示熟悉的 Windows 正在运行的消息。
