# Active Directory Rights Management Services

Passing secure documents and files within your company is vital to the company's information integrity. Your company's CFO, for example, may have a report listing the salaries of all the employees in the company. The CFO wants only other executives in the company to have access to the file. This is where Active Directory Rights Management Services (AD RMS) will be called to secure the file. With AD RMS the CFO can encrypt or apply authentication to the file. Prior to Windows Server 2012 R2, AD RMS setup required that only a user with local administrator privileges be allowed to install on the computer that hosted the SQL Server database. This was because AD needed to read the SQL Server settings from the registry during installation. Microsoft implemented the following changes to deal with the AD RMS and how SQL Server is accessed:

# CHAPTER 1 WHAT'S NEW IN WINDOWS SERVER 2012 R2

- AD RMS now requires the installer to have sysadmin permissions in the SQL Server installation.

- The browser for SQL Server must be in order to locate any available SQL Server instances.

- Any ports used by AD RMS setup on the SQL Server must have firewall exceptions enabled. You will need to enable TCP port (default port 1433) for the SQL instance and the UDP port (port 1434) for the SQL Server Browser Service.

Another piece of AD RMS setup was upgraded. In previous versions you would have to deploy from the computer where AD RMS was installed. In Windows Server 2012 R2 you are allowed to remotely deploy at targeted server computers. You can read more about AD RMS starting in Chapter 7.

# Active Directory Certificate Services

You can bind the identity of services, devices, and people to a private key using Active Directory Certificate Services (AD CS). This enhanced security feature allows access to only participating applications that support AD. Here are some of the changes affecting Windows Server 2012 R2:

- Server Manager integration.

- Deployment and management using Windows PowerShell.

- AD CS role can be run on Server Core or any version of Windows Server 2012 R2.

- Automatic certificate renewal is now supported for joined computers not in a domain.

- Certificate renewal with same key is enforced.

- International domain name support.

- CA role has increased security enabled by default.

You can read more about AD CS starting in Chapter 7.

# Virtualization

Virtualization allows you to put multiple operating systems on one physical machine. In the past, you would have used four servers for your domain controller, Exchange Server, DNS server, and DHCP server. Now you can have one physical box and four virtual servers. This saves money (on hardware) and also saves space (four servers before/one server now). Virtualization in Windows Server 2012 R2 is continuing to improve.

# Hyper-V

Server virtualization—breaking one physical server into a bunch of virtual machines—is one of the most significant changes in server management in the past 10 years. We wrote “server management” in lowercase because it's not just in Windows Server but in various flavors of Linux, Unix, Sun Solaris, and so on. Being able to buy one big, powerful, reliable piece of hardware and then feeling like it's 10 or 20 smaller pieces of computer hardware and then installing separate server OSes on those bits of “virtual server hardware” has greatly simplified server management for operations big and small. Furthermore, it has solved a server management problem that has beleagued server planners for years: underutilized hardware. The tool that fools the computer into thinking that it is actually separate computers is generically called a virtual machine manager (VMM).

You will see, at the start of server computing, most organizations have preferred to have their own particular server—email, AD domain controller, file server, web server, database server—on one. If you needed a domain controller, a web server, and an email server you would commonly buy three separate servers, put a copy of Windows Server on each, and make one a DC, one web server (by enabling Internet Services), R2's built-in web server, and an Exchange Server. The downside of this was that each of those servers would probably run at fairly low levels; it wouldn't be surprising to learn that the DC ran about 5 percent of the CPU's maximum capacity, the web server a bit more and the email server a bit more than that. Running bunches of physical hardware better than their capacity wasting electricity, and not you know? In contrast, buying one physical server and using a VMM (for example) three virtual servers would probably load to a physical server near capacity electricity and cooling needs.

First, let's cover the new technology added in this version. Since there are so many improvements to Hyper-V, we're just briefly touching on each one:

- Hyper-V gives desktop Windows Hyper-V technology without the need for installing an OS.

- Hyper-V module for Windows PowerShell provides more than any cmdlets.

- Hyper-V Replica allows you to replicate virtual machines between sites. This provides business continuity and disaster recovery.

- Resource metrics helps track and collect network usage.

- Simplified authentication allows administrators to configure virtual machines.

- Single-root I/O virtualization (SR-IOV) is a new feature that allows you to assign network directly to virtual machines.

- Storage management allows you to move virtual disks to a different storage.

- SMB 3.0 file share is a new feature that provides virtual machines with shared storage.

- Virtual Fibre Channel allows direct access to storage.

- Virtual Non-Uniform Memory Architecture (NUMA) allows certain high-performance applications running in the virtual machine to optimize.

# WHAT'S NEW IN WINDOWS SERVER 2012 R2

Now let's briefly talk about the enhancements made to existing Hyper-V that many administrators find useful.

- Dynamic memory allows you to configure Smart Paging so your virtual machines can efficiently restart. If a virtual machine has less startup memory, dynamic memory can be configured.

- Importing virtual machines has received a tune-up to better handle problems that would normally prevent an import.

- Live migrations make it possible to complete a live migration in a noncluster environment.

- Larger storage resources, increased scale, and better error-handling are offered in this version.

- Virtual Disk Format (VHDX) increases the maximum storage size of each virtual disk. The new format supports up to 64 terabytes of storage. It also comes with hardware protection against power failures. This format will also prevent performance payoff on large-scale physical disks.

- You no longer need to shut down the virtual machine to recover deleted storage space. Virtual machine snapshots will now free up the space consumed once it is deleted.

You can read more about this in Chapter 27, "Virtualization with Hyper-V"

RE OR DEPRECATED ITEMS IN WINDOWS SERVER 2012 R2
VM chimney, also referred to as TCP offload, has been removed and no longer available to guest operating systems. The WMI root/virtualization namespace is changed to just root/virtualization/w2 and will eventually be taken out completely in future Server versions. Authorization Manager (AzMan) has also been deprecated in this version and will be phased out in future releases. The new management tools for virtual machines will be the new standard.

# Virtual Desktop Infrastructure

In Windows Server 2012 R2, Microsoft has made vast improvements to the virtual desktop infrastructure (VDI), with simpler administration, increased value, and better overall experience.

Supporting mobile devices is a must in today's market. Virtual desktop infrastructure helps bridge the compatibility gap between devices by virtualizing resources. VDI provides stronger security and higher efficiency that improves productivity with a UI that the user is familiar with. Windows Server 2012 R2 and VDI make it a snap to deploy virtual resources across devices.
