# Establishing the Trust

Although we are not going through the ADMT v3.2 setup process, it is extremely important in any kind of Active Directory migration that you establish trust through the two domains. The quickest way to establish this trust is through the Active Directory Domains and Trusts console (domain.msc). Use the New Trust Wizard for the following:

+   * Specify the type of trust. An external trust is simple and effective for this procedure.

+   * Specify a two-way trust. Accounts from each domain will need to access each other's resources.

+   * Create the trust on the other domain. This will require domain admin credentials on that

+   * Validate the trust to make certain things are working correctly.

Once you have established the trust, you must test it—is the trust working, and are the permissions correct over the domains? Users from any domain can be members of domain local groups and member server local groups, you could now add a user from the opposite domain to a built-in group on the domain controller. This is a required step with any migration. So, you can search and add the Bigfirm administrator to the built-in group of Oldfirm in Active Directory Users and Computers.

But adding users to groups is not what you really want. You wanted the accounts to be able to access resources in the other domain. This is where SID comes into play. SID history is treated as another group on the trust that will be passed to the resource domain for access to the migrated accounts—

SID filtering is disabled by default, and if you require that it be enabled, then you will have to do it manually. SID history can be exploited by a hacker in an elevated privilege within the trust resource. It is possible they could construct a trust with a SID of a domain administrator, this account would have the same level of access. SID filtering stops any SIDs that don't originate from the trusted domain. Basically, your users' security token won't buy a gunball in the source domain with SID filtering enabled because the SID history value would be stripped of it. So, by following the helpful hyperlink “Securing external trusts” in the window, you'll learn that you can use the netdom command to enable and disable SID filtering for these digamos as these.

The netdom command installed with Windows Server 2012, but you be sure to search Microsoft's site for the latest version.
