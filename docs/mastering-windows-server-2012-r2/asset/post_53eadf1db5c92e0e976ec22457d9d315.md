# WHICH WINDOWS SERVER 2012 VERSION

Microsoft simplified the windows jungle and offers two Windows Server 2012 versions you can consider for setting up domain controllers: Windows Server 2012 Standard or Datacenter edition. There is no difference in functionality, availability, or features. The difference is in terms of licensing and the number of virtual machines you can run top of each edition. At the beginning of this book, we explained the differences between the two versions. If you need to install a domain controller, you can always choose Windows Server 2012 Datacenter edition, and if your license allows, you must be aware of that Windows Server 2012 is available only in 64-bit versions; there is no 32-bit version. This comes into play when you are thinking about upgrading your domain controllers. You cannot perform an in-place upgrade from a 32-bit system to a 64-bit system.

# Server Name

Before promoting a domain controller you need to assign the final computer name. What are good server names? I could write almost a book about naming servers, but there are a few things you should consider:

- Don't use any company, department, country, or other names that could change over time in your names.
- Keep the names short; your administrator will thank you.
- Use acronyms to identify your server roles.

A common naming scheme for domain controllers is DC01, DC02, and so on. You can rename a domain controller using the GUI or Nettool.

# IP Addressing

Because clients and servers locate the domain controller using DNS and your domain controller has the DNS role, you must always assign a static IP address. Otherwise, your domain controller becomes a moving target for other systems if you are trying to locate it. If you are configuring IPv4 address, it is best to leave IPv6 enabled.

# AUTHENTICATION PITFALL

Domain controllers running 2008 and later have the "Allow cryptography compatible with Windows NT" setting disabled by default. The legacy algorithms used in Windows NT 4.0 can be cracked with today's technologies.

Therefore, Microsoft made their domain controller more secure by using a Group Policy to prevent logins from clients using weak algorithms. The work-around is to enable this setting in the Default Domain Controller Policy. You can find more details on this page:

http://support.microsoft.com/kb/942564/

# OPERATING SYSTEM COMPATIBILITY

In Windows Server 2012 Microsoft introduces the Resilient File System (ReFS). This file system is, as its name suggests, more resilient than NTFS. It has higher integrity and stability, and it also has proactive error identification built in. You may be tempted to choose this file system for all your projects because of its qualities, but sadly there are limitations you need to be aware of:

- ReFS is only available in Windows Server 2012.
- ReFS is only used for data volumes. There is no way to use ReFS as an operating system volume or boot volume.
- As an Active Directory administrator, you need to know these best practices:
- Use only NTFS to store your SYSVOL, Active Directory database, and the Active Directory log files.
- Do not install SYSVOL on an ReFS-formatted volume or disk.
- Do not install the Active Directory database on an ReFS-formatted volume or disk.
