# USING SERVER MANAGER TO CONFIGURE YOUR SERVERS

Server Manager is the tool that you will use to manage the configuration of your Windows Server 2012 R2 machines. Using it, you can add and remove native functionality, manage that, and diagnose problems. You can also use a command-line alternative called PowerShell to manage the native functionality that is installed on Windows Server 2012 R2.

# Changes to Server Manager

There are some differences between Server Manager in Windows Server 2008 and Windows Server 2012 R2:

+   - As stated earlier in this chapter the Initial Configuration Tasks is no longer the default tool upon login; Server Manager will open all the server properties you can use to manage the server

+   - You will notice that the GUI is different from any previous version of Server Manager. With new metro boxes and a cleaner look, it may take a bit to get used, but in the long run you will appreciate it.

+   - With Server Manager you have multiserver remote support. You can easily add servers to the network within this tool. An added feature is group management, which allows you to send commands to all servers within the group.

+   - The event logs and services can now be accessed from Server Manager for both local and remote servers.

+   - The Roles Wizard has new screens with a few addition options before getting role selection. The first screen is called Installation Type. The second screen is called Server Selection. We will discuss these new screens and how they are used a little later in the chapter.

+   - Server manager cmd. exe has been deprecated. PowerShell is now the command-line tool for use.

+   - Adding a feature using the GUI is now part of the Roles Wizard and is no longer a separate tool.

This sounds like a lot of differences, Server Manager is more alike than different on Windows Server 2008 and Windows Server 2012 R2.
