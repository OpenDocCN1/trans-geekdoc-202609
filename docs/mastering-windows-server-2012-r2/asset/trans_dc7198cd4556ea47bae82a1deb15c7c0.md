# 现实世界场景

# VM 神其妙地运行缓慢

Bigfam 部署了多个 Hyper-V 主机作为测试环境。每台服务器都采用 RAID 5 配置，拥有 128 GB 的内部内存和 12 TB 的可用磁盘空间。Hyper-V 主机由 IS 部门运行。其他部门使用并管理这些 VM。

一天，开始收到投诉，某些 VM 响应缓慢，尽管这些 VM 并没有负载。IS 部门接收了投诉并进行调查。一个 VM 没有显示出任何故障迹象。CPU 使用率正常，所有应用程序都在运行，操作系统没有进行交换，也没有内存压力。简而言之，没有明显的原因。出现了一个模式：“慢速”VM。

IS 部门开始在主机上运行计数器，包括 CPU 和逻辑磁盘对象。经过一小时的测量后，他们注意到某些计数器持续处于高位：磁盘秒/读取计数器平均值为 30 毫秒，磁盘秒/写入计数器大多超过 50 毫秒。托管磁盘的磁盘平均队列长度计数器经常峰值超过 20。与其他主机相比，这些值真的非常高。主机在交付所需的 I/O 方面遇到了困难。

对主机进行检查发现，VM 上的磁盘位于 RAID 5 配置中，这很好，但读取速度慢。所有 VM 的组合磁盘 I/O 超过了主机的容量。通过将磁盘重新排列为 RAID 10 配置并增加更多磁盘以提高 I/O 吞吐量，解决了这个问题。

这个案例说明了管理虚拟化服务器环境的额外复杂性。如果底层物理磁盘硬件没有配置为最佳性能，组合 VM 可能会给主机带来麻烦。

# 磁盘维护

VM 的核心部分是它的磁盘。它们不仅包含数据，而且在很大程度上决定了 VM 的性能。在本节中，你将学习如何维护虚拟磁盘。

在使用动态和固定磁盘时，如果你创建了大量数据并将其删除（例如将大型 ISO 文件复制到其中然后删除它们），你会在磁盘上留下大量空空间。也就是说，虚拟磁盘比实际需要的大。Hyper-V 可以通过名为“压缩 (compaction)”的操作来删除这些空空间。要这样做，虚拟磁盘必须位于父分区中。如果磁盘上的文件系统是 NTFS，父分区可以检查其数据结构以找到空空间所在。它利用这些信息来减小代表虚拟磁盘的文件的大小。要压缩虚拟磁盘，对应的 VM 不能正在运行。你必须关闭它或保存其状态。完成后，操作如下：

- 1 从 Hyper-V 管理控制中的“操作”中启动“编辑虚拟硬盘向导”。
- 2 找到你想要压缩的虚拟磁盘（例如你之前创建的那个），并点击“下一步”。

如图 27.19 所示，“选择操作”对话框向你提供了三个可以应用于虚拟磁盘的选项。
