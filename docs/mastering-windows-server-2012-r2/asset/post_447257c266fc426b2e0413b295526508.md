## Understanding Event Levels

Events are categorized by their level. These levels have names and you can see them:

- Information Events: Level 0: These entries are for the successful completion of an operation. The icon used to represent Information Events is an i in circle.
- Critical Events: Level 1: A Critical event is one that cannot recover. The icon used to represent Critical Events is a white x in red.
- Error Events: Level 2: Error events indicate a problem occurred in the application or component. The icon used to represent Error Events is a white exclamation in circle.
- Warning Events: Level 3: Warning events indicate events that may lead to a problem in the future. The icon used to represent Warning Events is a black exclamation point in yellow triangle.
- Verbose: Level 5: Verbose logging provides more details in the log. If this check box is enabled, these additional details will be recorded.

The events are shown by default in all logs except the Security log. The Security log is focused on audit success and audit failure so it lists these keywords instead of the levels.

## Creating and Using Custom Views

When you're looking at the logs, you're looking for specific events, or at events related to a specific issue or problem. The Custom Views of Event Viewer provide predefined views and allow you to create your own. This is helpful because you don't have to re-create the view each time you want to look at. Some custom views are automatically created:

- Server Roles: Each time you add a server, an associated custom view is automatically created. For example, if you promote a server to a domain controller, a custom view named Active Directory Services will be added below the Server node to show system events for Active Directory Services.
- Administrative Events: The Administrative Custom view shows Critical, Error, and Warning events from all the administrative logs. In other words, it shows everything except for informational events. This view includes the basic administrative logs (Application, Security, and System) found on any system. It also includes logs in the Applications and Services logs and some of the logs in the Applications and Services > Microsoft > Windows.

When the server is configured with a new role or feature or additional logs are added, the Administrative Events custom view is modified to include these additional logs.

## PREDEFIN CUSTOM VIEWS CAN'T BE FILTERED

Neither the Administrative Events custom nor any of the server role custom views can be filtered. If you want to filter these logs, you'll need to create a copy of the custom view first.

## Creating a COPY of a CUSTOM VIEW

You may like one of the predefined custom views but want to make a slight modification. Instead of starting from scratch, you can create a copy of the custom view and modify it.
