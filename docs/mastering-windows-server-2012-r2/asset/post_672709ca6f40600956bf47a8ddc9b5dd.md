## CONFIGURING HOST SESSION PROPERTIES

In Windows Server 2012 R2, you can no longer use the Remote Desktop Host Configuration Tool that you may have used in Windows Server 2008 R2.

You can configure session properties for remote sessions in the Remote Desktop Session Host from Group Policy Management Editor. You can access this tool by hitting your Windows keys and choosing Group Policy Management.

The primary configuration you'll use when using Remote Desktop Session Host. Figure 17.24 shows the properties available for Remote Desktop Session Host.

## FIGURE 17.24
Using Group Policy to configure Desktop Session Host

![](img/41a83208e6906a3732620203b836cea7_939_0.png)

Since there are many properties listed, we discuss a couple of important ones you should be concerned with.

**Security** Since users will be remotely accessing the server, security properties should be an administrator's concern. The following are the security properties you can set:

**Server Authentication Template** This policy setting allows you to specify the name of the certificate template that determines which certificate is automatically selected to authenticate an RD Session Host server.

**Set Connection Encryption Level** This policy setting specifies whether to require the use of a specific encryption level to secure communications between client computers and RD Session servers during Remote Desktop Protocol connections.

**Always Prompt for Password Connection** You can use this setting to enforce a password prompt for users logging onto Remote Desktop Services, even if they already provided the password in the Remote Desktop connection client.

## REMOTE DESKTOP FOR ADMINISTRATION 905

**Require RPC Communications** You can use this setting to strengthen the security of RPC communication with clients by allowing only authenticated and encrypted requests.

**Require Use of Specific Security Layer for Remote (RDP) Connections** This policy setting specifies whether to require the use of a specific security layer to secure communications between clients and RD Session servers over Remote Desktop connections.

**Do Not Allow Local Administrators to Customize Permissions** You can use this setting to prevent administrators from making changes to the user groups allowed to connect remotely to the RD Session Host server. By default, administrators are able to make changes.

**Require User Authentication for Remote Connections by Network Level Authentication** If you enable this policy setting, only computers that support Network Level Authentication can connect to the RD Session Host server.

**Session Time Limits** The other properties you will find yourself will be the session time limits. The following are the session time limit properties with a short description of each.

**Set Time Limit for Disconnected Sessions** You can use this policy setting to specify the maximum amount of time that a disconnected session remains active on the server. By default, Remote Desktop Services allows users to disconnect from a Remote Desktop Services without logging off and ending the session.

**Set Time Limit for Active Idle Remote Desktop Sessions** If you enable this policy, you must select the desired limit in the idle session limit list. Remote Desktop Services will automatically disconnect active idle sessions after the specified amount of time. The user receives a warning two minutes before the session disconnects, which allows the user to press a key or move the mouse to keep the session active.

**Set Time Limit for Active Remote Desktop Sessions** This policy setting allows you to specify the maximum amount of time that a Remote Desktop Services can be active before it is automatically disconnected.

**End Session When Time Limits Are Reached** This policy setting specifies whether to end a Remote Desktop Services session that has timed out without disconnecting.

**Set Time Limit for Logoff** This policy setting specifies how long a session will remain before it is terminated.

In past versions of Windows, it was possible to remotely administer. However, you had to open port 3389 on the firewall. But every additional port opened on a presents a vulnerability that needs to be managed.

Since RD Gateway uses RDP over HTTPS through port 443, the external firewall needs only 443 open. Port 443 is common to open all other traffic. If port 443 is for other traffic, you don't need to open additional ports to use RDP.

## REMOTE DESKTOP CONNECTION CLIENT

RD Gateway supports connections from Remote Desktop Connection 6.0 or greater. However, to support all the features available in Windows Server 2012 R2, Remote Desktop Protocol 8.0 is recommended. This is natively provided in the RDC client supplied with Windows 8 and Windows 2012. The RDP 8.0 is also available as an add-on for Windows 7 SP1 and Windows Server 2008 R2 SP1 (http://support.microsoft.com/kb/2592687).
