
# UNDERSTANDING SERVER VIRTUALIZATION

How does this work, generally speaking? Clearly, you cannot have two operating systems accessing the same hardware at the same time. One has to be charge (that would be the host), and the other (the VM) will need to access hardware through emulation, synthetic drivers, or some other means. In principle, the same goes for the execution of CPU instructions and even memory access.

Modern virtualization systems like Hyper-V go out of their way to use system resources as efficiently as possible. They use real memory and the CPU directly executes the code of the VM with some exceptions that we will discuss later. The argument holds for high-performance devices such as network, disk, or video interfaces. Emulation where existing hardware behavior needs to be simulated will cost you performance. Sometimes it is unavoidable, but Hyper-V takes a different route. It uses its own driver architecture for each type of device to reduce overhead as much as possible. This design tightly integrates with the computer architecture.

# What Is Server Virtualization?

Now that you have some idea of what virtualization is, let's discuss what to use it for. Some applications are testing and development, consolidation of servers, and disaster recovery. You benefit from the high degree of flexibility that virtualization offers.

The technology took off in the beginning as a test bed for administrators and consultants in need of hardware for a quick test and who were too happy to use an existing machine with virtualized software to run a couple of VMs. Larger organizations usually have multiple testing environments for various purposes. With virtualization, you can quickly add and remove VMs as needed. When a new application comes along or a new infrastructure component needs to be integrated, a new virtual environment is all you need to deploy for the project to.

Many administrators have a couple of VMs for their own use so they can quickly test and changes before applying them in a production network. For instance, as an Active Directory specialist, you might run four or five DCs on a Windows 8.1 workstation on a normal 8-GB desktop that is running Windows Server 2012 R2 with Hyper-V. You might use this to research the fine points of Active Directory replication or the effects of a Group Policy change on the client.

Similarly, virtualization is great for giving technology demos. Because of the low-performance requirements demands, you can run multiple VMs on a powerful laptop and show how it it clearly.

Away using virtualization for testing and delivering demos, the largest deployments of server virtualization are in datacenters where numerous servers are consolidated for mainline and private cloud service. Also, huge numbers of organizations (big and small) are migrating their physical IT estates to virtual platforms to reap the cost-saving and flexibility benefits. A virtualized environment offers the following advantages:

- Conserves Resources and Saves Costs One host running multiple saves rack space, electrical power, and cooling capacity. It would not be unreasonable to consolidate 20 or 30 lowly physical machines to one high spec'd physical host.
- Shares Hardware A host offers the same “virtual” hardware to each VM. In other words, all VMs share common hardware. This makes them predictable and makes the maintenance of drivers easy. Deploying VMs is much easier than deploying physical machines, because drivers are no longer a factor.
- Increases Flexibility The feature of identical virtual hardware makes for a high degree of flexibility. You can move VMs from hosts for load distribution or maintenance. If your company is thinking of moving to the cloud (either public or private), then virtualization plays a major role in elasticity.
- Joins Legacy Systems Many organizations run a mix of operating systems—not only Windows Server 2012 R2 but also older systems running Windows 2008 or even Windows 2003. Chances are that those systems require little computing power on modern hardware. This makes them ideal candidates for consolidation. One host will have enough power for many operating systems, which will also benefit from the uniform virtual hardware.
- In large environments with large storage area network (SAN) deployments, mirrored datacenters, and similar infrastructure, virtualization is an asset for disaster recovery. Not only is server consolidation a benefit, but all virtual machines have the type of virtual hardware. You will have no driver or HAL issues when restarting a virtual machine on a new Hyper-V.

Each technology has its downside and virtualization is no exception. Some of these disadvantages may impact you more than:

- Increases Complexity: Virtualization adds a layer of complexity to the environment. You need to know whether a server is a VM or a physical server, and there is a host for VMs. For SQL Server administrators previously would be responsible for all aspects of SQL Server: software, hardware, and configuration. If SQL Server is virtualized, they must depend on the administrators of the host to keep their VMs running. The impact on the host will also impact the SQL Server VMs.
- Places Demands on Infrastructure A full-blown VM environment will need additional infrastructure: a SAN solution is mandatory in large environments, as dedicated management software and a scalable high-speed IP network.
- Can Large-scale Failure: If you are not specifically designing for service availability, a host is a single point of failure. If it goes down unexpectedly, for instance, because the CPU overheats and shuts down, it will take all VMs down with it. Think of the phrase “putting all your eggs in one basket!”
- Requires Special Maintenance: If you have a library of VMs, you will need to do some maintenance of those as well, such as applying patches.
- Unique Security Issues: There are some security considerations related to virtualization. For instance, in a SAN-environment, you will have two additional groups of administrators who can access data in a VM: the host machines and the SAN administrators. A SQL Server administrator responsible for the VM may not be aware that those administrators can, in principle, access his data at, assuming they have the desire and knowledge to do so.
Another example would be a scenario where multiple security domains are located on the same virtualization infrastructure, such as an organization’s DMZ and LAN located on the same host, or a multi-tenant cloud that runs completely different customer environments.
- Requires a Learning Curve: When you deploy a new technology, you need to learn it. While you are learning it, you will make mistakes. Some of these will impact your production environment. That’s nothing new, but it’s still a factor to consider.

Clearly, it's a balancing act. For most organizations (but not all), the advantages far outweigh the disadvantages. The main point is that server virtualization is here to stay. # Getting Started with Hyper-V

Not surprisingly, there are hardware and software requirements for running Hyper-V. In addition, there are some licensing issues involved, which we'll discuss later.

# HARDWARE REQUIREMENTS

The base requirements for running Hyper-V are quite simple, and these outlines what you need:

### CPU and BIOS
You need an x64-based CPU and a BIOS that supports both CPU-assisted virtualization and Data Execution Prevention (DEP). A common problem is that these features are offered by the system, they are not typically enabled in the BIOS of older hardware. Make sure these features are turned on. If you need to change the BIOS settings, be aware that a cold boot is required; the computer must be completely off. A reset or reboot is not sufficient. Not that any applicable server hardware may need a BIOS upgrade from 2008 or all servers now have these features enabled by default.

### Certified for Windows 2012
If you want to be really sure that the servers you can run Hyper-V, you should check directly with your vendor. They are responsible for testing that Hyper-V actually runs on their hardware. Most vendors also participate in the "Certified for Windows Server 2012" program, which requires them to test their hardware using Microsoft-standard procedures. After the server passes the test, the vendor can check the configuration for inclusion in the public catalog. However, no vendors submit all of their hardware. That's why you should ask them directly. At http://windowservercatalog.com, you can search for Hyper-V-compatible systems.

### RAM
When deploying Hyper-V, you must ensure that your server has the minimum requirements for running Windows Server 2012 R2 as outlined in Chapter 2. Once you have enough RAM to keep the operating system running smoothly, you need to work out how much additional memory is needed for each of your virtual machines. For a low-end personal testing server dedicated to virtualization, you should probably select something with least 8 GB of memory and a single- or dual-socket CPU motherboard with quad-core CPUs.
