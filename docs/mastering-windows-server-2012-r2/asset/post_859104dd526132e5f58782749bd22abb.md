```
PS C:\Users\Administrator> $pw = Read-Host "Please Enter The Password" -AsSecureString
```

```
PS C:\Users\Administrator> New-ADUser "Philipp Witschi" -SamAccountName "Pwitschi" -GivenName "Philipp" -Surname "Witschi" -DisplayName "Philipp\nWitschi" -Path 'OU=Users,OU=BigFirm,DC=bigfirm,DC=com' -UserPrincipalName -AccountPassword $pw -Enabled 1 -ChangePasswordAtLogon 1
```

The first line prompts the administrator to enter a password. When the text is entered, the $pw variable will be a variable or a container where you want to store a value. The Read-Host cmdlet will prompt you for a value. -AsSecureString will convert the value you entered in response to the prompt to enter a secure string. $pw will be stored in memory by this PowerShell session until you overwrite the value or close the PowerShell window.

When you run the command, you're prompted to enter the password. Respond with an easy-to-communicate string that meets the password complexity and length requirements.
The second command will create your user. You can add a few flags to meet your requirements:

- **AccountPassword**: Use the $pw from the previous command. This passes your desired password for the new user object in a secure format.
- **Enable**: This takes either a 1 (user object to be enabled) or 0 (user object to be disabled) value.
- **ChangePasswordAtLogon**: This takes either a 1 (a force password change) or 0 (do not force a password change) value.

The result of this is that the user object is created with your desired password and is enabled, the user will be forced to change their password when they log in for the first time.
It seems wonderful to run two commands, doesn't it? It would be for just one. But by this approach, you can repeat it for the other users you want to create. Each one would have the same password.

If you wanted to create just one, then you could do everything in one command. This approach will take advantage of PowerShell's speed. You'll need the Read-Host cmdlet:

```
PS C:\Users\Administrator> New-ADUser "Philipp Witschi" -SamAccountName "Pwitschi" -GivenName "Philipp" -Surname "Witschi" -DisplayName "Philipp\nWitschi" -Path 'OU=Users,OU=BigFirm,DC=bigfirm,DC=com' -UserPrincipalName -AccountPassword (read-host "Please Enter The Password") -AsSecureString -Enabled 1 -ChangePasswordAtLogon 1
```

Please Enter The Password: *************

What you've done here is substitute the Read-Host cmdlet for the $pw variable, as in the previous approach. This will cause the Read-Host cmdlet to run before the New-ADUser cmdlet can complete and then enter the secure string as a value for the -AccountPassword flag. When you run the command, you are prompted for a password, and then the user object is created.

## NOTICE THE HEADER ROW

The header row is the same as the variables used earlier with the New-ADUser cmdlet. The rows below the header row in the CSV file contain the values for creating each user. Now you want to run a command that will read each row from the CSV file that you've saved. The command will execute the New-ADUser cmdlet using the values:

```
PS C:\Users\Administrator> Import-csv c:\users.csv | foreach {New-ADUser -Name $_ -SamAccountName $_ -GivenName $_ -Surname $_ -DisplayName $_ -Path $_ -UserPrincipalName $_ -AccountPassword (Convert-SecureString $_.Password -PlainText -Force) -Enabled 1 -ChangePasswordAtLogon 1}
```

Don't let the size of this command confuse you. It is simple once you understand how to break it down into its components:

- **Import-CSV**: This PowerShell cmdlet reads the CSV file you created and saved as c:\users.csv. This gives you the ability to feed the results into another cmdlet.
- **Foreach**: This cmdlet takes the CSV file, reads it as items (excluding the header row). The Foreach cmdlet will now run using each row as a parameter.
- **New-ADUser**: You know this command will create a user. Each flag in the New-ADUser cmdlet requires a value. You know that you have assigned the header to the CSV. Each of the entries in the command refers to an object in PowerShell and $_Name represents the property of the object. For example, $_Name refers to the value from the first row.
- **AccountPassword**: You're again converting the password value to a secure string. The users will have their password set, enabled, and then forced to change the password when they log in.

Nothing is stopping you from adding columns to the command to further populate the attributes of the user object, such as roaming profile, directory, and so.

Using this approach, you could manually or automatically (using some export tool from a personnel system) create this CSV file and run this one command to create many user accounts. That's what PowerShell is all about: making work easier by automation.

## Unlocking a User Account

You can also use PowerShell to do the mundane work. If you want to unlock a user account, you can run the following:

```
PS C:\Users\Administrator> Unlock-ADAccount -identity SRed

The identity flag takes the name of the user to unlock. In this example we've used the friendly name. You might want to use the DN to identify the user object:

```
PS C:\Users\Administrator> Unlock-ADAccount -identity "CN=Steve Red,OU=Users,OU=Bigfirm,DC=com"
```

You can reset a user's password using this command:

```
PS C:\Users\Administrator> Set-ADAccountPassword -identity SRed -resetnewpassword (read-host "Please Enter The New Password" -AsSecureString)
