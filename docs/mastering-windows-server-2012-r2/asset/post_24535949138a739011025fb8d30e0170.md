Within each SMTP virtual server, one or more domains must exist to associate the related file system directory for mail delivery to a particular qualified domain name (FQDN). By default, the initially created SMTP server will only have one domain—that of the resident machine's FQDN.

Differing security and delivery limit requirements of additional domains may dictate which domains should be served by SMTP virtual servers. Before deciding which you should know which virtual servers will affect the domains. Each new virtual server will store its configuration settings in IIS 6-compatible database.xml file under a IISSMTPServer element with a Location attribute of /Lm/smtSvc/{number} where a sequential integer is assigned to new virtual servers in creation order. Feel free to create as many virtual servers as can be assigned to unique combinations of IP addresses and TCP port numbers supported by the server.

If you find that all email conforms to the same restrictions and limitations can be served by a single virtual server, then using the default SMTP Virtual Server #1 constructed is the easiest way to go. ## AUTHENTICATION

SMTP services can be configured to demand authentication from other SMTP hosts attempting to transfer messages to it for security. By default, any anonymous access is permitted, allowing any and all SMTP servers that want to push email messages for supported domain namespaces to flood the directory with items. In a secure environment and for auditing purposes, you may need to enforce an authentication method so that other SMTP hosts are required to identify themselves before being allowed to forward messages to your SMTP service.
