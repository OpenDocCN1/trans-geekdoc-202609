For about 15 minutes, he got a page from the afternoon support person that the main server at one location was down and he could not log in or see it using the ping command. He drove fearing the worst, only to arrive and see that production was going and nothing needed to be done. Those critical files needed for that's production were from another server.
The server was restored the next day (a problem with the motherboard) and the company missed a beat. The time that would have been required to restore from backup would have doubled the mean time to restore (MTTR) and cost millions of dollars in lost production. Those included the people who could not work in the plants because of the missing data. If you want the data in play, feel comfortable using the DFS function.

# Choosing Stand-Alone vs. Domain-Based DFS

Before begin making a DFS system, you need to decide which kind of DFS you want. This decision will be primarily based on whether you have an Active Directory. The big difference is going to be on the root of the DFS. In an Active Directory-based DFS or domain-based DFS, the root itself can have replicas. In other words, that single point of failure—the root—has spread out into the Active Directory. Using root replicas, if you have 27 places where every DFS information lives. Well, it's not all DFS information; it's enough information to point clients to all of the DFS replicas. With, as long as the Active Directory is alive and available, the DFS is too. Also, when integrated into the Active Directory, the File Replication Service takes over the synchronization of the contents of replicated folders to ensure that all replicas contain the same information. It might be safe to say that if you have an Active-based domain, you should choose domain-based DFS.
But here's the really cool part of an Active-based DFS. If you host your DFS in the Active Directory of the test domain, do not only your users need to know which server a particular share is on, but also which server the DFS is running on. Instead of making a drive to \server\DFSName, your users could map a drive to \test.com\DFSName. Now, using the same logic you can use to find an available controller for Active Directory, the client can search for all of DFS. If one fails, the client just calls on.
A-based DFS automatically publishes its topology in Active Directory. What this means is the actual DFS hierarchy—the roots, links, and targets—is published into Active Directory so that all controllers will know where the DFS lives, what it looks like, and how to get to it. It doesn't every controller is a DFS replica server.
