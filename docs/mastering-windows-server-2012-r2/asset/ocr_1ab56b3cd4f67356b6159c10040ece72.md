These backup types can be run manually on demand, or they can be scheduled either using Windows Server Backup or wbadmin.exe and Scheduled Tasks.

# LIMITATIONS OF DIRECTORY BACKUPS

You can use either Windows Server Backup or wbadmin.exe to perform a system state backup of a domain controller to back up Active Directory. Microsoft recommends using a dedicated internal disk or an external disk such as a USB hard drive to perform the backups. External disks have the advantage of being easily backed up for off-site storage as part of your disaster-recovery plan; however, they don't travel well in comparison to the more traditional tapes, make sure you have a solid transportation plan in place.

You must have administrative credentials to schedule a system state backup or restore; backup operators do not have privileges required to schedule backups. System state backups will back up Active Directory integrated DNS zones but will not up file-based DNS zones. File-based DNS zones must be backed up as part of a volume-level backup, such as a critical volumes backup or full server backup.

# Introducing the Active Recycle Bin

If you have ever to accidentally delete an object from your backups and then had to recover that object it's not one of the most pleasant tasks that you've ever had to carry out in your IT career. Frankly, in Windows Server 2008 R2, Microsoft introduced the Active Directory Recycle Bin to provide protection for deleted objects in the same way as you utilize the standard Windows Recycle Bin for your files and folders.

A downside for some people with the Windows Server 2008 R2 version of the Recycle Bin, though, was that it had to be managed fully through PowerShell. In Windows Server 2012, you have GUI management of the Recycle Bin through the Active Directory Administrative Center (ADAC), which ultimately makes managing deleted objects an easier task.

# AD RECYCLE BIN OR SYSTEM STATE?

If you're wondering the need to have a system state backup if you've configured the AD Recycle Bin, then think again. The AD Recycle Bin should be a supplementary offering to your normal AD backups and should not be used as the primary recovery method. This is because you might have a situation where the Recycle Bin is unreachable. To reach the Recycle Bin, you need to be logged on to the domain, and if the domain has fallen over, there's no Recycle Bin!

Without the Active Directory Recycle Bin and in earlier versions of Windows Server that didn't support it, when you deleted an object, it was flagged for deletion (tombstoned) rather than being immediately deleted. Tombstoned objects are permanently deleted when the garbage-collection process runs.
