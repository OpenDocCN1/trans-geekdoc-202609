## UNDERSTANDING THE STANDARD SECONDARY ZONE

The secondary zone is the read-only copy of the standard primary zone or an Active Directory integrated. Replication is performed through the zone transfer process, which is configured on the zone's properties. On Windows DNS servers, the default setting for zone transfers is to only register the name servers of the zone, as shown in Figure 6.14.

You can add a new server, such as EC1.Coast.Bigfirm.com to the Names tab, as in Figure 6.15, to permit replication to this server.
Once that is accomplished, you can run through the New Zone Wizard to create a secondary zone on EC1. This will require the master server's IP address, which would be the server to request the zone transfer. It doesn't necessarily have to be the DNS server with the standard primary zone. The result is a successful transfer of the zone to EC1, as shown in Figure 6.16.

The zone transfer process is not complex. For the primary zone changes it has made and has a serial number for the change. When a secondary server contacts the primary server, it checks out the serial number in the Start of Authority record. If the serial number on the secondary server doesn't match, it will replicate the changes. This is simply a text-based blast of DNS supported (all zone transfers) replication, which meant the entire zone was replicated to the secondary server. This could be too much traffic to throw onto the line. Windows DNS supports IXFR (which are incremental zone transfers), which replicates just the changes. Windows DNS also supports notification of secondary servers, which reduces the wait time to trigger replication.

## UNDERSTANDING ACTIVE DIRECTORY INTEGRATED

The third zone, Active Directory Integrated, is the predominant implementation of Windows DNS servers. The name Active Directory says it all:

- First, the DNS records are stored in the Active Directory database rather than a text file.
- Second, the zones are replicated to all other Active Directory domain controllers in the domain rather than zone transfer process.

Since the Active Directory database uses multicast replication, changes can be made to the DNS zone on any domain controller, and with the integration of DNS in Active Directory, the coupling of DNS and domain controllers became the norm. For more information concerning the replication process, refer to Chapter 22.

Like the standard, an Active Directory integrated zone can be created with the New Zone Wizard. On the first page of the window, shown in Figure 6.17, it says “Store the zone in Active Directory”–check box.

If you want to create a custom partition, use the Add-DNSServerPartition cmdlet. The name of it doesn't have to match the zone; use the following command:

```powershell
c:\administrator> Add-DNSServerPartition -Name "adintegrated.local"
```

Once the partition has been created, you can assign the zone to it, as shown in Figure 6.20. Let's say you want to add these two zones:

- adintegrated.local, which is placed in its own application partition
- 192.168.0.0, which is placed in the forest partition

First, add the server to the Names tab in the properties of the desired zone, similar to Figure 6.15.

Then, use the following command to list the available partitions on EC1:

```powershell
c:\administrator> Get-DNSServerPartition
```

From the output, there are four application partitions. The first one is one created earlier, which the server has enlisted for sharing. The second is the domain partition that is shared with all of domains. The third is for the Bigform.com domain. The fourth is for all domain controllers.

## USING STUB ZONES TO INTEGRATE WITH OTHER DNS SERVERS

The stub zone is an improvement that was first introduced with Windows Server 2003. Its concept and functionality haven't changed in Windows Server 2012 R2, and essentially it's an additional method to integrate with other DNS servers. The stub zone lists only the name server for a given namespace. It holds no control over the zone, so it indicates only server could support name resolution for the namespace. Like conditional forwards, it provides a lateral communication to the authoritative DNS server. These zones can also be replicated between domain controllers.

The New Zone Wizard sets up the stub zone with the following parameters:

- Type of zone: Stub
- Optionally stored in Active Directory with the desired application partition
- Name of the zone, such as Apex.com
- DNS server that supports this namespace

Once the stub zone is created, you can view its contents, as displayed in Figure 6.19. It lists the Start of Authority for the namespace, the name server for the namespace, and a host record for the name server.

## USING REVERSE LOOKUP ZONES TO INCREASE SECURITY

You may have noticed that the zones we created were found in the Forward Lookup Zones folder within the DNS management console. A forward lookup means the client a fully qualified domain name and the DNS server returns an IP address. A reverse lookup does the opposite: the client provides an IP address, and the DNS server returns an FQDN.
