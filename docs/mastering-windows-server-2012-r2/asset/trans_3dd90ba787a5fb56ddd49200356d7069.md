# 是再次需要密切关注的时候了

我们必须重复这一点：尽管你将用户、计算机和组视为 SRed、SERVER01 或 Fileshare 等相对熟悉的名称，但 Windows 并非如此 true。它通过 SID 来识别这些安全主体。每当创建一个新的安全主体时，都会创建一个唯一的 SID。这意味着如果你创建了 SRed，删除了它并重新创建它，Windows 将认为旧对象和新对象是两个不同的安全主体。你认为它们是同一个，但它们并不是。结果是，分配给账户的权限不会被该账户保留。

图 8.53 中的弹出窗口警告了你这一点。在删除安全主体之前，必须确保组织 100% 确定不再需要该安全主体。需要知道的是，一旦删除组，其分配的权限以及组成员关系将会丢失。任何通过此组组成被授予资源（如文件共享）访问权限的用户将失去对该资源的访问权限。

以下 localgroup 命令将在不发出任何警告或信息请求的情况下删除 Fileshare 组：

```bash
net localgroup fileshare /delete
```

# 活动目录组

Active Directory 的基本概念是将许多对象以与本地组相同的方式进行集合处理。然而，你可以利用 Active Directory 组完成许多很多工作。这是因为这种类型的组存储在 Active Directory 域控制器中，并且部分域控制器被配置为全局目录缓存（global catalogs）。这使得一个组可以包含许多基于域的安全主体（如用户和计算机），并可用于该组所在域内的所有计算机。事实上，你可以在其原生域之外使用这些组，甚至有一类组可以包含森林中任何域的成员。

出于本节的考虑，你应该假设当我们使用“组”时，指的是“活动目录组”。以下是两种基本的组类型：

**分发组 (Distribution Group)** 分发组用于将若干对象单元集合在一起。邮件服务器（如 Microsoft Exchange）可以将分发组呈现为一个目标地址。用户可以选择向分发组发送邮件，邮件服务器将邮件发送给组内的所有成员（假设他们已配置了电子邮件地址）。

**安全组 (Security Group)** 安全组也可以执行邮件分发功能。但这种类型的主要目的由其名称决定。你可以使用安全组为对象或一组对象（如组织单元、文件夹或应用程序组件）分配权限或权利。这使得 Active Directory 不仅成为你网络的单一身份验证机制，还成为你的授权机制。终端用户可以使用单个用户账户获取整个 Active Directory 森林中受保护资源的授权，而不仅仅是限于单个域或单台计算机。

# 管理组

还有三种组的作用范围需要处理：

**域本地组 (Domain Group)** 域本地组旨在仅在其创建的域内使用。它可以包含来自森林中任何域的用户/计算机账户、全局组和通用组，以及来自同一域的域本地组。

**全局组 (Global Group)** 这是你你在 Active Directory 中创建组时的默认作用范围。全局组可以被其所属域内的计算机使用，也可以被 Active Directory 森林中其他域的成员使用。它可以包含来自创建该全局组的所在域的用户/计算机账户。

**通用组 (Universal Group)** 有一点点使得通用组与另外两种组类型都截然不同。另外两种类型都存储并复制到其创建的所在域内的所有控制器上。而通用组则存储在配置为全局属性的域控制器上。这意味着通用组会被复制到整个森林中的各个域。这允许通用组不仅被森林中的所有计算机使用，还可以包含森林中任何域的成员。

# 关于通用组的警告

在较大的环境中设计通用组时必须非常小心，因为当你创建或修改它们时，会增加复制负载。Active Directory 只会同步通用组的更改，但仍需注意大规模的更改。你还需要确保启用了全局目录的域控制器对于高度依赖它们的服务是可用的。

单域网络不需要过于担心通用组，因为它们的内容不多。通用组可以包含来自森林中任何域的用户/计算机账户、全局组和其他通用组。

你可能注意到了其中的某点。组可以包含其他组。这通常被称为“组嵌套 (group nesting)”。为什么要考虑这样做呢？这里有两点需要考虑：

**同时管理多个组** 假设你的组包含“账户管理”和“销售管理”。你能够同时处理它们，也许为所有被你视为联系人列表的项目设置一个电子邮件地址。你可以创建一个名为“管理”的组，并将这三个账户都作为成员。你可以为“管理”组配置一个电子邮件地址。

**管理不同部门的组织单元** 另一个场景（如图 8.54 所示）是你为不同部门创建了组织单元；例如，假设你有 \BigFirm，它包含 \BigFirm\Accounts 和 \BigFirm\Sales。IT 有两个层级。BigFirm 有一个运行 Active Directory 和 IT 功能的部门。你在这个部门工作。Accounts 和 Sales 都有 IT 团队，他们只能管理自己的 OU。这种被称为“委派”的机制允许你拥有一个名为“管理”的组，其中包含所有部门的经理。你不想管理这些成员，而是希望部门的 IT 人员来管理这一过程。你可以在 \BigFirm\Accounts 中创建“账户管理”组，并在 \BigFirm\Sales 中创建“销售管理”。这允许部门管理那两个组。在 \BigFirm 中创建“管理”组。现在你可以将部门组作为“管理”组的成员。

如你所见，Active Directory 组比本地组要复杂得多。在创建组之前，理解你为什么要创建组以及该组将如何被使用非常重要。你可以更改组的作用范围和类型，但你必须理解其影响，因为从全局组更改为通用组将改变 Active Directory 的复制方式从“域内的域控制器”变为“全局目录服务器”。这种额外的规划是值得的，因为你将继续阅读这本书的后续内容。随着时间的推移，你会发现将组用于各种用途：

- 创建包含整个森林成员的邮件分发组
- 为部署操作系统分配权利
- 控制哪些计算机将自动部署 Microsoft Visio
- 控制谁是组策略对象的范围
- 向他人委派 Active Directory 部分的管理权限

你可能认为组嵌套的概念听起来非常复杂棘手。当你将其与组的描述性命名标准相结合时，你可以创建一个非常易于部署和管理且允许细粒度委派的组机制。
