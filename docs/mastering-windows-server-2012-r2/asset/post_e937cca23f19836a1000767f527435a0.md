# An Introduction and Active Directory Basics

A way to get started is to define the terms and definitions. Because Active Directory uses many specific words, we are going to explain the vocabulary that administrators need to know.

**Workgroup** A workgroup is basically one or more computers on a Windows network (LAN) that are not joined to a domain. Every computer resides on itself, so there is no dependency among them. For example, computer 1 has a local user Joe and computer 2 also has different users. These users use the same name and are the same person but completely different. If you want to manage these users' passwords, you'll need to connect to or log onto each computer console and change the password. There is no way to manage these users.

**Domain** A domain is a collection of objects that share the same domain. That means that in our workgroup example you would create one Joe in the central Active Directory and connect workgroup computers 1 and 2 to this. Why use a domain? If all objects are managed centrally, you don't need to connect to or walk to each to change the user's password. There is much more to do, but to get the best understanding, this example illustrates it well.

**Active Directory Domain Services** Active Directory Domain Services (AD DS) is a service that is integrated into the Windows Server operating system but not not installed by default. If you are promoting a Windows server to a domain controller, either to an existing domain or are going to a completely new domain, you must create the AD, the Active Directory database on the server, and many other components that are needed for Active Directory to function properly. Because Active Directory is running as a service in the background, you can stop and start it. This is a huge improvement because you don't need to boot into recovery mode for Active Directory authoritative restores or database maintenance tasks; just restart it and perform your operation.

Every domain controller has its copy of the Active Directory database that is dynamically updated by other domain controllers. Because all of the Active Directory joined integrated systems depend on Active Directory, it is essential to have at least two domain controllers for redundancy purposes. Otherwise, if one controller fails and it was the only one, your environment goes to a halt.
