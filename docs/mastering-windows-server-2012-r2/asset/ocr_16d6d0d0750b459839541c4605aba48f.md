4. In your Terminal session type in the following command:

```
Dsconfigad -aladmins enable -groups BigAdmin@Bigfrim.com, Enterprise BigAdmins@bigfrim.com
```

The commands require you to use cleartext passwords, so if your Active Directory does not allow them, you will have to set this up to be enabled for Services logging. Another tool that is commonly used is audit. This command will look at the internal state of directory services and records, allowing you to enable logging and change your statistics.

5. Run the following command:

```
odutil set log debug
```

This command will set log logging on the device to Debug mode, so if you have any issues connecting to your Active Directory domain, you can run debugging-event depth detailed logs. The logs for odutil are stored at /var/log/opendirectory.log.

# Connecting to File Shares

Once your Mac client is part of the Active Directory domain, connecting to shared folders is almost the same process as connecting to an OS server. The single exception is that you must specify that the Finder will use the SMB protocol to connect to the share. Use the format sm://servername/sharename to define the path, similar to Figure 18.39.

To connect your Mac client to a Windows Server 2012 shared folder, follows these steps:

+   1. In the Finder, click the Go menu, and then click Connect to Server.

+   2. Type the path to the shared folder using the format sm://servername/sharename.

+   3. Optionally, click the plus sign (+) to add this to your list of favorite servers. If you do, you will be able to click the server name in the list, and then click Connect.

+   4. Click Connect.

+   5. Provide your Active Directory user credentials, and click OK.
