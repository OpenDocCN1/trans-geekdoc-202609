## A WEB SERVER FOR IIS

We will be using the Service GUI to create two websites on Windows Server 2012. Website 1 will be dedicated to applications and website 2 will focus on IIS.

To begin, launch Server Manager, and add Roles and Features from the Manage menu to add the Web Server role to the server, as shown in Figure 19.1. Alternatively, you could use PowerShell to install IIS and even write scripts for automatic or remote installation (more on PowerShell).

## FIGURE 19.1 Manage task list from the service manager

![](img/41a83208e6906a3732620203b836cea7_1020)

1. On the Before You Begin page, click Next.
2. On the Installation Type page, click Next.
3. On the Server Selection page, click Next to accept the server target as the local server.
4. Select Web Server (IIS) on the Roles page, and click Next.
5. In the resulting pop-up, select Add Features to install the IIS Management tools over the IIS server, and then click Next.
6. On the Web Server (IIS) page, click Next to advance the wizard.
7. On the Roles Selection list, select all of the role services, and click Next to continue (see Table 19.1 for an explanation of each).
8. On the Confirm page, review your selections and click Install.
9. On the Installation Progress page, confirm that the installation was successful, and click Close.

## Installing IIS 8 via PowerShell

As with other features in Server 2012, you can install, configure, and remove IIS 8 using PowerShell. To install IIS from PowerShell, simply run the following command:

```
Install-WindowsFeature -Name Web-Server -IncludeManagementTools
```

This will install the Web Server role with all of the default options, exactly installing the Web Server role via the GUI. To add additional features to a running IIS server, run the Install-WindowsFeature cmdlet with the name of the feature you wish to install. Table 19.1 contains a list of all the web server feature names, or you can run the following PowerShell command to see them:

```
Get-WindowsFeature -name *
```

## Refining IIS Construction

Altering the construction of IIS is as easy as using the A/C adapter of your laptop computer for plugging in your mobile phone charger instead! Feel free to add or remove modules for exploration, testing, or actual production. The addition of a feature to IIS is not a permanent decision. You can remove the feature by deselecting the check box.

If you did not perform a full installation of all Web Server services in the OS when you initially installed IIS, then you will need to add the appropriate role service before that role service's associated native modules will be available to add to IIS. The “Adding Services to the Web Server for IIS” section shows how to register a native module using the OS, allowing Windows Server 2012 to trust the code and give it unrestricted access to all resources. With any code, be careful to register only native IIS modules from trusted sources because they will have privileged access to the system.

## Add Role Services to the Web Server Role for IIS

In order to configure the website in our example, you will need ASP page support on the website until you rewrite some of the content, and then you will use HTTP Redirection to point visitors to the new content it is written. You can add role services to an applied role server via the Web Server Manager, AppCmd.exe, or PowerShell. For example, to add the ASP role service to an existing web server role on the IIS server by the Web Server Manager, follow these steps:

1. Launch Server Manager.
2. Select the IIS role in the left tree pane.
3. Scroll down to the right details pane to reach the Role and Features section for a summary of the web server roles that are installed, as shown in Figure 19.2.

![](img/41a83208e6906a3732620203b836cea7_1021_0)

4. Click the Tasks drop-down menu on the role and select Add Roles and Features.
5. In the Roles and Features Wizard dialog box that pops up, advance to the Roles page, and select the ASP role service located under Web Server (IIS)\Web Server\Application Development.
