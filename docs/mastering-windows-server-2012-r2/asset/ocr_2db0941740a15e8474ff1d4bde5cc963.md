Also enabled by default is the "Allow management operating system to share with this network adapter" option. Leaving this means the host can access this switch, meaning traffic between the VMS and their host operating system is shared. In a lab or non-production environment where you might have only one NIC available, leaving this option should suffice, but if you have more than one NIC or running a production Hyper-V environment, it is recommended to enable this option by unchecking the box and clicking Apply.

+   4. If you want to create a new virtual switch instead of using the one you created during Hyper-V setup, in the Virtual Switch Properties pane, change the switch name and from the drop-down menu choose the particular NIC you will connect to.

An annoyance here if you have a number of physical NICs that you're presented with a list of NIC device names instead of the first description that you might have given your NICs in the Network Connections app. This makes it difficult to identify which NIC you want to assign to the new virtual switch, but if you use the Get-NetAdapter -Format-Table -Autosize cmdlets in PowerShell, you can see a list of NIC device names mapped to their more descriptive friendly names.

+   5. Once you've selected your virtual switch type and configured it, click the OK button to finish the process.

# PowerShell Tip

You can create a new virtual switch that isn't sharing connectivity with the Management OS using the following in PowerShell:
New-VMSwitch -Name "VMEXT1" -AllowManagementOS $false -NetAdapterName "Local Area Connection 2"
