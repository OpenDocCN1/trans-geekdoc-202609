# CHAPTER 9 GROUP POLICY: AD'S GAUNTLET AND ACTIVE DIRECTORY DELEGATION

As we pointed out before, Domain Admins and Enterprise Admins have Read and Modify permissions, and Authenticated Users have Read and Apply Group Policy. However, notice that you only see Authenticated Users in the list. Why is that? Well, this is a list of the users, computers, and groups that have permission to apply the GPO settings. To view the full ACL, you must first select the Delegation tab and then click the Advanced button. The 'Security Settings' dialog box will display, as shown in Figure 9.16.

It may happen that you create a GPO to restrict desktops and you don't want to apply it to a certain group of people. The Authenticated Users group includes everyone (user and computer accounts) but guests, by default the GPO will apply to everyone but guests; however even Domain Admins and Enterprise Admins will receive the policy. To prevent Domain Admins and Enterprise Admins from receiving this policy, you will only select the Deny box for both groups or one of the two, but you'll need to select the Deny box for both groups if the members of Domain Admins and Enterprise Admins are not the same people. To 'excuse' others is not enough to select the Allow box for Read and Apply Group Policy; the users in your special security group are also members of Authenticated Users, so you actually need to choose the Deny option for them as well. Deny takes precedence over Allow.

As an alternative to ACLining, remove the Authenticated Users group from the Security Filtering part of the Scope tab, add all the users who need to have the settings to a security group, and then add that security group to the Security Filtering part of the Scope tab This is shown in Figure 9.18.
