## Enforcing Blocking Inheritance

Just as security filtering is used to counter the blanket application of policy, Block Inheritance is a special setting on an AD node (domain or OU) to prevent higher-level GPOs from trickling down. When the Block Inheritance is set, the settings of higher policies will not be applied to lower containers at all. For example, if you create a GPO for a specific OU, say Brunswick, and set up all the necessary settings for the Brunswick OU, and then you want to prevent the main domain GPOs from affecting the Brunswick OU, enable the Block Inheritance setting on the Brunswick OU. The only GPOs applied will be those linked to the Brunswick OU.

There is also a counter to the Block inheritance configuration. When Force is turned on for a GPO, the Block Inheritance is neutralized for the enforced GPO. Also, the settings in subsequent GPOs are prevented from reversing the ones in the enforced GPO. For example, if domain admins have a set of highly restrictive settings turned on at the domain and rogue Brunswick admins set their own OU with ours policy settings and select the Block Inheritance, the Brunswick OU effectively manages the disputed settings, but only until the domain admin manages and sets the Force setting. The domain admin lives like OU people, who have the same restrictions as everyone else: Force beats Inheritance (just like force beats coverage).

Like all secret weapons, the Force and Block Inheritance are best used sparingly. Otherwise, in a troubleshooting situation, it becomes rather complex to determine what GPOs are applied. This could be detrimental to the mental health (and potentially the job security) of a network administrator.

Wew! Here's a summary of the factors that can decide which Group Policy object wins:

- Within any node, examine policies in this order: site, domain, then OU.
- If a setting is also specified in multiple policies, the last one heard takes precedence.
- If-enforced GPOs are used, they override the inheritance settings.
- To view the full ACL, use the Delegation tab and click the Advanced button.
- Deny always takes precedence over Allow.

## Decrypting User and Computer Configuration Settings

Windows Server 2012 and Windows 8 come with a completely new look and feel for User and Computer Configuration settings in GPME. The reason for this is that Microsoft has done us all a huge favor! The reason for this is that Microsoft introduced nearly 3,000 GPO settings. To give you a better grip on the volume of settings, Microsoft has also adjusted how the settings are presented.

As you in Figure 9.19, there are two main nodes to the GPME interface: Configuration and Computer Configuration. Both have the following subnodes: Policies and Preferences. The Policies subnode is further broken down into the following subnodes: Software Settings, Windows Settings, and Administrative Templates. The Preferences subnode is broken down into these subnodes: Control Panel and Windows Settings.

The difference between the two levels of nodes is this: settings for User Configuration apply to user accounts, and for Computer Configuration apply to computer accounts. For example, if registry settings are involved, as is the case with administrative templates, the changes will be written to HKEY_CURRENT_USER (HKCU) for User Configuration and to HKEY_LOCAL_MACHINE (HKLM) for Computer Configuration settings. You may want to create separate GPOs for machines and users to keep things straight.

## Group Policy Setting Possibilities

You can basically do anything with policies. Here are a few examples:

- Deploy Software: You can use GPOs to install a package of software into a server.
- Restrict the Applications That Users Run: You can control which applications users can run.
- Control System Settings: The easiest way to control disk quotas with GPOs.
- Set Logon, Logoff, Startup, and Shutdown Scripts: GPOs allow any of these four events to trigger a script.
- Simplify and Restrict Programs: You can use GPOs to remove many of the features from Internet Explorer.
- General Desktop Restriction: You can remove all of the items on user's Start button, keep her from adding printers, or disallow her from logging out or modifying her configuration. (Too much locking may lead to unproductive employees, so be careful.)

There's more to work with policies, but that was a basic introduction to get you started.
