# Monitor and Manage

This section of the IPAM console enables you to monitor and manage the DHCP and DNS servers that are under IPAM control. Here you'll find a centralized location that will enable you to carry out one of the standard tasks that you previously would have needed to run from each individual server—particularly related to DHCP management. There are four different views to work with.

# DNS AND DHCP SERVERS

This view shows a list of DHCP and DNS servers and has a Server Type to allow you to see the specific DHCP or DNS servers. If you right-click a DHCP server in the list, you will be presented with a number of management tasks for that particular DHCP server that will allow you to edit your DHCP scopes, create DHCP scopes, and configure user and vendor classes, but to name a few. Figure 5.22 shows the full menu of choices.

You can also use the MMC snap-in for both DHCP and DNS by right-clicking a server and choosing Launch MMC. The Details view provides information on the particular server that you have selected, as Server Properties, DHCP Options, and DNS Zones.

# DHCP SCOPES

This view brings together all of the DHCP scopes IPAM knows about. You can see key information about each scope's utilization and configured DHCP scopes. There are dedicated sections for IPv4 and IPv6 scopes, and you can filter the views here by private, global, and unmapped address space.

You can perform a number of management actions from this by highlighting a particular DHCP scope and right-clicking it. Some of these can be carried out on multiple scopes at the same time, and others be performed on one scope at a time. Here are some of your options:

- Edit DHCP Scope (can run on multiple scopes at once)
- Duplicate DHCP Scope (must be run on single scopes one at a time)
- Activate DHCP Scope (can run on multiple scopes at once)
- Replicate DHCP Scope (must be run on single scopes one at a time)
- Deactivate DHCP Scope (can run on multiple scopes at once)
- Delete (can run on multiple scopes at once)
- Create DHCP Reservation (must be run on single scopes one at a time)
- Configure DHCP Failover
- Clear Sync Errors

# DNS ZONE MONITORING

Here you can see a centralized view of all the DNS forward and reverse lookup zones that IPAM manages. For each zone, you can view the health status (healthy, warning, or error state), the duration it has been in that particular state, information about the server it's running on, and the type of zone it is. If you want to perform any management here, unlike with DHCP, the only actions you have are Launch MMC, Reset Zone Status, and Retrieve Server Data. Once you launch the MMC, it will scope the connection to the zone you had highlighted, and you can then administer the particular zone as you would if you were logged locally on the DNS server.

# MONITORING DNS WITH IPAM or System Center Operations MANAGER?

You might be wondering if this DNS monitoring is a substitute or replacement for something like Microsoft System Center Operations Manager. If you already have Operations Manager deployed, IPAM DNS monitoring is definitely not a substitute for it. Operations Manager is Microsoft's flagship monitoring and management tool that delivers IT service modeling based on their own best practices and recommendations. It takes into account a lot area of centralized actions and IPAM DNS zone monitoring. Chapter 30, "Windows Server 2012 R2," discusses this product in more detail.

However, if you don't have Operations Manager deployed or the cost implications of deploying System Center 2012 are prohibitive, IPAM DNS zone monitoring is a good starting point to give you a basic central overview that may be more sufficient for your particular environment.

# IPAM Delegation

When you install the server role, the installation process automatically creates a number of security groups that can be used to deliver Role-Based Access Control (RBAC) of your IPAM environment to designated users. Depending on the type of administrative privileges you want your users to have, all you need to do is add their accounts to the appropriate security group. Figure 5.24 shows these groups on the IPAM server, and here's a breakdown of what each one offers:

# IPAM Security Groups

IPAM Administrators Most likely, you will want to ensure that your own account is a member of the group. Members of this group have permissions to fully manage and administer IPAM and can run tasks and views.

IPAM Audit Auditors Members of this group can perform common IPAM management tasks and also have access to the IP address-tracking information so they can carry out audits if required.

IPAM ASM Administrators Any user accounts that are members of this group can carry out tasks related to the IPAM Address Space Management (ASM) functionality.

IPAM MSM Administrators Any user accounts that are members of this group can carry out tasks across multiple IPAM servers through the IPAM Multi-Server Management (MSM) functionality.

IPAM Users This is the most basic security group for IPAM, and all users who are members of this group can essentially just view information on server discovery, ASM, and MSM. They can also see about the operational events that IPAM and DHCP generate, but cannot view any audit or tracking information.
