## Understanding SMB 3.0

Server Block (SMB) is an application-layer network protocol that is used primarily to provide shared access to files, printers, ports, and communication between machines on a network. SMB is commonly referred to as Common Internet File System (CIFS). This protocol is used primarily for Windows operating systems and servers as the basis for Microsoft's Distributed File System implementation.

SMB 3.0 has changed a bit in this server edition. Many new features have made this protocol a high-performance alternative to Fibre Channel and iSCSI appliances. Let's take a look at some of the new features:

- SMB Failover This feature allows administrators to perform maintenance on clustered computers without incurring any downtime. In the event of a cluster failover, the SMB 3.0 clients will automatically reconnect to another cluster without losing any access to the files they were using. Clustered file servers eliminate the single point of failure of having only one file server or a nonclustered environment.

- SMB Scale Out SMB clients are no longer limited to the bandwidth of a single cluster node. When clustered, the machines load balance between themselves using their aggregate resources. Every server in a file cluster is an active node serving content to clients. SMB scale-out file shares are always configured with the Continuously Available property set.

## Understanding SMB 3.0

SMB Multichannel This feature allows servers to use multiple network connections simultaneously, which greatly increases throughput since you can transmit data across multiple high-speed network adapters at the same time. This also means you have a new level of fault tolerance on the network. While using multiple connections at the same time, the clients will continue to work uninterrupted in the event of a connection loss. Another benefit of SMB Multichannel is automatic discovery. It will discover the existence of available network paths and dynamically add connections as needed.

- SMB Direct SMB Direct is a new transport protocol for SMB 3.0 that allows direct data transfers between servers with minimal CPU utilization and low latency RDMA-capable adapters are used. This makes a network file server capable of handling large storage for applications like Microsoft Server 2012 and Hyper-V.

- SMB PowerShell Cmdlets and WMI Objects Another big win in server 2012 is all the PowerShell cmdlets are now included with the operating system. The new SMB cmdlets allow administrators to manage and monitor file servers and files. You can also write scripts to automate file server administrative tasks. With the new WMI objects, developers benefit from the ability to create automated solutions for file server configuration and monitoring.

- SMB Encryption This new feature allows you to encrypt data in motion on a per-file or per-share basis. It will protect the data being transferred against eavesdropping and tampering attacks with IPSec or any other dedicated hardware. SMB Encryption is also very useful when remote users are trying to access data from unsecured networks. It will secure the data transmission from the corporate network resources to the user's remote network. If you recall from earlier in the chapter, we enabled SMB encryption by checking the box on Other Settings page of the New Share when creating new shares. This feature can also be directly enabled in Server Manager without the wizard.

- SMB Directory Leasing This feature uses BranchCache to provide faster access to documents over high-latency WAN networks. Directory leasing reduces communication round-trips from client to server over a WAN. The client caches directory and file metadata in a consistent manner for longer periods of time. The server notifies the client when information changes and initiates an update to the client's cache. This feature is designed to work with user home folders and published shares.

## Compatibility with SMB 2.0 and 1.0

To maintain backward compatibility, newer operating systems support both SMB 2.0 and SMB 1.0. To take full advantage of the features available in SMB 3.0, both the server and client must have and be able to use SMB 3.0. Table 13.3 shows which SMB version is used with operating system.

| Windows 7 Server 2008 R2 | SMB 2.1 | SMB 2.1 | SMB 2.0 | SMB 1.0 |
| Windows Server 2008 | SMB 2.0 | SMB 2.0 | SMB 2.0 | SMB 1.0 |
