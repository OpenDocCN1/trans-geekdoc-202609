As you can see, many options are available for per-user configuration. You will likely use a mixture of per-user and per-system configurations. For example, an OU containing Windows kiosks can be effectively locked down using Computer Configuration policies. An open office featuring "hot-desking" will probably rely more on the Use of Configuration policies. The reason is that a per-system policy will not suit the variety of users who use a single computer. It would be better to configure the users rather than the computers.

What method you use to test and develop your lockdown policy will determine the success of your deployment and how easy it will be to manage. You've seen just a small sample of the available settings. There are many more included with Windows Server 2012. More can be added via templates for applications, for example, for Microsoft Office. You can also implement custom templates for deploments by editing them yourself or using third-party utilities.

Our advice is that you build a lab environment that is identical to your production network as you can. This can be a virtual network, which would give you an opportunity to deploy Hyper-V! Building policies should be a gradual and deliberate process. Add one setting at a time. Only then can you test to see what true effect of the policy is. If you implement many policies at once how can you tell which one is causing a problem? You should test each one. apply the policies, for example, after a logon, or during a normal policy refresh. We recommend logging on several times because we have seen complex scenarios where a policy implementation can be inconsistent. You can use the Group Policy Management console to document your policies once they are complete and export them for implementation in your production network.

# Managing Users with Group Policy
Preferences and Login Scripts

So in this chapter you have seen how to set up network resources for a user, such as a profile, a home directory, and redirected folders. Other resources are available on the network, such as files shares, DFS namespaces, and printers. How do you connect a user to those? The traditional solution is to use login scripts that run each time the user logs in to map drives, printers, and registry settings, but there is a better way, Group Policy Preferences. Group Policy Preferences allows you to do all the things you used to scripts but with better control and processing, and it is the preferred method for managing the user settings in Server 2012.
