
Minimum Password Age: This is the minimum number of days a password must be used before the user can change it. The default is one day.

Minimum Password Length: This is the minimum number of characters a password must contain. The default is 7.

Password Must Meet Complexity Requirements: Enabled by default, this setting enforces rules about how a password must be created. For example, a password must not contain more than two consecutive characters that are part of the user's name.

It's an even better idea to encourage users to use passphrases instead of passwords. A passphrase is a combination of words that, in the exact right order, form the password. A passphrase which still has to meet password complexity requirements is harder and contains spaces; the passphrase can be harder for the bad guys to guess out. With vowel substitution (substituting some letters, namely vowels, numbers), users can create very complex phrases. For example, a good passphrase could be My G00d d0cg4th3 fr1sb3b3! This is easy to remember but long (29 characters), complex (because of the use of multiple words, spaces, and vowel substitution), and would be difficult to crack.

See Chapter 9, "Group Policy: AD's Gauntlet and Active Directory Delegation," for an example of creating a complex policy GPO.

Security considerations dictate that you never allow two people to use the same account. Even if those people never use the account at the same time (if they do, doubling up on account usage will cause all kinds of grief from profile changes), it is a bad idea. If one person uses an account, you will never know who is using what on the network—or attempting to use resources they're not authorized to. Security auditing requires a model of one account and one password for each user.

Incidentally, this advice about unique passwords for each user applies not just to ordinary users. To enable security auditing, all Windows Server administrators should have their own basic user account (instead of all administrators using the Administrator account). Best practice is to have a separate admin account for each user; here's an example:

- Normal User Account: KevinB: Kevin would use this account to log in to all of his business resources, email, and personal files.
- Admin Account A: KevinB: Kevin would use this account for logging into servers, making changes, or performing any tasks that require escalated permissions.

You should use Group Policy to require regular passwords. Although this model requires more account management, it allows you to track which server administrator did what and allows you to easily disable administrative access when someone leaves the company, without having to change the administrative passwords for everybody. Password policies are domain-wide, so it makes sense to follow best practices for everyone in the domain.

## AVOID REPEAT PROMPTS AFTER PASSWORD CHANGE

If a user has more than one computer and is logged into both (for example, if they have a laptop and a desktop), then they should log out and log in both computers after changing the password. The session will still work, but because their password will have changed, this can lead to repeated password prompts for network resources such as Exchange servers, SharePoint sites, and other applications.

## Connecting to Network Resources

One of the main reasons to join a domain is to access resources on the domain, such as the printer down the hall or some documents you need to work on. You could access company photos, slide shows, and other media to make a marketing campaign. Whatever your need, you don't need to have these items and devices hooked or stored directly on your client machine. In fact, having stored on the network is ideal because they are more secure (access is centrally controlled, and ideally they are backed up regularly). Examples of network resources include the following:

- Printers
- Shared folders and files
- Wireless devices (such as wireless printers)
- Services (such as Web Services)
- Company applications

Connecting to shared resources is easy for users, thanks to many of the changes in Active Directory and Group Policy. You can still use features like Network Discovery as a way for your computer to find resources on the network easily, although in most enterprises this is not recommended. With the introduction to Group Policy: Preferences it can now publish resources more easily for employees or departments through Group Policy objects and membership in domain groups. Users can continue to search Active Directory for resources they may need. This means that the user doesn't need to know where the device is installed or connected. The user might not know the exact name of a shared folder or printer or the server where it's stored. As long as the resource is published to Active Directory, with a little searching the shared resource will most likely be able to find and utilize the resource.

There are several ways to access shared resources. This section will expand on these more common ways for each of the client operating systems addressed in this chapter:

- Resources are published to you through Group Policy objects.
- You can search for and access resources that are published in Active Directory.
- You can attach to shared network resources (for example, shared folders and printers) by the command line.
