You can also create users via the command line. This is helpful when using the Server Core installation of Windows Server 2012, but you may find it useful to learn for scripting as well. You can run the following command to create the local user SRed on your server:

```
C:\Users\administrator>net user SRed Skyblue2013 /ADD
The command completed successfully.
```

The syntax of this command is as follows:

```
net user <username> to create <password to set> /ADD
```

That command creates a user on the local computer. It does pretty much else. None of the other options that we've just talked about are turned on or used. If the passwordpassword is longer than 14 characters, you will be informed that the password is longer than 14 characters, which could have been a problem on legacy Windows systems. You are asked to confirm that you want such a long password. If you want to add spaces into your password, you can do that by surrounding the password with quotation marks. Here's your example:

```
net user SRed "My dog is yellow"
```

You can add a few options to this command to completely re-create what you did in the Computer Management

```
net user SRed Skyblue2013 /fullname:"Steve Reed" /comment:"Manager of the server team" /logonpasswordch:yes /add
```

That's a long command. Here's what the options do:

- /fullname gives the user account name for reference.
- /comment completes the Description field in the properties of the user account.
- /logonpasswordch:yes forces the user to change their password when they first log into the server.

Here are some of the other options that we covered for Computer Management:

- /password This is to set either yes or no to control whether a user can change their own password.
- /expires This is set either to a date (in the format mm/dd/yy[yy]) or NEVER.
- /active This enables or disables the account.

You can get more information on other options by typing net help as the command. Don't fall into the trap of typing net /. There isn't much information there.

# Creating Domain User Accounts

Let's quickly return to why you might prefer to use domain-based user accounts instead of local accounts. It turns out that your user, Steve Red, will need to be able to log into many servers on the network, not just stand-alone server. He's going to be using single sign-on experience. Administrators also want to set up one user account and be able to grant rights to just one user account. Steve wants to have only one user account and one password. The solution is simple—use a domain and a domain user account.

To do this, log into your domain controller (in this example, its DC01.bigfirm.com) to use a tool called Directory Users and Computers, which you can find in Administrative Tools on any domain controller. Using the free-to-download Remote Server Administration Tools, you can install this and other server management tools on your Windows 8 computer for remote management. You'll probably prefer to this when managing a production environment on a day-to-day basis.

# SEPARATION OF ADMINISTRATION

One of the things that Windows administrators have been slow to adopt the concept of separating our roles as office employees and network administrators. Unix administrators have been doing it for decades by simply using the su command. In order they log into the network using an ordinary account with normal user rights and elevate their privileges to a higher account when they ever need to do any administrative work. Why would you want to do this? It's pretty simple Imagine you are surfing the Internet or reading your email. A piece of malware slips through your defense mechanisms and execute. What is it going to run as? That's right; it will under your account. What is going to stop it from ramping across your corporate network if you have logged in as a domain administrator or other privileged account? Absolutely nothing! Windows does offer some protection with User Account Control (UAC), but its not a perfect defense. If you need physical security, the simplest solutions are the best.

The solution is quite simple and not so horrific as many administrators try to make out when they hear it. That means with administrative rights have two accounts. One account will be for their daily office work using Microsoft Word, surfing the internet, or reading email. The second account will be for administrative work. This is where people throw their hands up in the air and start protesting. Let us finish—you'll see how easy this can be to use.

Let's say you have this scenario up Steve Red. Steve's normal account is SRed. That's what Steve logs into his computer to do his non-administrative work. You also set up another account that has rights to manage parts of Active Directory, servers, and desktops in his office. This account is called SRed-Admin. You could have used a fine-grained password policy to enforce stricter rules on the administrative account, but you've gone with everywhere. That's perfectly secure.

How does Steve switch between roles during the day? This is the normal argument against separation of administration: "I don't want to be constantly logging out and in again." There are a few ways to get around this.

You've been able to use the RunAs to run programs under alternative user accounts. In Microsoft Server and Windows operating systems, you can run programs as a different user than the currently logged-on user. This is known as Run As. If you want to do so, you need to follow these basic steps:

- 1. Locate the program you want to start.
- 2. Press and hold the Shift key while right-click the program icon, and then click "Run as user.
- 3. Enter the credentials for the user you would like to run the program.

Some organizations have used this and even changed the shortcuts for the administrative MMC snap-ins in Administrative Tools to do this by default. Windows 8 and Windows Server 2012 allow you to quickly switch users without having to log out.

You should understand the need to separate the two working lives of an administrator and see that the solutions aren't all have to live with; in fact, they can be beneficial in saving time and effort.
