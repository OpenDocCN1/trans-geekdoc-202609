# # Website Provisioning

Provisioning is the art of allocating resources and creating the structure for a new website.
Several client protocols are supported these days (HTTP, FTP, SOAP, and so), so an accurate
description on the subject of creating a website should clarify which type of traffic you
expect the website to support. Vocabulary may provide arrange challenges when the searching
best method of creating sites. Remember that a site in IIS is a local entity that represents
protocol handling and endpoint listener behavior in order to receive client requests and
respond to them.

For example, to create an HTTP site, you would configure the IP address, port
number and host header that the server will recognize on an inbound request from
a client in order to respond to. Any client request bearing a destination IP address, destination
port, or host header that matches your new site's configuration will
immediately to your new site as opposed to any other site on that same IIS
server. These address, port bindings must be unique in IIS to avoid conflicts.

Because each HTTP setting binding values must be unique in order to correctly route
requests, IIS will throw an error if you attempt to create identical site protocol bindings
more than one. However, there are many possible combinations of IP address, port, and host
header that would allow you to build multiple sites on the same instance of IIS without conflict.
'll discuss hosting sites in more detail in a bit.

Within a site, a smaller local unit that represents all or part of the site is
called application. Applications may exist within a single site and can be configured
separately for performance and security reasons. Each application's URL namespace is\mapped to a physical drive via a virtual directory configuration parameter. A site must contain
m minimum of one application called the root application. This root application must be configured
with a minimum of one virtual directory.
