
# CONFIGURING HOME DIRECTORIES

- Who must be able to access each user’s home directory

The norm is to allow only the user, administrators, and System to access to the folder. Some organizations choose to treat the home directory as a personal folder that the user can use to share data with everyone. We'll demonstrate the more usual approach in this section.

- How will you name the folders?

Some people use something predictable. They name the folder after the user who owns the home directory. For example, the user Joe Bloggs has a username of JBloggs. His home directory will be called JBloggs. This makes it easier to perform automated tasks such as connecting the user to the share.

- How will you share the folder?

Some choose to create and share every home directory. That's a lot of work. Others prefer to create one generic and create a folder underneath for each user. This suits the DFS approach earlier because there's only one DFS link if you need to restore or move the home directory to a new location. The shared folder will be made available via a DFS namespace.

You'll be creating a shared folder called Home on BF2. Some administrators like to create all of their shares in a single folder on the file server. This serves a couple of purposes:

- It keeps tidy and the administrators can find all of their shares in one location.
- It makes automation tasks such as backup or directory replication much easier because there is only one folder to select.

Create a folder called Shares on the D drive, as shown in Figure 26.2.

# FIGURE 26.2
The Shares folder on BF2

![](img/41a83208e6906a3732620203b836cea7_1307_1.png)

# CONFIGURING HOME DIRECTORIES

Disable folder permission inheritance, and set the folder permissions as follows:

| Group | Permission |
| BF2\Administrators | Full Control |
| System | Full Control |

You're doing this because any folders you create in D:\Shares will inherit these permissions by default. This makes the new shared folders secure by default. It will be up to you and other administrators to assign access to the correct users or security groups. It will also prevent administrators from creating folders here without permission. Now create a folder in D:\Shares called Home.

The Home folder will now be shared. This will mean that you can create subfolders for each user and only have to manage a single share. The aim of this is to simplify deployment and make security management easy as possible.

You are now going to use the File and Storage Services tools. The tool shown in Figure 26.3 will appear when you select File and Storage Services from the Server Dashboard and then select the Shares.
