# PREPARING TO PROMOTE THE MEMBER SERVER

Before you promote your Windows Server 2012 member server to a domain controller, make sure the domain has a forest functional level of at least Windows Server 2003. If you are going to promote a Windows Server 2012 into a forest with a forest functional level of 2000, you will get an error.

# PERFORM A SWING MIGRATION

A swing migration involves these basic steps:

+   1. Check your domain for errors.
2. Add the Active Directory role to the member server.
3. Run the Active Directory Domain Services Configuration Wizard with Schema Admin, Enterprise Admin, and Domain permissions.
4. Perform post-migration steps, such as placing FSMO, changing the IP address, and other changes.
5. Redeploy the source domain controller as necessary.

The ADSCW will automatically run adprep / forestprep and adprep /domainprep the schema-respective infrastructure master.

# PREPP THE FOREST/SCHEMA AND DOMAIN

As with the in-place upgrade, the existing forest and target domain need to be prepped for Windows Server 2012's Active Directory changes. ForestPrep, DomainPrep, and GPPrep are required to run in the "Migrating with an In-Place Upgrade" procedures.
The other way of extending the domain is to start the Active Directory Domain Services Configuration Wizard right away. As we mentioned before, adprep.exe is integrated into the wizard, and it will take care of all the necessary steps. Whichever you choose, the rollback procedures at this point of the game are the same as for the in-place update. Restore the system state data on the schema master domain controller.

# BUILDING A WINDOW SERVER 2012 MEMBER SERVER

The target domain controller will start as a Windows Server 2012 member server in the original domain. In preparation, the Active Directory Domain Services and DNS role must be installed before running the Active Directory Domain Configuration Wizard.

# VERIFYING DNS

Since the new domain controller will support DNS, it should be added as a name server to the applicable forward and reverse zones. Once the member server is promoted as a domain controller, the DNS zones will be replicated.
To ensure proper name resolution of the domain controllers, the DNS resolution should be tested using Nslookup and Dcdi, which we covered earlier in this chapter.
