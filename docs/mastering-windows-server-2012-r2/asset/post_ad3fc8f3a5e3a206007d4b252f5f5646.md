- 14. Click the Settings button to take a look at the VM configuration, as shown in Figure 27.30.

The Settings dialog box is one you will see lot in the future. The left pane has two sections: Hardware, and Management.

The Hardware section manages all virtual hardware. Here's an explanation of each option that you will see on Generation 2 VM:

**Add Hardware**: Here you can add a SCSI controller that you can use to add virtual drives. As we discussed earlier, with this release of Hyper-V, you can now boot your VMs directly from a SCSI controller, and this is the only option available.

**Firmware**: This is where the new Extensible Firmware Interface (UEFI) BIOS delivers the ability to enable or disable secure-boot. You can also select the order of: DVD drive, network adapter.

**Memory**: Figure 27.31 shows the Memory section of the VM. In the figure, you can see selected startup RAM of 512 MB and enabled Dynamic Memory to manage the RAM of VM gets allocated by the host. The Minimum RAM setting allows you to specify an amount of memory that is lower than the actual startup RAM (which required to start the VM in the first place), and this can be useful in VMs that are idle over long periods.

With the Maximum RAM setting you can determine the amount of memory that gets allocated to a VM from the host with a top limit of 2 TB. It is useful to know that you can modify this value when the VM is running, but you can never allocate more RAM than is available on the physical host. Processor Here you can specify the number of virtual processors for this particular VM up to a maximum of 64. On boot, the VM will have specified number of processors; of course, they are not enabled by default. The hypervisor is the sole owner of processors and decides which VM gets how much. In 27.32, you use the "Resource control" settings where you specify what percentage of selected processors should be reserved for this VM. The upper limit is set by and the VM will never use more than this percentage. This feature is very useful for applications that use CPU resources.

Compatibility gives you the "Migrate to a physical computer with a different processor version" and is used in a situation where Hyper-V hosts have slightly different CPUs. The feature works by disabling certain CPU instructions whose functionality varies between processors. The price you pay is potential lower performance, depending on your workload.

NUMA Non-Uniform Memory Access delivers scalability for multiprocessor VMs through wide access of memory on the motherboard. This working in conjunction with the NUMA spanning option inside Hyper-V settings to control how Dynamic Memory spans across multiple nodes.

SCSI Controller The next item on the hardware list is SCSI hard disk that you configured as part of New Machine Wizard. It is automatically added. You can add up to four SCSI controllers to a virtual machine, and each of these controllers can have up to 64 virtual disks attached, each virtual machine having capacity of 64 TB. If you do the math on this, you'll see that a virtual machine in Windows Server 2012 R2 can have 16 terabytes of storage.

Under the SCSI Controller section, you can also attach a DVD drive to use for mounting ISO files. Unlike earlier versions of Hyper-V, the DVD drive is no longer available by default to Gen2 VMs, and this is why it is not available as an option when you run the New Virtual Wizard.

When you have a virtual drive attached to a SCSI controller, you can click the sign beside the drive to expand and access the Advanced Features area. Here you can turn on Quality of Service management for a specific virtual disk, where you can determine minimum and maximum values for IOPS in 8 KB increments. You can also enable virtual disk sharing here to allocate a specific disk to be used as shared storage to facilitate clustering scenarios with your virtual machines. Network Adapter virtual connections are managed by the Network adapter dialog box. For NIC, you can select any virtual switch from the drop-down menu. You can change the binding while the VM is running, which can be quite a hard feature to have. From the VM point of view, this is like pulling the cable from one switch and plugging it into another. One for it is to install the operating system, patch it on Windows Update, and connect it to another switch for switching.

Expanding the Network Adapter option gives you the following options, as shown in Figure 27.34:

Hardware Acceleration This is where you can perform different tasks to be offloaded to a physical network adapter. First here is "Virtual machine queue," which binds the MAC address of a virtual NIC to a queue on a physical NIC, optimizing network traffic for your VMs.

Next in the list is "IPSec traffic overloading." This allows you to offload the processing of your IPSec traffic encryption and decryption to hardware to free up resources on the host.

The final (and most intriguing) acceleration option is "Single-root I/O virtualization (SR-IOV). Take advantage of this feature, you will need dedicated hardware, but the rewards are worth if you take the time and money to invest. The idea of SR-IOV is to replace the virtual switch in your VM connectivity and route traffic directly to a special SR-IOV physical NIC connected to the host. This means far greater improvements in CPU utilization, network latency, and network throughput.
