
在检查点之间移动并不困难。然而，如果你想保留当前状态，你需要创建一个新的检查点。如果你不这样做，最后保存的状态将是其上一个检查点的状态。因此，为了在一个检查点运行的同时切换到另一个检查点，你需要执行以下操作：

- 选择你想要移动到的检查点。

你可以选择任何一个你喜欢的，即使是链中的中间检查点也可以。

- 使用“从检查点应用”（Apply from the Checkpoint）菜单。

你会看到一个带有三个选项的对话框：创建检查点并应用（Create Checkpoint and Apply，默认）、应用（Apply）和取消（Cancel）。

- 做出选择，几秒后，选定的检查点将开始运行。

同样，你可以删除任何你需要的检查点。从管理控制台来看，这似乎很简单，但在底层有更多操作。关键在于使用差异检查点。如果删除了链中间的一个检查点，会发生什么？在这种情况下，被删除检查点的差异文件将被保留，以保持磁盘完整。在 Hyper-V 2012 中，你可以在不停机的情况下将孤立磁盘合并到你的磁盘中。Hyper-V 管理控制台将显示状态为 Mer（并指示完成百分比）。这里还有更多需要考虑的场景，但关键点是 Hyper-V 能够感知这些并采取正确的措施。

一个例子是删除虚拟磁盘。对话框会告诉你它将不会删除虚拟磁盘。这只是部分正确。当你删除虚拟机时，花费的时间会比你想象的要长。屏幕上会有一个对话框告诉你它正在销毁（Destroying，并指示百分比）并在倒计时。它并不是在删除磁盘；而是在将检查点与其父级磁盘合并，只给你留下一个代表你刚刚删除的虚拟机数据的 vdx 文件。无论如何，这可能是正确的做法。

作为一种测试功能，检查点是非常棒的。你可以搞乱任何你想要的环境并拥有一张“免死牌”来脱身。不吗？总是如此。在某些情况下，应用较早的检查点可能会带来麻烦。对于与他人之间没有关系的独立配置，检查点是完全安全的。对于任何计算机共享某些配置的情况，你需要小心。最好的例子就是 Active Directory（活动目录）。

事实上，检查点有很多方法会让你在 Active Directory 中遇到麻烦。最明显的例子是你有一个 40 天前的成员服务器。所以你知道，一个属于域的服务器每 30 天更改一次密码。自 40 天前，该服务器在 Active Directory 中至少更改了一两次密码。在它的本地数据库中，存储了两个密码：当前和上一个。如果它更改了两次密码，那么检查点的服务器在 Active Directory 中就没有匹配的密码。换句话说，它不再是域的成员，需要重新加入域。这个问题与普通的备份相同。然而，还有一个更微妙且更危险的问题会影响任何版本早于 Windows Server 2012 (RTM) 的普通 Directory 域控制器。

# 第 27 章使用 Hyper-V 进行服务器虚拟化

为了让域控制器进行复制，它们需要一些管理操作来告诉它们已经从伙伴那里接收了什么，仍然缺少什么。这种管理取决于每个域控制器（DC）在每次修改其数据库时生成的更新序列号（USN）。任何更改都与一个唯一的 USN 关联。关键点在于，当你恢复 DC 的快照时，你恢复的是那个时刻的配置。问题是，其他 DC 并不知道这已经发生！当它们查看恢复了快照的 DC 时，它们会发现自己已经处理了该 DC 的当前 USN。所以，DC 的复制伙伴认为没有必要复制任何数据。有效来说，在 DC 的 USN 高于伙伴已更新之前，DC 将不会进行复制。受影响的 DC 在期间产生的所有数据将永远离开该 DC。

这种影响遗留 DC 的非常严重的问题，被称为 USN 回滚（USN rollback），已记录在微软的知识库文章 87549 (http://support.microsoft.com/kb/87549) 中。幸运的是，如果 DC 检测到此情况，它将立即停止 Active Directory 活动，并在目录服务事件日志中记录该问题。其目的在于让你意识到，在你熟悉的系统中，使用检查点可能会导致意外的问题。避免这种情况的最好方法是在关闭它们后对整个组创建检查点，并作为一个组进行恢复。你可能会奇怪，为什么当你对 DC 进行常规备份并恢复时会发生这些问题？答案是 Windows 恢复会感知 Active Directory 的复制放大和重置。当一个恢复的控制器在非权威性恢复后上线时，它会向伙伴发送信号，表示它应该被视为从未复制过。正如前面提到的，在 Windows Server 2012 (RTM) 中，在下一章，我们将讨论 Hyper-V 虚拟化的进展，以防止这种情况在 Windows Server 2012 DC 中发生。

完成关于 Hyper-V 检查点的这一节，两个关键总结点是：

- 检查点是一个非常棒的功能，可以让你的生活变得简单许多。

- 除非完全意识到相关风险，否则不应在生产网络中使用检查点。
