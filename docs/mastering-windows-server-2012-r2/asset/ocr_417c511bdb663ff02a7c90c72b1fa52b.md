# Clustering

In its most basic form, a cluster is one or more servers (physical or virtual) that are configured as a logical object and a single entity that manages shared resources and presents them to end users. Servers that are members of a cluster are known as nodes. The three common types of clusters in Windows Server 2012 R2 are file server clusters, SQL clusters, and Hyper-V clusters.

A two-node cluster, for example, would be configured with nodes (physical or virtual), multiple network interface cards, and a shared storage solution such as iSCSI, SAN, or attached disks. The purpose of clustering is to allow a specific group of nodes to work together in a shared capacity with high availability. This gives your users high availability for the workloads they need. Clustering provides the following benefits:

+   * The ability to survive a node crashing or offline
* The ability to restart a virtual machine or survive a VM crash
* Zero downtime for any patching or maintenance to cluster nodes
* The ability to move and disperse the load of servers (such as guest VMs) up to sixty-four nodes per cluster, with support for even-geographic locations.

The scalability options go well beyond two servers and can expand the capacity of geographically distributed clusters for availability and recovery are not the focus of this section, but they will become more important as you start to understand the capabilities of clustering.
Clusters are commonly used in high-capacity, high-visibility, and fault-tolerant scenarios. You design the cluster size and type based on the specific needs of the service and business and on the resources to be hosted. In any scenario, always think of clustering as a solution for making your services, applications, and components more available to the end user.
