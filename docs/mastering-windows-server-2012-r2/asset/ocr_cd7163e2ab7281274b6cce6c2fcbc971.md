# CHAPTER 32 WINDOWS SERVER 2012 R2 AND ACTIVE DIRECTORY BACKUP AND MAINTENANCE

There might be times when you need to check the integrity of your AD database—may rule out any corruption issues and also to generate reports on the number of deleted or phantom records that are referenced in it. You can check the integrity of the NTds.dit file in two ways: first uses the Files subcommand of Ndsutil.exe, and the second uses the Semantic database analysis subcommand of Ndsutil.exe. Microsoft warns that the Semantic database analysis subcommand should not be used as part of normal database management because improper use can result in severe loss for Active Directory; instead, it is used only for troubleshooting when working with Microsoft product support. Even though Microsoft warns against using Semantic database analysis, each time you use the integrity and recover subcommands under Files, it will prompt you to run Semantic database analysis.

# PERFORMING AN INTEGRITY CHECK OF NTDS.DIT

Using the Files subcommand of Ndsutil.exe lets you verify the integrity of the database file and repair any corruption that is found. You should always use the recover command before performing an integrity. The recover command flushes all transactions to the database file, ensuring that the file is the most up-to-date information. Use the Esentl exe to perform a soft recovery of the NTds.dit database and commits all outstanding transactions.

Perform these steps after stopping the AD DS service to check the integrity of NTds.dit:

+   1. Open an elevated command prompt.
2. Type ndsutil and press Enter.
3. Type Activate instance NTDS, and press Enter.
4. At the resulting ndsutil prompt, type Files (case sensitive), and then press Enter.
5. At the file maintenance prompt, type recover, and press Enter.
6. Type quit and press Enter.
7. Type quit and exit file maintenance mode, and then type quit and press Enter to exit Ndsutil.exe.
8. After you have completed these steps, restart AD DS.
