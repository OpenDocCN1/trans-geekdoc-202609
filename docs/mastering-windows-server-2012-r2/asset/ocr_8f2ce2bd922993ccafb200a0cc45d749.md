# CHAPTER 20 ADVANCED IP: ROUTING WITH WINDOWS

The computer sits between the New York and London networks, which we will call the Gateway computer, is well placed to be a router—it is multihomed, and each interface is on a different network. But is it a router yet? Not until it has been configured to forward.

By default, Windows Server 2012 R2 routers are not configured to forward. To cause a Windows Server 2012 R2 router to forward IPv4 packets, you need to edit a registry setting. The setting is HKEY_LOCAL_MACHINE\System\CurrentControlSet\Services\Tcpip\Parameters\EnableRouter; it should be enabled as a dword set to 0, or set it to 1 to enable IP routing, and restart the computer.

That's all you need to do to create a router between two local subnets. This computer will now automatically forward packets received on one interface to the interface corresponding to the network containing the destination address of the packets. Again, you can use the route (or netsh, if you are typing) command to add any routes that are not already present in the router.

# TUNNELING: NEARLY ROUTING

Network tunneling is a form of routing in which network traffic is encapsulated or transformed in some way by a tunnel endpoint so that it can reach another tunnel endpoint, at which point it is de-encapsulated or transformed.

In a way, NAT is a form of tunneling in which the transformation is to change the source and/or destination address and port along its paths. With other tunneling methods, NATs may between the start of the packet's travel and its end.

# CHEAT TUNNELING WITH PROTPOXY

The last tunnel you'll visit is a very useful one

At the other end, forwarding port 119 to port 80, you begin by encapsulating the NNTP traffic from your newsreader into a connection that seems to the firewall to a connection to a server.

Assuming that your home computer is at address 10.20.30.40 and the news server you want to reach isn't msnews.microsoft.com, these are the commands to use:

```
[At the work computer] netsh interfaceproxy add v44 119 10.20.30.40 80
[At the home computer] netsh interfaceproxy add v44 80 msnews.microsoft.com 119
```

Connecting to systems at home using this method is probably going to get you into trouble, but there may be some work you can use this method for. That portproxy does not offer any kind of authentication, and it does not provide any encryption to protect your data in transit. You may find that a virtual private network (VPN) offers you more of what you need in this direction. Read Chapter 21 to find out how to configure Windows Server 2012 R2 as your VPN endpoint.
