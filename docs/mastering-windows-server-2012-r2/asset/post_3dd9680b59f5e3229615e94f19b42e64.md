
Disks Get as many disk spindles as you can reasonably afford. Four independent medium-capacity disks will be faster than two large-capacity disks when using multiple VMs. SATA disks are OK for testing and non-demanding applications. For better performance for SCSI or SAS disks, but if you have the money for it, invest in high-speed solid-state disks for optimal performance. Avoid a RAID-5 configuration because it's slow on write operations. RAID 0 and RAID 1 combinations are fine for low-end systems—remember that RAID 0 has no fault tolerance. For high-end applications, consider RAID 0.

NICs For Hyper-V networking, the general recommendation is to have at least two NICs, to manage one and another for the VMs to access the network. Preferably, you should have four or more NICs if you want to make use of built-in NIC Teaming, Converged Networking, and Failover Cluster features of Windows Server 2012 R2. If you expect high network throughput or have iSCSI connections that require dedicated NICs, you will need even more.

Essentially, this means that you no longer need to configure your designs iSCSI, Fibre Channel, or SMB 3.0 file shares when you want to create clusters using virtual machines. You can configure VHDX sharing either through the GUI or with just a few lines of PowerShell code. ## Convert VHDs TO VHDX

After reading all how the new VHDX format is in Windows Server 2012 R2, you might be interested to know that you can easily convert those old VHD files that are currently running on your VMs inside your Windows Server 2008 environments. You can do this either through the Hyper-V Manager by clicking the Edit Disk from the Actions pane and choosing the Convert action from the wizard or by using the following PowerShell command (substituting the path and name of your configurations):

```
Convert-VHD -Path E:\VirtualMachine\DataDisk.vhd -DestinationPath E:\VirtualMachine\DataDisk.vhdx
```

Enhanced Session Mode (VM Direct Connect) This is a simple enhancement of the surface of things, but speaking as a consultants who worked with Hyper-V for years, I find it to be one of my favorite features of Hyper-V in Windows Server 2012 R2. With earlier versions of Hyper-V, rich copy and paste between the host server and a VM wasn't possible. You could copy and paste into a VM if you had a network connection configured, but no network connection means no copy and paste. This even simple tasks like inputting a key to a new VM circumstance. It also means that if you had no connection to the VM, you had to use the Hyper-V console to manage it, and performance was never optimal during this long-term.

With enhanced session, you can now easily copy and paste directly to and from a VM—without a network connection being configured. It is the same experience you get with a remote desktop connection to a machine but minus the need to worry about networking. Enhanced session leverages the VMBus the Hyper-V integration components to deliver this experience; we'll discuss the VMBus in more detail. This feature must be enabled and enabled on a per-host basis, and by default it's turned off.
