This idea of creating a first domain, populating it with only account or two, and doing nothing else with it, is called empty root AD design.

Some create an empty root domain even if it's just one domain in case they acquire other accounts at some time in the future. It's not a bit of bet-hedging, and we recommend it to some. # THE CASE FOR TWO DOMAIN CONTROLLERS

It's a good practice in any environment to ensure availability and disaster recovery for services and systems. Theマスター replication model provided with Active Directory makes these concerns a piece of cake. All you need to install least one domain controller in a site for availability or in another for disaster recovery or both.

It's a best practice to add least two domain controllers into an empty forest root domain. Although it may not have any users or resources in it, it is irreplaceable (literally) part of your Enterprise Directory. It needs to be highly available and able to withstand a disaster. If it is supported by only one domain controller, that domain controller is going to do a lot of work. If you lose it and can't restore it, you will probably be calling Microsoft Premier Support and then polishing your resume.
