As discussed earlier with SRV records, the number of SRV records registered by a domain controller is so great that it is difficult to eyeball whether it's working correctly. In addition to the /registerDNS /DnsDynamicUpdate and /DnsRecordRegistration through checking SRV registration by the domain controllers, unlike /registerDNS do not have to run locally on the domain controller. The following command will verify the /v option for "verbose". The output is lengthy because it lists all of the SRV records for the domain controller:

```
C:\Users\Administrator.BF1>ddiag /sBF1.bigfirm.com /test:dns / dnsrecordregistration /v
```

The following will validate that DNS update is operational on a zone. You will register a host and delete it from the DNS zone of the server. In this case, is Eacoast.Bigform.com:

```
C:\Users\Administrator.BF1>ddiag /siecl.Eacoast.Bigform.com /test:dns / dnsynamupdate /v
```

# Helpful DNS Troubleshooting Links

The tools we have discussed up to now have all based on what's available out of the box with Windows Server 2012 R2. Those tools are where you should start your troubleshooting from the inside network. In this section, we want to share some DNS-related websites that you can use to assist with external DNS problems.

www.IntoDNS.com is a simple effective website to add to your DNS troubleshooting arsenal. When you reach the page, all you need to do is enter the DNS name of the domain that you want to get information on and then click the Report button. This will then return all of the available information for the A (parent), NS, SOA, MX, and WWW records for that domain. With this information, you can quickly identify whether any of those records have been configured incorrectly, or you can just use it as a cross-check for the information you have been given.
