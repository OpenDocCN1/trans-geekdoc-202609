The following sections detail the steps to set up the KMS server on a branch-office Server Core installation.

SRV records are found in DNS and publish the existence of services within a network. This will be discussed in Chapter 5, “IP Address Management and DHCP Failover.” By default, the KMS server publishes the service with an SRV record in the primary DNS domain. For your Windows Server 2012 Server Core example, this is BigFirm.com.

In BigFirm.com DNS domain, you would see an SRV record for _VLMS._TCP.Bigfirm.com. It will have the following properties:

- * Name: _vlms._TCP
- Type: SRV
- Priority: 0
- Weight: 0
- Port: 1688
- Hostname: Bfsc.bigfirm.com

If this is to happen, you would need to add permissions to the DNS zone to allow updates to the KMS servers. We recommend using a domain controller as the KMS server. The service is light, and the domain controller already has permissions to register SRV records in DNS.

However, with SRV records, there is no control over which KMS server the clients will call if they are located in a branch office. They would query DNS and receive a response for a server located elsewhere. In addition, DNS publishing should be disabled for the branch-office server. This is done by creating a DisabledPublishing dword value of 1 in the HKEY_LOCAL_MACHINE\SOFTWARE\Windows\NT\CurrentVersion\key.

# ENABLING THE FIREWALL

There is already an inbound rule in the Windows Firewall configurations, and it’s part of the Key Management Service rule group. You need to enable it. The command for this is as follows:

```
netsh advfirewall firewall set group="Key Management Service" new enable=yes
```

# ACTIVATING THE INSTALLATION

Just as you activated the Server Core instance, the branch-office KMS server needs to be activated with the slmgr.vbs /ipk and ato options.

# POINTING CLIENTS TO KMS

By default, Volume Activation 3.0 clients (Windows 8 and Windows Server 2012) attempt to connect to KMS using SRV records. Since the process isn't aware, it will go to any provided KMS server. You can manually associate the KMS host on any client with the following:

```
cscript c:\windows\system32\slmgr.vbs /sk bfsc.bigfirm.com:1688
```

You could use Group Policy object to distribute this throughout the site.

# Protecting Data with Windows Backup

This is one of the features added to the Server Core installation. It's a good idea to back up data. Your environment may prefer the use of native backup tools or a third-party enterprise-class backup solution. However, Windows Backup is not installed or configured.

Microsoft reengineered its native backup utility and named it Windows Backup. It takes advantage of Volume Shadow Copy Service to freeze the state of the data for backup. Originally, it was designed to provide only off-site backups on tape drives. Tape backups were eliminated. Fortunately, Microsoft broadened the application to include locally attached hard drives. 

In this discussion, we'll explore the PowerShell cmdlets that manage Windows Backup. First, you need to install the Windows Backup feature. You can then run Get-WindowsFeature to see the list of names associated with Windows Backup. 

```
PS C:\Users\Administrator>Install-WindowsFeature Server-Backup
```

If installed properly, you will see the following in PowerShell:

| Success | Exit Code | Result |
|---|---|---|
| True | No | Windows Server Backup |

You will need to create a backup policy. The backup policy is the set of instructions for automating your backup. When you create a new one, it is empty by default. So you will create it and fill it with instructions. These instructions include scheduling the backup, setting the backup target location, and several other parameters which you will see as you install the policy. To install it use the New-WBPolicy cmdlet:

```
PS C:\Users\Administrator>New-WBPolicy
```

| Schedule : |
| BackupTargets : |
| VolumesToBackup : |
| FilesSpecsToBackup : |
| FilesSpecsToExclude : |
| ComponentsToBackup : |
| BMR : False |
| SystemState : False |
| OverwriteOldVhd : False |
| BackupOptions : False |

Now that you see the New-WBPolicy properties, you can use the following script to set them. This script will set the policy to back everything in the Sales folder every morning at 9 a.m.:

```
PS C:\Users\Administrator> $policy = New-WBPolicy

$fileSpec = New-WBFileSpec -FileSpec C:\Sales
Add-WBFileSpec -Policy $policy -FileSpec $fileSpec

Add-WBBackupMetadata $policy

$disks = Get-WBDisk
$backupLocation = New-WBBackupTarget -Disk $disks[0]
Add-WBBackupTarget -Policy $policy -Target $backupLocation

Set-WBSchedule -Policy $policy 09:00

Set-WBPolicy -Policy $policy
```

That will get you started using PowerShell to handle your Windows Backup. You can reference the complete cmdlet list for Windows Server Backup at http://microsoft.com/en-us/library/ee70683.aspx.
