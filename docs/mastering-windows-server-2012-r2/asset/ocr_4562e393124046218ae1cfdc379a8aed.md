# Understanding Virtual Switches

As you learned in Chapter 4, the enhancements to networking in Windows Server 2012 have been with the biggest investments and improvements compared to predecessors. Hyper-V introduces the concepts of converged fabric, storage QoS, and extensible switches. In this section we'll help you to understand these concepts and explain how you can use them in your Hyper-V deployments going forward.

In earlier versions of Hyper-V, you had a reasonably simple method of getting your VMs connected with three different types of virtual networks that you could configure through the Virtual Network Manager in Windows Server 2012. Virtual network concept was replaced with the virtual switch, and at a glance, it comes with the same type of behavior. When you dig into the capabilities of the virtual switch, however, it soon appears that you can do a lot more with your virtual networking than before.

Virtual switches are 100 percent software defined, and they deliver high-speed connections between VMs that are configured with one or more virtual NICs. In the physical world, of a virtual switch, "plug in" virtualized NICs of VMs.

# Choosing a Virtual Switch

With Hyper-V, you can choose from the following virtual switches:

+   External is full access. A VM connected to an external connection can communicate through the physical NIC of the host with the outside world. Any other network device will see the VM as if it were a normal computer. The switch is (the) physical switch connected to the host. This switch sees one host with two MAC addresses and two IP addresses. Be aware that some other network environments may not allow this Symptom might be your VM can talk to the host but not to any other machine on the network even you have specified external access.

+   Internal the virtual switch is interesting. It allows communication between all VMs with the host but not directly to the outside. This is suitable for most test installations where you want the VMs to talk to each other and be allowed to transfer files and folders from the host but to nothing external. For each internal virtual switch that you create, Hyper-V creates an additional Local Area Connection directly connected to the network switch. There is no DHCP for that particular NIC (unless you put there), so everything on that switch will get an APIPA address. Yes, there is network connectivity, but to use it you need to configure the IP settings yourself.
