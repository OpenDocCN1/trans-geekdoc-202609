# NOT THE ONLY SECURITY BOUNDARY

The domain provides a security boundary for access and control to resources. Yet it is not the security boundary. The domain is not an impenetrable wall where information is protected. Information about the domain is shared between other domain controllers within the Active Directory forest, and a group has a built-in relationship among its members. So, another security boundary is the forest that protects information shared between domain controllers.

User and group information of the domain can be found in global catalogs, which can be located in other domains. The domain controllers of the forest replicate additional information such as Active Directory configuration data.

The physical security boundary of Active Directory is the domain controllers. A domain controller contains the database on its physical disks and replicates changes to other domain controllers.

If any of these boundaries are compromised, the Active Directory environment is compromised and subjected to the whims of an evil hacker, who commonly depicted as a black silhouette with a wool cap and trench

When Microsoft became security conscientious, it discovered how damaging to an Active Directory environment the evil hacker can be. He could change configurations with administrative privileges in another domain, and the changes would replicate to the rest of the domain controllers. With a physical domain controller, he could decrypt passwords for account. This was the impetus for Windows Server features for read-only domain controllers and password replication policies for caching passwords. If an evil hacker could get his hands on a domain controller in an unsecured area, at least the domain could not replicate changes to other domain controllers, and it would have a limited number of passwords to decrypt.

When you created your first domain using the Active Directory Domain Services Wizard, the Active Directory database was created, which would be replicated using the multicast replication process. The database is structured with three basic parts, or partitions:

**Domain Partition** This contains the information of users, groups, and computers that are associated with accessing resources.

**Configuration Partition** This contains replication parameters and other nigdy configurations to the Active Directory environment like Exchange Server information.

**Schema Partition** This contains the definition of objects. It tells Active Directory how to build a user account or a group, and it tells what data can be assigned to a user.

The domain partition is the largest part of the database and is replicated to only domain controllers within the same domain. It will also be the growing part of the database because organizations will create more users, computers, and other domain objects than they will add data to the configuration or schema partitions.

If you want to limit the amount of replication across wide area (WAN) links, you would consider segregating users and groups in one location from other locations by defining separate partitions for each location.

That's basically how domains are structured. It is a security boundary administering access to resources and authenticating users. It is also a replication unit in that information is shared with domain controllers in the same domain. Now let's look at options to expand Active Directory with more domains.
