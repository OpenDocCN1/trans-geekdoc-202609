These include tablets and laptops and on occasions home desktop computers. From an IT administrator's perspective, this can be frustrating when you are asked to tightly control access to information. You can see the problem: the enterprise does not own the asset, there is only much that they can do for the security of the device. The big issue is these devices operate in an environment but that is not sensitive.

Take a few seconds to review Figure 15.5 again; you will see that we have a Device option. This allows us to decide whether a computer is part of a group and whether to allow access to a resource. Imagine you create four groups: one for desktop machines, the second group for laptops, the third group for Finance, and the fourth group for Engineering. Now you could create rules requiring that only the desktop and laptop computers that are also part of the Finance group can access all information within the Finance share. With you can encrypt the Finance machines (desktop or laptop) so that if a user does copy data off the central server, the information is protected. It's a simple example, but straight away you can see how much more you control to implement your company's information.

# Centrally Control Permissions Using Templates

You now have a powerful tool to control access to resources, but if you had to implement it, it would otherwise take a huge amount of time. Like most things in IT, centralized is best! Could you imagine the power of DAC but implementing it for every file server in your environment?

Windows 2012 has a management utility called Active Directory Administrative Center (ADAC). This utility can be found in Server Manager over Tools.

Once the ADAC is launched in the navigation section on the left side, you will see Dynamic Access Control list. When you click Dynamic Control, it brings you to the core area, where you will centrally configure the DAC rules for your environment.
