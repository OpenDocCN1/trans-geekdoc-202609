# UPGRADE AND MIGRATION STRATEGIES

# WHAT You NEED TO CREATE SID HISTORIES

You need a migration tool that knows how to create SID histories. Microsoft’s free Directory Migration Tool, which we’ll cover a bit later in this chapter, can do that. Other migration tools are available, but you have to pay for them. Quest Software, for example, offers a suite of industry-approved migration tools.

Migration tools create SID histories as they copy accounts from other domains to your 2012 functional-level domain. Before a migration tool can work, you must create a trust relationship between the old and new domains. But no matter which migration tool you have, your migration cannot create SID histories unless you have created that trust with netdom or with ADDT’s New Wizard. You can create SID histories only on domains with a functional level of Windows Server 2000 or better. So, when you create new clean-and-pristine AD, make sure it’s already shifted into Windows Server 2012 level—after all, you’re building a fresh, new domain; but you as well get the best out of it—before creating the trust relationship and running the migration tool.

Please note that if you are planning on utilizing ADMT tool, you will need to leave your domain functional level at Windows Server 2008 R2 because ADMT v3.2 does not currently support Windows Server 2012.

Windows Server 2012 also has the ability to manage and configure SID history from PowerShell; the module in PowerShell allows you to make configuration changes and set token sizes. It is an absolute must for troubleshooting issues that may occur. For more information about PowerShell and SID history, you can refer to http://tinyurl.com/c25SIDhistory.

# ACTIVE DIRECTORY DOMAIN (CLEAN AND PRISTINE)
MIGRATION: PRO AND CONS

Here are some migration advantages:

+   - Migrations let you do gradual upgrades.

+   - Migration copy user accounts; they don’t move them. The old accounts are still there if some- going wrong.

+   - Migrations let you do your DCs from clean installs, avoiding the extra complexity and potential-ials of an in-place upgrade.

+   - Migrations are for consolidating domains, collapsing a morass of many domains into just or a few.

+   - You can build a new domain structure in a virtual environment.

Although we’ve said that migrations have the advantage of reversibility, thus helping you manage risk, they’re not without some cons:

+   - You need more machines than you would if you were just upgrading. You’ll need machines or virtual machines to act as domain controllers in the new domain.
