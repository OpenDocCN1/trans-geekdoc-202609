# Leveraging NsLookup and DCDag

NsLookup, DDiag, and DNSLint are the tools that you will likely use the most when troubleshooting DNS issues. NsLookup provides immediate indications of something that could be wrong or misconfigured with name resolution. DDiag and DNSLint provide immediate indications considering Active Directory-related issues, such as DNS registration and SRV records. If these tools do not resolve the problem, you can rely on the features of the DNS management console and PowerShell to help you out.

# NSLOOKUP

NsLookup is the first tool we use when troubleshooting name-resolution problems. It connects to the listed DNS server in the IP configurations and makes requests for DNS queries. Notice that the utility doesn't perform the name-resolution, in other words, the circle of life. It narrows down to one portion of the circle. In our discussion on clients, the examples of ping and view commands were provided to show the different parts of the process. The ping example showed the DNS process that included the first step of looking the name up in the HOSTS file. So, you will see a disconnect between ping and NsLookup the HOSTS file has records for the same hostname in.

# CONFIKER VIRUS

One example of malicious software that uses DNS to cause disruption is the Conficker virus. This "lovely" bit of code originated in 2008 and can (believe it or not) be found today lingering on computers that haven't been patched with the latest virus definitions and system updates. It prevents browsers from infecting systems from important sites within specific DNS namespaces like Microsoft.com, Symantec.com, and Norton.com.

This has a crippling effect. The computer can't go to the Windows update site; it can't look up possible solutions for the problem. Even if you installed Norton AntiVirus on the machine, it couldn't access the Symantec update site for the latest definitions. The machine couldn't fix itself!

When we across Conficker, NsLookup was our first tool of choice to troubleshoot it. The queries to Microsoft.com and Symantec.com were positive, but it wouldn't fit in Internet Explorer or Firefox instances on that computer. This difference helped narrow down where the issue lied. Therefore, the browsers were infected.
