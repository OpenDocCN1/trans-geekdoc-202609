## Creating a Domain Controller and Managing DNS

In previous versions of Windows Server, you would use DCPromo from the command line to create and promote domain controllers. In Windows Server 2012, DCPromo has been deprecated and can only be used with an answer file. Therefore, we are going to teach you the newer way—using PowerShell—to create a domain controller. Since you already installed Active Directory Domain Services (AD DS) in this chapter, much of the work is already done.

You will need to use a prerequisite check that is in Windows Server 2012. This will help show you what the server needs to properly install the domain controller. Test-ADDDomainControllerInstallation checks the prerequisites for the domain controller installation if you are performing the actual installation. You will be prompted for domain and login credentials, as shown in Figure 3.19.

![](img/41a83208e6906a3732620203b836cea7_167_0.png)

```
C:\Users\Administrator> Test-ADDDSDomainControllerInstallation

    DomainName: contoso-bigfire.com
    DomainAdministratorPassword: ******

Message         Context         Required  Status
TestVerifyADTrustedFor...      False       Success
TestVerifyADPrereq...         False       Success
TestVerifyADReplication...     False       Prior
TestVerifyOutboundReplica...  False       Success
```

You are ready to install the domain controller. The cmdlet Install-ADDDSDomainController will install DNS at the same time. If you do not add any parameters, the following default settings will be:

- Read-only domain controller: No
- Global catalog: Yes
- DNS server: Yes
- Database folder: C:\Windows\NTDS
- Log file folder: C:\Windows\NTDS
- SYSVOL.folder: C:\Windows\SYSVOL

There are plenty of scripts you can download and use to change all the different parameters. Here is the complete format you may need to change the configuration:

```
Install-ADDDSDomainController -DomainName <String> [-ADPrepCredential <PSCredential>] [-ApplicationPartitionsToReplicate <String>] [-CreateDnsDelegation] [-Credential <PSCredential>] [-CriticalReplicationOnly] [-DatabasePath <String>] [-DnsDelegationCredential <PSCredential>] [-Force]
```

## Configuring the DHCP Server

When Windows Server 2003 came out, Microsoft was starting to kick up sand onto the ultra-geek Linux system. It increased the available suite of commands to provide ultra-geek wannabes with the tools to configure as much as possible. That the netsh command came into fashion.

A branch office requires a basic DHCP implementation, with a single scope with standard options of default gateway, DNS servers, and DNS domain name. Before setting that up, you need to identify it in Active Directory, by using the add option. In the following code, interactive mode is utilized to execute the commands:

```
netsh dhcp
netsh dhcp>add server bfsc1.bigfirm.com 192.168.1.11
```

Adding server bfsc1.bigfirm.com, 192.168.1.11

Command completed successfully.

```
netsh dhcp>show server
```

Servers were found in the directory service:

```
Server [bfsc1.bigfirm.com] Address [192.168.1.11] Ds location: c
bfscl=bigfirm.com
```

Command completed successfully.
to add a scope, you need to switch to the netsh dhcp server prompt and use the scope command. The required parameters are the subnet and subnet mask that the scope represents, the scope name, and any comments:

```
netsh dhcp>server
netsh dhcp server>add scope 192.168.1.0 255.255.255.0 "Branch Office 1"
"Sample Dhcp scope"
```

Command completed successfully.
netsh dhcp server>show scope

===============================================================================
| Scope Address | Subnet Mask | State | Scope Name | Comment |
| :--- | :--- | :--- | :--- | :--- |
| 192.168.1.0 | 255.255.255.0 | -Active | -Branch Office 1 | -Sample DHCP scope |
===============================================================================

Total No. of Scopes = 1
Command completed successfully.
The scope needs a range of IP addresses to serve to DHCP clients and the standard scope options. The options are identified with the option code, a three-digit identifier. You can see the identifiers in the DHCP Management Console. The options have values in byte, word, string, or IP address format. For our example, we have the following options, identifiers, and values:

* IP range: 192.168.1.50-100
* Default gateway: 003, 192.168.1.254
* DNS server: 006, 192.168.1.11
* DNS domain name: 015, bigfirm.com

```
netsh dhcp server>scope 192.168.1.1
```

Changed the current scope to 192.168.1.0.
netsh dhcp server>add range 192.168.1.50-100

Command completed successfully.
netsh dhcp server>set option 003 192.168.1.254

Command completed successfully.
netsh dhcp server>set option 006 192.168.1.11

Command completed successfully.
netsh dhcp server>set option 015 bigfirm.com

Command completed successfully.
netsh dhcp server>show option

DHCP Standard Options:

| Option Code | Value |
| :--- | :--- |
| 003 | 192.168.1.254 |
| 006 | 192.168.1.11 |
