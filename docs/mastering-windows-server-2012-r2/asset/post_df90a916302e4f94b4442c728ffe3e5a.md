
# Minimum Bandwidth

In earlier operating systems, you could use maximum bandwidth consumption—also known as rate limiting—and you didn't have the ability to specify minimum bandwidth. Instead of a bandwidth-reservation system, it was more like a bandwidth-throttling solution. This was a big problem when trying to achieve the right QoS bandwidth-management policy in virtual datacenter environments and, as a result, did not lend itself well to enterprises that were using cloud-hosting solutions.

To solve this problem, Minimum bandwidth was introduced as a new feature to QoS in Windows Server 2012. Minimum Bandwidth provides a bandwidth-reservation solution that was missing with previous iterations and gives you the ability to specify different types of network traffic get the granular bandwidth configurations that you require.

If you want to learn about Microsoft's best practices for deploying QoS Bandwidth, then take a look at their guide located here: http://tinyurl.com/ws2012qosmb

# RECOMMENDED ADAPTER SPEEDS FOR MINIMUM BANDWIDTH

Microsoft has determined that Minimum Bandwidth works best on 1-gigabit Ethernet network adapters or 10-gigabit Ethernet network adapters. Adapters with lower capacity than these are not suitable for QoS.

# Data Center Bridging

Data Center Bridging (DCB) is a supported feature in Windows Server 2012 that provides guaranteed bandwidth to different types of network traffic on a converged infrastructure or converged fabric. Converged traffic has mixed classes, such as high-speed SAN, VoIP, and traditional LAN—all of which you would typically want to keep isolated from each other. DCB offloads QoS calculations and politics from the main processor and onto the NIC. For this, if you want to use DCB in your environment, make sure that your network adapters and switches support DCB functionality.

An example of the benefits here would be from a hosted cloud provider's perspective. When they implement DCB, it could be particularly helpful in helping reduce complexity by allowing all traffic to flow over the same infrastructure as a converged subnet with isolated segments, removing the requirement for specific isolated hardware storage typically required to keep the storage separate from the LAN traffic.

# CAN MINIMUM BANDWIDTH AND DCB WORK TOGETHER?

Although Minimum Bandwidth and DCB have the same functionality, that is, to ensure that a workload receives its share of bandwidth when network congestion occurs, they are not designed to work together. It's important to note that you should never enable both Minimum Bandwidth and DCB for workloads that share the same network port or NIC because it would cause major bandwidth and performance issues on your network.

# Hyper-V QoS

QoS for Hyper-V can be extremely useful to organizations that offer multi-tenant cloud-hosting services where they are held accountable to service-level agreements (SLAs) on network bandwidth. By using Hyper-V QoS, these organizations can ensure that throttling and segmentation of network traffic are delivered seamlessly.
Microsoft defines the following capabilities for Hyper-V QoS:

- Enforce minimum bandwidth and maximum bandwidth for traffic flow, which is identified by a Hyper-V virtual switch port.
- Configure minimum bandwidth and maximum bandwidth per Hyper-V virtual switch by using Hyper-V cmdlets or Windows Management Instrumentation.
- Configure multiple virtual network adapters in Hyper-V, and specify QoS on each virtual network adapter individually.

Hyper-V QoS can take advantage of DCB-supported hardware to converge multiple types of Hyper-V network traffic (such as live migration, cluster shared volume, and storage traffic) onto a single network adapter with a guaranteed bandwidth SLA assigned to each type. Doing this would enable far more efficient utilization of expensive high-speed network adapters such as 10-gigabit Ethernet.

# Policy-Based QoS

Using Group Policy, you can determine an application's QoS by the following settings:

- The sending application and directory path
- The destination and source IP addresses and ports
- The protocol, either TCP or UDP
- Active Directory or groups

Working together, these settings will determine the Differentiated Services Code Point (DSCP) value. Use this to inject a value from 0 to 63 into the Type of Service (TOS) field in a TCP4 packet. Note that it also injects the value into the Traffic Class field in an IPv6 packet. Routers on the network then use the DSCP value assigned by an administrator via Group Policy, the routers will prioritize the associated packages.
Policy-Based QoS can be configured using Group Policy or Active Directory domain Group Policy configuration can be created at the computer level, the user level, or both levels if you wish. It's generally recommended to apply your QoS policy at the computer level, because ensures that no matter which users log onto the device, they will all receive the same QoS configuration.
