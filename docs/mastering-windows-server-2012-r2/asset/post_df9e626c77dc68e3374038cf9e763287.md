- **Searching Active Directory** If a client is a member of a domain, the Search Directory command appears on the Network console. You can launch Network by selecting Start ➤ Network on Windows Server 2012 R2.

- **Using net use** You can use the net use command at the command line. The basic syntax is as follows:

```
net use driveletter \servername\sharename
```

For example, to attach to the share Apps on the server BFI and then to be able to refer drive Z, you can use this command:

```
net use Z: \BF1\apps
```

If you later want to remove the mapping, you can use this command:

```
net use Z: /delete
```

# A Set of Credentials Conflicts

Sometimes when you're trying to attach to a share, you'll get an error message that says something like "A set of credentials conflicts with an existing set of credentials on that share." Here's what's happening. You've already tried to access this share and failed for some reason—perhaps you mistyped a password. The server that you have constructed security about tells that you're a deadbeat, and it doesn't want to hear anything. You need the server to forget about you so that you can start all over. You can do that with the / option

Suppose you've already tried accessing the \BF1\Apps share and apparently failed. It might be that you are actually connected to the share but with no permissions. (We know it doesn't make sense, but it happens.) You can find out what shares are connected to by typing net use by itself. Chances, you'll see that \BF1\Apps is on the list. You need to disconnect from BFI server so that you can start over. To do that, type this:

```
net use \BF1\apps /d
```

Then do other net to make sure that all of those connections cleaned up; you may find that you have multiple attachments to a particular server. Or...in a few cases, you may have to disconnect all of your file shares with this command:

```
net use * /d
```

With all the connections closed, you can try net use again, and it will work.

# Using net use on a WAN

Now you are into one of the most difficult situations: connecting to your resources across long distances and great unknowns. If you've ever had to rely on long-distance remote computing, know not to rely on it. But you have a little function in your net arsenal that acts like the "unknown" out of the picture.

Instead of relying on getting to the appropriate name resolution server, getting through to that server, and getting accurate resolution over an inaccurate or unreliable network link, you can now make a drive straight to your server via its IP address. Granted, you now need to know that IP address, but it is a good fail-safe. In our case, we work from several different locations with frame-relay WAN links. The network isn't always good about being able to convert server names to IP addresses, not use \net \BF1 usually tells us that our machine couldn't find \BF1. Even if it does work, name resolution—converting a name such as BF1 to a network address—takes time.

If you know the IP address of the server you're trying to connect, then you can use the IP address in lieu of the server's name. If you know BF1's IP address is 134.81.12.4, you can simply type this:

```
net use \134.81.12.4\apps
```

And, because you're probably connecting from a different network, you might have to use the /user:it's never a bad idea to /persistent:so that your system doesn't spend five minutes trying to reconnect to the next time you start up. For example, if BF1 is a member of a domain BigFirm and you have an account on BigFirm.com named boss, you could ensure that BF1 knows who you are and log on like so:

```
net use \134.81.12.4\apps /user:bigfirm.com\boss /persistent
```

Although there are many conventional methods of connecting to shares using different GUIs, don't overlook the net use command. You'll find it useful.

# Common Shares

In Windows Server, several common shares have already been created for you. Most of these are hidden. If you know of these shares, you can connect to any of them using the IPC path.

C$, D$, and So On. All drives, including CD-ROM drives, are a given share to the root of the drive. This share is what called an administrative share. You cannot change the permissions or properties of these shares, other to configure them for Offline Files (we'll talk about Offline Files at the end of this chapter). Only the Administrators and Backup Operators groups can connect to administrative shares, without modifying the registry or stopping the server service (which stops all sharing). These comes are handy for server administrators who do a lot of management work. Mapping a drive to the C$ share is equivalent to being at C:\ on the server.

ADMIN$ is another administrative share and it is used to map the location of the operating system. If you installed the operating system on D:\\windows, the ADMIN$ maps to D:\\windows.

IPC$ The IPC$ share is one of the most used shares in intercomputer communications, though you will rarely interact with it directly. When you try to access resources on other computers (to read event logs, for example), the system uses named pipes. A named pipe is a piece of memory that handles a communication channel between two processes, whether local or remote, and IPC is used by the named pipes.

NETLOG The NETLOG share is used in conjunction with login requests from users. Once users successfully log in, they are given any profile and script information they are required to run. This script is often a batch file. For example, we have a common batch file that we want all of users to run every time they log in. This allows us to have all clients run a standard set of commands, like copying updated information, mapping standard network drives

# File Server Resource Manager

File Server Resource Manager (FSRM) is an important addition that's configurable with the File and Storage Services role. It includes several additional capabilities that make it easier to manage a file server:

- Creating and managing quota policies
- Creating and managing file screen policies
- Viewing reports

These techniques are covered in the following sections.

# Creating Quota Policies

NTFS has long included quota management capabilities, but they have been significantly improved with FSRM. In short, quotas allow you to monitor and limit the space users consume on a volume or folder.

> STORAGE USAGE MONITORING VS. QUOTA POLIES

Although usage monitoring uses the same technology as quota policies available with NTFS, it has a subtle difference from the quota policies. Storage monitors monitor the entire volume and is configured by default to let you know when the drive reaches 85 percent of capacity. Quota policies can be configured on individuals folders, which allows you to fine-tune what monitor

When creating quotas, you have the ability to set warning limits, set enforcement limits, provide notification of reached limits via email or event logs, and execute commands in response to any limit. Quotas can be set for any share on a server or any specific path.

Quotas can be very useful for monitoring storage on file servers. For example, you may have a file server with 2 TB of storage. You may think this is more than enough, but if users are creating and editing audio and video files, 2 TB of space could disappear quickly.

A quota policy can help limit users to a specific amount. However, audio and video files may be integral to your business, and you may not want to limit the storage space but just ensure you're informed when the storage space reaches a certain threshold. Instead of actually limiting the storage space, you can use the quota policy to monitor the usage.
