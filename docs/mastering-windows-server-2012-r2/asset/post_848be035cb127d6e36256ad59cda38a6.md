As you can see, that's a lot of confusion to understand. Let's pick one of those outputs and analyze it. Because it's new to, let's go with the netsh output. This output has six columns—Publish, Type, Met, Prefix, Idx, and Gateway/Interface Name. Here is what each column represents:

**Publish**: Is this entry sent out in router advertisements? This will show only routers that are advertised.

**Type**: This should show Manual for routes that have been statically added either by hand or routes that are added automatically by the IP layer.

**Met**: abbreviation for "metric." The metric is an arbitrary number that indicates the relative cost of using this route over another. When several routes reach the same destination, the one with the lowest metric is always used. We will look at this in a bit.

**Prefix**: the network prefix that will be matched against the destination to find the shortest route.

**Idx**: abbreviation for "interface index." This is a numbering indicating which interface this route refers to for outgoing traffic, and often used in netsh commands to specify an interface without remembering its name.

**Gateway/Interface Name**: For routes outside the local subnet, this column contains the address of router that can forward them. For routes whose destination is on the local subnet, this column describes the name of the interface on which subnet lies.

# HOW IS THE ROUTING TABLE USED?

When an IP packet is assembled and sent to the IP layer, its destination address is checked against the local subnet mask to see whether the destination is local. If the address isn't local, obviously send it through a router. You will find a router to send the packet, and if necessary, the ARP is consulted and the packet placed onto the appropriate NIC for transmission to its target. In fact, in some instances, it is exactly what routers have been configured to do—respond to every ARP query if the router is the host being searched for.

How do you find the right route in the routing table? There are three simple criteria:

- The routing table entry must be the closest match to the destination address of your packet: in the real world, this is analogous to saying that if you had two couriers to offer your package and deliver it, you'd skip the one who says, "I can get your package delivered to anyone in England," in favor of the one who says, "I can get your package there much faster."

- If there are possible routing entries, the one with the lowest metric is chosen: Metrics are arbitrary numbers, and their only purpose is to act as tiebreakers in this step of finding matching route in the routing table. All that is necessary is to ensure routes to the same destination can be sorted by metric to indicate the network designer's preference for which router should be first.

- If there is more than one matching entry, the first one in the list is chosen: that "the first one in the list" is difficult to control accurately. As a result, you should be careful to choose metrics appropriately so that you can always predict which route gets chosen.

Once the IP layer has a routing entry, as we mentioned earlier, it will send the packet to the router listed as the gateway in that entry. Of course, that means the IP layer must use ARP to determine which MAC address corresponds to the IP address of the router. Note that the destination IP address in the IP packet that is eventually sent to the router is the original destination IP address, not that of the router.
