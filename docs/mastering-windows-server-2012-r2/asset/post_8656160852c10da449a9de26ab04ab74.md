### A BETTER DESTINATION

Rhonda Layfield, a colleague and a deployment guru, has a great tip for when you are installing ADK. You're asked to choose a location for installing ADK. We usually choose the default of C:\Program Files (x86)\Windows Kits\8\. Once you start using ADK a lot, however, you'll realize how much command-line stuff you need to do. By burying your work in a deep path full of long names isn't exactly command-line friendly. Rhonda's tip is to simply install ADK into C:\ That will save keyboard and tear.

You have arrived at the ADK select features screen. Let's take a moment to discuss these features. You will notice the list in Figure 2.67 that SQL Express is not shown. This is because I already have SQL Server on my computer. If you do not have SQL Server, then the SQL Server Express option will be in the list and is required for the Application Compatibility Toolkit (ACT).

# FIGURE 2.63
ADK features

![](img/41a83208e6906a3732620203b836cea7_120_0.png)

- **Application Compatibility Toolkit (ACT)**: This toolkit checks the compatibility of the computers you are going to do the unattended installation on.
- **Deployment Tools**: The deployment tools are required to do unattended installations because they are exactly what does the automated installation. This is really a subset of tools for ADK. It contains several support programs such as the Deployment Image Servicing and Management (DISM) tool, OEM Activation, and Windows System Image Manager, to name a few.
- **Windows Preinstallation Environment (Windows PE)**: This is a bare-operating system that is placed on the target machine. This is needed to prepare for the install process with the host computer.
- **User State Migration Tool (USMT)**: The User State Migration Tool migrates user account and application settings to the target machine. This saves the administrator time by not having to set the system back up to the original specifications.
- **Volume Activation Management Tool (VAMT)**: The Volume Activation Management Tool is self-explanatory. It handles the operating system software applications.
- **Windows Performance Toolkit**: This is another subset of tools used to trace the installation process and record events that would occur during the install. This is possible because it is built on the Event Tracing for Windows (ETW) infrastructure.
- **SQL Server Express**: SQL Server Express is a portable version of SQL Server and is required by the Application Compatibility Toolkit (ACT) because it stores data that will be used during the installation process.

## Creating an Answer File

Before you create an answer file, you should understand a little of what it is and what's going on behind the scenes.

You have been reading about it this far, but what exactly is an answer file? An answer file is an XML file that answers installation questions for you during the installation process. If you have installed an operating system, then you know at some point you will need to set the time zone, for example. Instead of setting your time manually, you could specify the time zone in the answer file. When the installation would normally prompt you for the time zone, the answer file will answer this for you. This may not mean much to you if you're installing one or two computers, but when you have many computers to do, this process will work for you and you will be glad you needed this.

When Windows 8 or Windows Server 2012 R2 is installing, the installation outline goes through some or all of seven configuration passes, described in Table 2.3. Each of these passes is responsible for carrying out certain tasks. You can think of them as stages. Some tasks can be performed in more than one of the passes. Typically only three of these passes actually need to be executed for Windows to install.

# TABLE 2.3: The Configuration Passes

| PASS | DESCRIPTION |
|---|---|
| windowsPE | Boots up the Windows PE installation environment, configures the product key, and configures the installation disk. |
| offlineServicing | Applies updates to the Windows image, including packages, patches, and languages. |
| generalize | Removes system-specific information, such as network and domain settings. |
| auditSystem | Processes unattended setup before a user logs on. |
| auditUser | Processes unattended setup after a user logs on. |
| systemPass | Configures settings that are unique to the system, such as configuration and regional settings. |
| specializePass | Prepares the system for use by running sysprep. |
