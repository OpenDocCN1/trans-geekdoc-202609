IPv6, by comparison, does not enable weak deands by default, the packet will always be sent to the interface whose IP address matches the source IP address of the outgoing packet. No change in there in Windows Server 2008.

The change, however, is that you can change this behavior. As with all new network configuration commands, you can achieve this through netsh:

```
netsh interface ipv4 set interface <NameOrIndex> weakhosts-enabled
netsh interface ipv4 set interface <NameOrIndex> weakreceive-enabled
netsh interface ipv6 set interface <NameOrIndex> weakhosts-enabled
netsh interface ipv6 set interface <NameOrIndex> weakreceive-enabled
```

Of course, you can set any of these values to disabled, as default, if you prefer that behavior.

Disabling weak hosts is a security feature for multiphomed computer, in packets will be discarded if they are not received on the anticipated interface, but this may discard valid traffic that really should reach your computer, if the routing and cabling sends it to the wrong interface your network design needs revisiting. A local link, or subnet, should not find itself split across two network cards in a single computer.
