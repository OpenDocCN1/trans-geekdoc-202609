If the client says "Connection refused," then the client has received a TCP RST ostensibly
from the IP address you tried to reach. This could be a sign of a firewall between you and the
server, or the server application itself might not be running.

If the client says "Timed out," then the client has received nothing in response to
multiple requests. This means either "stealth" firewall is in between the client and
server or the server computer is unreachable right now, either because there is no network
route to it or the computer is not currently running.

# AVOID STEALTH FIREWALLS

Although security proponents suggest using stealth firewalls, we do not. Stealth firewalls do
respond to unexpected incoming requests, preferring to remain silent. The appropriate
TCP expression for "go away and don't talk to me" is a TCP RST; silence traditionally means "try
a in a little." Not only is RST going to restrict accidental connections from retrying,
it will also prevent someone from using IP spoofing to pretend to be the server. If an IP spoofing
session is under way, the generic server will receive a SYN, and the RST it in response
will cause the client to abort its connection. In the absence of an RST, the client will continue to
the spoofed server, which is a security risk.

# Pinging a Remote Computer with ping

ping is the classic tool that many of us have used for decades. Its design has varied little, but
the basic principle is to send a packet to a remote machine that the remote machine is supposed
to reply and wait for the reply and indicate whether it is successful. Windows Server
2012 R2 still uses the "classic" method of sending an ICMP echo to the remote machine
(with extra data) "abcdefghijklmnopqruvabcdefgh" and waiting for the
ICMP echo to come back.

Thus, it is important to remember that pings only ICMP echo connectivity; it does not
the TCP connection to a server port. Only a TCP connection to the server port will do (which is
we suggested earlier that your debugging tool is you), so, as you can demonstrate by first pinging
and many firewalls block the ICMP echo server, so you can demonstrate connecting with a web browser to microsoft.com, a failed ping does not necessarily
mean a failed result.
