# THE ADD ROLES AND FEATURES WIZARD

The new Add Roles and Features Wizard is gigantic in scope and dynamic to your selections. We could write an entire book on all the options and features in this wizard because they change dending on your choices. We are only going to show you the most common administrator uses.

Lots of these new wizards have a welcome screen that describes the wizard (see Figure 2.35). You can disable the welcome screen from popping up by selecting the "Skip this page by default" check box.

On the next wizard (see Figure 2.36) you can select between "Role-based or feature installation" and "Remote Desktop Services installation", this is all new in Windows Server 2012 R2.

On the "Select installation type" page, you have two choices. You may need a role-based installation if you want to install (all) parts or features on a single server. You may select "Remote Desktop Services installation" to install either virtual machine-based desktop or a session-based desktop for Remote Desktop Services. The "Remote Desktop Services installation" option distributes (only logical parts) of the Remote Desktop Services role across different servers. We are going to use role-based for a single server.

# HMM...ROLES AND FEATURES DO MAKE SENSE

Note that you are told that you need to install additional features with IIS. This is the first hint that there is some intelligence behind all of these roles and features functionality in Windows Server 2012 R2. You will continue to see the wizard add more screens of options as you move forward.

A role is a subcomponent of a role. It is either the core component of the role or an optional component. Each role has one or a set of default roles. You can see in Figure 2.42 that the Server role has several additional services checked by default. Also shown are a number of optional role services that you can install if you require them.

# FIGURE 2.42 Role Services

![](img/41a83208e6906a3732620203b836cea7_97_0.png)

Microsoft has modeled all the available roles, role services, and the conflicts. It knows the relationships, the dependencies, and the conflicts. This is applied in Server Manager. For example, if a role requires a certain role service, clearing that role service will result in clearing the role. It removes the guesswork for administrators, which is a good thing.

You get a confirmation screen where you can verify your new configuration before anything is installed (Figure 2.43). Click Install to track that.

Some roles and role services can take a little time to install. You can get a progress screen so you can track the progress.

The installation will eventually finish. You can see that our role installation succeeded. Since you have not configured automatic updating for patching this server yet, you may receive a warning on the role you install. # INSTALLING ROLES USING POWERSHELL

You can install roles and features using PowerShell. At first, PowerShell might seem a bit clunky. But you will find that after a little while it is much faster to. We knew that depending on your typing skills, may not have all of that fast!

You can launch PowerShell from the start and right-clicking the PowerShell button. You will see a new menu bar at the bottom. Make sure you launch it with administrative rights. The PowerShell modules related to Server Manager are not loaded by default. This command to load them:

```hell
PS:\Users\Administrator> import-module ServerManager
```

You can run the command with the Get-WindowsFeature cmdlet to report on what roles, and features are installed:

```hell
PS:\Users\Administrator> Get-WindowsFeature
```

The generated report is pretty long, eh? We'll have to forgive us for not including the entire thing (see Figure 2-45!) We have rain features to think about, so we've included snippets of the query.

None of the role, role services, or features are with our IIS since we already added one. X designates that the role, role feature, or feature is installed as is. Here, we are working with a fairly blank server. You will see in Figure 2.46 that our Web IIS is installed.

That pretty simple, eh? And it was much faster than what we wanted, and we could run it as fast as we type it, using the GUI.

Some roles, role services, or features will require a reboot. You can have this automatic by adding the -restart flag to each of your command.

```hell
PS:\Users\Administrator>Install-WindowsFeature -Name Web-Ftp-Server -Restart..
```
