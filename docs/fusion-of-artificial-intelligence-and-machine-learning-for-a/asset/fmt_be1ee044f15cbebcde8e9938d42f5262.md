## 10.3 Image Authentication

Authentication means verifying the real value or content, which is achieved without being tampered with. In real-time applications, it is very difficult to maintain the original identity due to various reasons generated by the surroundings or communication devices. Image authentication does not accept any tampering in the image data. The conventional approach based on cryptography evaluates message authentication from images using a hash function. This hash function is then encrypted with the sender’s private key and attached to the image. For more secure data exchange between parties, the hash can be encrypted with the help of the beneficiary’s public key. The authentication and verification process are depicted in [Figure 10.5](#ch10.xhtml#fig10_5)(a) and (b). The recipient evaluates the hash from the received image, which was attached to the recovered image and decrypted with the help of the private key. Hash evaluation of images using column and line functions is obtained, and these hashes are stored and compared with those obtained from each column and line of the image to be verified. If any mismatch in the hash function is observed, the image is declared to be tampered with; otherwise, it is announced as authentic. Since hash functions are very sensitive to any slight changes in binary data or image pixels, this puts limits on image verification for many applications. The fragile watermarking approach is used to create a watermark and place it in the image to be protected in such a way that any changes found are also reflected in the placed watermark. Verifying the existence of the placed watermark approves the authenticity of the image and finally localizes the damaged areas. This method does not accept any distorted image and authenticates only if all its pixels remain constant. The generation and verification process are depicted in [Figure 10.6](#ch10.xhtml#fig10_6)(a) and (b).

Fragile watermarking algorithms are based on forming a watermark from the identity of an image, and the watermark is evaluated from a set of image pixels. The set of pixels, taken from the secret key `SK[I]`, can be encrypted with another set’s least significant bits using the secret key `SK[I]`. To enhance the security of the algorithm, the set of pixels can be determined by another secret key, `SK[2]`.

The purpose of a digital signature is to electronically sign a document, such as when signing a contract or withdrawing money from a bank. Digital signatures can be transferred electronically along with a signed letter. However, there are several issues associated with digital signatures.

Firstly, a digital signature requires an algorithm to be attached to the signature for electronic transfer. Secondly, there are problems related to verification and signature authentication. For example, when a person’s signature is verified by comparing it with their certified signature while making a purchase using a credit/debit card. This authentication approach is not strong enough, as it is easy to copy the signature of a certified person. Therefore, electronic signatures can be tested by anyone with knowledge of the verification algorithm.
