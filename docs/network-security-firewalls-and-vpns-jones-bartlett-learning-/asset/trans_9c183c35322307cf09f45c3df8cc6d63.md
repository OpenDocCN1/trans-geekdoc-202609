如果前四项检查中的任何一项失败，请查看安装屏幕下方的故障排除部分。

防火墙可能会干扰 Openswan，因此你需要留意防火墙设置。请确保允许 UDP 500 和 ESP（协议 50）通过防火墙。这是必要的，因为为了让 IPSec 流量穿越防火墙，你需要在双向开放以下端口/协议：

- 协议 50 ESP
- 协议 51 AH（可选）
- UDP 端口 500 IKE
- UDP 端口 4500（如果你使用 NAT 穿越通过 NAT/其他防火墙建立隧道）

Smoothwall 防火墙与 Openswan 配合良好。你需要执行以下操作：

- 在区域文件中为远程 VPN 创建一些名称。
- 根据区域文件中的名称描述要使用的 IPSec 接口。
- 在策略文件中描述区域文件中命名的网络如何交互。
- 在隧道文件中定义远程站点的公共 IP 地址。

Smoothwall 会自动为隧道文件中命名的网络创建允许 IPSec 所需的规则。

## VPN 实施最佳实践

VPN 的安全性取决于其所运行的计算机。在部署 VPN 之前，请查看[表 14-1](#22_chapter14.xhtml#tab14-1) 中列出的实施最佳实践（应该做和不应该做的事）。

VPN 服务器的其他可用步骤包括：

- **使用强身份验证**——确保只有授权客户端才能连接。由于 VPN 服务器将拥有公共 IP 地址，因此可从世界任何地方的互联网用户访问。如果有人能轻松登录 VPN 服务器，该人员就能轻松访问你的内部网络。
- **使用强加密**——当今 VPN 中使用的两种主要加密协议是 IPSec 和 SSL。这两种协议中的任意一种都足以保护 VPN，但也应仔细评估其他协议。
- **在防火墙后保护 VPN 服务器**——无论你使用的是主机到网关还是网关到网关配置，都不应将 VPN 服务器直接置于互联网上。相反，应将其置于防火墙后面，例如 DMZ 配置中。这将提供一层防护，抵御来自互联网的攻击。

**![Image](images/lock.jpg) 本章小结**

本章讨论了 VPN 的不同类型、设计、配置、实施和测试。还讨论了市场上可用的主要 VPN 技术及其实施中的最佳实践。VPN 可以在主机到网关配置中为远程客户端提供对内部网络的访问。它们也可以使用网关到网关模型为同一组织内的两个办公室之间提供访问。

有许多不同的 VPN 应用程序可用。Microsoft 在服务器操作系统中提供了内置的 VPN 解决方案。Cisco 和其他供应商销售可轻松安装和配置的 VPN 设备。你也可以使用 UNIX 或 Linux 系统并安装免费的 VPN 解决方案，如 Openswan。

VPN 正日益成为互联网日常生活的一部分。许多人使用它们访问办公室的资源，如电子邮件服务器和其他内部网资源。随着许多公司发现让员工在家工作更便宜，从而免除了租赁额外办公空间的需求，这一趋势肯定会变得更流行。

站点到站点 VPN 也将继续部署，因为大大小小的公司发现越来越有必要与远程办公室共享对其主网络的访问。一个值得注意的领域是 IP 电话领域，VPN 使所有远程办公室能够使用 VPN 中心辐射网络中心的单个 IP 交换机。办公室内部通信经过加密，使用单个交换机可节省资金。
