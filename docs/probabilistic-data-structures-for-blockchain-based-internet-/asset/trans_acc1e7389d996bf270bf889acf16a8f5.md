

# 哈希表冲突解决

在链表中，插入操作效率高，但查找仍然需要线性时间。此外，在有序数组中，查找效率高，但插入效率不足。值得注意的是，对于 `n` 个元素，链表可以在 `O(n)` 时间内搜索，而二分查找需要 `O(log2n)` 时间，数组搜索需要 `O(n)` 时间。与此相反，哈希表允许插入、删除和搜索操作非常快，即在平均情况下为 `O(1)` 时间（参考 [表 5.1](#07chap_05.xhtml#tab5_1)）。让我们以哈希表数据结构为例，如 [图 5.7](#07chap_05.xhtml#fig5_7) 所示，哈希函数为：`h(x) = xmod10`，其中 `x` 是键。假设项目为 (key, value) 格式，项目为 (1,999)、(2, 9876)、(45, 5434)、(90, 9877)。因此，哈希表组织数据，以便对于给定的键，可以快速查找任何数据。然而，可能会出现两个或多个数据项发生冲突并哈希到相同索引的情况。这被称为冲突问题。例如，如果我们要插入项目 (55, 7767)，此插入将导致冲突，因为索引 5 处已经有一个项目。一个被称为良好哈希函数的函数可以避免冲突。冲突解决技术分为两个主要部分，即封闭寻址和开放寻址。为了避免冲突，封闭寻址使用额外的数据结构，而开放寻址哈希将所有数据存储在表中。更正式地说，在开放寻址的冲突解决情况下，将依次尝试单元格 `h0(x), h1(x),……., hm-1(x)` 以满足等式，

| 删除 || `O(1)` || `O(n)` |

## 5.6.1 链地址法

避免冲突的一种可能方法是简单地将具有相同索引的数据存储在数组相应索引的链表中。此方法称为链地址法。在这里，每个数组槽持有指向链表的指针，该链表包含所有哈希到相同哈希索引的键的值，如 [图 5.9](#07chap_05.xhtml#fig5_9) 所示。

**查找：** 当然，此解决方案最终会导致线性时间，即在最坏情况下查找为 `O(n)`。因为在最坏情况下，所有键可能具有哈希表的相同索引，因此，为了执行顺序搜索，时间要求为 `O(n)`。此外，此方法的缓存性能不佳。尽管此方法易于实现，且哈希表永远不会填满。

**删除：** 要删除，首先需要搜索键，然后删除。由于搜索的最坏情况时间复杂度为 `O(n)`，因此删除所需时间为 `O(n)`。

## 5.6.2 线性探测

线性探测是处理冲突的一种流行方法。探测简单意味着在发生冲突时，找到要放置键的下一个空单元格。此方法属于开放寻址的冲突解决。在发生冲突时插入，将尝试紧邻的下一个单元格，直到找到空单元格。因此，表的大小应等于或大于键的总数。正式地说，对于线性探测，`f` 是线性函数，在等式 5.3 中大多为 `f(i) = i`，即，`h[i](x) = (h(x) + i)modm`。显然，搜索的最坏情况复杂度为 `O(m)`。

然而，线性探测面临聚集问题，即，如果多个连续项形成一个组，那么查找空槽进行插入或搜索项将花费大量时间。让我们通过一个示例来理解线性探测，假设 3、17、14、6、21、13、7、22 是要依次插入的键，`h(x) = (2x + 3)mod10` 是键 `x` 的哈希函数。参考 [图 5.10](#07chap_05.xhtml#fig5_10)，每个键的哈希值如下：

`h(3) = 9`

`h(17) = 7`

`h(9) = 1`

`h(6) = 5`

`h(21) = 5`

`h(13) = 9`

`h(7) = 7`

`h(22) = 7`

![FIGURE 5.10 线性探测示例。](images/fig5_10.jpg)

**FIGURE 5.10**  

线性探测示例。

**插入 3,17,14,6：** 插入这 4 个元素不会遇到任何冲突。因此，它们根据给定的哈希函数插入到其哈希索引处。

**插入 21**：由于 `h(21) = 5` 且该位置已被键 6 占用。因此，让我们尝试使用等式进行线性探测：`h[i](x) = (h(x) + i)modm`，其中 i=0 到 m-1

**i=0**: `h[0](x) = (h(x) + 0)modm ⟹ h[0](x) = (5)mod10 = 5`，该位置已被占用。

接下来，**i=1**: `h[1](x) = (h(x) + 1)modm ⟹ h[1](x) = (5 + 1)mod10 = 6`，该位置空闲。因此，21 被插入到位置 6。

同样，13、7 和 22 被插入。

此插入示例在 [图 5.10](#07chap_05.xhtml#fig5_10) 中展示。

## 5.6.3 二次探测

这是另一种开放寻址方案，用于解决哈希表中的冲突。它通过获取键的哈希值并添加二次多项式的连续值来工作。更正式地说，对于二次探测，`f(i) = i²`，即，`h[i](x) = (h(x) + i²)modm`，其中 i=0 到 m-1。

该方案具有良好的内存缓存，因为它保持了引用的局部性。此外，与线性探测相比，它避免了聚集问题。让我们通过一个示例来理解二次探测。参考 [图 5.11](#07chap_05.xhtml#fig5_11)。再次考虑 3、17、14、6、21、13、7、22 是要依次插入的键，`h(x) = (2x + 3)mod10` 是键 `x` 的哈希函数。每个键的哈希值如下：

![FIGURE 5.11 二次探测示例。](images/fig5_11.jpg)

**FIGURE 5.11**  

二次探测示例。

`h(3) = 9`

`h(17) = 7`

`h(9) = 1`

`h(6) = 5`

`h(21) = 5`

`h(13) = 9`

`h(7) = 7`

`h(22) = 7`

**插入 3,17,14,6：** 插入这 4 个元素不会遇到任何冲突。因此，它们根据给定的哈希函数插入到其哈希索引处。

**插入 21**：`h(21)` 是 5，已被键 6 占用。因此，让我们尝试使用等式进行二次探测：`h[i](x) = (h(x) + i²)modm`，其中 i=0 到 m-1 **i=0**: `h[0](x) = (h(x) + 0)mod m ⟹ h[0](x) =(5)mod 10 = 5`，该位置已被占用。

接下来，**i=1**: `h[1](x) = (h(x) + 1²)mod m ⟹ h[1](x) =(5+1)mod 10= 6`，该位置空闲。因此，21 被插入到位置 6。

**插入 13**：`h(13) = 9` 已被占用。因此，让我们尝试二次探测 **i=0**: `h[0](x) = (h(x) + 0)mod m ⟹ h[0](x) =(9)mod 10 = 9`，该位置已被占用。

**i=1**: `h[1](x) = (h(x) + 1²)mod m ⟹ h1(x)=(9+1)mod 10= 0`，该位置空闲。因此，13 被插入到位置 0。

**插入 7**：由于 `h(7) = 7` 已被占用，因此让我们尝试二次探测。 **i=0**: `h[0](x) = (h(x) + 0)mod m ⟹ h[0](x) =(7)mod 10 = 7`，该位置已被占用。

**i=1**: `h[1](x) = (h(x) + 1²)mod m ⟹ h[1](x) =(7+1)mod 10= 8`，该位置空闲。因此，7 被插入到位置 8。
