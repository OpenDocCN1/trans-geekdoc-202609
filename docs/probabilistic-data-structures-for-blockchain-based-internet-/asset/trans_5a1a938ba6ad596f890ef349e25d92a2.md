# [频率计数查询概率数据结构](#contents.xhtml#rchapter12)

## [12.1 简介](#contents.xhtml#rsec12_1)

此类别涉及估计集合中特定项目的计数。例如，搜索引擎使用频率估计器来提取经常搜索的查询，网络路由器使用它们来定位常见的源地址和目标地址。一种提出的解决方案是从集合中随机提取一个显示完整集合属性的样本。然而，实现真正的随机性是一项相当不利的任务。因此，抽样也不是解决我们问题的有用方法。同样，使用哈希表时，随着添加更多项目，内存需求会变得很高（线性空间需求）。多数算法 \[[52](#bib.xhtml#ch00-bib-52)\] 和 Misra-Gries \[[144](#bib.xhtml#ch00-bib-144)\] 算法是解决频率计数问题的两种流行的确定性算法。一种有效的方法是采用基于近似的查询来处理流数据。在此背景下，一种流行的数据结构是“草图”（Sketch），它基于摘要方法执行近似查询。基于近似和随机化的草图算法在此背景下是空间和时间高效的解决方案。草图是指一类算法，它通过一个比实际数据大小小得多的紧凑摘要来描绘大量数据 \[[89](#bib.xhtml#ch00-bib-89)\]。机器学习、NLP、安全是草图变体被使用的一些重要领域 \[[203](#bib.xhtml#ch00-bib-203)\]。草图还解决了抽样技术面临的问题，并在实践中支持并行化。草图中的并行化意味着它可以在数据的不同部分上独立实现，并进一步合并这些部分，从而得到一致的聚合。简而言之，并行化为面临可扩展性挑战的问题提供了一种简单的分治方法。此外，草图具有次线性渐近计算复杂度，从而导致低计算能力和存储。该类别下的算法由两个参数表征，即 `ϵ` 和 `δ`，其中 `ϵ`（精度参数）描述了频率估计结果中最大可承受的误差，最大概率为 `δ`（置信参数）。这两个参数可根据可用空间进行调整。此外，对于草图，在估计频率时，误差可能是高估、低估或两者的组合。

## [12.2 Count-Min Sketch](#contents.xhtml#rsec12_2)

Count-Min Sketch (CMS) \[[66](#bib.xhtml#ch00-bib-66)\] 是最流行的用于执行频率计数查询的草图数据结构。具体来说，这种数据结构用于对流数据进行高效的查询处理。CMS 使用数据的压缩表示来保证低存储需求。类似于哈希表，CMS 使用一个宽度为 `w`、深度为 `d` 的表。在设计草图时，参数 `w` 和 `d` 是固定的。表全部初始化为零。与哈希表不同，CMS 不使用单个哈希函数，而是为表的每一行使用不同的哈希函数，即总共使用 `d` 个两两独立的哈希函数，如 [Fig. 12.1](#15chap_12.xhtml#fig12_1) 所示。两两独立性构建了一个通用哈希族，从而导致最小碰撞 \[[113](#bib.xhtml#ch00-bib-113)\]。来自通用族的哈希函数是那些碰撞概率较低的类。应选择哈希函数，使其将传入的项目分散开，以达到高精度。每个哈希函数接收传入元素，并将其映射到范围 1,2,3,…..,`w` 内的相应列。CMS 只消耗次线性空间，但由于哈希冲突而存在高计数的缺点。线性空间复杂度意味着随着数据大小的增加，内存消耗也随之增加，两者之间存在直接关系。另一方面，次线性空间并不消耗与数据量相等的内存。然而，它消耗的内存比数据少或少一半，如 [Fig. 12.2](#15chap_12.xhtml#fig12_2) 所示。CMS 支持的操作如下：

* `Update(i, c)`：此函数将任何传入元素 `i` 的频率更新一个计数 `c`。对于每个传入元素，应用所有 `d` 个哈希函数，并将每个哈希函数对应的 1 到 `w` 之间的位置更新，方法是在现有值上添加一个值 `c`。

* `Estimate(i)`：此函数计算集合中元素 `i` 的频率。首先定位与 `d` 个哈希函数对应的位置。最后，元素 `i` 的频率计数是从 `d` 个获得位置中取出的最小值。由于使用了哈希函数，不同元素可能会在同一单元格上发生冲突。因此，通过选择最小值，可以为频率查询获取最接近准确的结果。显然，CMS 的结果可能会高估，但永远不会低估。值得注意的是，CMS 先进行计数，然后再计算最小值，因此得名 Count-Min Sketch。

* `Delete(i, c)`：要从集合中删除元素 `i`，只需在每一行中将 `d` 个对应位置的值减去计数 `c`。

值得注意的是，CMS 的频率估计在某种程度上类似于计数 BF。与其他 PDS 一样，CMS 的用例对于不关心元素精确频率计数的应用是有益的。数据库查询规划、流量监控中的重点发现、NLP、压缩感知、联合大小估计是频率查询估计 PDS 的一些有前途的用例。CMS 也支持并行化，因为这里可以通过对表格求和来合并子草图。但是，只有当两个草图使用相同的 `w` 和 `d` 值以及相同的哈希函数构建时，才能合并。此外，CMS 支持对任何可加和值（支持幺半群）的近似加法。CMS 的一个缺点是它对数字的真实频率计数显示出有偏估计的行为。Count-min-log sketch 和 count-min-mean sketch 是 CMS 的一些最新改进。显然，对于任何项目 `i`，实际频率（`f[i]`）始终小于或等于估计频率（`f̂[i]`）。对于大小为 `w*d` 的草图，设置 $w = \\frac{2}{\\epsilon}$ 和 $d = log\\left( \\frac{1}{\\delta} \\right)$ 可确保估计操作最多超过实际频率 `ϵ*N`（`f̂[i]` ≤ `f[i]` + `ϵ*N`），概率至少为 1 − `δ`。改变 `w` 和 `d` 值的影响在 [Table 12.1](#15chap_12.xhtml#tab12_1) 中表示。因此，大小为 `N` 的基数估计最多有 $\\frac{2N}{w}$ 的误差，概率至少为 $1 - \\left( \\frac{1}{2} \\right)^{d}$。CMS 消耗的空间为 O( $\\frac{1}{\\epsilon}log\\frac{1}{\\delta}$)，更新和估计所需时间由 $O\\left( log\\frac{1}{\\delta} \\right) = O\\left( d \\right)$ 给出。CMS 还通过减少相应的哈希位置来支持删除。
