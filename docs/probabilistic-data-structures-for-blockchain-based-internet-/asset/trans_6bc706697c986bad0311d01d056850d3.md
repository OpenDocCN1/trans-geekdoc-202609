

对于基于区块链的加密货币系统，此类攻击包括针对交易过程，即禁用机器以阻止新交易的生成。发起此攻击的一种方式是创建各种交易，在恶意攻击者预先创建的钱包之间转移资产。通过创建多个交易，矿工会投入其中为这些交易求解工作量证明。拒绝服务是由处理合法交易的要求引起的。值得注意的是，在比特币区块链网络中，会收取交易费用，但该费用对攻击者来说并不高到无法支付。

例如，当名为比特币黄金 \[[26](#bib.xhtml#ch00-bib-26)\] 的加密货币推出时，它立即受到 DDoS 影响，导致网站宕机四小时。比特币黄金硬分叉注意到每分钟有 1000 万次访问。后来的推特声明显示，大部分访问涉及通过中国路由的 IP 地址。

另一项关于在区块链上发起 DDoS 攻击的努力由 \[[143](#bib.xhtml#ch00-bib-143)\] 的作者讨论，该攻击被称为 `blockchain denial of service (BDoS)`。这基于区块链协议为安全性分配激励的基本原理，即矿工成功挖出一个区块会获得奖励。BDoS 通过给予矿工更高的利润来对抗系统，从而利用矿工的理性。与传统的 DoS 攻击相比，BDoS 可以用显著更少的资源破坏区块链。与自私挖矿不同，此处攻击者的目标不是为对手提供收益，而是破坏区块链网络。让我们来了解 BDoS 攻击。

如果多个矿工同时挖出区块，会导致分叉（如果区块具有相同的父区块），在这种情况下，链会出现不同的分支。根据比特币规则，为了防止歧义，只扩展单一链，即矿工应扩展主链中最长的链。然后，与该链分叉的区块奖励将被忽略。然而，为了避免奖励损失，矿工通常在当前区块验证之前就开始挖矿。值得注意的是，一旦接收到区块头的元数据，他们就会开始在最新区块上挖矿。因此，通过避免在区块上浪费资源，矿工试图增加挖出下一个区块的机会。这种仅使用区块头进行挖矿的方法称为 SPV 挖矿，如前面在 [第 7 章](#09chap_07.xhtml) 中所述。发起攻击时，攻击者创建一个区块并仅发布其区块头。给定区块头后，矿工尝试扩展该区块。然而，攻击者从不发布完整区块，理性矿工尝试的该区块永远不会被包含在区块链的主链中，并且来自该区块的预期奖励为零。因此，攻击者创造了一种情况，诚实矿工最终会损失奖励。此外，矿工无法处理合法请求，这导致诚实矿工放弃挖矿，从而造成资源浪费。

DDoS 攻击的对策包括识别洪水攻击的源头，然后设计过滤器以阻止该源头。只有当源地址在预期 IP 地址范围内时，才允许来自该源的出站和入站流量。

注意：

DDoS 攻击不会直接影响存储在区块链网络中的数据的安全性，但被攻击的节点无法参与共识机制，其计算能力和资源因此被浪费。

## [15.2 内存池交易计数](#contents.xhtml#rsec15_2)

所有等待确认的交易都存储在比特币网络的内存池(`mempool`)中。要获得确认，交易首先需要从 `mempool` 进入区块。值得注意的是，区块链网络中没有全局内存池。比特币网络上的每个节点通过连接到比特币网络来构建其自身版本的 `mempool`。`mempool` 中的每个交易都支付费用并具有一个大小。显然，矿工会优先选择费用较高的交易。每当节点重新启动时，`mempool` 就会被清除。节点向矿工支付费用以挖出交易。区块中交易的最大数量各不相同，因为并非所有交易都具有相同的大小。`mempool` 中交易数量越多，流量拥堵就越严重，从而导致更长的确认时间。此外，网络的交易费用由网络拥塞程度和交易大小决定。比特币区块大小为 1 MB，这意味着矿工每个区块大约可以获取并处理 1 MB 的交易，大约每 10 分钟一次。对于比特币网络，如果交易数量超过 1 MB，会导致网络拥塞，矿工随后会优先处理费用较高的交易。在此背景下，比特币的 `mempool transaction count` 指标 \[[27](#bib.xhtml#ch00-bib-27)\] 揭示了导致拥塞的交易数量。（相比之下，`mempool size` 将指定拥塞将持续多久。）

## [15.3 线性计数、LogLog 和 HyperLogLog 与区块链的交互](#contents.xhtml#rsec15_3)

尽管文献中没有现有工作将 HLL、LogLog 或线性计数集成到区块链中。但如下所述，这些 PDS 可用于区块链网络中的计数目的。值得注意的是，我们以 HLL 为背景提出了我们的观点，因为它是这三种算法中最流行且最高效的算法。

### [15.3.1 计算内存池中的交易](#contents.xhtml#rsec15_3_1)

这种基数估算 PDS 可用于计算 `mempool` 中的交易。`Mempool transaction count` 告诉有多少笔交易导致了拥塞。由于区块链网络上的每个系统对这些未确认交易的存储容量不同。在此背景下，HLL 可用于计算每个节点 `mempool` 中的交易数量。要实现此逻辑，每当有新交易添加到 `mempool` 时，它首先会被哈希，然后根据最长零序列的值将生成的哈希存储在桶中。最后，使用桶中值的调和平均值将桶中的值组合起来。此外，可以使用编程在 `mempool` 上设置上限，指定添加到 `mempool` 的最大交易数量以避免拥塞。要设置限制，也可以使用智能合约的概念，开发一个包含逻辑的合约，指定 `mempool` 中的最大交易数量。使用 HLL 检查区块链网络中拥堵流量的用法如 [图 15.1](#19chap_15.xhtml#fig15_1) 所示。
