

为了解决后续问题，即块大小限制，作者提出了一种使用双计数布隆过滤器（`DCBF`）的吊销检查方法。`DCBF` 提供高效的查询处理和经济的存储。系统的全部证书被分为两个集合，即有效证书集和吊销证书集。为了存储两种不同类型的集合，采用了两个计数 BF，即 `CBF1` 和 `CBF2`。更新或新创建的证书存储在 `CBF1` 中，而吊销证书首先从 `CBF1` 中删除，然后存储在 `CBF2` 中。当创建一个块时，`CBF1` 和 `CBF2` 都存储在一个块中。要检查吊销证书，首先，待检查的证书通过 `CBF2`。如果此 BF 返回负结果，则该证书被标记为有效证书。否则，在出现正结果的情况下，该证书在 `CBF1` 中进行匹配。如果在这种情况下结果为负，则该证书肯定已被吊销，而对于正结果，则在块中检查证书的相关操作。比较两个 BF 的结果可确保证书的准确状态，且没有任何误正。

### [14.2.4 区块链与 BF 在智能电网领域的集成](#contents.xhtml#rsec14_2_4)

在研究工作 \[[91](#bib.xhtml#ch00-bib-91)\] 中，作者提出了在智能电网中实现隐私的解决方案。在此，作者使用区块链进行数据聚合，而不是依赖可信的第三方。系统架构根据用户的用电类型将智能电网的所有用户划分为不同的组。所有用户的密钥由密钥管理中心（`KMC`）初始化。`KMC` 基本上为每个用户分配多个公钥和私钥，公钥用作用户的化名。在每个时间槽中，根据用电数据选择一个新的矿工节点。选定的矿工节点聚合节点数据，并将此数据记录在私有区块链中以确保消息完整性。要选择矿工节点，遵循一个随机过程。其用电数据最接近某个时间槽平均用电数据的节点将被选为矿工节点。网络中的用户可以创建多个化名来提交其电力生成/消耗信息。这样，用户的真实身份就不会被泄露。

此外，为了确保基于区块链的系统中的快速身份验证，使用了 BF。BF 使用零知识证明来探测伪造化名的存在。布隆过滤器是为每个不同的组使用该组的化名构建的，构建的 BF 会发送到相应组中的所有节点。要验证用户的有效性，将用户的注册化名传递给 BF。如果存在正匹配，则用户已通过身份验证，否则未通过。值得注意的是，身份验证是使用零知识证明完成的。如果一个未注册用户使用化名并向系统发送错误信息，BF 可以以高效的空间消耗验证用户的化名。因此，如果一个未在 `KMC` 注册的用户试图向网络发送虚假信息，此尝试将会失败，因为 BF 中的映射值将包含至少一个零。为了避免误正，作者建议 BF 的数组大小应足够大，以便降低哈希冲突的概率。[Fig. 14.2](#18chap_14.xhtml#fig14_2) 显示了使用布隆过滤器的身份管理系统。

### [14.2.5 区块链与比特币在可穿戴感知设备中的集成](#contents.xhtml#rsec14_2_5)

健康保险公司正在制定策略，以配合其政策与可穿戴设备协作。尽管可穿戴 IoT 设备会生成关于患者日常生活的大量私人信息，且这些信息绝不应被篡改 \[[209](#bib.xhtml#ch00-bib-209)\]。为了解决安全数据记录的问题，\[[172](#bib.xhtml#ch00-bib-172)\] 的作者提出了一种轻量级解决方案。在此，处于同一广播域中的所有智能设备通过记录所有数据对话以链式结构，作为相邻设备的见证人。然而，使用一个网关来记录其与传感器设备进行的所有详细信息。基本上，传感器设备记录它们在网络中听到的所有对话并维护记录，然后将其转发到网关。值得注意的是，这种方法会导致网络中存在大量流量，使用大量内存，并给见证人带来高通信开销。作为解决方案，这些设备不再记录整个对话，而是使用 BF 按时间顺序存储对话的指纹。因此，使用 BF 降低了空间复杂度。过一段时间后，见证人将其签名的 BF 上传到网关。数字签名确保了系统的完整性和不可否认性。此外，为了降低误正概率，作者建议使用不同的哈希函数。

### [14.2.6 Graphene：块传播协议](#contents.xhtml#rsec14_2_6)

在分布式系统中，为了在副本之间进行高效同步，始终需要尽量减少网络带宽。显然，高效设计的用于同步新挖出的块和新创建的交易的网络协议可以带来许多好处。例如，如果块在传输时消耗较少的网络数据，那么最大块大小可以相应增加。此外，每秒处理的交易总数也会增加。许多研究人员正在尝试发明使用较少带宽传输块的技术。使用的带宽越少，块或消息在网络中传播得就越快。使用较少带宽传输的块不仅增加了对等节点之间的同步，还减少了链中的分叉。区块链中的 Graphene 协议被认为是一种尽可能使用最少带宽传输块的协议。

此外，比特币矿工旨在快速广播新发现的块，因为即使是毫秒级的延迟也会增加其他块被添加到 BC 的概率。这促使矿工减少要添加到块中的交易数量。比特币网络中的矿工为所有未确认交易维护一个内存池。矿工从内存池中选择一些交易并构建一个新的候选块。如果所有矿工的挖矿池理想同步，并且他们使用相同的协议来选择要添加到其候选块中的交易，那么这消除了在块中包含交易的需求，并使每个矿工能够从内存池中重建块。在实际场景中，矿工的内存池并未完全同步，因此会导致块传播效率低下。为了解决这个问题，\[[159](#bib.xhtml#ch00-bib-159)\] 的作者提出了一种名为 Graphene 的协议，用于为基于 BC 的网络设计新块。它将 BF 与反向布隆查找表（`IBLT`）相结合，以解决 P2P 网络中的集合协调问题。`IBLT` \[[25](#bib.xhtml#ch00-bib-25)\] 解决了计算两个数据集差异的问题，这有助于确定哪些数据集具有共同点。为了同步块，发送方首先从块中的交易 ID 构建一个 `IBLT`。此外，它使用相同的交易 ID 构建一个 BF。接收方利用 BF 从内存池中筛选交易 ID 并构建其自己的 `IBLT`。最后，接收方解码两个块之间的差异。这样，网络带宽可以显著降低。仿真结果表明，使用 Graphene，网络流量会大幅减少。
