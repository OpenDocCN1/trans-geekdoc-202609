

Deletable BF (DBF) [[165](#bib.xhtml#ch00-bib-165)] 是为了解决计数 BF 中删除元素时出现的假阴性问题而引入的。然而，与计数 BF 使用计数器数组不同，DBF 使用一个 `m` 位的位数组。DBF 背后的关键洞察是，它试图定位插入元素时可能发生冲突的位区域，且删除只能在无冲突区域进行。这里，一个 `m` 位的位数组被分为 `r` 个区域，每个区域应包含 $\frac{m'}{r}$ 个位，其中 `m'` = `m` − `r`。在 `m` 位数组的开头，保留了一个大小为 `r` 的冲突位图来编码，这些 `r` 位初始化为 0。冲突位图中的 1 标记为易碰撞区域，而 0 表示无冲突区域。设计 BF 时的一个关键问题是选择 `r` 的值，因为这个值决定了 BF 删除元素的能力和 FPR。DBF 的假阳性概率计算如下：

$$
\begin{array}{l} {P = \left\lbrack {1 - \left( {1 - \frac{1}{m - r}} \right)^{k*n}} \right\rbrack^{k}} \\\\ \end{array}
$$

(10.14)

其中，`n` 是要插入的元素总数。DBF 支持的操作描述如下：

*   插入：要插入一个元素，将与 `k` 个哈希函数对应的 `k` 个位置设置为 1。如果 `k` 个位置中的任何一个已经是 1，则表示发生了冲突，作为对此冲突的响应，冲突位图中与冲突发生区域对应的位被设置为 1。[Fig. 10.15](#13chap_10.xhtml#fig10_15) 表示 DBF 中的插入操作。这里，元素 15、9、8、4 使用 3 个哈希函数依次插入，如下：`h[1] = x mod 11`，`h[2] = (2*x + 3) mod 11`，`h3 = (2 * x) mod 11`。对于元素 9，未检测到冲突，而对于元素 8，在第 3 个区域的第 8 个位置检测到冲突。因此，冲突位图中对应的位被设置为 1。同样，对于元素 4，冲突发生在区域 1、2 和 3，因此冲突位图中这些相同的位置被设置为 1。

    ![FIGURE 10.15. Insertion operation in deletable BF.](images/fig10_15.jpg)

    **FIGURE 10.15.**  

    Insertion operation in deletable BF.

*   查询：要查询一个元素，将该元素传递给 `k` 个哈希函数，如果 `k` 个位置中的任何一个为 0，则该元素不在集合中，否则它可能存在。

*   删除：要删除，在 `k` 个计算出的哈希位置中，仅重置位于无冲突区域的那些位。如果与哈希函数对应的所有 `k` 位都位于易碰撞区域，则该元素不可删除。因此，只有当 `k` 位中至少有一位可以重置为 0 时，才能删除元素。这样可以避免假阴性，但假阳性仍然可能发生。[Fig. 10.16](#13chap_10.xhtml#fig10_16) 表示 DBF 的删除操作。如图所示，元素 15 无法删除，因为相应的哈希位置，即 4、0、8 都位于易碰撞区域，而元素 9 被成功删除，因为在相应的哈希位置中，第 9 个和第 10 个位置位于无冲突区域。

### [10.2.3.5 Stable BF](#contents.xhtml#rsec10_2_3_5)

不幸的是，BF 中零的数量会随时间减少，并且会达到一个点，此时所有查询都被回答为可能在集合中。引入 SBF 的原因是为了消除流数据中的重复项，并在错误达到预定义阈值之前驱逐过时数据。Stable BF 为更近期的项目创建空间，因为这些数据比过时数据更重要。类似于计数 BF，这里使用一个 `d` 位计数器数组，所有计数器初始化为 0。因此，最大计数器值可以达到 2^(`d`) − 1。为了处理过时数据，Stable BF 驱逐过时数据以给新数据腾出空间。查询处理、URL 爬取、监控不同 IP 地址、图处理是 Stable BF 的一些应用。

*   插入：要插入一个项目，将其传递给 `k` 个哈希函数。在零的数量变为常数的某个点之后，更新 Stable BF。要更新，随机将 `p` 个计数器值减 1。此步骤后，所有 `k` 个计算出的哈希位置都设置为最大值。

*   检查重复性：要检查重复值，查询并检查 `k` 个哈希单元是否被哈希为 0 或 1。对于任何单元返回 0 的情况，集合中没有重复项目，否则存在重复。但是，随机将位设置为 0 可能导致假阴性。这里，假阴性被定义为查询重复项目时被回答为不同项目的情况。此外，假阴性取决于输入数据分布。对于没有前驱的元素，假阴性的概率为零。

此外，Stable BF 在引入由于随机驱逐过时信息而导致的假阴性的同时，保证了 FPR 的紧上界。设置 `p=0` 和 `d=1`，Stable BF 表现为 SBF。[Fig. 10.17](#13chap_10.xhtml#fig10_17) 表示 `p=2` 和 `d=3` 的情况。

### [10.2.3.6 Retouched Bloom Filter (RBF)](#contents.xhtml#rsec10_2_3_6)

减少假阳性的一种方法是增加位向量的大小。然而，这种方法可能导致内存使用量增加。Donnet *et al.* [[73](#bib.xhtml#ch00-bib-73)] 引入了另一种 BF 变体来降低过滤器中的 FPR，并将其命名为 RBF。该过滤器还增强了系统的灵活性。这里，试图从过滤器中移除那些比其他更麻烦的假阳性。然而，这种方法引入了随机假阴性。假阴性通过更容易处理更令人担忧的假阳性这一优势来补偿。这里，假阳性是在 BF 构建完成但尚未使用后试图识别的。Retouched BF 随机移除一些假阳性，以引入一些假阴性为代价。值得注意的是，标准 BF 中不会发生假阴性。

RBF 通过将位向量中某些选定的位重置为 0 来降低 FPR。RBF 的此过程称为位清除过程。显然，对于一个元素，如果与 `k` 个哈希函数对应的任何位置在位清除过程中被重置为 0，将导致假阴性。位清除过程可以是随机的或选择性的。RBF 的结果基于度量 `χ` 得出。如果该度量的值大于 1，则表示移除的假阳性比例高于生成的假阴性比例，而小于 1 的值表示移除的假阳性比例低于生成的假阴性比例。

*   随机位清除 RBF：在随机位清除过程中，随机将某些位重置为 0，无论这些位是否应被重置为 0。对于随机位清除过程，观察到 `χ` 的值计算为 1，这意味着系统的总体错误率保持不变。

*   选择性位清除 RBF：与随机位清除不同，仅将那些导致假阳性的位重置为零。选择性清除过程有 4 个算法来进行，讨论如下：

    *   随机选择：第一个是随机选择，不需要为选择性清除过程提供任何智能。这里，与随机位清除过程不同，不是在位向量中重置随机位，而是可以重置 `k` 个可用位中的一个。这里，仅重置一个与麻烦键的假阳性相关的位。
