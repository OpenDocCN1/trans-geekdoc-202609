

### 匿名性问题

匿名性意味着发送者不可识别。如今，在保持用户匿名性的同时进行用户身份验证是用户的另一项要求 \[[39](#bib.xhtml#ch00-bib-39)\]。从设计上讲，区块链支持匿名性，因为钱包地址与个人身份之间没有直接关联。区块链不是使用真实身份，而是采用假名，且大多数情况下公钥作为区块链网络的假名。不幸的是，这种不可追踪的特性激励人们进行非法网络购买。然而，使用公共地址在一定程度上保护匿名性。一旦一个人与另一个人进行交易，就会泄露其公共地址。由于区块链拥有每个钱包的完整历史记录，拥有公共地址即可查询所有先前活动、钱包余额等。此外，任何一方都可以拦截交易以找出源 IP 地址。显然，这个公共账本通过简单分析交易，就能轻易将钱包地址与可识别的姓名关联起来。解决此问题的一种方法是使用虚拟专用网络（VPN）技术，该技术使用他人的互联网连接。另外，为每笔交易使用新的比特币地址也能起到一定帮助。例如，门罗币（Monero）是另一种加密货币，它为每笔新交易使用不同的秘密地址。另一种流行的预防技术是洋葱路由，它会模糊节点上线时的 IP 地址。在此背景下，Tor \[[15](#bib.xhtml#ch00-bib-15)\] 是实现洋葱路由的开源平台。该软件也有助于隐藏节点的 IP 地址。

### [6.5.1 IPFS：去中心化数据存储问题的解决方案](#contents.xhtml#rsec6_5_1)

如上所述，在区块链上存储大文件具有挑战性。在存储容量方面，值得一提的是星际文件系统（IPFS）\[[16](#bib.xhtml#ch00-bib-16)\]。IPFS 网络适合共享需要大带宽上传/下载的大文件。IPFS 是一种去中心化的 P2P 分布式文件系统，用于存储共享文件。IPFS 是一种高效的存储方式，因为它消除了数据重复。在 P2P 连接的 IPFS 中，如果一个节点崩溃，其余节点可以提供所需的文件。这个分布式文件系统将所有计算设备连接在同一文件系统下。IPFS 基本上是用于访问互联网内容的超文本传输协议（HTTP）的替代方案。在 IPFS 中，网络上的文件托管在去中心化服务器上，这意味着内容不是存储在单个系统上，而是托管在散布在互联网各处的多个节点上。IPFS 节省了大约 60% 的网络带宽。与从单台机器下载单个文件的 HTTP 不同，IPFS 同时从多个去中心化机器下载文件的多个片段。

与按名称引用 IPFS 上存储的文件不同，该系统按文件的加密哈希值引用文件。文件的加密哈希值也作为地址使用。这个哈希值代表一个根对象以及路径中可找到的所有其他对象。特别是，内容寻址概念在 HTTP 层中使用，这意味着不是按位置引用文件（基于位置的引用模型支持中心化），而是按内容本身的任何表示来寻址。要存储文件，IPFS 依赖于分布式哈希表（DHT）。DHT 是类似字典的接口，用于访问分布在网络各节点上的数据。网络上的节点使用一种称为 bitswamp 的机制在节点之间交换数据。

当新文件添加到 IPFS 网络时，IPFS 使用其内容和节点 ID 生成文件的多哈希地址。要访问特定文件，IPFS 会查询网络中具有匹配哈希的文件。计算文件的加密哈希后，询问拥有与该哈希匹配内容的网络对等节点。接下来，内容直接从拥有所需数据的节点下载。因此，IPFS 网络上任何拥有内容哈希的节点都可以通过其内容 ID 查找特定文件，而与该 IP 匹配的节点将提供该文件。

IPFS 模型可以与区块链模型集成，例如比特币和以太坊，因为这两个系统具有相似的结构。与在区块链上存储实际值不同，IPFS 只是在区块链上存储文件的哈希值。此外，使用这些哈希值可以找到文件的实际位置。

[Fig. 6.5](#08chap_06.xhtml#fig6_5) 展示了作者在 \[[152](#bib.xhtml#ch00-bib-152)\] 中讨论的使用 IPFS 的数据共享模式。首先，文件所有者将文件及其元数据上传到 IPFS。其次，IPFS 生成文件的哈希值并返回给所有者。第三步，所有者在智能合约中查找提供加密/解密服务的节点。接下来，所有者将 IPFS 哈希分为 `k` 个片段，对其进行加密，最后将其存储在区块链网络上。
