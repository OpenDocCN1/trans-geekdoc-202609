

# Cuckoo Filter

Cuckoo filter 由其指纹（fingerprint）和桶大小（bucket size）决定。例如，`(3,5)` 过滤器表示 3 位长度的过滤器，每个桶可存储 5 个指纹。结论是，如果目标假阳性率（FPR）小于 3%，Cuckoo filter 占用的空间比标准 BF 更少。即使过滤器 95% 的空间被占用，Cuckoo filter 的成员查询性能也优于标准 BF。然而，仅存储指纹而不是实际项目，阻止了使用标准 Cuckoo 哈希进行插入。在这里，现有的指纹必须被重新定位到备用位置，而不是实际项目。Cuckoo filter 的操作描述如下：

## 插入

这里的问题是如何恢复和重新哈希原始项目以定位到备用位置？为了解决这个问题，Cuckoo filter 采用了“部分键 Cuckoo 哈希”来从指纹中查找项目的备用位置。这里，对于项目 `x`，两个哈希桶的索引计算如下：`h[1](x) = hash(x)` 和 `h[2] = h[1](x) + hash(f(x))`。通过使用 XOR 操作，确保可以使用 `h[2](x)` 和 `x` 的指纹来计算 `h[1](x)`。因此，要重新定位由 `h[1](x)` 或 `h[2](x)` 计算出的任一位置的键，备用位置由 `j = i ⊕ hash(f[i])` 计算，其中 `i` 是项目最初存储的桶索引位置，`j` 是备用桶的索引。通过此过程，不需要项目 `x` 的原始值。考虑一个每 10 个桶有两个条目的 Cuckoo filter，如 [图 10.20](#13chap_10.xhtml#fig10_20) 所示。要计算项目 `x` 的索引位置，请使用 `h[1] = hash(x)` 和 `h[2] = i[1] ⊕ hash(f)`。假设 `i[1]` 和 `i[2]` 是从这些哈希函数计算出的索引。此示例使用移位折叠法计算项目 `x` 的指纹（`f`），`x` 的哈希由 `xmod10` 计算。为了处理冲突，随机选择 `i[1]` 或 `i[2]`（假设为 `i`），并使用公式 `j = i ⊕ hash(f(x))` 将桶 `i` 中的指纹移位到备用桶 `j`。插入时可能存在以下情况：

### Case1: Insert(131)

*   (a)使用移位折叠法计算指纹 `f`，`f`= 13+1 = 14。
*   (b)`i[1](x) = hash(x) = hash(131) = 131mod10 =1`
*   (c)`i[2](x) = 1 ⊕ (hash(14)) = 1 ⊕ (14mod10) = 1 ⊕ 4 = 5`
*   (d)由于索引 1 可用，在同一位置插入 `f`。

### Case 2: Insert(1111)

*   (a)`f(1111) = 11 + 11 = 22`
*   (b)`i[1](1111) = 1111mod10 = 1`
*   (c)`i[2](3333) = 1 ⊕ (22mod10) = 1 ⊕ 2 = 3`
*   (d)由于索引 1 和 5 都已占用，这表示冲突情况。
*   (e)随机选择 `i[1]` 或 `i[2]`，并将所选位置的指纹移位到其他桶。假设选择 `i[1]`，则 `j = i[1] ⊕ hash(f[i[2]]) = 1 ⊕ (hash(f[1])) = 1 ⊕ (hash(14)) = 1 ⊕ 4 = 5`。

## 查询

对于项目 `x`，首先计算 `x` 的指纹和桶的两个索引。接下来，读取这两个位置的内容。如果匹配，则过滤器返回 true，否则返回 false。这样可以避免假阴性，因为没有溢出。如果两个元素具有相同的指纹且哈希索引也相同，则可能发生假阳性。显然，此过程的时间复杂度为 `O(1)`。但是，当过滤器填满时，FPR 会变得很高。

## 删除

要删除一个项目，首先遵循要删除元素的相同查询过程。如果没有匹配，则无法删除，否则如果有匹配，只需从桶中删除该指纹的副本。为了避免“误删除”，元素的条目不会被清除。有了这一洞察，删除后过滤器的假阳性特性保持不变。此过程的时间复杂度为 `O(1)`。

然而，与 Cuckoo 哈希不同，过滤器中仅存储指纹，而不是原始值。每个元素存储在 `f` 位指纹中。Cuckoo filter 占用的空间由 Eq. 10.15 给出，其中 `ϵ` 指定 FPR，`α` 是过滤器的最大容量，`B` 是每个桶的条目数。

## [10.2.3.9 Hierarchical BF](#contents.xhtml#rsec10_2_3_9)

在网络术语中，归因被定义为查找某些流量的源和目的地的过程。但是，有时由于缺乏日志机制，此过程很困难，例如，攻击者可能使用僵尸机器伪造地址。Hierarchical BF 有助于负载归因过程，给定负载时，目标是识别给定负载的发送者或接收者。这可能有助于检测某些安全攻击，例如 DDoS、伪造。Shanmugasundarm 等人 \[[168](#bib.xhtml#ch00-bib-168)\] 基本上扩展了 BF 以支持子字符串匹配。作为优势，此算法甚至不需要完整的数据包进行归因，只需一部分即可。除此之外，该算法需要低存储要求，并且通过简单存储负载的哈希而不是实际负载来确保数据隐私。

这里，长度为 `p` 的每个数据包的负载首先被分为 `q` 个大小为 `s` 的多个块。每个块附加其偏移值。接下来，将每个块及其偏移值哈希并插入标准 BF。这种数据结构称为基于块的 BF 带偏移，如 [图 10.21](#13chap_10.xhtml#fig10_21) 所示。

## [10.2.3.10 Stochastic Fair Blue](#contents.xhtml#rsec10_2_3_10)

虽然作者不将此数据结构定义为 BF 的变体，但它与 BF 的工作有很多相似之处。Stochastic Fair Blue (SFB) \[[81](#bib.xhtml#ch00-bib-81)\] 是一种使用计数 BF 与蓝色算法的技术。作者提出此方案以解决 TCP 的拥塞控制问题。它检测重击者以增强组播数据包的转发速度。SFB 使用 `N*k` 个桶，其中 `k` 是级别数，每个级别有 `N` 个桶，以及 `k` 个哈希函数。此外，每个桶关联一个丢弃/标记概率 `p[m]`。对于每个传入数据包，对其连接 ID（源-目的地址对、源-目的端口对和协议）应用 `k` 个哈希函数，并递增相应的桶位置。如果哈希到某个桶的数据包数量超过桶的最大大小，则为该桶的 `p[m]` 增加值 `δ[1]`；否则，如果链路空闲，则减少值 `δ[2]`。如果 `p[m]` 的值达到 1，则将数据包放入重击者列表。为了降低 FPR，作者使用了保守更新的思想。对于一个数据包，提取相应 `k` 个哈希位置中的 `p[min]`。现在，如果 `p[min] = 1`，则将数据包标记为重击者并将其丢弃。因此，使用 BF 可以用更少的空间和每个数据包更少的操作轻松检测重击者。

[图 10.22](#13chap_10.xhtml#fig10_22) 表示 Stochastic Fair Blue 的示例。如图所示，数据包 `p[x]` 提高了其映射到的所有桶的 `p[m]`。但是，数据包 `p[y]` 可能在某个级别中映射到与重击者流相同的桶，但在其他级别中，它映射到正常桶。由于数据包 `p[y]` 的 `p[min]` 为 0.2<1，它被识别为正常流，而 `p[x]` 被标记为重击者。
