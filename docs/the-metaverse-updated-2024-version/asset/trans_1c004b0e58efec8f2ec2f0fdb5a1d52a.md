

各个平台及元宇宙内的体验可能类似于标准化的“枢纽世界”，例如特斯拉的旧金山模拟、苹果的 AR 映射解决方案，或未来版本的 `Grand Theft Auto`。但整体元宇宙很可能缺乏这种统一的表现形式、目录或入口——就像互联网一样。例如，万维网被详尽地组织和索引，网站声称拥有“命名空间”，这些命名空间通过分配的服务器地址访问，而服务器地址又位于分配的网络地址上，然而网络除了空白浏览器之外没有“起点”，用户不需要一个网站来冲浪到另一个，页面之间也没有必经之路。如果用户想直接访问某个页面，他们只需输入地址或点击超链接即可直接到达。智能手机为用户的应用程序提供了统一的视图和所有应用程序的目录，但它们之间很少有体验上的关联，只有极少的标准化。而且，虽然 `Roblox` 和 `Fortnite` 都允许用户通过传送门和门在不同世界之间跳转，但大多数用户通过 2D 界面访问各种世界，这些界面更像流媒体视频服务，而非街道。

不仅基于行星的组织模型对元宇宙来说令人沮丧，而且可能也是不可能的。许多模拟，例如特斯拉、苹果以及城市自身的数字孪生，将覆盖同一用户和现实世界位置，并且经常互连，但除此之外将并行运行。幸运的是，这种模型也有许多技术优势。通过在平台之间分割用户或数据，而不是构建一个拥有数十亿并发用户和千万亿个对象的虚拟星球，本章讨论的许多技术挑战，例如渲染、同步和持久性，都大大简化了。

## 具有数据连续性的元宇宙，例如身份、历史、权利、对象、通信和支付

虽然建立互操作网络要求参与者交换一些数据（例如，标识符、地址、位置等），但它并不指定随后交换什么数据，更不用说支持其庞大网络上的数据了。一般来说，全规格元宇宙的愿景涉及互操作的身份、历史（或记录）、权利（即用户拥有或有权访问的事物）、对象（例如，虚拟商品、虚拟形象或资产模型）、通信（就像电子邮件在所有网络、域、设备等之间工作一样）和支付系统（用于虚拟“贸易”所必需）。如果没有这样一套系统，有人认为将不存在“元宇宙”，只有一个拥有越来越多 3D 应用程序的互联网。一个更具 3D 能力的互联网有价值，但它不太可能产生真正的“平行存在平面”或产生可能与“物理世界”相媲美的经济（同时也支撑着物理世界的大部分）。

互操作性对于用户权利以及元宇宙整体的健康也至关重要。如果用户的虚拟权利或创作被锁定在特定平台，那么随着时间推移和用户投资增加，该平台对用户的事实上的控制力将增强。出于类似的原因，任何其他平台（无论是新兴还是新出现的）都将越来越难以与该平台竞争。互操作性也是确保元宇宙中的投资（时间、金钱、精力、记忆）在其中某个虚拟世界或服务器关闭时仍能持续所必需的。在“现实世界”中，消费者不需要面对这类问题。许多底层互操作服务和注册表由政府拥有且不可排他（例如，护照、国家身份证号码、货币），个人实物拥有商品（不像大多数数字商品），如果制造商倒闭，这些商品不会消失，互操作性基于物理（一件 J.Crew 腰带可以与 Gap 裤子搭配，无论两家公司之间是否有协调或一方的许可），大多数交易不需要中介（例如，美元兑欧元，一顶帽子换一件 T 恤），等等。

建立这些标准面临许多障碍。一个是当前的碎片化状态。当今几乎所有最受欢迎的虚拟世界都使用各自不同的渲染引擎（许多发行商在其作品中运行多个引擎），拥有个性化的脚本语言、工具、框架和相关服务。这些引擎之间差异的实际后果对非开发者来说可能难以理解，但这些差异的深度体现在两个最流行的引擎在坐标轴上“意见不合”。在 Unity 中，基于 X/Y/Z 的 3D 模型中的 `y` 轴指向上下，而 Unreal 使用 `z` 轴指向上下，并将 `y` 轴映射为左右。中间件很容易转换此类做法，但技术差异延伸到代码结构、输入处理、粒子模拟等方面，而不仅仅是信息的顺序。

除了这些世界的底层逻辑和规则之外，还有运行在其中的信息的结构方式。对于 3D 对象，不存在“JPEG”、“MP4”、“.XLS”或“PDF”，更不用说环境或玩家数据了。因此，各方将其对象、纹理和玩家数据保存到完全不同的文件格式中，并且只包含他们预期需要的信息。解决这个问题不仅需要一种格式，还需要围绕它的理念。以“互操作虚拟形象”的概念为例。开发者相对容易就图像的定义及其呈现方式达成一致，作为由单独着色像素组成的静态 2D 内容单元，将一种图像文件类型（例如 PNG）转换为另一种（JPEG）的过程很简单。然而，3D 虚拟形象是一个更复杂的问题。虚拟形象是一个穿着服装的完整 3D 人物，还是由身体虚拟形象加上服装组成？如果是后者，他们穿着多少件衣服，什么定义了衬衫和夹克（夹克穿在衬衫外面）？虚拟形象的哪些部分可以重新着色？哪些部分需要一起重新着色（袖子是否与衬衫分开）？虚拟形象的头部是一个完整的对象，还是由数十个子元素组成的描述，例如单独的眼睛（带有自己的视网膜）、睫毛、鼻子、雀斑等等？此外，用户期望拟人化水母虚拟形象和盒状安卓虚拟形象以不同的方式移动。对象也是如此。如果纹身放置在虚拟形象的脖子上，无论他们如何移动，它都应该固定在皮肤上——但系在脖子上的领带应该随虚拟形象移动（并受其影响）。它的移动方式应该与海螺项链不同，而海螺项链的移动方式又应该与羽毛项链不同。仅仅共享虚拟形象的尺寸和视觉细节是不够的。开发者需要理解并同意它们的工作原理，然后构建代码来支持它。
