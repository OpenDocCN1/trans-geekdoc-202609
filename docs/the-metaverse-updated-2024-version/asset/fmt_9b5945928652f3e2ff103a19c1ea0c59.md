
# 实时 3D 模拟与元宇宙标准化

实时 3D 模拟的优势很难用文字描述，原因正是 SDP 最初认为构建物理模型和数字孪生具有价值的原因。然而，SDP 的投资使坦帕市、Water Street 开发项目的潜在租户、项目投资者以及施工合作伙伴能够更好地理解和规划该项目。可以清晰地看到，当今的坦帕不仅会受到施工过程的影响，还会受到完工项目的影响。为期五年的建设将如何影响当地交通？其影响与为期六年的建设有何不同？如果某栋建筑被公园取代会发生什么？或者如果其楼层高度从 15 英尺减少到 11 英尺呢？该开发项目将如何影响该地区其他建筑和公园的视野，包括折射光或辐射热的影响——以及一年中的任何时间或任何一天？这些建筑将如何影响该地区的紧急响应时间？是否需要新建警察局、消防局或救护车站？建筑的哪一侧应建造消防逃生通道？所有这些答案都可以无限次地模拟、测试和调整。

SDP 的 Water Street 开发项目旨在辅助设计过程，同时争取更多市政和商业支持。但这仅仅是个开始。此类模拟的长期目标是实时运营由此产生的建筑，包括其中的众多企业及其与城市的关系。这些模拟可以支持各种用例，从帮助管理零售商场购物者流量这样微小的事情，到协助疏散程序，以及帮助当地市政当局运营更全面、更智能的交通灯网络。要实现这一点，每个协作者必须拥有共同的代码类型、结构和交换机制，如本书所述。他们还必须拥有相似的模型。如果每个参与者都从头开始构建此类模型，即使在财务上可能的情况下，也毫无意义。更重要的是，这些重复且孤立的努力无疑会产生错误并导致可避免的功能重叠不足。虽然特斯拉可能能够生成旧金山的大部分区域，包括其实时和历史交通，但它需要第三方来源提供天气数据，且其预测旅行中断的能力受限于其网络了解城市在几分钟、几小时甚至几周内发生情况所需的时间。如果特斯拉需要外部数据支持，那么每个希望构建 AR 和基于位置体验的开发者也是如此。

这一需求已经催生了技术解决方案。2023 年 8 月，Amazon、Facebook、Microsoft 和导航公司 TomTom 与 Linux Foundation 的 Joint Development Foundation 合作，宣布成立 Overture Maps Foundation。Overture 的目的是开发世界上最大的开放式映射套件和数据库，所有内容都将符合通用数据结构和惯例，旨在促进互操作性而非封闭生态系统。Overture 的成立不仅是由 2D 和 3D 地理空间数据日益重要的需求以及开发者需要融合其地理空间服务所驱动，也是对 Google 和 Apple 等市场领导者所提供服务局限性的回应。Google Maps API 是全球最广泛使用的 API 之一，不允许开发者为每个用户查询提供超过 20 个搜索结果，也不允许存储或缓存任何信息，这实际上阻止开发者进行丰富的用户分析并降低了用户体验。开发者还必须为每千次 Google Maps API 使用付费给 Google。Apple Maps 表面上对 iOS 应用开发者免费，但要求这些开发者通过 Apple 的 App Store 分发，App Store 对所有符合条件的交易收取 15%–30% 的费用，并中介开发者与用户之间的计费关系，限制开发者的许多其他商业和技术决策，包括他们收集哪些数据。如果开发者选择基于浏览器的体验，或者将其与原生应用一起提供，则每次调用其地图 API 时都必须向 Apple 付费。如果开发者想要为 Apple 以外的平台（如 Android）构建原生应用，他们实际上被迫使用另一种映射解决方案。因此，开发者的选择实际上是在所有平台上使用 Google Maps，或者构建一个同时使用两种解决方案的技术栈，这会导致更大的技术复杂性、体验差异性和成本。

Overture 需要时间才能提供与 Google 和 Apple 的映射套件相当的细节，该基金会的工具也不太可能像商业化产品那样易于使用，但它在法律使用上完全免费且无限制，并可以集成到世界上的每个计算平台。为了启动 Overture，Facebook 和 Microsoft 贡献了近 6000 万个地理空间“兴趣点”——建筑物、纪念碑、湖泊、企业——以及未指定数量的交通路线和边界。2024 年 2 月，Niantic 作为贡献成员加入 Overture Maps Foundation，并承诺向该组织贡献地理位置数据。

无论标准化管道、资产和引擎的力量如何，元宇宙中始终会存在碎片化，因为始终会存在需要丰富定制的专业模拟、新软件和不可预见的用例。Nvidia 的 Omniverse 于 2020 年推出，是解决此问题的几个“互换”平台之一。一家汽车公司可能能够将其基于 Unreal 的汽车带到在 Unity 中设计的环境中，并让这些汽车与在 Blender 中制作的对象交互，同时根据 Nvidia 的 Earth 2.0 模拟的天气条件测试结果。Omniverse 不支持所有引擎、文件格式、元数据结构和功能，但其简短列表仍然推动了标准化进程，同时也使元宇宙更有可能实现，具体原因在于它允许公司在不重构其整个 3D 业务的情况下参与。

值得注意的是，Omniverse 是围绕 Universal Scene Description (USD) 构建的，这是一种由 Pixar 于 2012 年开发的文件格式，用于详细描述 3D 世界的几何、材质、物理和行为。2016 年，Pixar 开源了该格式，在随后的几年中，USD 在建筑、机器人和机械工程等行业得到广泛采用，Apple 的 ARKit 也选择衍生的 USDZ 格式作为用户扫描现实世界对象的标准。Omniverse 发布后，Jensen Huang 将 USD 宣称为“元宇宙的 HTML”——一种将作为虚拟世界内容声明性规范的格式。2023 年，Pixar 与 Adobe、Apple、Autodesk、Nvidia 和 Linux Foundation 的 Joint Development Foundation 一起成立了 Alliance for OpenUSD (AOUSD)，这是一个非营利标准组织，将指导新指定的“OpenUSD”格式并促进其周围生态系统的发展。Cesium、Epic Games、IKEA、SideFX 和 Unity 在 AOUSD 发布时加入成为普通成员。
