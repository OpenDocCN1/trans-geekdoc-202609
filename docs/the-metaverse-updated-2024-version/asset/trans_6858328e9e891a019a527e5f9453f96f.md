

在最初的几十年里，大多数开发者为其虚拟世界创建定制引擎。但正如[第 3 章](#chapter3.xhtml)所总结的，20 世纪 90 年代出现了一种替代模式，开发者可以授权引擎，例如 Epic Games 的 `Unreal Engine`（1996 年）以及后来的 Unity Technologies 的 `Unity`（2005 年）。

使用这些引擎是有成本的。`Unity` 向每个使用它的开发者收取年度费用，范围在 400 美元到 4,000 美元之间，具体取决于所需功能和开发者公司的规模。`Unreal` 通常收取净收入的 5%。

费用并非构建自有引擎的唯一原因。一些开发者认为，针对特定游戏类型或体验（例如逼真且节奏快速的第一人称射击游戏）这样做，可以确保他们的游戏“感觉更好”或性能更好。另一些人担心需要依赖另一家公司的管道和优先级，或者担心供应商对其游戏及其性能有如此详细的了解。鉴于这些顾虑，大型发行商构建和维护自己的引擎是很常见的（例如，Activision 和 Square Enix 甚至运营半打或更多）。

大多数开发者认为授权并定制 `Unreal` 或 `Unity` 有显著的净收益。授权使小型或经验不足的团队能够构建一个比他们可能自己构建的更强大、经过更广泛测试的引擎上的游戏——而且不太可能出故障，也永远不会超支。^([†](#chapter7.xhtml#footnote-025)) 开发者还可以将更多时间放在使其虚拟世界与众不同的方面——关卡设计、角色设计、游戏玩法等——而不是使其运行所需的基础技术。与其雇佣开发者然后培训他们使用或构建专有引擎，不如游戏制作商吸引数百万已经熟悉 `Unity` 或 `Unreal` 的开发者，并立即让他们投入工作。出于类似原因，集成第三方工具也更容易。例如，一家制作面部跟踪软件用于视频游戏头像的独立初创公司，不会设计其解决方案以适用于从未使用过的专有引擎，而是设计为适用于大多数开发者选择的引擎。

一个很好的类比是设计和建造房屋。无论是建筑师还是装饰师，都不会设计专有的木材尺寸、组装硬件、测量系统、蓝图框架或工具。这不仅使专注于创意工作更容易，而且使雇佣木匠、电工和水管工更容易。如果房屋需要翻新，另一支团队可以更容易地修改现有结构，因为他们不需要学习新技术、工具或系统。

这个类比有一个关键的缺陷。房屋是一次性且在一个地点建造的。相反，游戏旨在尽可能多地运行在尽可能多的设备和操作系统上——其中一些尚未发布甚至尚未开发。因此，游戏必须兼容，例如，不同的电压标准（例如，英国的 240 伏特和美国的 120 伏特）、测量系统（英制和公制）、惯例（架空电话线和地下电话线）等等。`Unity` 和 `Unreal` 构建和维护其游戏引擎，使其不仅与每个主要平台兼容，而且针对每个平台的优势和不足进行定制，以便开发者可以轻松利用每个平台，而无需构建到计算能力的最低公约。^([‡](#chapter7.xhtml#footnote-024))

从某种意义上说，可以将独立游戏引擎视为行业的共享研发池。是的，Epic 和 Unity 是营利性公司，但与其让每个开发者将部分预算投入到专有系统来管理核心游戏逻辑，不如少数跨平台技术提供商将部分预算集中到一个更强大的引擎上，该引擎支持并惠及整个生态系统。随着主要游戏引擎的发展，另一种独立游戏解决方案出现了：即时服务套件。`PlayFab`（现由 Microsoft 的 `Azure` 拥有）和 `GameSparks`（`Amazon`）等公司运营着虚拟世界“在线运行”以及多人体验所需的大部分内容。这包括用户账户系统、玩家数据存储、游戏内交易处理、版本管理、玩家间通信、匹配、排行榜、游戏分析、反作弊系统等，所有这些都跨平台工作。`Unity` 和 `Epic` 现在也有自己的即时服务产品，价格低廉甚至免费，且不仅限于其引擎。`Steam`，全球最大的 PC 游戏商店，也是[第 10 章](#chapter10.xhtml)讨论的关键点，提供其自己的即时服务产品 `Steamworks`。

随着全球经济继续向虚拟世界和环境转移，这些跨平台和跨开发者技术已变得悄然无处不在且必不可少。下一波虚拟世界构建者——不是游戏制作商，而是零售商、学校、体育队、建筑公司和城市——特别可能使用这些解决方案，而不是构建自己的。这使得拥有这些技术的公司处于有利的战略地位。最明显的是，它们成为虚拟世界的一种标准功能或通用语——可以将它们视为元宇宙的“英语”或“公制”。就像这本书的普通读者在国际旅行时可能使用一些英语和一些公制系统知识一样，如果有人今天在构建虚拟世界，他们很可能正在使用——并支付——一家或多家这些公司的服务。更广泛地说，谁比管理其逻辑的公司更适合在虚拟世界之间建立共同的数据结构和编码惯例？谁比在其中驱动相同内容的公司更适合促进这些虚拟世界之间信息、虚拟商品和货币的交换？谁比 `ICANN` 为网络域和 IP 地址所做的那样，更适合创建这些虚拟世界的互联网络？[第 8 章](#chapter8.xhtml)将回到这些问题，但首先，有必要审视一些人认为构建元宇宙的更简单、更好的途径。

## 集成虚拟世界平台

在过去二十年中，随着独立游戏引擎和即时服务套件的发展，其他公司将这些方法结合成一种新的方式：集成虚拟世界平台（IVWPs），例如 `Roblox`、`Minecraft` 和 `Fortnite Creative`。

IVWPs 基于其自身的通用且跨平台的游戏引擎，类似于 `Unity` 和 `Unreal`（`Epic` 的 `Fortnite Creative`，如同 `Fortnite`，运行在该公司的 `Unreal Engine` 上）。但在这种情况下，它们被进一步“产品化”，以至于不需要实际的“编码”。相反，游戏、体验和虚拟世界是使用图形界面、符号和目标构建的。作为类比，考虑使用基于文本的 `MS-DOS` 和可视化 `iOS` 之间的区别，或者在 `HTML` 中设计网站与在 `Squarespace` 中创建网站之间的区别。简而言之，IVWP 界面使用户能够更轻松地创建，并需要更少的人员、更少的投资、更少的专业知识和技能。正如 `Roblox` 爱好者所知，该游戏的许多创作者是儿童，近一千万人已在 `Roblox` 平台上创建并分发了他们的虚拟世界。
