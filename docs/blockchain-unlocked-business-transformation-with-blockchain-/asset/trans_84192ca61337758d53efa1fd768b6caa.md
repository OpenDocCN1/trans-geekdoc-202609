
# 创建 dApp

第二层级是企业通过在现有区块链上设计和构建自己的 dApp 来访问区块链服务。当没有区块链应用能提供所需服务时，就会出现这种情况。例如，如果你需要一个执行你业务独有流程的应用，你可能必须自己构建。即使存在此类服务，还有其他理由设计和开发自己的 dApp 吗？有的，例如如果你不确定是否要向第三方暴露内部流程或数据。

你可以在许多现有区块链（如 `Ethereum`、`EOS` 和 `Cardano`）上设计、构建和运行应用。但是，你需要具备高水平的技术专长。这不仅仅是插件式使用服务：熟练的开发人员不仅需要设计和构建它，还要确保应用与其运行的区块链良好对接。应用拥有友好的用户界面（`UI`）和用户体验（`UX`）至关重要。换句话说，构建此应用将经历任何典型应用都会经历的流程和步骤。然而，根据我们见证的趋势，不久几乎任何人都能构建区块链应用。一些较新的区块链正推出应用模板或构建模块，这将使即使编码技能很少的人也能构建功能强大且吸引人的 dApp。`EOS` 就是这种区块链之一，你可以在上面组装部件来创建应用，只需极少的编码。`EOS` 核心开发团队的目标是提供类似于使用 `WordPress` 构建网站的体验^([1](#ch08.xhtml#ch08fn1))。

# 构建你自己的区块链

构建区块链是第三个也是最低层级。但这也是企业参与门槛最高的层级。只有当既没有应用能在区块链上给企业提供所需能力，也没有区块链能构建和运行所需应用时，才应在此层级获取区块链收益。随着区块链及其上运行的应用列表不断增长，企业发现它们所需的一切几乎都已构建完成。正如谚语所说，没有必要重复造轮子。开发新区块链的主要动机几乎从来不是某个企业的内部需求，而是主要为了向更广泛的社会提供新技术和做事方式。

看看大多数区块链设计师，如 `Vitalik Buterin`、`Daniel Larimer` 和 `Charles Hoskinson`，他们分别构建 `Ethereum`、`EOS` 和 `Cardano` 并非因为他们需要区块链用于系统或业务。对他们来说，这或多或少是一种哲学动机。更重要的是，他们三人都是在为用户社区构建东西，其中包含无数大、中、小企业。

继续前进。

# 你能设计和构建区块链吗？

假设你有充分的理由构建一个全新的区块链。或者你可能发明了一种实现区块链协议的新方法，修复了其他区块链协议中的弱点。下一个需要思考的问题是，你是否拥有交付它所需的必要资源。在这方面最关键的资源是技术专长。如果你内部已具备该技能，你的任务就完成了一半。如果没有，请注意，获取这些技能是一个巨大的挑战。

你可以选择接受培训以获取技能。幸运的是，现在有几家机构提供区块链开发培训，其中最受欢迎的是 `Blockgeeks`、`Hyperledger` 和 `ConsenSys`。另一个选择是雇佣已经受过培训或具备必要经验的人。这看起来是一条更简单、更快捷的路；然而，鉴于区块链是一项新技术，擅长它的开发人员数量不多，公司和初创企业都在努力吸引合适的人才。由于这种短缺，可能需要相对巨额的预算来支付最优秀的人才。

第三个选择是聘请专业的区块链解决方案开发公司。有几家这样的公司，而且每年都在涌现更多。最好的公司由曾在早期区块链上工作过的人创建。许多首批 `Bitcoin` 和 `Ethereum` 核心开发人员后来都创立了自己的区块链解决方案公司，提供设计和构建应用等服务。`ConsenSys` 就是其中之一，专门设计和构建运行在 `Ethereum` 区块链上的企业级应用。另一家拥有大量区块链开发人才的公司是 `Blockstream`。这家加拿大公司汇聚了一些最受尊敬的区块链专家，包括 `Adam Back`、`Pieter Wuille` 和 `Eric Svenson`^([2](#ch08.xhtml#ch08fn2))。另一家提供区块链开发服务的公司是 `Ciphrex`，由前 `Bitcoin` 核心开发人员 `Eric Lombrozo` 和他的父亲 `Enrique Lombrozo` 共同创立。

# 你能创建并激励一个真正的区块链社区吗？

区块链之所以成为区块链，是因为点对点网络上的独立计算机协同工作、协作，并在共享账本上的交易上形成共识。区块链需要激励一个能够长期自我维护的社区。这也关乎点对点网络上的独立计算机形成虚拟机或某种形式的操作系统，以支持和运行不同类型的应用。

如果你的区块链运行在单台机器或你拥有并管理的私有网络上，它不符合区块链资格。它将被视为或多或少类似于中心化服务器系统。

因此，在设计协议和编写代码后，邀请他人加入你，共同构建一个强大的点对点网络至关重要。这并非易事；你需要给他们其他区块链上找不到的价值，以便他们投入资源使你的区块链运转。这可能是因为你的协议专门针对特定用途或利基市场，或者仅仅是因为采用了更优越的技术。`Satoshi Nakamoto` 在设计和构建 `Bitcoin` 核心软件后，着手通过 `P2P Foundation` 和 `Cypherpunk` 邮件列表等在线论坛建立社区，以保持项目的可行性。这是一个关键步骤。

# 打造一个可行的区块链

区块链需要一个社区才能生存。`Satoshi Nakamoto` 肯定遇到了许多困难，说服人们尝试他的发明。不单因为它完全是新颖且前所未有的。你将面临类似但不完全相同的挑战。人们现在选择过多；撰写本书时，已存在超过 3,000 条区块链。你必须说服他们，为什么你的区块链比其他数千条更适合他们。
