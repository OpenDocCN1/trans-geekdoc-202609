

## 第二，让具备深厚领域知识的人与你找到的机器学习专家共事

将这两者配对将成为你正在做的事情中最关键的枢纽。大多数组织**没有**从一开始就为机器学习而架构设计的数据结构。弄清楚正确的切入点意味着确定要标记什么数据，以及什么与旅程的起点相关。这就是为什么具备全栈机器学习技能的人如此重要的原因之一。

### 这究竟意味着什么？全栈机器学习技能

我可以走进你的组织搭建 `TensorFlow`，甚至让团队今天就开始共享一些 `Jupyter` 笔记本。拥有正确的数据源、正确的机器学习硬件，以及能够访问正确的生产端基础设施，以便在不压垮或破坏系统的情况下迅速移动数据，这些正是全栈技能必不可少的地方。

也许真正敏捷的团队应该是自我组织的，但这在初次尝试时很难实现。寻找共同或共享的目标听起来比实际操作容易得多。让人们围绕这个共同或共享的目标自我组织，可能需要一些基本规则或火花。

有时高绩效团队会直面挑战，努力消除可能面临的任何障碍或阻碍。大多数团队不具备那种程度的奉献精神、坚持或韧性。通常，项目需求或普遍的业务问题会将一群人聚集在一起采取某种行动。管理这类情况总是很有挑战性，通常包括试图将具有不同技能的人聚集在一起。

这涵盖了你将遇到的两类团队：已经组建好的高绩效团队，以及基于特定业务问题聚在一起的团队。除了这两种常见情况外，你可能面临的另一种人才状况很可能是“有解决方案找问题”。现在这种情况比以往任何时候都多见，因为市场上充斥着开源项目，让人们能够直接跳进来使用复杂工具。这种模式的下一步是想用这些新奇的工具做点什么。为此，你可能会发现一个解决方案正等着去解决某个问题。然而，这可能不是正确的解决方案，甚至可能与应采取的行动方案完全背道而驰。

对我来说，让人才协同工作，核心在于业务问题以及团队试图达成的目标。如果最终目标模糊不清，或者被务实地挪用为除解决当前业务问题以外的其他东西，那么很难围绕该目标团结大家。

我们最好直接深入，花一点时间了解必要的工具，以便让机器学习专家能够高效地与团队协作。你现在大概能看出，我倾向于使用像 `TensorFlow` 这样健壮的工具深入探索并开始大规模进行机器学习。你也可以从日志文件入手，使用像 `Splunk` 机器学习工具包这样的现成产品深入挖掘。这是一个让团队开始使用通用平台开展工作的切入点示例。

## 3. 这些工作流是什么，为什么它们很重要？

我们讨论了人才来源以及如何开始思考让团队协同工作。下一个问题应该与机器学习可用的现有工作流有关。我通常将工作流分为四个不同类别：数据流、存储数据、实时交易和正在运行的批量/大批量作业。每一种工作流都需要不同类型的机器学习方法。你可能会觉得这是牵强附会，但并非如此。将机器学习应用于流式数据所需的工作量，比处理静态数据难得多。仅仅因为你能在数据流上启动机器学习，并不意味着模型会准确或高效。

真正可靠、经过训练的生产模型，如果又快又准，就很有价值。说真的，那才是你想要达到的境地，但这不会偶然发生。在流式数据场景中，你必须拥有一种训练和处理模型的方法，以及一种在不中断数据流的情况下加载运行模型的方法。

处理存储数据比较容易，但有时当你不处理数据流时，会忘记速度的重要性。你可以允许机器学习模型花费更多时间。例如，汽车视觉处理所用的模型比处理美国职业棒球大联盟历史统计数据的模型对速度要求高得多。这是团队可以围绕他们想要评估的相对静态数据集成长和发展的地方。

实时交易是该过程中较有趣的部分之一。交易涉及的工作流通常非常清晰。数据流更流动，不如基于交易的视图那样是纯粹的模式。视频流总是比网站上的金融交易变化更大，但两者都有真实的机器学习机会。

我们真正开始进行一些端到端的思考，关于如何在你的组织内大规模将机器学习模型投入运营。你已经开始思考你的团队、团队如何协作，以及一些可作为数据源的工作流来开展工作。我们今天攻坚的下一步将是看看一些你可以用机器学习解决的具体问题。

我们需要的模式无处不在。现在是拥抱这种复杂性的时候了，数字世界的互联本质创造了一种场景，即工作流无处不在。工作流存在于各种业务流程中。有时它们是出于良好意图建立的，有时只是因需求而自然形成。在工作流上强行加装某种机器学习听起来很有趣。这是尝试用先进流程做点事情的一种方式。它可能是一个推荐系统、一个异常检测器，甚至是一个打破模式的对抗性设置。事情在工作流中以可定义和可重复的方式发生。这几乎就是跳进去使用某种机器学习算法的完美配方。是的，这可能读起来像“有解决方案找问题”，这很有可能是事实，也可能是一个等待被发现的机会。

将潜在工作流类型细分为几类，包括内容流、静态内容挖掘、基于交易的工作流和批量/大批量流程。这些类别中的每一个在机器学习实现方面都包含不同的工作流挑战。显然，静态内容挖掘是许多团队的起点。它不是一个移动的目标，而且时间可能站在你这边，让你深入研究弄清楚事情究竟如何运作。你有充足的训练时间，模型可以被应用和调整。或许与之相反的类别是尝试在内容流上应用机器学习。你的模型必须准备就绪，流程必须迅速推进。流中发生的任何事情都必须足够流畅，以允许吞吐量持续流动而不产生积压或延迟。同类论点也适用于基于交易的工作流，但在交易层面上，你会获得更多缓冲空间来允许模型完成工作。
