

# 像强力球或其他一些大型彩票项目这样的彩票通常基于数字

你有一个定义好的数字空间，而你选择的 `x` 个数字需要与彩票开奖结果中随机选出的 `x` 个数字集合相匹配。你可以 100% 尝试随时间寻找规律，并试图找出最有可能被选中的数字。这种努力甚至可能让你感觉好一些，但假设用于选号的机器准确地强制执行了选择的随机性，那么任何数字被选中的可能性都是相同的。这将是一个分数，由正在被选中的一个数字除以正在评估的数字空间中的总球数而得出。基于这一点逻辑，你可能已经意识到不需要机器学习来预测彩票。中彩票的最佳方式是明确购买每一种数字组合的彩票。这种做法将耗资巨大、耗时费力，且在后勤上难以实现。

# Substack 第 19 周：对错过机器学习的恐惧

发布于 2021 年 6 月 4 日

所有这些炒作导致了一定程度的轰动效应。给予足够的轰动效应，你几乎肯定会得到更多的炒作。这种循环在机器学习领域，当然也在人工智能领域 [1] 中起伏不断。我们已经达到了一个临界点，许多机器学习用例可以在几乎没有摩擦的情况下投入生产。许多更复杂的用例面临复杂的实现问题，但绝大多数开始使用机器学习的可能方式现在都很容易获得。你甚至不必构建基础设施或花费大量时间在你的数据上训练模型。GCP、Azure 和 AWS 都提供了轻松访问稳定且可扩展 API 的途径，以满足你的机器学习用例需求。

本简讯第一段提到的所有轰动效应和炒作，在许多组织的高层管理人员中制造了一种错过机器学习的恐惧。担心错过从机器学习用例中获得运营效率或竞争优势，是一件合理的事。目前，通过捕捉异常或预测异常来提高运营智能从而获得投资回报率（ROI）的可能性，在财务上可能是有益的。一些群体确实认为炒作的程度过头了 [2]。Andrew Ng 关于这一点的观点之一是，人们确实可以在测试数据集上真正展示“可能的艺术”，但进入生产环境日常强化运行的阶段，有时并不能转化为相同的效率 [3]。

# Substack 第 21 周：开展机器学习工作

发布于 2021 年 6 月 18 日

也许是时候有点“大胆”，开始在 Google 上搜索“机器学习项目为什么会失败？”了。我确信这会在未来几天给我带来各种奇怪的广告。你毫无疑问会被推向 Gartner 关于该主题的一项研究 [1]。也许你应该试着关注那项研究的一个细节，即新闻稿发布于 2018 年。三年后人们仍然关注它的原因是这句话：“Gartner 预测，到 2022 年，85% 的 AI 项目将因数据、算法或负责管理它们的团队中的偏见而产生错误结果。”也许出于显而易见的原因，这一指标一直萦绕在人们对机器学习项目的思考前沿 [2]。多年来，依我之见，一直在发生两种截然不同的趋势。第一，组织建立大型机器学习部门的做法正在消退。第二，外部咨询机构的数量迅速增长。你可以从从事机器学习领域的初创公司数量，以及提供顾问团队帮助的大型组织数量中看到这一点。

我仍坐在这里阅读关于机器学习项目为何失败的文章 [3]。在大多数情况下，它们都大同小异，汇聚成几个共同的观察：生产数据脏乱、模型不具备动态性、运营化需要持续投入以维持。这也是基于 API 交付的机器学习解决方案往往比野外部署的其他方案更持久的原因之一。负责维护和“喂养”其提供的 API 模型的大公司，将运营维持和持续维护作为嵌入在 API 交易价格中的服务提供。这些努力在很大程度上针对你试图通过 API 调用完成的具体任务。许多机器学习用例以这种方式效果足够好。
