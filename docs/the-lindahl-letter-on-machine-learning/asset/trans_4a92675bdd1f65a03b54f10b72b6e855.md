

# OpenAI Codex 演示与伦理考量

“昨天，我在客厅的电视上观看了 OpenAI Codex 的演示。这可能是一项新技术极其重要的演示。它几乎是对话式编程的一种实现。在演示过程中观察一个生成式、交互式、基于代码插值的语言模型运作，非常有趣。这项技术很可能就是与计算接口进行编码交互的未来。我非常担忧这类技术的伦理考量。在意识到他们构建了什么之后，这是我脑海中浮现的第一个念头。OpenAI 团队应该致力于开发一个伦理边界模块。这项行动很可能应该成为该整个团队的首要任务。波士顿动力公司的机器狗 Spot 完全有可能现在就拥有一个可工作的机器学习 API，而 Codex 可以在功能上对其进行教导和指挥。请思考一下：‘使用 OpenAI Codex 通过 Spot API 发布编程指令的伦理边界是什么？’对我来说，这是一个非常现实的担忧，在构建并投入运营更复杂的机器人实现之前，应该对此进行深思熟虑。”

# 机器学习集成：搜索现实与技术现实

坐在这里搜索一些关于机器学习集成的内容，我了解到 Google Chrome 的自动完成功能一直试图诱导我点击“机器学习面试题”。显然，搜索面试题比研究集成要流行得多 [1]。当我终于从这个震惊中缓过神来（花了几秒钟），我意识到在实际搜索结果之前展示了四个不同的广告。人们正在为这些展示位付费。我相信 Domo、Alteryx、Dataiku 和 BMC 的市场部门初衷是好的，但竞得向我展示广告权利的这些公司，没有一家能赢得我的生意。与你的机器学习层进行集成很难。句号。目前没有任何办法绕过这个现实。方程式中有趣的部分在于，在 Google Scholar 上你不会立即看到关于困难集成的文章 [2]。

像 Towards Data Science 那边那些更务实的人，会很快谈论为什么将机器学习集成到你的应用程序中如此困难 [3]。人们正在大规模地将机器学习构建进应用程序中，并且你可以在工作流中调用外部供应商的 API 并与之协作，没有太大困难。该 API 将明确定义你需要发送什么以及将收到什么。来自 GCP、AWS、Azure 或其他众多机器学习提供商的所有这些 API 都将有完善的脚本，唯一真正的顾虑是成本和延迟。搭建你自己的机器学习栈并服务机器学习模型将会更困难。我们现在看到更多用于部署和管理机器学习管道以实现稳健集成的端到端平台 [4]。所有让工作流与机器学习层之间集成变得更容易的基础工作正在进行中。我花时间研究的核心领域之一是 MLOps，这是人们渴望解决的问题。像 Weights & Biases 这样的工具正在增加功能，但它们还不是全栈任务控制系统。这就是 MLOps 领域的发展方向，但这一趋势的汇聚需要一些时间。请再看图 3。

# Substack 第 31 周：边缘机器学习集成

发布于 2021 年 8 月 27 日

我在 2021 年 8 月 17 日举行的 Ai4 人工智能大会上发表演讲，度过了愉快的时光。我的演讲主题是“什么是 ML 规模？ML 使用的地点与时机。”能在现场与人们聊聊机器学习用例非常有趣。在此次演讲中，我重点关注了大规模机器学习规模和 MLOps 决策背后的战略。你可以通过此 Vimeo 链接观看演讲：https://vimeo.com/577702076

你会很快发现，关于边缘机器学习这一理念，存在大量学术研究 [1]。这不应与前沿机器学习的概念混淆，后者是关于描述可能性的边界，而前者是关于边缘侧的机器学习。如果你考虑一下设备是如何设置和工作的，那么你就可以绘制出处于连接边缘的事物图。它可能是所有物联网设备、你的智能手机，或不断增长的连接设备池中的其他事物。我们在 IBM 的朋友甚至专门设立了一个页面，介绍在边缘部署机器学习模型的乐趣 [2]。你现在正在基于 Apple 或 Android 的智能手机上使用边缘部署的机器学习模型进行摄影或语音助手操作。有人训练了一个模型来处理照片或帮助驱动相关搜索，并将其部署在你的智能手机上，没有任何真正的喧嚣或庆祝。这样做是为了让边缘侧的事情变得更简单。

你在边缘的集成将始终受到两个与处理能力和互联网接入相关的不同因素的制约。你不能指望拥有足够的带宽，随时将智能手机的数据传出并在云端处理照片。我们的无线网络没那么好，而且大多数人没有无限的带宽来支持这种工作。你还会面临另一个与延迟相关的问题，人们就是不再喜欢等待事情发生。互联网伴随着一系列嗡嗡声和哔哔声启动、事情才开始发生的日子早已一去不复返。现在越来越多使用设备的人从未经历过等待拨号连接初始化的过程。这一现实意味着，为了避免等待、延迟和其他感知上的失败，你必须努力训练和部署机器学习模型，以最低可能的处理能力要求和空间需求实现真实结果。

我正在阅读 Gao 等人 2020 年在 arXiv 网站上发表的题为“The Pile: An 800GB Dataset of Diverse Text for Language Modeling”（The Pile：一个用于语言建模的 800GB 多样化文本数据集）的文章。该多样化数据集包含 825GB 的内容，功能上已清除所有来源并移除了作者信息。这一举措为了泛化而牺牲了语言模型的个性。未来的模型可能会走向另一个方向，倾向于个性而非泛化，但根据我目前在语言建模方面所见，这可能最终会更加孤立。
