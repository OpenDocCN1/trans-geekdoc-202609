

# 机器学习用例与策略

大量机器学习用例已被证明行之有效。首先应瞄准并部署类似的用例。这是进入机器学习生态系统、并可能从机器学习策略中获得可靠 ROI 的最佳方法。通过外部 API 执行可定义、可重复、且已被证明持久可靠的操作，总比尝试在组织内部做独特的事情要容易得多。其中一些用例回报可能非常丰厚，但要推动其走向成功将非常困难。因此，只想从 AWS、Azure 或 GCP 访问机器学习 API 的人，将发现一条通往用例成功的更轻松之路。所有训练、实施和持续改进机器学习模型的工作均由提供商完成。您还能获得众多用户对 API 进行压力测试的好处，而非局限于单一服务用例。

# Substack 第 39 周：机器学习安全

发布于 2021 年 10 月 22 日

NVIDIA 的研究人员发布了一个非常大的语言模型：“使用 DeepSpeed 和 Megatron 训练 Megatron-Turing NLG 530B，世界上最大、最强大的生成式语言模型” [1]。拥有 5300 亿参数，这确实是一个超大规模的生成式语言模型。所有这些模型发布以及在 GitHub 和其他途径上进行的机器学习领域代码共享，造就了一种局面：该领域的共享安全性和每个单独项目的安全性都至关重要。

本周在 Google Scholar 上出现的关于“机器学习安全”的文章比我预期的要多得多 [2]。部分内容涉及隐私相关项目，以及机器学习在安全领域的具体应用用例。部分归因于该主题内容的分散性，最好尝试同时考虑与安全相关的机器学习用例，以及围绕实际机器学习实现、代码和共享项目安全性的真实且日益增长的问题。我跟踪的许多实用开源 MLOps 项目在 GitHub 上到处都被扫描，人们提交 Pull Request 并沟通潜在问题。偶尔，您甚至可能读到关于这些 MLOps 项目的临时私有 Fork，有人正努力修补某块代码，使其通过扫描和其他安全措施 [3]。这是将问题推向解决的一种方式，但这是一个有趣的练习，因为它不属于推动产品功能的范畴，却是能够在企业环境中使用该产品的关键。

机器学习实现完全有能力检测统计异常。人们似乎喜欢的一个用例与网络安全入侵检测有关 [4]。许多安全工作都是关于在正常使用模式中发现标记为异常的事物。这就是为什么监控和流量分析是安全工作的重要组成部分。机器学习可以在该类工作中发挥关键作用。为此，我花了一些时间阅读 Cisco 团队关于利用机器学习的安全应用的文章 [5]。这是一篇关于机器学习如何增强安全用例的不错文章，但我试图更深入地挖掘实际机器学习实例内部安全运作的本质。AIOps 和 MLOps 领域的软件已存在且每天都在快速变化；您可以在 GitHub 上看到更新。这些应用程序的安全性是我搜索期间关注的焦点。您可以在我定期关注的 MLOps 软件的 GitHub 仓库中看到安全相关的推拉动态。我的计划是回过头来分析这些模式，看看能否分离出安全相关项目。

# Substack 第 40 周：应用机器学习技能

发布于 2021 年 10 月 29 日

在开始之前，我要承认关于如何在机器学习领域找工作的内容有很多。但关于机器学习从业者的学术研究却少得多 [1]。我对该主题学术内容的匮乏感到不满，所以不得不坐下来深思熟虑。学术界有人有机会对机器学习从业者进行详细的调查和研究。也许能从中产出像 Walter Isaacson 的《创新者》（2015）这样的书籍。

目前我正在查看名为“What Is ML Scale?”的演示文稿第 4 版，上次更新于 2021 年 7 月 16 日 [2]。这些内容没有专门涉及应用机器学习技能。总体而言，这些内容和涵盖的所有想法都与该考量相邻。这一认识让我产生了两组不同的问题，可能与今天的主题——应用机器学习技能——相关。要成为一名全栈机器学习（工程师）从业者，一个人必须能够同时驾驭两组截然不同的技能 [3]。首先，他们需要能够管理机器学习模型以及该技能组合中的所有内容。其次，他们需要具备将机器学习投入运营的技能。这两点在前文中仅寥寥数语带过，在某些方面可被标记和剖析为 MLOps 和 AIOps 混合了一些深度数据分析和策展。我将在下文深入探讨。

如今模型无处不在，我们到处都有开源模型库、可供调用的 API，以及日益增多的自研解决方案。我们可能已达到机器学习模型普遍普及、绝对新颖或新型模型程度每日递减的阶段。处理模型训练所需数据、理解相关要素以制作最终可投入生产的最终产品，需要特定的技能组合。使模型具备生产就绪性需要大量的规划和执行。这就是人们购买预训练模型并使用 API 来跳过该步骤的原因之一。相关数据和用例有可能过于专业化，以至于自行构建是唯一的前进道路。但许多用例不需要这样做，尤其是机器学习图像/视觉领域的用例。
