
# Finding orthologue candidates using reciprocal BLASTs

Orthology has many important uses in bioinformatics. Orthology can be used to infer the function of a gene in a newly sequenced genome based on its similarity to known genes in other species. This can be especially useful for identifying genes that are involved in specific biological processes or pathways. Orthologous genes can be used to compare the genomes of different organisms and study the evolution of gene families. By identifying which genes are conserved across different species, researchers can gain insights into the evolutionary history of these genes and the organisms that carry them.

Orthology can be inferred via various computational methods that compare the DNA or protein sequences of genes from different organisms. Reciprocal BLAST hit (RBH) is a simple method that involves searching for the best hit of a gene in one species against all genes in another, and then searching for the best hit of the gene in the other species against all genes in the first species. If the two hits are the same genes, then they are considered orthologues.

More complicated and sensitive methods exist, including the Inparalog method, tree-based methods, and Markov-clustering methods. In this recipe, we will look at the RBH method as implemented in R OrthologR package.

# How to do it...

Computing RBH to infer orthology can be done as follows:

- 1. Create a function that will find the path to:

```r
env_path <- function (env, program = "") {
  df <- reticulate::conda_list()
  b <- df$python(which(df$name == env))
  if (length(b) == 0) { stop("no environment with name found") }
  file.path(dirname(b), program)
}

blast_path <- env_path("bioinformatics_project")
```

- 2. Set up a function to make a blast database:

```r
make_blastdb <- function(fasta, blast_path) {
  system(paste0(blast_path, "makeblastdb -in ", fasta,
  "input_type fasta -dbtype prot -hash_index"))
}
```

- 3. Set up a function to run blastp:

```r
run_blast <- function(query, db, outfile, blast_path,
  evaluate="1E-5", max_target_seqs=1000) {

  system(paste0(
    blast_path,
    'blastp -db ',
    db,
    '-query ',
    query,
    '-evaluate ',
    evaluate,
    '-max_target_seqs ',
    max_target_seqs,
    '-out ',
    outfile,
    '-outfmt "6',
    ' gseqid ssdid pident nident length mismatch gapen gaps\npositive ppos qstart gend qlen qovs ccovhp sstart send len\nvalue bitscore score'
  ))
}
```

- 4. Run blastp in the first direction:

```r
sceres <- fs::path_package(
"extdata",
"sceres_100.fa",
package = "rbioinfookbook"
)

spombe <- fs::path_package(
"extdata",

```r
blast_res_a <- "sp_vs_sc.csv"

```

- 5. Run blast in the reciprocal direction:

```r

run_blast(sceres, spombe, blast_res_b, blast_path)
```

- 6. Set up a function to parse the blastp output:

```r
parse_hits <- function(outfile){
  col_names <- c(
    "query_id", "subject_id",
    "perc_identity", "num_ident",
    "aln_length", "mismatches",
    "gap_open", "n_gaps",
    "pos", "ppos",
    "q_start", "q_end",
    "q_len", "qcov",
    "qcov_sp", "s_start",
    "s_end", "s_len",
    "value", "bit_score",
    "score_raw"
  )
  hits <- data.table::as.data.table(
    readr::read_delim(
      file = outfile,
      delim = "\t",
      col_names = FALSE,
      col_types = readr::cols(
        "X1" = col_character(), "X2" = col_integer(),
        "X3" = col_double(), "X4" = col_integer(),
        "X5" = col_integer(), "X6" = col_integer(),
        "X7" = col_integer(), "X8" = col_integer(),
        "X9" = col_integer(), "X10" = col_double(),
        "X11" = col_integer(), "X12" = col_integer(),
        "X13" = col_integer(), "X14" = col_double(),
        "X15" = col_double(), "X16" = col_integer(),
        "X17" = col_integer(), "X18" = col_integer(),
        "X19" = col_double(), "X20" = col_integer(),
        "X21" = col_double()
      )
    )
  )
  data.table::setnames(x = hits, old = paste0("X", 1:length(col_names)), new = col_names)
  data.table::setkey(hits, c("query_id", "subject_id")
  return(hits)
}
```

- 7. Set up a function to filter the best hits:

```r
filter_best_hits <- function(x) {
  min_val <- min(x$value)
  aln_length <- NULL
  res <- dplyr::filter(x, value == min_val)
  if (nrow(res) > 1) {
    max_len <- max(res$aln_length)
    res <- dplyr::filter(res, aln_length == max_len)
  }
  if (nrow(res) > 1) {
    res <- dplyr::slice(res, 1)
  }
  return(res)
}
```

- 8. Apply the best hit function:

```r
sp_sc <- parse_hits(blast_res_a) |>
  dplyr::group_by(query_id) |>
  dplyr::do(filter_best_hits(.))
sc_sp <- parse_hits(blast_res_b) |>
  dplyr::group_by(query_id) |>
  dplyr::do(filter_best_hits(.))
```

- 9. Join the IDs on the reciprocal hits:

```r
colnames(sc_sp)[1:2] <- c("subject_id", "query_id")
rbh <- dplyr::semi_join(
  sp_sc,
  sc_sp,
  by = c("query_id", "subject_id")
)
```

# How it works...

Step 1 is a familiar function, and uses a custom function on the reticulate package to get the path to the BLAST executables that were installed under conda. Steps 2 and 3 each show how to build a function that will run a system command - makeblastdb and blastp respectively. The functions work by pasting together fragments of the relevant commands with the variables - notably, blast_path, and in step 3, some BLAST hit options to limit the number of hits and to format the output. The long output string at the end of the run() function does nothing more than say which output columns we want in the BLAST results, despite being verbose. The code is very wide and doesn't print to the page well, so note that it should be entered without any line breaks or carriage returns - press *Enter* in the middle of that code if transcribing it.

Step 4 and step 5, we just run the BLAST, using the functions we have created. We extract the sequence files from the data package, and in step 4, run *S. pombe* as a query against an *S. cerevisiae* database, putting the output into a CSV file. In step 5, we run the reciprocal search - *S. cerevisiae* against *S. pombe* again, putting the output into a CSV file for reading in. These steps take a very long time with whole genomes, especially large ones.

# Phylogenetic Analysis and Visualization

In step 6, we define our functions for the processing of the BLAST results. The `parse_hits()` function is simple in concept - it just wants to read the CSV file and return a dataframe-style object - it goes about in a fashion that is robust and efficient, to aid in reading large files. First, col_names contains a vector of names for the hit table, then we use readr for the data, being careful to explicitly set the column types we expect. Things can easily go wrong in big files this seemingly verbose approach can pay off. The data.table() call converts the object to a robust data.table, optimized for work on large datasets. The function returns the prepared data table.
