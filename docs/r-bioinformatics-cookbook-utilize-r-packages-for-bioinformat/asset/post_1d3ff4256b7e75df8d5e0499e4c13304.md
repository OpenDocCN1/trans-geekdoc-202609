# How it works...

The tidyr package has functions that work by allowing the user to specify a particular transformation that will be applied to the data to generate a new one. In this single step, we specify a row-count increasing operation that will find all the columns that contain age information. Next, we split the title of that column data into two new columns—one for the lower bound of the age category and for the upper bound of the age category. Then, we change the type of those columns to integer, and lastly, put the actual counts in a new column.

The first function in this pipeline is code `dplyr`, which helps us rename column headings. Our age data columns are largely consistent, except for the lower bound and the upper one, so we rename those columns to match the pattern of them, simplifying the transformation specification.

`pivot_longer()` function specifies the transform in the arguments, with the cols we choose to operate on any columns containing `to`. The names_pattern argument takes a regular expression (regex) that captures the bits of text before and after the string in the column names and uses them as values for the columns defined in the names_ argument. The actual counts from the cell are put into a new column called `counts`. The transformation is applied in one step and reduces the data frames count to, increasing the row count to 6,935, and in the process making the data tidy and easier to use in downstream packages.

# Tidying a long format table into a tidy table with tidyr

In this recipe, we look at the complementary operation to the Tidying a wide format table into a tidy table with tidyr recipe. We'll take a long table and split one of its columns out to make new columns. Initially, this might seem like we're not violating our tidy data frame requirement, but we do come across data frames that have more than one variable squeezed into a single column. As in the previous recipe, tidyr has a specification-based function to allow us to correct our data frame.

# Getting ready

We'll use the tidyr package and the treatment data frame in the rbioocookbook package. This data frame has four columns, one of which—measurement—has two variable names in it that needs splitting columns into their own.

# How to do it...

In stark contrast to the Tying a wide format table into a tidy table with tidyr recipe, this expression is extremely terse; we can tidy the wide table very easily:

```
library (rbiocookbook)
library (tidyr)

treatments |>
pivot_wider(
  names_from = measurement,
  values_from = value
)
```

This is so simple because all the data we need is already in the data frame.

# How it works...

In this very simple-recipe, the specification is clearly clear: simply take the measurement column and create new columns from its values, moving the value appropriately. The names_from argument specifies the column to split, and values_from specifies where its values come from.

# There’s more...

It is possible to incorporate values from more than one column at a time; just pass a vector of columns to the names_from argument, and you can format the computed column names in the output with names_glue.

# Combining tables using join functions

Joining rectangular tables in data science is a powerful way to combine data from multiple sources, allowing for more complex and detailed analysis. The process of joining tables involves matching rows from one table with corresponding rows in another table, based on shared columns or keys. The ability to join tables allows scientists to gather information from different sources and also be used to clean and prepare data for analysis by eliminating duplicates or filling in missing values. Note that although joining process is powerful and useful, it isn't magic and is actually a common source of errors. The user must take care that the operation was successful in the way they intended and that combining data doesn’t create unexpected combinations, especially empty cells and repeated rows.

# Loading, Tidying, and Cleaning Data in the tidyverse

The dplyr package provides functions for manipulating and cleaning data, including a function called join() that can be used to join tables based on one or more common columns. The join function supports various types of joins, including inner, left, right, and full outer joins. In this recipe, we'll look at each of these joins works.

We'll need the dplyr package and the rbioinfo cookbook package, which will give us a short gene dataset of 10 Mapagorte oryza, and related annotation data of approximately 60,000 rows for the entire genome.

# How to do it...

The process will begin with loading a data frame from the data package. The mo_gene_exp, mo_go_acc, and mo_go_evidence objects are all available as data objects when you load the rbioinfocookbook library, so we don't have to load them from the file. You will see this behavior in our R tutorials. For our work, this mimics the situation where you will already gone through the process of loading in data from a file on disk or received a data frame from an upstream function.

The following will help us to join tables:

- 1. Load the data and add terms to genes:

```
library(rbioinfocookbook)
library(dplyr)
```

```
x <- left_join(mo_gene_exp, mo_terms, by = c('gene_id' = 'Gene stable ID'))
```

- 2. Add accession numbers:

```
y <- right_join(mo_go_acc, x, by = c('Gene stable ID' = 'gene_id' ))
```

- 3. Add evidence code:

```
z <- inner_join(y, mo_go_evidence, by = c('GO term accession' = 'GO term evidence code'))
```

- 4. Compare the direction of joins:

```
a <- right_join(x, mo_go_acc, by = c('gene_id' = 'Gene stable ID') )
```

- 5. Stack two data frames:

```
mol_func <- filter(mo_go_evidence, `GO domain` == 'molecular function')
cell_comp <- filter(mo_go_evidence, `GO domain` == 'cellular component')

bind_rows(mol_func, cell_comp)
```

- 6. Put two data frames by side:

```
small_mol_func <- head(mol_func, 15)
small_cell_comp <- head(cell_comp, 15)
bind_cols(small_mol_func, small_cell_comp)
```

And with that, we have joined data frames into one in most possible ways.

# How it works..

The code joins different data frames in various. The mo_gene_exp, mo_terms, mo_go_acc, and mo_go_evidence objects are data frames, and they are loaded using the rbioinf library. Then, the first operation is to add terms using the left_join() function. The left_join() function joins the mo_gene_exp and mo_terms data frames on the gene_id column of the mo_gene_exp data frame and the stable ID column of the mo_terms data frame. Note the increase in rows as well as columns because of the multiple matching rows.

By step 2, we are adding accession numbers using the right_join() function to join the mo_go_acc data frame and the result of the first join (x) on the Gene stable ID column of the mo_go_acc data frame and the x data frame. Ordering the data frames minimizes the number of rows; see step 5 for how the converse goes. Note that the right_join() function returns the full set of rows from the right data frame.

Step 3:inner_join() demonstrates that only the rows shared are returned. The remaining steps create subsets of the mo_go_evidence data frame based on to highlight how bind_rows() does a name-unaware stacking and bind_cols() does a bind left-right paste concatenation of data frames. These last two functions are quick and easy but do not do anything clever, be sure that the data can be properly joined this way.
