# How it works...

Step 1 is a long one, but essentially repeats code discussed earlier in the chapter (for example, the first plot comes from the Changing chapters in this ggrides section). Note that in p1 and p3 we modify the legend, using the guides function in the scale_fill_manual() layer to make sure that the grid flows over two or three lines (so that there is one element per line)—this will be important later as the grid will extracted into a space of its own.

Step 2 we create a plot that includes p1, p2, and p3 by passing them to cowplot::plot_grid() function and setting the number of columns to 1, such that the plots are stacked vertically. We apply labels for each one. Note that the plots have their legends removed using theme before they are stacked; we will apply the labels manually.

Step 3 cowplot_get_legend() function to extract the legends from the original plots to their objects; these objects are stacked into a column, again using plot_grid(). NULL forces the grid to contain an empty element at that point.

Step 4, we compose the two columns we have (again with plot_grid()), this time in columns two (two_cols), using the rel_widths option to allow the plots to take up sixty percent the width of the plot. To finish, we add a label to p4—which you guessed—plot_grid() and then put that over our previous columns by calling plot_grid() for one last time, the number of columns to 1 and the relative heights such that the columns take up the majority of space. The final plot looks like this in Figure 3.18—or it when rendered in the small space for plots provided by this book's format. You may see a clearer plot when it your on your own machine. As R works by rendering in a viewport—a rectangle of a specified size—and trying to fit into objects, that can overlap when some objects can't reduced further. This is a problem in this plot composed of many subplots so some elements can't shrunk too—specifically, text must remain large enough to read when the plots get too small, it will overlap.
