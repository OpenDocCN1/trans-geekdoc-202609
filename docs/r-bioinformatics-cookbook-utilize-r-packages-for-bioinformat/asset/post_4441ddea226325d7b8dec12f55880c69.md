## Aligning genomic length sequences with DECIPHER

Aligning sequences longer than genes and proteins, such as from assembly projects, chromosomes, or whole genomes is a tricky task. For tasks, we need different techniques than those for short sequences. The longer the sequences, the harder they are to align. Long alignments are especially costly in terms of the computational time. The algorithms that are effective on short sequences take up exponentially time with increasing sequence length. Performing longer alignments generally starts with finding short anchor alignments and working the long alignment out from there. We typically end up with blocks of stony regions that match between the different sequences.

In this recipe, we will look at the DECIPHER package for genome length alignments. We'll use chloroplast genomes - small organic genomes of about 150 Kbp that are pretty well conserved as our sequences of interest.

## Getting ready

For this recipe, we will need the DECIPHER Bioconductor package and the plastid_genomes.fa file, which can be found in the rbinfoinfcookbook package.

## How to do it...

Aligning genomic length sequences with DECIPHER can be done by performing the following steps:

- 1. Load in the necessary libraries and genome sequences:

```
library(DECIPHER)
genomes_file <- fs::path_package(
"extdata",
"plastid_genomes.fa",
package = "rbinfoinfcookbook"
)
long_seqs <- readDNAString(genome_file)
long_seqs
```

```
Segs2DB(long_seqs, "XStringSet", "long_db", names(long_seqs))
```

```
synteny <- FindSynteny("long_db", verbose=FALSE)
```

```
plot(synteny)
```

- 5. Complete the alignment:

```
alignment <- AlignSynteny(synteny, "long_db", verbose=FALSE)
```

- 6. Save pairwise alignments:

```
blocks <- unlist(alignment[[1]])
writeXStringSet(blocks, "genome_blocks_out.fa")
```

That is all we need to do for a genome length alignment.

## How it works...

The DECIPHER package is very powerful, so there is a bit of setup to do before we can get the alignments. In step 1, we load the necessary libraries and sequence data into long_seqs, DNAStringSet; in step 2, we build an on-disk SQLite database for the subsequent steps. This is done with the Segs2DB() function, which takes long_seqs, an input type (here, XStringSet, which is the parent class of DNAStringSet), a name for the database, and a vector of sequences. Once we get the database, in step 3, we find the syntenic blocks in the database with FindSynteny(), which results in the following output:

## Novel feature detection in proteins

Sometimes, we'll have a list of protein sequences that have come from some analysis or are in some way related. We wish to determine the parts of those proteins that are responsible for the Domain and motif finding, as we've done in the preceding recipes, can only be helpful if we see the sequence conserved or statistically over-represented. A different approach is to try machine learning, in which we build a model that can classify our proteins accurately and use the properties of that to show which parts of the proteins result in the classification. We'll take that approach by training a support vector machine (SVM).

## Getting ready

For this recipe, we'll need the keras and Bioconductor packages, as well as the readr packages. We'll also need two data files that are provided in the rbinfocookbook package and will be extracted using the fs package. The data files represent Escherichia coli proteins, for which the STRING database provides evidence that these proteins interact. The ecoli_protein.fa.file is a single-column text file that describes the class of each protein, using 1 for positive and -1 for other.

## How to do it...

We can use machine learning for novel feature detection in proteins by performing the following steps:

- 1. Load the necessary libraries and input files:

```
library(keras)
library(Biostrings)
sequence_file <- fs::path_package(
"extdata",
"ecoli_proteins.fa",
package = "rbinfocookbook"
)
seqs <- readStringSet(sequence_file)

class_file <- fs::path_package(
  "extdata",
  "ecoli_protein_classes.txt",
  package = "rbinfocookbook"
)
```

- 2. Divide the data into training and test sets:

```
classes <- readr::read_csv(class_file, col_names = TRUE)
classes <- classes$class
num_seqs <- length(seqs)
training_proportion <- 0.75
training_set_indices <- sample(1:num_seqs, training_proportion)
test_set_indices <- c(1:num_seqs)[-training_set_indices]
```

- 3. Build the model with the training set:

```
kernel <- girlyKernel(k=1, m=3)

model <- ksvm(x=seqs[training_set_indices],
      y=classes[training_set_indices],
      kernel=kernel,
      package="e1071",
      svm="C", cost=15)
```

- 4. Use the model to predict the classes of the test set:

```
predictions <- predict(model, seqs[test_set_indices])
evaluatePrediction(predictions, classes[test_set_indices],
      labels=c(1,-1))
```

- 5. Examine the prediction profile of a sequence:

```
seq_to_test <- seqs[[1]][1:10]
prediction_profile <- getPredictionProfile(seq_to_test, kernel,
      model=model)
```

- 6. Plot the prediction profile:

```
plot(prediction_profile)
```

## How it works...

Step 1 is straightforward – we load in a simple vector of classes for that data, we extract from the main workflow. We just use the $ operator. Then, in step 2, we decide how much data we use for training and how much should be tested. We set 75% of the training data when we create the `training_proportion` variable. This is used in conjunction with `num_seqs` sample() to randomly choose indices of the sequences to put into the training set. The training_set_indices variable contains integers that we will use to subset data later. Then, we make a vector of complementary indices for the test set in test_set_indices by using the square bracket and the negation operator (-). In essence, this is an idiomatic way of creating a vector that contains every index not in training_set_indices.

In step 3, we construct and train the SVM model, and we start by choosing a kernel to map the input data into a matrix space that the SVM can learn. Here, we use the function. Note that there are lots of kernels; this one is well suited to sequence data. We pass the kernel to the ksvm() function with the training_set_indices subset of sequences as the x parameter and the same subset of classes as the y parameter. Other arguments in this function determine the exact model type and package and they can have a strong effect on the quality of the final model. It is well reading and doing some scientific experimentation on what works best for your particular data. The final model is saved in the model variable.

In step 4, although our model is constructed, we must now test its accuracy. To do this, we run it with the unseen data from earlier, by test_set_indices, and compare its predictions with real labels. Again, we use the prediction() function to do this evaluatePrediction(), along with the real class labels from the classes vector and a vector of all possible class labels. Using the AllLabels argument returns a summary of the accuracy and other metrics of the model, as shown here:

```

```

We have an accuracy of 69% in the model here, which is okay; it is better than random. We have a smaller dataset and the model is not optimized; with more work, it could be better. Note that if you run the code, you might get different answers. Since the selection of training sequences is random, the models might do slightly worse or better, depending on the input data.
