# Easy Performing Statistical Tests Using Linear Models

We do exactly that in step 2, using the mult package to do a general linear model hypothesis test through the glht (). The function is more flexible with respect to designs and contrasts you can get out than the built-in TukeyHSD(), it is a little more complicated. The base case is straightforward toward. The linf() option just takes a specification of the things to be tested, and the mcp() function helps generate the comparison based on a text description, here the variable group should be analyzed by Tukey. The output looks as follows:

```
## Simultaneous Tests for General Linear Hypotheses
##
## Multiple Comparisons of Means: Tukey Contrasts
##
## Fit: lm(formula = weight - group, data = PlantGrowth)
## Linear Hypotheses:
## Estimate Std. Error t value Pr(|t|)
## trtl1 ctrl == 0 -0.3710 0.2788 -1.331 0.3909
## trt2 ctrl == 0 0.4940 0.2788 1.772 0.1980
## trt2 trtl == 0 0.8650 0.2788 3.103 0.0121 *
##
## Signif. codes: 0 ' 0.001 *** 0.01 ** 0.05 ' * .1 . * 1
## (Adjusted p values reported - single-step method)
```

By printing the summary, we see the contrasts written explicitly (e.g. the probability that the difference between ctrl1 and trtl1 is zero). The conclusion is that there is no evidence to suggest either treatment is different from the control, but the difference we observe between trtl1 and trt2 occurs by chance about 1.2% of the time, so is deemed significant.

And that's it! That was a properly done and specified of the linear model and subsequent ANOVA with Tukey's post hoc used to determine differences.

# There's more...

In step 1, we generated a model, and R decided what the baseline should be. If we wish to, we can specify using the relevel(1) function and the ref option as follows:

```
df <- PlantGrowth
df$group<- relevel(df$group, ref="trt2")
model_2 <- lm(weight - group , data = df,)
summary(model_2)
```

In the summary() output, we can see the comparisons are all done on that new reference. We do not use this as a method for generating all comparisons as it gets tedious and generates multiple comparison errors. The multcomp package is cleaner, has many options for different types of comparisons, and corrects p-values for multiple hypothesis tests.
