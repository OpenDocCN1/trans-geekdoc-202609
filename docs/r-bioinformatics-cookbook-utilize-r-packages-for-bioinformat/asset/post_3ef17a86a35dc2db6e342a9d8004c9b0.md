
# Getting ready

For this recipe, we need a matrix describing the motif (a position-specific weight matrix or PWSM) and a set of sequences from upstream transcriptional start sites. These are provided in the rbioinfocookbook package. We'll use the universalmotif package to work with motifs and the reticulate package to help us paths to external tools. We will need to install the external tool before we begin. This can be done through bioconda, as described in Chapter 1, Setting Up Your R Bioinformatics Working Environment, in the Use bioconda to install external tools recipe. The package can be found at https://anaconda.org/bioconda/meme.

Now, we're to go.

# How to do it...

Finding DNA motifs with universalmotif can be done as follows:

- Create a function that will find the path to meme:
```python
env_path <- function(env, program = "") {

  df <- reticulate::conda_list()
  b <- df$python[which(df$name == env)]

  if (length(b) == 0) {
    stop("no environment with that name found")
  }

  file.path(dirname(b), program)
}

meme_path <- env_path("bio_project", "meme")
```

- Load the necessary libraries and motifs of interest:
```r
library(universalmotif)
library(Biostrings)

motif_file <- fs::path_package("extdata",
                               "simple_motif.txt",
                               package="rbioinfocookbook")
motif <- read_matrix(motif_file)
promoter_file <- fs::path_package(
"extdata",
  "promoters.fa",
package = "rbioinfocbook"
)
sequences <- readDNAStringSet(promoter_file)
```

- 3. Scan the sequences:

```r
motif_hits <- scan_sequences(motif, sequences = sequences)
head(motif_hits)
```

- 4. Calculate whether the motif is enriched in the sequences:

```r
motif_info <- enrich_motifs(motif,

sequences,
shuffle.k = 3,
verbose = 0, RC = TRUE)

motif_info
```

- 5. Run MEME to find motifs:

```r
meme_run <- run_meme(sequences, bin = meme_path, output = "meme-\nout", overwrite.dir = TRUE)
motifs <- read_meme("meme_out/meme.txt")
view_motifs(motifs)
```

And that's all we need to do to see the results of our searches.

# How it works...

This is efficient code! In just a few lines, we were able to complete a whole analysis. In step 1, we created a function that would find the path to the external meme program. Then, in step 2, we loaded in a matrix description of a motif and some sequences we use to find the motif. In step 3, we scanned the sequences and found a universal motif and a DNAStringSet object to work with. The scan_sequences() function searches each of the sequences and reports where it finds motifs - check out the motif_hits object to see where they are. The object prints like:

```
## motif motif.i sequence sequence.i start stop score
## 1 YTTTTTTTTTTTTTY 1 AT1G5670 47 62 76 9.402
## 2 YTTTTTTTTTTTTTY 1 AT1G5670 47 65 79 10.290
```

When it comes to working out whether a motif is enriched, enrich_motifs() does this work in step 4 and we use Fisher's exact test to confirm the frequencies of motifs in our set of sequences. It searches the sequences to find instances of motifs and uses with their frequencies in an automatically generated background set. The final motif_info output contains a report of the p-value. To find novel motifs, we run the external software MEME in step 5. The run_meme() function needs to know where the MEME package is on your system, so we defined in the meme_path variable that we generated from our function in step 1.

We passed that information to run_meme(), along with the DNAstringSet object containing the sequences. The function also needed an output directory to write results as it doesn't return anything to R. The run_meme() function executes MEME in the background and once the run is finished, we can load results from meme.txt file using read_meme(). It returns a universalmotif object. We can inspect the motifs found with view_motifs() function – looks like what's shown in Figure 8.1.

# There’s more...

Loading motifs from databases such as JASPAR and TRANS is easy with universalmotif as there are straightforward replacements for the read_matrix() function. To load motifs in various formats, we can use cisbp(), read_homer(), read_jasp(), read_meme(), and read_motifs() functions.

# Finding protein domains with PFAM

Decoding a protein sequence is a key task. We can do this in many ways, including whole sequence searches against BLAST. If we want more informative and granular information, we can instead look for individual functional domains. Databases such as PFAM and tools as hmmmer encode domains from Hidden Markov Models, which hmmmer uses to scan sequences and report any occurrences of the domains. Often, gene annotation projects will carry out the searches for us, which is a question of searching a database in these particular packages, usually ending in .db. In this recipe, we’ll look at how to work out whether a package contains PFAM domain information, how to extract it for specific genes of interest, and an alternative method for running PFAM search if there isn't any pre-existing information.

For this example, we'll need org.Hs.db and a FASTA sequence file, which can be found in the rbioinfocookbook package. To connect to the hmmer service, we'll need the bio3d, fs and dplyr packages.

# How to do it...

Finding proteins with PFAM database can be done by performing the following steps:

- 1. Load the database and inspect the keys in the database:
```r
library(org.Hs.eg.db)
keytypes(org.Hs.eg.db)
```

- 2. Get a vector of keys:
```r
k <- head(keys(org.Hs.eg.db, keytype = "ENSEMBL", n = 3)
```

- 3. Query the database:
```r
result <- select(org.Hs.eg.db, keys = k, keytype = "ENSEMBL",
columns = c("PFAM"))
result
```

- 4. Load the PFAM database to extract descriptions:
```r
library(PFAM.db)
descriptions <- PFAMDE
```

- 5. Get all the keys from the database:
```r
all_ids <- mappedkeys(descriptions)
```

- 6. Get all the descriptions from the IDs:
```r
id_description_mapping <- as.data.frame(descriptions[all_ids])
```

- 7. Join the descriptions to PFAM:
```r
dplyr::left_join(result, id_description_mapping, by = c("PFAM" = "ac"))
```

Here, added the necessary PFAM descriptions.

# How it works...

The key to this approach is finding out whether the database you are trying to use carries the domain information. That what happens in step 1 – we use the keytypes() function to list the search available and we can see PFAM in the results. Once we've verified that we can use this database for the information we want, we can follow a fairly standard procedure from step 2. In step 2, we have a list of keys to query – like gene names. We pull them from the database directly, but they could come from anywhere. In step 3, we query the database with the select() function to pull data for given keys. The columns argue that data to pull. In step 4, we make a list of PFAM IDs and descriptions. We load the PFAM.db package and use the PFAMDE object to get mapping between IDs and descriptions. This will result in the following output:

```
##
## 1 ENSG00000121410 PF13895
## 2 ENSG00000175899 PF02027
## 3 ENSG00000175899 PF17789
## 4 ENSG00000175899 PF07677
## 5 ENSG00000175899 PF17791
## 6 ENSG00000175899 PF01835
## 7 ENSG00000175899 PF07703
## 8 ENSG00000175899 PF07678
```

We can then get the actual descriptions with mappedkeys() in step 5, and extract and convert the descriptions of all the IDs into a DataFrame in step 6. Finally, we join the conversions of the domains to the IDs by using the columns that contain common data (PFAM and ac), resulting in the following output:

```

```

This is a DataFrame with the gene ID and the PFAM attached.
