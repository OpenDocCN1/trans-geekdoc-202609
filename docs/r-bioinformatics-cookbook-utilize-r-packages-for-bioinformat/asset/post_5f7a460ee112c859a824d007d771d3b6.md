enricher_to_david <- function(enrich,terms) {
  comma_sep_genes <- gsub("/", " ", enrichresult@result$geneID)

  terms <- dplyr::mutate(terms,
    short_category = dplyr::if_else(`GO domain` == 'biological_process', "BP",
    dplyr::if_else(`GO domain` == "molecular_function", "MF", "CC"))
  )

  id_to_category <- terms$short_category
  names(id_to_category) <- terms$GO term accession
  fixed_category <- id_to_category[enrich$result$ID]

  data.frame(
    category = fixed_category,
    ID = enrichresult$ID,
    term = enrichresult$Description,
    genes = comma_sep_genes,
    adj_pval = enrichresult@result$p.adjust
  )
}

# Finding GO enrichment in an Ontology Conditional way with topGO

The GO is a hierarchical ontology that describes the biological processes, molecular functions, and cellular components of gene products in a standardized way. The ontology is structured as a directed-acyclic graph (DAG) with three main categories: Biological Process (BP), Molecular Function (MF), and Cellular Component (CC).

Higher in the GO hierarchy, there are broader terms; for example, in the BP category, terms such as biological regulation and cellular process exist. As we move the hierarchy, the terms become more specific and narrower in scope, and regulation of gene expression or protein localization to organelle more specific terms within the BP category. Each term has parent terms and child terms.

The hierarchical nature of the GO allows researchers to perform analyses at different levels of specificity. A common need is to collapse similar terms to a higher, more general term that captures them all. In this recipe, we'll look at a couple of ways of automating with the topGO package. Specifically, topGO implements hierarchy-aware methods like elim and parent-child, as described in Alexa et al. (2006) and Grossman et al. (2007).

Hierarchy-aware GO analysis can be done as follows:

1. Prepare the sets of genes and GO annotations:

```r
library(clusterProfiler)
mo_ids <- unique(mo_go$`Gene ID`)
geneid2go <- lapply(mo_ids, function(gene_id){
  df <- dplyr::filter(mo_go, `Gene ID` == gene_id)
  unique(df$`GO term accession`)
})
names(geneid2go) <- mo_ids

mo_exp_path <- "data/mo_exp.csv"
mo_exp <- readr::read_csv(mo_exp_path)

gene_list <- factor(as.integer(mo_ids %in% mo_exp$gene_id))
names(gene_list) <- mo_ids
```

2. Build the topGO object:

```r
library(topGO)
topGO_data <- new("topGO",
  ontology = "MF",
  allGenes = gene_list,
  nodeSize = 3,
  annot = बनी.GO,
  gene2GO = geneid2go)
```

3. Run tests:

```r
test_result_elim <- runTest(topGO_data, algorithm = "elim", statistic = "fisher")
test_result_pc <- runTest(topGO_data, algorithm = "parent-child", statistic = "fisher")
```

4. Create a combined list:

```r
results <- combine(topGO_data,
  elim_fisher_pval = test_result_elim,
  pc_fisher_pval = test_result_pc,
  orderBy = "elim_fisher_pval",
  rankof = "elim_fisher_pval",
  topNodes = 10)
```

5. Plot the GO trees:

```r
showSigOfNodes(topGO_data, score(test_result_elim),
  firstSigNodes = 5,
  useInfo = "all")

showSigOfNodes(topGO_data, score(test_result_pc),
  firstSigNodes = 5,
  useInfo = "all")
```

This is all we need to perform topology-aware GO analysis.

# How it works...

The recipe starts off, as many GO analyses do, with the conversion of our data to a new format for analysis. In step 1, we take the mo_go data object, which contains a dataframe of GO annotations of Magnaporthe oryzae, and extract the unique IDs. We then use the lapply function to loop over all IDs, and apply dplyr::filter() to extract subsets of the annotation annotation, which include the current gene ID and return a vector of GO IDs attached to that gene by collapsing the dataframe with the GO IDs. The resulting list, gene2GO, contains a mapping in the right format for topGO. We next load a dataframe of IDs and gene expression values and prepare the gene_list, which must be a named vector of all genes in which the names of the vector are the gene IDs and the values are a factor of '0' or '1' levels, indicating whether the gene is in the list of interest or not. The code does this by checking logically which the members of the full list (mo_ids) are in the list of interest (mo_exp$gene_id) with %in%, then converts them to integers and then a factor, and adds the names to the vector with names().

In step 2, we create the topGO_data object using the constructor. We pass new (the ontology we're interested in, the list of all genes, and a node size threshold that will analyze GO IDs with the minimum number of genes (in this case, 3). The annot argument receives a constant - a function within the topGO package - gene2GO the mapping prepared in step 1.

By step 3, we set all to perform statistical tests. the runTest() function takes our input data and allows us to define the algorithm and test we want to use. Here we first use the elim method and the parent-child method, analyzing each with Fisher's exact.

In step 4, we combine the results of the tests into a single dataframe for analysis; note that it contains columns of p-values for both algorithms and they give different results.

In step 5, we visualize the GO tree and each node's level of significance within it. The firstSigNodes parameter limits how many significant GO terms to use. The resulting subgraphs are different for each algorithm, as you can see in Figure 10.3 and Figure 10.4:
