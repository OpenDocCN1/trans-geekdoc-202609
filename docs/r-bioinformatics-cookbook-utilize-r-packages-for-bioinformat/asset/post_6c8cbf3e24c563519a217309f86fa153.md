# Creating dot plots for alignment visualizations

Dot plots of aligned sequences are possibly the oldest alignment visualization. In these plots, the positions of two sequences are plotted on the x axis and y axis, and for every coordinate in space, a point is drawn if the letters (nucleotides or amino acids) correspond at (x,y) coordinate. Since the plot can show regions that match in the same region of the two sequences (as lines away from the diagonal), the plot is a good way to visualize plot insertions and deletions and structural rearrangements in the two sequences. In this recipe, we'll look at a speedy method for constructing a dot plot using the dotlot package and a bit of code for getting a grid plot of all pairwise dot plots for sequences in a file.

# Getting ready

We'll need the bhlh.fa file, which contains three basic helix-loop-helix (bHLH) transcription factors from pea, soy, and lotus. The file is provided by the rbioinf package. We'll also need the Biostrings package and the evolvedmicrobe/dotplot GitHub-hosted package.

# How to do it...

Generating dot plots for alignment visualization can be executed using the following steps:

- 1. Load the libraries and sequences:

```
library(Biostrings)
library(ggplot2)
library(dotplot)
seqfile <- fs::path_package(
  "extdata",
  "bhlh.fa",
  package = "rbiocookbook"
)

seqs <- readAAStringStringSet(seqfile)
```

- 2. Make a basic dot plot:

```
dotPlotg(as.character(seqs[[1]]),
as.character(seqs[[2]]))
```

- 3. Change the dot plot and apply themes and labels:

```
dotPlotg(as.character(seqs[[1]]), as.character(seqs[[2]]),
width=7, wstep=5,
nmatch4=4) + theme_bw() +
labs(x=names(seqs)[1], y=names(seqs)[2] )
```

- 4. Make a function that will create a dot plot automatically:

```
make_dot_plot <- function(i=1, j=1, seqs = NULL){
seqi <- as.character(seqs[[i]])
seqj <- as.character(seqs[[j]])
namei <- names(seqs)[i]

namej <- names(seqs)[j]
return(dotPlotg(seqi, seqj) + 
theme_bw() + labs(x=namei, y=namej))
}
```

- 5. Set up data structures to run the function:

```
combinations <- expand.grid(1:length(seqs),1:length(seqs))
plots <- vector("list", nrow(combinations))
```

- 6. Run the function on all the possible combinations:

```
for (r in 1:nrow(combinations)) {
i <- combinations[r,]$Var1[[1]]
j <- combinations[r,]$Var2[[1]]
plots[r] <- make_dot_plot(i,j, seqs)
}
```

- 7. Plot the grid of plots:

```
cowplot::plot_grid(plotlist = plots)
```

That is all we need to do.

# How it works...

The first part of this recipe is pretty familiar. In step 1, we load in the libraries and use Biostrings to load in our protein sequences. Note that our sequences in the seqs object are an instance of the XCString class. In step 2, we create a basic dot plot using the dotplot() function. The arguments are the sequences we want to plot. Note that we can't pass the XCString objects directly; we need to pass character vectors, so we coerce our sequences into that format with the as.character() function. With the size option, we state that we are looking at 7 residues at a time (instead of the default of 1), the wstep option tells the plotter to jump 5 residues at each step, and the nmatch option tells the plotter to mark a window as matching if four of the residues are identical. We then customize the plot by adding a ggplot2 theme to the usual manner and add axis names. Note how the results in Figure 9.14 are different from Figure 9.13:

It then converts the i-th and j-th sequence in seqs object to characters and those in seqi and seqj. It also extracts the names of those sequences as namei and namej. Finally, it creates and returns a dot plot using the variables created. To use the function, we need two things: combinations of sequences to be plotted and a list to hold the results. In step 4, expand.grid() function is used to create a dataframe of all possible combinations of sequences, which we store in the combinations variable. plots created from the vector function contains a list with the right number of slots to hold the resultant. # Reconstructing trees from alignments using phylorn

So in this chapter, we have assumed that trees are already available and ready to use. Of course, there are many ways to make a phylogenetic tree, and in this recipe, we'll look at some of the different methods.

# Getting ready

For this chapter, we'll use abc.fa file of sequences, the Biostrings package, and the CRAN msa and phylorn packages.

# How to do it...

Constructing trees using phylorn can be done like this:

- 1. Load in the libraries and sequences and make an alignment:

```
library(Biostrings)
library(msa)
library(phylorn)

seqfile <- fs::path_package(
  "extdata",
  "abc.fa",
  package="rbioocookbook"
)
seqs <- readAAStringStringSet(seqfile)
aln <- msa::msa(seqs, method="ClustalOmega")
```

- 2. Convert the alignment:

```
aln <- as.phyDat(aln, type = "AA")
```

- 3. Make UPGMA and neighbor-joining trees from a distance matrix:

```
dist_mat <- dist.ml(aln)
upgma_tree <- upgma(dist_mat)
plot(upgma_tree, main="UPGMA")
nj_tree <- NJ(dist_mat)
plot(nj_tree, main="unrooted", NJ="NJ")
```

- 4. Calculate the bootstraps and plot:

```
fit <- pml(nj_tree, aln)
bootstraps <- bootstrap.phyDat(aln, FUN=function(x) { NJ(dist.ml(x)) }, bs=100)
plotBS(nj_tree, bootstraps, p = 10)
```

And with that, we have our plot of a bootstrap tree.

# How it works...

Step 1 carries out loading and makes an amino acid alignment, returning an MAAAlignment object.

Step 2 uses the as.phyDat() function to convert the alignment to a phyDat object that can be used by the phylorn functions.

In step 3, we actually make trees. Trees are made from a distance matrix, which we can compute with dist.ml() and our alignment (this is a maximum-likelihood distance measure; other functions can be used if needed). The dist_mat object is passed to the upgma() and NJ() functions to make trees of those types. These functions return standard phylo objects that can be worked with in many other functions. Here we plot directly, giving output like that of Figure 9.16.

![](img/dd0d7d9aaacf496c4d1d0e31d83783b_280_0.png)

Figure 9.16 – An unrooted neighbor-joining tree

Finally, in step 4, we use the bootstrap.phyDat() function to compute the branches in the tree. The first argument to that is the phyDat object we created and named, aln, and the second argument, FUN, requires either the name of a function that can calculate trees or an anonymous in-line function. Here, we use an anonymous function wrapping the NJ() method we used earlier. The bs argument tells the functions how many bootstraps to compute. Finally, we can plot the resulting bootstrap values onto the tree using the plotBS() function, resulting in what's shown in Figure 9.17:

![](img/dd0d7d9aaacf496c4d1d0e31d83783b_280_1.png)

Figure 9.17 – A rooted neighbor-joining tree with bootstraps
