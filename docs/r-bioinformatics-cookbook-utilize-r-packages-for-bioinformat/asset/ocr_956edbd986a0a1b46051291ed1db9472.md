# How it works...

Although this recipe is long, it is relatively straightforward; all we are doing is setting global and formatspecific options and extracting some pre-prepared files from the support package to assist. In step 1, we base the YAML-less mtcars.qmd file somewhere we can use it on our machine, such as the desktop. We do the same with the bibliography file we need. .bib contains a BibTeX description of reference. In step 2, we add YAML to the top of the document that says the document should be formatted. Those key-value pairs at the top level (for example, title) are applied to all formatted documents we want to render. Most of these are obvious: title sets the title—a level 1 heading by default, date-modified sets to a piece of R code will generate the date dynamically, email-obfuscation chooses a method for scrambling addresses to prevent harvesting by bots, especially on websites, and bibliography.bib sets the path to the references. The HTML-specific options are applied in an indented block under the format and HTML tags. Here, we use values to set the theme from one of the built-ins (cyborg). This is a distinct feature that will be obvious if applied. When we turn on toc table of contents and set it to the left with toc-location, choose options for rendering math, and give an optional external CSS file for custom styles. We also choose options that will affect the rendering of doc. Experiment with these values to learn what they do. In step 3, we go to render the document; this on the command line. The result should be mtcars.html and a supporting folder of images and other files. Look at these in a web browser.

In step 4, we start with PDF formatting our document, first extracting a bioinformatics.csl file that describes references in documents. The code extracts it from the support package and puts it somewhere on your machine. Then, in step 5, we set up the PDF output options, choosing a pdf-engine renderer, some document types, more of contents options, and some specific fonts. These should be clear when you browse the document. The file is specified by the csl key. Note that this text is to the YAML already added, and its indentation should match the HTML block. In step 6, we render the two formats together. Compare the outputs to each other and observe how the format-specific options affect each.

With Word documents, styles are defined by reference .docx file. Again, there is one in the support package, but you can create your own by going into Word and setting styles however you like, then saving the file to a template. In step 7, we copy the package example document somewhere accessible. In step 8, we set some options. The most important is the reference-doc, which gets the path to your style reference. Also important is the citeproc key, which turns on the reference formatter. Finally, in step 9, back at the command line, we render all three formats of the document.
