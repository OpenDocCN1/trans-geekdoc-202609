# How to do it...

The first step is to create the index for Kallisto. It might take 10 minutes to run:

- 1. We do this in the terminal, not in R:

```
kallisto index -i gc38 gc38_transcripts.fa
```

- 2. Run Kallisto on each replicate. We have a short bash command to do that for us – in the terminal, not in R. Again, this can take 10 minutes or so:

```
for sample in 245 428 337 401 257 383
do
  kallisto quant -i gc38 \
  -t 1 -b 42 -o quantifications_${sample} \
  ERR188${sample}_1.fq.gz ERR188${sample}_2.fq.gz
done
```

- 3. Back in R, we can start to use sleuth. As preparation, we need to make a sample condition file mapping:

```
base <- c("245", "428", "337", "401", "257", "383")

s2c <- data.frame(
  sample = paste0("ERR188", base),
  condition = c(rep("F", 3), rep("M", 3)),
  path = paste0("quantifications_", base)
)
```

- 4. Now, set up the sleuth object:

```
library(sleuth)
so <- sleuth_prep(s2c, extra_bootstrap_summary = TRUE)
```

# Estimating differential expression with Kallisto and Sleuth

5. Carry out a fit to the full and a null (reduced) model:

```
so <- sleuth_fit(so, -condition, 'full',
n transformation_function = function(x) log2(x +
0.5))
so <- sleuth_fit(so, -1, 'reduced')
```

6. Carry out tests:

```
so <- sleuth_wt(so, "conditionM")
results <- sleuth_results(so, "conditionM")
```

7. Arrange and examine the results:

```
dplyr::arrange(results, desc(b) )
```

And that is all we need to get results from Kallisto and Sleuth.

# How it works...

In step 1, the bash command creates an index for the kallisto program by the gc38_transcripts.fa as input and saving the index as gc38.

In step 2, the code runs the kallisto quantification command for each of the six replicates specified in the base variable using the previously created index. The quantification results for each replicate output to a directory called quantifications_${sample}, where ${sample} is the specific replicate being run.

In step 3, the R code creates a DataFrame s2c that maps the samples to the conditions they belong to. The base variable is used to create the sample column, and the condition column is created by repeating F for the first three samples and M for the last three. The path column is created by concatenating quantifications_ elements of the variable.

In step 4, the code loads the sleuth library and creates a sleuth object called so using the s2c DataFrame while using the extra_bootstrap_summary_option to TRUE. This so is a container for all of the data and information necessary for running differential expression using the sleuth package. It includes information about the samples, conditions, and quantification results, as well as any models and tests that have been run. The extra_bootstrap_summary_option provides additional information about the bootstrap samples, which can be useful for interpreting results.

In step 5, the code fits so to a full model, which is specified as -condition, and a null (reduced) model, which is specified as -1. The full model is also using a transformation function that takes log2 of the input plus 0.5. The full model design in this case is ~condition, which means the effects of the condition variable will be included in the model. The null or reduced model is specified as ~1, which means that no variables are included in the model. The transformation function is used to normalize the data before the analysis.

sleuth, the full model is typically used to test for the effects of specific variables of interest, such as the condition variable in this case. The null or reduced model is used as a baseline for comparison and whether there is any significant difference in expression between the samples. The transformation function is used to account for the technical variability in the data and thus the results of the analysis are more robust.

In step 6, the code carries tests on the conditionLevel and creates a new object called results that contains the results of the tests. The test that carried out is a Wald Test, a statistical test that used to test the null hypothesis that the parameters of a linear model are equal to zero – in other words, the test checks if there is any significant difference in expression between conditionM and the other condition. The Wald Test is based on the ratio of the estimated parameter to its standard error. In step 7, the R code uses dplyr to arrange the rows based on b.

# Using Sleuth to analyze time course

One aspect that makes timecourse experiments more difficult is the filter function in sleuth_prep(). In a simple comparison, the filter function is relatively straightforward. However, in timecourse experiment, there are multiple conditions and timepoints, and genes in one sample could easily be absent from others, which means the filter function must be applied separately to condition. This can make the filtering process more time-consuming. To overcome this, the filter function in sleuth_prep() can be overridden with a custom function tailored to specific needs.

# How to do it...

Let's create the function that will allow us to work on a multi-factor experiment:

```
custom_filter <- function(design,
row,
min_reads = 5,
min_prop = 0.47) {
sum(apply(design, 2, function(x) {
  y <- as.factor(x)
  return(max(apply(row, y, function(f) {
    sum(f >= min_reads)
  }) / tapply(row, y, length)) == 1
|| basic_filter(row, min_reads, min_prop)
})) > 0
}
```

```

filter_fun=function(x) {custom_
filter(so$design,x))
```
