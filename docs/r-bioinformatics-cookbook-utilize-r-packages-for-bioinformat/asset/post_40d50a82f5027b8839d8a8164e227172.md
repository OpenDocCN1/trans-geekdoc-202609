
# Getting ready

We'll need a sample R Markdown document provided by the rbioinfcookbook package, so install the fs package, and the ggplot2 package, if you haven't got it already. You'll also need to follow the instructions for installing Quarto at the start of the chapter. Make sure you also have installed TinyTeX, which is needed by Quarto, also discussed at the start of the chapter.

# How to do it...

We can prep a marked-up document for rendering to various formats as follows:

- Save the example file accessible:

```
qmd_path <- fs::path_package("extdata", "mtcars.qmd",
package=rbioinfcookbook)
file.copy(qmd_path, 'somewhere/on/your/system/mtcars.qmd')

bib_path <- fs::path_package("extdata", "mtcars.bib",
package=rbioinfcookbook)
file.copy(bib_path, 'somewhere/on/your/system/mtcars.bib')
```

- In your editor, add a YAML header for HTML:

```yaml
---
title: "mtcars Analysis"
subtitle: "an analysis in many formats"
author: "anrwizard@email.com"
date-modified: "%format(Sys.time(), '%d %B, %Y')"
email-obfuscation: javascript
bibliography: mtcars.bib
execute:
  echo: true
  warning: false
format:
  html:
    theme: cyborg
    toc: true
    toc-location: left
    html-math-method: katex
    css: styles.css
    number-sections: true
    cap-location: top
    code-fold: true
    code-line-numbers: true
    citations-hover: false
---
```

- 3. Run that on the command line:

```
quarto render mtcars.qmd --to html
```

- 4. Get a Citation Style Language (CSL) file to determine how references will be formatted:

```
csl_path <- fs::path_package("extdata", "bioinformatics.csl",
package="rbioinfcookbook")
file.copy(csl_path, 'somewhere/on/your/system/bioinformatics.csl')
```

- 5. Extend the YAML to include a PDF block; note—add the existing HTML code:

```yaml
pdf:
  pdf-engine: xelatex
  papersize: A4
  class: report
  toc: true
  toc-title: "Workflow"
lof: true
  mainfont: Arial
  monofont: Courier
  fontsize: "24"
  colorlinks: true
  cap-location: margin
  csl: bioinformatics.csl
```

- 6. Render the document:

```
quarto render mtcars.qmd --to html,pdf
```

- 7. Get a Microsoft Word .docx file to act as a style template for the Microsoft Word doc:

```
docx <- fs::path_package("extdata", "custom-reference-doc.docx",
package="rbioinfcookbook")
file.copy(docx_path, 'somewhere/on/your/system/custom-reference-doc.docx')
```

- 8. Extend the YAML for .docx output:

```yaml
docx:
  reference-doc: custom-reference-doc.docx
  fig-align: center
  fig-width: 20
  number-sections: true
  citeproc: true
```

- 9. Do the final render:

```
quarto render mtcars.qmd --to html,pdf,docx
```

This will give us output files in html, pdf, and docx from input.

# How it works...

Although this recipe is long, it is relatively straightforward; all we are doing is setting global formats and extracting some pre-prepared files from the support package to assist. In step 1, we use the mtcars.qmd file somewhere accessible on our machine. We do the same with the bibliography file .bib, which sets the path to the references. The HTML-specific options are applied under the format HTML. Here, we use values to set the theme from one of the built-ins (cyborg). This is a distinct feature that will be applied when we turn on table of contents and set it to the left with toc-location, options for rendering math, and give an optional CSS file for custom styles. Experiment with these values to learn what they do. In step 3, we go to the command line to render the document; result should be mtcars.html and other files.

In step 4, we start with PDF formatting our document, first extracting the bioinformatics.csl file that describes references and puts it somewhere on your machine. In step 5, we set up the PDF output options, choosing pdf-engine, some document types, more contents options, and some specific fonts. These should be clear when you browse the document. Note that the csl key is already added to the YAML and its indentation should match the HTML block. In step 6, we render the two formats together. Compare the outputs to observe how the format-specific options affect each.

With Word documents, styles are defined by .docx file. Again, there is one in support package but you can create your own by going into Word and setting styles however like, then saving the file to a template. In step 7, we copy the example document. In step 8, we set some options. The most important is reference-doc, which gets the path to your style reference. Also important is the citeproc key, which turns on the reference formatter. Finally, in step 9, back at the command line, we render all three formats of the document.

# Creating data-rich presentations from code

Presenting data to audiences of other scientists is a key task; it is vital for us to be able to understand and discuss our results and methods. Creating slides that assist our presentations is usually a manual task that requires the insertion of figures and methods into documents and is one that can consume a lot of researcher's time. Microsoft PowerPoint is one of the commonly used presentation tools. It is a user-friendly GUI program and provides a wide variety of templates, animations, transitions, and multimedia features. However, it requires a lot of manual effort. Beamer is a LaTeX-based presentation system used for academic and scientific presentations. It is a powerful tool and especially useful for presentations with mathematical equations, formulas, and algorithms. However, Beamer requires some knowledge of LaTeX, which can make it less accessible. Reveal.js is an open source, web-based presentation system that uses HTML, CSS, and JavaScript, designed to be highly customizable and for interactive presentations. Reveal.js requires a good level of understanding of its underlying technologies.

The great advantage of using Quarto with an R Markdown document is that our presentations can become self-updating when the data changes. In this recipe, we'll look at how to format a Markdown document containing R code so that we can render it as a presentation in the four formats mentioned.

# Getting ready

We'll need the rbioinfookbook package and the fs package for our template files. We'll also need to have pre-installed Quarto, as described at the start of the chapter, and the ggplot2 packages for the pages themselves to run.

# How to do it...

Setting up a Markdown document for eventual rendering as a presentation might go like this:

- 1. Set up the first slide as a second-level heading:

## Method

::: {.incremental}

- Exploratory plot
- Statistical modelling

:::

- 2. Set up the second slide to render a plot but not code:

## Relationship between cylinder count and Miles Per Gallon

```{r, point1, echo=FALSE}
```r
library(ggplot2)

p <- ggplot(mtcars) +
aes(cyl, mpg) +
geom_point() +
geom_smooth(method = "lm")

p
```
```

- Set up a third slide with code and result, two-column layout, and presenter notes:

```markdown
## Linear Modelling

::: {.columns}
::: {.column width="35%"}
```{r, point2, echo=FALSE}
p
```
```

::: {.column width="65%"}
```{r, point2_model}
lmp(mpg - cyl, data=mtcars)
```
```
:::

::: {.notes} Discuss the negative slope... :::
```

- Set up the header to render a title slide and select formats:

```yaml
---
title: "Motor Cars"
author: "AN Rwizard"
format:
  pptx:
    incremental: true
    reference-doc: reference_presentation.pptx
  revealjs:
    incremental: true
    theme: blood
---
```
