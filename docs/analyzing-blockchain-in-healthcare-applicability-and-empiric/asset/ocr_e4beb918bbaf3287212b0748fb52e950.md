Each transaction includes a public key that may be used to validate the content of the transaction, thereby allowing for the detection of tampering. The blockchain’s security relies on hash functions. Blocks can be identified by their unique identities thanks to them. Even if the internal verifying nodes do not engage in collusion attacks, the private network’s integrity cannot be guaranteed. Furthermore, the private chain is unable to guarantee anonymity due to the possibility that select nodes inside it could identify users.

Changes to the chain can be tracked thanks to these unique block identifiers. The entire network of nodes verifies each block and transaction, ensuring the integrity of the data kept in the blockchain. To ensure data integrity, nodes must be able to detect and reject transactions and blocks that contain data alterations. # Unforgeability

Unforgeability of blockchain ensures that an adversary cannot pose as the user may corrupt the network. To this end, unforgeability in blockchain inherent from the data integrity combined with digitally signed transactions was adopted and employed in several works.

# Traceability

From an audit standpoint, traceability is one of the most interesting qualities. Using the chain of blocks, you can go back in time and evaluate the transactions made on a certain date by exploring all the blocks that were generated on that date in the chain of blocks. To audit query operations, you would need to query the blockchain, which doesn’t save them. Because this query has not been registered in the chain, each node answers the information request delivered to it. Consequently, it is impossible to know all the requests made in all the nodes of a given system. The blockchain serves as a central repository for all of these consolidated transactions. The number of nodes that make up the blockchain network store the complete chain, which is constantly expanding in size.
