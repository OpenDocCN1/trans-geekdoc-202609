### 3.1.2 Local Training and Model Updates

Each institution performs local training using stochastic gradient descent (SGD):

```
\(\theta_t^{t+1} = \theta_t^t - \eta \nabla L_i(\theta_t^t)\)
```

where \(\eta\) is the learning rate and \(\nabla L_i(\theta_t^t)\) is the local gradient at iteration \(t\).

After \(E\) local epochs, the update difference is:

```
\(\Delta\theta_t = \theta_t^{t+E} - \theta_t^t\)
```

### 3.1.3 Privacy Preservation via Homomorphic Encryption

To protect gradients during transmission, we apply an additive homomorphic encryption \(E(\cdot)\), which satisfies:

```
\(E(a) \oplus E(b) = E(a + b)\)
```

Encrypted local updates are:

```
\(\Delta\tilde{\theta}_i = E(\Delta\theta_i)\)
```

These encrypted updates are sent to the blockchain network.

### 3.1.4 Secure Aggregation of Encrypted Updates

Blockchain nodes aggregate encrypted updates weighted by dataset sizes:

```
\(\Delta\theta^- = \sum_{i=1}^N \frac{m_i}{M} \Delta\tilde{\theta}_i\)
```

Authorized parties decrypt the aggregated update:

```
\(\Delta\theta = D(\Delta\theta^-)\)
```

where \(D(\cdot)\) is the decryption function.

Global model update:

```
\(\theta^{t+1} = \theta^t + \Delta\theta\)
```

### 3.1.5 Differential Privacy

To prevent inference attacks, Gaussian noise is added locally to gradients:

$$\nabla^-_i = \nabla L_i(\theta_i) + N(0, \sigma^2 I)$$ (11)

where \( N(0, \sigma^2 I) \) is zero-mean Gaussian noise with variance \(\sigma^2\), ensuring \((\epsilon, \delta)\)-differential privacy guarantees.

## 3.2 Blockchain Network for Secure Coordination

### 3.2.1 Permissioned Blockchain Architecture

Each block \( B_t \) contains:

- Previous block hash \( H(B_{t-1}) \)
- Transactions \(\{ T_i \}\) (encrypted updates, access requests)
- Timestamp TS\(_t\)
- Hash of global model \( H(\theta^t) \)
- Digital signatures \(\sigma_t\)

### 3.2.2 Consensus Algorithm: Practical Byzantine Fault Tolerance (PBFT)

PBFT tolerates up to \( f \) faulty nodes in \( 3f + 1 \) total nodes. Consensus phases:

- **Pre-prepare**: Primary proposes block,
- **Prepare**: Nodes verify and broadcast,
- **Commit**: Nodes commit when \( 2f + 1 \) confirmations received.

This ensures finality and low latency.

### 3.2.3 Smart Contract-Based Access Control

Smart contract function:

$$SC(d_u, R, A) \rightarrow \{Grant, Deny\}$$ (12)

where \( d_u \) is user DID, \( R \) is resource, and \( A \) is requested action. Access rules encoded to enforce fine-grained, auditable permissions.

## 3.3 Identity and Access Management

### 3.3.1 Decentralized Identity (DID)

Each user has a cryptographic identifier:

$d_u = \text{DID}(u)$ 
(13)

linked to verifiable credentials certifying their role and privileges.

### 3.3.2 Auditable Data Access Logs

All data access events recorded on-chain:

$L = \{d_u, R, A, t, H(D_R)\}$ 
(14)

with $d_u$: user ID, $R$: resource, $A$: action, $t$: timestamp, $H(D_R)$: hash of accessed data.

## 4 Experimental Results

A virtual six-institutional healthcare environment with 200 patient records in each institution, totaling 1,200 records of the publicly available Pima Indians Diabetes Database (PIDD) was used to evaluate the proposed MediChain-FL system. Python 3.8 was used to set up the simulation environment on a PC with Ubuntu 20.04, equipped with an Intel Core i7 CPU and 32 GB of RAM. Permissioned blockchain was emulated with Hyperledger Fabric v2.3, whereas PySyft with homomorphic encryption capability was employed to create the FL framework. Centralized ML models that were trained on pooled data and centralized FL models that were not integrated with blockchain were instantiated to act as baselines for the system.

## 5 Conclusion

The study presents MediChain-FL, an innovative architecture for healthcare data sharing that integrates blockchain technology and federated learning to address significant privacy, security, and efficiency challenges. The proposed system had outstanding performance with 93.2% accuracy in predicting early-stage diabetes, a remarkable 91.7% reduction in the risk of data loss, and an acceptable blockchain consensus latency of less than 1.3 s based on rigorous testing with 1,200 patient records from multiple institutions. MediChain-FL preserved low-latency operations and low-cost transactions while realizing significant improvements in prediction accuracy and privacy preservation compared to traditional centralized and baseline federated learning models. The results prove that combining immutable blockchain ledgers with decentralized training of models makes it possible to provide secure, private, and scalable healthcare analytics and adhere to rigorous data locality and legal constraints.
