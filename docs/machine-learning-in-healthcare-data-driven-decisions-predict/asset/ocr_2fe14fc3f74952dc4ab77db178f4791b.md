# 5.3.1 Model Training and Evaluation

As a sequel to the feature extraction and algorithm selection steps outlined above, model training and evaluation is the subsequent next vital step in the stress detection pipeline. In this step, ML models are trained on the formatted datasets, like the one used in Section 5.2.2, which comprises multimodal physiological and behavioral features like HR, respiration rate, oxygenation levels, snoring range, and sleep length. These attributes are predictors of the stress level classification, the target variable [20,21].

Data Preparation and Preprocessing: Raw data is subject to necessary preprocessing steps before training, such as:

Data Cleaning: Missing value handling, outlier detection, and correction. Normalization/standardization: Bringing all features to a comparable scale, particularly for SVM and KNN algorithms.

Encoding Categorical Features: While there are many numeric variables in this dataset, some datasets could contain categorical context features (such as gender, type of activity) that need to be one hot encoded or label encoded.

Feature Selection or Dimensionality Reduction: Methods such as Recursive Feature Elimination (RFE) or Principal Component Analysis (PCA) can enhance model efficiency and help prevent overfitting.

Model Training Process: Every ML model (as defined in Section 5.3.1) is trained under a supervised learning scheme, with labeled instances (i.e., instances with known levels of stress) utilized in order for the model to learn associations and relationships between input features.

The data set would normally be divided into:

+   Training set (60–80%) – for training the model.

+   Validation set (10–20%) – for hyperparameter fine-tuning.

+   Test set (10–20%) – Utilized to test model performance on unknown data.

Higher level methods like k-fold cross-validation (frequently 5- or 10-fold) are frequently employed to guarantee that the model's performance is not only limited to a particular data split. Cross-validation enhances generalizability and minimizes the possibility of overfitting.
