# 3.3 Identity and Access Management

# 3.3.1 Decentralized Identity (DID)

Each user has a cryptographic identifier:

$d_u = \text{DID}(u)$ 
(13)

linked to verifiable credentials certifying their role and privileges.

# 3.3.2 Auditable Data Access Logs

All data access events recorded on-chain:

$L = \{d_u, R, A, t, H(D_R)\}$ 
(14)

with $d_u$: user ID, $R$: resource, $A$: action, $t$: timestamp, $H(D_R)$: hash of accessed data.

# Table 1: System workflow.

| Step | Description |
| :--- | :--- |
| 1 | Initialization: Broadcast initial global model $\theta^0$ |
| 2 | Local training at each institution to compute $\Delta\theta_i$ |
| 3 | Encrypt local updates $\Delta\theta_i^{\sim}$ using homomorphic encryption |
| 4 | Submit encrypted updates as blockchain transactions |
| 5 | PBFT consensus validates transactions |
| 6 | Homomorphic aggregation of encrypted updates |
| 7 | Decrypt aggregated update and update global model |
| 8 | User requests access controlled by smart contracts |
| 9 | All data access events logged on blockchain |
