```
w_{t+1} \rightarrow \{w_{t+1}^1, w_{t+1}^2, \dots, w_{t+1}^K\} (7)
```

Each client receives the latest model to begin a new local training round. The FL cycle continues over multiple communication rounds. In each round, clients retrain the model with fresh updates from the server, and the server refines the global model using new encrypted contributions. This iterative process is repeated until the model reaches a desired level of performance or converges according to predefined criteria, such as minimal changes in validation accuracy or loss. This formulation supports various enhancements such as differential privacy, client clustering etc.

**Differential Privacy (DP):** Differential privacy is integrated into the FL process to protect individual patient records from being inferred through model updates. Before transmitting updates to the server, each client injects calibrated random noise into its model parameters or gradients. Information leakage is minimized by this noise, which is derived from a probability distribution and ensures that the contribution of any one data point is unidentifiable in the final output [22]. A privacy budget, which measures the amount of information about a particular data point might be revealed, regulates the degree of privacy. Stronger privacy assurances are offered by smaller models, but they may also decrease model utility, necessitating careful trade-off adjustment. Let \(\Delta w_t^k\) be the model update form client k at round t. DP is enforced by adding Gaussian noise:

```
\(\hat{w}_t^k = \Delta w_t^k + N(0, \sigma^2 I)\) (8)
```

where \(N(0, \sigma^2 I)\) is Gaussian noise with standard deviation \(\sigma\) calibrated based on the desired privacy budget (\(\epsilon\), \(\delta\)) differential privacy.

**Secure Multiparty Computation (SMPC):** To further strengthen security against reconstruction or inference attacks, SMPC [23] is employed during model update sharing. Multiple parties can jointly compute a function over their inputs while maintaining the privacy of those inputs thanks to SMPC. To ensure that no one entity has access to the entire update, each client in the federated setup divides its model update into secret shares and distributes them around various parties or the server. Only when the shares are combined during aggregation can the server reconstruct the sum of updates without learning any individual contribution. This approach eliminates the need to trust the server with sensitive updates and protects against insider and collusion threats. Let \(\Delta w_t^k\) be the model update vector from client k.
```
\(\Delta w_t^k = s_1^k + s_2^k + \dots + s_M^k\) (9)
```
