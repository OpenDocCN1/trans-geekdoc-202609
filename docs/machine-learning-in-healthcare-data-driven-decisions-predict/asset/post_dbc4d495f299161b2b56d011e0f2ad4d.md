
## 5.3.1 Model Training and Evaluation

As a sequel to the feature extraction and algorithm selection steps outlined above, model training and evaluation is the subsequent next vital step in the stress detection pipeline. In this step, ML models are trained on the formatted datasets, like the one used in Section 5.2.2, which comprises multimodal physiological and behavioral features like HR, respiration rate, oxygenation levels, snoring range, and sleep length. These attributes are predictors of the stress level classification, the target variable [20,21].

**Data Preparation and Preprocessing:** Raw data is subject to necessary preprocessing steps before training, such as:

- Data Cleaning: Missing value handling, outlier detection, and correction.
- Normalization/standardization: Bringing all features to a comparable scale, particularly for SVM and KNN algorithms.
- Encoding Categorical Features: While there are many numeric variables in this dataset, some datasets could contain categorical context features (such as gender, type of activity) that need to be one-hot encoded or label encoded.
- Feature Selection or Dimensionality Reduction: Methods such as Recursive Feature Elimination (RFE) or Principal Component Analysis (PCA) can enhance model efficiency and help prevent overfitting.

**Model Training Process:** Every ML model (as defined in Section 5.3.1) is trained under a supervised learning scheme, with labeled instances (i.e., instances with known levels of stress) utilized in order for the model to learn associations and relationships between input features.

The data set would normally be divided into:

- Training set (60–80%) – for training the model.
- Validation set (10–20%) – for hyperparameter fine-tuning.
- Test set (10–20%) – Utilized to test model performance on unknown data.

Higher level methods like k-fold cross-validation (frequently 5- or 10-fold) are frequently employed to guarantee that the model's performance is not only limited to a particular data split. Cross-validation enhances generalizability and minimizes the possibility of overfitting.

**Performance Evaluation Metrics:** In order to calculate how good and reliable a model is, various metrics are applied, particularly in multi-class classification problems such as predicting stress level (0 to 4). The most widely applied metrics as shown in Table 9 are:

- Accuracy – The ratio of correct predictions to total predictions.
- Precision – The ratio of accurate positive predictions to all predicted positives for a given class. Shows how well the model can prevent false positives [21].
- Recall (Sensitivity) – The ratio of the true positives to the actual positives. Indicates the capacity of the model to capture all instances that are relevant.
- F1-score – The harmonic mean of precision and recall. Particularly valuable with imbalanced datasets where certain stress levels can be underrepresented.
- Confusion Matrix – A tabular representation that shows the correct and incorrect predictions made by the classifier, broken down by class. It helps to identify specific areas of weakness, such as confusion between stress levels 2 and 3.

As an example, in a five-class stress detection problem (0–4), the matrix can tell us if the model tends to mix up “moderate” stress (level 2) with “high” stress (level 3), which may need feature tuning or class balancing. **Statistical Validation:** In addition to simple metrics, statistical tests such as the paired t-test or Wilcoxon signed rank test are utilized to test model comparison. These tests verify if performance differences (e.g., between RF and GB) are statistically significant or due to random chance.

**Paired t test:** Utilized in comparing the performance of two models on the same dataset splits. ANOVA or Kruskal-Wallis test: Utilized for comparing more than two groups or models. These statistical techniques improve the credibility of findings and assist in model choice justification [22].
