# 5.4.1 Classification

Based on the behaviors of the intruders, intrusion detection is classified into (i) network-based intrusion detection system (NIDS) and (ii) host-based intrusion detection system (HIDS) [15]. These IPSs closely monitor the network traffic and take automatic actions to protect networks and systems. Network traffic flow analysis is done by using misuse “detection, anomaly detection and stateful protocol analysis.”

NIDS monitors networks using network equipment like routers, switches, and network taps—via mirroring by networking devices—and analyzes traffic to identify attacks and potential threats hidden within network traffic. In contrast, HIDS detects attacks by using system activities in the form of various log files running on the local host computer, where the host system’s logging and other information are used for the analysis (host-based handler is referred to as a sensor). Host-based sensors can obtain data from other sources that include system logs and other logs prompted by “operating system processes and contents of objects not reflected in standard operating system audit and logging mechanisms. NIDS inspects each packet contents in network traffic flows, HIDS relies on the information of log files which includes sensors logs, system logs, software logs, file systems, disk resources, users account information and others of each system” [16].

# 5.5 Methodologies of Detection

An IDS is one of the most significant parts of network architecture. Based on the nature of data processed, IDS can be categorized into misuse detection and anomaly detection. Misuse detection deals with known patterns establishing a signature database that detects only known attacks, whereas anomaly detection establishes a “normal behaviour baseline model” and tries to detect any new behavior that deviates from this baseline model [17].
