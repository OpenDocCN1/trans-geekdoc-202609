
## 6.3 Dataset Properties

For facilitating direct comparison between intrusion detection datasets, to aid researchers in choosing appropriate datasets for specific evaluation needs, it is essential to establish common properties as a foundation for assessment. In this regard, key dataset characteristics are frequently referenced in the literature to evaluate intrusion detection datasets. The FAIR principles [8] provide a general framework for scholarly data, emphasizing four key attributes: findability, accessibility, interoperability, and reusability.

### 6.3.1 Basic Information

The following four properties represent general details about the dataset, including its availability, year of creation, and the inclusion of both malicious and normal network traffic.

- 1) **Year of Creation:** The relevance of an intrusion detection dataset depends significantly on its age, as network traffic evolves over time and new attack scenarios emerge on a daily basis. This property indicates the year the dataset’s underlying network traffic was captured, which is often more critical for assessing its relevance than the year of publication.
- 2) **Public Availability:** For effective comparison of different intrusion detection methods, datasets should be publicly accessible. Public availability also ensures that third parties can independently verify the dataset’s quality. This property is classified into three categories: “yes” (freely available), “on request” (on request, requiring a message to the authors or responsible parties), and “no” (not publicly accessible).
- 3) **Normal Traffic:** This attribute determines whether a dataset contains regular user activity, classified as either “yes” or “no.” A “yes” value confirms the presence of normal user behavior but does not specify if attack data is included. The effectiveness of an IDS relies on distinguishing between normal and malicious activities, making the inclusion of typical user behavior crucial for evaluating detection accuracy and false alarm rates. However, datasets without normal traffic can still be utilized by merging them with other datasets or integrating real-world network data through techniques like overlaying or salting [9, 10].
- 4) **Attack Traffic:** Intrusion detection datasets should encompass a variety of attack scenarios. This property specifies whether malicious network traffic is included and is marked as “yes” if at least one attack is present in the dataset.

### 6.3.2 Nature of Data

This category outlines the characteristics of dataset formats and the inclusion of metadata.

- 1. **Metadata:** Understanding packet-based or flow-based network traffic can be difficult for external analysts. To enhance clarity, datasets should include metadata that provides contextual details about elements such as network topology, IP addresses, and attack scenarios. This attribute indicates whether a dataset contains such additional descriptive information to support analysis.
- 2. **Format:** Intrusion detection datasets come in different formats, generally classified into three main types. Flow-based traffic (e.g., NetFlow) retains only metadata related to network connections. Packet-based traffic (e.g., PCAP) captures network activity along with payload details. Additionally, some datasets combine flow-based data with attributes derived from packet-level traffic or host-based log files to provide enhanced insights.
- 3. **Anonymity:** Due to privacy concerns, intrusion detection datasets are often not publicly released or may be provided in an anonymized format. This attribute specifies whether data anonymization has been applied and which elements are affected. A value of “none” indicates that no anonymization is present, while “yes (IPs)” means IP addresses have been altered or removed. Similarly, “yes (payload)” signifies that payload information has been obscured or excluded from packet-based traffic to protect sensitive data.

### 6.3.3 Data Volume

This category defines datasets based on their size and the time span they cover.

- 1. **Count:** This property represents the size of the dataset, which can be expressed as its physical size in gigabytes (GB) or as the number of flows, packets, or data points it contains.
- 2. **Duration:** To capture periodic patterns, such as differences between daytime and nighttime or weekdays and weekends [11], datasets should span a significant time frame. The duration property specifies the time period over which the network traffic was recorded.

### 6.3.4 Recording Environment

This section defines the network environments and circumstances in which datasets are obtained.

- 1. **Kind of Traffic:** This property specifies the origin of the network traffic, categorized as real, emulated, or synthetic. “Real” traffic is collected from an operational, live network environment. “Emulated” traffic refers to real activity captured within a controlled test bed or simulated network setup. “Synthetic” traffic is artificially generated using tools like traffic generators and is not derived from virtual or actual network devices.
- 2) **Type of Network:** Network environments differ significantly between contexts, such as small or medium-sized businesses vs. internet service providers (ISPs). Since these environments require distinct security measures, evaluation datasets should align with the specific type of network. This property identifies the network environment in which the dataset was generated.
- 3) **Complete Network:** This property indicates whether the dataset includes comprehensive network traffic from an environment with multiple devices, such as hosts and routers. If the dataset only covers traffic from a single host (e.g., a honeypot) or focuses on specific protocols (e.g., SSH traffic only), it is labeled as “no.”

### 6.3.5 Evaluation

This category includes properties that pertain to evaluating intrusion detection methods using network-based datasets. Specifically, these properties address the availability of predefined subsets, dataset balance, and labeling.

- 1) **Predefined Splits:** Comparing the performance of different IDSs can be challenging, even when the same dataset is used. This is due to the uncertainty of whether the same subsets are used for both training and testing. This attribute specifies whether a dataset provides predefined divisions for training and evaluation.
- 2) **Balanced:** Many anomaly-based intrusion detection methods rely on machine learning (ML) or data mining techniques. During training, datasets need to be balanced in terms of class labels, with equal representation of normal and attack data points. However, real-world network traffic is typically imbalanced, with significantly more normal activity than attack traffic. This property specifies whether a dataset is balanced. If not, preprocessing is necessary to balance the dataset before applying ML algorithms. He and Garcia [12] offer a comprehensive overview of learning from imbalanced data.
- 3) **Labeled Data:** Labeled datasets play a crucial role in training supervised models and assessing the performance of both supervised and unsupervised IDSs. This attribute specifies whether a dataset includes labels and the type of labeling provided. Possible classifications include: “Yes” where the dataset contains at least two categories (attack and normal); “Yes, with BG (background),” which introduces another class representing data that could be either normal or malicious; “Yes (IDS),” where labels are assigned based on an IDS, though potential inaccuracies may arise due to system limitations; “Indirect,” indicating that while the dataset lacks explicit labels, they can be inferred from supplementary log files; and “No,” meaning the dataset is entirely unlabeled.

No single dataset is entirely perfect for all purposes. A careful balance must be achieved between key qualities of datasets, such as diversity, accuracy, and relevance. To create a dataset for intrusion detection, data from various sources can be aggregated, including network traffic flows that provide details about hosts, user behavior, and system configurations [3]. The collection of this data is essential for identifying malicious patterns and unexpected behaviors associated with different network threats. Routers or switches are used to document network operations, and network flow analysis is employed to examine the network traffic following the capture of incoming and outgoing data. Flow analysis involves the systematic study of network packet data.

This chapter aims to provide an in-depth examination of publicly available datasets that are aligned with the specific parameters and objectives of research. These datasets, made accessible to researchers, analysts, and the wider community, serve as essential resources for various types of investigations and analyses.

## 6.4 Datasets

### 6.4.1 DARPA

This data was first made available in February 1998. The DARPA 1998 dataset [13], created with support from DARPA and the Air Force Research Laboratory (AFRL), was one of the first large-scale, standardized collections of data used for evaluating IDSs. The dataset was designed to provide both training and testing data for intrusion detection, collected from a controlled network environment over several weeks. It contains both normal and attack traffic captured in tcpdump format, including the full payload of each packet, alongside system audit logs from Solaris and Windows NT platforms. The data collection was carefully structured, with weeks one and three of the training phase containing normal traffic and week two containing labeled attack data. The testing phase consists of weeks four and five, where the IDSs were evaluated on their ability to detect both normal and attack traffic. The training data, generated approximately four gigabytes of compressed binary TCP dump files, which were later processed into around five million connection records. Likewise, the test data produced nearly two million connection records. Each connection, representing a sequence of TCP packets exchanged between a source and destination IP within a specific protocol, was classified as either “normal” or belonging to one of several attack categories.
