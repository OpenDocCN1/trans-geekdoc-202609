On the other hand, UDP operates as a connectionless protocol with a simpler header containing only four fields: checksum, source port, length, and destination port. In contrast to UDP and TCP, ICMP functions as a support protocol designed for delivering status messages and features an even smaller header. Additionally, packets generally include an IP header, which holds critical information such as the destination and source IP addresses.

# 6.2.2 Flow-Based Data

Flow-based network data provides a condensed representation by primarily storing metadata related to network connections. It groups together packets with common characteristics within a specified time frame, forming a single flow while usually omitting payload details. The standard five-tuple definition includes transport protocol, destination IP address, source port, source IP address, and destination port [3] that are commonly used to group packets into flows. Flows can be represented in bidirectional or unidirectional formats. In the unidirectional format, packets moving from host A to host B with the same attributes are grouped into a single flow, while packets traveling in the opposite direction (from host B to host A) are recorded as a separate flow. In contrast, bidirectional flows merge all packets exchanged between hosts A and B, regardless of their transmission direction. Common flow-based formats include OpenFlow [4], sFlow [5], IPFIX [3], and NetFlow [6]. Common characteristics of flow-based network traffic may consist of metrics such as bytes per second, bytes per packet, TCP flags from the initial packet, or computed payload entropy, depending on the flow format and exporter. While packet-based data can be transformed into flow-based data using tools like YAF3 or nfdump2, the opposite conversion is not feasible.

# 6.2.3 Other Data

This category includes datasets that do not strictly belong to either packet-based or flow-based formats. Instead, they may integrate flow-based data enriched with packet-level details or information from host-based log files. A well-known example is the KDD Cup 1999 dataset [7], which merges network-related attributes such as the number of transmitted source bytes or TCP flags with host-based features, like the frequency of failed login attempts. Due to the unique nature of each dataset in this category, they have their own specific set of attributes. Consequently, each dataset requires individual analysis, and no generalizations can be made about the available attributes across this category.
