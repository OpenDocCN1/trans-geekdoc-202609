
- **Poisoning Attacks:** Adversaries inject malicious samples into IDS training datasets, corrupting the learning process and reducing model accuracy.
- **Adversarial Example Crafting:** Attackers use algorithms (e.g., the fast gradient sign method [FGSM] and the Carlini & Wagner [C&W] attack) to generate malicious traffic patterns that evade detection.
- **Traffic Obfuscation:** Attackers modify payloads, headers, and packet sequences to mimic legitimate traffic and avoid IDS detection.

### 11.6.1.2 Defensive Measures: Adversarial Training and Robust IDS Models

To counter adversarial attacks, IDS models need to be hardened using defensive mechanisms, such as the following:

- **Adversarial Training:** Enhancing IDS robustness by training on adversarially generated network traffic samples.
- **Defensive Distillation:** Smoothing the model's decision boundary to reduce susceptibility to adversarial perturbations.
- **GANs for IDS Defense:** Using GANs to simulate sophisticated attacks and train IDS models to recognize them.
- **Robust Feature Selection:** Identifying network traffic features that are less sensitive to adversarial perturbations.
- Developing an adversarial-resilient IDS remains an open research challenge, requiring continuous improvements in AI security.

## 11.6.2 Computational Overhead and Energy Efficiency

DL models require significant computational resources, making it challenging to deploy IDSs on resource-constrained devices such as IoT nodes and edge servers.

### 11.6.2.1 Issues in Deploying Deep Learning Models on Resource-Constrained Devices

- **High Memory and Processing Requirements:** Many IDS models require GPUs or TPUs for real-time processing, making deployment on IoT or embedded systems impractical [35].
- **Battery and Energy Constraints:** Wireless devices have limited power, making continuous DL-based IDS monitoring infeasible.
- **Network Bandwidth Limitations:** Processing high volumes of network traffic in real time is computationally expensive and can introduce latency issues.

### 11.6.2.2 Optimization Techniques: Model Pruning, Quantization, and Knowledge Distillation

To address these constraints, researchers are exploring model optimization techniques for lightweight IDS as follows:

- **Model Pruning:** Removing unnecessary neurons and layers to reduce computational costs without sacrificing performance.
- **Quantization:** Reducing precision in neural network weights (e.g., from 32-bit floating-point to 8-bit integers) to lower memory requirements.
- **Knowledge Distillation:** Training a lightweight IDS model using knowledge transferred from a larger, complex model, improving efficiency while retaining accuracy.

The future of IDS research should focus on low-power, energy-efficient DL architectures suitable for real-time security in IoT, edge, and mobile networks.

## 11.6.3 Real-Time Deployment Challenges

Real-time intrusion detection requires high-speed data processing and instantaneous threat mitigation. However, DL-based IDSs often struggle with scalability and latency in real-world applications.

## 11.6.4 Issues with Processing High-Speed Network Traffic

- **High-Dimensional Feature Space:** IDS models trained on large datasets require real-time processing of millions of network packets per second, leading to performance bottlenecks.
- **Latency Concerns in Time-Sensitive Networks:** Real-time IDSs should detect attacks within milliseconds, which is challenging for DL models with high computational requirements.
- **Encrypted Traffic Inspection:** The increasing use of encryption (e.g., TLS 1.3, VPNs) makes it difficult for IDSs to inspect payloads, reducing visibility into network anomalies.

### 11.6.4.1 Combining Deep Learning with Rule-Based and Hybrid IDSs

A promising solution is a hybrid IDS [36], which combines the following:

- Rule-based IDSs for known attack detection (e.g., Snort, Suricata).
- DL-based anomaly detection for unknown threats.
- Edge computing-based IDSs for real-time attack mitigation.
- A hybrid IDS reduces false positives, improves efficiency, and enhances real-time threat detection capabilities.

## 11.6.5 Explainability and Interpretability of IDS Models

DL models often function as "black boxes," making it difficult for security analysts to understand why certain decisions were made.

### 11.6.5.1 Need for Trust and Transparency in AI-Driven Security

- Security professionals need interpretable IDS models to debug false positives and false negatives.
- Regulatory frameworks (e.g., GDPR, CCPA) require transparency in AI-based security decisions [37].
- Lack of explainability reduces trust in AI-powered cybersecurity systems [38].

### 11.6.5.2 Explainable AI (XAI) Approaches

To improve interpretability, researchers are integrating XAI into IDSs [39]:

- Shapley Additive Explanations (SHAPs): Identifies which features contributed most to a detection decision.
- Local Interpretable Model-Agnostic Explanations (LIMEs): It generates human-readable explanations for IDS classifications.
- Attention Mechanisms in Deep Learning: Highlights critical network features used in IDS decision-making.

The development of transparent, interpretable AI-driven IDSs is crucial for widespread adoption in enterprise and government security operations.

### 11.6.5.3 Benefits of XAI in IDSs

Incorporating XAI techniques in DL-based IDS provides multiple advantages as follows:

- Increased Trust and Adoption: Transparent IDS decisions help security analysts and regulatory bodies trust AI-driven security mechanisms.
- Reduction in False Positives: XAI identifies which features contribute to false alarms, allowing IDSs to be fine-tuned for better accuracy.
- Enhanced Compliance with Regulations: AI-powered security solutions in finance, healthcare, and government sectors require explainable decisions to comply with standards such as GDPR and CCPA.
- Improved Adversarial Defense: Attackers often exploit weaknesses in IDS models by crafting adversarial network traffic.

XAI can help identify which features attackers are manipulating, leading to better adversarial training techniques.

### 11.6.6.2 Privacy-Preserving AI for Intrusion Detection

Future IDS research should integrate AI with decentralized security architectures to improve real-time responsiveness and privacy preservation.
