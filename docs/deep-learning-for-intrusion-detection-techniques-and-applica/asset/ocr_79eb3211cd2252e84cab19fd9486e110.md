Various approaches, such as creating signatures as state machines, using formal language string patterns, or semantic conditions, have been employed to create signatures for SIDS. These systems are effective at detecting known attacks and boast high accuracy rates with minimal false positives. However, they are computationally intensive and require a significant amount of time to maintain. Unfortunately, the number of attack variants and zero-day attacks is increasing rapidly, making it challenging to keep these systems up-to-date. These systems require continuous updating of the attack repository for new attacks and are not suitable for detecting zero-day attacks. To address this issue, an anomaly-based intrusion detection system (AIDS) can be utilized, functioning by establishing a profile of what is considered acceptable behavior rather than focusing on detecting anomalies.

# **Anomaly-Based Method**

AIDS surpasses the limitations of SIDS and is recognized as a behavior-based system with robust capabilities for detecting unknown, zero-day attacks. In this system, traffic patterns are analyzed, allowing for the identification of normal traffic patterns, while malicious traffic is blocked. However, the diverse nature of malicious traffic patterns often results in high numbers of false positives generated by these systems.

The detection of an intrusion as an anomaly hinges on a significant deviation between observed behavior and the established model. These methods operate on the premise that malicious activity differs from normal user activity, categorizing any unusual actions deviating from regular behavior as intrusions. Constructing such a system requires special care.

An anomaly-based detection system relies on rules that define the expected behavior of applications, users, hosts, or network connections. These rules are established by analyzing the attributes of regular activities within a defined timeframe. For instance, a rule related to network activity might specify the average occurrence of web activity during standard business hours. The IDS creates alerts by comparing current activity attributes with established rules based on statistical techniques.

Behavioral attributes, such as unsuccessful login attempts, the number of emails sent by a user, and the volume of packets transferred within a specific period, serve as the basis for formulating rules. Anomaly-based detection methods excel in detecting new types of attacks that were previously unknown. For instance, when a system is infected with a new and unknown malware variant exhibiting behaviors deviating from established system profiles, the anomaly-based detection system can identify and detect such anomalies.
