+   - **Data Collection:** The IDS relies on various data sources to monitor and analyze activities for potential intrusions. It is the foundational step in building an effective IDS. It involves gathering data that will be used to train and test the IDS model. The types of data used in the IDS are network traffic data, system log files, and application-level data.
+   
+   - **Data preprocessing:** It is the process of transforming raw data into a clean, organized, and suitable format for analysis and modeling. It involves a series of techniques aimed at addressing inconsistencies, redundancies, and other issues in raw data to ensure that it is of high quality and ready for ML, statistical analysis, or other applications.
+   
+   - **Data Splitting:** Split the dataset into training and testing sets. The training set is used to build and train the model, while the testing set is reserved for assessing its performance.
+   
+   - **Data Balancing:** It is the process of addressing class imbalance in datasets where one class (e.g., the “majority class”) significantly outnumbers another class (e.g., the “minority class”). Balancing the dataset ensures that ML models can effectively learn from both classes, improving their ability to detect minority class instances and avoiding bias toward the majority class.
+   
+   - **Data Transformation:** It is the process of converting raw data into a suitable format or structure to make it more usable for analysis, modeling, or interpretation. It involves modifying data attributes, formats, or distributions to enhance the efficiency and accuracy of ML models or other analytical tools.

# 2.4.1 Types of Data Used in IDSs

+   - **Network Traffic Data:** It Includes packets captured from network interfaces. Contains details like source/destination IP, ports, protocols, packet size, and payload. It is commonly used for detecting anomalous or malicious network behaviors. Examples: PCAP files, NetFlow data.
+   
+   - **System Log Files:** Generated by operating systems and other infrastructure components. It provides insights into user authentication, file access, system events, and errors. Examples: Syslog, Windows Event Logs.
+   
+   - **Application-Level Data:** Logs or telemetry from specific applications. Tracks user actions, error messages, and application-specific events. Useful for detecting attacks targeting specific applications, like SQL injection or web exploits. Examples: Web server logs, database query logs.
