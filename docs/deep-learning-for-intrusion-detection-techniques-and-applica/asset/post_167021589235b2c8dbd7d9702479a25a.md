### 6.1 Introduction

The increasing prevalence of security threats across the internet and computer networks necessitates highly dependable security measures. Intrusion detection systems (IDSs) and intrusion prevention systems (IPSs) are essential components in safeguarding modern networks, as they help in identifying and preventing a wide range of cyber attacks. To ensure the effectiveness of these systems, reliable benchmark datasets are essential for testing and evaluating their performance. Several well-known datasets, such as DARPA98, NSLKDD, and ISCX2012, have been widely used by researchers to assess IDS and IPS solutions. However, many of these datasets have become outdated, lack diversity in attack types, and fail to reflect current network threats. Additionally, some datasets suffer from limited traffic volume, anonymized packet payloads, or missing metadata, making them less effective for modern cybersecurity research. The expanding network infrastructures and the advancing complexity of cyber threats emphasize the necessity for high-quality, realistic, and publicly accessible datasets. This chapter explores the existing intrusion detection datasets, their strengths, and limitations. Furthermore, it discusses the evaluation of network traffic features and various attack categories. Datasets for intrusion detection include labeled data, such as network activity, system behaviors, and traffic logs, categorized as either malicious or benign. This labeling allows researchers to effectively train and test IDS models. These datasets encompass various domains, including conventional networks, internet of things (IoT) environments, and host-based systems. Below are some widely used datasets for intrusion detection:

### 6.2 Data

Network traffic is typically captured in one of two formats: flow-based or packet-based [1]. Packet-based traffic is obtained by duplicating data from network device ports, enabling the collection of complete payload information for every packet. On the other hand, flow-based traffic is a more compact representation, as it retains only connection metadata rather than capturing the entire packet content. Wheelus et al. illustrate this difference with a metaphor: packet capture is like hiking through a forest, offering a detailed view, while flow-based capture is akin to observing the forest from a hot air balloon, providing a broader perspective [2]. Additionally, this study introduces a third category, “other data,” which lacks a standard format and varies depending on the specific dataset.

### 6.2.1 Packet-Based Data

Packet-based data is typically stored in the PCAP format and includes payload information. The available metadata depends on the network and transport protocols in use, with the most significant ones being User Datagram Protocol, Transmission Control Protocol, Internet Protocol, and Internet Control Message Protocol. TCP is a reliable transport protocol that includes metadata such as acknowledgment numbers, sequence numbers, checksum values, and flags. On the other hand, UDP operates as a connectionless protocol with a simpler header containing only four fields: checksum, source port, length, and destination port. In contrast to UDP and TCP, ICMP functions as a support protocol designed for delivering status messages and features an even smaller header. Additionally, packets generally include an IP header, which holds critical information such as the destination and source IP addresses.

### 6.2.2 Flow-Based Data

Flow-based network data provides a condensed representation by primarily storing metadata related to network connections. It groups together packets with common characteristics within a specified time frame, forming a single flow while usually omitting payload details. The standard five-tuple definition includes transport protocol, destination IP address, source port, source IP address, and destination port [3] that are commonly used to group packets into flows. Flows can be represented in bidirectional or unidirectional formats. In the unidirectional format, packets moving from host A to host B with the same attributes are grouped into a single flow, while packets traveling in the opposite direction (from host B to host A) are recorded as a separate flow. In contrast, bidirectional flows merge all packets exchanged between hosts A and B, regardless of their transmission direction. Common flow-based formats include OpenFlow [4], sFlow [5], IPFIX [3], and NetFlow [6]. Common characteristics of flow-based network traffic may consist of metrics such as bytes per second, bytes per packet, TCP flags from the initial packet, or computed payload entropy, depending on the flow format and exporter. While packet-based data can be transformed into flow-based data using tools like YAF3 or nfdump2, the opposite conversion is not feasible.

### 6.2.3 Other Data

This category includes datasets that do not strictly belong to either packet-based or flow-based formats. Instead, they may integrate flow-based data enriched with packet-level details or information from host-based log files. A well-known example is the KDD Cup 1999 dataset [7], which merges network-related attributes such as the number of transmitted source bytes or TCP flags with host-based features, like the frequency of failed login attempts. Due to the unique nature of each dataset in this category, they have their own specific set of attributes. Consequently, each dataset requires individual analysis, and no generalizations can be made about the available attributes across this category.
