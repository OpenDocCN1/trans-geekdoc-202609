$$m = \frac{\sum_{i=1}^{n}(g_i)}{b} \ast \left(1 + \frac{1}{n}\right) \tag{4}$$

To estimate the offset of label $i$, we pass batches full of other labels $\forall j \in [1,n] : j \ne i$, each batch full of one label, one batch per run. We repeat that for various batch sizes. The total number of runs is $t$. In these runs, the gradients of label $i$ reflect to some extent the penalties that label $i$ receives when the model mistakenly predicts it. Therefore, we calculate the mean of these gradients to be our estimated offset.

$$s_i = \frac{\sum_{k=1}^{t}(g_{ik})}{t} \tag{5}$$

## E. Label Leakage from Gradients Algorithm

Based on Property 1 and 2 and the estimated impact $m$ and offset $s_i$, we propose LLG, which is illustrated in Algorithm 1. (1) We start with extracting the labels based on the negative values of the gradients. Thus, the label of each negative value is added to the list of the extracted labels. (2) We eliminate the offset by subtracting it from the gradients. Without auxiliary knowledge, the offset is assumed to be zero. (3) We pick the minimum value among the gradients and add the corresponding label to the extracted labels. We repeat Step (3) until the size of the extracted labels list matches the batch size. Every time we add a label to the extracted labels in Steps (1) and (3), we subtract the impact from the corresponding gradient. The output of the algorithm is the extracted labels list, which contains a corresponding label for each data sample in the batch.

```
**Algorithm 1** Label Leakage from Gradients (LLG)

**Require:** $G = \{g_1, \ldots, g_n\}$: set of gradients, $m$: impact,
$S = \{s_1, \ldots, s_n\}$: set of offsets, $b$: batch size

**Ensure:** $lbls$: empty list for extracted labels

1: **for all** $g_i \in G$ **do**
2: &nbsp;&nbsp;&nbsp;&nbsp;**if** $g_i < 0$ **then**
3: &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;append $i$ to $lbls$
4: &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;$g_i \leftarrow g_i - m$
5: &nbsp;&nbsp;&nbsp;&nbsp;**end if**
6: **end for**
7: $G \leftarrow G - S$
8: **while** $|lbls| < b$ **do**
9: &nbsp;&nbsp;&nbsp;&nbsp;Find $g_i : g_i = \min(G)$
10: &nbsp;&nbsp;&nbsp;&nbsp;append $i$ to $lbls$
11: &nbsp;&nbsp;&nbsp;&nbsp;$g_i \leftarrow g_i - m$
12: **end while**
13: **return** $lbls$
```

## IV. EXPERIMENTS

In this section, we report on an empirical analysis of gradient values to demonstrate the validity of Property 1 and 2 and evaluate the accuracy of the LLG algorithm with and without auxiliary knowledge.

We run our experiments on the classification task over two datasets, MNIST [3] and CIFAR-100 [2]. For proper future comparison with previous work, we replicate the setting used in [6]. As such, we use the LeNet [3] structure for the neural network. As optimizer, we use L-BFGS with learning rate 1. We train the neural network on a batch of size $2^k$ with $k \in [0,7]$. In distributed learning, the participants’ data can be *independent and identically distributed* (IID) or *non-IID*. We consider both in our experiments. For IID data, the samples of the batch are selected randomly from the dataset. For non-IID data, we select 50% of the batch samples from one random label $i$ and 25% from another label $j$. The remaining 25% of the batch is chosen randomly. We repeat all experiments 1,000 times with randomly initialized networks and report the mean values.

### A. Gradient Analysis

In our analysis, we focus on the gradients $G = \{g_1, \ldots, g_n\}$ with $g_i$ as defined in Eq. (1). The number of gradients we investigate corresponds to the number of labels. For MNIST, we have $n = 10$ values, while in CIFAR-100, we check $n = 100$ values. Considering the variety of settings and repetitions of our experiments, we analyze 1,760,000 gradients in total.

To demonstrate the validity of Property 1, we audit the signs of the gradients. We found that 100% of the negative gradients correspond to existing labels in the batch as shown in Table I, Relationship 1, which conforms with Property 1. Consequently, all non-existing labels correspond to positive values. However, we also notice in Relationship 2 that 6%-18% of the existing labels have positive gradients. We assume this is caused by the offset parameter we introduced in Section III-B.

To elaborate more on the impact and offset parameters, we plot the distribution of the gradient values for IID data as shown in Fig. 1.(a,b). The x-axis represents the number of occurrences for a label $i : \forall i \in [1,n]$ in the batch, while y-axis represents the value of the corresponding gradient $g_i$. For all batch sizes, we can see that the values of the gradients decrease consistently (by a roughly constant step) with the increase of the occurrences. This, in turn, conforms with Property 2 and our definition of the impact parameter. We also observe that the decrease in gradients values between different occurrences is roughly constant regardless the label, as the figure contains all the labels together. That confirms our assumption that the impact is label-agnostic, as we discussed earlier. Furthermore, we notice that the magnitude of the impact is negatively correlated with the batch size. Meaning, the more samples are present in a batch, the smaller are the changes of the gradients for different number of occurrences.

We see the distribution of the gradients between negative and positive values. As we discussed earlier, the values shifted into positive ones make the label extraction more difficult. Therefore, we prune the gradients by subtracting the offset from the gradients in Algorithm 1. We estimate the offset value as explained in Section III-D. In Fig. 1.(d,e), we see the pruned gradients, and how they become mainly negative values. Pruning process eliminates the effect of the offset and makes the values more consistent, thus, easier to be used for extracting the labels.

### B. Label Extraction Accuracy

The accuracy is expressed as the amount of the correctly extracted labels divided by the total number of the extracted labels. We apply our algorithm in all the aforementioned experiments and evaluate its accuracy with and without auxiliary knowledge. We refer to our algorithm with auxiliary knowledge as LLG+. We compare the accuracy with random guessing as a baseline. Fig. 1.(c) shows the accuracy for MNIST. We can see that LLG+ successfully detects the ground-truth labels with > 98% for batch sizes ≤ 128. LLG has accuracy > 80% and > 85% for IID and non-IID data, respectively. We notice that for increasing batch sizes (> 64) and IID data, LLG performs similarly to random guessing. Interestingly, LLG performs almost equally to LLG+ on the CIFAR-100 dataset, as shown in Fig. 1.(f). Both, LLG and LLG+ have > 96% accuracy for IID and non-IID data. Random guessing performs poorly for CIFAR-100 compared with MNIST, as the number of labels in CIFAR-100 is much bigger than in MNIST.

## V. CONCLUSION & FUTURE WORK

We presented Label Leakage from Gradients (LLG), an algorithm that extracts the ground-truth labels from shared gradients in distributed machine learning. We demonstrated the validity of our approach through an initial empirical analysis. As next steps, we will conduct more extensive experiments with various hyper parameters of the neural network, its structures, and additional datasets. We will assess the fidelity of DLG attack [7] combined with our algorithm. Lastly, we are currently researching defense mechanisms that are capable of mitigating the risk of LLG.
