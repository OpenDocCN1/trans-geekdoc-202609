
# 安全协议

*   **安全外壳协议** 是一种用于远程控制台访问设备的协议，是 Telnet 的安全替代方案。SSH 也常被用作隧道协议，或用于支持 SFTP 等其他用途。SSH 可以使用 SSH 密钥，用于身份验证。与许多基于证书或密钥的身份验证用法一样，缺少密码或使用弱密码，以及密钥管理不善，都会使 SSH 在实际使用中安全性大打折扣。

*   **基于 SSL/TLS 的超文本传输协议** 在现代实现中依赖 TLS，但尽管如此，仍常被称为 SSL。与此处讨论的许多协议一样，底层的 HTTP 协议依赖 TLS 来为 HTTPS 实现提供安全性。

*   **安全实时传输协议** 是实时传输协议的安全版本，后者是一种旨在通过网络提供音频和视频流的协议。SRTP 使用加密和身份验证，试图降低成功攻击的可能性，包括重放攻击和拒绝服务攻击尝试。RTP 使用成对的协议，即 RTP 和 RTCP。RTCP 是控制协议，用于监控服务质量和流同步，RTCP 也有一个安全的对应版本，即 SRTP。

*   **安全轻量级目录访问协议** 是受 TLS 保护的 LDAP 版本，提供机密性和完整性保护。

## 电子邮件相关协议

尽管许多组织已转向基于 Web 的电子邮件，但邮局协议 (POP) 和互联网消息访问协议 (IMAP) 等电子邮件协议仍在邮件客户端中使用。为两者实现 TLS 作为保护层的安全协议选项均已存在，从而催生了 **POPS** 和 **IMAPS** 的部署。

**安全/多用途互联网邮件扩展** 提供了加密和签名 MIME 数据的能力，MIME 是用于电子邮件附件的格式。因此，电子邮件的内容和附件可以受到保护，同时为使用 S/MIME 发送的消息提供身份验证、完整性、不可抵赖性和机密性。

与此处讨论的许多其他协议不同，S/MIME 要求用户拥有证书，才能发送和接收受 S/MIME 保护的消息。需要本地生成的证书或来自公共证书颁发机构 (CA) 的证书。这一要求增加了想要与其他个人安全通信的 S/MIME 用户的复杂性，因为证书管理和验证可能变得复杂。因此，尽管许多电子邮件提供商和工具广泛支持，S/MIME 的使用频率较低。

当然，相当一部分电子邮件是通过 Web 访问的，这实际上使 HTTPS 成为电子邮件访问最常用的安全协议。

## 文件传输协议

尽管通过 FTP 进行文件传输越来越少见，但 FTP 的安全版本确实存在且仍在使用。主要有两种选择：**FTPS**，它使用 TLS 实现 FTP；以及 **SFTP**，它利用 SSH 作为通道来执行类似 FTP 的文件传输。SFTP 经常被选用，因为它更容易穿越防火墙，因为它仅使用 SSH 端口，而 FTPS 可能需要额外的端口，具体取决于配置。

## IPSec

IPSec (Internet Protocol Security，互联网协议安全) 不仅仅是单一协议。事实上，IPSec 是一整套用于加密和认证 IP 流量的安全协议套件。Security+ 考试大纲重点关注该标准的两个组件：

*   **认证头** 使用哈希和共享密钥来确保数据完整性，并通过认证发送的 IP 数据包来验证发送者。AH 可确保 IP 负载和头部受到保护。

*   **封装安全载荷** 在传输模式或隧道模式下运行。在隧道模式下，它为整个数据包提供完整性和认证；在传输模式下，它仅保护数据包的负载。如果 ESP 与认证头一起使用，可能会给需要更改 IP 或端口信息的网络带来问题。

IPSec 经常用于 VPN，在隧道模式下用于在两个位置之间创建安全的网络连接。

## 中间人攻击

**中间人** 攻击（有时也称为中间人攻击 [MitM]）发生在攻击者导致本应发送给预期接收者的流量，通过攻击者控制的系统或设备进行中转时。一旦攻击者让流量流经该系统，他们就可以窃听，甚至随意篡改通信。[图 12.2](#c12.xhtml#c12-fig-0002) 显示了中间人攻击成功后，流量流向如何从正常状态发生改变。

![图 12.2 中间人攻击前后的通信](images/c12f002.png)

[**图 12.2**](#c12.xhtml#R_c12-fig-0002) 中间人攻击前后的通信

中间人攻击可用于实施 **SSL 剥离**，这是一种在现代实现中移除 TLS 加密、以读取本应发送给可信端点的流量内容的攻击。典型的 SSL 剥离攻击分三个阶段发生：

1.  用户发送网页的 HTTP 请求。
2.  服务器响应重定向到该页面的 HTTPS 版本。
3.  用户发送重定向页面的 HTTPS 请求，网站随之加载。

SSL 剥离攻击在 HTTP 请求发生时利用中间人攻击，将后续通信重定向通过攻击者控制的系统，从而允许读取或可能修改通信。虽然 SSL 剥离攻击可在任何网络上实施，但最常见的实现方式之一是通过开放无线网络，攻击者可控制无线基础设施，从而修改通过其接入点和网络连接的流量。

最后一种中间人攻击变体是基于浏览器的攻击（以前称为 **中间人浏览器** MitB 或 MiB）。这种攻击依赖于植入用户浏览器的木马。该木马随后能够访问和修改浏览器发送和接收的信息。由于浏览器接收并解密信息，基于浏览器的中间人攻击可以成功绕过 TLS 加密和其他浏览器安全功能，还可以访问具有打开会话的站点或浏览器已认证的站点，这使得 MitB 攻击成为攻击者的一个非常强大的选项。由于基于浏览器的中间人攻击需要安装木马，无论是作为浏览器插件还是代理，系统级安全防御（如反恶意软件工具、系统配置管理和监控功能）最适合防范此类攻击。

## 域名系统攻击

剥离加密并不是唯一能让恶意行为者窥探你流量的网络攻击类型。事实上，如果他们能控制流量发送到的系统，那就简单多了！这就是 DNS 攻击发挥作用的地方。Security+ 考试大纲重点关注三种类型的 DNS 和域相关攻击，以及一个关键的安全和监控工具。
