
虚拟机快照是取证从业人员必须处理的日益常见的工件。

网络流量和日志可以提供关于发送或接收了什么、何时发送或接收、通过什么端口和协议以及其他有用细节的详细信息或线索。

设备、打印输出、介质以及与调查相关的其他物品等工件都可以提供额外的有用取证数据。

无论获得或处理哪种类型的取证数据，如果取证案件可能导致法律诉讼，保持*证据保管链*文档非常重要。事实上，一些组织无论案件如何都应用这些规则，以确保在必要时案件能得到支持。证据保管链表单是简单的签署和文档记录表单，如[图 15.2](#c15.xhtml#c15-fig-0002)所示。每次访问、传输或以其他方式处理驱动器、设备或工件时，都会按照表单所示进行记录。

法庭案件中的证据通常具有法律可采性，前提是它被用来证明案件事实且不违反法律。要确定证据是否可采，会应用诸如证据的相关性和可靠性、证据是否合法获取、证据是否真实等标准。证据必须是可获得的最佳证据，且流程和程序应经得起法庭质疑。

除了这些要求外，数字取证的*可采性*还要求数据完整且未被篡改，并能证明在取证过程之前和期间一直保持未被篡改。取证分析师必须能够证明他们具备适当的技能、使用了适当的工具和技术，并以一种可靠且可通过可审计线索进行测试的方式记录了他们的行动。因此，如有必要，第三方必须能够重复他们的工作和发现。

#### 云取证

尽管现场取证构成了传统取证工作的大部分，但向云服务的广泛迁移给取证分析师带来了新的挑战。除了需要支持取证发现需求的工具和能力外，组织越来越多地确保他们已与云提供商合作。除了组织必须考虑的关于从云提供商保留和生成数据能力的高层关注点外，Security+ 考试专门包含三个概念：

*   **审计权条款**，它是云服务与组织之间合同的一部分。审计权条款提供直接审计云提供商的能力，或同意使用第三方审计机构的协议。许多云提供商使用标准合同，可能不同意为小型组织提供审计权条款。在这种情况下，他们可能会提供定期更新的第三方审计声明的访问权限，这可能符合您组织的需求。如果您有特定的审计要求，应尽可能在合同中解决它们，并决定如果无法进行审计，审计能力是否是贵组织决定采用云提供商服务的决定性因素。

*   **法规**和**管辖权**顾虑也是采用云服务的重要因素。法规要求可能因云服务提供商的运营地和总部所在地而异。涵盖您的数据、服务或基础设施的法律可能不是您所在地区、区域或国家的法律。此外，管辖权顾虑可能超出涵盖整个组织的法律范围。云提供商通常在世界各地设有站点，数据复制和其他服务要素意味着您的数据或服务可能存储或使用在同样广泛的位置。当地司法管辖区可能声称有权通过搜查令或其他法律手段访问该数据。对此有重大顾虑的组织通常通过合同条款、提供商提供的仅在特定区域或国家托管数据或系统的服务选择，以及技术控制（如自行处理加密密钥以确保知晓数据是否被访问）来解决此问题。

*   **数据泄露通知法律**，与其他法规要素一样，因国家而异，在美国各州之间也明显不同。合同通常涵盖通知客户前可经过的最长时间，确保您拥有满足需求的适当泄露通知条款可能很重要。一些供应商延迟数天、数周甚至数月通知，可能导致不知情的客户面临重大问题。

这些考虑因素意味着从云提供商获取取证数据的可能性不大。虽然您可能能够从日志或您在基础设施即服务提供商环境中维护的系统和基础设施中恢复取证数据，但服务本身的取证数据很少移交给客户。因此，使用云服务的组织必须制定计划来处理潜在事件和调查，而不依赖直接取证技术。

### 采集工具

获取驱动器或设备的取证副本需要一种能在比特级创建设备完整副本的工具。Security+ 考试涉及多种可获取磁盘映像的工具，包括`dd`、`FTK Imager`和`WinHex`。

在 Linux 中，`dd` 是一个命令行实用程序，允许您为取证或其他目的创建映像。`dd` 命令行接受输入，如输入位置（`if`）、输出位置（`of`）以及描述您想要执行操作的标志，例如尽管出错仍创建完整副本。

要将挂载为`/dev/sda`的驱动器复制到名为`example.img`的文件，可以执行如下命令：

```
dd if=/dev/sda of=example.img conv=noerror,sync
```

其他设置通常有助于获得更好的性能，例如设置适合驱动器的块大小。如果您想将 `dd` 用于取证目的，值得投入额外时间学习如何使用针对您用于取证工作站的设备和接口的块大小设置来调整其性能。

`FTK Imager` 是一款用于创建取证映像的免费工具。它支持原始（`dd`）格式，以及 `SMART`（ASR Data 的 SMART 取证工具格式）、`E01`（EnCase）和 `AFF`（高级取证格式）等取证工具常用的格式。了解您需要为分析工具生成什么格式，以及是否可能需要多种格式的副本，在设计取证流程时非常重要。

`FTK Imager` 支持物理驱动器、逻辑驱动器、映像文件、文件夹以及多 CD/DVD 卷。在大多数情况下，取证采集可能来自物理或逻辑驱动器。[图 15.3](#c15.xhtml#c15-fig-0003) 显示了使用 `FTK Imager` 从物理驱动器完成映像创建的过程。注意匹配且经过验证的 MD5 和 SHA1 哈希值，以及确认没有坏块（这将表明潜在的数据丢失或驱动器问题）。
