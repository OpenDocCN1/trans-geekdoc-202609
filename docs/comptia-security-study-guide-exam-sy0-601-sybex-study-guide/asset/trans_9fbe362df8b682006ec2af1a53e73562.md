
# 网络攻击链阶段

## 侦察
此阶段用于识别目标。攻击者正在规划攻击，并将收集关于目标的情报，包括开源情报以及通过扫描直接获取的目标数据。防御者必须收集关于侦察活动的数据，并根据该信息确定防御优先级。

## 武器化
此阶段涉及构建或以其他方式获取 `weaponizer`（武器化工具），它将恶意软件和漏洞利用组合成可投递给目标的载荷。这可能需要创建诱饵文档、选择合适的命令与控制（`C2`）工具以及处理其他细节。该模型强调了这样一个事实：防御者需要在此阶段进行完整的恶意软件分析，不仅要了解投放了什么载荷，还要了解武器化漏洞利用是如何制作的。防御者还应为武器化工具构建检测规则，查看恶意软件创建时间与使用时间的时间线对比，并收集文件和元数据，以帮助判断这些工具是广泛共享的，还是严格保密的，从而可能具有高度针对性。

## 投递
当攻击者直接针对目标部署工具，或通过依赖目标员工与其交互的方式发布工具（如电子邮件载荷、USB 存储棒，或通过他们访问的网站）时，即发生此阶段。此阶段的防御者必须观察攻击是如何投递的以及针对什么目标，然后推断攻击者意图达成的目的。日志保留至关重要，因为它有助于确定发生了什么，并协助攻击分析。

## 利用
此阶段利用软件、硬件或人为漏洞获取访问权限。它可能涉及零日漏洞利用，并可能使用攻击者触发的漏洞利用或受害者触发的漏洞利用。针对此阶段的防御侧重于用户意识、安全编码、漏洞扫描、渗透测试、端点加固以及类似活动，以确保组织拥有强大的安全态势和极小的攻击面。

## 安装
此阶段专注于为攻击者建立持久化后门访问。防御者必须监控持久化远程 Shell 或其他远程访问方法的典型工件。

## 命令与控制（C2）
`C2` 访问允许双向通信和对远程系统的持续控制。防御者将通过加固网络、部署检测能力以及进行持续研究，来寻求检测 `C2` 基础设施，以确保他们了解新的 `C2` 模型和技术。

## 目标行动
当任务目标达成时，将发生最后阶段。攻击者将收集凭证、提升权限、在环境中横向移动和转移，并收集和窃取信息。他们还可能对系统或数据造成破坏。防御者必须建立事件响应剧本，检测攻击者的行动并捕获相关数据，响应警报，并评估攻击者造成的损害。

# 事件响应数据与工具

事件响应人员依赖各类数据开展工作。作为安全专业人员，你需要了解可能需要哪些类型的数据来进行调查，并确定发生了什么以及如何防止再次发生。

## 安全信息与事件管理系统

在许多组织中，核心安全监控工具是 `安全信息与事件管理 (SIEM)` 工具。`SIEM` 设备和软件具有广泛的安全功能，这些功能通常基于从多种来源收集和聚合日志数据的能力，然后利用这些数据执行关联和分析活动。这意味着组织会将数据输入（包括来自系统、网络安全设备、网络基础设施和许多其他来源的日志及其他有用信息）发送到 `SIEM` 进行摄取，与其拥有的其他数据进行比较，然后对数据应用规则、分析技术以及机器学习或人工智能。`SIEM` 系统可能包括审查和警报用户行为的能力，或执行情感分析，这是一个利用自然语言处理和其他文本分析工具查看文本以从文本数据中确定情绪的过程。

`SIEM` 设备的另一个数据输入是数据包捕获。从网络流量中捕获和分析原始数据包数据，或从其他数据源接收数据包捕获，对于事件分析非常有用，特别是在需要关于网络事件的具体信息时。将原始数据包数据与 `IDS` 或 `IPS` 事件、防火墙和 `WAF` 日志以及其他安全事件相关联，为安全从业者提供了一个强大的工具。

`SIEM` 设备还提供警报、报告和响应功能，使组织能够了解何时需要处理问题，并跟踪该问题在其生命周期内的响应情况。这可能包括取证能力，也可能更侧重于工单和工作流流程来处理问题和事件。

### SIEM 仪表板

许多安全从业者看到的 `SIEM` 的第一部分是仪表板，如图 [14.6](#c14.xhtml#c14-fig-0006) 所示的 AlienVault `SIEM` 仪表板。仪表板可配置为显示组织或个人分析师认为最有用和最关键的信息，并且可以配置多个仪表板以显示特定视图和信息。仪表板的关键在于理解它们提供了所包含信息的高层级可视化表示。这有助于安全分析师快速识别潜在问题、异常模式和可能感兴趣或令人担忧的新趋势。

`SIEM` 仪表板有许多重要组件，提供其显示的各个要素。这些包括收集并发送信息到 `SIEM` 的传感器、趋势和警报功能、关联引擎和规则，以及设置灵敏度和级别的方法。

### 传感器

尽管设备可以直接将数据发送到 `SIEM`，但通常会部署传感器来收集额外数据。传感器通常是软件代理，尽管它们也可以是虚拟机甚至专用设备。传感器通常部署在云基础设施、远程数据中心或其他产生大量独特数据的环境中，或者现有能力无法满足数据获取需求、需要专用设备的位置。传感器为 `SIEM` 收集有用数据，并可能按原始形式转发，或在 `SIEM` 摄取前进行一些预处理以优化数据。选择传感器部署位置是网络和安全架构及设计工作的一部分，传感器必须像其他网络安全组件一样得到保护，防止遭受攻击和妥协。

### 灵敏度与阈值

组织可以产生海量数据，安全数据也不例外。分析师需要了解如何控制和限制 `SIEM` 产生的警报。为此，他们设置阈值、过滤规则，并使用其他管理 `SIEM` 灵敏度的方法。警报可设置为仅在事件发生特定次数时触发，或仅在影响特定高价值系统时触发。或者，警报可设置为仅触发一次，而不是成百上千次。无论您的 `SIEM` 如何处理灵敏度和阈值，配置和管理它们以确保仅在需要警报的项目上发送警报，有助于避免警报疲劳和误报。
