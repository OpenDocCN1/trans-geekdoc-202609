
尽管影响应用程序的众多漏洞是网络安全专业人员极为关注的重大问题，但好消息是，有许多工具可用于协助开发纵深防御安全方法。通过安全编码实践和安全基础设施工具的结合，网络安全专业人员可以构建强大的防御体系来抵御应用程序攻击。

## 输入验证

网络安全专业人员和应用程序开发人员手头有多种工具，可帮助防范应用程序漏洞。其中最重要的是 `input validation`（输入验证）。允许用户输入的应用程序应对该输入执行验证，以降低其包含攻击代码的可能性。不当的输入处理实践会使应用程序面临注入攻击、跨站脚本攻击和其他攻击。

最有效的输入验证形式是 `input whitelisting`（输入白名单），即开发人员描述预期从用户处接收的确切输入类型，然后在将输入传递给其他进程或服务器之前，验证该输入是否符合该规范。例如，如果输入表单提示用户输入年龄，输入白名单可以验证用户提供的值是否为 0–120 范围内的整数。应用程序随后会拒绝该范围之外的任何值。

由于许多允许用户输入的字段的性质，执行输入白名单验证通常很困难。例如，设想一个分类广告应用程序，允许用户输入待售产品的描述。要编写描述该字段所有有效提交且同时防止恶意代码插入的逻辑规则是很困难的。在这种情况下，开发人员可能会使用 `input blacklisting`（输入黑名单）来控制用户输入。采用这种方法时，开发人员不尝试显式描述可接受的输入，而是描述必须阻止的潜在恶意输入。例如，开发人员可能会限制用户输入中 HTML 标签或 SQL 命令的使用。执行输入验证时，开发人员必须注意字段中可能出现的合法输入类型。例如，完全禁止使用单引号（`'`）可能有助于防范 SQL 注入攻击，但也可能导致包含撇号的姓氏（如 O’Brien）难以输入。

## Web 应用程序防火墙

`Web application firewalls (WAFs)`（Web 应用程序防火墙）在保护 Web 应用程序免受攻击方面也发挥着重要作用。虽然开发人员应始终依靠输入验证作为抵御注入攻击的主要防线，但现实是应用程序有时仍会包含注入缺陷。这可能发生在开发人员测试不足，或供应商未及时为易受攻击的应用程序提供补丁时。

WAF 的功能类似于网络防火墙，但它们工作在应用层。WAF 位于 Web 服务器前方，如 [图 6.18](#c06.xhtml#c06-fig-0018) 所示，并接收所有发往该服务器的网络流量。然后，它会仔细检查发往应用程序的输入，在将输入传递给 Web 服务器之前执行输入验证（白名单和/或黑名单）。这可以防止恶意流量到达 Web 服务器，并作为针对 Web 应用程序漏洞的分层防御的重要组成部分。

## 数据库安全

安全的应用程序依赖于安全的数据库，以提供支持业务运营所需的内容和事务处理。关系型数据库构成了大多数现代应用程序的核心，保护这些数据库不仅仅是防范 SQL 注入攻击。网络安全专业人员应深入了解安全的数据库管理实践。

### 规范化

`Database normalization`（数据库规范化）是数据库设计人员在构建和修改数据库时应遵循的一组设计原则。遵循这些原则的数据库被称为符合范式，范式按遵循原则的程度递增编号。最简单的范式是第一范式（1NF），更高级的范式依次递增（2NF、3NF 等）。

数据库社区就数据库设计人员应多严格地遵循范式进行着积极而健康的讨论。在切实可行的范围内尽可能实施这些原则的一些优势包括：规范化设计可做到以下几点：

*   防止数据不一致
*   防止更新异常
*   减少重构现有数据库的需求，以及
*   使数据库模式更具信息量

### 参数化查询

参数化查询提供了另一种保护应用程序免受注入攻击的技术。在参数化查询中，客户端不会直接将 SQL 代码发送给数据库服务器。相反，客户端将参数发送给服务器，服务器再将这些参数插入预编译的查询模板中。这种方法可防范注入攻击，还能提高数据库性能。

`Stored procedures`（存储过程）是某些数据库平台使用的参数化查询的一种实现示例。

### 混淆与伪装

在数据库中维护敏感个人信息会使组织面临风险，一旦该信息被攻击者窃取。数据库管理员应采取措施防范 `data exposure`（数据泄露）。

*   `Data minimization`（数据最小化）是最佳防御。组织不应收集不需要的敏感信息，并应在收集的敏感信息不再用于合法业务目的时尽快销毁。数据最小化可降低风险，因为你无法失去对你原本就没有掌握的信息的控制！
*   `Tokenization`（令牌化）使用查找表用唯一标识符替换可能直接揭示个人身份的个人标识符。例如，我们可以用一个随机生成的 10 位数字替换广为人知的值（如学生 ID）。然后我们维护一个查找表，以便在需要确定某人身份时将这些数字转换回学生 ID。当然，如果使用这种方法，你需要保护好查找表的安全！
*   `Hashing`（哈希）使用加密哈希函数将敏感标识符替换为不可逆的替代标识符。在哈希之前用随机数对这些值进行 `Salting`（加盐），可使这些哈希值能抵抗一种称为彩虹表攻击的攻击类型。你将在 [第 7 章](#c07.xhtml)“密码学和公钥基础设施”中了解更多关于哈希、加盐和彩虹表攻击的内容。

## 代码安全

软件开发人员还应采取措施，保护其代码的创建、存储和交付。他们通过多种技术来实现这一点。

### 代码签名

`Code signing`（代码签名）为开发人员提供了一种向最终用户确认其代码真实性的方法。开发人员使用加密函数以其私钥对代码进行数字签名，然后浏览器可以使用开发人员的公钥来验证该签名，确保代码合法且未被未经授权的人员篡改。在缺乏代码签名的情况下，用户可能会无意中运行非真实代码。

### 代码复用

许多组织不仅在内部复用代码，还通过使用第三方软件库和软件开发工具包（SDK）来复用代码。第三方软件库是开发人员之间共享代码的常用方式。
