

## OWASP 主动控制措施

*   **实施数字身份**  使用多因素认证、安全的密码存储与恢复以及会话处理。
*   **强制执行访问控制**  要求所有请求都经过访问控制检查，默认拒绝，并应用最小权限原则。
*   **保护无处不在的数据**  在传输中和静态时使用加密。
*   **实施安全日志记录和监控**  这有助于检测问题，并允许事后进行调查。
*   **处理所有错误和异常**  错误不应提供敏感数据，且应测试应用程序以确保其能妥善处理问题。

您可以在 `www.owasp.org/index.php/OWASP_Proactive_Controls` 找到 OWASP 的主动控制措施列表，在 `www.owasp.org/index.php/OWASP_Secure_Coding_Practices_-_Quick_Reference:Guide` 可获取一份有用的安全编码实践快速参考指南。

## API 安全

*应用程序编程接口* (API) 是客户端与服务器之间，或应用程序与操作系统之间的接口，它们定义了客户端应如何向服务器请求信息以及服务器将如何响应。这一定义意味着用任何语言编写的程序都可以实现 API 并发起请求。

API 对于构建系统间的接口非常有用，但如果未妥善保护，它们也可能成为脆弱点。API 安全依赖于认证、授权、适当的数据范围界定（以确保不会发布过多数据）、速率限制、输入过滤，以及适当的监控和日志记录来保持安全。当然，保护底层系统、配置 API 端点服务器或服务，以及提供正常的网络层安全性以保护服务也很重要。

许多安全工具和服务器提供 API，安全专业人员通常需要编写脚本或程序来访问 API 以提取数据。

## 代码审查模型

审查为应用程序编写的代码具有诸多优势。它有助于共享代码知识，且编写代码获得的经验优于单纯的文档，因为它提供了对代码及其功能的个人理解。它还有助于在开发周期中通过让代码接受审查来发现问题，同时强制执行编码最佳实践和标准。最后，它确保团队的多名成员知晓代码的预期功能及其实现方式。

存在许多常见的*代码审查*流程，包括正式和敏捷流程，如结对编程、过肩审查和 Fagan 代码审查。

### 结对编程

*结对编程* 是一种敏捷软件开发技术，让两名开发人员共用一个工作站。一名开发人员编写代码，而另一名开发人员在编写过程中审查其代码。这旨在提供实时代码审查，并确保多名开发人员熟悉所编写的代码。在大多数结对编程环境中，开发人员需要频繁轮换角色，使他们都能花时间在键盘前思考代码，并在审查时思考设计及代码中存在的任何问题。

结对编程增加了开发成本，因为它需要两名全职开发人员。同时，它为代码的审查和分析提供了额外机会，并将更多经验直接应用于编码问题，从而有可能提高代码质量。

### 过肩审查

*过肩代码审查* 同样依赖于一对开发人员，但它不要求持续的互动和交接，而是要求编写代码的开发人员向另一名开发人员解释代码。这种方法允许对代码进行同行评审，还能帮助开发人员理解代码如何工作，且没有结对编程相对较高的成本。

### 传阅代码审查

*传阅代码审查*，有时称为电子邮件传阅代码审查，是一种通过将完成的代码发送给审查人员来检查代码问题的手动同行评审形式。传阅审查可能涉及多名审查人员，允许具有不同专业知识和经验的审查人员做出贡献。虽然传阅审查在*发生时间*上比过肩审查更灵活，但它们不像过肩审查和结对编程那样提供从编写代码的开发人员那里轻松了解代码的机会，这使得文档变得更加重要。

### 工具辅助审查

*工具辅助代码审查* 依赖基于正式或非正式软件的工具来进行代码审查。Atlassian 的 Crucible 协作代码审查工具、Codacy 的静态代码审查工具和 Phabricator 的 Differential 代码审查工具等，都是为了改进代码审查流程而设计的。用于代码审查的各种工具不仅反映了软件开发生命周期选项的多样性，也反映了组织如何建立其设计和审查流程。

### 选择审查方法

[表 6.1](#c06.xhtml#c06-tbl-0001) 对比了四种非正式代码审查方法和正式代码审查。具体实现可能有所不同，但这些对比在各类代码审查之间通常成立。此外，每种方法背后的理论可能并不总是反映组织实际使用它的情况。例如，结对编程旨在提供与两名开发人员独立工作相同的开发速度，同时提高代码质量。这对于配合良好的经验丰富的程序员可能成立，但缺乏培训、个性差异和工作风格的变化可能会使结对编程的效果不如预期。

**表 6.1** 代码审查方法对比

| 方法 | 成本 | 审查发生时间 | 解释代码的能力 | 所需技能 |
| :--- | :--- | :--- | :--- | :--- |
| **结对编程** | 中 | 实时 | 高 | 用户必须学习如何结对编程 |
| **过肩审查** | 中 | 实时 | 高 | 无需额外技能 |
| **传阅代码审查** | 低/中 | 异步 | 低 | 无需额外技能 |
| **工具辅助审查** | 中 | 取决于工具/流程 | 通常较低 | 可能需要工具使用培训 |
| **正式代码审查** | 高 | 异步 | 通常较低 | 代码审查流程培训 |

当代码需要比传阅和过肩审查等相对轻量级的敏捷流程更深入的审查时，有时会使用正式代码审查流程。顾名思义，正式代码审查是一个深入、通常耗时的过程，旨在利用专家团队全面审查代码。正式代码审查的主要形式是 Fagan 检查。

### Fagan 检查

*Fagan 检查* 是一种结构化的正式代码审查，旨在在开发过程中发现各种问题。Fagan 检查为流程指定了进入和退出标准，确保在执行适当的尽职调查之前不启动流程，并确保有已知的标准用于进入下一阶段。

[图 6.6](#c06.xhtml#c06-fig-0006) 所示的 Fagan 检查流程展示了典型流程的六个阶段：

1.  **规划**，包括材料、与会人员和地点的准备
2.  **概览**，通过审查材料和分配角色（如编码人员、阅读人员、审查人员和主持人）来准备团队
3.  **准备**，涉及审查被检查的代码或其他项目，并记录他们可能存在的任何问题或疑问
4.  **会议**，根据准备阶段的记录识别缺陷
