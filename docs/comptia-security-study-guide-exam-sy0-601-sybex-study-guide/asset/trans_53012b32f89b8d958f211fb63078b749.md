

## 第 7 章：密码学与公钥基础设施

### 问题 3-20

**3. A.** 参数化查询（有时称为预处理语句）使用预构建的 SQL 语句来防止基于 SQL 的攻击。来自应用程序的变量被传递给查询，而不是在应用程序需要数据时构建自定义查询。对数据进行编码有助于防止跨站脚本攻击，输入验证也是如此。适当的访问控制可以防止访问账户或应用程序不应有权访问的数据，但它们不使用预编译的 SQL 语句。存储过程是参数化查询实现的一个示例。

**4. A.** 不当的错误处理往往会向用户（甚至可能向攻击者）暴露本不应暴露的数据。在本例中，了解应用程序内部使用的 SQL 代码可为攻击者提供详细信息，以便其发动进一步攻击。代码暴露并非本书讨论的漏洞之一，且 SQL 代码暴露并不一定意味着存在 SQL 注入漏洞。虽然这可能是由默认配置问题引起的，但题目中没有任何线索指向该问题。

**5. B.** 该应用程序存在竞争条件，当多个操作因完成顺序不同而导致不良结果时，就会发生这种情况。如果内存位置不正确，会发生解引用；不安全函数本身会存在安全问题；不当的错误处理涉及错误本身及其显示方式或提供的数据。

**6. B.** 虽然此示例包含持续集成，但关键在于代码随后被部署到了生产环境。这意味着 Susan 处于持续部署环境中，代码既持续集成又持续部署。敏捷是一种开发方法论，通常使用 CI/CD，但我们无法确定 Susan 是否在使用敏捷。

**7. B.** 从事活跃代码更改的开发人员应始终在开发环境中工作。测试环境是可以在不影响生产环境的情况下对软件或系统进行测试的地方。预发布环境是通过测试并等待部署到生产环境的代码的过渡环境。生产环境是实时系统。经过测试和批准的软件、补丁和其他更改会移至生产环境。

**8. B.** 敏捷软件开发方法的核心原则之一是通过尽早且持续地交付软件来确保客户满意度。

**9. B.** 场景中描述的情况——需求激增时扩充容量，需求下降时再减少容量——正是弹性的定义。

**10. B.** 数据库规范化有四大主要优势。规范化设计可防止数据不一致、防止更新异常、减少重构现有数据库的需求，并使数据库模式更具信息量。它们无法防止 Web 应用程序攻击，例如 SQL 注入。

**11. A.** 令牌化使用查找表，用唯一标识符替换可能直接揭示个人身份的个人标识符。哈希使用加密哈希函数，用不可逆的替代标识符替换敏感标识符。在哈希之前使用随机数对这些值进行加盐，可使这些哈希值能抵抗一种称为彩虹表攻击的攻击类型。

**12. D.** 当攻击者操纵程序向内存区域放入超出该程序分配用量的数据时，就会发生缓冲区溢出攻击。其目标是用指令覆盖内存中的其他信息，这些指令可能会被系统上运行的其他进程执行。

**13. A.** 在中间人攻击中，攻击者欺骗用户与其通信，从而拦截或篡改数据。证书绑定将证书与特定主机关联，防止攻击者使用有效证书冒充其他主机。证书透明度是一种公开记录和监控证书颁发的机制。证书吊销用于撤销已颁发证书的有效性。

**9. C.** 当第 11 位员工加入 Acme Widgets 时，他们将需要与每位现有员工共享一个密钥。现有员工有 10 位，因此需要 10 个新密钥。
