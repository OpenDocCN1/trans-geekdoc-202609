

## 敏捷开发

**敏捷**软件开发是一个迭代和增量的过程，而不是瀑布模型和螺旋模型所采用的线性过程。敏捷植根于《敏捷软件开发宣言》，该文档包含四个基本前提：

*   个体和互动胜过流程和工具。
*   可工作的软件胜过详尽的文档。
*   客户合作胜过合同谈判。
*   响应变化胜过遵循计划。

如果你习惯了瀑布或螺旋开发流程，敏捷将显著区别于敏捷前辈们所采用的以规划、设计和文档为中心的方法。敏捷方法倾向于将工作拆分为更小的单元，从而使工作能够更快完成，并减少前期规划。它专注于适应需求，而非预测需求，主要里程碑在流程早期确定，但随着项目的持续开发可能会发生变化。

工作通常被分解为称为**冲刺**的短时工作会话，持续时间可以从几天到几周不等。[图 6.4](#c06.xhtml#c06-fig-0004) 展示了一个包含多个冲刺的敏捷项目方法论的简化视图。当开发人员和客户同意任务完成，或分配给冲刺的时间用完时，开发工作即告完成。

敏捷方法论基于 12 条原则：

*   通过早期且持续地交付软件，确保客户满意。
*   欢迎需求变更，即使是在开发后期。
*   频繁交付可工作的软件（以周为单位，而非月）。
*   确保开发人员与业务人员之间每天的合作。
*   项目应围绕有动力的个体构建，给予他们所需的支持、信任和环境以取得成功。
*   面对面交谈是向开发团队内部传递信息的最高效方式。
*   以可工作的软件作为进度的主要度量标准。
*   开发应保持可持续的步调，能够持续维持。
*   持续关注技术卓越和良好设计。
*   简洁性——即最大化未完成工作量的艺术——至关重要。
*   最佳架构、需求和设计源自自组织团队。
*   团队应定期反思如何提高效率，并相应地调整行为。

这些原则驱动了一种 SDLC 流程，其正式结构不如螺旋模型或瀑布模型严谨，但提供了许多客户反馈和修订的机会。它能更灵活地应对问题，并通常允许更快的客户反馈——这在发现安全问题时是一大优势。

### DevSecOps 和 DevOps

**DevOps** 将软件开发和 IT 运维相结合，旨在优化 SDLC。这是通过使用称为**工具链**的工具集合来实现的，旨在改进软件开发生命周期中的编码、构建和测试、打包、发布、配置和配置管理以及监控等环节。

当然，DevOps 也应将安全融入其中。术语 **DevSecOps** 将安全描述为 DevOps 模型的一部分。在该模型中，安全是整个开发和运维周期中共同承担的责任。这意味着将安全集成到设计、开发、测试以及生产应用程序和服务的运维工作中。

在 DevSecOps 模型中，安全从业者的角色包括威胁分析和沟通、规划、测试、提供反馈，当然还有持续改进和安全意识职责。要做到这一点，需要深入了解组织的风险承受能力，以及了解 DevSecOps 环境中其他参与者在做什么以及何时做。DevOps 和 DevSecOps 通常与持续集成和持续部署方法相结合，它们可以依赖自动化安全测试、集成安全工具（包括扫描、更新和配置管理工具）来帮助确保安全。

#### 持续集成和持续部署

**持续集成**（**CI**）是一种开发实践，要求将代码持续、定期地签入共享代码库。在 CI 环境中，频率可以从每天几次到非常频繁的签入和自动化构建过程不等。这种方法的主要目标是启用自动化和脚本，以实施自动化的行动方案，从而实现代码的持续交付。

由于持续集成依赖自动化构建过程，因此也需要自动化测试。它也经常与**持续部署**（**CD**）（有时称为持续交付）配对使用，后者在测试通过后自动将测试过的变更推送到生产环境。

使用持续集成和持续部署方法要求将**持续验证**和自动化安全测试构建到管道测试过程中。这可能导致新漏洞被部署到生产环境，并可能允许不受信任或恶意开发人员将缺陷插入已部署的代码中，然后在下一个周期的部移除该代码。这意味着日志记录、报告和**持续监控**都必须设计为适应 CI/CD 流程。

## 面向安全的设计与编码

作为安全专业人员参与 SDLC，为提高应用程序安全性提供了重要机会。首次协助软件安全的机会出现在需求收集和设计阶段，此时安全可以作为需求的一部分内置其中，然后基于这些需求进行设计。随后，在开发过程中，安全编码技术、代码审查和测试可以提高所开发代码的质量和安全性。

在测试阶段，可以使用 Web 应用安全扫描器或渗透测试技术等工具对完全集成的软件进行测试。这还为持续的安全运营奠定了基础，通过为未来的安全扫描以及补丁和更新期间的回归测试建立基线。贯穿这些步骤，了解开发人员面临、制造和发现的常见安全问题会有所帮助。

### 安全编码实践

安全编码实践的最佳资源之一是开放 Web 应用安全项目（OWASP）。OWASP 是一个广泛的开发人员和安全从业者社区的家园，它托管了许多社区开发的标准、指南和最佳实践文档，以及大量开源工具。OWASP 提供了定期更新的主动控制清单，不仅作为一套有用的最佳实践供审查，也作为了解 Web 应用安全威胁逐年变化的一种方式。

以下是 OWASP 2018 年的顶级主动控制措施及其简要说明：

*   **定义安全需求** — 在整个开发过程中实施安全。
*   **利用安全框架和库** — 预先存在的安全功能可以使保护应用程序更容易。
*   **安全数据库访问** — 预构建 SQL 查询以防止注入，并为安全访问配置数据库。
*   **编码和转义数据** — 移除特殊字符。
*   **验证所有输入** — 将用户输入视为不可信并进行适当过滤。
