

# 网络与安全协议

网络通过在不同网络层运行的多种不同协议来传输流量。虽然可以通过为每个可能的系统使用加密通道来保护网络，但在大多数情况下，网络并不会加密每一个端到端的连接。因此，正确选择和实施安全协议对于纵深防御策略至关重要。安全协议有助于确保系统或网络遭到入侵时，不会导致网络流量进一步暴露。

## 使用安全协议

安全协议在网络和基础设施的许多部分都有其用武之地。安全专业人员需要能够为以下每种场景推荐合适的协议：

*   **语音和视频**依赖许多常见协议。视频会议工具通常依赖 `HTTPS`，但会话发起协议（`SIP`）和实时传输协议（`RTP`）的安全版本分别以 `SIPS` 和 `SRTP` 的形式存在，它们也被用于确保通信流量的安全。
*   网络时间协议（`NTP`）的安全版本称为 `NTS`，但 `NTS` 尚未被广泛采用。正如你在本章将了解到的许多其他协议一样，`NTS` 依赖 `TLS`。与其他协议不同，`NTS` 并不保护时间数据本身。相反，它专注于认证，以确保时间信息来自受信任的服务器且在传输过程中未被篡改。
*   **电子邮件和 Web 流量**依赖许多安全选项，包括 `HTTPS`、`IMAPS`、`POPS`，以及域名消息认证、报告和一致性（`DMARC`）、域名密钥识别邮件（`DKIM`）和发件人策略框架（`SPF`）等安全协议。
*   文件传输协议（`FTP`）已在很大程度上被 `HTTPS` 文件传输以及 `SFTP` 或 `FTPS` 的组合所取代，具体取决于组织的偏好和需求。
*   目录服务（如 `LDAP`）可以迁移到 `LDAPS`，即 `LDAP` 的安全版本。
*   **远程访问技术**——包括 Shell 访问，曾经通过 `telnet` 实现，现在几乎完全通过 `SSH` 完成——也可以得到保护。微软的 `RDP` 默认加密，但其他远程访问工具可能使用其他协议（包括 `HTTPS`）来确保其流量不被暴露。
*   **域名解析**仍然是一个安全挑战，长期以来的多次努力对 `DNS` 协议安全性的影响有限。
*   **路由和交换协议安全**可能很复杂，边界网关协议（`BGP`）等协议缺乏内置安全功能。因此，`BGP` 劫持攻击和其他路由攻击仍然可能发生。在许多情况下，组织无法依赖安全协议，需要围绕这一缺陷进行设计。
*   使用 `DHCP` 进行**网络地址分配**不提供安全协议，针对 `DHCP` 攻击的网络保护依赖于检测和响应，而非安全协议。
*   **订阅服务**（如云工具和类似服务）通常利用 `HTTPS`，但也可能为其特定用例提供其他安全协议。可能的订阅和服务类型种类繁多，这意味着如果可用选项存在，必须单独评估这些服务，架构和设计审查以及数据流审查都是保护订阅服务流量最佳实践的一部分。

上述可能的安全选项清单很长，但 `DHCP`、`NTP`、`BGP` 和 `DHCP` 缺乏安全协议这一显著事实表明，虽然安全协议是安全设计的有用组成部分，但它们只是设计过程的一部分。作为安全专业人员，你的评估应确定是否包含合适的安全协议选项、是否正在使用以及是否配置正确。即使正在使用安全协议，你还必须评估现有的其他安全层，以确定设计或实施是否具有适当的安全性，以应对使用过程中将面临的风险。

## 安全协议

Security+ 考试重点关注许多常见协议，考生需要了解如何识别和实施它们。在阅读本节时，请考虑何时建议切换到安全协议、两种协议是否可能在环境中共存，以及如果实施该协议还需要考虑哪些额外因素。这些因素包括客户端配置要求、切换到备用端口、不同的客户端软件包、对可能无法直接监控加密流量的安全工具的影响等类似问题。

组织依赖各种各样的服务，其中许多服务的原始实现（如文件传输、远程 Shell 访问、电子邮件检索、Web 浏览等）均为明文实现，这使得流量很容易被捕获、分析和修改。这意味着这些服务所依赖的流量的机密性和完整性无法得到保证，从而促使这些协议的安全版本得以实施。安全分析师经常被要求识别不安全的服务，并推荐或协助实施安全替代方案。

[表 12.2](#c12.xhtml#c12-tbl-0002) 列出了 Security+ 考试大纲中常见的协议及其安全替代方案。许多安全协议依赖 `TLS` 来保护流量，而其他协议则实现 `AES` 加密或使用其他技术来确保其传输数据的机密性和完整性。许多协议为安全版本使用不同的端口，但其他协议则依赖初始协商或服务请求来确定流量是否将被保护。

**表 12.2** 安全与非安全协议

| 非安全协议 | 原始端口 | 安全协议选项 | 安全端口 | 备注 |
| --- | --- | --- | --- | --- |
| `DNS` | `UDP/TCP 53` | `DNSSEC` | `UDP/TCP 53` | |
| `FTP` | `TCP 21 (and 20)` | `FTPS` | `TCP 21` 显式模式和 `990` 隐式模式 (`FTPS`) | 使用 `TLS` |
| `FTP` | `TCP 21 (and 20)` | `SFTP` | `TCP 22` (`SSH`) | 使用 `SSH` |
| `HTTP` | `TCP 80` | `HTTPS` | `TCP 443` | 使用 `TLS` |
| `IMAP` | `TCP 143` | `IMAPS` | `TCP 993` | 使用 `TLS` |
| `LDAP` | `UDP and TCP 389` | `LDAPS` | `TCP 636` | 使用 `TLS` |
| `POP3` | `TCP 110` | `POP3S` | `TCP 995` | 使用 `TLS` |
| `RTP` | `UDP 16384-32767` | `SRTP` | `UDP 5004` | |
| `SNMP` | `UDP 161 and 162` | `SNMPv3` | `UDP 161 and 162` | |
| `Telnet` | `TCP 23` | `SSH` | `TCP 22` | |

考生应识别出上述每一项：

*   **域名系统安全扩展**（`DNSSEC`）专注于确保 `DNS` 信息未被修改或篡改，但它不像此处列出的许多其他安全协议那样提供机密性。`DNSSEC` 使用数字签名，允许查询 `DNSSEC` 服务器的系统验证服务器的签名是否与 `DNS` 记录匹配。`DNSSEC` 还可用于为 `IPSec` 密钥、`SSH` 指纹和类似记录建立信任链。
*   **简单网络管理协议第 3 版**（`SNMPv3`）通过提供消息源认证、消息完整性验证和通过加密实现的机密性，改进了 `SNMP` 的早期版本。它支持多个安全级别，但只有 `authPriv` 级别使用加密，这意味着不安全的 `SNMPv3` 实现仍然可能存在。仅使用 `SNMPv3` 并不能自动使 `SNMP` 信息变得安全。
