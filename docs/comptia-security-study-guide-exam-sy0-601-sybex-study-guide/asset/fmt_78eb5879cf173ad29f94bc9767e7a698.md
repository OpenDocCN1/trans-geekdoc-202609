
虚拟机随后运行在 Hypervisor 提供的此虚拟基础设施之上，运行标准操作系统，如 Windows 和 Linux 变体。虚拟机可能不知道它们正在虚拟化环境中运行，因为 Hypervisor 欺骗它们，让它们以为拥有对底层硬件的正常访问权限，而实际上，这些硬件与其他系统共享。

### Hypervisor

Hypervisor 的主要职责是强制执行虚拟机之间的`isolation`（隔离）。这意味着 Hypervisor 必须向每个虚拟机呈现一个完全独立的物理环境的假象，该环境专供该虚拟机使用。从运营角度来看，隔离确保虚拟机不会相互干扰彼此的操作。从安全角度来看，这意味着虚拟机无法访问或更改分配给另一个虚拟机的信息或资源。

Hypervisor 主要有两种类型：

*   **Type I Hypervisor**（第 I 类 Hypervisor），也称为**Bare Metal Hypervisor**（裸金属 Hypervisor），直接在底层硬件之上运行。随后，Hypervisor 为每个虚拟机支持 Guest OS（客户操作系统），如[图 10.9](#c10.xhtml#c10-fig-0009)所示。这是数据中心虚拟化中最常用的模型，因为它效率极高。

    ![FIGURE 10.9 Type I hypervisor](images/c10f009.png)

    **[图 10.9](#c10.xhtml#R_c10-fig-0009) Type I Hypervisor**

*   **Type II Hypervisor**（第 II 类 Hypervisor）作为应用程序运行在现有操作系统之上，如[图 10.10](#c10.xhtml#c10-fig-0010)所示。在此方法中，操作系统支持 Hypervisor，而 Hypervisor 从 Host OS（宿主操作系统）为每个 Guest OS 请求资源。此模型常用于在个人计算机上为开发人员、技术人员及其他需要运行自己虚拟机的人员提供虚拟化环境。它比裸金属虚拟化效率低，因为宿主操作系统引入了一个消耗资源的低效层。

    **[图 10.10](#c10.xhtml#R_c10-fig-0010) Type II Hypervisor**

## 云基础设施组件

IaaS 计算环境为组织提供各种计算资源的访问权限，包括计算容量、存储和网络。这些资源以灵活的方式提供，通常可在请求后立即使用。

### 云计算资源

计算容量是组织迁移到云的主要需求之一。当它们寻求增强或替换自有数据中心中运行的服务器时，会寻求云中的虚拟化服务器和其他提供计算容量的方式。所有这些技术均受益于云的动态资源分配，允许管理员根据需求变化自动或手动添加和移除资源。

#### 虚拟化服务器

虚拟机是云中计算容量的基本构建块。组织可配置运行大多数常见操作系统的服务器，并指定满足业务需求所需的特定 CPU 核心数、RAM 容量和存储容量，如[图 10.11](#c10.xhtml#c10-fig-0011)所示。服务器实例的成本通常按小时费率累计，该费率根据服务器消耗的计算、内存和存储资源而异。

配置好虚拟化服务器后，您可以像与自有数据中心中运行的服务器交互一样与其交互。[图 10.12](#c10.xhtml#c10-fig-0012)显示了到 Linux IaaS 实例的 SSH 连接。

[图 10.13](#c10.xhtml#c10-fig-0013)显示了使用 Microsoft Remote Desktop 工具通过远程桌面协议（RDP）连接到 Windows IaaS 实例以获取图形用户界面。这些工具允许管理员正常地与虚拟化服务器交互。

#### 容器

`Containers`（容器）提供应用级虚拟化。容器不创建需要自己操作系统的复杂虚拟机，而是打包应用程序，允许将它们视为可跨操作系统和硬件平台移植的虚拟化单元。

实施容器化的组织运行容器化平台（如 `Docker`），这些平台为操作系统资源提供标准化接口。无论底层操作系统或硬件如何，此接口保持一致，接口的一致性使容器能根据需要在系统间移动。

容器化平台与虚拟化平台共享许多相同的安全考量。它们必须强制执行容器间的隔离，以防止运行在一个容器中的应用程序意外或故意与分配给另一个容器的资源交互而导致运营和安全问题。

### 云存储资源

基础设施提供商还为客户提供存储资源，包括与其计算产品配套的存储，以及用于构建其他云架构的独立存储产品。这些存储产品主要分两大类：

*   **Block Storage**（块存储）为虚拟服务器实例分配大量存储卷。这些卷随后由这些服务器实例上的操作系统格式化为虚拟磁盘，并像使用物理驱动器一样使用。AWS 通过其 `Elastic Block Storage (EBS)` 服务提供块存储。[图 10.14](#c10.xhtml#c10-fig-0014)显示了一系列分配用于虚拟服务器的 EBS 卷。

*   **Object Storage**（对象存储）使客户能够将文件放入存储桶，并将每个文件视为可通过 Web 或提供商 API 访问的独立实体。对象存储向最终用户隐藏存储细节，用户无需知道或关心底层磁盘。AWS `Simple Storage Service (S3)` 是对象存储的一个示例。[图 10.15](#c10.xhtml#c10-fig-0015)显示了一个 S3 存储桶示例。

    ![FIGURE 10.14 AWS Elastic Block Storage (EBS) volumes](images/c10f014.png)

    **[图 10.14](#c10.xhtml#R_c10-fig-0014) AWS Elastic Block Storage (EBS) 卷**

    ![FIGURE 10.15 AWS Simple Storage Service (S3) bucket](images/c10f015.png)

    **[图 10.15](#c10.xhtml#R_c10-fig-0015) AWS Simple Storage Service (S3) 存储桶**

在使用云存储时，请务必将以下三个关键安全考量牢记在心：

*   **正确设置权限**。确保您仔细关注放置在存储上的访问策略。这对于对象存储尤为重要，因为几次错误的点击可能会无意中将敏感文件发布到 Web 上。

*   **考虑高可用性和持久性选项**。云提供商向用户隐藏实现细节，但这并不意味着它们能免疫硬件故障。请使用提供商的复制功能或实施自己的复制，以满足可用性和完整性要求。
