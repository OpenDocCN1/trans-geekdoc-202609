

# 网络分段与访问控制

网络安全中最常见的概念之一是**网络分段**的理念。网络分段根据信任边界、功能需求或其他有助于组织实施控制或辅助功能的原因，将网络划分为逻辑或物理分组。许多技术和概念用于分段，但最常见的之一是使用**虚拟局域网（VLAN）**。VLAN 在数据链路层建立一个被分段的广播域。交换机或其他设备利用 VLAN 标签创建 VLAN，使跨越多个网络设备（如交换机）的不同端口都能属于同一个 VLAN，而插在这些交换机上的其他系统则不在同一个广播域中。

许多网络设计概念描述了网络分段的具体实现：

*   **DMZ（非军事区）**，是包含暴露于低信任区域的系统的网络区域。DMZ 通常用于容纳 Web 服务器或其他面向互联网的设备，但也可描述信任级别不同的内部用途。
*   **内部网**是为向员工或组织其他成员提供信息而建立的内部网络，通常受保护免受外部访问。
*   **外部网**是为外部访问而建立的网络，通常由合作伙伴或客户访问，而非面向大众公众。

尽管许多网络设计过去假定威胁来自用于定义网络段的安全边界之外，但**零信任**网络的核心概念是：无论是内部还是外部的人员或系统，均不予信任。因此，零信任网络应在系统之间以及安全边界处都包含安全措施。

## 网络访问控制

网络分段有助于将网络划分为逻辑安全区域，但保护网络免受未授权访问同样重要。这就是**网络访问控制（NAC）**，有时称为网络准入控制，发挥作用的地方。NAC 技术专注于确定系统或设备是否应被允许连接到网络。如果通过了准入要求，NAC 会将其置于适当的区域中。

为完成此任务，NAC 可使用安装在计算机上的软件代理执行安全检查。或者该过程可能是无代理的，通过浏览器或其他方式运行，无需在本地安装软件。功能各异，软件代理通常能更深入地通过验证补丁级别、安全设置、杀毒软件版本及其他设置和细节来确定机器的安全状态，然后再准许系统接入网络。某些 NAC 解决方案还会跟踪用户行为，如果系统从事可疑行为，可将其从网络中移除。

由于 NAC 能够验证系统的安全状态，它可以成为一种有效的策略执行工具。如果系统不满足安全目标，或存在问题，可将其置于隔离网络中。在那里对系统进行修复并重新检查，或者直接禁止其连接到网络。

NAC 检查可在设备被允许接入网络前（准入前）或连接后（准入后）进行。代理或无代理解决方案与准入前或准入后设计的组合，取决于安全目标和组织所选工具的技术能力。基于代理的 NAC 需要安装，因此增加了复杂性和维护工作，但提供了更深入的洞察和控制。无代理安装轻量级且易于处理，适用于机器可能不受集中管理或设备可能不支持 NAC 代理的用户。然而，无代理安装提供的细节较少。准入前 NAC 决策可将潜在危险系统拒之门外；准入后决策有助于响应，并防止失败的 NAC 接入尝试阻碍业务。

## 端口安全与端口级防护

保护网络免受连接设备的威胁，不仅需要使用 NAC 验证其安全状态。许多防护措施专注于确保网络本身不因在其上传输的流量而陷入危险。

**端口安全**是一项允许你限制单个端口上可使用的 MAC 地址数量的功能。这可防止许多可能的问题，包括 MAC（硬件）地址欺骗、内容可寻址存储器（CAM）表溢出，以及在某些情况下插入额外网络设备以扩展网络。尽管端口安全实现各异，但大多数端口安全功能允许你通过设置最大 MAC 地址数量来动态锁定端口，或静态锁定端口以仅允许特定 MAC 地址。虽然这种类型的 MAC 过滤不如 NAC 细致且提供的信息较少，但它依然有用。

由于欺骗 MAC 地址相对容易，不应依赖端口安全来防止不受信系统连接。尽管如此，配置端口安全有助于在 NAC 不可用或未使用时，防止攻击者轻易连接到网络。它还可防止原本可能发生的 CAM 表溢出攻击。

除了端口安全，协议级防护是交换机和其他网络设备提供的重要安全功能。这些包括：

*   **环路防护**专注于检测环路并禁用端口，以防止环路引发问题。生成树协议（STP）使用桥协议数据单元，以及思科的环回检测功能等防环实现，发送带有交换机标识符的帧，交换机随即监控这些帧以防止环路。虽然环路可以简单到一根网线两端插在同一交换机上，但环路也可能由插在不同交换机上的网线、反向插入的防火墙、多张网卡插在同一网络不同部分的设备，以及网络中发现的其他错误配置导致。
*   **广播风暴防护**，有时称为风暴控制，防止广播数据包在遍历网络时被放大。防止广播风暴依赖多项功能，如在将连接用户设备的端口上提供环路保护、在交换机上启用 STP 以确保检测并禁用环路，以及限制广播流量速率。
*   **桥协议数据单元（BPDU）防护**通过防止不应发送 BPDU 消息的端口发送它们来保护 STP。它通常应用于将插入用户设备和服务器的交换机端口。连接交换机的端口不会开启 BPDU，因为它们可能需要发送 BPDU 消息，作为网络底层管理和控制的一部分，提供关于端口、地址、优先级和成本的信息。
*   **动态主机配置协议（DHCP）侦听**专注于防止流氓 DHCP 服务器向托管网络中的客户端分发 IP 地址。DHCP 侦听会丢弃任何不在受信服务器列表中的 DHCP 服务器发来的消息，但也可配置附加选项，如阻止源 MAC 与网卡硬件 MAC 不匹配的 DHCP 消息。最后一个安全选项是：如果释放或拒绝 DHCP 提供的消息不是来自发出请求的同一端口，则丢弃该消息，防止攻击者导致 DHCP 提供或续约失败。
