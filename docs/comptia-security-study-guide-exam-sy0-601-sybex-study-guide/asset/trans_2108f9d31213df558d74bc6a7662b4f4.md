

设备驱动程序需要对操作系统进行低级访问，并以管理员权限运行。如果攻击者能说服用户在其计算机上安装恶意驱动程序，该恶意软件就能完全控制系统。

攻击者实现这一点的一种方法是*重构*现有驱动程序。如果他们能访问驱动程序的源代码，就可以对其进行修改，使其也包含恶意软件元素。然而，在实践中这非常难以实现，因为获取驱动程序的源代码并不容易。

无法访问驱动程序源代码的攻击者可以使用一种称为*垫片*的技术。这会获取一个合法驱动程序，并在其外部包裹一个恶意驱动程序。恶意驱动程序（称为垫片）接收来自操作系统的请求，并将其直接传递给合法驱动程序，以便设备正常运行。然而，该驱动程序也可以在后台执行其恶意软件载荷。

幸运的是，现代操作系统都包含针对恶意驱动程序的保护措施。其中最重要的保护是代码签名。设备制造商编写驱动程序，然后对其应用数字签名，以便操作系统能够验证其真实性。如果驱动程序未经过数字签名，操作系统可能会警告用户存在可疑驱动程序，或直接阻止其安装。

驱动程序的特权性质使其能深度访问操作系统。安全专业人员必须确保其组织中使用的驱动程序是合法的，且未被修改用于执行恶意活动。

## 摘要

软件在每个组织中都发挥着不可或缺的作用，执行的任务范围从财务交易到敏感物理基础设施组件的管理。网络安全专业人员必须确保其环境中使用的软件经过严格测试，以确保其满足业务需求，且不会使组织面临严重的网络安全风险。

实现这一目标需要深入了解源代码以及客户端-服务器和 Web 应用程序部署中可能出现的不同类型的漏洞。在本章中，您了解了许多此类漏洞以及用于管理软件安全风险的工具。

## 考试要点

**了解如何分析与应用程序攻击相关的指标。** 软件应用程序可能遭受各种漏洞的影响，使其容易受到攻击。您应该熟悉这些攻击，包括权限提升、跨站脚本、注入攻击、请求伪造攻击，以及攻击者利用应用程序代码的许多其他方式。了解这些攻击背后的方法有助于安全专业人员建立充分的防御并识别针对其组织的攻击。

**理解安全软件开发概念。** 软件应使用标准化的软件开发生命周期来创建，该周期将软件移动通过开发、测试、暂存和生产环境。开发人员应了解与代码重用和软件多样性相关的问题。Web 应用程序的开发应符合行业标准原则，例如开放 Web 应用程序安全项目 (OWASP) 制定的原则。

**解释安全代码部署和自动化概念。** 代码仓库充当版本控制机制，以及代码安全预配和取消预配的集中授权机构。开发人员和运维团队应共同制定自动化行动方案，因为他们在实施创建和部署软件的 DevOps 方法。软件应用程序的设计应支持可扩展性和弹性。

**了解如何实施数据库安全控制。** 数据库通常存储组织最敏感的信息，应采取数据库安全控制来充分保护该信息。这始于使用规范化的数据库设计，并继续使用存储过程与数据库交互。存储在数据库中的敏感信息应通过数据最小化、数据标记化，以及加盐和哈希的组合来保护。

**了解如何实施应用程序安全控制。** 应用程序安全应成为安全运营原则的重中之重。这包括通过输入验证保护代码。依赖 Cookie 进行会话管理的 Web 应用程序应通过传输加密来保护这些 Cookie。代码应定期接受代码审查以及静态和动态测试。
