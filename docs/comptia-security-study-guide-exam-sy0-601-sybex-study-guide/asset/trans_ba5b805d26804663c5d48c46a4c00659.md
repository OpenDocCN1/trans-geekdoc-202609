

## 对等僵尸网络控制模型

除了客户端-服务器僵尸网络外，[图 3.2](#c03.xhtml#c03-fig-0002) 所示的对等僵尸网络控制模型也经常被使用。对等网络将僵尸节点相互连接，这使得攻击者更难通过攻陷单个中央服务器或少量已知的 C&C IP 地址或域名来摧毁网络。加密的对等流程可能极难识别，尽管监控网络流量以查找基于行为的模式以及大型多组织数据集的机器学习工具可以提供帮助。

![图 3.2 对等僵尸网络控制模型](images/c03f002.png)

[**图 3.2**](#c03.xhtml#R_c03-fig-0002) 对等僵尸网络控制模型

许多僵尸网络使用快速通量 DNS，它利用许多 IP 地址来响应一个或多个完全合格域名的查询。频繁更新（快速通量）意味着控制主机网络中的许多系统会持续不断地注册和注销其地址，通常每隔几分钟就进行一次。更高级的技术还会对 DNS 区域的 DNS 服务器执行类似的快速更改，使网络更难被摧毁。在受控网络中，可以通过强制 DNS 请求使用组织控制的 DNS 服务器，而不是允许出站 DNS 请求，来防御此类技术。记录所有 DNS 请求在恶意软件狩猎时也能提供有用信息，因为机器生成的 DNS 条目在日志中通常很容易被发现。虽然 IRC 过去常用于僵尸网络控制，但较新的僵尸网络通常使用快速通量 DNS 和伪装成看似无害的 Web、DNS 或其他流量的加密 C&C 通道。

检测僵尸网络通常通过使用网络监控工具（如 IPS 和 IDS）及其他网络流量分析系统来分析僵尸流量来完成。通过逆向工程和分析与僵尸网络相关的恶意软件感染可收集更多数据。底层恶意软件可使用防病毒和反恶意软件工具，以及端点检测和响应工具等进行检测。

### 僵尸网络与分布式拒绝服务 (DDoS) 攻击

僵尸网络可用于攻击服务和应用程序，针对应用程序的分布式拒绝服务 (DDoS) 攻击是僵尸网络的一种常见应用。僵尸网络依赖其规模（可淹没应用程序和服务）以及其中系统的数量（使得几乎无法识别哪些主机在恶意消耗资源或发送带有恶意意图的看似合法流量）。

识别僵尸网络驱动的 DDoS 攻击需要监控网络流量、趋势，有时还需要来自互联网服务提供商的上游可见性。其症状可能难以与合法流量的大幅增长区分开来，这意味着可能需要安全信息和事件管理 (SIEM) 系统等安全工具，它们能关联来自多个来源的数据。行为分析工具也有助于将 DDoS 与更典型的流量模式区分开来。

### 键盘记录器

*键盘记录器* 是从键盘捕获按键的程序，尽管键盘记录器应用程序也可能捕获其他输入，如鼠标移动、触摸屏输入或连接设备的信用卡刷卡数据。键盘记录器的工作方式多种多样，范围从从内核捕获数据的工具，到 API 或脚本，甚至直接从内存捕获。无论它们如何捕获数据，键盘记录器的目标都是捕获用户输入，以便攻击者分析和利用。

防止软件键盘记录通常侧重于常规安全最佳实践，以确保不安装包含键盘记录器的恶意软件，包括打补丁和系统管理，以及使用反恶意软件工具。由于许多键盘记录器旨在窃取密码，使用多因素认证 (MFA) 可以帮助限制键盘记录器的影响，即使它无法完全击败键盘记录器本身。

在底层系统不可信的更复杂的安全环境中，使用可启动的 USB 驱动器可以防止使用潜在受损的底层操作系统。

### 逻辑炸弹

与此处描述的其他类型恶意软件不同，*逻辑炸弹* 不是独立的恶意程序。相反，它们是放置在其他程序内部的函数或代码，当设定的条件满足时就会激活。某些恶意软件使用此类代码在特定日期或满足一组条件时激活。虽然与其他类型的恶意软件相比相对罕见，但逻辑炸弹是软件开发和系统管理中的一个考量因素，如果成功激活，可能会产生重大影响。

### 病毒

计算机*病毒* 是能够自我复制和自我传播的恶意程序。病毒需要一种或多种感染机制来传播自身，通常配合某种搜索能力以寻找新的传播目标。病毒通常还具有*触发器*（设定病毒执行的条件）和*有效载荷*（病毒所做、投递或执行的动作）。病毒种类繁多，包括：

*   **驻留型病毒**，在系统或设备运行时保留在内存中
*   **非驻留型病毒**，执行、传播，然后关闭
*   **引导扇区病毒**，驻留在驱动器或存储介质的引导扇区内
*   **宏病毒**，利用文字处理软件或其他工具内部的宏或代码进行传播
*   **电子邮件病毒**，通过电子邮件作为附件或作为邮件本身的一部分利用电子邮件客户端中的缺陷进行传播

### 无文件病毒

*无文件病毒* 攻击在许多关键方面与传统病毒相似。它们通过垃圾邮件和恶意网站等方式传播，并利用浏览器插件和 Web 浏览器本身的缺陷。一旦成功进入系统，它们会将自身注入内存并进行进一步的恶意活动，包括通过注册表项或其他技术在重启时通过相同过程重新感染系统的能力。在其整个活跃生命周期中，它们始终驻留在内存中，从不需要本地文件存储——事实上，许多无文件攻击唯一的存储痕迹就是其持久化技术的痕迹，如 [图 3.3](#c03.xhtml#c03-fig-0003) 所示的注册表项。

正如你从 [图 3.3](#c03.xhtml#c03-fig-0003) 的感染流程图中所预料的那样，无文件攻击需要漏洞才能成功，因此确保浏览器、插件和其他可能被攻击者利用的软件保持最新和受保护，可以防止大多数攻击。使用能够检测脚本工具（如 `PowerShell`）意外行为的反恶意软件工具也有助于阻止无文件病毒。最后，网络级防御（如 IPS）以及基于信誉的保护系统，可以防止潜在脆弱的系统访问已知恶意站点。
