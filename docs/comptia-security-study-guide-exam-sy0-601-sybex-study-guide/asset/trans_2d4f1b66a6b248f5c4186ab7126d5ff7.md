
# 网络 DDoS 攻击与侦察工具

## 常见的网络 DDoS 攻击类型

网络分布式拒绝服务攻击可分为两大类：基于流量的攻击和基于协议的攻击。

### 基于流量的网络 DDoS 攻击

基于流量的网络 DDoS 攻击侧重于海量流量导致拒绝服务状况。某些基于流量的 DDoS 攻击依赖放大技术，利用协议和服务中的缺陷或特性，产生比攻击者发送的流量大得多的流量。基于流量的攻击示例包括 UDP 和 ICMP 洪水攻击：

*   **UDP 洪水攻击**利用了 UDP 不像 TCP 那样使用三次握手这一事实，因此只需发送大量流量，目标主机就会接收并尝试处理，从而执行 UDP 洪水攻击。由于 UDP 不受速率限制或其他保护，且不使用握手，因此攻击系统只需极少资源即可发动 UDP 洪水攻击。可使用具有 UDP 洪水检测规则或模块的 `IDSs` 和 `IPSs` 及其他网络防御设备来检测 UDP 洪水攻击。作为响应过程的一部分，可使用数据包分析器手动检测洪水攻击，但对实时攻击进行手动分析可能具有挑战性，且未必及时。

*   **ICMP 洪水攻击**（有时称为 ping 洪水攻击）发送大量 ICMP 数据包，每个数据包都请求响应。与 UDP 不同，许多现代操作系统对 ICMP 进行了速率限制。ICMP 洪水攻击要求攻击方拥有比防御方更多的总带宽，这也是为什么可能会尝试通过 ICMP 发动分布式拒绝服务攻击。许多组织在网络入口处对 ping 进行速率限制或阻断，以防止此类攻击，它们也可能对安全区域之间的 ICMP 进行速率限制。与 UDP 洪水攻击非常相似，网络安全设备上的检测规则以及手动检测均可使用，但主动防御相对容易且部署非常普遍，尽管如果触及速率限制，可能会丢失一些 ICMP 流量。

### 基于协议的网络 DDoS 攻击

基于协议的网络 DDoS 攻击侧重于网络所用的底层协议。

*   **SYN 洪水攻击**发送三次握手的第一步，但不响应返回的 `SYN-ACK`，从而耗尽 TCP 栈资源。这些攻击是最常见的现代基于协议的网络 DDoS 攻击之一。
*   **早期攻击**针对脆弱的 TCP 栈，采用如**死亡之 Ping** 等攻击，发送过大的 ping 数据包导致许多系统无法处理；以及 **Smurf 攻击**，利用带有伪造发送者地址的 ICMP 广播消息，导致广播域内的系统向所谓的发送者发送流量，从而将其淹没。
*   **分片数据包**、所有 TCP 标志位均置 1 的数据包（**Christmas Tree** 或 **Xmas 攻击**），以及各种其他攻击，均利用了操作系统中网络实现的缺陷和局限性。

安全专业人员需知晓，网络协议的特性及这些协议的具体实现可能被用作攻击的一部分，并且他们可能需要识别这些攻击。

[图 12.4](#c12.xhtml#c12-fig-0004) 显示了在 `Wireshark` 中开启适当过滤器后看到的 SYN 洪水攻击。识别 SYN DDoS 通常意味着查看针对目标主机的流量，并注意到有大量 `SYN` 数据包被发送，但请求方未完成握手的其余部分。请注意，在该图中，单个系统正在发送 SYN 洪水；在真实的 DDoS 中，会显示多个系统作为流量来源。需要按目标系统进行过滤，并确保三次握手未完成，以验证 DDoS 攻击。

## 运营技术 DDoS

**运营技术 (OT)** 是控制建筑、工厂、发电厂及其他行业中设备和系统的软件和硬件。**物联网 (IoT)** 的增长导致更多设备具备网络功能，从而产生了一整套可通过网络攻击的新设备。由于 IoT 设备通常缺乏计算机和网络设备所具备的安全防护，且可用的处理器、内存和存储可能更有限，因此它们比网络上的其他设备更容易受到基于网络的 DDoS 攻击。

尽管 OT DDoS 攻击在 **Security+** 考试大纲中被列为一个独立主题，但大多数运营技术攻击将依赖我们已讨论的相同类型的网络和基于应用程序的 DDoS 攻击。安全从业者需牢记的一个关键要素是：OT 通常具有较少的报告、较少的管理和较少的内置安全功能，这意味着针对 OT 设备和系统的网络 DDoS 和其他攻击的检测与响应，将需要使用外部设备和工具来处理。

在没有额外安全工具的情况下，检测针对 OT 设备或网络的攻击，通常意味着注意到其无响应或似乎已从网络掉线。进一步调查可能会显示设备已崩溃，或虽在线但因不堪重负而不响应网络流量。此时，可启动传统的事件响应和网络事件调查技术。

由于 OT 和 IoT 设备总体上对潜在敌对网络的准备仍不足，设计和架构规划可能是保障其安全的关键控制措施。使用隔离的 `VLAN`、限制网络流量的入站和出站、防止未知设备添加到隔离的 `VLAN`、以及对这些网络进行监控检测，均是防止各类 OT 网络攻击的有用技术。

## 路由、DNS 信息和路径

当你想确定系统是否在线以及发送到该系统的流量延迟时，最简单的工具是 `ping`。`ping` 向目标主机发送 `ICMP` 回显请求数据包，并计算最小、最大和平均往返时间。正如你所料，你可以使用命令行标志来确定发送多少个 ping、载荷大小以及各种其他设置。最有用的标志之一是 `-t` 标志，它会持续发送 ping 直到被停止。运行 `ping -t` 可以显示系统是否突然停止响应，或系统的响应时间是否大幅波动。

了解系统在互联网上的逻辑位置，以及流量从该系统到其他系统将采取的路由，在你试图了解网络拓扑或进行故障排除时也非常有用。Windows 和基于 Linux/Unix 的系统都包含运行路由跟踪命令的功能，该命令将尝试验证系统之间的路由。
