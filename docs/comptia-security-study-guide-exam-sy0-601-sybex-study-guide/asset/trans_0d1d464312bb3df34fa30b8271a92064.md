

## 密钥管理最佳实践

*   切勿将加密密钥存储在存放加密数据的同一系统上。这只会让攻击者更容易得手！
*   对于敏感密钥，可考虑将密钥的一半提供给一名人员，另一半提供给另一名人员。随后，他们必须协作才能重建完整的密钥。这被称为 `split knowledge`（分散知识）原则（本章前面已讨论过）。

当知晓密钥的用户离开组织，或不再被允许访问受该密钥保护的资料时，必须更换密钥，并使用新密钥对所有加密资料重新加密。在对称密码系统中，销毁密钥以移除用户的困难，是组织转向非对称算法的主要原因之一。

### 密钥托管与恢复

密码学是一种强大的工具。像大多数工具一样，它可用于多种有益目的，但也可能被用于恶意意图。为了控制密码技术的爆发式增长，世界各国政府都提出了实施密钥托管系统的想法。这些系统允许政府在有限情况下（如法院命令），从中央存储设施获取特定通信所用的加密密钥。

过去十年间，主要提出了两种密钥托管方法。

*   **公平密码系统** — 在此托管方法中，通信中使用的密钥被分成两份或多份，每份交给一个独立的第三方。每一份单独来看毫无用处，但可重组以获得密钥。当政府获得访问特定密钥的法律授权时，它向各第三方提供法院命令的证据，然后重组密钥。
*   **托管加密标准** — 此托管方法为政府提供了一种解密密文的技术手段。该标准是 Skipjack 算法的基础。

政府监管机构极不可能克服在广泛范围内实施密钥托管所必需的法律和隐私障碍。技术当然是可用的，但公众极不可能接受其所助长的潜在政府侵入性。

## 非对称密码学

回顾本章前面的内容，`public key cryptosystems`（公钥密码系统）依赖于分配给每个密码系统用户的一对密钥。每个用户同时维护一个公钥和一个私钥。顾名思义，公钥密码系统用户将其公钥免费提供给任何想要通信的人。第三方仅持有公钥并不会给密码系统带来任何弱点。另一方面，私钥仅供密钥所有者个人使用。它绝不与任何其他密码系统用户共享。

公钥密码系统用户之间的正常通信非常直接，如 [图 7.8](#c07.xhtml#c07-fig-0008) 所示。请注意，该过程不要求共享私钥。发送方使用接收方的公钥加密明文消息（`P`）以生成密文消息（`C`）。当接收方打开密文消息时，他们使用自己的私钥对其解密，以重建原始明文消息。

一旦发送方使用接收方的公钥加密消息，在不知道接收方私钥（用于生成消息的公私钥对的另一半）的情况下，任何用户（包括发送方）都无法解密该消息。这就是公钥密码学的妙处——公钥可通过不安全通信自由共享，随后用于在互不相识的用户之间创建安全通信通道。

您在上一章还了解到，公钥密码学涉及更高程度的计算复杂性。公钥系统中使用的密钥必须比私钥系统中的密钥更长，才能产生同等强度的密码系统。

### RSA

最著名的公钥密码系统以其创建者的名字命名。1977 年，Ronald Rivest、Adi Shamir 和 Leonard Adleman 提出了 `RSA public key algorithm`（RSA 公钥算法），该算法至今仍是全球标准。他们为该算法申请了专利，并成立了名为 RSA Security 的商业企业，以开发其安全技术的主流实现。如今，RSA 算法已发布到公共领域，并广泛用于安全通信。

RSA 算法依赖于分解大素数所固有的计算难度。密码系统的每个用户使用该算法生成一对公钥和私钥。密钥生成的具体细节超出了考试范围，但您应记住，它基于分解大素数的复杂性。

### 椭圆曲线

1985 年，两位数学家——华盛顿大学的 Neal Koblitz 和 IBM 的 Victor Miller——独立提出将 `elliptic curve cryptography`（ECC，椭圆曲线密码学）理论应用于开发安全密码系统。

任何椭圆曲线均可由以下方程定义：

```
y2 = x3 + ax + b
```

在该方程中，`x`、`y`、`a` 和 `b` 均为实数。每条椭圆曲线都有一个对应的 `elliptic curve group`（椭圆曲线群），由椭圆曲线上的点以及位于无穷远处的点 `O` 组成。同一椭圆曲线群内的两个点（`P` 和 `Q`）可通过椭圆曲线加法算法相加。该运算表示为：

```
P + Q
```

通过假设 `Q` 是 `P` 的倍数，即以下含义，可将此问题扩展为乘法运算：

```
Q = xP
```

计算机科学家和数学家认为，即使已知 `P` 和 `Q`，找到 `x` 也极其困难。这个被称为 `elliptic curve discrete logarithm problem`（椭圆曲线离散对数问题）的难题，构成了椭圆曲线密码学的基础。人们普遍认为，该问题比 RSA 密码系统所基于的素因子分解问题，以及 Diffie-Hellman 所利用的标准离散对数问题，都更难解决。

## 哈希函数

本章稍后您将了解密码系统如何实现数字签名，以证明消息源自密码系统的特定用户，并确保消息在双方传输过程中未被篡改。在完全理解该概念之前，我们必须先解释 `hash functions`（哈希函数）的概念。我们将探讨哈希函数的基础知识，并介绍现代数字签名算法中使用的几种常见哈希函数。

哈希函数的目的非常简单——它们接收一条可能很长的消息，并根据消息内容生成一个唯一的输出值。该值通常称为 `message digest`（消息摘要）。消息摘要可由消息发送方生成，并随完整消息一起传输给接收方，主要有两个原因。

首先，接收方可使用相同的哈希函数，从完整消息中重新计算消息摘要。然后，他们可将计算出的消息摘要与传输的摘要进行比较，以确保发送方发送的消息与接收方收到的消息完全一致。如果消息摘要不匹配，则意味着消息在传输过程中以某种方式被修改了。重要的是要注意，消息必须 `exactly`（完全）相同，摘要才会匹配。如果消息在间距、标点或内容上即使有细微差别，消息摘要值也会完全不同。无法通过比较摘要来判断两条消息的差异程度。即使是细微的差别，也会生成完全不同的摘要值。
