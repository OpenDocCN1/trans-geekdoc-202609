

# 嵌入式系统与射频协议

嵌入式系统还可以利用专门为其设计的射频协议。`Zigbee` 就是一种为个人局域网设计的网络协议示例，此类网络常见于家庭自动化场景。`Zigbee` 和 `Z-wave` 等协议为那些不需要 `Wi-Fi` 和 `Bluetooth` 所提供的带宽及附加功能的设备提供了低功耗、点对点的通信。这意味着它们在通信范围和可传输数据量方面存在限制，并且由于它们是为家庭自动化及类似用途设计的，因此不具备强大的安全模型。作为安全从业者，你应该意识到，使用 `Zigbee` 等协议通信的设备可能会作为楼宇监控或其他用途的一部分被部署，且不太可能具备企业级的管理、监控或安全能力。

`Zigbee` 等射频系统可以是窄带或宽带。窄带无线电系统通常噪声较小，因此具有更好的范围和灵敏度；而宽带无线电因为拥有更多可用的无线频谱，可以传输更多数据。Security+ 考试大纲还提到了基带无线电，这是一种包含接近零频率的信号类型。

## 嵌入式系统的安全约束

嵌入式系统存在许多约束，安全解决方案必须将其纳入考量。由于嵌入式系统可能能力有限、部署和管理选项各异，且生命周期延长，因此保护它们需要投入额外的思考。

当你考虑嵌入式系统的安全性时，应考虑以下因素：

*   嵌入式系统的整体计算能力和容量通常远低于传统 PC 或移动设备。尽管这可能因情况而异，但嵌入式系统可能使用低功耗处理器、拥有较少内存，且存储空间非常有限。这意味着可能不具备加密处理所需的算力，或者必须在 CPU 周期的其他需求之间进行平衡。同时，有限的内存和存储容量意味着可能没有能力运行额外的安全工具，如防火墙、反恶意软件工具，或你习惯在设计中包含的其他安全工具。

*   嵌入式系统可能不连接网络。它们可能完全没有网络连接，或者虽有连接但因环境、运营或安全顾虑而未启用或使用。事实上，由于许多嵌入式系统部署在传统网络之外，或处于连接性可能受限的区域，即使它们具备内置无线网络能力，也可能没有足够的有效范围连接到可用网络。因此，你可能无法远程修补、监控或维护这些设备。嵌入式设备可能需要作为独立单元进行保护。

*   没有网络连接、CPU 和内存容量以及其他要素，身份认证也很可能无法实现。事实上，由于安全或可用性因素，对嵌入式系统进行身份认证可能并不合乎需求。你将遇到的许多使用嵌入式系统的设备内置于工业机械、传感器和监控系统，甚至家用电器中。没有身份认证，就需要确定其他安全模型，以确保对嵌入式系统的更改经过授权。

*   嵌入式系统成本可能很低，但许多实际上成本极高，因为它们是大型工业或专用设备中的一个组件。因此，简单地更换有漏洞的设备可能是不可能的，这要求采取补偿控制或做出特殊的设计决策，以确保设备保持安全，且不会给其所属组织带来问题。

鉴于所有这些限制，嵌入式设备可能依赖隐含信任。它们假定操作员和与其交互的人员之所以这样做是因为他们受信任，并且物理接触设备意味着用户被授权使用并可能更改设置、更新设备或以其他方式修改它。嵌入式设备随物理访问而来的隐含信任模型使其成为组织的潜在漏洞，并且必须在部署前对其进行审查和设计。

# 总结

终端是大多数组织中最常见的设备，也是种类最繁多的。因此，你必须特别关注它们从启动那一刻起是如何被保护的。你可以利用系统固件内置的安全启动技术来保持启动完整性。

作为安全专业人员，你需要了解许多常见的终端安全工具类型，以及何时和如何使用它们。防病毒和反恶意软件工具有助于检测恶意程序和感染。在不同位置（如终端和邮件服务器）使用多种工具，可以帮助检测通过另一种工具防线的恶意代码。允许列表和阻止/拒绝列表也可用于控制终端系统可运行的应用程序和软件。它们需要更多的维护和精力，因为它们要么只允许运行清单内的应用程序，要么完全阻止清单外的程序。`EDR` 工具通过将检测和监控工具与集中报告及事件响应能力相结合，为终端设备的安全防护增加了另一层保护。最后，数据丢失防护（`DLP`）工具被部署用于确保数据不会无意或故意泄露。

终端系统还使用各种网络防御。最常见的是防火墙，基于端口、协议或应用程序控制流量。主机入侵防御系统（`HIPS`）可以阻止进入或离开系统的攻击流量，而主机入侵检测系统（`HIDS`）只能对恶意或不需要的流量发出警报或警示，但无法阻止它。下一代防火墙主要作为网络设备存在，但高级终端防护工具可以具有类似功能，包括行为分析和高级系统保护。

所有这些工具都很有帮助，但系统加固也很重要。加固技术专注于通过禁用不必要或不需要的服务、将安全选项从默认值配置为符合设备风险概况和安全需求的更安全设置，以及进行其他更改来减少终端系统的攻击面。修补和更新系统也有助于保持其安全，拥有完全修补的系统通常是加固过程的一部分。此外，系统配置标准、命名标准、IP 地址方案、加固脚本、程序和流程有助于确保企业中的系统得到适当的清点和保护。

驱动器加密可在驱动器被盗或丢失时保护数据安全。在生命周期结束时，当设备退役或损坏，或介质需要重复使用时，会采用清理程序以确保残留数据不泄露。擦除驱动器和物理销毁都是常见选项。选择与介质及存储在介质或驱动器上的数据所需安全级别相匹配的清理方法至关重要。

常见命令行命令是 Security+ 考试的一部分，你可能会遇到 `tail`、`head`、`cat`、`grep`、`chmod` 和 `logger` 等工具，应了解如何使用它们以及它们的功能。`Bash` 等 Shell、`Python` 等脚本语言和 `PowerShell` 等环境也是安全从业者的关键知识。安全 Shell（`SSH`）和 `SSL/TLS` 及其在远程访问和保护传输中数据方面的用途，也是安全专业人员工具箱的一部分。
