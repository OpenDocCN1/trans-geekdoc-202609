# 第 8 章：身份与访问管理

身份是现代组织中最重要的安全层之一。身份及其关联的账户，使组织能够控制谁有权访问其系统和服务；识别用户、系统和服务正在执行的操作；并控制这些账户拥有或不拥有的权限。所有这些意味着，精心设计的身份与访问管理架构及实施，对组织的运作至关重要。

本章首先介绍身份的概念，即关于主体的一组声明。身份通过认证过程进行声明，该过程证明该身份属于声明它的用户。随后，该用户根据与其用户账户关联的权利和特权被授权执行操作。您将了解认证方法、框架和技术，以及有关其实施和如何保护它们的关键细节。

在探讨完身份、认证和授权后，您将了解账户类型，包括用户、管理员、服务、来宾和共享账户。您还将了解账户策略如何用于管理和保护账户。最后，您将了解文件系统权限如何与账户协同工作，以控制用户可以读取、写入和执行哪些文件。

## 身份

身份是关于主体的一组声明。主体通常是人、应用程序、设备或组织，但 `identity`（身份）最常见的应用对象是个人。身份通常与关于主体的信息相关联，包括对其身份使用至关重要的详细信息。这些信息包括属性，即关于主体的信息。属性可以包含广泛的信息，从姓名、年龄、位置或职位，到发色、瞳色或身高等身体特征。

当主体想要使用其身份时，他们需要使用多种常见方式之一来断言或声明身份：

*   **用户名**，声明身份最常用的方式。重要的是要记住，用户名与身份相关联，本身**并非**一个认证因素。
*   **证书**，可存储在系统上，或与存储设备或安全令牌配对。
*   **令牌**，一种物理设备，可生成代码、通过 USB 插入，或通过蓝牙或其他方式连接以呈现证书或其他信息。
*   **SSH 密钥**，身份的加密表示形式，可替代用户名和密码。
*   **智能卡**使用嵌入式芯片。非接触式和物理芯片读取器兼容卡以及混合卡均已广泛部署，加密智能卡通常具备在卡片上直接生成密钥对的能力。

## 认证与授权

当主体想要声明身份时，他们需要证明该身份属于他们自己。这意味着他们需要进行认证。认证技术（如认证协议、服务器和标准）旨在确保主体就是他们声称的那个人，确保认证过程保持安全可靠，并确保单点登录（SSO）等功能正常工作。

授权验证您有权访问的内容。两者结合时，认证和授权首先验证您是谁，然后根据您被授权使用的内容，允许您访问资源、系统或其他对象。

### 认证与授权技术

目前有大量认证和授权技术用于认证和授权。针对 Security+ 考试，您需要熟悉其中许多技术的基础知识，包括当前和历史技术。让我们来看看您需要了解的认证技术。

**可扩展认证协议（EAP）** 是一种常用于无线网络的认证框架。存在许多使用 EAP 框架的不同实现，包括厂商专有和开放方法，如 EAP-TLS、LEAP 和 EAP-TTLS。这些协议中的每一个都使用该协议的消息传递标准来实现 EAP 消息。EAP 通常用于无线网络认证。

**质询握手认证协议（CHAP）** 是一种认证协议，旨在提供比 PAP（您将在本节后面读到）等协议更高的安全性。CHAP 使用加密质询和三次握手来发送凭据，如[图 8.1](#c08.xhtml#c08-fig-0001)所示。

![图 8.1 CHAP 质询与响应序列](images/c08f001.png)

**图 8.1** CHAP 质询与响应序列

Microsoft 推出了他们自己的 CHAP 版本，称为 MS-CHAP，但 MS-CHAP 第 1 版和第 2 版中发现的漏洞导致它在很大程度上被其他协议取代。

**密码认证协议（PAP）** 是一种以密码为中心的认证协议，常与点对点协议（PPP）配合使用以认证用户。尽管 PAP 仍出现在 Security+ 考试大纲中，但您不太可能在现代实现中使用 PAP，因为它已被 CHAP 和 EAP 实现所取代。
