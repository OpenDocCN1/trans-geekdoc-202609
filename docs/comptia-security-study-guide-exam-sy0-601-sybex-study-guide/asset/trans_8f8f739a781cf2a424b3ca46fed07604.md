

# 事件响应准备

事件响应准备包括组建团队、制定政策和程序、开展演练，以及构建将支持事件响应需求的技术和信息收集基础设施。事件响应计划并非孤立存在。相反，它们伴随着沟通和利益相关者管理计划、业务连续性和灾难恢复计划，以及每个组织特有的其他详细响应流程。

## 攻击框架

响应人员需要一种方式来谈论事件、攻击者、工具和技术。这就是攻击框架发挥作用的地方。**MITRE ATT&CK 框架**是一个非常完整的对手战术和技术知识库，并在信息安全领域的工具和系统中得到了广泛支持。**钻石入侵分析模型**是一个更简单的工具，它映射到菱形的四个顶点，允许分析师从一点移动到另一点，考虑他们已知和需要了解的要素。最后一个选项是**网络攻击链**，这是一个基于工具和技术的模型，有助于分析攻击如何发生并被利用。

## SIEM 和数据源

许多组织事件响应计划中的关键组件是**安全信息和事件管理 (SIEM)** 工具。**SIEM** 工具集中化信息收集和分析，并提供仪表板和报告，使事件信息能够通过可视化、报告和手动分析以及自动化分析功能被查看和快速识别。它们配合使用 `syslog`、`syslog-ng` 或其他收集和集中日志的工具来构建日志基础设施，从而捕获用于事件分析的关键信息。同时，网络流量和流信息、文件和系统元数据以及其他工件也被需要分析系统或网络上发生了什么的响应人员所使用。

## 缓解与控制

一旦事件被识别，响应人员必须对其进行缓解和控制。这涉及更改系统、设备和软件配置，以防止进一步问题并阻止事件。防火墙更改、使用 **MDM** 和 **DLP** 等安全工具、应用程序允许列表和阻止列表或拒绝列表，以及其他技术可用于在事件初期就将其遏制。这些更改可以包含在运行手册和剧本中，这些手册记录了组织采取的行动，以及在行动前、中、后将遵循的选择和流程。

# 考试要点

## 事件响应周期与流程

**事件响应周期和事件响应流程概述了如何响应事件。** Security+ 考试的事件响应周期包括准备、识别、遏制、根除、恢复和经验教训。响应流程可能不会一次只处于单一阶段，并且根据发现和进一步事件，阶段可能会前进或后退。事件响应团队由员工组成，包括管理层、安全人员、技术专家、沟通和公共关系人员，在某些情况下也可能包括法律、人力资源和执法人员。组织会举办桌面演练、演练走查和模拟演练等演习，让他们的团队练习事件响应。

## 事件响应规划

**规划对成功的事件响应至关重要。** 组织制定事件响应计划，以确保他们在事件发生期间知道该做什么，而不是在事件发生时才临时想办法。计划可能包括业务连续性计划，以确保业务能够继续运营，以及灾难恢复计划，以解决组织如何从重大灾难中恢复。沟通计划概述了谁需要接收沟通、谁将进行沟通以及何时进行沟通，确保关键沟通不被忽视。最后，**运营连续性规划 (COOP)** 由美国政府实施，以确保机构拥有详细计划，在发生中断或事件时继续运营。

## 用于分析的攻击框架

**攻击框架帮助分析师识别和分类攻击。** 攻击框架是可用于对攻击、攻击技术、流程和工具进行分类的工具。**MITRE ATT&CK 框架**将攻击分解为矩阵，这些矩阵映射到包含技术和组件的完整攻击生命周期。**钻石入侵分析模型**使用核心特征、元特征和置信度值，通过在菱形顶点之间移动来帮助分析师理解入侵。**网络攻击链**是一个七步流程，从侦察、武器化、投递、利用、安装、命令与控制，到目标行动，专注于攻击和漏洞利用。

## 数据源与管理

**用于事件响应的数据源和数据管理提供了对发生了什么的洞察，以及调查和检测工具。** 许多组织使用**安全事件和信息管理 (SIEM)** 工具，通过仪表板、自动化分析和手动调查功能来收集和分析数据。漏洞扫描输出、系统配置数据、系统和设备日志以及其他组织数据等信息被摄入并分析，以提供对事件和事故的广泛洞察。`rsyslog`、`syslog-ng`、`syslog` 和 `NXLog` 等日志工具都是日志基础设施中常见的工具，用于集中和管理日志。网络流量信息通过 `NetFlow`、`SFlow` 和数据包分析器等工具收集。它们提供关于带宽使用情况的有用信息，以及哪些系统进行了通信、使用的端口和协议、时间和日期，以及其他对事件分析有用的高层信息。除了日志和事件信息外，来自文件和其他位置的元数据也常用于事件调查和事件响应。

## 缓解技术

**缓解技术确保将事件的影响限制在最小范围内。** 事件响应人员使用各种技术来缓解和遏制事件。最常见的任务之一是更改端点安全解决方案以及设备的配置。这可能包括使用允许列表或阻止/拒绝列表、隔离文件或设备、进行防火墙更改、使用 **MDM** 或 **DLP** 工具、添加内容或 URL 过滤规则，或吊销或更新证书。在网络和基础设施层面，隔离、遏制和分段都被用来将涉及事件的系统与其他系统或网络分离开。**安全编排、自动化和响应 (SOAR)** 工具可用于管理和监控这些流程，并实现响应流程的自动化。
