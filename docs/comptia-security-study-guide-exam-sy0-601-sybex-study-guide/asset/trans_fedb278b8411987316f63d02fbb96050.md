
`机密性指标` 描述了如果攻击者成功利用该漏洞可能发生的信息泄露类型。机密性指标根据 [表 5.5](#c05.xhtml#c05-tbl-0005) 中的标准进行分配。

[**表 5.5**](#c05.xhtml#R_c05-tbl-0005)  CVSS 机密性指标

| 值 | 描述 | 分数 |
| --- | --- | --- |
| 无 (N) | 没有机密性影响。 | 0.00 |
| 低 (L) | 可能访问某些信息，但攻击者无法控制泄露哪些信息。 | 0.22 |
| 高 (H) | 系统上的所有信息均被泄露。 | 0.56 |

### 完整性指标

`完整性指标` 描述了如果攻击者成功利用该漏洞可能发生的信息篡改类型。完整性指标根据 [表 5.6](#c05.xhtml#c05-tbl-0006) 中的标准进行分配。

[**表 5.6**](#c05.xhtml#R_c05-tbl-0006)  CVSS 完整性指标

| 值 | 描述 | 分数 |
| --- | --- | --- |
| 无 (N) | 没有完整性影响。 | 0.00 |
| 低 (L) | 可能修改某些信息，但攻击者无法控制修改哪些信息。 | 0.22 |
| 高 (H) | 系统的完整性完全被破坏，攻击者可随意更改任何信息。 | 0.56 |

### 可用性指标

`可用性指标` 描述了如果攻击者成功利用该漏洞可能发生的中断类型。可用性指标根据 [表 5.7](#c05.xhtml#c05-tbl-0007) 中的标准进行分配。

[**表 5.7**](#c05.xhtml#R_c05-tbl-0007)  CVSS 可用性指标

| 值 | 描述 | 分数 |
| --- | --- | --- |
| 无 (N) | 没有可用性影响。 | 0.00 |
| 低 (L) | 系统性能下降。 | 0.22 |
| 高 (H) | 系统完全关闭。 | 0.56 |

### 范围指标

`范围指标` 描述了该漏洞是否会影响漏洞范围之外的系统组件。范围指标根据 [表 5.8](#c05.xhtml#c05-tbl-0008) 中的标准进行分配。请注意，范围指标表不包含分数信息。范围指标的值反映在较早前 [表 5.3](#c05.xhtml#c05-tbl-0003) 所示的所需权限指标的值中。

[**表 5.8**](#c05.xhtml#R_c05-tbl-0008)  CVSS 范围指标

| 值 | 描述 |
| --- | --- |
| 未改变 (U) | 被利用的漏洞只能影响由同一安全机构管理的资源。 |
| 已改变 (C) | 被利用的漏洞可影响管理包含该漏洞组件的安全机构范围之外的资源。 |

### 解读 CVSS 向量

`CVSS 向量` 使用单行格式来传达漏洞在前几节所述所有六个指标上的评级。例如，回顾 [图 5.12](#c05.xhtml#c05-fig-0012) 中呈现的漏洞的 CVSS 向量：

```
CVSS:3.0/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N
```

该向量包含九个组件。第一部分“CVSS:3.0”仅告知读者（人或系统）该向量是使用 CVSS 3.0 版本编写的。接下来的八个部分对应八个 CVSS 指标中的每一个。在本例中，[图 5.1](#c05.xhtml#c05-fig-0001) 中的 SSL 漏洞获得了以下评级：

*   攻击向量：网络（分数：0.85）
*   攻击复杂性：低（分数：0.77）
*   所需权限：无（分数：0.85）
*   用户交互：无（分数：0.85）
*   范围：未改变
*   机密性：高（分数：0.56）
*   完整性：无（分数：0.00）
*   可用性：无（分数：0.00）

### CVSS 分数汇总

`CVSS 向量` 提供了关于漏洞所构成风险性质的详细信息，但向量的复杂性使其难以用于优先级排序练习。因此，分析师可以计算 `CVSS 基础分`，这是一个代表漏洞总体风险的单一数字。得出基础分需要首先计算其他一些 CVSS 组件分数。
