
其中 `$account` 字段的值取自 [图 6.7](#c06.xhtml#c06-fig-0007) 中的输入字段。在此场景下，攻击者可以通过在账号字段中输入以下内容来测试标准的 SQL 注入漏洞：

```
52019' OR 1=1;--
```

如果成功，这将导致以下查询被发送到数据库：

```
SELECT FirstName, LastName, Balance
FROM Accounts
WHERE AccountNumber = '52019' OR 1=1
```

此查询将匹配所有结果。然而，Web 应用程序的设计可能会忽略第一行以外的任何查询结果。如果是这种情况，查询将显示与 [图 6.8](#c06.xhtml#c06-fig-0008) 所示相同的结果。尽管攻击者可能无法看到查询结果，但这并不意味着攻击失败。然而，由于对应用程序的可见性有限，很难区分防御完善的应用程序和成功的攻击。

攻击者可以通过使用已知会产生结果的输入来执行进一步测试，例如提供 [图 6.8](#c06.xhtml#c06-fig-0008) 中的账号 52019，并使用可修改该查询以返回*无*结果的 SQL 语句。例如，攻击者可以向该字段提供以下输入：

```
52019' AND 1=2;--
```

如果 Web 应用程序容易受到盲目 SQL 注入攻击，它将向数据库发送以下查询：

```
SELECT FirstName, LastName, Balance
FROM Accounts
WHERE AccountNumber = '52019' AND 1=2
```

当然，此查询永远不会返回任何结果，因为 1 永远不等于 2！因此，Web 应用程序将返回一个无结果的页面，如 [图 6.9](#c06.xhtml#c06-fig-0009) 所示。如果攻击者看到此页面，他们可以合理地确定该应用程序容易受到盲目 SQL 注入攻击，随后便可尝试更多恶意查询，以篡改数据库内容或执行其他非预期操作。

#### 基于时间的盲目 SQL 注入

除了利用应用程序返回的内容来评估其对盲目 SQL 注入攻击的易感性外，渗透测试人员还可以利用处理查询所需的时间作为从数据库检索信息的通道。

这些攻击依赖于不同数据库平台提供的延迟机制。例如，Microsoft SQL Server 的 Transact-SQL 允许用户指定如下命令：

```
WAITFOR DELAY '00:00:15'
```

此命令将指示数据库在执行下一个操作前等待 15 秒。试图验证应用程序是否容易受到基于时间的攻击的攻击者，可能会向账户 ID 字段提供以下输入：

```
52019'; WAITFOR DELAY '00:00:15'; --
```

立即返回 [图 6.8](#c06.xhtml#c06-fig-0008) 所示结果的应用程序，很可能不容易受到基于时间的攻击。然而，如果应用程序在 15 秒延迟后返回结果，则很可能存在漏洞。

这看起来可能像是一种奇怪的攻击，但它实际上可用于从数据库中提取信息。例如，假设前面示例中使用的 Accounts 数据库表包含一个名为 `Password` 的未加密字段。攻击者可以使用基于时间的攻击，通过逐个字母检查来发现密码。

执行基于时间的攻击的 SQL 语句有点复杂，考试不要求你掌握它。相反，这里有一些伪代码，从概念上说明该攻击的工作原理：

```
For each character in the password
 For each letter in the alphabet
 If the current character is equal to the current letter, wait 15
 seconds before returning results
```

通过这种方式，攻击者可以遍历所有可能的密码组合，逐个字符地推导出密码。这看起来可能很繁琐，但像 `SQLmap` 和 `Metasploit` 这样的安全工具可以自动执行基于时间的盲目攻击，使其变得非常简单。

### 代码注入攻击

SQL 注入攻击是一类被称为*代码注入*攻击的通用攻击的具体示例。这些攻击旨在将攻击者编写的代码插入到 Web 应用程序开发人员创建的合法代码中。任何将用户提供的输入插入到应用程序开发人员编写的代码中的环境，都可能容易受到代码注入攻击。

类似的攻击也可能针对其他环境发生。例如，攻击者可能会在作为轻量级目录访问协议 (LDAP) 查询一部分发送的文本中嵌入命令，从而实施 *LDAP 注入攻击*。他们还可能试图在可扩展标记语言 (XML) 文档中嵌入代码，实施 *XML 注入攻击*。命令甚至可能尝试加载包含恶意代码的动态链接库 (DLL)，实施 *DLL 注入攻击*。

除了 SQL 注入，跨站脚本也是一种代码注入攻击的示例，它将攻击者编写的 HTML 代码插入到开发人员创建的网页中。我们将在本章后面详细讨论跨站脚本。

### 命令注入攻击

在某些情况下，应用程序代码可能会回溯到操作系统以执行命令。这非常危险，因为攻击者可能利用应用程序中的缺陷，获得直接操纵操作系统的能力。例如，考虑 [图 6.10](#c06.xhtml#c06-fig-0010) 中所示的简单应用程序。

![图 6.10 账户创建页面](images/c06f010.png)

[**图 6.10**](#c06.xhtml#R_c06-fig-0010) 账户创建页面

此应用程序为课程设置新的学生账户。除其他操作外，它会在服务器上为学生创建一个目录。在 Linux 系统上，应用程序可能会使用 `system()` 调用将目录创建命令发送到底层操作系统。例如，如果有人在文本框中填入

```
mchapple
```

应用程序可能会使用函数调用

```
system('mkdir /home/students/mchapple')
```

为该用户创建主目录。审查此应用程序的攻击者可能会猜测这就是其工作原理，然后提供输入

```
mchapple & rm -rf /home
```

应用程序随后用它来创建系统调用：

```
system('mkdir /home/students/mchapple & rm -rf home')
```

这一系列命令将删除 `/home` 目录及其包含的所有文件和子文件夹。此命令中的 `&` 符号表示操作系统应将 `&` 符号后的文本作为单独的命令执行。这使得攻击者能够通过利用仅旨在执行 `mkdir` 命令的输入字段来执行 `rm` 命令。

## 利用身份认证漏洞

应用程序与服务器、网络一样，依赖身份认证机制来确认用户和设备的身份，并验证它们是否被授权执行特定操作。攻击者经常试图破坏这些认证系统的安全性，因为如果他们能够做到这一点，就可能获得对受该认证基础设施保护的系统、服务和信息的非法访问。

### 密码认证

密码是当今最常用的认证形式，但遗憾的是，它们也是最容易被攻破的。原因在于密码是一种基于知识的认证技术。获知用户密码的攻击者，从那时起就可以冒充该用户，直到密码过期或被更改。

攻击者获知用户密码的途径有很多，范围涵盖技术手段到社交手段。以下只是攻击者可能发现用户密码的几种可能方式：
