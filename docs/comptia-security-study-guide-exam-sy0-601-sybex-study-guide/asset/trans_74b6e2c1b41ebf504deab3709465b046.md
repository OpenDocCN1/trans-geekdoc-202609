# 第 11 章

终端安全

保护组织中的终端是许多安全专业人员日常任务的重要组成部分。对于大多数组织而言，终端的数量远超服务器和网络设备，且由于最终用户控制或使用它们，它们面临着各种各样的威胁，而这些威胁是服务器不太可能遇到的。

在本章中，您将首先了解终端保护技术，包括如何保护系统的启动过程；反恶意软件和防病毒工具如何检测、预防和修复恶意软件感染；以及为何允许列表和阻止列表对于控制终端系统上可运行的应用程序很有用。您还将了解数据丢失防护、网络防御技术等概念，以及系统和服务加固涉及的内容。配置标准、命名和 IP 寻址方案、补丁管理，以及在磁盘和介质重复使用或退役时如何处理，也是加固和系统保护过程的一部分。最后，您将探索一些常见的文件操作命令行工具，以及为 Security+ 考试所需熟悉的脚本、安全传输和 Shell 实用程序。

本章后半部分重点介绍嵌入式和专用系统，这些是常见的终端设备，其安全需求不同于传统的桌面和移动操作系统。您将了解一些嵌入式平台，以及驱动其专用需求的操作系统和芯片，还有它们所集成的系统，例如用于工业自动化和管理的 SCADA 和 ICS 系统。您将探索物联网，以及它和其他专用系统对安全的影响。嵌入式系统使用的通信详情以及嵌入式系统所需的安全约束将作为本章的总结。

## 保护终端

作为一名安全专业人员，您将被要求推荐、实施、管理或评估旨在保护台式机、移动设备、服务器以及组织中各种其他系统的安全解决方案。这些设备通常被称为 `endpoints`（终端），意味着它们是网络的一个端点，无论是有线还是无线网络。

鉴于如此广泛的潜在终端范围，安全选项的菜单也非常广泛。作为一名安全从业者，您需要知道有哪些选项存在，它们通常部署在何处以及如何部署，以及您需要考虑哪些因素。

### 保持启动完整性

在终端运行时保持其安全，始于其启动过程。如果不受信任或恶意的组件被插入启动过程，则无法信任该系统。高安全环境中的安全从业者需要一种方法来确保整个启动过程具有可证明的安全性。

幸运的是，现代统一可扩展固件接口（`UEFI`）固件（传统基本输入/输出系统 [`BIOS`] 的替代品）可以利用两种不同的技术来确保系统安全。`Secure boot`（安全启动）确保系统仅使用原始设备制造商（`OEM`）信任的软件进行启动。要执行安全启动操作，系统必须拥有一个签名数据库，其中列出了启动过程中受信任软件和固件的安全签名（请参见[图 11.1](#c11.xhtml#c11-fig-0001)）。
