## 软件安全测试

无论应用程序的开发团队多么优秀，代码中总会存在某种形式的缺陷。Veracode 2019 年基于其测试得出的应用程序指标显示，他们扫描的应用程序中有 83% 在测试过程中至少表现出一个安全问题。这一数字表明，迫切需要将软件安全测试更好地集成到软件开发生命周期中。

安全专业人员和开发人员可使用各种各样的手动和自动测试工具及方法。幸运的是，自动化工具不断改进，提供了一种更简便的方式来验证代码的安全性。在接下来的几页中，我们将回顾当今可用的一些关键软件安全测试方法和工具。

### 分析和测试代码

作为每个应用程序和程序基础的源代码可能包含各种错误和缺陷，从编程和语法错误到业务逻辑、错误处理以及与其他服务和系统集成方面的问题。能够分析代码以了解代码的功能、执行任务的方式以及程序本身中可能出现缺陷的位置非常重要。这通常通过`静态`或`动态代码分析`以及`模糊测试`等测试方法来完成。一旦对代码进行更改并部署，必须进行`回归测试`，以确保修复措施没有产生新的安全问题！

#### 静态代码分析

*静态代码分析*（有时称为源代码分析）是通过审查应用程序的代码来进行的。由于静态分析使用应用程序的源代码，因此它可以被视为一种`白盒测试`，测试人员拥有完全可见性。这使测试人员能够发现其他测试可能遗漏的问题，原因可能是逻辑未暴露给其他测试方法，或者是由于内部业务逻辑问题。

与许多其他方法不同，静态分析不运行程序；相反，它专注于理解程序是如何编写的以及代码旨在做什么。静态代码分析可以使用自动化工具进行，也可以通过人工审查代码来进行——这一过程有时称为“代码理解”。自动化静态代码分析在查找已知问题方面非常有效，而人工静态代码分析有助于识别程序员引入的错误。

#### 动态代码分析

*动态代码分析*依赖于在提供输入以测试软件的同时执行代码。与静态代码分析非常相似，动态代码分析可以通过自动化工具或手动完成，但由于大多数动态代码测试过程中需要进行大量测试，因此强烈倾向于自动化测试。

#### 模糊测试

*模糊测试*或*模糊测试*，涉及向应用程序发送无效或随机数据，以测试其处理意外数据的能力。系统会监控应用程序，以确定其是否崩溃、失败或以不正确的方式响应。由于模糊测试涉及大量数据，因此通常是自动化的，它对于检测输入验证和逻辑问题以及内存泄漏和错误处理特别有用。不幸的是，模糊测试往往只能识别简单的问题——它不考虑复杂的逻辑或业务流程问题，并且如果不监控其进度，可能无法提供完整的代码覆盖率。

## 注入漏洞

现在您已经很好地理解了安全代码开发和测试实践，让我们将注意力转向建立这些机制的动力：攻击者可能利用的漏洞，以破坏我们的安全。在本章中，我们将探讨许多不同的漏洞类别。

*注入漏洞*是攻击者用来突破 Web 应用程序并访问支持该应用程序的系统的主要机制之一。这些漏洞允许攻击者向 Web 应用程序提供某种类型的代码作为输入，并诱使 Web 服务器执行该代码或将其提供给另一台服务器执行。

### SQL 注入攻击

Web 应用程序通常接收来自用户的输入，并使用它来构建数据库查询，将结果返回给用户。例如，考虑电子商务网站上的搜索功能。如果用户在搜索框中输入**橙色老虎枕头**，Web 服务器需要知道目录中哪些产品可能与该搜索词匹配。它可能会向后端数据库服务器发送如下所示的请求：

```
SELECT ItemName, ItemDescription, ItemPrice
FROM Products
WHERE ItemName LIKE '%orange%' AND
ItemName LIKE '%tiger%' AND
ItemName LIKE '%pillow%'
```

此命令检索可包含在返回给最终用户的结果中的项目列表。在 SQL 注入攻击中，攻击者可能会向 Web 服务器发送一个看起来非常异常的请求，例如搜索：

```
orange tiger pillow'; SELECT CustomerName, CreditCardNumber FROM Orders; -- 
```

如果 Web 服务器只是将此请求传递给数据库服务器，它将执行以下操作（为便于查看稍作重新格式化）：

```
SELECT ItemName, ItemDescription, ItemPrice
FROM Products
WHERE ItemName LIKE '%orange%' AND
ItemName LIKE '%tiger%' AND
ItemName LIKE '%pillow';
SELECT CustomerName, CreditCardNumber
FROM Orders;
--%'
```

如果成功，此命令将运行两个不同的 SQL 查询（由分号分隔）。第一个将检索产品信息，第二个将检索客户姓名和信用卡号码的列表。

在我们刚才描述的基本 SQL 注入攻击中，攻击者能够向 Web 应用程序提供输入，然后监控该应用程序的输出以查看结果。虽然这是攻击者的理想情况，但许多存在 SQL 注入缺陷的 Web 应用程序并不提供让攻击者直接查看攻击结果的方法。然而，这并不意味着攻击不可能；这只是使其更加困难。攻击者使用一种称为*盲目 SQL 注入*的技术，即使无法直接查看结果也能实施攻击。我们将讨论两种形式的盲目 SQL 注入：基于内容和基于时间。
