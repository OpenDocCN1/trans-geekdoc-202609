
查看趋势信息的能力是 SIEM 平台功能中极具价值的一部分。趋势可以指向一个开始出现的新问题、正在发生并蔓延的漏洞利用，或者仅仅是你组织中最流行的恶意软件是什么。在[图 14.7](#c14.xhtml#c14-fig-0007)中，你可以看到一个对恶意软件活动进行分类的示例，识别出检测频率最高的签名、最流行的恶意软件家族，以及其发送流量的去向。这有助于组织在新威胁浮出水面时识别它们。

### 警报和告警

警报和告警是 SIEM 系统的重要组成部分。[图 14.8](#c14.xhtml#c14-fig-0008)展示了 AlienVault 演示系统的一个示例。请注意，告警按其时间和严重性进行分类，随后提供可深入探究的详细信息。恶意软件信标和感染等事件会被自动分类、确定优先级、标记源和目的地，并根据需要匹配给分析师进行调查。它们还显示诸如哪个传感器正在报告问题之类的信息。

### 关联与分析

在调查事件时，单个数据点可能很有用，但将数据点与其他数据点进行匹配是大多数调查的关键部分。关联需要拥有诸如事件发生的时间、发生在什么系统上、涉及哪些用户账户以及其他有助于分析过程的详细信息等数据。SIEM 允许你基于这些多个数据点搜索和过滤数据，以缩小与事件相关的信息范围。自动化关联与分析旨在匹配已知事件和妥指标（IOC），以构建一个完整的数据集供事件或事故审查和分析。正如你在 AlienVault SIEM 的屏幕截图中所见，你可以为数据添加标签和调查。尽管每个 SIEM 工具可能用略微不同的术语来称呼这些功能，但基本概念和能力保持不变。

### 规则

SIEM 的告警、警报和关联引擎的核心是驱动这些组件的规则集。[图 14.9](#c14.xhtml#c14-fig-0009)展示了一个如何利用 SIEM 收集的信息构建告警规则的示例。规则条件可以使用逻辑来确定规则是否以及何时被激活，随后可基于规则触发动作。结果可能只是简单的警报，也可能是复杂的程序化动作，例如更改基础设施、启用或禁用防火墙规则，或触发其他防御措施。

![FIGURE 14.9 Rule configuration in AlienVault](images/c14f009.png)

[**图 14.9**](#c14.xhtml#R_c14-fig-0009) AlienVault 中的规则配置

规则很重要，但也可能引发问题。构建不当的规则逻辑可能导致漏报事件，或造成误报或过于宽泛的检测。如果规则包含主动响应组件，错误触发的规则可能导致中断或其他基础设施问题。因此，规则需要被仔细构建、测试，并定期审查。虽然 SIEM 厂商通常提供默认规则和检测能力，但组织为其环境和系统设计的自定义规则是成功部署 SIEM 的关键。

最后，SIEM 设备还遵循数据的整个生命周期。这意味着大多数都具备为每种数据类型设置保留期和数据生命周期的能力，并支持合规性要求。事实上，大多数 SIEM 设备都有预构建的规则或模块，旨在根据所需标准满足特定的合规性要求。

#### 日志文件

日志文件为事件响应人员提供有关已发生事件的信息。当然，这也使得日志文件成为攻击者的目标，因此事件响应人员需要确保他们使用的日志未被篡改，并且其中的时间戳和其他数据是正确的。一旦你确信正在处理的数据是可靠的，日志就能提供大量与事件相关的宝贵信息。

[图 14.10](#c14.xhtml#c14-fig-0010)展示了 Windows 事件查看器，这是查看单个 Windows 系统日志最常用的方式之一。在许多企业环境中，特定日志或关键日志条目会被发送到安全的日志基础设施，以确保存在终端系统收集日志的可信副本。安全从业人员仍会审查本地日志，特别是因为组织中各终端的日志数据量巨大，通常不会为每个系统维护所有日志的完整副本。

![FIGURE 14.10 The Windows Event Viewer showing a security log with an audit event](images/c14f010.png)

[**图 14.10**](#c14.xhtml#R_c14-fig-0010) Windows 事件查看器显示包含审核事件的安全日志

Security+ 考试大纲涵盖的事件响应人员常用的日志包括以下内容：

*   **系统日志**包括从服务更改到权限问题的所有内容。Windows 系统日志记录系统运行时生成的信息。
*   **应用程序日志**在 Windows 中包含应用程序的安装程序信息、应用程序生成的错误、许可证检查，以及应用程序生成并发送到应用程序日志的任何其他日志。
*   **安全日志**在 Windows 系统中存储有关登录失败和成功的信息，以及其他身份验证日志信息。Linux 系统的身份验证和安全日志存储在 `/var/log/auth.log` 和 `/var/log/secure` 中。
*   **漏洞扫描输出**是另一种可纳入事件分析活动的数据形式。扫描可提供关于攻击者可能瞄准的目标、服务变更，甚至攻击者在身后封堵漏洞导致的突然修补问题的线索。
*   **网络和安全设备日志**可包括路由器和交换机的配置更改、流量信息、网络流量，以及 **数据包分析器**（如 Wireshark）捕获的数据。
*   **Web 日志**，如来自 Apache 和 Internet Information Services (IIS) 的日志，记录对 Web 服务器的请求及相关事件。这些日志有助于追踪访问了什么、何时访问的，以及发送请求的 IP 地址。由于请求会被记录，这些日志还有助于识别攻击，包括 SQL 注入和其他针对 Web 服务器和 Web 应用程序的特定攻击。
*   **DNS 日志**提供关于 DNS 查询的详细信息。这看似用处不大，但 DNS 日志可以显示攻击者收集信息的行为，根据系统的 DNS 请求提供哪些系统可能已被入侵的信息，并显示内部用户是否滥用组织资源。
*   **身份验证日志**可用于确定账户何时被登录，还可能显示权限使用、登录系统或位置、错误密码尝试，以及可关联到入侵和滥用的其他登录和使用详情。
*   **转储文件**，如 Windows 出现蓝屏死机时创建的内存转储，看似对事件响应没什么用处，但它们可能包含显示崩溃时内存和系统状态的信息。如果崩溃是由攻击者或漏洞利用导致的，或者系统上存在恶意软件或攻击工具，转储文件可能包含这些工件。
