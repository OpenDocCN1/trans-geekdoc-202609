

# 软件生命周期结束

软件供应商最终会停止对其生产的每一款产品提供支持。操作系统和应用程序均不例外。一旦供应商宣布某产品最终停止支持，继续运行该过时软件的组织将面临重大的攻击风险。供应商将不再调查或修复该日期后出现的产品安全缺陷。从安全角度来看，继续运行不受支持产品的组织将独自面对风险，除非你碰巧维护着一支操作系统开发团队，否则这绝不是一个好局面。

也许最著名的主要操作系统停止支持事件发生在 2015 年 7 月，当时微软停止了对使用了十多年的 Windows Server 2003 的支持。[图 5.14](#c05.xhtml#c05-fig-0014) 展示了 Nessus 在识别出运行此过时操作系统的服务器时生成的报告示例。

从该报告中我们可以看到，扫描检测到网络上有两台服务器运行着 Windows Server 2003。漏洞描述对继续运行任何不受支持操作系统的组织将面临的局势给出了严峻的评估：

> 缺乏支持意味着供应商将不再为该产品发布新的安全补丁。因此，它很可能包含安全漏洞。此外，微软不太可能调查或确认漏洞报告。

[**图 5.14**](#c05.xhtml#R_c05-fig-0014) 不受支持的操作系统漏洞

对于运行不受支持操作系统的组织而言，解决方案在措辞上很简单，但在实施上却很复杂。“升级到当前仍受支持的 Windows 版本”是一条相当直接的指令，但对于运行着根本无法升级到新版 Windows 的应用程序的组织来说，这可能构成重大挑战。在组织必须继续使用不受支持的操作系统的情况下，最佳实践要求尽可能隔离该系统，最好不要将其连接到任何网络，并应用尽可能多的补偿性安全控制，例如加强监控和实施严格的网络防火墙规则。

## 弱配置

漏洞扫描还可能突出显示系统、应用程序和设备上的弱配置设置。这些弱配置可能包括以下内容：

*   使用构成安全风险的默认设置，例如在将系统移至生产环境前本应禁用的管理设置页面。
*   存在不安全的账户，包括普通用户账户和拥有管理权限的不安全根账户。当账户缺乏强身份验证或使用默认密码时，可被视为不安全账户。
*   非支持正常系统运行所必需的开放端口和服务。这将根据服务器或设备的功能而异，但一般来说，系统应仅暴露执行其功能所需的最少量服务。
*   违反最小权限原则、允许用户过度访问的开放权限。

这些只是可能危及安全的众多弱配置设置中的几个例子。你需要仔细阅读漏洞扫描结果，以识别你的环境中可能出现的其他问题。

## 错误消息

许多应用程序开发平台支持 `debug modes`（调试模式），为开发人员提供在开发过程中排查应用程序所需的关键错误信息。调试模式通常提供关于应用程序和服务器内部运作以及支持数据库的详细信息。虽然这些信息对开发人员有用，但可能会无意中协助攻击者获取有关数据库结构、应用程序使用的认证机制或其他细节的信息。因此，漏洞扫描会对扫描服务器上存在的调试模式发出警报。[图 5.15](#c05.xhtml#c05-fig-0015) 展示了此类扫描结果的示例。

在该示例中，目标系统似乎是一个支持 ASP.NET 开发环境的 Windows 服务器。报告的输出部分显示，当客户端发送 DEBUG 请求时，服务器会做出响应。

解决此问题需要开发人员配合，在面向公众的系统上禁用调试模式。在成熟的组织中，软件开发应始终在专用的开发环境中进行，该环境仅可从私有网络访问。应鼓励（或强制！）开发人员仅在专用于该目的的系统上进行测试，在这些服务器上启用调试模式完全合适。面向公众的系统无需支持此功能。

## 不安全协议

互联网早期网络上使用的许多旧协议在设计时未考虑安全性。它们通常未能使用加密来保护用户名、密码以及通过开放网络发送的内容，使协议用户面临窃听攻击的风险。Telnet 是一种用于获取远程服务器命令行访问权限的不安全协议示例。文件传输协议 (FTP) 提供了在系统间传输文件的能力，但不包含安全功能。[图 5.16](#c05.xhtml#c05-fig-0016) 展示了一个检测到支持不安全 FTP 协议的系统的扫描报告示例。

解决此问题的方法是简单地切换到更安全的协议。幸运的是，Telnet 和 FTP 都存在加密替代方案。系统管理员在寻求获取远程系统命令行访问权限时，可以使用安全外壳协议 (SSH) 作为 Telnet 的安全替代品。同样，安全文件传输协议 (SFTP) 和 FTP-Secure (FTPS) 都提供了在系统间安全传输文件的方法。

## 弱加密

加密是每个网络安全计划中用于保护存储数据和网络传输数据的关键安全控制。然而，与任何控制一样，加密必须安全配置才能提供充分的保护。你将在 [第 7 章](#c07.xhtml) “密码学和公钥基础设施” 中了解更多关于安全实施加密的内容。

当你实施加密时，需要做出两个重要选择：

*   用于执行加密和解密的算法
*   与该算法配合使用的加密密钥

你对这两个特性所做的选择可能对环境安全性产生深远影响。如果你使用弱加密算法，攻击者可能轻易攻破它。如果你选择的加密密钥因其长度或组成而易于猜测，攻击者可能通过密码学攻击找到它。例如，[图 5.17](#c05.xhtml#c05-fig-0017) 显示了一份来自支持不安全 RC4 密码套件系统的扫描报告。
