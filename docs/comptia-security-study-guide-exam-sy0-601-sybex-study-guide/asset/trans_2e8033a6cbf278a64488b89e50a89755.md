
# 硬编码凭据

在某些情况下，开发人员可能会在源代码中包含用户名和密码。此错误有两种变体。首先，开发人员可能会为应用程序创建一个硬编码的维护账户，即使身份验证系统发生故障，也允许开发人员重新获得访问权限。这被称为 `backdoor`（后门）漏洞，之所以成问题，是因为它允许任何知道后门密码的人绕过正常身份验证并访问系统。如果后门被公开（或私下！）知晓，生产环境中的所有代码副本都将受到威胁。

硬编码凭据的第二种变体发生在开发人员在其源代码中包含其他服务的访问凭据时。如果该代码被有意或意外泄露，这些凭据就会为外部人员所知。当开发人员意外将包含 API 密钥或其他硬编码凭据的代码发布到公共代码仓库（如 `GitHub`）时，这种情况经常发生。

# 内存管理

应用程序通常负责管理其自身的内存使用，在这种情况下，不良的内存管理实践会破坏整个系统的安全性。

## 资源耗尽

我们需要关注的关于内存或系统上任何其他有限资源的问题之一是 `resource exhaustion`（资源耗尽）。无论是有意还是无意，系统可能会消耗掉其可用的所有内存、存储、处理时间或其他资源，导致系统瘫痪或无法用于其他用途。

`Memory leaks`（内存泄漏）是资源耗尽的一个例子。如果应用程序向操作系统请求内存，最终将不再需要该内存，并应将内存返还给操作系统供其他用途使用。在存在内存泄漏的应用程序中，应用程序未能返还其不再需要的部分内存，可能只是丢失了对已写入内存保留区域的对象的跟踪。如果应用程序长期持续这样做，会慢慢耗尽系统可用的所有内存，导致系统崩溃。重启系统通常能重置问题，将内存返还给其他用途，但如果内存泄漏未得到修正，循环将重新开始。

## 指针解引用

`Memory pointers`（内存指针）也可能导致安全问题。指针是应用程序开发中常用的概念。它们只是存储内存中另一位置地址的内存区域。

例如，我们可能有一个名为 `photo` 的指针，它包含存储照片的内存位置的地址。当应用程序需要访问实际照片时，它会执行一个称为 `pointer de-referencing`（指针解引用）的操作。这仅意味着应用程序遵循指针并访问指针地址引用的内存。此过程并无异常。应用程序一直在这样做。

可能出现的一个特定问题是指针为空，包含程序员所谓的 `null`（空）值。如果应用程序尝试解引用此 `null` 指针，会导致称为 `null pointer exception`（空指针异常）的情况。在最好的情况下，`null pointer exception` 会导致程序崩溃，向攻击者提供可用于侦察应用程序安全性的调试信息。在最坏的情况下，`null pointer exception` 可能允许攻击者绕过安全控制。安全专业人员应与应用程序开发人员合作，帮助他们避免这些问题。

## 缓冲区溢出

当攻击者操纵程序将比为该程序分配的内存区域更多的数据放入其中时，会发生 `Buffer overflow`（缓冲区溢出）攻击。其目标是用可能由系统上运行的其他进程执行的指令覆盖内存中的其他信息。

缓冲区溢出攻击非常普遍，且往往在首次发现后持续多年。例如，2016 年 Verizon 数据泄露调查报告确定了 10 个漏洞，它们导致了研究中 85% 的妥协事件。前 10 名中有四个是溢出问题：

*   `CVE 1999-1058`：Vermillion FTP Daemon 中的缓冲区溢出
*   `CVE 2001-0876`：Windows 98、98SE、ME 和 XP 上通用即插即用 (UPnP) 中的缓冲区溢出
*   `CVE 2002-0126`：BlackMoon FTP Server 1.0 至 1.5 中的缓冲区溢出
*   `CVE 2003-0818`：Microsoft ASN.1 库中的多个整数溢出

每个漏洞标题中字母 `CVE` 后面的四位数字表示发现该漏洞的年份。在一项发生于 2015 年的泄露事件研究中，导致泄露的前 10 个问题中有四个是利用了已有 12 到 16 年历史的溢出漏洞！Verizon 在最近的报告中未包含此类分析，但没有理由认为这一趋势已改变。

在漏洞扫描期间发现 `buffer overflow`（缓冲区溢出）漏洞的网络安全分析师应寻找修复该问题的补丁。在大多数情况下，扫描报告将直接指出可用的补丁。

# 竞争条件

当代码段的安全性取决于系统内事件发生的顺序时，会发生 `Race conditions`（竞争条件）。`time-of-check-to-time-of-use (TOCTTOU or TOC/TOU)`（检查时间到使用时间）问题是一种竞争条件，它发生在程序过早检查访问权限（远在资源请求之前）时。例如，如果操作系统在用户登录时构建一份详尽的访问权限列表，然后在整个登录会话期间查阅该列表，则存在 `TOCTTOU` 漏洞。如果系统管理员撤销了特定权限，该限制直到用户下次登录时才会应用。如果用户在访问权限撤销时已登录，他们将无限期地拥有对该资源的访问权限。用户只需保持会话打开数天，新限制就永远不会被应用。为防止此竞争条件，开发人员应在每次请求时评估访问权限，而不是缓存权限列表。

# 无保护的 API

组织通常希望其他开发人员在其创建的平台基础上进行构建。例如，`Twitter` 和 `Facebook` 可能希望允许第三方应用程序开发人员创建向用户社交媒体动态发布内容的应用。为了实现这种创新，服务通常会创建 `application programming interfaces (APIs)`（应用程序编程接口），以实现自动化访问。

如果未妥善保护，无保护的 API 可能导致功能被未经授权地使用。例如，未使用适当身份验证的 API 可能允许任何知道 API URL 的人修改服务。非供公共使用的 API 应始终使用身份验证机制（如 `API key`（API 密钥））进行保护，并且仅通过加密通道访问，以保护这些凭据免受窃听攻击。

# 驱动程序操纵

`Device drivers`（设备驱动程序）在计算中发挥着重要作用。它们充当硬件设备与操作系统之间的软件接口。设备驱动程序是您可以将几乎任何制造商的打印机与 `Windows` 或任何其他操作系统配合使用的原因。`Microsoft` 无需设计 `Windows` 以适配市场上每一款单独的打印机。相反，他们为打印机制造商提供为其打印机编写 `Windows` 驱动程序的能力。当制造商制造新打印机时，他们还会设计一个驱动程序，为 `Windows` 提供如何与打印机交互的指令。
