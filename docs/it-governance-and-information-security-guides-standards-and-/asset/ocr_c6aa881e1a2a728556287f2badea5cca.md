The security policy is primarily implemented to communicate with system users and administrators, which must be taken into account when security decisions are made. It defines the explicit expectations and responsibilities of users and administrators and allows both groups to know what to expect (Knapp et al., 2009). It should explain why certain decisions have been made and why they are important, to help users understand how the policy is designed to benefit them (Flowerday & Tuikeike, 2016).

The security policy should specifically state the types of data that are considered important enough to warrant protection. This would include the user's files in the form of programs, text documents like a thesis or an email, and system-configuration files (Yassine et al., 2017). This helps users understand why security measures are in place, and why secure services have been restricted.

A password policy is already in place. However, it should most be defined in the security policy. It is one of many things the user could do to help keep the system secure, but it is probably one of the most important. Other ways that a user could contribute to system security would be properly managing its file and directory permissions or using other software designed with the security-conscious person in mind (Knapp et al., 2009).

Should a security incident occur, the security policy should state and any procedures that should be followed throughout the period. If the person in charge of system security detects a break-in, like should be notified and what should be done with the compromised machine? Issues these must be addressed to ensure that any disrupted services are restored properly and second, so that proof of the incident can be obtained should legal need arise (Male, 2018). The source of the security breach should be identified and fixed so that the incident does not repeat itself. Once the problem has been adequately documented, the system administration team should be aware of what happened (Gwwe et al., 2020).

The Information Systems Security Policy (ISSP) reflects the expectations and requirements of the executive management concerning the information system (Canavan, 2003; Hone & Eloff, 2002b). It must take into account the needs of availability, confidentiality, and integrity of applications and data used and transitioning on networks and systems. It constitutes a set of technical, organizational, legal, and human security rules and principles to ensure an efficient and uniform level of security (Fomin, 2008). The ISSP is the counterpart of the Information Systems Master Plan for security. It should be an ISSP action plan that prioritizes projects to meet ISSP objectives. There are several standards and best practices to guide organizations in implementing an information security policy such as ISO 27000, ISACA, and NIST. ISO 27001 (ISECT, 2012) is an international standard that is part of the ISO 27000 family (Van Solms, 2005). It refers to a set of standards relating to the ISMS. The ISO 27001 standard is a British standard that came into being in October 2005, succeeding the BS 7799-2 standard. It describes the requirements for the implementation of ISMS. This standard allows to choose security measures to protect sensitive assets within a well-defined perimeter by implementing a systematic and proactive approach to security risk management.
