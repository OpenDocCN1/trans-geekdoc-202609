### 8.4.2 Mathematical relationship between KPIs

The KPIs interact in complex ways. For instance:

- Latency (L) inversely affects throughput ($T_t$) and traffic capacity ($T_c$).
- Reliability (R) is directly related to packet loss rate and impacts QoS adherence (Q).
- Resource Utilization (U) impacts availability (A) and fault tolerance ($F_t$).

To model these interactions, we can define the following relations:
- Latency-Throughput Relation:

```
$L = \frac{C}{T_b} + J$
```

Where C is the constant dependent on network infrastructure.

- Reliability–QoS Relation:

```
$Q = 1 - R$
```
QoS adherence decreases as reliability drops.

- Resource Utilization–Availability Relation:

```
$U = \frac{1}{A}$
```

### 8.4.3 GA-RL hybrid workflow

#### 8.4.3.1 GA and RL phase

The GA runs over a population of slice configurations, optimizing based on the KPI fitness function. Each configuration is assessed using the KPI probability distribution to favor solutions likely to meet KPI targets. Once an optimal configuration is found, the RL agent adjusts the slice parameters to environmental changes to maximize long-term KPI adherence.

The proposed model is a hybrid optimization and adaptive control framework that combines GA with RL. The core objective is to maximize adherence to KPI targets across all slices, ensuring efficient network utilization, high QoS, and minimal service disruptions.

### 8.4.4 Chromosome representation

In GA, a chromosome represents a candidate solution for network slicing. For each slice (e.g., eMBB, uLLRC, or mMTC), the chromosome encodes the configuration of KPI parameters. Each slice chromosome can be represented as a general fitness function can be defined as:

$Chromosome_i = [L_i, T_{b,i}, R_i, A_i, U_i, M_i, S_i, S_{li}, J_{ci}, Q_i, D_{ri}, F_{li}] \quad$ (8.4)

- $L_i$ is the latency and $T_{b,i}$ is the throughput for slice $i$.

### 8.4.5 Fitness function

The fitness function evaluates how well a chromosome meets the KPI targets.

$Fitness_i = \sum_{k=1}^n w_k \cdot f_k(X_i) \quad$ (8.5)

The fitness function evaluates how well a chromosome meets the KPI targets, where $X_i$ is the vector of KPI values for slice $i$; $W_k$ is the weight of KPI based on its importance; and $f_k(X_i)$ is the penalty function for each KPI, which can be calculated as the deviation of each KPI from its target:

$f_k(X_i) = |KPI_k - Target_k| \quad$ (8.6)

The objective is to minimize Fitness, meaning that the best meets the KPIs is the optimal solution.

#### 8.4.5.1 GA workflow

1. **Initialization**: Randomly initialize a population of chromosomes (slices).
2. **Selection**: Select the best chromosomes based on fitness values using techniques like Gaussian, Poisson, and Erlang distribution for optimized allocation for each specific use cases.
3. **Crossover**: Perform crossover (e.g., single-point or multi-point crossover) to create new offspring chromosomes by combining genes from parent chromosomes.
4. **Mutation**: Introduce small random changes (mutations) to genes to explore new solutions.
5. **Iteration**: Repeat selection, crossover, and mutation over multiple generations until a stopping criterion (e.g., convergence or maximum number of generations) is met.

#### 8.4.5.2 Mutation rate

Mutation helps to maintain diversity and avoid local optima. Mutation rate controls the probability of altering a gene:

$P_{mutation} = \mu \quad$ (8.7)

### 8.4.6 Erlang distribution (latency and queueing)

Latency in Network Slices: The Erlang distribution models latency through multiple hops or stages in a network slice. Each stage (such as packet forwarding or processing) contributes to the overall delay. This helps in optimizing the number of hops and service rates for different slices, ensuring that latency remains within the bounds defined by the QoS Agreement for each slice:

$f_l(x;k,\lambda) = \frac{\lambda^k x^{k-1} e^{-\lambda x}}{(k-1)!} \quad$ (8.8)

where $\lambda$ is the rate of service (packets per second), $k$ is the number of stages (hops), and $x$ is the latency (time in seconds).

- **Total Latency**: For each slice, the expected latency $L_{slice}$ is the sum of the latencies across all hops:

$L_{slice} = \sum_{i=1}^n L_i = \sum_{i=1}^n \frac{k_i}{\lambda_i} \quad$ (8.9)

### 8.4.7 Poisson distribution (packet arrivals and traffic bursts)

```
$P(k\text{ packets in interval } t) = \frac{\lambda^k e^{-\lambda}}{k!} \quad$ (8.10)
```

$\lambda$ is the average rate of packet arrivals (per second) and $k$ is the number of packets.

In the GA-RL combination, the Poisson distribution informs the RL agent about changes in traffic patterns (such as bursty traffic), triggering slice modifications. The RL agent monitors real-time traffic, adapting the slice's bandwidth and resource allocation based on the packet arrival rates. It minimizes over-provisioning and under-provisioning by dynamically adjusting slice capacity according to Poisson-modeled traffic arrivals.

### 8.4.8 Gaussian distribution (jitter and noise modeling)

Gaussian distributions are employed to model fluctuations (jitter) in network performance, such as delays due to queuing or packet loss caused by transient network issues.

```
$f(x\mu, \sigma^2) = \frac{1}{\sqrt{2\pi\sigma^2}} e^{\frac{(x-\mu)^2}{2\sigma^2}} \quad$ (8.11)
```

where $\mu$ is the mean delay and $\sigma^2$ is the variance (jitter).

The RL agent uses Gaussian distribution to learn and predict jitter behavior in the network. The GA component can then optimize slice configurations by selecting parameters that minimize jitter, ensuring real-time communication in uRLLC (ultra-reliable low-latency communication) slices. A truncated Gaussian distribution is used in the GA to prioritize configurations that are likely to perform:

```
$f(x) = \frac{1}{\sqrt{2\pi\sigma^2}} e^{\frac{(x-\mu)^2}{2\sigma^2}}, \ a \le x \le b \quad$ (8.12)
```

where $a$ and $b$ are the lower and upper bounds based on QoS constraints.

#### 8.4.8.1 Optimization

The optimization for the GA-RL combo is

```
$$\Minimize \sum_{i=1}^n w_i \cdot \text{KPI}_i - R(t) \quad$ (8.13)
```

$W_i$ is the weight assigned to each KPI (importance level), KPI is the predicted KPI value using the Erlang, Poisson, and Gaussian distributions, and $R(t)$ is the real-time reward provided by the RL agent.

#### 8.4.8.2 Reinforcement learning reward function

The RL agent's reward function is

```
$r_t = \alpha \cdot Q(t) - \beta \cdot (L(t) + J(t)) + \gamma \cdot T(t) \quad$ (8.14)
```

$\alpha$, $\beta$, and $\gamma$ are weights based on the importance of QoS adherence, latency minimization, and throughput maximization.

#### 8.4.8.3 Genetic algorithm fitness function

The GA fitness function uses KPI distributions to ensure slice configuration meets requirements:

```
$$\text{(Chromosome)} = \sum_{i=1}^n w_i \cdot \text{KPI}_i, \text{(Slice)} \quad$ (8.15)
```

where KPI uses Erlang for latency, Poisson for traffic, and Gaussian for jitter.

#### 8.4.8.4 Optimizing via genetic algorithm

The GA optimizes network slices by simulating natural selection processes. It uses fitness functions to evaluate solutions based on KPI values (latency, bandwidth, and jitter). The GA works by:

- Population Initialization: Each individual represents a possible slice configuration.
- Fitness Evaluation: The fitness function is computed using weighted KPI parameters:

```
$F = w_1 \left( \frac{1}{L+0.1} \right) + w_2 \cdot T + w_3 \left( \frac{1}{J+0.1} \right) \quad$ (8.16)
```
