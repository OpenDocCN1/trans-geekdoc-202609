## 14.3.2 Flowchart explanation

In Figure 14.2, the methodology flowchart is presented. The steps are explained as follows:

- 1. First, the Raspberry Pi and Arduino be powered up using USB cable, which provides an appropriate supply to the sensors.
- 2. Place the sensors on the patient’s body surface.
- 3. If the sensor is not correctly placed, the system shows “PLACE THE SENSORS PROPERLY” on the serial monitor.
- 4. After correct sensor placement, the patient’s vital parameters (body temperature, oxygen level of blood, heartbeat rate, and blood pressure) are collected using biomedical sensors.
- 5. The collected information will be displayed on an LCD and a serial monitor.
- 6. Collected parameters will be shared with the doctor through IOT using ThingSpeak Cloud.
- 7. The collected data was applied to the SVM classifier as testing data.
- 8. Here, the real-time data is taken from the patient. The SVM model created using the heart disease dataset was taken from Kaggle. This four-class dataset has temperature, blood pressure, oxygen, and heart rate values.

- 11. In the next class, if the heartbeat rate and blood pressure are high per medically defined values, the system will display the patient’s status in “HYPERTENSION”.

## 14.4 SYSTEM ARCHITECTURE AND COMPONENTS

### 14.4.1 System architecture

Figure 14.3 shows the system architecture of the proposed health monitoring system. The DHT11 temperature sensor is connected directly to the Raspberry Pi, while the blood pressure and pulse oximeter sensors (for heart rate and oxygen levels) are connected to an Arduino Uno R3. The pulse oximeter is routed through the Arduino instead of the Raspberry Pi due to accuracy concerns when connected directly.

The Arduino communicates with the Raspberry Pi via serial communication using the I2C protocol, with the Arduino as the slave and the Raspberry Pi as the master. This setup ensures efficient data transmission from the sensors.

Sensor data is then sent to a cloud platform, which is accessible via a doctor’s webpage for remote health monitoring. The data also serves as input for a ML model trained to predict conditions like fever, hypertension, and lung disease based on the readings.

### 14.4.2 Raspberry Pi

Figure 14.4 shows the Raspberry Pi 3 Model B, a compact yet powerful single-board computer released in February 2016. It offers advanced features ideal for IoT and health monitoring applications.

#### 14.4.2.1 Key features

##### 14.4.2.1.1 Quad-core processor and 1 GB RAM

The Raspberry Pi 3 Model B features a quad-core processor and 1 GB of RAM, offering enough power for multitasking and efficiently processing data from multiple sensors.

#### 14.4.2.2 40 GPIO pins

The board has 40 GPIO pins, enabling the Raspberry Pi to connect and communicate with external hardware like sensors and displays, making it ideal for embedded and IoT applications.

#### 14.4.2.3 Wireless LAN and Bluetooth Low Energy

The Raspberry Pi 3 Model B features the BCM43438 chip, providing built-in Wi-Fi and Bluetooth Low Energy (BLE) for easy data transfer and communication with Bluetooth devices, making it ideal for wireless IoT applications.

#### 14.4.2.4 64-bit CPU

The 64-bit CPU of the Raspberry Pi 3 Model B enhances performance, enabling faster computation, improved efficiency, and the ability to handle complex tasks like ML for health monitoring systems. These features make it a versatile platform for building real-time health monitoring systems, integrating biosensors, and managing cloud communication.

## 14.4.3 Arduino

Figure 14.5 shows the Arduino Uno, an open-source microcontroller based on the Microchip ATmega328P. Known for its simplicity and versatility, it has 28 pins, including six analog I/O pins, 12 digital I/O pins, and dedicated serial communication pins.

### 14.4.3.1 Key features

The Arduino Uno uses the Microchip ATmega328P microcontroller, known for its reliability and efficiency in interfacing with sensors and controlling hardware. It operates at 5 V, the standard voltage for powering and communicating with components like sensors, displays, and actuators.

### 14.4.3.2 Input voltage range

The Arduino Uno accepts an input voltage between 7 V and 20 V, allowing flexible power options through a 5 V supply or external sources like batteries or adapters. These features make it ideal for projects involving sensing, data acquisition, and control, offering a balance of functionality, ease of use, and adaptability.
