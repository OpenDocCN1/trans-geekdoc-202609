`**N O T E**`

`TCP` 也在一定程度上与 OSI 第 5 层相叠加，因为 `TCP` 包含会话管理功能，这些功能在 OSI 模型中属于会话层的范畴。但在此我们可以将传输层概括为 OSI 的第 4 层。

大多数网络应用依赖传输层协议来处理错误校正、流量控制、段的重传以及确认。然而，TCP/IP 模型并不要求每个传输层协议都必须实现这些功能。`UDP` 就是一个例子。如果你的应用需要使用 `UDP` 以获得最大吞吐量，则由你自己实现某种错误检测或会话管理，因为 `UDP` 本身不提供这些功能。

***The Internet Layer***

`Internet Layer` 负责在上层节点和目的节点之间路由数据包，通常跨越多个具有不同物理介质的网络。它的功能与 OSI 的第 3 层（网络层）相同。（有些资料将 TCP/IP 的 Internet Layer 称为 `网络层`。）

`IPv4`、`IPv6`、`BGP`、`ICMP`、`IGMP`、`IPsec` 等协议为 TCP/IP 的 Internet Layer 提供主机标识和路由功能。我们将在下一章讨论 **14** 章节——主机寻址与路由时，对这些协议进行详细说明。现在只需知道，该层在确保数据无论源到目的之间的复杂程度如何，都能成功送达目的地方面发挥关键作用。

***The Link Layer***

`Link Layer` 对应 OSI 参考模型的第 1、2 层，是核心 TCP/IP 协议与物理介质之间的接口。

`Link Layer` 的 `ARP`（地址解析协议）将节点的 IP 地址转换为其网络接口的 MAC 地址。Link Layer 在帧的头部嵌入 MAC 地址，然后将帧交给物理网络。我们将在下一章讨论 MAC 地址及其路由意义。

并非所有 TCP/IP 实现都包含链路层协议。老一辈读者可能记得通过模拟调制解调器（analog modems）连接互联网的乐趣。模拟调制解调器通过串行链路与 ISP 相连，这些串行链路本身并不包含通过串行驱动或调制解调器实现的链路层支持。相反，它们需要使用 `SLIP`（串行线 Internet 协议）或 `PPP`（点对点协议）等链路层协议来填补空白。那些没有实现链路层的实现通常依赖底层网络硬件和驱动程序来弥补缺失。本书将使用以以太网、无线和光纤为基础的 TCP/IP 实现，它们依赖设备驱动或网络硬件来完成 TCP/IP 栈的链路层部分。

**The Internet Protocol**

`Internet Protocol (IP)` 是一组规则，规定了数据在网络（即互联网）上传输的格式。`IP 地址` 在 TCP/IP 栈的 Internet 层标识网络上的节点，并用于促进节点间的通信。
