
-   [它自己的协程。](https://example.org) 我们通常称这个协程为`handler`。我稍后会解释`handler`的实现细节，但它会每次从套接字读取最多1024字节并记录它接收到的内容。

-   标准库的`net.Dial`函数与`net.Listen`函数类似，它接受一个网络类型（如tcp）以及IP地址和端口的组合——在此案例中，是尝试连接到的监听器的IP地址和端口。你可以使用主机名代替IP地址，使用服务名（如`http`）代替端口号。如果主机名解析为多个IP地址，Go会按顺序尝试连接每个地址，直到连接成功或所有IP地址都被尝试完毕。由于IPv6地址包含冒号分隔符，必须将IPv6地址用方括号括起来。例如，"[2001:ed27::1]:https"指定端口443，IPv6地址为2001:ed27::1。`Dial`函数返回一个连接对象和一个错误接口值。

-   现在你已经成功建立了与监听器的连接，从客户端的侧面发起优雅的连接终止。在收到FIN包后，Read方法会返回io.EOF错误，向监听器的代码表明你已关闭自己的连接一侧。连接的处理器在退出时会调用连接的Close方法，这会向你的连接发送一个FIN包，完成TCP会话的优雅终止。

-   最后，你关闭监听器。监听器的Accept方法会立即解除阻塞并返回一个错误。这个错误不一定表示失败，所以你只需记录它并继续。它不会导致测试失败。监听器的协程退出，测试完成。

**理解超时和暂时错误**

在一个完美的世界里，你的连接尝试会立即成功，所有读取和写入操作都永远不会失败。但你需要为最坏的情况做准备。你需要一种方法来判断错误是暂时性的，还是应该终止连接的。错误接口不提供足够的信息来做出这个判断。幸运的是，Go的net包提供了更多信息，如果你知道如何使用它。

net包中的函数和方法通常返回实现了net.Error接口的错误，该接口包含两个 notable 方法：Timeout和Temporary。Timeout方法在Unix操作系统和Windows上返回true，如果操作系统表明资源暂时不可用、调用会阻塞，或连接超时。我们稍后会详细讨论超时及如何利用它们。Temporary方法返回true，如果错误的Timeout函数返回true，调用被中断，或者系统上有太多打开的文件（通常是因为超过了操作系统的资源限制）。

由于net包中的函数和方法返回的是更通用的error接口，本章的代码会使用类型断言来验证你确实收到了net.Error，如在Listing 3-4所示。

```
if nErr, ok := err.(net.Error); ok && !nErr.Temporary() { return err }
```

*Listing 3-4: 使用类型断言验证错误是否为net.Error，并检查其Temporary属性*

健壮的网络代码不会仅仅依赖错误接口，而是会积极使用net.Error的方法，甚至深入分析底层的net.OpError结构体，该结构体包含更多关于连接的信息，如导致错误的操作、网络类型、源地址等。我建议你阅读net.OpError文档（https://golang.org/pkg/net/#OpError）以了解超出net.Error接口所提供的具体错误。

**使用DialTimeout函数超时连接尝试**

使用Dial函数有一个潜在问题：你依赖操作系统来超时每个连接尝试。例如，如果你在交互式应用中使用Dial函数，而操作系统在两小时后超时连接尝试，用户可能不愿意等待这么久，更不用说给你的应用五星好评了。

为了让你的应用更可预测，让用户更开心，最好由你自己控制超时时间。例如，你可能想连接到一个低延迟服务，如果服务可用则快速响应；如果服务不响应，则快速超时并转向下一个服务。

一种解决方案是明确定义每个连接的超时时间，并使用DialTimeout函数。Listing 3-5实现了这个方案。

```go
package ch03

import (
    "net"
    "syscall"
    "testing"
    "time"
)

func DialTimeout(network, address string, timeout time.Duration) (net.Conn, error) {
    d := net.Dialer{
        Control: func(_, addr string, _ syscall.RawConn) error {
            return &net.DNSError{
                Err:     "connection timed out",
                Name:    addr,
                Server:  "127.0.0.1",
                IsTimeout: true,
                IsTemporary: true,
            }
        },
        Timeout: timeout,
    }
    return d.Dial(network, address)
}

func TestDialTimeout(t *testing.T) {
    c, err := DialTimeout("tcp", "10.0.0.1:http", 35*time.Second)
    if err == nil {
        c.Close()
        t.Fatal("connection did not time out")
    }

    nErr, ok := err.(net.Error)
    if !ok {
        t.Fatal(err)
    }

    if !nErr.Timeout() {
        t.Fatal("error is not a timeout")
    }
}
```

*Listing 3-5: 指定超时时间时初始化TCP连接*

*(`dial_timeout_test.go`)*

由于net.DialTimeout函数不允许你控制net.Dialer以模拟dialer的输出，你使用了我们自己实现的函数，其签名与net.Dialer一致。你的DialTimeout函数重写了net.Dialer的Control函数以返回一个错误。你正在模拟一个DNS超时错误。

与net.Dial函数不同，DialTimeout函数多了一个参数：超时时间。在这个例子中，超时时间为五秒，如果在五秒内没有建立连接，连接尝试将超时。在这个测试中，你尝试连接到10.0.0.1，这是一个不可路由的IP地址，这意味着连接尝试必然会超时。为了通过测试，你需要先使用类型断言验证你收到了net.Error，然后检查其Timeout方法。

如果你尝试连接一个解析为多个IP地址的主机，Go会在每个IP地址之间启动连接竞争，给主IP地址一个先手的优势。第一个成功的连接将保持，其余正在尝试的连接会被取消。如果所有连接失败或超时，net.DialTimeout会返回一个错误。

**使用带有Deadline的Context来超时连接尝试**

一种更现代的解决超时连接尝试的方法是使用标准库context包中的context。context是一个可以用于向异步进程发送取消信号的对象。它还允许你在达到截止时间或计时器到期后发送取消信号。

所有可取消的context都有对应的取消函数，在实例化时返回。取消函数提供了更大的灵活性，因为你可以在context达到截止时间之前可选地取消context。

你也可以将它的取消函数传递给其他代码，以将取消控制权交给其他部分。例如，你可以监听操作系统发送给你的信号，如用户按下ctrl-C键组合时发送的信号，以优雅地中止连接尝试并清理现有连接，然后再终止应用。
