`TCP` 是第 4 层协议，其负载也被称为 `segments` 或 `datagrams`。`TCP` 接受第 5 层的负载，并在发送到第 3 层之前添加头部。第 3 层的 `Internet Protocol` *(IP)* 接收 `TCP` 段，并为其添加头部，创建第 3 层的负载，称为 `packet`。第 2 层接受数据包，添加头部和尾部，创建其负载，称为 `frame`。第 2 层的头部将接收方的 IP 地址转换为 `media access control` *(MAC)* 地址，这是分配给节点网络接口的唯一标识符。其尾部包含 `frame check sequence` *(FCS)*，这是一种校验和，用于便于错误检测。第 1 层接收第 2 层的负载（比特形式），并将比特发送到服务器。

服务器的第 1 层接收比特，将其转换为帧，并向上传到第 2 层。第 2 层从帧中剥除头部和尾部，并将数据包传递给第 3 层。自上而下逆转每一层的封装过程，直到负载到达第 7 层。最终，HTTP 服务器从网络栈中接收到客户端的请求。

**The TCP/IP Model**

与研究人员在开发 OSI 参考模型的同时，国防高级研究计划局（DARPA），美国国防部下属机构，也在并行开发协议。这一努力促成了我们现在称之为 `TCP/IP model` 的一组协议。该项目对美国军队的影响深远，进而影响了全球通信。`TCP/IP model` 在微软于 1990 年代初期将其纳入 Windows 95 时达到了关键质量。如今，`TCP/IP` 在计算机网络中无处不在，是本书将使用的协议栈。

`TCP/IP`——以 `Transmission Control Protocol` 和 `Internet Protocol` 命名——促进了基于 `end-to-end` *principle* 的网络设计，即每个网络段仅包含传输和路由比特所需的最小功能；所有其他功能都属于端点，即发送方和接收方的网络栈。这与现代蜂窝网络不同，在蜂窝网络中，必须由位于手机之间的网络提供更多功能，以便在手机在不同基站之间切换时，电话连接不会中断。

`TCP/IP` 规范建议实现应具有健壮性；它们应发送结构正确的数据包，但应接受任何意图明确的数据包，无论其是否严格遵守技术规范。

与 OSI 参考模型类似，`TCP/IP` 也依赖于层封装来抽象功能。它包含四个命名层：应用层、传输层、Internet 层和链接层。`TCP/IP` 的应用层和链接层对应 OSI 的相应层，如图 1-11 所示。

`TCP/IP model` 简化了 OSI 的应用、表示和会话层为单一的应用层，主要是因为 `TCP/IP` 的协议经常跨越 OSI 第 5 至 7 层的边界。同样，OSI 的数据链路层和物理层对应 `TCP/IP` 的链接层。`TCP/IP` 的传输层和网络层与 OSI 的对应层是一一对应的。

这种简化的原因是研究人员先开发原型实现，然后再正式标准化最终实现，从而得到一个更偏向实际使用的模型。相反，委员会花费大量时间在创建 OSI 参考模型之前制定广泛的需求，导致模型复杂度增加。

***The Application Layer***

与 OSI 的应用层类似，`TCP/IP model` 的 `application layer` 直接与软件应用交互。我们编写的大多数软件都使用该层的协议，当你的 Web 浏览器检索网页时，它也从该层读取数据。

你会发现 `TCP/IP` 的应用层实际上涵盖了三个 OSI 层。这是因为 `TCP/IP` 没有定义具体的表示或会话功能。相反，具体的应用协议实现负责这些细节。正如你将看到，一些 `TCP/IP` 应用层协议很难仅落在 OSI 模型的单一上层，因为它们的功能跨越多个 OSI 层。

常见 `TCP/IP` 应用层协议包括 `HTTP`，用于网页检索，`File Transfer Protocol` *(FTP)* 用于节点间文件传输，以及 `Simple Mail Transfer Protocol` *(SMTP)* 用于向邮件服务器发送电子邮件。An Overview of Networked Systems **13**

`Dynamic Host Configuration Protocol` *(DHCP)* 和 `Domain Name System` *(DNS)* 也在应用层运行。`DHCP` 和 `DNS` 分别提供地址分配和名称解析服务，使其他应用层协议能够运行。`HTTP`、`FTP` 和 `SMTP` 是提供 `TCP/IP` 应用层表示或会话功能的协议实现示例。我们将在后续章节中讨论这些协议。
