
网络。一个 `computer network` 是两个或多个设备（或 `nodes`）之间的连接，允许每个节点共享数据。这些连接本身并不具有可靠性或安全性。好在 Go 的标准库及其丰富的生态系统非常适合编写安全、可靠的网络应用。

本章将为本书的练习提供基础知识。你将了解网络的结构以及网络如何通过协议进行通信。

## 选择网络拓扑结构

网络中节点的组织被称为 `topology`。网络的 `topology` 可以是简单的两个节点之间的单一连接，也可以是复杂的、节点之间不直接相连但仍能交换数据的布局。这通常是你的电脑与互联网节点之间的连接情况。拓扑类型主要分为六类：点对点、串联、总线、环、星和网格。

`Ring` 拓扑是一个闭合环，数据单向传输。例如，图 1-4 中节点 N 可以通过节点 O、P、Q 向节点 R 发送消息。节点 O、P、Q 会重传消息，直到到达节点 R。

如果节点 P 失败未能重传消息，它将永远到达不了目的地。

由于这种设计，最慢的节点会限制数据传输的速度。假设流量顺时针传输且节点 Q 最慢，节点 Q 会限制从节点 O 到节点 N 的流量，但从节点 N 到节点 O 的流量不受节点 Q 慢速的影响，因为该流量不经过节点 Q。

在完全连接的 `mesh` 网络中，每个节点都与其他所有节点有直接连接（图 1-6）。这种拓扑消除了单点故障，因为单个节点的故障不会影响其他节点之间的流量。但成本和复杂度随节点数量增加而上升，使得大规模网络不适用。这也是你可能只会在大型无线网络中遇到的拓扑。

混合拓扑旨在通过利用每种拓扑的优势、限制每种拓扑的缺点到单个网络段，来提升可靠性、可扩展性和灵活性。

例如，图 1-7 中 `star-ring` 混合网络的中心节点故障只会影响环网间的通信，各环网仍能正常工作且彼此隔离。在星环混合网络中，单个节点的故障比在单一大环网中更容易定位，且故障范围仅限于网络的子集。

## 带宽 vs. 延迟

网络 `bandwidth` 是在时间间隔内我们可以在网络连接上传输的数据量。如果你的互联网连接被标记为 **6** 第 1 章 *100Mbps download*，这意味着你的 ISP 到调制解调器的理论最大传输速率为每秒 100 兆位元。

运营商不断用广告宣传他们提供的带宽，以至于我们很容易只关注带宽，并把它等同于连接速度。但更快不一定意味着更好的性能。这可能看似反直觉，但低带宽的网络连接可能因为一个特性——延迟（latency）——表现得比高带宽的连接更好。延迟是指从发送网络请求到接收响应所经过的时间。例如，点击网站链接后到页面渲染完成的延迟就是延迟的体现。你可能曾点击链接却发现页面迟迟加载，浏览器在放弃等待服务器响应前就放弃了。

高延迟会对用户体验产生负面影响，导致服务不可用，并驱使用户离开你的软件或服务。管理网络软件中的延迟对开发者来说常被忽视。不要陷入认为带宽是网络性能唯一重要因素的误区。

网站的延迟来源包括：客户端与服务器之间的网络延迟、从数据存储中获取数据的时间、服务器端动态内容编译的时间、以及浏览器渲染页面的时间。如果用户点击链接后页面渲染耗时过长，用户很可能离开，延迟会导致流量流失。在编写网络软件（无论是 Web 应用还是应用程序编程）时，保持延迟最小是关键。
