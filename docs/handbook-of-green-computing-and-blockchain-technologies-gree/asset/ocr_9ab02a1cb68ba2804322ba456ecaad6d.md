The size of a transaction in a block is approximately 250 bytes. A block header is a field of 80 bytes in a block. The size of a complete block having maximum of its transaction is approx. 1,000 times of the block header. The rest of the fields are as follows:

+   * Block size: Represents the size of block of 4 bytes.
+   * Transactions: It is a variant and stored in the same block.
+   * Transaction Counter: It is variant in size (1–9) bytes and defines how many transactions have been done.

**VI. Block creation and verification:** A blockchain consists of a number of blocks which are used to store the data generated by the number of transactions takes place in the network. To make a fresh transaction, there is a requirement of public key and private keys for the implementation of secure and successful transaction between two parties. During a transaction, both of these keys are used to generate the digital signature which are further used to authorize and validate the transaction [9]. If any third tries to make changes in the transaction data leads to the drastic change in the digital signature. To validate the transaction on the network various consensus algorithm are used. In short, if a node is interested to make transaction, this transaction is further broadcast to every node in a peer-to-peer network as shown in Figure 6.4.

The next step is to validate and authenticate the transaction done with the help of consensus mechanism. After the validation of transaction, it will get added in the block. When a block is reaches to its maximum capacity then it is added to the current blockchain with the help of a hash function [10].
