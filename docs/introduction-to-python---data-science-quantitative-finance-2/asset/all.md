How about two-digit integers, or three, four or even five and what if we would like to have all the Armstrong numbers printed out within a given upper limit? Now we need an algorithm or a more structured plan: First of all, we read the input of the integer number digit by digit (to do so, we must convert the integer into a string then we repeat the i3 for each digit and sum up. Since the purpose is to sum up the i3 ![](Image00004.jpg)for each digit, we need to add up the previous calculation in each for loop step since otherwise, with l=int(i)\*int(i)\* int(i) only, it gives the last digit’s cube value. We use a for  loop if we know the maximum number of times that we will need to execute the body. For example, if we are traversing a list of elements, we know that the maximum  number of loop iterations we can need is “all the elements in the list”. By contrast, if we are required to repeat some computation until some condition is met, and we cannot calculate in advance when this will happen, we will need a while  loop. We call the first case (for loop) definite iteration  — we have some definite bounds for what is needed. The latter case (while loop) is called indefinite iteration  — we’re not sure how many iterations we’ll need — we cannot even establish an upper bound! 3.4       Object Oriented Programming (OOP) What we have seen so far are either command line programming or functions that we could be executed in a simple Shell and editor. And now we will introduce another approach which is called Object Oriented programming. Believe me that most of personal usage cases, functional programming can handle well, unless it is in a large-scale team development environment. The main advantages that I could think of by using OOP are: 

*   Code reusability – reuse the same code, nevertheless, this can also be achieved by functions 
*   Encapsulation – internal representation of an object is generally hidden from view outside of the objects’ definition. A class is an example of encapsulation as it encapsulates all the data that is member functions, variables, etc. 

The disadvantages are: 

*   It slows down the programme by allocating object space in the memory 
*   Unnecessary complexity which confuses people and increase the chance of mistakes 
*   Not easy to read by others if people have different mindset 

For the example explored and analysed in this chapter: Asset Price paths, we could easily write it an OOP way. Modifying the three model functions, we have the following code: 

class Model ():  
     def \_\_ init \_\_ ( self , s\_1 , dt , r ):  
         self .s\_1 = s\_1  
         self .dt = dt  
         self .r = r  
def calculate\_drift\_ds ( self ):  
        ds = self .s\_1 \* self .r \* self .dt  
        return ds  
\# subclass

         \# re-use the parent class function  
         Model. \_\_init\_\_ ( self , s\_1 , dt , r )

        return self .calculate\_drift\_ds() + self .s\_1  
class Stochastic\_model (Model):  
    def \_\_ init \_\_ ( self , s\_1 , dt , mu , vol ):  
        Model. \_\_init\_\_ ( self , s\_1 , dt , mu )  
         self .vol = vol

        dW = self .calculate\_dW()  
         \# re-use the parent class function PLUS modification
