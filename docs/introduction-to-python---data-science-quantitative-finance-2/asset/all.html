Stories apart, let's look at the definition of programming:
Programming is the process of taking an algorithm and encoding it into a notation, a programming language so that it can be executed by a computer. The important first step is the need to find a solution to a problem or requirement. Programming is often the way we create a representation of our solutions.
Let’s start with a small example: Armstrong Numbers. An Armstrong number of three digits is an integer such that the sum of the cubes of its digits is equal to the number itself. For example, 371 is an Armstrong number because 33 + 73 + 13 = 371.
How shall we program the algorithm or solution for this? Now we have a requirement and a need to solve it. Second, we must break down the problem (abstract it) before attempting a solution.
The smallest Armstrong number is 1 since 1^3 = 1. It is easy for a single digital integer, we just need to get the input and multiply it by itself three times. If it is equal to the input integer, it is Armstrong number, otherwise, it is not.
How about two-digit integers, or three, four or even five and what if we would like to have all the Armstrong numbers printed out within a given upper limit? Now we need an algorithm or a more structured plan:
First of all, we read the input of the integer number digit by digit (to do so, we must convert the integer into a string then we repeat the i3 for each digit and sum up. This involves a for loop:
l = 0
s = str(n)
for i in s:
l = int(i)* int(i)* int(i) + l
We have converted the multi-digit integer into a string s by having s = str(n) where n is the input integer.
The for loop reads each character of the string and calculates the i3 . Here there is a data type conversion from string to integer by writing int(i) so that an arithmetic operation can be performed. Since the purpose is to sum up the i3 for each digit, we need to add up the previous calculation in each for loop step since otherwise, with l=int(i)*int(i)* int(i) only, it gives the last digit’s cube value.
For n = 123, the result of the above code gives 13 + 23 + 33 = 36
Now we need to wrap it into a function so that it can be reused later from the main function. Let's say the next step is to find all the Armstrong numbers between 1 and an upper limit. Now you must be visualizing that there is a kind of for loop involved to calculate each integer within this range and if it fits the Armstrong number criteria, we keep it and print it out. If not, we continue. Consequently, a sort of Armstrong number test function is needed to check whether the criteria is met or not.
First, we wrap the algorithm that we have just mentioned into a function arm(n) ( Python function will be introduced in chapter 1.6) with the case where the input n is single digit integer:

For or while?
We use a for  loop if we know the maximum number of times that we will need to execute the body. For example, if we are traversing a list of elements, we know that the maximum number of loop iterations we can need is “all the elements in the list”.
By contrast, if we are required to repeat some computation until some condition is met, and we cannot calculate in advance when this will happen, we will need a while  loop. We call the first case (for loop) definite iteration  — we have some definite bounds for what is needed. The latter case (while loop) is called indefinite iteration  — we’re not sure how many iterations we’ll need — we cannot even establish an upper bound!

  #we assume that asset increase at the risk-free rate r
    s = s_1 * ( 1 + r * dt )
     return s

    s = s_1
     return s
def stochastic_model ( s_1 , dt , mu , vol ):
    dW = np.random.randn( 1 )[ 0 ]* np.sqrt(dt )
#numpy ndarray gives an array type, as there is only one random number in it, we take the value using [0]
    ds = mu * s_1 * dt + vol * s_1 * dW
    s = s_1 + ds
    return s
As the future asset path is a time series along the time horizon. For the stochastic model, we will need the Monte Carlo technique which is realized by the NumPy package here.
Because of the uncertainty (unlike the deterministic or constant Model), we will need simulation not just along the time horizon, but also on multiple simulation paths which leads to an overview of potential asset price paths.
At the beginning of the code, I have defined certain market data by hard coding. Obviously, these parameters could have different values, but some condition must be respected:
  1. volatility cannot excess 100% - here we set volatility to 10%
  2. drift rate μ ( mu ) and risk-free rate r need to be a small number – we set the risk-free rate to 1% and the drift rate to 4% which represents the current rate and economic growth level.
  3. dt is the time step which needs to be small enough to respect its conceptual meaning – we set dt to 0.1
  4. time_step is linked to the maturity of the underlying
  5. sim_step determines the accuracy of the simulation results.
Here for the purpose of illustration, we set both two low numbers for both time_step and sim_step to speed up the running time.

3.4      Object Oriented Programming (OOP)
What we have seen so far are either command line programming or functions that we could be executed in a simple Shell and editor. And now we will introduce another approach which is called Object Oriented programming.
Believe me that most of personal usage cases, functional programming can handle well, unless it is in a large-scale team development environment. The main advantages that I could think of by using OOP are:
  • Code reusability – reuse the same code, nevertheless, this can also be achieved by functions
  • Encapsulation – internal representation of an object is generally hidden from view outside of the objects’ definition. A class is an example of encapsulation as it encapsulates all the data that is member functions, variables, etc.
The disadvantages are:
  • It slows down the programme by allocating object space in the memory
  • Unnecessary complexity which confuses people and increase the chance of mistakes
  • Not easy to read by others if people have different mindset
For the example explored and analysed in this chapter: Asset Price paths, we could easily write it an OOP way. Modifying the three model functions, we have the following code:

class Model ():
     def __ init __ ( self , s_1 , dt , r ):
         self .s_1 = s_1
         self .dt = dt
         self .r = r
def calculate_drift_ds ( self ):
        ds = self .s_1 * self .r * self .dt
        return ds
# subclass
class Deterministic_model (Model):
    def __ init __ ( self , s_1 , dt , r ):
         # re-use the parent class function
         Model. __init__ ( self , s_1 , dt , r )
def calculate_price ( self ):
        return self .calculate_drift_ds() + self .s_1
class Stochastic_model (Model):
    def __ init __ ( self , s_1 , dt , mu , vol ):
        Model. __init__ ( self , s_1 , dt , mu )
         self .vol = vol
def calculate_price ( self ):
        dW = self .calculate_dW()
         # re-use the parent class function PLUS modification
         drft_ds = self .calculate_drift_ds()
        stochastic_ds = self .vol * self .s_1 * dW
        ds = drft_ds + stochastic_ds
        return ds + self .s_1
    def calculate_dW ( self ):
        return np.random.randn( 1 )[ 0 ] * np.sqrt( self .dt)
Class is a set or category of things having some property or attribute in common and differentiated from others by kind, type, or quality.
We have parent class called Model() and two subclass called Deterministic_model(Model) and Stochastic_model(Model). They both inherit the parent class Model, meaning its constructor __init__() and its function calculate_drift_ds()
Self represents the instance of the class. By using the "self" keyword we can access the attributes and methods of the class in python.
The __init__() method is a constructor and runs as soon as an object of a class is instantiated. Its aim is to initialize the object. This method is called when an object is created from the class and it allows the class to initialize the attributes of a class.
Object is one of instances of the class, which can perform the functionalities which are defined in the class.
On the Python console, we could execute the following command line code to illustrate what does these classes are doing and how to understand the basic of OOP. First, we set some variables which will be used as arguments for inputs:
>>> dt = 0.1
>>> r = 0.01
>>> s_1 = 100
Second, we create an object of class Model:
>>> x = Model(s_1, dt, r)
>>> x
<__main__.Model instance at 0x00000000110E17C8>
The object x - one of instances of the class Model has been created and the constructor __init__() is run as soon as x is instantiated by having the three arguments:  s_1, dt, r provided as input at the instantiation.
By having the object x, we could access the functions defined in the class Model:
>>> x.calculate_drift_ds()
0.1
We then create an object y – one of instances of the class Deterministic_model(Model) which is the subclass of the Model . So y runs Model’s constructor ___init__() and its function calculate_price() which reuses its parent model’s function calculate_drift_ds():
>>> y = Deterministic_model(s_1, dt, r)
>>> y.calculate_price()
100.1
For object z, the instance of the Stochastic_model(Model) ,it inherits the parent class Model’s constructor and modify it by having an extra argument vol.
The beauty of the OOP is the code reusability which inherits part of the code and add extra features if needed.
>>> z = Stochastic_model(s_1, dt, r, vol)
>>> z.calculate_price()
97.5257618399161
Each time we execute the above two lines, the output is different as each time, the class Stochastic_model ’s internal function calculate_dW() is called within the class function Stochastic_model.calculate_price() to generate a random number which is used in the stochastic price calculation. This is a typical example of encapsulation which “hides” from outside view the function calculate_dW() and its relevant data.
You can spot the downside of the OOP, x, y and z object all have its own function calculate_price() , but outputs different results under the same input variables. If we do not pay attention on the class level implementation of each calculate_price() function, confusion and mistakes are inevitable.
