
# MQTT 协议

MQTT 协议 \[[37](#ch5.xhtml#ref5_37)\] 在本章中被考虑。它是一种轻量级协议，易于在软件中实现以实现更好的数据传输。它基本上以服务器和客户端的概念工作，具有低网络使用率和低功耗。服务器（代理）负责处理客户端之间发送或接收数据的请求。这种安排也称为发布和订阅。在发布概念中，客户端希望向代理发送数据，而在订阅中，客户端希望从代理接收数据。

MQTT 协议数据包格式的基本结构在 [图 5.5](#ch5.xhtml#fig5_5) 中给出。字段长度被认为是 8 位以处理信息。在第 1 字节中，考虑了消息类型、DUP（重复标志）和服务质量（QoS）级别位。在第 2 字节中，使用剩余长度（1–4 字节）来完成通信。第 3 字节到第 n 字节用于可变长度头部，第 n+1 字节到第 m 字节包含消息负载。当客户端和代理之间激活连接时，订阅者需要从客户端接收一个或多个主题。

![图 5.5 MQTT 数据包基本格式。](images/fig5_5_B.jpg)
[图 5.5 MQTT 数据包基本格式。](#ch5.xhtml#R_fig5_5)

安全 MQTT 提供身份验证以确认单个数据或信息的属性的真实性。它在通信消息或连接消息中提供用户名和密码字段。因此，它使客户端在连接到 MQTT 代理时能够发送经过身份验证的用户名和密码。然后，代理将在实现的机制上评估身份验证凭据并返回各种代码，如 0 – 已接受，1 – 用户名和密码错误，以及 2– 未授权。客户端标识符也通过提供唯一的客户端标识符、序列号和唯一的 MAC 标识来对 MQTT 通信进行身份验证。

[图 5.6](#ch5.xhtml#fig5_6) 显示了面向 IoT 的环境中通信协议的基本结构。基础层被认为是网络/链路层，支持蓝牙低功耗（BLE）/IEEE 803.15.4。第二层被称为互联网层，有助于在低功耗无线个人局域网（LoWPAN）上创建 IPv6 协议。第三层在传输层支持 TCP 和 UDP 协议。顶层向应用层提供 MQTT/CoAP 协议服务。TCP 支持 MQTT 协议，UDP 有助于 CoAP 协议在 IoT 传输层上运行。

![图 5.6 面向 IoT 环境的通信协议。](images/fig5_6_B.jpg)
[图 5.6 面向 IoT 环境的通信协议。](#ch5.xhtml#R_fig5_6)

MQTT 协议的各种优势如下列出。
* 在数据/信息分发方面更有效
* 有助于提高可扩展性
* 在轻量级处理中工作
* 基于权限的方法提供更好的安全性
* 缩短开发阶段的持续时间
* 基于发布者和订阅者的协议支持大数据的通信，同时带宽更少。

## 5.5.2 带用户名和密码的 MQTT 协议

相同的代码加上用户名和密码提供单层安全性。以下信息为 MQTT 协议在用户名和密码方面提供单层安全性。这种身份验证与 MQTT 协议的传输层和应用层相连。在传输层，使用基于客户端的认证，在应用层，用户和密码保护 MQTT 协议。

经身份验证的 MQTT 协议由以下 Python 语法组成：
* `User = “username”`
* `Password=“password”`
* `Client.username_pw_set (“username”, “password”)`

上述语法被视为具有简单实体的单一保护。它通过验证用户名和密码来帮助识别经过身份验证的人员、设备和应用程序。当这种单层安全性内置于 MQTT 协议时，对应的 MQTT 代理会评估身份验证并响应，如连接已接受或因用户名和密码无效而连接失败。因此，在 MQTT 协议中提供内置的用户名和密码以实现安全数据传输非常容易。

## 5.5.3 IoT Arduino 环境中的 MQTT 协议

一个常见的 IoT 环境被称为 Arduino 硬件 \[[34](#ch5.xhtml#ref5_34)\]，它也支持 MQTT 协议以及用户名和密码保护。Arduino 支持以太网网络并允许用户连接到互联网。也可以使用以太网和 MQTT 库来开发 MQTT 客户端-服务器。MQTT 库在 Arduino 环境中不是默认的，有必要通过导航到 Arduino IDE 草图来安装它们，如 [图 5.8](#ch5.xhtml#fig5_8) 所示。步骤如下：

![图 5.8 MQTT 库安装。](images/fig5_8_B.jpg)
[图 5.8 MQTT 库安装。](#ch5.xhtml#R_fig5_8)

1. 步骤 1：`Arduinouno` 草图 > 包含新库 > 管理库（用于搜索 MQTT 库 – `PubSubClient`）
2. 步骤 2：创建新文件 > 包含 `SPI.h`、`Ethernet.h` 和 `PubSubClient.h` 库。
   `SPI` 库（串行外设接口）用于较短距离的硬件通信以获得更快的响应。它也用于以太网支持库。`PubSubClient` 库用于激活 MQTT 协议。
3. 步骤 3：以 IP 地址、MAC 地址和服务器配置的形式定义 MQTT 规范
   IP 地址用于以太网连接，MAC 地址包含唯一值。服务器配置是一个简单的设计，可以使用免费的 MQTT 代理。
4. 步骤 4：在 `Void setup` 中，包含用于调试过程的串行开始、以太网开始、设置 MQTT 服务器、尝试连接服务器并建立订阅。
5. 步骤 5：在 `Void loop` 中，包含顶层循环，并尝试向接收者发布和订阅消息。
