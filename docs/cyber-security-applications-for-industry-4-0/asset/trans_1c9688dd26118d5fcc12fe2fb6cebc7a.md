

# 云计算与数据隐私

云计算对于 IT 应用极具前景；尽管如此，仍有一些问题亟待解决。Doshi、Riddhi 和 Vivek Kute [[1](#ch10.xhtml#ref10_1)] 介绍了云计算，它使用户能够生成、个性化和设置在线应用程序。它允许用户自适应地访问软件工具和一组资源。它是一种计算方法论，其中大量系统节点通过私有或公共方式链接在一起，为各种数据文件存储提供持续、高可用的网络协议栈。它通过互联网提供受限的消费者操作服务访问和数据资源利用。尽管它提供了重要的服务，但也面临着安全问题。许多潜在的云应用程序受到通用方法的困扰，即由于来自 IT 和其他企业组织的商业需求，共享云服务变得不稳定且不安全。由于“资源池化”被认为是最重要的特征之一，当该特性与其他云用户共享时，它变得至关重要。由于数据泄露、不稳定的数据接口和数据破坏，导致了更大的风险和安全问题。

在云生态系统中部署数据应用程序时，一个重大问题是在敏感交易期间如何保持隐私。具有挑战性的因素是如何在许多云服务外包给多个用户（特别是 `Storage-as-a-service` [存储即服务]）的情况下，以确保隐私的方式传输数据。当然，隐私顾虑并不以同等程度影响所有与云部署模型相关的模型。与公有云和混合云模型相比，私有云受影响较小。事实上，前者或多或少地面向公众（个人、企业等）开放，而私有云资源则专门为单一实体（如企业）量身定制。管理和监管这些资源是该组织的职责。“私有云”一词是指遵循云范式（包括其特征、特性和服务层级）的个人身份信息系统。

恶意攻击存储在云系统中的用户数据是任何商业实体常见的现象，其主要目标是在获取经济利益之前获取用户隐私。在这种情况下，最迫切需要解决的问题是传统的法律、法规和流程，因为这些现有的法律政策不足以保护与业务相关的敏感数据。因此，应建立和完善相关法律法规，为第三方系统提供可信且保护隐私的安全性，以满足公司要求。当问题出现时，应提供明确的责任划分，同时也应考虑在云服务提供商（`CSPs`）退出时提供保护机制。大多数国内实体不愿将敏感数据委托给第三方，而是倾向于建立自己的私有云。当数据被带出公司时，`Data Privacy`（数据隐私）设置将超出企业的控制范围。使用第三方云服务伴随着多种风险。一个重大风险是 `Key Management`（密钥管理），在云环境中，加密密钥的管理变得更加复杂。

数据隐私可以通过在数据离开组织边界之前对其进行加密来简单实现，无论是使用对称/非对称加密，还是使用当前的密码学技术，如 `Identity-Based Encryption`（`IBE`，基于身份的加密）或 `Attribute-Based Encryption`（`ABE`，基于属性的加密）。`IBE` 是由授权的第三方服务器从公钥中提取相关私钥的过程。然而，通过第三方云服务安全地管理和发送加密密钥是组织的责任。使用客户端加密可以提高数据保密性；然而，大多数提出的解决方案侧重于数据安全而非密钥安全，导致密钥保密性不够安全，这在 `FADE` 的架构中数据传输期间的密钥泄露得到了证明。现代加密技术，如 `IBE` 和 `ABE`，并不意味着应给予 `Secure Key Exchange`（安全密钥交换）更多关注。

## 10.2 IaaS 密钥管理问题

`IaaS` 是指按需访问云托管基础设施，如服务器、存储和网络资源，云用户可以像使用本地硬件一样安装、配置和使用它们。区别在于 `CSP` 通过其自己的云数据中心托管和管理硬件和存储资源。使用 `IaaS` 的客户按订阅制或按使用付费的方式，通过互联网为其使用的存储系统付费。安全威胁和要求因 `IaaS` 环境中的部署模型（`Hybrid` 混合云、`Public` 公有云或 `Private` 私有云）而异。数百万个变量和技术影响 `IaaS` 安全威胁列表，特别是通过云存储数据库进行的敏感数据交易。

Ahmed Bentajer 和 Mustapha Hedabou [[2](#ch10.xhtml#ref10_2)] 在其论文中强调了 `CSP` 管理加密密钥的两种技术。一种是 `Bring Your Own Key`（`BYOK`，自带密钥），另一种是 `Key Management Interoperability Protocol`（`KMIP`，密钥管理互操作性协议）。`BYOK` 最初由 `Amazon` 提供，允许企业将其自己的 `Key Management Infrastructure`（`KMI`，密钥管理基础设施）导入 `Amazon Web Services`（`AWS`）`Key Management Service`（`KMS`，密钥管理服务）。此功能使 `Service Providers`（服务提供商）能更好地控制密钥管理，并允许他们将 `Cloud Customer/User`（云客户/用户）密钥安全地保存在 `Hardware Module`（硬件模块）中。

`Amazon` 为此提出了 `AWS CloudHSM`，它在企业授权下的虚拟私有云上运行。`Hardware Module` 物理上位于 `Cloud`（云）数据中心，允许创建自己的主密钥，用于加密数据。因为它隐藏在 `Hardware Module` 中，没有人可以读取它，甚至连 `Cloud Hardware Module`（云硬件模块）提供商也无法读取。关于密钥类型和强度（`AES256` 对比 `AES-128` 或 `3DES`），以及密钥生成来源（`Hardware Module` 对比 `Software` 软件）的担忧，可以通过 `BYOK` 来解决。因此，`BYOK` 在部署 `Cloud Infrastructure`（云基础设施）的任何业务审计过程中都很有用。然而，当密钥被导入 `CSP KMS` 时，客户并不拥有对这些加密密钥的完全控制权和独占访问权 [[3](#ch10.xhtml#ref10_3)]。
