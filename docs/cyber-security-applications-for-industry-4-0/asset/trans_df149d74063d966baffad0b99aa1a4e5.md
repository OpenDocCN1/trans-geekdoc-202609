
开发者在敏捷环境中协作；所有利益相关者都参与开发过程。系统领域知识不足可能会影响需求获取过程并导致需求规范中的缺陷。开发人员和分析师通过访谈、工作坊或问卷来识别功能和特性。它们随后以简单且原子化的格式写在故事卡上，作为产品待办事项列表的一部分 \[[57](#ch2.xhtml#ref2_57),[58](#ch2.xhtml#ref2_58)\]。

用户故事对敏捷团队有益，因为它们促进协作并允许将新颖的创新想法纳入系统。它有助于分享关于系统用户、待执行任务以及预期目标的信息 \[[59](#ch2.xhtml#ref2_59),[60](#ch2.xhtml#ref2_60)\]。

### 2.4.2 看板
看板是一种源自制造业的框架。它已在许多行业中得到广泛应用，从工厂车间到软件开发项目。看板在敏捷开发团队中很受欢迎，但一些非敏捷团队也采用看板来优化工作流程。看板包含一个三步工作流程——待办、进行中和已完成。它利用卡片（或便利贴）和看板；待办事项写在卡片上并放置在板上。所有团队成员都可以访问看板并查看其他成员的任务。这种结构有助于限制在制品并防止任务过载。看板鼓励工作透明度并促进团队成员之间的更轻松协作。看板帮助团队识别工作流程中的瓶颈以改进产品开发流程 \[[53](#ch2.xhtml#ref2_53),[61](#ch2.xhtml#ref2_61)\]。看板的一些基本原则包括从当前任务开始，然后持续推进来自待办事项列表的新增量任务。看板鼓励透明度；各种角色、任务和开发阶段对所有人可见，促进协作和团队合作 \[[52](#ch2.xhtml#ref2_52)\]。

### 2.4.3 冲刺/迭代
冲刺或迭代是 Scrum 的特征。它表示用于处理任务的指定时间段，通常为 2–4 周。一些团队会调整时长，根据团队规模、经验和工作范围偏好 1–3 周。冲刺开始时是冲刺计划会议，团队在会上确定待办事项。冲刺结束时，预计团队将交付一个 MVP，即对用户有价值的潜在可交付产品。团队在冲刺结束时进行回顾，以反思开发过程并讨论下一阶段的改进。团队还为产品待办事项提供功能输入。冲刺会议有固定的开始和结束日期；所有后续冲刺会议的时长保持不变。冲刺期间未完成的任务会被添加到待办事项列表中，并在下一冲刺中考虑；不会延长冲刺时长以完成待处理任务 \[[54](#ch2.xhtml#ref2_54),[62](#ch2.xhtml#ref2_62),[63](#ch2.xhtml#ref2_63)\]。

### 2.4.4 每日站会
每日站会会议是冲刺或迭代会议的特征。每日站会是敏捷团队每天举行的约 15 分钟的限时会议。成员站立开会以保持简洁扼要。团队成员谈论自上次会议以来完成的工作，说明在执行任务时遇到的任何障碍或挑战，并告知其他成员当天计划开展的工作。涉及大量透明度；团队成员了解进展程度并有机会提供输入以帮助团队进展。团队使用每日站会来改进正在开发的产品和开发过程，确保检查其他成员的任务、同步角色并每日适应需求变化 \[[52](#ch2.xhtml#ref2_52),[54](#ch2.xhtml#ref2_54),[63](#ch2.xhtml#ref2_63)\]。

### 2.4.5 冲刺回顾与复盘
冲刺回顾在冲刺会议结束时进行，以反思开发过程并讨论下一阶段的改进方法。敏捷团队，包括利益相关者、开发人员、用户和客户，都参与回顾过程。团队为产品待办事项提供功能输入。冲刺的最后一个活动是复盘。在复盘期间，团队讨论做得好的地方并确定可以改进的地方。他们还讨论对改进下一冲刺会议的承诺。Scrum 主持人主持这些会议。主要重点是检查和调整产品和开发过程 \[[54](#ch2.xhtml#ref2_54),[63](#ch2.xhtml#ref2_63)\]。

## 2.5 工业 4.0 中的敏捷实践
工业 4.0 九大支柱的技术力求满足客户不断变化的需求；通过实施敏捷开发方法 \[[4](#ch2.xhtml#ref2_4)\]。Cyber-physical systems 通常具有敏捷性，并需要不断演进的生产需求以持续改进系统。工业 4.0 整合了多个利益相关者，以开发满足其需求的多维解决方案 \[[64](#ch2.xhtml#ref2_64)\]。生产组织通常专注于为客户进行间歇性的产品发布和升级。情况已随着更多迭代生产而演变，生产不断融入不断变化的客户需求 \[[48](#ch2.xhtml#ref2_48)\]。协作和沟通对于满足客户需求以改善体验至关重要。客户从开发过程开始到所有阶段的参与对于产品的成功至关重要。客户可以提供有价值的输入并提供实时反馈以整合到生产中 \[[43](#ch2.xhtml#ref2_43)\]。应用适当的方法来获取客户和用户需求是需要考虑的重要方面，以确保有效的产品开发过程 \[[65](#ch2.xhtml#ref2_65)\]。

在工业 4.0 应用的开发过程中，已确定了一些需要遵循的步骤 \[[66](#ch2.xhtml#ref2_66)\]。应用预计满足组织目标和目的。需求被获取和收集以开始开发；所有相关利益相关者应共享共同利益并对需求和目标保持清晰，没有任何歧义。这种清晰度有助于保持透明并让所有人参与开发过程。它还有助于从一开始就克服任何潜在障碍，这是在处理可能冲突的优秀措施。存在共同责任；然而，团队成员应了解各自在完成任务中的角色。利益相关者应认识到他们为实现满足客户需求的最终目标而带来的努力、技能和经验。
