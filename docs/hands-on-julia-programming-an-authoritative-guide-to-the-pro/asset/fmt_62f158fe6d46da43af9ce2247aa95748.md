
```
RectangleA(a=1.0)=RectangleA(a, a)

julia> RectangleA()
RectangleA(1.0f0, 1.0f0)
julia> RectangleA(2.0)
RectangleA(2.0f0, 2.0f0)
julia> methods(RectangleA)
# 3 methods for type constructor:
[1] RectangleA() in Main at REPL[7]:1
[2] RectangleA(w::Real, h::Real) in Main at REPL[1]:4
[3] RectangleA(a) in Main at REPL[7]:1
```

We created the two constructors with one statement as the other one was created due to the default argument. You can see now 3 constructors are created. Two of them are outer constructors, declared outside of the type definition. One inner constructor declared within the type definition. The internal constructors are created for ensuring construction constraints are enforced. The external constructors are used mostly for convenience and providing construction flexibility. When no constructors are provided then a default constructor is provided that initializes the attributes of the type. In the preceding `RectangleA` example, the following default inner constructor will be created when no other inner constructor is defined:

```
RectangleA(h::Float32, w::Float32)=new(h, w)
```

The function `new` is a special function that can be used only inside the inner constructor. It creates the object while initializing the parameters in the order in which they are defined.

## Constructor Requirements

The constructor must return a well-initialized object. In Julia, the objects are expected to be initialized properly at the end of a call to the constructor. While there are cases where compound objects may not be initialized due to performance reasons they are more of exceptions than the rule. The constructor must return an object of the type it is trying to construct.

## Parametric Types and Constructors

In [previous section], when we discussed the parametric data types, we did not elaborate on their impact on function and dispatch interfaces or on the constructors. In the following `RectangleB` type we create, we will like to use any of the Real types as parametric types for the Rectangle attributes.

```
struct RectangleB{T <: Real}
    w::T
    h::T
end
```

```
julia> RectangleB(2//3, 1//4)
RectangleB{Rational{Int64}}(2//3, 1//4)
```

```
julia> RectangleB(1f0, 2f0)
RectangleB{Float32}(1.0f0, 2.0f0)
```

```
julia> RectangleB(2//3, 1f0)
ERROR: MethodError: no method matching RectangleB(::Rational{Int64}, ::Float32)
Closest candidates are:
  RectangleB(::T, ::T) where T<:Real at REPL[6]:2
```

The default constructor `RectangleB(::T, ::T)` where `T<:Real` is created but `T` can be only one specific type. It cannot be of `Rational{Int64}` and `Float32` the same time.

```
julia> RectangleB{Int}('a', 1f0)
RectangleB{Int64}(97, 1)
```

However, when we specify the parameter type as part of the constructor explicitly, types are converted to the proper ones.

## Methods for RectangleB

Let us create two methods called `aspect_ratio` and `area`. Aspect ratio is the ratio of the width to height in a rectangle. Area is multiplication of height with width in case of a rectangle. We have seen an implementation of the area method in an earlier example.

```
area(r::RectangleB)=r.w*r.h
```

```
aspect_ratio(r::RectangleB)=r.w/r.h
```

```
r, r1, r2 = RectangleB(1//2, 2//3), RectangleB(1.5, 0.5), RectangleB(1, 2)
```

```
julia> area(r), area(r1), area(r2)
(1//3, 0.75, 2)
```

```
julia> aspect_ratio(r), aspect_ratio(r1), aspect_ratio(r2)
(3//4, 3.0, 0.5)
```

While `area` function returned values as `Rational{Int}` and `Int` depending on the parametric type of Rectangle the same seems to have been ignored in the function `aspect_ratio`. The operator (`/`) is explicitly a floating-point division operator. The rational or division operator in Julia is (`//`). Let us introduce two additional methods for `aspect_ratio` specifically for the integer and rational types.

```
aspect_ratio(r::RectangleB{T}) where T<:Union{Integer, Rational} = r.w//r.h

julia> aspect_ratio(r), aspect_ratio(r1), aspect_ratio(r2)
(3//4, 3.0, 1//2)
```

Clearly, the method for `Rational` and `Integer` types get dispatched to the new method while the rest of the numeric types like the Float64 get dispatched to the older method. `T<:Union{Integer, Rational}` essentially means the type can be derived from either an Integer type or can be of a Rational type. Union is used extensively in Julia to represent where the types are of one of the types. One could instead use 3 methods instead of using a Union like the following examples as well.

```
aspect_ratio(r::RectangleB{T}) where T<:Integer = r.w//r.h
```

```
aspect_ratio(r::RectangleB{T}) where T<:Rational = r.w//r.h
```

It is important to understand the dispatch rules from the perspective of how the subtype relationship flows down into the parametric types.

```
julia> RectangleB{Rational{Int}} <: RectangleB{Rational}
false
julia> RectangleB{Rational{Int}} <: RectangleB
true
julia> RectangleB{Rational} <: RectangleB
true
```

The subtype relationship is only relevant up to the immediate parametric type. `RectangleB{Rational{Int}}` is not a subtype of `RectangleB{Rational}` while it is a subtype of `RectangleB`.

## Type Promotion Examples

Let us look at the some of the examples as follows:

```
julia> 1f0+2
3.0f0
julia> 1f0+2.0
3.0
```

We added a `Float32` to an `Int` and the result returned was a `Float32`. Similarly, we added `Float32` to `Float64` and got a `Float64` as a result. All these seemed very natural. It seemed `Int` got promoted to a `Float32` and then the addition was performed. Unlike other programming languages, the type promotions in Julia are not implicit. Any conversions of types need to be carried out explicitly. Julia core library internally has many such rules defined which are called explicitly so that we see these seamless transitions.

## Type Conversion

The typical method of initializing any value is by a constructor. For example, you can convert an integral floating-point value like 1.0 to `Int` by specifying `Int(1.0)`. But, `Int(1.5)` will throw an `InexactError`. In most cases, this is to be carried out by an explicit call by the programmer. But, sometimes the conversion is to be carried out by an implicit call. In such a case a `convert(T, x)` is called.

```
julia> function f()
           i::Int = 0
           i = 1.5
           return i
       end
f (generic function with 1 method)
```
