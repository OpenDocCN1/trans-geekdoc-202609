## 背景

*优化的第一原则是不要*[^1]。这一建议由 Unix 操作系统大师 *Kernighan* 和 *Pike* 在其开创性著作 *The Practice of Programming* 中提出。二十多年来，情况并没有太大变化。一个正确运行的程序远胜过一个运行快但不正确的程序。然而，为确保程序表现出可接受的性能，往往会采取许多变通方法。不存在绝对的性能，也不存在针对所有条件都优化的代码。按今天标准的高性能代码，其计算能力可能远不如未来一个相对简单的应用程序。旅行者号是离开太阳系的第一个人造物体，其计算能力远不如现代手机[^2]。人们并不真的需要手动优化每一行代码。在大多数情况下，许多最优代码生成器和编译器编译出的代码远优于手动优化的代码。像 Julia 这样的现代语言利用 `LLVM` 来处理跨平台最优代码生成，并在编译或代码生成期间解决许多已知的优化问题。人们可能会问，既然硬件便宜且易于获取，为什么还要费心去优化代码？答案在于：无论硬件变得多么便宜，你都需要从中榨取那额外的一丁点性能。

在单个处理器的单个线程上运行多个应用程序并非真正的同时多任务处理。操作系统根据调度抢占任务，让处理器一次只执行一个任务。用户会感觉所有任务都在同时运行，而实际上它们只是在很短的时间间隔内执行，然后切换到下一个任务。在基于**图形用户界面 (GUI)** 的应用程序中，用户界面对用户输入的响应速度被赋予了比其他后台任务完成执行更高的优先级。对于在单处理器系统上运行长时间计算密集型任务的多任务应用程序，惯例做法是间歇性地处理 UI 事件以保持 UI 响应。这在 Windows 系统中被称为**空闲循环处理**[^3]。这里最优响应时间优先于原始执行速度。因此，代码的纯执行速度可能并非所有代码优化项目的目标。

当处理器指令集中没有三角函数时，三角函数的计算会非常耗时，因为它们必须通过软件模拟来计算。像游戏程序这样的性能敏感型应用程序会使用以下数学方程来模拟其行为。

![三角函数近似](n4upl4fndqh.jpeg)

它们基本上会保留 `sinθ` 和 `cosθ` 在 15 度或 30 度间隔处的查找值，并使用前面给出的增量方程计算中间值。使用前面的方程按 15 度间隔生成的表格仍处于显著精度范围内。

```julia
julia> n = 6;
δ = pi/180*(90/n);
sinδ, cosδ = δ, (1 - δ*δ/2);

m = Matrix{Float64}(undef, (n+1, 2));
m[1, 1], m[1, 2] = 0.0, 1.0;

for i = 1:n
    m[i+1, 1] = m[i, 1]*cosδ + m[i, 2]*sinδ
    m[i+1, 2] = m[i, 2]*cosδ - m[i, 1]*sinδ
end

julia> m
7×2 Array{Float64,2}:
 0.0        1.0
 0.261799   0.965731
 0.505655   0.864097
 0.714547   0.702104
 0.87387    0.490976
 0.97246    0.245371
 1.00337   -0.0176268

julia> m1 = [[sin(i*δ) for i=0:n] [cos(i*δ) for i=0:n]]
7×2 Array{Float64,2}:
 0.0        1.0
 0.258819   0.965926
 0.5        0.866025
 0.707107   0.707107
 0.866025   0.5
 0.965926   0.258819
 1.0        6.12323e-17

julia> using Statistics
julia> mean(m1-m), std(m1-m)
(0.0009570353971457324, 0.00784842483267987)
```

这种粗略的估算可以在保持计算足够快的同时产生合理准确的计算结果。随着拥有内置三角函数指令的现代 CPU 的出现，这些权衡可能不再需要。然而，性能与精度的权衡在优化中很常见，这正是一个例证。而且，它们大多是特定领域的。

## 云计算与资源管理

云计算资源可根据需求添加到项目或问题中。然而，资源成本正给项目增加显著成本。增加更多硬件或处理能力可以解决大得多的问题。但它们也增加了总体成本。例如，如今的智能手机能够处理设备端语音识别以及涉及深度学习和神经计算的许多计算复杂任务。十年前，即使是先进的台式机也无法做到这一点。如今智能手机的硬件比十年前的台式机更先进。因此，增加更多资源来解决复杂问题从来都不是解决方案。最优利用资源以减少成本超支是一种必要。因此，性能管理将永远是每个软件系统的需求。
