上述表示称为 **UTF-8**。那超过 21 位的编码呢？到目前为止，Unicode 规范并未使用超过 21 位的信息，但该方案最多可容纳 36 位的信息，覆盖整个 UCS-4 范围。与 UTF-8 类似，UTF-16 也被引入，它考虑将字符代码一次扩展为 2 字节字符。还有 UTF-32 转换方案。

随着计算机的普及，很明显计算不再能局限于特定区域。其次，数据交换也要求数据能在任何可用的计算系统中呈现。第三，表示文本所需的内存可以超过一个字节，因为计算机中的存储和内存都变得更便宜了。不再需要对字符进行单字节限制。来自各种组织和学术界的计算机科学家和语言学家在 Unicode Consortium（Unicode 联盟）的旗下聚集在一起，推出了 **通用编码字符集**（**UCS**）。1991 年推出的第一组字符包含约 7000 个字符，采用称为 UCS-2 的 2 字节字符表示。然而，随着更多语言被添加到规范中，字符数量很快开始增长。于是决定在称为 UCS-4 的表示中为每个字符采用 4 个字节。实际上，Unicode 规范定义了 16 个代码平面，每个平面大小为 65536 (2^16)，但实际上只使用了少数值。从技术上讲，32 位中只有 20 位真正用于实际目的。然而，许多计算机系统继续在操作系统中实现宽字符，Windows 通过 Windows NT 开发了原生 16 位操作系统，并停止了旧的 Windows 95 代码库。在 90 年代末和千禧年初，代码需要通过使用宏分别为 8 位和 16 位版本进行编译。
