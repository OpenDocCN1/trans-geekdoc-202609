
`nzval` is the storage vector for all the non-zero values and `nzind` is the index location of the values where `n` is the length of the sparse vector.

```julia
using SparseArrays
I = [1, 4, 3, 5]; V = [1, 2, -5, 3];
R = sparsevec(I,V)
```

```text
5-element SparseVector{Int64,Int64} with 4 stored entries:
  [1]  =  1
  [3]  =  -5
  [4]  =  2
  [5]  =  3
```

A 5-element vector is created as the maximum value of the index was 5 in the `I` vector. Members of vector `R` can be accessed like a normal vector.

```julia
R[2]
```

```text
0
```

`findnz` method provides all index locations where non-zero values are stored. Essentially, given a sparse vector or matrix it reports the `nzind` and `nzval` vectors.

```julia
findnz(R)
```

```text
([1, 3, 4, 5], [1, -5, 2, 3])
```

# Sparse Matrix Storage (CSC Format)

Taking the concept of the sparse vector a step further, one can store a matrix adding a vector for the second dimension. However, for better storage management the following approach is typically used.

1.  Column indices are stored in a vector in an increasing order.
2.  Rows are stored in a second vector, and in increasing order when there is a clash in the column indices.
3.  Values are stored in a separate vector defined for the same.

This concept is called **compressed sparse column** (`CSC`). While the format is highly storage efficient, it is not insertion or modification friendly as any insertion may need all the values in the vectors to be shifted to the right.

```julia
struct SparseMatrixCSC{Tv,Ti<:Integer} <: AbstractSparseMatrix{Tv,Ti}
    m::Int                  # Number of rows
    n::Int                  # Number of columns
    colptr::Vector{Ti}      # Column j is in
                            # colptr[j]:(colptr[j+1]-1)
    rowval::Vector{Ti}      # Row indices of stored values
    nzval::Vector{Tv}       # Stored values, typically nonzeros
end
```

```julia
I = [1, 4, 3, 5]; J = [4, 7, 18, 9]; V = [1, 2, -5, 3];
S = sparse(I, J, V)
```

```text
5×18 SparseMatrixCSC{Int64, Int64} with 4 stored entries:
⠀⠈⠀⡀⠀⠀⠀⠀⠠
⠀⠀⠀⠀⠁⠀⠀⠀⠀
```

```julia
findnz(S)
```

```text
([1, 4, 5, 3], [4, 7, 9, 18], [1, 2, 3, -5])
```

```julia
S[1, 2]
```

```text
0
```

```julia
size(S)
```

```text
(5, 18)
```

Just like the sparse vector examples, `SparseMatrixCSC` has similar functions to create, access, and manipulate the matrices. We will leave the details of using these data structures to the reader and suggest an understanding of the language documentation for the same in the interest of space and complexities they can add.

# Performance Considerations

While sparse data structures are good for storage, they may not be the best for indexing and iterations. Be very cautious of data access complexities while using these structures. Even simple index access may need to scan a good portion of the index and data vectors. While incremental access of non-zero values for iterations may be efficient, random access for a specific index may not be as efficient.
