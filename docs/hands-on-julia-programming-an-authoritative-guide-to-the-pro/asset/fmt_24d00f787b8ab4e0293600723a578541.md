
# Iteration Framework and Custom Iterators in Julia

We saw a few examples of sequences and collections being iterated over using the `for` loop. This is practically possible because all such types implement the iteration framework. If you were to write a custom iterator, you may need to implement this framework. While some basic ideas are highlighted here, you are suggested to read the Julia documentation[3](#xjo4a1bi.html#n4upl4fndno) for the relevant details.

```
julia> v = collect(3:2:10)
4-element Vector{Int64}:
 3
 5
 7
 9
julia> for i=v
           println(i)
       end
3
5
7
9
```

The same can be written in the following form:

```
julia> next = iterate(v)
(3, 2)
julia> while next !== nothing
           value, state = next
           println(value)
           next = iterate(v, state)
       end
3
5
7
9
```

## Core Iteration Methods

`iterate(collection)` returns the first item and initial state or `nothing` if no values exist.

In the return value `(3, 2)` in the preceding example, `3` is the value of the first element and `2` is an internal parameter representing the state. Although it may seem like the index of the next value, one should not assume the same as those are completely implementation specific.

`iterate(collection, state)` returns the next item and next state or `nothing` if no additional items exist.

`iterate` methods must be implemented by all iterator types.

## Optional Iterator Methods

These are methods that need to be optionally defined by the iterator authors.

`IteratorSize(IterType)` is a helper method that says if the iterator has a length or a shape. Based on which `size` or/and `length` methods must be defined for the collection iterator.

```
julia> Base.IteratorSize(Vector{Int})
Base.HasShape{1}()
```

`IteratorEltype(IterType)` is a helper method that decides if the iterator has a specific element type.

```
julia> Base.IteratorEltype(Vector{Int})
Base.HasEltype()
```

`eltype(IterType)` returns the type of the first parameter of the `iterate` method.

```
julia> eltype(Vector{Int})
Int64
```

A detailed explanation of the methods can be seen from Julia’s documentation.

## Example: Custom `Squares` Iterator

We create a `Squares` type that will provide a sequence of squares of numbers up to the value stored in the type.

```
struct Squares
    value::Int
end
```

```
Base.iterate(s::Squares) = s.value <= 0 ? nothing : (1, 2)

Base.iterate(s::Squares, state) = s.value < state ? nothing :
                                   (state*state, state+1)

julia> for i=Squares(3)
           println(i)
       end
1
4
9
```

While the preceding one works for simple `for` loop. Trying to create an array with `collect` the method will not work.

```
julia> collect(Squares(3))
ERROR: MethodError: no method matching length(::Squares)
…
```

So we add a `length` method to achieve the same.

```
julia> Base.length(s::Squares)=s.value
julia> collect(Squares(3))
3-element Vector{Any}:
 1
 4
 9
```

While an `Array` is populated properly the type is of `Any`. Defining the `eltype(IteratorType)` method will ensure the proper type of `Array` is created.

```
Base.eltype(::Type{Squares})=Int

julia> eltype(Squares)
Int64

julia> collect(Squares(3))
3-element Vector{Int64}:
 1
 4
 9
```

**Note:** `Type{Squares}` is a special type whose only instance object is `Squares`. This is needed as `eltype` is a function of the type itself and not an instance of the type.

## Comprehensions and Generators

In Julia, arrays and collections are used extensively in scientific computations. It is rather imperative that the language provides easy access to creation and manipulation of arrays. Comprehension representations provide the ease of creating such arrays.

```
julia> [i*i for i=1:3]
3-element Vector{Int64}:
 1
 4
 9
julia> [i*j for i=1:3, j=1:3]
3×3 Matrix{Int64}:
 1  2  3
 2  4  6
 3  6  9
```

In the preceding examples, comprehensions are used to create a single dimension and multi-dimensional array. Following is an example where an index may depend on another.

```
julia> [i*j for i=1:3 for j=i:3]
6-element Vector{Int64}:
 1
 2
 3
 4
 6
 9
```

Comprehensions compute the complete arrays, it may also help to have a delayed execution iterator where the computation of the values happens when demanded than for all the elements. These are called **generators**.

```
julia> gen=(i*j for i=1:3 for j=i:3)
Base.Iterators.Flatten{Base.Generator{UnitRange{Int64},var"#6#7"}}(Base.Generator{UnitRange{Int64},var"#6#7"}(var"#6#7"(), 1:3))
julia> for v=gen
           println(v)
       end
1
2
3
4
6
9
```

## Summary

Collections provide a simple yet scalable interface for a class of algorithms and a unified iterator interface to access the elements. In this chapter, we reviewed a few simple data structures defined in the core Julia language. However, for a computation-centric language as Julia is, these are only the tip of the iceberg. You are requested to review the `DataStructures.jl` package to get more elaborate understanding of the data structures that are available for Julia. Similarly, if you are implementing custom data structures, you are advised to implement the iterator interface for your data structures to be compatible with the iteration framework of Julia language like `for`, `while` loops, and so on.
