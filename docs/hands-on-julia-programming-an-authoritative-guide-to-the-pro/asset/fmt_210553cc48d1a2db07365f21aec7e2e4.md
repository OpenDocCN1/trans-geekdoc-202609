# Test Framework Integration

No code is good enough unless it is thoroughly tested and the test cases are run frequently to detect regression on new code addition. Julia packages are expected to have unit test cases to address such needs. The test framework can be integrated with the following steps:

1.  Enter the folder `PointLib` with `cd("PointLib")`.

2.  Now edit the `Project.toml` to add the code in bold to add the Test package.

    ```toml
    name = "PointLib"
    uuid = "7de1f589-fb91-4994-b265-ccfc43c44ada"
    authors = ["Sambit Kumar Dash <sambitdash@gmail.com>"]
    version = "0.1.0"
    [deps]
    LinearAlgebra = "37e2e46d-f89d-539d-b4ee-838fcccc9c8e"
    [extras]
    Test = "8dfed614-e22c-5e08-85e1-65c5234f0b40"
    [targets]
    test = ["Test"]
    ```

3.  `test/runtests.jl` contains the test cases for the package. We add the following code to the file:

    ```julia
    using Test
    using PointLib

    @test iscollinear(Point2D(0, 0), Point2D(10, 0),
                      Point2D(20, 2ϵ()))
    @test !iscollinear(Point2D(0, 0), Point2D(10, 0),
                       Point2D(20, 3ϵ()))
    @test iscollinear(Point2D(10, 0), Point2D(10, 0),
                      Point2D(20, 3ϵ()))
    ```

4.  Now run the test using the command `]test` in the package mode.

The `@test` expr validates if expr is true. However, there are other commands like `@test_throws` that validate a specific exception being raised. A set of tests can be grouped under a test set and aggregated reporting on number of tests passed can be reported. While we used simple test case creation and saw how to trigger them with commands from the REPL, we will need to make sure they are integrated as part of an integrated continuous integration framework. That way whenever there is any push into the GitHub repository there is a continuous integration framework triggered. It ensures the code is built and test is run and results are reported.
