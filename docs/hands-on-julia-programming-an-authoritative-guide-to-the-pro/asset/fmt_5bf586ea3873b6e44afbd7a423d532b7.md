
A new variable `z` is created with the value of `1` and `x` with a value of `5` is picked up from the previous section. Hence, the `ex` expression evaluates to `7`.

## 复杂引用表达式

Let us look at some more complex quote expressions, where one `quote…end` is included inside another quote expression.

```
julia> e = :(1 + 1);
julia> eval(:e)
:(1 + 1)
julia> eval(e)
2
```

In the preceding example, `eval` of the symbol `:e`, evaluates to the contents of the variable `e`. However, the `eval` on the variable `e` actually evaluates the expression, and hence the difference.

We will relook at a similar concept in nested quotes.

```
julia> e = :(1+2)
julia> ex = quote
           quote
           $e
           end
           end
quote
#= In[32]:3 =#
$(Expr(:quote, quote
#= In[32]:4 =#
$(Expr(:$, :e))
end))
end
julia> eval(ex)
quote
#= In[32]:4 =#
1 + 2
end
```

In the preceding example, `$e` is bound to the inner quote and is equivalent to `eval(:e)`. Hence, the expression `1+2` appears in between `quote…end`.

```
julia> ex = quote
           quote
             $$e
           end
           end
quote
#= In[34]:2 =#
$(Expr(:quote, quote
#= In[34]:3 =#
$(Expr(:$, :(1 + 2)))
end))
end
julia> eval(ex)
quote
#= In[34]:3 =#
3
end
```

When `$$e` is used instead of `$e`, `eval(eval(:e))` is computed and thus the computed value 3 is placed between `quote…end`.

## 从输入参数生成表达式的函数

The following function can generate and return an interned expression from input parameters.

```
Julia> function math_exp(op, p1, p2)
           p1f, p2f = map(x-> x isa Number ? 2x :
                          error("Parameters have to be numbers"),
                          (p1, p2))
           return Expr(:call, op, p1f, p2f)
       end
julia> ex = math_exp(:+, 2, 3)
:(4 + 6)
julia> eval(ex)
10
```

The function returns a Julia expression. However, you will need an additional `eval` call to compute the values.

## 宏与函数的区别

Functions can return an expression but one has to explicitly call `eval` to evaluate the expression. Macros return expressions that are automatically evaluated as shown:

```
julia> macro sayhello()
           return :(println("Hello, World!!!"))
       end
@sayhello (macro with 1 method)
julia> @sayhello()
Hello, World!!!

julia> macro sayhello(name)
           return :(println("Hello, ", $name, "!!!"))
       end
@sayhello (macro with 2 methods)
julia> @sayhello("John")
Hello, John!!!
```

## 宏的调用形式

Macros can be called in any of the following forms:

```
@mymacro(param1, param2, …, paramN) or
@mymacro param1 param2 … paramN
```

Thus, the two `@sayhello` macros can be invoked as follows:

```
julia> @sayhello
Hello, World!!!
julia> @sayhello "John"
Hello, John!!!
```

Let us add a more complex expression.

```
julia> @sayhello begin
           1 + 3
       end
Hello, 4!!!
```

Just like methods follow multiple dispatch architecture, the same is applicable to the macros as well. Introducing a new macro `@sayhello(x::Int)` can affect the behavior in the following ways:

```
julia> macro sayhello(x::Int)
           println("Calling Int ", x)
           return :(println("Hello Int, ", $x))
       end
@sayhello (macro with 3 methods)
julia> @sayhello 21
Calling Int 21
Hello Int, 21
julia> x = 21;
julia> @sayhello x
Hello, 21!!!
```

When an `Int` literal is used as a parameter, the macro specifically `@sayhello(::Int)` is called. However, when the variable `x` is used as a parameter the `@sayhello(x)` is called. Macros take AST objects as input parameters. Hence, the call `@sayhello x` will be interpreted as `sayhello` being called with Symbol `x` as a parameter and not `21` as a parameter. The following example will clarify the statement further:

```
julia> macro intype(x)
           println(typeof(x))
       end
@intype (macro with 1 method)
julia> @intype begin
           x = 5
       end
Expr
julia> @intype x
Symbol
julia> @intype 21
Int64
julia> @intype "John"
String
```

## 字符串宏

These are essentially convenience macros used in place of constructors. We have already seen examples of these macros in the context of regular expressions in the chapter on Strings. The regular expression macro as defined Julia is shown as follows:

```
macro r_str(p)
    Regex(p)
end
```

One can invoke a regular expression match expression as shown.

```
julia> m = match(r"a.a", "abracadabra")
RegexMatch("aca")
```

Expression `r"…"` is equivalent to calling the macro `@r_str()`. Let us create a custom expression for capitalized strings.

```
julia> struct CapsString
           s::String
           CapsString(s::String)=new(uppercase(s))
       end
julia> macro C_str(s)
           CapsString(s)
       end
julia> C"This is upper case string"
CapsString("THIS IS UPPER CASE STRING")
```

## 生成函数

Functions and methods are invoked in Julia using the multiple dispatch architecture. However, sometimes one may desire to create more complex dispatch models than the language supports and build their own. The generated functions help in these scenarios. Let us consider a simple dispatch scenario.

```
julia> f(x::Integer) = x^2;
julia> f(x) = x;
julia> f(4)
16
julia> f("John")
"John"
```
