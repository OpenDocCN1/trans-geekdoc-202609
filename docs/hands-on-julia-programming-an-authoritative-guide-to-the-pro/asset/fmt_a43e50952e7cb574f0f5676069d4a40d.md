## 1. Use Functions

It is very easy for a REPL-based language to be mistaken as a scripting language. The dynamically typed, with all code written in a global scope (`Main` module), gives the language a flavor of a scripting language. However, using proper functions makes the code maintainable; moreover as functions can be written in a type-safe manner, they can be optimized better.

## 2. Code must be generalized and not type specific

This concept can be explained easily with the following code:

```
julia> addone(x) = x + one(x);
julia> addone(5), addone(5.0), addone(5f0)
(6, 6.0, 6.0f0)
```

Julia has many methods like `one()` and `zero()` that use the type of the operand and judiciously provide values that do not require explicit type promotion in calculations. The same principle can be applied to your code making it easily extensible.

## 3. Keep the function scope narrow if that is the intent

Where a function argument expects a specific type, the type must be specified. This ensures a run time error does not propagate further and no additional assertion is needed.

```
calc1() = 2, 1
calc2() = 1.1, 1.2
myvalidate(x::Int, y::Int) = x == y
julia> myvalidate(calc1()…)
false
julia> myvalidate(calc2()…)
MethodError: no method matching myvalidate(::Float64, ::Float64)
```

While `calc1()` is the proper kind of computation, `calc2()` is definitely erroneous, and `myvalidate()` ensures the error is localized. Second, any explicit type conversion if needed must be carried out by the caller and not the callee.

```
function myvalidate2(x, y)
    xi, yi = Int(x), Int(y)
    return xi == yi
end
julia> myvalidate2(2, 3.0) # Not good style
false
julia> myvalidate(2, Int(3.0)) # Better style
false
```

## 4. Append exclamation mark (!) to function that change parameters

Where parameter values are modified the function name should have a clear indicator of an exclamation mark. The same will be further clarified in subsequent sections.

```
function double!(v::Vector)
    for i=firstindex(v):lastindex(v)
        v[i] *= 2
    end
    return v
end
julia> double!([1,2,3])
3-element Array{Int64,1}:
2
4
6
```

## 5. Avoid complex data types

Data types particularly used in conjunction with collections must be kept simpler. `Vector{Union{Int, Float, Function, MyType}}` should better be specified as `Vector{Any}`. It may be more efficient for the compiler to have simpler types. Similarly, `Union{Function, AbstractString}` can suggest possible improper design choice in the code.

## 6. Naming conventions

Julia coders are used to certain naming conventions. Here are some:

*   Types start with capital letters and can be in Camel case: `MyType`, `AbstractArray{T}`, and so on.
*   Module names follow the same convention as regular types.
*   Functions must be in all lower case.
    *   Simple predicates with merged words: `beginswith`, `isequal`, `haskey`, etc.
