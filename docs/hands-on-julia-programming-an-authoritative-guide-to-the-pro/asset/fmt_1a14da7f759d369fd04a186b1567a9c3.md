
As we worked with strings and encodings, we realized some functions provide properties of individual characters. Thus, it is important for us to convert a `String` into an array of characters. We shall look into that in the next section.

## Converting Strings to Character Arrays

`String` objects are collections of characters as we have seen earlier. But, they cannot be modified. You do not get to operate on them as flexibly as you will like to as an array or other container types. However, there are a lot of functions you can use to transform the `String` objects and create alternate `String` objects. However, if required you can convert a String to a Char Array by simply using the `collect` method.

```julia
julia> collect("∀ x ∃ y")
7-element Array{Char,1}:
 '∀': Unicode U+2200 (category Sm: Symbol, math)
 ' ': ASCII/Unicode U+0020 (category Zs: Separator, space)
 'x': ASCII/Unicode U+0078 (category Ll: Letter, lowercase)
 ' ': ASCII/Unicode U+0020 (category Zs: Separator, space)
 '∃': Unicode U+2203 (category Sm: Symbol, math)
 ' ': ASCII/Unicode U+0020 (category Zs: Separator, space)
 'y': ASCII/Unicode U+0079 (category Ll: Letter, lowercase)
```

You can also use the `transcode` method to obtain UTF-8, 16, 32 transformation vectors of a `String` object as shown previously. Once you have an array of `Char`, you could use it in any way desired with array operations.

## AbstractString and AbstractChar Architecture

Rome was not built in a day; nor was the Julia String API. While `String` remains a UTF-8 representation wrapped inside a collection that delivers `Char` objects as `eltype`.

```julia
julia> eltype("abcd")
Char
```

This architecture was extended further to define an abstract `AbstractString` type that would consider `AbstractChar` as an element type. Julia in the pre-1.0 incarnations had many such implementations like `ASCIIString`, `UTF8String`, and so on., which essentially were providing the basis of some of the encoding schemes that are commonly used[3](#5ozsl153.html#n4upl4fndkz). Many classic string types are functionally merged into the `String` type and some are moved into an optional package called `LegacyStrings.jl`. While there are no significant benefits of using that package, they can be a good source of reference for people interested to try out and implement their own string types. If you are interested in implementing your own string types make sure you have `AbstractString` and `AbstractChar` interfaces implemented. There are not many requirements for the abstract types save they expect you to have the easier conversion to and from `String` and `Char` objects respectively if needed.

## Implementing Custom Character Types

This interface essentially demands that any derived character should have a Unicode representation value. Similarly, given a valid Unicode value one must be able to create a character.

```julia
struct MyChar <: AbstractChar end

MyChar(::UInt32)    # returns the MyChar with valid codepoint
codepoint(::MyChar) # returns the Unicode value in UInt32
```

The constructor must throw an error if the `codepoint` input value is not within the encoding range.

## AbstractString Interface Requirements

`AbstractString` interface is far more elaborate and makes certain assumptions on the internal composition of the string object as well. For example, these interfaces define assumptions on how many minimum bytes you will need to define a character in the string. If you use the `LegacyStrings` you will realize `ASCIIString` utilizes a `codeunit` of a `UInt8` while `UTF16String` utilizes a `codeunit` of `UInt16`. But both have a same size of internal data length in the code units.

```julia
julia> ]add LegacyStrings;

julia> using LegacyStrings;
julia> s = ASCIIString("abcd");

julia> codeunit(s)
UInt8

julia> ncodeunits(s)
4

julia> s16 = UTF16String(transcode(UInt16, "abcd\0")); # NULL termination
julia> codeunit(s16)
UInt16

julia> ncodeunits(s16)
4

julia> eltype(s), eltype(s16)
(Char, Char)
```

> **Note:** The `add` and `using` commands are used in the context of package management and module usage in Julia. We will discuss about them in details when we discuss about package management.

Although, the `ASCIIString` and `UTF16String` in the preceding example have completely different internal representations of the stored internal data, they utilize `Char` as the iterated `eltype`. No additional character types are defined for both these data types.

Other than the aforementioned methods, the derived types of `AbstractString` need to implement all the iteration and indexing methods like `iterate`, `getindex`, `nextind`, `prevind`, `lastindex`, `firstindex` and some collections-related methods like length as well[4](#5ozsl153.html#n4upl4fndk0).
