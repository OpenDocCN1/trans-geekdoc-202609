

# Julia 生态系统与社区

任何不可扩展的平台在当今世界都是不完整的。Julia 深谙这一需求，提供了完整的包开发和管理生态系统。你可以使用 `JuliaHub`[^1] 搜索所需的包并将其部署到你的环境中。目前约有 4500+ 个包，与 `Python`、`R`、`MATLAB` 等其他平台相比，这个数量相当有限。然而，对于一门在 2018 年 10 月才达到稳定接口 **版本 1.0** 的语言来说，这个数字显示了持续增强平台生态系统的兴趣。虽然某些功能可能在 Julia 中不存在，但考虑等效的 C/C++ 或 Java 二进制文件，并使用原生接口将它们与你的 Julia 代码集成并不难。Julia 包基础设施基于 `git`，这使得人们开发自己的私有仓库变得非常容易。此外，完整的包和环境管理系统 `Pkg` 提供了独立的环境，从而保持了包之间的兼容性。

## 云原生应用开发

当你开始使用 Julia 时，你会意识到该系统非常适合基于云的应用程序开发。Julia 将在后端系统中用于计算层，而将渲染和连接管理接口留给定义良好的应用程序和 Web 服务器。虽然一些基于 Web 的应用程序服务器是用 Julia 开发的，但它们大多处于实验阶段。大多数用 Julia 编写的代码都以源代码形式保存，适合 JIT 编译。因此，静态编译代码不是 Julia 中最常见的部署实践，尽管通过某些包[^2] 可以实现这种灵活性。作为一个基于服务器的平台，Julia 及其包集合可以轻松部署在 AWS、Azure 等云平台上，或作为 `Docker` 包交付。

## 开源许可与企业支持

Julia 是作为一系列开源项目开发的。我们坚持使用“开源项目集合”这一术语，因为大多数使用的包作为开源分发，但其许可证可能与 Julia 语言不同。Julia 语言是在 **MIT 许可证**[^3] 下开发的，这在使用和扩展源代码方面提供了显著的灵活性。这也使得任何人都可以轻松地将完整的 Julia 或其衍生版本作为他们正在开发的其他应用程序的一部分。大多数用 Julia 开发的包也遵循类似的许可方案。请务必在将包[^4] 用于商业许可产品之前查看其许可灵活性。

正如许可证一样，Julia 在架构上也是为联邦企业环境设计的。人们可以使用自己的私有仓库来管理应用程序和包，部署在以企业为中心的内部云基础设施上，并使用包来集成企业联邦身份验证和授权方案。Julia 语言还维护所有主要版本（如 1.0）作为 **长期支持** (**LTS**) 版本，以满足企业支持需求[^5]。最重要的是，Julia 得到 `Julia Computing Inc.`[^6] 的支持，这是一家提供工具、支持 Julia 并积极参与 Julia 编程社区活动的企业。对 Julia Computing 工具感兴趣的企业将能够从他们那里获得各种支持计划。Julia 语言的所有创始成员目前都在 Julia Computing 任职。

## 社区与贡献

任何开源软件只要社区持续感兴趣就是好的。Julia 最初仅由三位研究人员及其导师发起，随后团队不断壮大，吸引了许多学术机构和研究人员的积极参与。语言的主仓库拥有约一千名贡献者、30,000+ 星标[^7] 和 4200+ 复刻[^8]。除了主语言仓库外，许多开发者还为 Julia 包生态系统中可用的 4500+ 个包做出贡献。仓库维护在 GitHub 上。虽然大多数交流作为 GitHub 上拉取请求和问题跟踪的一部分进行，但特定项目组也通过 Discourse、Slack 和 GitHub Projects 进行交流。Julia 社区举办 `JuliaCon`[^9]，这是一个致力于 Julia 生态系统开发和推广的会议。还有许多聚会小组，社区在其中互动和交流想法。提供免费和付费课程以更好地了解生态系统[^10]。

在像 Julia 这样相对较新的编程语言上工作最重要的优势是，可以灵活地查看代码、理解实现、通过提出问题建议更改、提交 PR 并积极地为环境做贡献。对于有眼光的程序员来说，有能力并有兴趣在你希望带来改变的地方做出贡献，这绝对值得探索。对于学生来说，对 Julia 的贡献可以通过 `Google Summer of Code` 赞助[^11] 项目获得资助；从而满足他们的专业实习需求。如果你是一位喜欢深入一线的开发者，这里是一个你既可以工作又可以贡献的平台。而且，社区在鼓励甚至新手程序员的更改方面是最热情的之一。这也是快速学习和更好地理解系统的途径。

## 语言历史

Julia 大约在十年前构想出来，但在 2012 年作为一个开源项目崭露头角。由三位计算机科学家 `Jeff Bezanson`、`Stefan Karpinski` 和 `Viral B. Shah` 在 `MIT` 的 `Prof. Alan Edelman` 指导下发起，Julia 作为一个开源项目有着非常谦逊的开端。他们意识到的一个重大问题是：研究人员需要先开发原型，然后将代码产品化为较低级别的预编译语言，以获得编译语言的额外性能。Julia 试图打破原型与生产之间的这一障碍。Julia 的作者选择 Julia 这个名字是为了向 Julia 集合这一数学概念致敬。他们坚持在交流时使用“Julia 编程语言”或“Julia 语言”。当 Julia 用作专有名词时，必须使用中性形式。我们将在本书中遵守相同的惯例。

## 本书缘起

作者大约三年前开始使用该系统，寻找一门专门为数据科学项目设计的编程语言。当时 Julia 1.0 仍处于开发阶段，需要更深入的投入来理解该语言。令人惊讶的是，对于一门仅有几年历史的语言，已经有不少书籍出版。已经有质量不错的文档可用。然而，许多基于 1.0 版本之前写的书已不再相关，因为语言的接口已经改变。其次，没有一本书能提供经验丰富的专业人士所寻找的整个 Julia 生态系统的全面视野。本书旨在解决这两个需求。

本书由 3 个模块和 17 章组成。

本模块专注于理解 Julia 编程语言。
