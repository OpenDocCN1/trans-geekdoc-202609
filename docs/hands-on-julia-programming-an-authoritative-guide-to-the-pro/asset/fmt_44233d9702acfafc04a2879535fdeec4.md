
# Abstract Syntax Trees (ASTs)

Abstract Syntax Trees (ASTs) are a syntactical construct of a code expression in computer science. The structural form makes it easier to understand the code by a machine and eliminates operator precedence or the usage of brackets to modify the precedence. The AST of a code snippet in Julia is a valid object in Julia. Thus you have the flexibility to take a piece of code, generate the AST of it, and manipulate or act on the AST as a Julia object to create interesting derivative ASTs that can be executed. This is the foundation of Julia’s metaprogramming architecture. Simply put, you can generate any valid code string and execute it in the context of the program by effectively manipulating it. Let us see some of these in action in the following example:

```
julia> s = "1+1"
"1+2"
julia> ex = Meta.parse(s)
:(1 + 1)
julia> typeof(ex)
Expr
julia> dump(ex)
Expr
  head: Symbol call
  args: Array{Any}((3,))
    1: Symbol +
    2: Int64 1
    3: Int64 2
```

We took a valid string that can be a Julia expression. We parsed it with a Julia parser and the output is returned in an interned string format. The interned string format is of type `Expr`. The `dump` method provides the AST of the expression. The following can be discerned from the AST:

1.  `ex` is of type `Expr`.
2.  `ex.head` is a call symbol.
3.  `ex.args` have 3 elements.
4.  `args[1]` is Symbol `+` that will be invoked by call.
5.  `args[2]` and `[3]` are arguments to the function call.

Let us evaluate the expression and we should get `2`.

```
julia> eval(ex)
2
```

Let us modify the interned expression `ex` and change `ex.args[1]` from `+` to `-`.

```
julia> ex.args[1] = :(-);
julia> dump(ex)
Expr
  head: Symbol call
  args: Array{Any}((3,))
    1: Symbol -
    2: Int64 1
    3: Int64 1
julia> eval(ex)
0
```

A simple modification of the argument in the call sequence could change the function to be called for evaluation.

## Symbol Objects

`Symbol` objects are used as function names and terminals in the Julia AST. The character (`:`) preceding a token can be used to quickly define a `Symbol` as well. `Symbol` constructor is also available. It would concatenate all the arguments to form a symbol.

```
julia> Symbol("A")
:A

julia> Symbol("A", "_", 5, "32")
:A_532

julia> :A_532
:A_532

julia> :(==)
:(==)
```

When a symbol is defined using a colon, some alphabets may need disambiguation like the `==` operator in this case. You can use the colon character (`:`) to define an expression or interned string rather than use the `Expr` constructor or `Meta.parse` a string as we did in the previous section.

```
julia> ex = :(z = 1 + 2);
julia> typeof(ex)
Expr
```

The `Expr` generated here has two parts to the AST:

1.  Part one: an assignment to a variable.
2.  Part two: a call to the operator `+` whose result is the r-value of the assignment.

```
julia> dump(ex)
Expr
head: Symbol =
args: Array{Any}((2,))
1: Symbol z
2: Expr
head: Symbol call
args: Array{Any}((3,))
1: Symbol +
2: Int64 1
3: Int64 2

julia> eval(ex)
3

julia> z
3
```

Assignment expression introduces a new assigned variable `z` to the program state. Thus, manipulations of expressions and evaluations can modify the program states. When operating on them one has to be careful on the scope of variables.

## Interpolation

While one can design expressions by choice, it is not very useful unless you get to include pre-evaluated expressions. For example:

```
julia> x = 5;
julia> ex = :($x + 1)
:(5 + 1)
```

You could introduce computation expressions in inline evaluations as well. For example:

```
julia> ex = :($(x*x)+1)
:(25 + 1)
julia> y = eval(ex)
26
```

This technique is also known as **interpolation** in Julia programming.

## Complex Expressions and Quote Blocks

So far we have seen simple expressions as interned strings, their ASTs. However, real-life functions and expressions can be much more elaborate. It is natural to have doubts if there are any specific limitations to expressions that can be manipulated programmatically.

```
julia> ex = quote
x = 1
y = 2
x + y
end
quote
#= In[38]:2 =#
x = 1
#= In[38]:3 =#
y = 2
#= In[38]:4 =#
x + y
end
```

The multiline expression is included between a `quote…end` block. As you can see, line number expressions are added to track line numbers for line debugging purposes. A dump of the expression will show a more detailed view of the AST. The longer AST has the following features:

1.  It starts with a `head` attribute of the type block.
2.  The line nodes and subsequent expressions are available as a part of the `args` array.
3.  The line has a line number part and a file part that sets the context of the expression.

```
julia> dump(ex)
Expr
head: Symbol block
args: Array{Any}((6,))
1: LineNumberNode
  line: Int64 2
  file: Symbol In[38]
2: Expr
  head: Symbol =
  args: Array{Any}((2,))
    1: Symbol x
    2: Int64 1
3: LineNumberNode
  line: Int64 3
  file: Symbol In[38]
4: Expr
  head: Symbol =
  args: Array{Any}((2,))
    1: Symbol y
    2: Int64 2
5: LineNumberNode
  line: Int64 4
  file: Symbol In[38]
6: Expr
  head: Symbol call
  args: Array{Any}((3,))
    1: Symbol +
    2: Symbol x
    3: Symbol y
```

Let us modify the assignment in line #2 from `x = 1` to `z = 1`.

```
julia> ex.args[2].args[1] = :z
:z

julia> ex
quote
#= In[38]:2 =#
z = 1
#= In[38]:3 =#
y = 2
#= In[38]:4 =#
x + y
end

julia> eval(ex)
7

julia> z
1
```
