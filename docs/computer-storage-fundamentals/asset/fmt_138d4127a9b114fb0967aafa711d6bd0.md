
# Data Replication and Backup Solutions

## Replication Strategies

To increase the degree of fault tolerance, replication can also be one to many, multiple hops. Typically, advanced storage systems have these implemented.

Asynchronous mode of replication is commonly referred to as async replication.

### Block-Level Replication

Generally, replication between two storage systems of the same vendor uses their own proprietary protocol to copy data at block level. This makes the replication faster and more reliable. Most enterprise organizations prefer and implement block-level replication in their environment.

![Figure 7.20: Block level data replication between same types of storage systems](`images/Fig_7.20.jpg`)

### Software-Based Replication

There are also software solutions available that access virtual volumes from both storage systems and copy data from one to the other. Copy can be performed at file system level or volume level. This solution is comparably slower and less reliable, but can be implemented between two different types of storage systems. Software-based replication solution is mostly asynchronous replication.

![Figure 7.21: Software-based replication solution](`images/Fig_7.21.jpg`)

## Achieving RPO Objectives Through Data Replication

Local and remote replication are both data protection solutions. For instance, to achieve a six-hour RPO objective through local replication, you need to create a snapshot at least every six hours. In synchronous remote replication, the RPO value is zero. To improve the RPO value for asynchronous replication, both storage systems must have sufficient bandwidth available and unwritten data space at the local storage system. In the case of snapshot-based asynchronous replication, you need to schedule replication at least every six hours. Of course, bandwidth must be available to copy the changed data within six hours to avoid overlap with the next replication cycle.

## Backup Solutions

### Traditional Backup Solution

Backup solution is a data backup and recovery solution that ensures critical data is copied onto another system at a regular interval basis. Backup solution is also part of a storage solution. The system on which data is backed up is called the backup system; it can have a pool of tape drives, disk drives, or optical disks. Backup system is also called secondary storage, which is typically designed to store more data. Primary storage, such as storage disk arrays, is designed for high performance. Applications run on host servers and do not perform direct RW operations onto the backup system.

![Figure 7.22: Traditional backup solution](`images/Fig_7.22.jpg`)

Though remote replication technology copies data from one storage system to another, it has a disadvantage. In the event of accidental deletion or update of data, data corruption, or virus-infected data, the corrupted data also gets replicated to the other storage system. Replication solution does not help in these scenarios. Therefore, every organization must implement a backup solution to recover data in case of any loss.

Backup solution typically consists of a backup server that runs backup software; the client part of the backup software runs on application servers, and then backup jobs are configured and scheduled to read data from the application server and copy it to backup devices. The first backup is called a full backup; subsequent backups of the same set of data are called incremental backups, as they copy only the changed data since the last full or incremental backup.

Some backup solutions also copy data to cloud storage to ensure double protection of data and easy access from geographical locations.

### Snapshot-Based Backup Solution

In recent years, storage snapshot-based data backup has been replacing traditional backup solutions. A snapshot is a point-in-time (PIT) copy of the data of a primary virtual volume. Instead of reading data from the application server, data is read directly from the snapshot of the virtual volume on which the application stores data.

![Figure 7.23: Snapshot based backup solution](`images/Fig_7.23.jpg`)

Every time a backup job runs, a snapshot is created, data is read from the snapshot, and copied onto a backup system. This method of backup technology is called flat backup.

![Figure 7.24: Direct backup solution](`images/Fig_7.24.jpg`)

Latest storage systems or backup systems have backup software incorporated within them, eliminating the need for a separate backup server in between and copying data directly from the storage system to the backup system. Thus, it further improves the efficiency of data copying.

Some storage systems and backup software are intelligent enough to understand data blocks on the snapshot that contain user data; the software backs up only those blocks, thus significantly reducing backup time. However, this impacts only the first backup.

Subsequent backups are called incremental backups. Some intelligent storage systems have Changed Block Tracking (CBT) technology implemented; backup software leverages this technology to back up only the blocks that have changed with respect to the previous snapshot and backup.

When an application is actively performing RW operations on storage volumes, at any given time there may be some data in memory; therefore, a PIT snapshot may miss in-memory data. The application may find inconsistency upon recovery of data from this snapshot. To create an application-consistent snapshot, backup software sends a command to the application to quiesce I/O operations and flush data to disk; once completed, the snapshot is created and then I/O is resumed. Quiescing is a technique to pause application I/Os for a while to get it into a consistent state. A snapshot created with this method is called an application-consistent snapshot. A snapshot created without quiescing the application is called a crash-consistent snapshot.

For instance, to achieve a six-hour RPO objective through local replication, you need to schedule backup at least every six hours.

### Continuous Data Protection (CDP)

Continuous Data Protection (CDP) refers to real-time data backup for every change of data. This technology keeps track of all changes to data and ensures backup is always occurring. Unlike traditional backup, CDP technology does not require any scheduling of backup tasks.

Data on a virtual volume can be reverted to any point in time. For example, suppose the data gets infected or corrupted at 9:41 AM. Data that existed at 9:40 AM can be restored. Therefore, with CDP technology, the RPO value is near zero.

Most vendors offer CDP through implementing frequent snapshots. Some intelligent storage systems are capable of keeping track of every block change in a journal. However, these frequent tasks create overhead in the system and impact host server I/O performance. Therefore, the frequency of CDP backup becomes a tunable parameter and a trade-off for an administrator to decide between performance and granularity of data backup.

## Copy Data Management

Data on snapshots or backup sets is not only used for recovery; these copies of data can also be used for other purposes, such as report generation, data analytics, test, and development. In recent days, the need for these has grown significantly because of big data and e-commerce evolutions.

Copy data management is a software solution that manages copies of data more efficiently and meets the demand for several copies at the same time.

## Write Once Read Many (WORM)

Some storage vendors make backup devices or media that allow Write Once Read Many (WORM) technology, which is used to archive data for long periods of time in terms of years. This way of storing not only prevents accidental deletion or modification of data but also enhances the lifespan of the storage device or media. Most organizations look for this feature for compliance with their data protection policies for data security and legal reasons.
