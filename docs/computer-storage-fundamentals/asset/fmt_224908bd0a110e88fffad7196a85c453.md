
# Overview

CD-R or Blu-ray discs are WORM storage, but they cannot store TBs of data, hence special WORM devices or media are used.

Content addressable storage (CAS) is a storage technology in which data is stored based on a unique address derived from the data itself. CAS technology is primarily designed for archival solutions to store and access fixed data that does not change over time. Once the data object is stored, it cannot be altered or deleted, thus supporting WORM technology.

Modern object stores also rely on globally unique identifiers (GUIDs) but no longer generate them from the content. Object storage evolved from the concept of CAS technology, in which data is used as an object along with the metadata and unique identifier.

# Conclusion

Data protection has always been a critical requirement for any storage solution. Fundamentally, this has two aspects: prevention of disruption due to any hardware or software component failure (fault tolerance), and recovery of data in case of any disaster or accidental loss of data. Several features and solutions are implemented to address both aspects. For example, multiple controllers in a storage system, disk enclosure with dual cabling, and multipath configuration provide NSPOF. A fully NSPOF solution requires a host server with at least two HBAs, two switches, and a storage system with high availability features like multiple controllers, disk enclosures, and so on. Any component failure will cause the workload to switch to other available active paths.

A snapshot is a PIT copy of a primary volume. Initially, all blocks of a snapshot refer to the corresponding blocks of the primary volume. As data on the primary volume changes, the old data is first copied to the snapshot area, and then the reference of the snapshot block to the primary block is broken.

There is a wide variety of uses for a snapshot. It helps to have a copy of application data at regular intervals; data can be recovered to the latest copy or a desired snapshot if data gets corrupted, configuration is changed accidentally, or virus infection occurs. Snapshot data can also be used for report generation, analytics, and test and development purposes.

The purpose of a snapshot and a clone is almost the same, except a clone becomes an independent volume once all blocks are physically copied and references are unlinked. Both snapshots and clones are called local replication, as the data gets copied locally within the storage system.

In remote replication, data gets copied to another storage system, called the remote or target storage system. The target storage system can be physically located at the same place as the source storage system or at a different geographical location to provide better fault tolerance in the event of natural calamities such as flood, fire, or earthquake.

There are two primary modes of remote replication. In synchronous mode, every data write gets replicated to the remote site and acknowledged to the host server. If bandwidth between both storage systems is not sufficient, write operations may be slow, but a copy of each data at both sites is guaranteed. In asynchronous mode, data is first written to the local site and stored temporarily for replication at a later point in time. This mode allows completing the I/O operation faster, but replication of data between the two sites may not be in exact sync always.

A backup solution is another way to protect data from accidental loss. Recently, instead of using the application server, snapshot technology is used to copy data directly from the storage system to the backup system. This improves backup performance significantly.

# Case Studies

## Case Study 1: An organization has business critical data, ready to compromise with performance

### Requirement

A financial business organization has business critical data. They are looking for a storage solution that can protect from any system failure. They are ready to compromise with performance, but not with data loss.

### Analysis

A disaster recovery solution makes a copy of data from one storage system to another. Since this organization is concerned with data protection, disaster recovery can be recommended. There are two replication modes available: synchronous and asynchronous. In synchronous replication mode, every bit of data replicates to the other system before it acknowledges to the host system, thus ensuring a highly protected solution.

To protect data in the local system itself, RAID 1 or RAID 6 can be suggested, which provides the highest level of data protection against any disk failure.

In addition, a backup solution can be recommended to keep a copy of the data off-site.

## Case Study 2: Protect from accidental deletion by end users

### Requirement

An organization has deployed a high-end storage solution along with fault protection features, but the administrator is still concerned about data deletion or corruption by employees. What solution can be proposed?

### Analysis

A disaster recovery solution replicates data from one storage system to another, but if data is corrupted or deleted at the source, the same data gets replicated at the target site. Therefore, disaster recovery does not solve this problem.

The best solution to protect data against accidental deletion is snapshot technology. The administrator can schedule regular intervals. In case of any accidental deletion, previous data can be retrieved from a snapshot.

The frequency of snapshot creation can be decided based on the desired RPO value. It can be daily or even five-minute granularity. Let us consider hourly snapshot creation for this case.

Retention of snapshots is also an important decision: the number of days snapshots can be retained. Let us consider a retention period of one week.

### Solution

A scheduled job can be created to create a snapshot of the data volume at every hour interval. Another scheduled job can delete week-old snapshots. Therefore, at any given point in time, the volume will have about 24 × 7 = 168 snapshots. This solution will help the administrator restore data from the latest available snapshot in case of any accidental data deletion or corruption by employees.

## Case Study 3: High availability support for a storage solution

### Requirement

A healthcare institute is planning to deploy a storage solution. Availability is the most critical requirement. They cannot compromise with inaccessibility of data at any cost. What solution can be proposed?

### Analysis

Most enterprise storage systems provide a number of features to ensure data availability. A fully NSPOF solution needs to be implemented starting from the host server:

- At least two host servers in a cluster configuration
- Each server with two FC HBAs
- Two independent fabrics
- Multipath configured
- Storage system with multiple controllers and dual-path disk enclosures
- Volumes configured with RAID 1
- Spare disks configured
- Monitoring for any errors in the system and taking corrective action
- Disaster recovery
- Management software to automatically failover applications from one site to another in the event of failure

Implementation of these features enables a highly available solution, allowing data availability in the event of any hardware failure or disaster.
