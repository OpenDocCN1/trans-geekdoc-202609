
# Storage System Hardware Components

## Hard Disk Drives (HDD)

The most critical hardware component of a storage system is the hard drive, which essentially stores the user data.

The disk has platters that rotate at a speed expressed in revolutions per minute (`RPM`). This is the number of times the platters will do a full rotation in one minute. The head is fixed on an arm to read and write data from the platters. Since the disk arm and the head are fixed in one position, it will often have to wait for the platter to spin to the right place. The common `RPM` values are 5400 or 7200 for consumer Serial Advance Technology Attachment (`SATA`) disks and 10000 or 15000 for high-performance server/storage area network (`SAN`) disks.

There are mainly two types of hard drives available:

- **Small Form Factor (`SFF`)**, 2.5-inch disks
- **Large Form Factor (`LFF`)**, 3.5-inch disks

`SFF` disks consume less power and space compared to `LFF`. `SFF` disks are generally higher cost, with Serial Attached SCSI (`SAS`) interface, and used for high-workload environments. `LFF` disks are lower cost, with `SATA` interface, and used for high-capacity storage.

![Figure 2.8: SFF and LFF hard drives](images/Fig_2.4.png)

*Figure 2.8: SFF and LFF hard drives*

Each hard drive has a printed circuit board (`PCB`) that runs firmware. When the hard drive is powered on, firmware checks the health of each part of the drive, sends the command to power on the motor, along with stabilizing and monitoring the speed. This is how the drives become ready to accept read/write commands from storage controllers.

Hard disks store 0s and 1s in the form of magnetic fields. The circular part of a hard disk is called a platter, and a tiny magnetized region on the platter stores a bit. To write data on the hard disk, a magnetic field is applied on the tiny field in North-South (`N-S`) or South-North (`S-N`) polarities. The pattern of polarities represents 1 or 0.

For instance, reversals (`N-S` to `S-N` or `S-N` to `N-S`) represent 1, whereas same polarity (`N-S` to `N-S` or `S-N` to `S-N`) represents 0.

## Solid State Drives (SSD)

Solid state drive (`SSD`) has no moving mechanical parts, like platters or motors in hard disk drives (`HDD`). `SSD` performance is significantly higher than traditional electromechanical disk drives.

Recently, `SSD` uses non-volatile `NAND` flash memory. A special type of metal-oxide-semiconductor field-effect transistor (`MOSFET`), called a floating gate transistor, isolated by a highly resistive layer, is used to permanently trap charged electrons. Each transistor can store a single bit. 1 is represented if the cell is not charged, and 0 if it is charged.

Storage systems which are designed and use all `SSD` drives are also known as all-flash array (`AFA`).

## Storage Class Memory

In a computer system, the storage device is the slowest component compared to any other major components, such as `CPU` or `DRAM` memory. Typically, `DRAM` is known for high performance, high cost, but low capacity. On the other hand, storage such as `SSD` and `HDD` are known for high capacity, low cost, but lower performance than `DRAM`. Storage Class Memory (`SCM`) is a type of memory that has the capacity and price similar to storage but performance similar to memory.

Let us imagine the `CPU` operates in seconds; in that case, to get data from `DRAM` takes about a few minutes, whereas to get data from `HDD` takes a few months. Therefore, `HDD` is a significantly slower device compared to `CPU` and `DRAM`.

Though `SSD` has reduced this gap to less than a day now, there is still a huge difference between minutes and a day, as `SSD` is approximately 1000 times slower than `DRAM`. `SCM` brings that down to approximately 100 times, to just a few hours.

Recently, most storage vendors are planning to implement `SCM` in their storage systems. Based on the evolution of storage devices so far, it is predicted that `SCM` may become the primary storage in the future and `SSD` may be used as secondary storage for data archival.

## Non-Volatile Memory Express

`ATA` and `SCSI`-based protocols support only a single queue. Therefore, for accessing high-speed storage media such as `NAND` flash memory and `SCM`, these protocols have become a bottleneck. Non-Volatile Memory Express (`NVMe`) is a storage protocol specifically designed for these storage devices.

While `SATA` and `SAS` protocols are best suitable for spinning `HDDs`, `NVMe` protocol suits `NAND` flash memory and `SCM`. `NVMe` protocol provides low-latency, high performance through a large number of parallel operations over PCI Express (`PCIe`) bus. Due to the interface speed, performance of the new storage media, and proximity to the `CPU`, `PCIe` becomes a better choice of storage interface for `NVMe` protocol. `NVMe` is a `NUMA`-optimized protocol, which allows multiple `CPU` cores to share the ownership of queues, their priority, as well as arbitration mechanisms and atomicity of the commands.

As shown in the following `PCIe` topology, the `NVMe` disk subsystem is a `PCIe` endpoint which has primarily two components: `NVMe` controller and `NVM`.

The host interacts with the `NVMe` controller to send read, write, system call requests, and the controller in turn accesses devices that are connected to it for performing block I/O (`BI/O`).

![Figure 2.12: NVMe topology](images/Fig_2.7.png)

*Figure 2.12: NVMe topology*

Graphics and Memory Controller Hub (`GMCH`) is also referred to as Memory Bridge, Memory Hub, or North Bridge. I/O Controller Hub (`I/OCH`) is also referred to as I/O Bridge, I/O Hub, or South Bridge.

Though fundamentally data transfer on the `PCIe` bus is serial, with `NVMe`, every command and data transmission happens in massively parallel using multiple `PCI` lanes, multi-core `CPUs`, and parallel access to the `NAND` devices. This is how `NVMe` achieves exceptionally high bandwidth.

```
# ls -l /dev/nvme*
crw------- 1 root root 245, 0 Mar 30 21:07 /dev/nvme0
brw-rw---- 1 root disk 259, 0 Mar 30 21:07 /dev/nvme0n1
brw-rw---- 1 root disk 259, 1 Mar 30 21:07 /dev/nvme0n2
```

`/dev/nvme0` is a character special file for the `NVMe` controller, whereas `/dev/nvme0n1` and `/dev/nvme0n2` are two block special files for block devices attached to the controller.

Due to faster access of `NVMe` flash memory-based disks, the following are the use cases and deployment models being adopted:

1. Boot disk of client computers
2. Server's internal storage disks
3. Server's cache memory for frequently used data
4. Storage system's backend disks

Recently, most storage vendors are designing their storage systems to support `NVMe`-based disks to avoid any disk bottleneck at the backend and improve overall storage performance.

### Namespace

A namespace is a collection of blocks of a device connected to the `NVMe` controller. This is similar to a file system partition for better management of storage space.

Here are some features of a namespace:

- From the kernel point of view, a namespace is nothing but a linear sequence of sectors.
- Each namespace has an ID.
- A namespace is created on flash memory and attached to the `NVMe` controller.
- `NVMe` can support up to 64K I/O queues, with each queue having 64K commands in it. Whereas `SAS` and `SATA` can only support a single queue, and each can have 254 and 32 commands respectively.
- One namespace can have a maximum of 64K queues (`2^16 = 65535`) per controller. Total, (`2^32 = 2^16 x 2^16`) commands are supported.
- There are two types of queues: admin queue to perform get and set for controller management, and I/O queue (read/write for `NAND`).

### NVMe over Fabrics

`NVMe` is designed for local use over the `PCIe` bus. Therefore, initial deployments of `NVMe` have been as local disks in a computer, direct attached storage (`DAS`) in servers, and backend disks in storage systems.
