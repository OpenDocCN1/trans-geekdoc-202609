

# NiPoPoW (非交互式工作量证明)

由雅典大学、爱丁堡大学、伊利诺伊大学等开发。这些用于验证运行在工作量证明（PoW）共识机制的区块链网络是否发生了某个事件。这些可以在不连接区块链网络且不下载区块头的情况下，通过网络中的各种节点进行验证。它们支持侧链和手机手机区块链钱包。

# Node JS

Node.js 是一个开源、跨平台的后端 JavaScript 运行时环境，运行在 V8 引擎上并在网络浏览器之外执行 JavaScript 代码。它由 Ryan Dahl 编写于 2009 年发布。Node.js 让开发者可以使用 JavaScript 编写命令行工具和进行服务器端脚本——在服务器端运行脚本以便在页面发送到用户的网络浏览器之前生成动态网页内容。除了 JavaScript 之外，它还用 C 和 C++ 编写。Node JS 正用于开发加密货币和建立区块链。

# Nodes (节点)

节点构成了区块链的基础设施。它们存储、传播和保护区块链数据，因此从理论上说，区块链存在于节点之上。全节点基本上是一个设备（如计算机），它包含了区块链交易历史的完整副本。点对点（P2P）协议允许节点在区块链网络中相互交互、通信并传播有关新区块和交易的信息。节点分为三种：矿工节点、轻节点和全节点。

# Nonce (仅使用一次的数字)

Nonce 是一个随机整数，是一个 32 位（4 字节）字段。它代表了矿工竞争求解并获得加密货币的数字。矿工调整 Nonce 以使其成为一个有效的数字，用于区块值的哈希。Nonce 是只能使用一次的数字。一旦找到了完美的 Nonce（也称为黄金 Nonce），它会被添加到哈希后的区块中。这完成了区块及其添加到区块链的操作。与该数字一起，该区块的哈希值将被重新哈希，以创建一个让区块链更强大、更安全的算法。

# Notary (公证)

在传统世界中，公证员是授权在法律事务中执行行为的人，特别是见证文件签名。分布式账本技术公司 R3 使用“公证服务”来防止其 Corda 区块链网络中的双重花费。公证集群是一种网络服务，通过对给定交易进行证明为共识提供唯一性。它仅适用于未签名的交易以及未消耗任何提议交易输入状态的交易。如果交易已经签名，它将拒绝交易并将其标记为双重花费尝试。它代表了交易在系统中作为有效或无效的终点。

# NVT ratio (NVT 比率)

NVT 代表网络价值与交易量的比率，通过将网络价值除以每日交易量来计算。它由 Willy Woo 于 2017 年引入。对于加密货币而言，NVT 可以等同于用于计算股票估值的市盈率（P/E 比率）。NVT 意味着区块链网络或加密货币是否被高。如果区块链网络的价值过高，且没有相应数量的交易或代币交换支撑，则表明存在一个很快就会纠正的潜在价格泡沫。

# OAuth (开放授权)

OAuth 是一种单点登录（SSO）和访问委托的开放标准。它通常用作互联网用户授予网站或应用程序授权或权限，以访问其在其他网站上的信息的方法，而无需提供密码。例如：使用某人的 Google 或 Facebook 账号/身份验证登录其他网站或应用程序。它允许对用户数据的受限访问。目前 OAuth 有两个版本：版本 1 和版本 2。

# Off Chain Governance (链下治理)

链下治理是指适用于区块链或加密货币网络中发生的、将价值移到区块链之外的交易规则。支持链下交易是为了使交易更快、更廉价且更私密。它们最适合非加密货币交易。例如：数字标识可以存储在公链或私有区块链的链上，而支持它的信息（如护照、驾照和这些文档中包含的个人身份信息 (PII））可以存储在链下。

# Offline Wallet (离线钱包)

也称为冷钱包，是一种不连接到互联网的钱包，因此被接管或破解的风险要低得多。Electrum 冷钱包、Ledger Nano S、Trezor Model T 和 Coinbase Vault 都是离线钱包的良好示例。

# On Chain (链上)

链上交易发生在区块链上的交易，并反映在相应的分布式、公共或私有账本上。这些交易在区块链上经过验证和确认后无法撤销。只有在网络大多数人同意这样做的情况下才能被撤销。因此，它们提供了很好的安全性和透明度。

# On chain Governance (链上治理)

链上治理是一种升级区块链的系统，其中代码更改被编码到协议中并由利益相关者的投票决定，即每个节点都对是否接受或拒绝提议更改进行投票。它促进了透明度、更快的共识、持久且强制的代码更改以及去中心化的决策。

# Onclave

Onclave Networks, Inc. 是全球网络安全领导者，通过私有网络保护运营技术（OT/IoT）。它提供零信任安全通信平台，保护 OT/IoT 设备免受未经的访问和网络攻击。

# Online Wallet (在线钱包)

也称为热钱包，连接到互联网，因此更容易受到黑客攻击。Exodus 和 Mycelium 热钱包是在线钱包的示例。

# OpenShift

OpenShift 是由 Red Hat 开发的一系列容器软件产品。它是一个关注开发者体验和应用程序安全的 Kubernetes 发行版，与平台无关。OpenShift 帮助将应用程序部署到一个或多个主机上。这些可以是面向用户的应用程序，也可以是后端应用程序，包括微服务或数据库。一些区块链应用提供商已实现以现成方式使用 OpenShift。

# Open Zeppelin

Open Zeppelin 提供了一个经过测试的智能合约库，用于在以太坊上进行安全的智能合约开发。它包含了最常用的 ERC 标准实现。Coinbase、Augur、Bitgo,Brave 和以太坊基金都使用了它。

# Oracles (预言机)

预言机是第三方服务，为智能合约提供外部信息以便智能合约做出决策。它们作为区块链与外部世界系统之间的桥梁。加密货币交易所和农业保险是两个著名的案例，证明了预言机对于验证智能合约执行的外部数据集来源和完整性的重要性。例如：如果是一种涵盖农民自然灾害的去中心化作物保险，预言机会向管理此类保险的智能合约发送损害程度的数据，以便授权或拒绝保险理赔。

# Orchestration (编排)

偏排是对计算机系统、应用程序和服务的自动化配置、管理和协调。区块链可以用于云计算和网络虚拟化的虚拟机编排。

# Orderer (排序器)

排序服务为客户端和节点提供共享的通信信道，为包含交易的消息提供广播服务。它有助于将交易汇组成区块并分发到区块链网络中的锚节点。排序服务作为 Hyperledger Fabric 的重要功能，通过维护允许创建通道的组织列表来促进通道的创建。此类组织列表被称为联盟。
