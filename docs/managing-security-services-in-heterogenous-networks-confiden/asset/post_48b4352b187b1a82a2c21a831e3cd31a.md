## 3.4.3 Dempster-Shafer Theory

Dempster-Shafer theory [3] is the mathematical aggregation function. A node uses DST to aggregate multiple trust recommendations

![](img/058011bdc8fc3d3d77199bfcbf721be0_62_0.png)

![](img/058011bdc8fc3d3d77199bfcbf721be0_62_1.png)

**Figure 3.12** (a) MANET Network Topology. (b) DFPN-Modeled MANET Network.

that are received from multiple paths. The DST method can identify the bias recommendations, and it can reduce the impact of biased recommendation in trust computations.

The DST function depends on three functions, i.e. mass function, plausibility function (PI), and belief function (Bel). Let an event e happen, and E = {e1, e2, e3} is the set of evidences about the event e. The power set P(E) is the {Ø, {e1}, {e2}, {e3}, {e1, e2}, {e2, e3}, {e1, e3}, {e1, e2, e3}}.

*Mass function*: The mass function(m) maps all the subsets in P(E) to the range [0,1], m:P(E) → [0,1] where m(Ø) = 0 and ΣB∈P(E) m(B) = 1.

*Belief function* (Bel): If X is the subset in P(E), then bel(X) = ΣC⊆X m(C).

*Plausibility function* (pl): If X is the subset in P(E), then pl(X) = ΣC∩X≠Ø m(C).

### 3.4.3.1 Dempster's Rule for Combinations

Let X be the element in P(E), and A and B are two observer nodes about event X. Their observations are represented as m<sub>A</sub>(X), m<sub>B</sub>(X). The combination of these two observations can be calculated using Equation (13).

```
m_{A,B}(X) = \frac{\Sigma_{P \cap Q=X} m_A(P) m_B(Q)}{1 - K} (13)
```

where the constant K is defined as K = \Sigma_{P \cap Q = \emptyset} m_A(P) m_B(Q).

### 3.4.3.2 DST Example

In Figure 3.13, node S is taking a trust recommendation from nodes P and Q about node D. The trust recommendation is in the form (T, T̄, U), i.e. trust, distrust, and uncertainty, respectively. Here nodes P and Q trust recommendations on node D are {0.7, 0.2, 0.1} and {0.3, 0.5, 0.2}, respectively. These recommendations are multiplied with their trust values.

Node S has 0.9 trust on P, so P's trust is recalculated as

```
m<sub>P</sub>(T) = T<sub>P</sub> × 0.7 = 0.63
m<sub>P</sub>(T̄) = T<sub>P</sub> × 0.2 = 0.18
m<sub>P</sub>(U) = T<sub>P</sub> × 0.1 = 0.09
```

Node S has 0.8 trust on Q, so Q's trust is recalculated as

```
m<sub>Q</sub>(T) = T<sub>Q</sub> × 0.3 = 0.24
m<sub>Q</sub>(T̄) = T<sub>Q</sub> × 0.5 = 0.40
m<sub>Q</sub>(U) = T<sub>Q</sub> × 0.2 = 0.16
```

The aggregation of P,Q node recommendations on node D is evaluated as in Equation (21).

\( m_{P,Q}(T) = \frac{m_P(T)m_Q(T) + m_P(T)m_Q(U) + m_P(U)m_Q(T)}{1 - [m_P(T)m_Q(\overline{T}) + m_P(\overline{T})m_Q(T)]} \)
\( = \frac{0.05}{0.09} = 0.55 \)

This equation can be extended for combining \( n \) node recommendations on node D, i.e. \( m_{1.....n}(T) \).

## 3.4.4 Trust Matrix Operations

Trust matrix operations are used for propagating trust values in the network to avoid the risk of trust computational work of the same node.

Here each node has the trust information, and it maintains the information in a matrix format of \( n \times n \) order (n represents the number of nodes in the network).

\( N^T = \left( \begin{array}{ccccc} t_{11} & ... & t_{k1} & ... & t_{n1} \\ ... &  & ... &  & ... \\ t_{1k} & ... & t_{kk} & ... & t_{nk} \\ ... &  & ... &  & ... \\ t_{1n} & ... & t_{kn} & ... & t_{nn} \end{array} \right) \) (14)

In Equation (14), \( t_{ij} \) means the node i trust value on node j. Using trust matrix operations, a node can calculate the trust value of a target node that is not in direct communication (by applying a trust transitive rule).

Trust transitive rule:

- i. \( t_{ij} \) : node i trust value on node j
- ii. \( t_{jk} \) : node j trust value on node k
- iii. Then node i trust value on node k is evaluated as \( t_{ik} = t_{ij} * t_{jk} \).

Let \( t_i = [t_{i1}....t_{ik}....t_{in}] \) be the trust vector of node i; it can get updated iteratively by using Equation (15).

\(\left( \begin{array}{c} t_{i1} \\ ... \\ t_{ik} \\ ... \\ t_{in} \end{array} \right)_{NEXT} = \left( \begin{array}{ccccc} t_{11} & ... & t_{k1} & ... & t_{N1} \\ ... &  & ... &  & ... \\ t_{1k} & ... & t_{kk} & ... & t_{Nk} \\ ... &  & ... &  & ... \\ t_{1n} & ... & t_{kn} & ... & t_{nn} \end{array} \right) \otimes \left( \begin{array}{c} t_{i1} \\ ... \\ t_{ik} \\ ... \\ t_{in} \end{array} \right)_{CURRENT} \) (15)

In Equation 15, the value \( t_{ik} \) is evaluated as \( t_{ik} = max_{1 \le j \le n} \{t_{ij} \times t_{jk}\} \).

Here node i can apply this formula iteratively to find the trust values of multi-hop away nodes like

- \( t_i = (N^T)t_i \)
- \( t_i = (N^T)^2t_i \)
- \( \vdots \)
- \( t_i = (N^T)^n t_i \)

## 3.5 Conclusion

In MANETs, due to resource constraints and network dynamics, the implementation of complex security algorithms degrades network performance. In this work, this limitation is overcome with trust handling methods. Here node trust is evaluated by taking into consideration ability (resources) and attitude. A comprehensive discussion was provided on the trust attacks and their countermeasures. Different soft computing techniques (i.e. fuzzy logic, fuzzy Petri-nets, Dempster-Shafer theory, and trust matrix operations) are discussed for trust management in MANETs.
