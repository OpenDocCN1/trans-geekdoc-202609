
# CHAPTER 7 解释性和可解释性技术在 Transformer 中

DOI: [10.1201/9781003170082-7](https://doi.org/10.1201/9781003170082-7)

在医疗、立法、执法或金融等关键领域的实际应用中，除了预测结果外，还需要从可解释性角度理解模型。遗憾的是，大多数最先进的 Transformer 模型和本文中涵盖的技术仍被视为“黑盒”，这会显著阻碍其采用。因此，有迫切的需求在从理解和诊断两个角度为这些复杂的最先进的模型构建可解释性。正如 Xie 等人所提议，我们将介绍能够提升可解释性的模型特性、影响可解释性的相关领域、针对基于 Transformer 和基于注意力系统的可解释方法的分类法，以及在使用不同可解释技术的电子健康记录系统中进行的详细案例研究，以获得实用的洞见 \[[275](#refbib.xhtml#refbib.xhtml#refbib_275)\]。

## 7.1 可解释系统的特征

可解释系统的决定性目标之一是让系统的最终用户能够理解输入与输出之间的关系。因此，特征可以定义为用户可以评估和测量的系统属性。正如 Xie 等人所提议，必要的四个特征如下：

1. **置信度**。当最终用户（决策者）能够根据输入和输出将 Transformer‑based 模型的处理过程与自己的思考过程对齐时，系统的置信度会提升。注意力热图在图像或文本上突出模型在决策（分类、识别、问答等）时认为重要的输入部分，输出模拟人类通过关注机制进行关联的形式，从而作为一种解释 \[[106](#refbib.xhtml#refbib_106), [127](#refbib.xhtml#refbib_127), [154](#refbib.xhtml#refbib_154), [195](#refbib.xhtml#refbib_195), [254](#refbib.xhtml#refbib_254)\]。

2. **安全**。在直接或间接影响人类生命的应用中，Transformer‑based 模型应被认为是安全的。安全可以从以下几个方面衡量：(i) 行为一致且确定性，即相同的输入始终产生相同的输出；(ii) 在标准和异常条件下保持稳健可靠；(iii) 能够防止对社会整体产生负面影响的选择 \[[191](#refbib.xhtml#refbib_191)\]。

3. **信任**。可靠的模型不需要额外验证。已证明，预测置信度高的模型并不保证可信度 \[[95](#refbib.xhtml#refbib_95), [189](#refbib.xhtml#refbib_189), [191](#refbib.xhtml#refbib_191), [291](#refbib.xhtml#refbib_291)\]。Xie 等人提出了两个重要的可信度标准：(i) 满意的测试，即模型在训练数据上表现与在未见测试数据上的表现相似；量化上，当训练集和测试集的准确率、精确率等指标相近时，信任度提升。经验是一种更质性的评估，判断系统是否足以在不进行检查的情况下完成任务。真实部署中的数据和概念漂移会进一步降低系统的信任。近年来有许多研究探讨从模型预测角度对安全进行研究 \[[5](#refbib.xhtml#refbib_5), [22](#refbib.xhtml#refbib_22), [134](#refbib.xhtml#refbib_134), [252](#refbib.xhtml#refbib_252)\]。

4. **伦理**。如果模型的决策过程不违背最终用户设定的伦理原则，则可以视为在伦理层面上是可接受的。为伦理人工智能制定框架和指南的研究本身就是一个 rapidly growing 研究领域 \[[20](#refbib.xhtml#refbib_20), [26](#refbib.xhtml#refbib_26), [59](#refbib.xhtml#refbib_59), [268](#refbib.xhtml#refbib_268)\]。

## 7.2 影响可解释性的相关领域

Xie 等人指出四个与可解释性紧密相关且与前文定义的特征相呼应的领域：

* **学习机制**：能够提供模型训练过程的洞察有助于提升模型的置信度和信任度。模型达到的学习状态的形成过程可以通过以下方式进一步探讨：从滤波器、权重和激活的视角理解不同层在学习概念或统计模式上的演变；研究不同层在输入和权重影响下的收敛情况，并从记忆和统计力学角度分析网络的泛化特性 \[[294](#refbib.xhtml#refbib_294), [301](#refbib.xhtml#refbib_301)\]。对不同层的收敛性进行输入和权重分析，以及从记忆和统计力学角度分析网络的泛化属性 \[[206](#refbib.xhtml#refbib_206)\]。

* **模型调试**：类似于软件调试，模型调试指对模型架构、网络中数据处理以及训练和运行过程中引入的错误进行检查。常见的研究方法是构建辅助模型，作为诊断和检查的探针 \[[140](#refbib.xhtml#refbib_140)\]。Amershi 等人提出的 ModelTracker 允许对标记错误数据、缺失特征的识别、训练数据不足导致标签学习不足的洞察、异常影响、特征空间可视化、性能总结等进行可视化交互，是一种模型无关的调试方法 \[[4](#refbib.xhtml#refbib_4)\]。Fuchs 等人提出的神经听诊器（Neural stethoscopes）是另一种通用框架，通过量化重要因素的影响并通过促进/抑制信息来分析学习过程 \[[90](#refbib.xhtml#refbib_90)\]。

* **对抗攻击与防御**：对抗示例是人工工程的输入，用于检验模型的判别能力。构建对抗示例需要理解输入空间以及分类问题中类别边界。对抗攻击和防御是从可解释性和诊断角度探索模型的两种不同方式 \[[291](#refbib.xhtml#refbib_291), [295](#refbib.xhtml#refbib_295)\]。黑盒攻击和白盒攻击是两种主要的对抗攻击类型，用于生成误导模型的示例 \[[76](#refbib.xhtml#refbib_76), [86](#refbib.xhtml#refbib_86), [233](#refbib.xhtml#refbib_233)\]。最近的研究表明，在输入上加入不可感知的噪声会暴露模型的脆弱性 \[[178](#refbib.xhtml#refbib_178)\]。对抗防御是使模型对抗示例保持鲁棒的方法。两种常见的防御手段是：(i) 对抗训练，即在训练数据集中加入对抗示例以提升鲁棒性；(ii) 扰动消除，即模型识别并拒绝对抗示例 \[[95](#refbib.xhtml#refbib_95), [218](#refbib.xhtml#refbib_218)\]。
