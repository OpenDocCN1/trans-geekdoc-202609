
# Dilated sliding window attention

这种注意力模式通过在上下文窗口中加入长度为 `d` 的间隙，扩展了滑动窗口注意力的范围。实际上，这扩展了上下文窗口的有效大小。例如，在前面使用的九个 token 的序列中，若设定膨胀 `d` = 2，则在生成 `w[5]` 的上下文时，会跳过中间的一个词。因此，`w[5]` 的左上下文为 (`w`[1], `w`[3])，右上下文为 (`w`[7], `w`[9])。注意，尽管整体上下文宽度增大，这种注意力模式仍然阻止 token 关注其紧邻的 token，或距离窗口中心 `d` − 1 的 token，或窗口内已被关注的位置。不同的注意力头可以使用不同的 `d` 值，从而缓解上述问题。[Fig. 5.8](#ch5.xhtml#fig5_8) 展示了 `L` = 2、`w` = 4、`d` = 2 时的 dilated sliding window attention。

# Global attention

全局注意力模式允许部分 token 关注序列中任意其他 token。此类情况下，序列中所有 token 都关注该 token。这相当于在注意力权重矩阵中选择特定的行及其转置的列。

Longformer 根据训练任务决定哪些 token 允许拥有全局注意力。例如，在问答任务中，问题中的所有 token 都拥有全局注意力。拥有全局注意力的 token 数量通常与序列长度无关，因此全局注意力的时间复杂度也是线性于序列长度。Longformer 将全局注意力与滑动窗口注意力相结合。

全局注意力和局部（短范围）注意力的权重分别通过为全局和滑动窗口模式提供各自的查询、键和值矩阵来计算：**Q**[*g*], **K**[*g*], **V**[*g*] 与 **Q**[*s*], **K**[*s*], **V**[*s*]， respectively。

Longformer 在低层使用小窗口大小，在高层使用大窗口大小。这使得高层具有层次化结构。事实上，稀疏滑动窗口仅用于高层，使得低层能够专注于局部上下文。

## 5.2.2.2 Reformer

Reformer，如文献[\[[142](#refbib.xhtml#refbib_142)\]\] 所述，通过修改注意力机制来降低注意力机制的复杂度，并通过使用可逆残差网络来减少内存使用。这些技巧使得 Reformer 能够包含几乎是 Transformer 中数个数量级更大的上下文窗口（最高可达 1,000,000 个词）。

### 注意力与局部敏感哈希

如[section 5.2.1.1](#ch5.xhtml#sec5_2_1_1) 所述，Transformer 核心的缩放点积注意力的时间复杂度为 *O*(*L*²)，随着序列 token 数量 *L* 增加，这一复杂度变得不可接受。Reformer 通过修改注意力机制并采用局部敏感哈希（locality‑sensitive hashing）来解决这一问题，从而将时间复杂度降至 *O*(*L*log *L*)。

回顾在缩放点积注意力中，查询、键和值矩阵是将 `d[m]` 维输入向量转换后得到的，查询和键的维度为 `d[k]`，值的维度为 `d[v]`。

在 *A* 的公式中，最耗时的项是 **QK**<sup>(`T`)</sup> 的乘积，且在应用软max 函数后，仅在每个 `d[m]` 维度中保留最大的项。这意味着对每个查询向量 **q**[*i*]，只需要在 **K** 中与它最接近的键。为此，他们将 **Q** = **K**，即每个查询向量只需找到最接近的键。这是一个近似最近邻问题，可以使用局部敏感哈希（LSH）来解决。

### 局部敏感哈希

局部敏感哈希（LSH）于 1998 年在[\[[129](#refbib.xhtml#refbib_129)\]\] 中被提出，作为基于哈希的近似相似度搜索方法。形式上，LSH 基于一族哈希函数 ℱ，作用于 item 集合，若两个 item *x* 与 *y* 满足 *P*(_r_∘_o_∘_b_∈ℱ)_h_(_x_) = _h_(_y_) = _s_(_x_, _y_) = s**i**m(_x_, _y_)，其中 _s_(_x_, _y_) ∈ [0, 1] 为定义在 item 集合上的相似度函数[\[[39](#refbib.xhtml#refbib_39)\]\]。换句话说，只要能够为数据集中的 items 进行哈希，使得两个相近的 items 碰撞概率远高于相远的 items，即可视为一种 LSH 方法。

LSH 实现方式多样，Reformer 采用文献[\[[6](#refbib.xhtml#refbib_6)\]\] 中定义的角度 LSH 方案。请注意，查询矩阵 **Q**（同样是键矩阵 **K**）的形状为 *l* × `d[k]`。计算 **Q** 的哈希如下：首先生成一个 `d[k]` × *b*/2 的随机矩阵 **R**，其每列仅含一个非零值，均匀采样自 ±1，且 *b* 为哈希数量。随后计算 **QR**，对查询（以及键）矩阵进行旋转。最后，哈希结果为 _h_(**Q**) = arg max(**QR**, ‑**QR**) [\[[142](#refbib.xhtml#refbib_142)\]\]。哈希后，查询和键的索引会被 permute，使得映射到同一桶的序列位置相邻。随后，在每个哈希桶内计算完整注意力。
