## 2.4 Transformer

如 [Fig. 2.7](#ch2.xhtml#fig2_7) 所示，Vaswani 等人提出的主要 Transformer 结构基于前文描述的编码器-解码器架构。Transformer 将卷积神经网络 (`CNN`) 的并行计算优势与循环神经网络 (`RNN`) 的捕获长距离、变长序列信息的能力相结合。Transformer 架构中提出了许多系统性变化，下面的若干子节将逐一详细说明。

### 2.4.1 源表示和目标表示

源词和目标词都进行分词，分词后的 token 经过词嵌入和位置编码，得到所有句子的位置编码表示。

#### 2.4.1.1 词嵌入

标准的词嵌入查找可以将句子长度为 *l* 的句子转换为维度为 (*l*, *d*) 的矩阵 **W**，即 **W** ∈ ℝ^(*l* × *d_)。

#### 2.4.1.2 位置编码

词序和位置在大多数 NLP 任务中起关键作用。循环神经网络通过逐词处理本质上已经将词序纳入模型。在 Transformer 架构中，为加快速度并实现并行化，循环神经网络被多头注意力层取代，后文将详细说明。因此，必须显式将词序信息作为输入传递给模型层，以此方式捕获词序。这种词序信息的编码被称为位置编码。可以推导出多种有效位置编码的要求，具体包括：

1. 每个时间步（句子中的词）拥有唯一的编码值。

2. 跨不同长度句子的两个时间步之间的距离保持一致。

3. 编码结果对句子长度是泛化的、独立的。

4. 编码是确定性的。

实现上述所有要求的简朴方法是使用二进制表示。[Fig. 2.8](#ch2.xhtml#fig2_8) 展示了在维度为 3 的向量中，如何通过二进制值生成 8 个满足上述要求的位置编码。将每个比特表示为灰色（0）和白色（1），显示出每个位置的差异以及恒定的差值。使用二进制值在内存方面成本很高。

![Figure 2.8 维度为 3 的位置编码，对应 8 个位置。](images/fig2_8.jpg)

[Figure 2.8](#ch2.xhtml#b2fig2_8) 维度为 3 的位置编码，对应 8 个位置。

$$\\begin{array}{l} {\\mathbf{P}\_{i,2j} = \\sin(i/1000^{2j/d})} \\\\ \\end{array}$$  

(2.15)

$$\\begin{array}{l} {\\mathbf{P}\_{i,2j + 1} = \\cos(i/1000^{2j/d})} \\\\ \\end{array}$$  

(2.16)

### 2.4.2 注意力层

Transformer 中的基本构件是自注意力（self‑attention），在编码器和解码器中均有使用，只是在使用方式上略有差异。下面的子节将逐步构建注意力层，从最基础的自注意力开始。

#### 2.4.2.1 自注意力

要理解多头注意力，必须先拆解并理解其单头部分——自注意力。[Fig. 2.10](#ch2.xhtml#fig2_10) 展示了输入向量 **x**[*i*] 如何通过自注意力层转换为输出向量 **z**[*i*]。每个输入向量 **x**[*i*] 会生成三个不同的向量：查询（query）、键（key）和值（value），记作 (**q**[*i*], **k**[*i*], **v**[*i*])。查询、键、值向量通过对应的可学习权重矩阵 **W**[*q*]、 **W**[*k*]、 **W**[*v*] 对输入向量 **x**[*i*] 进行线性投影得到。这些权重矩阵在训练开始时随机初始化，随后在训练过程中联合学习。对于编码器和解码器的第一层注意力，输入是单词嵌入与位置编码之和。

![Figure 2.10 自注意力：输入向量映射为查询、键、值，并生成对应的输出向量。](images/fig2_10.jpg)

[Figure 2.10](#ch2.xhtml#b2fig2_10) 自注意力：输入向量映射为查询、键、值，并生成对应的输出向量。

与前文[章节 2.3](#ch2.xhtml#sec2_3) 讨论的查询、键、值的作用类似，自注意力的三个向量各自承担不同职责：

1. 查询向量 **q**[*i*] 的作用是将其与所有其他键向量的点积 $\\sum\_{j = 0}^{l}{\\mathbf{q}\_{i}\\mathbf{k}\_{j}\\ ^{T}}$ 聚合，从而影响其自身输出 **z**[*i*] 的权重。

2. 键向量 **k**[*i*] 的作用是与其他查询向量配对，计算相似度，并通过查询‑键乘积得分影响输出。

3. 值向量 **v**[*i*] 的作用是结合查询‑键得分的结果，提取相应信息，形成输出向量 **z**[*i*]。

下面的 [Fig. 2.11](#ch2.xhtml#fig2_11) 展示了每个 token 从输入到输出的完整计算流程。
