The expected time to add a new block in permission-less blockchains where any node can propose a new block is generally pre-determined in order to avoid problems that can be introduced by the latency in the network. In cryptocurrencies, this is generally determined by the block difficulty and it is updated to the network's block addition speed. Currently in Bitcoin, blockchain block difficulty is chosen so that a block is expected to be added to the blockchain every 10 minutes. Bitcoin's difficulty is recalculated in every 2016 blocks, which happens around 2 weeks. In Ethereum the difficulty is chosen so that a new block is added in 1 minute. Note that a change in the expected time for block addition would create a hard fork in the blockchain.

Bitcoin requires SHA-256 to be applied to a block to get a hash value with smaller than the current difficulty. Thus, miners aim to obtain a hash value starting with a lot of zero bits. In order to succeed, miners can change a 32-bit nonce value and fields in the coinbase transaction is used to award the miner for solving this hash puzzle. For example, a coinbase transaction can use the 256-bit previous transaction hash field as a nonce since a coinbase transaction has no previous transaction. Although finding a solution to the hash puzzle is hard, verifying a solution is fast which is what for the blockchain to function properly.

Initially, Bitcoin miners used CPUs and then moved to GPUs. However, today it is almost impossible to mine Bitcoin using CPUs, GPUs, or FPGAs because ASICs outperform these devices in Bitcoin mining. This is somewhat against the decentralization idea behind the Bitcoin only the nodes with special devices now have the control of the Network. For this reason, many cryptocurrencies tried to obtain hash that are ASIC-resistant. Initial designs like script [17] focused on puzzles that require a lot of memory which was assumed to slow down ASICs. Script requires the miner to store successive hash values in the memory. Litecoin is an example for a cryptocurrency that use script and it aimed for ASIC-resistance. However, many ASICs for script were produced in the past that outperform GPU miners. The requirement of script algorithm can be increased for ASIC-resistance but this would slow down the verification of the hash puzzle solution, rendering the blockchain unusable.

Another approach used in practice is to use different hash functions successively instead of a single hash function like Bitcoin's SHA-256 puzzle. Without a theory, this approach was assumed to be ASIC-resistant. In this respect, X11 is used by many cryptocurrencies which is successive of 11 hash algorithms which were in the SHA-3 competition. Similarly, X16 algorithm uses 16 different hash functions making it harder for ASIC designing efficient hardware.

Having a hash function that is ASIC resistant is also necessary for password hashing. Because slowing down password hashing also slows down brute force password breaking attacks. Many previous password hashing solutions are ad hoc methods and there were no dedicated designs for password hashing. Password Hashing Competition (PHC) ran from 2013 to 2015. This competition received 2 candidates and the winner was Argon2. However, other candidates like Lyra2 and its variants received by cryptocurrency designers and they are used in hash puzzles of various cryptocurrencies.

# Cryptographic Foundations

In its proof-of-work algorithm ethash, Ethereum uses Keccak but it should be noted that it is slightly different from the standardized version of Keccak, namely SHA-3. A late change in the standardization process of SHA-3 resulted in a different padding than the one used in ethash. Thus, sometimes the hash algorithms in ethash are referred to as Keccak-256 and Keccak-512, instead of SHA-256 and SHA-512.

The difference between the proof-of-work algorithms of Ethereum and Bitcoin is not the used hash algorithm. Ethash is based on Dagger-Hashimoto in order to be a memory-hard algorithm. Ethash generates 16-MB pseudorandom code from a seed that can be obtained from the previous block headers. Light nodes only store this chain. However, full nodes and miners generate 1-GB data set from each. The dataset size increases linearly with time. This dataset is actually a directed acyclic graph (DAG) which is created every epoch (currently every 30000 blocks). At the beginning of 2021, ethash DAG exceeded 4 GB, preventing older GPUs and ASICs from continuing mining.

In all of hash puzzles considered so far the aim of the miners is to obtain a hash value that starts with many zero bits. Therefore, hash functions used in the hash puzzle must be preimage resistant. Since only the first bits of the hash value are fixed to zero, we actually need a hash function that is near-preimage resistant (i.e only some of the hash output are fixed). Therefore, an adversary that has a fast method to obtain small hash values can dominate the blockchain. Solving the hash puzzles faster than the rest of the network would give the adversary the complete control of the blockchain. So far no near-preimage attacks are discovered for the hash functions that are standardized or used in hash puzzles.

# 13.4 Public-Key Cryptography

In public-key encryption and digital signature algorithms, users generate private and public key pairs. In a blockchain, public-key cryptography provides authentication via digital signatures. It can be used to verify that the person signing the transaction transfers value to another person has the private key. Thus, transactions are digitally signed by private keys and signatures can be verified by the public keys. Moreover, public keys are used as identities.

Public-key cryptography provides different algorithms for encryption, key exchange, and digital signatures. The security of these algorithms depends on the intractability of some mathematical problems like discrete logarithm or integer factorization:

**Definition 2 (Integer Factorization Problem):** Let $p, q$ in $\mathbb{Z}^+$. Given $n = pq$, finding $q$ or $p$ is called the IFP (integer factorization problem). Note that it is easy to compute $n$ when one knows $p$ and $q$ but known algorithms to find prime numbers require much more linearly time. Security of the RSA public-key encryption algorithm depends on the intractability of this problem. The best-known factorization algorithms show that in order to reach 128-bit security, one needs 3072-bit RSA modulus $n$.

**Definition 3 (Group):** A group $G$ in algebra is a set of elements together with a binary operation that combines two elements in $G$ and produces a third element in $G$ satisfying associativity, identity element, and inverse element group axioms. In a group $a(bc) = (ab)c$

there is an identity element, and every element has an inverse with respect to the group operation. A group has many points when it is considered in R or C. For an odd prime p > 3, an elliptic curve over finite fields Fp is defined by y² = x³ + ax + b where 4a³ + 27b² ≠0 (mod p). The set E(Fp) consists of all points (x, y) where x, y ∈ Fp satisfying the elliptic curve equation and a special point O called the infinity as an identity element.

**Definition 4 (Discrete Logarithm Problem):** Let $g$ be a generator of a group. Given $b = g^a$, finding $a$ is the discrete logarithm problem (DLP). The tractability of DLP depends on the group G. In additive groups, a is represented as ag. Similarly, in multiplicative groups, a is represented as g^a.

The addition of two points Q and P on the elliptic curve provides the output R where addition is defined by drawing the line that passes through P and Q and taking the negative of the y-coordinate of the third point where this line intersects the elliptic curve.

**Definition 5 (Elliptic Curve Discrete Logarithm Problem):** Let E be an elliptic curve over a finite field Fq. Let N be the order of the group E(Fq) and P ∈ E(Fq). Given j = ord(P) and Q ∈ <P>, finding the unique m ∈ {0, 1, 2, ..., j-1} such that Q = mP is the elliptic curve discrete logarithm problem (ECDLP). This problem becomes even harder if we use the points of an elliptic curve as the elements of group G. This is ECDLP.

Digital signature algorithm (DSA) and its elliptic curve analogue ECDSA (elliptic curve digital signature algorithm) are used mostly for signing transactions.
