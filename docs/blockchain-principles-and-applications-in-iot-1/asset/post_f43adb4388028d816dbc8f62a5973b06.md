
# Cryptographic Foundations

DSA Signing:

- 1. Randomly choose $k$ per message $m$ where $0 < k < q$
- 2. Calculate $s = k^{-1}(H(m) + xr) \mod q$ where $r = (g^k \mod p) \mod q$

The signature is the pair $(r, s)$.

DSA Verification:

- 1. Calculate $v = (g^{u1}y^{u2} \mod p)$ where $u2 = rw \text{ mod } q, u1 = H(m)w \text{ mod } q$, and $w = s^{-1} \mod q$ 

If $r = v$, then the signature is verified.

The security of the digital signature algorithm also depends on DLP. Unlike the ordinary DLP and IFP, subexponential-time algorithm is found so far for ECDLP. Thus, algorithms using elliptic curves have greater strength-per-key-bit and therefore signatures using elliptic curves result in shorter keys. Note that the Bitcoin uses ECDSA. Known attacks on the ECDLP force us to carefully select the elliptic curve parameters:

- 1. To avoid the Pohlig-Hellman [19] attacks and Pollard's Rho [20,21] attacks, j should be a large prime of at least 224 bits because they have a time complexity of $O(\sqrt{j})$.

- 2. The MOV [22] and Frey-Ruck [23] attacks reduce the ECDLP on $E(F_q)$ to the DLP in $F_t$, where $t = q^l$ using a Weil pairing $E[l]$. When $\gcd(l, q) = 1$, this reduction is polynomial in terms of the number of operations in $F_t$. To avoid the MOV attack, $j$ should not divide $q^i - 1$ for $1 \le i \le C$ where $C=20$ is sufficient. This required property of $j$ cannot be obtained when the curve is supersingular.

- 3. When $q$ is prime, the elliptic curves whose trace of Frobenius $t$ is $1$ and $q=N$ are called anomalous curves. These curves resist the MOV attack. However, using $q$-adic logarithm [24] or considering the $q$-primary part of the subgroup generated by $P[26]$, one can gain a linear time method to solve the ECDLP. To avoid these attacks, N should be different from $q$.

Known techniques like GHS' Weil Descent [27] can break ECDLP on elliptic curves faster than Pollard's Rho method but it was shown in [28] that this attack is ineffective against Koblitz curves which are elliptic curves defined over $F_2$ and for elliptic curves against NIST's recommended fields.

Therefore, in practice, we need non-anomalous ($i \neq q$) elliptic curves with group order divisible by a large prime of at least 224 bits. In practice an elliptic curve is selected randomly and kept if it satisfies these conditions. Determining the order of the group $E(F_q)$, which is also known as the point counting, is critical of importance in elliptic curve cryptography. Schoof's point counting algorithm [29,30] solves this problem efficiently. Although working with random curves is not as efficient as working with special curves like Koblitz curves [31], it is practical. Therefore, it is a natural question to ask if the ECDLP is equally hard for every elliptic curve over a finite field having the same number of points. This problem is answered in terms of random self-reducibility.

Bitcoin uses the elliptic curve $y^2 = x^3 + 7$ over $F_p = 2^{256} - 2^{32} - 2^9 - 2^7 - 2^1$ for ECDSA. This curve is called $secp256k1$ and the same curve with the same / private keys can be used by other algorithms like Schnorr signatures [5] also on the reliability of DLP. Bitcoin only supports ECDSA. However, Taprot fork is expected to happen in November 2021, will will provide support for Schnorr signatures.

Unlike DSA, ECDSA allows us to choose many elliptic curves with the same number of points on them. Thus, a natural question arises: Does the DLP equally hard for elliptic curves that have the same number of points? This question is older than Bitcoin in cryptography, a common practice is to use random curves. Thus, cryptographers wondered if it is possible to come across weak elliptic curve. In the case of Bitcoin, if $secp256k1$ is a weak curve for which DLP is easy to solve. In [32], it is shown that almost all elliptic curves over the same finite field having the same number of points have same density of discrete logarithm by showing polynomial self-reducibility among others. For a fixed $N$ and $m$, elliptic curves that are isomorphic to one in imaginary quadratic field have the vertices of an isogeny graph and prime degree between them less than $m$. The polynomial time self-reducibility of the ECDLP is achieved by navigating this isogeny graph. If there are polynomial amount of weak curves over the same finite field having the same number of points can be solved by transferring ECDLP for strong curve. Thus, it is reasonable to assume that Bitcoin elliptic curve $secp256k1$ is secure as any elliptic curve over same finite field having same number of points. Moreover, NIST announced that they are going to include more elliptic curves to their portfolio [33].

Although Schnorr signatures were invented in 1990, they expired in 2008. Bitcoin was not as popular as ECDSA, which was widely used and tested. Bitcoin did not support Schnorr signatures at the beginning and now a soft fork is required to add a new cryptography. This soft fork for Bitcoin called Taprot is scheduled for November 2021.

The main advantage of Schnorr signatures against ECDSA or DSA is signature aggregation. Bitcoin and most blockchains allow multi-signature, which provides transactions that are signed by multiple parties. A multisig transaction is signed by $n$ parties contains $n$ public keys which increases the transaction size and the computation required for the verification of the transaction. However, Schnorr public key can be aggregated [7] so that $n$ parties that are going to sign a transaction can combine their public key to form a single public key. Thus a verifier must only check that all of $n$ parties signed the message. Therefore, it is expected to have smaller transaction sizes resulting in fee savings because it makes impossible to distinguish single signature from multisig spends when the transaction requires transferring assets from more than one previous transaction.

In [6], unlike DSA signatures, Schnorr signatures do not rely on collision-resistant hash functions which allows smaller signatures with the same amount of security.

Randomness plays a very important role in DSA, ECDSA, and Schnorr Signature Algorithm. We require random numbers for key generation and every signature. Thus a strong random number generator (RNG) is a must for security of these algorithms. Using a weak random number generator might result in predictable secret keys during the key generation step. Moreover, we need random numbers for every signature and these numbers must be secret and different. Because, if the attacker knows the number $k$ that is randomly selected during the signing step, they can easily extract the secret $x$ from the signature $(r, s)$.

Random numbers generated for signing must also be distinct. When signing two different transactions allows an attacker to capture this $k$ and consequently obtain the secret $x$. In the past, some Bitcoin users used the same $k$ for two different transactions due to a bug in the JavaSecureRandom class on Android and attackers stole their Bitcoins by obtaining secret keys from these transactions.

Many devices like those of modern systems-on-chip (SoCs) have a dedicated hardware RNG peripheral. However, incorrectly failing the hardware RNG might result in non-random numbers because sometimes the hardware runs out of entropy, the produced random numbers might have low entropy. Thus, using the entropy generated from the hardware RNG as a random number might result in weak uses. Using CSPRNG (cryptographically secure pseudorandom number generator) on top of the entropy source of IoT devices can prevent this kind of problems.

One way to keep a private secret is to use PBKDF. Another cryptographic way to secure the private key is to use threshold schemes like Shamir's Secret Sharing Scheme [3]. We call it a $(t, n)$-threshold scheme when $t$ out of $n$ parties can combine their shares. This user can keep their shares in different devices so that it stays secure when the number of compromised devices is less than $t$. This scheme uses the polynomial interpolation idea which allows to construct a $t-1$ degree polynomial when $t$ points are on it. Although this looks like a multi-signature scheme where $t=n$, we have $n$ different public/private key pairs. Here, $n$ shares of a single secret are distributed among $n$ parties.

# 13.5 Post-Quantum Cryptography

Development of a large quantum computer would solve ECDLP, DLP, and IFP on a quantum computer in polynomial-time [8]. Public key cryptography algorithms whose security depends on the tractability of these problems would easily be broken if such a quantum computer is built. This includes leakage of every blockchain user secret key that uses DSA, ECDSA, or Schnorr signature. Thus, we need quantum algorithms for public key cryptography. For this reason, NIST is currently organizing a Post-Quantum Cryptography Competition.
