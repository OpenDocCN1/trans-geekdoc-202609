- 1. Preimage Resistance: When the output $y$ is known, finding an input $x$ such that $h(x) = y$ should be infeasible.
- 2. Second Preimage Resistance: When an input $x_1$ and the output $y$ is known where $h(x_1) = y$, finding $x_2$ such that $h(x_2) = y$, where $x_1 \neq x_2$, should be infeasible.
- 3. Collision Resistance: Without any condition on the output $y$, finding any different $x_1$ and $x_2$ such that $h(x_1) = y$ and $h(x_2) = y$ should be infeasible.

Although it is not included in the definition, the message digest appears random. This property is necessary for hash puzzles. For an n-bit message digest size, a brute force collision attack would require $2^{n/2}$ hash calculations due to the birthday paradox. However, brute force attacks for finding a preimage or a second preimage require around $2^{n/2}$ hash calculations. Although collision resistance and second preimage resistance look similar, an input is fixed in second preimage resistance which makes it harder for the attacker. However, using a hash function that is not collision resistant is suggested as it reduces the trust in the digest. Moreover, attacks get better and a collision might lead to a second preimage attack in the future.

Many hash functions like MD4, MD5, RIPEMD, SHA-2, and SHA-1 use Merkle-Damgard construction to convert a collision-resistant one hash function. As shown in Figure 13.1, firstly a padding is added to the input $M$ in Merkle-Damgard construction and then it is divided into $t$ blocks $M_i$. At the $i$-th step, the compression function $f$ produces $h_i$, from the inputs $h_{i-1}$ and $M_i$. An initialization vector (IV) is used as $h_0$. A finalization function is generally applied to the final output $h_t$ to produce the message digest.

It was shown MD4 and MD5, which are designed by Rivest, are not collision resistant and many collisions can be produced in milliseconds. However, these designs influenced many hash functions like SHA-2, RIPEMD, and SHA-1.

SHA-1 was developed by NSA in 1993 and a small modification was made in 1995 with a single bitwise rotation added. The initial version was generally referred to as SHA-0. SHA-1 has a block size of 512 bits and a message digest size of 160 bits. It has 80 rounds and its type is Merkle-Damgard. Although a theoretical collision attack on SHA-1 was provided in [2] as early as 2004, or in 2017 that a practical collision was obtained [4]. Note that a collision attack on a hash function only affects scenarios where collision resistance is required. However, chosen-prefix collisions on SHA-1 are provided in [3]. This new attack is more threatening for real protocols because it allows building two messages with arbitrary prefixes that have the same hash value. As an example, the authors of [3] provided a PGP/GnuPG attack. This should be avoided at all costs.

RIPEMD-160 hash function [16] is also a Merkle-Damgard construction. It has a block size of 512 bits and consists of 80 steps. One step of RIPEMD-160 is 32-bit provided in Figure 13.2 where $K[i]$ represents round constants and $X[i]$ represents a 32-bit part of the message block. RIPEMD-160 is a good candidate for applications where small SHA-1 and small hash sizes are not being broken. Moreover, unlike SHA-1, RIPEMD-160 was designed by academians.

SHA-2 was designed by NSA and first published in 2001. The digest length can be 224, 256, 384, or 512 bits, depending on the message digest. Generally, this number is used with the algorithm name. For example, SHA-256 is SHA-2 with 256-bit digest size. The number of rounds is either 64 or 80, which also depends on the message digest. It is a Merkle-Damgard-type hash function. The design is similar to its predecessors SHA-1, MD5, and MD4.

Although SHA-2 is not broken, its predecessors SHA-1, MD5, and MD4 are broken. For this reason, NIST (National Institute of Standards and Technology) announced a SHA-3 Competition that took place between 2007 and 2012. This competition received 64 submissions and the winner KECCAK became SHA-3. Its digest sizes are the same as SHA-2 to allow transition from SHA-2 to SHA-3 if necessary. The block sizes are 1,152, 1,088, 832, and 576 bits corresponding to 224, 256, 384, and 512-bit digest sizes. The number of rounds is 64 or 80. Unlike SHA-2, it is a sponge construction. Sponge functions have relatively large internal states and a permutation that modifies this internal state at each step. A small part of the state is used for producing output.

It is a common mistake to indicate that a hash function can be anything or its input space is infinite because designs generally limit the input size by 2n bits. However, such a limit allows 2 to the power of $2^n$ different inputs, which is virtually infinite.

Cryptographic hash functions have many different use cases in a blockchain network such as address derivation, securing the block header, securing block data, creating identifiers, and creating cryptographic puzzles.

Currently, the Bitcoin script allows the use of three hash functions: SHA-1, SHA-256, and RIPEMD-160. In a blockchain, users sign transactions by their private key and their public key. To shorten the size of these identities, their hashes are used most of the time. Once, a transaction needs to be verified, a node checks if the provided public key is capable of generating second preimages that claim a transaction belongs to a public key pk1;一样 belongs to the public key pk2 because $h(pk1)=h(pk2)$. However, this is not a problem for the blockchain's security because the attacker that find a pk2 would not be able to obtain the private key that corresponds to pk2, the adversary would be able to sign transactions by impersonating pk1.

Since it is vital to keep private key secret, many cryptocurrencies use password-based key functions (PBKDF) where the user-selected password is hashed many times to obtain a secret key for symmetric encryption algorithm like AES. This key is used to encrypt the private key. The users must choose passwords and provide them when they want to make a transaction.
