Randomness plays a very important role in DSA, ECDSA, and Schnorr Signature Algorithm. We require random numbers for key generation and every signature. Thus, a strong random number generator (RNG) is a must for security of these algorithms. Using a weak random number generator might result in predictable secret keys during the key generation step. Moreover, we need random numbers for every signature and these numbers must be secret and different. Because, if the attacker knows the number $k$ that is randomly selected during the signing step, they can easily extract the secret $x$ from the signature $(r, s)$.

Random numbers generated for signing must also be distinct. When signing two different transactions allows an attacker to capture this $k$ and consequently obtain the secret $x$. In the past, some Bitcoin users used the same $k$ for two different transactions due to a bug in the JavaSecureRandom class on Android and attackers stole their Bitcoins by obtaining secret keys from these transactions.

Many devices like those of modern IoT systems-on-chip (SoCs) have a dedicated hardware RNG peripheral. However, incorrectly failing the hardware RNG might result in non-random numbers because sometimes the hardware runs out of entropy, the produced random numbers might have low entropy. Thus, using the entropy generated from the hardware RNG as a random number might result in weak uses. Using CSPRNG (cryptographically secure pseudorandom number generator) on top of the entropy source of IoT devices can prevent this kind of problems.

One way to keep a private secret is to use PBKDF. Another cryptographic way to secure the private key is to use threshold schemes like Shamir's Secret Sharing Scheme [3]. We call it a $(t, n)$-threshold scheme when $t$ out of $n$ parties can combine their shares. This user can keep their shares in different devices so that it stays secure when the number of compromised devices is less than $t$. This scheme uses the polynomial interpolation idea which allows to construct a $t-1$ degree polynomial when $t$ points are on it. Although this looks like a multi-signature scheme where $t=n$, in we have $n$ different public/private key pairs. Here, $n$ shares of a single secret are distributed among $n$ parties.

# 13.5 Post-Quantum Cryptography

Development of a large quantum computer would solve ECDLP, DLP, and IFP on a quantum computer in polynomial-time [8]. Public key cryptography algorithms whose security depends on the tractability of these problems would easily be broken if such a quantum computer is built. This includes leakage of every blockchain user secret key that uses DSA, ECDSA, or Schnorr signature. Thus, we need quantum algorithms for public key cryptography. For this reason, NIST is currently organizing a Post-Quantum Cryptography Competition.
