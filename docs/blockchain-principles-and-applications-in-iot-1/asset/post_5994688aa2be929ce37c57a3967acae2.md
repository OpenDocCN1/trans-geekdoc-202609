## 1.8.1.1 Block Header

### 1.8.1.1 Header hash

A header hash is used to recognize the block with a cryptographic digest method and it is also used as an input variable. Each entire node computes a new block when it is received. Then it stores it in a separate database as part of the block metadata.

### 1.8.1.1.2 Height

The blocks are added to the chain in a chronological order. Using this order, one number is issued to each new block [35]. The height is the difference between the numbers of the last and first blocks. In this case, a fork in the chain happens.

### 1.8.1.1.3 Hash of the previous block

The previous block's hash is given in the header to allow the block to connect to the one before it.

### 1.8.1.1.4 Nonce

A nonce is an integer value to adjust the header hash's output. The header hash starts with a series of 0's, the miner will iterate the nonce until it meets its requirement. When completed, the process of nodes gets a new block. They will only calculate the header hash once to determine if the nonce is valid.

### 1.8.1.1.5 Difficulty

A difficulty is partial hash collision problem, which means that a hash algorithm always outputs the same assimilate for a given input. If a bit from this input is changed, the resulting hash output will be completely dissimilar. As a result, a hash that fulfills this partial collision is dependent on the mining node's processing capability. The collision is created by a mechanism called the nonce.

### 1.8.1.1.6 Transaction

Transactions are the records of data in the block. A value transfer is referred to as a transaction. It's a collection of inputs and outputs in a nutshell. A node distributes a transaction to all of its neighbors after making it [36]. The nodes that receive the action pass it on to their neighbors, and so on, until it reaches every node in the network.

### 1.8.1.1.7 Merkle trees

A Merkle tree is also often called a binary hash tree. It is one of complete binary tree with a bit value at each node. An inner node's value is a one-way function of the values of its children.

## 1.8.4 Consensus Mechanism

When nodes start sharing data via a blockchain platform, they lack a centralized unit to regulate and resolve all the problems, as well to maintain the flow of cash and assure a secure exchange to prevent the fraud, such as double spending assaults. To maintain a consistent state, all nodes should agree on a common update procedure for the ledger, and blocks should not be allowed into the blockchain without majority permission. This is known as a consensus mechanism because it involves creating new blocks and adding them to the existing ledger for future use. In the case of bitcoin, recipients may justify the outputs numerous times for use in subsequent transactions with signature verification because they appear genuine to individual recipients.

## 1.9 Privacy and Security Requirements

The security and privacy of any information system are critical requirements. We use concepts like integrity, availability, and confidentiality to describe safety. To ensure security, most people utilize a mix of authentication, authorization, and identification.

- Integrity: It's the guarantee that hasn't been changed by anyone other than those with the right to do so. Integrity ensures that transactions on the blockchain remain immutable. Integrity is routinely verified using cryptographic processes.
- Availability: It ensures system users have access to it whenever they need it. In other words, when a legitimate user wants the service, it is always available, which means the communication infrastructure and database. The block-chain achieves this purpose by allowing users to communicate with one another and store blocks in a distributed manner.
- Confidentiality: It ensures that unapproved individuals do not gain access to all the information. That is, only with the necessary rights and obligations will be able to access the data, whether it is being processed or transported. To ensure this concept, the blockchain makes use of pseudo-anonymization technologies such as hash functions, which hide the identity of users.
- Authorization, Authentication, and Auditing: This tries to identify the person who is performing a function in a system, as well as determine privileges that person has and track their usage statistics. The blockchain's structure ensures all three purposes because only users with private keys can make transactions, and all transactions are public and auditable.
- Non-Repudiation: It assures that no one can deny the operation of a system. Non-Repudiation proves that a user did something specific, give money, authorize a transaction, or send a communication. A user can't claim he didn't do something because all transactions are signed.
