Blocks in a blockchain are identified by block headers. Headers generally contain metadata about the block and the hash of the transactions included in this block which provides integrity without the use of signatures. For example, a Bitcoin block header contains a 4-byte version, 32-byte Merkle root, 32-byte previous hash, 4-byte difficulty target of the cryptographic puzzle, 4-byte timestamp, and the 4-byte nonce is used by the miner that mined that block.

Since the block header contains the hash of the block, an attacker that is capable of computing 굉장히 speeds might gather different set of transactions that would lead to the same hash and claim that transactions are the correct ones. Moreover, a strong adversary can focus on a single transaction, instead of the whole block. Forging a transaction that hashes to a transaction value that appeared in a previous block can cause confusion among the nodes.

Blocks like Bitcoin use Merkle Trees as a tree structure for verification of transactions in a block. In a Merkle Tree, hash of the transaction are the leaf-levels of the tree and pairs of hashes are hashed to obtain parents upwards until the root hash is obtained. If an attacker forges a transaction that has the same hash with another that is recorded in the block and before in the Merkle Tree, a full blockchain node that every transaction can realize that the forged transaction is a second image of transaction they recorded. However, Simplified Payment Verification (SPV) do not store every transaction and they may verify the forged transaction since its hash eventually reaches to the Merkle root. Therefore, it is vital to have a second preimage resistant hash in a blockchain to secure the transactions and the blocks.
