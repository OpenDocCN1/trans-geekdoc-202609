
区块链是完全去中心化的，因此不受中心机构的治理。由于缺乏中心机构，目前许多区块链需要代币（区块链加密货币）来鼓励和奖励其用户。引入代币的目标之一是建立对区块链网络的信任。因为数据一旦经过验证并上传到区块链，几乎无法修改或修订，所以公有链上的数据是安全的。以太坊和比特币是两个广为人知的公有链示例。

## 9.2.2 私有区块链

私有区块链是运行在封闭网络中的许可链区块链。许可链区块链是一个只有少数特定人员可以访问的私有网络。与无许可区块链相比，许可链的优势在于它们为区块链提供了访问控制。参与该区块链的参与者所执行的交易对世界上其他地方保持保密。当信息被认为敏感、不宜向公众共享时，这些区块链经常被企业内部使用。在这些类型的区块链上验证交易之前，你必须首先获得该区块链中心机构的授权。Hyperledger Fabric 和 Ripple 都是私有区块链的示例。

## 9.2.3 联盟链区块链

联盟链是一种半去中心化的区块链类型，其区块链网络由多个组织管理。在这种区块链中，一个以上的组织可以作为节点，进行信息交换或挖矿。银行、政府机构和其他机构经常采用联盟链。Energy Web Foundation、R3 以及其他联盟链都是其示例。

## 9.3 Hyperledger Fabric

Linux基金会构建了 Hyperledger Fabric，这是一项开源技术。Hyperledger Fabric 设计用于作为构建模块化产品和解决方案的基础（Hyperledger Fabric – Hyperledger, n.d.）。它是一个用于建立和管理模块化且可扩展的许可区块链的解决方案 [2]。该平台将被大量利用以满足我们对许可区块链的需求。这是一个简单的平台，具有各种模块和功能，可以直接利用，而无需在应用程序中重新实现它们。因此，此类功能可以轻松地复用，当前的功能也可以轻松集成。它还允许我们指定具有完全不同权限和功能的网络参与者。

## 9.3.1 Hyperledger Fabric 架构

Hyperledger Fabric 架构相比普通的无许可区块链，包含了一些额外的节点和组件。Hyperledger Fabric 由一个模块化架构组成，即每个组件都是可插的。Fabric 网络由如图所示的组件和节点组成，下面提供了作为 Hyperledger Fabric 架构部分的每个组件和节点的简要说明（图 9.3）。

### 9.3.1.1 成员服务 (Membership Service Service)

成员服务将为要在区块链上进行交易的用户提供身份概念。这种身份将是一个数字证书，用户将使用此数字证书对其交易进行签名并提交到区块链。签名此类交易的好处是向区块链验证该用户是合法用户，并确保用户对其在网络上执行的交易拥有正确的访问权限。数字证书由证书颁发机构提供。证书颁发机构或默认的 Fabric 证书颁发机构是一个可插模块，可以是任何外部证书颁发机构或默认的 Fabric 证书颁发机构。这一切都使用了基于公钥的基础设施。

### 9.3.2 Fabric SDK

SDK 用于与区块链网络交互，提供 NodeJS、Python 和 Java 等多种语言。我们可以使用这些任何一个 SDK 在区块链上执行交易。

### 9.3.3 背书节点 (Endorsing Peer)

背书节点执行提议的交易但不更新账本。背书节点收集在交易执行期间写入和读取的数据元素。这些在执行期间被读取和写入的数据元素被称为 RW 集，然后背书者对它们进行数字签名并发送回客户端应用程序。

背书节点也可以是提交节点，也可以仅是背书节点。背书节点必须持有链码，但它可能也可能没有账本。

### 9.3.1.4 提交节点 (Committing Peer)

提交节点在验证区块中的交易后，将从排序器接收到的区块提交到其账本中。一旦 commit 验证了收到的区块中的所有交易，该区块就会被添加到提交节点的账本中，并根据交易中收到的写入集（Write Set）更新世界状态。提交节点也可以是背书者，即它可以拥有智能合约。

### 9.3.1.5 排序节点 (Ordering Peer)

排序节点的主要功能是接收经过背书的交易并将它们排序成一个区块。这些排序后的区块由排序节点交付给提交节点。排序服务的主要功能是为节点提供一组完全排序的交易。排序服务本身是去中心化的，可能由许多节点组成。这些节点不拥有智能合约和账本。

### 9.3.2 链码 (Chaincodes)

链码基本上是 Hyperledger 中的智能合约。它们在满足其中写的特定条件时执行。链码用 Go、node.js 或 Java 等多种语言编写。链码部署在背书节点上，一旦部署，就可以通过交易进行调用，并通过交易更新账本状态。
