

# PAKE 的 UC 安全性要求

Canetti 等人 (2005) 所示的 UC PAKE 协议是 Katz–Ostrovsky–Yung (KOY) 协议 (Katz 等人, 2001) 的一种修改版，后者是首个被证明在标准模型下 BPR 安全的 PAKE 协议（参见 [第 10.6 节](#c10.xhtml#sec10-6)）。Canetti 等人 (2005) 提出的 KOY 的 UC 安全版本在 *A* 的最后一条消息中增加了第二个密文 `cpa`，该密文加密相同的密码 `pw^A`，以及一个模拟可靠的零知识证明，证明密文 `cpa` 和 `c[A]` 加密的是同一个值（参见 [图 10.5](#c10.xhtml#c10-fig-5) 中的 KOY 协议）。这一额外流程的意义乍看之下并不明确。然而，UC 安全 PAKE 往往比 BPR 安全 PAKE 代价更高，主要有以下两个原因：

1.  **输入提取**：在 UC PAKE 证明中，模拟器 `S*` 需要从攻击者的消息中（直线式地）提取出攻击者在该会话中测试的唯一密码 `pw*`。（这源于通用的 UC 安全框架，其中真实世界攻击者的任何动作都必须由 `S*` 转化为对理想功能的唯一输入。）在 BPR 模型中，不存在此要求，且许多在 BPR 模型下安全的 PAKE 似乎不支持这种提取。
2.  **模拟“被成功攻击”的参与方**：在 UC PAKE 证明模拟器中，`S*` 必须在所有情况下正确模拟真实世界的视图，包括攻击者的密码猜测 `pw*` 与诚实会话密码 `pw` 匹配的情况。在 BPR 模型中，这种事件会结束安全游戏，因此模拟器能否高效计算被攻击方输出的会话密钥并不重要。确实，Canetti 等人 (2005) 添加到 KOY 协议中那个神秘的“密码重加密 + NIZK”步骤的好处在于，它允许在模拟会话已被攻击且模拟器必须计算真实世界被攻击方将输出的会话密钥这一确切情况下进行高效模拟。

在标准计算模型中，目前已知的最优 UC PAKE 与 BPR 模型 PAKE 之间存在效率/假设上的差距（参见 [第 10.6 节](#c10.xhtml#sec10-6)），而在 ROM 中，这些效率差异已被弥合 (Abdalla 等人, 2020; McQuoid 等人, 2020)（参见 [第 10.7 节](#c10.xhtml#sec10-7)）。然而，我们应注意到，UC 安全 PAKE 与任何非平凡的 UC 功能一样，只能存在于公共参考串 (CRS) 模型中 (Canetti, 2001)，而 BPR 安全 PAKE 则是在没有任何公共信任假设的情况下构建的 (Goldreich 和 Lindell, 2001; Nguyen 和 Vadhan, 2004; Barak 等人, 2005; Goyal 等人, 2010)，尽管具体成本高得多（参见 [第 10.6 节](#c10.xhtml#sec10-6)）。

# 与 BMP 模型的差异

BMP 安全模型可被视为上述范式在 PAKE 协议情况下的一种特化（参见 [第 10.4.2 节](#c10.xhtml#sec10-4-2)）。然而，Canetti 等人 (2005) 做出了一些定义选择，使其 UC PAKE 概念与 Boyko 等人 (2000) 的 BMP 模型有所区别。这些差异可概括如下（对比请见 [第 10.4.1 节](#c10.xhtml#sec10-4-1) 中的“理想世界游戏”段落）：

- 参与方通过命令 (`NewSession`, `sid`, `P`, `P'`, `pw`, `role`) 启动，其中 `P`, `P'`, `pw`, `role` 与 BMP 模型中的含义相同，即参与方的身份、预期对端身份、密码以及参与方在协议中扮演的发起方/响应方角色。然而，在 UC PAKE 模型中有一个新的输入元素，即*会话标识符* `sid`，假定它是*全局唯一*的，除了打算相互运行 PAKE 的两方之外。与 BMP 一样，除 `pw` 外的所有输入均假定为非秘密，因此 `F_Pake` 将它们发送给 `S*`。
- 理想世界对手只能为 `fresh` 会话发送 `TestPwd` 命令，特别是不能为处于悬空状态终止的会话发送。
- `NewKey` 规则与 BMP 中的相同，不同之处在于：两个会话 `Psid` 和 `P'sid'` 建立相同的密钥，仅当除了满足 BMP 模型标准（即两个会话均为 `fresh`，`P = P'` 且 `P' = P`）外，还满足 `sid` = `sid'`。

与 BMP 模型一样，对手可以为每个会话设置输入 `pw` 并接收输出 `sk`，但在 UC 框架中这是隐含的，因为环境 `Z` 确定每个参与方的输入并观察其输出，且由于 UC 安全性意味着对于任意环境 `Z` 和对手 `A`，真实世界游戏与理想世界游戏不可区分，所有这些值均可无损一般性地传递给 `A` 并从 `A` 获取。确实，无损一般性地可以认为 `A` 是 `Z` 的子过程，因此在安全性证明中可将它们视为同一实体，正如在 BMP 模型中那样。

# UC PAKE 模型的放宽

上述建模决策造成了与 BMP 模型的两个独立差异：首先，运行 PAKE 的参与方必须首先建立一个匹配的全局唯一标识符 `sid`。其次，主动攻击中的密码测试必须在被攻击会话终止前完成。如果每次 PAKE 交互之前都有一个随机数交换，将 `sid` 定义为这些随机数的拼接，则可满足第一个要求。不过，这会给协议增加一个额外流程（第二个随机数可搭载在第一个 PAKE 流程上）。第二个要求意味着模拟器 `S*` 必须在会话 `Psid` 终止前，有效提取主动攻击者 `A` 对该会话实际使用的密码猜测 `pw*`，这排除了像 Boyko 等人 (2000) 的 PPK 这样的协议（参见 [图 10.4](#c10.xhtml#c10-fig-4)），其协议消息的分布独立于密码，且 `S*` 可以从对手对 `H'` 的哈希查询中提取对手使用的密码 `pw*`，而这些查询可能在参与方 `Psid` 终止后发生。

这两种建模均可放宽，以允许轮数更少、效率更高的协议。尽管 UC 框架 (Canetti, 2001) 要求每个协议实例有一个局部无歧义的指针，但这些指针无需对两个通信方相同，PAKE 功能 `F_Pake` 可被放宽为一种“机会主义约会”功能，允许对手连接任何具有匹配参与方标识符和相反角色的两个会话。甚至可以进一步移除 UC PAKE 参与方预先指定对端标识符的要求，并将参与方标识符和会话标识符均设为 PAKE 的输出。

Boyko 等人 (2000) 的会话终止后密码测试被 Abdalla 等人 (2020) 作为*惰性提取* UC PAKE 重新引入 UC 框架。除了匹配 `sid` 要求（Abdalla 等人, 2020）是沿用自 Canetti 等人 (2005) 之外，Abdalla 等人 (2020) 的惰性提取 UC PAKE 模型似乎等价于 BMP 模型。因此，[图 10.4](#c10.xhtml#c10-fig-4) 中的 PPK 在进行简单调整以强制满足 UC PAKE 匹配 `sid` 要求后，很可能是一个安全的惰性提取 UC PAKE。
