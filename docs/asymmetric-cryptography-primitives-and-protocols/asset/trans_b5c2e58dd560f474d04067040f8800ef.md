# 5.3. 指尖上的密码学协议新世界

离散对数问题引入了线性单向函数 ![image](images/f.jpg)[*a*] : *g* ![image](images/g.jpg)→ *g^a*；然而，在不明确给出秘密陷门 *a* 的情况下，无法检查两对输入和输出是否由同一函数生成。

得益于配对，给定两对输入和输出，现在可以在不泄露陷门的情况下检查它们是否由同一函数生成。给定 (*x*[1], *y*[1])，(*x*[2], *y*[2])，只需比较 *e*(*x*[1], *y*[2]) 和 *e*(*x*[2], *y*[1])，而无需显式知道离散对数。

这种额外的验证能力克服了*纯*基于离散对数构造的局限性，在后者中，在不知道秘密的情况下无法组合元素。

## 5.3.1. 简单易行的基于身份的加密

1984 年，A. Shamir 提出了基于身份的加密概念（见[第 7 章](#c07.xhtml)）。长达 17 年，构建这样一种方案一直是一个开放问题（至少在学术界）。

然而，在配对引入仅 1 年后，它们提供的额外“魔法步骤”使得 Boneh 和 Franklin（2001）得以实现该原语的实用实例化。他们简单地利用了配对允许组合三个元素这一事实：

– 映射到群中的身份哈希值，其离散对数未知（虽然存在，且仅在安全性分析中由模拟器知晓）；

– 一个封装（其离散对数仅由发送者知晓）；

– 一个主公钥（其离散对数由中心机构知晓）。

在[图 5.6](#c05.xhtml#c5-fig-6)中，我们展示了与 Boneh–Franklin 构造相关的基于身份的密钥封装机制（IBKEM）。要获得他们的基于身份的加密，只需将生成的密钥用作消息一次性出现的 nonce 即可。

![图 5.6. Boneh–Franklin 基于身份的密钥封装机制作为三方 Diffie–Hellman 交换的表示](images/fig5-6.jpg)

[**图 5.6.**](#c05.xhtml#rc5-fig-6) *Boneh–Franklin 基于身份的密钥封装机制作为三方 Diffie–Hellman 交换的表示*

当然，这样一个协议缺少一个关键参与者——用户。在这种情况下，他/她将从机构接收一个将其身份的哈希评估与秘密密钥混合的中间值：`usk[id]` = ![image](images/h.jpg)(`id`)^(*x*)。有趣的是，他可以通过检查以下等式来验证机构发送的值是否正确：*e*(`usk`[`id`], *g*) = *e*(![image](images/h.jpg)(`id`), `pk`)。

我们可以看到，任何外部人只能看到三个群元素，而不知道任何一个离散对数。这正是最初引入的三方 Diffie–Hellman 的设定，事后看来，由此得到后者进而导致此类基于身份方案的高效（且安全）构造，并不令人惊讶。

## 5.3.2. 高效确定性紧凑签名

在配对出现之前，大多数基于离散对数的方案都是 ElGamal 签名方案（ElGamal 1985）的变体。这些方案有两个主要缺点：签名由两个标量组成，且签名必须是概率性的。

然而，2001 年，Boneh 等人（2001）引入了一种额外紧凑的确定性签名，可在随机预言机模型下基于计算 Diffie–Hellman 假设被证明是安全的。

[图 5.7](#c05.xhtml#c5-fig-7) 回顾了 BLS 签名方案的构造。它非常接近 Boneh–Franklin IBKEM，其中用户的私钥现在是签名 *σ*，而验证包含在发送者侧对随机数 *r* = 1 进行正确的封装/解封装检查。由于从 IBE 到签名的 Naor 变换，这并不令人惊讶。

![图 5.7. Boneh–Lynn–Shacham 签名方案](images/fig5-7.jpg)

[**图 5.7.**](#c05.xhtml#rc5-fig-7) *Boneh–Lynn–Shacham 签名方案*

可以看出，签名的所有难点在于能否从 *g, g^x,* ![image](images/h.jpg)(*M*) 计算出 *σ*，换句话说，就是解决这个计算 Diffie–Hellman 问题的实例。

配对在此至关重要；一方面，它们允许在没有任何陷门的情况下公开验证签名；另一方面，因为它们是非退化的，它们确保如果等式成立，则提供的 *σ* 就是计算 Diffie–Hellman 挑战的解。
