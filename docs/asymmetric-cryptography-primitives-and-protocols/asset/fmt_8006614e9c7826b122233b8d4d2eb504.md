
#### 7.4.2.3. Chapter notes and history

– `KeyGen`(`msk`, `att`): `EncKey`(`att`) → `r` ← `Z_p`, `usk` = `g_2^r`. It outputs `usk`.

– `Dec`(`mpk`, `ct`, `usk`): Parse `ct` = (`[V]_1`, `[w]_1`, `P`) with `[w]_1 ∈ G_1`. `Decode`(`P`, `att`) → `d ∈ Z_p^2` which we write as `d = (d_ct, d_usk)` with `d_ct, d_usk ∈ Z_p`. It outputs `e([V]_1, d_ct) / e([w]_1, d_usk)`.

**Correctness**: Let `P` and `att` be such that `P`(`att`) = 1. The encryption `Enc`(`mpk`, `P`) outputs `ct` = (`[U_1 b s | ··· | U_n b s]_1`, `C`, `[b s]_1`, `P`) where `C = EncCt`(`P`). The user secret key generation `KeyGen`(`msk`, `att`) outputs `[a r]_2 [K]_2` where `K = EncKey`(`att`). Decryption computes `e([U_i b s]_1, [a r]_2) / e([b s]_1, [K]_2) = e([a]_1, [b s]_2)^r / e([b]_1, [s]_2)^r` where `α = k^⊤ b s`, `u[i] = (a r)^⊤ U[i] b s` and the last equality follows from the correctness of the predicate encoding.

**Security**: We show that the ABE is secure if DDH holds in `G_1` and `G_2`, and the predicate encoding is secure. Namely, we show that for all admissible PPT adversaries `A` making `q` user secret key queries, there exist PPT algorithms `B_1`, `B_2`, and a negligible function `ν` such that for all `λ ∈ N`, `Adv_A^ABE(λ) ≤ Adv_B1^DDH(λ) + Adv_B2^DDH(λ) + ν(λ)` denotes the ABE scheme above.

We proceed using a series of hybrid games, described below. For any `i ∈ [n]`, we denote by `Adv[i]` the probability (taken over the random coins of the adversary `A` and `Game[i]`) that `Game[i]` outputs 1 when interacting with the adversary `A`.

– `Game[0]`(`1^λ`): This is the game that corresponds to the security definition (see definition 7.3); thus, we have `Adv[0] = Adv_A^ABE(λ)`. For completeness, we describe the game here. It runs `Setup`(`λ`) → (`mpk`, `msk`) where `msk` = (`[k]_2`, `[a]_2`, `U_i`). It sends `mpk` to the adversary `A`. When `A` sends the query `att` to its oracle `O_KeyGen`, the game computes `[a r]_2 [K]_2` and returns `usk` to `A`. At some point, `A` sends a predicate `P`, upon which the game samples `b ←_R {0, 1}`, computes `Enc`(`msk`, `mpk`, `P`) → `ct` = (`[U_1 b s | ··· | U_n b s]_1`, `C`, `[b s]_1`, `P`), `kem` = `[k^⊤ b s]_T`. It sets `kem[0] = [k^⊤ b s]_T` and `kem[1] ←_R G_T`. It returns (`ct`, `kem[b]`) to `A`. At some point, `A` sends a guess `b'`, upon which the game ends and outputs 1 if `b' = b`, 0 otherwise.

– `Game[1]`(`1^λ`): This game is as `Game[0]`, except the challenge ciphertext is computed as follows (the differences with `Game[0]` are highlighted). Given `P`, it computes `[z]_1 ←_R G_1`. These games are computationally indistinguishable by the DDH assumption in `G_1`, which states that (`[b]_1`, `[b s]_1`) ≈_c (`[b]_1`, `[z]_1`) where `s ←_R Z_p`. Namely, there exists a PPT algorithm `B_1` such that `|Adv[1] - Adv[0]| ≤ Adv_B1^DDH(λ)`.

– `Game[2]`(`1^λ`): This game is as `Game[1]`, except the `mpk` and the challenge ciphertext are computed as follows (the differences with `Game[1]` are highlighted): `mpk` = (`[b]_1`, (`[U_i b]_1`)[i∈[n]], `[k^⊤ b]_T`), `ct` = (`[U_1 z | ··· | U_n z]_1`, `C`, `[z]_1`, `P`), `kem` = `[k^⊤ z]_T` where `(b | z) ←_R GL_2` as opposed to `b ←_R Z_p^2, z ←_R Z_p^2` in `Game[1]`. Recall that `GL_2` denotes the general linear group of degree 2, that is, the group of 2 by 2 non-singular matrices over `Z_p`. Since the probability over the random choices of `(b | z)` that `(b z)` is singular is less than `2/p`, these two games have statistical distance less than `2/p`.

– `Game[3]`(`1^λ`): This game is as `Game[2]`, except the challenge ciphertext and the user secret keys are computed as follows (the differences with `Game[2]` are highlighted): `[a]_2 ←_R G_2^2` with `a = a_∥ + α b^⊥`. `[a r]_2 [K]_2` where `b^⊥` is the vector such that `b^⊤ b^⊥ = 0` and `z^⊤ b^⊥ = 1`. `Game[3]` and `Game[2]` are identically distributed, which comes from the fact that the two following distributions are equal: `([a]_2, [a r]_2)` and `([a_∥ + α b^⊥]_2, [a_∥ r + α r b^⊥]_2)` where `b^⊥` is the vector such that `b^⊤ b^⊥ = 0` and `z^⊤ b^⊥ = 1`. There is a post-processing algorithm that given an input distributed according the first distribution, produces an output distributed as specified by `Game[2]`, whereas when given an input distributed according to the second distribution, the same post-processing algorithm produces an output distributed as specified by `Game[3]`. Namely, the post-processing algorithm, upon receiving its input, samples `r ←_R Z_p` and generates `A`'s view straightforwardly.

Finally, we show that the security in `Game[3]` reduces to the security of the *secret-key* variant of the ABE, as presented above. Namely, we build a reduction `B_3` such that `Adv[3] ≤ Adv_A^sk-ABE(λ)` where `sk-ABE` is the secret-key ABE obtained by transforming the predicate encoding (`EncCt`, `EncKey`, `Decode`) as described a few pages above (using the cyclic group `G_2`; see [Figure 7.2](#c07.xhtml#c7-fig-2)). In fact, the vectors `U_i` and the scalar `α ∈ Z_p` introduced in `Game[3]` (highlighted above) serve as a secret key of the scheme `sk-ABE`. We now proceed to describe `B_3`. It receives a public key `mpk` = `G_1` from its security game. It samples `(b | z) ←_R GL_2`, `k ←_R Z_p^2` and sends `mpk` = (`[b]_1`, (`[U_i b]_1`)[i∈[n]], `[k^⊤ b]_T`) to `A`. It computes `b^⊥` the vector such that `b^⊤ b^⊥ = 0` and `z^⊤ b^⊥ = 1`. Whenever `A` queries its oracle `O_KeyGen` on `att`, `B_3` queries its own oracle to get `[K]_2` where `K = EncKey`(`att`) are global parameters of `sk-ABE`, whereas `r ←_R Z_p` is sampled freshly for each `usk` generation, and `K = EncKey`(`att`). The reduction `B_3` sends `[a_∥ r + α r b^⊥]_2 [K]_2` to `A`, which it can compute since it knows the values (`U_i`)[i∈[n]] and `a_∥`. When `A` sends the challenge `P`, `B_3` forwards it to its own security game to receive `ct` = (`u[1] | ··· | u[n]`) `C` where `C = EncCt`(`P`) and `kem` = `[γ]_2`, where `γ = α` or `γ ←_R Z_p`, depending on the random bit chosen by the security game for `sk-ABE`. Then, `B_3` sends `[U_i z]_1` and `kem` = `[k^⊤ z + γ]_T`, which it can computes since it knows the values `k`, `b`, `z` and (`U_i`)[i∈[n]]. It is clear that the output generated by `B_3` corresponds to the view of `A` in `Game[3]`, and that its input is distributed according to the security game for the security of `sk-ABE`. Thus, we have `Adv[3] ≤ Adv_A^sk-ABE(λ)`. Finally, by the security of `sk-ABE`, proven a few pages above, we know there exists a PPT adversary `B_2` and a negligible function `ν` such that `Adv_A^sk-ABE(λ) ≤ Adv_B2^DDH(λ) + ν(λ)`. Overall, we get `Adv_A^ABE(λ) ≤ Adv_B1^DDH(λ) + Adv_B2^DDH(λ) + ν(λ) + 2/p`.
