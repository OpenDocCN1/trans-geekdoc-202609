
### Security

We show that the secret-key ABE is secure if DDH holds with respect to `GGen` and the predicate encoding is secure. Namely, we show that for all admissible PPT adversaries $\mathcal{A}$ making $q$ user secret key queries, there exists a PPT algorithm $\mathcal{B}$ and a negligible function $\nu(\lambda)$ such that for all $\lambda \in \mathbb{N}$, where $\Pi = (\text{Setup}, \text{Enc}, \text{KeyGen}, \text{Dec})$ denotes the ABE scheme above.

We proceed using a series of hybrid games, described below. For any $i \in [n]$, we denote by $\text{Adv}[i]$ the probability (taken over the random coins of the adversary $\mathcal{A}$ and $\text{Game}[i]$) that $\text{Game}[i]$ outputs 1 when interacting with the adversary $\mathcal{A}$.

*   **`Game[0](1^λ)`**: This is the game that corresponds to the security definition (see Definition 7.3); thus, we have $\text{Adv}[0] = \text{Adv}_{\Pi,\mathcal{A}}^{\text{ABE}}(\lambda)$. For completeness, we describe the game here. It runs $\text{Setup}(1^\lambda) \to (\text{mpk}, \text{msk})$ where $\text{msk} = (\mathbf{U}, \alpha, [\mathbf{a}], [\mathbf{Ua}])$ and $\text{mpk} = [\mathbf{G}_1]$. It sends $\text{mpk}$ to the adversary $\mathcal{A}$. When $\mathcal{A}$ sends the query $\text{att}$ to its oracle $\mathcal{O}_{\text{KeyGen}}$, the game computes $\text{KeyGen}(\text{msk}, \text{att}) \to \text{usk}$ and returns $\text{usk}$ to $\mathcal{A}$. At some point, $\mathcal{A}$ sends a predicate $P$, upon which the game samples $b \xleftarrow{R} \{0, 1\}$. It computes $\text{Enc}(\text{msk}, \text{mpk}, P) \to (\text{ct}, \text{kemb})$. It sets $\text{kemb}[0] = [\alpha]$ and $\text{kemb}[1] \xleftarrow{R} [\mathbf{G}_1]$. It returns $(\text{ct}, \text{kemb}[b])$ to $\mathcal{A}$. At some point, $\mathcal{A}$ sends a guess $b'$, upon which the game ends and outputs 1 if $b' = b$, 0 otherwise.

*   **`Game[i](1^λ)`**: This game is defined for all $i \in \{0, \dots, q\}$, where $q$ denotes the number of queries from $\mathcal{A}$ to its oracle $\mathcal{O}_{\text{KeyGen}}$. For the last $q - i$th queries to $\mathcal{O}_{\text{KeyGen}}$, `Game[i]` computes $\text{usk}$ exactly as for `Game[0]`. However, it answers the first $i$th queries as follows (the differences with `Game[0]` are highlighted). Given $\text{att} \in \{0, 1\}^s$, it computes $[\mathbf{U} \mathbf{r}]$.

Note that $\text{Adv}[q] = 0$, since in `Game[q]`, none of the user secret keys given to $\mathcal{A}$ depend on the secret value $\alpha \in \mathbb{Z}_p$. Thus, in this last game, both $\text{kemb}[0]$ and $\text{kemb}[1]$ are identically distributed, namely, uniformly random (independent from everything else). Thus, to conclude the security proof, we show that for all $i \in [q]$, there exists a PPT algorithm $\mathcal{B}[i]$ and a negligible function $\nu[i]$ such that $|\text{Adv}[i-1] - \text{Adv}[i]| \le \nu[i](\lambda)$.

To do so, we introduce intermediate games defined below for all $i \in [q]$.

*   **`Game[i-1.1](1^λ)`**: This game is as `Game[i-1]` except for the $i$th query to $\mathcal{O}_{\text{KeyGen}}$. This query is answered as follows (the differences with `Game[i-1]` are highlighted). Given $\text{att} \in \{0, 1\}^s$, it computes $[\mathbf{z}] \xleftarrow{R} [\mathbb{G}_1]^2$.
    This transition is justified by the DDH assumption, which states that the following are computationally indistinguishable: $([\mathbf{a}], [\mathbf{a}r]) \approx_c ([\mathbf{a}], [\mathbf{z}])$ where $\mathbf{a} \xleftarrow{R} \mathbb{Z}_p^2$ and $r \xleftarrow{R} \mathbb{Z}_p$. Namely, there exists a PPT algorithm $\mathcal{B}[i.1]$ such that $|\text{Adv}[i-1] - \text{Adv}[i-1.1]| \le \text{Adv}_{\mathcal{B}[i.1]}^{\text{DDH}}(\lambda)$.

*   **`Game[i-1.2](1^λ)`**: This game is as `Game[i-1.1]` except for the $i$th query to $\mathcal{O}_{\text{KeyGen}}$. This query is answered as follows (the differences with `Game[i-1.1]` are highlighted). Given $\text{att} \in \{0, 1\}^s$, it computes $\text{EncKey}(\text{att}) \to \mathbf{K}$, $\mathbf{z} \xleftarrow{R} \text{Span}(\mathbf{K})^\perp$.
    We show that the following are statistically close: $\text{Adv}[i-1.1] \approx_s \text{Adv}[i-1.2]$ with statistical distance $1/p$, using the security of the predicate encoding.

Write $\mathbf{C} = \text{EncCt}(P)$ and $\mathbf{K} = \text{EncKey}(\text{att})$, where $\text{att}$ is the $i$th query to $\mathcal{O}_{\text{KeyGen}}$. We have (difference from one distribution to the next one are highlighted):

The first approximation $\approx_s$ relies on the fact that with probability less than $2/p$ over the random choices $\mathbf{U} \xleftarrow{R} \mathbb{Z}_p^{2 \times 2}$, the matrix $\mathbf{U}^\top \mathbf{a}$ is non-singular. In that case, we can define $\mathbf{a}^\perp$ to be the vector such that $\mathbf{a}^\top \mathbf{a}^\perp = 0$ and $\mathbf{z}^\top \mathbf{a}^\perp = 1$. We denote $\text{GL}_2$ the set of non-singular 2 by 2 matrices over $\mathbb{Z}_p$ – equipped with matrix multiplication, this is a group called general linear group.

The first equality follows from the fact that for all $\mathbf{U} \in \text{GL}_2$, we have: $\{\mathbf{U} \xleftarrow{R} \mathbb{Z}_p^{2 \times 2} \mid \mathbf{U}^\top \mathbf{a} \in \text{GL}_2 \} \dots$

The last equality follows the security of the predicate encoding.

Then, note that `Game[i-1.2]` is the same as `Game[i]` except the $i$th query to $\mathcal{O}_{\text{KeyGen}}$ is answered using a vector $[\mathbf{z}] \xleftarrow{R} [\mathbb{G}_1]^2$ instead of $[\mathbf{a}r]$ with $r \xleftarrow{R} \mathbb{Z}_p$ in `Game[i]`. These games are computationally indistinguishable by the DDH assumption, which states that $([\mathbf{a}], [\mathbf{z}]) \approx_c ([\mathbf{a}], [\mathbf{a}r])$ where $\mathbf{a} \xleftarrow{R} \mathbb{Z}_p^2$. Namely, there exists a PPT algorithm $\mathcal{B}[i.2]$ such that $|\text{Adv}[i-1.2] - \text{Adv}[i]| \le \text{Adv}_{\mathcal{B}[i.2]}^{\text{DDH}}(\lambda)$.

This completes the proof that `Game[i-1]` is computationally indistinguishable from `Game[i]`. The security bound is obtained by summing up the differences $\text{Adv}[i-1] - \text{Adv}[i]$ for all $i \in [q]$.

#### 7.4.2.2. From secret-key ABE to ABE

Here, we show how to compile a secret-key ABE into an ABE. The underlying secret-key ABE is only apparent in the security proof. Namely, the security of the ABE will boil down to the use of a computational assumption on the ciphertext space, and the security of the secret-key variant of the ABE. The construction itself relies only on a predicate encoding.

Let $s$ be a polynomial and $\mathcal{P} = \{P_\lambda\}_{\lambda \in \mathbb{N}}$ be a family of predicates. Assume there exists a PPT algorithm `PGGen` such that for all $\lambda \in \mathbb{N}$, `PGGen`$(1^\lambda)$ outputs groups $\mathbb{G}_{1,\lambda}$, $\mathbb{G}_{2,\lambda}$, $\mathbb{G}_{T,\lambda}$ of prime order $p[\lambda]$, equipped with a non-degenerate bilinear map $e_\lambda : \mathbb{G}_{1,\lambda} \times \mathbb{G}_{2,\lambda} \to \mathbb{G}_{T,\lambda}$ such that the DDH assumption holds in both $\mathbb{G}_{1,\lambda}$, $\mathbb{G}_{2,\lambda}$. Assume there exist polynomials $|\text{ct}|$, $|\text{usk}|$, $n$ such that for all $\lambda \in \mathbb{N}$, there exists a predicate encoding $(\text{EncCt}_\lambda, \text{EncKey}_\lambda, \text{Decode}_\lambda)$ with respect to $(p[\lambda], |\text{ct}|(\lambda), |\text{usk}|(\lambda), n(\lambda), P_\lambda)$. Then, the construction presented below is a secure ABE. Note that to keep notations light, we do not explicitly write the dependency on $\lambda$ from here on. As explained above, to prove security, we rely on the security of the secret-key variant of the ABE. We describe informally the transformation from the secret-key ABE to the ABE in [Figure 7.3](#c07.xhtml#c7-fig-3).

![Figure 7.3. Transformation from secret-key ABE to ABE. Here, C = EncCt(P) for a predicate P and K = EncKey(att) for attribute att ∈ {0, 1}^s](images/fig7-3.jpg)

**Figure 7.3.** Transformation from secret-key ABE to ABE. Here, $\mathbf{C} = \text{EncCt}(P)$ for a predicate $P$ and $\mathbf{K} = \text{EncKey}(\text{att})$ for attribute $\text{att} \in \{0, 1\}^s$.

*   **`Setup(1^λ)`**: Samples $\mathbf{b}_1 \xleftarrow{R} \mathbb{G}_1^2$ of order $p$, for all $i \in [n]$, $\mathbf{U}_i \xleftarrow{R} \mathbb{Z}_p^{2 \times 2}$, $([\mathbf{U}_i \mathbf{b}_1])_{i \in [n]}$, $[\mathbf{k}^\top \mathbf{b}_1]_T$. It outputs $(\text{mpk}, \text{msk})$.

*   **`Enc(mpk, P)`**: $\text{EncCt}(P) \to \mathbf{C} \in \mathbb{Z}_p^{n \times 2}$. Computes $([\mathbf{U}_1 \mathbf{b}_1 s | \dots | \mathbf{U}_n \mathbf{b}_1 s]^\top \mathbf{C}, [\mathbf{b}_1 s]_1, P)$, $\text{kemb} = [\mathbf{k}^\top \mathbf{b}_1 s]_T \in \mathbb{G}_T$. It outputs $(\text{ct}, \text{kemb})$.
