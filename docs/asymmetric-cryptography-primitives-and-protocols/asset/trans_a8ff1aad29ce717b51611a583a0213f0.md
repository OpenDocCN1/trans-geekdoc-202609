

Bellare等人（2000）对EKE2的安全性分析假设在DH密钥交换中使用的群〈*g*〉上存在一个理想密码（IC）`E`。可以在〈*g*〉上实现一个*随机化*的IC `E`，即`E`(*k, m*) = `E`′(*k, ξ*(*m*))，其中`E`′是{0, 1}^(*n*)上的IC，而*ξ* : 〈*g*〉 → {0, 1}^(*n*)是一个随机化可逆编码，它是*均匀*的，意思是{*ξ*(*m*)}[*m*←[$]〈*g*〉]在统计上接近于一个均匀的*n*位比特串。这样的随机化IC在定理10.1的证明中就足够了：一个从密文*c*中提取(*k, m*′)的模拟器，使得*m*′ = `D`′(*k, c*)，可以计算*m* = *ξ*^(−1)(*m*′)，这满足*m* = `D`(*k, c*)，并且它可以通过将*ξ*(*m*)嵌入`D`′(*k, c*)中，将*m* ∈ 〈*g*〉嵌入`D`(*k, c*)中。因此，〈*g*〉上均匀随机化可逆编码的存在意味着在随机预言机模型（ROM）中是安全的，因为比特串上的IC可以使用Feistel网络从随机预言机构造而成（Holenstein等人，2011；Dachman-Soled等人，2016；Dai和Steinberger，2016）。在〈*g*〉 = ![image](images/zsp.jpg)（素数*p*）这一特殊情况下，即〈*g*〉是整数区间\[1, *..., p* 1\]，当*n ← |p|* + *κ*时，这种编码很容易构造：*ξ*(*m*)选取*r* ←[$] \[2^(*n*)/*p*\]并输出*m*′ = *m* + *rp*（在整数上），而*ξ*^(−1)(*m*′)输出*m* = (*m*′ mod *p*)。然而，对于椭圆曲线群，这样的编码并非显而易见。

在出现这种椭圆曲线编码之前，Black和Rogaway（2002）展示了在任意群![image](images/g1.jpg)上实现IC `E`′的期望常数时间方法，该群在{0, 1}^(*n*)上是*稠密*的，即如果![image](images/g1.jpg)的元素可以编码为*n*位比特串，使得|![image](images/g1.jpg)|*/*2^(*n*)是一个常数，给定*n*位比特串上的IC `E`。在该构造中，对于*m* ∈ ![image](images/g1.jpg)，`E`′(*k, m*)定义*c*[0] = `E`(*k, m*)和*c*[*i*+1] = `E`(*k, c[i]*)对所有*i* ≥ 0成立，并设置`E`′(*k, m*) = *c[i]*，其中*i*使得*c[i]*是序列*c*[1], *..., c[i]*中第一个属于![image](images/g1.jpg)的元素。解密在反方向实现相同的过程，即它对`D`(*k, ·*)进行递归，直到找到![image](images/g1.jpg)中的一个元素。该方法的一个弱点是时序信息会泄露加密方/解密方应用`E`(*k, ·*)或`D`(*k, ·*)的次数，如果*k* = *pw*，这将泄露关于密码的信息，因为对于任何密码猜测*pw*^∗，对手都可以看到从给定密文*c*到达![image](images/g1.jpg)中的一个元素需要多少次`D`(*pw*^∗, ·)操作。

Bernstein等人（2013）为一类椭圆曲线群构造了一个均匀编码，称为*Elligator2*，它适用于群中一半的元素。具体来说，Elligator2将*ξ* : G^′ → \[0, *...,* (*q* 1)*/*2\]映射为椭圆曲线群![image](images/g1.jpg)（阶为*q*）的子域![image](images/g1.jpg)^′，使得![image](images/g1.jpg)^′ = (*q*+1)*/*2。（由于\[0, *...,* (*q* − 1)*/*2\]是一个整数区间，Elligator2将与上述整数区间编码组合使用。）然而，由于Elligator2仅适用于一半的域，每一方都必须重新采样其DH密钥交换贡献，直到找到![image](images/g1.jpg)′中的一个元素，这是次优的，因为预计需要2次迭代。Tibouchi（2014）；Kim和Tibouchi（2015）为更大一类椭圆曲线群展示了均匀编码，称为*Elligator-squared*，它适用于完整域〈*g*〉。其解码*ξ*^(−1)的成本与Elligator2解码相似，但编码*ξ*需要采样和测试原像点，并且似乎大约贵三倍（取决于曲线）。此外，Elligator-squared将EC点编码为一对域元素，因此比Elligator2多使用2倍的带宽。或者，可以应用Holenstein等人（2011）；Dachman-Soled等人（2016）；Dai和Steinberger（2016）的结果，使用“混合”Feistel在群〈*g*〉上构造随机化IC，其中一条线保存群元素，该线上的XOR被群运算替代，而作用于该线上的轮哈希函数是作用于〈*g*〉上的RO不可区分哈希。（这些Feistel结果的证明似乎可以推广到这种情况。）使用Dachman-Soled等人（2016）的8轮Feistel，这将在加密和解密中各产生四次哈希到群操作，但McQuoid等人（2020）显著优化了该设计，表明两轮混合Feistel，因此单次哈希到群操作，实现了一种足以满足EKE2的“一次性”IC形式。

## 10.4. 基于模拟的PAKE安全模型

Boyko–MacKenzie–Patel（BMP）PAKE安全模型（Boyko等人，2000）与Bellare–Pointcheval–Rogaway（BPR）模型（Bellare等人，2000）同年出现，后者在[第10.3节](#c10.xhtml#sec10-3)中已概述。这里我们将解释BMP模型并将其与BPR模型进行对比。

### 10.4.1. BMP安全模型

PAKE的BMP安全模型借鉴了Bellare–Canetti–Krawczyk的AKE协议模型（Bellare等人，1998），及其由Shoup（1999）所做的改进。这些模型遵循*基于模拟*的安全定义范式，该范式此前曾用于建模安全多方计算（MPC）（例如Beaver，1991；Micali和Rogaway，1992；Canetti，2000；参见[第4章](#c04.xhtml)）。基于模拟的范式考虑两个安全游戏，涉及两类对手。第一个游戏称为*真实世界*游戏，是对手![image](images/a.jpg)与运行协议Π的诚实参与方之间的交互。第二个游戏称为*理想世界*游戏，是一个称为*理想世界对手*的算法![image](images/a.jpg)^∗与理想化系统（记为![image](images/f.jpg)，代表*功能*）之间的交互，该系统根据定义除了方案功能所必需的信息外，不向对手泄露任何信息。如果对于所有有效的真实世界对手![image](images/a.jpg)，都存在一个有效的理想世界对手![image](images/a.jpg)^∗（也称为*模拟器*），使得这两个游戏产生不可区分的视图，则该方案被定义为安全的，其中两种情况下的“视图”都定义为对手的输出（不失一般性地包括其完整交互记录）与所有诚实参与方输出的联合分布。这一概念捕捉了方案Π的安全性，因为它意味着对手![image](images/a.jpg)在与运行Π的诚实参与方交互时能做的一切（这“一切”包括![image](images/a.jpg)学到的一切，即其交互记录，以及![image](images/a.jpg)导致诚实参与方做的一切，即它们的输出），也可以由模拟器![image](images/a.jpg)^∗在与理想系统![image](images/f.jpg)交互时完成。^()

*真实世界游戏*：让我们首先描述BMP模型中的真实世界游戏，它捕捉了对手![image](images/a.jpg)与运行PAKE协议多项式多个实例的诚实参与方（`P`[1]*,...,* `P`[*n*]）之间的交互。这种交互类似于BPR安全游戏，就像在那里一样，假设对手![image](images/a.jpg)完全控制所有诚实参与方之间的网络。然而，与BPR安全游戏不同，这里没有定义“攻破”该协议的事件，也没有对手必须预测的挑战比特*b*。^()
