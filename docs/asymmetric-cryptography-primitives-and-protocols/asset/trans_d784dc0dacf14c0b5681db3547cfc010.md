

## 2. b) 计算乘法门

我们再次将门的输入线上的多项式表示为 `a(x)` 和 `b(x)`。与加法门类似，第 `i` 个参与方可以在本地相乘其份额来定义 `c(i) = a(i) * b(i)`。根据多项式乘法的性质，这定义了一个多项式 `c(x)`，使得 `c(0) = a(0) * b(0)`。因此，`c(x)` 是正确值（即输入线上值的乘积）的一个共享。然而，`c(x)` 是 2`t` 次的，因此这是一个 (2`t`+1)-out-of-`n` 秘密共享，而不是 (`t`+1)-out-of-`n` 秘密共享。因此，为了完成乘法门的计算，参与方有必要执行一个*降度*步骤，在不改变其在 0 处的值的情况下，安全地将参与方间共享的多项式的次数从 2`t` 降低到 `t`。在继续描述此步骤之前，请注意，由于 `t < n/2`，`n` 个参与方持有的份额完全决定了 2`t` + 1 次的多项式 `c(x)`。

为了计算降度步骤，我们使用了 Damgård 和 Nielsen (2007) 的一个基本思想（尽管他们实现它的方法比我们在此描述的要高效得多）。假设所有参与方都持有未知随机值 `r` 的两个独立秘密共享，第一个共享通过一个记为 `R[2t](x)` 的 2`t` 次多项式，第二个共享通过一个记为 `R[t](x)` 的 `t` 次多项式。注意 `R[2t](0) = R[t](0) = r`。然后，每个参与方可以通过设置 `d(i) = c(i) - R[2t](i)` 在本地计算其关于 2`t` 次多项式 `d(x) = c(x) - R[2t](x)` 的份额。注意 `c(x)` 和 `R[2t](x)` 都是 2`t` 次的。接下来，参与方通过将其所有份额发送给所有其他参与方来重构 `d(0) = a(0) · b(0) - r`。最后，对于所有 `i = 1,...,n` 的第 `i` 个参与方通过计算 `c'(i) = R[t](i) + d(0)` 来计算其在输出线上的份额。

观察到 `c'(x)` 是 `t` 次的，因为 `R[t](x)` 是 `t` 次的，并且它是通过向 `R[t](x)` 添加一个常数 `d(0)` 来定义的。接下来，`c'(0) = a(0) · b(0)`，因为 `R[t](0) = r` 且 `d(0) = a(0) · b(0) - r`；因此在求和时 `r` 抵消了。因此，正如所要求的，参与方持有输入线上值的乘积的一个有效的 (`t` + 1)-out-of-`n` 秘密共享。此外，请注意，向所有参与方揭示的值 `d(0)` 不会泄露任何信息，因为 `R[t](x)` 完美地掩盖了 `c(x)` 的所有值，特别是它掩盖了值 `a(0) · b(0)`。

剩下的问题是如何让参与方生成未知随机值 `r` 的两个独立秘密共享，分别通过 2`t` 次和 `t` 次多项式。这可以通过第 `i` 个参与方（对于所有 `i = 1,..., n`）扮演分发者，通过一个 2`t` 次多项式和一个 `t` 次多项式来共享一个随机值 `r[i]` 来实现。然后，在从每个参与方接收到此类份额后，对于所有 `i = 1,...,n` 的第 `i` 个参与方通过计算接收到的份额之和来定义其 `R[2t](x)` 和 `R[t](x)` 的份额。由于所有参与方都贡献了秘密随机值 `r[1],..., r[n]`，因此没有任何参与方知道 `r`。

### 3) 输出重构

一旦参与方获得了输出线上的份额，他们就可以通过简单地将份额发送给彼此并通过插值重构输出来获得输出。请注意，如果需要，不同的参与方也可以获得不同的输出。在这种情况下，参与方仅将用于重构的份额发送给应该在给定线上获得输出的相关参与方。

只要被破坏的参与方少于 `n/2` 个，上述协议对*半诚实对手*是安全的。这是因为参与方在计算过程中看到的唯一值是秘密份额（它们不泄露所隐藏值的任何信息）和打开的 `d(0)` 值，由于每次使用独立的随机共享，这些值不泄露线上实际值的任何信息。请注意，为了在*恶意对手*（他们可能偏离协议规范）存在的情况下实现安全性，有必要利用不同的方法来防止作弊。有关如何高效实现针对恶意对手安全性的几个示例，请参见 Beerliová-Trubíniová and Hirt (2008); Chida et al. (2018); Furukawa and Lindell (2019)。

## 4.4.3. 私有集合求交

在 [第 4.4.2 节](#c04.xhtml#sec4-4-2) 中，我们描述了一种*通用*安全计算的方法，可用于安全地计算任何函数。在许多情况下，这些通用方法实际上被证明是最高效的（尤其是在考虑恶意对手时）。然而，在某些情况下，所求解函数的特定结构使我们能够找到更快、量身定制的解决方案。在本节和下一节中，我们将展示两个此类函数的示例。

在私有集合求交协议中，两个拥有私有值集合的参与方希望找到这些集合的交集，而不泄露交集中的元素之外的任何信息。在某些情况下，可能只需要交集的某个函数，例如仅其大小。关于这个问题已经有大量工作，涵盖针对半诚实和恶意对手的安全性，以及不同的效率目标（轮数少、通信量低、计算量低等）。在本节中，我们将描述 Kolesnikov 等人 (2016) 协议背后的思想；实际协议要复杂得多，但我们展示了其构建背后概念上简单的思想。

伪随机函数 `F` 是一个带密钥的函数，其性质是该函数在已知输入上的输出看起来完全随机。因此，对于任何给定的元素列表 `x[1],..., x[n]`，值序列 `F[k](x[1]),..., F[k](x[n])` 看起来是随机的。特别地，给定 `F[k](x[i])`，无法确定 `x[i]` 的值。在以下简单协议中，我们利用了一个称为*遗忘伪随机函数求值*的工具。这是一种特定类型的 MPC 协议，其中第一个参与方输入 `k`，第二个参与方输入 `x`，第二个参与方接收 `F[k](x)`，而第一个参与方不获得关于 `x` 的任何信息（注意第二个参与方学习 `F[k](x)` 但不获得除此以外的任何信息；特别地，`k` 保持秘密）。这样的原语可以用多种方式构建，我们将不在此描述它们。

现在，考虑两个拥有各自私有元素集合的参与方；分别将它们表示为 `x[1],..., x[n]` 和 `y[1],..., y[n]`（为简单起见，我们假设它们的列表大小相同，尽管这不是必需的）。然后，协议按如下方式进行：

1.  第一个参与方为伪随机函数选择一个密钥 `k`。
2.  两个参与方运行 `n` 次遗忘伪随机函数求值：在第 `i` 次执行中，第一个参与方输入 `k`，第二个参与方输入 `y[i]`。结果，第二个参与方学习 `F[k](y[1]),..., F[k](y[n])`，而第一个参与方不获得关于 `y[1],..., y[n]` 的任何信息。
3.  第一个参与方在本地计算 `F[k](x[1]),..., F[k](x[n])` 并将列表发送给第二个参与方。它可以计算这个，因为它知道 `k`。
4.  第二个参与方计算列表 `F[k](y[1]),..., F[k](y[n])` 和 `F[k](x[1]),..., F[k](x[n])` 之间的交集，并输出所有使得 `F[k](y[j])` 在交集中的值 `y[j]`。（该参与方知道这些值，因为它知道 `y[j]` 和 `F[k](y[j])` 之间的关联。）
