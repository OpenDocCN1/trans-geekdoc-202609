

## 9.3.3 从 KEM 构建认证密钥交换

正如 [9.2 节](#c09.xhtml#sec9-2) 所讨论的，KEM 可用作未认证密钥交换协议。有几种已知方法可向被动安全的密钥交换协议添加认证，以将其转换为 AKE 协议。也许最简单的方法是在 [图 9.2](#c09.xhtml#c9-fig-2) 的协议消息中添加签名。通过 Bellare 等人 (1998) 和 Canetti 与 Krawczyk (2001) 提出的*认证器*，可实现从未认证协议到 AKE 协议的通用转换。将其基于签名的认证器应用于 [图 9.2](#c09.xhtml#c9-fig-2) 中的协议，可得到 [图 9.4](#c09.xhtml#c9-fig-4) 所示的协议构造。双方对原始未认证协议中交换的消息提供签名。Canetti 和 Krawczyk (2001) 的通用定理保证了在其模型中的安全性。

尽管 [图 9.4](#c09.xhtml#c9-fig-4) 中的协议因其简洁性和灵活性而具有吸引力，但源自通用认证器的此类协议也有其局限性。一是需要额外的消息流，因此无法实现具有相互认证的两消息协议。第二个局限性是独立应用认证的协议无法达到最高安全级别，因为它们必然不安全于能够获取临时密钥的对手。（然而请注意，该方法始终能实现前向保密，因为长期密钥仅用于认证。）

从 KEM 获取 AKE 的另一种替代方法是根本不使用签名，而是以另一种方式进行认证。一个有吸引力的选项是除使用带有临时密钥的 KEM 外，还使用带有长期密钥的 KEM。Fujioka 等人 (2012) 提供了一种遵循此方法的通用 AKE 构造，如 [图 9.5](#c09.xhtml#c9-fig-5) 所示。我们将此协议称为 FSXY 协议。在该描述中，KEM 封装中使用的随机性被显式展示，并按下文讨论的方式为 FSXY 协议进行特殊选择。

![Figure 9.4. Generic authenticated key exchange from signed KEMs](images/fig9-4.jpg)

[**图 9.4.**](#c09.xhtml#rc9-fig-4) *基于签名 KEM 的通用认证密钥交换*

这种通用方法的优势在于可应用不同的具体 KEM 构造，包括为后量子安全设计的构造。[图 9.5](#c09.xhtml#c9-fig-5) 中使用的两个 KEM 采用相同符号表示，但可以是相同的，也可以是不同的。KEM 的选择当然会影响协议的安全性和效率。Fujioka 等人 (2012) 在强安全模型 (Krawczyk 2005) 下提供了安全性证明，假设配合长期密钥使用的 KEM 是 CCA 安全的，而配合临时密钥使用的 KEM 是 CPA 安全的。他们给出了基于分解、编码和格的具体实例化。Hülsing 等人 (2021) 以 FSXY 协议为基础，构建了 WireGuard 协议的后量子版本。

### 9.3.3.3 NAXOS 技巧与扭曲 PRF 技巧

FSXY 协议中使用的随机性输入值 `r[A]` 和 `r[B]` 可以通过不同方式计算，包括像标准 KEM 用法那样简单地随机选择。另一种选择是通过组合长期秘密和临时秘密来计算这些值，这一想法源于 LaMacchia 等人 (2007) 的研究，他们在 NAXOS 协议设计中使用了它。这样做的原因是为了提供安全性，抵御能够获取临时秘密或长期秘密（但不能同时获取两者）的对手。这一想法已在多个后续协议设计中被复用，通常采用以下两种不同形式之一。

![Figure 9.5. Simplified protocol of Fujioka et al. (2012)](images/fig9-5.jpg)

[**图 9.5.**](#c09.xhtml#rc9-fig-5) *Fujioka 等人 (2012) 的简化协议*

- **NAXOS 技巧**：随机性值计算为 `H(e, l)`，其中 `e` 是临时秘密，`ℓ` 是长期秘密，`H` 是哈希函数。在 NAXOS 协议 (LaMacchia 等人, 2007) 中，`H` 被建模为随机预言机，且 `H(e, l)` 被用作 Diffie-Hellman 临时输入。

- **扭曲 PRF 技巧**：随机性值计算为 `F[e[1]](ℓ[1]) ⊕ F[l[2]](e[2])`，其中 `e[1]` 和 `e[2]` 是临时秘密，`l[1]` 和 `l[2]` 是长期秘密，`F` 是 PRF。Okamoto (2007) 首次使用了这一想法，其动机与 NAXOS 技巧相同，但避免了随机预言机模型，从而在标准模型中获得安全性。这就是 FSXY 协议中 `r[A]` 和 `r[B]` 值的计算方式。

### 9.3.3.4 HMQV：一种极高效的 AKE 协议

通用协议构造往往不如定制构造高效。已知最高效的 AKE 协议之一最初由 Menezes、Qu 和 Vanstone 于 1995 年在一个无正式论文集的会议上提出。他们的协议后来于 2005 年由 Krawczyk (2005) 改编为一个称为 HMQV 的版本，并具有归约式安全性证明。HMQV 协议的主要两消息版本如 [图 9.6](#c09.xhtml#c9-fig-6) 所示，采用 Diffie-Hellman KEM 的符号表示（定义 9.4）。Krawczyk 还提出了单消息和三消息的替代版本。

![Figure 9.6. HMQV protocol](images/fig9-6.jpg)

[**图 9.6.**](#c09.xhtml#rc9-fig-6) *HMQV 协议*

HMQV 协议消息与临时 Diffie-Hellman 相同，但会话密钥计算使用长期密钥和临时密钥的函数来计算共享秘密 `Z` = `g^((esk[A]+d·sk[A])(esk[B]+e·sk[B]))`。临时值 `d` 和 `e` 使用哈希函数 `H` 计算，其输出大小仅为 Diffie-Hellman 计算中使用的指数长度的一半。这导致该协议中每方大约使用 2.5 次指数运算即可实现认证密钥交换，相比之下，普通未认证 Diffie-Hellman 密钥交换使用 2 次指数运算。Krawczyk 在类似 CK 模型 (Canetti 和 Krawczyk, 2001) 的模型中提供了安全性证明，假设哈希函数 `H` 充当随机预言机。请注意，HMQV 仅实现弱前向保密，因为主动对手可自由选择 `esk[A]` 的有效输入，在 `B` 接受后，破坏 `A` 以获取 `sk^(A)` 并计算 `S[A]`，然后像 `A` 一样计算 `K`。

HMQV 协议刚发表时引起了争议，特别是关于其安全性证明是否可靠。争议很大程度上围绕是否需要*密钥验证*这一问题，即检查接收到的临时公钥 `epk^(A)` 和 `epk^(B)`，以及可能的长期公钥 `pk^(A)` 和 `pk^(B)`，是否在正确的 Diffie-Hellman 群中。取决于代数设定，密钥验证的成本可能高达一次额外的指数运算。是否需要密钥验证取决于所需的安全级别，但要达到较高安全级别可能需要它 (Menezes 和 Ustaoglu, 2006)。HMQV 论文完整版 (Krawczyk, 2005b) 的前言讨论了这一情况。

如何将 HMQV 协议推广到其他代数设定并不明显。Zhang 等人 (2015) 的一项协议以 HMQV 为基础，构建了格设定下的 AKE 协议，旨在实现后量子安全。然而，他们并不声称达到相同的安全级别，具体而言是不允许对手获取会话状态。此外，其单消息变体已遭受攻击 (Gong 和 Zhao, 2017)。
