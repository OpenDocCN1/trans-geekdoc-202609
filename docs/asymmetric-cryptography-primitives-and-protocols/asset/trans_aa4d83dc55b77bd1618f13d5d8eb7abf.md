

# IND-CCA安全PKE的通用构造

迄今为止，我们描述和列举的仅是*标准模型*中的PKE方案。另一种通常能产生非常高效的IND-CCA安全PKE的流行方法，是在*随机预言机模型*（RO）（Bellare和Rogaway 1993）中构造方案。随机预言机是以预言机形式提供的均匀随机函数。在RO模型中，方案中使用的哈希函数在安全性证明中被随机预言机替代。缺点是，随机预言机模型方法仅具有启发式性质，且通常不合理（例如（Canetti等人 1998））。RO模型中PKE的一个例子是RSA-OAEP方案（Bellare和Rogaway 1995），该方案在RO模型下基于RSA假设被证明是IND-CCA安全的（Fujisaki等人 2001）。另一个例子是所谓的DHIES方案（Abdalla等人 2001），其在RO模型下的IND-CCA安全性可归约到所谓的gap-DH假设（Okamoto和Pointcheval 2001a），即即使对手拥有解决DDH问题的预言机，CDH假设依然成立。还有一个值得一提的方案是ElGamal的一个变体，称为Twin ElGamal（Cash等人 2008），它在RO模型下基于CDH假设是IND-CCA安全的，并且像原始ElGamal PKE一样拥有非常紧凑的密文。事实上，DHIES和Twin ElGamal都具有混合加密的结构（参见[第1.3.1节](#c01.xhtml#sec1-3-1)）。

此外，我们还拥有更多“通用”的构造，它们可以将基础方案（通常满足某种弱安全形式，如IND-CPA或CPA下的单向性）通用地转换为在RO模型下达到IND-CCA安全的方案。（事实上，RSA-OAEP就属于此类，它是通过将OAEP变换应用于RSA加密方案而获得的。）我们将在[第1.3.3节](#c01.xhtml#sec1-3-3)中涉及它们。

## 1.3. IND-CCA安全PKE的通用构造

上一节描述了一些基于具体数学假设的*特定*PKE方案。本节描述基于通用密码学原语的*通用*IND-CCA安全PKE构造。

### 1.3.1. 混合加密

通常，公钥密码学的计算量级比对称密钥密码学重且慢得多。*混合加密*是一种实用技术，旨在尽可能兼顾PKE的功能性和SKE的高效性。具体而言，要加密一条（长）消息，我们仅用PKE方案加密一个随机的、固定长度的“会话”密钥`K`，而实际要发送的消息则使用密钥`K`通过SKE进行加密。Cramer和Shoup（2003）为混合加密（也称为KEM/DEM框架）引入了现代处理方式和形式化，其中加密随机会话密钥`K`的过程被形式化为一个称为*密钥封装机制（KEM）*的专用原语。

在本节中，我们回顾混合加密的现代处理方式。具体来说，我们回顾KEM和SKE的形式化，然后回顾文献中混合加密的构造及相关结果。

对于KEM，IND-CCA安全性和IND-CPA安全性的定义方式与PKE非常相似。本质区别仅在于：在KEM的安全性实验中，对手不再选择两个挑战明文，而是被给予挑战密文`c*`以及一个真实的会话密钥`K*`（与`c*`一起生成）或一个完全随机的会话密钥`K'`，并被要求区分这两种情况。

其中`D`是确定性算法，`K`表示密钥，`c`表示明文`m`在密钥`K`下的密文。与PKE和KEM一样，`D`允许输出特殊的无效符号⊥。在此语法中，密钥`K`的长度决定了安全参数。通常，SKE方案也可能有专门的密钥生成算法，但为简化起见，此处不考虑此类语法。

在一般情况下考虑SKE的安全性时，我们需要考虑拥有加密预言机访问权限的对手，因为与PKE情况不同，对手无法自行生成密文。另一方面，对于此处混合加密语境下的SKE，我们只要求“一次性”加密，因为混合加密将仅在每次加密时使用一个全新的会话密钥进行单次加密。回想一下，PKE的安全概念已经以挑战密文`c*`的形式提供了一次加密（参见[图1.1](#c01.xhtml#c1-fig-1)）。因此，“一次性”SKE的安全概念可以精确地定义为PKE的安全概念，唯一的例外是作为输入给对手的公钥`pk`变为空。我们将由此从PKE的IND-CCA（分别IND-CPA）安全性导出的SKE安全概念称为*IND-OT-CCA安全性*（分别*IND-OT安全性*），其中OT代表“一次性加密”。

值得一提的是，构造IND-OT和IND-OT-CCA安全的SKE方案相对直接。所谓的“伪随机一次性密码本”方案（即将密钥定义为伪随机生成器以随机输入为输出的一次性密码本方案）是IND-OT安全SKE的一个例子。类似地，任何强伪随机排列（Luby和Rackoff 1988）都可视为IND-OT-CCA安全的SKE方案，其中通过将消息输入排列来进行加密。注意，理论上，这样的排列可以从任何单向函数构造（Håstad等人 1999；Luby和Rackoff 1988）。从这两个例子可知，IND-OT-CCA和IND-OT安全的SKE均可通过加密算法为确定性且密文开销（即密文大小与待加密明文大小的差值）为零的加密方案来实现。
