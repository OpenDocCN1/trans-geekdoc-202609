
## 2. 2) Sample a random point `s` ←[$] `F`^(*μ*), compute `q` ← `p`(`s`) and return `q`. For simplicity, we assume that `q` always contains an entry 1; this way we do not have to distinguish between affine and linear (adversarial) prover strategies. The query answers are computed as `a` = Π · `q`.

– `D`(`q`, `x`, `a`) ∈ {0, 1}: The deterministic decision algorithm outputs 1 (accept) or 0 (reject) and consists of two steps:

1.  1) Run `t`[1](`z`),..., `t`[η](`z`) ← `Test`(`R`, `x`) to obtain η polynomials {`t[i]` : `F`^(*m*+*k*) → `F`}[*i*] of degree ≤ `d`[D];
2.  2) Return 1 if and only if ∀*i* ∈ [*η*] : `t[i]`(`q`, `a`) = 0.

### COMPLETENESS
An algebraic NILP for a family `R` is perfectly complete if for every `R` ∈ `R`, (`x`, `w`) ∈ `R`, all `q` ← `Q`(`R`), Π ← `P`(`R`, `x`, `w`), we have `D`(`q`, `x`, Π · `q`) = 1.

### SOUNDNESS
An algebraic NILP is sound if for every relation `R` ∈ `R`, any `x` ∉ `L`(`R`) and any proof matrix Π^∗ ∈ `F`^(*k*×*m*), we have that for `s` and `t`[1],..., `t`[η] ← `Test`(`R`, `x`) there is at least an index *i* ∈ [*η*] such that `t[i]`(`p`(`s`), Π^∗ · `p`(`s`)) is non-zero over `F`[`s`].

The above notion of soundness is defined to hold perfectly for the deterministic version of the algebraic query of the verifier. Using the commonly known Schwartz (1980) and Zippel (1979), the notion above implies (*d*[Q] · `d`[D] / `F`)-statistical soundness for the full probabilistic version of the verifier’s query. Namely, it guarantees that, over the random coins of `Q`(`R`) (i.e. over the choice of `s` ←[$] `F`^(*μ*)), for any `x` ∉ `L`(`R`) and any proof matrix Π^∗ ∈ `F`^(*k*×*m*) it holds Pr[`D`(`p`(`s`), `x`, Π^∗ • `p`(`s`)) = 1] ≤ (*d*[Q] · `d`[D]) / |`F`|.

The notion of algebraic NILP presented above is quite similar to the notion of algebraic, input-oblivious, two-message linear interactive proofs introduced by Bitansky et al. (2013). The main difference in the syntax is that in the LIP notion the proof is supposed to be a single linear function, that is, a vector `π`, and the verifier makes more linear queries, that is, the query is a matrix.

## 11.5.2. Bilinear groups

A general introduction to pairings has been presented in [Chapter 5](#c05.xhtml); we briefly precise here our notations. A *bilinear group generator* `BG`(1^(*λ*)) outputs (`p`, `G`[1], `G`[2], `G`[*T*], `e`), where `G`[1], `G`[2], `G`[*T*] are additive groups of prime order `q`, and `e` : `G`[1] × `G`[2] → `G`[*T*] is an efficiently computable, non-degenerate, bilinear map. We use the bracket notation of Escala et al. (2013), that is, for `s` ∈ {1, 2, *T*} and `a` ∈ `Z`[*q*], we write [`a`][`s`] to denote `a · g`[`s`] ∈ `G`[`s`], where `g`[`s`] is a fixed generator of `G`[`s`]. From an element [`a`][`s`] ∈ `G`[`s`] and a scalar `b`, it is possible to efficiently compute [`ab`] ∈ `G`[`s`]. Also, given elements [`a`][1] ∈ `G`[1] and [`b`][2] ∈ `G`[2], one can efficiently compute [`a · b`][*T*] by using the pairing `e`([`a`][1], [`b`][2]), that we compactly denote with [`a`][1] · [`b`][2]. Using these properties, we observe that it is possible to evaluate a quadratic polynomial `f` over two vectors of elements ([`a`][1], [`b`][2]) and obtain its result in the target group, that is, [`f`(`a`, `b`)][*T*] – by abusing notation we denote this operation by `f`([`a`][1], [`b`][2]). Although it may not be efficient to extract the result `f`(`a`, `b`) from the encoding [`f`(`a`, `b`)][*T*], one can efficiently check if the result is 0. In our compiler, we make use of the latter property. In addition, for simplicity of presentation, in this work we use Type-1, also known as symmetric, pairings where `G`[1] = `G`[2], denoted with `G`.

In the next sections, we explain the AGM of Fuchsbauer et al. (2018), which formalizes the notion of algebraic adversaries in security reductions, and then we state the computational assumptions needed for our SNARG construction.

### 11.5.2.1. Algebraic group model

Consider a group `G` of prime order `p`. An *algebraic security game* is an experiment where one distinguishes between elements of the group `G` and all other elements which do not depend on the group elements. An *algebraic algorithm* that is executed in an algebraic game is an algorithm that, for any group element `h` ∈ `G` that it outputs, it also returns an “algebraic explanation” of `h` relative to all the previously received elements. Namely, if `A` is executed in an algebraic game where it receives as input a vector of group elements [`v`] and outputs `h`, then `A` additionally outputs a vector `z`[`h`] ∈ `Z`[*p*] such that `h` = Σ `z`[`h`]_i [`v`]_i.

Proving that a cryptographic scheme reduces to a certain assumption in the algebraic group model means that any algebraic adversary against the security of the scheme can be transformed into an algebraic adversary against the assumption with a polynomially related running time and success probability.

### 11.5.2.2. Computational assumptions

We define a stronger variant of the discrete logarithm assumption in bilinear groups. The standard discrete logarithm problem, for a fixed generator `g` = [1], asks to extract `s` from [`s`]. The power discrete logarithm problem, first formalized by Lipmaa (2012), is a generalization in which the adversary additionally receives [`s`², ..., `s`^`d`] for some `d` = `poly`(`λ`).

**DEFINITION 11.5 (*d*-PDL Assumption).** Let `BG` be a bilinear group generator and let `d` ∈ `N` be a positive integer. We say that the `d`-power discrete logarithm assumption (`d`-PDL) holds in `BG` if for every PPT `A`

```
Pr[BG(1^λ) → (p, G1, G2, GT, e), s ← Zp : A(p, G1, G2, GT, e, [s], [s^2], ..., [s^d]) = s] ≤ negl(λ)
```
