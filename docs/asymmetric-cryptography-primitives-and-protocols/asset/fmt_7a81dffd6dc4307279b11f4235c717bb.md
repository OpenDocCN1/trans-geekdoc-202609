
## 数字签名方案

与手写签名类似，我们期望数字签名 `σ` 将来自某个可接受消息空间 ![image](images/m.jpg) 的消息 `m` 的内容与签名者绑定。签名者由公钥 `pk` 标识，该公钥可能经过认证，从而与身份关联。由于我们期望只有签名者能够创建此类签名，因此签名者持有与 `pk` 匹配的密钥 `sk`，二者通过某个 `KGen` 算法共同生成。使用密钥 `sk` 进行签名由方案的 `Sig` 算法执行，而在公钥 `pk` 下的验证则通过 `Vf` 算法完成。

有了上述接口，三个算法 `KGen`、`Sig` 和 `Vf` 尚未“关联”。这是通过正确性属性来实现的：该属性指出，由 `KGen` 生成的密钥下，通过算法 `Sig` 生成的签名会被验证算法 `Vf` 识别为正确。注意，原则上让 `Vf` 接受任何签名即可轻松实现这一点。但我们稍后将要求：在不知道密钥的情况下，很难找到这种有效签名，即这种不可伪造性概念与正确性要求在这方面可以视为对立面。

**定义 2.1（签名方案）。** *数字签名方案* `S` = (`S`.`KGen`, `S`.`Sig`, `S`.`Vf`) *由三个概率多项式时间算法组成，满足：*

*– **密钥生成**：密钥生成算法以单元编码的安全参数 `1^λ` 为输入，输出一对密钥和公钥，`(sk, pk)` ←[$] `S`.`KGen`(`1^λ`)。我们假设每个密钥都能高效恢复 `1^λ`，且安全参数决定了一个消息空间 ![image](images/m.jpg)[λ] ⊆ {0, 1}^∗。*

*– **签名**：签名算法接收密钥 `sk` 和消息 `m` ∈ ![image](images/m.jpg)[λ] 作为输入，输出一个签名，`σ` ←[$] `S`.`Sig`(`sk, m`)。*

*– **验证**：验证算法接收公钥 `pk`、消息 `m` ∈ ![image](images/m.jpg)[λ] 和潜在签名 `σ` 作为输入，输出一个决策比特，`d` ←[$] `S`.`Vf`(`pk, m, σ`)。*

*正确性表明，以压倒性概率（作为 `λ` 的函数），对于任意消息 `m` ∈ ![image](images/m.jpg)[λ]，当 `(sk, pk)` ←[$] `S`.`KGen`(`1^λ`)、`σ` ←[$] `S`.`Sig`(`sk, m`) 且 `d` ←[$] `S`.`Vf`(`pk, m, σ`) 时，有 `d` = 1。如果正确性以概率 1 成立，则称该方案为**完全正确**。*

我们针对概率验证算法定义了签名方案。在所有已知方案中，验证都是确定性的，如果签名算法输出一个签名，则（确定性）验证者也会接受该签名。尽管如此，当今一些实用的签名方案，特别是基于格的方案如 Dilithium (Bai et al. 2020)，可能在单次执行中无法创建有效签名，因此需要在此情况下迭代。此时，该算法理论上可能永远运行，或者需要在一定迭代次数后中止，导致签名生成过程中通常出现可忽略的错误。对于实际用途，该概率无关紧要。

我们注意到，理论上，对于确定性验证者，很容易修复可忽略的正确性错误，且不违背不可伪造性。为此，签名者在输出签名 `σ` 前先对其进行验证，若验证失败则改为输出签名密钥 `sk`。验证算法随后也接受密钥作为任意消息 `m` 的签名，从而修复签名过程中的任何错误。此处假设可以检查 `sk` 是否为 `pk` 的有效签名密钥。如果 `sk` 包含执行 `KGen` 生成密钥对所用的随机性，则后者易于实现。但请再次强调，该解决方案仅具有理论意义。

### 2.1.2 实用方案示例

本节介绍实践中部署最广泛的两种签名方案。我们将在后续章节介绍安全概念后，再讨论它们的安全属性。

#### 2.1.2.1 数字签名算法

数字签名算法 (DSA) 由美国国家标准与技术研究院 (NIST) 提出，最早于 1994 年作为数字签名标准 (National Institute of Standards and Technology 1994) 中唯一的签名算法。该算法使用一个群 `G`，并在 `G` 的一个由元素 `g` ∈ `G` 生成的素数阶 `q` 的子群中工作。我们用 ⟨`g`⟩ 表示这个由 `g` 生成的循环群。最初，NIST 仅建议使用群 `G` = ![image](images/zsp.jpg)，其中素数 `p` 在 512 位到 1024 位之间，`q` 的阶为 2^160。最新版 DSS 标准 (National Institute of Standards and Technology 2013) 允许 `(p, q)` 采用 (1024, 160)、(2048, 224)、(2048, 256) 或 (3072, 256) 位的其他选择，并包含一个称为 ECDSA 的椭圆曲线版本。我们首先采用模 `p` 乘法群 ![image](images/zsp.jpg) 形式来描述算法，随后讨论 ECDSA 的变化。

对于签名消息 `m`，DSA 部署一个函数 `H` 将消息哈希为短字符串。随后通过标准的字符串到整数转换将该字符串嵌入 ![image](images/z1.jpg)[q]，这要求哈希算法的输出足够短。我们在此简单假设 `H`(`m`) 是来自 ![image](images/z1.jpg)[q] 的值。NIST 建议使用 National Institute of Standards and Technology (2015) 中指定的任何安全哈希算法。由于最新版哈希标准提出了输出长度各异的不同算法，较大的哈希输出可能需要截断。

**构造 2.2（数字签名算法）。** *群 ⟨`g`⟩* ⊆ ![image](images/zsp.jpg) *上素数阶为 `q`、带哈希函数* `H` *的* `DSA` *包含以下算法：*

*– **密钥生成**：对于给定群，密钥生成算法随机选取 `sk` ←[$] ![image](images/z1.jpg)[q]，设定 `pk` ← `g^sk` mod `p`，并输出 `(sk, pk)` 作为密钥对。*

*– **签名**：为签名消息 `m` ∈ {0, 1}^∗，签名者随机选取 `k` ←[$] ![image](images/zsp.jpg) 并计算*

```
r = (g^k mod p) mod q
s = k^(−1) (H(m) + sk · r) mod q
```

*其中 `k^(−1)` 是 `k` 在 ![image](images/z1.jpg)[q] 上的逆元。它输出 `σ` = (`r, s`) 作为 `m` 的签名。若 `r` = 0 或 `s` = 0，则签名者须重启签名过程。*

*– **验证**：输入 `pk`、`m` 和 `σ` = (`r, s`)，验证者检查 `r` 和 `s` 是否在 ![image](images/zsq.jpg) 中，即 `0 < r, s < q`，然后计算*

```
u1 = H(m) · s^(−1) mod q
u2 = r · s^(−1) mod q
```

*并检查 `r` = (`g^u1` · `pk^u2` mod `p`) mod `q`。当且仅当所有测试均通过时，验证者输出 1，否则输出 0。*

关于正确性，我们注意到，对于公钥 `pk` 下消息 `m` 的合格签名 `σ` = (`r, s`)，有

```
g^u1 · pk^u2 = g^(H(m)·s^(−1)) · g^(sk·r·s^(−1))
            = g^(H(m)·s^(−1) + sk·r·s^(−1))
            = g^(s·k^(−1)·s^(−1))   (因为 s = k^(−1)(H(m) + sk·r))
            = g^k   (mod p)
```

因此，对该值取模 `q` 可得值 `r`，验证者接受该签名。

椭圆曲线版本称为 ECDSA，运行在特殊群上（同样为素数阶 `q`），群元素由 `x` 坐标和 `y` 坐标组成。椭圆曲线也提供群运算，通常称为加法而非乘法。因此，生成元由一对 `g` = (`g[x]`, `g[y]`) 组成，我们可以将步骤 `g^k` 解释为在曲线上对 (`g[x]`, `g[y]`) 进行 `k` 次加法。
