
The security analysis of EKE2 of Bellare et al. (2000) assumes an IC `E` on group 〈*g*〉 used in DH KE. One can implement a *randomized* IC `E` on 〈*g*〉 as `E`(*k, m*) = `E`′(*k, ξ*(*m*)), where `E`′ is an IC on {0, 1}^(*n*) and *ξ* : 〈*g*〉 → {0, 1}^(*n*) is a randomized invertible encoding, which is *uniform* in the sense that {*ξ*(*m*)}[*m*←[$]〈*g*〉] is statistically close to a uniform *n*\-bit string. Such randomized IC on 〈*g*〉 would suffice in the proof of theorem 10.1: A simulator that extracts (*k, m*′) from ciphertext *c* such that *m*′ = `D`′(*k, c*) can compute *m* = *ξ*^(−1)(*m*′) which satisfies *m* = `D`(*k, c*), and it can embed *m* ∈ 〈*g* into `D`(*k, c*) by embedding *ξ*(*m*) into `D`′(*k, c*). Thus, the existence of uniform randomized invertible encoding on 〈*g*〉 implies security in ROM, because an IC on *bitstrings* can be constructed from a random oracle using Feistel (Holenstein et al. 2011; Dachman-Soled et al. 2016; Dai and Steinberger 2016). In the special case when 〈*g*〉 = ![image](images/zsp.jpg)for prime *p*, that is, 〈*g*〉 is an integer interval \[1, *..., p* 1\], such encoding is easy to construct for *n ← |p|* + *κ*: *ξ*(*m*) picks *r* ←[$] \[2^(*n*)/*p*\] and outputs *m*′ = *m* + *rp* (over integers), and *ξ*^(−1)(*m*′) outputs *m* = (*m*′ mod *p*). However, for elliptic curve groups such encodings are not immediate.

Before such elliptic curve encodings appeared, Black and Rogaway (2002) showed an expected constant-time implementation of an IC `E`′ on any group ![image](images/g1.jpg), which is *dense* over {0, 1}^(*n*), that is, if elements of ![image](images/g1.jpg)can be encoded as *n*\-bit strings such that |![image](images/g1.jpg)|*/*2^(*n*) is a constant, given an IC `E` on *n*\-bit strings. In that construction, `E`′(*k, m*) for *m* ∈ ![image](images/g1.jpg)defines *c*[0] = `E`(*k, m*) and *c*[*i*+1] = `E`(*k, c[i]*) for all *i* ≥ 0, and sets `E`′(*k, m*) = *c[i]* for *i* such that *c[i]* is the first element of ![image](images/g1.jpg)in the sequence *c*[1], *..., c[i]*. The decryption implements the same process in reverse, that is, it recurses on `D`(*k,*) until it finds an element in ![image](images/g1.jpg). One weakness of this method is that timing information would reveal the number of `E`(*k,* ·) or `D`(*k,* ·) applications the encryptor/decryptor applied, and if *k* = *pw* then this would reveal information about the password, because for any password guess *pw*^∗ the adversary can see how many `D`(*pw*^∗, ·) operations are needed to get from a given ciphertext *c* to an element in ![image](images/g1.jpg).

Bernstein et al. (2013) constructed a uniform encoding for a class of elliptic curve groups, called *Elligator2*, which works for half the elements in the group. Specifically, Elligator2 maps *ξ* : G^′ → \[0, *...,* (*q* 1)*/*2\] for a subdomain ![image](images/g1.jpg)^′ of an elliptic curve group ![image](images/g1.jpg)of order *q* such that ![image](images/g1.jpg)^′ = (*q*+1)*/*2\. (Since \[0, *...,* (*q* − 1)*/*2\] is an integer interval, Elligator2 would be composed with the integer interval encoding shown above.) However, since Elligator2 works only on half the domain, each party would have to re-sample its DH KE contribution until it finds an element in ![image](images/g1.jpg)′, which is suboptimal because it would take expected 2 iterations. Tibouchi (2014); Kim and Tibouchi (2015) showed a uniform encoding for a larger class of elliptic curve groups, called *Elligator-squared*, which works on the full domain 〈*g*〉. Its decoding *ξ*^(−1) has similar costs as Elligator2 decoding, but encoding *ξ* requires sampling and testing preimage points, and appears to be about three times more expensive (depending on a curve). Furthermore, Elligator-squared encodes an EC point as a pair of field elements so it uses 2x more bandwidth than Elligator2. Alternatively, one can apply results of Holenstein et al. (2011); Dachman-Soled et al. (2016); Dai and Steinberger (2016) to construct a randomized IC on group 〈*g*〉 using a “mixed” Feistel, where one wire holds group elements, XOR on that wire is replaced with a group operation, and round hash functions onto that wire are an RO-indifferentiable hash onto 〈*g*〉. (The proofs of these Feistel results appear to generalize to this case.) Using 8-round Feistel of Dachman-Soled et al. (2016), this would incur four hash-onto-group operations in both encryption and decryption, but McQuoid et al. (2020) optimized this design significantly, by showing that a two-round mixed Feistel, hence a single hash-onto-group, realizes a form of “one-time” IC that suffices for EKE2.

## 10.4. Simulation-based model of PAKE security

The Boyko–MacKenzie–Patel (BMP) model for PAKE security (Boyko et al. 2000) appeared in the same year as the Bellare–Pointcheval–Rogaway (BPR) model (Bellare et al. 2000) overviewed in [section 10.3](#c10.xhtml#sec10-3). Here, we explain the BMP model and we contrast it with the BPR model.

### 10.4.1. The BMP security model

The BMP security model for PAKE takes inspiration from the Bellare–Canetti–Krawczyk model for AKE protocols (Bellare et al. 1998), and its refinement by Shoup (1999). These models follow a *simulation-based* security definition paradigm, which was used before to model secure multi-party computation (MPC) (e.g. Beaver 1991; Micali and Rogaway 1992; Canetti 2000; see [Chapter 4](#c04.xhtml)). The simulation-based paradigm considers two security games, involving two types of adversaries. The first game, called the *real-world* game, is an interaction of adversary ![image](images/a.jpg)with honest parties running protocol Π. The second game, called the *ideal-world* game, is an interaction of an algorithm ![image](images/a.jpg)^∗, called the *ideal-world adversary*, with the idealized system, denoted ![image](images/f.jpg)for a *functionality*, which by definition leaks no information to the adversary except what is necessary by the functionality of the scheme. The scheme is then defined as secure if for all efficient real-world adversaries ![image](images/a.jpg)there exists an efficient ideal-world adversary ![image](images/a.jpg)^∗, also called a *simulator*, such that the two games produce indistinguishable views, where the “view” is in each case defined as a joint distribution of an adversary’s output (which without loss of generality includes its entire transcript) and the outputs of all honest parties. This notion captures security of scheme Π because it implies that everything that an adversary ![image](images/a.jpg)can do when interacting with honest parties running Π (and this “doing” includes both everything ![image](images/a.jpg)learns, that is, its transcript, and everything ![image](images/a.jpg)causes the honest parties to do, that is, their outputs) could also be done, and this is the role played by the simulator ![image](images/a.jpg)^∗, when interacting with an ideal system ![image](images/f.jpg).^()

*The real-world game*: Let us first describe the real-world game in the BMP model, which captures an interaction of ![image](images/a.jpg)with honest parties (`P`[1]*,...,* `P`[*n*]) running polynomially many instances of the PAKE protocol. This interaction is similar to the BPR security game, and just like there the adversary ![image](images/a.jpg)is assumed to fully control the network between all honest parties. However, unlike in the BPR security game, there is no event that defines a “break” of this protocol, or a challenge bit *b* which the adversary has to predict.^()
