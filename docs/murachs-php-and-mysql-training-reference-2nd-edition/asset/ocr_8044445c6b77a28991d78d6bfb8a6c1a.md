# # How to code functions

Before you can write code that uses the MVC pattern, you need to learn how to code your own (custom) functions as described in figure 5-2. To do that, you can use the syntax shown in this figure.

When you code the name of the function, you must choose a unique name. In other words, one function can’t have the same name as another function. In addition, a function name can’t begin with a number and can only contain letters, numbers, and underscores (no special characters).

Within the parentheses of a function, you can code an optional *parameter list* that contains one or more *parameters*. When a function has multiple parameters, you separate the parameters with commas.

If you want a function to return data, you can code a *return statement* within the body of the function. This statement ends the execution of the function and returns the specified value.

The first example is a function named get_products_by_category that accepts a single parameter that specifies the category ID. Then, this function returns an array that contains the products in the specified category. To do that, the first statement uses the *global* keyword to make the $db variable (the PDO object) available within this function. This is necessary because the $db variable is declared outside of the get_products_by_category function. After that, this function uses the database techniques of chapter 4 to execute a SELECT statement and store the array for the result set in the $products variable. Then, the return statement returns this variable.

The second example is a function named add_product that accepts four parameters. This function executes an INSERT statement that adds a product row to the database that contains the data specified by the four parameters. Since this function doesn’t include a return statement, it doesn’t return any data.

To call a function, you code the function name followed by a set of parentheses that contains the *arguments* that are required by the function. This works the same as when you call a built-in function. When you code these arguments, they must be in the same order as the parameters in the parameter list that’s defined by the function, and they must have compatible data types. However, the arguments don’t have to have the same names as the parameters, although that’s a common coding practice.

The examples of function calls illustrate how this works. Here, the first statement calls the get_products_by_category function with one argument and stores the array that’s returned in a variable named $products. In this example, the function call stores the returned data in a variable that has the same name as the variable in the return statement of the function. Although this is a common coding practice that makes it easy to remember variable names, this isn’t required. For example, you could store the value that’s returned by the get_products_by_category function in a variable named $products_array.

The second statement calls the add_product function with four arguments. Since this function doesn’t return any data, this statement doesn’t attempt to store any data in a variable.
