# # How to display data on a web page

This topic begins by looking at two formatting issues that arise when working with text entered by a user. Then, this topic describes two statements that you can use to send data to the browser.

# ## How to format special characters

If you are familiar with HTML, you should know that you can’t type every character into a web page. For example, the less than sign (<) and the greater than sign (>) are used to mark the start and end of HTML tags. As a result, to display these characters on a web page, you have to use the *HTML character entities* for these characters.

Some of these character entities are summarized in the second table in figure 7-8. For example, to display the less than sign (<), you have to code its HTML character entity (&lt;). Otherwise, the browser interprets the less than sign as the beginning of an HTML tag.

So, what happens if the user enters special HTML characters in a control on a form and you later want to display those characters on a web page? For example, what happens if the user enters “Welcome to <i>PHP</i> and MySQL” in a text area?

If you want the browser to italicize the text between the <i> tags, you can use an echo statement to send this text to the browser. Then, the browser treats the <i> tags as HTML and italicizes the text they contain. Unfortunately, this opens the door to a cross-site scripting (XSS) attack. As a result, you should only use this approach if you’re sure the text that you’re sending to the browser doesn’t contain an XSS attack.

If, on the other hand, you want to display the <i> tags themselves, you can convert the < and > characters to their HTML character entities. To do that, you can use the htmlspecialchars function as shown in this figure. This also helps guard against XSS attacks. As a result, you can use this approach any time you think the text that you’re sending to the browser might contain an XSS attack.

As the syntax summary shows, the htmlspecialchars function provides for four parameters. Of these parameters, the first parameter is required, and the other three are optional.

In most cases, you’ll only need the first parameter as shown in the first PHP example. Here, the first statement gets some text from a text area, the second statement uses the htmlspecialchars function to convert any special characters in that text to HTML entities, and the echo statement that’s coded within the <p> tag sends that text to the browser.

However, if you want to prevent double encoding of HTML entities, you’ll need to use all four parameters as shown in the second PHP example. Here, the first three parameters are relatively easy to understand. They provide the name of the string to be processed, a constant that specifies how quotation marks should be handled, and a code that specifies the character set to be used.
