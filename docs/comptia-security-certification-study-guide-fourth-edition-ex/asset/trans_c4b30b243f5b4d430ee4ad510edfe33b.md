
# 对于所有安全计划而言，一个重要的考量因素是：获批准的个人如何向不同系统证明其身份，以及该信息如何被用于验证这些个人确实是他们自称的那个人。验证个人身份的过程称为**身份验证**。在组织中的员工能够进入大楼的安全区域，或访问服务器上的资源之前，必须先经过身份验证。

本章将讨论身份验证的概念，并回顾当今环境中常见的一些身份验证协议。

## 认证目标 10.01

## 识别身份验证模型

身份验证最常见的例子是：员工向系统提供用户名和密码，系统根据数据库核对这些信息，以确定该用户名和密码是否存在。如果信息与数据库中存储的内容匹配，则该员工通过身份验证，并被授予对系统的访问权限。

在本节中，您将了解不同的身份验证因素和单点登录的概念，但让我们首先回顾一下您在[第 2 章](#ch02.xhtml#ch2)中学到的一些术语——标识和身份验证。

### 身份验证术语

请回顾[第 2 章](#ch02.xhtml#ch2)的内容：用户必须先向系统标识其身份，然后才能进行身份验证。例如，当用户在登录屏幕输入用户名时，他们是在标识自己；但当他们输入密码时，则是通过知道只有该人才知道的信息来证明其身份。

大多数身份验证示例涉及用户由服务器进行验证。但从安全角度来看，更安全的场景是让客户端也验证服务器。这将确保没有其他系统冒充服务器以拦截来自客户端的机密信息。用于标识通信双方均进行身份验证的认证方案的术语是 `mutual authentication`（双向身份验证）。

### 身份验证方法和技术

在对系统或网络进行身份验证时，可以使用多种不同的方法。以下概述了常见的身份验证方法及其用途说明：

- **目录服务** 目录服务是一种存储对象（如用户和组）及其属性（如部门和城市）的系统。目录服务是用户名和密码的数据库，用于验证尝试访问系统或网络的人员。`Active Directory` 是基于 Microsoft 域的网络的目录服务示例。

- **联合** 使用联合服务是跨组织或应用程序实现身份验证的方式。例如，一家公司可能建立一个网站，允许您使用 Google 或 Facebook 账户进行身份验证。您将在本章后面了解更多关于联合服务的内容。

- **证明** 证明是指某人为另一个人担保。作为身份验证中使用该概念的一个示例，您可以将数字证书链接到一个账户，并用它来验证个人身份。

- **智能卡身份验证** 智能卡，也称为 `PKI card`（PKI 卡），是一种带有芯片的卡，用于存储身份验证信息，如用户的数字证书。当用户需要向系统进行身份验证时，他们可以将智能卡插入智能卡读卡器，然后输入与智能卡关联的 `PIN`（个人识别码）。

系统、设备和网络可以使用多种不同的技术来执行身份验证。以下是关于 Security+ 考试中身份验证部分您应熟悉的几项关键技术：

- **TOTP** `Time-based one-time password`（基于时间的一次性密码）是由身份验证系统基于当前时间生成的随机密码代码，仅在短时间内作为有效密码。例如，基于云的应用程序可能会将通行码发送到您手机上运行的应用程序中，您在输入用户名和密码后有 30 秒的时间输入该通行码。

- **HOTP** `HMAC-based one-time password`（基于 HMAC 的一次性密码）是一种用于生成密码的基于哈希的消息认证码（`HMAC`）算法。

- **SMS** 短消息服务（`SMS`）涉及向您的移动设备发送短信。例如，`SMS` 可被具有多因素身份验证（`MFA`）的应用程序用于在您输入用户名和密码后向您的手机发送代码。如果您持有手机并输入该代码，就证明您是正在进行身份验证的个人。

- **令牌密钥** 令牌密钥是企业网络用于多因素身份验证（`MFA`）的常用工具。在您输入用户名和密码后，您持有的令牌密钥上会生成一个随机数字，然后您输入该数字作为第二个身份验证因素。

- **静态代码** 静态代码与 `TOTP` 代码不同，`TOTP` 代码仅在短时间内有效，之后会发生变化。静态代码不会过期，因此也不会改变。静态代码的一个例子见于 Facebook，称为恢复代码。当您已设置多因素身份验证但身边没有手机接收 `SMS` 消息时，您可以使用恢复代码。您可以输入恢复代码作为第二种身份验证方式，代替 `SMS` 短信。

- **身份验证应用程序** 身份验证应用程序是可用于验证个人身份的应用程序。例如，`Google Authenticator` 应用程序是一种基于软件的身份验证应用程序，同时使用 `TOTP` 和 `HMAC-based OTP`。

- **推送通知** 推送通知被应用程序用作一种多因素身份验证（`MFA`）形式，要求用户在登录网站时持有其移动设备。在用户在网站输入用户名和密码后，网站将要求用户通过选择推送到设备上的“批准”或“验证”按钮，从其移动设备批准该身份验证。

- **电话呼叫** 作为应用程序内多因素身份验证的一部分，您使用用户名和密码登录，然后可能会选择接收短信或拨打账户中注册的电话号码。如果您选择接听电话，身份验证系统将呼叫注册的电话号码（例如您的家庭电话），然后提示您输入 `PIN` 以完成身份验证。

### 多因素身份验证因素和属性

多因素身份验证（`MFA`）是当今身份验证系统的重要组成部分，也是您备考 Security+ 考试应熟悉的内容。多因素身份验证涉及用户使用不同因素向系统进行身份验证，例如他们拥有的东西（`PKI card`）和他们知道的东西（该卡的 `PIN`）。总体而言，`MFA` 提高了身份验证过程的安全性，确保某人就是他们声称的那个人。Security+ 考试要求您了解身份验证的不同方法或因素。

#### MFA 因素

个人可以使用以下任意身份验证因素进行验证：

- **您知道的东西** 这是最常见的身份验证因素，即您知道某些信息以证明您的身份。此身份验证因素的一个例子是知道密码或 `PIN`。
