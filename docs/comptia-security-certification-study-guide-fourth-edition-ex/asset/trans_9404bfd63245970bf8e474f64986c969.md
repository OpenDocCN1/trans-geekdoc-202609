

### Wireless
无线网络可以放置在其自己的网络区域中，这使防火墙管理员有机会控制无线客户端可以访问哪些区域。例如，您可能不希望无线网络访问内部网和外部网区域。

### Guest
来宾区域是为您办公地点的访客设计的。访客通常不需要访问私有网络，甚至不需要访问外部网区域；他们通常只需要互联网访问权限来查看电子邮件和访问互联网资源。您可以创建一个具有公共互联网区域访问权限但无法访问任何其他区域的来宾区域。

与在组织内设计安全性相关的最后一个概念或 Security+ 术语是*零信任*的概念，也称为*零信任安全模型*。零信任是指在设计网络时，连接到网络的网络设备和系统默认不应受信任。因为当今的网络有许多网段，并且有大量类型的设备连接到这些网段，所以在授予它们网络访问权限之前，实施相互身份验证和系统运行状况检查非常重要。最终用户设备是应归入零信任安全模型的设备的典型示例。

### INSIDE THE EXAM

#### Understanding DMZs
对于 Security+ 认证考试，请了解非军事区（DMZ）是两个防火墙之间的区域：一个外部防火墙和一个内部防火墙。DMZ 是网络上允许来自互联网的选定流量到达的区域。您通常会在 DMZ 中放置 DNS 服务器、Web 服务器、FTP 服务器和 SMTP 服务器。

在外部防火墙上打开以下端口，以允许与 DMZ 内的相应服务通信：

- **DNS** `UDP` 端口 `53`
- **HTTP** `TCP` 端口 `80`
- **FTP** `TCP` 端口 `21`（控制端口）和端口 `20`（数据端口）
- **SMTP** `TCP` 端口 `25`
- **SSH** `TCP` 端口 `22`

#### NAT and Ad Hoc Networking
许多防火墙解决方案提供网络地址转换（NAT），它允许您在网络内部使用专用地址范围，然后将其转换为 NAT 设备上使用的公共地址。这是通过 NAT 设备的一个接口连接到互联网（称为公共接口），而其他接口连接到专用网络（称为专用接口）来实现的。公共接口连接到互联网并获取一个 IP 地址（公共 IP 地址）。NAT 设备上的其他接口被分配专用地址，网络内的所有系统在同一范围内都有一个专用地址。当专用网络上的人尝试浏览互联网时，例如，数据包首先从客户端计算机传送到 NAT 设备，该设备将数据包的专用源 IP 地址切换为 NAT 设备上公共接口的 IP 地址。然后数据包被发送到互联网上，就互联网上的任何人而言，是 NAT 设备在浏览互联网。其余系统仍隐藏在专用网络上。

Ad hoc 网络涉及一种没有中央服务器或设备来创建网络的拓扑；您只需将两个设备连接在一起，例如即时连接两台笔记本电脑，即可创建网络。一个很好的例子是 Ad hoc 无线网络，其中没有无线接入点，只有两台带有无线网卡的笔记本电脑直接相互连接，以便笔记本电脑用户可以共享信息。

#### Proxy Servers
根据定义，代理服务器是代表另一个系统执行功能的服务器。代理服务器负责代表组织内的系统发出互联网资源请求（因为它使用 NAT 技术）。[图 8-11](#ch08.xhtml#ch8fig11) 和以下列表详细说明了代理服务器的工作原理：

![Image](f0342-01.jpg)

**图 8-11 代理服务器的工作原理**

1. 网络上的工作站（客户端）被配置为将互联网请求发送到代理服务器。
2. 一台工作站向代理服务器提交互联网上网页的请求。
3. 代理服务器代表用户连接到互联网站点，并将请求传输到互联网 Web 服务器。
4. 互联网网站将回复发送给代理服务器。
5. 代理服务器将回复发送给发出请求的原始工作站。

代理服务器的好处是，从外部世界的角度来看，请求来自代理服务器（实际上确实如此）。如果有人查看请求的源 IP 地址并决定攻击该源 IP 地址，那么他们攻击的是代理服务器，而不是内部系统。内部网络中的工作站从未与互联网资源建立连接！

一些代理服务器还实现了缓存功能，它将客户端请求的网页存储在代理服务器上。其好处是，请求同一网页的下一个客户端可以更快地接收该页面，因为代理服务器已经拥有内容，不需要从互联网检索它。

代理服务器还允许管理员有一个中心点，可以在该点记录和过滤用户被允许访问的网站。大多数代理服务器都有报告功能，以便管理员可以查看访问量最大的网站列表。然后，管理员可以选择是否继续允许访问某个站点，或者如果该站点与业务无关，则拒绝访问该站点。

代理服务器的关键功能之一是用户通常向代理服务器进行身份验证，以便代理服务器可以控制用户可以访问哪些网站或可以使用哪些互联网应用程序。

代理服务器有不同类型，或者您的代理服务器提供不同的功能。对于 Security+ 考试，请务必了解以下代理功能：

- **Forward and reverse proxy（正向代理和反向代理）**
  正向代理是前面描述的那样——客户端将请求发送到代理服务器，代理服务器在互联网上检索资源并将响应发送给客户端。使用正向代理时，内部系统不会直接与互联网上的系统通信。反向代理用于您希望互联网上的系统能够向您的内部系统（如 Web 服务器或邮件服务器）发送请求的场景。在这种情况下，通信方向被反转，但所有通信仍然通过代理（在这种情况下是反向代理）。互联网上的系统将请求发送到反向代理服务器，后者在检查请求不是恶意的后，将请求转发给内部服务器。
