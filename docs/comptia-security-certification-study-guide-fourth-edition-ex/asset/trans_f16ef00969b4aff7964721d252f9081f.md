安全专业人员的一项重要任务是评估组织的安全性。组织安全评估不仅涉及评估技术层面（如服务器和防火墙配置），还涉及评估物理安全控制以及员工针对社会工程学攻击的安全意识。

在本章中，你将了解应在组织内执行的不同类型的评估以及用于评估的工具。请务必学习本章中的考试提示，因为你在 Security+ 认证考试中肯定会遇到一些关于安全评估的问题！

### 认证目标 20.01

### 理解评估类型

定期评估安全是一项重要任务，而知道如何执行该评估是一项重要技能。安全不仅仅是防火墙和权限。了解如何评估业务的不同领域以及与这些领域相关的风险非常重要。

在本节中，你将了解不同类型的安全评估。请确保你对这些内容非常熟悉，以应对 Security+ 认证考试。

#### 评估类型

安全评估包括风险评估、威胁评估、配置评估、漏洞评估和渗透测试。每种类型的评估采用不同的方法来评估安全性。

##### 风险评估

风险评估是安全诸多方面（如业务连续性规划）广泛使用的一种评估类型。风险评估也称为风险分析，它涉及识别组织内资产面临的风险，然后寻找解决方案以将这些风险降至最低。[第 17 章](#ch17.xhtml#ch17) 更详细地介绍了风险分析，但以下列表概述了风险评估的主要阶段：

- **识别资产** 风险评估的第一步是识别组织内的资产。资产是指对组织有价值的任何事物；例如，如果一家公司拥有一个每天带来数十万美元收入的电子商务网站，那将是一项资产。
- **识别针对资产的威胁（风险）（威胁评估）** 一旦识别出资产，接下来就要识别针对每项资产的威胁。每项资产通常会面临不止一种威胁。此时只需列出这些威胁。例如，该网站可能遭受拒绝服务 (DoS) 攻击，或者 Web 服务器的硬盘可能发生故障。
- **分析影响** 此阶段称为影响分析阶段，用于确定每种威胁对资产造成的影响。例如，分布式拒绝服务 (DDoS) 攻击对公司电子商务网站的影响将是在从攻击中恢复所需的时间内造成收入损失。这种威胁会产生高影响。
- **确定威胁优先级** 在识别出资产的所有威胁后，你需要根据威胁若成为现实将对业务造成的影响，以及威胁发生的概率，对每个威胁进行评级。此时你应该已了解哪些威胁更为严重。
- **缓解威胁** 一旦确定了威胁的优先级，你就可以着手考虑如何缓解它们。例如，你可以通过将 Web 服务器置于防火墙后面来帮助防止对其的攻击。你可以通过实施 RAID 解决方案来防范硬盘故障。

##### 威胁评估

威胁评估实际上是风险评估的一部分，你在其中识别针对资产的不同威胁。如前所述，单个资产将面临许多不同的威胁，而风险评估的一部分工作就是对这些威胁确定优先级。

##### 配置评估

通过配置评估，安全管理员将审查系统或网络的安全配置。这通常涉及拥有一份配置最佳实践清单，并确保遵循了这些最佳实践。以下是你需要检查配置的资产列表：

- **所有系统** 在评估任何系统的安全性时，请确保其已打好补丁并经过加固。确保系统上没有运行不必要的软件或服务。所有系统都应要求用户使用强密码登录。所有系统都应安装防病毒软件，并使病毒定义数据库自动更新。还应配置并启用基于主机的防火墙。
- **文件服务器** 在检查文件服务器的安全配置时，请确保用户必须通过身份验证才能访问服务器上的文件。确保为文件夹分配了权限以控制谁有权访问信息，并确保遵循了最小权限原则。
- **Web 服务器** 对于 Web 服务器配置，请验证如果网站处理访问者的敏感信息，则已实施 SSL/TLS。确保实施了适当的身份验证，并确保 Web 服务器上没有不应存在的文件。确保 Web 服务器已启用日志记录，以便你可以监控对网站的访问。
- **SMTP 服务器** 除了给系统打补丁和加固外，请确保 SMTP 服务器位于防火墙后面，且不允许 SMTP 中继。SMTP 服务器应具备邮件级病毒防护，且应启用垃圾邮件过滤功能以维护邮件卫生。我曾与一位启用了邮件服务器垃圾邮件过滤功能的客户交谈，其垃圾邮件过滤器每天拦截 40,000 封非合法邮件！
- **DNS 服务器** 请确保组织使用两套 DNS 解决方案——一套用于内部名称解析，另一套用于公共名称解析。公共 DNS 服务器应位于 DMZ 中并经过加固。DNS 服务器应仅允许向辅助服务器进行 DNS 区域传送。
