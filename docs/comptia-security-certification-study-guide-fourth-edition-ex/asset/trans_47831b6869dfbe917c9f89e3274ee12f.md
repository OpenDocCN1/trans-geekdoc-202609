

#### 带内与带外密钥交换

Security+ 认证考试要求你了解 `in-band key exchange`（带内密钥交换）和 `out-of-band key exchange`（带外密钥交换）这两个术语。在 `in-band key exchange` 中，加密密钥作为通信的一部分在各方之间交换。使用 `out-of-band key exchange` 时，双方必须在一个独立的通信信道中交换密钥，该信道不同于双方交换数据的通信信道。

### 理解哈希

哈希是一项重要的密码学服务，因为它旨在确保数据或消息的完整性。完整性涉及确保信息自创建或发送给接收者以来未被篡改。

#### 哈希概念

要使用哈希，发送方首先将数据通过哈希算法运行，该算法根据数据计算出一个哈希值。其理念是没有两段不同的数据会产生相同的哈希值。哈希值计算完成后，会随消息一起存储或发送。接收到消息时，接收方将其通过相同的哈希算法运行，以计算消息的哈希值。然后将计算出的哈希值与随消息发送的哈希值进行比较，如果两者相同，则意味着信息未被篡改。

哈希值被称为 `one-way hash values`（单向哈希值），因为不可能执行反向操作，即从哈希值反推计算出消息（或数据）。这也是大多数供应商在系统上存储密码时对其进行哈希处理的原因——哈希值无法被检索并用于计算用户账户的密码。

请记住关于哈希的以下要点：

- 哈希值具有固定长度，取决于所使用的哈希算法。无论哈希多少数据，哈希算法生成的哈希值大小始终相同。
- 哈希值也称为 `message digest`（消息摘要）。
- 哈希基于数据，而非文件的头部。例如，如果你计算一个文件的哈希值，然后更改文件名并再次计算哈希，结果将是相同的哈希值。这是为了防止有人通过重命名文件来隐藏或伪装文件。从技术上讲，如果你想证明是同一个文件，只需计算其哈希值即可。
- 虽然可能性极小，但技术上两段不同的数据有可能生成相同的哈希值，这取决于算法生成的哈希值大小。例如，64 位哈希值只有有限的可能值，因此计算时可能会出现重复哈希。另一方面，128 位哈希值有更多可能的值可作为哈希计算。这意味着有更多机会生成唯一的哈希值。
- `Collision`（碰撞）是指两段不同数据计算出相同哈希值的情况。

#### 哈希算法

正如对称加密算法执行加密信息所涉及的数学运算一样，哈希算法执行从数据计算哈希值的数学运算。

以下是近年来常用的一些哈希算法：

- **Message Digest (MD，消息摘要)** MD 算法由 Ron Rivest 创建，有不同版本，如 MD2、MD4 和 MD5。MD5 算法是当今最常用的哈希算法之一。它生成 128 位哈希值。
- **Secure Hash Algorithm (SHA，安全哈希算法)** 由国家安全局创建，SHA 算法有不同版本，如 SHA-0、SHA-1 和 SHA-2。这三者中目前最常用的哈希协议 SHA-1 生成 160 位哈希值。
- **SHA-256 和 SHA-512** 这是 SHA 算法的两个较新版本，分别生成 256 位和 512 位哈希值。它们被认为不易受碰撞攻击。
- **LANMAN** 也称为 LM hash，此哈希算法被旧版 Microsoft 操作系统用于哈希和存储密码。LM hash 通过使用 DES 加密密码来创建。它被认为是一种不安全的密码哈希存储方法。
- **NT LAN Manager (NTLM)** 从 Windows NT 操作系统开始，采用了一种新的改进方法在注册表中存储密码。密码通过 NTLM 进行哈希处理，它使用 MD4 而非 DES（LANMAN 使用）。NTLMv2 是比 NTLM 更强的认证协议，它使用 HMAC-MD5 对客户端和服务器之间的质询和响应进行哈希处理。
- **RACE Integrity Primitive Evaluation Message Digest (RIPEMD)** RIPEMD 有多种不同哈希级别的版本，如 128 位、160 位、256 位和 320 位。版本号体现在哈希算法的名称中，例如 RIPEMD-160。
- **Hash-based Message Authentication Code (HMAC，基于哈希的消息认证码)** HMAC 涉及将密钥与哈希算法结合使用来计算 `message authentication code (MAC，消息认证码)`。MAC 是生成的哈希值。
