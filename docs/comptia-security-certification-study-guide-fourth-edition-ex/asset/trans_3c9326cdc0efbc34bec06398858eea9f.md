### 证书类型

有许多不同类型的证书。每种证书类型用于特定场景。例如，代码签名证书用于对贵公司创建的应用程序代码进行数字签名，而电子邮件证书用于加密电子邮件。以下列出了不同的证书类型：

- **Wildcard（通配符）** 创建证书时会分配一个通用名称，该名称与使用该证书的站点或实体的 URL 匹配。通配符证书是一种特殊证书，可应用于域内的多个 URL。例如，我可以拥有一个 `*.gleneclarke.com` 的通配符证书，它可用于 `www.gleneclarke.com`、`mail.gleneclarke.com` 和 `login.gleneclarke.com` 等服务器。
- **SAN** 主题替代名称（SAN）证书是一种可以关联多个通用名称的证书。当服务器运行多项服务并因此使用多个名称时，这非常有用。例如，我可以为我的 Exchange 服务器申请一个 SAN 证书，其中包含 `mail.gleneclarke.com` 和 `autodiscover.gleneclarke.com` 这两个名称。如果不使用 SAN 证书，我将需要购买多个单一通用名称证书。
- **Code signing（代码签名）** 代码签名证书用于对您创建的应用程序代码进行数字签名。当您为应用程序代码签名时，您是在对代码进行数字盖章，以指明代码的来源。对代码进行数字签名还会在签名中包含一个消息摘要，用于检测是否有人篡改了代码。
- **Self-signed（自签名）** 自签名证书由根 CA 使用。PKI 中的每个实体都需要一个证书。根 CA 创建自己的证书（因此称为自签名），而所有其他系统和用户将从 CA 获取证书。
- **Machine/computer（计算机/机器）** 公司可能希望加密网络上计算机之间的通信。例如，公司可能希望加密其服务器之间的通信。为此，每台计算机都需要应用一个机器证书，也称为计算机证书。
- **E-mail（电子邮件）** 电子邮件证书用于通过 S/MIME 协议加密电子邮件。电子邮件客户端软件需要配置为使用该证书，以便加密电子邮件。
- **User（用户）** 正如机器证书由计算机使用一样，用户证书由系统用户用于加密不同类型的信息。例如，用户证书可用于通过 Microsoft 的加密文件系统（EFS）加密磁盘上的数据。
- **Root（根）** 创建 PKI 时，安装的第一个证书颁发机构称为根 CA。根 CA 拥有一个自签名证书，用于对该 CA 创建的所有其他证书进行数字签名。根 CA 使用的证书称为根证书。
- **Domain validation（域验证）** 域验证证书，也称为域验证型证书，是一种用于 SSL/TLS 的证书，其证书请求针对注册的域信息进行验证。作为验证过程的一部分，当您（作为管理员）向 CA 请求证书时，CA 会向与域关联的管理员电子邮件地址发送一封电子邮件。通过回复 CA 的电子邮件，您证明您是该域的管理员，从而可以接收证书。
- **Extended validation（扩展验证）** 扩展验证证书在域验证证书的基础上构建，不仅验证域，还检查证书请求中填写的组织信息（这部分验证实际上称为*组织验证*）。扩展验证包含以上所有内容，还验证该组织是否为合法实体。

### 证书格式

正如图形文件有许多不同的文件格式（如 JPG、GIF 和 PNG），证书也有不同的文件格式。之所以有不同的文件格式，是因为证书中存储信息的方式不同。以下列表列出了常见的证书文件格式：

- **DER/CER** *Distinguished Encoding Rules (DER，卓越编码规则)* 和 *Canonical Encoding Rules (CER，规范编码规则)* 是用于存储证书文件信息的二进制文件格式。DER 格式的文件可以有 `.der` 或 `.cer` 文件扩展名。
- **PEM** *Privacy-enhanced Electronic Mail (PEM，隐私增强电子邮件)* 是一种 ASCII 文件格式，可以有 `.pem`、`.crt`、`.cer` 或 `.key` 文件扩展名。PEM 文件非常常见，以 `-----BEGIN CERTIFICATE-----` 开头，以 `-----END CERTIFICATE-----` 结尾。
- **PFX/P12** *Personal Information Exchange (PFX，个人信息交换)* 格式，也称为 P12 或 PKCS#12 格式，是一种常用于 Microsoft 环境中导入和导出证书的二进制文件格式。PFX 格式的文件扩展名为 `.pfx` 或 `.p12`。
- **P7B** P7B 格式，也称为 PKCS#7，是另一种用于存储证书信息的 ASCII 文件格式。如果您打开该 ASCII 文件，将看到它以 `-----BEGIN PKCS7-----` 开头，以 `-----END PKCS7-----` 结尾。P7B 文件可以有 `.p7b` 或 `.p7c` 扩展名。

![Image](exam.jpg)

**针对 Security+ 考试，请了解此列表中的不同证书文件类型。另请注意，如果您导出证书以包含私钥，则使用 `.pfx` 文件；但如果您仅导出公钥，则可以使用 `.cer` 文件。**

### 证书颁发机构和注册颁发机构

证书从何而来？包含公钥的证书来自 CA。CA 负责为 PKI 创建和管理证书。

#### 证书颁发机构

有两类 CA：

- **Public CA（公共 CA）** *公共 CA* 用于标识从事向其他企业销售证书业务的 CA，以便这些证书可用于应用程序。公共 CA 的优势在于，大多数应用程序（如 Web 浏览器）都信任来自常见公共 CA（如 Entrust、Verisign 和 GoDaddy）的证书。
- **Private CA（私有 CA）** 当组织决定创建自己的 PKI 时，它就是*私有 CA*。这允许组织创建自己的 CA 并用它为组织生成证书。使用私有 CA 的优势在于，组织无需为创建的每个证书付费。

无论您创建自己的 CA 还是使用公开可用的 CA，基础设施中都可能存在整个 CA 层级结构（请参阅[图 13-3](#ch13.xhtml#ch13fig3)）。
