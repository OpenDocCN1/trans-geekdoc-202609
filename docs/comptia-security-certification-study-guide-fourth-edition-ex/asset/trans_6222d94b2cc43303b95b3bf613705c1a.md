

# 常见漏洞与暴露 (CVE)

**常见漏洞与暴露 (CVE)** 是针对不同操作系统和产品的公开披露漏洞的列表。该已知漏洞列表由 MITRE 在 [https://cve.mitre.org/cve](https://cve.mitre.org/cve) 进行管理。每个漏洞都会被分配一个 CVE ID、描述、日期以及该漏洞的任何相关评论。您可以手动搜索 CVE，或者许多漏洞扫描器可以为您搜索它，以报告有关漏洞的详细信息。

# 常见漏洞评分系统 (CVSS)

**常见漏洞评分系统 (CVSS)** 是一种用于报告漏洞严重程度级别的标准评分系统。例如，CVSS 评分为 1 或 2 的漏洞不被视为严重，但 CVSS 评分为 9 的漏洞被视为严重漏洞，应立即修复或打补丁。

许多细节因素都会纳入 CVSS 评分的计算中，例如漏洞是否可以被远程利用（风险较高）或必须在本地系统上才能利用。CVSS 评分还考虑了诸如漏洞是否对机密性、完整性或可用性构成风险等特征。

# 执行渗透测试

执行渗透测试时，您是在模拟组织从真实攻击者那里会经历的真实攻击。这意味着您将建立一套常见的渗透测试工具包，这些是攻击者用来攻破系统、破解加密或窃听通信的程序。

## 渗透测试中使用的注意事项和技术

在深入渗透测试的有趣部分（即使用执行渗透测试的工具）之前，您需要了解许多注意事项和技术。在本节中，您将学习许多渗透测试术语，Security+ 考试目标专门引用了这些术语。

### 测试类型

执行安全测试，特别是渗透测试时，请理解存在不同类型的测试。您可以执行以前称为黑盒测试、白盒测试或灰盒测试的测试。以下概述了三者之间的区别：

- **未知环境测试**  
  以前称为 `black box` 测试。执行未知环境测试时，或聘请渗透测试人员执行测试时，目标是测试人员不掌握组织或其网络配置的任何信息。测试人员必须充当黑客，自行发现组织及其配置的详细信息，然后模拟攻击。这种测试耗时最长，因为测试人员必须在尝试攻破资产之前弄清楚组织拥有哪些资产。

- **已知环境测试**  
  以前称为 `white box` 测试。在已知环境测试中，您（或您聘请的顾问）会获得组织资产和配置的所有详细信息。这种测试的目标是查看系统是否会被攻破。虽然这种测试比未知环境测试快，但它无法让测试人员了解他人发现组织信息可能有多容易或多难。

- **部分已知环境测试**  
  以前称为 `gray box` 测试。部分已知环境测试介于两者之间：测试人员获得关于组织及其配置的一些详细信息，但仅限于有限的详细信息。例如，测试人员可能获得组织使用的 IP 地址列表，并必须弄清楚这些 IP 地址上运行着什么，然后模拟攻击。

### 渗透测试概念

执行渗透测试时，您应该熟悉一些核心概念。以下概念列表包含 Security+ 目标确定的关键点，但这些并非唯一需要了解的概念（PenTest+ 涵盖了执行渗透测试的更多细节）：

- **交战规则**  
  交战规则应在渗透测试的初始阶段制定。它们是渗透测试的规则，例如应测试什么、何时进行测试，以及谁被允许与渗透测试团队通信。

- **横向移动**  
  横向移动是指利用已攻破的系统来攻破网络上的另一个系统。例如，在一台服务器上获取密码哈希后，渗透测试人员可能会尝试使用密码哈希连接到一个不存在漏洞的系统，这种技术称为 `pass-the-hash`（传递哈希）。

- **漏洞赏金**  
  漏洞赏金是向在软件中发现缺陷并将该缺陷报告给软件供应商的人员支付的补偿和认可。

- **跳板攻击**  
  跳板攻击是指测试人员攻破一台服务器（如 Web 服务器），然后利用该系统访问连接到同一网络的其他系统。重要的是要注意，渗透测试是一个漫长、拖沓的过程，类似于黑客攻击，在最终系统被攻击之前可能需要花费时间。
