
# 取证与事件响应

## 最佳实践

- **请始终记得在证据副本上工作。** 切勿直接在嫌疑人的驱动器或 SIM 卡上进行调查。
- **实时取证** 具有捕获内存内容和加密驱动器内容的优势。实时取证会修改系统，因此只有在征求法律顾问意见后才应使用。**静态取证** 是最常见的，它用于通过写保护器将嫌疑人的驱动器连接到取证工作站后，获取该驱动器的镜像。
- **确保对嫌疑人的驱动器进行位级复制**，因为它不仅包含磁盘上的文件，还包含磁盘上的所有内容，包括已删除的文件。
- **执行取证调查时，请务必记录每一步操作**，以防日后在法庭上需要为你的所有行为负责。
- **确保你拥有所有证据的保管链文档**，该文档记录了自证据被扣押以来谁一直持有该证据。
- **如果你要重复使用硬盘作为取证复制操作的目标驱动器**，请务必在使用前通过安全擦除来清理目标磁盘。
- **了解事件响应流程的阶段** 分别为：准备、识别、遏制、根除、恢复和经验教训。
- **第一响应者的角色** 是评估并遏制安全事件，这通常涉及将涉及事件的系统或网络与其余网络断开连接。

通过深入理解本章呈现的材料，你将能轻松应对 Security+ 认证考试中提出的取证和事件响应问题。

## ✓ 两分钟演练

### 处理证据

- 扣押证据后，你需要获取证据的镜像，以便在副本上而非嫌疑人原始驱动器上进行调查。
- 始终创建嫌疑人驱动器的位级副本，该副本逐扇区复制驱动器。在证据副本上工作将有助于你保全证据。
- 保管链是一份记录所有接触过证据人员的文档，这对调查的完整性至关重要。
- 确保记录你在扣押、获取和分析数字证据时采取的所有步骤。

### 收集数字证据

- 如果认为实时取证是可接受的，你可以使用 `FTK Imager` 等工具捕获内存内容。
- `KFFs`（已知文件过滤器）通过在数据库中拥有已知文件哈希值并将其作为参考，提供了一种筛选出需要审查的文件的方法。
- 证据的易失性降序为：缓存内存、`RAM`、交换文件/页面文件、硬盘、远程系统上的日志（网络）和光盘（如 `DVDs`）。
- `FAU` 拥有用于安全擦除（`wipe.exe`）和获取嫌疑人驱动器镜像（`dd.exe`）的工具。
- `SIM` 卡存储移动网络的路由信息和认证信息，但也可能存储联系人和短信。这些信息可以通过使用 `SIM` 卡读取器和 `Paraben's SIM Card Seizure` 等程序来检索。

### 审视事件响应

- 事件响应团队经过组建和培训，旨在处理公司内部的安全事件。
- `CIRT` 由团队负责人、技术专家、文档专家和法律顾问等成员组成。
- 第一响应者的目标是评估问题并遏制事件。
