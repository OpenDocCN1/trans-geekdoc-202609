

# 安全评估章节总结

在本章中，你学习了执行安全评估的相关知识，主要有两种评估类型——渗透测试和漏洞评估。备考 Security+ 考试时，请牢记以下要点：

- 可执行不同类型的评估，例如威胁评估、配置评估、漏洞扫描和渗透测试。
- 渗透测试被视为主动测试，因为你实际尝试攻破系统并绕过安全控制。漏洞评估是一种被动测试，仅识别系统配置中的安全问题。
- 可使用 `Kali Linux`（前身为 BackTrack）和 `Metasploit` 等工具进行渗透测试，以及 `John the Ripper` 等密码破解工具。
- 可使用多种不同技术来确定安全问题。你可以对公司创建的应用程序执行代码审查，对创建的解决方案执行设计审查以确保其满足初始需求，或对系统执行架构审查以确保其为安全环境。
- 渗透测试应遵循黑客攻击流程的步骤。
- 确保已起草法律文件并由所有相关方签署，授予你执行渗透测试的许可。
- 可使用多种工具执行评估，例如端口扫描器、网络嗅探器、漏洞扫描器、无线扫描器、无线破解工具和蜜罐。

通过深入理解本章呈现的材料，你将轻松应对考试中的安全评估问题。此处呈现的材料不仅对考试至关重要，在你顺利通过考试并继续从事安全专业工作后也将至关重要。

## ✓ 两分钟演练

### 理解评估类型

- **风险评估** 涉及识别资产、识别针对这些资产的威胁、确定威胁优先级，然后确定如何缓解这些威胁。
- **配置评估** 涉及审查系统配置并识别安全关注领域。这可能是手动漏洞评估的一部分。**漏洞评估** 通常涉及运行软件来识别安全问题，例如缺失补丁和不良配置。
- **渗透测试** 是一种主动测试，涉及测试人员尝试通过绕过安全控制来攻破系统。应起草并签署法律文件，授予你执行渗透测试的许可。
- **未知环境测试**（formerly known as a black box test，以前称为黑盒测试）涉及在未获得环境任何信息的情况下执行安全评估。**已知环境测试**（formerly known as a white box test，以前称为白盒测试）涉及在已获得配置和网络设置所有详细信息的情况下执行评估。
- 应对公司创建的任何应用程序执行 **代码审查**。

### 执行安全评估

- **漏洞扫描** 是一种被动测试，用于识别系统漏洞，例如缺失补丁和不良配置。
- 执行漏洞扫描时，应同时进行 **凭证** 和 **非凭证扫描**。**凭证扫描** 是指你向系统进行身份验证（通常作为管理员）并收集尽可能多的信息。**非凭证扫描** 是指你不登录系统，因此只能检索有限信息（即黑客在没有凭证时可能看到的内容）。
- **通用漏洞披露 (CVE)** 是针对不同操作系统和产品的公开披露漏洞列表。
- **通用漏洞评分系统 (CVSS)** 是一种标准评分系统，用于报告漏洞的严重程度级别。

### 执行渗透测试

- 执行渗透测试时，应遵循黑客攻击过程的各个阶段——分析、扫描和枚举、获取访问权限、维持访问权限和清除痕迹。
- 执行渗透测试时，务必在初始会议中确定并设定预期。例如，了解在渗透测试期间是否允许拒绝服务攻击。

### 用于评估安全的工具

- **协议分析器/网络嗅探器** 用于捕获流量并查看网络中传输的数据包内容。
- **端口扫描器** 用于识别系统上哪些端口处于开放状态。这有助于你确定系统上运行的是什么软件。请记住，系统上的开放端口愿意接受流量，因此你需要密切关注开放端口。
- 可使用 **无线扫描器** 评估无线网络——例如，识别无线网络、其 SSID、信道及所用的加密类型。
- **蜜罐** 是一种经过配置的系统，旨在将黑客从生产系统引诱到蜜罐。你需遵循安全最佳实践配置蜜罐，并确保配置了高级别的审核和日志记录。**蜜罐网络** 是一个完整的网络，经过配置旨在将黑客从真实网络引诱开并记录活动。
