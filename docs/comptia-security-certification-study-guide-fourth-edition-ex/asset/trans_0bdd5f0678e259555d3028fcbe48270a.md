

# TCP

TCP 通过使用所谓的序列号和确认号来确保数据被送达。`序列号` 是分配给发送的每个数据片段的一个编号。系统在接收到一个数据片段后，会通过向发送方发回一个确认消息来确认已收到该数据，其中原始序列号将作为回复消息的确认号。

## TCP 三次握手

在系统能够通过 TCP 进行通信之前，它必须首先与远程系统建立连接。为了与远程系统建立连接，TCP 使用所谓的 TCP 三次握手。TCP 三次握手分为三个阶段（如 [图 1-10](#ch01.xhtml#ch1fig10) 所示）：

![Images](f0022-01.jpg)

**图 1-10**  
TCP 三次握手

- **SYN** 在第一阶段，发送系统向接收系统发送一条 `SYN` 消息。发送的每个数据包都被分配一个唯一的序列号。`SYN` 消息包含 `初始序列号 (ISN)`，即将要使用的第一个序列号。在本例中，计算机 A 正在连接计算机 B 上的网站，因此向计算机 B 的端口 80 发送了一条 `SYN` 消息。

- **SYN/ACK** 第二阶段称为 `SYN/ACK` 阶段，因为该消息在确认第一条消息的同时，也指示了其自身的初始序列号。在本例中，计算机 B 发回 `SYN/ACK` 消息，确认已收到数据包 123（通过确认 124 为下一个序列号），同时也指定了其 `ISN` 为 326。

- **ACK** 三次握手的最后阶段是确认消息，它确认第二阶段发送的数据包已被接收。在本例中，计算机 A 发送 `ACK`，通过确认下一个数据包将为序列号 327，来确认已收到数据包 326。

## 断开 TCP 会话

正如 TCP 使用三次握手来创建两个希望通信的系统之间的连接一样，TCP 也有一个流程让参与者退出对话。查看 [图 1-11](#ch01.xhtml#ch1fig11)，可以看到如果计算机 A 想要断开 TCP 会话，它必须首先发送一个 `FIN` 标志以示意要结束对话。

![Images](f0022-02.jpg)

**图 1-11**  
终止 TCP 连接

当计算机 B 收到 `FIN` 消息时，它会回复一个确认，然后向计算机 A 发送自己的 `FIN` 消息。作为该流程的最后一步，计算机 A 必须确认已收到来自计算机 B 的 `FIN` 消息。这类似于打电话交谈——要结束通话，你说再见，然后等待对方说再见后再挂断。我将其描述为以一种“礼貌”的方式结束对话。

还有一种以“不礼貌”方式结束对话的方法。回到电话类比：你可以在不说再见的情况下挂断电话，从而不礼貌地结束对话。在 TCP 世界中，你可以通过发送一个设置了 `RST`（复位）标志的 TCP 消息来“挂断”。

## TCP 端口

当应用程序使用 TCP 通过网络进行通信时，每个应用程序必须通过使用端口号来唯一标识。`端口` 是分配给应用程序的唯一地址。当客户端想要与这些应用程序（也称为服务）之一通信时，客户端必须将请求发送到该系统上相应的端口号。

## TCP 标志

TCP 协议使用 TCP 标志来识别重要类型的数据包。以下是您应为 Security+ 认证考试熟悉的常见 TCP 标志：

- **SYN** `SYN` 标志分配给属于三次握手 `SYN` 阶段的任何数据包。
- **ACK** 确认标志确认之前的数据包已被接收。
- **PSH** 推送标志旨在强制将数据传递给应用程序。
- **URG** 紧急标志指定某个数据包为紧急数据包。
- **FIN** 结束标志指定您想要终止或结束连接。这以礼貌的方式结束 TCP 连接，就像打电话时说再见来结束通话一样。
- **RST** 复位标志用于以不礼貌的方式结束 TCP 对话。这就像不打招呼就挂断电话一样。

## TCP 头部

使用 TCP 协议发送的每个数据包都分配有一个 TCP 头部，其中包含与 TCP 相关的信息，如源端口、目的端口和 TCP 标志。[图 1-13](#ch01.xhtml#ch1fig13) 显示了 TCP 头部中的不同字段。以下是每个字段的简要说明：

![Images](f0025-01.jpg)

**图 1-13**  
TCP 头部

- **源端口** 这个 16 位字段标识发送系统的端口号。
- **目的端口** 这个 16 位字段标识数据包在目的系统上要发往的端口号。
- **序列号** 这个 32 位字段标识数据包的序列号。
- **确认号** 这个 32 位字段标识该数据包所确认的数据包。
- **偏移量** 这个 4 位字段指示数据从何处开始。
- **保留** 这个 6 位字段始终设置为 0，为将来使用而设计。
- **标志** 这个 6 位字段存放 TCP 标志。前文提到的每个标志都有一个 1 位字段。
- **窗口大小** 这个 16 位字段决定在需要确认之前可以发送多少信息。
- **校验和** 这个 16 位字段用于验证 TCP 头部的完整性。
- **紧急指针** 这个 16 位字段仅在设置了 `URG` 标志时使用，它指向最后一个紧急信息片段。
- **选项** 这是一个可变长度字段，指定 TCP 头部中可能需要的任何附加设置。

### 用户数据报协议

用户数据报协议 (UDP) 供那些不想关心确保数据到达目的系统的应用程序使用。UDP 用于无连接通信（不可靠），这意味着数据被发送到目的地，但不作任何努力来跟踪数据包的进度以及它是否已到达目的地。
