
如果镜像中的某个磁盘发生故障，您可以通过打破镜像、添加一个新的正常工作磁盘，然后从未发生故障的现有磁盘重建镜像来替换故障磁盘。一旦您重新建立了镜像，您就恢复了容错能力。

**在 Windows Server 上创建镜像卷**

在本分步过程中，您将通过使用上一练习中创建的两个动态磁盘，在 Windows Server 上创建一个镜像卷。请记住，镜像卷将所有数据存储在该卷的两个成员（磁盘）上。

1.  登录到 ServerA，然后启动“计算机管理”控制台。
2.  在“计算机管理”控制台中，在左侧“存储”下选择“磁盘管理”。
3.  右键单击磁盘 1 上的一块未分配空间区域，然后选择“新建镜像卷”。
4.  “新建镜像卷向导”出现。单击“下一步”。
5.  将磁盘 2 添加为镜像卷的选定磁盘，并在“选择空间量 (MB)”框中键入 `200`。还请注意，该卷使用的总空间也是 200MB（而不是条带卷情况下的 400MB）。对于镜像卷，每个磁盘有 200MB，但您只能存储 200MB——另外的 200MB 用于在灾难发生时存储数据副本。
6.  单击“下一步”。
7.  分配 `M` 作为驱动器号，然后单击“下一步”。
8.  键入卷标 `Mirrored` 并选择“执行快速格式化”选项。单击“下一步”以格式化为 NTFS。
9.  单击“完成”。镜像卷已创建。请注意，“磁盘管理”中的图例显示了每种卷类型的颜色代码。

如前所述，RAID 1 称为磁盘镜像，因为数据跨两个不同磁盘复制，但仅使用一个磁盘控制器。当使用两个磁盘控制器，每个控制器连接一块硬盘时，我们称该 RAID 1 解决方案为 `磁盘双工` 而非磁盘镜像。[图 18-4](#ch18.xhtml#ch18fig4) 显示了磁盘镜像和磁盘双工的区别。两者都被视为 RAID 1。

**RAID 1 称为磁盘镜像，它将数据的完整副本“镜像”或存储在第二个磁盘上，以防第一个磁盘发生故障。磁盘镜像是指两个驱动器连接到单个控制器，而磁盘双工（一种镜像形式）是指两个驱动器连接到不同的控制器。**

### RAID 5

RAID 5 称为 `带奇偶校验的条带化`，因为 RAID 5 卷的作用类似于 RAID 0 卷，但添加了奇偶校验信息以创建冗余。RAID 5 卷将数据写入卷中的所有磁盘，但在每个条带的一个磁盘上存储冗余信息（`条带` 是由每个磁盘上的 64KB 块组成的一行，如 [图 18-5](#ch18.xhtml#ch18fig5) 所示）。例如，当您将数据保存到由四个磁盘组成的 RAID 5 卷时，数据会被分割成 64KB 数据块（这可能会因产品或实现而异）并写入每个磁盘（假设为磁盘 0、1 和 2）。但磁盘 3 将存储已保存的三个 64KB 块的冗余数据（奇偶校验数据）。如果三个 64KB 块不足以完成文件保存，保存操作将继续到下一行。该行也将有奇偶校验信息，但奇偶校验信息存储在每行的不同磁盘上。

**在 Windows Server 上创建 RAID 5 卷**

在本练习中，您将了解如何通过使用三个驱动器在 Windows Server 上创建 RAID 5 卷。请记住，RAID 5 卷类似于条带卷，但它还为写入的每个条带存储冗余信息。

1.  登录到 ServerA 并启动“计算机管理”控制台。
2.  在“计算机管理”控制台中，在左侧“存储”下选择“磁盘管理”。
3.  右键单击磁盘 1 上的一块未分配空间区域，然后选择“新建 RAID-5 卷”。
4.  “新建 RAID-5 卷向导”出现。单击“下一步”。
5.  您现在需要选择将参与条带卷解决方案的磁盘。在左侧选择磁盘 2 和磁盘 3，然后单击“添加”以添加到条带卷。请注意，您开始创建卷所在的磁盘已自动选为该卷的成员。因为我们在磁盘 1 上开始创建卷并添加了磁盘 2 和磁盘 3，所以该解决方案将包含三个磁盘。
6.  添加每个磁盘后，在对话框底部，键入您想在每个磁盘上用于该卷的空间量。键入 `200`，并注意每个磁盘将使用 200MB——整个卷总共 400MB，因为三分之一的空间用于奇偶校验，并非实际可用空间。
7.  单击“下一步”。
8.  为 RAID-5 卷分配驱动器号 `R`。
9.  单击“下一步”。
10. 单击“下一步”以格式化为 NTFS。
11. 单击“完成”；新的 RAID-5 卷已创建。请注意，驱动器 R: 显示多次，因为它由多个磁盘组成。
12. 关闭所有窗口。

如果某个磁盘发生故障，使用 RAID 5 卷您仍然可以访问数据，但您可能想要更换故障磁盘。要从 RAID 5 的磁盘错误中恢复，您只需更换故障磁盘并重新生成卷，以便在新添加的磁盘上重建故障磁盘上的数据。

**RAID 5 卷称为带奇偶校验的条带化，因为这种卷类型将数据分割到所有磁盘上，但在每个条带的一个磁盘上保存奇偶校验数据。如果 RAID 5 卷中的某个磁盘发生故障，奇偶校验信息用于计算丢失的数据。**

## 理解高可用性

重要的是要理解，拥有 RAID 阵列并不能确保您的用户能够访问数据。例如，如果您有一台连接到 RAID 阵列的电子邮件服务器，如 [图 18-6](#ch18.xhtml#ch18fig6) 所示，请注意客户端连接到电子邮件服务器以检索数据，而不是直接连接到 RAID 阵列。如果电子邮件服务器发生故障怎么办？尽管您在 RAID 阵列上有电子邮件数据，但用户无法访问这些数据，因为他们必须通过电子邮件服务器发出请求。

![Image](f0726-01.jpg)

**图 18-6**

识别高可用性的需求

`高可用性` 是确保客户端始终能够访问他们所需的服务，无论是电子邮件服务器、数据库服务器还是 WAN 链路。要实现高可用性，您必须首先识别所有单点故障，然后在这些领域创建冗余。以下是一些常见单点故障的关键领域：

- **服务器** 提供网络服务（如电子邮件或网站）的服务器是单点故障。可以使用群集或负载均衡来提供这些服务的高可用性。群集通常为维护数据的后端服务器（如数据库服务器）提供高可用性。负载均衡是一种为解决方案增加可扩展性（以及高可用性）的方法。例如，如果您在两台 Web 服务器之间对网站进行负载均衡，随后您的公司网站变得非常流行，可扩展性体现在您可以向负载均衡解决方案中添加更多服务器，以便将工作负载分配给负载均衡解决方案中的所有服务器。
- **硬盘驱动器** 硬盘驱动器存储我们宝贵的公司数据，是单点故障。您可以使用 RAID 为驱动器提供容错能力。
