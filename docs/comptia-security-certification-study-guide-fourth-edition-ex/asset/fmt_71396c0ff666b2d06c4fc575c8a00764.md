
# Application Attacks and Secure Development

## Common Application Attacks

![Image](boxsq.jpg) An SQL injection attack involves the hacker inserting SQL statements into forms in an application to try to control what the application does.

![Image](boxsq.jpg) A buffer overflow attack is when the hacker sends too much data to an application, which typically results in the hacker obtaining shell access to the system with administrative permissions.

![Image](boxsq.jpg) A zero-day exploit is an exploit that is unknown to the vendor of the vulnerable application but is known to the hacker community.

![Image](boxsq.jpg) To prevent application attacks, developers must ensure validation of any input sent to the application before acting on that input. Network administrators can prevent application attacks by patching all software and operating systems on a regular basis.

## Secure Application Development Concepts

![Image](boxsq.jpg) Remember that an application should be deployed to the following environment in this order: `Development` → `Test` → `Staging` → `Production` → `Quality Assurance (QA)`.

![Image](boxsq.jpg) Developers implement error handling within most programming environments by implementing `try/catch` blocks.

![Image](boxsq.jpg) Any data inputted into an application should be validated before being processed.

![Image](boxsq.jpg) Stored procedures should be used to help prevent against SQL injection attacks.

![Image](boxsq.jpg) In distributed applications, implement input validation on the client side and the server side (especially on the server side).

## Implement Host and Application Security

![Image](boxsq.jpg) You can control what applications are allowed to run on a system by using an allow list (formerly known as whitelisting).

![Image](boxsq.jpg) You can deny a specific application from running on a system by using a block/deny list (formerly known as blacklisting).

![Image](boxsq.jpg) Fuzzing is a way to test how an application responds to random input.
