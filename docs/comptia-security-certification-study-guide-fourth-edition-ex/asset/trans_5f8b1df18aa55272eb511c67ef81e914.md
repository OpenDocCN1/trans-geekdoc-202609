# 自测答案

## 理解评估类型

### 1.
**B.** 渗透测试被视为主动测试，因为您正在对系统执行实际攻击并试图破坏安全控制。

**A、C** 和 **D** 不正确。漏洞扫描或评估被称为被动评估方法，因为您并没有真正尝试破坏系统的安全控制。`LANguard` 是漏洞扫描器的一个示例。风险评估也是被动的，因为您只是列出针对系统的威胁并想出如何缓解这些威胁。

### 2.
**D.** 每当您的企业开发应用程序时，都应执行代码审查，以确保应用程序中没有不安全的代码。您正在检查以确保开发人员验证输入且未为应用程序创建后门。

**A、B** 和 **C** 不正确。风险评估涉及识别资产、针对这些资产的威胁，然后计划如何缓解这些威胁。威胁评估是风险评估（分析）的一部分。渗透测试是主动尝试绕过系统的安全控制。

### 3.
**C.** 如果不允许您尝试通过绕过系统的安全控制来攻破系统，则执行漏洞扫描以识别系统中缺失的补丁或配置错误。

**A、B** 和 **D** 不正确。渗透测试涉及尝试入侵系统以确定其安全性，而在本场景中，说明不允许这种类型的操作。设计审查涉及审查解决方案的需求，以确保解决方案满足要求。代码审查涉及审查应用程序代码，以验证代码是否以安全方式开发。

### 4.
**A.** 风险评估涉及识别资产、针对这些资产的威胁，以及如何缓解这些威胁。

**B、C** 和 **D** 不正确。代码审查涉及审查应用程序代码，以验证其是否以安全方式开发。设计审查涉及审查解决方案的需求，以确保解决方案满足要求。渗透测试涉及尝试入侵系统以确定其安全性。

### 5.
**B.** 在做任何与渗透测试相关的事情之前，您首先必须弄清楚需要做什么的范围，然后让律师起草一份法律文件，声明您有权执行此类操作。该文件需要由您为其执行渗透测试的公司的高层管理人员签署。

**A、C** 和 **D** 不正确。虽然您最终将创建测试计划，并且很可能会进行一些密码破解和缓冲区溢出攻击，但您首先需要管理层的签署批准。

## 执行安全评估

### 6.
**C.** 被动安全测试意味着您并没有真正尝试绕过安全控制，而只是查看系统或环境的状态以评估安全性。漏洞扫描器在不尝试绕过系统安全性的情况下评估安全级别。

**A、B** 和 **D** 不正确。主动测试具有侵入性，因为主动测试试图通过尝试绕过安全控制并入侵系统来破坏安全性。渗透测试使用主动评估技术。

### 7.
**B.** 执行凭据扫描允许您向系统进行身份验证，并收集比匿名（非凭据）扫描更多的关于系统的信息。

**A、C** 和 **D** 不正确。您不会执行非凭据（匿名）扫描，因为那很可能是您当前正在执行的扫描类型。您也不会使用 `Metasploit`，因为那是一个用于主动攻破系统的工具集，被认为是侵入性的。您也不会尝试执行密码破解，因为那被视为黑客行为且具有侵入性（您的经理正在寻找非侵入性方法）。

## 执行渗透测试

### 8.
**C.** 端口扫描器识别哪些端口是开放的，这有助于确定系统上正在运行哪些服务。例如，如果系统上的端口 80 是开放的，您就知道 Web 服务器软件正在运行。

**A、B** 和 **D** 不正确。蜜网是一个为引诱黑客远离真实网络而创建的虚假网络。嗅探器是一种将捕获网络流量的被动工具，蜜罐是一个虚假系统，将引诱黑客远离生产系统并记录黑客入侵系统所采取的所有步骤。

### 9.
**B.** 您可以使用端口扫描器（如 `nmap`）来定位网络上的特定服务。在本示例中，您想要定位 SQL 服务器，它们默认监听端口 1433。
