
# 认证协议与实现

回顾[第8章](#ch08.xhtml#ch8)，`802.1X`是一种常见的认证协议，它通过要求客户端针对中央认证数据库（如`RADIUS`服务器）进行认证，来控制谁能访问有线或无线网络。你可以使用`802.1X`来控制对支持`802.1X`认证的无线网络和交换机的访问。这是一种实现*网络访问控制（NAC）*的方法，即控制谁可以连接到网络。

## DIAMETER

`DIAMETER`是一种较新的`AAA`协议，旨在取代`RADIUS`。因为`DIAMETER`基于`TCP`，所以它比`RADIUS`提供更可靠的通信。`DIAMETER`作为一种更安全、可扩展的协议，改进了`RADIUS`提供的服务。

## TACACS 和 XTACACS

`TACACS`代表终端访问控制器访问控制系统，起源于运行在Unix系统上的认证服务。`TACACS`服务运行在`TCP`和`UDP`端口`49`上。

`TACACS`推出几年后，`Cisco`创建了其专有的认证服务，称为扩展`TACACS`（`XTACACS`），它作为`Cisco`设备的中央认证服务工作。

## TACACS+

终端访问控制器访问控制系统+（`TACACS+`）协议是`Cisco`网络使用的`AAA`协议，取代了原始的`TACACS`和`XTACACS`协议。`TACACS+`使用传输控制协议（`TCP`）进行通信，并采用与`RADIUS`相同的拓扑结构：客户端尝试连接网络，网络设备（即`TACACS`客户端）将认证请求发送给`TACACS`服务器。

![Image](exam.jpg)

**`Security+`考试要求你了解为网络提供认证、授权和审计（`AAA`）服务的协议。请记住`RADIUS`、`DIAMETER`和`TACACS+`提供`AAA`服务。**

从安全角度来看，`TACACS+`改进了`RADIUS`，因为它加密`TACACS`客户端和`TACACS`服务器之间的所有信息，而`RADIUS`仅加密`RADIUS`客户端和`RADIUS`服务器之间的密码。

## 其他认证协议

许多其他认证协议或方法被系统和应用程序用于向环境认证用户。以下是`Security+`考试应熟悉的其他认证技术：

- **`LDAP`** 轻量级目录访问协议（`LDAP`）是一种互联网协议，设计用于通过`TCP`端口`389`访问目录服务，允许启用`LDAP`的应用程序向目录认证，然后检索存储在目录中对象的信息。
- **安全`LDAP`** 安全`LDAP`是使用安全套接字层（`SSL`）的轻量级目录访问协议，通过`TCP`端口`636`加密客户端和`LDAP`系统之间的通信。
- **`SAML`** 安全断言标记语言（`SAML`）是一种`XML`标准，旨在允许系统交换认证和授权信息。这通常用于身份联合和基于声明的认证。
- **隐式拒绝** 一种与认证相关的安全概念，即在用户经过认证之前，拒绝任何人访问系统。
- **可信操作系统** 用于标识实现多层安全（如认证和授权）以确定谁可以访问系统以及他们能做什么的系统术语。
- **`OAuth`** 一种行业标准协议，用于授权应用程序访问用户信息，而无需暴露密码等敏感信息。
- **`OpenID Connect`** 与`OAuth`授权协议配合工作的认证协议。`OpenID Connect`允许应用程序检索关于认证会话的信息。
- **`Shibboleth`** 一种使用`SAML`令牌和联合服务实现`SSO`应用程序的软件实现。
- **安全令牌** 用户用于获取网络资源访问权限的硬件令牌。安全令牌可以是智能钥匙或钥匙扣的形式。
- **`NTLM`** `NT LAN Manager`是旧版`Microsoft`网络上发现的一种安全协议，为网络提供认证服务。`NTLM`已被`Kerberos`取代。

![Image](exam.jpg)

**对于`Security+`考试，请记住`SAML`是联合服务中用于基于声明令牌的语言。还要记住`OAuth`是一种授权协议，允许用户授权应用程序访问其信息，而无需提供密码访问权限。**

# 实现认证

本章前面你了解了不同的认证因素，如你知道的东西、你拥有的东西和你本身的东西。你还了解到许多认证方案会结合这些因素来创建双因素或三因素认证方案。

在本节中，你将学习实现认证的常用方法，如用户账户、访问令牌和生物识别。

## 用户账户

最常见的认证形式是确保每位员工都有唯一的用户名和密码来访问网络。使用用户账户向网络认证时，每位员工通过输入用户名来标识自己，但通过输入密码来进行认证。其他标识示例包括用户`ID`、账号和工号——任何可用于识别个人的信息。

员工在为用户名输入密码、通行短语或可能与账户关联的`PIN`码以证明其身份后，即完成认证。

用户输入用户名和密码后，账户信息被发送到认证服务器以验证其正确性。认证服务器验证信息后，会为用户生成访问令牌。

![Image](exam.jpg)

**考试要点：请记住标识和认证的区别。标识是提供标识信息（如用户名），而认证是证明你是拥有该用户名的人——在本例中，通过知道密码。**

在用户账户和认证方面，请确保使用强密码并配置账户锁定策略。如果你想评估用户密码，请务必执行离线密码审计：将账户数据库副本带到测试环境中运行密码审计。这一点至关重要，因为如果你进行在线评估，会锁定账户。

![Images](job.jpg)**如果你的认证方案基于用户账户，请务必配置强密码策略和账户锁定策略以保护账户。**

## 令牌

如今许多网络环境使用令牌。在讨论安全时，我们有三种主要类型的令牌：

- **硬件令牌** 一种通常用于识别个人并用于认证过程的小型设备。在不同类型的硬件令牌中，最流行的是一种在`30`到`60`秒内显示随机数的设备（见图`10-2`）。用户输入该随机数以及用户名和密码以登录。
- **软件令牌** 与硬件令牌非常相似，不同之处在于它是存储在计算设备上的软件（应用程序），而不是独立的硬件设备。
- **逻辑令牌** 登录时生成的令牌，包含用户`SID`、组`SID`和用户权限。此令牌呈现给任何资源，以确定是否应授予对这些资源的访问权限。
