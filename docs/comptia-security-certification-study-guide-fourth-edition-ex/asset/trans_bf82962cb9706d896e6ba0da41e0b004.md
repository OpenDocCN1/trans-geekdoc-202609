

## D 类地址

D 类地址用于网络上称为*多播应用程序*的特殊类型应用程序。这些应用程序通过将数据发送到多播地址，同时向多个系统发送数据，任何已向该地址注册的系统都将接收数据。多播地址即是 D 类地址的用途，因此你不会将它们专门分配给网络上的主机用于正常的网络通信。

D 类地址的第一个八位字节的值范围为 224 到 239。拥有如此多的范围，D 类地址有可能提供 268,435,456 个唯一的多播组，用户可以从多播应用程序订阅这些组。

## E 类地址

E 类地址的有趣之处在于，它们仅为实验目的而设计，因此你永远不会在网络上看到 E 类地址。E 类地址的第一个八位字节的值落在 240 到 247 的范围内。

虽然 Network+ 认证考试测试你的 IP 寻址和配置概念，但你仍然需要了解地址类别的概念，以回答 Security+ 认证考试上的相关问题。以下段落回顾了关于地址类别的关键信息。

A 类地址的 IP 地址第一个八位字节在 1 到 126 之间。A 类地址还有一个默认子网掩码 `255.0.0.0`。另请注意，此子网掩码可以显示为地址末尾的 `/8`——例如，`12.0.0.10/8` 表示前 8 位构成子网掩码。

B 类地址的 IP 地址第一个八位字节的值在 128 到 191 之间。B 类地址的默认子网掩码为 `255.255.0.0`，也可以显示为地址末尾的 `/16`。

C 类地址的 IP 地址第一个八位字节的值在 192 到 223 之间。此外，C 类地址的默认子网掩码为 `255.255.255.0`，可以显示为地址末尾的 `/24`。

### 特殊地址

你已经了解到，不允许将第一个八位字节值为 127 的 IP 地址分配给主机。这是因为 A 类地址范围 127 已被保留用于环回地址。

*环回地址*用于指代本地系统，也称为 localhost。如果你想验证 TCP/IP 软件是否已在本地系统上初始化，即使你可能没有 IP 地址，也可以 ping 环回地址，通常称为 `127.0.0.1`。

*私有地址*是可以分配给系统但不能用于任何类型 Internet 连接的地址。私有地址是不可路由地址，因此使用它们的任何系统将无法在网络外运行。以下是三个私有地址范围：

- `10.0.0.0` 到 `10.255.255.255`
- `172.16.0.0` 到 `172.31.255.255`
- `192.168.0.0` 到 `192.168.255.255`

使用这些地址无法跨 Internet 路由数据不会构成问题，因为实际上，这些私有地址将位于网络地址转换 (NAT) 服务器后面，该服务器会将私有地址转换为可在 Internet 上路由的公共地址。

Windows 客户端支持一项称为*自动专用 IP 寻址 (APIPA)* 的功能。当客户端无法联系动态主机配置协议 (DHCP) 服务器时，此功能会使 Windows 客户端自动使用 `169.254.x.y` 地址进行配置。如果 DHCP 服务器出现故障，导致网络上的所有系统都无法从 DHCP 服务器获取地址，则客户端都会为自己分配一个 `169.254` 地址范围内的地址，然后能够相互通信。

APIPA 不分配默认网关，因此你将无法访问远程网络和 Internet 上的资源——但仍可与本地网络上的系统通信。在排查计算机无法在网络上通信的原因时，请留意具有 `169.254.x.y` 地址范围的系统，因为这意味着它们找不到 DHCP 服务器。

### 无效地址

你不仅应该熟悉 TCP/IP 中的私有地址范围，还应该能够识别无效地址。无效地址是不允许分配给网络上主机（如系统或路由器）的地址。从认证考试的角度来看，你需要能够识别这些无效地址。以下被视为无效地址：

- **以 127 开头的任何地址** 以 127 开头的 IP 地址保留用于环回地址，不能分配给系统。此类无效地址的示例是 `127.50.10.23`。
- **所有主机位均设置为 0** 不允许为系统分配主机 ID 部分所有位均设置为 0 的 IP 地址，因为这是网络 ID。此类无效地址的示例是 `131.107.0.0`。
- **所有主机位均设置为 1** 不允许为系统分配所有主机位均设置为 1 的 IP 地址，因为这对应于网络的广播地址。此类无效地址的示例是 `131.107.255.255`。
- **重复地址** 不允许为系统分配另一系统正在使用的地址，因为这会导致“重复 IP 地址”错误。

## 理解 TCP/IP 协议

现在你已了解 IP 寻址的基础知识，让我们来谈谈 TCP/IP 协议套件中存在的不同协议。作为负责配置防火墙和路由器访问列表的安全专业人员，理解每个 TCP/IP 协议至关重要。

### 传输控制协议

传输控制协议 (TCP) 负责提供面向连接的通信，并确保数据交付（称为可靠交付）。面向连接的通信涉及首先在两个系统之间建立连接，然后确保跨连接发送的数据到达目的地。TCP 通过重传任何丢失或损坏的数据来确保数据到达目的地。TCP 由需要可靠传输的应用程序使用，但由于会话的建立以及跨会话的数据监控和重传，这种传输比无连接协议具有更多开销。

关于 TCP 要记住的另一个因素是，该协议要求接收方确认成功接收数据。当然，所有确认（称为 ACK）都会在网络上产生额外流量，从而减少在给定时间范围内可传递的数据量。TCP 会话的创建、监控和结束所涉及的额外开销，换来的是 TCP 确保数据到达目的地的确定性，这是值得的。
