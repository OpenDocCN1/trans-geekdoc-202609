
启用防火墙后，它通常会有一条默认规则：拒绝所有流量，除非该流量是对防火墙所在系统发出的请求的响应。例如，启用 Windows 防火墙时仍可浏览互联网，因为你通过输入网站 URL（实际上是发送 HTTP GET 请求）来请求网页，因此响应（即网页内容）被允许通过防火墙。

如果你在系统上托管服务，则需要在基于主机的防火墙上打开端口，以允许这些请求通过。例如，若要通过远程桌面访问服务器且已启用基于主机的防火墙，则需打开远程桌面端口（TCP 端口 3389）。

### Windows 防火墙

在 Windows 中配置基于主机的防火墙，请按以下步骤操作：

1. 右键单击“开始”按钮，选择“控制面板”。
2. 选择“系统和安全” | “Windows 防火墙”（参见[图 7-2](#ch07.xhtml#ch7fig2)）。

![Image](f0278-01.jpg)

**图 7-2** Windows Server 中的 Windows 防火墙

3. 在 Windows 防火墙窗口左侧，你会看到以下链接：
   - **允许程序或功能通过 Windows 防火墙** 添加或移除允许的程序和端口。允许的程序是指能够向互联网发送数据的程序。
   - **更改通知设置** 启用或关闭 Windows 防火墙，并配置当 Windows 防火墙阻止程序时是否通知你。
   - **启用或关闭 Windows 防火墙** 针对特定网络位置启用或关闭 Windows 防火墙，并配置当 Windows 防火墙阻止程序时是否通知你。
   - **恢复默认值** 将 Windows 防火墙恢复为默认设置。
   - **高级设置** 打开“Windows 防火墙和高级安全”管理工具，可用于配置更详细的入站和出站规则。

4. 单击“高级设置”以访问可对防火墙上配置的出站和入站规则进行更多控制的设置。

5. 要创建允许流量通过防火墙的新入站规则，请在左窗格中右键单击“入站规则”，然后选择“新建规则”。

6. 在“新建入站规则向导”的“规则类型”步骤中，选择“端口”以基于 TCP 或 UDP 端口创建规则（参见[图 7-3](#ch07.xhtml#ch7fig3)），然后单击“下一步”。

![Image](f0279-01.jpg)

**图 7-3** 选择要创建的规则类型

7. 在“协议和端口”向导步骤中，选择协议并指定你希望允许通过防火墙的本地端口。本例中，我选择 TCP 端口 3389（参见[图 7-4](#ch07.xhtml#ch7fig4)）。单击“下一步”。

![Image](f0279-02.jpg)

**图 7-4** 在防火墙上打开端口 3389

8. 在“操作”向导步骤中，指定是允许还是阻止此流量（称为连接）。请注意，你也可以指定仅允许安全流量。选择“允许连接”，然后单击“下一步”。

9. 在“配置文件”向导步骤中，通过为每个网络配置文件启用复选框，确保规则在连接到企业域、专用网络和公用网络时均适用。单击“下一步”。

10. 在向导的最后一步，将规则名称输入为 **RDP Traffic**，然后单击“完成”。

### Linux 防火墙和 TCP Wrappers

Windows 操作系统并非唯一具有防火墙功能的系统；大多数操作系统都允许启用基于主机的防火墙。如果你想在 Linux 中启用防火墙功能（我使用的是 Fedora），可以按以下步骤操作：

1. 选择“系统”菜单，然后选择“管理” | “安全级别和防火墙”。
2. 在“防火墙选项”选项卡上，选择启用 Linux 防火墙，如[图 7-5](#ch07.xhtml#ch7fig5)所示。

![Image](f0280-01.jpg)

**图 7-5** 配置 Linux 防火墙

3. 然后可以通过执行以下任务之一来在防火墙上打开端口：
   - **受信任的服务** 可以使用受信任服务列表来打开特定端口，以允许与该服务通信。要为某服务打开端口，只需选中该服务的复选框。例如，如果我想让客户端连接到我的 Linux 系统上的 FTP 服务，我会启用 FTP 复选框。
   - **其他端口** 如果要打开受信任服务中未列出的端口，可以展开“其他端口”并单击“添加”按钮。在“添加端口”对话框中，输入要打开的端口号和协议（TCP 或 UDP）（参见[图 7-6](#ch07.xhtml#ch7fig6)）。

![Image](f0281-01.jpg)

**图 7-6** 在 Linux 防火墙上添加例外

虽然它不是真正的防火墙功能，但 **TCP Wrappers** 是 Linux 中另一个出色的访问控制功能。`TCP Wrappers` 允许你控制对 Linux 系统上运行的不同服务（如 Telnet、SSH 和 FTP）的访问。`TCP Wrappers` 功能易于实现，因为你只需配置两个文件：

- **/etc/hosts.allow** 此文件列出你希望允许客户端访问的不同服务，并指定哪些客户端可以访问这些服务。
- **/etc/hosts.deny** 此文件列出你希望拒绝客户端访问的不同服务，并允许你指定哪些客户端被拒绝访问这些服务。

对于这两个文件中的每一个，你都可以为允许客户端访问的服务添加规则（如果服务配置在 `hosts.allow` 文件中），以及为不允许客户端访问的服务添加规则（如果服务配置在 `hosts.deny` 文件中）。通常通过 IP 地址或 DNS 名称来允许或拒绝对不同系统的访问。

当客户端连接到特定服务（如 Telnet）时，Linux 系统会读取 `hosts.allow` 文件以确定该客户端是否被允许访问该服务。如果 `hosts.allow` 文件中没有该服务的规则，则会读取 `hosts.deny` 文件以查找规则。如果在任一文件中都不存在与该客户端匹配的服务规则，则尝试连接该服务的客户端将被授予访问权限。

作为使用 `TCP Wrappers` 的示例，我将编辑 `hosts.deny` 文件，指定拒绝所有系统访问 FTP 服务。要为此规则配置该文件，我添加一行新内容，输入服务名，加一个冒号（`:`），并列出该规则适用的客户端，如下面的代码所示：

```
# 示例：拒绝所有客户端访问 FTP 服务
vsftpd: ALL
```

![Image](f0282-01.jpg)

**图 7-7** 配置 `/etc/hosts.deny` 以拒绝来自所有客户端的 FTP 流量

配置 `hosts.deny` 文件后，所有系统均被拒绝访问，但我希望 `192.168.2.0` 网络上的任何系统以及 IP 地址为 `10.0.0.2` 的系统能访问该服务。为实现此目标，我向 `hosts.allow` 文件添加一行新内容，指定服务名，然后是一个冒号（`:`），后跟允许的 IP 地址列表，每个地址用逗号分隔。请注意下面的代码中，我是如何为 `192.168.2.0` 网络指定网络 ID 的（我没有在末尾加零）：

```
# 示例：允许特定网络和 IP 访问 FTP 服务
vsftpd: 192.168.2., 10.0.0.2
```

[图 7-8](#ch07.xhtml#ch7fig8) 显示了 `hosts.allow` 文件的内容。请注意，这两个文件的组合允许来自 `192.168.2.0` 网络的任何系统和 IP 地址为 `10.0.0.2` 的系统访问 Linux 系统上的 FTP 服务，而拒绝所有其他系统访问。
