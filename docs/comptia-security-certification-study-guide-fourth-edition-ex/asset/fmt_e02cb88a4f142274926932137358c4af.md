
# SIEM Dashboards

You can collect information from a security information and event management (SIEM) dashboard, which is a central tool using sensors that collect security events and alerts that are generated by devices and applications on the network. The SIEM system correlates the events with security trends and allows you to adjust the sensitivity of the alert system.

## Log Files

Log files are an important source for information to understand what has transpired during a security incident. The following are common logs you should look for when responding to incidents:

- **Network** Network logs are logs from network devices such as routers and switches. These devices allow you to forward logged messages to a central syslog server for easy review.
- **System** The system log on a Windows system contains operating system–related information such as drivers failing to start or a system shutting down.
- **Application** The application log on Windows is where applications record events to.
- **Security** The security log in Windows is where any security-related events are stored. For example, if a user account fails to log on, that information is stored in the security log.
- **Web** Web logs are where information about requests for web and FTP services are stored.
- **DNS** The DNS logs will display information about the DNS service, including zone transfers that have occurred.
- **Authentication** An authentication log would show information about authentication success and failures.
- **Dump files** Dump files store the contents of memory when the system crashes.
- **VoIP and call managers** VoIP and call managers store information about voice over IP calls that have occurred.
- **Session Initiation Protocol (SIP) traffic** SIP traffic can be used to identify the types of VoIP calls and communications occurring on the network.

## Metadata

You can obtain information from metadata, which is data that describes data. For example, when you take a photo with your phone, the photo has metadata that is automatically stored with the photo such as the date and time the photo was taken, the type of camera used to take the photo, and potentially the GPS coordinates of where the photo was taken. You can view the properties of photos, e-mails, files, and other mobile and web data to see the metadata.

## NetFlow/sFlow

NetFlow is a feature of Cisco routers that allows you to collect and display the packets that enter or leave an interface. NetFlow is used to monitor network traffic and identify potential intrusions. While NetFlow is a Cisco proprietary network monitoring tool, Internet Protocol Flow Information eXport (IPFIX) is an RFC standard supported by many vendors. sFlow is an industry standard protocol, supported by many vendors of network equipment and monitoring software, that allows packets to be sampled and exported along with interface counters.

> **Remember the difference between NetFlow and IPFIX for the Security+ exam. NetFlow is a Cisco proprietary solution to monitor traffic that passes through a router, whereas IPFIX is an RFC standard.**

# Mitigation Techniques as a Response to an Incident

The Security+ exam expects you to understand the mitigation techniques that should be implemented in response to a security incident. In this section you learn about common methods for mitigating a security incident.

## Reconfigure Endpoint Security Solutions

If you find that client systems or servers are compromised during a security incident, you should look to implementing the following strategies to protect against a repeat incident:

- **Application approved list** As part of your security policy you should have a list of authorized applications that are allowed to be used on client systems and servers. You should then implement an application approve list (formerly known as application whitelisting) that only allows those applications.
- **Application blocklist/deny list** You should implement an application blocklist or deny list to deny specific applications from running. This was formerly known as application blacklisting.
- **Quarantine** You should use the quarantine feature of malware protection software to protect the system against suspicious software. Be sure to review the quarantine on a regular basis and remove any infected files.

## Configuration Changes

There are a number of configuration changes that can be made to improve the overall security of the infrastructure and its systems:

- **Firewall rules** Look to revising firewall rules to block traffic from the source of suspicious traffic or even the unique port number used by the suspicious traffic.
- **MDM** Use a `mobile device management (MDM)` product to help centrally manage the security of smart phones, tablets, and laptops. With MDM, you can enforce policies (such as ensuring password requirements on devices), approve applications for use, incorporate remote wipe functionality if the device is lost or stolen, and remotely lock the device.
- **DLP** `Data loss prevention (DLP)` was mentioned in a few chapters of this book and is important for the Security+ exam. With DLP, you can prevent data leakage by preventing sensitive data from being sent in an e-mail message outside the company, or prevent sensitive data from being stored on a USB drive.
- **Content filter/URL filter** You can implement content filters to inspect the content of web sites or e-mail messages and then block malicious content. You could also use URL filters to block certain web sites from being reachable by users on the network.
- **Update or revoke certificates** If a digital certificate has expired, it will need to be renewed before applications will trust that certificate. Also, if a certificate has been compromised, you will need to revoke it at the certificate authority (CA).

## Other Mitigation Strategies

There are a number of other mitigation strategies you can use to help protect systems:

- **Isolation** You can isolate highly secure systems from the rest of the network so that the risk of network communication to those system is eliminated.
- **Containment** You should isolate any compromised systems to contain the spread of the security incident from affecting other systems or areas of the network. For example, if a system is infected with malware, be sure to disconnect the system from the network right away to contain the malware.
- **Segmentation** Create different network segments based on security requirements for each different area of the network. Use firewalls and access control lists to control traffic from one segment to another.
- **Secure Orchestration, Automation, and Response (SOAR)** SOAR is a threat management solution that allows you to automate security operations across the network as well as to respond to security incidents. SOAR uses `runbooks`, which are documents that contain procedures on how to perform IT tasks, and `playbooks`, which are actions that should be taken when a security incident occurs.
