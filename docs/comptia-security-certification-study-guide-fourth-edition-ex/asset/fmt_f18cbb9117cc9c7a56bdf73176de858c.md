
# Common Vulnerabilities and Exposures (CVE)

**Common Vulnerabilities and Exposures (CVE)** is a listing of publicly disclosed vulnerabilities for different operating systems and products. This list of known vulnerabilities is managed by MITRE at [https://cve.mitre.org/cve](https://cve.mitre.org/cve). Each vulnerability is assigned a CVE ID, a description, date, and any related comments for the vulnerability. You can search the CVE manually, or many vulnerability scanners can search it for you to report details about the vulnerabilities.

# Common Vulnerability Scoring System (CVSS)

**Common Vulnerability Scoring System (CVSS)** is a standard scoring system used to report the severity level of a vulnerability. For example, a vulnerability with a CVSS score of 1 or 2 is not considered severe, but a CVSS score of 9 is considered a severe vulnerability that should be fixed or patched right away.

A number of details go into the calculating of the CVSS score, such as whether the vulnerability can be exploited remotely (bad) or you have to be local on the system. The CVSS score also takes into account characteristics such as whether the vulnerability is a risk to confidentiality, integrity, or availability.

# Performing a Penetration Test

When performing a penetration test, you are simulating true attacks that the organization would experience from a real attacker. This means that you will build up a toolkit of common penetration testing tools, which are programs used by attackers to compromise systems, crack encryption, or tap into the communication.

## Considerations and Techniques Used in a Penetration Test

You need to understand a number of considerations and techniques before diving into the fun part of penetration testing, which is working with the tools used to perform a penetration test. In this section you learn a number of penetration testing terms that the Security+ objectives make a specific reference to.

### Types of Testing

When performing security testing, and specifically penetration testing, understand that there are different types of testing. You can perform what was formerly known as a black box test, a white box test, or a gray box test. The following outlines the differences among the three:

- **Unknown environment test**  
  Formerly known as a `black box` test. When an unknown environment test is being performed, or a pentester (penetration tester) is hired to perform the test, the goal is for the tester to have no information on the organization or its network configuration. The tester will have to act as a hacker and discover the details of the organization and its configuration on their own and then simulate the attacks. This type of test would take the longest because the tester has to figure out what assets the organization has before trying to compromise them.

- **Known environment test**  
  Formerly known as a `white box` test. With a known environment test, you (or the consultants you hire to do the test) are given all the details about the organization's assets and configuration. In this type of test, the goal is to see if the systems can be compromised. Although this type of test is quicker than the unknown environment test, it does not give the tester any idea of how easy or hard it may be for someone to discover information about the organization.

- **Partially known environment test**  
  Formerly known as a `gray box` test. A partially known environment test is in the middle: the tester gets some details about the organization and its configuration, but only limited details. For example, the tester may get a list of IP addresses used by the organization and will have to figure out what is running on those IP addresses and then simulate an attack.

### Penetration Testing Concepts

When you're performing a penetration test, there are some core concepts you should be familiar with. The following list of concepts comprises the key points identified by the Security+ objectives, but these are not the only concepts to know (PenTest+ covers more details on performing a penetration test):

- **Rules of engagement**  
  The rules of engagement should be set in the initial stages of the penetration test. They are the rules for the penetration test, such as what should be tested, when testing should occur, and who is allowed to communicate with the pentest team.

- **Lateral movement**  
  Lateral movement is using a compromised system to compromise another system on the network. For example, after grabbing the password hashes on one server, the pentester may try to connect to a system that is not vulnerable using the password hashes in a technique known as `pass-the-hash`.

- **Bug bounty**  
  A bug bounty is compensation and recognition that is paid to a person who has identified a bug in a piece of software and reports that bug to the vendor of the software.

- **Pivoting**  
  Pivoting is when the tester compromises a server, such as a web server, and then uses that system to gain access to other systems connected to the same network as that system. It is important to note that penetration testing is a long, drawn-out process, like hacking, and may take time before the final system is attacked.
