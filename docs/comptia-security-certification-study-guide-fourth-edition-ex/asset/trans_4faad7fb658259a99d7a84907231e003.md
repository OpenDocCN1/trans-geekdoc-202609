
# 计算机取证调查最佳实践

创建取证镜像的多个副本，并使用不同的成像工具进行创建，以防某个成像方法出现问题，这是最佳实践。

## 验证证据完整性

取证过程的很大一部分是通过在数据上运行哈希算法生成哈希值，来验证取证镜像内容的完整性。其概念在于：基于证据中的数据，生成的哈希值将是唯一的。如果您需要证明您正在使用的驱动器副本与原始数据相同，可以比较哈希值。

大多数取证工具在创建位流镜像时会生成哈希值，但您也可以使用其他工具（如 `MD5sum`）来计算数据的哈希值。您还应确保工具通过使用校验和对镜像执行某种形式的验证。

正如本章前面所讨论的，您还可以通过维护证据的**保管链**来提供证据的完整性。请注意，Security+ 考试目标明确指出了 `provenance`（来源/来历）一词——即对象的保管清单。

## 分析证据

在获取嫌疑人驱动器的镜像并生成哈希值后，您就可以开始取证分析了。您应该仅在证据副本上进行分析，而绝不在原始证据上进行。

执行分析时，您将使用取证软件定位驱动器上的数据，包括已删除的文件。根据案件性质，您可能需要检查嫌疑人的电子邮件、互联网历史记录和已删除文件，以查找相关文件。

### 文件过滤

大多数取证软件都具有允许您从分析工具中过滤掉已知文件的功能。其好处在于：系统上有数千个文件需要审查，如果能让取证软件识别已知的操作系统文件并将其从过程中移除，那么您需要查看的文件就会减少！

文件过滤功能通过拥有已知操作系统文件和违禁品（例如儿童色情制品）的哈希值数据库来工作，将数据库中的这些哈希值与磁盘上文件的哈希值进行比较。这使取证软件能够识别已知文件，即使嫌疑人已重命名文件。

`EnCase Forensic` 和 `Forensic Toolkit (FTK)` 是具有哈希文件过滤功能的流行取证软件工具。此功能的常用术语是 `known file filter (KFF)`。

### RAID 阵列

取证软件的另一个重要功能是其是否能获取 RAID 阵列中驱动器的镜像。这可以通过两种方式完成。某些取证软件允许您将阵列作为单个逻辑磁盘进行成像，然后您可以复制和分析该磁盘。其他软件可能会为 RAID 阵列中的每个物理磁盘创建镜像，然后创建一个组文件，以确保同时加载所有磁盘镜像。

### 网络流量和日志

根据您正在调查的事件类型，可能需要查看网络设备和软件的网络流量和日志文件。例如，如果您正在调查一起涉及某人通过互联网入侵系统的安全事件，您将需要查看受损系统的服务器日志，以及路由器和防火墙日志。查看日志时，请务必查看相关服务的活动日志（例如显示网站请求的 Web 服务器日志），同时也要查看事件日志以获取任何安全事件的详细信息。

### 证人访谈

在进行调查时，请务必与可能对发生的事情有所了解的证人交谈。在企业环境中，这意味着与系统用户交谈，了解系统的正常活动与异常活动的区别。

### 大数据分析

确定可能需要的大数据分析。大数据是指数据集大到无法使用典型的数据管理工具进行处理或分析。请记住，被认为太大而无法作为单个集合处理的数据量达 EB（Exabytes）级别！您可能会在气象学、金融和互联网搜索等行业发现这种情况。

## 报告调查结果

在证据分析期间，大多数取证软件允许您为感兴趣的项目添加书签，并将它们添加到可生成的报告中。在进行调查时，通过记录所有步骤并标记感兴趣的项目来规划调查结果报告至关重要。报告应包含以下内容：

- **感兴趣的项目** 您的报告应列出来自镜像的任何感兴趣项目。这可能包括电子邮件、图片、视频和已删除的文件。
- **采取行动的日志** 某些取证软件会记录您在软件中执行的每项操作。这对于验证您采取的行动非常有用。如果软件不记录您的操作，您将需要手动记录，以便解释您采取的步骤并通过遵循相同步骤重现结果。
- **调查报告** 报告应包含调查期间发现的证据摘要。例如，如果您恢复了一个包含潜在定罪证据的已删除文件，则应予以记录。

在执行调查时，记录所有活动及每项活动的时间至关重要。记录每项操作的开始时间及其耗时对调查的成功至关重要。`Record time offset`（记录时间偏移）是调查员在执行调查时需要配置的重要设置。配置记录时间偏移涉及调查员在取证软件中配置时区，使其与嫌疑人系统的时区匹配，从而确保证据中的所有时间戳信息准确。

## 证据获取来源

在进行计算机取证调查时，了解可以在哪里找到证据并理解**易失性顺序**至关重要。以下是进行计算机调查时可能找到证据的位置列表：

- **内存/RAM** 内存包含近期使用的信息。这可能包括文档内容甚至近期使用的密码。这被视为易失性证据，因为信息只会在内存中保留很短的时间。请确保准备好 `dd` 或 `FTK Imager` 等工具，以便在需要时捕获内存内容。

- **交换文件/页面文件** 信息不断从 RAM 转储到 Windows 系统上的 `pagefile.sys` 交换文件中。较新版本的 Windows（如 Windows 10）还有一个名为 `swapfile.sys` 的文件，也用于将内存内容交换到磁盘。在尝试查找易失性内存时，请务必检查交换文件。

- **硬盘** 大多数调查涉及对硬盘（或多个驱动器）进行成像，并在注册表、电子邮件或文件系统中查找存储在磁盘上的证据。

- **可移动存储介质** 如果在扣押计算机时发现现场有其他类型的介质，请务必也带走这些介质（假设搜查令涵盖了它们）。嫌疑人可能将文件存储在 CD、DVD 或闪存驱动器等可移动介质上。

- **移动设备** 如果您发现笔记本电脑、手机、平板电脑甚至 iPod 等移动设备，可能也需要搜查这些物品以获取证据。

- **缓存** 证据可能存储在缓存中——无论是安装在系统中的物理缓存内存，还是缓存文件。缓存内存用于存储近期项目，被认为比 RAM 更易失性。
