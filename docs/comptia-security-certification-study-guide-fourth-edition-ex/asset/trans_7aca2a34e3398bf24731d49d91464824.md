

### 路由器

路由器应配置控制台、辅助和 Telnet 密码，以控制谁能获得路由器的管理访问权限。出于安全考虑，您应使用 Secure Shell (SSH) 而非 Telnet 来远程管理路由器。确保路由器已实施访问控制列表 (ACL)，以控制允许什么流量通过路由器。例如，思科路由器上的以下配置将创建访问列表 45，允许来自 12.0.0.0 网络和 11.0.0.0 网络的流量。ACL 末尾存在一条*隐式拒绝所有*规则，因此除非流量来自 11.0.0.0 或 12.0.0.0 网络，否则将被拒绝。该规则随后应用于路由器的串行接口以处理入站流量，这将导致试图进入网络的流量被 ACL 过滤。

### 防火墙

防火墙应配置为拒绝所有流量，除非是明确允许通过防火墙的流量。这种配置称为*隐式拒绝*——除非另有指定，否则拒绝所有流量。由于防火墙连接到互联网，您应确保已禁用任何远程管理功能，并且设备上使用了强身份验证。

### 交换机

就交换机的配置而言，请确保在控制台端口、辅助端口和 Telnet 端口上配置了密码，以控制谁能获得设备的管理访问权限。此外，请检查是否有任何未使用的端口被禁用，以确保端口安全。要将系统分离到不同的网络段，请检查是否正在使用 VLAN，如果没有，请考虑是否应该使用。

### 员工

在执行手动评估时，还应通过计划并针对员工实施几次社会工程学攻击，来评估员工的安全知识。例如，您可以测试员工是否会泄露他们的密码。您还可以在办公室的不同区域放置无标签的 USB 驱动器，看有多少员工将 USB 驱动器连接到他们的系统。这里的想法是 USB 驱动器可能包含病毒，员工不应在系统中使用未知介质。

### 物理安全

通过手动评估，您还需要评估物理安全。所有必要的门窗都已上锁吗？系统的 CMOS 设置是否已更改，以防止从光盘或 USB 驱动器启动？对于显示机密信息的工作站，它们是否远离未经授权的查看者？机密系统是否存放在受保护区域并禁用了 USB 端口，以防止使用闪存驱动器？

### 漏洞评估

漏洞评估是一种评估，您在其中识别配置中使系统容易受到攻击或安全事件影响的区域。大多数漏洞评估通过使用漏洞评估工具（如 `Nessus`、`OpenVAS` 或 `GFI’s LANguard`）实现自动化（请参见[图 20-1](#ch20.xhtml#ch20fig1)）。

![Image](f0780-01.jpg)

**图 20-1**

漏洞扫描器将扫描网络并报告每个系统的安全问题。

漏洞评估工具的目的是分析系统的配置，以确定从安全角度需要改进的领域。例如，漏洞评估工具将检查系统的补丁级别，并告知您是否缺少补丁。如果您有无密码的用户账户、近期未登录的账户或过多的管理账户，它也会报告。所有这些要点都会在系统上造成安全风险。

关于漏洞评估需要理解的关键点是，尽管您可能正在运行一个程序来为您进行评估，但该软件仅检查系统的配置，以决定在哪里应进行改进。该软件实际上并未对系统执行攻击；它只是检查系统的配置。这被称为对评估采取*被动*方法（*被动评估*），因为您并未实际尝试利用系统；您只是检查配置并基于此做出决策。

![Image](exam.jpg)

> **针对考试，请记住漏洞评估被视为被动评估，因为您并未实际尝试绕过安全控制并入侵系统。**

以下列表概述了漏洞评估将检查的一些项目：

#### 未使用的账户

检查是否有任何用户账户近期未被使用。许多公司都有员工离职而未通知管理员禁用其账户的情况。任何未被使用的账户都可能被黑客攻破，因此识别任何未使用的账户并将其禁用至关重要。

#### 管理账户

密切关注管理账户（请参见[图 20-2](#ch20.xhtml#ch20fig2)）。管理账户越少越好，因为您需要限制能够对环境进行更改的人数。您还需要留意额外的管理账户，因为黑客可能已将其植入作为系统的后门。

#### 未修补的操作系统

未修补的系统构成巨大的安全风险，因此请务必留意未修补的系统。大多数类型的漏洞评估软件都能识别未修补的操作系统（请参见[图 20-3](#ch20.xhtml#ch20fig3)）。

#### 未修补的软件

您不仅应识别未修补的操作系统，还应检查未修补的软件。如果您的电子邮件服务器或数据库服务器未修补，攻击者很可能会对其执行缓冲区溢出攻击，并获得对系统的完全管理访问权限。

#### 易受攻击的软件

漏洞评估软件的一大优势是它能识别系统上运行的任何易受攻击的软件。例如，如果您的系统容易受到通用网关接口 (CGI) 攻击，评估软件会通知您。

Security+ 考试要求您了解漏洞扫描的特征以及执行扫描时应考虑的事项：

#### 被动测试安全控制

请知晓，执行漏洞扫描被视为被动测试系统的安全性，因为您并未实际尝试入侵系统或利用漏洞。

#### 识别漏洞

漏洞扫描的目标是识别系统中的漏洞或弱点。例如，如果该系统未及时应用补丁，则被视为一个漏洞。

#### 识别安全控制的缺失

执行漏洞评估时，您旨在识别是否有任何本应使用但当前未使用的安全控制。例如，您可能评估数据库服务器的安全性，并注意到它未受防火墙保护。在这种情况下，您应报告该系统可使用防火墙来控制与数据库服务器的通信。

#### 识别常见的错误配置

执行漏洞扫描时，您要深入检查系统的配置，以确定任何可能导致安全问题的错误配置。例如，您可能会注意到服务器上的管理员账户未被重命名。
