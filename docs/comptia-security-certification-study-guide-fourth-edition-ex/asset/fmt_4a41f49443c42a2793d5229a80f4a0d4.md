
渗透测试与漏洞评估是完全不同类型的安全评估。渗透测试中，测试人员使用常见攻击方法，查看能否绕过系统的安全防护。若渗透测试人员无法利用常见漏洞攻破系统，则系统通过测试；反之，若系统被攻破，则测试失败，测试人员将报告发现的问题及加固建议。

Security+ 考试要求掌握渗透测试的特征，主要特征与注意事项如下：

- **验证威胁是否存在** 渗透测试对系统发起实际攻击，若模拟攻击成功，便是威胁存在的最有力证明。
- **绕过安全控制** 测试针对已加固的系统，测试人员需像黑客一样绕过这些控制，以验证安全方案的实际有效性。
- **主动测试安全控制** 渗透测试属于主动测试系统安全，而漏洞扫描属于被动测试。
- **利用漏洞** 渗透测试主动利用系统漏洞以验证系统是否安全。漏洞评估仅指出漏洞存在，而渗透测试通过尝试利用漏洞，判断其是否构成实际风险。

> **考试提示**：若安全策略规定安全测试不得使用实战攻击或主动测试，则应避免渗透测试，改用漏洞扫描。

### 法律问题

作为执行安全评估的顾问，必须警惕渗透测试的法律风险，因为实际攻击系统属于违法行为。必须明确：**未经授权访问任何系统均属违法，即使目的是报告发现并协助加固**。执行渗透测试时，关键在于获取公司授权签署人（应为业务所有者或高管，而非 IT 经理或网络管理员）提供的书面许可。

高层管理人员可能不太支持渗透测试，因为这涉及对生产系统的实战攻击。若受邀执行测试，应向管理层充分说明测试内容、潜在风险（如可能导致系统在工作时间崩溃），以便其决策。管理层可能倾向于选择风险较低的漏洞评估。

![Image](exam.jpg)

> **务必在执行任何渗透测试前，获得由律师起草、经组织高层管理人员签署的法律文件，授权执行此类测试。这称为 `渗透测试授权`。执行漏洞扫描前同样需获授权，称为 `漏洞测试授权`。**

可向管理层承诺不故意发起拒绝服务攻击以免影响生产，但需明确：因攻击工具特性，可能意外触发拒绝服务；将预先测试工具以降低风险，但无法绝对保证不发生拒绝服务。生产系统上某些软件可能对攻击产生负面响应导致崩溃。

## INSIDE THE EXAM

### 渗透测试

Security+ 考试重点：
- 渗透测试属于**主动评估**，因其实际尝试绕过安全控制并入侵系统。
- **必须**获得高层管理人员书面许可方可执行评估。
- 即使无意发起拒绝服务攻击，系统对黑客工具的响应仍可能导致拒绝服务。

## 评估技术

了解常见安全评估类型后，介绍执行评估的具体技术。渗透测虽是热门术语，但掌握其他安全测试方法同样重要。

### 基线报告

基线报告通过采集系统正常运行时的基线状态，再将其与性能数据对比。常用于涉及拒绝服务或恶意软件导致系统性能不达预期的安全事件。

评估时，对比当前性能与基线以定位问题。例如：某日服务器变慢，性能监视器显示 CPU 占用 89%，但业务无异常；基线显示正常 CPU 占用为 29%。这表明有进程占用大量 CPU。可使用性能监视器追踪占用 CPU 周期的软件。

### 代码审查

虽身为程序员不愿承认，但大多数安全问题源于开发人员以不安全方式构建应用。例如：安全编码的关键规则是验证发送给应用的所有数据，否则黑客可实施 SQL 注入或缓冲区溢出攻击。

应定期对内部开发软件进行代码审查。安排专门的安全测试人员审查开发人员编写的所有应用代码，查找可能导致安全问题的代码错误。

> **考试重点**：术语 `攻击面` 指系统上运行的软件和服务。

### 确定攻击面

通过确定系统的攻击面来评估安全。攻击面包括系统上安装的所有软件和运行的服务。作为安全专业人员，关键职责是协助组织通过移除不必要的软件和服务来缩减攻击面。
