

# 加密数据时，加密操作既可以由系统上的软件执行，也可以由硬件（安装在系统上的计算机芯片）执行。基于硬件的加密优于软件解决方案，由于计算的复杂性，你会发现硬件解决方案能更快地完成工作。

# 可信平台模块 (TPM)

可信平台模块 (TPM) 是系统上的一个计算机芯片，用于存储加密数据所用的加密密钥。使用密码加密数据的应用程序容易遭受字典攻击；TPM 内置了防字典攻击模块。Windows BitLocker 支持使用 TPM 存储密钥。但请记住，要在系统上使用 TPM，必须拥有支持 TPM 的 BIOS。

## 通过隐匿实现安全

通过隐匿实现安全是一种安全原则，即将技术的设计或实现变得极其复杂，从而使其保持机密。例如，你可以将系统文档写得晦涩难懂，使其无法被完全理解。或者你可以将应用程序或系统的命令设计得晦涩难懂，以至于攻击者需要花费很长时间才能入侵系统，因为他们首先必须学习该系统。我必须强调，**不应将通过隐匿实现安全作为唯一的安全方法！**

## 加密通信

如果你在网络或互联网上发送或接收机密信息，甚至在移动设备上通信时，都要确保通过安全通道进行通信。`安全通道` 是一种已建立的通信对话，它加密对话中系统之间发送的流量。

### 安全通信协议/传输加密

你可能需要加密的常见流量类型包括 Web、电子邮件、Telnet 和 FTP 流量。在设计或评估安全性时，你要确保使用尽可能最安全的通信协议。Security+ 认证考试要求你根据场景了解应实施哪些安全协议。以下是成熟技术或应用程序用于加密传输中通信（网络流量）的常见安全协议：

*   **HTTP Secure (HTTPS)** 不应使用 HTTP（非安全 Web 流量的协议），而应使用 HTTPS，也称为 Secure HTTP (SHTTP)。HTTPS 使用 SSL（下文讨论）来加密客户端与 Web 服务器之间的通信。HTTPS 的一个使用场景或用例是：如果你有一个允许客户更新其个人资料信息的网站，并且希望确保其信息在穿越互联网时经过加密。

*   **安全套接字层 (SSL)/传输层安全性 (TLS)** 多年来，SSL 一直是加密流量（如 Web 和电子邮件流量）的流行协议。TLS 是一种更安全的协议，旨在取代 SSL。SSL 或更新的 TLS 协议可用于加密组织内部服务器之间的通信。你也可以用它来保护组织内部或与合作伙伴公司之间两台电子邮件服务器之间的通信。

*   **安全多用途互联网邮件扩展 (S/MIME)** S/MIME 是网络上用于加密电子邮件消息的协议。例如，S/MIME 可用于加密来自客户端的电子邮件消息。

*   **安全实时传输协议 (SRTP)** 对于使用 RTP 的语音和视频会议应用程序，如果你担心有人捕获你的语音和视频流量并回放，可以实施 SRTP 作为替代协议。它为语音和视频通信提供加密和认证服务。

*   **基于 SSL 的轻量级目录访问协议 (LDAPS)** LDAPS 是一种安全的目录服务访问协议，当安全性是关注点时，应使用它代替 LDAP，因为它加密与目录服务器的所有通信。

*   **域名系统安全扩展 (DNSSEC)** DNSSEC 是 DNS 的一项重要安全协议。DNSSEC 不加密与 DNS 服务器的通信，但确实为 DNS 记录增加了完整性，以便客户端知道 DNS 数据是否被未经授权的人员修改。DNSSEC 通过向每条记录添加包含数据哈希值的数字签名来实现这一点，该哈希值可被验证。

*   **互联网协议安全 (IPSec)** IPSec 是一种流行的安全协议，旨在加密所有 IP 流量，而不管应用程序如何。IPSec 有两种模式：传输模式和隧道模式。使用 `传输模式` 时，仅对数据包的有效载荷（数据部分）进行加密。使用 `隧道模式` 时，对数据包的头部和数据都进行加密。IPSec 对不同的加密服务使用不同的协议：

    *   **认证头 (AH)** 负责 IPSec 中的数据完整性和发送方认证。
    *   **封装安全载荷 (ESP)** 通过加密数据包中的数据（也称为有效载荷）来提供数据完整性、认证和数据机密性。

    IPSec 的一个使用场景是：如果你需要加密所有网络流量，或者可能是加密一组系统之间的所有网络流量。

    > **考试重点：请记住，AH 提供数据完整性和认证，但不提供数据机密性（加密）。ESP 在 IPSec 中提供数据完整性、认证和数据机密性。**

*   **安全外壳协议 (SSH)** SSH 旨在成为 Telnet 的安全替代品，并提供认证和加密服务。SSH 可用于创建加密通道，以便通过该通道的通信经过加密。SSH 的一个常见使用场景是对交换机和路由器进行远程访问。

*   **FTP Secure (FTPS)** FTP Secure，也称为 FTP-SSL，应作为 FTP 的安全替代品使用，因为它使用 SSL 或 TLS 安全协议加密 FTP 通信。

*   **SSH FTP (SFTP)** SFTP 是 SSH 的扩展，允许通过 SSH 通道安全地传输和管理文件。请注意，这与 FTPS 不同，后者使用 SSL 或 TLS 来保护 FTP 流量。

*   **简单网络管理协议 v3 (SNMPv3)** 与早期版本的 SNMP 相比，应使用此版本，因为它提供认证和通信加密功能。SNMP 用于监控和管理网络上的设备，如路由器和交换机。你应该检查这些设备，并验证它们是否使用 SNMPv3 而不是版本 1 或版本 2。

*   **安全邮局协议/互联网消息访问协议 (安全 POP/IMAP)** 当你有一个位于互联网上的电子邮件客户端，将使用 POP 或 IMAP 连接到公司电子邮件服务器时，这些协议以未加密格式发送数据（包括用户名和密码），你应该考虑使用安全 POP 或安全 IMAP 来加密通信。安全 POP 和安全 IMAP 均使用 TLS 或 SSL 来保护电子邮件通信。

*   **安全复制协议 (SCP)** 与 SFTP 类似，SCP 运行在 SSH 通道之上，以加密用于传输文件的通信。

*   **无线** 你应该使用 WPA2 加密无线通信。

### 安全协议的用例

在许多常见场景中，你应该使用安全协议而非协议的非安全版本。以下列出了一些关键场景：

*   **语音和视频** 如果你的组织使用 VoIP 解决方案，请务必使用 SRTP 加密网络上的语音流量。

*   **时间同步** 许多网络设备（如路由器和防火墙）都具备连接到时间同步服务器以维持设备时间的能力。
