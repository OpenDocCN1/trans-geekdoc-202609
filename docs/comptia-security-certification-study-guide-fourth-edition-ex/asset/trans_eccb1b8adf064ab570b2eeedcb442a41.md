**对于 Security+ 认证考试，请记住基于角色的访问控制涉及将用户放入容器（称为角色），并为这些角色分配执行特定任务的特权。当用户被放入角色时，他们将继承该角色被分配的任何能力。**

许多应用程序使用 RBAC，例如 Microsoft SQL Server 和 Microsoft Exchange Server。以下练习展示了如何通过将某人放入 `sysadmin` 角色来授予其对 SQL Server 的管理访问权限。

### 练习 11-1

![Images](video.jpg)

**为用户分配 sysadmin 角色**

在本练习中，您将为用户分配 `sysadmin` 角色，这是 SQL Server 中被授权执行所有 SQL Server 管理任务的角色。在本练习中，您需要访问已配置为 SQL Server 安全模式的 Microsoft SQL Server 系统。

1.  登录到 SQL Server，然后从“开始”菜单启动 SQL Server Management Studio。
2.  选择“连接”，使用 Windows 身份验证登录到本地服务器。
3.  Management Studio 启动后，展开 `(Local) | Security | Server Roles`。注意 `sysadmin` 角色。

![Image](f0481-01.jpg)

4.  双击 `sysadmin` 角色以向其中添加用户。请注意，在我的示例中，Windows Administrator 账户已在该角色中。这允许 Windows 系统的管理员管理 SQL Server。
5.  单击“添加”按钮以将登录名添加到该角色。键入登录名，然后单击“确定”。
6.  单击“确定”关闭 `sysadmin` 对话框。

#### 基于属性的访问控制

基于属性的访问控制 (ABAC) 是一种访问控制模型，涉及向用户和资源分配属性，然后在规则中使用这些属性来定义哪些用户可以访问哪些资源。例如，您可以配置一条规则，指定如果用户具有“Accounting”部门属性和“Boston”城市属性，则他们可以访问该文件。这与 RBAC 或 GBAC 不同，因为那些模型仅检查用户是否在角色或组中。

#### 其他访问控制工具

许多其他工具可以与访问控制结合使用。以下是一些用于控制访问的其他工具：

*   **条件访问** 在设置系统访问控制时，您可能有选项指定访问的条件。这在基于声明的环境中很常见，因为访问令牌可以包含用户的城市或部门以及他们正在使用的设备等属性。您可以在权限上设置条件，例如：“如果用户的部门是 accounting 且他们使用的设备的部门是 accounting，则用户获得修改权限。”
*   **特权访问管理** 这是限制哪些用户账户拥有对系统的特权访问的概念。作为降低安全妥协风险的一种技术，您应该限制哪些用户账户拥有系统的管理员特权。如果拥有系统管理员特权的用户意外运行了恶意代码，该代码可能会损害系统。
*   **文件系统权限** 正如您在本章中所学，您可以在每个操作系统中的文件夹和文件上实现文件权限，作为控制谁可以访问数据的一种方式。

### 实施访问控制

现在您了解了各种访问控制模型，让我们看看访问控制在不同环境中是如何实施的。在本节中，您将了解安全组、权利与权限的区别，以及如何在路由器上实施访问控制列表。

#### 身份标识

*身份标识* 是访问系统或数据的人员。身份标识的最佳示例是用户账户，但也可能是计算机账户或组。身份标识也称为安全主体，并被授予对系统或网络上资源的访问权限。

身份标识存在于*身份提供程序* 中。身份提供程序是创建用户和组的数据库或身份验证系统。例如，Active Directory 是基于 Microsoft 域的网络的身份提供程序。

每个对象（如用户账户）都具有随账户存储的*属性*。属性示例包括名、姓、用户名、城市、部门、登录时间——列表还在继续。

身份标识可以由其他对象表示或识别，例如在登录系统时使用*数字证书*或 *SSH 密钥*。您将在 [第 12 章](#ch12.xhtml#ch12) 和 [第 13 章](#ch13.xhtml#ch13) 中了解更多关于证书的信息。代表用户的数字证书可以放置在*智能卡* 上，插入系统以便向系统进行身份验证。用户还需要输入与智能卡关联的 PIN 码。

*令牌* 也用于控制对系统的访问。这可能是您必须持有以便刷卡访问系统的硬件令牌，也可能是在登录过程中生成的软件令牌。

#### 账户类型

在控制对资源的访问时，您通常应首先为组织内的每个人定义用户账户。重要的是要知道，拥有用户账户有不同的原因，因此存在不同类型的账户：

*   **用户账户** 您组织内的每位员工都应分配一个单独的用户账户，供他们用来访问网络和系统。此用户账户不应被任何其他人使用，因为它代表该特定用户并控制员工将有权访问的资源。您还将通过记录用户账户执行的操作来监控员工活动，因此请强调员工不要共享其账户的密码。
*   **共享和通用账户/凭据** 您有时可能会考虑创建一个由多个员工共享的账户，因为他们共享相同的工作角色。例如，Sue 是上午的会计文员，而 Bob 是下午的会计文员。您可能会考虑创建一个名为 `AccountingClerk` 的共享账户，让每位员工使用该账户，而不是创建多个账户。但请记住，从安全角度来看，安全专业人员尽量避免让多个员工共享一个账户。出于监控和审计的目的，能够记录 Bob 执行了哪些操作、Sue 执行了哪些操作是非常受青睐的。日志中有一条 `AccountingClerk` 删除了文件的记录无法帮助您确定是谁执行了该操作。当心共享或通用账户！
