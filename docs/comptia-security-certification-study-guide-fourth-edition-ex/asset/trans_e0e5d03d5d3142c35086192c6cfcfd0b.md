

### 签发 CA

您必然会遇到的一个常见问题是：签发证书的 CA 应该是您的应用程序所“信任”的 CA。默认情况下，应用程序信任由知名 CA（如 Entrust、Verisign 和 GoDaddy）签发的证书，而不信任您创建的内部 CA 签发的证书。当应用程序使用不受信任的证书时，会出现警告消息，告知用户该证书是由未知 CA 生成的。为了消除警告消息，您应该使用受信任 CA 的证书，或将您的 CA 证书导入受信任证书列表中。

### 主题名称

当应用程序尝试使用证书时，它会检查证书上的主题名称，有时称为通用名称 (CN)。如果主题名称与您正在访问的、使用该证书的地址（URL）不匹配，则会出现警告消息。较新的 X.509 标准允许将多个备用主题名称应用于证书，以便您可以将多个名称与一个证书关联。例如，我可以将 `mail.gleneclarke.com` 和 `server1.gleneclarke.com` 也分配给证书，而不仅仅是分配 `http://www.gleneclarke.com`。

### 实施 RA

在实施注册机构时，您必须制定一项政策，规定组织内部人员如何执行证书请求。该政策应定义谁可以请求证书、需要填写哪些表格，以及 RA 需要对请求执行哪种类型的验证。

### 安装 CA

如果您想为企业内部用途创建自己的证书，则需要安装 CA。要在 Windows 服务器上安装 CA，请遵循以下练习中的步骤。

#### 练习 13-1

![Images](video.jpg)

**安装证书颁发机构**

在本练习中，您将在 Windows Server 上安装 Active Directory 证书服务 (ADCS)，以创建证书颁发机构。

1.  从“开始”菜单启动“服务器管理器”。
2.  在“服务器管理器”中，选择 **“管理”** | **“添加角色和功能”**。
3.  在 **“开始之前”** 页面上，单击 **“下一步”**。
4.  在 **“选择安装类型”** 页面上，单击 **“下一步”** 以安装角色或功能。
5.  在 **“选择目标服务器”** 页面上，请注意已选中 `ServerA.certworld.loc` 服务器，然后单击 **“下一步”**。
6.  在 **“选择服务器角色”** 页面上，选中 **“Active Directory 证书服务”** 复选框以安装它，然后选择 **“下一步”**。
7.  当弹出窗口要求添加所需功能时，选择 **“添加功能”**。
8.  连续单击三次 **“下一步”**。在 **“选择角色服务”** 页面上，确保同时选中 **“证书颁发机构”** 复选框和 **“证书颁发机构 Web 注册”** 复选框。然后单击 **“下一步”**。
9.  单击 **“安装”**。安装将需要几分钟，完成后单击 **“关闭”**。
10. 现在您已安装证书颁发机构，可以通过选择标志图标（位于 **“管理”** 的左侧），然后选择链接 **“在此服务器上配置 Active Directory 证书服务”** 来执行初始配置。在 **“凭据”** 页面上，请注意正在使用管理员账户（在底部），然后单击 **“下一步”**。
11. 在 **“角色服务”** 页面上，同时选中 **“证书颁发机构”** 和 **“证书颁发机构 Web 注册”** 复选框，然后单击 **“下一步”**。
12. 接下来，在 **“安装类型”** 页面上，系统会询问您希望执行的安装类型：
    *   **企业 CA**：用于在 Active Directory 环境中创建根 CA。
    *   **独立 CA**：用于在不属于 Active Directory 环境的服务器上创建根 CA。

![Images](f0569-01.jpg)

13. 在此示例中，选择 **“企业 CA”**，然后单击 **“下一步”**。
14. 在 **“CA 类型”** 页面上，系统会询问您是创建根 CA 还是从属 CA。您可以创建证书服务器的层级结构，首先安装的 CA 为根 CA，其下的子服务器为从属 CA。大型公司可能需要多个从属 CA 来帮助分担创建证书的工作负载。选择 **“根 CA”**，然后单击 **“下一步”**。
15. 在 **“私钥”** 页面上，选择 **“创建新私钥”**。这是 CA 创建其自己的自签名证书（私钥），它将用该私钥为其创建的所有其他证书签名，以便应用程序知道证书的来源。单击 **“下一步”**。
16. 在 **“CA 加密”** 页面上，接受用于签名证书的密钥强度和哈希算法的默认值。单击 **“下一步”**。
17. 在 **“CA 名称”** 页面上，为 CA 的通用名称键入计算机名称。请注意，完全可分辨名称是根据域名生成的。单击 **“下一步”**。
18. 在 **“有效期”** 页面上，为 CA 生成的自签名证书指定 **“5 年”** 的有效期。然后单击 **“下一步”**。
19. 在 **“证书数据库”** 页面上，接受存储证书服务数据库的默认文件夹位置。单击 **“下一步”**。
20. 在 **“确认”** 页面上，单击 **“配置”** 以接受所有设置。单击 **“关闭”**。
21. 要验证证书服务是否已安装，请通过在服务器管理器中选择 **“工具”** | **“证书颁发机构”** 来启动证书服务管理工具。启动管理工具后，展开左侧的服务器，您可以看到以下文件夹：
    *   **“吊销的证书”**：包含已被吊销的任何证书。
    *   **“已颁发的证书”**：包含由 CA 颁发的任何证书。
    *   **“挂起的请求”**：包含仍在颁发过程中任何证书请求。
    *   **“失败的请求”**：包含 CA 未能颁发的任何证书。
    *   **“证书模板”**：包含证书模板，这些是您 PKI 中可存在的证书类型的定义。

### 配置 SSL

现在您已安装 CA，可以向 CA 发送请求，获取供应用程序使用的证书。证书最常见的用途之一是将证书安装在 Web 服务器上用于 SSL，以加密客户端和服务器之间的流量。

在 Web 站点上配置 SSL 或将证书应用于任何应用程序时，主要有四个步骤：

1.  **创建请求。** 第一步是创建证书请求，也称为 *证书签名请求 (CSR)*。您通常导航到 CA 的网站以填写 Web 表单来创建请求，或从实际应用程序创建请求。例如，Microsoft 的 IIS 和 Exchange Server 都提供了用于创建证书请求的向导。创建请求后，它将存储在文本文件中。您也可以从 Microsoft 管理控制台 (MMC) 中的“证书”管理单元创建证书请求。
2.  **提交请求。** 将请求存储在文本文件中后，您即可将请求（文本文件的内容）提交给 CA。同样，您可以通过导航到 CA 的网站来执行此操作。
3.  **下载证书。** 通过网站提交请求后，您需要将生成的证书下载到计算机上。通常在“提交请求”阶段结束时会提供一个用于下载证书的链接。
4.  **安装证书。** 下载证书后，您可以将其安装在应用程序中。
