

### 密码保管库
密码保管库是一种加密数据库，用于存储用户可能访问的本地系统和网站的许多不同密码。密码管理器软件生成复杂密码，并为不同系统检索它们。

### TPM
可信平台模块（`TPM`）是系统上的一个计算机芯片，可用于存储具有加密驱动器的系统的加密密钥。`TPM` 还可与安全启动配合使用，以确保启动环境的完整性。

### HSM
硬件安全模块（`HSM`）是一种可添加到系统的卡，用于生成和存储加密密钥。它还可根据需要对系统上的数据执行加密和解密。

### 基于知识的认证
当验证您身份的系统或人员询问只有您知道的信息时。例如，如果您致电银行，他们可能会询问您账户上次购买的信息；如果您致电加拿大税务局（`CRA`），他们会询问您去年纳税申报表的详细信息，例如“您去年纳税申报表第 150 行的金额是多少？”

#### 单点登录
关于认证的一个重要概念是单点登录，也称为 `SSO`。单点登录的原则是：当您向网络进行身份验证时，您有能力根据您的身份验证信息访问多个系统。使用 `SSO`，您无需向访问的每个不同系统进行身份验证——您只需验证一次，然后即可在无需再次验证的情况下访问多个系统。

为什么 `SSO` 如此有价值？多年前，您必须单独向每台服务器进行身份验证。这意味着每个系统都存储一个单独的用户名和密码数据库，用户必须记住各种密码才能访问多台服务器。使用 `SSO`，用户使用一组凭据登录，然后访问许多不同的服务器，甚至是其他组织的服务器。针对您组织中的身份存储进行身份验证，并被授权使用其他组织的网络服务，称为*身份联合*。

![Image](exam.jpg)

**Security+ 考试要求您知道单点登录（`SSO`）允许用户向网络进行一次身份验证，并访问多个系统，而无需提供额外的凭据。**

`SSO` 的好处在于，作为网络管理员，您无需为每台服务器管理多个用户名和密码。然而，同时 `SSO` 的缺点是，如果黑客攻破了账户，他们可以访问多台服务器。如果您不在 `SSO` 环境中，黑客攻破了账户，他们将只能访问那台服务器，并需要攻破另一个密码才能访问不同的服务器。

**对于 Security+ 考试，请知道 `SSO` 环境存在风险。如果黑客能够破坏认证方案，例如破解密码，那么他们就能访问网络上的多个系统。**

##### 访问令牌
当用户登录到系统或网络时，会为该用户创建一个访问令牌，用于确定他们是否应被允许访问资源或执行操作系统任务。此逻辑令牌维护资源验证所需的所有信息，并包含以下信息：

- **安全标识符（`SID`）** `SID` 是分配给用户的唯一编号。`SID` 是 Windows 用来识别用户的标识，而不是实际的用户名。我们知道 Bob 是 `bsmith` 用户账户，但 Windows 通过他的 `SID` 认识 Bob，看起来类似于 `S-1-5-21-2752813485-788270693-1974236881-116`。
- **组安全标识符** 访问令牌包含用户所属的任何组的列表。这很重要，因为当用户双击资源时，资源通常配置有分配给组的权限。Windows 通过访问令牌检查用户属于哪些组，然后检查这些组中是否有一个拥有对所访问资源的权限。如果访问令牌中包含的组被允许访问该资源，用户将获得对该资源的访问权限。
- **主要组安全标识符** 为符合 POSIX 标准，您可以指定主要组——即在 POSIX 环境中成为文件和目录所有者的组。主要组默认设置为“域用户”，在 Microsoft 环境中很少使用。
- **访问权限** 在登录过程中，Windows 确定您在操作系统中的权利，并将权利列表存储在访问令牌中。例如，如果您拥有“更改系统时间”权利，该信息会在登录过程中存储在访问令牌中。如果您尝试更改计算机上的时间，将检查您的访问令牌中是否有该权利；如果权利在访问令牌中，则允许您更改系统时间。

重要的是要注意，访问令牌仅在登录时创建，因此如果您将用户添加到新组，该用户需要注销并重新登录，访问令牌才会在组成员列表中包含新组。再次登录后，用户应该能够访问新添加的组可以访问的任何资源，因为访问令牌已更新。

#### 云与本地部署需求
当我们查看本地部署环境的认证方案时——即您日常访问的本地 LAN 或 WAN 上的服务器——大多数系统要求您首先向网络进行身份验证。对于常规网络，您通常只需使用用户名和密码登录，但对于高安全性网络，您可能会使用某种形式的多因素认证（`MFA`）。

对于基于云的环境或任何需要身份验证的网站，您应该考虑实施 `MFA`。大多数云服务允许用户将移动设备注册到其用户账户，以便当他们登录时，验证码会发送到他们的手机，然后他们必须输入该验证码以证明他们是他们声称的人。这确保了即使有人弄清了您的用户名和密码，也无法进入该网站或云服务。

### 认证目标 10.02

### 认证协议
当用户提供用户名和密码等凭据时，它们会通过认证协议传递给认证服务器。认证协议决定了认证信息如何从客户端传递到服务器。在本节中，您将了解不同的认证协议。

#### Windows 认证协议
我要介绍的第一类认证协议是 Windows 认证协议。这些认证协议存在于 Internet 信息服务（`IIS`）和 Exchange Server 等 Microsoft 产品中。以下是 Microsoft 世界中使用的许多认证方法的说明：

- **匿名认证** 您无需登录服务器。Windows 使用实际服务的账户，您将作为该账户被传递。匿名账户拥有什么权限，您在匿名连接时就拥有什么权限。这是网站和 FTP 服务器常用的认证方法。
- **基本认证** 您需要登录，用户名和密码以明文形式发送到服务器。这意味着如果有人在您和服务器之间使用数据包嗅探器，该人将能够捕获您的密码并查看它，因为它未加密。
