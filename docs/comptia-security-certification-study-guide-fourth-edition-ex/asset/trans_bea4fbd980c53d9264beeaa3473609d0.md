## 使用 SOAR

在讨论帮助我们监控安全事件的企业级解决方案时，我们还应该讨论 *Security Orchestration, Automation, and Response*（安全编排、自动化与响应）的概念，简称 **SOAR**。**SOAR** 不仅仅是一个监控工具；它更像是一个安全管理工具。借助 **SOAR**，您可以使用软件工具帮助您简化并自动化安全运营，重点关注三大领域——威胁与漏洞管理、安全事件响应和安全运营自动化。

公司可以使用 **SOAR** 从不同来源收集安全事件数据，检测安全威胁，然后自动响应威胁以采取某种形式的纠正措施。

## 实施日志记录和审计

现在您了解了一些可用于监控系统的工具，让我们来谈谈审计和日志记录。作为一名安全专业人员，您需要确保评估系统和应用程序上已启用的审计和日志记录级别。以下是审计和日志记录区别的快速定义：

- **Auditing（审计）** 通常是指您出于安全目的希望在系统或应用程序上监控的操作。例如，您可能希望审计系统上的用户账户管理或应用程序中的客户记录删除操作。
- **Logging（日志记录）** 通常是指记录应用程序或系统中发生的所有活动。例如，您可以记录对网站的所有请求，稍后再查看日志。

### 理解审计

作为任何环境中的安全专业人员，请确保已在所有关键系统和设备上启用审计，并确定已配置的审计级别。至关重要的是，必须有人接受过如何查看审计日志的培训，并知道如何将其归档到安全位置，以防需要回溯。

配置审计主要有四个步骤：

1. 决定审核哪些事件。
2. 决定您关心每个事件的成功还是失败。
3. 配置审计。
4. 定期查看审计日志。

#### 配置审计

配置审计的第一步是定义您的审计策略。在定义审计策略时，为操作系统中的特定事件启用审计。*事件* 是指系统中发生的事情，通常由用户调用。例如，登录或注销网络是一个事件。访问文件夹也是一个事件。因此，您需要确定希望收到通知的事件——相信我，您在启用哪些事件方面必须极其挑剔！重要的是要记住，您审计的事件越多，收集的信息就越多——您不想收集不必要的信息，因为这可能会掩盖重要的审计数据。

在 Windows 中，您可以通过单个系统的本地安全策略实施审计，也可以使用 Active Directory 中的组策略将审计设置部署到多个系统。要在 Windows 中配置审计，请从以下工具中选择一项来管理审计策略：

- **Start | Administrative Tools | Local Security Policies（开始 | 管理工具 | 本地安全策略）** 在单个独立系统上实施审计。
- **Start | Administrative Tools | Domain Controller Security Policy（开始 | 管理工具 | 域控制器安全策略）** 在网络上的所有域控制器上实施审计。
- **Start | Administrative Tools | Domain Security Policy（开始 | 管理工具 | 域安全策略）** 在整个 Active Directory 域中的所有系统上实施审计。

启动正确的管理工具后，您可以为许多事件启用审计（请参阅 [Figure 19-5](#ch19.xhtml#ch19fig5)），并且在启用审计时，您必须决定关心此类事件的成功还是失败。例如，您是否关心某人成功登录网络还是登录失败？

#### 查看审计日志

配置审计后，您将使用 Windows 事件查看器来监控您已启用审计的安全相关事件。以下是您可以在 Windows 事件查看器中查看的一些日志列表：

- **Application log（应用程序日志）** 存储在 Windows 上运行的应用程序的错误和信息
- **System log（系统日志）** 存储操作系统组件的错误、警告和信息，例如服务启动失败时
- **Security log（安全日志）** 存储审计信息和其他安全相关事件
- **DNS log（DNS 日志）** 存储域控制器上 DNS 的错误和信息
- **Hardware Events log（硬件事件日志）** 存储与系统硬件组件相关的信息
- **Windows PowerShell log（Windows PowerShell 日志）** 存储与系统上 PowerShell 环境相关的信息和错误

启用审计后，您在 Windows 事件查看器中监控 **Security log（安全日志）**，因为所有审计数据都显示在那里。[Figure 19-6](#ch19.xhtml#ch19fig6) 显示了 Windows Server 中的 Windows 事件查看器。在事件查看器中，您可以查看各种事件，将日志内容保存到文件以供存档，然后清除日志以开始新的记录。归档日志非常重要，以防需要回溯。许多安全问题直到事件发生很久后才被发现。Windows 还允许您将日志文件存储在任何位置，包括另一台安全主机上。
