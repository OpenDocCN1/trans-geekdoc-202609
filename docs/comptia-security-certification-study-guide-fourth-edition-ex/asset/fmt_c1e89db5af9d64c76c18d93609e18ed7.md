
### Identifying Encryption Uses

This section discusses some common uses of encryption in today’s computing and networking environments using proven technologies. Encryption is used to encrypt data in storage, but is also used to encrypt communication between systems or people.

#### Common Use Cases

There are a number of situations where different cryptographic concepts and technologies are used on a daily basis. The following outlines some common scenarios where you see these concepts in practice:

- **Low-power devices** Using low-power devices is a method we use today to restrict how far a communication signal can go. For example, you should be lowering the power on your wireless signal so that someone outside the building cannot get a connection to your wireless network.
- **Low latency** Latency is a measure of network performance on a daily basis. Low latency means the wait time for a response is minimal. For example, you would want the latency low between your client system and the authentication server.
- **High resiliency** Resiliency refers to how resilient a solution is to failure. Examples of technology used to provide high resiliency are high-availability solutions (for example, clustering and RAID) and load-balancing solutions.
- **Supporting confidentiality** There are a large number of technologies used to maintain confidentiality, including any encryption technology, such as `WPA2` for wireless, and disk encryption, such as `BitLocker`.
- **Supporting integrity** An example of when integrity solutions are used is when you create `MD5` or `SHA-1` hashes of a file so that when the file is downloaded by someone, they can verify that they have an unmodified version of the file.
- **Supporting obfuscation** Encryption algorithms and the different block modes are an example of obfuscation.
- **Supporting authentication** Client-side certificates and two-factor authentication with web sites are examples of concepts that support authentication.
- **Supporting nonrepudiation** When you digitally sign an e-mail message, you are supporting nonrepudiation to ensure that the sender cannot dispute that they sent the message.
- **Resource vs. security constraints** There are many use cases for when a resource may conflict with a security constraint. For example, wireless is built into many devices today, and some companies have a policy of not allowing wireless. In this case, the wireless functionality is disabled on the device because the company security constraint has superseded the resource.

#### Understanding Limitations

The Security+ exam expects you to understand the different encryption protocols and the risks involved with some of the limitations of each protocol. For example, if an application is using `DES` or `3DES`, the security risk is that they are weak encryption methods, as those are old standards that have been cracked. The following are some of the limitations with encryption standards to be aware of:

- **Speed** Know that symmetric encryption is faster than asymmetric encryption, which is why many technologies use both methods—symmetric for the speed and asymmetric for the key management.
- **Size** Know that the larger the key size, the stronger the encryption. For example, `256-bit AES` encryption is stronger than `128-bit AES` encryption.
- **Weak keys** Using weak encryption keys can make the encryption vulnerable to attack. Using an encryption standard with the largest key size possible would lower the risk of the key being cracked.
- **Time** Know that different encryption types will take longer to encrypt and decrypt larger amounts of data. For example, using symmetric encryption to encrypt a large file will take less time than asymmetric encryption.
- **Longevity** Knowing the life expectancy of an encryption protocol or application is important to be aware of. You do not want to invest in a technology that is no longer acceptable a short time after implementation.
- **Predictability** Using technologies that make it difficult to predict random values used by the technology. For example, using `IVs` that are predictable could present risk to the privacy of the data being encrypted.
- **Reuse** Reusing keys could present security risks to your environment, as it can help an attacker crack the encryption key.
- **Entropy** Entropy is random information about a system that an encryption application uses to encrypt data. An application that does not create good entropy could be vulnerable to having data decrypted by an attacker.
- **Computational overheads** The more advanced the encryption algorithm, the more processing power that is needed by the system. You can use a `GPU` to handle the computational overhead of strong encryption applications.
- **Resource vs. security constraints** Related to the computation overhead, the stronger the encryption algorithm and key size, the more resources (RAM and processor) that are being used. Finding a balance between getting good security and not overloading the system is important.

#### Encrypting Data

If you want to ensure that your company information is not viewable to unauthorized individuals, you will need to encrypt the data. When looking at encrypting data, consider encrypting the following:

- **Data in transit** Encrypt data as it travels across the network from the source to its destination so that if someone taps into the communication, they will not be able to read the data. You will learn about communication encryption protocols later in this chapter.
- **Data at rest** When storing information on disk or in a database, encrypt the data so that if someone gets access to the drive or database, they cannot view the sensitive data.
- **Data in use** Encrypt data when it is stored in `RAM`, the `CPU cache`, or even the `CPU registers`. The purpose is to ensure someone cannot get access to sensitive data by writing code that would retrieve data from these areas.

Let’s focus on data in storage here and review some of the key points you learned in [Chapter 7](#ch07.xhtml#ch7). As a review, you can use any of the following proven technologies to encrypt data in storage:

- **Full disk** Most operating systems today support full-disk encryption (`FDE`). For example, Windows has `BitLocker`, which allows you to encrypt the contents of the entire drive, including the operating system, or encrypt specific partitions. In order to fully boot the system, an individual would need to know the key so that the encrypted contents can be decrypted.
- **Database** When storing information in a database, it is critical that you encrypt sensitive information. For example, if your company has an application that stores customer credit card numbers, or even customer passwords, you should encrypt that data in the database because a hacker could gain access to the database and discover this information. Many database products allow you to encrypt the entire database so if an attacker steals the database files, they are unable to read the data because the decryption key is not present on their system.
- **Individual files** If you are not encrypting the contents of the entire drive, then you can encrypt the contents of selected sensitive documents. For example, you can use the Encrypting File System (`EFS`) in Windows to encrypt individual files and folders.
- **Removable media** If you are storing data on a removable drive, such as a flash drive, be sure to encrypt all company data on this drive. It is too easy to lose or forget the flash drive somewhere, and if the data is not encrypted, it can be read by anyone!
- **Mobile devices** Most mobile devices will allow you to encrypt the contents of the mobile device so that if the device is lost or stolen, no one is able to retrieve the data on the device.
