
### 行业标准与框架

#### Center for Internet Security (CIS)
CIS 是一个成立于 2000 年的非营利组织，致力于制定和推广网络安全防御最佳实践，以帮助保护系统安全。您可以在 [www.cisecurity.org](http://www.cisecurity.org) 查阅最佳实践文档并下载网络安全工具。

#### National Institute of Standards and Technology (NIST) Risk Management Framework (RMF)/Cybersecurity Framework (CSF)
**NIST Risk Management Framework (RMF)** 是一份概述了将安全风险管理集成到系统开发生命周期中的步骤的文档。该框架分为七个阶段来执行风险管理，可在 [https://csrc.nist.gov/projects/risk-management/about-rmf](https://csrc.nist.gov/projects/risk-management/about-rmf) 访问。

**NIST Cybersecurity Framework (CSF)** 是 NIST 提供的一套资源，包含一系列策略，旨在帮助公司管理网络安全风险。该文档帮助组织了解应采取哪些安全措施和控制来降低资产风险并更好地保护资产。您可以在 [www.nist.gov/cyberframework](http://www.nist.gov/cyberframework) 查看 CSF。

#### NIST SP 800-171
NIST Special Publication 800-171 是联邦组织在非联邦系统上处理、存储和使用信息时保护信息的推荐标准。该框架定义了一系列可用于保护信息的技术控制。

#### International Organization for Standardization (ISO)/IEC 27001/27002/27701/31000
如前所述，ISO 制定了一系列作为国际标准的文档，指导读者如何在其组织内管理信息安全。以下概述了每个标准的目的：

*   **ISO 27001** 定义了如何在组织内管理安全，包括实施安全策略和安全控制，以协助资产管理、物理安全和运营安全。
*   **ISO 27002** 是对 27000 标准的更新，用于实施安全控制以帮助保护信息系统。
*   **ISO 27701** 定义了实施安全控制和流程以维护个人可识别信息 (PII) 隐私的标准。
*   **ISO 31000** 定义了一个框架，帮助组织管理其内部风险。

#### SSAE SOC 2 Type I/II
Service Organization Control (SOC) 2 是一项审计标准，服务提供商可用其确保客户数据受到保护。
*   **SOC 2 Type I** 审计旨在确认服务提供商已部署适当的安全控制。
*   **SOC 2 Type II** 审计更为深入，审计员将对组织内的安全控制和安全策略进行更彻底的审查。

#### Cloud Security Alliance
Cloud Security Alliance (CSA) 提供了一个框架，用于制定安全最佳实践以创建安全的云计算环境。CSA 通过提供 Cloud Control Matrix (CCM) 来实现这一点，CCM 是一份由 197 个控制目标组成的文档，分为 17 个域，涵盖了云计算的所有关键方面。您可以在 [cloudsecurityalliance.org](http://cloudsecurityalliance.org) 了解 CSA。CSA 还提供了一个称为 Enterprise Architecture 的参考架构，这是一种评估内部 IT 或云提供商安全能力的方法论。

### 基准/安全配置指南

此外，还有许多安全配置指南，提供关于保护特定类型产品或系统的最佳实践。NIST 发布了保护特定平台的步骤文档，但您也可能会发现产品供应商会发布自己的文档，说明如何保护其产品。NIST 安全配置指南的一个示例是 **Special Publication (SP) 800-123**，这是一份概述通用服务器安全应采取步骤的文档（即适用于任何服务器的安全实践）。

NIST 拥有涵盖不同类型产品的许多安全配置指南。例如，它提供了 Web 服务器（如 Microsoft IIS）、操作系统（如 Windows）、不同类型的应用程序服务器（如 Microsoft SQL Server 或 Microsoft Exchange Server 的安全配置）以及网络基础设施设备（如交换机和路由器）的安全配置指南。

许多供应商创建安全配置指南，解决其操作系统、软件和设备的最佳实践。以下是一些示例：

*   **Cisco IOS Security Configuration Guide, Release 12.4**  
    [www.cisco.com/c/en/us/td/docs/ios/security/configuration/guide/12_4/sec_12_4_book.html](http://www.cisco.com/c/en/us/td/docs/ios/security/configuration/guide/12_4/sec_12_4_book.html)
*   **VMware vSphere 6.5 Security Configuration Guide**  
    [https://www.vmware.com/security/hardening-guides.html](https://www.vmware.com/security/hardening-guides.html)

在寻找安全配置指南时，您可能会在以下类别中找到指南：

*   **Platform/vendor-specific guides (平台/供应商特定指南)**  
    供应商特定指南概述了应针对该供应商特定产品采取的关键安全配置步骤。
*   **Web server (Web 服务器)**  
    有安全配置指南概述了配置特定 Web 服务器（如 IIS 或 Apache）的关键步骤。
*   **Operating system (操作系统)**  
    操作系统配置指南概述了保护 Windows、macOS 和 Linux 等操作系统的关键配置步骤。
*   **Application server (应用程序服务器)**  
    应用程序服务器可以是 Microsoft Exchange Server、SQL Server 或 IBM WebSphere 等服务器。有安全配置指南概述应用程序服务器及其实施的最佳实践。
*   **Network infrastructure devices (网络基础设施设备)**  
    有许多针对不同供应商网络设备（如交换机、路由器和无线接入点）的安全指南。
*   **General-purpose guides (通用指南)**  
    通用指南概述了应遵循的通用安全实践，如修补系统、使用网络防火墙或使用基于主机的防火墙。这些是遵循通用安全实践的绝佳指南，但您也需要为您的产品寻找特定的供应商指南。
*   **Vendor diversity and control diversity (供应商多样性和控制多样性)**  
    这不是一份指南，而是指南中应识别的一个重要观点。您应该在环境中使用来自不同供应商的不同产品，这样如果黑客能够入侵一种产品，他们就无法使用相同的方法攻破另一种产品（不同产品具有不同的漏洞）。

### 认证总结

在本章中，您了解了安全策略的重要性，因为它为公司内部的安全计划奠定了基础。重要的是要确保不时审查和更新安全策略，以跟上当前的趋势和安全问题。以下是关于安全策略、培训和意识的一些关键点：

*   安全策略是一个由不同策略组成的大型文档。安全策略中常见的策略示例包括可接受使用策略、密码策略、无线策略和远程访问策略。
*   每个策略都应以一致的方式创建，所有策略中应包含相同的章节。例如，每个策略中都应包含概述、范围、策略、执行、定义和修订历史章节。
*   存在不同的策略类型——**标准** 是必须遵循的策略，**指南** 是不必遵循的建议，而**程序** 是演示如何执行任务的分步文档。
