### 版本控制与变更管理

拥有开发团队创建应用程序的大型组织将受益于使用版本控制功能，这些功能标识开发人员正在处理的应用程序版本。这是通过版本号或修订号来完成的。版本号可帮助您跟踪哪些文件代表了对文档所做的最近更改。版本控制软件可自动跟踪更改，并允许您在任何给定时间轻松恢复到之前的版本（如果您愿意）。

变更管理是您实施变更应遵循的流程。大多数公司都有变更管理策略，规定了如何进行变更。变更管理流程通常涉及变更规划、变更测试、变更应用，然后验证变更。变更管理还包括变更管理审批流程，即在实施变更之前必须获得批准，通常由 `变更咨询委员会 (CAB)` 批准。

### 供应与取消供应

在计划部署应用程序时，重要的是确保您已制定流程来供应将运行该应用程序的系统。`供应` 是设置新系统的过程。这是当今应用程序安全的关键部分，因为应用程序复杂且通常涉及使用多台服务器。您可能需要供应一台应用程序服务器、一台 Web 服务器和一台数据库服务器来部署应用程序。请确保供应系统以支持应用程序，但同时要确保遵循安全最佳实践，例如加固系统。供应的目标是确保系统合规，从而减少遭受攻击的漏洞。作为供应流程的一部分，您将授予用户对应用程序的访问权限。

`取消供应` 系统是将系统从应用程序环境中移除的过程。在取消供应应用程序或系统时，您首先会更改访问控制，以确保用户无法访问该系统或应用程序。重要的是要注意，如果您不取消供应（或移除）网络中的旧系统，它们最终可能无法打补丁，这会使这些系统容易受到攻击。

另一个例子是取消供应离职员工的用户账户。作为离职流程的一部分，您应该取消供应离职员工使用的账户，并确保他们不再有权访问这些系统。

### 完整性度量

完整性度量是一种用于验证文件是否已被系统上的软件修改的技术。完整性度量系统将关键操作系统文件的文件哈希存储在一个中央列表中，以便稍后可以通过将每个文件的当前文件哈希与文件哈希列表进行比较来验证。

## 安全编码技术

开发安全代码的两个重要部分是编写良好的异常处理例程和验证传递给应用程序的所有数据。

### 适当的错误处理

当应用程序开发人员创建应用程序时，他们有时无法预见不同情况下可能发生的错误。例如，创建“文件打开”对话框时的一个常见错误是，未计划用户在系统中未放置 DVD 时选择从 DVD 设备打开文件。这通常会导致 `运行时错误`——即直到应用程序运行时才会发生的错误——这意味着开发人员在创建应用程序时没有任何迹象表明该错误会存在。

运行时错误会发生，因为开发人员无法强制某人在浏览该资源之前将 DVD 放入 DVD 托架。因此开发人员必须做的是捕获此时发生的错误。`捕获` 错误意味着错误不会实际发生，而是程序员拦截该错误并显示友好的警告消息或采取某种纠正措施，而不是让应用程序崩溃（运行时错误会导致应用程序崩溃）。

异常处理是一种更高级的错误处理方法。`异常` 是运行时错误的一个花哨术语，诸如 .NET 或 Java 开发人员之类的程序员将实现异常处理代码。异常处理代码使用所谓的 `try/catch` 块——意思是“尝试这段代码并捕获任何错误”。以下代码是 `try/catch` 块的示例：

### 适当的输入验证

开发人员需要遵循这样一个理念：当有人将信息输入应用程序并单击“保存”、“查找”或“执行”等按钮时，开发人员必须在应用程序的某处使用该输入之前对其进行验证。`验证输入` 意味着开发人员检查以确保用户键入应用程序的信息对于预期的输入类型是合适的。任何未通过验证测试的输入都应被丢弃且不予处理。

![Image](exam.jpg)

**针对 Security+ 考试，请记住安全的内部应用程序必须从开发人员验证输入开始。您肯定会在 Security+ 考试中看到关于输入验证的问题！**

例如，在应用程序的登录屏幕上，用户需要键入用户名和密码。用户名和密码在大多数情况下是包含少于 14 个字符的短单词。程序员应该测试此输入，并确保用户名不超过 14 个字符，密码也不超过 14 个字符。此外，密码中没有空格，因此程序员应检查空格是否被用作字符之一——如果是，则应取消处理该信息，因为它可能是恶意的。要注意的其他字符示例包括破折号和撇号。它们通常不用于密码，但黑客会将它们输入登录屏幕以操纵软件的执行方式。

### 存储过程

存储过程是在数据库上创建的对象，它们封装了执行插入记录、删除记录和更新记录等操作所需的 SQL 代码。这些代码可以直接写在客户端应用程序（Web 应用、移动应用或桌面应用程序）中，但将数据库逻辑放在存储过程中有许多好处：

- **性能** 如果数据库代码在客户端应用程序中，当应用程序执行时，它必须将代码发送到服务器，服务器随后会解析代码、优化它、编译它并执行它。使用存储过程，解析、优化和编译仅在首次调用存储过程时完成。后续调用只需执行已缓存的、已编译的存储过程版本。

- **可维护性** 如果您将 SQL 代码放在存储过程中而不是每个软件应用程序中，您就有一个集中的位置来更新数据库逻辑。当逻辑需要更改时，您只需更改存储过程中的 SQL 代码，所有调用该存储过程的应用程序都将运行更新后的代码。
