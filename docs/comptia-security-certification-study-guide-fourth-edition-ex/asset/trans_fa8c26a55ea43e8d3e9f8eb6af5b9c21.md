

### 权限
在资源上实施权限是一种有助于确保可用性的方法，因为如果你限制谁可以删除数据，那么数据在需要时很有可能仍然可用。

### 备份
确保定期备份关键信息，以便在数据损坏或不可用时，能够从备份中恢复。

### 容错
你可以实施数据冗余解决方案，以确保如果其中一块硬盘发生故障，其他硬盘仍保存有该信息的副本。让多块硬盘以这种方式协同工作被称为 `RAID`，即独立磁盘冗余阵列。使用 `RAID` 时，如果其中一块硬盘发生故障，其他硬盘将提供缺失的数据。

### 集群
为确保电子邮件或数据库服务器等服务的可用性，你可以使用集群等高可用性解决方案。集群允许你让多台服务器作为一个整体运行，这样如果一台服务器发生故障，另一台服务器将接管工作负载。例如，你可以在两台服务器（称为 `节点`）上都安装电子邮件服务器，其中一台服务器充当活动节点（当前在线），另一台服务器充当被动节点（不在线）。当活动节点发生故障时，被动节点将变为活动节点，以便用户仍能访问电子邮件。

### 补丁管理
通过应用服务包和安全热修复程序使系统保持最新状态称为补丁管理。给系统打补丁有助于减少系统中的漏洞，并降低遭受攻击的几率。

#### 问责制
近年的一个趋势是让 CIA 中的 `A` 同时代表可用性和问责制（或者增加一个 `A` 来代表问责制，即 `CIAA`）。问责制是确保用户对其行为负责——例如，如果有人不当删除了文件，则会有该操作的记录以追究其责任。

你可以通过在系统、路由器、防火墙和应用程序中实施审计和日志记录功能，在组织内实现问责制。这里的概念是：如果你记录了活动，并能识别出是谁导致了某个特定事件的发生，就可以让该人对其行为负责。以下是在组织内实施问责制的一些常用方法：

### 日志文件
大多数网络服务要么默认实施日志记录，要么可以配置为将活动记录到日志文件中。请务必为网络上的所有核心服务启用日志记录，以便在发生事件时，你可以查看记录的数据。

### 审计文件
大多数操作系统都具有安全审计功能，允许你查看系统上发生的安全相关事件。在 Windows 中，这是事件查看器中的安全日志。请务必定期查看安全审计日志。

### 防火墙和代理服务器
大多数防火墙和代理服务器可以记录用户的出站活动，例如访问的网站和用于出站通信的应用程序。请务必定期查看防火墙和代理服务器日志，以追究用户对其行为的责任。

### 应用程序日志记录
在应用程序内记录活动变得越来越重要。例如，如果有人从采购系统中删除了客户记录或采购订单，你会想知道这件事。了解所有关键应用程序中可用的日志记录级别，并让用户知道你正在记录活动。这将有助于让他们对在业务软件中的行为负责。例如，Microsoft SQL Server 具有允许数据库开发人员在数据库应用程序中实施日志记录和审计的功能。

## 认证目标 2.02
## 理解认证与授权
保护环境安全的很大一部分是确保你实施某种形式的识别和验证组织内的个人，然后控制他们可以访问哪些资源、网站和设施区域。

本节旨在向你介绍认证和授权的概念。请注意，这些主题中的每一个都有专门的章节进行讲解，但我希望确保你在本章中对这些概念和术语有基本的了解。

### 识别与认证
识别发生在认证之前，是用户向系统标识自身身份的过程。公司用于识别个别用户的最流行方法是给每个用户分配一个唯一的用户名。用户将用户名输入系统以标识自己。

用户输入识别信息（用户名）后，输入该账户的密码以进行认证。然后将信息发送到认证系统，由其负责验证用户名和密码是否有效。如果用户名和密码正确，则授予用户系统访问权限；如果信息不正确，则显示错误并拒绝访问。

用户可以通过多种方式向系统标识自身并进行认证。以下列出了一些用于识别和认证目的的常用方法：

### 用户名
在网络上识别用户的最流行方法是给他们每人分配一个唯一的用户名。为了标识自己，用户将用户名输入登录屏幕。为了进行认证，他们输入与该用户名关联的密码。

### 智能卡
智能卡大小与信用卡相当，带有一个微芯片，可包含系统或应用程序使用的数据（参见[图 2-3](#ch02.xhtml#ch2fig3)左侧）。智能卡可用于识别该特定智能卡的唯一所有者。智能卡插入系统后，用户输入与智能卡关联的 `PIN` 以向系统进行认证。

### 令牌
安全令牌是一种小型设备，通常用于识别个人，并用于认证过程。在不同类型的令牌中，最流行的是一种在 30 到 60 秒内显示随机数字的设备（参见[图 2-3](#ch02.xhtml#ch2fig3)右侧）。随机数字、用户名和密码用于登录。

### 生物识别
生物识别是利用你身体的一部分来向系统进行认证的概念。例如，你可以扫描指纹或视网膜来向系统进行认证。高安全环境通常使用生物识别系统，因为物理特征无法被复制。
