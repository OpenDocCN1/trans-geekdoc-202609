

### 自动化处理流程
自动化的目标是将您必须定期执行的任务或处理流程自动化，从而降低执行这些任务时发生人为错误的几率。

### 持续交付
一个编程术语，指软件开发团队以短周期更新软件，以确保能够随时发布新版本。

### 持续验证
使用脚本在应用程序编译并最终部署之前执行代码检查，从而实现验证代码过程的自动化。

### 持续部署
将编译后的应用程序部署到生产系统中。

### 持续集成
一种流程，每当代码被签入系统时，就会触发持续验证；如果验证成功，则编译代码。一旦构建成功（应用程序编译完成），可能会触发通过持续部署将应用程序自动部署到生产环境中。

### 持续监控
系统或应用程序部署后，您可以使用脚本自动监控该系统或应用程序的健康状况。

## 弹性与可扩展性

如今我们常听到的术语，尤其是在云计算领域，就是 `elasticity` 和 `scalability`。将应用程序置于云端将为您带来弹性和可扩展性的优势。`Elasticity`（弹性）是指云环境可以根据工作负载动态调整分配给应用程序的资源。如果负载较重，云环境可以分配更多内存或处理能力，然后在不需要时降低这些资源。`Scalability`（可扩展性）是指云提供商可以随着需求在较长时期内增长，在后台手动提供更多服务器。

## 实施主机与应用安全

既然您已经了解了针对软件的常见攻击，并理解了一些可用于帮助防止通过软件发起攻击的安全编码技术，那么让我们来看看一些可用于保护主机系统和应用程序免受攻击的常见技术。

### 主机安全

有多种方法可以帮助保护主机系统免受在该系统上运行的恶意代码侵害。以下是针对 Security+ 考试需要了解的三项关键安全功能：

- **允许列表** 以前称为白名单。您可以创建一个允许在系统上运行的应用程序列表。任何其他应用程序都将被禁止运行。这有助于确保只有经过测试和批准的应用程序才能在公司系统上运行。
- **阻止列表/拒绝列表** 以前称为黑名单。您可以创建一个应用程序阻止列表（或拒绝列表）。除您放入阻止/拒绝列表的应用程序外，所有应用程序都将被允许在系统上运行。这是处理通过电子邮件发送给人们的恶意应用程序的绝佳方式，可确保您的用户不会运行它。
- **安全编码实践** 遵循我们之前讨论的安全编码实践至关重要，包括在将应用程序部署到生产环境之前对其进行测试。

### 应用安全

为帮助提高应用安全性，您可以遵循以下最佳实践：

- **输入验证** 如果软件程序员在处理发送给应用程序的输入之前对其进行验证，则可以防止许多针对应用程序的攻击。这是防止多种注入攻击和跨站脚本攻击的方法。
- **安全 Cookie** Cookie 用于存储用户访问网站时的偏好设置。Cookie 从客户端发送到 Web 服务器以读取信息，并根据用户偏好定制站点。使用安全 Cookie 会在 Cookie 上设置一个标志，使其仅在站点使用 HTTPS 时才发送到 Web 服务器。
- **超文本传输协议 (HTTP) 标头** HTTP 现在支持可提高 Web 应用程序安全性并防范点击劫持和跨站脚本攻击的标头值。例如，您可以使用 `Content-Security-Policy` 标头来控制脚本、样式和图片的允许来源。
- **代码签名** 代码签名是验证应用程序代码完整性的重要功能。出于安全原因，许多环境将仅执行由受信任来源使用代码签名证书进行数字签名的代码。

### 代码质量与测试

创建安全应用程序的关键在于确保实施适当的代码质量检查和测试。以下是应执行的不同代码质量检查和应用程序测试：

- **静态代码分析** 静态代码分析通常是执行的第一种代码测试类型，涉及在不运行代码的情况下审查代码以识别问题。代码可以人工审查，由团队通读，但也有称为静态代码分析器的工具可用于审查代码并查找潜在漏洞。
- **动态代码分析** 动态分析涉及通过执行代码来测试代码，并查看应用程序在系统上使用时的响应方式。动态分析的示例包括运行单元测试、集成测试、系统测试和验收测试。
- **压力测试** 压力测试是一种测试形式，它给应用程序施加大量负载，以确定如果大量用户同时使用该应用程序，它在生产环境中会如何响应。
- **沙箱** `Sandboxing`（沙箱技术）是指在隔离环境中运行已更改的代码（远离生产系统），以测试代码更改的影响。
- **模型验证** 模型是对即将开发的真实程序的模拟，但并非所有功能都编程在模型中。模型在应用程序开发的初始阶段创建，用于验证客户是否对应用程序的基本元素满意。应定期验证模型，以确保其仍满足客户需求。

#### 模糊测试

公司必须通过在应用程序的所有数据输入屏幕中故意输入无效信息，来测试他们创建的任何软件。向应用程序的输入字段输入无效或随机数据的软件测试术语称为 `fuzzing`（模糊测试）。

## 认证总结

在本章中，您了解了针对应用程序的常见攻击以及开发人员用于降低这些攻击利用软件漏洞几率的常见技术。以下是您在准备 Security+ 认证考试时应从本章记住的一些要点：

- 为保护应用程序环境，开发人员必须在处理信息之前验证提交给应用程序的任何输入。作为网络管理员，您可以通过移除不必要的功能来强化应用程序，并可通过将应用程序配置为安全状态来创建应用程序安全基线。
- 开发人员应遵循 SDLC（软件开发生命周期），它概述了应用程序开发的主要阶段。这些阶段包括：需求收集与分析、设计、实现、测试、部署和维护。
- 开发人员应在其代码中实施适当的错误处理和输入验证，以帮助降低应用程序遭受攻击的风险。
