
# SDN

**SDN** 软件定义网络是一项可在虚拟化环境中配置的功能，它允许您创建虚拟网络并对网络流量进行分段。

## 业务连通性考量

在审视组织的企业安全时，您还需要考虑业务地点的地理因素，因为办公室的位置会影响您可能遇到的自然灾害类型以及应急人员的响应时间。

您还应考虑事件响应程序，以及在发生安全事件时贵企业将依赖的恢复控制类型。您将在[第 18 章](#ch18.xhtml#ch18)了解更多关于灾难恢复和业务连通性的内容，而[第 21 章](#ch21.xhtml#ch21)则讨论事件响应。

## 安全设备与网络设备的部署

在设计网络时，将不同的安全设备和网络设备放置在正确的位置至关重要。以下列表列出了关键安全设备和网络设备及其应放置的位置：

- **传感器** 传感器应部署在每个网段上，以便捕获该网段的网络流量并将其发送给收集器或分析引擎。
- **收集器** 您可以在任意网段上放置单个收集器，并让每个传感器将捕获的流量发送给该收集器。
- **关联引擎** 关联引擎应运行在有权访问收集器数据的系统上，并应放置在安全的网段上。
- **过滤器** 这些组件用于过滤不同类型的流量，应放置在网络边缘。例如，您可以在代理服务器上使用 URL 过滤器来阻止用户访问特定站点。代理服务器位于 Internet 连接与用户之间，以便审查每个被访问的网站并过滤掉已被禁止的网站。
- **代理服务器** 正向代理是一种部署在网络边缘、位于 Internet 连接与用户之间的设备。用户对 Internet 资源的所有请求都会经过代理，以便其过滤掉任何未经授权的内容。反向代理部署在 DMZ 中，用于将网络内的服务器（如 Web 服务器）发布到 Internet。当 Internet 上的系统尝试访问您的服务器时，它首先会联系反向代理（该代理分配了 DNS 名称），然后反向代理将流量转发给内部系统。
- **跳板服务器** 跳板服务器是一种用于访问或管理另一安全区域内设备的系统。跳板服务器经过加固，并配置了安全通信协议（如 SSH），它部署在包含待访问设备的区域中。防火墙有严格的规则限制可用于与跳板服务器通信的协议和系统。
- **防火墙** 防火墙应部署在网络边缘，以保护网络免受来自 Internet 的未经授权流量的侵入。您也可以在不同网段之间部署防火墙，以控制网段间的流量。
- **VPN 聚合器** VPN 聚合器同样部署在网络边缘，但在防火墙之后，以便防火墙能阻断可能针对 VPN 聚合器的恶意流量。防火墙需要开放端口以允许 VPN 流量到达 VPN 聚合器。
- **SSL 加速器** SSL 加速器可部署在执行大量加密功能的任何系统或服务器内部。
- **负载均衡器** 负载均衡器通常部署在 DMZ 中，一般用于对 Web 应用程序的请求进行负载均衡。您也可以在内部网络中部署负载均衡器，用于可能需要多台服务器分担负载的网络服务。
- **DDoS 缓解设备** DDoS 缓解设备部署在 Internet 与您的公共 Internet 资源（如网站和电子邮件服务器）之间，以保护这些资源免受 DDoS 攻击。
- **分流器和端口镜像** 您可以在每个网段上部署网络分流设备，使其将所有数据的副本发送给监控系统。监控系统连接到镜像端口，并运行软件以监控网络流量。

## 配置管理

构建安全网络基础设施的一部分是确保公司制定了配置管理策略，该策略规定了在网络上实施变更所需遵循的变更管理流程。这包括在生产环境中实施变更前，先在测试环境中部署该变更。

变更管理还涉及拥有最新的网络 `diagrams`（网络拓扑图），并确保有一个可应用于新设备的 `baseline configuration`（基线配置）。基线配置是一种用于确保所有设备配置一致的工具，从而防止配置错误的发生。您还应确保对网络上的系统和设备使用标准化命名约定，以帮助理解设备名称的含义。您还应记录网络上使用的 Internet 协议 (IP) 地址方案，特别是当您使用多个网段且每个网段使用不同 IP 地址块时。

## 设备安全防护

本章的最后一个主题回顾了一些保护网络设备的常见做法。在过去的几章中，您已经读到过保护系统和设备应采取的常见步骤。让我们结合网络设备回顾其中的一些要点：

- **权限提升** 请务必随时了解攻击者连接到系统或设备后，如何提升其在系统上的权限并获得管理访问权限。这通常是由于产品漏洞导致的，因此请务必为系统或设备应用更新。为设备应用更新涉及在固件版本发布时升级设备上的固件。
- **弱密码** 我简直不敢相信还有这么多管理员在使用弱而明显的密码。在对一家公司的 Cisco 路由器进行评估时，我查看了运行配置，发现该公司管理员配置了路由器的 Telnet 访问，密码却是 `telnet`。我还通过输入密码 `cisco` 获得了路由器的管理访问权限。这些不仅不是强密码，而且是黑客尝试获取访问权限时会尝试的常见密码。这个例子中的另一个安全问题是，我本不应该能够查看密码，因为它们本应在配置中加密。使用 Cisco 设备时，您可以使用 `service password-encryption` 命令对配置文件中的密码进行加密。
- **后门** 检查网络设备是否存在潜在后门。我发现的一个典型例子是：网络管理员在路由器的控制台端口配置了密码，却未在路由器的辅助端口（如果存在）设置密码。辅助端口就像另一个控制台端口，拥有路由器物理访问权限的人可以连接到该端口来管理设备。请务必为这些设备上的所有端口设置密码保护！
- **默认账户** 请留意系统或设备上存在的默认账户，并务必使用强密码保护这些账户。如果可能，您应将默认账户重命名为不那么显而易见的名称。
