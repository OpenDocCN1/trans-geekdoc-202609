

### 识别加密用途

本节讨论了在当今计算和网络环境中，利用成熟技术实现加密的一些常见用例。加密不仅用于加密存储中的数据，还用于加密系统之间或人与人之间的通信。

#### 常见用例

在日常工作中，有许多场景会用到不同的加密概念和技术。以下概述了一些您会在实践中见到这些概念的常见场景：

- **低功耗设备** 使用低功耗设备是我们目前用来限制通信信号传输距离的一种方法。例如，您应该降低无线信号的功率，以便大楼外部的人无法连接到您的无线网络。
- **低延迟** 延迟是日常衡量网络性能的一个指标。低延迟意味着响应的等待时间极短。例如，您希望客户端系统与认证服务器之间的延迟很低。
- **高弹性** 弹性是指解决方案抵御故障的能力。用于提供高弹性的技术示例包括高可用性解决方案（例如，集群和 RAID）和负载均衡解决方案。
- **支持机密性** 有大量技术用于维护机密性，包括任何加密技术，例如用于无线网络的 `WPA2`，以及磁盘加密，例如 `BitLocker`。
- **支持完整性** 使用完整性解决方案的一个示例是，当您为文件创建 `MD5` 或 `SHA-1` 哈希值时，以便下载文件的人可以验证他们拥有的是未被修改的文件版本。
- **支持混淆** 加密算法和不同的分组模式是混淆的示例。
- **支持认证** 客户端证书和网站的双因素认证是支持认证概念的示例。
- **支持不可抵赖** 当您对电子邮件进行数字签名时，您就是在支持不可抵赖性，以确保发送方无法否认发送过该消息。
- **资源与安全约束** 存在许多资源可能与安全约束发生冲突的用例。例如，无线功能内置于当今的许多设备中，但一些公司有禁止使用无线的策略。在这种情况下，设备上的无线功能会被禁用，因为公司的安全约束优先于资源可用性。

#### 理解局限性

Security+ 考试要求您了解不同的加密协议以及每种协议局限性所涉及的风险。例如，如果应用程序使用 `DES` 或 `3DES`，安全风险在于它们是薄弱的加密方法，因为这些是已被破解的旧标准。以下是一些需要注意的加密标准局限性：

- **速度** 请了解对称加密比非对称加密快，这就是为什么许多技术同时使用这两种方法——对称加密用于速度，非对称加密用于密钥管理。
- **密钥长度** 请了解密钥长度越大，加密强度越高。例如，`256-bit AES` 加密比 `128-bit AES` 加密更强。
- **弱密钥** 使用弱加密密钥会使加密容易受到攻击。使用具有尽可能最大密钥长度的加密标准可降低密钥被破解的风险。
- **时间** 请了解不同加密类型在加密和解密大量数据时所需时间不同。例如，使用对称加密加密大文件所需时间比非对称加密少。
- **寿命** 了解加密协议或应用程序的预期寿命非常重要。您不希望投资一种技术，结果在实施后不久就不再被接受。
- **可预测性** 使用难以预测技术所用随机值的技术。例如，使用可预测的 `IVs`（初始化向量）可能会给正在加密的数据隐私带来风险。
- **重用** 重用密钥可能会给您的环境带来安全风险，因为这有助于攻击者破解加密密钥。
- **熵** 熵是加密应用程序用来加密数据的关于系统的随机信息。无法生成良好熵的应用程序可能容易受到攻击者解密数据的威胁。
- **计算开销** 加密算法越先进，系统所需的处理能力就越强。您可以使用 `GPU` 来处理强加密应用程序的计算开销。
- **资源与安全约束** 这与计算开销相关，加密算法和密钥长度越强，使用的资源（内存和处理器）就越多。在获得良好安全性和不使系统过载之间找到平衡非常重要。

#### 加密数据

如果您想确保公司信息不被未授权人员查看，就需要对数据进行加密。在考虑加密数据时，请考虑加密以下内容：

- **传输中数据** 对数据在从源头传输到目的地的网络传输过程中进行加密，这样如果有人窃听通信，将无法读取数据。您将在本章后面了解通信加密协议。
- **静态数据** 当在磁盘或数据库中存储信息时，对数据进行加密，这样如果有人访问了驱动器或数据库，就无法查看敏感数据。
- **使用中数据** 对存储在 `RAM`、`CPU 缓存` 甚至 `CPU 寄存器` 中的数据进行加密。目的是确保没有人能通过编写代码从这些区域检索数据来访问敏感数据。

让我们在此专注于存储中的数据，并回顾一下您在 [第 7 章](#ch07.xhtml#ch7) 中学到的一些关键点。作为复习，您可以使用以下任何成熟技术来加密存储中的数据：

- **全盘** 当今大多数操作系统都支持全盘加密 (`FDE`)。例如，Windows 拥有 `BitLocker`，它允许您加密整个驱动器的内容（包括操作系统），或加密特定分区。为了完全启动系统，个人需要知道密钥，以便解密加密内容。
- **数据库** 在数据库中存储信息时，加密敏感信息至关重要。例如，如果您的公司有一个存储客户信用卡号甚至客户密码的应用程序，您应该加密数据库中的该数据，因为黑客可能访问数据库并发现这些信息。许多数据库产品允许您加密整个数据库，因此如果攻击者窃取了数据库文件，他们无法读取数据，因为其系统上不存在解密密钥。
- **单个文件** 如果您不加密整个驱动器的内容，则可以加密选定敏感文档的内容。例如，您可以使用 Windows 中的加密文件系统 (`EFS`) 来加密单个文件和文件夹。
- **可移动介质** 如果您将数据存储在可移动驱动器（如闪存驱动器）上，请务必加密该驱动器上的所有公司数据。闪存驱动器太容易丢失或遗忘在某处了，如果数据未加密，任何人都可以读取！
- **移动设备** 大多数移动设备允许您加密移动设备的内容，以便在设备丢失或被盗时，无人能够检索设备上的数据。
