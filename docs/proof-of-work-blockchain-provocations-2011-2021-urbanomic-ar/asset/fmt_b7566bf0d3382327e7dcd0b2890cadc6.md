### 1. Introduction

The Tarot is a prefigurative Artificial Intelligence (AI). It is a set of symbols embodied physically outside of human minds and manipulated according to a set of rules. Like an Expert System or other rule-based AI system, it is consulted by human beings for advice, communication with and exerting influence on them.

‘Turing Completeness’ is the property of a given representation for computer programs that means it can represent any possible program (with more or less effort). Even very simple programming languages can be Turing Complete. The idea of Turing Completeness is a shorthand for the power of computing. Artificial Intelligence is an expression of that power.

We can use the symbols of the Tarot not just for their evocative iconography but also as the symbols of a simple programming language. This allows us to treat a reading as the execution of a (random) computer program determined by the drawing of cards. Doing so provides a longer and more engaged experience of drawing cards that may help to consider different possibilities or may increase confidence in the cards in the resulting layout.

To do this we must identify a suitable programming language, map its operators onto the cards in a standard Tarot deck, and describe the method used for executing drawn cards as a program in that language in order to determine the cards to be used to complete a reading.

### 2. A Minimal Programming Language

P′′ is a minimal representation for computer programs created by Corrado Böhm in 1964. It allows an array of memory cells to be very simply manipulated and tested. The ‘Brainfuck’ esoteric programming language created in 1993 by Urban Müller extends P′′ with input and output operators and uses simpler names for its operators.

Even a simple program expressed in P′′ will take many, many operations. It is laboriously close to raw computation. But it is Turing Complete, and so however laborious it may be, it does allow any program to be expressed.

We will use the six P′′ operators under their Brainfuck names:

| **Operator** | **Meaning** |
| --- | --- |
| `+` | Increase the value in the current memory cell by one. |
| `–` | Decrease the value in the current memory cell by one. |
| `<` | Move one memory cell to the left. |
| `>` | Move one memory cell to the right. |
| `[` | If the current memory cell is zero, jump forward to the instruction after the matching `]`. |
| `]` | If the current memory cell is greater than zero, jump back to the instruction after the matching `[`. |

Unless otherwise noted, each operator also moves the program to the next instruction. The program finishes when there are no more instructions.

From some non-standard implementations of Brainfuck we take the principle that the memory cells extend both left and right (this makes it easier for an initial `<` to be acted on).

### 3. Mapping P′′ onto the Tarot

A standard Tarot deck consists of seventy-eight cards. This is divided up into twenty-two major arcana and fifty-six minor arcana divided up into four suites of fourteen cards each. In order to use a standard Tarot deck as both the data and program deck, we must assign a P′′ operator to each card in the deck.

In order to make it practical to use any mapping scheme with an unprepared Tarot deck we should ensure that it is as simple as possible. Any visual or numeric properties of cards that may help remember the scheme should be exploited.

Seventy-eight divided by six is thirteen. We can therefore have thirteen of each operator in a standard Tarot deck. But thirteen does not fit neatly into either the major or minor arcana, so we must take this into account in any scheme we devise. We may also decide that some P′′ operators are likely to occur more frequently in programs than others, or that they are more useful in drawing cards for readings, and so include more of them.

#### 3.1 Simple Six Times Thirteen

| **Suite** | **Card: Operator** |
| --- | --- |
| Wands | 1–13: `<`; 14: `[` |
| Cups | 1–13: `>`; 14: `[` |
| Swords | 1–13: `–`; 14: `]` |
| Pentacles | 1–13: `+`; 14: `]` |
| Major Arcana | 0–10: `[`; 11–21: `]` |

This scheme has an even number of operators. It fits the first four operators entirely into a suite, and the last two into the Major Arcana with the shortfall made up from the remainders of the Minor Arcana suites. Swords and Pentacles were chosen for `–` and `+` respectively based on distant visual resemblance.

#### 3.2 Fewer Jumps

| **Suite** | **Card: Operator** |
| --- | --- |
| Wands | 1–14: `<` |
| Cups | 1–14: `>` |
| Swords | 1–14: `–` |
| Pentacles | 1–14: `+` |
| Major Arcana | 0–10: `[`; 11–21: `]` |

This scheme assumes that, whether for practical or aesthetic purposes, fewer control structures (jumps) are more useful. It fits the non-control operators (left, right, minus and plus) into the Minor Arcana and divides the Major Arcana between the two jump operators. This means that each non-control operator has three more cards than either of the control operators.

#### 3.3 Split Suites

| **Suite** | **Card: Operator** |
| --- | --- |
| Wands | 1–7: `<`; 8–14: `–` |
| Cups | 1–7: `[`; 8–14: `]` |
| Swords | 1–7: `+`; 8–14: `–` |
| Pentacles | 1–7: `+`; 8–14: `>` |
| Major Arcana | 0–10: `+`; 11–21: `–` |

There are several possible variations of this mapping. We can divide each suite into odd and even cards rather than numeric ranges. This may be easier or harder to manage depending on mathematical experience. We can also apply different operators to each run of cards to adjust their quantity in the deck.

#### 3.4 Contiguous Six Times Thirteen

| **Suite** | **Card: Operator** |
| --- | --- |
| Wands | 1–13: `–`; 14: `–` |
| Cups | 1–12: `–`; 13–14: `>` |
| Swords | 1–11: `>`; 12–14: `<` |
| Pentacles | 1–10: `<`; 8–14: `[` |
| Major Arcana | 0–8: `[`; 9–21: `]` |

Similarly to the Simple Six Times Thirteen mapping, this has thirteen of each operator but it maps them in continuous runs that ignore suite boundaries. This is conceptually simpler than the ‘simple’ mapping, but is harder to remember and to work with in practice.
