# 6.2. Custom Types

# 6.2.1.2. Method Expressions

Just as we can assign and pass functions, we can also assign and pass method expressions. A method expression is a function that must be passed a value of the method's type as its first argument. (The term unbound method is often used in other languages for this concept.)

We have created four method expressions: asStringV() which takes a Part value as its sole argument, hasPrefix() which takes a Part as its first argument and a string as its second argument, and asStringP() and lower() which both take a Part as their sole argument.

Method expressions are an additional feature which can be very useful on the uncommon occasions when they are needed.

All the custom types we created so far potentially suffer from a critical flaw. None of them provide any means of ensuring that the data they are initialized with is valid (or forced to be valid), nor any means of ensuring the type's data (or fields in the case of struct types) cannot be given invalid data. For example, the Part.Id and Name can be set to any values we like. But if we wanted to apply constraints—for example, only allow IDs to be positive integers greater than zero, or only allow names that had a specific format? We will address these issues in the next subsection where we will create a small custom type with validated fields.

# 6.2.2. Validated Types

For many simple types, no validation is necessary. For example, we might have type Point (X, Int), for which any values of X and Y are valid. Furthermore, since Go guarantees to initialize all variables (including struct fields) to their zero values, the need for explicit constructors is reduced.
