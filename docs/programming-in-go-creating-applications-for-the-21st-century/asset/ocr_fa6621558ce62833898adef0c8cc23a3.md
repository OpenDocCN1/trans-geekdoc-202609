Since the FuzzyBool type is based on a struct that contains a value whose type
is inside the struct, we could simplify the type to type FuzzyBool struct
{ float32 }. This would mean changing the code that accesses the value—and
which we will see in one of the methods—fuzzy.value to fuzzy-zy.float32. We preferred to use a named variable partly because we found it more aesthetically pleasing, and partly because we wanted to change the underly type (to, say, float64), we would have fewer changes to make.

Further variations are also possible since the struct contains only a single value.
For example, we could change the type to type FuzzyBool float32 to make it based
directly on a float32. Doing this works perfectly well, but requires slightly more
code and is a bit trickier to implement the struct-based approach we used
However, if we constrain ourselves to creating immutable Fuzzy Booleans
(where the only difference is that instead of setting a value with the Set()
method would have to assign a new Fuzzy Boolean), we can greatly simplify
the code by basing the type directly on a float32.

```
func New(value interface{}) (*FuzzyBool, error) {
    amount, err := float32ForValue(value)
    return &FuzzyBool{amount}, err
}
```

For the convenience of fuzzy Boolean users, rather than accept only float32 as
t initializing value we also accept float64s (Go's default floating-point type),\ints (the integer type), and bools. This flexibility is achieved by using
custom float32ForValue() function which returns a float32 and nil for the
given value—or returns an error if the value is not of a type it
 handle.

If we passed a value of an invalid type we have made a programming error and
want to know about it away. But we don't want the application to crash
on our users. So, instead of just returning a *FuzzyBool, we also return an error.
If we pass a known valid literal to New (as in the earlier snippet: 283),
s safely ignore the error; but if we pass a variable, we should check the error
at is returned in case it isn't nil.

The New() function returns a pointer to a FuzzyBool rather than a value because
have chosen to make the Fuzzy Booleans in this implementation mutable.
This means that those methods which modify a Fuzzy Boolean (in this example,
 one, Set()) must take a pointer receiver, not a value.*
