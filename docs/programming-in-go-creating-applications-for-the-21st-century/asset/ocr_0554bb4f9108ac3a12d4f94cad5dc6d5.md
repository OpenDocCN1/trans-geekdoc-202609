# 2.1. Preliminaries

```
type BitFlag int
const (
    Active BitFlag = 1 << iota // 1 << 0 == 1
    Send    // Implicitly BitFlag = 1 << iota // 1 << 1 == 2
    Receive // Implicitly BitFlag = 1 << iota // 1 << 2 == 4
)
var flag := Active | Send
```

In this snippet we have created three bit flags of type BitFlag and then set variable flag (of type BitFlag) to the bitwise or of two of them (so flag has value 3; Go's bitwise flags are shown in Table 2.6, ►). We could have omitted the custom type in which case Go would have the constants untyped integers and inferred flag's type as int. BitFlag can have any int value; nonetheless BitFlag is a distinct type so can only be used in operations with ints converted to an int (or if the ints are converted to BitFlags).

The BitFlag type is useful as it stands, but if we printed flag we would just get 3 with no indication of what that means. Go makes it really easy to control how values of custom types are printed, because the package functions will use a type String() method if it has one. To make our BitFlag type print in a more informative way, we can simply add a String() method to it. (Custom types and methods are covered fully in Chapter 6.)

```
func (flag BitFlag) String() string {
    var flags []string
    if flag&Active == Active {
        flags = append(flags, "Active")
    }
    if flag&Send == Send {
        flags = append(flags, "Send")
    }
    if flag&Receive == Receive {
        flags = append(flags, "Receive")
    }
    if len(flags) > 0 { // int(flag) is vital to avoid infinite recursion!
        return fmt.Sprintf("%ds", int(flag), strings.Join(flags, " | "))
    }
    return "0"
}
```

This method builds up a (possibly empty) slice of strings for those bit fields that are set and prints the bit field's value as a decimal int and with the strings to indicate its.
