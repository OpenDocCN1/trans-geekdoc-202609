This function creates a channel for passing filenames. It uses a buffered channel since in tests it this improved throughput. (As is often the case we have traded memory for speed.)

Once the output channel has been created we create a goroutine which iterates over the files and sends each one to the channel. When all the files have been sent we close the channel. As usual, the go statement returns immediately, so there may be a long gap in time between sending the first item and sending the last item and closing the channel. The send to the channel does not block (at least, not for the first 1000 files—or however many files are if fewer than a 1000)—but block if there are more to send, at least until one or more are received from the channel.

As noted earlier, by default channels are bidirectional, but we can constrain a channel to unidirectional. Recall from the section that the chan<- Type is a send-only channel and the type<- Type is a receive-only channel. At the end of the function the bidirectional out is returned as a unidirectional receive-only so that can be received from it. We could, of course, have returned it as a bidirectional channel, but this way we have expressed our intentions.

After executing the go statement to start the anonymous function processing in its own goroutine, the function immediately returns the channel that the goroutine's function sends filenames to. So, the source() function has been called, there are two goroutines executing—the main goroutine and the additional one created in the function.

func filterSuffixes(suffixes []string, in <-chan string) <-chan string {

	go func() {

		if ext == suffix {
