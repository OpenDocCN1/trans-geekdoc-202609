# 9.1. Custom Packages

Here is an example test run where the tests pass.

```
$ go test
ok    qtrac.eu/emap
PASS
```

And here is the same test run, but this time with verbose output switched using the -test.v option.

```
$ go test -test.v/emap
ok    qtrac.eu/KeyOMapInsertion-4
=== TestStringKeyOMapInsertion-4
PASS: TestStringKeyOMapInsertion-4 (0.00 seconds)
=== TestIntKeyOMapFind-4
PASS: TestIntKeyOMapFind-4 (0.00 seconds)
=== TestIntKeyOMapDelete-4

=== TestPassing-4

PASS
```

If we change the constant string to force the test to fail and run the tests (in the default nonverse mode), here is the output we will get.

```
$ go test
FAIL qtrac.eu/KeyOMapInsertion-4
--- FAIL: TestStringKeyOMapInsertion-4 (0.01 seconds)
omap_test.go:35: "FiveouroneTHREETwo" != "FiveouroneTHREEToo"
FAIL
```

In addition to the Error(f) method used in the example, the testing package's *testing.T has various other methods such as testing.T.Fail(), T.Fatal(), and so on. All these methods provide us with a good level of control over how we respond to test failures.
