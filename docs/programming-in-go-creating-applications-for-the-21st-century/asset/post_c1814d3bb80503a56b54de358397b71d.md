## 5.1.2. Type Assertions

A type's method is the set of all the methods that can be called on a value of type—this is empty for types that have no methods. The Go interface{} type is used to represent the empty interface, and it is a value of type whose method set includes the empty set. Since every type has a method set that includes the empty set (no matter how many methods it has), interface{} can be used to represent a value of any Go type. Furthermore, we can convert interface{} to a value of the actual type it holds using a type switch (see §5.2.2.2, 197), or a type assertion, or by introspection with Go's reflect package (§9.4.9, 427).

The use of variables of type interface{} (or of custom type interfaces) can arise when we are handling data received from external sources, when we want to generate functions, and when using object-oriented programming. To access the underlying value, one approach is to use a type assertion using one of these syntaxes:

```
resultType, boolean := expression.(Type) // Checked
resultType := expression.(Type) // Unchecked; panic() on failure
```

A checked type assertion returns the expression as a value of the specified Type and true to indicate success. If the checked assertion fails (i.e., the expression's type is not compatible with the specified Type), a zero value of the specified Type and false are returned. Unchecked assertions either return the expression as a value of the specified Type or call the built-in panic() function which will result in program termination if the panic isn’t recovered. (Panicking and recovery is covered later; §5.5, ➤ 212.)

- * More obscure conversions are also possible; these are covered in the Go specification (golang.org/doc/spec.html).*
- Python programmers may find it helpful to think of interface{} as being like an instance of Object, and Java programmers as being like an instance of Object, unlike Java's Object, interface{} can be used to represent both custom and built-in types. For C and C++ programmers, interface{} is rather like a void* that knows what type it is.

Here is a tiny example to illustrate the syntaxes in use.

```
var i interface{} = 99
var s interface{} = []string{"left", "right"}
j := i.(int) // j is of type int (or a panic() has occurred)
fmt.Printf("%T-%d\n", j, j)
if i, ok := i.(int); ok {
	fmt.Printf("%T-%d\n", i) // i is a shadow variable of type int
}
if s, ok := s.(string); ok {
	fmt.Printf("%T-%q\n", s, s) // s is a shadow variable of type []string
}
```

```
int-99
int-99→["left" "right"]
```

It is quite common when doing type assertions to use the same name for the result variable, that is, to shadow variables. And, generally, we use checked type assertions only when we expect the result to be of the specified type. (If the expression could be any of a number of types, we can use a type switch; §5.2.2, ➤ 197.)

Note that if we printed the original i and s variables (both of type interface{}) they would be printed as an int and a []string. This is because the fmt package’s print functions are faced with interface{} types, they are sensitive enough to print the actual values.

## 5.2. Branching

Go provides three branching statements: if, switch, and select—the latter is discussed on (§5.4.1, ➤ 209). A branching effect can also be achieved using a map whose keys are used to select the “branch” and whose values corresponding functions to call—something we will see later in the chapter (§5.6.5, ➤ 230).

## 5.2.1. If Statements

Go’s if statement has the following syntax:

```
if optionalStatement1; booleanExpression {
  block1
} else if optionalStatement2; booleanExpression {
  block2
} else {
  block3
}
```

There may be zero or more else if clauses and zero or one final else clause. Each block consists of zero or more statements.

The braces are mandatory, a semicolon is needed only if an optional statement is present. The optional statement is a simple statement in Go terminology: This means that it may be only an expression, a channel send (using the < operator), an increment or decrement statement, an assignment, or a short variable declaration. If variables are created in an optional statement (e.g., using the : operator), their scope extends from the point of declaration to the end of the complete statement—so they exist in the if else if they are declared, and in every branching, and cease to exist at the end of the statement.

The Boolean expressions must be of type bool. Go will not automatically convert non-bool, so we must always use a comparison operator—for example, if i == 0. (The Boolean and comparison operators are listed in Table 2.3)

We have already seen numerous examples of statements in use, and will see many more in the rest of the book. Nonetheless, we will look at two tiny examples, the first to show the value of the optional simple statement, and the second to illustrate a Go statement idiom.

```
// Canonical ✓
if alpha := compute(); alpha < 0 {
  fmt.Printf("%d\n", -alpha)
} else {
  fmt.Println(alpha)
}
```

```
// Long-winded!
{
  alpha := compute()
  if alpha < 0 {
    fmt.Printf("%d\n", -alpha)
  } else {
    fmt.Println(alpha)
  }
}
```

These code snippets print exactly the same thing. The right-hand snippet must use extra braces to limit the scope of the alpha variable, whereas the left-hand snippet automatically limits the scope to the if statement.

The second statement example is the ArchiveFileList() function which is taken from the archive_file_list example. Later on we will use this function to compare and switch statements.

```go
func ArchiveFileList(file string) ([]string, error) {
  if suffix := Suffix(file); suffix == ".gz" {
    return ZipFileList(file)
  } else if suffix == ".tar" || suffix == ".tar.gz" || suffix == ".tgz" {
    return TarFileList(file)
  } else if suffix == ".zip" {
    return ZipFileList(file)
  }
  return nil, errors.New("unrecognized archive")
}
```

The example program reads the files given on the command line, and for those archive files it can handle (.gz, .tar, .tar.gz, .zip), it prints the name of the archive and an indented list of the files it contains.

Notice that the scope of the suffix variable created in the first clause extends throughout the entire if ... else statement, it is visible in every branch, just like the variable in the previous example.

The function could have been written using a final else statement, but it is very common in Go to use the structure shown here: an if statement and zero or more else statements each of which ends with a return statement, with this followed by a return statement rather than a final else statement.

```go
func Suffix(file string) string {
  file := strings.ToLower(filepath.Base(file))
  if i := strings.LastIndex(file, "."); i > -1 {
    if file[i:] == ".bz2" || file[i:] == ".gz" || file[i:] == ".xz" {
      j := strings.LastIndex(file[:], ".")
      if j > -1 && strings.HasPrefix(file[j:], ".tar") {
        return file[j]
      }
    }
    return file[i]
  }
  return file
}
```

The Suffix() function is included for completeness: It takes a filename (which may include a path), and returns the lowercased suffix—also called the extension—that is, the last part of the name that begins with a period. If the filename has no period, it is returned as (but without any path); if the filename ends in .tar.bz2, .tar.gz, or .tar.xz this is the suffix that is returned.
