
## 6.4. Structs

The simplest types in Go are based on Go’s built-in types—for example, type Integer creates a custom Integer type to which we could add our own methods. Custom types can also be based on structs which are used to aggregate and embed values together. This is particularly useful when the values—called fields in the context of structs—are of different types, and cannot be stored in a slice (unless we use an []interface{}). Go’s structs are more closer to C’s structs than C++’s (e.g., they are not classes), and they are more convenient to because of their excellent support for embedding.

We have already seen numerous examples of structs in earlier chapters and in this chapter, and we will see many more throughout the rest of the book. Nonetheless, there are some struct features that we have not yet seen, so we will begin with illustrative examples to show them.

```go
points := []int{{4, 6}, {}, {-7, 11}, {15, 17}, {14, -8}}
for _, point := range points {
  fmt.Printf("%d, %d\n", point[0], point[1])
}
```

The snippet's points variable is a slice of arrays of []int, so we must use the [] index operator to get each coordinate. (Incidentally, the {} item is the same as {0, 0} thanks to Go’s automatic zero-value initialization.) For small samples of simple data this works, but there is a nicer way to do this using an anonymous struct.

```go
points := []struct{x, y int}{{4, 6}, {}, {-7, 11}, {15, 17}, {14, -8}}
for _, point := range points {
  fmt.Printf("%d, %d\n", point.x, point.y)
}
```

Here, the snippet's points variable is a slice of struct{x, y int}. Although the struct itself is unnamed, we can access its data via its named fields which is easier and safer than using array indexes.

### 6.4.1. Struct Aggregation and Embedding

We can embed structs in the same way as we can embed interfaces or other types, by including the type name of a struct as an anonymous field inside another struct. (Of course, if we gave the inner struct a variable name it would be an aggregated named field rather than an anonymous field.)

Usually an embedded field’s fields can be accessed directly using the . (dot) selector operator without mentioning the type name, but if the containing struct has a named field whose name is the same as one of the embedded struct’s fields, then we must use the embedded struct’s type to disambiguate.

Every field name in a struct must be unique. For embedded (i.e., anonymous) fields the uniqueness requirement is sufficiently strict to avoid ambiguity. For example, if we have an embedded field of type Integer, we can have other fields called Integer2 or BigInteger, since they are essentially different, but we cannot have fields called Matrix.Integer or *Integer since the last component of these names is exactly the Integer embedded field, and the uniqueness of field names is based on their last component.

#### 6.4.1.1. Embedding Values

Let’s start by looking at a simple example involving two structs.

```go
type Person struct {
    Title     string   // Named field (aggregation)
    Forenames []string // Named field (aggregation)
    Surname   string   // Named field (aggregation)
}

type Author struct {
    Names    string   // Named field (aggregation)
    Title    []string // Named field (aggregation)
    YearBorn int      // Named field (aggregation)
}
```

We have seen many similar examples in earlier chapters. Here, the Author struct’s fields are all named. This is how we can use these structs and the output that’s (produced using a custom Author.String() method, not shown).

```go
author1 := Author{"Mr",[]string{"Robert","Louis","Balfour"},"Steveson",[]string{"Kidnapped","Treasure Island"}, 1850}
fmt.Println(author1)
author1.Names.Title = []string{"Oscar","Fingal","O'Flahertie"},"Wills"
author1.Names.Surname = "Wilde"
author1.Title = []string{"The Picture of Dorian Gray"}
author1.YearBorn += 4
fmt.Println(author1)
```

Stevens, Robert Balfour, Mr (1850) "Kidnapped" "Treasure Island" Wilde, Oscar Fingal O'Flahertie Wills (1854) "The Picture of Dorian Gray"

We begin by creating an Author1 value, populating all of the fields in order, and printing it. Then we change the value’s fields and print it again.

```go
type Author2 struct {
    Person                // Anonymous field (embedding)
    Title     []string // Named field (aggregation)
    YearBorn int          // Named field (aggregation)
}
```

To embed an anonymous field we can use the name of the type (or interface, as we will see later) that we want to embed, without specifying a variable name for it. i.e. we can access such a field's owns directly (without specifying the type or interface), or by using the type or interface's name if we need to disambiguate from another name. The containing struct embeds Person. This means we can use these structs and the output directly (without specifying the type or interface), or by using the type or interface's name if we need to disambiguate from another name.

The creation of the Author2 value is identical to the Author1, but now we can use these structs and the output directly (without specifying the type or interface), or by using the type or interface's name if we need to disambiguate from another name.

```go
author2 := Author{Person{"Mr",[]string{"Robert","Louis","Balfour"},"Steveson"},[]string{"Kidnapped","Treasure Island"}, 1850}
author2.Person.Forenames = []string{"Oscar","Fingal","O'Flahertie"}
author2.Person.Surname = "Wilde"
author2.Title = []string{"The Picture of Dorian Gray"}
author2.YearBorn += 4
fmt.Println(author2)
```

Stevens, Robert Balfour, Mr (1850) "Kidnapped" "Treasure Island" Wilde, Oscar Fingal O'Flahertie Wills (1854) "The Picture of Dorian Gray"

By embedding Person as an anonymous field, we get the same as the Author1, but now we can use these structs and the output directly (without specifying the type or interface), or by using the type or interface's name if we need to disambiguate from another name.

The snippet's points variable is a slice of arrays of []int, so we must use the [] index operator to get each coordinate. (Incidentally, the {} item is the same as {0, 0}) thanks to Go’s automatic zero-value initialization.) For small samples of simple data this works, but there is a nicer way to do this using an anonymous struct.


#### 6.4.1.2. Embedding Values That Have Methods

The creation of the Author2 value is identical to the Author1 value, but now we can use these structs and the output directly (without specifying the type or interface), or by using the type or interface's name if we need to disambiguate from another name.

```go
type Tasks struct {
    slice []string // Named field (aggregation)
    Count         // Anonymous field (embedding)
}

func (tasks *Tasks) Add(task string) {
    tasks.slice = append(tasks.slice, task)
    tasks.Increment()
}

func (tasks *Tasks) Tally() int {
    return int(tasks.Count)
}
```

We saw the custom Count type earlier (259). The Tasks struct has two fields: an aggregated slice of strings and an embedded Count value. As the implementation of the Tasks.Add() method illustrates, we can access the anonymous Count value's methods directly.

```go
tasks := Tasks{}
fmt.Println(tasks.IsZero(), tasks.Tally())
tasks.Add("One")
tasks.Add("Two")
fmt.Println(tasks.IsZero(), tasks.Tally())
true 0 []{}
false 2 [One Two]
```

We have created a Tasks value, and called the Tasks.Add(), Tasks.Tally(), and Count.IsZero() (as Tasks.IsZero()) methods on it. Even though we have not defined the Tasks.String() method, Go still produces sensible output when asked to print the Tasks.

It is important to remember that when an embedded field's method is called on a value that contains that field, it is only the embedded field that gets as the method's receiver. When Tasks.IsZero(), Tasks.Increment(), or any other Count method is called on a Tasks value, these methods receive a Count (or Count value), not the Tasks value.

In this example the Tasks type has its own methods (Add() and Tally()), and also the embedded Count type's methods Increment(), Decrement(), and IsZero(). It is, of course, possible for the Tasks type to override any or all of the Count type's methods by implementing its own methods of the same names.
