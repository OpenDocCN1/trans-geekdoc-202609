# 1.2. Editing, Compiling, and Running

correctly, enter the following in a console (xterm, gnome-terminal, konsole, Terminal.app, or similar):

```
$ go version
```

Or on Windows in an MS-DOS Prompt or Command Prompt window:

```
C:\go version
```

If you get a “command not found” or “go” is not recognized...” error message then it means Go is not in the PATH. The easiest way to set this on Unix-like systems (Mac OS X) is to set the environment variables in .bashrc (or the equivalent file for other shells). the author’s .bashrc contains these lines:

```
export GOROOT=$HOME/opt/go
export PATH=$PATH:$GOROOT/bin
```

Naturally, you must adjust the values to match your own system. (And, of course, this is only necessary if the go version command fails.)

On Windows, one solution is to create a batch file that sets up the environment for Go, and to execute this time you start a console for Go programming. However, it is much more convenient to set the environment variables once and for all the Control Panel. Then click Start (the Windows logo), then Control Panel, then System and Security, then Advanced settings, and in the System Properties click the Environment Variables button, then New..., and add a variable with the name GOROOT and a suitable value, such as C:\Go. In the same day, edit the PATH environment variable by adding the text C:\Go\bin at the end—leading semicolon is vital! In both cases replace the C:\Go component with the actual path where Go is installed if it isn't C:\Go. (Again, this is only necessary if the go version command failed.)

From now on we will assume Go is installed and the Go binary directory containing all Go is in the PATH. (It may be necessary—once only—to open a new console window for the new settings to take effect.)

Two steps are required to build Go programs: compiling and linking.* Both of these steps are handled by the go tool which can not only build local programs and packages, but can also fetch, build, and install third-party programs and packages.

> * Since the book assumes the use of the gc compiler, readers using gccgo need to follow the compile and link process described in golang.org/doc/gccgo_install.html. Similarly, readers using other compilers will need to compile and link as per their compiler's instructions.
