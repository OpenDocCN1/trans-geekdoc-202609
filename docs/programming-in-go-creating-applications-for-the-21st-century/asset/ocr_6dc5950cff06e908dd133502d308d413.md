In this example we used Stack receivers rather than pointers (i.e., of type *Stack) for methods that do not modify the Stack. For custom types with lightweight representations (say, a few ints or strings), this is perfectly reasonable. But for heavyweight custom types it is usually best to always use pointer receivers since a pointer is much cheaper to pass (typically a 32- or 64-bit value), than a large value, for methods where the value is modified.

A subtle point is that if we call a method on a value, and the method requires a pointer to the value Go is smart to pass the value’s address rather than a copy of the value (providing the value is addressable; §6.2.1, ► 258). Correspondingly, if we call a method on a pointer, and the method requires a value, Go is smart enough to reinforce the pointer and give the pointed-to-value.*

As this example illustrates, creating custom types in Go is generally straightforward, and doesn’t involve the cumbersome formalities that many other languages demand. Go’s object-oriented features are covered fully in Chapter 6.

# 1.6. Americanise—Files, Maps, and Closures

To have any practical use a programming language must provide means of reading and writing external data. In previous sections we had a glimpse of Go’s versatile and powerful print functions from its fit package; in this section we will look at Go’s basic file handling facilities. We will also look at some advanced features as Go’s treatment of functions and methods as first-class values which makes it possible to pass them as parameters. And in addition we will use of Go’s map type (also known as a dictionary or hash).
