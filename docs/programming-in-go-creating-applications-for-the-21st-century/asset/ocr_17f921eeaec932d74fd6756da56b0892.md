By default test does not run any benchmarks, if we want them to run we must explicitly say so using the -test.bench option and providing it with a regular expression that matches the benchmarks we want to run. A regex of .* matches anything, that is, all the benchmarks in the test file, plan also works.

```

PASS

PASS
BenchmarkOMapFind-Success    1000000    1380 ns/op

```

This output shows two benchmarks were run with 1 000 000 loop iterations, and with the number of nanoseconds per operation. The number of iterations (i.e., the value of b.N) is chosen by go test, but we can use the -test.bench option to see the approximate number of seconds we want each benchmark to run if we prefer.

# 9.1.2. Importing Packages

Go allows us to alias packages. This feature can be convenient and useful—making it easy to switch between two implementations of a package. For instance, we could import a package like this: import "bio-v1", so that in code the bio_v1 package is accessed instead of bio_v1. Later, when a more mature implementation is available, we could switch to it by changing the import to bio "bio-v2". This will work if both bio v1 and bio v2 provide the same APIs (or if bio v2’s API is a superset of bio v1s), and means that the rest of the code can be left unchanged. On the other hand, aliasing standard library package names is probably best, since it could cause confusion or irritation to maintainers later on.
