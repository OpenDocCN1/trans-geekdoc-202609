Here is the XMLInvoices struct that will be used to hold the entire data set.

```go
type XMLInvoices struct {
    XMLName xml.Name `xml:"INVOICES"`
    Version int `xml:"version,attr"
    Invoice []*XMLInvoice `xml:"INVOICE"`
}
```

No tag has any intrinsic semantics in Go—they are just strings using Go's reflection interface (9.4, ► 427). However, the encoding/xml package requires us to use such tags to provide it with information about how we want to map our structs' fields to or from XML. An xml.Name field is used to name the tag that will contain the struct that it is. Fields with `xml:` become attributes of the tag using the field name as the attribute name. We can force another name to be used if we wish, by preceding the comma with the name we want to use. We have done so to make the Version field become an attribute called version, rather than accepting the default name of Version. If the tag contains just a name, this name is used to indicate nested tags, `<INVOICE>` in this example. One important subtlety to that instead of calling the XMLInvoices's fields Invoice, we have called it Invoice (case-insensitively) to match the tag name.

Here is the original XML struct and the parallel XML-equivalent XMLInvoice.

```go
type Invoice struct {
    Id int
    CustomerID int
    Raised time.Time
    Due time.Time
    Paid bool
    Note string
    Items []*Item
}
```

```go
type XMLInvoice struct {
    XMLName xml.Name `xml:"INVOICE"`
    Id int `xml:"attr"`
    CustomerID int `xml:"attr"`
    Raised string `xml:"attr"`
    Due string `xml:"attr"`
    Paid bool `xml:"attr"`
    Note string `xml:"NOTE"`
    Items []*Item `xml:"ITEM"`
}
```

We have used the default names for the attributes—for example, field Customer will be an attribute with exactly the same name. There are two nested tags, `<NOTE>` and `<ITEM>`, and just as for the XMLInvoices struct, instead of calling the XML invoice's fields Items, we have called it Item (case-insensitively) to match the tag name.

We have made the XMLInvoices' Raised and Due fields strings since we want to handle their values ourselves (storing dates), rather than allow encoding/xml package to store full date/time strings.

## 8.1. Custom Data Files

Here is the original Item struct and the parallel XML-equivalent XMLItem.

```go
type Item struct {
    Id       string
    Price    float64
    Quantity int
    Note     string
}

type XMLItem struct {
    XMLName xml.Name `xml:"ITEM"`
    Id       string `xml:",attr"`
    Price    float64 `xml:",attr"`
    Quantity int `xml:",attr"`
    Note     string `xml:"NOTE"`
}
```

The XMLItem's fields are tagged to make attributes, except for the Note field which will become a nested <NOTE> tag, and the XMLName field which holds the item's own XML tag name.

Just as we did for the JSON format, for XML we have created an empty struct to give us something with to associate the XML-specific MarshalInvoices() and UnmarshalInvoices() methods.

This fulfills the generic InvoicesMarshaller and InvoicesUnmarshaler interfaces that we saw earlier (365).

```go
func (XMLMarshaller) MarshalInvoices(writer io.Writer, 
    invoices []*Invoice) error {
    if _, err := writer.Write([]byte(xml.Header)); err != nil {
        return err
    }
    xmlInvoices := XMLInvoicesForInvoices(invoices)
    encoder := xml.NewEncoder(writer)
    return encoder.Encode(xmlInvoices)
}
```

This method takes an io.Writer (i.e., anything that satisfies the io.Writer interface such into which we can write an open file or compressed file). The method begins by writing the standard XML header, `<?xml version="1.0"?>` (the xml.Header content also includes a trailing newline). Then it converts all the Invoices and their items into the equivalent XML structures. Although this looks like it will use as much memory as the original data, because Go's strings are immutable, under the hood only references to the original strings will be copied into the XML structs, so the overhead will not be great as it appears. And for applications that use XML tags directly, no conversion is necessary.

Once we have populated the xmlInvoices (of type XMLInvoices), we create a new xml.Encoder, passing it to the io.Writer we want it to write to. Then we encode all the data as XML and return the encoder's return value—which will be either error or nil.

```go
func XMLInvoicesForInvoices(invoices []*Invoice) *XMLInvoices {
	xmlInvoices := &XMLInvoices{
		Version: version,
		Invoice: make([]*XMLInvoice, 0, len(invoices)),
	}
	for _, invoice := range invoices {
		xmlInvoices.Invoice = append(xmlInvoices.Invoice, invoice)
	}
	return xmlInvoices
}
```

This function takes an []*Invoice and returns the equivalent XMLInvoice. The conversion is straightforward; we simply copy the Invoice values to the corresponding fields. Since we have chosen to handle the raised and due dates ourselves (so that we store only values and not times), we convert them to strings. And for the Invoice.Items we append each item as an XMLItem to the XMLInvoice slice.

```go
func XMLInvoiceForInvoice(invoice *Invoice) *XMLInvoice {
	xmlInvoice := &XMLInvoice{
		Id: invoice.Id,
		CustomerID: invoice.CustomerID,
		Raised: invoice.Raised.String(),
		Due: invoice.Due.String(),
		Paid: invoice.Paid,
		Note: invoice.Note,
		Items: make([]*XMLItem, 0, len(invoice.Items)),
	}
	for _, item := range invoice.Items {
		xmlItem := &XMLItem{
			Id: item.Id,
			Price: item.Price,
			Quantity: item.Quantity,
			Note: item.Note,
		}
		xmlInvoice.Items = append(xmlInvoice.Items, xmlItem)
	}
	return xmlInvoice
}
```

## 8.1.2. Reading XML Files

Reading XML files is slightly more involved than writing, especially if we have to parse some fields (such as dates); but it isn't difficult if we use suitable XML-tagged structs.

```go
func (XMLMarshaller) UnmarshalInvoices(reader io.Reader) ([]*Invoice,
error) {
	xmlInvoices := &XMLInvoices{}
	decoder := xml.NewDecoder(reader)
	if err := decoder.Decode(xmlInvoices); err != nil {
		return nil, err
	}
	if xmlInvoices.Version > fileVersion {
		return nil, fmt.Errorf("version %d is too new to read",
		xmlInvoices.Version)
	}
	return xmlInvoices, nil
}
```

This method takes an io.Reader (i.e., anything that satisfies the io.Reader interface such as an open file or compressed file), from which to read XML. The method begins by creating a pointer to an empty XMLInvoices struct and an xml.Decoder for reading the io.Reader. The entire XML file is then parsed by the xml.Decoder.Decode() method, and if the parse is successful the XMLInvoices struct is populated with the XML file's data. If the parse failed (e., if there is an XML syntax error or if the file isn't an invoices), the decoder will return an error which we immediately pass to the caller.
