## 6.1 Interfaces for reading and writing byte slices

We can also add custom methods—for example, func (i Integer) Double() Integer { return i * 2 }, as we will shortly (§6.2.1, ► 258). Not only are custom types based on built-in types easy to create, they are also efficient to use. Converting to or from a built-in type has no runtime cost since the conversion is efficiently done at compile time. In view of this is practically to "promote" values of built-in types to a custom type to use "demote" such values to the underlying built-in type when we want to pass them to functions whose parameters are of built-in types. We will see an example of promotion earlier when we converted a []string to a FoldedStrings (162 ►), and we will see an example of demotion when we first look at the Custom type later in this chapter (► 259).

## 6.2. Custom Types

Custom types are created using Go's type statement with the following syntax:

```
type tagName typeSpecification
```

The tagName can be any Go identifier that is unique to the enclosing package or function. The typeSpecification can be any built-in type (such as a string, int, map, or channel), an interface (see §6.3, ► 265), a struct (seen in earlier chapters, with more coverage later in this one, §6.4, ► 275), or a function signature.

In some situations creating a custom type is sufficient, but here we need to add methods to the custom type to make it really useful. Here are some examples of methodless custom types.

```
type Count int
type StringMap map[string]string
type FloatChan chan float64
```

None of these custom types look particularly useful on their own, although using types like this can improve a program's readability and can also make possible to change the underlying type later on, so they serve as a basic abstraction mechanism.

```
var i Count = 7
i++
fmt.Println(i)
sm := make(StringMap)
sm["key1"] = "value1"
sm["key2"] = "value2"
fmt.Println(sm)
fc := make(FloatChan, 1)
fc <- -2.2955814939
fmt.Println(-fc)
```

| map[key2:value2 key1:value1] |
| --- |
| 2.2955814939 |

Types like Count, StringMap, and FloatChan that are based directly on a built-in type can be used in the same way as the built-in type—for example, we can use the built-in append() function on a custom type []string—but we must convert them (at no cost because it is done at compile time) to the underlying type if we need to pass them to a function that expects their underlying type. And sometimes we need to do the reverse and promote the value of a built-in type to a custom type to benefit from the custom type's methods. We saw an example of this when converted a []string to a FoldedStrings value in the SortFoldedStrings() function (162) ◀

```
type RuneForRuneFunc func(rune) rune
```

When working with higher order functions (§5.6, 238 ◀) it is often convenient to define custom types that specify the signatures of the functions we want to pass. Here we have specified the signature of a function that takes and returns a single rune.

```
var removePunctuation RuneForRuneFunc
```

The removePunctuation variable is created to refer to a function of type RuneForRuneFunc (i.e., with the signature func(rune) rune). All variables are automatically initialized to its zero value, so in this case to nil.

```
phrases := []string{"Day; dusk, and night.", "All day long"}
removePunctuation = func(char rune) rune {
if unicode.Is(unicode.Punctuation, char) {
    return -1
}
return char
}
processPhrases(phrases, removePunctuation)
```

We have created an anonymous function that matches the RuneForRune signature and passed it to the custom processPhrases() function.

```go
func processPhrases(phrases []string, function RuneForRuneFunc) {
    for _, phrase := range phrases {
        fmt.Println(strings.Map(function, phrase))
    }
}
Day dusk and night
All day long

Using RuneForRuneFunc as a type rather than the underlying func(rune) rune is more meaningful for human readers; it also provides abstraction. (The strings.Map() function was covered in Chapter 3 ◄)

Creating custom types based on built-in types or function signatures can be useful, but doesn't get us far. What we need are custom methods, and the subject of the next subsection.

## 6.2.1. Adding Methods

A method is a special kind of function that is called on a value of a custom type and is (usually) passed as a pointer depending on how the method is defined. The syntax for defining methods is almost identical to defining functions, except that between the func keyword and the method's name we must write the receiver—this is written in parentheses, either as the type the method belongs to or as a variable. We can add one or more methods to any custom type. A method's receiver is always a value of the type or a pointer to the type. However, every method name must be unique for any given type. One consequence of the name requirement is that we cannot have two methods of the same name where one takes a pointer and the other a value. Another consequence is that there is no support for overloaded methods, that is, methods with the same name but different signatures; however the Go way is to use uniquely named methods.

This simple int-based custom type supports methods of which the two are declared to accept pointer receivers since both modify the value they are called on:

```type Count int

func (count *Count) Increment() { *count++ }
func (count *Count) Decrement() { *count-- }
func (count *Count) IsZero() bool { return count == 0 }
```

```
var count Count
i := &count
i.Increment()
j := &count
j.Decrement()
k := &count
fmt.Println(count, i, j, k.IsZero())
```
This code snippet shows the Count type in action. It doesn't look like much, but we will use it in this chapter's fourth section (► 278). Let's look at a slightly more elaborate custom type, this type based on a struct (We will return to this example in §6.3, ► 270).

```go
type Part struct {
  Id int    // Named field (aggregation)
  Name string // Named field (aggregation)
}

func (part *Part) LowerCase() {
  part.Name = strings.ToLower(part.Name)
}

func (part *Part) UpperCase() {
  part.Name = strings.ToUpper(part.Name)
}
```

* In C++ and Java receivers are always called `this` and in Python `self`; in Go the practice is to get more meaningful type-specific names.

```go
func (part Part) String() string {
	return fmt.Sprintf("%d %q", part.Id, part.Name)
}
func (part Part) HasPrefix(prefix string) bool {
	return strings.HasPrefix(part.Name, prefix)
}
```

We have made the String() and HasPrefix() methods accept a value receiver purely to show how it is done. Of course, methods that accept values rather than pointers cannot modify the value they are on.

```go
part := Part{5, "wrench"}
part.UpperCase()
part.Id += 1
fmt.Println(part, part.HasPrefix("w"))
```

When custom types are based on structs we can create values using the type name and a brace-enclosed list of initializing values. (As we will see, Go also has a syntax whereby we can provide just those values we want, and rely on Go to zero-initialize the rest.) Once the value is created we can call methods on it (e.g., Part.UpperCase()), access its exported (public) fields (e.g., Part.Id), and print it, safe in the knowledge that Go's print functions are intelligent enough to use the custom type's String() method if it has one.

A method is the set of all the methods that can be called on a value of the type.

If we have a pointer to a value of a custom type, its method set contains all the methods defined for the type—whether they accept a value or a pointer. If we call a method that takes a value, on a pointer, Go is smart enough to dereference the pointer and pass the underlying value as the method's receiver.

If we have a value of a custom type, its method set contains all of those methods defined for the type that accept a value receiver—but not those methods that accept a pointer receiver. This isn't limiting as if we have a value we can still call a method that has a pointer receiver and rely on Go to pass the value's address the value is addressable (i.e., it is a variable, a dereferenced pointer, or an array or slice, or an additional field in a struct). So, given the call `value.Method()` where `Method()` requires a pointer and `value` is an addressable value, Go will treat the code as if we had written `(&value).Method()`.
