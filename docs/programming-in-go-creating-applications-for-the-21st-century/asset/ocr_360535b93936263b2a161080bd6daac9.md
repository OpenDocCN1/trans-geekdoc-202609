# 6.3. Interfaces

```
func (pair StringPair) String() string {
treturn fmt.Sprintf("%q+%q", pair.first, pair.second)
}
```

This method returns a string that consists of each of the strings in double quotes with a "+" sign between them. With this method defined, Go’s fmt package’s print methods will use it to print StringPair values—and also *StringPair, since Go will dereference pointers to get the pointed-to value.

Here is a code snippet that shows the creation of some custom Exchanger values, some calls to the Exchange() method, and a call to a custom exchangeThese() function that accepts Exchanger values.

```
jekyll := StringPair("Henry", "Jekyll")
hlyde := StringPair("Edward", "Hyde")
point := Point(5,-3)
fmt.Println("Before", jekyll, hyde, point)
yll.Exchange() // Treated as: (&jekyll).Exchange()
hlyde.Exchange() // Treated as: (&hyde).Exchange()
point.Exchange() // Treated as: (&point).Exchange()
fmt.Println("After #1", jekyll, hyde, point)
exchangeThese(&jekyll, &hyde)
fmt.Println("After #2", jekyll, hyde, point)
```

> Before: "Henry"+"Jekyll" "Edward"+"Hyde" [5 -3]
After #1: "Jekyll"+"Henry" "Hyde"+"Edward" [-3 5]
After #2: "Henry"+"Jekyll" "Edward"+"Hyde" [5 -3]

 the variables are created as values, yet the Exchange() methods require pointer seems. This isn’t a problem, since we noted earlier, Go is smart enough to pass a value’s address when we call a method on it that requires pointer—providing the value is addressable. So, in the snippet, jekyll.Exchange() is automatically treated as if it were written (&jekyll).Exchange(), and the same for the others.

In the call to the exchangeThese() function, we must pass the values addresses explicitly. If, for instance, we passed the value of type StringPair, the Go compiler would notice that StringPairs do not fulfill the Exchanger interface—there is no Exchange() method with a StringPair receiver—and would stop compiling and report the error. However, if we pass a *StringPair (e.g., &hyde), the compilation will complete successfully. This works because there is an Exchange() method which takes a *StringPair receiver which means there is *String-Pairs fulfill the Exchanger interface.
