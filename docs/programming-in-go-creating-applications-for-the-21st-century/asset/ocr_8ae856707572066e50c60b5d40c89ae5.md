# 1.4. Big Digits—Two-Dimensional Slices

We will review the code in three parts: first the imports, then the static data, and then the processing. But right now, let's look at a sample run to get a feel for how it works:

```
$ ./bigdigits 290175493
222 9999 000 1 77777 55555 4 9999 333
2 2 9 9 0 0 11 7 5 44 9 3 3
2 9 9 0 0 1 7 5 4 4 9 3
9999 0 0 1 555 4 9999 33
2 9 0 0 1 7 5 5 444444 9 3
2 9 0 0 1 7 5 4 9 3 3
22222 9 000 111 7 555 9 333
```

Each digit is represented by a slice of strings, with all the digits together represented by a slice of slices of strings. Before looking at the data, here is how we could declare and initialize single-dimensional slices of strings and numbers:

```
longWeek := []string("Friday", "Saturday", "Sunday", "Monday")
var lowPrimes = []int{2, 3, 5, 7, 11, 13, 17, 19}
```

Slices form the Type if we want to initialize them immediately with a brace-delimited comma-separated list of elements of the corresponding type. We could have used the same variable declaration syntax for both, but have used a longer form for the lowPrimes slice to show the syntactic difference and for a reason that will be explained in a moment. Since a slice's Type itself can be a slice type we can easily create multidimensional collections (slices of slices, etc.).

The bigdigits program needs to import four packages.

```
import (
  "fmt"
  "log"
  "os"
  "path/filepath"
)
```

The fmt package provides functions for formatting text and reading formatted text ($3.5, ► 93). The log package provides logging functions. The os package provides platform-independent operating-system variables and functions including the os.Args variable of []string (slice of strings) that holds the command-line arguments. And the path package's filepath package provides functions for manipulating filenames and paths that work across platforms. Note that for packages that are logically other packages, we only specify the last component of their name (in this case filepath) when accessing them in our code.
