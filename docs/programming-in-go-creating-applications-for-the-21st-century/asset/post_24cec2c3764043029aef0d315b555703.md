The Stack type uses a slice for its representation and therefore Stack values can be used with functions that operate on a slice, such as append() and len(). Nonetheless, Stack values are in their own right, distinct from their representation, they must be passed by pointer if we want to modify them.

```go
func (stack Stack) Top() (interface{}, error) {
	if len(stack) == 0 {
		return nil, errors.New("can't Top() an empty stack")
	}
	return stack[len(stack)-1], nil
}
```

Stack.Top() returns the item at the top of the stack (the item that added last) and a nil error; or a nil item and a non-nil error value, if the stack is empty. The stack receiver is passed by value since the stack isn't modified.

The error type is an interface type ($6.3, ► 265) which specifies a single method, Error() string. In general, Go's library functions return an error as their last (or) return value to indicate success (where error is nil) or failure. Here, we have made our Stack type work like a standard library type by creating a new error using the package's errors.New() function.

Go uses nil for zero pointers (and for zero references); there is no pointer to nothing and for references that refer to nothing.* Such pointers should be used only in conditions or assignments; methods should not normally be called on them.

Constructors are never called implicitly in Go. Instead Go guarantees that when a value is created it is always initialized to its zero value. For example, numbers are initialized to 0, strings to the empty string, pointers to nil, and the fields inside structs are similarly initialized. There is no uninitialized data in Go, thus eliminating a major source of errors that afflicts many other programming languages. If the zero value isn't suitable we can write a construction function—and call it explicitly—as we here to prevent values of a type being created without using a construction function, as we will see in Chapter 6.

> * Go's nil is in effect the same as NULL or 0 in C and C++, in Java, and nil in Objective-C.

If the stack is nonempty we return its topmost value and a nil error value. Since Go uses 0-based indexing the first element in a slice or array is at position 0 and the last element is at position len(sliceOrArray) - 1.

There is no formality when returning more than one value from a function or method; we simply list the types we are returning after the function or method's name and ensure that we have at least one return statement that has a corresponding list of values.

```go
func (stack *stack) Pop() (interface{}, error) {
	theStack := *stack
	if len(theStack) == 0 {
		return nil, errors.New("can't Pop() an empty stack")
	}
	x := theStack[len(theStack)-1]
	*stack = theStack[:len(theStack)-1]
	return x, nil
}
```

The Stack.Pop() method is used to remove and return the top (last added) item from the stack. Like the Stack.Top() method it returns the top and a nil error, or if it is empty, a nil item and a nil-error.

The method must have a receiver that is a pointer since it modifies the stack. For syntactic convenience, rather than referring to *stack (the actual stack that the variable points to) throughout the method, we assign the actual stack to a local variable (theStack), and work with that variable instead. This is quite cheap, because *stack is pointing to a stack, which uses a slice for its representation, so we are assigning little more than a reference to a slice.

If the stack is empty we return a suitable error. Otherwise we retrieve the stack's top (last) item and store it in a local variable (x). We take a slice of the stack (which is a slice). The new slice has one less element than the original and is immediately set to be the value that the stack points to. At the end, we retrieve the returned value and a nil error. We can reasonably expect any Go compiler to compile the slice, simply reducing the slice's length by one, while leaving its capacity unchanged.

The item to return is retrieved using [] operator with a single index (⓪); in this case of the stack's last element. The new slice is obtained by using [] operator with an index range (②). An index range has the form: end. If first is omitted—as here—0 is assumed, and if end is omitted, the len() of the slice is used. The slice has elements from the first up to the last excluding the end. In this case, by specifying the last index as one less than the length, we used Stack receivers rather than pointers (i.e., *Stack) for methods that do not modify. For custom types with lightweight representations (say, few ints or strings), this is perfectly reasonable. As this example illustrates, creating custom types in Go is generally straightforward and doesn’t involve the cumbersome formalities that many other languages demand. Go’s object-oriented features are covered fully in Chapter 6. A subtle point is that if we call a method on a value, and the method requires a pointer Go is smart to pass the value’s address rather than a copy of the value (providing the value is addressable; §6.2.1, 258).

## 1.6. Americanise—Files, and Closures

To have any practical use a programming language must provide means of reading and writing external data. In previous sections we had a glimpse of Go’s versatile and powerful functions from its package; in this section we will look at Go’s basic file handling facilities. We will also look at some advanced features as Go’s treatment of functions and methods as first-class values which makes it possible to pass them as parameters and map types (dictionary or hash).

By the middle of the twentieth century, American English surpassed British as the most used form of English. In this section’s example we will review a program that reads a file and writes a copy of the file into a new file with any words replaced with U.S. counterparts. (This doesn’t help with differences in semantics or idioms, of course.) The program is in the file americanise/americanise.go, and we will review it top-down, starting with its imports, then its main() function, then the functions that main() calls, and so on.

> * This is why Go does not have or need the -> redirection operator used by C and C++.

```go
import (
    "bufio"
    "fmt"
    "io"
    "io/ioutil"
    "log"
    "os"
    "path/filepath"
    "regexp"
    "strings"
)
```

The americanise program's imports are from Go’s standard library. Packages can be nested inside one another without formality, as the io package's ioutil package and the path package's filepath package illustrate.

The bufio package provides functions for buffered I/O, including ones for reading and writing strings to UTF-8 encoded text files. The io package provides low-level I/O functions—and the io.Reader and io.Writer interfaces need for the americanise() program. The io/ioutil package provides high-level file handling functions. The regexp package provides powerful regular expression support. The other packages (fmt, log, filepath, and strings) have been mentioned in earlier sections.

```go
func main() {
	filename, inFile, err := filenamesFromCommandLine()
	if err != nil {
		fmt.Println(err)
		os.Exit(1)
	}

	inFile, outFile := os.Stdin, os.Stdout
	if inFile != "" {
		if err, err = os.Open(filename); err != nil {
			log.Fatal(err)
		}
		defer inFile.Close()
	}
	if outFile != "" {
		if err, err = os.Create(filename); err != nil {
			log.Fatal(err)
		}
		defer outFile.Close()
	}
	if err = americanise(inFile, outFile); err != nil {
		log.Fatal(err)
	}
}
```
