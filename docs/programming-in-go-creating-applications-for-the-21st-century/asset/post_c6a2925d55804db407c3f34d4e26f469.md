## 9.3. A Brief Survey of Go's Commands

Go installation for the gc compiler naturally includes compilers and linkers (6g, l1, etc.), but also a number of other tools. The most useful of these is go, which can be used as a build tool for our programs and packages, as a tool for downloading and installing third-party packages and packages, as a tool for executing unit tests and for benchmarking, as we saw earlier (§9.1.3, 414 ◀). Execute go for a full list of the commands available and go help command for help on the specified command. There is also the godoc tool for documentation ("The Go Documentation", 8 ▶.

In addition to the tools we have used in the book, there are several other tools and go tool commands, a few of which we will mention here. One is vet which does some error checking on Go programs, specifically on the fmt package's print functions.

Another command is go fix. Sometimes a new release incorporates changes the language—or more often, to library APIs—that invalidate existing code. By running go fix over our code base, all of our code can be automatically updated. We strongly recommend that go files are registered with a version control system, and that they are all checked in, or at least backed up, before running go fix. This will allow us to easily see what changes were applied and be to roll back any or all of them if the fixes break the code. We can also use go fix -diff option in the first place, since this shows the changes go fix would apply without actually applying them.

The last command we mention is goofmt. This command formats Go code in a standardized way and its use is highly recommended by the Go developers. The advantages of goofmt is that it eliminates arguments over the best way to lay out code, and it ensures that all Go code has a uniform look. All the book's code was formatted using goofmt (but lines longer than 75 characters were manually wrapped to fit on the book's pages).

## 9.4. A Brief Survey of the Go Standard Library

The Go standard library includes a large number of packages that provide them a wide range of functionality. The overview provided here is highly selective and very brief. This is because the contents of the library are likely to continue grow after this book is published, so it is best to look at the library APIs online (golang.org/pkg/) or locally using godoc, both to see the up-to-date information and to get a comprehensive overview of what is available in each package.

The exp "experimental" package is where packages that might potentially be added to the standard library begin, so these packages should not be used unless we specifically want to participate in their development (e.g., testing, commenting, or submitting patches). The exp package is normally available when pulling from Google's Go source tree, and it may not be included in prebuilt packages. All the other packages are okay to use, although at the time of this writing, some were incomplete.

### 9.4.1. Archive and Compression Packages

Go can read and write tarballs and .zip files. The relevant packages are archive/tar and archive/zip, and for compressed tarballs, compress/gzip and compress/bzip2. The book's pack and unpack examples illustrate the use of these ($8.2, 397).

Other formats are also supported; for example, Lempel-Ziv-Welch (compress/lzw) which is used for .tiff images and .pdf files.

### 9.4.2. Bytes and String-Related Packages

The bytes and strings packages have many functions in common, only the former operates on []byte values and the latter on string values. For strings, the strings provides all the most useful utilities to find substrings, replace substrings, split strings, trim strings, and change case (see $3.6.1, 107). The strconv provides conversions from numbers and Booleans to strings and vice versa (see $3.6.2, 113).

The fmt package provides a variety of extremely useful print and scan functions. The print functions were covered in Chapter 3 ($3.5, 93 ▶) with examples of use throughout the book, and the scan functions are shown in Table 8.2 (383 ▶), with some examples of use nearby ($8.1.2, 380 ▶).

The unicode package provides functions for determining character properties, such as whether a is a printable character, whether it is a digit ($3.6.4, 118 ▶). The unicode/utf8 and unicode/utf16 packages provide functions for decoding and encoding runes (i.e., Unicode code points/characters). For the unicode/utf8 package, we $3.6.3, 117 ▶. Some of the unicode/utf16 package is shown in Chapter 8's utf16-to-utf8 exercise solution.

The text/template and html/template packages can be used to create templates which can be used to generate textual output (e.g., HTML), based on data that is fed into them. Here is a tiny and very simple example of the text/template:

```go
type GIndex struct {
  Country string
  Index float64
}
gini := []GIndex{{"Japan", 54.7}, {"China", 55.0}, {"U.S.A.", 80.1}}
giniTable := template.New("giniTable")
giniTable.Parse(`<TABLE>
  {{range .}}    {{printf("<TR><td>%s</td><td>%.1f</td></tr>", .Country, .Index)}}
  {{end}}
</TABLE>`)
er := giniTable.Execute(os.Stdout, gini)
```
