# 8.1.2. Handling XML Files

The XML (eXtensible Markup Language) format is widely used both as a data interchange format and as a file format in its own right. XML is a much more complex and sophisticated format than JSON, but is generally more verbose and tedious to write by hand.

The encoding/xml package can encode and decode strings to and from XML in a manner similar to the encoding/json package. However, the XML encoding and decoding functionality is much more demanding than for encoding/json package. This is partly because xml package requires structs to have suitably formatted tags (whereas they are not always needed for JSON). Also, Go! encoding/xml package does not have an xml.Marshaler interface, so we must write more code to handle XML than the JSON and binary formats. (This is expected to be resolved in a later Go 1.x release).

Here is a single example invoice in XML format with newlines and whitespace to make it fit the page and be easier to read.

```
<INVOICE Id="2640" CustomerId="968" Raised="2012-08-27" Due="2012-09-26"
<Paid value="false"><NOTE>Special Terms &amp; Conditions</NOTE>
<Item Id="MI2419" Price="342.80" Quantity="1"><NOTE></NOTE></Item>
<Item Id="U9541" Price="448.99" Quantity="3"><NOTE>&quot;Blue&quot; ordered will be buck &quot; Navy&quot;</NOTE></Item>
<Item Id="IF9284" Price="475.01" Quantity="1"><NOTE></NOTE></Item>
<Item Id="TI4394" Price="417.79" Quantity="2"><NOTE></NOTE></Item>
<Item Id="V64325" Price="48.67" Quantity="5"><NOTE></NOTE></Item>
</INVOICE>
```

Having raw character data in tags (e.g., for the invoices' and items' fields) is tricky rather when using the xml package encoder and decoder, so the invoicedata example uses explicit <NOTE> tags.
