# 4.2. Arrays and Slices

Go provides a sort.Search() method which uses the binary search algorithm: This requires the comparison of log2(n) items (where n is the number of items) each time. To put this in perspective, a linear search of 100 000 items requires 500 000 comparisons on average, with a worst case of 1 000 000 comparisons; a binary search needs at most 20 comparisons, even in the worst case.

sort.Search() function takes two arguments: the length of the slice to work on and a function that compares an item in a sorted slice with a target item using the >= operator for slices that are sorted in ascending order or the <= operator for slices in descending order. The function must be a closure, that is, it must be created in the scope of the slice it is to work on since it must capture the slice as part of its state. (Closures are covered in 5.6.3, ► 225.) The sort.Search() returns an int; only if it is less than the length of the slice and the item at index position matches the target, can we be sure that we found the item we are looking for.
