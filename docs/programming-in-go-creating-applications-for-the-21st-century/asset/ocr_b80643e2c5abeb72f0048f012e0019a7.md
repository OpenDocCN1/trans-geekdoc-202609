# 1.7. Polar to Cartesian—Concurrency

```
var prompt = "Enter a radius and an angle (in degrees), e.g., 12.5 90, " +
  "or %s is to quit."

func init() {
    if runtime.GOOS == "windows" {
        prompt = fmt.Sprint(prompt, Ctrl+Z, Enter)
    } else { // Unix-like
        prompt = fmt.Sprint(prompt, Ctrl+D)
    }
}
```

If a package has one or more init() functions they are automatically executed before the main package's main() function is called. (In fact, init() functions must never be called explicitly.) So when our polar2esian prompt is invoked this init() function is the first that is called. We use init() to set the prompt to account for platform differences in how end of file is signified—example, on Windows end of file is given by pressing Ctrl+Z then. Go's runtime package identifies the operating system by constant called GOOS (Go Operating System) which is a string identifying the operating system is running on. Typical values are darwin (Mac OS X), freebsd, linux, and windows.

Before diving into main() and the rest of the program we will briefly discuss channels and show some toy examples before seeing them in proper use.

Channels are modeled on Unix pipes and provide two-way (or at our option, one-way) communication of data items. Channels behave like FIFO, (in first, first out) queues, hence they preserve the order of the items that are sent into them. Items cannot be dropped from a channel, but we are free to ignore or all of the items we receive. Let's look at a very simple example. We will make a channel:

```
messages := make(chan string, 10)
```

Channels are created with the make() function (Chapter 7) and are declared using the syntax, chan Type. Here we have the messages channel to send and receive strings. The second argument to make() is the buffer size (which defaults to 0); here we made it enough to accept ten integers. If a channel's buffer is filled it blocks until least one item is received from it. This means that any number of items can pass through a channel, providing the items are retrieved to make room for subsequent items. A channel with a buffer size of 0 can only send an item if the other end is waiting for an item. (It is also possible to get the effect of nonblocking channels using Go's select statement, as we will see in Chapter 7).
