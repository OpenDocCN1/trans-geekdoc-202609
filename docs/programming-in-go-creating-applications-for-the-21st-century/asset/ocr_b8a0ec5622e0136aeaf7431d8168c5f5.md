# 4.1. Values, Pointers, and Reference Types

In this section we discuss what variables hold (values, pointers, and references—including array values, slice and map references), whereas in the following sections we explain how to actually use arrays, slices, and maps.

In general, Go variables hold values. That is, we can think of a variable as “being” the value it stores. The exceptions are variables that refer to channels, functions, methods, and slices—these hold references—and variables that hold pointers.

Values that are passed to functions or methods is called. This is cheap for Booleans and numbers because they only occupy from one to eight bytes each. Passing strings by value is also cheap because Go compilers can safely optimize them so that only a small amount of data is actually passed per string, no matter how large the string is, since Go strings are immutable.(The amount per string is 16 bytes on 64-bit machines and 8 bytes on 32-bit machines.) Of course, if a passed-in string is modified (e.g., using the += operator), the scenes Go do a copy on write which would be expensive for large strings—but this is a price that would have to be paid no matter what language was used.

Unlike C or C++, Go are passed by value—so passing large arrays are expensive. Fortunately, arrays are rarely needed in Go programming since slices are used instead, as we will see in the next section. Passing a slice costs much the same as 16 bytes on 64-bit machines and 12 bytes on 32-bit machines), no matter there is any copy on write overhead if the slice is modified, because unlike strings, slices are mutable (if, if a slice is modified the modification is visible to all the variables—references—that refer to it).
