Both the *Part and *StringPair types satisfy all the cas interfaces, including the ChangeCaser interface since it embeds interfaces that the types fulfill. They also satisfy the standard library's fmt.Stringer. And the *StringPair type also satisfies our Exchanger interface and the standard library's io.Reader.

We are not obliged to fulfill every interface—for example, if we chose not to implement the StringPair.FixCase() method the *StringPair type would satisfy only the LowerCase, UpperCase, LowerUpperCase, Exchanger, fmt.Stringer, and io.Reader.

Let's create a couple of these values and see some of the methods in use.

```
toastRack := Part{8427, "TOAST RACK"}
toastRack.LowerCase()
lobelia := StringPair{"LOBELIA", "SACKVILLE-BAGGINS"}
lobelia.FixCase()
fmt.Println(toastRack, lobelia)

8427 "toast rack" "Sackville-Baggins"
```

The methods are called and behave as we expect. But what happens if we have a bunch of such values and want to call a method on them? Here is a bad way to do it.

```
for _, x := range [interface]{&toastRack, &lobelia} { // UNSAFE!
    x.(UpperCase).UpperCase() // Unchecked type assertion
}
```

We must use pointers to the values since all the case methods modify the value they are called on and require pointer receivers.

The approach used in this snippet has two deficiencies. The minor deficiency is that the unchecked type assertion is to the LowerUpperCase interface which is more general than the interface we actually use. We could have done worse, though, and used the ChangeCase interface since that is even more general. But we could not use the FixCase interface since that provides only the FixCase() method.
