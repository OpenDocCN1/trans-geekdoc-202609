If we had a very small replacer function, say, one that simply uppercased words it matched, we could have created it as an anonymous function when we called the replacement function. For example:

```
line = strings.ReplaceAllFunc(line,
func(word string) string { return strings.ToUpper(word) })
```

However, the american program's replacer function, although only a few lines long, requires some preparation, so we have created makeReplacerFunction(), with given the name of a file that contains lines of original and replacement words, returns a replacer function that will perform the appropriate replacements.

If the makeReplacerFunction returns a non-nil error, we return and the caller is expected to check the returned error and respond appropriately (as it does).

Regular expressions can be compiled using regexp.Compile() function which returns *regexp.Regexp and nil, or nil and error if the regular expression is invalid. This is ideal for use from an external source or a file received from the user. Here, we have used the regexp.Compile() function—this simply returns a *regexp.Regexp, or panics if the regular expression, or "regex", is invalid. The regular expression used in the example matches the longest sequence of one or more alphabetic characters.

With the replacer function and the regular expression in place we start an infinite loop by reading a line from the reader. The bufio.Reader.String() method reads (or strictly speaking, decodes) the underlying reader's raw bytes as UTF-8 encoded text (which also works for 7-bit ASCII) up to and including the byte (or to the end of the file). The function conveniently returns the text with an error (or nil).

If the error returned by the call to the bufio.Reader.String() method is not nil, either we have reached the end of the input or we have hit a problem. At the end of the input err will be io.EOF which is perfectly okay, in this case we set err to nil (since there isn't an error), and set err to ensure that the loop finishes at the next iteration, so won't advance beyond the end of the file. We don't return immediately with io.EOF, since it is possible that the file's last line doesn't end with a newline, in which case we will receive a line to be processed, in addition to the io.EOF.

For each line we use the regexp.Regexp.ReplaceAllStringFunc() method, giving it the line and the replacer function.
