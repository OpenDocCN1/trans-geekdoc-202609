We create an anonymous deferred function that will flush the writer's buffer before the americanise() function returns control to its caller. The anonymous function will be called when americanise() returns normally—or abnormally due to a panic. If no error occurs and the writer's buffer contains unwritten bytes, the bytes will be written before americanise() returns. Since it is possible that the flush will fail we set the err value to the result of the writer.Flush(). A less defensive approach would be to have a much simpler statement of defer writer.Flush() to ensure the writer is flushed before the function returns and ignoring any error that might have occurred before the flush—or occurs during the flush.

Go allows use of named return values, and we have taken advantage of this facility here in filenamesCommandLine(). Be aware, however, that there is subtle scoping issue we must consider when using named return values. For example, if we have a named return value, we can assign it to anywhere in the function using the assignment operator (=) as expect. However, if we have a statement such as value :=, if the statement starts a new block, the value in the state will be a new variable, so the statement's variable will shadow the return variable. In the americanise() function, err is a named return value, so we have made sure that we never assign it using the short variable declaration operator (:=) to avoid the risk of accidentally creating a shadow variable. One consequence of this is that we must declare the variables we want to assign to the same time, such as the replace function (35 ◀, ⌨) and the line we read in (35 ◀, ⌨). An alternative approach is to avoid named return values and return the required value or explicitly, as we have done elsewhere.

One other small point to note is that we have used the blank identifier, _ (35 ◀). The blank identifier serves as a placeholder for where a variable is expected in an assignment, and discards any value it gives. The blank identifier is not considered to be a new variable, so if used with :=, at least one (new) variable must be assigned to.

The Go standard library contains a powerful regular expression package regexp ($3.6.5, 120). This package can be used to create pointers to regexp.Regex (i.e., of type *regexp.Regex). These values provide methods for searching and replacing. Here we have chosen to use the exp.Regex.ReplaceAllStringFunc() method which given a string and a “replacer” string, calls the replacer function for every match, passing in the matched text, and replacing the matched text with the text replacer returns.
