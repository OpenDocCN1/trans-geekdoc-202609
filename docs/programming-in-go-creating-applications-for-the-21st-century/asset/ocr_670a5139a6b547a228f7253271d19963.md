# Epilogue

The Go developers took a long hard look at some of the most widely used programming languages and tried to discern which features were really useful and productive to have, and which were redundant or even counterproductive. They also drew on the many decades of programming experience that they collectively had had. As a result they produced the Go programming language.

In the tradition of Objective-C and C++, Go is an object-oriented "better C". Like Java, Go has its own syntax, so it doesn't have to maintain C compatibility in the way that Objective-C and C++ do. But unlike Java, Go compiles to native code and is not limited to the speed of a virtual machine.

In addition to Go's novel approach to object orientation with its emphasis on abstract interfaces and concrete types with smart embedding and aggregation, Go also supports advanced features such as function literals and closures. And Go's built-in map and slice types between them serve almost every data structure need. Go's Unicode-based string type uses the world's facto standard encoding (UTF-8), and the standard library provides excellent support at both the type and character level.

Go's support for concurrency is outstanding. Its lightweight goroutines and its type-safe and high-level channels make it much easier to create concurrent programs compared with many other languages (e.g., C, C++, or Java). And Go's lightning-fast compilation times are a breath of fresh air, especially to anyone used to building large C++ programs and libraries.

Go is already being used by a variety of commercial and noncommercial organizations. Go is used internally by Google, as well as being available alongside Java and Python, as a language for developing web applications with the Google App Engine (google.com/appengine/docs/go/overview.html).

The language is still evolving quite quickly, thanks to the go tool, it is easy to update code with the latest release. Furthermore, the Go developers intend to keep all Go 1.x versions backward compatible with Go 1 to ensure that Go users have a language that is both stable and being improved at the same time.
