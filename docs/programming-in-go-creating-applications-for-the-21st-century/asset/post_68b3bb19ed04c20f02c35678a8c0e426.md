## 2.2. Boolean Values and Expressions

Go provides two built-in Boolean values, true and false, both of type bool. Go supports the logical and comparison operators, all of which produce a result; they are shown in Table 2.3.

Boolean values and expressions are used in statements (§5.2.1, ► 192), in the conditions of statements (§5.2.2, ► 195), and sometimes in the conditions of switch statements' care clauses (§5.3), as we will see in Chapter 5.

The binary logical operators (| || &&) use short-circuit logic. This means that if we have b1 || b2 expression b1 evaluates to true, the result must be true no what b2 is, it is returned and b2 is not evaluated. Similarly, if have b1 && b2 and expression b1 evaluates to false, the result must be false, false is returned and b2 is not evaluated.

Go is strict about the values that can be compared using the comparison operators, <, <=, !=, >. The two values must be of the same type, or—if interfaces—they implement must of a type that is compatible with the other's type. a constant then it must be of a type that untyped numeric constant can be compared with another value of any numeric type, but numbers of different types—and that are constants—cannot be compared unless one of them is explicitly converted to be the same type as the other. (Numeric conversions are discussed in §2.3, ► 57).

### Table 2.3 Boolean and Comparison Operators

| Syntax | Description/result |
| :--- | :--- |
| !b | Logical NOT operator; false if Boolean expression b is true |
| a || b | Short-circuit logical OR operator; true if either Boolean expression a or b is true |
| a && b | Short-circuit logical AND operator; true if both Boolean expressions a and b are true |
| x < y | true if expression x is less than expression |

The == and != operators can be applied to operands of any comparable types, including arrays and structs whose items or fields are comparable with == and !=. These operators cannot be used to compare slices, although a comparison can be done using the Go standard library's reflect.DeepEqual() function. The == and != operators are used to compare pointers or interfaces—or compare a pointer or reference (e.g., a channel, map, or slice) with nil. The comparison operators (<, <=, >=, > may be applied only to numbers and strings. (Since Go—like C and Java—doesn't support operator overloading, for our own custom types we can implement our own comparison methods or functions needed, such as Less() or Equal(), as we will see in Chapter 6.)

## 2.3. Numeric Types

Go provides a wide range of built-in numeric types, and the standard library adds integers of type big.Int and rationals of type big.Rat which are unbounded (i.e., limited only by the memory's). Every numeric type is distinct: This means that we cannot use binary arithmetic operations or comparisons (e.g., + or -) on values of different types (e.g., of type int and int32), no matter what. If we need to perform arithmetic or comparisons on typed numbers of different types we must perform conversions—usually from one type to another to succeed—even if this results in data loss. Here are some examples:

```
const factor = 3 // factor is compatible with any numeric type
i := 0           // i is of type int
i* = factor
j := int16(20)      // j is of type int16; same as: var j int16
i += int(j)         // Types must match so conversion is required
k := uint8(0)        // Same as: var uint8
k = uint8(i)        // Succeeds, but k's value is truncated to 8 bits
fmt.Println(i, j, k) // Prints: 20
```

If we want to parse sliceconversions can always create suitable functions. For example:

```go
func Uint8FromInt(x int) (uint8, error) {
	if 0 <= x <= math.MaxUint8 {
		return uint8(x), nil
	}
	return 0, fmt.Errorf("%d is out of range", x)
}
```

Numbers of the same type can be compared using the comparison operators (see Table 2.3). Similarly, Go's arithmetic operators can be applied to numbers; these are shown in Table 2.4 (59) applicable to all built-in numbers, and in Table 2.6 (60) applicable only to integers. Constants are evaluated at compile time; they may use any of the arithmetic, Boolean, and comparator operators. For example:

```
const (
	efri int64 = 100000000000 // type: int64
	hlutföll = 16.0 / 9.0     // type: float64
	mælikvarða = complex(-2, 3.5) // type: complex
	erGjgengur = 0.0 <= 1.0 // type: bool

```

The example uses Icelandic identifiers as a reminder that Go fully supports native identifiers. (We will discuss complex() shortly; 2.3.2.1, ► 70.)

## 2.3.1. Integer Types

Go provides 11 separate integer types, five signed and unsigned, plus an integer type for storing pointers—their names and values are shown in Table 2.5. In addition, Go allows the use of byte as a synonym for the unsigned uint8 type and encourages the use of rune as a synonym for the int32 type when working with individual characters (i.e., Unicode code points). For processing purposes the only integer type that we need is int. This is suitable for counters, array and slice indices, and all general-purpose integer arithmetic; it is also normally the type that offers the fastest processing speeds. At the time of writing, the int is represented by a signed 32-bit integer (even on 64-bit platforms), but is expected to change to 64-bit in a future version.

The other integer types that Go provides are needed when it comes to reading and writing integers outside the program—for example, from and to files or network connections. In such cases it is essential to know exactly how many bits must be read or written so that integers can be handled without corruption.

* A panic is an exception; see Chapter 1 (32 ◄) and 5.5, ► 212.
