The import statement (14, ➤) imports three packages from the standard library. the fmt package provides functions for formatting text and for reading text (3.5, ➤), the os package provides platform-independent operating-system variables and functions, and the strings package provides functions for manipulating strings (3.6.1, ➤).

Go's fundamental types support the usual operators (,, + for numeric addition and string concatenation), and the Go standard library supplements these by providing packages of functions with the fundamental types, as the strings package imported here. it is also possible to create our custom types based on the fundamental types and to provide our own methods—that is, custom type-specific functions—for them. (We will get a taste of this in 1.5, ➤, with full coverage in Chapter 6).

The reader may have noticed that the program has no semicolons; the imports are not comma-separated, and that if the statement's condition does not require parentheses. In Go, blocks, including function and control structures (e.g., for if statements and for loops), are delimited using braces. Indentation is used instead of semicolons; they are put in the compiler, so Go states are separated by semicolons, we don't have to use ourselves unless we want to put multiple statements on the same line. Semicolons and fewer commas and parentheses give Go a lighter look and require less typing.

Go functions and methods are defined using the func keyword. The main package's main function always has the signature—it takes no arguments and returns nothing. When main() finishes the program will terminate and return θ to the operating system. Naturally, we can exit whenever we like and return our own choice of value, as we see (1.4, ➤).

The first statement in the main() function (14, ➤, using the := operator) is a short variable declaration in Go terminology. Such a statement declares and initializes a variable at the same time. Furthermore, we don't need to specify the variable type because Go can deduce from the initializing value. In this case we have declared a variable name of type string, and thanks to Go's strong typing we may only assign strings to name.

As with most languages the if statement tests a condition—in this case, how many strings were entered on the command-line—which we will see a more sophisticated if statement syntax later in this chapter (1.6, ➤), and further in (5.2.1, ➤).

The os.Args variable is a slice of slices (14, ➤). Arrays, slices, and other collection data types are covered in Chapter 4 (4.2, ➤). For it is sufficient to know that a slice's length can be determined using the built-in len() function and its elements can be accessed using the [] operator using a subset of the Python syntax. In particular, slice[n] returns the slice's nth element (counting from zero), and slice[n:] returns another slice which has the elements from the nth element to the last element. In the collections we will see the full generality of Go's syntax in this area. In the case of os.Args, the slice should always have at least one string (the program's name), at index 0. (All indexing is zero-based.)

## 1.4. Big Digits—Two-Dimensional Slices

The bigdigits program (in bigdigits.go) reads a number on the command line (as a string), and outputs the same number onto the console. Back in the twentieth century, where lots of users shared a high-speed printer, each user's job to be preceded by a cover that showed some details as their username and the name of the file being printed. We will review the code in three parts: first the imports, then the static data, and then processing. But right now, let's look at a sample run to get a feel for how it works

Each digit is represented by a slice of strings, with all digits together represented by a slice of slices. Before looking at the data, here is how we could declare and initialize single-dimensional slices of strings and numbers:

```go
week := []string{"Friday", "Saturday", "Monday"}
var lowPrimes = []int{2, 3, 5, 7, 11, 13, 17, 19}
```

Slices form the type if we want to initialize them immediately with a brace-delimited comma-separated list of elements. We could have used the same variable declaration syntax for both, but used a longer form for the lowPrimes slice to show the syntactic difference and for a reason that will be explained in a moment. Since a slice's type itself can be a slice we can easily create multidimensional collections (slices of slices, etc.).

The bigdigits program needs to import four packages.

```go
import (
  "fmt"
  "log"
  "os"
  "path/filepath"
)
```

The fmt package provides functions for formatting text and reading formatted text (3.5, ► 93). The log package provides logging functions. The os package provides platform-independent operating-system variables and functions including the os.Args variable of []string (slice of strings) that holds the command-line arguments. And the path package's filepath package provides functions for manipulating filenames and paths that work across platforms. Note that for packages that are logically other, we only specify the last component of their name (in this case filepath) when accessing them in our code.

For the bigdigits program we need two-dimensional data (a slice of slices of strings). Here is how we have created it, with the strings for digit 0 laid out to illustrate how a digit's strings correspond to rows in the output, and with the strings for digits 3 to 8 included.

```go
var bigDigits = [][]string{
  "000",
  "00",
  "00",
  "00",
  "00",
  "000",
  "111", "22222",
  "22222", "2", "2", "2", "2", "22222",
  ... 3 to 8
  "99999", "999", "9999", "9", "9", "9",
}
```

Variables declared outside of any function or method may not use the := operator, but we can get the same effect using the long declaration form (with var) and the assignment operator (=) as we have done here for the bigdigits variable (and earlier for the lowPrimes variable). We still don't need to specify bigdigits' type since Go can deduce that from the assignment.

We leave the counting to the Go compiler, so there is no need to specify the dimensions of the slice of slices. One of Go's many conveniences is its excellent support for composite literals, braces so we don't have to declare a data variable in one place and populate it with data in another—unless we want to, course.
