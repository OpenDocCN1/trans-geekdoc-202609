# 12 Chapter 1. An Overview in Five Examples

For the go tool to be able to build local programs and packages, there are three requirements. First, the Go binary directory ($GOROT/bin or %GOROT%\bin) must be in the path. Second, there must be a directory that has an src directory under which the source code for the local programs and packages resides. For example, the book's examples unpack to goeg/src/hello, goeg/src/bigdigits, and so on. Third, the directory above the src directory must be in the GOPATH environment variable. For example, to build the book's hello example using the go tool, we must do this:

```
$ export GOPATH=$HOME/goeg
$ cd $GOPATH/src/hello
$ go build
```

We do almost exactly the same on Windows:

```
C:\set GOPATH=C:\goeg
C:\>cd %opath%\src\hello
C:\>goeg\src\hello-go build
```

In both cases we assume that the PATH includes $GOROT/bin or %GOROT%\bin. Once the go tool has built the program we can run it. By default the executable is given the same name as the directory it is in (e.g., hello on Unix-like systems and hello.exe on Windows). Once built, we can run the program in the usual way.

```
$ ./hello
Hello World!
```

Or:

```
$ ./hello Go Programmers!
Hello Go Programmers!
```

On Windows it is very similar:

```
C:\goeg\src\hello-hello Windows Go Programmers!
Hello Go Programmers!
```

We have shown what must be typed in bold and the console's text in Roman. We have also assumed a $ prompt, but it doesn't matter what it is (e.g., C:\>).

Note that we do not need to compile—or even explicitly any other packages (even though we will see, hello.go uses three standard library packages). This is another reason why Go programs build so quickly.
