
This web site has only one page, although the technique we will present can be easily applied to multiple pages. If a panic occurs that is not caught by a recover(), that is, if a panic reaches the main() function, the server will terminate; this is what we must protect against.

```go
func homePage(writer http.ResponseWriter, request *http.Request) {
	defer func() {
		if x := recover(); x != nil {
			log.Printf("%s caught panic: %v", request.RemoteAddr, x)
		}
	}()
	// ...
}
```

For a web server to be robust in the face of panics we must make sure that every page handler has a deferred function that calls recover(). This will stop any panic from propagating (since deferred statements are executed just before a function returns). Of course, for a large web site with lots of handlers, adding a deferred function to catch and log panics involves a lot of duplication and is easy to forget. This can be solved by using a wrapper function that has the code needed by each page handler. Using the wrapper we can omit the recover code from page handlers, so long as we change the http.HandleFunc() calls:

```go
http.HandleFunc("/", logPanics(homePage))

func logPanics(function func(http.ResponseWriter, request *http.Request)) func(http.ResponseWriter, request *http.Request) {
	return func(writer http.ResponseWriter, request *http.Request) {
		defer func() {
			if x := recover(); x != nil {
				log.Printf("%s caught panic: %v", request.RemoteAddr, x)
			}
		}()
		function(writer, request)
	}
}
```

## 5.6. Custom Functions

Functions are the bedrock of procedural programming and Go provides first-class support for them. Go methods (covered in Chapter 6) are very similar to Go functions, so this section is relevant for both procedural and object-oriented programming. Here are the fundamental syntaxes for function definitions:

```go
func name(optionalParameters) optionalReturnType {}
func name(optionalParameters) (optionalReturnValues) {}
```

A function can take zero or more parameters. If there are no parameters the parentheses. If there is one or more, they are written params1 type, ..., paramsN type, where params1 is a single parameter name or a comma-separated list of two or more parameter names of the given type. Parameters must be passed in the order: there is no equivalent to Python's named parameters, although a similar effect can be achieved as we will see later.

The very last parameter's type may be preceded by an ellipsis (...). Such functions are called variadic; this means the function will accept zero or more values of that type as that parameter's value and inside the function parameter will be of type []type.

A function may return zero or more values. If there are none value it can be written as type. If there are two or more return values, parentheses must be used and they are written as (type1, ..., typeN). If there are one or more named return values, parentheses must be used and they are written as (values1 type1, ..., valuesN typeN), where values1 is a single return name or a comma-separated list of two or more return names of the given type. Function return values may all be unnamed or all named, but not a mixture.

Functions that have one or more return values must have at least one return statement—or a call to panic() as their final statement. If return values are unnamed, the return statement must specify as many values as there are return values, each with a type matching the corresponding return value. If the return values are named the return statement can either specify values just like in the unnamed case or bare (i.e., giving no explicit values to return). Note that although bare returns are legal, they are considered poor style—none of the book's examples use them.

If a function has one or more return values its last executable statement must be a return or a panic(). Go compilers are smart enough to realize that a function ends with a panic won't return normally and so doesn't return a statement at that point. Unfortunately, current Go compilers do not understand that an if has an unconditional else statement ends with a return statement, or a switch statement has a default case that ends with a return statement, no additional return is needed afterward.
