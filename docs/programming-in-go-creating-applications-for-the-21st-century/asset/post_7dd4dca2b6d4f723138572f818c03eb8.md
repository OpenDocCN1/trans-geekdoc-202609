## The Go Documentation

Go's official web site is golang.org which hosts the most up-to-date documentation. The "Packages" link provides access to the documentation on all Go standard library’s packages—and their source code, which can be very helpful when the documentation is sparse. The "Commands" link leads to the documentation for the programs distributed with Go (e.g., the compilers, build tools, etc.). The "Specification" link leads to an accessible, informal, and quite thorough Go language specification, and the "Effective Go" link leads to a document that explains many best practices.

The web site also features a sandbox in which (somewhat limited) Go programs can be written, compiled, and run, all online. This is useful for beginners for checking odd bits of syntax and for learning the fmt package sophisticated formatting facilities or the regexp regular expression engine. The Go web search searches only the Go documentation; search for Go resources generally, visit go-cat-v.org/go-search.

The Go documentation can also be viewed locally, in a web browser. To do this, run godoc tool with a command-line argument that tells it to operate as a web server. Here's how to do this in a Unix console (xterm, gnome-terminal, console, Terminal.app, or similar):

```
$ godoc -http=8000
```

In a Windows console (i.e., a Command Prompt or MS-DOS Prompt window):

```
C:\godoc -http=8000
```

The number used here is arbitrary—use one different if it conflicts with an existing server. This assumes that godoc is in your PATH.

To view the served documentation, open a web browser and give it a http://localhost:8000. This will present a page that looks very similar to the golang.org web site’s front page. The "Packages" link will show the documentation for Go’s standard library, plus any third-party packages that have been installed under GOROOT. If GOPATH is defined (e.g., for local programs and packages), a link will appear beside the "Packages" link through which the relevant documentation can be accessed. (The GOROOT and GOPATH environment variables are discussed later in this chapter and in Chapter 9).

It is also possible to view the documentation for a single package or a small item in the console by executing godoc on the command line. For example, executing godoc main will output the documentation for the main() function, and executing godoc . will output the documentation for the entire . package.

## 1.1. Getting Go

The Go compiler is called gc and its toolchain includes programs as gc, go, and noob for compiling, link, and test for linking, and godoc for viewing the Go documentation. (These are gc.exe, go.exe, etc., on Windows). The strange names follow Plan 9 operating system's compiler conventions where the digit identifies the architecture (e.g., "5" for ARM, "6" for AMD—including 64-bit processors—and "8" for Intel 386). Frankly, we don't need to concern ourselves with these tools since Go provides a high-level build tool that handles the compiling and linking for you. Go comes with support for using C code from Go programs in the form of the cgo tool (golang.org/cmd/cgo), and at least on Linux and BSD systems, with C and C++ code can be used in Go programs using the SWIG tool (www.swig.org).

In addition there is also the gccgo compiler. A Go-specific front to gcc (the GNU Compiler Collection) available for gcc from version 4.6. Like gc, gccgo may be available for some Linux distributions. Instructions for building and installing gccgo are given at golang.org/doc/gccgo_install.html.

## 1.2. Editing, Compiling, and Running

Go programs are written as plain text using the UTF-8 encoding. Most modern text editors can handle this automatically, and some of the most popular may even have support for Go color highlighting and automatic indentation.

> Some Windows editors (e.g., Notepad) go against the Unicode standard's recommendation and insert the bytes 0xEF, 0x88, 0x8F, at the start of UTF-8 files. This book's examples assume that UTF-8 files do not have these bytes.

## Go Shebang Scripts

One side effect of Go's fast compilation is that it makes it realistic to write Go programs that can be treated as shebang (!) scripts on Unix-like systems. This requires a one-off step of installing a suitable tool. At the time of writing, two rival tools provide the necessary functionality: gonow (github.com/kless/gonow), and gorun (wiki.ubuntu.com/gorun).

Once gorun is available, we can make any Go program into a shebang script. This is done with two simple steps. First, add #!/usr/bin/env gonow or #!/usr/bin/env gorun, as the very first line of the .go file that contains the main() function (in package). Second, make the file executable (e.g., with chmod +x). Such files can only be compiled by gonow or gorun rather than in the normal way where # line is not legal in Go.

When gorun executes a .go file for the first time, it will compile it (extremely fast, of course), and then run it. On subsequent runs, the program will only be recompiled if the go source file has been modified since the previous compilation. This makes it possible to use Go quickly and conveniently create various small utility programs, for example, for system administration tasks.

If your editor doesn't have Go support, try entering the editor's name in the Go search engine to see if there are suitable add-ons. For convenience, all of Go's keywords and operators use ASCII characters; however, Go identifiers can start with any Unicode letter followed by any Unicode letter or digits, so Go programmers can freely use their native language.
