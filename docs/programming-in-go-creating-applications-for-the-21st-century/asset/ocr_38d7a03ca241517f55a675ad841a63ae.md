```
func readInItems(reader io.Reader, count int) ([]*Item, error) {
    items := make([]*Item, 0, count)
    for i := 0; i < count; i++ {
        item, err := readItem(reader)
        if err != nil {
            return nil, err
        }
        items = append(items, item)
    }
    return items, nil
}
```

This function reads in all of an invoice's items. It knows how many items to read because it is passed the count.

```
func readItem(reader io.Reader) (item *Item, err error) {
    item := &Item{}
    if item.Id, err := readInvString(reader); err != nil {
        return nil, err
    }
    if err := binary.Read(reader, byteOrder, &item.Price); err != nil {
        return nil, err
    }
    if item.Quantity, err = readIntFrom16(reader); err != nil {
        return nil, err
    }
    item.Note, err = readInvString(reader)
    return item, err
}
```

This function reads each individual item. Structurally, it is very similar to the readInvoice() function that it creates a zero-valued Item and stores a pointer to it in the item variable, and then populates the items. The price can be read directly since that was written as a float64—that is, as a sized type—and the Item.Price field has the same name (We omitted it since almost identical to the readIntFrom16() function we saw earlier: 393.)

This completes our review of writing and reading custom binary data. Working with binary data isn't difficult, so long as we are careful to use specifically signed and sized integers and to precede variable-length values (e.g., slices) with their length.
