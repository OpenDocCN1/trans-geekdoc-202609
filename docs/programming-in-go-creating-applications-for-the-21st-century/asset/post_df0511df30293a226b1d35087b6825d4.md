The slices passed to the built-in copy() function must be of the same type—except that the first (destination) slice is a []byte the second (source) argument may be a []byte or a string. If the source is a string, its bytes are copied into the first argument. (An example of this is shown in Chapter 6, ➤ 268.)

In the customInsertSliceCopy(), we begin by creating a new slice (result) that is large enough to hold the items from the two slices passed in. Then we copy a subslice of the first slice (slice[:index]) into the result slice. We copy the insertion slice into result starting at the position in the result slice we have reached (at). Then we copy the rest of the first slice (slice[index:]) into the result slice at the next position we have reached (at). By last copy we ignore the copy() function's return value since we don't need it. And finally, we return the result slice.

If the index is 0, the slice[:index] in the first copy statement will be slice[:0] (an empty slice, so no copying is done. Similarly, if the index is greater than or equal to the length of the slice in the last copy statement will effectively be slice[len(slice):] (i.e., an empty slice), so again, no copying is done.

Here is a function that has almost the same behavior as the InsertStringSlice-Copy() function with much shorter and simpler code. The difference is that the InsertStringSlice() function changes the original slice (and possibly the inserted slice), whereas the InsertStringSliceCopy() function does not.

```
func InsertStringSlice(slice []string, insertion []string, index int) []string {
	return append(slice[:index], append(insertion, slice[index:]...)...)
}
```

InsertStringSlice() function appends the end of the original slice from the index position onto the end of the insertion slice, and then appends the resultant slice onto the end of the original slice at the index position. The returned slice is the original slice with the insertion applied. (Recall that append() takes a slice and one more slices, so we use the ellipsis syntax to transform a slice into its individual values—and in this example, we must do so.)

Items can be removed from the beginning and end of slices using Go's slice syntax, but removing from the middle can require a little care. We will start by seeing how to remove from the start, end, and middle of a slice, in-place. Then we will see how to take a copy of a slice with items that removed leaves the slice unchanged

```
s := []string{"A", "B", "C", "D", "E", "F", "G"}
s = s[2:] // Remove s[:2] from the front

## 4.2. Arrays and Slices

Removing items from the start of a slice is easily achieved by reslicing.

```
s := []string("A", "B", "C", "D", "E", "F", "G")
s := s[4:] // Remove s[4:] from the end
fmt.Println(s)
```

Removing items from the end of a slice is achieved by reslicing, just as the item at the start.

```
s := []string("A", "B", "C", "D", "E", "F", "G")
s := append(s[:1], s[5:]...) // Remove s[1:5] from the middle
fmt.Println(s)
```

Retrieving items from the middle of a slice is easy—for example, to get the three middle items of slice s, we would use the expression s[2:5]. But removing items from the middle of a slice is slightly tricky. Here we have done the removal using the append() function to add the sublice of s that follows what we want, to the sublice of s that precedes what we want, and assigning the result slice back to s. Clearly, using append() and assigning back to the original slice to remove items, changes. Here are some examples that a custom RemoveSliceCopy() function returns a copy of the slice it is given, and with the items at the end.

```
s := []string("A", "B", "C", "D", "E", "F", "G")
x := RemoveSliceCopy(s, 0, 2) // Remove s[:2] from the front
s := RemoveSliceCopy(s, 1, 5) // Remove s[1:5] from the middle
z := RemoveSliceCopy(s, 4, len(s)) // Remove s[4:] from the end
fmt.Printf("%v\n%v\n%v\n", s, x, z)
```

```
A B C D E F G
C E F
A D
```

In RemoveSliceCopy() function, we begin by creating a new slice (result) that is large enough to hold the items it will contain. Then we copy a sublice of the slice to the start position (slice[:start]) into the result slice. Next we copy the slice from the end position (slice[end:]) to the result slice at the position we have reached (at). And finally, we return the result.

It is also possible to create a simpler RemoveSlice() function that works on the slice it is given rather than making a copy.

```go
func RemoveSlice(slice []string, start, end int) []string {
	result := make([]string, len(slice)-(end-start))
	at := copy(result, slice[start:end])
	copy(result[at:], slice[end:])
	return result
}
```

This is a generalization of the remove from the middle used by the built-in append() function. The returned slice is the original slice with the items from the start position up to (but excluding) the end position removed.

### 4.2.4. Sorting and Searching Slices

The standard library's sort package provides functions for sorting slices of ints, float64s, and strings, for checking if a slice is sorted, and for searching for an item in a sorted slice using the binary search algorithm. There are also generic sort.Sort() and sort.Search() functions that can be easily used with custom data. These functions are listed in Table 4.2.

The way Go sorts numbers holds no surprises, as we saw in an earlier chapter (73 ◀). Strings are sorted purely in terms of the bytes that represent them, as we discussed in the previous chapter (§3.2, 86 ◀). This means, for example, that string sorting is case-sensitive. Here are a couple of string sorting examples and the results they produce.

```
files := []string{"Test.conf", "util.go", "Makefile", "misc.go", "main.go"}
fmt.Printf("Unsorted: %q\n", files)
sort.Strings(files) // Standard library sort function
fmt.Printf("Underlying bytes: %q\n", files)
SortFoldedStrings(files) // Custom sort function
fmt.Printf("Case insensitive: %q\n", files)
```
Unsorted: ["Test.conf", "util.go", "Makefile", "misc.go", "main.go"]
Underlying bytes: ["Test.conf", "util.go", "Makefile", "misc.go", "main.go"]
Case insensitive: ["main.go", "Makefile", "misc.go", "Test.conf", "util.go"]
```
