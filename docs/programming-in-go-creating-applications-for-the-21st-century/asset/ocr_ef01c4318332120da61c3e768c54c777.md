Next, the invoice's Items field is populated by iterating over the *XMLItems in the XMLInvoice's Item field and creating equivalent *Items. And at the end, the *Invoice is returned.

Just when writing XML, we don't have to concern ourselves with unescaping any XML we read—the XML.Decoder.Decode() function can take care of this-automatically.

The xml package supports more sophisticated tags than we have needed here, with nesting. For example, the tag name `xml:content="Books>Author"` would result in the XML `<Books><Author</Author></Books>`. Also, in addition to `xml:attr`, the package supports `xml:chardata` and `xml:` to write the field as character data, `xml:innerxml` to write the field verbatim, and `xml:comment` to write the field as an XML comment. By using tagged structures we are to take full advantage of the convenient encoding and decoding functions, and at the same time exercise considerable control over how the XML is written and read.
