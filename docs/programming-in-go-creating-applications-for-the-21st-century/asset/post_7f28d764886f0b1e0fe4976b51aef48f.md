A Go identifier is a nonempty sequence of letters and digits where the first character must be a letter, or which is not the name of a keyword. A letter is the underscore, _, or any character that is in the Unicode categories, "Lu" (letter, uppercase), "LL" (letter, lowercase), "Lt" (letter, titlecase), "Lm" (letter, modifier), or "Lo" (letter, other), this includes all English alphabetic characters (A-Z and a-z). A digit is any character in the Unicode category "Nd" (number, decimal digit); Arabic digits (0–9). The compiler will prevent the use of an identifier that has the same name as a keyword; see Table 2.1.

### Table 2.1 Go's Keywords

| break default func interface select |
| case defer map struct |
| chan else goto package switch |
| const fallthrough range type |
| continue import var |

Go has many predefined identifiers; it is possible—but rarely wise—to create an identifier with the same name as a predefined identifier; see Table 2.2.

Identifiers are case-sensitive, for example, LINECOUNT, Linecount, LineCount, lowercase and linecount are five different identifiers. Identifiers that begin with a capital letter, that is, with a character in Unicode category "Lu" (including A-Z), are considered to be public—exported in Go terminology—while others are considered to be private—unexported in Go terminology. (This rule does not apply to package names which are conventionally lowercase.) We will see this distinction in action when we discuss object-oriented programming in Chapter 6, and packages in Chapter 9.

The blank identifier, serves as a placeholder for where a variable is expected in an assignment, and discards any value it is given. The blank identifier is not considered to be a new variable, so if it is used with the := operator, at least one other (new) variable must be assigned to. It is legitimate to discard or all of a function's return values by assigning them to the blank identifier. However, if no return values are wanted it is more conventional to ignore them.

Here are some examples:

```go
count, err = fmt.Println(x) // get number of bytes printed and error
count, _ = fmt.Println(x) // get number of bytes printed; discard error
_, err = fmt.Println(x) // discard number of bytes printed; get error
fmt.Println(x) // ignore return values
```

It is not uncommon to return the values when printing to the console, but the error value should always be checked when printing to files, network connections, and so on—for example, using fmt.Fprint and similar functions. (Go functions are fully covered: $3.5, 93.)

### 2.1.1. Constants and Variables

Constants are declared using the const keyword; variables can be declared using the var keyword, or using the short variable declaration syntax. Go can infer the type of the declared type, although it is legal to specify it if we wish or need—for example, specify a type that is different from the type Go would normally infer. Here are some examples:

```go
const limit = 512 // constant; type-compatible with any number
const top uint16 = 1421 // constant; type: uint16
start := -19 // variable; inferred type: int
end := int64(9876543210) // variable; inferred type: int64
var i // variable; inferred type: int
var debug = 1.5 // variable; value 0; type: int
checkResults := true // variable; inferred type: bool
stepSize := 1.5 // variable; inferred type: float64
acronym := "FOSS" // variable; inferred type: string
```

Go infers type for int, for floating-point literals Go infers float64, and for complex literals Go infers complex128 (the numbers in their names refer to how many bits they occupy). The normal practice is to leave unspecified unless we want to use a specific type that Go won't; we will discuss this in $2.3, 57. Typed numeric constants (e.g., top) can be used in expressions with other numbers of the same type (unless converted). Untyped numeric constants can be used in expressions with numbers of any built-in type (e.g., limit can be used in an expression with integers or in one with floating-point numbers).

The variable was not given any explicit value. This is perfectly safe in Go since Go always assigns variables their type zero value if no other value is specified. This means that every numeric variable is guaranteed to be zero and every string to be empty—unless we specify otherwise. This ensures that Go programs don't suffer from the problems of uninitialized garbage values that affect some other languages.

### 2.1. Preliminaries

```go
type BitFlag int
const (
    Active BitFlag = 1 << iota // 1 << 0 == 1
    Send                   // 1 << 1 == 2
    Receive                // 1 << 2 == 4
)
var flag := Active | Send
```

In this snippet we have created three flags of type BitFlag and then set variable flag (of BitFlag) to the bitwise or of two of them (so flag has value 3; Go's bitwise flags are shown in Table 2.6). The BitFlag type is useful as it stands, but if we printed flag we would just get 3 with no indication of what that means. Go makes it really easy to control how values of custom types are printed, because the package functions will use a type String() method if it has one. To make our BitFlag type print in a more informative way, we can simply add a String() method to it. (Custom types and methods are covered fully in Chapter 6.)

```go
func (flag BitFlag) String() string {
    var flags []string
    if flag&Active == Active {
        flags = append(flags, "Active")
    }
    if flag&Send == Send {
        flags = append(flags, "Send")
    }
    if flag&Receive == Receive {
        flags = append(flags, "Receive")
    }
    if len(flags) > 0 { // int(flag) is vital to avoid infinite recursion!
        return fmt.Sprintf("%ds", int(flag), strings.Join(flags, " | "))
    }
    return "0"
}
```

This method builds up a (possibly empty) slice of strings for those bit fields that are set and prints the bit field's value as a decimal int and with the strings to indicate its.
