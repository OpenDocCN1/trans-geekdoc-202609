
# Chapter 8. File Handling

```go
func unpackTarFiles(reader *tar.Reader) error {
    for {
        header, err := reader.Next()
        if err != nil {
            if err == io.EOF {
                return nil // OK
            }
            return err
        }
        filename := sanitizedName(header.Name)
        switch header.Type {
        case tar.TypeDir:
            if err := os.MkdirAll(filename, 0755); err != nil {
                return err
            }
        case tar.TypeReg:
            if err := unpackTarFile(filename, header.Name, reader); err != nil {
                return err
            }
        }
        return nil
    }
}
```

The function has an infinite loop that iterates over each tarball until io.EOF is reached (or until an error occurs). The tar.Next() method returns the first—or next—tarball entry's *tar.Header, or reports an error. If the error is EOF it means that we have finished so we return a nil error value.

If a *tar.Header is successfully obtained we create a sanitized filename based on the header's Name field. Then we switch declining on the entry's type flag. For this simple example we only consider directories and regular files, but in fact, tarballs can contain other entries (e.g., symbolic links).

If the entry is for a directory we create the directory just the same as we did for directories in .zip files (◄). And if the entry is for a file we pass on to the work to a helper function.

```go
func unpackTarFile(filename, tarFilename string,
    reader *tar.Reader) error {
    writer, err := os.Create(filename)
    if err != nil {
        return nil
    }
    defer writer.Close()
}
```

## 8.2. Archive Files

This function creates a new file for the tarball's next entry, and defers closing. It copies the tarball's next entry's data to the file. And just like we did for the unpackZippedFile() function, we print name of the file that was created to the console, with the original filename in brackets if the sanitized filename is different.

This concludes our coverage of compressed and archive files, and of file handling in general. Go's approach to file handling using the io.Reader, io.ReadCloser, io.Writer, and io.WriteCloser interfaces makes it easy to read and write files or other streams (such as network connections or even strings) using the same consistent coding patterns.

## 8.3. Exercises

There are three exercises for this chapter. The first one involves a small but slightly subtle modification to one of the programs presented in this chapter. The second requires the writing of a short—but—new program from scratch. The third introduces substantial changes to another of this chapter's examples.

- 1. Copy the unpack directory to, say, my_unpack, and modify the unpack.go program so it can additionally unpack .tar.bz2 (compressed) files. This makes small changes to a couple of functions, and the addition of about ten lines to the unpackTar() function. The change is a bit tricky because the bzip2.NewReader() function doesn't return an io.ReadCloser. A solution is provided in the file unpack_unpack.go which is about ten lines longer than the original example.

- 2. Windows text files (.txt) often use the UTF-16-LE (UTF-16 little-endian) encoding. UTF-16-encoded files must always begin with a byte order mark, [0xFE, 0xFF] for little-endian or [0xFF, 0xFE] for big-endian. Write a program that reads a UTF-16-encoded file on the command line, and writes out the same using UTF-8 encoding either to os.stdout or to a file on the command line. Be sure to read both little-endian and big-endian UTF-16 encodings correctly. The book's examples with a couple of tiny files: utf16-to-utf8/utf16-to-utf8.txt and utf16-to-utf8/utf16-le.txt. The binary package's Read() function can read uint16 values (which is UTF-16 characters are) using a specified endianness. The unicode/utf16 package's Decode() function can convert a slice of uint16 values to a slice of code points (i.e., to []rune); so wrapping the result of utf16.Decode() call in string() is to produce a UTF-encoded string. A solution is the file utf16-to-utf8/utf16-to-utf8.go, and is around 50 lines excluding imports.

- 3. Copy the invoicedata directory to, say, my_icedata, and modify the invoicedata program in a few distinct ways. First, change the Invoice and Items to those shown below.

```go
type Invoice struct {
  CustomerID int
  DepartmentID string
  Raised time.Time
  Due time.Time
  Paid bool
  Note string
  Items []*Item

type Item struct {
  Price float64
  Quantity int
  TaxBand int

```

Now modify the program so it always writes invoices in the new format (i.e., one that handles the new structs), and can read in invoices in the original format or in the new format.

When the program reads data in the original format, the zero values for the extra fields are not acceptable, populate these fields with values according to these rules: Set an invoice's department ID to "GEN" if the invoice ID is less than 3000, to "MKT" if the ID is less than 4000, to "COM" if the ID is less than 5000, to "ERP" if the ID is less than 6000, to "INP" if the ID is less than 7000, to "TZ" if the ID is less than 8000, to "V20" if the ID is less than 9000, and to "X15" otherwise. Set each item's band to the integer value of the invoice's third character. For example, if the ID is "JU661", the tax band should be 4.

A solution is provided in the invoicedata directory. The solution adds three functions to invoicedata.go: one to update all the invoices (i.e., to provide acceptable values for the new fields), one to update an individual invoice, and one to update individual item. The solution needed changes to all the .go files, with the jsn.go, xml.go, and txt.go most affected. In all, the changes amount to around 150 lines of additional code.

The Go standard library has a large number of packages, which provide a wide range of functionality out of the box. In addition, third-party packages are available from the Go Dashboard at godashboard.app/project.

Go allows us to create our own custom packages. These packages can be installed in our copy of Go's standard library, or kept in our own Go tree (i.e., in the, or one of the, GOPATH paths).

In this chapter we will look at how to create and import packages, including our own custom packages and third-party packages. Then we will briefly review some of the commands supplied with Go reinventing the wheel.

It is best to create custom packages in the GOPATH src directory or one of the GOPATH src directories. Application-specific packages can be created within the application, but packages we want to share out to be created directly under a GOPATH src directory, ideally under a unique directory to avoid name conflicts. In this book we have adopted the convention of giving the .go file (or one of, if there is more than one) the same name as the package.
