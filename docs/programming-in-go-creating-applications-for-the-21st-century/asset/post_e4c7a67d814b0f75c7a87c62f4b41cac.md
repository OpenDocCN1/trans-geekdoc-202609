```go
type shape struct{ fill color.Color }
func newShape(fill color.Color) shape {
  if fill == nil // We Silently treat a nil color as black
    fill = color.Black
  }
  return shape{fill}
}
func (shape) Fill() color.Color { return shape.fill }
func (shape *shape) SetFill(fill color.Color) {
  if fill == nil // We Silently treat a nil color as black
    fill = color.Black
  }
  shape.fill = fill
}
```

This simple type is unexported so it is only accessible inside the shapes package. This means that no shape value can be created outside the package.

In the hierarchical shape1 shapes type does not fulfill any of the interfaces because it does not have a Draw() method. But in the compositional shape2 package it fulfills the Filler interface.
In the code as it stands, only the Circle type (which we will cover in a moment) directly embeds a shape. So, we could have incorporated the color.Color value into the Circle type and make the color getter and setter Circles instead of shapes, and eliminated the shape type altogether. However, we prefer to keep the shape type because it gives us the flexibility to add shape interfaces and types that might be based directly on the shape type (i.e., to have a color), rather than on the Circle type (e.g., they don't have a notion of radius). This flexibility will come in handy in one of the exercises.

This is the complete implementation of the Circle type. Although we create concrete *Circle values, we can pass them around as interfaces, which gives us a lot of flexibility. For example, the drawShapes() function (292 ◀) accepts Shapers (or Drawers), no matter what their underlying type is.

In the hierarchical shape1 package this type satisfies the CircularShaper and Shaper interfaces. In the compositional shape2 package it satisfies the Filler, Radiuser, Drawer and Drawer interfaces. And in both cases the type also satisfies the fmt.String interface.

Since Go doesn't have constructors and we have unexported fields, we provide construction functions which can be explicitly explained. The Circle's construction function is NewCircle(); later on we will see that the package also has a New() function that can create a value of any of the package's shapes. The saneRadius() helper function returns the given int if it is in a specified range or a sensible value otherwise; we saw it created earlier (290 ◀).

The code for the Draw() method has been elided (although it is in the book's source code), since our concern in this chapter is with creating custom interfaces and types rather than graphics.

The saneSides() helper function is just like the saneRadius() and saneLength() functions (240 ◄).

In the hierarchical shape1 package this type satisfies the RegularPolygon-Shaper, CircularShape, and fmt.String interfaces. In the compositional shape2 package it satisfies the Filler, Radiuser, Desirer, Shaper, and fmt.String interfaces.

The NewCircle() and NewPolygon() functions allow us to create *Circle and *Polygon values, and since their types fill the Shape and other interfaces, we can pass them as Shapers or values of any of the other interfaces they fulfill. We can call any Shaper method on such values (i.e., Fill(), SetFill(), and Draw()). If we want to call a non-Shaper method on a Shaper value, we can do so using a type assertion or type switch to access the value as a value of the interface we want to call. We will see an example when we look at the showShapeDetails() functions (► 300).
