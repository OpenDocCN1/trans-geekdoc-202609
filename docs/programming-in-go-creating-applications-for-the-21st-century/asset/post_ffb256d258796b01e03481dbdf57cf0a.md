### 9.1.1.3. Unit Testing and Benchmarking Packages

The Go standard library includes good support for unit testing the packages. Setting up unit testing for a package is a simple matter of creating a test file in the same directory as the package we want to test. This file should begin with the package name and end with _test.go. For example, the omap package's test file is called omap_test.go.

In the book's examples, test files are put in their own unique package (e.g., omap_test), and they import the package they are testing and the testing package, plus any other packages that are needed. This constrains us to use black testing. However, some Go programmers prefer white box testing. This can be easily done by putting test files in the same package as they are testing (e.g., omap), in which case there is no need to import the package being tested. This approach means that nonexported types can be tested, and methods can be added to support testing.

The test file is unusual in that it has no main() function. Instead, it has one or more exported functions whose names contain Test and take a single argument of type *testing.T and return nothing. We can add any supporting functions we need, of course, providing their names start with Test.

```go
func TestStringKeyOmapInsertion(t *testing.T) {
	word := omap.NewCaseFoldedKey()
	for _, word := range []string{"one", "Two", "THREE", "four", "Five"}{
		word.Insert(word, word)
	}
	var words []string
	word.Do(func(_, value interface{}) {
		words = append(words, value.(string))
	})
	actual, expected := strings.Join(words, ""), "FivefourTHREE"
	if actual != expected {
		t.Error("%q != %q", actual, expected)
	}
}
```

Here is one of the tests in the omap_test.go file. It begins by creating an empty omap.Map, then it inserts some string keys (which are treated case-insensitively), and string values. We then iterate over all the key-value pairs in the map using the Map.Do method, and append each value to a slice of strings. We join the strings into a single string and see if this matches what we expect. If the match fails we call the testing.T.Error method to report the failure and provide some explanation. If no error or function is called then the test is assumed to have passed.

In addition, the testing package has support for benchmarking. Benchmark functions can be added to package_test.go in the same way as test functions, only in this case the functions names must begin with Benchmark and receive a single testing.B argument and return nothing.

```go
func BenchmarkOapFind(b *testing.B) {
	b.StopTimer() // Don't time creation and population
	intMap := omap.New()
	for i := 0; i < 1e6; i++ {
		intMap.Insert(i, i)
	}
	b.StartTimer() // Time the Find() method
	for i := 0; i < b.N; i++ {
		intMap.Find(i)
	}
}
```

This function begins by stopping the timer since we don't want to time the creation and population of omap.Map. We then create an empty omap.Map and populate it with a million key–value pairs. By default test does not run any benchmarks, if we want them to run we must explicitly say so using the -bench option and providing it with a regular expression that matches the benchmarks we want to run. A regex of .* matches anything, that is, all the benchmarks in the test file also works.

```bash
$ go test -bench=.*
ok    qtrac.eu/omap
PASS
BenchmarkOmapFind-Success    1000000    1380 ns/op
BenchmarkOmapFind-Failure  1000000    1350 ns/op
```

This output shows two benchmarks were run with 1,000,000 iterations, and with the number of nanoseconds per operation. The number of iterations (i.e., the value of b.N) is chosen by go test, but we can use the -bench option to see the approximate number of seconds we want each benchmark to run.

### 9.1.2. Importing Packages

Go allows us to alias packages. This feature can be convenient and useful—making it easy to switch between two implementations of a package. For instance, we could import a package like this: import v1 "v1", so that in code the v1 package is accessed instead. Later, when a more mature implementation is available, we could switch to it by changing the import to v2. This will work if both v1 and v2 provide the same APIs (or if v2’s API is a superset of v1), and means that the rest of the code can be left unchanged. On the other hand, aliasing standard library package names is probably best, since it could cause confusion or irritation to maintainers later on.

As we mentioned in Chapter 5 (5.6.2), when a package is imported its init() functions are executed (if it has any). In some situations we don't want to make explicit use of a package, but do want its init() to be executed.

For example, if we are processing images we might want to register all the image formats that Go supports, but not actually use any functions from the packages that provide the formats. Here is the import statement for the imag1.go file (from Chapter 7's exercises).

```go
import (
    "fmt"
    "image"
    "os"
    "path/filepath"
    "runtime"
    "image/gif"
    "image/jpeg"
    "image/png"
)
```

We import the image/gif, image/jpeg, and image/png packages purely to execute their init() functions (which registers their image format with the image package). Each of these packages is aliased to the blank identifier _, Go will not complain about not making explicit use of any of them in code.

## 9.2. Third-Party Packages

The tool that we have used throughout the book to build programs and packages (e.g., the omap package) can also be used to download, build, and install third-party packages. (Of, this assumes that our computer is connected to the Internet.) A list of third-party packages is maintained at github.appspot.com/project. (An alternative approach is to download the source code—often obtained as a copy from a distributed version control system—and build the package ourselves locally).

To install one of the Go Dashboard's packages, first click its link to go to the package's home page. Wherever there be a command that shows how to download and install the package.

For example, if we were to click the Go Dashboard freetype-go.google.com/hg/freetype link, it would take you to code.google.com/p/freetype-go/ page which shows the installation command up front (at the time of this writing): get freetype-go.google.com/hg/freetype.
