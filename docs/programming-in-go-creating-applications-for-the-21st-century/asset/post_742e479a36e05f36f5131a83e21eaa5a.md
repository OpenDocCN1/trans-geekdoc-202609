
# Chapter 6. Object-Oriented Programming

```go
type Exchanger interface {
    Exchange()
}
```

The Exchanger interface specifies a single method, Exchange(), which takes no arguments and returns nothing. We have followed the Go convention for interface names, which is that they should end with er. It is common to have interfaces with only one method—for example, the standard library's io.Reader and io.Writer each specify a single method. Notice that an interface is really specifying an API (Application Programming Interface), that is, zero or more methods—although it says nothing about what those methods actually do.

A nonempty interface on its own is not usually of any use; to make it useful we create some custom types that have the methods interface requires.* Here are two such types.

```go
type StringPair struct{first, second string}
func (pair *StringPair) Exchange() {
    pair.first, pair.second = pair.second, pair.first
}
type Point [2]int
func (point *Point) Exchange() { point[0], point[1] = point[1], point[0] }
```

The custom StringPair and Point types are completely different, since both provide an Exchange() method, both satisfy the Exchanger interface. This means that we can create StringPair and Point values and pass them to functions that accept Exchangers.

Notice that although both the StringPair and Point types fulfill the Exchanger interface, nowadays we have not said this explicitly—there are no “implements” or “inherits” statements. The fact that the StringPair and Point types provide the methods (in this case just one method) that the interface specifies, is sufficient for Go to know that they satisfy the interface.

The methods' receivers are specified as pointers to their types so that we can change the (pointed) values the methods are called on. Although Go is smart enough to create custom types in a sensible way, we usually prefer to take control over their representation. This can be easily done by adding a method that fulfills the Stringer interface, that is, a method with signature String() string. If we were creating a framework we might create interfaces but no types that implement them, and require users of the framework to create such types for use with.

## 6.3. Interfaces

```go
func (pair StringPair) String() string {
    return fmt.Sprintf("%q+%q", pair.first, pair.second)
}
```

This method returns a string that consists of the strings in double quotes with a "+" sign between them. With this method defined, Go’s fmt package’s print methods will use it to print StringPair values—and also *StringPairs, since the variables are created as values, yet Exchange() methods require pointer. This isn’t a problem, since we noted earlier, Go is smart enough to pass a value’s address when we call a method on it that requires pointer—providing the value is addressable. So, in the snippet, pair.Exchange() is automatically treated as if it were (&pair).Exchange(), and the same for the others.

In the call to exchangeThese() function we must pass the addresses explicitly. If, for instance we passed the value of type StringPair, the Go compiler would notice that StringPairs do not fulfill the Exchanger interface—there is no Exchange() method with a StringPair receiver—and would stop compiling and report the error. However, if we pass a *StringPair (e.g., &hyde), the compilation will complete successfully. This works because there is an Exchange() method which takes a *StringPair receiver which means *StringPairs fulfill the Exchanger interface.

Here is the exchangeThese function:

```go
func exchangeThese(exchangers ...Exchanger) {
	for _, exchanger := range exchangers {
		exchanger.Exchange()
	}
}
```

This function doesn't know or care that passed it two *StringPairs and one *Point; all that it requires is that the parameters are Exchangers—and this requirement is enforced by the compiler, the duck typing used here is type-safe.

In addition to satisfying our own custom interfaces, we can satisfy those in the standard library or others we want, as we saw when we defined the StringPair.String() method to fulfill the String interface. Another example is the io.Reader interface which specifies a single method with the signature Read([]byte) (int, error) that writes the data of the value it is called on to the given []byte. The writing is destructive, that is, each byte written is removed from the called-on value.

```go
func (pair *StringPair) Read(data []byte) (int, error) {
	if pair.first == "" && pair.second != "" {
		return 0, io.EOF
	}
	if pair.first != "" {
		n = copy(data, pair.first)
		pair.first = pair.first[:n]
	}
	if n < len(data) && pair.second != "" {
		m = copy(data[n:], pair.second)
		pair.second = pair.second[m:]
		n += m
	}
	return n, nil
}
```

By implementing this method we have made the String type fulfill the io.Reader interface. So now StringPairs (or, strictly speaking, *StringPairs since some of the methods require pointer receivers) are Exchangers and fmt.Stringers and io.Readers—with no need to say that *String "implements" Exchanger or any of the other interfaces. And we could add further methods and fulfill additional interfaces if we wished.

The method uses the built-in copy() function (§4.2.3). This function can be used to copy into a slice from another slice of the same type—but here we have used it in its other form to copy into a []byte from a string. The copy() function never copies more bytes than the destination []byte has room for, and returns the number of bytes copied. The custom StringPair.Read() method writes bytes from its first string (removes any that are written), and does the same for its second string. If both strings are empty the method returns a count of zero and EOF. Incidentally, the method would work perfectly well if the second statement were deleted—but at some (perhaps insignificant) cost in efficiency. Here is a code snippet:

```go
const size = 16
robert := &StringPair("Robert L.", "Stevenson")
david := StringPair("David", "Balfour")
for _, reader := range io.Readers{robert, &david} {
	raw, err := ToBytes(reader, size)
	if err != nil {
		fmt.Println(err)
	}
	fmt.Printf("%q\n", raw)
}
```
