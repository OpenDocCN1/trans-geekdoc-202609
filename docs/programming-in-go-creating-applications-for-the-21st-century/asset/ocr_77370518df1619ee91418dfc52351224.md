# 6.5. Examples

```
type Shaper interface {
    Drawer // Draw()
    Filler // Fill(); SetFill()
}
type Drawer interface {
    Draw(img draw.Image, x, y int) error
}
type Filler interface {
    Fill() color.Color
    SetFill(fill color.Color)
}
type Radiuser interface {
    Radius() int
    SetRadius(radius int)
}
type Sideres interface {
    Sides() int
    SetSides(sides int)
}
```

This package's Shaper interface is a convenient way of specifying shapes generally, that is, shapes which can be drawn and which can get/set a fill color. Each of the other interfaces specifies one very specific behavior (counting and setting as one).

Having many independent interfaces is the shapes package much more flexible than using a hierarchy. For example, we were able to be much more specific about the shapes passed to the DrawShapes() function than was possible using a hierarchy (292). Also, with no hierarchy to preserve we can add other interfaces much more freely, and of course, with these more fine-grained interfaces we can compose with them more readily—as we did to the Shaper interface.

The different versions of the shapes package have completely different interfaces (although both have a Shaper interface, its body differs between them). Nonetheless, since interfaces and concrete types are completely separate and independent, these differences have no effect whatsoever on the concrete implementations that fulfill them.
