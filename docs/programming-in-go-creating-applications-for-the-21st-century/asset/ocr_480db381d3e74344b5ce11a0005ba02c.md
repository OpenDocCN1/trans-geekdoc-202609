If we fail to open the file we call log.Fatal() with the error. As we noted in a previous section, this function logs the date, time, and err to os.Stderr—another log destination is specified, and calls os.Exit(1) to terminate the program. When os.Exit() is called (directly, or by log.Fatal()), the program is terminated immediately—and any deferred statements are lost. This is not a problem, though, since Go's runtime system will close any open files, the garbage collector will release the program's memory, and any other database or network that the application has been talking to will detect the application's demise and respond gracefully. In Go a panic is a runtime error (rather like an exception in other languages). We can panic ourselves using the built-in panic() function and can stop a panic in its tracks using the recover() function ($5.5, 212). In theory, Go's panic/recover functionality can be used to provide a general-purpose exception handling mechanism—but doing so is considered to poor practice. The Go way to handle errors is for methods to return an error value as their sole or nil if no error occurred—and for callers to always check the error they receive. The purpose of panic/recover is to deal with genuinely erroneous (i.e., unexpected) problems and not with normal errors.

With both files successfully opened (the os.Stdin, os.Stdout, and os.Stderr are automatically opened by the Go runtime system), we can call the anonymous() function to do the processing, passing the files on which it works. If anonymous() returns nil the main() function terminates and any deferred statements—in one that closes the inputFile and outputFile if they are not os.Stdin and os.Stdout—executed. And if any err is not returned, the program is exited, and Go's runtime system closes any open files.

The anonymous function accepts an io.Reader and an io.Writer, not *os.Files, but this doesn't matter since the os.File type supports the io.Reader interface (which aggregates the io.Reader and io.Writer interfaces) and can be used wherever an io.Reader or an io.Writer is required.
