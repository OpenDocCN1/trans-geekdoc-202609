# 6.2. Custom Types

None of these custom types look particularly useful on their own, although using types like this can improve a program's readability and can also make possible to change the underlying type later on, so they serve as a basic abstraction mechanism.

```
var i Count = 7
i++
fmt.Println(i)
sm := make(StringMap)
s["key1"] = "value1"
sm["key2"] = "value2"
fmt.Println(sm)
fc := make(FloatChan, 1)
fc <- -2.2955814939
fmt.Println(-fc)
```

| map[key2:value2 key1:value1] |
| 2.2955814939 |

Types like Count, StringMap, and FloatChan that are based directly on a built-in type can be used in the same way as the built-in type—for example, we can use the built-in append() function on a custom type []string—but we must convert them (at no cost because it is done at compile time) to the underlying type if we need to pass them to a function that expects their underlying type. And sometimes we need to do the reverse and promote the value of a built-in type to a custom type to benefit from the custom type's methods. We saw an example of this when converted a []string to a FoldedStrings value in the SortFoldedStrings() function (16) ◀

```
type RuneForRuneFunc func(rune) rune
```

When working with higher order functions ($5.6, 238 ◀ it is often convenient to define custom types that specify the signatures of the functions we want to pass. Here we have specified the signature of a function that takes and returns a single rune.

```
var removePunctuation RuneForRuneFunc
```

The removePunctuation variable is created to refer to a function of type RuneForRuneFunc (i.e., with the signature func(rune) rune). All variables are automatically initialized to its zero value, so in this case to nil.
