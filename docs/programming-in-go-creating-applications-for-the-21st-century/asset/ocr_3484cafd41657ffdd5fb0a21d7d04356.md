The filenamesFromCommandLine() function returns two strings and an error
-value—and unlike the functions we have seen so far, the return values are given variable names, not just types. Return variables are set to their zero values (empty strings and nil for error in this case) when the function is entered, and keep their zero values explicitly assigned to the body of the function.
(We will say a bit more on this topic when we discuss the americanise() function, next.)

The function begins by seeing if the user has asked for usage.* If they have, we create a new error value using the fmt.Errorf() with a suitable usage string, and return immediately. As with Go, the caller is expected to check the return error and behave accordingly (and this is exactly how main() does). The fmt.Errorf() function is like the fmt.Printf() function we saw earlier, except that it returns an error containing a string using the given format string and arguments rather than writing a string to os.Stdout.(The errors.New() function is used to create an error literal.)

If the user did not request usage information we check if they entered any command-line arguments, and if they did set the infilename return variable to their first command-line argument and the outfilename return variable
