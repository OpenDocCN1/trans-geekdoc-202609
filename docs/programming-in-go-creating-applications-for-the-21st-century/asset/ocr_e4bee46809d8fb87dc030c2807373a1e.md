# 7.2. Examples

This struct type is used to store the details of each duplicate file, that is, its size, and all the file's paths and filenames. It is merged by the merge() and outputResults() functions.

```
func mergeResults(infoChan <-chan fileInfo) map[string]*pathsInfo {
	pathData := make(map[string]*pathsInfo)
	format := fmt.Sprintf("%06X:%dX", sha.Size*2) // = "%06X:%40X"
	for info := range infoChan {
		key := fmt.Sprintf(format, info.size, info.sha)
		value, found := pathData[key]
		if found {
			value = &pathsInfo{size: info.size}
			pathData[key] = value
	}
		value.paths = append(value.paths, info.path)
	}
	return pathData
}
```

This function begins creating a map to store duplicate files. The keys are strings composed of the file's size, a colon, and the file's SHA-1, and the values are *pathsInfos.

To produce the keys we have created a format string which has 16 zero-padded hexadecimal digits to represent the file's size and enough hexadecimal digits to represent the file's SHA-1. We use leading zeros for the file size part of the key so that we can sort the keys by size later on. The shaSize constant holds the number of bytes occupied (i.e., 20). Since one byte is represented in hexadecimal with two digits, we must use twice as many characters as there are bytes for the SHA-1 in the format string. (Incidentally, we could have created the format string with format = "%06X:%" + fmt.Sprintf("%X", sha.Size*2)).

Although multiple goroutines send to the infoChan, this function (in the main goroutine) is the only one that receives from the channel. For the loop receives fileInfo values—or blocks waits. The loop ends when all the values have been received and the infoChan is closed. For each fileInfo received, a map key is constructed. If the map doesn't have an item with the key, we create a suitable value with the file size, and an empty slice of paths, and add it to the map under the new key. With the new or existing item in the map, append to the item's paths of the file in the fileInfo value.

And at the end, this will result in duplicate files having path slices with more than one path, and nonduplicates path slices with exactly one path. Once all the fileInfo values have been processed and the map populated, the function returns the map ready for further processing.
