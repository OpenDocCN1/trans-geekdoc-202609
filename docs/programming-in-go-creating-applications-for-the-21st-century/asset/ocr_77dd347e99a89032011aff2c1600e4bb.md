# 4.1. Values, Pointers, and Reference Types

| Statement | Variable | Value | Type | Memory Address |
| --- | --- | --- | --- | --- |
| y := 1.5 | y | 1.5 | float64 | 0xf840000f8 |
| y++ | y | 2.5 | float64 | 0xf840000f8 |
| z := math.Ceil(y) | x | 2.5 | float64 | Modifiable copy of y in Ceil(y) |
| z | z | 3.0 | float64 | 0xf840000c0 |

Figure 4.1 Simple values in memory

Go will set aside memory to store a float64 (ie., 8 bytes) and will put the 1.5 value into this memory. From this point onward—while y remains in scope—Go will treat the variable y as synonymous with the memory that stores the float64 y is associated with. If we follow the declaration variable y++, Go will increment the y that is associated with. However, if we pass y to a function or method, Go will pass a copy of y; in other words Go will create a new variable that is associated with the called function or method's corresponding parameter name and will copy y's value into the memory set aside for the new variable.

Sometimes we want to modify a variable that we pass. This can be done without formality for reference types as we see all, but values are copied, so any modifications are applied to the copy and the original value is left unchanged. Also, it can be expensive to pass some values, because they are large (e.g., an array, or a struct with fields). Furthermore, local variables are garbage-collected if they are no longer being used (e.g., when they are not referred to and go out of scope), in many situations we will need to create variables whose lifetime is determined by us rather than by their enclosing scope.

Parameters that are cheap to pass, parameters that are modifiable, and variables whose lifetimes are independent of scope, can all be achieved by using pointers. A pointer is a variable that holds another variable's memory address. This ensures that Go knows how large (ie., how many bytes) the pointed-to value occupies. A variable pointed to by a pointer can be modified through the pointer, as we will see shortly. Pointers are cheap to pass (8 bytes on 64-bit machines, 4 bytes on 32-bit machines), regardless of the size of the value they point to. And pointed-to variables persist in memory as long as there is at least one pointer pointing to them, so their lifetime is independent of the scope in which they were created.

> * C and C++ programmers should be aware that although a particular Go compiler may make internal distinctions between stack and heap memory, Go programmers never have to worry about this since Go handles all the memory management internally.
