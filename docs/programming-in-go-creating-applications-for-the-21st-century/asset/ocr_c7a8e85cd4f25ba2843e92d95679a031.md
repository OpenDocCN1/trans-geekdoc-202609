# 7.2. Examples

```
type Job struct {
	filename string
	results chan<- Result
}
```

This struct is used to specify each job: the name of the file to be processed and the channel where any result is sent. We could have defined the results field as chan Result, but since we only want Job values to send results into the channel and never receive from it, we have specified that the channel is a unidirectional send-only channel.

```
type Result struct {
	filename string
	lino int
	line string
}
```

Each result is encapsulated by a value of this struct's type, and contains the filename, the line number (lino), and the matching line.

```
func main() {
	runtime.GOMPROCS(runtime.NumCPU()) // Use all the machine's cores
	if len(os.Args) < 3 || os.Args[1] == "-h" || os.Args[1] == "-help" {
		fmt.Printf("usage: %s <regexp> <files>\n",
			filepath.Base(os.Args[0]))
		os.Exit(1)
	}
	if lineX, err := regexp.Compile(os.Args[1]); err != nil {
		log.Fatalf("invalid regexp: %s\n", err)
	} else {
		grep(lineX, commandLineFiles(os.Args[2:]))
	}
}
```

The program's main() function's first statement tells the Go runtime system to use as many processors (cores) as the system has available. Calling runtime.GOMAXPROCS(0) returns the number of processors and changes nothing; calling it with a positive number sets the number of processors the Go runtime should use. The runtime.NumCPU() returns how many logical processors/cores the machine has.* We put this at the start of many concurrent programs, but eventually it will be redundant because Go’s runtime will become smart enough to automatically adapt to the program it is running.

> * Some processors claim to have more cores than they really have; see en.wikipedia.org/wiki/Hyper-threading.
