
The reflect.Value.Int() method returns an int64; we have converted this to a plain int to match the generic Len() function's return value's type.

## 9.4. A Brief Survey of the Go Standard Library

If a value is passed in that doesn't support the len() function and doesn't have a Len() method, the generic Len function panics. We could have handled this error in other ways—for example, by returning -1 to signify “no length available”, or by returning an index and an error.

Go's reflect package is incredibly flexible and allows us to do things at runtime that depend on the program's dynamic state. However, to quote Rob Pike, reflection is “a powerful tool that should be used with care and avoided unless strictly necessary”.

## Epilogue

The Go developers took hard look at some of the most widely used programming languages and tried to discern which features were really useful and productive to have, and which were redundant or even counterproductive. They also drew on the many decades of programming experience that they collectively had. As result they produced the Go programming language.

In the tradition of Objective-C and C++, Go is an object-oriented "better C". Like Java, Go has its own syntax, so to maintain C compatibility in the way that Objective-C and C++ do. But unlike Java, Go compiles to native code and is not limited to the speed of a virtual machine.

In addition to Go's novel approach to object orientation with its emphasis on abstract interfaces and concrete types with smart embedding and aggregation, Go also supports advanced features such as function literals and closures. And Go's built-in map and slice types between them serve almost every structure need. Go's Unicode-based string type uses the world's facto encoding (UTF-8), and the standard library provides excellent support at both the type and character level.

Go's support for concurrency is outstanding. Its lightweight goroutines and its type-safe and high-level channels make it much easier to create concurrent programs compared with many other languages (e.g., C, C++, or Java). And Go's lightning-fast compilation times are a breath of fresh air, especially to anyone used to building large C++ programs and libraries.

Go is already being used by a variety of commercial and noncommercial organizations. Go is used internally by Google, as well as being available alongside Java and Python, as a language for developing web applications with the Google App Engine (google.com/appengine/docs/go/overview.html).

The language is still evolving quite quickly, thanks to the go tool, it is easy to update code with the latest release. Furthermore, the Go developers intend to keep all Go 1.x versions backward compatible with Go 1 to ensure that Go users have a language that is both stable and being improved at the same time.

Go's standard library is very wide ranging, but even in cases where we doesn't have the functionality we need, we can always see if what we want available from the Go Dashboard (godash.appspot.com/project), or in some

Most people learning Go will have knowledge of other programming language (e.g., C++, Java, Python), and will come to Go with experience of inheritance-based object orientation. Go deliberately doesn’t support inheritance, while it is relatively easy to convert code between, say, C++ and Java, when it comes to Go it is best to go back to the fundamentals of what the code is designed to do—rather than how it does it—and rewrite from scratch in Go. Perhaps the most important distinction is that inheritance-based languages allow code and data to be merged, whereas Go forces them to keep separate. This separation gives great flexibility, and also makes it easier to create concurrent programs, but it can take time and practice for programmers to use inheritance-based languages to adapt to the Go approach. Russ Cox, one of the Go developers, says:

> “It’s unfortunate that every time someone asks for inheritance the answer is ‘well, there’s embedding’. Embedding is useful and a kind of inheritance. The answer is: you’re thinking in C++, or in Python or Java or Eiffel or whatever. Don’t do that. Think in Go.”

Go is a fascinating language to learn and use, as well as being a pleasure to program with Go. Go programmers may well find it worth while to join the Go mailing list—this has many excellent posters and is an ideal place for discussion and for questions (groups.google.com/group/golang-nuts). And since Go is developed in the open, it is possible to become a Go developer to help maintain, improve, and extend the language itself (golang.org/doc/contribute.html).
