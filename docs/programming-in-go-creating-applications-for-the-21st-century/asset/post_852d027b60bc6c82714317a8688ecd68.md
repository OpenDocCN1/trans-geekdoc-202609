### Unicode

Prior to Unicode it was not really possible to have plain text in different languages—for example, English with some Japanese and Russian—since separate encodings were used for separate languages.

Unicode is designed to be able to represent the characters from all of the world’s writing systems, so a single text file using a Unicode encoding can contain

Every Unicode character has a unique identifying number called a code point. There are more than 100000 Unicode characters defined, with code points ranging from 0x0 to 0xFFFFthe latter defined in Go as the constant unicode.MaxRun, with large gaps). In Unicode documentation, code points are written using four hexadecimal digits in the form U+hhhh.

Unicode text—whether in file or memory—must be represented using an encoding. The Unicode standard defines various Unicode Transformation Formats (encodings), as UTF-8, UTF-16, and UTF-32. Go uses the UTF-8 encoding for strings.

UTF-8 encodes between one and four bytes to represent each code point. For strings that contain only 7-bit ASCII (US-ASCII) characters, there is a one-to-one relationship between bytes and characters because each 7-bit ASCII character is represented by a single byte (of the same value) in UTF-8. One consequence of this is that UTF-8 stores English text very compactly (one byte per character); another consequence is that a text file encoded using 7-bit ASCII is indistinguishable from a UTF-8 encoded text file.

A string is an immutable sequence of arbitrary bytes. In most cases a string’s bytes represent Unicode using the UTF-8 encoding (see the “Unicode” sidebar above). The use of Unicode means that Go strings can contain text in any mixture of any of the world’s languages, without any of the confusions and limitations of code pages.
