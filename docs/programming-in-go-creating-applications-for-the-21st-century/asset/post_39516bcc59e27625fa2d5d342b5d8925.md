## Chapter 3. Strings

An example that typically involves the use of replacements is where we have a list of names of the form forename1...forenameN surname and want to change the list to have the form surname,forename1...forenameN. Here is how we can achieve this using the regex package, with correct handling of accented and other non-English characters.

```go
nameRx := regexp.Compile(`(\pL\.)?(?:\s|\pL\.)*)\s+(\pL*)`)
for i := 0; i < len(names); i++ {
    names[i] = nameRx.ReplaceAllString(names[i], "${2}, ${1}")
}
```

The names variable is of type [] and initially holds the original names. Once the loop completes the names variable holds the modified names.

The regexp matches one or more whitespace-separated names(\pL) optionally followed by a period, followed by whitespace and a surname of one or more Unicode letters.

Using named replacements can lead to maintenance problems—for example, if we inserted a capture group in the middle, at least one of the numbers would be wrong. The solution is to use named replacements since these're order-dependent.

```go
nameRx := regexp.Compile(`(\p<forenames>\pL\.)?(?:\s|\pL\.)*)\s+(\p<surname>\pL*)`)
for i := 0; i < len(names); i++ {
    names[i] = nameRx.ReplaceAllString(names[i], "${surname}, ${forenames}")
}
```

Here we have given two capture groups meaningful names. This helps make both the regular expression and the replacement string more understandable.

A simple regex for matching duplicate "words" that relies on backreferences would be written in, say, Python or Perl, as \b(\w+)\s+\1\b. Since the regex package doesn't support backreferences, to achieve the same effect we must combine a regex with a few lines of code.

```go
wordRx := regexp.Compile(`\b(\w+)`)
if matches := wordRx.FindAllString(text, -1); matches != nil {
	previous := ""
	for _, match := range matches {
		if match == previous {
			fmt.Println("Duplicate word: %s", match)
		}
		previous = match
	}
}
```

The regexp greedily matches one or more "word" characters. The regexp.FindAllString() returns a []string of all nonoverlapping matches. If there was at least one match (i.e., matches is not nil), we iterate the string slice and print any duplicates by comparing the current matched word with the previous word.

Another common regexp use is to match key: value lines in configuration files. Here is an example that populates a map based on lines.

```go
keyValueKey := make(map[string]string)
keyValueRx := regexp.Compile(`\s*([[:alpha:]]\w*):\s*(.+)`)
if matches := keyValueRx.FindAllStringSubmatch(lines, -1); matches != nil {
	for _, match := range matches {
		keyValueKey[match[1]] = strings.TrimRight(match[2], "\t ")
	}
}
```

The regexp says to skip any leading whitespace and match a key which must begin with an English letter followed by zero or more letters, digits, or underscores, followed by optional whitespace, a colon, and then the value. Incidentally, we used the slightly different [A-Za-z] instead of [[:alpha:]], or if we wanted to support Unicode keys, [\p{L}\p{N}_*], Unicode letter followed by zero or more Unicode characters, decimal digits, or underscores. Since the .+ expression matches this, the regexp will work on a string that contains multiple key: value lines.

Thanks to the use of greedy matching (which is the default), the regexp will consume any whitespace that precedes the value. To get rid of whitespace at the end of a value we must use a trim function since the .+ expression's greediness means that following it with .* would have no effect. Could not have used nongreedy matching (e.g., .+*), since that would only match the first word of values that contain two or more space-separated words.

By using the regexp.FindAllStringSubmatch() function we get a slice of slices (or nil); the -1 says to match as many times as possible (without overlaps). In this example, each match will produce a slice of exactly three strings, the first containing the whole match, the second containing the key, and the third containing the value. Both the key and the value will have at least one character because their quantification is one.
