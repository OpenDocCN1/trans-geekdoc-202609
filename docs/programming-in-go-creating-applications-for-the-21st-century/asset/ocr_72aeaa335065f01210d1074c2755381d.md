# Chapter 4. Collection Types

We have created three variables of type int and given them initial values. Then we have called a custom swapAndProduct1() function that takes three pointers and makes sure that the first two (pointed to) integers are in ascending order and set the third one's (pointed to) value to the product of the first two. Since the function pointers rather than value, we must pass the addresses of the ints, not the ints themselves. Whenever we see the & of operator being used in a function call, we should assume that the corresponding variable's value might be modified inside the function. Here is the swapAndProduct1() function.

```
func swapAndProduct1(x, y, product *int) {
    if *x > *y {
        *x, *y = *y, *x
    }
    *product = *x *y // The compiler would be happy: *product=x**y
}
```

The function's parameter declaration's *int uses the * modifier to specify that the parameters are all pointers to integers. This means, of that we can only pass the addresses of integer variables (using the & address of operator), not integer variables themselves or literal integer values.

Within the function we are concerned with the values that the pointers point to, so we use the * dereference operator throughout. In the last executable we multiply two pointed-to values together and assign the result to another pointer's pointed-to value. Go can distinguish between two consecutive *s mean Inside the function the pointers are called x, y, and product, but the values they point to are the ints i, j, and, at the function's call.

Writing functions in this way is common in C and older C++ but is less necessary in Go. If we have just one or a few values it is more idiomatic in Go to return them, and if we have lots of values it is common to pass them as a slice or map (which can be easily passed without using pointers, as we will see shortly), or in a struct passed by pointer if they are all of different types.
