Again, we can do the same on Windows:

```
C:\set GOPATH=C:\goeg
C:\cd %GOPATH%\src\hello
C:\goeg\hello-go install
```

The go install command does the same as build but puts the executable in a standard location (%GOPATH%/bin or %GOPATH%in). This means that by adding a single path (%GOPATH/bin or %GOPATH%in) to our PATH, *all* the Go programs that we install will conveniently be in the PATH.

In addition to the book's examples, we are likely to want to develop our own Go programs and packages in our own directory. This can easily be modified by setting the GOPATH environment variable to two (or more) separated paths (semicolon-separated on Windows); for example, export GOPATH=$HOME/app/go:$HOME/goeg or SET GOPATH=C:\goeg. In this case we must put all our program and package's source code in $HOME/app/go/src or C:\goeg\src. So, if we develop a program called myapp, .go source files go in $HOME/app/go/src/myapp or C:\goeg\src\myapp. And if we go install to build a program in a GOPATH directory where the GOPATH has two or more directories, the executable will be in the corresponding directory's bin directory.

Naturally, it would be tedious to export or set the GOPATH every time we want to build a Go program, so it is best to set this environment variable permanently. This can be done by setting GOPATH in the .bashrc file (or similar) on Unix-like systems (see the book's example of go.sh). On Windows it can be done by editing a path to the system's environment variables: Click Start (the Windows logo), Control Panel, then System and Security, then System, then Advanced system settings, and in the Properties dialog click Environment variables, then the New... button, and add a variable with the name GOPATH and a suitable value, such as C:\goeg or C:\app\go;C:\goeg.
