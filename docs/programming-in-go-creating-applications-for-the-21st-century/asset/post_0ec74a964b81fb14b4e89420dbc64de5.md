### 4.3.1. Creating and Populating Maps

Here is an example that shows the creation and population of a map with string keys and float64 values.

```go
massForPlanet := make(map[string]float64) // Same as: map[string]float64{}
massForPlanet["Mercury"] = 0.06
massForPlanet["Venus"] = 0.82
massForPlanet["Earth"] = 1.00
massForPlanet["Mars"] = 0.11
fmt.Println(massForPlanet)
```

`map[Venus:0.82 Mars:0.11 Earth:1 Mercury:0.06]`

For small maps it doesn't matter whether we specify their initial capacity, but for large maps doing so can improve performance. In general it is best to specify the initial capacity if it is known (even if only approximately).

Maps use the [] index operator just like arrays and slices, for maps the index inside square brackets is of the map's key type which might not be an int—here, for example, we have string keys.

To print the map to the console we have used the fmt.Println() function; this uses the % formatting verb and outputs the map's items space-separated in key: value form. Maps are unordered, so on a different machine the order of items printed may be different from that shown here.

As noted earlier, pointers can be used as map keys. We will look at an example whose keys are of type *Point where Point is defined as follows:

```go
type Point struct{x, y, z int}
func (point Point) String() string {
	return fmt.Sprintf("%d,%d,%d", point.x, point.y, point.z)
}
```

The Point type stores three ints. It has a String() method that ensures when we print a *Point Go will use the String() method rather than simply printing the Point's memory address.

Incidentally, we can force Go to print a memory address by the %p format verb; the format verbs were covered earlier (§3.5.6, 103 ◄).

### 4.3. Maps

```go
triangle := make(map[*Point]string, 3)
triangle[&Point{89, 47, 27}] = "\alpha"
triangle[&Point{86, 65, 86}] = "\beta"
triangle[&Point{7, 44, 45}] = "\gamma"
fmt.Println(triangle)
```

`map([7,44,45]):y (89,47,27):alpha (86,65,86):beta`

Here, we have created a map with an initial capacity and populated it with pointer keys and string values. Each Point is created using the composite literal syntax and the & operator so we get a *Point rather than a Point value. (This syntax was introduced earlier in the chapter; 145 ◄) And thanks to the Point.String(), when the map is printed we see the *Point values in human-readable format.

Using pointers as map keys means we can add two Points with the same coordinates, providing that they are created separately (and so have different addresses). But what if we want the map to store only one point for any particular set of coordinates? This can be easily done by storing Point values rather than pointers to Points; after all, Go permits structs to be used as map keys—so long as all fields are comparable with == and !=. Here is an example.

```go
nameForPoint := make(map[Point]string) // Same as: map[*Point]string{
nameForPoint[Point{54, 91, 78}] = "\x"
nameForPoint[Point{54, 158, 89}] = "\y"
fmt.Println(nameForPoint)
```

`map([5,91,78]):x (54,158,89):y`

The mapForCity's map keys are unique Points whose associated name strings can change at any time.

```go
populationForCity := map[string]int{
	"Istanbul": 12610000,
	"Karachi": 10620000,
	"Mumbai": 12690000,
	"Shanghai": 13680000,
}
for city, population := range populationForCity {
	fmt.Printf("-%10s %%8d\n", city, population)
}
```

Shanghai 13680000
Mumbai 12690000
Istanbul 12610000
Karachi 10620000

For this section's final example we have created an entire map using the composite literal syntax.

When a for ... range loop is applied to a map and there are two variables, the loop returns a key and a value on each iteration until every key-value item has been returned or the loop is broken out of. If just one variable is present only the key is returned on each iteration. Since maps are unordered we cannot know what particular sequence the items will come in. In many situations we just want to iterate over all of a map's items to update them, or the iteration order doesn't matter. However, if we want to iterate in, say, key order, it is easy to do as we will see shortly ($4.3.4, ➤ 170).

### 4.3.2. Map Lookups

### 4.3.3. Modifying Maps

Maps can be modified by adding, updating, or deleting entries. Here are a few examples.

```go
populationForCity["Tokyo"] = 14000000
delete(populationForCity, "Mumbai")
populationForCity["Shanghai"] = 13700000
```

Adding a new entry to a map is identical to updating one; if the key already exists, the value is overwritten. Deleting an entry removes the key from the map.

### 4.3.4. Key-Ordered Iteration

When producing data for human consumption we often need to present the data in some order. Here is an example that shows how to output populationForCity map in alphabetical (strictly speaking, Unicode point) order of city.

```go
cities := make([]string, 0, len(populationForCity))
for city := range populationForCity {
    cities = append(cities, city)
}
sort.Strings(cities)
for _, city := range cities {
    fmt.Printf("-%10s %8d\n", city, populationForCity[city])
}
```

| City | Population |
|---|---|
| Beijing | 11290000 |
| Istanbul | 12610000 |
| Karachi | 10620000 |
| Mumbai | 12690000 |
| Shanghai | 13680000 |

The algorithm shown here—create an empty slice large enough to hold all of the map's keys, add all the map's keys to the slice, sort the slice, and iterate over the slice to produce ordered output—can be applied generally for key-ordered map iteration.

An alternative to the approach taken here is to use an ordered data structure in the first place—for example, an ordered map. We will see an example of this in a later chapter.
