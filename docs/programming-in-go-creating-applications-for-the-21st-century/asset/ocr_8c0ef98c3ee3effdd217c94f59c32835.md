If valid numbers were input and sent to the questions channel (in a polar struct), we block the question routine waiting for an answer on the answers channel. The additional goroutine created in the createSolver() function is itself blocked waiting for a polar on the questions channel, so when we send the polar, the additional goroutine performs the computation, and sends the result cartesian to the answers channel, and then waits (blocking only itself) for another question to arrive. Once the answer is received in the interact() function on the answers channel, interact() is no longer blocked. At this point we print the string using fmt.Printf() function, and passing the polar and cartesian values as the arguments that the string's %s placeholders are expecting. The interact() function's loop is an infinite loop, so soon as a result the user is once again asked to enter a radius and angle, with the loop being broken out of only if the reader reads the end of file—either interactively from the user or the end of a redirected input file has been reached.

The calculations in polarcartesian are very lightweight, so there is no real need to do them in a separate goroutine. However, a similar program that needed to do them on multiple independent heavyweight calculations as the result of each input might well benefit from using the approach here, for example, with one goroutine per calculation. We will see more realistic use cases for channels and goroutines in Chapter 7.
