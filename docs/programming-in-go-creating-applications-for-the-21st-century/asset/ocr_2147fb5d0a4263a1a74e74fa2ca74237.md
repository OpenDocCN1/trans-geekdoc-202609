If the original slice doesn't have sufficient capacity, the append() function creates a new slice under the hood and copies the original slice's items into it, the new value or values at the end, and returns the new slice—hence the need to assign append()'s return value to the original slice variable.

It sometimes occurs when we insert items at the front or in the middle of a slice, not just after. Here are some examples that a custom InsertStringSliceCopy() takes a slice to insert into, a slice to insert, and the index position where the insertion should be.

```
s := []string{"M", "N", "O", "P", "Q", "R"}
x := InsertStringSliceCopy(s, []string{"a", "b", "c"}, theta) // At the front
y := InsertStringSliceCopy(s, []string{"x", "y"}, 3) // In the middle
z := InsertStringSliceCopy(s, []string{"z"}, len(s)) // At the end
fmt.Printf("%v\n%v\n%v\n%v\n", s, x, y, z)
```


The custom InsertStringSliceCopy() creates a new slice (which is why slice s is unchanged in that of the snippet), making use of the built-in copy() function to copy the first slice it is given and to the second slice.

```
func InsertStringSliceCopy(slice []string, insertion []string, index int) []string {
	result := make([]string, len(slice)+len(insertion))
	at := copy(result, slice[:index])
	at += copy(result[at:], insertion)
	copy(result[at:], slice[index:])
	return result
}
```

The built-in copy() function takes two slices (which could be portions of the same slice—even overlapping ones) that contain items of the same type. The function copies items into the first (destination) slice from the second (source) slice and returns the number of items copied. If the source slice is empty, the function will safely do nothing. If the destination slice's length is insufficient to accommodate the source's items, the items that don't fit are ignored. If the destination slice's capacity is greater than its length, we can increase its length to its capacity with the statement slice = slice[:cap(slice)], before doing the copy.
