# 5.6. Custom Functions

Functions are the bedrock of procedural programming and Go provides first-class support for them. Go methods (covered in Chapter 6) are very similar to Go functions, so this section is relevant for both procedural and object-oriented programming.

Here are the fundamental syntaxes for function definitions:

```
func name(optionalParameters) optionalReturnType {
}
func name(optionalParameters) (optionalReturnValues) {
}
```

A function can take zero or more parameters. If there are no parameters the parentheses. If there is one or more, they are written params1 type, ..., paramsN type, where params1 is a single parameter name or a comma-separated list of two or more parameter names of the given type. Parameters must be passed in the order: There is no equivalent to Python's named parameters, although a similar effect can be achieved as we will see later (§5.6.1.3, ➤222).

The very last parameter's type may be preceded by an ellipsis (...). Such functions are called variadic; this means the function will accept zero or more values of that type as that parameter's value and inside the function parameter will be of type []type.

A function may return zero or more values. If there are none return value it can be written as type. If there are two or more return values, parentheses must be used and they are written as (type1, ..., typeN). If there are one or more named return values, parentheses must be used and they are written as (values1 type1, ..., valuesN typeN), where values1 is a single return name or a comma-separated list of two or more return names of the given type. Function return values may all be unnamed or all named, but not a mixture of.

Functions that have one or more return values must have at least one return statement—or a call to panic() as their final statement. If return values are unnamed, the return statement must specify as many values as there are return values, each with a type matching the corresponding return value. If the return values are named the return statement can either specify values just like in the unnamed case or bare (i.e., giving no explicit values to return). Note that although bare returns are legal, they are considered poor style—none of the book's examples use them.
