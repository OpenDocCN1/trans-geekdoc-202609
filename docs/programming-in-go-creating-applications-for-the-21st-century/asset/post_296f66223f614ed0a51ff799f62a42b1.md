Go takes a consistent approach to reading and writing data that allows us to read and write to, buffers (e.g., to slices of bytes or strings), and to the standard input, output, and error streams—or to our own custom types—so long as we provide the methods necessary to satisfy the reading and writing interfaces.

For a value to be readable it must satisfy the io.Reader interface. This interface specifies a single method with signature, Read([]byte) (int, error). The Read() reads data from the value it is called on and puts the data into the given slice. It returns the number of bytes and an error value which will be nil if no error occurred, or io.EOF("end of file") if no error occurred and the end of the input was reached, or some other non-nil value if an error occurred. Similarly, for a value to be writable it must satisfy the io.Writer interface. This interface specifies a single method with signature, Write([]byte) (int, error). The Write() method writes data from the given slice to the value it was called on, and returns the number of bytes written and an error value (which will be nil if no error occurred).

The io package provides readers and writers but these are unbuffered and operate in raw bytes. The bufio package provides buffered input/output where the input will work on any value that satisfies the io.Reader interface (i.e., provides a suitable Read() method), and the output will work on any value that satisfies the io.Writer interface (i.e., provides a suitable Write() method). The bufio package's readers and writers providing buffering can work in terms of bytes or strings, and so are ideal for reading and writing UTF-8 encoded text files.

> * In fact, the user could still overwrite the input file by using redirection—for example, ./americanise infile > infile—but at least we have prevented an obvious accident.

## 1.6. American—Files, Maps, and Closures

var britishAmerican = "british-american.txt"

```go
func americanise(inFile io.Reader, outFile io.Writer) (err error) {
	reader := bufio.NewReader(inFile)
	writer := bufio.NewWriter(outFile)
	defer func() {
		if err == nil {
			err = writer.Flush()
		}
	}()
	var replacer func(string) string
	if replacer, err := makeReplacerFunction(britishAmerican); err != nil {
		return err
	}
	wordRx := regexp.MustCompile("[A-Za-z]+")
	eof := false
	for !eof {
		var line string
		line, err := reader.ReadString('\n')
		if err == io.EOF {
			err = nil // io.EOF isn't really an error
			eof = true // this will end the loop at the next iteration
		} else if err != nil {
			return err // immediately for real errors
		}
		line = wordRx.ReplaceAllFunc(line, replacer)
		if _, err := writer.WriteString(line); err != nil {
			return err
		}
	}
	return nil
}
```

The americanise() function buffers the inFile reader and writes the outFile to the buffered writer. Then it reads lines from the buffered reader and writes each line to the buffered writer, having replaced any British English words with their U.S. equivalents.

The function begins by creating a buffered reader and a buffered writer through their contents can be accessed as bytes—or more conveniently in this case, as strings. The bufio.NewReader() construction takes as argument any value that satisfies the io.Reader (i.e., provides a suitable Read() method) and returns a new buffered io.Reader that reads from the given reader. The bufio.NewWriter() function is synonymous with any value that satisfies the io.Writer (i.e., provides a suitable Write() method) and returns a new buffered io.Writer that writes to the given writer.

This way of working with interfaces is very flexible and makes it easy to compose functionality in Go. We create an anonymous function that will flush the writer's buffer before americanise() function returns control to its caller. The anonymous function will be called when americanise() returns normally—or abnormally due to a panic. Be aware, however, that there is subtle scoping issue we must consider when using named return values. For example, if we have a named return value, we can assign it to anywhere in the function using the assignment operator (=). However, if we have a statement such as :=, if the statement starts a new block, the value in the state will be a new variable, so the statement will shadow the return variable. One consequence of this is that we must declare the variables we want to assign to the same time. Regular expressions can be compiled using regexp.Compile() function which returns *regexp.Regexp and nil, or nil and error if the regular expression is invalid. This is ideal for use from an external source or a file received from the user. Here, we have used the regexp.Compile() function—this simply returns a *regexp.Regexp, or panics if the regular expression, or "regex", is invalid. The regular expression used in the example matches the longest sequence of one or more alphabetic characters.

With the replacer function and the regular expression in place we start an infinite loop by reading a line from the reader. The bufio.Reader.String() method reads (or strictly speaking, decodes) the underlying reader's raw bytes as UTF-8 encoded text (which also works for 7-bit ASCII) up to and including the byte (or to the end of the file). The function conveniently returns the text with an error (or nil).

If the error returned by the call to the bufio.Reader.String() method is not nil, either we have reached the end of the input or we have hit a problem. At the end of the input err will be io.EOF which is perfectly okay, in this case we set err to nil (since there isn't an error), and set err to ensure that the loop finishes at the next iteration, so won't advance beyond the end of the file. We don't return immediately with io.EOF, since it is possible that the file's last line doesn't end with a newline, in which case we will receive a line to be processed, in addition to the io.EOF.

For each line we use the regexp.Regexp.ReplaceAllStringFunc() method, giving it the line and the replacer function.
