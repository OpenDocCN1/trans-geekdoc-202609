The .Push() method always works (unless the counter runs out of memory), so we don't need to return an error value to indicate success or failure.

If we want to modify a value we must make its receiver a pointer.* A pointer is a variable that holds the memory address of value. One reason that pointers are used for efficiency—example, if we have a value of a large type it is much cheaper to pass a pointer to the value as a parameter to pass the value itself. Another use is to make a value modify. For example, when a variable is passed into a function it gets a copy of the value (e.g., the stack passed into the stack.len() 25). This means that if we make any changes to the variable inside the function, they will have no effect on the original value. Or if we need to modify the original value—as here we need to append to the stack—we must pass a pointer to the original value, and then inside the function we can modify the pointer that points to.

A pointer is declared by preceding the type name with a star (i.e., an asterisk, *). So here, in the Stack.Push() method, the variable is of type *Stack, that the stack variable holds a pointer to a Stack value and not an actual Stack value. We can access the actual Stack value that the pointer points to by dereferencing the pointer—simply means that by preceding the variable name with a star. So here, when we write *stack we are referring to a pointer to a Stack, and when we write *stack we are dereferencing the pointer, that is, referring to the actual stack that the pointer points to.

So, in (Go and C++ for that matter), the star is overloaded for multiplication (between a pair of variables, e.g., x * y), pointer declaration (when preceding a type name, e.g., *My), and pointer dereference (when preceding a pointer variable's name, e.g., *x). Don't worry too much about these for now: Go's pointers are fully explained in Chapter 4.

Note that Go's channels, maps and slices are all created using the make() function, and make() always returns a reference to the value it created. References behave much like pointers in that when they are passed any changes made to them inside the function affect the original channel, map, or slice.
