This function creates and returns an anonymous function of type filepath.WalkFunc (i.e., that has signature func(string, os.FileInfo, error)). This function will be called for every file and directory that the filepath function encounters. The path is the file or directory name, the info has the results of a stat call on the path, and the err either is nil or the details of any problem was encountered reaching the path. We can skip directories by returning an error value of filepath.SkipDir, and we can stop the walk by returning other non-nil error.

We have chosen to process only regular files of nonzero size. (Of course, all files of size 0 bytes are the same, but we ignore them.) The Mode is a bitmask that has bits set for directories, symbolic links, named pipes, sockets, and devices—so none of these are set as a regular file.

If the file is “small” (in this case up to 32KiB), we compute its SHA-1 immediately using a custom processFile(). But for all others we create a new goroutine in the processFile() function executed asynchronously. This means that small files will block (until we computed their SHA-1), big files will not block until their computation is done. Either way, when the computation is complete the result FileInfo value is sent to the info channel.

We need only the sync.Group.Add(1) method when we create a new goroutine, but when we do so we must be sure to call the corresponding sync.Group.Done() method once the goroutine has finished. We do this by taking advantage of Go’s support for closures (§5.6.3, 225 ◀). We for the processFile() function in a new goroutine we pass an anonymous function as the argument—when this anonymous function is called we call the sync.Group.Done() method. The processFile() function is expected to have a deferred call to Done() gets when the goroutine finishes. If we call the processFile() method in the current goroutine, we pass nil instead of an anonymous function.

Why didn’t we simply process every file in a new goroutine? Go would have no problem with that since we can create hundreds or thousands of goroutines without hitting any problems. Unfortunately, most operating systems impose a limit as to how many files may be open at the same time. For Windows the default limit could be as small as 512 although this can be increased to 2048.
