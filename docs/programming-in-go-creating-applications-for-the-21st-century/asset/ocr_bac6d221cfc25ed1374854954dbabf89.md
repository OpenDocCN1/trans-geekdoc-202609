+   Create a concurrent program that uses a fixed number of worker goroutines and that accepts one or more HTML files on the command line. The program should read each HTML file and every time it finds an <img> tag it should check if the tag has width and height attributes, and if not, it should ascertain the image's width and height and adding the attribute or attributes. The concurrency structure could be done in a similar way to one of the apachereport examples (but not the mutex-using imagetag2 version), except that there is no need for results counter.

Since Go 1 doesn't have an HTML parser, for this exercise we use the reg and strings packages. We searched for image tags using the regular expression string '<[Ii][Mm][^>]+>', and we identified filenames within image tags using the regular expression 'src=['"][^\']+['']'. (These regexes are not very sophisticated since we want to focus on concurrency, for which we use 3.6.5,120) Use the image.DecodeConfig() function discussed in the previous exercise (along with all imports) to use the commandFiles() function (176) to handle file globbing.

The concurrency aspects of this program are quite straightforward, and the processing is quite tricky. This is a welcome change from programming in other languages where the concurrency aspects overwhelm the actual processing that needs to be done.

Two solutions are provided. The first solution, sizes1 (in file sizes1/sizes1.go), does everything, but has one disadvantage: it can only find the image files if it is run in the same directory as the HTML files. This limitation is due to the fact that we replace <img> tag with an updated tag using the regexp.Replace.ReplaceAllString() method. This method expects to be passed a replacer function with signature func(string) string with the string being the matched text and the returned string being the replacement. A typical tag might be <img src="splash.png">. The replacer function has no idea what the path to the splash.png file is, and so must assume the current directory, and hence the limitation that sizes1 must be run in the same directory as the HTML files.

It might be tempting to try to solve the problem by using a global directory string and assigning the current HTML file's path to it before using the replacer function—but this won't work in all situations. Why?
