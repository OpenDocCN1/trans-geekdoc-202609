## 3.6.5. Regexp Package

This subsection presents tables listing the regexp package's functions and the regular expression syntax the package supports, and includes a few illustrative examples. Here and elsewhere in this book, we assume prior knowledge of regular expressions, or "regexes*".

The regexp is a Go implementation of Cox's RE2 regular expression engine. This engine is fast and thread-safe. The RE2 engine doesn't use backtracking, O(n) where n is the length of the matched string, whereas backtracking engines can easily take exponential O(n²) (see the sidebar “Big-Notation”, 89 ►). The superior performance is gained at the expense of having no support for backreferences in searches. However, it is straightforward to avoid this constraint by making good use of the regexp API.

Table 3.12 lists the regexp package's functions, including four functions for creating *regexp values. These values provide the methods shown in Tables 3.18 and 3.19 (► 124–125). The RE2 engine's syntax supports the sequences listed in Table 3.13 (► 121), the character classes listed in Table 3.14 (► 122), the zero-width assertions listed in Table 3.15 (► 122), the quantifiers listed in Table 3.16 (► 123), and the flags listed in Table 3.17 (► 123).

The regexp.Regexp.ReplaceAll() and regexp.ReplaceAllString() methods support both numbered and named replacements. Numbered replacements support $1 for the first capturing parenthesized match. Named replacements refer to capture groups. Although replacements can be referred to by number or name (e.g., $2, $filename), it is safest to use braces as delimiters (e.g., ${2}, ${filename}). $$ us to include a literal in a replacement string.
