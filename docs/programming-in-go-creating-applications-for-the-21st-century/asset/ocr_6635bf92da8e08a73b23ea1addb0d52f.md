There is a subtlety in the makeReplacerFunction() function that is not immediately apparent. In the anonymous function created inside it we access the usBritish map, yet this map was created outside the anonymous function. This works because Go supports closures (§6.3) . ➤ 225. A closure is a function that “captures” some external state—for example, the state of the function the closure accesses. So, the anonymous function created inside the makeReplacerFunction() is a closure that has captured the usBritish map.

Another subtlety is that the usBritish map is a local variable and we will be accessing outside the function in which it is declared. It is perfectly fine to return local variables in Go. Even if they are references or pointers, Go won't delete them while they are in use and garbage-collect them when they are finished with (i.e., when every variable holds, refers, or points to them has gone out of scope).
