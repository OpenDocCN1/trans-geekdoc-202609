• 威胁源（例如，黑客、自满的用户、雷雨等）

• 泛化威胁与特定威胁（例如，针对未打补丁操作系统的一般威胁与专门识别用于利用特定漏洞的威胁）

## 威胁行为体

威胁行为体，也称为 `threat agents` 或 `threat sources`，是发起威胁、传播威胁或使威胁发生的实体。威胁行为体并不总是人类，尽管我们将大多数恶意行为归因于人类。还有自然威胁源，例如洪水、飓风和龙卷风。请记住，威胁源也可以以不同的方式分类，正如我们在目标 1.10 中也提到的：

• 对抗性 恶意实体，例如个人、群体、组织，甚至国家

• 意外性 自满的用户

• 结构性 设备或软件故障

• 环境性 自然或人为引发的灾难和中断

**EXAM TIP** 虽然有时很难做到，但请记住，你必须尝试区分威胁行为体或源与威胁本身。有时这些几乎是一回事，但给定足够的信息和上下文，你可以区分威胁的来源与威胁，威胁是发生的事件。请记住，威胁也利用漏洞；威胁行为体不利用。它们仅仅发起或使能威胁。

### 1.11 问题

**[1](#ch01.xhtml#ch1ques11-1).** 你是公司事件响应团队的成员。你的公司刚刚遭受了一次恶意攻击，多个服务器中包含关键数据的几个关键硬盘已被完全擦除。初步调查表明，一名黑客渗透了基础设施并运行了一个脚本来删除这些关键硬盘的内容。关于威胁行为体和威胁事件，以下哪项陈述是正确的？

**A.** 黑客是威胁行为体，数据删除是威胁事件。

**B.** 脚本是威胁行为体，黑客是威胁事件。

**C.** 脚本既是威胁行为体也是威胁事件。

**D.** 数据删除是威胁事件，脚本是威胁行为体。

**[2](#ch01.xhtml#ch1ques11-2).** Nichole 是一名网络安全分析师，为 O'Brien Enterprises 工作，这是一家小型网络安全公司。她正在向一位客户推荐各种威胁方法论，该客户希望为 Microsoft Windows 开发定制应用程序。她的客户希望纳入一种威胁建模方法论，以帮助他们进行安全代码开发。Nichole 应该向她的客户推荐以下哪项？

**A.** PASTA

**B.** Trike

**C.** VAST

**D.** STRIDE

### 1.11 答案

**[1](#ch01.xhtml#r_ch1ques11-1).** A 在这个场景中，黑客发起了威胁事件，实际事件是从关键硬盘中删除数据。脚本可能是攻击的工具，但它既不发起威胁也不是威胁本身，因为脚本本身不会做任何恶意的事情。负面事件是数据删除。

**[2](#ch01.xhtml#r_ch1ques11-2).** D `STRIDE`（欺骗、篡改、否认、信息泄露、拒绝服务和权限提升）是由 Microsoft 创建的一种威胁建模方法论，用于将安全性纳入应用程序开发中。列出的其他方法论都不特定于应用程序开发，除了 `VAST`（可视化、敏捷和简单威胁建模），但它并不特定于 Windows 应用程序开发。

## 应用供应链风险管理 (SCRM) 概念

公司的供应商为组织引入了严重的安全考量，特别是因为供应品（包括软件和硬件）可能被恶意软件破坏、功能或性能低劣，甚至可能是假冒的。在这个目标中，我们讨论组织如何减少与供应链相关的潜在安全问题。

### 供应链风险管理

供应链组织由硬件、软件以及商品和服务的供应商序列组成。一个组织可以拥有提供其供应品的上游供应链，以及用于向他人供应品的下游供应链。供应链风险管理 (SCRM) 是组织采取的措施，以确保供应链的每个环节都是安全的。与 SCRM 相关的许多问题包括有缺陷或假冒的部件、嵌入恶意软件的组件以及其他恶意行为。这个目标探讨供应链管理中涉及的风险以及组织应如何应对它们。

### 与硬件、软件和服务相关的风险

供应链中的任何环节都可能受到攻击，但三个常见目标是硬件、软件和服务。与这些目标各自相关的不同风险一样，组织可以采取不同的步骤来减轻或降低这些风险。接下来的几个部分将描述这些风险和措施。
