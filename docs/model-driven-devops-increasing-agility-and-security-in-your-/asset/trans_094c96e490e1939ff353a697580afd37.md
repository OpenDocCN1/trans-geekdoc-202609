

事实来源的主要作用是数据管理，而代码的主要作用是数据移动和转换。模型驱动 DevOps 的目标是使代码尽可能简单且可重用。为此，本书中使用的大多数 Ansible playbook 只是将数据从事实来源移动到网络中。虽然我们在本书中使用 Ansible，但所介绍的原则可以用于任何语言。应特别强调从事实来源检索所有数据，而不要在自动化代码中硬编码。代码与事实来源之间的清晰划分使其更具可重用性。当代码不可重用时，会编写更多代码。编写的代码越多，就越需要维护更多代码。维护不当的代码会导致网络不规则和不稳定。

我们主要使用 Ansible 来编排数据从事实来源通过各种任务移动到网络的过程。然而，在此过程中，我们可能需要进行一些数据结构转换，特别是从已有自己的架构的数据库事实来源（例如 CMDB）转换到我们的 OpenConfig 模型。例如，让我们看看从 NetBox 获取的接口数据，如 [清单 4-18](#ch04.xhtml#ch4list18) 所示。请注意，`show-hostvars.yml` 是一个简单的 playbook，用于显示库存中特定主机的 hostvars（包含所有 Ansible 库存数据的数据结构）。此输出允许我们查看 NetBox 通过其动态库存插件提供的数据。

同样，此输出为了简洁而被截断，但我们可以看到 NetBox 为每个主机提供了一系列接口。问题是，数据是使用 NetBox 原生模型的，因此我们必须将其转换为我们的通用模型（OpenConfig）。在之前的示例中，我们通过 Ansible 变量扩展进行转换。这里的问题是，由于设备通常会有许多接口，因此 interfaces 是一个列表数据结构。在 Ansible 中原生处理这会很麻烦，但非常适合使用 Jinja。首先，让我们创建一个以 OpenConfig 系统模型为基础的 Jinja 模板，然后添加适当的逻辑来遍历来自 NetBox 的接口（如 [图 4-8](#ch04.xhtml#ch4fig8) 中所示）以将其转换，如 [清单 4-19](#ch04.xhtml#ch4list19) 所示。

### LISTING 4-19 Jinja2 Template to Translate NetBox Data to OpenConfig Data

[Click here to view code image](Images/ch04_images.xhtml#plist4-19)

```
$ more templates/netbox-to-oc.j2
{
   "openconfig-interfaces:interfaces": {
      "interface": [
{% for interface in interfaces | default([]) %}
         {
            "config": {
               "description": "{{ interface.description }}",
               "mtu": "{{ interface.mtu | default('1500') }}",
               "name": "{{ interface.name }}",
               "type": "ethernetCsmacd",
               "ethernet": null,
               "config": {
                  "auto-negotiate": true,
                  "enable-flow-control": false
                },
               "hold-time": null,
{% if interface.ip_addresses is defined and interface.ip_addresses %}
               "subinterface": [
                  {
                     "config": {
                        "index": "0",
                        "ipv4": null,
                        "addresses": {
                           "address": [
{% for address_item in interface.ip_addresses | default([]) %}
                              {
                                 "config": {
                                    "ip": "{{ address_item.address.split('/')[0] }}",
                                    "prefix-length": "{{ address_item.address.split('/')[1] }}"
                                 }
                              },
{% endfor %}{# for address_item in interface.ip_addresses #}
                           ]
                        },
                        "config": {
                           "dhcp-client": false
                        }
                     }
                  }
               ],
{% endif %}{# interface.ip_addresses is defined #}
               "enabled": "{{ interface.enabled }}"
            }
         },
{% endfor %}{# for interface in interfaces #}
      ]
   }
}
```
