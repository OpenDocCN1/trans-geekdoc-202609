
# 使用 Ansible 管理 NetBox 数据

这段代码告诉 Ansible 库存系统我们想要哪个插件，以及我们想要所有信息；它还告诉系统按原始组名对 Ansible 中的设备进行分组。要了解此插件提供的内容，让我们使用 playbook 来配置 NetBox。我们可以通过 GUI 完成此任务，但因为这是一章关于 IaC 的内容，让我们使用 Ansible 模块。[Listing 4-14](#ch04.xhtml#ch4list14) 中的代码添加了在 NetBox 中创建设备所需的最少信息。

## Listing 4-14 使用 Ansible 向 NetBox 添加数据

[Click here to view code image](Images/ch04_images.xhtml#plist4-14)

```yaml
- hosts: localhost
  gather_facts: no
  tasks:
    - name: Create manufacturer in Netbox
      netbox.netbox.netbox_manufacturer:
        netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
        netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
        data:
          name: RouterMaker
        state: present
        validate_certs: no

    - name: Create device role in netbox
      netbox.netbox.netbox_device_role:
        netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
        netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
        data:
          name: router
        state: present
        validate_certs: no

    - name: Create device type in netbox
      netbox.netbox.netbox_device_type:
        netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
        netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
        data:
          model: router9000
          manufacturer: RouterMaker
        state: present
        validate_certs: no

    - name: Create site in Netbox
      netbox.netbox.netbox_site:
        netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
        netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
        data:
          name: "{{ item }}"
        state: present
        validate_certs: no
      when: item.startswith('site')
      loop: "{{ groups.keys() }}"

    - name: Create device in Netbox
      netbox_device:
        netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
        netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
        data:
          name: router1
          device_role: router
          device_type: router9000
          site: site3
        validate_certs: no
        state: present
```

这个 playbook 从我们之前设置的环境变量中获取 NetBox API 信息，以查找并验证 NetBox 实例。它包含添加设备所需的一些虚构信息，并从在 [Listing 4-6](#ch04.xhtml#ch4list6) 中创建的 `inventory.yaml` 文件中提取站点列表，以在 NetBox 中创建 site1-4。在 playbook 调用时运行 NetBox 动态库存脚本时，数据将 `router1` 与 `site3` 在 Ansible 库存中关联，因为我们告诉动态库存插件按站点分组，如在 [Listing 4-13](#ch04.xhtml#ch4list13) 中所示。这个简单示例说明了如何从外部数据库获取库存信息，并将其与文件中静态指定的库存信息相结合。运行此 playbook 后，库存如 [Listing 4-15](#ch04.xhtml#ch4list15) 所示。

我们刚刚演示了如何将数据库来源真理数据作为动态库存脚本的一部分进行管理。现在让我们看看 ad hoc 调用方法，以了解如何在 playbook 本身中存储和检索来源真理中的信息（而不是作为库存的一部分拉取）。例如，让我们从网络中添加一个可用 IP 地址到 `router1`。首先，通过添加 [Listing 4-16](#ch04.xhtml#ch4list16) 中的任务到 playbook 来用网络对我们的来源真理进行预处理。

## Listing 4-16 使用 Ansible 在 NetBox 中创建前缀

[Click here to view code image](Images/ch04_images.xhtml#plist4-16)

```yaml
- name: Create prefix in Netbox
  netbox.netbox.netbox_prefix:
    netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
    netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
    validate_certs: no
    data:
      prefix: 172.30.1.0/24
    state: present
```

接下来，我们创建另一个 playbook，将接口 `GigbitEthernet1` 添加到 NetBox 中的 `router1`，并将其分配给我们刚刚创建的网络上的第一个可用 IP 地址，如 [Listing 4-17](#ch04.xhtml#ch4list17) 所示。

## Listing 4-17 从 NetBox 提取 IP 并将其分配给接口

[Click here to view code image](Images/ch04_images.xhtml#plist4-17)

```yaml
- hosts: localhost
  gather_facts: no
  tasks:
    - name: Create GigabitEthernet1 on router1
      netbox.netbox.netbox_device_interface:
        netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
        netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
        validate_certs: no
        data:
          device: router1
          name: GigabitEthernet1
          type: 10GBASE-T
        state: present

    - name: Attach a new available IP on 172.30.1.0/24 to GigabitEthernet1
      netbox.netbox.netbox_ip_address:
        netbox_url: "{{ lookup('env', 'NETBOX_API') }}"
        netbox_token: "{{ lookup('env', 'NETBOX_TOKEN') }}"
        validate_certs: no
        data:
          prefix: 172.30.1.0/24
          assigned_object:
            name: GigabitEthernet1
            device: router1
```

在这个示例中，我们演示了两个原则。首先，这个示例说明了如何在 Ansible play 中从来源真理存储和检索信息。虽然是一个简单的示例，但它展示了如何检索可用 IP 地址以分配给设备。其次，我们检索了可用 IP 地址，并将其分配给来源真理中的接口。也就是说，我们将来源真理更改为网络的期望状态。在这里，`router1` 尚未实际配置，但来源真理首先被更新，展示了涉及来源真理时的变更流程。当来源真理反映网络的期望状态时，该状态可以推送到网络，使网络的实际状态与期望状态保持一致。

使用类似 NetBox 的来源真理的优势在于，对于操作员来说更容易上手。不是每个人都会习惯于更新基于文本的来源真理，因此 NetBox 提供的 GUI 可能更受欢迎，并且有时更高效。
