

Jinja 在 Ansible 中被大量使用，尤其是在其变量扩展和过滤器的使用方面。事实上，大多数使用 Ansible 的传统网络自动化方法往往更多是 Jinja2 而非 Ansible。Jinja2 模板用于创建负载，而 Ansible 模块用于交付这些负载。

##### AWS CloudFormation

AWS CloudFormation 是最早被广泛采用的基础设施即代码（IaC）工具之一，至今仍被许多云运维人员大量使用。它只能与 AWS 及其虚拟网络一起使用；但是，由于其受欢迎程度，我们将其包含在内以确保完整性。它使 IaC 对非开发人员可用，因为它提供了一种方式，可以将云基础设施定义为由数据模型定义的数据，然后将该模型推送到一个服务中，该服务随后配置基础设施。

##### Terraform

我们包含的另一个 IaC 工具是 Terraform，目的是确保完整性。Terraform 也是开源的，并且经常与 Ansible 配合使用。Terraform 本质上是声明式的（与过程式相对），通常用于配置基础设施，而 Ansible 主要用于配置。在撰写本书时，Terraform 配置物理网络基础设施的能力有限，但非常擅长配置虚拟网络，并支持多个云和虚拟化提供商。Terraform 与 CloudFormation 类似，因为它使 IaC 对非开发人员可用。

#### Organization

源数据的组织非常重要。大多数设备的配置是结构化的，因此以类似的方式结构化源数据很有帮助。由于 OpenConfig 是为此操作用例开发的，因此它以这种方式结构化。每个模型涵盖设备的特定服务或子系统。例如，OpenConfig 系统模型定义设备级设置，如主机名、域名、DNS、日志记录和身份验证。其他服务（如接口）构建在系统设置之上，而 VRF 和路由等服务则构建在接口之上。[Figure 4-5](#ch04.xhtml#ch4fig5) 说明了各种模型之间的关系。当所有这些服务合并在一起时，它们提供了整个设备配置。

![FIGURE 4-5 OpenConfig Model Relationships](Images/04fig05.jpg)

FIGURE 4-5 OpenConfig Model Relationships

源数据的另一个维度是设备的分层分组。在最细粒度级别，信息按设备组织。通常，设备将拥有与其关联的最多数据，因为它包括包含大量元素的信息组，例如接口、路由、ACL 和负载平衡规则。然后可以将设备分组为站点，站点分组为区域，区域分组为父组织，如 [Figure 4-6](#ch04.xhtml#ch4fig6) 所示。这些分组中的每一个都包含特定于该分组的数据，并由该分组的子级继承（例如，站点包含其父区域的所有数据）。当同一数据存在于一个分组中时，子级的数据将覆盖父级的数据（例如，站点的 DNS 服务器将覆盖区域的 DNS 服务器）。这种继承和优先级关系允许数据合并。例如，不需要为站点中的每个设备指定 DNS 服务器。相反，设备将继承为其站点或区域指定的 DNS 服务器。理想情况下，数据只需在适当级别指定一次，以便于跟踪和更改。

![FIGURE 4-6 Inheritance Hierarchy](Images/04fig06.jpg)

FIGURE 4-6 Inheritance Hierarchy

这种类型的组织也适用于 Ansible 的库存系统。Ansible 有一个灵活的库存系统，它从各种来源提取数据来为您的模型提供数据。其中一个来源可以是以 YAML 或 JSON 渲染的文本文件。这些文件存储在库存结构中，该结构使用 `host_vars` 和 `group_vars` 目录分别存储设备和组数据，如 [Listing 4-5](#ch04.xhtml#ch4list5) 所示。

要配置的设备列表以及用于配置这些设备的数据被合并到每个设备上下文中的特定事实组中。库存中指定的每个设备和组的数据位于 `host_vars/<device name>.yaml` 或 `group_vars/<group name>.yaml` 中，其中 `group_vars/all.yaml` 提供组织级数据。

作为示例，让我们展示如何在这些不同级别设置 DNS 服务器。让我们在 `group_vars/all.yaml` 中将组织级 DNS 服务器 DNS1 和 DNS2 分别设置为 1.1.1.1 和 2.2.2.2。如果我们随后在 `group_vars/region_b.yaml` 中将区域 b 的 DNS2 覆盖为 3.3.3.3，并在 `group_vars/site_4.yaml` 中将站点 4 的 DNS2 覆盖为 4.4.4.4，则我们将得到 [Listing 4-8](#ch04.xhtml#ch4list8) 中的结果。

#### Types of Source of Truth

组织的源数据通常由多个不同的来源构成。这些来源通常分为两种类型：文本型和数据库型。

##### Textual Source of Truth
