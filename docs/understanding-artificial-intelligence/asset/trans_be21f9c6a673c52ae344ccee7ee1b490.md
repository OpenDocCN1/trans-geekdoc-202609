
-   [算法](https://wiki.example.org/feynmans_learning_method)就像数学家的烹饪配方：打开鸡蛋，放入碗中，搅拌，倒入煎锅，以此类推。情况相同。就像为厨师编写煎蛋配方一样，你可以编写一个算法来描述如何处理信息。例如，要进行加法运算，我们可以学习加法算法并将其应用。

当构建计算器时，工程师将这些算法转化为一组电子线路。我们得到一台机器，它在提供两个数字时，能够计算并显示相应的和。这三个概念（烹饪配方、算法以及应用算法的电子机器）在复杂度上有所不同，但都很容易理解：厨师知道如何编写和遵循配方；计算机科学家知道如何编写算法；电气工程师知道如何构建计算器。

## [ALGORITHMS AND COMPUTER SCIENCE](#contents.xhtml#toc2_5)

计算机科学的原创性在于将算法本身视为信息。想象能够用数字或其他机器可解释的符号来描述我们的加法配方，这在理论上是可能的。想象一下，我们不是在构建计算器，而是在构建一个稍微更复杂的机器。当给出两个数字和我们的加法算法时，这台机器能够“解码”算法以执行它所描述的操作。会发生什么？

机器将执行加法运算，这并不令人惊讶。但随后，同样的机器可以使用不同的算法，比如说乘法算法。于是，我们拥有一台机器，它可以根据所给的算法，同时执行加法和乘法。

我能感觉到兴奋达到顶点。执行加法和乘法对你来说可能并不特别特别。然而，这一 brilliant 创意（我们称之为它）归功于查尔斯·巴贝奇（1791–1871），正是它促成了计算机的诞生。计算机是一种机器，它通过物理介质（例如穿孔卡片、磁带、光盘）上的数据进行处理，并遵循写在相同物理介质上的指令集（通常是数据的同一介质）：它是一台执行算法的机器。

## [THE ALL-PURPOSE MACHINE](#contents.xhtml#toc2_6)

1936 年，阿兰·图灵提出了著名的 *Turing machines*（图灵机）数学计算模型。

图灵机由一条带有可书写符号的纸带组成。为了让你更好地理解，想象一卷 35 mm 电影胶片，上面有若干小格，你可以在这些格子里放置照片。然而，图灵机并不使用照片。相反，我们使用一个 *字母表*——即一系列符号的列表（例如 0 和 1，这是计算机工程师最喜欢的符号）。在每个格子里，只能写入一个符号。

为了让图灵机工作，需要给出一组编号的指令，如下所示：

```
Instruction 1267:
```

```
Symbol 0 → Move tape one cell to the right,
Go to instruction 3146
```

```
Symbol 1 → Write 0,
Move tape one cell to the left,
Resume instruction 1267.
```

图灵机会分析当前格子中的符号并执行相应的指令。

从某种意义上说，这一原理类似于“选择你的冒险”书籍：*记下你拾起了剑，然后翻到第 37 页*。比较在此结束。与阅读“选择你的冒险”书籍的读者不同，机器不会自行决定打开宝箱或进入龙的巢穴：它只会按照作者在页面上写的内容行动，并且不会自行做出任何决定。

它完全遵循算法中写明的内容。

阿兰·图灵证明，他的“机器”可以复现任何算法，无论多么复杂。事实上，计算机的工作方式与图灵机完全相同：它拥有记忆（相当于图灵机的“纸带”），读取内存单元中的符号，并借助电子线路执行特定指令。因此，理论上，计算机能够执行任何算法。

## [PROGRAMS THAT MAKE PROGRAMS](#contents.xhtml#toc2_7)

让我们回顾一下。计算机是一台配备*记忆*的机器，记忆中存储了两类内容：数据（或更广义地说，信息，因此称为*信息技术*）和一种在特定语言中编写的算法，该算法指明了数据应如何处理。用机器可解释的语言编写的算法称为*计算机程序*，当机器执行该算法所描述的内容时，我们说计算机*运行*该程序。

正如图灵机所示，编写程序比单纯说“把数字列在列中并相加”要复杂得多。它更像是：

```
Take the last digit of the first number.
```

```
Take the last digit of the second number.
```

```
Calculate the sum.
```

```
Write the last digit in the “sum” cell.
```

```
Write the preceding digits in the “carrty” cell.
```

```
Resume in the preceding column.
```

必须逐步、准确地描述机器必须执行的操作，且只能使用由微小电子线路允许的操作。以这种方式编写算法非常受限。

因此，计算机工程师发明了语言和程序来解释这些语言。例如，我们可以让机器将上述操作序列中的 `+` 符号进行转换。

这使得编程变得更加容易，因为可以复用已有的程序来编写更复杂的程序——就像使用原始工具一样！一旦有了轮子，就可以制造推车，再经过足够的时间和精力，甚至可以制造一台制造轮子的机器。

## [AND WHERE DOES ARTIFICIAL INTELLIGENCE FIT IN ALL THIS?](#contents.xhtml#toc2_8)

人工智能 consist of 编写特定的程序。

根据 [Minsky (1968)](#ch01.xhtml#ref1_1)，他在 1950 年代创立了这一学科，认为 AI 是*“构建能够执行目前由人类更有效完成的任务的计算机程序，这些任务目前需要高层次的心理过程，如：感知、学习、记忆组织和批判性推理*​​​​​​”。

换句话说，就是编写程序来执行信息处理任务，从表面上看，人类在第一眼看上去更有优势。因此，我们应该说“一个 AI 程序”，而不是“一个人工智能”。

如今，存在许多能够解决信息处理任务的 AI 程序，包括下棋、预测明天的天气、回答“美国第五任总统是谁？”等。所有这些机器可以完成的事务都依赖于人工智能的方法和算法。因此，人工智能并没有什么神奇或智能的地方：机器应用算法——这是一套由人类编写的算法。如果有任何智能，则来源于程序员为机器提供正确指令的那位程序员。

## [A MACHINE THAT LEARNS?](#contents.xhtml#toc2_9)

显然，编写 AI 程序并不容易：必须编写指令，使其在任何提供的数据下都能产生看似“智能”的回答。与其手动编写详细指令，计算机科学家通常使用能够从数据源中自动提取“正确”答案的高级程序。正如加法的例子所示，思想是让机器减轻编写程序的负担。正如加法一样，我们试图利用机器让编程更加容易。这一原则是 *机器学习* 这一 AI 技术的核心。
