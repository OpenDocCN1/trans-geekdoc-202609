### 8.3.3.1.1 Handling Missing Data

For attributes like age, gender, ethnicity, born with jaundice, and family member with PDD, it’s essential to managing missing values to maintain data quality.

- i. Imputation for age: If some age are missing, you can use imputation to fill the missing values.

```
Imputed Age = \sum_{i=1}^{N} Age_i
```

where N is the number of non-missing age entries.

- ii. Imputation for categorical attributes: For categorical attributes like gender or ethnicity, mode imputation could be:

```
Imputed Value for Gender = Mode(Gender)
```

where mode is the most frequent value in the dataset.

- iii. Record removal: If an attribute has screening score is missing, and this attribute is critical, the entire record might be removed:

```
Remove record if Screening Score is missing.
```

### 8.3.3.1.2 Encoding Categorical Variables

For attributes like gender, ethnicity, born with jaundice, family member with PDD, country of residence, relation,class/ASD, and who is completing the test, categorical encoding is necessary.

- i. Label encoding for gender: Convert the gender attribute to numeric labels.

```
Gender Encoded = \begin{cases} 0 & \text{if Male} \\ 1 & \text{if Female} \end{cases}
```

- ii. One-Hot Encoding for Ethnicity: Convert the Ethnicity attribute to binary variables for each ethnicity.

```
Ethnicity_{Category} = \begin{cases} 1 & \text{if ethnicity is Category} \\ 0 & \text{otherwise} \end{cases}
```

### 8.3.3.1.3 Standardization and Normalization of Numerical Features

For numerical attributes like age and screening score, standardization or normalization can be applied.

- *Standardization of age*: Adjust the age to have a mean of 0 and standard deviation of 1.

```
$$\text{Age} = \frac{\text{Standardized - Age}}{\sigma_{\text{Age}}}$$ (8.6)
```

where $\mu$ Age is the mean age, and $\sigma$ Age is the standard deviation.

- *Normalization of screening score*: Rescale the screening score to a range [0, 1].

```
$$\text{Screening Score}_{\text{Normalized}} = \frac{\min(\text{Screening Score})}{\max(\text{Screening Score}) - \min(\text{Screening Score})}$$ (8.7)
```

## 8.3.3.2 Feature Extraction

The process of feature extraction involves selecting and transforming significant attributes from pre-processed data to improve the accuracy and efficiency of predictive models. This process begins by identifying features, such as family history of PDD, screening scores, and specific question responses. These attributes are crucial as they provide essential information that can significantly contribute to predicting ASD. By focusing on these key features, the model can better understand patterns and relationships within the data, leading to more accurate predictions.

To select significant features from the pre-processed data, we identify the variables X that have a strong correlation with the target Y (ASD prediction). We suppose we have a dataset with n samples and m features, represented as X = {xl,x2,...,xm} and target Y. The selection of informative features can be framed as finding the X'⊆X that maximizes the correlation with Y.

### 8.3.3.2.1 Derived Feature Creation

In addition to selecting features, crafting derived features is a valuable aspect of feature extraction. Derived features can provide additional insights and enhance model performance. For instance, categorizing age into specific groups such as toddlers, children, adolescents, and adults can reveal trends and differences in ASD prediction across different ages. Similarly, defining relationships such as parent, self, or healthcare professional who completed the test can help contextualize the data, offering a deeper understanding of the individual's background and circumstances.

Derived features are created by applying transformations to selected features. For instance, if age is a feature, we can derive categories as:

> Age Category = \begin{cases} Toddler & if 0 \le Age < 3 \\ Child & if 3 \le Age < 12 \\ Adolescent & if 12 \le Age < 18 \\ Adult & if Age \ge 18 \end{cases} \quad (8.12)

### 8.3.3.2.2 Redundant and Correlated Feature Removal

Another critical aspect of feature extraction is removing redundant or highly correlated features. Redundant features do not contribute new information and can unnecessarily complicate the model, while highly correlated features can distort the model's predictions by giving undue weight to certain aspects of the data. By eliminating these features, the model becomes much more streamlined and interpretable, reducing complexity without compromising predictive accuracy.

To remove redundant or highly correlated features, we compute the correlation matrix C for all features:

```
C_{ij} = \frac{Cov(Xi,Xj)}{\sigmaXi\sigmaXj} \quad (8.13)
```

Cov(Xi,Xj) is the covariance between features Xi and Xj, and σXi and σXj are the standard deviations. To remove one of the features Xi and Xj if |Cij| exceeds a threshold.

### 8.3.3.2.3 Uniform Scaling

After feature extraction, it is essential to ensure uniform scaling among features, preventing any single feature from dominating the model. This involves standardizing or normalizing features to have a mean of 0 and a standard deviation of 1, particularly for sensitive models. The standardized feature Zi can be calculated as:

```
Zi = \frac{\Xi - \muXi}{\sigmaXi} (8.14)
```

where muXi is the mean and sigmaXi is the standard deviation.

### 8.3.3.2.4 Tailoring to ASD Prediction

Tailoring extraction to the unique characteristics of ASD prediction is also vital. This involves considering factors like family history and chosen method. For instance, we may assign weights to features based on their relevance, and a weighted sum:

```
S = \sum_{i=1}^{m} wiXi (8.15)
```

where S is a composite score for prediction.

### 8.3.3.3 Vote

In data science, the vote model is a simple and efficient model. This methodology involves several models contributing to their forecasts, with a majority vote deciding the final result. The projected class is to vote by each model, and the class with the highest votes becomes the forecast. Mathematically, the predicted class (C) is found as the mode of the predicted classes from models if there are "n" individual models:

```
C = mode(C1, C2, ..., Cn) (8.16)
```

Here C1, C2, ..., represent the predicted classes from each individual model. The vote model is particularly useful when different models bring diverse perspectives or expertise, and the collective decision helps enhance overall prediction accuracy.
