## 4.3. Data Pre-Processing

The “raw sensor data” from the previous step serve as input for the data pre-processing phase, which is illustrated in Figure 2.

![](img/601340ca744b738277eef45ff127492a_162_1.png)

Figure 2. Data pre-processing phase—from raw sensor data (left) to sensor data to analyse (right).

This pre-processing phase consists of three main steps:

- 1. Extracting values from differently formatted strings of values:

Data in the SQL DB are stored at 1 s intervals in various sampling rates of each the sensors measuring different physiological parameters. For instance, the Empatica E4 measures GSR at a sampling rate of 4 Hz, while the VarioPort measures GSR at a sampling rate of 25 Hz. The result is a table with sensor values where each measurement has a correct timestamp.

- 2. Transcription of parameters and temporal alignment of measurements:

First, the vertical parameter structure (one row consists of a single measurement, the next row consists of the same timestamp and with another single sensor measurement) must be transposed to a horizontal alignment (a common timestamp and individual values as columns: one row consists of a timestamp and all measurements that occurred at that timestamp).
Second, the irregular timestamps of all measurements are aligned to the millisecond in order to ensure the best possible match to the sensors synchronized. Since 1 millisecond resolution is below the original sampling period, the measurements are aggregated depending the parameters.

The result is a multivariate time series with 10 or 100 millisecond resolutions where some parameters at some timestamps may be missing values while other parameters are averaged within the given millisecond interval.

- 3. Interpolation, moving average and scaling:

To fill missing values introduced by the temporal alignment in step 2, we applied interpolation, because it greatly reduce oscillation by taking into account data points before and after the gap to be interpolated for a continuous representation [45]. In addition to the raw data, we calculated a moving averaged version with a window of ±5 s to eliminate high local variations.

For the correlation analysis of same type parameters and exploratory plots, we keep the original scaling of individual time series to identify potential offsets of measurements. For the similarity analysis, however, we rescale the measurements of individual time series from minimum and maximum to 0 and 1 in order to compare similarity distances.

The data pre-processing was mainly carried out directly in the database using SQL and Java.

## 4.4. Statistical Signal Analysis—Time Series Correlation and Similarity Analysis

This sub-section illustrates how we assessed the correlations and similarities between time series of the same physiological parameters measured by different sensor platforms. For some selected, such as the MIC, we also run the analysis between different physiological parameters in order to explore potentially unknown relationships. The basic analytical workflow is shown in Figure 3. Note that we use the original scaling factor for exploratory plots, linear regression, and cross-correlation, while we use the rescaled signal (minimum $\rightarrow$ 0 $\dots$ 1) to get similarity measures such as Frechet and DTW distance.

![](img/601340ca744b738277eef45ff127492a_163_0.png)

**Figure 3.** Data workflow—from sensor data to analyse (left) to visualizations of exploratory plots and quantitative analysis results to deriving conclusions (right).

Of the complete time series derived from the pre-processing workflow (See 4.2), we selected the following physiological parameters: HR, GSR, IBI, ECG. Additionally, from the ECG signal, we again derived the IBI and the Complex Demodulation amplitudes for the following frequency bands to estimate the heart rate variability [46];

- Very low frequency VLF (0.05–0.07 Hz)
- Low frequency LF (0.07–0.5 Hz)
- High frequency HF (0.5–4 Hz)

In order to quantify the associations, we used the following:

- $R^2$, to assess fit
- Cross-correlation, to assess temporal
- Mutual Information Coefficient (MIC), to explore
- Frechet distance, to explore similarity
- DTW distance, to explore similarity

Signal analysis was done using R, while other plots were produced with Tableau.
