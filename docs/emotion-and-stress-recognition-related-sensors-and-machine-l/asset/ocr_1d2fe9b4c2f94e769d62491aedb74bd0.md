#  4.3. Data Pre-Processing

The “raw sensor data” from the previous step serve as input for the data pre-processing phase, which is illustrated in Figure 2.

![](bbox=[0.143, 0.415, 0.857, 0.473])

Figure 2. Data pre-processing phase—from raw sensor data (left) to sensor data to analyse (right).

This pre-processing phase consists of three main steps:

+   1. Extracting values from differently formatted strings of values:

Data the SQL DB are stored at 1 s intervals in various sampling rates of each the sensors measuring different physiological parameters. For instance, the Empatica E4 measures GSR at a sampling rate of 4 Hz, while the VarioPort measures GSR at a sampling rate of 25 Hz. The result is a table with sensor values where each measurement has a correct timestamp.

+   2. Transcription of parameters and temporal alignment of measurements:

First, the vertical parameter structure (one row consists of a single measurement, the next row consists of the same timestamp and with another single sensor measurement) must be transposed to a horizontal alignment (a common timestamp and individual values as columns: one row consists of a timestamp and all measurements that occurred at that timestamp).
Second, the irregular timestamps of all measurements are aligned to the millisecond in order to ensure the best possible match to the sensors synchronized. Since 1 millisecond resolution is below the original sampling period, the measurements are aggregated depending the parameters.

The result is a multivariate time series with 10 or 100 millisecond resolutions where some parameters at some timestamps may be missing values while other parameters are averaged within the given millisecond interval.

+   3. Interpolation, moving average and scaling:

To fill missing values introduced by the temporal alignment in step 2, we applied interpolation, because it greatly reduce oscillation by taking into account data points before and after the gap to be interpolated for a continuous representation [45]. In addition to the raw data, we calculated a moving averaged version with a window of ±5 s to eliminate high local variations.
