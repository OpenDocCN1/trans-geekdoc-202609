2. Q-Value 函数具有良好的泛化能力，配合合适的函数近似（确实，深度神经网络能力的最新进展对此帮助很大）。

这种以这种方式解决 MDP 预测和控制问题的想法（在 Q-Value 函数近似中具有适当泛化能力，从经验数据流中学习）源于 Chris Watkins 的博士论文（[Watkins 1989](#bib01.xhtml#refbib_65））。如前所述，我们将 Sutton 和 Barto 的 RL 书籍（[Richard S. Sutton and Barto 2018](#bib01.xhtml#refbib_62））视为 RL 算法综合研究以及所有与 RL 相关参考文献的最佳来源（因此，我们在这本书中不提供太多参考文献）。

如前几章所述，大多数 RL 算法都建立在 Bellman 方程之上，所有 RL 控制算法都基于我们在 [Chapter 4](#chapter4.xhtml) 中解释的 `Generalized Policy Iteration` 的基本思想。但是，Bellman 方程和 Generalized Policy Iteration 思想在 RL 算法中的具体应用方式因算法而异，并且与它们在 DP 算法中的应用方式有显著不同。

一如既往，我们先从预测问题（本章）开始，然后再介绍控制问题（下一章）。

## 11.2 RL FOR PREDICTION

我们重复使用了在 Module I 中开发的大量符号。作为提醒，预测是针对给定策略 `π` 估计 MDP 的 Value Function 的问题。我们知道从 [Chapter 4](#chapter4.xhtml) 这等同于估计 `π`-implied MRP 的 Value Function。因此在本章中，我们假设我们正在处理一个 MRP（而不是 MDP），并且我们假设 MRP 以接口的形式可用，该接口给定当前状态后提供一个 (next state, reward) 对的个体经验。该接口可能是真实环境或模拟环境。我们将给定当前状态时，代理接收到一个 (next state, reward) 的个体经验称为 `atomic experience`。连续与该接口交互（从状态 `S[0]` 开始）给我们一个由交替状态和奖励组成的 `trace experience`，如下所示：

$$
\begin{array}{r}
{S_{0},R_{1},S_{1},R_{2},S_{2},\ldots}
\\
\end{array}
$$

给定一个原子经验流或一个轨迹经验流，RL 预测问题是估计 MRP 定义的 `Value Function` `V`:𝒩→ℝ，定义如下：

$$
\begin{array}{r}
{V(s) = \mathbb{E}\lbrack G_{t}|S_{t} = s\rbrack\text{~for~all~}s \in \mathcal{N},\text{~for~all~}t = 0,1,2,\ldots}
\\
\end{array}
$$

其中，每个 `t = 0, 1, 2, …` 的 `Return G[t]` 定义为：

$$
\begin{array}{r}
{G_{t} = {\sum\limits_{i = t + 1}^{\infty}\gamma^{i - t - 1}} \cdot R_{i} = R_{t + 1} + \gamma \cdot R_{t + 2} + \gamma^{2} \cdot R_{t + 3} + \ldots = R_{t + 1} + \gamma \cdot G_{t + 1}}
\\
\end{array}
$$

即使对于终止的轨迹经验（假设在 `t = T` 终止，即 `S[T] ∈ 𝒯`），我们也使用上述 `Return` 定义，方法是对所有 `i > T` 处理 `R[i] = 0`。

我们即将开发的 RL 预测算法会消耗一个原子经验流或一个轨迹经验流来学习所需的 Value Function。因此，我们希望 RL 预测算法的输入要么是原子经验的 Iterable，要么是轨迹经验的 Iterable。现在让我们讨论一下单个原子经验的表示（在代码中）和单个轨迹经验的表示。我们带你回到 [Chapter 3](#chapter3.xhtml) 中的代码，在那里我们设置了一个 `@dataclass TransitionStep`，它作为抽象类 `MarkovRewardProcess` 中方法 `simulate_reward` 的构建块。

![](images/comp11_1.jpg)

`TransitionStep[S]` 表示一个单个原子经验。`simulate_reward` 产生一个 `Iterator[TransitionStep[S]]`（即以采样轨迹形式的原子经验流），但一般来说，我们可以将单个轨迹经验表示为 `Iterable[TransitionStep[S]]`（即原子经验的序列 *或* 流）。因此，我们希望 RL 预测算法的输入要么是：

*   一个 `Iterable[TransitionStep[S]]`，表示原子经验流

*   一个 `Iterable[Iterable[TransitionStep[S]]]`，表示轨迹经验流

让我们向 `MarkovRewardProcess` 添加一个方法 `reward_traces`，它产生由 `simulate_reward` 生成的采样轨迹的 `Iterator`（流）。![](images/comp11_2.jpg)

## 11.3 MONTE-CARLO (MC) PREDICTION

蒙特卡洛（MC）预测是一个非常简单的 RL 算法，它执行监督学习来预测 MRP 中任何状态的预期回报（即，它估计 MRP 的 Value Function），给定一个轨迹经验流。请注意，我们在 [Chapter 6](#chapter6.xhtml) 中编写了抽象类 `FunctionApprox` 用于监督学习，它以 (*x*, *y*) 对的形式获取数据，其中 *x* 是预测变量，*y* ∈ ℝ 是响应变量。对于蒙特卡洛预测问题，*x*-值是输入轨迹经验流中遇到的状态，*y*-值是轨迹经验上的相关回报（从相应的遇到状态开始）。以下函数（在文件 `rl/monte_carlo.py` 中）`mc_prediction` 以轨迹经验的 Iterable 作为输入，每个轨迹经验表示为 `TransitionSteps` 的 Iterable。`mc_prediction` 以增量方式执行所需的监督学习，通过在从每个轨迹经验中提取的 (state, return) 对的 `Iterator` 上调用 `approx_0: ValueFunctionApprox[S]` 的方法 `iterate_updates`。作为提醒，方法 `iterate_updates` 迭代调用 `FunctionApprox` 的方法 `update`（在此情况下，每次调用 `update` 都会为单个 (state, return) 数据点更新 `ValueFunctionApprox`）。`mc_prediction` 产生 `ValueFunctionApprox[S]` 的 `Iterator` 作为输出，即每个轨迹经验结束时 Value Function 的更新函数近似（请注意，函数近似更新只能在每个轨迹经验结束时进行，因为轨迹经验回报只在每个轨迹经验结束时可用）。

![](images/comp11_3.jpg)

上述 `mc_prediction` 函数的核心是对 `returns` 函数的调用（详细如下，可在文件 `rl/returns.py` 中找到）。`returns` 以以下内容作为输入：`trace` 表示一个轨迹经验（`TransitionStep` 的 `Iterable`）、折扣因子 `gamma`，以及一个 `episodes_length_tolerance`，它确定在 `γ < 1` 时每个轨迹经验覆盖多少时间步骤（直到 `γ^(steps)` 低于 `episodes_length_tolerance` 或轨迹经验在终止状态结束，以先发生者为准）。如果 `γ = 1`，每个轨迹经验需要以终止状态结束（否则 `returns` 函数会无限循环）。

`returns` 函数计算从轨迹经验中的每个状态 `S[t]` 开始的回报 `G[t]`（累积折扣奖励）。

我们在 `TransitionStep` 中添加了一个名为 `add_return` 的方法，以便我们可以将属性 `state`、`reward`、`next_state` 与额外的属性 `return_` 增强，该属性计算为 `reward` 加上 `gamma` 乘以下一个状态的 `return_`。![](images/comp11_4.jpg)![](images/comp11_5.jpg)
