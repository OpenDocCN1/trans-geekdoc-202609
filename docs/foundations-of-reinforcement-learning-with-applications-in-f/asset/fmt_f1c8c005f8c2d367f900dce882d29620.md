
# 基于 GPI 思想的 MC 控制

让我们思考如何基于 GPI 思想进行 MC 控制。自然而然的想法是先进行基于 MC 的策略评估（这基本上就是 MC 预测），然后进行贪婪策略改进，接着再用改进后的策略进行 MC 策略评估，如此循环……这似乎是一个合理的想法，但进行贪婪策略改进存在一个问题。问题是，贪婪策略改进计算（公式 12.1）需要状态转移概率函数 $\mathcal{P}$ 和奖励函数 $\mathcal{R}$ 的模型，而在 RL 接口中这些模型是不可用的。

$$\\begin{array}{r} {\\pi\_{D}^{\\prime}(s) = \\text{arg}\\,\\text{max}\_{a \\in \\mathcal{A}}\\left\\{ \\mathcal{R}(s,a) + \\gamma{\\sum\\limits\_{s^{\\prime} \\in \\mathcal{N}}\\mathcal{P}}(s,a,s^{\\prime}) \\cdot V^{\\pi}(s^{\\prime}) \\right\\}\\text{~for~all~}s \\in \\mathcal{N}} \\\\ \\end{array}$$  

(12.1)

然而，我们注意到公式 12.1 可以更简洁地写成：

$$\\begin{array}{r} {\\pi\_{D}^{\\prime}(s) = \\text{arg}\\,\\text{max}\_{a \\in \\mathcal{A}}Q^{\\pi}(s,a)\\text{~for~all~}s \\in \\mathcal{N}} \\\\ \\end{array}$$  

(12.2)

这种贪婪策略改进的观点很有价值，因为我们不再需要为了计算 $V^{\pi}$（MC 预测）而进行策略评估，而是可以进行策略评估来计算 $Q^{\pi}$（使用针对 Q-值函数的 MC 预测）。通过对策略评估的这种修改，我们可以在策略评估和策略改进之间不断交替，直到收敛，从而获得最优值函数和最优策略。确实，这是一个有效的 MC 控制算法。然而，这个算法不实用，因为每次策略评估（MC 预测）通常需要很长时间才能收敛（如我们在 [Chapter 11](#chapter11.xhtml) 中所指出的那样），并且直到 GPI 收敛的评估和改进迭代次数也会很多。更重要的是，这个算法只是通过用 MC Q-值策略评估替换 DP/ADP 策略评估来修改策略迭代 DP/ADP 算法——因此，我们最终只是得到了策略迭代 DP/ADP 算法的一个更慢版本。相反，我们寻求一个 MC 控制算法，它可以在不需要策略评估收敛的情况下从策略评估切换到策略改进（这基本上就是 GPI 思想）。

因此，这里的自然 GPI 思路是在每个回合结束时进行通常的 MC 预测更新（针对 Q-值估计），然后在该回合结束时改进策略，然后在下一个回合结束时使用改进后的策略进行 MC 预测更新，如此循环……让我们看看这个算法是什么样子。公式 12.2 告诉我们，在任何回合的任何时间步执行所需的贪婪动作（来自改进后的策略），只需要一个 Q-值函数的估计。为了便于理解，目前我们只限于表格式每次访问 MC 控制的情况，即对任何 (state, action) 对获得的每个 Return 数据点赋予相等权重。在这种情况下，我们可以简单地在每个回合结束时对回合中遇到的每个 ($S[t]$, $A[t]$) 对执行以下两个更新（注意，在每个时间步 $t$，$A[t]$ 是基于当前 Q-值函数估计推导出的贪婪策略）：

$$\\begin{aligned} {Count(S\_{t},A\_{t})} & \\left. \\leftarrow Count(S\_{t},A\_{t}) + 1 \\right. \\\\ {Q(S\_{t},A\_{t})} & \\left. \\leftarrow Q(S\_{t},A\_{t}) + \\frac{1}{Count(S\_{t},A\_{t})} \\cdot (G\_{t} - Q(S\_{t},A\_{t})) \\right. \\\\ \\end{aligned}$$  

(12.3)

需要注意的是，$Count(S[t], A[t]) 是迄今为止所见所有回合的累积值。注意，估计 $Q(S[t], A[t]$ 不是单个策略的 Q-值函数估计——相反，它随着我们在回合集合中遇到新的贪婪策略而不断更新。

那么，这就是我们的第一个表格式 RL 控制算法了吗？并非如此——还有另一个问题。这个问题更微妙，我们用一个简单的例子来说明。让我们考虑一个特定的状态（称之为 $s$），并假设状态 $s$ 只有两个允许的动作 $a[1]$ 和 $a[2]$。假设状态 $s$ 的真实 Q-值函数为：$Q[true](s, a[1]) = 2$，$Q[true](s, a[2]) = 5$。假设我们将 Q-值函数估计初始化为：$Q(s, a[1]) = Q(s, a[2]) = 0$。当我们第一次遇到状态 $s$ 时，在 $a[1]$ 和 $a[2]$ 之间选择动作是任意的，因为它们具有相同的 Q-值估计（意味着 $a[1]$ 和 $a[2]$ 在 $Q(s, a)$ 的两个选择中产生相同的最大值）。假设我们任意选择 $a[1]$ 作为动作选择，并且假设在状态 $s$ 的第一次遇到（使用任意选择的动作 $a[1]$）时，获得的回报是 3。因此，$Q(s, a[1]) 更新为值 3。所以，当状态 $s$ 第二次被遇到时，我们看到 $Q(s, a[1]) = 3$ 且 $Q(s, a[2]) = 0$，因此，将根据 Q-值函数估计所暗示的贪婪策略采取动作 $a[1]$。假设我们现在获得回报 -1，将 $Q(s, a[1]) 更新为 $\frac{3 - 1}{2} = 1$。当 $s$ 第三次被遇到时，再次将根据 Q-值函数估计所暗示的贪婪策略采取动作 $a[1]$。假设我们现在获得回报 2，将 $Q(s, a[1]) 更新为 $\frac{3 - 1 + 2}{3} = \frac{4}{3}$。我们看到，只要与 $a[1]$ 关联的回报不足以使估计 $Q(s, a[1]) 变为负数，$a[2]$ 就会被 $a[1]$“锁定”，因为 $a[1]$ 的前几次出现恰好产生的平均回报大于 $Q(s, a[2]) 的初始化。即使选择了 $a[2]$，也有可能 $a[2]$ 的前几次出现产生的平均回报小于 $a[1]$ 的前几次出现获得的平均回报，在这种情况下，$a[2]$ 可能会过早地被锁定。
