

# Policy Iteration 与 Generalized Policy Iteration

我们还想分享一个关于 Policy Iteration 的可视化图表，该图表在动态规划（Dynamic Programming）的大量文献中非常流行，最初出现在 Sutton 和 Barto 的 RL 书籍中（[Richard S. Sutton and Barto 2018](#bib01.xhtml#refbib_62））。这是 [Figure 5.3](#chapter5.xhtml#fig5_3) 的可视化内容。这是一个有些模糊的图表，但在 Policy Iteration 的教学方面有其优势。该图像的核心思想是：下方的线代表“策略线”（policy line），表示 Policy Iteration 算法推进时策略的演进；上方的线代表“值函数线”（value function line），表示 Policy Iteration 算法推进时值函数的演进。

指向上方线（“值函数线”）的箭头表示给定策略 `π` 的策略评估（Policy Evaluation），得到上方线上的点（值函数）**V**^(*π*)。指向下方线（“策略线”）的箭头表示从值函数 **V**^(*π*) 进行贪婪策略改进（Greedy Policy Improvement），得到下方线上的点（策略）*π*^′ = *G*(**V**^(*π*))。这里的关键概念是：策略评估（指向上方线的箭头）和策略改进（指向下方线的箭头）是“竞争”的——即使它们旨在使值函数和策略相互一致，它们也“向不同方向推动”。这种同时试图竞争又试图保持一致的概念可能看起来令人困惑和矛盾，因此值得得到恰当的解释。通过注意到值函数 **V** 和策略 `π` 之间实际上存在两种一致性概念，事情就变得清晰了：

1. 值函数 **V** 与策略 `π` 的值函数 **V**^(*π*) 保持一致/接近的概念。
2. 策略 `π` 与值函数 **V** 的贪婪策略 *G*(**V**) 保持一致/接近的概念。

策略评估旨在实现第一种一致性概念，但在过程中，会使第二种一致性概念变差。策略改进旨在实现第二种一致性概念，但在过程中，会使第一种一致性概念变差。这也帮助我们理解在策略评估和策略改进之间交替进行的理由，这样上述两种一致性概念都不会滑落得太多（得益于两种一致性概念的交替支撑）。此外，请注意，随着 Policy Iteration 的推进，上方线和下方线越来越接近，“向不同方向推动”看起来越来越协作而非竞争（一致性的差距越来越小）。最终，两条线相交，此时策略评估或策略改进都不再需要推动，因为在收敛时，*π*^(\*) 和 **V**^(\*) 已经完全一致。

现在我们准备讨论一个非常重要的概念，即 *Generalized Policy Iteration*，这一概念在 Sutton 和 Barto 的 RL 书籍中（[Richard S. Sutton and Barto 2018](#bib01.xhtml#refbib_62））被强调为统一所有 DP 变体以及 RL 算法的视角。Generalized Policy Iteration 的思想是：我们可以使用 *任意* 策略评估方法来评估策略的值函数，并可以使用 *任意* 策略改进方法来改进策略（不一定是经典 Policy Iteration DP 算法中使用的方法）。特别是，我们想强调的一点是：策略评估和策略改进都不需要完全朝向它们各自努力追求的一致性概念。举个简单的例子，考虑修改策略评估（针对策略 `π`），使其不完全达到 **V**^(*π*)，而是仅执行例如 3 次贝尔曼策略评估。这意味着它会部分弥合第一种一致性概念的差距（接近 **V**^(*π*) 但不完全达到 **V**^(*π*)），但也意味着不会在第二种一致性概念上滑落太多。另一个例子，考虑仅更新 5 个状态（例如在大状态空间中）使用贪婪策略改进函数（而不是在所有状态上操作的常规贪婪策略改进函数）。这意味着它会部分弥合第二种一致性概念的差距（接近 *G*(**V**^(*π*)) 但不完全达到 *G*(**V**^(*π*))），但也意味着不会在第一种一致性概念上滑落太多。Generalized Policy Iteration 的一个具体例子实际上是值迭代（Value Iteration）。在值迭代中，我们在进行策略改进之前只应用一次贝尔曼策略算子。在二维布局中，值迭代的样子如下：

```
\begin{array}{r} \left. \pi_{1} = G(\mathbf{\mathbf{V}}_{\mathbf{0}}),\mathbf{\mathbf{V}}_{\mathbf{0}}\rightarrow\mathbf{\mathbf{B}}^{\pi_{1}}(\mathbf{\mathbf{V}}_{\mathbf{0}}) = \mathbf{\mathbf{V}}_{\mathbf{1}} \right. \\ \end{array}
```

```
\begin{array}{r} \left. \pi_{2} = G(\mathbf{\mathbf{V}}_{\mathbf{1}}),\mathbf{\mathbf{V}}_{\mathbf{1}}\rightarrow\mathbf{\mathbf{B}}^{\pi_{2}}(\mathbf{\mathbf{V}}_{\mathbf{1}}) = \mathbf{\mathbf{V}}_{\mathbf{2}} \right. \\ \end{array}
```

```
\begin{array}{r} \ldots \\ \end{array}
```

```
\begin{array}{r} \ldots \\ \end{array}
```

```
\begin{array}{r} \left. \pi_{j + 1} = G(\mathbf{\mathbf{V}}_{\mathbf{\mathbf{j}}}),\mathbf{\mathbf{V}}_{\mathbf{\mathbf{j}}}\rightarrow\mathbf{\mathbf{B}}^{\pi_{j + 1}}(\mathbf{\mathbf{V}}_{\mathbf{\mathbf{j}}}) = \mathbf{\mathbf{V}}^{\*} \right. \\ \end{array}
```

因此，贪婪策略改进步骤保持不变，但策略评估被减少到仅应用一次贝尔曼策略算子。事实上，强化学习中几乎所有控制算法都可以被视为 Generalized Policy Iteration 的特例。在一些简单的强化学习控制算法版本中，策略评估步骤仅针对单个状态进行（而不是像常规 Policy Iteration 或甚至值迭代中那样针对所有状态），策略改进步骤也仅针对单个状态进行。因此，这些强化学习控制算法本质上是单状态策略评估和单状态策略改进的交替序列（其中单状态是由采样产生的状态或在现实世界环境交互中遇到的状态）。[Figure 5.4](#chapter5.xhtml#fig5_4) 说明了 Generalized Policy Iteration，表现为较短的箭头（与常规 Policy Iteration 算法中 [Figure 5.3](#chapter5.xhtml#fig5_3) 看到的较长箭头相反）。请注意，这些较短的箭头并没有完全到达“值函数线”或“策略线”，但它们确实朝着算法在该阶段应当前进的线的方向前进了一段距离。
