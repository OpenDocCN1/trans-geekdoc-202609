攻击事件为公众所知后，瑞士政府联合国家信息安全报告与分析中心（MELANI）发布了一份关于该网络安全事件的技术报告。该报告的主要目的是与潜在的脆弱方（无论国家还是非国家行为体）共享相关信息。与事件早期的保密性形成鲜明对比的是，官方网络安全事件报告的发布获得了广泛认可。信息安全专家对妥协指标和安全建议的汇编尤为热情，这使其他潜在的脆弱实体能够检测并阻断相关攻击。[^(25)](#c05.xhtml#c5-note-0025) 例如，安全研究教授托马斯·里德在推文中提到：“瑞士发布的新 RUAG 报告是一个非常大的进步。向 @GovCERT_CH 致敬，提高了政府归因报告的标杆。”[^(26)](#c05.xhtml#c5-note-0026)

报告表明，入侵最早始于 2014 年 9 月。取证分析显示，入侵者依赖一种属于 Turla 家族的恶意软件，这是一种被认为源自俄罗斯的特洛伊木马工件。然而，报告刻意避免将攻击归因于特定的威胁行为体。[^(27)](#c05.xhtml#c5-note-0027) 据称，攻击者在渗透和横向移动阶段表现出了极大的耐心，并极度专注于高价值目标，包括活动目录。[^(28)](#c05.xhtml#c5-note-0028) 对后者的检索和渗透使入侵者能够控制其他主机，并通过提升权限和使用适当权限访问（推测为）专有数据。据称，恶意软件编写者总共窃取了 23 GB 数据。[^(29)](#c05.xhtml#c5-note-0029) 根据 RUAG 的说法，这仅占该国防承包商管理的数据量的 0.01% 以下。[^(30)](#c05.xhtml#c5-note-0030)

## 5.3.2 Conficker 工作组

### 5.3.2.1 背景

Conficker 工作组的成立是为了应对一种高度流行的计算机蠕虫 Conficker（有时也称为 Downadup 或 Kido），其第一个变种于 2008 年底出现。总共记录了五种 Conficker 蠕虫变种。[^(31)](#c05.xhtml#c5-note-0031) Conficker 恶意软件旨在创建一个大型僵尸网络（即易受外部控制的受损系统网络），它感染了全球许多未打补丁的个人、企业和政府计算机。它利用 Windows 机器上服务器服务中的缓冲区溢出漏洞，允许基于特制的远程过程调用（RPC）请求进行远程代码执行。[^(32)](#c05.xhtml#c5-note-0032)

### 5.3.2.2 事件经过

Conficker 蠕虫使用多种传播和利用技术，包括域名系统、加密的点对点通信，以及用于通过互联网推送和拉取可执行载荷的自动运行功能。[^(33)](#c05.xhtml#c5-note-0033) 安装后，恶意软件执行以下步骤：

1. Conficker 使用随机名称将自身复制到系统目录 `%systemroot%\system32`，并将自身注册为一项服务。它还将自身添加到注册表中。
2. 接着，它使用网站检查受感染主机的互联网协议（IP）地址，包括：[www.getmyip.org](http://www.getmyip.org)、[http://getmyip.co.uk](http://getmyip.co.uk) 和 [http://checkip.dyndns.org](http://checkip.dyndns.org)。
3. 识别出 IP 地址后，蠕虫随即在受感染机器上下载并设置一个小型 HTTP 服务器。
4. HTTP 服务器设置完成后，蠕虫开始扫描其他脆弱系统，并将受感染机器的 URL 发送给识别出的目标。
5. 目标机器随后从发送的 URL 下载蠕虫，并开始完成上述相同步骤。[^(34)](#c05.xhtml#c5-note-0034)

在 2008 年底蠕虫出现并迅速传播后，一群不同的利益相关者于 2009 年初聚集在一起以遏制该恶意软件。在没有官方赞助商或既定结构的情况下，Conficker 工作组代表了一个志同道合实体的临时组织。[^(35)](#c05.xhtml#c5-note-0035) 遏制工作得到了软件提供商、学术研究人员、防病毒供应商、执法单位以及域名注册商和注册局的支持。[^(36)](#c05.xhtml#c5-note-0036)

工作组启动的首批缓解策略之一是沉洞处理和预先注册蠕虫依赖的用于命令与控制的域名。互联网名称与数字地址分配机构（ICANN）作为 Conficker 工作组成员，其贡献在此至关重要。鉴于恶意软件的普遍性和影响，ICANN 同意免除蠕虫使用的域名注册费，从而有效支持了工作组切断恶意软件编写者与 Conficker 受感染系统之间通信的努力。

根据国土安全部委托的 2011 年“经验教训”报告，Conficker 工作组认为其最大的成功是破坏了僵尸网络通信。尽管在这一方面取得了成功，但工作组未能“修复受感染的计算机并消除僵尸网络的威胁”，[^(37)](#c05.xhtml#c5-note-0037) 这在一定程度上玷污了其成果。

### 5.3.2.3 经验教训

在 Conficker 蠕虫案例中，缓解活动表现出强烈的多利益相关方治理特征。响应策略遵循协作逻辑，公私实体之间建立了基于信任的合作。通过基于技能的协调和沟通，弥合了非结构化、复杂的问题情境和异质的利益相关方利益。[^(38)](#c05.xhtml#c5-note-0038) Conficker 工作组的案例表明，当威胁足够普遍时，不同的利益相关方利益可以得到协调，并可共同执行遏制策略。
