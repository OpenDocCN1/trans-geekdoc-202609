# 12 私人订立塑造网络安全政策：以漏洞赏金为例

*Amit Elazari Bar On*

*加利福尼亚大学伯克利分校信息学院，美国加利福尼亚州伯克利*

## 12.1 介绍

社会产生的代码行数比以往任何时候都多，[¹](#c12.xhtml#c12-note-0001) 一切事物——从汽车到性玩具——都正在变得互联互通。[²](#c12.xhtml#c12-note-0002) 这意味着每天都会产生更多的漏洞和利用代码，招致入侵事件，而这些事件可能带来天文数字般的成本，无论是法律上的、声誉上的，甚至是个人层面的。[³](#c12.xhtml#c12-note-0003) 随着网络安全风险的风险与成本不断增长，[⁴](#c12.xhtml#c12-note-0004) 一个合法的漏洞市场蓬勃发展。政府和公司推出漏洞奖励计划，支付费用给个人安全专家，让他们进行对抗性研究并披露关键漏洞，这些漏洞此前未被组织的内部检查和质量保证流程发现。[⁵](#c12.xhtml#c12-note-0005)

漏洞赏金计划在多个平台上推动安全研究，支付数百万美元，[⁶](#c12.xhtml#c12-note-0006) 影响数万名友善黑客的收入，并保护数十亿用户的数据（使其）更安全。[⁷](#c12.xhtml#c12-note-0007) 从硅谷巨头和暗网网站[⁸](#c12.xhtml#c12-note-0008) 到国土安全部[⁹](#c12.xhtml#c12-note-0009) 和美国陆军，漏洞赏金正逐渐将触角延伸至传统行业和政府组织，同时仍保持在Web和移动应用领域的主导地位。[^(10)](#c12.xhtml#c12-note-0010)

尽管最近声名大噪，但漏洞赏金并非近期发明。第一个漏洞赏金于1995年由网景公司发起，该公司承诺为在其Navigator 2.0互联网浏览器中发现的漏洞支付1000美元。[^(11)](#c12.xhtml#c12-note-0011) 2004年，Mozilla跟进，为在Firefox中发现漏洞的研究人员提供奖励；该漏洞赏金计划至今仍在运行，已支付数百万美元。漏洞赏金的逻辑也建立在一条源自开源软件文化的古老“技术”智慧之上，即“只要有足够多的眼睛，所有Bug都变得浅显易见。”[^(12)](#c12.xhtml#c12-note-0012) 这意味着，如果我们能邀请世界上每一位安全研究人员加入“协同开发者群体”，安全漏洞将被更快地发现和修复。[^(13)](#c12.xhtml#c12-note-0013) 漏洞赏金收割了这一逻辑——该逻辑在网络安全语境下被证明极为有效——通过扩大从事渗透测试和搜寻安全漏洞的研究人员（及技能组合）圈子。[^(14)](#c12.xhtml#c12-note-0014) 实证研究支持这一逻辑，发现与雇佣全职员工这一替代方案相比，漏洞赏金是一种具有成本效益的安全研究机制。[^(15)](#c12.xhtml#c12-note-0015)

尽管漏洞赏金在网络安全格局和不断演变的漏洞市场中扮演主导角色，但法律文献中关于漏洞赏金利用格式合同创建漏洞交易替代法律制度的讨论仍然很少。关于这些计划的学术辩论大多演变于计算机科学和经济学学科内部。[^(16)](#c12.xhtml#c12-note-0016) 这令人惊讶，考虑到漏洞赏金计划的运作和有效性在很大程度上取决于其法律条款的起草方式，以及提供给黑客的法律激励和保障体系。此类保障包括清晰传达计划的范围和针对每个漏洞分配的奖励类型，[^(17)](#c12.xhtml#c12-note-0017) 以及研究人员承担的法律风险类型和法律赋予其的授权范围。清晰的计划条款对于确保漏洞赏金继续作为漏洞的“合法”市场——即黑市的替代方案——运作至关重要。如果条款起草不当，黑客仅参与计划就可能触犯法律。[^(18)](#c12.xhtml#c12-note-0018)

在目前反黑客法律模糊不清的格局下，漏洞赏金提供了一个有趣的案例研究，展示合同如何能促进而非扼杀安全研究——即促进道德黑客行为的替代法律制度。目前，法律仍未很好地适配“*白帽*”安全研究。[^(19)](#c12.xhtml#c12-note-0019) 这在一定程度上是矛盾的，考虑到网络安全正成为一个日益受监管的领域，且越来越多的法规（和监管机构）要求公司进行渗透测试并建立接收漏洞的程序。[^(20)](#c12.xhtml#c12-note-0020) 漏洞赏金法律条款在此格局下作为黑客与赞助公司之间的合同运作，是确定从事漏洞猎捕的黑客法律责任和风险的焦点。[^(21)](#c12.xhtml#c12-note-0021)

正如将要解释的，反黑客法律，主要是《数字千年版权法》（DMCA）和《计算机欺诈和滥用法》（CFAA），部分促进了安全测试。然而，它们也要求合同语言“授权”测试。因此，计划条款应为黑客建立真正的“安全港”，[^(22)](#c12.xhtml#c12-note-0022) 通过授权访问、在黑客遵循计划指南时免除责任，并明确允许采用逆向工程等研究技术，而这些技术通常被通用的最终用户许可协议（EULA）所禁止。通过采用这种用于安全港的标准条款语言，漏洞赏金作为一种私人监管形式，提供了一个独特的机会，大规模影响白帽黑客的法律格局。

本文首次全面梳理了漏洞赏金的*法律*条款。它主张，虽然计划通常清晰披露授予研究人员的“技术范围”，但“授权”和“访问”的法律范围往往被忽视、不存在或缺失。黑客平台也助长了这一现实，它们强调定义技术范围和经济（奖励）范围的重要性，却较少关注起草适当法律条款的重要性。[^(23)](#c12.xhtml#c12-note-0023) 确实，在某些情况下，法律条款与计划目的直接冲突，让使用基础研究技术的黑客直接违反条款，并面临法律责任。在其他情况下，条款创造了一种现实：黑客如果做计划希望他们做的事——寻找漏洞——几乎默认就会违反条款。

缺乏安全港语言已导致至少一起公开案例，即参与漏洞赏金的安全研究人员据称遭到赞助公司以CFAA法律行动相威胁。[^(24)](#c12.xhtml#c12-note-0024) 积极的一面是，越来越多的公司采取直接承诺不对黑客追究法律行动，有些甚至采用了明确授权依据相关反黑客法律进行访问的法律语言。不幸的是，这仍是例外而非标准。
