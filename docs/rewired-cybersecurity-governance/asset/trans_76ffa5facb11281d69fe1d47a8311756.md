
# 国家安全与关键基础设施

人们广泛理解并接受这样一个观点：国家负责提供国家安全，保护民族国家及其公民。由于该概念是在第二次世界大战后发展起来的，国家安全的概念最初带有强烈的军事内涵。[^(10)](#c06.xhtml#c6-note-0011) 虽然国家安全仍与军事相关，但该术语的使用已扩展至包含非军事安全，例如国家的经济安全。随着对国家安全理解的拓宽，人们越来越关注`CI`及其在维护国家安全中发挥的作用。`CI`是指被认为对社会至关重要的服务、资产、系统和网络，无论是物理的还是数字的。[^(11)](#c06.xhtml#c6-note-0012) 各国根据服务或部门对政府、经济和社会的安全与防护的关键性来定义其`CI`。[^(12)](#c06.xhtml#c6-note-0013)

## 行政命令与CI保护

`CI`保护一直是许多国家法律、指南和框架的重点。在美国，自克林顿政府以来，一直有专注于`CI`保护的行政命令和总统政策指令。自1996年生效以来，`行政命令13010`（“关键基础设施保护”）是展示政府关注`CI`的关键。[^(13)](#c06.xhtml#c6-note-0014) 它成立了一个由不同联邦机构代表组成的指导委员会。该委员会负责识别并咨询被视为`CI`或支持和从事与国家`CI`相关要素的公共和私营部门。这项行政命令为公私实体在国家安全问题上合作铺平了道路，并为`CI`与政府之间`PPPs`的发展奠定了基础。2001年发布的`行政命令13231`（“信息时代的关键基础设施保护”）更侧重于保护对`CI`至关重要的信息系统的运行。[^(14)](#c06.xhtml#c6-note-0015) 除了强调`CI`信息的重要性外，该行政命令还讨论了利用`PPPs`来加强`CI`的安全和保护。重要的是，该行政命令宣示了支撑`CI`的信息系统的重要性，并催化了对这些系统安全的关注。

## 共同责任与PPPs

支撑经济和社会的`CI`系统复杂且多样。它们包括广泛分布的网络，体现多种运营模式和所有权结构，且往往同时在物理空间和网络空间发挥作用。[^(15)](#c06.xhtml#c6-note-0016) 此外，`CI`具有复杂的治理结构，包含各种法规、责任和权限。[^(16)](#c06.xhtml#c6-note-0017) 由于大部分`CI`（如金融、公用事业和交通）由私营部门拥有和/或运营，国家不能成为确保其保护和安全的唯一行为体。在美国，维护`CI`安全被视为“联邦、州、地方、部落和领土实体，以及关键基础设施的公共和私营运营商之间的共同责任”。[^(17)](#c06.xhtml#c6-note-0018) 由于`CI`潜在失陷带来的广泛而深远的风险，政府和私营行业已认识到并接受了共同责任，以确保其免受安全威胁（包括网络威胁）的侵害。

因此，`CI`的网络安全已成为公共和私营部门的优先事项。国家和私营行业的共同责任——国家负责提供国家安全，私营行业负责确保关键服务的提供和运营得到保护——导致了`PPPs`被广泛用于推动网络安全工作。特别是`FSS`，在网络安全领域见证了众多`PPPs`。接下来的章节将深入探讨其中三个合作伙伴关系：`FS-ISAC`，一个成熟的运营小组；`FSSCC`，一个政策协调机构；以及`FSARC`，一个新成立的行业小组。我们将讨论每个组织的起源、目的、成员/组成、与政府的关系，以及（如果有）显著成就（[表6.1](#c06.xhtml#c6-tbl-0001)）。

## 6.3 金融服务信息共享与分析中心

`FS-ISAC`于1999年成立，以响应1998年发布的`总统决策指令63`（`PDD-63`）。[^(18)](#c06.xhtml#c6-note-0019) 该指令强烈鼓励`CI`行业建立私营部门信息共享与分析中心（`ISACs`），以收集、分析和共享私营部门信息，与其他行业成员及`国家基础设施保护中心`（`NIPC`）共享，该中心是政府的一个部门——直到2003年被撤销——负责保护`CI`的计算机和信息系统。[^(19)](#c06.xhtml#c6-note-0020) `FS-ISAC`的宗旨、运营和组织结构深受`PDD-63`中概述的运营概念和高层制度框架的影响。

### 起源与宗旨

该指令概述了两个主要概念，它们将塑造`FS-ISAC`的宗旨和结构。关于宗旨，该指令要求在`NIPC`与每个`CI`行业创建的`ISAC`之间建立清晰且相互的沟通渠道。作为一种互惠沟通机制，`FS-ISAC`由`FSS`设计，旨在成为政府与行业之间关于物理和网络安全漏洞、入侵、威胁和异常情况信息的接收者和贡献者。因此，`FSS`利用`FS-ISAC`向成员创建和传播信息，正如收集和摄取信息一样多。重要的是，该指令强制规定分析和信息共享中心不得干扰私营部门公司与政府机构之间的信息交换。考虑到`FSS`与联邦和州监管机构保持持续联系，设计`FS-ISAC`时确保其分析和信息共享运营不侵犯或模仿监管沟通显得尤为重要。[^(20)](#c06.xhtml#c6-note-0021)

### 结构与运营模式

关于结构，`PDD-63`建议特定行业的`ISACs`以那些被认为能有效与私营和非联邦部门进行信息交换的机构为模型。该指令以`疾病控制与预防中心`（`CDC`）为模型，主要因为其在沟通、分析和报告不同倡议方面的有效性。为响应这一建议，`FS-ISAC`采用了技术重点，其目标超出了监管和执法要求。该指令还指出，特定行业`ISAC`的有效性将取决于其跨目标开发统计数据和模式的能力，以及其成为行业和政府利益相关者内部及之间收集数据和共享信息工具的能力。[^(21)](#c06.xhtml#c6-note-0022)
