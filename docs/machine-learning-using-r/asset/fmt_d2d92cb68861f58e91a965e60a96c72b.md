## 8.8 XGBoost using h2o Package

`XGBoost` is another popular boosting technique which further builds on the Gradient Boosting Machine (`GBM`) framework and is one of the best `GBM` frameworks. The objective function for `XGBoost` is derived using Taylor’s expansion of the loss function.[⁴](#16_Chapter08.xhtml#ch8-r-fn4) `XGBoost` also places more emphasis on regularization parameters.

The parameters in `XGBoost` may be categorized as general parameters, booster parameters and task parameters.

### 8.8.1 XGBoost with h20 – General Parameters

General parameters relate to the `booster` which will be used for developing the model. These are generally tree or linear model:

`booster`: Can be `gbtree`, `gblinear` or `dart`; `gbtree` and `dart` use tree-based models while `gblinear` uses linear functions. Default is `gbtree`.

Based on the `booster` selected, other booster parameters become applicable. There are other general parameters as well which `h2o` `XGBoost` method handles efficiently.

### 8.8.2 XGBoost with H2O – Learning Task Parameters

In `h2o`, the `distribution` (i.e., the loss function) parameter decides the learning scenario. The options are `AUTO`, `Bernoulli`, `multinomial`, `Gaussian`, `Poisson`, `gamma`, or `Tweedie` (Anon, 2016) According to doc.h2o.ai:.

1. For `Bernoulli` distribution, the response column must be 2-class categorical.
2. For `multinomial` distribution, the response column must be categorical.
3. For `poisson` distribution, the response column must be numeric.
4. For `Tweedie` distribution, the response column must be numeric.
5. For `gaussian` distribution, the response column must be numeric.
6. For `gamma` distribution, the response column must be numeric.

As per the site docs.h2o.ai, “`AUTO` distribution is performed by default. In this case, the algorithm will guess the model type based on the response column type. If the response column type is numeric, `AUTO` defaults to ‘`gaussian`’; if categorical, `AUTO` defaults to `binomial` or `multinomial` depending on the number of response categories (Anon, 2016)”.

### 8.8.3 XGBoost with h20 – Booster Parameters

This depends on the selected `booster`. In `h2o.xgboost`, for `booster = gbtree`, the following are the booster parameters defined:

#### Random Subspace Selection

The following methods can be used for subspace selection (*Source:* docs.h2o.ai):

1. “`col_sample_rate` (`colsample_bylevel`) – This parameter specifies the proportion of columns to be randomly selected (without replacement) for each tree. The default value is 1, but it can take any value between 0.0 and 1.0. A higher value for this parameter may improve training accuracy.
2. `col_sample_rate_per_tree` (`colsample_by_tree`) – This parameter specifies the proportion of columns to be randomly selected (without replacement) for each tree. This takes a value between 0.0 and 1.0. The default value is 1 which implies to select all columns for each tree growth. This parameter works in conjunction with `col_sample_rate`. Thus setting `col_sample_rate = 0.7` and `col_sample_rate_per_tree = 0.7` will result in 49% of columns being considered at any given node to split.

#### Random Row Selection (Bootstrap)

`sample_rate` (`subsample`) – According to docs.h2o.ai this parameter, “Specifies the row sampling ratio of the training instance (*x*-axis). Note that this method is sample without replacement. For example, setting this value to 0.5 makes `XGBoost` to randomly collect half the data instances to grow trees. The default value is 1, and the range is 0.0 to 1.0. Higher values may improve training accuracy. Test accuracy improves when either columns or rows are sampled. For details, refer to ‘Stochastic Gradient Boosting’ (Friedman, 1999)”.

#### Class Imbalance

`max_abs_leafnode_pred` (`max_delta_step`): As per docs.h2o.ai, this parameter, “specifies the maximum delta step allowed in each tree’s weight estimation. The default value is 0. Setting this value to 0 specifies no constraint. Setting this value to greater than 0 can make the update step more conservative and reduce overfitting by limiting the absolute value of a leaf node prediction. This option also helps when a class is extremely imbalanced. Setting it to value of 1-10 might help control the update”.

#### Other Booster Parameters

The parameters which can lead to controlling the growth of the tree (*Source:* docs. h2o.ai).

1. `min_split_improvement` (`gamma`) – This parameter can be used to reduce overfitting by restricting the growth of the tree. The value of this parameter signifies the minimum change in the in squared error to split a node into two. The optimal values for this parameter can be in the range of 10^(−10) to 10^(−3).
2. `max_depth` – This is another parameter to reduce overfitting. It is used to control the depth to which a tree can grow. A higher value for this parameter will lead to a more complex tree. If the value is set to 0, it will mean no limit to grow the tree (highly complex tree). The default is set to 5.
3. `min_rows` (`min_child_weight`) – Specifies the minimum number of observations for a leaf, defaults to 1.
4. `learn_rate` (`eta`) – Specifies the learning rate by which to shrink feature weights. Shrinking feature weights after each boosting step makes the boosting process more conservative and prevents overfitting. The range of `learn_rate` is between 0.0 and 1.0. This value defaults to 0.3.
5. `reg_lambda` (`lambda`) – L2 regularization term on weights with a default value of 1. Increasing this value will make the model more conservative.
6. `reg_alpha` (`alpha`) – L1 regularization term on weights with a default value of 0. Increasing this value will make the model more conservative.
