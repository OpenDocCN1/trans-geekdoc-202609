
### 2. `class_sampling_factors`
This parameter can be used along with `balance_classes` (set to `TRUE`) to specify how much to up-sample or down-sample the data. It requires us to pass the upsampling or downsampling ratios per class lexicographic order. It is an optional parameter and if we do not pass this parameter, then sampling factors are automatically computed during model training.

### 3. `max_after_balance_size`
With `balance_classes` set to `TRUE`, this parameter is used to control the relative size of the training data. The value of 1.0 will mean that, after removing class imbalance, set the size of the training data to be the same as the original training set.

## 8.4.6 Random Row Selection (Bootstrap)
The following methods are used for sampling records in RF (*Source:* docs.h2o.ai).

### 1. `sample_rate`
This parameter specifies the proportion of rows to be randomly selected (without replacement) for each tree. This parameter takes a value between 0.0 and 1.0. The default value is 0.6320000291. A higher value for this parameter may improve training accuracy. This parameter along with `col_sample_rate_per_tree` may be used to fine-tune the model.

### 2. `sample_rate_per_class`
This parameter is optional and is a substitute for `sample_rate` (either one can be used). For each tree in the ensemble model, this parameter can be used to control the proportion of rows, which needs to be sampled without replacement for each class. The parameter expects a list to be passed with the value between 0 and 1 (relative fraction of rows). This may be used to remove the class imbalance without using the parameters described in [Section 8.4.5](#16_Chapter08.xhtml#sec8.4.5).

While using `sample_rate_per_class` parameter, `balance_classes` and `class_sampling_factors` may be ignored. In the NPS prediction case, `sample_rate_per_class` seems to give a better result than using any combination of `balance_classes` and `class_sampling_factors` parameters.

## 8.4.7 Control Growth
Brieman (2001) suggested that the classifier, that is, decision trees in random forest need not be pruned. However, from implementation perspective, packages give options to limit the growth of the trees. The below parameters can be used to limit the tree growth.

### 1. `min_split_improvement`
This parameter can be used to reduce overfitting by restricting the growth of the tree. The value of this parameter signifies the minimum change in the squared error to split a node into two. The default value is set to 10^(−5). The optimal values for this parameter can be in the range of 10^(−10) to 10^(−3).

### 2. `max_depth`
This parameter is used for reduce overfitting. It is used to control the depth to which a tree can grow. A higher value for this parameter will lead to a more complex tree. If the value is set to 0, it will mean no limit to grow the tree (highly complex tree). The default is set to 20.

### 3. `min_rows`
This parameter specifies the minimum number of observations to be present in the leaf node. The default is set to 1 which may lead to overfitting issues.

## 8.4.9 Random Forest (h2o) – Search Criteria
In previous section, we created a list of values, `hyper_params`, for the three parameters from which we want to find the best combination of values. The values in `hyper_params` can be searched by adopting the `strategy = Cartesian` or `strategy = RandomDiscrete`.

### 1. Specifying search criteria
Specifying `search_criteria = list(strategy = "Cartesian")` will apply Cartesian strategy.

Cartesian will search for all combinations of hyper-parameters. However, RandomDiscrete may be needed in case of infrastructure limitation or if the number of combinations of hyper-parameters is too large. In case of RandomDiscrete strategy, there are three ways of randomly searching the space and specifying when to stop the search:

### 2. max number of models
`search_criteria = list(strategy = "RandomDiscrete", max_runtime_secs = 600, max_models = 100, stopping_metric = "AUTO", stopping_tolerance = 0.00001, stopping_rounds = 5, seed = 123456)`

### 3. max time
`search_criteria = list(strategy = "RandomDiscrete", max_models = 42, max_runtime_secs = 28800)`

### 4. metric-based early stopping
`search_criteria = list(strategy = "RandomDiscrete", stopping_metric = "AUC", stopping_tolerance = 0.00001, stopping_rounds = 5)`

We can apply early stopping once the validation logloss does not improve by at least 0.01% for five consecutive scoring events.

## 8.4.10 Random Forest – Grid Search
While using the `caret` package in [Chapters 6](#14_Chapter06.xhtml) and [7](#15_Chapter07.xhtml), we discussed `expand.grid()` method from the base package. The `expand.grid()` method helps create a data frame from all combinations of the supplied vectors, that is, `hyper_params`. The analogous method in h2o is `grid`. We will use the `grid` method of h2o and pass model parameters, search criteria, and list of hyper-parameters. Also pass the `train` and `validate` dataframe.

By default, the `balance_classes` parameter of `grid` method up-samples the cases. To apply down-sampling, let us calculate the proportions by which to down-sample. **[Table 8.5](#16_Chapter08.xhtml#tab8.5)** shows the number of cases in `NPS_CLASSIFICATION` in `train_h2f`.

**TABLE 8.5** | The number of cases in `NPS_CLASSIFICATION` in `train_h2f`

| `NPS_CLASSIFICATION` || Count |
| --- | --- |
| Detractor || 59 |
| --- | --- |
| Passive || 573 |
| Promoter || 709 |

In order to down-sample and make observations proportional to Detractor class:
1. Down-sample the Passive by 59/573 = 0.102 (approx.)
2. Down-sample the Promoter by 59/709 = 0.083 (approx.)

Thus `class_sampling_factors` in `grid` method may be set as `class_sampling_factors = c(1.0,0.102,0.083)`. The numbers are written according to the lexical order of the classes.

The other option is to set `sample_rate_per_class` in the `grid` method as:
`sample_rate_per_class = c(1.0,0.102,0.083)`. The numbers are written according to the lexical order of the classes.

While trying for the above two options for the multiclass classification problem, we found that `sample_rate_per_class` gives a better outcome compared to using `class_sampling_factors`.

Models with different combinations of hyper-parameters will be validated on the `validation_frame` and/or on cross-validation frame (`nfolds`) using the applicable metrics.

![](images/page302-01.png)

`h2o.grid` also has `parallelism` as a parameter, which can be used to define parallel processing while model training.
1. A value of 1 means sequential building and is the default for this parameter.
2. A value of 0 means adaptive parallelism, that is, the h2o package will decide how to utilize parallel processing.
3. A value greater than 1 will mean to build those many models in parallel.

![](images/page303-01.png)

We will use `parallelism` while building `gbm` and `xgboost` model. Note that the `grid` method also has parameters such as `calibrate_model` and `calibration_frame`. These are used to improve the performance with respect to probability estimation (platt scaling) of the ensemble models (`randomforest`, `gbm`, `xgboost`). However, currently it works in binary classification problem only.
