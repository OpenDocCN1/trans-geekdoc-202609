### Feature Engineering

One of the most important aspects of ML model building is to derive features not available as a part of raw data. In the `HR_Attrition` data, we can see that there are many features which are derived features. For example, `CURRENT_AGE` is derived based on the Current Date - Date of Birth. Similarly, features such as, `ZODIAC_SIGN`, `AGE_DURING_DOJ`, `TENURE`, `AVG_WEIGHTED_PERFORMANCE`, `WORKING_IN_NATIVE_PLACE` are derived features which may not be directly present as a part of the raw data. All these features are derived from raw data but not shown here due to the sensitivity (personally identifiable information) of some of the features. However, below are some features which can still be derived from the given features list of `raw_dt`:
**1.** `CHANGE_IN_CTC = (CTC_CURRENT_YEAR - CTC_PREVIOUS_YEAR)/CTC_PREVIOUS_YEAR`
**2.** `AGE_DIFFERENCE = RM_AGE - EMPLOYEE_AGE_DURING_DOJ`
**3.** `EMPLOYEE_AGED_OVER_MANAGER = ifelse((RM_AGE - EMPLOYEE_AGE_DURING_DOJ) < 0, "Yes", "No")`
**4.** `LEAVES_PREVIOUS_YEAR = PL2014+CL2014+SL2014`
**5.** `LEAVES_CURRENT_YEAR = PL2015+CL2015+SL2015`
**6.** `LEAVE_OVER_LAST_YEAR = LEAVES_CURRENT_YEAR/LEAVES_PREVIOUS_YEAR`
**7.** `FEMALE_TO_MALE_REPORTEE = RM_REPORTEE_FEMALE/RM_REPORTEE_MALE`

As discussed in [Chapter 2](#09_Chapter01.xhtml), we will use `data.table`’s `:=` operator to add/update/delete a column so as to have these features available as a part of the original `raw_dt`. We will also remove `EMPLOYEE_CODE` from the feature list before performing further analysis.
