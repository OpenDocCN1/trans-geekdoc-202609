It is very rare to use the same number of points to approximate the shape of different geographical objects. Some geographical objects may be approximated using fewer than ten points, while others may use a few hundred or more points. Therefore, it is difficult to define a fixed number of columns for a table to store coordinates. In addition, the table structure is too restrictive for many geographical features that have complex structures, such as a polygon with island polygons inside. Decomposing a complex geographical object into simple geometric objects that can be stored in tables will lead to many relations and unnatural joins, which, as mentioned earlier, is inefficient. Due to these weaknesses of a relational database, GIS systems generally store and manage spatial data in **georelational databases**, in which the attribute component of spatial data is stored in a conventional relational database managed by an RDBMS, and the locational component (describing feature geometry) of spatial data is stored in separate files based on one of the spatial data structures discussed in the previous section and managed by specialised GIS data management software (Yeung and Hall 2007). In a georelational database, spatial data are conceptualised as a series of independent data layers covering the same geographical space (Figure 2.30). Each layer represents a single theme of a particular feature class, such as soil, land use, geology and vegetation. Each layer is a data-set, consisting of files storing geometric data defining the positions and shapes of geographical features, and relational tables containing attribute data associated with the geographical features. When the spatial data are structured using a vector data structure, each feature is assigned a system-generated unique ID number called a feature ID, or FID. The attribute table associated with a vector data layer is called the feature attribute table. The FID is the primary key of a layer's feature attribute table, which is used internally by the GIS system to link a feature's locational data with its attributes. When the spatial data are structured using a raster data structure, the cell data are stored separately from the attribute data associated with each unique cell value, which are stored in a table, often called the value attribute table. A value attribute table uses the unique cell value as the primary key to link it with the associated raster data layer. ArcInfo coverages, ESRI shapefiles and ESRI grids are all managed with the georelational database model in ArcGIS. Many existing spatial databases are georelational databases. When spatial data are stored in an object-relational database, feature attributes are stored in columns as traditional tabular attributes, while feature geometries represented as either vector features or rasters are stored using an extended spatial type. The ESRI Geodatabase is an example of object-relational databases. In a geodatabase, spatial datasets are stored using relational tables and feature geometries are stored in fields along with traditional attributes. Three primary types of datasets that can be stored and managed in a geodatabase include feature classes, raster datasets and attribute tables. A feature class is stored as a table, in which each row represents a feature – a spatial object with a geometric shape. A feature class table has one distinguished field of type Geometry, referred to as the Shape field. This field stores the geometry for each feature in the table. The type of shape of a feature is defined by the feature class, which could be Point, Multipoints (features that are composed of more than one point), Polyline or Polygon. Figure 2.32 shows a polygon feature class table for a land cover layer. The Shape field in the table holds the polygon geometry for each feature. The value Polygon indicates that the field contains the coordinates and the geometry that defines one polygon feature in each row.

A raster dataset refers to an image (such as an orthoimage) or raster (such as a DEM) organised into one or more bands. Each band consists of a matrix of pixels or cells. A raster has a single band. An image may have one or more bands. In a geodatabase, a raster dataset is typically divided into small tiles, referred to as blocks. The typical size of a block is about 128 rows by 128 columns or 256 rows by 256 columns. These blocks are stored in a table for each image or raster, which is called a block table. Each row in the block table represents a block. Figure 2.33 shows an example of a block table. The field Block Data in the table stores the block's tile of the raster. It has a BLOB data type. The block structure of a raster dataset allows only the blocks for an extent to be retrieved when they are needed, instead of the entire raster layer or image. In addition, it facilitates the building of an image or raster pyramid. A raster pyramid is a collection of the same raster or image with different resolutions. It is made by repeatedly subsampling the original raster or image dataset usually by a factor of 2 (reducing the resolution to half), as illustrated in Figure 2.34. A pyramid may contain many subsampled layers. It enables the rapid display of image or raster data by retrieving only the data at a specified resolution that is required for the display.
