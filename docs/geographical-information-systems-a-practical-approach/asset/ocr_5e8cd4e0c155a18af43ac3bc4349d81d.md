# File Geodatabases

A file geodatabase is a collection of spatial datasets of various types (feature classes, topologies, networks, tables, raster datasets and so on) held in a file folder structured based on the object-relational data model and managed by the computer's file management system and ArcGIS's own data management system. Each dataset is stored as a separate file on disk, which can contain more than 300 million features and be up to 1 TB (terabyte) in size by default, but this can be changed to 4 or 256 TB using a configuration keyword. It uses a more efficient data structure than shapefiles and coverages in terms of performance and storage. File geodatabases are designed for a single user and recommended for GIS applications involving very large datasets and requiring fast performance. A file geodatabase is named with a .gdb extension.

An example of a file geodatabase called FileDB is shown in Figure 2.36, which contains five feature datasets, each consisting of a group of feature classes with the common georeferencing system. For example, Hydrology is a geodatabase feature dataset. It consists of three feature classes: gauges (point feature class), lakes (polygon feature class) and rivers (line feature class). Icons are used to differentiate different types of feature classes in Catalog, and actual data files are not visible in the folder-tree view.

# Mobile Geodatabases

A mobile geodatabase is based on the object-relational data model with the ESRI ST_Geometry data type (providing storage for point, line and polygon objects that represent geographical features) but stored and managed using SQLite – a cross-platform RDBMS that can run on all platforms, including macOS, Windows, mobile phones, etc. All the datasets in a mobile geodatabase are held in a single file with a .geodatabase extension and can be accessed through SQL statements.
