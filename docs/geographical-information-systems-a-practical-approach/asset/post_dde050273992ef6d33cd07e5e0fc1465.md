Time in the context of non-temporal cartographic animation is presentation time (time to show the frames), not real time, as in temporal cartographic animation.

Animation can be used as an exploratory tool to understand changes, trends and processes, detect similarities or differences in distribution within a series of maps and gain insights into spatial relations. For example, it has been successfully used in visualisation of hydrological temporal data and processes (Fuhrmann 2002), simulation of storm surge flooding (Zhang et al. 2006) and animation of climate change (Weber and Buttenfield 1993). More recently, cartographic animation, 3D visualisation and virtual globes have been combined to support the presentation, exploration and dissemination of spatial data and communication of findings from scientific research. ## 4.6 Online Mapping

Online mapping is the process of making and publishing maps on the internet, more specifically in the web. It makes spatial data more accessible and up-to-date. An online map or web map, just like any web page, can be accessed by anyone at any time from any device that has an internet browser or map viewer and an internet connection. It is mostly interactive, which not only provides cartographic functionality, such as panning and zooming, but also seamlessly integrates with web functionality to provide links and access to other relevant information on the web (including other internet maps, texts, graphs, videos, images, sounds, etc.). Moreover, online maps make it possible to supply users with really up-to-date or real-time spatial information. Google Maps and Bing Maps are the most popular online maps providing functions for map browsing, place finding and route planning for various transport modes, with up-to-date street maps, satellite imagery, aerial photography and real-time information on traffic conditions. Nowadays, online maps have become an important means of spatial data sharing, real-time information delivery, online spatial query and reporting, spatial data searching, public participation and collaborative mapping.

### Box 4.3 Application of Spatial Visualisation to Communicate Climate Change Information to Local Farming Communities in Victoria, Australia

#### CASE STUDY

Climate change is the greatest global challenge the human race has ever faced. Protecting people and ecosystems from unavoidable changes in climate to whatever degree possible requires significant public engagement in the issue so that difficult decisions can be made by members of the public and policymakers. However, climate change has predominantly been a highly complex and abstract discussion of science, policy and the economic issues. Making climate change information relevant, interesting and engaging for the public is an ongoing challenge.

The former Victorian Department of Primary Industries in Australia investigated the use of spatial visualisation to communicate climate change information to the community under the Victorian Climate Change Adaptation Program (VCCAP). As part of a VCCAP visualisation project, they developed Virtual DemoDairy. DemoDairy, located near Terang, Victoria, is a research demonstration dairy farm with more than 300 members from the south-west region of Victoria. It supports dairy-focused research and provides applied demonstration and educational activities to members. Virtual DemoDairy aims to communicate some information on the long-term impacts of climate change at both the regional and local scale, in the south-western region of Victoria, and to make it accessible to DemoDairy managers and stakeholders. It uses Google Earth, a virtual globe, as a development platform, which provides an interactive environment to visually explore and interact with scientific data on climate change. The multi-level resolution remote sensing imagery and terrain data contained in Google Earth allow users to contextualise data within their own catchment or farming area.

At the regional scale, Virtual DemoDairy uses cartographic animation to show the projected changes in temperature and rainfall for the whole of Victoria from a baseline year 2000 to year 2050. Figure 4.35 shows two frames from the animation representing the predicted mean annual temperatures in Victoria in 2020 and 2050. The time-step slide bar at the upper-left corner of the view allows users to animate the temperature surfaces. The temperature and rainfall surfaces (rasters) of each year were created in ArcGIS based on monthly climate records and climate change projections (using the CSIRO Mark 3.5 climate change model). They were then converted to KML for display in Google Earth. The KML time span function was used to automatically specify the dates and duration for each temperature or rainfall surface to display.

### 4.6.1 Technical Components of Online Mapping

Online mapping utilises the distributed infrastructure of the internet, which is a global system of interconnected computer networks that uses the internet protocol suite (TCP/IP) to communicate between networks and devices. The protocol most commonly used on the web is known as HTTP (Hypertext Transfer Protocol). It enables users to access web pages by standardising communications and data transfer between the internet’s servers and clients (commonly web browsers). Most web pages are created using Hypertext Markup Language (HTML), which describes the structure of web pages using elements or tags and displays the content of these pages through a web browser. To access one of these pages, a user and their client device supply a universal identifier to the web server via a browser. This identifier may be a uniform resource locator (URL) or uniform resource identifier (URI) and is unique to each web page. A collection of web pages belonging to a URL is called a website. The most basic method to publish online maps is to create a website that stores a set of HTML pages that contain a collection of maps in the form of GIF or JPEG images. Practically, an online map is created in HTML or another markup language on the fly in response to a user query (Jones and Purves 2008).

The system architecture of online mapping is similar to the client–server architecture of distributed GIS shown in Figure 1.11. Its server-side components typically include a web server, a map server, databases and/or file servers (Figure 4.37). All these components can be located on one computer or distributed across several computers.

A web server is a computer software and underlying hardware that uses HTTP or its secure variant, HTTPS, to respond to client requests made over the web. On the hardware side, a web server connects to the internet so that it can exchange data or files between other devices that are likewise connected. Web server software installed on the server hardware controls how clients access hosted data or files and how the server responds to different service requests. The main job of a web server is to display website content through storing, processing and delivering web pages to users. It is also a place where web application code (such as HTML and JavaScript files) for online maps resides.

A map server is a specialised software application as part of the web server model, which translates a request for a map or map service from clients into a query into data from one or more data sources. It may also include functions for map authorisation and some aspects of spatial data processing and analysis associated with the requested data. A map server typically uses Web Map Services (WMS), Web Feature Services (WFS), Web Coverage Services (WCS) and other protocols for serving and exchanging spatial data over the internet.

The WMS protocol provides an HTTP interface for requesting georeferenced map images (for example, TIFF, JPEG and PNG) from one or more distributed spatial databases (OGC 2006). A WMS request defines the geographical layer(s) and area of interest, and the response to the request is one or more map images to be displayed in a browser application. Features displayed in the map images can be queried to view descriptive information.
