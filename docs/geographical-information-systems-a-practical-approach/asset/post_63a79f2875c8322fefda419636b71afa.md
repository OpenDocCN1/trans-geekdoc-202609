In addition to feature classes, raster datasets and attribute tables, a geodatabase can also store network datasets, geometric networks, topologies, terrains, parcel fabrics (connected parcel features or parcel networks) and many others and use SQL to create, modify and query tables and their data elements (Allen 2019). Moreover, a geodatabase allows users to build spatial datasets with topological structures and add behaviour to them with no programming required. Figure 2.35 shows the general structure of an object-relational database, in which spatial data are stored using tables and managed by the object-relational database management system (ORDBMS).

SQL has been extended to incorporate spatial types and functions (Shekhar and Chawla 2003). Therefore, the contents of relational tables containing feature geometries, when stored as an SQL spatial type, can be accessed through SQL. However, different GIS systems may employ specific database management systems, which may implement SQL differently, and may have different definitions of spatial data types and different storage structures and access methods.

## Georelational Databases

A georelational database in ArcGIS is a workspace containing ArcInfo coverage (including TIN) and grid files, or a collection of shapefiles held in a file system folder. A shapefile contains a single feature class, and a coverage may contain multiple feature classes. All the files are managed by the computer's file management system, but some file management functions, including deleting, renaming, copying, pasting and creating a shapefile or coverage, should be conducted in Catalog. The locational or geometric data and attribute tables of a shapefile or a coverage or a grid are linked, related or joined in ArcGIS via its data management software tools.

Georelational databases were conventional spatial databases in ArcGIS and have served the purposes of many GIS applications very well where spatial data management is not a central task.

Figure 2.36 shows an example georelational database, named Shapefiles. It contains three layers: landslides, sampledArea and transect. Only .shp files appear in Catalog, and other files associated with each shapefile, as listed in Box 2.1, are not shown. Shapefiles of different feature classes are represented with different icons.

## File Geodatabases

A file geodatabase is a collection of spatial datasets of various types (feature classes, topologies, networks, tables, raster datasets and so on) held in a file folder structured based on the object-relational data model and managed by the computer's file management system and ArcGIS's own data management system. Each dataset is stored as a separate file on disk, which can contain more than 300 million features and be up to 1 TB (terabyte) in size by default, but this can be changed to 4 or 256 TB using a configuration keyword. It uses a more efficient data structure than shapefiles and coverages in terms of performance and storage. File geodatabases are designed for a single user and recommended for GIS applications involving very large datasets and requiring fast performance. A file geodatabase is named with a .gdb extension.

An example of a file geodatabase called FileDB is shown in Figure 2.36, which contains five feature datasets, each consisting of a group of feature classes with the common georeferencing system. For example, Hydrology is a geodatabase feature dataset. It consists of three feature classes: gauges (point feature class), lakes (polygon feature class) and rivers (line feature class). Icons are used to differentiate different types of feature classes in Catalog, and actual data files are not visible in the folder-tree view.

## Mobile Geodatabases

A mobile geodatabase is based on the object-relational data model with the ESRI ST_Geometry data type (providing storage for point, line and polygon objects that represent geographical features) but stored and managed using SQLite – a cross-platform RDBMS that can run on all platforms, including macOS, Windows, mobile phones, etc. All the datasets in a mobile geodatabase are held in a single file with a .geodatabase extension and can be accessed through SQL statements. It can contain up to 2 TB of data. There is no limit for the table or feature class size within the 2 TB database limit. Because of its single-file nature, a mobile geodatabase can be easily copied, moved, sent by email or written to a USB device, which makes the database extremely portable, thus allows a very efficient data exchange.

A mobile geodatabase has a logical name called main, reserved for the primary database by SQLite, regardless of the geodatabase file name. As shown in Figure 2.36, the logical name, main, is appended to the name of each feature class contained in the mobile geodatabase MobileDB.geodatabase. The database holds three feature classes: parcels, road_junctions and roads. Mobile geodatabases are intended for use by a single user or app at a time.

## Enterprise Geodatabases

Enterprise geodatabases are large, multi-user spatial databases. They are based on the geodatabase object-relational data model, stored and managed using an RDBMS, such as Oracle, Microsoft SQL Server, PostgreSQL, SAP HANA or IBM DB2. They can be used to manage extremely large spatial datasets, primarily used for data-centric spatial database applications in departmental and enterprise settings. They take advantage of the underlying RDBMS architecture to provide high performance, provide a multi-user access and editing environment with access control and support spatial data management for scalability, reliability, security, backup and data integrity. In addition to supporting many users with concurrent access to the same data, enterprise geodatabases can be integrated with an organisation’s existing IT systems.

A GIS system may also support different types of databases. For example, the ESRI Geodatabase can be stored in IBM DB2, IBM Informix, Oracle, Microsoft Access, Microsoft SQL Server, SQLite and PostgreSQL relational database management systems, or in a folder of files, such as a file geodatabase. Selecting the appropriate type of databases to work with will depend on the specific requirements of the GIS project and/or application. Box 2.4 describes four types of spatial databases in ArcGIS.
