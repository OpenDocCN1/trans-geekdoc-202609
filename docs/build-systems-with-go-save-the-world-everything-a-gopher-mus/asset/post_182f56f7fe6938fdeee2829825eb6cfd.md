## 5.2.1 Setting values

Using reflect.value we can set values on run-time. Every value has methods SetInt32, SetFloat32, SetString, etc. that set the field to a int32, float32, string, etc. value. Example 5.8 sets the string fields from struct to uppercase.

## Example 5.8: Setting values using reflection.

```go
package main

import (
	"fmt"
	"reflect"
	"strings"
)

type T struct {
	A string
	B int32
	C string
}

func main() {
	t := T{"Hello", "42"}
	fmt.Println(t)

	valueT := reflect.ValueOf(&t).Elem()
	for i:=0;i<valueT.NumField();i++ {
		f := valueT.Field(i)
		if f.Kind() == reflect.String {
			current := f.String()
			f.SetString(strings.ToUpper(current))
		}
	}
	fmt.Println(valueT)
}
```

## 5.3 CREATING FUNCTIONS ON THE FLY

In previous sections, we have explored how to inspect fields and modify values. Additionally, the reflect package permits the creation of new entities as functions on the fly. This offers certain functionalities available in other programming languages. For example, the lack of generics in Go imposes some limitations although there is already a proposal at the moment of this writing.

Assume we want to write a function that generalizes the add operation. This function must sum numbers (integers and floats) and append strings. Given the current language definition, this is not possible. Check the code below. Does not permit any kind of function overload. Every function must have a unique name. Similarly, the lack of generics makes it impossible to reuse the same code using the add operator (-) defined for every type.

```go
func Sum(a int, b int) int {..}
```

```go
func Sum(a float32, b float32) float32 {..} // Not unique.
```

```go
func Sum(a string, b string) string {..} // Not unique.
```

One interesting workaround is to use the reflect.MakeFunction to build your own functions with different signatures. Example 5.10 builds an add function in BuildAdder with two arguments of the same type and one output. The MakeFunction receives a pointer to a function of the same type and the MakeFunction receives a function type and a variable number of Value types inside an array, and returns an array of Value. We fill this function with a switch statement that implements the addition between the two arguments according to its type. Finally, we set this function to the original function (fn.Set(newF)).

## Example 5.10: Using reflect.MakeFunction to create functions on run-time.

```go
package main

import (
    "fmt"
    "reflect"
)

func BuildAdder(i interface{}) {
    fn := reflect.ValueOf(i).Elem()
    newF := reflect.MakeFunction(fn.Type(), func(in []reflect.Value) []reflect.Value {
        if len(in) > 2 {
            return []reflect.Value{in[2].Value()}
        }
        a, b := in[0], in[1]
        if a.Kind() != b.Kind() {
            return []reflect.Value{reflect.ValueOf(nil)}
        }
        var result reflect.Value
        switch a.Kind() {
            case reflect.Int8, reflect.Int32, reflect.Int64:
                result = reflect.ValueOf(a.Int() + b.Int())
            case reflect.Uint, reflect.Uint8, reflect.Uint16, reflect.Uint32, reflect.Uint64:
                result = reflect.ValueOf(a.Uint() + b.Uint())
            case reflect.Float32, reflect.Float64:
                result = reflect.ValueOf(a.Float() + b.Float())
            case reflect.String:
                result = reflect.ValueOf(a.String() + b.String())
            default:
                result = reflect.ValueOf(interface{}(nil))
        }
        return []reflect.Value{result}
    })

    fn.Set(newF)
}

var intAdder func(int64, int64) int
var floatAdder func(float64, float64)
var strAdder func(string, string) string

func main() {
    BuildAdder(&intAdder)
    BuildAdder(&floatAdder)
    BuildAdder(&strAdder)

    fmt.Println(intAdder(1, 2))
    fmt.Println(floatAdder(1.0, 2.0))
    fmt.Println(strAdder("hello", "world"))
}
```

## 5.4 TAGS

Go provides powerful and versatile structs using tags. These tags can be interpreted on run-time which adds valuable information that can be employed for different purposes.

```go
type User struct {
    ID       string `tag:"value1"`
    Email    string `tag:"value2"`
    Password string `tag:"value"`
    Others   string `tag:"something b"`
}
```

The struct declares four fields. Every tag becomes an attribute of the field that can be accessed. Go permits tags to declare string literals like "something b". However, by convention, tags follow a key-value schema separated by spaces. For example: tag:"value1" declares tagA and value1 respectively. The type returned by TypeOf has functions to check the name, number of fields, size, etc. Information is stored in StructField that can be accessed using Field() and FieldByName(). For every field, tags are stored in StructTag.

## Example 5.11: Access field tags using reflect

```go
package main

import (
    "fmt"
    "reflect"
)

type User struct {
    ID       string `tag:"value1"`
    Email    string `tag:"value2"`
    Password string `tag:"value"`
    Others   string `tag:"something b"`
}

func main() {
    t := reflect.TypeOf(User{})

    fieldID := t.FieldByName("ID")
    fmt.Printf("Tag: %s\n", fieldID.Tag.Get("tag"))

    fieldEmail := t.FieldByName("Email")
    vEmail := fieldEmail.Tag.Get("tag")
    fmt.Printf("Email: %s\n", vEmail)

    fieldPassword := t.FieldByName("Password")
    fmt.Printf("Password: %s\n", fieldPassword.Tag.Get("tag"))
}
```

By convention tags must be declared like key:"value". That blank spaces do not follow the convention: key:"value is not a valid declaration.

## 5.5 THE THREE LAWS OF REFLECTION

At this point, we have explored some actions we can carry out using reflection. Reflection is an extremely powerful tool although can become extremely convoluted. Rob Pike enumerated the three laws of reflection that govern Go. We reproduce and explain these three laws in this Section.

### 5.5.1 The first law of reflection

Reflection goes from interface value to reflection object.

We have explained that function reflect.TypeOf inspects any type. The signature of this function receives an empty interface by argument (i interface{}). However, we have already seen any type returned by this function like in the code below.

```go
var a int32 = 42
fmt.Println(reflect.TypeOf(a)) // Prints int32
```

How is this possible? Value a is stored into an empty interface before TypeOf is called. A similar process is done with Value. The empty interface stores the underlying type and points to the corresponding value. That is why we can resolve the type or value.

### 5.5.2 The second law of reflection

Reflection goes from object to interface value.

If the first line defines how we go from the interface to the value, the second law defines the inverse. For a value type we can get the original interface using func (v Value) Interface() interface(). The code below will print 42.

```go
var a int32 = 42
v := reflect.ValueOf(a)
fmt.Println(v) // Prints 42
fmt.Println(v.Interface()) // Prints 42
```

What is the difference between v and v.Interface() if both outputs are the same? In the first case, we print a value. In the second case, we print the int32 variable. The reason why the first case is that println states that in the case of reflect.Value types the output is the concrete value that this type holds. Then, why v.Interface()? Simply because v is not the real value although some operations Print can reach it.

### 5.5.3 The third law of reflection

To modify an object, the value must be settable.

The third law may sound evident: you cannot set something it is not settable. However, this is difficult to see. The example below tries to set an integer.

```go
var a int32 = 42
v := reflect.ValueOf(a)
v.SetInt(16) // <- panic
```

The last instruction will panic. This is due to the settability of v. The value contained by v is not the original, it is a copy. Notice that reflect.ValueOf(a) uses a copy of a. The value does not point to the original place where the 42 is stored, we need a pointer.
