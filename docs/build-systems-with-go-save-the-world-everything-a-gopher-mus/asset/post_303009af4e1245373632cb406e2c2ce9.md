
```go
	fmt.Printf("Consumer %d done\n", id)
}

func main() {
	rand.Seed(42)

	ch := make(chan int, 10)
	var wg sync.WaitGroup

	wg.Add(3)

	go generator(ch, &wg)
	go consumer(1, 400, &wg)

```

Similar behaviour can be obtained using channels. However, this approach is highly recommended in scenarios where several goroutines block the execution flow and their termination can be determined by the goroutines themselves.

## 6.5 TIMERS, TICKERS, AND TIMEOUTS

In concurrent scenarios time management becomes really important. During the execution several events may occur with different periods or timelines. For single events to occur in the future the time package offers the Timer type. A Timer has a channel c that triggers a signal after a given time. Similarly, the ticker type triggers a signal for channel c a given period.

Example 6.13: Timer and Ticker.

```go
package main
import (
	"fmt"
	"time"
)

func worker(x *int) {
	for {
		time.Sleep(time.Millisecond * 500)
		*x = *x + 1
	}
}

func main() {
	timer := time.NewTimer(time.Second * 5)
	ticker := time.NewTicker(time.Second)

	x := 0
	go worker(&x)

	for {
		select {
		case <-timer.C:
			fmt.Printf("timer -> %d\n", x)
		case <-ticker.C:
			fmt.Printf("ticker -> %d\n", x)
		}
		if x != 10 {
			break
		}
	}
}
```

| ticker -> 2 |
| ticker -> 3 |
| ticker -> 5 |
| ticker -> 7 |
| ticker -> 9 |
| ticker -> 11 |

Example 6.13, checks the value of x over time using a Timer and a Ticker. The worker increases x by one every 500 milliseconds. The select statement can be used here to react when timer and ticker send an event. ticker will wake up every second x to be increased by two. Notice that worker sleeps for half second in every iteration. For timer there will be the single operation after five seconds. Notice, that worker could be implemented using a Ticker instead of time.Sleep.

## Example 6.14: Timer and Ticker management.

```go
package main

import (
	"fmt"
	"time"
)

func reaction(t *time.Ticker) {
	for {
		select {
		case x := <-t.C:
			fmt.Println("quick", x)
		}
	}
}

func slowReaction(t *time.Timer) {
	select {
	case x := <-t.C:
		fmt.Println("slow", x)
	}
}

func main() {
	quick := time.NewTicker(time.Second)
	slow := time.NewTicker(time.Second * 5)
	stopper := time.NewTimer(time.Second * 4)
	go reaction(quick)
	go slowReaction(slow)

	<-stopper.C

	quick.Stop()

	stopped := slow.Stop()
	fmt.Println("Stopped before the event", stopped)
}
```

Timers and tickers can be managed using Stop() and Reset(). Invoking the Stop method closes the channel and terminates the triggering of new events. In case of timers, the method returns true if the invocation was triggered before the event was triggered.

In Example 6.14 we define events, using a ticker every second, and slow using a Timer triggered after 5 seconds. The third timer is set to 4 seconds. When the stop timer is reached we stop quick and slow. Observe that quick.Stop has returned no value. In the case of slow.Stop, true value is returned as the timer was not triggered.

## 6.6 CONTEXT

Working with APIs and processes requires additional logic such as cancellations, timeouts and deadlines. If we send a request to an API, we will wait for completion. Afterwards, we can assume the request expired. The context package from Go offers constructions to deal with these situations. The Context interface defines elements of a common context in Go:

```go
type Context interface {
	Deadline() (time.Time, bool)
	Done() <-chan struct{}
	Err() error
	Value(key interface{}) interface{}
}
```

The Deadline() method returns the deadline for the context and false if not expired. The Done() method returns a channel that is closed when the operations in the context are completed. Finally, Value() stores key-value pairs that belong to the context. A context can be built using an empty context (context.Background()) or a previously defined context. Go provides four types of contexts with their corresponding initialization functions: WithCancel(), WithTimeout(), WithDeadline(), and WithValue().

### 6.6.1 WithCancel

The context.WithCancel() returns a context and a CancelFunc. This type forces the context to be done. In Example 6.15, setter is simultaneously in several goroutines to increase a shared counter variable. The cancel function is invoked informing about its termination. All the goroutines receive the message by checking the Done() method.

## Example 6.15: Context WithCancel

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"time"
)

func setter(id int, c *int32, ctx context.Context) {
	t := time.NewTicker(time.Millisecond * 300)
	for {
		select {
		case <-ctx.Done():
			fmt.Println("Done", id)
			return
		case <-t.C:
			atomic.AddInt32(c, 1)
		}
	}
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())

	var c int32 = 0
	for i := 0; i < 5; i++ {
		go setter(i, &c)
	}

	time.Sleep(time.Second * 1)
	fmt.Println("Final check: ", c)
	cancel()
}
```

| Final check: 15 |
| Done 1 |
| Done 3 |
| Done 2 |
| Done 4 |
Normally, the cancel function is executed using defer to ensure that the context is terminated.

### 6.6.2 WithTimeout

Timeouts are a common approach to avoid allocating resources for long time. context.WithTimeout function receives a time.Duration argument setting how much time to wait until the context is done. Example 6.16 executes a goroutine that takes incrementally longer to finish. The select statement blocks the execution until we receive a new number or the context is done. Observe that in the case the context reaches the timeout, Err() method is filled with the corresponding message.

## Example 6.16: Context Timeout

```go
package main

import (
	"context"
	"time"
)

func work(i int, info chan int) {
	t := time.Duration(i*100) * time.Millisecond
	time.Sleep(t)
	info <- i
}

func main() {
	d := time.Millisecond * 300
	ch := make(chan int)
	i := 0
	for {
		ctx, cancel := context.WithTimeout(context.Background(), d)
		work(i, ch)
		select {
		case x := <-ch:
			fmt.Println("Received", x)
		case <-ctx.Done():
			fmt.Println("Done!")
		}
		if ctx.Err() != nil {
			fmt.Println(ctx.Err())
			return
		}
		cancel()
		i++
	}
}
```

| Received 0 |
| Received 1 |
| Received 2 |
| Received 3 |
| Done! |
| context deadline exceeded |

> When working with contexts inside loops, cancel functions should not be deferred. Remember that defer executes when the function returns, therefore all the resources allocated not released until then. If there is a number of contexts declared inside a loop

```go
for {
    ctx, cancel = context.WithCancel(context.Background())
    // defer cancel() -> release when the function returns

    cancel()
}
```

### 6.6.3 WithDeadline

Similar to a timeout, kind of context has an absolute termination time set. When the deadline is reached, the context is finished. 6.17 uses various goroutines to modify a shared variable. The context is set to expire after three seconds. Notice that this is similar to use a context with a timeout. We block the execution until the context is done (ctx.Done()). From the output, we can observe how the goroutines are informed about the context termination. Not all messages are printed because the program terminates before the goroutines have time to print the message.

## Example 6.17: Context WithDeadline.

```go
package main

import (
	"context"
	"fmt"
	"sync/atomic"
	"time"
)

func accum(c *uint32, ctx context.Context) {
	t := time.NewTicker(time.Millisecond * 250)
	for {
		select {
			case <-t.C:
				atomic.AddUint32(c, 1)
			case <-ctx.Done():
				fmt.Println("Done context")
				return
		}
	}
}

func main() {
	d := time.Now().Add(time.Second * 3)
	ctx, cancel := context.WithDeadline(context.Background(), d)
	defer cancel()

	var counter uint32 = 0

	for i := 0; i < 5; i++ {
		go accum(&counter, ctx)
	}
}
```
