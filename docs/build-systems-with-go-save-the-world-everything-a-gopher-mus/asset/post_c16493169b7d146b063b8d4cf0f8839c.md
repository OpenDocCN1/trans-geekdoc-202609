The main.go file is minimal and only executes the root command. Every command file must contain the logic required to execute this command. The logic of the program, library, framework, etc. must not be coupled to these commands. Cobra commands must only be used to capture the required information to trigger actions and must not be part of the logic of your program.

As point of clarification, the examples in this Chapter have been condensed into single files that contain all the logic. Notice that these examples are focused on demonstrating CLI concepts, not any additional logic. For demonstration purposes and better clarity, the examples contain all the commands in a single file. However, the concepts shown here can be easily adapted to the Cobra conventions.

## 17.2 ARGUMENTS AND FLAGS

Commands may require arguments to be executed. These arguments are passed to the Run field of every Command. In Example 17.2, the arguments received by the root command are printed.

> Example 17.2: Command receiving arguments

```go
package main

import (
    "fmt"
    "github.com/spf13/cobra"
    "os"
    "strings"
)

var RootCmd = &cobra.Command{
    Use: "main",
    Long: "Long message",
    Run: func(cmd *cobra.Command, args []string) {
14 fmt.Printf("%s\n",strings.Join(args," "))
15 }
16 
17 
18 func main() {
19 if err := RootCmd.Execute(); err != nil {
20 fmt.Fprintln(os.Stderr,err)
21 os.Exit(1)
22 }
23 }
```

```bash
>>> /main These are arguments
These,are,arguments
>>> /main 1 2 three four five

```

Observe that these arguments are not typed and there is no control over the number of arguments the program expects. Using flags, passing arguments that can be later used in the commands. The Example 17.3 expects a -msg flag with a message to be displayed with the program.

### Example 17.5: Command with required flags.

```go
package main

import (
	"fmt"
	"github.com/spf13/cobra"
	"os"
)

var RootCmd = &cobra.Command{
	Use: "main",
	Long: "Long message",
	Run: func(cmd *cobra.Command, args []string) {
		for i := 0; i < *Rep; i++ {
			fmt.Printf("[%s]\n", *Msg)
		}
	}
}

var Msg *string
var Rep *int

func init() {
	Msg = RootCmd.Flags().String("msg", "Save the world with Go!!!", "Message to show")
	Rep = RootCmd.Flags().Int("rep", 1, "Number of repetitions")
	RootCmd.MarkFlagRequired("msg")
}

func main() {
	if err := RootCmd.Execute(); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}
```

```bash
>>> ./main -msg Hello -rep 3
[Hello]
[Hello]
[Hello]
>>> ./main
Error: required flag "msg" not set
Usage:
main [flags]

Flags:
  -h, --help      help for main
  -msg string     Message to show (default "Save the world with Go!!!")
  -rep int         Number of repetitions (default 1)
```

### Example 17.6: Flag parsing using pointer variables.

```go
package main

import (
	"fmt"
	"github.com/spf13/cobra"
	"os"
)

type Config struct {
	Msg string
	Rep int
}

var cnfg Config

func RootCmd = &cobra.Command{
	Use: "main",
	Short: "short message",
	Run: func(cmd *cobra.Command, args []string) {
		for i := 0; i < cnfg.Rep; i++ {
			fmt.Printf("[%s]\n", cnfg.Msg)
		}
	}
}

func init() {
	RootCmd.Flags().StringVar(&cnfg.Msg, "msg", "Save the world with Go!!!", "Message to show")
	RootCmd.Flags().IntVar(&cnfg.Rep, "rep", 1, "Number of repetitions")
}

func main() {
	if err := RootCmd.Execute(); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}
```

## 17.3 COMMANDS

A CLI can contain one or several commands, and these commands can have subcommands. Generally, the root command is not intended to run any operation. It usually displays help and presents the actions that can be executed.

Example 17.7 two different messages: hello and bye. There are several ways to implement a CLI to do this. First, we have to consider that we have two possible actions that can be translated into A CLI with a syntax like ./say hello is easy to remember and clearly identifies the requested action. It would be possible to define the final action using flags. However, it would be difficult to remember how to operate this command (maybe ./say something -msg=?). On the other hand, ./say clearly lacks of arguments because we expect the prompt to say something.
