enum Category {
  DEVELOPER = 0;

  int32 id = 1;

The User message is renamed User_User.

## 14.5 TYPE ANY

Messages are allowed to fields with no defined type. Type Any may occur when the time of defining a field type the content of this field is not clear. The type Any is a byte serialization of any size with a URL that works as an identifier for the type in the field.

The proto file in Example 14.10 uses Any to define the info field to allocate any available data. This type is not available by default, and it has to be imported from the any.proto definition.

## Example 14.10: Utilization of type Any.

```proto
syntax = "proto3";
package user;

option go.package="github.com/juanmanuel-tirado/savetheworld/go/12_protocolbuffers/pb/example_05/user";

import "google/protobuf/any.proto";

message User {
  string user_id = 1;
  string email = 2;
  repeated google.protobuf.Any info = 3;
}
```

When translated into Go (Example 14.11), the type Any can be initialized with any array of bytes and a string as the URL. Notice that the anypb package has to be imported to have the Go definition of the Any type.

## Example 14.11: Utilization of messages from Example 14.10.

```go
package main
import (
  "fmt"
  "google.golang.org/protobuf/proto"
  "google.golang.org/protobuf/types/known/anypb"
  "github.com/juanmanuel-tirado/savetheworld/go/12_protocolbuffers/pb/example_05/user"
)

func main() {
  info := anypb.Any{Value:[]byte("John rules"), TypeUrl:"urltype"}
  userA := user.User(UserId: "John", Email: "john@gmail.com", Info: []*anypb.Any{&info})
  fmt.Println("To encode: %s", userA.String())
  encoded, err := proto.Marshal(&userA)
  if err != nil {
    panic(err)
  }
  recovered := user.User()
  err = proto.Unmarshal(encoded, &recovered)
  fmt.Println("Recovered: %s", recovered.String())
}
```

To encode: user_id:"John" email:"john@gmail.com" info:(type_url:"urltype" value:"John rules")
Recovered: user_id:"John" email:"john@gmail.com" info:(type_url:"urltype" value:"John rules")

## 14.6 ONEOF

If a message with fields can have only one field when sent, there is no point in sending all the fields. The type oneof forces messages to include only one field from a collection.

Example 14.12 allows the User message with a field indicating which type of user we have. A user can only be a developer or an operator. Additionally, developers have information about the language they use, while operators have information about the platform they administrate.

> 14.12: Utilization of type Oneof.

```proto
syntax = "proto3";
package user;

option go_package="github.com/juanmanuel-tirado/savetheorldwithgo/12_protocolbuffers/pb/example_06/user";
message Developer {
    string language = 1;
}

message Operator {
    string platform = 1;
}

message User {
    string user_id = 1;
    string email = 2;
    oneof typeof {
        Developer developer = 3;
        Operator operator = 4;
    }
}
```

When using oneof, PB defines nested types in the User message. In our case, types User_Developer and User_Operator must contain a Developer Or Operator respectively. This forces the message to only contain one of those forces as shown in Example 14.13.

## Example 14.13: Utilization of messages from Example 14.12.

```go
package main

import (
  "fmt"
  "google.golang.org/protobuf/proto"
  "github.com/juanmanuel-tirado/savetheworldwithgo/12_protocolbuffers/pb/example_06/user"
)

func main() {
  dev := &user.User_Developer{Language: "Go"}
  userA := user.User{UserId: "John", Email: "john@gmail.com", Typeof: dev}
  fmt.Printf("To encode: %s\n", userA.String())

  encoded, err := proto.Marshal(&userA)
  if err != nil {
    panic(err)
  }

  recovered := user.User{}
  err = proto.Unmarshal(encoded, &recovered)
  fmt.Printf("Recovered: %s\n", recovered.String())
}
```

## 14.7 MAPS

Messages can contain key-value pairs. Example 14.14 defines a map with string keys and UserList values. The map type is useful.

## Example 14.14: Utilization of maps.

```proto
syntax = "proto3";
package user;

option go_package="github.com/juanmanuel-tirado/savetheworldwithgo/12_protocolbuffers/pb/example_07/user";

message User {
  string user_id = 1;
  string email = 2;
}

message UserList {
  repeated User = 1;
}

message Teams {
  map<string, UserList> users = 1;
}
```

```go
package main

import (
  "fmt"
  "google.golang.org/protobuf/proto"
  "github.com/juanmanuel-tirado/savetheworldwithgo/12_protocolbuffers/pb/example_07/user"
)

func main() {
  user1 := user.User{UserId: "John", Email: "john@gmail.com"}
  user2 := user.User{UserId: "Mary", Email: "mary@gmail.com"}

  teams := map[string]*user.UserList{
    "teamA": &user.UserList{Users: []*user.User{&user1}},
    "teamB": &user.UserList{Users: []*user.User{&user2}},
  }

  teamsPB := &user.Teams{Users: teams}
  fmt.Printf("To encode: %s\n", teamsPB.String())

  encoded, err := proto.Marshal(teamsPB)
  if err != nil {
    panic(err)
  }

  recovered := user.Teams{}
  err = proto.Unmarshal(encoded, &recovered)
  fmt.Printf("Recovered: %s\n", recovered.String())
}
```

## 14.8 JSON

PB encodings are JSON compatible to marshal and unmarshal the systems that can use .proto file. If you check any PB generated .go file you can see that the structures have JSON tags (see Section 8.2), therefore they can be represented in a JSON format.

Example 14.16 uses the encodings/json package to marshal messages defined in Example 14.14. The applicability of JSON encoding is straight forward and does not require additional code. For a low-level detail explanation of JSON mappings in PB check the official documentation.
