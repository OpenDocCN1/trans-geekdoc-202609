As mentioned before, this would generate a lot of overhead. A possible solution is to store incoming messages and process them after the commit in a batch. This could even be done in a routine.

case *kafka.Message:

# 20.3 USING THE SEGMENTIO CLIENT

One of the drawbacks of the Kafka client is the fact that it is a wrapper of a C library. This can be an issue in certain platforms or for those projects where only Go is going to be available. The Segmentio28 Kafka client is fully written in Go and offers a complete implementation of consumers and producers with additional features such as compression or secure connections.

# 20.3.1 The Connection type

The Segmentio client uses a straight forward implementation based on a Connection instance. Connection can be instantiated indicating the Kafka host, the topic, and the partition. This connection offers all the methods required by consumers and producers.
