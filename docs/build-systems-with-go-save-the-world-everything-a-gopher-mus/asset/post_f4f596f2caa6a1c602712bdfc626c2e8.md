## 8.5 TAGS AND ENCODING

In Section 5.4, we explained how Go provides field tags to enrich structs and how reflection can be used. The encodings presented in this Chapter use tags to define how to marshal/unmarshal structs. Similarly, we can define our own tags to define new encoding. To show how we can leverage tags to define our encoding, let's assume we have a solution that works with structs. For some reason, this makes a strong distinction between lowercase and uppercase strings. Due to the nature of the problem, we have to constantly use functions strings.ToUpper and strings.ToLower. To eliminate redundant code, we decide to use encoding to automatically convert our strings to uppercase or lowercase.

```go
type User struct {
    UserID   string `pretty:"upper"`
    Email    string `pretty:"lower"`
    password string `pretty:"lower"`
}
```

```go
type Record struct {
    Name    string `pretty:"lower"`
    Surname string `pretty:"upper"`
    Age     int    `pretty:"other"`
}
```

For the structs above, we defined the tag key pretty, with values upper or lower respectively. Our encoding is defined as follows:

- Unexported fields such as password are ignored.
- Only lower and upper are valid tag values.
- Only strings are candidates to be encoded.
- Every field is identified by its name, and separated from the value by a colon.
- The fields are surrounded by brackets.
- No recursion or collections will be encoded.

With this definition we User("John", "John@Gmail.com", "admin") is encoded as {UserID:JOHN, Email:john@gmail.com} and Record("John", "Jonathan") AS (Name:john, Surname:JOHN). As you can see, the output only tags Following the common interface for encodings we have already seen in this Chapter, we can define a custom function for our encoding. 8.12 defines how to process the field tags from any interface to return our encoding. What we do is to iterate through the fields of the interface and encode them using the auxiliary function encodeField. The encoded fields are written to a buffer that contains the field name from the definition above, but not all situations are permitted and this may generate errors.

## 8.12: Marshal function for custom encoding using field tags (except).

```go
package main

import (
	"bytes"
	"encoding/json"
	"errors"
	"fmt"
	"reflect"
	"strings"
)

func Marshal(input interface{}) ([]byte, error) {
	var buffer bytes.Buffer
	t := reflect.TypeOf(input)
	v := reflect.ValueOf(input)

	buffer.Write("encoding:")
	for i := 0; i < t.NumField(); i++ {
		encodedField, err := encodeField(t.Field(i), v.Field(i))
		if err != nil {
			return nil, err
		}
		if len(encodedField) != 0 {
			if i > 0 && i <= t.NumField()-1 {
				buffer.WriteString(",")
			}
			buffer.WriteString(encodedField)
		}
	}
	buffer.WriteString(",")
	return buffer.Bytes(), nil
}

func encodeField(f reflect.StructField, v reflect.Value) (string, error) {
	if f.PkgPath() == "" {
		return "", nil
	}

	if f.Type.Kind() != reflect.String {
		return "", nil
	}

	tag, found := f.Tag.Lookup("pretty")
	if !found {
		return "", nil
	}

	result := f.Name + ":"
	var err error = nil
	switch tag {
	case "upper":
		result = result + strings.ToUpper(v.String())
	case "lower":
		result = result + strings.ToLower(v.String())
	default:
		err = errors.New("invalid tag value")
	}

	if err != nil {
		return "", err
	}

	return result, nil
}
```
