# 12.2 DOCUMENTATION

Documenting code is one of tasks developers always postpone, although we know it is a big mistake. A successful project must have good, up-to-date, and accessible documentation. Not only to ensure others understand the code but to make code maintainable. Go follows a minimalist approach to code documentation that can be summarized with the following rules:

+   - Comments before package declaration are considered to be a package comment.
- Every package should have a comment. With multiple files, the package comment only needs to be present in one file.
- Every exported name should have a comment.
- Every exported item begins with the name of the item describes.

Example 12.2 documents a piece of code following the mentioned conventions. It is important to note that every comment starts with the name of the commented item. For explanations, in particular, those containing the /* */ comment marks can be used.

# Example 12.2: Program documentation.

```
// Package example_01 contains a documentation example.
package example_01

import "fmt"

// Msg represents a message.
type Msg struct{
	Note // Note is the note to be sent with the message.
	ote string
}

// Send a message to a target destination.
func (m *Msg) Send(target string) {
	fmt.Printf("Send to %s\n", m.Note, target)
}

// Receive a message from a certain origin.
func (m *Msg) Receive(origin string) {
	fmt.Printf("Received from %s\n", m.Note, origin)
}
```

Documented code can be processed with the go doc tool executing go doc -all in the project folder.
