## 13.4 LINKING LIBRARIES

Accessing external libraries is one of the most powerful features of Cgo. This makes it possible to use a large variety of existing solutions. The preamble admits cgo directives to indicate the compiler what libraries and headers to use. Refer to the documentation for a complete list of available directives. If you are familiar with C compilation, you have probably recognized the flags to link libraries (-l) or other compilation flags (-DDEBUG=1).

```go
/*
#cgo LDFLAGS: -L/lib -lm
#cgo CFLAGS: -I/include -DDEBUG=1
*/
import "C"
```

An interesting example of what we can get with these directives is the utilization of functions implemented in other libraries. In Example 13.1, we use some mathematical functions implemented in C. We link the standard libraries using #cgo LDFLAGS:-lm. Remember following the compiler notation, the library to be linked by -l is libm. If no alternative path is given with -L, the default path is assumed. math.h headers expose the signature of all functions and constants from the library. Finally, we can call any function defined in math.h. In the example, we compute logarithms, sines, and cosines just to show some options.

## Example 13.1: Go executing functions from C library.

```go
package main

/*
#cgo LDFLAGS:-lm
#include <math.h>
*/
import "C"
import "fmt"

func main() {
	fmt.Printf("Log PI: %f\n", C.Log(C.M_PI))
	fmt.Printf("Sine PI: %f\n", C.Sin(C.M_PI))
	fmt.Printf("Cosine PI: %f\n", C.Cos(C.M_PI))
}
```

## 13.5 CALLING FUNCTIONS FROM C

We have explored how to pass arguments between Go and C. From the previous examples, we can conclude that Go easily executes C functions. One remaining question is how Go functions can be called from C. This situation differs from calling functions from Go. Check the following example.

## Example 13.2: Incorrect definition of Go function to be called from C.

```go
/*
#include <stdio.h>
void CFunction() {
	printf("CFunction will call goFunction\n");
	goFunction();
}
*/
import "C"
import "fmt"

func main() {
	C.CFunction()
}

func goFunction() {
	fmt.Println("goFunction was called")
}
```

This code will not work because goFunction is not exposed to C. This can be fixed with the reserved word export followed by the function name just before the function. This makes the compiler copy the function definition to the c_export.h header. Unfortunately, there is a restriction that forces us to not include any function definition in the C preamble. Functions must be defined in a separate file or using function modifiers as we see. This is because functions defined in the preamble are also copied to C headers and this results in the same function defined twice which triggers a linking error.

Considering these restrictions we can set our code to correctly expose functions to be called from C. We differentiate three cases based on the arguments of the Go function to be called.

### 13.5.1 Go functions without arguments

Example 13.3 shows a working solution for the previous example. First, in the preamble we define the goFunction() as an extern function to make it fully visible. The implementation of this function is available in our Go program. The compiler will link this function with the Go implementation we have declared the //exportFunction statement.

### 13.3: Go function without arguments called from C.

```go
package main

/*
#include <stdio.h>
extern void goFunction();

static inline void CFunction() {
	printf("CFunction will call goFunction\n");
	goFunction();
}
*/
import "C"
import "fmt"

// call function with no parameters
func main() {
	CFunction()
}

//export goFunction
func goFunction() {
	fmt.Println("goFunction was called")
}
```

![](img/c7dcb4df7215ed1d3fb76d25373be6c7_175_0.png)

We mentioned that one restriction of using the export statement in Go is that no functions can be implemented in the C preamble. However, we have implemented CFunction, how is that possible? This can be because the static inline embeds the given code and does not require additional function definitions. If this modifier is not used, the function must be defined in an external C file. When the program runs, we get the message from the C function followed by the message from Go.
