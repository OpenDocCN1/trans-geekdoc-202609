## 11. EXAMPLES

In the same way, examples are defined in Go with functions starting with Test, examples can be defined with functions starting with An. An interesting feature of examples is that the standard output they generate can be checked during testing. This is an important feature to ensure code coherence. Additionally, examples are included in Go generated documentation as described in Chapter 12.2.

Examples follow the naming convention described below.

```go
func Example() { // for the package
func ExampleF(f *F) // F for functions
func ExampleT(t *T) // T for types
func ExampleM(m *M) // M method of type T
func ExampleMSuffix(suffix string) // with a suffix if more than one
```

To check the correctness, every example must define the output to be generated. This is indicated using the Output command as output order is not guaranteed, we can use unordered output: instead of Output.

```go
func Example() {
  // Output:
  // Expected output
}
```

## 11.3 BENCHMARKING

Provides benchmarking for those functions starting with the Benchmark prefix. Benchmarks are executed with the go test command when the -bench flag is set. They use the testing.B type instead of testing.T normal tests.

A basic benchmarking is shown in Example 11.7 for a loop computing a sum of numbers. The value of b contains the number of repetitions per operation in performance is being measured. As confirmed from the benchmark output, the benchmark runs three times with b.N values. This is done to ensure the reliability of the benchmark.

Benchmarks are highly configurable using the available go test flags. The benchmark output indicates the number of available goroutines (BenchmarkSum-16), the number of executed iterations (3817), and the nanoseconds elapsed per iteration (265858).
