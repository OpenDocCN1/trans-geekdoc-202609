PB permits defining messages with their fields and corresponding types. This definition is done in a file with the .proto suffix. The PB version is set with the syntax statement. PB entities are organized into packages that can be imported from other proto files. In our example, we work with package user. PB permits the definition of various options that may help the generation of code for certain languages. The go_package option indicates the path of the package where the Generated code will be saved. This package must be imported into our code.

Any message is composed of fields and every field has a name, and a field type Field types resemble those used in int32, uint32, bool although there are some additional types like float, double, int64 among others. The equivalent type in every PB supported language is described in the official documentation after marshaling. In this case, user_id will be the first marshaled field followed by the email.

Once we have our message, we can create the corresponding Go implementation. To do so, we have to run the proto command. For this example, protoc -out=$GOPATH/src user.proto. The -out parameter indicates where to write the generated code. Remember that these fields must be accessible from your final code and must match the go_package statement. The generated output is contained within the user.pb file. This file contains all the code that defines the user and the functions to encode the PB protocol specification.

Finally, we can import the types defined in our user.pb file from any package. Example 14.2 creates a user and uses the PB code to marshal it and then, unmarshal it. Remember that once the type is marshaled, it can be sent through the network and unmarshaled by any other recipient independently of the programming language and platform.
