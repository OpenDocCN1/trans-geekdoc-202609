## 11.5 PROFILING

Getting high performance and finding potential optimizations in your code is not an easy task. Profiling is a complex task that requires a deep understanding of code and the underlying language. Go provides the runtime/pprof package with functions to define profiling entities. Fortunately, profiling functions are ready-to-use with benchmarks that facilitates the exploration of CPU and memory consumption in our code.

Profiling can be generated by launching benchmarks like described in this chapter. To force profiling, the -cpuprofile filepath and -memprofile filepath flags must be set for CPU and memory profiling respectively test. For both, a file is created. These files can be interpreted by pprof to generate useful reports. This tool is already integrated into the go tool pprof.

To illustrate how to use profiling, we use the benchmark from Example 11.11. The BuildGraph returns a directed graph with edges connecting selected vertices. The graph may not have sense, but it will help us understand how to approach a case of performance profiling.

# Example 11.11: Profiling of a graph generation program.

```go
package example_01
import (
	"math/rand"
	"testing"
	"time"
)

func BuildGraph(vertices int, edges int) [][]int {
	graph := make([][]int, vertices)
	for i:=0; i<len(vertices); i++ {
		graph[i] = make([]int, 0, 1)
	}
	for i:=0; i<edges; i++ {
		from := rand.Intn(vertices)
		to := rand.Intn(vertices)
		graph[from] = append(graph[from], to)
	}
	return graph
}

func BenchmarkGraph(b *testing.B) {
	rand.Seed(time.Now().UnixNano())
	for i:=0; i<b.N; i++ {
		BuildGraph(100,20000)
	}
}
```

## 12.1 MODULES

Dealing with dependencies is always key to ensure code compatibility and reproducibility. As it was explained in Chapter 2.1.1 we showed throughout this book, the most basic tool to make code accessible is go get. However, this is a very basic solution that does not solve issues as code versioning. Nowadays projects require several third-party projects to run. For some years solutions were proposed to manage code dependencies in Go, until Go modules became the official solution.

> Go 1.16 was released while this was being written in version v0.1.0. One of the most important changes in this release is the use of go modules by default. For compatibility purposes, and to facilitate migrations the environment variable GO11MODULE can be set to false. However, this variable will be ignored in Go 1.17. This means, that every project will be expected to use Go modules.

Go modules facilitates the management of dependencies and makes it easier to share project requirements among developers. The idea is simple, to show the requirements of a project in a common format that can be used to acquire all the necessary code for a successful completion. Go modules are governed by the go.mod file that contains information about what projects in versions are required. We assume with the code from Example 12.1. This code uses a third-party logger to print a message.
