## Example 11.3: Test skipping.

```go
package example_03

import (
	"fmt"
	"math"
	"testing"
	"time"
)

func Sum(n int64, done chan bool) {
	var result int64 = 0
	var i int64
	for i = 0; i < n; i++ {
		result = result + i
	}
	done <- true
}

func TestSum(t *testing.T) {
	var i int64
	done := make(chan bool)
	for i = 0; i < math.Max64; i+=100000 {
		go Sum(i, done)
		timeout := time.NewTimer(time.Millisecond)
		select {
		case <-timeout.C:
			t.Skip(fmt.Sprintf("%d took longer than 1 millisecond", i))
		case <-done:
		}
	}
}
```

## 11.1.1 Subtests

Certain tests can be utilized to test particular code properties. permit triggering other tests using the t.Run() function.

```go
func TestFoo(t *testing.T) {
	t.Run("A1", func(t *testing.T) { })
	t.Run("A2", func(t *testing.T) { })
	t.Run("B1", func(t *testing.T) { })
}
```

In the example below, TestFoo invokes three functions. Subsequently, these testing functions invoke others. The first argument is a string that can be conveniently set as key=value format. This identifies the test and permits us to isolate what tests to be run in the go command.

We show how to work with subtests with a practical example. Because the code can be a bit large to show at once, we split it into two sections for better readability. In this example, we want to test a user type that can be defined in XML and JSON formats. Check Chapter B if you are not familiar with encoders.

## Example 11.4: Subtests in practice (part I).

```go
package example_03

import (
	"encoding/json"
	"encoding/xml"
	"errors"
	"fmt"
	"io/ioutil"
	"os"
	"testing"
)

type Encoding int

const (
	XML Encoding = iota
	JSON
)

type User struct {
	UserID string `xml:"id" json:"id"`
	Email string `xml:"email" json:"email"`
	Score int    `xml:"score" json:"score"`
}

var Users []User

func (u *User) Equal(v User) bool {
	if u.UserID != v.UserID || u.Email != v.Email || u.Score != v.Score {
		return false
	}
	return true
}

func (u *User) encode(format Encoding) ([]byte, error) {
	var encoded []byte
	var err error
	switch format {
	case XML:
		encoded, err = xml.Marshal(u)
	case JSON:
		encoded, err = json.Marshal(u)
	default:
		return nil, errors.New("unknown encoding")
	}
	return encoded, err
}

func (u *User) fromEncoded(format Encoding, encoded []byte) error {
	recovered := User{}
	var err error
	switch format {
	case XML:
		err = xml.Unmarshal(encoded, &recovered)
	case JSON:
		err = json.Unmarshal(encoded, &recovered)
	default:
		err = errors.New("unknown encoding")
	}
	if err == nil {
		*u = recovered
	}
	return err
}

func (u *User) write(encoded []byte, path string) error {
	return ioutil.WriteFile(path, encoded, 0644)
}

func (u *User) ToEncodedFile(format Encoding, filePath string) error {
	encoded, err := u.encode(format)
	if err != nil {
		return err
	}
	return u.write(encoded, filePath)
}
```

The code to be tested. The User type can be written to a file and recovered from a file with ToEncodedFile and FromEncoded methods respectively. The Encoding type is an enum to indicate the format we are using. For the same type we have features: we can work with XML and JSON formats and we can read and write both. We can use subtests to obtain finer granularity and better control. Example 11.5 continues with all the corresponding tests. The entry point for testing is TestMain where we set up code to be used during the process. Afterwards, we invoke m.Run() to start the tests.

## Example 11.5: Subtests in practice (part II).

```go
func testWriteXML(t *testing.T) {
	tmpDir := os.TempDir()
	for _, u := range Users {
		f := tmpDir + u.UserID + ".xml"
		err := u.ToEncodedFile(XML, f)
		if err != nil {
			t.Error(err)
		}
	}
}

func testWriteJSON(t *testing.T) {
	tmpDir := os.TempDir()
	for _, u := range Users {
		f := tmpDir + u.UserID + ".json"
		err := u.ToEncodedFile(JSON, f)
		if err != nil {
			t.Error(err)
		}
	}
}

func testReadXML(t *testing.T) {
	tmpDir := os.TempDir()
	for _, u := range Users {
		f := tmpDir + u.UserID + ".xml"
		newUser := User()
		err := newUser.FromEncoded(XML, f)
		if err != nil {
			t.Error(err)
		}
		if !newUser.Equal(u) {
			t.Error(fmt.Sprintf("found %v, expected %v", newUser, u))
		}
	}
}

func testReadJSON(t *testing.T) {
	tmpDir := os.TempDir()
	for _, u := range Users {
		f := tmpDir + u.UserID + ".json"
		newUser := User()
		err := newUser.FromEncoded(JSON, f)
		if err != nil {
			t.Error(err)
		}
		if !newUser.Equal(u) {
			t.Error(fmt.Sprintf("found %v, expected %v", newUser, u))
		}
	}
}

func testXML(t *testing.T) {
	t.Run("ActionWrite", testWriteXML)
	t.Run("ActionRead", testReadXML)
}

func testJSON(t *testing.T) {
	tmpDir := os.TempDir()
	for _, u := range Users {
		f := tmpDir + u.UserID + ".json"
		os.Remove(f)
	}
}

func testEncoding(t *testing.T) {
	t.Run("EncodingXML", testXML)
	t.Run("EncodingJSON", testJSON)
}

func TestMain(m *testing.M) {
	Users = []User{
		{UserID: "user1", Email: "user1@example.com", Score: 10},
		{UserID: "user2", Email: "user2@example.com", Score: 20},
	}
	os.Exit(m.Run())
}
```

Notice that only TestEncoding is a valid function because it is named with an uppercase letter. The other functions (testJSON, testXML, etc.) are not test functions and will not be executed when running go test. This is not in this way to permit a test routing using subsets. The main idea is to test encodings (XML and JSON) separately as we write and read both.
