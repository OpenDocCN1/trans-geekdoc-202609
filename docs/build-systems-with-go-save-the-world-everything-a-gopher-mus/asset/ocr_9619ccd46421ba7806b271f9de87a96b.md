#  20.2 USING THE CONFLUENT CLIENT

The confluent-kafka-go75 is a wrapper around the librkafka library. This wrapper defines a Kafka client with a producer and a consumer types. Examples 20.1 and 20.2 show standard implementations for a producer and a consumer respectively.

# 20.2.1 Synchronous producer

The Producer type is instantiated using a ConfigMap which contains key-pairs with all the required configuration for the connection72. The Producer holds a connection that has to be released with Close(). For this Example, we send events to the topic named helloTopic. Events are defined by the Message type described below.

```
type Message struct {
  TopicPartition TopicPartition
  Value          [byte]
  Key            [byte]
  Timestamp      time.Time
  TimestampType  TimestampType
  Opaque         interface{}
  Headers        []Header
}
```

The most important field is value which contains the message content in a raw byte slice. Key can be used for additional control inside the topic as mentioned above. Opaque can be used to pass arbitrary data to the corresponding event handler.

The producer shown in Example 20.1 passes a message to the Produce method indicating the partition and message value. Note that we target the partition set by Kafka using the PartitionKey policy. Produce function receives a chan event to handle the production of events. Messages are sent to the librkafka which has its own queue of messages. To avoid an overflow, we can wait until the message is sent using the deliveryChan. This is not the most efficient approach as the production of messages is stopped until a message is processed. Flush function waits for a given time in milliseconds until all messages have been sent. In the Example it is commented because we are waiting for every message submission.
