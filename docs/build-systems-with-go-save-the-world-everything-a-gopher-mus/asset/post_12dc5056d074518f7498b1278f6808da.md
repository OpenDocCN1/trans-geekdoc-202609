
done := make(chan bool)
go func() {
    for {
        resp, err := stream.Recv()
        if err == io.EOF {
            done <- true
            return
        }
        if err != nil {
            panic(err)
        }
        fmt.Println("Received:", resp.String())
    }
}()
<-done
fmt.Println("Client done")
```

## 15.5.2 Client streaming

In a client streaming scenario, the client directly opens a data stream with the server. When the client decides to stop sending data, it can close the channel or close the channel and wait for a response from the server. What regards the server, it receives all the data from the client until EOF is found. Afterwards, depending on the condition it can send a response or not.

Example 15.8 defines the sum procedure that receives a request of requests. This procedure will compute the sum of all the numbers sent from the stream and return the result to the client. To define a streaming input, we have to add the stream modifier to the incoming message.

**Example 15.8: Definition of a client streaming method.**

```
syntax = "proto3"
package numbers;
```

**Figure 15.3:** Client-server communication in a client streaming scenario.

The client-side (Example 15.9) the Sum function does not receive any request, only a context. This function returns a streaming client that can be used to send requests to the server once the connection is established. If the stream has to be finished, then there are two options: We can close the stream if we do not expect any answer with Close, or we can close the stream and wait for a server response with CloseAndRec. In both cases, the server is informed that the client has closed the channel. In our example, we close and wait for the server response containing the result with the sum of all the numbers it has received.

**Example 15.9:** Client sending data in streaming.

```go

```

```go
import (
	"context"
	"fmt"
	pb "github.com/juanmanuel-tirado/savetheworldwithgo/13_grpc/streaming/example_02/numbers"
	"google.golang.org/grpc"
	"time"
)

func main() {
	conn, err := grpc.Dial(":50051", grpc.WithInsecure(), grpc.WithBlock())
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	c := pb.NewServiceClient(conn)

	ctx, cancel := context.WithTimeout(context.Background(), time.Second(10))
	defer cancel()

	stream, err := c.Sum(ctx)
	if err != nil {
		panic(err)
	}

	from, to := 1, 100
	for i := from; i <= to; i++ {
		err := stream.Send(&pb.NumRequest{X: int64(i)})
		if err != nil {
			panic(err)
		}
	}

	fmt.Println("Waiting for response...")
	result, err := stream.CloseAndRecv()
	if err != nil {
		panic(err)
	}
	fmt.Printf("The sum from %d to %d is %d\n", from, to, result.Total)
}
```

The server implementation from Example 15.10 is mostly contained in an example for loop. When the sum is invoked, the server checks the input stream until the EOF or an error occurs. If no error or EOF is found, the server accumulates the incoming values (line 28), otherwise, the server invokes SendAndClose sending the accumulated value to the client.

**Example 15.10: Server processing client stream and responding.**

```go
package main
import (
	"fmt"
	pb "github.com/juanmanuel-tirado/satetheworldwithgo/13_grpc/streaming/example_02/numbers"
	"google.golang.org/grpc"
	"io"
	"net"
)

type NumServer struct {
	pb.UnimplementedNumServer
}

func (n *NumServer) Sum(stream pb.NumService_Server) error {
	var total int64 = 0
	var counter int = 0
	for {
		next, err := stream.Recv()
		if err == io.EOF {
			fmt.Printf("Received %d sum: %d\n", counter, total)
			stream.SendAndClose(&pb.NumResponse{Total: total})
			return nil
		}
		if err != nil {
			return err
		}
		total = total + next.X
		counter++
	}
	return nil
}

func main() {
	lis, err := net.Listen("tcp", "localhost:50051")
	if err != nil {
		panic(err)
	}
	s := grpc.NewServer()

	pb.RegisterNumServerService(s, &NumServer{})

	if err := s.Serve(lis); err != nil {
		panic(err)
	}
}

## 15.5.3 Bidirectional streaming

We have already mentioned that gRPC provides full-duplex communication using HTTP/2. This makes it possible to use bidirectional streaming between client and server. Bidirectional streaming may be particularly suitable for scenarios where data may arise on the fly or even to define your protocols on top of gRPC.

In Example 15.11, we define a chat service that sends back to the user data consumption stats. In a chat service, client and server are expected to send data asynchronously. The client can send text messages to the server at any moment. On the other side, the server periodically sends stats to the user with some periodicity that may vary. Observe the remote method SendTxt sets the argument and responds to the streams.

**Example 15.11: Definition of a bidirectional streaming method.**

```proto
syntax = "proto3"
package numbers;

option_package="github.com/juanmanuel-tirado/savetheworldwithgo/13_grpc/streaming/example_02/numbers";

message ChatRequest {
  int64 id = 1;
  int64 to = 2;
  string txt = 3;
}

message StatsResponse {
  int64 total_char = 1;
}

service Service {
  rpc SendTxt (stream ChatRequest) returns (stream StatsResponse);
}
```

Figure 15.4 depicts this scenario. The client establishes a new stream with the server. Both ends listen to the stream. Finally, the client or server closes the connection. Because two actions are asynchronous we use two goroutines: one to sending and other to receiving data.

| client server |
| :--- |
| ChatRequest txt:"Hello,I’m OK" |
| ChatRequest txt:"Bye" |
| StatsResponse total_char:11 |
| StatsResponse total_char:21 |
| EOF |

package main

import (
	"context"
	"fmt"
	pb "github.com/juanmanuel-tirado/savetheworldwithgo/13_grpc/streaming/example_02/numbers"

	stream, err := c.SendTxt(context.Background())
	if err != nil {

	}

	done := make(chan bool)
	go func() {
		for {
			stats, err := stream.Recv()
			if err != nil {
				return
			}
			fmt.Println(stats.String())
		}
	}()

	t := time.NewTicker(500 * time.Millisecond)
	for {
		select {
		case <-done:
			return
		case <-t.C:

			if err != nil {
				panic(err)

		}
	}
}

```go
package main

import (
	"context"
	"fmt"
	pb "github.com/juanmanuel-tirado/savetheworldwithgo/13_grpc/streaming/example_02/numbers"
	"google.golang.org/grpc"
	"io"
	"net"
	"time"
)

type ChatServer struct {
	pb.UnimplementedChatServer
}

func (s *ChatServer) SendTxt(stream pb.ChatService_SendTxtServer) error {
	var totalChar int64
	for {
		req, err := stream.Recv()
		if err == io.EOF {
			return nil
		}
		if err != nil {
			return err
		}
		totalChar += int64(len(req.Txt))
		stream.Send(&pb.StatsResponse{TotalChar: totalChar})
	}
}

func main() {
	lis, err := net.Listen("tcp", "localhost:50051")
	if err != nil {
		panic(err)
	}
	s := grpc.NewServer()
	pb.RegisterChatServer(s, &ChatServer{})
	if err := s.Serve(lis); err != nil {
		panic(err)
	}
}
```

The server implementation from Example 15.13 listens for incoming chat messages and count the number of received characters. Additionally, every two seconds it sends a message with the current value of the characters counter. Notice that sending stats is completely independent of the incoming messages and occurs at a regular pace. The server expects the client to close the connection by checking any incoming EOF.
