
PB permits defining messages with their fields and corresponding types. This definition is done in a file with the .proto suffix. The PB version is set with the syntax statement. PB entities are organized into packages that can be imported from other proto files. In our example, we work with package user. PB permits the definition of various options that may help the generation of code for certain languages. The go_package option indicates the path of the package where the Generated code will be saved. This package must be imported into our code.

Any message is composed of fields and every field has a name, and a field type. Field types resemble those used in int32, uint32, bool although there are some additional types like float, double, int64 among others. The equivalent type in every PB supported language is described in the official documentation after marshaling. In this case, user_id will be the first marshaled field followed by the email.

Once we have our message, we can create the corresponding Go implementation. To do so, we have to run the proto command. For this example, protoc -out=$GOPATH/src user.proto. The -out parameter indicates where to write the generated code. Remember that these fields must be accessible from your final code and must match the go_package statement. The generated output is contained within the user.pb file. This file contains all the code that defines the user and the functions to encode the PB protocol specification.

Finally, we can import the types defined in our user.pb file from any package. Example 14.2 creates a user and uses the PB code to marshal it and then, unmarshal it. Remember that once the type is marshaled, it can be sent through the network and unmarshaled by any other recipient independently of the programming language and platform.

## Example 14.2: Using protos from Example 14.1.

```go
package main
import (
	"fmt"
	"github.com/manuel-tirado/savetheorldwithgo/12_protocolbuffers/pb/example_01/user"
	"google.golang.org/protobuf/proto"
)

func main() {
	u := user.User{Email:"john@gmail.com", UserId:"John"}

	fmt.Println("To encode:", u.String())
	encoded, err := proto.Marshal(&u)
	if err != nil {
		panic(err)
	}

	v := user.User{}
	err = proto.Unmarshal(encoded, &v)
	if err != nil {
		panic(err)
	}
	fmt.Println("Recovered", v.String())
}
```

To encode: user_id:"John"@gmail.com
Recovered: user_id:"John"@gmail.com

There are some considerations before you run this code. In Example 14.2 we import a third-party package, golang.org/protobuf/proto that contains the Marshal and Unmarshal functions. This is a third-party package and is not available in the base Go installation. The package can be installed using get get (see Section 2.1.1). However, we recommend to use go mod to make it more flexible. To revisit how go works visit Chapter 12. As a brief reminder, initialize the modules with go mod init. Then you can build the code with go build main.go and the go.mod file will have all the required dependencies.

> There is no other package defined in github.com/golang/protobuf. This package has been superseded by google.golang.org/protobuf/proto and it is not recommended to be used.

## 14.2 COMPLEX MESSAGES

PB facilitates the definition of complex message structures with sophisticated types. We extend our user message example to demonstrate how to use other types such as enumerations and repeated fields.

Example 14.3 defines a message that represents a group of users. Every group has an id, a category, a certain score, and a list of users that belong to the group. Notice that the user category is an enumerated value. Enumerated values are defined with the reserved word enum. For every item of the enumeration, we use the name and the associated value. Do not confuse this value with the field tag. The category field in Group is defined as type Category. For the list of users, we indicate that a field can appear several times with the reserved word repeated. This list of users has no size limit and can be empty.

Example 14.3: Definition of complex messages.

```proto
syntax = "proto3"
package user;

option go_package="github.com/juanmanuel-tirado/savethehelloworldwithgo/12_protocolbuffers/pb/example_02/user";

message User {
  string user_id = 1;
  string email = 2;
}

enum Category {
  DEVELOPER = 0;
  OPERATOR = 1;
}

message Group {
  int32 id = 1;
  Category category = 2;
  float score = 3;
  repeated User users = 4;
}
```

The new Group type is used in Example 14.4. When defining enumerations, for every item PB creates a variable named with concatenation of the enumeration and the name of the item. The enumeration of categories generates Category_DEVELOPER and Category_OPERATOR constants. The list of users is used actually in a slice of User type. Observe that actually, this uses pointers to the User type.

## Example 14.4: Utilization of messages from Example 14.3.

```go
package main

import (
	"github.com/juanuel-tirado/savetheprotocolwithgo/12_protocolbuffers/pb/example_02/user"
	"google.golang.org/proto"
	"fmt"
)

func main() {
	userA := user.User{Id: "John", Email: "john@gmail.com"}
	userB := user.User{Id: "Mary", Email: "mary@gmail.com"}

	g := user.Group{Id: 1,
		Score: 42.0,
		Category: user.Category_DEVELOPER,
		Users: []user.User{&userA, &userB},
	}
	fmt.Printf("To encode: %s", g.String())

	encoded, err := proto.Marshal(&g)
	if err != nil {
		panic(err)
	}
	recovered := user.Group{}
	err = proto.Unmarshal(encoded, &recovered)
	fmt.Printf("Recovered: %s", recovered.String())
}
```

Recovered: user_id:"John"@gmail.com (Wait, the OCR text has some garbled output here, correcting based on logical flow).

## 14.3 IMPORTING OTHER DEFINITIONS

Protocol buffers can be imported into other files. This facilitates the reuse of messages and complex solutions. Example 14.5 and 14.6 show how this is done. The user message can be defined in its own package. order to replicate the user logic from Example 14.5 and 14.6.

Example 14.5: User definition.

```proto
syntax = "proto3"
package user;

option go_package="user";

message User {
  string user_id = 1;
  string email = 2;
}
```

Example 14.6: Group definition.

```proto
syntax = "proto3"
package group;

option go_package="group";

import "user.proto";

enum Category {
  DEVELOPER = 0;
  OPERATOR = 1;
}

message Group {
  int32 id = 1;
  Category category = 2;
  float score = 3;
  repeated user.User users = 4;
}
```

The import "user.proto" statement makes accessible the messages defined at its corresponding package. The users field in Group has different user.User.

## Example 14.7: Using protos from Examples 14.5 and 14.6.

```go
package main

import (
	"github.com/juanmanuel-tirado/savetheworldwithgo/12_protocolbuffers/pb/example_03/group"
	"github.com/juanmanuel-tirado/savetheworldwithgo/12_protocolbuffers/pb/example_03/user"
	"google.golang.org/protobuf/proto"
	"fmt"
)

func main() {
	userA := user.User{UserId:"John", Email:"john@gmail.com"}
	userB := user.User{UserId:"Mary", Email:"mary@gmail.com"}

	g := group.Group{
		Id: 1,
		Score: 42.0,
		Category: group.Category_DEVELOPER,
		Users: []*user.User{userA, userB},
	}

	if err != nil {
		panic(err)
	}
	recovered := group.Group{}
	err = proto.Unmarshal(encoded, &recovered)
	fmt.Printf("To encode: %s\n", g.String())
	fmt.Printf("Recovered: %s\n", recovered.String())
}
```

## 14.4 NESTED TYPES

Certain messages may only make sense when found within other messages. PB permits the definition of nested types that are only accessible through other types. Our Group message can be rewritten using the User message as an embedded field shown in Example 14.8. Now the winner message represents a user who won in a given category. Otherwise, that user field has to be referred to as Group.User.

**Example 14.8:** Group definition with nested User type.

```proto
syntax = "proto3"
package group;

option go_package="group";

import "user.proto";

enum Category {
  DEVELOPER = 0;
  OPERATOR = 1;
}

message Group {
  int32 id = 1;
  Category category = 2;
  float score = 3;
  repeated User users = 4;
}
```
