# # 17.3 COMMANDS

A CLI can contain one or several commands, and these commands can have subcommands. Generally, the root command is not intended to run any operation. It usually displays help and presents the actions that can be executed. A good CLI syntax should be close to natural language. The commands, subcommands, and their flags should be easy to remember and make sense when the whole command is read as a sentence.

Example 17.7 two different messages: hello and bye. There are several ways to implement a CLI to do this. First, we have to consider that we have two possible actions that can be translated into A CLI with a syntax like ./say hello is easy to remember and clearly identifies the requested action. It would be possible to define the final action using flags. However, it would be difficult to remember how to operate this command (maybe ./say something -msg=?). On the other hand, ./say clearly lacks of arguments because we expect the prompt to say something. In case printing the help is the best option.
