Events inside topics are indexed by a consecutive number. When a consumer is subscribed to a topic, she receives an event with the offset of the next event to be consumed. When producers consume events, they increment this offset to new events if they are available. Different consumers can have different offsets like in Figure 20.2. To ensure that consumers get all the available messages in their order of arrival, consumers can commit the offset of the latest message they have consumed. This informs the broker about the current status of the consumer. Kafka by default executes this commit operation automatically although consumers can specify when to commit with the correct configuration.
