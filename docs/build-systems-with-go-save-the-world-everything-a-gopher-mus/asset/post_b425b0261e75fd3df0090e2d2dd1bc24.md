It is possible to execute templates inside other templates using the {{block "name"}} and {{define "name"}} actions. In Example 10.7, we define two template strings in Header and Welcome. It is idea that our welcome template prints a collection of items after printing a header. The {{define "hello"}} statement for the template "hello" and executes it. Notice that we parse both templates independently. However, the second one uses the helloMsg instead of creating a new one. Finally, we have to execute both templates in the order expected to appear.

## Example 10.7: Rendering templates inside other templates.

```go
package main
import (
    "os"
    "text/template"
)

const Header = `{{block "hello"}}Hello and welcome{{end}}`

const Welcome = `{{define "hello"}}{{range .}}{{print .}}{{end}}{{end}}`

func main() {
    musketeers := []string{"Athos", "Porthos", "Aramis", "D'Artagnan"}

    helloMsg, err := template.New("start").Parse(Header)
    if err != nil {
        panic(err)
    }

    welcomeMsg, err := template.Must(helloMsg.Clone()).Parse(Welcome)
    if err != nil {
        panic(err)
    }

    if err := helloMsg.Execute(os.Stdout, musketeers); err != nil {
        panic(err)
    }
}
```

Testing is one of the most important tasks to develop a successful project. Unfortunately, testing is usually postponed or not seriously taken into consideration by developers. ## 11.1 TESTS

Go provides an integrated solution for testing. Actually, any function with signature TestXXX(*testing.T) is interpreted as a testing function. Example 11.1 is a naive demonstration of how to check the correctness of 2+2. In this case, no error is going to occur. However, if any error is found, the t argument provides access to the Error function that sets this test to failed.

## Example 11.1: Simple test.

```go
package example_01

import "testing"

func TestMe(t *testing.T) {
	r := 2 + 2
	if r != 4 {
		t.Error("expected 2 got", r)
	}
}
```

Tests are thought to be used in the go test tool. For the example we can run the test as follows:

```bash
go test
PASS
ok github.com/juanmuel-tirado/SaveTheWorldWithGo/go_10_testing/testing/example_01.341s
>>> go test -v
=== RUN TestMe (0.00s)
- PASS TestMe (0.00s)
ok github.com/juanmuel-tirado/SaveTheWorldWithGo/go_10_testing/testing/example_01.090s
```

The basic output from go test is the final status of the testing (ok) and the elapsed time. When using the verbose flag (-v) this information is printed for every test. Now, if we force an error we get:

```bash
go test
FAIL: TestMe (0.00s)
- example_01_test.go:8: expected 2 got 3
```
