Events inside topics are indexed by a consecutive number. When a consumer is subscribed to a topic, she receives an event with the offset of the next event to be consumed. When producers consume events, they increment this offset to new events if they are available. Different consumers can have different offsets like in Figure 20.2. To ensure that consumers get all the available messages in their order of arrival, consumers can commit the offset of the latest message they have consumed. This informs the broker about the current status of the consumer. Kafka by default executes this commit operation automatically although consumers can specify when to commit with the correct configuration.

## 20.2 USING THE CONFLUENT CLIENT

The confluent-kafka-go75 is a wrapper around the librkafka library. This wrapper defines a Kafka client with a producer and a consumer types. Examples 20.1 and 20.2 show standard implementations for a producer and a consumer respectively.

### 20.2.1 Synchronous producer

The Producer type is instantiated using a ConfigMap which contains key-pairs with all the required configuration for the connection72. The Producer holds a connection that has to be released with Close(). For this Example, we send events to the topic named helloTopic. Events are defined by the Message type described below.

```go
type Message struct {
  TopicPartition TopicPartition
  Value          []byte
  Key            []byte
  Timestamp      time.Time
  TimestampType  TimestampType
  Opaque         interface{}
  Headers        []Header
}
```

The most important field is value which contains the message content in a raw byte slice. Key can be used for additional control inside the topic as mentioned above. Opaque can be used to pass arbitrary data to the corresponding event handler.

The producer shown in Example 20.1 passes a message to the Produce method indicating the partition and message value. Note that we target the partition set by Kafka using the PartitionKey policy. Produce function receives a chan event to handle the production of events. Messages are sent to the librkafka which has its own queue of messages. To avoid an overflow, we can wait until the message is sent using the deliveryChan. This is not the most efficient approach as the production of messages is stopped until a message is processed. Flush function waits for a given time in milliseconds until all messages have been sent. In the Example it is commented because we are waiting for every message submission.

**Example 20.1:** Confluent Kafka synchronous producer.

```go
package main

import (
    "fmt"
    "github.com/confluentinc/confluent-kafka-go/kafka"
)

func main() {
    cfg := kafka.ConfigMap{"bootstrap.servers": "localhost:9092"}
    p, err := kafka.NewProducer(cfg)
    if err != nil {
        panic(err)
    }
    defer p.Close()

    deliveryChan := make(chan kafka.Event, 10)
    defer close(deliveryChan)
    topic := "HelloTopic"
    msgs := []string{"Save", "the", "world", "with", "Go!!!"}
    for _, word := range msgs {
        err = p.Produce(&kafka.Message{
            TopicPartition: kafka.TopicPartition{Topic: &topic, Partition: kafka.PartitionAny},
            Value:          []byte(word),
        }, deliveryChan)
        if err != nil {
            panic(err)
        }
    }
    e := <-deliveryChan
    fmt.Printf("Sent %v\n", e.TopicPartition)
    // p.Flush(10000)
}
```

### 20.2.2 Synchronous consumer

The Producer type, the Consumer is instantiated with a ConfigMap with its corresponding configuration parameters. Consumers subscribe to one or several topics matching a regular expression. The Poll function blocks the execution for a given timeout and returns an Event or nil. Like shown in Example 20.2, using a switch statement we can control the execution and process messages.

**Example 20.2:** Confluent Kafka consumer.

```go
package main

import (
	"fmt"
	"github.com/confluentinc/confluent-kafka-go/kafka"
)

func main() {
	c, err := kafka.NewConsumer(&kafka.ConfigMap{
		"bootstrap.servers": "localhost:9092",
		"group.id": "helloGroup",
		"auto.offset.reset": "earliest",
	})
	if err != nil {
		panic(err)
	}
	defer c.Close()

	c.Subscribe([]string{"helloTopic"}, nil)

	for {
		ev := c.Poll(1000)
		if ev == nil {
			break
		}
		switch e := ev.(type) {
		case *kafka.Message:
			fmt.Printf("On %v: %s\n", e.TopicPartition, string(e.Value))
		case kafka.Error:
			fmt.Printf("Error: %v\n", e)
		default:
			fmt.Printf("Ignored: %v\n", e)
		}
	}
}
```
