
```go
package main

    "github.com/rs/zerolog"
    "github.com/rs/zerolog/log"
)

func main() {
    logger := log.Sample(&zerolog.BasicSampler{N:200})
    for i:=0;i<100;i++{
        logger.Info().Int("i", i)
    }
}
```

The BurstSampler provides more sophisticated limiting indicating how many messages are allowed per period. Additionally, a nextSampler can be used to indicate what sampler has to be invoked when the limit is reached. In 16.15, the sampler defines a burst of two messages every five seconds and then one sample every 90000000 iterations. After the first two entries, the burst limit is reached. Looking at the timestamp, we see that no more consecutive messages will be printed after five seconds.

## 16.4.3 Integration with HTTP Handlers

A common scenario for logging messages is HTTP handlers. Zerolog provides additional tools to integrate with http.Handler types. The hlog.NewHandler returns a function that receives http.Handler and returns another. The concatenation of handlers is possible and their integration with them however. Some logging functions are already available to extend the message context adding information from the requests.

In Example 16.16, we create a simple HTTP Server that returns a predefined message for every request. We use our logger hlog with additional context from HTTP requests. We add the IP address, the handler, and RequestIDHandler respectively. The concatenation of the loggers with our handler creates a middleware of loggers that is available for every request. Because hlog works as a contextual logger, we invoke hlog.FromRequest to get a logger with the contextual information (line 17). In the final output the message from the hlog logger contains additional context from the incoming request without any additional intervention.

# Example 16.16: Integration of contextual HTTP loggers.

```go
package main

import (
    "net/http"
    "github.com/rs/zerolog"
    "github.com/rs/zerolog/hlog"
    "os"
)

var log zerolog.Logger = zerolog.New(os.Stdout).With(
    zerolog.Str("app","example_04")).Logger()

type MyHandler struct {
}

func (h MyHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    hlog.Info().Msg("This is not a contextual logger")
    hlog.FromRequest(r).Info().Msg("")
    w.Write([]byte("Perfect!!!"))
    return
}

func main() {
    mine := MyHandler{}
    a := hlog.NewHandler(log)
    b := hlog.RemoteAddrHandler("ip")
    c := hlog.UserAgentHandler("user-agent")
    d := hlog.RequestHandlerHandler("req_id", "Request-ID")

    panic(http.ListenAndServe(":8080", a(b(c(d(mine))))))
}
```

```json
{"level":"info","app":"example_04","message":"This is not a contextual logger"}
{"level":"info","app":"example_04","ip":"127.0.0.1","user-agent":"curl/7.64.1","req_id":"12345"}
```

Logging HTTP requests may imply several levels of contextual information. However it may not be handy when the number of loggers varies in frequency. The wrapper and its method wrap any handler with a context of loggers. This method invokes all the layers and finally simplifies the code required to start the server. A similar solution for HTTP middleware is using a loop instead of recursion.

# Example 16.17: Integration of several contextual loggers.

```go
package main

import (
    "net/http"
    "github.com/rs/zerolog"
    "github.com/rs/zerolog/log"
    "os"
)

var log zerolog.Logger = zerolog.New(os.Stdout).With(
    zerolog.Str("app", "example_04")).Logger()

type MyHandler struct {
}

func (h *MyHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    hlog.FromRequest(r).Info().Msg("")
    w.Write([]byte("Perfect!"))
    return
}

type Wrapper struct {
    layers []func(http.Handler) http.Handler
}

func NewWrapper(h http.Handler) Wrapper {
    layers := []func(http.Handler) http.Handler{
        func(next http.Handler) http.Handler { return hlog.NewHandler(log)(next) },
        func(next http.Handler) http.Handler { return hlog.RemoteAddrHandler("ip")(next) },
        func(next http.Handler) http.Handler { return hlog.UserAgentHandler("user-agent")(next) },
        func(next http.Handler) http.Handler { return hlog.RequestHandlerHandler("req_id", "Request-ID")(next) },
    }
    return Wrapper{layers}
}

func (w *Wrapper) GetWrapper(h http.Handler, i int) http.Handler {
    if i >= len(w.layers) {
        return h
    }
    return w.layers[i](w.GetWrapper(h, i+1))
}

func main() {
    mine := &MyHandler{}
    wrapper := NewWrapper()
    h := wrapper.GetWrapper(mine, 0)

    panic(http.ListenAndServe(":8080", h))
}
```

```json
{"level":"info","app":"example_04","ip":"127.0.0.1","user-agent":"curl/7.64.1","req_id":"12345"}
```

# CHAPTER 17 COMMAND LINE INTERFACE

A software developer is used to interact with command-line interfaces (CLI). Good systems not only solve problems but are also easy to use. Nowadays solutions may offer hundreds of commands with several parameters each. Defining a good command-line interface that enables users to execute any operation is challenging. Frankly, the Go ecosystem offers powerful solutions that reduce the effort to define powerful and solid CLIs. This Chapter presents how the Cobra library can help developers define solid CLIs in an efficient and consistent way.

## 17.1 THE BASICS

Cobra is a library that provides all the necessary items to develop CLIs in Go. This library is used by major projects such as Kubernetes, Github or Istio and has some interesting features such as intelligent suggestions, automatic help generation, documentation, shell autocompletion, it is POSIX compliant.

Before explaining basics make sure you have Cobra available in your environment. The examples from this Chapter require the library to be installed. As usual, you can Go Modules (see Chapter 12) or run the following command to download the code in your GOPATH.

```bash
go get github.com/spf13/cobra
```

Cobra CLIs are built around the command type which fields define the name of the actions to be executed, their arguments, and help information. Example 17.1 contains a minimal example of a Cobra CLI for a program. This naive program is intended to be executed like ./hello and print a message using the standard output.

# Example 17.1: Basic Cobra CLI

```go
package main

import (
    "fmt"
    "github.com/spf13/cobra"
    "os"
)

var RootCmd = &cobra.Command{
    Use:   "short message",
    Short: "short message",
    Long:   "Long v0.1.0",
    Example: "this is an example",
    Run: func(cmd *cobra.Command, args []string) {
        fmt.Println("Save the world with Go!!!")
    },
}

func main() {
    if err := RootCmd.Execute(); err != nil {
        fmt.Println(os.Stderr, err)
        os.Exit(1)
    }
}
```

Observe that the main function only executes the root command or at least triggered, by commands. In this Example, RootCmd is a Cobra command with some fields that are used to populate the program help displayed below. This minimal example already generates this automatically with no additional information. The output below corresponds to the execution of the compiled program in a shell. The >>> indicates the shell prompt. Looking at the Use field in RootCmd, we expect the executable program to be named hello. If we call the program’s help, we get the following,

>>> /hello-help

hello [flags]

Examples:
this is an example
