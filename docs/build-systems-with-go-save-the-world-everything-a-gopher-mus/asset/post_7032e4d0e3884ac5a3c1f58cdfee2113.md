# CHAPTER 16
LOGGING WITH ZEROLOG

The execution of a program generates a substantial amount of information. Part of this information is dedicated to ensuring the correctness of the program or recording what happened. Logging is therefore a basic component of any program. For any software developer, logging must be one of the first elements to be designed in any solution. Projects such as Zerolog take advantage of Go features to offer a modern and complete logging solution. This Chapter exhaustively explores how to create logs in Go with special attention to the Zerolog project.

# 16.1 THE LOG PACKAGE

Go provides a basic logging solution in the log package. This package defines three types of messages Fatal, Panic, and Println. The first two messages are equivalent to executing Print followed by os.Exit and panic functions. Messages can be customized using prefixes and flags as shown in Example 16.1.

**Example 16.1:** log package messaging.

```go
package main

import "log"

func main() {
	// Panic or fatal messages stop the execution flow
	// log.Fatal("This is a fatal message")
	// log.Panic("This is a panic message")
	log.SetPrefix("prefix -> ")
	log.Println("This is a log message")
	log.SetFlags(log.Lshortfile)
}
```
2021/02/08 19:30:34 This is a log message
prefix -> 2021/02/08 19:30:34 This is a log message

More customized loggers can be defined using the log.New function which receives a writer argument, a prefix, and a flag. This facilitates logs using file writers as shown in Example 16.2.

**Example 16.2:** log package messaging.

```go
package main

import (
	"io/ioutil"
	"log"
	"os"
)

func main() {
	tmpFile, err := ioutil.TempFile(os.TempDir(), "logger.out")
	if err != nil {
		log.Panic(err)
	}
	logger := log.New(tmpFile, "prefix ->", log.Ldate)
	logger.Println("This is a log message")
}
```

# 16.2 ZEROLOG BASICS

The Previous Section explored how to use the basic logging features provided within the log package. The limitations of this package in terms of customization, efficiency, and adaptability made third-party developers write their own logging solutions. A remarkable solution is Zerolog which provides JSON oriented logging using zero-allocation.

The simplest Zerolog message defines a logging level and a message string. The generated output is a JSON object with the level, time, and the message. There are seven log levels shown in Example 16.3 from panic (level 5) to trace (level -1).

> Example 16.3: Logging messages in zerolog.

```go
package main

import(
    "github.com/rs/zerolog/log"
)

func main() {
    // Panic or fatal messages stop the execution flow
    // log.Panic().Msg("This is a panic message")
    // log.Fatal().Msg("This is a fatal message")
    log.Error().Msg("This is an error message")
    log.Warn().Msg("This is a warning message")
    log.Info().Msg("This is an information message")
    log.Debug().Msg("This is a debug message")
    log.Trace().Msg("This is a trace message")
}
```

# Example 16.4: Set global level zerolog.

```go
package main

import (
	"github.com/rs/zerolog/log"
	"github.com/rs/zerolog"

func main() {
	zerolog.SetGlobalLevel(zerolog.DebugLevel)
	log.Debug().Msg("Debug message is displayed")
	log.Info().Msg("Info message is displayed")

	zerolog.SetGlobalLevel(zerolog.InfoLevel)
	log.Debug().Msg("Debug message is no longer displayed")
	log.Info().Msg("Info message is displayed")
}
```
