### 选择活动日志事件以查看其详细信息

在[图 14-1](#c14.xhtml#c14-fig-0001)中，你可以清楚地看到是谁（我）在何时成功启动了虚拟机。[图 14-2](#c14.xhtml#c14-fig-0002)中显示的 JavaScript 对象表示法 (JSON) 源数据揭示了 VM 名称和其他详细信息。

[图 14-2](#c14.xhtml#c14-fig-0002)顶部的工具栏包含一些有用的按钮：

*   **编辑列：** 自定义资源列表视图中使用的显示属性。你应该养成在所有资源列表中使用此控件的习惯。请注意，此处的自定义仅影响你的 Azure Active Directory (AD) 帐户，不影响同事的帐户。
*   **刷新：** 单击以确保你看到最新数据。
*   **导出到事件中心：** 将当前筛选后的活动日志数据流式传输到事件中心命名空间。然后，你可以使用其他 Azure 资源订阅此活动日志流，并根据业务要求处理数据。
*   **下载为 CSV：** 下载当前活动日志视图的逗号分隔值 (CSV) 表示形式。
*   **日志：** 转到活动日志分析。如果你尚未创建 Log Analytics 工作区，系统将提示你创建一个。
*   **固定当前筛选器：** 允许你将当前筛选后的结果集放置在仪表板磁贴中。当你需要持续关注活动日志数据时，此选项非常方便。
*   **重置筛选器：** 删除任何用户定义的筛选器，并将视图重置为默认值。

单击一个活动日志事件会显示摘要。[图 14-2](#c14.xhtml#c14-fig-0002)中显示的“摘要”选项卡显示常规信息。单击“JSON”选项卡以 JSON 格式查看详细信息。此 JSON 提供了关于事件的深度细节，当你执行取证故障排除以弄清订阅中究竟是谁在何时做了什么时，这非常有用。

### Azure Monitor 诊断设置

Azure Monitor 诊断设置是用于启用非 VM 资源诊断的中央控制站。请按照以下步骤在 Azure Monitor 中启用资源诊断：

1.  **在 Azure Monitor 中，选择“诊断设置”边栏选项卡。**
2.  **使用筛选器控件缩小视图范围，并从列表中选择一个资源。**

    在[图 14-3](#c14.xhtml#c14-fig-0003)中，你可以看到来自两个订阅的四个资源。此示例选择了 vm1-nsg 网络安全组。

3.  **在“诊断设置”边栏选项卡上，单击“添加诊断设置”。**

    ![请记住](images/remember.png) Azure Monitor 诊断数据的两种类型是日志和指标。某些 Azure 资源两者皆有；其他资源则只有一种。

4.  **完成“诊断设置”边栏选项卡。**

    将你看到的内容与[图 14-4](#c14.xhtml#c14-fig-0004)进行比较。为诊断流命名；我总是将 `-diag` 追加到资源名称后。

    ![图 14-3：Azure Monitor 诊断设置允许你为多个资源集中启用诊断。](images/9781119612148-fg1403.png)

    [图 14-3：](#c14.xhtml#rc14-fig-0003) Azure Monitor 诊断设置允许你为多个资源集中启用诊断。

    ![图 14-4：配置 Azure 资源诊断。](images/9781119612148-fg1404.png)

    [图 14-4：](#c14.xhtml#rc14-fig-0004) 配置 Azure 资源诊断。

    你可以将诊断数据发送到以下一个或多个目标：

    *   **存储帐户：** 优势是长期归档存储。
    *   **事件中心：** 优势是实时订阅诊断流。
    *   **Log Analytics：** 优势是 Log Analytics 固有的强大查询/报告功能。

    如果稍后需要更改这些设置，可以重新访问它们。

    除了诊断设置目标外，你还需要指定要收集哪些日志和指标类别。不同资源收集不同类型的指标和日志。例如，网络安全组诊断会在每次触发 NSG 规则时记录日志。

5.  **单击“保存”以提交更改。**

![警告](images/warning.png) 你将为使用任何其他 Azure 资源付费，即使它是作为单独配置的一部分。例如，在配置诊断以将资源诊断数据存储在存储帐户中时，你即接受了与该存储帐户相关的额外费用。

### VM 诊断设置

VM 资源诊断的处理方式与其他 Azure 资源分开。启用 VM 诊断涉及安装 Azure 诊断扩展。正如你所料，此扩展收集的特定指标和日志取决于操作系统（Windows 或 Linux）。

要启用 VM 诊断，请执行以下步骤：

1.  **导航到要为其启用诊断的 VM，然后选择“诊断设置”菜单项。**
2.  **在“诊断设置概述”页面上，单击“启用来宾级监视”。**

    重要的是要注意，Azure 无需代理即可收集非常基本的 VM 数据。通过启用来宾诊断，你指示 Azure 为虚拟机收集更详细、更细粒度的诊断数据。

3.  **在 VM 的设置列表中，单击“扩展”，并验证 Azure 诊断扩展是否已安装。**

    在[图 14-5](#c14.xhtml#c14-fig-0005)中，你可以看到我的 VM1 虚拟机已安装 VM 诊断和其他扩展。

    在我撰写本文时，该扩展的正式名称为 `Microsoft.Insights.VMDiagnosticsSettings` (Windows)。

    ![图 14-5：验证 Azure VM 的 VM 诊断扩展是否存在。](images/9781119612148-fg1405.png)

    [图 14-5：](#c14.xhtml#rc14-fig-0005) 验证 Azure VM 的 VM 诊断扩展是否存在。

4.  **返回 VM 的“诊断设置”边栏选项卡，并查看配置选项。**

    你可以在 Windows VM 上收集以下数据：

    *   性能计数器
    *   事件日志
    *   内存崩溃转储

    你可以在 Linux VM 上收集以下数据：

    *   系统硬件指标（处理器、内存、网络、文件系统和磁盘）
    *   在 VM 上运行的任何已启用守护进程的 Syslog 事件
