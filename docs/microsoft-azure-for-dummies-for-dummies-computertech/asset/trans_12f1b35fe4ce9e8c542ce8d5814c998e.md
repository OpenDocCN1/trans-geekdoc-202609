
# 从 Azure 快速入门模板部署 Windows Server VM

假设你已打开 Visual Studio 并登录到 Azure 订阅，那么你就可以开始了。在本节中，你将从 Azure 快速入门模板库部署一台 Windows Server VM，该库位于 `https://azure.microsoft.com/en-us/resources/templates/`。我使用的是一个包含托管磁盘的模板定义。请遵循以下步骤：

1.  **在 Visual Studio 中，选择“文件”⇒“新建”⇒“项目”。**
    “创建新项目”对话框随即打开。

2.  **在 Visual Studio 模板库中搜索“Azure 资源组”，将其选中，然后单击“下一步”。**

3.  **为项目命名并保存。**
    选择一个有意义的项目名称，例如“Simple Windows VM”，选择你喜欢的目录位置，然后单击“创建”。

4.  **在 Azure 快速入门模板库中选择 `101-vm-with-standardssd-disk` 模板，然后单击“确定”。**
    [图 5-6](#c05.xhtml#c05-fig-0006) 显示了该界面。
    ![图 5-6：在 Visual Studio 2019 中创建资源组部署项目。](images/9781119612148-fg0506.png)
    [图 5-6：](#c05.xhtml#rc05-fig-0006) 在 Visual Studio 2019 中创建资源组部署项目。

5.  **双击 `azuredeploy.json` 模板文件。**
    此操作将 JavaScript Object Notation (JSON) 文件加载到代码编辑器中。请特别注意 JSON 大纲窗格，如[图 5-7](#c05.xhtml#c05-fig-0007) 所示。
    ![图 5-7：代码编辑器中的 ARM 模板。](images/9781119612148-fg0507.png)
    [图 5-7：](#c05.xhtml#rc05-fig-0007) 代码编辑器中的 ARM 模板。

6.  **浏览 ARM 模板的内容。**
    JSON 大纲视图中显示的三个元素为：
    *   **parameters（参数）：** 你在部署时向模板提供这些值。请注意第 26-30 行的 `allowedValues` 元素；模板作者预先填充了 VM 磁盘类型，以简化验证和部署。
    *   **variables（变量）：** 这些值表示在模板内部引用的固定或动态数据。
    *   **resources（资源）：** 在此部署中，你将创建四种资源类型：虚拟机、虚拟 NIC、虚拟网络和公共 IP 地址。

7.  **在解决方案资源管理器中，右键单击项目，然后从快捷菜单中选择“验证”。**
    “验证到资源组”对话框随即打开。

8.  **填写对话框的字段，然后单击“编辑参数”以提供参数值。**
    你可以在[图 5-8](#c05.xhtml#c05-fig-0008) 中看到我的环境。
    ![图 5-8：验证我们的 ARM 模板。](images/9781119612148-fg0508.png)
    [图 5-8：](#c05.xhtml#rc05-fig-0008) 验证我们的 ARM 模板。
    ![请记住](images/remember.png) Visual Studio 允许你在将模板部署到 Azure 之前对其进行验证。资源组是 Azure 中的基本部署单位。因此，你的部署必须指定一个新的或现有的资源组。

9.  **单击“验证”，并观察“输出”窗口中的状态消息。**
    请务必查看 Visual Studio 应用程序后面；Azure 会生成一个 PowerShell 控制台会话，提示你确认管理员密码。
    你在“输出”窗口中寻找的反馈信息是：
    `Template is valid.`
    如果模板验证失败，Visual Studio 会相当清楚地告诉你发现问题的模板代码行。你可以调试并根据需要重试验证多次，直到模板通过验证。

10. **通过在解决方案资源管理器中右键单击项目并从快捷菜单中选择“部署”来部署 VM。**
    ![提示](images/tip.png) 快捷菜单包含对验证配置的引用。

11. **监视进度，并在 Azure 门户中验证 VM 是否存在。**
    当你在“输出”窗口中看到以下状态行时，即表示部署已成功完成：
    `Successfully deployed template 'azuredeploy.json' to resource group 'your-resource-group'.`

## 连接到 VM

通常，你会使用远程桌面协议在本地远程管理 Windows Server，Azure 也不例外。浏览到新 VM 的“概述”边栏选项卡，然后单击“连接”。随即打开“远程桌面连接”对话框（请参阅[图 5-9](#c05.xhtml#c05-fig-0009)）。你可以从此处下载 `.rdp` 连接文件并将其打开。

如[图 5-9](#c05.xhtml#c05-fig-0009) 所示，建立 RDP 连接的步骤如下：
1.  从“概述”边栏选项卡工具栏单击“连接”。
2.  将 RDP 连接文件下载到本地计算机。
3.  使用你首选的 RDP 客户端软件打开连接。

![图 5-9：远程桌面连接在 Azure VM 上的工作方式与在本地 VM 上完全相同。](images/9781119612148-fg0509.png)
[图 5-9：](#c05.xhtml#rc05-fig-0009) 远程桌面连接在 Azure VM 上的工作方式与在本地 VM 上完全相同。
![提示](images/tip.png) Microsoft 为 macOS 提供了原生的远程桌面协议客户端；可在 Mac App Store 中获取。

# 配置 VM

Azure 云中的配置管理实质上与本地环境相同。你希望尽早在 VM 的生命周期中就正确配置它。

首先，我将解释如何调整网络设置，这是 VM 至关重要且潜在脆弱的子系统。

![警告](images/warning.png) **请勿尝试从 VM 内部配置 Azure VM 的网络设置。** 如果这样做，你将把自己锁在 VM 外部。相反，你需要在 ARM 中执行所有 TCP/IP 配置。

包含计算机 IP 配置的不是 VM 资源，而是其 vNIC。请遵循以下步骤为 Windows Server VM 配置 TCP/IP：

1.  **打开 Windows Server VM 的“设置”边栏选项卡，然后选择“网络”。**
    “网络”边栏选项卡提供一目了然的 TCP/IP 配置，并提供指向关联网络资源的直接超链接：
    *   vNIC
    *   虚拟网络
    *   公共 IP 地址
    *   网络安全组
    我在[图 5-10](#c05.xhtml#c05-fig-0010) 中展示了此界面。如果你是从上一练习中使用的 Simple Windows VM 模板部署的 Windows Server VM，你会惊讶地发现 VM 没有受到 NSG 的保护。你可以解决这个问题。

2.  **在 Azure 搜索框中，浏览到“网络安全组”边栏选项卡，然后单击“添加”。**
    ![警告](images/warning.png) 请务必将任何额外的 NSG 放置在与你的 NSG 相同的 Azure 区域中。否则，你的 VM 和 VNet 都无法使用它们。
    如果你一直在按顺序阅读本书（我衷心希望如此），你已经知道如何创建 NSG。

3.  **添加一条入站规则以允许入站远程桌面协议流量。**
    你将在第 4 章中学习如何创建网络安全组。

4.  **浏览到 VM 的“网络”边栏选项卡，然后选择其 vNIC。**
    你需要将新的 NSG 与 VM 的 vNIC 关联，以防止基于 Internet 的访问。

5.  **从“网络接口”设置菜单中选择“网络安全组”，单击“编辑”，选择新的 NSG，然后单击“确定”。**
    现在我们说到点子上了！通过这一简单步骤，你已大幅减少了这台新 VM 的攻击面。

6.  **在“网络接口”设置中，选择“IP 配置”设置，然后单击 `ipconfig1`。**
    vNIC 始终有一个名为（毫无想象力地）`ipconfig1` 的单一 IP 配置。你需在 IP 配置中指定专用和公用 IP 地址。
    [图 5-10](#c05.xhtml#c05-fig-0010) 将引导你完成在 Azure 中查找 IP 地址存储位置的点击路径：
    1.  在网络接口的设置列表中，单击“IP 配置”。
    2.  单击 `ipconfig1`（默认 IP 配置）。
    3.  根据需要调整公用和专用 IP 地址。
    ![图 5-10：Azure 门户中的 Azure VM TCP/IP 设置。](images/9781119612148-fg0510.png)
