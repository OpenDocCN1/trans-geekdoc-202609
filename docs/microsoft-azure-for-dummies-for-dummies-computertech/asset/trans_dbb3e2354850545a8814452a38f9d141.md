## ARM 管理范围

在计算机的文件系统中，存在已定义的层次结构：卷、文件夹、子文件夹和文件。在较高范围设置的权限通过继承流向较低范围。例如，授予 Pat 对服务器 E 盘的只读访问权限，将导致 Pat 继承对 E 盘所有文件夹、子文件夹和文件的只读访问权限。

[图 2-2：](#c02.xhtml#rc02-fig-0002) 你可以定位并下载每个 Azure 资源背后的 JSON 源代码。

继承和多层范围在 Azure 中的工作方式大致相同。所有资源组都包含在 Azure 订阅中，你可以将一个或多个订阅汇总到一个管理组中。这些管理范围（请参阅 [图 2-3](#c02.xhtml#c02-fig-0003)）简化了向资源（最终是其用户）授予基于角色的访问控制授权分配和治理策略的过程。

让我举个例子说明 Azure 管理员如何组合使用这些管理范围。请先跟着我的思路走；等你读完本书时，你将对这些概念有深入的了解。

假设一位管理员需要确保其他 Azure 管理员部署的任何 VM 仅位于企业授权的区域中。但我要使此场景复杂化：该组织的 VM 分散在 6 个订阅的 44 个资源组中。哇！即使有继承机制，这里的管理开销也将非常巨大。

但情况并非乍看之下那么糟糕。管理员创建一个包含这六个企业订阅的单一管理组。然后她创建一个定义资源部署规则的单一 Azure 策略，并将该策略与管理组关联。Azure 策略通过继承流经其包含的订阅和资源组，作用于现有和未来的 VM，这实现了强大而高效的管理。

## 熟悉 Azure 区域

在公有云计算中，你将资源存储在 Microsoft 的物理基础设施中。（请参阅 [第 1 章](#c01.xhtml)。）此基础设施由遍布全球的庞大数据中心网络组成。

这个（可以说是）Azure 数据中心的“环球网”意味着你可以将云资源在地理上放置在靠近客户的位置，从而为他们提供连接到你应用程序的低延迟、高性能连接。在撰写本书时，Microsoft 在 140 个国家/地区拥有 54 个区域。每个区域由一个或多个独立的物理数据中心组成，并具有冗余的高速网络互连。

### 可用性区域

当你在 Azure 中托管面向客户的服务时，高可用性应是你最关心的问题。如果主区域的数据中心发生故障，你有什么应对计划？

Microsoft 正在逐步在其区域地图中推出可用性区域。从本质上讲，`可用性区域` 允许你在同一区域的不同数据中心中放置副本 VM。换句话说，可用性区域代表单个 Azure 区域内的独立位置。

[图 2-4](#c02.xhtml#c02-fig-0004) 说明了这一概念：两个配置相同的 Web 服务器 VM 分别放置在我的主区域中的两个可用性区域内。VM 前面的 Azure 负载均衡器使这两个 VM 均可在同一 IP 地址或域名系统主机名下访问。通过此设置，如果我的某个 VM 脱机（由于我自己的错误或 Microsoft 数据中心中断），我的服务仍保持在线且功能正常。

### 地理位置

Microsoft 将其区域组织为地理位置，以支持企业合规性和数据驻留要求。

### 特殊区域

Azure 被称为公有云服务，因为其大多数区域和服务可供公众购买。也就是说，Microsoft 托管称为政府云或主权云的特殊区域，供全球特定政府机构专用（请参阅 [第 1 章](#c01.xhtml)）。

Azure Government 区域对非政府雇员不可见（不可见）。在撰写本书时，Microsoft 为美国、中国和德国政府维护独立的区域、可用性区域和数据中心。

### 区域对

本章前面提到，你可以将 Azure 服务的冗余副本放置在多个区域中以实现故障转移冗余。当你这样做时，应首先确定 Microsoft 指定的配对区域，以确保最低延迟。

Microsoft 在配对区域之间构建了额外的高速网络连接，这向客户保证其多区域部署不会遭受过度延迟。

搜索 [`https://docs.microsoft.com/azure`](https://docs.microsoft.com/azure) 中的文章“业务连续性和灾难恢复 (BCDR)：Azure 配对区域”，其中包含配对区域的主列表。

![提示](images/tip.png)在我的 Azure 咨询工作中，我建议客户通过访问 Azure Speed Test 2.0 [`https://azurespeedtest.azurewebsites.net/`](https://azurespeedtest.azurewebsites.net/) 来测试其位置与 Azure 之间的延迟。你可能会发现，延迟最低的 Azure 区域并非你想象的那个。

### 功能可用性

Azure 产品团队逐步在区域地图中推出新功能，因此某些产品目前可能在你的主区域中不可用。

因此，密切关注“按区域提供的产品”页面 [`https://azure.microsoft.com/en-us/global-infrastructure/services/`](https://azure.microsoft.com/en-us/global-infrastructure/services/) 非常重要。同样的指导原则也适用于 Azure Government 区域。大多数时候，我发现新功能始于 Azure 公有云，很久之后才进入主权云。
