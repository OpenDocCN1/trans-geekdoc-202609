### 密码
您的密码长度需在 8 到 128 个字符之间。密码不能包含登录名的任何部分，且必须具备复杂性特征，例如大小写字母、数字和非字母数字字符的混合。

### 网络配置
在 **网络** 选项卡上，选择 **允许 Azure 服务和资源访问此服务器**。

此设置颇具争议但至关重要。启用后，所有 Azure IP 地址都将共享一条通往您虚拟 SQL 服务器的连接路径。该设置绝不会授予访问权限，而只是提供了这种可能性。

许多管理员在需要将 SQL 数据库与 Azure Key Vault、存储帐户、HDInsight 和 Azure Data Factory 等服务集成时，都需要此设置。

您可以将 **其他设置** 和 **标记** 选项卡的设置保留为默认值。

### 部署
单击 **查看 + 创建**，然后单击 **创建** 以将部署提交给 Azure 资源管理器 (`ARM`)。

![技术细节](images/technicalstuff.png) Azure 不会向您收取虚拟服务器的费用。SQL 数据库的费用来自于您放置在虚拟服务器上的数据库，而非虚拟服务器本身。

## 部署 SQL 数据库

接下来，您需要部署一个 Azure SQL 数据库虚拟服务器以及 AdventureWorks 示例数据库，后者为您提供了一些预先存在的数据供您操作。首先创建虚拟服务器，然后添加数据库。

![技术细节](images/technicalstuff.png) AdventureWorks 示例数据库拥有悠久的历史。有关详细信息，请访问 [`https://www.microsoft.com/en-us/download/details.aspx?id=10331`](https://www.microsoft.com/en-us/download/details.aspx?id=10331)。

使用您的管理员帐户登录 Azure 门户，然后执行以下步骤：

1.  **在 Azure 门户中，浏览到 SQL 数据库边栏选项卡，然后单击“添加”。**

2.  **在“创建 SQL 数据库”边栏选项卡上，完成“基本信息”选项卡（如 [图 9-3](#c09.xhtml#c09-fig-0003) 所示）。**

    使用以下信息填写字段：

    *   **数据库名称：** 此名称无需全局唯一。
    *   **服务器：** 列表中应包含您在上一节（“[部署 SQL 数据库虚拟服务器](#c09.xhtml#c09-sec-0016)”）中创建的虚拟服务器。
    
    ![图 9-3：创建 Azure SQL 数据库数据库。](images/9781119612148-fg0903.png)
    
    [图 9-3：](#c09.xhtml#rc09-fig-0003) 创建 Azure SQL 数据库数据库。

    *   **是否要使用 SQL 弹性池？：** 对于此示例，回答“否”。
    *   **计算 + 存储：** 选择 **配置数据库**，在 **配置** 边栏选项卡上（请参阅 [图 9-4](#c09.xhtml#c09-fig-0004)），选择 **正在寻找基本、标准、高级？**。然后选择 **标准** 层。

        ![提示](images/tip.png) 因为您只是在测试，所以无需为数据库计算层“超配”。选择标准层是个好主意，因为它解锁了您所需的大多数管理和安全功能。

3.  **单击“应用”以确认您的选择。**

4.  **完成“其他设置”页面。** 

    *   **数据源：** 示例。此选项指示 Azure 还原 AdventureWorksLT 示例数据库。(`LT` 是 `light` 的缩写，指数据库的精简版本。)

5.  **单击“查看 + 创建”，然后单击“创建”以将部署提交给 ARM。**

## 配置数据库

本节介绍一些最常见的 SQL 数据库配置设置。

![提示](images/tip.png) 每当您需要熟悉新的 Azure 资源时，请查看资源“设置”列表中的“快速入门”边栏选项卡。此边栏选项卡提供提示、过程和文档链接。

### 防火墙

SQL 数据库防火墙是一个软件定义的网络组件，可保护您的数据库免受未经授权的入站连接。

您可以在虚拟服务器级别或数据库级别配置防火墙。设置服务器防火墙的优势在于，您可以使用单一配置保护多个数据库。

要进行配置，请从数据库打开服务器防火墙：浏览到 **概述** 边栏选项卡，然后单击工具栏上的 **设置服务器防火墙**。

SQL 数据库防火墙由三个组件组成：

*   **允许访问 Azure 服务：** 此选项启用来自所有 Azure 源公共和专用 IP 地址的连接流量。此设置不构成授权，您需要单独配置授权。
*   **客户端 IP 地址和 IP 规则：** 这些设置允许从您本地工作站的公共 IP 地址进行数据库连接。您还可以定义一个允许连接到数据库的公共 IP 地址范围列表。
*   **虚拟网络：** 如果您在虚拟网络中定义了 SQL 数据库服务终结点，则可以在此处完成配置，以将对虚拟服务器的访问限制为来自该网络的访问。

### 连接字符串

数据库连接字符串代表您的应用程序与数据库本身之间的接口。SQL 数据库提供四种驱动程序选择：

*   **ADO.NET：** 通常用于 .NET 应用程序
*   **JDBC：** 通常用于 Java 应用程序
*   **ODBC：** 通用驱动程序
*   **PHP：** 通常用于 PHP 应用程序

选择最适合您的应用程序及您的开发团队技能组合的连接字符串。

### 异地复制

依我之见，为 SQL 数据库配置异步复制的能力是 PaaS 的杰出功能之一。极少有企业拥有资源自行完成此配置。

您可能会将数据库复制到另一个区域以实现故障转移；这意味着如果主数据库脱机，您可以将连接重定向到辅助备用数据库副本。异地复制的另一个好处是能够针对副本数据库运行只读查询，而不会给您的用户造成阻塞问题。

请执行以下步骤为 SQL 数据库启用异地复制：

1.  **在数据库的“设置”边栏选项卡上，单击“异地复制”。**

    将出现一张全球地图。

2.  **在“目标区域”列表中，选择您想要用于托管辅助数据库的区域。** [图 9-5](#c09.xhtml#c09-fig-0005) 显示了此界面。

    ![提示](images/tip.png) 考虑选择指定为您的主要区域配对的区域。Microsoft 会在配对区域之间建立额外的高速网络连接以减少延迟。您不必使用配对区域，但这样做是个好主意，因为可以减少区域间的网络延迟。

    ![图 9-5：为 Azure SQL 数据库配置异地复制。](images/9781119612148-fg0905.png)

    [图 9-5：](#c09.xhtml#rc09-fig-0005) 为 Azure SQL 数据库配置异地复制。

    ![技术细节](images/technicalstuff.png) 在 Azure 文档中查看 Azure 主要区域和次要区域的映射：[`https://docs.microsoft.com/en-us/azure/best-practices-availability-paired-regions`](https://docs.microsoft.com/en-us/azure/best-practices-availability-paired-regions)。

3.  **完成“创建辅助数据库”配置边栏选项卡，然后单击“确定”以保存更改。**

    您需要在次要区域中创建一个虚拟服务器。创建辅助数据库会产生定价影响，但为了省钱，您可以在比主数据库更低的定价层上运行辅助数据库。
