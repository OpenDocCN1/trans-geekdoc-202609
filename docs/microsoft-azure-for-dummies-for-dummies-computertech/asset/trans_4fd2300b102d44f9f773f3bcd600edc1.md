
作为云顾问，我的一大乐趣是向客户展示他们不必使用 Azure VM。Azure 包含许多出色的平台即服务 (PaaS) 选项，例如 Azure 应用服务和 Azure SQL 数据库，这些选项可以提供地理缩放和快速敏捷性。

如果你需要对环境进行全栈控制，Azure 完全支持 VM。在本章中，我将解释各种 Azure VM 选项，以及如何在 Azure 中部署和配置 Windows Server 和 Linux VM。

## 规划 VM 部署

你可能还记得木匠的格言“三思而后行”，这强调了在投入项目之前进行规划的重要性。对于 Azure VM 部署，你需要深思熟虑，以便第一次就做出正确的决定；否则，你就有删除并重新创建 VM 的风险。

然而，在规划部署之前，你需要了解 VM 在 Azure 中是如何运行的。

### 理解 VM

VM 是计算机的软件表示。每个 Azure 区域由多个数据中心组成；每个数据中心由数千台硬件刀片服务器组成。VM 在这个庞大的计算结构中运行。

每个 VM 都从其父硬件主机分配虚拟硬件资源：

*   计算（CPU [中央处理器] 和 RAM [随机存取存储器]）
*   存储
*   网络

![Technical stuff](images/technicalstuff.png)Microsoft 的数据中心服务器运行专用版 Windows Server Core，你的 VM 位于 Microsoft Hyper-V 主机上。相比之下，Amazon Web Services (AWS) 在开源 Xen 管理程序下运行其弹性计算云 VM 实例。

截至撰写本文时，Microsoft Azure VM 服务支持以下 64 位版本：

*   Windows 7
*   Windows 8.1
*   Windows 10
*   Windows Server 2008 R2
*   Windows Server 2012 R2
*   Windows Server 2016
*   Windows Server 2019

![Tip](images/tip.png)Microsoft 仅出于开发目的支持 Azure 中的 Windows 客户端 VM 映像。其理念是开发人员可以部署 Windows 客户端 VM，将其用作针对基于云的业务线应用程序的测试代理。

Azure 还支持以下认可的 64 位 Linux 发行版：

*   CentOS
*   CoreOS
*   Debian
*   OpenSUSE
*   Oracle Linux
*   Red Hat Enterprise Linux
*   SUSE Enterprise Linux
*   Ubuntu

### 从 Azure 市场开始 VM 部署

在 Azure 中部署 VM 的最快方法可能是从 Azure 市场进行部署。Azure 市场是一个在线集市，包含数千个 Microsoft 和非 Microsoft VM 映像，包括本章前面所述的所有裸操作系统 (OS) 映像。[图 5-1](#c05.xhtml#c05-fig-0001) 显示了 Azure 市场。

你可以通过在 Azure 门户的全局搜索框中输入 `marketplace` 来访问 Azure 市场。

### 从本地环境开始 VM 部署

在[第 13 章](#c13.xhtml)中，我将解释如何使用 Azure Migrate 将本地物理服务器和虚拟服务器迁移到 Azure。话虽如此，你始终可以将通用的 OS 映像上传到 Azure。为此，你需要一个快速的 Internet 连接或到 Azure 云的专用连接；仅此而已。

[图 5-1：](#c05.xhtml#rc05-fig-0001) Azure 市场是多种 VM 类型的一站式商店。

![Warning](images/warning.png)我在此提供的说明仅供参考，并不全面。请查阅 Azure 文档，以获取关于准备本地 Linux 和 Windows Server VM 以上传到 Azure 的完整分步指导。

以下是常规工作流：

1.  **准备 VM 磁盘以上传到 Azure。**

    如果你的本地 VM 不是 Hyper-V，则需要使用适当的工具进行转换。虽然 Azure 支持 Hyper-V 第 2 代虚拟硬盘 (VHD)，但磁盘必须采用 `.vhd` 格式（而非 `.vhdx`）才能在 Azure 中工作。

    要将 `.vhdx` 虚拟磁盘转换为固定大小的 `.vhd`，可以在本地 Hyper-V 主机上运行 `Convert-VHD` PowerShell cmdlet，如下所示：

    ```
    Convert-VHD –Path d:\dev\vm1-gen2.vhdx –DestinationPath d:\dev\vm1-gen1.vhd -VHDType Fixed
    ```

    ![Tip](images/tip.png)顺便说一下，PowerShell 命令通常称为“cmdlet”，发音为 *command-lets*。

    另请注意，你的 OS VHD 必须是通用的。通用化会从 VM 磁盘映像中删除所有唯一信息，包括安全标识符、静态 IP 地址、主机名等。在 Windows Server 中，你可以使用内置的 Sysprep 实用程序。

2.  **将通用的 OS 映像上传到 Azure 存储帐户的 Blob 服务。**

    有关使用存储帐户和 Azure 存储资源管理器工具的更多信息，请参阅[第 3 章](#c03.xhtml)。

3.  **使用 Azure PowerShell 将上传的 VHD 添加到 Azure 托管存储服务，步骤如下。**

    1.  *定义一些变量以使代码更整洁：*

        ```
        $vmName = "vm1"
        $rgName = "myResourceGroup"
        $location = "EastUS"
        $imageName = "myImage"
        $osVhdUri = "https://mystorageaccount.blob.core.windows.net/vhds/vm1-gen1.vhd"
        ```

    2.  *创建 Microsoft 所谓的*托管映像*：*

        ```
        $imageConfig = New-AzImageConfig -Location $location
        $imageConfig = Set-AzImageOsDisk -Image $imageConfig -OsType Windows -OsState Generalized -BlobUri $osVhdUri
        $image = New-AzImage -ImageName $imageName -ResourceGroupName $rgName -Image $imageConfig
        ```

4.  **使用托管映像进行 VM 部署。**

## 识别 Azure VM 组件

从更高层次的抽象来看，Azure 虚拟机是一种云资源，由以下三个子系统组成：

*   计算
*   存储
*   网络

在解释如何部署和配置 VM 之前，我将介绍 Azure VM 如何实现这些子系统。

### 计算

你需要为 Azure VM 分配并运行的每一分钟付费。*已分配*意味着 Microsoft 为你的 VM 预留硬件计算能力——主要是 CPU 和 RAM 资源。

可用的 VM 实例大小分为多个系列。[表 5-1](#c05.xhtml#c05-tbl-0001) 列出了 Windows Server VM 大小及每种大小的预期工作负载，这将帮助你了解 VM 大小系列之间的差异。你可以在 Azure 文档 (`https://docs.microsoft.com/en-us/azure/virtual-machines/linux/sizes`) 中找到关联的 Linux VM 大小。

[表 5-1](#c05.xhtml#rc05-tbl-0001) Azure 中的 Windows Server VM 大小

| **系列** | **大小** | **预期工作负载** |
| --- | --- | --- |
| 通用 | B, Dsv3, Dv3, Dasv3, Dav3, DSv2, Dv2, Av2, DC | 测试和开发 |
| 计算优化 | Fsv2 | Web 服务器 |
| 内存优化 | Esv3, Ev3, Easv3, Eav3, Mv2, M, DSv2, Dv2 | 数据库服务器 |
| 存储优化 | Lsv2 | 大数据工作负载 |
| GPU | NC, NCv2, NCv3, ND, NDv2, NV, NVv3 | 繁重的图形渲染作业 |
| 高性能计算 | HB, HC, H | 高性能计算 |

![Tip](images/tip.png)如果你不因合规目的而绑定到特定的 Azure 区域，请考虑在部署 VM 之前货比三家，因为在不同区域运行 VM 会产生显著不同的成本。价格差异源于电力成本、物理工厂成本等，这些因 Azure 数据中心所在的区域而异。

随着时间的推移，你将通过检查其 ID 标签来识别特定 VM 大小来自哪个系列。例如，D 系列 VM 属于通用型，因此是 Azure 客户最常使用的。请注意，这些大小是有版本的；例如，你可以期望 v3 映像拥有 v2 映像没有的功能。
