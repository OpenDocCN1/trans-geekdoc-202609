The connection between neurons that flows in one direction is called feed-forward networks. This flow direction goes from the input layer, through hidden layers that contain the neurons, to the output layers (see Fig. 8.1). There are two feed-forward network types have been used by many authors in rainfall-runoff modeling: The Multilayer Perceptron (MLP) and the Radial-Basis function (RBF). The MLP is defined by Solomatine and Wagener (2011) as a device that consists of several layers of mutually interconnected neurons, which transform the inputs using a multiparameter nonlinear transformation so the resulting model is capable of approximate complex input-output relationships. The objective of the training process is to optimize the number of neurons and hidden layers to which the network is applied using a trial and error procedure (Shamseldin, 1997). If there are too few neurons in the hidden layer, the Artificial Neural Network may not be capable of reproducing the output function. On the contrary, if there are too many neurons, the ANN may overfit the output function, losing the ability to generalize (Dawson & Wilby, 2001). The Radial-Basis function is a feed-forward ANN, similar in topology to the MLP (Fernando & Jayawardena, 1998), which tries to approximate a function y = f(x) by a superposition of other functions F(x,σ), where σ is a parameter that characterizes the width of the function in the input space (Solomatine & Wagener, 2011). Typically, Gaussian functions are used as RBF functions. More details on RBF networks can be seen in Dayhoff (1990), Fernando and Jayawardena (1998), Dawson and Wilby (2001), Sudheer and Jain (2003), and Solomatine and Wagener (2011).

# 8.2.2. Data Partitioning

Data analysis and preparation is an important procedure in developing hydrological models. In particular, a DDM Rainfall-Runoff model requires that the complete data set should be separated into three different data sets: training (i.e., calibration), cross-validation, and verification. This particular data partitioning in DDM models is quite different from the standard procedure for calibration in conceptual and physically based models since the data are split into two data sets: calibration and verification. The cross-validation data set serves as a small test set, which avoids overfitting of the function and stops the training process. The verification data set serves as testing set, which allows seeing how the model would perform if new data were fed into it.
