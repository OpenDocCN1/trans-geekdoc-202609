# 前言

我第一次听说 WebGPU 时，并没有特别印象深刻。WebGL 或 WebGL 2.0 并没有问题，所以我看不出另一个 API 的必要性。看起来科技公司正在为不存在的问题创造解决方案。

但我越想越感兴趣。我记得在浏览器中检查电子邮件曾是革命性的，我也清楚记得在浏览器中观看电影的想法曾显得荒谬。今天，这些活动已司空见惯。

随着每年的推移，越来越多的应用程序迁移到浏览器中，这是有原因的。每个人都知道如何使用浏览器，Web 应用程序不需要复杂的安装或卸载。此外，运行在浏览器内部的应用程序（通常）不会像运行在浏览器外部的应用程序那样损坏你的系统。

在我看来，在浏览器中运行应用程序的最后障碍是 *性能*。如果浏览器中的计算机游戏运行性能与普通游戏相同，我会很乐意在浏览器中玩游戏。如果浏览器中的建模工具执行速度与浏览器外的建模应用程序一样快，我也会很满意。

由于 WebGPU 使 Web 应用程序能够访问 GPU，这一最后的障碍很可能被克服。随着我对该主题了解得越多，我对 API 的简洁性感到印象深刻。与 OpenGL 不同，WebGPU 不需要顶点缓冲对象和顶点数组对象。与 Vulkan 不同，WebGPU 不需要冗长的交换链和表面配置。

我很高兴有机会介绍这一迷人的主题，并将本书内容分为三个部分。第一部分从高层次介绍 WebGPU，不涉及图形渲染或计算。该部分由 [第1章](#chapter1.xhtml) 和 [第2章](#chapter2.xhtml) 组成，其中介绍了应用程序为了访问 GPU 而需要创建的众多 JavaScript 对象。

第二部分中的章节专注于图形渲染。这从 [第3章](#chapter3.xhtml) 开始，其中介绍了整体渲染过程并介绍了图形应用程序中需要创建的对象类型。[第4章](#chapter4.xhtml) 更进一步，讨论了 WebGPU 着色语言（WGSL），该语言用于为图形应用程序编写顶点和片段着色器。

[第5章](#chapter5.xhtml) 介绍了创建三维场景时至关重要的两个主题。第一个涉及创建统一缓冲区，用于存储在渲染过程中保持不变的数据。第二个主题是变换，它使顶点在场景内移动成为可能。变换也用于定义场景的整体形状，称为 *视野区域*。

而 [第5章](#chapter5.xhtml) 专注于设置物体的位置，[第6章](#chapter6.xhtml) 则专注于设置其颜色。光照是定义场景如何被照亮以及光照如何反射到物体表面的过程。此外，纹理包含可用于为物体表面分配像素的图像数据。[第7章](#chapter7.xhtml) 探讨了与 WebGPU 相关的一些高级主题，包括调试、模板映射和访问视频。

本书的第三部分专注于计算着色器。[第8章](#chapter8.xhtml) 展示了如何编写和执行计算应用程序，并解释了工作组和组本地内存这一重要主题。[第9章](#chapter9.xhtml) 展示了计算着色器如何用于实现机器学习。具体来说，它展示了如何编写一个使用神经网络对数据进行分类的计算应用程序。

[第10章](#chapter10.xhtml) 解释了 WebGPU 如何使图像和视频处理成为可能。[第11章](#chapter11.xhtml) 展示了如何对大型矩阵执行操作，包括转置、乘法和分解。[第12章](#chapter12.xhtml) 解释了 WebGPU 应用程序如何使用快速傅里叶变换（FFT）高速过滤音频。

[附录 A](#appa.xhtml#appa) 和 [附录 B](#appb.xhtml#appb) 介绍了 WebGPU 标准中未讨论但可能仍对读者感兴趣的主题。[附录 A](#appa.xhtml#appa) 解释了如何使用 TypeScript 编写 WebGPU 应用程序，TypeScript 增加了静态类型和改进的错误检查。[附录 B](#appb.xhtml#appb) 讨论了有趣的 Google Dawn 主题，它使能够用 C/C++ 编写 WebGPU 程序。

# 引言1

DOI: [10.1201/9781003422839-1](https://doi.org/10.1201/9781003422839-1)

在高性能计算领域最非凡的发展之一是图形处理单元（GPU）的使用。在 2010 年之前，世界上排名前列的超级计算机都没有 GPU。但在 2010 年 11 月，中国的曙光-1A 超级计算机凭借其 7,168 个 GPU 大部分原因占据了 TOP500 的榜首。此后，每一台排名第一的超级计算机都拥有数千个 CPU 和 GPU。截至 2023 年 11 月，世界上排名第一的超级计算机是 Frontier 系统，拥有 561,664 个 CPU 核心和 36,992 个 GPU 核心。

图形处理器深受游戏玩家和性能爱好者的喜爱，但它们编程起来可能很困难。GPU 架构与 CPU 架构如此不同，以至于代码需要重新结构化和重写。除此之外，选择编程工具集也不容易：

*   OpenGL 和 OpenCL 多年来没有显著进展。
*   CUDA 仅在 Nvidia 设备上运行。
*   Direct3D 仅在 Windows 系统上运行。
*   Metal 仅在 macOS 系统上运行。
*   Vulkan 极其复杂。
