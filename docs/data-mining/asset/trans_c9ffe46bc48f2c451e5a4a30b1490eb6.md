
[图 C.8A](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 显示了在此数据下以最小支持度阈值为 6 时得到的 FP 树结构。树本身用实线箭头表示。每个节点上的数字表示已排序的项前缀（包括该节点处的项）到该节点为止在数据集中出现的次数。例如，沿着树中从左数起的第三个分支可以看出，排序后有两个实例以前缀 `humidity = high` 开始——即 [表 C.1C](#FigC1_655-685_B9780443158889000236.xhtml#t0010) 的第二个和最后一个实例。沿着该分支继续向下，下一个节点记录了同样的两个实例其下一个最频繁的项也是 `windy = true`。该分支中的最低节点显示，这两个实例中的一个（[表 C.1C](#FigC1_655-685_B9780443158889000236.xhtml#t0010) 中的最后一个）也包含 `temperature = mild`。另一个实例（表中的第二个）在此阶段被剔除，因为其下一个最频繁的项未满足最小支持度约束，因此从树中省略。

## 查找大项集

从头表到树结构的链接的目的是便于遍历树以查找除树中已有的两个之外的其他大项集。这是通过一种分而治之的方法实现的，该方法递归地处理树以增长大项集。每个头表列表依次被跟随，从表的底部开始向上工作。实际上，头表可以按任何顺序处理，但先处理树中最长的路径更容易思考，而这些路径对应于频率较低的项目。

从头表的底部开始，我们可以立即将 `temperature = mild` 添加到大项集列表中。[图 C.8B](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 显示了下一阶段的结果，即仅包含数据集中包含 `temperature = mild` 的实例的 FP 树。该树并非通过重新扫描数据集创建，而是通过进一步处理 [图 C.8A](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 中的树创建，如下所示。

为了查看是否可以扩展包含 `temperature = mild` 的更大项集，我们跟随其从头表的链接。这使我们能够找到所有包含 `temperature = mild` 的实例。从这里开始，[图 C.8B](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 中的新树被创建，其计数从原始树投影，对应于以 `temperature = mild` 存在为条件的实例集合。这是通过将计数从 `temperature = mild` 节点向上传播到树中完成的，每个节点接收其子节点的计数之和。

快速查看此新 FP 树的头表可知，`temperature = mild` 模式无法再扩展，因为在以 `temperature = mild` 为条件的情况下，没有单个项目满足最小支持度阈值。然而，需要创建整个 [图 C.8B](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 树来发现这一点，因为它实际上是自底向上创建的，左侧头表中的计数是从树中的数字计算得出的。递归在此点退出，处理继续进行原始 FP 树中剩余的头表项目。

[图 C.8C](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 显示了第二个示例，即跟随 `humidity = normal` 的头表链接后得到的 FP 树。这里 `windy = false` 节点的计数为 4，对应于原始树中其左分支中具有 `humidity = normal` 的四个实例。同样，`play = yes` 的计数为 6，对应于来自 `windy = false` 的四个实例以及来自 [图 C.8A](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 中以 `play` = `yes` 为根的子树的中间分支中包含 `humidity = normal` 的两个实例。

处理此 FP 树的头列表显示，`humidity = normal` 项集可以扩展以包含 `play = yes`，因为这两个项一起出现了六次，满足最小支持度约束。这对应于 [表 C.1D](#FigC1_655-685_B9780443158889000236.xhtml#t0010) 中的第二个项集，实际上完成了输出。然而，为了确保没有其他合格的项集，有必要继续处理 [图 C.8A](#FigC1_655-685_B9780443158889000236.xhtml#f0045) 中的整个头链接表。

一旦递归树挖掘过程完成，所有满足最小支持度阈值的大项集都已找到。然后使用 [第 4.5 节](#Ch004_91-164_B9780443158889000054_a.xhtml#s0075) 中解释的方法创建关联规则。研究声称 FP-growth 算法在查找大项集时比 Apriori 快一个数量级，尽管这取决于实现的细节和数据集的性质。

## 讨论

递归创建投影 FP 树的过程可以通过在树的每个节点和头表的每个元素中维护一个按递归深度索引的频率列表，在单个前缀树结构中高效实现。树结构本身通常远小于原始数据集，如果数据集密集，则可实现高度压缩。这抵消了在每个节点上必须维护指针和计数器所带来的开销。只有当支持阈值设置得非常低时，FP 树压缩数据集的能力才会下降。在这种条件下，树变得繁茂，节点共享很少。对于 FP 树超过主内存的大规模数据集，可以使用为关系数据库系统开发的索引技术构建磁盘驻留树。
