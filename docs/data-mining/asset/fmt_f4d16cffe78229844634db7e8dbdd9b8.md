
[Hochreiter and Schmidhuber (1997)](#References_705-736_B978044315888900025X.xhtml#fur271) is the seminal paper on the “long short-term memory” architecture for recurrent neural networks; our explanation follows Graves and Schmidhuber’s (2005) formulation. Greff, Srivastava, Koutník, Steunebrink, and Schmidhuber’s (2015) paper “LSTM: A search space odyssey” explored a wide range of variants and found that: (1) none of them significantly outperformed the standard LSTM architecture; and (2) forget gates and the output activation function were the most critical components. Forget gates were added by [Gers, Schmidhuber, and Cummins (2000)](#References_705-736_B978044315888900025X.xhtml#fur212).

IRNNs were proposed by [Le, Jaitly, and Hinton (2015)](#References_705-736_B978044315888900025X.xhtml#fur212), while [Chung, Gulcehre, Cho, and Bengio (2014)](#References_705-736_B978044315888900025X.xhtml#fur100) proposed gated recurrent units and [Schuster and Paliwal (1997)](#References_705-736_B978044315888900025X.xhtml#fur481) proposed bidirectional recurrent neural networks. [Chen and Chaudhari (2004)](#References_705-736_B978044315888900025X.xhtml#fur92) used bidirectional networks for protein structure prediction, while [Graves et al. (2009)](#References_705-736_B978044315888900025X.xhtml#fur231) used them for handwriting recognition. [Cho et al. (2014)](#References_705-736_B978044315888900025X.xhtml#fur98) used encoder-decoder networks for machine translation, while [Sutskever, Vinyals, and Le (2014)](#References_705-736_B978044315888900025X.xhtml#fur514) proposed deep encoder-decoder networks and used them with massive quantities of data. Residual connections, proposed by [He et al. (2016)](#References_705-736_B978044315888900025X.xhtml#fur257), were a substantial architectural advance that eased the training of much deeper neural networks.

For further accounts of advances in deep learning and a more extensive history of the field, consult the reviews of [LeCun, Bengio, and Hinton (2015)](#References_705-736_B978044315888900025X.xhtml#fur357), [Bengio (2009)](#References_705-736_B978044315888900025X.xhtml#fur30), and [Schmidhuber (2015)](#References_705-736_B978044315888900025X.xhtml#fur476).

## 10.7 Deep Learning Software and Network Implementations

Deep learning software frameworks make it easy to develop and train deep neural network models. These frameworks typically include high-level APIs (“application programming interfaces”) that allow a model to be specified with a few lines of code; automatic differentiation features that remove the manual burden of deriving gradients, GPU support, implementations of advanced learning algorithms and deep learning architectures, and more. They generally represent the data flow in a deep neural network (or other computation) as a `computation graph`, in which the mathematical operations at each stage of the computation—and their relation to each other—are encoded as a graph. By storing the graph in advance, computations can be optimized, and backpropagation can be automatically performed with gradients flowing through the graph in the “backward pass” in the opposite direction to the original “forward pass” computations. Many of these frameworks are open source and freely available.

The most popular deep learning software platforms are currently TensorFlow and PyTorch. Historically, TensorFlow, which is developed mainly by Google, was generally viewed as better for creating deployed systems, while PyTorch, which is developed mainly by the Facebook AI Research group, was considered by many to be better for academic research due to advantages in development and debugging. The gaps between the two platforms have substantially closed, however, with both platforms addressing their perceived weaknesses vs their competition in their recent versions. Now, both platforms are highly capable for both the deployment and development phases.

### TensorFlow and Keras

TensorFlow is a C++ and Python-based software library for the types of numerical computation typically associated with deep learning ([Abadi et al., 2016](#References_705-736_B978044315888900025X.xhtml#fur1)). It uses dataflow graphs to represent the ways in which multidimensional data arrays communicate between one another. These multidimensional arrays are referred to as “tensors.” TensorFlow also supports symbolic differentiation and execution on multiple GPUs. It was released in 2015 and is available under the Apache 2.0 license. In earlier versions building DNN models in TensorFlow involved first explicitly specifying a computation graph and then starting a session that the model is run in. Now, in TensorFlow version 2, a high-level API, Keras, is more tightly integrated into TensorFlow, allowing the developer to focus on the model rather than its underlying graph, and it now defaults to an eager execution mode, which obviates the need to deal with sessions and aids debugging.

Keras is a deep learning library that allows users to specify deep neural network models with simple Python code. Keras emphasizes its easy-to-use interface, and it requires another deep learning framework as a backend. Although Keras previously temporarily only supported TensorFlow, it currently also supports PyTorch and JAX backends.

### PyTorch

PyTorch is a Python ML and deep learning framework. It is based on the Torch library, an open-source ML library built using C and a high-level scripting language known as Lua ([Collobert, Kavukcuoglu, and Farabet, 2011](#References_705-736_B978044315888900025X.xhtml#fur108)), but was largely rewritten in Python. Similarly to TensorFlow, it uses multidimensional array data structures, supports various basic numerical linear algebra manipulations, and has a neural network package with modules that permit the typical forward and backward methods needed for training neural networks. It also supports automatic differentiation. PyTorch uses `dynamic computation graphs`, also known as a `define-by-run` approach, in which the computation graph can change during execution. This is useful when processing data that can vary in size (e.g., text documents), and it simplifies debugging since the code is run when its corresponding line is executed, enabling more timely error messages. It also made coding in PyTorch closer to coding in native Python, making it more intuitive to code in. Historically, this was an advantage of PyTorch in terms of ease of use over TensorFlow, which traditionally used static computation graphs. However, as of version 2.0 TensorFlow has an “eager execution” mode, essentially the same as dynamic computation graphs, which mitigates this. Since this mode is optional, TensorFlow 2 users can choose whether to use it or stick to static computation graphs, which are faster.

### Other Packages

While TensorFlow, Keras, and PyTorch are currently the most popular deep learning frameworks, other options exist, including:

*   • The `Computational Network Toolkit (CNTK)` is a C++ library for manipulating computational networks ([Yu et al., 2014](#References_705-736_B978044315888900025X.xhtml#fur583)). It was produced by Microsoft Research but has been released under a permissive license. It has been popular for speech and language processing but also supports convolutional networks of the type used for images. It supports execution on multiple machines and using multiple GPUs.

*   • `Caffe` is a C++ and Python-based BSD-licensed CNN library ([Jia et al., 2014](#References_705-736_B978044315888900025X.xhtml#fur290)). It has a clean and extensible design that made it a popular alternative to the original open-source implementation of Krizhevsky et al.’s (2012) famous AlexNet, which won the 2012 ImageNet challenge. Facebook developed an extension to it called Caffe2 but it was merged into PyTorch.
