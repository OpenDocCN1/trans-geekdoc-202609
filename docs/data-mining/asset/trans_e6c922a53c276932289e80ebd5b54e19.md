
## 选项树

另一种方法是推导出一个单一结构，该结构可以紧凑地表示一组分类器。如果该集合由决策树组成，则可以实现；结果称为 `option tree`。选项树与决策树不同之处在于它们包含两种类型的节点：决策节点和选项节点。[图 8.4](#Ch009_323-345_B9780443158889000091.xhtml#f0025) 显示了针对天气数据的简单示例，仅有一个选项节点。对实例进行分类时，将其沿树向下过滤。在决策节点处像往常一样只取其中一个分支，但在选项节点处取 `all` 个分支。这意味着实例会结束于多个叶节点，必须以某种方式将这些叶节点获得的分类组合成整体分类。这可以通过投票简单实现，将选项节点处的多数投票作为该节点的预测。在这种情况下，如果只有两个选项（像 [图 8.4](#Ch009_323-345_B9780443158889000091.xhtml#f0025) 中那样）设置选项节点意义不大，因为只有当两个分支一致时才会有多数。另一种可能性是对不同路径获得的概率估计进行平均，使用未加权平均或更复杂的贝叶斯方法。

![图 8.4 天气数据的简单选项树.](images/F000091f08-04-9780443158889.jpg)

图 8.4 天气数据的简单选项树。

选项树可以通过修改现有的决策树学习器来生成，如果根据信息增益来看有几个分割相似有用，则创建选项节点。在用户指定的容差范围内与最佳选择相近的所有选择都可以作为选项。在剪枝期间，选项节点的误差是其选项的平均误差。

另一种可能性是通过增量添加节点来生长选项树。这通常使用提升算法完成， resulting trees 通常称为 `alternating decision trees` 而不是选项树。在此上下文中，决策节点称为 `splitter nodes`，选项节点称为 `prediction nodes`。如果尚未向其添加分割节点，则预测节点是叶节点。标准交替决策树适用于二分类问题，每个预测节点都关联一个正值或负数值。要为实例获得预测，请向下过滤所有适用分支并汇总遇到的任何预测节点的值；根据总和为正还是负来预测其中一个类别。

天气数据的简单示例树显示在 [图 8.5](#Ch009_323-345_B9780443158889000091.xhtml#f0030) 中，其中正值对应类别 `play = no`，负值对应 `play = yes`。对 `outlook` = `sunny`、`temperature` = `hot`、`humidity` = `normal` 且 `windy` = `false` 的实例进行分类，将其过滤到相应的叶节点，得到值 −0.255、0.213、−0.430 和 −0.331。这些值的总和为负；因此预测 `play` = `yes`。交替决策树在根部始终有一个预测节点，如本示例所示。

![图 8.5 天气数据的交替决策树.](images/F000091f08-05-9780443158889.jpg)

[图 8.5](#Ch009_323-345_B9780443158889000091.xhtml#Bf0030) 天气数据的交替决策树。

交替树使用提升算法生长——例如，使用数值预测的基础学习器的提升算法，如前面描述的 `LogitBoost` 方法。假设基础学习器在每次提升迭代中产生一条合取规则。然后可以通过简单地将每条规则添加到树中生成交替决策树。与预测节点关联的数值分数来自规则的后件。然而，结果树会迅速变得很大，因为不同提升迭代的规则可能不同。因此，交替决策树的学习算法只考虑那些通过添加一个分割节点和两个对应的预测节点（假设二元分割）来扩展树中某个 `existing` 路径的规则。在算法的标准版本中，树中每个可能的添加位置都会被考虑，并根据所采用的特定提升算法的性能度量添加节点。然而，可以使用启发式方法代替穷举搜索来加快学习过程。

### 逻辑模型树

选项树和交替树基于单一结构可提供非常好的分类性能，但在存在许多选项节点时仍可能难以解释，因为难以看出特定预测是如何得出的。然而事实证明，提升也可以用于构建非常有效的决策树，这些树完全不包含任何选项。例如，`LogitBoost` 算法已被用于诱导叶节点具有线性逻辑回归模型的树。这些称为 `logistic model trees`，其解释方式与模型树 for regression described in [第 9.3 节](#Ch010_347-389_B9780443158889000108.xhtml#s0105) 中描述的回归模型树相同。

`LogitBoost` 执行加性逻辑回归。假设提升算法的每次迭代都通过遍历所有属性来拟合一个简单回归函数，找到误差最小的简单回归函数并将其添加到加性模型中。如果 `LogitBoost` 算法运行到收敛，结果是最大似然多元逻辑回归模型。然而，为了在未来数据上获得最佳性能，通常无需等待收敛——而且这样做往往是有害的。可以通过使用交叉验证估计给定迭代次数的预期性能，并在性能停止增加时停止过程来确定适当的提升迭代次数。

该算法的一个简单扩展导致了逻辑模型树。提升过程在数据中不再存在可使用线性逻辑回归函数建模的进一步结构时终止。然而，如果将注意力限制在数据子集上，例如通过使用信息增益等标准决策树准则分割数据获得的数据子集，线性模型仍可能拟合的结构。因此，一旦通过添加更多简单线性模型无法获得进一步改进，就分割数据并在每个子集中分别恢复提升。该过程取到目前为止生成的逻辑模型，并针对每个子集中的数据分别对其进行细化。再次，在每个子集中运行交叉验证以确定在该子集中执行的适当迭代次数。

该过程递归应用，直到子集变得太小。结果树肯定会过度拟合训练数据，可以使用决策树学习的标准方法之一对其进行剪枝。实验表明剪枝操作非常重要。使用在 [附录 C](#FigC1_655-685_B9780443158889000236.xhtml#FigC1_655-685_B9780443158889000236) 中讨论的成本复杂度剪枝方法，“Implementation details of trees and rules”，该方法使用交叉验证选择正确的树大小，算法会产生小型但非常准确的树，其叶节点具有线性逻辑模型。

## 8.7 堆叠

`Stacked generalization`，或简称为 `stacking`，是组合多个模型的不同方式。尽管早已开发出来，但在机器学习文献中提及的频率仍不如 bagging 和 boosting，部分原因是理论上难以分析，部分原因是没有公认的最佳做法——基本思想可以应用于许多不同的变体。
