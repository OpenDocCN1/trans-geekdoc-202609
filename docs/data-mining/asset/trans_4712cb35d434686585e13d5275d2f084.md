
# 决策树复杂度

## 复杂度分析

假设训练数据包含 `n` 个实例和 `m` 个属性。我们需要对树的规模做出一些假设，并假设其深度为 log `n` 的量级，`O(log n)`<mml:math><mml:mi>O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>log</mml:mi><mml:mi mathvariant="italic">n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:math>![Equation](images/F000236si25.png)。这是具有 `n` 个叶子的树的标准增长速率，前提是它保持“茂盛”，并且不会退化为少数几条很长、细长的分支。请注意，我们暗中假设大多数实例彼此不同——这几乎是同一件事——`m` 个属性提供了足够的测试来区分实例。例如，如果只有少数几个二元属性，它们只能区分有限数量的实例，树就无法超过某个点，从而使“极限”分析变得毫无意义。

构建树的计算成本首先是

`O(m n log n)`。<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo>(</mml:mo><mml:mi mathvariant="italic">mn</mml:mi><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo>)</mml:mo><mml:mo>.</mml:mo></mml:math>

![Equation](images/F000236si26.png)

考虑对树中所有节点执行一个属性所需的工作量。当然，并非所有示例都需要在每个节点考虑。但在每个可能的树深度处，必须考虑整个 `n` 个实例集合。而由于树中有 log `n`<mml:math><mml:mi>log</mml:mi><mml:mi>n</mml:mi></mml:math>![Equation](images/F000236si27.png) 个不同的深度，该属性的工作量为 `O(n log n)`<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>n</mml:mi><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:math>![Equation](images/F000236si28.png)。在每个节点都会考虑所有属性，因此总工作量为 `O(m n log n)`<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi mathvariant="italic">mn</mml:mi><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:math>![Equation](images/F000236si29.png)。

这种推理做了一些假设。如果某些属性是数值型的，则必须对其进行排序，但一旦初始排序完成，如果使用适当的算法（前面已描述），则在每个树深度处无需重新排序。初始排序对多达 `m` 个属性中的每个属性需要 `O(n log n)`<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>n</mml:mi><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:math>![Equation](images/F000236si30.png) 次操作；因此之前的复杂度数值保持不变。如果属性是名义的，则所有属性都*不*需要在每个树节点考虑，因为在树中更高处使用的属性不能被重用。然而，如果属性是数值型的，则可以重用，因此必须在每个树层级考虑。

接下来考虑通过子树替换进行剪枝。首先必须为每个树节点做出误差估计。只要计数得到适当维护，这就与树中节点的数量成线性关系。然后需要考虑每个节点是否替换。树最多有 `n` 个叶子，每个实例一个。如果它是二叉树，每个属性为数值型或二值的，则会有 `2n − 1`<mml:math><mml:mn>2</mml:mn><mml:mi>n</mml:mi><mml:mo>&#8722;</mml:mo><mml:mn>1</mml:mn></mml:math>![Equation](images/F000236si31.png) 个节点；多路分支只会减少内部节点的数量。因此子树替换的复杂度为

`O(n)`。<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo>(</mml:mo><mml:mi>n</mml:mi><mml:mo>)</mml:mo><mml:mi>.</mml:mi></mml:math>

![Equation](images/F000236si32.png)

最后，子树提升的基本复杂度等于子树替换。但由于在提升操作期间需要对实例进行重新分类，因此存在额外成本。在整个过程中，每个实例可能需要在其叶子和根之间的每个节点重新分类，最多 `O(log n)`<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:math>![Equation](images/F000236si33.png) 次。这使得重新分类的总次数为 `O(n log n)`<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>n</mml:mi><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:math>![Equation](images/F000236si34.png)。而重新分类不是单一操作；发生在根附近的重新分类需要 `O(log n)`<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:math>![Equation](images/F000236si35.png) 次操作，而平均深度的重新分类需要其一半。因此子树提升的总复杂度如下：

`O(n (log n)^2)`。<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>n</mml:mi><mml:msup><mml:mrow><mml:mo stretchy="false">(</mml:mo><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:mrow><mml:mrow><mml:mn>2</mml:mn></mml:mrow></mml:msup><mml:mo stretchy="false">)</mml:mo><mml:mo>.</mml:mo></mml:math>

![Equation](images/F000236si36.png)

考虑到所有这些操作，决策树归纳的完整复杂度为

`O(m n log n) + O(n (log n)^2)`。<mml:math><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi mathvariant="italic">mn</mml:mi><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo><mml:mo>+</mml:mo><mml:mi mathvariant="normal">O</mml:mi><mml:mo stretchy="false">(</mml:mo><mml:mi>n</mml:mi><mml:msup><mml:mrow><mml:mo stretchy="false">(</mml:mo><mml:mi>log</mml:mi><mml:mi>n</mml:mi><mml:mo stretchy="false">)</mml:mo></mml:mrow><mml:mrow><mml:mn>2</mml:mn></mml:mrow></mml:msup><mml:mo stretchy="false">)</mml:mo><mml:mo>.</mml:mo></mml:math>

### 从树到规则

可以直接从决策树读取一组规则，如 [第 3.4 节](#Ch003_67-89_B9780443158889000042.xhtml#s0025) 中所述，通过为每个叶子生成一条规则，并将从根到该叶子的路径上遇到的所有测试进行合取。这会产生无歧义的规则，即执行顺序无关紧要。然而，这些规则比必要的更复杂。

前面描述的估计误差率提供了剪枝规则所必需的精确机制。对于特定规则，其中的每个条件都通过临时移除它来考虑删除，计算出现在被该规则覆盖的训练示例，基于此计算新规则的误差率的悲观估计，并将其与原始规则的悲观估计进行比较。如果新规则更好，则删除该条件并继续，寻找其他可删除的条件。当没有条件在被移除时能改善它时，保留该规则。一旦所有规则都以这种方式被剪枝，就有必要查看是否存在重复项并将其从规则集中移除。
