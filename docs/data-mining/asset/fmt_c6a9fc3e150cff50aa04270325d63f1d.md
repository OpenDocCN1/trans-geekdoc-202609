
In practice, there are a couple of other layers that are appended to the two main sublayers. These layers are essentially simply employing the various architectural “tricks” that the deep learning community has developed to help ease the training of deep neural networks. More specifically, `dropout` and `layer normalization` are performed after each of the sublayers. (`layer normalization` is similar to batch normalization but it normalizes the neurons in a layer, instead of normalizing over data points in a minibatch.) Finally, there is a residual connection around each sublayer. See [Fig. 11.10](#Ch012_433-471_B9780443158889000121.xhtml#f0055) for an overview of a `transformer block`.

By stacking several of these `transformer blocks` on top of each other, we obtain a powerful deep neural network model. The original paper used `N` = 6 `transformer blocks` in each of the modules of their system, an `encoder` and a `decoder`, with the overall system designed for neural machine translation. In a language model the final layer is normally a `softmax` layer that outputs the predicted probability of the next word in the text sequence.

An astute reader will notice that a `transformer block` takes three inputs (`queries`, `keys`, and `values`) and produces one output, so it is not completely obvious how these modules can be stacked on each other. There are actually several different ways to use a `transformer block`, depending on how the input data to the block is assigned to `queries`, `keys`, and `values`, which address this point differently. In `self-attention`, we apply attention internally within a single input sequence. The context sequence that we wish to attend to (the items with `keys` and corresponding `values`) is the same as the set of things we wish to make predictions for (the `queries`). We therefore often set `Q` = `K` = `V` = `x`, where the input sequence `x` is represented as an array of embeddings for each token in the sequence.

For `global self-attention`, we want to process the entire sequence at once so that every position can attend to every other position in the sequence. On the other hand, if we aim to predict the next word in the sequence we cannot look ahead at future words, as that would be “cheating.” So-called `causal self-attention` uses masking to prevent the model from attending to the current and subsequent words in the sequence, thus preserving this “`auto-regressive property`.”

In other cases, the items and the `queries` may be different sets of entities, a scenario called `cross-attention`. For example, in `NMT` an `encoder` may be used to produce latent representations for the input sequence in the first language, and we may wish to give this as input to the `decoder`, which aims to predict the translated sequence of tokens in the second language. Then we can set `K` and `V` to be the context embeddings produced by the `encoder` and set `Q` to be the embeddings for the translated tokens.

### Positional Encoding

There is one remaining challenge in using the `transformer` architecture for language models. `RNNs` and `CNNs` are effective for natural language data because they explicitly address the sequential nature of such data. `RNNs` such as `LSTMs` process the data in a left-to-right fashion, while `CNNs` slide convolutional filters over each position in the sequence to find local patterns. However, nothing we have described so far regarding `transformer` models has made use of the information in the sequential ordering of the tokens, and they would need to do so to be competitive with the models that do this. How can they accomplish this?

The solution turns out to be as simple as injecting some information about the position of each token to its representation. First, in the input layer we initially represent each token with a word embedding, capturing the meaning of the word in vector form just like we saw in `word2vec`. These `input embeddings` can either be learned or obtained from a pretrained word embedding model. Next, we add a “`positional encoding`” (`PE`) vector to each of the `input embeddings` that is determined by the word’s index in the sequence, thereby making positional information available to the model.

The positional encodings are the same dimensionality as the `input embeddings` so that they can be added together. The dimensionality of the embeddings is set to `d_model`, the same dimensionality that the `multihead attention` layers will produce. The authors of the `transformer` model proposed to use `sin` and `cos` functions for even and odd dimensions, respectively:

`PE(pos,2*i) = sin(pos / n^(2*i / d_model))`

`PE(pos,2*i+1) = cos(pos / n^(2*i / d_model))`
