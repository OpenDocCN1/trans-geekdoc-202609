
# k-means 聚类

经典的聚类技术称为 `k-means`。首先，你需要预先指定要寻找的聚类数量；这是参数 `k`。然后随机选择 `k` 个点作为聚类中心。所有实例根据普通的欧几里得距离度量被分配到其最近的聚类中心。接下来计算每个聚类中实例的质心，或均值——这就是“means”部分。这些质心被用作其各自聚类的新的中心值。最后，用新的聚类中心重复整个过程。迭代继续进行，直到连续几轮中每个聚类分配的点相同为止，此时聚类中心已稳定并将永远保持不变。

这种聚类方法简单有效。很容易证明选择聚类中心为质心可以最小化聚类中每个点到其中心的平方距离之和。一旦迭代稳定，每个点都被分配到其最近的聚类中心，因此总体效果是最小化所有点到其聚类中心的平方距离之和。但最小值是局部的——没有保证它是全局最小值。最终聚类对初始聚类中心非常敏感。初始随机选择的小变化可能导致完全不同的排列。事实上，这对所有实际聚类技术都是正确的。几乎总是无法找到全局最优聚类。为了增加找到全局最小值的机会，人们通常用不同的初始选择多次运行算法，并选择最佳的最终结果，即总平方距离最小的一个。

很容易想象 `k-means` 无法找到良好聚类的情况。考虑在二维空间中位于矩形顶点上的四个实例。存在两个自然聚类，通过将短边的两端顶点分组在一起形成。但假设两个初始聚类中心恰好落在 *长* 边的中点上。这形成了一个稳定配置。两个聚类各自包含长边两端的两个实例——无论长边和短边的差异有多大。

`k-means` 聚类可以通过仔细选择初始聚类中心，通常称为“seeds”来显著改进。不要从任意一组种子开始，这里有一个更好的程序。从整个空间中以均匀概率分布随机选择初始种子。然后以与第一个距离的平方成比例的概率选择第二个种子。继续，在每个阶段以与已选最近种子距离的平方成比例的概率选择下一个种子。这种称为 `k-means++` 的程序在速度和准确性方面都优于使用随机种子的原始算法。

## 更快的距离计算

`k-means` 聚类算法通常需要多次迭代，每次迭代都涉及从每个实例找到 `k` 个聚类中心的距离以确定其聚类。存在一些简单的近似方法可以显著加快这一过程。例如，你可以投影数据集并沿选定轴进行切割，而不是使用选择最近聚类中心所隐含的任意超平面划分。但这不可避免地会损害所得聚类的质量。

这里有一个更好的加速方法。寻找最近的聚类中心与在基于实例的学习中寻找最近邻并不那么不同。相同的有效解决方案——`kD-trees` 和 `ball trees`——能被使用吗？可以！事实上，它们可以以更有效的方式应用，因为在 `k-means` 的每次迭代中，所有数据点一起处理，而在基于实例的学习中测试实例是单独处理的。

首先，为所有数据点构建一个 `kD-tree` 或 `ball tree`，它将在整个聚类过程中保持静态。`k-means` 的每次迭代都会产生一组聚类中心，所有数据点都必须被检查并分配到最近的中心。处理点的一种方法是從根开始向下遍历树直到到达叶节点，然后检查叶节点中的每个单独点以找到其最近的聚类中心。但可能更高层的内部节点所代表的区域完全落在单个聚类中心的域内。在这种情况下，该节点下的所有数据点可以一次性处理！

归根结底，练习的目标是通过计算它们包含的点的质心来找到聚类中心的新位置。质心可以通过保持聚类中点的运行向量和以及到目前为止的数量来计算。最后，将一个除以另一个即可找到质心。假设我们为树的每个节点存储该节点内点的向量和以及点的数量。如果整个节点完全落在单个聚类的范围内，则该聚类的运行总计可以立即更新。如果不是，则通过递归向下遍历树来查看节点内部。
