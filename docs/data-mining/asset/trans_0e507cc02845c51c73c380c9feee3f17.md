比较距离时不必执行开方运算——平方和可以直接比较。欧氏距离的一种替代方案是曼哈顿距离或城市街区度量，其中属性值之间的差异不进行平方，而是直接相加（在取绝对值之后）。其他度量是通过取高于平方的幂得到的。较高的幂会增加大差异的影响，而以牺牲小差异为代价。通常，欧氏距离代表了一个良好的折中。在特殊情况下，其他距离度量可能更为合适。关键在于思考实际实例，以及它们被一定距离分隔意味着什么。例如，两倍的距离意味着什么？

不同属性是在不同的尺度上测量的，因此如果直接使用欧氏距离公式，一些属性的影响可能会完全被具有较大测量尺度的其他属性所掩盖。因此，通常的做法是将所有属性值归一化到 0 到 1 之间，通过计算

其中 `v[i]` 是属性 `i` 的实际值，而最大值和最小值是在训练集中的所有实例上取的。

这些公式隐含地假设属性为数值型。这里两个值之间的差异只是它们之间的数值差，而正是这个差异被平方并相加以得到距离函数。对于取值为符号而非数值的名义属性，不同的两个值之间的差异通常取为 1，而如果值相同则差异为 0。在这种情况下不需要缩放，因为只使用 0 和 1 这两个值。

处理缺失值的常见策略如下：对于名义属性，假设缺失特征与任何其他特征值最大程度不同。因此，如果任一值或两者都缺失，或者值不同，则它们之间的差异取为 1；只有在两者都不缺失且相同的情况下，差异才为 0。对于数值属性，两个缺失值之间的差异也取为 1。然而，如果只有一个值缺失，则差异通常取为另一个值（归一化）的大小或该大小的 1 减去值，两者取较大者。这意味着如果值缺失，则差异尽可能大。

### 高效寻找最近邻

尽管基于实例的学习简单有效，但通常速度较慢。找到训练集中最接近未知测试实例的成员的显而易见的方法是计算训练集中每个成员的距离并选择最小值。该过程在训练实例数量上是线性的。换句话说，进行一次预测所需的时间与训练实例的数量成正比。处理整个测试集所需的时间与训练集和测试集中实例数量的乘积成正比。

通过将训练集表示为树，可以更高效地找到最近邻，尽管具体如何操作并不十分明显。一种合适的结构是 `kD-tree`。这是一棵二叉树，它用超平面划分输入空间，然后递归地再次分割每个分区。在二维情况下，所有分割都与其中一个轴平行，垂直或水平。该数据结构称为 `kD-tree`，因为它存储 `k` 维空间中的点集，`k` 为属性的数量。
