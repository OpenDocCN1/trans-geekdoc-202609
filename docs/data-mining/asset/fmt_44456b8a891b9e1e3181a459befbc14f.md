
A natural approach to try to achieve privacy is to *anonymize* the data, so that each record is not associated with the name of the individual in question. For example, as previously mentioned, HIPAA allows the release of data if a specified set of 18 types of PII have been excised. However, as was discussed in [Chapter 1](#Ch001_3-42_B9780443158889000029.xhtml#Ch001_3-42_B9780443158889000029), “What’s it all about?,” this approach is unsatisfactory because individuals can often be re-identified when enough information is available. The crux of the problem is a *curse of dimensionality*—for every additional attribute that is measured, in the worst case there are exponentially fewer data points corresponding to each possible feature vector. Like snowflakes, everyone is unique and special so if you know enough about someone you can pick them out of a crowd.

A key strategy for re-identifying individuals is the *linkage attack*, in which an anonymized dataset is combined with additional auxiliary data from another dataset. For example, if an anonymized record can be “linked” to a corresponding identified record from another dataset its identity would be revealed. A famous example of this is the Netflix Prize dataset, which we discussed in [Chapter 1](#Ch001_3-42_B9780443158889000029.xhtml#Ch001_3-42_B9780443158889000029), “What’s it all about?” The online movie rental service Netflix released an anonymized dataset to be used as the training dataset for its contest to improve its recommendation algorithm, which had a million-dollar prize. However, using a linkage attack strategy, security researchers were able to re-identify some of the dataset by connecting it to public movie ratings data from IMDb, another website that is a source of information on film and television media. Although movie ratings data might appear to be innocuous, when associated with a timestamp, it reveals what the users were doing in their own home on a particular evening, which could be rather personal. This privacy vulnerability led to a class-action lawsuit that resulted in Netflix having to scrap its follow-up data mining contest.

## `k`-Anonymity

The simplest linkage attack is to simply look for a match between the anonymized dataset and the background knowledge dataset when looking at the potentially relevant features that remain after removing *explicit identifiers*; for example, the attributes that uniquely identify individuals. These attributes are called *quasiidentifiers*—a set of attributes that, in combination, can uniquely identify individuals. The approach used on the Netflix Prize was slightly more sophisticated and does not require knowing which attributes are quasiidentifiers, but it was along these same lines.

An early and relatively direct attempt to prevent linkage attacks is a methodology due to privacy researcher Latanya Sweeney, called `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi1.png)*\-anonymity*. The goal of this approach is to release a version of a dataset that is safe from the harms of re-identification while still being useful for analysis. Note, however, that this approach does not actually guarantee this is achieved. The definition is as follows:

*A release of a dataset is said to satisfy* `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi2.png)*\-anonymity if and only if each sequence of quasiidentifier values occurs at least* `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi3.png) *times in the release*.

The idea here is that if an adversary matches their background knowledge to a sequence of quasiidentifier values, they won’t know which of the `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi4.png) or more individuals with those same quasiidentifier values that it refers to. So, in theory, individuals can’t be uniquely identified via linkage attacks. The first step in achieving `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi8.png)\-anonymity is to partition the attributes into explicit identifiers, quasiidentifiers, and nonidentifiers. Explicit identifiers are *suppressed* (removed from the release) while *nonidentifiers* (which we suppose do not help with identifying individuals) are ignored. The key challenge is to process the quasiidentifiers to achieve the desired value of `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi9.png). We can do this using the strategies of *suppression* (replacing one or more values of attributes with a dummy value, \*<mml:math><mml:mo>\*</mml:mo></mml:math>![Equation](images/F00008Xsi10.png)) and *generalization* (coarsening the granularity of an attribute by binning it into certain ranges).

While the method looks nice on paper, unfortunately, `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi11.png)\-anonymity has several severe limitations that hamper it in practice. First, if you don’t correctly determine the quasiidentifiers, or the adversary knows more than the designated set of quasiidentifiers, the method will fail completely. Second, it’s difficult to achieve in high dimensions since we may need to process the data to have `k`<mml:math><mml:mi>k</mml:mi></mml:math>![Equation](images/F00008Xsi12.png) copies of an exponentially large number of feature vectors.
