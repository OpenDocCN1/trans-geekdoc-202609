## 3.3 树

“分而治之”方法用于从一组独立实例中学习的问题，自然导向一种称为 `decision tree` 的表示风格。我们已经见过决策树的例子，针对隐形眼镜（[图 1.2](#Ch001_3-42_B9780443158889000029.xhtml#f0015)）和劳资谈判（[图 1.3](#Ch001_3-42_B9780443158889000029.xhtml#f0020)）数据集。决策树中的节点涉及测试特定属性。通常，测试将属性值与常数进行比较。叶节点给出适用于到达该叶的所有实例的分类，或一组分类，或所有可能分类上的概率分布。要对未知实例进行分类，它会根据在后续节点中测试的属性值沿树向下路由，并在到达叶时根据分配给该叶的类别对实例进行分类。

如果在节点处测试的属性是名义属性，则子节点的数量通常是该属性可能值的数量。在这种情况下，因为每个可能值都有一个分支，所以同一属性不会在树中更下方重新测试。有时属性值被划分为两个子集，树仅根据值位于哪个子集而分两路分支；在那种情况下，属性可能在一条路径中被测试多次。

如果属性是数值型的，则节点处的测试通常确定其值是否大于或小于预定的常数，从而产生两路分割。或者也可以使用三路分割，在这种情况下有几种不同的可能性。如果 `missing value` 被视为其自身的一个属性值，这将创建一个第三分支。对于整数值属性的一种替代方案是将三路分割为 `less than`、`equal to` 和 `greater than`。对于实数值属性而言，`equal to` 并不是一个有意义的选项，一种替代方案是对区间而不是单个常数进行测试，同样给出三路分割：`below`、`within` 和 `above`。数值属性在从根到叶的给定路径中经常被多次测试，每次测试涉及不同的常数。我们在描述数值属性的处理时在 [附录 C.1](#FigC1_655-685_B9780443158889000236.xhtml#FigC1_655-685_B9780443158889000236) 中会回到这个问题。

缺失值带来了一个明显的问题。当节点测试的属性值缺失时，不清楚应采用哪个分支。有时，如 [第 2.4 节](#Ch002_43-66_B9780443158889000030.xhtml#s0035) 中所述，`missing value` 被视为其自身的一个属性值。如果不是这种情况，缺失值应以特殊方式处理，而不是被视为属性可能取的另一个值。一个简单的解决方案是记录训练集中沿每个分支下降的元素数量，并在测试实例的值缺失时使用最受欢迎的分支。

更复杂的解决方案是将实例概念上拆分为若干部分，并将其中一部分发送到每个分支，然后一直向下发送到所涉及子树的所有叶。拆分使用 0 到 1 之间的数值权重完成，且分支的权重选择为与沿该分支下降的训练实例数量成比例，所有权重之和为 1。加权实例可能在更低的节点处进一步拆分。最终实例的各个部分都将到达叶节点，并且这些叶节点处的决策必须使用已渗透到叶节点的权重进行重新组合。我们在 [附录 C.1](#FigC1_655-685_B9780443158889000236.xhtml#FigC1_655-685_B9780443158889000236) 中会回到这个问题。
