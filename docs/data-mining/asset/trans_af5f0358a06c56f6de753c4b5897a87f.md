
## 决策树与规则集
因为决策树难以轻松表达规则集中不同规则之间所隐含的析取，将一般规则集转换为树并非那么简单。一个很好的例证是当规则具有相同的结构但不同的属性时，例如：

```
If a and b then x
```

```
If c and d then x
```

然后有必要打破对称性并为根节点选择一个单一的测试。例如，如果选择 `a`，第二个规则在树中实际上必须重复两次，如 [图 3.5](#Ch003_67-89_B9780443158889000042.xhtml#f0030) 所示。这被称为 *复制子树问题*。

[图 3.5](#Ch003_67-89_B9780443158889000042.xhtml#Bf0030) 简单析取的决策树。

复制子树问题的重要性足以值得再看几个例子。[图 3.6](#Ch003_67-89_B9780443158889000042.xhtml#f0035) 左侧的图示展示了一个 *异或* 函数，其输出为 `a` 当 `x` = 1 或 `y` = 1 但不同时为 1。要将其做成树，必须先对一个属性进行划分，从而导致如中心所示的结构。相比之下，规则可以忠实地反映问题相对于属性的真实对称性，如右侧所示。

在这个例子中，规则并没有比树更紧凑得多。事实上，它们只是以显而易见的方式从树中读出规则所得到的结果。但在其他情况下，规则比树紧凑得多，特别是如果可以有一个“默认”规则来覆盖其他规则未指定的情况。例如，要捕捉 [图 3.7](#Ch003_67-89_B9780443158889000042.xhtml#f0040) 中的规则效果，其中有四个属性——`x`、`y`、`z` 和 `w`，每个都可以是 1、2 或 3——需要右侧所示的树。右上方三个小的灰色三角形实际上应包含显示为灰色的整个三层子树，这是复制子树问题的一个相当极端的例子。这是对一个相当简单概念的令人沮丧的复杂描述。

规则受欢迎的一个原因是每个规则似乎代表一个独立的“知识块”。可以向现有规则集添加新规则而不会干扰已有的规则，而向树结构添加内容可能需要重塑整棵树。然而，这种独立性有点像幻觉，因为它忽略了规则集如何执行的问题。我们之前解释过，如果规则是作为“决策列表”按 *顺序* 解释的，其中一些规则单独取出、脱离上下文时可能是错误的。另一方面，如果解释的顺序本应无关紧要，那么当不同规则对同一实例得出不同结论时该怎么办就不清楚了。这种情况不会出现在直接从决策树读取的规则中，因为规则结构中包含的冗余防止了任何解释上的歧义。但当规则以其他方式生成时就会出现这种情况。

如果一个规则集对某个特定示例给出多个分类，一个解决方案是根本不给出结论。另一个是统计每个规则在训练数据上触发的次数并采用最受欢迎的那个。这些策略可能导致截然不同的结果。另一个问题是当遇到规则完全无法分类的实例时。同样，这不会发生在决策树或直接从中读取的规则上，但很容易发生在一般规则集上。处理这种情况的一种方法是无法对这样的示例进行分类；另一种是选择最频繁出现的类别作为默认值。同样，这些策略可能得到截然不同的结果。单个规则很简单，规则集似乎也具有欺骗性的简单——但仅给出一个规则集而没有额外信息时，很不清楚应该如何解释它。

一个特别简单的情况是当规则导致一个布尔类（例如 `yes` 和 `no`）时，并且仅表达导致一个结果（例如 `yes`）的规则。假设是如果某个实例不在类 `yes` 中，那么它必须在类 `no` 中——这是一种封闭世界假设的形式。如果是这种情况，规则不能冲突，规则解释也没有歧义——任何解释策略都会给出相同的结果。这样的规则集可以写成逻辑表达式，称为 *析取范式*，例如作为析取（OR）的合取（AND）条件。

正是这个简单的特例诱使人们认为规则很容易处理，因为在这里每个规则确实作为一个新的、独立的信息片段以直接的方式贡献于析取。不幸的是，它仅适用于布尔结果并需要封闭世界假设，而这些限制在许多实际情况下是不现实的。生成规则的机器学习算法在多类情况下必然产生有序规则集，这牺牲了任何模块化的可能性，因为执行顺序至关重要。

## 关联规则
关联规则与分类规则没有区别，只是它们可以预测任何属性，而不仅仅是类，这使它们能够预测属性组合。同样，关联规则并不打算像分类规则那样作为集合一起使用。不同的关联规则表达了数据集背后的不同规律性，并且通常预测不同的事物。

因为即使从很小的数据集也能推导出如此多的不同关联规则，研究兴趣仅限于那些适用于相当多实例并且在适用实例上具有相当高准确度的规则。关联规则的 *覆盖率* 是其正确预测的实例数量——这通常称为其 *支持度*。其 *准确率*——通常称为 *置信度*——是其正确预测的实例数量，表示为其适用实例总数的比例。例如，对于规则：

```
If temperature = cool then humidity = normal
```

覆盖率是既凉爽又有正常湿度的天数（在 [表 1.2](#Ch001_3-42_B9780443158889000029.xhtml#t0015) 的数据中为 4），准确率是凉爽天中湿度正常的比例（本例中为 100%）。通常指定最小覆盖率和准确率值，并仅寻找覆盖率和准确率都至少达到这些指定最小值的规则。例如，在天气数据中，有 58 条规则的覆盖率和准确率分别至少为 2 和 95%。 （也可以方便地将覆盖率指定为实例总数的百分比。）

预测多个结果的关联规则必须相当谨慎地解释。例如，在 [表 1.2](#Ch001_3-42_B9780443158889000029.xhtml#t0015) 的天气数据中，我们看到过这个规则：

```
If windy = false and play = no then outlook = sunny
```

```
and humidity = high
```

这 *不是* 只是两个独立规则的简写表达式：

```
If windy = false and play = no then outlook = sunny
```

```
If windy = false and play = no then humidity = high
```
