
As with regular gradient descent, invoking momentum in `SGD`—sometimes called the *stochastic heavy ball method*—can help the optimization escape local optima and plateaus in the loss function. If the current gradient of the loss is `∇[θ]L(θ)`, momentum is implemented by computing a moving average of the gradients and adding this moving average to the `SGD` updates. It updates the parameters by adding `Δθ = − η ∇[θ]L(θ) + α Δθ^(old)`, where `α ∈ [0,1]`. Since the mini-batch approach operates on a small subset of the data, this averaging can allow information from other recently seen mini-batches to contribute to the current parameter update. A momentum value of 0.9 is often used as a starting point but it is common to hand-tune it, the learning rate, and the schedule used to modify the learning rate during the training process.

A variant of this method, called *Nesterov momentum*, uses the moving average of the gradients to “look ahead.” Instead of stepping to that point, the algorithm calculates the gradient at that look-ahead point and then uses this new gradient to take a step from the original position. Essentially the method is able to anticipate how the gradients would change and use that information to update its position instead.

### Adaptive Gradient Methods
As we mentioned earlier, `SGD` uses a single learning rate for all parameters. Intuitively, some parameters might be relatively settled during training while others might need to change a lot, so some parameters could require different learning rates than others to converge quickly. If we could have a different learning rate for each parameter, the ones that have already converged could slow down their learning rates, while the ones that are still far off could move more quickly. If some of the features are sparse and occur rarely, we also want to move faster on their corresponding parameters when we do see them. The *AdaGrad (Adaptive Gradient)* algorithm aims to adaptively set learning rates for each parameter. In its practical implementation `AdaGrad` maintains a sum of the (elementwise) squares of past gradients and divides the learning rate of each dimension by the square root of the corresponding sum.

An advantage of `AdaGrad` is that it is relatively robust to the overall learning rate `η`. However, it has a flaw in that its per-parameter learning rates get divided by larger and larger values, eventually slowing learning to a crawl. The *AdaDelta* algorithm is a variant of `AdaGrad`, which addresses this by instead using a moving average of the elementwise squares of the previous gradients so that the values to divide each dimension’s learning rate by don’t keep getting larger. `AdaDelta` also removes the learning rate hyperparameter `η`, relieving the analyst of the burden of setting it. If the analyst prefers to have control over the learning rate, `RMSProp` is similar to `AdaDelta` (and was invented independently of it at around the same time) but it has a settable learning rate.

At the time of writing, the most popular optimizer for deep learning is *Adam (Adaptive Moment Estimation)*, a variant of `RMSProp` that uses a moving average of past gradients for each parameter for the updates instead of the current gradients. (It also includes some terms to correct for a bias toward zero due to how it is initialized.)

When choosing between these learning algorithms, it is worth noting that some studies have found that `SGD` (with or without momentum) can have better generalization properties than these more sophisticated adaptive gradient methods in some cases. While the precise reasons for this are not well understood, there is a complex relationship between the learning algorithm and the local optima that it tends to find—in the ability (or inability) of the learning algorithm to escape certain local optima—and differences in this regard likely play a role. Intuitively, overfitting could also be part of the reason for this gap, perhaps the adaptive gradient methods fit *too* well to the training data. Nevertheless, the faster convergence of adaptive gradient methods makes them the method of choice in many deep learning applications. `AdaGrad`, `AdaDelta`, and `RMSProp` are precursors to `Adam` and may perform as well as it in some cases. They can be used fairly interchangeably. `Adam` typically performs as well as those methods, though there could be exceptions. It is a good default choice of optimizer. If feasible, a grid search over learning algorithms and their hyperparameters, measuring performance on a validation set, will reveal the best choice for the specific problem at hand.

### Regularization With Priors on Parameters
Many standard techniques for parameter regularization are applicable to deep networks. We mentioned earlier that `L2` regularization corresponding to a Gaussian prior on parameters has been used for neural networks under the name “weight decay.” As with logistic regression, such regularization is usually applied just to the weights in a network, not to the biases. Alternatively, a weighted combination of `L2` and `L1` regularization, `λ2 R[L2](θ) + λ1 R[L1](θ)`, can be applied to the weights in a network, as in the elastic net model discussed in [Section 14.4](#Ch015_516-570_B9780443158889000157_a.xhtml#s0160). Although the loss functions used in deep learning may not generally be convex, such regularizers can nevertheless be implemented.
