
构建树的算法在 [图 C.5](#FigC1_655-685_B9780443158889000236.xhtml#f0030) 中进行了总结；它将一组实例递归地分割成一棵部分树。第一步选择一个测试并据此将实例划分为子集。该选择使用与通常用于构建决策树时相同的信息增益启发式方法（[第 4.3 节](#Ch004_91-164_B9780443158889000054.xhtml#s0040)）。然后子集按其平均熵的递增顺序进行扩展。其原因是后面的子集很可能最终不会被扩展，而平均熵较低的子集更可能产生较小的子树，从而产生更一般的规则。此过程递归进行，直到某个子集被扩展为叶节点，然后通过回溯继续。但只要出现其所有子节点都已扩展为叶节点的内部节点，算法就会检查该节点是否更适合由单个叶节点替换。这是决策树剪枝的标准子树替换操作（[附录 C.1](#FigC1_655-685_B9780443158889000236.xhtml#APP3)）。如果执行了替换，算法会以标准方式回溯，探索新替换节点的兄弟节点。然而，如果在回溯期间遇到一个节点，其并非所有已扩展的子节点都是叶节点——这种情况只要潜在的子树替换未执行就会发生——那么剩余的子集将被保留未探索，对应的子树也保持未定义。由于算法的递归结构，这一事件会自动终止树的生成。

如果数据无噪声并且包含足够的实例以防止算法进行任何剪枝，则只需探索完整决策树的一条路径。这相对于每次都构建完整决策树的朴素方法实现了最大可能的性能提升。随着剪枝量的增加，增益会下降。对于具有数值属性的数据集，算法的渐近时间复杂度与构建完整决策树相同，因为在这种情况下，复杂度主要由最初对属性值进行排序所需的时间决定。

一旦构建了部分树，就会从中提取一条规则。每个叶节点对应一条可能的规则，我们寻求那些已扩展为叶节点的子树（通常是少数）中“最佳”的叶节点。实验表明，最好的做法是选择覆盖实例数量最多的叶节点，以实现最一般的规则。

当数据集包含缺失值时，可以像构建决策树时那样处理它们。如果由于属性值缺失而无法将某个实例分配到给定分支，则将其分配到每个分支，权重与沿该分支向下传递的训练实例数量成正比，并按该节点处已知值的训练实例总数进行归一化。在测试期间，相同的过程分别应用于每条规则，从而为每条规则对测试实例的应用关联一个权重。在将实例传递给列表中的下一条规则之前，该权重会从实例的总权重中扣除。一旦权重降至零，根据权重将预测的类别概率合并为最终分类。

这产生了一种简单但出人意料地有效的用于噪声数据学习决策列表的方法。它相对于其他全面的规则生成方案的主要优势在于简单性，因为它不需要复杂的全局优化阶段。

### 带例外的规则

在 [第 3.4 节](#Ch003_67-89_B9780443158889000042.xhtml#s0025) 中我们了解到，规则的自然扩展是允许它们具有例外，以及例外的例外，等等——事实上，整个规则集可以被视为对默认分类规则的例外，当没有其他规则适用时使用该规则。使用前面描述的度量之一生成“良好”规则的方法提供了生成带例外规则所需的机制。

首先为顶层规则选择一个默认类别；自然的做法是使用训练数据中出现频率最高的类别。然后找到一条与默认类别以外的任何类别相关的规则。在所有此类规则中，自然的做法是寻求判别力最强的规则，例如在测试集上评估最好的规则。假设此规则的形式为

```
If <condition> then class = <new class>
```

它用于将训练数据拆分为两个子集：一个包含规则条件为 `true` 的实例，另一个包含条件为 `false` 的实例。如果任一子集包含多于一个类别的实例，则算法会递归地应用于该子集。对于条件为 `true` 的子集，“默认类别”是规则指定的新类别；对于条件为 `false` 的子集，默认类别保持不变。
