
还有其他度量代表了簇成员之间最小距离和最大距离极端之间的折中。其中一种方法是用其成员的质心来表示簇，正如 `k-means` 算法所做的那样，并使用质心之间的距离——`centroid-linkage` 方法。当实例位于多维欧几里得空间中且质心的概念明确时，这种方法效果很好，但如果我们只有实例之间的成对相似性度量，则不适用，因为质心不是实例，它们之间的相似性可能无法定义。

另一种避免此问题的度量是计算两个簇中每对成员之间的平均距离——`average-linkage` 方法。虽然这看起来工作量很大，但无论如何要找到最大值或最小值都必须计算所有成对距离，而对它们取平均值并不会增加太多负担。

这两种度量都有一个技术缺陷——它们的结果取决于距离测量的数值尺度。最小距离和最大距离度量产生的结果仅取决于所涉及距离之间的 `ordering`。相比之下，基于质心和平均距离聚类的结果可以通过对所有距离进行单调变换而改变，即使它保留了它们的相对顺序。

另一种方法称为 `group-average` 聚类，使用合并簇中所有成员之间的平均距离。这与刚才描述的“average”方法不同，因为它在平均值中包含了来自同一原始簇的配对。最后，`Ward’s` 聚类方法计算融合两个簇前后实例与质心距离的平方和的增量。其思想是在每次聚类步骤中最小化该平方距离的增量。

如果簇是紧凑且分离良好的，所有这些度量都会产生相同的层次聚类结果。然而，在其他情况下它们可能会产生相当不同的结构。

### 增量聚类

而 `k-means` 算法在达到收敛之前对整个数据集进行迭代，层次方法在每次合并阶段检查迄今为止存在的所有簇，我们接下来要检查的聚类方法则按实例增量工作。在任何阶段，聚类形成一棵树，实例位于叶节点，根节点代表整个数据集。开始时，树仅由根组成。实例逐一添加，并在每个阶段适当地更新树。更新可能只是找到放置代表新实例的叶节点的合适位置，也可能涉及对受新实例影响的树部分进行彻底重组。决定如何以及在何处更新的关键是一个称为 `category utility` 的量，它衡量实例划分为簇的整体质量。我们将如何定义它的详细考虑推迟到类别效用部分，先看看聚类算法的工作原理。

该过程最好通过一个示例来说明。我们将再次使用熟悉的天气数据，但不使用 `play` 属性。为了跟踪进度，14 个实例被标记为 `a`、`b`、`c`、…、`n`（如 [表 4.6](#Ch004_91-164_B9780443158889000054_a.xhtml#t0035) 中所示），并且出于兴趣我们在标签中包含类别 `yes` 或 `no`——尽管应强调，对于这个人工数据集，很少有理由认为两个类别的实例应落入不同的类别。[图 4.20](#Ch004_91-164_B9780443158889000054_a.xhtml#f0105) 显示了整个聚类过程中关键点的状况。
