
让我们检查该算法如何适用于 [第 3.4 节](#Ch003_67-89_B9780443158889000042.xhtml#s0025) 中给出的带异常的规则，用于 [表 1.4](#Ch001_3-42_B9780443158889000029.xhtml#t0025) 的鸢尾花数据。我们将以 [图 C.7](#FigC1_655-685_B9780443158889000236.xhtml#f0040) 所示的图形形式表示这些规则，其等价于我们在 [图 3.8](#Ch003_67-89_B9780443158889000042.xhtml#f0045) 中展示的文本规则。`Iris setosa` 的默认值是左上角的入口节点。水平虚线表示异常，因此下一个包含结论为 `Iris versicolor` 的规则的框是对默认值的异常。其下方是一个备选方案，即第二个异常——备选方案由垂直实线表示——导致结论 `Iris virginica`。沿着上方的水平路径继续，会导致对 `Iris versicolor` 规则的异常，只要右上角框中的条件成立，该异常就会覆盖它，结论为 `I. virginica`。其下方是一个备选方案，（碰巧）导致相同的结论。回到底部中央的框，它有自己的异常，即右下角的框，给出结论 `Iris versicolor`。每个框右下角的数字给出规则的“覆盖率”，表示为满足该规则的示例数除以满足其条件但不满足其结论的示例数。例如，顶部中央框中的条件适用于 52 个示例，其中 49 个是 `Iris versicolor`。这种表示的优点在于，你可以从左侧的框中很好地感受到规则的效果；右侧的框仅覆盖少数异常情况。

![图 C.7 鸢尾花数据的带异常规则。](images/F000236bm07-9780443158889.jpg)

图 C.7 鸢尾花数据的带异常规则。

要创建这些规则，首先将默认值设为 `I. setosa`，方法是取数据集中出现频率最高的类别。这是任意选择，因为对于该数据集，所有类别都恰好出现 50 次；如 [图 C.7](#FigC1_655-685_B9780443158889000236.xhtml#f0040) 所示，该默认“规则”在 150 个案例中有 50 个是正确的。然后寻找预测另一类别的最佳规则。在本例中为

```
if petal-length ≥ 2.45 and petal-length < 5.355 and petal-width < 1.75 then Iris-versicolor
```

该规则覆盖 52 个实例，其中 49 个是 `Iris versicolor`。它将数据集分为两个子集：满足规则条件的 52 个实例和剩余的 98 个不满足的实例。

我们首先处理前一个子集。这些实例的默认类别是 `Iris versicolor`。只有三个异常，全部碰巧是 `I. virginica`。接下来确定该子集的最佳规则，该规则不预测 `Iris versicolor`：

```
if petal-length ≥ 4.95 and petal-width < 1.55 then Iris-virginica
```

它覆盖了三个 `I. virginicas` 中的两个，且没有其他。再次将子集分为两部分：满足其条件的实例和不满足的实例。幸运的是，在本例中，所有满足条件的实例确实都属于 `I. virginica` 类，因此无需进一步的异常。然而，剩余的实例仍包括第三个 `I. virginica`，以及 49 个 `Iris versicolors`，它们是此时的默认值。再次寻找最佳规则：

```
if sepal-length < 4.95 and sepal-width ≥ 2.45 then Iris-virginica
```

该规则覆盖剩余的 `I. virginica` 且没有其他，因此也没有异常。此外，子集中不满足其条件的全部剩余实例都属于 `Iris versicolor` 类，即默认值，因此无需再做其他处理。

现在回到初始规则创建的第二个子集，即不满足条件的实例

```
petal-length ≥ 2.45 and petal-length < 5.355 and petal-width < 1.75
```

对于这些实例且不预测默认类别 `I. setosa` 的规则中，最佳的是

`if petal-length ≥ 3.35 then Iris-virginica`

它覆盖了示例集中全部 47 个 `Iris virginicas`（三个已被第一条规则移除，如前所述）。它还覆盖了 1 个 `Iris versicolor`。这需要作为异常处理，由最终规则处理：

```
if petal-length < 4.85 and sepal-length < 5.95 then Iris-versicolor
```

幸运的是，*不*满足其条件的实例集合全部为默认值 `I. setosa`。因此该过程结束。

所产生的规则具有以下特性：大多数示例由高层规则覆盖，而低层规则确实代表异常。例如，最后一个异常子句和深层嵌套的 `else` 子句都只覆盖一个孤立示例，移除它们影响不大。甚至剩余的嵌套异常规则也只覆盖两个示例。因此，只需忽略所有更深的结构，只看第一层或两层，就能很好地了解规则的作用。这就是带异常规则的吸引力所在。

### 讨论

我们所描述的所有用于生成分类规则的算法都使用基本的覆盖或分而治之方法。对于简单、无噪声的情况，这会产生 `PRISM`（[Cendrowska, 1987](#References_705-736_B978044315888900025X.xhtml#fur87)），一种简单易懂的算法。当应用于具有封闭世界假设的二分类问题时，只需为一个类别生成规则即可。然后规则以析取范式形式存在，可以在测试实例上执行而不会产生任何歧义。当应用于多分类问题时，为每个类别生成单独的规则集；因此测试实例可能被分配到多个类别，或不分配到任何类别，如果需要唯一预测，则需要进一步的启发式方法。

为了在噪声情况下减少过拟合，有必要生成即使在训练集上也不是“完美”的规则。为此需要对规则的“好坏”或价值有一个度量。有了这样的度量，就有可能放弃基本覆盖算法的逐类方法，而先生成最好的规则，无论它预测哪个类别，然后移除该规则覆盖的所有示例并继续该过程。这产生了一种生成决策列表而非独立分类规则集的方法，而决策列表的重要优点是解释时不会产生歧义。

增量简化误差剪枝的思想归功于 [Fürnkranz and Widmer (1994)](#References_705-736_B978044315888900025X.xhtml#fur204)，并构成了快速有效的规则归纳的基础。`RIPPER` 规则学习器归功于 [Cohen (1995)](#References_705-736_B978044315888900025X.xhtml#fur107)，尽管已发表的描述似乎在 `DL` 如何影响停止条件方面与实现有所不同。我们在此介绍的是该算法的基本思想；实现中还有更多细节。

衡量规则价值的问题很困难。提出了许多不同的度量，有些明显是启发式的，其他则基于信息论或概率论。然而，似乎没有共识认为哪种度量最好。 [Fürnkranz and Flach (2005)](#References_705-736_B978044315888900025X.xhtml#fur203) 对各种标准进行了广泛的理论研究。
