
## 数值预测
数值预测是分类学习的一种变体，其中结果是数值而非类别。CPU 性能问题就是一个例子。另一个，如[表 2.2](#Ch002_43-66_B9780443158889000030.xhtml#t0015)所示，是天气数据的版本，其中预测的内容不是是否进行游戏，而是进行游戏的时间（以分钟计）。对于数值预测问题，就像其他机器学习情况一样，新实例的预测值往往不如所学习描述的结构重要，后者用重要属性是什么以及它们如何与数值结果相关来表达。

## 2.2 示例中有什么？
机器学习方案的输入是一组实例。这些实例是要被分类、关联或聚类的事物。虽然到目前为止我们称它们为*示例*，从今以后我们通常会使用更具体的术语*实例*来指代输入。在标准情况下，每个实例都是待学习概念的一个独立的、独立的例子。实例由一组预定属性的值来表征。这在[第 1 章](#Ch001_3-42_B9780443158889000029.xhtml#Ch001_3-42_B9780443158889000029)，“这都是关于什么的？”（天气、隐形眼镜、鸢尾花和劳资谈判问题）中描述的所有示例数据集中都是如此。每个数据集都表示为实例与属性的矩阵，在数据库术语中它是一个单一的关系，或一个*平面文件*。
将输入数据表达为一组独立实例是实际数据挖掘中最常见的情况。然而，这是一种相当受限的问题表述方式，值得花时间回顾一下原因。问题通常涉及对象之间的关系，而非单独的、独立的实例。假设，举一个具体情况，给定一个家谱，我们想要学习概念*姐妹*。想象一下你自己的家谱，亲戚（及其性别）放置在节点上。这棵树是学习过程的输入，连同人员配对的列表以及他们是否姐妹的指示。

### 关系
[图 2.1](#Ch002_43-66_B9780443158889000030.xhtml#f0010)显示了家谱的一部分，下面有两个表格，它们以略有不同的方式定义姐妹关系。表格第三列中的*是*意味着第二列中的人是第一列中人的姐妹（这只是我们在设置此示例时做出的任意决定）。
![图 2.1 一个家谱和两种表达姐妹关系的方式。](images/F000030f02-01-9780443158889.jpg)
图 2.1 一个家谱和两种表达 `sister-of` 关系的方式。
首先要注意的是，左侧表格第三列中有很多*否*s——因为有 12 个人，总共有 12 × 12 = 144 对人，而大多数人对并不是姐妹。右侧表格提供了相同的信息，只记录正例，并假设其他都是负例。只指定正例并采用其余为负的默认假设的想法称为*封闭世界假设*。在理论研究中经常被假设；然而，在现实问题中可能不太合适。
没有家谱本身，[图 2.1](#Ch002_43-66_B9780443158889000030.xhtml#f0010)中的任何一个表格都没有用。这棵树也可以以表格形式表达，其中一部分显示在[表 2.3](#Ch002_43-66_B9780443158889000030.xhtml#t0020)中。现在问题是用两个关系来表达的。但这些表格不包含独立的实例集合，因为 `sister-of` 关系中 `Name`、`Parent1` 和 `Parent2` 列的值引用了家谱关系中的行。我们可以通过将这两个表格合并为[表 2.4](#Ch002_43-66_B9780443158889000030.xhtml#t0025)中的单一表格，使其成为一组实例。

我们终于成功地将原始的关系问题转换成了实例的形式，每个实例都是待学习概念的一个独立的、独立的例子。当然，实例并不是真正独立的——表格中不同行之间存在大量关系！——但就姐妹关系概念而言，它们是独立的。大多数机器学习方案在处理这种数据时仍会遇到困难，但至少问题已被重新表述为正确的形式。姐妹关系的简单规则是：
```
If second person’s gender = female
and first person’s parent1 = second person’s parent1
then sister-of = yes
```
这个例子展示了如何将树中不同节点之间的关系重新表述为一组独立实例。在数据库术语中，你取两个关系并将它们连接起来形成一个，这是一个扁平化的过程，技术上称为*反规范化*。对于任何（有限的）关系（有限的）集合，都可以这样做，但反规范化可能会产生需要聚合以形成独立实例的行集合。
