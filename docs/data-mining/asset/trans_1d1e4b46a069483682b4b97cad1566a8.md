
我们所描述的基本信息增益算法称为 `ID3`。对 `ID3` 的一系列改进，包括增益率准则，最终形成了用于决策树归纳的实用且有影响的系统 `C4.5`。进一步的改进包括处理数值属性、缺失值、噪声数据以及从树生成规则的方法。它们在 [附录 C](#FigC1_655-685_B9780443158889000236.xhtml#FigC1_655-685_B9780443158889000236) 中有所描述，树和规则的实现细节。

## 4.4 覆盖算法：构造规则

正如我们所见，决策树算法基于对分类问题的分而治之方法。它们自上而下工作，在每个阶段寻求一个最佳分离类别的属性，然后递归处理由此分割产生的子问题。这种策略生成决策树，如果必要的话，可以将其转换为一组分类规则——尽管如果要产生有效的规则，转换并非微不足道。

一种替代方法是依次处理每个类别，并寻求一种覆盖其中所有实例的方法，同时排除不属于该类别的实例。这被称为 *覆盖* 方法，因为在每个阶段你都会识别出一个“覆盖”某些实例的规则。凭其本质，这种覆盖方法导致一组规则而不是决策树。

覆盖方法可以在实例的二维空间中直观地可视化，如 [图 4.6A](#Ch004_91-164_B9780443158889000054_a.xhtml#f0035) 所示。我们首先制定一个覆盖 `a` 的规则。对于规则中的第一个测试，如中心图所示垂直分割空间。这给出了一个规则的开始：

![图 4.6 覆盖算法。(A) 覆盖实例。(B) 相同问题的决策树。](images/F000054f04-06-9780443158889.jpg)

图 4.6 覆盖算法。(A) 覆盖实例。(B) 相同问题的决策树。

```
If x > 1.2 then class = a
```

然而，该规则同时覆盖了许多 `b` 以及 `a`，因此通过如第三图所示进一步水平分割空间来向规则添加新的测试：

`If x > 1.2 and y > 2.6 then class = a`

这给出了一个覆盖除一个 `a` 之外的所有 `a` 的规则。可能适当就此为止，但如果有必要覆盖最后一个 `a`，则需要另一个规则——也许。

```
If x > 1.4 and y < 2.4 then class = a
```

相同的程序导致了覆盖 `b` 的两个规则：

```
If x ≤ 1.2 then class = b
```

```
If x > 1.2 and y ≤ 2.6 then class = b
```

再次，这些规则错误地覆盖了一个 `a`。如果有必要将其排除，则必须向第二个规则添加更多测试，并且需要额外的规则来覆盖这些新测试所排除的 `b`。

### 规则与树

自上而下的分而治之算法以一种方式操作相同的数据，至少在表面上与覆盖算法非常相似。它可能会首先使用 `x` 属性分割数据集，并且很可能会在相同的位置分割，`x` = 1.2<mml:math><mml:mi>x</mml:mi><mml:mo>=</mml:mo><mml:mn>1.2</mml:mn></mml:math>![Equation](images/F000054si57.png)。然而，而覆盖算法只关心覆盖单个类别，分裂将同时考虑两个类别，因为分而治之算法创建适用于所有类别的单一概念描述。第二个分割也可能在相同的位置，`y` = 2.6<mml:math><mml:mi>y</mml:mi><mml:mo>=</mml:mo><mml:mn>2.6</mml:mn></mml:math>![Equation](images/F000054si58.png)，导致 [图 4.6B](#Ch004_91-164_B9780443158889000054_a.xhtml#f0035) 中的决策树。该树与规则集完全对应，在这种情况下，覆盖和分而治之算法的效果没有区别。

但在许多情况下，规则和树在表示的清晰度方面 *是* 有区别的。例如，当我们描述 [第 3.4 节](#Ch003_67-89_B9780443158889000042.xhtml#s0025) 中的复制子树问题时，我们注意到规则可以是对称的，而树必须首先选择一个属性进行分割，这可能导致树比等效规则集大得多。另一个区别是，在多类情况下，决策树分割会考虑所有类别，试图最大化分割的纯度，而规则生成方法一次集中于一个类别，忽略了对其他类别的影响。

### 一个简单的覆盖算法

覆盖算法通过向正在构建的规则添加测试来操作，始终努力创建具有最大准确性的规则。相比之下，分而治之算法通过向正在构建的树添加测试来操作，始终努力最大化类别之间的分离。这两者都涉及找到一个分割属性。但最佳属性的标准在每种情况下是不同的。而像 `ID3` 这样的分而治之算法选择属性以最大化信息增益，我们将描述的覆盖算法选择属性-值对以最大化所需分类的概率。

[图 4.7](#Ch004_91-164_B9780443158889000054_a.xhtml#f0040) 给出了情况的图示，显示了包含所有实例的空间、部分构建的规则以及在添加新项后同一规则。新的项限制了规则的覆盖范围；想法是尽可能多地包含所需类别的实例，并尽可能多地排除其他类别的实例。假设新规则将覆盖总共 `t` 个实例，其中 `p` 是该类别的正例，`t`–`p` 是其他类别的实例——它们是规则犯的错误。然后选择新的项以最大化比率 `p`/`t`。

一个例子会有所帮助。换一下，我们使用 [表 1.1](#Ch001_3-42_B9780443158889000029.xhtml#t0010) 的隐形眼镜问题。我们将依次形成覆盖三个类别 `hard`、`soft` 和 `none` 的规则。首先，我们寻求一个规则。

```
If? then recommendation = hard.
```

对于未知项“?”，我们有九种选择：

| `age = young` || 2/8 |
| --- | --- |
| `age = prepresbyopic` || 1/8 |
| `age = presbyopic` || 1/8 |
| `spectacle prescription = myope` || 3/12 |
| `spectacle prescription = hypermetrope` || 1/12 |
| `astigmatism = no` || 0/12 |
| `astigmatism = yes` || 4/12 |
| `tear production rate = reduced` || 0/12 |
| `tear production rate = normal` || 4/12 |

右侧的数字显示了该选择所挑选出的集合中“正确”实例的比例。在这种情况下，*正确* 意味着推荐是 `hard`。例如，`age = young` 选择了八个实例，其中两个推荐硬性隐形眼镜，因此第一个分数为 2/8。（要跟上这一点，你需要回顾 [表 1.1](#Ch001_3-42_B9780443158889000029.xhtml#t0010) 中的隐形眼镜数据并统计表中的条目。）我们选择最大分数 4/12，在列表中第七项和最后一项之间任意选择，并创建规则：

```
If astigmatism = yes then recommendation = hard
```
