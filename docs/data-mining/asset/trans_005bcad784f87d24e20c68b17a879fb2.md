
在实际数据集中包含以整数编码的名义值是很常见的。例如，整数标识符可能被用作 `part number` 等属性的代码，但这些整数并不 intended 用于小于或大于的比较。如果是这样，就必须明确该属性是名义型而非数值型。

完全有可能将序数属性当作名义属性来处理。事实上，一些机器学习方法只处理名义元素。例如，在隐形眼镜问题中，`age` 属性被当作名义属性处理，所生成的规则包括以下这些：

```
If age = young and astigmatic = no
and tear production rate = normal
then recommendation = soft
```

```
If age = pre-presbyopic and astigmatic = no
and tear production rate = normal
then recommendation = soft
```

但事实上，按这种方式指定的 `age` 实际上是一个序数属性，其满足以下关系：

```
young < pre-presbyopic < presbyopic
```

如果将其作为序数属性处理，这两个规则可以合并为一条：

```
If age ≤ pre-presbyopic and astigmatic = no
and tear production rate = normal
then recommendation = soft
```

这是一种更简洁，因而更令人满意的表达相同内容的方式。

## 缺失值

实际遇到的大多数数据集，例如 [表 1.6](#Ch001_3-42_B9780443158889000029.xhtml#t0035) 中的劳工谈判数据，都包含缺失值。缺失值经常用超出范围的条目表示；例如，在通常只为正的数值字段中出现负数（如 −1），或在通常不可能为 0 的数值字段中出现 0。对于名义属性，缺失值可能用空白或破折号表示。有时不同种类的缺失值会被区分开（如未知 vs 未记录 vs 不相关的值），并可能用不同的负整数（−1、−2 等）表示。

你必须仔细思考缺失值的意义。它们可能因多种原因而出现，例如测量设备故障、数据收集期间实验设计的变更，以及多个相似但不完全相同的数据集的汇编。调查受访者可能拒绝回答某些问题，例如 `age` 或 `income`。在考古研究中，标本如头骨可能受损，导致某些变量无法测量。在生物学研究中，植物或动物可能在所有变量都测量完毕前死亡。这些事情对所考虑的实例 *意味着* 什么？头骨受损本身可能具有某种意义，还是只是随机事件造成的？植物的早逝对案例是否有影响呢？

大多数机器学习方法都隐含假设某个实例的属性值缺失并无特别意义；该值只是未知。然而，属性值未知可能有充分理由——例如根据现有证据决定不进行某项特定测试——这可能传达有关该实例的其他信息，而不仅仅是值缺失的事实。如果是这种情况，那么将 `not tested` 记录为该属性的另一个可能取值，或作为数据集中另一个属性会更合适。正如前述示例所示，只有熟悉数据的人才能做出明智判断，判断某个值缺失是否具有额外意义，还是应简单地编码为普通缺失值。当然，如果似乎存在几种类型的缺失值，那就是初步证据表明存在需要调查的问题。

如果缺失值意味着操作员决定不进行某项特定测量，这可能传达的信息远不止值未知的事实。例如，分析医疗数据库的人们注意到，在某些情况下，病例可能仅凭医生决定开具的检查项目即可诊断，而与检查结果无关。那么记录哪些值是“缺失”的就足以进行完整诊断——实际值完全可以忽略！

## 不准确的值

检查数据挖掘文件时，必须仔细核查异常的属性和属性值。用于挖掘的数据几乎肯定不是专门为此目的收集的。最初收集时，许多字段可能无关紧要而被留空或未勾选。只要不影响数据的原始用途，就没有纠正的动力。然而，当同一数据库用于挖掘时，错误和遗漏突然变得非常重要。例如，银行实际上不需要知道客户的 `age`，因此其数据库可能包含许多缺失或错误的值。但 `age` 可能是挖掘规则中非常重要的特征。

数据集中出现的排版错误显然会导致值不正确。经常会出现名义属性的值拼写错误，从而为该属性创建了一个额外的可能取值。或者可能不是拼写错误，而是同一事物的不同名称，例如 `Pepsi` 和 `Pepsi-Cola`。显然，像 `ARFF` 这样的定义格式的意义在于允许对数据文件进行内部一致性检查。然而，原始数据文件中出现的错误通常会通过转换过程保留到用于数据挖掘的文件中；因此应仔细检查每个属性可能取值的列表。

数值中的排版或测量错误通常会导致异常值，可通过一次绘制一个变量来检测。错误的值往往与剩余值中明显的模式显著偏离。然而，有时不准确的值很难找到，尤其是在没有专业领域知识的情况下。

重复数据是另一类错误来源。如果数据文件中的某些实例被重复，大多数机器学习工具会产生不同的结果，因为重复会使它们对结果产生更大影响。

人们在向数据库输入个人数据时经常故意出错。他们可能会对街道拼写做细微更改，以判断自己提供的信息是否最终被出售给让他们收到垃圾邮件的广告机构。如果过去曾被拒保，他们在申请保险时可能会调整姓名的拼写。僵化的计算机化数据录入系统常常施加限制，需要创造性的变通方法。有一个故事讲到一个外国人在美国租车。由于他来自国外，没有 `ZIP` 编码；但电脑坚持要求提供；在绝望中，操作员建议他使用租车机构的 `ZIP` 编码。如果这是常见做法，未来的数据挖掘项目可能会注意到一群看似与该机构住在同一区域的客户！同样，超市收银员有时会在顾客未提供时使用自己的常客卡，要么让顾客获得原本不可用的折扣，要么只是为了在收银员账户中累积积分。只有对正在发生的事情有深刻的语义知识，才能解释这类系统性数据错误。

最后，数据会过时。许多项目会随着情况变化而变化。例如，邮件列表中的项目——姓名、地址、电话号码等——经常变化。你需要考虑你正在挖掘的数据是否仍然是当前的。
