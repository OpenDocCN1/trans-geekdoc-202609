
到目前为止，我们描述的决策树是在节点处通过将某个属性的值与常数进行比较来划分数据。这是常见的方法。如果用两个输入属性在二维中可视化，将一个属性的值与常数比较会使数据沿该轴平行分割。然而，还有其他可能性。有些树会将两个属性相互比较，而另一些则计算多个属性的某个函数。例如，如[第 3.2 节](#Ch003_67-89_B9780443158889000042.xhtml#s0015)所述使用超平面会产生不平行于轴的*斜*分割。*函数树*可以具有斜分割以及用于预测的叶节点上的线性模型。树中某些节点也可以指定不同属性上的替代分割，就好像树设计者无法决定选择哪一个一样。如果属性似乎对分类数据同样有用，这可能很有用。这类节点称为*选项*节点，在对未知实例进行分类时，会跟随选项节点引出的所有分支。这意味着实例最终会落入多个叶节点，产生各种替代预测，然后以某种方式组合（例如，使用多数投票）。

手动为数据集构建决策树既有启发性，甚至也很有趣。为了有效地做到这一点，你需要一种良好的数据可视化方法，以便决定哪些属性最有可能成为最佳测试属性以及适当的测试可能是什么。Weka Explorer 中描述了[附录 B](#AppendixB_637-654_B9780443158889000224.xhtml#AppendixB_637-654_B9780443158889000224)，它具有用户分类器功能，允许用户交互式地构建决策树。它会向你展示数据相对于两个选定属性的散点图，由你选择。当你找到一对能很好地区分类别的属性时，可以通过在散点图上围绕适当的数据点绘制多边形来创建二分分割。

例如，在[图 3.3A](#Ch003_67-89_B9780443158889000042.xhtml#f0020)中，用户正在操作一个具有三个类别的数据集，即鸢尾花数据集，并找到了两个属性 *petallength* 和 *petalwidth*，它们很好地划分了类别。手动绘制了一个矩形以分离出其中一个类别（*I. versicolor*）。然后用户切换到[图 3.3B](#Ch003_67-89_B9780443158889000042.xhtml#f0020)中的决策树视图以查看目前的树。左边的叶节点主要包含一种类型的鸢尾花（*I. versicolor*，仅被一个 *virginica* 污染）；右边的叶节点主要包含两种类型（*I. setosa* 和 *virginica*，仅被三个 *versicolors* 污染）。用户很可能会选择右边的叶节点并下一步对其进行处理，用另一个矩形进一步分割它——也许基于不同的属性对（尽管从[图 3.3A](#Ch003_67-89_B9780443158889000042.xhtml#f0020)来看，这两个看起来相当不错）。

我们一直在研究的决策树种类旨在预测类别而非数值。当预测数值时，如[表 1.5](#Ch001_3-42_B9780443158889000029.xhtml#t0030)中的 CPU 性能数据，可以使用同类型的树，但每个叶节点将包含一个数值，该数值是叶节点所适用的训练集所有值的平均值。因为预测的是数值，所以叶节点具有平均数值的决策树称为*回归树*。

[图 3.4A](#Ch003_67-89_B9780443158889000042.xhtml#f0025) 显示了 CPU 性能数据的回归方程，而[图 3.4B](#Ch003_67-89_B9780443158889000042.xhtml#f0025) 显示了回归树。树的叶节点是数字，表示到达该叶节点的实例的平均结果。树比回归方程大得多且更复杂，如果我们计算预测 CPU 性能度量与实际值之间误差的绝对值的平均值，结果树的误差明显小于回归方程。回归树更准确，因为简单的线性模型在这个问题中不能很好地表示数据。然而，由于树规模庞大，它笨重且难以解释。

## 3.4 规则

规则是决策树的流行替代方案，我们已经对天气、隐形眼镜、鸢尾花和大豆数据集看到了示例。规则的*前件*，或前提，是一系列测试，就像决策树节点中的测试一样，而*后件*，或结论，给出了该规则所覆盖的实例适用的类别或类别，或许给出类别上的概率分布。通常前提条件在逻辑上是 AND 组合的，如果规则要触发，所有测试必须成功。然而，在某些规则表述中，前提条件是一般逻辑表达式而不是简单合取。我们通常认为各个规则在逻辑上有效地是 OR 组合的：如果其中任何一个适用，则在其结论中给出的类别（或概率分布）应用于实例。然而，当多个具有不同结论的规则适用时，会出现冲突；我们稍后会回到这个问题。

### 分类规则

可以直接从决策树读取一组分类规则。每个叶节点生成一条规则。规则的前件包括从根到该叶节点路径上每个节点的条件，而规则的后件是叶节点分配的类别。此过程产生的规则是无歧义的，因为执行的顺序无关紧要。然而，通常直接从决策树读取的规则比必要的情况复杂得多，并且从树派生的规则通常会被修剪以删除冗余测试。
