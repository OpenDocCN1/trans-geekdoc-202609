
Another simple option is to include features for each word in the document up to a fixed document length of `N`<mml:math><mml:mi>N</mml:mi></mml:math>![Equation](images/F000121si83.png) word tokens while clipping the end of longer documents down to length `N`<mml:math><mml:mi>N</mml:mi></mml:math>![Equation](images/F000121si84.png) and padding shorter documents with dummy values until they reach length `N`<mml:math><mml:mi>N</mml:mi></mml:math>![Equation](images/F000121si85.png).

The approaches for obtaining fixed-length representations of documents we have discussed so far do not encode the meanings of words relative to each other. To achieve this we can instead use `document embeddings` (i.e., learned representations of documents). A straightforward approach for obtaining `document embeddings` is to average the word embeddings for all the word tokens in each document. This is equivalent to adding the word embeddings’ vectors in an end-to-tail fashion, which we could visualize as taking a step in each word embedding’s direction for each word token in the document, then dividing the length of the vector by the number of word tokens. Alternatively, there are models that learn document embeddings directly such as `doc2vec`. These document embedding models can outperform the simple averaging approach but are more complicated to implement. More recently, transformer-based language models such as `BERT`, which we will discuss later, have proven effective at learning document representations and currently achieve state-of-the-art performance on most NLP tasks.

Once a fixed-length document representation is obtained, we can apply a feed-forward neural network to predict the class labels. If pretrained document or word embeddings are used in the initial representation, we have the option to either hold those embeddings fixed while training or fine-tuning the classification model or to update the embeddings during training. The latter may perform better but is only feasible if sufficient task-specific data and computational resources are available.

Alternatively, we can instead directly address the sequential nature of text data by applying neural network architectures that handle sequential data. Convolutional neural networks can be applied to the sequence of tokens in a document using one-dimensional convolution, where we slide convolutional filters over the word tokens to identify patterns that occur within the convolutional window (i.e., a window of several words before or after the current token, similar to the context windows used in `word2vec`). Each filter identifies the presence of one type of pattern in a document, and many such filters are used simultaneously, each producing a corresponding feature, producing a feature vector that can be processed by additional convolutional or dense layers. However, since `CNNs` only consider a small convolutional window at once they cannot model long-range dependencies, such as between words at the beginning and end of a sentence.

Recurrent neural networks (`RNNs`) are another option that do not have this problem. While simple `RNNs` suffer from vanishing gradient issues due to the necessity of backpropagating through the input sequence as well as through the layers, effectively making them behave like much deeper neural networks, more sophisticated `RNNs` including long short-term memory (`LSTMs`), bi-directional `LSTMs`, and gated recurrent unit models keep track of a “long-term memory,” which helps to address vanishing gradients. These models have been successfully used for many deep learning NLP tasks, and this approach was popular for several years in the 2010s. However, at the time of writing, even these sophisticated methods have been mainly supplanted by transformer-based large language models, which process a context window of text in parallel rather than sequentially while still capturing long-range dependencies, unlike `CNNs`.

### Unsupervised and Self-Supervised Training of Large Language Models

Large language models, which learn models of sequences of words based on very large datasets, are the keystone of recent progress in NLP. The size of the training datasets is an enabling factor in the success of these models as it allows them to learn the linguistic patterns present in natural language and to even capture knowledge about the world that is present in text. One crucial challenge in training `LLMs` is a lack of labeled text data compared to the amount of unlabeled text data that could be obtained from large-scale unannotated text corpora including books, the internet, social media, and so on.

There are several key ideas that enable training `LLMs` without fully labeled data. The first idea is `self-supervised learning`—using an auxiliary task, for which labels can be automatically extracted without human annotation, to train the model. For example, the `skip-gram` `word2vec` model learns embeddings by predicting the words in the context of a given word. This task was invented for the sole purpose of training a model that obtains good embeddings, and the labels are extracted from the text itself automatically, without requiring human annotation. Self-supervised learning can be considered to be “in between” the unsupervised and supervised learning paradigms as it shares aspects of both.

The second key idea is the `encoder-decoder architecture`, based on autoencoders (see the previous chapter). Similarly to autoencoders, these models consist of two component networks; an `encoder` and a `decoder`. The encoder network maps the input (in our case, input text data) to a latent embedding representation that captures the important semantic information in the input. The decoder network then maps the embedding to the desired output. While autoencoders use the decoder to reproduce the input based on the embedding representation, in the more general encoder-decoder architecture the output could be something else of interest, that is, the next token in the document or the translation of the input text into another language.

To elaborate the latter case, the task of `machine translation` (`MT`) is to translate from one language to another (e.g., from English to French). If neural networks are used, this is called `neural machine translation` (`NMT`), and when using statistical models it is called `statistical machine translation` (`SMT`). `NMT` methods currently generally outperform `SMT` approaches and are deployed in the Google Translate service. `Seq2Seq` is a classic `NMT` model that uses an encoder-decoder architecture. Its training data pairs corresponding sentences in the two languages. The encoder learns to represent the input sentence with an embedding, and the decoder then converts the resulting embedding to the output language. The final hidden state from the encoder’s recurrent network is the embedding that provides the “context” information for the decoder to use to do the translation. The encoder and decoder are both deep `LSTMs`. In the original paper, each of these submodels had four `LSTM` layers. The two modules can also be used alone; some other models use only an encoder (e.g., `BERT`), and others use only a decoder (e.g., `GPT`).

A third idea, which is not essential to training `LLMs` but which proves highly beneficial, is `attention`—modeling which of the words in the input to pay more attention to or focus on the most. We will discuss this in the next section.
