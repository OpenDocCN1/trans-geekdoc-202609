
A privacy mechanism `M(X)` is (`ϵ`, `δ`)-differentially private if for all pairs of datasets `D1` and `D2` differing in a single element, and all `S` ⊆ `Range(M)`,

`Pr(M(D1) ∈ S) ≤ e^(ϵ) × Pr(M(D2) ∈ S) + δ.` (7.5)

If `δ` = 0 the definition corresponds to `ϵ`-differential privacy. For the definition to offer meaningful privacy guarantees, `δ` must be very small, as it only ensures that the guarantees of `ϵ`-differential privacy will be enforced with probability `1 - δ`.

Stated informally, these guarantees and other useful properties include:

- Neutralization of linkage attacks. No matter what auxiliary data is available, an adversary cannot undo the obfuscation of the query due to noise to increase its privacy parameters `ϵ` and `δ`.
- Closure under postprocessing. Without access to the private database, no further computation can make the algorithm `M` less differentially private.
- Economic guarantees for those who contribute their data. For any utility function, a user’s utility value will not be changed by more than a multiplicative factor of `e^(ϵ)`, which approximately equals `1 + ϵ` for small values of `ϵ`, due to their decision to contribute their data to the dataset.
- Group privacy. It is possible to calculate the quantification of differential privacy as it extends to a group of individuals, to an entire family.
- Composition. When performing multiple differentially private computations, the privacy parameters of the overall process increase gracefully and in a measurable way. If an `ϵ1`-differentially private operation is performed followed by an `ϵ2`-differentially private operation, then the overall procedure is (`ϵ1 + ϵ2`)-differentially private.

This type of composition calculation is much more complicated in the case of (`ϵ`, `δ`)-differential privacy but with some sophisticated mathematical wizardry, which can be outsourced to software libraries, it can be done. For a fixed value of `δ`, we can view `ϵi` of the `i`th query as its “privacy cost,” which accumulates toward using up an overall target “privacy budget” `ϵoverall`.

## Differentially Private Machine Learning

In practice, the art of differentially private machine learning is to carefully design a privacy-preserving learning scheme so that the target level of differential privacy is achieved while retaining satisfactory performance. We can see from the equation for the Laplace mechanism that the more private we want to make it (smaller `ϵ`), the more noise we need to add, garbling the results. In general, there is a trade-off between differential privacy and the accuracy or usefulness of the output, often referred to as “utility.” We must engineer our privacy-preserving learning algorithm to manage this privacy-utility trade-off.
