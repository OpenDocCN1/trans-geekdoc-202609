
总之，数据挖掘方案的输入通常表示为待学习概念的独立实例的表格。正因如此，有人曾贬义地建议，我们应该真正谈论 `file mining` 而不是 `database mining`。关系数据比平面文件更复杂。有限个有限关系总可以重构为单一表格，尽管通常会以巨大的空间成本为代价。此外，反规范化会产生数据中的虚假规律，在应用学习方案之前，必须检查数据是否存在此类人为产物。潜在的无限概念可以通过递归的学习规则来处理，尽管这超出了本书的范围。最后，一些重要的现实世界问题最自然地以多实例格式表达，其中每个示例实际上是一组独立的实例。

## 2.3 属性中有什么？

提供机器学习输入的每个实例都由其在固定、预定义的特征或 `attributes` 集合上的取值来表征。我们在天气、隐形眼镜、鸢尾花和 CPU 性能问题中展示的表格中，实例是行，属性是列。（劳工谈判数据是一个例外；出于空间原因，我们将其以实例为列、属性为行为展示。）

使用固定的特征集对实际数据挖掘中通常考虑的问题类型施加了另一个限制。如果不同实例具有不同的特征怎么办？例如，如果实例是交通工具，那么 `number of wheels` 是适用于许多车辆但不适用于船只的特征，而 `number of masts` 可能是适用于船只但不适用于陆地车辆的特征。标准的变通方法是使每个可能的特征都成为一个属性，并使用特殊的“`irrelevant value`”标志来表示特定属性在特定情况下不可用。当一个特征的存在（例如，`spouse’s name`）取决于另一个特征的值（`married or single`）时，也会出现类似情况。

特定实例的属性值是对该属性所指数量的测量。属性可大致分为 `numeric` 和 `nominal` 两类。数值属性，有时称为 `continuous` 属性，测量的是数字——实数或整数值。请注意，在此上下文中 `continuous` 一词经常被滥用；整数值属性在数学意义上 certainly 不是连续的。名义属性取值于预先指定的有限可能性集合中，有时称为 `categorical`。但还有其他可能性。统计学教材常引入“测量水平” such as `nominal`、`ordinal`、`interval` 和 `ratio`。

名义属性的值是不同的符号。值本身仅用作标签或名称——因此得名 `nominal`，它源自拉丁语中表示 `name` 的词。例如，在天气数据中，属性 `outlook` 的取值有 `sunny`、`overcast` 和 `rainy`。这三者之间没有暗示任何关系——没有顺序或距离度量。把这些值相加、相乘，甚至比较其大小显然是没有意义的。使用此类属性的规则只能测试相等或不相等，如

```
outlook: sunny→no
```

```
overcast→yes
```

```
rainy→yes
```

序数属性是可以对类别进行排序的属性。然而，虽然存在 `ordering` 的概念，但没有 `distance` 的概念。例如，在天气数据中，属性 `temperature` 的取值有 `hot`、`mild` 和 `cool`。这些是有序的。说

`hot > mild > cool or hot < mild < cool`

是约定俗成的——只要保持一致，使用哪一种都无所谓。重要的是 `mild` 位于其他两个之间。虽然比较两个值是有意义的，但加减它们是没有意义的——`hot` 与 `mild` 之间的差异无法与 `mild` 与 `cool` 之间的差异进行比较。使用此类属性的规则可能涉及比较，如

```
temperature = hot → no
```

```
temperature < hot → yes
```

请注意，名义属性与序数属性之间的区别并不总是简单明了。事实上，我们之前使用的名义属性示例 `outlook` 并不是完全清楚的；你可以争辩说这三个取值 `do` 确实存在顺序——随着天气从好变坏，`overcast` 在某种程度上介于 `sunny` 和 `rainy` 之间。

区间量值的取值不仅有序，而且以固定且相等的单位进行度量。一个很好的例子是以度（例如华氏度）表示的温度，而不是 cool、mild 和 hot 所暗示的非数值尺度。谈论两个温度之间的差异，例如 46°C（114.8 °F）和 48°C（118.4 °F），并将其与另外两个温度之间的差异进行比较，例如 22°C（71.6 °F）和 24°C（75.2 °F），是完全合理的。另一个例子是日期。你可以谈论 1939 年和 1945 年之间的差异（6 年），甚至 1939 年和 1945 年的平均值（1942 年），但考虑 1939 年和 1945 年之和（3884）或 1939 年的三倍（5817）就没什么意义了，因为起点，即公元 0 年，完全是任意的——事实上，它在历史进程中已多次改变。（孩子们有时会想知道在公元前 300 年时，公元前 300 年被称为什么。）

比率量是指测量方案本身定义了零点的量。例如，在测量一个物体到另一个物体的距离时，物体与其自身之间的距离构成自然零点。比率量被视为实数；任何数学运算都是允许的。谈论距离的三倍，甚至将一个距离乘以另一个距离得到面积，显然是有意义的。

然而，是否存在“inherently”定义的零点取决于我们的科学知识——它具有文化相对性。例如，丹尼尔·华伦海特不知道温度的下限，他的温标是区间尺度。如今，我们却将温度视为基于绝对零度的比率尺度。以某种文化定义的零点（如 ad 0）为起点的年份来衡量时间不是比率尺度；自大爆炸以来的年份才是。即使是金钱的零点——我们通常很乐意说某物花费是另一物的两倍——对于那些不断透支信用卡的人来说，可能也并不完全明确。

许多实际的数据挖掘系统仅容纳这四种测量水平中的两种：名义和序数。名义属性有时称为 `categorical`、`enumerated` 或 `discrete`。`Enumerated` 是计算机科学中表示分类数据类型的标准术语；然而，该术语的严格定义——即与自然数一一对应——意味着一种排序，而这在机器学习上下文中 specifically 并未暗示。`Discrete` 也带有排序的含义，因为你经常将连续数值量离散化。序数属性通常被编码为 `numeric` 数据，或许是 `continuous` 数据，但不暗示数学上的连续性。名义尺度的一个特例是 `dichotomy`，它只有两个成员——通常指定为 `true` 和 `false`，或在天气数据中为 `yes` 和 `no`。此类属性有时称为 `Boolean`。
