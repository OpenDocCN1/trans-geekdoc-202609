
字符串属性的值可能非常长——甚至是一个完整的文档。为了能够将字符串属性用于文本挖掘，有必要能够对其进行操作。例如，字符串属性可能被转换为多个数值属性，每个单词一个，其值是该单词在字符串中出现的次数。这些转换在 [第 6.3 节](#Ch006_209-259_B9780443158889000078.xhtml#s0060) 中有描述。

日期属性是具有特殊格式的字符串，引入方式如下：

```
@attribute today date
```

(名为 `today` 的属性)。Weka 使用 ISO-8601 组合日期和时间格式 `yyyy-MM-dd’T’HH:mm:ss`，年份用四位数字表示，月份和日期各用两位数字，然后是字母 `T`，随后是时间，小时、分钟和秒各用两位数字。^(<a aria-label="noteref" href="#fn1" id="Cfn1">1</a>1) 在文件的数据部分，日期以日期和时间的对应字符串表示形式指定（例如，`2004-04-03T12:00:00`）。尽管它们被指定为字符串，但在读取输入文件时日期会被转换为数值形式。日期也可以在内部转换为不同格式，因此您可以在数据文件中保留绝对时间戳，并使用转换将其变为诸如一天中的时间或一周中的日期等形式以检测周期性行为。

关系值属性与其他类型不同，因为它们允许以 ARFF 格式表示多实例问题。关系属性的值是一组单独的实例。该属性使用名称和类型 `relational` 定义，后跟一个嵌套的属性块，描述引用实例的结构。例如，一个名为 `bag` 的关系值属性，其值是一个与天气数据结构相同但不包含 `play` 属性的数据集，可以这样指定：

```
@attribute bag relational
```

```
@attribute outlook {sunny, overcast, rainy}
```

```
@attribute temperature numeric
```

```
@attribute humidity numeric
```

```
@attribute windy {true, false}
```

```
@end bag
```

`@end bag` 表示嵌套属性块的结束。[图 2.3](#Ch002_43-66_B9780443158889000030.xhtml#f0020) 显示了一个基于天气数据的多实例问题的 ARFF 文件。在这种情况下，每个示例由一个标识符值、原始天气数据中的两个连续实例以及一个类标签组成。属性的每个值都是一个字符串，其中包含两个由 `\\n` 字符分隔的天气实例（该字符表示嵌入的换行符）。这可能适用于持续 2 天的游戏。类似的数据集也可能用于持续不确定天数的游戏（例如，一级板球赛持续 3–5 天）。然而请注意，在多实例学习中，通常认为实例提供的 `order` 顺序并不重要。算法可能会学习到如果没有一天下雨且至少有一天晴朗就可以打板球，但不会学习到它只能在某种特定的天气事件序列中进行。

## 稀疏数据

有时大多数属性在大多数实例中的值都是 0。例如，市场篮子数据记录了超市顾客的购买情况。无论购物规模多大，顾客永远不会购买商店提供的超过一小部分商品。市场篮子数据包含顾客购买的每种商品的数量，而对于库存中的几乎所有商品，这一数量都是 0。数据文件可以被视为一个矩阵，其行和列分别代表顾客和库存商品，该矩阵是“稀疏的”——几乎所有元素都是 0。另一个例子出现在文本挖掘中，其中实例是文档。这里，列和行分别代表文档和单词，数字表示特定单词在特定文档中出现的次数。大多数文档的词汇量相对较小，因此大多数条目都是 0。

表示稀疏矩阵的每个元素可能不切实际。与按顺序表示每个值不同，例如这样：

```
0, X, 0, 0, 0, 0, Y, 0, 0, 0, “class A”
```

```
0, 0, 0, W, 0, 0, 0, 0, 0, 0, “class B”
```

非零属性可以通过属性编号明确标识并说明其值：

```
{1 X, 6 Y, 10 “class A”}
```

```
{3W, 10 “class B”}
```

每个实例用大括号括起来，包含每个非零属性的索引号（索引从 0 开始）及其值。稀疏数据文件具有相同的 `@relation` 和 `@attribute` 标签，后跟 `@data` 行，但数据部分不同，包含前面所示的大括号内的规范。请注意，被省略的值的值为 0——它们不是“缺失”值！如果某个值未知，必须用问号明确表示。

## 属性类型

ARFF 格式支持两种基本数据类型：名义型和数值型。字符串属性和日期属性在本质上分别相当于名义型和数值型，尽管在使用之前字符串通常会被转换为诸如词向量之类的数值形式。关系值属性包含具有基本属性（如数值型和名义型）的单独实例集。两种基本类型的解释取决于所使用的学习方案。例如，许多方案将数值属性视为序数尺度，仅使用值之间的小于和大于比较。然而，有些方案将它们视为比率尺度并使用距离计算。在使用它们进行数据挖掘之前，您需要了解机器学习方案的工作原理。

如果学习方案将数值属性视为按比率尺度测量，则会出现归一化问题。属性通常被归一化到固定范围内——通常从零到一——方法是除以遇到的最大值，或减去最小值并除以最大值与最小值之间的范围。另一种归一化技术是计算属性值的统计均值和标准差，从每个值中减去均值，然后将结果除以标准差。此过程称为对统计变量进行 `standardizing`，结果得到一组均值为零、标准差为一的值。

一些学习方案（例如，基于实例和回归方法）仅处理比率尺度，因为它们根据属性的值计算两个实例之间的“距离”。如果实际尺度是序数，则必须定义数值距离函数。一种方法是使用两级距离：如果两个值不同则为一，如果相同则为零。任何名义量都可以通过使用此距离函数被视为数值。然而，这是一种相当粗糙的技术，会掩盖实例之间真实的变化程度。另一种可能性是为每个名义属性生成几个合成的二元属性；我们将在 [第 9.3 节](#Ch010_347-389_B9780443158889000108.xhtml#s0105) 中再次讨论这一点，当时我们将研究树在数值预测中的使用。

有时名义属性与数值尺度之间存在真正的映射。例如，邮政 ZIP 编码表示的区域可以用地理坐标表示；电话号码的前几位数字也可能如此，具体取决于您居住的地方。学生身份证号的前两位数字可能是她首次入学的年份。
