
# 概率估计与贝叶斯网络

概率估计通常比单纯的预测更有用。它们允许对预测进行排序，并使预期成本最小化（[第 5.8 节](#Ch005_165-207_B9780443158889000066.xhtml#s0070)）。事实上，将分类学习视为从数据中学习类别概率估计的任务是有充分理由的。所估计的是在给定其他属性值的情况下，类属性值的条件概率分布。理想情况下，分类模型以简洁且易于理解的形式表示这种条件分布。

按这种方式来看，朴素贝叶斯分类器、逻辑回归模型、决策树等等仅仅是表示条件概率分布的替代方法。当然，它们在表示能力上有所不同。朴素贝叶斯分类器和逻辑回归模型只能表示简单分布，而决策树可以表示——或至少近似——任意分布。然而，决策树也有其缺点。它们将训练集分割成越来越小的片段，这不可避免地导致可靠性较低的概率估计，并且它们遭受[第 3.4 节](#Ch003_67-89_B9780443158889000042.xhtml#s0025)中描述的重复子树问题。规则集在一定程度上解决了这些不足，但设计一个好的规则学习器是由理论依据甚少的启发式方法指导的。

这是否意味着我们必须接受命运并生活在这些不足中？不！存在一种基于统计的替代方案，一种在理论上具有良好基础的、以图形化方式简洁且可理解地表示概率分布的方法。这些结构被称为 `Bayesian networks`。它们被绘制为节点网络，每个属性一个节点，通过有向边连接，使得没有环——一个 `directed acyclic graph (DAG)`。

在本节中，为了解释如何解释贝叶斯网络以及如何从数据中学习它们，我们将做出一些简化假设。我们假设所有属性都是标称的——它们对应于离散随机变量——并且没有缺失值，因此数据是完整的。一些高级学习算法可以在数据中已有的属性之外创建新的属性——所谓的隐藏属性，对应于无法观察其值的潜在变量。如果它们代表了底层问题的显著特征，这些属性可以支持更好的模型，并且贝叶斯网络提供了一种在预测时使用它们的好方法。然而，它们使学习和预测变得更加复杂和耗时，因此我们将推迟考虑它们到[第 14.1 节](#Ch015_516-570_B9780443158889000157.xhtml#s0010)。

## 进行预测

[图 13.1](#Ch014_485-514_B9780443158889000145.xhtml#f0010) 显示了天气数据的简单贝叶斯网络。它为四个属性 `outlook`、`temperature`、`humidity` 和 `windy` 各有一个节点，以及类属性 `play` 的一个节点。一条边从 `play` 节点指向每个其他节点。但在贝叶斯网络中，图的 fiy 结构只是故事的一半。[图 13.1](#Ch014_485-514_B9780443158889000145.xhtml#f0010) 在每个节点内显示一个表格。表格中的信息定义了一个概率分布，用于预测任意给定实例的类概率。

![图 13.1 天气数据的简单贝叶斯网络。](images/F000145f13-01-9780443158889.jpg)
图 13.1 天气数据的简单贝叶斯网络。

在查看如何计算该概率分布之前，先考虑表格中的信息。最下面的四个表格（`outlook`、`temperature`、`humidity` 和 `windy`）分为两部分，中间用垂直线分隔。左侧是 `play` 的取值，右侧是节点所代表属性每个取值对应的概率。一般来说，左侧为指向该节点的每条边包含一列，在本例中只是从 `play` 属性节点发出的边。这就是为什么与 `play` 本身关联的表格没有左侧——它没有父节点。每一行概率对应父属性值的一个组合，该行中的条目显示在该组合下节点属性每个值的概率。实际上每一行都在节点属性的值上定义了一个概率分布。一行中的条目始终总和为 1。

[图 13.2](#Ch014_485-514_B9780443158889000145.xhtml#f0015) 显示了同一问题的更复杂网络，其中三个节点（`windy`、`temperature` 和 `humidity`）有两个父节点。同样，左侧为每个父节点有一列，右侧的列数与属性的取值数相同。考虑与 `temperature` 节点关联的表格的第一行。左侧为每个父属性 `play` 和 `outlook` 给出一个值；右侧为 `temperature` 的每个取值给出一个概率。例如，第一个数字（0.143）是在 `play` 和 `outlook` 的值分别为 `yes` 和 `sunny` 的条件下，`temperature` 取值为 `hot` 的概率。

![图 13.2 天气数据的另一个贝叶斯网络。](images/F000145f13-02-9780443158889.jpg)
图 13.2 天气数据的另一个贝叶斯网络。

这些表格如何用于预测给定实例的每个类值的概率？这实际上非常简单，因为我们假设没有缺失值。实例为每个属性指定一个值。对于网络中的每个节点，根据其父节点属性值确定的行查找该节点属性值的概率。然后将所有这些概率相乘。

例如，考虑一个实例，其值为 `outlook = rainy`、`temperature = cool`、`humidity = high` 和 `windy = true`。要计算 `play = no` 的概率，注意 [图 13.2](#Ch014_485-514_B9780443158889000145.xhtml#f0015) 中的网络给出节点 `play` 的概率为 0.367，`outlook` 为 0.385，`temperature` 为 0.429，`humidity` 为 0.250，`windy` 为 0.167。乘积为 0.0025。对 `play = yes` 进行同样的计算得到 0.0077。然而，这些显然不是最终答案；最终概率必须总和为 1，而 0.0025 和 0.0077 并非如此。它们实际上是联合概率 `P`(`play` = `no`, `E`) 和 `P`(`play` = `yes`, `E`)，其中 `E` 表示实例属性值提供的所有证据。联合概率衡量观察到具有 `E` 中的属性值以及相应类值的实例的可能性。只有当它们穷尽所有可能的属性-值组合（包括类属性）时，它们才总和为 1。在我们的例子中显然不是这样。
