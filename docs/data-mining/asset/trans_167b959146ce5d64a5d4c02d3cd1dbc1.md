
当子树替换被实现时，它从叶节点开始并向上回溯至根节点。在[图 1.3](#Ch001_3-42_B9780443158889000029.xhtml#f0020)示例中，(b) 中的整个子树不会一次性被替换。首先会考虑将 `health plan contribution` 子树中的三个子节点替换为单个叶节点。假设决定执行此替换；我们稍后会解释如何进行。然后，继续从叶节点回溯，会考虑用单个叶节点替换现在仅有两个子节点的 `working hours per week` 子树。在[图 1.3](#Ch001_3-42_B9780443158889000029.xhtml#f0020)示例中，此替换确实进行了，这就解释了为什么(b)中的整个子树被单个标记为 `bad` 的叶节点所替换。最后会考虑将 `wage increase 1st year` 子树中的两个子节点替换为单个叶节点。在这种情况下，该决定并未作出，因此树保持如图[图 1.3A](#Ch001_3-42_B9780443158889000029.xhtml#f0020)所示。同样，我们稍后会研究这些决策是如何实际做出的。

第二种剪枝操作，子树提升，更为复杂，并且不明确它是否总是值得进行。然而，由于它被有影响力的决策树构建系统 `C4.5` 所使用，我们在此描述它。子树提升在[图 1.3](#Ch001_3-42_B9780443158889000029.xhtml#f0020)示例中并未出现，因此使用[图 C.1](#FigC1_655-685_B9780443158889000236.xhtml#f0010)的人工示例进行说明。这里考虑对[图 C.1A](#FigC1_655-685_B9780443158889000236.xhtml#f0010)中的树进行剪枝，结果显示在[图 C.1B](#FigC1_655-685_B9780443158889000236.xhtml#f0010)中。从 C 向下的整个子树已被“提升”以替换 B 子树。请注意，尽管 B 和 C 的子节点显示为叶节点，但它们可以是整个子树。当然，如果我们执行此提升操作，则有必要将标记为 4 和 5 的节点中的示例重新分类到以 C 为头的新的子树中。这就是为什么该节点子节点被标记为带撇号——1′、2′ 和 3′——以表明它们与原始子节点 1、2 和 3 不同，而是因包含了原本由 4 和 5 覆盖的示例而有所差异。

子树提升是一种可能耗时的操作。在实际实现中，它通常限制为提升最受欢迎分支的子树。也就是说，我们考虑执行[图 C.1](#FigC1_655-685_B9780443158889000236.xhtml#f0010)中所示的提升，前提是从 B 到 C 的分支具有比从 B 到节点 4 或从 B 到节点 5 的分支更多的训练示例。否则，如果节点 4 是 B 的多数子节点，我们将考虑提升节点 4 以替换 B，并将 C 下的所有示例以及节点 5 的示例重新分类到新节点中。

## 估计误差率

关于这两种剪枝操作就说到这里。现在我们必须解决如何决定是否用叶节点替换内部节点（用于子树替换）或是否用其下方的节点之一替换内部节点（用于子树提升）的问题。要合理地做出此决定，有必要估计在给定独立选择的测试集的情况下，特定节点所期望的误差率。我们需要估计内部节点以及叶节点的误差。如果我们有这样的估计，只需将子树的估计误差与其拟议替换的误差进行比较，就能清楚是否替换或提升特定子树。在估计拟议提升的子树的误差之前，当前节点的兄弟节点下的示例——[图 C.1](#FigC1_655-685_B9780443158889000236.xhtml#f0010)中的 4 和 5 的示例——必须暂时重新分类到提升后的树中。

将训练集误差作为误差估计是没有用的；这不会导致任何剪枝，因为树是专门为该特定训练集构建的。得到误差估计的一种方法是标准验证技术；保留部分原始数据并将其用作独立测试集来估计每个节点的误差。这称为 `reduced-error` 剪枝。它的缺点是实际树基于的数据更少。

另一种选择是尝试基于训练数据本身对误差进行估计。这就是 `C4.5` 所做的，我们将在此描述其方法。它是一种基于某些统计推理的启发式方法，但其统计基础相当薄弱。然而，它在实践中似乎效果很好。其思想是考虑到达每个节点的实例集合，并假设多数类被选来代表该节点。这给出了总实例数 `N` 中的一定数量的“错误”，`E`。现在假设节点处的真实错误概率为 `q`，并且 `N` 个实例由参数为 `q` 的伯努利过程生成，其中 `E` 个最终为错误。
