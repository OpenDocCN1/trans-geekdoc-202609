
## 3.4 形状问题与规则学习

我们隐含地假设规则中的条件涉及将属性值与常数进行比较。但这可能并不理想。举一个具体的例子，假设我们有一组八个各种形状和大小的积木，如 [图 3.9](#Ch003_67-89_B9780443158889000042.xhtml#f0050) 所示，我们希望学习 `standing up` 的概念。这是一个经典的二分类问题，类别为 `standing` 和 `lying`。四个阴影块是该概念的正例（`standing`），而未阴影的块是负例（`lying`）。学习算法唯一会得到的信息是每个积木的 `width`、`height` 和 `number of sides`。训练数据显示在 [表 3.2](#Ch003_67-89_B9780443158889000042.xhtml#t0015) 中。

对于此数据可能产生的常规规则集是：

```
If width ≥ 3.5 and height < 7.0 then lying
```

如果 `height` ≥ 3.5 则 `standing`

如果你好奇的话，3.5 被选为 `width` 的断点，因为它位于最薄的 `lying` 积木的 `width`，即 4，和 `height` 小于 7 的最胖 `standing` 积木的 `width`，即 3 之间。同样，7.0 被选为 `height` 的断点，因为它位于最高 `lying` 积木的 `height`，即 6，和 `width` 大于 3.5 的最短 `standing` 积木的 `height`，即 8 之间。常见的做法是将数值阈值放在界定概念边界的值之间。

尽管这两种规则在给出的示例上效果不错，但它们并不很好。许多新积木都不会被任一规则分类（例如 `width` 为 1 且 `height` 为 2 的积木），并且很容易设计出许多合法的积木而规则无法拟合。

对八个积木进行分类的人可能会注意到“站立的积木是那些比宽更高的积木。”该规则不将属性值与常数进行比较，而是将属性彼此进行比较：

```
If width > height then lying
```

```
If height > width then standing
```

`height` 和 `width` 属性的实际值并不重要——只是比较的结果。

许多机器学习方案不考虑属性之间的关系，因为这样做成本相当高。一种补救方法是添加额外的二级属性，说明两个主要属性是否相等，或者如果它们是数值则给出它们之间的差异。例如，我们可能在 [表 3.2](#Ch003_67-89_B9780443158889000042.xhtml#t0015) 中添加一个二元属性 `is width < height?`。这类属性通常作为数据工程过程的一部分被添加。

通过一个看似很小的进一步改进，可以极大地扩展知识表示的表达能力。诀窍是以使实例的角色明确的方式表达规则：

```
If width(block) > height(block) then lying(block)
```

```
If height(block) > width(block) then standing(block)
```

虽然这看起来可能不是很大的扩展，但如果实例可以分解为部分的话就是如此。例如，如果一个 `tower` 是一堆叠起来的积木，则塔顶积木站立的事实可以表示为：

```
If height(tower.top) > width(tower.top) then standing(tower.top)
```

这里，`tower.top` 用于指代最上面的积木。到目前为止，什么也没有得到。但如果 `tower.rest` 指代塔的其余部分，则塔完全由站立积木组成的事实可以用以下规则表示：

```
If height(tower.top) > width(tower.top) and standing(tower.rest) then standing(tower)
```

看似微不足道的条件 `standing(tower.rest)` 的添加是一个递归表达式，它只有在塔的其余部分由站立积木组成时才为真。这将通过对同一规则的递归应用来测试。当然，有必要通过添加进一步的规则来确保递归“到底”正确，例如：

```
If tower = empty then standing(tower.top)
```

像这样的规则集被称为 `logic programs`，而机器学习这一领域被称为 `inductive logic programming`。我们将在本书中不再进一步讨论它。

## 3.5 基于实例的表示

最简单的学习形式是纯粹的记忆，或 `rote learning`。一旦训练实例集被记忆，在遇到新实例时，记忆会被搜索以找到与新实例最相似的训练实例。唯一的问题是如何解释“相似”；我们稍后会解释。首先，请注意，这是一种完全不同的表示从一组实例中提取的“知识”的方式：只需存储实例本身，并通过将类别未知的实例与类别已知的现有实例相关联来操作。不要试图创建规则，直接从示例本身工作。这被称为 `instance-based` 学习。从某种意义上说，其他所有学习方法也是“基于实例的”，因为我们总是以一组实例作为初始训练信息为起点。但基于实例的知识表示使用实例本身来表示所学内容，而不是推断规则集或决策树并将其存储。

在基于实例的学习中，所有真正的工作都是在对新实例进行分类时完成，而不是在处理训练集时完成。从某种意义上说，那么这种方法与其他我们见过的方法之间的区别在于“学习”发生的时间。基于实例的学习是懒惰的，将真正的工作尽可能推迟，而其他方法是急切的，一旦看到数据就产生泛化。在基于实例的分类中，每个新实例都使用距离度量与现有实例进行比较，最接近的现有实例用于为新实例分配类别。这被称为 `nearest-neighbor` 分类方法。有时使用不止一个最近邻居，最接近的 `k` 个邻居的多数类（如果类别是数值，则为距离加权平均值）被分配给新实例。这被称为 `k-nearest-neighbor` 方法。

当示例只有一个数值属性时，计算两个示例之间的距离是微不足道的：它只是两个属性值之间的差值。当有多个数值属性时也几乎一样简单：通常使用标准欧几里得距离。然而，这假设属性已归一化且重要性相等，而学习的主要问题之一是确定哪些是重要特征。

当存在名义属性时，有必要为该属性的不同值提出“距离”。例如，值 `red`、`green` 和 `blue` 之间的距离是多少？通常如果值相同则分配零距离；否则距离为一。因此 `red` 与 `red` 之间的距离为零，但 `red` 与 `green` 之间的距离为一。然而，使用更复杂的属性表示可能是可取的。例如，对于更多颜色，可以使用颜色空间中的色调数值度量，使 `yellow` 比与 `green` 更接近 `orange`，而 `ocher` 更接近。
