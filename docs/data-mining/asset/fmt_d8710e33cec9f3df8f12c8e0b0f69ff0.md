
The original `GPT` model was fine-tuned for each individual supervised `NLP` task separately. The larger `GPT-2` model, trained on a broader corpus, was able to solve several `NLP` tasks in a `zero-shot learning` environment, without fine-tuning for each task, by providing a natural language prompt asking the system to solve the task at hand. This was further improved in the subsequent scaled-up and more powerful `GPT-3` model, which had a context size large enough to include several examples of the target task in the prompt, frequently achieving state-of-the-art `NLP` performance for many tasks with just those few examples (“`few-shot learning`.”) One of the models from the `GPT-4` suite includes image data and provides an `API` to answer questions about user-provided images. The ability of `GPT-4` to solve a variety of `AI` tasks spanning mathematics, coding, medicine, law, and beyond has led some researchers to declare that it is beginning to reach the early stages of an artificial general intelligence (`AGI`) system. However, at the time of writing, despite its impressive performance `GPT` is still vulnerable to producing `hallucinations`, in which it confidently produces incorrect information. See [Chapter 15](#Ch016_571-615_B9780443158889000169.xhtml#Ch016_571-615_B9780443158889000169), “Moving on: applications and their consequences,” for a discussion on concerns and issues regarding `GPT` and other similar `LLMs`.

### Bidirectional Encoder Representations From Transformers
As we have discussed, `GPT` processes the text data from left-to right, which makes it very good at generating new text. `GPT` was also motivated by using a single language model to solve many `NLP` tasks. However, the left-to-right processing is not optimal for this. `BERT` is an `LLM` proposed by researchers from Google that uses a “bi-directional” transformer architecture (i.e., it no longer uses left-to-right processing and it can also examine subsequent tokens). `BERT` models are state of the art at solving downstream `NLP` tasks via fine-tuning or extracting embeddings to use as features. Transformer-based methods, largely based on `BERT`, are currently state of the art across much of the spectrum of `NLP` tasks, which has rapidly revolutionized the field.

The `BERT` model uses a version of the transformer architecture in which a stack of transformer blocks is used to produce an embedding of the text that can subsequently be used to perform downstream `NLP` tasks. Since it produces embeddings and not text sequences, we can think of it as an `encoder-only` architecture. `BERT` is intended to be used by pretraining the model on a large unlabeled text corpus and then fine-tuning it to solve a particular `NLP` task. During pretraining, instead of being trained to predict the next token in a sequence, `BERT` uses a `masked language model` (`MLM`) approach. In `MLM`, to pretrain the model, we simply hide, or “mask,” a random percentage of tokens from the model and ask it to predict them. `BERT` also uses a second pretraining task, called `next-sentence prediction` (`NSP`). In this task we concatenate two sentences with a separator token between them. In some cases the second sentence is one that appears immediately after the first, and sometimes it is another randomly selected sentence. Then we train the model to predict whether the second sentence is the “next sentence.” Both `MLM` and `NSP` are self-supervised learning techniques, in which supervised labels are extracted directly from the text itself, as convenient proxy tasks to train a language model. This approach is thus reminiscent of the `skip-gram`, in which the prediction of context words was similarly chosen as a convenient and effective self-supervision training objective.

`BERT` processes a pair of sentences at a time so that it can perform `NSP`. It appends a special “classification token,” called `CLS`, before the first sentence, and a “separator” token (`SEP`) in between the sentences. It also adds “segment embeddings” to each token’s input and positional embeddings to indicate whether the token is in sentence one or sentence two. The embedding for the `CLS` token is often used as an embedding representation of the sentence to use for downstream tasks. The two-sentence format is also convenient for fine-tuning to solve downstream tasks by using question-answer pairs as sentence one and sentence two in the task-specific fine-tuning dataset. Thus the architecture applies generally to many `NLP` tasks, with little modification to adapt it to new tasks. ### Transformer-Based Neural Machine Translation
The original paper by Google researchers that proposed the transformer architecture, called “`Attention Is All You Need`,” used it for `NMT`. Their approach uses an encoder-decoder architecture reminiscent of the `Seq2Seq` and `RNNSearch` models that we discussed earlier, yet it uses transformers. Both the encoder and decoder are stacks of transformer blocks (six blocks each in the original paper). The encoder processes the input text in the original language via its multihead attention mechanisms, identifying and processing the relevant portions of the text. The decoder is used to generate the translation, predicting the next token in the translated sequence based on the input text and the translate sequence so far. The decoder uses masked multihead attention to prevent it from attending to tokens that occur after the current token, ensuring that the predictions are made in a strict left-to-right fashion. The encoder does not need to use masking because we do not need to predict the input sentence, only its translation. The translated tokens are predicted via a final softmax layer like for `GPT`.
