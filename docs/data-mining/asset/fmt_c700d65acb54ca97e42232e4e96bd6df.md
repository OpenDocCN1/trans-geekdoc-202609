
We will process multiple queries simultaneously. Let `Q` be a matrix containing `n_q` queries, with each row corresponding to a query’s `d_k`-dimensional *query embedding*, let `K` be a matrix containing `n_i` keys with each row corresponding to an item’s `d_k`-dimensional *key embedding*, and let `V` be a matrix containing `n_i` values with each row corresponding to an item’s `d_v`-dimensional *value embedding*. The embeddings in `Q`, `K`, and `V` are all model parameters that can be learned from data or in some cases provided in advance as pretrained embeddings. Scaled dot-product attention is calculated as ([Fig. 11.8](#Ch012_433-471_B9780443158889000121.xhtml#f0045)):

```
Attention(Q, K, V) = softmax(Q K^T / sqrt(d_k)) V
```

Then the value embeddings are averaged, weighted by their attention weights. Credit: James Foulds](images/F000121f11-08-9780443158889.jpg)

Here, for each query in `Q`, the `softmax` produces attention weights over the items. The `softmax` takes as input the dot products between queries and keys, scaled by a factor `1/sqrt(d_k)` that aims to prevent the dimensionality of the vectors from having an impact on the scale of the outputs. Applied to all of the queries at once, the `softmax` produces queries by items matrix `A` of *attention weights*, whose rows sum to one. After multiplying this matrix `A` by `V`, the final output of scaled dot-product attention is an `n_q` × `d_v` matrix, where each row contains the output for a query, consisting of an average of the items’ value embeddings weighted by their attention weights.

In some cases, we want to exclude some of the items from obtaining any attention. In transformer-based language models, for example, we sometimes want to prevent the model from looking at words that are later in the document so that we are predicting the “future” based only on the “past.” A variant of the method, called *masked scaled dot-product attention*, replaces the input to the `softmax` with −∞ for any item that should be excluded for a particular query, effectively forcing its attention weight to be zero.

## Multihead Attention

As we mentioned before, the goal in transformer-based language models is to replace RNN and CNN architectures with something that addresses their limitations. This means that we need to design the architecture so that it has at least as much representational power as those modules do. Specifically, CNNs use multiple filters to create the representations at each layer, where each filter captures one type of pattern or feature. With multiple filters together in a single CNN layer, each capturing a different pattern, the layer outputs a multidimensional vector representation where each dimension captures different and complementary properties of the data to pass enough relevant information to the subsequent layers. Similarly, RNNs used multiple RNN units per layer to capture multiple patterns, producing a multidimensional representation at each RNN layer of the network.

In transformers we need an analogous approach if we are to replace RNN and CNN layers using only attention. The corresponding concept is called *multihead attention*. The idea is to perform scaled dot-product attention multiple times, each with its own learned `Q`, `K`, and `V` parameter matrices. Finally, the representation learned from a multihead attention module is the concatenation of the outputs of each of these attention functions.
