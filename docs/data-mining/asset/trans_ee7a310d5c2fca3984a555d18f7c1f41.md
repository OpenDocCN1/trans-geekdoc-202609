理论上可以证明，最小化信息值的切分点永远不会出现在同一类别的两个实例之间。这导致了一个有用的优化——只需考虑将不同类别的实例分开的潜在划分。请注意，如果基于区间中的多数类为区间分配类别标签，就无法保证相邻区间会获得不同的标签。你可能会想合并具有相同多数类的区间（例如 [图 6.3](#Ch006_209-259_B9780443158889000078.xhtml#f0020) 的前两个区间），但正如我们稍后会看到的，一般情况下这样做并不是好主意。

唯一剩下需要考虑的问题是停止准则。在温度示例中，所识别的大多数区间都是“纯”的，即其所有实例都属于同一类别，显然没有必要尝试划分这样的区间。（例外是最终区间，我们默示决定不对其进行划分，以及 70.5 到 73.5 的区间。）然而，一般情况下情况并非如此简单。

停止基于熵的划分离散化程序的一个好方法被证明是我们在 [第 5 章](#Ch005_165-207_B9780443158889000066.xhtml#Ch005_165-207_B9780443158889000066) 中遇到的 MDL 原则，“可信度：评估所学内容”。根据该原则，我们希望最小化“理论”的大小加上指定该理论下所有数据的所需信息的大小。在这种情况下，如果我们进行划分，“理论”就是分割点，我们将比较划分与不划分的情况。在这两种情况下，我们都假设实例是已知的，但其类别标签未知。如果不进行划分，类别可以通过编码每个实例的标签来传输。如果进行划分，我们首先编码分割点（以 `log[2][N – 1]` bits，其中 `N` 为实例数），然后是该点下方实例的类别，然后是上方实例的类别。你可以想象，如果划分是好的——例如，下方所有类别都是 `yes`，上方所有类别都是 `no`——那么进行划分可以获得很大收益。

如果 `yes` 和 `no` 实例数量相等，未划分时每个实例花费 1 bit，而划分后几乎花费不到 0 bit——并非完全为 0，因为与划分本身相关的类别值必须被编码，但这种惩罚在所有实例中被摊销。在这种情况下，如果示例很多，编码分割点的惩罚将被划分所节省的信息远远超过。
