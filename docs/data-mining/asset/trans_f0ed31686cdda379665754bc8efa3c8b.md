构造一棵显式枚举全部 27 个计数的树是微不足道的。然而，这与普通表格相比毫无优势，而且显然不是 [图 13.4B](#Ch014_485-514_B9780443158889000145.xhtml#f0025) 所做的树，因为它只包含八个计数。没有分支测试 `humidity` = `high`。这棵树是如何构造的，又如何从中获得所有计数？

假设数据中的每个属性都被分配了一个索引。在天气数据的简化版本中，我们给 `humidity` 索引 1，`windy` 索引 2，`play` 索引 3。AD 树是通过用具有索引 `j` > `i` 的所有属性的值扩展对应于属性 `i` 的每个节点生成的，带有两个重要限制——每个属性的最庞大扩展被省略（任意打破平局）作为计数为零的扩展也被省略。根节点被赋予索引 0，因此对其所有属性都被扩展，受相同限制。

例如，[图 13.4B](#Ch014_485-514_B9780443158889000145.xhtml#f0025) 从根节点没有 `windy` = `false` 的扩展，因为它有八个实例是最庞大的扩展；值 `false` 在数据中出现的频率比值 `true` 更高。类似地，从标记为 `humidity` = `normal` 的节点没有 `windy` = `false` 的扩展，因为在所有 `humidity` = `normal` 的实例中，`false` 是 `windy` 的最常见值。事实上，在我们的示例中，第二个限制——即省略计数为零的扩展——从未生效，因为第一个限制排除了以测试 `humidity` = `normal` 和 `windy` = `false` 开始的任何路径，而这是到达 [图 13.4A](#Ch014_485-514_B9780443158889000145.xhtml#f0025) 中唯一零值的唯一方式。

树的每个节点代表特定属性值组合的发生。检索树中出现的组合的计数是很直接的。然而，树并未显式表示许多非零计数，因为每个属性的最庞大扩展被省略了。例如，组合 `humidity` = `high` 和 `play` = `yes` 在数据中出现三次，但在树中没有节点。尽管如此，事实证明任何计数都可以从树显式存储的计数中计算出来。

这里有一个简单的例子。[图 13.4B](#Ch014_485-514_B9780443158889000145.xhtml#f0025) 没有 `humidity = normal, windy = true` 且 `play = yes` 的节点。然而，它显示有三个实例具有 `humidity = normal` 和 `windy = true`，其中一个的 `play` 值与 `yes` 不同。由此可知，必须有两个实例的 `play = yes`。现在来看一个更棘手的情况：`humidity = high, windy = true` 且 `play = no` 出现了多少次？乍一看似乎无法判断，因为没有 `humidity = high` 的分支。然而，我们可以通过计算 `windy = true` 且 `play = no` 的计数（3）并减去 `humidity = normal, windy = true` 且 `play = no` 的计数（1）来推断该数值。这得到 2，是正确的值。

AD 树只有在数据包含数千个实例时才有回报。很明显它们对天气数据没有帮助。它们在小数据集上没有收益这一事实意味着，实际上，将树一直扩展到叶节点是没有意义的。通常会采用截止参数 `k`，覆盖少于 `k` 个实例的节点保存指向这些实例的指针列表，而不是指向其他节点的指针列表。这使得树更小且使用更高效。

## 13.3 聚类和概率密度估计

增量式启发式聚类方法在 [第 4.8 节](#Ch004_91-164_B9780443158889000054_a.xhtml#s0140) 中进行了描述。虽然在某些实际情况下效果相当不错，但它存在缺点——类别效用公式中为防止过拟合而必须的任意除以 `k`、需要为聚类标准差提供人工最小值，以及防止每个实例都成为其自身聚类的临时截止值。除此之外还有增量算法固有的不确定性。结果在多大程度上取决于示例的顺序？合并和分裂的局部重构操作真的足以逆转因不幸的顺序导致的不良初始决策的影响吗？最终结果是否甚至代表类别效用的 *局部* 最大值？再加上最终配置与 *全局* 最大值相差多远的问题，当然，重复聚类过程几次并选择最好的方法会破坏算法的增量性质。最后，层级结果的性质难道不是真的引出了哪些是 *最佳* 聚类的问题吗？[图 4.21](#Ch004_91-164_B9780443158889000054_a.xhtml#f0110) 中有如此多的聚类，以至于很难区分精华和糟粕。

一种更原则性的统计聚类方法可以克服其中一些缺点。从概率角度来看，聚类的目标是找到在给定数据（以及不可避免的先验期望）的情况下最可能的聚类集合。因为有限量的证据不足以对该问题做出完全确定的决定，实例——即使是训练实例——也不应被范畴化地放在一个聚类中或另一个聚类中。相反，它们属于每个聚类的概率是确定的。这有助于消除与做出硬性判断的方案通常相关的脆性。
