
浏览器可以向 Web 服务器传输数据。有时这仅仅是表单的内容，通常作为使用用户名和密码向 Web 服务器进行身份验证的方式。但浏览器还允许用户在银行账户之间转账、购买产品或从图书馆借阅电子书。相同的机制允许用户向网站发布内容，然后该网站上的其他人也能看到这些内容。例如，用户可以上传视频、状态更新、博客文章，并分享他们的活动，例如他们购买了什么。

除了浏览器与 Web 服务器之间的显式通信外，还存在大量旨在跟踪用户行为的隐式通信（例如，使用 `cookies`）。由于许多用户同时与多个网站交互（可能使用单独的标签页），因此一个网站的交互有机会泄露关于与另一个网站交互的信息。

一种旨在处理简单请求（上行）和静态数据（下行）的机制，已成为大量不同种类数据以及可执行代码进行高容量双向传输的通道。

网页包含超文本标记语言（HTML），它描述网页各部分是什么，而不是其确切的格式。例如，HTML 标签标记段落、标题、列表等。浏览器可以利用关于每部分是什么类型的 HTML 信息来决定如何显示它，同时了解将显示它的设备的屏幕尺寸和分辨率。

Web 流量的主要漏洞之所以成为可能，是因为网页中作为代码或用户生成内容的部分也用标签标记。因此，这些部分内部的文本在到达浏览器或 Web 服务器时就变成了可执行代码。检查这种可执行代码是否合理且安全是困难的，而且往往甚至不曾尝试。

三种主要攻击利用了数据变为可执行代码的这种能力。第一种称为 `cross-site request forgery`（跨站请求伪造）。攻击者利用自己的网站，通过不知情用户的浏览器向另一台 Web 服务器发起恶意请求。例如，假设用户已登录银行网站的银行账户，同时在另一个标签页打开了攻击者的网站。攻击者可以导致用户的 Web 浏览器下载一个恶意请求（例如转账），然后将其传递给银行网站。银行知道用户已通过身份验证，却没有意识到该请求并非来自用户的操作，而是间接来自另一个网站。用户甚至可能没有意识到发生了任何事情。

第二种称为 `cross-site scripting`（跨站脚本）攻击，其工作方式相反。攻击者在允许用户上传内容的网站上插入 HTML 格式的内容——例如，社交媒体网站可能允许用户描述他们的兴趣。在这个上传的内容中，有一个包含可执行代码的 HTML 部分。每当用户下载该内容时，这段代码就会在他们的计算机上执行，并能执行浏览器中允许执行代码做的任何事情。下载的恶意代码可能直接做一些坏事，但也可能导致下载其他恶意代码。

这两种攻击看似应该很容易预防，但它们与 HTML 和浏览器的核心机制相互作用：可执行代码如何处理、身份验证和 cookies 如何工作，以及同时与多个网站交互的能力。已经有过几次防止这些攻击的尝试，这是一个不断发展的领域，但解决方案需要所有浏览器和所有网站就确切需要做什么达成一致。实际上，浏览器尝试了不同的方法来试图解决根本问题，而不需要更改网站（因为这在全世界范围内永远不会发生）。

第三种攻击称为 `SQL injection`（SQL 注入），也许是最流行的单一网络攻击机制。网站在收到请求时通常即时创建页面。例如，如果你访问你的银行，你必须首先填写一个提供你的账户标识和密码的表单；但随后银行会显示一个包含你的余额和其他个人详细信息的页面。当然，这个页面对每个人都是不同的。

填充此页面的数据来自一个数据库，该数据库拥有每个客户的记录。数据库是专门的数据存储，响应以查询形式表示的请求提供信息：“显示具有此账户号码的个人的余额”、“显示该分行所有人的账户号码”，等等。这些查询使用查询语言以结构化方式表示，其中 `SQL`、`Structured Query Language` (SQL) 是最流行的一种。

当你在 Web 浏览器的表单中输入信息（“账户 xxxx 的余额是多少”）时，它会变成一个 SQL 查询，被传递给 Web 服务器，Web 服务器再将其传递给数据库。当数据库响应 Web 服务器时，服务器将响应转换为 HTML 并发送给浏览器以供显示。

问题在于 Web 浏览器和/或 Web 服务器不（在某些情况下，不能）验证输入表单的文本是否为安全的 SQL 查询。因此，知识渊博的用户可以在表单中输入执行数据库中恶意操作的信息，甚至包括删除全部内容。

已知有几种针对 SQL 注入攻击的对策，大多基于在输入到达数据库之前更努力地验证输入。然而，这些依赖于正确配置 Web 服务器和数据库。许多 Web 服务器（和数据库）是为中小型企业构建的，它们可能不了解这些问题，因此允许这些攻击的错误配置仍然很常见。

这些攻击可以协同作用。跨站请求攻击允许恶意网站向另一个网站创建请求。该请求可以是针对位于该其他网站后面的数据库的 SQL 注入攻击。

用于运行 Web 服务器的代码也可能存在潜在攻击者已知的漏洞。即使是存在已久的知名 Web 服务器也包含错误。例如，`Apache` Web 服务器每年大约发布 10 个安全修复。复杂的攻击者可能能够直接攻击此类网站，即不依赖浏览器作为中介。

许多允许恶意行为者进入个人社交媒体账户或银行账户的攻击，使用钓鱼或定向钓鱼将恶意软件植入个人的计算机或手机。此类恶意软件可以监视个人何时登录其账户，捕获其密码，然后在后台悄悄登录；随后发布内容到社交媒体、发送垃圾邮件，或从其银行账户转移资金。用户可以通过使用防病毒和反恶意软件来防范这些攻击，这些软件可在恶意软件进入设备前或后检测到它们。

利用 Web 服务器机制的攻击更难检测，因为它们大多是瞬态的——攻击发生在一瞬间，当时没有产生任何迹象表明正在发生什么，并且留下的痕迹很少。

# 7.3 区块链

`Blockchains`（区块链）是一种应用层系统，依赖于我们在[第 3 章](#03chap_03.xhtml)讨论的许多加密思想。尽管区块链的长期用处仍是一个开放性问题，但它们创造了一个值得探索的复杂安全环境。
