
# 网络安全威胁与对策

## 窃听
数据包和段的全部内容均可读，除非载荷部分在到达 TCP 协议前已被加密。即使载荷已加密，数据流向的所有细节及流量大小在网络中仍完全可见。

这需要访问流动中的网络流量。可通过物理窃听流量（点对点管道）、监听无线网络，或诱导网络接口硬件将其本地区域内所有流量复制到节点（该功能原用于故障检测，但仍普遍存在）。

网络空间中大量流量未加密，易被捕获读取。加密流量的协议头仍可见，因节点需知晓各段/包的发送去向。流量分析可揭示端点对间的流量大小及时间；TCP/UDP 端口号常关联特定应用，从而推断通信应用；即便单一流涉及多应用，包大小分布也可能泄露所用应用，进而推断计算机功能（如 Web 服务器、打印服务器具有特征流量模式）。

## 地址欺骗
因数据包和段头部的 IP（及端口号）字段无保护，伪造流量可随意发送，合法流量可被重定向。修改目的地址可将流量发送至错误位置（如冒充真实计算机的主机）；修改源地址可生成恶意流量并伪装来源（这也是网络攻击溯源困难的原因之一，因隐藏流量来源极其容易）。

## 篡改内容
若载荷未加密，可在不留痕迹的情况下篡改或替换内容。若操作得当，部分流量内容可被不可检测地替换。

段头部部分字段含校验和，源自内容的简单函数。这些远非数字哈希；设计初衷是捕获传输错误，而非刻意篡改。若内容被篡改，对应校验和只需重新计算修改即可匹配，过程简单。

此三协议通用缺陷，或许是全流量加密普及的主因。

## IP 分片攻击
IP 可将大包分片为小片段，以便穿越无法承载典型包的细链路。每片段含字段描述其距初始大载荷起始处的偏移。全部分片到达目的地（可能不到达）时，IP 利用这些字段作为偏移量重组。然而，这些偏移量未经过合理性检查。攻击者若在途篡改偏移量，重组过程可能导致载荷部分被其他部分覆盖，最终包载荷与原始形态毫无相似。

此攻击非直接损坏包（可直接实施），而是使携带分片的包在防火墙等设备前显得无害，重组后却成防火墙本会拦截的包。

## 拒绝服务
TCP（及 UDP 程度较轻）的端点交互含状态，存在利用此状态的攻击。最简单是 SYN 洪水攻击。因 TCP 会话建立需三步交互，攻击者可执行第一步——请求会话——并忽略目标响应。目标须跟踪所有建立中会话。分配空间满时，无法接受新连接请求（含合法请求），且攻击填满的进行中连接表槽位永不解决。这类似反复致电餐厅用不同名字预订同一时段却从不赴约。

其他拒绝服务攻击令目标过忙而无法做有用工作。单一攻击者系统难产生足够流量，但攻击者可向大量其他系统发送伪装成来自目标系统的流量，这些系统随即同时响应目标。

接收 UDP 包导致接收方检查对应端口是否有应用等待流量；若无，发回“地址无此用户”响应。拒绝服务攻击可向大量系统发送目标为罕见端口地址的段，伪造发送者地址为待攻击目标系统。响应随即涌向目标并将其淹没。

## 序列号预测与插入
攻击者可篡改 TCP 段内容，即“中间人”攻击。但插入额外流量较难，因会话各方向连续段具有递增序列号。序列号使目的地跟踪已收段并正确确认，亦使其按正确顺序重组。这增加了插入额外段（从而有限接管流量）的难度。若攻击者能猜测序列号（并可能通过如拒绝服务攻击阻止真实源系统发送），可伪装成源。早期 TCP 生成初始序列号方案极简，现代实现则致力于使其随机。攻击仍可能但需更多工作。

## 协议栈指纹识别
协议官方协议规范不足，致使各实现可在最高效（或最简）处自由发挥。不同厂商（或 Windows、Linux、Mac 等操作系统家族）实现略有差异。虽在关键处必须一致，但段头部仍留有痕迹泄露生成该协议的特定实现。这类似人类言语口音——虽能听懂不同口音（大多），但口音透露与所言无关的信息。

攻击者可观察流量，通过不同实现选择的痕迹或后果，推断特定节点运行何种软件。这可能因暴露已知弱点而使攻击规划更易，揭示哪些节点为良好目标。

# 5.5 对策

因数据移动机制被视为“幕后”且高技术活动，效率成关键设计标准，安全鲜被考量。故针对这些攻击的对策寥寥。

核心问题在于管道须“说同一语言”以连接异构节点并承载混合流量。协议变更须向后兼容，致使安全弱点即使在坚定改进努力下仍存续多年。
