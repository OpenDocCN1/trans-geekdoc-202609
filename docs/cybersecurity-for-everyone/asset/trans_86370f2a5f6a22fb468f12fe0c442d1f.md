
# 6.2 域名服务

另一个在网络空间幕后运行的系统是 **域名服务**，它负责处理人类可读的计算机名称与 IP 地址之间的映射。它是一组分布式的数据表，记录着当前的映射关系。

DNS 服务器的进出流量使用 UDP，但这种流量对用户不可见——它嵌入在 Web 浏览器、邮件客户端以及其他需要将名称解析为 IP 地址的应用程序中。

**域** 是名称空间的一部分，之所以存在是因为计算机名称具有层级结构。例如，`.uk` 是英国所有计算机的域，`gov.uk` 是英国所有政府计算机的集合，而 `data.gov.uk` 是存放英国政府开源数据的系统的域。

在互联网的每个子区域中，至少有一台计算机，即 **本地 DNS 服务器**，将保存名称到 IP 地址的映射，通常是与本地计算机正在执行的任务相关的映射。例如，这些本地服务器可能保存属于同一企业或机构的所有计算机（无论本地还是远程）的映射，因为本地计算机很可能与它们通信；也可能保存用户通常使用的热门新闻或社交媒体网站的映射。

如果设备请求的映射不在其本地 DNS 服务器中，该服务器会将请求发送到更高级别的 DNS 服务器。如果该服务器知道答案，它将返回映射，该映射会被发送回原始请求计算机，并**同时存储在本地 DNS 服务器中**。之所以这样做，是因为一旦一台本地计算机请求某个映射，它或其他本地计算机在不久的将来也很可能想要知道该映射。如果 DNS 服务器映射存储空间耗尽，它将删除近期最少使用的映射。

如果更高级别的服务器也不知道该映射，它会将请求发送给下一级更高的服务器，或者可能跳过某些级别直接发送给 **顶级 DNS 服务器**。顶级 DNS 服务器知道如何找到 `.com`、`.uk` 以及所有最高级域的 DNS 服务器。

层级结构中的某些 DNS 服务器是特定域的 **权威 DNS 服务器**，它们永远不会删除该域的映射。因此，`.uk` 有其权威 DNS 服务器，其他 DNS 服务器总能通过询问每个子域的权威服务器来找到 `.uk` 内的子域。换句话说，权威 DNS 服务器持有域名与 IP 地址之间的**权威映射**，而较低级别的 DNS 服务器持有此类映射的**副本**。

DNS 系统因 **区域** 的定义而变得复杂，区域横跨域和子域的层级结构。例如，一家企业可能在不同国家拥有域名，如 `fredmart.com`、`fredmart.co.uk` 和 `fredmart.com.au`，并希望将访问其任何网站的访问者重定向到适合其国家的版本。它们可以为所有 `fredmart.*` 域名设置一个权威 DNS 区域服务器来实现这一点。

名称与 IP 地址之间不必是一对一的映射。将一个名称映射到多个 IP 地址是常见做法，用于负载均衡，使流量分散到不同的物理系统。这种能力也提供了一种应对拒绝服务攻击的方法，通过无缝分发大量入站流量，甚至可能将参与攻击的位置的流量分流，使攻击流量仅干扰其他攻击流量。热门网站也可以在繁忙时段透明地添加额外服务器。

虽然 DNS 是一个低级系统，但它也通过 `whois` 命令提供应用层接口。该命令将提供域名与 IP 地址之间的当前映射，以及关于地址所有者及其权威名称服务器的信息。

DNS 系统存在重大漏洞。如果攻击者能导致 DNS 服务器将请求转发给更高级别的服务器，然后模拟来自该服务器的虚假响应，就能导致虚假条目被包含在该 DNS 服务器的映射表中。普通应用程序随后对映射的请求将被不可见地重定向到错误位置。

DNS 服务器也容易受到拒绝服务攻击。攻击者可以生成大量针对不存在域名的映射请求。这些域名的映射当然是未知的，因此会触发级联请求到更高级别的服务器，而没有任何一台服务器知道该映射，以此类推。

DNS 的弱点已通过允许请求和响应加密部分得到解决。这使得攻击者更难插入虚假内容，因为虚假内容无法被正确加密。然而，旧系统仍需支持，因此在域名请求和响应的加密成为强制要求之前，这帮助不大。

# 6.3 交换机漏洞

交换机只是配置为能够处理大量数据传输的计算机系统，因此它们可以在无需人工直接干预的情况下运行。它们拥有自己的 IP 地址，并运行标准系统软件。交换机是特殊的脆弱点，因为它们参与了数据移动的各个方面。操纵交换机的能力创造了前所未有的攻击和破坏力量。
