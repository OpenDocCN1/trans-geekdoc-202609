# 4.7.2 Computational Time and Resources

The runtime for the algorithms detailed in this chapter vary greatly. On the quick end, the application of regularized regression with the glmnet package takes only a matter of seconds, even when testing the default of 10 penalties. This amount of time can increase as the number of predictors increases, but it rarely longer than a few minutes. On the slow end is the hierarchical lasso, with models often taking on the order of hours to fit a small number of penalties (i.e., 10). The authors have tested this method (as implemented in multiple packages) across a variety of empirical problems, and on more than one occasion been unable to get models to finish, as the runtimes were on the order of days. In between regularized regression and the hierarchical lasso lie stability selection and the forms of the group lasso, with both methods being closer to regularized regression in run times. Bayesian estimation almost takes longer, but there are a number of front-end packages that have been developed that require less programming and model specification, have built-in functions to implement shrinkage priors, and drastically cut the runtimes. Both the brms (Bürkner, 2017) and stanarm (Goodrich, Gabry, Ali, & Brilleman, 2022) packages for implementing Bayesian regression. Both packages recommend the use of the horseshoe prior for regularization.
