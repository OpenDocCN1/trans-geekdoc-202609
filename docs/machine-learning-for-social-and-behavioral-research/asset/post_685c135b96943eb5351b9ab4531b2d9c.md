For random forests, there are two tuning parameters, the number of trees $B$ (in bagging) and $m$ the variable subset size when making a partition of the data. Typically $B$ is fairly large (i.e., 500 to 2,000) and larger than the number of trees needed when bagging because the prediction from each decision tree is somewhat poor with random forests. Oftimes, the variable subset size $m$, often referred to as $mtry$, is a fairly small number (e.g., $\sqrt{p}$, where $p$ is the number of predictor variable). Predictor variables are highly correlated, a smaller value of $m$ typically leads to superior performance.

The optimal value of $m$ can be determined using a grid search, whereas the optimal value of $B$ is first examined using the out-of-bag (OOB) prediction error. Whereas observations that are left out of the bootstrap sample—recall that bootstrapping is resampling with replacement. Thus, a single observation can appear multiple times in a bootstrap sample, whereas another observation can be left out of a bootstrap sample entirely. These left-out observations are the OOB observations and the prediction error on these OOB observations are a decent approximation of the out-of-sample prediction error (Breiman, 1996). Although the number of trees and variable subset size are treated as tuning parameters, the size of each decision tree is typically controlled or varied.

In comparison to bagging, random forests are able to model more nuanced relationships in the data, resulting in improved fit. This increased degree of flexibility can lead to overfit the training dataset, resulting in less dramatic improvements in the test set. Random forests were also applied to the ECLS-K data as demonstrated in section 6.2, with a sequence of trees and their corresponding training and test datasets displayed in 6.3. Relative to both decision trees and bagging, random forests demonstrated striking improvements in the training dataset, while only incremental improvements are seen in the test dataset. Additionally, we can see that random forests required a larger number of trees to achieve minimum misfit, which can be attributed to the random selection of predictors.

## 6.4 Gradient Boosting

Similar to random forests, gradient boosting (also known as gradient machines or gradient boosting trees) is a method that combines the use of hundreds or thousands of individual trees in an attempt to overcome the problems with a decision tree. However, in contrast to bagging and random forests, where each tree is created independently on a bootstrapped sample, boosting creates a sequence of trees based on weighted forms of the data. Developed originally for classification in the form of the AdaBoost algorithm (Freund & Shapire, 1995; 1997); the idea behind the boosting algorithm has also been extended to many other statistical problems (see Buhmann & Hothorn, 2007 for more details). Most notably, Friedman, Hastie, and Tibshirani (2000), as well as Friedman (2001), developed highly adaptable algorithms that can be applied to list of different loss functions. This algorithm has also been extended to multivariate outcomes (Miller, Lubke, McArtour, & Bergheman, 2016). The basic idea of this algorithmic framework, originally termed gradient boosting machines by Friedman (2001), now more frequently referred as simply boosting, is to fit an additive combination of weak learner (weak in the sense that its predictive performance is usually substandard), most often a decision tree with few (potentially one) partitions of the data, to the gradient (residuals) of the prior combination of weak learners.

### Algorithm 2 Boosting Algorithm Overview

1. Set tree depth, $D$ for each decision tree
2. Set learning rate or shrinkage parameter $\Lambda$
3. Set the number of trees $B$
4. Initialize the residuals $r_b$ with initial predictions $p_0$ of 0 for each $y$
5. For $b=1, 2, ..., B$, repeat:
   (a) Fit a tree $t_b$ of depth $D$ to the current residuals of the response, $r_b$
   (b) Create new predictions $p_b$ for each case using $t_b$
   (c) Update the residuals using a shrunken version of the prediction, $r_b = r_b - \Lambda p_b$
