## 3.5.4 Recommendations

The first thing to note is that there are a number of variants of both CV and the bootstrap that we do not cover. While methods such as leave-one-out have performed well in small sample sizes, other methods have demonstrated poor performance. Further, a number of resampling methods were developed prior to the development of many machine learning algorithms, and haven't been tested in conjunction with flexible algorithms with a high propensity to overfit.

# The Practices of Machine Learning

This was seen recently in a paper by Jacobucci, Littlefield, Kleiman, & Steinley (2021), where extreme amounts of bias were found when the random forests algorithm was paired with the optimistic corrected bootstrap.

There have been a number of studies that have compared the bias and variance (detailed) of CV and bootstrapping, but it has generally been difficult to evaluate the results the differences in which algorithms were used, types of data (simulation or benchmark datasets), and which methods of resampling were tested. Across studies, a general recommendation has been to use repeated k-fold CV when the sample size is not small (a few hundred), and the bootstrap when the sample size is small. Just as in the no-free theorem, no method has performed universally across various conditions of study, as seen in a recent study by Xu and Goodcaire (2018). Further, this study concluded that when using the bootstrap, the number of repeats should be large (> 100).

While the use of repeated k-fold CV or bootstrap sampling is recommended for model assessment, nested CV should be used when conducting model selection and assessment. In nested CV, it does not seem to matter whether k-fold CV or bootstrap sampling is used for the outer and inner loops. The main drawback to this approach is a lack of easy implementation in R. As of this writing, users need to program their own CV script.

Regardless of the resampling method used, it is extremely important to use the same resampling method when comparing results across models or algorithms. Depending on dataset characteristics, each resampling method is likely to be at least biased. Thus, when performing selection it is important to use the same resampling method so that the bias is consistent across models or algorithms.

## 3.6 Classification

In modeling binary outcomes (classification), the methods and recommendations detailed above apply equally well as they do to continuous outcomes. The one caveat is in the presence of imbalanced (skewed) binary outcomes. We cover this further in the Imbalanced Outcomes section. In this section, our focus is on detailing the many prediction performance metrics that are different with binary outcomes.

# Machine Learning for Social and Behavioral Research

To demonstrate predicting a binary^1 outcome as opposed to one that is continuous, we use a simple example that is predicting whether a case is labeled as having depression or not (using a cut score on the Beck Depression Inventory) by Big Five personality scales (agreeableness, conscientiousness, extraversion, neuroticism, and openness; taken from the epi.bfi dataset in psych package). With this data, we ran logistic regression, first making sure the outcome classes are labeled with 1 = “dep”, and 0 = “no”. Designing the class of interest as “1” makes inference into the various metrics down the line. To assess model performance, the most straightforward metric is accuracy, and the percentage of correct predictions:

```
$Accuracy = \frac{1}{n} \sum_{i=1}^{n} l(y_i, \hat{y}_i); \quad (3.8)$
```

$\hat{y}_i$ is the predicted response for observation $i$, and $I$ is an indicator of 1 if there is agreement in class label and 0 if the labels do not agree. The most important thing to note here is that calculating accuracy creating a predicted class for each observation. Most machine learning algorithms (including logistic regression) create predicted class probabilities, then require the user to use either the default probability of 0.5 (those with predicted probabilities > 0.5 are assigned to class one) or a different cutoff that reflects the cost for misclassifying these cases.

Before examining the accuracy from our logistic model, we examine the predicted probabilities from the model. In Figure 3.11 we display a histogram and a density plot for each class of the predicted probabilities. The first thing to note is the large degree of skew in the histogram. Note that this is not what we hope to see. In a well-calibrated model we would hope to see somewhat of a symmetric, bimodal distribution, as we are generating both classes about equally well. However, in modeling predicting outcomes, such as admitting suicide or how diagnosis of psychopathology, this is rarely what we see. In general, it is easier to model the negative cases (generally without a diagnosis or disease), while we are rarely able to generate confident predictions with positive values of the outcome. This can further be seen in the two-class density plot, with little separation between the predicted probabilities for each class, and a small number of predicted probabilities > 0.75.
