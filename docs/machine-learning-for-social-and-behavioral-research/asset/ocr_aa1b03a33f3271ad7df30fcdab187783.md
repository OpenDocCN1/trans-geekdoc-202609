# 10.3.2 Algorithm Details

The SEM trees algorithm is implemented in the semree package (Brandmaier et al., 2022) in R. Prior to running SEM trees, researchers need to first fit the outcome model, which can take just any form of SEM. The SEM can be tested and paired with semree using either the lavaan (Rossel, 2012) or (Boker et al., 2011) packages. We note, however, that semree was originally designed for pairing with OpenMx and in practice better than with OpenMx compared to lavaan.

A number of tuning parameters are available for the SEM trees algorithm. Although we term these options parameters, we do not mean that researchers should test multiple values of each. Instead, the tests should be based on best practices and theoretical considerations given the nature of identifying heterogeneity. One of the options is the splitting criterion (method = in semree.control()). The default, naive, compares all possible split values across the predictor,, the cutoff that maximizes the likelihood ratio. Cross-validation (method = "cross-validation") defaults to 5-fold CV splits the data into partitions, testing the improvement in fit due to cutoff on a holdout set of observations. In practice, this procedure can be extremely intensive from a computational standpoint. The procedure that we recommend in most scenarios is the fair criterion. This method proceeds in two steps: The first step is to split the sample into two, using the first half of the sample to estimate the improvement in fit associated with each cutoff, associating a single best cutoff for predictor. In the second step, the second half of the sample is used to test the best cutoff for each predictor. This procedure for selecting cutoffs overcomes some of the bias of decision decision for selecting cutoffs from predictors with more response options (possible cutoffs). Given this, we recommend using the fair criterion.

The second tuning parameter to consider setting is the minimum sample size. It is important to note that an SEM is estimated in each node, and depending on the complexity of the specified SEM, this could lead to testing complex SEMs with inadequate sample sizes. Therefore, we recommend setting a minimum sample size for each node (min.N = in semree.control()), with 100 being a reasonable default for most SEMs.
