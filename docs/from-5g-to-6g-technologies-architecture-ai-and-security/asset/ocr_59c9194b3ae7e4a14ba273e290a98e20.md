# 2.4.1 Basic Concepts of ICN

+   * Named naming is an essential idea for ICN Name allowing the identification of data objects minus their location. There are two primary techniques to name a data object in ICN: flat naming scheme and a hierarchical scheme [33]. Hierarchical naming scheme functions based on the publisher, making it possible to aggregate routing data and improve the scalability of a routing scheme [34]. The flat naming scheme employs a hash of the data object like the content. By using this hash, the flat naming scheme employs a fixed-length name for every data object, which improves the speed of name lookup.
* Routing involves three stages: resolution, discovery, and delivery. During name resolution, the name of a data object is translated into the locator. What follows is the discovery stageing request to the data object. The requested object is routed to the consumer in the third stage. Relying on these three stages, ICN routing is classified primarily into two: by name routing and route by name.

# 2.4.2 In-Network Computing

One of the most promising for increasing application performance is in-network computing [35]. In-network computing denotes a specific type of hardware acceleration with network traffic interrupted by the alternating device before getting to the host, and where computations are carried out implemented by a network device, like networked FPGA (field-programmable gate array), smart network interface card, or a programmable ASIC [36]. Programmable network hardware can operate services traditionally separately on servers, with orders-of-magnitude enhancements in performance. Regarding the performance of these enhancements, network operators are still doubtful of in-network computing. The conventional wisdom is that the operational expenses from higher power consume suspends any application performance returns. Without in-network computing justifying its costs, it will be dismissed as an additional academic exercise.

One of the principal reproaches of in-network computing is its power-hungry nature [37]. Every application's consumer cost concerned for hardware and software implementation has overheads like power supply units. Different applications possess different power consumption abilities, and servers tend to implement different units. Different possess power efficiency optimizations with different cores to attain peak throughputs. In the same way, smart NICs, FPGA, and programmable network devices tend to end up in various performance and power consumption [38].
