### 2.4.1 Basic Concepts of ICN

- Named naming is an essential idea for ICN Name allowing the identification of data objects regardless of their location. There are two primary techniques to name a data object in ICN: flat naming scheme and a hierarchical scheme [33]. Hierarchical naming scheme functions based on the publisher, making it possible to aggregate routing data and improve the scalability of a routing scheme [34]. The flat naming scheme employs a hash of the data object like the content. By using this hash, the flat naming scheme employs a fixed-length name for every data object, which improves the speed of name lookup.
- Routing involves three stages: resolution, discovery, and delivery. During name resolution, the name of a data object is translated into the locator. What follows is the discovery stage request to the data object. The requested object is routed to the consumer in the third stage. Relying on these three stages, ICN routing is classified primarily into two: by name routing and route by name.
- Sec objects can be cached in an in-network cache; hence, origins are not all but a security unit [33]. Additionally, origin verification, which validates the integrity of ICN objects and their publishers also functions as another axis of ICN security. Failure of such techniques results in susceptibility to various attacks by inserting altered content into the network.
- Mobility aims to allow consumers to easily get content without unforeseen interruptions in ICN applications. Because of a receiver-driven content recovery in ICN, a modification in the physical location does not disturb incessant content reception. On the other hand, server-side mobility presents a challenge in offering support. ### 2.4.2 In-Network Computing

One of the most promising for increasing application performance is in-network computing [35]. In-network computing denotes a specific type of hardware acceleration with network traffic interrupted by the alternating device before getting to the host, and where computations are carried out implemented by a network device, like networked FPGA (field-programmable gate array), smart network interface card, or a programmable ASIC [36]. Programmable network hardware can operate services traditionally separately on servers, with orders-of-magnitude enhancements in performance. Regarding the performance of these enhancements, network operators are still doubtful of in-network computing. The conventional wisdom is that the operational expenses from higher power consumption suspend any application performance returns. Without in-network computing justifying its costs, it will be dismissed as an additional academic exercise.

One of the principal reproaches of in-network computing is its power-hungry nature [37]. Different devices possess power efficiency optimizations with different cores to attain peak throughputs. In the same way, smart NICs, FPGA, and programmable network devices tend to end up in various performance and power consumption [38].

### 2.4.5 Active Networking

Current research in active networking displays the prospects of this new kind of technology. From a service perspective, active networking allows for customized packet processing within the network on a per-packet, per-flow, or per-service level. It is possible to use customized packet processing with packet filtering, application-aware routing, multi-party communications, and information caching. From a management point of view, active networking technologies make it possible to attain fast service deployment and flexible service management [39]. The model of active networking permits an organization to set up and operate a service in a network in an identical manner to a program that can be set up and run on a computer. In comparison, the network assumes the computer's responsibility, which is simultaneously shared between numerous parties like consumers.

Ends attached to a network remain open so it is possible to program them in suitable languages and implements. Contrasting, the nodes of a traditional network like ATM are IP routers, and integrated frameworks whose functions and interfaces are defined through the standardization procedure. The nodes transport packets even without systems. The processing of packets inside the network is restricted to operations on the packet headers, particularly for routing. Networks do not change the packet payloads. In addition, node functionality is permanent and can only change with a primary attempt. Active networks break this tradition by letting the network acquire customized computations on whole packets, including payloads. Consequently, the active network technique paves the way for the fastest of packet processing functions in networks concerning service-particular and user-particular needs and computation of regulation, user, and management data packets within [40].
