
-   [系统模型](https://wiki.example.org/feynmans_learning_method)包括在MEC中进行的工作卸载（见[图18.1](#ch18.xhtml#fig18_1)）。任务是根据从UE发来的任务上传到任意三台服务器中的一台。选择哪一台服务器是基于深度Q学习算法。我们使用TCP/IP和用户数据报文协议（UDP）在根据应用类型（如图像处理、AR/VR、医疗、农业）传输任务时从UE到边缘服务器。服务器会使用Q学习算法跟踪Q值，并在一个任务消耗的电力少于其他任务时更新整个任务队列。

**`Q-learning`**是一种在MEC中使用的增强学习算法，它在环境构建和服务器分配算法提供的参数基础上对自身进行训练。随后，可以通过学习得到的模型在服务器上实现最优的作业分配。在本地计算时，延迟较大的任务更难以处理。在MEC中，状态空间可以代表当前的网络状况、设备状态以及资源可用性（如CPU、内存和带宽）。要对这些资源进行分配的判断需要访问此状态信息。`Q-learning`利用奖励机制评估在特定条件下进行活动的有效性。MEC中的奖励可以基于多种性能指标，包括延迟、能耗、吞吐量或用户满意度。更高的奖励对应更好的决策。

学习方法包括在迭代中探索状态‑动作空间，并根据获得的奖励更新Q表。`Q-learning`使用Bellman方程对Q值进行迭代更新：

(2)  

`P(s, a) = P(s, a) + α^(\*)[R(s,a) + γ^(\*)max(P(s′,a′)) − P(s,a)]`

其中，“`P(s, a)`”是状态“`s`”和动作“`a`”的Q值，“`α`”是学习率。

“`R(s, a)`”是在状态“`s`”中执行动作“`a`”时的即时奖励。

“`γ`”是折扣因子。

“`max(Q(s′, a′))`”表示下一个状态“`s`”及其所有可能动作“`a`”的最大Q值。

## Algorithm

输入：`Pt`, `Pt0`, `Pre_node`, `Comp_list`, `Trans_amount`

输出：`Trans_energy`

初始化：`Trans_energy` → 0；

如果 `Pt` ≠ 0 且 `Pre_node` (`Pt(0)(0)`) ≤ `Comp_list`，则 `Trans_energy` += ε `ptr`

如果 `Trans_amount` ≥ `Pt(0)(2)`，则 `Pt0` 添加 `Pt(0)` 并按 `Pt0` 对任务进行排序；

否则 `Pt(0)(2)` 减去 `Trans_amount`。

## V. Conclusion

在MEC中，深度Q学习算法在任务卸载中发挥关键作用。我们在本研究中假设多个任务在不同用户设备上并发运行，且这些任务既不敏感于延迟也不敏感于电力消耗。我们根据应用类型使用TCP/IP或UDP将用户设备与服务器相连。服务器上的工作队列根据完成任务所需的传输量进行调整，而Q学习过程会更新奖励值。基于强化学习的Q学习算法考虑奖励和惩罚，以最小化电力消耗。将工作卸载到节点服务器而非远程服务器可以提高电力效率、降低处理延迟，并降低整体基础设施成本。
