
# FYI: NIST Cybersecurity Framework and ISO/IEC 27002:2013

如本章前所述，NIST网络安全框架第3.3节“与利益相关者沟通网络安全要求”为组织提供了指导，帮助其学习如何在相互依赖的利益相关者之间沟通要求。示例包括组织如何使用目标概况来向外部服务提供商表达网络安全风险管理要求。这些外部服务提供商可能是云提供商，例如亚马逊网络服务（AWS）、Google Cloud或Microsoft Azure；也可能是云服务，例如Box、Dropbox或其他任何服务。

此外，NIST框架建议组织可通过当前概况表达其网络安全状态，以报告结果或与采购要求进行比较。此外，关键基础设施所有者或运营商可使用目标概况传达所需的类别和子类别。

关键基础设施部门可建立一个目标概况，可在其构成成员之间用作初始基线概况，以构建其量身定制的目标概况。

ISO 27002:2013第12节“运行安全”侧重于数据中心运营、运营完整性、漏洞管理、防止数据丢失和基于证据的日志记录。ISO 27002:2013第13节“通信安全”侧重于传输中信息的保护。ISO 27002:2013第15节“供应商关系”侧重于服务交付和第三方安全要求。

## 标准作业程序

***标准作业程序（SOPs）***是对如何执行任务的详细说明。SOP的目标是提供标准化指导、改善沟通、减少培训时间并提高工作一致性。SOP的另一种名称是*标准作业协议*。有效的SOP会说明谁执行任务、需要什么材料、任务在何处进行、何时执行以及人员如何执行任务。

### 为何记录SOP？

创建SOP的过程本身要求我们评估正在做什么、为何这样做，以及或许如何做得更好。SOP应由熟悉该活动和组织内部结构的人员编写。一旦编写完成，SOP中的细节可标准化目标流程并提供足够的信息，使具有有限经验或对程序了解有限但具备基本理解的人员能够在无人监督的情况下成功执行程序。写得好的SOP可减少组织对个人和制度知识的依赖。

员工变得如此重要以至于失去该个人会对公司造成巨大打击的情况并不罕见。想象一下，这个人是唯一执行关键任务的人；没有人接受过交叉培训，也没有关于员工如何执行此任务的文档。员工突然无法工作可能会严重损害组织。拥有适当的作业程序文档不是奢侈品：它是业务需求。

#### 授权SOP文档

程序文档化后，应在发布前进行评审、验证和授权。评审者分析文档的清晰度和可读性。验证者测试程序以确保其正确且未遗漏任何步骤。流程负责人负责授权、发布和分发。发布后对程序的更改必须由流程负责人授权。

#### 保护SOP文档

应建立访问和版本控制，以保护文档免受无意错误和恶意内部人员的侵害。想象一下，一名不满的员工获取了业务关键的程序文档并更改了关键信息的情况。如果篡改未被发现，可能导致公司陷入灾难性局面。修订版亦然。如果存在同一程序的多个修订版，很可能有人会使用错误版本。

### 开发SOP

SOP应让所有使用者都能理解。SOP应以简洁、逐步的***简明语言***格式编写。如果写得不好，SOP的价值有限。最好使用简短、直接的句子，以便读者能快速理解并记住程序中的步骤。信息应清晰明确地传达，以消除对所需内容的任何疑虑。步骤必须按逻辑顺序排列。任何例外情况必须注明并解释。警告必须突出显示。

四种常见的SOP格式为简单步骤、分层、流程图和图形。如[表8-1](#ch08.xhtml#ch08tab01)所示，决定使用何种SOP类型的两个因素是：用户需要做多少决策以及程序中有多少步骤。简短且决策较少的常规程序可以使用简单步骤格式编写。步骤超过10步且决策较少的长程序应以分层格式或图形格式编写。需要做出许多决策的程序应以流程图形式编写。选择正确的格式很重要。如果无法遵循，即使写得最好的SOP也会失败。
