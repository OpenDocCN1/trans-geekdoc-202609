## 5.3.2 Transition Matrix Estimation

The distribution shift from OOD data $x^{ood}$ leads to unreliable label prediction $\hat{y}^{ood}$, which is highly unreliable due to instance-feature noises [296, 123] as shown in Section 5.4.8. In order to capture the relationship between $\hat{Y}^{ood}$ and $Y^{ood}$, we leverage transition matrix $T \in [0,1]^{C \times C}$ [267, 272] which satisfies $P(Y^{ood}|X^{ood}) = T^T P(\hat{Y}^{ood}|X^{ood})$. However, estimating such a transition is difficult without access to any noisy label supervision or strong assumption [267, 172]. Therefore, we propose a simple effective selection approach to construct a support set with labels.

Specifically, we rank all OOD data within each class based on their prediction confidence, i.e., $\max_c\{x^{ood}\}$, where $[\cdot]$ denotes the value of the $c$-th entry. From the sorted dataset $\{x^{ood}_1, x^{ood}_2, \dots, x^{ood}_C\}_{c=1}^C$ we uniformly sample $\rho$ examples per class, where $\rho$ is the labeling duty, i.e., $D^{supp} = \{x^{ood}_1, \dots, x^{ood}_\rho\}_{c=1}^\rho$. In this way, we can effectively model the noisy posterior $P(\hat{Y}^{ood}|X^{ood})$. Through an accurate labeling process³, we can obtain the clean label posterior $P(Y^{ood}|X^{ood})$, effectively estimating the transition matrix $T$. Finally, the noise transition probability $T$ [; $\arg \max[f_{few}]$] of a query can be obtained indexing $T$ through their current process.

> ²Although some manual annotation is required, we show later in experiments that our strategy has an acceptable labeling workload and demonstrates superior performance to fine-tuning on the support set. Furthermore, the support set is not used for parameter tuning in our method, our fine-tuning does not actually use any human annotation for training.

> ³We experimentally show that when there is a distribution shift between $D^{supp}$ and $D^{ood}$, the proposed method can still perform effectively. As a result, it is unnecessary to conduct the labeling process on each practical task. Instead, we can use the existing support set to instruct OOD tasks.

## 5.3.3 Denoising In-Context Learning

Thanks to the previously obtained noise probability $T$ [; $\arg max[f_\theta]$], we can further decide which one is the possible ground truth through DICL. In particular, we only consider the classes of the top-N noise probability as potential candidates. If the label prediction denoted by “PRE#0” is not in the candidates, we would fix it in the first place. Further, we conduct *Diagnosing* which decides the fidelity of the current prediction, and *Therapy* which finds the possible ground truth.

**Diagnosing.** Since the inference time of MLLMs is non-trivial, it is necessary to avoid redundant analysis on confident examples. Hence, to examine the fidelity of model predictions, our Diagnosing focuses on answering whether query belonging to class “PRE#0” = “True”. Specifically, we retrieve from $D^{sup}$ to obtain one exemplar belonging to “PRE#0”, and another exemplar belonging to the class with the largest noise transition probability “CLN#1”. Then, combined with the query image $X_q$, an in-context is constructed:

> Question: This image <IMG_PRE#0> shows a photo of <PRE#0>, True or False?
> Answer: True;
> Question: This image <IMG_CLN#1> shows a photo of <PRE#0>, True or False?
> Answer: False;
> Question: This image <IMG_Query> shows a photo of <PRE#0>, True or False?
> Answer:

The symbols <IMG_PRE#0>, <IMG_CLN#1>, and <IMG_Query> are replace tokens for the image features of exemplars from “PRE#0” and “CLN#1”, and $X_q$, respectively. The first exemplar acts as the positive one to show MLLMs the true image from class “PRE#0”, and the second exemplar shows the negative to show the highly probable false image from “CLN#1”. Then, based on the $X_q$ and “PRE#0”, MLLMs can effectively judge the 84 correctness by outputting $z_0$:

$z_0 = \theta_{mll}((X_{PRE}\#,Y_{PRE}\#); (X_{CLN}1,Y_{PRE}\#):X_q) \quad (5.2)$

To enable further quantitative analysis, we obtain the logits of “True” and “False” tokens from the MLLM output $z_0$ followed by a softmax function:

$z_0 := \text{softmax}([z_0[True], z_0[False]]). \quad (5.3)$

Finally, we combine $z_0[True]$ and the prediction confidence of the vision model to obtain a detection score $\Delta$:

$\Delta = \frac{1}{2}(z_0[True] + \max [f_{o, \cdot}](x^{output})). \quad (5.4)$

If $\Delta$ is larger than a threshold $\delta$, we assume the current prediction “PRE#” is correct⁵, otherwise, we continue the next Therapy process.

**Therapy.** During therapy, we continue to use the instruction template above to traverse across the rest class candidates. Particular, for each iteration $e$ in $\mathcal{N}-1$ trials, we choose “$CLN\#c$” as the positive class and “PRE#” as the negative class, whose exemplars are comprehensively retrieved from $\mathcal{D}^{supp}$ to construct the prompt. Then, it is into MLLM to output the query image belongs to the class “$CLN\#c$”, i.e., $z_c = \theta_{mll}((X_{CLN}\#c,Y_{PRE}\#):X_q)$,let $z_c := \text{softmax}([z_c[True], z_c[False])$.

As a result, we decide the final prediction:

$y_{mll} = \arg \max [z_e]]_{e=0}. \quad (5.5)$
