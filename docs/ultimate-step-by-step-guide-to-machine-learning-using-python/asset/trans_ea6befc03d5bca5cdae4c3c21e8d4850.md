

# 9. 如何利用机器学习解决问题

既然我们已经了解了如何在 Python 中构建机器学习模型，以及不同种类的机器学习和深度学习算法，那么我们如何将它们应用到日常生活或组织中的实际问题中呢？在本章中，我将介绍一个结构化流程，指导你如何从最初的问题描述一步步走向解决该问题的机器学习模型。作为该框架的一部分，我们将涵盖以下步骤：

1.  确立你的用例
2.  就项目驱动因素达成一致：时间、成本和范围
3.  确认数据是否随时可用
4.  确认数据质量
5.  确认数据的可解释性
6.  可视化你的数据
7.  为你的用例拟合合适的机器学习模型
8.  如果你的用例允许使用监督模型，则训练你的模型
9.  如果有真实世界数据可用，则用该数据测试模型预测的准确性
10. 将模型投入生产
11. 迭代！

## 9.1 确立你的用例

此步骤涉及问题描述的构建，我建议将该问题描述构建为一个需要解决的问题或需要获得的洞察。问题越具体越好。当你试图确定哪种机器学习算法最适合你的问题时，这一步尤为关键。以下是一些供参考的用例示例：

1.  “基于历史通话量和季节性，夏季淡季期间我应该安排多少呼叫中心代表来处理人寿保险理赔队列？”
2.  “基于呼叫中心通话中使用的语言和语气，该客户离开我们组织或升级投诉的可能性有多大？”
3.  “根据该客户的购买模式，他/她在未来 6 个月内可能会购买哪些额外产品？”

## 9.2 就项目驱动因素达成一致：时间、成本和范围

一旦你确定了问题描述，了解你在数据科学项目中面临的约束条件就变得很重要。

1.  如果你的项目是**时间驱动**的，它很可能需要快速解决或增量交付，以提供即时洞察
2.  如果你的项目是**成本驱动**的，你很可能没有太多预算用于数据获取或额外资源
3.  如果你的项目是**范围或质量驱动**的，你在向客户共享结果之前，拥有额外的灵活性来真正完善你的模型和相应预测

## 9.3 确认数据是否随时可用

视问题性质而定，数据有时可能随时可用，有时则不然。例如，如果你试图分析流感病毒的模式以为即将到来的流感季节的疫苗研发提供依据，你可能无法获得基于当前流感季节的最新数据集——这可能是由于时机问题，或数据由卫生机构提供。在这种情况下，你必须利用现有数据，并在可能的地方进行外推/做出假设。在成本或时间驱动的项目中，这种情况将成为障碍。在缺乏可执行数据的情况下，你很可能需要通过商业论证说服利益相关者，投资获取额外数据以解决问题是正确的投资决策。

## 9.4 确认数据质量

你可能拥有海量数据，但数据质量可能不佳，即存在大量缺失、不完整或普遍难以解读的信息。在数据准备好进行分析之前，你将不得不花费大量时间进行数据清洗和处理。在许多数据科学项目中，这是最不讨好且最耗时的工作。好消息是 `Python` 拥有大量内置函数，正如我们在本书前面所演示的，它们允许你清洗数据并将其可视化，以消除异常值和空值。

## 9.5 确认数据的可解释性

你可能拥有大量高质量数据。然而，如果组织中没人理解这些数据，你将难以进行分析或训练模型。如果你被空降到一个组织负责他们的数据科学项目，该组织极有可能拥有大量旧遗留系统，这些系统使用自己的内部编码，而关于数据及如何解读它的知识往往只存在于人们的脑海中，或属于部落知识——即仅为少数资深老员工所知，但未记录在案或广泛共享。在一个高度关注运营且无法抽调数据主题专家（SME）协助数据科学项目的组织中，这往往是一个绊脚石。通常，必须通过商业论证来争取这些 SME 的可用性，以推动数据科学项目前进。

## 9.6 可视化你的数据

现在你拥有了高质量、可解释的数据，并能随时联系到 SME，你已准备好分析数据，真正的乐趣由此开始！第一步是可视化数据，以观察模式、异常和离群值。这也是你开始决定哪种机器学习模型和算法最适合你的问题及数据结构的步骤。例如，正如本书前面所示，如果你发现变量之间存在直线相关性，那可能是一个简单的线性回归问题。又或者，可能是一堆未定义的数据点，你需要寻找分组和共性——这听起来像是聚类算法的工作！幸运的是，`Python` 拥有功能强大的可视化库，如 `seaborn`，允许你在决定哪个模型最合适之前，从多个角度审视数据。

## 9.7 为你的用例拟合合适的机器学习模型

如上所述，数据的可视化结合你的用例性质和项目驱动因素，将决定你最终选择哪个模型作为最佳拟合。这基本上就像从工具腰带中为手头的工作选择最合适的工具，或者根据你需要开球还是推杆来选择最合适的高尔夫球杆。你懂的！正如本书前面提到的并通过房屋销售示例演示的，在针对真实世界数据测试中找到能提供最高准确度的模型之前，这通常是一个反复试错的过程。

## 9.8 训练你的模型

对于监督机器学习模型，你有机会提供带标签的数据和训练数据集，使其做好解决真实世界问题的准备。即使在无监督或深度学习模型中，随着更多数据变得可用，你也可以优化模型并调整算法。例如，在我们使用的房屋销售数据中，我们发现房屋类型和面积在推动房屋销售价格方面起了重要作用。然而，那也是一个相对较小的数据集。随着更多数据变得可用，车库数量或房屋是否有泳池等额外房屋特征可能变得更重要，模型将不得不重新训练。

## 9.9 测试你的模型

仅构建并训练一次模型是不够的。你必须不断测试它，并持续输入新数据作为反馈循环，以确保模型准确度保持在可接受范围内。开发监控机制也是最佳实践，这样如果模型准确度或错误率超出特定阈值，就该将模型拉回绘图板进行重新训练。

## 9.10 将模型投入生产

如果你构建的机器学习模型旨在用于组织的持续运营环境，而非一次性分析，你的最后一步是将模型训练和测试运营化和自动化。这可能涉及对基础设施的额外投资，以自动化数据流入模型，以及在准确度指标低于可接受限制时自动触发模型重新校准。

## 9.11 迭代！

一旦你完成模型的构建和生产部署，你将从模型预测中获得新的洞察。这些预测和洞察可用于优化你的用例和问题描述。当你调整问题描述时，你将重复上述步骤，以持续更新和增强你的模型。
