### 部署 Azure Databricks 工作区

可以通过任何 Azure 部署方法创建 Azure Databricks 工作区。最简单的入门方式是通过 Azure 门户创建工作区，步骤如下：

1. 登录到 `portal.azure.com`，并在页面顶部的搜索栏中搜索 `Azure Databricks`。单击 Azure Databricks 以转到 Azure 门户中的 Azure Databricks 页面。

2. 单击 Create 以开始选择 Azure Databricks 工作区的配置选项。

3. 创建 Azure Databricks 工作区页面包含五个选项卡，用于自定义工作区配置。让我们先探索 Basics 选项卡中的选项。与其他服务一样，此选项卡要求你为工作区选择一个 Azure 订阅、一个资源组、一个名称和一个区域。此选项卡上的最后一个选项要求你选择一个定价层。此选项卡的完成示例可以在 [图 5.5](#c05.xhtml#c05-fig-0005) 中查看。

![图 5.5 创建 Azure Databricks 工作区：Basics 选项卡。](images/c05f005.png)

[图 5.5](#c05.xhtml#R_c05-fig-0005) 创建 Azure Databricks 工作区：Basics 选项卡。

4. Networking 选项卡允许用户配置两个可选的网络安全设置：安全群集连接（无公共 IP）和 VNet 注入。

* 安全群集连接设置是一个简单的是/否单选按钮。如果选择是，群集节点将不会分配任何公共 IP 地址，群集网络上的所有端口都将关闭。无论是 Databricks 托管的 VNet 还是通过 VNet 注入配置的客户 VNet，情况均如此。这既简化了网络管理，又增强了 Azure Databricks 群集的网络安全性。

* VNet 注入设置允许用户使用其 VNet 作为群集资源关联的网络。这使你能够以更安全的方式使用服务终结点或私有终结点轻松将 Azure Databricks 连接到其他 Azure 服务，使用用户定义的路径连接到本地数据源，并配置 Azure Databricks 使用自定义 DNS。如果选择是，系统将提示你选择一个 VNet，并将该 VNet 的两个子网委派给 Azure Databricks 独占使用。第一个子网将用作主机子网，第二个子网将用作容器子网。主机子网是每个群集节点 IP 地址的来源，容器子网是部署在每个群集节点上的 Databricks 运行时容器的 IP 地址来源。主机子网默认是公共的，但如果启用了安全群集连接，主机子网将是私有的。容器子网默认是私有的。[图 5.6](#c05.xhtml#c05-fig-0006) 是启用了安全群集连接和 VNet 注入的 Networking 选项卡示例。出于安全原因，示例子网范围已保留。/26 的子网范围是两个子网推荐的最小子网大小。

![图 5.6 创建 Azure Databricks 工作区：Networking 选项卡。](images/c05f006.png)

[图 5.6](#c05.xhtml#R_c05-fig-0006) 创建 Azure Databricks 工作区：Networking 选项卡。

5. Advanced 选项卡允许你为存储在 DBFS 中的数据启用基础结构加密。请记住，Azure 默认会加密静态存储帐户数据，因此此选项为存储帐户增加了第二层加密。

6. Tags 选项卡允许你为使用 Azure Databricks 部署的资源添加标记。标记用于对资源进行分类，以便进行成本管理。

7. 最后，Review + Create 选项卡允许你查看设计过程中所做的配置选择。如果你对为 Azure Databricks 所做的选择感到满意，请单击 Create 按钮以开始部署工作区。

部署 Azure Databricks 工作区后，返回 Azure Databricks 页面，然后单击新创建的工作区。单击概述页面中间的 Launch Workspace 按钮，以导航到工作区 UI 并开始在 Databricks 生态系统中工作。[图 5.7](#c05.xhtml#c05-fig-0007) 是该按钮外观的示例。

![图 5.7 Launch Workspace 按钮](images/c05f007.png)

[图 5.7](#c05.xhtml#R_c05-fig-0007) Launch Workspace 按钮

单击 Launch Workspace 按钮后，将打开一个新的浏览器窗口，提示你使用 Azure AD 凭据登录。登录后，你将被带到 Azure Databricks Web 应用程序，在那里你可以开始使用 Databricks。下一节将介绍 Web 应用程序的关键组件。
