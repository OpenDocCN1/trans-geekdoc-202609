

## 18. A. Azure SQL Database Hyperscale

Azure SQL Database Hyperscale 用于非常大的 OLTP 数据库（>4 TB），并可自动缩放存储和计算。它使用横向扩展架构将数据存储在多个节点的文件组中。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 19. C. Server-level IP firewall rules

Azure SQL Database 的服务器级 IP 防火墙规则将端口 1433 开放到指定 IP 地址，以供逻辑服务器上的所有数据库使用。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 20. B. Data Migration Assistant

Data Migration Assistant 可用于检测 SQL Server 各版本之间的兼容性问题，并就如何解决这些问题提出建议。Azure 数据库迁移服务使用 Data Migration Assistant 来评估本地 SQL Server 数据库与不同版本 Azure SQL 的兼容性。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 21. D. Resource deployments in Azure

Azure 中的资源部署可以使用 Azure PowerShell、Azure CLI 和基础设施即代码模板（例如 Azure 资源管理器模板）进行脚本编写和自动化。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 22. B. Azure database backups

Azure 每周创建一次完整数据库备份，同时每 12 到 24 小时创建一次差异备份，每 5 到 10 分钟创建一次事务日志备份。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 23. A. Data Manipulation Language (DML)

数据操作语言 (DML) 命令用于与数据库中存储的数据进行交互。DML 命令可用于检索和聚合数据以进行分析、插入新行或编辑现有行。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 24. C. Dynamic data masking

动态数据掩码会模糊数据库表中的敏感数据。它允许用户指定要使用多种可用掩码模式之一掩码的列。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 25. D. Azure PaaS offerings

PostgreSQL、MySQL 和 MariaDB 均可作为 Azure 上的 PaaS 产品/服务使用。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 26. A. Read Committed transactions

读取已提交事务会在数据修改时对涉及的数据加锁，以防止其他事务读取脏数据。但是，数据可能会被其他事务修改，这可能导致不可重复读取或幻影读取。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 27. D. Fact tables

事实表存储可观测的数据或事件，例如销售总额和库存。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 28. B. SQL Server storage configuration

SQL Server 存储的推荐配置是将数据、日志和 tempdb 文件放在不同的驱动器上。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 29. D. Nonrepeatable reads

当事务多次读取同一行且每次返回的数据不同时，就会发生不可重复读取。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 30. C. Left outer joins

左外连接检索连接条件左侧表中的所有数据，以及右侧表中满足连接条件的数据。有关详细信息，请参阅 [第 2 章](#c02.xhtml)。

## 31. A. Graph databases

图数据库是专注于存储数据实体之间关系的专用数据库。从图数据库读取数据的应用程序会遍历实体网络，分析其关系。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 32. C. Document databases vs key-value stores

与键值存储不同，文档既可以通过键查询，也可以通过不同的数据值查询。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 33. D. Azure Cosmos DB Core (SQL) API

Azure Cosmos DB Core (SQL) API 是 Azure Cosmos DB 的原生文档数据库 API。它以 JSON 格式存储数据，允许存储事务的文档保持不同的架构。Azure Cosmos DB 可以全球分布到世界各地的多个区域，甚至允许用户将一个或多个复制区域设置为允许写入操作。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 34. B. Azure Table storage vs Azure Cosmos DB Table API

Azure 表存储仅支持一个额外副本，该副本可选择支持只读工作负载。Azure Cosmos DB 表 API 支持多区域复制，并支持只读和读写副本。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 35. B. Request Units (RUs)

请求单位 (RUs) 是计算资源单位，用于衡量在 Azure Cosmos DB 中读取和写入数据所需的吞吐量。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 36. D. Azure Cosmos DB keys

Azure Cosmos DB 提供主密钥和辅助密钥，用于读写和只读访问。这允许用户在无需任何停机时间的情况下重新生成和轮换密钥。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 37. C. Strong consistency

强一致性保证读取将返回最新版本。这是以写入性能为代价的，因为所有应用程序连接都将暂停，直到事务与每个参与区域完全同步。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 38. A. Partition keys

分区键是用于将数据分布到逻辑分区的数据字段。逻辑分区随后分布到物理存储分区。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 39. A. Private endpoint

专用终结点是使用虚拟网络中的专用 IP 地址的网络接口。您可以将专用终结点附加到 PaaS 技术（例如 Azure Cosmos DB），以将其隔离在虚拟网络中。有关详细信息，请参阅 [第 3 章](#c03.xhtml)。

## 40. C. Object storage

对象存储用于以二进制和文本格式存储大量数据。这可以包括以文本格式保存的视频、图像、音频文件和元数据。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 41. B. Azure Files

Azure 文件是 Azure 存储服务套件中的完全托管文件共享服务。它具有全球冗余，并可使用 SMB 或 NFS 协议访问。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 42. D. Access tiers for file shares

事务优化、热和冷访问层可用于托管在标准 Azure 存储帐户上的文件共享。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 43. A. Storage accounts and Blob storage

存储帐户允许用户在容器对象中组织其 Blob 存储数据。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 44. C. Azure Data Lake Gen2 (ADLS)

Azure Data Lake Gen2 (ADLS) 使用分层命名空间以优化数据访问的方式组织数据。使用 Azure Blob 文件系统 (ABFS) 驱动程序允许 Apache Hadoop 轻松与 ADLS 交互。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 45. D. Azure Data Lake Storage Gen2 (ADLS) access control

Azure Data Lake Storage Gen2 (ADLS) 实现了支持基于角色的访问控制 (RBAC) 和类似 POSIX 的访问控制列表 (ACL) 的访问控制模型。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 46. D. GRS and GZRS disaster recovery

GRS 和 GZRS 都是有效的灾难恢复选项，因为它们都将数据复制到辅助 Azure 区域。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 47. A. Storage account resources

单个存储帐户可以托管多个 Blob 容器、文件共享、表和队列。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 48. B. Azure AD identities and Storage Blob Data Contributor

分配了存储 Blob 数据参与者 RBAC 角色的 Azure AD 标识可以读取、写入和删除 Blob 容器和数据。存储 Blob 数据所有者角色也授予这些权限，但还提供额外的管理访问权限。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 49. C. Azure Storage Explorer

Azure 存储资源管理器是一个独立的桌面应用程序，可用于管理 Azure 存储资源和数据。有关详细信息，请参阅 [第 4 章](#c04.xhtml)。

## 50. D. Azure HDInsight

Azure HDInsight 是 Azure 中的托管开源分析服务，可用于部署用于 Apache Hadoop、Apache Spark、Apache Interactive Query/LLAP、Apache Kafka、Apache Storm 和 Apache HBase 的分布式群集。有关详细信息，请参阅 [第 5 章](#c05.xhtml)。

## 51. B. Spark executors

Spark 执行程序安装在每个工作节点上，并从 Spark 驱动程序分配任务。执行程序随后负责处理分配给它的任务。有关详细信息，请参阅 [第 5 章](#c05.xhtml)。
