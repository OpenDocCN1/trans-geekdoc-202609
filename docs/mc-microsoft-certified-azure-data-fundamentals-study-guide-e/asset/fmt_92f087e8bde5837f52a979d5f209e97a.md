
## 18. A. Azure SQL Database Hyperscale

Azure SQL Database Hyperscale is used for very large OLTP databases (>4 TB) and can automatically scale storage and compute. It uses a scale-out architecture to store data on filegroups across multiple nodes. See [Chapter 2](#c02.xhtml) for more information.

## 19. C. Server-level IP firewall rules

Server-level IP firewall rules for Azure SQL Database opens port 1433 for all databases on a logical server to a specified IP address. See [Chapter 2](#c02.xhtml) for more information.

## 20. B. Data Migration Assistant

The Data Migration Assistant can be used to detect compatibility issues between versions of SQL Server and make recommendations on how to address them. The Azure Database Migration Service uses the Data Migration Assistant to assess an on-premises SQL Server database's compatibility with the different versions of Azure SQL. See [Chapter 2](#c02.xhtml) for more information.

## 21. D. Resource deployments in Azure

Resource deployments in Azure can be scripted out and automated with Azure PowerShell, Azure CLI, and Infrastructure as Code templates such as Azure Resource Manager templates. See [Chapter 2](#c02.xhtml) for more information.

## 22. B. Azure database backups

Azure creates a full database backup once a week, while creating differential backups every 12 to 24 hours and transaction log backups every 5 to 10 minutes. See [Chapter 2](#c02.xhtml) for more information.

## 23. A. Data Manipulation Language (DML)

Data Manipulation Language (DML) commands are used to interact with data stored in a database. DML commands can be used to retrieve and aggregate data for analysis, insert new rows, or edit existing rows. See [Chapter 2](#c02.xhtml) for more information.

## 24. C. Dynamic data masking

Dynamic data masking obfuscates sensitive data in a database table. It allows users to specify which columns to mask with one of several available masking patterns. See [Chapter 2](#c02.xhtml) for more information.

## 25. D. Azure PaaS offerings

PostgreSQL, MySQL, and MariaDB are available on Azure as PaaS offerings. See [Chapter 2](#c02.xhtml) for more information.

## 26. A. Read Committed transactions

Read Committed transactions issue locks on involved data at the time of data modification to prevent other transactions from reading dirty data. However, data can be modified by other transactions, which can result in non-repeatable or phantom reads. See [Chapter 2](#c02.xhtml) for more information.

## 27. D. Fact tables

Fact tables store measurable observations or events such as sales totals and inventory. See [Chapter 2](#c02.xhtml) for more information.

## 28. B. SQL Server storage configuration

The recommended configuration for SQL Server storage is to place data, log, and tempdb files on separate drives. See [Chapter 2](#c02.xhtml) for more information.

## 29. D. Nonrepeatable reads

Nonrepeatable reads occur when a transaction reads the same row several times and returns different data each time. See [Chapter 2](#c02.xhtml) for more information.

## 30. C. Left outer joins

Left outer joins retrieve all data from the table on the left side of the join condition and data that meets the join condition from the table on the right. See [Chapter 2](#c02.xhtml) for more information.

## 31. A. Graph databases

Graph databases are specialized databases that focus on storing the relationship between data entities. Applications reading data from graph databases traverse the network of entities, analyzing their relationships. See [Chapter 3](#c03.xhtml) for more information.

## 32. C. Document databases vs key-value stores

Unlike key-value stores, documents can be queried by both their key and different data values. See [Chapter 3](#c03.xhtml) for more information.

## 33. D. Azure Cosmos DB Core (SQL) API

Azure Cosmos DB Core (SQL) API is the native document database API for Azure Cosmos DB. It stores data in a JSON format, allowing documents storing transactions to maintain different schemas. Azure Cosmos DB can be globally distributed to multiple regions around the world, even allowing users to set one or more of the replicated regions to allow write operations. See [Chapter 3](#c03.xhtml) for more information.

## 34. B. Azure Table storage vs Azure Cosmos DB Table API

Azure Table storage only supports one additional replica, which can optionally support read-only workloads. The Azure Cosmos DB Table API supports multi-region replication and supports both read-only and read-write replicas. See [Chapter 3](#c03.xhtml) for more information.

## 35. B. Request Units (RUs)

Request Units (RUs) are units of compute resources that are used to measure the throughput required to read and write data in Azure Cosmos DB. See [Chapter 3](#c03.xhtml) for more information.

## 36. D. Azure Cosmos DB keys

Azure Cosmos DB provides primary and secondary keys for read-write and read-only access. This allows users to regenerate and rotate keys without requiring any downtime. See [Chapter 3](#c03.xhtml) for more information.

## 37. C. Strong consistency

Strong consistency guarantees that reads will return the most recent version. This is at the expense of write performance as all application connections will be paused until a transaction is fully synchronized with every participating region. See [Chapter 3](#c03.xhtml) for more information.

## 38. A. Partition keys

Partition keys are data fields that are used to distribute data into logical partitions. Logical partitions are then distributed to physical storage partitions. See [Chapter 3](#c03.xhtml) for more information.

## 39. A. Private endpoint

A private endpoint is a network interface that uses a private IP address from a virtual network. You can attach a private endpoint to a PaaS technology, such as Azure Cosmos DB, to isolate it in a virtual network. See [Chapter 3](#c03.xhtml) for more information.

## 40. C. Object storage

Object storage is used to store large volumes of data in binary and text format. This can include videos, images, audio files, and metadata that is saved in text format. See [Chapter 4](#c04.xhtml) for more information.

## 41. B. Azure Files

Azure Files is a fully managed file share service in the Azure Storage suite of services. It is globally redundant and can be accessed using SMB or NFS protocols. See [Chapter 4](#c04.xhtml) for more information.

## 42. D. Access tiers for file shares

Transaction optimized, hot, and cool access tiers are available for file shares hosted on a standard Azure storage account. See [Chapter 4](#c04.xhtml) for more information.

## 43. A. Storage accounts and Blob storage

Storage accounts allow users to organize their Blob storage data in container objects. See [Chapter 4](#c04.xhtml) for more information.

## 44. C. Azure Data Lake Gen2 (ADLS)

Azure Data Lake Gen2 (ADLS) uses a hierarchical namespace to organize data in a way that optimizes data access. Using the Azure Blob Filesystem (ABFS) driver allows Apache Hadoop to easily interact with ADLS. See [Chapter 4](#c04.xhtml) for more information.

## 45. D. Azure Data Lake Storage Gen2 (ADLS) access control

Azure Data Lake Storage Gen2 (ADLS) implements an access control model that supports role-based access control (RBAC) and POSIX-like access control lists (ACLs). See [Chapter 4](#c04.xhtml) for more information.

## 46. D. GRS and GZRS disaster recovery

GRS and GZRS are both valid disaster recovery options because they both replicate data to a secondary Azure region. See [Chapter 4](#c04.xhtml) for more information.

## 47. A. Storage account resources

A single storage account can host multiple blob containers, file shares, tables, and queues. See [Chapter 4](#c04.xhtml) for more information.

## 48. B. Azure AD identities and Storage Blob Data Contributor

Azure AD identities assigned the Storage Blob Data Contributor RBAC role are able to read, write, and delete blob containers and data. The Storage Blob Data Owner role also grants these rights, but it provides additional management access as well. See [Chapter 4](#c04.xhtml) for more information.

## 49. C. Azure Storage Explorer

Azure Storage Explorer is a stand-alone desktop application that can be used to manage Azure Storage resources and data. See [Chapter 4](#c04.xhtml) for more information.

## 50. D. Azure HDInsight

Azure HDInsight is a managed, open-source analytics service in Azure that can be used to deploy distributed clusters for Apache Hadoop, Apache Spark, Apache Interactive Query/LLAP, Apache Kafka, Apache Storm, and Apache HBase. See [Chapter 5](#c05.xhtml) for more information.

## 51. B. Spark executors

Spark executors are installed on every worker node and are assigned tasks from the Spark driver. The executor is then responsible for processing the task it is assigned. See [Chapter 5](#c05.xhtml) for more information.
