

# 第 31–33 题参考下面描述的 Hi-Lo 游戏。

考虑编写一个 Hi-Lo 游戏的问题，用户想一个 1 到 100（含）之间的整数，计算机尝试猜出该数字。每次计算机猜测时，用户会做出以下三种响应之一。

- “Lower”（即该数字低于计算机的猜测）
- “Higher”（即该数字高于计算机的猜测）
- “You got it in < ***however many*** > tries!”（你用 < ***多少*** > 次就猜到了！）

使用顺序查找策略，计算机平均需要猜测多少次才能猜中数字？

(A) 100
(B) 51 到 99 之间
(C) 50

### [答案解析](#05_Contents.xhtml#rsec175)

## [1](#54_Chapter46.xhtml#rqans3_1)

**(E)** 排序算法的时间和空间需求受给定三个因素全部影响，因此选择特定排序算法时必须考虑所有因素。

## [2](#54_Chapter46.xhtml#rqans3_2)

**(D)** 选项 B 不合理：一旦找到不等于 `a[i]` 的值，循环就会退出。排除选项 A，因为如果 `value` 不在数组中，`a[i]` 最终会越界。你需要布尔表达式中的 `i < n` 部分来避免这种情况。然而，测试 `i < n` 必须位于 `value != a[i]` 之前，这样如果 `i < n` 失败，表达式将评估为 false，测试将短路，从而避免越界错误。选项 C 无法避免此错误。选项 E 是错误的，因为表达式的两部分必须都为 true 才能继续搜索。

## [3](#54_Chapter46.xhtml#rqans3_3)

**(C)** 二分查找算法依赖于数组已排序。顺序查找没有排序要求。两者都依赖选项 A（列表长度），而其他选项与两种算法均无关。

## [4](#54_Chapter46.xhtml#rqans3_4)

**(B)** 在无序数组中插入新元素既快速又简单——只需将其添加到列表末尾。计算平均值涉及求元素之和并除以 *n*（元素个数）。无论列表是否排序，执行时间都相同。操作 II（搜索）对无序列表效率低下，因为必须使用顺序查找。在 `sortedArr` 中，可以使用高效的二分查找算法，它涉及的比较次数较少。事实上，在有序列表中，即使是顺序查找也比无序列表更高效：如果搜索项不在列表中，一旦列表元素大于搜索项，搜索就可以停止。

## [5](#54_Chapter46.xhtml#rqans3_5)

**(C)** 假设数组有 1000 个元素，*x* 位于前 8 个槽位中的某处。所描述的算法将使用不超过五次比较找到 *x*。相比之下，二分查找将数组对半分割并进行比较六次，才会检查数组前 15 个槽位中的元素（每次分割后的数组大小：500、250、125、62、31、15）。

## [6](#54_Chapter46.xhtml#rqans3_6)

**(E)** 断言指出第一个元素大于数组中所有其他元素。这排除了选项 A 和 D。选项 B 和 C 不正确，因为你不知道元素 `a[1]...a[N-1]` 的相对大小。

## [7](#54_Chapter46.xhtml#rqans3_7)

**(C)** 当 `key` 不在数组中时，`index` 最终会变得足够大，导致 `a[index]` 抛出 `ArrayIndexOutOfBoundsException`。在选项 A 和 B 中，算法将无错误地找到 `key`。如果 0 在数组中，选项 D 不会失败。如果 `a[key]` 不越界，选项 E 将正常工作。

## [8](#54_Chapter46.xhtml#rqans3_8)

**(A)** 该算法利用了数组 `v` 按从小到大排序这一事实。`while` 循环终止——意味着搜索停止——只要 `v[index] >= key`。

**(C)** 第一遍使用区间 `a[0]...a[7]`。因为 `mid` = (0+7)/2 = 3，`low` 被调整为 `mid`+1 = 4，第二遍使用区间 `a[4]...a[7]`。

## [11](#54_Chapter46.xhtml#rqans3_11)

**(B)** 第一遍：将 27 与 `a[3]` 比较，因为 `low` = 0 `high` = 7 `mid` = (0+7)/2 = 3。

第二遍：将 27 与 `a[5]` 比较，因为 `low` = 4 `high` = 7 `mid` = (4+7)/2 = 5。

第三遍：将 27 与 `a[6]` 比较，因为 `low` = 6 `high` = 7 `mid` = (6+7)/2 = 6。

第四遍不会发生，因为 `low` = 6 而 `high` = 5，因此测试 `(low <= high)` 失败。根据当 `key` 不在列表中时查找迭代次数的通用规则：如果 *n* 是元素个数，将 *n* 向上取整到最近的 2 的幂，本例中为 8。注意 8 = 2³。因为 27 位于 4 和 41 之间，所以“分治比较”循环将有 3 次迭代。

## [15](#54_Chapter46.xhtml#rqans3_15)

**(A)** 30,000 = 1000×30 ≈ 2^(10) ×2⁵ = 2^(15)。因为最坏情况下成功的二分查找需要 log[2]*n* 次迭代，15 次迭代将保证找到 `key`。（注意 30,000 < 2^(10) ×2⁵ = 32,768。）捷径：30,000 < 2^(15)。因此，保证找到键的最大（最坏情况）比较次数等于指数 15。
