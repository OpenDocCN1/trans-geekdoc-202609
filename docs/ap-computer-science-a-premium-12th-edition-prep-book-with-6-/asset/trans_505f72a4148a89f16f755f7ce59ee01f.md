### 时间管理

你有 90 分钟完成 40 道题，意味着每道题略多于 2 分钟。然而，有几道复杂的题目需要手工跟踪，可能耗时超过 2 分钟。关键在于你没有时间可以浪费。

别让自己在一道题上陷入僵局。你懂其中的套路：你离答案很近了，已经花时间跟踪代码了，也许你在跟踪时出错了，应该重做一遍……与此同时时钟在滴答作响。如果某道题难住了你，圈出来然后继续往下做。如果最后有时间，你随时可以回来再做。

### 猜题

猜题不扣分。如果你不知道某道题的答案，准备跳过时，先排除明显错误的选项，然后从剩下的选项中猜一个。

当时间快用完时，为每道未作答的题目填上一个答案。记住，你应该随机猜测，而不是留空。

### Java 快速参考

在 AP 考试的选择题和简答题两个部分，你都可以使用 Java 快速参考。你应该提前熟悉它（参见 [第 xvii 页](#08_Intro.xhtml#page_xvii) 了解如何获取），以免浪费时间去查找其中没有的内容。

快速参考包含了 Java 库中 `Object`、`Integer`、`Double`、`String`、`Math` 和 `ArrayList` 类的方法和常量规范。所提供的每个方法都可能出现在 AP 考试的选择题中。

### 善用铅笔

考试不提供草稿纸，但你可以在试卷册子上书写。不要在脑子里跟踪棘手的算法。以下是一些善用铅笔的技巧：

对于循环的每次迭代，写下循环变量和其他关键变量的值。通常，纸上仅几个值就能揭示规律，阐明算法在做什么。

当你跟踪一个带有参数的方法的算法时，画出内存槽来直观展示值的变化。记住，调用方法时，会复制实参的副本。除非参数是引用，否则无法修改实际值。（参见 [第 104 页](#48_Chapter40.xhtml#page_104)。）

要找出递归算法返回的值，写下多次方法调用以便跟踪。（例如参见 [第 297 页](#53_Chapter45.xhtml#page_297) 的第 5 题。）

对于涉及继承的复杂题目，快速绘制一个 UML（继承）图以加强对类之间关系的理解。（参见 [第 196 页](#51_Chapter43.xhtml#page_196)。）

在选择题部分，经常出现类似以下的问题：

- 该算法有什么作用？
- ……的后置条件可能是什么？
- ……将导致哪个数组作为结果？
- 将返回哪个字符串？

轻松解决这些问题的关键是思考*小规模*情况。给自己一个 3 元素的数组，或一个 2×2 的矩阵，或一个 3 字符的字符串，在你易于管理的小数据结构上手工执行代码。写下数值。跟踪循环变量。答案就会显现出来。

### 故障排查——这段代码有什么问题？

一些选择题会告诉你代码无法按预期工作。你需要找出 `/* more code */` 的错误替代项，或直接找出错误。以下是一些可快速检查的细节：

如果是递归算法，它有基本情况吗？

递归算法中的基本情况真的会导致终止吗？

在数组算法中，索引能等于 `arr.length` 吗？如果可以，则越界。

算法是否包含 `arr[i]` 和 `arr[i + 1]`？通常 `arr[i + 1]` 会越界。

在包含 `str.substring[start]` 的字符串算法中，`start` 是否大于 `str.length()`？如果是，则越界。

在包含 `str.substring[start, end]` 的字符串算法中，`start` 是否大于或等于 `end`？如果是，会导致错误。`end` 是否大于 `str.length()`？如果是，则越界。

在除 `add` 以外的 `ArrayList` 方法中，索引值是否大于或等于 `list.size()`？如果是，则越界。

`SomeClass` 的客户端程序是否试图直接访问 `SomeClass` 的私有实例变量或私有方法？这会导致错误。

是否在构造函数中使用了关键字 `super`？如果是，它最好位于代码的第一行；否则，会导致编译时错误。

如果要将值插入有序列表，是否有范围检查，以确保算法不会超出列表末尾？

### 循环跟踪

以下是一些技巧：

有几道题会询问循环执行了多少次。问题的表述方式可能不同：某个单词或短语将打印多少次？循环体中的方法将执行多少次？如果数字较小，写下循环将执行时循环变量的所有值，然后数一数！那就是答案。

如果带有循环的问题的答案取决于参数 `n`，尝试将 `n` 设为 2 或 3 以观察规律。

务必注意循环测试使用的是 `<` 还是 `<=`（或 `>` 还是 `>=`）。

留意循环变量是如何变化的。它不总是 `i++`（增 1）或 `i--`（减 1）。

### Java 异常

有时，其中一个答案选项如下：

代码抛出 `<某种运行时异常>`。

浏览算法检查以下情况：

数组、`ArrayList` 或 `String` 越界。每种情况都会抛出相应的异常：`ArrayIndexOutOfBoundsException`、`IndexOutOfBoundsException` 或 `StringIndexOutOfBoundsException`。如果发现了，甚至无需瞥一眼其他选项即可继续做下一题。

整数除以零。如果除以零发生在复合测试的第一部分，则 `ArithmeticException` 总会被抛出。如果除法在测试的第二部分，且整个测试的值已知（短路求值），则不会抛出异常。（参见 [第 70 页](#47_Chapter39.xhtml#page_70)。）

### 矩阵操作

假设给定一个矩阵和一个以某种方式修改该矩阵的算法。这些算法通常难以跟踪，而且更棘手的是，你没有太多时间。

假设 `row` 和 `col` 是算法中的循环变量。对于快速解法，尝试查看对应循环中第一个 `row` 值和第一个 `col` 值的元素。通常这是左上角的元素。它会变吗？基于这一个元素，你能排除某些选项吗？对最终的 `row` 和 `col` 值重复此过程。通常这是右下角的元素。你能排除其他选项吗？

换句话说，你不总是需要跟踪所有值就能找到答案。
