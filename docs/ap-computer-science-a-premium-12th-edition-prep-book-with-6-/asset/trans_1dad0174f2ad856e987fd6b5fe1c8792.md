
关键是在第二遍扫描时检查 `a[0]` 时找到的。因此，键值为 `3` 并非最坏情况。这种差异是由于 `div` 运算的非对称性造成的，它产生的 `mid` 值更接近左端点而非右端点。

![](images/sq1.jpg)

如果键是 `1` 或 `20`（超出数组值的范围且不在数组中），算法将需要通过搜索循环 3 次才能确定键不在数组中，这是最坏情况。

![](images/sq1.jpg)

如果键是 `8`（不在数组中但在数组值的范围内），算法将只需通过搜索循环 2 次即可确定键不在数组中。所以这不是最坏情况。

![](images/sq1.jpg)

如果键是 `10`（不在数组中但在本例中的 `a[2]` 和 `a[3]` 之间），算法将需要通过搜索循环 3 次才能确定键不在数组中，这是最坏情况！具体过程如下：

第 1 遍：`low` = `0 high` = `3 mid` = `1`

第 2 遍：`low` = `2 high` = `3 mid` = `2`

第 3 遍：`low` = `3 high` = `3 mid` = `3`

当发现 `a[3]` 大于 `key` 时，`low` 的值变为 `4`，而 `high` 仍为 `3`，这意味着测试 `if (low > high)` 变为真，成为终止算法的基本情况。不再有与 `key` 的进一步比较。

这是另一个例子，其中 *n* 不是 2 的幂。

假设数组是 `1`、`3`、`5`、`7`、`9`。这里 *n* 为 5。要找到最坏情况下的遍数，将 *n* 向上取整到最近的 2 的幂，即 8 或 2³。在最坏情况下，通过搜索循环的遍数将是 3：

![](images/sq1.jpg)

如果键是 `1`，将有 2 遍找到它，这不是最坏情况。

![](images/sq1.jpg)

如果键是 `9`，将有 3 遍找到它，这是最坏情况。

![](images/sq1.jpg)

如果键是 `8`，将有 3 遍找到它，这是最坏情况。

![](images/sq1.jpg)

如果键是 `4`，将有 2 遍找到它，这不是最坏情况。

![](images/sq1.jpg)

如果键是 `1` – `9` 范围外的任何值，将有 3 遍找到它，这是最坏情况。

这些例子的教训是，并非每个不在数组中的键都代表最坏情况。

以下是在不同二分查找情况下计算最大循环遍数的一些通用规则。在每种情况下，都假设使用本书给出的算法。

![](images/sq1.jpg)

如果元素数量 *n* 不是 2 的幂，将 *n* 向上取整到最近的 2 的幂。最坏情况下的遍数等于指数。

![](images/sq1.jpg)

如果 *n* 是 2 的幂，最坏情况下的遍数等于指数加一。

![](images/sq1.jpg)

无论 *n* 如何，最坏情况总是涉及位于右端点的键或不在数组中的键。

![](images/sq1.jpg)

无论 *n* 如何，任何不在数组中且小于 `a[0]` 或大于 `a[n-1]` 的键都将是最坏情况。

![](images/sq1.jpg)

无论 *n* 如何，任何位于 `a[0]` 和 `a[n-1]` 之间但不在数组中的键可能是最坏情况，也可能不是。

### 章节总结

你不应该死记硬背任何排序代码。然而，你必须熟悉每种排序算法所使用的机制。例如，你应该能够解释归并排序的归并方法是如何工作的，或者在经过选择排序循环的一定次数遍历后，有多少元素处于其最终排序位置。你应该知道每种排序算法的最佳和最坏情况。

熟悉顺序查找和二分查找算法。你应该知道二分查找比顺序查找更高效，并且二分查找只能用于按搜索键排序的数组。
