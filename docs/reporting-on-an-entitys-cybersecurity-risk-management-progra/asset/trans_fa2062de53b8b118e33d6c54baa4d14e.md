| CC7.1 | **为实现其目标，实体使用检测和监控程序来识别：(1) 导致引入新漏洞的配置变更，以及 (2) 对新发现漏洞的易感性。** |
|  | 以下关注点专门针对使用信任服务标准的所有业务，突出了与该标准相关的重要特征： |
|  | • **使用定义好的配置标准**——管理层已定义配置标准。 |
|  | • **监控基础设施和软件**——实体监控基础设施和软件，查找不符合标准的情况，这些情况可能威胁到实体目标的实现。 |
|  | • **实施变更检测机制**——IT 系统包含变更检测机制（例如文件完整性监控工具），以向人员发出关键系统文件、配置文件或内容文件被未授权修改的警报。 |
|  | • **检测未知或未授权的组件**——已建立程序以检测未知或未授权组件的引入。 |
|  | • **执行漏洞扫描**——实体定期以及在环境发生任何重大变更后执行旨在识别潜在漏洞或配置错误的漏洞扫描，并及时采取措施修复发现的缺陷。 |
| CC7.2 | **实体监控系统组件及其操作，识别表明恶意行为、自然灾害和错误（这些影响实体实现其目标的能力）的异常情况；并对这些异常进行分析，以确定它们是否代表安全事件。** |
|  | 以下关注点专门针对使用信任服务标准的所有业务，突出了与该标准相关的重要特征： |
|  | • **实施检测策略、程序和工具**——定义并实施检测策略和程序，并在基础设施和软件上实施检测工具，以识别操作中的异常或系统中的异常活动。程序可能包括：(1) 安全事件检测和管理的既定治理流程，包括资源提供；(2) 使用情报来源识别新发现的威胁和漏洞；以及 (3) 记录异常系统活动。 |
|  | • **设计检测措施**——检测措施旨在识别由实际或尝试发生的以下情况引起的异常：(1) 物理屏障被攻破；(2) 授权人员的未授权行为；(3) 已破解的身份识别和认证凭证的使用；(4) 来自系统边界外部的未授权访问；(5) 授权外部方的被攻破；以及 (6) 未授权硬件和软件的实施或连接。 |
|  | • **实施过滤器以分析异常**——管理层已实施程序，以过滤、汇总和分析异常，以识别安全事件。 |
|  | • **监控检测工具的有效运行**——管理层已实施流程以监控检测工具的有效性。 |
| CC7.3 | **实体评估安全事件，以确定它们是否可能或已经导致实体未能实现其目标（安全事件），如果是，则采取措施防止或解决此类失败。** |

|  | • **制定和实施分析安全事件的程序**——已建立程序以分析安全事件并确定系统影响。 |
