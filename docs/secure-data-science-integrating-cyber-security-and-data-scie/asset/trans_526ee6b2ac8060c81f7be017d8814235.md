

# 基于 Hadoop 的 RDF 存储与查询处理

Hadoop [[HADOa](#ch15.xhtml#ref15_20)] 是一种分布式文件系统，文件可通过复制进行保存。它是构建存储系统的理想选择。Hadoop 具有高容错性和极高的可靠性。此外，它还包含 MapReduce [[DEAN2004](#ch15.xhtml#ref15_16)] 编程模型的实现，这是一种适合大规模数据并行处理的函数式编程模型。通过将数据划分为若干独立的数据块，MapReduce 进程针对这些数据块运行，从而简化了并行化。而且，MapReduce 编程模型有助于简化连接多个三元组模式的任务。

在本章中，我们将描述一种在 Hadoop 中存储 RDF 数据的模式，并详细介绍针对这些数据处理查询的解决方案。在预处理阶段，我们处理 RDF 数据并填充分布式文件系统中的文件。此过程包括对数据文件进行分区和组织，以及执行字典编码。随后，我们将详细介绍用于信息检索的查询引擎。我们将明确说明如何利用 MapReduce 编程来满足 SPARQL 查询。具体而言，我们必须确定将要执行哪些 Hadoop“作业”来解决查询。我们提出了一种贪心算法，该算法生成的查询计划所需的 Hadoop 作业数量最少。这是一种利用启发式方法的近似算法，但我们证明了最坏情况具有合理的上界。最后，我们利用两个标准基准数据集进行实验。我们展示了数据集从 0.1 亿到超过 66 亿三元组的实验结果。我们证明了我们的解决方案具有极佳的可扩展性。我们还证明了在超大数据集上使用标准基准查询时，我们的解决方案优于领先的最先进语义网存储库。

我们还为大数据设计并开发了两种访问控制模型。一种是基于令牌的机制，另一种基于 XACML。这两个系统均构建在我们的 SPARQL 查询优化器和用于语义网数据的 JENA 数据管理系统之上。我们的贡献如下所示，并以 [图 15.2](#ch15.xhtml#fig15_2a) 进行说明。更多细节请参见 [HUSA2011a]。

1.  我们设计了一种存储方案，用于在 Hadoop 分布式文件系统 (HDFS) [[HADOb](#ch15.xhtml#ref15_21)] 中存储 RDF 数据。

2.  我们开发了一种算法，保证提供的查询计划成本由给定 SPARQL 查询中变量总数的对数上界约束。它利用汇总统计信息估算连接选择性以打破平局。

3.  我们构建了一个高度可扩展、容错且支持数据密集型查询处理的框架。

4.  我们证明了我们的方法在所有查询上均优于 Jena，在具有大结果集的复杂查询上优于 BigOWLIM 和 RDF-3X。

5.  我们在 RDF 数据系统之上开发了两套访问控制系统。

## 15.3 相关工作

MapReduce 虽是一种编程范式，但正被研究人员迅速采纳。这项技术在处理大量数据的社区中日益流行。它是解决研究人员在云计算中面临的性能问题最有前景的技术。在 [ABAD09a] 中，作者讨论了 MapReduce 如何满足构建理想云数据库管理系统 (Cloud DBMS) 的大部分需求。研究人员和企业正利用 MapReduce 技术进行网页索引、搜索和数据挖掘。在本节中，我们首先调查与 MapReduce 相关的研究。接下来，我们讨论与语义网相关的工作。

Google 将 MapReduce 用于网页索引、数据存储和社交网络 [[CHAN2006](#ch15.xhtml#ref15_9)]。Yahoo! 在其数据分析任务中大量使用 MapReduce [[OLST2008](#ch15.xhtml#ref15_38)]。IBM 已成功试验了利用 MapReduce 技术的纵向扩展-横向扩展搜索框架 [MORE07]。在 [[SISM2010](#ch15.xhtml#ref15_44)] 中，他们报告了如何集成 Hadoop 和 System R。Teradata 通过将 Hadoop 与并行数据库管理系统集成完成了类似工作 [[XU2010](#ch15.xhtml#ref15_61)]。

研究人员已利用 MapReduce 扩展分类器以挖掘 PB 级数据 [[MORE2008](#ch15.xhtml#ref15_35)]。他们研究了用于数据挖掘的数据分发和分区，并应用了三种数据挖掘算法来测试性能。数据挖掘算法正以不同形式被重写，以利用 MapReduce 技术。在 [[CHU2006](#ch15.xhtml#ref15_12)] 中，研究人员通过利用 MapReduce 编程范式重写知名机器学习算法，以发挥多核机器的优势。该技术成功应用的另一个领域是仿真 [[MCNA2007](#ch15.xhtml#ref15_33)]。在 [ABOU09] 中，研究人员报告了一个将 MapReduce 与现有关系数据库技术相结合的有趣想法。这些工作与我们的研究不同之处在于，我们将 MapReduce 用于语义网技术。我们的重点是开发一种可扩展的解决方案，用于存储 RDF 数据并通过 SPARQL 查询检索它们。

在语义网领域，利用 MapReduce 技术的工作并不多。我们发现了两个相关项目：BioMANTA [[ITEE](#ch15.xhtml#ref15_26)] 项目和可扩展、高性能、稳健和分布式 (SHARD) [[CLOU](#ch15.xhtml#ref15_13)]。BioMANTA 提出了对 RDF 分子 [[DING2005](#ch15.xhtml#ref15_17)] 的扩展，并实现了一个基于 MapReduce 的分子存储 [NEWM2008]。他们使用 MapReduce 来回答查询。他们最多查询了四百万三元组。我们的工作有以下不同之处：首先，我们查询了十亿级三元组。其次，我们设计了一种存储模式，专门针对提高 RDF 数据的查询执行性能。我们根据三元组的谓词和对象的类型，将 RDF 三元组存储在文件中。最后，我们还有一种算法，用于确定查询处理计划，其成本由给定 SPARQL 查询中变量总数的对数上界约束。通过使用该算法，我们可以确定作业的输入文件及其运行顺序。据我们所知，我们是首批提出一种在 HDFS 中使用平面文件存储 RDF 数据的存储模式，以及一种用于回答 SPARQL 查询的 MapReduce 作业确定算法的人。

SHARD 是一个使用 Hadoop Cloudera 发行版的 RDF 三元组存储。该项目展示了初步结果，证明了 Hadoop 提高 RDF 数据集可扩展性的能力。然而，SHARD 仅以三元组存储模式存储数据。它目前不进行查询规划或重排序，且其查询处理器不会最小化 Hadoop 作业的数量。针对语义网存储库的研究已相当深入，特别强调查询效率和可扩展性。事实上，此类存储库太多，无法逐一公平评估和讨论。因此，我们关注那些开源或可下载、且在语义网和数据库社区获得良好声誉的语义网存储库。
