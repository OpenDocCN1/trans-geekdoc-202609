
# 隐私感知的数据存储与访问系统

最后，永久保留所有收集的数据会带来严重的隐私挑战。例如，永久记录所有位置数据可能会让恶意应用或恶意方推断出多年前用户移动模式的重要信息。为了增强隐私，我们设想了一些场景，用户可能希望根据预定义的条件删除某些信息。例如，用户可能希望在一段时间（如 10 年）后，删除访问特定地点（如拉斯维加斯）期间捕获的某些信息（如拍摄的照片）。当然，要实现这种安全的数据删除，需要我们追踪数据的存储位置。为了支持自动化的 QS 数据删除策略，需要高效的技术来追踪和删除敏感数据。

为了应对上述挑战，我们需要设计一个**隐私感知的数据存储与访问系统**。我们的高层设计如 [图 13.3](#ch13.xhtml#fig13_3a) 所示，来自不同来源的所有数据将首先在移动设备上进行处理和存储。本地存储将在本地（即智能手机上）保留不同类型的索引，以帮助查询存储的数据。此外，该框架将管理不同移动应用的数据访问策略。我们需要使该框架与现有工作（如 `OpenPDS` [MONT2014]）兼容，以便通过使用基本机制访问存储的数据，在框架之上运行多个不同的应用。随后，随着移动设备存储空间被占满，部分存储的 QS 数据将通过不同的启发式算法推送到云端。例如，上个月的心率数据可能会以加密格式推送到云端。在此操作之前，相应的本地索引将被更新，以便日后轻松检索。此外，本地构建的模型将被保留以支持特定任务。例如，即使底层数据通过流处理技术转移到了云端，用于发现心率异常的时间序列模型仍可在本地更新。另外，框架将记录哪些应用访问了哪些数据（即保留基本的来源信息），以便于未来的数据删除。显然，实现这样一个框架需要我们解决许多研究挑战。下面，我们总结了需要探索的活动。

## 1. QS 数据的安全长期存储

我们设想，一个典型用户在其一生中可能会生成数 TB 的数据。基于当前智能手机的能力，显然无法在本地存储所有数据。同时，正如前面讨论的，我们必须以加密格式将数据推送到云端，以保护个人隐私。我们需要探索如何将现有的可搜索加密技术无缝应用于查询本地和（加密的）云端数据。由于大多数 QS 数据将基于时间和位置进行索引、查询和访问，我们将首先针对不同类型的 QS 数据，在这两个维度上构建加密索引。为了能够利用现有的关键词搜索技术，我们需要对每个维度进行离散化（例如，按天、月、年对时间进行离散化），并将给定的搜索转换为关键词搜索和/或简单的一维范围查询搜索。这种简单的方法将为我们提供基于位置和时间的数据查询基本能力。这种加密查询可能构成从 QS 数据构建数据挖掘模型的基础。此外，我们需要探索在 QS 数据推送到云端之前，预先计算数据上某些有趣函数的方法。例如，可以使用人脸检测算法自动检测给定图像中的人脸。随后，与检测到的人脸相关的信息可被插入适当的索引中，以实现快速图像检索。我们需要探索从数据中预计算各种有趣特征（例如，给定图像中的人脸、传感器信息的移动平均值），以构建索引，从而利用现有的范围和关键词搜索技术，实现对云端加密数据的快速检索。

## 2. 面向 QS 应用的安全且隐私感知的查询接口

为了支持广泛的应用，我们需要为应用提供访问存储数据的接口。应用使用的某些数据可能需要从云端和本地移动存储中同时检索。在此数据访问过程中，我们要确保应用仅以不侵犯个人隐私的粒度访问数据。以安全且保护隐私的方式为 QS 应用提供全功能的查询语言支持（如 `SQL`）可能代价过高。我们需要探索简单的接口（例如 `SQL` 的一个受限子集），使应用能够在简化访问控制和隐私策略执行要求的同时，提供增值服务。我们还需要探索聚合技术（即披露聚合结果以隐藏敏感数据）和噪声添加技术（即本地差分隐私技术）。

## 3. 可用性/人因

由于最终用户必须通过界面来定义策略、设置数据管理选项，并为自己的目的使用数据，因此界面的设计必须符合人类的认知能力。至关重要的是，用户需要理解应用/推荐器给出的推荐和建议。我们需要利用我们在处理组织隐私策略的理解和用户隐私偏好的规范 [[PROC2007](#ch13.xhtml#ref13_58)]，以及对 Android 应用请求权限的理解 [GATE2014] 方面的知识和经验，来设计和评估界面，使其对于参与 QS 数据生命周期不同阶段的不同类型用户来说，都易于使用且直观。
