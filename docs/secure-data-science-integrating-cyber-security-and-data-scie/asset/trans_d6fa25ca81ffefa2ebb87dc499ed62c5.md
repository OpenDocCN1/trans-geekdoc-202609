
此处 `N` 为用户定义的参数。为简洁起见，我们将 `Foutlier x` 的 `λ[c]`\-邻域记为 `λ[c](x)`。因此，`Foutlier x` 的 `λ[+](x)` 是距离异常值 `x` 最近的 `N` 个类别 `c[+]` 的实例的集合。类似地，`λ[o](x)` 指距离 `x` 最近的 `N` 个 `Foutliers` 的集合。这在 [图 7.5](#ch07.xhtml#fig7_5a) 中有所说明，其中 `Foutliers` 显示为黑点，类别 `c[+]` 和类别 `c[−]` 的实例用相应的符号显示。`Foutlier x` 的 `λ[+](x)` 是属于类别 `c[+]` 且距离 `x` 最近的 `N` (= 3) 个实例的集合（圆圈内），以此类推。

![图 7.5 λc\-邻域，N = 3。](images/fig7_5.jpg)

[图 7.5 λ[*c*]\-邻域，*N* = 3。](#ch07.xhtml#Ffig7_5)

接下来，我们定义 `N`\-邻域轮廓系数（`N`\-NSC）（[定义 7.5](#ch07.xhtml#def7_5)）。

**定义 7.5：** （**`N`\-NSC**）*设 `a(x)` 为 `Foutlier x` 到 `λ[o](x)` 中实例的平均距离，`b[c](x)` 为 `x` 到 `λ[c](x)` 中实例的平均距离（其中 `c` 为现有类别）。设 `b[min](x)` 为所有 `b[c](x)` 中的最小值。则 `x` 的 `N-NSC` 由下式给出*：

```
N - NSC(x) = \frac{b_{\min}(x) - a(x)}{\max(b_{\min}(x),a(x))} (7.1)
```

根据定义，`N`\-NSC 的值介于 −1 和 +1 之间。它实际上是内聚度和分离度的统一度量。负值表明 `x` 更靠近其他类别（分离度较低）且远离其自身类别（内聚度较低）。如果至少存在 `N'` (> `N`) 个 `Foutliers` 且其 `N`\-NSC 为正，则我们宣布发现一个 `new class`（新类别）。

需要注意的是，`N` 的值越大，我们判断新类别是否到达的置信度就越高。然而，如果 `N` 过大，当对应数据块中属于新类别的实例总数 ≤ `N` 时，我们也可能无法检测到新类别。我们通过实验找到了 `N` 的最优值，这在 [第 7.4 节](#ch07.xhtml#sec7_4) 中有所解释。

### 7.3.2.3.1 计算新类别实例的集合

一旦检测到新类别的存在，下一步就是找出这些实例，并将其与现有类别数据分离。根据*必要且充分条件*，如果满足以下三个条件，则一组 `Foutlier` 实例属于一个新类别：(i) 该组中的所有 `Foutliers` 均具有正 `N`\-NSC，(ii) 该组中的所有 `Foutliers` 在该组内具有（注：原文此处似有省略，推测指“在该组内具有最近邻”或类似含义），以及 (iii) 该组的基数 ≥ `N`。设 `G` 为这样一个集合。注意，寻找精确集合 `G` 计算代价高昂，因此我们采用一种近似方法。设 `G'` 为所有具有正 `N`\-NSC 的 `Foutliers` 的集合。如果 |`G'`| ≥ `N`，则 `G'` 是 `G` 的一个近似。`G'` 中的某些数据点可能实际上并非新类别实例，反之亦然。然而，在我们的实验中，发现该近似效果良好。

### 7.3.2.3.2 加速计算

为每个 `Foutlier` 实例 `x` 计算 `N`\-NSC 需要 `Foutliers` 数量的平方时间。为了加快计算，我们还使用 `K`\-means 聚类从 `Foutliers` 创建 `K[O]` 个伪点，并在伪点上进行计算（称为 `Fpseudopoint`s），其中 `K[O]` = (`N[O]`/`S`)∗`K`。此处 `S` 为数据块大小，`N[O]` 为 `Foutliers` 的数量。因此，计算所有 `Fpseudopoints` 的 `N`\-NSC 的时间复杂度为 `O(K[O]*(K[O] + K))`，这是常数级的，因为 `K[O]` 和 `K` 均与输入规模无关。注意，`Fpseudopoint` 的 `N`\-NSC 实际上是该 `Fpseudopoint` 中每个 `Foutlier` 的 `N`\-NSC 的近似平均值。通过使用这种近似，虽然我们获得了速度，但也损失了一些精度。然而，正如实验结果所示，只要保留足够数量的伪点，这种精度下降可以忽略不计。新类别检测过程总结在 [算法 7.2](#ch07.xhtml#alg7_2) 中（DetectNovelClass）。

只要每个新类别遵循性质 7.1 且至少包含 `N` 个实例，该算法就能并发检测一个或多个新类别（即在同一数据块中）。即使类别分布倾斜，这也成立。然而，如果多个此类新类别同时出现，我们的算法将识别出属于这些类别的实例为新类别，而不对不同的新类别实例施加任何区分（即将它们简单视为“新类别”）。但一旦这些实例被标记并用于训练分类器，我们的模型就会学会这种区分。

### 7.3.2.3.3 时间复杂度

算法 7.1 的第 1–3 行需要 `O(KSL)` 时间，其中 `S` 为数据块大小。第 4 行（聚类）需要 `O(KS)` 时间，最后的 for 循环（5–10）需要 时间。因此，算法 7.1 的总体时间复杂度为 = `O(K*(S + SL + KL))`。假设 `S` >> `KL`，复杂度变为 `O(KS)`，这在 `S` 上是线性的。因此，MineClass 算法（算法 7.1）的总体时间复杂度（每个数据块）为 `O(KS + f[c](LS) + f[t](S))`，其中 `f[c](n)` 为对 `n` 个实例进行分类所需的时间，`f[t](n)` 为用 `n` 个训练实例训练分类器所需的时间。

### 7.3.2.3.4 演化类别标签对集成分类的影响

读者可能已经意识到，数据流中新类别的到达会导致集成中的分类器拥有不同的类别标签集合。例如，假设集成中较旧（较早）的分类器 `L[i]` 是用类别 `c[0]` 和 `c[1]` 训练的，而较新（较晚）的分类器 `L[j]` 是用类别 `c[1]` 和 `c[2]` 训练的，其中 `c[2]` 是在 `L[i]` 训练完成后出现的新类别。这会对投票决策产生负面影响，因为较旧的分类器会将 `c[2]` 的实例误分类。因此，我们不是计算每个分类器的票数，而是按如下方式选择性地计算它们的票数：如果较新的分类器 `L[j]` 将测试实例 `x` 分类为类别 `c`，但较旧的分类器 `L[i]` 的模型中没有类别标签 `c`，则如果 `x` 被发现是 `L[i]` 的异常值，将忽略 `L[i]` 的投票。当最旧的分类器 `L[i]` 是用某个类别 `c'` 训练的，但没有任何较新的分类器是用该类别训练时，会出现相反的情况。这意味着类别 `c'` 已过时，在这种情况下，我们将 `L[i]` 从集成中移除。通过这种方式，我们确保较旧的分类器在投票过程中影响较小。如果类别 `c'` 稍后在数据流中重新出现，它将再次被自动检测为新类别。
