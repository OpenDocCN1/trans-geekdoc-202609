

# 社交网络访问控制框架

在我们提出的框架中，我们计划在现有的在线社交网络应用之上构建多个层。我们计划使用基于 Java 的开源语义 Web 应用开发框架 `JENA` ([http://jena.sourceforge.net/](http://jena.sourceforge.net)) 来实现我们的原型，因为它为实现本章讨论的思想提供了一个易于使用的编程环境。在这里，我们将独立描述这些层中的每一个，以及在我们框架中选择特定技术背后的动机。虽然我们使用 Facebook 的具体实例作为利用底层语义层的总体应用，但任何社交网络应用都可以修改为使用我们在此描述的设计。[图 17.3](#ch17.xhtml#fig17_3a) 描述了我们的框架。策略和数据以 RDF 三元组的形式存储。参考监视器控制对数据的访问。它将执行诸如查询重写之类的功能。框架中的一些关键点将在随后的段落中讨论。接下来，我们将讨论框架的组件。

## RDF 数据存储

我们假设使用通用的 RDF 三元组存储来保存底层数据。在这种表示中，关于实体的所有事实都被记录为 `<主语, 谓语, 宾语>` 形式的三元组。因此，假设我们有一个名为 John Smith 的个体，被分配了唯一标识符 999999，这将给我们一个元组 `<999999, foaf:Name, "John Smith">`。

我们计划在一个单独的表中使用类似的格式来存储授权列表，这样我们就不必在每次请求授权时重新推断它们。对于数据存储系统，我们计划使用 `MySQL`，因为它易于获取，且易于与 `JENA` 进行接口对接。

我们在此指出，RDF 数据存储与关系数据库的不同之处在于，没有数据库方法来确保整个本体上的约束得到维护，例如确保定义的 `Person` 有一个名称。该事实的数据库表示与“该人住在阿尔伯克基”这一非必要陈述没有区别。然而，我们计划使用 `OWL-DL` 语句来定义这些约束，然后允许 RDF/OWL 引擎强制执行这些约束，稍后将对此进行描述。

### 推理器

任何支持 `SWRL` 规则的推理器都可以用来执行本章中描述的推理。然而，我们选择了 `SweetRules` ([https://ebiquity.umbc.edu/project/html/id/60/SweetRules](https://ebiquity.umbc.edu))，因为它能与 `JENA` 接口对接，并拥有基于规则的推理引擎。这意味着我们可以同时使用前向链接和后向链接来提高推理效率，以强制执行我们的访问控制策略。前向链接是一种推理方法，引擎从提供的数据开始，查看已建立的推理规则，试图推导出更多信息。这可以在系统需要大规模推断权限时使用，例如当资源首次添加时。

此时，将会有一次性大量地将授权添加到允许的用户列表中。然而，稍后，在添加其他朋友后，检查用户是否有权访问有限数量的资源可以通过后向链接完成。基本上，在后向链接中，我们从期望的目标开始（例如，目标是推断“John 是否有权查看相册 A”），并检查它是否被显式陈述，或者是否可以通过其他规则以递归方式推断出来。显然，这将允许在不重新检查所有其他个体的情况下，推断出关于某个个体（例如 John）的结果。在 [MIKA2007] 中，Mika 提出了一个名为 `Flink` 的基本通用社交网络，基于使用类似于我们提出的框架的语义数据存储，但使用了几种不同的具体语义技术。然而，他确实指出，他们的实现使用后向和前向链接，可以高效地扩展到数百万个元组，这为我们提出的方案的可行性提供了证据。

### RDF/OWL 引擎

对于 RDF/OWL 接口，我们选择使用 `JENA API`。我们用它来在应用程序和底层数据存储之间转换数据。`JENA` 有几个重要特性被考虑用于其使用。首先，它与 `SweetRules` 兼容。其次，它支持 `OWL-DL` 推理，我们可以用它来验证数据是否与本体上的 `OWL` 限制一致。`OWL` 限制是简单的基数和域/范围约束，例如每个人必须有一个名称，并且必须至少属于一个网络。为了强制执行这些约束，我们计划让应用层传递关于个体的待输入语句，直到收集完所有语句。然后我们让 `JENA` 将这些语句插入数据库，并检查新模型的一致性。如果有任何约束被违反，则将此信息传回社交网络应用，并让它从用户那里收集所需信息。

在我们的系统中，我们在一个简化的在线社交网络应用之上构建了多个层。我们考虑了社交网络的动作（消息、墙贴、查看个人资料、查看图片等），并检查了那些涉及最多访问请求的动作。例如，如果用户 John 要访问 Jane 的个人资料，那么在最好的情况下，只需进行一次检查（John 和 Jane 是否是适当级别的朋友）来确定权限。然而，当你考虑一张图片时，它很容易标记十几个人，而每个个体可能会指定他们自己额外的查看约束，那么很容易看出这将是系统中权限推断更复杂的例子。实际上，我们构建系统是为了测试一系列一致的最坏情况场景，以测试其处理测试负载的能力。

我们使用基于 Java 的开源语义 Web 应用开发框架 `JENA` ([http://jena.sourceforge.net/](http://jena.sourceforge.net)) 实现我们的原型，因为它为实现本章讨论的思想提供了一个易于使用的编程环境，并且通常是一个被当前大多数语义产品支持的框架。虽然我们使用 Facebook 的具体实例作为利用底层语义层的总体应用，但任何社交网络应用都有可能被修改为使用我们在此描述的设计。如前所述，我们系统的主要组件是 RDF 数据存储、推理器和 RDF/OWL 引擎。

## 17.9 实验

### 17.9.1 数据生成

当我们开始实施时，很明显我们需要能够在大型数据集上衡量我们实现的性能。因为 Facebook 的规模（在我们开始实施时）约为 3 亿用户，我们将 3.5 亿确立为数据集中所需的节点数量，以确保我们的实现能够扩展以匹配 Facebook 将达到的数字（目前接近 30 亿 ([https://www.businessofapps.com/data/facebook-statistics/](https://www.businessofapps.com))）。不幸的是，没有可公开获取的此规模数据集供我们使用。相反，我们生成了自己的数据集。
