## 9.2.3 面向可扩展性的大数据技术

流数据以高速度和大规模持续到来 [ALKH2012b]。这符合大数据的特征。“大数据”是指其规模、多样性和复杂性需要新的架构、技术、算法和分析来进行管理，并从中提取价值和隐藏知识的数据。因此，大数据研究人员正在寻找工具，以便及时且可扩展地管理、分析、汇总、可视化并从收集的数据中发现知识。

关于大数据管理，有许多技术可用于在廉价商用硬件组成的网格上实现大规模可扩展的数据处理，例如以下技术。Google 文件系统 [[CHAN2006](#ch09.xhtml#ref9_11), [DEAN2008](#ch09.xhtml#ref9_20)] 是一种可扩展的分布式文件系统，它利用商用硬件集群来促进数据密集型应用。该系统具有容错性，由于使用商用硬件，机器故障属于正常现象。为了应对故障，数据将复制到多个节点。如果一个节点发生故障，系统将利用存有复制数据的另一个节点。

MapReduce [CHAN2006, DEAN2008] 是一种支持以并行方式处理数据密集型应用的编程模型。MapReduce 范式支持 map 和 reduce 函数。Map 生成一组中间键值对，然后 reduce 函数合并结果并进行归纳。事实上，正如 [CHAN2006] 和 [DEAN2008] 所示，map/reduce 范式可以解决许多现实世界的问题。

Hadoop [[ABOU2009](#ch09.xhtml#ref9_1), [BU2010](#ch09.xhtml#ref9_8), [XU2010](#ch09.xhtml#ref9_87)] 是一个开源的 Apache 项目，支持 Google 文件系统和 MapReduce 范式。Hadoop 广泛用于结合 MapReduce 解决可扩展性问题。例如，针对海量语义 Web 数据集，Husain 等人 [[HUSA2009](#ch09.xhtml#ref9_35), [HUSA2010](#ch09.xhtml#ref9_36), [HUSA2011](#ch09.xhtml#ref9_37)] 表明 Hadoop 可用于提供可扩展的查询。此外，MapReduce 技术已被 BioMANTA 项目 [[DING2005](#ch09.xhtml#ref9_22)] 和 SHARD 利用（另见 [[BIOM](#ch09.xhtml#ref9_5)] 和 [[SHAR](#ch09.xhtml#ref9_78)]）。

Amazon 开发了 Dynamo [[DECA2007](#ch09.xhtml#ref9_21)]，一种分布式键值存储。Dynamo 不支持 Hadoop 所支持的主从架构。Dynamo 中的节点通过 gossip 网络通信。为了实现高可用性和性能，Dynamo 通过牺牲强一致性来支持一种称为最终一致性的模型。在最终一致性中，更新将异步传播到集群中的节点，并为每次更新生成一个新版本的数据。

Google 开发了 BigTable [CHAN2006, [CHAN2008](#ch09.xhtml#ref9_12)]，一种面向列的数据存储系统。BigTable 利用 Google 文件系统和 Chubby [[BURR2006](#ch09.xhtml#ref9_9)]（一种分布式锁服务）。BigTable 是一种基于行键、列名和时间戳的分布式多维稀疏映射。

研究人员 [ABOU2009] 利用了 MapReduce 和关系数据库技术的组合力量。关于大数据分析，有少量相关工作。例如，一方面，一些研究人员专注于通用分析工具以解决可扩展性问题；另一方面，其他研究人员专注于特定的分析问题。

关于工具，Mahout 是一个开源大数据分析工具，支持大数据的分类、聚类和推荐系统 [[OWEN2011](#ch09.xhtml#ref9_64)]。在 [[CHU2006](#ch09.xhtml#ref9_15)] 中，研究人员定制了知名机器学习算法，以利用多核机器和 MapReduce 编程范式。MapReduce 已被广泛用于挖掘 PB 级数据 [[MORE2008](#ch09.xhtml#ref9_62)]。

关于具体问题，Al-Khateeb 等人 [ALKH2012b] 和 Haque 等人 [[HAQU2013a](#ch09.xhtml#ref9_32), [HAQU2013b](#ch09.xhtml#ref9_33)] 提出了利用 MapReduce 和 Hadoop 框架在演化流上进行可扩展分类的方法。有一些关于结合 MapReduce 进行并行 Boosting 的研究工作。Palit 等人 [[PALI2012](#ch09.xhtml#ref9_65)] 提出了两种并行 Boosting 算法：ADABOOST.PL 和 LOGITBOOST.PL。

对于序列数据，量化字典构建耗时较长。可扩展性是此处的瓶颈。我们利用分布式计算来解决这一问题。有两种方法可以实现这一目标。第一种是利用昂贵硬件的共享内存架构并行计算。后一种方法是利用商用硬件的无共享架构分布式计算。在我们的案例中，我们采用后一种选择。这里，我们使用基于 MapReduce 的框架，通过 Hadoop 分布式文件系统 (HDFS) 来促进量化。我们提出了多种算法来量化字典。对于每种算法，我们讨论其优缺点，并在大型数据集上报告性能结果。

## 9.3 基于集成的内部威胁检测

### 9.3.1 集成学习

集成分类过程如 [图 9.2](#ch09.xhtml#fig9_2a) 所示。我们首先使用 OCSVM（有监督方法）或 GBAD（无监督方法）从单个数据块构建模型 [PARV2011a, PARV2011b, PARV2013]。在 GBAD 的情况下，在数据块中识别出 `规范子结构`，每个子结构表示为一个子图。为了识别异常，将测试子结构与集成中的每个模型进行比较。模型将根据测试子结构与模型的规范子结构差异程度，将其分类为异常。一旦所有模型投出票数，将应用加权多数投票做出最终分类决策。集成演化的安排旨在始终保持恰好 `K` 个模型。随着每个新数据块的到来，从新数据块创建第 `K` + 1 个模型，并从这 `K` + 1 个模型中丢弃一个牺牲模型。

![图 9.2 集成分类。](images/fig9_2.jpg)

[图 9.2 集成分类。](#ch09.xhtml#Ffig9_2)

选择牺牲模型有多种方式。一种方法是在最近的数据块上计算 `K` + 1 个模型中每个模型的预测误差，并丢弃预测效果最差的模型。这要求最近数据块的 `真实标签` 立即可用，以便准确测量预测误差。如果真实标签不可用，我们则依赖多数投票；与多数决定一致性最低的模型将被丢弃。这将产生一个由最符合当前概念的 `K` 个模型组成的集成。
