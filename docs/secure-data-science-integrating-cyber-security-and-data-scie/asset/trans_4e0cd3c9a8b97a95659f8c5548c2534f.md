
我们随后意识到，对于任何单个访问请求，只有那些其安全策略和好友关系对确定请求成败至关重要的用户群体才相关：（1）资源所有者，（2）发起访问请求的人，以及（3）资源中被标记的那些人。因此，我们采用了一种修正的分区方案。对于任何访问请求，我们生成一个临时表，仅包含上述三个群体的成员、涉及这些人的所有链接、请求者以及所有这些人的安全策略。

随后，我们使用三种测量信任值的方法，并进行实验以确定每种类型如何影响执行推理所需的时间：

*   **仅链接类型（LTO）**：即前文所述方法，其中每条边仅有一种链接类型。
*   **仅信任值（TVO）**：一种用信任值替代大多数链接类型的方法。但请注意，由于“ParentOf”/“ChildOf”关系具有独特的约束条件，我们仍保留这一链接类型。不过，我们不再维护其他通用或特定的链接类型。我们假设信任值（由用户分配）比定义的链接类型是更具体的度量。
*   **值/信任混合（VTH）**：一种保留所有通用链接类型声明、“ParentOf”特定类型，并在其基础上增加信任值的方法。这为安全策略提供了更细的粒度。例如，用户不必仅将某人定义为 `BestFriend`，而是可以定义各种安全策略，如仅允许信任值大于 7 的 `Friend` 访问，其中他们可能将 `BestFriend` 声明为信任值 6 或更高。这允许用户甚至在最好的朋友或家人中进行限制。

我们的实验结果见[表 17.2](#ch17.xhtml#table17_2a)。该表显示了执行推理任务所需的平均时间、最长时间和最短时间。请注意，这包括生成请求评估所需的临时表所需的时间。此外，我们还进行了其他系列测试，以确定图中好友数量的影响，如[图 17.4](#ch17.xhtml#fig17_4a)所示。对于这些测试，我们生成了一个子图，其中每个人拥有特定数量的好友，范围在 50 到 150 之间。我们使用三种信任度量类型（LTO、TVO 和 VTH）重复测试，并报告推理所花费的平均时间。同样，我们看到 LTO 显然用于推理的时间最少。此外，我们可以看到，在每个额外的好友群体中，推理所花费的时间仅略有增加。此外，在所有成员拥有 50 个好友的点上仅有轻微下降，这表明我们推理操作的大部分时间被推理引擎的开销（包括我们的动态分区方法）所消耗。

## 17.10 利用大数据和云技术实现可扩展性

我们使用语义 Web 来表示和推理用于访问控制的社交媒体数据，我们的策略和数据使用语义 Web 技术指定。社交媒体数据库规模庞大，支持数十亿用户。因此，我们需要可扩展的技术来表示和推理关于安全性和隐私的数据。我们现在拥有大数据管理技术，包括 `MongoDB`、`Google's Big Query` 和 `Apache HIVE` 等系统。大数据解决方案正由 `Amazon`、`IBM`、`Google` 和 `Microsoft` 等云提供商开发。此外，基于 `Apache Hadoop`、`Spark` 和 `Storm` 等产品的基础设施/平台也在开发中。还有基础设施管理工具以及大数据管理工具。

基础设施管理工具包括以下内容：

*   **Apache Hadoop**：`Hadoop` 是一个用于处理大量数据的开源分布式框架。它使用 `MapReduce` 编程模型。其存储系统称为 `Hadoop Distributed File System (HDFS)`。它托管在机器集群上。
*   **MapReduce**：`MapReduce` 是一种编程模型及其相关实现，它接收客户端请求并将其转换为 `MapReduce` 作业。这些作业随后由 `Hadoop` 执行。该编程模型的主要特性是作业的生成。
*   **Apache Spark**：`Apache Spark` 是一个用于处理海量数据的开源分布式计算框架。应用程序员通过一个包含称为 `Resilient Distributed Dataset (RDD)` 数据结构的接口来使用 `Spark`。`Spark` 的开发是为了克服 `MapReduce` 编程模型的局限性。
*   **Apache Storm**：`Apache Storm` 是一个用于处理海量数据的开源分布式实时计算系统。`Storm` 本质上是一个用于处理流数据和实时分析的实时框架。它可以与 `HDFS` 集成。

大数据管理工具包括以下内容：

*   **Apache Hive**：`Apache Hive` 是一个建立在 `Hadoop/MapReduce` 平台之上的开源类 SQL 数据库/数据仓库。它最初由 `Facebook` 开发，用于存储与 `Facebook` 数据相关的信息。后来它成为一个开源项目和 `Apache` 的商标。
*   **Google Big Query**：`Big Query` 本质上是一个管理 PB 级数据的数据仓库。它运行在 `Google` 的基础设施上，可以极快地处理 SQL 查询或进行分析。
*   **NoSQL 数据库**：`NoSQL database` 本质上是指非关系型数据库设计或面向 Web 的可扩展性的通用术语。它被称为非关系型高性能数据库。`NoSQL` 数据库的数据模型可能包括图、文档结构和键值对。一些流行的 `NoSQL` 数据库包括 `MongoDB` 和 `HBase`。

[图 17.5](#ch17.xhtml#fig17_5a) 展示了我们可扩展安全社交媒体系统的架构。在这里，大数据管理工具托管在基础设施工具之上。大数据管理工具增强了推理引擎。这些推理引擎本质上实现了各种机器学习算法，包括深度学习算法以及聚类算法。这些算法将检查策略、了解数据，然后提取模式并进行预测。如果模式和预测不是用户被授权查看的内容，则不会提供给用户。更多详情见[[THUR2020]](#ch17.xhtml#ref17_14)。
