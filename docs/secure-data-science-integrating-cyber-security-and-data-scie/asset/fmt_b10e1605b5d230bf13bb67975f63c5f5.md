
## 2. A local data analytics framework to build models and local statistics based on streaming data and encrypted data stored in the cloud

我们需要探索如何利用现有的流挖掘技术 [MAS2008, MAS2013] 来维护不同数据挖掘任务的本地统计和数据摘要。然而，当前的流学习算法 [[MASU2010](#ch13.xhtml#ref13_47)] 可能无法直接用于隐私感知或加密数据的场景。训练集的微小变化可能会影响所学模型的质量和性能。为此，我们将探索维护基本统计的方法，例如多流之间的相关性。根据需要，一些较旧的模型和统计将被加密备份到云端。在某些情况下，这些学习到的模型和统计将被结合起来，基于近似来回答重要问题。此类近似通常利用滑动窗口或采样方法。例如，要回答个体的睡眠质量如何受其体重影响的问题，将选择性地利用存储在云端的关于睡眠模式和体重数据的先前模型来计算此类相关性。

## 3. A global recommender system able to work on sanitized data

我们需要开发一个能够基于数据值范围而非精确值工作的推荐系统。此外，将探索随机响应等噪声添加技术，以便在共享数据前添加噪声。我们需要遵循测试匿名数据上学习到的分类器质量时所用的相同测试方法，测试基于清洗数据构建的推荐系统的相对有效性。

## 4. Cloud-based privacy-aware distributed data mining protocols to build population-level data mining models

除了前面讨论的噪声添加/清洗技术，我们还需要构建分布式数据挖掘技术，这些技术除最终数据挖掘模型外不泄露任何关于个人的信息。最初，我们将探索每个用户是否可以将其数据推送到云端的几个非串通、半诚实的服务器。例如，为了促进一项试图寻找规律锻炼、用户位置和空气污染对哮喘发作影响的科学研究，本地数据挖掘模型可以自动创建关于每周锻炼次数的统计数据，并结合用户的人口统计信息、哮喘发作记录（假设用户保留电子日记）和位置信息。这些统计数据将被分成秘密份额 [[DESM1992](#ch13.xhtml#ref13_17), CRAM2003] 并发送到不同的服务器。稍后，将利用基于秘密分享的分布式数据挖掘技术，将现有的本地污染信息数据安全地链接到用户的位置数据。构建此类应用将面临独特的挑战：如何最好地汇总本地数据，以便在云端最好地利用并扩展基于秘密分享的协议以支持大量用户。此外，我们可能需要探索如何利用额外的外部数据源在本地提高全局分布式数据挖掘协议的效率。例如，每个移动设备可能从互联网下载本地污染数据并在本地进行链接（再次使用类似 Tor 的系统以防止链接到个人）。这将减少公共云中所需的加密协议执行量。

## 5. A customization system able to refine the global recommender system for specific users

我们需要基于多重混合模型 [[LEE2013](#ch13.xhtml#ref13_43)] 研究一种方法，通过该方法我们将结合基于单个用户非清洗数据构建的本地推荐器获得的推荐，以及全局推荐系统获得的推荐，从而为特定用户获得定制化推荐。重要的是要注意，本地推荐系统将基于非常小的数据集获得，且非常精确，因为它未经过清洗。而全局推荐系统将基于非常大的数据集，由于潜在的数据清洗，其精确度较低。将进行广泛的实验分析以评估这种两步法的准确性。

## 6. A human-factors analysis to determine the risks and benefits associated with QS data sharing perceived by both expert and typical users

将采用一对一访谈和在线调查方法进行此类分析。政策专家将受邀进行一对一的半结构化访谈，并被询问关于 QS 数据存储可能涉及的风险和收益的看法。将从访谈数据中识别不同类别的风险和收益及其感知重要性。将通过 MTurk 招募典型用户回答问卷，以确定他们是否区分专家所识别的相同类别，并以相似方式感知其相对重要性。在两项研究中，用户都将被询问他们对 QS 数据存储的信任程度，并将风险和收益的类别作为不同信任水平的函数进行分析。如果典型用户感知到的风险和收益与专家用户识别的不同，将设计并测试教育用户了解这些风险和收益的方法，通过比较教育前后用户的反应来验证。我们还需要将关于用户偏好的发现与定义充分同意数据收集或处理的法律原则进行比较，并找出确保用户决策构成法律上有效限制的方法。为了实现 QS 数据共享隐私策略的个性化，应识别设置隐私策略的不同选项。我们需要向政策专家和典型用户询问他们希望隐私规范界面适应哪些选择。根据这些信息，我们将在实验室环境下以大学生计算机用户为对象，或在 MTurk 上以更广泛的计算机用户为对象，通过受控实验评估已识别的设计特性。许多用户因高信息处理需求而不愿进行详细规范，因此我们将开发大多数用户可接受的智能默认设置，并评估呈现预设选项的方式，这些选项允许相对简单的策略设置，但粒度比单独指定每个因素更粗。我们需要将实验结果纳入一个或多个可能界面的设计中，并对其进行可用性评估。

## 13.4 Novel Directions

第 13.3 节描述了我们针对数据收集、数据存储、数据共享和数据分析的隐私感知数据管理框架的高层设计。为了开发一个有用的框架，我们需要考虑一些额外方面，例如 (i) 用户设备的安全性，(ii) 框架的形式化，(iii) 行为方面，以及 (iv) 物联网 等新型应用，以便我们能够证明一致性和完整性等属性。我们将在本节讨论这些额外方面。
