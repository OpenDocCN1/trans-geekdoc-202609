[图 7.6(a)–(d)](#ch07.xhtml#fig7_6a) 展示了各方法在不同数据集上，决策树分类器在数据流某一时间点前的错误率（ERR）。K近邻（K-NN）分类器也呈现出类似的结果。例如，当 `X` 轴 = 100 时，`Y` 值显示了各方法从数据流开始到第 100 个数据块的平均 ERR。此时，对于 KDD 数据集（图 7.6(c)），MC、W-OP 和 W-OS 的 ERR 分别为 1.7%、11.6% 和 8.7%。每个数据集中新类别的到达，在每个图表顶部边框对应数据块处用叉号（x）标记。例如，在 SynCN 数据集上（图 7.6(a)），W-OP 和 W-OS 漏掉了大部分新类别实例，导致它们的曲线在相应数据块处出现尖峰（如第 12、24、37 个数据块等）。W-OS 几乎漏掉了 99% 的新类别实例。在 KDD 和 Forest Cover 数据集中，新类别出现的数据块处，W-OP 和 W-OS 也观察到类似的尖峰。例如，在 KDD 数据集的第 9–14 个数据块之间出现了许多新类别，其中大部分都被 W-OP 和 W-OS 漏掉了。注意，SynC 数据集没有新类别。MC 正确检测了大部分这些新类别。因此，MC 在所有数据集上均优于 W-OP 和 W-OS。

[图 7.7(a)–(d)](#ch07.xhtml#fig7_7a) 说明了在 KDD 数据集和决策树分类器上，MC 的错误率如何随不同参数设置而变化。这些参数对其他数据集和 K-NN 分类器也有类似的影响。图 7.7(a) 展示了在其他参数取默认值时，数据块大小对 ERR、`F[new]` 和 `M[new]` 率的影响。随着数据块大小增加，`M[new]` 降低。这是可取的，因为较大的数据块降低了漏掉新类别的风险。但 `F[new]` 率略微上升，因为将现有类别实例识别为新类别的风险也略微上升。这些变化从数据块大小 4,000 开始趋于稳定（对于合成数据集，则是 1,000）。这就是我们在实验中使用这些值的原因。图 7.7(b) 展示了聚类数量（`K`）对错误率的影响。增加 `K` 通常会降低错误率，因为异常值被更正确地检测出来，从而导致 `M[new]` 率下降。然而，`F[new]` 率也开始缓慢上升，因为更多的测试实例变成了异常值（尽管它们并非异常值）。综合效果是总体错误率持续下降直到某个值（例如 `K` = 50），之后变得几乎平坦。这就是我们在实验中使用 `K` = 50 的原因。图 7.7(c) 展示了集成规模（`M`）对错误率的影响。我们观察到错误率下降直到某个规模（= 6），此后趋于稳定。这是因为当 `M` 从较低值（如 2）增加时，由于误差方差的减少 [WANG2003]，分类错误自然会下降到一定程度。图 7.7(d) 展示了 `N` 对错误率的影响。该图表的 `x` 轴采用对数刻度。自然地，将 `N` 增加到某个点（如 20）有助于降低错误率，因为较高的 `N` 值使我们在声明新类别时具有更大的信心。但过大的 `N` 值会增加 `M[new]` 和 ERR 率，因为如果一个新类别在数据块中的实例少于 `N` 个，算法就会漏掉它。我们发现 20 到 100 之间的任何值都是 `N` 的最佳选择。

#### 7.4.3.3 运行时间

[表 7.2](#ch07.xhtml#table7_2a) 比较了 MC、W-OP 和 W-OS 在各数据集上针对决策树的运行时间。K-NN 也显示出类似的性能。标题为“Time (sec)/chunk”的列显示了每个数据块的平均运行时间（训练和测试），单位为秒；标题为“Points/sec”的列显示了平均每秒处理（训练和测试）的点数；标题为“speed gain”的列显示了 MC 速度与 W-OP 和 W-OS 速度的比率。例如，在 KDD 数据集上，MC 比 W-OP 快 2,095 倍；在 Forest Cover 数据集上，快 105 倍。此外，在 SynCN 数据集上，MC 分别比 W-OP 和 W-OS 快 203 倍和 27 倍。W-OP 和 W-OS 在 SynCN 上比在 SynC 上慢，因为 SynCN 数据集拥有更多属性（20 对 10）和类别（10 对 2）。W-OP 相对比 W-OS 慢，因为 W-OP 维护 `C` 个并行模型，其中 `C` 是现有类别的数量，而 W-OS 仅维护一个模型。由于 Forest Cover 的类别数量较少，且演变程度相对低于 KDD，W-OP 和 W-OS 在 Forest Cover 上相对比在 KDD 上快。导致 W-OP 和 W-OS 处理极其缓慢的主要原因是，每个 OLINDDA 模型的聚类数量随着数据流规模的增长而线性增加，导致内存需求和运行时间也线性增加。但 MC 的运行时间和内存需求在整个数据流长度上保持不变。
