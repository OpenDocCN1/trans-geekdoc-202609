
在 `[ORAC12]` 中，数据访问约束使用两种图模式来描述：匹配模式和应用模式。匹配模式确定要强制执行的访问限制类型，并将一个或多个变量绑定到用户查询中访问的相应数据实例。

**示例 18.3：** 使用匹配和应用模式的数据访问约束。

匹配：`{?contract pred:hasContractValue ?cvalue }`

应用：`{?contract pred:hasManager emp:Andy }`

此示例确保仅当 `Andy` 是所访问合同的管理员时，才能访问合同的 `hasContractValue`。示例 18.3 中的重要特性是：在匹配模式中定义的变量被用于相应的应用模式中，以对已识别资源强制执行访问限制。

### 18.3.4.6.1 处理规则

仅查询 RDF 图但不处理规则的查询引擎，与同时处理规则的推理引擎之间存在差异。在文献中，这种差异并不总是清晰的。推理引擎的复杂度比查询引擎高得多。原因在于规则允许我们进行顺序演绎。在查询执行过程中，必须构建这些演绎。而查询引擎则不需要这样做。请注意，还有其他查询引擎依赖于有向标记图的形式化模型，例如 DQL 和 RQL `[[FIKE2002](#ch18.xhtml#ref18_12), [KARV2002](#ch18.xhtml#ref18_17)]`。

规则还支持一个逻辑基础，其固有复杂性高于无规则情况下的逻辑。对于 RDF 查询引擎，仅需要图上简单的蕴含原则。`RuleML` 是一项重要工作，旨在定义可用于万维网的规则。推理 Web 是一个最近的实现，它定义了一个在语义 Web 上处理不同推理引擎的系统 `[[MCGU2004](#ch18.xhtml#ref18_21)]`。

### 18.3.4.6.2 通过图重写强制执行约束

图重写，也称为图变换，是一种利用某种自动机器从原始图创建新图的技术。这通常是一种编译抽象，其基本思想是：计算状态可以表示为图，而计算的进一步步骤则表示为图上的变换规则 `[[EHRI2006](#ch18.xhtml#ref18_10), [ROZE1997](#ch18.xhtml#ref18_29)]`。

图重写源于逻辑和数据库理论，其中图被视为数据库实例，重写操作被视为定义查询和视图的机制。流行的图重写方法包括双推出方法、单推出方法和代数方法 `[[EHRI1991](#ch18.xhtml#ref18_9)]`。我们描述的方法类似于单推出方法。图重写系统由一组形式为 `p: L → R` 的重写规则组成，其中 `L` 是图模式（或左侧），`R` 是替换图（或规则的右侧）。通过在原始图中搜索模式图的出现，并用替换图的存在来替换找到的出现，将图重写规则应用于原始图。

## 18.4 推理控制器实现的方法

我们实现推理控制器的方法如 `[图 18.4](#ch18.xhtml#fig18_4a)` 所示。传统上，我们使用访问控制策略和基于清理的策略等策略来保护数据。然而，当前强制执行这些策略的机制无法作用于以有向图形式呈现的数据 `[[BRAU2008](#ch18.xhtml#ref18_3)]`。此外，用户可以通过对溯源图执行频繁查询，从返回的结果中推断出敏感信息。我们特别关注从前提形成的任何结论，其中该结论的形成未经任何控制或处理前提或结论来源信息的个人或组织的明示或事先批准。我们也将从前提形成这些结论的过程称为推理。当推断出的信息是用户未获授权查看的内容时，我们称之为推理问题的一个实例。该问题始终存在于同时包含公共和私有信息的系统中。推断出的知识可能依赖于从知识库获得的数据，也可能依赖于用户拥有的先验知识以及从知识库获得的信息 `[[THUR1993](#ch18.xhtml#ref18_33)]`。

![图 18.4 实现推理控制器。](images/fig18_4.jpg)

[图 18.4 实现推理控制器。](#ch18.xhtml#Ffig18_4)

仅从知识库获得的推断知识可用于揭示知识库中有什么和没有什么。例如，如果用户询问与患者 X 光检查相关的信息，任何响应都可能表明该患者是否做过 X 光检查。一般来说，对查询的肯定回答揭示了知识库中的内容，而否定回答可能有多种解释。例如，用户可能将否定回答解读为答案不在知识库中，或者解读为答案在知识库中，但知识库选择不向查询揭示正确答案。这两种解释也可能取决于知识库使用封闭世界假设还是开放世界假设 `[[REIT1977](#ch18.xhtml#ref18_28)]`。通常，开放世界假设表示数据不完整，或者数据可能在系统的其他地方，不限于特定文件或位置。在封闭世界假设中，数据是完整的，对查询的否定回答通常表示数据不在知识库中。我们假设开放世界假设；特别是，用户不应能准确区分被推理控制器隐藏的事实的存在，与可在别处获得的事实的不存在。

我们的主要重点是对呈现为 RDF 图的社交媒体数据进行分类和保护。然而，我们推理控制器的初始实现是针对溯源数据的，溯源数据存在于包括社交媒体数据在内的众多领域中。我们的推理控制器可针对社交媒体数据进行调整，因为我们的社交网络表示为 RDF 图。语义 Web 通过使用形式语义扩展了 RDF 图模型，使其具备推理能力。正是这种推理服务被我们用来支持推理控制器的推理策略。此外，我们还展示了如何执行新的查询修改技术，以在溯源图上强制执行安全策略，这可以扩展到 `[第 19 章](#ch19.xhtml#chapter19)` 和 `[第 20 章](#ch20.xhtml#chapter20)` 中讨论的社交媒体图。

语义推理器使我们能够从一组公理中推断逻辑后果。它提供了一组更丰富的机制，使我们能够从使用 OWL 词汇编码的溯源图中得出推论。我们可以通过本体语言指定推理规则。推理器通常使用一阶谓词逻辑进行推理。推理通过前向链接和后向链接进行。（图 18.4）。
