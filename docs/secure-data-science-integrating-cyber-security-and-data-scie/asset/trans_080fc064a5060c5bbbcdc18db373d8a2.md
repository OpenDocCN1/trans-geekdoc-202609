

## 2. 一个用于根据我们的策略语言制定策略的策略编写工具

该工具将提供一个易于使用的界面来制定策略，以及一种导入策略的机制（例如，必须在用户设备上强制执行的企业策略）。我们需要利用现有的“示例策略”研究成果 [CHEE2012]；然而，这种方法是为社交网络开发的，主要处理对好友进行分组以分配权限。我们需要借用“示例策略”的概念，并将其调整以适应我们的场景。编写工具还将支持基于图形的位置界面，用于指定位置信息。

## 3. 一个灵活的位置和在场检测机制

我们需要开发一套用于检测用户位置的机制，以便根据位置类型（如封闭/开放位置）以及可用的网络和传感设备，使用最方便的机制。我们的位置检测系统将利用基于 Wi-Fi 的定位技术来检索设备位置。除了这些技术外，我们的系统还将收集从 GPS 和蜂窝网络检索到的位置数据，以应对关注区域没有 Wi-Fi 覆盖的情况。作为系统的一部分，我们将开发一个用户专属的 Wi-Fi 接入点数据库，记录用户访问过的区域，从而允许用户为这些区域关联名称并在策略中引用它们。关于在场检测，我们将开发基于近场通信 (NFC) 技术 [KIRK2011]、物理访问控制、运动传感器、监控设备及其他方法 [GUPT2012] 的机制。

## 4. 一个策略执行引擎

该引擎位于设备中，将负责执行策略。一个主要挑战是执行那些要求在特定情境下不得使用设备上某些资源的策略。我们的初步方法将在 Android 上解决此问题，并利用我们在 IdentiDroid 匿名系统 [[SHEB2014](#ch13.xhtml#ref13_64), [MIDI2014](#ch13.xhtml#ref13_49)] 中关于动态撤销 Android 权限的先前工作。在我们的系统中，一个主要挑战是必须根据情境动态撤销或恢复权限，而在 IdentiDroid 中，切换是在用户需要进入或退出匿名模式时执行的。

需要进行详细分析，以识别特定于我们目标环境的隐私问题，该环境由每个人对自己进行的连续/普适个人数据收集组成。此外，我们需要探索设计以下内容的方法：

### 1. 面向隐私感知数据收集的策略语言

我们需要开发一种策略语言，作为著名的 XACML 标准 [[XACM2005](#ch13.xhtml#ref13_76)] 的扩展。

### 2. 策略编写工具

我们需要调整或开发一个用户友好的工具，支持用我们的语言表达的策略规范。一种可能性是使用具有高层信息表示的对话代理 [[PARI2012](#ch13.xhtml#ref13_57)]。该工具需要支持基于用户反馈和策略覆盖的策略分析和演进。该工具还需要支持策略集成，支持合并不同的策略（例如，关于在办公室工作时可以捕获什么数据的企业策略，以及用户定义的个人策略），并包含用于策略冲突解决的简单机制和默认设置。

### 3. 位置和在场检测机制

我们需要为智能手机等设备设计位置检测机制。

### 4. 策略执行引擎

我们需要设计引擎来应用策略。引擎设计中的一个重要挑战是确保策略不被（可能的）恶意用户绕过，在企业策略的情况下，是指不想遵守策略的用户，或者是目标收集用户私人数据的恶意软件。为了应对此类挑战，我们需要集成和扩展可信平台管理 (TPM) 技术、容器化技术，以及最初为保护数据免受内部威胁而开发的应用程序剖析技术 [[HUSS2015](#ch13.xhtml#ref13_34)]。

## 13.3.2 面向隐私的数据存储与访问

在从不同传感器（如健康监测仪）、设备（如 Narrative Clip 生活记录仪）和移动源（如移动设备用户发送的推文和短信）收集 QS 数据后，我们需要存储这些数据以进行挖掘和分析，从而提取有趣的模式。在某些情况下（例如，将位置数据与空气质量数据相关联以了解长期哮喘趋势），根据策略存储所有捕获的数据可能具有长期价值。存储此类收集的数据带来了有趣的研究挑战。首先，目前正成为所有捕获数据中心的智能手机可能无法在设备上存储所有数据。为了解决智能手机的存储限制，可以利用云存储。许多移动设备支持自动云备份和存储机制。例如，iPhone 自带基于 iCloud 的默认数据备份支持。不幸的是，正如近期事件所示 [[DUKE2014](#ch13.xhtml#ref13_19)]，以明文格式存储在云中的隐私敏感数据可能容易受到攻击。在将此类数据移至云端之前对其进行加密可以防止其中一些攻击，但直接的数据加密会导致许多查询执行和数据检索挑战。查询加密数据的最新进展可被利用，以实现安全的云数据存储，同时允许选择性地检索数据，但仍存在需要解决的重要挑战，以满足各种 QS 应用的需求。现有技术如范围查询（例如 [[SHI2007](#ch13.xhtml#ref13_65)]）、关键词搜索（例如 [CURM2011, GOH2003, STEF2014]）、基于属性的加密（例如 [[WANG2010](#ch13.xhtml#ref13_75)]）和全同态加密（例如 [GENT2009]），不能直接支持诸如“查找在纽约市拍摄的、画面中有吉姆的照片”这样的查询。在利用智能手机能力的同时，改进和优化现有的加密数据查询技术，仍然是一个重要的研究方向。正如我们稍后将讨论的，我们计划通过从 QS 数据中提取重要特征，然后修改现有的可搜索加密技术以适应这些提取的特征，来应对这些挑战。

另一个重要需求是支持为用户提供有价值服务的移动应用。考虑一个访问运动数据以自动提取睡眠模式并将其与体重信息相关联，从而了解体重对睡眠模式影响的应用。为了支持此类应用，我们可能只想提供晚上的运动传感器数据，隐藏白天的活动模式。提供对收集的 QS 数据的细粒度访问，将是在保护隐私的同时允许有用的 QS 应用的第一步。考虑到可能结合不同类型的 QS 数据以提供增值服务的潜在应用数量众多，使用户能够为每个应用定义访问控制策略成为一项挑战。理解用户对易用机制的需求至关重要；否则，用户最终将不会使用细粒度的访问控制策略。
