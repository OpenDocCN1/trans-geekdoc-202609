
# 内部威胁检测

内部威胁表现为与规范子结构的微小百分比差异。这是因为内部威胁试图紧密模仿合法的系统操作，仅在由非法行为所体现的微小变化上有所不同。我们应用三种不同的方法来识别此类异常，具体讨论如下。

## 9.3.4.1 GBAD-MDL

在找到最佳压缩规范子结构后，`GBAD-MDL` 会在后续子结构中搜索与该规范子结构的偏差。通过分析与规范子结构大小相同的子结构，识别出边和顶点标签的差异，以及边的方向或端点的差异。其中最异常的是那些只需最少修改即可生成与规范子结构同构的子结构的子结构。在图 9.3 中，标记为 `E` 的阴影顶点是由 `GBAD-MDL` 发现的异常。

## 9.3.4.2 GBAD-P

相比之下，`GBAD-P` 搜索那些如果被删除，将产生规范子结构的插入。对图所做的插入被视为规范子结构的扩展。`GBAD-P` 基于边和顶点标签计算每个扩展的概率，因此利用标签信息来发现异常。概率由下式给出：

$$P(A=v) = P(A=v|A)P(A) \tag{9.4}$$

其中 `A` 表示边或顶点属性，`v` 表示其值。概率 `P(A = v | A)` 可由高斯分布生成：

$$\rho(x) = \frac{1}{\sigma\sqrt{2\pi}}\exp\left( {- \frac{(x - \mu)^{2}}{2\sigma^{2}}} \right) \tag{9.5}$$

其中 `µ` 为均值，`σ` 为标准差。`ρ(x)` 值越高对应越异常的子结构。

因此，使用 `GBAD-P` 可确保由图中实际数据（而非仅其结构）所反映的恶意内部人员行为，能被我们的算法可靠地识别为异常。在图 9.3 中，标记为 `C` 的阴影顶点是由 `GBAD-P` 发现的异常。

## 9.3.4.3 GBAD-MPS

最后，`GBAD-MPS` 考虑那些如果被重新插入，将产生规范子结构的删除操作。为发现这些操作，`GBAD-MPS` 会检查父结构。父结构中大小和方向的变化意味着子图中存在删除。最异常的子结构是那些使父子结构变得相同所需转换代价最小的子结构。在图 9.3 中，`A-B-C-D` 顶点的最后一个子结构被 `GBAD-MPS` 识别为异常，因为由阴影矩形标记的 `B` 和 `D` 之间缺少一条边。

## 9.4 序列数据的内部威胁检测

### 9.4.1 序列数据分类

由于序列的长度定义为有序元素的数量，序列数据的长度可以是有限的，也可以是无限的。无限序列称为流序列数据。与内部威胁检测相关的序列数据本质上是基于流的。序列数据可能随时间收集，甚至持续数年。在这种情况下，我们假设数据流将被转换为若干个块。例如，每个块可能代表一周，并包含该时间段内到达的序列数据。

[图 9.4](#ch09.xhtml#fig9_4a) 演示了分类器决策边界如何随时间变化（从一个块到下一个块）。数据点与两个类别（正常和异常）相关联。特别是，用户命令或命令子序列可能形成一种模式/短语，此处将其称为数据点。用户的非重复模式/短语可能形成异常。如图 9.4 所示，有三个连续的数据块。深色实线代表其自身块的决策边界，而虚线代表前一个块的决策边界。如果数据流中不存在概念漂移，当前块及其前一个块的决策边界将相同（虚线和实线重合）。白点代表正常数据（真阴性），蓝点代表异常数据（真阳性），条纹点代表概念漂移的受害实例。

![图 9.4 流数据中的概念漂移。](images/fig9_4.jpg)

[图 9.4 流数据中的概念漂移。](#ch09.xhtml#Ffig9_4)

图 9.4 中展示的两种不同情况如下：

1.  **情况 1。** 第二个块的决策边界相对于第一个块向上移动。结果，第一个块的决策边界会将更多正常数据分类为异常，因此 FP（假阳性）会上升。回顾一下，真实类别为良性（正常）的测试点被分类器分类为异常，称为 FP。

2.  **情况 2。** 第三个块的决策边界相对于第一个块向下移动。因此，第一个块的决策边界会将更多异常数据分类为正常数据，因此 FN（假阴性）会上升。回顾一下，真实类别为恶意的测试点被分类器分类为良性，称为 FN。

在更一般的情况下，当前块的决策边界可能会发生变化，导致前一个块的决策边界同时错误分类正常和异常数据。因此，FP 和 FN 可能同时上升。

这表明基于单个块构建的模型将不再足够。这促使我们采用自适应学习。具体而言，我们将利用两种方法：

#### 9.4.1.1 增量学习

维护单个字典 [PARV2012a]。当从一个块中学习到规范序列模式时，它将被简单地添加到字典中。为寻找规范模式，我们将利用无监督基于流的序列学习（`USSL`）。增量学习分类过程如 [图 9.5](#ch09.xhtml#fig9_5a) 所示。首先，从新块中提取模式，随后将这些模式与来自前几个块的旧量化字典合并。最后，对新的合并字典进行量化（[图 9.6](#ch09.xhtml#fig9_6a)）。

#### 9.4.1.2 集成学习

维护多个字典 [PARV2012b]。在集成中，我们维护 `K` 个模型。对于每个模型，我们维护单个字典。我们的集成方法使用一组不断演进的 `K` 个模型对数据进行分类。集成分类过程如 [图 9.7](#ch09.xhtml#fig9_7a) 所示。回顾一下，我们使用无监督基于流的序列学习（`USSL`）从单个块训练模型。`USSL` 识别块中的规范模式并将其存储在量化字典中。文献 [MASU2008, MASU2010a, MASU2011a] 表明，基于集成的学习比增量学习更有效。在此，我们将重点关注基于集成的学习。为识别异常，测试点将与集成中的每个模型进行比较。
