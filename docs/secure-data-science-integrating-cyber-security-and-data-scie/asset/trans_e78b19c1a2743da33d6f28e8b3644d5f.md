

## 4.4.2 XML、RDF 和本体安全

已有多项关于 XML 安全的研究工作被报道（参见例如 [[BERT2002](#ch04.xhtml#ref4_10)]）。我们简要讨论一些关键点。主要挑战在于：是授予对所有 XML 文档的访问权限，还是仅授予对文档部分内容的访问权限。Bertino 等人开发了用于 XML 的授权模型。他们专注于访问控制策略以及传播策略。他们还考虑了推送和拉取架构。他们使用 XML 来指定策略。策略规范包含有关哪些用户可以访问文档的哪些部分的信息。在 [[BERT2002](#ch04.xhtml#ref4_10)] 中，提出了访问控制算法以及计算结果视图的算法。此外，还讨论了保护 XML 文档的架构。在 [[BERT2004](#ch04.xhtml#ref4_11)] 和 [[BHAT2004](#ch04.xhtml#ref4_12)] 中，作者进一步阐述了如何在 Web 上发布 XML 文档。其思路是：所有者发布文档，主体请求访问文档，而不受信任的发布者向主体提供其被授权查看的文档视图。W3C 正在制定 XML 安全标准。XML 安全项目专注于提供 XML 安全标准的实现。重点在于 XML 签名语法与处理、XML 加密语法与处理以及 XML 密钥管理。虽然标准侧重于近期可实现的内容，但保护 XML 文档仍需要大量研究（另见 [[SHE2009](#ch04.xhtml#ref4_59)]）。

### 4.4.2.2 RDF 安全

RDF 是语义 Web 的基础。虽然 XML 在提供机器可理解文档方面存在局限，但 RDF 克服了这一局限。因此，RDF 为互操作性以及搜索和编目提供了更好的支持。它还描述文档的内容以及文档中各实体之间的关系。虽然 XML 提供语法和符号，但 RDF 通过以标准化方式提供语义信息来补充这一点 [[ANTO2008](#ch04.xhtml#ref4_?)]。

基本 RDF 模型有三个组成部分：资源、属性和陈述。资源是由 RDF 表达式描述的任何事物。它可以是一个网页或页面集合。属性是用于描述资源的特定属性。RDF 陈述是资源连同一个命名属性及该属性的值。陈述组件包括主语、谓语和宾语。因此，例如，如果我们有一句 "John is the creator of xxx"（John 是 xxx 的创建者）形式的句子，那么 xxx 是主语或资源，属性或谓语是 "creator"，宾语或字面值是 "John"。有非常类似于实体关系图或对象图的 RDF 图来表示陈述。重要的是必须对 RDF 句子使用预期的解释。这通过 RDF 模式来实现。模式是一种字典，包含句子中所用各术语的解释。

RDF 中更高级的概念包括容器模型和关于陈述的陈述。容器模型有三种容器对象：包、序列和替代。包是资源或字面值的无序列表。它用于表示一个属性有多个值但顺序不重要。序列是有序资源的列表。这里顺序很重要。替代是表示属性值的备选项的资源列表。各种 RDF 教程更详细地描述了容器的语法。RDF 还支持对其他陈述进行陈述。例如，利用此功能可以进行 "The statement A is false"（陈述 A 为假）形式的陈述，其中 A 是陈述 "John is the creator of X"。同样，可以使用类对象图来表示容器和关于陈述的陈述。RDF 还有一个与之关联的形式化模型。该形式化模型具有形式化语法。访问 RDF 文档的查询语言是 `SPARQL`。有关 RDF 的更多信息，请参阅 Antoniou 和 van Harmelen 所著书籍中的精彩讨论 [[ANTO2008](#ch04.xhtml#ref4_?)]。

现在，要使语义 Web 安全，我们需要确保 RDF 文档是安全的。这将涉及从语法角度保护 XML。然而，对于 RDF，我们还需要确保在语义层面保持安全。问题包括资源、属性和陈述概念的安全含义。即：如何确保访问控制？如何保护关于陈述的陈述和属性？如何在更细的粒度上提供访问控制？容器模型的安全属性是什么？如何保护包、列表和替代？我们能否用 RDF 指定安全策略？如何解决策略的语义不一致性？关于陈述的陈述有什么安全含义？如何保护 RDF 模式？这些都是困难的问题，我们需要开始研究以提供答案。XML 安全只是开始。保护 RDF 要困难得多（另见 [[CARM2004](#ch04.xhtml#ref4_16)]）。

### 4.4.2.3 安全与本体

本体本质上是各种概念的表示，旨在避免歧义。已经开发了大量本体。这些本体已被代理用于理解网页并执行数据库集成等操作。此外，本体可以用 RDF 或特殊语言（如 Web 本体语言 `OWL`）表示。现在，本体必须是安全的。即，必须控制对本体的访问。这意味着不同用户可能访问本体的不同部分。另一方面，本体可用于指定安全策略，就像 XML 和 RDF 被用于指定策略一样。即，我们将描述如何保护本体，以及如何使用本体来指定各种策略。

### 4.4.2.4 安全查询与规则处理

安全 RDF 层之上的层是安全查询与规则处理层。虽然 RDF 可用于指定安全策略（参见例如 [[CARM2004](#ch04.xhtml#ref4_16)]），但 W3C 开发的 Web 规则语言在指定复杂策略方面更强大。此外，还开发了用于处理和推理规则的推理引擎（例如马里兰大学开发的 Pellet 引擎）。可以将我们开发的数据库推理控制器的思想（参见 [[THUR1993](#ch04.xhtml#ref4_63)]）与 Web 规则处理相结合，为语义 Web 开发推理或隐私控制器。查询处理模块负责访问语义 Web 上异构的数据和信息源。研究人员正在研究将 Web 查询处理技术与语义 Web 技术相结合的方法，以定位、查询和集成异构的数据和信息源。
