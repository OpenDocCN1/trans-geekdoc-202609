

[图 18.18](#ch18.xhtml#fig18_18a) 中的溯源图展示了一个工作流，该工作流更新了一位在医院经历三个医疗阶段的患者的虚构记录。在第一阶段，医生对患者进行了检查。检查期间，医生查阅了患者记录中的病史 `med:Doc1_1`，并执行了记录患者笔记的任务。检查结束时，医生更新了患者记录，生成了一个更新版本 `med:Doc1_2`。在第二阶段，应医生要求，患者返回进行随访。在此次就诊中，医生查阅患者记录以回顾病史，随后对患者进行了一系列检查。此次就诊结束时，医生再次更新患者记录，生成了更新版本 `med:Doc1_3`。在第三阶段，患者返回接受心脏手术。此手术由患者主治医师下令，由住院医师实施。手术开始前，主治医师和外科医生均对患者记录进行了仔细审查。手术过程中，外科医生执行了记录心脏手术各阶段结果的任务。手术结束时，外科医生更新了患者记录，生成了更新版本 `med:Doc1_4`。

我们假设医院有一套标准程序，管辖医院提供的每一项医疗服务。因此，每位需要使用医疗服务的患者都必须经历这套程序。我们在图 18.18 中使用一组固定的符号来表示溯源图中的实体，例如：

`<med:Checkup_n_1>`

其中“n”表示在医院接受特定程序的特定患者。因此，`n = 1` 标识 ID 为 1 的患者，`n = 2` 标识 ID 为 2 的患者，依此类推。每个过程、代理和工件后缀中的较大数字表示该特定溯源实体在医疗程序的后期阶段被使用。在实践中，“n”将用实际患者 ID 实例化；这将为 ID = 1 的患者在第 1 阶段产生以下 RDF 三元组集合：

```
<med:Checkup_1_1><opm:WasControlledBy><med:Physician_1_1>
<med:Checkup_1_1><opm:Used><med:Doc_1_1>
<med:Doc_1_2><opm:WasDerivedFrom><med:Doc_1_1>
<med:Doc_1_2><opm:WasGeneratedBy><med:Notes_1_1>
<med:Notes_1_1><opm:WasControlledBy><med:Physician_1_1>
```

浅色阴影箭头上的 `sameAs` 注解旨在说明：对医生的引用意指在所有三个阶段中均为同一人。

这并非溯源图的完整图景；它还将进一步用 RDF 三元组进行注解，以指示位置、时间和其他上下文信息等。图中的每个实体将根据其类型拥有一组唯一的 RDF 注解。[表 18.2](#ch18.xhtml#table18_2a) 显示了每种溯源实体类型兼容的一组注解。将这些注解用于 ID = 1 的患者相关医生的 RDF 表示示例如下：

### 18.8.1 工作流中的语义关联

我们识别出多种语义关联，例如：如果 X 是更新患者 Y 记录的心脏外科医生，则患者 Y 的程序和药物与心脏手术相关。这将允许查询用户在查询 Y、X 以及 Y 的溯源记录中 X 和 Y 位于同一路径上的情况后，确定 Y 的疾病。

## 18.9 实现约束

约束通常是规则，但也可能包含附加条件。这些条件可能规定应用规则的情形（例如，某些时间或位置标准）。

我们的方法之一是使用正则表达式来编写约束。因此，我们可以通过正则表达式指定规则的左侧（LHS），以便在溯源图中存在某种模式时强制执行约束。我们研究了以下约束处理方法。我们将讨论查询修改过程。

*   DL 概念
*   查询实现
*   SWRL 规则
*   图文法/图重写

### 18.9.1 用于强制执行约束的查询修改

我们提出了两种修改 SPARQL 查询中图模式的方法。这些方法使用 SPARQL 过滤器和属性函数。为了根据安全类型（或标签）确定三元组的类型，推理引擎将使用领域本体来确定三元组主语或对象中找到的每个数据项的概念，或 TBox 中找到的属性的分类。然而，当三元组模式仅包含变量和字面量时，此方法会失效。我们假设图模式中任何三元组的主语、谓语或宾语均为 URI。可以为三元组宾语中出现的各种字面量的安全类型确定做出特殊规定；例如，识别九位数的 SSN 或十六位数的信用卡号。

#### 18.9.1.1 查询过滤器

图模式匹配产生一个解序列，其中每个解包含一组变量到 RDF 术语的绑定。SPARQL FILTER 将解限制为使过滤器表达式评估为 TRUE 的那些。SPARQL 规范 [PRUD2006] 提供了修改图模式的不同技术。

*   **SPARQL FILTER 可使用 regex 限制字符串的值。**

    ```
    PREFIX dc: <http://purl.org/dc/elements/1.1/>
    SELECT ?title
    WHERE { ?x dc:title ?title
    FILTER regex(?title, "^SPARQL")
    }
    ```

*   **SPARQL FILTER 可限制算术表达式。**

    ```
    PREFIX dc: <http://purl.org/dc/elements/1.1/>
    PREFIX ns: <http://example.org/ns#>
    SELECT ?title ?price
    WHERE { ?x ns:price ?price.
    FILTER (?price < 30.5)
    ?x dc:title ?title. }
    ```

*   可选模式匹配中的约束，例如。

    ```
    PREFIX dc: <http://purl.org/dc/elements/1.1/>
    PREFIX ns: <http://example.org/ns#>
    SELECT ?title ?price
    WHERE { ?x dc:title ?title.
    OPTIONAL { ?x ns:price ?price. FILTER (?price < 30) }
    }
    ```

## 18.10 下一代推理控制器

社交媒体数据以及高度链接的数据均可表示为 RDF 图。因此，前几节提出的思想适用于此类社交图。安全策略也可表示为 RDF 或 SWRL 等语言。这些策略包括访问控制策略和信息共享策略。例如，如果一个人透露了其宗教信仰，则其政治倾向会被推断出来。因此，如果一个人想保持其政治倾向私密，则不应在其社交媒体网站上发布其宗教信仰。
