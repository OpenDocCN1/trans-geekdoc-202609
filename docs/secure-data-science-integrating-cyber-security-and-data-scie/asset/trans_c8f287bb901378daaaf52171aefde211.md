
# 一些用于网页浏览的近期高级预测方法

一些用于网页浏览的近期高级预测方法是利用马尔可夫模型开发的 [[PIRO1996](#ch03.xhtml#ref3_17), [YANG2001](#ch03.xhtml#ref3_28)]。对于这些预测模型，浏览者访问的网页序列通常被视为马尔可夫链，并作为输入提供。马尔可夫模型的基本概念是：它根据前一个动作或前几个动作的结果来预测下一个动作。对于不同的应用，动作可能意味着不同的事物。为了便于说明，我们将考虑特定于 WWW 预测应用的动作。在 WWW 预测中，下一个动作对应于预测下一个将被遍历的页面。前一个动作对应于要考虑的前几个网页。根据所考虑的前一个动作的数量，马尔可夫模型可以有不同的阶数。在下文中，我们将展示不同阶数马尔可夫模型的说明性示例及其预测方式。

## 3.2.4.1 示例

假设一个包含六个网页的网站：`P1`、`P2`、`P3`、`P4`、`P5` 和 `P6`。假设我们有如[表 3.1](#ch03.xhtml#table3_1a)所示的用户会话。表 3.1 描绘了该网站许多用户的导航路径。[图 3.9](#ch03.xhtml#fig3_9a) 展示了*一阶马尔可夫模型*，其中下一个动作的预测仅基于用户执行的最后一个动作，即最后遍历的页面。状态 `S` 和 `F` 分别对应初始状态和最终状态。每次转移的概率通过状态序列被遍历的次数与锚定状态被访问的次数之比来估算。在图 3.9 的每个弧旁，第一个数字是该转移的频次，第二个数字是转移概率。例如，转移（`P2` 到 `P3`）的转移概率为 0.2，因为用户从页面 2 遍历到页面 3 的次数是 3 次，而页面 2 被访问的次数是 15 次（即 0.2 = 3/15）。

### 表 3.1 用户会话集合及其频次

| 会话 | 频次 |
| --- | --- |
| P1, P2, P4 | 5 |
| P1, P2, P6 | 1 |
| P5, P2, P6 | 6 |
| P5, P2, P3 | 3 |

![图 3.9 一阶马尔可夫模型。](images/fig3_9.jpg)

[图 3.9 一阶马尔可夫模型。](#ch03.xhtml#Ffig3_9)

请注意，转移概率用于解析预测。例如，已知用户访问了 `P2`，则她下一步最可能访问的页面是 `P6`。这是因为从 `P2` 到 `P6` 的转移概率最高。

请注意，某些页面的转移概率可能不可用。例如，从 `P2` 到 `P5` 的转移概率不可用，因为没有用户在访问 `P2` 后访问 `P5`。因此，这些转移概率被设为零。类似地，`K^(th)` 阶马尔可夫模型是在考虑用户执行的最后 `K^(th)` 个动作后计算预测。在 WWW 预测中，`K^(th)` 阶马尔可夫模型是指在给定用户前 `k-1` 个页面访问的情况下，用户访问第 `P[k]^(th)` 个页面的概率。

[图 3.10](#ch03.xhtml#fig3_10a) 展示了对应于表 3.1 的二阶马尔可夫模型。在二阶模型中，我们考虑最后两个页面。转移概率的计算方式类似。例如，从状态（`P1`、`P2`）到状态（`P2`、`P6`）的转移概率为 0.16 = 1 × 1/6，因为用户从状态（`P1`、`P2`）遍历到状态（`P2`、`P6`）的次数是 1 次，而页面（`P1`、`P2`）被访问的次数是 6 次（即 0.16 = 1/6）。转移概率用于预测。例如，已知用户访问了 `P1` 和 `P2`，她最可能访问 `P4`，因为从状态（`P1`、`P2`）到状态（`P2`、`P4`）的转移概率大于从状态（`P1`、`P2`）到状态（`P2`、`P6`）的转移概率。马尔可夫模型的阶数与滑动窗口有关。`K^(th)` 阶马尔可夫模型对应大小为 `K-1` 的滑动窗口。

## 3.2.5 关联规则挖掘 (ARM)

关联规则挖掘是一种数据挖掘技术，已成功应用于发现相关事务。关联规则技术基于项集在事务中的共现来发现它们之间的关系。具体而言，关联规则挖掘发现这些项集中的频繁模式（规律）。例如，超市中哪些商品是一起购买的？在下文中，我们简要介绍 ARM。更多详情请参见 [[AGRA1993](#ch03.xhtml#ref3_1)] 和 [[AGRA1994](#ch03.xhtml#ref3_2)]。有几种高效的算法被提出用于寻找关联规则，例如 `AIS 算法` [[AGRA1993](#ch03.xhtml#ref3_1), [AGRA1994](#ch03.xhtml#ref3_2)]、`SETM 算法` [[HOUT1995](#ch03.xhtml#ref3_10)] 和 `AprioriTid` [[LIU1999](#ch03.xhtml#ref3_12)]。

在 Web 事务的情况下，我们使用关联规则来发现用户间的导航模式。这将有助于提前缓存页面并减少页面加载时间。此外，发现导航模式有助于实现个性化。事务是从 Web 服务器日志中捕获的点击流数据中获取的。

在许多应用中，使用 ARM 存在一个主要问题。首先，使用全局最小支持度（`minsup`）存在问题，因为罕见点击，即很少被访问的网页，将不会被包含在频繁项集中，因为它无法获得足够的支持度。一种解决方案是设置一个非常小的支持度阈值；然而，我们将最终得到非常大的频繁项集，这在计算上很难处理。Liu 等人 [[LIU1999](#ch03.xhtml#ref3_12)] 提出了一种挖掘技术，为不同的项使用不同的支持度阈值。指定多个阈值允许将可能非常重要的罕见事务包含在频繁项集中。根据应用本身，可能会出现其他问题。例如，在 WWW 预测的情况下，会为每个用户记录一个会话。会话可能包含数十个点击流（有时甚至数百个，取决于会话时长）。将每个会话作为一个事务使用行不通，因为很少能找到两个频繁重复（即完全相同）的会话；因此，即使是非常高的支持度阈值 `minsup` 也无法达到。需要将每个会话分解为许多子序列。Mobasher 等人 [[MOBA2001](#ch03.xhtml#ref3_16)] 提出了一种推荐引擎，将活跃用户会话与数据库中的频繁项集进行匹配，并预测用户最可能访问的下一个页面。

## 3.2.6 决策树

顾名思义，决策本质上是一棵由不同类型节点组成的树：根节点、中间节点和叶节点。在每个根节点或中间节点处提出一个问题，根据答案选择一个分支。当到达所有叶节点时，过程结束。问题可以是“性别是男性还是女性”这种形式，也可以是“年龄是否大于 50”这种形式。挑战在于选择合适的特征，如性别和年龄。训练数据用于训练模型，随后模型在测试数据上进行测试。

人们可能会问，构建决策树的挑战是什么？主要挑战之一是确定何时停止分裂树。过去几十年来，开发了多种算法，以不同的方式构建树。在本书的[第 III 部分](#part_03.xhtml#part3)中，我们将考虑一种这样的决策树并探讨隐私方面的问题。更多详情请参见 [[HAN2000](#ch03.xhtml#ref3_9)]。
