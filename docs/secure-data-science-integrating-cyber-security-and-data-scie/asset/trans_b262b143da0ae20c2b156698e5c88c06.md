
在 [[ABAD2009b](#ch15.xhtml#ref15_3)] 和 [ABAD2007] 中，研究人员报告了一种用于 RDF 数据存储和检索的垂直分区 DBMS。他们的解决方案是一种模式，为每个谓词使用一张两列的表。然后，他们的模式在列式关系数据库（如 CStore [[STON2005](#ch15.xhtml#ref15_46)] 或 MonetDB [BONC06]）之上实现。他们观察到，与传统的关系数据库模式相比，他们的方案提升了性能。我们在 MapReduce 框架内的基于谓词的分区中利用了这项技术。然而，在垂直分区研究中，仅使用了小型数据库（<1亿）。有几篇论文 [[SIDI2008](#ch15.xhtml#ref15_43), [MCGL2009](#ch15.xhtml#ref15_31), [WEIS2008](#ch15.xhtml#ref15_57)] 表明，随着数据集规模的增加，垂直分区的性能会大幅下降。

Jena [CARR2004] 是一个用于 Jena 的语义 Web 框架。忠实于其框架设计，它允许集成多种持久化解决案。它还支持通过开发推理器进行推理。然而，Jena 仅限于三元组存储模式。换句话说，所有数据都存储在一张单一的三列表中。Jena 对大型数据集的查询性能非常差。此外，对数据集的任何更改都需要对推理三元组进行完全重新计算。

BigOWLIM [KIRY2005] 是目前可用的最快、最具可扩展性的语义 Web 框架之一。然而，它的可扩展性不如我们的框架，且需要非常高端且昂贵的机器。它需要昂贵的硬件（大量主内存）来加载大型数据集，且加载时间很长。正如我们的实验所示，当查询中没有绑定对象时，它的表现不佳。然而，我们的框架在这种情况下性能不受影响。

RDF-3X [NEUM2008] 被认为是现有最快的语义 Web 存储库。换句话说，它拥有最快的查询时间。RDF-3X 使用直方图、汇总统计和查询优化来实现高性能语义 Web 查询。因此，RDF-3X 通常能在带有绑定对象的查询和聚合查询上胜过任何其他解决方案。然而，RDF-3X 的性能对于非绑定查询会呈指数级下降，对于选择性因子低的甚至简单的连接查询也是如此。这对于推理查询变得越来越相关，因为推理查询通常需要带有非绑定对象的子查询的并集。我们的实验表明，RDF-3X 不仅在这类查询上较慢，而且经常中止且无法完成查询。例如，考虑一个简单的查询“选择所有学生”。在 LUBM 中，该查询要求我们选择所有研究生、选择所有本科生，并将结果合并。然而，该并集包含大量结果。虽然两个子查询都能轻松完成，但在拥有 33 亿三元组的 LUBM (30,000) 上，RDF-3X 的并集操作会中止。

RDF 知识库 (RDFKB) [[MCGL2010](#ch15.xhtml#ref15_32)] 是一种使用基于位向量的关系数据库模式构建的语义 Web 存储库。RDFKB 实现了比 RDF-3X 或垂直分区更好的查询性能。然而，RDFKB 旨在提供知识库功能，如推理正向链接、不确定性推理和本体对齐。RDFKB 将这些目标置于可扩展性之前。RDFKB 无法加载拥有 30 亿三元组的 LUBM (30,000)，因此在可扩展性方面无法与我们的解决方案竞争。

Hexastore [WEIS08] 和 BitMat [[ATRE2008](#ch15.xhtml#ref15_5)] 是针对 RDF 索引优化的主内存数据结构。这些解决方案在热运行中可能实现卓越的性能，但它们未针对从持久化存储进行的冷运行进行优化。此外，它们的可扩展性直接与可用的主内存 RAM 数量相关。这些产品不可用于测试和评估。

在我们之前的工作 [[HUSA2009](#ch15.xhtml#ref15_22), [HUSA2010](#ch15.xhtml#ref15_23)] 中，我们提出了一种贪心算法和一种穷举搜索算法来生成查询处理计划。然而，穷举搜索算法开销大，而贪心算法无界限且其理论复杂度未定义。在本章中，我们提出了一种新的带有上界的贪心算法。此外，我们确实观察到旧贪心算法无法生成最优计划的场景。新算法能够在每种此类情况下获得最优计划。Join Executer 组件使用 MapReduce 框架运行作业。然后它将查询答案从 Hadoop 传回给用户。

### 15.4.1 数据生成与存储

在我们的实验中，我们使用 LUBM [[GUO2005](#ch15.xhtml#ref15_19)] 数据集。它是一个基准数据集，旨在使研究人员能够评估语义 Web 存储库的性能 [[GUO2004](#ch15.xhtml#ref15_18)]。LUBM 数据生成器以 RDF/XML 序列化格式生成数据。这种格式不适合我们的目的，因为我们将数据作为平面文件存储在 HDFS 中，因此即使检索单个三元组，也需要解析整个文件。因此，我们将数据转换为 N-triples 以存储数据，因为采用该格式，一个文件的一行就包含一个完整的 RDF 三元组（主语、谓语和宾语），这非常方便与 MapReduce 作业配合使用。为将数据转换为我们预期格式所需的处理步骤将在以下章节中描述。

### 15.4.2 文件组织
