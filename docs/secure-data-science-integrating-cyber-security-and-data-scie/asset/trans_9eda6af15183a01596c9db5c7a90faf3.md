

# 18.6.2.1 填充溯源知识库

溯源知识库通过一组生成器进行更新。其中有后台生成器，负责提取通常可在线获取的背景信息。还有一个工作流生成器，用于生成实际的溯源信息。工作流生成器产生的合成溯源数据在网上是不可用的。正是这些溯源数据包含我们必须保护的子集。我们通过提取与医疗领域相关的信息来填充溯源存储。医疗领域在两方面具有适用性。首先，该领域实际记录溯源信息；其次，该领域的数据部分可在线获取 [[KIFO2006](#ch18.xhtml#ref18_18)]。

# 18.6.2.2 生成并填充知识库

我们创建一组种子，包含名、姓、州和城市。每个种子用于创建一个查询，该查询针对 [http://www.yellowpages.com/](http://www.yellowpages.com) 或 [http://www.whitepages.com/](http://www.whitepages.com) 网站发起。这些网站可通过搜索词定位企业和个人。为了从这些网站提取信息，我们使用了网络爬虫服务。网络爬虫是一种计算机程序，它以有条不紊、自动化的方式或有序的方式浏览万维网。网络爬虫有时被称为自动索引器、机器人、蚂蚁、收割器、网络蜘蛛、网络机器人或网络刮取器。这些爬虫是遵循万维网链接结构并在访问的网页上执行某些任务的计算机程序。

爬取匹配我们初始查询种子的页面后，我们以适当的格式将结果存储在文本文件中。由于此过程开销较大，我们在离线状态下构建所有网络爬取程序，并在实验阶段的测试周期中将文本文件内容加载到内存中。第一次爬取收集我们假设的患者列表。我们利用患者的邮政编码创建查询，以搜索医院、医生及其专业。这些搜索的结果也存储在具有预定格式的文本文件中。这些预定格式的文本文件使我们能够为人员、医院、医生和护士等实体构建带有属性的对象类。

# 18.6.2.3 生成工作流

对于我们玩具知识库中的每位患者，我们启动更新该患者记录的工作流。记录的溯源信息是我们在系统中假设的唯一机密数据。其目的是让查询用户有机会推断与记录相关的患者疾病、药物或检查。溯源数据比传统数据库更有趣，因为控制器不仅要预测涉及用户先验知识的推理，还要预测与溯源数据对象之间因果关系相关的推理。

# 18.6.2.4 工作流的属性

我们观察到所生成工作流的几个属性：

*   我们的溯源工作流使用 `OPM toolbox` [[OPEN](#ch18.xhtml#ref18_24)] 生成。该工具箱通过使用 `V[G]^(P)` 中的谓词捕获工作流的骨架，其中

    `V[G]^(P) = {WasControlledBy, Used, WasDerivedFrom, WasGeneratedBy, WasTriggeredBy}`。

    也就是说，我们最初生成的工作流通常未使用与工作流实体相关的 RDF 三元组进行标注；例如，断言代理名称、地址或年龄的三元组。因此，我们避免了杂乱，使医疗程序更易于可视化。

*   我们工作流图 `G` 中的每个实体均可由 RDF 三元组标注，这些三元组对实体进行断言。我们的工作流通常以完整形式存储。即，我们通过将工作流转换为包含与工作流实体相对应的相关背景信息的形式，为每个工作流添加标注。

*   `G` 中的每个实体都具有从黄页 ([http://www.yellowpages.com](http://www.yellowpages.com)) 或白页 ([http://www.whitepages.com/](http://www.whitepages.com)) 网站派生的属性。这些属性属于用户背景知识的一部分。我们还为溯源图中的实体添加了其他虚构属性。这些虚构属性使我们能够扩展溯源图的规模和复杂度，从而获得关于系统可扩展性的一些实验数据。

*   工作流图 `G` 包含私有信息，即对患者记录执行的活动的溯源信息。这是我们的推理控制器所保护的信息。我们用于保护该信息的主要方法是语义网推理器中可用的推理服务以及作用于 `G` 的策略提供的。

# 18.6.3 策略管理

我们在设计中讨论了策略管理的几个方面。本节将重述部分信息。

## 18.6.3.1 策略界面

策略界面为用户提供选项，以加载策略并针对溯源图数据库执行。用户可选择执行任何类型的策略，例如默认策略（访问控制、编辑、DL 规则或编码为 SWRL 规则的策略）或其他策略类型。默认策略附带一组解析器，可将其转换为内部策略表示。只要提供合适的解析器将每种策略类型转换为内部表示，新策略类型即兼容。内部表示可以是任何作用于 RDF 图的技术，例如 `SPARQL query`、`DL` 或 `SRWL rule`。策略界面包含两个面板。左侧面板显示已加载但未生效的策略列表，右侧面板显示已加载且生效的策略列表。策略界面如 [图 18.6](#ch18.xhtml#fig18_6a) 所示。
