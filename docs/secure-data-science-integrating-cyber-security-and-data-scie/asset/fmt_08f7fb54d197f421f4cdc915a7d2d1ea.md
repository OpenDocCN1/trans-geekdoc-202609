# 6.2 恶意可执行文件

## 6.2.1 架构

[图 6.2](#ch06.xhtml#fig6_2a)展示了我们用于检测恶意可执行文件的架构。训练数据由一组良性和恶意可执行文件组成。我们从每个可执行文件中提取三种不同类型的特征（稍后解释）。这些提取的特征随后被分析，仅选择最具判别力的特征。利用选定的特征集，从每个训练实例生成特征向量。这些特征向量用于训练分类器。当需要测试新的可执行文件时，首先从中提取训练期间选定的特征，并生成特征向量。该特征向量通过分类器进行分类，以预测其是良性还是恶意可执行文件。

![Figure 6.2 Architecture.](images/fig6_2.jpg)

[Figure 6.2 Architecture.](#ch06.xhtml#Ffig6_2)

在我们的方法中，我们从可执行文件的不同抽象层级提取三种不同类型的特征，并将它们组合成一个称为**混合特征集（HFS）**的特征集。这些特征用于训练分类器（例如`支持向量机 (SVM)`、`决策树`等），并应用于检测恶意可执行文件。这三种特征分别是：(i) 二进制 `n-gram` 特征，(ii) 衍生汇编特征（DAF），(iii) 动态链接库（DLL）调用特征。每个二进制 `n-gram` 特征实际上是二进制可执行文件中 `n` 个连续字节的序列，使用[第 10 章](#ch10.xhtml#chapter10)中解释的技术提取。二进制 `n-gram` 揭示了良性和恶意可执行文件之间的区分字节模式。每个 DAF 是可执行文件中一条汇编指令序列，对应一个二进制 `n-gram` 特征。DAF 揭示了良性和恶意可执行文件之间独特的指令使用模式。它们通过我们的`汇编特征检索 (AFR)`算法从反汇编的可执行文件中提取。汇编 `n-gram` 特征未用于 HFS，因为我们的发现表明 DAF 表现优于它们。每个 DLL 调用特征实际对应可执行文件中的一个 DLL 函数调用，从可执行文件头中提取。这些特征揭示了良性和恶意可执行文件之间的区分 DLL 调用模式。我们通过实证表明，这三种特征的组合在分类准确率方面始终优于任何单一特征。

我们的工作侧重于扩展不同抽象层级的特征，而非在单一抽象层级使用更多特征。这主要有两个原因。首先，给定抽象层级（如二进制层级）的特征数量极其庞大。例如，在我们的较大数据集中，我们获得了 2 亿个二进制 `n-gram` 特征。使用如此大量的特征进行训练远超出了任何实用分类器的能力。因此，我们将给定抽象层级的特征数量限制在适用范围内。其次，我们通过实证观察到向组合特征集（即 HFS）添加更多抽象层级的益处。HFS 结合了三个抽象层级的特征：二进制可执行文件、汇编程序和系统应用程序编程接口（API）调用。我们证明，与任何单一抽象层级的特征相比，这种组合具有更高的检测准确率和更低的误报率。

我们的技术因以下几个原因与知识管理相关。首先，我们应用二进制 `n-gram` 特征的知识来获取 DAF。其次，我们应用从特征提取过程中获得的知识来选择最佳特征。这是通过从训练数据中提取所有可能的二进制 `n-gram`，应用与每个 `n-gram` 对应的统计知识（即其在恶意和良性可执行文件中的频率）来计算其`信息增益` [[MITC1997](#ch06.xhtml#ref6_14)]，并选择最好的 `S` 个来实现的。最后，我们应用从特征提取过程中获得的另一种统计知识（特征在可执行文件中的存在/不存在）来训练分类器。

我们的研究贡献如下。首先，我们提出并实现了 HFR（混合特征检索）模型，结合了上述三种特征。其次，我们应用一种新颖的想法，利用二进制 `n-gram` 特征提取汇编指令特征，并通过 AFR 算法实现。第三，我们提出并实现了一个可扩展的解决方案，用于解决一般的 `n-gram` 特征提取和选择问题。我们的解决方案在有限内存下工作良好，并通过应用高效强大的数据结构和算法显著减少了运行时间。因此，它可扩展到大量可执行文件集合（数千量级），即使在有限的主内存和处理器速度下。最后，我们将结果与 [KOLT2004] 的结果进行比较，后者仅使用二进制 `n-gram` 特征，并表明我们的方法获得了更好的准确性。我们还报告了我们方法与 [KOLT2004] 方法的性能/成本权衡。必须指出的是，我们的主要贡献是一种高效的特征提取技术，而非分类技术。我们通过实证证明，无论使用何种分类器（如 SVM/决策树），利用我们算法提取的组合特征集（即 HFS）均优于其他单独特征集（如二进制 `n-gram`）。
