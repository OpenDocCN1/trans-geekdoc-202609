# 9 用于内部威胁检测的流分析

DOI：[10.1201/9781003081845-14](https://doi.org/10.1201/9781003081845-14)

## 9.1 介绍

恶意内部人员或许是许多或大多数组织信息保障面临的最强大威胁 [[BRAC2004](#ch09.xhtml#ref9_7)，[HAMP1999](#ch09.xhtml#ref9_31)，[MATZ2004](#ch09.xhtml#ref9_60)，[SALE2011](#ch09.xhtml#ref9_74)]。解决内部威胁检测问题的一种传统方法是监督学习，它从训练数据构建数据分类模型。不幸的是，监督学习方法的训练过程往往耗时且昂贵，且通常需要大量平衡良好的训练数据才能有效。在我们的实验中，我们观察到该问题的现实数据集中，不到 3% 的数据与内部威胁（少数类）相关；超过 97% 的数据与非威胁（多数类）相关。因此，从这种不平衡数据训练的传统支持向量机 (SVM) [[CHAN2011](#ch09.xhtml#ref9_13)，[MANE2002](#ch09.xhtml#ref9_49)] 在测试数据集上可能表现不佳。

单类 SVM (OCSVM) [MANE2002] 通过构建仅考虑正常数据（即非威胁数据）的模型来解决稀有类别问题。在测试阶段，测试数据根据与模型的几何偏差被分类为正常或异常。然而，该方法仅适用于有界长度的静态数据流。相比之下，与内部威胁相关的数据通常是连续的，且威胁模式随时间演变。换句话说，数据是无界长度的流 [[CANG2006](#ch09.xhtml#ref9_10)]。因此，有效的分类模型必须具有自适应性（即能够应对不断演变的概念），并且必须高效，以便从大量不断演变的数据中构建模型。与内部威胁检测和分类相关的数据通常是连续的。在这些系统中，普通用户和内部威胁的模式可能会逐渐演变。新手程序员可以随着时间的推移发展技能成为专家程序员。内部威胁可以改变其行为，使其更接近合法用户进程。无论哪种情况，当直接相互比较时，这些发展两端的模式看起来可能截然不同。在我们的方法中，这些自然变化不会被视为异常。相反，我们将它们归类为自然概念漂移。传统的静态监督和无监督方法在这些情况下会产生不必要的误报，因为它们无法在系统中出现时处理这些情况。这些传统方法遇到高误报率。学习模型必须擅长应对不断演变的概念，并能高效地从大量数据构建模型，以快速检测真实威胁。基于这些原因，内部威胁问题可以被概念化为一个适用于连续数据流的流挖掘问题。无论使用监督还是无监督学习算法，所选方法都必须高度自适应，才能在这些条件下正确处理概念漂移。增量学习和基于集成的学习 [[ALKH2012a](#ch09.xhtml#ref9_2)，[ALKH2012b](#ch09.xhtml#ref9_3)，[KANG2011](#ch09.xhtml#ref9_40)，[MASU2008](#ch09.xhtml#ref9_50)，[MASU2009](#ch09.xhtml#ref9_51)，[MASU2010a](#ch09.xhtml#ref9_52)，[MASU2010b](#ch09.xhtml#ref9_53)，[MASU2011a](#ch09.xhtml#ref9_55)，[MASU2011b](#ch09.xhtml#ref9_56)，[MASU2011c](#ch09.xhtml#ref9_57)，[MASU2011d](#ch09.xhtml#ref9_58)，[MASU2013](#ch09.xhtml#ref9_59)] 是克服这一障碍的两种自适应方法。由 *K* 个模型组成的集成，通过集体投票决定最终分类，可以减少测试集的假阴性 (FN) 和假阳性 (FP)。随着新模型的创建和旧模型的更新以变得更精确，准确度最低的模型会被丢弃，以始终保持恰好 *K* 个当前模型的集成。监督学习的一种替代方法是无监督学习，它可以有效地应用于纯未标记数据——即没有数据点被明确标识为异常或非异常的数据。基于图的异常检测 (GBAD) 是无监督学习的一种重要形式 [[COOK2000](#ch09.xhtml#ref9_17)，[COOK2007](#ch09.xhtml#ref9_18)，[EBER2007](#ch09.xhtml#ref9_25)]，但传统上仅限于静态、有限长度的数据集。这限制了其在内部威胁相关流中的应用，后者往往具有无界长度且威胁模式随时间演变。因此，将 GBAD 应用于内部威胁问题要求所用模型具有自适应性和高效性。增加这些特性允许从大量不断演变的数据中构建有效模型。

我们将内部威胁检测视为一个流挖掘问题，并提出了两种方法（监督和无监督学习），用于高效检测流数据中的异常 [[PARV2013](#ch09.xhtml#ref9_71)]。为了应对概念演变，我们的监督方法维护一个不断演变的多个 OCSVM 模型集成 [[PARV2011a](#ch09.xhtml#ref9_67)]。我们的无监督方法将多个 GBAD 模型结合在一个分类器集成中 [[PARV2006](#ch09.xhtml#ref9_66)，[PARV2011b](#ch09.xhtml#ref9_68)]。在两种情况下，集成更新过程的设计都是为了随着流的演变保持集成的时效性。这种演变能力提高了分类器在合法和非法代理行为随时间变化时对概念漂移的生存能力。在实验中，我们使用记录大型基于 Unix 的多用户系统系统调用数据的测试数据 [[QUMR2013](#ch09.xhtml#ref9_72)]。
