

我们的数据共享高层设计由多个组件组成。第一个组件包含一个个人访问控制系统，支持对个人数据的访问控制策略进行规范和强制执行，以及不同策略的演进与合并，范围涵盖从基于事件的共享到个人为研究捐赠数据。访问控制系统还将包含一个创作工具。第二个组件是一个能够处理已清洗数据的数据挖掘系统。一个重要问题是评估从匿名数据集衍生出的数据挖掘模型的质量。更重要的是，必须确定是否以及如何利用每个用户的非匿名个人数据来优化基于大规模人群构建的数据挖掘模型，或者由这种公共数据挖掘系统获得的预测能否与本地数据挖掘系统获得的推荐相结合（即基于特定用户数据的本地数据挖掘系统）。目标是基于多用户的清洗数据创建全局数据挖掘模型，然后为每个特定用户个性化这些模型。

我们需要构建一个框架，在该框架中，来自不同来源的 QS 数据流将在本地进行分析。利用移动设备的计算能力，将计算个人的重要统计数据以及数据挖掘模型。此外，根据需要，将使用前面讨论的加密查询机制来检索云中存档的数据，以改进本地模型和统计数据。随后，这些模型和统计数据将根据用户注册的策略和事件进行共享。我们还需要开发基于云的安全分布式数据挖掘技术，以允许个人安全地捐赠和/或出售数据以满足各种数据挖掘需求。根据数据共享策略，将自动提交给数据挖掘模型的数据将被自动提取。在某些场景中，数据还将利用来自对等节点的信息进行聚合（即来自附近朋友的信息）。在某些情况下，在与基于云的服务共享之前，信息将通过添加噪声进行清洗（例如，利用基于随机响应的差分隐私技术 [ERLI2014]）。这些本地计算的信息将使用秘密分享技术 [[CRAM2000](#ch13.xhtml#ref13_13), [CRAM2003](#ch13.xhtml#ref13_14)] 与位于公共云上的多台服务器共享，并使用 Tor [DING2004] 等服务，使得将数据关联回特定个人变得更加困难。一旦数据通过秘密分享机制发送到多台服务器，服务器之间将执行基于秘密分享的安全协议，以构建人口层面的数据挖掘模型。为了扩展到大量用户，我们计划结合有效采样和随机响应技术，并结合基于秘密分享的安全多方计算思想。例如，我们可能希望结合特定子人群（例如，患有高血压的 65 岁以上人群）的用户数据来构建线性回归模型。如果用户 `i` 使用其数据向量 `x[i]` 参与系统，其中 1 ≤ `i` ≤ `n`，我们可以将数据挖掘过程写为线性回归函数 `f` 的安全多方评估：`f(I[C(x[1])].x[1], I[C(x[2])].x[2], …, I[C(x[n])].x[n])`，其中 `I[C(x[i])]` 是描述用户数据选择条件的指示函数。首先，既然这是一个数据挖掘模型，为了具有统计显著性，我们可能不需要获取所有样本。给定选择条件 `C`，我们可以估计满足条件 `C` 的用户数量 `t`，如果 `t` ≫ `s`，其中 `s` 是统计显著性所需的样本数量，那么我们可以以概率 `s/t` 从匹配该条件的用户群体中进行子采样，以减少在 SMC 阶段秘密分享的数据量。当然，在进行采样时，我们可能会泄露哪些用户匹配条件 `C`。为了防止这种情况，我们也可能希望从不满足条件 `C` 的用户中进行采样。采样率可以调整以平衡个人隐私保护与效率。一旦在此采样步骤后选定用户数据，可以使用噪声添加技术或与多台服务器的秘密分享技术将数据发送到基于云的基于秘密分享的 SMC 框架。在某些情况下，这些构建的模型将被发送回用户，以便在本地进行定制，从而提高其对用户的效用。

最后，为了从人因角度研究数据共享，我们需要采取多方法途径，即使用包括访谈、调查、实验室实验和众包实验在内的多种方法，在自然和受控环境中获取定性和定量数据 [PROC2007]。这些信息将用于确定智能默认值。我们需要利用我们在普渡大学接触各种用户群体的优势，并通过其信息保障与安全教育研究中心（CERIAS）合作伙伴，在与 QS 数据存储特定问题最相关的群体上开发和测试我们的界面设计概念。对于需要大量经验丰富的计算机用户样本的研究，我们将在 Amazon Mechanical Turk (MTurk) 上进行研究，以获取绩效指标以及调查和人口统计信息，就像我们在应用选择研究中所做的那样 [CHEN2014, GATE2014]。作为我们方法的第一阶段，我们将通过确定与 QS 数据存储相关的风险和收益（包括考虑可能产生这些风险的法律规则（如搜查令）或避免这些风险的法律规则（如《健康保险流通与责任法案》[HIPAA] 等法规中对某些数据处理实践的禁令））来识别与个人数据共享相关的人因问题。作为下一阶段，我们将确定典型用户是否意识到这些风险和收益，并认为它们是实质性的。第三阶段将是评估指定个人隐私策略所涉及的可用性问题。该阶段的核心重点将是关注在规范过程中以可理解的方式呈现策略信息的方法。我们不仅需要评估替代界面的可用性，还要评估用户是否准确理解其策略规范允许和不允许的内容。以下六项概述了需要探索的活动。

### 面向个人数据的风险感知访问控制系统

该系统将包含一个基于 XACML 标准扩展/定制的策略语言，用于策略规范；一个能够合并和演进访问控制策略的策略创作工具；以及一个策略执行引擎。此外，我们还将探索定量方法来分析和量化共享 QS 数据的风险，并根据现有风险自动调整策略。在我们过去的工作 [[BENS2014](#ch13.xhtml#ref13_7)] 中，我们在共享大型数据集的背景下探讨了基于风险的数据共享问题。我们需要将人类受试者实验中捕捉到的风险接受行为整合到定量模型中，以更好地解释现实生活中的行为。我们需要探索如何在 XACML 扩展的基础上构建基于事件的共享策略。此外，数据也必须是可信的 [[LIM2012](#ch13.xhtml#ref13_45)]。
