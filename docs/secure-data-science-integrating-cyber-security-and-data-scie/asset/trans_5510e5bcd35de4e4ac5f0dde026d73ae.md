
我们创建了一个数据生成器，用于生成 *n* 个节点。我们首先创建了一组 50 个节点，并生成了 50 条边，这些边随机分布在图中的 50 个节点上。然后我们选择一个至少有一个朋友的随机节点 *n*[*i*]，并执行 Dijkstra 算法以确定子图是否连通。如果子图不连通，则有 *j* 个节点无法从 *n*[*i*] 到达。我们随后选择 0 < *r*[*i*] ≤ *j* 作为要创建的新边的数量。对于每条边，我们从包含 *n*[*i*] 的连通子图中随机选择一个节点，并从断开连接的子图部分中选择一个目标节点。只要存在断开连接的子图部分，我们就继续生成边。通过这种方式执行子图连接，我们能够生成类社交网络图，同时保持随机性，而无需手工挑选哪些边之间会有链接。

此时需要注意的是，我们的数据存储将每个链接记录两次。尽管图是无向的，但存在一种链接类型（用于推理）是有向的。例如，虽然通用的“Friend”链接类型是双向的，但特定的“BestFriend”链接类型不一定是双向的。为了维护这一点，我们记录了链接的每个方向及其关联的链接类型。初始子图完成后，我们遍历节点为每条边分配一个链接类型。我们建立了三种通用链接类型：Friend、Family 和 Co-Worker，并为边的每个方向记录它们。也就是说，如果 (*n*[*i*], *n*[*j*]) ∈ ℰ 被分配了 Friend 链接类型，将生成元组 {*n*[*i*], *n*[*j*], Friend} 和 {*n*[*j*], *n*[*i*], Friend}。

我们为节点所属的每条边统一选择一种通用类型。之后，我们分配特定子类型。对于 10% 的 Friend 通用链接类型，我们分配了特定的（单向）链接类型 bestFriend。也就是说，在上述示例中，如果 *n*[*i*] 宣称 *n*[*j*] 为 bestFriend，则元组 {*n*[*i*], *n*[*j*], Friend} 将变为 {*n*[*i*], *n*[*j*], bestFriend}。请注意，此时第二个元组将保持不变。

接下来，我们对定义的 Family Members 数量使用 Pareto 分布来确定有多少关系会被定义为“ParentOf”。我们使用 Pareto 分布是因为虽然列出一两个父母是我们通常认为对孩子合理的，但在当今的混合家庭中，为一个孩子列出更多父母也并非不可信。还要注意的是，当链接被定义为 ParentOf 时，其对应的元组会自动被分配反向关系 ChildOf。也就是说，假设我们之前的示例是 {*n*[*i*], *n*[*j*], Family} 和 {*n*[*j*], *n*[*i*], Family}。如果确定 *n*[*i*] 是父母，在单个步骤中，我们将得到修正后的元组 {*n*[*i*], *n*[*j*], ParentOf} 和 {*n*[*j*], *n*[*i*], ChildOf}。

对于 Co-worker 通用链接类型，我们没有进一步定义特定链接类型。

对于每个节点，我们还定义了一个安全策略。为清晰起见，我们定义了三种安全策略，均匀随机选择：

1.  **Strict**：只有 BestFriends 和 Family 可以查看自己的照片和任何孩子的照片；他们的孩子不能查看任何视频。
2.  **Casual**：任何人都可以查看照片；对孩子无限制。
3.  **ParentStrict**：任何人都可以查看父母的照片，只有家人可以查看他们孩子的照片；孩子不能查看任何视频。

然后我们生成了 *m* 个资源，其中 *m* 是一个小于 450 万且大于 75 万的随机数，这应使我们能够对更活跃和更被动的社交网络进行建模。资源可以是照片或视频。我们将资源为照片的概率加权为 75%。然后我们从 1 到 25（含）的均匀分布中抽取，以表示照片中“标记”的人数。这个“标记”表示出现在照片中的人，我们将其视为在网络中对该照片拥有“利益”的个人。

这里有几点需要注意。首先，虽然我们的均匀分布可能不能反映 Facebook 等社交网站照片的真实概率模型，但包含拥有照片利益的大群体代表了此类网站更困难的推理问题。其次，我们不限制照片中被标记的人仅为照片所有者的朋友。因为此功能存在于当前的在线社交网络中，我们需要支持这种类型的标记。这种能力可以支持婚礼等活动的照片，拍照者可能只认识照片中一部分人，但查看照片的人可以提供关于其他被拍摄者的更多细节。我们还要指出，我们的方法生成的图中，每个人的平均好友数为 102 个用户（Facebook 平均好友数为 338 [https://www.onaverage.co.uk/other-averages/average-number-of-facebook-friends](https://www.onaverage.co.uk/other-averages/average-number-of-facebook-friends)）。

*   **Event Generation**：我们接下来生成了一系列事件，这些事件将被处理以检查使用基于语义 Web 的推理器进行社交网络访问控制的效果。我们将社交网络中可执行的完整动作集（如游戏、发帖、更改状态等）浓缩为最能影响推理器能力的动作：添加好友、访问现有资源、创建新资源和更改权限。创建用户、添加好友或创建新资源时，我们按前述方式执行任务。然而，在访问现有资源时，随机选择的用户尝试访问随机选择的资源。

*   **Experiments**：我们对推理器进行了两次独立实现。我们的第一个实现依赖于 SweetRules 推理引擎。我们尝试对整个数据集执行推理。以这种方式执行推理将初始模型加载到内存中花费了 17 小时，然后每个特定推理请求需要几秒钟。然而，我们注意到当我们的模型需要更新（通过新资源、好友或安全策略变更）时，这些变更未反映在我们的内存模型中。这导致后续推理变得越来越不正确。

因此，我们使用 Pellet 实现了一个推理解决方案，Pellet 已成为一个非常流行的推理器。最初，我们只是将使用的推理器更改为 Pellet。然而，在使用 Pellet 的初始加载步骤中，我们收到了内存溢出错误，无法继续进行推理阶段。我们随后决定需要为社交网络实施某种分区方案。一种简单的分区方法会导致某些友谊链接跨越分区。这些跨分区边会导致以下两种情况之一：

1.  **Reconstructing partitions**：假设分区 *P*[*i*] 有一个用户 *u*[*a*] 和 *n* 个朋友 *u*[1], …, *u*[*n*]，他们分别存储在分区 *P*[1], … *P*[*n*] 中。请记住，我们可以从 *Friends* 数据存储中确定 *u*[*a*] 的朋友是谁。然而，如果没有额外的索引，此能力无法帮助我们确定他们的朋友具体在哪个分区中。我们必须投入大量资源来重组特定分区，以便有效地推断访问权限。

2.  **Ignoring links**：另一种选择是简单地忽略通向另一个分区的任何友谊链接。这显然不是一个可行的选项，因为它显然会导致太多无效的访问请求。
