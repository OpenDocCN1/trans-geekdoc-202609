
# 16.2.2 开发 CAISS 的增强措施

我们正在增强为 AFOSR 开发的工具，包括 (i) 面向语义 Web 数据的安全云查询处理，以及 (ii) 基于语义 Web 的策略引擎，以开发 CAISS。我们工具的详细信息见 [第 16.4 节](#ch16.xhtml#sec16_4)（相关工作部分）。在本节中，我们将讨论为开发 CAISS 而对工具进行的增强。

首先，我们基于 RDF 的策略引擎可对表示为 RDF 图的数据强制执行访问控制、编辑和推理控制策略。其次，我们用于 RDF 数据的云 SPARQL 查询引擎使用 Hadoop/MapReduce 框架。请注意，Hadoop 是 Apache 分布式文件系统，而 MapReduce 运行在 Hadoop 之上并执行作业调度。与我们基于云的关系查询处理器原型 [THUR2010] 类似，我们的 SPARQL 查询引擎也处理用 XACML 指定的策略，且策略引擎实现了 XACML 协议。将 XACML 用作策略语言需要深入了解 XACML 设计中使用的通用概念。因此，XACML 策略编写需要陡峭的学习曲线，因而成为一项留给经验丰富的管理员的任务。使用 XACML 的第二个缺点与性能有关。目前的 XACML 实现要求针对系统中的每个策略评估访问请求，直到有策略适用于传入的请求。这种策略对于用户和策略相对较少的系统已足够。然而，对于拥有大量用户和大量访问请求的系统，上述策略会成为性能瓶颈。最后，XACML 的表达能力不足以捕捉信息共享策略的语义。先前的研究表明，基于语义 Web 的策略具有更强的表达能力。这是因为语义 Web 技术基于描述逻辑，具有表示知识和推理知识的能力。因此，我们的第一步是用基于语义 Web 的策略引擎替换基于 XACML 的策略引擎。由于我们已为第一阶段原型拥有基于 RDF 的策略引擎，我们将增强该引擎并将其与 SPARQL 查询处理器集成。由于我们的策略引擎基于 RDF，而查询处理器也管理大型 RDF 图，因此数据与策略之间不会存在阻抗失配。

## 16.2.2.1 增强的策略引擎

我们当前的策略引擎存在一个局限性，即它不在云环境中运行。因此，我们将把 RDF 策略引擎移植到云环境中，并将其与用于云中联合查询处理的 SPARQL 查询引擎集成。我们的策略引擎将受益于 Hadoop MapReduce 框架提供的可扩展性和分布式平台，以回答大型分布式 RDF 三元组存储（数十亿 RDF 三元组）上的 SPARQL 查询。使用 RDF 作为数据模型的原因如下：(1) RDF 使我们能够实现由各机构/组织分别编目的看似不同的信息源之间的数据互操作性。(2) 使用 RDF 允许参与机构创建以数据为中心的应用程序，利用现已可用的集成数据。(3) 由于 RDF 生成数据不需要显式模式，因此可以轻松适应不断变化的用户需求。策略引擎的灵活性基于其接受高层策略，并将其作为查询规则在数据的有向 RDF 图表示上执行。虽然我们之前的工作侧重于溯源数据和访问控制策略，但我们的 CAISS 原型将足够灵活，能够处理用 RDF 表示的数据，并将包含信息共享策略。我们策略引擎的优势在于它可以处理任何可使用 RDF 和 Horn 逻辑规则表示的策略类型。

我们策略引擎的第二个局限性是它目前仅针对某些类型的策略，如保密性、隐私和编辑策略。我们需要将信息共享策略纳入策略引擎。然而，我们已为基于激励的 AIS 以及云中的 AIS 原型进行了仿真研究。我们定义了许多信息共享策略，例如“美国向英国提供信息，前提是英国不与印度共享该信息。”我们用 RDF 指定此类策略，并将其纳入由增强后的策略引擎处理。

## 16.2.2.2 增强的 SPARQL 查询处理器

虽然我们有一个工具可在 Hadoop 上对大型 RDF 图执行 SPARQL 查询，但仍需支持路径查询（即提供 RDF 图中路径答案的 SPARQL 查询）。RDF 三元组可视为从主语到宾语的弧，谓语用于标记该弧。SPARQL 查询的答案基于可达性（即源节点和目标节点之间的路径）。沿路径弧标签的连接可视为属于路径查询答案集的一个词。词中的每个项由 RDF 图中某个三元组的谓语标签贡献。我们设计了一种算法，以在分布式 RDF 图中确定作为答案集的候选三元组。首先，RDF 文档被转换为基于谓语标签拆分的 N-triple 文件。词中的一项可能对应某个谓语文件。其次，我们通过在分布式 RDF 图中追踪适当的路径来形成该词。我们使用 MapReduce 作业来构建该词并获取作为有序集的候选 RDF 三元组。最后，我们返回所有有序 RDF 三元组集作为相应 SPARQL 查询的答案。

## 16.2.2.3 集成框架

[图 16.2](#ch16.xhtml#fig16_2a) 提供了 CAISS 架构的概览。将以云为中心的 RDF 策略引擎与增强的 SPARQL 查询处理器集成必须解决以下问题。首先，我们需要确保基于 RDF 的策略可以存储在查询处理器使用的现有存储模式中。其次，我们需要确保增强的查询处理器能够高效地评估底层 RDF 存储上的策略（即路径查询）。最后，我们需要对 CAISS 进行性能评估，以验证其是否满足各参与机构的性能要求。[图 16.3](#ch16.xhtml#fig16_3a) 说明了 CAISS 的操作概念。在此，多个机构将在单个云中共享数据。增强的策略引擎和以云为中心的 SPARQL 查询处理器将强制执行信息共享策略。这个概念验证系统将推动 CAISS++ 的详细设计和实现。
