## 8.4.2 误差减少分析

正如算法 8.1 所述，我们构建了包含 `Kv` 个分类器的集成 `A`。测试实例 `x` 通过集成中分类器的多数投票进行分类。我们使用简单多数投票而非加权多数投票（参考 [WANG2003](#ch08.xhtml#ref8_3)），因为简单多数投票已被理论证明是数据流的最佳选择 [GAO2007](#ch08.xhtml#ref8_7)。加权投票在这些场景下可能存在问题，因为它假设训练数据和测试数据的分布相同。然而，在数据流中，由于概念漂移，这一假设被违背。因此，简单多数投票是更好的替代方案。我们的实验在实践中证实了这一点，简单多数投票获得的结果优于加权多数投票。

我们在 [[MASU2011](#ch08.xhtml#ref8_27)] 中已经证明，与*单分区、单数据块*（SPC）方法相比，EMPC 可以进一步降低对概念漂移数据流进行分类时的期望误差，后者仅使用一个数据块来训练单个分类器（即 `r` = `v` = 1）。直观上，误差减少主要有两个原因。首先，通过引入多数据块概念，每个分类器的训练数据量增加了。更大的训练数据自然能带来训练更好的模型，从而降低误差。其次，我们不是仅从训练数据中训练一个模型，而是将数据划分为 `v` 个分区，并从每个分区训练一个模型。这进一步降低了误差，因为 `v` 个分类器组成的集成的平均期望误差在理论上比单个分类器低 `v` 倍 [TUME1996](#ch08.xhtml#ref8_28)。因此，多数据块和多分区策略都有助于误差减少。

## 8.4.3 经验误差减少与时间复杂度

对于给定的分区大小 `v`，增加窗口大小 `r` 仅在一定程度上能产生误差减少。在此之后，增加 `r` 实际上会损害我们算法的性能，因为违反了不等式 (18)。`r` 的上界取决于漂移幅度 `ρd`。我们在 [MASU2011](#ch08.xhtml#ref8_27) 中展示了 `v` = 2 时，不同 `ρd` 值下，随着 `r` 增加的相对误差 `ER`。从图中可以清楚地看出，对于较低的 `ρd` 值，增加 `r` 能以更大的幅度降低相对误差。然而，在所有情况下，一旦 `r` 超过某个阈值，`ER` 就会变得大于 1。虽然可能无法从数据中得知 `ρd` 的实际值，但我们可以通过实验确定 `r` 的最优值。在我们的实验中，我们发现对于较小的数据块大小，较高的 `r` 值效果更好，反之亦然。然而，`r` = 2 或 `r` = 3 时能找到最佳的性能-成本权衡。我们在实验中使用了 `r` = 2。同样，对于固定的 `r` 值，`v` 的上界可以从不等式 (18) 推导得出。应注意到，如果增加 `v`，运行时间也会增加。从我们的实验来看，`v` = 5 时获得了最佳的性能-成本权衡。

该算法的时间复杂度为 `O(vn(Ks + f(rs)))`，其中 `n` 是数据块总数，`s` 是每个数据块的大小，`f(z)` 是在大小为 `z` 的训练数据上构建分类器所需的时间。由于 `v` 是常数，复杂度变为 `O(n(Ks + f(rs)))`。这最多比最近的相关工作 [WANG2003](#ch08.xhtml#ref8_3) 慢一个常数因子 `rv`，但具有显著降低误差的优势。

## 8.4.4 Hadoop/MapReduce 框架

我们使用开源的 Hadoop [[APAC2010](#ch08.xhtml#ref8_3)] MapReduce 框架来实现实验。在此，我们提供 Hadoop MapReduce 特征提取和选择算法的一些算法细节。MapReduce 框架中的 `Map` 函数接受一个键值对作为输入，并为每个输入产生一个中间键值对列表。

```
Map: (MKey × MVal) → (RKey × RVal)*
```

所有 `Map` 任务由集群中的每个节点并行处理，节点间不共享数据。Hadoop 通过将共享公共中间键 `k` ∈ `RKey` 的每组中间值 `V` ⊆ `RVal` 分组，来汇总 `Map` 任务的输出。生成的汇总对 (`k`, `V`) 随后被流式传输到 `Reduce` 节点。因此，Hadoop MapReduce 框架中的每个 reducer 都会接收一个包含多个 (`k`, `V`) 对的列表，由 Hadoop 以迭代方式一次发出一个。因此 `Reduce` 可以理解为具有以下签名的函数：

```
Reduce: (RKey × RVal*)* → Val
```

陪域 `Val` 是 MapReduce 周期最终结果的类型。

在我们的框架中，`Map` 键 (`MKey`) 是二进制文件标识符（例如文件名），`Map` 值 (`MVal`) 是以字节形式存储的文件内容。`Reduce` 键 (`RKey`) 是 `n`-gram 特征，其对应的值 (`RVal`) 是发现这些特征的文件实例的类标签。[算法 8.2](#ch08.xhtml#alg8_2) 展示了 `Map` 节点用于将前者映射为后者的特征提取过程。[算法 8.3](#ch08.xhtml#alg8_3) 的第 5-10 行统计 `Map` 报告的类标签，以获得每个 `n`-gram 的正负实例计数。这些构成了第 11 行计算每个 `n`-gram 信息增益的基础。第 12-16 行使用最小堆数据结构 `h` 根据信息增益过滤掉除最佳 `S` 个特征之外的所有特征。最终遇到的最佳 `S` 个特征由第 18-20 行返回。

Hadoop 系统中的 `q` 个 reducer 因此总共产生 `qS` 个候选特征及其信息增益。这些被流式传输到第二个 reducer，该 reducer 仅实现算法 8.3 的后半部分以选择最佳的 `S` 个特征。
