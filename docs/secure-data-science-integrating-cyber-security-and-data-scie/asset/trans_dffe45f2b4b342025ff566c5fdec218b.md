

为了解环境因素（如空气污染）和生活方式因素（如睡眠质量）对儿童哮喘发作的影响，美国国家卫生研究院（NIH）最近启动了“利用集成传感器监测系统的儿科研究（PRISMS）”计划。该计划的目标是“解决与集成监测系统数据集相关的重大数据科学和工具开发挑战，以推动我们对儿童哮喘环境决定因素理解的重要进展”[[NIH2015](#ch13.xhtml#ref13_54)]。作为该研究的一部分，预计监测设备将佩戴在儿童身上以收集其生活方式数据（如身体活动、血氧水平），并将这些生活方式数据集与环境（如儿童住所附近的空气污染）和医疗（如因哮喘发作住院的次数）数据集相结合，以更好地理解和预测哮喘发作。该 NIH 计划要求研究人员具备“确保数据安全并维护个人身份信息机密性的专业能力”，因为家长在参与此类研究前需要获得关于其孩子隐私的有力保障。同样，收集的关于员工的 QS 数据（如睡眠质量、活动数据）可用于预测员工压力水平并改善员工福祉，前提是采取了保护隐私的适当措施。根据普华永道（PwC）最近的一项调查，只有“超过一半的员工会考虑佩戴雇主提供的智能手表，如果他们的数据被用于改善工作时长、压力水平和工作地点等方面。”好消息是，根据调查，“如果数据被匿名化并在汇总层面共享，而不是个性化的，人们也更愿意接受这一想法。”这些例子展示了收集和共享 QS 数据以改善医疗结果和员工生产力的潜力，但前提是必须保护个人隐私。因此，我们需要一个框架来强制执行由用户隐私需求指导的适当隐私感知策略，以确定收集、存储和共享哪些数据，由谁、何时、何地、为何以及如何进行，同时还需要工具和技术来高效地执行这些策略，并从 QS 数据中获取尽可能多的效用。

## 13.2.2 架构概览

我们需要开发一个隐私感知的 QS 数据管理框架，以控制 QS 数据的整个生命周期（[图 13.2](#ch13.xhtml#fig13_2a)）。我们设想不同的数据源和设备将根据隐私感知数据收集策略，向运行在移动设备上的 `Data Collection Layer`（[第 13.2.3 节](#ch13.xhtml#sec13_002_003)）提供敏感信息。这些策略将指定设备何时、何地以及可以收集和存储什么数据。例如，自动捕获所有图像的设备（如 Narrative Clip [[NARR2014](#ch13.xhtml#ref13_52)]）可能不得在某些地点使用，如国际机场的入境身份核查区。此类数据收集限制将由运行在设备上的隐私感知数据收集管理器自动管理。

[图 13.2 隐私感知量化自我架构.](#ch13.xhtml#Ffig13_2)

在我们的平台中，我们假设只有移动设备是受信的，例如，它采用了智能手机安全的最先进技术，如容器化 [[OLUW2015](#ch13.xhtml#ref13_56), [ASOK2013](#ch13.xhtml#ref13_6)]，并被允许以明文形式访问所有传入数据；移动设备在控制释放什么信息方面扮演“守门人”的角色。然而，基于云的服务和运行在设备上的应用是不受信的。随后，收集的数据将被索引，并在传入的 QS 数据上本地计算某些统计信息（如过去 12 个月的日均睡眠时长）和基本数据分析功能（如两个数据流之间的相关系数）。随着收集数据的增多，设备上的存储空间将不足以存储所有数据。我们设想了一个加密云存储组件，用于将较旧的数据和/或不常访问的数据推送到云端。例如，先前活动拍摄的照片可能以加密形式存储在云端。将维护适当的本地索引，以便在需要时高效检索存储在云端的加密数据。此外，基于访问控制策略，运行在设备上的本地应用将被授予访问部分收集数据的权限。当需要时，这些应用将被允许通过简单的查询接口访问存储在云端的部分加密数据。我们强调，我们的架构不要求对任何现有应用或设备进行更改。例如，如果用户乐于使用 Fitbit 应用，用户可以继续按原样使用它。另一方面，利用 Fitbit 提供的应用程序编程接口（API），运行在移动设备上的代理可以收集必要的活动数据，并将其与移动设备收集的位置数据相结合，以执行某些策略或启用其他应用。我们需要利用设备制造商提供的 API 开发一个集成不同类型数据的概念验证架构。

`Data Storage and Access Layer` 还将处理数据生命周期的管理。在某些情况下，数据可能不再需要以细粒度形式保存。例如，存储 20 年前的每日体重数据可能是不必要的；相反，存储和挖掘月均体重数据可能足以支持各种医疗应用。在其他情况下，为了保护隐私，数据可能必须被删除（例如，删除和/或生成虚假位置数据以隐藏用户参加过抗议活动的事实）。此类数据删除策略将由存储层自动管理，并将使用定量信息流分析来分析此类删除的潜在隐私影响（例如，仅删除敏感信息可能会产生一些推理侧信道）。由于人们经常更换或丢失移动设备，我们设想存储在移动设备上的信息将使用另一家云服务提供商持续备份。因此，如果移动设备丢失，可以使用加密备份副本设置新的移动设备。当然，云服务提供商需要确保存储的加密数据可靠可访问 [[KIRK2010](#ch13.xhtml#ref13_38)]。
