

# 基于 RDF 的云应用策略引擎

我们开发了一个基于 RDF 的策略引擎，用于云环境中的各种应用，包括社交媒体和信息共享应用。使用 RDF 作为数据模型的原因如下：

1. RDF 使我们能够实现数据互操作性，连接那些看似截然不同、由各机构/组织分别编目管理的信息源。
2. 使用 RDF 使参与机构能够创建以数据为中心的应用，利用现已可用的集成数据。
3. 由于 RDF 生成数据不需要显式模式，因此可以轻松适应不断变化的用户需求。

该策略引擎的灵活性建立在其接受高级策略，并将其作为规则/约束在源数据及其关联数据的有向 RDF 图表示上执行的基础之上。我们策略引擎的优势在于，它可以处理任何可使用 RDF 技术、霍恩逻辑规则（如 `SWRL`）和 `OWL` 约束表示的策略类型。这些语义 Web 技术的强大功能可在云计算环境中成功加以利用，为用户提供高效存储和检索数据的能力，以支持数据密集型应用。

在云中存储 RDF 数据带来了许多新特性，例如可扩展性和按需服务、为用户按需提供资源和服务、按需付费服务和容量、位置独立性，以及在硬件/CPU 性能、带宽和内存容量方面为用户保证服务质量。

在开发我们的 RDF 集成框架时，我们考察了以下工作。

在 [[SUN2010]](#ch04.xhtml#ref4_62) 中，作者采用了 Hexastore 的思想，并同时考虑了 RDF 数据模型和 `HBase` 能力。他们将 RDF 三元组存储在六个 `HBase` 表（`S_PO`、`P_SO`、`O_SP`、`PS_O`、`SO_P` 和 `PO_S`）中，覆盖了 RDF 三元组模式的所有组合。他们利用 `HBase` 在行键上提供的索引结构对三元组进行索引。他们还为 `SPARQL` 基本图模式（`BGP`）处理提出了一种 `MapReduce` 策略，该策略适合其存储模式。该策略使用多个 `MapReduce` 作业来处理典型的 `BGP`。在每个作业中，它使用贪婪方法选择连接键并消除多个三元组模式。他们的评估结果表明，该方法在大规模 RDF 数据集上表现良好。

在 [[HUSA2009]](#ch04.xhtml#ref4_37) 中，作者描述了一个使用 `Hadoop` 存储和检索大量 RDF 三元组的框架。他们描述了一种在 `HDFS` 中存储 RDF 数据的模式。他们还提出了回答 `SPARQL` 查询的算法。这利用了 `Hadoop` 的 `MapReduce` 框架来实际回答查询。

在 [[HUAN2011]](#ch04.xhtml#ref4_36) 中，作者介绍了一个可扩展的 RDF 数据管理系统。他们介绍了以下技术：(i) 利用最先进的单节点 RDF 存储技术，以及 (ii) 跨节点划分数据，通过局部性优化来加速查询处理。

在 [[PAPA2012]](#ch04.xhtml#ref4_54) 中，作者提出了 `H2RDF`，这是一个完全分布式的 RDF 存储，结合了 `MapReduce` 处理框架和 `NoSQL` 分布式数据存储。其系统具有独特特性，能够在虚拟无限数量的三元组上高效处理简单和多连接 `SPARQL` 查询。这些特性包括：根据查询选择性执行连接以减少处理的连接算法，以及在集中式和分布式（基于 `MapReduce`）连接执行之间自适应选择以实现快速查询响应。他们声称其系统能高效回答简单连接和复杂多变量查询，并能使用由九个工作节点组成的小型集群扩展至三十亿三元组。

在 [[KHAD2012b]](#ch04.xhtml#ref4_42) 中，作者设计了一个 `Jena-HBase` 框架。其基于 `HBase` 的三元组存储可与 `Jena` 框架配合使用。`Jena-HBase` 为最终用户提供了一个可扩展的存储和查询解决方案，支持 RDF 规范的所有特性。更多 `HBase` 详情可参见 [`HBASE`] 和 [[GEOR2011]](#ch04.xhtml#ref4_28)。

## 4.4.3.2 来源集成

虽然我们针对社交网络应用在云中实现可靠信息共享的方法足够通用，适用于包括网络安全数据在内的任何类型数据，但我们以来源数据为例进行了说明。我们将讨论在来源数据集成工作中考察的各种方法。更多工作详情可参见 [[THUR2014]](#ch04.xhtml#ref4_66)。

在 [[IKED2011]](#ch04.xhtml#ref4_39) 中，作者考虑了一类称为广义 Map 和 Reduce 工作流（`GMRWs`）的工作流。输入数据集由 Map 和 Reduce 函数的有向无环图处理以产生输出结果。他们还展示了如何透明地捕获 Map 和 Reduce 函数的数据来源（谱系）。

在 [[CHEB2013]](#ch04.xhtml#ref4_19) 中，作者探索并解决了在 `Apache HBase` 数据库中高效且可扩展地存储和查询大量序列化为 RDF 图的来源图集合的挑战。

在 [[PARK2011]](#ch04.xhtml#ref4_55) 中，他们提出了 `RAMP`（Reduce 和 Map 来源）作为 `Hadoop` 的扩展，支持 `MapReduce` 作业工作流的来源捕获和追踪。

[[ABRA2010]](#ch04.xhtml#ref4_1) 中讨论的工作提出了一个系统，展示了如何利用 `HBase` 类 Bigtable 的能力，对用 RDF 表示的来源数据进行分布式存储和查询。特别是，他们的 `ProvBase` 系统包含一个 `HBase`/`Hadoop` 后端、一个用于存储来源三元组的存储模式，以及一个用于在其系统中评估 `SPARQL` 查询的查询算法。

在 [[AKOU2013]](#ch04.xhtml#ref4_3) 中，作者的研究引入了 `HadoopProv`，这是一个实现了 `MapReduce` 作业中来源捕获和分析的修改版 `Hadoop`。其系统旨在通过 (i) 分别处理 Map 和 Reduce 阶段的来源跟踪，以及 (ii) 将来源图的构建推迟到查询阶段，来最小化来源捕获开销。来源图随后在 Map 和 Reduce 来源文件的匹配中间键上进行连接。

# 4.5 分析与保护社交网络

## 4.5.1 社交网络简介

在线社交网络（`OSNs`）在互联网上获得了极大普及，成为一个重要的研究课题，吸引了来自不同领域的众多专业人士。自 `Facebook`、`Twitter` 和 `LinkedIn` 等 `OSNs` 网站出现以来，`OSNs` 持续影响并改变着我们生活的方方面面。从政治到商业营销，从名人到新闻制造者，每个人都沉迷于这一现象。`Facebook` 用于与朋友联系并分享各种个人和专业数据以及照片和视频；`LinkedIn` 完全是一个专业网络，用于与同事建立联系。`Google+` 类似于 `Facebook`，而 `Twitter` 是一项免费的社交网络和微博服务，允许用户发送和阅读称为推文的消息。推文是显示在作者个人资料页面上并分发给作者订阅者（称为 `followers`）的约 140 字符的文本帖子。每个网络都有其自身的优势，这些网络主要通过广告盈利，因为它们提供的服务在很大程度上是免费的，除非当然有人想在 `LinkedIn` 等网络中获得高级服务。
