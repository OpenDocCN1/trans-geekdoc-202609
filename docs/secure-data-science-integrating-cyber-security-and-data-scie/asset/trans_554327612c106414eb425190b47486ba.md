
# 15.5.4.1 Bestplan 的计算复杂度

可以证明，生成最小代价查询计划在计算上是昂贵的，因为搜索空间呈指数级增长。首先，我们对问题进行建模，然后展示其复杂性。

## 15.5.4.2 问题建模

我们将 Bestplan 建模为一个搜索问题。设 `G = (V, E)` 为一个加权有向图，其中每个顶点 `v[i] ∈ V` 表示三元组模式的一种状态，每条边 `e[i] ∈ (v[i[1]], v[i[2]]) ∈ E` 表示一个从状态 `v[i[1]]` 转移到状态 `v[i[2]]` 的作业。`v[0]` 是初始状态，此时尚未执行任何连接，即给定的查询。此外，`v[goal]` 是目标状态，表示所有连接均已执行完毕的三元组模式状态。该问题在于寻找从 `v[0]` 到 `v[goal]` 的最短加权路径。

例如，在我们的运行示例查询中，初始状态 `v[0] = {X, Y, Z, XY, XZ}`，目标状态 `v[goal] = ∅`，即不再有剩余的三元组模式。假设第一个作业执行 `join(X, XY, XZ)`。那么，生成的三元组模式（新状态）将为 `v[1] = {Y, Z, YZ}`，作业1将由边 `(v[0], v[1])` 表示。边 `(v[0], v[1])` 的权重即为 `job[1]` 的代价 `= cost(job[1])`，其中 cost 为给定的代价函数。图 15.4 展示了示例查询的部分图。

## 15.5.4.3 搜索空间大小

给定图 `G = (V, E)`，Dijkstra 最短路径算法可在 `O(|V| log |V| + |E|)` 时间内找到从源点到所有其他节点的最短路径。然而，对于 Bestplan，可以证明在最坏情况下，`|V| ≥ 2^K`，其中 `K` 为给定查询中连接变量的总数。因此，图中的顶点数量呈指数级增长，导致这是一个指数级搜索问题。在 [HUSA11a] 中，我们已证明 Bestplan 问题的最坏情况复杂度在给定查询的连接变量数 `K` 上呈指数级。

## 15.5.4.4 松弛 Bestplan 问题与近似解

在松弛 Bestplan 问题中，我们假设所有作业的代价均匀。尽管这种松弛并未减小搜索空间，但问题简化为寻找具有最少作业数量的作业计划。请注意，这是该模型实用版本所面临的问题。

**定义 15.12：松弛 Bestplan 问题**：松弛 Bestplan 问题旨在寻找具有最少作业数量的作业计划。

接下来，我们将证明：如果合理选择连接，且在一个作业中不留下任何符合条件的连接操作未执行，则可为任意给定查询所需的最大作业数设定一个上界。然而，生成所有可能的作业计划在计算上仍然昂贵。因此，我们采用了一种贪心算法（[算法 15.1](#ch15.xhtml#alg15_1)），它能求得松弛 Bestplan 问题的近似解，但保证能在上界内找到一个作业计划。

**定义 15.13：早期消除启发式**：早期消除启发式旨在每个作业中尽可能多地进行完全消除。

该启发式使得留给下一个作业进行连接的变量数量最少。为应用该启发式，我们必须首先在每个作业中选择 E-count 最小的变量。该启发式应用于算法 15.1 中。

### 算法 15.1 说明

算法首先从查询 `Q` 中移除所有非连接变量。在我们的运行示例中，`Q = {X, Y, VZ, XY, XZ}`，移除非连接变量 `V` 后得到 `Q = {X, Y, Z, XY, XZ}`。在 while 循环中，从 `Job[1]` 开始生成作业计划。第 4 行，我们根据变量的 E-count 对其进行排序。排序后的变量为：`U = {Y, Z, X}`，因为 `Y` 和 `Z` 的 E-count = 1，而 `X` 的 E-count = 2。对于每个作业，要执行的连接操作列表存储在变量 `Job[J]` 中，其中 `J` 为当前作业的 ID。此外，临时变量 `tmp` 用于存储当前作业中将要执行的连接所产生的结果三元组（第 6 行）。在 for 循环中，检查每个变量以判断其是否可以被完全或部分消除（第 8 行）。若可以，则将连接结果存入临时变量（第 9 行），更新 `Q`（第 10 行），并将该连接加入当前作业（第 11 行）。在我们的运行示例中，这将导致以下操作：

for 循环第 1 次迭代：`u[1] = (Y)` 可被完全消除。此处，`TP(Q, Y)` 为包含

for 循环第 3 次迭代：`u[3] = (X)` 无法被完全或部分消除，因为没有其他 `TP` 剩余可与其连接。因此，当 for 循环结束时，我们得到 `job[1] = {join(Y, XY), join(Z, XZ)}`，且 `Q = {X, X, X}`。在 while 循环的第 2 次迭代中，我们将得到 `{job[2] = {X, X, X}}`。由于执行此连接后 `Q` 变为空，while 循环退出。最终，算法返回 `{job[1], job[2]}`。

在 [HUSA2011a] 中，我们已证明：对于包含 `K` 个连接变量和 `N` 个三元组模式的任意给定查询 `Q`，算法松弛 Bestplan (`Q`) 生成的作业计划最多包含 `J` 个作业，其中

```
J = { 0                    若 N = 0
    { 1                    若 N = 1 或 K = 1
    { min(ceil(1.71 log₂ N), K)  若 N, K > 1
```
