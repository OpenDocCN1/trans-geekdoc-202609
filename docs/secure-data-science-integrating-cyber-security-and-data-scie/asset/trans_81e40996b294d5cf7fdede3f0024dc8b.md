例如，`CAISS` 的一种实现是用 `Java` 编写的，并基于一种灵活的设计，我们可以在其中即插即用多个组件。服务提供商和/或用户将拥有灵活性，既可以将 `SPARQL` 查询处理器和基于 `RDF` 的策略引擎作为单独的组件使用，也可以将它们组合使用。用于 `CAISS` 的开源组件将包括 `Pellet` 推理器以及我们的内部工具，如基于 `Hadoop/MapReduce` 框架的 `SPARQL` 查询处理器和以云为中心的 `RDF` 策略引擎。`CAISS` 将允许我们在基于云的框架上演示基本的 `AIS` 场景。

# 16.3.3 演示系统的实现

## 16.3.3.1 架构

本节描述了我们为演示而实现的架构和系统的细节、模块及其他详情。我们的策略引擎框架由 `RDF` 配置文档驱动，这些文档编码了策略引擎的逻辑及其用法、用户界面布局和可定制参数，以及使用可用数据连接将可解引用的 `URI` 映射到数据存储。我们的策略引擎框架可作为关键推动者，增强 `RDBMS`（关系数据库管理系统）以及基于云的系统的安全性。`RDBMS` 的开发考虑了原子性、并发性和持久性，但通常随附的访问控制支持有限。云存储层允许机构存储和扩展策略，并对 `RDF` 资源实施更精细的控制。云的开发考虑了可扩展性和可用性，但忽视了安全考量。我们的策略引擎可配置为补充 `RDBMS` 中的策略，并为支持基于云的后端上的安全策略提供一个入口点。我们首先概述框架的配置。然后定义架构中的各层，最后描述我们实现的新颖特性。[图 16.16](#ch16.xhtml#fig16_16a) 展示了我们的架构，[图 16.17](#ch16.xhtml#fig16_17a) 展示了我们的配置框架。

松耦合系统为我们的 `RDF` 策略引擎框架提供了易于配置和灵活的特性。通过采用包含机构对策略偏好或数据存储数据连接的 `RDF` 文档，每个组件都与其他组件抽象开来。此外，松耦合的 Web 前端促进了策略框架的更易维护和复用，因为适配器模式抽象了 Web 接口（及通信）到其他层的映射。抽象向机构隐藏了策略引擎管理器和数据管理器的实际实现及复杂性。因此，这允许机构使用任何表示语言（如 `XML`、`RDF` 或 `Rei` [[KAGA2002](#ch16.xhtml#ref16_38)]）指定其策略；适配器隐藏了从高层策略规范到策略实现的转换。

我们的系统架构由三层组成。前端是用户界面；中间层包含我们的策略引擎逻辑；后端是我们的数据存储。接下来我们将讨论这些模块。应注意，在本实现中，我们的重点在于共享数据的溯源。该实现受本章前面讨论的原型以及[第 17 章](#ch17.xhtml#chapter17)中讨论的基于溯源的推理控制器的驱动。

### 16.3.3.1.1 用户界面层

为了实现与我们框架的一对一交互，在策略层之上构建了一个基于 Web 的用户界面。丰富客户端和开源 Web 技术简化了用户、网页以及底层策略和数据层之间的交互。这种集成具有许多优势。策略框架在分布式环境中运行，具有更广泛的地理分布；因此，机构和用户具有移动性。Web 界面要求用户创建账户（也是一种注册）并选择唯一的凭证，这些凭证随后将被用户用于向策略框架标识自己。基于表单的身份验证模式以及质询-响应测试将合法用户与机器人（可能伪装成普通用户）区分开来。合法用户将看到一个查询屏幕，允许他们在通过身份验证后编写 `SPARQL` 查询。注意，`SPARQL` [[PRUD2006](#ch16.xhtml#ref16_49)] 是一种用于 `RDF` 的查询语言，用于从三元组存储中检索数据。`SPARQL` 查询经过验证后被发送到我们的策略引擎层，后者返回一个结果 `RDF` 图，然后在网页上显示。
