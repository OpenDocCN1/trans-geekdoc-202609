### 4.4.1 语义网技术栈

#### 4.4.1.1 XML

由于 HTML（超文本标记语言）的局限性和 SGML（标准通用标记语言）的复杂性，XML 变得必要。XML 是由 W3C 制定的一种可扩展标记语言，旨在使结构化文档在互联网上的交换更加容易。XML 的一个重要方面曾经是文档类型定义（DTD），它在正式模型中定义了每个文本元素的角色。XML Schema 现在已成为指定数据结构的关键。XML Schema 本身也是 XML 文档 [[BRAY1997](#ch04.xhtml#ref4_15)]。

#### 4.4.1.2 RDF

RDF 是语义网上描述资源的标准。它提供了一个通用框架来表达这些信息，以便它们可以在应用程序之间交换而不丢失含义。RDF 基于使用 Web 标识符（称为统一资源标识符，或 URI）来标识事物的思想，并通过简单的属性和属性值来描述资源 [[KLYN2004](#ch04.xhtml#ref4_45)]。

RDF 具有形式语义，这为推理 RDF 图的含义提供了可靠的基础。这种推理通常称为蕴含。蕴含规则规定了可以从显式信息中推断出哪些隐式信息。通常，不假设 RDF 查询中包含关于任何资源的完整信息。查询语言应意识到这一点，并能容忍不完整或相互矛盾的信息。类的概念及对类的操作通过 RDF Schema 的概念在 RDF 中规定 [[ANTO2008](#ch04.xhtml#ref4_8)]。

#### 4.4.1.3 SPARQL

SPARQL（简单协议和 RDF 查询语言）[[PRUD2006](#ch04.xhtml#ref4_58)] 是一种强大的查询语言。它是一项关键的语义网技术，并由 W3C 的 RDF 数据访问工作组标准化。SPARQL 语法类似于 SQL，但它的优势在于能够使查询跨越多个不同的数据源，这些数据源由异构和半结构化数据组成。SPARQL 基于图模式匹配 [PRUD2006]。

#### 4.4.1.4 OWL

Web 本体语言（OWL）[[MCGU2004](#ch04.xhtml#ref4_49)] 是一种本体语言，其表达能力和推理能力比 RDF 和 RDF Schema（RDF-S）更强。它具有额外的词汇以及形式语义。OWL 有三种表达能力逐渐增强的子语言：OWL Lite、OWL DL 和 OWL Full。这些子语言是为特定的实现者和用户社区设计的。OWL 中的形式语义基于描述逻辑（DL），后者是一阶逻辑的一个可判定片段。

#### 4.4.1.5 描述逻辑

描述逻辑（DL）是一系列知识表示（KR）形式化方法，用于表示应用领域的知识 [[BAAD2003](#ch04.xhtml#ref4_9)]。它将领域的概念（即其术语）定义为称为类的对象集合，并使用这些概念来指定领域中出现的对象和个体的属性。描述逻辑的特点是具有一组构造器，允许从原子概念和角色构建复杂的概念和角色。

#### 4.4.1.6 SWRL

语义网规则语言（SWRL）将 OWL 公理集扩展为包含类 Horn 规则，并将类 Horn 规则扩展为可与 OWL 知识库相结合 [[HORR2004](#ch04.xhtml#ref4_35)]。提议的规则采用前件（主体）和后件（头部）之间蕴含的形式。其预期含义可理解为：每当前件中指定的条件成立时，后件中指定的条件也必须成立。前件（主体）和后件（头部）均由零个或多个原子组成。空前件被视为显然为真（即被每种解释满足），因此后件也必须被每种解释满足。空后件被视为显然为假（即不被任何解释满足），因此前件不得被任何解释满足。多个原子被视为合取，头部和主体均可包含此类原子的合取。请注意，具有合取后件的规则可以很容易地通过 Lloyd-Topor 变换转换为多条每条具有原子后件的规则。

### 4.4.2 语义网与安全

我们首先概述语义网的安全问题，然后讨论 XML 安全、RDF 安全和安全信息集成的一些细节，这些都是安全语义网的组成部分。随着对这些各种问题研究的深入，我们希望能制定出适当的标准来保障语义网的安全。安全不能孤立考虑。安全贯穿所有层。

例如，考虑最底层。需要安全的 TCP/IP、安全套接字和安全的 HTTP。现在这些各种底层协议都有了安全协议。需要端到端安全。也就是说，不能仅在不受信的通信层上构建安全的 TCP/IP；我们需要网络安全。下一层是 XML 和 XML Schema。需要安全的 XML。也就是说，必须控制对文档各部分的访问，以进行读取、浏览和修改。目前已有关于保护 XML 和 XML Schema 的研究。下一步是保护 RDF。现在有了 RDF，我们不仅需要安全的 XML，还需要对解释和语义的安全保护。例如，在某些上下文中，文档的部分内容可能是*非密的*，而在其他某些上下文中，该文档可能是*密级的*。

一旦 XML 和 RDF 得到保护，下一步就是检查本体和互操作的安全性。也就是说，本体可能附有安全级别。本体的某些部分可能是*机密的*，而其他部分可能是*非密的*。挑战在于如何利用这些本体进行安全信息集成？研究人员已经在数据库安全互操作性方面做了一些工作。我们需要重新审视这项研究，然后确定还需要做什么，以便 Web 上的信息能够被安全地管理、集成和交换。逻辑、证明和信任位于语义网的最高层。也就是说，我们如何信任 Web 给我们的信息？接下来我们将讨论 XML、RDF、本体和规则的各种安全问题。

#### 4.4.2.1 XML 安全
