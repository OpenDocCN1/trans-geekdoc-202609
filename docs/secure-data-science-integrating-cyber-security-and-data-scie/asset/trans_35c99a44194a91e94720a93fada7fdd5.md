

# 4.2 大数据工具

## 4.2.1 托管大数据系统的基础设施工具

在本节中，我们将讨论托管各种大数据系统的各种基础设施产品。它们包括：Apache 的 `Hadoop`、`Spark`、`Storm`、`Flink` 和 `Kafka` 以及 `MapReduce` 编程模型 [[WHIT2015](#ch04.xhtml#ref4_73)]。这些基础设施工具也可以被视为云计算工具。

### 4.2.1.1 Apache Hadoop

`Hadoop` 是一个用于处理大量数据的开源分布式框架。它使用我们接下来将讨论的 `MapReduce` 编程模型。其存储系统称为 Hadoop 分布式文件系统（`HDFS`）。它托管在机器集群上。一个文件由多个块组成，文件的块会被复制以保证可用性。它支持数据的并行处理以提高性能。`JobTracker` 是 `Hadoop` 的一部分，用于跟踪 `MapReduce` 作业。这些作业由客户端应用程序提交。大多数大数据系统以及云应用程序都托管在 `Hadoop` 上。更多 `Hadoop` 详情请参见 [HDFS]。

### 4.2.1.2 MapReduce

`MapReduce` 是一种编程模型及其相关实现，它接收客户端请求并将其转换为 `MapReduce` 作业。然后这些作业由 `Hadoop` 执行。该编程模型的主要特性是作业的生成。`MapReduce` 模型有两个组件：(i) `Map` 和 (ii) `Reduce`。正如 [[MAPR](#ch04.xhtml#ref4_48)] 所述，“一个 `MapReduce` 作业通常会将输入数据集分割成独立的块，这些块由 map 任务以完全并行的方式处理。框架对 map 的输出进行排序，然后将其输入给 reduce 任务。通常，作业的输入和输出都存储在文件系统中。框架负责任务调度、监控以及重新执行失败的任务。” `MapReduce` 模型的更多细节见 [MAPR]。

### 4.2.1.3 Apache Spark

`Apache Spark` 是一个用于处理海量数据的开源分布式计算框架。应用程序员通过一个接口使用 `Spark`，该接口包含一个称为弹性分布式数据集（`RDD`）的数据结构。`Spark` 的开发旨在克服 `MapReduce` 编程模型的局限性。`Spark` 的 `RDD` 数据结构提供了对分布式共享内存的支持。得益于内存处理能力，`Spark` 提供了良好的性能。`Spark` [[SPAR](#ch04.xhtml#ref4_60)] 与各种基于 NoSQL 的大数据系统（如 `Cassandra`）以及 Amazon 的云平台具有接口。`Spark` 通过 `Spark SQL` 支持 SQL 功能。

### 4.2.1.4 Apache Pig

`Apache Pig` 是一个用于分析和处理大型数据集的脚本平台。`Apache Pig` 使 `Hadoop` 用户能够使用一种称为 `Pig Latin` 的简单脚本语言编写复杂的 `MapReduce` 转换。`Pig` 将 `Pig Latin` 脚本转换为 `MapReduce` 作业。然后这些 `MapReduce` 作业由 `Hadoop` 执行，处理存储在 `HDFS` 中的数据。`Pig Latin` 编程类似于指定查询执行计划。也就是说，`Pig Latin` 脚本可被视为执行计划。这使得程序员更容易完成任务。更多关于 `Pig` 的详情见 [[PIG](#ch04.xhtml#ref4_57)]。

### 4.2.1.5 Apache Storm

`Apache Storm` 是一个用于处理海量数据的开源分布式实时计算系统。`Storm` 本质上是一个用于处理流式数据和实时分析的实时框架。它可以与 `HDFS` 集成。它提供可扩展性、可靠性和容错性等特性。`Storm` 的最新版本支持流式 SQL、预测建模以及与 `Kafka` 等系统的集成。总之，`Storm` 用于实时处理，而 `Hadoop` 用于批处理。更多关于 `Storm` 的详情见 [[STOR](#ch04.xhtml#ref4_61)]。

### 4.2.1.6 Apache Flink

`Flink` 是一个开源的可扩展流处理框架。正如 [[FLIN](#ch04.xhtml#ref4_27)] 所述，`Flink` 具有以下特性：“(i) 即使在数据乱序或迟到的情况下也能提供准确的结果；(ii) 有状态且容错，能在保持精确一次应用状态的同时无缝从故障中恢复；(iii) 在大规模下表现优异，可在数千个节点上运行，具有极佳的吞吐量和延迟特性。” `Flink` 本质上是一个用 `Scala` 和 `Java` 实现的分布式数据流引擎。它以并行和流水线模式执行程序。它支持 `Java`、`Python` 和 `SQL` 编程环境。虽然它没有自己的数据存储，但它与 `HDFS`、`Kafka` 和 `Cassandra` 等系统集成。

### 4.2.1.7 Apache Kafka

`Kafka` 最初由 `LinkedIn` 开发，随后作为一个开源 Apache 项目进一步开发。它也是用 `Scala` 和 `Java` 实现的，是一个分布式流处理系统。它具有高度可扩展性，能处理海量流式数据。其存储层基于发布/订阅消息队列架构。其设计本质上基于分布式事务日志。事务日志用于数据库系统中，以从事务故障中恢复。更多关于 `Kafka` 的详情见 [[KAFK](#ch04.xhtml#ref4_40)]。

## 4.2.2 大数据管理与分析工具

在本节中，我们将讨论各种大数据管理与分析（`BDMA`）系统和工具。我们首先提供基于 SQL 的大数据系统。它们是 `Apache Hive` 和 `Google BigQuery`。然后我们一般性地讨论 NoSQL（非 SQL）数据库。随后讨论示例 NoSQL 系统，如 `Google BigTable`、`HBase`、`MongoDB`、`Cassandra`、`CouchDB` 和 `Oracle NoSQL Database`。随后将讨论两个用于大数据的数据挖掘/机器学习系统，它们是 `Weka` 和 `Apache Mahout`。

### 4.2.2.1 Apache Hive

`Apache Hive` 是一个建立在 `Hadoop`/`MapReduce` 平台之上的开源类 SQL 数据库/数据仓库。它最初由 `Facebook` 开发，用于存储与 `Facebook` 数据相关的信息。然而，后来它成为一个开源项目和 Apache 的商标。`Hive` 管理超大型数据集，并在 `Hadoop`/`MapReduce` 存储模型之上运行。它提供一种类 SQL 查询语言，称为 `HiveQL`。也就是说，`Hive` 支持类 SQL 查询。然而，由于 `Hadoop` 是用 `Java` 实现的，查询也用 `Java` 实现。这样，就不需要低级 `Java` API 来实现查询。`Hive` 引擎本质上将 SQL 查询转换为 `MapReduce` 作业，然后由 `Hadoop` 执行。更多关于 `Apache Hive` 的详情见 [[HIVE](#ch04.xhtml#ref4_34)]。

### 4.2.2.2 Google BigQuery

`BigQuery` 本质上是一个管理 PB 级数据的数据仓库。它运行在 `Google` 的基础设施上，能极快地处理 SQL 查询或进行分析。例如，TB 级数据可在几秒内访问，而 PB 级数据可在几分钟内访问。`BigQuery` 数据存储在不同类型的表中：原生表存储 `BigQuery` 数据，视图存储虚拟表，外部表存储外部数据。`BigQuery` 可以通过多种方式访问，如命令行工具、RESTful 接口或 Web 用户界面，以及客户端库（例如 `Java`、`.NET`、`Python`）。更多关于 `BigQuery` 的详情见 [[BIGQ](#ch04.xhtml#ref4_13)]。

### 4.2.2.3 NoSQL 数据库
