# 17 面向社交网络数据管理的访问控制

DOI：[10.1201/9781003081845-28](https://doi.org/10.1201/9781003081845-28)

## 17.1 简介

在[第IV部分](#part_04.xhtml#part4)的章节中，我们展示了利用社交网络内的数据来改进局部分类和关系分类方法的途径。虽然流行病学和反恐领域普遍被认为是这些任务的重要应用领域，但一个主要的新兴领域是通过与社交网络提供商合作，将这些数据用于市场营销。这种用法引发了这些社交网络许多用户的隐私担忧。在此，我们提供了一个框架，赋予用户对其在社交网络内信息的访问拥有更大的控制权。通过利用语义Web技术，我们能够提出非常细粒度的控制，以管理从用户照片到谁能向未成年儿童发送消息或视频的一切内容。

在线社交网络（OSN）是允许人们发布关于自己的详细信息，并通过链接连接到网络其他成员的平台。最近，OSN的流行度显著增加。例如，Facebook现在声称拥有近30亿活跃用户（[https://www.businessofapps.com/data/facebook-statistics/](https://www.businessofapps.com)）。包含个人特定信息的OSN的存在既创造了有趣的机会，也带来了挑战。例如，社交网络数据可用于向合适的客户营销产品。同时，安全和隐私担忧在实践中可能会阻碍此类工作 \[[BERT2007](#ch17.xhtml#ref17_2)\]。改进OSN访问控制系统似乎是解决与在线社交网络相关的现有安全和隐私问题的第一步。然而，大多数当前的OSN实现非常基础的访问控制系统，仅仅是让用户通过将特定项目标记为公开、私有或仅直接联系人可访问，来决定哪些个人信息可被其他成员访问。为了提供更多灵活性，一些在线社交网络强制执行这些设置的变体，但原则是相同的。例如，除了基本设置外，Bebo（[http://bebo.com](http://bebo.com)）、Facebook（[http://facebook.com](http://facebook.com)）和Multiply（[http://multiply.com](http://multiply.com)）支持“选定的朋友”选项；Last.fm（[http://last.fm](http://last.fm)）支持“邻居”选项（即具有相似音乐偏好和品味的用户集合）；Facebook、Friendster和Orkut（[http://www.orkut.com](http://www.orkut.com)）支持“朋友的朋友”选项；Xing（[http://xing.com](http://xing.com)）支持“联系人的联系人”（二度联系人）、“三度”和“四度联系人”选项。重要的是要注意，所有这些方法都具有易于实现的优势，但它们缺乏灵活性。事实上，可用的保护设置不允许用户轻松指定其访问控制需求，因为它们要么过于严格，要么过于宽松。此外，现有解决方案是特定于平台的，难以针对各种不同的在线社交网络实施。

为了解决其中一些局限性，我们提出了一种基于语义Web技术的可扩展、细粒度OSN访问控制模型。我们的主要思想是利用本体对社交网络相关信息进行编码。具体而言，我们建议使用语义Web本体对OSN的以下五个重要方面进行建模：（1）用户档案，（2）用户之间的关系（例如，Bob是Alice的密友），（3）资源（例如，在线相册），（4）用户与资源之间的关系（例如，Bob是相册的所有者），以及（5）动作（例如，在某人的墙上发布消息）。通过构建这样的本体，我们对社交网络知识库（`SNKB`）进行建模。使用本体对OSN数据建模的主要优势在于，许多不同社交网络概念之间的关系可以使用`OWL`自然地表示。此外，通过推理，可以自动完成关于此类关系的许多推断。我们的访问控制执行机制随后通过利用这些知识来实现。具体而言，思路是将安全策略定义为规则（见[第17.4节](#ch17.xhtml#sec17_4)），其前件陈述`SNKB`上的条件，后件指定授权动作。特别是，我们建议利用本体对安全策略隐含的授权进行编码，从而获得`SAKB`。因此，安全策略必须被转换为规则，其前件和后件在本体上表达。为了实现这一目标，我们使用语义Web规则语言（`SWRL`）\[[HORR2004](#ch17.xhtml#ref17_11)\]。因此，访问控制策略可以通过简单地查询授权（即`SAKB`）来执行。该查询可以通过实例检查操作由本体推理器直接轻松实现，或者如果本体以`RDF`序列化，则可以通过`SPARQL`查询执行。在本章中，我们重点关注如何利用语义Web技术对这种细粒度社交网络访问控制系统进行建模。我们还假设由社交网络管理者托管的集中式参考监视器将执行所需的策略。由于我们提出的方法依赖于可扩展的本体，它可以通过修改我们`SNKB`中的本体轻松适应各种在线社交网络。此外，正如我们稍后在本章中详细讨论的那样，语义Web工具允许我们定义比当前OSN提供的更细粒度的访问控制策略。

本章组织如下。在[第17.2节](#ch17.xhtml#sec17_2)中，我们简要讨论了与在线社交网络相关的当前安全和隐私研究。在[第17.3节](#ch17.xhtml#sec17_3)中，我们讨论如何使用语义Web技术对社交网络进行建模。在[第17.4节](#ch17.xhtml#sec17_4)中，我们介绍了我们框架中支持的安全策略的高层概览。除了访问控制策略外，我们还陈述了过滤策略，允许用户（或其监护人之一）自定义其访问的内容。我们还引入了管理策略，规定谁有权指定访问控制和过滤策略。在[第17.5节](#ch17.xhtml#sec17_5)中，我们介绍授权本体和安全策略的`SWRL`规则编码。在[第17.6节](#ch17.xhtml#sec17_6)中，我们讨论安全策略如何执行。我们设计的实现问题在[第17.7节](#ch17.xhtml#sec17_7)中讨论。在[第17.8节](#ch17.xhtml#sec17_8)中，我们描述我们的架构，也称为我们的框架。在[第17.9节](#ch17.xhtml#sec17_9)中，我们讨论我们用语义Web-based访问控制进行社交网络实验的实验。大数据和云技术的可扩展性在[第17.10节](#ch17.xhtml#sec17_10)中讨论。[第17.11节](#ch17.xhtml#sec17_11)总结本章。[图17.1](#ch17.xhtml#fig17_1a)说明了本章的概念。我们的研究受\[[FINI2008](#ch17.xhtml#ref17_10)\]中报告的工作影响。
