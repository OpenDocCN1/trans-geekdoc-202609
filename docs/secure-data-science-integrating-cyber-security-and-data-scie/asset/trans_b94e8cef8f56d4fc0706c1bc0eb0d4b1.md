

# 关于角色层级的各种研究工作

文献中讨论了关于角色层级的各种研究工作。还有一个名为**SACMAT**（访问控制模型与技术研讨会）的会议系列，它是从基于角色的访问控制研究工作演变而来的。例如，访问是如何传播的？一个角色能否包含另一个角色？请考虑[图 2.5](#ch02.xhtml#fig2_5a)中所示的角色层级。这意味着如果我们授予层级中某个节点的访问权限，该访问权限是否会向上传播？也就是说，如果部门经理拥有对特定项目信息的访问权限，该访问权限是否会传播给父节点（即总监节点）？如果组长拥有其组内员工信息的访问权限，该访问权限是否会在角色层级中传播给作为父节点的部门经理？子节点会发生什么情况？也就是说，访问权限是否会向下传播？例如，如果部门经理拥有对特定信息的访问权限，那么他的下属是否也拥有对该信息的访问权限？是否存在下属拥有部门经理所没有的数据访问权限的情况？如果一名员工必须向两位主管汇报，一位是他的部门经理，另一位是他的项目经理，会发生什么？当部门经理参与一个项目，必须向同样为他工作的项目组长汇报时，会发生什么？

## 2.2.1.3 使用控制

最近，Sandhu 等人开发了另一种类访问控制模型，即使用控制模型，他称之为**UCON**（参见例如 [[PARK2004](#ch02.xhtml#ref2_14)] 中报道的工作）。**UCON** 模型试图将一些额外特性纳入基于角色的访问控制，包括属性可变性和义务。

## 2.2.1.4 基于属性的访问控制

由于角色在不同组织中并不统一，因此认为基于角色的访问控制不足以满足基于 Web 的系统需求。大致在同一时期，Web 服务、面向服务的架构和基于云的系统变得流行并被广泛使用。因此，为这种环境开发了一种基于声明的访问控制模型。该模型即基于属性的访问控制。在此模型中，用户对自己提出某些声明。然后，这些声明由想要授予用户资源访问权限的组织进行验证。如果用户的声明有效，则检查策略以确定此类用户是否有权访问资源。在过去十年中，基于属性的访问控制变得极其流行 **[NIST](#ch02.xhtml#ref2_15)**。

## 2.2.2 管理策略

访问控制策略规定特定用户对数据拥有的访问权限，而管理策略规定谁来管理数据。管理职责包括保持数据最新、确保数据更新时元数据也随之更新，以及确保从故障中恢复及相关活动。

通常，数据库管理员（**DBA**）负责更新元数据、索引和访问方法，并确保访问控制规则得到正确实施。系统安全官（**SSO**）也可能发挥作用。也就是说，**DBA** 和 **SSO** 可能会分担职责。安全相关问题可能由 **SSO** 负责，而数据相关问题可能由 **DBA** 负责。其他正在考虑的管理策略包括指派看管人。通常，所有者控制其创建的数据，并可在数据的整个生命周期内对其进行管理。在某些情况下，所有者可能无法管理数据，此时他们可指派看管人（即保管人）。

在分布式环境中，尤其是 Web 环境中，管理策略变得更加复杂。例如，在 Web 环境中，分发文档可能涉及多方，包括所有者、发布者和请求数据的用户。数据归谁所有？是所有者还是发布者？一旦数据离开所有者并到达发布者，发布者是否接管数据控制权？随着我们从关系数据库环境迁移到分布式环境，甚至可能是 Web 环境，有许多有趣的问题需要解答。这些还包括管理版权问题、数据质量、数据溯源和治理。近期会议上发表了许多关于管理策略的有趣论文。[图 2.6](#ch02.xhtml#fig2_6a) 说明了各种管理策略。

## 2.2.3 标识与认证

为求完整，我们将标识与认证作为自主安全讨论的一部分进行探讨。标识是指用户必须使用其用户 ID 和密码进行自我标识。认证是指系统随后将用户 ID 与密码进行匹配，以确保此人确实是其声称的那个人。用户可能因其角色不同而拥有多重身份。特别是随着 Web 服务的出现，身份管理受到了广泛关注（参见 [[BERT2006](#ch02.xhtml#ref2_5)]）。

基于密码的方案已报告出许多问题。其中之一是黑客可以闯入系统获取用户密码，然后冒充用户。在集中式系统中，问题不如在分布式环境中复杂。现在，随着万维网和电子商务应用的发展，黑客冒充合法用户导致金融组织损失数十亿美元。

最近，生物识别技术被应用于标识和认证。这些技术包括人脸识别、指纹识别和语音识别技术来认证用户。这些技术显示出巨大潜力且已投入使用。随着人脸识别技术的进步，我们可以预期生物识别技术将得到广泛应用。

## 2.2.4 数据库系统审计

数据库审计服务于多种目的。例如，审计可用于记录查询次数、更新次数、执行的事务数以及辅助存储的访问次数，以便更高效地设计系统。数据库也可出于安全目的进行审计。例如，是否有访问控制规则被绕过而向用户泄露信息？是否发生了推理问题？隐私是否被侵犯？是否发生了未经授权的入侵？

审计会创建审计跟踪，审计数据可存储在数据库中。该数据库可被挖掘以检测任何异常模式或行为。在利用数据挖掘进行审计和入侵检测方面已有大量工作。随着 Web 上电子商务交易的增多，审计跟踪分析显得尤为重要。组织应具备进行分析的能力，以确定信用卡欺诈和身份盗窃等问题。
