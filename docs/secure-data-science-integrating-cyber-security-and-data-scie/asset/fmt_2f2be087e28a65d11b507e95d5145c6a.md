
# 云数据库与语义Web技术

## 云数据库管理

运行在云端的数据库称为云数据库管理器。利用云数据库管理器有多种方式。

**第一种模型**：用户需购买*虚拟机镜像*以在云端运行数据库，数据库随后在虚拟机上运行。

**第二种模型**：数据库即服务模型；服务提供商维护数据库。用户使用数据库服务并为服务付费。例如Amazon关系型数据库服务（Amazon RDS），这是一种SQL数据库服务，具有MySQL接口 [[AMAZ](#ch04.xhtml#ref4_6)]。

**第三种模型**：云提供商代表用户托管数据库。用户既可以使用云维护的数据库服务，也可以在云端运行自己的数据库。

云数据库必须优化其查询、存储和事务处理，以充分利用云提供的服务。[图 4.7](#ch04.xhtml#fig4_7a) 展示了云数据管理。

## 4.3.4 云平台

本节讨论云服务提供商如何支持大数据管理，重点介绍Amazon DynamoDB、Microsoft Cosmos DB，以及IBM和Google的云端大数据解决方案。

### 4.3.4.1 Amazon Web Services DynamoDB

`DynamoDB`是属于Amazon Web Services (AWS)产品组合的NoSQL数据库。它同时支持文档模型和键值存储模型。高性能和高吞吐量是`DynamoDB`的目标。在存储方面，`DynamoDB`可根据应用需求动态扩展和收缩。它还拥有一个名为`Amazon DynamoDB Accelerator` (DAX)的内存缓存，可为每秒百万级请求提供毫秒级响应。更多详情请参阅 [[DYNA](#ch04.xhtml#ref4_26)]。

### 4.3.4.2 Microsoft Azure Cosmos DB

`Cosmos DB`是运行在Microsoft云平台`Azure`上的数据库。其设计初衷是可扩展性和高性能。它采用具有可用性复制的分布式模型。其可扩展架构支持多数据模型和多种编程语言。正如 [[COSM](#ch04.xhtml#ref4_22)] 所述：

> Azure Cosmos DB数据库引擎的核心类型系统基于原子-记录-序列 (ARS)。原子包含一小组原始类型（如字符串、布尔值、数字等）。记录是结构体，序列是由原子、记录或序列组成的数组。

开发者通过预配数据库账户来使用`Cosmos DB`。容器的概念用于存储存储过程、触发器和用户定义函数。该数据库账户下的实体包括容器、数据库和权限，这些实体称为资源。容器中的数据进行水平分区。更多`Cosmos DB`详情请参阅 [[COSM](#ch04.xhtml#ref4_22)]。

### 4.3.4.3 IBM云端大数据解决方案

IBM是云计算领域的领导者，包括云端大数据管理。它开发了一种利用硬件和软件集合的架构，可托管多种大数据系统。IBM提供数据库即服务，并支持数据管理和数据分析。例如：
- `Cloudant`是一个NoSQL数据层。
- `dashDB`系统是一个基于云的数据分析系统，用于执行分析。
- `ElephantSQL`是在云端运行的开源数据库。

此外，IBM云还为流计算和内容管理等多种数据管理能力提供支持。更多详情请参阅 [[IBM](#ch04.xhtml#ref4_38)]。

### 4.3.4.4 Google云端大数据解决方案

`Google Cloud Platform`是一个全面的硬件和软件集合，使用户能从Google获取各种服务。该云平台同时支持`Hadoop/MapReduce`和`Spark`平台。除了访问`BigTable`和`BigQuery`中的数据外，Google还提供分析解决方案，以及访问`YouTube`等系统的方案。更多详情请参阅 [[GOOG](#ch04.xhtml#ref4_30)]。

## 4.4 语义Web

### 4.4.1 语义Web技术

正如本章前文所述，我们开发的一些实验性大数据系统利用了云和语义Web技术。云计算已在[第 4.3 节](#ch04.xhtml#sec4_3)讨论，本节将概述语义Web技术。

当前Web技术从语法角度促进了信息集成，但在处理各种系统和应用的不同语义方面仍有大量工作要做。也就是说，当前Web技术在很大程度上依赖“人工介入”进行信息管理和集成。WWW之父Tim Berners-Lee意识到当前Web技术的不足，致力于使Web更智能。他的目标是构建一个Web，基本上能减轻人类整合分散信息源和执行大量搜索的负担。他得出结论：需要机器可理解的网页和本体来进行信息集成，从而催生了语义Web的概念 [[LEE2001](#ch04.xhtml#ref4_46)]。利用语义Web技术的Web服务称为语义Web服务。

语义Web可被视为一个高度智能和复杂的Web，几乎无需人工干预即可执行预约安排、活动协调、复杂文档搜索，以及整合分散的数据库和信息系统等任务。虽然开发此类智能Web已取得很大进展，但仍有大量工作待做。例如，本体匹配、智能代理和标记语言等技术对语义Web发展贡献巨大。尽管如此，人类仍需做决策和采取行动。自2000年代以来，语义Web有了许多发展。万维网联盟 (W3C) 正在制定语义Web标准 [[W3C](#ch04.xhtml#ref4_71)]。这些标准包括XML (可扩展标记语言)、RDF (资源描述框架) 和互操作性规范（另见 [[AKIV2012](#ch04.xhtml#ref4_2)]、[[ALIP2010a](#ch04.xhtml#ref4_4)]、[[ALIP2010b](#ch04.xhtml#ref4_5)]、[[KHAN2002](#ch04.xhtml#ref4_43)]、[[KHAN2004](#ch04.xhtml#ref4_44)] 和 [[PART2011](#ch04.xhtml#ref4_56)]）。

[图 4.8](#ch04.xhtml#fig4_8a) 展示了语义Web的分层技术栈。这是由Tim Berners-Lee开发的栈。语义Web本质上由多层组成，每层利用前一层的技术。最底层是协议层，通常不包含在语义技术讨论中。下一层是XML层。XML是一种文档表示语言。虽然XML足以指定语法，但难以用XML指定“文档D的创建者是John”这类语义。因此，W3C开发了使用XML语法的RDF。语义Web社区进一步提出了用OWL (Web本体语言) 等语言指定本体的规范。注意OWL解决了RDF的不足。为了推理各种策略，语义Web社区提出了SWRL (语义Web规则语言) 等Web规则语言。下面将描述构成语义Web的各种技术。
