

# 7.4.1 数据集描述

## 7.4.1.1 仅包含概念漂移的合成数据

SynC 仅模拟概念漂移，不包含新类别。这样做是为了表明概念漂移不会在我们的方法中错误地触发新类别检测。SynC 数据通过移动超平面生成。超平面的方程如下：

```
Σ^d[i=1] a[i] * x[i] = a[0]
```

如果 `Σ^d[i=1] a[i] * x[i] <= a[0]`，则样本为负例，否则为正例。每个样本是一个随机生成的 d 维向量 `{x[1], …, x[d]}`，其中 `x[i] ∈ [0, 1]`。权重 `{a[1], …, a[d]}` 也在范围 `[0, 1]` 内随机初始化为实数。`a[0]` 的值经过调整，使得生成的正负样本数量大致相同。这可以通过选择 `a[0] = Σ^d[i=1] a[i]` 来实现。我们还通过随机切换 `p%` 样本的标签来引入噪声，在实验中设置 `p = 5`。

有几个参数用于模拟概念漂移。参数 `m` 指定涉及权重变化的总维度百分比，设置为 20%。参数 `t` 指定每 `N` 个样本的变化幅度。在实验中，`t` 设置为 0.1，`N` 设置为 1,000。`s[i]`（`i ∈ {1, …, d}`）指定每个权重的变化方向。权重连续变化，即每生成一个样本后，`a[i]` 按 `s[i] * t / N` 进行调整。每生成 `N` 个样本后，有 10% 的概率变化方向会反转。我们总共生成 250,000 条记录。

## 7.4.1.2 包含概念漂移和新类别的合成数据

这种合成数据同时模拟概念漂移和新类别。每个类别的数据点使用高斯分布生成，不同类别具有不同的均值（-5.0 到 +5.0）和方差（0.5 到 6）。此外，为了模拟数据流的演化特性，不同类别的概率分布随时间变化。这导致某些类别在不同时间出现，而其他类别消失。

为了引入概念漂移，某个百分比属性的均值以恒定速率发生偏移。与 SynC 数据集类似，这种变化率也由参数 `m`、`t`、`s` 和 `N` 以类似方式控制。

数据集经过归一化，使所有属性值落在范围 `[0, 1]` 内。我们生成的 SynCN 数据集包含 20 个类别、40 个实值属性，共 400K 个数据点。

## 7.4.1.3 真实数据 – KDD Cup 99 网络入侵检测

我们使用了该数据集的 10% 版本，它更集中，因此比完整版本更具挑战性。它包含约 490,000 个实例。这里不同类别频繁出现和消失，使得新类别检测极具挑战性。该数据集包含从 MIT Lincoln Labs 为期两周的局域网流量中提取的 TCP 连接记录。每条记录指代正常连接或攻击。共有 22 种攻击类型，如 `buffer-overflow`、`portsweep`、`guess-passwd`、`neptune`、`rootkit`、`smurf`、`spy` 等。因此共有 23 个不同的数据类别。大多数数据点属于正常类别。每条记录包含 42 个属性，如连接持续时间、传输字节数、root 访问次数等。我们仅使用 34 个连续属性，并移除分类属性。该数据集也经过归一化，将属性值保持在 `[0, 1]` 范围内。

## 7.4.1.4 真实数据 – Forest Cover (UCI 存储库)

该数据集包含不同森林类型的地理空间描述。它包含 7 个类别、54 个属性，约 581,000 个实例。我们对数据集进行归一化，并安排数据，使得在任何数据块中最多共存 3 个、最少共存 2 个类别，且新类别随机出现。

# 7.4.2 实验设置

我们使用 Java 实现算法。决策树代码改编自 Weka 机器学习开源存储库（`http://www.cs.waikato.ac.nz/ml/weka/`）。实验在配备 2GB 内存和 3GHz 双核 CPU 的 Intel P-IV 机器上运行。除非另有说明，参数设置如下：
(i) `K`（每个数据块的伪点数）= 50，
(ii) `N` = 50，
(iii) `M`（集成大小）= 6，
(iv) 数据块大小 = 合成数据集 1,000，真实数据集 4,000。
这些参数值经过调优以达到整体满意的性能。

## 7.4.2.1 基线方法

据我们所知，没有方法能同时对数据流进行分类和检测新类别。因此，我们将 MineClass 与两种基线技术的组合进行比较：`OLINDDA` [SPIN2007] 和加权分类器集成（`WCE`）[WANG2003]，前者作为新类别检测器，后者执行分类。对于每个数据块，我们首先使用在线新颖性与漂移检测算法（`OLINDDA`）检测新类别实例。数据块中所有其他实例假定属于现有类别，使用 `WCE` 进行分类。我们选择 `OLINDDA` 作为新颖性检测器，因为它是最近提出的算法，据 [SPIN2007] 显示，它在数据流新颖性检测技术中表现优于其他方法。

然而，`OLINDDA` 假设只有一个“正常”类别，所有其他类别都是“新颖”的。因此，它不能直接应用于多类新颖性检测问题，在该问题中，任意类别组合都可视为“现有”类别。我们提出两种替代方案。第一，我们为每个类别构建并行的 `OLINDDA` 模型，它们同时演化。每当新类别实例出现，我们就为该类别创建一个新的 `OLINDDA` 模型。如果**所有现有类别模型**都将测试实例识别为新颖，则该实例被判定为新颖。我们将这种基线方法称为 `WCE-OLINDDA_PARALLEL`。第二，我们最初用所有可用类别构建一个 `OLINDDA` 模型。每当发现新类别，该类别就被吸收进现有的 `OLINDDA` 模型。因此，整个流过程中仅维护一个“正常”模型。这称为 `WCE-OLINDDA_SINGLE`。在所有实验中，这两种技术的集成大小和数据块大小保持相同。此外，`WCE` 和 `MC` 使用相同的基学习器。`OLINDDA` 的参数设置为：
(i) 每簇数据点数（`N[excl]`）= 15，
(ii) 更新现有模型所需的最少正常实例数 = 100，
(iii) 构建初始模型所需的最少实例数 = 30。
这些参数根据 [SPIN2007] 中的默认值或通过试错选择，以获得整体满意的性能。此后我们将使用缩写：`MC` 代表 MineClass，`W-OP` 代表 `WCE-OLINDDA_PARALLEL`，`W-OS` 代表 `WCE-OLINDDA_SINGLE`。

# 7.4.3 性能研究

## 7.4.3.1 评估方法

我们使用以下性能指标进行评估：
`M[new]` = 被误分类为现有类别的新类别实例百分比，
`F[new]` = 被错误识别为新类别的现有类别实例百分比，
`ERR` = 总误分类错误率（%）（包含 `M[new]` 和 `F[new]`）。
我们用前 `M` 个数据块在每种方法中建立初始模型。从第 `M + 1` 个数据块开始，我们先评估每种方法在该数据块上的性能，然后用该数据块更新现有模型。每种方法在每个数据块上的性能指标被保存并平均，以产生汇总结果。
