

### 8.6.3 Hadoop 分布式系统搭建

我们实验所用的分布式系统由一个包含十个节点的集群组成。每个节点具有相同的硬件配置：Intel Pentium IV 2.8 GHz 处理器、4GB 主内存和 640GB 硬盘空间。软件环境包括 Ubuntu 9.10 操作系统、Hadoop-0.20.1 分布式计算平台、JDK 1.6 Java 开发平台以及 100MB 局域网链路。

### 8.7 讨论

我们的工作考虑了一个纯粹由句法特征组成的特征空间：从可执行代码段、静态数据段、头部以及不可信文件的所有其他内容中提取的二进制 `n`-gram。更高层级的结构特征（如调用图和控制流图）以及动态特征（如运行时轨迹）超出了我们当前的研究范围。尽管如此，`n`-gram 特征已被观察到对恶意软件检测具有极高的判别能力，这既得到了大量先前工作的证明，也得到了我们实验的验证。部分原因在于，跨越整个二进制文件内容（包括头部和数据表）的 `n`-gram 集合捕获了重要的底层结构细节，而这些细节往往被更高层级的表示形式所抽象掉了。例如，恶意软件通常包含使用非标准工具汇编和链接的手写汇编代码。这使得攻击者能够实现高级源语言和标准编译器无法提供的二进制混淆和底层漏洞利用。因此，恶意软件通常包含异常的指令编码、头部结构和链接表，它们的异常只能在原始二进制层面看到，而无法在汇编代码清单、控制流图或系统 API 调用轨迹中发现。将特征空间扩展以包含这些额外的高层级特征，需要一种高效可靠的方法来收集它们，并在特征选择期间评估其相对判别能力，这被保留为未来的研究课题。

文献 [MASU2011] 中报告的实证结果证实了我们的分析，即多划分、多块方法的表现应优于单块、单划分方法。直观上，基于多个块训练的分类器应比基于单个块训练的分类器具有更高的预测准确性，因为其拥有更大的训练数据。此外，如果通过多划分训练数据来训练多个分类器，所得分类器集成的预测准确性应高于基于相同训练数据训练的单个分类器，这是由于集成相对于单一分类器具有错误降低的能力。另外，EMPC 的准确性优势可归结为我们的工作与 AWE 之间的两个重要差异。首先，当 AWE 在集成更新过程中移除一个分类器时，来自相应块的所有信息都会被遗忘；但在 EMPC 中，来自较早块的一个或多个分类器可能会保留下来。因此，EMPC 的集成更新倾向于保留比 AWE 更多的信息，从而形成更好的集成。其次，AWE 至少需要 `Kv` 个数据块，而 EMPC 至少需要 `K + r − 1` 个数据块即可获得 `Kv` 个分类器。因此，AWE 倾向于在集成中保留比 EMPC 古老得多的分类器，导致一些过时的分类器可能对分类准确性产生负面影响。

然而，更高的准确性伴随着运行时间的增加成本。理论上，EMPC 最多比 AWE（其在准确性方面最接近的竞争对手）慢 `rv` 倍。这在实证评估中也显而易见，评估显示 EMPC 的运行时间在 AWE 的五倍以内（当 `r` = 2 且 `v` = 5 时）。不过，可以采用一些优化来降低运行时成本。首先，可以轻松实现每个划分训练的并行化，将训练时间减少 `v` 倍。其次，集成中每个模型的分类也可以并行完成，从而将分类时间减少 `Kv` 倍。因此，训练和分类的并行化应至少将运行时间减少 `v` 倍，使其接近 AWE 的运行时间。或者，如果无法并行化，可以降低参数 `v` 和 `r`，以降低运行时成本为代价牺牲预测准确性。在这种情况下，可以通过使用不同的 `v` 和 `r` 值评估流的前几个块，并选择最合适的值，来获得运行时间和预测准确性之间的理想平衡。

### 8.8 总结与展望

许多入侵检测问题可以表述为针对无限长、概念漂移数据流的分类问题。概念漂移发生在这些流中，因为攻击者会对防御做出反应并进行适应。我们将恶意代码检测和僵尸网络流量检测都表述为此类问题，并引入了 EMPC，这是一种用于自动分类无限长、概念漂移流的新型集成学习技术。将 EMPC 应用于从多态恶意软件和僵尸网络流量样本获得的真实数据流，其检测准确率优于其他流数据分类技术。这表明该方法对于入侵检测和更通用的数据流分类均有用且有效。

EMPC 采用广义的多划分、多块集成学习。理论和实证评估均表明，与现有的单划分、单块集成方法相比，该技术显著降低了预期分类误差。此外，我们展示了 EMPC 可以基于 MapReduce [DEAN2008] 优雅地在云计算框架中实现。结果是一个低成本、可扩展的流分类框架，具有高分类准确性和低运行时开销。

至少有两个针对我们技术的扩展为未来工作提供了有前景的方向。首先，我们当前的特征选择过程仅关注基于信息增益作为选择标准的最佳 `S` 个特征。通过利用近期关于监督降维技术 [[RISH2008](#ch08.xhtml#ref8_31), [SAJA2005](#ch08.xhtml#ref8_32)] 的工作来改进特征选择，分类准确性有望进一步提高。其次，通过利用云计算架构中可用的额外并行性，可以提高我们方法的运行时性能。例如，集成的分类器可以在 MapReduce 框架中作为 Mapper 并行运行，Reducer 则聚合结果进行投票。同样，下一轮集成的候选分类器也可以并行训练和评估。以这种方式重新构思系统的集成组件，可能会显著缩短处理时间，从而有机会投入更多处理时间用于分类以提高准确性。其他大数据平台（如 Storm 和 Spark）也需要被探索以托管我们的算法。最后，虽然用于分析收集的恶意软件数据量可能巨大，但我们需要探索使用 NoSQL 数据库系统（如 CouchDB）来存储、管理和查询数据。
