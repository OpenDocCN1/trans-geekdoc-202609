
存在致力于研究在 RDF 存储上强制执行策略的先前研究。其中包括 [[CARM2004](#ch16.xhtml#ref16_15)] 的工作，该工作使用 RDF 进行策略规范和执行。此外，策略通常用 RDF 编写。在 [[JAIN2006](#ch16.xhtml#ref16_35)] 中，作者提出了一种用于 RDF 的访问控制模型。他们的模型基于 RDF 数据语义，并结合了 RDF 和 RDF Schema (RDFS) 蕴含。此处，保护在资源级别提供，这为他们的框架增加了粒度。其他强制执行 RDF/OWL 策略的框架包括 [KAGA2002, [USZO2004](#ch16.xhtml#ref16_63)]。[USZO2004] 描述了 KAoS，这是一个使用 OWL 的策略和域服务框架，既用于表示策略也用于表示域。[KAGA2002] 引入了 Rei，这是一个灵活且允许陈述不同种类策略的策略框架。Rei 的扩展最近已被提出 [[KHAN2010](#ch16.xhtml#ref16_42)]。策略规范语言允许用户基于 RDF、DAML+OIL 和 OWL 中的领域特定本体开发声明式策略。[[REDD2005](#ch16.xhtml#ref16_50)] 的作者还引入了一个原型 RAP，用于实现具有集成维护能力和访问控制的 RDF 存储。然而，这些框架并未解决 RDF 存储变得非常大的情况，或策略无法随数据扩展的情况。在一个由 IARPA 资助的项目下，我们开发了用于超大规模 RDF 图处理的技术 [[UTD2](#ch16.xhtml#ref16_65)]。

### 16.4.1.4 Hadoop 存储架构

针对 RDF 数据的大规模分布式存储和检索技术引起了极大的关注。Castagna 等人 [[CAST2009](#ch16.xhtml#ref16_17)] 的工作展示了 RDF 数据并行处理框架的理论设计。这项工作主张使用具有不同粒度级别的数据分发模型，如三元组级别、图级别和数据集级别。针对这种分布式模型的查询随后被划分为一组子查询，分发到包含分布式数据的机器上。所有子查询的结果随后将被合并，以向用户应用程序返回完整结果。研究界存在该理论概念的多种实现。这些工作包括 Choi 等人 [[CHOI2009](#ch16.xhtml#ref16_19)] 和 Abraham 等人 [[ABRA2010](#ch16.xhtml#ref16_2)] 的工作。一种单独的用于存储和检索 RDF 数据的技术利用了对等系统 [[ABER2004](#ch16.xhtml#ref16_1), [CAI2004](#ch16.xhtml#ref16_14), [HART2007](#ch16.xhtml#ref16_32), [VALL2006](#ch16.xhtml#ref16_66)]。然而，此类系统存在一些缺点，因为对等系统需要拥有超级节点来存储关于 RDF 数据在节点间分发的信息。另一个缺点是需要将 SPARQL 查询联合分发到网络中的每个节点。

### 16.4.1.5 分布式推理

InteGrail 系统使用分布式推理，其愿景是塑造未来的欧洲铁路组织 [[INTE2009](#ch16.xhtml#ref16_34)]。在 [[URBA2009](#ch16.xhtml#ref16_62)] 中，作者展示了基于 MapReduce 的可扩展 RDFS 推理实现，该实现可在两小时内从真实数据集推断出 300 亿个三元组，分别产生 123,000 三元组/秒的输入吞吐量和 327 万三元组/秒的输出吞吐量。他们展示了一些在 MapReduce 中编码 RDFS 规则集的非平凡优化，并使用多个真实数据集在包含 64 个计算节点的集群上评估了其实现的可扩展性。

### 16.4.1.6 访问控制和策略本体建模

已有一些尝试使用语义 Web 技术来建模访问控制和策略模型。在 [[CIRI2007](#ch16.xhtml#ref16_20)] 中，作者展示了如何使用 OWL 和描述逻辑来构建访问控制系统。他们开发了一个高层 OWL-DL 本体来表达基于角色的访问控制系统的要素，并构建了一个领域特定本体来捕获示例场景的特征。最后，他们将这两个产物结合起来，以考虑策略定义和访问控制决策中的属性。在 [[REUL2010](#ch16.xhtml#ref16_51)] 中，作者首先展示了一个基于 DOGMA 的安全策略本体，DOGMA 是一个形式化的本体工程框架。该本体涵盖了安全策略的核心要素（即条件、动作、资源），并可轻松扩展以表示特定的安全策略，如访问控制策略。在 [[ANDE2009](#ch16.xhtml#ref16_4)] 中，作者提出了一种本体驱动的方法，用于信息系统的多级访问控制和溯源。

## 16.4.2 商业发展

### 16.4.2.1 RDF 处理引擎

研究和商业 RDF 处理引擎包括 HP 实验室的 Jena、BigOWLIM 和 RDF-3X。尽管这些工具中的一些存储模式和查询处理机制是专有的，但它们都基于某种类型的 RDF 数据索引策略。然而，只有极少数工具使用以云为中心的架构来处理 RDF 数据，而且这些工具无法扩展到非常大数量的三元组。相比之下，CAISS++ 中的查询处理器将构建为一个行星级的 RDF 处理引擎，支持所有 SPARQL 算子，并将为 SPARQL 查询提供优化的执行策略，可扩展到数十亿个三元组。

### 16.4.2.2 基于语义 Web 的安全策略引擎

正如 [第 16.2 节](#ch16.xhtml#sec16_2) 所述，目前关于基于语义 Web 的策略规范和执行的工作，并未解决针对海量数据和大量用户的策略生成和执行问题。**云：** 据我们所知，不存在针对以云为中心的 AIS 的重大商业竞争。由于我们采用了模块化方法来创建工具，我们可以单独迭代优化每个组件（策略引擎、存储架构和查询处理器）。由于我们采取了基于组件的方法，我们将能够适应我们使用的平台的变化（例如 Hadoop、RDF、OWL 和 SPARQL），而无需依赖特定平台的特定功能。

## 16.5 总结与展望

本章描述了我们对一个称为 CAISS 的基于云的信息共享系统的设计和实现。CAISS 利用了我们开发的几项技术以及开源工具。我们还描述了一个理想的基于云的 AIS 系统 CAISS++ 的设计。我们讨论了一系列 CAISS、CAISS+ 和一个演示系统的实现。

我们开发了 CAISS 和 CAISS++ 的概念验证原型。在 CAISS 的实现中，我们在云中利用了我们的 SPARQL 查询处理器，策略以 XACML 和 RDF 两种形式指定。我们的策略包括访问控制策略以及信息共享策略。在 CAISS++ 的实现中，我们用 OWL 指定策略，在云中开发了策略引擎，并将其与 SPARQL 数据引擎集成。这些系统在 [[CADE2012a](#ch16.xhtml#ref16_12)] 和 [CADE2012b] 中进行了讨论。
