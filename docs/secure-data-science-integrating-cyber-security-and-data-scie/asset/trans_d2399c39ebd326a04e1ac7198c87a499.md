
近年来，检测恶意可执行文件方面已投入大量精力。自动化检测过程主要有两种主流技术：行为分析和基于内容的分析。行为分析法主要用于检测移动恶意代码。该技术用于分析网络流量特征，如源/目的端口、IP 地址、各种数据包级/流级统计信息，以及应用级特征，如电子邮件附件类型、附件大小等。行为分析法的示例包括社交网络分析 [GOLB2004, NEWM2002] 和统计分析 [[SCHU2001a](#ch06.xhtml#ref6_17)]。[MASU2007a] 提出了一种基于数据挖掘的行为分析法来检测电子邮件蠕虫。[[GARG2006](#ch06.xhtml#ref6_4)] 结合机器学习应用特征提取技术进行 `masquerade detection`。他们从基于 GUI 系统的用户行为中提取特征，如鼠标速度、每会话点击次数等。然后将问题建模为二分类问题，并使用 SVM 进行训练和测试。我们的方法是基于内容的，而非行为分析。

基于内容的方法分析可执行文件的内容。其中一些试图从网络数据包载荷中自动生成签名。示例包括 EarlyBird [[SING2003](#ch06.xhtml#ref6_19)]、Autograph [[KIM2004](#ch06.xhtml#ref6_7)] 和 Polygraph [NEWS2005]。相比之下，我们的方法不需要签名生成或签名匹配。其他一些基于内容的技术从可执行文件中提取特征并应用机器学习来检测恶意可执行文件。示例见 [[SCHU2001b](#ch06.xhtml#ref6_18)] 和 [KOLT2004]。[SCHU2001a] 和 [SCHU2001b] 中的工作使用 GNU Bin-Utils 从 Windows PE 可执行文件 [[CYGN1999](#ch06.xhtml#ref6_2), [Windows P.E.](#ch06.xhtml#ref6_20)] 的头部提取 DLL 调用信息，使用 GNU `strings` 提取字符串。此外，他们还使用字节序列作为特征。我们使用字节序列和 DLL 调用信息，但也应用反汇编并使用汇编指令作为特征。此外，我们提取各种长度（2 到 10 字节）的字节模式，而他们仅提取 2 字节长度的模式。[KOLT2004] 做了类似的工作。他们从二进制可执行文件中提取二进制 `n-gram` 特征，将其应用于不同的分类方法，并报告准确率。我们的模型不同于 [KOLT2004]，因为我们不仅从反汇编的可执行文件中提取二进制 `n-gram`，还提取汇编指令序列，并从程序头收集 DLL 调用信息。我们仅将模型性能与 [KOLT2004] 进行比较，因为他们报告的准确率高于 [SCHU2001a] 和 [SCHU2001b] 中给出的准确率。

## 6.2.3 混合特征检索模型

我们的 HFR 模型是恶意代码检测中的一个新颖思路。它利用从二进制可执行文件获得的信息，从反汇编的可执行文件中提取有用特征。然后将汇编特征与其他特征（如 DLL 函数调用和二进制 `n-gram` 特征）相结合。我们解决了许多棘手的实现问题，并提供了高效、可扩展且实用的解决方案。实施过程中面临的困难与内存限制和长运行时间有关。通过使用高效的数据结构、算法和磁盘 I/O，我们能够实现一个快速、可扩展且稳健的恶意代码检测系统。我们在两个具有不同类分布的数据集上运行实验，并表明更真实的分布能提高模型性能。

我们的模型也存在一些局限性。首先，它无法直接处理混淆的 DLL 调用或加密/打包的二进制文件。已有技术可用于检测二进制文件中的混淆 DLL 调用 [[LAKH2005](#ch06.xhtml#ref6_9)] 并自动解包打包的二进制文件。我们可以应用这些工具进行去混淆/解密，并将其输出用于我们的模型。尽管尚未实现，但我们期待在未来的版本中将这些工具与我们的模型集成。其次，当前实现是一种离线检测机制。这意味着它不能直接部署在网络上以检测恶意代码。然而，它可以近实时地检测恶意代码。

我们将在未来的工作中解决这些问题，并承诺解决这些问题。我们还提出了几种模型修改方案。例如，我们希望将我们的特征与可执行文件的 `run-time` 特征相结合。此外，我们提议建立一个特征数据库，存储所有特征并增量更新。这将节省大量训练时间和内存。我们的方法如 [图 6.3](#ch06.xhtml#fig6_3a) 所示。
