
我们设计安全机制来控制 SPARQL 查询的评估，以防止机密溯源信息的泄露。我们的方法是通过添加在三元组模式上求值的过滤器和/或属性函数来修改 SPARQL 查询中的图模式。这些方法返回的答案可能与用户最初的查询意图不同。在这种情况下，可能需要决定采取适当的行动。我们提出了两种可遵循的方法。第一种方法根据初始查询检查查询的有效性，并通知用户无法保证查询的有效性。第二种方法考虑到关于查询结果有效性的反馈可能会导致用户得出不良推断。

在某些情况下，可能只返回已知符合策略约束的答案。在其他情况下，可能需要根据某些转换规则，用一个满足查询的受限子图来替换它，该规则使发布的知识库与策略约束保持一致。另一种方法可能是“撒谎”；这类似于多级安全数据库中的多实例化，不同权限级别的用户看到不同版本的现实。

### 18.3.4 为强制执行约束而进行的查询修改

修改 SPARQL 查询中图模式的方法使用不同的技术，例如 SPARQL 过滤器和属性函数、图转换以及匹配/应用模式。为了根据安全分类确定三元组的类型，推理引擎将使用领域本体来确定每个数据项所属的概念，以及基于 SPARQL `BGP`（基本图模式匹配）转换的查询修改。

#### 18.3.4.1 SPARQL 查询过滤器

SPARQL 规范提供了另一种修改图模式的技术 [[PRUD2006](#ch18.xhtml#ref18_27)]。SPARQL `FILTER` 将解限制为使过滤器表达式求值为 `TRUE` 的那些。我们简要讨论如何通过应用 SPARQL 过滤器来重写 SPARQL 查询。以下是一个请求患者年龄的 SPARQL 查询。

```
PREFIX med: <http://cs.utdallas.edu/semanticweb/Prov-AC/medical#>

SELECT ?patient

WHERE { ?patient med:age ?age }
```

查询修改后，我们将查询限制为仅年龄大于 18 岁的患者。

```
PREFIX med: <http://cs.utdallas.edu/semanticweb/Prov-AC/medical#>

SELECT ?patient

WHERE { ?patient med:age ?age
FILTER (?age > 18)
}
```

#### 18.3.4.2 属性路径

属性路径是图中两个图节点之间可能的路线。一个简单的情况是长度恰好为 1 的属性路径，即三元组模式。属性路径表达式（或简称“路径”）类似于正则表达式字符串，但作用于属性而非字符。[表 18.1](#ch18.xhtml#table18_1a) 描述了正则路径表达式及其说明。

[表 18.1 正则路径表达式](#ch18.xhtml#Ttable18_1)

| Uri | 一个 URI 或前缀名。长度为一的路径。 |
| --- | --- |
| `^elt` | 反向路径（对象到主语）。 |
| `(elt)` | 分组路径 elt，括号控制优先级。 |
| `elt1/elt2` | `elt1` 后跟 `elt2` 的序列路径 |
| `elt1 ^ elt2` | `elt1 ^ elt2` 的简写，即 elt1 后跟反向 elt2。 |
| `elt1 \| elt2` | `elt1` 或 `elt2` 的替代路径（尝试所有可能性） |
| `elt*` | 零个或多个 `elt` 出现的路径。 |
| `elt+` | 一个或多个 `elt` 出现的路径。 |
| `elt?` | 零个或一个 `elt` 的路径。 |
| `elt{n,m}` | `elt` 出现次数在 n 和 m 之间的路径。 |
| `elt{n}` | 恰好 n 次 elt 出现。固定长度路径。 |
| `elt{n,}` | n 个或更多 `elt` 出现。 |
| `elt{,n}` | `elt` 出现次数在 0 和 n 之间。 |
| `!uri` | 匹配非 uri 属性的路径（否定属性集） |
| `!(uri1 \| ... \| uriN)` | 匹配非 uri1...uriN 中任意属性的路径（否定属性集） |

#### 18.3.4.3 属性路径查询

这些查询允许我们修改三元组模式的属性（注意该属性可以是有向标签边，也可以是主语和宾语之间的有向路径）。一个重要应用是支持正则表达式。我们打算在图模式上建立路径约束，作为减少导致推理问题泄露的一种方式。我们编写的代码可以根据用户查询的内容执行。该代码可以检查用户查询的各个方面，例如三元组或三元组模式的字面文本，并采取即时行动以确保适当的策略约束保持完整。以下是一个在溯源图上使用正则表达式作为 `SELECT` 查询 `BGP` 一部分的示例，该示例使用 `OPM` 词汇表。

```
{
  med:Doc_n_4 gleen:Subgraph("([opm:WasDerivedFrom]*/[opm:WasGeneratedBy]/[opm:WasControlledBy])" ?x).
}
```

此查询模式将授予对通往 John 记录路径上的工件、过程和代理的访问权限。此查询使用 Gleen 正则表达式库编写 [[DETW2008](#ch18.xhtml#ref18_7)]。Gleen 库 [DETW2008] 提供了两个有用的函数：`OnPath` 和 `Subgraph`。`OnPath` 函数可用于定位图中所有与查询资源处于特定关系模式的资源，通过返回可达资源集合来实现。`Subgraph` 函数返回通往这些结果的路径上遍历的资源和属性集合。

#### 18.3.4.4 查询修改概述

SPARQL 查询修改的概述如下：

1.  遍历图模式。
2.  识别图模式中每个三元组 `t` 的 `sub(t)`、`obj(t)`、`pred(t)`。
3.  如果 `sub(t)`、`obj(t)` 或 `pred(t)` 是机密的，则隔离 `t` 或对其进行转换。
4.  创建一个包含修改后图模式的新查询。

#### 18.3.4.5 SPARQL 查询 BGP 的图转换

SPARQL 基于图模式匹配，SPARQL 查询 `BGP` 是一个图模式（即一组三元组）[PRUD2006]。

**定义 18.1：** *（图模式）SPARQL 图模式表达式递归定义如下*：

1.  三元组模式是一个图模式。
2.  如果 `P1` 和 `P2` 是图模式，则表达式 (`P1 AND P2`)、(`P1 OPT P2`)、(`P1 UNION P2`) 是图模式。
3.  如果 `P` 是一个图模式，`R` 是一个内置 SPARQL 条件，则表达式 (`P FILTER R`) 是一个图模式。
4.  如果 `P` 是一个图模式，`V` 是一个变量集合，`X ∈ U ∪ V`，则 (`X GRAPH P`) 是一个图模式。

在 SPARQL 查询重写过程中，`BGP` 将被一个更新的图模式替换。图转换规则将原始 `BGP` 作为其 `LHS`（左侧），并指定另一个模式作为 `RHS`（右侧）。

**示例 18.2：** *隐藏患者的手术信息*。

```
{
  med:Doc_n_4 gleen:OnPath("([opm:WasDerivedFrom]*/[opm:WasGeneratedBy])" ?x).
}
```

此模式匹配这样一条路径：患者记录中的一个条目（可选择性地源自患者记录的其他版本）是作为某个过程的结果而创建的。该过程即为手术。当此模式作为图转换规则的 `LHS` 时，可以被规则的 `RHS`（即另一个模式）替换，从而不泄露手术信息。一个可能的 `RHS` 模式如下：

```
{
  med:Doc_n_4 gleen:OnPath("([opm:WasDerivedFrom])" ?x).
}
```

此模式将仅返回患者记录的前一个版本，而不包含任何记录版本具有通往手术路径的条目。
