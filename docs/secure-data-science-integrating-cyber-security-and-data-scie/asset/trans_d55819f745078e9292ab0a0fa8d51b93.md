

## 4. QS 数据删除/清洗支持

正如我们之前讨论的，出于隐私和效率原因，我们可能希望删除或清洗部分数据。评估数据删除或清洗的效率影响很简单，但评估其对隐私的影响更具挑战性。*William Weld 重识别* [[SWEE2002](#ch13.xhtml#ref13_72)] 就是一个惊人的例子，仅将记录清洗至（出生日期、性别、邮政编码）并不能防止该事件。一种富有成效的方法是研究特定清洗手段针对特定对手的有效性 [[HEAT2013](#ch13.xhtml#ref13_31)]。但我们认为，通过定量信息流分析可以实现更强的隐私保证。其思路是将删除/清洗机制视为一个信息论信道，该信道接收原始数据并输出清洗后的数据。该信道的泄露量量化了清洗手段针对任意对手的有效性。正如 [13.2.2 节](#ch13.xhtml#sec13_002_002) 所讨论的，一个挑战是存在*许多*泄露度量，具体取决于操作场景，哪个最合适可能不同。因此，专注于*最小容量* 很有吸引力，根据 [[ALVI2012](#ch13.xhtml#ref13_2)] 的奇迹定理，它是所有场景下泄露的上界。最小容量也相对容易计算；例如，在确定性信道的情况下，它只需计算可行信道输出的数量。以（出生日期、性别、邮政编码）信道为例，可行输出的数量可粗略估计为约 2.4 亿。（大约有 40,000 个邮政编码，每个邮政编码的平均人口约为 8000 人，即每种性别约 4000 人。由于有 36,500 个可能的出生日期，我们可以假设某一邮政编码内每种性别的 4000 人大多拥有不同的出生日期，从而得到 40,000 × 2 × 3000 = 2.4 亿个可行输出。）因此，如果秘密是一个均匀分布的美国人，该信道会使其被正确猜测的脆弱性增加 2.4 亿倍，导致后验脆弱性为 240/320 = 0.75，表明这种清洗完全不充分。我们随后需要开发具有较小最小容量的清洗机制，从而能够精确陈述它们提供的隐私保护。一个挑战是秘密之间可能存在*相关性*。[[ALVI2014](#ch13.xhtml#ref13_3)] 给出了任意相关性存在下的一些泄露界限，但我们需要进一步探索这一点。关于数据清洗的更多细节见 [[RACH2013](#ch13.xhtml#ref13_59), [RACH2014a](#ch13.xhtml#ref13_60), [RACH2014b](#ch13.xhtml#ref13_61)]。

### 13.3.3 隐私感知数据分析与共享

我们认为，要从 QS 数据中创造更多价值，需要在存储和查询框架之上支持更多功能。每个人收集的个人数据可以以不同方式使用，以造福个人、他人和整个社会。例如，通过收集和聚合数百万人的运动活动数据与血压数据，可以轻松开展大规模医学研究项目，以了解规律运动对高血压的影响。然而，即使个人有动机共享数据，隐私顾虑也可能阻碍这种共享。因此，支持隐私感知共享至关重要。因此，我们需要允许指定和演进访问控制策略的技术，以支持与其他个人选择性地共享个人数据。

在某些场景中，直接允许应用访问哪怕是数据的一个子集也可能泄露敏感信息，因此我们可能希望共享本地挖掘出的结果。例如，可以在本地挖掘传入的 QS 数据以发现有趣的关联规则（例如，用于录入饮食信息的健身应用可能与血压测量数据相结合以发现关联）。这样，我们可以将应用的访问权限限制在少数数据挖掘或查询结果上（例如，本地关联规则结果）。此外，用户的数据可以由第三方开发的应用在本地挖掘，但仅当用户明确批准共享结果时才可共享。

此外，来自不同个人的数据可能需要集成，以创建聚合/样本级/人口级模型。促进此类数据共享的一种方法是使用洋葱路由等技术（例如使用 Tor [[DING2004](#ch13.xhtml#ref13_18)]）发送数据，以避免数据被关联到捐赠数据的个人。然而，关于可识别性的先前研究 [[SWEE2002](#ch13.xhtml#ref13_72)] 明确表明，即使数据不包含标识符并使用洋葱路由发送，仍可用于识别个人。另一种选择可能是向数据添加噪声，使共享数据变得不那么准确（例如，随机响应类型应用 [[ERLI2014](#ch13.xhtml#ref13_22)]），从而降低对个人造成负面结果的可能性。我们认为，需要探索适用于 QS 数据并能支持大量应用的正确技术组合。特别重要的是要有合适的隐私感知技术，并提供工具和指南，使个人能够权衡隐私风险与个人收益。

最后，正如本章前几节所示，为了使数据共享方案实现其为个人用户强制执行个性化隐私策略的目标，界面需要设计为满足用户需求并做到“用户友好”。为了让用户允许数据共享，他们必须相信其数据将按照其意愿受到保护，且不会面临泄露和攻击的风险。此外，用户必须能够理解策略管理选项，以便了解他们的选择及其可能的后果。由于这些选项涉及可收集的数据及其收集场景，以及谁将被允许访问其数据，用户进行策略指定必然是一个复杂的过程。因此，用户定义其策略和设置数据管理选项所需的界面交互应尽可能简单直接，并允许个性化。并非所有用户都希望对其个人信息进行详细控制，因此界面需要支持不同粒度级别的决策，并提供大多数用户可接受的智能默认设置。智能默认设置至关重要，因为大多数用户不会更改隐私/安全设置（例如，>90% 的 Google 账户未启用双因素认证 [[SULL18](#ch13.xhtml#ref13_68)]）。
