
此外，正如[第4章](#ch04.xhtml#chapter4)所述，语义Web技术正在开发中，旨以标准化方式呈现数据，使得数据既能被人类也能被机器检索和理解。历史上，网页是以纯HTML（超文本标记语言）文件发布的，这些文件不适合推理。相反，机器将这些HTML文件视为一袋关键词。研究人员正在开发已标准化的语义Web技术，以解决此类缺陷。最著名的标准是`Resource Description Framework (RDF)` [[W3b](#ch15.xhtml#ref15_51)]、`SPARQL Protocol and RDF Query Language` [[W3c](#ch15.xhtml#ref15_52)]（`SPARQL`）。`RDF`是存储和表示数据的标准，而`SPARQL`是从`RDF`存储中检索数据的查询语言。`RDF`被广泛用于表示社交网络。云计算系统可以利用这些语义Web技术的力量来表示和管理社交网络，从而使这些网络的用户具备为数据密集型应用高效存储和检索数据的能力。

语义Web技术对于维护云中的数据可能特别有用。基于语义Web的社交网络提供了以标准化方式指定和查询异构数据的能力。此外，使用`Web Ontology Language (OWL)`，本体、不同的模式、类、数据类型和关系可以被指定，而无需牺牲标准的`RDF/SPARQL`接口。反之，云计算解决方案可能对基于语义Web的大数据社区（如社交网络社区）大有裨益。语义Web数据集正呈指数级增长。在Web领域，可扩展性至关重要。然而，高速响应时间在Web社区中也至关重要。我们相信云计算范式提供了一种能够同时实现这两个目标的解决方案。

现有的商业工具和技术在云计算环境下扩展性不佳。研究人员最近才开始关注这些问题。他们正在提议从头构建系统。在[[WANG2010](#ch15.xhtml#ref15_56)]中，研究人员为一种新的分布式数据库[[COMP](#ch15.xhtml#ref15_14)]提出了一种索引方案，该数据库可用作云系统。当涉及到诸如`RDF`之类的语义Web数据时，我们面临着类似的挑战。随着存储变得更便宜，以及存储和检索大量数据的需求，开发处理数十亿`RDF`三元组（需要TB级磁盘空间）的系统不再是遥不可及的前景。研究人员已经在处理数十亿三元组[[NEWM2008](#ch15.xhtml#ref15_37), [ROHL2007](#ch15.xhtml#ref15_41)]。竞赛正在组织中，以鼓励研究人员构建高效的存储库[[CHAL](#ch15.xhtml#ref15_8)]。目前，语义Web技术只有少数几个框架（例如`RDF-3X` [[NEUM2008](#ch15.xhtml#ref15_36)]、`Jena` [[CARR2004](#ch15.xhtml#ref15_7)]、`Sesame` [[OPEN](#ch15.xhtml#ref15_40)]和`BigOWLIM` [[KIRY2005](#ch15.xhtml#ref15_29)])，并且这些框架对于大型`RDF`图存在局限性。因此，存储大量`RDF`三元组并高效查询它们是一个具有挑战性且重要的问题。

在本章中，我们讨论了一种基于访问控制的安全查询处理系统，该系统运行在云中并管理大量`RDF`三元组。这些`RDF`三元组可用于表示大数据应用，如社交网络，正如我们在之前的书中所讨论的[[THUR2015](#ch15.xhtml#ref15_49)]。我们在`JENA`之上开发了一个`SPARQL`查询优化器，用于查询处理引擎。我们在`SPARQL`查询优化器之上开发了两种访问控制模型，以控制对数据的访问。一种基于基于令牌的访问控制机制，另一种基于`XACML`（可扩展访问控制标记语言）访问控制框架[[XACM](#ch15.xhtml#ref15_60)]。也就是说，我们本质上讨论的是针对大数据系统的访问控制模型。

本章的组织结构如下。我们的方法在[第15.2节](#ch15.xhtml#sec15_2)中讨论。在[第15.3节](#ch15.xhtml#sec15_3)中，我们讨论相关工作。在[第15.4节](#ch15.xhtml#sec15_4)中，我们讨论我们的系统和操作架构。在[第15.5节](#ch15.xhtml#sec15_5)中，我们讨论如何回答一个`SPARQL`查询。在[第15.6节](#ch15.xhtml#sec15_6)中，我们展示实验结果。在[第15.7节](#ch15.xhtml#sec15_7)中，我们讨论我们在原型系统之上构建的安全策略执行机制方面的工作。最后，在[第15.8节](#ch15.xhtml#sec15_8)中，我们得出一些结论并讨论我们确定的未来改进领域。本章讨论的关键概念在[图15.1](#ch15.xhtml#fig15_1a)中说明。概念、架构和实验的更详细讨论见[[HUSA2011a](#ch15.xhtml#ref15_24)]和[[HUSA2011b](#ch15.xhtml#ref15_25)]。由于语义Web技术可用于建模社交网络系统等大数据系统，我们的查询处理系统可用于查询社交网络和相关的大数据系统。

## 15.2 我们的方法

可以构建一个分布式系统，以克服当前语义Web框架的可扩展性和性能问题。数据库正在被分布式部署，以提供此类可扩展的解决方案。然而，迄今为止，还没有用于存储和管理`RDF`数据的分布式存储库。研究人员只是最近才开始探索必须解决的问题和技术解决方案，以构建这样一个分布式系统。一条有前景的研究路线涉及利用现成的分布式数据库系统或关系数据库。此类数据库系统可以使用关系模式来存储`RDF`数据。`SPARQL`查询可以通过首先将其转换为`SQL`来回答[[CHEB2007](#ch15.xhtml#ref15_10), [CHON2005](#ch15.xhtml#ref15_11), [CYGA2005](#ch15.xhtml#ref15_15)]。最优关系模式正在为此目的被探究[[ABAD2007](#ch15.xhtml#ref15_1)]。此类系统的主要缺点是它们针对关系数据进行了优化。它们可能无法针对`RDF`数据表现良好，特别是因为`RDF`数据是三元组集合[[W3a](#ch15.xhtml#ref15_50)]（一个有序的三元组，分别称为主语、谓语和宾语），这些三元组形成大型有向图。在`SPARQL`查询中，任意数量的三元组模式（TP）[[W3e](#ch15.xhtml#ref15_54)]可以在单个变量[[W3d](#ch15.xhtml#ref15_53)]上连接，这使得关系数据库查询计划变得复杂。由于这些系统针对关系数据模式和事务性数据库用法进行了优化，性能和可扩展性将仍然是一个具有挑战性的问题。

然而，另一种方法是从头构建一个用于`RDF`的分布式系统。在这里，将有机会设计和优化一个专门针对`RDF`数据的系统。在这种方法中，研究人员将是在重复造轮子。我们没有从空白开始，而是构建了一个利用云计算平台的通用分布式存储系统解决方案。然后，我们专门定制了系统和模式，以满足语义Web数据的需求。最后，我们使用这种存储设施构建了一个语义Web存储库。
