
高级策略必须转换为合适的格式和表示，以便由溯源推理控制器处理。这通常涉及将高级策略解析为低级表示。我们的设计使用了一种可扩展语言来表达策略。该语言已成功用于编写访问控制策略 [[MOSE2005](#ch18.xhtml#ref18_22), [NI2009](#ch18.xhtml#ref18_23)]。我们的策略以 XML 文档形式编写，驻留在磁盘上，直到被请求时才加载 [[BRAY2000](#ch18.xhtml#ref18_4)]。XML 还具备编写规则的功能 [[GROS2003](#ch18.xhtml#ref18_15), [GOVE2005](#ch18.xhtml#ref18_14), [HORR2004](#ch18.xhtml#ref18_16)]。此外，RDF 和 OWL 可以用 XML 语法表示 [[BECH24, HORR04](#ch18.xhtml#ref18_...)]。我们选择 XML 语言，使我们能够接受任何高级策略规范及其关联的解析器，将其映射为低级策略格式。高级应用用户也因我们使用 XML 语言而受益，因为 XML 是一种广泛使用的开放标准，许多数据交换格式都基于 XML。

[图 18.7](#ch18.xhtml#fig18_7a) 概述了策略解析过程。加载 XML 策略文件时，文件中的每个策略都会使用兼容的解析器进行解析。解析器负责确保策略格式良好。默认策略（即访问控制、编辑、推理规则）以 XML 文件形式编写，解析器根据 XML Schema 文件评估该 XML 文件。成功解析的 XML 文件中的策略随后被转换为低级表示。

### 18.6.3.3 高级策略转换

本节讨论如何将正确解析的高级策略转换为内部低级策略。我们首先讨论两个推理组装器：`SWRL` 规则组装器和描述逻辑规则组装器。然后，我们讨论两个策略组装器，分别转换访问控制和编辑高级策略。

### 18.6.3.4 SWRL 规则组装器

该模块将高级 XML 文件映射为一组 `SWRL` 规则。`SWRL` 规则包含头部和主体。主体用于编码必须满足的条件，随后头部编码的信息才会应用于溯源知识库。

### 18.6.3.5 SWRL 策略转换示例

以下策略规定：如果医生拥有（或正在诊治）一名患者，则该医生也可以读取该患者的记录。

```xml
<policies>
  <policy ID="1">
    <description>…some description....</description>
    <body>
      <atom>?x rdf:type provac:Doctor</atom>
      <atom>?y rdf:type provac:Patient</atom>
      <atom>?y provac:patientHasDoctor ?x</atom>
      <atom>?y provac:hasRecord ?r</atom>
    </body>
    <head>
      <atom>?x provac:canReadRecord ?r</atom>
    </head>
  </policy>
</policies>
```

此策略可在内部表示为：

$$
\begin{array}{l}
Doctor(?x) \land Patient(?y) \land patientHasDoctor(?y,?x) \land hasRecord(?r) \\
\quad \rightarrow canReadRecord(?x,?r)
\end{array}
$$

### 18.6.3.6 描述逻辑规则组装器

该模块将高级 XML 文件映射为一组 `OWL` 限制。`OWL` 属性用于创建限制，进而限制属于某个类的个体。这些限制可分为三大类：

1.  量词限制
2.  基数限制
3.  `hasValue` 限制

**量词限制** 由三部分组成：

1.  量词，即存在量词（`∃`）或全称量词（`∀`）。
2.  限制作用的属性。
3.  作为类描述的填充项。

对于给定个体，量词有效地约束该个体参与的关系。它通过指定至少必须存在一种关系，或指定只能存在的关系类型（如果存在）来实现。存在量词示例可用于定义拥有医学学位的医师：

`Physician ⊑ ∃has.MedicalDegree`

全称限制规定：如果某属性存在关系，则该关系必须指向属于特定类的个体。全称量词示例可用于定义其所有患者都有保险的快乐医师：

`HappyPhysician ⊑ ∀hasPatients.(∃hasCoverage.Insurer)`

### 18.6.3.7 基数限制

`OWL` 基数限制描述这样一类个体：它们与其他个体或数据类型值具有至少（`≥`）、至多（`≤`）或恰好指定数量的关系。设 `P` 为一个属性，则：

1.  最小基数限制指定个体必须参与的 `P` 关系的最小数量。
2.  最大基数限制指定个体可以参与的 `P` 关系的最大数量。
3.  基数限制指定个体必须参与的 `P` 关系的确切数量。

### 18.6.3.8 hasValue 限制

`hasValue` 限制描述这样一组个体：它们沿指定属性与特定个体至少存在一种关系。`hasValue` 限制用符号 `∈` 表示。示例：`hasCountryOfOrigin ∈ Italy`（其中 `Italy` 是一个个体）。这描述了沿 `hasCountryOfOrigin` 属性与特定个体 `Italy` 至少存在一种关系的个体集合（匿名类）。

### 18.6.3.9 支持的限制

我们当前支持以下 `OWL` 限制：

1.  **SomeValuesFromRestriction**
    `SomeValuesFrom` 限制是存在限制，描述这样一组个体：它们与属于特定类的个体至少存在一种特定类型的关系。

2.  **AllValuesFromRestriction**
    `AllValuesFromRestriction` 是全称限制，将给定属性的填充项约束为特定类。

3.  **MinCardinalityRestriction**
    `MinCardinalityRestriction` 是基数限制，指定个体就给定属性必须参与的最小关系数量。最小基数限制的符号为“大于或等于”（`≥`）。

4.  **MaxCardinalityRestriction**
    `MaxCardinalityRestriction` 是基数限制，指定个体就给定属性可以参与的最大关系数量。最大基数限制的符号为“小于或等于”（`≤`）。

5.  **DataRange**
    这是一个内置属性，将一个属性（或 `rdf:Property` 类的某个实例）链接到类描述或数据范围。`rdfs:range` 公理断言该属性的值必须属于类描述的类外延，或属于指定数据范围内的数据值。

6.  **Domain**
    这是一个内置属性，将一个属性（或 `rdf:Property` 类的某个实例）链接到类描述。`rdfs:domain` 公理断言此类属性陈述的主语必须属于所指示类描述的类外延。

  <policy ID="1">
    <description>...some description....</description>
    <rule>
