## 2.7 Security Techniques—User Authentication

Fundamental features of a robust and secure system verify and validate the user at all times. The authentication could be based on either a single step or multiple steps, depending on the application or security objective. Time-out and re-authentication measures are also recommended when the communication links are exposed to vulnerabilities. Coded and unique protocols are effective in user authentication and their deployment is to be assessed based on vulnerability tests.

ISO/IEC 9798 entails a range of authentication protocols for different security systems and security goals [8]. System integrators and architects should evaluate the relevance of the adoption of these protocols in their system based on the perceived and assessed degree of vulnerabilities and desired resilience.

Attackers employ techniques such as camouflaging, masking and creating dummy user accounts to gain access to healthcare systems, and can hack data in the absence of security mechanisms—viz., authentication. Such deployment of various techniques by attackers demands appropriate development of complex protection systems, to counter and prevent them, on a case-to-case basis. The standards like the one mentioned above address such scenarios and effectively against multiple attacks.

The involvement of trusted third parties is a common practice to secure the system safety in which those parties are entrusted with the task of implementing protection systems in conformance with the mandated security standards. Trusted third parties are also required to submit the performance indices periodically to report on the types of incidents and the extent of protection afforded. The data collected by these means are used to assess the adequacy of protection including the type of standards selected for adoption. The feedback loop provided by third parties become quite useful in system upgradation and enhancement while expanding the scope of the network or increasing the number of users substantially.

ISO/IEC 9798-2:2019 provides information on entity authentication by adopting authenticated encryption and ISO/IEC 9798-3:2019 provides information on entity authentication mechanisms using digital signature techniques [9].

The list of standards and the details thereof scare away the system integrators and hospital administrators to consider and implement those. This is where the services of cybersecurity specialists with expertise, knowledge and skills are required to advise on the scope and extent of security measures required to be adopted and implemented. The key consideration is continuous scanning of the developments and performing cost–benefit analysis for inclusion and updating.

## 2.8 Conclusions

One size fits all paradigm is anathema in attempting to have a universal recommendation for establishing and regaining security and privacy of data in IoHT. The following is a set of recommendations for enabling a reasonably high level of security in the provision of services:

- 1. Healthcare institutions should develop and publish their approved policy on authentication and authorization of users, involved in data handling, posting and transfer.
- 2. Authentication and authorization, both at the process level and system level, should be segregated and dealt with by separate protocols.
- 3. Access to sensitive data should be restrained or prohibited from remote users (layers 2 and 3 of the network access).
- 4. An IoT device needs to be evaluated for its protection features, concerning security criteria, before being inducted into an already existing operational environment, such as the healthcare industry. Resorting to techniques like type approval of equipment is a common practice to validate devices/equipment.
- 5. Healthcare institutions should implement appropriate technical and organizational measures to manage the security risks of their public networks and services. These include but not limited to ISO22301 certification for business continuity and ISO27001 certification for information security management.
- 6. Security incident reporting policy and system should comply with ITIL and similar global standards.
- 7. Healthcare institutions should regularly conduct appropriate assessments of all application-level, server and systems software, to identify potential threats and vulnerabilities. Gaps identified during audits/tests should be resolved in a time-bound manner.
- 8. Healthcare institutions should have suitable support arrangements with their vendors to ensure that security and stability fixes are provided and installed in a timely, effective manner.
- 9. Security protocols deployed in the system need regular updates with the latest security patches, as older versions may expose the system to new vulnerabilities. Therefore, constant updates of security patches and incorporation of request for changes are needed for IoT devices to ward off the latest threats in the form of viruses or machine tampering. However, designing a mechanism for the dynamic scanning and installation of the latest security patches is a challenging and formidable task. Artificial intelligence will play a major contributory role in shaping policies and procedures in terms of aiding updates.
- 10. Healthcare institutions should conduct periodic external and internal security audits, including penetration tests that simulate real-world attack scenarios, to identify threats and weaknesses at the network operating system and application layer levels, as well as in the institution's procedures and processes.
