

还有许多其他补充性的 Apache 组件可为 Hadoop 提供价值，例如用于数据仓库的 `Hive` 或 `Pig`、用于数据摄取的 `Flume` 以及用于协调分布式应用程序的 `ZooKeeper`。`Apache Kafka` 和 `Apache Spark` 是可帮助 Hadoop 加快工作速度的选项，因为它们可以使用内存数据存储（这是 `MapReduce` 的一项局限性）来适应实时数据。围绕 Hadoop 的开源社区庞大且非常支持，使您能够通过研究发现许多用例。

### Hadoop 挑战

关于使用 Hadoop 的较大挑战之一是解决安全顾虑，这需要的工作量超出了补充性插件所能提供的范围。Hadoop 确实有一些安全选项，但它们是碎片化的，因为供应商和开源软件社区不得不将安全功能改装到一个在设计之初未考虑安全性的 Apache 框架中。大数据正成为许多组织的关键资源，使其成为网络攻击的高价值目标而备受瞩目。为了更好地了解大数据的安全挑战，云安全联盟（CSA）大数据安全工作组在 CSA 2012 年的出版物《十大大数据安全与隐私挑战》中列出了以下需要克服的十大安全和隐私挑战：

1.  分布式编程框架中的安全计算
2.  非关系型数据存储的安全最佳实践
3.  安全的数据存储和事务日志
4.  端点输入验证/过滤
5.  实时安全/合规监控
6.  可扩展且可组合的隐私保护数据挖掘与分析
7.  密码学强制的访问控制和安全通信
8.  细粒度访问控制
9.  细粒度审计
10. 数据溯源

Ajit Gaddam 在 2015 年美国黑帽大会上发表了其白皮书《保护您的大数据环境》，针对上述关注列表提出了建议。Gaddam 的白皮书提出了一个大数据安全框架，如[图 5-23](#ch05.xhtml#ch05fig23)所示。我发现这些安全建议中的许多都与 `NIST` 和 `ISO` 等流行指南中的主题一致。

![FIGURE 5-23 Big Data Security Framework](Images/05fig23.jpg)

**图 5-23** 大数据安全框架

关于该框架如何应用于保护 Hadoop 的总结可分为五个重点领域：

*   **数据管理：** 解决如何收集和识别大数据，以确保对保护范围的内容进行适当的评估和理解。
*   **身份和访问管理：** 侧重于如何控制谁可以访问组织收集的大数据的哪些方面。此重点领域还包括验证大数据来自授权来源，以避免包含被修改或不需要的数据。
*   **数据保护和隐私：** 保护所收集的数据，并确保解决任何隐私顾虑。
*   **网络安全：** 旨在保护数据在收集过程中以及在属于或利用 Hadoop 基础设施的系统之间移动时的安全。
*   **基础设施安全和完整性：** 解决其框架内 Hadoop 组件的安全问题。

### 保护 Hadoop

Hadoop 包含不同的安全选项，例如 `Kerberos`、`HDFS` 内的加密、`HDFS` 文件权限、使用 `Apache Knox` 的边界安全，以及诸如 `Apache Ranger` 之类的授权应用程序，以解决数据保护、网络安全和基础设施安全顾虑。我在本书中涵盖了许多这些安全主题，我的建议是利用大数据安全框架作为参考点，类似于使用任何流行指南，来解决该框架中提出的顾虑。要评估当前的 Hadoop 设置，您可以执行能力评估，以确保包含纵深防御方法，这在[第 1 章](#ch01.xhtml#ch01)中已介绍。

大多数现代 `SIEM` 解决方案都有用于与 Hadoop 或类似技术协作的配置选项。例如，`Splunk` 使用 `Splunk Hadoop Connect` 应用程序来简化 Hadoop 和 Splunk 之间的集成过程。通过此应用，Splunk 可以将事件转发到 Hadoop 进行长期归档和额外的批量分析。`Splunk Hadoop Connect` 提供的功能简要总结为导出、探索和导入大数据的能力。Hadoop 实时收集和索引海量机器数据流，并允许 Splunk 从 `Splunk Hadoop Connect` 用户界面导航和检查 `HDFS` 目录。`Splunk Hadoop Connect` 用户界面还可以将 Hadoop 数据导入并索引到 Splunk 中，使这些数据可用于搜索、报告、分析和可视化，而无需编写 `MapReduce` 代码的限制。[图 5-24](#ch05.xhtml#ch05fig24) 显示了 Splunk、Hadoop 和 `Splunk Hadoop Connect` 应用程序之间关系的图示。
