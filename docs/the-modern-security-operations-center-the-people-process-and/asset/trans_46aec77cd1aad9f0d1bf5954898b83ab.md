

## 理解 CVSS 简写

FIRST 并不指望你手动计算每个 CVSS 值，因为那将极其繁琐。漏洞的严重程度已经根据所有指标值计算为风险评分，而指标则使用一种简写形式进行汇总。在 NVD 中提供指标的评分和简写，是为了展示风险值是如何计算的，以便你更好地理解威胁，并明白评分为何呈现为该数值，而不是使用计算器生成你自己的评分。

为了简化对风险评分所考虑的指标权重的理解，CVSS v2 使用每个评分的简短摘要来表示 CVSS 评分是如何计算的。请注意，每个显示的指标和权重都包含括号 `()`，括号内有简短的短语。括号内的简短短语后跟冒号 `:`，用于表示为特定指标选择了哪个选项。例如，`AV` 用于表示攻击向量，`L` 用于表示本地。这在 CVSS 简写中将表示为 `AV:L`。反斜杠 `/` 用于分隔下一个因子，因为所有大小因子都作为漏洞风险因素的一个简写说明显示。另一个例子是继续使用 `AC` 表示访问复杂性，这是紧随攻击向量之后的因子。一个完整的 CVSS 2.0 状态可能如 `AV:N/AC:L/Au:N/C:P/I:P/A:C`。如果你回顾 [图 9-5](#ch09.xhtml#ch09fig05)，你会注意到 `AV:N/AC:L/Au:N/C:P/I:P/A:C` 与 CVSS 计算器中选定的简写值相匹配。

为了将这些整合在一起，[图 9-7](#ch09.xhtml#ch09fig07) 显示了基于 CVSS 2.0 版本的 Apache Struts 漏洞 `CVE-2017-9793`（前文提及）的 NVD 页面中的严重性部分。这显示了一个 5.0 的基础评分，并使用 CVSS v2 简写解释了该评分是如何计算的。

### CVSS 3 版本

CVSS v2 仍然是行业标准；然而，它也受到了供应商和客户的一些批评。为了解决这些问题，FIRST 开发了 CVSS v3，旨在为供应商提供一种更好地分析安全漏洞影响的方法，同时允许客户提供更多细节，以便他们确定响应漏洞所需的紧迫程度。行业专家 Omar Santos（恰好是我的好友）在 Cisco Blogs 上发表了一篇文章（[https://blogs.cisco.com/security/cvssv3-study](https://blogs.cisco.com/security/cvssv3-study)），解释了他关于 CVSS v2 和 CVSS v3 之间变化的研究，包括他发现使用新系统计算时，CVSS v3 会导致许多漏洞的基础评分增加。关注程度的轻微增加可能会导致 SOC 运作方式的重大变化，包括触发不同的工作编排，并导致客户处理漏洞的顺序发生变化。

2019 年 6 月，FIRST 发布了一个小版本更新 CVSS v3.1，旨在在不引入新指标或指标值的情况下，澄清并进一步改进 3.0 标准。[图 9-8](#ch09.xhtml#ch09fig08) 说明了 CVSS v3 基础评分系统相较于先前在 [图 9-5](#ch09.xhtml#ch09fig05) 中显示的 CVSS v2 系统的变化。一个变化的例子是攻击向量现在包含物理 (`AV:P`) 组件。

![FIGURE 9-8 CVSS v3 Base Score Metrics](Images/09fig08.jpg)

> **注意**
>
> 你应高度重视通过供应商验证任何漏洞，以获取最新信息，包括供应商建议的修复相关风险的步骤。

NVD 中包含的另一个关键信息是所有受影响系统的列表。对于 Struts 示例，已知受影响软件配置部分列出了许多版本的 Apache Struts，包括 `cpe:2.3:a:apache:struts:2.3.7:*:*:*:*:*:*`、`cpe:2.3:a:apache:struts:2.3.8:*:*:*:*:*:*` 等。我再次强烈建议直接与供应商验证你的特定系统和软件是否会受到影响，以确保 NVD 没有不准确地列出或遗漏你的系统或软件作为潜在易受攻击对象。

大多数安全工具供应商在引用漏洞时，其产品中使用 CVSS 两种评分系统中的一种或两种。[图 9-11](#ch09.xhtml#ch09fig11) 是 Rapid7 Nexpose 中显示的 Struts 漏洞示例。请注意，同时显示了 CVSS v2 和 v3 的简写，以及两个版本的 CVSS 评分差异。在该示例中，CVSS v2 评分 (9.3) 远高于 v3 评分 (8.1)。

## 漏洞技术

现在你已经了解了计算漏洞严重程度的构成要素，是时候将这些知识应用到实践中了。为此，你的 SOC 需要一些关键工具，包括识别网络上资产的能力、扫描网络漏洞的能力，以及进行某种形式的案例管理以确保所有漏洞都得到跟踪和处理。以下各节涵盖的类别可用于满足这些需求。
