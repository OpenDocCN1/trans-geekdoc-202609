

## SIEM 故障排除示例：验证结果

[图 5-10](#ch05.xhtml#ch05fig10) 显示了我使用 SMC 默认 syslog 格式时发生的情况。虽然 Splunk 能看到数据，但无法正确解析数据，因此我无法将这些数据用于任何规则、小组件或报表。[图 5-10](#ch05.xhtml#ch05fig10) 中的箭头标识了原始数据中的有用数据，但 SIEM 解决方案并未将这些重要项目视为数据点。在排查存在数据索引问题的 SIEM 解决方案时，请牢记这一关键概念。与其创建复杂的自定义解析器来适应格式不良的数据集，不如首先尝试调整数据的发送格式，以便 SIEM 解决方案能够使用其默认的数据索引和解析功能来接受数据。此时，我至少可以验证连接正在发生，且数据正被 SIEM 解决方案接收。但是，我需要修复 SIEM 解决方案处理来自 SMC 数据的方式。

![FIGURE 5-10 Results from Poorly Formatted Syslog](Images/05fig10.jpg)

**图 5-10** 格式不良的 Syslog 产生的结果

解决此问题的最佳方法是确定 Splunk 期望如何接受 syslog 数据。通过研究 Splunk 和其他 SIEM 厂商支持页面上关于 syslog 应如何格式化的内容，我发现有可用的 syslog 模板，且曾遇到相同问题的各类客户均推荐使用这些模板。具有讽刺意味的是，我在 IBM QRadar 支持页面上发现了一个非常有用的模板，它在 Splunk 中也能很好地工作，如[图 5-11](#ch05.xhtml#ch05fig11) 所示。我复制了该模板并将其粘贴到 SMC Syslog Format 的左侧部分，而不是使用 SMC 默认模板工具。

![FIGURE 5-11 Using Custom Syslog Template in SMC](Images/05fig11.jpg)

**图 5-11** 在 SMC 中使用自定义 Syslog 模板

使用错误与正确的 syslog 格式之间的差异，导致 SIEM 解决方案能够在无需自定义数据接收方式的情况下，将数据转化为报表和小组件，如[图 5-12](#ch05.xhtml#ch05fig12) 所示。使用正确的 syslog 格式后，Splunk 能够识别关键术语，我可以轻松搜索这些术语并将其转换为小组件。查看[图 5-12](#ch05.xhtml#ch05fig12)，我通过搜索从 SMC 发送的数据中的 Recon（侦察）、Data hording（数据囤积）、Exfiltration（数据渗漏）和 Concern（关注项）等术语创建了这些小组件。如果由于不良的 syslog 格式导致相同数据未被正确索引，要创建这些小组件将是一场绝对的噩梦。此外，SMC 发送数据方式的任何变更都可能破坏自定义解析和搜索规则背后的逻辑，导致这些小组件停止显示有用数据。

![FIGURE 5-12 Converting Syslog Data into Reports and Widgets](Images/05fig12.jpg)

**图 5-12** 将 Syslog 数据转换为报表和小组件

当规则、小组件和报表未显示正确数据时，始终要通过验证数据的发送和接收方式来开始故障排除。如果你发现数据虽被检测到，但未被 SIEM 解决方案正确解析或索引，请尝试调整数据发送到 SIEM 解决方案的方式，然后再修改或自定义接收端。

### SIEM 故障排除示例：验证结果

除上一节涵盖的情况外，还可能发生其他问题。例如，数据发送方或 SIEM 解决方案可能选择了错误的端口或协议，导致收集到异常数据。此外，SIEM 解决方案发送和接收数据的功能可能正常，但发送的数据本身可能是错误的。任何时候配置似乎都正常但结果不佳时，请务必验证原始日志，确保发送的数据是应该发送的数据。我曾受邀排查一个报表产生错误数据的情况。经过一些故障排除，我发现不同工具的 IP 地址在重启期间发生了切换，导致 SIEM 解决方案对其接收的预期数据感到“困惑”。我还发现一个工具停止发送日志，转而向 SIEM 解决方案发送错误数据，导致相关报表显示随机字符。验证原始日志的最佳方法是首先查看发送方发送的日志，并将其与 SIEM 解决方案收集并索引后看到的相同数据进行比较。[图 5-13](#ch05.xhtml#ch05fig13) 显示了 IBM QRadar 中的“日志活动”页面。我可以在此处使用“快速筛选”选项或执行更高级的搜索，来查找 SIEM 解决方案接收的数据。

![FIGURE 5-13 IBM QRadar Search Screen](Images/05fig13.jpg)

**图 5-13** IBM QRadar 搜索屏幕

如果我想查看数据是否从某台设备传到了 SIEM，我会首先搜索来自特定 IP 地址的任何数据。接下来，我会将时间范围限制在最近 10 分钟，并缩小范围，聚焦于我成功标准所需的感兴趣数据项。如果我的目标是识别来自 SMC 日志的数据渗漏活动，我会搜索可能包含该值的术语，即“exfiltration”（渗漏）。[图 5-14](#ch05.xhtml#ch05fig14) 显示了搜索 SMC 的 IP 地址并将“exfiltration”作为搜索一部分的结果。如果基于此搜索未看到任何结果，我会恢复为搜索来自 SMC IP 地址的所有数据，并查看数据是如何被索引的，以及根据 IBM QRadar 对 SMC 数据中发现的数据变量进行分类，有哪些关键术语可供我搜索。

![FIGURE 5-14 Searching for Data Exfiltration in IBM QRadar](Images/05fig14.jpg)

**图 5-14** 在 IBM QRadar 中搜索数据渗漏

### SIEM 故障排除示例：可操作情报

将工具发送到 SIEM 解决方案的数据转换为可操作情报，是设置和排查数据发送的最后阶段。对许多 SIEM 解决方案而言，这意味着创建小组件和报表，根据将数据发送到 SIEM 解决方案的安全工具，按 SOC 分析师的需求进行筛选。可以创建包含多个小组件的仪表板。这些数据可以导出为报表、显示在监视器上，并通过电子邮件发送给分析师，以提供环境状态的更新。[图 5-15](#ch05.xhtml#ch05fig15) 显示了在 IBM QRadar 中创建一些简单小组件的示例，专注于安全事件的分析师将从中受益。每个小组件代表使用特定筛选标准的结果。如果这些小组件中的任何一个停止产生有用数据，分析师可以单击“编辑”按钮，查看搜索结果以验证一切是否仍在正常工作。也许某些东西已经改变，或者也许在应用筛选后，搜索没有任何结果填充。

![FIGURE 5-15 IBM QRadar Dashboard Example](Images/05fig15.jpg)

**图 5-15** IBM QRadar 仪表板示例

大多数现代 SIEM 解决方案提供开发小组件、仪表板和报表的类似方法。作为该仪表板工作原理的一个示例，在[图 5-16](#ch05.xhtml#ch05fig16) 中，我可以单击标记为“High Concern”（高关注）的小组件，并选择打开列出的 31 个项目中的一个，将其用作专用搜索。请注意，对于标记为“High Concern”的小组件之一，我可以单击进入并选择打开该小组件中使用的数据作为专用搜索。该示例展示了仪表板本质上就是一堆显示在一个屏幕上的过滤搜索。
