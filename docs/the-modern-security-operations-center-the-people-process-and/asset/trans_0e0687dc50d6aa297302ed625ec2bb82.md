## 运营数据与 Web 处理

我之前解释过，某些威胁数据将聚焦于特定的威胁活动。您需要 SOC 监控攻击行为的趋势，并监控您的市场领域内何时发生活跃的攻击活动。获取这些数据可能需要从各种来源收集数据，包括社交媒体、博客和其他论坛，这些来源夹杂着大量由无关对话和主题组成的噪音。

从公共资源中寻找有用数据并无简单方法，因为威胁情报的很大一部分在于了解您未曾知晓的概念和事件——您不知道该搜索什么。不过，您可以利用一些策略，在您认为潜在威胁数据有用且值得调查时发出警报。一种方法是启用 Web 警报，当提及特定类型的对话时触发通知。`Google Alerts`（Google 警报）就是一个免费工具示例，可用于在公共论坛上出现特定术语或对话时接收警报。其他示例包括 `BuzzBundle`、`Mention`、`Talkwalker Alerts` 和 `Hootsuite`。[图 7-5](#ch07.xhtml#ch07fig05) 展示了设置 `Google Alerts` 以获取 Ryuk 勒索软件详情的示例。提供的细节越多，例如哈希值或威胁行为者的数据，获得的结果就越好。您的 SOC 可能会捕风捉影地得知某个攻击活动，并针对该活动的特定特征设置 `Google Alerts`，以此监控互联网上研究人员发布的关于该活动的更新。这比每次出现感兴趣话题时手动搜索 Google 要有效得多。

识别新威胁数据的另一种选择是利用社交媒体和其他资源，关注那些发布重要时事的安全专业人士和影响力人物。网络安全行业重要影响力人物的示例包括 Bruce Schneier、Brian Krebs、Jeff Moss 和 Dan Kaminsky。您还可以关注漏洞和风险咨询源/博客以了解行业趋势。示例包括美国计算机应急响应小组（`US-CERT`）、国家漏洞数据库（`NVD`）和 SANS 互联网风暴中心。其他值得考虑的源和报告包括分析师报告，例如来自 `Dragos` 和 `Cisco Talos` 的威胁报告，以及备受推崇的 Verizon（数据泄露报告）、`Gartner` 和 `Forester` 的研究报告。请记住，许多此类来源的受众非常广泛，因此投资定制的战略威胁情报可能比手动处理公开可用信息更有价值。

### 爬虫

当您收到包含威胁数据的基于 Web 资源的警报时，将面临的另一个挑战是从噪音中识别出有用的信息。您可能也拥有能将特定细节（如 `IOC`）转化为行动的工具，但这些细节可能混杂在大量需要移除的无用细节中。这就是爬虫派上用场的地方。爬虫可配置为识别关键术语，复制它们，并将其粘贴到有用的格式中，例如 `.csv` 文件。示例可以是设置爬虫收集与恶意行为相关的哈希值或 IP 地址，这些数据可被解析为安全工具能够转化为报告或行动的单元格。爬虫示例包括 `Import.io`、`Dexi.io`、`Scrapinghub` 和 `ParseHub`。

您可以使用的一款免费但功能有限的爬虫是 `Scraper Chrome extension`（Scraper Chrome 扩展程序）。只需安装 `Chrome Scraper extension`，找到包含感兴趣数据的页面，然后高亮即可抓取类似数据。[图 7-6](#ch07.xhtml#ch07fig06) 展示了从 `Cisco Talos` 博客抓取哈希值的示例，该博客讨论了各类网络威胁。这些哈希值可输入 `SIEM` 解决方案或其他安全工具，以扫描模式匹配。

### 社交媒体

如果利用得当，社交媒体也可用于威胁数据。让我们以 Twitter 为例用例。Twitter 不仅仅是一个用于推广或分享个人事件的个人平台。有许多机器人分享海量数据，包括最近的 `IOC` 和威胁检测规则。有些 Twitter 机器人配置为监控物联网（`IoT`）设备。还有开源蜜罐将其发现记录在 Twitter 上。[图 7-7](#ch07.xhtml#ch07fig07) 展示了一些从 Twitter 获取的此类行为示例。

**图 7-7** Twitter 威胁数据行为示例

为什么您应该关注 Twitter 威胁数据？请考虑 Twitter 等资源上信息发布的速度。有价值数据的三大关键要素之一是**及时性**，这正是 Twitter 可作为新威胁通知的有用工具所在。同样的价值适用于识别新漏洞。您更有可能在社交媒体圈子中捕捉到极新的漏洞，而不是等待供应商提供更新或等待漏洞登上国家级新闻。就态势感知最佳实践而言，您希望在弱点被全国性广播之前就知情，因为那意味着该漏洞已存在一段时间，并在组织中造成了足够多的问题，才会成为大新闻。Twitter 可以帮助您感知新兴威胁。

您利用 Twitter 等资源的挑战在于提取相关且可靠的数据。这可以通过爬虫技术再次实现。您将无法使用我之前介绍的爬虫，因为它们无法理解 Twitter 的运作方式。一款您可以使用的 Twitter 友好型爬虫是 `Twint` ([https://github.com/twintproject/twint](https://github.com/twintproject/twint))。`Twint` 与其他 Twitter 友好型爬虫不同，因为它不使用 Twitter 的 API，后者对可抓取的内容有很多限制。相反，`Twint` 使用 Python，允许您在规避 API 限制的同时抓取用户的关注者、关注列表、推文等。使用 `Twint`，您可以搜索特定关键词，如“0-day”、“CVE-”、“CVE-2020-\*”和“bugbounty”。收集数据时，您可以使用额外的 CVE 相关标签深入挖掘结果并过滤噪音。一个示例是搜索“Github”和“CVE”，以识别包含近期漏洞概念验证的 GitHub 仓库。诸如“ThreatHunting”之类的标签可以收集数据并填充 `SIEM` 解决方案中的组件，以在近期网络犯罪活动在 Twitter 上被讨论时发出警报。利用 Twitter 这种始终流动的数据源获取近期事件，有数百种用例。
