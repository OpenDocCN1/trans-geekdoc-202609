

# SIEM 解决方案与 API

SIEM 解决方案形式多样，除基本的数据汇总与显示外，还提供许多特殊功能。Splunk 就是一个重点关注应用的 SIEM 解决方案示例。[图 5-17](#ch05.xhtml#ch05fig17) 展示了在 Splunk 中使用的 Cisco Network Security Analytics（原 Stealthwatch）应用。该应用使分析师无需登录 SMC，即可在 Splunk 中查看类似于 SMC 仪表板的视图。使用此类应用不仅因为无需在工具间来回切换即可获取可操作情报而节省了分析师的时间，还因为能够在应用内自定义从发送数据的工具接收哪些数据，而无需自定义工具本身。应用故障排除涉及查看与应用相关的文档，因为安装方法会因供应商而异。如果您将 SIEM 应用作为部署的一部分，则需要将应用的设置和故障排除纳入研究流程。

## API

应用程序编程接口（API）是一种软件中介，使两个应用程序能够相互通信。API 定义了可用的特定功能，这些功能独立于其各自的实现。优秀的 API 通过提供功能性强且实用的构建模块来简化编程，这些模块旨在完成原本需要更多工作量的任务。开发人员可以使用这些构建模块开发复杂流程，而只需编写极少量的新代码。使用 API 最大的好处是程序员不必“重复造轮子”，也就是说，他们不必为现有功能开发代码，而是直接调用它。

API 过程的一个类比是在餐厅点餐。您不是自己烹饪食物，而是通过服务员发送指令，服务员将指令传达给厨师。厨师通过烹饪您的餐点来处理这些指令，然后服务员将餐点端给您。在这个例子中，服务员充当了 API 的角色。如果服务员正确理解并传达了您的指令，您最终会得到想要的餐点。如果服务员误解了您的指令或传达不正确，您收到的餐点将与您点的不同，或者您的订单会被厨师拒绝。

一个涉及 IBM QRadar SIEM 和 Rapid7 Nexpose 漏洞扫描器集成的 API 技术示例是：Rapid7 使用 API 指令将漏洞数据发送给 IBM QRadar。这些指令指定了数据发送的时间、频率、数据格式，以及双方正确完成数据共享所需的任何其他要求。如果指令不被接受，IBM QRadar 将产生错误消息、不显示任何漏洞数据，或显示错误数据。[图 5-19](#ch05.xhtml#ch05fig19) 展示了该示例集成工作原理的高层图解。

### 利用 API

从高层来看，利用 API 似乎很简单，但在使用 API 之前，必须评估许多重要因素。首先，考虑 API 的使用方式。基于系统的 API 允许一个系统访问另一个系统的数据。在安全领域，我经常看到这种类型的 API 用于从 Active Directory 系统拉取用户信息、在系统数据库之间共享漏洞数据，以及从系统拉取安全警报。面向流程的 API 与单个系统内或跨系统的数据进行交互并对其进行整理，目的是将数据分解为数据孤岛。这种方法常用于创建报表，报表可以使用不同的 API 来收集和修改数据。有时会应用过滤 API，意味着 API 的目的是将数据缩减为特定格式，以便系统消化或查看，例如客户门户。API 采用的方法将由供应商定义，包括预期使用 API 完成的任务。[图 5-19](#ch05.xhtml#ch05fig19) 中的 API 从 Nexpose 拉取 XML 输出并将其发送给 QRadar。

关于 API 要考虑的另一个因素是 API 是在内部还是外部运行和访问。某些 API 仅对系统开发人员可用，这意味着系统投入生产上线后，系统用户将无法利用该 API。外部可用 API 是指在系统生产使用期间，可由任何用户和系统调用的 API。[图 5-19](#ch05.xhtml#ch05fig19) 展示的是一个外部 API，因为活跃的生产系统正在使用该 API 进行相互通信。极其重要的是要意识到与内部和外部 API 相关的风险，以免攻击者滥用它们。如果某些 API 被暴露且未加保护，恶意方可能会以非预期的方式修改系统。

### API 架构

业界使用通用的 API 架构风格，以帮助简化工具与其他系统互操作需求的预期。以下是 IT 市场中一些最常见的 API 架构：

*   **表述性状态传递：** REST 是一种架构方法，它依赖于内置于底层网络协议中的命令，将 API 使用者与 API 提供者分离开来。客户端使用特定的链接和表单来执行读取、更新、共享或审批等操作。HTML 常使用 REST API，因为它在支持 JSON 和 XML 等数据格式方面很灵活。许多基于 HTTP 的图形用户界面（GUI）都具有 REST API 选项，这些选项仅限于其他第三方工具可调用的特定功能。

*   **远程过程调用：** RPC 使开发人员能够在另一个系统或网络上执行特定代码块，而无需了解网络的细节。RPC 用于调用远程系统上的其他进程，类似于本地系统之间的通信方式。RPC 使用客户端/服务器模型来实现这一点。在 RPC 模型中，请求程序是客户端，提供服务的程序是服务器。
