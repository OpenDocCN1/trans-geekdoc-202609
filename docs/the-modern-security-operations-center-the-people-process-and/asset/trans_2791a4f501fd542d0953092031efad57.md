

# 安全能力

什么是安全方面的能力？它们是你识别和应对威胁的能力。管理威胁造成的风险是大多数 SOC 解决的关键服务，这是 [第 3 章](#ch03.xhtml#ch03) 涵盖的主题。理解风险的关键在于威胁利用漏洞的可能性。简单来说，威胁利用漏洞，而 SOC 的工作是尝试检测并防止这种情况发生。检测和预防涉及不同的安全能力。安全行业以声称安全工具能提供复杂的能力而臭名昭著，例如利用类人行为（人工智能）来决定某事物是否构成风险，利用云资源进一步评估潜在威胁，或拥有不同“检查”的层级来捕捉最隐蔽的恶意软件。其中一些说法属实；然而，事实是安全工具使用三种基本的检测能力。安全工具旨在利用以下三种基本能力中的一种或多种：检测已知攻击的能力、检测已知恶意行为的能力，以及检测异常（例如新型攻击的异常行为）的能力。行业能力可以归结为这些基本的检测概念。[图 1-4](#ch01.xhtml#ch01fig04) 表示了安全工具用于检测和预防威胁的三种核心安全能力的概念。

## 特征检测

让我们从检测已知攻击的能力开始，它依赖于基于特征的技术。查找已知威胁的一种方法是使用特征，这些特征代表安全行业以前识别出的特定威胁的检测。例如，防病毒解决方案拥有许多已知恶意软件的特征，并将文件与一个不断更新的近期威胁特征列表进行比对。检测恶意软件可能基于各种特征，例如文件的哈希值，但这并不像看起来那么简单。创建和管理特征存在相关挑战。特征越具体，攻击者越容易修改攻击以避免被检测。特征越通用，越有可能产生误报，即对非实际威胁触发警报。对手通常会修改现有恶意软件以改变文件的外观，这被称为 `encoding the file`（编码文件）。他们这样做是为了让恶意对象在防病毒解决方案眼中显得与其已知恶意文件列表中的内容不同。还有其他避免检测的方法，包括加密文件、添加无用代码行或添加空操作（`NOPs`）。对手可以在公共特征列表（如 `VirusTotal`）上测试恶意软件，以查看恶意软件是否可能被流行的安全工具触发。（如果你从未听说过 `VirusTotal`，请访问 [https://www.virustotal.com](https://www.virustotal.com) 了解详情。）

> **注意**
>
> 开源渗透测试工具（如 Rapid7 的 `Metasploit`）提供了多种隐藏文件的方法。例如，你可以使用 `Metasploit` 对测试载荷进行编码，并查看你的安全工具是否能检测到你编码后的威胁。Kali Linux 的创建者 Offensive Security 发布了一篇精彩的文章来解释这一概念，地址为 [https://www.offensive-security.com/metasploit-unleashed/generating-payloads/](https://www.offensive-security.com/metasploit-unleashed/generating-payloads/)。

## 行为检测

检测已知恶意行为的概念基于观察到的动作，而非扫描特定事物（模式匹配）。恶意行为可能是从计算机扫描网络到文件尝试获取系统的 root 访问权限等任何行为。回到我恶意文件的例子，假设对手对文件进行了编码，使其不被防病毒特征检测到。防病毒软件可以监控文件的行为以将其识别为恶意。在这个例子中，假设该文件是勒索软件，这意味着它会尝试加密其感染系统的硬盘。如果勒索软件配置为使用非对称加密，它需要在加密过程完成前连接互联网上的外部源以执行密钥交换。这意味着该文件会向威胁行为者拥有的 Web 源发送信标以完成加密过程。文件引起的这些动作中的任何一个都应该触发安全工具，阻止文件继续执行这些动作。这使得行为规则成为验证威胁未绕过特征规则的理想选择。

## 异常检测

当威胁未被特征和行为检测能力识别时会发生什么？这就是异常检测极其有益的地方。虽然检测异常似乎与检测已知恶意行为相似，但它们是不同的。异常检测基于网络基线，标记任何异常情况。例如，某些组织可能允许员工从公司邮箱发送邮件到个人邮箱。尽管在拥有数百名员工的组织中，这种活动可能一直在发生，但 SOC 可以配置一条异常规则，当公司邮箱向个人邮箱发送异常数量的邮件时触发标记。组织为什么要实施这条规则？这种活动可能表明员工即将离职，并在辞职交还电脑前，将大量敏感内部资料发送到个人邮箱。对于此用例，该规则可以是基于行为的（即特定时间内发送一定数量的邮件会触发警报），也可以是基于异常的（查看用户的平均邮件活动，并根据该特定用户标记异常峰值）。某些用户因角色原因可能拥有较高的平均邮件活动量，这使得异常检测能够适应现实世界的活动。此例所示的一个关键点是异常检测不如其他方法准确。对于此例，如果出于合法原因从公司邮箱向个人邮箱发送异常数量的邮件，邮件规则可能会触发。合法原因可能包括用户为授权的邮件营销活动发送大量邮件，或执行邮件备份。

> **注意**
>
> 我在职业生涯中升级电脑时经历过邮件异常检测警报。我花了几分钟时间通过邮件将文件从公司邮箱发送到个人邮箱，因为这比连接外置硬盘或使用云盘传输文件更快。我的目标是快速将文件从旧电脑迁移到新电脑，两台电脑都连接了互联网，因为我需要清理旧电脑以便归还给雇主。在我向个人 Gmail 账户发送了大约 15 到 20 封邮件后，我接到了人力资源部的电话，询问我对目前职位是否满意。基于我异常的邮件活动，我的雇主担心我可能要离职。我只是解释说我在迁移到新电脑，对话就此结束。还要注意，这条规则并非为数据丢失防护目的而设。如果我只发了几封邮件，我不会接到 HR 或数据安全团队的电话，因为实际数据未被评估。这意味着该异常规则仅旨在针对发送数据量的激增，以锁定潜在的员工离职风险。
