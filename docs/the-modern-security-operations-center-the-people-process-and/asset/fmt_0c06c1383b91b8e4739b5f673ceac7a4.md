
# 桌面推演

桌面推演是一种基于假设场景的演练，用于演示组织如何应对安全事件。其目的是在概念上测试人员、流程和技术，而无需这些资源执行实际响应。当需要对策略进行真实世界测试时，渗透测试等其他服务更为理想。

桌面推演的一个示例是测试组织如何应对勒索软件大流行。勒索软件不会凭空出现在终端上，因此桌面推演会考虑从响应到恢复的各个方面。对于此场景，执行桌面推演的团队可能会被问到以下示例问题：

* 谁负责接收最终用户关于在其系统上发现恶意软件的通知？
* 存在哪些终端应用程序能够识别并提醒 IT 部门有关勒索软件等恶意软件的情况？
* 存在哪些工具可用于确定所识别的恶意软件类型？
* 哪个团队监控终端，该团队如何响应事件？
* 当发现恶意软件时，如何界定范围并进行遏制？
* 将采取哪些补救措施，由谁执行这些步骤？
* 将采取哪些取证步骤来确定恶意软件是如何安装在终端上的？
* 将采取哪些漏洞和安全评估行动，以确保其他系统不受导致恶意软件感染的恶意软件或漏洞的影响？
* 谁负责对外或对内发布信息，解释该恶意软件的影响？
* 哪些具体团队成员将成为响应团队的一部分？他们的替补是谁？
* 什么样的响应时间和结果会被视为成功或失败？
* 组织当前的预期响应与期望的成功响应有何对比？
* 人员、流程和技术方面存在哪些差距，会影响对此威胁的成功响应？
* 人力资源、管理和法务团队的哪些成员会因事件导致的任何必要纪律处分而参与其中？

从示例问题列表可以看出，桌面推演可能非常复杂，需要数小时才能妥善执行。你还应该注意到，组织不同部门的成员都需要参与，以便在桌面推演期间彻底验证将要评估的人员、流程和技术。这就引出了一个问题：谁应该参与桌面推演？简短的回答是：视情况而定。以下部分概述了交付桌面推演的不同选项，这些选项需要不同的人员参与演练。

## 桌面推演选项

执行桌面推演有不同的方法。一种方法是为组织内的不同群体运行相同的场景，这意味着要执行多个较小的桌面推演。以勒索软件示例为例，组织可以首先与桌面支持团队合作，了解他们将如何应对勒索软件情况。接下来，组织可以与网络安全团队会面，运行相同的勒索软件场景，但重点关注他们对整体事件响应的影响。采用这种小组方法有利于保持演练的专注度，减少参与人数，并可能降低其他团队影响或干扰特定团队在桌面推演中响应方式的担忧。

交付桌面推演的另一种方法是让各部门的管理者参与，并在同一次会议中获取所有部门的意见。这种方法允许每个部门在场景涵盖过程中贡献意见，而不需要交付桌面推演的团队将所有单独小组演练的响应整合到一份桌面推演结果文档中。这还允许在分析基于桌面推演后发生的变化的当前和潜在未来响应时进行实时辩论。让组织内所有团队参与时存在的一些顾虑包括：会议规模、听取桌面推演中所有参与成员反馈所需的时间，以及部门间潜在的冲突。将桌面推演仅限于部门管理者可以缓解这些及其他问题；然而，部门管理者可能不知道回答桌面推演期间问题所需的具体细节。例如，管理者可能不知道将使用的具体技术，但会知道其团队中哪位成员能够回答此类问题。采用管理者主导的桌面推演形式将要求管理者将未回答的问题带回团队，稍后提供答复。

## 桌面推演执行

桌面推演的最佳形式通常取决于正在测试的场景。然而，以下技巧普遍适用于执行成功的桌面推演，改编自 Bob Violino 撰写的 CSO 文章“6 Tips for Effective Security Tabletop Testing”：

* **花时间准备演练：** 投入时间制定目标和范围，并选择合适的参与者。规划通常是最耗时的阶段，但会为演练的成功带来回报。参与人员不当或范围过窄、过宽不仅会产生不良结果，还会导致参与者认为他们的时间被浪费，从而对桌面推演后的任何建议调整缺乏支持。
* **让来自不同部门的多方参与：** 安全是组织中每个人的责任。这意味着事件响应将影响许多不同的部门。最好的桌面推演结果来自于让所有将受影响并可能在事件响应期间提供价值或造成麻烦的相关方参与。
* **预先制定基本规则：** 桌面推演代表演练压力情境。有些人可能希望无论话题积极或消极都能公开发言，而另一些人可能除非被点名否则不愿参与。不解决会议中不同的个性差异会导致挫败感和对演练结果支持的丧失。务必预先设定对必要参与度的期望、演练期间可以和不可以讨论的内容、会后可以和不可以谈论的内容，以及任何其他基本规则，以确保每个人的时间都得到成功利用。
* **利用外部资源（如果可用）：** 许多组织已使用桌面推演服务，且有最佳实践文档可用。聘请提供桌面推演服务的顾问可能很有价值，因为顾问提供外部、无偏见的声音，并拥有执行成功桌面推演的经验。如果您的团队从未交付过桌面推演，建议寻求外部支持，并在执行自己的内部演练之前向他人的最佳实践学习。
