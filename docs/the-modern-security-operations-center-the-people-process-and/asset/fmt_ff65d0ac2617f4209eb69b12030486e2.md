
# 检测与分析

## 检测能力

执行 SOC 安全能力评估（参见[第 1 章](#ch01.xhtml#ch01)），以确保您具备以下一项或多项入侵检测能力：

*   将内部入侵检测系统 (IDS) 连接到 SPAN/端口镜像以监控内部流量
*   监控网络设备内的数据，如 NetFlow
*   设置蜜罐以引诱威胁攻击蜜罐而非真实目标
*   使用工具监控出站流量，查找与高风险资源（如暗网、Tor 或已知恶意资源）的通信
*   捕获和分析网络内部的数据包
*   您的员工及其系统向您报警可能发生的事件

> **注意**：当我说具备一项或多项能力时，并不意味着您的最终用户应该是唯一的检测能力！

[第 5 章](#ch05.xhtml#ch05)“[数据集中化](#ch05.xhtml#ch05)”介绍了如何将安全工具的日志拉取到集中式工具中，并将该数据转化为可操作的情报。利用这些概念制定事件响应程序文档，涵盖谁应监控集中式数据工具、事件如何在适用时转化为案例，以及所有这些如何在您的 SOC 分级支持模型中运作。

随着可能的事件被您的 SOC 或外部方检测到，检测与分析阶段的后半部分开始启动，您的事件响应程序将分析已检测到的内容。此时，您的事件响应团队的目标是确定威胁是否真实，如果是，适当的响应是什么。这种做法通常被称为**威胁分析**。

## 威胁分析

SOC 事件响应团队将遇到存在潜在威胁但需要进一步分析以确定威胁是否真实的情况。例如：

*   员工可能报告“自从我运行这个文件后，我的电脑表现异常”，并询问该文件是否包含恶意软件。
*   用户可能抱怨收到的邮件被标记，附件被移除并存入沙箱。用户可能会询问为何移除文件，威胁分析团队必须能够证明该文件构成风险。
*   用户可能抱怨外部资源被屏蔽，并希望 SOC 批准允许访问这些资源。威胁分析团队需要基于资源被屏蔽的原因，通过威胁分析研究来解释被屏蔽资源背后的风险。

在所有这些情况下，SOC 都需要在采取任何行动（如执行事件响应或通知最终用户不存在风险）之前，确定与工件和资源相关的风险。

分析服务涉及调查工件和研究恶意软件的特定技能组合。正如[第 3 章](#ch03.xhtml#ch03)所述，分析服务回答关于工件是什么及其预期用途（恶意或安全）的问题。事件响应分析师与恶意软件分析师技能组合的总体对比在于各自处理恶意软件的方式：

*   **事件响应分析师**：想了解与工件相关的总体风险，并负责响应威胁。
*   **恶意软件分析师**：知道如何识别工件是否恶意、隔离工件、研究其特性以更好地理解其功能、寻找威胁所有变体的特征，甚至可能制定步骤以降低未来类似威胁攻击的风险。

普通事件响应分析师不知道如何反汇编恶意软件或阅读汇编语言，这就是为什么分析服务包含具有非常具体和专业分析技能的 SOC 员工。请参阅[第 4 章](#ch04.xhtml#ch04)以了解更多与分析专家相关的技能组合。

### 检测恶意软件行为

恶意软件开发者知道像您这样的安全工具和 SOC 存在。我合作过的团队和安全行业的朋友们已经瓦解了攻击活动的实施者，并发现他们拥有包含行业内所有安全工具的研究实验室。恶意软件开发者通常拥有流行厂商的防火墙型号、IPS 工具、各种沙箱、大多数现代防病毒产品，以及您的组织和其他组织用于防御网络威胁的任何其他工具。在分析工件时请记住这一点，并预期会遇到旨在混淆您和您用于了解威胁的工具的反检测、反反汇编和反调试战术。

### 受感染系统

一旦恶意软件安装在受影响的系统上，您应该预期它会执行许多操作。以下是您可能遇到的常见恶意软件行为的部分列表：

*   创建新文件和/或修改现有文件
*   将恶意文件移动或复制到已知位置（如 Windows 系统文件夹）；此处的恶意软件可使用用户权限运行
*   恶意软件可能不生成可执行文件，而是生成 DLL 或批处理脚本
*   删除其创建的临时文件
*   创建注册表项（可能还控制网络适配器）
*   创建唯一标识符，这些标识符本身无害但非常适合检测恶意软件家族
*   禁用安全工具，如 Windows 防火墙
*   向恶意源“回连”

凭借经验，您的 SOC 分析师团队将学会识别这些恶意软件行为及其他更多行为；但是，您不必具有查找恶意软件行为的经验就能分析恶意软件。好消息是，我将介绍的许多行业工具会为您完成检测和分析工作！[图 8-7](#ch08.xhtml#ch08fig07) 显示了由 Cisco Advanced Malware Protection (AMP)（一种端点检测和响应 (EDR) 程序）生成的分析报告，显示了导致工件被判定为恶意软件的所有指标。任何技能水平的分析师都可以执行恶意软件分析，但技能更娴熟的专业人员能够在安全工具提供的数据之外开展工作。我强烈建议您的 SOC 利用行业认证和培训计划来提升负责分析工件人员的技能，因为这个领域非常专业且难以招聘。

### 分析工件

分析工件的第一个重要观点是**不存在单一的分析方法**。我强烈建议您在调查工件时始终牢记这一概念。如果一种方法不起作用，请尝试其他方法。不要纠结于某一战术的失败，因为很可能还有另一种方法能实现相同的结果，即确定工件是否构成威胁以及它的功能是什么。

不同的工具擅长不同的工作，并能提供对同一事物的不同视角。一个简单的例子是使用不同的 Web 浏览器分析外部资源。为此，我的 Mac 上安装了 Firefox、Chrome 和 Safari。有时某事在一种浏览器中无法工作，但当我切换浏览器时却能神奇地正常运行。请记住，如果一种工具失败了，请尝试另一种。
