

## 发现阶段

发现阶段由两部分组成。首先，识别所有落在范围内的网络端口和服务，以制定潜在目标列表。也可能使用其他技术，例如垃圾箱搜寻，目的是收集信息并建立潜在目标列表。这些数据收集步骤属于 `目标侦察` 类别，是最耗时但也是最有价值的工作。发现并收集的关于目标的高质量数据越多，识别可利用的潜在目标的能力就越强。您可以用来进行目标侦察的一些示例工具包括：用于执行端口扫描的 `NMAP` 和 `masscan`；用于研究面向 Web 的资源（如网站、网络摄像头和支持网络的 IoT 设备）的 `Shodan`；以及搜索 `LinkedIn` 和 `Facebook` 等社交媒体来源，以获取目标网络内工作人员的详细信息。

发现阶段的第二部分是分析潜在目标的漏洞。漏洞分析通常通过将潜在目标的服务、应用程序和操作系统与漏洞数据库进行比较，或利用测试人员自身的漏洞知识来执行。来自 `Rapid7` 的 `Metasploit` 等工具提供了一个已知漏洞利用的数据库，您只需输入一个已识别的漏洞，即可找到与该弱点相关的各种武器化漏洞利用代码。[图 6-7](#ch06.xhtml#ch06fig07) 展示了在 `Metasploit` 中搜索 Apache Struts 漏洞的示例。请注意可用漏洞利用代码的数量如何超出了屏幕的显示范围！

### 第 3 阶段：攻击

一旦确认目标，实际的利用将在攻击阶段发生。请记住，利用并不一定意味着坏事已经发生。利用可能为恶意行为打开道路，例如将远程访问工具 (RAT)、勒索软件或其他形式的恶意软件推送到系统中。利用的一个示例可能是针对易受 Struts 漏洞利用的系统运行 `Armitage`/`Metasploit` 武器化攻击，如[图 6-8](#ch06.xhtml#ch06fig08) 所示。该示例显示系统有一个开放的 Shell，意味着攻击者拥有对受损系统的完全访问权限。从这一点开始，攻击者可以执行许多操作，包括将此受损系统用作进入网络的网关，以对内部系统发起新的攻击。在该示例中，攻击者通过运行 `whoami` 命令展示了其访问级别。

![图 6-8 使用 Armitage 利用 Struts 漏洞](Images/06fig08.jpg)

**图 6-8** 使用 Armitage 利用 Struts 漏洞

在其他情况下，利用行为会导致负面结果，例如利用网站使其下线，称为拒绝服务攻击。另一个示例可能是使交换机的内存过载，导致其退回到类似集线器的状态，从而允许攻击者查看该设备内的所有流量。从渗透测试的角度来看，使用 `网络攻击链` 是查看利用目标并投放载荷所涉及步骤的好方法，这些步骤也是渗透测试人员和真实攻击者针对目标所使用的步骤。作为[第 1 章](#ch01.xhtml#ch01)的复习，[图 6-9](#ch06.xhtml#ch06fig09) 描绘了 `网络攻击链`。`NIST` 渗透测试流程的攻击阶段对应于 `网络攻击链` 的投放、利用、安装以及命令与控制阶段。

### 第 4 阶段：报告

攻击阶段的结果记录在最后阶段，即报告阶段。报告还应包含其他阶段的步骤，以便记录整个渗透测试过程。报告中使用的语言极其重要，这意味着您必须了解您的目标受众，并考虑基于谁审查报告而产生的影响。我见过人们因对其工作的负面反馈或因渗透测试演习的结果被指责而失去工作。我建议您的渗透测试报告至少应包含以下信息：

*   **漏洞：** 渗透测试期间发现了什么？列出所有漏洞及其详细详情。
*   **影响：** 如果真正的攻击者利用渗透测试演习中发现的漏洞，可能会发生什么潜在的负面影响？
*   **可能性：** 利用已识别的漏洞有多难？是否需要 root 访问权限或内部网络连接，还是说任何人都可以从任何地方访问并利用该漏洞？
*   **风险评估：** 已识别的漏洞如何影响整体业务？
*   **建议：** 针对降低已识别漏洞的风险，有何建议？
*   **参考人员：** 谁参与了渗透测试演习？
*   **其他详细信息：** 请务必包含任何附录、词汇表项目、使用的工具和其他有助于读者理解渗透测试报告的详细信息。

#### NIST SP 800-115 的其他指导

随着您深入阅读文档，`NIST SP 800-115` 提供了更多细节。例如，`NIST` 四阶段渗透测试方法论的攻击阶段进一步细分为四个步骤，如[图 6-11](#ch06.xhtml#ch06fig11) 所示。第一步是获取对目标的访问权限，也称为建立立足点。基于访问的实现方式，当前权限级别可能会受到限制，因此下一步将是尝试提升权限到更高级别，例如管理员级访问。一旦达到最高级别的系统访问权限，第三步是浏览系统以发现获取对其他系统访问权限的机制。最后一步代表漏洞利用的结果，这可能包括安装后门、移除数据（或记录执行此操作的可能性），或针对其他内部系统重复该过程。此循环将重复进行，直到生成足够的结果，以便在 `NIST` 渗透测试方法论的报告阶段进行记录。
