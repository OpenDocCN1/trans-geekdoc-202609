#### SOC 目标评估总结

完成这项工作后，您的组织将大致了解哪些部门是投资 SOC 服务和能力的首要目标，以实现既定目标。目前仍缺少的是识别能力方面的具体差距，以及可以通过整合来创造新预算的领域。在下一节中，我将重点介绍一种基于能力模型评估安全能力的方法论。

以下步骤总结了目标的排序过程：

1.  确立业务目标，并使 SOC/IT 目标和 IT 流程与之对齐。
2.  根据重要性对业务目标和 IT 目标进行排序。
3.  就排名进行辩论，并与组织内的不同群体进行验证，以确保所有声音都被听到。
4.  对每个排名项目应用差距分析，从最关键的项目开始。
5.  将差距分析转化为为期三到五年的计划，以增强 SOC 能力。

我刚才介绍的两个评估项目将产生一份与业务对齐的目标清单。评估 SOC 并制定改进路线图的下一步，是在 IT 目标中识别差距或重叠的能力。例如，如果一个 IT 目标是降低漏洞风险，您如何知道哪些现有能力可以实现该目标？要评估人员和流程，您需要进行桌面推演，这将在[第 4 章](#ch04.xhtml#ch04)中介绍。要评估技术能力，我建议使用 SOC 能力评估。

### SOC 能力评估

上一节讨论了评估 SOC 业务目标、IT 目标和 IT 流程。您学习了如何对这些目标进行排序，以了解如何为投资 SOC 服务和能力确定优先级。我尚未探讨的是如何验证存在哪些 SOC 能力，从而确定具体的投资领域。例如，在线游戏公司拥有哪些能力来实现其游戏和服务 99.9% 正常运行时间的目标？在线学校可以利用哪些能力来确保学生网络正常运行？重点应放在边缘、网络内部还是主机上？假设 SOC 预算有限，最佳的投资选择是什么？

在本节中，我将探讨开发能力图谱，可用于整合相似能力以及识别差距。整合能为未来的工具、人员和服务腾出更多预算。识别差距有助于 SOC 成员和非 SOC 成员了解需要哪些类型的服务和能力来提高 SOC 服务的成熟度。行业标准、指南和框架也可提供改进建议，但如前所述，它们不会针对您的具体组织。能力图谱是根据您的环境定制的，但如果需要，也可以包含在行业标准、指南和框架中发现的缺失能力。

#### 能力图谱

创建能力图谱涉及识别网络的不同部分，并绘制用户和系统在该环境中如何交互。为了更好地理解这一点，让我们演练一下绘制普通组织分支网络的图谱。我将从最终用户入手，尝试定义存在哪些安全能力或服务来保护该用户的笔记本电脑。组织是否在硬件和软件上实行标准化，还是说员工自带设备 (BYOD)？员工是否有权安装或修改软件？根据您的业务需求以及您希望在能力图谱中包含的内容，您可能关心也可能不关心这种详细程度。以在线学校为例，假设学校不关心学生使用哪种操作系统，即允许学生自带系统。这与在线游戏公司等组织不同，后者要求所有员工在公司网络上仅使用公司发放的设备。

##### 能力图谱示例：端点安全

对于此能力图谱示例，我将忽略系统和主机详情，以便纯粹专注于安全技术能力。能力图谱可能包含其他概念，例如主机上运行的服务，但为保持示例简单且聚焦，我将仅关注安全能力。从关注最终用户系统开始，这些计算机将安装防病毒软件以防止已知恶意文件。那么，用于应对更高级未知威胁、能够基于绕过防病毒软件的行为来检测威胁的反恶意软件呢？主机上是否安装了任何内容过滤或信誉安全功能，以保护用户免受外部已知恶意源的侵害？主机系统是否启用了防火墙或基于主机的入侵防御 (`HIPS`)？您可以使用本章前面介绍的行业标准、指南或框架，作为识别端点防护安全能力行业最佳实践的方法，并将这些建议与现有能力进行比较。例如，`NIST` 有一套关于主机系统应具备哪些安全能力的建议。您使用哪个具体标准、指南或框架，应基于您认为对您的组织最有用的一个。

此示例的关键在于列出不同的能力，或至少提供针对威胁的额外检查点。这引出了纵深防御的安全方法。冗余能力（如两个防病毒程序）可被识别为重复能力，在能力图谱中用相同的图标出现两次表示。[图 1-25](#ch01.xhtml#ch01fig25) 展示了绘制基于主机的安全能力的示例。请记住，对于此示例，我仅关注存在于主机内的能力。SOC 服务（如端点漏洞扫描和管理用户权限）未涵盖在内，但它们与 IT 能力同等重要。
