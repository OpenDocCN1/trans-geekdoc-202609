
回顾我的示例，我提到在线游戏公司的 IT 目标将包括保护在线资源，这将需要 DoS 和 Web 攻击防御技术能力及服务。我提到在线学校的目标将是保护网络性能，这将需要漏洞管理、事件响应和网络持续监控的 IT 目标。以这种方式评估 SOC 有助于证明所部署的特定工具和流程的合理性，稍后可以使用之前回顾的任何标准、指南或框架对其成熟度进行评估。[表 1-3](#ch01.xhtml#ch01tab03) 和 [表 1-4](#ch01.xhtml#ch01tab04) 分别概述了在线学校和在线游戏公司的高层业务与技术目标映射示例。

制定技术目标并对其进行排序，应比对业务目标执行相同过程容易得多，因为先前创建的业务目标会影响并缩小技术目标讨论的范围。出于此目的，首先制定并排序业务目标至关重要。目标评估的顺序很重要！我为数百位客户执行过这些评估，很多时候发现，例如，组织在评估前认为他们需要一款新防火墙，但通过评估发现，他们的业务目标凸显出在完全缺乏能力和服务的领域有更大的投资需求。在在线游戏系统的示例中，WAF 和 DoS 技术的优先级应高于新的 NGFW 或分段技术。我在本节开头提出了公司应选择 WAF 还是 NGFW 的问题。对于在线游戏公司示例，基于业务目标和 IT 目标排序的结果，答案将是 WAF。如果另一个组织经历此过程，他们可能会发现基于其得出的结果，NGFW 是更好的投资。

> **Note**
>
> 你可能会想知道为什么 SOC 会参与采购安全工具（我交谈过的一些客户认为 SOC 仅负责响应安全事件）。在我在全球成熟 SOC 中常见的 SOC 服务中，一项关键服务是研发。这项服务专注于研究和评估安全工具，以便组织内预期的安全专家——即 SOC——为组织选择最佳的技术匹配，而不是由组织内的另一个团队选择。我强烈建议 SOC 参与将由 SOC 使用的任何工具的评估。我见过数百次组织采购办公室全权负责获取工具，且仅基于价格选择工具。相信我，这种方法往往会导致糟糕的决策。[第 10 章](#ch10.xhtml#ch10)涵盖了评估是自行创建工具、利用开源工具，还是采购企业级选项。

IT 目标应为高层级，而 IT 流程应针对所提供的特定人员、流程或技术。IT 流程应包含执行某项工作的分步说明、涉及工具的详细信息以及负责执行该服务的人员。一个或多个 IT 流程可以对应单个 IT 目标。例如，一个 IT 流程可能是关于如何配置 WAF 的具体细节，而另一个 IT 流程可能涵盖如何监控 WAF。在这两个 IT 流程中，谁做这项工作、何时做、如何做等详细信息只是应包含的一些信息。IT 流程也可以像前面示例中的 IT 目标一样进行排序。

#### 威胁排序

除目标外，可评估的第三个方面是查看组织面临的主要威胁。这可以补充我在本章前面介绍的威胁建模练习。对威胁进行排序可以证明技术目标如何与业务目标保持一致，并验证是否存在应对高关注情况的能力和流程。威胁类型和预期威胁行为可从威胁建模练习中提取。以在线游戏公司为例，考虑针对其 99.9% 正常运行时间目标的威胁作为业务的首要任务是合理的。这意味着可能导致其服务中断的威胁将被排为 1 级。[表 1-7](#ch01.xhtml#ch01tab07) 和 [表 1-8](#ch01.xhtml#ch01tab08) 分别展示了为我的示例在线学校和在线游戏公司执行此操作的示例。
