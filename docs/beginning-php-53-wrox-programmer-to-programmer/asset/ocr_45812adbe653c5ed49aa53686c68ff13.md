# Chapter 20: Writing High-Quality Code

If you worked through the Try It Examples in previous chapters, you're probably already familiar with include(), require(), include_once(), and require_once(). Essentially, they allow you to include the code contained in a library inside a script file, just as if it had been copied and pasted into the script file.

Here's a simple example. Say you created a simple function animalSpeak() that returns the sound made by a cat, a dog, or a mouse:

```
function animalSpeak($animal ) {
$sounds = array ( "cat" => "meow", "dog" => "woof", "mouse" => "squeak" );

  if ( array_key_exists($animal, $sounds ) ) {
    return $sounds[$animal];
  } else
    return false;
}
```

```
echo animalSpeak("mouse") . "<br />"; // Displays "squeak"
echo animalSpeak("cat") . "<br />"; // Displays meow
```

Here, the function and the code that uses it are both contained within the same script. This is all well, but what if you wanted to call animalSpeak() from within a different script or application? You'd have to copy and paste the code that defines the animalSpeak() function from one script to the other—clearly not the best approach, you'd end up with duplicate versions of animalSpeak() lying about.

This is where the include() function comes in. By storing the animalSpeak() function definition in a separate file, you can include include to include the function from within as many other script files as you like. For example, you might store it in a file called animal_functions.php:

```
<?php
function animalSpeak($animal ) {
$sounds = array ( "cat" => "meow", "dog" => "woof", "mouse" => "squeak" );

  if ( array_key_exists($animal, $sounds ) ) {
    return $sounds[$animal];
  } else
    return false;
}
?>
```

Note that you need to place the <?php ?> around any PHP code in the included file. If you don't do this, the included file will be treated as HTML markup, and sent straight to the browser.
