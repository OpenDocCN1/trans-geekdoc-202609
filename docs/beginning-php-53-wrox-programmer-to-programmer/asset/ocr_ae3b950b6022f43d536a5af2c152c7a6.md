# Chapter 18: String Matching with Regular Expressions

The expression has been laid out in an easy-to-read format using the x pattern modifier. The comments help to make the expression self-explanatory. Essentially, in order to match the expression, the email address needs to consist of a name pattern, followed by an @ symbol, followed by a domain pattern.

The name pattern should be a string of letters and/or digits. The string may optionally contain hyphens, dots, or underscores; however, the name muster't begin with a hyphen or dot.

The domain pattern needs to start with a string of letters and/or digits

Next, the function defines a regular expression to validate a U.S. phone number:

```
$phoneNumberPattern = "/
# Start of string
(
# Optional area code followed by optional
# separator:
\\d{3}\\\[[-.]?\n# Code with parentheses
# or
\\d{3}\[[-.]?\n)?
\\d{3}
# Prefix
# Hyphen or dot separator
# Line number
$\/x*;
# End of string
```

A U.S. phone number can consist of an optional three-digit area code, followed by an optional hyphen, dot, or space, followed by the three-digit prefix, a hyphen or dot, then the four-digit line number. The expression can deal with area codes surrounded by parentheses — such as (599) 123-4567 — as well as area codes without parentheses— for example: 599-123-4567.

The function also defines a regular expression to validate a product code — this is used to convert the product code into products:

```
$productCodePattern = "^(SW|MW|WW)(\\d{2})$/i";
```

A product code is simply "SW", "MW", or "WW", followed by a two-digit number. Notice that both portions of the product code are matched using subpatterns so that the matched values can be extracted.
