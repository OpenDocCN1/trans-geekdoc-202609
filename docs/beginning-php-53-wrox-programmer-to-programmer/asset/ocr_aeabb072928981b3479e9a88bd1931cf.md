# # Setting a Cookie in PHP

How do you actually set a cookie in your browser by PHP script? Although you can set a cookie directly with a `Set-Cookie`: HTTP header (using PHP's `header()` function), there's an easier way. PHP provides a built-in function, `setcookie()`, that can send the appropriate HTTP header to create the cookie on the browser. This accepts arguments for each of the cookie fields in the order shown in the previous table. Only the name argument is required, it's always a good idea to supply at least name, value, expires, and path to avoid any ambiguity.

The expires argument should be in UNIX timestamp format. A UNIX timestamp is expressed as the number of seconds from midnight on January 1, 1970 (in the UTC zone) and the date/time to represent. Don't worry—you don't need to work this out yourself. PHP provides many time-related functions to calculate this value, as you see in the moment.

For more on PHP's time and date-related functions, see Chapter 16.

Make sure you call `setcookie()` before sending any output to the browser. This is because `setcookie()` needs to send the `Set-Cookie`: HTTP header. If you output any content before calling `setcookie()`, PHP automatically sends the headers, so the cookie that is called it's too late to send the Set-Cookie: header.

Here's an example where we use `setcookie()` to create a cookie using the user's font size preference (in this case):

```
setcookie("fontSize", time() + 60 * 60 * 24 * 365, "/.example.com", false, true);
```

Note that the expires uses a PHP function called `time()`. This returns the current time in UNIX timestamp format. So the expire is 60 * 60 * 24 * 365 seconds after the current time, or one year into the future. The cookie will remain until deleted, even if the browser is closed unless the user chooses to delete it manually. The remaining arguments set a path of `/` (so the cookie will be returned to any URL within the Web site), a domain of `.example.com` (so that the cookie is sent to any server within the domain `example.com`), no `secure` flag (so that the cookie can be sent over standard HTTP connections), and the `HttpOnly` flag (so that JavaScript cannot read the cookie).

Note that it's a good idea to define the domain with a dot (`.`) character, as in `.example.com`, unless the domain is a hostname as `www.example.com`, in which case the initial period should not be used.

In this next example, `setcookie()` is used to store the number of page views in the user's browser session. Note that the expires argument is zero, so the cookie will disappear when the user closes her browser. In the domain argument is an empty string, which means the browser will only send the cookie back to the exact Web server that created it:

```
setcookie("pageViews", 7, 0, "/*", "", false, true);
```

You can also update an existing cookie simply by calling `setcookie()` with the cookie name and the new value. You still need to supply the path and expires arguments when updating the cookie:

```
setcookie("pageViews", 8, 0, "/*", "", false, true);
```
