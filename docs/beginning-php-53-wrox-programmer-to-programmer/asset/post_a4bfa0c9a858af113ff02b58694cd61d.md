# Introduction

## What You Need to Use This Book

To work through the examples in this book you'll find it helpful to install, or have access to, a Web server running. Because PHP runs happily on most operating systems, including Windows, Linux, and Mac OS, you should have no trouble installing a Web server with the PHP engine on your setup. Chapter 2 contains easy instructions on how to install PHP and the Apache Web server on Windows, Linux, and Mac. You can also use a remote Web server — for example, at your hosting provider — to run the examples.

Although this book covers PHP 5.3, the production version at the time of writing was 5.2. Some sections of the book — particularly Chapter 2 — contain references to version 5.2. However, as long as you install a version of PHP greater than 5.1 — whether that's 5.2, 5.3, or later — you will be fine.

You'll need a text editor to create and edit your PHP scripts, and many free editors are available. Windows has the Notepad editor built in, which is fine for small projects. On the Mac you can use TextEdit, or one of the command-line editors such as vi or Emacs. On Linux you can use vi, Emacs, or another command-line editor, or install one of the graphical text editors for Linux, such as Bluefish (http://bluefish.openoffice.org/).

## Using the Command Line

Some parts of the book — notably the chapters on databases, as well as Appendix D — make use of the command-line interface, or "shell", to enter commands and run programs. This is a powerful tool for communicating with your system.

Before rich graphical environments came into common use, the only way to interact with computers was to type commands, one line at a time. You wanted to run a program? There was no one to click — you typed your name.

Many programs still use the command-line interface. For one thing, it's a lot simpler to write them that may. What's more, many people find it easier to interact with the command prompt with a mouse-driven window environment.

In order to use the command line, you need to do one of the following:

- On Windows, begin the Start menu and choose Accessories ⇨ Command Prompt. Alternatively, press Windows+R to call up the Run dialog, type cmd, and click OK.
- On Ubuntu, choose Applications ⇨ Accessories ⇨ Terminal. On other Linux distributions or flavors of UNIX, look for a program with a name such as console, terminal, xterm, etern, or kterm. These are all widely used shell programs that can be found on a broad range of UNIX-based systems.
- On OS X, double-click the Applications ⇨ Utilities ⇨ Terminal app in the Finder.

After you've called the interface, you'll probably be confronted by a nearly blank window, with just a snippet of text such as one of these:

```
$$
%
C:\n#
bash$
```

This is a command prompt or shell prompt, which is simply there to let you know that the interface is ready to receive instructions — prompting you for commands, in effect. It doesn't really matter what the prompt looks like, just that you recognize it when it appears. In this book, the prompt is designated this way:

```
$
```

The book shows you any commands that you need to type after the prompt ($). The computer-generated output follows below. For example:

```
$ ./hello.php
Hello, world!
$
```

Sometimes a different prompt is shown. For example, if you're working with the MySQL command-line program, the following prompt will be shown:

```
mysql>
```
