## How It Works

Most of the code is similar to the script in Chapter 4. The script displays an XHTML header, then creates a table to display the results. It also uses a for loop to display the Fibonacci numbers to numbers much like the Chapter 4 script.

The difference is in how the Fibonacci numbers are computed. The iterative version in Chapter 4 uses two variables, `$num1` and `$num2`, to hold the current Fibonacci numbers, computing new numbers as it iterates through the loop. On this script, the other uses a recursive function, `fibonacci()`, to compute the Fibonacci number for any given sequence number. This function is then called from the for loop to display the Fibonacci numbers, to numbers.

How does the fibonacci function work? You can see that it accepts the current sequence, `$n`, as an argument. The first line of the function returns the base case:

```php
if ( $n == 0 ) || ( $n == 1 ) return $n;
```

This code checks if sequence number is 0 or 1; if it then it immediately exits the function and returns the sequence (because F is 0 and F is 1). Upon so condition, the function finishes and control is passed back to the calling code.

If the base case hasn't been reached, the second line of code is:

```php
return fibonacci($n-2) + fibonacci($n-1);
```

This code calls the `fibonacci()` function twice — once to compute the Fibonacci two positions lower in the sequence, and once to compute the Fibonacci number's one position lower in the sequence. It adds these two when it returns to the calling code to produce the Fibonacci number for the current sequence number, which will either be the code within the for loop, or another instance of the `fibonacci()` function.

When this function is run with a sequence number of, say, 10, it calls itself to obtain the numbers at positions 8 and 9. In turn, when called with the sequence number 8, it computes the Fibonacci number at this position by calling itself to obtain the numbers at positions 6 and 7, and so on. This process continues until the function is called with a sequence number of 0 or 1; at this point, no longer calls itself but merely returns the value 0 or 1.

You can see that the function calls itself in a pattern that resembles a tree, with the initial call as the root of the tree and the various recursive calls as branches of the tree. In fact, recursive functions are well suited to working on data organized like a tree, as you see working with files and folders in Chapter 11.

## What Is Object-Oriented Programming?

So far in this book you've written code that passes chunks of data from one function to the next — a technique known as procedural programming. Object-oriented programming takes a different approach. Models the real-world things, processes, and ideas that your application is designed to handle. An object-oriented application is a set of collaborating objects that independently handle capabilities.

For example, when a house is being constructed, the plumbers deal with the pipes, and the electricians deal with the wires. The plumbers need only to know which circuit they are on. They only concern themselves with their activities. A general contractor ensures that each subcontractor is completing the work that needs to be accomplished but isn't necessarily interested in the particulars of each task. An object-oriented approach is similar in that each object hides the details of its implementation. How its job is irrelevant to the other components of the system. All that matters is the service that object is to provide.

The concepts of classes and objects, and the ways in which you can use them, are the fundamental ideas behind object-oriented programming. As you'll see, an object-oriented approach gives you some benefits over procedural programming.

## Advantages of OOP

Let's take a look at the advantages of an OOP approach to software development.

To start with, OOP makes it easy to map business requirements to code modules. Because your application is based on real-world objects, you can create a direct mapping of people, things, and concepts to classes. These classes have the same properties and behaviors as the real-world concepts they represent, which helps you quickly identify what code needs to be written and how different parts of the application need to interact.

A second benefit of OOP is code reuse. You frequently need the same types of data in different places in the application. For example, an application that manages hospital patient records might contain a class `Person`. A number of people are involved in patient care — the doctor, nurses, hospital administrators, and so on. By defining a class `Person` that encompasses the properties and methods common to all of these, you can reuse an enormous amount of code in a way that isn't always possible in a procedural programming approach.

What other applications? How many applications can you think of that handle information about individuals? Quite few. A well-written `Person` class can easily be copied from one project to another with little or no change, instantly giving you all the richness for functionality that you developed previously. This is one of the biggest benefits of an object-oriented approach — the opportunities for code reuse within a given application as well as across different projects.

Another OOP advantage comes from the modularity of classes. If you discover a bug in your `Person` class, or want to add new features to the class or change the way it functions, you have only one place to go.
