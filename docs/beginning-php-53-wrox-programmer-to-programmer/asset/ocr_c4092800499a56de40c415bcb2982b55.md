By using any of these three methods (or a combination of them), you can create persistent Web applications that carry their data from one page to the next.

# Saving State with Query Strings

Query strings are a quick, convenient way to pass small amounts of data between browser requests. Common uses of query strings include remembering a user's entered keywords when using a search function, identifying which topic within a forum to display to the user, and specifying which post within a blog to display.

Query string is very easy for the alter, because it is visible and editable within the browser's address bar. Therefore, query strings should be used only in situations where sending incorrect data will not compromise security (unless your script additionally verifies that the users are who they say they are).

> You also need to make sure you don't rely on query strings to authenticate users, because people send URLs to friends in email or instant messaging applications. If your URL contains all the data needed to authenticate a user, and that user uses the URL to a friend, then the friend can pretend to be them! You will find that sessions — discussed later in the chapter — are a much better way of authenticating.

If you've worked through Chapter 9, you're easily somewhat familiar with the concept of query strings. You'll remember that you can send form data in a URL by setting the form's method attribute to get. When the form data is sent to the server, it is appended to the end of the URL as follows:

```
http://localhost/myscript.php?firstName=Fred&lastName=Bishop&
```

In other words, the browser adds a query (?) character to the end of the URL, then follows with each of the form fields as "name=value", each pair separated by an ampersand (&). The query string is the string of the URL after the (?) character.
