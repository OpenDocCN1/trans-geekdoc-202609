The next two statements, getMembers() and getMember(), form the core of the class.
getMembers() expects three arguments: $startRow, $numRows, and $order. It returns a list of $numRows records from the members table, ordered by $order and starting from $startRow. The records are returned as an array of Member objects.

After calling the DataObject::connect method to create a database connection, the method sets up the SQL query to retrieve the rows:

```
$sql = "SELECT SQL_CALC_FOUND_ROWS * FROM TBL_MEMBERS ORDER BY \n$order LIMIT :startRow, :numRows";
```

Much of this is vital to you. By selecting all columns (*) from the members table, ordered by the $order variable, and limited to the range specified by the $startRow and $numRows variables. However, there are a couple of concepts here that you've never seen before.

SQL_CALC_FOUND_ROWS is a special MySQL keyword that computes the total number of rows that would be returned by the query, assuming the LIMIT clause wasn't applied. If the query would return 20 records, but the LIMIT clause limits them to five, SQL_CALC_FOUND_ROWS returns a value of 20. This is useful if it enables you to display records over several pages, as you see in the moment:

:startRow and :numRows are placeholders or parameter markers. They serve two purposes. First of all, let you prepare — that is, MySQL parse the query once, then run it multiple times with different values. If you need to run the same query using different input values — when inserting rows for data, instance — prepared statements can really speed up execution. Second, they reduce the risk of SQL injection attacks. For an alternative to using placeholders to write:

```
$sql = "SELECT SQL_CALC_FOUND_ROWS * FROM TBL_MEMBERS ORDER BY \n$order LIMIT $startRow, $numRows";
```

However, imagine that, due to insufficient checking of input, a malicious user set $numRows to "1; DELETE FROM members". This would run the query as intended, but it would also run the second statement, which would delete all records from your table!

When you use placeholders, you pass data to the query via PDO (as you see shortly), not directly into your query string. This PDO to check the data to ensure that it contains what it’s supposed to contain (integers in this case).

The next block of code is a try catch method. This ensures that any PDO exceptions that occur during the query are caught by the method. The first method calls the prepare() method of the PDO object, passing in the SQL string:

```
$stmt = $pdo->prepare($sql);
```

This sets up the query in the MySQL engine, the two :startRow and :numRows placeholders you created earlier are populated with the actual data from the $stmt variable and :numRows variables:

```
$stmt->bindValue(":startRow", $startRow, PDO::PARAM_INT); \n$stmt->bindValue(":numRows", $numRows, PDO::PARAM_INT);
```
