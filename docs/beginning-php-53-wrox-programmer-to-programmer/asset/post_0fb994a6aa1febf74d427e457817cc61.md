## How It Works

The script starts with the regular XHTML_PAGE header, adding some CSS styles for the table in the page. The next script defineine a constant, PAGE_SIZE, that holds the number of squares to display on each page (in this case).

The script then creates a variable, $start, to hold the first integer to display within the page. This defaults to zero. However, if the field start has been passed to the script in a query string — and the field's value is within an acceptable range — this value is used instead. Note that the script casts the value of $_GET["start"] to an integer as a security measure; it's always good to filter and/or validate any user input to make sure it is of the correct format:

```php
$start = 0;

if ( isset($_GET["start"] ) && $_GET["start"] >= 0 && $_GET["start"] <= 1000000) {
  $start = (int) $_GET["start"];
}
```

Next, the script works out the last integer to display on the current page, and stores it in another variable,

```php
$end = $start + PAGE_SIZE - 1;
```

Now it's a simple case of displaying the title of ten integers, along with their squares. PHP's pow() function is used to calculate the square of each integer:

```php
<h2>Number squaring</h2>

<p>Displaying the squares of the numbers <?php echo $start ?> to <?php echo $end ?>></p>
<table cellspacing="0" border="0" style="width:20em; border:1px solid #666;">
<tr>
<th>n</th>
<th>n²</th>
</tr>

<?php
for ($i=$start; $i <= $end; $i++) {
<tr<?php if ($i % 2 != 0 ) echo ' class="alt"' ?>><td><?php echo $i; ?></td>
<td><?php echo pow($i, 2); ?></td>
</tr>
}
?>
</table>
```

Finally, the Next Page and (if appropriate) Previous Page links are displayed. Notice how the script builds the query string within:

```php
if ($start > 0 ) {
<a href="number_squaring.php?start=<?php echo $start - PAGE_SIZE ?>">&lt; Previous Page</a> |
<?php }

<a href="number_squaring.php?start=<?php echo $start + PAGE_SIZE ?>">Next Page&gt;</a>
```

## Working with Cookies

So you've looked up query strings, and in the previous chapter, hidden form fields as ways to preserve the application's state between requests. Though perfectly adequate for small amounts of temporary data, these techniques become unwieldy when you need to store larger amounts of data for long periods. For example, you might want to allow each user to choose a font size for the text on your site. This would be arduous to implement.

Cookies are a somewhat sophisticated approach to this problem. A cookie lets you store a small amount of data — no more than 4KB — within the browser itself. Then, whenever the browser requests a page on your Web site, the cookie is automatically sent to the server within the request.

Although cookies are somewhat more secure than query strings — for example, a browser (by default) only sends cookies to the Web site that created them — they are still easy for attackers to tamper with. You shouldn't rely on cookies to identify or authenticate your users. Furthermore, it's easy to turn off cookie support in browsers, and many do so. This means your Web site shouldn't rely on cookies for essential functionality — or, if it does, it should prompt you to enable cookies for your site if necessary.

However, if you need to store non-critical data, such as preferences, on an ongoing basis, then cookies are a useful tool.

> Here's a tip: most browsers let you view, as well as delete, any cookies stored by the browser. For example, in Firefox choose Edit -> Preferences (on the Mac), then choose Privacy and click the Cookies button.

## Cookie Components

A cookie is sent from the server to the browser as part of the HTTP headers. Here's an example of an HTTP header to create a cookie:

```
Set-Cookie: fontSize=3; expires=Tuesday, 6-Jan-2009 17:53:08 GMT; path=/; domain=.example.com; HttpOnly
```

As you can see, a cookie contains a number of pieces of information, summarized in the following table:

| Cookie Field | Description |
| --- | --- |
| name (for example) |

Although you can use the domain field to get the browser to send cookies back to other machines within the same domain, you can't use this trick to set cookies for sending to other domains. For example, if your Web site at www.example.com tries to set a cookie with a domain value of www.google.com, the cookie will be rejected by the browser.

## Setting a Cookie in PHP

How do you actually set a cookie in your browser by PHP script? Although you can set a cookie directly with a `Set-Cookie`: HTTP header (using PHP's `header()` function), there's an easier way. PHP provides a built-in function, `setcookie()`, that can send the appropriate HTTP header to create the cookie on the browser. This accepts arguments for each of the cookie fields in the order shown in the previous table. Only the name argument is required, it's always a good idea to supply at least name, value, expires, and path to avoid any ambiguity.

The expires argument should be in UNIX timestamp format. A UNIX timestamp is expressed as the number of seconds from midnight on January 1, 1970 (in the UTC zone) and the date/time to represent. Don't worry — you don't need to work this out yourself. PHP provides many time-related functions to calculate this value, as you see in the moment.

For more on PHP's time and date-related functions, see Chapter 16.

Make sure you call `setcookie()` before sending any output to the browser. This is because `setcookie()` needs to send the `Set-Cookie`: HTTP header. If you output any content before calling `setcookie()`, PHP automatically sends the headers, so the cookie that is too late to send the Set-Cookie: header.

Here's an example where we use `setcookie()` to create a cookie using the user's font preference (in this case):

```php
setcookie("fontSize", time() + 60 * 24 * 365, "/.example.com", false, true);
```
