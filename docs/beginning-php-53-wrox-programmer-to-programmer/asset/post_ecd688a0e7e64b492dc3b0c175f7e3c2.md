
# Chapter 18: String Matching with Regular Expressions

```php
echo preg_match("/\d+\:/i", "12: The Sting"); // Displays "1"
echo preg_match("/\d+\:/i", "Die Hard 2: Die Harder"); // Displays "0"
```

The caret^) specifies that the start of the pattern will only match at the start of the string. Similarly, you can use the dollar ($) symbol to anchor a pattern to the end of the string:

```php
echo preg_match("/\[(G|PG-13|R-NC-17)\]$/", "The Sting [PG]"); // Displays "1"
echo preg_match("/\[(G|PG-13|R-NC-17)\]$/", "[PG Amadeus]"); // Displays "0"
```

By combining the two anchors, you can ensure that a string contains the desired pattern, nothing more:

```php
echo preg_match("/Hello, \w+\$/, "Hello, world"); // Displays "1"
echo preg_match("/Hello, \w+\$/, "Hello, world!"); // Displays "0"
```

The second match fails because the target string contains a non-word character (!) between the searched- and the end of the string.

You can use other anchors for more control over your matching. Here's a full list of the anchors you use within a regular expression:

| Anchor | Meaning |
| --- | --- |
| ^ | Matches at the start of the string |
| $ | Matches at the end of the string |
| \b | Matches at a word boundary (between a \w character and a \W character) |
| \B | Matches at a word boundary |
| \A | Matches at the start of the string |
| \z | Matches at the end of the string |
| \Z | Matches at the end of the string or just before a newline at the end of the string |
| \G | Matches at the starting offset character position, as passed to the preg_match() function |

It's important to note that an anchor doesn't match any characters; it merely ensures that the pattern appears at a specified point in the target string.

# Part III: Using PHP Practice

\A and \z are similar to ^ and $ which will match at the beginning and end of a line, respectively, matching a multi-line string in multi-line mode (explained in the "Altering Matching Behavior with Pattern Modifiers" section in the chapter). \A and \z only match at the beginning and end of the target string, respectively.

\Z is used when reading lines from a file that may or not have a newline character at the end.

\b and \B are used when searching for complete words:

```php
echo preg_match("/.*", "My hovercraft is full of eels"); // Displays "1"
echo preg_match("\\bover\\b", "My hovercraft is full of eels"); // Displays "0"
echo preg_match("\\bover\\b", "One flew over the's nest"); // Displays "1"
```

When using \b, the beginning or end of the string is also considered a word boundary:

```php
preg_match("\\bover\\b", "over and under"); // Displays "1"
```

By using \b anchor, with alternatives within a subexpression, it's possible to enhance the "early date" selection, so that it matches only two or four-digit years (and not three-digits):

```php
preg_match("\\b(jan|feb|mar|apr|may|jul|aug|sep|oct|nov|dec)*\\/\\d{1,2}\\/\\d(2)|d(4))\\b", "jul/15/2006"); // Displays "1"
```

The last part of the expression reads, "either two digits or four digits, followed by a word boundary (or the end of the string)",

```text
\d(2)\\d(4)\b
```

You can create your own types of anchor, for example, you can match only when it comes before an ampersand, or only when it follows a capital letter (without actually including the ampersand or capital in the match). These kinds of custom anchors are known as lookahead and lookbehind assertions, and they're out of the scope of this chapter; however, you can read them in the PHP manual at http://www.php.net/manual/en/regexp.reference.assertions.php.

# Finding Multiple matches with preg_match_all

Though the preg_match() function is useful for many matching scenarios, it only finds the first pattern match in the target string. For example, you might want to extract a list of all the phone numbers mentioned in an email message, or count the number of links in an HTML Web page.

To all matches for a regular expression within a string, use the `preg_match_all()` function. `preg_match_all()` takes the same parameters as `preg_match()`:

- The regular expression
- The string to search through
- An array to hold the matches (note that for `preg_match_all()` the array is not optional)
- Optional flags for the match operation
- An optional offset to start the search

With `preg_match()`, `preg_match_all()` returns the number of matches as an integer. Unlike `preg_match()`, where this value can be 0 or 1, `preg_match_all()` returns the total number of matches in the string:

```php
$text = "Call Mary on 49, John on 56, or Karen: 77";
echo preg_match_all("/(\w+):\s(\d+)/", $text, $matches); // Displays "3"
```

`preg_match_all()` stores all matches in the array passed to the third argument. The matches are stored in the first element of the array (with index 0) as a nested array:

```php
$scores = "John: 43 points, Anna: 75 points, and Nicole: 19 points";
preg_match_all("/(\w+):\s(\d+)/", $scores, $matches);
echo $matches[0][0]; // Displays "John: 43"
echo $matches[1][0]; // Displays "Anna: 75"
echo $matches[2][0]; // Displays "Nicole: 19"
```

If your expression contains subpatterns, the matches are stored in subsequent elements. Consider the following example:

```php
// John scored 43
// Anna scored 75
// Nicole scored 19
```

```php
echo $matches[0][0] . " " . $matches[0][1];
echo $matches[1][0] . " " . $matches[1][1];
echo $matches[2][0] . " " . $matches[2][1];
```

As you can see from this example, the first element is a nested array containing all the matches from the first subpattern (the names), and the second contains matches from the second subpattern (the scores). For each subpattern in the expression, an extra element is created in the matches array.

# Part III: Using PHP in Practice

If you prefer, you can use preg_match_all() swap the arrays so that the first index represents the match number and the second index represents the subpattern (You might find the array easier to work with this). To do this, use the flag PREG_SET_ORDER as the fourth argument to `preg_match_all()`:

```php
$scores = "John: 43 points, Anna: 75 points, and Nicole: 19 points";
preg_match_all("/(\w+):\s(\d+)/", $scores, $matches, PREG_SET_ORDER);
echo $matches[0][0]; // Displays "John: 43"
echo $matches[1][0]; // Displays "Anna: 75"
echo $matches[2][0]; // Displays "Nicole: 19"
```

The following code displays:

```php
// John 43
// Anna 75 points
// Nicole 19 points
```

```php
echo $matches[0][1] . " scored " . $matches[0][2];
echo $matches[1][1] . " scored " . $matches[1][2];
echo $matches[2][1] . " scored " . $matches[2][2];
```

Notice how the array of elements has reversed. Each top-level element in the matches is a nested array containing the full string as element number 0, and each subpattern as element 1 and 2.

As with preg_match(), you pass the PREG_OFFSET_CAPTURE flag to capture the position of each match (or subpattern) in the target string. This causes each match to be returned as a two-element nested array rather than a string, with the first element being the matched text and the second element being the offset. The result is that the matches array contains three levels of nesting: the subpattern number (zero for the whole pattern), the match number, the matched text and offset. For example:

```php
$scores = "John: 43 points, Anna: 75 points, and Nicole: 19 points";
preg_match_all("/(\w+):\s(\d+)/", $scores, $matches, PREG_OFFSET_CAPTURE);
```

The following code displays:

```php
// John: 43 (position: 0)
// Anna: 75 points (position: 18)
// Nicole: 19 points (position: 40)
echo $matches[0][0] . " (" . $matches[0][1] . ")";
echo $matches[1][0] . " (" . $matches[1][1] . ")";
echo $matches[2][0] . " (" . $matches[2][1] . ")";
```

You can combine PREG_SET_ORDER and PREG_OFFSET_CAPTURE as follows:

```php
preg_match_all("/(\w+):\s(\d+)/", $scores, $matches, PREG_SET_ORDER | PREG_OFFSET_CAPTURE);
```

In this case, the top level of the matches array will contain the match number, the second level will contain the subpattern, and the third level will contain the matched text and offset.
