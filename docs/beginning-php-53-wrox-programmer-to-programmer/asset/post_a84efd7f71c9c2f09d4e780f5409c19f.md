If you worked through the previous chapter and this chapter so far, there should be no surprises here. `insert()` builds a SQL statement to insert the data in the current Member object into the database. Note that the statement doesn't attempt to insert a value for the id field, because this is generated automatically by MySQL.

Then the method prepares it with `PDO::prepare()`, binds each of the placeholders to the appropriate value in the Member object's `$data` array property, and executes the statement by `PDOStatement::execute()`. If there were any problems with the insertion, the exception is caught and displayed and the application exits.

Again, you'll recognize the generic structure from the registration.php script in Chapter 9. The main differences are that this script contains additional error checking, and it also creates the new member record (the script in Chapter 9 nearly displayed a thank-message).

The first script includes the required common.inc php file, then checks to see if the registration form has been submitted. If it has, it calls processForm() to handle the form data. Otherwise, it displays form by calling displayForm(), passing in two empty arrays and an empty Member object. (You see why it does not in a moment.)

The displayForm() function, as its name suggests, handles the displaying of the registration form. It expects three arguments:

- $errorMessages is an array holding any error messages to display to the user
- $missingFields is a list of any required fields that weren't filled by the user
- $member is a Member object holding any data entered by the user so far, used for holding temporary form fields if an error needs to be displayed. This gives you an idea of the flexibility of OOP—the script uses the Member class not only for database access, but also to hold temporary data from form submissions.

The function displays the page header, and if any error messages caught in $errorMessages, these are displayed at the top of the page. Otherwise a message is displayed.

Next, the form itself is output. This works using the registration.php file in Chapter 9. Each field is displayed, calling validate() to highlight any required fields. A field's value is prefilled by calling $member->getValueEncoded() to retrieve the previously stored value in the member object. In the case of the checkbox, setChecked() is called to pre-check the appropriate box. With the favoriteGenre() select menu, setSelected() is used to pre-select the correct option.
