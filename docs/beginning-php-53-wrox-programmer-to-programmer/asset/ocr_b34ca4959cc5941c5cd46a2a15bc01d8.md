# Chapter 20: Writing High-Quality Code

# Summary

In this chapter you looked at a wide range of techniques that help you write better code. High-quality code is important because it's quicker and easier for you (and others) to maintain; it's more robust in
the ways it handles problems and errors; and it's more secure against attacks from unscrupulous users.
You explored the following techniques:

+   - How to write modular code: This involves splitting your code into small, easy-to-maintain chunks that can be reused by different applications. You briefly revisited functions and classes, looked at PHP's include(), require(), include_once(), and require_once() functions that let you split your application across different script files, and a quick look at using namespaces to avoid clash function, and constant names across code modules

+   - How to create and use coding standards: Coding standards help you write formatted, readable code that is easier to maintain. You looked at some of the conventions used in PHP and other languages

+   - Creating code documentation: You learned that comments and code documentation are an integral part of well-written applications, and you looked at how to write good comments and use phpDocument to generate documentation

+   - Application security: This important, often-overlooked aspect of Web programming is a critical part of any robust application. You looked at how to check and filter user input to ensure its integrity, as well as how to encode or escape your application's output to ensure it contains only safe data

+   - Error handling: For your application to behave as reliably as possible, it needs to handle problems gracefully. You saw how to use PHP's error handling and logging functions to deal with errors, and how to use the power of exception classes to create flexible, robust error handling

+   - Separating application and presentation code: You looked at how to move your presentation markup into separate template files, creating a clean division between your application's logic and its user interface. This makes your application code easier to work with, both for designers and programmers

+   - Unit testing: You learned about the benefits of testing code in general, and unit testing in particular. Testing code early often saves a lot of headaches down the line. You looked briefly at PHPUnit, a testing framework that lets you write your own automated tests

Having read all the chapters in this book, you know how to not just PHP code, but good PHP code. Creating high-quality code requires time, effort, and discipline, but it results in applications that are easy to maintain and extend. Anyone who works on your code — including you — will thank you for it!
