# Appendix C: Alternatives to MySQL

These days, there's much less to choose between the two systems, MySQL becomes more feature-rich and stable while PostgreSQL gets easier to work with. At the time of writing, the main criticism of MySQL is possibly that it is not strict enough at preventing data loss (such as letting you insert an invalid DATETIME value and silently converting it to zero), PostgreSQL has built-in replication (it can be added as a plugin) and is installed on many Web hosting accounts as MySQL. However, by the time you read this, the gap between the two will doubt have narrowed further.

The truth is, as a Web developer probably doesn't matter greatly which of the two systems you choose initially. If you use PDO to connect to the database, and you're not using some of the more esoteric features of either engine, you'll find it straightforward to port your application from MySQL to PostgreSQL, or vice-versa.

You can find a thorough discussion of the merits of MySQL and PostgreSQL at http://www.wikivs.com/wiki/MySQL_vs_PostgreSQL

Here's the get_fruit.php script for Chapter 12 rewritten to use PostgreSQL instead of MySQL. As you can see, the changes required were minimal:

```
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 1.0//EN"
"http://www.w3.org/TR/DTD/xhtml1-strict.dtd">
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en" lang="en">
<head><title>Fruit</title>
<link rel="stylesheet" type="text/css" href="common.css" />
</head>
<body>

<h1>Fruit</h1>
</body>
</html>

<?php
$dsn = "postgresql:host=localhost;dbname=mydatabase";
$username = "postgres";n$password = "mypass";

try {
    $conn = new PDO($dsn, $username, $password);
$conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ATTR_ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    echo "Connection failed: " . $e->getMessage();
}

$sql = "SELECT * FROM fruit";
echo "<ul>";

try {
    $rows = $conn->query($sql);
    foreach ($rows as $row) {
        echo "<li>A " . $row["name"] . " is " . $row["color"] . "</li>";
    }
}
```
