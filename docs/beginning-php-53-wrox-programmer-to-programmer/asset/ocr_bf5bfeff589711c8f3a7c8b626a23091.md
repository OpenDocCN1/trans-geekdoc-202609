ENUM fields serve two purposes. First, by limiting the range of values allowed in the field, you effectively validating any data that is inserted into the field. If a value doesn't match one of the values in the predefined set, MySQL rejects the attempt to insert the value. Second, ENUM fields can save storage space. Each string value—“crime”, “horror”, and so on—is associated with an integer, and stored in a separate part of the table. Each ENUM field can then be stored as an integer, rather than a string of characters.

As you can imagine, the ENUM data type is quite useful in a situation where there is a small number of possible values for the field. Although you can define up to 65,535 allowed values for an ENUM type, practically speaking, things can get a bit uneasy after 20 or so years!

# The TIMESTAMP Data Type

You'll remember from the last chapter that MySQL stores data and times using a number of different types, such as DATE, DATETIME, TIME, YEAR, and TIMESTAMP. A TIMESTAMP field is a bit different from the other date/time types in it can automatically record the time that occurs. For example, when you add a new row to a table containing a TIMESTAMP column, the field stores the time that the insertion took place. Similarly, whenever a row is updated, the TIMESTAMP field is automatically updated with the time of the update.

The other point to remember about TIMESTAMP fields is that they store the date and time in the UTC (Universal Coordinated Time) time zone, which is essentially the same as the GMT time zone. This won't affect you much, because MySQL automatically converts TIMESTAMP values between UTC and your server's time zone as required. However, bear in mind that if you store a TIMESTAMP value in a table, and you change the server's time zone, the value that you get back from the TIMESTAMP will be different.

A TIMESTAMP field is great for tracking things such as when a record was last created or updated, because you don't have to worry about setting or changing its value; it happens automatically. For example, you created a TIMESTAMP field in the accessLog to track when the last access was made:

```
lastAccess TIMESTAMP NOT NULL,
```
