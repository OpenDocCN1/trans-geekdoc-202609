
# Appendix C: Alternatives to MySQL

These days, there's much less to choose between the two systems, MySQL becomes more feature-rich and stable while PostgreSQL gets easier to work with. At the time of writing, the main criticism of MySQL is possibly that it is not strict enough at preventing data loss (such as letting you insert an invalid DATETIME value and silently converting it to zero), PostgreSQL has built-in replication (it can be added as a plugin) and is installed on many Web hosting accounts as MySQL. However, by the time you read this, the gap between the two will doubt have narrowed further.

The truth is, as a Web developer probably doesn't matter greatly which of the two systems you choose initially. If you use PDO to connect to the database, and you're not using some of the more esoteric features of either engine, you'll find it straightforward to port your application from MySQL to PostgreSQL, or vice-versa.

You can find a thorough discussion of the merits of MySQL and PostgreSQL at http://www.wikivs.com/wiki/MySQL_vs_PostgreSQL

Here's the get_fruit.php script for Chapter 12 rewritten to use PostgreSQL instead of MySQL. As you can see, the changes required were minimal:

```php
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 1.0//EN"
"http://www.w3.org/TR/DTD/xhtml1-strict.dtd">
<html xmlns="http://www.w3.org/1999/xhtml" xml:lang="en" lang="en">
<head><title>Fruit</title>
<link rel="stylesheet" type="text/css" href="common.css" />
</head>
<body>

<h1>Fruit</h1>
</body>
</html>

<?php
$dsn = "postgresql:host=localhost;dbname=mydatabase";
$username = "postgres";
$password = "mypass";

try {
    $conn = new PDO($dsn, $username, $password);
    $conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ATTR_ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    echo "Connection failed: " . $e->getMessage();
}

$sql = "SELECT * FROM fruit";
echo "<ul>";

try {
    $rows = $conn->query($sql);
    foreach ($rows as $row) {
        echo "<li>A " . $row["name"] . " is " . $row["color"] . "</li>";
    }
} catch ( PDOException $e ) {
    echo "Query failed: " . $e->getMessage();
}

echo "</ul>";
$conn = null;
?>
```

## # dbm-Style Databases

dbm is an old type of embedded database engine written in 1979. As with SQLite, the engine is embedded within the program that uses it (the PHP engine in this), and it stores data in files on the server's hard disk. It's not as powerful as SQLite (or other SQL-based database engines), and doesn't use SQL to store and retrieve data. However, it can be extremely fast to retrieve records by key, like SQLite, requires no setup or administration.

dbm isn't used much nowadays, but it has spawned several successors over the years, of which Oracle's Berkeley DB (http://www.oracle.com/technology/products/berkeley-db/index.html) is probably the most popular.

PHP provides access to dbm-style databases through the DBA abstraction layer, which you can think of as "PDO for db databases". However, because the DBA extension is not bundled with the default install of PHP, you'll probably need to recompile PHP to include it. You can find details on how to do this at http://www.lamdocs.com/blog/2008/04/17/adding-dba-to-php/

This example shows how to use a db4 database (the current incarnation of Berkeley DB), create a record of "The MegaWidget", and read the record by looking up its key (123):

```php
$conn = dba_open("/home/joe/products.db", "n", "db4");

if (!$conn) {
    die "Couldn't open database";
}

dba_replace(123, "The MegaWidget", $conn);

if ( dba_exists(123, $conn)) {
    echo dba_fetch(123, $conn); // displays "The MegaWidget"
}

dba_close($conn);
?>
```

## Oracle

Oracle (http://www.oracle.com/database/) is a large, complex, powerful RDBMS. Like MySQL and others, Oracle lets you use SQL manipulate data. Oracle is commonly used in large organizations for storing and managing large amounts of data, such as customer or financial records. Because of these factors, it's fairly expensive to use (though a free version, Oracle XE, is available) and ideally requires an experienced database administrator to set up and run the system.

That said, it's perfectly possible to use Oracle with a Web application, and PHP provides support for Oracle connectivity through both its OCI extension and PDO. This is handy if you're writing a Web site or application to interface with an existing Oracle structure.

Talking to an Oracle database with PDO is fundamentally similar to working with MySQL. Here's an example:

```php
<?php
// Open Oracle database
try {
$conn = new PDO("oci:dbname=mydatabase", $username, $password);
$conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ATTR_ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    echo "Connection failed: " . $e->getMessage();
}

// Add a product
$sql = "INSERT INTO products (id, productname) VALUES (:id, :productname)";
$stmt = $conn->prepare($sql);
$stmt->bindValue(":id", 123, PDO::PARAM_INT);
$stmt->bindValue(":productname", "WonderWidget", PDO::PARAM_STR);
$stmt->execute();

// Retrieve the product
$sql = "SELECT * FROM products WHERE id=:id";
$stmt = $conn->prepare($sql);
$stmt->bindValue(":id", 123, PDO::PARAM_INT);
$stmt->execute();
$product = $stmt->fetch();

// Displays WonderWidget
echo "Product name: " . $product["productname"];
?>
```

## ODBC

ODBC (Open Database Connectivity API). It isn't a database engine as such, but rather it is an application programming interface (API). It allows an application to talk to a variety of database engines, without either the application or the database engine needing knowledge of each other. Communication happens through a driver manager installed on the client machine.

Microsoft Windows has an ODBC driver manager built in, and open-source versions of ODBC exist for other platforms, including various flavors of UNIX, Linux, and Mac OS.

You can connect to an ODBC database using PHP's PDO. (The ODBC extension is built into the Windows version of PHP; however, if you want to use ODBC with PDO you need to connect the PDO_ODBC extension.) Here's a PDO example that connects to a SQL Server database, adds a product to tables, and retrieves the product for display:

```php
<?php
$dsn = "odbc:driver={SQL Server};server=localhost;database=mydatabase";
$username = "username";
$password = "password";

// Connection to SQL Server database
try {
$conn = new PDO($dsn, $username, $password);
$conn->setAttribute(PDO::ATTR_ERRMODE, PDO::ATTR_ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    echo "Connection failed: " . $e->getMessage();
}

// Add a product
$sql = "INSERT INTO products (id, productname) VALUES (:id, :productname)";
$stmt = $conn->prepare($sql);
$stmt->bindValue(":id", 123, PDO::PARAM_INT);
$stmt->bindValue(":productname", "WonderWidget", PDO::PARAM_STR);
$stmt->execute();

// Retrieve the product
$sql = "SELECT * FROM products WHERE id=:id";
$stmt = $conn->prepare($sql);
$stmt->bindValue(":id", 123, PDO::PARAM_INT);
$stmt->execute();
$product = $stmt->fetch();

// Displays WonderWidget
echo "Product name: " . $product["productname"];
?>
```
