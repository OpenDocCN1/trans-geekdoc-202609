## The UNIQUE Constraint

You've already seen how you can use the keywords PRIMARY KEY to create an index on a column that uniquely identifies each row in a table. The UNIQUE constraint is similar to PRIMARY KEY in it creates an index on the column and also ensures that the values in the column must be unique. The differences are:

- You can have as many UNIQUE keys as you like in a table, whereas you can have only one primary key
- The column(s) that make up a UNIQUE key can contain NULL values; primary key columns cannot contain NULLs

In the members table, you add UNIQUE constraints for the username and emailAddress columns because, although they're primary keys, you don't want to allow multiple club members to have the same username or email address.

You can also create a unique key for column (or columns) by using the keywords UNIQUE KEY at the end of the definition. So:

```sql
CREATE TABLE members (
  id SMALLINT UNSIGNED NOT NULL AUTO_INCREMENT,
  username VARCHAR(30) BINARY NOT NULL UNIQUE,
  ...
  emailAddress VARCHAR(50) NOT NULL UNIQUE,
  ...
  PRIMARY KEY (id)
);
```

## The ENUM Data Type

You briefly looked at ENUM columns when learning about data types in the last chapter. An ENUM (enumeration) column is a type of string where only predefined string values are allowed in the field. For the members table, you created two ENUM fields:

ENUM fields serve two purposes. First, by limiting the range of values allowed in the field, you effectively validating any data that is inserted into the field. If a value doesn't match one of the values in the predefined set, MySQL rejects the attempt to insert the value. Second, ENUM fields can save storage space. Each string value—“crime”, “horror”, and so on—is associated with an integer, and stored in a separate part of the table. Each ENUM field can then be stored as an integer, rather than a string of characters.

As you can imagine, the ENUM data type is quite useful in a situation where there is a small number of possible values for the field. Although you can define up to 65,535 allowed values for an ENUM type, practically speaking, things can get a bit uneasy after 20 or so years!

## The TIMESTAMP Data Type

You'll remember from the last chapter that MySQL stores data and times using a number of different types, such as DATE, DATETIME, TIME, YEAR, and TIMESTAMP. A TIMESTAMP field is a bit different from the other date/time types in it can automatically record the time that occurs. For example, when you add a new row to a table containing a TIMESTAMP column, the field stores the time that the insertion took place. Similarly, whenever a row is updated, the TIMESTAMP field is automatically updated with the time of the update.

The other point to remember about TIMESTAMP fields is that they store the date and time in the UTC (Universal Coordinated Time) time zone, which is essentially the same as the GMT time zone. This won't affect you much, because MySQL automatically converts TIMESTAMP values between UTC and your server's time zone as required. However, bear in mind that if you store a TIMESTAMP value in a table, and you change the server's time zone, the value that you get back from the TIMESTAMP will be different.

A TIMESTAMP field is great for tracking things such as when a record was last created or updated, because you don't have to worry about setting or changing its value; it happens automatically. For example, you created a TIMESTAMP field in the accessLog to track when the last access was made:

```sql
lastAccess TIMESTAMP NOT NULL,
```

## Limiting the Number of Rows Returned

You've already seen in the last chapter how to use a WHERE clause to limit the results of a query based on field values:

```sql
mysql SELECT * from fruit WHERE name = 'banana';
+
| id | name  | color  |
+--------------------------------+
| 1  | banana | yellow |
+--------------------------------+
1 row in set (0.08 sec)
```

As well (or instead of) using a WHERE clause, you can set an upper limit on the number of returned rows by the LIMIT keyword. For example, the following query returns the IDs and usernames for just the first four members of the members table:

```sql
mysql SELECT id, username FROM members LIMIT 4;
+------+----------+
| id | username |
+------+----------+
| 1  | sparky   |
| 2  | mary    |
| 3  | jojo     |
| 4  | marty    |
+------+----------+
4 rows in set (0.00 sec)
```

The LIMIT clause always comes at the end of the query. By default, LIMIT starts the first row. However, by including two numbers after LIMIT, you can specify which row to start:

```sql
mysql SELECT id, username FROM members LIMIT 0, 2;
+------+----------+
| id | username |
+------+----------+
| 1  | sparky   |
| 2  | mary    |
+------+----------+
2 rows in set (0.00 sec)
```

## Chapter 13: Retrieving Data from MySQL with PHP

You might be wondering what point of LIMIT is, because you can just loop through the result in PHP. The main reason to use LIMIT is that it reduces the amount of data that has to flow between MySQL and your script. Imagine that you want to retrieve the first 100 rows of a million-row table. If you use LIMIT 100, all 1,000,000 rows will be sent to your PHP script, where they will need to be stored as PDOStatement object you loop through. This will quickly bring the script to a halt, due to the memory required.

LIMIT is particularly useful when building a paging function. For example, if the user requests the second page, and you display 10 results per page, you can use LIMIT to retrieve the second page.
