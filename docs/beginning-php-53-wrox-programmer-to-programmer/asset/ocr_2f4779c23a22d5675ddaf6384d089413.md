Notice the reference to the URL of an external DTD in the second line. This allows a piece of software to validate the document by reading it and making sure the document conforms to a DTD. Of course, you could manually read through the DTD and compare it with the elements, attributes, and other document components specified in the DTD, but many applications are available that can automatically validate an XML document either directly in the document or online; and because the DTD orxsd is available either directly in the document or online, it's easy for these applications to perform the validation for you automatically as they parse the document.

It's also possible to embed the contents of a DTD within the XML document itself, rather than referencing an external DTD. However, embedding is recommended only if the DTD is simple.

DTDs are special documents written in Extended Backus-Naur Form (EBNF), which is not an XML language and isn't easy to parse as XML. DTD specify constraints on XML elements, attributes, content, and more.

XSDS serve the same purpose as DTDs, but are written in the XML-based Schema language, and as easily they can be processed using an XML parser. XSDs are much more capable than DTDs for defining detail in your elements and attributes (such as data type, range of values, and so forth) and are preferred over DTDs by many XML authors. However, XSDs are a complex topic that is out of the scope of this book, so this concentrates on DTDs instead.

> If you're interested in XSDs you can find more at: http://www.wschools.com/schema/default.asp.

# XHTML: An Example of DTDs In Action

As mentioned previously, anyone can author an XML document, and anyone can define a DTD or XSD against which to validate it. One well-known example of a DTD is XHTML, which is HTML reformulated as XML. The XHTML DTD is essentially similar to the existing HTML DTD, with very small modifications, and it defines all the elements, attributes, and other components allowed in an XHTML document. The main difference between HTML and XHTML is that the XHTML document at heart—must conform to the XML specification, whereas HTML documents are not required to do so.

To display an XHTML document as a regular web page, the document will be well-formed, and also validate against the XHTML DTD. In the next few seconds you examine a portion of the DTD for XHTML, learn how the DTD can be referenced in an XHTML document, explore XML namespaces, and learn to create an XHTML web page.
