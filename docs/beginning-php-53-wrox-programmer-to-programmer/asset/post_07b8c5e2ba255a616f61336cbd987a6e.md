| --- | --- |
| $_SERVER ["DOCUMENT_ROOT"] | The absolute path to the document root folder of the Website (for example: /home/matt/mysite/htdocs) |
| $_SERVER ["HTTP_REFERER"] | The referring URL, as seen by the browser of the Referrer HTTP header. (See the "Working with HTTP" section in this chapter for more details) |

| $_SERVER ["PATH_INFO"] | Any extra info appended onto the URL. For example, if the script is accessed via the URL:http://www.example.com/myscript.php/extra/info then $_SERVER ["PATH_INFO"] contains /extra/info. (Not supported on all servers) |
| $_SERVER ["PHP_SELF"] | The URL of the currently running script, relative to the Website's document root. For example: /about/index.php |
| $_SERVER ["QUERY_STRING"] | The query string in the URL of the request, if present (this is the string that appears after the '?' in the URL) |
| $_SERVER ["REMOTE_ADDR"] | The IP address of the visitor's computer (or proxy server if the visitor is using) |
| $_SERVER ["REMOTE_HOST"] | The hostname of the visitor's computer (or proxy server if the visitor is using). Because this involves making a DNS lookup it can have performance hit on the server, so many Web server applications disable this by default. However, you can use gethostbyaddr() to manually retrieve the hostname from the IP address as follows: echo gethostbyaddr( $_SERVER {"REMOTE_ADDR"] ) |
| $_SERVER ["REQUEST_METHOD"] | The request method used to access the script (as GET, POST, or HEAD) |

With all external input, it's unwise to trust the contents of $_SERVER variables. Most of them can be manipulated by your visitors in one way or another. Make sure you check, filter, or encode the values as appropriate.

## Send Email

Many Web applications have a need to send email. For example, a contact form typically processes a form submitted by a visitor and emails the information to the Webmaster. Other scenarios include "tell friend" and "forgot password" functions that email information to members.

PHP includes built-in support for creating and sending email messages, which makes it very easy to send from your PHP scripts. To send an email message in PHP, you use mail() function. On Unix servers such as Linux and Mac OS, PHP uses the system's built-in mail transfer agent (MTA) to send the email (Common MTAs include sendmail, postfix, and exim.). On Non-Unix servers such as Windows, PHP talks directly to SMTP server (either on the server or another machine).

At minimum, mail() requires three arguments:

- A string containing the recipient's email address (or a comma-separated list of email addresses if sending to multiple recipients)
- The email subject line, as a string
- The message body, as a string

mail() returns true if the mail was accepted by the mail server, or false if there was a problem (Note that an email message might still bounce, even if the mail server accepted it for delivery.).

For example, the following code sends an email entitled "Hello", with a message body of "Hi Jim, how are you?", to jim@example.com:

```php
mail("jim@example.com", "Hello", "Hi Jim, how are you?");
```

You can also include the recipient's name in the string, provided you follow it with the recipient's email address in brackets:

```php
mail("Jim Smith <jim@example.com>", "Hello", "How are you?");
```

To send a multi-line message, pass in a string that contains newline characters. Here's an example:

```php
$message = "Hi Jim,
How are you?\n";
mail("Jim Smith<example.com", "Hello", $message);
```

Lines of text in an email body should not exceed 70 characters. To ensure that your lines are of the correct length you can use PHP's wordwrap() function:

```php
$message = wordwrap($message, 70);
```

## Specifying the Sender and Adding Headers

By default, when running on a Unix server like Linux or Mac OS, mail() usually sends messages from the Web server's username, such as "www-data". (On Windows servers you need to specify a default "from" address using sendmail_option in the php.ini configuration file.) If you want to send your email from a "different" address, you can specify that in a fourth argument to mail(), as follows:

```php
mail("Jim Smith<example.com>", "Hello", $message, "From: Bob Jones\n<bob@example.com>");
```

This fourth argument lets you specify additional headers to include in the mail message. In this case, just one header was added — the From: header — but you can add as many as like. Just sure you separate each header by both a carriage return (\r) and line feed (\n) character; this is required by the specification for Internet messages:

```php
$extraHeaders = "From: Bob Jones <bob@example.com>\r\n"
"Cc: Anna James <anna@example.com>\r\n"
"X-Priority: 1 (Highest)\r\n"
"X-Mailer: Matt's PHP Script";
mail("Jim <example.com>", "Hello", $message, $extraHeaders);
```

This code sets four headers: From (the message), Cc: (an additional carbon-copied recipient), X-Priority: (a value from 1 to 5 indicating the importance of the message), and X-Mailer: (a header specifying the software that sends the message).

RFC 2822 defines the format of email messages, including all the different headers you can use in a message. You can read it at: http://www.rfc.org/rfc/2822.

X-Priority and X-Mailer are known as experimental headers and are not officially part of RFC2822 (though usage is widespread).

## Controlling the Return Path Address

If your script is running on a Web server, you can pass additional command-line arguments to the MTA as a mail function(). This is used to add a -f command-line argument in order to set the back-envelope sender or return path address:

Most email messages contain two "from" headers: the From and the Return-Path. The From address is the one usually displayed when the email is viewed in a mail program, and the Return-Path used to determine the "real" sender of the email for the purposes of sending back bounce messages, determining if the email might spam, and so on.

Often the two headers contain the same address. However, when sending mail via a Web script the Return-Path address is usually set to the Web server's username (for example, www@example.com). This can be a problem if you receive bounce messages (you don't have access to the "www" mailbox on the server). By using the -f argument as shown, you can set the Return-Path address to be the same as the From address (or you can set it to any email address you can pick up).

There's one case using -f. If the Web server is not used by the MTA, the MTA adds a warning header to the email message similar to the following:

```
X-Authentication-Warning: www@example.com user set to bob@example.com -f
```
