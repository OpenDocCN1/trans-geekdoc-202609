## MySQL Data Types

When you create a database table — which you do later in the chapter — the type and size of each field must be defined. A field is similar to a PHP variable that you can store only the specified type and size of data in a given field. For example, you can't insert characters into an integer field. MySQL supports three main groups of data types — numeric, date/time, and string — which are outlined in the following sections.

> The descriptions here are fine for everyday use, but they're not complete. For full details see the MySQL manual at http://dev.mysql.com/doc.

This book assumes that you're using MySQL version 5 (the current version at the time of writing).

## Numeric Data Types

You can store numbers in MySQL in many ways, as shown by the following table. Generally speaking, you should pick the data type most suited for the type of numbers you need to store.

| Numeric Data Type | Description | Allowed Range of Values |
|---|---|---|
| TINYINT | Very small integer | -128 to 127, or 0 to 255 if UNSIGNED |
| SMALLINT | Small integer | -32768 to 32767, or 0 to 65535 if UNSIGNED |
| MEDIUMINT | Medium-sized integer | -8388608 to 8388607, or 0 to 16777215 if UNSIGNED |
| INT | Normal-sized integer | -2147483648 to 2147483647, or 0 to 4294967295 if UNSIGNED |
| BIGINT | Large integer | -9223372036854775808 to 9223372036854775807, or 0 to 1844674407390551615 if UNSIGNED |
| FLOAT | Single-precision floating-point number | Smallest non-zero value: ±1.176 × 10⁻³⁸; largest value: ±3.403 × 10³⁸ |
| DOUBLE | Double-precision floating-point number | Smallest non-zero value: ±2.225 × 10⁻³⁰⁸; largest value: ±1.798 × 10³⁸ |
| DECIMAL(precision, scale) | Fixed-point number | Same as DOUBLE, but fixed-point rather than floating-point. precision specifies the total number of allowed digits, many digits sit to the right of the decimal point. |
| BIT | 0 or 1 | 0 or 1 |

Why not just use the data types that can hold the biggest range of numbers, such as BIGINT and DOUBLE? Well, the bigger the data type, the more storage space it takes up in the database. For example, an INT field takes four bytes, whereas a SMALLINT field requires only two bytes of storage. If you end up storing millions of records, those extra two bytes can really make a difference! Use the smallest data type that could hold the range of values you expect to use.

You can add the UNSIGNED attribute to a numeric data type when defining a field. An unsigned data type can only hold positive numbers. In the case of the integer types, an unsigned data type can hold a maximum value that around twice the size of its equivalent signed type. For example, a TINYINT can hold a maximum value of 127, whereas an unsigned TINYINT can hold a maximum of 255. However, for the unsigned FLOAT, DOUBLE, and DECIMAL types, the maximum values are the same as for their equivalents.

## Date and Time Types

With numbers, you can choose from a range of different data types to store dates and times, depending on whether you want to store a date only, a time only, or both:

| Date/Time Data Type | Description | Allowed Range of Values |
| --- | --- | --- |
| DATE | Date | 1 Jan 1000 to 31 Dec 9999 |
| DATETIME | Date and time | Midnight, 1 Jan 1000 to 23:59:59, 31 Dec 9999 |
| TIMESTAMP | Timestamp | 00:00:01, 1 Jan 1970 to 03:14:07, 9 Jan 2038, UTC (Universal Coordinated Time) |
| TIME | Time | -838:59:59 to 838:59:59 |
| YEAR | Year | 1901 to 2155 |

When you need to specify a literal DATE, DATETIME, or TIMESTAMP value in MySQL, you can use any of the following formats:

- YYYY-MM-DD / YY-MM-DD
- YYYY-MM-DD HH:MM:SS / YYYY-MM-DD HH:MM:SS
- YYYYMMDD / YYYYMMDD
- YYYYMMDDHMMSS / YYYYMMDDHMMSS

## String Data Types

MySQL lets you store text or binary strings of data in many different ways, as shown in the following table:

| String Data Type | Description | Allowed Lengths |
|---|---|---|
| CHAR | Fixed-length string | 0 to 255 |
| VARCHAR | Variable-length string | 0 to 65535 |
| BINARY | Fixed-length binary | 0 to 255 |
| VARBINARY | Variable-length binary | 0 to 65535 |
| TINYTEXT | Small text | 0 to 255 |
| TEXT | Normal text | 0 to 65535 |
| MEDIUMTEXT | Medium-sized text | 0 to 16777215 |
| LONGTEXT | Large text | 0 to 4294967295 |
| TINYOB | Small object | 0 to 255 |
| BLOB | Normal-sized object | 0 to 65535 |
| MEDIUMBLOB | Medium-sized object | 0 to 16777215 |
| LONGBLOB | Large object | 0 to 4294967295 |
| ENUM | Enumeration | list of values |
| SET | A set of | list of values |

The difference between CHAR and VARCHAR is that CHAR stores one, whereas VARCHAR uses more. Suppose you insert the following:

- YYYY-MM-DD / YY-MM-DD
- YYYY-MM-DD HH:MM:SS / YYYY-MM-DD HH:MM:SS
- YYYYMMDD / YYYYMMDD
- YYYYMMDDHMMSS / YYYYMMDDHMMSS
