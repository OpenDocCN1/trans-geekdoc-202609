
# Preserving State With Query Strings, Cookies, and Sessions

Most of the PHP scripts you created in previous chapters are very much one-shot affairs. Each time they run, they start with a "clean slate" of variables and other data. This is because each request that a browser makes to a Web server is independent of any previous requests. When a Web server receives a request to run a PHP script, it loads the script into its memory, runs it, then removes all trace of it from memory.

However, most of the Web applications you use today have a need to store data between browser requests. For example, a shopping cart needs to remember which items you have added to your cart, and a forum application needs to remember your identity when you post a message in the forum.

In other words, there is a need to preserve the current state of a user's interaction with an application from one to the next.

You've already looked at a simple example of storing data in the previous chapter, when you used hidden form fields to store previously entered data at each step of a three-stage registration form. Although filling in the registration involved three separate browser requests — therefore three separate runs of the PHP script — the script was able to "remember" the state of the registration process by storing it in the fields.

Although this approach works perfectly for simple cases, it has a few disadvantages. For example, it's slow to store large amounts of data, because all the data has to be carried backward and forward from browser to server during each request. What's more, it's pretty insecure, because it's almost trivial for a mischievous user to change the data stored in the form at will. In addition, if you need to store large numbers of variables between requests, as well as complex variables such as arrays and objects, the hidden form field approach can start to get quite cumbersome.

# Part III: Using PHP Practice

In this chapter, you look at other ways to save state. You learn how to use:

- Query strings to store small amounts of data in the URL
- Cookies to store larger amounts of data in the browser itself
- Sessions to store even larger amounts of data, and store it in a more secure fashion

By using any of these three methods (or a combination of them), you can create persistent Web applications that carry their data from one page to the next.

# Saving State with Query Strings

Query strings are a quick, convenient way to pass small amounts of data between browser requests. Common uses of query strings include remembering a user's entered keywords when using a search function, identifying which topic within a forum to display to the user, and specifying which post within a blog to display.

Query string is very easy for the user, because it is visible and editable within the browser's address bar. Therefore, query strings should be used only in situations where sending incorrect data will not compromise security (unless your script additionally verifies that the users are who they say they are).

> You also need to make sure you don't rely on query strings to authenticate users, because people send URLs to friends in email or instant messaging applications. If your URL contains all the data needed to authenticate a user, and that user uses the URL with a friend, then the friend can pretend to be them! You will find that sessions — discussed later in the chapter — are a much better way of authenticating.

If you've worked through Chapter 9, you're easily somewhat familiar with the concept of query strings. You'll remember that you can send form data in a URL by setting the form's method attribute to get. When the form data is sent to the server, it is appended to the end of the URL as follows:

```
http://localhost/myscript.php?firstName=Fred&lastName=Bishop&
```

In other words, the browser adds a query (?) character to the end of the URL, then follows with each of the form fields as "name=value", each pair separated by an ampersand (&). The query string is the string of the URL after the (?) character.

# Building Query Strings

The great thing about query strings is that they're not limited to form data. Because a query string is simply a string of characters stored in a URL, you can manually create a query string in your PHP script, then include the URL as a link within the displayed page or in email, for example. PHP even has built-in functions to make the process easier.

Here's a simple example that creates two variables, $firstName and $age, then creates a link in the displayed page that contains a query string to store the variable values:

# Chapter 10: Preserving State With Query Strings

```php
<?php
$firstName = "John";
$age = 25;
$queryString = "firstName=" . $firstName . "&age=" . $age;
echo '<a href="moreinfo.php?' . $queryString . '">Click here for info</a>';
?>
```

This code generates the following markup:

```html
<a href="moreinfo.php?firstName=John&age=25">Click here for info</a>
```

If the user clicks this link, moreinfo.php is run:

```php
<?php
$firstName = $_GET['firstName'];
$age = $_GET['age'];
echo "First name: " . htmlspecialchars($firstName) . ", Age: " . htmlspecialchars($age);
?>
```

This outputs:

First name: John, Age: 25
