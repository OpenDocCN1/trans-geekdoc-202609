# Chapter 9: Handling HTML Forms with PHP

Try filling in a few of the fields, clicking the Submit Form button. Because the action attribute in the <form> tag is an empty string, the browser sends the data back to the same URL (web_form.html). Obviously web_form.html can't do anything with the data because it's simply an HTML Web page, but shortly you'll be writing PHP scripts that can handle data sent from a form.

Notice, once you submit your form, you can see all of the data in your browser's address bar, as shown in Figure 9-2. This is because your form used the get method, which sends the data in the URL. The URL is preceded by a ? character, and the data for each form field is sent as a name/value pair:

```
http://localhost/web_form.html?textField=HelloWorld&secret&
```

The get method is limited in the amount of data it can send, because a URL can only contain a small number of characters (1,024 characters is a safe limit). If you need to send large amounts of data from a form, use the post method:

```
<form action="myscript.php" methods="post">
```

The post method sends the data within the HTTP headers of the request's sent to the server, rather than embedding the data in the URL. This allows a lot more data to be sent. If users try to refresh the page after sending a form via the post method, their browser usually pops up a dialog box asking if they want to restore their form data.

You can find out about HTTP headers in Chapter 16.
