# Resource Limits

Web servers have only so much CPU time and RAM to allocate to all running processes, which PHP scripts. It is possible for every PHP script to consume all resources on a server, bringing it to its knees. For this, the PHP engine sets certain limits on the amount of resources each running script can use. You can adjust these limits (although it's best to stick to the defaults if you can).

```
;;;;;;;;;;;;;;;;;;;;
; Resource Limits
;;;;;;;;;;;;;;;;;;;;;

; Maximum execution time of each script, in seconds
; http://php.net/max-execution-time
; Note: This default is hardcoded to 0 for the CLI SAPI
max_execution_time = 30
```

```
; Maximum amount of time each script may spend parsing request data. It's a good
; idea to limit this time on production servers in order to eliminate unexpectedly
; long running scripts.
; Note: This default is hardcoded to -1 for the CLI SAPI
; Default Value: -1 (Unlimited)
; Development Value: 60 (60 seconds)
; Production Value: 60 (60 seconds)
; http://php.net/max-input-time
max_input_time = 60
```

```
; Maximum input variable nesting level
; http://php.net/max-input-nesting-level
max_input_nesting_level = 64
```

```
; Maximum amount of memory a script may consume (128MB)
; http://php.net/memory-limit
memory_limit = 128M
```

# Error Handling and Logging

This section counts how PHP deals with and reports errors. If you have read the "Handling Errors" section of Chapter 20, many of these directives will be familiar to you. Another useful directive is ignore_repeated_errors, which ensures that the same line of code generates the same error repeatedly, the error is logged only once. Finally, track_errors, if enabled, stores the last error message in a predefined variable $php_errorsg (only available in the scope in which the error occurred).

Remember that you should usually turn display_errors off when running PHP on a live Web server.

;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;
;; Error handling and logging;
;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;;

; This directive informs PHP of which errors, warnings and notices you would like
; it to take action. The recommended way of setting values for this
; directive is through the use of error level constants and bitwise
; operators. The error level constants are below for convenience as well as
; some common settings and their meanings.
; By default, PHP will report on all errors, notices and warnings EXCEPT
; those related to E_NOTICE and E_STRICT, which cover better practices and
; recommended coding standards in PHP. For performance reasons, this is the
; recommended error reporting setting. Your production server shouldn't be wasting
; resources complying about best practices and coding standards. That's what
; development servers are for.
; Note: the php.ini-development file has this as E_ALL | E_STRICT. This
; means pretty much reports everything which is exactly what you want during
; development and early testing.

* Error Constants:
* E_ALL - All errors (includes E_STRICT as of PHP 6.0.0)
* E_ERROR - fatal run-time errors
* E_RECOVERABLE_ERROR - almost fatal run-time errors
* E_WARNING - run-time warnings (non-fatal)
* E_PARSE - compile-time parse errors
* E_NOTICE - run-time notices (these are warnings which often result
from a bug in your code, but it is possible that it was intentional (e.g., using an uninitialized variable and relying on the fact it's automatically initialized to an
empty string);
* E_STRICT - run-time notices, enable to have PHP suggest changes to which code will ensure the best interoperability
and forward compatibility of your code
* E_CORE_ERROR - fatal errors that occur during PHP's initial startup
* E_CORE_WARNING - warnings (non-fatal errors) that occur during PHP's initial startup
* E_COMPILE_ERROR - compile-time errors
* E_COMPILE_WARNING - compile-time warnings (non-fatal errors)
* E_USER_ERROR - user-generated error message
* E_USER_WARNING - user-generated warning message
* E_USER_NOTICE - user-generated notice message
* E_DEPRECATED - warn about code that will not work in future versions
of PHP
* E_USER_DEPRECATED - user-generated deprecation warnings
* Common settings:
* E_ALL & ~(E_NOTICE | E_STRICT) - Report all except notices and strict.
* E_ALL - Report everything.
* E_ALL & ~E_STRICT - Report everything except strict.
* E_ALL & ~E_NOTICE - Report everything except notices.
* E_ALL & ~(E_NOTICE | E_STRICT) - Report all except notices and strict.
