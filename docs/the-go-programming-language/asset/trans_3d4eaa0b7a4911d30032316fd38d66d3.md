
虽然 `io.WriteString` 记录了它的假设，但调用它的函数极少会记录它们也做了同样的假设。为特定类型定义方法被视为对某种行为契约的隐式同意。Go 语言的新手，特别是那些有强类型语言背景的人，可能会觉得这种缺乏显式意图的做法令人不安，但在实践中这很少是个问题。除了空接口 `interface{}` 之外，接口类型极少会因无意的巧合而被满足。

上面的 `writeString` 函数使用类型断言来查看通用接口类型的值是否也满足更具体的接口类型，如果满足，则使用该具体接口的行为。无论被查询的接口是标准的（如 `io.ReadWriter`）还是用户定义的（如 `stringWriter`），这种技术都很有用。

这也是 `fmt.Fprintf` 区分满足 `error` 或 `fmt.Stringer` 的值与所有其他值的方式。在 `fmt.Fprintf` 内部，有一个步骤将单个操作数转换为字符串，大致如下：

[点击此处查看代码图片](#ch07_images.html#id210pro02_r)

```go
package fmt

func formatOneValue(x interface{}) string {
    if err, ok := x.(error); ok {
        return err.Error()
    }
    if str, ok := x.(Stringer); ok {
        return str.String()
    }
    // ...所有其他类型...
}
```

如果 `x` 满足这两个接口中的任意一个，那就决定了该值的格式化方式。如果不满足，默认情况会使用反射或多或少统一地处理所有其他类型；我们将在 [第 12 章](#ebook_split_110.html#id-reflection) 了解具体如何做。

同样，这假设任何拥有 `String` 方法的类型都满足 `fmt.Stringer` 的行为契约，即返回一个适合打印的字符串。

## 7.13 类型开关

接口有两种截然不同的使用风格。第一种风格，以 `io.Reader`、`io.Writer`、`fmt.Stringer`、`sort.Interface`、`http.Handler` 和 `error` 为例，接口的方法表达了满足该接口的具体类型之间的相似性，但隐藏了这些具体类型的表示细节和内在操作。重点在于方法，而非具体类型。

第二种风格利用了接口值可以容纳多种具体类型值的能力，将接口视为这些类型的*联合*。使用类型断言在这些类型中动态区分，并区别对待每种情况。在这种风格中，重点在于满足接口的具体类型，而非接口的方法（如果确实有方法的话），并且不隐藏信息。我们将这种使用方式的接口描述为*可辨识联合*。

如果你熟悉面向对象编程，你可能会将这两种风格分别认作*子类型多态*和*特设多态*，但你不必记住这些术语。在本章剩余部分，我们将展示第二种风格的示例。

Go 语言用于查询 SQL 数据库的 API，与其他语言一样，让我们能够清晰地将查询的固定部分与可变部分分离开来。一个示例客户端可能如下所示：

[点击此处查看代码图片](#ch07_images.html#id211pro01_r)

```go
import "database/sql"

func listTracks(db sql.DB, artist string, minYear, maxYear int) {
    result, err := db.Exec(
        "SELECT * FROM tracks WHERE artist = ? AND ? <= year AND year <= ?",
        artist, minYear, maxYear)
    // ...
}
```

`Exec` 方法会用表示相应参数值的 SQL 字面量替换查询字符串中的每个 `'?'`，参数值可以是布尔值、数字、字符串或 `nil`。以这种方式构建查询有助于避免 SQL 注入攻击，这种攻击利用输入数据引用不当，让攻击者控制查询。在 `Exec` 内部，我们可能会找到一个如下所示的函数，它将每个参数值转换为其 SQL 字面量表示法。

[点击此处查看代码图片](#ch07_images.html#id211pro02_r)

```go
func sqlQuote(x interface{}) string {
    if x == nil {
        return "NULL"
    } else if _, ok := x.(int); ok {
        return fmt.Sprintf("%d", x)
    } else if _, ok := x.(uint); ok {
        return fmt.Sprintf("%d", x)
    } else if b, ok := x.(bool); ok {
        if b {
            return "TRUE"
        }
        return "FALSE"
    } else if s, ok := x.(string); ok {
        return sqlQuoteString(s) // (未显示)
    } else {
        panic(fmt.Sprintf("unexpected type %T: %v", x, x))
    }
}
```

`switch` 语句简化了执行一系列值相等性测试的 `if`-`else` 链。类似地，*类型开关*语句简化了类型断言的 `if`-`else` 链。

在最简单的形式中，类型开关看起来像一条普通的 switch 语句，其操作数是 `x.(type)`——这就是字面上的 `type` 关键字——并且每个 case 有一个或多个类型。类型开关基于接口值的动态类型实现多路分支。`nil` case 在 `x == nil` 时匹配，`default` case 在没有其他 case 匹配时匹配。`sqlQuote` 的类型开关将包含以下 case：

```go
switch x.(type) {
case nil:       // ...
case int, uint: // ...
case bool:      // ...
case string:    // ...
default:        // ...
}
```

与普通的 switch 语句一样（[§1.8](#ebook_split_018.html#id-looseends)），case 按顺序考虑，当找到匹配时，执行该 case 的主体。当一个或多个 case 类型是接口时，case 顺序变得重要，因为此时存在两个 case 都匹配的可能性。`default` case 相对于其他 case 的位置无关紧要。不允许使用 `fallthrough`。

注意在原始函数中，`bool` 和 `string` case 的逻辑需要访问类型断言提取出的值。由于这很典型，类型开关语句有一种扩展形式，它将提取的值绑定到每个 case 内的一个新变量：

[点击此处查看代码图片](#ch07_images.html#id212pro01_r)

```go
switch x := x.(type) { /* ... */ }
```

这里我们也将新变量命名为 `x`；与类型断言一样，重用变量名很常见。像 `switch` 语句一样，类型开关隐式创建一个词法块，因此名为 `x` 的新变量声明不会与外部块中的变量 `x` 冲突。每个 `case` 也隐式创建一个单独的词法块。

使用类型开关的扩展形式重写 `sqlQuote` 使其清晰得多：

[点击此处查看代码图片](#ch07_images.html#id212pro02_r)

```go
func sqlQuote(x interface{}) string {
    switch x := x.(type) {
    case nil:
        return "NULL"
    case int, uint:
        return fmt.Sprintf("%d", x) // x 在这里的类型是 interface{}。
    case bool:
        if x {
            return "TRUE"
        }
        return "FALSE"
    case string:
        return sqlQuoteString(x) // (未显示)
    default:
        panic(fmt.Sprintf("unexpected type %T: %v", x, x))
    }
}
```

在这个版本中，在每个单类型 case 的块内，变量 `x` 具有与该 case 相同的类型。例如，`x` 在 `bool` case 中类型为 `bool`，在 `string` case 中类型为 `string`。在所有其他情况下，`x` 具有 `switch` 操作数的（接口）类型，在本例中为 `interface{}`。当多个 case 需要相同的动作时，如 `int` 和 `uint`，类型开关使组合它们变得容易。

虽然 `sqlQuote` 接受任意类型的参数，但只有当参数的类型与类型开关中的某个 case 匹配时，函数才会正常完成；否则它会因“unexpected type”（意外的类型）而 panic。虽然 `x` 的类型是 `interface{}`，但我们将其视为 `int`、`uint`、`bool`、`string` 和 `nil` 的*可辨识联合*。
