
重命名导入即使在没有冲突时也很有用。如果导入包的名称笨重（自动生成的代码有时会出现这种情况），使用缩写名称可能更方便。应始终如一地使用相同的短名称以避免混淆。选择替代名称有助于避免与常见的局部变量名发生冲突。例如，在一个包含许多名为 `path` 的局部变量的文件中，我们可以将标准包 `"path"` 导入为 `pathpkg`。

每个导入声明都会建立从当前包到被导入包的依赖关系。如果这些依赖关系形成循环，`go build` 工具会报错。

## 10.5 空白导入

将包导入文件却不在该文件中引用其定义的名称是错误的。然而，有时我们必须导入包仅仅为了其副作用：求值其包级变量的初始化表达式并执行其 `init` 函数（[§2.6.2](#ebook_split_025.html#id-packageinitialization)）。为了抑制原本会遇到的“未使用导入”错误，我们必须使用重命名导入，其中替代名称为 `_`（空白标识符）。和往常一样，空白标识符永远不能被引用。

[Click here to view code image](#ch10_images.html#id287pro01_r)

```
import _ "image/png" // register PNG decoder
```

这被称为**空白导入**。它最常用于实现一种编译时机制，即主程序通过空白导入额外的包来启用可选功能。首先我们将看到如何使用它，然后了解其工作原理。

标准库的 `image` 包导出了一个 `Decode` 函数，该函数从 `io.Reader` 读取字节，判断数据使用哪种图像格式编码，调用相应的解码器，然后返回生成的 `image.Image`。使用 `image.Decode`，很容易构建一个简单的图像转换器，以一种格式读取图像并以另一种格式写出：

[Click here to view code image](#ch10_images.html#id287pro02_r)

gopl.io/ch10/jpeg

```
// The jpeg command reads a PNG image from the standard input
// and writes it as a JPEG image to the standard output.
package main

import (
    "fmt"
    "image"
    "image/jpeg"
    _ "image/png" // register PNG decoder
    "io"
    "os"
)

func main() {
    if err := toJPEG(os.Stdin, os.Stdout); err != nil {
        fmt.Fprintf(os.Stderr, "jpeg: %v\n", err)
        os.Exit(1)
    }
}

func toJPEG(in io.Reader, out io.Writer) error {
    img, kind, err := image.Decode(in)
    if err != nil {
        return err
    }
    fmt.Fprintln(os.Stderr, "Input format =", kind)
    return jpeg.Encode(out, img, &jpeg.Options{Quality: 95})
}
```

如果将 `gopl.io/ch3/mandelbrot`（[§3.3](#ebook_split_030.html#id-mandelbrot)）的输出传递给转换程序，它会检测到 PNG 输入格式并写入 [Figure 3.3](#ebook_split_030.html#id-figures-mandelbrot) 的 JPEG 版本。

[Click here to view code image](#ch10_images.html#id287pro03_r)

```
$ go build gopl.io/ch3/mandelbrot
$ go build gopl.io/ch10/jpeg
$ ./mandelbrot | ./jpeg >mandelbrot.jpg
Input format = png
```

注意 `image/png` 的空白导入。没有该行，程序照常编译链接，但无法再识别或解码 PNG 格式的输入：

[Click here to view code image](#ch10_images.html#id288pro01_r)

```
$ go build gopl.io/ch10/jpeg
$ ./mandelbrot | ./jpeg >mandelbrot.jpg
jpeg: image: unknown format
```

其工作原理如下。标准库提供了 GIF、PNG 和 JPEG 的解码器，用户也可以提供其他解码器，但为了保持可执行文件体积小，除非显式请求，否则解码器不会包含在应用程序中。`image.Decode` 函数查阅支持格式的表。表中的每个条目指定四项内容：格式名称；所有以这种方式编码的图像的前缀字符串（用于检测编码）；一个解码已编码图像的 `Decode` 函数；以及一个仅解码图像元数据（如尺寸和色彩空间）的 `DecodeConfig` 函数。通过调用 `image.RegisterFormat` 向表中添加条目，通常在每种格式的支持包的包初始化器中进行，例如 `image/png` 中的这个：

[Click here to view code image](#ch10_images.html#id288pro02_r)

```
package png // image/png

func Decode(r io.Reader) (image.Image, error)
func DecodeConfig(r io.Reader) (image.Config, error)

func init() {
    const pngHeader = "\x89PNG\r\n\x1a\n"
    image.RegisterFormat("png", pngHeader, Decode, DecodeConfig)
}
```

其效果是：应用程序只需空白导入所需格式的包，即可使 `image.Decode` 函数能够解码该格式。

`database/sql` 包使用类似的机制让用户仅安装所需的数据库驱动程序。例如：

```

                                               unknown driver "sqlite3"
```

## 10.6 包与命名

本节将提供一些建议，说明如何遵循 Go 语言独特的包及其成员命名约定。

创建包时，保持名称简短，但不要短到晦涩难懂。标准库中最常用的包名为 `bufio`、`bytes`、`flag`、`fmt`、`http`、`io`、`json`、`os`、`sort`、`sync` 和 `time`。

在可能的情况下要具有描述性且明确。例如，当 `imageutil` 或 `ioutil` 这样具体且简洁的名称可用时，不要将工具包命名为 `util`。避免选择常用于相关局部变量的包名，否则可能会迫使包的客户端使用重命名导入，就像 `path` 包那样。

包名通常采用单数形式。标准包 `bytes`、`errors` 和 `strings` 使用复数形式是为了避免隐藏对应的预声明类型，而在 `go/types` 的情况下，是为了避免与关键字冲突。

避免使用已有其他含义的包名。例如，我们最初在 [Section 2.5](#ebook_split_024.html#id-typedeclarations) 中将温度转换包命名为 `temp`，但这名字没用多久。这是个糟糕的主意，因为“temp”几乎是“temporary”的通用同义词。我们短暂地用过 `temperature`，但太长且没说明包的功能。最终它变成了 `tempconv`，这更短且与 `strconv` 并行。
