

## 7.14 基于 Token 的 XML 解码

[第 4.5 节](#ebook_split_039.html#id-json) 展示了如何使用 `encoding/json` 包中的 `Marshal` 和 `Unmarshal` 函数将 JSON 文档解码为 Go 数据结构。`encoding/xml` 包提供了类似的 API。当我们想要构建文档树的表示时，这种方法很方便，但对于许多程序来说这是不必要的。`encoding/xml` 包还提供了一个用于解码 XML 的低级*基于 Token* 的 API。

在基于 Token 的风格中，解析器消费输入并产生一个 Token 流，主要分为四种——`StartElement`、`EndElement`、`CharData` 和 `Comment`——每种都是 `encoding/xml` 包中的一个具体类型。每次调用 `(*xml.Decoder).Token` 都会返回一个 Token。

API 的相关部分如下所示：

```go
package xml

type Name struct {
    Local string // 例如 "Title" 或 "id"
}

type Attr struct { // 例如 name="value"
    Name  Name
    Value string
}

// Token 包含 StartElement、EndElement、CharData、
// 和 Comment，以及一些晦涩的类型（未显示）。
type Token interface{}
type StartElement struct { // 例如 <name>
    Name Name
    Attr []Attr
}
type EndElement struct { Name Name } // 例如 </name>
type CharData []byte                 // 例如 <p>CharData</p>
type Comment []byte                  // 例如 <!-- Comment -->

type Decoder struct{ /* ... */ }

func NewDecoder(io.Reader) *Decoder
func (*Decoder) Token() (Token, error) // 返回序列中的下一个 Token
```

`Token` 接口没有任何方法，也是一个判别联合的例子。像 `io.Reader` 这样的传统接口的目的是隐藏满足它的具体类型的细节，以便可以创建新的实现；每个具体类型都被统一对待。相比之下，满足判别联合的具体类型集合是由设计固定并暴露的，而不是隐藏的。判别联合类型只有很少的方法；操作它们的函数被表示为一组使用类型开关的情况，每种情况有不同的逻辑。

下面的 `xmlselect` 程序提取并打印 XML 文档树中特定元素之下的文本。使用上述 API，它可以在一次遍历输入的过程中完成任务，而无需实例化树。

```go
// Xmlselect 打印 XML 文档中选定元素的文本。
package main

import (
    "encoding/xml"
    "fmt"
    "io"
    "os"
    "strings"
)

func main() {
    dec := xml.NewDecoder(os.Stdin)
    var stack []string // 元素名称栈
    for {
        tok, err := dec.Token()
        if err == io.EOF {
            break
        } else if err != nil {
            fmt.Fprintf(os.Stderr, "xmlselect: %v\n", err)
            os.Exit(1)
        }
        switch tok := tok.(type) {
        case xml.StartElement:
            stack = append(stack, tok.Name.Local) // 入栈
        case xml.EndElement:
            stack = stack[:len(stack)-1] // 出栈
        case xml.CharData:
            if containsAll(stack, os.Args[1:]) {
                fmt.Printf("%s: %s\n", strings.Join(stack, " "), tok)
            }
        }
    }
}

// containsAll 报告 x 是否按顺序包含 y 的元素。
func containsAll(x, y []string) bool {
    for len(y) <= len(x) {
        if len(y) == 0 {
            return true
        }
        if x[0] == y[0] {
            y = y[1:]
        }
        x = x[1:]
    }
    return false
}
```

`main` 中的循环每遇到一个 `StartElement`，就将元素名称压入栈，每遇到一个 `EndElement` 就从栈中弹出名称。API 保证 `StartElement` 和 `EndElement` Token 的序列将正确匹配，即使在格式不良的文档中也是如此。`Comment` 被忽略。当 `xmlselect` 遇到 `CharData` 时，只有当栈包含命令行参数指定的所有元素且顺序一致时，才会打印该文本。

**练习 7.17：** 扩展 `xmlselect`，使得元素不仅可以按名称选择，还可以按属性选择，类似于 CSS 的方式，例如，像 `<div id="page" class="wide">` 这样的元素可以通过匹配的 `id` 或 `class` 以及其名称来选择。

**练习 7.18：** 使用基于 Token 的解码器 API，编写一个程序来读取任意 XML 文档并构建一个通用节点树来表示它。节点分为两种：`CharData` 节点代表文本字符串，`Element` 节点代表命名元素及其属性。每个元素节点都有一个子节点切片。

你可能会发现以下声明很有帮助。

```go
import "encoding/xml"

type Node interface{} // CharData 或 *Element

type CharData string

type Element struct {
    Type     xml.Name
    Attr     []xml.Attr
    Children []Node
}
```

## 7.15 几点建议

在设计新包时，初学者 Go 程序员通常首先创建一组接口，然后再定义满足它们的具体类型。这种方法会导致许多接口，每个接口只有一个实现。不要这样做。这种接口是不必要的抽象；它们也有运行时成本。你可以使用导出机制（[§6.6](#ebook_split_058.html#id-encapsulation)）来限制类型的方法或结构体的字段在包外的可见性。只有当有两个或更多具体类型必须以统一的方式处理时，才需要接口。

当接口由单个具体类型满足，但由于依赖关系，该类型无法与接口位于同一个包中时，我们对此规则作例外处理。在这种情况下，接口是解耦两个包的好方法。

因为接口在 Go 中只有在被两个或更多类型满足时才会使用，所以它们必然抽象掉了任何特定实现的细节。结果是接口更小，方法更少、更简单，通常只有一个，就像 `io.Writer` 或 `fmt.Stringer`。小接口在新类型出现时更容易满足。接口设计的一个好经验法则是*只请求你需要的东西*。

这结束了我们对方法和接口的探索。Go 对面向对象编程风格有很好的支持，但这并不意味着你必须专门使用它。并非所有东西都需要是对象；独立函数有它们的位置，未封装的数据类型也是如此。请注意，前五章的示例总共调用的方法（如 `input.Scan`）不超过两打，而普通函数调用（如 `fmt.Printf`）则多得多。
