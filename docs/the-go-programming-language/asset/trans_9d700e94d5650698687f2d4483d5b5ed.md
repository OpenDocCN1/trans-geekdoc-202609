

## 并发爬虫：计数信号量方案

```go
func main() {
    worklist := make(chan []string)
    var n int // number of pending sends to worklist

    // Start with the command-line arguments.
    n++
    go func() { worklist <- os.Args[1:] }()

    // Crawl the web concurrently.
    seen := make(map[string]bool)
    for ; n > 0; n-- {
        list := <-worklist
        for _, link := range list {
            if !seen[link] {
                seen[link] = true
                n++
                go func(link string) {
                    worklist <- crawl(link)
                }(link)
            }
        }
    }
}
```

在此版本中，计数器 `n` 用于跟踪尚未发生的向 `worklist` 发送操作的数量。每当我们知道某个项目需要发送到 `worklist` 时，我们就增加 `n`：在发送初始命令行参数前增加一次，并在每次启动爬虫 goroutine 时再次增加。当 `n` 降为零时主循环终止，因为不再有工作要做。

现在，并发爬虫的运行速度比 [第 5.6 节](#ebook_split_047.html#id-anonymousfunctions) 中的广度优先爬虫快约 20 倍，不会出错，并且如果能完成任务则会正确终止。

下面的程序展示了解决过度并发问题的另一种方案。此版本使用了不带计数信号量的原始 `crawl` 函数，但从 20 个长期运行的爬虫 goroutine 中调用它，从而确保最多同时有 20 个 HTTP 请求处于活动状态。

[点击此处查看代码图像](#ch08_images.html#id243pro01_r)

gopl.io/ch8/crawl3

```go
func main() {
    worklist := make(chan []string)  // lists of URLs, may have duplicates
    unseenLinks := make(chan string) // de-duplicated URLs

    // Add command-line arguments to worklist.
    go func() { worklist <- os.Args[1:] }()

    // Create 20 crawler goroutines to fetch each unseen link.
    for i := 0; i < 20; i++ {
        go func() {
            for link := range unseenLinks {
                foundLinks := crawl(link)
                go func() { worklist <- foundLinks }()
            }
        }()
    }

    // The main goroutine de-duplicates worklist items
    // and sends the unseen ones to the crawlers.
    seen := make(map[string]bool)
    for list := range worklist {
        for _, link := range list {
            if !seen[link] {
                seen[link] = true
                unseenLinks <- link
            }
        }
    }
}
```

爬虫 goroutine 都由同一个通道 `unseenLinks` 提供数据。主 goroutine 负责对从 `worklist` 接收到的项目进行去重，然后将每个未见过的项目通过 `unseenLinks` 通道发送给爬虫 goroutine。

`seen` 映射被*限制*在主 goroutine 内部；也就是说，它只能被该 goroutine 访问。与其他形式的信息隐藏一样，限制有助于我们推断程序的正确性。例如，局部变量不能在声明它们的函数外部通过名称提及；不会[逃逸](#ebook_split_022.html#id-escaping)的变量不能从函数外部访问；对象的封装字段只能通过该对象的方法访问。在所有情况下，信息隐藏都有助于限制程序各部分之间的意外交互。

`crawl` 发现的链接通过一个专用的 goroutine 发送到 `worklist`，以避免死锁。

为节省篇幅，本示例未解决终止问题。

## 8.7 使用 `select` 进行多路复用

下面的程序执行火箭发射倒计时。`time.Tick` 函数返回一个通道，它会定期向该通道发送事件，表现得像节拍器一样。每个事件的值是一个时间戳，但其送达这一事实比时间戳本身更有趣。

[点击此处查看代码图像](#ch08_images.html#id244pro01_r)

gopl.io/ch8/countdown1

```go
func main() {
    fmt.Println("Commencing countdown.")
    tick := time.Tick(1 * time.Second)
    for countdown := 10; countdown > 0; countdown-- {
        fmt.Println(countdown)
        <-tick
    }
    launch()
}
```

现在让我们增加一个功能：在倒计时期间按回车键可中止发射序列。首先，我们启动一个 goroutine 尝试从标准输入读取单个字节，如果成功，则向名为 `abort` 的通道发送一个值。

[点击此处查看代码图像](#ch08_images.html#id244pro02_r)

gopl.io/ch8/countdown2

```go
abort := make(chan struct{})
go func() {
    os.Stdin.Read(make([]byte, 1)) // read a single byte
    abort <- struct{}{}
}()
```

现在，倒计时循环的每次迭代都需要等待两个通道之一的事件到达：如果一切正常（“nominal”，NASA 行话），则是定时器通道；如果出现“异常”，则是中止事件。我们不能直接从每个通道接收，因为我们先尝试的那种操作会阻塞直到完成。我们需要*多路复用*这些操作，为此我们需要 `select` 语句。

```go
select {
case <-ch1:
    // ...
case x := <-ch2:
    // ...use x...
case ch3 <- y:
    // ...
default:
    // ...
}
```

上图展示了 `select` 语句的一般形式。像 `switch` 语句一样，它包含若干 `case` 和一个可选的 `default`。每个 `case` 指定一个*通信*（对某个通道的发送或接收操作）和一个关联的语句块。接收表达式可以单独出现，如第一个 `case` 所示，也可以出现在短变量声明中，如第二个 `case` 所示；第二种形式允许你引用接收到的值。

`select` 会等待，直到某个 `case` 的通信操作可以进行。然后它执行该通信操作并运行该 `case` 关联的语句；其他的通信操作不会发生。没有 `case` 的 `select`，即 `select{}`，会永远等待。

让我们回到火箭发射程序。`time.After` 函数会立即返回一个通道，并启动一个新的 goroutine，在指定时间后向该通道发送单个值。下面的 `select` 语句等待两个事件中最先到达的一个：要么是中止事件，要么是表示 10 秒已过的事件。如果 10 秒内没有中止，则继续发射。

[点击此处查看代码图像](#ch08_images.html#id245pro01_r)

```go
func main() {
    // ...create abort channel...

    fmt.Println("Commencing countdown.  Press return to abort.")
    select {
    case <-time.After(10 * time.Second):
        // Do nothing.
    case <-abort:
        fmt.Println("Launch aborted!")
        return
    }
    launch()
}
```

下面的例子更微妙。通道 `ch` 的缓冲区大小为 1，它交替处于空和满状态，因此一次只能有一个 `case` 执行：要么是 `i` 为偶数时的发送，要么是 `i` 为奇数时的接收。它总是打印 `0 2 4 6 8`。

[点击此处查看代码图像](#ch08_images.html#id245pro02_r)

```go
ch := make(chan int, 1)
for i := 0; i < 10; i++ {
    select {
    case x := <-ch:
        fmt.Println(x) // "0" "2" "4" "6" "8"
    case ch <- i:
    }
}
```

如果多个 `case` 都准备好，`select` 会随机选择一个，这确保了每个通道都有平等的被选中机会。增加前一个例子中通道的缓冲区大小会使其输出变得非确定性，因为当缓冲区既不满也不空时，`select` 语句就像抛硬币一样随机选择。
