
上述的 `dup` 版本以“流式”模式运行，即根据需要读取输入并将其拆分为行，因此原则上这些程序可以处理任意数量的输入。另一种方法是一次性将整个输入读入内存，一次性将其拆分为行，然后处理这些行。下面的版本 `dup3` 采用这种方式。它引入了函数 `ReadFile`（来自 `io/ioutil` 包），用于读取指定文件的全部内容，以及 `strings.Split`，用于将字符串分割成子字符串切片。(`Split` 是 `strings.Join` 的逆操作，我们之前见过。)

我们对 `dup3` 做了一些简化。首先，它只读取命名文件，不读取标准输入，因为 `ReadFile` 需要一个文件名参数。其次，我们将行计数移回了 `main` 函数中，因为现在它只在一个地方需要。

```
package main

import (
    "fmt"
    "io/ioutil"
    "os"
    "strings"
)

func main() {
    counts := make(map[string]int)
    for _, filename := range os.Args[1:] {
        data, err := ioutil.ReadFile(filename)
        if err != nil {
            fmt.Fprintf(os.Stderr, "dup3: %v\n", err)
            continue
        }
        for _, line := range strings.Split(string(data), "\n") {
            counts[line]++
        }
    }
    for line, n := range counts {
        if n > 1 {
            fmt.Printf("%d\t%s\n", n, line)
        }
    }
}
```

`ReadFile` 返回一个字节切片，必须将其转换为 `string` 以便能被 `strings.Split` 分割。我们将在 [3.5.4 节](#ebook_split_032.html#id-stringsandbyteslices) 详细讨论字符串和字节切片。

在底层，`bufio.Scanner`、`ioutil.ReadFile` 和 `ioutil.WriteFile` 使用 `*os.File` 的 `Read` 和 `Write` 方法，但大多数程序员很少需要直接访问那些底层例程。来自 `bufio` 和 `io/ioutil` 等包的高级函数更容易使用。

## 1.4 动画 GIF

下一个程序演示了 Go 标准图像包的基本用法，我们将用它们创建一系列位图图像，然后将该序列编码为 GIF 动画。这些图像被称为*利萨如图形*，是 20 世纪 60 年代科幻电影中的常见视觉效果。它们是由二维谐振产生的参数曲线，例如将两个正弦波分别输入示波器的 *x* 和 *y* 输入端。[图 1.1](#ebook_split_014.html#id-figures-lissajous) 展示了一些示例。

```
// Lissajous 生成随机利萨如图形的 GIF 动画。
package main

import (
    "image"
    "image/color"
    "image/gif"
    "io"
    "math"
    "math/rand"
    "os"
)

var palette = []color.Color{color.White, color.Black}

const (
    whiteIndex = 0 // 调色板中的第一种颜色
    blackIndex = 1 // 调色板中的下一种颜色
)

func main() {
    lissajous(os.Stdout)
}

func lissajous(out io.Writer) {
    const (
        cycles  = 5     // x 振荡器完成的完整周期数
        res     = 0.001 // 角分辨率
        size    = 100   // 图像画布覆盖 [-size..+size]
        nframes = 64    // 动画帧数
        delay   = 8     // 帧间延迟，单位为 10ms
    )
    freq := rand.Float64() * 3.0 // y 振荡器的相对频率
    anim := gif.GIF{LoopCount: nframes}
    phase := 0.0 // 相位差
    for i := 0; i < nframes; i++ {
        rect := image.Rect(0, 0, 2*size+1, 2*size+1)
        img := image.NewPaletted(rect, palette)
        for t := 0.0; t < cycles*2*math.Pi; t += res {
            x := math.Sin(t)
            y := math.Sin(t*freq + phase)
            img.SetColorIndex(size+int(x*size+0.5), size+int(y*size+0.5),
                blackIndex)
        }
        phase += 0.1
        anim.Delay = append(anim.Delay, delay)
        anim.Image = append(anim.Image, img)
    }
    gif.EncodeAll(out, &anim) // 注意：忽略了编码错误
}
```

导入路径包含多个组件的包（如 `image/color`）后，我们使用由最后一个组件派生的名称来引用该包。因此变量 `color.White` 属于 `image/color` 包，而 `gif.GIF` 属于 `image/gif`。

`const` 声明（[§3.6](#ebook_split_033.html#id-constants)）为常量命名，即编译时固定的值，例如周期数、帧数和延迟等数值参数。与 `var` 声明一样，`const` 声明可以出现在包级别（这样名称在整个包中可见）或函数内部（这样名称仅在该函数内可见）。常量的值必须是数字、字符串或布尔值。

表达式 `[]color.Color{...}` 和 `gif.GIF{...}` 是*复合字面量*([§4.2](#ebook_split_036.html#id-slices)，[§4.4.1](#ebook_split_038.html#id-structliterals))，这是一种简洁的表示法，用于从一系列元素值实例化 Go 的任意复合类型。这里，第一个是切片，第二个是*结构体*。

类型 `gif.GIF` 是一个结构体类型（[§4.4](#ebook_split_038.html#id-structs)）。结构体是一组被称为*字段*的值的集合，通常类型不同，它们被收集在一个可以作为一个单元处理的单一对象中。变量 `anim` 是 `gif.GIF` 类型的结构体。结构体字面量创建了一个结构体值，其 `LoopCount` 字段被设置为 `nframes`；所有其他字段都具有其类型的零值。结构体的各个字段可以通过点号表示法访问，如最后两个赋值语句所示，它们显式更新了 `anim` 的 `Delay` 和 `Image` 字段。

`lissajous` 函数有两个嵌套循环。外层循环运行 64 次迭代，每次生成动画的一帧。它创建一个新的 201×201 图像，调色板包含白色和黑色两种颜色。所有像素初始设置为调色板的零值（调色板中的第零种颜色），我们将其设为白色。内层循环的每次迭代通过将某些像素设为黑色来生成新图像。结果连同 80ms 的指定延迟，使用内置的 `append` 函数（[§4.2.1](#ebook_split_036.html#id-theappendfunction)）追加到 `anim` 的帧列表中。最后，帧序列和延迟被编码为 GIF 格式并写入输出流 `out`。`out` 的类型是 `io.Writer`，这让我们可以写入各种可能的目标，稍后我们将展示。

内层循环运行两个振荡器。*x* 振荡器就是正弦函数。*y* 振荡器也是正弦波，但其相对于 *x* 振荡器的频率是 0 到 3 之间的随机数，其相对于 *x* 振荡器的相位初始为零，但随着动画的每一帧而增加。循环运行直到 *x* 振荡器完成五个完整周期。在每一步中，它调用 `SetColorIndex` 将对应于 (*x*, *y*) 的像素着色为黑色，即调色板中位置 1 的颜色。
