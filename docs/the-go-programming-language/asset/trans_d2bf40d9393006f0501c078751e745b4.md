
`addEdge` 函数展示了惯用的方式来惰性填充 map，即在键首次出现时初始化每个值。`hasEdge` 函数展示了缺失 map 条目的零值通常是如何被利用的：即使 `from` 和 `to` 都不存在，`graph[from][to]` 也总会给出一个有意义的结果。

## 4.4 结构体

*结构体* 是一种聚合数据类型，它将零个或多个任意类型的命名值组合在一起作为一个单一实体。每个值被称为一个 *字段*。来自数据处理的结构体经典示例是员工记录，其字段包括唯一 ID、员工姓名、地址、出生日期、职位、薪水、管理者等。所有这些字段被收集到一个单一实体中，可以作为一个单元进行复制、传递给函数和从函数返回、存储在数组中，等等。

这两条语句声明了一个名为 `Employee` 的结构体类型和一个名为 `dilbert` 的变量，该变量是 `Employee` 的一个实例：

```
type Employee struct {
    ID        int
    Name      string
    Address   string
    DoB       time.Time
    Position  string
    Salary    int
    ManagerID int
}

var dilbert Employee
```

`dilbert` 的各个字段通过点号表示法访问，如 `dilbert.Name` 和 `dilbert.DoB`。因为 `dilbert` 是一个变量，所以它的字段也是变量，因此我们可以给字段赋值：

```
dilbert.Salary -= 5000 // 因写代码行数太少被降职
```

或者获取其地址并通过指针访问：

```
position := &dilbert.Position
*position = "Senior " + *position // 因外包给 Elbonia 而晋升
```

点号表示法也适用于结构体指针：

```
var employeeOfTheMonth *Employee = &dilbert
employeeOfTheMonth.Position += " (proactive team player)"
```

最后一条语句等价于：

```
(*employeeOfTheMonth).Position += " (proactive team player)"
```

给定员工的唯一 ID，函数 `EmployeeByID` 返回一个指向 `Employee` 结构体的指针。我们可以使用点号表示法来访问其字段：

```
func EmployeeByID(id int) *Employee { /* ... */ }

fmt.Println(EmployeeByID(dilbert.ManagerID).Position) // "Pointy-haired boss"

id := dilbert.ID
EmployeeByID(id).Salary = 0 // 因……没有真正的原因被解雇
```

最后一条语句更新了由 `EmployeeByID` 调用结果指向的 `Employee` 结构体。如果 `EmployeeByID` 的结果类型被改为 `Employee` 而不是 `*Employee`，赋值语句将无法编译，因为其左侧不会标识一个变量。

字段通常每行写一个，字段名在其类型之前，但相同类型的连续字段可以合并，如这里的 `Name` 和 `Address`：

```
type Employee struct {
    ID            int
    Name, Address string
    DoB           time.Time
    Position      string
    Salary        int
    ManagerID     int
}
```

字段顺序对类型标识至关重要。如果我们也合并了 `Position` 字段的声明（也是字符串），或交换了 `Name` 和 `Address`，我们将定义一个不同的结构体类型。通常我们只合并相关字段的声明。

如果结构体字段名以大写字母开头，则该字段被导出；这是 Go 语言主要的访问控制机制。一个结构体类型可能包含导出和未导出字段的混合。

结构体类型往往比较冗长，因为它们通常每个字段占一行。虽然我们可以在每次需要时写出完整的类型，但重复会让人厌烦。相反，结构体类型通常出现在像 `Employee` 这样的命名类型声明中。

命名结构体类型 `S` 不能声明一个相同类型 `S` 的字段：聚合值不能包含它自己。（类似的限制也适用于数组。）但 `S` 可以声明一个指针类型 `*S` 的字段，这使我们能创建递归数据结构，如链表和树。下面的代码演示了这一点，它使用二叉树实现了插入排序：

```
gopl.io/ch4/treesort

type tree struct {
    value       int
    left, right *tree
}

// Sort 就地排序 values。
func Sort(values []int) {
    var root *tree
    for _, v := range values {
        root = add(root, v)
    }
    appendValues(values[:0], root)
}

// appendValues 将 t 的元素按顺序追加到 values
// 并返回结果切片。
func appendValues(values []int, t *tree) []int {
    if t != nil {
        values = appendValues(values, t.left)
        values = append(values, t.value)
        values = appendValues(values, t.right)
    }
    return values
}

func add(t *tree, value int) *tree {
    if t == nil {
        // 等价于 return &tree{value: value}。
        t = new(tree)
        t.value = value
        return t
    }
    if value < t.value {
        t.left = add(t.left, value)
    } else {
        t.right = add(t.right, value)
    }
    return t
}
```

结构体的零值由其每个字段的零值组成。通常希望零值是一个自然或合理的默认值。例如，在 `bytes.Buffer` 中，结构体的初始值是一个可直接使用的空缓冲区，而 `sync.Mutex` 的零值（我们将在[第 9 章](#ebook_split_086.html#id-concurrencywithsharedvariables)看到）是一个可直接使用的未锁定互斥锁。有时这种合理的初始行为是自动获得的，但有时类型设计者必须为此付出努力。

没有字段的结构体类型被称为 *空结构体*，写作 `struct{}`。它的大小为零且不携带信息，但仍可能有用。一些 Go 程序员用它代替 `bool` 作为表示集合的 map 的值类型，以强调只有键才重要，但节省的空间微乎其微且语法更繁琐，所以我们通常避免使用它。

```
seen := make(map[string]struct{}) // 字符串集合
// ...
if _, ok := seen[s]; !ok {
    seen[s] = struct{}{}
    // ...第一次看到 s...
}
```

### 4.4.1 结构体字面量

结构体类型的值可以用 *结构体字面量* 来书写，它为字段指定值。

```
type Point struct{ X, Y int }

p := Point{1, 2}
```

结构体字面量有两种形式。第一种形式如上所示，要求为*每个*字段按正确顺序指定值。它要求编写者（和阅读者）准确记住字段是什么，并且如果字段集合后来增长或重新排序，会使代码变得脆弱。因此，这种形式倾向于仅在定义该结构体类型的包内使用，或用于有明显字段排序约定的较小结构体类型，如 `image.Point{x, y}` 或 `color.RGBA{red, green, blue, alpha}`。

更常用的是第二种形式，即通过列出部分或全部字段名及其对应的值来初始化结构体值，就像[第 1.4 节](#ebook_split_014.html#id-animatedgifs) Lissajous 程序中的这条语句：

```
anim := gif.GIF{LoopCount: nframes}
```
