
函数 `flag.Bool` 会创建一个类型为 `bool` 的新标志变量。它接受三个参数：标志的名称（`"n"`）、变量的默认值（`false`），以及当用户提供无效参数、无效标志，或 `-h` 或 `-help` 时将要打印的提示信息。类似地，`flag.String` 接受一个名称、一个默认值和一条提示信息，并创建一个 `string` 变量。变量 `sep` 和 `n` 是指向标志变量的指针，必须通过 `*sep` 和 `*n` 间接访问。

程序运行时，必须在使用标志之前调用 `flag.Parse`，以便从默认值更新标志变量。非标志参数可通过 `flag.Args()` 作为字符串切片获取。如果 `flag.Parse` 遇到错误，它会打印一条用法提示并调用 `os.Exit(2)` 终止程序。

### 2.3.3 `new` 函数

创建变量的另一种方法是使用内置函数 `new`。表达式 `new(T)` 会创建一个类型为 `T` 的*未命名变量*，将其初始化为 `T` 的零值，并返回其地址，该地址属于类型 `*T`。

[点击此处查看代码图片](#ch02_images.html#id034pro02_r)

```
p := new(int)   // p，类型为 *int，指向一个未命名的 int 变量
fmt.Println(*p) // "0"
*p = 2          // 将未命名的 int 设置为 2
fmt.Println(*p) // "2"
```

用 `new` 创建的变量与一个获取了地址的普通局部变量没有什么区别，只是不需要发明（并声明）一个虚拟名称，而且我们可以在表达式中使用 `new(T)`。因此 `new` 只是一个语法上的便利，而非基本概念：下面两个 `newInt` 函数具有完全相同的行为。

[点击此处查看代码图片](#ch02_images.html#id035pro01_r)

```
func newInt() *int {            func newInt() *int {
    return new(int)                 var dummy int
}                                   return &dummy
                                }
```

每次调用 `new` 都会返回一个具有唯一地址的不同变量：

```
p := new(int)
q := new(int)
fmt.Println(p == q) // "false"
```

这条规则有一个例外：类型不携带任何信息因而大小为零的两个变量，例如 `struct{}` 或 `[0]int`，取决于实现，可能拥有相同的地址。

`new` 函数使用相对较少，因为最常见的未命名变量是结构体类型，对于结构体类型，结构体字面量语法（[§4.4.1](#ebook_split_038.html#id-structliterals)）更加灵活。

由于 `new` 是预声明函数而非关键字，因此可以在函数内部将该名称重新定义为其他用途，例如：

[点击此处查看代码图片](#ch02_images.html#id035pro02_r)

```
func delta(old, new int) int { return new - old }
```

当然，在 `delta` 内部，内置的 `new` 函数将不可用。

### 2.3.4 变量的生命周期

变量的*生命周期*是指变量在程序执行过程中存在的时间段。包级变量的生命周期是整个程序的执行过程。相比之下，局部变量具有动态生命周期：每次执行声明语句都会创建一个新的实例，变量一直存活直到变得*不可达*，此时其存储空间可能被回收。函数参数和返回值也是局部变量；每次调用其外层函数时都会创建它们。

例如，在 [1.4 节](#ebook_split_014.html#id-animatedgifs) Lissajous 程序的这个片段中，

[点击此处查看代码图片](#ch02_images.html#id035pro03_r)

```
for t := 0.0; t < cycles*2*math.Pi; t += res {
    x := math.Sin(t)
    y := math.Sin(t*freq + phase)
    img.SetColorIndex(size+int(x*size+0.5), size+int(y*size+0.5),
        blackIndex)
}
```

变量 `t` 在 `for` 循环开始时创建，而新变量 `x` 和 `y` 在循环的每次迭代中创建。

垃圾收集器如何知道变量的存储空间可以被回收？完整的故事比我们这里需要的要详细得多，但基本思想是：每个包级变量，以及每个当前活跃函数的每个局部变量，都可能成为通往相关变量路径的起点或根，通过跟踪指针和其他类型的引用最终到达该变量。如果不存在这样的路径，该变量就变得不可达，因此不再能影响后续的计算。

因为变量的生命周期仅由其是否可达决定，所以局部变量可能比外层循环的单次迭代存活得更久。即使其外层函数已经返回，它也可能继续存在。

编译器可能会选择在堆上或栈上分配局部变量，但令人惊讶的是，这个选择并不取决于使用 `var` 还是 `new` 来声明变量。

[点击此处查看代码图片](#ch02_images.html#id036pro01_r)

```
var global *int

func f() {                      func g() {
    var x int                       y := new(int)
    x = 1                           *y = 1
    global = &x                 }
}
```

这里，`x` 必须在堆上分配，因为即使在 `f` 返回后，它仍可从变量 `global` 访问，尽管它被声明为局部变量；我们说 `x` *从* `f` *逃逸*。相反，当 `g` 返回时，变量 `*y` 变得不可达并可被回收。既然 `*y` 没有从 `g` 逃逸，编译器将 `*y` 分配在栈上就是安全的，尽管它是用 `new` 分配的。无论如何，逃逸的概念不是你编写正确代码时需要担心的事情，但在性能优化时最好记在心里，因为每个逃逸的变量都需要一次额外的内存分配。

垃圾收集对编写正确程序有极大帮助，但它并不能免除你思考内存的负担。你不需要显式地分配和释放内存，但要编写高效程序，你仍然需要了解变量的生命周期。例如，在长寿命对象（尤其是全局变量）中保留指向短寿命对象的不必要指针，会阻止垃圾收集器回收这些短寿命对象。

## 2.4 赋值

变量持有的值通过赋值语句更新，其最简单的形式是在 `=` 号左侧放一个变量，右侧放一个表达式。

[点击此处查看代码图片](#ch02_images.html#id036pro02_r)

```
x = 1                       // 命名变量
*p = true                   // 间接变量
person.name = "bob"         // 结构体字段
count[x] = count[x] * scale // 数组、切片或映射元素
```

每个算术和位运算的二元运算符都有一个对应的*赋值运算符*，例如，允许将最后一条语句重写为

```
count[x] *= scale
```

这避免了我们必须重复（并重新求值）变量的表达式。

数值变量也可以通过 `++` 和 `--` 语句进行增量和减量操作：

[点击此处查看代码图片](#ch02_images.html#id037pro01_r)

```
v := 1
v++    // 等同于 v = v + 1；v 变为 2
v--    // 等同于 v = v - 1；v 再次变为 1
```
