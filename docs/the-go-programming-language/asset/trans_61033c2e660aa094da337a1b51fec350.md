## 7.8 `error` 接口

自本书开篇以来，我们一直在使用和创建神秘的预声明 `error` 类型的值，却未解释它到底是什么。实际上，它只是一个拥有单一方法的接口类型，该方法返回错误消息：

```
type error interface {
    Error() string
}
```

创建 `error` 最简单的方法是调用 `errors.New`，它会为给定的错误消息返回一个新的 `error`。整个 `errors` 包仅有四行代码：

```
package errors

func New(text string) error { return &errorString{text} }

type errorString struct { text string }

func (e *errorString) Error() string { return e.text }
```

`errorString` 的底层类型是结构体而非字符串，这是为了保护其表示免受无意（或蓄意）的更新。而指针类型 `*errorString`（而非 `errorString` 本身）满足 `error` 接口的原因，是为了让每次调用 `New` 都分配一个独一无二的 `error` 实例，它不等于任何其他实例。我们不希望像 `io.EOF` 这样特殊的错误，与仅仅碰巧拥有相同消息的错误比较结果相等。

```
fmt.Println(errors.New("EOF") == errors.New("EOF")) // "false"
```

调用 `errors.New` 的情况相对较少，因为有一个方便的包装函数 `fmt.Errorf`，它也能进行字符串格式化。我们在 [第 5 章](#ebook_split_041.html#id-functions) 中多次使用过它。

```
package fmt

import "errors"

func Errorf(format string, args ...interface{}) error {
    return errors.New(Sprintf(format, args...))
}
```

虽然 `*errorString` 可能是最简单的 `error` 类型，但它远非唯一。例如，`syscall` 包提供了 Go 的底层系统调用 API。在许多平台上，它定义了一个满足 `error` 接口的数值类型 `Errno`，而在 Unix 平台上，`Errno` 的 `Error` 方法会在字符串表中查找，如下所示：

```
package syscall

type Errno uintptr // 操作系统错误代码

var errors = [...]string{
    1:   "operation not permitted",   // EPERM
    2:   "no such file or directory", // ENOENT
    3:   "no such process",           // ESRCH
    // ...
}

func (e Errno) Error() string {
    if 0 <= int(e) && int(e) < len(errors) {
        return errors[e]
    }
    return fmt.Sprintf("errno %d", e)
}
```

以下语句创建了一个接口值，它持有值为 `2` 的 `Errno`，表示 POSIX `ENOENT` 状况：

```
var err error = syscall.Errno(2)
fmt.Println(err.Error()) // "no such file or directory"
fmt.Println(err)         // "no such file or directory"
```

`err` 的值如 [图 7.6](#ebook_split_067.html#id-figures-iface-errno) 所示。

![一个持有 syscall.Errno 整数的接口值。](graphics/iface-errno.png)

`Errno` 是从有限集合中提取的系统调用错误的高效表示，且满足标准 `error` 接口。我们将在 [7.11 节](#ebook_split_070.html#id-discriminatingerrors) 中看到其他满足此接口的类型。

## 7.9 示例：表达式求值器

在本节中，我们将构建一个简单的算术表达式求值器。我们将使用一个接口 `Expr` 来表示该语言中的任意表达式。目前该接口无需任何方法，但稍后我们会添加一些。

```
// Expr 代表一个算术表达式。
type Expr interface{}
```

我们的表达式语言包含浮点数字面量；二元运算符 `+`、`-`、`*` 和 `/`；一元运算符 `-x` 和 `+x`；函数调用 `pow(x,y)`、`sin(x)` 和 `sqrt(x)`；变量如 `x` 和 `pi`；当然还有括号和标准的运算符优先级。所有值均为 `float64` 类型。以下是一些示例表达式：

```
sqrt(A / pi)
pow(x, 3) + pow(y, 3)
(F - 32) * 5 / 9
```

下面的五个具体类型代表特定种类的表达式。`Var` 代表对变量的引用。（稍后我们将看到为何它是导出的。）`literal` 代表浮点数常量。`unary` 和 `binary` 类型分别代表具有一个或两个操作数的运算符表达式，这些操作数可以是任意类型的 `Expr`。`call` 代表函数调用；我们将其 `fn` 字段限制为 `pow`、`sin` 或 `sqrt`。

```
gopl.io/ch7/eval

// Var 标识一个变量，例如 x。
type Var string

// literal 是一个数值常量，例如 3.141。
type literal float64

// unary 代表一元运算符表达式，例如 -x。
type unary struct {
    op rune // '+' 或 '-'
    x  Expr
}

// binary 代表二元运算符表达式，例如 x+y。
type binary struct {
    op   rune // '+', '-', '*', '/' 之一
    x, y Expr
}

// call 代表函数调用表达式，例如 sin(x)。
type call struct {
    fn   string // "pow", "sin", "sqrt" 之一
    args []Expr
}
```

为了对包含变量的表达式求值，我们需要一个*环境*，将变量名映射为值：

```
type Env map[Var]float64
```

我们还需要每种表达式都定义一个 `Eval` 方法，返回该表达式在给定环境下的值。因为每个表达式都必须提供此方法，所以我们将其添加到 `Expr` 接口中。该包仅导出 `Expr`、`Env` 和 `Var` 类型；客户端无需访问其他表达式类型即可使用求值器。

```
type Expr interface {
    // Eval 返回该 Expr 在环境 env 中的值。
    Eval(env Env) float64
}
```

具体的 `Eval 方法如下所示。`Var` 的方法执行环境查找，如果变量未定义则返回零值；`literal` 的方法直接返回字面量值。

```
func (v Var) Eval(env Env) float64 {
    return env[v]
}

func (l literal) Eval(_ Env) float64 {
    return float64(l)
}
```

`unary` 和 `binary` 的 `Eval` 方法递归地求其操作数的值，然后将运算符 `op` 应用于它们。我们不将除以零或无穷大视为错误，因为它们会产生结果，尽管是非有限的。最后，`call` 的方法对 `pow`、`sin` 或 `sqrt` 函数的参数求值，然后调用 `math` 包中对应的函数。
