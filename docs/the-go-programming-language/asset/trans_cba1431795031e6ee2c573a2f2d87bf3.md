

## 10.7 Go 工具

本章剩余部分介绍 `go` 工具，它用于下载、查询、格式化、构建、测试和安装 Go 代码包。

`go` 工具将一组多样化工具的功能整合到一个命令集中。它是一个包管理器（类似于 `apt` 或 `rpm`），可回答关于其包库存的查询、计算依赖关系，并从远程版本控制系统下载它们。它是一个构建系统，可计算文件依赖关系并调用编译器、汇编器和链接器，尽管它有意设计得不如标准 Unix `make` 完整。正如我们将在[第 11 章](#ebook_split_103.html#id-testing)中看到的，它还是一个测试驱动器。

其命令行界面采用“瑞士军刀”风格，拥有十多个子命令，其中一些我们已经见过，如 `get`、`run`、`build` 和 `fmt`。你可以运行 `go help` 查看其内置文档的索引，但为了方便参考，我们在下面列出了最常用的命令：

```
$ go
...
    build       编译包和依赖项
    clean       移除目标文件
    doc         显示包或符号的文档
    env         打印 Go 环境信息
    fmt         对包源码运行 gofmt
    get         下载并安装包和依赖项
    install     编译并安装包和依赖项
    list        列出包
    run         编译并运行 Go 程序
    test        测试包
    version     打印 Go 版本
    vet         对包运行 go tool vet

Use "go help [command]" for more information about a command.
...
```

为了将配置需求降至最低，`go` 工具严重依赖约定。例如，给定一个 Go 源文件的名称，该工具可以找到其所属的包，因为每个目录只包含一个包，且包的导入路径对应于工作区中的目录层级。给定一个包的导入路径，该工具可以找到存储其目标文件的相应目录。它还可以找到托管源代码仓库的服务器 URL。

### 10.7.1 工作区组织

大多数用户唯一需要的配置是 `GOPATH` 环境变量，它指定工作区的根目录。切换到不同工作区时，用户需更新 `GOPATH` 的值。例如，编写本书时我们将 `GOPATH` 设置为 `$HOME/gobook`：

```
$ export GOPATH=$HOME/gobook
$ go get gopl.io/...
```

使用上述命令下载本书所有程序后，你的工作区将包含如下层级结构：

```
GOPATH/
    src/
        gopl.io/
            .git/
            ch1/
                helloworld/
                    main.go
                dup/
                    main.go
                ...
        golang.org/x/net/
            .git/
            html/
                parse.go
                node.go
                ...
    bin/
        helloworld
        dup
    pkg/
        darwin_amd64/
            ...
```

`GOPATH` 有三个子目录。`src` 子目录存放源代码。每个包位于一个目录中，该目录相对于 `$GOPATH/src` 的名称即为包的导入路径，例如 `gopl.io/ch1/helloworld`。请注意，单个 `GOPATH` 工作区在 `src` 下包含多个版本控制仓库，如 `gopl.io` 或 `golang.org`。`pkg` 子目录是构建工具存放编译后包的地方，`bin` 子目录存放可执行程序，如 `helloworld`。

第二个环境变量 `GOROOT` 指定 Go 发行版的根目录，其中提供了标准库的所有包。`GOROOT` 下的目录结构类似于 `GOPATH`，因此，例如 `fmt` 包的源文件位于 `$GOROOT/src/fmt` 目录中。用户无需设置 `GOROOT`，因为默认情况下 `go` 工具将使用其安装位置。

`go env` 命令打印与工具链相关的环境变量的有效值，包括缺失变量的默认值。`GOOS` 指定目标操作系统（例如 `android`、`linux`、`darwin` 或 `windows`），`GOARCH` 指定目标处理器架构，如 `amd64`、`386` 或 `arm`。虽然 `GOPATH` 是你必须设置的唯一变量，但其他变量偶尔会出现在我们的解释中。

```
$ go env
GOPATH="/home/gopher/gobook"
GOROOT="/usr/local/go"
GOARCH="amd64"
GOOS="darwin"
...
```

### 10.7.2 下载包

使用 `go` 工具时，包的导入路径不仅指示在本地工作区中何处可以找到它，还指示在互联网上何处可以找到它，以便 `go get` 能够检索和更新它。

`go get` 命令可以下载单个包，也可以使用 `...` 表示法下载整个子树或仓库，如前一节所示。该工具还会计算并下载初始包的所有依赖项，这就是为什么上一个示例中 `golang.org/x/net/html` 包会出现在工作区中的原因。

`go get` 下载包后，会构建它们，然后*安装*库和命令。我们将在下一节查看详细信息，但一个示例将展示该过程有多简单。下面的第一个命令获取 `golint` 工具，它用于检查 Go 源代码中的常见风格问题。第二个命令在 `gopl.io/ch2/popcount`（来自[第 2.6.2 节](#ebook_split_025.html#id-packageinitialization)）上运行 `golint`。它有帮助地报告我们忘记为包编写文档注释：

```
$ go get github.com/golang/lint/golint
$ $GOPATH/bin/golint gopl.io/ch2/popcount
src/gopl.io/ch2/popcount/main.go:1:1:
  package comment should be of the form "Package popcount ..."
```

`go get` 命令支持 GitHub、Bitbucket 和 Launchpad 等流行的代码托管网站，并能向其版本控制系统发出适当的请求。对于不太知名的网站，你可能必须在导入路径中指明使用哪种版本控制协议，如 Git 或 Mercurial。运行 `go help importpath` 查看详情。
