
## 5.9 Panic

Go 的类型系统在编译时捕获许多错误，但其他错误（如数组越界访问或空指针解引用）需要在运行时检查。当 Go 运行时检测到这些错误时，它会 **panic（恐慌）**。

在典型的 panic 过程中，正常执行停止，该 goroutine 中所有延迟函数调用被执行，程序随即崩溃并输出日志信息。该日志包含 **panic value（恐慌值）**，通常是某种错误消息，以及每个 goroutine 的 **stack trace（堆栈跟踪）**，显示 panic 发生时活动的函数调用栈。此日志通常包含足够的信息来诊断根本原因，无需再次运行程序，因此应始终包含在关于 panic 程序的 bug 报告中。

并非所有 panic 都来自运行时。内置的 `panic` 函数可被直接调用；它接受任意值作为参数。当发生某种“不可能”的情况时，panic 往往是最佳处理方式，例如执行到逻辑上不可能到达的 case 分支：

```go
switch s := suit(drawCard()); s {
case "Spades":   // ...
case "Hearts":   // ...
case "Diamonds": // ...
case "Clubs":    // ...
default:
    panic(fmt.Sprintf("invalid suit %q", s)) // Joker?
}
```

断言函数的前置条件是良好的实践，但容易过度。除非你能提供更有信息量的错误消息或更早地检测错误，否则断言运行时会为你检查的条件毫无意义。

```go
func Reset(x *Buffer) {
    if x == nil {
        panic("x is nil") // unnecessary!
    }
    x.elements = nil
}
```

虽然 Go 的 panic 机制类似于其他语言的异常，但使用 panic 的场景截然不同。因为 panic 会导致程序崩溃，它通常用于严重错误，如程序逻辑不一致；严谨的程序员将任何崩溃视为代码中存在 bug 的证明。在健壮的程序中，“预期内”的错误（源于错误输入、配置错误或 I/O 失败）应被优雅处理；它们最好通过 `error` 值来处理。

考虑 `regexp.Compile` 函数，它将正则表达式编译为用于匹配的高效形式。若模式格式错误，它返回 `error`，但如果调用者知道特定调用不可能失败，检查此错误则是不必要且繁琐的。在这种情况下，调用者通过 panic 处理错误是合理的，因为它被认为不可能发生。

由于大多数正则表达式是程序源码中的字面量，`regexp` 包提供了一个封装函数 `regexp.MustCompile` 来执行此检查：

```go
package regexp

func Compile(expr string) (*Regexp, error) { /* ... */ }

func MustCompile(expr string) *Regexp {
    re, err := Compile(expr)
    if err != nil {
        panic(err)
    }
    return re
}
```

该封装函数使客户端能方便地用编译后的正则表达式初始化包级变量，如下所示：

```go
var httpSchemeRE = regexp.MustCompile(`^https?:`) // "http:" or "https:"
```

当然，`MustCompile` 不应用于不受信的输入值。`Must` 前缀是此类函数的常见命名约定，如 `template.Must`（见 4.6 节）。

当 panic 发生时，所有延迟函数按逆序运行，从栈顶函数的延迟调用开始，一直执行到 `main`，如下程序所示：

```go
func main() {
    f(3)
}

func f(x int) {
    fmt.Printf("f(%d)\n", x+0/x) // panics if x == 0
    defer fmt.Printf("defer %d\n", x)
    f(x - 1)
}
```

运行时，程序向标准输出打印以下内容：

```
f(3)
f(2)
f(1)
defer 1
defer 2
defer 3
```

在调用 `f(0)` 期间发生 panic，导致三个对 `fmt.Printf` 的延迟调用运行。随后运行时终止程序，向标准错误流打印 panic 消息和堆栈转储（为清晰起见已简化）：

```
panic: runtime error: integer divide by zero
main.f(0)
        src/gopl.io/ch5/defer1/defer.go:14
main.f(1)
        src/gopl.io/ch5/defer1/defer.go:16
main.f(2)
        src/gopl.io/ch5/defer1/defer.go:16
main.f(3)
        src/gopl.io/ch5/defer1/defer.go:16
main.main()
        src/gopl.io/ch5/defer1/defer.go:10
```

稍后我们将看到，函数可以从 panic 中 recover（恢复），使程序不终止。

为诊断目的，`runtime` 包允许程序员使用相同机制转储堆栈。通过在 `main` 中延迟调用 `printStack`，

```go
func main() {
    defer printStack()
    f(3)
}

func printStack() {
    var buf [4096]byte
    n := runtime.Stack(buf[:], false)
    os.Stdout.Write(buf[:n])
}
```
