## 5.8 延迟函数调用

我们的 `findLinks` 示例使用 `http.Get` 的输出作为 `html.Parse` 的输入。如果请求的 URL 内容确实是 HTML，这工作良好，但许多页面包含图片、纯文本和其他文件格式。将此类文件送入 HTML 解析器可能会产生不良影响。

下面的程序获取一个 HTML 文档并打印其标题。`title` 函数检查服务器响应的 `Content-Type` 头部，如果文档不是 HTML 则返回错误。

[点击此处查看代码图像](#ch05_images.html#id144pro01_r)

gopl.io/ch5/title1

```
func title(url string) error {
    resp, err := http.Get(url)
    if err != nil {
        return err
    }

    // 检查 Content-Type 是否为 HTML（例如 "text/html; charset=utf-8"）。
    ct := resp.Header.Get("Content-Type")
    if ct != "text/html" && !strings.HasPrefix(ct, "text/html;") {
        resp.Body.Close()
        return fmt.Errorf("%s has type %s, not text/html", url, ct)
    }

    doc, err := html.Parse(resp.Body)
    resp.Body.Close()
    if err != nil {
        return fmt.Errorf("parsing %s as HTML: %v", url, err)
    }

    visitNode := func(n *html.Node) {
        if n.Type == html.ElementNode && n.Data == "title" &&
            n.FirstChild != nil {
            fmt.Println(n.FirstChild.Data)
        }
    }
    forEachNode(doc, visitNode, nil)
    return nil
}
```

观察重复的 `resp.Body.Close()` 调用，它确保 `title` 在所有执行路径上（包括失败时）都关闭网络连接。随着函数变得更复杂并需要处理更多错误，这种清理逻辑的重复可能会成为维护问题。让我们看看 Go 独特的 `defer` 机制如何简化事情。

从语法上讲，`defer` 语句是一个普通的函数或方法调用，前面加上关键字 `defer`。函数和参数表达式在语句执行时求值，但实际调用被*延迟*到包含 `defer` 语句的函数结束时，无论是正常结束（通过执行 return 语句或运行到末尾），还是异常结束（通过 panic）。可以延迟任意数量的调用；它们按与延迟顺序相反的顺序执行。

`defer` 语句常用于成对的操作，如打开和关闭、连接和断开、或加锁和解锁，以确保在所有情况下都释放资源，无论控制流多么复杂。释放资源的 `defer` 语句的正确位置是紧跟在成功获取资源之后。在下面的 `title` 函数中，单个延迟调用替换了之前对 `resp.Body.Close()` 的两次调用：

[点击此处查看代码图像](#ch05_images.html#id145pro01_r)

gopl.io/ch5/title2

```
func title(url string) error {
    resp, err := http.Get(url)
    if err != nil {
        return err
    }
    defer resp.Body.Close()

    ct := resp.Header.Get("Content-Type")
    if ct != "text/html" && !strings.HasPrefix(ct, "text/html;") {
        return fmt.Errorf("%s has type %s, not text/html", url, ct)
    }

    doc, err := html.Parse(resp.Body)
    if err != nil {
        return fmt.Errorf("parsing %s as HTML: %v", url, err)
    }

    // ...打印文档的 title 元素...

    return nil
}
```

`defer` 语句还可用于在调试复杂函数时配对“入口”和“出口”动作。下面的 `bigSlowOperation` 函数立即调用 `trace`，后者执行“入口”动作，然后返回一个函数值，该函数被调用时执行相应的“出口”动作。通过这种方式延迟调用返回的函数，我们可以在一条语句中检测函数的入口点和所有出口点，甚至可以在两个动作之间传递值，如 `start` 时间。但不要忘记 `defer` 语句中的最后一对括号，否则“入口”动作会在出口时发生，而出口动作根本不会发生！

[点击此处查看代码图像](#ch05_images.html#id146pro01_r)

gopl.io/ch5/trace

```
func bigSlowOperation() {
    defer trace("bigSlowOperation")() // 别忘了额外的括号
    // ...大量工作...
    time.Sleep(10 * time.Second) // 通过休眠模拟慢操作
}

func trace(msg string) func() {
    start := time.Now()
    log.Printf("enter %s", msg)
    return func() { log.Printf("exit %s (%s)", msg, time.Since(start)) }
}
```

每次调用 `bigSlowOperation` 时，它都会记录其入口和出口以及两者之间的 elapsed time（我们用 `time.Sleep` 来模拟慢操作）。

[点击此处查看代码图像](#ch05_images.html#id146pro02_r)

```

2015/11/18 09:53:36 exit bigSlowOperation (10.000589217s)
```

延迟函数在 return 语句更新了函数的结果变量*之后*运行。因为匿名函数可以访问其外层函数的变量，包括命名结果，所以延迟的匿名函数可以观察函数的结果。

考虑函数 `double`：

[点击此处查看代码图像](#ch05_images.html#id147pro01_r)

```
func double(x int) int {
    return x + x
}
```

通过命名其结果变量并添加 `defer` 语句，我们可以使函数在每次被调用时打印其参数和结果。

[点击此处查看代码图像](#ch05_images.html#id147pro02_r)

```
func double(x int) (result int) {
    defer func() { fmt.Printf("double(%d) = %d\n", x, result) }()
    return x + x
}

_ = double(4)
// 输出：
// "double(4) = 8"
```

对于像 `double` 这样简单的函数，这属于过度设计，但在有许多 return 语句的函数中可能很有用。

延迟的匿名函数甚至可以更改外层函数返回给调用者的值：

```
func triple(x int) (result int) {
    defer func() { result += x }()
    return double(x)
}

fmt.Println(triple(4)) // "12"
```
