
声明的词法块决定了其作用域，作用域范围可大可小。内置类型、函数和常量（如`int`、`len` 和 `true`）的声明位于全局块，可在整个程序中引用。位于任何函数之外的声明，即*包级*声明，可从同一个包中的任意文件引用。导入的包（如 `tempconv` 示例中的 `fmt`）在*文件级*声明，因此只能在同一文件中引用，若要在同一包的另一文件中引用，则需再次 `import`。许多声明（如 `tempconv.CToF` 函数中的变量 `c`）是*局部*的，因此只能在同一函数内部，甚至仅在函数的某一部分中引用。

控制流标签的作用域（由 `break`、`continue` 和 `goto` 语句使用）是整个包含它的函数。

只要每个声明位于不同的词法块中，程序就可以包含多个同名声明。例如，可以声明一个与包级变量同名的局部变量。或者，如[第 2.3.3 节](#ebook_split_022.html#id-thenewfunction)所示，可以声明一个名为 `new` 的函数参数，尽管同名函数已在全局块中预先声明。不过不要滥用此特性；重声明的作用域越大，越容易让读者感到意外。

当编译器遇到一个名称引用时，它会从最内层的包含词法块开始，向外逐层查找声明，直到全局块。如果找不到声明，则报告“未声明的名称”错误。如果一个名称在外层块和内层块均有声明，内层声明会被优先找到。此时称内层声明*遮蔽*或*隐藏*了外层声明，使其无法访问：

[点击此处查看代码图像](#ch02_images.html#id046pro01_r)

```
func f() {}

var g = "g"

func main() {
    f := "f"
    fmt.Println(f) // "f"; 局部变量 f 遮蔽了包级函数 f
    fmt.Println(g) // "g"; 包级变量
    fmt.Println(h) // 编译错误: undefined: h
}
```

在函数内部，词法块可嵌套至任意深度，因此一个局部声明可遮蔽另一个。大多数块由控制流结构创建，如 `if` 语句和 `for` 循环。下面的程序有三个名为 `x` 的不同变量，因为每个声明出现在不同的词法块中。（此例说明作用域规则，并非良好风格！）

[点击此处查看代码图像](#ch02_images.html#id047pro01_r)

```
func main() {
    x := "hello!"
    for i := 0; i < len(x); i++ {
        x := x[i]
        if x != '!' {
            x := x + 'A' - 'a'
            fmt.Printf("%c", x) // "HELLO" (每次迭代一个字母)
        }
    }
}
```

表达式 `x[i]` 和 `x + 'A' - 'a'` 分别引用了外层块中 `x` 的声明；稍后我们将解释这一点。（注意后者*不*等同于 `unicode.ToUpper`。）

如前所述，并非所有词法块都对应显式的大括号包裹的语句序列；有些仅是隐式存在。上述 `for` 循环创建了两个词法块：循环体的显式块，以及一个额外包含初始化子句所声明变量（如 `i`）的隐式块。在隐式块中声明的变量，其作用域为 `for` 语句的条件、后置语句（`i++`）和循环体。

下面的示例也有三个名为 `x` 的变量，分别声明在不同的块中——一个在函数体，一个在 `for` 语句的块，一个在循环体——但只有两个块是显式的：

[点击此处查看代码图像](#ch02_images.html#id047pro02_r)

```
func main() {
    x := "hello"
    for _, x := range x {
        x := x + 'A' - 'a'
        fmt.Printf("%c", x) // "HELLO" (每次迭代一个字母)
    }
}
```

与 `for` 循环类似，`if` 语句和 `switch` 语句也会在其主体块之外创建隐式块。以下 `if`-`else` 链中的代码展示了 `x` 和 `y` 的作用域：

[点击此处查看代码图像](#ch02_images.html#id047pro03_r)

```
if x := f(); x == 0 {
    fmt.Println(x)
} else if y := g(x); x == y {
    fmt.Println(x, y)
} else {
    fmt.Println(x, y)
}
fmt.Println(x, y) // 编译错误: x 和 y 在此处不可见
```

第二个 `if` 语句嵌套在第一个内部，因此在第一个语句的初始化子句中声明的变量在第二个语句中可见。`switch` 语句的每个 case 也适用类似规则：条件有一个块，每个 case 主体也有一个块。

在包级别，声明出现的顺序不影响其作用域，因此声明可以引用其自身或后面出现的另一个声明，从而允许声明递归或相互递归的类型和函数。不过，如果常量或变量声明引用其自身，编译器会报错。

在以下程序中：

[点击此处查看代码图像](#ch02_images.html#id048pro01_r)

```
if f, err := os.Open(fname); err != nil { // 编译错误: unused: f
    return err
}
f.ReadByte() // 编译错误: undefined f
f.Close()    // 编译错误: undefined f
```

`f` 的作用域仅限于 `if` 语句，因此后续语句无法访问 `f`，导致编译错误。视编译器而定，可能会额外报告局部变量 `f` 未被使用的错误。

因此，通常需要在条件之前声明 `f`，以便后续访问：

```
f, err := os.Open(fname)
if err != nil {
    return err
}
f.ReadByte()
f.Close()
```

你可能想通过将 `ReadByte` 和 `Close` 调用移至 `else` 块，来避免在外层块声明 `f` 和 `err`：

[点击此处查看代码图像](#ch02_images.html#id048pro02_r)

```
if f, err := os.Open(fname); err != nil {
    return err
} else {
    // f 和 err 在此处也可见
    f.ReadByte()
    f.Close()
}
```

但 Go 的常规做法是在 `if` 块中处理错误并返回，使成功执行路径保持不缩进。

短变量声明要求对作用域有清醒的认识。请看下面的程序，它首先获取当前工作目录并保存在包级变量中。这可以在 `main` 函数中调用 `os.Getwd` 完成，但最好将此关注点与主要逻辑分离，特别是当获取目录失败属于致命错误时。函数 `log.Fatalf` 会打印消息并调用 `os.Exit(1)`。

[点击此处查看代码图像](#ch02_images.html#id049pro01_r)

```
var cwd string

func init() {
    cwd, err := os.Getwd() // 编译错误: unused: cwd
    if err != nil {
        log.Fatalf("os.Getwd failed: %v", err)
    }
}
```

由于 `init` 函数块中尚未声明 `cwd` 和 `err`，`:=` 语句将它们俩都声明为局部变量。内层的 `cwd` 声明使外层的包级 `cwd` 不可访问，导致该语句未能按预期更新包级 `cwd` 变量。

当前的 Go 编译器会检测到局部 `cwd` 变量从未使用并报错，但规范并未强制要求此检查。此外，微小的改动（如增加一条引用局部 `cwd` 的日志语句）就会绕过该检查。

[点击此处查看代码图像](#ch02_images.html#id049pro02_r)

```
var cwd string

func init() {
    cwd, err := os.Getwd() // 注意: 错误!
    if err != nil {
        log.Fatalf("os.Getwd failed: %v", err)
    }
    log.Printf("Working directory = %s", cwd)
}
```

全局 `cwd` 变量保持未初始化状态，而看似正常的日志输出掩盖了该 Bug。
