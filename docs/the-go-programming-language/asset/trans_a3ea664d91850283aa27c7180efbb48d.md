
让我们使用一种新类型来测试一下。下面 `*ByteCounter` 类型的 `Write` 方法仅统计写入的字节数，然后丢弃它们。（需要进行类型转换，以使 `+=` 赋值语句中 `len(p)` 和 `*c` 的类型匹配。）

## 7.2 接口类型

接口类型指定了一组方法，具体类型必须拥有这些方法才能被视为该接口的实例。

`io.Writer` 类型是使用最广泛的接口之一，因为它为所有可以写入字节的类型提供了抽象，包括文件、内存缓冲区、网络连接、HTTP 客户端、归档工具、哈希器等。`io` 包定义了许多其他有用的接口。`Reader` 代表任何可以从中读取字节的类型，`Closer` 代表任何可以关闭的值，例如文件或网络连接。（到目前为止，你可能已经注意到了 Go 语言中许多单方法接口的命名约定。）

[点击此处查看代码图像](#ch07_images.html#id174pro02_r)

```
package io

type Reader interface {
    Read(p []byte) (n int, err error)
}

type Closer interface {
    Close() error
}
```

进一步查看，我们会发现新接口类型的声明是作为现有接口的组合。以下是两个示例：

[点击此处查看代码图像](#ch07_images.html#id174pro03_r)

```
type ReadWriter interface {
    Reader
    Writer
}

type ReadWriteCloser interface {
    Reader
    Writer
    Closer
}
```

上述使用的语法类似于结构体嵌入，允许我们将另一个接口命名为其所有方法的简写。这被称为*嵌入*接口。我们本可以不使用嵌入来编写 `io.ReadWriter`，尽管不那么简洁，如下所示：

[点击此处查看代码图像](#ch07_images.html#id175pro01_r)

```
type ReadWriter interface {
    Read(p []byte) (n int, err error)
    Write(p []byte) (n int, err error)
}
```

甚至可以混合使用这两种风格：

[点击此处查看代码图像](#ch07_images.html#id175pro02_r)

```
type ReadWriter interface {
    Read(p []byte) (n int, err error)
    Writer
}
```

这三种声明效果相同。方法出现的顺序无关紧要。唯一重要的是方法的集合。

## 7.3 接口满足

如果一个类型拥有接口所需的所有方法，则该类型*满足*该接口。例如，`*os.File` 满足 `io.Reader`、`Writer`、`Closer` 和 `ReadWriter`。`*bytes.Buffer` 满足 `Reader`、`Writer` 和 `ReadWriter`，但不满足 `Closer`，因为它没有 `Close` 方法。简言之，Go 程序员常说具体类型“是”某个特定接口类型，意指它满足该接口。例如，`*bytes.Buffer` 是一个 `io.Writer`；`*os.File` 是一个 `io.ReadWriter`。

接口的可赋值规则 ([§2.4.2](#ebook_split_023.html#id-assignability)) 非常简单：只有当表达式的类型满足接口时，才能将其赋值给接口。因此：

[点击此处查看代码图像](#ch07_images.html#id175pro04_r)

```
var w io.Writer
w = os.Stdout           // OK: *os.File 有 Write 方法
w = new(bytes.Buffer)   // OK: *bytes.Buffer 有 Write 方法
w = time.Second         // 编译错误: time.Duration 缺少 Write 方法

var rwc io.ReadWriteCloser
rwc = os.Stdout         // OK: *os.File 有 Read、Write、Close 方法
rwc = new(bytes.Buffer) // 编译错误: *bytes.Buffer 缺少 Close 方法
```

即使右侧本身是一个接口，此规则依然适用：

[点击此处查看代码图像](#ch07_images.html#id175pro05_r)

```
w = rwc                 // OK: io.ReadWriteCloser 有 Write 方法
rwc = w                 // 编译错误: io.Writer 缺少 Close 方法
```

因为 `ReadWriter` 和 `ReadWriteCloser` 包含 `Writer` 的所有方法，任何满足 `ReadWriter` 或 `ReadWriteCloser` 的类型必然满足 `Writer`。

在继续之前，我们应该解释一下类型拥有方法的一个细微差别。回顾 [6.2 节](#ebook_split_054.html#id-methodswithapointerreceiver)，对于每个命名的具体类型 `T`，其某些方法的接收者类型是 `T` 本身，而另一些则需要 `*T` 指针。还记得，只要参数是*变量*，就可以在类型为 `T` 的参数上调用 `*T` 方法；编译器会隐式地获取其地址。但这只是语法糖：类型 `T` 的值并不拥有 `*T` 指针的所有方法，因此它可能满足更少的接口。
