
第一个 goroutine `counter` 生成整数 0、1、2……，并通过一个 channel 将它们发送给第二个 goroutine `squarer`，后者接收每个值，计算其平方，并通过另一个 channel 将结果发送给第三个 goroutine `printer`，后者接收平方值并将其打印出来。为了示例的清晰性，我们特意选择了非常简单的函数，尽管当然在实际程序中，它们的计算太过简单，不值得拥有各自独立的 goroutine。

[点击此处查看代码图像](#ch08_images.html#id228pro01_r)

`gopl.io/ch8/pipeline1`

```
func main() {
    naturals := make(chan int)
    squares := make(chan int)

    // Counter
    go func() {
        for x := 0; ; x++ {
            naturals <- x
        }
    }()

    // Squarer
    go func() {
        for {
            x := <-naturals
            squares <- x * x
        }
    }()

    // Printer (在 main goroutine 中)
    for {
        fmt.Println(<-squares)
    }
}
```

正如你所料，该程序打印无限的平方数序列 0、1、4、9，依此类推。这种管道可能存在于长期运行的服务器程序中，在这些程序中，channel 被用于包含无限循环的 goroutine 之间的终身通信。但如果我们只想通过管道发送有限数量的值怎么办？

如果发送者知道某个 channel 上永远不会再发送更多值，那么将这一事实告知接收者 goroutine 会很有用，这样它们就可以停止等待。这通过使用内置的 `close` 函数*关闭* channel 来实现：

```
close(naturals)
```

在一个 channel 被关闭后，对它的任何进一步发送操作都将 panic。在关闭的 channel 被*耗尽*后，即最后一个发送的元素被接收后，所有后续的接收操作将不再阻塞，但会产出零值。关闭上面的 `naturals` channel 将导致 squarer 的循环空转，因为它接收到源源不断的零值，并将这些零值发送给 printer。

无法直接测试一个 channel 是否已被关闭，但接收操作有一个变体可以产生两个结果：接收到的 channel 元素，外加一个布尔值，通常称为 `ok`，成功接收时为 `true`，在已关闭且已耗尽的 channel 上接收时为 `false`。利用这一特性，我们可以修改 squarer 的循环，使其在 `naturals` channel 耗尽时停止，并依次关闭 `squares` channel。

[点击此处查看代码图像](#ch08_images.html#id229pro01_r)

```
// Squarer
go func() {
    for {
        x, ok := <-naturals
        if !ok {
            break // channel 已关闭且已耗尽
        }
        squares <- x * x
    }
    close(squares)
}()
```

由于上述语法笨拙且这种模式很常见，Go 语言允许我们使用 `range` 循环来迭代 channel。这是一种接收 channel 上发送的所有值并在最后一个值之后终止循环的更方便的语法。

在下面的管道中，当 counter goroutine 在处理完 100 个元素后结束循环，它会关闭 `naturals` channel，导致 squarer 结束其循环并关闭 `squares` channel。（在更复杂的程序中，让 counter 和 squarer 函数在一开始就 defer 调用 `close` 可能更合理。）最后，main goroutine 结束其循环，程序退出。

[点击此处查看代码图像](#ch08_images.html#id229pro02_r)

`gopl.io/ch8/pipeline2`

```
func main() {
    naturals := make(chan int)
    squares := make(chan int)

    // Counter
    go func() {
        for x := 0; x < 100; x++ {
            naturals <- x
        }
        close(naturals)
    }()

    // Squarer
    go func() {
        for x := range naturals {
            squares <- x * x
        }
        close(squares)
    }()

    // Printer (在 main goroutine 中)
    for x := range squares {
        fmt.Println(x)
    }
}
```

当你用完某个 channel 时，不必关闭每一个 channel。只有当需要告诉接收 goroutine 所有数据已发送完毕时，才有必要关闭 channel。垃圾回收器判定为不可达的 channel，无论是否关闭，其资源都会被回收。（不要将这与打开文件的 close 操作混淆。用完文件后，*必须*调用每个文件的 `Close` 方法。）

试图关闭一个已经关闭的 channel 会导致 panic，关闭 nil channel 也是如此。关闭 channel 还有一种用作广播机制的用途，我们将在 [8.9 节](#ebook_split_084.html#id-cancellation) 中介绍。

### 8.4.3 单向 Channel 类型

随着程序的增长，将大型函数拆分为较小的部分是很自然的。我们之前的示例使用了三个 goroutine，通过两个作为 `main` 局部变量的 channel 进行通信。该程序自然地划分为三个函数：

```
func counter(out chan int)
func squarer(out, in chan int)
func printer(in chan int)
```

处于管道中间的 `squarer` 函数接受两个参数，即输入 channel 和输出 channel。两者类型相同，但预期用途相反：`in` 仅用于接收，`out` 仅用于发送。参数名 `in` 和 `out` 传达了这一意图，但仍然无法阻止 `squarer` 向 `in` 发送或从 `out` 接收。

这种安排很典型。当 channel 作为函数参数提供时，几乎总是打算专门用于发送或专门用于接收。

为了记录这一意图并防止误用，Go 的类型系统提供了*单向* channel 类型，它们仅暴露发送和接收操作中的一种。类型 `chan<- int` 是一种*只发送*的 `int` channel，允许发送但不允许接收。相反，类型 `<-chan int` 是一种*只接收*的 `int` channel，允许接收但不允许发送。（`<-` 箭头相对于 `chan` 关键字的位置是一个助记符。）对此规则的违反会在编译时被检测出来。

由于 `close` 操作断言不再会有发送操作发生在 channel 上，因此只有发送 goroutine 有资格调用它，因此试图关闭一个只接收 channel 会导致编译时错误。

这里再次展示平方管道，这次使用了单向 channel 类型：

[点击此处查看代码图像](#ch08_images.html#id231pro01_r)

`gopl.io/ch8/pipeline3`

```
func counter(out chan<- int) {
    for x := 0; x < 100; x++ {
        out <- x
    }
    close(out)
}

func squarer(out chan<- int, in <-chan int) {
    for v := range in {
        out <- v * v
    }
    close(out)
}

func printer(in <-chan int) {
    for v := range in {
        fmt.Println(v)
    }
}

func main() {
    naturals := make(chan int)
    squares := make(chan int)

    go counter(naturals)
    go squarer(squares, naturals)
    printer(squares)
}
```

调用 `counter(naturals)` 会隐式地将 `naturals`（一个 `chan int` 类型的值）转换为参数类型 `chan<- int`。`printer(squares)` 调用执行类似的隐式转换为 `<-chan int`。允许在任何赋值中从双向 channel 类型转换为单向 channel 类型。但是无法逆向操作：一旦你拥有了一个单向类型的值，如 `chan<- int`，就无法从中获得一个引用相同 channel 数据结构的 `chan int` 类型的值。
