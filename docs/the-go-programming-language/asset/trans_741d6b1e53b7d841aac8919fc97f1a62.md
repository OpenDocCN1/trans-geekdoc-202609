// Package word provides utilities for word games.
package word

import "unicode"

// IsPalindrome reports whether s reads the same forward and backward.
// Letter case is ignored, as are non-letters.
func IsPalindrome(s string) bool {
    var letters []rune
    for _, r := range s {
        if unicode.IsLetter(r) {
            letters = append(letters, unicode.ToLower(r))
        }
    }
    for i := range letters {
        if letters[i] != letters[len(letters)-1-i] {
            return false
        }
    }
    return true
}
```

我们还编写了一组更全面的测试用例，将所有之前的用例和许多新用例合并到一个表中。

```
func TestIsPalindrome(t *testing.T) {
    var tests = []struct {
        input string
        want  bool
    }{
        {"", true},
        {"a", true},
        {"aa", true},
        {"ab", false},
        {"kayak", true},
        {"detartrated", true},
        {"A man, a plan, a canal: Panama", true},
        {"Evil I did dwell; lewd did I live.", true},
        {"Able was I ere I saw Elba", true},
        {"été", true},
        {"Et se resservir, ivresse reste.", true},
        {"palindrome", false}, // 非回文
        {"desserts", false},   // 半回文
    }
    for _, test := range tests {
        if got := IsPalindrome(test.input); got != test.want {
            t.Errorf("IsPalindrome(%q) = %v", test.input, got)
        }
    }
}

这种 *表驱动* 测试风格在 Go 中非常常见。根据需要添加新的表条目非常简单，而且由于断言逻辑没有重复，我们可以投入更多精力来生成良好的错误消息。

失败测试的输出在调用 `t.Errorf` 时 *不* 包含完整的堆栈跟踪。此外，与其他语言的许多测试框架中的断言失败不同，`t.Errorf` 不会导致 panic 或停止测试的执行。测试之间相互独立。如果表中的早期条目导致测试失败，后面的表条目仍将被检查，因此我们可能在一次运行中了解到多个失败。

当我们真的必须停止测试函数时，也许是因为某些初始化代码失败了，或者为了防止已报告的失败导致令人困惑的级联错误，我们使用 `t.Fatal` 或 `t.Fatalf`。这些必须从与 `Test` 函数相同的 goroutine 中调用，而不是从测试期间创建的另一个 goroutine 中调用。

测试失败消息通常采用 `"f(x) = y, want z"` 的形式，其中 `f(x)` 解释了尝试的操作及其输入，`y` 是实际结果，`z` 是预期结果。在方便的情况下，如我们的回文示例，会对 `f(x)` 部分使用实际的 Go 语法。显示 `x` 在表驱动测试中尤为重要，因为给定的断言会使用不同的值执行多次。避免样板代码和冗余信息。测试布尔函数（如 `IsPalindrome`）时，省略 `want z` 部分，因为它不增加任何信息。如果 `x`、`y` 或 `z` 很长，则打印相关部分的简明摘要。测试作者应致力于帮助必须诊断测试失败的程序员。

### 11.2.1 随机化测试

表驱动测试便于检查函数在精心挑选的、能覆盖逻辑中有趣情况的输入上是否正常工作。另一种方法，*随机化测试*，通过随机构造输入来探索更广泛的输入范围。
