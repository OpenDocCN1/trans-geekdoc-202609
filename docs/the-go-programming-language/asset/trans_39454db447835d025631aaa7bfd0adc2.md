
现在，当取消发生时，所有后台 goroutine 会迅速停止，且 `main` 函数返回。当然，当 `main` 返回时，程序就会退出，因此很难分辨一个会自我清理的 main 函数和一个不会自我清理的 main 函数。我们可以在测试期间使用一个方便的技巧：如果在发生取消时不从 `main` 返回，而是执行一个 `panic` 调用，那么运行时会转储程序中每个 goroutine 的堆栈。如果 main goroutine 是唯一剩下的，那么它就已经自我清理完毕了。但如果还有其他 goroutine 残留，它们可能没有被正确取消，或者虽然已被取消但取消过程需要时间；稍作调查可能很有价值。panic 转储通常包含足够的信息来区分这些情况。

**练习 8.10：** 通过关闭 `http.Request` 结构体中可选的 `Cancel` 通道，可以取消 HTTP 请求。修改 [8.6 节](#ebook_split_081.html#id-exampleconcurrentwebcrawler) 中的网络爬虫以支持取消。

提示：`http.Get` 便利函数不会给你自定义 `Request` 的机会。取而代之的是，使用 `http.NewRequest` 创建请求，设置其 `Cancel` 字段，然后通过调用 `http.DefaultClient.Do(req)` 来执行请求。

## 8.10 示例：聊天服务器

我们将用一个聊天服务器来结束本章，它允许多个用户相互广播文本消息。该程序中有四种 goroutine。`main` 和 `broadcaster` goroutine 各有一个实例，而对于每个客户端连接，则有一个 `handleConn` 和一个 `clientWriter` goroutine。broadcaster 很好地说明了 `select` 的用法，因为它必须响应三种不同类型的消息。

下面展示的 main goroutine 的工作是监听并接受来自客户端的传入网络连接。对于每一个连接，它都会创建一个新的 `handleConn` goroutine，就像我们在本章开头看到的并发 echo 服务器一样。

[点击此处查看代码图像](#ch08_images.html#id254pro01_r)

gopl.io/ch8/chat

```
func main() {
    listener, err := net.Listen("tcp", "localhost:8000")
    if err != nil {
        log.Fatal(err)
    }

    go broadcaster()
    for {
        conn, err := listener.Accept()
        if err != nil {
            log.Print(err)
            continue
        }
        go handleConn(conn)
    }
}
```

接下来是 broadcaster。其局部变量 `clients` 记录当前已连接客户端的集合。关于每个客户端记录的唯一信息是其传出消息通道的标识，稍后将详述。

[点击此处查看代码图像](#ch08_images.html#id254pro02_r)

```
type client chan<- string // 一个传出消息通道

var (
    entering = make(chan client)
    leaving  = make(chan client)
    messages = make(chan string) // 所有传入的客户端消息
)

func broadcaster() {
    clients := make(map[client]bool) // 所有已连接的客户端
    for {
        select {
        case msg := <-messages:
            // 将传入消息广播给所有
            // 客户端的传出消息通道。
            for cli := range clients {
                cli <- msg
            }

        case cli := <-entering:
            clients[cli] = true

        case cli := <-leaving:
            delete(clients, cli)
            close(cli)
        }
    }
}
```

broadcaster 监听全局 `entering` 和 `leaving` 通道，以获取客户端到达和离开的通知。当它收到其中一个事件时，会更新 `clients` 集合，如果事件是离开，则关闭该客户端的传出消息通道。broadcaster 还监听全局 `messages` 通道上的事件，每个客户端将其所有传入消息发送到该通道。当 broadcaster 收到此类事件时，会将消息广播给每个已连接的客户端。

现在让我们看看每个客户端的 goroutine。`handleConn` 函数为其客户端创建一个新的传出消息通道，并通过 `entering` 通道向 broadcaster 宣布该客户端的到来。然后它从客户端读取每一行文本，将每一行发送到全局传入消息通道，并以前缀发送者的身份标识每条消息。一旦没有更多内容可从客户端读取，`handleConn` 就会通过 `leaving` 通道宣布该客户端的离开并关闭连接。

[点击此处查看代码图像](#ch08_images.html#id255pro01_r)

```
func handleConn(conn net.Conn) {
    ch := make(chan string) // 传出客户端消息
    go clientWriter(conn, ch)

    who := conn.RemoteAddr().String()
    ch <- "You are " + who
    messages <- who + " has arrived"
    entering <- ch

    input := bufio.NewScanner(conn)
    for input.Scan() {
        messages <- who + ": " + input.Text()
    }
    // 注意：忽略了 input.Err() 的潜在错误

    leaving <- ch
    messages <- who + " has left"
    conn.Close()
}

func clientWriter(conn net.Conn, ch <-chan string) {
    for msg := range ch {
        fmt.Fprintln(conn, msg) // 注意：忽略网络错误
    }
}
```

此外，`handleConn` 为每个客户端创建一个 `clientWriter` goroutine，它接收广播给客户端传出消息通道的消息，并将它们写入客户端的网络连接。当 broadcaster 在收到 `leaving` 通知后关闭通道时，client writer 的循环就会终止。
