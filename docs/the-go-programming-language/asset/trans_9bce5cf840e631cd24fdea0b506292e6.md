
## 位运算

当作为二元运算符使用时，运算符 `^` 是按位异或 (XOR)；但当作为一元前缀运算符使用时，它是按位取反或补码；也就是说，它返回一个值，该值的操作数中每一位都被取反。`&^` 运算符是位清除 (AND NOT)：在表达式 `z = x &^ y` 中，如果 `y` 对应的位为 1，则 `z` 的每一位为 0；否则它等于 `x` 对应的位。

下面的代码展示了如何使用位运算将 `uint8` 值解释为一组紧凑且高效的 8 个独立位。它使用 `Printf` 的 `%b` 动词来打印数字的二进制位；`08` 修饰 `%b`（一个副词！）以零填充结果，使其恰好为 8 位数字。

[点击此处查看代码图像](#ch03_images.html#id054pro01_r)

```
var x uint8 = 1<<1 | 1<<5
var y uint8 = 1<<1 | 1<<2

fmt.Printf("%08b\n", x)    // "00100010", 集合 {1, 5}
fmt.Printf("%08b\n", y)    // "00000110", 集合 {1, 2}

fmt.Printf("%08b\n", x&y)  // "00000010", 交集 {1}
fmt.Printf("%08b\n", x|y)  // "00100110", 并集 {1, 2, 5}
fmt.Printf("%08b\n", x^y)  // "00100100", 对称差集 {2, 5}
fmt.Printf("%08b\n", x&^y) // "00100000", 差集 {5}

for i := uint(0); i < 8; i++ {
    if x&(1<<i) != 0 { // 成员测试
        fmt.Println(i) // "1", "5"
    }
}

fmt.Printf("%08b\n", x<<1) // "01000100", 集合 {2, 6}
fmt.Printf("%08b\n", x>>1) // "00010001", 集合 {0, 4}
```

（[第 6.5 节](#ebook_split_057.html#id-intset) 展示了整数集合的实现，其大小可以远超一个字节。）

在移位运算 `x<<n` 和 `x>>n` 中，`n` 操作数决定移位的位数，且必须是无符号数；`x` 操作数可以是无符号或有符号数。从算术上讲，左移 `x<<n` 等同于乘以 2^(`n`)，右移 `x>>n` 等同于除以 2^(`n`) 后向下取整。

左移用零填充空出的位，无符号数的右移也是如此，但有符号数的右移用符号位的副本填充空出的位。因此，当你将整数视为位模式处理时，使用无符号运算非常重要。

尽管 Go 提供了无符号数和运算，但我们倾向于使用有符号的 `int` 形式，即使对于不可能为负的量，例如数组的长度，尽管 `uint` 似乎是更明显的选择。确实，内置的 `len` 函数返回有符号的 `int`，如这个按逆序宣布奖牌的循环所示：

[点击此处查看代码图像](#ch03_images.html#id054pro02_r)

```
medals := []string{"gold", "silver", "bronze"}
for i := len(medals) - 1; i >= 0; i-- {
    fmt.Println(medals[i]) // "bronze", "silver", "gold"
}
```

另一种做法将是灾难性的。如果 `len` 返回无符号数，那么 `i` 也将是 `uint`，且根据定义，条件 `i >= 0` 永远为真。在第三次迭代（此时 `i == 0`）之后，`i--` 语句将导致 `i` 变为不是 −1，而是最大的 `uint` 值（例如 2^(64)−1），并且对 `medals[i]` 的求值将在运行时失败，或 *panic*（[§5.9](#ebook_split_050.html#id-panic)），因为它试图访问切片边界之外的元素。

因此，无符号数通常仅在需要其位运算符或特殊算术运算符时使用，例如实现位集、解析二进制文件格式，或用于哈希和加密。它们通常不用于仅仅是非负的量。

通常，将值从一种类型转换为另一种类型需要显式转换，并且算术和逻辑的二元运算符（移位除外）必须具有相同类型的操作数。虽然这偶尔会导致表达式变长，但它也消除了一整类问题，并使程序更易于理解。

作为一个从其他上下文中熟悉的例子，考虑以下序列：

[点击此处查看代码图像](#ch03_images.html#id055pro01_r)

```
var apples int32 = 1
var oranges int16 = 2
var compote int = apples + oranges // 编译错误
```

尝试编译这三个声明会产生一条错误消息：

[点击此处查看代码图像](#ch03_images.html#id055pro01_01_r)

```
invalid operation: apples + oranges (mismatched types int32 and int16)
```

这种类型不匹配可以通过几种方式修复，最直接的方法是将所有内容转换为通用类型：

[点击此处查看代码图像](#ch03_images.html#id055pro02_r)

```
var compote = int(apples) + int(oranges)
```

正如 [第 2.5 节](#ebook_split_024.html#id-typedeclarations) 所述，对于每种类型 `T`，转换操作 `T(x)` 会在允许转换的情况下将值 `x` 转换为类型 `T`。许多整数到整数的转换不会导致值的任何变化；它们只是告诉编译器如何解释该值。但将大整数收窄为较小整数的转换，或整数到浮点数或反之的转换，可能会改变值或丢失精度：

[点击此处查看代码图像](#ch03_images.html#id055pro03_r)

```
f := 3.141 // 一个 float64
i := int(f)
fmt.Println(f, i)   // "3.141 3"
f = 1.99
fmt.Println(int(f)) // "1"
```

浮点数到整数的转换会丢弃任何小数部分，向零截断。你应该避免操作数超出目标类型范围的转换，因为其行为取决于实现：

[点击此处查看代码图像](#ch03_images.html#id055pro04_r)

```
f := 1e100  // 一个 float64
i := int(f) // 结果取决于实现
```

任意大小和类型的整数字面量可以写作普通十进制数，如果以 `0` 开头则写作八进制数，如 `0666`，或者如果以 `0x` 或 `0X` 开头则写作十六进制数，如 `0xdeadbeef`。十六进制数字可以是大写或小写。如今八进制数似乎只用于一个目的——POSIX 系统上的文件权限——但十六进制数被广泛用于强调数字的位模式而非其数值。

使用 `fmt` 包打印数字时，我们可以使用 `%d`、`%o` 和 `%x` 动词控制基数和格式，如以下示例所示：

[点击此处查看代码图像](#ch03_images.html#id056pro01_r)

```
o := 0666
fmt.Printf("%d %[1]o %#[1]o\n", o) // "438 666 0666"
x := int64(0xdeadbeef)
fmt.Printf("%d %[1]x %#[1]x %#[1]X\n", x)
// 输出：
// 3735928559 deadbeef 0xdeadbeef 0XDEADBEEF
```

请注意两个 `fmt` 技巧的使用。通常包含多个 `%` 动词的 `Printf` 格式字符串需要相同数量的额外操作数，但 `%` 后的 `[1]` “副词”告诉 `Printf` 反复使用第一个操作数。其次，`%o`、`%x` 或 `%X` 的 `#` 副词分别告诉 `Printf` 输出 `0`、`0x` 或 `0X` 前缀。

Rune 字面量写作单引号内的字符。最简单的例子是 ASCII 字符，如 `'a'`，但也可以直接或通过数字转义写入任何 Unicode 码点，我们稍后将看到。

Rune 使用 `%c` 打印，如果需要带引号则使用 `%q`：

[点击此处查看代码图像](#ch03_images.html#id056pro02_r)

```
ascii := 'a'
unicode := ''
newline := '\n'
fmt.Printf("%d %[1]c %[1]q\n", ascii)   // "97 a 'a'"
fmt.Printf("%d %[1]c %[1]q\n", unicode) // "22269  ''"
fmt.Printf("%d %[1]q\n", newline)       // "10 '\n'"
```

## 3.2 浮点数

Go 提供两种大小的浮点数，`float32` 和 `float64`。它们的算术特性由所有现代 CPU 实现的 IEEE 754 标准控制。

这些数值类型的值范围从极小到极大。浮点数值的限制可以在 `math` 包中找到。常量 `math.MaxFloat32`，即最大的 `float32`，约为 `3.4e38`，而 `math.MaxFloat64` 约为 `1.8e308`。最小的正值分别接近 `1.4e-45` 和 `4.9e-324`。
