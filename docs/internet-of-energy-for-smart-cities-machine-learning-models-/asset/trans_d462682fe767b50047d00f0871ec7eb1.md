### 1.3.6 能源区块链

大数据分析需要适合的基于 Web 的平台来实现安全的数据存储和处理。现代能源系统对实时操作日益增长的需求必将导致数据处理成本显著增加。区块链是一种共享账本，已成为高效在线数据存储的解决方案。它满足了大数据分析的两个主要要求，即数据安全和保护其价值。区块链本质上是一系列存储后续操作信息的区块。它在无需中介参与的情况下促进透明操作。区块链的安全性和自主性由智能合约和共识机制 [1] 确保。

在智慧能源系统的背景下，区块链被称为能源区块链，主要用于以下应用，即点对点能源交易、微电网运行以及网络物理安全 [18, 19]。以能源交易为例，两个独立的参与者可以通过智能合约进行交易，无需第三方介入。智能合约集成在区块链中，并在满足某些先决条件后作为软件代理执行。有多种软件平台可用于制定智能合约，例如 Ethereum Blockchain 和 Hyperledger Project。

区块链的三个主要特征是去中心化、透明性和不可篡改性。使区块链适合实时交易操作的重要特征如下 [22]。

- 1. 共识机制允许所有参与节点对每个操作达成必要的一致意见，从而确保存储在区块链中的数据的完整性。
- 2. 由于每个节点仅直接与区块链通信，因此通信要求降至最低。
- 3. 它是一个完全分布式框架，不需要中央控制实体的介入，从而避免不必要的通信成本和时间延迟。
- 4. 由于分布式架构，单点故障或单点被攻破的风险被消除，在此架构中，节点可以通过单独的接口直接与网络通信。
- 5. 区块链为数据提供隐私性和不可篡改性，指的是无法更改已经完成的交易。每个区块都使用加密哈希函数进行哈希处理，基于其数据内容和前一个区块的哈希值，从而确保区块链安全。

## 1.4 智能基于云的电网应用

能源系统由多种可控资源组成，包括分布式发电源（如 RES 和燃料电池）、储能系统（如电池和超级电容器）以及响应性负荷。能源系统运行需要多种协调控制动作，这些动作受系统物理限制（如线路热极限和母线电压极限）的约束，同时确保所有母线上的有功和无功功率平衡。这些控制动作（如负荷调度、经济调度、故障清除、再同步和孤岛运行）在不同的时间尺度上进行协调，从几秒钟到几个小时不等。此外，电网中的能源和功率交易持续时间很长，从长期合同（签订期限为数月至数年）、日前市场（计算直至实际运行日的调度）、日内交易，一直到最终的实时功率交易。

还值得注意的是，参与这些运行的代理在空间上分布并位于能源系统的不同位置。此外，每个代理周围的环境可能是独特且动态的，可能偏离控制器的设计条件。因此，能源系统的规划、调度、运行和控制过程跨越从数年到不到一秒的时间尺度，覆盖广阔区域，并在不同条件下进行，这凸显了对时间和空间协调框架的需求。因此，三种主要控制策略已广泛应用于能源系统控制，即 (a) 集中式、(b) 分散式和 (c) 分布式控制 [31]。

### 1.4.1 集中式控制

集中式控制是指存在单一决策实体的控制架构。不同的系统组件由中央控制代理进行控制。该代理负责在实时系统运行期间监控、收集和分析数据。集中式方法在实践中被广泛使用，并逐年逐步演变。电力系统中集中式控制的常见应用包括微电网控制、经济调度、机组承诺、批发电力市场、能源管理系统等。然而，多年来，人们逐渐认识到，随着由分布式能源资源、可控储能系统和灵活负荷组成的主动配电系统逐渐发展，控制变量的维度在不断增加。这显著增加了优化或控制模型的复杂性。这导致计算时间非常长，不适合实时操作。因此，对于智慧能源系统，集中式控制由于以下主要原因似乎并不合适。

- 1. 随着控制变量数量的增加，计算负担也会增加。此外，随着维度的增加，问题可能变得不可行。
- 2. 随着受控区域的增大，信息传输可能变得越来越困难。
- 3. 集中式控制系统存在单点故障问题，这使得这种控制类型不适合故障影响实体数量较大的大型控制系统。
- 4. 此类系统的拓扑结构在不影响其他系统组件的情况下难以轻易修改或扩展，而这是模块化微电网的基本要求。
- 5. 系统的集中式控制需要广泛的通信网络来控制系统组件。

### 1.4.2 分散式控制

分散式控制是指这种控制系统类型：不依赖单一中央控制器，而是由多个本地化控制器以自主和独立的方式进行决策。本地代理使用本地化信息进行决策，不依赖中央控制实体。本地代理的决策取决于输入变量的本地测量，从而最大限度地减少了集中式控制所需的广泛通信网络需求。这也最大限度地减少了单点故障风险以及因通信延迟导致的系统运行中断。然而，由于代理之间缺乏通信和信息交换，这种控制形式无法保证全局最优。因此，分散式控制容易陷入局部最优并产生次优解的风险。
