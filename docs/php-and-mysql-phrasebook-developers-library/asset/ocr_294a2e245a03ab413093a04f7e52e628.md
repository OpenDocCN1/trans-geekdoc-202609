*Changing the Session ID (session_regenerate_id.php)*

One common attack against Web sites that are secured with sessions is that the session ID of a user is somehow taken (for instance, by analyzing HTTP_REFERER entries in HTTP requests) and then used to impersonate that specific user. This is hard to battle, but one convenient way to make it harder for attackers is to change the session ID whenever something "important" happens, such as the user signing in. For instance, Amazon requires users who are already authenticated with their cookie to sign in again when they want to order something.

In this case, the function session_regenerate_id() just changes the current session ID but leaves all data intact.
