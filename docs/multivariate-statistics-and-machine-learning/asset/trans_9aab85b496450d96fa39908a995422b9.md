
## 霍普金斯统计量
*霍普金斯统计量* 是可用于评估数据可聚类性的一个流行度量。它可以解释为数据集的 *聚类倾向* 测度（[Aggarwal, 2015](#ref.xhtml#re_CIT000005); [Wright, 2022](#ref.xhtml#re_CIT000393)）。在此方法中，`p[r]` 值是随机生成的，同时 `p[d]` 点是从数据中随机抽样的。对于这两组点，计算它们在数据中最近邻的距离。也就是说，如果我们令 `x[i]` 为最近邻，那么我们希望比较的是 `p[r]` 到 `x[i]` 的距离，我们称之为 `D_random` 与 `p[d]` 到 `x[i']` 的距离，我们称之为 `D_data`。也就是说，我们感兴趣的是了解基于 *随机数据集* 与数据集中 *实际数据点* 的最近邻距离如何比较。

霍普金斯统计量因此定义为

$$H = \\frac{\\sum\\limits\_{i = 1}^{r}D\_{i(random)}}{\\sum\\limits\_{i = 1}^{r}\\left( D\_{i(data)} + D\_{i(random)} \\right)}$$

(14.9)

对于均匀随机生成的数据，霍普金斯的期望值在 0.5 附近。这是因为 `D_i(data)` 和 `D_i(random)` 相似。如果数据可聚类，`D_i(data)` 通常小于 `D_i(random)`，因此 `H` 会增大。`H` 大于 0.75 的值已被发现相当于 90% 的聚类“置信度”（[Lawson & Jurs, 1990](#ref.xhtml#re_CIT000212); [Wright, 2022](#ref.xhtml#re_CIT000393)）。[Adolfsson et al. (2019)](#ref.xhtml#re_CIT000004) 提供了所谓的聚类性方法的广泛综述（除霍普金斯外还存在许多其他技术），并发现当簇接触或重叠时，霍普金斯统计量可能是一个 somewhat 有限的度量。

包 `hopkins` ([Wright, 2023](#ref.xhtml#re_CIT000394)) 可在 R 中用于计算霍普金斯统计量。作为包中的示例，我们在 iris 数据上计算霍普金斯统计量（萼片长度至花瓣宽度，排除物种），其中我们在 `m = 15` 个观测值上计算霍普金斯（或抽样的 *行*，如果未特别设置，默认是行数的 1/10）：
```
> library(hopkins)
> hopkins(iris[, 1:4], m=15)
[1] 0.9986529
```
我们还可以获得计算得到的霍普金斯统计量的 `p-value`，其中 `x` 是计算得到的霍普金斯值，`n` 是抽样的观测数：506
```
> hopkins.pval(x = 0.9986529, n = 15)
[1] 0
```
由于霍普金斯的值如此之大，`p-value` 极小（它被四舍五入为 0，`p-values` *永远* 不 *恰好* 等于 0）。假设我们得到的霍普金斯等于 0.5，则 `p-value` 将为
```
> hopkins.pval(x = 0.5, n = 15)
[1] 1
```
该值等于 1，因为请回忆霍普金斯在均匀分布下的期望等于 0.5。越远离 0.5，`p-value` 越低，如下再次所示，
```
> hopkins.pval(0.1, 15)
[1] 3.925226e-08
> hopkins.pval(0.9, 15)
[1] 3.925226e-08
```
我们看到对于 0.1 和 0.9 这两个值，得到的 `p-values` 相同。与显著性检验一样，通常随着 `n` 的增大，在其他条件相同的情况下，`p-values` 会下降。使用之前的示例但将 `n` 增加到 100，毫不奇怪地得到
```
> hopkins.pval(0.9, 100)
[1] 0
```

## 14.8 聚类分析算法
本节我们概述一些更受欢迎的聚类算法，包括 `k-means` 和相关的 `k-representatives`、层次或凝聚聚类、基于密度的聚类（具体为 DBSCAN）以及通过混合模型进行聚类。

### 14.8.1 `K-Means` 聚类和 `K-Representatives`
`k-means` 聚类算法可能是最简单、最知名、最常用的聚类分析形式。`k-means` 是更广泛的 *基于代表* 聚类算法组中的特例，这些算法依赖于观测值之间 *距离* 的概念作为聚类的基础。这些方法有时也被称为 *划分* ([Madhulatha, 2012](#ref.xhtml#re_CIT000233)) 或 *非嵌套* 方法，因为它们试图通过将案例分配给最近的聚类质心来将数据划分为组或簇，而层次聚类被认为是一种 *嵌套* 聚类形式，通过本质上融合较小的从属簇来构建簇。在这种情况下，质心就是所说的给定簇的“代表”。其他基于代表的算法包括 `k-medians`、`k-medoids` 和 `kernel-based k-means`。简而言之，`k-medians` 方法使用中位数代替均值，因此比 `k-means` 方法对极端和离群情况更稳健。在 `k-medoids` 方法中，启动算法的初始起点取自原始数据库，而在基于核的 `k-means` 中，通过熟悉的 *核技巧* 应用核函数来生成簇。

如前所述，基于代表的算法通常与 *层次方法* 对比，后者采用 *自底向上* 或 *自顶向下* 的方法构建簇，通常需要存储距离矩阵。非层次聚类方法通常比层次方法 507 更高效，因为它们不需要存储距离矩阵。术语可能因阅读的资料来源而略有不同，因此研究聚类算法的读者应确保了解作者如何使用这些术语。

### 14.8.2 `K-Means` 如何工作
`k-means` 聚类试图将案例划分为不同的簇，其中簇的数量由用户事先指定。在 `k-means` 中，最优化到其最近代表的平方距离之和，且一个属于一个簇的观测不能同时属于另一个簇。也就是说，簇成员资格是 *互斥的*。在某些其他聚类方法中通常不会如此，例如基于密度或混合模型聚类。所谓的 *模糊聚类* 算法也允许一个案例被聚类到多个簇中。

`k-means` 算法还对每个对象进行聚类，这意味着聚类中不会有任何观测被遗漏。从这个意义上说，`k-means` 被视为一种 *完全聚类* 算法，它寻求聚类 *每一个* 案例。这与允许某些案例未被聚类的 *部分聚类* 算法形成对比。例如，DBSCAN 是一种基于密度的聚类算法，我们稍后会介绍，它通常不会产生完全聚类，因为它将某些案例简单定义为 *噪声* 点，而不是将其分类到簇中。这些“噪声”点是指似乎无法“适应”正在生成的任何簇的点。而且尽管今天 `k-means` 通常被视为“算法”，但就该过程而言，“算法”一词并没有什么特别之处。的确，在过去，`k-means` 常常被称为数据分析的 *程序* 或 *方法*。就像今天许多统计和机器学习方法一样，它通常被称为“算法”，很大程度上（但并非 *排他性*）是由于我们目前所处的时代精神。否则优秀的聚类分析著作甚至可能一次也不提及“算法”一词，而只是描述推导出簇的过程。

> `K-means` 是更广泛的基于代表的聚类算法组的特例。另一方面，层次算法可以分为自底向上和自顶向下方法。
