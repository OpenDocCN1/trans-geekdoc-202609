
> *Though linear models dominate statistics and science, many, if not most phenomena in science are nonlinear. Seeking alternatives to linearity is often preferred to better capture the reality of scientific processes. Advancements in statistics and machine learning are often geared toward models and algorithms that help better unpack nonlinear features in data. Efforts to detect complex nonlinear patterns are at the heart of cutting-edge statistics and machine learning.*

The truth of the matter is that most if not all relationships are *nonlinear* and may be even more complex than we could even ever model. Having surveyed the linear ground thus far in this book, our goal in this chapter is to survey a few methods that model nonlinear relationships. There are 291three general approaches that we will consider here that seek to capture nonlinearity in data: 1) *polynomial regression*, 2) *regression splines*, and 3) *kernel regression*, which we will first motivate by simple local-averaging.

## 7.1 Polynomial Regression

Recall the classic linear model,

*y*[*i*] = *β*[0] + *β*[1]*x*[*i*] + *ε*[*i*]

(7.1)

The above model is actually a special case of the more general *polynomial regression model*,

*y*[*i*] = *β*[0] + *β*[1]*x*[*i*] + *β*[2]*x*[*i*]² + *β*[3]*x*[*i*]³ + *β*[4]*x*[*i*]⁴+   ⋅  ⋅ ⋅   + *β*[*p*]*x*[*i*]^(*p*) + *ε*[*i*]

(7.2)

A polynomial of order *p* can have *p − 1* “bends.” For instance, a straight line of order “1” has *p −* 1 = 1 − 1 = 0 bends, which is what makes it a straight line (i.e., there are no “bends” in a straight line, at least macroscopically). A parabola has a single bend (i.e., 2 − 1 = 1), and so on. A constant-only model (e.g., the mean) implies *p* = 0.

Typically, polynomials of only degrees 1 through 4 are generally used in scientific practice, since the higher the order of the polynomial, the greater the possibility of *overfitting*. That is, while fitting a polynomial of say, degree 10 might provide an exceptional fit to your training data (you may in fact be connecting the dots if your sample size is rather small!), many of those higher degrees are likely simply capitalizing on chance factors or random noise in the training data and hence the fit will not generalize well when validated on test data. That is, a polynomial of excessive order is likely to overfit the data. Recall that when it comes to model validation, it is how the model fits on *test* data that matters most, not how it fits on *training* data.

> *A polynomial of order (or “degree”) p can have p − 1 “bends.” The complexity of a polynomial increases with the number of bends in it. Typically, polynomials of only up to degree 4 are used in scientific practice, as higher-order polynomials are likely to overfit the training data. However, higher-order polynomials may be useful depending on the nature of the scientific material and domain.*

When we are fitting the classic linear model, we are in actuality performing polynomial regression, only that the polynomial is a rather simple one, that of a *line*. That is, the linear equation is simply a special case of the wider polynomial equation where only powers of one are included:

$$\\begin{array}{l} {y\_{i} = \\left\\{ {\\beta\_{0} + \\beta\_{1}x\_{i}} \\right\\} + \\beta\_{2}x\_{i}^{2} + \\beta\_{3}x\_{i}^{3} + \\beta\_{4}x\_{i}^{4} + \\,\\, \\cdot \\cdot \\cdot \\,\\, + \\beta\_{p}x\_{i}^{p} + \\varepsilon\_{i}} \\\\ \\left. \\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\downarrow \\right. \\\\ {y\_{i} = \\left\\{ {\\beta\_{0} + \\beta\_{1}x\_{i}} \\right\\} + \\varepsilon\_{i}} \\\\ \\end{array}$$

Another way of thinking of the above is that the linear model is a polynomial model in which all higher powers beyond unity are constrained or set to zero.292

### 7.1.1 Polynomial Regression in Python

We can fit a basic polynomial regression in Python quite easily using `numpy.polyfit()`:

```
import numpy as np
import matplotlib.pyplot as plt
```

We would like to fit a polynomial to the following data:

```
x = [1,2,3,5,6,7,8,9,10,12,13,14,15,16,18,19,21,22]
y = [100,90,80,60,60,55,60,65,70,70,75,76,78,79,90,99,99,100]
```

We specify a third-degree polynomial ([Figure 7.1](#c7.xhtml#f7.1)):

![Figure 7.1 Third-degree polynomial fit to curvilinear data.Return to text.⏎](images/fig7.1.jpg)

*Figure 7.1* Third-degree polynomial fit to curvilinear data.[Return to text.⏎](#c7.xhtml#re_f7.1)

```
mymodel = np.poly1d(np.polyfit(x, y, 3))
myline = np.linspace(1, 22, 100)
plt.scatter(x, y)
Out[209]: <matplotlib.collections.PathCollection at 0x1af74f20dd0>
plt.plot(myline, mymodel(myline))
Out[210]: [<matplotlib.lines.Line2D at 0x1af77d64cd0>]
plt.show()
import numpy
from sklearn.metrics import r2_score
print(r2_score(y, mymodel(x)))
0.9432150416451026
```

We can see from the R-squared that the proportion of variance explained by the polynomial is approximately 94%. The cubic model (i.e., degree 3) fits better than had we tried a quadratic one:293

```
mymodel = np.poly1d(np.polyfit(x, y, 2))
print(r2_score(y, mymodel(x)))
0.759777160189589
```

Had we fit a model of degree 4 (i.e., quartic), we would have obtained only a slightly larger R-squared than the cubic, which would have probably resulted in overfitting the data:

```
mymodel = np.poly1d(np.polyfit(x, y, 4))
print(r2_score(y, mymodel(x)))
0.9542030834699506
```

Polynomial regression can also be performed in Python using `statsmodels`.

### 7.1.2 Polynomial Regression in R

We illustrate polynomial regression on the `Boston` data set. This is data derived from information collected by the U.S. Census Service on housing characteristics and measures in the area of Boston, MA. We will use the `tidyverse` ([Wickham](#ref.xhtml#re_CIT000384) et al., 2019) and `caret` ([Kuhn, 2008](#ref.xhtml#re_CIT000208)) packages. A version of polynomial regression using this data can also be found in James et al. ([2013](#ref.xhtml#re_CIT000168), p. 115):

```
> library(tidyverse)
> library(caret)
> data(“Boston”, package = “MASS”)
```

There are a total of 506 observations in the Boston data. We will now split the data 0.8 into train and 0.2 into test:

```
> set.seed(123)
> training.samples <- Boston$medv %>%
+ createDataPartition(p = 0.8, list = FALSE)
> train.data <- Boston[training.samples, ]
> test.data <- Boston[-training.samples, ]
```

We confirm that the data has been split correctly:

```
> nrow(train.data)
[1] 407
> nrow(test.data)
[1] 99
```

The number of rows in the `train.data` is 407 while the number of rows in the `test.data` is 99. Recall we had requested that the train data be 80% of the entire data. The total number of cases is equal to 407 + 99 = 506, of which 407 is 80%.
