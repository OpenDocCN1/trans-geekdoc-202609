## 10.6 Random Forests

We have seen how bagged trees (or whatever statistical learning method we are using) can help reduce variance in the method by averaging results. The question now is, *can we improve on bagging?* It turns out that we can. The technique of *random forests* is yet another committee machine. Random forests take bagging to the next level, seeking to improve upon it. To appreciate how random forests improve on bagging, we first need to consider what is lacking in bagging in the first place.

### 10.6.1 The Problem with Bagging Decision Trees

We know that in building decision trees, overfitting can occur because the nodes will contain the “best option” at each split. That is, a decision tree is, in a sense, *optimized* to produce the best outcome and hence is capitalizing on the training data a great deal. Thus, we can expect trees to be *similar* in many respects when bagged because each tree is built with the same optimization strategy in mind. Of course, if you build trees with the same optimization, this will quite naturally and quickly lead to overfitting.

*Random forests* are an ingenious way to combat the overfitting problem of combining decision trees. How they do this is by introducing a *randomization feature* into each node split in an effort to combat overfitting. That is, each node is split in a random manner where a random sample of predictors is chosen as split “candidates” from the full set of possible predictors. This improves over bagging alone because when we bag, if there is, say, one strong predictor, most of the trees developed will use this strong predictor in the top split, and hence, *all bagged trees will look similar, which produces predictions that are highly correlated*. Where bagging reduces variance and potentially bias for full-grown trees, a random forest reduces the correlation between 385tree-structured classifiers. That is, random forests essentially *decorrelates* the trees through this randomization process. Random forests forces each split to consider only a *subset of the predictors*, which is what “decorrelates” the trees.

> *The problem with bagging decision trees is that the trees are correlated. Averaging many highly correlated quantities reduces variance, but not as much as averaging many uncorrelated quantities. Random forests overcomes this problem by introducing a randomization process regarding how predictors are chosen at each split.*

### 10.6.2 Equivalency of Random Forests and Bagging

The observant reader may have noticed that there is a certain condition in which random forests must be equivalent to bagging. Indeed, random forests have a natural relationship to bagging *when the random forest is built using the number of trees equal to the number of predictors*. Under this condition, *random forests equate to bagging*. Random forests then can be considered, in this context, simply a *special case* of bagging where a randomization feature is introduced, or vice versa, one can also consider bagging a special case of random forests where no randomization feature is implemented.

> *Random forests can be considered a special case of bagging in which a random sample of decision trees are selected from the bootstrapped “bagged” samples in an effort to decorrelate the trees. When all predictors are used in the random forest and hence there is no randomization element, this then reduces to bagging.*

### 10.6.3 Random Forests in R
