
That is, instead of the tuning parameter being applied to the sum of squared regression weights, $\\sum\\limits\_{j = 1}^{p}\\beta\_{j}^{2}$, it is now applied to the sum of the *absolute value* regression weights, $\\left. {\\sum\\limits\_{j = 1}^{p}\\left| \\beta\_{j} \\right.} \\right|$. Be sure to note however that whether adding a squared term in ridge regression or absolute value term in lasso regression, the general principle is the same, and that is to include a penalty term to the least-squares residual sum of squares to seemingly increase the error function. But again, it is worth asking why we would want to do such a thing. As before with ridge, it becomes “worth it” if such an addition of the penalty reduces `MSE` on `test` (not necessarily *train*) data. The only difference between ridge and lasso is the nature of the penalty. In both cases, as `lambda` *λ* increases, all coefficients in the regression will eventually go to 0, and hence a “stopping point” will be required; otherwise performing ridge or lasso regression would be trivial and meaningless. That is, while we would like to shrink some coefficients to or toward 0, driving all coefficients to 0 would be 277counterproductive. As we will soon see, in practice, the stopping point is typically selected via `cross-validation`.

According to [Müller and Guido (2017)](#ref.xhtml#re_CIT000258), ridge is usually the first choice between that of ridge vs. lasso. Lasso might be most useful if you have a large number of predictors and expect only a few of them to be important, so that the rest can drop out. Remember, lasso can be used for variable selection because it drives some coefficients all the way to 0. This is the key distinguishing feature, in an applied sense, between using ridge vs. the lasso.
