
## 11.7 Principal Curves

Other more local, or *bottom-up* approaches estimate the curve essentially “step by step” moving through the data cloud ([Delicado, 2001](#ref.xhtml#re_CIT000081)). These more local approaches are generally more flexible but have higher variance since small perturbations in the training data can drastically affect the location of the curve. *Local principal curves* is one technique that models segments of the curve within a certain *bandwidth*. The concept of principal curves can be extended to that of *principal surfaces* when working in higher dimensions.

### 11.7.1 Principal Components as a Special Case of Principal Curves and Surfaces

We can now see how principal components can be conceptualized as a special case of principal curves in which the “curve” in `PCA` is linear ([Sandilya & Kulkarni, 2002](#ref.xhtml#re_CIT000321)). Principal curves are the more general procedure. That is, while principal curves uses the data to fit a curve, principal components in a sense still uses the data to determine the placement of the components, but *the curve is always a hyperplane*. Indeed, if we extend curves to surfaces, then `PCA` becomes a special case of principal curves which in turn is a special case of principal *surfaces*. This is also clear from the fact that the principal curve algorithm begins with fitting a principal component, until it iterates to successfully fit the corresponding curve based on the arrangement of the data ([Hastie et al., 2009](#ref.xhtml#re_CIT000145)).

### 11.7.2 Principal Curves in R

## 11.8 Principal Components Analysis as an Encoder

An *encoder* is a general term that has many variations and connotations depending on the exact context, but in its most general sense, is some function that translates or transforms data or information into another form, usually, and most generally, into a form with desirable properties. There are two parts to an encoder, the *encoding* element and the *decoding* element.428

An *autoencoder* is a special type of encoder that encodes through some latent path such as a *hidden layer* in a neural network. If the autoencoder has more than a single hidden layer, it is generally referred to as a *deep autoencoder*. The key feature of a *classic autoencoder* is that there are *as many inputs as there are outputs* ([Alpaydin, 2020](#ref.xhtml#re_CIT000009)). An autoencoder in which the new function is required to have a lesser dimension than the inputting function is sometimes referred to as an *undercomplete autoencoder* ([Goodfellow et al., 2016](#ref.xhtml#re_CIT000131)). Autoencoders generally belong to the family of unsupervised techniques.

A classic example of an autoencoder at a conceptual level is that of encoding cell phone data into the cloud, then decoding that data back to the cell phone. The important feature here is that, for the classic autoencoder at least, the data has not really changed dimensionality; it has simply changed *forms*. Had we constrained the data in the cloud to assume a lesser dimensionality than the original cell phone data, this would have been an example of the aforementioned *undercomplete autoencoder*.

More formally, the encoder in an autoencoder can be given by

`z` = `Encode`(`x`|`W`)

where `W` are the parameters of the encoder and `x` is the vector being encoded. The decoder is thus given by

`x` = `Decode`(`z`|`V`)

where `V` are now the parameters of the decoder and `z` is the vector being decoded.

Autoencoders can be linear or nonlinear. For example, consider the two images in Figure 11.12, one a linear encoder and one a nonlinear encoder, the only difference being the form of function in the hidden nodes (i.e., linear vs. nonlinear).

## 11.9 Neural Networks and PCA as Autoencoders

The classic case of an encoder, as featured just above, is that of a neural network where the mappings are no longer linear but instead nonlinear. As we will see when we survey neural networks, there is nothing necessarily and intrinsically nonlinear about a neural network; technically the 429activation function *can* be linear if chosen as such. However, neural networks typically feature nonlinear activation functions in an effort to capture more complex configurations in the data.

This is where now `PCA` comes in. An autoencoder with a single fully connected hidden layer combined with a linear activation function and a squared error cost function is closely allied to classical `PCA`. Essentially, a neural network that is trained to learn the identity function is what an autoencoder actually is since we are not interested in “changing” the data at all, we are simply interested in *reconstructing* it ([Plaut, 2018](#ref.xhtml#re_CIT000290)), such as the example with the phone data being transmitted to the cloud. This sounds very much like `PCA`! Indeed, it can be shown that the subspace formed by the first few components of a `PCA` is near equal to the vectors formed from encoding an autoencoder neural network and the reconstruction error from each is approximately the same ([Oken, 2017](#ref.xhtml#re_CIT000272)). Autoencoders reconstruct the data as efficiently as possible, and hence `PCA` can be regarded as a special case of the more general autoencoder idea. Recall however that `PCA` does not by itself perform dimension reduction. *We do*, by choosing among the components the first few that explain most of the variance. Essentially, an autoencoder multilayer perceptron with one hidden layer of units (a *linear* encoder) implements `PCA`.

`Sparse PCA` has also been proposed (Zou et al., [2004](#ref.xhtml#re_CIT000406)) which seeks to regularize coefficients in the components model by penalization, such as `l1` regularization. As we will briefly discuss in the following chapter, a similar regularization penalty can be adopted in factor analysis as well giving birth to the *sparse factor analysis* model.
