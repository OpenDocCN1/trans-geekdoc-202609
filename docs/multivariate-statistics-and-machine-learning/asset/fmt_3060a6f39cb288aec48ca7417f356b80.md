
# Test Error Estimation and Cross-Validation

The `test error` is the average error that results from using a statistical learning method to predict the response on a new observation – that is, a measurement that was not used in training the method. This definition and the wider concept are critical in evaluating a model. As mentioned, `training error typically underestimates the test error rate`. Estimating test error is not as easy as it sounds, however. Ideally, we would have a designated test set of observations (say, 20–30% of the original data set) that we could directly apply the statistical model to in order to observe how it performs. However, often we do not have such a data set at our disposal and hence a number of 56techniques have been developed to aid in estimating test error by simply using the available training data (e.g., Akaike Information Criterion (AIC)).

For the moment, assume we do have enough data such that we can set aside some of it for empirical cross-validation. There are different approaches that have been developed for cross-validating on the new sample. The `validation set approach` designates a subset or `holdout` of observations on which to test (e.g., 20–30%). `Leave-one-out cross-validation` adopts a similar philosophy but sets aside a single observation to predict and hence can be considered a special case of the validation approach for which `n` = 1. The test observation is (`x` [1], `y` [1]) and is not used in the fitting, so (`y`[1]−`ŷ`[1])² provides an approximately unbiased estimate of the test error. It is unbiased, but highly variable since it is only a single observation. By “highly variable” is implied that if we used a different observation we might get a quite different result. So, we repeat for all observations and thus the leave-one-out estimate for the test mean squared error (MSE) is the average of all `n` test error estimates:

$$CV\_{(n)} = \\frac{1}{n}{\\sum\\limits\_{i = 1}^{n}{MSE\_{i}}}$$

(1.8)

where `MSE` `[i]` is used for quantitative responses (for discrete or categorical responses, other measures of error are typically used). Leave-one-out cross-validation is less biased than the validation set approach. That is, it is less likely to overestimate test error as the validation approach typically will. Also, there is no randomness in this approach as with the validation approach. Since we use all `n`, the idea of random sampling or splitting into arbitrary validation sets does not exist. Yet another approach is that of `k-fold cross-validation`, a kind of compromise between the validation set and leave-one-out approaches. K-fold cross-validation produces “folds” of greater number than `n` = 1 as in the leave-one-out case. Keep in mind that when we examine real data, we do not know the true test MSE, and so we can’t `fully` determine the accuracy of the cross-validation estimate. When performing cross-validation, sometimes we want to know the exact value of the minimum, whereas other times we just want to know which method gives the lowest minimum.

We will revisit cross-validation as we apply it to select methods throughout the book. However, we need to issue an important caveat: the process of cross-validating a model can result in a relatively elaborate exercise of simulating various parameters via `grid searches` and other exploratory visual tools as to seek out and arrive at the “best” model or tuning parameter(s) in terms of minimizing error, but these tools should also be interpreted in conjunction with substantive concerns of the area you are working in. In this way, “fine-tuning” a model is not usually as straightforward as following this or that computational cross-validation “routine” and should be considered in a wider scientific context.

Further, trying `ranges` of tuning parameters via grid searches and varying other settings is often recommended instead of relying too much on one or two parameters exclusively. For example, in methods such as `ridge` and `lasso` regression, good cross-validation often involves grid searches with varying ranges of input parameters to determine the best values to minimize error, not simply one or two values that have been “tuned” on the train data. Our select “snipet” discussions of cross-validation in this book usually simplify this process greatly for the purpose of keeping the treatment brief and space-wise manageable. However, this is in no way meant to suggest the process of cross-validation and arriving at the final model is therefore complete. In actual data analysis, `it may be just the beginning`. It would be a mistake for the reader to assume that because our discussion of cross-validation is brief or often omitted that it is therefore not necessary or important for the 57given method. It most often and surely `is`; however, extensive cross-validating via computational demonstrations would take us far beyond where we want to go in an introductory text that seeks to strike an ideal balance of `theory`, `method`, and `practice`. In many cases, we provide the requisite references to packages where extensive cross-validation direction can be sought out. As mentioned earlier in the book, most software examples in the book are simply meant as “foot in the door” glimpses into the computational aspects and in most cases are meant only to selectively `demonstrate` the technique; these easy demonstrations are not meant to be exhaustive or in any way complete “cookbook” or necessarily thorough or exhaustive steps to conducting any of the analyses.

## 1.24 Monte Carlo Methods

Monte Carlo methods feature the use of repeated iterative sampling facilitated by the computer. Note that we do not `need` the computer to do such sampling but suffice to say that it would be virtually impossible to sample extensively without the convenience of a computer that can easily and very quickly automate such a process. Any time a method features repeated sampling of some kind by computer, it is, by definition, a `Monte Carlo method`. Of course, the evolution of the computer and advanced computing speed has made the idea of resampling relatively easy to implement. It should be noted, however, that despite a Monte Carlo method being advertised as executing `random sampling`, resampling by computer could never `truly` be random. That is, once we have an algorithm choosing the next “random” number, the true randomness idea is forever lost.

One common use of the technique is in estimating the sampling distribution of a statistic, either because the sampling distribution cannot be derived analytically or simply because we want to compare the Monte Carlo method to its analytical counterpart. When we estimate a quantity and its sampling distribution using such methods, it often goes by the name of `bootstrapping`. We survey the bootstrap in the following chapter. The bootstrap is a special case of the more general Monte Carlo method because it features resampling. However, note that bootstrapping is not `equivalent` to the Monte Carlo method.

Monte Carlo methods are also often used to solve complicated optimization problems via randomized algorithms and hence are often employed in statistics and machine learning. Such approaches can also quite easily be used to estimate statistical power against competing alternatives. For a good example of this, see [Rizzo (2019)](#ref.xhtml#re_CIT000303).

## 1.25 Missing Data

Missing data should never be ignored as there is often a reason for the `missingness`. The fact that an individual did not answer a particular question on a survey is not missing data; rather, it is `extremely informative data` and may signal the most important of responses. Perhaps the individual did not want to admit to ever stealing anything? Hence, the question, “Have you ever stolen anything?” is answered by not answering! That is the data that becomes of `most interest`. `Never ignore missing data`. `Instead, get curious as to why it is missing`.
