
To consolidate what the kernel trick does, it is helpful to remember the following:

> *Nonlinearly Separable Data in Original Data Space + Kernel Trick* = *Linearly Separable Data in the Feature Space*144

[Aggarwal (2015)](#ref.xhtml#re_CIT000005) summarizes the kernel trick concisely in the following way in relation to support vector machines; however, the following quote is applicable to a much broader set of statistical and machine learning methods well beyond SVMs:

> The kernel trick leverages the important observation that the SVM formulation can be fully solved in terms of dot products (or similarities) between pairs of data points. One does not need to know the feature values … all computations are performed in the original space and the actual transformation does not need to be known as long as the kernel similarity function is known.

## 2.49.1 When Are Kernel Methods Useful?

Based on the above discussion, it stands to reason that kernels are most useful when dealing with data that are not linearly separable in the data space. If we did not have the kernel trick at our disposal we would need to map the data to higher dimensions of nonlinearity, that is, *enlarge the feature space to account for the complexity of the data*. This can be time-consuming, complicated, and sometimes not even doable. By using a kernel transformation, we do not need to map the data to higher dimensions at all but instead can simply use the kernel trick, which essentially means computing kernels in the *original dimensionality* of the problem instead of trying to enlarge the feature space ourselves. Kernel functions are, in general, and as already emphasized, less concerned about the actual data than they are about how *similar* data points are to each other ([Alpaydin, 2020](#ref.xhtml#re_CIT000009)).

Yet another way of conceptualizing kernels is that they can also be seen as a way to express or “encode” prior knowledge. Consider that if `x[i]` and `x[j]` are similar before applying a function to them, then it will generally imply that functions of those observations, `f(x[i])` and `f(x[j])` are also similar. Indeed, in many procedures, the specifying of the `kernel matrix` is essentially somewhat akin to specifying a kind of “Bayesian” *prior knowledge*.

## 2.50 Systems of Equations

Many problems in statistical modeling at their core reduce to solving systems of linear equations. What is a “system” in this respect? A system is simply a *set of equations* for which we are seeking a solution for the variables that will solve the set of equations *simultaneously*. The idea of a *set* here is, as the reader is already likely familiar, a collection of objects, the objects in this case being *equations*. The solution set for one set of linear equations consisting of two equations will likely be different from the solution set for those same two equations but with a third equation added to the set. Once again, *context matters*.

A simple example will suffice to demonstrate the principle of solving a set of linear equations. Consider the following two linear equations:

$$\\begin{array}{l} {4x\_{1} + 4x\_{2} = 5} \\\\ {2x\_{1} - 4x\_{2} = 1} \\\\ \\end{array}$$

When we plot these two equations, we obtain the linear system depicted in [Figure 2.15](#c2.xhtml#f2.15).145

![Figure 2.15 The solution set to the linear system is where the lines intersect.Return to text.⏎](images/fig2.15.jpg)

*Figure 2.15* The solution set to the linear system is where the lines intersect.[Return to text.⏎](#c2.xhtml#re_f2.15)

The *solution set* is where the *intersection* occurs between the two lines. A system of linear equations such as this can be solved using the technique of *Gaussian elimination*, where the matrix is reduced to what is known as *reduced row-echelon* form which allows one to easily see the solution. We do not review Gaussian elimination here due to space limitations but also because it is not terribly enlightening from an applied statistics point of view.

We can solve systems of linear equations in R quite easily. For example, consider the following two equations set up in R, where first we designate the two coefficients for `x[1]` and `x[2]` on the left-hand side of the equation:

```
> left_matrix <- matrix(c(5, 2, 4, 6), nrow=2)
> left_matrix
```

|  || \[,1\] || \[,2\] |

| --- | --- | --- |

| \[1,\] || 5 || 4 |

| --- | --- | --- |

| \[2,\] || 2 || 6 |

Next, we define the `y` values on the right-hand side:

```
> right_matrix <- matrix(c(35, 36), nrow=2)
> right_matrix
```

|  || \[,1\] |

| --- | --- |

| \[1,\] || 35 |

| --- | --- |

| \[2,\] || 36 |

We next solve the equation:146

```
> solve(left_matrix, right_matrix)
```

|  || \[,1\] |

| --- | --- |

| \[1,\] || 3 |

| --- | --- |

| \[2,\] || 5 |

We can see that the solutions to the linear system are 3 and 5. That is, we have just solved the equations

$$\\begin{array}{l} {5x\_{1} + 4x\_{2} = 35} \\\\ {2x\_{1} + 6x\_{2} = 36} \\\\ \\end{array}$$

for which when we substitute solutions `x[1]` = 3 and `x[2]` = 5 we obtain,

$$\\begin{array}{l} {5\\left( 3 \\right) + 4\\left( 5 \\right) = 35} \\\\ {2\\left( 3 \\right) + 6\\left( 5 \\right) = 36} \\\\ \\end{array}$$

In Python, suppose we want to solve the following system of equations:

`24a + 4b = 35`

`8a + 4b = 94`

```
a = np.array([[24, 4], [8, 4]])
b = np.array([35, 94])
print(np.linalg.solve(a,b))
[-3.6875 30.875 ]
```

The solutions to the above equations are thus −3.6875 and 30.875.

There are a variety of methods useful for solving systems of linear equations, including the *elimination method*, *substitution method*, and *graphical method*. Regression analysis is an example of solving a system of equations when an exact solution is not achievable and hence an *approximation* is required, typically that of ordinary least-squares. The approximation is required as a result of there being too many equations to provide a unique solution. That is, the set of equations is *overdetermined*, meaning that there are too many equations because of the scatter of the data and as such many lines *could* be fit. However, we only wish to fit a single line, and that will mean approximating weights for `β[0]`, the intercept, and `β[1]`, the slope.

Many times when considering systems of equations, some equations will be a consequence of others. That is, one equation may reveal the same *information* as one or more other equations. For example, if two equations are scalar multiples of one another, then one equation, as previously discussed, essentially duplicates the “information” provided by the first. Such can be visually depicted by two lines taking up the same space (i.e., laying on top of each other). As an easy example, consider the following two equations:

$$\\begin{array}{l} {\\,\\,\\,\\,\\, x\_{1} + x\_{2} = y} \\\\ {2x\_{1} + 2x\_{2} = 2y} \\\\ \\end{array}$$

Clearly, the second equation is simply a scalar multiple of the first and as such provides no new “information” to the system. As previously discussed in terms of vectors, the equations are said to be *linearly dependent*.147

Note that we have only surveyed linear equations above. What made them linear was that each term in the equation was raised to no power higher than one. For instance,

`x[1] + x[2] = y`

only featured powers to `x[1]`, `x[2]` and `y` equal to one. In contrast, the following is a *nonlinear* equation because at least one of the terms is raised to an exponent greater than one:

`x[1]² + x[2] = y`

Many times in applied problems, systems of equations are *nonlinear*. *Newton’s method* is a classic algorithm used to solve nonlinear equations. For details, see [Hubbard and Hubbard (2002)](#ref.xhtml#re_CIT000161).
