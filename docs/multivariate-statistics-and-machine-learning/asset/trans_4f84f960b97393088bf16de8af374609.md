
大多数聚类都围绕 *不相似性度量* 的概念展开。对于某些类型的聚类，不相似性或相似性是明确定义的，而对于其他聚类方法，如混合模型，距离度量通常由聚类执行的方式隐含。如果数据是 *定性* 而非 *定量*，则无法计算数学距离，需要用某种相似性度量来代替 ([Xu & Tian, 2015](#ref.xhtml#re_CIT000396))。

在数学中，不相似性系数 `d` 可能是对称的，意味着 `d(A, B)` = `d(B, A)`，并且是非负的，即 `d(A, A)` = 0。我们也可以很容易地从不相似性度量推导出，对于点 `A`、`B`、`C`，其中 `B` 位于 `A` 和 `C` 之间，

`d(A,C) ≤ d(A,B) + d(B,C)`

(14.1)

我们也可以将 `d(A,B)` 表示为 *超度量*，501

`d(A,B) ≤ max(d(A,C),d(B,C))`

(14.2)

其中 `A`、`B`、`C` 也可以被视为包含点的簇。超度量规定簇 `A` 与 `B` 之间的距离小于或等于簇 `A` 与 `C` 中点之间的最大距离，或簇 `B` 与 `C` 中点之间的最大距离。[Venables and Ripley (2002)](#ref.xhtml#re_CIT000376) 指出，聚类分析的层次方法在很大程度上可以解释为最终近似于超度量不相似性。的确，Simovici 和 Hua ([2019](#ref.xhtml#re_CIT000338)) 发现，不相似性空间（经验上是数据集）越接近超度量，其可聚类性越强。

## 14.4 关联规则：市场篮子分析

关联规则是一种相对原始的聚类方式。*关联规则* 分析背后的思想，也常被称为 *市场篮子分析*（因为它常用于产品的营销分析），不出所料，是为了寻找变量之间的关联，通常是二元变量 ([Hastie et al., 2009](#ref.xhtml#re_CIT000145))。大量的关联规则分析归结为熟悉的 *条件概率* 概念，即概率 `p(y|x)`，其中 `y` 是被购买的商品，但条件于产品 `x`。例如，我们可能想知道客户在刚购买台式电脑后购买电脑显示器的概率，或在刚购买新电视后购买电视架的概率。许多关联分析算法归结为寻找数据中的众数或所谓的“凸起”，其中原型 `x` 值的集合与概率密度相关（即“凸起”）。

更正式地说，关联分析寻求找到 `x` 上变量子集的 *交集*，即如下类型的重叠空间

$$p\\left\\lbrack {\\underset{j = 1}{\\overset{p}{\\cap}}\\left( x\_{j} \\in s\_{j} \\right)} \\right\\rbrack$$

其中此类子集的交集被称为 *合取规则* ([Hastie et al., 2009](#ref.xhtml#re_CIT000145))。这些子集自然出现在定性变量中，而对于定量变量，子集 `s[j]` 由某个连续体上的区间组成。

聚类关联规则也已被提出，其基本目的是将关联规则本身分组到类别中，而不是通过多个单独的规则进行操作 (Lent et al., [1997](#ref.xhtml#re_CIT000217))。关联规则的现代起源可追溯至 Agrawal et al. ([1993](#ref.xhtml#re_CIT000006))，他们提供了对该主题高度可读且强烈推荐的介绍。R 语言中的包 `arules` ([Hahsler et al., 2024](#ref.xhtml#re_CIT000139)) 可用于挖掘关联规则。有关市场分析的更多细节，请参阅 [Aggarwal (2015)](#ref.xhtml#re_CIT000005)。

## 14.5 为什么不考虑所有组？

聚类分析 *算法* 研究中首先出现的问题是，为什么不查看案例的 *所有组*，然后通过某种度量决定哪一个最优？例如，在考虑从三个可用对象中选择两个对象的可能聚类时，不去简单考虑简单组合问题 *3选2* 的所有可能性，即等于 3，是愚蠢的。的确乍一看，使用来自聚类组合范式的组合算法似乎是显而易见的选择，即简单地枚举所有可能性并选择使某个目标函数最大化或最小化的解。也就是说，以此意义上选择“最佳”聚类，然后完成任务。502

虽然上述解决方案对于非常小的数据集是高度推荐的，但对于任何中等规模的数据集，它将是无效的或不切实际的。其原因在于，将 `n` 个案例划分为 `g` 个簇的方式数量 literally 巨大，可以证明等于

$$N\\left( n,g \\right) = \\frac{1}{g!}{\\sum\\limits\_{k = 1}^{g}\\left( \\begin{array}{l} g \\\\ k \\\\ \\end{array} \\right)}\\left( - 1 \\right)^{g - k}k^{n}$$

(14.3)

更简洁地说，该数量也可以相当好地近似为 `g^(n)/g!`。这种方法有时被称为 *大锤* 方法。不仅从实质观点来看该方法不切实际，而且从计算角度来看也是绝对禁止的，因为评估这种庞大的组合数量需要巨大的计算时间和资源。虽然较小的数据集永远不会遇到这些能力上限，但越来越大的数据集会遇到，而且鉴于大数据时代今天可以聚类的海量数据，计算能力在决定如何聚类时成为决定性和有影响力的因素。一个好的算法不仅仅是聚类良好的算法；它还必须是 *计算高效* 的。

因此，需要的是在某种意义上高效地将案例分组的 *方法*，而无需搜索每一种可能的组合模式。也就是说，我们需要考虑或假设一个更小的 *枚举可能性* 集合。这正是聚类分析算法存在的确切原因。算法旨在划分案例，使数学上有意义的组出现，这些组可能同时具有实质意义（即用户和研究社区可以“理解”聚类可能代表什么）。然而好的算法并不考虑所有可能的分组；它们只考虑 *最佳* 的分组，在最 *高效*、*创造性* 和 *贪婪* 的生成此类分组的方式意义上，其中“贪婪”意味着许多算法考虑的是“现在这里”最好，而不是两三步之后的最好。举例来说，足够让你头晕的胡萝卜蛋糕现在听起来 *很棒*，而完全没有考虑几个小时后你会感觉如何。
