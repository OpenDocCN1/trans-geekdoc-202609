
As was the case for classic PCA, the goal in kernel PCA will be to minimize the reconstruction error. It should make sense as to why this goal has not changed when moving from classical PCA to kernelized PCA; both methods are essentially doing the same thing, but simply on different transformations of the variables and data. At first glance, it may appear that enlarging the feature space would *increase* the dimensionality in which we need to compute. However, contrary to what we may expect, this is not what occurs, thanks again to the *kernel trick*. As we have emphasized, due to the kernel trick, we will not actually have to do any calculations in the higher-dimensional feature space. *Computation of kernels occurs in the original lower-dimensional space of the data*. As summarized by Hastie et al. ([2009, p. 547](#ref.xhtml#re_CIT000145)):421

> Kernel PCA expands the scope of PCA, mimicking what we would obtain if we were to expand the features by non-linear transformations, and then apply PCA in this transformed feature space.

To add to all this, the higher-dimensional space could very well turn out to be *infinite dimensional*. This is why it’s called a “trick,” because we can simply compute kernels in lower dimensions and learn something of the higher dimensions without actually doing complex computations in higher dimensions. By analogy, it would be somewhat like being able to add two numbers, a very simple operation, to learn more about how the numbers relate in very complex ways (e.g., whether the distance between the numbers is a prime number). *The kernel trick allows for a simple computation to represent a much more complex reality or “space” behind those numbers*. Inexact analogy to be sure, but approximates the idea somewhat in spirit. The takeaway message is that the kernel trick is a *big deal* in statistics and machine learning.

### 11.6.5 The Matrices of Kernel PCA

Mathematically, kernel PCA relies on the fact that principal components can be obtained from a data matrix `X` by computing inner products of that data matrix,

`K = X X^(T)`

(11.9)

Eigen analysis is then performed on the double-centered version of `K`, where `K̃` is now equal to

`K[c] = (I - M) K (I - M)`

(11.10)

and where `M = 11^(T)/N` which serves to center `K` ([Hastie et al., 2009](#ref.xhtml#re_CIT000145), p. 547). That is, we are computing a kernel matrix `K̃` that contains all pairwise dot products between data points. The double-centering here ensures the mean of every row and column is equal to 0. Whereas classical PCA uses the covariance matrix and scales regarding the number of input dimensions, kernel PCA scales with respect to the number of *data points* rather than dimensions in that the eigen analysis occurs on the `K̃` matrix and not the covariance matrix as in PCA.

As is true when using kernels, a variety of kernels are available, such as the *radial kernel* and others. However, the choice of kernel is critical, and the expression “*what you find is a function of what you put in*” is very relevant here; one kernel over another can drastically generate different findings (for an example of this, see Hastie et al., [2009](#ref.xhtml#re_CIT000145), p. 549). What does the eigen problem look like? Recall classic eigen decomposition:

`A x = λ x`

For kernel PCA, `A` is now the kernel matrix `K̃`, and by simple substitution ([Bishop, 2006](#ref.xhtml#re_CIT000032), p. 588) the eigenvalue problem becomes,

`A x = λ x → K̃ x = λ N x`

(11.11)

or as simply422

`K̃ x = λ̃ x`

if `λ̃ = λ N` ([Izenman, 2008](#ref.xhtml#re_CIT000167), p. 611). Note that we are performing eigen analysis on the `K̃` matrix and not the covariance or correlation matrix as in traditional PCA ([Bishop, 2006](#ref.xhtml#re_CIT000032)). Once we have the eigenvalues and eigenvectors, we can now project the data onto each new dimension.

> *Kernel PCA can be conceptualized as an “ordinary” PCA, but instead of weighted by input variables by values of the eigenvector, it is the kernel of the data points that is weighted by values of the eigenvector. Hence, `KPCA` simply replaces the variables (dimensions) with the kernel of observations, so that the kernel trick can “do its magic.”*

### 11.6.6 Classical PCA as a Special Case of Kernel PCA

We have seen that kernel PCA allows for nonlinearity. Hence, it stands that with some constraints imposed, classical linear PCA should be able to be obtained and operationalized as a *special case* of kernel PCA. Indeed, it should be evident from our earlier discussion that classical PCA must simply be a special case of `KPCA` ([Bishop, 2006](#ref.xhtml#re_CIT000032), p. 589) in which the *kernel is the linear kernel*. This is powerful insight. *In general, many linear methods can be regarded as special cases of a more general nonlinear framework*. The set of nonlinear statistical “possibilities” is much wider than the smaller set of linear models, and hence linear methods are a subset of that wider set, not only in the case of kernel PCA in relation to PCA but for most statistical methods in general.

### 11.6.7 Kernel Trick Is Not Simply about Cost

The kernel trick is useful since it saves on computational cost in accessing the higher-dimensional feature space. However, it should be emphasized that that is not the only reason for its utility. The primary benefit to using kernel methods is not only as a way around computational complexity. To reiterate, *the kernel trick allows us to work in higher dimensions without knowing the specific details of that dimensionality. That is its key benefit*. Hence, though often kernel methods in general are advertised or evaluated for their computational properties in “accessing” higher dimensionality, applying kernel methods in general is far from simply a way to ease computation. Even if the computations are laborious, which they can be in computing dot products of large matrices, kernel methods are useful since they allow access to those higher dimensions in the first place. *In general, kernel methods allow access to higher dimensionality while working in lower dimensions, often all for a more reasonable computational cost than if we were to access those higher dimensions directly.*
