
As we have seen, classical or “standard” principal components analysis allows for linear dimensionality reduction. However, we must ask the question of how often the true dimensionality of the variables or data lies in a subspace that is precisely linear. Probably not that often just as most data subjected to regression models are hardly linear, which is why techniques such as polynomial regression, splines, and other nonlinear and nonparametric approaches were surveyed earlier in the book. Though linearity is a useful *approximation* for dimension reduction, the true underlying dimensionality of most sets of variables is probably *nonlinear*. That is, the true manifold is likely, in the end, a *nonlinear* structure, not a linear one. We emphasize again that the linear vs. nonlinear underlying dimensionality always refers only to the set of variables you are working with and have included in your set of chosen variables. Dimension analysis, as is the case with any mathematical technique, can only operate on the set of variables you have subjected to analysis. All analyses are on what might be called *restricted universes* of variables and their respective interrelationships. This seems like an obvious point to make, but is one worth emphasizing: *a PCA, or any statistical method can only provide results on the variables on which it is analyzed! If you leave out important variables, your entire analysis will be misspecified. What you “find” is entirely related to what you supply the “machine” doing the searching. All is context-dependent all of the time.*

*Kernel principal components analysis* (KPCA) allows one to generalize standard PCA to *nonlinear dimensionality reduction*. As we will see, it is one of many nonlinear options to choose from when it comes to uncovering nonlinear dimensions.

## 11.6.2 How KPCA Works

Recall that the big idea of using kernel methods in general, not just for PCA (but for example, support vector machines), is that data that may not be separable in its current feature space may benefit from being projected into higher dimensions. For example, instead of having variables `x[1]` and `x[2]` only, an enlargement of the feature space might be `x[1]`, `x[2]`, `x[1]²`, `x[2]²`. *This enlargement of the feature space makes the data more linearly separable*. This is the very essence of what kernel methods, and kernel PCA in particular, seek to accomplish. Through the calculation of a kernel, we can then apply PCA in higher-dimensional space without ever having to really go there. When you think about it, this is truly a marvel! Indeed, kernel methods can be applied to many algorithms that can be formulated in terms of inner products in the feature space.

> *By projecting data that is nonlinear into higher-dimensional space, we make otherwise nonlinear data in the data space more linearly separable in the feature space. This is the essence of how kernel PCA (and other kernel methods) work.*

To further unpack how kernel PCA may be useful, consider Figure 11.7 consisting of data in two dimensions. Clearly, the data are not linearly separable. That is, we cannot draw a line through the data to separate the circles from the crosses. A more complex decision surface would provide much better separability. ## 11.6.3 Kernelizing and Computational Complexity

There is another benefit to kernelizing. When we move from two dimensions to three, or, more generally, from lower dimensions to higher, such can seriously increase computation time. For smaller problems, this is usually not a problem, but for larger dimensionality tasks it becomes prohibitive. Hence, an immediate problem with high dimensionality is that of *computational complexity*. We would like to get around this problem and still capitalize on the benefits of working in higher-dimensional feature space. If we can compute in lower-dimensional space but actually work in higher-dimensional space, such would be ideal. This is precisely what the kernel trick allows us to do in terms of facilitating computation. That is, we can take advantage of higher-dimensional representations *without having to actually work in those higher configurations*. Instead, we can remain in lower dimensions and nonetheless conduct our analyses there. This is accomplished by computing *kernels*, which even though computed in lower dimensions, contain information about higher-dimensional representation.

The above result is due to *Mercer’s theorem*, which the reader may recall was discussed earlier in the book in relation to support vector machines. In brief, *the computational complexity of kernel PCA does not one-to-one increase with the dimensionality of the feature space* (Schölkopf et al., [1998](#ref.xhtml#re_CIT000327), p. 4), and so even if we are working in very high-dimensional space theoretically, the computational complexity can be “tamed” somewhat by computing in a lower-dimensional space. This is thanks to the fact that we can compute kernels to represent this higher-dimensional inner product (Hilbert) space, and the fact that kernels are relatively simple to compute. Again, kernelizing is a marvel!

What is more, with kernel PCA no nonlinear optimization is involved. We can simply solve an eigenvalue-eigenvector problem as we would in traditional PCA *but now on the kernelized data*. The benefit of this is that getting “stuck” in local optima, in this case, *minimums*, is not a problem as it might be using other nonlinear methods. That is, *global optima* can be attained in kernel PCA ([Belkin & Niyogi, 2003](#ref.xhtml#re_CIT000026), p. 1374). Clearly, kernel PCA has computational benefits to employing direct nonlinear methodologies.

> *The kernel trick allows us to work and compute in lower dimensions but benefit from higher-dimensional representation. The advantage of this is to both account for potential nonlinearity in the data but also to simplify computation time since we do not have to actually access the higher-dimensional space or surfaces in order to account for it. This is more generally known as the “kernel trick” and is due to Mercer’s theorem.*
