
We might ask then whether there is a *general approach*, aside from trying different polynomials, to enlarging the feature space that will also lead to efficient computations. It turns out there is, one for which we are already familiar, and involves computing *kernels* in the data or variable space instead of directly choosing among a variety of basis functions such as polynomials. What is more, *knowledge of inner products of observations is often just as useful as knowing the observations themselves*. These results are significant, if not rather extraordinary and extremely convenient, because they suggest we can use kernels in the original data or variable space to account for *potentially nonlinear feature spaces* instead of attempting to take polynomials and higher powers in the original space.

As we have seen earlier with regard to kernels, when we *kernelize* data in the input space, such says something about the similarity of observations in a higher-dimensional space by way of inner products in that higher-dimensional feature space. That is, *taking the kernel* *K*(*x*[*i*],*x*[*i*′]) *of observations* *x*[*i*], *x*[*i*′] *in the input space essentially makes the nonlinear problem in data space now potentially linear in the higher-dimensional feature space*. Said differently, *a kernel quantifies the similarity between two observations and, in generalizing from an inner product to a kernel function, essentially “hides away” the nonlinear feature map* (Deisenroth et al., [2020](#ref.xhtml#re_CIT000080)).

As already discussed elsewhere in this book, there are many kinds of kernels, but they all essentially seek to account for *similarity* in some sense. The most obvious case for taking the kernel is to use a *linear kernel*:363

$$K\\left( x\_{i},x\_{i'} \\right) = {\\sum\\limits\_{j = 1}^{p}{x\_{ij}x\_{i'j}}}$$  
(9.11)

Notice that the linear kernel is the same as simply taking the inner product on its own, and it can be shown that the above plays a key role in the Pearson correlation coefficient between observations. This isn’t surprising since recall that the numerator of Pearson, in part, features

$$\\left. {\\sum\\limits\_{i = 1}^{n}\\left( x\_{i} - \\overline{x} \\right.} \\right)\\left( y\_{i} - \\overline{y} \\right)$$  
and will be easily recognized as an inner product of deviations from respective means.

Of course, computing the linear kernel is not very climactic. The generality, however, of taking kernels is the option of being able to try out a variety of kernels (e.g., *polynomial kernel*, *radial basis function kernel*, *sigmoid kernel*, etc.), not only the linear kernel ([Cortes & Vapnik, 1995](#ref.xhtml#re_CIT000068)).

Kernels are not in any way new in linear algebra. Much of the theoretical work on kernels in mathematics took place in the early 1900s. Kernel functions as inner products were first introduced into machine learning by Aizerman et al. ([1964](#ref.xhtml#re_CIT000007)) and were first applied to support vector machines by [Cortes and Vapnik (1995)](#ref.xhtml#re_CIT000068). However, it should be emphasized that the kernel property itself is in no way *unique* to support vector machines, as Hastie et al. ([2009, p. 424](#ref.xhtml#re_CIT000145)) emphasize:

> In the early literature on support vectors, there were claims that the kernel property of the support vector machine is unique to it and allows one to finesse the curse of dimensionality. Neither of these claims is true.

Hence, as we have noted elsewhere in the book, kernels can be applied quite widely and generally to different methods. Support vector machines do not have a “monopoly” on their utility or application. Many statistical and machine learning methods can be *kernelized* and kernels are undoubtedly one of the hallmarks of modern machine learning in general.

### 9.4.2 Support Vector Machines in Python

As we have discussed in this chapter, a support vector machine can be used for a linear boundary or one that is nonlinear. The following is sample code from `sklearn` for a simple support vector machine (*classifier*) in Python:

```
from sklearn import svm
```

We will next define some data on `X`:

```
X = [[0, 0], [1, 1]]
X
Out[41]: [[0, 0], [1, 1]]
```

We next define the categories on the response variable `y`:

```
y = [0, 1]
```

Note that we could have used any values for y, it was not necessary to use 0, 1. Next, we fit the `SVM` using a *radial basis function* (`kernel = "rbf"`) with a regularization penalty of `C = 100`:364

```
clf = svm.SVC(kernel = “rbf”, C=100)
clf.fit(X, y)
Out[44]: SVC()
```

Now, for values on `X`, we ask the support vector classifier (`SVC`) to make predictions on the response class:

```
clf.predict([[2., 2.]])
Out[45]: array([1])
clf.predict([[2., 0.]])
Out[46]: array([1])
clf.predict([[0., 0.]])
Out[47]: array([0])
```

We can see the predicted group membership for 2, 2, is 1, for 2, 0 is 1, and for 0, 0 is 0. We can identify the actual support vectors through `clf.support_vectors_`:

```
clf.support_vectors_
Out[160]:
array([[0., 0.],
      [1., 1.]])
```

For boundaries that are linear, one can also use `LinearSVC`.

### 9.4.3 Support Vector Machines in R

We can fit a support vector machine in R using the `e1071` package (Meyer et al., [2023](#ref.xhtml#re_CIT000251)). We adopt and explain the code from the package on the `iris` data to demonstrate the application of a simple support vector machine:

```
> library(e1071)
> data(iris)
> attach(iris)
> x <- subset(iris, select = -Species)
> y <- Species
```

Note that we have designated species to have its own `y` vector and removed species from the `iris` data (`select = -Species`) calling the new vector `x`. We now run the `model` (`scale = FALSE` if you do not wish to standardize):
