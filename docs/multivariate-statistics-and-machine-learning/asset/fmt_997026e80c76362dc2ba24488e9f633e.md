
$$\\begin{array}{l} {d\_{E}\\left( x,\\mu \\right) = \\sqrt{\\left( x - \\mu \\right)^{T}I\\left( x - \\mu \\right)}} \\\\ {\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\,\\, = \\sqrt{\\left( x - \\mu \\right)^{T}\\left( x - \\mu \\right)}} \\\\ \\end{array}$$

(8.44)

The default distance metric for `KNN` methods is that of Euclidean; however, `KNN` is actually compatible with a number of distance metrics. If using a more complex metric such as Mahalanobis, the computational expense increases significantly. It should be emphasized that like in multidimensional scaling, as we will later see, there is no “correct” choice of distance measure in `KNN`; sometimes a variety of measures need to be tried and sometimes the decision is more problem-dependent. Many of the distance measures used for `KNN` are those used in clustering algorithms and in addition to the classic Euclidean distance also include the `Manhattan` and `Minkowski` distances. The `Hamming distance` can also be used, which is simply the Manhattan distance applied to binary features.348

To speed up `KNN` algorithms, a variety of so-called “pruning” techniques can also be used, such as removing outliers so the algorithm does not have to incorporate such extreme observations in determining its classification. This is sometimes referred to as `KNN editing`.

### 8.18.3 Disadvantages of KNN

At first glance, `KNN` can seem like an ideal and excellent classifier. It is simple, intuitive, and in actuality classifies relatively close to the ideal and most perfect classifier, which is Bayes. Remember, Bayes is best! Or once more, as [Cover and Hart (1967)](#ref.xhtml#re_CIT000070) put it, “The Bayes risk serves merely as a reference – the limit of excellence beyond which it is not possible to go” (p. 23). That is, we cannot do “better” than the Bayes risk, and `KNN` does a reasonably good job at approximating the accuracy of this “ideal” classifier.

So why not use `KNN` all the time? The problem is that discussed at the outset of this book, which is the `curse of dimensionality`. Briefly, as the number of dimensions in the data increases, the “nearest neighbor” ends up being a point that is quite distant, and hence using such points to determine the classification of the current point will likely be deficient. In other words, that “distant” point is not really a “nearest neighbor” other than simply by mathematical definition. It would be like if your neighbor lived on Mars; they may still be your nearest neighbor, but they are a planet away! More technically, the volume of the space we are working in grows exponentially with dimensionality ([Hastie et al., 2009](#ref.xhtml#re_CIT000145)), so unless we have the sample size to fill that volume of widening space, dimensionality will be a problem. This drawback then is one motivating factor for introducing a parametric model, that is, a model that comes “pre-packaged” with assumptions. The parametric model will make assumptions underlying the data so that the curse of dimensionality is less problematic (Murray, 2022).

> KNN, at first glance and due to its simplicity, can appear to be an excellent classifier. However, due to the curse of dimensionality, the “nearest neighbor” will often end up being a point that is quite distant. The solution to this problem, aside from possibly greatly increasing sample size, is often to introduce a parametric model, that is, one that comes with it prior assumptions about the form of the relationship.

Another possibility and solution to the problem of dimensionality is to simply locate a smaller set of the observations in higher dimensions and make classification decisions more locally. We can easily see as well that the nearest-neighbor approach is quite sensitive to random perturbations in the data. That is, it has `high variance`. This can easily be appreciated by inspecting the aforementioned `Voronoi tessellation` of points ([Figure 8.10](#c8.xhtml#f8.10)). Note that by moving just a single point significantly, we can drastically change the classification status for that point, since its new nearest neighbor now is a different neighbor. The `KNN` method often has more variance associated with it than it has bias in the classic `bias-variance trade-off` paradigm.

How can we make data points a bit less sensitive to nearby data points? We can do so by regularizing the approach, which in this case means simply introducing more neighbors, that is, increasing `k`. For example, increasing `k` = 2 to `k` = 5 means that instead of looking at the closest 2 nearest neighbors, we will instead consider the closest 5. It is plausible that this will reduce variance but at an increase in bias. In this case, we are essentially `smoothing` our classification process.349

Computationally, `KNN` also needs to store all of the data so that it can draw on such data to make each classification. As Murray (2022) remarks, this is not a very efficient use of memory, and hence the `KNN` approach for large sample size can be relatively slow. Consequently, `KNN` is not best used when you have a lot of features ([Müller & Guido, 2017](#ref.xhtml#re_CIT000258)). An alternative approach, which is still nonparametric, but which overcomes this memory issue, is that of the `sparse kernel machine`, which only considers a subset of the data in making its classification decisions. This technique also capitalizes on the `kernel trick`, which is a nonparametric approach.

`KNN` can be performed in Python using `KNeighborsClassifier`. The packages `neighbr` ([Bolotov, 2020](#ref.xhtml#re_CIT000040)) and `caret` ([Kuhn](#ref.xhtml#re_CIT000209) et al., 2024) can be used to perform `k`-nearest neighbors. The caret package includes cross-validation techniques for selecting the best number for `k` to maximize accuracy.
