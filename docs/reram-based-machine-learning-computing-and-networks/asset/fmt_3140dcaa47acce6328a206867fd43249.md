
# TNN Mapping on 3D Multilayer CMOS-ReRAM Accelerator

To fully map TNN on the 3D multilayer CMOS-ReRAM accelerator, the CMOS logic needs to be designed mainly for logic control and synchronization using a top-level state machine. It prepares the input data for computing cores, monitors the states of ReRAM logic computation, and determines the computation layer of the neural network. [Figure 6.22](#Chapter6.html#c06_fig22) shows the detailed mapping of the TNN on the proposed 3D multilayer CMOS-ReRAM accelerator. This is a folded architecture utilizing the sequential operation of each layer in the neural network. The testing data will be collected from ReRAM memory through-silicon via (TSV) and then sent into the vector core to perform vector–matrix multiplication through highly parallel processing elements in the ReRAM layer. The ReRAM layer has many distributed ReRAM-crossbar structures to perform multiplication in parallel. Then, the computed output from ReRAM will be transferred to the scalar core to perform accumulations. The scalar core can perform addition, subtraction, and comparisons. Then, the output from the scalar core will be sent to the sigmoid function model for the activation matrix in a pipelined fashion, which performs the computation of (4.4). The activation matrix will be used for the next layer computation. As a result, the whole TNN inference process can be mapped to the 3D multilayer CMOS-ReRAM accelerator.

![Figure 6.22 Data control and synchronization on the layer of CMOS with highly parallel ReRAM-based processing elements](images/PBPC0390-06-f22.jpg)

In addition, to support TNN on ReRAM computation, a dedicated index LUT is needed. Since the weight matrix is actually folded into a high-dimensional tensor as shown in Figure 4.8, a correct index selection function called a bijective function is designed. The bijective function for the weight matrix index is also performed by the CMOS layer. Based on the top state diagram, it will choose the correct slice of the tensor core by determining the index. Then, the correct ReRAM-crossbar area will be activated to perform vector–matrix multiplication.

## ReRAM Layer Accelerator

In the ReRAM layer, this section presents the design of the ReRAM layer accelerator for highly parallel computation using the single instruction multiple data (SIMD) method to support data parallelism.

### Highly Parallel TNN Accelerator on the ReRAM Layer

The TNN accelerator has to be designed to support highly parallel tensor-train-matrix-by-vector multiplication by utilizing the associative principle of matrix product. According to (4.28), the core tensor needs to be multiplied by multiple matrices unlike the general neural network. As a result, if traditional matrix–vector multiplication in serial is applied, data need to be stored in the ReRAM array for multiple times, which is time-consuming. Since the size of tensor cores in the TNN is much smaller than the weights in the general neural network, multiple matrix–vector multiplication engines can be placed in the ReRAM logic layer. When the input data are loaded, the index of the core tensor can be known. For instance, one needs to compute the intermediate result given the input for the summation in (4.28). The core tensors in (4.28) can be precomputed in a parallel fashion before the input data are loaded.

As shown in [Figure 6.23](#Chapter6.html#c06_fig23), the tensor cores (TC1-6) are stored in the ReRAM logic layer. When the input data arrive, the index of each tensor core is loaded by the logic layer controllers first. The controller will write the corresponding data from the tensor cores to ReRAM cells. As a result, the matrix–vector multiplication of the core tensors can be performed in parallel to calculate the intermediate matrices while the final core is in the loading process. After all the intermediate matrices are obtained, they can be multiplied by the final core so that the operations in the ReRAM logic layer can be efficient.

### Highly Parallel Dot-Product Engine on the ReRAM Layer

We further develop the digitalized ReRAM-based dot-product engine on the ReRAM layer. The tensor-train-matrix-by-vector operation can be efficiently accelerated by the fast dot-product engine on the ReRAM layer, as shown in [Figure 6.23](#Chapter6.html#c06_fig23)(b). By taking the correct index of cores, each operation can be divided into a vector-vector dot product operation. Here, we design the dot-product engine based on [237]. The output matrix is `C`, with input matrices `A` and `B` for better understanding. The overall equation is `C = A * B` with dimensions `M x N`, `M x K`, and `K x N`. For every element in `C`, it follows:

`C[i][j] = sum(A[i][k] * B[k][j])`

where `A[i][k]` and `B[k][j]` are the elements in `A` and `B`, respectively. The basic idea of implementation is to split the matrix–vector multiplication into multiple inner-product operations of two vectors `a` and `b`. Such multiplication can be expressed in binary multiplication by adopting fixed-point representation of `a` and `b`:

`Result = sum(a_bit[m] * b_bit[n] * 2^(m+n))`

where `R_accel` is the accelerated result from the ReRAM crossbar. `a_bit[m]` is the binary bit of `a` with `M` bit-width and `b_bit[n]` is the binary bit of `b` with `N` bit-width. As mentioned above, bit-width `M` and `N` are decided during the algorithm-level optimization. The matrix–vector multiplication based on (22) can be summarized in four steps on the ReRAM layer.

**Step 1: Index Bijection**: Select the correct slice of tensor cores `G_core`, where a pair of indices `(i, j)` determines a slice from `G_core`. In the current example, the indices `i_sel` and `j_sel` represent two selected slices from cores `TC1` and `TC2`.

**Step 2: Parallel Digitizing**: It requires an `N x M` ReRAM crossbar. Each inner product is produced by the ReRAM crossbar as shown in [Figure 6.23](#Chapter6.html#c06_fig23)(c). `a_vec` is set as crossbar input and `b_mat` is written in ReRAM cells. In the `N x M` ReRAM crossbar, resistance of ReRAMs in each column are the same, but the `k-th` among columns are different. As a result, the output of each column mainly depends on ladder-like threshold voltages `V_th`. If the inner-product result is `IP_res`, the output of step 1 is like `Out_vec`, where `Out_vec[i]` and `Out_vec[j]`.
