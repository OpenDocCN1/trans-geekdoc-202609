In the room example, the two roles participating in the conceptual join are both mandatory for the join object type (Room). This ensures that the conceptual join is an inner join. However, if one or more roles involved in the conceptual join is optional, the use of an external uniqueness constraint needs special care. The ORM schema in Fig. 10.2(a) is a fragment of an ORM metaschema. ORM requires each predicate to have at least one reading, but it is optional whether roles are given names. In the figure, the role played by RoleName is named “name”, but the other roles are not named. The external uniqueness constraint indicates that role names are unique within a given predicate. A predicate may have many unnamed roles, but if a role is named it can be identified by the combination of its name and its predicate.

This situation requires an inner join interpretation for the join path underlying the external uniqueness constraint.
