# FIG. 9.61 Step 4: Map an n-ary fact type to association classes or coreferenced classes.

If an object type in a ternary fact type should not map to a class (typically an m:n:1 uniqueness pattern with it outside the uniqueness constraint), then objectify the rest of the association as an association class, and map its role as an attribute. Fig. 9.61(b) shows an example. A less preferable alternative is to use a coreferenced class instead of an association class, as in Fig. 9.61(c).

Objectified associations map to association classes, as shown earlier in Fig. 9.18. Some cases of coreference could be mapped into qualified associations, but mapping to separate attributes or associations supplemented by a textual composite uniqueness constraint offers a more general solution.

In step 5, the simplest constraints in ORM usually map in an obvious way to multiplicity constraints, as illustrated earlier. The more complex ORM constraints have no graphic counterpart in UML, so you need to record these separately in textual form. Table 9.4 summarizes the main correspondences. Join constraints are considered in the next chapter.
