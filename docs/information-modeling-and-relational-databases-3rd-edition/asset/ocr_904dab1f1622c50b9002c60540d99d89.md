As a hint, *if you need to relate different rows of the same table, then a self-join is needed.* Also, recall that table aliases are required to join a table to itself.

The solution is shown in Fig. 12.29. First, we define two aliases, “Speaks1” and “Speaks2” for the Speaks table. You can think of this as two different copies of the table, as shown. By using the original table name, we could get by with only one alias. Check to make sure that you understand the solution. Notice that we should not use the natural join for this query (why?).

The query of Fig. 12.29 could use “>” or “<>” instead of “<”. However, “<” nicely arranges for the first name of each pair to be alphabetically prior to the second name. Moreover, “<>” is inadvisable because it would result in each pair being listed twice, once for each order (recall our earlier example about drinkers and smokers).
