In step 6, subtypes are mapped to subtypes, adding relevant constraints if needed. Subtype definitions are handled with discriminators and/or textual constraints. If needed, introduce an “Other” subtype to complete a partition. If needed, use multiple diagrams (e.g., when multiple categorization schemes apply to the same supertype). Fig. 8.50 shows a simple example. The braced value constraint and footnoted constraints are not part of the Barker ER notation.

In step 7, we map derived and semiderived fact types. Industrial ER typically has no graphical support for derivation, so the derivation rules are captured as textual notes. Fig. 8.51 provides a simple example. With these few hints, and the examples discussed, you should have enough background to do the mapping manually. The mapping procedure is fairly boring and is best automated with a CASE tool.
