In Australia, pieces of lumber have their longest length specified in meters, but their breadth and depth are measured in millimeters. Because this is a standard in the Australian building industry, a report on lumber sizes might look like Table 5.11. Suppose we want to compare the different linear measurements (e.g., Which sizes of lumber are 20 times as long as their breadth?) or compute volumes in standard units (e.g., What is the volume of lumber size C7 in cubic meters?). FIG. 5.30 Derived units are based on a standard unit.

The asterisk “*” after “(mm:)” indicates that millimeter (mm) is a derived unit, unlike meter (m), which is a standard unit. Fig. 5.30(b) displays the expanded form of the unit reference modes, with each unit based on the same unit dimension (Length). It also shows the conversion rule between the units, with the derived unit on the left of the “=” sign. We use the term “dimension” to include derived dimensions (e.g., Volume = Length³). Both sides of a conversion rule equation must have the same dimension (e.g., Length) or dimension expression (e.g., Mass/Volume).

Many units might be used for the same physical quantity. To reduce the number of conversion rules, we choose a standard unit and just supply rules to convert to this standard (rather than supply conversions between each unit pair).

ORM 2 regards object types with the same unit-based reference mode to be compatible. So, if Length and Pressure occur in the same model, it would be incorrect to use the reference schemes Length(mm:) and Pressure(mm:) because this implies that Length and Pressure are based on the same semantic domain. To avoid this problem, we need to rename one of the reference modes, for example, Pressure (mmHg:).
