assumption. OWL Lite and OWL DL are based on description logics that lie in a decidable fragment of first-order logic that is efficient to compute. OWL Full has the same looseness as RDFS.

In 2009, a major upgrade to the OWL language, known as OWL 2, was recommended by the W3C. In 2012, a second edition of OWL 2 was recommended, and is still the current version (see https://www.w3.org/TR/owl-overview/). OWL 2 can express most aspects of ORM models, but it is not rich enough to capture several ORM features, such as set-comparison constraints involving multirole arguments, acyclic ring constraints, and deontic constraints.

OWL models may be expressed textually in various syntaxes (e.g., RDF/XML, OWL/XML, Manchester syntax, Functional syntax, and Turtle) but lacks a graphic notation. To fully exploit OWL, it seems best to capture the ontology first in a conceptual language such as ORM and then map to OWL or a more appropriate description logic, noting those constraints that are lost in the mapping.

By treating conceptual schemas as sample database states, the CSDP may be used to develop a conceptual metaschema. This may be used by a CASE tool to ensure that only valid conceptual schemas are entered. The activity of metamodeling, or making models of models, also helps to clarify and translate between different formalisms.

The literature on data warehousing and OLAP is substantial. Date (2000, Chapter 21) includes a clear overview of decision support. Inmon (1993), Kimball (1996), and Silverston (2001a,b) provide practical advice and examples of data warehousing. Jukik (2006) provides a useful overview of alternative strategies for modeling data warehouses. The gendercode example of data cleansing was suggested by Scot Becker—thanks Scot! For an extensive treatment of MDX for SQL Server 2022, see MDX Language Reference (MDX) - SQL Server | Microsoft Learn. For detailed coverage of Microsoft's OLAP architecture, see Logical Architecture (Analysis Services - Multidimensional Data) | Microsoft Learn.

A brief review of conceptual query prototypes, such as ERQL, Super, Hybris, and CBQL, is given in Bloesch and Halpin (1997). Some other graphical database query languages are surveyed in Ozsoyoglu and Wang (1993). Details on several query builders for SQL may be accessed at 9 Best SQL Query Builder & Generator Tools (2023) (guru99.com) and www.activequerybuilder.com/.

The RIDL language was originally used in conjunction with Control Data's IAST tool for NIAM, which was the first true CASE tool for information modeling (Meersman and Van Assche, 1983). A full description of the RIDL language is given in Meersman et al. (1984), and further discussions of RIDL may be found in Meersman (1982) and Verheijen and van Bekkum (1982). For further discussion of ConQuer, see Bloesch and Halpin (1996, 1997) and Halpin (1998).

For more details about schema abstraction within ORM, see Campbell and Halpin (1994a), Campbell et al. (1996), and their various references. A procedure for generating default external forms from major object types is discussed in Campbell and Halpin (1993).

McLeod (2000) offers useful suggestions for extending use case and activity diagrams in UML. For practical advice on traditional ways to model the process aspects of information systems, see Barker and Longman (1992) and Barker (1990a,b). Some promising ways to integrate data and process are discussed by Shoval and Kabeli (2000), Halpin and Wagner (2003), Dietz and Halpin (2003), and Morgan (2007).
