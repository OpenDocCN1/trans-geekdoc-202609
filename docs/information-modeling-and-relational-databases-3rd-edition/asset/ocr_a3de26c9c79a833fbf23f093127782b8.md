Vertical partitioning can be used within the same server. Horizontal partitioning (also known as *sharding*) is used to split data over several servers. This introduces an additional difficulty because applications now need to know which server contains the relevant partition. This can be done in several ways, for example:

+   - By range: Each server contains a known range of key values.
+   - By lookup: An auxiliary table contains a cross-reference between keys and servers.
+   - By hash: A hashing function is used on the key to identify the relevant server.

The distribution strategy may also consider other factors such as geography. If data traffic is primarily driven by localized concerns, it can be directed to servers that are physically close to where the information is created or consumed. # The CAP Theorem

The CAP theorem was first introduced by Brewer in 2000 and is a widely used concept in distributed systems design (Gilbert and Lynch, 2002). At its core, the CAP theorem is about understanding the trade-offs that must be made when building distributed systems. Specifically, it states that it is impossible for a distributed system to simultaneously provide all three of the following guarantees:

+   - Consistency: Every node in a distributed system sees the same data at the same time, implying that every read operation must return the value of the most recent write of the data.
+   - Availability: Every request made to the system will receive a response in a reasonable time frame, regardless of whether a node in the system has failed or is experiencing issues.
