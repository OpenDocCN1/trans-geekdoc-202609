
ExactCardinality restrictions other than 1 are allowed. For example, the following OWL 2 code may be used to state that Asimov authored exactly 506 books.

```
ObjectProperty: authored
Domain: Person
Range: Book
Individual: Asimov
Types: Person
authored exactly 506 Book
```

Database systems typically identify countries by country codes or country names. Many country names contain embedded spaces (e.g., “Czech Republic”) so can’t be used directly as IRIs (though modified names using underscores or hyphens for spaces could be).

In practice, many OWL ontologies use meaningless, automatically generated identifiers as IRIs just as some relational database designers prefer artificial, surrogate keys for their table schemas. Human-readable labels can be associated with IRIs using rdfs:label annotation properties, and OWL software tools such as Protégé (http://protege.stanford.edu/) can be configured to display labels instead of IRIs to make the ontologies more readable.

Constraints specified in data models are not translated into actual constraints in OWL, but rather logical propositions that are understood in terms of open world semantics where some individuals may be unnamed. For example, the subclass restriction “hasPoliticianName min 1” for Politician simply says that each politician has a politician name—it doesn’t require the system to know what that code is.

## Union, Intersection, and Complement

Recall that the union of sets A and B is the set of all elements in A or B or both. The union operator is supported in all versions of OWL, except for OWL Lite, and may be applied to classes or data ranges (e.g., datatypes or other collections of literals). The complex class expression or data range expression resulting from a union may be used anywhere a simple class or data range may be used. The union of two or more classes contains all the individuals that occur in at least one of those classes. In Manchester syntax, the union operator appears as “or”, placed in infix position. This is an inclusive-or operator. For example, we may define a promising student as a student who is either bright or industrious (or both) as follows:

```
Class: PromisingStudent EquivalentTo: BrightStudent or IndustriousStudent
```

This implies that BrightStudent and IndustriousStudent are subclasses of PromisingStudent. Inferences may be drawn about membership in the superclass. For example, given Individual: Hermione Types: BrightStudent, IndustriousStudent, we may infer Individual: Hermione Types: PromisingStudent.

A class partition may be declared in OWL by adding a disjoint classes declaration to the union operation. In Manchester syntax, to declare two or more classes that are disjoint (i.e., mutually exclusive), simply prepend “DisjointClasses:”. Adding this to an inclusive-or operator results in an exclusive-or operator. For example, we may define a Party as either a person or an organization but not both, thus:

```
DisjointClasses: Person, PrivateCompany, PublicOrganization
Class: Party EquivalentTo: Person or Organization
```

A partition of more than two classes may be specified in a similar way, for example,

```
DisjointClasses: Person, PrivateCompany, Organization
Class: Party EquivalentTo: Person or PrivateCompany or PublicOrganization
```

As an alternative for declaring partitions, OWL supports the disjoint union operator. In Manchester syntax, this is rendered by using “DisjointUnionOf:”. For instance, the partition just discussed may be declared more concisely thus:

```
Class: Party
DisjointUnionOf: Person, PrivateCompany, PublicOrganization
```

Recall that the intersection of sets A and B is the set of all elements that occurs in both A and B. In OWL, the intersection operator may be applied to classes or data ranges, and the complex class expression or data range expression resulting from an intersection may be used anywhere a simple class or data range may be used. In Manchester syntax, the intersection operator appears as “and”, placed in infix position. For example, the final line of the following OWL code defines the class StudentEmployee as the intersection of Student and Employee, which are themselves subclasses of Person.

```
Class: Person
Class: Student SubClassOf: Person
Class: Employee SubClassOf: Person
Class: StudentEmployee EquivalentTo: Student and Employee
```

Contrast this example with the following declaration, which is based on an example from the official OWL 2 Primer. Here, the class Grandfather is simply asserted, not defined. Instead, it is simply constrained to be included in (rather than being identical to) the intersection of the Man and Parent classes. Not all men who are parents are grandparents.

```
Class: Grandfather SubClassOf: Man and Parent
```

Recall that the complement of set A is the set of all elements in the universal set but not in the set A. In OWL, the complement operator may be applied to classes or data ranges, and the complex class expression or data range expression resulting may be used anywhere a simple class or data range may be used.

The complement of a class contains each individual that is not a member of that class. In Manchester syntax, the complement operator appears as “not”. For example, the class NonHuman may be defined as the complement of the class Human as follows:

```
Class: Human
Class: NonHuman EquivalentTo: not Human
```

The definition below of the class NonDriver is another example:

```
Class: Person
Class: Driver EquivalentTo: Person and drives min 1 Car
Class: NonDriver EquivalentTo: Person and not Driver
```

All the examples so far have used classes. In OWL 2, the union, intersection, and complement operations may also be applied to data ranges. For example:

```
Datatype: StringOrInteger EquivalentTo: xsd:string or xsd:integer
Datatype: PassGradeNr EquivalentTo: GradeNr and not FailGradeNr
```

## Reflexive, Irreflexive, Symmetric, Asymmetric, and Transitive Predicates

In OWL, all properties are binary predicates. If the domain and range are the same or compatible, one may compare subject and object instances. In ORM, such predicates are called ring predicates, and constraints that apply specifically to them (or more generally, pairs of compatible roles) are called ring constraints.

ORM includes graphical notation for several kinds of ring constraints, some of which are simply defined (e.g., irreflexive, asymmetric) while others are recursively defined (e.g., acyclic, strongly intransitive). OWL 2 supports only the following five kinds of restrictions on ring predicates: reflexive, irreflexive, symmetric, asymmetric, and transitive. Of these, OWL 1 supported only symmetric and transitive. Unlike ORM, OWL allows restrictions on ring predicates to be applied only to object property expressions, not data property expressions.

A relation R is reflexive if and only if every individual thing in the domain of R bears the relation R to itself. If the domain is owl:Thing, the only predicate likely to be reflexive is the identity relation “=”.

OWL allows object property expressions to be declared reflexive by characterizing them as reflexive properties. In Manchester syntax, we declare “Reflexive” as a characteristic. For example, if each person knows himself/herself, the “knows” predicate may be declared to be reflexive as follows:

```
ObjectProperty: knows
Domain: Person
Range: Person
Characteristics: Reflexive
```

Given this, the following inferences may be made:

```
Individual: Einstein
Types: Person
-> Individual: Einstein Facts: knows Einstein.

Individual: Terry
Facts: knows Tony
-> Individual: Terry Types: Person
   Individual: Tony Types: Person
```

As an example with a union domain, the following declaration of the isAsOldAs predicate asserts that each Person, each Cat, and each Dog is as old as itself.

```
ObjectProperty: isAsOldAs
Domain: Person or Cat or Dog
Characteristics: Reflexive
```

A ring predicate R is irreflexive if and only if no individual can bear the relation R to itself. For example, the parenthood relation is irreflexive because nothing can be a parent of itself. OWL object property expressions are declared irreflexive by characterizing them as irreflexive properties. To do this in Manchester syntax, we declare “Irreflexive” as a characteristic. For example, the isaParentOf predicate is declared irreflexive as follows. Any assertion that someone is his/her own parent would then render the OWL ontology inconsistent.

```
Class: Person
ObjectProperty: isaParentOf
Domain: Person
Range: Person
Characteristics: Irreflexive
```

A ring predicate R is symmetric if and only if ∀x∀y(xRy → yRx); that is, for each individual x and y (not necessarily distinct), if xRy then it is also the case that yRx. For example, the siblinghood relation is symmetric because if one person is a sibling (brother or sister) of another, then the second person is a sibling of the first.

OWL object property expressions are declared symmetric by characterizing them as symmetric properties. In Manchester syntax, we declare “Symmetric” as a characteristic, for example, isaSiblingOf may be declared to be symmetric in OWL as shown below. For completeness, the irreflexive nature of the predicate is also declared.

```
Class: Person
ObjectProperty: isaSiblingOf
Domain: Person
Range: Person
Characteristics: Symmetric, Irreflexive
```
