In the early 1990s, Halpin developed an extended version of NIAM called Formal ORM (FORM), initially supported in the InfoDesigner modeling tool from ServerWare. This product later evolved to InfoModeler (at Asymetrix Corp. and then InfoModelers Inc.) and then VisioModeler (at Visio Corp.). This ORM technology was then recoded to work on the Visio engine, first appearing in Visio Enterprise. Anthony Bloesch and Terry Halpin designed an associated query language called ConQuer (Bloesch and Halpin, 1997), supported in the ActiveQuery tool. Microsoft acquired Visio in 2000 and modified its ORM solution for use in Visual Studio.

Many researchers have contributed to the ORM method, and a full history would include many not listed here. Today, various versions of the method exist but all adhere to the fundamental object-role framework. Although most ORM proponents favor n-ary relationships, some prefer binary-relationship modeling (BRM) such as Shoval and Shreiber (1993). Habrias (1993) developed an object-oriented version called the normalized object-oriented method (MOON). The predicator set model (PSM) was developed mainly by Arthur ter Hofstede, Erik Proper, and Theo van der Weide (ter Hofstede et al., 1993), and includes complex object constructors. De Troyer and Meersman (1995) developed another version with constructors called the natural object-relationship model (NORM). Harm van der Lek and others (Bakema et al., 1994) allowed entity types to be treated as objectified predicates, to produce fully communication-oriented information modeling (FCO-IM). Independently of the main ORM movement, Dave Embley and others decided that using attributes in conceptual modeling was a bad idea, so they developed object-oriented systems analysis (OSA), which includes an attribute-free “object-relationship model” component that has much in common with ORM (Embley et al., 1992; Embley, 1998). The Semantics of Business Vocabulary and Business Rules (SBVR) approach adopted in 2007 by the Object Management Group is a recent addition to the family of fact-orientation, and has much in common with ORM 2, with its support of deontic as well as alethic rules. The latest version of the SBVR specification at the time of writing is accessible at www.omg.org/spec/SBVR/1.5.

Various software tools have been developed to support different flavors of the fact-oriented approach. The earliest tools developed by Nijssen, Meersman, and others at Control Data (e.g., IAST, RIDL*) are no longer available. Bloesch, Halpin, and others developed VisioModeler (discontinued but freely available), ActiveQuery (currently unavailable), and the ORM modeling solution in Microsoft soft Visio for Enterprise Architects (Halpin et al., 2003). The FCO-IM version is supported by the commercial tool CaseTalk (www.casetalk.com). Nijssen’s group at PNA developed tools based on CogNIAM (cognition-enhanced NIAM), including various iKnow tools (www.pna-group.com). Meersman and others developed academic ORM-based tools for specifying ontologies, such as Dogma Modeler and T-Lex (Trog et al., 2006).

NORMA (Curland and Halpin, 2010) is an open-source plug-in to Microsoft Visual Studio that provides deep support for ORM 2, the next generation of ORM, and may be downloaded from https://orms.com/ or https://sourceforge.net/projects/orm. For details on installing and using NORMA, see www.orm.net/resources.

Clifford Heath developed ActiveFacts (http://dataconstellation.com/ActiveFacts/), another suite of tools designed to support ORM 2.

Victor Morgante (https://victormorgante.medium.com/) is the main developer of a variety of tools such as Boston and FactEngine that include support for ORM 2 and other modeling approaches (https://www.factengine.ai/).
