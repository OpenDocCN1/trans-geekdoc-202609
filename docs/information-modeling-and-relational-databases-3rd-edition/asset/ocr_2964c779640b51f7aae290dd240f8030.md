# # 14.5 Conceptual Schema Optimization

Previous sections discussed how to transform conceptual schemas to equivalent, or at least acceptable, alternatives. Conceptual schema optimization involves transforming a conceptual schema into an alternative conceptual schema that maps to a more efficient (ideally, most efficient) implementation. Section 14.1 gave a simple example of this. Guidelines for performing such optimizations are now discussed.

Four **main factors** to consider when optimizing a conceptual schema are the _target system_, the _query pattern_, the _update pattern_, and _clarity_. The target system is the DBMS or other platform used for implementation. Here, we assume it is a centralized, relational system. The query pattern includes the kinds of questions the system has to answer as well as statistics about the expected frequency and priority of these questions. The update pattern includes the kinds, frequencies, and priorities of the expected insertions, deletions, and modifications to the database.
