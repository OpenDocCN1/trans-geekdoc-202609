# Mapping ORM to a Graph Database

Chapter 11 discussed the mapping of an ORM model to a relational structure and presented a systematic procedure (Rmap) to produce a redundancy-free relational design. We'll now consider the possibility of an equivalent approach for a graph database.

Fig. 17.11 shows a simple ORM model (constraints omitted, as discussed later) and a comparable graph model showing node labels. Leaving aside the obvious differences in graphical notation, it's clear that the two models are very similar in structure.

At this simple level, it appears that an ORM model could potentially be taken as a direct definition of a graph schema. Unfortunately, things become more complicated when we get into the detail. The first difficulty is that graph databases can only represent binary relationships.

![](bbox=[0.35, 0.34, 0.67, 0.48])

FIG. 17.11 Comparison of simple ORM and graph structures.

An ORM fact type of any other arity must be mapped to something structurally different in a graph model.

A unary fact type can be mapped to a graph property (normally a node property) or a binary relationship in a fairly straightforward way. Ternary or higher fact types must be remapped to binary relationships, perhaps involving multiple binary relationships for one ORM fact type. This may require additional constraints to preserve the intent of the original ORM model.

However, this raises the next difficulty, which is that graph databases generally provide very limited constraint options. In Neo4j, the only options are uniqueness and nonnull constraints (although a few more are available in the Enterprise Edition). It may be possible to work around these by taking care in the framing of create or update statements to preserve an appropriate structure, but for many ORM constraints, the only realistic solution is to implement the constraints in the application, not in the database.

A final difference in capability is the notion of subtypes. It is certainly possible to express subtyping notions in graph form, for example:

```
( :Species ) – [ :IS_MEMBER_OF ] -> ( :Genus ) – [ :IS_MEMBER_OF ] -> ( :Family ) ...
```
