As in standard set theory, the operations of union, intersection, and Cartesian product are *associative*. For instance, \( A \cup (B \cup C) = (A \cup B) \cup C \). Because no ambiguity results, parentheses may be dropped in such cases. For example, the expression “\( A \cup B \cup C \)” is permitted. Of the four table operations considered so far, difference is the only one that is not associative; that is, it is possible that \( A - (B - C) \) is not equal to \( (A - B) - C \). # FIG. 12.6 What is wrong with this Cartesian product?

Recall that column names of a table must be unique. If \( A \) and \( B \) have no column names in common, then \( A \times B \) uses the simple column names of \( A \) and \( B \). If \( A \) and \( B \) are different but have some common column names, the corresponding columns in \( A \times B \) are uniquely referenced by using *qualified names* (with the prefix “\( A \)” or “\( B \)”). However, what if \( A \) and \( B \) are the same (i.e., we wish to form the Cartesian product of a table with itself)?

Consider the Person × Person table in Fig. 12.6. This breaks the rule that column names in a table must be unique. In this case, simply using the qualified column names will not solve the problem either because we would have two columns named “Person.firstname” and two columns named “Person.gender”.

This problem is overcome by defining *aliases* for tables. For example, we could use “Person2” as an alternative name for the table and form the product as shown in Fig. 12.7. If desired, we could use two aliases, “Person1” and “Person2”, to specify the product Person1 × Person2. The need to multiply a table by itself may arise if we have to compare values on different rows. Aliases can also be used simply to save writing (by introducing shorter names). As discussed later, our **define alias** notation is an alternative syntax for trivial cases of the **rename** operator in relational algebra.
