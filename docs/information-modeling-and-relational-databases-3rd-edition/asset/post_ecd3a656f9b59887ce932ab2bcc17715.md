In some respects, a JSON file (and a corresponding program to load and process the file) could be considered a small database in its own right, though perhaps lacking many features expected in a complete database system such as transactions, concurrency, and so on. However, the JSON format has proved so useful that it has been used as the basis for full database systems, commonly referred to as Document Databases. These are usually classified as a type of “NoSQL” database and are discussed in more detail in Chapter 17.

## SQL/JSON

Given the widespread use of JSON, the SQL standard needed to be extended to accommodate it in the same way that it had previously accommodated XML. SQL:2016 provided support for JSON stored as text in a character-based column (typically **varchar**). Time pressures did not allow the full definition of JSON as a data type, but this was completed in SQL:2023, so data can be stored in a column of data type **json**. This had already been anticipated by several vendors, but their solutions are not necessarily compatible with each other or with the SQL:2023 standard. However, all vendors consistently adhere to the standard definition of JSON. There are two immediate advantages of a **json** data type.

- 1. Values can be automatically validated as correctly formed JSON. A data type such as **varchar** has no intrinsic understanding of JSON structure, so an additional function is required for text to establish that it represents a valid JSON value.
- 2. Values can be processed more efficiently by converting JSON text into a binary form for internal operations, avoiding relatively expensive string processing. The binary versions also require less storage.

The SQL/JSON data model covers SQL/JSON items and SQL/JSON sequences. A sequence is an ordered list of items. An item is any of the following:

- An SQL/JSON object: an unordered collection of members, where each member is a key-value pair, the value component being an SQL/JSON item.
- An SQL/JSON array: an ordered list of elements, where each element is an SQL/JSON item.
- An SQL/JSON scalar: a nonnull value with a type that is one of the standard JSON types (character string, numeric, or Boolean) or datetime.
- An SQL/JSON null (different from an SQL null).

Because the structural items (object and array) can be nested, JSON text can represent data with any required degree of complexity.

Values can be inserted into a **json** column in the usual way. Assume we have the following table definition:

```sql
create table movies (
movienr int primary key,

)
```

However, we don't necessarily have to split data up in this way. For example, all the movie data in Listing 16.2 could be entered as a single value in a json column.

SQL:2023 provides several functions to work with JSON values. These fall into two categories. SQL/JSON retrieval functions operate on SQL/JSON data and return values either as SQL data or SQL/JSON data. SQL/JSON construction functions return SQL/JSON values from either SQL data or SQL/JSON data.

Although JSON support was added to SQL:2016, it did not include the json data type until SQL:2023. During the intervening period, several vendors introduced individual interpretations of the data type and the corresponding functions to work with it. The result was some variance between different systems, including the following:

- 1. Certain SQL/JSON functions are missing completely, though it may be possible to obtain similar results in a more roundabout way.
- 2. Functions are provided with the same names as SQL/JSON functions but with different syntax.
- 3. Functions have the same main syntax as the SQL/JSON definitions but do not support some optional clauses defined in SQL:2023.

Hopefully, this situation will normalize in the future. The main SQL/JSON query functions in SQL:2023 are summarized in Table 16.7.

| Operator | Functionality |
| :--- | :--- |
| json_query() | Returns an object or an array from the specified JSON text |
| json_value() | Returns a scalar value from the specified JSON text |
| json_exists() | Returns true if the data is found in the specified JSON text. |
| json_table() | Converts identified parts of specified JSON text into a relational table. |

Some systems may provide alternatives such as json_extract(), which offers similar functionality to json_query(), and json_contains(), which may be used as a replacement for json_exists().
