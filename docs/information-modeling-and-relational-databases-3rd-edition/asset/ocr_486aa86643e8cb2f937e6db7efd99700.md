# 14.3 Nesting, Coreferencing, and Flattening

Humans may think of the universe in different ways. One modeling choice is whether to represent some feature in terms of an object type, and if so, how. The previous section discussed how to absorb or extract object types by predicate specialization and generalization. An object type with a composite identification scheme may be portrayed explicitly as a nested object type or as a coreferenced object type. If we don't want to think of this feature in terms of an object type, we can model it with predicates using a flattened approach. This section considers transformations among nested, coreferenced, and flattened approaches.
