we can distinguish between them with optional clauses to deal with the “on empty” and “on error” cases. For example, the following query will return the text “Not found” because we have specified an array index that does not exist in the data. Such optional clauses are not supported in all systems.

```
select json_value(movie, '$.movies[8].movieNr' default 'Not found' on empty) from videos
```

We can use json_exists to check whether a specific item is present or not. In this case, the return value is 1 if the item exists and 0 if it does not. For example:

```
select json_exists(movie, '$.movies[*].director') from videos
```

will return 1 indicating that at least one occurrence of the specified item has been found, but:

```
select json_exists(movie, '$.movies[*].producer') from videos
```

returns 0 because our movie objects do not contain a producer member.

One useful application of json_exists is in the creation of check constraints to ensure that JSON data contains some mandatory elements. Further predicates can be used to check whether an item is (or is not) a JSON value, array, object, or scalar, but we won't go into the details of these here.

Although json_query can return results from JSON documents, the results remain in a JSON format. To be consistent with other operations, we may prefer results in the form of a standard SQL table. This is the functionality provided by json_table, which extracts data from a JSON document and returns it as a relational table. Here's a simple example, based on our usual movie data.

```
select jt.Title, jt.Director from videos as v,
json_table (v.movies, '$.movies[*]' columns(
Title varchar(20) path '$.title',
Director varchar(20) path '$.director'
)) as jt
```

The select statement identifies columns from the aliased JSON table (“jt”) created by the json_table function. The first argument to the function specifies the JSON source, in this case the movies column of the videos table. The second argument defines the starting point in the JSON text, in this case the movies array. The column list defines the column name, the SQL data type, and the path in the current context (in this case, the starting point defined previously). The result is a straightforward SQL table.
