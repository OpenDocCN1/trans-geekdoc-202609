
If knowledge of parenthood facts is incomplete, we may wish to allow some grandparenthood facts to be simply asserted by adding the following declarations.

```
ObjectProperty: isaGrandparentOf
  Domain: Person
  Range: Person
```

Property chains composed from more than two predicate occurrences are also allowed. For example, the following declaration enables great-grandparenthood facts to be inferred from three relevant parenthood facts. For instance, given the facts that Edward VII is a parent of George V, George V is a parent of George VI, and George VI is a parent of Elizabeth II, we may derive the fact that Edward VII is a great-grandparent of Elizabeth II.

```
ObjectProperty: isaGreatGrandparentOf
  SubPropertyChain: isaParentOf o isaParentOf o isaParentOf
```

As an example of a property chain with three different predicates, the following declarations capture the derivation that a person drives a car made by a specific company if that person drives a car that is of a car model made by that company.

```
ObjectProperty: drives
  Domain: Person
  Range: Car
ObjectProperty: isOfCarModel
  Domain: Car
  Range: CarModel
ObjectProperty: isMadeBy
  Domain: Car
  Range: CarModel
ObjectProperty: drivesCarMadeBy
  SubPropertyChain: drives o isOfCarModel o isMadeBy
```

In dealing with property chain axioms, OWL includes formal restrictions to avoid circular reasoning that could lead to problems of decidability. We now consider an example. In general, an uncle is either a brother of a parent or the husband of an aunt. Unclehood by birth may be defined as follows: given persons x and y, x is a birth uncle of y if x is a brother of a parent of y. Now suppose we also define brotherhood as follows: given persons x and y, x is a brother of y if x is a birth uncle of a child of y. These derivation rules may be specified in OWL as follows.

```
ObjectProperty: isaBirthUncleOf
  SubPropertyChain: isaBrotherOf o isaParentOf
ObjectProperty: isaBrotherOf
  SubPropertyChain: isaBirthUncleOf o isaChildOf
```

Note that the derivation rule for brotherhood calls the birth unclehood predicate, which itself depends on brotherhood. So, the derivation rules in combination involve a vicious circle. In OWL, this property chain combination is illegal.

## Some Differences Between OWL Ontologies and Typical Databases

In OWL 2, a named individual is identified by an IRI. OWL 2 also allows unnamed or *anonymous individuals* (corresponding to blank nodes in RDF), which may be referenced within a given ontology by a local *nodeID* that starts with an underscore, for example, *_:x* or *_:p1*. The following example asserts the existence of a woman president of Taiwan, using the nodeID _:p1 to denote this person.

```
Individual: _:p1
Types: Woman
Facts: isPresidentOf Taiwan
```

In relational databases, individuals are normally identified by simple or compound names, so existential assertions like those above are typically not supported, although we can store specific facts that imply them, such as Tsai Ing-wen is a woman and president of Taiwan.

From a logical perspective, IRIs correspond to individual constants rather than names in the usual sense they have in relational databases. To illustrate how OWL's treatment of IRI-based identification schemes differs from the value-based identification schemes used in database systems, consider the following declarations:

```
DataProperty: hasCountryCode
  Domain: Country
  Range: xsd:string
Class: Country
  SubClassOf: hasCountryCode exactly 1
Individual: Australia
  Types: Country
  Facts: hasCountryCode "AU"
Individual: Germany
  Types: Country
```

Here, we asserted that Germany is a country without explicitly providing a country code for it. This would not be allowed in an information model or relational database because our declaration that each country has a country code is implemented as an integrity constraint, forbidding a country without a country code.

In contrast, OWL allows this because the declaration that each country has a country code is *interpreted simply as a proposition, not as a constraint*. This proposition may be formalized in logic as ∀x(Country x → ∃y x hasCountryCode y). Because we asserted that Germany is a country, the system infers that Germany has a country code, which is currently unknown. This is allowed in OWL, which adopts open world semantics and permits unnamed individuals.

Note also that if we add the data property hasCountryName, OWL has no way to choose one of the hasCountryCode or hasCountryName relationships for the preferred reference scheme, as any distinction between primary and alternate keys is lost.

InverseFunctional declarations apply to any kind of individual (named individuals, anonymous individuals, and individuals whose existence is implied by existential quantification). However, the uniqueness aspect of HasKey declarations applies only to named individuals (individuals that are explicitly named by an IRI). Suppose we declare the object property wasBornInCountry and the data property hasCountryCode in the usual way and then add the following declarations.

```
Class: Country
  SubClassOf: hasCountryCode exactly 1
  HasKey: hasCountryCode
```

We can now assert that Julia Gillard (a former prime minister of Australia) was born in some country that has the country code "GB" without knowing the name of that country, as follows:

```
Individual: JuliaGillard
  Facts: wasBornInCountry _:c1
Individual: _:c1
  Facts: hasCountryCode "GB"
```

Now, suppose we discover that the United Kingdom has the country code "GB" (chosen by ISO based on the long name "The United Kingdom of Great Britain and Northern Ireland"). Using TheUK as an intuitive IRI for the United Kingdom, we can now assert that the UK has the country code "GB" as follows:

```
Individual: TheUK
  Facts: hasCountryCode "GB"
```

One might expect that it is correct to infer the fact that Julia Gillard was born in the United Kingdom, which may be expressed thus:

```
Individual: JuliaGillard
  Facts: wasBornInCountry TheUK
```

However, this fact does not follow! This is because the HasKey declaration for Country applies only to named individuals (those with IRIs explicitly asserted) while allowing that Julia Gillard may be born in many unnamed countries.

## Negated Facts and Unary Facts in OWL

Similar to the way OWL uses "not" as a complement operator for classes and data ranges, OWL enables you to explicitly assert the *negation* of a proposition by declaring a *NegativePropertyAssertion*. Manchester syntax uses the logical **not** operator before the relevant predicate object pair in the Facts slot for the individual. Consider the ORM fact type Scientist was born in Country. This is used purely to record which scientists are born in which country. Suppose we know that Newton was born in England, and that although we don't know where Einstein was born, we do know he wasn't born in England. OWL allows us to assert both the positive and negated facts as follows:

```
ObjectProperty: wasBornIn
  Domain: Scientist
  Range: Country
  Characteristics: Functional
Individual: Newton
  Facts: wasBornIn England
Individual: Einstein
  Facts: not wasBornIn England
```

Contrast this approach with the closed world approach of typical databases where any fact that is neither asserted nor derived is assumed to be false. The previous example negates an object property. Data properties may be negated in a similar way. For example, treating IQs as numbers, we may assert that Einstein's IQ is not equal to 100 as follows:

```
DataProperty: hasIQ
  Domain: Scientist
  Range: xsd:nonNegativeInteger
  Characteristics: Functional
Individual: Einstein
  Facts: not hasIQ 100
```

OWL adopts the open world assumption, so if a fact is neither asserted nor implied, it is unknown. Hercule Poirot, Captain Hastings, and Inspector Japp are characters from Agatha Christie novels. *Unary facts* (e.g., Poirot smokes) and their *negations* (e.g., Hastings does not smoke) have to be remodeled in OWL as binary relationships that relate the subject to an object that is either a Boolean value (true or false) or a status value with two possibilities (e.g., "Smoker", "NonSmoker").

For example, the following OWL declarations assert that Poirot smokes, Hastings doesn't smoke, and leave it *unknown* whether Japp smokes. In ORM, this example would be modeled using the unary fact type Person smokes under open world with negation semantics.

```
DataProperty: isaSmoker
  Domain: Person
  Range: xsd:boolean
```
