Although the unbundling of entities in ORM potentially offers a finer-grained definition of a relationship between activity and information, it is not necessarily convenient for cross-referencing of the kind we are considering. An activity is likely to require all information about an entity to be treated together rather than as isolated facts. For example, an agent updating stored data about personnel would probably expect to see all relevant information about a particular employee to be displayed at the same time. Instead of referring to individual fact types, it would be much simpler if the fact types were arranged in convenient bundles related to major entity types.

A straightforward way of achieving this is to group fact types into relations, in the sense originally expressed by Codd. Facilities already exist in ORM to produce normalized relations from an ORM model with the Rmap procedure. In a conceptual model, there is no prior commitment to a relational database solution, but this does not matter because normalized relations can be realized in other types of data structures such as XML and JSON; see Chapter 16 for more details.

A convenient data reference to a group of fact types in an information model can therefore be made by simply using the (unique) name of the relation. Accessing a particular data item during the execution of a process would require the relation name plus a key value that is unique within the relation. The same activity may access different instances of the relation in different instances (executions) of the process. However, only the relation’s name is necessary to define the linkage between a process model and an information model.
