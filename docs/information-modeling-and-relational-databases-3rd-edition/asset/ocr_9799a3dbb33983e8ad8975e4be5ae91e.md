As a related example, consider the notion of team membership, where a person may be a member of many teams and vice versa. Fig. 10.39 shows how to model this in ORM with and without the set constructor. In Fig. 10.39(b), the circled “[ ]” depicts an *extensional uniqueness constraint* (ter Hofstede and van der Weide, 1994) to declare that teams may be defined by their membership (i.e., different teams cannot have exactly the same set of members). A sample population for two teams is included. The underline (like a uniqueness bar) inside the set braces intuitively suggests that the set is unique. An alternative notation for this constraint is a circled “eu”. This constraint is implicit in Fig. 10.39(a). Its use in B allows unnamed structures without introducing collection types.

Bakema et al. (1994) provide another notation for this constraint, and argue that if teams are unnamed in reality, this must be reflected in the conceptual model to obey the conceptualization principle to model only conceptually relevant features. We adopt a relaxed reading of this principle, encouraging the introduction of identifiers that improve model usability. In Fig. 10.39(c), we add a team code as a simple identifier for teams to facilitate talk about teams.

The extensional uniqueness constraint is still required if we definitely don’t want two different teams to have the same membership, as illustrated by the counterexample provided. This constraint is very expensive to enforce, so should be used only when necessary.

A complex example cited in the ORM literature to justify the use of constructors deals with chemical reactions (Falkenberg, 1993). This models reactions such as 2H2 + O2 <=> 2H2O. One way to model this with a set collection type is shown in Fig. 10.40(a). This schema, based on a solution by ter Hofstede et al. (1992), treats each side of a reaction equation as a set of chemical quantities, for example, {(H2, 2), (O2, 1)}.

The reaction itself is then captured in the binary input/output association. An alternative flat model is shown in Fig. 10.40(b). Here, a reaction number is introduced as a convenient way of referring to reactions. This model also shows a complex example of the extensional uniqueness constraint.
