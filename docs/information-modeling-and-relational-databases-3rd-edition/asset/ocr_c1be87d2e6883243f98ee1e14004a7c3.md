More interesting are the functions to construct JSON structural elements, objects and arrays. The constructors can be nested, so we can build JSON values of arbitrary complexity. These functions are summarized in Table 16.8.

# Table 16.8 SQL/JSON structural construction functions.

| Operator | Functionality |
| :--- | :--- |
| json_object() | Creates an SQL/JSON object from a given list of name-value pairs |
| json_array() | Creates an SQL/JSON array from a given list of values |
| json_objectagg() | Creates an SQL/JSON object from a given collection of rows |
| json_arrayagg() | Creates an SQL/JSON array from a given collection of rows |

Creating objects is straightforward. The following query defines an object structure with members for employee number and office, which is then applied to each row of the Agent table.

```
select json_object('empNr' value nr, 'office' value office) from Agent
```

```
Result:
{"empNr": 101, "office": "Boston"}
{"empNr": 232, "office": "Portland"}
{"empNr": 397, "office": "Durham"}
{"empNr": 468, "office": null}
```

Some implementations of json_object replace the value keyword with a comma. An ugly feature of the result is the null in the last object. A more natural JSON representation would omit this member entirely. SQL/JSON defines an optional absent on null clause to effect this, but it's not supported in all implementations.
