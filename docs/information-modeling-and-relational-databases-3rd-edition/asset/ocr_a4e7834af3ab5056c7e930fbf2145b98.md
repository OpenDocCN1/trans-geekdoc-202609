![](bbox=[0.156, 0.098, 0.836, 0.166])

In this example, the simple object type Subject is also independent. In this universe of discourse (UoD), it is possible that all we know about a subject is its subject code. It is not necessary that all subjects be taught. However, *simple object types are rarely independent*.

In most academic domains, we need to know the title of any subject, not just its code. This more realistic situation is depicted in Fig. 6.11(a), where Subject is no longer independent because it has a mandatory fact role. Similarly, in our Olympics example, if all countries had codes as well as names, and we chose code for preferred reference, then Country has CountryName becomes a mandatory fact type, and Country is no longer independent (see Fig. 6.11(b)).

The use of an independent object type or unary predicates instead of a value constraint adds flexibility because the data can be changed without recompiling the schema (and relevant forms, etc.). However, the responsibility for this is now in the hands of the person entering the data rather than the schema designer. Typically, write-access to such reference tables is granted only to database administrators.

A Dutch version of ORM known as Fully Communication Oriented Information Modeling (FCO-IM) treats all entity types, independent or not, as objectified predicates. For example, in Fig. 6.12 the entity type Country is depicted as the objectification of a role played by the value type CountryName. The notion of an entity type can then be treated as a derived, rather than a base construct.
