State machine descriptions have been popular for several decades as a way of specifying and implementing automata; we see many examples in everyday life in the form of digital watches, cell phones, video recorders, and so on. However, for a long time, it was believed that state machines did not scale well because of the explosion of states required to deal with all the combinations of variables. In a naïve state machine interpretation, the total number of states required is of the same order as the product of the number of different values for each involved variable. For instance, if we have three variables with 3, 4, and 5 possible values, respectively, the likely number of states is 3 × 4 × 5 = 60 to cover all possible combinations of values. Of course, some combinations may actually be associated with the same state but considering the large number of variables involved in a typical business system, the idea of a state-based description seems futile.
