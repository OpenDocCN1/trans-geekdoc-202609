# ## 3.1 Conceptual Modeling Language Criteria

Before discussing the conceptual schema design procedure (CSDP) of object-role modeling (ORM), let's review the design principles that underlie the ORM language. Some of these ideas were mentioned before, but we generalize the discussion here so that you can apply the principles to evaluate modeling languages in general. As you go through the book, consider how these principles are realized in the various languages discussed.

A modeling method (or modeling process) comprises both a language and a procedure describing how to use the language to build models. A language has associated syntax (marks), semantics (meaning), and pragmatics (use). Written languages may be graphical (diagrams) and/or textual. The terms “abstract syntax” and “concrete syntax” are sometimes used respectively to distinguish underlying concepts (e.g., object type) from their representation (e.g., named, soft rectangle).

Conceptual modeling portrays the business domain at a high level, using terms and concepts familiar to the business users, ignoring logical and physical level aspects (e.g., underlying database or programming structures used for implementation) and external level aspects (e.g., screen forms used for data entry). The following criteria drawn from various sources (van Griethuysen, 1982; ter Hofstede, 1993; Bloesch and Halpin, 1996) provide a basis for evaluating conceptual modeling languages.

+   * Expressibility
+   * Clarity
+   * Simplicity and orthogonality
+   * Semantic stability
+   * Semantic relevance
