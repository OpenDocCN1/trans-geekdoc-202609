To further reduce the need for parentheses, the algebra adopts the logical operator priority convention commonly used in computing languages, such as Pascal and SQL. First evaluate not, then and, and then or. Table 12.1 shows the evaluation order for both comparison and logical operators. This operator precedence may be overridden by the use of parentheses.

For example, suppose we want details about males who are taller than 175 cm or shorter than 170 cm. The query in Fig. 12.11(a) looks like it should work for this, but the wrong result is obtained. Why?

# Table 12.1 Priority convention for the operators (1 = first).

| Priority | Operators |
|---|---|
| 1 | =, <>, <, >, <=, >= |
| 2 | not |
| 3 | and |
| 4 | or |

```
(a) Player where gender = 'M'
and height > 175 or height < 170
```

| name | gender | height |
|---|---|---|
| Selena | F | 165 |
| Terry | M | 178 |

```
(b) Player where gender = 'M'
and (height > 175 or height < 170)
```

| name | gender | height |
|---|---|---|
| Terry | M | 178 |

FIG. 12.11 Unless parentheses are used, and is evaluated before or.

Because the and operator is evaluated before the or, this query is interpreted as Player where (gender='M' and height>175) or height<170. Notice that line breaks have no significance to the meaning of the query. So, the result includes details about anybody shorter than 170 cm (including females).

The query in Fig. 12.11(b) corrects this by including parentheses around the height disjunction to evaluate the or operator before the and operator.

To obtain details about players who are either males over 175cm or females at least 170 cm tall, either of the queries shown in Fig. 12.12 may be used. In the query in Fig. 12.12(b), parentheses are redundant because the and operators are evaluated before the or operator anyway. If in doubt about whether parentheses are needed, put them in.

```
(a) Player where gender = 'M' and height > 175
or gender = 'F' and height >= 170
```

| name | gender | height |
|---|---|---|
| Terry | M | 178 |
| Norma | F | 170 |

```
(b) Player where (gender = 'M' and height > 175)
or (gender = 'F' and height >= 170)
```

FIG. 12.12 Two equivalent queries; if in doubt, include parentheses.
