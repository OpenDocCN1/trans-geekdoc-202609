In OWL, the equijoin operation is known as a *composition* operation, and an expression that composes two or more predicates is called a *property chain*.

To illustrate this notion, consider a business domain in which each person is born in at most one city (e.g., some people might instead be born in a village), and each city is located in exactly one country. One way of specifying this schema in OWL using Manchester syntax is as follows:

```
ObjectProperty: wasBornInCity
Domain: Person
Range: City
Characteristics: Functional
ObjectProperty: isLocatedInCountry
Domain: City
Range: Country
Class: Person SubClassOf: wasBornInCity max 1
Class: City SubClassOf: isLocatedInCountry exactly 1
```

Now, suppose we are also interested in knowing which countries people are born in. In ORM, we could add the semiderived fact type Person was born in Country, allowing some instances to be asserted and others derived using the derivation rule Person was born in Country if Person was born in some Country that is located in that Country.

In OWL 2, we can specify the derivation rule by declaring the wasBornInCountry predicate to be a subproperty of the predicate formed by projecting on the start and end of the property chain that composes the wasBornInCity and isLocatedInCity predicates. In Manchester syntax, the property chain is specified using the symbol “o” as the *composition operator* placed between adjacent predicates in the chain, and listed after the header “SubPropertyChain:”. Our current example may be specified in Manchester syntax by adding the following OWL code:

```
ObjectProperty: wasBornInCountry
Domain: Person
Range: Country
SubPropertyChain: wasBornInCity o isLocatedInCountry
```

The subproperty declaration is just a simple implication that applies to any satisfying models. OWL is not concerned with choices about how to actually implement implications. A property chain may compose multiple occurrences of the same predicate. For example, grandparenthood facts may be derived by composing two parenthood facts, as shown.

```
ObjectProperty: isaGrandparentOf
SubPropertyChain: isaParentOf o isaParentOf
```
