| **Preferred internal UC**<br>Country —[has / is of]— CountryCode | A double bar on a UC indicates that it underlies the preferred reference scheme. |
| **External UC (inner-join semantics)**<br>State —has—> StateCode<br>State —is in—> Country(.Code)<br>State —has—> StateName | A double-bar indicates that the constrained roles provide the preferred reference for the object type at the other end.<br>Here, each state is primarily identified by combining its country and state code. Each combination of country and state name also applies to only one state. |
| **External UC (outer-join semantics)**<br>Course(.Code) —has—> CourseTitle<br>Course(.Code) —is offered by—> Department(.Code)<br>Course —has—> CourseTitle<br>Course —is offered by—> Department(.Code) | An inner “o” through the uniqueness bars indicates that the external UC has outer join semantics, with the added proviso that nulls produced in the outer join are treated as actual values (see Section 10.1 for further discussion).<br>A double uniqueness bar indicates the UC is used in the preferred reference scheme.<br>The inner “o” notation is not yet supported by the NORMA tool. |
| **Object type value constraint**<br>Gender(.Code) {'M', 'F'}<br>Rating(.Nr) {1, 2, 3, 4, 5, 6, 7}<br>Rating(.Nr) {1..7}<br>Grade(.Code) {'A'..'F'}<br>Age(y:) {0..}<br>NegativeInt {-..1}<br>PassScore(%) {50..100}<br>PositiveScore(%) {0..100}<br>NegativeTemperature (°C:) {-273.15..0}<br>ExtremeTemperature (°C:) {-100..-20, 40..100}<br>SqlChar {'a'..'z', 'A'..'Z', '0'..'9', '_'} | The allowed values may be specified as a list of discrete values and/or value ranges. The first two examples specify an enumerated list of values.<br>Ranges are inclusive of end values by default.<br>Round brackets exclude an end value.<br>Square brackets explicitly declare inclusion, such as the constraint on PositiveScore may also be specified as {[0..100]}.<br>Multiple combinations of value constraints may also be specified. |
| **Role value constraint**<br>Person(.Name) has Age(Y): {0..}<br>{0..140} | As for object type value constraints, but connected to the constrained role. Here, an age of a person must be at most 140 years. |
| **Subset constraint**<br>is cancer prone<br>enrolled in<br>Person Course Grade<br>smokes ... for ... obtained ... | The arrow points from the subset end to the superset end (e.g., if a person smokes then that person is a cancer prone).<br>The role sequences at both ends must be compatible.<br>A connection to the junction of two roles constrains that role pair. |
| **Join subset constraint**<br>speaks Language(Name) is often used in<br>Advisor.(Nr) Country.(Code)<br>serves in | The constrained role pair at the superset end is projected from a role path that involves a conceptual join on Language. The constraint declares that if an advisor serves in a country, then that advisor must speak a language that is often used in that country. |
| **Exclusion constraint**<br>is married Person authored Book<br>is widowed reviewed | These exclusion constraints mean that no person is both married and widowed, and no person reviewed and authored the same book.<br>Exclusion may apply between two or more compatible role sequences, possibly involving joins. |
| **Exclusive-or constraint**<br>is male Academic is tenured Date<br>is female is contracted till<br>Spouse<br>is a husband of / is a wife of | An exclusive-or constraint is simply the conjunction of an inclusive-or constraint and an exclusion constraint. The first two examples say that each academic is male or female but not both, and is tenured or contracted until some date but not both.<br>The third example says each spouse is a husband or wife of a spouse but not both.<br>The 1:1 nature of the fact type assumes monogamy. |
| **Equality constraint**<br>has systolic-<br>Patient o BloodPressure<br>has diastolic- | This constraint means that a patient's systolic BP is recorded if and only if his/her diastolic BP is recorded.<br><br>An equality constraint may apply between two or more compatible role sequences, possibly involving joins. |
| **Derived fact type, and derivation rule**<br>[languageSpoken]<br>Person speaks Language<br>speaks* NrLanguages<br><br>*For each Person,<br>nrLanguages = count(languageSpoken). | A fact type is either asserted, derived, or semiderived.<br><br>A derived fact type is marked with an asterisk "*". A derivation rule is supplied. A double asterisk "**" indicates derived and stored (eager evaluation). |
| **Semiderived fact type, and derivation rule**<br>is a parent of<br>Person +<br>Person1 is a grandparent of Person2<br>if Person1 is a parent of some Person3<br>who is a parent of Person2.<br><br>is a grandparent of + | A fact type is semiderived if some of its instances may be derived, and some of its instances may be simply asserted. It is marked by "+" (half an asterisk).<br>"++" indicates semiderived and stored (eager evaluation for derived instances). |
| **Subtyping**<br>Person (.Nr)<br>Student (.Nr) Employee (.Nr)<br>Student Employee Lecturer | All subtypes are proper subtypes.<br><br>An arrow runs from subtype to supertype. A solid arrow indicates a path to the subtype's preferred identifier (e.g., here, student employees are primarily identified by their employee number).<br><br>A dashed arrow indicates the supertype has a different preferred identifier. |
| **Subtyping constraints**<br>Animal TeamMember Person<br>Dog Cat Player Coach Male Person Female Person | X indicates that the subtypes are mutually exclusive. dot indicates that the supertype equals the union of the subtypes. The combination (xor constraint) indicates that the subtypes partition the supertype (exclusive and exhaustive). |

| **Internal frequency constraint**<br>Person is a member of Jury 12<br>Jury is on / includes Panel<br>Expert 4..7 <=5 >=2 Paper reviews / is reviewed by<br>Department ... in ... had staff of ... in ... Quantity 2 Year Gender | This constrains the number of times an occurring instance of a role or role sequence may appear in each population. Here, each jury has exactly 12 members; each panel that includes an expert includes at least four and at most seven experts; each expert reviews at most five papers; each paper that is reviewed is reviewed by at least two experts; and each department and year that has staff numbers recorded in the quaternary appears there twice (once for each gender). |
| **External frequency constraint**<br>Enrollment is by Student (<=2)<br>Enrollment is in Course | The example constraint has the following meaning. In this context, each combination of student and course relates to at most two enrollments (i.e., a student may enrol at most twice in the same course). |
| **Value-comparison constraint**<br>Project started on Date ended on [enddate] | The example constraint verbalizes as:<br>**For each Project, existing enddate >= startdate.** |
| **Object cardinality constraint**<br># ≤ 1<br>[President] [UN_SecurityCouncilMember]<br>#(0, 5.15] | The example constraints ensure that at any given time there is at most one president and either zero or at least five and at most 15 members of the UN Security Council. |
| **Role cardinality constraint**<br>[Politician] is the president [ ]<br># ≤ 1 | The example constraint ensures that at most one politician is the president (at any given time). |
| **Ring constraints**<br>Diagram: A ... Irreflexive ... Reflexive (locally) ... Purely Reflexive ... Asymmetric ... Symmetric ... Antisymmetric ... Transitive ... Intransitive ... Strongly Intransitive ... Acyclic ... Asymmetric + Intransitive ... Acyclic + Intransitive ... Acyclic + Strongly Intransitive ... Symmetric + Irreflexive ... etc.<br>E.g., [ObjectType] is a direct subtype of [diagram] | A ring predicate R is locally reflexive if and only if, for all x and y, xRy implies xRx. For example, “knows” is locally but not globally reflexive. Reflexive, Symmetric, and transitive properties may also be enforced using semiderivation rather than by constraining asserted fact types.<br>The example constraints the subtyping relationship in ORM to be acyclic (no cycles can be formed by a chain of subtyping connections) and strongly intransitive (no object type A can be both a direct subtype of another type B and an indirect subtype of B, where indirect subtyping means there is a chain of two or more subtyping relationships that lead from A to B).<br>Ring constraints may be combined only if they are compatible, and one is not implied by the other. ORM tools ensure that only legal combinations are allowed. |
