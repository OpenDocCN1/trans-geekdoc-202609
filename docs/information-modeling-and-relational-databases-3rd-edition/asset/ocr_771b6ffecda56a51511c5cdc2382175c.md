A UC that spans all roles in a fact type is called a *spanning UC*. In addition to expressing the m:n nature of the binary fact type, the UC in Fig. 4.11 ensures that the fact type is populated by a set of facts (no duplicate rows). This may be verbalized as “**Each** Politician, Country **combination occurs at most once** in the **population of** Politician visited **Country**”.

Whenever you have a spanning UC, you should check with the domain expert that a bag (multiset) of facts is to be excluded. For example, a politician may visit the same country many times. If we wish to distinguish between visiting a country at all and visiting it many times, we need to remodel the situation (e.g., by expanding the binary to a ternary that includes a visit date). We’ll discuss such temporal aspects of modeling in detail in Section 10.3.

Simple 1:1 reference schemes are usually abbreviated by placing the reference mode name in parentheses. However, we may set them out fully as in Fig. 4.13. This is an *existential fact type* (also called a *reference type*): instances are used to simply assert the existence of an entity. This diagram is still incomplete; the next chapter shows how to add the constraint that each country has a country code.

If there is only one means of referring to an entity type, the UCs on the reference type are the responsibility of the user to enforce rather than the system. For example, we must ensure that there is only one country with the code “US”. If two 1:1 naming conventions are used (e.g., code or name), choose one as our preferred reference scheme, and treat the other like any other elementary fact type.

The four possible patterns of UCs for a binary predicate are: many to many; many to one; one to many; and one to one. Each of our examples so far has involved a heterogeneous predicate (different object types). Let’s look now at some ring predicates (both roles played by the same object type). To clarify the different roles being played, inverse predicate names are included. Our first example concerns parenthood (see Fig. 4.14). For simplicity, assume that we can identify people by their first names.

As the sample fact table in Fig. 4.14 reveals, a person may have many children. Moreover, a person may have many parents. The column entries need not be unique, but the whole row must be. Hence, the UC spans the whole row. Contrast this with motherhood (see Fig. 4.15).
