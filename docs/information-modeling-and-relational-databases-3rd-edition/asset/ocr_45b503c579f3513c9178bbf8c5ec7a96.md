The ORM schema in Fig. 17.18 includes several other kinds of constraints. The inclusive-or constraint in example (a) ensures that each job applicant is either qualified or has a reference (or both). This may be expressed in Rel thus:

```
ic (p) requires JobApplicant(p) implies (isQualified(p) or hasaReference(p))
```

The exclusive-or constraint in example (b) ensures that each planet in our solar system is an inner planet or an outer planet but not both. This may be expressed in Rel thus:

```
ic (p) requires Planet(p) implies (isAnInnerPlanet(p) xor isAnOuterPlanet(p))
```

The value constraint in example (c) restricts the value of GenderCode in the underlying reference type Gender has GenderCode. The value constraint in example (d) restricts IQ values to the range 0..300. These constraints may be formulated thus:

```
ic (g, gc) requires hasGenderCode(g,gc) implies (gc = "M" or gc = "F")
ic (x, y) requires hasIQNr(x,y) implies (x >= 0 and x <<300)
```

The exclusion constraints in examples (e) and (f) say that nobody can author and review the same book, and that nobody can review a paper authored by someone who lectures at the same university where he/she lectures. The diagram in (f) for the exclusion constraint over a join path is a screenshot from the NORMA tool. The constraints may be formulated thus:

```
ic (p, b) requires reviews(p, b) implies not authors(p, b)
```

```
ic (p1, p2, u, pr) requires (authors(p1, pr) and lecturesAt(p1, u) and reviews(p2, pr)) implies not lecturesAt(p2,u)
```

The ORM schema in Fig. 17.19 includes some more constraints. The equality constraint in example (a) ensures that a patient has a diastolic blood pressure reading if and only if the patient has a systolic blood pressure reading. This may be expressed in Rel using an anonymous variable as follows:

```
ic (p) requires hasDiastolicBP(p, _) iff hasSystolicBP(p,_)
```

The internal frequency constraint in example (b) ensures that each reviewer is assigned at most three papers to review. It may be formulated thus:

```
ic (r, n) requires isAssignedNrPapers(r, n) implies n <= 3
```

The composite frequency constraint in example (c) ensures that no student may enroll more than twice in the same course. This may be formulated as follows. Here, “def” prepends the definition or derivation rule for the inCourseHasNrEnrollments relation, which uses the built-in count function. The constraint makes use of the derived ternary relation.

```
def inCourseHasNrEnrollments(s, c, n):
n = count[{e}: isanEnrollmentByStudent(s, e) and isanEnrollmentlnCourse(e, c)]
ic (s, c, n) requires inCourseHasNrEnrollments(s, c, n) implies n <=2
```
