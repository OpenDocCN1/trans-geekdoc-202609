+   • Partition tolerance: A distributed system should continue to function even when network partitions occur, due to nodes in the system becoming separated from each other due to network failures or other issues.

In other words, the CAP theorem proposes that it's only possible to have two of the three guarantees at any given time. This means that a highly available and partition-tolerant system must sacrifice consistency; a highly consistent and partition-tolerant system must sacrifice availability; and a system with high availability and consistency must sacrifice partition tolerance.

If the database is not partitioned, then it can be both consistent and available (sometimes known as a CA database). This is exactly the case in the traditional database with a large central server (i.e., a single-node system). If the database is partitioned, then it can prioritize consistency (CP) or prioritize availability (AP). Updates made on one node can be transferred to the other node, with some latency, over the network connection. Both sets of users can eventually see consistent data. But if there is a failure, such as a loss of the network connection between Node 1 and Node 2, then there are two possibilities:

+   (a) Prevent access to one node. This assures consistency on the working node but removes availability for users on the other node (the CP option).
+   (b) Allow access to both nodes. The system remains available for all users, but updates on one node cannot reach the other, thus losing consistency (the AP option).

This example is obviously trivial, but it illustrates the balance that must be considered in a distributed system. There is no single right answer, as the choice depends on the purpose that the application is intended to serve. A financial system may prefer consistency, but a social media platform may prefer availability. Different distributed systems may explore different compromises in trading off some loss of consistency against some loss of availability.
