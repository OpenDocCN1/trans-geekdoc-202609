## 16.3 JSON

JSON stands for JavaScript Object Notation, which describes its origin and function very clearly. Like XML, JSON is a text-based format that makes it very easy to interchange data between different systems. Each system can store the data in its own internal form for efficient processing, but these internal representations do not need to be the same. JSON was first defined by Douglas Crockford in the early 2000s as a format for data interchange, but it subsequently became widely adopted as a convenient way of expressing data structure and is supported in most programming languages. An early “informational” standard (Crockford, 2006) was followed by the first international standard (ECMA-404) in 2013. The syntax of JSON is very simple and is a slightly modified version of JavaScript syntax. There are two main structural elements.

- 1. Sets of key-value pairs. A colon character separates the key and the value, as in:
- “givenName” : “Alan”,
- “familyName” : “Turing”

The key is enclosed in double quotes. Successive items are separated by a comma character and the set is enclosed in braces. The order of items in the set is not significant. Such sets are termed “objects” from their JavaScript origins.

- 2. Arrays containing an ordered collection of values. Values are separated by comma characters. An array is enclosed in square brackets.

Whitespace characters (space, tab, newline, ...) outside quoted values are ignored. Values can be a string, a number, a Boolean, the special value null, or either of the structured types (objects and arrays). The broad guidelines are that arrays are used for collections of similar items and objects are used for collections of properties for an individual item.

The JSON syntax is slightly different to JavaScript, which does not require quoted keys and allows other possible values, such as functions, but the general style is similar. This makes JSON processing in JavaScript very straightforward, and the language has built-in functions for handling JSON text. JSON.parse() converts a text representation into a JavaScript object structure and JSON.stringify() converts a JavaScript object structure into text. Similar functionality is provided in other object-oriented languages. One noticeable absence from JSON is any capability for expressing comments. This was a deliberate choice made by its designers but has been a source of frustration for many users.

This straightforward processing is a distinct advantage over XML, which requires a more complex parser to process text into an internal representation and provides only indirect access to data values.

The nesting of entities (e.g., objects containing objects) produces a hierarchical structure in much the same way as XML, but JSON also provides arrays, which have no direct equivalent in XML. Like XML, a JSON file can be opened and edited with nothing more than a simple text editor. Human readability can be helped by sensible use of whitespace characters, but dedicated editors, sensitive to JSON structure, are also available. JSON files are generally more compact than the equivalent XML representation of the same data.

Another difference between XML and JSON is the approach to data typing. XML, like SQL, has an extensive range of data types that can be specified in a schema. JavaScript is a dynamically typed language, and this is carried over into JSON, which has only three scalar data types: string, number, and Boolean (plus null, which, like SQL, indicates the absence of a value). Numbers can be integer or floating point, and Booleans have the value true or false.

JSON support is available in many languages, not just JavaScript. Once a JSON file is loaded into the language of choice, the standard facilities of that language can be used to carry out operations on the data in the usual way, such as iterating over the members of a collection. Extracting data from the object structure created by loading the JSON file requires code in JavaScript, Python, C#, or whatever host language is being used. Strictly speaking, JSON refers to the text format, so once it has been loaded, it is no longer JSON but a structure of the kind appropriate to the language. The syntax may vary by language, there may be different conventions for single versus double quotes, and so on. Data operations are normally carried out on this internal structure, not on the JSON text. Each language will also provide some function to carry out the reverse process to output a textual representation of the inner structure. Different languages may change the format slightly by introducing extra whitespace characters into the output. This does not change the data, but it means that results may not be identical if moving from one programming language to another.

Like XML, a JSON file can be described precisely with a schema. The JSON Schema specification describes the structure, constraints, and validation rules for JSON documents. JSON Schema is itself written in a JSON format. It uses JSON objects to describe the structure of the data it validates. This means that JSON Schema documents themselves can be validated. The expected properties of an object can be defined, each property with its own validation rules and data types. This includes maximum and minimum values for numeric properties, maximum and minimum and lengths for strings, regular expression patterns, and special formats such as email or URL. Array properties can be specified with data types and maximum and minimum numbers of items. JSON Schema includes many other features that we will not cover here. The specification is constantly reviewed and updated and is freely available. There are many tools available for validation of JSON against a specific schema, generating a JSON schema, generating code from a schema, and so on. As with XML Schema, we will not delve into the full details here.
