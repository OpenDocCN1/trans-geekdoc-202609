
In this case, the FL-HPO problem can be stated in the two following ways depending on the desired goals:

(i) For a global holdout dataset `D'` (also known as validation set, possibly from the same distribution as the aggregated dataset `D`), the target problem is

```
\min\limits_{\substack{\mathbf{\phi} \in \mathbf{\Phi},\mathbf{\theta}_{G} \in \mathbf{\Theta}_{G}, \\ \mathbf{\theta}_{L}^{(m)} \in \mathbf{\Theta}_{L},m \in \lbrack n\rbrack}}\mathcal{L}\left( \mathcal{F}\left( \mathcal{M},\mathbf{\phi},\mathbf{\theta}_{G},\left\{ \mathbf{\theta}_{L}^{(m)} \right\}_{m \in \lbrack n\rbrack},\mathcal{A},\bar{D} \right);D^{\prime} \right).
```

(13.3)

(ii) An alternative FL-HPO problem would involve per-client holdout datasets `D[m]'`, `m ∈ [n]` as follows:

```
\min\limits_{\substack{\mathbf{\phi} \in \mathbf{\Phi},\mathbf{\theta}_{G} \in \mathbf{\Theta}_{G}, \\ \mathbf{\theta}_{L}^{(m)} \in \mathbf{\Theta}_{L},m \in \lbrack n\rbrack}}\mathsf{Agg}\left\{ \mathcal{L}\left( \mathcal{F}\left( \mathcal{M},\mathbf{\phi},\mathbf{\theta}_{G},\left\{ \mathbf{\theta}_{L}^{(m)} \right\}_{m \in \lbrack n\rbrack},\mathcal{A},\bar{D} \right);D_{m}^{\prime} \right) \right\}_{m \in \lbrack n\rbrack},
```

(13.4)

where `Agg : ℝ^(n) → ℝ` is some aggregation function (such as weighted average or maximum) that scalarizes the `n` per-client predictive losses.

Contrasting problem [(13.1)](#Chp013_237-255_B9780443190377000223.xhtml#deq1) to problems [(13.3)](#Chp013_237-255_B9780443190377000223.xhtml#deq3) and [(13.4)](#Chp013_237-255_B9780443190377000223.xhtml#deq4), we can see that the FL-HPO is significantly more complicated than the centralized HPO problem. In the ensuing presentation, we focus on problem [(13.3)](#Chp013_237-255_B9780443190377000223.xhtml#deq3) although much of it also applies to problem [(13.4)](#Chp013_237-255_B9780443190377000223.xhtml#deq4). The problems [(13.3)](#Chp013_237-255_B9780443190377000223.xhtml#deq3) and [(13.4)](#Chp013_237-255_B9780443190377000223.xhtml#deq4) differ in the objective they wish to optimize – one optimizes for the performance on a global data distribution while the other optimizes for an aggregate over the performances on the per-client distribution.

### 13.1.2 Challenges and goals

HPO in the centralized setting has been studied extensively [[32]](#Chp013_237-255_B9780443190377000223.xhtml#br0160) and it might seem intuitive to explore the direct applicability in the FL setting. However, there are some basic technical issues that make it infeasible.

*   Existing HPO techniques to solve problem [(13.1)](#Chp013_237-255_B9780443190377000223.xhtml#deq1) with centralized training often make use of the entire dataset (not only a centralized training dataset but also a centralized validation dataset), which is not available in FL.
*   Centralized HPO schemes train a vast variety of models for a large number of HP configurations which would be prohibitively expensive in terms of communication and training time in FL settings.
*   Personalization of models have received wide attention in FL [[8](#Chp013_237-255_B9780443190377000223.xhtml#br0040),[18](#Chp013_237-255_B9780443190377000223.xhtml#br0090),[22]](#Chp013_237-255_B9780443190377000223.xhtml#br0110). However, personalization of models as well as personalization of HPs adds another level of complexity to the whole FL-HPO problems [(13.3)](#Chp013_237-255_B9780443190377000223.xhtml#deq3); whether to personalize or not can itself be a hyper-parameter for each client!
*   It is not clear how existing centralized HPO schemes can handle the different kinds of HPs in FL-HPO problem [(13.3)](#Chp013_237-255_B9780443190377000223.xhtml#deq3) that do not exist in the centralized HPO problem [(13.1)](#Chp013_237-255_B9780443190377000223.xhtml#deq1).

Another important challenge that has not been adequately explored in FL literature is the support for tabular data, which are widely used in enterprise settings [[23](#Chp013_237-255_B9780443190377000223.xhtml#br0115),[24]](#Chp013_237-255_B9780443190377000223.xhtml#br0120). One of the best models for this setting is based on gradient boosting tree algorithms [[11]](#Chp013_237-255_B9780443190377000223.xhtml#br0055) which are different from the stochastic gradient descent algorithm used for neural networks. Recently, a few approaches have been proposed for FL-HPO, however, they focus on handling HPO using personalization techniques [[20]](#Chp013_237-255_B9780443190377000223.xhtml#br0100) and neural networks [[19]](#Chp013_237-255_B9780443190377000223.xhtml#br0095), and we will provide a detailed review of these approaches in Section [13.2](#Chp013_237-255_B9780443190377000223.xhtml#s0025). To the best of our knowledge, there is no HPO approach for FL systems to train non-neural network models, such as `XGBoost` [[5]](#Chp013_237-255_B9780443190377000223.xhtml#br0025) that is particularly common in the enterprise setting. In this chapter, we first provide an overview of the FL-HPO literature and discuss how these different existing schemes fare against the above technical challenges in solving problem [(13.3)](#Chp013_237-255_B9780443190377000223.xhtml#deq3). Then, we consider a version of the FL-HPO problem [(13.3)](#Chp013_237-255_B9780443190377000223.xhtml#deq3) and present the `FLoRA` algorithm [[41](#Chp013_237-255_B9780443190377000223.xhtml#br0205),[42]](#Chp013_237-255_B9780443190377000223.xhtml#br0210) in Section [13.3](#Chp013_237-255_B9780443190377000223.xhtml#s0030). This algorithm has the following unique properties we will discuss in detail:

*   **(C1)** It can be applied to any machine learning model such as tree ensembles, kernel machines, as well neural networks and linear models.
*   **(C2)** It can **perform "single-shot" FL-HPO**, and hence is useful in situations where we have *limited* resources (in the form of computation and communication overhead), requiring only a single model via federated learning (that is, a single HP configuration).
*   **(C3)** It does not *assume that clients have independent and identically distributed (IID) data distributions* and hence is able to handle heterogeneity between the per-client data distributions.

## 13.2 State-of-the-art FL-HPO approaches

In this section, we provide a general overview of the recent advance in FL-HPO approaches.

One of the main challenges in FL is achieving high accuracy and low communication overhead. `FedAvg` [[25]](#Chp013_237-255_B9780443190377000223.xhtml#br0125) is a predominant algorithm used for training in FL and several optimization schemes build on it. It is executed in multiple global rounds. At each round, the clients perform stochastic gradient descent (`SGD`) updates on their parameters based on their local objective functions. They subsequently send their updates to the server, which averages them and transmits their mean back to the clients. Several approaches have been devised for optimizing the communication performance of FL systems. Initially, communication optimizations included performing multiple `SGD` local iterations at the clients and randomly selecting a small subset of the clients to compute and send updates to the server [[25]](#Chp013_237-255_B9780443190377000223.xhtml#br0125). Subsequently, compression techniques were used to minimize the size of model updates to the server. It has been shown that the accuracy and communication performance of these techniques depend highly on their HPs [[25]](#Chp013_237-255_B9780443190377000223.xhtml#br0125).
