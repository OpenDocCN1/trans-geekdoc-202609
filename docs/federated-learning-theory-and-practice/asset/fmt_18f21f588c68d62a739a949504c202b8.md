
Sample-level DP in FL follows the same notion as centralized-DP [[1]](#Chp003_57-74_B9780443190377000119.xhtml#br0005), which aims to protect each sample in the union of all datasets $\mathcal{D} = \bigcup_{m = 1}^{n}\mathcal{D}_{m}$ (see [Definition 3.2](#Chp003_57-74_B9780443190377000119.xhtml#enun0015)). As discussed earlier, this notion of DP is useful for *cross-silo* FL problems. Similar to DP-SGD, a natural approach to ensure sample-level DP for FedAvg is to introduce gradient clipping and noise injection during the local updates in step 7 of [Algorithm 1](#Chp003_57-74_B9780443190377000119.xhtml#f0010). Below, we discuss FedAvg with sample-level DP guarantees.

#### 3.3.1.1 Algorithms and discussion

In [Algorithm 3](#Chp003_57-74_B9780443190377000119.xhtml#f0020), we state the Sample-Level DP FedAvg. Note that [Algorithm 3](#Chp003_57-74_B9780443190377000119.xhtml#f0020) ensures sample-level DP guarantees by adding a clipping and a noise injection procedure for the stochastic gradients evaluated at each local update. Sample-level DP has been proposed in [[30]](#Chp003_57-74_B9780443190377000119.xhtml#br0150), in a more general form with secure multi-party encryption protocol deployed for secure aggregation of the model parameters. Though [[30]](#Chp003_57-74_B9780443190377000119.xhtml#br0150) has not provided convergence or DP guarantees for the proposed approach, it has numerically demonstrated its effectiveness. In [[12]](#Chp003_57-74_B9780443190377000119.xhtml#br0060), convergence guarantees for [Algorithm 3](#Chp003_57-74_B9780443190377000119.xhtml#f0020) have been established for the case when individual clients use a single-step gradient descent for local updates, the per sample gradient norm is bounded, no gradient clipping is used, and all the clients participate in training. Specifically, [[12]](#Chp003_57-74_B9780443190377000119.xhtml#br0060) showed the following result.

**Theorem 3.5**

**Sample-level DP-FedAvg [[12]](#Chp003_57-74_B9780443190377000119.xhtml#br0060)**

*For $\epsilon, \delta > 0$, if the loss $\ell[m](\mathbf{x}[m], c[m])$ is G-Lipschitz then [Algorithm 3](#Chp003_57-74_B9780443190377000119.xhtml#f0020) is $(\epsilon, \delta)$-DP if we choose*

$$\sigma \geqslant c\frac{G \cdot \sqrt{\tau \cdot \log(1/\delta)}}{|\mathcal{D}| \cdot \epsilon},$$

*where $c > 0$ is some constant and $|\mathcal{D}|$ is the total number of samples.*

Note that the above guarantee resembles that in [Theorem 3.4](#Chp003_57-74_B9780443190377000119.xhtml#enun0040), but there is no privacy amplification compared to [Theorem 3.4](#Chp003_57-74_B9780443190377000119.xhtml#enun0040) as the local nodes utilize full gradients for the local updates. The authors in [[12]](#Chp003_57-74_B9780443190377000119.xhtml#br0060) also provide optimization guarantees for the cases when the objective function $g(\mathbf{w})$ (see Problem [(3.1)](#Chp003_57-74_B9780443190377000119.xhtml#deq1)) is strongly convex or satisfies the Polyak–Lojasiewicz condition. Later [[17]](#Chp003_57-74_B9780443190377000119.xhtml#br0085) extended sample-level DP-FedAvg developed in [[12]](#Chp003_57-74_B9780443190377000119.xhtml#br0060) for stochastic local updates and partial client participation. Different from [Algorithm 3](#Chp003_57-74_B9780443190377000119.xhtml#f0020), the authors in [[17]](#Chp003_57-74_B9780443190377000119.xhtml#br0085) injected noise only after all the local updates are concluded, also since the per-sample gradient norms have been assumed to be bounded, the clipping operation was not used. Specifically, [[17]](#Chp003_57-74_B9780443190377000119.xhtml#br0085) shows that to achieve an $(\epsilon, \delta)$-privacy guarantee for each communication round, we require

$$\sigma \geqslant \sup_{m \in [n]}\left\{ c\frac{G \cdot \tau_{m}^{2} \cdot q_{m} \cdot \sqrt{\log(1.25q/\delta)}}{\epsilon} \right\}$$

(3.4)

*for some constant $c > 0$ and where $q[m] = B[m]/|\mathcal{D}[m]|$ with $B[m]$ being the batch size and $|\mathcal{D}[m]|$ the dataset size at agent $m$. The above Eq. [(3.4)](#Chp003_57-74_B9780443190377000119.xhtml#deq6) implies that if we choose a larger batch size $B[m]$, and a large number of local updates $\tau[m]$, we will need a higher noise level for DP protection. In contrast, for FedAvg it is observed that a larger batch size and a larger number of local updates might help speed-up convergence [[27]](#Chp003_57-74_B9780443190377000119.xhtml#br0135). This implies that there is a trade-off between the DP guarantees and the algorithm's convergence speed. The authors in [[17]](#Chp003_57-74_B9780443190377000119.xhtml#br0085) further analyze the optimization performance of sample-level DP FedAvg to understand this trade-off.*

Next, we discuss some other works that address sample-level DP in the context of FL. In [[11]](#Chp003_57-74_B9780443190377000119.xhtml#br0055), the DP algorithm based on alternating direction method of multipliers (ADMM), DP-ADMM, is proposed. Similarly, [[18]](#Chp003_57-74_B9780443190377000119.xhtml#br0090) develops a stochastic primal–dual algorithm for FL with differential privacy. The authors in [[3]](#Chp003_57-74_B9780443190377000119.xhtml#br0015) propose a coordinate decent algorithm that incorporates the DP framework. In [[4]](#Chp003_57-74_B9780443190377000119.xhtml#br0020), with the goal of reducing the communication overhead while keeping the information private, the normalized and quantized gradients are transmitted. The work in [[23]](#Chp003_57-74_B9780443190377000119.xhtml#br0115) investigates the trade-off between communication costs and training variance under a resource-constrained FL system.

In the next subsection, we discuss the client-level DP for FL in detail.

### 3.3.2 Client-level DP

In this subsection, we discuss the algorithms for the client-level DP where the goal is to protect the identities of clients in contrast to individual samples (see [Definition 3.3](#Chp003_57-74_B9780443190377000119.xhtml#enun0020)) so that an adversary could not identify which client has participated in the training by the information transmitted. Similar to sample-level DP, clipping and noise injection are the two mechanisms that ensure client-level DP. However, in contrast to sample-level DP where we clip the stochastic gradients before *each* local update, in client-level DP, there are multiple ways to implement the clipping operation. Below we discuss the major clipping strategies that protect the client-level DP for FL algorithms.

#### 3.3.2.1 Clipping strategies for client-level DP
