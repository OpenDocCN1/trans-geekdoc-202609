## JSON over HTTP Services 在分布式系统中的位置

JSON over HTTP APIs 是网络上最常见的 API，原因充分。它们易于构建，因为大多数语言都内置 JSON 支持，并且易于使用，因为 JSON 是人类可读的，你可以通过终端使用 curl、在浏览器中访问站点，或使用各种优秀的 HTTP 客户端调用 HTTP API。如果你有一个想快速实现并让人尝试的 Web 服务构想，那么使用 JSON/HTTP 是最佳选择。

JSON/HTTP 不仅适用于小型 Web 服务。大多数提供 Web 服务的科技公司至少有一个 JSON/HTTP API 作为其服务的公共 API，供公司内部前端工程师使用，或供公司外部工程师构建第三方应用。对于内部 Web API，公司可能会使用 protobuf 等技术来提供 JSON/HTTP 所不具备的功能（如类型检查和版本控制），但公共 API 仍然是 JSON/HTTP，因为其可访问性。这一点在我目前和之前任职的公司中均适用。在 Segment，我们多年来使用 JSON/HTTP 架构处理每月数十亿次 API 调用，之后才改为使用 protobuf/gRPC 以提升效率。在 Basecamp，所有服务均基于 JSON/HTTP，据我所知至今仍然如此。

JSON/HTTP 是基础设施项目 API 的绝佳选择。像 Elasticsearch（流行的开源分布式搜索引擎）和 Etcd（许多项目（包括 Kubernetes）使用的流行分布式键值存储）的客户端 API 也使用 JSON/HTTP，而内部节点间通信则使用自己的二进制协议以提升性能。JSON/HTTP 并非玩物——你可以用它构建各种类型的服务。

Go 在其标准库中提供强大的构建 HTTP 服务器和处理 JSON 的 API，使其非常适合构建 JSON/HTTP Web 服务。我曾使用 Ruby、Node.js、Java、Python 编写 JSON/HTTP 服务，但发现 Go 是最愉快的语言。这是因为 Go 的声明式标签与标准库中的 JSON 编码包 (encoding/json) 的出色 API 相结合，省去了其他语言中需要手动编写的繁琐序列化代码。现在，让我们直接进入正题。

## 构建 JSON over HTTP 服务器

现在我们将编写 JSON/HTTP Web 服务器。Go Web 服务器由一个函数（net/http.HandlerFunc）组成，它处理每个 API 端点。我们的 API 有两个端点：Produce 用于写入日志，Consume 用于读取日志。在构建 Go 的 JSON/HTTP 服务器时，每个处理函数包含三个步骤：

1.  解析请求体的 JSON 并反序列化为结构体。
2.  运行该端点的逻辑以获取结果。
3.  序列化结果并写入响应。

如果你的处理函数变得过于复杂，建议将代码移至中间件中，将请求和响应处理与业务逻辑分离。
