# Chapter 2  

## Structure Data with Protocol Buffers

在构建分布式服务时，你需要在服务之间通过网络进行通信。为了在网络上传输数据（例如结构体），你需要将数据编码为一种格式，而许多程序员选择 JSON。当你构建公共 API 或创建一个你不控制客户端的项目时，JSON 很合理，因为它既易于人阅读，也易于计算机解析。但当你构建私有 API 或创建一个你控制客户端的项目时，你可以使用一种结构化和传输数据的机制——与 JSON 相比，它能让你更高效，并帮助你构建更快、功能更丰富、更少错误的服务。

那么，这个机制是什么呢？Protocol Buffers（也称为 protobuf），这是 Google 的语言和平台中立的可扩展机制，用于结构化和序列化数据。使用 protobuf 的优势包括：

*   保证类型安全；

*   防止 schema 违规；

*   实现高速序列化；和

*   提供向后兼容性。

Protobuf 让你定义想要如何结构化数据，将 protobuf 编译成多种语言的代码，然后读取和写入结构化数据到不同的数据流中。Protocol Buffers 适合在两个系统之间（例如微服务）进行通信，这也是为什么 Google 在构建 gRPC 时使用了 protobuf 来开发高性能的远程过程调用（RPC）框架。

如果你以前从未使用过 protobuf，你可能会有一些我曾经有的顾虑——protobuf 看起来像是很多额外的工作。我向你保证，在本章以及本书其余部分中使用它后，你会发现它其实并不那么难。与 JSON 相比，它提供了许多优势，并且能为你节省大量工作。

## Why Use Protocol Buffers?

Protobuf 提供了各种有用的功能：

Consistent schemas

: 

使用 protobuf，你一次编码语义，并在所有服务中使用它们，确保整个系统的数据模型一致。我们在上一家和上一家公司构建的微服务基础设施中，都有一个名为“structs”的仓库，里面存放了 protobuf 及其编译代码，所有服务都依赖于它。通过这样做，我们确保了不会向生产环境发送多个不一致的 schema。借助 Go 的类型检查，我们可以更新结构体依赖，运行触及数据模型的测试，编译和测试会告诉我们代码是否与 schema 一致。

Versioning for free

: 

Google 创建 protobuf 的动机之一是消除版本检查的需求，防止出现像下面这样丑陋的代码：

[StructureDataWithProtobuf/example.go](http://media.pragprog.com/titles/tjgo/code/StructureDataWithProtobuf/example.go) 

| ​  || ​**if**​ (version == 3) { |

| --- | --- |

| ​  || ... |

| ​  || } ​**else**​ ​**if**​ (version > 4) { |

| ​  || ​**if**​ (version == 5) { |

| ​  || ... |

| ​  || } |

| ​  || ... |

| ​  || } |

: 

将 protobuf 消息视为 Go 结构体，因为编译后的消息会转换为结构体。使用 protobuf 时，你为消息中的字段编号，从而确保在滚动新功能和修改 protobuf 时保持向后兼容。因此，很容易添加新字段，中间服务器如果不需要使用该数据，只需解析并透明传递即可，无需了解所有字段。同样，移除字段时，你可以通过标记为保留字段来确保已废弃字段不再被使用；编译器会在有人尝试使用已废弃字段时报错。

Less boilerplate

: 

protobuf 库负责编码和解码，这意味着你无需手写这些代码。

Extensibility

: 

编译器支持插件，可以自定义生成代码的逻辑。例如，你可能希望多个结构体共享一个方法。通过 protobuf，你可以编写插件自动生成该方法。

Language agnosticism

: 

Protobuf 在许多语言中实现：自从 Protobuf 3.0 起，支持 Go、C++、Java、JavaScript、Python、Ruby、C#、Objective C、PHP，以及第三方支持的其他语言。你无需做额外工作即可在不同语言的服务之间通信。这对于拥有多个团队使用不同语言的公司很有帮助，或者当团队希望迁移到另一种语言时非常有用。

Performance

: 

Protobuf 高度性能，负载更小，序列化速度比 JSON 快多达六倍。^([\[3\]](#f_0024.xhtml#FOOTNOTE-3))

gRPC 使用 protobuf 定义 API 并序列化消息；我们将使用 gRPC 构建客户端和服务器。

希望我已经说服了你 protobuf 是很酷的。但理论本身很无聊！让我们开始创建自己的 protobuf 并使用它构建东西。
