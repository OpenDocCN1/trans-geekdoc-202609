

# 云架构与交通管理系统

云帮助我们维护和同步一个中心化数据库，同时提供为所需系统设置实时更新的能力，维护产品的整体完整性。在云架构中，多个云组件使用应用程序编程接口（API），通常是 Web 服务，相互连接。这些系统比典型的单体系统更易于管理，因为它们将复杂性控制在可控范围内。云架构由不同的层组成，即：基础设施即服务（IaaS）、平台即服务（PaaS）和软件即服务（SaaS）。数据存储在全球多个数据中心的云数据库中。云数据库结构不同于关系数据库管理系统。它拥有多个用于查询服务的节点。这是为了让数据库能够通过云服务轻松且完整地访问。对等通信是处理用户实施的任何查询的最佳选择。云数据库中的每个节点都有一张指向每个节点所含数据的映射表。这张存储数据的映射表使得访问回答特定查询所需的信息变得简单直接。

无论节点是被添加到集群中还是从集群中撤出，确定何时传输协同工作的数据块的路由方法和算法都能确保数据持续可用。当数据需求被复制到新安装的节点时，数据将从原始位置提供服务。一旦新节点拥有了数据的最新版本，路由机制就会开始将请求导向该新节点。

## 7.4.1 基于云的车辆与交通控制系统

拟议系统关注交通信号灯状态、车辆密度和道路相对速度，以实现现代智慧城市的完整交通管理。为确保交通顺畅，交通信号灯管理应高度可靠且一致，而交通密度和速度监控应高度可用，但由于车辆移动，有时可能不一致。如[图 7.2](#chapter7.xhtml#fig7_2)所示，系统主要分为两部分：本地交通管理系统和全局交通监控服务。该服务的关键组件是小型本地 Redis 数据库，由一项服务管理，用于按区域通过交通信号灯进行交通控制，以存储少量车辆的即时数据。对于交通信号控制和其他操作，在小范围区域内，可使用 Redis 数据库形式的临时存储。全局交通监控服务监控速度、位置、发动机状态以及与可扩展 MongoDB 集群和 SQL 数据库共享的车辆身份（ID）对应的每辆车的其他记录。

它还使用图数据库存储道路的地图和连接以及地理坐标点。在该系统中，每辆车将其数据发送到一个通用服务，该服务再根据需要将数据分发给本地和全局交通监控系统。

## 7.4.2 本地交通管理系统

本地交通管理系统由三项服务组成：本地数据馈送器、交通密度分析器和交通信号灯控制器。

本地数据馈送服务将接收每辆车在相应道路上的速度和位置，并将其存储在该区域的 Redis 数据库中。交通密度分析服务将处理 2-3 分钟跨度内收集的车辆数据，并计算平均交通密度和速度。根据交通密度分析服务的结果、相邻道路交通信号灯的当前状态以及是否存在应急车辆，交通信号灯控制器将决定交通信号的变化。汽车使用 MQTT 协议与本地交通管理和全局交通监控进行通信。

## 7.4.3 全局交通监控系统

全局交通监控系统包含几项服务：全局数据馈送器、交通违规检查器、最优路径查找服务和应急服务，如[图 7.3](#chapter7.xhtml#fig7_3)所示。全局数据馈送服务负责收集地理位置、平均速度、车辆 ID 和类型等数据，并将所需值存储在数据库中。交通违规检查服务将监控车辆状况，如速度、闯红灯违规，并在数据库中记录相应的罚款。违规车辆可通过唯一 ID 被识别并因违规被罚款。最优路径查找服务将利用沿途每条道路的本地交通管理系统中的本地交通密度分析器，为车辆提供最优或耗时最少的路线。在发生任何紧急情况时，应急服务将利用传感器发送警报或消息，以便交通系统相应地改变其状态。

## 7.5 工作流程

系统架构的设计使其整合为单一工作流，以高效且同步的方式同时实现汽车自动驾驶和交通管理，如[图 7.4](#chapter7.xhtml#fig7_4)所示。

![图 7.4 工作流程。](images/fig7_4.jpg)

[图 7.4](#chapter7.xhtml#b7fig7_4) 工作流程。

车辆将在云系统中充当一个节点。车辆启动时，会连接到云并从云收集数据。导航设置完成后，汽车开始根据 SLA 算法驾驶，通过感知环境和障碍物。云将向本地交通桩设备提供所需信息。随后车辆与本地交通设备连接并完成同步，以在道路上导航。由于每辆本地车辆都连接到云交通系统，间接地，交通设备部分控制着车辆的速度和方向。传感器从环境中收集实时数据，数据被送入传感器处理单元（SPU），在那里数据被处理并生成一个独特的虚拟环境，根据这些数据，汽车了解周边情况并在道路上行驶。此外，在行程期间，车辆持续向云提供数据，用于深度学习方法，以更高效地更新自动驾驶算法并高效同步其他车辆。用于设计 SLA 模型的深度学习算法解释如下。
