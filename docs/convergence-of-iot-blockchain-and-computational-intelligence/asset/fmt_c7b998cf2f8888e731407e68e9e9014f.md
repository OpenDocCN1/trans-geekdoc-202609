
# 数学模型与公式

## 网络能量损耗
$$E_{\text{network}} = \frac{\text{Total number of packets dropped by network}}{\text{Total number of packets received by the sink}}$$

## 传感器节点剩余能量
$$E_r = \frac{\text{Remaining energy}}{\text{Initial energy}}$$

## 数据包投递率
数据包投递率对于评估数据传输性能至关重要，因为由于干扰，数据包丢失可能发生在网络的任何步骤中。

$$\text{Packet delivery rate} = \frac{\text{No. of packets received by sink}}{\text{No. of packets generated by the source}}$$

## 峰值信噪比 (PSNR)
“峰值信噪比 (PSNR)”用于确定解码器处视频序列的质量 [[25]](#chapter14.xhtml#ref14_25)：

$$\text{PSNR} = 20 \log \frac{255}{\sqrt{\text{MSE}}}$$

其中 `MSE` 是均方误差。

# 14.3.2.4 根据数据类型进行数据传输

通常，大量实时数据与多媒体系统和源相结合 [[26]](#chapter14.xhtml#ref14_26)。由于这一需求，产生了高比特率以维持质量和应用。因此，需要一种既能满足多媒体通信需求，又兼容传感器节点特性的协议 [[27]](#chapter14.xhtml#ref14_27)–[[29]](#chapter14.xhtml#ref14_29)。

在 MPEG 服务器或视频编码器等多媒体数据流中，图像（“I、P 和 B 帧”）、视频和音频都被划分为帧。每一帧具有不同级别的可靠性。基于这一级别，数据通信仅限于图像传输。`PR-SCTP` 协议可用于实现一种新的建议传输协议，该协议提供各种级别的可靠性 [[30]](#chapter14.xhtml#ref14_30)。由于存在三种图像数据，数据通过三个流传输（参见 [图 14.2](#chapter14.xhtml#fig14_2)）。

![图 14.2 根据数据类型进行多媒体数据传输](images/fig14_2.jpg)

**[图 14.2](#chapter14.xhtml#b14fig14_2) 根据数据类型进行多媒体数据传输。**

`I` 帧传输由流 1 表示，具有最高优先级。如果 `I` 帧在数据传输过程中损坏或丢失，则直到下一个 `I` 帧为止的 `P` 帧和 `B` 帧将变得毫无价值 [[31]](#chapter14.xhtml#ref14_31)。该传输可分为两部分：队列优先级和数据传输差异化。此处重点关注基于数据类别的数据传输。

[图 14.3](#chapter14.xhtml#fig14_3) 中基于数据类型的多媒体数据传输流程图使用了 `PR-SCTP` 和 `TC-SCTP` 协议。

![图 14.3 多媒体数据传输流程图](images/fig14_3.jpg)

**[图 14.3](#chapter14.xhtml#b14fig14_3) 多媒体数据传输流程图。**

为避免不必要的数据传输，`PR-SCTP` 通过降低每个数据的重复率，根据数据优先级改变传输。在发送数据前，`TC-SCTP` 对每个数据的传输时间进行同样的目的性检查。因此，上述有线网络协议需要一种新协议来使用 `IEEE 802.15.4` `WSN` 算法。

该协议用于限制 `TC-SCTP` 持续时间，并决定接收端缓冲区上的数据是否可播放 [[32]](#chapter14.xhtml#ref14_32)。该建议协议仅使用单个缓冲区，不需要唯一的时间限制。发射时间根据发射端接收部分允许播放所有数据的最大时间进行评估分配。

- `Tp` 为接收端数据播放时间
- `Tos` 为偏移延迟
- `Tr` 为从顶层获取数据的时间

`Tos` 定义为从顶层在接收端接收数据的最大时间量。因此：

$$T_p = T_{os} + T_r$$

为确保源和目标之间可靠的数据传输，避免不必要的传输，以便缓冲区控制传输前传输所有数据的传输时间 `T[x]`。如果传输时间较长，数据将成功传输到接收端。否则，发射端将不继续传输并删除缓冲区数据。

$$T_x = T_p - T$$

计算传输时间后，检查数据类型是 `I` 帧、`P` 帧还是 `B` 帧，以满足传输时间 `T[X]` 的条件。

`Th1`、`Th2` 和 `Th3` 是使用重传超时 (`RT`) 确定的阈值。

$$Th_1 = (RT \times 2) + a[1]$$
$$Th_2 = (RT \times 1) + a[2]$$
$$Th_3 = (RT \times 2) + a[3]$$

其中 `a[1]`、`a[2]` 和 `a[3]` 为常数。

- 若数据为 `I` 帧，则 `T[x]` 大于 `Th1`，随后数据将传输到流 1。
- 若数据为 `P` 帧，则 `T[x]` 大于 `Th2`，随后数据将传输到流 2。
- 若数据为 `B` 帧，则 `T[x]` 大于 `Th3`，随后数据将传输到流 3。
- 若 `T[x]` 小于 `Th3`，则数据被丢弃而不传输。

# 14.4 协议比较

在本部分中，根据消息传递的可靠性、能量效率和干扰控制，对某些现有的传输协议进行了比较。现有协议无法满足所有需求。许多协议不关注可靠性方法，仅关注拥塞控制。但目前有三种协议同时提供传输层、可靠性和拥塞控制能力 [[33]](#chapter14.xhtml#ref14_33)–[[36]](#chapter14.xhtml#ref14_36)。几乎所有协议都使用隐式拥塞通知方法、队列长度过程进行拥塞检测阶段，以及精确速率调整方法。子节点可以通过改变速率来降低传输速率，以防止更多父节点拥塞 [[11]](#chapter14.xhtml#ref14_11)。精确速率调整是一种已知技术，其中节点在指定时间调度数据包传输，以满足预期速率进行特殊速率调整 [[11]](#chapter14.xhtml#ref14_11)。

传输层最关键的功能是可靠性，它确保数据从源正确传递到目标或汇聚节点。由于大多数建议协议基于应用，因此存在许多可靠性策略。此外，许多协议采用否定确认 (`NACK`) 和超时来检测丢失，以及通知和数据包重传来恢复丢失。未来应开发与广泛应用程序互操作的协议。提供可靠性机制的现有传输协议总结见 [表 14.1](#chapter14.xhtml#tbl14_1)。提供干扰控制的现有传输协议总结见 [表 14.2](#chapter14.xhtml#tbl14_2)。
