
为了管理大型网络产生的海量数据，需要一种技术来高效管理传输给接收端的数据。物联网拥有应用层协议来完成这种管理。要交换数据，节点必须注册为网络的成员；这个过程称为订阅。一旦节点完成订阅，发布者就可以获取与服务相关的数据；当数据发布时，这被称为发布/订阅过程。当部署大量节点时，这种方式很合适。对于极少量的节点，可以执行请求/响应过程。在此过程中，汇聚节点通常会显式请求与服务相关的信息，并获得包含所请求数据的响应。当节点进入系统时，它会分配网络服务，并且还可以开始交换数据并作为物联网系统组件发挥作用。[表 3.2](#chapter3.xhtml#tbl3_2) 列出了物联网数据交换协议、部署平台及所提供的安全类型（[Sankar and Srinivasan, 2016](#chapter3.xhtml#ref3_18)）。

### 3.3.3.3 受限应用协议

IETF 设计了 CoAP，这是一种用于在受限环境（如较低的 RAM 容量和丢包网络）中工作的协议。它专门设计用于在无线个域网上运行并使用低功耗 (WPAN)。它是一种基于 Web 的协议，具有 HTTP 接口。它允许机器到机器应用的自动化。它采用客户端-服务器模型，客户端发起请求，服务器进行响应。即使对于大量用户，它也能提供良好的性能。它提供组播通信，消息发送给发布者，订阅者接收消息。

CoAP 是一种可靠且简单的协议，包含两层。顶层由 UDP 构建，称为消息层。另一层称为请求/响应层。它通过请求/响应消息提供可靠通信。[图 3.2](#chapter3.xhtml#fig3_2) 显示了 CoAP 消息格式，[图 3.3](#chapter3.xhtml#fig3_3) 显示了 CoAP 的客户端-服务器架构，其中交互通过 REST API 进行。CoAP 通过 UDP 传输。它采用固定大小的二进制消息格式。它包含选项和负载。消息支持可确认、非可确认、确认和重置。数据报传输层安全 (DTLS) 用作安全协议。它提供高带宽，因此连接到它的设备是可靠的。

### 3.3.3.4 消息队列遥测传输协议

MQTT 由 IBM 设计，旨在减少带宽消耗并实现可靠的数据包传输。它通过最小化流量来减少网络协议开销。MQTT 通过支持低功耗设备、组播和发布者/订阅者架构，与 CoAP 相似。它构建在 TCP/IP 模型之上。可靠传输通过三个服务质量 (QoS) 级别来考量，即至多一次、至少一次和恰好一次。最低级别是至少传输一个数据包，无需确认。中间级别支持确认，但可能有重复消息。为了仅传输一次消息并带有确认，应使用特殊协议以达到最高 QoS 级别。[图 3.4](#chapter3.xhtml#fig3_4) 显示了 MQTT 代理架构。[图 3.4](#chapter3.xhtml#fig3_4) 中的传感器节点可以是温度传感器、湿度传感器等。传感器节点收集的数据发布到 MQTT 代理，而不是直接发送给设备。代理将数据发布给已订阅的设备。因此，大量数据可以通过 MQTT 代理进行监控和控制。

### 3.3.3.5 可扩展消息与 Presence 协议

最常见的通信协议是可扩展消息与 Presence 协议 (XMPP)。其可扩展特性允许根据功能定制协议。它是一种轻量级协议，用于许多实时应用，如多方聊天、即时消息、语音通话、视频通话等。它使用传输控制协议 (TCP)。它具有高度灵活性，并采用去中心化架构实现可扩展性。发布者和订阅者启用事件通知，并作为社交网络、即时新闻推送和许多其他实时交互的基础。[图 3.5](#chapter3.xhtml#fig3_5) 表明 XMPP 客户端不直接与另一个客户端交互，而是通过 XMPP 服务器进行交互。每个客户端由一个称为 Jabber ID (JID) 的唯一 ID 标识。它由用户、服务器和资源组成。例如，如果用户访问 Facebook，则 JID 中的“用户”是“Facebook 账号”，“服务器”代表“Facebook 服务器”，资源代表访问应用程序的“移动端/桌面端”。

### 3.3.3.6 高级消息队列协议

AMQP 是一种开源的异步消息传递标准。它允许应用程序和组织之间进行安全且互操作的通信。该协议用于客户端/服务器通信和物联网应用的管理。它可靠、紧凑、安全且多通道。二进制协议提供 SASL 或 TLS 认证和加密，依赖于 TCP 等传输协议。

该消息传递协议速度快，具有确保投递并确认消息接收的特性。它由一个庞大且简单的组件组成，该组件在代理操作器中记录和存储通信，以及一组用于连接组件的策略。AMQP 协议帮助客户端系统与代理对话并连接到 AMQP 模型。[图 3.6](#chapter3.xhtml#fig3_6) 显示了 AMQP 代理将消息从发布者交换给订阅者。代理模型中的队列允许为订阅者提供有保证的服务（[Glaroudis et al., 2020](#chapter3.xhtml#ref3_6)）。

### 3.3.3.7 数据分发服务

DDS 通过发布-订阅技术，实现可扩展、实时、可靠、高性能的系统结果和互操作的数据交换。它采用较少的架构和组播代理，向高质量应用通信 QoS。[图 3.7](#chapter3.xhtml#fig3_7) 显示了发布者在集中式全局数据空间中直接与订阅者通信。DDS 旨在为系统和网络使用最少的资源。
