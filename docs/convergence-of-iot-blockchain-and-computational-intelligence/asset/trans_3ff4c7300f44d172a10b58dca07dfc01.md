
数据摄取层是第四层，包括大数据、清洗、流式处理和数据管理。`Apache Flume` 和 `Apache NiFi` 是大数据摄取工具的示例。`Apache Flume` 提供分布式服务。大量数据被收集、聚合并传输，同时保持可靠性。从多个来源收集的数据流被存储并在 `Hadoop` 中进行分析。基于数据流式处理的流向，其架构变得简单。它健壮且具备容错能力，拥有多种故障恢复机制。`Apache NiFi` 是一个易于使用、可靠的系统，广泛用于数据分发和处理。它支持数据流跟踪，为监控和控制提供无缝服务。数据通过 `SSL`、`HTTPS`、`SSH` 加密，因此是安全的。

### 3.3.4.1 存储工具

#### 3.3.4.1.1 Hadoop 分布式文件系统

一种基于 Java 的文件系统，用于大数据的安全存储，称为 `Hadoop 分布式文件系统 (HDFS)`。它具有可扩展性，可服务大型客户，并允许从大型存储库轻松访问。由于数据的多个副本存储在不同的机器上，因此保持了冗余。它采用主/从架构模型，通过划分数据并将其放置在不同的集群中，实现并行处理（[Nazini and Sasikala, 2019](#chapter3.xhtml#ref3_11)）。

#### 3.3.4.1.2 Gluster 文件系统

`Gluster 文件系统 (Gluster FS)` 是一个开源、可靠的分布式文件系统，在存储方面提供线性扩展性能。它可部署用于非结构化数据。它具有可扩展性并允许分布式存储。`Gluster FS` 可用于云计算、媒体流和内容分发。

#### 3.3.4.1.3 Amazon 简单存储服务

`Amazon 简单存储服务 (Amazon S3)` 是一种简单的对象存储 Web 服务。它提供最高的持久性，并可大规模扩展。云应用程序使用 `S3` 服务。它允许拥有具备故障恢复能力的大型数据存储库。数据迁移比其他服务更容易。存储在 `S3` 上时，成本相对降低。

### 3.3.5 数据分析

数据分析是第五层，涉及数据调查、提取和机器处理。大多数公司使用大数据分析来提高生产力、收入并降低成本。`Apache Hive`、`Apache Spark SQL`、`Amazon Redshift`、`Presto SQL 查询引擎` 是大数据查询工具的示例（[Kamilaris et al., 2017](#chapter3.xhtml#ref3_8)；[Samanta et al., 2021](#chapter3.xhtml#ref3_15)；[Vinodhini et al., 2020](#chapter3.xhtml#ref3_34)；[Karthiprem et al., 2016](#chapter3.xhtml#ref3_9)）。

#### 3.3.5.1 Apache Hive

`Apache Hive` 运行在 `Apache Hadoop` 之上。它为分析提供大型数据集，并支持通过临时查询进行汇总。用于 Hive 的 `SQL` 查询称为 `HiveQL`。它具有可扩展性；随着数据增长，会添加许多机器以提升性能。

#### 3.3.5.2 Apache Spark SQL

`Apache Spark SQL` 拥用用于结构化数据处理的 Spark 模型。它具有基于成本的优化器。它提供代码生成器以实现快速查询。其可扩展性出奇地高，且具备容错能力。

#### 3.3.5.3 Amazon Redshift

`Amazon Redshift` 在云端处理 PB 级数据。它用于查询数据处理。当 `SQL` 运行时，可按需创建数据库。可获取客户和业务洞察。整体管理由 `Redshift` 协调。这些任务包括提供集群算力、监控和备份，以及向 `Amazon Redshift` 系统部署更新和改进。

#### 3.3.5.4 Presto – SQL 查询引擎

`Presto` 是一个开源 `SQL` 数据库引擎。它以分布式方式运行，对数据源的所有数据量执行交互式分析查询。它专为商业用途设计，可大规模扩展。它从关系数据库查询数据。其目标是面向每分钟需要操作响应的分析师。`Facebook` 在许多内部数据存储中使用 `Presto`。员工执行的查询超过 40,000 条，扫描海量数据。`Dropbox` 和 `Airbnb` 是使用 `Presto` 的公司示例。

### 3.3.6 应用层

第 6 层是 `IoT` 应用的基础。该层提供客户端所需的服务。客户端可以使用任何智能应用，如智能手机、智能手表等。该层提供的服务包括身份相关服务、聚合服务和协作服务。提供给系统的身份相关支持会持续受到监控和更新。例如，考虑医疗记录的数字化。`RFID` 标签包含患者身份。从标签收集的数据被聚集并存储在数据库中。每次就诊时，记录都会更新。存储的信息通过基于 Web 或移动应用程序提取。智能电网之间的负载分发是数据聚合服务的一个示例。它审查从各种传感器获得的信息。网络分析信息并将数据馈送给 `IoT` 应用。智能家居自动化要求数据在家中的各种智能设备之间共享。这是协作服务的一个示例。它在任何时间点提供完全的控制和访问（[Perez et al., 2019](#chapter3.xhtml#ref3_13)）。

### 3.3.7 人员与流程层

人员与流程层还涉及基于 `IoT` 计算的业务交互和决策制定。在大规模实施 `IoT` 时，安全性和数据完整性是关注的重点。[图 3.8](#chapter3.xhtml#fig3_8) 展示了在所有技术中部署安全的情况。应防止安全漏洞，以降低脆弱性风险。`国际电工委员会 (IEC)` 是一个国际标准。它对所有电气和电子技术给出一致性评估。`IoT` 设备应遵守 `IEC` 的标准和指南（Ahmed et al., 2018）。

#### 3.3.7.1 人员

`美国国家标准与技术研究院 (NIST)` 持续监控并推广新标准以增强安全性。安全团队是一组为安全紧密协作的专业人员。当检测到漏洞时，安全团队会识别其严重性影响。它调试更新并立即部署给客户。

#### 3.3.7.2 流程

在设备实时部署之前，应建立强有力的安全流程。一旦发现设备存在漏洞，安全流程应立即启动。在任何设备部署中，应考虑 [表 3.3](#chapter3.xhtml#tbl3_3) 中的以下流程来处理安全问题。

| --- | --- |

| **隔离** | 将其与设备网络分离 |
| **验证** | 确保真实性 |
| **处理** | 处理漏洞 |
