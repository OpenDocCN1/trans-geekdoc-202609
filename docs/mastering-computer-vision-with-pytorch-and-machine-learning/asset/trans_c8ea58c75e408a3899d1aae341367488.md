
有使用 Photoshop 去除图像背景经验的人，对于一个新工具的出现会感到非常高兴：即“分割一切模型”（Segment Anything Model，SAM），该模型由 Meta AI 于 2023 年 4 月 15 日发布。不具备任何计算机代码知识的用户可以将照片上传到 Meta 的 SAM 网站，并使用鼠标在照片上点击或绘制方框。用户通过这些鼠标提示选择照片上的物体，只需几毫秒即可将其从照片中分割出来，并将这些物体的像素与照片背景分离。随后，人们可以利用这些物体的像素来编辑图像和分析照片。图 [11.6](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11fig6)(A) 显示了一张母鹿站在我花园积雪覆盖的地面上的照片。该照片通过项目 [11.4.1](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11ueqn10) 的 Cell 01 中的代码，加载模型和来自检查点文件 `sam_vit_h_4b8939.pth` 的预训练参数，被分割成了 74 个物体。由于该文件大小超过 2.5 GB，我笔记本电脑的 6 GB GPU 显存不足以运行需要 8 GB 显存的代码。幸运的是，我可以在 CPU 上运行代码，但代码运行时间约为 130 秒。借助 Google Colab 的免费 GPU，代码运行时间约为 4 秒。虽然我可以用较小的检查点文件 `sam_vit_b_01ec64.pth`（0.37 GB）在笔记本电脑的 GPU 上运行代码，但代码输出结果很糟糕。SAM GitHub 网站上最大的检查点文件是 `sam_vit_l_0b3195.pth`。我结合我的代码尝试了它，与中等大小的文件相比，没有看到显著的质量提升。我的代码受 Piotr Skalski 的 Colab 代码启发，其中使用了 Roboflow supervision 模块（版本 ⩾ 5.0）来显示 SAM 掩膜（图 [11.6](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11fig6)(B)）。

Cell 01 最后一行 SAM 掩膜生成器的输出是一个列表，列表中的每个元素都是一个物体的字典。Cell 02 前两行的代码打印出从图像中分割出的物体数量，每个物体的字典键包括：`segmentation`、`area`、`bbox`、`predicted_iou`、`point_coords`、`stability_score`、`crop_box`。`segmentation` 键对应一个 SAM 分割掩膜，掩膜的形状即原始图像的分辨率：480 × 480。`point_coords` 和 `crop_box` 这两个键是用户设置的鼠标提示。由于我们在 Cell 01 中将 SAM 设置为使用自动掩膜生成器，这两个键的值由模型自动设置。`stability_score` 键用于将物体从背景中分离出来。我们可以通过 Cell 02 最后一行的代码，以网格大小 (9, 8) 显示 72 个掩膜。你会看到许多掩膜对应同一个物体，图像上许多无意义的阴影斑点也被分割为物体。Cell 02 中的代码按面积对掩膜进行逆序排序，并仅将前六个掩膜作为黑白图像显示。Cell 03 中的代码显示原始图像和仅包含三个主要掩膜的处理后图像。鹿和雪从背景中分离出来。Cell 04 中的代码使用主要掩膜 `masks[0]` 将鹿从背景中提取出来。

SAM 不具备目标检测功能。通过将 Cell 04 的输出图像输入到项目 [8.4.2](#Chapter_8.xhtml#bk978-0-7503-6244-3ch8ueqn8) 中，我们可以使用 YOLOv8 检测图像中的物体：结果为置信度 79% 的“牛”。这是错误的，因为 YOLOv8 使用 COCO 数据集的类别来识别物体，但 COCO 数据集中没有“鹿”这一类别。随后，我使用项目 [10.4](#Chapter_10.xhtml#bk978-0-7503-6244-3ch10ueqn10) 中的代码，通过 Owl-ViT 零样本目标检测来分析该图像。在项目 [10.4](#Chapter_10.xhtml#bk978-0-7503-6244-3ch10ueqn10) 的 Cell 01 类别列表中添加 `deer` 项后，Owl-ViT 程序能够在图像中找到鹿，如图 [11.6](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11fig6)(C) 所示。SAM 模型本身没有什么特别之处（Kirillov *et al* [2023](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11bib5)），仅包含一个作为图像编码器的 ViT、一个用于点、框和文本的提示编码器，以及一个掩膜解码器。Meta AI 使用 1100 万张图像和 10 亿个掩膜训练了 SAM 模型。人们说，Meta AI 的 SAM 对世界的影响将如同 Open AI 的 ChatGPT 一样深远。

Meta AI 提出的 SAM 正成为许多计算机视觉任务的基础，例如图像分割、图像描述和图像编辑。然而，SAM 需要大量的计算资源，因为 SAM 的架构基于第 [10.1](#Chapter_10.xhtml#bk978-0-7503-6244-3ch10s10-1) 节提到的视觉变换器。Xu Zhao 及其合作者于 2023 年 6 月提出了基于 YOLOv8 的 FastSAM（Zhao *et al* [2023](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11bib11)）。使用 FastSAM，他们在运行速度提高 50 倍的情况下，实现了与 SAM 方法相当的性能。他们在 [GitHub 网站](https://github.com/CASIA-IVA-Lab/FastSAM) 发布了代码。根据他们的说明，我在名为 `Exercises` 的当前工作文件夹中，下载并解压了他们的代码到一个名为 `FastSAM` 的文件夹内，环境为带有 Python v3.9 的 VS Code 虚拟环境。在一个 VS Code 单元格中，运行带引号的代码 `'import os; os.getcwd(); %cd fastsam'`，我可以运行项目 [11.4.2](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11ueqn12) 中的代码，这些代码使用了 FastSAM 文件夹中的一些 Python 文件。通过这些设置，我们可以使用 Cell 01 第 03 行的代码导入一些库：`from fastsam import FastSAM, FastSAMPrompt`。

![](images/bk978-0-7503-6244-3ch11uf10_pr.gif)

原始的 FastSAMPrompt 库仅接受图像文件名路径字符串作为图像源。要将 FastSAM 用于相机帧，我们必须修改 `FastSAM/fastsam/prompt.py` 第 23 到 27 行的代码，以便 NumPy 数组可以作为图像源供 FastSAMPrompt 库使用。我从 Nicolai Nielsen 的 [YouTube 视频](https://www.youtube.com/watch?v=SslzS0AsiAw) 中找到了这个解决方案。Roboflow 也有一个关于 FastSAM 的有用 YouTube 视频。在 Cell 02 中，第 06-08 行被禁用的代码分别用于框提示、点提示和文本提示。它们可以工作，但结果可能不是我们预期的。例如，使用文本提示 `lady` 时，图 [11.7](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11fig7) 的图像中只分割出了一位女士。重复使用 Cell 05 和 07 中的代码并将 `yolov3` 替换为 `fastsam`，我们可以使用 Cell 02 中定义的函数处理文件夹中的图像、相机帧或视频文件。视频速度约为 3 FPS。虽然 FastSAM 的图像分割质量不如 SAM，但我们必须为了速度牺牲一点质量。
