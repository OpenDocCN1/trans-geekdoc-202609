
当我们在 Cell 02 最后一行使用代码定义 `Tracker` 类的实例时，该实例通过一个名为 `center_points` 的空字典和一个名为 `id_count` 的标量进行初始化。Cell 03 第 12 行的代码仅调用实例的 `tracker.update()` 函数来处理当前视频帧。上一帧汽车的中心坐标保存在 `center_points` 中，上一帧的最大 ID 号加 1 后保存在 `id_count` 中。

假设预训练的 YOLOv8 模型在第一帧检测到三辆汽车，并使用 `tracker.update()` 函数处理汽车列表。在 Cell 02 第 07 行开始的 `for` 循环中，首先获取第一辆汽车的中心点，并将该汽车的 `same object detected` 属性设置为 `False`。由于此时 `center_points` 字典为空，第 12 行至第 18 行的代码被跳过。第一辆汽车将通过第 20 行的代码被分配 ID 号 1，此时 `id_count` 变为 2。现在 `center_points` 字典有一个元素 `{1: (cx1, cy1)}`，`center_ids` 为 `[[cx1, cy1, 1]]`。

我们仍在从第 07 行开始的循环中计算第二辆汽车的中心。第 12 行至第 18 行开始的子循环检查第二辆汽车与第一辆汽车之间的欧几里得距离。如果距离小于 35 像素，则认为这两辆汽车是同一物体。如果不是同一物体，第二辆汽车将被分配 ID 号 2，`center_points` 将有两个元素 `{1: (cx1, cy1), 2: (cx2, cy2)}`。处理完第三辆汽车后，如果它们的距离都大于 35，我们得到 `center_points {1: (cx1, cy1), 2: (cx2, cy2), 3: (cx3, cy3)}`，且 `id_count` 为 4。偶尔两辆汽车之间的距离小于 35，因此它们拥有相同的 ID 号。第 23 行至第 28 行的代码用于仅保留具有相同 ID 号的众多汽车中最新的那一辆。

当 `yolov8tc` 函数处理第二帧时，`tracker.update()` 函数将再次被调用。从第一帧获得的 `center_points` 字典和 `id_count` 标量保存在 `Tracker` 类的 `__init__()` 函数中，它们用于第二帧的处理。如果第二帧只有相同的三辆汽车，且每辆汽车移动的距离都小于 35 像素，`Tracker` 的 `update` 函数将使用第一帧上的旧 ID 号识别这三辆汽车。`id_count` 不会改变（=4），但三辆汽车的 `center_points` 字典将被更新。在一辆汽车在两帧之间的时间间隔内移动距离大于 35 像素的情况下，该汽车将被分配一个新 ID 作为新物体。但这是不正确的。数字 35 是一个关键距离，是该项目的一个超参数。它取决于相机分辨率和许多其他硬件设置。

新版本项目 [8.4.3](#Chapter_8.xhtml#bk978-0-7503-6244-3ch8ueqn9) 的代码列在附录 [G](#Appendix1.xhtml#bk978-0-7503-6244-3AppAsA-G) 中。新版本中的代码可以检测多个 COCO 类别中的运行物体。YOLOv8 检测到的每个物体的 COCO 类别标签（一个整数）在 Cell 03 第 07 行的代码中被记录在汽车列表中。有了这个额外信息，我们可以同时统计汽车和卡车。

#### 8.4.4 微调 YOLOv8 以进行自定义数据集的目标检测和标注
