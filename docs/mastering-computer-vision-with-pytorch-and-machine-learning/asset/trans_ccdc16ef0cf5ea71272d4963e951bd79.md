
首次运行单元格 01 中的代码时，小型预训练 DINOv2 模型将自动从 Facebook 下载。文件大小约为 21 MB。大型 DINOv2 模型的大小约为 300 MB。单元格 06 中的代码处理验证数据集中的每张图像，以获取一个包含 384 个元素的一维张量，用于表示图像的详细物体信息。该单元格输出张量的形状为 701 × 384，因为验证数据集中有 701 张图像。我们使用单元格 06 选择一张查询图像，然后使用模型提取图像特征。使用 Facebook 库 `faiss`（Johnson *et al* [2019](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11bib4)）进行图像相似性搜索。根据 `faiss` GitHub 仓库的介绍，它假设图像特征向量可以通过 L2（欧几里得）距离或点积进行比较。与查询向量相似的向量是指那些与查询向量具有最低 L2 距离或最高点积的向量。单元格 07 的输出是一个包含批次大小个元素的列表。每个元素是一个整数，代表验证数据集中检索到的图像的位置索引（<701）。然后由单元格 08 中的代码显示检索到的图像。本节中三个小型 DINOv2 项目的代码受到 Purnasai Gudikandula 的 GitHub 仓库代码的启发。在我的 Python 和 PyTorch 更新后，我遇到了来自 FAISS 库的一个问题。项目 [11.3.1](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11ueqn7) 的改进版本列在附录 [J](#Appendix1.xhtml#bk978-0-7503-6244-3AppAsA-J) 中，其中直接计算欧几里得距离，而不使用第三方库。

由于 DINOv2 模型非常强大，能够在没有人工指令的情况下学习图像特征，我们可以使用这些模型进行图像分类，代码列在项目 [11.3.2](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11ueqn8) 中。为了节省空间，我复用了项目 [9.3.2](#Chapter_9.xhtml#bk978-0-7503-6244-3ch9ueqn17) 中的单元格 02–04 用于花卉图像数据集，以及项目 [2.3](#Chapter_2.xhtml#bk978-0-7503-6244-3ch2ueqn22) 中的单元格 06–09 用于不带学习率调度器的模型训练。分类模型的类在单元格 05 中定义。模型的主干网络是预训练的大型 DINOv2 模型。两个全连接层被附加到 DINOv2 模型后用于图像分类。在不到 8 分钟的五轮模型训练中，训练数据集和验证数据集的图像分类准确率分别达到 99.5% 和 95.5%。

DINOv2 模型可以提取用于图像检索和图像分类的图像特征。我们可以在项目 [11.3.3](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11ueqn9) 中使用数学工具 PCA（主成分分析）来可视化高维特征。项目中使用了预训练的大型 DINOv2 模型 `dinov2_vitl14`，该项目对一张包含四只鹿的彩色图像的输出结果如图 [11.5](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11fig5) 所示。图像的原始尺寸为 800 × 533 × 3。单元格 02 中定义的一个变换函数处理原始图像，得到一个分辨率为 1 × 3 × 518 × 518 的张量。使用大小为 14 的补丁，模型将图像分割成 1369 个（=518/14 × 37）补丁，嵌入维度为 1024。模型的输出为一个类别标记和 1369 个补丁标记。在单元格 02 中使用 `model.forward_features(img_transformed)` 而非 `model(img_transformed)`，我们获得一个包含四个键的字典，但项目中仅使用其中一个键的值作为图像的张量 `batch_total_features`，该张量的形状为 1 × 1369 × 1024。使用 PCA，单元格 03 中的代码将形状为 1369 × 1024 的 `total_features` 张量降维，得到形状为 1369 × 3 的 `pca_features` NumPy 数组。仅 `pca_features` 数组的第零通道被归一化并由单元格 04 显示。为了节省空间，我将第一张 PCA 图像叠加在图 [11.5](#Chapter_11.xhtml#bk978-0-7503-6244-3ch11fig5) 所示原始照片的左上角。
