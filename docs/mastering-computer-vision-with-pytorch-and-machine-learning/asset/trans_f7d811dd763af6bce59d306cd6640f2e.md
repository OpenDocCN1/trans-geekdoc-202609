

# 理解 YOLOv1 和 Pascal VOC 2012

要理解 YOLOv1，我们需要了解 Pascal VOC 2012 数据库的数据结构（Everingham *et al* [2012](#Chapter_7.xhtml#bk978-0-7503-6244-3ch7bib1)）。数据库中的图片选自 Flickr，这是一个由许多拥有不同许可证的个人贡献的图片来源。该数据库可用于目标分类、检测和分割。图片和标签可以从 Kaggle 下载。在用我的 Google 账号设置好 Kaggle 账号后，我下载了一个名为 `VOCtrainval_11-May-2012.tar` 的 2 GB 压缩文件，然后将其解压到笔记本电脑上。五个子文件夹中的未压缩文件占用了我笔记本电脑硬盘上超过 5.6 GB 的空间。我们只需要使用其中两个子文件夹进行目标检测。一个子文件夹名为 `JPEGImages`，另一个名为 `Annotations`。在第一个子文件夹中，有 20 个类别共 17,125 张图片。在第二个子文件夹中，有 17,125 个 XML 文件，包含每张图片的边界框信息。每个 JPEG 图片文件名的前缀与为该图片标注的 XML 文件名的前缀相同（XML 是可扩展标记语言的缩写）。XML 文件也用于存储、传输和重构任意数据。它们可以用任何网页浏览器或任何文本编辑器打开和编辑，例如 MS Windows 中的 `Notepad`。下面的代码是在网页浏览器中打开的一个 XML 文件的结构。从 XML 文件中的数据可知，图片的形状为 600 × 540 × 3。图片上有三个物体：两个人和一条狗。每个物体两个角的坐标列在 XML 文件中。这些坐标是相对于图片左上角 `[0,0]` 的像素值。为了避免版权问题，第 [7](#Chapter_7.xhtml#bk978-0-7503-6244-3ch7)–[12](#Chapter_12.xhtml#bk978-0-7503-6244-3ch12) 章中使用的许多图片来自我自己的相机。

## 7.2 使用边界框对 VOC 图片进行编码以适配 YOLOv1

计算机实际上对图片物体一无所知，只理解数字 '0' 和 '1'。经过模型训练后，计算机似乎拥有了智能，能告诉我们数据集中图片的一些信息，因为我们使用特殊格式的数据和特殊的损失函数在计算机上训练模型。神经网络非常强大，它们记住了图片的许多细节，以至于能通过“过拟合”来欺骗我们。我们必须在图片增强上做更多工作以避免过拟合问题。

### 7.2.1 带边界框的 VOC 图片增强

当图 [7.1](#Chapter_7.xhtml#bk978-0-7503-6244-3ch7fig1) 中所示的图片被调整大小为 448 × 448 以进行 YOLOv1 模型训练时，那三个边界框的坐标也需要相应地进行转换。在 YOLOv1 模型训练中，转换后图片中每个边界框的宽度和高度归一化为 448。每个边界框中心坐标 `[x_c, y_c]` 归一化为 64。由于 `x_c` 或 `y_c` 的值可以是 0 到 448 之间的任意整数，归一化到 64 后的数值应在 0–7 范围内。该数值的整数部分用作网格单元的行索引或列索引；归一化余数的值小于 64 个像素。该余数再次按 64 归一化，作为边界框中心相对于网格单元左上角的坐标。通过这种方式，每个边界框的四个参数都是值小于 1 的正数。我们做这些额外工作是为了减少损失函数数值爆炸的可能性。
