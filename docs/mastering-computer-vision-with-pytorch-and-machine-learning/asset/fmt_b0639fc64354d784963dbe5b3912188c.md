
# Object Tracking and Counting

Object tracking and counting refer to processes of locating and monitoring objects in a video or an image sequence and then counting the number of objects belonging to a class of interest. Object tracking and counting find applications in many domains, such as surveillance, traffic monitoring, people counting, retail analytics, sports analysis, and wildlife monitoring, etc.

There are three steps for this kind of computer vision task:

1.  **Object detection** by `YOLO` or other object detection algorithms.
2.  **Object tracking**, which aims to associate objects detected in the current frame with previously tracked objects from the previous frame.
3.  **Object counting**.

Applying the codes of the following project [8.4.3](#Chapter_8.xhtml#bk978-0-7503-6244-3ch8ueqn9) to a video file, we will track and count cars running in opposite directions separately. Trucks running beside cars will be ignored in the video. The project codes are inspired by FREEDOM TECH's [YouTube](https://www.youtube.com/watch?v=DXqdjWndooI) and his [GitHub](https://github.com/freedomwebtech/yolov8counting-trackingvehicles/blob/main/tracker.py) repository.

Before being processed by a pre-trained `YOLOv8` model, each video frame is resized to 1024 × 512. A processed video frame shown in Figure [8.5](#Chapter_8.xhtml#bk978-0-7503-6244-3ch8fig5) depicts vehicles running on a highway. The left-hand-side vehicles are moving towards the camera (direction **down**: top to bottom of the frame). The right-hand-side vehicles are moving away from the camera (direction **up**: bottom to top of the frame).

Codes in **Cell 01** import libraries and a small pre-trained `YOLOv8` model. Seven hyperparameters are also set in the cell. Two of them on lines 03 and 04 set the *y*-axis locations of a green line and a red line as shown in the figure. Corresponding to the green line's position at `y=340`, a green zone on the frame defined by `340-dy ≤ y ≤ 340+dy` serves as a detection zone for cars running up, where `dy` is set to 6 pixels by code on line 05. Similarly, the red line at `y=370` sets a red zone of the same size to detect cars running down. The other four hyperparameters will be explained later.

We begin explaining the project codes from the last cell: **Cell 04**, which is almost the same as Cell 07 of project [7.5](#Chapter_7.xhtml#bk978-0-7503-6244-3ch7ueqn23). Codes in this cell read a video file frame by frame. After a frame is processed by a function defined in Cell 03, information is added to the processed frame as shown in the figure above. The digit on the lower-left corner indicates the number of cars running down from frame 0 to the current frame; the digit on the lower-right corner indicates the number of cars running up.

When a car is in a detection area, its bounding box center is marked by a white dot, and its ID number is displayed beside the dot. The color of the ID number matches the color of the horizontal line for the detection zone. The top-left corner shows the image processing speed (with high variance). When no vehicle is on the road, a "divided by zero" error may occur in FPS calculations; a small number (`10^(-5)`) is used to prevent this. The current frame's sequence number and the total frames of the video are shown on the top-right corner.

At frame 140/572 (as shown in the figure), four cars had been counted running up and two running down. The image processing speed was 57 FPS. At that moment, a black car with ID 229 was running down and was inside the red zone.

![](images/bk978-0-7503-6244-3ch8uf11_pr.gif)

The function defined in **Cell 03**, named `yolov8tc`, indicates that a pre-trained `YOLOv8` model is used for object tracking and counting. This function modifies the `yolov8` function defined in Cell 01 of project [8.4.2](#Chapter_8.xhtml#bk978-0-7503-6244-3ch8ueqn8).

- Line 02 resizes an original video frame to 1024 × 512.
- The resized frame is processed by the `YOLOv8` model to obtain bounding box coordinates (`boxes`) and COCO class identity numbers (`labels`).
- Lines 07–11 filter for cars and pack the four coordinates of each car's bounding box (`x`, `y`, `X`, `Y`) into a list appended to `car_list`.
- Line 12 processes `car_list` via the `track` function of a `Tracker` class instance (defined in Cell 02). The output list `cxcyid` has the same length as the input. Each sublist in `cxcyid` contains three elements: the center coordinates (`cx`, `cy`) and an assigned ID number.
- Center coordinates are calculated as: `cx = int((x + X) / 2)` and `cy = int((y + Y) / 2)`.
- The `Tracker` associates detections across frames; new objects receive a new, higher ID number.

On the current frame, each car has an ID and center coordinates. Lines 13–30 check the *y*-axis positions of cars:

- If a car is in the **green zone** (line 15), it is marked with a white dot and its ID is printed. The car is registered in the dictionary `vh_down` (for cars running down).
- If a car's ID in `vh_down` touches the **red zone** and the ID is new to the list `n_down` (line 21), the ID is appended to `n_down`. The length of `n_down` represents the count of cars running down.
- Lines 23–30 apply the same logic to count cars running up (using `vh_up` and `n_up`).

The two counts are printed on the lower corners of the frame, and the green/red zone lines are drawn. The function `yolov8tc` returns the annotated frame.
