## 6.19 DELETION IN AN AVL TREE

The deletion of a node from an AVL tree is exactly the same as the deletion of a node from the BST. The sequence of steps to be followed in deleting a node from an AVL tree is as follows:

- Initially, the AVL tree is searched to find the node to be deleted.
- The procedure used to delete a node in an AVL tree is the same as deleting the node in the binary search tree.
- After deletion of the node, check the balance factor of each node.
- Rebalance the AVL tree if the tree is unbalanced. For this, AVL rotations are used.

## 6.20 RED-BLACK TREE

A red-black tree is a binary search tree in which every node has a colour which is red or black. Recall that an extended binary tree is a tree in which all NULL links are replaced by special nodes that are called external nodes. The properties of a red-black tree are as follows:

- Property 1: The colour of a node is either red or black.
- Property 2: The colour of the root node is always black.
- Property 3: All leaf nodes are black.
- Property 4: Every red node has both the children coloured in black.
- Property 5: Every simple path from a given node to any of its leaf nodes has an equal number of black nodes.

All paths from a node n to any external node will have same number of black nodes. If a path from root to external node has all the black nodes, then it will be the longest possible path. Since, black height of root node is k, each path will have k black nodes. Therefore, the total nodes in shortest path will be k and total nodes in longest path will be 2k. Thus, we see that no path in a red-black tree can be more than twice another node is at most 2log_2(n+1).

## 6.21 INSERTION A NODE IN A RED-BLACK TREE

The insertion operations start in the same way as we add a new node in the binary search tree. However, in a binary search tree, we always add the new node as a leaf, while in a red-black tree, leaf node contain no data. Instead of adding the new node as a leaf, we add a red interior node that has two black leaf nodes. Remember that the colour of the new node is red and its leaf nodes are coloured in black. Once a new node is added, it may violate some property of the red-black tree. So in order to restore its property, we check for certain cases and restore depending on the case that turns after insertion. Before learning these cases in detail, let us discuss important terms that will be used.

- (i) Grandparent node (G) of a n refers to parent of n's parent (P).
- (ii) Uncle node (U) of a n refers to sibling of n's parents (P).

When we insert a new node in a red-black tree, note the following points:

1. All leaves are always black. Property 3 holds true.
2. Property 4 (both children of every red node is black) is threatened only by adding a red node, repainting a black node, or a rotation.
3. Property 5 (all paths from any given node to its leaf nodes has equal number of black nodes) is threatened only by adding a black node, repainting a red node, or a rotation.

### Case 1: The new node n is added as the root of the tree

In this case, n is repainting black, as the root of the tree is always black. Since n adds one black node to every path at once.

### Case 2: The new node's parent P is black

In this case, both children of every red node are black, so property 4 is not invalidated. Property 5 is also not threatened. This is because the new node n has two black leaf children, but because n is red, the paths through each of its children have same number of black nodes. In the following cases, it is assumed that n has a grandparent G, because its parent P is red, and if it were the root, it would be black. Thus, n also has an uncle node U, irrespective of whether U is a leaf node or an internal node.

### Case 3: If both the Parent (P) and the Uncle (U) are red

In this case, property 5 which allows paths from any given node to its leaf nodes have an equal number of black nodes is violated. In order to restore property 5, both node (P and U) are repainting and the grandparent G is repaired. The new red n has a black path. Since, any path through the parent or uncle must pass through the grandparent, the number of black nodes on these paths has not changed. However, the grandparent G may violate property 2 which says that the root node is always black or property 4 states that both children of every red node are black. Property 4 will be violated when G has a red parent.

![](img/3d5da05d64722faaa72fdc4daca105f9_287_0.png)

### Case 4: the parent P is red but the uncle U is black and n is the right child of P and P is the left child of G

In this case, a left rotation is done to switch the roles of n and P. After the rotation, we have re-labelled n and P. This is done because property 4 which says both children of every red node is black is violated.

![](img/3d5da05d64722faaa72fdc4daca105f9_287_1.png)

### Case 5: The parent P is red but the uncle U is black and n is the left child of P and P is the right child of G

In this case, a right rotation on G is performed. In the resultant tree, S will become n's grandparent. We know that the colour of G is black because otherwise P could not have been red, so now switch the colours of P.

## 6.22 DELETING A NODE FROM RED-BLACK TREE

We start deleting a node from a red-black tree in the same way as we do in case of binary search tree. In this section, we will assume that we are deleting a node with at most one non-leaf child, which we will call its child. In this case node has both leaf children, and then let one of them is its child. While deleting a node if its colour is red, then we can simply replace it with its child, which must be black. All paths through the deleted node will simply pass through one less red, and both the deleted node's parent must be black, so none of the properties will be violated. Another simple case is when we delete a black node has a red child. In this case, property 4 and property 5 could be violated, to restore them, just repaint the deleted node's child with black.

### Case 1: n is the new root

In this case, we have removed one black node from every path, and the new row is black, so none of the properties are violated.

### Case 2: Siber is red

In this case, interchange the children of P and S, and then rotate left at P. In the resultant tree, S will become n's grandparent.

![](img/3d5da05d64722faaa72fdc4daca105f9_288_1.png)

### Case 3: P, S and S’s Children are Black

In this case, simply repaint S with red. In the resultant tree, all the paths passing through S will have one less black node. Therefore, all the paths that pass through P now have fewer black nodes than the paths that do not pass through P, so property 5 is still violated.
