# 2. Creation of binary tree from post-order and in-order traversal.

The general rule for creating a binary tree is as follows:

Rule 1: scan the post-order traversal from right to left.

Rule 2: for each node scanned locate its position in in-order traversal. Assume the scanned node is X.

Rule 3: the node preceding X in in-order from its left sub-tree and nodes succeeding it from right sub-tree.

# 2. Searching in a Binary Search Tree

Tree- Start at the root and move down the tree. To search in the tree, first the data element is compared with the value at the root. If the data element is found, then the search is successful. If the data element is less than the key in the root, then the search is performed in the left-tree. If the data element is greater than the key in the root, then the search is performed in the right-tree.

# 3. Finding nodes with Minimum and Maximum Values

To find minimum valued node in binary search tree start at the root and move along the leftmost path until we get a node no left child.

To find maximum value node start at the root and move along the rightmost path until we get a node no right child.

# 4. Insertion in a Binary Tree

To insert an element in binary tree start at the root node and compare the value to be inserted with the value at root and take following actions:

1. If the value to be inserted is equal to the value at the root then there is nothing to be done as duplicate values are not allowed.
2. If the value to be inserted is less than the value of the node then we move to left child.
3. If the value to be inserted is greater than the value of the node then we move to right child.

# 5. Deletion in a Binary Search Tree

Deletion of a node from binary search tree depends on the number of its children. There are three cases that can occur:

- Case 1: Node has no child, i.e. it is a leaf node.
- Case 2: Node has exactly one child.
- Case 3: Node has exactly two children.

Case 1: To delete a leaf node, the link to node is replaced by NULL. If the node is left child of its parent then the link of its parent is set to NULL and if the node is right child of its parent then the right link of its parent is set to NULL. Then the node is de-allocated using free ().

To delete 20, the left link of node 30 is set to NULL.

Case 2: In this case, the node to be deleted has only one child. After deletion this single child takes the place of the deleted node. For this we change the appropriate pointer of the parent node so that after deletion it points to the child of deleted node. After this, the node is de-allocated using free ().

To delete node 65 from the below given tree. Node 65 is the right child of its parent node 48, the single child 56 takes the place of 65 by becoming the right child of 65.

Case 3: This is the case when the node has been deleted two children. Here we have to find the in-order successor of the node. The data of the in-order successor is copied to the node and then the in-order successor is deleted from the tree. In-order successor of a node is the node that comes after that node in the in-order traversal of tree.

# 6.12 HUFFMAN’S TREE

Suppose, we have n nodes and their weights the Huffman algorithm is used to find a tree with minimum-weighted path length. The process essentially begins by merging (or adding the values) of two smallest weights among n valued nodes and hence to the creation of a new node, such that the new node’s weight is equal to the sum of the merged children weight. This process is repeated until the tree has only one node which is known as the Huffman tree.

The Huffman’s algorithm can be implemented using a priority queue. Huffman tree is built from bottom up to top down ie the creation of trees from leaf nodes and proceeds upwards.
