# Rule 1

If something else besides the input data is used to determine the hash, then the hash value is not as dependent upon the input data, thus allowing for a worse distribution of the hash values.

# Rule 2

If the hash function does not use all the input data, then slight variations to the input data would cause an inappropriate number of similar hash values resulting in too many collisions.

# Rule 3

If the hash function does not uniformly distribute the data across the set of possible hash values, a large number of collisions will result, cutting down on the efficiency of the hash table.

# Rule 4

In real applications, many data sets contain very similar data elements. We would like these data elements to still be distributable over a hash table.

# 9.6 TYPES OF HASH FUNCTIONS

# 1. Division Method

Perhaps the simplest of all the methods of hashing is division method hashing which states that an integer $x$ is to divide $x$ by $M$ and then leave the remainder modulo $M$. In this case, the hash function is

```
h(x) = x \mod M
```

Generally, this approach is quite good for any value of $M$. However, in certain situations extra care is needed in the selection of a suitable value for $M$. For example, it is convenient to make $M$ an even number. But this means that $h(x)$ is even if $x$ is even; and $h(x)$ is odd if $x$ is odd. If all possible keys are equiprobable, this is not a problem. However, if we use, even keys are more likely than odd keys, the hash function $h(x)=x \mod M$ will not spread the hashed values of those keys ever.

Similarly, it is tempting to let $M$ be a power of two, $e.g.$, $M=2^k$ for some integer $k>1$. In this case, the hash function $h(x)=x \mod 2^k$ simply extracts the bottom $k$ bits of the binary representation of $x$. While this hash function is easy to compute, it is not a desirable function because it does not depend on all the bits in the binary representation of $x$.

For these reasons $M$ is often chosen to be a prime number. For example, suppose there is a bias in the keys we are created that makes it more likely for a key to be a multiple of some small constant, say two or three. Making $M$ a prime increases the likelihood that those keys are spread out evenly. Also, if $M$ is prime number, the division of $x$ by that prime depends on all the bits of $x$, not just the bottom $k$ bits, for some small constant $k$.
