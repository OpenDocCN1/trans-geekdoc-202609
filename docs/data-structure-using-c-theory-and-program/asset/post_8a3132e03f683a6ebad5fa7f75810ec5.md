## 1. Address of element in Column-Major Implementation

Column major ordering is the other function frequently used to compute the address of an array element. FORTRAN and various dialects of BASIC (e.g. Microsoft) use this method to index arrays. In row major ordering the right most index increased fast as you moved through consecutive memory locations. In column major ordering the left most index increases the fastest.

Address of element $a[i][j] = B + W \times (m(j - L2) + (i-L1))$

Where
$B=base address$
$W=size of each array element
$m=number of row (i.e., $U1 – L1 + 1)$
$L1=lower bound of row$
$L2=lower bound of column$
$U1=upper bound of a row$

Q1. A 2-D array defined as $A[4....6, 1....4]$ required 4 bytes of storage space for each element. If the array is stored in column major, then calculate the address of element at location $A[5,2]$. Base address is 100.

Solution: Apply the formula
Address of element $a[i][j] = B + W \times (m(j - L2) + (i-L1))$
$B=100, w=4, m=3, i=5, j=2, L1=4, L2=1$
$m=U1-L1+1$
$= 6-4+1$
$= 3$

Address of element of $A[5][2] = 100 + 4 \times (2 - 1) + (5 - 4)$
$= 100 + 4 \times 4$
$= 100 + 16$
$= 116$

## 2.7 SPARSE MATRICES

There are special types of matrices in which most of the elements are "0". That is, if lot of elements from matrix have a value 0 then the matrix is known as sparse matrix. There is no clear definition of when matrix is sparse and when it is not, we can recognise intuitively. If the matrix is sparse, we must consider an alternate way of representing it rather than the normal row-major or column-major arrangement. This is because a sparse matrix is a matrix containing few non-zero elements. If the user stores the entire matrix there is wastage of storage space.

Consider a $1000 \times 1000$ matrix have 5 non-zero elements per row then the non-zero percentage of the matrix can be calculated as:
$\frac{5 \times 1000 \text{ non-zero element}}{1000 \times 1000 \text{ rows}} \times = 0.5\%$

Thus, to represent this $1000 \times 1000$ matrix in memory only $0.5\%$ of the memory is required. So significant storage and computational saving can be realised by using sparse storage techniques. There are two types of representing sparse matrices:

1. Array Representation.
2. Linked List Representation.

## 2.8 ARRAY REPRESENTATION OF A SPARSE MATRIX

In the array representation of a sparse matrix, only the non-zero elements are stored so that storage space can be reduced. Each non-zero element in the sparse matrix is represented as Row, Column, and Value. For this, two-dimensional array containing 3 columns can be used. The first column is for storing the row numbers, the second column for storing the column numbers and the third column represents the value corresponding to the non-zero element at row, column.

For example, consider the sparse matrix:

The above matrix can be represented as:

| Row | Column | Value |
| :--- | :--- | :--- |
| 0 | 0 | 2 |
| 1 | 1 | 1 |
| 2 | 1 | 4 |
| 2 | 2 | 3 |
| 3 | 2 | 6 |

The structure declaration for array is:
```c
#define MAX 50
struct triplet {
    int row;
    int column;
    int element;
} sparse_matrix[MAX];
```

The maximum number of non-zero elements in sparse matrix is defined by constant MAX. The array representation will use $[2 \times (n + 1) \times \text{size (int)} + n \times \text{size (T)}]$ bytes of memory where $n$ is the number of non-zero bytes and $T$ is the data type of elements.

## Linked List Representation of a Sparse Matrix

Representing a sparse matrix as an array of 3-tuples, we need to know the number of non-zero terms in each of the sparse matrices. As a result, it is not possible to predict the size of the resultant matrix before hand. Instead of an array, we can represent the sparse matrix in the form of a linked list. The linked list representation is maintained for each column as well as each row of the matrix, i.e., if the matrix is of size $4 \times 4$, then there would be 4 lists for 4 columns and 4 lists for 4 rows. A node in a list stores the information about the non-zero element of the sparse matrix. The head node for a column list stores the column number, a pointer to the node which comes first in the column and a pointer to the next column head node. A head node for a row list, a pointer to the node which comes first in the row list, and a pointer to the next head node.

(i) Find the number NUM of non-zero element in A.
(ii) Find the product PROD of diagonal elements $(a_{11}, a_{22}, \dots, a_{nn})$

Solution:

(i) The algorithm finds the number of non-zero elements in A.
Steps:
1. Set $k=0$
2. Repeat for $i = 0$ to $N-1$
3. Repeat for $j = 0$ to $N-1$
4. if $A[i][j] \neq 0$
5. then $k = k+1$
6. print "number of non-zero elements", k
7. stop

(ii) The algorithm finds the product of diagonal elements.

Steps:
1. $PROD = 1$
2. Repeat for $i = 0$ to $N-1$
3. Repeat for $j = 0$ to $N-1$
4. if $(i \neq j)$
5. then $PROD = PROD \times A[i][j]$
6. print "PROD"
7. stop
