The first collision occurs when 49 hashes to the same location as 9. Since 89 occupies the A[9], we need to place 49 to the next available position. Considering the array as circular, the next available position is 0. That is (9+1) % 10. So we place 49 in A[0]. Several more collisions occur in this simple example and in each case we keep looking to find the next available location in the array to place the element. However, if we need to find the element, for example, 49, we first compute hash code of 79 = 9. We probe in A[9], A(9+1)%10=A[0], A(9+2)%10=A[1], A(9+3)%10=A[2], A(9+4)%10=A[3]. Since A[3]=null, we know that 79 could not exist in the set.

## 2. Quadratic probing

Although linear probing is a simple process where it is easier to compute the next location, linear probing also leads to clustering when keys are computed to closer values. Therefore, we define a new process of Quadratic probing that provides a better distribution of keys when collisions occur. In quadratic probing, if the hash value is K, then the next location is computed using the sequence K + 1, K + 4, K + 9 ..

## Hashing with Rehashing

Once the hash table gets too full, the running time for operations will start to take too long and may fail. To solve this problem, a table at least twice the size of the original will be built and the elements will be transferred to the new table.

The new size of the hash table:

- should also be prime
- will be used to calculate the new insertion spot (hence the name rehashing) This is a very expensive operation! O(N) since there are N elements to rehash the table size is roughly 2N. This is though since it doesn't happen that often.

The question arises when the rehashing should be applied:
Some possible:

- once the table becomes half full
- once an insertion fails
- once a specific load factor has been reached, where load factor is the ratio of the number of elements in the hash table to the table size

## Hashing

Hashing can be used to build, search, or delete from a table. The basic idea behind hashing is to take a field in a record, known as the key, and convert it through some fixed process to a numeric value, known as the hash key, which represents the position to store or find an item in the table. The numeric value will be in the range of 0 to n-1, where n is the maximum number of slots (or buckets) in the table.

The fixed process to convert a key to the table size is known as a hash function. This function will be used whenever access to the table is needed. One common method for determining a hash key is the division method. The formula that will be used is hash key = key % table size Assume a table with 8 slots:

| [0] | 72 |
| [1] | |
| [2] | 18 |

The division method is a reasonable strategy, unless it happens to have some undesirable properties. For example, if the table size is 10 and all keys end in zero. One problem though that keys are not always numeric. To get a numeric value from strings:

```
int hashValue = 0;
for (int j = 0; j < stringKey.length(); j++)
    hashValue += stringKey[j];

```

In this case, the choice of table size need be carefully considered. The best table sizes are prime numbers.
