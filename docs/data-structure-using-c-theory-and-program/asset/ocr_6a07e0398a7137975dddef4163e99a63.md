# 3. Mid square Method

We consider a hashing method which avoids the use of division. Since integer division is usually slower than integer multiplication, avoiding division we can potentially improve the running time of the hashing algorithm. We can avoid division by making use of the fact that a computer does finite-precision arithmetic. e.g., all arithmetic is done by modulo W where W=2², a power of two such that w is the word size of the computer.

The middle-square hashing method works as follows. First, we assume that M is a power of two, say M=2ᵏ for K>=1. Then, to hash an integer x, we use the following function:

```
h(x) = ⌊(x² mod W)/W⌋
```

Notice that M and W are powers of two, the ratio W/M=2⁻ᵏ is also a power of two. Therefore, in order to multiply the term (x mod W) by M/W we shift it to the right by w-k bits! In effect, we extract k bits from the middle of the square of the key—hence the name of the method.

The middle-square method does a pretty good job when the integer-valued keys are equiprobable. The middle-square method also has the characteristic that it scatters consecutive keys nicely. However, since the middle-square method only considers a subset of the bits in the middle of x², keys which may have a large number of leading zeros will collide. e.g., consider the set of keys:

```
{x ∈ Z⁺ : x < √W/M}
```

This set contains all keys x such that x < 2⁽k-w)/2. For all of these keys h(x)=0. A similar line of reasoning applies for keys which have a large number of trailing zeros.

W be an even power of two. Consider the set of keys

```
{x ∈ Z⁺ : x = nW : n ∈ Z⁺}
```

The least significant w/2 bits of the keys in this set are all zero. Therefore, the least significant w bits of x² are also zero and as a result h(x)=0 for all such keys.
