
## 3.1 The pipe operator: |>

- 1. Take x then
- 2. Use x as an input to a function f() *then*
- 3. Use the output of f(x) as an input to a function g()
- 4. Use the output of g(f(x)) as an input to a function h()

One way to achieve this sequence of operations is by nesting parentheses as follows:

```
h(g(f(x)))
```

This code isn’t so hard to read since we are applying only three functions: f(), then g(), h() and each of the functions is short in its name. Further, each of these functions only has one argument. However, you can imagine that this will get progressively harder to read as the number of functions applied in your sequence increases and the arguments in each function increase as well. This is where the pipe operator | comes handy. |> takes the output of one function and then “pipes” it to be the input of the next function. Furthermore, a helpful trick is to read |> as “then” or “and then.” For example, you can obtain the same output as the hypothetical sequence of functions as:

```
x |>
f() |>
g() |>
h()
```

You would read this sequence as:

- 1. Take x *then*
- 2. Use this output as the input to the next function f() *then*
- 3. Use this output as the input to the next function g() *then*
- 4. Use this output as the input to the next function h()

While both approaches achieve the same goal, the latter is much more human readable we can clearly see the sequence of operations line-by-line. But what are the hypothetical x, f(), g(), and h()? Throughout this chapter on data wrangling:

- 1. The starting value x will be a data frame. For example, the flights data we explored in Section 1.4.
- 2. The sequence of functions, here f(), g(), and h(), will mostly be a sequence of any number of the six data-wrangling verb-named functions we listed in the introduction to this chapter. For example, the filter(carrier == "MQ") function and argument specified we previewed earlier.

## 3 Data Wrangling

The result will be the transformed/modified data frame that you want. In our example, we'll save the result in a new data frame by using the <- assignment operator with the name alaska_flights via alaska_flights <-.


## 3.2 filter rows

### Subset Observations (Rows)

![](img/445742518041017e8f01f11b0c3190d9_98_0.png)

The filter() function works much like the “Filter” option in Microsoft Excel; it allows you to specify criteria about the values of a variable in your dataset and then filters out the rows that match that criteria.

We begin by focusing on flights from New York City to Phoenix, Arizona. The dest destination code (or airport code) for Phoenix, Arizona is “PHX”. Run the following and look at the results in RStudio’s spreadsheet viewer to ensure that only flights heading to Phoenix are chosen here:

```
phoenix_flights <- flights |
filter(dest == "PHX")
View(phoenix_flights)
```

Note the order of the code. First, take the flights data frame flights then filter() the data frame so that only where the dest equals "PHX" are included. We test for equality using the double sign == and not a single sign ==. In words, filter(dest = "PHX") will yield an error. This is a convention across many programming languages. If you are new to coding, you'll probably forget to use the double sign == a few times before you get the hang of it.

You can use other operators besides the == operator that tests for equality:

- * corresponds to "greater than"
- * corresponds to "less than"
- >= corresponds to "greater or equal to"
- <= corresponds to "less or equal to"
- != corresponds to "not equal to." The ! is used in many programming languages to indicate "not."

Furthermore, you can combine multiple criteria using operators that make comparisons:

- * corresponds to "or"
- * corresponds to "and"

To see many of these in action, let's filter flights for all rows that departed from JFK and were heading to Burlington, Vermont ("BTV") or Seattle, Washington ("SEA") and departed in the months of October, November, or December. Run the following:

```
btv_sea_flights_fall <- flights |
filter(origin == "JFK" & dest == "BTV" | dest == "SEA" & month > 10)
View(btv_sea_flights_fall)
```

Note that even when colloquially one might say "all flights leaving Burlington, Vermont and Seattle," in terms of operations, we mean "all flights leaving Burlington, Vermont or leaving Seattle, Washington." For a given row in the data, dest can be "BTV", "SEA", or something else, but not both "BTV" and "SEA" at the same time, note the careful use of parents around dest == == "BTV" | dest == "SEA".

We can often skip the use of & just separate our conditions with a comma, the previous code will return the identical output btv_sea_flights_fall as the following code:

```
btv_flights_fall <- flights |>
filter(origin == "JFK", dest == "BTV" | dest == "SEA", month >= 10)
View(btv_flights_fall)
```

Let's present another example that uses the ! operator to pick rows that don't match a criteria. As mentioned earlier, the ! can be read as "not." Here we are filtering rows corresponding to flights that didn't go to Burlington, VT or Seattle, WA.

```
not_BTV_SEA <- flights |>
filter(!(dest == "BTV" | dest == "SEA"))
View(not_BTV_SEA)
```

Again, the careful use of parentheses around the (dest == "BTV" | dest == "SEA"). If we didn't use parentheses as follows:

```
flights |> filter(dest == "BTV" | dest == "SEA")
```

We would be returning all flights not headed to "BTV" or headed to "SEA", which is an entirely different resulting data frame.

Now we have a larger number of airports we want to filter for, say "SEA", "SFO", "PHX", "BTV", "BDL". We could continue to use the | (or) operator.

```
many_airports <- flights |>
filter(dest == "SEA" | dest == "SFO" | dest == "PHX" |
dest == "BTV" | dest == "BDL")
```

As we progressively include more airports, this will get unwieldy to write. A shorter approach using the %in% operator along with the c() function. Recall from Subsection 1.2.1 that the c() function "combines" or "concatenates" values into a single vector.

```
many_airports <- flights |>
filter(dest %in% c("SEA", "SFO", "PHX", "BTV", "BDL"))
View(many_airports)
```

What this code doing is filtering flights for all flights where dest is in the vector of airports ("BTV", "SEA", "PHX", "SFO", "BDL"). Both outputs of many_airports are the same, but as you can see the latter takes much less energy to code. The %in operator is useful for looking.

As a final note, we recommend that filter() should often be among the first you consider applying to your data. This cleans your dataset to only those rows you care about, or put differently, it narrows the scope of your data frame to just the observations you care about.
