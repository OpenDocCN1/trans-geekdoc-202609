# Linting and Formatting Your Code

The first time I came across a programming language that came “out of the box” with a code formatter was when I first played around With Go$^{[1]}$ more than a decade ago. I was equally shocked to see how the Go community embraced it so quickly. Given all the online arguments I had seen over the years about things like semicolon usage in JavaScript and where to put opening and closing braces in PHP, it felt like a small breath of fresh air to see it.

Over the years, I discovered code linters and formatters can do a lot more than tell you “that opening brace is in the wrong place.” They can enforce many practices that often come up in code reviews and can also be used in build systems to apply those changes for you. An OSS project I used to lead made heavy use of them in ways that would surprise you.
