# 5. CONTINUOUS INTEGRATION

A developer creates a branch of the code under version control and does some work in that branch. Once they are ready to share, they use tooling to create a “pull request,” which is a notification that there are some changes to be reviewed. Generally speaking, you are comparing the developer’s work in their own branch with the main branch that gets deployed into a production environment.

People reviewing the pull request can see what the changes are and make comments about those changes. One of the downsides of the pull request method is that long-running work can easily get out of date if the codebase itself is changing rapidly. This, in turn, forces the developer to do a lot of work, constantly merging in other changes from other developers that have been applied to the main branch.

This method puts the pressure for smooth integrations onto the tooling by providing tools that reduce the friction involved in managing all these changes.

# Integrate Via Flags

As more people experience some of the pains and frustrations of a pull-request-centric integration plan, other programmers have been advocating not using separate branches for their work. Instead, they work in the main branch that is deployed and use “feature flags” or other techniques to make sure that the new code is only used under specific conditions.

Feature flags or other ways of configuring what code is available to users can be as complicated as an admin system where you define these values or as straight-forward as a conditional statement around a block of code.

The project I am using in this book does more of an “integrate with main” strategy, with a few flags to change what gets displayed. The other developer who helps out does pull requests for their work as they do not understand the codebase as well as I do.

This method puts the integration pressure on the developers to make sure the conditions under which this code should be executed are correct.

No matter what method you choose to use, the process for doing either method is well-established, and there are lots of resources available that can show how to do it.
