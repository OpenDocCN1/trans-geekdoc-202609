# 3. MUTATION TESTING

# Why Should I Use It?

My approach to writing unit tests goes something like this:

+   •  What is the scenario I am writing a test for?
•  What are my dependencies?
•  How do I create those dependencies?
•  How do I give those dependencies to the code I am testing?
•  What assertions do I need to make?
•  Does any code need to change to make those assertions succeed?

If I come up with enough scenarios, I start to take it for granted that I have both sufficient test coverage and that the tests themselves are good.

Mutation testing sets about to challenge that second assumption. If it mutates your code by doing something like switching `if` (`$foo > $bar`) to `if` (`$foo < $bar`) and a test for that portion of code still passes, there is a problem with your test.

Yes, sometimes tests succeed by accident! If you are making heavy use of test doubles, you need a way to detect whether the code you are creating doubles for behaves the way the test expects. Otherwise, you end up with tests that pass but no longer reflect how the code actually works.

# How Do I Use It?

In our sample app, I wanted to create a test for some code which verifies that the ordering of teams in our standings works correctly. The test looks like this:

```

2.    {
3.    
4.        $unsortedStandings = unserialize(

6.        );

9.        );
10.   
11.   $results = $this->component->sort($unsortedStandings);
12.   
13.   self::assertSame($expectedStandings['AC1'], $results);
```
