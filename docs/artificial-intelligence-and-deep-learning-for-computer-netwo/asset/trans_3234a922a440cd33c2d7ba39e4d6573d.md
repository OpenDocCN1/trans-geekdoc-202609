## 4.4.1 基线机制

我们使用了 NIS \[[20](#ch04.xhtml#ref4_20)\]、NANIS \[[18](#ch04.xhtml#ref4_18)\] 和“General”作为与 NB-PTS 性能比较的基线机制。NIS 解决了 NB-IoT 中时域无线资源浪费相关的问题，并设计了一个下行链路调度算法。NIS 还描述了 NB-IoT 系统中的无线接入策略及其下行链路调度问题。由于 NIS 解决了 NB-IoT 中的下行链路调度，因此可以通过优先流量分析下行链路调度，以找出其对分组传输延迟的影响。NANIS 专注于两个连续 NPDCCH 之间的时间间隔的自适应，以及在下行链路传输期间接收数据所消耗的无线资源的最小化。NANIS 的主要设计概念是尽可能多地利用窄带物理下行链路共享信道（NPDSCH）子帧。因此，NANIS 可以帮助在考虑优先流量的情况下最小化分组传输延迟。因此，我们使用 NIS 和 NANIS 作为基线。“General”基本上是一种用于调度分组的先进先出（FIFO）方法。

## 4.4.2 优先流量生成

在 NB-PTS 的性能评估中，我们考虑了三种与 QCI 值 QCI-4、QCI-6 和 QCI-8 相关的流量，这些值在 [Table 4.1](#ch04.xhtml#table4_1) 中给出。3GPP LTE 中定义的其他 QCI 值具有比上述 QCI 值更低的分组延迟预算，因此主要集中在比 QCI-4、QCI-6 和 QCI-8 更延迟敏感的方面。由于 NB-IoT 技术适合延迟容忍型应用，上述三个 QCI 值已在我们在 ns-3-dev-NB-IOT 中的 NB-PTS 实现中用于优先流量传输。在此实现中，我们将流量称为“Priority-1”、“Priority-2”和“Priority-3”，分别对应 QCI-4、QCI-6 和 QCI-8。在仿真设置中，eNB 和每个 UE 以相同比例生成这三种不同优先级的流量。流量是通过使用 `OnOffApplication` 生成的。QCI-4、QCI-6 和 QCI-8 相关的流量分别由枚举器 `GBR_NON_CONV_VIDEO`、`NGBR_VIDEO_TCP_OPERATOR` 和 `NGBR_VIDEO_TCP_PREMIUM` 生成；这些 QCI 值由枚举 `EpsBearer::Qci` 设置。

## 4.4.3 实现细节

我们已将 NB-PTS 实现为 ns-3-dev-NB-IOT 中 LTE MAC \[[1](#ch04.xhtml#ref4_1)\] 的扩展，[Figure 4.3](#ch04.xhtml#fig4_3) 说明了此实现。类 `LteEnbMac` 实现 eNB 的 MAC 层，`PfFfMacScheduler` 实现 `proportional fair scheduler` 以调度 UEs。`uplink` (UL) 和 `downlink` (DL) 块负责队列中存储的分组的上行链路和下行链路调度。MAC 调度器接口中的三个块是调度器块、控制块和子帧块。

![Figure 4.3 NB-PTS implementation modules in ns-3-dev-NB-IOT.](images/fig4_3.jpg)

[Figure 4.3 NB-PTS implementation modules in ns-3-dev-NB-IOT.](#ch04.xhtml#Ffig4_3)

`LteFfrAlgorithm` 是实现频率复用算法以分配 PRB 用于数据传输的抽象基类。通常，此算法对数据传输的 PRB 分配做出决策。与 `LteFfrSap` 接口对应的服务访问点（SAPs）是 `LteFfrSapProvider` 和 `LteFfrSapUser`。控制块与 MAC 调度器的通信通过 `FfMacCschedSapProvider` 和 `FfMacCschedSapUser` 进行。为了处理数据传输，`FfMacSchedSapProvider` 和 `FfMacSchedSapUser` 有助于在 MAC 调度器和子帧块之间建立连接。对于 MAC 调度器，接口 `LteEnbCmacSap`、`LteMacSap` 和 `LteEnbPhySap` 与无线资源控制（RRC）、无线链路控制（RLC）和物理（PHY）层建立通信。MAC 调度器包含以下块。`HARQ` 块用于处理混合自动重传请求（HARQ）重传。`Cell Cfg`、`UE Cfg`、`LC Cfg` 和 `Sched Cfg` 块分别存储小区配置、UE 配置、逻辑信道配置和调度器特定配置。`Physical downlink control channel (PDCCH)/random access channel (RACH)` 负责在 UL 和 DL 之间共享资源。拟议的 NB-PTS 算法作为 `LteEnbMac` 的扩展实现，并通过处理 UL 和 DL 块中的传输队列来增强 `LteEnbMac` 的功能。基于 QCI，`LteEnbCmacSapProvider::LcInfo` 为 NB-PTS 提供流量的优先级。

## 4.4.4 吞吐量分析

单个流量（Priority-1、Priority-2 和 Priority-3）的平均吞吐量显示在 [Figure 4.4](#ch04.xhtml#fig4_4) 和 [Figure 4.5(a)](#ch04.xhtml#fig4_5) 中。基于信道条件，需要动态确定队列阈值，以最大化调度期间传输的分组数量。此外，目标平均延迟的估计会导致流量的延迟容忍水平。因此，计算目标平均延迟至关重要，这样可以尽可能多地增强通过各自的目标平均延迟传输的分组数量。因此，基于学习的自适应机制可以帮助根据当前网络条件确定队列阈值和目标平均延迟的值；拟议的 NB-PTS 是朝这个方向的在线学习方法。此外，拟议的度量 `W[t+1]` 也有助于通过考虑目标平均延迟、HOL 延迟和流量优先级来调度流量。因此，NB-PTS 中的调度在考虑流量延迟约束的同时考虑流量优先级，因此，随着流量优先级的提高，平均吞吐量增加，如 [Figure 4.4](#ch04.xhtml#fig4_4) 和 [Figure 4.5(a)](#ch04.xhtml#fig4_5) 所示。
