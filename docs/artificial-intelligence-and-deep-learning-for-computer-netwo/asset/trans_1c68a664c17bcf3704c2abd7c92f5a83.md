## 3.1 引言

在过去几年中，SDN 定义了一种使网络范围自动化成为可能的架构范式。SDN 市场正在快速发展，根据市场报告 \[[1](#ch03.xhtml#ref3_1)]，它仍被认为处于早期阶段。SDN 的普及源于这样一个事实：它通过分离转发平面和控制平面，允许自动配置、网络虚拟化和高效管理。网络智能通过可编程的 SDN 控制器集中化。尽管控制平面是集中化的，但单个物理控制器可能导致可靠性、性能和鲁棒性问题。

在实践中，控制平面在逻辑上是集中化的，这是通过使用多个物理分布的控制器实现的。每个控制器控制一组交换机，并控制网络的特定部分，称为 SDN 域。SDN 域定期交换消息以允许同步。然而，这些 SDN 域不能是静态的。组织需要持续的网络监控和性能优化来支持高度动态的网络流量。因此，网络需要通过不断改变 SDN 域的边界来演进。静态 SDN 网络可能导致控制器负载不平衡。

研究界已经考虑了应用人工智能来自动优化网络配置。使用机器学习（ML）技术来操作网络，导致了一个称为知识平面的新构造 \[[2](#ch03.xhtml#ref3_2)\]。控制平面的逻辑集中化有助于 ML 技术，这些技术在传统的本质上分布式的网络上是不可能实现的。知识平面捕获网络流量，使用分析，并代表网络运营商做出决策。知识平面提供的闭环反馈对于实现所需的性能水平至关重要。

在本章中，我们提出了一种基于强化学习的交换机迁移，以处理控制器之间的负载不平衡问题。该框架旨在发现哪些动作会导致最优网络配置。动作是将交换机从一个控制器移动到另一个控制器。对于每个此类动作，都关联一个奖励。最终，算法将学习一组交换机迁移（动作更新），从而达到平衡网络的目标。

## 3.2 文献综述

实际网络上的流量在空间和时间上都有所变化。时间变化是由于取决于一天中的小时数的流量条件而发生的。空间流量变化是由于与各种交换机相关的应用程序产生的流量而发生的。由于这些变化，控制器上的累积流量可能会超过其容量。我们可能需要将交换机从过载控制器迁移到负载较低的控制器，以处理这种负载不平衡。然而，与静态控制器到交换机映射不同，迁移需要实时进行。另一个需要解决的问题是正在进行的流量的中断。

Dixit 等人 \[[3](#ch03.xhtml#ref3_3),[4](#ch03.xhtml#ref3_4)\] 提出通过使用等效控制器模式（在 OpenFlow v1.2 中指定）来解决负载平衡问题，同时将控制器从主控制器过渡到从控制器。此外，他们建议根据控制器负载是否超过或低于上限或下限阈值来调整控制器池的大小。

Wang 等人 \[[5](#ch03.xhtml#ref3_5)\] 提出了一个称为基于交换机迁移的决策（SMDM）的框架，其中他们计算负载多样性，即控制器负载的比率。当两个控制器之间的负载多样性超过一定阈值时，会发生交换机迁移。选定用于迁移的交换机是负载较低且效率较高的交换机。

Hu 等人 \[[6](#ch03.xhtml#ref3_6)\] 提出了感知效率的交换机迁移（EASM），其中他们使用控制器负载的归一化负载方差来衡量负载平衡的程度。如果负载差异矩阵超过阈值，则假定控制器负载不平衡。阈值是最大和最小控制器负载之间差异的函数。

Filali 等人 \[[7](#ch03.xhtml#ref3_7)\] 使用 ARIMA 时间序列模型来预测交换机的负载。预测允许找到控制器将变得过载的时间步，并相应地提前安排交换机迁移。作者使用预定义的阈值来识别过载控制器。

Zhou 等人 \[[8](#ch03.xhtml#ref3_8)\] 的工作是少数考虑由于不当交换机迁移导致的负载振荡问题的工作之一。当用于卸载过载控制器流量负载的负载较低的控制器本身迅速变得过载时，就会发生负载振荡。如作者所述，问题在于目标交换机不是根据整体网络状态选择的。

Ul Haque 等人 \[[9](#ch03.xhtml#ref3_9)\] 通过使用控制器模块（一组控制器）来解决控制器负载的方差问题。他们的方法估计交换机将在定期间隔内产生的流量数量，并相应地激活适当数量的控制器。

Chen 等人 \[[10](#ch03.xhtml#ref3_10)\] 使用博弈论方法来解决控制器负载平衡问题。负载较低的控制器被建模为竞争从过载控制器获取交换机的参与者。当负载较低的控制器被选为受害交换机的主控制器时，确定回报。

经过这项调查，我们发现，由于网络流量特征的变化，系统变得不平衡。如果我们了解网络流量的行为，那么我们就可以做出正确的决策。几篇论文使用阈值来影响交换机迁移，但它们没有概述如何确定阈值。我们提出的工作应用强化学习来提出一个学习网络流量特征的框架。它可以为选择负载较低的控制器以平衡系统负载做出最优决策。

## 3.3 SDN 中的负载平衡

在分布式 SDN 控制器架构中，转发设备（如 SDN 交换机）与其中一个控制器相关联。交换机和控制器之间最常见且最关键的消息交换是流请求消息和响应。转发设备与控制器之间的通信通过南向 API 进行。OpenFlow 是南向 API 的一个著名示例。当转发设备接收到新流时，它会向其映射的控制器发送流请求消息。在处理请求后，控制器会将分组处理规则发送到交换机。

因此，控制器上的负载是交换机发送的流请求消息数量的函数。控制器-交换机关联可以是静态的或动态的。在静态关联中，交换机根据控制器预先安装的分组处理规则将流请求定向到控制器。静态分配策略的主要缺点是它无法适应网络流量的空间和时间变化。
