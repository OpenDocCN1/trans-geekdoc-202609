API keys are simple replacements for a password and have no expiration date. They are often found in a user profile page or in the settings page for a Web application. An API key may be a long alphanumeric value (e.g., 15zv8ua896maxm). Because API keys have no expiration date assigned, anyone who obtains the key maliciously may be able to use the API to access data and backend systems for an indefinite period of time. Resetting an API key usually requires a manual step within the user profile or settings page, assuming that the API provider offers API key reset capabilities at all.

# API Tokens

API tokens are a robust alternative to API keys. They represent a session that a user is authorized to interact with an API. While they may be alphanumeric and look similar to an API key, they are not the same. An API token may represent a user or a third party who has been limited or full access to the API on the user's behalf. API tokens also have an associated expiration time.

An API token's expiration time may vary from a few seconds to a few days depending on various configuration elements. With an API token also comes a refresh token, which allows the API client to request a new API token when the previous one has expired or is no longer valid.

An API token may have one or more controls associated with it. These controls are often referred to as scopes. Multiple API tokens may be generated on behalf of a user, one with an assigned scope for read-only access of a specific API resource, another with assigned scope for read/write access to all resources, and yet another that offers a single scope for limited API access by a delegated third-party application. APIs often use a variety of methods for passing an API token to the server, including as a query argument on the URL, or through an HTTP header. Avoid using query arguments in the URL, as the API token will be logged by Web servers and reverse proxy servers, and JavaScript code may also be allowed to access the token easily. POST parameters tend to be more secure, but the location of the token will vary across APIs.

Therefore, it is recommended to use the standardized HTTP Authorization header. Access to HTTP headers can be limited through the use of CORS response headers, and headers are less likely to be logged by intermediary servers.
