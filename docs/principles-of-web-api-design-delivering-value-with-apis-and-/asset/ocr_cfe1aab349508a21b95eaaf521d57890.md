# Selecting an Async API Style

While there are several choices available for async APIs, it is important to note that some choices may be a better option than others, depending on the circumstances and constraints of the solution. Following are some considerations for each async API style to help teams determine which style(s) may be the best options for an API:

+   * **Webhooks** Webhooks are the only async API style that are server-originated—that is, they don't require the client to initiate a connection. Because subscriptions require being able to receive a POST-based callback, use Webhooks when server-to-server notification is needed. Web browsers and mobile apps are unable to take advantage of Webhooks, as they cannot establish an HTTP server to receive the callback. Subscribers with inbound communication restricted by a firewall will not be able to receive the callback, as there will be no network path to the callback server.
* **Server-Sent Events**: SSE is typically the easiest to implement on the server and client sides but has limited browser support. It also lacks bidirectional communication between client and server. Use SSE when there is a need for the server-push of events that follows RESTful API design.
