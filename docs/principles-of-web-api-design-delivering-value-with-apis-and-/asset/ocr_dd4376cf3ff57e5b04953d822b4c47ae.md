+   - A reply message provides the result, or outcome, of a command message. Reply messages often add the suffix Result or Reply to differentiate them from their command counterparts: CreateOrderReply, RegisterPaymentResult, and so on. Reply messages are also referred to as response messages. Not all command messages have a reply message

+   - Event messages tell the receiver about something that has happened in the past. A good event uses past tense to indicate that an action has taken place: OrderCreated, PaymentSubmitted, and so on. Event messages are typically used when a business event has occurred, a workflow state has changed, or data has been modified.

# Messages Are Immutable

It is important to note that messages are immutable. Once they are published, they may not be modified. Therefore, a message that requires modification must be republished as a new message. If necessary, include a correlation identifier to map the new message to the original message.
