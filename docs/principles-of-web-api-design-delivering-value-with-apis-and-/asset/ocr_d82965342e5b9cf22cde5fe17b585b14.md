Avoid using the terms service and manager, as they are generally not useful in understanding the purpose of the API.

The APIs in Figure 5.3 are named Shopping API, Order Creation API, and Payment Processing API. This is a good start and clearly articulates the scope and responsibility of each API.

# Note

Some AI designers prefer to combine the Order Creation and Payment APIs, as they could be considered cohesive and therefore should exist as a single API. They are separated in this simple example for instructional purposes. However, field insights dictate separating order creation and payment through clearly defined boundaries allows for more complex payment processing at a future without burdening the order boundary with the added complexity.
