
耗尽的资源不仅仅是时间。突发的大量传入消息可能会淹没传入电子邮件的缓冲区。大量必须处理的错误或故障状况可能会淹没日志记录和日志文件。用于重组分片通信的缓冲区也可能耗尽。

即使是识别和身份验证，在耗尽攻击中也可能变得脆弱。为了防止自动猜测攻击，某些身份验证服务在发生一定次数（如三次或五次）登录失败后，会暂时或永久禁用账户访问。因此，恶意用户可以通过反复以受害者身份登录失败来阻断访问。

### IP 分片：Teardrop 攻击

**Teardrop** 攻击滥用了一个初衷是为了改善网络通信的功能。网络 IP 数据报是一个可变长度的对象。为了支持不同的应用程序和条件，数据报协议允许将单个数据单元分片，即分成多个片段并单独传输。每个片段指示其在数据单元中的长度和相对位置。接收端将这些片段重组为单个数据单元。

如[图 6-22](#ch06.html#ch06fig22)所示，在 Teardrop 攻击中，攻击者发送一系列无法正确拼合的数据报。一个数据报可能声称其位于位置 0，长度为 60 字节；另一个位于位置 30，长度 90 字节；还有一个位于位置 41，长度 173 字节。这三个片段相互重叠，因此无法正确重组。在极端情况下，操作系统会因这些无法重组的部分数据单元而死锁，从而导致拒绝服务。

![Image](graphics/06fig22.jpg)

**图 6-22** Teardrop 攻击

导致拒绝服务的另一个原因基于网络路由：如果路由表不再指向某个站点，该站点实际上就变得不可达。我们接下来将描述路由攻击。

#### 由寻址故障导致的拒绝服务

正如我们之前所述，攻击者拒绝服务的另一种方式是通过物理或逻辑手段阻止访问。在本节中，我们将探讨阻止数据到达受害者的方法。可以看出，任何能够切断、中断或使系统容量过载的人都可以实施拒绝服务。物理威胁相当明显，将在本章后面描述。我们将重点考虑几种可能导致拒绝服务的电子攻击。在本节中，我们将探讨服务被有意或无意拒绝的方式。

错误路由是一种一举两得的攻击。假设您邻居的家庭住址是“Main Street 217 号”，但您取下了她房子上的门牌号，并将“217”挂在了您自己的房子上。那么，寄给邻居的所有邮件都会被投递到您的家里，而邻居一封也收不到。您将处于理想位置，可以检查（甚至打开）邻居本应收到的所有东西，同时阻断所有投递给邻居的邮件。这种地址变更将助长拦截和拒绝服务。网络地址也会发生类似情况，我们将在下文描述。

##### DNS 欺骗

互联网寻址的核心是一种称为 **DNS** 或 **域名系统** 协议的协议。DNS 是互联网名称到地址转换的数据库，DNS 协议将名称解析为地址。为了提高效率，DNS 服务器会构建最近使用的域名缓存；在一种称为 DNS 投毒的攻击中，攻击者试图将不准确的条目插入该缓存，以便将未来的请求重定向到攻击者选定的地址。

标准的 DNS 查询和响应如[图 6-23](#ch06.html#ch06fig23)所示，用户请求转换 URL `microsoft.com`，名称服务器响应地址 `207.46.197.32`。

![Image](graphics/06fig23.jpg)

**图 6-23** 将域名解析为地址

DNS 服务实现在远程服务器上，因此中间人攻击涉及攻击者在真正的 DNS 服务器响应之前拦截查询并进行回复。这种情况称为 **DNS 欺骗**，如[图 6-24](#ch06.html#ch06fig24)所示。在该示例中，攻击者迅速响应地址 `7.0.1.1`（推测是攻击者控制的地址）。有了这个变化，攻击者可以介入用户与 `www.microsoft.com` 的通信中间，将攻击者想要的任何内容转发给真正的 Microsoft 网站。用户的浏览器会忽略随后到达的来自 DNS 服务器的正确响应，因为浏览器已经接受了来自攻击者的虚假地址。

##### 重新路由

一种中间人攻击的示例涉及一个节点重定向网络，使所有流量都流经攻击节点，从而导致潜在的拦截。网络路由器是一个松散的、相互信任的组件联盟，它们安排通过网络（包括互联网）传递所有数据。针对路由器的中间人解释有点复杂，因此我们提供了一个强调“中间”角色的简化版本；有关此现象的更完整描述，请参阅 Hepner 等人的文献 [[HEP09](#bib01.html#bib_265)]。

每个路由器向其他路由器发送消息，列出它有路径可达的地址；其他路由器随后添加它们的路径，并将扩展后的列表转发给其他路由器。通过这种方式，所有路由器都能了解其他路由器的连接情况。在[图 6-25](#ch06.html#ch06fig25)中，四个路由器控制四个子网：A 控制 `10.0.0.0` 子网；B 控制 `20.0.0.0` 子网，以此类推。A 与 B 相邻，B 与 C 相邻，T 是另一个不与其他三个相邻的路由器。A 向其邻居通告它距离 `10.0.0.0` 子网中的任何机器的距离为 1。

![Image](graphics/06fig25.jpg)

**图 6-25** 路由器通告其子网

因为 B 刚刚得知路由器 A 距离 `10.0.0.0` 子网仅为 1，所以 B 向其邻居 A 和 C 通告它距离自己的子网为 1，距离 `10.0.0.0` 子网为 2，如[图 6-26](#ch06.html#ch06fig26)所示。当然，A 不在乎它可以通过 B 到达 `10.0.0.0` 地址；那将是一个无意义的环路，但它确实记录了 B 是通往 `20.0.0.0` 地址的最近路径。

![Image](graphics/06fig26.jpg)

**图 6-26** 路由器通告其自己的子网和其邻居的子网

[图 6-27](#ch06.html#ch06fig27)展示了 C 如何获取刚从 B 学到的信息并将其广播给与其相邻的其他路由器。通过这种方式，路由器在整个网络中通告其能力。随着时间的推移，路由器共享详细描述完整网络拓扑的信息。每个路由器维护一个目的地和下一步的表，因此如果 C 有发往 `10.0.0.0` 子网络的数据，其表将指示它应将该数据流转发给 B。

![Image](graphics/06fig27.jpg)

**图 6-27** 路由器传播路由信息
