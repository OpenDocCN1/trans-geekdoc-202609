

# Stuxnet 病毒攻击伊朗核设施

2010 年 6 月，伊朗的核浓缩设施遭到了复杂且精密的计算机病毒 Stuxnet 的袭击（在[第 3 章](#ch03.html#ch03)中提及，在[第 13 章](#ch13.html#ch13)中讨论）。Stuxnet 以工业控制系统为目标，通过修改可编程逻辑控制器（`PLCs`）上的代码，使其按攻击者预期的方式工作，并对设备操作员隐藏这些更改。Stuxnet 攻击的系统是使用西门子 Simatic 控制器的系统，显然位于布什尔或纳坦兹的核电站。Stuxnet 以用于控制设备（如电机）转速的特定电源为目标。该恶意软件修改了从西门子 SCADA 软件发送到驱动器的命令，导致控制器改变设备的转速，使其间歇性地变速。

Stuxnet 以高速运行的特定驱动器为目标。这种高速仅用于特定应用，其中之一是铀浓缩。根据赛门铁克的 Eric Chien 称：“Stuxnet 在短时间内将输出功率频率改为 1410Hz，然后改为 2Hz，再改为 1064Hz。” [[FAL10](#bib01.html#bib_187)] 电机的正常频率为 1064 Hz；以 1400 Hz 的速度运行可能会损坏设备。这种剧烈的频率振荡导致电机加速、减速，然后再加速。浓缩铀需要离心机以精确的速度长时间旋转；改变速度会显著降低浓缩产品的质量。

确实，一些外部专家认为，在 2009 年至 2010 年 Stuxnet 活动高峰期，伊朗浓缩计划中约 8000 台离心机中多达 1000 台发生故障。伊朗自行制造离心机，众所周知它们经常发生故障，尽管可能没有达到 8000 台中 1000 台那么多。该病毒也可能旨在让维护工程师和设计师忙于更换故障硬件并想办法维持整个系统运行。Stuxnet 可能导致了这种故障率，这或许是恶意攻击导致硬件故障的首个案例。

# 端口扫描

扫描是一种检查活动，因此它本身不会造成危害（如果你不认为了解对手是一种危害）。然而，扫描通常被用作攻击的第一步，即探测，以确定哪些进一步的攻击可能会成功。因此，我们接下来介绍针对子网架构和暴露面进行探测的主题。

不同版本软件产品中的漏洞是众所周知的：供应商会发布缺陷列表以及防护或纠正措施（补丁和变通方法），安全专业人员也维护和分发类似的列表，以及用于测试漏洞的工具。黑客流传攻击代码和脚本的副本。攻击者面临的问题是知道对哪些机器发起哪些攻击：针对特定版本 Adobe Reader 的攻击，如果目标机器不运行 Reader 或运行的版本不包含该特定漏洞，则不会奏效。向非易受攻击的机器发送攻击至少是耗时的，但更糟的是，甚至可能使攻击者暴露或变得可识别。攻击者只想将箭射向可能的目标。

收集网络信息的一个简单方法是使用**端口扫描器**，这是一种程序，针对特定的互联网（`IP`）地址，报告哪些端口响应查询，以及存在哪些已知漏洞。Dan Farmer 和 Wietse Venema [[FAR90](#bib01.html#bib_188), [FAR95](#bib01.html#bib_189)] 是最早使用 COPS 和 SATAN 工具描述该技术的人之一。此后，NESSUS 和 Nmap 等工具扩展了网络探测的概念。

---

**端口扫描可绘制网络段的拓扑结构以及硬件和软件组件。**

---

端口扫描很像医生的常规体检，特别是用于确定病史的初步询问。问题和答案本身可能看起来不重要，但它们指向了建议进一步调查的领域。

## 端口扫描工具

端口扫描工具随处可得，不仅限于地下社区。最初由 Fyodor 编写、可在 [www.insecure.org/nmap](http://www.insecure.org/nmap) 下载的 Nmap 扫描器是一个任何人都可以下载的有用工具。给定一个地址，Nmap 将报告所有开放端口、每个端口支持的服务，以及提供该服务的守护进程的所有者（用户 ID）。（所有者很重要，因为它暗示了攻破该服务的人将获得什么权限。管理员倾向于用 `admin` 或 `system` 之类的名称命名特权账户。）

另一个现成的扫描器是 netcat，由 Hobbit 编写，位于 [www.l0pht.com/users/l0pht](http://www.l0pht.com/users/l0pht)。商业产品稍贵一些，但并非高不可攀。知名的商业扫描器有 Nessus（Nessus Corp. [[AND03](#bib01.html#bib_17)]）、CyberCop Scanner（Network Associates）、Secure Scanner（Cisco）和 Internet Scanner（Internet Security Systems）。

## 端口扫描结果

正如本章前面所述，端口只是将数据路由到等待它的特定程序的一个数字标识。等待的程序称为守护进程，据说它监听特定端口；实际上，它向网络管理软件注册，以便接收发往该端口的数据。例如，按照惯例，端口 110 是与邮件局协议关联的端口号，80 专用于 HTTP（网页）流量，123 分配给网络时间协议用于时钟同步。随着时间的推移，服务数量超过了可用数字的范围，因此存在冲突、重用、非正式使用和重新分配。

让我们继续之前关于数据请求进入端口 110（邮局协议）的讨论。客户端通过 ASCII 文本命令中实现的定义协议发起连接 POP 服务器的请求。服务器响应，通常标识自身，有时还包括版本号（以便客户端和服务器在功能和预期上同步）。我们在[图 6-11](#ch06.html#ch06fig11) 中展示了该交换的示例。来自客户端的行标记为 `CL`，来自 POP 服务器的响应标记为 `SV`。任何人都可以通过使用 Telnet 终端仿真程序发起此类交换。

[点击此处查看代码图像](#ch06_images.html#pp-06fig11a)

```
CL:    telnet incoming.server.net 110

SV:    +OK Messaging Multiplexor (Sun Java(tm) System Messaging Server
6.2-6.01 (built Apr  3 2006))
<4d3897ff.11ec04f8@vms108.mailsrvcs.net>

CL:    user v1

SV:    +OK password required for user v1@server.net

CL:    pass p1

SV:    -ERR [AUTH] Authentication failed

CL:    quit

SV:    +OK goodbye
```
