
同样，测试几乎总是受限于项目的预算和进度安排。这些限制通常意味着测试在某些方面是不完整的。因此，我们在测试策略中考虑测试覆盖率、测试完整性和测试有效性的概念。我们的测试越完整、越有效，我们对软件的信心就越强。更多关于测试的信息可参见 Pfleeger 和 Atlee [[PFL10](#bib01.html#bib_485)] 的著作。

### 专门针对安全的对策

通用软件工程原则旨在产出正确的代码，这当然也是一个安全目标。然而，在程序设计、实现和部署过程中，也存在专门旨在提高成品安全性的活动。接下来我们将探讨这些实践。

#### 安全设计原则

Multics（多路复用信息与计算服务）是一个主要的安全软件项目，旨在为用户提供计算公用设施，就像我们使用电力或水一样。系统愿景是用户能毫不费力地连接到它，使用所需的计算服务，然后断开连接——就像我们打开和关闭水龙头一样。显然，计算机安全的三个基本目标——机密性、完整性和可用性——对于这种广泛共享的事业都是必要的，安全也是三个参与方：麻省理工学院、AT&T 贝尔实验室和通用电气公司的主要目标。尽管该项目从未取得显著的商业成功，但其开发过程帮助确立了安全计算作为一门严谨且活跃的学科。Unix 操作系统源于 Multics，其他现在常见的操作系统设计元素也是如此，例如分层文件结构、动态调用模块和虚拟内存。

Multics 的首席安全架构师 Jerome Saltzer 和 Michael Schroeder 记录了几条旨在提高他们正在开发的代码安全性的设计原则。其中几条原则对于构建一个可靠、受信的操作系统至关重要。这些原则在 Saltzer [[SAL74](#bib01.html#bib_535)] 和 Saltzer 与 Schroeder [[SAL75](#bib01.html#bib_536)] 的著作中得到了清晰的阐述，包括以下内容：

* **最小权限**。每个用户和每个程序都应使用尽可能最少的特权进行操作。这样，无意或恶意攻击造成的损害将被最小化。
* **机制经济性**。保护系统的设计应当小巧、简单且直截了当。这样的保护系统可以被仔细分析、彻底测试、甚至被验证，并值得信赖。
* **公开设计**。保护机制不应依赖于潜在攻击者的无知；机制应当是公开的，仅依赖极少数关键项目的保密性，例如密码表。公开的设计也可供广泛的公众审查，从而提供对设计安全性的独立确认。
* **完全中介**。每一次访问尝试都必须被检查。必须同时考虑直接访问尝试（请求）和绕过访问检查机制的尝试，并且该机制的定位应使其无法被绕过。
* **基于许可**。默认条件应为拒绝访问。保守的设计者会识别出应该可访问的项目，而不是那些不应该可访问的项目。
* **权限分离**。理想情况下，对对象的访问应取决于不止一个条件，例如用户认证加上加密密钥。这样，攻破一种保护系统的人将无法获得完全访问权。
* **最小公共机制**。共享对象为信息流提供了潜在通道。采用物理或逻辑分离的系统可降低共享带来的风险。
* **易用性**。如果保护机制易于使用，就不太可能被用户规避。

这些原则已被安全社区普遍接受，认为有助于软件和系统设计的安全性。尽管它们源于计算机的“石器时代”——20 世纪 70 年代，但它们今天至少同样重要。作为这些基本准则何其根本和有效的标志，请参考卡内基梅隆大学软件工程学院计算机应急响应小组（CERT）最近发布的“十大安全编码实践” [[CER10](#bib01.html#bib_113)]。

1. 验证输入。
2. 重视编译器警告。
3. 为安全策略进行架构和设计。
4. 保持简单。
5. 默认拒绝。
6. 遵循最小权限原则。
7. 清理发送到其他系统的数据。
8. 实践纵深防御。
9. 使用有效的质量保证技术。
10. 采用安全编码标准。

这十条中，第 4、5、6 条直接对应 Saltzer 和 Schroeder 的原则，第 3、8 条是该工作的自然延伸。同样，代码卓越软件保障论坛（SAFECode）^([2](#ch03a.html#ch03fn02a)) 发布的一份指导文档 [[SAF11](#bib01.html#bib_534)] 也与这些概念兼容，其中包括实施最小权限和沙箱（稍后定义）等建议，这些源自权限分离和完全中介。我们将在本章中详细阐述 SAFECode 的许多要点，并建议您在读完本章后阅读他们的完整报告。其他作者，如 John Viega 和 Gary McGraw [[VIE01](#bib01.html#bib_637)] 以及 Michael Howard 和 David LeBlanc [[HOW02](#bib01.html#bib_280)]，也在开发安全程序的过程中详细阐述了这些概念。

[2](#ch03a.html#ch03fn02). SAFECode 是一个非营利组织，专门致力于通过推进有效的软件保障方法，增加对信息和通信技术产品及服务的信任。其成员包括 Adobe Systems Incorporated、EMC Corporation、Juniper Networks, Inc.、Microsoft Corp.、Nokia、SAP AG 和 Symantec Corp.

#### 面向安全的渗透测试

本章所述的测试方法描述了适用于所有测试目的的方法：正确性、易用性、性能以及安全性。在本节中，我们将探讨几种在发现安全缺陷方面特别有效的方法。

我们在本章前面指出，**渗透测试**或**虎队分析**是计算机安全中常用的一种策略。（例如参见 [[RUB01](#bib01.html#bib_527), [TIL03](#bib01.html#bib_619), [PAL01](#bib01.html#bib_468)]。）有时它被称为**道德黑客攻击**，因为它涉及由一个专家团队尝试破解被测系统（而不是出于不道德原因闯入系统）。渗透测试人员的工作与实际攻击者可能做的事情非常相似 [[AND04](#bib01.html#bib_18), [SCH00b](#bib01.html#bib_543)]。虎队非常了解操作系统和计算系统中的典型漏洞。利用这些知识，该团队尝试识别并利用系统的特定漏洞。

渗透测既是一门艺术，也是一门科学。艺术的一面要求在选择测试用例时进行仔细分析和创造性思考。但科学的一面要求严谨、有序、精确和组织性。正如 Clark Weissman 所观察到的 [[WEI95](#bib01.html#bib_651)]，存在一种用于假设和验证缺陷的有组织方法论。这并非如某些人所想，是一场随机的拳击比赛。
