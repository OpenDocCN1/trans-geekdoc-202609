
正如您出于安全原因希望专用化 VM 一样，您也希望专用化网络。IaaS 提供商通常为客户提供选项，可轻松将系统隔离到无法从互联网寻址的私有网络飞地中。使用这些私有飞地按功能隔离您的系统（参见[图 8-8](#ch08.html#ch08fig08)）。例如，将 FTP 服务器放在一个飞地中，将 Web 服务器放在另一个飞地中。使用防火墙规则保护每个飞地，将流量限制在您已知必要的范围内。执行所有这些操作将最大程度地限制每个系统的暴露面，并有助于防止攻击在您的系统间蔓延。当然，这些系统大多将是必须以某种方式从互联网访问的服务器；为此，请使用应用代理服务器将流量中继到私有飞地中。您可能希望将我们在[第 6 章](#ch06.html#ch06)中讨论的典型边界防护设备——防火墙、IDS、IPS 及其同类——放置在位于互联网和代理服务器之间的 VM 中。

![Image](graphics/08fig08.jpg)

**图 8-8** IaaS 安全飞地

您的 VM 必须运行 SSH 或某种屏幕共享软件，以便您对其进行管理。限制对这些服务的访问：它们是攻击者的主要目标。实现这一点的一种方法是使用网络 ACL 限制 SSH 和屏幕共享流量，使连接必须源自您的 IP 地址空间。您还可以使用日志数据来发现并调查针对这些服务的登录失败尝试。您应从所有 VM 收集日志数据，但除非绝对必要，请勿将日志数据存储在与您的 VM 相同的 IaaS 基础设施上。如果 IaaS 基础设施遭到入侵，攻击者不应有机会通过擦除日志来掩盖踪迹。

实施和维护我们推荐的所有 IaaS 控制措施并非易事，但非常值得。除了这些针对 IaaS 的控制建议外，本书中描述的所有网络和操作系统安全最佳实践均适用于 IaaS 环境。如果您能真正通过将系统限制在最低限度的功能来最小化 VM 和网络攻击面，攻击者将极难有所作为。即使攻击者设法控制了您的某个 VM 或飞地，严格受限的用户权限结合应用程序白名单也应有助于防止进一步损害。

### 8.6 结论

云具有五个定义特征：

*   **按需自助服务**
*   **广泛的网络访问**
*   **资源池化**
*   **快速弹性**
*   **计量服务**

有三种基本类型的云服务——SaaS、PaaS 和 IaaS——以及四种基本服务模型：公有、私有、社区和混合。云服务和服务模型的选择应建立在仔细的风险分析和云提供商评估基础之上。

云服务使客户面临新威胁，但也可以成为有用的安全工具。它们对于可用性以及增强小型组织的安全性特别有帮助。

云客户在应对发生在云提供商系统上的安全事件时，可预期拥有有限的选择。客户应主动与云提供商合作，了解在这些情况下将提供何种支持。

FIdM 允许云客户使用云资源，而无需额外的一组登录凭据。它还允许所有登录凭据和认证选项由客户组织集中管理。SAML 和 OIDC 目前是用于认证的主流 FIdM 标准，而 OAuth 是用于 API 授权的主流 FIdM 标准。

保护 IaaS 意味着在充分利用 VM 和虚拟网络的安全优势的同时，保护您的系统免受共享基础设施带来的威胁。在使用共享基础设施时，审慎地使用加密（无论是传输中数据还是静态数据）至关重要。VM 应被隔离在飞地中，并配置为高度专用化，以最大程度地减少其攻击面和成功攻击的影响。

#### 领域发展方向

云计算安全研究的大部分集中在通过共享基础设施发起的攻击上。Zhang 等人关于跨 VM 侧信道攻击的研究[[ZHA12](#bib01.html#bib_669)]是这一趋势的有力例证。另一方面，由 MIT 的 Shafi Goldwasser 领导的研究人员[[GOL13](#bib01.html#bib_231)]正在研究同态加密，这是一种技术，将来可能允许用户在共享基础设施上处理数据，而无需解密。UCLA 的研究人员正在引领密码学混淆[[GAR13](#bib01.html#bib_215)]方面的工作，这将来可能允许用户在共享基础设施上运行软件，而不会冒任何其他基础设施用户甚至识别出该软件功能的风险。

波士顿大学的一个研究团队正在创建他们所谓的云安全模块化方法（MACS）。MACS 的目标是从小型模块化组件构建云基础设施，每个组件都有自己的安全保证。他们的目标是将这些组件组装成比当今云环境中存在的系统具有更强、更可分析安全性的系统。

#### 了解更多

CSA 的安全指导白皮书[[CSA11](#bib01.html#bib_136)]全面概述了云安全问题。NIST SP 800-144[[JAN11](#bib01.html#bib_294)]、800-145[[MEL11](#bib01.html#bib_397)] 和 800-146[[BAD12](#bib01.html#bib_43)] 提供了进一步的云安全指导。

有关取证证据收集的更详细指南，请参阅 RFC 3227[[BRE02b](#bib01.html#bib_96)]。

要更完整地了解 SAML，请参阅 SAML 协议标准[[OAS05a](#bib01.html#bib_458)] 和 SAML 安全关注标准[[OAS05b](#bib01.html#bib_459)]。对于有兴趣构建支持 OAuth 服务的开发人员，RFC 6819[[LOD13](#bib01.html#bib_373)] 详细列出了与 OAuth 2.0 相关的威胁和建议的对策。其他典型的 OAuth 信息流和用例定义在 RFC 6749[[HAR12](#bib01.html#bib_259)] 中。

Todorov 和 Ozkan 的白皮书[[TOD13](#bib01.html#bib_620)] 提供了 IaaS 最佳实践的有力概述。
