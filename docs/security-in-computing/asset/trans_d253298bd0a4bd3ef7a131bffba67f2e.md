

客户端和服务端协商用于认证、会话加密和哈希的加密算法，称为**密码套件**。为了允许算法随时间推移进行扩展和弃用，首先发起交互的一方（通常是客户端）声明其首选算法，第二方则从该列表中选择其能够处理的最高优先级算法进行响应。互联网号码分配局（IANA）在全球范围内协调 DNS 根区、IP 地址分配和其他互联网协议资源，包括密码套件；我们在[表 6-4](#ch06a.html#ch06tab04)中展示了一些可选项。当客户端和服务端开始 SSL 会话时，服务端发送一组记录，列出其可使用的密码套件标识符；客户端则从该集合中响应其首选选择。正如表中所示，SSL 支持使用我们深入描述过的流行加密算法，例如 `RSA`、三重 `DES` 和 `AES`；IANA 还批准使用 `Camellia` 和 `Aria` 等算法，这些算法在某些国家更为常用。(`Camellia` 和 `Aria` 是类似于 `DES` 和 `AES` 的分组密码；`Camellia` 由三菱和 NTT 于 2000 年设计，`Aria` 由韩国密码学家于 2003 年开发。椭圆曲线密码系统是一种公钥密码学；我们将在[第 12 章](#ch12.html#ch12)中更详细地描述它们。)

### SSL 会话

由于 SSL 常用于网页，因此常被称为 `HTTPS`（HTTP Secure），你会在浏览器地址栏看到 `https:` 前缀，以及在 SSL 运行时角落里出现的关闭的挂锁图标。要使用 SSL，客户端请求一个 SSL 会话。服务端响应其公钥证书，以便客户端确定服务端的真实性。客户端返回一个用服务端公钥加密的对称会话密钥。服务端和客户端均计算出会话密钥，然后切换到加密通信，使用共享的会话密钥。

SSL 会话建立后，可以查看会话的详细信息。例如，[图 6-41](#ch06a.html#ch06fig41) 显示了一个与 `https:login.yahoo.com` 建立的 SSL 连接。

证书和签名者链之所以重要，是因为存在**不道德的 CA** 的可能性。如果你检查浏览器中预加载的 CA 证书集合，很可能会发现来自世界各地的熟悉和陌生的组织名称。这些 CA 中的任何一个都可以为另一个较低级别的证书颁发机构签署证书，依此类推，直到参与 SSL 会话的单个组织。例如，如果攻击者想建立一个假冒银行网站，让一个不道德的 CA 为 SSL 颁发证书，会增加该网站的表面可信度，而不一定提供安全性。

最后，在[图 6-44](#ch06a.html#ch06fig44) 中，你可以看到 `DigiCert` 根证书是由 `GTE CyberTrust Solutions` 颁发的。其他字段包括有效期、使用的算法、颁发日期和联系详情。因此，感兴趣的用户可以比较从受信任根开始的完整证书和签名链。

![Image](graphics/06fig44.jpg)

**图 6-44** 根证书

尽管预加载的证书颁发机构是信誉良好的，但如果其中一个为一个不太光彩的公司签署证书，SSL 操作仍会成功。SSL 要求来自浏览器列表中 CA 的证书链，但对浏览器而言，所有这些 CA 都具有同等的可信度。这就是为什么你应该检查你加载的证书集合，以确保你会信任它们中任何一个签署的任何内容。

SSL 协议简单但有效，是互联网上使用最广泛的安全通信协议。然而，请记住，SSL 仅保护从客户端浏览器到服务端解密点的数据（这通常仅到达服务端的防火墙，或者稍强一些，到达运行 Web 应用程序的计算机）。数据从用户键盘到浏览器，以及在接收方环境中始终是暴露的。请记住我们在[第 4 章](#ch04.html#ch04)中描述的击键记录器和中间人浏览器攻击的漏洞。`Blue Gem Security` 开发了一款名为 `LocalSSL` 的产品，它从数据被输入时起进行加密，直到操作系统将其传递给客户端浏览器，从而挫败任何已植入用户计算机、旨在窃取用户输入内容的键盘记录木马。

### 洋葱路由

正如我们所描述的链路加密和端到端加密，通信的数据部分为保密性得到了保护。然而，寻址数据却是暴露的。因此，监控 A 点和 B 点之间流量的人会知道通信的流量大小。

Paul Syverson 及其同事 [[SYV97](#bib01.html#bib_608)] 引入了**洋葱路由**的概念。该模型使用一组转发主机，每个主机仅知道通信是从哪里接收的以及下一步发送到哪里。因此，要从 A 向 B 发送不可追踪的数据，A 选择一定数量的转发主机，称它们为 X、Y 和 Z。A 首先使用 B 的公钥加密通信。然后 A 添加一个从 Z 到 B 的头部，并使用 Z 的公钥加密结果。接着 A 在其上添加一个从 Y 到 Z 的头部，并使用 Y 的公钥加密。然后 A 再添加一个从 X 到 Y 的头部，并使用 X 的公钥加密。最后，A 添加一个发送数据包给 X 的头部。

收到数据包后，X 解密它，发现指示将内层数据包转发给 Y 的指令。Y 随后解密它，发现指示将内层数据包转发给 Z 的指令。Z 然后解密它，发现指示将内层数据包转发给 B 的指令。数据包像剥洋葱层一样被逐层解构，这就是为什么这种技术被称为洋葱路由。

没有中间主机能知道最终接收者是谁。即使 Z 也无法判断 B 是最终目的地，因为 Z 传递给 B 的内容是用 B 的公钥加密的。因此，X、Y 和 Z 只知道它们是中介，但不知道还有哪些其他中介、有多少中介，以及它们在链中的位置。任何中间接收者——原始发送者和最终接收者之外的实体——既不知道数据包从何而来，也不知道将去向何方。该方案提供了内容、源、目的地和路由的机密性。
