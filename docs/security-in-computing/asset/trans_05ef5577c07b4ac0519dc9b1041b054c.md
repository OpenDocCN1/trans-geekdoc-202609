发生了什么？请记住，操作系统功能是由分布在整个操作系统中的任务实现的。用于显示文件列表的实用程序使用诸如 `FindNextFile()` 和 `NTQueryDirectoryObject` 之类的原语。为了保持不可见，Rootkit 会拦截这些调用，因此如果 `FindNextFile()` 的结果指向 `mal_code.exe`，Rootkit 就会跳过该文件并再次执行 `FindNextFile()` 以查找 `mal_code.exe` *之后* 的下一个文件。生成列表的高级实用程序会保留其接收到信息的文件大小的运行总计，因此列表中的总计正确报告了除 `mal_code.exe` 之外的所有文件。这种 Rootkit 的隐蔽操作如[图 5-22](#ch05.html#ch05fig22)所示。

这些列表是用简单的 DOS `dir` 命令生成的，用于表示这些系统 API 产生的输出类型。如果攻击者拦截并修改了进入 API 的输入或来自 API 的输出，其效果就是使文件 `mal_code.exe` 对高级调用者不可见。因此，如果防病毒工具通过获取文件列表并检查每个文件来进行扫描，该工具将会遗漏恶意文件。

Rootkit 实际上成为了操作系统内核的一部分。在本例中，Rootkit 干扰了磁盘上文件的枚举，因此它不会将自己的文件名传递给病毒检查程序进行检查。但是，因为 Rootkit 与操作系统集成在一起，它可以执行操作系统能够执行的任何功能，通常无法被检测到。例如，它可以替换操作系统的其他部分，重写处理中断的例程的指针，或从系统启动时要调用的代码列表中移除程序（如恶意代码检查器）。这些行为除了更常见的恶意效果之外，还包括删除文件、将敏感数据发送到远程系统，以及将有害代码转发给电子邮件联系人。

Rootkit 以操作系统组件的权限和位置运行。它作为操作系统启动的一部分自动加载，并且由于其位置，它可以拦截和修改操作系统调用和返回值，如[图 5-23](#ch05.html#ch05fig23)所示。操作系统执行审核日志记录，但 Rootkit 可能无法将其自身的活动传递给日志记录器。Rootkit 处于保持未被发现和不可发现的最佳位置，并可不受限制地执行任何操作。

### Rootkit 在无监管状态下运行

在[第 3 章](#ch03.html#ch03)中，我们介绍了恶意代码的概念，例如病毒或特洛伊木马，它们从系统传播到系统，并在当前用户的权限下运行。正如我们在该章中所说，恶意代码作者的一个目标是提升权限，即以管理员或更强大用户的更高权限运行；显然，代码拥有的特权越多，造成的危害就越大。终极特权级别是操作系统，因此替换部分或全部操作系统功能相当于获得了最高权力。

因为它们想要保持不被发现，Rootkit 可能难以检测和根除，甚至难以统计。据估计，Rootkit 占所有恶意代码的 7% [[TRE10](#bib01.html#bib_622)]。正如[侧边栏 5-7](#ch05.html#ch05sb07)所述，Rootkit 还可能干扰计算机维护，因为它们的功能可能与正在被修改的其他操作系统功能交织在一起。

#### 侧边栏 5-7 Rootkit 导致内核修改失效

2010 年 2 月，微软发布了其惯例的每月操作系统更新，其中包括一个名为 MS10-015 的补丁，级别为“重要”。该补丁旨在修复一个先前已公开的漏洞和一个未公开的漏洞。微软建议用户尽快安装补丁。

不幸的是，这个补丁显然以一种相当戏剧性的方式干扰了恶意 Rootkit 的操作。发布补丁后，微软收到了大量用户投诉，这些用户安装补丁后突然发现他们的计算机陷入了无休止的重启循环。微软发布了如下建议：“在 32 位版本的 Microsoft Windows 上安装此更新后，您可能会在蓝屏上收到一条 Stop 错误消息，导致计算机反复重启。此问题可能是由安全更新与驻留在系统上的恶意软件之间的冲突引起的。此问题不是安全更新的质量问题，也不特定于任何 OEM。” [[MIC10](#bib01.html#bib_403)] 当然，那些机器已经陷入持续重启的人无法阅读微软发布的消息。

显然，在系统启动时，TDL-3 或 Alureon Rootkit 构建了一个表，使用特定 Windows 内核函数的固定地址。在微软补丁中，这些地址被更改了，因此当 TDL-3 获得控制权并尝试调用一个（真实的）内核函数时，它转移到了错误的地址，系统随即关闭，出现所谓的“蓝屏死机”（显示器在蓝色背景上显示文本错误消息并重启）。

无法知道 Alureon 或任何 Rootkit 在整个计算机群体中的普遍程度。微软接收其恶意软件删除工具从用户机器中移除的感染报告。仅在 2010 年 4 月，该工具就移除了 262,969 个 Alureon 变体实例，因此与 MS10-015 的交互可能很严重。

Rootkit 干扰正常系统功能以保持隐藏。正如我们所描述的，一种常见的 Rootkit 伎俩是拦截文件目录枚举函数以隐藏 Rootkit 的存在。啊，两可以玩这个游戏。假设你怀疑代码正在干扰你的文件显示程序。然后你编写一个程序来显示文件，直接检查磁盘和文件系统以枚举文件，并比较这两个结果。Rootkit 揭示器就是这样的程序。

### Sony XCP Rootkit

一位名为 Mark Russinovich 的计算机安全专家开发了一个 **Rootkit 揭示器**，并在他的一台系统上运行。Russinovich 没有使用像文件管理器这样的高级实用程序来清点所有文件，而是编写了直接调用 `NTQueryDirectoryObject` 函数的代码。通过在他的程序中汇总文件大小，他将目录大小与文件管理器报告的大小进行了比较；差异促使他进一步调查。他惊讶地发现了一个 Rootkit [[RUS05](#bib01.html#bib_531)]。进一步调查后，他确定该 Rootkit 是在他加载并播放一张 Sony 音乐 CD 时安装的。普林斯顿大学的研究人员 Edward Felten 和 Alex Halderman [[FEL06](#bib01.html#bib_192)] 对这个名为 XCP（extended copy protection，扩展复制保护的缩写）的 Rootkit 进行了广泛检查。
