
这些攻击试图通过限制系统解析地址的能力来拒绝服务。由于地址解析在互联网中是分布式的，这些攻击往往更有效地导致局部拒绝服务，而对大片网段的效果较差。

拒绝服务攻击通常是二级攻击。首先，攻击者将攻击代码植入目标系统；然后，在代码就位后，攻击者触发该代码以实施拒绝服务攻击。接下来我们将探讨攻击者如何渗透目标系统，以便从中发起拒绝服务攻击。

### 会话劫持

在**会话劫持**攻击中，攻击者允许双方开始交互，但随后转移通信，这很像中间人攻击。例如，设想登录到一个金融网站，完成身份验证，然后会话被攻击者接管。金融网站通常通过加密得到良好保护，但其他网站可能脆弱，例如那些传输医疗记录或支持师生互动的网站。

会话劫持得益于 TCP/IP 协议设计的某些要素。首先，考虑 IP 协议头部，如[图 6-29](#ch06.html#ch06fig29)所示。关键部分是第 12-19 字节，包含源和目的 IP 地址。目的地址的用途显而易见；源地址是必要的，以便接收方能生成响应消息发回给发送方。在从源到目的的旅程中的任何一点，攻击者都可以更改该源地址，从而将响应重定向给攻击者，而非原始发送方。

如果数据包乱序到达，协议处理程序使用 TCP 序列号和确认号，即[图 6-30](#ch06.html#ch06fig30)中的第 4-11 字节，来重构数据项。TCP 协议在设计时考虑到了不稳定的网络，因此它包含识别和纠正错误的功能，不仅针对消息数据的损坏，也针对这些头部中显示的控制数据的损坏。

发送方创建并发送数据包 1，然后是 2、3，依此类推，接收方在收到数据包时返回带有确认号的数据包，如[图 6-31](#ch06.html#ch06fig31)所示。我们通过仅从客户端视角展示排序，略微简化了解释。客户端发送其当前缓冲区指针，服务器确认该相同指针。（对于完整协议，双方各自确认对方的最后一个指针，并发送其当前指针，该指针已核算最新收到的数据。）如果客户端发送一个带有错误的序列号和确认号对的数据包，这将破坏同步，接收方将丢弃数据包，直到收到一个与前一个确认号匹配的数据包。如果它们不重新同步，则会终止并重新建立会话。因此该协议具有自愈性，因为一旦两端重新同步，它们就能确定最后一次成功的交换，并从该点开始重传。

![Image](graphics/06fig31.jpg)

**图 6-31** 正常 TCP 交换

攻击者可以利用这种纠正机制，插入一个与接收方保持同步但破坏与真实发送方同步的数据包。攻击者和接收方现在重新同步，并继续原始发送方开始的交换。通过这种方式，如[图 6-32](#ch06.html#ch06fig32)所示，攻击者悄无声息地滑入会话，取代了原始发送方的位置。这个插入的数据包是一个由中间人精心构造的重放包。该攻击由 Robert Morris, Sr. 发现 [[MOR85](#bib01.html#bib_416)]，并由 Steven Bellovin 扩展 [[BEL89](#bib01.html#bib_54)]。

![Image](graphics/06fig32.jpg)

**图 6-32** TCP 劫持

同时，如[图 6-33](#ch06.html#ch06fig33)所示，攻击者向原始发送方发送一个 `RST`（复位）命令，使发送方相信接收方已关闭原始连接。发送方可能尝试与接收方打开一个新连接，却不知攻击者正在继续之前的会话。取决于当时运行的应用程序，攻击者可以接受发送方作为新用户（可能要求用户重新认证），或因连接重复而拒绝该用户。

![Image](graphics/06fig33.jpg)

**图 6-33** 复位原始发送方

因此，通过会话劫持攻击，攻击者可以在两个原始参与方都不明显的情况下滑入正在进行的通信流中；通信在攻击者替代原始发送方的情况下继续，而该发送方被阻止。由于瞬间连接丢失由许多良性原因引起，用户倾向于不怀疑这是攻击；会话通常由网络协议处理程序在用户不知情的情况下重新建立。

攻击者简单地融入通信流中，从原始发送方手中接管交互。攻击之所以成功，是因为攻击者能看到并操纵 TCP 和 IP 头部，但当然这些头部必须在整个网络中可见，因为它们是实现流量投递的基础。然而，我们在下一节将展示一种防范劫持的方法，既通过在应用层隐藏连接数据，又通过隐藏头部数据。

### DNS 缓存投毒

**DNS 缓存投毒**攻击是一种颠覆寻址的方式，导致 DNS 服务器将客户端重定向到指定地址。一种概念上简单的 DNS 投毒攻击是向 DNS 注册机构伪造一条消息，请求将特定域名从一个地址更改为另一个地址。当网站从一个托管提供商迁移到另一个，或组织更改其地址结构时，此类请求正常发生。然而，恶意攻击者可以利用 DNS 更改请求，将发往特定域名的流量重定向。由于强认证要求，注册机构很少落入此类伪造陷阱。

一种更可能的攻击是利用所有互联网名称服务器协调其地址转换的 DNS 协议消息。Dan Kaminsky [[KAM08](#bib01.html#bib_311)] 扩展了一些先前已知的方法来投毒 DNS 缓存。DNS 协议很复杂，但你不需要了解细节就能理解这种攻击。

需要域名对应地址的客户端向其本地 DNS 名称服务器发送查询。如果该服务器没有答案，它会将查询转发给根名称服务器；查询被转发给更具体的名称服务器，直到有一个服务器以权威方式回复地址。该地址通过解析查询涉及的服务器链传播，最终返回给客户端。沿途的服务器缓存响应，以便它们可以直接响应针对同一地址的未来查询。
