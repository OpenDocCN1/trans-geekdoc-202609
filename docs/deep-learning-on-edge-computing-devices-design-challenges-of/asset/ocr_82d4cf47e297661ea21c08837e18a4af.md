In a functional point of view, the input data of each core are processed as coded address events. The address event \(i\) is active when the \(i\)th visible unit is one, which triggers a look-up operation; otherwise, the address event \(i\) is inactive, and the core will check the next visible unit for an active address event. No look-up operation will be fired until a nonzero visible unit is found. The zeros in the input data stream are omitted, and only the spikes of ones can activate the core.
