
# 增强持续监控

关键供应商清单在 KC 近期董事会层面的风险委员会会议上被多次讨论。他们向网络第三方风险领导层提出疑问，是否应对该清单进行更深入的尽职调查，以进一步降低泄露风险。在审查其他尽职调查工作时，他们发现除提出更多问题外，在准入、持续或现场评估方面几乎无事可做。然而，问题在于这些项目虽然已发展完善，但仍聚焦于某一时间点。随着疫情的爆发，形势发生了变化，网络犯罪和活动的急剧增加意味着他们需要更多地关注持续监控方面。

因此团队创建了名为增强持续监控的项目，该项目基于第三方泄露的历史和典型的薄弱安全点，聚焦于四个关键风险领域（软件漏洞、第四方风险、数据位置和连接）。

## 软件漏洞/补丁节奏

正如书中一些泄露案例研究所示，KC 团队注意到许多事件都是由于供应商未按照其自身的补丁和漏洞管理政策更新软件所致。有必要了解他们运行的软件和版本，以便为公司提供服务。虽然 KC 网络安全团队承担供应商漏洞管理项目的一部分，但风险已高到足以值得投资。任何对贵公司系统性关键的供应商都必须提供用于向其提供服务的软件清单。

## 第四方风险

第四方风险是真实存在的，KC 曾观察到其竞争对手和其他公司因此遭到泄露的实例。然而，管理第四方的范围存在问题。在 KC Enterprises，有数百家供应商，每家供应商可能还有数百家自己的供应商（即对 KC 而言的第四方），数据量过大，且方法并非基于风险。KC 决定系统性关键风险类别规模足够小且重要性足够高，也值得投入资源了解这些供应商为向 KC 提供服务或产品所使用的第四方。

被列为对运营系统性关键的第三方必须列出所有为 KC 提供服务所需的供应商（即 KC 的第四方）。该清单在尽职调查周期中的多个节点得到验证。在准入流程中，该清单会被收集，并在现场评估以及任何持续监控 engagement 期间得到验证。此外，这些供应商的主服务协议（MSA）合同义务要求他们在第四方发生任何重大变更时通知 KC。

## 数据位置

涉及数据时，关键在于其位置、传输路径以及如何受到保护。在 KC 的尽职调查过程中，会询问数据位置问题，这些关键供应商需要对该风险项进行更广泛的监控。对于位于 CSP 的供应商，会尝试利用其提供的监控 API，使其能够向 KC 的第三方风险人员发出警报。最低限度，供应商必须通过其安全门户按季度提供安全配置报告。如果数据位于供应商数据中心或托管设施，则供应商必须要求现场团队每年进行一次数据中心物理和逻辑安全评估。

## 连接安全

并非所有关键供应商都与 KC 有网络连接，但有连接的供应商将对其连接硬件上运行的软件进行季度检查。此外，供应商必须在每次季度软件版本检查期间提供连接两端的日志。这种透明度被视为确保这些供应商连接未被入侵的关键。

## 董事会批准与供应商参与

KC Enterprises 董事会批准并资助了该请求，因为这项额外的尽职调查需要一些额外资源。网络安全团队又聘请了四名网络威胁分析师全职关注这些关键供应商。与这 25 家关键供应商的供应商经理合作，他们在供应商门户上开发并交付了一份在线问卷。

通过与供应商建立关系并在每个尽职调查步骤中进行沟通，贵公司能够培养信任和合作伙伴关系。清单并不能建立信任，也不会促进业务关系的成长。它只是必须完成的事情，仅此而已。KC 的 TPRM 领导层、供应商经理和网络第三方风险团队制作了一份幻灯片并向每家关键供应商进行推介。幻灯片的一部分迎合了供应商的自尊心，强调他们对 KC Enterprises 成功的重要性以及双方公司如何受益。推介的另一部分解释了合作伙伴关系的牢固程度，并延伸至网络安全和第三方风险领域。最后，双方公司所处的环境，无论是供应商还是客户，从网络安全角度来看都是危险的。这要求 KC 与关键供应商合作，探讨如何相互帮助。

在某些情况下，KC 的供应商希望获得更多资金以覆盖额外的监督，如果请求在不夸大风险的范围内，则会获批。鉴于供应商数量仅二十余家，完成该工作仅用了几周时间。真正的工作始于一个月后数据收集之时。

## 生产部署

在 CM 生产部署期间，KC 的 CM 团队收集所有关键供应商的数据并将其放入数据库。不幸的是，典型的供应商管理软件记录系统不具备以团队计划的方式存储和报告数据的能力。因此，他们选择部署前端商业智能软件来呈现数据。这些详细数据现已与供应商安全软件工具、供应商风险管理软件以及其他数据来源作为触发器相连。

软件补丁和漏洞数据要求 CM 团队为关键供应商报告的软件找到触发器和阈值。在大多数情况下，软件在它们之间是共通的（即 Microsoft Server、Unix Server、Oracle 数据库、Apache Web 服务器），因此他们将这些软件制造商的重要和零日警报直接关联到商业智能引擎，以匹配任何制造商和版本信息。其他较不常见的软件更难自动化，但数量很少。随着制造商发布重要或零日警报，通知会发送到分发列表以采取行动并进行调查。

第四方风险数据可以通过统计关键供应商提交的总第四方数量来处理。回顾一下，问题是第三方使用哪些第四方来为 KC 提供服务或产品。预计每个最多几十家，25 家供应商共计 250 家。决定为供应商安全工具增加许可证，以便这些第四方能够与剩余的供应商池一起被监控。许可证在软件中存放在单独的文件夹中，并在 CM 程序中像其他供应商一样进行监控。

数据位置触发数据与供应商选择的云解决方案相关联。如前所述，一些使用 CSP 的供应商被邀请合作并使用 API 来监控实例的安全健康状况。这些触发器将在 [第10章](#c10.xhtml)，‘‘云安全’’ 中进行解释，但它们使供应商和 KC 都能够针对特定标准发出警报，例如不再要求对 root 访问进行 MFA 或实例加密被禁用。
