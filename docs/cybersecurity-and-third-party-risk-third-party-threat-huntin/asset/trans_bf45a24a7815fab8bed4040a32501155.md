
由于移动软件与操作系统以及其他差异（与 Web 应用相比）的工作方式，它们不太容易受到典型的攻击，如跨站脚本（XSS）或缓冲区溢出。然而，粗糙的编码会使手机或平板电脑应用程序容易受到攻击者利用。仍应遵循软件开发的最佳实践。

## 测试移动应用程序

测试身份验证和授权的强度是移动应用程序如何执行并授予访问权限的关键关注点。使用静态分析来测试代码中的密码复杂度（即最小和最大长度、字符要求）可确保在每个步骤都执行验证检查。随之而来的是对登录限流的测试，即在给定时间段内尝试登录设备的次数计数器。存在动态测试工具可以模拟自动密码猜测器，以测试验证这些身份验证弱点。

在对身份验证和授权进行测试时需要关注的一些常见领域是确保移动软件不会永久存储会话 ID，会话 ID 在服务器上随机生成，任何 ID 交换都通过安全连接进行，ID 长度适当，且熵足够难以被猜测；并且所有会话在服务器上终止，并在完成后将所有信息从移动设备上删除。开发工具提供的常见框架应被利用，这些框架提供已建立的安全集成。

测试安全加密通信涉及查看软件如何管理流量并执行一些常见的攻击类型。使用网络安全工具或嗅探器查看传出流量可以了解流量是否明文传输或已加密。确保代码使用 TLS v1.2 或更高版本。（SSL 已弃用，不应使用。）该领域的常见攻击是中间人攻击（即攻击者 literally 介于通信之间并重定向或窃取数据）。在不安全的 Wi-Fi 环境中，攻击者可以利用此方法窥探移动用户正在做什么。动态分析会发现大部分此类风险，但如果测试工具允许 ARP 欺骗（一种中间人攻击类型），它将在源代码中定位中间人攻击漏洞。

加密测试侧重于移动设备上一些常见的弱点领域。弱密钥生成、弱随机数生成器、密钥长度不足、硬编码加密密钥、已弃用的加密算法、自定义加密，以及密钥存储在内存中及其保护是验证的高风险类别。确保验证结果与开发团队制定的策略以及移动设备加密的最佳实践相匹配。

静态和动态分析测试还可以揭示松散的编码技术。如前所述，这类应用程序不太容易受到典型的浏览器端攻击，但并非免疫。SQL 注入、XML 注入或进程间通信（IPC）注入是此验证输出中需要关注的领域。缓冲区溢出是移动应用程序的常见攻击点，而模糊测试是找到此类漏洞的绝佳方法。

## 代码存储

如果管理不当，代码存储可能是安全漏洞的来源。存在用于保护代码存储库（即应用程序代码存储位置）的程序和方法，但挑战可能是安全配置错误或开发人员试图以易用性换取安全性而绕过安全措施。将凭据硬编码到代码中或未确保代码存储库具有足够的访问控制是两个最大的漏洞。请要求您的供应商查看他们存储代码的位置，以确保它不是公共空间，而是私有且访问受控。GitHub 是一个非常流行的代码存储提供商，由于其不当的安全设置，已发生多次代码和数据泄露的实例。互联网搜索可以揭示问题的范围，该问题不仅限于 GitHub，还涉及许多其他代码存储库产品。

## 结论

商业、个人使用和政府的世界都运行在软件之上。无论是基于云的、本地部署的、在智能手机上，还是利用开源，都必须遵循安全设计生命周期。此过程必须有文档记录并经过验证为已遵循并内部测试。最后，作为第三方应用程序的消费者，您应对组织中使用的软件进行风险评级，然后决定哪些符合标准并进行自己的内部测试。每个类型都需要一些不同的方法和分析方法，鉴于它们在开发、使用和维护方面的差异。

第三方软件被恶意行为者利用的例子已得到明确证实。从 Heartbleed 到 SolarWinds，都有记录显示公司未进行充分测试、缺乏足够的安全设计和验证，以及在客户如何测试第三方软件方面采取不一致的方法。商业中有一个术语叫做 *买者自负*，其翻译为“买者自负”。然而，它是更大警告的一部分：*买者自负，因买者不应不知其所购他人财产之性质*，其含义为“买方须自负其责，因为他们不应忽视其从另一方购买的财产的性质。”这一更完整的声明体现了组织在第三方软件方面需要采取的方法：为了确保该软件安全，他们必须测试和验证其安全性，并对供应商提供的产品承担法律责任。

# Chapter 13 Network Due Diligence

验证传输中的数据是否受保护涉及许多控制措施、工具和风险，需要进行一些特定的尽职调查工作。这项工作不仅仅是确定数据在传输中是否已加密，还包括入侵检测/预防系统（IPS/IDS）、安全 Web 网关（SWG）、数据丢失防护（DLP）、云访问安全代理（CASB）以及安全信息和事件管理（SIEM）工具等系统，以检测和防止数据泄露。随着虚拟专用网络（VPN）使用的扩展，网络攻击面在过去几年中发生了演变。然而，这些表面的数量在疫情后爆炸式增长，疫情在几天内就让近 30% 的美国劳动力在家工作（根据皮尤研究：`www.pewresearch.org/social-trends/2020/12/09/how-the-coronavirus-outbreak-has-and-hasnt-changed-the-way-americans-work`）。VPN 是企业网络的延伸，也是另一个在疫情期间成百上千倍增的入口点。

虽然前几章已涵盖了一些安全工作，但对供应商如何连接到客户网络以及由此带来的更高风险进行更多审查是必要的。几乎 100% 的这些连接都是通过供应商提供的和管理硬件进行的，导致客户无法直接访问以了解易受攻击的软件操作系统（OS）或配置。此类设备作为未管理且未监控的网络入口所带来的风险可以降低。

## 第三方连接

第三方连接尽职调查可分为以下主要类别：

* 人员物理安全
* 硬件安全
* 软件安全
* 带外安全
* 云连接

接下来，我们将分解这些类别，说明它们是什么以及如何保护它们。
