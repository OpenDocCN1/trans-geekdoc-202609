
BI 工具和供应商数据库定期存储并展示这些数据，而 ABC Corp. 在此期间仍保持黄色状态。然而有一天，威胁情报软件触发了一个警报，称暗网中有人在出售从 ABC Corp. 盗取的某些主管账号。供应商数据库通过与威胁情报应用相连的 API 接收这些数据。BI 工具随后将其标记，并根据所呈现的关键词（即 supervisor、administrator、privileged）将其标记为高风险。该供应商随后出现在红色高风险区域，因此 BI 将其展示在新高风险事件的仪表板上。网络安全第三方风险分析师会查看底层数据以确保没有逻辑错误或不匹配，然后他们开始主动利用数据与 ABC Corp. 的网络安全 SME 沟通，看看是否能协助调查这些账号是否仍活跃。这也可以成为一次对话的起点，讨论 PAM 解决方案的价值以及该工具如何大幅降低特权账号被入侵的风险。

## 用例 #2：红色供应商
如同许多中大型公司一样，KC Enterprises 拥有众多供应商但资源有限。红色类别的供应商是指满足以下阈值的供应商：
* 过去一年内发生过数据泄露
* 存在仍未关闭的高风险接受（RA）
* 存在未经过实地验证已修复的高风险发现
* 存在风险评级为高等级的 CM 触发项

当供应商满足其中一个或多个条件时，团队就知道需要对其进行更多审慎和尽职调查。在团队所称的这个红色供应商类别中，会对同时满足多个条件的供应商进行额外排序。因此，这些供应商会上升到类别顶部，进一步将注意力引导至已知风险最高之处。每月会向担任业务信息安全官（BISOs）的同事发送更新，他们既是联络人也是推动网络安全融入业务单元的倡导者。由于这些供应商在仪表板上以“Top 10 红色供应商”形式呈现，它们常被称为“耻辱墙”。这个绰号有效地引发了更多讨论，围绕这些供应商如何降低风险并在与业务合作的情况下降至黄色或绿色类别。（推动此类合作的第二个驱动因素将在用例 #3 中解释。）一旦高管们在报告中反复看到这面耻辱墙，他们意识到自己此前并不知晓这些特定供应商的网络安全控制如此薄弱。

供应商数据库和 BI 工具指明哪些供应商属于红色类别并将注意力集中在它们身上。这并不意味着黄色和绿色供应商被忽视。这种分类为所有供应商提供了一个单一视图（仪表板），整合了多个数据源。按业务单元排序的红色供应商仪表板，常在与业务领导层讨论其自身供应商群整体健康状况的会议中使用。在进行这些讨论时，标准可以轻松解释（并且不是复杂的算法或数学）这一事实，使得能够透明地讨论供应商带来的风险以及供应商经理如何规划进入绿色类别。

## 用例 #3：报告
总会有需求报告结果、关键风险/绩效指标（KRI/KPI），以及针对个人、业务线和整个投资组合数据和趋势的临时请求。无论这些报告是向董事会风险委员会提交的定期、月度或季度报告，还是临时请求，供应商数据库和 BI 都能以满足需求的方式清晰呈现数据，从而节省从不同系统收集数据花费的数小时时间，或避免因数据未关联或难以定位而遗漏重要风险数据。

KC 的网络安全第三方风险团队为每个目的或用例创建了以下自定义仪表板：网络安全领导层视图、BISO 视图、BU 视图、关联供应商视图、增强 CM 视图、第三方事件管理（TPIM）视图、CISO/CIO 视图，等等。需要花费时间与利益相关者会面并为每个仪表板制定需求，并进行一些反复的质量评估（QA），以便确定最终的仪表板或视图。在许多情况下，他们能够从现有仪表板开始并让其逐步演进。每个接收这些视图的查看者（用户）可以等待为其提供的定期更新（董事会报告为季度，Enhanced CM 工作每天作为工作队列和报告查看），也可以按需查看分配给他们的 BI 视图。由于数据加载主要来自夜间运行的 API 或 ETL，查看者可以查询及时的风险数据以做出决策或提出问题。

另一个数据优势是风险透明度，即单个供应商带来的风险，以及数据如何根据其业务单元或技术栈有效塑造行为的方式呈现。当业务领导层能够查看风险并理解第三方风险（SolarWinds 事件之后等）时，他们的支持就会渗透到公司的文化中。这对 KC 来说并非一夜之间实现的，但在考虑之前，业务赞助商更关注其供应商风险的情况有所增加。随着数据在数月内被追踪，报告期间的讨论显示红色供应商数量缓慢下降。这种下降可能需要时间，因为许多合同为多年期，并且在某些情况下，如前所述，KC 在该领域别无选择，只能选择唯一的合格供应商。然而，来自业务领导层的压力增大，强调了修复重要高风险发现或风险接受的重要性。这种对高风险的关注为 KC Enterprises 带来了真正的风险降低。

## 结论
在任何组织中，从小型到大型，都存在关于供应商网络安全控制表现的数据。在小型公司中，数据可能存储在电子表格和文件中。在中大型企业中，存在软件包、工作流工具、采购软件、第三方风险管理工具、技术工具和软件，以及包含这些信息的许多其他工具。还有 CVE 订阅源、RSS 订阅源推送、API 等外部来源，它们拉取或推送与相同主题相关的信息。几乎所有拥有网络安全团队的公司都有一支团队在 Splunk 或其他工具中收集大量数据，以便查看并对公司安全做出决策。针对供应商带来的风险和漏洞，同样存在更多数据。工具和软件收集并管理这些数据（在数据湖、数据库等中），此外还有无数 BI 和分析工具连接到数据存储位置。
