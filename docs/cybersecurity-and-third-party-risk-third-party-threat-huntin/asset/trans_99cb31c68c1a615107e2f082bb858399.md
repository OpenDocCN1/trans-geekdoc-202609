
# 云安全模式

## AWS TAR 安全项目

- `MFA for Root Account:` 这是一个布尔值复选框，可以启用或不启用。在此情况下，Root 是最终的特权账户；此标志必须启用，否则将不符合模式标准。
- `Amazon Relational Database Service (RDS) Security Group Risk:` 会检查 Amazon 的 RDS 是否对数据库具有过于宽松的访问权限。模式要求将访问限制为特定的弹性计算云 (EC2) 或特定的 IP 地址。
- `AWS Cloudtrail Logging:` 日志记录对于发现和防止入侵至关重要。如果发生入侵，则必须有日志来确定受损程度。要求确保 CloudTrail 具有向 S3 存储桶写入的权限。
- `Elastic Load Balancer (ELB) Security Groups:` 负载均衡器对于 Web 流量管理很重要。此项不得对安全组发出任何警报，该安全组允许访问负载均衡器上未配置的端口。
- `Exposed Access Keys:` 在任何代码存储库中或 Amazon EC2 的任何异常使用中，均不得出现暴露密钥的标记，这表明加密密钥已被泄露。
- `Amazon Elastic Block Store (EBS) Public Snapshot:` 这可确保不会将快照的警报标记为公开。
- `Amazon RDS Public Snapshot:` 这与上面相同——没有任何 RDS 可以被标记为公众可查看。
- `AWS Identity & Access Management (IAM) Password Policy:` 密码策略和密码内容要求通过强制执行更强的密码来提高安全性。此项不得有任何警告。
- `AWS IAM Access Key Rotation:` 密钥轮换必须每 90 天进行一次，以降低密钥被泄露的风险。

Security 部分（在 AWS TAR 中）的特定项目列出为供应商如何以可重复的方式设计其云安全的方式。当您决定希望供应商遵守的安全设置时，则可以将其作为一组预先批准的安全控制提供给供应商。如果新的云供应商正在进行使用 AWS 的 Intake 评估，则这些安全控制会输出在提供给他们的 TAR 报告上。

## Azure Advisor 安全项目

Azure Advisor 是用于确定是否需要解决任何差距的安全工具。与 AWS TAR 一样，此处的意图是为前往 Azure 或已在 Azure 中的第三方提供可供 KC 重复的模式。在 Advisor 产品中，Microsoft 拥有一个与 Azure 安全中心集成的 Security 选项卡。Azure 模式中的安全项目可以在安全中心的菜单选项“Recommendations”中找到。以下任何一项在工具中都不得有高严重性警报：
- 修复漏洞。
- 启用静态加密。
- 修复安全配置。
- 应用系统更新。
- 防御 DDoS 攻击。
- 保护管理端口。
- 应用自适应应用程序控制。
- 传输中加密数据。
- 管理访问和权限。
- 限制未经授权的网络访问。
- 启用端点保护。
- 启用审核和日志记录。
- 应用数据分类。
- 启用 Azure Defender。
- 实施安全最佳实践。
- 启用 MFA。

当供应商审查这些项目中的每一项时，工具会提供补救步骤。它还具有“View Remediation Logic”选项，可在应用更改之前查看逻辑影响。这些补救步骤足够明确，以便在存在高严重性警报的情况下采取行动。

## Google Cloud Security Command Center

Google Cloud 用于查看安全控制的服务是 Security Command Center。Google 的服务与 AWS 类似，分为免费和高级层级。鉴于 KC 团队不认为安全是可以省钱的事情，其供应商必须在高级层级功能中复制该模式。Security Command Center 报告必须清除任何高风险发现，才能被视为符合模式审批。待审查的标准（免费）扫描输出列表如下：
- `MFA_NOT_ENFORCED`: 表示用户未使用 MFA 验证。
- `NON_ORG_IAM_MEMBER`: 组织外部的用户在项目或组织上拥有 IAM 权限。
- `OPEN_FIREWALL`: 表示防火墙保持开放且未拒绝流量。
- `OPEN_RDP_PORT`: 表示远程桌面协议处于开放状态。
- `OPEN_SSH_PORT`: 表示安全 Shell 协议处于开放状态。
- `OPEN_TELNET_PORT`: 表示 Telnet 协议端口保持开放。
- `PUBLIC_BUCKET_ACL`: 表示公共 Cloud Storage 存储桶可公开访问。
- `PUBLIC_COMPUTE_IMAGE`: 表示 Compute Engine 实例可公开访问。
- `PUBLIC_IP_ADDRESS`: 表示存在公共互联网地址且未使用私有子网。
- `PUBLIC_LOG_BUCKET`: 用作日志接收器的存储桶公开开放。
- `PUBLIC_SQL_INSTANCE`: 数据库对公众开放。
- `SSL_NOT_ENFORCED`: 未强制执行安全套接层 (SSL)，后者可在浏览器与目标之间建立经过身份验证和加密的链接。
- `WEB_UI_ENABLED`: 高度特权的 Kubernetes 服务帐户支持 Kubernetes Web 界面。如果被入侵，服务帐户可能会被滥用。

高级层级功能监控供应商的云日志并消费日志以检测以下威胁：
- 恶意软件
- 加密货币挖矿
- SSH 暴力破解
- 外发 DoS
- IAM 异常授权
- 数据外泄
- 跨站脚本 (XSS)
- Flash 注入
- 混合内容
- 明文密码
- 使用不安全的 JavaScript 库

所有这些 CSP 都提供可作为模式利用的安全监控，以指导供应商进行云部署。KC 团队随时保留此文档，并在 Intake、持续或其它尽职调查评估期间使用它来指导最佳实践。

## 云安全基线、基准、框架和认证作为第三方模式

云安全方面的框架、基准和认证可能有数百种。KC Enterprises 的目标是提供其第三方最常用的且与 KC 风险承受能力相符的框架，但我们在此列出一些其他框架，以展示可能性并将其作为云供应商的模式提供。

ISO 27017 是一项旨在使云计算更安全的 CSP 安全标准。该标准提供指南、安全控制建议、控制的实施方式和实施者，以及 CSP 如何支持实施。所有三大（以及更多）都遵循此标准，该标准对多个关键领域提供指导：共享责任模型、资产的移除和返还、客户虚拟环境的保护和隔离、虚拟机配置、行政程序、监控以及虚拟和云网络。将供应商指向由其中一家 CSP 提供的 27017 标准，可为其提供降低风险的模板或模式。

国家科学技术研究所 (NIST) 提供了多个基准供使用。对于 AWS、Azure 和 Google，互联网安全中心 (CIS) 已上传框架供使用。请访问 NIST 国家漏洞数据库 (`http://nvd.nist.gov`)。在此位置 (`http://nvd.nist.gov/ncp/repository`) 您会找到国家检查表计划存储库。这里列出了所有三家（以及许多其他）。CIS Amazon Web Services 基础基准为用户提供有关为 AWS IAM、CloudTrail、AWS S3 和 AWS 虚拟私有容器 (VPC) 配置安全的具体指导。CIS Google Cloud Platform 基础基准为在 Google Cloud 上设计和部署提供安全配置。Azure 安全基准基于 CIS 框架，并指导用户进行这些部署的安全和合规控制。
