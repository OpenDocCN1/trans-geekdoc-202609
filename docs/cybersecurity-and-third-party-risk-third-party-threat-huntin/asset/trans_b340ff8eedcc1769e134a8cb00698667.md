
# SOC2 Type II 报告审查

## 报告章节
*   **意见免责声明：** 不良，相当于不仅仅得了“F”，而是被开除出学校
*   **管理声明：** 管理层对部分审计发现以及业务的期间、范围和时间作出回应。
*   **系统描述：** 一个重要的章节，因为它描述了公司的结构、提供的服务，以及 IT 系统和控制措施。
*   **标准与测试矩阵：** 这通常是对标准、控制措施和测试的列表或矩阵，以及结果。

## 关键审查项目
在审查 SOC2 Type II 报告时，有几个关键项目需要注意，以确保其相关性：
*   **Type I 或 Type II：** 对于 SOC2 报告被认为足以用于网络安全尽职调查，审计和测试必须在 Type II 级别进行，在该级别下会评估控制措施的有效性。
*   **覆盖范围：** 报告是否涵盖公司委托供应商提供的服务和/或产品，还是存在遗漏的部分？
*   **标准：** 有五个受信服务标准：隐私、安全、数据完整性、可用性和保密性。报告是否涵盖全部五个？
*   **分包商：** 报告是否包含供应商为提供服务而使用的第三方？
*   **例外情况：** 如果报告存在任何重大例外情况，则需要审查其对风险尽职调查的影响。
*   **日期：** 检查检查日期是否已旧到被视为过时。日期不应早于入职流程进行时的一年以上，理想情况下应少于九个月，因为供应商的入职流程从开始到生产实施可能需要很长时间。

SOC2 Type II 报告是让供应商证明其 IT 控制措施接受独立评估的有效方式。它不能替代执行尽职调查和风险评估。这些是时点审计，不能提供供应商持续遵守安全控制的保证。报告是公众公司降低 SOX 问题或发现风险的要求。然而，正如本文所述，它们并非网络安全尽职调查的理想选择。

## KC 的供应商风险管理流程

### 费用回拨
这对网络安全与业务领导层讨论可能是一个困难的话题。然而，这一模式是为业务部门提供 IT 服务时普遍接受的做法。这是一种常见的方式，确保业务包含其业务规模所有权的真实成本。在这种情况下，尽职调查级别的要求由 KC 第三方风险管理部门和网络安全部门明确阐述。阈值是既定的原则并且一直有效，但管理层担心业务承担了大量需要更多资源的中等风险和高风险供应商。
业务部门领导层、TPRM 和网络安全领导层同意基于供应商 engagement 风险类别的成本模型。定价并非实际成本，因为它从一个部门传递到网络安全和 TPRM 以支付资源成本，但业务部门在入职审查流程期间“资助”了网络安全资源作为项目的一部分。资源可以得到充分资助，网络安全和 TPRM 可以与每个业务部门协作，作为每年财政年度规划的一部分，根据未来一年需要尽职调查的已资助项目确定预期的员工配置水平。这并不是一门精确的科学，因为并非所有项目都可能知道是否需要连接或数据分类级别，或者因为项目有时会在年中增加。因为这不是一门科学，三支团队按照正常的优先级流程在预算中解决这个问题。
这种基于风险的项目资助方式（从而资源配置）有一些附带好处。首先，它为 KC Enterprises 风险水平提高的供应商项目提供了业务“成本”，因此在权衡外包还是在内部资源和系统上内部完成时，成本被纳入考量。其次，它弥合了业务与网络安全尽职调查工作之间经常存在的摩擦差距。基于量化值建立供应商风险分类，并让业务资助尽职调查所需资源的这一练习，对三支团队都是一种教育。网络安全了解了业务运营和需求，TPRM 了解了未来一年预计的投入，而业务则通过查看每个级别所需的活动水平了解了网络安全尽职调查的“成本”。

### 上线生产审查
在任何上线生产之前，新的供应商服务必须满足并完成完成门禁审查所需的所有尽职调查。在 KC，这些审查取决于供应商风险等级。在低风险方面，供应商需要在入职流程期间关闭任何高风险发现。所有较低风险的网络安全项目均可由业务发起人和网络安全风险顾问或其代表批准进行风险接受。
中等风险和高风险供应商必须具有更高级别的上线预批准。在中等风险和高风险供应商方面，他们还必须在上线前关闭所有高风险发现；并且所有中等风险发现必须在上线后一年内或更早完成补救，具体取决于与第三方在生产前的协议。

### 连接性网络安全审查
由于与企业网络的连接存在风险，KC 要求在任何线路上线前采取一些额外步骤。一旦连接建立，更改就很难进行。此外，如果存在安全漏洞，可能会在很长时间内未被发现，具体取决于扫描和补丁管理。历史表明，网络安全团队这些连接可能会被供应商“遗忘”；但由于供应商管理硬件并且是唯一有访问权限的人，这意味着一旦安装后纠正供应商的不良行为可能会很困难。
连接性网络安全审查涉及网络安全第三方风险在之前审查几个关键项目：
*   供应商必须在部署时确认硬件和补丁级别。
*   供应商必须确认连接的加密符合设计批准。
*   KC 安全架构必须已完成连接的高层设计，并获得相关网络连接政策的批准。目前，这是拥有信息技术和网络安全部门所有相关利益相关者的企业架构委员会。
*   不存在未解决的高风险发现或直接影响与供应商连接安全的风险接受情况。
一旦确认这四个流程已完成，网络安全部门即已对连接进行批准。
**连接生命周期** 一个经常被忽视的项目是将供应商合同与连接的生命周期联系起来。如果没有流程让网络连接和安全团队知道合同已终止，KC 发现设备通常仍保持连接。他们采取了纠正措施，将用于网络服务管理的流程工具与供应商管理软件连接起来。两个程序之间的工作流程意味着如果供应商的合同被终止，一个标志会触发工作流程。如果该供应商的“连接”有复选标记，则会向服务管理工具中的工作流程发送夜间批处理文件。这并不是魔术，但在那时，相关人员会被通知需要调查并与供应商管理团队协调何时关闭连接。此外，设备必须退还给供应商，或另行通知 KC 如何处置。
