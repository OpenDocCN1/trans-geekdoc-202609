
贵公司应执行输入验证，其中测试涉及确定软件是否会允许意外、格式错误或不允许的数据输入。必须拒绝 `null` 值，并测试 `API` 的输出是否符合预期。签名测试会检查数字签名，以验证软件包是否真实且未被篡改。使用 `Unix` 中的 `command‐line` 对字符串进行静态分析会产生此类信息，这可能使应用程序容易受到推断攻击。推断攻击类似于透过公寓楼的墙壁偷听邻居的谈话。墙壁隔音越差，你就能推断出隔壁发生的事情越多。

云软件的动态测试重点关注三个领域：内存、注册表和网络。在测试期间会访问内存数据，以查看是否发生任何敏感数据泄露。在动态分析中，注册表键和对注册表的修改会发出警报，如果出现意外行为。网络流量测试可以查看发送到云端的 `username` 是否可以被更改。这种名称更改可能会提升用户的权限级别，并允许他们查看并可能外泄敏感数据。

可以对第三方基于云的应用程序执行非常直接的动态和静态分析。使用干净的数据集，与供应商合作建立沙箱环境，并就测试中发现的任何问题与他们沟通。

# 开放式 Web 应用程序安全项目解析

开放式 Web 应用程序安全项目（OWASP）是一个在线组织，发布有关 Web 应用程序安全的免费文章、方法论、文档、工具和技术。它是一个接受捐赠和会员费的非营利 501c 组织。它在全球各地设有分会，供人们建立联系并向本地同行学习。

## OWASP Top 10

为开发人员和网络第三方风险团队提供了许多优秀资源。其中之一被称为 OWASP Top 10 Web 应用程序安全风险，这是一个动态列表，会随着威胁的变化而定期更新。该列表包括以下项目：

* **注入：** 当不受信任的数据作为命令或查询的一部分发送给解释器时，这可能允许攻击者欺骗解释器执行命令或访问数据。
* **身份验证损坏：** 如果身份验证和会话管理实现不当，可能允许黑客访问密码、密钥或会话令牌，或冒充另一用户的身份。
* **敏感数据泄露：** 在网站上传输时未受保护（未加密）的敏感数据可能导致数据泄露。
* **XML 外部实体：** 可扩展标记语言（`XML`）旨在存储和传输数据。如果配置错误或版本较旧，可能导致数据丢失、远程代码执行、内部端口扫描和拒绝服务攻击。
* **访问控制损坏：** 当对经过身份验证的用户不能执行哪些操作以及查看的数据的限制未得到良好执行或未执行时，黑客可以滥用它来获取数据或非预期功能。
* **安全配置错误：** 据报道这是最常见的漏洞，是由于用户未按照最佳实践建议正确配置安全控制而导致，从而引发泄露和安全事件。
* **跨站脚本 (`XSS`)：** 当应用程序在未进行验证或无法转义的情况下将不受信任的数据包含在网页中时，可能允许远程脚本执行劫持浏览器会话、将用户或流量重定向到恶意站点，或篡改网站。
* **不安全反序列化：** 反序列化是将数据从另一种格式取出并重建为对象的过程。它可能导致远程代码执行、重放攻击、注入和权限提升攻击。
* **使用存在已知漏洞的组件：** 库、框架和其他软件模块通常以与应用程序相同的权限级别运行。在存在已知漏洞时使用这些项目是对攻击者的明显邀请。
* **日志记录和监控不足：** 缺少这一关键部分会导致无法跟踪或查看可疑行为，如果发生泄露，也无法确定发生了什么。

## OWASP Web 安全测试指南

OWASP 测试指南为开发人员和安全专业人员提供了一个最佳实践渗透测试框架。该指南是关于测试 Web 应用程序安全的完整文档。它包括威胁建模、测试技术、源代码审查以及如何推导安全测试要求。测试框架分为五个阶段：

1. **阶段 1：** 开发开始之前
2. **阶段 2：** 在定义和设计期间
3. **阶段 3：** 在开发期间
4. **阶段 4：** 在部署期间
5. **阶段 5：** 在维护和运营期间

此外，还有针对 Web 应用程序安全、身份验证、授权、会话管理、输入验证、错误处理、业务逻辑、密码学以及众多其他测试的详细计划和指导。

本指南提供了有关对 Web 应用程序尽职调查所执行的安全测试的详细信息，可作为供应商使用的测试来源。

OWASP 还有许多其他工具和文档，对开发人员和安全社区很有用。此外，指南创建者也在不断寻找贡献者，以便在需要更新时对已收集的数据进行补充。

# 开源软件

开源软件（`OSS`）是一种代码或软件，其源代码在版权持有者授予其他用户研究、使用、更改和分发给任何人任何用途的许可下可用。这些操作可以通过众多人员和组织协作完成，也可由单一许可持有者完成。这种软件通常被认为免费，但这不准确。它的使用通常（但并非排他）是免费的，但使用它确实会产生一定的成本，例如维护和修补。由于其开发便捷、灵活性和快速创新，它确实具有一些巨大的优势。一些 `OSS` 示例包括 Apache Web 服务器、Mozilla Firefox 和 Libre Office。

一些开发团队忽视了开源软件的维护和修补成本，这可能成为尽职调查工作的切入点。这项工作可以在两个主要领域进行：1）对任何供应商现有的安全审查（即入职、持续、现场评估；了解更多关于他们如何维护其 `OSS` 记录并对其进行测试），以及 2）使用本章前面讨论的一些工具测试软件是否存在开源漏洞。

商业现成软件可能包含对某些开源库的引用。确保这些内容得到审查和同意，要么在合同谈判期间（通过添加条款保护贵公司免受任何开源相关事件的影响），要么在正常运营期间或合同续签期间。

开源代码在开发中最常被使用的方式与 `OpenSSL` 代码的使用方式类似：当开发人员需要一种方式让他们创建的程序安全地与其他程序通信时，他们会加入 `OpenSSL` 代码。虽然这不仅仅是“加入代码”那么简单，但对于本书来说，这已经是深入编码的程度了。许多应用程序包含数千到数百万行代码，因此挑战在于确保所有者知道数据被加入的位置以及加入的版本。
