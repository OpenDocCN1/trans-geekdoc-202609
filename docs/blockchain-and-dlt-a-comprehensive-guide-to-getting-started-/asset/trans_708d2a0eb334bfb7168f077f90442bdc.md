

# Hyperledger Fabric 优势

## 可插拔共识机制
**优势：** Fabric 支持可插拔共识机制。在监管要求严格的场景中，组织可以选择符合合规需求的共识算法，确保信任并遵守法规。

## 模块化身份管理
**场景：** 政府机构在跨机构区块链上协作。

**优势：** Hyperledger Fabric 的 MSP（成员服务提供者）支持对身份进行细粒度控制。在政府联盟中，这确保每个机构都保持对其成员访问权限的控制，从而增强安全性和问责制。

## 多语言链码
**场景：** 拥有多元化开发团队的全球供应链。

**优势：** Fabric 对多种编程语言的支持使全球开发团队能够共同贡献。在需要多元化专业知识和贡献来构建复杂全球系统的场景中，这极具优势。

## 可扩展性与性能
**场景：** 管理大量交易的电商平台。

**优势：** Fabric 的架构支持可扩展且高效的交易处理。在高交易吞吐量至关重要的场景中，Hyperledger Fabric 能有效应对负载。

# 链码

Hyperledger Fabric 的基石之一是其对智能合约的支持，称为 **链码**。这些链码是管辖网络内交易的业务逻辑。设想一家房地产代理公司采用 Hyperledger Fabric 来简化房产交易。链码使他们能够安全高效地自动化验证和转移房产所有权。

| 方面 | Hyperledger Fabric | Ethereum |
| :--- | :--- | :--- |
| 编程语言 | 支持多种语言（Go、JavaScript 等）。 | 主要使用 Solidity，要求开发者学习一门新语言。 |
| 执行模型 | 在确定性的许可环境中执行交易。 | 在全球去中心化网络上运行，允许任何人参与。 |
| 隐私与机密性 | 通道支持指定参与者间的私有交易。 | 所有交易对所有参与者可见，可能难以满足隐私要求。 |
| 共识机制 | 支持可插拔共识机制（例如 Raft、Kafka）。 | 依赖 PoW，正在向 PoS 过渡。 |
| 交易成本 | 交易成本更可预测，因为可能由联盟定义。 | Gas 费用随网络需求波动，导致成本难以预测。 |
| 最终确定性 | 因许可性质实现更快的最终确定性。 | 最终确定性耗时较长，尤其是在 PoW 模型中。 |

Hyperledger Fabric 的部分优势如下：

- **隐私：** 通过通道增强隐私功能。
- **许可网络：** 适合参与者已知且受信的企业联盟。
- **可插拔共识：** 允许灵活选择共识机制。

以太坊的部分优势如下：

- **去中心化：** 运行在全球去中心化网络上。
- **全球执行：** 智能合约可由以太坊网络上的任何人执行。
- **生态系统：** 拥有庞大成熟的生态系统，包含多样化的去中心化应用（DApps）。

了解这些差异有助于组织根据其特定用例和需求选择合适的平台。

## 链码生命周期

理解链码生命周期对于有效的区块链应用管理至关重要，可确保持续的功能性、安全性以及对不断变化的业务需求的适应性。链码生命周期包含多个不同阶段，每个阶段都有自己的流程和结果。这些阶段可归类如下：

### 部署
- 也可称为初始化阶段。
- 链码在区块链网络上初始化并实例化。
- 此阶段设置初始参数和配置。

### 背书与批准
- 链码由一部分网络参与者背书。
- 部署需要大多数背书节点批准。
- 链码按定义的背书策略进行背书。

### 实例化
- 经批准的链码被实例化，新版本在网络上激活。
- 智能合约准备好处理交易。

### 交易处理
此阶段包含两个阶段，如下：

#### 调用交易
- 应用程序通过与已部署的链码交互来调用交易。
- 交易被提议、背书，然后提交至账本。

#### 状态更新
- 链码执行可能导致世界状态（账本）更新。
- 更新后的状态在网络所有节点间复制。

### 升级
此阶段调用对现有链码的修改和增强。可能涉及以下要素：

- **代码变更：** 开发链码的更新版本，包含漏洞修复或新功能。
- **升级背书与批准：** 与部署类似，升级版链码由网络节点背书和批准。
- **执行升级：** 升级版链码安装在节点上。现有实例被新版本替换。
- **状态迁移：** 若需要，执行从旧版链码向新版迁移数据的机制。

### 维护
此阶段对确保已部署区块链的稳定性和效率至关重要。包括：

- **监控与诊断：** 持续监控链码的性能、健康状况和资源使用情况。诊断以便及时发现并解决问题。
- **补丁部署：** 部署补丁或更新以提升安全性、稳定性或性能。

### 扩展
此阶段对于扩展网络或调整资源以适应不断变化的需求至关重要。这可能涉及添加新节点或调整现有配置。包括：

- **定期升级：** 规划并执行定期升级，确保链码与不断演进的需求和最佳实践保持一致。
- **治理与策略：** 遵守链码管理的网络治理和策略。根据需要更新访问控制、策略和配置。

# 排序服务

为维护网络间账本的一致性，Hyperledger Fabric 采用排序服务将交易排序打包成区块。这确保所有网络参对账本历史拥有统一视图。可将其想象为大型交响乐团的指挥，协调交易的和谐执行。

# 成员服务

在任何企业级区块链中，身份管理至关重要。Hyperledger Fabric 提供成员服务以认证参与者并管控访问权限。设想一个医疗联盟，仅授权人员可访问患者记录。成员服务确保敏感医疗数据保持机密。
