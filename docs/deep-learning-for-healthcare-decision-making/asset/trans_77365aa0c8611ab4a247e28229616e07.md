
# 相关工作

文献 [1](#ch9.xhtml#ref9_1) 的作者设计了一个融合了 `blockchain 3.0` 和 `healthcare 4.0` 的智能医疗系统。该设计网络已在 `Ethereum` 网络上实现，并结合了 `Solidity` `Web3.js` 等其他编程语言和工具。此外，为应对信任构建的挑战，采用了 `smart contracts`。

文献 [2](#ch9.xhtml#ref9_2) 提出了一个基于区块链的安全、高效且易于维护的框架，用于患者与医生之间的医疗数据访问。该框架允许患者完全控制其数据。

文献 [13](#ch9.xhtml#ref9_13) 还开发了一个用于安全、稳健、稳定且以患者为中心的健康信息交换框架。为此使用了 `Distributed ledgers` 和 `smart contracts`。

文献 [43](#ch9.xhtml#ref9_43) 开发了一个以患者为中心的名为 `PACEX` 的应用程序，允许共享 `EHR` 数据。使用了 `Ethereum blockchain` 和 `smart contracts`。

文献 [3](#ch9.xhtml#ref9_3) 的作者扩展了文献 [9](#ch9.xhtml#ref9_9) 的工作，设计了一种利用区块链和边缘节点进行 `EHR` 数据管理的混合架构。该架构使用 `attribute-based multi-signature (ABMS)` 方案认证用户签名，并使用 `multi-authority attribute-based encryption (ABE)` 方案加密 `EHR` 数据。分别使用 `Hyperledger Fabric` 平台和 `Hyperledger Ursa` 库实现了该方案。

文献 [4](#ch9.xhtml#ref9_4) 的作者首次提出了一种基于跨链的 `EHR` 存储解决方案，以解决区块链在医疗保健领域的互操作性问题。为此使用了 `relay-chain as a service (Raas)`，它允许患者在进入不同医院时删除 `EHR` 信息。

文献 [5](#ch9.xhtml#ref9_5) 开发了一个基于区块链的平台，用于糖尿病领域的增强型 `EHR`，因为糖尿病是当今世界增长最快的疾病。该平台在紧急情况下向患者和护理人员生成警报消息。

文献 [6](#ch9.xhtml#ref9_6) 提出了一种基于区块链和哈希的新策略，以增强分布式 `EHR` 的安全性。该策略使用 `collision-resistant hash function` 快速生成唯一的患者 ID，使用 `PoW` 降低可扩展性问题，并使用 `smart contracts` 和密码学技术进行同意管理。

文献 [7](#ch9.xhtml#ref9_7) 和 [40](#ch9.xhtml#ref9_40) 针对 `EHR` 中区块链的可扩展性问题。为提高可扩展性，所提架构使用 `multi-hyperledgers`：一个用于患者，另一个用于医疗机构。为存储大量数据并满足更多请求，每个通道维护自己的账本。

文献 [8](#ch9.xhtml#ref9_8) 将 `AI` 与区块链相结合，用于更安全的 `EHR`、高效的数据管理和可靠的疾病诊断。使用 `constraint goal model (CGM)` 来激发生成系统需求。

文献 [50](#ch9.xhtml#ref9_50) 针对台湾使用的 `NHIA’s NMR` 的可扩展性问题。开发的框架可将 `NHIA’s NMR` 数据与 `EMR` 和 `EHR` 集成。

文献 [10](#ch9.xhtml#ref9_10) 开发了一种用于数据共享和访问控制的同意模型。`Smart contracts` 用于表示同意。该模型分别使用 `data use ontology (DUO)` 和 `automatable discovery and access matrix (ADA-M)` 对用户同意和请求者的查询描述进行建模。`Ethereum` 平台用于数据验证。

文献 [11](#ch9.xhtml#ref9_11) 和 [55](#ch9.xhtml#ref9_55) 提出了一种用于云存储环境中安全多授权 `EHR` 的方案。该方案使用 `attribute signcryption scheme` 实现安全性。此外，`verifiable outsourcing computational mechanisms` 的使用减轻了用户的计算负担。

此外，文献 [22](#ch9.xhtml#ref9_22) 开发了一种高效的认证方案，用于解决云的中心化问题。

文献 [12](#ch9.xhtml#ref9_12) 使用 `fuzzy decision models` 评估用于安全可信 `EHR` 的区块链模型。该评估有助于选择最适合可信 `EHR` 的区块链。

文献 [14](#ch9.xhtml#ref9_14) 使用 `zk-proofs` 认证受益人。

然而，文献 [29](#ch9.xhtml#ref9_29) 使用 `keyless signature infrastructure` 保护云上的 `EHR` 数据。所提框架在不同参数上进行了评估并与现有框架进行了比较。

文献 [42](#ch9.xhtml#ref9_42) 使用 `revocable attribute scheme` 保护隐私。`Attribute signing key` 通过 `attribute master key` 和 `update master key` 的组合计算得出。

文献 [16](#ch9.xhtml#ref9_16) 提出了一种用于隐私保护的 `multi-tier architecture`。这种新颖的架构在不同的 `EHR` 云提供商之间使用 `public blockchain`，在患者传感器和患者系统之间使用另一个 `public blockchain`。

文献 [28](#ch9.xhtml#ref9_28) 和 [33](#ch9.xhtml#ref9_33) 使用 `cryptographic functions` 维护患者数据的假名性。

文献 [49](#ch9.xhtml#ref9_49) 使用各种 `utility functions` 评估隐私保护框架。`Multiple smart contracts` 用于访问控制评估和交易评估。

文献 [35](#ch9.xhtml#ref9_35) 使用区块链保护去中心化 `EHR` 共享。

文献 [18](#ch9.xhtml#ref9_18) 提出了一种结合区块链和边缘节点的混合架构，以促进 `EHR` 访问控制。该架构维护访问事件的 `tamper-proof log`。`Hyperledger Fabric` 用于混合架构的评估。

此外，文献 [19](#ch9.xhtml#ref9_19) 和 [44](#ch9.xhtml#ref9_44) 也提出了一种新颖的 `EHR` 框架，用于 `EHR` 各类用户之间的可信访问控制机制。`Ethereum` 用于原型实现。

此外，文献 [20](#ch9.xhtml#ref9_20) 专注于患者控制的共享方案，而非第三方。一些医疗机构用于存储 `PES chain`。这些用于存储加密患者记录的哈希值。构建了 `Stealth authorization scheme` 用于隐私保护和数据共享。

文献 [21](#ch9.xhtml#ref9_21) 针对云上 `EHR` 记录共享的隐私保护和安全问题。开发了基于 `Searchable encryption` 和 `conditional proxy re-encryption` 的方案来解决这些问题。`Proof of authorization` 用作共识协议。

文献 [24](#ch9.xhtml#ref9_24) 提出了一种新颖的审计机制，用于在欧洲跨境交换电子健康数据，而文献 [47](#ch9.xhtml#ref9_47) 则为秘鲁卫生组织的 `EHR` 数据提出了一种架构。遵循秘鲁当局维护的法律，用于医疗数据的链下存储和提供交易日志。

文献 [48](#ch9.xhtml#ref9_48) 提出了一个用于癌症患者数据共享和管理的框架。数据验证在 `Stony Brook University Hospital` 的数据上进行。

文献 [25](#ch9.xhtml#ref9_25) 提出了一种基于区块链的安全 `EHR` 互换解决方案。从系统内部和外部威胁方面进行了安全分析。

文献 [41](#ch9.xhtml#ref9_41) 提出了一种用于跨组织数据共享的 `permissioned blockchain`。

文献 [26](#ch9.xhtml#ref9_26) 提出了一种名为 `MedSBA` 的新颖安全方案，一种用于 `EHR` 共享的 `attribute-based encryption` 方案。使用了 `Private blockchain`。

文献 [27](#ch9.xhtml#ref9_27) 开发了真实、可操作且安全的 `PHRs`。制定了三项设计原则用于安全的 `PHR`。

文献 [36](#ch9.xhtml#ref9_36) 提出了一种用于数据安全的 `certificate-less scheme` 和 `elliptical curve cryptography` 方案。

文献 [30](#ch9.xhtml#ref9_30) 将 `Hyperledger blockchain` 与 `deep learning` 相结合，分别用于安全数据管理和诊断模型。开发的模型分五个不同阶段工作。应用 `SIMON block cipher` 技术进行数据加密，应用 `variational autoencoder` 进行疾病检测。

文献 [31](#ch9.xhtml#ref9_31) 利用 `smart contracts` 实现患者、医生和护理人员之间的数据共享。使用 `Modified Merkle tree` 数据结构实现数据的安全快速访问。使用 `Cryptographic hash functions` 保障数据安全。

文献 [32](#ch9.xhtml#ref9_32) 使用 `attribute and identity-based encryption` 保障云上数据的安全。

文献 [37](#ch9.xhtml#ref9_37) 开发了一种名为 `MedRec` 的新颖模型，用于医疗数据的数据访问和权限管理。

文献 [39](#ch9.xhtml#ref9_39) 提出了一种 `granular access control mechanism`，可在保持与底层区块链架构兼容的同时提供不同级别的授权。

文献 [45](#ch9.xhtml#ref9_45) 关注医院急诊病房的 `EHR` 数据。该工作使用 `P2P network` 分析 `smart contracts` 的数据传输。

文献 [46](#ch9.xhtml#ref9_46) 构建了一个统一解决方案，用于迁移现有的 `EHR`。链下资产存储通过患者和策略交易进行控制。
