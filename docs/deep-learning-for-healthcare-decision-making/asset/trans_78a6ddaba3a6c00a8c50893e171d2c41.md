
通过将代码拆分为几个小组，然后根据事件的发生情况在组内进行排序来处理。`Skip-gram` 通常用于此类目的 [[37](#ch6.xhtml#ref6_37)]、[[42](#ch6.xhtml#ref6_42)]、[[43](#ch6.xhtml#ref6_43)]。在潜在编码中，分析不同医学概念之间的相关性，并利用通过 `autoencoders` 获得的图示训练线性模型 [[44](#ch6.xhtml#ref6_44)]。

深度学习技术 [[39](#ch6.xhtml#ref6_39)]、[[40](#ch6.xhtml#ref6_40)]、[[42](#ch6.xhtml#ref6_42)]、[[43](#ch6.xhtml#ref6_43)]、[[45](#ch6.xhtml#ref6_45)] 用于基于自然语言处理 [[46](#ch6.xhtml#ref6_46)] 以向量形式表示患者，或使用 `autoencoders` 降低维度 [[26](#ch6.xhtml#ref6_26)]。堆叠的三层 `AEs` 经过设计，使得最后一层的权重提供患者的表示。还提取了患者的时间数据，以了解代码识别是否从 `EHR` 记录中尽早完成。

### 6.4.3 表示的评估

表示通常通过分类技术进行评估，评估的准确性取决于临床数据在 `EHR` 中呈现的完美程度。某些研究专注于直接评估表示，而不进行任何下一层级的分类。到目前为止，还没有针对深度学习网络产生的临床数据输出的通用评估参数。因此，无法对各种深度学习网络所做的预测进行评估。文献中使用的常见参数包括概念连贯性 [[40](#ch6.xhtml#ref6_40)]、[[43](#ch6.xhtml#ref6_43)]、医学概念相似度度量 (`MCSM`) 和医学相关性度量 `MRM`，用于评估 `EHR` 医疗代码。研究人员并未在通用基准数据集上执行深度学习 `EHR` 工作，因此无法根据其工作中获得的结果进行评估。

### 6.4.4 疾病诊断

深度学习进行 `EHR` 分析的最终目标是基于可用记录进行疾病诊断。当患者数据明确显示症状时，诊断可以立即进行；也可能会延迟，并建议进行进一步检查以做出明确预测。根据预测的时间，诊断分为静态或时序。时序预测需要时间进行最终诊断，而静态预测在首次就诊时即识别出疾病。心力衰竭、高血压、骨质疏松等被归类为静态，而心血管疾病、肾脏糖尿病、心理健康以及某些类别的心力衰竭被归类为静态。无监督学习是此类预测的常用技术。通过改进深度学习概念的表示，可以提高此类预测的准确性。静态预测不考虑时序事件，研究人员已证明 `MLP` 是此类预测中 `ANNs` 中的最佳模型 [[37](#ch6.xhtml#ref6_37)]。利用完整 `EHR` 数据设计的自杀风险识别分类器 [[24](#ch6.xhtml#ref6_24)] 表现优于仅使用诊断代码的分类器。某些深度学习架构需要一定的时间段来诊断疾病。带有时序医疗细节的 `CNN` 网络用于预测心脏问题，发现其效果更好，结果良好 [[47](#ch6.xhtml#ref6_47)]。`Skip-gram`、`GRU` 和 `LSTM` 网络也在文献中用于诊断和代码标记 [[39](#ch6.xhtml#ref6_39)]、[[45](#ch6.xhtml#ref6_45)]、[[48](#ch6.xhtml#ref6_48)]。Nickerson 等人 [[49](#ch6.xhtml#ref6_49)] 使用 `MLP` 和 `LSTM` 网络预测术后并发症，而另外两项工作建议使用 `CNN` 和 `RNN` 预测出院后的再入院情况和肾移植后的并发症 [[38](#ch6.xhtml#ref6_38)]、[[50](#ch6.xhtml#ref6_50)]。

### 6.4.5 评估指标

`EHR` 数据的首要问题是不同医疗代码的分类。医学图像需要根据深度学习策略进行分割或分类。此类分类的输出应通过通用指标进行评估。准确率、精确率和召回率是用于评价深度学习网络诊断输出的常用指标。由于没有通用的基准数据集，现有文献的分类结果无法直接基于这些现有结果进行比较。

### 6.4.6 风险识别与生存预测

为了预防疾病复发，应正确识别导致疾病的因素。这种识别还能帮助医生为患者提供良好的治疗，使其早日康复。文献还建议使用深度网络从存储在 `EHR` 数据中的风险因素中识别特征 [[51](#ch6.xhtml#ref6_51)]、[[52](#ch6.xhtml#ref6_52)]。

## 6.5 EHR 数据集

`EHR` 数据集由医院持有，很难获取此类数据。此类数据以图像、文本、数值等多种格式提供 [[8](#ch6.xhtml#ref6_8)]。深度学习研究报告的结果基于专有数据集，不公开可用。公开可用的数据集有重症监护医学信息市场 (`MIMIC`) 和 i2b2：整合生物学与床边信息学 [[53](#ch6.xhtml#ref6_53)]、[[54](#ch6.xhtml#ref6_54)]。`PCORnet` 数据库由合作伙伴网络组成——13 个临床数据研究网络 (`CDRNs`)。`PCORnet` 指的是通用数据模型 (`CDM`)，用于规范临床记录。Data World 网站 `https://data.world/datasets/ehr` 也包含被多个项目使用的 `EHR` 数据集。

## 6.6 研究空白

用于 `EHR` 数据分析的传统机器学习方法正被深度学习技术取代，并被证明能产生良好结果。尽管近期文献表明深度学习技术在临床数据分析中取得了成功，但要实现准确的分析和预测仍有很长的路要走，这需要进一步的研究和改进现有方法。主要问题是获取医院持有的 `EHR` 数据。为了维护患者数据的隐私，大多数医院拒绝提供数据供研究人员分析 [[8](#ch6.xhtml#ref6_8)]。结果，尽管医院的 `EHR` 数据大量增长，但可用于实际分析的数据却非常少。尽管公开有一些数据，但这些数据并未涵盖所有医疗并发症，因此很难用这少量数据进行深入分析。设计稳健且泛化的深度 `EHR` 模型需要大量数据。第二个主要问题是 `EHR` 数据高度非结构化和无序排列，包含更多噪声、错误和缺失数据 [[8](#ch6.xhtml#ref6_8)]。这两个主要问题构成了深度 `EHR` 记录分析设计中的瓶颈。
