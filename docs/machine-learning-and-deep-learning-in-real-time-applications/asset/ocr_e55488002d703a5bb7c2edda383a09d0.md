The same holds for deep learning frameworks. The commonly used framework is TensorFlow (Abadi et al., 2016) that is developed by Google and launched in 2015. Other frameworks that are less used are Caffe (Jia et al., 2014), MXNet (MXNet, 2017), etc. The recent addition to this is PyTorch

PyTorch is an open-source, python-based deep learning framework and backed by Facebook AI Research with strong support for GPU accelerated computations of deep learning models. It is based on Torch, which is written in the Lua programming language (Ierasalumisch et al., 1996). Due to its dynamic nature of computation graphs and integration with python, it is gaining a lot of- attention in the research community.

The dynamic nature of PyTorch allows us to use native python code and other python libraries like Numpy (Py 2018) and Scipy (2015), to easily integrate with PyTorch compared to other deep learning libraries where library-specific methods are used to execute the same.

The dynamic nature of graphs allows PyTorch to build its deep learning applications to be executed at runtime, as compared to other deep learning frameworks that rely on static graphs that have been built before running the model.

A computational graph is a directed graph in which the nodes correspond to operations or variables. Variables can feed their values into operations, and operations can feed their output into other operations. In this way, each node defines a function of the variables. The values fed into the node and come out of the nodes are called tensors, which is a multi-dimensional array. Hence, it comprises scalars, vectors, and matrices as well as tensors of a higher rank.

The dynamic nature of computation graphs allows the creation and execution of the graph at the same time. This allows easy debugging of a neural network. The debugging becomes even more prominent as the size of the neural network model increases. The dynamic nature also allows for changing the graph at run time which is particularly helpful in sequence modeling where the size of inputs is different. However, dynamic computational graphs do not offer optimization of computations nor static analysis which computational graphs offer.
