

下一步是从该初始样本生成许多新列表，以便从决策列表的后验分布中获得许多样本。

新的决策列表是通过从初始列表开始，然后随机将规则移动到列表中的不同位置、从预先挖掘的条件中将规则添加到当前决策列表，或从决策列表中删除规则来进行采样的。被切换、添加或删除的规则是随机选择的。在每个步骤中，算法都会评估决策列表的后验概率（准确性与简洁性的混合）。Metropolis Hastings 算法确保我们采样具有高后验概率的决策列表。此过程为我们提供了来自决策列表分布的许多样本。BRL 算法选择样本中后验概率最高的决策列表。

## 示例

理论部分到此结束，现在让我们看看 BRL 方法的实际应用。示例中使用了一种名为 Scalable Bayesian Rule Lists (SBRL) 的 BRL 快速变体，由 Yang et. al (2017) 22 提出。我们使用 SBRL 算法来预测宫颈癌风险。首先，我必须对所有输入特征进行离散化，以便 SBRL 算法能够工作。为此，我根据分位数将连续特征分箱。

我们得到以下规则：

### 规则

```
If {STDs=1} (rule[259]) then positive probability = 0.16049383
else if {Hormonal.Contraceptives.years.=[0,10)} (rule[82]) then positive probability = 0.04685408
else (default rule) then positive probability = 0.27777778
```

需要注意的是，我们得到的规则是合理的，因为 THEN 部分的预测不是类别结果，而是癌症的预测概率。

这些条件是从使用 FP-Growth 算法预先挖掘的模式中选择的。下表显示了 SBRL 算法在构建决策列表时可以选择的条件池。作为用户，我允许的条件中特征值的最大数量为两个。以下是十个模式的样本：

### 预先挖掘的条件

- Num.of.pregnancies=[3.67,7.33)
- IUD=0,STDs=1
- Number.of.sexual.partners=[1,10),STDs.Time.since.last.diagnosis=[1,8)
- First.sexual.intercourse=[10,17.3),STDs=0
- Smokes=1,IUD.years.=[0,6.33)
- Hormonal.Contraceptives.years.=[10,20),STDs.Number.of.diagnosis=[0,1)
- Age=[13,36.7)
- Hormonal.Contraceptives=1,STDs.Number.of.diagnosis=[0,1)
- Number.of.sexual.partners=[1,10),STDs.number.=[0,1.33)
- STDs.number.=[1.33,2.67),STDs.Time.since.first.diagnosis=[1,8)

接下来，我们将 SBRL 算法应用于自行车租赁预测任务。只有当预测自行车数量的回归问题被转换为二分类任务时，这才可行。我通过创建一个标签来任意创建一个分类任务：如果某一天的自行车数量超过 4000 辆，则标签为 1，否则为 0。

以下列表是由 SBRL 学习得到的：

### 规则

```
If {yr=2011,temp=[-5.22,7.35)} (rule[718]) then positive probability = 0.01041667
else if {yr=2012,temp=[7.35,19.9)} (rule[823]) then positive probability = 0.88125000
else if {yr=2012,temp=[19.9,32.5)} (rule[816]) then positive probability = 0.99253731
else if {season=SPRING} (rule[351]) then positive probability = 0.06410256
else if {temp=[7.35,19.9)} (rule[489]) then positive probability = 0.44444444
else (default rule) then positive probability = 0.79746835
```

让我们预测 2012 年某天气温为 17 摄氏度时，自行车数量超过 4000 辆的概率。第一条规则不适用，因为它只适用于 2011 年的日期。第二条规则适用，因为该日期在 2012 年，且 17 摄氏度位于区间 [7.35, 19.9) 中。我们对概率的预测是，租出超过 4000 辆自行车的概率为 88%。

## 4.5.4 优势

本节讨论 IF-THEN 规则的一般优势。

IF-THEN 规则易于解释。它们可能是可解释模型中最具可解释性的模型。此说法仅在规则数量较少、规则条件较短（我最多会说 3 个）且规则组织为决策列表或非重叠决策集时才适用。

决策规则可以与决策树一样具有表达性，同时更加紧凑。决策树也经常遭受复制子树的影响，即当左子节点和右子节点的分割具有相同结构时。

使用 IF-THEN 规则进行预测很快，因为只需检查少数几个二元语句即可确定哪些规则适用。

决策规则对输入特征的单调变换具有鲁棒性，因为只有条件中的阈值会发生变化。它们对异常值也具有鲁棒性，因为只关心条件是否适用。

IF-THEN 规则通常生成稀疏模型，这意味着包含的特征不多。它们只为模型选择相关特征。例如，线性模型默认会为每个输入特征分配一个权重。不相关的特征可以简单地被 IF-THEN 规则忽略。

像 OneR 这样的简单规则可以用作更复杂算法的基线。

## 4.5.5 劣势

本节讨论 IF-THEN 规则的一般劣势。

IF-THEN 规则的研究和文献主要关注分类，几乎完全忽略回归。虽然你始终可以将连续目标划分为区间并将其转换为分类问题，但你始终会丢失信息。一般来说，既可用于回归又可用于分类的方法更具吸引力。

通常，特征也必须是类别特征。这意味着如果要使用数值特征，必须对其进行分类。将连续特征切分为区间有多种方法，但这并非易事，并且伴随着许多没有明确答案的问题。特征应该被分成多少个区间？分割标准是什么：固定区间长度、分位数或其他？对连续特征进行分类是一个非平凡的问题，经常被忽视，人们只是使用最次佳的方法（就像我在示例中所做的那样）。

许多旧的规则学习算法容易过拟合。这里介绍的算法都至少具有一些防止过拟合的保障措施：OneR 受到限制，因为它只能使用一个特征（只有当特征具有太多级别或存在许多特征时才有问题，这相当于多重检验问题），RIPPER 进行剪枝，而 Bayesian Rule Lists 在决策列表上施加先验分布。

决策规则在描述特征与输出之间的线性关系方面表现不佳。这是它们与决策树共有的问题。决策树和规则只能产生阶梯状的预测函数，预测的变化始终是离散步骤，而绝不是平滑曲线。这与输入必须是类别特征的问题有关。在决策树中，它们通过分割被隐式分类。
