### 5.4.4 优点

交互 H-statistic 通过部分依赖分解具有基础理论。

H-statistic 具有**有意义的解释**：交互被定义为由交互解释的方差份额。

由于该统计量是**无量纲的**，因此它可跨特征甚至跨模型进行比较。

该统计量**检测各种类型的交互**，无论其具体形式如何。

借助 H-statistic 还可以分析任意**高阶交互**，例如 3 个或更多特征之间的交互强度。

### 5.4.5 缺点

首先你会注意到：交互 H-statistic 计算耗时很长，因为它在**计算上代价高昂**。

计算涉及估计边缘分布。如果不使用所有数据点，这些**估计也具有一定的方差**。这意味着在抽样点时，估计值在每次运行之间也会有所变化，且**结果可能不稳定**。我建议重复计算几次 H-statistic，以查看是否有足够的数据来获得稳定结果。

目前不清楚交互是否显著大于 0。我们需要进行统计检验，但此**检验在（尚未）模型无关版本中不可用**。

关于检验问题，很难说 H-statistic 多大才足以让我们认为交互是“强”的。

另外，H-statistics 可能大于 1，这使得解释变得困难。

H-statistic 告诉我们交互的强度，但不会告诉我们交互长什么样。部分依赖图就是为此而设。一个有意义的工作流是先测量交互强度，然后为你感兴趣的交互创建 2D 部分依赖图。

如果输入是像素，则无法有意义地使用 H-statistic。因此，该技术对图像分类器不有用。

交互统计量基于我们可以独立打乱特征的假设。如果特征强相关，则该假设被违反，我们将在现实中极不可能出现的特征组合上进行积分。部分依赖图也存在同样的问题。一般来说，你无法判断这是否会导致高估或低估。

有时结果很奇怪，在小规模模拟中无法产生预期结果。但这更多是一种偶然的观察。

### 5.4.7 替代方案

H-statistic 不是衡量交互的唯一方法：

Hooker (2004) 33 提出的变量交互网络（VIN）是一种将预测函数分解为主效应和特征交互的方法。然后将特征之间的交互可视化为网络。不幸的是，目前尚无可用软件。

Greenwell 等人 (2018) 34 提出的基于部分依赖的特征交互方法衡量两个特征之间的交互。这种方法衡量一个特征在另一个特征不同固定点上的特征重要性（定义为部分依赖函数的方差）。如果方差较高，则特征之间存在交互；如果方差为零，则不存在交互。相应的 R 包 vip 可在 Github 上获取。该包还涵盖部分依赖图和特征重要性。

## 5.5 排列特征重要性

排列特征重要性衡量在我们排列特征值后模型预测误差的增加，这打破了特征与真实结果之间的关系。

### 5.5.1 理论

这个概念非常简单直接：我们通过计算排列特征后模型预测误差的增加来衡量特征的重要性。如果打乱特征的值会增加模型误差，则该特征是“重要”的，因为在这种情况下模型依赖该特征进行预测。如果打乱特征的值使模型误差保持不变，则该特征是“不重要”的，因为在这种情况下模型忽略了该特征进行预测。排列特征重要性由 Breiman (2001) 35 为随机森林提出。基于这一思路，Fisher, Rudin, 和 Dominici (2018) 36 提出了特征重要性的模型无关版本，并称其为模型依赖。他们还介绍了关于特征重要性的更高级概念，例如（特定于模型的）版本，该版本考虑到许多预测模型可能对数据进行很好的预测。他们的论文值得一读。

**基于 Fisher, Rudin, 和 Dominici (2018) 的排列特征重要性算法：**

输入：训练好的模型 f，特征矩阵 X，目标向量 y，误差度量 L(y,f)。

- 1. 估计原始模型误差 e<sup>orig</sup> = L(y, f(X))（例如，均方误差）
- 2. 对于每个特征 j = 1,...,p：
    - 通过在数据 X 中排列特征 j 生成特征矩阵 X<sup>perm</sup>。这打破了特征 j 与真实结果 y 之间的关联。
    - 基于排列数据的预测估计误差 e<sup>perm</sup> = L(Y,f(X<sup>perm</sup>))。
    - 计算排列特征重要性 FI = e<sup>perm</sup>/e<sup>orig</sup>。或者，也可以使用差值：FI = e<sup>perm</sup> - e<sup>orig</sup>
- 3. 按 FI 降序排列特征。

Fisher, Rudin, 和 Dominici (2018) 在其论文中建议将数据集分为两半，并交换两半中特征 j 的值，而不是排列特征 j。仔细想想，这与排列特征 j 完全相同。如果你想要更准确的估计，可以通过将每个实例与其他每个实例（除了自身）的特征 j 值配对，来估计排列特征 j 的误差。这会给你一个大小为 n (n-1) 的数据集来估计排列误差，并且需要大量计算时间。只有在你认真追求极其准确的估计时，我才建议使用 n(n-1)-方法。

### 5.5.2 我应该在训练数据还是测试数据上计算重要性？

tl;dr：我没有确切答案。

回答关于训练数据还是测试数据的问题，触及了什么是特征重要性这一根本问题。理解基于训练数据与基于测试数据的特征重要性之间差异的最佳方法是举一个“极端”的例子。我训练了一个支持向量机，使用 50 个随机特征（200 个实例）来预测连续的随机目标结果。这里的“随机”是指目标结果与 50 个特征独立。这就像根据最新的彩票号码预测明天的气温。如果模型“学习”了任何关系，那么它就过拟合了。事实上，SVM 确实在训练数据上过拟合了。训练数据的平均绝对误差（简称 mae）为 0.29，测试数据为 0.82，这也是始终预测平均结果为 0 的最佳可能模型的误差（mae 为 0.78）。换句话说，SVM 模型是一堆垃圾。你会对这个过拟合 SVM 的 50 个特征的特征重要性期望什么值？零，因为没有任何特征对未见测试数据的性能改进有贡献？还是应该让重要性反映模型对每个特征的依赖程度，无论学习到的关系是否能推广到未见数据？让我们来看看训练数据和测试数据的特征重要性分布有何不同。
