Shapley 值可以组合成全局解释。如果对每个实例运行 SHAP，我们将得到一个 Shapley 值矩阵。该矩阵每个数据实例对应一行，每个特征对应一列。我们可以通过分析该矩阵中的 Shapley 值来解释整个模型。

我们从 SHAP 特征重要性开始。

## 5.10.5 SHAP 特征重要性

SHAP 特征重要性的理念很简单：绝对 Shapley 值较大的特征很重要。由于我们需要全局重要性，因此按特征对数据中的绝对 Shapley 值求平均：

```
|I_j| = \sum_{i=1}^n |\phi_i^j(i)|
```

接下来，我们按重要性递减顺序对特征进行排序并绘制图表。下图显示了先前用于预测宫颈癌的随机森林模型的 SHAP 特征重要性。

![](img/9328bf422a53c0f374079f63527c081f_178_0.png)

图 5.51：SHAP 特征重要性，按平均绝对 Shapley 值计算。使用激素避孕药的年数是最重要的特征，平均将预测的绝对癌症概率改变了 2.4 个百分点（x 轴上的 0.024）。

SHAP 特征重要性是置换特征重要性的替代方案。两种重要性度量之间存在巨大差异：置换特征重要性基于模型性能的下降。SHAP 基于特征归因的大小。

特征重要性图很有用，但除了重要性之外不包含任何信息。为了获得更具信息量的图表，我们接下来将查看汇总图。

## 5.10.6 SHAP 汇总图

## 5.10.7 SHAP 依赖图

SHAP 特征依赖可能是最简单的全局解释图：
- 选择一个特征。
- 对于每个数据实例，绘制一个点，x 轴为特征值，y 轴为相应的 Shapley 值。
- 完成。

从数学上讲，该图包含以下点：{(x_j^{[i]}, phi_j^{[i]})}_{i=1}^n

## 5.10.8 SHAP 交互值

交互效应是考虑单个特征效应后的额外组合特征效应。博弈论中的 Shapley 交互索引定义为：

```
\phi_{i,\{i,j\}}=\sum_{\{S\subseteq\text{features}\setminus\{i,j\}\}}\{\frac{1}{M-1}\}\{\frac{1}{(M-|S|-2)!}\}\{\delta_{\{ij\}}(S)\}
```

当 (i \neq j) 且：

```
\{\delta_{\{ij\}}(S)=f_X(S\cup\{i,j\})-f_X(S\cup\{i\})-f_X(S\cup\{j\})+f_X(S)\}
```

此公式减去特征的主效应，因此在考虑个体效应后，我们得到纯交互效应。我们像计算 Shapley 值一样，对所有可能的特征联盟 S 的值进行平均。当我们为所有特征计算 SHAP 交互值时，每个实例会得到一个 M x M 维度的矩阵，其中 M 是特征数量。

## 5.10.9 对 SHAP 值进行聚类

可以借助 Shapley 值对数据进行聚类。聚类的目标是找到相似实例的组。通常，聚类基于特征。特征通常处于不同的尺度。例如，身高可能以米为单位，色彩强度从 0 到 100，某些传感器输出在 -1 到 1 之间。困难在于计算具有如此不同、不可比较特征的实例之间的距离。

SHAP 聚类通过对每个实例的 Shapley 值进行聚类来工作。这意味着你按解释相似性对实例进行聚类。所有 SHAP 值都具有相同的单位——预测空间的单位。你可以使用任何聚类方法。下例使用层次聚合聚类来对实例进行排序。

## 5.10.10 优点

由于 SHAP 计算 Shapley 值，因此 Shapley 值的所有优点都适用：SHAP 在博弈论中具有**坚实的理论基础**。预测在特征值之间**公平分配**。我们得到**对比性解释**，它们将预测与平均预测进行比较。

SHAP 连接了 **LIME 和 Shapley 值**。这有助于更好地理解这两种方法。它还有助于统一可解释机器学习领域。

SHAP 有 **基于树的模型的快速实现**。我认为这是 SHAP 流行的关键，因为 Shapley 值采用的最大障碍是计算缓慢。

快速计算使得能够计算 **全局模型解释** 所需的众多 Shapley 值。全局解释方法包括特征重要性、特征依赖、交互作用、聚类和汇总图。使用 SHAP 时，全局解释与本地解释保持一致，因为 Shapley 值是全局解释的“原子单位”。如果你使用 LIME 进行本地解释，并使用部分依赖图加上置换特征重要性进行全局解释，你将缺乏共同基础。

## 5.10.11 缺点

**KernelSHAP 很慢**。这使得在需要为许多实例计算 Shapley 值时，KernelSHAP 不实用。此外，所有全局 SHAP 方法（例如 SHAP 特征重要性）都需要为大量实例计算 Shapley 值。

**KernelSHAP 忽略特征依赖**。大多数其他基于置换的解释方法也存在这个问题。通过将特征值替换为随机实例中的值，通常更容易从边缘分布中进行随机采样。但是，如果特征存在依赖（例如相关），这会导致对不太可能的数据点赋予过多权重。TreeSHAP 通过显式建模条件期望预测来解决这个问题。

**TreeSHAP 可能会产生不直观的特征归因**。虽然 TreeSHAP 解决了外推到不太可能数据点的问题，但它引入了一个新问题。TreeSHAP 通过依赖条件期望预测来改变值函数。随着值函数的改变，对预测没有影响的特征也可能得到非零的 TreeSHAP 值。

Shapley 值的缺点也适用于 SHAP：Shapley 值可能被误解，并且需要访问数据才能为新数据计算它们（TreeSHAP 除外）。

使用 SHAP 有可能创建故意误导性的解释，这可能会掩盖偏见 52。如果你是创建解释的数据科学家，这并不是一个实际问题（如果你是想要创建误导性解释的邪恶数据科学家，这甚至可能是一个优势）。作为解释的接收者，这是一个缺点，因为你无法充分确定其真实性。
