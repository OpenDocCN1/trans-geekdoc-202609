## 4.4 决策树

当特征与结果之间的关系为非线性，或者特征之间存在交互作用时，线性回归和逻辑回归模型会失效。决策树大显身手的时候到了！基于树的模型会根据特征中的某些截断值多次拆分数据。通过拆分，会创建数据集的不同子集，每个实例属于其中一个子集。最终的子集称为终端节点或叶节点，中间的子集称为内部节点或拆分节点。要预测每个叶节点中的结果，使用该节点中训练数据的平均结果。树可用于分类和回归。

有多种算法可以生长决策树。它们在树的可能结构（例如每个节点的拆分数量）、寻找拆分的标准、何时停止拆分以及如何估计叶节点内的简单模型方面有所不同。分类与回归树（CART）算法可能是树归纳中最流行的算法。我们将重点介绍 CART，但对大多数其他树类型来说，解释是相似的。我推荐《统计学习基础》（Friedman, Hastie and Tibshirani 2009）一书，以便更详细地介绍 CART。

![](img/9328bf422a53c0f374079f63527c081f_70_0.png)

图 4.16：使用人造数据的决策树。特征 x1 值大于 3 的实例最终进入节点 5。所有其他实例根据特征 x2 的值是否超过 1，被分配到节点 3 或节点 4。

以下公式描述了结果 y 与特征 x 之间的关系。

```
[\hat{y} = ...]
```

每个实例恰好落入一个叶节点（=子集 \R_m)）。\1(\{x\in \{R_m\})) 是身份函数，如果 \x\ 在子集 \R_m) 中则返回 1，否则返回 0。如果一个实例落入叶节点 \R_l)，则预测结果为 \hat{y} = c_l)，其中 \c_l) 是叶节点 \R_l) 中所有训练实例的平均值。

但是子集从何而来？这很简单：CART 选取一个特征，并确定哪个截断点能最小化回归任务中 y 的方差或分类任务中 y 的类别分布的基尼指数。方差告诉我们节点中 y 值围绕其均值的离散程度。基尼指数告诉我们一个节点有多不“纯”，例如，如果所有类别的频率相同，则节点不纯；如果只存在一个类别，则其纯度最大。当节点中的数据点具有非常相似的 y 值时，方差和基尼指数被最小化。因此，最佳截断点使两个生成的子集在目标结果方面尽可能不同。对于类别特征，算法通过尝试不同的类别分组来创建子集。在确定每个特征的最佳截断点后，算法选择在方差或基尼指数方面能产生最佳划分的特征进行拆分，并将此拆分添加到树中。算法在两个新节点中递归地继续这种搜索和拆分，直到达到停止标准。可能的标准是：拆分前节点中必须包含的实例最小数量，或终端节点中必须包含的实例最小数量。

### 4.4.1 解释

解释很简单：从根节点开始，你进入下一层节点，边告诉你正在查看哪些子集。一旦到达叶节点，该节点就会告诉你预测结果。所有边均通过 'AND' 连接。

模板：如果特征 x 小于/大于阈值 c 且 ... 则预测结果是该节点中实例的 y 的平均值。

### 特征重要性

决策树中某个特征的整体重要性可以通过以下方式计算：遍历所有使用该特征的拆分，并衡量它相比于父节点减少了多少方差或基尼指数。所有重要性之和将缩放到 100。这意味着每个重要性都可以解释为整体模型重要性的份额。

### 树分解

可以通过将决策路径分解为每个特征的一个组成部分来解释决策树的单个预测。我们可以跟踪树中的决策，并通过每个决策节点添加的贡献来解释预测。

决策树中的根节点是我们的起点。如果我们使用根节点进行预测，它将预测训练数据结果的均值。在下一次拆分时，我们要么从这个总和中减去一个项，要么加上一个项，具体取决于路径中的下一个节点。为了得到最终预测，我们需要遵循要解释的数据实例的路径，并不断向公式中添加项。

```
[\hat{y} = ...]
```

单个实例的预测是目标结果的均值，加上从根节点到实例最终到达的终端节点之间发生的 D 次拆分的所有贡献之和。不过，我们感兴趣的不是拆分贡献，而是特征贡献。一个特征可能被用于多次拆分或一次也不被使用。我们可以将每个 p 个特征的贡献相加，从而得到每个特征对预测贡献了多少的解释。

### 4.4.3 优点

树结构非常适合**捕捉数据中特征之间的交互作用**。

数据最终会落入**不同的组**中，这些组通常比线性回归中的多维超平面上的点更容易理解。解释可以说相当简单。

树结构还具有**自然的可视化**，带有其节点和边。

树**能够创建良好的解释**，正如“人性化解释”一章中所定义的那样。树结构会自动引导我们将单个实例的预测值视为反事实：“如果某个特征大于/小于拆分点，预测结果将是 y1 而非 y2。”树的解释是对比性的，因为你始终可以将实例的预测与相关的“什么如果”场景（由树定义）进行比较，这些场景就是树的其他叶节点。如果树较短，例如深度为一到三层拆分，那么生成的解释具有选择性。深度为三的树最多需要三个特征和拆分点来为单个实例的预测创建解释。预测的真实性取决于树的预测性能。短树的解释非常简单且通用，因为对于每次拆分，实例会落入其中一个叶节点，而二元决策易于理解。

无需转换特征。在线性模型中，有时需要对特征取对数。决策树对特征的任何单调变换都同样有效。

### 4.4.4 缺点

**树无法处理线性关系。** 输入特征与结果之间的任何线性关系都必须通过拆分来近似，从而创建一个阶梯函数。这并不高效。

这与**缺乏平滑性**相伴而生。输入特征的轻微变化可能会对预测结果产生重大影响，这通常不是可取的。想象一棵预测房价的树，该树使用房屋大小作为其中一个拆分特征。拆分发生在 100.5 平方米。想象使用你的决策树模型的房价估算器用户：他们测量房屋，得出房屋面积为 99 平方米的结论，将其输入价格计算器并得到 200,000 欧元的预测。用户注意到他们忘记测量一个面积为 2 平方米的小储藏室。储藏室有一面斜墙，因此他们不确定是否可以计算全部面积或只计算一半。因此，他们决定分别尝试 100.0 和 101.0 平方米。结果：价格计算器输出 200,000 欧元和 205,000 欧元，这相当不直观，因为从 99 平方米到 100 平方米并没有变化。

树也相当**不稳定**。训练数据集的少量变化可能会创建一棵完全不同的树。这是因为每个拆分都取决于父节点拆分。如果选择了不同的特征作为第一个拆分特征，整个树结构都会改变。如果结构如此容易改变，就不会对模型产生信心。

决策树非常可解释——前提是它们足够短。**终端节点的数量随深度快速增加。** 终端节点越多、树越深，就越难以理解树的决策规则。深度为 1 意味着 2 个终端节点。深度为 2 意味着最多 4 个节点。深度为 3 意味着最多 8 个节点。树中终端节点的最大数量为 2 的深度次方。
