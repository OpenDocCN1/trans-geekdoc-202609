### 步骤 3（可选）：特征重要性

对于原始特征的线性项，特征重要性通过标准化预测器来衡量：

```
I_j = |\hat{\beta}_j| \cdot \text{std}(I_j(x_j))
```

其中 (\beta_j) 是 Lasso 模型的权重，(\std(I_j(x_j))) 是线性项在数据上的标准差。

对于决策规则项，重要性按以下公式计算：

```
I_k = |\hat{\alpha}_k| \cdot \sqrt{s_k(1-s_k)}
```

其中 (\hat{\alpha}_k) 是决策规则对应的 Lasso 权重，(s_k) 是特征在数据中的支持度，即决策规则适用的数据点百分比（其中 (r_k(x)=1)）：

```
s_k = \frac{1}{n} \sum_{i=1}^n \{ r_k(x^{(i)}) \}
```

特征既可以作为线性项出现，也可能出现在众多决策规则中。如何衡量特征的总重要性？特征的重要性 (J_j(x)) 可以针对每个单独预测进行测量：

```
J_j(x) = I_j(x) + \sum_{x_j \in \text{lin}\{r_k\}} I_k(x) / m_k
```

其中 (I_l) 是线性项的重要性，(I_k) 是 (x_j) 出现的决策规则的重要性，(m_k) 是构成规则 (r_k) 的特征数量。将所有实例的特征重要性相加，即可得到全局特征重要性：

```
J_j(X) = \sum_{i=1}^n J_j(x^{(i)})
```

可以选择一个实例子集，并计算该组的特征重要性。

### 4.6.3 优点

RuleFit 会自动将特征交互添加到线性模型中。因此，它解决了线性模型需要手动添加交互项的问题，并且在一定程度上有助于建模非线性关系。

RuleFit 可以处理分类和回归任务。

创建的规则易于解释，因为它们是二进制决策规则。规则要么适用于某个实例，要么不适用。只有当规则内的条件数量不过多时，才能保证良好的可解释性。在我看来，具有 1 到 3 个条件的规则似乎是合理的。这意味着树集中树的最大深度为 3。

即使模型中有许多规则，它们也不适用于每个实例。对于单个实例，只有一小撮规则适用（＝具有非零权重）。这提高了局部可解释性。

RuleFit 提供了一组有用的诊断工具。这些工具与模型无关，因此你可以在书的模型无关部分找到它们：特征重要性、部分依赖图和特征交互。

### 4.6.4 缺点

有时 RuleFit 会创建许多在 Lasso 模型中获得非零权重的规则。随着模型中特征数量的增加，可解释性会下降。一个有希望的解决方案是强制特征效应单调，即特征的增加必须导致预测值的增加。

一个轶事式的缺点：论文声称 RuleFit 性能良好——通常接近随机森林的预测性能！——但在我个人尝试过的几个案例中，性能令人失望。你可以针对自己的问题试一下，看看表现如何。

RuleFit 流程的最终产品是一个带有附加花哨特征（决策规则）的线性模型。但由于它是线性模型，权重解释仍然不直观。它带有与常规线性回归模型相同的“脚注”：“……在所有其他特征固定的情况下。”当存在重叠规则时，情况变得更棘手。例如，自行车预测的一个决策规则（特征）可能是：“temp > 10”，而另一条规则可能是：“temp > 15 & weather='GOOD'”。如果天气好且温度高于 15 度，那么温度自动大于 10。在第二条规则适用的情况下，第一条规则也适用。第二条规则的估计权重解释为：“假设所有其他特征保持不变，当天气好且温度高于 15 度时，预测的自行车数量增加 \text{beta\_2}。”但现在很明显，“所有其他特征固定”是有问题的，因为如果规则 2 适用，规则 1 也适用，这种解释就没有意义了。

### 4.6.5 软件与替代方案

RuleFit 算法由 Fokkema 和 Christoffersen (2017) 25 在 R 中实现，你可以在 Github 上找到一个 Python 版本。

一个非常相似的框架是 skope-rules，一个 Python 模块，它也从集合中提取规则。它在学习最终规则的方式上有所不同：首先，skope-rules 基于召回率和精度阈值删除表现不佳的规则。然后，通过基于逻辑项（变量 + 大于/小于运算符）多样性和规则性能（F1 分数）的选择来删除重复和相似的规则。这一最终步骤不依赖于使用 Lasso，而仅考虑外袋 F1 分数和构成规则的逻辑项。

## 4.7 其他可解释模型

可解释模型的列表在不断增长，规模未知。它包括线性模型、决策树和朴素贝叶斯等简单模型，也包括结合或修改不可解释机器学习模型以使其更具可解释性的更复杂模型。特别是关于后一类模型的出版物目前以高频率产生，很难跟上发展步伐。本书在本章中仅简要介绍了朴素贝叶斯分类器和 k-近邻。

### 4.7.1 朴素贝叶斯分类器

朴素贝叶斯分类器使用条件概率的贝叶斯定理。对于每个特征，它根据特征值计算类的概率。朴素贝叶斯分类器独立地计算每个特征的类概率，这相当于对特征的条件独立性做出强（=天真）假设。朴素贝叶斯是一个条件概率模型，对类 \C_k\ 的概率建模如下：

```
P(C_k|x) = \frac{1}{Z} P(C_k) \prod_{i=1}^n P(x_i|C_k)
```

Z 是一个缩放参数，确保所有类的概率之和为 1（否则它们就不是概率）。类的条件概率是类概率乘以给定类下每个特征的概率，并由 Z 归一化。该公式可以通过使用贝叶斯定理推导出来。

由于独立性假设，朴素贝叶斯是一个可解释模型。它可以在模块层面进行解释。对于每个特征，它对某个类预测的贡献程度非常清晰，因为我们可以解释条件概率。

### 4.7.2 K-近邻

k-近邻方法可用于回归和分类，并使用数据点的最近邻进行预测。对于分类，k-近邻方法将实例最近邻中最常见的类分配给该实例。对于回归，它取邻居结果的平均值。棘手的部分是找到合适的 k 并决定如何衡量实例之间的距离，这最终定义了邻域。

k-近邻模型与本书中介绍的其他可解释模型不同，因为它是基于实例的学习算法。如何解释 k-近邻？首先，没有参数需要学习，因此在模块层面没有可解释性。此外，由于模型本质上是局部的，并且没有显式学习全局权重或结构，因此缺乏全局模型可解释性。也许它在局部层面是可解释的？要解释预测，你可以始终检索用于预测的 k 个近邻。模型是否可解释完全取决于你是否能“解释”数据集中的单个实例。如果一个实例由数百个或数千个特征组成，那么我认为它是不可解释的。但如果你的特征很少，或者有办法将实例缩减到最重要的特征，展示 k 个近邻可以给你提供良好的解释。
