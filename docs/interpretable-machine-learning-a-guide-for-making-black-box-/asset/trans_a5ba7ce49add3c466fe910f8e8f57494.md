

## 示例

让我们用真实数据试用 OneR。我们使用宫颈癌分类任务来测试 OneR 算法。所有连续输入特征被离散化为其 5 个分位数。创建了以下规则：

- 年龄预测
- (12.9,27.2] 健康
- (27.2,41.4] 健康
- (41.4,55.6] 健康
- (55.6,69.8] 健康
- (69.8,84.1] 健康

OneR 将年龄特征选为最佳预测特征。由于癌症罕见，每条规则的多数类（因此也是预测标签）总是健康，这不太有帮助。在这个不平衡的情况下，使用标签预测没有意义。'Age' 区间与癌症/健康的交叉表，以及患癌女性的百分比，更具信息量：

| | # 癌症 | # 健康 | P(癌症) |
|---|---|---|---|
| Age=(12.9,27.2] | 26 | 477 | 0.05 |
| Age=(27.2,41.4] | 25 | 290 | 0.08 |
| Age=(41.4,55.6] | 4 | 31 | 0.11 |
| Age=(55.6,69.8] | 0 | 1 | 0.00 |
| Age=(69.8,84.1] | 0 | 4 | 0.00 |

但在开始解读任何内容之前：由于每个特征和每个值的预测都是健康，因此所有特征的总错误率相同。默认情况下，总错误的平局通过使用错误率最低的特征中的第一个特征来解决（在这里，所有特征的错误率均为 55/858），这恰好是年龄特征。

## 4.5.2 序列覆盖（Sequential Covering）

序列覆盖是一种通用程序，通过反复学习单条规则来创建逐条规则覆盖整个数据集的决策列表（或集合）。许多规则学习算法都是序列覆盖算法的变体。本章介绍主要步骤，并使用 RIPPER（序列覆盖算法的一种变体）作为示例。

想法很简单：首先，找到适用于部分数据点的良好规则。删除被规则覆盖的所有数据点。当条件适用时，数据点即被覆盖，无论这些点是否被正确分类。使用剩余点重复规则学习和已覆盖点的删除，直到不再有点剩余或满足其他停止条件。结果是一个决策列表。这种反复进行规则学习和删除已覆盖数据点的方法称为 "分而治之"（separate-and-conquer）。

假设我们已经有一个可以创建覆盖部分数据的单条规则的算法。两类（一正一负）的序列覆盖算法的工作方式如下：

- 从空规则列表 (rlist) 开始。
- 学习一条规则 r。
- 当规则列表低于某个质量阈值（或正例尚未被覆盖）时：
  - 将规则 r 添加到 rlist。
  - 删除规则 r 覆盖的所有数据点。
  - 在剩余数据上学习另一条规则。
- 返回决策列表。

例如：我们有一个基于房屋大小、位置以及是否允许宠物来预测房屋价值的任务和数据集。我们学习第一条规则，结果为：如果 `size=big` 且 `location=good`，则 `value=high`。然后我们从数据集中删除所有位于好位置的大房子。使用剩余数据，我们学习下一条规则。也许：如果 `location=good`，则 `value=medium`。请注意，此规则是在没有位于好位置的大房子的数据上学习的，只剩下位于好位置的中型和小型房子。

对于多类设置，必须修改该方法。首先，按患病率递增顺序对类进行排序。序列覆盖算法从最不常见的类开始，为其学习一条规则，删除所有被覆盖的实例，然后转到第二不常见的类，依此类推。当前类始终被视为正类，所有患病率更高的类被合并为负类。最后一个类是默认规则。这在分类中也被称为一对所有策略（one-versus-all strategy）。

我们如何学习一条规则？OneR 算法在这里将毫无用处，因为它将始终覆盖整个特征空间。但还有许多其他可能性。一种可能性是使用束搜索从决策树中学习单条规则：

- 学习一棵决策树（使用 CART 或另一种树学习算法）。
- 从根节点开始，递归选择最纯净的节点（例如错误分类率最低的节点）。
- 终端节点的多数类用作规则预测；通往该节点的路径用作规则条件。

学习单条规则是一个搜索问题，搜索空间是所有可能规则的空间。搜索的目标是根据某些标准找到最佳规则。有许多不同的搜索策略：爬山（hill-climbing）、束搜索（beam search）、穷举搜索（exhaustive search）、最佳优先搜索（best-first search）、有序搜索（ordered search）、随机搜索（stochastic search）、自顶向下搜索（top-down search）、自底向上搜索（bottom-up search）、...

Cohen (1995) 的 RIPPER（重复增量剪枝以产生错误缩减）是序列覆盖算法的一种变体。RIPPER 更为复杂，并使用后处理阶段（规则剪枝）来优化决策列表（或集合）。RIPPER 可以以有序或无序模式运行，并生成决策列表或决策集合。

## 示例

我们将对示例使用 RIPPER。

RIPPER 算法在宫颈癌分类任务中未找到任何规则。

当我们使用 RIPPER 处理预测自行车数量的回归任务时，找到了一些规则。由于 RIPPER 仅适用于分类，因此必须将自行车数量转换为类别结果。我通过将自行车数量切分为四分位数来实现这一点。例如，(4548, 5956) 是涵盖 4548 到 5956 之间预测自行车数量的区间。下表显示了学习规则的决策列表。

## 规则

```
(days_since_2011 >= 438) and (temp >= 17) and (temp <= 27) and (hum <= 67) => cnt=(5956,8714]
(days_since_2011 >= 443) and (temp >= 12) and (weathersit = GOOD) and (hum >= 59) => cnt=(5956,8714]
(days_since_2011 >= 441) and (windspeed <= 10) and (temp >= 13) => cnt=(5956,8714]
(temp >= 12) and (hum <= 68) and (days_since_2011 >= 551) => cnt=(5956,8714]
(days_since_2011 >= 100) and (days_since_2011 <= 434) and (hum <= 72) and (workingday = WORKING DAY)
=> cnt=(3152,4548]
(days_since_2011 >= 106) and (days_since_2011 <= 323) => cnt=(3152,4548]
=> cnt=[22,3152]
```

解释很简单：如果条件适用，我们预测右侧的自行车数量区间。最后一条规则是默认规则，当没有其他规则适用于实例时适用。要预测新实例，请从列表顶部开始，检查是否有规则适用。当条件匹配时，规则的右侧就是该实例的预测值。默认规则确保总是有一个预测。

## 4.5.3 贝叶斯规则列表（Bayesian Rule Lists）

在本节中，我将向您展示学习决策列表的另一种方法，它遵循这个大致步骤：

1. 从数据中预挖掘可用作决策规则条件的频繁模式。
2. 从预挖掘规则的选集中学习决策列表。

使用此步骤的一种特定方法称为贝叶斯规则列表（Bayesian Rule Lists，Letham et al., 2015）20，简称 BRL。BRL 使用贝叶斯统计从用 FP-tree 算法（Borgelt 2005）21 预先挖掘的频繁模式中学习决策列表。

但让我们从 BRL 的第一步开始慢慢介绍。

## 频繁模式的预挖掘（Pre-mining of frequent patterns）

频繁模式是特征值的频繁（共）发生。作为 BRL 算法的预处理步骤，我们使用特征（此步骤不需要目标结果），并从中提取经常出现的模式。模式可以是单个特征值，例如 `size=medium`，也可以是特征值的组合，例如 `size=medium AND location=bad`。

模式的频率通过其在数据集中的支持度来衡量：

```
|{Support(x_j=A)=frac{1}{n}{sum_{i=1}^n I(x^{(i)}_j=A)}}|
```

其中 `A` 是特征值，`n` 是数据集中的数据点数量，`I` 是指示函数，如果实例 `i` 的特征 (`x_j`) 具有级别 `A` 则返回 1，否则返回 0。在房屋价值数据集中，如果 20% 的房子没有阳台，80% 的房子有一个或多个阳台，则模式 `balcony=0` 的支持度为 20%。支持度也可以针对特征值的组合进行衡量，例如 `balcony=0 AND pets=allowed`。
