## 5.8.2 复杂度与运行时间

了解锚点方法的渐近运行时行为有助于评估其在特定问题上的预期表现。设 (B) 表示束宽，(p) 表示所有特征的数量。那么，锚点算法受以下约束：

```
\mathcal{O}(B \cdot p^2 + p^2)
```

该边界抽象掉了与问题无关的超参数，例如统计置信度 (\delta)。忽略超参数有助于降低边界的复杂度（更多信息请参见原论文）。由于 MAB 在每一轮中从 (B \cdot p) 个候选项中提取 (B) 个最佳项，因此大多数 MAB 及其运行时间对 (p^2) 因子的乘积影响大于任何其他参数。

由此可见：算法的效率随特征丰富的问题而降低。

表格数据是由表格表示的结构化数据，其中列体现特征，行体现实例。例如，我们使用自行车租赁数据来演示锚点方法对选定实例的机器学习预测进行解释的潜力。为此，我们将回归问题转化为分类问题，并训练随机森林作为黑盒模型。其目的是对租赁自行车数量是高于还是低于趋势线进行分类。

## 5.8.4 优势

锚点方法相对于 LIME 具有多项优势。首先，该算法的输出更易于理解，因为规则易于解释（即使是对外行人士也是如此）。

此外，锚点是可子集化的，并且通过包含覆盖率概念甚至给出了重要性度量。其次，当模型在实例邻域中的预测是非线性或复杂的时，锚点方法也适用。由于该方法部署强化学习技术，而非拟合代理模型，因此不太可能欠拟合模型。

除此之外，该算法与模型无关，因此适用于任何模型。

此外，它非常高效，因为可以通过使用支持批量采样的 MAB（例如 BatchSAR）来并行化。

## 5.8.5 劣势

该算法存在高度可配置且影响深远的设置问题，这与大多数基于扰动的解释器类似。不仅需要调整束宽或精度阈值等超参数才能产生有意义的结果，还需要为特定领域/用例显式设计扰动函数。想想表格数据是如何扰动的，并思考如何将相同概念应用于图像数据（提示：这些无法应用）。幸运的是，在某些领域（例如表格数据）中可以使用默认方法，从而便于初始解释设置。

此外，许多场景需要离散化，否则结果将过于具体、覆盖率低，且无法帮助理解模型。虽然离散化可能有所帮助，但如果使用不当，也可能模糊决策边界，从而产生完全相反的效果。由于没有最佳离散化技术，用户在决定如何对数据进行离散化以避免获得糟糕结果之前，需要了解数据。

构建锚点需要对机器学习模型进行大量调用，这与所有基于扰动的解释器一样。虽然算法部署 MAB 来最小化调用次数，但其运行时间仍很大程度上取决于模型的性能，因此具有高度可变性。

最后，覆盖率的概念在某些领域中未定义。例如，没有显而易见或通用的定义来说明一张图像中的超像素如何与其他图像中的超像素进行比较。

## 5.8.6 软件与替代方案

目前有两种可用实现：anchor，一个 Python 包（也由 Alibi 集成）和一个 Java 实现。前者是锚点算法作者的参考实现，后者是一个带有 R 接口的高性能实现，名为 anchors，用于本章中的示例。截至目前，anchors 仅支持表格数据。然而，从理论上讲，锚点可以构建于任何领域或任何类型的数据。
