## Sharding

Sharding is a technique used to divide the blockchain into smaller fragments, called shards, each containing a portion of the total network state. Each shard processes a subset of transactions, allowing multiple operations to be performed simultaneously.

In the sharding model, each node on the network does not need to process every transaction. Instead, nodes are assigned to specific shards, reducing computational load and increasing processing capacity.

```python
class Shard:
    def __init__(self, shard_id):
        self.shard_id = shard_id
        self.transactions = []

    def add_transaction(self, transaction):
        self.transactions.append(transaction)

shard1 = Shard(shard_id=1)
shard2 = Shard(shard_id=2)

shard1.add_transaction({"from": "Alice", "to": "Bob", "amount": 10})
shard2.add_transaction({"from": "Charlie", "to": "Dave", "amount": 20})

print(f"Shard 1 Transactions: {shard1.transactions}")
print(f"Shard 2 Transactions: {shard2.transactions}")
```

The code illustrates how shards can divide transaction processing to improve efficiency.

## Advantages of Sharding

- Greater transaction capacity per second.
- Reduction of load on individual nodes.
- Horizontal scalability, allowing the network to grow as needed.

## Rollups

Rollups are solutions that group multiple transactions into a single batch outside of the main blockchain and then send the compressed results for on-chain validation. They can be classified into two types:

- **Optimistic Rollups**: They assume transactions are valid, but allow challenges in case of discrepancies.
- **ZK Rollups**: They use zero-knowledge proofs to guarantee the validity of transactions.

```python
def batch_transactions(transactions):
    batch = {"total": len(transactions), "transactions": transactions}
    return batch

transactions = [{"from": "Alice", "to": "Bob", "amount": 10},
                {"from": "Charlie", "to": "Dave", "amount": 20}]

rollup_batch = batch_transactions(transactions)
print(rollup_batch)
```

Rollups reduce the amount of data processed directly on the main blockchain, improving efficiency without sacrificing security.

Security is one of the fundamental pillars of blockchain, which uses advanced cryptography and decentralized structures to ensure data integrity and transaction reliability. However, even the most robust networks are not immune to threats and attacks. Understanding the main attack vectors and implementing effective protection measures is essential to ensuring the security of blockchain networks.

## Common Attacks

### 51% Attack

The 51% attack occurs when an individual or group controls more than 50% of the mining power of a blockchain network. This allows the attacker to manipulate transactions, such as reversing transfers, by spending the same asset twice, known as "double spending."

This attack exploits consensus' dependence on the majority of computing power. Smaller networks, with fewer miners, are particularly vulnerable, as it is easier for an attacker to accumulate the necessary power.

```python
class Blockchain:
    def __init__(self):
        self.chain = []
        self.power_distribution = {}

    def add_miner(self, miner, power):
        self.power_distribution[miner] = power

    def is_vulnerable(self):
        total_power = sum(self.power_distribution.values())
        for miner, power in self.power_distribution.items():
            if power / total_power > 0.5:
                return True
        return False

blockchain = Blockchain()
blockchain.add_miner("MinerA", 60)
blockchain.add_miner("MinerB", 40)

print("Vulnerable to 51% Attack:", blockchain.is_vulnerable())
```

The code assesses a network's vulnerability to 51% attacks, based on the distribution of power among miners.

### Sybil Attack

A Sybil attack occurs when an attacker creates multiple fake identities on the network to gain disproportionate influence. In consensus-based systems such as Proof of Stake, this can be used to manipulate validation and consensus decisions.

Measures such as Proof of Work, Proof of Stake, and identity requirements help mitigate Sybil attacks by making it expensive or impractical for attackers to create multiple identities.

### Distributed Denial of Service (DDoS) Attacks

DDoS attacks seek to overload network infrastructure, disrupting its operations. In the context of blockchain, this could include sending large numbers of malicious transactions to congest the network or target attacks at critical nodes.

```python
class Node:
    def __init__(self):
        self.requests = 0

    def receive_request(self):
        self.requests += 1
        if self.requests > 100:
            return "Node Overloaded"
        return "Request Processed"

node = Node()
for i in range(105):
    print(node.receive_request())
```

The code illustrates how a node can be overwhelmed with excessive requests, demonstrating the impact of a DDoS attack.

## Protection and Prevention Measures

### Decentralization

Decentralization is the first line of defense against attacks. In highly decentralized networks, it is more difficult for any entity to gain enough control to launch 51% or Sybil attacks.

Increasing the number of nodes and diversifying the distribution of computing power among miners helps strengthen the network's resilience.

### Efficient Consensus Algorithms

Consensus algorithms such as Proof of Work, Proof of Stake and Proof of Authority play a fundamental role in network security. Choosing the right algorithm for the network context helps mitigate risk.

- **Proof of Work** protects against Sybil attacks as it requires significant computational resources.
