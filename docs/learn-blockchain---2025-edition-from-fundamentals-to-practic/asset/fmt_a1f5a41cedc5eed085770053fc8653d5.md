## Healthcare Applications

In the healthcare sector, blockchain enables the secure management of medical records. Instead of storing data on centralized servers that are vulnerable to attack, records can be distributed across a network of nodes, where only authorized people can access them. ## Challenges

Although blockchain has numerous advantages, it also faces challenges. Scalability is one of the most discussed issues. As the number of transactions increases, blockchain networks may experience congestion, resulting in longer processing times and higher fees. Another challenge is adoption. Despite its growing popularity, many organizations still do not fully understand how to integrate blockchain into their existing processes. This requires investments in infrastructure, training and, often, a change in mindset regarding how data is managed.

# Chapter 2. Blockchain Fundamentals

The blockchain is made up of a unique architecture that combines a series of structural elements and mechanisms to guarantee security, transparency and immutability. A detailed understanding of how these pieces fit together is critical to mastering the technology. The block structure, hash, timestamp and chaining are the core elements that make blockchain a reliable and widely applicable solution.

## Block Structure

Each block in the blockchain is a unit of data that contains essential information organized into three main sections: header, transaction data, and hash of the previous block. This organization follows a logic that guarantees the immutability and integrity of the record.

A block's header includes the hash of the previous block, a timestamp marking the time the block was created, the nonce used to solve the proof-of-work algorithm (where applicable), and other metadata necessary to identify the block.

Transaction data represents the content of the block and can include any information valid for the blockchain application. In the case of Bitcoin, this data consists of financial transactions, while in other networks, such as Ethereum, it may contain smart contracts or other forms of data.

Each block is linked to the previous one through hashing, creating a continuous chain. This sequential structure is the basis for the secure and decentralized functioning of the blockchain.

## Hash and Its Function

The hash is an alphanumeric sequence generated by mathematical functions that transforms input data into a fixed-size output. In the blockchain, the hash serves as a fingerprint for each block, uniquely identifying it. Even a small change to the input data will result in a completely different hash, ensuring the integrity of the stored data.

On blockchain, the most widely used hash algorithm is `SHA-256` (Secure Hash Algorithm 256 bits). It processes any input and returns a fixed 256-bit sequence, which is used to create the unique block and transaction identifiers.

```python
import hashlib

def generate_hash(data):
    return hashlib.sha256(data.encode('utf-8')).hexdigest()

data = "blockchain example"
print(generate_hash(data))
```

This Python code demonstrates how to generate a `SHA-256` hash. The returned string is unique to the given input and changes completely if any character in the input changes.

In addition to providing integrity, hashing plays a crucial role in consensus algorithms such as proof of work. The solution to a hash-based mathematical problem is the mechanism that validates the addition of new blocks to the chain.

## Timestamp and Chronological Record

The timestamp is an essential component in the header of each block and indicates the exact moment the block was created and validated. This timestamp ensures that data on the blockchain is recorded chronologically, avoiding clutter and inconsistencies.

The reliability of the timestamp depends on consensus between network nodes, eliminating the possibility of unilateral manipulation. This is especially important in applications that require accurate history, such as supply chain asset tracking or medical records.

## Block Chaining

The connection between blocks occurs through the hash of the previous block, forming a continuous chain. This approach is fundamental to blockchain security, as any attempt to change a block invalidates the hashes of all subsequent blocks, making the change easily detectable.

Imagine a chain with three blocks. If a malicious actor attempts to modify the data in block 2, the hash of that block will change, breaking the connection to block 3. To disguise the change, it would be necessary to recalculate the hashes of all subsequent blocks, which would require significant computational power, especially in large networks.

Hash-based chaining also allows for quick verification of chain integrity. Any discrepancy between the hashes indicates manipulation or error, helping network participants maintain confidence in the stored data.

## Basic Cryptography on Blockchain

Cryptography is one of the pillars of blockchain security. It protects transactions, guarantees anonymity when necessary and authenticates network participants. Two main types of encryption are widely used: public and private key encryption and digital signatures.

### Public and Private Key Cryptography

Each participant in the blockchain has a pair of keys: a public key and a private key. The public key is used to identify the user, while the private key is used to sign transactions and authenticate ownership of assets.

The transaction is digitally signed with the sender's private key, ensuring that only the owner can initiate the transaction. The sender's public key allows other participants to verify the signature without revealing the private key.

```python
from cryptography.hazmat.primitives.asymmetric import rsa
from cryptography.hazmat.primitives import serialization, hashes
from cryptography.hazmat.primitives.asymmetric import padding

# Generating private key
private_key = rsa.generate_private_key(
    public_exponent=65537,
    key_size=2048,
)

# Generating public key
public_key = private_key.public_key()

# Signing message
message = b"transaction data"
signature = private_key.sign(
    message,
    padding.PSS(
        mgf=padding.MGF1(hashes.SHA256()),
        salt_length=padding.PSS.MAX_LENGTH
    ),
    hashes.SHA256()
)

# Verifying signature
public_key.verify(
    signature,
    message,
    padding.PSS(
        mgf=padding.MGF1(hashes.SHA256()),
        salt_length=padding.PSS.MAX_LENGTH
    ),
    hashes.SHA256()
)
```
