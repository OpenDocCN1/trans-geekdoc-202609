The Envoy is the Istio proxy that handles all the inbound and outbound traffic of the service mesh. The notebook communicates with the ml-pipeline service through the service mesh, the header information needs to be forwarded to the ml-pipeline service to establish the user identity from the notebook. The following .yaml file enables that. Run the following in the CloudShell environment to create the file:

```
cat << EOF > notebook_filter.yaml
apiVersion: networking.istio.io/valpha3
kind: EnvoyFilter
metadata:
  name: add-header
  namespace: admin
spec:
  configPatches:
    - applyTo: VIRTUAL_HOST
      match:
        context: SIDECAR_OUTBOUND
      routeConfiguration:
        host:
          name: ml-pipeline.kubeflow.svc.cluster.local:8888
          route:
            name: default
      patch:
      operation: MERGE
      value:
        request_headers_to_add:
          append: true
          header:
            key: kubeflow-userid
            value: admin@kubeflow.org
workloadSelector:
  labels:
```
