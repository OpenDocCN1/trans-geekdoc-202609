# Automating ML pipeline workflows

To automate the core ML platform components we have covered so far, we need to build pipelines that can orchestrate different steps using these components. Automation not only increases efficiency and productivity – it also helps enforce consistency, enable reproducibility, and reduce human errors. There are several open source technologies that can be used for automating ML workflows. In this section, we will take a look at Apache Airflow and Keflow Pipelines.

# Apache Airflow

Apache Airflow is an open source software package for programmatically authoring, scheduling, and monitoring multi-step workflows. It is a general-purpose workflow orchestration that can be used to define workflows for a wide range of tasks, including ML tasks. First, let's review some core Airflow concepts:

- **Directed Acyclic Graph (DAG):** A DAG defines independent tasks that are executed independently in a pipeline. The sequences of the execution can be visualized as a graph.
- **Tasks:** Tasks are basic units of execution in Airflow. Tasks have dependencies between them during executions.

- **Operators**: Operators are DAG components that describe a single task in the pipeline. An operator implements the task execution logic. Airflow provides a list of operators for common tasks, such as a Python operator for running Python code, or an Amazon S3 operator to interact with the S3 service. Tasks are created when operators are instantiated.

- **Scheduling**: A DAG can run on demand or on a predetermined schedule.

Airflow can run on a single machine or in a cluster. It can also be deployed on the Kubernetes infrastructure. The following figure shows a multi-node Airflow deployment:

![](img/bd21298357d8484151447cff0b2f138b_220_0.png)

The *master node mainly runs the web server and scheduler*. The scheduler is responsible for scheduling the execution of the DAGs. It sends tasks to a queue, and the worker nodes retrieve the tasks from the queue and run them. The metadata store is used to store the metadata of the Airflow cluster and processes, such as task instance details or user data.

You can author the Airflow DAGs using Python. The following sample code shows how to author a basic Airflow DAG in Python with two bash operators in a sequence:

```python
from airflow import DAG
from airflow.operators.bash.bash_operator import BashOperator
from datetime import datetime, timedelta
```

```python
default_args = {
    'owner': 'myname',
}
```

```python
with DAG('test', default_args=default_args, start_date=datetime(2023, 1, 1)) as dag:
    t1 = BashOperator(task_id='print', bash_command='date')
    t2 = BashOperator(task_id='sleep', bash_command='sleep 5')
    t1 >> t2
```

Airflow can connect to many external services, such as Amazon SageMaker.

# Kubeflow Pipelines

Kubeflow Pipelines is purpose-built for orchestrating end-to-end ML workflows on Kubernetes. First, let's review some core-core concepts:

- **Pipeline**: A pipeline describes a workflow and how the components are related.
- **Pipeline components**: A pipeline component performs a task. Examples of pipeline components could be data processing or model training.
- **Experiment**: An experiment organizes different runs.
- **Step**: The execution of one component in a pipeline is called a step.
- **Run trigger**: You use a run trigger to kick off the execution. A run trigger can be periodic (for example, every 2 hours), or a scheduled trigger (at a specific time).
- **Output artifacts**: Output artifacts are the outputs from the pipeline. Examples of output artifacts could be metrics or datasets.

Kubeflow Pipelines is installed as part of Kubeflow. It comes with its own UI, which is a dashboard. The service manages the pipelines and their status and stores them in a metadata database. The following figure (Figure 7.9) shows the core architecture:

![](img/bd21298357d8484151447cff0b2f138b_222_0.png)

Figure 7.9 – Kubeflow architecture

You author the pipeline using the Python SDK. To create and run a pipeline, follow these steps:

- Create a pipeline definition using the SDK. The pipeline definition specifies a list of components and how they are joined together in a graph.
- Compile the definition into a static YAML specification to be executed by the Kubeflow service.
- Register the specification with the Kubeflow service and call the pipeline from the static definition.
- The Kubeflow service calls the API server to create resources to run the pipeline.
- Orchestration controllers execute various containers to complete the pipeline run.
