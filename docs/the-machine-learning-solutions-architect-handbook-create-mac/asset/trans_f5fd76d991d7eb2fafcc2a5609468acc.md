# 业务理解与机器学习转型

业务工作流分析的目标是识别工作流中的低效环节，并确定是否可以应用机器学习（ML）来帮助消除痛点、提高效率甚至创造新的收入机会。

例如，当你对呼叫中心运营进行分析时，你想要识别痛点，如等待时间过长、客服人员之间的知识鸿沟、从通话录音中提取洞察的能力，以及缺乏针对增量服务和产品进行目标客户营销的能力。在识别出这些痛点后，你想要找出可用数据是什么以及业务指标如何改进。根据这些点和数据的可用性，你可以对潜在的机器学习解决方案提出一些假设，例如用于处理常见客户查询的虚拟助手、允许对转录文本进行文本分析的语音转文字，以及用于产品销售和追加销售的意图检测。

有时，为了实现既定的业务目标采用机器学习解决方案，需要对业务流程进行修改。以同样的呼叫中心为例，如果业务需求是根据通话录音分析生成的洞察来产生更多的交叉销售或追加销售，但没有业务流程能够根据这些洞察采取行动对目标客户进行交叉销售/追加销售，那么应该引入自动化的目标营销流程或销售人员的主动触达。

# 机器学习技术的识别与验证

一旦确定了机器学习选项列表，就要确定验证机器学习假设的必要性。这可能涉及简单的概念验证（POC）建模以验证可用数据集和建模方法，或者使用预构建的 AI 服务进行技术 POC，或是对机器学习框架进行测试。例如，你可能想测试使用现有的文本转录服务从音频文件中提取文本转录的可行性，或者为营销活动中的新产品转换构建自定义的倾向模型。机器学习解决方案架构并不侧重于新机器算法的研发，这通常是应用数据科学家和研究数据科学家的工作。

相反，机器学习解决方案架构侧重于识别和应用机器学习算法来解决不同的机器学习问题，如预测性分析、计算机视觉和/或自然语言处理。此外，任何建模任务的目标都不是构建生产级模型，而是为进一步的实验验证方法，这通常是全职应用数据科学家的责任。

# 系统架构设计与实现

机器学习解决方案架构涵盖的最重要方面是机器学习平台的技术架构设计。平台需要提供技术能力，以支持机器学习周期的不同阶段和人员角色，例如数据科学家和运维工程师。具体而言，机器学习平台需要具备以下功能：

- **数据探索与实验**：数据科学家使用机器学习平台进行数据探索、实验、模型构建和模型评估。机器学习平台需要提供等能力，如用于模型编写和实验的数据科学开发工具、用于数据探索和清洗（Wrangling）的数据处理工具、用于代码管理的源码控制以及用于库包管理的包仓库。
- **数据管理与大规模数据处理**：数据科学家或数据工程师需要技术能力来存储、访问和处理大量数据，以进行清洗、转换和特征工程。
- **模型训练基础设施管理**：机器学习平台需要为不同的建模需求提供使用不同类型计算资源、存储和网络配置的模型训练基础设施。它还需要支持不同类型的机器学习库或框架，例如 scikit-learn、TensorFlow 和 PyTorch。
- **模型托管/服务**：机器学习平台需要提供托管和提供模型以生成预测的技术能力，无论是实时、批处理还是兼者。
- **模型管理**：训练好的机器学习模型需要被管理和跟踪，以便于访问和查找，并带有相关的元数据。
- **特征管理**：通用且复用的特征需要被管理和提供，用于模型训练和模型服务。

# 机器学习平台工作流自动化

机器学习平台设计的关键方面是工作流自动化和持续集成/持续部署（CI/CD）。机器学习是一个多步骤工作流——它需要自动化，包括数据处理、模型训练、模型验证和模型托管。基础设施供应自动化和自服务是自动化设计的另一个方面。工作流自动的关键组件包括：

- **流水线设计与管理**：为各种任务（如模型训练和模型托管）创建不同自动化流水线的能力。
- **流水线执行与监控**：运行不同流水线并监控整个流水线以及每个步骤流水线执行状态的能力。
- **模型监控配置**：监控生产环境中模型的各种指标的能力，如数据漂移（使用的数据分布偏离了模型训练时的数据分布）、模型漂移（模型在生产环境中的性能与训练结果相比下降）以及偏差检测。

# 安全与合规

机器学习解决方案架构的另一个重要方面是敏感设置的安全与合规考量：

- **身份验证与授权**：机器学习平台需要提供访问平台和资源的身份验证与授权机制。
- **网络安全**：机器学习平台需要配置网络安全以防止未经授权的访问。
- **数据加密**：对于安全敏感的组织，数据加密是设计的另一个重要方面。
- **审计与合规**：审计和合规人员需要了解决策是如何做出的、从数据到模型的血缘，以及数据和模型中显示的任何偏差。机器学习平台需要提供解释性、偏差检测和可追溯性等其他能力。
