## 7.1.4 Training and testing decision trees

So, the example functions provide a means to assess split results in the optimal cost for a given feature; but how do we decide feature to choose at each node in a tree?

The basic idea behind decision tree optimization (see Algorithm 7.1) is, at each node, to search through all features and all possible thresholds on features $(\tau)$ to find the best possible cost, where the range of thresholds would be defined simply by all unique values of the data for feature: $[x_1, x_2, ... x_k]$. Once the tree is trained, a label is assigned to each leaf node, based on the labels of the training examples that reach that leaf. For classification, this equates to the class of the most common training label within that leaf; for regression, the leaf values is derived from some function of the data (such as the mean). ## 7.1.5 Decision trees with scikit-learn

To implement decision trees in scikit-learn, you may implement either DecisionTreeClassifier or DecisionTreeRegressor. With all scikit-learn supervised learning models, you de take a data matrix $X$, of shape $N$ (examples) $\times M$ (features), and a matrix $y$, of length $N$:

```
from sklearn.tree import DecisionTreeClassifier
classifier = DecisionTreeClassifier()
classifier.fit(X,y) # here y stores classes
```

```
from sklearn.tree import DecisionTreeRegressor
regressor = DecisionTreeRegressor()
regressor.fit(X,y) # here y stores continuous values
```

In addition to the default constructors (as shown), scikit-learn offers a range of tunable parameters including: the `criterion` argument, which tunes the choice of learning rule; and a selection of parameters designed to control overfitting including: `max_depth`, which limits total tree depth; `min_samples_split` and `min_samples_leaf`, which control the minimum number of training examples allowed for internal nodes and leaf nodes, respectively; `max_features`, which limits the choice of features available for each decision to a subset of the total (where this is important for training forests, Sect. 7.2.5). Finally, `ccp_alpha` allows pruning of terminal nodes that do not fit noise to improve the quality of the prediction.

## 7.2. Ensemble learning

Decision trees make for highly intuitive learning models; they are prone to overfitting, the deeper the tree, the more nonlinear the model and the greater chance of fitting to noise. While this may be addressed through judicious choice of hyperparameters, further gains may be achieved by enrolling (combining) predictions across a large number of trees. As we will see in this section, ensembles can improve the generalization of predictions by averaging away isolated errors.

## 7.2.1 Motivation

Take this toy example, where we have a test set for which the ground truth is class “1” for all ten examples:

```
$y = {1, 1, 1, 1, 1, 1, 1, 1, 1} \quad (7.13)
```

Let’s assume that we train three classifiers $A, B$ and $C$, and these return different predictions, each with 30% error

```
$$\hat{Y}_A = {1, 1, 0, 0, 1, 1, 1, 0, 0} \quad (7.14)$$
$$\hat{Y}_B = {0, 0, 1, 1, 1, 0, 1, 0, 1} \quad (7.15)$$
$$\hat{Y}_C = {1, 1, 1, 0, 0, 1, 1, 0, 1} \quad (7.16)$$
```

Each model makes mistakes on different examples. This means that, if we fuse the predictions across all three models through majority voting (assigning each example the label predicted most commonly across all constituent models), then the resulting prediction is 90% accurate

```
$$\hat{Y}_{ensemble} = {1, 1, 1, 1, 1, 1, 1, 0, 1} \quad (7.17)$$
```

By contrast, if we instead had three highly correlated prediction models:

```
$$\hat{Y}_D = {1, 1, 0, 1, 1, 1, 1, 0, 0} \quad (7.18)$$
$$\hat{Y}_E = {1, 1, 1, 1, 1, 1, 1, 0, 0} \quad (7.19)$$
$$\hat{Y}_F = {1, 1, 0, 1, 0, 1, 1, 0, 0} \quad (7.20)$$
```

then the potential gains throughsembling will be much less (or zero), i.e.,

```
$$\hat{Y}_{corr,ensemble} = {1, 1, 0, 1, 1, 1, 1, 0, 0} \quad (7.21)$$
```

The logic behind is therefore that, when decisions of uncorrelated prediction models are fused, the resulting prediction will have higher accuracy than any individual.

## 7.2.2 Classes of ensemble learning

Ensemble methods come in several forms that can be broadly classed as homogeneous or heterogeneous, with parallel or sequential models.

Homogeneous models combine predictions from the same class of machine learning. For scikit-learn, the default base learning is the decision tree; however, in principle, any classifier or regression model may be used. By contrast, heterogeneous models combine predictions from a variety of models. Colloquially, these methods are more often known as stacking.

Parallel learners, like the majority voting already described, train large numbers of models independently and combine them to smooth away errors. The objective is to learn as uncorrelated as possible. However, it's important to be conscious of the fact that, if predictions are stable, then parallel enrolling may even lead to a degradation of the result. Sequential models, on the other hand, train weak learners one after another, up-weighting the importance of wrongly predicted examples in each round. Combining in this way enables methods to collectively reduce the bias of the model and to improve the performance on edge cases. The family of methods known as boosting are examples of learners.

## 7.2.3 Bagging

Bagging (short for bootstrap aggregating [4]) is an example of a parallel homogeneous ensemble that seeks to reduce model variance by training a large number of decision trees, on others than in the original data set. It seeks to leverage the statistical property that, for independent random variables, the sampling distribution of the mean is $\frac{1}{T}$ times the variance, where $T$ is the number of trained models, i.e.,

$$\frac{var(Y)}{T}. \quad (7.22)$$

In other words, the act of averaging will naturally reduce the variance of the model. However, if we have only one training set, where do all these independent samples come from?

It turns out that we can generate any number of datasets through a process known as bootstrapping. We create new sets $\mathbf{X}_i, i=\{0, 1, \dots, T\}$ by sampling with replacement. In this way, each example from $\mathbf{X}$ may be sampled, several times or not at all, with the result, even though the total number of examples within each bootstrapped sample remains $N$, the composition of each $\mathbf{X}_i$ will be different (see the example in Sect. 7.2.4). Importantly, for large-enough sample size, bagging will closely approximate any sampling distribution estimated from the full population [26].
