
Fortunately, on corporate networks there are software applications which are used to enforce strong password policies within an organisation (e.g., `Active Directory`). Nevertheless, as mentioned above, IT staff struggle to protect business data located in mobile devices. Strong passwords are recommended if personal services are going to be accessed on mobile phones. The UK National Cyber Security Centre (NCSC), along with various security consultancy organisations, recommend that passwords should be created according to the combination of three random words that users can remember without doubt. In addition to this combination, it is important to use numeric and symbolic characters for password configuration. Nowadays, there is password enforcer software which makes users set authentication credentials that have a minimum length of 15 characters. The longer the password is, the harder it will be for attackers to crack it.

### 7.4.2.*Anti-virus software*

Anti-viruses are used in computers and laptops within organisations for detective and corrective purposes. They can detect threats and risks which are reported on exploit databases and download the latest updates to counteract the threat posed by viruses and malware. Anti-virus software can be downloaded to smartphones from marketplaces (e.g., `Google Play`, `Apple Store`) because it is common for attackers to develop malicious software for smartphones which tricks users and injects payloads that run in the background and perform unauthorized procedures. Applications considered attractive to users are exposed to cyber risks executed by attackers, allowing them to trigger rootkits, trojans or any other kind of viruses which can in turn allow them to perform information theft, file navigation, eavesdropping, etc.

### 7.4.3.*Authentication mechanisms*

As mobile networks and devices improve in terms of their performance and the service they provide to users, they demand more sophisticated security mechanisms for their protection. One of these mechanisms is authentication. During the rise of mobile networks several years ago, security was not necessary because the wireless transmission channels used in mobile networks were based on analogical technology as it had greater coverage, and these were used only for phone calls. Later, with the rise of 2G networks, multimedia messaging services (MMS) and internet services at lower speeds (e.g., 56 kbps), authentication mechanisms began to be required. The first authentication mechanism of this sort was phone locking on mobile phones using a hardware-based button. The user could control how long the phone would have to lie idle before they got locked out. With the rise of Apple and Android devices, authentication mechanisms got more sophisticated. It became possible to set a specific pattern which would unlock the phone, allowing the user to access the main windows. The pattern unlocking systems required the user to draw a specific figure on a nine-button environment.

Mobile devices have different authentication mechanisms. The first one is based on “something you know”, which, according to [Fig. 7.5](#chapter7.xhtml#fig7.5), can require the user to unlock the phone by: (a) drawing a pattern, (b) typing in a PIN number, or (c) inserting login credentials, in order to get access to the services the application offers. Login credentials are generally used to access services in BYOD environments. In addition, there is token-based authentication, which is commonly used for multi-factor authentication (MFA) purposes. For instance, some users receive a one-time passcode (OTP) via SMS, email or an application from the marketplace during the authentication process. This is called two-factor authentication (2FA) and is used to verify that the user legitimately owns the account they are logging in to. The latest authentication mechanism used nowadays on mobile devices is based on “something you are”. For instance, the latest smartphones come with biometric authentication such as fingerprint reading, facial or iris recognition or voice-based authentication (Samaras `*et al*., 2014`).

**Fig. 7.5.**Authentication mechanisms on smartphones. (a) `Pattern`, (b) `PIN`, (c) `login credentials`.

Upon analysing the authentication mechanisms, it can be concluded that the recommendation for mobile device users regardless of being connected or not to BYOD environments is to enable the latest authentication mechanism. Applications can also be purchased from the marketplace to add another layer of authentication to specific mobile applications. For instance, if a mobile device is hacked, the attacker would not be able to access a certain application or a certain piece of information if it is protected with another layer of authentication. This is because the attacker does not have the password, the temporary token, or even worse, the physical features of the owner that must be used for biometric authentication procedures.

### 7.4.4.*Remote control*

The implementation of BYOD security architecture and the MDM enables organisations to perform remote wipe or factory reset to mobile phones, but users can also take remote control of their mobile devices by registering them with the accounts associated with their respective marketplaces. For instance, to remotely protect Android devices, register the phone with a `Google Account` and use features such as `Find my Device`, which allows the user to locate the device through GPS services, play a sound remotely and remote wipe the phone to factory settings, deleting all the information on it, including any information in external storage.

### 7.4.5.*Importance of not rooting/jailbreaking the device*

Some years ago, the act of rooting mobile phones started gaining popularity, particularly in South American countries. This was because it gave users the freedom to customize their mobile phones to their tastes. One of the main reasons to root the device was to get access to applications from unknown sources for specific purposes, and to avoid paying for the benefits these applications provided. For Apple devices the process is called “jailbreaking”, and it was commonly used to connect the phone to the mobile network and to get access to phone calls, SMS and internet services. However, attackers nowadays take advantage of rooted phones because they can escalate privileges on these phones easily, taking full control of the devices in order to perform actions such as installing rootkits, using the devices within a botnet to perform further attacks, especially DoS attacks, and performing cryptomining in the background, thus consuming the phone’s resources. Moreover, rooting the phone also voids the warranty given when the user purchased the device. This leads to the user losing certain benefits. For instance, the provider will no longer troubleshoot problems with the device, or repair the device for free, as they ordinarily would during the duration of the warranty. Even though the user will have to pay to download some applications if they do not root or jailbreak a device, it is still best not to root or jailbreak the device, as doing so will remove a layer of security and the provider will no longer have control over the device. Due to rooting and jailbreaking, mobile providers have also had to dedicate more resources to customer service (Vignesh and Asha, 2015).
