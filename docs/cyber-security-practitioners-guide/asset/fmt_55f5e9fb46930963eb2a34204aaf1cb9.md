
The threat of employees transferring data to web storage accounts is very real. OneDrive is ubiquitously installed on workstations and can easily be configured by users to steal data, then to be removed from a system. It is interesting to note that OneDrive is unusual as an application in that it does not require local administrative rights to install and often installs itself when Office is upgraded as access rights are automatically elevated by the operating system to install updates. OneDrive is also installed by default on many new machines. Microsoft OneDrive for Business is an application which is often unintentionally installed on systems when Microsoft Office is installed. Assuming OneDrive is installed on a workstation, all a user or an attacker needs to do is temporarily configure it to use a Microsoft account. Once data has been taken, OneDrive can then be reconfigured, leaving no obvious trace that it has been used to exfiltrate data.

Tracking browsing is difficult as one webpage might reference several others for content. Looking at proxy server logs can also be confusing as references to other sites can often imply that a user has knowingly navigated to these referenced sites.

Not surprisingly, removing general web browsing from networks is becoming more common. Proxy servers can be set to allow access to only the banking sites and business sites needed. This might sound extreme but is not as impractical as it sounds. If access is removed totally, any forms that need to be completed online can be done by machines in a DMZ, and the completed forms transferred up to internal systems by email or hot folders. This model is effectively that of cloud computing where internet access from the cloud is restricted but a user can access the web directly from the desktop. Done properly this is like the age-old model used by the military called Bell-LaPadula where information can be transferred up to more secure areas but not down.

### 1.4.1.*ICMP tunnelling*

Several utilities are available for establishing ICMP tunnels. The most popular tool is `ptunnel` (Stodal, 2005). The main reason for these utilities is to allow a notebook user to bypass a proxy server on a public WIFI system. Despite the use of these, a good firewall should detect this traffic; however, to remove the vulnerability, the organisation’s firewall rules should not allow users to send the Ping message from workstations.

ICMP tunnelling tools were developed to provide a means to bypass a proxy server by creating an ICMP tunnel to an external web proxy server. However, it is easy to see how ICMP tunnelling can be exploited in a similar way to DNS tunnelling to create a covert channel by which data could be exfiltrated.

### 1.4.2.*NTP tunnelling*

Liska (2016) highlights that NTP is an old protocol with certain vulnerabilities in its design. NTP uses UDP port 123 and is required by servers to synchronise time. Workstations generally synchronise with domain controllers as part of a global policy. NTP or UDP 123 outbound is therefore not required from a workstation, however it can be used to generate several attacks internally and as an exfiltration method from a server configured as the network’s internal time server. Hyper-V replication requires that time is synchronised on a network to within 5 minutes, else replication stops. Microsoft’s Kerberos implementation requires time not to drift too much else machines have problems accessing network resources. Therefore, disrupting time on a network has serious consequences. Because an NTP query to the internet requires a response, NTP could also be used to establish a tunnel in a way similar to DNS tunnelling. The firewall rule allowing NTP outbound should therefore be restricted to genuine NTP time servers only. CVE-2015-7871 is a vulnerability that allows a server to accept a forged NTP packet from temporary peers (Liska, 2016). Safebreach, in their 2017 Security report, highlights that NTP is a sneaky method that hackers use to exfiltrate data (Safebreach, 2018).

### 1.4.3.*The threat posed by email*

Tracking email is quite straightforward, as each email generally has one source and one recipient. So, if email is exfiltrated by email, seeing what has happened is straightforward assuming an email gateway such as the Trustwave Secure Email Gateway or Mimecast has been used. Any rogue insider with a little knowledge would be aware that using email as a method to exfiltrate data is likely to leave a trail.

### 1.4.4.*Steganography*

This is the practice of hiding a message within a picture. The most popular method is to use the least significant bit of a pixel to hide data, as changing this causes no visible change to the appearance of a picture. `Steghide`, `Stegosuite`, `Jsteg`, `Openpuff`, `JPHide` and `JPSeek` are just some of the tools available with which to do this (Hegarty, 2018). Another technique is to merely append code to the end of a file; however, this is more likely to get detected.

Several leaks have used steganographic means to exfiltrate data; however, looking at this from a practical perspective, an attacker needs to find image files on a system in which sensitive data can be hidden. If a large amount of data is to be stolen, then it goes without saying that the amount of data to be exfiltrated using steganographic means will become significant, causing a bottleneck for the attacker. The volume of network traffic generated by using this method would provide easily detectible evidence, especially for any traffic monitoring systems such as Darktrace or Bro. An attacker would also need to be transmitting different pictures for the transfer not to look odd. The automation of the process of sending out data via varying pictures so that the hidden data can easily be extracted is perhaps a bit unlikely, though this method is not to be overlooked as a way of exfiltrating small amounts of data. The main threat from steganography is as an attack vector to deliver payload hidden in a picture. eBay and Facebook now re-render images uploaded to their platforms, which corrupts any steganographic content. Software tools like `Stegohunt` have been developed to detect the presence of hidden data and payloads in images (Whetstone, 2018), though real-time detection using antivirus programs is not standard.

### 1.4.5.*Dealing with a cyber attack*

After an incident, the key element that one looks at is logs. Logs hold tangible evidence of events. After an incident, a timeline must be drawn up showing what happened where and when. If clocks are not synchronised, this becomes not only very difficult but extremely confusing and provides ammunition for contesting any breach report. The time synchronisation of a system to a single reference time source is a requirement of ISO27001:2013(A.12.4.4).

Response plans need to be in place to address likely risks and recovery plans need to be designed to meet organisational recovery objectives in the event of system interruption or failure. Recovery plans need to be tested according to the “Plan, Do, Check” model of continual improvement described in BS 22301 (2014).

Whilst systems can be made resilient by deploying virtual servers on clusters using storage array networks and implementing server replication, the threat from ransomware is that unauthorised changes to data are also replicated to replica servers. For this reason, offline backups are vital. The downside of offline backups is the time taken to restore them and the loss of any data that may have been added or changed since the backup was taken. It is important where recovery time objectives are low to create an environment whereby as many risks as possible to system uptime are eradicated.

Should an incident occur, affected systems must be isolated immediately. The measures deployed will depend on budget and the organisation’s risk appetite.
