
Binod and Hyuk (2010) took the advantages of multipath routing which are useful for reliable MANET, and they proposed a basis for sending secure real-time streaming data over a multipath mobile adhoc network. Multipath routing can offers security for wireless ad-hoc routing and multimedia transfer. They considered digital signatures and encryption techniques. Their results show the good performance of the multipath mobile ad-hoc network. They also suggest the using of multicast, which is important in many video applications, in the future.

Emmanouis and Christos (2012) suggested a secure model for autonomous networks like mobile ad-hoc networks to create realtime communication in disaster rescue operations. Secure P2PSIP, intrusion detection and secure routing methods are vital parts of any secure model. The aforementioned concerns in the realm of emergency ad-hoc networks have been discussed. Emmanouis and Christos (2012) presented two additions to the IETF drafts and analysed them in relation to security power and scalability. The design of these extensions helps to meet the requirements of a mission-critical MANET within which rescuers can create links to communicate with each other by using lightweight devices such as PDAs. The situation concerning adaptive routing protocols and the use of IPsec to make them more secure has also been discussed.

These research studies have addressed some security issues for real-time traffic in MANET. However, they have not addressed the cryptographic issues in this network.

Sehgal *et al*. (2011) proposed an architecture in their research paper which states that self-organized distributed security could be provided by a five-layer security model, as well as authenticated and security-aware routing. After they carried out the simulation, they found that it provided security with negligible overhead.

A layered architecture can provide such advantages as modularity, simplicity, flexibility, and the standardization of protocols. The five-layer security architecture for MANETs incorporates the following layers: the Trust Relationship Security Layer, the Node-To-Node Security Layer, the Routing Level Security Layer, the Network Level Security Layer and the Application Level Layer. They expect this security architecture can be used as a framework when designing system security for ad-hoc networks.

Many previous research studies have also been conducted to address cryptographic issues related to real-time traffic. They could develop some algorithms to deal with real-time limitation issues, like delays.

Hu *et al*. (2009) propose a relay encryption scheme based on the threshold secret-sharing algorithm to enhance the data confidentiality, reliability and integrity in MANET. The basic idea is to distribute the whole encryption task to all the nodes along the route. Every node completes part of the encryption task instead of the single source node encrypting all of the data. They found that the encryption scheme can effectively alleviate the burden of the source node and reduce the transmission delay, besides, it improves the reliability of MANET.

Mohammed and Rohiem (2009) have introduced a Variable Mapping S-box technique with AES (VMS-AES) for the Voice over Internet Protocol (VoIP). A key is used to generate a parameter that is used to shift (remap) the substitution of the S-box randomly to another location depending on the initial key and the derived subkeys data. The results of this work could maximize nonlinearity so as to provide more resistance against linear attacks and to solve the fixed structure of the substitution function. They could also increase the overall security. Mohammed and Rohiem (2009) have also shown that seven rounds of encryption consume less power and execution time without affecting the security level. However, their findings have been criticised a long time ago, by Ferguson *et al*. (2001) and Daernen and Rijrnen (2002) who explained the possibility of saturation attacks on six and seven rounds of AES. They state that a seven-round attack can be mounted by adding one round before the distinguisher and two rounds after it. For these reasons their work is still unsuitable for the security requirements of wireless networks.

Another study on the topic has been published by Rahma and Yaco (2012). They proposed a symmetric dual key dynamic block algorithm (SDD) for digital video, which is a type of partial encryption technology. This algorithm meets the requirements of real time by combining a high level of complexity and a considerable speed. The proposed encryption algorithm SDD achieves better results than AES. It is faster by a factor of 13 times for encryption and faster by a factor of 9 times for decryption. It also has a high resistance to brute-force attack because two keys were used in the encryption process; however, it encrypts only selected parts of the data, which is considered a risk factor for a security breach. Also, in spite of the new features which have been achieved in their paper, there is still a lack of security analysis, which could have helped to prove its strength.

### 11.2.1.*Security and information protection*

1.Every wireless LAN implementation within UCSF must be done in accordance with a security plan. This plan must address the following issues at least:

1.Make sure that only authorized people can use it.

2.Prevent unauthorized users from being able to see confidential data appearing on the network, particularly UCSF passwords (Silver, 2017).

2.The Security Incident Response should include a wireless security response procedure.

3.Vendor default settings such as encryption keys and SNMP passwords must be changed regularly.

4.Wireless access point owners and managers are responsible for updating software.

5.Wireless networks which provide access to the UCSF campus network must limit usage to authorized users (Silver, 2017).

1.As of July 1st 2010 this option is mandatory for wireless networks comprised of three (3) or more access points.

2.As of July 1st 2010 this option is restricted to wireless networks comprised of two (2) or fewer access points.

3.Legacy host-based authorization systems utilizing the machine address code (MAC) may continue to be used until June 30th 2010. In the interim it is strongly recommended that the vpn@UCSF system be used to protect the communications of the wireless network user.

6.Encryption and Data Protection:

1.WPA2/AES-CCMP as defined by 802.11i is strongly recommended for departments that deal with highly sensitive information such as patient and HR/staff information. WPA2/AES-CCMP provides a higher degree of encryption protection for sensitive data being transmitted wirelessly.

2.WPA and WPA2 (RSN) as defined by 802.11i are the standard protocols for UCSF wireless security.

3.WEP on existing wireless access points must be updated to WPA or phased out by June 1, 2010. In the interim it is strongly recommended that the vpn@UCSF system be used to protect the communications of the access point users.

7.Wireless networks which do not support encryption and authentication:

1.Until June 30th 2010 it is strongly recommended that the vpn@UCSF system be utilized to protect communications to provide user authentication as well as data protection.

2.Starting July 1st, 2010 unencrypted wireless networks must restrict user access to the following:

1.Informational pages regarding network access, local service or customer support and helpdesk.

2.Access to vpn@UCSF or an ITS-approved authentication portal.

3.Access to a specific system or service for which the wireless network has been created so long as that system or service contains no restricted or private data.
