
•Professional User: A professional user is one with experience and advanced security knowledge and expertise, commonly considered to be at a senior level or higher. Moreover, they are highly trusted and require the usage of personal devices in the workplace and at home. This is because they are likely to be sent to meetings with stakeholders and other organisations to establish partnerships, and meetings can be held at places where networks are not trusted by security experts. They use VPNs and cloud services to access confidential information.

•Guest User: A guest user is the new user in the network. Their devices do not have access to the corporate network. Organisations must also consider the configuration of guest wireless networks used only for web browsing purposes. These should have strong access controls, which can be established by rules at access points and proxies to prevent the leakage of network information that can expose the organisation.

## Layer 2 — Application Security

This layer provides strong security for mobile devices such as smartphones through monitoring carried out by enterprise applications which assist the user in securing their devices. The application used for this purpose is the MDM, which has three main functions — control, monitoring and protection. Its main server can be configured and accessed from this application. The installation of the MDM allows for the implementation of various kinds of device control such as locking down, creating an SSL connection to the server, remote wipe, siren, data backup and policy enforcement on mobile devices. MAM is used to control specific applications on the device. It should be applied to control customised applications developed for the organisation, and should include patch management to correct coding bugs encountered by vulnerability testers and software developers. Furthermore, these customised applications must be developed properly to ensure GDPR compliance. To this end, the user must accept the terms and conditions set out by the application, which includes giving the application consent to run on their mobile device and accepting their responsibilities as a user. A good example of this is the use of cookies on websites. This is done in the name of regulatory compliance. MIM is the most important application, to be used when handling sensitive information. The installation of this application must be enforced mainly for professional users who have higher privileges within the organisation. The application must be implemented in smartphones, tablets and PDAs. In addition, customised applications should be developed with strong authentication mechanisms to validate legitimate users. The use of two-factor authentication, i.e., the generation of random tokens with every new session to avoid session hijacking, is suggested (Eslahi `*et al`., 2014).

There should be external encryption software installed to protect data from external storage media. This is because, when a user installs an application from a marketplace, the application generally asks for permission to access some features in mobile devices such as:

•Account details

•Application information

•Phone calls

•Camera, gallery

•Network communication

•Location

•Storage

•Messaging

•Synchronization settings

•System Tools

•Bookmarks and web browsing history

The abovementioned features and credentials are sensitive, and when some applications request access to this information, the device is made more vulnerable to attackers as it becomes easier for details of the devices to be exposed and leaked. The MDM should monitor and restrict the application being installed and label it as a high-risk application if it requests access to lots of sensitive information. This is because the application could contain malware, or devices could be used to form a botnet for further attacks, or data could be used for information theft and privilege escalation within a corporate network. Therefore, MDM must warn the user before they install a high-risk application on their mobile devices.

## Layer 3 — Device Security

Most organisations leave device-level security to the owner and the manufacturer of the device. Previously, device-level security policies included the certificate authority, data encryption and multiuser and rooting events. Nowadays, every smartphone comes with preloaded trusted CAs, and the removal of one can result in the user working online in untrusted networks. If a digital certificate is hacked, the chances of accessing the device is higher, and if the organisation is using the same certificate, the attacker can gain access to critical systems. Therefore, the device must monitor the CA credentials. The latest smartphones come with inbuilt encryption applications, ciphering data such as accounts, settings and applications. Moreover, some smartphones make it possible to encrypt the SD card inserted. In countries like Australia, USA and the UK rooting is considered legal, hence organisations must prevent the usage of rooted devices in a BYOD environment.

## Information Governance Framework

It is a legal requirement for organisations to implement an efficient and effective agreement for information governance. These requirements are set out in the Information Governance Framework.

Organisations adopting BYOD environments are the data controllers for the personal and confidential data under their custody. Therefore, they have a legal responsibility to comply with the information governance requirements associated with this design. To ensure their accountability regarding information governance, organisations should consider that professional users must have access to a range of core support services. The elements of the framework are detailed below:

•`Core Element 1 — IG policy support`: Must be in place for the production and maintenance of local IG policies and procedures. Provides advice and support on the approval, ratification and adoption of IG policies by organisations. These must include policies on confidentiality, consent procedures for the use of personal data, responsibilities and requirements, human rights with regard to privacy, information security (paper records, access control for computer systems, mobile computing risk management), incident management and reporting, staff training and needs assessments.

•`Core Element 2 — IG Consultancy and Support` — Advice and support by phone and/or email on IG issues, including operational processes and new business initiatives. Advice and guidance about access and laws (including GDPR advice for regulatory compliance).

•`Core Element 3 — IG Training` — Training staff regarding IG, which includes the development and provision of training materials to support IG as required and communication methodologies to enhance teamwork and better relationships between stakeholders, customers, employees and third-party providers so as to achieve personal data security.

•`Core Element 4 — Compliance Support` — Advice and guidance for IG compliance. When following the IG framework, compliance support allows organisations to ensure internal and regulatory compliance, including compliance with the new GDPR.

•`Core Element 5 — Incident Management and Investigations` — Advice and support during the investigation of possible cyber security incidents and data breaches. Advising on incident assessment and reporting the incident to regulatory authorities (e.g., ICO in the UK). The reporting should be done by the CISO, the DPO and the involved personnel. Advice on postincident reviews and actions taken to protect the organisation’s and individual’s rights.
