
-   [规则1]最初是为了隐私保护，所有提交者只能在系统中查看自己，这限制了当前用户的访问权限。动态情况意味着，当接收者成为对象的新看护者时，会获得新的特权，例如接收者现在可以与他人交换该物品。与关系型数据库不同，区块链不强制执行引用完整性，因此可以将物品交换给不存在的接收者。为了防止这种情况，交易代码会检查两项内容：i) 当前参与者是否是该物品的看护者；以及 ii) 接收者是否存在于参与者登记册中。第二项检查总是会失败，因为规则1仅允许当前参与者查看自己，因此当请求访问参与者登记册时，只有当前用户被包含在内。因此，即使接收者存在，规则1也会阻止其被识别，交换将在规则下被拒绝（在规则下，提交者可以将物品与自己交换）。

-   访问控制规则的冲突解决通常需要进行，以确保某些事务能够正确完成。这是一种不寻常的安全妥协，可能会创造漏洞。当用户访问系统时，通常不允许其他用户拥有读取特权。

-   由于访问控制模型存在动态过程的问题，所有可能性仍需在区块链应用的设计中考虑。这里我们选择使用流程图，并通过提供单一角色的示例来展示访问控制。

-   流程图常被视为简化的，但许多流程图用于提出标准操作程序（SOP），例如 Mitchell *et al*. (2018)，它们可以提供一系列按顺序执行的指令。当然，这种简化方法也有很多批评；然而，这里的目标是为系统中识别的每个事务提供事件序列。通常，这会在 UML 中通过序列图来识别；然而，这会产生误导，因为方法和数据并未封装在类中。在物理实现中，它们是分离的。

### 10.4.4.*Operational Logic*

[Figure 10.2](#chapter10.xhtml#fig10.2) 识别了四项事务，下面将逐一详细讨论。

**Adding a New Investigation:** 只有经理才能添加新调查。^([1](#chapter10.xhtml#fn_1)) 经理不能代他人添加新调查，因此当前参与者必须是经理，并且只能将自己作为新调查的经理添加。最终，调查 ID 必须唯一，只有在满足此条件后，区块链才能被更新。该过程在左侧的流程图 [Fig. 10.4](#chapter10.xhtml#fig10.4) 中以单个区块链更新为例，展示了整个过程结束前的唯一更新。

![image](images/fig10.4.jpg)

**Fig. 10.4.**左侧为添加新调查的流程图，右侧为向 FRT 添加人员的流程图。

在添加调查 ID 的过程中，系统会检查该 ID 是否已存在。这种数据完整性检查在大多数数据建模技术中不常见，因为通常假设此类项目会由系统通过 referential integrity（如 RDBMS 提供的引用完整性）进行验证。Hyperledger 会进行此检查，但需要记住，区块链上的数据本身只是数据，控制这些数据的过程、函数和方法是由设计者提供的业务逻辑驱动并存储在其他地方。因此，流程图 [Fig. 10.4](#chapter10.xhtml#fig10.4) 的最后一步会访问所有调查资产登记册并搜索 ID 是否唯一。在 Hyperledger 实现中，由于每个调查资产都唯一且不可重复地标识，从而防止了重复调查的出现。这里强调的是数据与方法的分离，而非面向对象或关系数据库的设计方式。

**Adding a Member of Staff to the FRT:** 同样，只有调查的经理才能向 FRT 添加人员。此处的访问控制更具动态性，只有调查的经理才能执行更新，这防止经理通过中介更新 FRT，并将权限与责任相挂钩。由于区块链上的信息一旦写入即不可更改，务必确保准确无误。经理登录后，需提供调查 ID 和人员 ID 来添加人员。首先检查该经理是否是该调查的经理。其次检查所选人员是否存在且具备资格。如果第一步和第二步均通过，则区块链被更新。最后，第二阶段可以重复多次以添加更多人员。更新不是批量进行的，每个新增的人员都会单独写入区块链，而不是等待批量模式。区块链在最早的时机更新，而不是留待批量处理，即信息不会在一段时间后一次性写入。该过程在 [Fig. 10.4](#chapter10.xhtml#fig10.4) 的流程图中展示，其中包含多次对区块链的更新，直到过程结束。访问是动态的，取决于用户类型和成员身份。

与“Adding a New Investigation”子章节类似，系统会检查当前用户是否为经理。用户 ID 会与访问控制列表中的 ID 进行比对。被标记为经理的条目拥有对区块链上调查资产的读取、写入和更新特权。由于缺乏引用完整性，需要额外检查该人员 ID 是否在相应登记册中存在。随后对调查资产和区块链进行更新。随后可以重复此过程以添加更多 FRT 成员。每个区块链都有一个唯一的交易代码。提交者的 ID、时间戳和唯一交易代码用于在后续审计中识别该交易。
