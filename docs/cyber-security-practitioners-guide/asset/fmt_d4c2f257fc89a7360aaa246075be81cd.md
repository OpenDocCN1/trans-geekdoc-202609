
The SDFIPM was designed using a top-down approach in order to enable DFPs to gain a better insight into its compositional components, namely Processes, Phases and Sub-Phases. The model consists of seven Processes, each of which contains a different number of Phases. Each Process provides additional lower layers of details, i.e. Phases and Sub-Phases. ### 9.4.1.*Examination process*

During this Process, a large number of techniques should be used to access, find and extract the potential digital evidence into a humanreadable format (Montasari, 2016a; Montasari, 2016b; Kohn *et al*., 2013). The Survey Digital Crime Scene Phase enables DFPs to find apparent pieces of digital evidence for a particular category of crime in a swift manner. It also assists them in ascertaining the skill level of the suspect, which in turn will allow them to decide what examination and analysis techniques are required in the next process of the SDFIPM, the Analysis Process (discussed later). DFPs must survey the digital crime scene to locate potential evidence, possibly within unconventional locations on the system (Montasari and Peltola, 2015). It is preferable to perform this Phase in a digital forensic laboratory (DFL), using the image (working copy) of the system acquired during the Acquisition Process \[8\], as it provides a controlled environment and the results can be repeated with another copy of the system. In cases where DFPs might need to perform this phase also on a live system, they must conduct field searches (Montasari, 2016a; Montasari, 2016d) by booting the system into what Carrier and Spafford (2003) call a “trusted environment”. DFPs must adapt their investigative techniques based on the specific category of crime to expedite the subsequent Analysis activities as there is often a large volume of data to deal with. For instance, in cases involving server intrusions, DFPs should search for apparent signs of a rootkit installation, examine application logs and also search for new configuration files. Another example (Carrier and Spafford, 2003) concerns analysing network traffic to learn more about an incident; the Survey Digital Crime Scene Phase might analyse traffic for the incident time frame and filter out certain ports and hosts. In other cases, as suggested in Montasari and Peltola (2015), the investigators should also analyse the “common” and “uncommon” locations on the system that might contain artefacts related to the suspect’s browsing activities. Unallocated file system space must also be extracted and processed for deleted files, and a low-level timeline of file activity should be examined to trace the user’s activities. Often, there are large volumes of data to be examined (Kohn *et al*., 2013; Ciardhuáin, 2004), and automated techniques should be employed using tools such as FTK (AccessData, 2018) or EnCase (Guidance Software, 2018) in order to support the investigators. Furthermore, a large number of techniques might be performed to process the obfuscated data. For instance, deleted or hidden data can be processed by utilising sound digital forensic methods, as File Allocation tables or disk indexing might be deleted in some investigations. Therefore, this Phase will enable DFPs to ensure that files that have been partially deleted are recognized from the original evidence. DFPs can also reverse-engineer suspicious executables and examine encrypted files (Carrier and Spafford, 2003). It might also be necessary for DFPs to examine the contents of every cluster (physical search) or every file (logical search) (Casey, 2011).

After all data including partially discovered files and folders have been made visible, data then needs to be harvested by giving a logical structure to the entire data set. The file and folder structure should be indexed to provide structure to acquired data. Raw data will be shown as information, and the partially deleted files which were processed during the Examine Acquired Data Phase will become visible to the degree that they were rendered visible. The result of the Harvest Data Phase is the production of a logical structured data set (Kohn *et al*., 2013) where the extracted raw data has now become structured information (Kohn *et al*., 2013; Cohen, 2009). Therefore, the harvested information can now be displayed by the original file systems such as FAT or NTFS. The data examined during the course of a DFI can be very large and therefore must be reduced to expedite the Examination Process. Identifying known elements can enable DFPs to reduce data. Metadata and unique identifiers such as MD5 must be used to remove known system files and other application data (Casey, 2011; Cohen, 2009; Beebe and Clark, 2005). The data that remains will be modified data or data that could be uniquely attributed to the users of a specific computer system. This will result in the identification of the potential digital evidence from data that has been examined, harvested and reduced. DFPs should also group together digital evidence with similar identifying patterns by focusing on the incident type. Digital evidence also needs to be restructured so that the investigation can be conducted more appropriately. If similar types of incidents or crimes have taken place in the past and are known to DFPs, they should then use the known classification in order to compare the current digital forensic data to the similar past incidents or crimes. The output of the Examination Process becomes the input to the Analysis Process, discussed in the following subsection.
