
In a Command and Control attack, a staging server under the control of the attacker is used to mount the attack. This means that any tracing done on the target network will lead to the compromised system that is the staging server. The staging server might be controlled over the TOR network, thus protecting the anonymity of the attacker. An alternative approach that allows an attacker to protect their identity is `ngrok` (ngrok, 2018), a free utility available from GitHub which allows the attack to be proxied via ngrok’s server using a temporary URL (Hackersgrid, 2018). `ngrok` was developed as an educational tool to assist students to run web servers on the internet even though they might be behind routers and firewalls because students might not be able to configure port forwarding on the routers they use and might not want to pay for dynamic Domain Name System (DNS) services. The use of ngrok as a hacking tool is therefore not its intended use. `ngrok` can be purchased, which gives permanent URLs, or used for free, which has the limitation that the URL changes with each use. However, when attackers use the free version of ngrok, there is no payment trail to disclose the attacker.

The `ChessMaster` cyber espionage campaign (Hsieh and Kohei, 2017) is partly based on a technique that can be demonstrated with the use of `Koadic` (Takhion, 2018). `Koadic` (available from zerosum0x0’s github page) is a Command and Control tool built for educational purposes. It is like the `Metasploit` and `Empire` frameworks except that it exploits a Microsoft Windows JavaScript engine, `mstha.exe`, rather than using a payload. A user just needs to be persuaded to click on a web page link to launch the attack. These attacks work by creating a reverse proxy from the victim back to the attacker and could in practice use common ports like port 80 (HTTP) or 53 (DNS) which might be open to provide internet access.

### 1.2.5.*Phishing emails*

Phishing emails are often regarded as spam, but the difference is that they are generally targeted and have malicious links to code on external websites. By clicking on one a user might be doing no more than effectively confirming their email address.

By looking at the yearly reports from Symantec and Sophos it is seen that spear-phishing attacks are currently the most common attack vector. According to Symantec:

“*If you’re going to be attacked, the chances are that initial compromise, the gap in the fence the attackers sneak through, is going to be created by social engineering rather than anything technically sophisticated such as exploit of a zero-day vulnerability. Spear-phishing emails are the number one means of attack we’ve seen used, meaning a well-crafted email, sent to an unsuspecting staff member is the most likely source of compromise and can be the trigger to a potentially serious security breach.*” (Symantec, 2018) 74% of attacks involved phishing emails (Symantec, 2018, p. 76).

From Trustwave’s 2017 Security Report, targeted spear phishing attacks are the most common method to gain initial access (Trustwave, 2018).

To be successful in duping a victim, the emails used for the attacks must be convincing. This level of detail in spear-phishing emails, i.e. the use of familiar names, logos and style, is now becoming commonplace. Vigilance, the verification of email instructions by other means and good email filtering is paramount.

### 1.2.6.*Documents with embedded code and other attachments*

According to the Sophos Annual Report 2018 the two most common Office exploits in 2017 were CVE-2012-0158 and CVE-2017-0199 (Sophos, 2018). CVE-2012-0158 is the most exploited document vulnerability going back to 2012. Though patched it remains a popular exploit. This is a buffer overflow vulnerability in the ListView/TreeView ActiveX controls in the MSCOMCTL.OCX library (Janus, 2013). The CVE-2017-0199 vulnerability is exploited by malicious code that can be triggered by a specially crafted DOC or RTF file for Microsoft Office versions 2003, 2007 and 2010 (Jiang, 2017). This vulnerability allows a malicious actor to download and execute a Visual Basic script containing PowerShell commands when a user opens a document containing an embedded exploit.

### 1.2.7.*Business Email Compromise*

With so many email systems having web interfaces, improper use of webmail is not surprising, and the threat of Business Email Compromise (BEC) can easily be understood. The attack vector might be a link in an email, which leads a user to a clone website asking a user to change their password. The email looks legitimate and the website the user is directed to is a perfect clone of a web email service provider’s website. Another scam is an email that requests users to log on and upgrade storage quotas (Ragan, 2017). Having gained access to a user’s email, an attacker can gather information and look for an opportunity to intercept a future large transaction. An attacker will subsequently advise new bank details in relation to a payment at precisely the time the payment is expected. The sophistication can be extreme, and the sums defrauded in this way can be large. These attacks are targeted, customised and now extremely common. They are known as Business Email Compromise (BEC) and according to the FBI Internet Crime Complaint Center, BEC has been a bigger issue than ransomware since 2016 (FBI IC3, 2018). The FBI is therefore now tracking BEC as a single crime type (FBI IC3, 2017). The attack vector could be a shared computer in a hotel lobby that is set to record passwords.

### 1.2.8.*Emerging threats: Knock-Knock and Office 365*

Artificial Intelligence (AI) is seen as the concept that will make all our lives easier, although it can also be used as an attack tool. The Knock-Knock attack against Microsoft Office 365 servers is an example of this. Having determined an organisation to target, a company’s email domain name is easily deduced from a company’s website. The company’s web site is then trawled for employee names, and the internet is searched for email addresses related to the company. Once one is found then the format of all others in the company is deduced. One of the flaws of Office365 is that the usernames are generally the email addresses. AI is used to try each email address with just two passwords, then move on to the next email address, which is how the attack gets its name. The attacking machine then goes to sleep or performs an attack on another company. It then returns and tries the email addresses again with another two passwords, then goes to sleep again and so on. Eventually an account is cracked, and a user’s email is downloaded, which gives the attacker knowledge of everything a user is doing, including access to their calendar. Office365 accounts can be protected by the implementation of the Enterprise Security and Mobility Suite as this can be set to only allow registered devices to connect.

### 1.3.Exfiltration Methods

There are a couple of comprehensive reviews of data exfiltration methods, one published by Ullah *et al.* (2017), the other by Rashid *et al.* (2017); however, many of the methods discussed in Ullah *et al.* and Rashid *et al.* assume that an attacker has the necessary access rights to install malware. As mentioned earlier, locking down access rights, patching systems, restricting the ports that are enabled on firewalls and keeping antivirus systems up to date are normal practices on corporate networks, so this study will be limited to only the methods possible on such a system.
