
-   [`62443-4-1`]和`2`均于`2018`年2月和8月分别发表，尽管`62443-4-1`已被BSI采用，`62443-4-2`仍未被采用。

`62443-2-1`定义了网络安全管理体系（CSMS）的要求，尽管其在第一段中使用了不同的术语，BSI（2010）将`62443-2-1`的输出指向`27001`，而`62443`的CSMS则将信息安全三要素（保密性、可用性、完整性）倒置并以安全性为前提，变为安全性、可用性、完整性和保密性，以体现工业环境中网络安全的HSE影响。正如`27001`一样，它要求实施风险管理和审查流程，以支持CSMS的生命周期。

`27001`与`62443`在方法上的根本差异在`62443-3-3`中表现得更为明显（尽管部分内容计划纳入`62443-1-1`，因为标准不断演进），该部分描述了安全向量的使用，该术语归功于Gilsinn和Schierholz（2010）。SL（安全级别）与SIL（安全完整性级别）相类比，后者在`61508`及其相关标准（包括`61511`）中使用。

SL在`62443`风险评估过程中确定；作为网络隔离控制的一部分，IACS网络被划分为区域，每个区域包含要求相同保护水平的系统组件。根据区域所需的保护水平，向区域分配SL-T（目标安全级别）：

- SL 0：无特定要求或安全保护，无需额外保护
- SL 1：防范偶然或巧合性违规
- SL 2：防范使用简单手段、资源有限、技能通用且动机低的有意违规
- SL 3：防范使用高级手段、资源适中、IACS特定技能且动机适中的有意违规
- SL 4：防范使用高级手段、资源充足、IACS特定技能且动机高的有意违规

每个系统组件随后根据标准定义的安全要求评估其SL-C（安全级别能力）。如果SL-C大于或等于区域的SL-T，则无需进一步控制；若SL-C低于SL-T，则需正式接受剩余风险或实施进一步控制。在同一区域内，系统可能具有混合的SL-C值，此时必须针对较低的SL-C值进行处理以实现SL-T。

为验证，系统可进行检查、审计或安全测试，由检查人员确定SL-A（实际服务级别）。风险通过这三个值——ST-T、SL-C和SL-A——进行管理。

`62443-2-1`旨在使SL最终成为对系统或其部分组件的安全问题的定量解决方案。这似乎是一个长期愿景，预计在标准更广泛采用、数据充分积累后才能实现。它还旨在提供可重复的模型，适用于设备和对策。

`50129`定义的安全风险分析过程关注安全危害及其发生频率，而非安全威胁。它探讨失败的后果（事故、接近事故或“安全失败”），并判断结果在安全方面是否可接受。它使用SIL作为“一种将消除系统性失败的定性方法与控制随机失败的定量方法相结合的手段”，因为无法量化系统性失败（(BSI, 2003) 50129）。系统性失败是系统生命周期中人为错误引入的，通过过程（如质量管理）加以管理；随机失败源于硬件组件的可靠性，可从已知故障率计算并表示为THR（可容忍危害率）。SIL所表示的安全级别要求是过程与可接受THR的结合。

采用SL并假设其与SIL相似可能产生误导，因为两者在本质上有所不同。正如Braband（2016）所倡导的，应用于SIL的概率方法并不适用于SL及IT安全，因为无法依赖统计数据或经验，威胁环境可能瞬间且毫无预警地发生变化。

Braband和Schäbe（2016）深入探讨了安全与安全风险评估的相似性与差异，指出安全与安全的风险评估过程高度相似，逻辑上应分别采用相同的过程。他们指出，国际安全标准中的安全风险评估基于“概率”，而安全风险评估基于“可能性”。ISO（2009）分别定义这两个词：“概率是指事件发生的可能性，以0到1的数值表示，0代表不可能，1代表绝对确定”，以及“可能性是指事件发生的可能性”。安全标准基于这样的概念：危险失败在时间上可能发生，且其发生概率可以被测量。失败可能是系统性的或随机的；随机失败的发生可以计算，而系统性失败则有公认的对策集，普遍被行业接受。可能性则更不精确，更依赖主观判断。安全之所以更具客观性，是因为安全环境变化缓慢，且可以从历史经验中学习；而安全领域变化迅速，常在信息技术领域观察到新漏洞的出现和威胁环境的变化。NCSC的警报和通告页面（NCSC, 2018b）提供了一个典型例子：

国家行为体可能是最有能力和资源的攻击者，这可能导致任何潜在目标的SL-T要求提升至SL 4，以给其提供抵御攻击的可能性。

Kriaa *et al.*（2015）持相同观点，认为安全危害随时间变化较稳定，分析员对以往事故的反馈可靠，而安全属性则较难预测。这种情况使得安全分析师更难以评估和量化潜在场景。可以看到，定量方法在安全领域更为普遍，但在安全学科中尚未被广泛接受。
