
A data encryption algorithm would not be of much use if it is secure but slow in performance, especially because it is a common practice to embed encryption algorithms in other applications such as e-commerce, banking, and online transaction processing applications (Nadeem and Javed, 2005). The wireless device is limited in resources such as processing power, memory and power supply (from a battery). Battery technology is improving at a slower rate than other technologies. This causes a “battery gap”. This indicates that mobile devices normally operate on an economical power budget, and therefore, computationally intensive encryption/decryption algorithms and their related security parameters may not be supported. The key issue is that the processing in encryption algorithms consumes remarkable amounts of computing resources. This leads to battery power draining fast. That is the problem for mobile devices (Jiehong and Detchenkov, 2016). We also note that there are several applications such as wireless sensor networks in which the battery power limitation is extreme and recharging or changing drained batteries may be impossible.

Furthermore, there is a relationship between security and the power consumption. For instance, a higher number of rounds in AES encryption processes produces higher levels of security at the cost of additional power consumption. [Figure 11.3](#chapter11.xhtml#fig11.3) shows a general trend in the trade-off between vulnerability and power consumption with varying numbers of encryption rounds. Therefore, in order to design power-efficient encryption algorithms for wireless networks there is an `inherent need to understand the relationships between power consumption and encryption parameters`. Only then is it possible to optimize power consumption with respect to a security requirement.

Traditional cryptography deals generally with ensuring the security of the encrypted data. Several designs focus on security objectives while neglecting the QoS requirement. One main point is that the crypto-algorithms based on these designs usually do not account for physical constraints such as limited battery power (Chandramouli *et al*., 2006). It may not be possible to support a security requirement given the power budget. Then, the key questions are twofold: how does one optimize crypto-parameters for a given power budget? Therefore, the primary challenge in providing security in low-power mobile wireless devices lies in the conflicting aims of minimizing power consumption and maximizing security. In general, we can safely assume that by doing more computations one can achieve a higher amount of security.

Many previous studies have addressed the issue of energy consumption in encryption processes. Khan *et al*. (2017) proposed a mechanism to reduce the cost of network coding by reducing the size of the data used for permutation. The basic idea is that the source permutes only global encoding vectors (GEVs) without permuting all the symbols in the message. This would significantly reduce the complexity and transmission cost over the network. Also, they suggest an algorithm for key generation and random permutation confusion key calculation. The proposed scheme achieves better performance in throughput, encryption time, and energy consumption. Zhang and Lin (2014), introduced a permutation coding scheme, called P Coding, which is a lightweight encryption method.

Also, there are some hardware solutions to address the high power consumption in encryption processing. However, Hamalainen *et al*. (2006) declare that a loop-unrolled and pipelined hardware implies a large area and high power consumption. Furthermore, these architectures cannot be fully exploited in feedback modes of operation. The hardware implementation has many limitations as well. Bansod *et al*. (2015) stated that the standard algorithms such as DES & AES have vast memory requirements and it would not be possible to implement them in the embedded system. So many research studies tried to use lightweight encryption algorithms such as PRESENT which should be more efficient in devices connected to wireless networks. However, there are many claims by other authors which suggest that these algorithms are weak against cryptanalysis (Lee, 2014; Faghihi *et al*., 2015) Several full-round attacks using biclique cryptanalysis have been introduced on PRESENT. According to Ramesh and Umarani (2012), “The last performance comparison point is the changing different key sizes for AES and UR5. In case of AES, we consider the three different key sizes possible, i.e., 128 bit, 192 bit and 256 bit keys. The simulation results are shown in Figure…. In the case of AES it can be seen that higher key size leads to clear change in the battery and time consumption. It can be seen that going from a 128 bit key to a 192 bit key causes an increase in power and time consumption of about 9% and going to a 256 bit key causes an increase of 17%. Also in the case of UR5, we consider the three different key sizes possible i.e., 128 bit, 192 bit and 256 bit keys.” The encryption and decryption processes consume a significant amount of computing resources such as CPU time, throughput, and battery power (Jiehong and Detchenkov, 2016; Ramesh and Umarani, 2012). [Figure 11.4](#chapter11.xhtml#fig11.4), for instance, shows the time taken to encrypt different images.

These research studies have addressed some issues regarding wireless networks; however there are still some clear gaps in their research. For example, the proposed mechanism to reduce the cost of the network may not provide sufficient security. As only part of the message will be encrypted, this might affect the security level. Researchers have tried modifying the transmission protocol using AES encryption, but they have not tried to modify the AES algorithm itself to make it cost-effective. For these reasons we are going to develop the current AES algorithm to make it cost-effective by keeping its power consumption low and its security at a high level.

### 11.5.4.*Current state of security*

Security for a mobile environment today is much like it was in the early days of laptops. There is a sea of emerging mobile security solutions from both startups and more established software companies; we’ve published articles about several of these solutions on SandHill.com in the past few months. Organizations are trying to sort through the hype and figure out which products to use.

As companies learned over the years with laptops and desktops, a good mobile security strategy should be comprised of multiple solutions to provide in-depth security for the mobile device.

### 11.5.5.Secure access to applications

The security and management strategies for supporting a BYOD policy include an access-only approach to applications. This tactic prevents employees from downloading and storing any information on their mobile devices.

In addition, most of the CIOs we interviewed said their companies were looking at ways to separate corporate and personal data by implementing “container” structures on the devices. There are now several software companies with products enabling containment.

A `virtual desktop` is another structure which is used to contain information. This strategy eliminates the need for a BYOD policy and reduces device support costs while maintaining security and control. Currently software vendors such as `VMware` and `Citrix` and others are making virtual desktops more secure and therefore more organizations are following this strategy.
