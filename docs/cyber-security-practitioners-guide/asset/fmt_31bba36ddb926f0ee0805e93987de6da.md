### 10.5.3.*Seizure*

[Figure 10.8](#chapter10.xhtml#fig10.8) shows the data stored in the asset registry on the blockchain for the investigation assets after the completion of the seizure of all the artefacts.

[Figure 10.9](#chapter10.xhtml#fig10.9) indicates an individual seizure transaction (lines 1-16) and the resulting entry in the artefact asset registry (lines 17-26). This may raise some concern amongst readers since there is no time or date in the investigation registry or the artefact. However, [Fig. 10.9](#chapter10.xhtml#fig10.9) does not show the full picture; the blockchain is updated with each individual seizure, and only the individual records and not the transactions are viewed in the Investigation and Artefact Registry. Further explanation is required.

![image](images/fig10.8.jpg)

**Fig. 10.8.**The investigation asset registry for the item with Investigation ID ‘C222’. Note that all custodians are members of the FRT. This changes when exchanges occur. Nevertheless, when a seizure transaction is made, only members of the appropriate FRT can be custodians of artefacts. Some artefacts have been removed to improve clarity.

In the seizure transaction in [Fig. 10.9](#chapter10.xhtml#fig10.9) (line 11) the custodian is identified with the PIN code ‘0950’. This does not match the committed code in the final output and furthermore the person identified by the code does not exist as a person in the system. This is not a mistake. The user is logged in via their business network card, which is issued by the system and uniquely identifies them. In this particular case the business network card is for ‘S23’, identified by ‘P111113’. It is these values that are passed to the asset registries. If ‘P111113’ is a member of the FRT (clearly seen from [Fig. 10.8](#chapter10.xhtml#fig10.8), lines 8-9), then the update occurs to both registries. This explains the difference between the information in Figs. 10.8 and 10.9. Users cannot seize artefacts on behalf of other users.

![image](images/fig10.9.jpg)

**Fig. 10.9.**Individual seizure transaction and corresponding artefact.

[Figure 10.9](#chapter10.xhtml#fig10.9) does show when the transaction was committed to the blockchain. In the example, line 15 shows that the artefact ‘1636’ was seized at ‘2018-09-04T10:03:05.455Z’. So, all the information about the seizure of this item can be retrieved for internal or external audits. Simple generic queries can be set up to recall and organise all artefacts seized for an investigation.

There is also the issue of integration of systems across LEAs. [Figure 10.8](#chapter10.xhtml#fig10.8) (lines 18-24) shows an example whereby an external person is included in the FRT and demonstrates that they are able to seize artefacts, as shown by person ‘P211112’ submitting artefact ‘4695’. Auditors can have read access to the blockchain and they can retrieve such queries.
