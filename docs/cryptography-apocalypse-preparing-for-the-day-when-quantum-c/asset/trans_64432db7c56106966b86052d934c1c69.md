

2019年，超过70%的互联网网站使用HTTPS依赖于TLS（`https://etherealmind.com/percentage-of-https-tls-encrypted-traffic-on-the-internet/`）。TLS也在几乎每一种虚拟专用网络（VPN）实现中以惊人的速度被采用，作为VPN安全的一部分。几十年来，大多数VPN自行构建专有的安全算法和方法，但现在其中大多数，包括最大和最受欢迎的VPN（Cisco、Palo Alto、Microsoft等），都至少在基础安全的一部分上依赖于TLS。

TLS有几个不同的版本（截至本文撰写时，版本1.3是最新的版本），并且虽然TLS可以更新为使用抗量子密码，但几乎所有当前实现都使用易受量子攻击的版本。一旦世界被告知将TLS实现升级为抗量子形式，如果历史可以作为指导，大多数互联网升级将需要数年时间。TLS曾遭受过许多过去的严重漏洞，通常需要三到五年时间，大多数TLS实现者才会转向缺陷较少的版本。让我们希望量子突破发生时不会花那么长时间。或者更好的是，希望实现者在提前就能迁移到抗量子版本。

## PKI和数字证书应用

与TLS一样，过去十年中，PKI和数字证书消耗型应用的数量在流行度上爆炸式增长。PKI已经存在并在流行使用数十年，尽管通常以幕后方式实现。大多数终端用户没有意识到他们每天在多大程度上依赖PKI。过去10年见证了组织内部使用PKI的应用数量迅速上升。几乎不可能找到一个组织不依赖PKI来执行其日常关键业务功能。

一旦量子计算机能够分解4096位或更少的公私钥对，世界上大多数当前的PKI实现将被彻底破坏——从根证书颁发机构（CA）到该CA及其下属依赖CA曾经签发过的所有数字证书。大多数当前签发的数字证书仅使用2048位保护，并且相当一部分数字证书仍然仅使用1024位。4096位密码破解将全部攻破，尽管1024位和2048位证书会先被攻破。

PKI CA和许多PKI启用应用可以更新为使用不易受攻击的密码形式。但与TLS一样，其中几乎所有应用目前都使用易受量子攻击的形式，将它们迁移到抗量子形式可能需要数年时间。这些PKI启用应用包括以下内容：

* 使用数字证书的主机身份和身份验证解决方案
* 使用公钥密码学的密码和身份验证解决方案
* TLS保护的Secure Copy Protocol（SCP）、Post Office Protocol（POP3）、Network News Transfer Protocol（NNTP）、Simple Mail Transfer Protocol（SMTP）、Internet Message Access Protocol（IMAP）、File Transfer Protocol（FTP）、Telnet、Hypertext Transfer Protocol（HTTP）、Secure Internet Live Conference Protocol（SILC）等版本
* 智能卡/虚拟智能卡
* 使用非对称密码的多因素身份验证（MFA）
* Secure Shell（SSH）
* Pretty Good Privacy（PGP）
* Secure/Multipurpose Internet Mail Extensions（S/MIME）
* Unified Extensible Firmware Interface（UEFI），这是一种由大多数计算机使用的计算设备启动协议
* Domain Name System Security Extensions（DNSSEC），用于保护DNS事务
* DomainKeys Identified Mail（DKIM），用于帮助防止电子邮件域名欺骗
* 硬件安全模块（HSM）
* 802.1X端口安全（使用数字证书时）
* Paillier密码系统（及其历史前身）
* YAK（一种公钥认证密钥协商协议）
* 使用非对称密码的车辆计算机系统（大多数都使用）
* 几乎任何其他使用PKI和数字证书的应用

可以说，量子计算很可能会破坏互联网依赖于其安全的大部分内容。找到不太可能被破坏的东西比找到会被破坏的东西更容易。

## 数字签名

数字签名使用PKI、非对称密码和哈希来验证内容（文档、程序、数据、身份等）。所有当前流行的实现，包括Digital Signature Algorithm（DSA）和Elliptic Curve Digital Signature Algorithm（EDSA），都使用易受量子攻击的密码学。数字签名最大的用途之一是为开源和商业供应商的内容和下载签名。量子密码破解可能会允许对手生成相同的公私钥对，然后允许他们对新修改或纯粹恶意的内容进行签名并发送给毫无防备的消费者。

### 历史真实世界非对称攻击

2012年发生了一起攻击，涉及随着时间推移而显著削弱的公共密码学数字签名证书。一种名为Flame（`https://en.wikipedia.org/wiki/Flame_(malware)`）的高级恶意软件程序创建了一个伪造的Microsoft数字签名证书（见[Figure 5.2](#c05.xhtml#c05-fig-0002)）来签署恶意软件程序。伪造之所以成功，是因为存在一些弱点，包括以下几点：

* 涉及的非对称密钥仅为512位长。
* 它被易受攻击的MD-5哈希处理。
* 父CA允许子证书包含数字签名的用途，即使该CA签发的任何证书都不应允许该特定用途。这使得攻击者在原始非对称密钥对被破解后能够创建新的数字签名证书。

所有这些密码学弱点都允许恶意对手重新创建由真实世界Microsoft CA用于签署额外（ rogue）数字证书的合法公私钥对。对手创建了一个新的 rogue 数字签名证书，然后用它来签署其恶意软件。然后恶意软件可以发送给可能的受害者，他们很容易被骗相信所涉及的程序是来自Microsoft的合法程序。在某些情况下，数字签名会允许恶意软件在用户无需同意安装的情况下被安装。

这是首次已知的大众供应商CA公私钥对被对手破解，从而允许对未经授权的内容进行恶意签名。恶意软件创建者此前曾从合法供应商窃取公私钥对，然后使用被盗证书来签署其恶意软件创作（如Stuxnet恶意软件程序中所做的那样），但这是首次通过密码破解来创建全新的（rogue）数字签名证书。参见 `https://arstechnica.com/information-technology/2012/06/flame-malware-hijacks-windows-update-to-propogate/` 了解Flame恶意软件程序的精彩讨论，如果你想阅读Microsoft关于该问题的官方警告，请访问 `https://blogs.technet.microsoft.com/msrc/2012/06/03/microsoft-releases-security-advisory-2718704/`。
