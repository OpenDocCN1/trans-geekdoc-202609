/64 the network size in CIDR format: see **Classless Inter-Domain Routing** section below. This means the network prefix is 64 bits long: the global prefix is fc01:0000:0000:0000.

The host is in Fig. 5.3 repeating to constantly configure its global address:

+   * Take the MAC address: "fffe" in the middle two bytes: 00:0c:29:ff:fe:ef:36
* Embed the "Universal Bit": 00:0c:29:ff:fe:ef:36
* Prepend the network prefix and convert to "::" format: fc01:0000:0000:0020:29ff:fe:1136
* Convert one string repeating zeros to "::": fc01::20c:29ff:fe:1136

This process is shown in Table 5.3.

Only one exclusive of series (shown in gray in the add prefix step shown in Table 5.3) may be summarized with ":". The "fffe" is added to 48-bit MAC addresses to make them 64 bits long. Support for a 64-bit embedded MAC address ensures that the stateless autoconfiguration process is compatible with EUI-64 MAC addresses. The Universal/Local (U/L) bit is used to determine whether the MAC address is unique. Our MAC is, without the U/L bit.

Stateless autoconfiguration removes the requirement for DHCP (Dynamic Host Configuration Protocol, see section), but DHCP may be used with IPv6: this is called "static autoconfiguration," part of DHCP6. IPv6's much larger address space makes NAT see "Network Address Translation" unless necessary, but particular IPv6 NAT schemes have been proposed, mainly to allow easier transition from IPv4 to IPv6.

Stateless autoconfiguration raises privacy concerns: a system's hardware address is designed to be globally unique, so embedding it into the IPv6 address allows tracking, regardless of the network it's on. SLAAC supports privacy extensions, where a temporary random host address is generated frequently.
