# ICMP

ICMP is the Internet Control Protocol, a helper protocol that helps Layer 3 (IP, see note). ICMP is used to troubleshoot and report error conditions: Without ICMP to help, IP would fail when faced with routing loops, ports, hosts, or networks, etc., that are down. ICMP has no concept of ports, as TCP and UDP do, but instead uses types and codes. Commonly used ICMP types are echo request and echo reply (using ping) and time to leave exceeded in transit (traceroute).

# Note

> "Which protocol runs at layer 4?” is often a subject of fierce debate. We call this the “bucket game.” For example, which bucket does ICMP go into: Layer 3 or Layer 4? ICMP headers are at Layer 4, just like TCP and UDP, so many will answer “Layer 4.” Others argue ICMP is a Layer 3 protocol, since it assists IP (a Layer 3 protocol), and has no ports.

This shows how arbitrary the bucket game is: a packet capture shows the ICMP header at Layer 4, so many network engineers will want “Layer 4” never agree with a packet. The same argument exists for many routing protocols; for example, BGP is used to route at Layer 3, but BGP is carried by TCP (IP). This book will clear-cut bucket game protocol/layers in the text and tests, but avoid murky examples (just as the exam should).

# Ping

Ping (named after sonar used to “ping” submarines) sends an ICMP Echo Request to a node and listens for an ICMP Echo Reply. Ping was designed to determine whether a node is up or down.
