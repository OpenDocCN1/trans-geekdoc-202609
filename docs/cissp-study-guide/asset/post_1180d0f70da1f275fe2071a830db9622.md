## Routers

Routers are Layer 3 devices that route traffic from one LAN to another. IP-based routers make decisions based on the source and destination IP addresses.

> Note
> In the real world, chassis, such as a Cisco 6500, can be many devices at once: a router, a switch, a firewall, a NIDS. The exam is likely to give more-clear examples: a firewall, a dedicated switch, or if the exam references a multifunction device, that will be made clear.
> Regardless, it is helpful to know how to think of these devices as distinct concepts.

## Static and Default Routes

For simple routing needs, static routes may suffice. Static routes are fixed routing entries, saying “The route for network 10.0.0.0/8 routes via router 192.168.2.7; the route for network 172.168.0.0/12 routes via router 192.168.2.8.” Most SOHO (Small/Home/Office Network) routers have a “default route” that sends all external traffic to (typically controlled by the ISP). Here is an example of a typical home LAN configuration:

- Internal network: 192.168.1.0/24
- Internal Firewall IP: 192.168.1.1
- External Network: 192.0.2.0/30
- External Firewall IP: 192.168.1.2
- Next hop address: 192.168.1.1

The firewall has an internal and external interface, with IP addresses of 192.168.1.1 and 192.0.2.2, respectively. Internal (trusted) hosts receive addresses on 192.168.1.0/24 subnet via DHCP. External traffic is translated to the external firewall IP of 192.0.2.2. The default route for internal hosts is 192.168.1.1. The default route is 192.0.2.1. This is a router owned by the ISP.

Routing protocols come in two basic varieties: Interior Gateway Protocols (IGPs), like RIP and OSPF, and Exterior Gateway Protocols (EGPs), like BGP. Private networks use Intranets and EGPs are used on public networks like the Internet. Routing protocols support Layer 3 (Network) of the OSI model.

## Distance Vector Routing Protocols

Metrics are used to determine the “best” route across a network. The simplest metric is hop count. In Fig. 5.21, the hop count from the data center to each office via T3 is 1. Additional paths are available from the data center to each office, such as the T3 to Office B, followed by T1 to A. The latter route is two hops, and the second hop is a slower T1. Any network engineer would prefer the single-hop T3 connection from the data center to Office A instead of the two-hop detour via Office B. And all routing protocols would do the same, choosing the one-hop T3. Things get trickier when you consider connections between the offices. Should traffic route from Office A to B? The shortest hop count is the direct T1. But if link only has 1.5 megabits: taking the two-hop route from Office A down to the data center and back up to B offers 45 megabits at the expense of an extra hop. A distance vector routing protocol as RIP would choose the direct T1 connection and consider one hop at 1.5 megabits “faster” than two hops at 45 megabits. Most Engineers (and all Link state routing, as described in the next section) would disagree. Distance vector protocols use metrics such as hop count, and are prone to routing loops, which loop between routers. ## RIP

RIP (Routing Information Protocol) is a distance vector routing protocol that uses hop count as its metric. RIP will route traffic from Office A to Office B in Fig. 5.2 via T3.

Convergence means that all routers on a network agree on the state of routing. A network that has no outages is “converged”: all routers see routes as available. Then a circuit goes down; routers that are further away know one is down. A goal of routing protocols is to make convergence as fast as possible. The goals of routing protocols are to automatically learn a network topology and learn the best routes quickly. Ideally this should happen while engineers are asleep.

RIP’s maximum hop count is 15; 16 is considered “infinite.” RIP added support for CIDR. RIP loses a down timer to avoid “flapping” (repeatedly changing a route’s status from “down” to up). Once RIP changes a route’s status to “down,” RIP will “hold” to that decision for 180 seconds. The hope is that the network will have convergence during that time. If not, after 180 seconds, RIP may change its status.

Split horizon means a router will not send routing information back out the interface it learned it from. This prevents routing loops. Poison reverse is an extension of split horizon where the router sends the route back with an unreachable metric (16). This speeds up convergence when a link fails.

RIP is used in small networks because it is simple to configure. However, for larger networks, link state protocols like OSPF or exterior gateway protocols like BGP are preferred because they converge faster and support more complex topologies.
