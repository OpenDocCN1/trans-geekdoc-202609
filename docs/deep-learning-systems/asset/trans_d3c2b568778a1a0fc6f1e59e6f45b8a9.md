
# 训练与服务系统
训练系统旨在在不牺牲精度的情况下减少训练时间。服务或推理系统旨在在延迟要求约束下最大化吞吐量。产品推荐、搜索结果、语音助手查询以及自动驾驶汽车中的行人识别都需要实时（低延迟）结果。通常，仅使用一个数据样本或一个微批次来满足特定应用的延迟要求。鉴于从内存读取的每个字节对应的计算量更少，GPU 和 CPU 在服务时的运算强度或计算效率低于训练时。

## 命名法
命名说明：在本书中，batch（文献中有时称为 `mini-batch`）指的是从 1 到整个数据集的训练样本子集。`full-batch` 指由整个训练数据集组成的批次。`micro-batch` 指包含 1–8 个样本的批次。`large-batch` 指批次大小大于 1,000 个样本但小于整个训练数据集。`node-batch` 指分布式训练中在单个节点上处理的批次，详见 [第5章](#15_Chapter05.xhtml)。

在本节剩余部分，我们介绍 `NNs` 的一些组件，并使用一个简单示例描述训练过程。训练和服务模型的主要计算操作是乘法和加法，通常以组形式计算并表示为矩阵。

## 训练过程
一旦拓扑结构定义完成，训练就涉及学习一组良好的权重值。监督学习的训练步骤通常如下：

### 监督学习步骤
1. 通常通过从零均值高斯分布或均匀分布中采样来初始化模型的权重或参数。
2. 将训练样本或更常见的一批样本前向传播通过网络以计算输出。
3. 使用预期输出（由训练标签已知）与实际输出之间的差异度量来评估成本或惩罚。
4. 将成本相对于各层权重和激活的梯度反向传播。
5. 使用计算得到的梯度更新模型的权重。
6. 返回步骤 2，或在验证误差小于某个阈值或不再下降时停止。

### 迭代与轮次
在训练期间，数据集以批次形式处理。对一批样本完成步骤 2–6 的一个循环称为 `iteration`，而对整个训练数据集完成一个循环称为 `epoch`。例如，如果数据集有 `1*M` 个样本，而批次有 100 个样本，则完成一个 epoch 需要 `10*K` 次迭代。

训练模型可能需要数十个 epoch 才能学习到一组良好的权重。训练后，使用验证数据集测量验证（也称为样本外）性能。验证数据集包含训练期间未使用且已标记的数据，应尽可能与模型部署时遇到的服务数据相似。该验证数据集上的性能是部署性能的良好指标，有助于判断模型是否对训练数据集过拟合。过拟合发生在模型学习到训练数据特有的特征时，因此无法泛化到训练数据集之外的数据。用于缓解过拟合的正则化技术在 [第4.1节](#14_Chapter04.xhtml#sub4-1) 中讨论。

## 服务 / 推理
在服务期间，模型处理一个微批次。数据通过网络前向传播以计算输出。服务也称为推理，因为模型正在推断数据样本的标签。上述步骤 2 即为推理；也就是说，推理是训练过程中的一个步骤，但通常使用更小的批次大小并采用一些特定于服务的优化。

## 示例：MNIST 手写数字分类
以下示例说明了训练过程。任务是使用 `MLP` 模型 \[LBB+98\] 对 MNIST 数据集中的手写数字进行分类。[图1.13](#11_Chapter01.xhtml#fig1-13) 显示了 MNIST 数据集中 70,000 张灰度 28 × 28 像素图像的一个小子集。通常使用 MNIST 时，60,000 张图像用于训练，10,000 张图像用于验证。实际上，`CNN` 模型更适合图像分类，但这里使用简单的 `MLP` 模型来介绍一些基本概念。

`MLP` 中的每一层由单元（神经元）组成，这些单元将来自前一层的加权输出或激活与偏置权重线性组合，如 [图1.14](#11_Chapter01.xhtml#fig1-14) 所示的一个单元。该仿射变换的输出传递给非线性激活函数 `g(·)`。`activation function` 指非线性函数，`activation input` 是激活函数的输入，而 `activation`（`activation output` 的简称）指激活函数的输出。常见的激活函数有修正线性单元 (`ReLU`) 及其变体、`sigmoid` 及其泛化 `softmax`，以及双曲正切 (`tanh`)，这些都详细说明在 [第2.1节](#12_Chapter02.xhtml#sub2-1) 中。
