### HIDS 和 HIPS

基于主机的入侵检测系统（HIDS）和基于主机的入侵防御系统（HIPS）是 NIDS 和 NIPS 的基于主机的对应物。它们处理主机内部的信息。它们可能会在网络流量进入主机时进行处理，但考试的重点通常在于文件和进程。

一个著名的 HIDS 是开源 Tripwire®，在该公司扩展其商业产品之前，它仅被称为 Tripwire（参见 [https://github.com/Tripwire/tripwire-open-source](https://github.com/Tripwire/tripwire-open-source)）。开源 Tripwire® 通过检测关键操作系统文件的变更来保护系统完整性。变更通过多种方法进行检测，包括加密哈希的比较。

### 模式匹配

模式匹配 IDS 通过将事件与静态特征码进行比较来工作。关于前面提到的 Log4Shell 漏洞，Crowdstrike 指出：“可以通过检查日志文件中是否存在特征 URL 模式 `${jndi:ldap://` 来检测利用尝试” [\[7\]](#Ch008_361-457_B9780443187346000064_2.xhtml#bb0040)。基于该信息，可以使用以下模式来检测此类尝试性的 Log4Shell Log4j2 利用。如果字符串 `${jndi:ldap://` 出现在发往组织 Web 服务器的流量中：警报。

模式匹配非常适合检测已知攻击，但通常在面对新攻击时表现不佳。

### 协议行为

协议行为 IDS 对协议应有的工作方式建模，通常通过分析 RFC（征求意见稿）来实现。RFC 793（TCP，参见 [https://datatracker.ietf.org/doc/html/rfc793](https://datatracker.ietf.org/doc/html/rfc793)）描述了 TCP 标志。SYN 表示同步，FIN 表示结束。一个标志用于创建连接，另一个用于终止连接。

基于对 RFC 793 的分析，生成的协议行为规则可以是“如果单个数据包中同时设置了 SYN/FIN 标志：警报。”根据 RFC，单个段尝试同时开始和结束连接是讲不通的。

攻击者会构造此类“损坏”的段，因此协议行为确实能检测到恶意流量。问题在于汉隆剃刀，这是一条格言，内容为：“永远不要将恶意归因于那些用愚蠢即可充分解释的事物” [\[8\]](#Ch008_361-457_B9780443187346000064_2.xhtml#bb0045)。协议行为还会检测“愚蠢的”（损坏的）流量：由未阅读或遵循 RFC 的开发人员设计的应用程序产生的流量。这相当常见：应用程序“能用”（流量流动），但违背了 RFC 的初衷。

> **注意**
>
> 所有信息安全专业人员都应理解汉隆剃刀。我们的世界充满了恶意：蠕虫、网络钓鱼攻击、身份盗窃等。但愚蠢和破坏更多：大多数灾难都是由用户错误引起的。

### 异常检测

异常检测 IDS 通过建立正常流量的基线来工作。异常检测 IDS 随后忽略该流量，报告不符合基线的流量。

与模式匹配不同，异常检测可以检测新攻击。挑战在于建立“正常”的基线：这在小型可预测的网络上通常很简单，但在大型复杂的网络上可能非常困难（甚至不可能）。

## 出站监控

历史上，对入侵和对手活动的检测主要专注于进入我们更受信任的内部网络的攻击流量；入侵检测系统（IDS）天然契合这一范式。出站监控采取相反的方法，专注于通过监视离开我们网络的内容来进行检测。许多利用后活动，包括命令与控制（C2）和数据渗漏，自然必然会导致可能通过监控流出我们网络的流量来辨别的流量模式。利用出站监控成功检测对手的一个经典示例是，通过观察源自预期内部邮件服务器以外的系统且目标为 TCP 25 端口的流量，识别出发送垃圾邮件的受感染主机。

## 安全信息和事件管理

入侵检测系统（IDS）长期以来一直是组织使用的主要技术侦查控制手段。尽管 IDS 的重要性并未减弱，但组织现在认识到，除了 IDS 之外，更多数据源可以提供有价值的信息。这些不同的信息源可以提供各自有价值的数据；组织越来越看重能够更高效地关联来自多个来源的数据。

安全信息和事件管理（SIEM）是用于简化跨不同来源数据关联的主要工具。关联安全相关数据是 SIEM 提供的主要效用。数据关联的目标是更好地理解背景，从而因跨各种安全平台记录的活动而更深入地了解组织内部的风险。虽然 SIEM 通常带有一些内置警报，用于查找特定的关联数据，但可以创建自定义关联规则以增强内置功能。

要想通过数据关联成功获取情报，必然意味着能够访问多个数据源。虽然 SIEM 的威胁检测用例可能是可行的，但关联所需的数据收集量可能巨大。由于大多数 SIEM 中整合的数据量很大，因此 SIEM 通常还有与更轻松或更好地证明合规性相关的用例。

## 用户和实体行为分析（UEBA）

入侵合法最终用户系统和账户是对手的常见目标。即使是权限最小的用户账户，拥有的访问权限也比外部对手大得多。虽然对手在必要时会利用漏洞，但几乎每次入侵的一个共同主题都是对手滥用合法用户。尽管检测漏洞利用似乎相当困难，但从历史上看，这一挑战与检测对手利用合法用户账户攻击我们自己的信息系统相比，简直相形见绌。用户和实体行为分析（UEBA）专门致力于解决识别来自我们“受信任”用户或系统的可疑活动这一问题。

UEBA 试图辨别组织内用户和系统的正常行为配置文件，然后主动提醒我们偏离预期行为模式的可疑偏差。虽然概念简单，但多年来这种行为分析方法已被证明是一个艰巨的挑战。然而，随着对面向最终用户系统的可见性水平提高，以及数据科学和机器学习在安全领域的应用，这些系统已有了巨大改进。
