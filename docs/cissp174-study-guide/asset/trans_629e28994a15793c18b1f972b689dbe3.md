

# 访问供应生命周期

一旦选择并部署了适当的访问控制模型，就必须维护并保障访问供应生命周期的安全。虽然许多组织遵循授予访问权限的最佳实践，但许多组织缺乏正式流程，以确保在员工和承包商在组织内部流动时，访问权限的整个生命周期始终保持安全。身份与访问生命周期包含诸如身份注册与审核、定义逻辑角色、安全地供应和取消供应账户及访问权限等考量因素。限制账户及其关联访问权限暴露的操作控制也同样相关，包括访问评审、即时供应和权限提升机制等组件。

始终将账户撤销作为访问供应生命周期中的必需步骤。此流程应与人力资源部门紧密协调，不仅要跟踪离职情况，还要跟踪组织内部的横向和纵向调动或晋升。此外，如前所述，不活跃账户应作为撤销目标。

## 注册、审核与身份建立

当考虑对个人进行审核和验证时，许多安全专业人员在思维上会直接跳到认证环节，但逻辑上的前置步骤涉及一个健壮的身份识别组件流程。简单来说，在我们能够认证某个个体之前，我们需要实际了解并收集与该个体相关的信息。为此，在信息系统中建立身份涉及身份注册和审核的过程。

注册（也可称为入册）涉及在系统中请求或申请身份，并提供系统所需的、允许唯一识别的信息。一旦提供了必要的识别属性，就需要对这些属性进行验证。审核涉及对注册/入册过程中提供的属性进行验证和确证。将审核明确作为一个单独流程提出的原因之一，是因为某些场景在身份验证过程中会利用第三方处理器。身份审核验证过程的范围，与大多数事物一样，由风险管理原则决定。

## 角色定义

组织及其信息系统会定期发生变化。随着组织内部新职能的定义，显然也将需要以定义角色的形式来表达这些职能的访问控制要求。然而，即使员工继续从事同一份工作，其职能随时间推移也可能发生重大变化。工作性质的变化同样可能导致访问控制系统中需要新的角色定义。前文讨论的基于角色的访问控制（RBAC）和利用角色作为属性的基于属性的访问控制实现的有效性，取决于定义清晰且被充分理解的角色。

## 供应与取消供应

CISSP® 指南中常见的一个主题是适当管理资产整个生命周期内的安全。供应和取消供应这两个术语进一步凸显了这一重点。供应是指将资产带入运行状态的过程，有时称为投入生产。必须在供应前考虑安全性，以确保该过程以足够的严谨性处理，且不会对已认定可接受的安全态势产生负面影响。

不可避免地，资产不再需要保持运行状态的时刻终将到来。取消供应是指将资产安全地从生产环境中移除的过程。这一过程同样需要从安全角度进行考量。虽然供应/取消供应仅代表可适用于任何资产的通用过程，但这些术语更常见于用户账户、系统和应用程序的讨论中。自然，与 IAM（身份与访问管理）最相关的考量是与用户供应/取消供应相关的安全性。在对用户进行供应/取消供应时，或许最关键的考量是与访问控制相关的问题。

显然，供应在雇佣新员工时相关，取消供应在员工随后离职时相关，但当员工在组织内发生重大角色变更时，也应给予应有的考量。理想情况下，如果员工的角色性质发生实质性变化，则应取消供应其初始访问权限，并重新供应其现在所需的访问权限。然而在现实中，完整地走完取消供应和供应流程可能过于繁琐。尽管如此，仍应极力避免员工仅不断积累越来越多的访问权限，而不撤销不必要的访问权限这一常见情况。

## 即时访问（JIT）

虽然“即时”（JIT）一词在商业界已使用多年，但其在信息安全领域的应用则近得多。访问控制领域的即时现象，与传统的、典型的永久性和持续性访问形成鲜明对比，在 JIT 视角中，后者被称为“常驻访问”。在 JIT 访问中，需要注意在可用性与安全性之间取得适当平衡。如果 JIT 访问工作流变得过于繁琐，往往会产生恢复常驻访问范式的愿望。

设想一个经典场景：员工入职，其账户被供应了组织预期该员工所需的所有权利和权限。其中一些权限会每天使用，而另一些可能很少用到。特别是在那些不常用但具有重大安全影响的访问权限场景中，可能存在实施 JIT 访问的机会。采用 JIT 可能涉及这样一个流程：当员工需要利用该不常用但敏感的访问权限时，必须启动一个审批流程，以允许提供临时访问权限。

JIT 不仅涉及按需向用户提供特权，还涉及用户和系统供应以及远程访问。JIT 远程访问的一个示例是：仅在需要访问时临时开放远程访问端口（例如 `TCP/3389`），而不是让该服务始终可访问、从而始终处于攻击之下。JIT 账户供应涉及仅在明确需要时创建账户，然后在所需账户及其关联访问权限被使用后自动取消供应该账户。

## 账户访问评审

无论在访问控制管理中投入了多少关怀和严谨，必然会出现过度授权的情况，即提供了超出严格必要范围的访问权限。虽然应用程序可能因权限不足而中断、员工可能会抱怨，但因账户被提供过多访问权限而引发的抱怨会少得多。定期访问评审可作为控制多余访问的一种手段。

虽然理论上审慎的做法是审查每个主体和对象的所有访问权限，但这样做极其繁琐。通常应采用基于风险的方法，优先审查高权限账户、重要交易或服务、敏感数据以及关键系统和应用程序。
