
# 组合软件测试

**组合软件测试**是一种黑盒测试方法，旨在识别并测试软件输入的所有唯一组合。组合软件测试的一个示例是**成对测试**（也称为**全对测试**）。

NIST 提供了以下成对测试示例（参见 [http://csrc.nist.gov/groups/SNS/acts/documents/kuhn-kacker-lei-hunter09.pdf](http://csrc.nist.gov/groups/SNS/acts/documents/kuhn-kacker-lei-hunter09.pdf)）：“假设我们要演示一个新的软件应用程序能在使用 Windows 或 Linux 操作系统、Intel 或 AMD 处理器以及 IPv4 或 IPv6 协议的 PC 上正确运行。这总共是 2 × 2 × 2 = 8 种可能性，但正如[表 7.1](#Ch007_337-359_B978044318734600009X.xhtml#t0010)所示，只需四个测试即可测试每个组件与其他每个组件之间至少一次的交互。在这种最基本的组合方法（称为成对测试）中，这四个测试中的至少一个涵盖了三个参数中所有可能的值对（t = 2）” [[8]](#Ch007_337-359_B978044318734600009X.xhtml#bb0045)。

## 表 7.1：NIST 成对测试示例 [[8]](#Ch007_337-359_B978044318734600009X.xhtml#bb0045)

| --- | --- | --- | --- |

| 2 | Windows | AMD | IPv6 |
| 3 | Linux | Intel | IPv6 |
| 4 | Linux | AMD | IPv4 |

## 误用用例测试

合成事务旨在模拟正常行为；误用用例测试旨在模拟异常用户行为。应用程序的用例详细说明了各种功能将如何在应用程序中被利用。正式用例通常构建为流程图，使用**UML**（统一建模语言）编写，旨在帮助建模预期的行为和功能。

误用用例测试的思路是正式建模（同样很可能使用**UML**），对手如何通过滥用应用程序来实现安全影响。这可以简单地视为一种不同类型的用例，但专门提出误用用例测试的原因是为了突显普遍缺乏对针对应用程序的攻击的考虑。

## 测试覆盖率分析

测试或代码覆盖率分析旨在确定已测试的应用程序百分比。目标是确保不存在重大缺口，即缺乏测试可能导致本应被发现的缺陷或安全问题遗留存在。

## 接口测试

应用程序内的传统接口测试主要关注适当的功能是否通过用户与应用程序交互的所有方式暴露出来。从安全导向的角度来看，目标是确保安全性在各种接口上得到统一应用。实际上，这种类型的测试考虑了对手可能利用的各种潜在攻击向量。

一个简化的示例可能是一个 Web 应用程序，当客户端具备该能力时使用 Adobe Flash，但会向缺乏 Adobe Flash 支持的客户端呈现替代视图。如果测试仅使用内置 Flash 支持的桌面浏览器执行，则可能会遗漏呈现给 iPhone 的移动版应用程序中存在的安全缺陷。虽然接口测试不仅限于桌面与移动浏览器的对比，但该概念仍然适用。无论人或机器以何种方式与代码交互，应用程序的安全需求都必须得到实施。

## 分析和报告测试输出

积累大量安全测试结果很容易；但根据这些结果修复发现的问题则困难得多。一个例子是组织几乎持续不断地执行漏洞扫描。然而，仅生成该报告并无法改善现状。生成安全测试数据是必要的第一步，但不足以改善未来的测试结果。

待分析的数据量可能惊人，但应采用某种方法来确定优先审查和处理某些结果而非其他结果的顺序。与安全领域的许多事物一样，分诊的方法应基于对风险的理解。想象一下，完全相同的缺陷或漏洞存在于组织中的每个系统上。与每个漏洞相关的风险会相同吗？不，当然不会。即使完全相同的缺陷存在，风险也可能因系统或数据的关键性、对手利用每个缺陷表现形式的可能性等因素而截然不同。

组织应已拥有大量针对业务资产的机密性、完整性和可用性关注点的数据。这些数据应用于指导安全测试输出的分析。视风险数据的易用程度而定，一些基本的优先级排序和分析可能可以自动化。其他数据最初至少需要人工审查，但应尽可能以有助于更好地实现未来测试数据审查自动化的方式进行记录。

必须建立管理例外的正式流程。遗留系统是一个常见示例。它们通常缺乏现代控制，且通常被漏洞扫描软件视为关键风险。用现代、安全的系统替换所有遗留系统是显而易见的选择，但预算限制可能使其在短期内不可能实现。在这种情况下，应使用补偿控制（如额外的防火墙、物理隔离、应用程序白名单和额外的监控）。在这种情况下，应要求系统或数据所有者书面接受风险。

# 收集安全流程数据

组织需要收集支持其安全流程和控制日常有效性的数据。待提出的问题包括：账户管理的运营效果如何，备份能否恢复，以及能否及时恢复？请注意，收集灾难恢复规划（**DRP**）和业务连续性规划（**BCP**）数据也是此过程的一部分。我们将在第 8 章（[Chapter 8](#Ch008_361-457_B9780443187346000064_1.xhtml)），领域 7：安全运营中讨论 **DRP** 和 **BCP**。
