

# 业务连续性计划与灾难恢复计划

区分业务连续性计划（BCP）与灾难恢复计划（DRP）的一种方法在于认识到：BCP 关注的是业务关键职能或服务的提供，而非通常用于执行这些职能的系统。虽然在当今普遍以系统为中心的组织中，这似乎只是一个学术上的区别，但请考虑电子邮件在大多数组织中所扮演的角色。虽然大多数技术人员会认为电子邮件属于业务关键范畴，但许多组织仍可在没有电子邮件的情况下继续运营，尽管过程会很痛苦。DRP 肯定会将电子邮件系统纳入考量，但 BCP 可能不那么关注电子邮件本身，而更关注通过其他通信方式为客户提供服务。理解这一区别对组织至关重要，因为它最终将有助于指导诸如 `Maximum Tolerable Downtime (MTD)`（最大可容忍停机时间）等考量因素，而后者又将作为输入，用于确定如何分配资源和设计恢复策略。

## 灾难或破坏性事件

鉴于组织制定业务连续性计划和灾难恢复计划是因为灾难可能影响运营，因此理解灾难和破坏性事件是必要的。在考虑 BCP 和 DRP 时，最直观浮现的破坏性事件类型是自然灾害，如飓风、龙卷风、地震和洪水。虽然这些代表了某些类型的灾难，但它们远非唯一类型，甚至不是最常见的破坏性事件类型。

对可能发生的灾难类型进行分类的一种方法是按成因归类。灾难成因的三种常见分类方式是：威胁源是自然的、人为的，还是环境的 [\[12\]](#Ch008_361-457_B9780443187346000064_2.xhtml#bb0065)。

### 自然

最明显的可导致灾难的威胁是自然发生的。此类别包括地震、飓风、龙卷风、洪水和某些类型的火灾等威胁。历史上，自然灾害造成了组织不得不应对的最毁灭性灾难之一。然而，自然灾害发生的频率通常低于其他类别的威胁。自然威胁发生的可能性通常与地理位置密切相关。

### 人为

人为威胁类别代表了灾难最常见的来源。人为威胁可进一步按其是故意威胁还是非故意威胁进行分类。人为故意攻击指人类蓄意发动的、有动机的攻击。人为非故意攻击是指某人无意中充当了威胁源。例如，攻击者试图在组织内植入恶意软件以窃取持卡人数据，这属于人为故意威胁；员工因懒惰或疏忽大意导致运营中断，则属于人为非故意威胁。虽然人为故意威胁在威胁建模中可能更引人注目，但人为非故意威胁才是灾难最常见的来源。人为故意威胁的例子包括恐怖分子、恶意软件、内部叛徒、拒绝服务攻击、黑客行动主义、网络钓鱼和社会工程学。人为非故意威胁主要涉及无心的错误和遗漏，即人员因缺乏知识、懒惰或疏忽大意而成为破坏源。

### 环境

“环境威胁”这一名称容易引起混淆，让人联想到天气相关现象。在此语境下，环境威胁与天气关系不大（天气属于自然威胁），而是关注与信息系统或数据中心相关的环境。计算环境中断的威胁非常显著。此类威胁包括电力问题（停电、电压不足、电压浪涌、尖峰脉冲）、系统组件或其他设备故障，以及应用程序或软件缺陷。

> **注意**
>
> 技术威胁是另一类威胁。技术威胁可视为人为威胁的一个子集，但因其对信息安全的重要性，有时会被单独列出。技术威胁的常见例子包括恶意软件、拒绝服务攻击、网络战、网络恐怖主义、黑客行动主义、网络钓鱼和 DNS 劫持。这些威胁通过 `Cyber Incident Response Plan`（网络安全事件响应计划）进行缓解。

威胁分析及确定威胁实现的相关可能性，是 BCP 和 DRP 流程的重要组成部分。对威胁的认识将有助于指导组织采取的潜在风险缓解或规避策略。此外，威胁分析将有助于为恢复和响应能力的规划及优先级排定提供指导。为了能够执行这些威胁分析，需要对威胁类型有更详细的了解。[表 8.2](#Ch008_361-457_B9780443187346000064_1.xhtml#t0015) 简要汇总了部分灾难事件及其所属的灾难类型。

### 错误和遗漏

错误和遗漏通常被认为是破坏性事件的单一最常见来源。人类，通常是组织雇员，无意中导致此类威胁。数据录入错误就是错误和遗漏的一个例子。这些错误可能给组织造成高昂代价，在投入生产前可能需要人工审查，这便是职责分离的一个例子。

> **注意**
>
> 虽然错误和遗漏是组织面临的最常见威胁，但它们也代表了最容易避免的威胁类型。如果组织能确定特别常见或特别具有破坏性的特定错误或遗漏类型，通常就能建立控制措施来帮助降低该威胁实现的风险。组织将降低其对特别重大错误或遗漏的脆弱性。

### 自然灾害

自然灾害包括地震、飓风、洪水和海啸。为了在 BCP 和 DRP 中制定适当的响应和恢复策略，需要了解自然灾害发生的可能性。自然威胁发生的可能性主要取决于组织信息系统或数据中心的地理位置。自然灾害发生的可能性通常较低。然而，一旦发生，影响可能非常严重。有关这些风险的更多信息以及具体的缓解策略，请参见[第 4 章](#Ch004_107-223_B9780443187346000076_1.xhtml)，领域 3：安全架构与工程。
