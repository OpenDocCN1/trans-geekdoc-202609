

# 微服务

微服务在降低成本的同时，提供了额外的扩展机会。服务器在历史上是单体式的：一台服务器提供一系列服务。以上面的玩具公司为例，每台服务器可能提供一系列服务：身份验证、库存、搜索、购物车、信用卡验证、配送等。微服务通过 API（应用程序编程接口）将这些服务拆分出来，并使用容器和无服务器等技术来提供所需功能。Amazon 对微服务的描述如下：

> 采用单体架构时，所有进程都紧密耦合并作为单个服务运行。这意味着，如果应用程序的某个进程遇到需求激增，则必须扩展整个架构。随着代码库的增长，添加或改进单体应用程序的功能变得更加复杂。这种复杂性限制了实验，并使实施新想法变得困难。单体架构增加了应用程序可用性的风险，因为许多依赖且紧密耦合的进程增加了单个进程故障的影响。

> 采用微服务架构时，应用程序作为独立组件构建，每个应用程序进程作为一个服务运行。这些服务通过定义良好的接口使用轻量级 API 进行通信。服务是为业务能力而构建的，每个服务执行单一功能。因为它们是独立运行的，所以每个服务都可以更新、部署和扩展，以满足应用程序特定功能的需求 [\[18\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0095)。

## 容器

容器是一项（相对）较老但持续改进的技术。它们源自 BSD 的“chroot”（更改根目录）功能，该功能将进程锁定在一个目录中。该进程（如 Bind 域名服务器守护进程）只能访问其目录中的文件，而无法访问目录外部的文件。例如：如果 Bind 被 chroot 到 `/var/bind`，它就无法读取该目录及其子目录（如 `/var/bind/conf`）之外的任何内容。这样做是为了将受损服务对操作系统其余部分的风险降至最低：例如，无法访问 `/etc/passwd` 和 `/etc/shadow` 等文件。

BSD jails（BSD 监狱）建立在 chroot 概念之上，同时也隔离了网络：例如，每个 jail 都有自己的 IP 地址。同一系统上需要传输数据的两个 jail 需要通过网络进行通信。

BSD 操作系统称此概念为 jail，而 Linux 使用术语 container（容器）。Docker 是最流行的容器技术之一，专注于大规模编排。Docker 对容器的描述如下：

> 容器是一种标准的软件单元，它将代码及其所有依赖项打包在一起，以便应用程序能够从一个计算环境快速可靠地运行到另一个计算环境。Docker 容器镜像是一种轻量级、独立、可执行的软件包，包含运行应用程序所需的一切：代码、运行时、系统工具、系统库和设置 [\[19\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0100)。

### 容器与虚拟化

您可能会想：容器与虚拟化有何不同？关键区别在于：每个虚拟系统运行自己的内核。运行三台虚拟机的管理程序意味着有四个内核在运行：一个用于管理程序，每个 VM 一个。运行三个容器的宿主系统意味着只有一个内核在运行：宿主系统的内核。每个容器也使用宿主系统的内核。这意味着容器比 VM 需要更少的资源，但也意味着它们（从安全角度来看）不如 VM 那样隔离。[图 4.17](#Ch004_107-223_B9780443187346000076_1.xhtml#f0090) 来自美国能源部阿贡国家实验室，展示了容器和虚拟机之间的区别 [\[20\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0105)。

## 无服务器

无服务器是一个容易让人误解的技术名称：它确实使用服务器，但这些服务器属于别人。“别人的服务器”是个更好的名字，尽管承认不那么朗朗上口。它也被称为函数即服务，这更准确。无服务器简单来说就是将代码发送到另一台服务器，由其返回结果。流行的无服务器技术包括 AWS（Amazon Web Services）Lambda、Azure Functions 和 Google Cloud Functions。

下面是一个简单的“Hello World!”风格的函数 [\[21\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0110)，使用 Python 和 JSON（JavaScript 对象表示法）。请注意，Python 编程和 JSON 结构不在考试范围内；此处仅用于提供无服务器代码的简单示例。

```
import json

print('Loading function')
def lambda_handler(event, context):
 print("value1 = " + event['key1'])
 print("value2 = " + event['key2'])
 print("value3 = " + event['key3'])
```

匹配的 JSON：

```
{
 "key1": "Pass",
 "key2": "the",
 "key3": "CISSP!"
}
```

我们已经在自己的 CPU 上运行此类函数几十年了。在这种情况下，函数被发送到 AWS，由 AWS 的 CPU 执行该函数并返回结果。AWS 按执行该函数所需的 CPU 周期收费。这比在物理主机或虚拟机上运行代码高效得多（物理主机或虚拟机上运行着数百个其他进程并消耗 CPU 周期），也比容器高效（容器使用的 CPU 周期比物理主机或 VM 少，但比无服务器多）。

# 高性能计算（HPC）和网格计算

高性能计算（HPC）和网格计算都旨在通过大量计算机实现高计算性能。关键区别在于：高性能计算系统（也称为超级计算机）利用单一位置的并行计算机（通常都在处理同一任务），而网格计算则利用大量分布式计算机（处理各种任务）。

HPC 系统利用海量 CPU 实现每秒千万亿次浮点运算（FLOPs）。常见的 HPC 应用包括 DNA 测序、自动驾驶、天气预测等。HPC 系统的主要目的是通过规模经济实现性能提升。HPC 系统的一个关键安全问题是确保数据完整性在整个处理过程中得以维护。HPC 系统通常会利用一定程度的共享内存进行操作。如果管理不当，这种共享内存可能会暴露潜在的竞争条件，从而引入完整性挑战。

网格计算通常利用设备当前不需要用于自身需求的闲置 CPU 周期，并将它们集中用于网格计算资源的目标。虽然来自每台单个计算机的这些少量闲置周期对整体任务可能意义不大，但汇总起来却非常可观。SETI@HOME 是网格计算的一个著名例子：它是“基于加州大学伯克利分校的一个科学实验，利用连接互联网的计算机搜寻地外文明（SETI）” [\[22\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0115)。
