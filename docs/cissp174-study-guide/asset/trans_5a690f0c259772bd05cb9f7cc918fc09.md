
# 路径 MTU 发现

路径 MTU 发现利用分片来发现网络路径上允许的最大数据包大小。发送一个设置了 `DF`（不分片）标志的大数据包。如果路由器的 MTU 小于数据包大小，它会尝试分片，发现无法分片，然后丢弃该数据包，并发送一个“需要分片但设置了 DF 标志”的 ICMP 消息。发送节点随后发送越来越小的、设置了 `DF` 标志的数据包，直到它们能干净利落地通过网络路径。

## IPv6

IPv6 是 IPv4 的继任者，具有更大的地址空间（128 位地址，而 IPv4 为 32 位）、更简单的路由和更简单的地址分配。IPv4 地址枯竭是导致 IPv6 诞生的主要因素。

自微软 Vista 操作系统发布以来，IPv6 变得更加普遍，Vista 是第一个支持 IPv6 并默认启用它的微软客户端操作系统。一直到 Windows 11 的所有版本都沿用了这一做法。其他现代操作系统，如 OS X、Linux 和 UNIX，也默认启用 IPv6。

> **注意**
>
> IPv6 地址空间为 2^128，非常大：真的非常大。总共有超过 340 穰（undecillion）个 IPv6 地址，这是一个十进制 39 位的数字：340,282,366,920,938,463,463,374,607,431,768,211,456。IPv4 只有不到 43 亿个地址，这是一个十进制 10 位的数字：4,294,967,296。如果所有 43 亿个 IPv4 地址加起来重 1 千克，那么所有 IPv6 地址将重 79,228,162,514,264,337,593,543,950,336 千克，相当于 13,263 个地球的质量。另一个有用的比较：如果所有 IPv4 地址能装进一个高尔夫球，那么所有 IPv6 地址几乎能装满太阳。

### IPv6 地址和无状态自动配置

IPv6 主机可以无状态地自动配置唯一的 IPv6 地址，从而省去了静态寻址或 DHCP 的需求。IPv6 无状态地址自动配置（SLAAC）获取主机的 MAC 地址并用其来配置 IPv6 地址。[图 5.3](#Ch005_225-293_B9780443187346000039.xhtml#f0020) 中的 `ifconfig`（接口配置）输出显示 MAC 地址为硬件地址（HWAddr）`00:0c:29:ef:11:36`。

![图 5.3 显示 MAC 地址和 IPv6 地址的“ifconfig”输出。](images/B9780443187346000039/f05-03-9780443187346.jpg)

[图 5.3](#Ch005_225-293_B9780443187346000039.xhtml#B-f0020) 显示 MAC 地址和 IPv6 地址的“ifconfig”输出。

IPv6 地址长 128 位，使用冒号而非句点来分隔段。一串连续的零可以压缩为两个冒号（`::`）。[图 5.3](#Ch005_225-293_B9780443187346000039.xhtml#f0020) 中的“ifconfig”输出显示了两个 IPv6 地址：

*   `fc01::20c:29ff:feef:1136/64`（作用域：全局）
*   `fe80::20c:29ff:feef:1136/64`（作用域：链路）

第一个地址（`fc01::…`）是“全局”（可路由）地址，用于本地网络以外的通信。IPv6 主机依赖 IPv6 路由通告来分配全局地址。在[图 5.3](#Ch005_225-293_B9780443187346000039.xhtml#f0020)中，本地路由器发送了 `fc01` 网络的路由通告，主机利用它来配置其全局地址。

第二个地址（`fe80::…`）是链路本地地址，仅用于本地网络通信。系统独立分配链路本地地址，无需 IPv6 路由器通告。即使没有任何集中式 IPv6 基础设施（如发送 IPv6 路由通告的路由器），任何 IPv6 系统也会分配一个链路本地地址，并可使用该地址与 LAN 上的其他链路本地 IPv6 地址通信。

`/64` 是 CIDR 格式的网络大小：见下文“[无类别域间路由](#Ch005_225-293_B9780443187346000039.xhtml#s0200)”一节。这意味着网络前缀长 64 位：完整的全局前缀为 `fc01:0000:0000:0000`。

[图 5.3](#Ch005_225-293_B9780443187346000039.xhtml#f0020) 中的主机使用以下过程无状态地配置其全局地址：

*   获取 MAC 地址：`00:0c:29:ef:11:36`
*   在中间两字节嵌入“fffe”常量：`00:0c:29:ff:fe:ef:11:36`
*   设置“通用位”：`02:0c:29:ff:fe:ef:11:36`
*   添加网络前缀并转换为“:”格式：`fc01:0000:0000:0000:020c:29ff:feef:1136`
*   将一串连续的零转换为“::”：`fc01::20c:29ff:feef:1136`

在[表 5.3](#Ch005_225-293_B9780443187346000039.xhtml#t0020)所示的添加前缀步骤中（灰色显示），只有一个连续的零序列可以用 `::` 来汇总。添加“fffe”常量是为了将 48 位 MAC 地址扩展为 64 位。对 64 位嵌入式 MAC 地址的支持确保了无状态自动配置过程与 EUI-64 MAC 地址兼容。通用/本地（U/L）位用于确定 MAC 地址是否唯一。我们的 MAC 地址是唯一的，因此设置了 U/L 位。

无状态自动配置消除了对 DHCP（*动态主机配置协议*，见下文“BOOTP 和 DHCP”部分）的需求，但 DHCP 可用于 IPv6：这称为“有状态自动配置”，是 DHCPv6 的一部分。IPv6 更大的地址空间也使得 NAT（见下文“[网络地址转换](#Ch005_225-293_B9780443187346000039.xhtml#s0210)”）变得没有必要，但已提出各种 IPv6 NAT 方案，主要是为了更容易地从 IPv4 过渡到 IPv6。

无状态自动配置引发了隐私担忧：系统的硬件 MAC 地址设计为全局唯一，将其嵌入 IPv6 地址允许进行跟踪，无论其位于哪个网络。SLAAC 现在支持隐私扩展，即生成临时的随机主机地址，且地址频繁变更。

请注意，系统可以是“双栈”的，同时使用 IPv4 和 IPv6，如[图 5.3](#Ch005_225-293_B9780443187346000039.xhtml#f0020)所示。该系统使用 IPv6，同时也拥有 IPv4 地址 `192.168.2.122`。主机也可能通过 IPv4 访问 IPv6 网络；这称为隧道技术。另一个值得注意的 IPv6 地址是环回地址：`::1`。这相当于 IPv4 地址 `127.0.0.1`。

### IPv6 安全挑战

IPv6 解决了许多问题，包括增加足够的地址空间和自动配置，使路由变得更简单。但其中一些解决方案（如自动配置）可能会引入安全问题。

一个启用了 IPv6 的系统将自动配置一个链路本地地址（以 `fe80:…` 开头），而无需任何其他启用 IPv6 的基础设施。该主机可以与同一 LAN 上的其他链路本地地址通信。即使管理员不知道 IPv6 正在他们的网络上流动，这也是成立的。

ISP 也在启用 IPv6 服务，有时客户并不知情。现代网络工具，如网络入侵检测系统，可以“看到” IPv6，但通常未配置为这样做。而且许多网络专业人员对 IPv6 的经验或理解有限。从攻击者的角度来看，这可能提供一个绝佳的机会，通过 IPv6 发起攻击或窃取数据。
