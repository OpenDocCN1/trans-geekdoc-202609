
CORBA 的本质不仅在于作为网络对象代理，更在于将接口（与对象通信的语法）与实例（特定对象）相分离：“每个对象的接口都有非常严格的定义。相反，对象的实现——其运行代码及其数据——被隐藏在系统的其余部分之外（即封装），位于客户端不可跨越的边界之后。客户端只能通过其公开的接口访问对象，仅能调用对象通过其 `IDL` 接口暴露的操作，且仅限于调用中包含的那些参数（输入和输出）”[\[27\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0140)。

除了通过网络定位对象外，CORBA 还强制执行基本的面向对象设计：底层细节对客户端封装（隐藏）。对象在不透露实现方式的情况下执行其方法。实现者专注于连接，而非代码。

### 面向对象分析（OOA）与面向对象设计（OOD）

**面向对象分析**（OOA）和**面向对象设计**（OOD）是软件设计方法论，它们将对象的概念提升到比面向对象编程（OOP）更高、更概念化的层面。这两个术语有时合称为面向对象分析与设计（OOAD）。

这就像在白板上绘制流程图，展示程序在概念上应如何运行。程序中数据的流动和操作方式被可视化为一系列消息和对象。软件设计完成后，代码可使用 `Ruby` 等面向对象编程语言编写。

面向对象分析（OOA）旨在理解（分析）**问题域**（你试图解决的挑战），并识别所有对象及其交互。面向对象设计（OOD）则开发（设计）解决方案。

我们将使用面向对象分析与设计来设计一个网络入侵检测系统（NIDS）。正如我们在[第 8 章](#Ch008_361-457_B9780443187346000064_1.xhtml)“领域 7：安全运营”中所学，NIDS 执行以下操作：

1.  从网络嗅探数据包并将其转换为 `pcap`（数据包捕获）格式；
2.  分析数据包中的攻击迹象，这可能包括拒绝服务、客户端攻击、服务端攻击、Web 应用攻击及其他；
3.  如果发现恶意攻击，NIDS 发送警报。NIDS 可通过电子邮件、寻呼、`syslog` 或安全信息和事件管理器（SIEM）发送警报。

上述步骤构成了我们面向对象分析的基础。嗅探器对象以数据包形式接收来自网络的消息。嗅探器将数据包转换为 `pcap`（数据包捕获）数据，并将其发送给分析对象。分析对象执行多项功能（方法），包括检测拒绝服务、客户端、服务端或 Web 应用攻击。如果检测到任何攻击，它会向警报对象发送警报消息。警报对象也可执行多项功能，包括通过电子邮件、寻呼、`syslog` 或 SIEM 进行告警。NIDS 面向对象设计如[图 9.12](#Ch009_459-508_B9780443187346000088.xhtml#f0065)所示。

## 评估软件安全的有效性

项目启动且软件编程完成后，接下来的步骤是测试软件，重点关注系统、应用程序及应用程序处理的数据的机密性、完整性和可用性。必须特别注意发现可能导致数据或系统泄露的软件漏洞。最后，组织需要能够衡量其软件创建过程的有效性，并找出改进方法。

### 软件漏洞

程序员会犯错：自计算机编程诞生以来，这始终是真理。在《代码大全》中，Steve McConnell 表示，“经验表明，每 1000 行交付代码中会有 15–50 个错误”[\[28\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0145)。一千行代码有时称为 `KLOC`；“K”代表千。遵循正式的应用成熟度框架模型可以降低这一数字。卡内基梅隆大学软件工程研究院研究员 Watts S. Humphrey 声称，遵循 SEI 能力成熟度模型集成（CMMI，见下文“[软件能力成熟度模型集成 (CMMI)](#Ch009_459-508_B9780443187346000088.xhtml#s0340)”一节）的组织，可将错误数量降低到每 `KLOC` 一个[\[29\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0150)。

即使每千行代码仅有一个错误，随着软件日益复杂，也会引入巨大的安全风险。以 Microsoft Windows 为例：“因此，Windows 的每个新版本都背负着其过去的包袱。随着 Windows 的增长，技术挑战变得日益艰巨。数千名工程师辛勤工作以构建和测试 Windows Vista，这是一个庞大、复杂的软件建设项目，拥有 5000 万行代码，比 Windows XP 大 40% 以上”[\[30\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0155)。请注意，Microsoft 尚未发布其近期操作系统（包括 Windows 11 和 Server 2022）的代码行数。

如果 Microsoft Vista 的程序员每 `KLOC` 仅犯一个错误，那么 Vista 将有 50,000 个错误。大型软件项目凸显了对稳健且系统化的软件测试方法的需求。

#### 软件漏洞类型

本节将简要描述常见的应用程序漏洞。请同时参阅[第 4 章](#Ch004_107-223_B9780443187346000076_1.xhtml)“领域 3：安全架构与工程”中的“系统漏洞、威胁和对策”部分，以了解其他漏洞类型的信息。最新的漏洞信息可参考“CWE Top 25 Most Dangerous Software Weaknesses”（CWE 25 个最危险的软件弱点），网址为 <https://cwe.mitre.org/top25/archive/2021/2021_cwe_top25.xhtml>；以下摘要基于此列表。`CWE` 指通用弱点枚举，是 MITRE 维护的软件漏洞字典（见 <https://cwe.mitre.org/>）。

*   **越界写入**（又称缓冲区溢出，发生在程序员未执行变量边界检查时）
*   **跨站脚本**（Web 页面生成过程中对输入的不当中和）
*   **越界读取**（读取缓冲区末尾之后的数据）
*   **输入验证不当**
*   **操作系统命令注入**
*   **SQL 注入**：通过前端 Web 服务器操纵后端 SQL 服务器
*   **跨站请求伪造 (CSRF)**
*   **目录路径遍历**：通过引用 `../..` 等目录，从 Web 服务器根目录（如 `/var/www`）逃逸到常规文件系统[\[31\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0160)

##### 缓冲区溢出

当程序员未执行边界检查时，会发生**缓冲区溢出**。以下是“输入用户名”程序的伪代码。该程序声明 `$username` 变量长度为 20 个字符，打印“Enter Username:”，然后将用户输入存储在 `$username` 变量中：

```
variable $username[20]
print “Enter Username:”
getstring($username)
```

此函数包含缓冲区溢出。程序员声明 `$variable` 长度为 20 字节，但未对 `getstring` 函数执行边界检查。程序员假设用户会输入类似“bob”的内容。
