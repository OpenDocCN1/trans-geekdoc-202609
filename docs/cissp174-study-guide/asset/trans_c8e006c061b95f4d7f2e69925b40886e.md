

# 公有云计算

公有云计算将 IT 基础设施、存储或应用程序外包给第三方提供商。云也意味着计算资源的地理多样性。云计算的目标是让大型提供商利用其规模经济，向其他公司提供计算资源，这些公司通常根据使用量为这些服务付费。

## 云服务层级

云提供商提供的三种常见服务层级是**基础设施即服务**，**平台即服务**，和**软件即服务**。

*   **基础设施即服务**提供完整的虚拟化操作系统，由客户从操作系统层面开始进行配置。
*   **平台即服务**提供预配置的操作系统，由客户配置应用程序。
*   **软件即服务**从操作系统到应用程序均已完全配置，客户只需使用该应用程序即可。

在以上三种情况下，云提供商均负责管理硬件、虚拟化软件、网络、备份等。各类型的典型示例请参见[表 4.2](#Ch004_107-223_B9780443187346000076_1.xhtml#t0015)。

## 云部署模型

**私有云**存放单个组织的数据，可由第三方运营，也可由组织自行运营。**政府云**旨在将数据和资源在地理上限制在一个国家的边界内，专为相应国家的政府设计。

## 优势与安全考量

云计算的优势包括降低前期资本支出、降低维护成本、提供稳健的服务级别以及总体运营成本节约。

从安全角度来看，利用公有云计算服务需要严格的服务级别协议，并了解新的风险来源。一个担忧是多个组织的客户机运行在同一宿主机上。一家云客户的遭受攻破可能导致其他客户也被攻破。

此外，许多云提供商提供预配置的系统镜像，这可能因不安全的配置而引入风险。例如，设想一个包含操作系统、Web 服务和博客软件且均已预配置的博客服务镜像。与预配置镜像相关的任何漏洞都可能给使用该镜像的每个组织带来风险。

### 实例学习：预置镜像

2011 年，亚马逊向部分 **EC2 (Elastic Cloud Compute，弹性云计算)** 客户发送邮件，警告称：“我们最近注意到，美国东部区域的一个公共 **AMI** 附带分发了一个 SSH 公钥，这将允许发布者以 root 身份登录” [[16]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0085)。

**AMI** 代表 **Amazon Machine Image（亚马逊机器镜像）**，即预配置的虚拟客户机。TippingPoint 的 DVLabs 描述了发生的情况：“受感染的镜像由 Ubuntu 10.4 服务器组成，运行着 Apache、MySQL 和 PHP……该镜像似乎是在……6 个月前发布的，而我们直到现在才听说这个问题。究竟发生了什么？一位名为 guru 的 EC2 用户创建了这个镜像，其中包含他最常用的软件栈，然后将其发布到 Amazon AMI 社区。如果不是一个简单的事实，这一切本来都很好。该镜像在发布时仍然保留着他的 SSH 密钥。这意味着镜像发布者（本案中为 guru）可以作为 root 用户登录任何运行其镜像的服务器实例。密钥被遗留在 `/root/.ssh/authorized_keys` 和 `/home/ubuntu/.ssh/authorized_keys` 中。我们将生成的镜像称为‘官方翻新’。发布者声称这纯属意外，只是其缺乏经验的结果。无论这说法是否属实，该事件暴露了 EC2 社区内的一个重大安全漏洞” [[16]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0085)。

组织必须分析与预配置云系统相关的风险，并考虑从“基础”开始配置系统的选项，即从基础操作系统着手。

组织在与云计算提供商签订合同前，还应协商具体权利。这些权利包括审计权、漏洞评估权，以及对放置在云中的数据和系统进行渗透测试（包括电子和物理测试）的权利。

最后，你知道你的数据在哪里吗？公有云可能会将数据移动到任何国家，可能超出组织所在国的司法管辖范围。例如，基于美国的法律，如**《健康保险流通与责任法案》**或**《格雷姆-里奇-比利雷金融服务现代化法案》**，在美国境外不生效。在这些情况下，应考虑使用私有云或政府云。

## 共享责任

在云计算出现之前的世界里，责任划分更简单。正如我们稍后将讨论的，**分界点**描述了客户（其路由器及其后方的所有设备）和 ISP（ISP 的路由器及其后方的所有设备）各自的责任。共享责任实际上就是连接这两个路由器的一根电缆。“责任”描述了谁负责配置、维护和保护分界点两侧的系统。它也反映了对可用性（正常运行时间）和法律责任的双重承担。

由于其本质，责任在云中更为复杂。[图 4.16](#Ch004_107-223_B9780443187346000076_1.xhtml#f0085) 来自美国总务管理局 (GSA)，是一张很棒的图表 [[17]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0090)，描述了从本地部署（标记为企业 IT，客户承担 100% 责任）到 IaaS、PaaS 和 SaaS（云提供商承担最大责任）的责任范围。

# 微服务、容器和无服务器

云计算革命持续发展并演化出新技术，包括微服务、云和无服务器。这些技术的目标之一是降低计算成本。最初我们有运行在裸机硬件上的计算机。随后虚拟化技术允许多个操作系统在一个管理程序上运行。云为虚拟化带来了规模。每一步都降低了成本。这一过程随着微服务、容器和无服务器的出现而继续，我们接下来将进行讨论。

## 微服务

想象一家 20 年前在线销售玩具的公司。一年中的大部分时间使用量（相对）较低，但在促销和圣诞节期间会激增。该公司日常运营需要 100 台服务器。在高峰期（圣诞购物季），使用量会激增，公司需要 1000 台服务器来满足需求。

直接构建在硬件上（虚拟化之前）将非常昂贵：900 台服务器将在大半年内闲置。虚拟化改善了情况，但公司仍需要一个能运行 1000 台虚拟机的管理程序。云提供了真正的突破；玩具公司可以利用 **Amazon AWS**、**Microsoft Azure**、**Google Compute**（以及许多其他云提供商）按需配置虚拟系统，并在高峰期过后将其关闭。
