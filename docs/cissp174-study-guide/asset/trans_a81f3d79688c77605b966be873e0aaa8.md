

# 标准化安全配置

标准化安全配置当然很重要，但关于安全基线还有一个额外的考量因素。安全`基线化`是捕获某一时间点当前系统安全配置理解的过程。建立一种简便的方法来捕获当前系统安全配置，对于响应潜在安全事件极有帮助。假设相关系统或设备是基于标准化安全基线构建的，且严格遵守了强有力的变更控制措施，那么几乎就没有必要捕获当前安全配置了。然而，在现实世界中，即使在控制最严格的环境里，未经授权的变更也会发生，这使得随时间监控系统的安全配置成为必要。此外，即使是遵循变更管理程序的授权系统修改，也需要被理解并能轻松捕获。强调持续基线化的另一个原因是，可能存在最初并未按初始安全基线构建的系统。组织在系统安全方面的一个常见错误是：专注于建立强大的系统安全配置，却未能快速、轻松地掌握系统安全配置随时间发生的变化。

## 自动化

安全配置管理旨在确保硬件和软件的组织基线代表组织认为可接受的、经过审查的安全配置。历史上，安全配置管理的主要关注点在于资产的供应或部署阶段。或许也会采用定期（如每年一次）与初始基线进行比较。不幸的是，除非以极高的警惕性进行锁定和控制，否则在供应和重新评估之间，资产上会发生许多变化，且必然会发生。自动化重新评估可以缩短检测安全相关配置变更的时间。更好的做法是利用自动化主动解决任何偏离已批准配置基线的情况。

## 补丁管理

维护强大的系统安全配置相关的最基本但仍相当困难的任务之一是`补丁管理`，即管理软件更新的过程。要从根本上改善组织的安全态势，最重要的单一途径莫过于改进其补丁管理实践。所有软件在发布前都存在未完全解决的缺陷或不足。修复软件的常见方法是应用补丁以解决已知问题。并非所有补丁都关乎安全；许多补丁涉及简单的非安全相关错误修复。然而，安全补丁确实占据了整个补丁生态系统的很大一部分。

软件供应商会公开并直接向客户宣布补丁。一旦收到补丁通知，组织需要从风险管理的角度评估该补丁，以确定部署的紧迫程度。绝大多数入侵事件都涉及利用那些已有补丁却未及时部署的漏洞。何为“及时”很难界定，应由组织的风险管理实践来决定。美国网络安全和基础设施安全局（CISA）维护着已知被利用漏洞目录，这可以作为输入，为向关键系统快速部署补丁提供更有力的理由 [[10]](#Ch008_361-457_B9780443187346000064_2.xhtml#bb0055)。尽管可能感到部署补丁的紧迫性，但通常仍需要测试以确定补丁安装是否可能导致不良后果。从时间线来看，测试通常与风险评估同时进行。假设不良影响不需要补救，安装是补丁管理过程的最后阶段。

虽然从单一供应商处在单个系统上安装单个补丁的过程看似不那么繁重，但管理来自数十家供应商、跨越数千个系统的安全补丁的识别、测试和安装，可能会变得极其繁琐。此外，不同供应商对补丁安装的集中部署或自动化程度差异很大。随着攻击者的利用尝试越来越多地集中在浏览器（及其相关插件、扩展和框架）、办公套件和 PDF 阅读器等客户端应用程序上，补丁管理的格局正迅速变得更加复杂。

### 补丁测试与部署

虽然大家都理解打补丁的重要性，但补丁安装所需的停机时间，以及补丁问题偶尔导致的服务中断，都可能阻碍补丁的部署。维护窗口需求令人沮丧，但最终证明了为例行维护进行需求规划，以及建立例外流程以在有明确需求时允许紧急补丁窗口的合理性。为应对补丁本身导致服务中断的挑战，常见的前进方式是再次为这种可能性做计划，以便快速检测补丁问题并恢复到未打补丁的状态。理想情况下，补丁问题会在非关键系统上被发现，从而在关键系统受影响前停止补丁部署。

补丁测试有助于识别这些问题，但补丁的频率和数量会使得稳健且切合实际的补丁测试变得极其困难。一种常见的折中方案是采用分阶段补丁部署。采用这种方法，定义系统组在不同时间框架接收补丁部署，使得一组具有代表性且非关键的系统首先接收补丁，只有当每个分阶段的系统组都实现无问题安装时，补丁部署才会更广泛地继续进行。

## 漏洞管理

安全补丁通常旨在消除已知漏洞。组织不断为桌面、服务器、网络设备、电话设备和其他信息系统打补丁。组织完全修补所有系统的可能性很低。虽然未修补的系统可能是已知的，但拥有补丁失败的系统也很常见。补丁失败最常见的原因是部署了需要重启的补丁后，未能重启。

发现需要未知补丁的系统也很常见。`漏洞扫描`是发现环境中不良配置和缺失补丁的一种方式。虽然这似乎显而易见，但仍值得一提：漏洞扫描设备只能发现已知漏洞的存在。虽然发现缺失补丁是漏洞扫描设备或软件提供的最重要功能，但有些设备也能发现与不良配置相关的漏洞。

使用`漏洞管理`一词而非仅用漏洞扫描，是为了强调对漏洞信息进行管理的必要性。许多组织最初在漏洞扫描上略显过度热心，想要持续枚举企业内的所有漏洞。如果没有一个流程来处理这些漏洞的优先级排定和修复，仅仅列出数千个漏洞的价值是有限的。漏洞的修复或缓解应根据对组织的风险和修复程序的难易程度进行优先级排定。
