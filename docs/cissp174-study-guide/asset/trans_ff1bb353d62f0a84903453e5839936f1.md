
# 电子保管库

*Electronic vaulting*（电子保管库）是一种批量过程，按例行的、定期计划的时间间隔，以电子方式传输待备份的数据。它用于将大量信息传输到异地设施。有许多商业可用的工具和服务可以为组织执行电子保管库操作。电子保管库是每天甚至可能每小时需要备份的数据的良好工具。它同时解决了两个问题：将敏感数据存储在异地，并能以极短的间隔执行备份，以确保备份的是最新数据。

由于电子保管库在大多数情况下通过互联网进行，因此通过安全通信信道发送用于备份的信息，并通过强加密协议进行保护非常重要。

## 远程日志记录

数据库日志包含所有数据库事务的日志。日志可用于从数据库故障中恢复。假设每小时保存一个数据库检查点（快照）。如果数据库在检查点后 20 分钟丢失完整性，则可以通过恢复到该检查点，然后应用数据库日志中描述的所有后续事务来恢复。

*Remote Journaling*（远程日志记录）将数据库检查点和数据库日志保存到远程站点。如果主站点发生故障，可以恢复数据库。

## 数据库影子

数据库影子使用两个或更多相同的数据库，它们同时更新。影子数据库可以本地存在，但最佳实践是将一个影子数据库托管在异地。数据库影子的目标是大大减少数据库实现的恢复时间。与远程日志记录相比，数据库影子允许更快的恢复。

## 高可用性选项

越来越多的系统要求实际上具有零停机时间，即 `MTD` 为零。磁带上的数据恢复当然无法满足这些可用性需求。一旦发生故障或灾难，需要立即可用的备用系统。实现这种正常运行时间要求的常用方法是采用高可用性集群。

> **Note**（注意）
>
> 不同供应商对同一原则（即在发生故障时拥有主动处理或可用于处理的冗余系统）使用不同的术语。尽管具体实现可能略有不同，但持续可用性的总体目标通常通过类似（尽管不完全相同）的方法来实现，即使术语不尽相同。

高可用性集群的目标是减少系统或网络设备的恢复时间，使服务的可用性受到的影响小于重建、重新配置或以其他方式设置替换系统所造成的影响。存在两种典型的部署方法：

*   **Active-active cluster（主动-主动集群）**：涉及多个系统，所有系统均在线并主动处理流量或数据。这种配置也通常称为负载均衡，在面向公众的系统（如 Web 服务器场）中尤为常见。
*   **Active-passive cluster（主动-被动集群）**：涉及已就位、已配置、已通电并准备好在主系统发生故障时开始处理网络流量的设备或系统。主动-被动集群通常设计为将主系统或设备上所做的任何配置更改复制到备用系统。此外，为了加快服务恢复，许多故障转移集群设备将在无需用户交互的情况下，自动在次要系统上开始处理服务，前提是中断影响了主设备。它也可以称为热备用、备用或故障转移集群配置。

# 软件托管

随着将软件和应用程序开发外包给第三方变得普遍，组织必须确保即使最初开发软件的供应商倒闭，其应用程序的可用性也能得到维护。代表其他组织开发产品的供应商可能会因知识产权和竞争优势顾虑，而不愿向客户透露其应用程序的源代码。这两个实体之间的一个共同中间立场是：应用程序开发公司允许中立的第三方持有源代码。这种方法称为 *software escrow*（软件托管）。如果开发组织倒闭或以其他方式违反软件托管协议条款，持有托管的第三方将向采购组织提供源代码和任何其他信息。

# DRP 测试、培训和意识

必须为 BCP/DRP 的“灾难”部分执行测试、培训和意识建设。跳过这些步骤是最常见的 BCP/DRP 错误之一。一些组织“完成”了他们的 DRP，然后认为事情解决了，把厚厚的 DRP 文件夹放在架子上积灰。这种做法在许多层面上都是错误的。

首先，DRP 永远不会“完成”，而是一种不断修正的方法，旨在确保组织能够以可接受的方式恢复。其次，虽然善意的个人执行 DRP 的创建和更新，但即使是最勤勉的管理员也会犯错。为了在实际灾难中阻碍恢复之前发现并纠正这些问题，必须定期进行测试。第三，任何有效的 DRP 都将包含一些管理员必须执行的固有复杂操作和机动。灾难期间总会发生意外情况，但 DRP 的每个成员都应非常熟悉其在 DRP 中角色的细节，这要求对流程进行培训。

最后，普通用户在 DRP 中角色的意识，以及组织在灾难发生时确保人员安全和业务运营的重点意识，是至关重要的。本节将提供有效测试、培训和建立组织 DRP 意识的步骤详情。

## DRP 测试

为了确保灾难恢复计划代表一个可行的恢复计划，需要进行彻底的测试。考虑到 DRP 详细的战术主题，常规基础设施、硬件、软件和配置更改将改变 DRP 的执行方式，这不足为奇。组织的信息系统处于不断变化的状态，但遗憾的是，许多这样的更改并没有及时纳入更新后的 DRP。为了确保 DRP 作为一种可行的恢复方法的初始和持续有效性，需要执行测试。

下面将讨论不同类型的测试及其相关的优缺点。然而，至少无论选择哪种类型的测试，这些测试都应每年执行一次。许多组织可以、应该并确实更频繁地测试其 DRP，这是值得赞扬的。

### DRP 评审

DRP 评审是最基本的初始 DRP 测试形式，重点是通读整个 DRP 以确保覆盖面的完整性。此评审通常由制定计划的团队执行，涉及团队成员通读整个计划，以快速审查总体计划是否存在明显缺陷。DRP 评审主要只是一个合理性检查，以确保覆盖面中没有明显的遗漏或方法上的根本缺陷。
