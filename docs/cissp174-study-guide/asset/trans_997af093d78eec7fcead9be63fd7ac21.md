
防火墙的主要关注点历来是部署用于保护网络上系统集合的资产。虽然防火墙对于实现网络分段的重要性依然存在，但部署在单个端点上的防火墙提供了实质性的额外收益。在任何防火墙上执行的最基本配置涉及定义与各种网络相关的信任级别。历史上，这意味着信任内部资产并将所有非内部资产视为不受信。不幸的是，对手越来越多地利用横向移动（MITRE ATT&CK® 企业矩阵中的 TA0008 [[6]](#Ch008_361-457_B9780443187346000064_2.xhtml#bb0035)）降低了将内部等同于受信这一做法的有效性。

值得庆幸的是，端点防火墙为我们提供了一种技术上简单的方法来应对这种过度慷慨的内部信任区。端点防火墙有时被称为桌面防火墙或基于主机的防火墙，作为安装在单个系统上的软件运行。只有安装了端点防火墙的系统需要被隐性信任，这使得在对手从受损内部资产的有利位置发起攻击时，能够获得极大增强的保护和检测能力。

## 基础防火墙设计

防火墙设计多年来不断演进，从简单扁平的设计（如双宿主主机和屏蔽主机）发展到分层设计（如屏蔽子网）。虽然这些术语不再常用，且扁平设计已逐渐淡出使用，但了解基础防火墙设计仍然很重要。这种演进融合了网络纵深防御，从而导致了 DMZ 和更安全网络的使用。

### 堡垒主机

`堡垒主机` 是指放置在互联网上且未受其他设备（如防火墙）保护的任何主机。堡垒主机必须自我保护，并经过加固以抵御攻击。堡垒主机通常提供特定服务，所有其他服务都应被禁用。

### 双宿主主机

`双宿主主机` 拥有两个网络接口：一个连接到受信网络，另一个连接到不受信网络（如互联网）。双宿主主机不进行路由：如 [图 8.8](#Ch008_361-457_B9780443187346000064_1.xhtml#f0045) 所示，希望从互联网访问受信网络的用户，会先登录到双宿主主机，然后从那里访问受信网络。这种设计在 1990 年代现代防火墙出现之前更为常见，有时仍用于访问遗留网络。

![图 8.8 双宿主主机。](images/B9780443187346000064/f08-08-9780443187346.jpg)

[图 8.8](#Ch008_361-457_B9780443187346000064_1.xhtml#B-f0045) 双宿主主机。

### 屏蔽主机架构

`屏蔽主机架构` 是一种较旧的扁平网络设计，使用一台路由器通过访问控制列表 (ACL) 过滤进出 `堡垒主机` 的外部流量。堡垒主机可以访问其他内部资源，但路由器 ACL 禁止直接的内部/外部连接，如 [图 8.9](#Ch008_361-457_B9780443187346000064_1.xhtml#f0050) 所示。

![图 8.9 屏蔽主机网络。](images/B9780443187346000064/f08-09-9780443187346.jpg)

[图 8.9](#Ch008_361-457_B9780443187346000064_1.xhtml#B-f0050) 屏蔽主机网络。

双宿主主机与屏蔽主机设计的区别在于，屏蔽主机使用屏蔽路由器，该路由器过滤发往其他内部系统的互联网流量。屏蔽主机网络设计不采用网络纵深防御：堡垒主机的故障会使整个受信网络面临风险。屏蔽子网架构应运而生，通过使用 DMZ 网络实现了网络纵深防御。

### DMZ 网络与屏蔽子网架构

`DMZ` 是 `非军事区` 网络；该名称基于现实世界的军事 DMZ，如朝鲜和韩国之间的 DMZ。DMZ 是一个危险的“无人区”：这对军事 DMZ 和网络 DMZ 皆适用。

任何从不受信源（如互联网）接收流量的服务器都面临被攻陷的风险。我们使用纵深防御缓解策略来降低这种风险，包括打补丁、服务器加固和 NIDS，但总会残留一些风险。

出于这个原因，从不受信网络（如互联网）接收流量的网络服务器应放置在 DMZ 网络上。DMZ 的设计假设任何 DMZ 主机都可能被攻陷：DMZ 旨在遏制攻陷，防止其蔓延到内部受信网络。DMZ 上的任何主机都应经过加固。加固应考虑来自不受信网络的攻击，以及来自被攻陷的 DMZ 主机的攻击。

“经典” DMZ 使用两个防火墙，如 [图 8.10](#Ch008_361-457_B9780443187346000064_1.xhtml#f0055) 所示。这称为 `屏蔽子网` 双防火墙设计：两个防火墙屏蔽 DMZ 子网。

![图 8.10 屏蔽子网双防火墙 DMZ 设计。](images/B9780443187346000064/f08-10-9780443187346.jpg)

[图 8.10](#Ch008_361-457_B9780443187346000064_1.xhtml#B-f0055) 屏蔽子网双防火墙 DMZ 设计。

单防火墙 DMZ 使用一个防火墙，如 [图 8.11](#Ch008_361-457_B9780443187346000064_1.xhtml#f0060) 所示。这有时被称为“三足式” DMZ。

![图 8.11 单防火墙 DMZ 设计。](images/B9780443187346000064/f08-11-9780443187346.jpg)

[图 8.11](#Ch008_361-457_B9780443187346000064_1.xhtml#B-f0060) 单防火墙 DMZ 设计。

单防火墙设计要求防火墙能够过滤所有接口上的流量：不受信、受信和 DMZ。双防火墙设计更复杂，但被认为更安全。如果因防火墙故障导致攻陷，双防火墙 DMZ 需要两个防火墙同时故障，受信网络才会暴露。单防火墙设计仅需一次故障。

> **注意**
>
> 单独使用“DMZ”一词即暗示双防火墙 DMZ。

## Web 应用防火墙 (WAF)

Web 应用防火墙 (WAF) 并非仅仅是另一种类型或代的通用网络防火墙，而是一种完全独立且独特的控制措施。顾名思义，WAF 的唯一重点是提升组织在 Web 应用方面的安全态势，最常见的是组织自行开发的 Web 应用。WAF 的部署方式使其能够审查发往组织控制的 Web 应用的应用层流量。名称中的“防火墙”清楚地表明 WAF 通常旨在作为一种预防性控制使用。然而，即使配置为完全不阻断任何内容，它们也能提供实质性的检测收益。

组织最常为面向公众的应用程序部署 WAF，但也可用于增强面向内部的 Web 应用的安全性。WAF 可以通过多种方式部署，包括云托管、作为部署在托管应用的 Web 服务器前面的反向代理的本地部署，甚至作为运行在托管目标应用的 Web 服务器上的服务。这些第 7 层控制措施只需内联部署，使 Web 应用流量流经 WAF，以便其能够阻断公然恶意的流量或对可疑活动发出警报。

## 沙箱技术

基于签名的恶意内容预防方法存在一个主要的固有弱点；签名从根本上依赖于先验知识来创建。如果您的组织是首个遇到新型漏洞利用或技术的组织，基于签名的方法必然会失效。沙箱技术试图通过专注于识别可疑行为而非主要依赖签名来填补这一空白。
