

# 单播、多播和广播

**单播** 是一对一流量，例如客户端浏览网页。**多播** 是一对多，且“多”是预先选定的。**广播** 是局域网上的一对所有。

**多播** 流量在 IPv4 中使用“D 类”地址。节点被放入多播组。常见的多播应用是流式音频或视频。通过单播发送 1000 个音频流将需要大量带宽，因此使用多播。它的工作原理类似于一棵树：初始流是树干，多播组的每个成员是一片叶子。一个流从流媒体服务器发出，当它到达拥有通往多播组中节点的多条路由的路由器时，会在网络上分支。多播通常使用 UDP。

## 受限广播地址和定向广播地址

**广播** 流量发送给局域网上的所有站点。IPv4 广播地址有两种类型：受限广播和定向广播。受限广播地址是 `255.255.255.255`。之所以称为“受限”，是因为它永远不会被路由器转发，这与定向广播不同。

`192.0.2.0/24` 网络的定向（也称为网络定向）广播地址是 `192.0.2.255`（地址的主机部分在二进制中全为“1”，即 255）。之所以称为“定向”广播，是因为发往这些地址的流量可能来自远程网络（可以被“定向”发送）。

## 第 2 层广播流量

第 2 层广播流量到达“广播域”内的所有节点。同一局域网（或 VLAN）上的设备处于同一广播域中。以太网广播地址是 MAC 地址 `FF:FF:FF:FF:FF:FF`：发送到以太网交换机上该地址的流量将被所有连接的节点接收。

## 混杂网络访问

访问网段上的所有单播流量需要“**混杂**”网络访问。网络入侵检测系统 (NIDS) 等系统需要混杂网络访问，以便监控网络上的所有流量。网络节点通常只能“看到”直接发送给它们的单播流量。访问发送给其他节点的单播流量需要两样东西：配置为混杂模式的网络接口卡 (NIC) 以及访问网段上其他单播流量的能力。

将 NIC 置于混杂模式通常需要超级用户访问权限，例如 UNIX 系统上的 `root` 用户。交换机等设备提供流量隔离，因此每个主机将只接收发送给它的单播流量（除了广播和多播流量）。正如我们在后面章节将看到的，**集线器**、交换机 SPAN 端口或 TAP 通常用于提供混杂网络访问。

# TCP

TCP 是传输控制协议，一种可靠的第 4 层协议。TCP 使用三次握手在网络上创建可靠连接。TCP 可以对乱序到达的段进行重新排序，并重传丢失的段。

## 关键 TCP 首部字段

如 [图 5.5](#Ch005_225-293_B9780443187346000039.xhtml#f0030) 所示，TCP 首部长度为 20 字节（无选项时），包含多个字段。重要字段包括：

*   **源端口和目的端口**
*   **序列号和确认号**：保持全双工通信同步
*   **TCP 标志**
*   **窗口大小**：在收到确认前可发送的数据量

## TCP 端口

TCP 从源端口连接到目的端口，例如从源端口 `51178` 到目的端口 `22`。TCP 端口字段为 16 位，允许端口号从 `0` 到 `65535`。

端口分为两类：**保留端口** 和 **临时端口**。保留端口为 `1023` 或更低；临时端口为 `1024`–`65535`。大多数操作系统要求超级用户权限才能打开保留端口。任何用户均可打开（未使用的）临时端口。

常见服务（如 HTTP）使用知名端口。互联网号码分配局 (IANA) 在 [https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml) 维护一份知名端口列表。大多数 Linux 和 UNIX 系统在 `/etc/services` 中有一份较小的知名端口列表。

## 套接字对

**套接字** 是一个节点上 IP 地址与 TCP 或 UDP 端口的组合。**套接字对** 描述两个节点之间的唯一连接：源端口、源 IP、目的端口和目的 IP。[图 5.6](#Ch005_225-293_B9780443187346000039.xhtml#f0035) 中的 `netstat` 输出显示了源 IP `192.168.80.144`、TCP 源端口 `51178` 与目的 IP `192.168.2.4`、目的 TCP 端口 `22` 之间的套接字对。

![图 5.6 TCP 套接字对。](images/B9780443187346000039/f05-06-9780443187346.jpg)

[图 5.6](#Ch005_225-293_B9780443187346000039.xhtml#B-f0035) TCP 套接字对。

套接字可以“监听”（等待连接）；监听套接字在 [图 5.6](#Ch005_225-293_B9780443187346000039.xhtml#f0035) 中显示为 `127.0.0.1:631`。连接期间，套接字对随后变为“已建立”。你可能拥有从同一主机（如 `192.168.80.144`）到同一主机（`192.168.2.4`），甚至到同一端口（`22`）的多个连接。操作系统和路由器等中间设备能够因套接字对而保持这些连接的唯一性。在前面的例子中，两个来自相同源 IP 且发往相同 IP/目的端口的连接将拥有不同的源端口，从而使套接字对（和连接）唯一。

## TCP 标志

最初的六个 TCP 标志是：

*   **URG**：数据包包含紧急数据
*   **ACK**：确认收到的数据
*   **PSH**：将数据推送至应用层
*   **RST**：复位（拆除）连接
*   **SYN**：同步连接
*   **FIN**：结束连接（优雅地）

2001 年新增了两个 TCP 标志：**CWR**（拥塞窗口减小）和 **ECE**（显式拥塞通知回显），利用了 TCP 首部中以前保留的位。2003 年又新增了第三个标志：**NS**（Nonce Sum，随机数和）。这些标志用于管理网络路径上的拥塞（延迟）。所有 9 个 TCP 标志如 [图 5.7](#Ch005_225-293_B9780443187346000039.xhtml#f0040) 所示。

## TCP 握手

TCP 使用三次握手建立可靠连接。连接是全双工的，双方相互同步 (SYN) 并确认 (ACK)。这四个标志的交换分三步完成：SYN、SYN-ACK、ACK，如 [图 5.8](#Ch005_225-293_B9780443187346000039.xhtml#f0045) 所示。

![图 5.8 TCP 三次握手。](images/B9780443187346000039/f05-08-9780443187346.jpg)

[图 5.8](#Ch005_225-293_B9780443187346000039.xhtml#B-f0045) TCP 三次握手。

客户端选择一个初始序列号，设置在第一个 SYN 数据包中。服务端也选择自己的初始序列号，设置在 [图 5.8](#Ch005_225-293_B9780443187346000039.xhtml#f0045) 所示的 SYN/ACK 数据包中。双方通过将对方的序列号加 1 来确认：这就是确认号。序列号和确认号的使用使双方能够检测丢失或乱序的段。

连接建立后，通常每个段都会跟随 ACK。连接最终将以 RST（复位或拆除连接）或 FIN（优雅地结束连接）结束。
