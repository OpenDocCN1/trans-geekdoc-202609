### 字典攻击

*字典攻击*使用字表：一个预定义的单词列表，列表中的每个单词都会被哈希。如果破解软件将字典攻击产生的哈希输出与密码哈希匹配，攻击者就成功识别出了原始密码。

> **注意**
>
> 攻击者通常会根据目标调整其字典，例如为讲西班牙语的目标组织在字表中添加西班牙语字典，甚至为拥有《星际迷航》粉丝的组织添加克林贡语字典。Packet Storm Security 在 <https://packetstormsecurity.com/Crackers/wordlists/> 维护着多个字典。

因为字典攻击可以快速执行，许多组织要求用户创建包含特殊字符、数字、大写字母且长度在八位或以上的密码。[Fig. 6.2](#Ch006_295-335_B9780443187346000052.xhtml#f0015) 展示了使用密码破解工具 `John the Ripper` (<https://www.openwall.com/john/>) 对抗 [Fig. 6.1](#Ch006_295-335_B9780443187346000052.xhtml#f0010) 中所示从 SAM 文件获取的详细信息。即使运行简单的字典攻击也能快速揭示用户 deckard 的密码为“replicant”。应限制对 SAM 文件 (Windows) 和 shadow 文件 (UNIX/Linux) 的访问。

### 暴力破解和混合攻击

*暴力破解攻击*耗时更长，但效果更好。攻击者计算所有可能密码的哈希输出。就在几年前，基本计算机速度仍然足够慢，使这成为一项艰巨的任务。然而，随着 CPU 速度和并行计算的进步，暴力破解复杂密码所需的时间已大幅减少。

近期密码破解的另一项突破是利用 GPU（图形处理单元）破解密码：“为应对电脑游戏日益增长的需求而设计，当今顶级 GPU 的信息处理速率接近每秒两万亿次浮点运算（一万亿次浮点运算等于每秒一万亿次浮点运算）。为了更直观地理解这一点，在 2000 年，世界上最快的超级计算机——一组耗资 1.1 亿美元的联网机器——运算速度仅略高于每秒七万亿次浮点运算。图形处理单元之所以如此之快，是因为它们被设计为并行计算机。在并行计算中，给定的问题被分配给多个称为核心的处理单元，这些核心同时处理问题的不同部分” [\[1\]](#Ch006_295-335_B9780443187346000052.xhtml#bb0010)。

攻击者也可能使用彩虹表进行密码攻击。*彩虹表*充当一个数据库，包含大多数或所有可能密码的预计算哈希输出。生成彩虹表需要大量时间，且并不总是完整的：它们可能不包含所有可能的密码/哈希组合。虽然彩虹表充当数据库，但其内部更为复杂，依赖时间/内存权衡来表示和恢复密码及哈希。我们将在[第 4 章](#Ch004_107-223_B9780443187346000076_1.xhtml)（领域 3：安全架构与工程）中更详细地讨论彩虹表的技术细节。

> **注意**
>
> 利用彩虹表的预计算暴力破解攻击的效率取决于密码哈希算法的实现。决定彩虹表是否能大幅提高密码恢复速度的主要特性是该算法的实现是否涉及盐值，盐值只是一种在生成的哈希中引入随机性的方式。在没有盐值的情况下，相同的密码每次都会产生完全相同的哈希。值得注意的是，Windows 的 LM 和 NT 哈希不包含盐值，这使它们特别容易受到此类暴力破解的攻击。Linux 和 UNIX 系统已使用盐值数十年。使用 16 位盐值的旧版 UNIX/Linux 系统将要求攻击者创建 65,536 组单独的彩虹表，每个可能的盐值一组。使用 SHA-512 哈希的现代 UNIX/Linux 系统支持 8 字符的 Base64 盐值。这允许 600 亿亿亿（一个包含 58 位数字的十进制数）种不同的盐值。

*混合攻击*在哈希之前对字典中的单词进行追加、前置或更改字符，以尝试最快地破解复杂密码。例如，攻击者可能拥有潜在系统管理员密码的字典，但也会将每个字母“o”替换为数字“0”。如果目标的密码类似于任何类型的标准 8-15 字符单词，且仅在带有特殊字符的文本上进行了少量更改，则其复杂密码可能被混合攻击破解。

### 盐值

*盐值*允许一个密码以多种方式进行哈希。某些系统（如现代 UNIX/Linux 系统）在哈希前将盐值与密码结合。虽然存储密码哈希优于存储明文密码，但“UNIX 操作系统的设计者通过使用一个称为‘盐’的随机值改进了这种方法（哈希）。盐值确保相同的密码在不同用户使用时会以不同方式加密。这种方法的优势在于，攻击者必须多次加密同一个单词（每个盐值或用户一次）才能发起成功的密码猜测攻击” [\[2\]](#Ch006_295-335_B9780443187346000052.xhtml#bb0015)。

这使得彩虹表对于使用盐值的系统效果大打折扣（甚至完全无效)。对于不使用盐值的系统（如 Microsoft LAN Manager (LM) 哈希），只需编译一张彩虹表；而对于使用盐值的系统，则需要数千、数百万、数十亿甚至更多张彩虹表，具体取决于盐值长度。

在 Microsoft Windows 环境中管理密码相当简单。IT 或信息安全人员确定组织策略并通过 DC 实施该策略。互联网安全中心（CIS）的 Microsoft Windows Server 2019 基准包含关于标准密码策略的以下建议：

- 密码历史记录 = 设置为记住 24 个密码
- 最大密码期限 = 365 天
- 最小密码期限 = 1 天（这是因为用户不会循环更换 24 个密码以立即返回其最爱的密码）
- 最小密码长度 = 14 字符
- 密码必须符合复杂性要求 = 真
- 使用可逆加密存储密码 = 假 [\[3\]](#Ch006_295-335_B9780443187346000052.xhtml#bb0020)

困难在于用户未能妥善创建或保护他们选择的密码。例如，用户将密码写下来并存放在钱包、通讯录、手机中，甚至贴在显示器上的便利贴上，这种情况并不少见。
