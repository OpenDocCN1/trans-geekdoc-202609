
TGT 适用于站点选定的特定生命周期，通常设置为 10 小时（工作日的长度，再加上几个小时）。这允许典型用户进行一次身份验证，并在票据的生命周期内访问网络资源。Kerberos 因此是无状态的：一旦 Alice 拥有了 TGT，她就可以在其生命周期内使用它，即使 KDC 离线也没关系。此外，TGS 可以允许 Alice 打印而无需咨询 KDC：TGS 所需了解的一切都包含在 Alice 发送的流量中，包括 TGT 和第一个认证器。

Alice 发送给打印机的服务票据也是如此。它是用打印机的密钥加密的，并包含一份客户端/服务器会话密钥的副本。Alice 无法解密它，只是将其原封不动地传回给打印机。这使得打印机能够完全根据 Alice 发送的内容做出决定，而无需咨询 KDC 或 TGS。

> **注意**
>
> 本节（以及考试）描述的是“原生” Kerberos，而非特定供应商的实现，例如 Microsoft Windows Active Directory 中的 Kerberos。

#### Kerberos 的优势

Kerberos 提供客户端和服务器的相互认证。我们已经了解到 TGS 和服务器（如打印机）如何知道主体 Alice 已通过认证。Alice 也知道 KDC 是真正的 KDC。真正的 KDC 同时知道 Alice 和 TGS 的密钥。如果一个流氓 KDC 假装成真正的 KDC，它将无法访问这些密钥。[图 6.9](#Ch006_295-335_B9780443187346000052.xhtml#f0050) 展示了 Alice 尝试通过流氓 KDC 进行认证的步骤 1 和 2。

![图 6.9 流氓 KDC。](images/B9780443187346000052/f06-09-9780443187346.jpg)

[图 6.9](#Ch006_295-335_B9780443187346000052.xhtml#B-f0050) 流氓 KDC。

流氓 KDC 不知道 Alice 或 TGT 的密钥。因此它提供垃圾密钥（`Key^(garbage)`）。当 Alice 尝试解密会话密钥时，她将得到垃圾数据，而不是有效的会话密钥。Alice 就会知道该 KDC 是伪造的。

Kerberos 通过使用时间戳来缓解重放攻击（攻击者嗅探 Kerberos 凭据并在网络上重放它们）。认证器包含一个时间戳，请求的服务将拒绝任何过旧的认证器（通常为 5 分钟）。使用 Kerberos 的系统上的时钟需要同步，原因就在于此：时钟偏差会使认证器失效。

除了相互认证外，Kerberos 还是无状态的：由 KDC 或 TGS 颁发的任何凭据在其生命周期内均有效，即使 KDC 或 TGS 宕机也是如此。

#### Kerberos 的弱点

Kerberos 的主要弱点在于 KDC 存储了所有主体（客户端和服务器）的密钥。KDC 遭到攻破（物理或电子方式）可能导致 Kerberos 领域中每个密钥的泄露。

KDC 和 TGS 也是单点故障：如果它们宕机，将无法颁发新凭据。现有凭据仍可使用，但新的身份验证和服务授权将停止。

在认证器的生命周期内，重放攻击仍然可能发生。攻击者可以嗅探认证器，针对客户端发起拒绝服务攻击，然后冒充或欺骗客户端的 IP 地址。

在 Kerberos 4 中，任何用户都可以为另一个用户请求会话密钥。因此 Eve 可以说：“嗨，我是 Alice，我想进行身份验证。”然后 KDC 会发送一个用 Alice 的密钥加密的 TGT 和会话密钥给 Eve。Eve 随后可以对加密的会话密钥发起本地密码猜测攻击，尝试猜出 Alice 的密钥。Kerberos 5 增加了一个额外步骤来缓解此攻击：在[图 6.8](#Ch006_295-335_B9780443187346000052.xhtml#f0045) 的步骤 1 中，Alice 用她的密钥加密当前时间并将其发送给 KDC。KDC 知道 Alice 是真实的（拥有她的密钥），然后继续执行步骤 2。

最后，Kerberos 旨在缓解恶意网络：嗅探器将几乎没有价值。Kerberos 无法缓解恶意本地主机：明文密钥可能存在于内存或缓存中。恶意的本地用户或进程可能能够窃取本地缓存的凭据。

#### Kerberos 攻击利用

Kerberos 作为许多企业环境中的主要凭据守门人，意味着针对该生态系统的攻击无处不在且应在预料之中。针对 Kerberos 最常见的攻击涉及对手仅仅获取并冒充已认证的安全主体。严格来说，这并不真正涉及对 Kerberos 的利用，而只是利用账户之前颁发的服务票据。在 Kerberos 生态系统中，利用用户当前已验证的服务票据将允许对手访问用户已在访问的资源。

也存在更明显的以 Kerberos 为中心的攻击模式。MITRE 的 ATT&CK® 企业矩阵包含技术 1558 (T1558)：窃取或伪造 Kerberos 票据，这还强调了特定的攻击模式，如黄金票据、白银票据和 Kerberoasting [\[13\]](#Ch006_295-335_B9780443187346000052.xhtml#bb98)。在每种情况下，总体目标都是让对手破坏 Kerberos 认证，以合法用户的身份出现，这可以实现对手的横向移动，并允许在受害环境中进行一般性访问。

### 访问控制协议和框架

集中式和分布式模型都可能支持远程用户向本地系统进行身份验证。许多协议和框架可用于支持这一需求，包括 `RADIUS`、`Diameter`、`TACACS/TACACS+`、`PAP` 和 `CHAP`，以及 Microsoft Active Directory。

#### RADIUS

*远程认证拨号用户服务* 协议是一种第三方认证系统。`RADIUS` 在 RFC 2865 和 2866 中有描述，并使用用户数据报协议（`UDP`）端口 1812（认证）和 1813（计费）。`RADIUS` 以前使用（非官方分配的）端口 1645 和 1646 用于相同的目的；某些实现仍继续使用这些端口。

`RADIUS` 被视为一个“AAA”系统，由三个组件组成：认证、授权和计费。它根据认证数据库验证主体的凭据。它通过允许特定用户访问特定数据对象来授权用户。它通过为每个建立的 `RADIUS` 连接创建日志条目来记录每个数据会话。

`RADIUS` 请求和响应数据以属性值对（`AVPs`）的形式承载。根据 RFC 2865 ([https://datatracker.ietf.org/doc/html/rfc2865](https://datatracker.ietf.org/doc/html/rfc2865))，`RADIUS` 支持以下代码：

*   `Access-Request`
*   `Access-Accept`
*   `Access-Reject`
*   `Accounting-Request`
*   `Accounting-Response`
*   `Access-Challenge`
*   `Status-Server`（实验性）
*   `Status-Client`（实验性） [\[14\]](#Ch006_295-335_B9780443187346000052.xhtml#bb0065)

#### Diameter

*Diameter* 是 `RADIUS` 的继任者，旨在提供改进的认证、授权和计费（`AAA`）框架。`RADIUS` 提供的问责功能有限，且在灵活性、可扩展性、可靠性和安全性方面存在问题。`Diameter` 也使用属性值对，但支持更多：`RADIUS` 对 `AVP` 字段使用 8 位（允许总共 256 个可能的 `AVPs`），而 `Diameter` 对 `AVP` 字段使用 32 位（允许数十亿个潜在的 `AVPs`）。这使得 `Diameter` 更加灵活，例如允许支持移动远程用户。

`Diameter` 使用单个服务器来管理许多服务的策略，而 `RADIUS` 则需要许多服务器来处理所有安全连接协议。与 `RADIUS` 一样，`Diameter` 提供 `AAA` 功能，但此外，它通过使用传输控制协议（`TCP`）变得更加可靠。`Diameter` 在 RFC 6733 ([https://datatracker.ietf.org/doc/html/rfc6733](https://datatracker.ietf.org/doc/html/rfc6733)) 中有描述。

#### TACACS 和 TACACS+
