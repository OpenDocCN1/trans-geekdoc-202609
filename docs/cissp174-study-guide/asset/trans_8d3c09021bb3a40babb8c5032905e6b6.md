#### Microsoft NTFS 权限

Microsoft NTFS（新技术文件系统）具有以下基本文件权限：

*   读取
*   写入
*   读取和执行
*   修改
*   完全控制（读取、写入、执行、修改，此外还包括更改权限的能力）

NTFS 的权限类型比大多数 UNIX 或 Linux 文件系统更多。NTFS 文件由所有者控制，所有者可向其他用户授予权限。[图 4.14](#Ch004_107-223_B9780443187346000076_1.xhtml#f0075) 显示了位于 `C:\Users\Public\Pictures\Sample Pictures\Penguins.jpg` 的示例照片的权限。

#### 特权程序

在 UNIX 和 Linux 系统中，普通用户无法编辑密码文件（`/etc/passwd`）和影子文件（`/etc/shadow`），它们分别存储账户信息和加密密码。但用户需要能够更改他们的密码（从而更改这些文件）。如果他们不能（直接）更改这些文件，如何更改密码呢？

答案是 `setuid`（设置用户 ID）程序。`Setuid` 是一种 Linux 和 UNIX 文件权限，它使可执行文件以文件所有者的权限运行，而不是以运行用户的权限运行。`Setgid`（设置组 ID）程序以文件所属组的权限运行。

[图 4.15](#Ch004_107-223_B9780443187346000076_1.xhtml#f0080) 显示了用于设置和更改密码的 Linux 命令 `/usr/bin/passwd` 的权限。它是 `setuid` root（该文件由 root 用户所有，且所有者的执行位设置为“s”，表示 `setuid`），这意味着它以 root（超级用户）权限运行，无论运行用户是谁。

![Fig. 4.15 Linux setuid root program /usr/bin/passwd.](images/B9780443187346000076/f04-15-9780443187346.jpg)

[图 4.15](#Ch004_107-223_B9780443187346000076_1.xhtml#B-f0080) Linux `setuid` root 程序 `/usr/bin/passwd`。

“passwd”程序以 root 身份运行，允许任何用户更改其密码，从而更改 `/etc/passwd` 和 `/etc/shadow` 的内容。`Setuid` 程序必须经过严格审查以发现安全漏洞：攻击者可能会试图欺骗 `passwd` 命令以修改其他文件。应密切监控系统上所有 `setuid` 和 `setgid` 程序的完整性。

## 虚拟化、云计算和分布式计算

虚拟化和分布式计算彻底改变了计算世界，给应用程序、服务、系统数据和数据中心带来了彻底的变革。昨天的最佳实践可能不再适用。当数据在云端时，DMZ 在哪里？你的 NIDS 能否监控单个主机上从一个客户机发送到另一个客户机的数据？你的物理防火墙还重要吗？

### 虚拟化

*虚拟化*在操作系统和底层计算机硬件之间增加了一个软件层。这允许多个“客户机”操作系统在一台物理“主机”计算机上同时运行。流行的透明虚拟化产品包括 VMware、QEMU 和 Xen。

虚拟化有两种基本类型：透明虚拟化（有时称为完全虚拟化）和半虚拟化。透明虚拟化将标准操作系统（如 Windows 11 或 Ubuntu Linux 22.04）作为虚拟客户机运行。无需更改客户机操作系统。半虚拟化运行专门修改过的操作系统，具有修改过的内核系统调用。半虚拟化可能更高效，但需要更改客户机操作系统。对于闭源操作系统（如 Microsoft Windows 系列）来说，这可能是不可能的。

#### 管理程序

虚拟化安全的关键在于*管理程序*，它控制虚拟客户机与主机硬件之间的访问。类型 1 管理程序（也称为裸金属）是直接运行在主机硬件上的操作系统的一部分。类型 2 管理程序作为普通操作系统（如 Windows 10）上的应用程序运行。例如：VMware ESX 是类型 1 管理程序，VMware Workstation 是类型 2。

许多虚拟化漏洞利用针对管理程序，包括主机与客户机之间、客户机与客户机之间共享的由管理程序控制的资源。这些包括剪切粘贴、共享驱动器和共享网络连接。

#### 虚拟化优势

虚拟化提供了许多优势，包括降低整体硬件成本、硬件整合，以及降低电力和冷却需求。快照允许管理员创建操作系统镜像，只需点击鼠标即可恢复，使备份和恢复变得简单快捷。测试新操作系统、应用程序和补丁可以非常简单。虚拟客户机集群比直接运行在硬件上的操作系统集群要简单得多。

#### 虚拟化安全问题

虚拟化软件复杂且相对较新。如前所述，复杂性是安全的敌人：虚拟化软件的极高复杂性可能导致安全问题。

将多个客户机合并到一台主机上也可能引发安全问题。虚拟化不能替代防火墙：切勿将具有不同安全需求的客户机（如 DMZ 和内部）合并到一台主机上。虚拟化逃逸（称为 VMEscape，攻击者从一个客户机利用主机操作系统或另一个客户机）的风险是近期研究的热门话题。Network World 报道：“在 Cisco 的企业 NFV 基础设施软件 (NFVIS) 中发现了多个漏洞。最严重的漏洞可能允许攻击者从客户机虚拟机 (VM) 逃逸到主机，Cisco 披露。另外两个问题涉及允许恶意行为者注入在根级别执行的命令，以及允许远程攻击者将主机的系统数据泄露给 VM” [\[15\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0080)。已知的虚拟化逃逸漏洞已修补，但新问题可能会出现。

许多基于网络的安全工具（如网络入侵检测系统）可能因虚拟化而“失明”。连接到物理 SPAN 端口或分流器的传统 NIDS 无法看到同一主机上从一个客户机传递到另一个客户机的流量。NIDS 厂商开始提供虚拟 IDS 产品，这些产品作为软件运行在主机上，能够检查主机-客户机和客户机-客户机流量。防火墙也正在发生类似的从物理到虚拟的转变。
