

# 三个关键 RAID 术语

三个关键 RAID 术语是：镜像、条带化和奇偶校验。

## 镜像

*镜像* 是基本 RAID 概念中最明显、最基础的一个，其作用仅仅是通过将相同数据写入多块硬盘来实现完全的数据冗余。由于镜像数据必须写入多块磁盘，写入时间会变慢（尽管 RAID 控制器的缓存可能会缓解这一问题）。然而，通过同时从多块硬盘拉取数据，读取镜像数据时可以获得性能提升。除了读写性能考量外，与镜像相关的主要成本是磁盘使用率；使用镜像时，至少一半的驱动器用于冗余。

## 条带化

*条带化* 是一种侧重于通过将数据分散到多块硬盘来提高读写性能的 RAID 概念。由于数据分散在多个磁盘驱动器上，读写操作可以跨多个磁盘并行执行，而不是在单个磁盘上串行执行。这种并行化提供了性能提升，但无助于数据冗余。

## 奇偶校验

*奇偶校验* 是一种在磁盘使用率和写入性能方面，无需承担与镜像同等程度成本即可实现数据冗余的方法。

> **考试警告**
>
> 虽然快速从磁盘故障中恢复是 RAID 的目标，但存在一些不具备可靠性能力的配置。考试时，务必理解并非所有 RAID 配置都提供额外的可靠性。

## RAID 0——条带化集

顾名思义，*RAID 0* 采用条带化来提高读写性能。条带化本身不提供数据冗余，因此如果利用 RAID 的原因是为了数据恢复，RAID 0 是一个糟糕的选择。[图 8.15](#Ch008_361-457_B9780443187346000064_1.xhtml#f0080) 直观展示了 RAID 0 的构成。

## RAID 1——镜像集

这个 RAID 级别或许是所有 RAID 级别中最容易理解的。*RAID 1* 会创建/写入所有数据的精确副本到额外的一块磁盘。写入性能会下降，但读取性能可能会提升。磁盘成本是该 RAID 级别最棘手的方面之一，因为至少一半的磁盘专门用于冗余。[图 8.16](#Ch008_361-457_B9780443187346000064_1.xhtml#f0085) 直观展示了 RAID 1。

## RAID 2——海明码

RAID 2 不被认为在硬盘上具有商业可行性，且未被使用。该 RAID 级别需要 14 块或 39 块硬盘以及专门设计的硬件控制器，这使得 RAID 2 的成本高得令人望而却步。考试不太可能涉及 RAID 2。

## RAID 3——带专用奇偶校验的条带化集（字节级）

条带化因其将数据分散到多个磁盘所带来的性能增益而备受青睐。然而，仅靠条带化并不理想，因为它缺乏冗余。使用 *RAID 3* 时，数据在字节级别上跨多个磁盘进行条带化，但会利用一块额外的磁盘存储奇偶校验信息，该信息用于在发生故障时进行恢复。

## RAID 4——带专用奇偶校验的条带化集（块级）

*RAID 4* 提供与 RAID 3 完全相同的配置和功能，但数据条带化是在块级别而非字节级别进行的。与 RAID 3 一样，RAID 4 采用专用奇偶校验驱动器。

## RAID 5——带分布式奇偶校验的条带化集

最流行的 RAID 配置之一是 *RAID 5*，即带分布式奇偶校验的条带化集。RAID 5 同样专注于条带化以获取其提供的性能提升，并利用块级条带化。与 RAID 3 和 4 一样，RAID 5 写入用于恢复的奇偶校验信息。然而，与 RAID 3 和 4 需要一块专用磁盘存储奇偶校验信息不同，RAID 5 将奇偶校验信息分布在多块磁盘上。RAID 5 流行的原因之一是其冗余的磁盘成本低于镜像集。该级别流行的另一个重要原因是支持基于硬件和基于软件的实现，这显著降低了 RAID 配置的准入门槛。RAID 5 允许在任意一块磁盘故障时恢复数据。[图 8.17](#Ch008_361-457_B9780443187346000064_1.xhtml#f0090) 提供了 RAID 5 的可视化表示。

## RAID 6——带双重分布式奇偶校验的条带化集

虽然 RAID 5 可容忍阵列中任意一块驱动器的损失，但 *RAID 6* 允许两块驱动器故障并仍能运行。这种冗余是通过将相同的奇偶校验信息写入两块不同的磁盘来实现的。

> **注意**
>
> 存在许多仅仅是标准 RAID 级别组合的各种 RAID 配置。嵌套 RAID 解决方案在需要高度可靠性和速度的大型磁盘阵列中变得越来越普遍。一些常见的嵌套 RAID 级别包括 RAID 0 + 1、1 + 0、5 + 0、6 + 0 和 (1 + 0) + 0，通常也分别写作 RAID 01、10、50、60 和 100。

## RAID 1 + 0 或 RAID 10

*RAID 1 + 0 或 RAID 10* 是所谓嵌套 RAID 或多重 RAID 的一个例子，这仅仅意味着一个标准 RAID 级别被封装在另一个标准 RAID 级别内部。对于 RAID 10（也常写作 RAID 1 + 0 以明确指示嵌套关系），其配置是镜像的条带化集。

# 系统冗余

虽然 RAID 和备份解决方案提供的数据冗余和弹性很重要，但还需要进一步考虑提供对这些冗余数据访问的系统本身。

## 冗余硬件

许多系统可以为极易发生故障的组件提供内部硬件冗余。这种内置冗余最常见的例子是系统或设备拥有冗余机载电源，以应对电源故障。除了冗余电源外，冗余网络接口卡 (NIC) 和冗余磁盘控制器也很常见。有时系统只是拥有常见易损组件的现场可更换模块化版本。虽然物理更换电源可能会增加停机时间，但备齐一套备用模块来维护整个数据中心的服务器，成本会低于为所有服务器配置安装好的冗余电源。

## 冗余系统

虽然许多易故障的内部组件可以配置为内置在系统中以实现冗余，但内部冗余是有限度的。如果系统可用性极其重要，那么在库存中备有完整的系统作为恢复手段可能是明智之举。虽然恢复时间可能较长，但组织与硬件制造商签订 SLA 以便及时快速采购替换设备的做法相当普遍。如果恢复时间可接受，那么快速采购选项很可能比备有闲置备用设备以应对临时系统恢复要便宜得多。
