

# 小程序

**小程序** 是嵌入在其他软件（如 Web 浏览器）中的小段移动代码。与提供内容显示方式的 HTML（超文本标记语言）不同，小程序是可执行文件。主要的安全顾虑在于小程序从服务器下载后在本地运行。恶意小程序可能会危及客户端的安全。

小程序可以用多种编程语言编写；两种主要的小程序语言是 **Java**（由 Oracle/Sun Microsystems 开发）和 **ActiveX**（由 Microsoft 开发）。"Applet" 一词用于 Java，而 "control" 用于 ActiveX，尽管它们在功能上相似。

## Java

Java 是一种面向对象的语言，不仅用于编写小程序，还作为一种通用编程语言。Java 字节码与平台无关：它由 Java 虚拟机（`JVM`）解释执行。`JVM` 可用于多种操作系统，包括 Linux、FreeBSD 和 Microsoft Windows。

Java 小程序在沙箱中运行，将代码与操作系统隔离开。沙箱旨在防止攻击者在攻破 Java 小程序后访问系统文件（如密码文件）。在沙箱中运行的代码必须是自给自足的：它不能依赖沙箱外部存在的操作系统文件。受信任的 Shell 是静态编译的 Shell（不使用操作系统共享库），可用于沙箱中。

## ActiveX

ActiveX 控件是 Java 小程序的功能等价物。它们使用数字证书而非沙箱来提供安全性。ActiveX 控件与操作系统的联系更紧密，允许通过 Windows Update 安装补丁等功能。与 Java 不同，ActiveX 是 Microsoft 技术，仅适用于 Microsoft Windows 操作系统。

## OWASP

开放 Web 应用程序安全项目（`OWASP`，参见 [https://www.owasp.org](https://www.owasp.org)）是最好的应用安全资源之一。`OWASP` 提供了大量免费资源，致力于改善组织的应用安全状况。他们最著名的项目之一是 OWASP Top 10 项目，该项目就什么是 10 个最重要的应用安全风险提供了共识指导。OWASP Top 10 可在 [https://owasp.org/www-project-top-ten/](https://owasp.org/www-project-top-ten/) 获取。

除了关于应用安全威胁、漏洞和防御的丰富信息外，`OWASP` 还维护着几款可免费下载的安全工具，包括一款领先的拦截代理：`ZAP`，即 Zed Attack Proxy。

## XML

**XML**（可扩展标记语言）是一种标记语言，旨在作为编码文档和数据的标准方式。XML 类似于 HTML，但更通用。XML 用于 Web，但不局限于 Web：XML 可用于存储应用程序配置和审计工具的输出，还有许多其他用途。可扩展意味着用户可以使用 XML 定义自己的数据格式。

## 面向服务的架构 (SOA)

面向服务的架构（`SOA`）试图将应用程序架构简化为服务的功能单元。`SOA` 旨在允许多个异构应用程序成为服务的消费者。服务可在整个组织中使用和重用，而非在每个需要该服务提供的功能的单个应用程序中单独构建。

服务预期应与平台无关，并能以不依赖特定编程语言的通用方式被调用。其意图是任何应用程序只需使用其所选编程语言中可用的标准手段即可利用该服务。服务通常以某种形式的目录发布，提供有关如何使用该服务及其提供功能的详细信息。

虽然 Web 服务不是唯一的例子，但它们是 `SOA` 模型最常见的例子。XML 或 JSON（JavaScript 对象表示法）常用于 Web 服务的底层数据结构，SOAP（最初是 "Simple Object Access Protocol" 的首字母缩写，但现在仅称为 "SOAP"）或 REST（表述性状态转移）提供连接性，而 WSDL（Web 服务描述语言）提供有关如何调用 Web 服务的详细信息。

> **考试警告**
>
> 不要混淆面向服务的架构（`SOA`）与 SOAP。它们相关但不同：`SOA` 可能使用 SOAP 进行连接。

# 数据库安全

数据库带来了独特的安全挑战。数据库中可能存放的海量数据需要特殊的安全考量。正如我们将在 "推理与聚合" 部分看到的那样，数据库用户通过创建、查看和比较记录建立的逻辑联系可能导致推理和聚合攻击，这需要数据库安全预防措施，如 **推理** 控制和 **多实例化**。

## 多实例化

多实例化允许两个不同的对象拥有相同的名称。该名称基于拉丁语词根：multiple（多个，poly）和 instances（实例，instantiation）。数据库多实例化意味着两行可能具有相同的主键，但数据不同。

假设你有一个多级安全数据库表。每个元组（元组是关系数据库中的一行或一个条目）包含带有机密、秘密或绝密安全标签的数据。具有相同三种级别许可的主体可以访问该表。系统遵循强制访问控制规则，包括 "不上读"：秘密主体不能读取标记为绝密的条目。

一位具有秘密许可的经理正准备裁员，打开 "layoffs"（裁员）表，并尝试为员工 John Doe 创建一个主键为 `123-45-6789` 的条目。该秘密主体不知道已存在一个主键相同、标记为绝密的 John Doe 条目。事实上，整个部门（包括经理）都存在标记为绝密的条目：整个部门都将被裁员。此信息标记为绝密：经理无法读取。

正常数据库通常要求表中所有行包含唯一的主键，因此当经理尝试插入新条目时，普通数据库会生成类似 "duplicate entry"（重复条目）的错误。多级安全数据库不能这样做，否则会允许经理推断出绝密信息。

多实例化意味着数据库将创建两个具有相同主键的条目：一个标记为秘密，一个标记为绝密。

## 推理与聚合

当用户能利用较低级别的访问权限获取受限信息时，就会发生推理和 **聚合**。这些问题发生在多个领域，包括数据库安全。

推理需要演绎：有一个谜题待解，较低级别的细节提供了线索。聚合是一个数学过程：用户提出所有问题，获得所有答案，并推导出受限信息。
