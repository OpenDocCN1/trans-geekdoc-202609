
# 最小权限与知悉必要性

*最小权限*意味着用户应仅被授予完成其工作所需的最低访问权限（授权），而不得更多。*知悉必要性*比最小权限更细粒度：用户在访问特定信息前，必须具有知悉该特定信息的业务需求。

塞巴斯蒂安是一名护士，在一家拥有多个诊所的医疗机构工作。他的诊所共有四名医生，塞巴斯蒂安可以为这四名医生中的任意一位诊治患者。最小权限可允许塞巴斯蒂安访问这四名医生患者的记录，但不允许访问其他诊所其他医生患者的记录。

知悉必要性意味着塞巴斯蒂安只有在有业务需要时，才能访问患者的记录。如果有一名患者由塞巴斯蒂安所在诊所诊治，但并非由塞巴斯蒂安本人诊治，最小权限可能允许访问，但知悉必要性则不允许。

## 举例学习

### 现实世界中的最小权限

一家大型医疗服务提供商拥有一支 60 人的 IT 团队，负责管理 4000 台运行 Microsoft Windows 的系统。该公司未实施最小权限：整个 IT 团队均被授予了 Windows 域管理员访问权限。拥有此类权限的人员包括服务台人员、备份管理员等众多角色。所有 60 名域管理员在所有 4000 台 Windows 系统上均拥有超级用户特权。

这种权限级别过高，并导致了问题。操作错误导致了 CIA（机密性、完整性、可用性）原则被违反。由于人人都能做太多事情，环境破坏频发。数据丢失；发生未授权更改；系统崩溃，且难以定位原因。

公司聘请了一位新的安全主管，他的首要任务之一就是强制执行最小权限。创建了基于角色的账户：允许访问工单系统的服务台角色、允许备份和恢复的备份角色等。域管理员名单被精简为极少数授权人员。

许多前域管理员抱怨失去了超级用户授权，但每个人获得的访问权限都足以完成其工作。改进效果立竿见影且显著：未授权更改几乎停止，系统崩溃变得少见得多。操作员仍会犯错，但这些错误造成的代价小得多。

## 主体与客体

*主体*是数据系统上的活动实体。大多数主体示例涉及人员访问数据文件。然而，计算机程序也可以是主体。一个更新数据库文件以录入新信息的动态链接库文件或 Perl 脚本也是主体。

*客体*是系统内的任何被动数据。客体范围可从纸质文档、数据库表到文本文件。关于客体要记住的关键是，它们在系统内是被动的。它们不操作其他客体。

有一个棘手的主体与客体示例非常重要，必须理解。例如，如果你正在运行 `iexplore.exe`（Microsoft Windows 系统上的 Internet Explorer 浏览器），它在内存中运行时是一个主体。当浏览器未在内存中运行时，文件 `iexplore.exe` 就是文件系统上的一个客体。

> **考试警告**
>
> 通过判断 CISSP® 考试中的所有示例是属于主体定义还是客体定义，保持对示例的理解简单明了。

## 纵深防御

*纵深防御*（也称为分层防御）应用多种保障措施（也称为控制：为降低风险而采取的措施）来保护资产。任何单一的安全控制都可能失效；通过部署多重控制，可以提高数据的机密性、完整性和可用性。

### 举例学习

#### 纵深防御恶意软件防护

一家拥有 12,000 名员工的公司每天接收 250,000 封互联网邮件。绝大多数邮件都是恶意的，从浪费时间和资源的垃圾邮件到蠕虫、病毒等恶意软件。攻击者频繁更改战术，总是试图规避旨在拦截垃圾邮件和恶意软件的保障措施。

该公司部署了预防性的纵深防御控制，用于基于互联网邮件的恶意软件防护。一组 UNIX 邮件服务器对传入的互联网邮件进行过滤，每台服务器运行两种由两家不同主要供应商提供的自动更新防病毒/反恶意软件解决方案。扫描无毒的邮件随后被转发至内部 Microsoft Exchange 邮件服务器，该服务器运行着另一家供应商的防病毒软件。通过该扫描的邮件可到达用户的客户端，客户端运行着第四家供应商的防病毒软件。客户端台式机和笔记本电脑也已完全打补丁。

尽管有这些保障措施，仍有少量恶意软件成功逃过了四种不同防病毒软件的检查，感染了用户的客户端系统。幸运的是，公司部署了额外的纵深防御控制，如*入侵检测系统*（IDS）、事件处理策略和 *CERT*（*计算机应急响应小组*）来处理事件。这些防御措施成功识别出受感染的客户端系统，从而实现了及时响应。

所有控制都可能失效，有时多个控制会同时失效。在组织中部署一系列不同的纵深防御保障措施，可降低所有控制同时失效的几率。

## 尽职照料与尽职调查

*尽职照料*是指做一个理性的人会做的事。它有时被称为“谨慎人”规则。该术语源于“照料义务”：例如，父母有义务照料子女。*尽职调查*是对尽职照料的管理。

尽职照料与尽职调查常被混淆；二者相关但不同。尽职照料是非正式的；尽职调查遵循一个流程。可将尽职调查视为比尽职照料更进一步的步骤。期望员工保持其系统打补丁，意味着期望他们履行尽职照料。验证员工是否已给系统打补丁，则是尽职调查的一个例子。

### 重大过失

重大过失是尽职照料的反面。这是一个法律上重要的概念。例如，如果你遭遇了 PII（个人身份信息）丢失，但能证明在保护 PII 方面履行了尽职照料，你在法律上处于更有利的地位。如果你无法证明尽职照料（即你存在重大过失），你的法律地位将恶化得多。

# 法律与监管问题

尽管了解主要法律体系和法律类型的总体情况很重要，但信息安全专业人员理解下一节所述概念至关重要。随着信息系统、数据和应用程序的普及，随之而来的是一系列需要关注的法律问题。影响信息安全的法律概念示例包括：由计算机系统实施或协助的犯罪、针对知识产权的攻击、隐私担忧以及国际问题。

## 遵守法律法规

遵守法律法规是信息安全管理的首要任务：无论是在现实世界中还是在考试中。组织必须遵守所有适用于其的法律法规。不知法从来不是违法的有效借口。

> **考试警告**
>
> 考试将对你遵守法律法规的要求举持极高标准。我们不需要像律师那样精通法律，但需知道何时该咨询律师。例如，混淆 `Kerberos` 等安全控制的技术细节可能不会导致严重的负面后果。但因对搜查员工个人财产的合法性产生混淆而违反搜查扣押法，则极可能导致严重的负面后果。法律上最正确的答案往往是考试中的最佳答案。
