
# 将两个模型部署到同一端点

将两个模型部署到同一端点，可让您逐步用一个模型替换另一个模型。在 A/B 测试场景中，如果您不想在应用中造成突发性变化，可以将新模型添加到同一端点，为其分配一小部分流量，然后逐渐增加新模型的流量分割比例，直到其承载 100% 的流量。

## 使用流量分割进行 A/B 测试

对于 Vertex AI 中的 A/B 测试，我们在部署模型时介绍了 `traffic-split` 参数。您可以在将两个模型托管到同一端点时，向此 `traffic-split` 参数提供 `model_id` 和分割值，以拆分流量。以下是在 Cloud Shell 中使用 `gcloud` 命令的示例：

```
gcloud ai endpoints update <Endpoint> --region=us-central1 \
  --traffic-split=[DEPLOYED_MODEL_ID=Value] --service-account=<Service account> \
  --project=<Project> \
  --traffic-split=[DEPLOYED_MODEL_ID=VALUE,…]
```

在上述代码中，`traffic-split` 参数接受一个已部署模型 ID 列表，并将其值设置为 `traffic-split`。请查看此链接以了解有关部署模型参数的更多信息：

`https://cloud.google.com/sdk/gcloud/reference/ai/endpoints/update`

由于资源与模型相关联而非端点，因此您可以将不同类型的模型部署到同一端点。然而，最佳实践是将特定类型的模型（例如 AutoML 文本、AutoML 表格、自定义训练）部署到一个端点。这种配置更易于管理。

开箱即用方面，除了使用 `traffic-split` 之外，Vertex AI 并不具备您通常用于 A/B 测试的所有功能，例如控制模型流量、实验、跟踪结果、对比等。

不过，您可以结合 Vertex AI 模型评估功能与 Vertex AI 模型监控来创建一套 A/B 测试方案。此功能目前处于实验性版本。

Vertex AI 模型评估功能允许您运行模型评估作业（在测试数据集上衡量模型性能），而无论使用哪种 Vertex 服务来训练模型（AutoML、托管流水线、自定义训练等），并可在 Vertex AI 模型注册表中跨多个模型存储和可视化评估结果。凭借这些功能，Vertex AI 模型评估使用户能够决定哪些模型可以进入在线测试或投入生产，以及一旦投入生产后，何时需要重新训练模型。

## 取消部署端点

如果您没有关键业务需求，仅需在一天中的几个小时或工作日期间让端点保持运行，则需要取消部署这些端点。运行中的端点会产生费用。因此，最好在不使用时取消部署它们。您可以使用 `undeploy` 函数来取消部署，如以下 Python 代码片段所示：

```
deployed_model_id = endpoint.list_models()[0].id
endpoint.undeploy(deployed_model_id=deployed_model_id)
```

## 发送在线解释请求

如果您已为模型配置了 Vertex Explainable AI，则可以获取在线解释。在线解释请求的格式与在线预测请求相同，返回的响应也类似；唯一的区别在于在线解释响应除了包含预测结果外，还包含特征归因。以下示例 Python 代码使用 Vertex AI Python SDK 发送在线解释请求：

```
aiplatform.init(project=project, location=location)

endpoint = aiplatform.Endpoint(endpoint_id)

response = endpoint.explain(instances=[instance:dict], parameters={})
```

# 批量预测

在批量预测中，您需要指向 Google Cloud Storage 中的模型和输入数据（生产数据），并运行批量预测作业。该作业使用模型对输入数据运行预测，并将预测输出保存在 Cloud Storage 中。

您需要确保输入数据的格式符合 AutoML 模型（视觉、视频、图像、文本、表格）或自定义模型（预构建容器或自定义容器）的要求。要从自定义训练模型获取批量预测，请按照 [表 10.2](#c10.xhtml#c10-tbl-0002) 中所述的方式之一来准备输入数据。

**表 10.2** Vertex AI 中批量训练的输入数据选项

| 输入 | 说明 |
| --- | --- |
| JSON Lines | 使用 JSON Lines 文件指定要进行预测的输入实例列表。将 JSON Lines 文件存储在 Cloud Storage 存储桶中。 |
| TFRecord | 您可以选择使用 gzip 压缩 TFRecord 文件。将 TFRecord 文件存储在 Cloud Storage 存储桶中。Vertex AI 将 TFRecord 文件中的每个实例读取为二进制数据，然后对实例进行 base64 编码，作为一个键名为 `b64` 的 JSON 对象。 |
| CSV 文件 | 在 CSV 文件中每行指定一个输入实例。第一行必须为表头行。您必须用双引号 (") 括起所有字符串。 |
| 文件列表 | 创建一个文本文件，其中每一行为指向文件的 Cloud Storage URI。示例：`gs://path/to/image/image1.jpg`。 |
| BigQuery | 将 BigQuery 表指定为 `projectId.datasetId.tableId`。Vertex AI 将表中的每一行转换为一个 JSON 实例。 |

与在线预测类似，您可以使用 Vertex AI API 或 Google Cloud 控制台来创建批量预测作业（请参阅 [图 10.7](#c10.xhtml#c10-fig-0007)）。

![图 10.7 控制台中的批量预测作业](images/c10f007.png)

# 在 Google Cloud 上托管第三方流水线 (`MLflow`)

在本节中，我们将介绍在 Google Cloud 上托管特定于 MLflow 的第三方流水线的各种方式。MLflow (`https://mlflow.org/docs/latest/concepts.html`) 是一个用于管理端到端机器学习生命周期的开源平台。它与库无关，您可以将其与任何机器学习库以及任何编程语言配合使用。它主要解决四大功能：

*   **MLflow Tracking** 用于实验跟踪，以及记录和对比参数与结果。您可以将其视为类似于 Vertex AI Experiments，后者用于在 Vertex AI 中跟踪实验。我们将在即将到来的 [第 14 章](#c14.xhtml) 中介绍实验。
*   **MLflow Projects** 用于以可重用、可复现的形式打包 ML 代码，以便与其他数据科学家共享或迁移至生产环境。
*   **MLflow Models** 用于管理和部署来自各种 ML 库的模型，以适配各种模型服务和推理平台。
*   **MLflow Model Registry** 用于提供一个中央模型存储，协作管理 MLflow Model 的完整生命周期，包括模型版本控制、阶段转换和注解。这类似于 Vertex AI Model Registry，后者是一个集中存储模型、支持版本控制和注解的场所。

您可以单独使用这些组件中的每一个。例如，您可能只想使用 MLflow 来跟踪实验，而不使用 MLflow Model Registry 或 Projects。

您会在 Google Cloud 上使用 MLflow，以利用 Google Cloud Vertex AI 平台为模型训练和托管提供的可扩展性和可用性。您可以访问 GPU、TPU 和 CPU 等高性能计算资源，在 Google Cloud 上运行 MLflow 训练和托管工作负载。

要在 Google Cloud 上运行或安装 MLflow：

*   创建一个 PostgreSQL 数据库，用于存储模型元数据。
*   创建一个 Google Cloud Storage 存储桶，用于存储工件。
*   创建一个 Compute Engine 实例来安装 MLflow 并运行 MLflow 服务器，或者您可以在 Kubernetes 上使用 Docker 环境运行 MLflow Projects。
