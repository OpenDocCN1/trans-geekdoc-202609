

## 异步

在这种方法中，最终用户可能不会直接查询模型端点。最终用户可能会收到通知，或者轮询特征存储或数据存储以实时获取预测。这可以通过以下两种方法发生：

### 推送

模型生成预测并将它们作为通知推送给最终用户。例如，在欺诈检测中，当识别出潜在的欺诈交易时，如果您想通知其他系统采取行动，则会使用此方法。请参阅[图 5.5](#c05.xhtml#c05-fig-0005) 以供参考。

### 轮询

模型生成预测并将它们存储在低延迟读取数据库中，例如 NoSQL 数据存储。最终用户定期轮询数据库以获取可用的预测。一个例子是定向营销，系统会实时检查活跃客户的预测倾向评分，以决定是否发送带有促销或挽留优惠的电子邮件。

**[图 5.5](#c05.xhtml#R_c05-fig-0005)** 在线预测的推送通知架构

最小化延迟以提供预测对于实时用例非常重要。这可以在这两个层面发生：

### 在模型层面最小化延迟

您需要最小化模型在收到请求时进行预测所需的时间。您可以通过构建更小的模型来最小化延迟，因为它将拥有更少的神经网络层，并且处理预测所需的计算量更少。

您可以使用 Cloud GPU 和 `TPU` 等加速器来提供模型端点服务。通常，只有当您拥有大型深度学习模型和大批次大小时，才会使用 `TPU`。

### 在服务层面最小化延迟

这是您最小化系统在收到请求时提供预测所需时间的地方。这包括将输入特征存储在低延迟读取查找数据存储中，在离线批量评分作业中预计算预测，以及缓存预测。

## 摘要

在本章中，我们讨论了在 Google Cloud Platform (`GCP`) 上设计可靠、可扩展和高可用 ML 解决方案的最佳实践。然后我们讨论了何时使用 `GCP` AI/ML 技术栈三层中的哪项服务。我们介绍了用于在集成的 Vertex AI 平台中使用 `BigQuery` 管理数据的数据收集和数据管理策略。我们还介绍了用于亚毫秒级和毫秒级延迟的数据存储选项，例如 NoSQL 数据存储。然后我们介绍了用于 ML 流水线的自动化和编排技术，例如 `Vertex AI Pipelines`、`Kubeflow Pipelines` 和 `TFX pipelines`。

我们讨论了如何使用批处理模式和实时模式来提供模型服务以进行预测。我们介绍了一些架构模式，用于使用 `Vertex AI Prediction` 创建批量预测以及在线预测。最后，我们讨论了在使用实时服务时提高模型延迟的一些方法。

## 复习题

1.  您在一家在线旅行社工作，该公司还向其他公司出售其网站上的广告位。您被要求预测用户接下来应该看到的最相关网页横幅。安全性对您的公司很重要。模型延迟要求为 `300ms@p99`，库存有数千个网页横幅，您的探索性分析表明导航上下文是一个很好的预测因子。

    您想要实现最简单的解决方案。应该如何配置预测流水线？

    1.  在网站上嵌入客户端，然后在 Vertex AI 平台预测上部署模型。
    2.  在网站上嵌入客户端，在 `App Engine` 上部署网关，然后在 Vertex AI 平台预测上部署模型。
    3.  在网站上嵌入客户端，在 `App Engine` 上部署网关，在 `Cloud Bigtable` 上部署数据库以写入和读取用户的导航上下文，然后在 Vertex AI Prediction 上部署模型。
    4.  在网站上嵌入客户端，在 `App Engine` 上部署网关，在 `Memorystore` 上部署数据库以写入和读取用户的导航上下文，然后在 Google Kubernetes Engine (`GKE`) 上部署模型。

2.  您正在使用 `TensorFlow` 训练一个模型，该模型基于存储在多个 `CSV` 文件中的 1000 亿条记录的结构化数据集。您需要提高输入/输出执行性能。应该怎么做？

    1.  将数据加载到 `BigQuery` 中并从 `BigQuery` 读取数据。
    2.  将数据加载到 `Cloud Bigtable` 中，并从 `Bigtable` 读取数据。
    3.  将 `CSV` 文件转换为 `TFRecords` 分片，并将数据存储在 Google Cloud Storage 中。
    4.  将 `CSV` 文件转换为 `TFRecords` 分片，并将数据存储在 Hadoop 分布式文件系统 (`HDFS`) 中。

3.  您是一名数据工程师，正在为基于登录用户信息的电子商务网站产品推荐系统构建 ML 模型。您将使用 `Pub/Sub` 处理传入请求。您想存储结果以进行分析和可视化。应该如何配置流水线？

    `Pub/Sub` -> `预处理(1)` -> `ML 训练/服务(2)` -> `存储(3)` -> Data studio/Looker studio 进行可视化

    1.  `1 = Dataflow`，`2 = Vertex AI 平台`，`3 = Cloud BigQuery`
    2.  `1 = Dataproc`，`2 = AutoML`，`3 = Cloud Memorystore`
    3.  `1 = BigQuery`，`2 = AutoML`，`3 = Cloud Functions`
    4.  `1 = BigQuery`，`2 = Vertex AI 平台`，`3 = Google Cloud Storage`

4.  您正在开发模型对客户支持邮件进行分类。您使用小数据集在本地系统上通过 `TensorFlow Estimator` 创建了模型，但现在需要使用大数据集训练模型以确保高性能。您将模型移植到 Google Cloud，并希望最大限度地减少代码重构和基础设施开销，以便更轻松地从本地迁移到云端。应该怎么做？

    1.  使用 Vertex AI 平台进行分布式训练。
    2.  在 `Dataproc` 上创建集群进行训练。
    3.  创建具有自动扩缩功能的托管实例组。
    4.  使用 `Kubeflow Pipelines` 在 Google Kubernetes Engine 集群上进行训练。

5.  您是一名 `CTO`，希望在 Google Cloud 上实施可扩展的解决方案，以数字化各个孤岛中的文档，例如 `PDF` 文件和 `Word DOC` 文件。您还在寻找在数据湖中存储文档的存储建议。哪些选项所需的基础设施工作量最少？（选择两项。）

    1.  使用 Document AI 解决方案。
    2.  使用 Vision AI OCR 对文档进行数字化。
    3.  使用 Google Cloud Storage 存储文档。
    4.  使用 `Cloud Bigtable` 存储文档。
    5.  使用自定义 Vertex AI 模型构建文档处理流水线。
