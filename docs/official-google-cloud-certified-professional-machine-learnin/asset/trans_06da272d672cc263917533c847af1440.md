
# GPU 和 TPU 硬件加速

GPU 在单个处理器中包含数千个算术逻辑单元（ALU）。因此，GPU 不会为每次操作都访问内存，而是加载一块内存，并利用数千个 ALU 并行应用某些操作，从而使其更快。将 GPU 用于大型矩阵乘法和微分运算，可将速度提高一个数量级。

要使用 GPU，必须使用 A2 或 N1 机器系列。目前 GPU 提供以下类型：

*   `NVIDIA_TESLA_T4`
*   `NVIDIA_TESLA_K80`
*   `NVIDIA_TESLA_P4`
*   `NVIDIA_TESLA_P100`
*   `NVIDIA_TESLA_V100`
*   `NVIDIA_TESLA_A100`

在 `WorkerPoolSpec` 中，在 `machineSpec.acceleratorType` 字段中指定要使用的 GPU 类型，在 `machineSpec.acceleratorCount` 字段中指定工作池中每个 VM 要使用的 GPU 数量。

尝试使用实例类型配置 GPU 时，基于实例类型、实例内存等存在若干限制。部分限制如下：

*   所选 GPU 类型必须在执行自定义训练的位置可用。并非所有类型的 GPU 在所有区域都可用。
    列出可用位置的页面：`cloud.google.com/vertex-ai/docs/general/locations`。
*   存在每个实例的 GPU 数量限制。例如，可在 VM 上使用两个或四个 `NVIDIA_TESLA_T4` GPU，但不能使用三个。Google 提供了完整的参考表，随着更多实例类型和 GPU 的推出，该表可能会发生变化；请参阅下方提示中的链接。
*   GPU 配置必须具有与之匹配的机器类型相比足够的虚拟 CPU 和内存。例如，如果在工作池中使用 `n1-standard-16` 机器类型，则每个 VM 拥有 16 个虚拟 CPU 和 60 GB 内存。由于每个 `NVIDIA_TESLA_V100` GPU 最多可提供 12 个虚拟 CPU 和 76 GB 内存，因此每个 `n1-standard-16` VM 必须至少使用 2 个 GPU 以满足其要求。（一个 GPU 资源不足，且无法指定 3 个 GPU。）

## TPU

随着 ML 工程师使用 GPU 训练超大型神经网络，他们开始注意到下一个瓶颈。GPU 仍是一种半通用处理器，必须支持包括视频处理软件在内的许多不同应用。因此，GPU 与 CPU 存在相同的问题。对于数千个 ALU 中的每次计算，GPU 都必须访问寄存器或共享内存以读取操作数并存储中间计算结果。为将性能提升到新水平，Google 设计了 TPU。

张量处理单元（TPU）是 Google 专门为机器学习工作负载设计的专用硬件加速器。请参阅[图 4.5](#c04.xhtml#c04-fig-0005) 了解 TPU-v4 的系统架构。

![图 4.5 TPU 系统架构](images/c04f005.png)

**[图 4.5](#c04.xhtml#R_c04-fig-0005) TPU 系统架构**

CPU 中的 ALU 一次执行一项操作，而每个 TPU 拥有多个矩阵乘法单元（MXU）。

每个 MXU 拥有 128 × 128 个乘累加器。每个 MXU 每个周期可使用 `bfloat16` 数字格式执行 16,000 次乘累加运算。

TPU 的主要任务是矩阵处理，这是乘法和累加运算的组合。TPU 包含数千个直接相连的乘累加器，形成一个大型物理矩阵。

TPU 可对巨大矩阵执行海量运算，而这正是神经网络训练循环的核心。

### 如何使用 TPU

TPU 可组成称为 Pod 的群组，只需极少或无需代码更改即可扩展工作负载。

Cloud TPU 提供以下 TPU 配置：

*   单个 TPU 设备
*   TPU Pod（由高速互连连接的一组 TPU 设备）
*   TPU 切片（TPU Pod 的一个细分）
*   TPU VM

### TPU 的优势

TPU 将计算速度提升到超越 GPU 的水平。在 CPU 上需数月训练的模型，在 GPU 上可能仅需数天，而在 TPU 上可能只需数小时。简单来说，TPU 相较于 GPU 可提供一个数量级的性能提升。

### 何时使用 CPU、GPU 和 TPU

TPU 适合特定工作负载，但在某些情况下，使用 GPU 甚至 CPU 可能更好。以下是为您的用例选择合适硬件的指南：

*   **CPU**
    *   需要灵活性的快速原型设计
    *   训练速度快的模型
    *   适用小批量的小型模型
    *   使用 C++ 编写的自定义 TensorFlow 操作
    *   受限于主机的可用 I/O 或网络带宽

*   **GPU**
    *   源代码不存在或更改过于繁琐的模型
    *   包含大量自定义 TensorFlow 操作、因此至少需部分在 CPU 上运行的模型
    *   包含 TPU 上不可用的 TensorFlow ops 的模型
    *   中大型模型搭配中等批量

*   **TPU**
    *   以矩阵计算为主的模型
    *   无自定义 TensorFlow 操作的模型
    *   训练时间长达数周或数月的模型
    *   具有超大有效批量的大型和超大型模型

Cloud TPU **不**适合以下工作负载：

*   需要频繁分支（if/else 或条件判断）或以元素级代数为主的程序。TPU 非为执行条件判断而设计，而是为大规模矩阵乘法而设计。
*   稀疏数据（包含大量零值、仅极少非零值的数据），会导致稀疏内存访问，不适用。
*   高精度场景不适合 TPU。勿期望双精度运算。
*   包含使用 C++ 编写的自定义 TensorFlow 操作的深度神经网络，特别是主要训练循环中的自定义操作不适合 TPU 的情况。

要有效发挥 TPU 优势，应在 TPU 上运行训练循环的多次迭代。这非理论要求，而是为消除否则将导致的显著低效而提出的实际要求。您可在 `https://cloud.google.com/tpu/docs/tpus` 文档中找到这些指南及更多 TPU 信息。

#### Cloud TPU 编程模型

使用 TPU 时的主要瓶颈是 Cloud TPU 与主机内存之间的数据传输。该数据传输通过 PCIe 总线进行，其速度远慢于 TPU 互连和片上高带宽内存（HBM）。若使用模型的部分编译（部分在 TPU 上执行，其余在主机上执行），TPU 将处于空闲等待数据状态。正确的编程模型是在 TPU 上执行训练循环的大部分，理想情况下是全部。

# 预测阶段的资源预配

上一节探讨了训练阶段的硬件预配方面。本节将探讨预测阶段。

预测工作负载与训练工作负载截然不同。训练期间，我们将预配置在特定时长内使用、完成后释放的资源。

预测可通过两种方式进行：在线和批量。在线预测是指模型部署在服务器上，可通过 REST 等便捷接口查询。此处预期响应时间接近实时。批量预测是指大量输入数据已就绪并存储，预测作为“批量作业”启动。此处用户预期作业在合理时间内完成（非实时），但重点关注预测成本。
