
### Clipping

在极端异常值的情况下，可以将所有高于或低于某个固定值的特征值限制在该值。可以在其他归一化技术之前或之后执行特征裁剪。

### Handling Outliers

异常值是指与其他数据点相距甚远、过大或过小的观测值。它们可能因人为错误或数据倾斜而存在。

需要使用以下可视化技术和统计技术（其中一些在前面章节已讨论）来检测异常值：

*   箱线图
*   Z-score
*   裁剪
*   四分位距（IQR）

一旦检测到异常值，可以将其从数据集中移除以免影响模型训练，也可以使用均值、中位数、众数或边界值进行插补或替换。

## Establishing Data Constraints

数据分析和探索过程会产生关键洞察和结果，例如数据质量问题（缺失值、异常值和类型转换）。

为了进行一致且可复现的检查，需要通过为 ML 流水线定义模式来建立数据约束。

带有定义元数据的模式描述了数据的属性，例如数据类型（数值型与分类型）、允许范围、格式以及数据值的分布。模式是数据分析过程的输出。

拥有模式的优势如下：

*   对于特征工程和数据转换，分类数据和数值数据都需要转换。模式支持元数据驱动的预处理。
*   可以使用数据模式验证新数据，并在训练和预测期间捕捉偏斜和异常值等异常情况。

### Exploration and Validation at Big-Data Scale

数据量正在快速增长。训练深度神经网络需要大量数据。验证这些大型数据集的挑战在于数据需要在内存中进行验证。需要多台机器来扩展大型数据集的数据验证规模。

`TensorFlow Data Validation`（TFDV）可用于大规模理解、验证和监控 ML 数据（参见[图 2.5](#c02.xhtml#c02-fig-0005)）。

TFDV 用于检测数据中的数据异常和模式异常。它是 `TensorFlow Extended`（TFX）平台的一部分，为 ML 流水线中的大型数据集提供数据验证和模式验证库。关键的 TFX 库包括：`TensorFlow Data Validation`、`TensorFlow Transform`（用于数据预处理和特征工程）、`TensorFlow Model Analysis`（用于 ML 模型评估和分析）以及 `TensorFlow Serving`（用于服务 ML 模型）。

![FIGURE 2.5 TensorFlow Data Validation](images/c02f005.png)

[**图 2.5**](#c02.xhtml#R_c02-fig-0005) TensorFlow Data Validation

TFDV 的使用方式如下：

*   **探索性数据分析阶段** 可以使用 TFDV 生成数据模式，以了解 ML 流水线的数据。此模式可作为 ML 流水线与数据之间的定义契约。每当模式被违反时，需要修复数据或流水线。
*   **生产流水线阶段** 模型部署后，此模式可用于定义基线，以检测训练和服务期间导致模型偏斜或漂移的任何新数据。

## Running TFDV on Google Cloud Platform

TFDV 核心应用程序编程接口（API）构建在用于构建批处理和流式处理流水线的 Apache Beam 开源软件开发工具包（SDK）之上。`Dataflow` 是一项托管服务，可大规模运行 Apache Beam 数据处理流水线。

`Dataflow` 与数据仓库无服务器服务 `BigQuery` 和数据湖（`Google Cloud Storage`）以及 `Vertex AI Pipelines` 机器学习原生集成。

## Organizing and Optimizing Training Datasets

在上一节中，你学习了如何检查数据质量。本节将讨论数据采样、不平衡数据以及如何划分数据集。我们通常将数据划分为训练集、测试集和验证集（参见[图 2.6](#c02.xhtml#c02-fig-0006)）。

![FIGURE 2.6 Dataset representation](images/c02f006.png)

[**图 2.6**](#c02.xhtml#R_c02-fig-0006) 数据集表示

*   **训练数据集** 这是用于训练模型的实际数据集，模型从此数据中学习。
*   **验证数据集** 这是用于模型评估的数据子集。此数据用于超参数调优。模型不使用此数据进行学习（这与训练数据不同）。它用于在训练后改进模型行为。
*   **测试数据集** 这是用于测试或评估模型性能的数据样本。测试集不同于训练集和验证集，因为它在模型训练和验证后使用。测试集不应包含验证集或训练集中的数据样本，因为这可能导致数据泄露。此外，绝不应使用测试集训练数据。

### Imbalanced Data

当数据集中的两个类别不相等时，结果就是不平衡数据。如[图 2.7](#c02.xhtml#c02-fig-0007)所示，数据集中信用卡欺诈的可能性比非欺诈小得多。

以信用卡交易为例，假设在所有交易中，1000 笔非欺诈，仅 5 笔欺诈。这是不平衡数据的典型表现。在这种情况下，没有足够的交易来训练模型对信用卡交易是否为欺诈进行分类。训练模型将花费更多时间在非欺诈场景上。

在随机采样中，可以执行*过采样*（复制少数类样本）或*欠采样*（删除多数类样本）。这两种方法都会引入偏差，因为它们通过引入更多或更少的样本来消除不平衡。

![FIGURE 2.7 Credit card data representation](images/c02f007.png)

[**图 2.7**](#c02.xhtml#R_c02-fig-0007) 信用卡数据表示

现在考虑前面的例子，对多数类（非欺诈示例）进行降采样。按 10 倍降采样将改善平衡（参见[图 2.8](#c02.xhtml#c02-fig-0008)）。

![FIGURE 2.8 Downsampling credit card data](images/c02f008.png)

[**图 2.8**](#c02.xhtml#R_c02-fig-0008) 信用卡数据降采样

现在对降采样的类别增加权重。由于我们按 10 倍因子降采样，示例权重应为 10。*示例权重*意味着在训练期间将单个示例视为更重要。示例权重为 10 意味着模型将该示例视为比权重为 1 的示例重要 10 倍（在计算损失时）。请参考 `https://developers.google.com/machine-learning/data-prep/construct/sampling-splitting/imbalanced-data` 了解更多信息。

对多数类进行降采样并增加降采样类别权重的优势之一是模型收敛更快，因为与降采样和加权之前的数据相比，我们拥有更多的少数类示例。

### Data Splitting

通常在通用数据清洗中，会从数据的随机划分开始。例如，考虑具有天然聚类示例的数据集。

假设你想让模型对书籍文本中的主题进行分类。主题可以是恐怖、爱情故事和戏剧。在这种情况下，随机划分会是一个问题。

为什么随机划分会导致偏斜？因为同类主题的故事写在同一时间线上。如果数据随机划分，测试集和训练集可能包含相同的故事。
