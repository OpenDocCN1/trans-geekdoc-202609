## 8. 基于 GCS 新数据自动触发 Kubeflow 训练

你与一个数据工程团队合作，该团队开发了一个管道来清理数据集并将其保存在 `Google Cloud Storage` 存储桶中。你已经创建了一个 ML 模型，并希望在新数据可用时立即使用该数据刷新模型。作为 CI/CD 工作流的一部分，你希望在 `Google Kubernetes Engine (GKE)` 上自动运行 `Kubeflow Pipelines` 训练作业。应如何设计此工作流架构？

1.  配置带有 `Dataflow` 的管道，将文件保存在 `Google Cloud Storage` 中。文件保存后，在 `GKE` 集群上启动训练作业。
2.  使用 `App Engine` 创建一个轻量级 Python 客户端，持续轮询 `Google Cloud Storage` 以查找新文件。一旦文件到达，立即启动训练作业。

4.  使用 `Cloud Scheduler` 按固定时间间隔调度作业。作为作业的第一步，检查 `Google Cloud Storage` 存储桶中对象的时间戳。如果自上次运行以来没有新文件，则中止作业。

## 构建安全的 ML 系统

任何企业的关键任务之一是帮助确保其用户和员工数据的安全。Google Cloud 提供内置的安全措施来促进数据安全，包括静态数据加密和传输中数据加密。让我们看看云系统中的静态加密和传输加密分别是什么。

### 静态加密

对于机器学习模型，你的数据将位于 `Cloud Storage` 或 `BigQuery` 表中。Google 默认对 `Cloud Storage` 和 `BigQuery` 中静态存储的数据进行加密。默认情况下，Google 管理用于保护数据的加密密钥。你也可以使用客户管理的加密密钥 (CMEK)。你可以使用带关联数据的认证加密 (AEAD) 加密函数在 `BigQuery` 中加密单个表值。请参考 `https://cloud.google.com/bigquery/docs/reference/standard-sql/aead-encryption-concepts` 以了解 `BigQuery` AEAD 加密函数。
