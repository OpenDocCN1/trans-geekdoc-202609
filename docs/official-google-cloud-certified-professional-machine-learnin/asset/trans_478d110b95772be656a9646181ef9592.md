# 数据收集与数据管理

Google Cloud 提供了多种数据存储，以满足您对特征在延迟、负载、吞吐量和规模方面的组合要求：

*   Google Cloud Storage
*   BigQuery
*   `Vertex AI's datasets`，用于管理训练集和标注集
*   Vertex AI Feature Store
*   NoSQL 数据存储

## Google Cloud Storage (GCS)

Google Cloud Storage 是一项在 Google Cloud 中存储对象的服务。您可以使用 GCS 存储图像、视频、音频和非结构化数据。您可以将这些单独的数据类型合并为大小至少为 100 MB 的大文件（https://cloud.google.com/architecture/ml-on-gcp-best-practices#store-image-video-audio-and-unstructured-data-on-cloud-storage），并分成 100 到 10,000 个分片，以提高读写吞吐量。如果您使用 TensorFlow，这适用于分片 TFRecord 文件；如果您使用任何其他框架，则适用于 Avro 文件。

## BigQuery

最佳实践是将表格数据存储在 BigQuery 中。对于训练数据，最好将数据作为表存储，而不是视图，以获得更好的速度。可以通过以下方式使用 BigQuery 功能：

*   Google Cloud 控制台，搜索 BigQuery
*   `bq` 命令行工具
*   BigQuery REST API
*   使用 BigQuery Magic 或 BigQuery Python 客户端的 Vertex AI Jupyter Notebook。

## Vertex AI 托管数据集

Google Cloud 建议使用 Vertex AI 托管数据集来训练自定义模型，而不是编写训练应用以直接从 Google Cloud Storage 或本地存储等存储系统中摄取训练数据。主要支持四种数据格式：图像、视频、表格（CSV、BigQuery 表）和文本。

使用托管存储的优势如下：

*   在中心位置管理数据集。
*   使用 Vertex AI 数据标注，对视频、文本和图像等未标注的非结构化数据进行集成数据标注。
*   易于追踪模型谱系，以便进行治理和迭代开发。
*   使用相同的数据集训练 AutoML 和自定义模型，以对比模型性能。
*   生成数据统计信息和可视化结果。
*   自动将数据拆分为训练集、测试集和验证集。

当您拥有未标注的非结构化数据时，可以使用 Vertex AI 数据标注服务，对 Google Cloud Storage 或 Vertex AI 托管数据集中的数据进行标注。这只是一项标注数据的服务，并不存储数据。您可以使用第三方众包标注人员或您自己的标注人员来标注数据。

## Vertex AI Feature Store

Vertex AI Feature Store 是一个全代管的中心化存储库，用于组织、存储和服务 ML 特征。您可以独立使用 Vertex AI Feature Store，也可以将其作为 Vertex AI 工作流的一部分使用。例如，您可以从 Vertex AI Feature Store 获取数据，在 Vertex AI 中训练自定义模型或 AutoML 模型。当您使用结构化数据训练模型时，用户可以定义特征，然后从各种数据源摄取（导入）特征值。任何获授权的用户都可以搜索并从 Feature Store 检索值。例如，您可以查找特征，然后执行批量导出以获取用于创建 ML 模型的训练数据，或者如果特征不存在，则创建一个新特征。您还可以实时检索特征值，以执行快速在线预测。

使用 Feature Store 的好处是，您无需计算特征值并将它们保存在各种位置，例如 BigQuery 中的表和 Google Cloud Storage 中的文件。此外，由于特征是在中心化的方式下创建的，Feature Store 可以帮助检测漂移并缓解数据倾斜。

## NoSQL 数据存储

对于预测期间的静态特征查找，BigQuery 等分析型数据存储并非为低延迟的单例读取操作而设计，此类操作的结果是包含许多列的单行数据。此类查询的示例是“为特定客户 ID 从多个表中选择 100 列”。因此，静态参考特征会被收集、准备并存储在针对单例查找操作进行了优化的 NoSQL 数据库中。

[表 5.4](#c05.xhtml#c05-tbl-0004) 显示了 Google Cloud 中托管数据存储的 NoSQL 数据存储选项。作为 ML 专家，我们曾使用 Memorystore 处理需要亚毫秒级延迟的用例。我们曾在延迟可达毫秒级的用例中使用数据存储来存储用户登录详细信息，并使用 Bigtable 处理具有动态变化数据的毫秒级延迟场景。

**表 5.4** NoSQL 数据存储选项

| | Memorystore | Datastore | Bigtable |
| --- | --- | --- | --- |
