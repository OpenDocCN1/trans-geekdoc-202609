
管理对数据集、模型等各种不同资源的访问，以及提供执行训练、部署和监控等各种操作的权限至关重要。身份与访问管理 (IAM) 是强制执行此操作的机制。请参阅 [第 6 章](#c06.xhtml)“构建安全的 ML 流水线”，了解关于 IAM 的讨论。

您可能已经有 GCP IAM 模型的经验——例如在 Compute Engine 或 Google Cloud Storage 中——这将派上用场。

强调遵循最佳实践以使用 IAM 安全性非常重要。以下是一些高层级要点：

*   **最小权限：** 限制用户和应用仅执行必要的操作。
*   **管理服务账号和服务账号密钥：** 积极管理这些安全资产并定期检查它们。
*   **审计：** 启用审计日志并使用 Cloud Logging 角色。
*   **策略管理：** 使用更高层级的检查，确保策略在每个层级得到实施。

有关 IAM 最佳实践的更多详细信息，请参阅此网址：

`https://cloud.google.com/blog/products/identity-security/iam-best-practice-guides-available-now`

我们了解了通用的 IAM 最佳实践，现在将了解 Vertex AI 的一些特殊情况。

### 自定义服务账号

当您运行 Vertex AI 训练作业时，它会使用 Google 为您的 Google Cloud 项目自动创建的几个*服务账号*之一。然而，这些服务账号可能拥有超出需求的权限，例如访问 BigQuery 和 GCS 的权限。最好使用仅具有所需权限集的自定义服务账号。

### Vertex AI 中的访问透明度

要验证谁在访问您的内容以及访问了什么内容，您需要日志。在许多领域，对此类日志记录有法律和合规性要求。重要的是，它还为您提供访问日志，记录 Google 人员在您项目中的操作。有两种类型的访问日志。*Cloud Audit 日志* 是您组织中用户的日志。*Access Transparency 日志* 是 Google 人员的日志。大多数服务都支持此功能，但有一些功能不在覆盖范围内。

有关支持的服务的完整列表，请参阅此网址：

`https://cloud.google.com/vertex-ai/docs/general/access-transparency`

## 常见训练和服务错误

在以下部分中，我们将了解训练和服务期间常见的一些错误。了解错误类型将帮助您有效地调试问题。虽然错误取决于所使用的框架，但我们将在本讨论中使用 TensorFlow 作为框架。

### 训练时错误

在训练阶段，当您运行 `Model.fit()` 时会看到最相关的错误。当发生以下情况时会出现错误：

1.  输入数据未转换或未编码。
2.  张量形状不匹配。
3.  由于实例大小（CPU 和 GPU）导致内存溢出错误。

### 服务时错误

服务时错误仅在部署期间出现，错误的性质也不同。典型错误如下：

1.  输入数据未转换或未编码。
2.  发生签名不匹配。

有关 TensorFlow 错误的完整列表，请参阅此网址：

`www.tensorflow.org/api_docs/python/tf/errors`

### TensorFlow 数据验证

为了防止和减少这些错误，您可以使用 TensorFlow 数据验证 (TFDV)。TFDV 可以按如下方式分析训练和服务数据：

1.  计算统计信息
2.  推断架构
3.  检测异常

有关完整文档，请参阅此处：

`https://cloud.google.com/vertex-ai/docs/training/monitor-debug-interactive-shell`

### Vertex AI 调试 Shell

Vertex AI 提供了一个交互式 Shell 来调试预构建容器和自定义容器的训练。您可以使用交互式 Shell 检查训练容器，以调试训练代码或 Vertex AI 配置中的问题。使用它，您可以执行以下操作：

1.  运行跟踪和分析工具。
2.  分析 GPU 利用率。
3.  验证容器的 IAM 权限。

有关完整文档，请参阅此网址：

`https://cloud.google.com/vertex-ai/docs/training/monitor-debug-interactive-shell`

## 摘要

在本章中，我们探讨了 ML 应用的长期维护。ML 运维或 MLOps 基于维护软件应用的 CI/CD 原则。在此过程中，我们了解了如何自动化训练、部署和监控。模型的重新训练策略是一个重要概念，必须在模型质量和训练成本之间取得平衡。大型企业中出现的另一个重要问题是部门间无法共享特征，这导致了大量的低效。为了解决这个问题，特征存储的概念应运而生，它可以使用开源软件或 Vertex AI Feature Store 来实现。

## 考试要点

*   **理解 MLOps 成熟度。** 学习 MLOps 的不同成熟度级别以及它们如何与组织目标相匹配。了解实验阶段的 MLOps 架构，然后是具有一定自动化的战略阶段，最后是完全成熟的受 CI/CD 启发的 MLOps 架构。
*   **理解模型版本控制和重新训练触发器。** MLOps 中面临的一个常见问题是知道何时触发新的训练。这可能基于模型监控中观察到的模型性能下降，也可能基于时间。重新训练模型时，了解如何将其作为新版本或新模型添加。
*   **理解特征存储的用途。** 特征工程是一项昂贵的操作，因此使用这些方法生成的特征如果在团队间共享会更有用。Vertex AI Feature Store 是一项托管服务，Feast 是 Google 的开源特征存储。

## 复习题

1.  以下哪项*不是* MLOps 工作流的主要步骤？

    1.  数据处理，包括提取、分析和准备
    2.  与第三方软件集成并识别类似模型的进一步用例
    3.  模型训练、测试和验证
    4.  模型部署、监控和触发重新训练

2.  您是一家历史悠久的零售组织中一个小型 ML 团队的成员，该组织希望开始探索机器学习以预测产品的日销量。在这种情况下，您会实施哪级 MLOps？

    1.  无 MLOps，将临时构建 ML 模型
    2.  MLOps 级别 0
    3.  MLOps 级别 1
    4.  MLOps 级别 2

3.  您是一名数据科学家，作为 ML 团队的一员，该团队已为其在线时尚零售店尝试过 ML。您构建的模型将客户与合适尺寸/版型的衣服进行匹配。组织决定大力推进此项工作，您负责领导这项工作。您将在此实施哪级 MLOps？

    1.  无 MLOps，将临时构建 ML 模型
    2.  MLOps 级别 0
    3.  MLOps 级别 1
    4.  MLOps 级别 2

4.  您受聘为一家处理照片和图像的大型组织的 ML 工程师。该团队创建模型来识别照片中的物体、人脸和照片方向（以自动旋转），还创建模型来调整照片颜色。该组织还在尝试可以根据文本自动创建图像的新算法。您会推荐哪级 MLOps？

    1.  无 MLOps，临时构建，因为他们使用新算法
    2.  MLOps 级别 0
    3.  MLOps 级别 1
    4.  MLOps 级别 2

5.  MLOps 级别 0 解决什么问题？

    1.  它是临时构建模型，因此不解决任何问题。
    2.  它自动化训练，使构建模型成为一个可重复的过程。
    3.  模型训练是手动的，但在模型移交后部署是自动化的。
