
与训练工作负载相比，预测（尤其是在线预测）是一种持续性工作负载，也需要根据需求持续地扩容或缩容。批量预测工作负载与这两者也有显著差异。

在此背景下，为预测配置资源时最重要的两个考量因素是扩缩容行为和寻找理想的机器类型。让我们详细了解这两个考量因素。

### 扩缩容行为

如果您使用自动扩缩容配置，`Vertex AI` 会在现有节点的 `CPU` 使用率变高时自动扩容以使用更多预测节点。如果您使用的是 `GPU` 节点，请务必配置适当的触发器，因为有三种资源（`CPU`、内存和 `GPU`）需要监控其使用情况。

### 寻找理想的机器类型

要从成本角度确定自定义预测容器的理想机器类型，请将该容器作为 `docker` 容器直接部署到 `Compute Engine` 实例，然后通过调用预测接口对实例进行基准测试，直到实例达到 90% 以上的 `CPU` 利用率。确定不同机器类型的*每秒查询数成本（QPS cost per hour）*。例如，如果自定义容器包含一个只能有效利用 1 个核心的 `Python` Web 服务器进程，而该进程调用的是多线程 `ML` 模型（如大多数 `XGBoost` 实现），随着 `QPS` 增加，Web 服务器将开始“阻塞” `XGBoost`，因为每次 `XGBoost` 预测都将等待 Web 服务器进程。如果部署到 2 核或 4 核机器规格上，容器将触及 `QPS` 限制且 `CPU` 利用率会很高，因此该容器部署到 `Vertex AI` 后将能有效地自动扩缩容。

请注意自定义容器中单线程 Web 服务器的局限性；即使部署在 32 核机器规格上，它也可能无法扩容。

因此，您需要综合考虑模型类型、自定义模型情况下的服务封装代码、资源（`CPU`、内存、 `GPU`）的有效利用率、延迟和吞吐量要求以及价格，以确定要使用的实例类型。

您可以选择使用 `GPU` 来加速预测，但存在一些限制。限制如下：

*   `GPU` 只能用于 `TensorFlow SavedModel`，或用于经过设计可利用 `GPU` 的自定义容器。您不能将 `GPU` 用于 `scikit-learn` 或 `XGBoost` 模型。
*   `GPU` 在某些地区不可用。
*   每个 `DeployedModel` 资源或 `BatchPredictionJob` 只能使用一种类型的 `GPU`，并且根据您使用的机器类型，可添加的 `GPU` 数量存在限制。

以上考量因素针对的是云端预测。在许多用例中，训练好的模型需要部署在边缘设备上。让我们在下文探讨这些用例。

### Edge TPU

物联网（`IoT`）的重要组成部分是边缘设备。这些设备收集实时数据、做出决策、采取行动，并与其他设备或云端通信。由于此类设备带宽有限，有时可能完全离线运行，因此在设备本身上运行推理（称为*边缘推理*）的需求日益增长。

`Google` 设计的 `Edge TPU` 协处理器可加速这些边缘设备上的 `ML` 推理。单个 `Edge TPU` 仅消耗 2 瓦功率，即可执行每秒 4 万亿次运算（4 `TOPS`）。

`Edge TPU` 为您的原型和生产设备提供多种外形规格，包括单板计算机、系统级模块、 `Edge TPU` 本身及所有可用产品。这些产品以 `Coral.ai` 品牌销售。

### 部署到 Android 或 iOS 设备

`ML Kit`（`https://developers.google.com/ml-kit`）将 `Google` 的机器学习专业知识以功能强大且易于使用的软件包形式带给移动开发者。您可以利用针对设备端运行进行优化的解决方案，使您的 `iOS` 和 `Android` 应用更具吸引力、个性化和实用性。

您可以在 `Google Cloud` 上训练 `ML` 模型，使用 `AutoML` 或自定义模型，并将模型部署到您的 `Android` 或 `iOS` 应用中。预测在设备端进行，以实现低响应时间、节省带宽，并支持离线模式下的预测。

## 总结

在本章中，您了解了 `Google Cloud` 上可用的不同预训练模型。您还了解了 `AutoML` 模型及其在不同场景下的适用性。在本章的主要部分，您了解了可用于训练模型的不同硬件选项，以及训练工作负载和预测工作负载的区别。`Google Cloud` 以 `GPU` 和 `TPU` 的形式为您提供了各种硬件加速器。最后，超越云端，您了解了部署到边缘设备的理念。

## 考试要点

*   **选择正确的 ML 方法。** 了解需求，以在预训练模型、`AutoML` 或自定义模型之间进行选择。了解解决方案的就绪程度、灵活性和方法。
*   **为训练配置正确的硬件。** 了解可用于机器学习的各种硬件选项。同时了解 `GPU` 和 `TPU` 硬件的要求以及支持专用硬件的实例类型。还要了解训练和部署中的硬件差异。
*   **为预测配置正确的硬件。** 了解训练时配置和预测时配置的区别。预测的要求通常是可扩展性以及 `CPU` 和内存限制，因此云端使用 `CPU` 和 `GPU`。然而，边缘设备使用 `TPU`。
*   **了解可用的 ML 解决方案。** 通过使用针对特定领域问题构建的预训练模型和解决方案，采用无服务器方法，而非配置硬件。

## 复习题

1.  您的公司从事房地产业务，作为软件开发团队的一员，您被要求添加一个机器学习模型来识别上传到网站的照片中的物体。您该如何着手？

    1.  使用自定义模型以获得最佳结果。
    2.  使用 `AutoML` 创建目标检测模型。
    3.  从 `Vision AI` 开始，如果不起作用，则使用 `AutoML`。
    4.  结合 `AutoML` 和自定义模型以获得更好的结果。

2.  您的公司正在处理法律文档（数千页），需要将其翻译成西班牙语和法语。您注意到 `Google` 的 `Translation AI` 中的预训练模型效果不错，但有几百个领域特定术语的翻译不符合预期。您没有任何标注数据，公司里只有几位专业翻译。您该怎么做？

    1.  使用 `Google` 翻译服务，然后安排人工介入（`HITL`）逐条修正翻译。
    2.  使用 `Google AutoML Translation` 为您的场景创建新的翻译模型。
    3.  使用 `Google Translation AI` 并搭配您需要的术语“词汇表”。
    4.  因为您似乎没有数据，所以无法翻译。

3.  您正在处理一千小时的西班牙语视频录制，需要创建英语和法语字幕。您已经拥有一个包含数百小时已手动创建字幕的视频的小型数据集。您的首选方法是什么？

    1.  没有“翻译字幕”服务，所以使用 `AutoML` 利用现有数据集创建“字幕”作业，然后使用该模型创建翻译字幕。
    2.  没有“翻译字幕”服务，也没有针对该任务的 `AutoML`，所以您必须使用数据创建自定义模型并在 `GPU` 上运行。
    3.  没有“翻译字幕”服务，也没有针对该任务的 `AutoML`，所以您必须使用数据创建自定义模型并在 `TPU` 上运行。
