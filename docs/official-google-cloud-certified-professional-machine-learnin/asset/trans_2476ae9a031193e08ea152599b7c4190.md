

# 练习题答案与解析

## Chapter 1: 机器学习问题框架

1.  **A, B, D**. 首先理解用例，然后寻找影响、成功标准、预算和时间框架等细节。寻找算法是在后面。

2.  **B**. 超参数是无法学习的变量。你将使用超参数优化（HPO）算法自动找到最佳超参数。当你尝试将业务案例匹配到 ML 问题时，这不在考虑范围内。

3.  **B**. 输入数据是时间序列数据，预测未来 7 天是预测问题的典型特征。

4.  **B**. 预测只有两种输出：有效或无效。这是二分类。如果有两个以上的类别，则是多分类。线性回归是预测数字。选项 C 常用于支持工单以识别主题聚类，但不能用于此场景。

5.  **C**. 当你试图跨多帧识别对象时，这是视频目标跟踪。选项 A 事实上不正确。选项 B 用于图像，而非视频。场景检测或动作检测对视频中是否发生了“动作”进行分类，这是另一类问题，因此选项 D 也是错误的。

6.  **D**. 主题建模是无监督 ML 问题。给定一组文档，它会将它们聚类成组，并提供定义每个聚类的关键词。

7.  **C**. 精确率是不平衡分类问题的指标。

8.  **A**. 如果你试图减少极端误差，均方根误差（RMSE）是最佳选择。

9.  **A**. RMSE、MAPE 和 R2 是回归指标。准确率是此处唯一的分类指标。

10. **C**. 我们可以排除 RMSE，因为它是回归指标。准确率也是错误的，因为它是不平衡（1:100）数据集的不良指标。因此，正确答案是精确率或召回率。在这种情况下，假阴性可能导致严重的后续问题，所以我们要选择最小化假阴性的指标。因此，答案是召回率。

11. **B**. “无标签数据”意味着你不能进行监督学习或半监督学习。强化学习是智能体主动探索环境（如机器人），这与此无关。只有无监督学习可以应用于纯无标签数据。

12. **C**. 此处的“点赞”按钮是用户对内容提供的显式反馈，可用于训练。协同过滤是可用于此类推荐的算法类别。

13. **B**. 选项 B 是坏主意，因为你需要更新与新产品相关的数据。“黄金数据集”的想法存在，但在这种情况下，数据集需要更新。

14. **D**. 有标签数据时使用监督学习。无标签数据时使用无监督学习。混合数据时使用半监督学习。不存在“超监督学习”这种东西。

15. **A, D**. 选项 A 绝对正确，并在整个行业中普遍采用。选项 B 不正确，因为在实践中经常这样做。选项 C 部分正确，因为它可能放大错误，但这并不意味着你永远不输入一个。选项 D 正确，因为有一整类模型有助于转换数据以供下游预测。

16. **D**. 每当处理客户数据和敏感数据时，测试模型偏见并应用负责任的 AI 实践非常重要。

17. **C**. 更多测试数据在这里不会有太大帮助。但这并不意味着我们无计可施。你无法总是移除所有可能导致偏见的字段，因为某些细节可能隐藏在其他字段中。正确答案是使用模型可解释性和解释。

18. **C**. 模型部署得当。大多数 Android 手机可以很好地处理深度学习模型。我们无法对指标发表太多看法，因为它是未知的。这个有趣的 Android 应用可能被各种各样的人使用，且可能未在代表性样本数据集上进行测试。

19. **B, D**. 私密数据有很多种，不仅仅是照片。扫描件也是私密数据。使用敏感数据时应始终保持关注。

20. **B**. 虽然你可以创造性地使用数据，但处理客户数据时始终存在隐私顾虑。选项 A 正确，因为你通常在结账时推荐其他产品。选项 C 正确，因为用户行为和产品目录的变化需要重新训练。选项 D 正确，因为你可以使用关于产品的重要信息（如相似产品或互补产品）来销售更多。

1.  **C**. 通过独热编码，你可以将分类特征转换为数值特征。此外，并非所有算法都能在分类特征上良好工作。

3.  **C**. 对于不平衡数据集，AUC PR 是相比 AUC ROC 最小化假阳性的一种方法。

4.  **B**. 由于模型在训练数据上表现良好，这是数据泄露的情况。交叉验证是克服数据泄露的策略之一。我们在 [Chapter 2](#c02.xhtml) 中介绍过此内容。

6.  **A**. 使用 `tf.data.Dataset.prefetch` 转换。

7.  **C**. 我们将获得一个分箱纬度、分箱经度和分箱 roomsPerPerson 的特征组合。

8.  **A**. Cloud Data Fusion 是基于 UI 的 ETL 工具。

9.  **A**. TensorFlow Transform 是为生产工作负载转换训练和测试数据的最可扩展方式。

10. **D**. 由于模型在生产数据上表现不佳，存在训练-服务偏差。使用 `tf.Transform` 管道通过为训练和测试分别创建转换来防止这种偏差。

## Chapter 4: 选择合适的 ML 基础设施

1.  **C**. 始终从预训练模型开始，看它有多好地解决你的问题。如果不行，可以转向 AutoML。自定义模型应始终是最后的手段。

2.  **C**. “术语表”是旨在解决此确切问题的功能。如果你有一些术语需要以特定方式翻译，可以在 XML 文档中创建这些术语列表并传递给 Google Translate。选择 Advanced 选项而非 Basic。每当这些特定词汇/短语出现时，它将用你术语表中的翻译替换它们。

3.  **D**. 确实不存在“翻译字幕”服务；但是，你可以组合两个服务来满足你的需求。选项 A 错误，因为 Vertex AI 中目前没有 AutoML。选项 B 和 C 虽然可行，但不应是第一步。

4.  **A**. 这是一个分类问题。使用 AutoML Edge 模型类型是正确的方法，因为模型将部署在边缘设备上。虽然 Coral.ai 和 Android 应用部署都正确，但如果你想快速上市，最好选择使用 ML Kit 的 Android 应用程序。
