

# 第 13 章  

## 维护机器学习解决方案

在前几章中，您学习了模型训练、部署策略以及已部署模型的监控。在本章中，我们将讨论之前未涉及但对于创建成熟的机器学习解决方案并对其进行维护至关重要的一些概念。

这包括重训练策略、MLOps 成熟度（第 0、1、2 级），以及一种常见的设计模式，它解决了随着 MLOps 成熟而频繁出现的问题。

MLOps 是将 DevOps 原则应用于机器学习运营。这为管理运营的 ML 工程师提供了架构和策略指导。在本章中，您将了解到 MLOps 并非“一刀切”的方法，而是一种基于组织采用机器学习成熟度的分级方法。

稍后我们还将讨论 ML 工程师在实施 MLOps 时面临的两个重要问题。首先，确定 ML 模型的重训练策略并使其与组织目标保持一致，随后介绍一种用于模型版本控制的有用约定。其次，组织在特征工程上投入巨大，将机器学习扩展到内部多个团队所面临的复杂性。这两个问题均可通过我们描述为设计模式的解决方案来解决。

## MLOps 成熟度

组织会经历一个历程：从尝试机器学习技术开始，然后逐步将持续集成/持续部署（CI/CD）的概念引入机器学习。将 DevOps 原则应用于机器学习被称为 MLOps。

虽然 MLOps 和 DevOps 之间存在相似之处，但也存在一些关键差异。

我们发现，组织首先通过手动训练模型来尝试机器学习，然后使用流水线为该过程带来自动化；随后，随着完全实现自动化，它们进入转型阶段。它们经历的这三个阶段使用不同的技术，并反映了其“AI 就绪度”。

在详细了解这些阶段之前，让我们先看看 ML 的步骤：

1.  数据 
    1.  **提取：** 从不同来源收集数据，聚合数据，并使其可供下游 ML 流程使用。
    2.  **分析：** 对收集的数据执行探索性数据分析（EDA），以了解模式、统计分布和关系。确定将要执行的特征工程和数据准备要求。
    3.  **准备：** 对数据应用转换和特征工程。将数据拆分为训练集、测试集和验证集，用于 ML 任务。

2.  模型 
    1.  **训练：** 使用输入数据设置 ML 训练，并预测输出。尝试不同的算法和超参数，以确定表现最佳的模型。
    2.  **评估：** 使用保留集评估模型，并根据预定义的指标评估模型质量。
    3.  **验证：** 验证模型是否符合部署条件，即指标是否满足特定的基线性能标准。

3.  部署 
    1.  **服务：** 部署模型以提供在线或批量预测。对于在线预测，为模型创建并维护 RESTful 端点，并根据需求配置扩展。这也可能包括进行批量预测。
    2.  **监控：** 部署后持续监控模型，以检测异常、漂移和偏差。

我们在前几章中已经了解了所有这些步骤，因此您应该对它们很熟悉。这些步骤的自动化程度定义了 MLOps 的成熟度。Google 将 MLOps 定义为具有三个级别：MLOps 第 0 级（手动阶段）、MLOps 第 1 级（战略自动化阶段）和 MLOps 第 2 级（CI/CD 自动化，转型阶段）。

### MLOps 第 0 级：手动/战术阶段

开始尝试 ML 的组织处于此阶段。在此阶段，重点是构建概念验证并测试一些 AI/ML 用例。其目的是验证一些关于如何利用 ML 改进业务的想法。

在此阶段，通常有一个个人或团队在进行实验和训练模型。他们工作的成果是模型，该模型通过模型注册表（如[图 13.1](#c13.xhtml#c13-fig-0001)所示）移交给发布或部署团队。然后部署团队获取该模型并将其部署以提供预测服务。

#### 第 0 级的关键特性

让我们看看此战术阶段流程的关键点：

1.  **手动：** 所有步骤均无自动化。每个任务均为手动执行，包括数据分析、准备、训练和验证。其中大部分步骤在数据科学家的 Jupyter Notebook 中完成，这并不奇怪。

2.  **ML 与 MLOps 之间的分离：** 服务模型的数据科学家和工程师完全分离，唯一的联系点是模型移交。即使是移交，也可能只是将模型文件存储在存储位置供部署团队获取，或者稍成熟的团队可能会使用模型注册表进行移交。这种分离对检测训练-服务偏差产生负面影响。
