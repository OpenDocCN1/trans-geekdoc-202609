## 测试目标性能

在测试模型在生产环境中的性能时，您需要考虑以下事项：

*   您需要检查模型中的**训练-服务偏差**，并使用实时数据测试模型在生产环境中的质量。
*   您可以在整个 ML 流水线中监控模型的生命周期和性能。
*   您可以测试模型权重和输出在数值上是否稳定。例如，在模型训练期间，您的权重和层输出不应为 `NaN` 或 `null`。您需要编写测试来检查模型权重和层输出的 `NaN` 和 `null` 值。此外，您需要测试某层输出中超过一半的值不为零。

Vertex AI 拥有诸如 `Vertex AI Model Monitoring` 和 `Vertex AI Feature Store` 等服务，可帮助解决部署在生产环境中的模型的一些测试问题，例如检测偏差和监控模型随时间推移的性能。

如需了解详情，请参阅 `https://developers.google.com/machine-learning/testing-debugging/pipeline/production`。

## 配置触发器和流水线计划

对于本节，您需要知道如何根据用例在 Vertex AI 平台上触发训练或预测作业。

例如，要触发实时预测作业，您可以在 Google Cloud App Engine 上设置预测端点，以创建无服务器 ML 网关。我们在本章前面的“服务（在线、批量和缓存）”一节中介绍了该架构模式。

以下是一些有助于创建触发器并在 Vertex AI 上安排训练或预测作业的服务：

*   `Cloud Scheduler` 可帮助您设置 cron 作业计划，以安排 Vertex AI 训练或预测作业。
*   使用 `Vertex AI managed notebooks`，您可以使用 Jupyter Notebook 执行和安排 Vertex 训练和预测作业。请参阅此链接了解详情：`https://cloud.google.com/vertex-ai/docs/workbench/managed/schedule-managed-notebooks-run-quickstart`。
*   `Cloud Build` 是 GCP 上的 CI/CD 产品。如果您想重新训练模型、构建 `Dockerfile` 并将其推送用于自定义训练，请使用 `Cloud Build` 启动它。`Cloud Run` 是用于部署容器的托管产品。假设您部署的容器是一个包含您模型的 Flask 或 FastAPI 应用。您可以使用 `Cloud Build` 将应用部署到 `Cloud Run`。
*   您还可以使用事件驱动的无服务器 `Cloud Functions` 和 `Cloud Pub/Sub`。`Cloud Functions` 是无服务器且无状态的函数即服务，而 `Pub/Sub` 实现了发布者-订阅者模式。您可以为 `Cloud Function` 使用基于事件的 `Cloud Storage` 触发器，以便在存储桶中添加新版本的模型时，激活 `Cloud Function` 以启动部署。

当有多个 `Cloud Functions` 执行多项任务时，使用 `Cloud Function` 和 `Pub/Sub` 具有挑战性。例如，`Cloud Function A` 触发数据转换，然后 `Cloud Function B` 触发模型训练，最后 `Cloud Function C` 部署模型。在这种情况下，您需要一个编排器来在流水线中编排这些事件。要使用 `Cloud Functions` 编排数据清洗、数据转换、模型部署和模型训练，您可以使用 `Cloud Workflows`。

**Cloud Workflows** 将多个基于 HTTP 的服务编排为持久且有状态的工作流。工作流非常适合将微服务链接在一起、自动化基础设施任务（如启动或停止 VM）以及与外部系统集成。工作流连接器还支持 Google Cloud 服务（如 `Cloud Storage` 和 `BigQuery`）中的简单操作序列。

如果您不想使用 `Cloud Function` 进行编排，请使用 `Cloud Scheduler` 和 `Workflows`。

Vertex AI 提供了编排选项，例如 [表 10.3](#c10.xhtml#c10-tbl-0003) 中列出的 Vertex AI 流水线，我们将在下一章（[第 11 章](#c11.xhtml)，“设计 ML 训练流水线”）中详细介绍。

### 表 10.3 ML 编排选项

| 选项 | 说明 |
| --- | --- |
| Vertex AI Pipelines | Vertex AI Pipelines 通过以无服务器方式编排 ML 工作流并使用 Vertex ML Metadata 存储工作流的工件，帮助您自动化、监控和治理 ML 系统。通过将 ML 工作流的工件存储在 Vertex ML Metadata 中，您可以分析工作流工件的血缘关系。 |

## 考试要点

*   **理解 TensorFlow Serving。** 了解什么是 TensorFlow Serving 以及如何使用 TF Serving 部署训练好的 TensorFlow 模型。了解使用 Docker 设置 TF Serving 的不同方法。根据保存模型的 `SignatureDef` 张量理解 TF Serving 的预测响应。
*   **理解扩展预测服务（在线、批量和缓存）。** 理解在线、批量和缓存的区别。对于在线服务，理解架构和用例的差异，特别是关于实时获取输入特征以调用模型进行预测的方面（静态参考特征和动态参考特征）。此外，理解提高服务延迟的缓存策略。
*   **理解 Google Cloud 服务选项。** 了解如何使用 Google Cloud Vertex AI Prediction 为自定义模型或在 Vertex AI 之外训练的模型设置实时端点；了解如何使用 API 和 GCP 控制台设置进行预测设置。此外，了解如何使用 Vertex AI 批量预测为任何模型设置批量作业。
*   **测试目标性能。** 理解模型在生产环境中性能下降的原因。此外，从高层面理解 Vertex AI 服务（如 `Vertex AI Model Monitoring`）如何帮助解决性能下降问题。
