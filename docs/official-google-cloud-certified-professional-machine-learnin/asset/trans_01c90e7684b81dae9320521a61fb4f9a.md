## 框架选择与模型并行性

现代深度学习模型的参数数量越来越大，数据集规模也在急剧增加。要在大型数据集上训练复杂的现代深度学习模型，必须使用多节点训练；否则耗时极长。在分布式深度学习训练中，你总会看到数据并行性和模型并行性。

### 数据并行性

**数据并行性**是指将数据集拆分为多个部分，然后分配给并行的计算机器或图形处理单元（GPU）。对于每个 GPU 或节点，前向传播使用相同的参数。一小批数据被发送到每个节点，梯度正常计算并发回主节点。分布式训练实践中有两种策略：**同步**和**异步**。对于数据并行性，如果计算节点过多，我们必须降低学习率以保持平滑的训练过程。详情请参考 `https://analyticsindiamag.com/data-parallelism-vs-model-parallelism-how-do-they-differ-in-distributed-training`。

#### 同步训练

在同步训练中，模型将数据的不同部分发送到每个加速器或 GPU。每个 GPU 拥有模型的完整副本，并仅在数据的一部分上进行训练。每个部分同时开始前向传播，并计算不同的输出和梯度。同步训练使用全归约算法，从各个工作器和加速器收集所有可训练参数。

#### 异步训练

同步训练难以扩展，且可能导致工作器有时处于空闲状态。在异步训练中，工作器在维护停机期间无需相互等待，所有工作器独立地在输入数据上训练并异步更新变量。一个例子是 TensorFlow 分布式训练的参数服务器策略。请参阅[图 7.1](#c07.xhtml#c07-fig-0001) 以了解带有参数服务器的数据并行性。

### 模型并行性

在**模型并行性**中，每个模型被划分为多个部分，这与数据并行性类似。然后每个模型部分被放置在单个 GPU 上。

模型并行性具有明显的优势。它可用于训练无法仅放入单个 GPU 的模型。例如，假设我们有 10 个 GPU，想要训练一个简单的 ResNet50 模型。我们可以将前五层分配给 GPU 1，第二组五层分配给 GPU 2，依此类推，最后五层分配给 GPU 10。在训练期间，每次迭代中，前向传播必须先在 GPU 1 中完成，GPU 2 等待来自 GPU 1 的输出。前向传播完成后，我们计算位于 GPU 10 中的最后几层的梯度，并更新 GPU 10 中那些层的模型参数。然后梯度反向传播到 GPU 9 中的前几层。每个 GPU/节点就像工厂流水线上的一个隔间；它等待来自前一个隔间的产品，并将自己的产品发送到下一个隔间。请参阅[图 7.2](#c07.xhtml#c07-fig-0002)，其中模型被拆分到各个 GPU 上。

![图 7.2 模型并行性](images/c07f002.png)

**图 7.2** 模型并行性

增加深度学习模型的规模（层和参数）可提高复杂视觉模型的准确性。然而，单个 GPU 内存能容纳的最大模型规模是有限的。训练大型深度学习模型时，GPU 内存限制可能成为瓶颈。因此，可以使用模型并行性来克服在单个 GPU 上训练模型的相关限制。你可以将模型（层）拆分到多个 GPU 上。

你可能希望将训练扩展到一台机器上的多个 GPU、网络中的多台机器（每台机器有 0 个或多个 GPU）或 Cloud TPU。`tf.distribute.Strategy` 是一个用于跨多个 GPU、多台机器或 TPU 分发训练的 TensorFlow API。（请参阅 `www.tensorflow.org/guide/distributed_training`。）使用此 API，你只需极少的代码更改即可分发现有模型和训练代码。[表 7.1](#c07.xhtml#c07-tbl-0001) 解释了在 TensorFlow 中哪些策略受支持以及适用场景。

**表 7.1** 使用 TensorFlow 的分布式训练策略

| 策略 | 说明 |
| --- | --- |
| `MirroredStrategy` | 单机多 GPU 同步分布式训练。 |
| `CentralStorageStrategy` | 同步训练但不镜像。 |
| `MultiWorkerMirroredStrategy` | 跨多个工作器的同步分布式训练，每个工作器可能有多个 GPU 或多台机器。 |
