
# 通过机器学习交付业务价值

通过机器学习（ML）交付业务价值，不仅仅是针对手头的用例构建最佳的 ML 模型。交付这种价值还关乎构建一个集成的 ML 系统，使其持续运行以适应业务环境动态的变化。这样的 ML 系统涉及收集、处理和管理 ML 数据集与特征；大规模训练和评估模型；为预测提供模型服务；监控生产环境中的模型性能；以及跟踪模型元数据和工件。

ML 系统的挑战在于，ML 代码只是整个 ML 组件的一小部分。您需要管理模型、数据和 ML 代码之间的关系，如[图 11.1](#c11.xhtml#c11-fig-0001)所示。

![FIGURE 11.1 Relation between model data and ML code for MLOps](images/c11f001.png)

**[图 11.1](#c11.xhtml#R_c11-fig-0001)** MLOps 中模型数据与 ML 代码的关系

机器学习运维（MLOps）支持 ML 的开发和部署，正如 DevOps 和 DataOps 分别支持应用工程和数据工程。区别在于：当您部署 Web 服务时，您关心的是弹性、每秒查询数和负载均衡。而当您部署 ML 模型时，还需要担心数据的变化、模型的变化和用户行为的变化。

MLOps 过程是一个迭代过程，它需要输入，并产生进入下一步骤的输出，如[图 11.2](#c11.xhtml#c11-fig-0002)所示。您可以在 `https://services.google.com/fh/files/misc/practitioners_guide_to_mlops_whitepaper.pdf` 了解更多信息。

ML 流水线让您能够检测、编排和自动化[图 11.2](#c11.xhtml#c11-fig-0002)所示的复杂 ML 步骤，从 ML 开发到预测服务。

ML 流水线的关键功能包括：按需、按计划或响应指定事件触发流水线。流水线还与 ML 元数据跟踪功能集成，以捕获流水线执行参数并生成工件。

然后我们将介绍如何在这些流水线中调度工作流。我们将深入探讨 `Kubeflow` 和 `TFX`（`TensorFlow Extended`）的系统设计，以搭建 ML 流水线。

最后，我们将介绍一些用于搭建 ML 工作流的混合云和多云策略。

## 编排框架

您需要一个编排器来管理 ML 流水线中的各个步骤，例如清洗数据、转换数据和训练模型。编排器按顺序运行流水线，并根据定义的条件自动从一个步骤移动到下一个步骤。例如，一个定义的条件可能是在模型评估步骤之后执行模型服务步骤，前提是评估指标达到预定义的阈值。编排 ML 流水线在开发和生产阶段均很有用：

*   在开发阶段，编排帮助数据科学家运行 ML 实验，而无需手动执行每个步骤。
*   在生产阶段，编排帮助根据计划或特定触发条件自动执行 ML 流水线。

在以下部分中，我们将介绍 `Kubeflow Pipelines`、`Vertex AI Pipelines`、`Apache Airflow` 和 `Cloud Composer`，作为您可以使用的不同 ML 流水线编排器。

### Kubeflow Pipelines

在了解 `Kubeflow Pipelines` 如何工作之前，您应该先了解什么是 `Kubeflow`。`Kubeflow` 是面向 Kubernetes 的 ML 工具包。（您可以在 `www.kubeflow.org/docs/started/architecture` 了解更多相关信息。）`Kubeflow` 基于 Kubernetes 构建，作为一个用于部署、扩展和管理复杂系统的系统。使用 `Kubeflow`，您可以为工作流指定所需的任何 ML 框架，如 `TensorFlow`、`PyTorch` 或 `MXNet`。然后，您可以将工作流部署到各种云端或本地和本地部署平台，用于实验和生产用途。[图 11.3](#c11.xhtml#c11-fig-0003) 展示了如何使用 `Kubeflow` 作为平台，在 Kubernetes 之上安排 ML 系统的组件。

![FIGURE 11.3 Kubeflow architecture](images/c11f003.png)

**[图 11.3](#c11.xhtml#R_c11-fig-0003)** Kubeflow 架构

当您开发和部署 ML 系统时，ML 工作流通常包含多个阶段。开发 ML 系统是一个迭代过程。您需要评估 ML 工作流各阶段的输出，并在必要时对模型和参数应用更改，以确保模型持续产生您所需的结果。

`Kubeflow Pipelines` 是一个基于 Docker 容器的平台，用于构建、部署和管理多步骤 ML 工作流。

流水线是以图的形式描述的 ML 工作流，包含工作流中的所有组件以及组件之间的关系。流水线配置包括运行流水线所需的输入（参数）定义，以及每个组件的输入和输出。

当您运行流水线时，系统会启动一个或多个与工作流（流水线）中的步骤（组件）对应的 Kubernetes Pod。Pod 启动 Docker 容器，容器随即启动您的程序，如[图 11.4](#c11.xhtml#c11-fig-0004)所示。

![FIGURE 11.4 Kubeflow components and pods](images/c11f004.png)

**[图 11.4](#c11.xhtml#R_c11-fig-0004)** Kubeflow 组件和 Pod

`Kubeflow Pipelines` 平台包含以下内容：

*   用于管理和跟踪实验、作业和运行的用户界面（UI）
*   用于调度多步骤 ML 工作流的引擎
*   用于定义和操作流水线及组件的 SDK
*   用于使用 SDK 与系统交互的笔记本
*   编排、实验和复用

您可以在 Google Cloud 的 `GKE` 上安装 `Kubeflow Pipelines`，或使用托管的 `Vertex AI Pipelines` 在 Google Cloud 上运行 `Kubeflow Pipelines`。

### Vertex AI Pipelines

您可以使用 `Vertex AI Pipelines` 运行 `Kubeflow Pipelines` 或 `TensorFlow Extended` 流水线，而无需搭建任何服务器来设置 `Kubeflow` 基础设施或 `TFX` 基础设施。`Vertex AI Pipelines` 会自动为您预配和管理底层基础设施。您可以携带现有的 `Kubeflow` 或 `TFX` 流水线代码，在 `Vertex AI Pipelines` 上以无服务器方式运行。

`Vertex AI Pipelines` 还提供数据血缘。*血缘* 在机器学习中是指跟踪数据随时间从源系统流向转换过程，再到被模型消费的过程。这包括数据一路经历的所有转换，从源系统开始、数据如何被转换、发生了什么变化以及为什么变化。每次流水线运行都会生成*元数据*和 ML *工件*，例如模型或数据集。*工件血缘* 描述了导致工件产生的所有因素，例如用于模型训练的训练数据或超参数。通过使用工件血缘，您可以理解多次流水线运行中性能或准确率的差异：

*   流水线让您能够自动化、监控 ML 工作流中相互依赖的部分并进行实验。
*   ML 流水线具有可移植性、可扩展性，且基于容器。
*   您的流水线工作流的每个单独部分（例如创建数据集或训练模型）均由代码定义。此代码称为*组件*。组件的每个实例称为*步骤*。组件由一组输入、一组输出和一个容器镜像位置组成。组件的容器镜像是一个包，包含组件的可执行代码和代码运行环境的定义。
