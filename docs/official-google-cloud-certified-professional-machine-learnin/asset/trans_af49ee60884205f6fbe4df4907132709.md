

# 漂移与偏差计算

我们将向您展示如何计算基准分布，然后使用相同的方法计算预测时的分布，并使用比较方法。这些方法将因数据类型而异。

1.  计算基准。

    *   **用于偏差检测的基准：** 训练数据中特征值的统计分布即为基准。

    *   **用于漂移检测的基准：** 近期过去在生产环境中观察到的特征值的统计分布即为基准。

        这些如何应用取决于数据类型是分类型还是数值型。用于基准的分布计算如下：

    *   **分类特征的分布计算：** 每个可能值的实例计数或百分比。

    *   **数值特征的分布计算：** 落入各个桶中的值的计数或百分比。（全范围被划分为等大小的桶。）

2.  使用上述方法计算在生产环境中看到的最新值的统计分布。

3.  Vertex AI 随后将基准与步骤 2 中计算的最新分布进行比较。距离度量的计算如下：

    *   **分类特征：** 基准分布与最新生产分布之间的距离得分使用 L-无穷距离 计算。这是沿任何坐标维度测量的两个向量之间的最大距离。

    *   **数值特征：** 距离得分使用 Jensen-Shannon 散度 计算。（其数学定义超出了考试范围。）

4.  当距离得分达到配置的阈值时，Vertex AI 会将其识别为异常（偏差或漂移）。

## 启用监控的实际注意事项

有几件事需要牢记，以便有效地监控数据，同时使其具有成本效益：

*   **采样率：** 配置 `预测请求采样率` 以仅获取生产输入的样本。

*   **监控频率：** 配置 `频率` 以设置监控模型记录输入以检测偏差或漂移的速率。这设置了每次运行中分析的已记录数据的监控窗口大小。

*   **告警阈值：** 为您感兴趣的每个特征配置阈值。当基准与生产输入特征分布之间的统计距离超过此阈值时，会生成告警。默认值为 0.3。

*   **端点中的多个模型：** 当您在端点上启用并配置偏差或漂移检测时，该配置将应用于部署在该端点后面的所有模型，包括以下内容：

    *   检测类型

    *   采样率

    *   监控频率

# 输入架构

输入值是预测请求负载的一部分。Vertex AI 应能够解析输入值以进行监控。您可以在配置模型监控时指定架构，以帮助解析此输入。

对于 AutoML 模型，输入架构会自动解析，因此您无需提供。对于不使用键/值输入格式的自定义训练模型，您必须提供一个。

## 自动架构解析

为偏差或漂移启用模型监控时，通常可以自动解析输入架构。Vertex AI 模型监控将分析前 1,000 个请求以检测架构。如果输入值采用键/值对的形式，这种自动检测的效果最好。此处 `key` 是特征的名称，实际值紧随冒号之后。请参阅以下以键/值对形式呈现的输入（汽车）示例：

```
{"make":"Ford", "model":"focus": year: "2011", "color":"black"}
```

## 自定义架构

为了确保 Vertex AI 正确解析输入值，您可以在所谓的 `分析实例` 中指定架构。分析实例预期为 Open API 架构格式。

以下是预期架构的详细信息：

*   “type” 可以是以下之一：

    *   `object`：键/值对

    *   `array`：类数组格式

    *   `string`：csv 字符串

*   `Properties`：每个特征的类型。

*   对于 `array 或 csv` 字符串格式，指定特征的顺序。

以下是预测汽车转售价值的模型的输入示例：

```
type: object
properties:
  make:
    type:string
  model:
    type:string
  year:
    type:number
  color:
    type:string
  known_defects:
    type: array
    items:
       type: string
required:
 -make
 -model
 -year
 -color
```

上述架构以 `object` 格式指定。特征 `make`、`model` 和 `color` 是字符串特征，`year` 是数字。特征 `known_defects` 是字符串数组。最后一部分告诉您除 `known_defects` 外所有特征均为必需。

在 CSV 格式中，您可以通过提供空字段来跳过可选输入特征。例如，假设您期望五个特征：`["a","b",,"d","e"]`。请注意第三个特征被跳过。第三个缺失特征将被理解为“null”值。

# 日志记录策略

当您部署模型进行预测时，除了监控输入（即跟踪输入特征的趋势）外，记录请求可能也很有用。在某些领域（如受监管的金融垂直领域），出于未来审计的目的，所有模型都强制要求记录日志。在其他情况下，收集监控数据以更新您的训练数据可能很有用。

在 Vertex AI 中，您可以为 AutoML 表格模型、AutoML 图像模型和自定义训练模型启用预测日志。这可以在模型部署或端点创建期间完成。

## 预测日志的类型

您可以启用三种日志以从预测节点获取信息。这三种日志类型相互独立，因此可以独立启用或禁用。

### 容器日志记录

这会将预测节点的 `stdout` 和 `stderr` 记录到 Cloud Logging。这对于调试您的容器或模型非常有用且相关。了解 GCP 上更大的日志记录平台可能会有所帮助。

### 访问日志记录

这会将诸如每个请求的时间戳和延迟之类的信息记录到 Cloud Logging。这在 v1 服务端点上默认启用；此外，您在将模型部署到端点时可以启用访问日志记录。

### 请求-响应日志记录

这会将在线预测请求和响应的样本记录到 BigQuery 表中。这是主要机制。通过它，您可以创建更多数据来增强您的训练或测试数据。您可以在创建预测端点期间启用此功能，也可以稍后更新它。

## 日志设置

创建端点或将模型部署到端点时，可以更新日志设置。了解日志记录的默认设置很重要。如果您已经使用默认日志设置部署了模型，但想要更改日志设置，则必须取消部署模型，并使用新设置重新部署。

如果您预计模型会有大量请求，除了扩展部署外，还应考虑日志记录的成本。高“每秒查询率”，即 QPS，将产生大量日志。
