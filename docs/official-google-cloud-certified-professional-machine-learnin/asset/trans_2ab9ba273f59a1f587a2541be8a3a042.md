#### 挑战

此阶段最重要的挑战是模型退化。由于训练数据与真实数据之间的差异，训练良好的模型在现实生活中经常表现不佳。缓解这些问题的唯一方法是主动监控预测质量，频繁重新训练模型，并频繁尝试新的算法或模型实现，以利用技术改进带来的优势。

### MLOps 第 1 级：战略自动化阶段

处于此阶段的组织通常已确定业务目标，并将 ML 确定为解决某些问题的优先事项。此阶段涉及使用流水线来自动化模型的持续训练和模型预测服务的持续交付。实现这一点需要新的服务，包括自动化的数据和模型验证步骤、流水线触发器、特征存储和元数据管理，如 [图 13.2](#c13.xhtml#c13-fig-0002) 所示。

在此阶段，有基础设施支持团队间共享工件，并且开发环境和生产环境有明确的区分。ML 模型的开发发生在编排环境中。数据流水线的源代码存储在中央代码库中，模型训练实现了自动化。

#### MLOps 第 1 级的关键特性

此阶段具有一些独特的特性，使其比第 0 级更成熟，我们将在此列出：

1. **实验：** 实验阶段的每个步骤都经过编排。由于步骤之间的转换是自动化的，因此加快了实验迭代的速度。

2. **持续训练：** 模型在生产环境中自动训练，由新数据触发。

3. **实验-运营对称性：** 用于创建实验流水线的代码也用于生产环境，这与统一 MLOps 的最佳实践非常吻合。

4. **模块化组件：** 用于创建流水线的每个组件都应可复用、可组合且可共享。

5. **持续交付：** 由于生产流水线是自动化的，因此可以基于新数据构建新模型并交付用于预测服务。

6. **流水线部署：** 在第 1 级，你部署的是一个通过执行来创建模型的流水线。

#### 挑战

在此阶段，预期团队仅管理少量流水线。此外，新流水线是手动部署的。流水线主要在数据发生变化时触发。当你基于新的 ML 思路部署模型时，这并不理想。例如，此方法适合使用新特征重新训练模型。然而，如果你想使用现有流水线中不包含的技术，则必须手动部署。要做到这一点，你需要创建 CI/CD 设置来自动化 ML 流水线的构建/测试/部署。

### MLOps 第 2 级：CI/CD 自动化，变革阶段

这是处于变革阶段的组织所期望的成熟度级别，此时组织利用 AI 进行创新并提供敏捷性。通常，你可以期望 ML 专家成为产品团队的一部分，并分布在各个业务单元中。数据集通常可跨孤岛访问，ML 项目在产品组之间共享。如 [图 13.3](#c13.xhtml#c13-fig-0003) 所示，整个流水线都经过 CI/CD 自动化（不仅仅是模型）。因此，如果你想将库从 TensorFlow 2.1 更新到 TensorFlow 2.5，它将自然地经过 CI/CD 自动化步骤，而无需手动操作。

#### 第 2 级的关键特性

进入第 2 级的显著特征是完全采用 CI/CD 模型。让我们详细了解一下一些特性：

1. **流水线：** 第一阶段是新 ML 算法的开发和实验，可能使用新库。输出是通过代码库共享的流水线源代码。从那时起，自动化接管一切，从构建流水线代码、对流水线代码运行各种测试、创建流水线代码的工件（如包、可执行文件等），随后部署此流水线并生成模型工件。训练好的模型自动部署以实现持续交付。部署后启用监控，收集监控数据以创建更多训练数据并自动触发训练。

2. **测试：** 测试是流水线持续集成的必要条件，从测试特征工程逻辑、模型训练收敛性检查、检查模型输出中的错误（如 NaN 值）、验证每个阶段创建的工件，以及流水线组件之间的集成测试开始。

3. **交付：** 为了实现持续交付，你需要验证模型与服务环境中的软硬件基础设施的兼容性。测试预测服务是否符合 API 模式、负载测试等。此外，根据特定模型的需求，你还可以在完全推出之前使用蓝绿部署、金丝雀部署或影子部署策略。

总之，维护 ML 解决方案不仅仅是训练模型并在 API 后面部署单个模型。它意味着自动化模型的重新训练、测试和部署的能力。由于机器学习领域几乎每天都在见证技术的快速进步，因此拥有管理这种变化的能力非常重要。

然而，并非每个组织在旅程开始时都必须达到第 2 级。这取决于组织使用 AI/ML 的成熟度，随着组织思维的成熟，自动化也随之而来。

在前面的章节中，我们详细讨论了重新训练模型，甚至持续训练和部署方法论。在这一过程中存在一些常见场景和实际问题，我们将在下一节中将其中两个作为设计模式进行解决。
