# III. CONCERNS OF SOFTWARE MODERNIZATION

As mentioned before, two properties that software modernization tools (or concrete transformation techniques) strive to maximize automation and precision. We have also seen that two often exclude each other and a trade-off must be made between them. The more automatic the transformation is, the less post-transformation work developers must deal with. On the other hand, a higher level of automation often means a decrease in precision. This may result in two outcomes: the transformation may produce many false negatives during multiple-choice decisions. This, which depends on the complexity of the problem at hand. Whereas, the transformation might succeed, more automatic solutions may end up decreasing the quality of the generated code; such was the case with the legacy systems, where inserting pointer functionality resulted in us lower quality-oriented code, but the process became fully automatic.

In contrast, machine learning techniques may be both highly precise (if used properly) and automatic making them extremely useful in code modernization. However, there is one significant drawback as well: machine learning takes more effort and more allocated resources than static code analysis methods. Machine learning for just any possible decision to make the transformation we want to make seems highly overkill in general. Thus, we propose to use it only when other, more traditional and easier methods fail to produce satisfying results. In these cases, we believe that the advantages of machine learning far outweigh the drawbacks.
