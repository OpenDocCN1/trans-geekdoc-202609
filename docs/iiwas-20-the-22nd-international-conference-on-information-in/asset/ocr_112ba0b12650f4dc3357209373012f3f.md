# 3.2 Blockchain technology

The BCT is a network ledger that records the transactions that take place between users in the network. The advantage of being a distributed database, where every user on the BCT has access to the entire database and its complete history from anywhere. It is also a new type of peer-to-peer distribution technology, meaning that communication takes place directly between users without the need for a third party to pass the message. This technology allows to build trusted, accountable, and transparent applications that are secured using cryptographic fundamentals such as hashing functionality, digital signature and encryption. Every user on this network has its own digital signature. BCT is gaining interest from a wide range of industries: from healthcare [7], finance [6], other sectors [8]. The reason for this increased interest: The BCT allows them to operate in a decentralized manner, without the need for a verification system and with the same amount of reliability to achieve the same functionality. BCT is a new technology for creating a peers decentralized network with a data protection mechanism, this technology has an ability to share and track data between peers [2]. Based on what was mentioned, we find that BCT is the key to formalizing coordination between agents. In this paper, we proposed a MAS Approach for prediction process using BCT. A new approach for improve prediction is presented in this paper. The proposed approach involves integration of the MAS and BCT to detects early warning signals for system failure prediction before it occurs, and this integration made the proposed system able to operate in any complex environment.

# 3.3 Architecture of our prediction approach

The prediction approach was constructed by using a four-layer MAS architecture, each layer having its own responsibilities and processes. All these classes cooperate with each other to reach the general goal of predicting the failure of the system before it occurs. Fig. 1, shows the proposed architecture. In the following, we will discuss each layer, in detail. The first layer called data prepossessing layer (DPL). The goal of agent in this layer are log key extraction and also analyze, transform and reorganize the data, in order to apply machine learning to classify the data. Because the main input

in our system is the log file, which is an unstructured file. Due to the huge size of this file, it is difficult for administrators to know and understand the main structure of it, so we reduce its size by extracting the log key (the main structure of messages) to help these administrators discovery and understand the main structure of this file. So that in the future they can find solutions to the failures that appear. Due to the nature of this file, it contains a lot of information that may not be important to our system, so we analyze and reorganize the file by using the log key extracted in the first step. The final output of this layer is groups, each group containing a series of log keys, which have been replaced with numerical data, to feed the second layer. The second layer called data classification layer (DCL) In this layer, the agent used a rule-based classifier, and this makes it an expert agent [22]. A rule-based classifier is better than the rest of the classification algorithms is highly expressive as decision trees, easy to interpret, easy to generate, and new states can be classified quickly. The main advantage is that rules can be created by two ways, First: Direct Method: Extract rules directly from data Such as RIPPER [25], CN2, Holte's IR [20], Second: Indirect Method: Extract rules from other classification models (Such as decision trees, neural networks, etc). The final output of this layer is groups classified by type of failure. The third layer called Build Anomaly Model (BAM). The agent of this layer uses finite-state automation to model the execution behavior of each anomaly. We are adopting the FSA [14], although there are some other alternative models, such as Petri-Net [15], because it is both effective and simple. The final output of this layer is a model for all type of failures, it is used for prediction in the fourth layer. The fourth layer is called the prediction layer (PL). Agents of this layer are intelligent agents who learn from models and collect information. Then they use decision tree algorithm to predict any failure before it happens. If any of these agents detects any indication of a failure, that agent will write all the details about that failure into BCT.

Our main goal behind using the layer architecture is to simplify the prediction process and increase the speed of work, as each layer has a special role to play with its own agent. All agents in this layer cooperate to achieve the overall goal quickly and efficiently.

# 3.3.1 Analysis and design of methodology.

The first step to design a program is to identify the goals. This method can lead to a list of goals that are linked as a tree of goals and sub-goals. To achieve the main objective of the program, the method must be performed. In our study, the main objective of the MAS integrate with BCT is to detects early warning signals for system failure prediction during executing. While the sub-goals of the layers are the first layer is data preparation, the second layer is to classify these data, the third layer is to build a model from these data, and the fourth layer is a prediction based on the pattern from the previous step. Once we have identified the goals and sub-objectives of the system, we move to the second step, which is the roles. Roles are created based on predefined objectives in order to clarify the detailed functions of the system [19]. Defining roles is very helpful in modifying a system, because every system includes a set of roles that are directly related to the major system functions. After clearly defining the roles of the system, we move on to the third step, which is defining the agents of the system by grouping the roles.
