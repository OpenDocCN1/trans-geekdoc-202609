# 3.3.2 Agents description.

In our proposed approach several agents work together to achieve the overall objective of the system, with each agent having a specific responsibility. This section aims to describe the steps involved in the work of each agent, explain the logic behind these steps, and also define the input and output for each agent.

**Agent layer1: Data prepossessing.** A large data set is usually a large number of well-organized rows and columns. On the contrary, logs file is unstructured, as they come in the form of text and unstructured datasets, and this is the reason why they are not used by developers to analyze events even though they contain valuable information. So, we have developed an autonomous intelligent agent to perform this process, it works to convert it from unstructured files to structured files that are easy to use and understand. Also, this step is one of the most important steps in the machine learning process, because the machine learning process cannot deal with unstructured data. Input: We used the input of our study a part of an original event log linked to the Hadoop Distributed File System (HDFS) execution trace. We assume that each line in execution trace (log file) shows an event (or feature), We also assume that a series of events are associated with a specific failure. Output: The goal of prepossessing data is to create an ordered dataset to feed into the second layer machine learning algorithms. This dataset is a copy of the original event log that has been formatted in a specific way and is suitable for feeding machine learning algorithms. The agent in this layer produces records structured through five steps: 1. log key extraction, 2. parsing, 3. transformation, 4. Grouping, 5. Normalization.

**Agent layer 2: Data classification,** Typically, data is stored in target files. In a file system, a file is divided into one or more sections and stored in individual data nodes. These file segments are called blocks. In another term, the data that HDFS can read or write is called block. Each block goes through certain stages or steps in order to be stored, and all of those steps it goes through are recorded in HDFS execution traces. When looking at the sequence of events for each block, we can know if this block was stored normally or not. Through the study of previous researches [29] we were able to determine the type of failures that occur in the block, which they clarified in Decision Tree. In this layer we developed an expert agent who can derive rules from Decision Tree and use them for classification. Input: The input of this agent is an output from the agent in the first layer, which is groups. Each group contains the events of a particular block. Output: They are groups classified according to the type of failure. The agent in this layer classifies groups into groups based on specific rules, through two steps: 1. extract a rule from decision tree, 2. rule-based classification.

**Agent layer 3: Building a failure model,**Building a failure model. The inputs in this layer are the classified groups from the previous step. Based on the foregoing, we find that each group is assigned to specific failure, and each group contains groups of blocks. And each block group contains a set of serialized events as recorded. If we find that every failure has many cases, in other words, we find that every failure does not have a single sequence of events. So, we used the FSA to model all cases of every failure and

show all the interactions between the internal components that led to this failure. From that we will have a single model showing all failure sequences. And we can use it to predict this failure before it happens. An autonomous intelligent agent has also been developed to automate the steps. Input: The input of this agent is the output from the agent in the second layer, which are groups classified according to the type of failure. The agent uses it to build a model for failures. Output: They are failure models that will be used in Layer 4 to predict failure before it occurs. In this layer, the agent builds a failure model from the classified groups by using FSA. FSA consists of a finite number of states and transitions between the states. Each event in the group is a transition. Agent uses the algorithm proposed by [18] to learn the FSA about every failure of the system through the sequence of events in the blocks.

**Agents layer 4: Prediction,**The goal of use a group of agents in this layer, so that each agent searches for a specific problem that is different from the rest. This will reduce time and effort. When an agent detects an early warning signal of failure, it writes in the BCT so that the rest of the agents and the administrators know at the same time before the failure occurs, and this is the reason for using the BCT in this layer because it provides transparency, trust and communication between the agents, and the synchronization between the agents and the administrators. All these agents used in this layer are intelligent agents, because they are able to learn from the model, discover information and make the decision towards failure. Input: The input of this agents is single line from execution traces. Output: When any agents detects an early warning signal of failure it writes in the BCT, so the output here is a new block carrying information about the prediction. The agents in this layer cooperate with each other in detecting the early warning signal, through four steps: 1. Data Preprocessing, 2. Knowledge discovery, 3. Prediction. 4. Writing in a BCT.
