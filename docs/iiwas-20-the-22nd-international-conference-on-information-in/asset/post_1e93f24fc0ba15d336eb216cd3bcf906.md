## 3.2 Blockchain technology

The BCT is a network ledger that records the transactions that take place between users in the network. The advantage of being a distributed database, where every user on the BCT has access to the entire database and its complete history from anywhere. It is also a new type of peer-to-peer distribution technology, meaning that communication takes place directly between users without the need for a third party to pass the message. This technology allows to build trusted, accountable, and transparent applications that are secured using cryptographic fundamentals such as hashing functionality, digital signature and encryption. Every user on this network has its own digital signature. BCT is gaining interest from a wide range of industries: from healthcare [7], finance [6], other sectors [8]. The reason for this increased interest: The BCT allows them to operate in a decentralized manner, without the need for a verification system and with the same amount of reliability to achieve the same functionality. BCT is a new technology for creating a peer-to-peer decentralized network with a data protection mechanism, this technology has an ability to share and track data between peers [2]. Based on what was mentioned, we find that BCT is the key to formalizing coordination between agents. In this paper, we proposed a MAS Approach for prediction process using BCT. A new approach to improve prediction is presented in this paper. The proposed approach involves integration of the MAS and BCT to detect early warning signals for system failure prediction before it occurs, and this integration made the proposed system able to operate in any complex environment.

## 3.3 Architecture of our prediction approach

The prediction approach was constructed by using a four-layer MAS architecture, each layer having its own responsibilities and processes. All these classes cooperate with each other to reach the general goal of predicting the failure of the system before it occurs. Fig. 1, shows the proposed architecture. In the following, we will discuss each layer, in detail. The first layer called data preprocessing layer (DPL). The goal of agent in this layer are log key extraction and also analyze, transform and reorganize the data, in order to apply machine learning to classify the data. Because the main input in our system is the log file, which is an unstructured file. Due to the huge size of this file, it is difficult for administrators to know and understand the main structure of it, so we reduce its size by extracting the log key (the main structure of messages) to help these administrators discover and understand the main structure of this file. So that in the future they can find solutions to the failures that appear. Due to the nature of this file, it contains a lot of information that may not be important to our system, so we analyze and reorganize the file by using the log key extracted in the first step. The final output of this layer is groups, each group containing a series of log keys, which have been replaced with numerical data, to feed the second layer. The second layer called data classification layer (DCL) In this layer, the agent used a rule-based classifier, and this makes it an expert agent [22]. A rule-based classifier is better than the rest of the classification algorithms is highly expressive as decision trees, easy to interpret, easy to generate, and new states can be classified quickly. The main advantage is that rules can be created by two ways, First: Direct Method: Extract rules directly from data Such as RIPPER [25], CN2, Holte's IR [20], Second: Indirect Method: Extract rules from other classification models (Such as decision trees, neural networks, etc). The final output of this layer is groups classified by type of failure. The third layer called Build Anomaly Model (BAM). The agent of this layer uses finite-state automaton to model the execution behavior of each anomaly. We are adopting the FSA [14], although there are some other alternative models, such as Petri-Net [15], because it is both effective and simple. The final output of this layer is a model for all type of failures, it is used for prediction in the fourth layer. The fourth layer is called the prediction layer (PL). Agents of this layer are intelligent agents who learn from models and collect information. Then they use decision tree algorithm to predict any failure before it happens. If any of these agents detects any indication of a failure, that agent will write all the details about that failure into BCT.

Our main goal behind using the layer architecture is to simplify the prediction process and increase the speed of work, as each layer has a special role to play with its own agent. All agents in this layer cooperate to achieve the overall goal quickly and efficiently.

### 3.3.1 Analysis and design of methodology.

The first step to design a program is to identify the goals. This method can lead to a list of goals that are linked as a tree of goals and sub-goals. To achieve the main objective of the program, the method must be performed. In our study, the main objective of the MAS integrate with BCT is to detects early warning signals for system failure prediction during executing. While the sub-goals of the layers are the first layer is data preparation, the second layer is to classify these data, the third layer is to build a model from these data, and the fourth layer is a prediction based on the pattern from the previous step. Once we have identified the goals and sub-objectives of the system, we move to the second step, which is the roles. Roles are created based on predefined objectives in order to clarify the detailed functions of the system [19]. Defining roles is very helpful in modifying a system, because every system includes a set of roles that are directly related to the major system functions. After clearly defining the roles of the system, we move on to the third step, which is defining the agents of the system by grouping the roles. The roles are grouped according to their similarity and joined together in an agent. Additionally, there is a data flow in the system that determines how data flows between roles.

### 3.3.2 Agents description.

In our proposed approach several agents work together to achieve the overall objective of the system, with each agent having a specific responsibility. This section aims to describe the steps involved in the work of each agent, explain the logic behind these steps, and also define the input and output for each agent.

**Agent layer1: Data preprocessing.** A large data set is usually a large number of well-organized rows and columns. On the contrary, logs file is unstructured, as they come in the form of text and unstructured datasets, and this is the reason why they are not used by developers to analyze events even though they contain valuable information. So, we have developed an autonomous intelligent agent to perform this process, it works to convert it from unstructured files to structured files that are easy to use and understand. Also, this step is one of the most important steps in the machine learning process, because the machine learning process cannot deal with unstructured data. Input: We used the input of our study a part of an original event log linked to the Hadoop Distributed File System (HDFS) execution trace. We assume that each line in execution trace (log file) shows an event (or feature), We also assume that a series of events are associated with a specific failure. Output: The goal of preprocessing data is to create an ordered dataset to feed into the second layer machine learning algorithms. This dataset is a copy of the original event log that has been formatted in a specific way and is suitable for feeding machine learning algorithms. The agent in this layer produces records structured through five steps:
- log key extraction
- parsing
- transformation
- Grouping
- Normalization

**Agent layer 2: Data classification,** Typically, data is stored in target files. In a file system, a file is divided into one or more sections and stored in individual data nodes. These file segments are called blocks. In another term, the data that HDFS can read or write is called block. Each block goes through certain stages or steps in order to be stored, and all of those steps it goes through are recorded in HDFS execution traces. When looking at the sequence of events for each block, we can know if this block was stored normally or not. Through the study of previous researches [29] we were able to determine the type of failures that occur in the block, which they clarified in Decision Tree. In this layer we developed an expert agent who can derive rules from Decision Tree and use them for classification. Input: The input of this agent is an output from the agent in the first layer, which is groups. Each group contains the events of a particular block. Output: They are groups classified according to the type of failure. The agent in this layer classifies groups into groups based on specific rules, through two steps:
- extract a rule from decision tree
- rule-based classification

**Agent layer 3: Building a failure model,** Building a failure model. The inputs in this layer are the classified groups from the previous step. Based on the foregoing, we find that each group is assigned to specific failure, and each group contains groups of blocks. And each block group contains a set of serialized events as recorded. If we find that every failure has many cases, in other words, we find that every failure does not have a single sequence of events. So, we used the FSA to model all cases of every failure and show all the interactions between the internal components that led to this failure. From that we will have a single model showing all failure sequences. And we can use it to predict this failure before it happens. An autonomous intelligent agent has also been developed to automate the steps. Input: The input of this agent is the output from the agent in the second layer, which are groups classified according to the type of failure. The agent uses it to build a model for failures. Output: They are failure models that will be used in Layer 4 to predict failure before it occurs. In this layer, the agent builds a failure model from the classified groups by using FSA. FSA consists of a finite number of states and transitions between the states. Each event in the group is a transition. Agent uses the algorithm proposed by [18] to learn the FSA about every failure of the system through the sequence of events in the blocks.

**Agents layer 4: Prediction,** The goal of use a group of agents in this layer, so that each agent searches for a specific problem that is different from the rest. This will reduce time and effort. When an agent detects an early warning signal of failure, it writes in the BCT so that the rest of the agents and the administrators know at the same time before the failure occurs, and this is the reason for using the BCT in this layer because it provides transparency, trust and communication between the agents, and the synchronization between the agents and the administrators. All these agents used in this layer are intelligent agents, because they are able to learn from the model, discover information and make the decision towards failure. Input: The input of this agents is single line from execution traces. Output: When any agents detects an early warning signal of failure it writes in the BCT, so the output here is a new block carrying information about the prediction. The agents in this layer cooperate with each other in detecting the early warning signal, through four steps:
- Data Preprocessing
- Knowledge discovery
- Prediction
- Writing in a BCT
