## ABSTRACT

The execution traces generated by an application contain information that the developers believed would be useful in debugging or monitoring the application, it contains application states and significant events at various critical points that help them gain insight into failures and identify and predict potential problems before they occur. Despite the ubiquity of these traces universally in almost all computer systems, they are rarely exploited because they are not readily machine-parsable. In this paper, we propose a Multi-Agents approach for prediction process using Blockchain technology, which allows automatic analysis of execution traces and detect early warning signals for system failure prediction during execution. The proposed prediction approach is constructed using a four-layer Multi-Agents system architecture. The proposed prediction approach performance is based on data preprocessing and supervised learning algorithms for prediction. Blockchain was used to coordinate collaboration between agents, and to synchronize prediction between agents and the administrators. We validated our approach by applying it to real-world distributed systems, where we predicted problems before they occurred with high accuracy. In this paper we will focus on the Architecture of our prediction approach.

## 1 INTRODUCTION

With recent developments in computing, we have witnessed a rapid increase in levels of reliance on computing technology for a variety types of daily use software, as it has become dependent on a series of heterogeneous computing systems. For example, banking systems, health systems, transportation systems, etc. Therefore, we must work to keep these systems working and reduce their downtime because it is very important and has many effects on the functions of society. There are many examples that have shown the effects of computing failure. For example, in 2012, 6 million customers of the Royal Bank of Scotland Group in the United Kingdom and Ireland found they had no access to their accounts for weeks [5]. Also, in March 2008, 140,000 people were affected by a computing failure in the baggage system at Heathrow Airport and the cost of the failure was estimated at 32 million dollars [5]. Hence, this highlights the need to ensure continuity of the system. Each system has its own database containing the history of the different operations performed at each moment. These data are called logs. logs are a rich source of useful information that helps developers debug or monitor app errors to ensure system dependability. In general, logs are unstructured text generated by logging statements in system source code. Looking at relevant researches on log analysis, we find that it focused on three distinct management problems; (i) Forensic analysis, which aims to identify the root cause of system failure after an occurrence [13, 30]. (ii) Fault detection, which aims to quickly detect signs of system failure when they occur [29]. (iii) System failure prediction, which aims to provide early warning of a system failure before it occurs [28, 31]. One of the challenges of log-based failure prediction is the number of features required or the length of time period required to make the prediction [28, 31]. For example, we find that current research [28] uses nearly 400 features extracted from system logs. While [31] it uses a certain period of time to make prediction. Another challenge is that it can identify the failure, but it cannot determine its exact type before it occurs. To overcome these challenges, we are developing a Multi-Agents (MAS) approach for prediction process using Blockchain technology (BCT). The proposed approach involves integration of the MAS and BCT to detect early warning signals for system failure prediction during execution. Our approach, first extracts the log key from execution traces by grouping the identical log message together and replaces all free text of the original log message with the log key, which reduces the amount of data drastically. Second, we send the output from the first step to rule based classifier algorithm to classify the data. Third, we use a Finite State Automaton (FSA) to model the execution behavior of each problem. Finally, we do a prediction using decision tree algorithm. The main contributions of our work can be summarized as follows: (1) We developed a general log analysis fully automatic approach involves integration of the MAS and BCT to detect early warning signals for system failure prediction before it happens. It works on analyzing the log line by line, it does not need a series of lines (features) to make the prediction which is often associated with log-based analysis. (2) We designed and implemented automated log analysis, which can analyze log data on a large scale accurately, quickly and efficiently. (3) We designed a prediction system based on the supervised learning algorithms (rule-based classification, decision tree algorithm), which is able to outperform the most existing systems. (4) We evaluated our approach by using real dataset (Hadoop Distributed File System) and validated its effectiveness through the standard performance metrics, precision, recall and F-score. We have also shown that our system can identify the exact type of failure before it occurs and also provide a detailed report to the administrators about the failure before it occurs. For example, [10], proposed a new ensemble-based MAS called “EMAS” to prediction of problems in data mining. It uses the MAS to increase prediction accuracy and decrease complexity of the prediction. EMAS architecture has a four-layer of MAS architecture. The first layer is cleaning and normalizing data. The second layer is data preprocessing. The third layer is building prediction model. Fourth layer is knowledge discovery, prediction and data display. Their proposed system predicts problems in data mining based on previous data, as it checks the data and predicts problems in it, meaning that it does not predict any failure before it occurs. They also work on a set of structured data sets (tables).
