# 4 工作模式

### 4.1 简介

我们已经介绍了如何使用 `AES` 加密 128 位分组，或使用 `DES` 加密 64 位分组，这些原语有一个很好的特性：如果攻击者修改了密文的任何部分，解密的结果实际上将是一个随机数。遗憾的是，大多数有用的消息都超过 128 位。**工作模式**是使用分组加密算法作为原语进行迭代应用，从而加密任意大小消息的技术。此类算法可以具有其他理想特性。如果我们多次发送相同的消息，最好每次加密后的消息都不同，这样窃听者就无法判断我们在发送相同的消息……

# 5 密码学哈希

### 5.1 简介

哈希函数输入任意大小的比特串，输出固定大小的比特串，理想情况下所有输出值出现的概率均等。**密码学哈希**（也称为**消息摘要**）具有一些额外的安全属性：

*   **原像抗性**：给定一个预先指定的哈希值，应该无法在计算上找到具有该哈希值的消息。
*   **抗碰撞性**：应该无法在计算上找到具有相同哈希值的两条消息。
*   **第二原像抗性**：给定一条消息，应该无法在计算上找到具有相同哈希值的第二条消息。

# 12 IPsec

正如我们在第 11 章 *通信会话建立* 中所述，`IPsec` 是一种运行在网络层第 3 层之上的安全会话协议（参见§11.7 *哪一层？*）。直接运行在第 3 层（*例如*，`IP`）上的含义是每个数据包都独立受到加密保护。`IPsec` 不保证所有数据包都会到达，也不保证到达的数据包会按发送顺序交付。`IPsec` 只保证未通过完整性检查的数据包将被丢弃，重复的数据包将被丢弃。这种设计使其易于在网络适配器中实现。`IPsec` 不需要缓冲数据包。即使数据包乱序到达，`IPsec` 也能独立处理和交付数据包。`IPsec`……

# 14 电子邮件安全

提到 *电子邮件安全* 一词，首先浮现在脑海中的场景是：`Alice` 给 `Bob` 发送一条消息，用她的私钥签名，并用 `Bob` 的公钥加密。`Lotus Notes` 在 1989 年就拥有了加密电子邮件的专有且广泛部署的实现。`PGP` 由 `Phil Zimmermann` 于 1991 年创建并作为开源软件发布。二十多年前就开发了多种用于用户间签名和加密电子邮件的标准，包括

*   `PEM` [`RFC 1421`—1993 年 2 月]
*   `PGP/GPG` [`RFC 2015`—1996 年 10 月]
*   `S/MIME` [`RFC 2311`—1998 年 3 月]

在 1990 年代初期，存在出口管制和专利等部署障碍，但这些问题现已解决。因此，这些标准（或实现……）均未得到广泛部署，这多少令人惊讶。
