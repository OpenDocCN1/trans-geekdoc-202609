The solid circle shows the start of the object’s life cycle, and arrows indicate transitions from one state to another. After the new `Performance` is initialized and dispatches a message to the venue system, the awaiting confirmation state polls until it receives a message back from the venue system.

One new symbol in Figure 2-13 is a *note* indicating that the awaiting confirmation state should wait one minute to receive a reply from the venue system. A note can be used in any UML diagram where you want to add extra information such as this.

# Component and Deployment Diagrams

The last diagram discussed in this chapter is the *component diagram*, which provides a high-level, abstract view of your software. For the BandSpy component diagram, the majority of the code is reduced to a single component on the Web server. Technically, elements such as the Web server are parts of another UML diagram called a *deployment diagram*. Deployment diagrams show some of the physical elements of your application’s infrastructure (such as the different servers on which your application runs).

In Figure 2-14, the large cube-shaped boxes are called *nodes*. Think of a node as a separate piece of physical hardware, or, in a more conceptual sense, as a defined, separate system of software such as a Web browser.
