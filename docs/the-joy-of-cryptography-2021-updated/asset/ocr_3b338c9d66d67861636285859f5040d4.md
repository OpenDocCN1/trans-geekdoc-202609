**Proof** It suffices to show that ElGamal has pseudorandom ciphertexts when the calling program sees only a single ciphertext. In other words, we will show that L<sub>pk-ots$-real</sub> ≈ L<sub>pk-ots$-rand</sub>, where these libraries are the L<sub>pk-cpa-★</sub> libraries from Definition 15.2 but with the single-ciphertext restriction used in Definition 15.4. It is left as an exercise to show that L<sub>pk-ots$-real</sub> ≈ L<sub>pk-ots$-rand</sub> implies CPA$ security (which in turn implies CPA security); the proof is very similar to that of Claim 15.5.
The sequence of hybrid libraries is given below:

```
L<sub>pk-ots$-real</sub>

a <- Z<sub>n</sub>
A := g<sup>a</sup>
count = 0

GETPK():
return A

QUERY(M ∈ G):
count : count + 1
if count > 1: return null
b <- Z<sub>n</sub>
B := g<sup>b</sup>
X := M · A<sup>b</sup>
return (B, X)
```

The starting point is the L<sub>pk-ots$-real</sub> library, shown here with the details of ElGamal filled in.

```
a <- Z<sub>n</sub>; b <- Z<sub>n</sub>
A := g<sup>a</sup>; B := g<sup>b</sup>; C := A<sup>b</sup>
count = 0

GETPK():

QUERY(M ∈ G):

return (B, X)
```

The main body of QUERY computes some intermediate values B and A<sup>b</sup>. But since those lines are only reachable one time, it does not change anything to pre-compute them at initialization time.
