Imagine the calling program trying to predict which string will be chosen when uniformly sampling from \(\{0, 1\}^\lambda\). The left library tells the calling program whether its prediction was correct. The right library doesn’t even bother sampling a string, it just always says “sorry, your prediction was wrong.”

Here is one obvious strategy (maybe not the best one, we will see) to distinguish these libraries. The calling program \(\mathcal{A}_{obvious}\) calls PREDICT many times and outputs 1 if it ever received true as a response. Since it seems like the argument to PREDICT might not have any effect, let’s just use the string of all-0s as argument every time.

```
\(\mathcal{A}_{obvious}\)
do q times:
if PREDICT(\(0^\lambda\)) = true
return 1
return 0
```

+   \(\mathcal{L}_{right}\) can never return true, so \(\text{Pr}[\mathcal{A}_{obvious} \diamond \mathcal{L}_{right} \Rightarrow 1] = 0\).

+   In \(\mathcal{L}_{left}\) each call to PREDICT has an independent probability \(1/2^\lambda\) of returning true. So \(\text{Pr}[\mathcal{A}_{obvious} \diamond \mathcal{L}_{left} \Rightarrow 1]\) is surely non-zero. Actually, the exact probability is a bit cumbersome to write:

```
\(\text{Pr}[\mathcal{A}_{obvious} \diamond \mathcal{L}_{left} \Rightarrow 1] = 1 - \text{Pr}[\mathcal{A}_{obvious} \diamond \mathcal{L}_{left} \Rightarrow 0]\)
\(= 1 - \text{Pr}[\text{all } q \text{ independent calls to PREDICT return false}]\)
\(= 1 - \left( 1 - \frac{1}{2^\lambda} \right)^q\)
```

Rather than understand this probability, we can just compute an upper bound for it. Using the union bound, we get:

```
\(\text{Pr}[\mathcal{A}_{obvious} \diamond \mathcal{L}_{left} \Rightarrow 1] \leqslant \text{Pr}[\text{first call to PREDICT returns true}]\)
\(+ \text{Pr}[\text{second call to PREDICT returns true}] + \cdots\)
\(= q \frac{1}{2^\lambda}\)
```

This is an overestimate of some probabilities (e.g., if the first call to PREDICT returns true, then the second call isn’t made). More fundamentally, \(q/2^\lambda\) exceeds 1 when \(q\) is large. But nevertheless, \(\text{Pr}[\mathcal{A}_{obvious} \diamond \mathcal{L}_{left} \Rightarrow 1] \leqslant q/2^\lambda\).

We showed that \(\mathcal{A}_{obvious}\) has non-zero advantage. This is enough to show that \(\mathcal{L}_{left} \not\cong \mathcal{L}_{right}\).

We also showed that \(\mathcal{A}_{obvious}\) has advantage at most \(q/2^\lambda\). Since \(\mathcal{A}_{obvious}\) runs in polynomial time, it can only make a polynomial number \(q\) of queries to the library, so \(q/2^\lambda\) is negligible. However, this is not enough to show that \(\mathcal{L}_{left} \approx \mathcal{L}_{right}\) since it considers only a single calling program. To show that the libraries are indistinguishable, we must show that **every** calling program’s advantage is negligible.

In a few pages, we will prove that for **any** \(\mathcal{A}\) that makes \(q\) calls to PREDICT,

```
\(\left| \text{Pr}[\mathcal{A} \diamond \mathcal{L}_{left} \Rightarrow 1] - \text{Pr}[\mathcal{A} \diamond \mathcal{L}_{right} \Rightarrow 1] \right| \leqslant \frac{q}{2^\lambda}.\)
```

For any polynomial-time \(\mathcal{A}\), the number \(q\) of calls to PREDICT will be a polynomial in \(\lambda\), making \(q/2^\lambda\) a negligible function. Hence, \(\mathcal{L}_{left} \approx \mathcal{L}_{right}\).
