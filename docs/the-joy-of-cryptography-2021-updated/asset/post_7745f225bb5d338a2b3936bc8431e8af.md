
=\left|\begin{aligned} &\left( \Pr[\mathcal{A} \diamond \mathcal{L}_{left} \Rightarrow 1 \mid \mathcal{B}_{left}] \cdot p^* + \Pr[\mathcal{A} \diamond \mathcal{L}_{left} \Rightarrow 1 \mid \overline{\mathcal{B}_{left}}](1 - p^*) \right) \\ -\left( \Pr[\mathcal{A} \diamond \mathcal{L}_{right} \Rightarrow 1 \mid \mathcal{B}_{right}] \cdot p^* + \Pr[\mathcal{A} \diamond \mathcal{L}_{right} \Rightarrow 1 \mid \overline{\mathcal{B}_{right}}](1 - p^*) \right) \end{aligned}\right|\\
=\left|\begin{aligned} &p^* \left( \Pr[\mathcal{A} \diamond \mathcal{L}_{left} \Rightarrow 1 \mid \mathcal{B}_{left}] - \Pr[\mathcal{A} \diamond \mathcal{L}_{right} \Rightarrow 1 \mid \mathcal{B}_{right}] \right) \\ &(1 - p^*) \left( \Pr[\mathcal{A} \diamond \mathcal{L}_{left} \Rightarrow 1 \mid \overline{\mathcal{B}_{left}}] - \Pr[\mathcal{A} \diamond \mathcal{L}_{right} \Rightarrow 1 \mid \overline{\mathcal{B}_{right}}] \right) \end{aligned}\right|

In both of the expressions \(\Pr[\mathcal{A} \diamond \mathcal{L}_{left} \Rightarrow 1 \mid \overline{\mathcal{B}_{left}}]\) and \(\Pr[\mathcal{A} \diamond \mathcal{L}_{right} \Rightarrow 1 \mid \overline{\mathcal{B}_{right}}]\), we are conditioning on bad never being set to 1. In this case, both libraries are executing the same sequence of instructions, so the probabilities are equal (and the difference of the probabilities is zero). Substituting in, we get:

advantage_\mathcal{A} = p^* \left| \Pr[\mathcal{A} \diamond \mathcal{L}_{left} \Rightarrow 1 \mid \mathcal{B}_{left}] - \Pr[\mathcal{A} \diamond \mathcal{L}_{right} \Rightarrow 1 \mid \mathcal{B}_{right}] \right|

Intuitively, the proof is confirming the idea that differences can only be noticed between \(\mathcal{L}_{left}\) and \(\mathcal{L}_{right}\) when bad is set to 1 (corresponding to our conditioning on \(\mathcal{B}_{left}\) and \(\mathcal{B}_{right}\)).

The quantity within the absolute value is the difference of two probabilities, so the largest it can be is 1. Therefore,

advantage_\mathcal{A} \leq^* p^* \stackrel{\text{def}}{=} \Pr[\mathcal{B}_{left}] = \Pr[\mathcal{A} \diamond \mathcal{L}_{left} \text{ sets bad } = 1].

This completes the proof.

**Example** Consider \(\mathcal{L}_{left}\) and \(\mathcal{L}_{right}\) from the previous example (where the calling program tries to "predict" the result of uniformly sampling a \(\lambda\)-bit string). We can prove that they are indistinguishable with the following sequence of hybrids:

![](img/da79fa21b263fe549aecaabd2a0a41c8_85_0.png)

Let us justify each of the steps:

-   \(\mathcal{L}_{left} \equiv \mathcal{L}_{hyb-L}\): The only difference is that \(\mathcal{L}_{hyb-L}\) maintains a variable “bad.” Since it never actually reads from this variable, the change can have no effect.

-   \(\mathcal{L}_{hyb-L}\) and \(\mathcal{L}_{hyb-R}\) differ only in the highlighted line, which can only be reached when \(bad = 1\). Therefore, from the bad-event lemma:

\left| \Pr[\mathcal{A} \diamond \mathcal{L}_{hyb-L} \Rightarrow 1] - \Pr[\mathcal{A} \diamond \mathcal{L}_{hyb-R} \Rightarrow 1] \right| \leq \Pr[\mathcal{A} \diamond \mathcal{L}_{hyb-L} \text{ sets bad } = 1].

But \(\mathcal{A} \diamond \mathcal{L}_{\text{hyb-L}}\) only sets \(bad = 1\) if the calling program successfully predicts \(s\) in one of the calls to \(\text{PREDICT}\). With \(q\) calls to \(\text{PREDICT}\), the total probability of this happening is at most \(q/2^\lambda\), which is negligible when the calling program runs in polynomial time. ## 4.4 Birthday Probabilities & Sampling With/out Replacement

In many cryptographic schemes, the users repeatedly choose random strings (e.g., each time they encrypt a message), and security breaks down if the same string is ever chosen twice. Hence, it is important that the probability of a repeated sample is negligible. In this section we compute the probability of such events and express our findings in a modular way, as a statement about the indistinguishability of two libraries.

### Birthday Probabilities

If \(q\) people are in a room, what is the probability that two of them have the same birthday (if we assume that each person's birthday is uniformly chosen from among the possible days in a year)? This question is known as the **birthday problem**, and it is famous because the answer is highly unintuitive to most people.\(^9\)

Let's make the question more general. Imagine taking \(q\) independent, uniform samples from a set of \(N\) items. What is the probability that the same value gets chosen more than once? In other words, what is the probability that the following program outputs 1?

```
B(q, N)
for i := 1 to q:
    s_i <- {1, ..., N}
    for j := 1 to i - 1:
        if s_i = s_j then return 1
return 0
```

Let's give a name to this probability:

BirthdayProb(q, N) \stackrel{\text{def}}{=} \Pr[\mathcal{B}(q, N) \text{ outputs } 1].

It is possible to write an exact formula for this probability:

Lemma 4.9 BirthdayProb(q, N) = 1 - \prod_{i=1}^{q-1} \left( 1 - \frac{i}{N} \right).

\(^9\)It is sometimes called the "birthday paradox," even though it is not really a paradox. The actual birthday paradox is that the "birthday paradox" is not a paradox.

Proof Let us instead compute the probability that \(\mathcal{B}\) outputs 0, which will allow us to then solve for the probability that it outputs 1. In order for \(\mathcal{B}\) to output 0, it must avoid the early termination conditions in each iteration of the main loop. Therefore:

```
\(\text{Pr}[\mathcal{B}(q, N) \text{ outputs } 0] = \text{Pr}[\mathcal{B}(q, N) \text{ doesn't terminate early in iteration } i = 1]\)
\(\cdot \text{Pr}[\mathcal{B}(q, N) \text{ doesn't terminate early in iteration } i = 2]\)
\(\vdots\)
\(\cdot \text{Pr}[\mathcal{B}(q, N) \text{ doesn't terminate early in iteration } i = q]\)
```

In iteration \(i\) of the main loop, there are \(i - 1\) previously chosen values \(s_1, ..., s_{i-1}\). The program terminates early if any of these are chosen again as \(s_i\), otherwise it continues to the next iteration. Put differently, there are \(i - 1\) (out of \(N\)) ways to choose \(s_i\) that lead to early termination — all other choices of \(s_i\) avoid early termination. Since the \(N\) possibilities for \(s_i\) happen with equal probability:

```
\(\text{Pr}[\mathcal{B}(q, N) \text{ doesn't terminate early in iteration } i] = 1 - \frac{i - 1}{N}.\)
```

Putting everything together:

```
\(\text{BirthdayProb}(q, N) = \text{Pr}[\mathcal{B}(q, N) \text{ outputs } 1]\)
\(= 1 - \text{Pr}[\mathcal{B}(q, N) \text{ outputs } 0]\)
\(= 1 - \left(1 - \frac{1}{N}\right) \left(1 - \frac{2}{N}\right) \cdots \left(1 - \frac{q - 1}{N}\right)\)
\(= 1 - \prod_{i=1}^{q-1} \left(1 - \frac{i}{N}\right)\)
```

This completes the proof.

### Example

This formula for \(\text{BirthdayProb}(q, N)\) is not easy to understand at a glance. We can get a better sense of its behavior as a function of \(q\) by plotting it. Below is a plot with \(N = 365\), corresponding to the classic birthday problem:

### Asymptotic Bounds on the Birthday Probability

It will be helpful to have an *asymptotic* formula for how BirthdayProb(q, N) grows as a function of q and N. We are most interested in the case where q is relatively small compared to N (e.g., when q is a polynomial function of λ but N is exponential).

**Lemma 4.10** (Birthday Bound) If \( q \le \sqrt{2N} \), then

\( 0.632 \frac{q(q-1)}{2N} \le \text{BirthdayProb}(q, N) \le \frac{q(q-1)}{2N} \).

Since the upper and lower bounds differ by only a constant factor, it makes sense to write \(\text{BirthdayProb}(q, N) = \Theta(q^2/N)\).

### Proof

We split the proof into two parts.

-   To prove the upper bound, we use the fact that when x and y are positive,

\( (1-x)(1-y) = 1 - (x+y) + xy \ge 1 - (x+y) \).

More generally, when all terms \(x_i\) are positive, \(\prod_i(1-x_i) \ge 1 - \sum_i x_i\). Hence, \( 1 - \prod_i(1-x_i) \le 1 - (1 - \sum_i x_i) = \sum_i x_i \).

Applying that fact,

\(\text{BirthdayProb}(q, N) \stackrel{\text{def}}{=} 1 - \prod_{i=1}^{q-1} \left(1 - \frac{i}{N}\right) \le \sum_{i=1}^{q-1} \frac{i}{N} = \frac{\sum_{i=1}^{q-1} i}{N} = \frac{q(q-1)}{2N}.\)

-   To prove the lower bound, we use the fact that when \( 0 \le x \le 1 \),

\( 1 - x \le e^{-x} \le 1 - 0.632x \).

This fact is illustrated below. The significance of 0.632 is that \( 1 - \frac{1}{e} = 0.63212 \dots \).

![](img/da79fa21b263fe549aecaabd2a0a41c8_88_0.png)

We can use both of these upper and lower bounds on \( e^{-x} \) to show the following:

\( \prod_{i=1}^{q-1} \left(1 - \frac{i}{N}\right) \le \prod_{i=1}^{q-1} e^{-\frac{i}{N}} = e^{-\sum_{i=1}^{q-1} \frac{i}{N}} = e^{-\frac{q(q-1)}{2N}} \le 1 - 0.632 \frac{q(q-1)}{2N} \).
