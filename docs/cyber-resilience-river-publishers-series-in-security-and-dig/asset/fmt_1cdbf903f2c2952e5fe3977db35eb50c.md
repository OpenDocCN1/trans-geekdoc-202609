
# 邮件系统架构文档

## 现状分析

莫斯科的预留通道未组织建设，基于回顾性数据表明通道恢复速度极快。后端服务器未采用集群解决方案。绝大多数站点的邮件服务器同时承担**前端**和**后端**角色。

作为入站**SMTP网关**，部署了**2台垃圾邮件过滤服务器**。在正常模式下，服务器（**MX, 10** = `ba 01.***.ru` = `***.248.20.152` = `10.0.0.166`）接收主要邮件流量，服务器（**MX, 20** = `ba 02.***.ru` = `***.248.20.158` = `10.0.0.167`）作为热备。服务器位于集群中，确保配置文件统一。邮件传输到Exchange服务器通过静态**IP路由**实现，这是潜在故障点，桥头服务器故障时需手动重新配置**SMTP网关**。两台服务器均通过在**BGP协议**层面具有冗余的通道连接互联网。

外部**DNS区域**由位于不同机房的**2台DNS服务器**维护（`a:ns:***:ru` 和 `b:ns:***:ru` (=`swap`)`）。内部用户的**DNS区域**由**2台DNS服务器**维护（`cerber` 和 `coil`）。

出站**SMTP邮件**及分支机构网络的**SMTP邮件**（**库尔斯克-库尔干**站点对除外）通过**CommuniGate Pro 4.8 SMTP网关**传递：主网关（`10:0:0:144` = `dragon`）或备用网关（`10:0:0:144` = `bambi`）。**SMTP**网关无自动流量均衡，主服务器故障需手动切换。**SMTP**队列未做预留。

除**萨拉托夫和萨马拉**分支机构大多数客户端（超过**60%**）使用**SMTP和POP3**协议外，连接客户端邮件程序到服务器的协议均为**RPC/TCP/IP**栈。

故障监控与报告由监控专家使用**MOM 2015 (Exchange模块)**、**HP OpenView (WAN网络、局域网交换节点供电)** 以及全球网络部专家（WAN网络、SMTP网关）执行。工作日专家接收入侵报警器通知，且**24**小时内接收严重事故通知（服务器故障、重启等）。工作时间告警阶段持续**5**分钟。

备份覆盖系统所有组件，包括以下层级：
*   文件系统层级
*   Microsoft Windows系统状态层级
*   Microsoft Exchange存储层级
*   单个Microsoft Exchange邮箱层级

最小备份时间量子为 **1** 天。

## 目标架构

目标架构基于将服务器邮件系统整合至位于俄罗斯联邦各主体的若干邮件处理和存储中心，以优化数据传输通道负载并提高服务弹性。拟议架构包含：

### 总部处理中心
基于以下组件：
*   **2台垃圾邮件过滤器集群** (`Barracuda` - `Barracuda Networks`)
*   后端服务器集群（按`AAP`方案）
*   **NLB场中的2台ISA服务器**
*   **带ISA负载均衡的2台前端服务器场**
*   **NLB场中的2台桥头服务器**
*   **2台CommuniGatePro SMTP网关**（用于发送互联网**SMTP**邮件及分支网络邮件路由）
*   **2台**记录收发邮件的服务器 (`Dozor-Jet Jet Infosystems`)

### 喀山处理中心
基于以下组件实施：
*   后端服务器集群（按`AAP`方案）
*   **2台前端服务器场**
*   **2台CommuniGatePro SMTP网关**（分别用于收发邮件）
*   **2台桥头服务器 + 2台ISA服务器**

### 伏尔加-维亚特卡处理中心
基于以下组件实施：
*   后端服务器集群（按`AA`方案）
*   **CommuniGatePro SMTP网关**
*   **ISA服务器**

### 客户端连接协议

**企业网络内部：**
*   **Microsoft Outlook** 使用 `RPC/TCP/IP` 栈（缓存和非缓存模式）
*   **OWA接口** (`HTTPS`)
*   **EAS接口**

**企业网络外部：**
*   **Microsoft Outlook** 使用 `RPC/HTTPS/TCP/IP` 栈（缓存和非缓存模式）
*   **OWA接口** (`HTTPS`)
*   **EAS接口**

### 监控与归档

为监控IT服务及故障告警，部署 **MOM 2015** 服务器。

为归档并确保对归档邮件的有效访问，部署基于双服务器方案且具有2个独立信息存储库的 **Symantec Enterprise Vault**。同时部署基于 **Symantec Veritas NetBackup** 软件的备份恢复系统。亦使用基于 NetBackup 的备份系统；Exchange数据使用 **Windows 2018** 标准工具 `NTBackup.exe` 备份。最小备份量子为 1 天。

### 服务恢复优先级

根据企业要求，服务恢复优先级排序如下：
*   **最高级**（恢复时间不超过 2 小时）
*   **高级**（恢复时间 4 小时）
*   **标准级**（恢复时间 8 小时）
*   **低级**（恢复时间 2 个工作日）
*   **零级**（恢复时间 5 个工作日）
