向服务器添加功能很容易。一个有用的添加是特定的 URL 返回某种状态。例如，这个版本执行相同的 echo 但也计算请求数量；对 URL `/count` 的请求返回迄今为止的计数，不包括 `/count` 请求本身：

[点击此处查看代码图像](#part0129_split_021.html#id020pro02_r)

`gopl.io/ch1/server2`

```
// Server2 is a minimal "echo" and counter server.
package main

import (
    "fmt"
    "log"
    "net/http"
    "sync"
)

var mu sync.Mutex
var count int

func main() {
    http.HandleFunc("/", handler)
    http.HandleFunc("/count", counter)
    log.Fatal(http.ListenAndServe("localhost:8000", nil))
}

// handler echoes the Path component of the requested URL.
func handler(w http.ResponseWriter, r *http.Request) {
    mu.Lock()
    count++
    mu.Unlock()
    fmt.Fprintf(w, "URL.Path = %q\n", r.URL.Path)
}

// counter echoes the number of calls so far.
func counter(w http.ResponseWriter, r *http.Request) {
    mu.Lock()
    fmt.Fprintf(w, "Count %d\n", count)
    mu.Unlock()
}
```

服务器有两个处理器，请求的 URL 决定调用哪一个：对 `/count` 的请求调用 `counter`，其他所有请求调用 `handler`。以斜杠结尾的处理器模式匹配任何以该模式为前缀的 URL。在后台，服务器为每个传入请求在单独的 `goroutine` 中运行处理器，以便同时服务多个请求。然而，如果两个并发请求尝试同时更新 `count`，可能无法一致地递增；程序将有一个称为 *race condition*（竞态条件）的严重 Bug（[§9.1](#part0088.html#id-raceconditions)）。为避免此问题，我们必须确保一次最多只有一个 `goroutine` 访问该变量，这就是 `mu.Lock()` 和 `mu.Unlock()` 调用括住每次 `count` 访问的目的。我们将在[第 9 章](#part0087.html#id-concurrencywithsharedvariables)更仔细地研究带共享变量的并发。

作为一个更丰富的示例，处理器函数可以报告它接收到的头部和表单数据，使服务器可用于检查和调试请求：

[点击此处查看代码图像](#part0129_split_022.html#id021pro01_r)

`gopl.io/ch1/server3`

```
// handler echoes the HTTP request.
func handler(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintf(w, "%s %s %s\n", r.Method, r.URL, r.Proto)
    for k, v := range r.Header {
        fmt.Fprintf(w, "Header[%q] = %q\n", k, v)
    }
    fmt.Fprintf(w, "Host = %q\n", r.Host)
    fmt.Fprintf(w, "RemoteAddr = %q\n", r.RemoteAddr)
    if err := r.ParseForm(); err != nil {
        log.Print(err)
    }
    for k, v := range r.Form {
        fmt.Fprintf(w, "Form[%q] = %q\n", k, v)
    }
}
```

这使用 `http.Request` 结构体的字段产生如下输出：

[点击此处查看代码图像](#part0129_split_023.html#id021pro02_r)

```
GET /?q=query HTTP/1.1
Header["Accept-Encoding"] = ["gzip, deflate, sdch"]
Header["Accept-Language"] = ["en-US,en;q=0.8"]
Header["Connection"] = ["keep-alive"]
Header["Accept"] = ["text/html,application/xhtml+xml,application/xml;..."]
Header["User-Agent"] = ["Mozilla/5.0 (Macintosh; Intel Mac OS X 10_7_5)..."]
Host = "localhost:8000"
RemoteAddr = "127.0.0.1:59911"
Form["q"] = ["query"]
```

注意 `ParseForm` 的调用嵌套在 `if` 语句中。Go 允许简单语句（如局部变量声明）位于 `if` 条件之前，这对于错误处理特别有用，如此例所示。我们也可以写成：

```
err := r.ParseForm()
if err != nil {
    log.Print(err)
}
```

但合并语句更简短并减少变量 `err` 的作用域，这是良好的实践。我们将在[第 2.7 节](#part0027.html#id-scope)定义作用域。

在这些程序中，我们见到三种截然不同的类型用作输出流。`fetch` 程序将 HTTP 响应数据复制到 `os.Stdout`（一个文件），`lissajous` 程序也是如此。`fetchall` 程序通过复制到微不足道的接收器 `ioutil.Discard` 丢弃响应（同时计算其长度）。上面的 Web 服务器使用 `fmt.Fprintf` 写入 `http.ResponseWriter`（代表 Web 浏览器）。

虽然这三种类型在做什么的细节上不同，但它们都满足一个通用的 *interface*（接口），允许在需要输出流的任何地方使用它们。该接口称为 `io.Writer`，在[第 7.1 节](#part0061.html#id-interfacesascontracts)讨论。

Go 的接口机制是[第 7 章](#part0060.html#id-interfaces)的主题，但为了展示其能力，让我们看看将 Web 服务器与 `lissajous` 函数结合有多容易，使动画 GIF 写入 HTTP 客户端而非标准输出。只需向 Web 服务器添加这些行：

[点击此处查看代码图像](#part0129_split_024.html#id022pro01_r)

```
handler := func(w http.ResponseWriter, r *http.Request) {
    lissajous(w)
}
http.HandleFunc("/", handler)
```

或等价地：

[点击此处查看代码图像](#part0129_split_025.html#id022pro02_r)

```
http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
    lissajous(w)
})
```

紧接在上方 `HandleFunc` 函数调用的第二个参数是一个 *function literal*（函数字面量），即在使用点定义的匿名函数。我们将在[第 5.6 节](#part0048.html#id-anonymousfunctions)进一步解释。

做完此更改后，在浏览器访问 `http://localhost:8000`。每次加载页面，你都会看到如[图 1.3](#part0018.html#id-figures-lissajous-browser)所示的新动画。
