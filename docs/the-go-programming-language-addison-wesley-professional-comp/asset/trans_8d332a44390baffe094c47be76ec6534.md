
最后，一个重要提醒：正如我们在[第 1.7 节](#part0018.html#id-awebserver)中提到的，Web 服务器会在一个新的 `goroutine` 中调用每个处理程序，因此当处理程序访问的变量可能被其他 `goroutine`（包括对同一处理程序的其他请求）同时访问时，必须采取预防措施，如 `locking`（加锁）。我们将在接下来的两章中讨论并发。

### 练习 7.11

## 7.8 `error` 接口

自本书开篇以来，我们一直在使用和创建神秘的预声明 `error` 类型的值，却未解释它到底是什么。实际上，它只是一个接口类型，拥有一个返回错误消息的方法：

```
type error interface {
    Error() string
}
```

创建 `error` 最简单的方法是调用 `errors.New`，它会为给定的错误消息返回一个新的 `error`。整个 `errors` 包只有四行代码：

[点击此处查看代码图像](#part0137_split_062.html#id196pro01_r)

```
package errors

func New(text string) error { return &errorString{text} }

type errorString struct { text string }

func (e *errorString) Error() string { return e.text }
```

`errorString` 的底层类型是结构体而非字符串，以防止其表示被无意（或蓄意）更新。之所以指针类型 `*errorString` 而非 `errorString` 本身满足 `error` 接口，是为了让每次调用 `New` 都分配一个独特的 `error` 实例，使其不等于任何其他实例。我们不希望像 `io.EOF` 这样特殊的错误与仅碰巧具有相同消息的错误比较相等。

[点击此处查看代码图像](#part0137_split_063.html#id196pro02_r)

```
fmt.Println(errors.New("EOF") == errors.New("EOF")) // "false"
```

调用 `errors.New` 相对较少，因为有一个方便的包装函数 `fmt.Errorf`，它也能进行字符串格式化。我们在[第 5 章](#part0042.html#id-functions)中多次使用过它。

[点击此处查看代码图像](#part0137_split_064.html#id196pro03_r)

```
package fmt

import "errors"

func Errorf(format string, args ...interface{}) error {
    return errors.New(Sprintf(format, args...))
}
```

虽然 `*errorString` 可能是最简单的 `error` 类型，但远非唯一。例如，`syscall` 包提供了 Go 的低级系统调用 API。在许多平台上，它定义了一个满足 `error` 的数值类型 `Errno`，而在 Unix 平台上，`Errno` 的 `Error` 方法会在字符串表中查找，如下所示：

[点击此处查看代码图像](#part0137_split_065.html#id196pro04_r)

```
package syscall

type Errno uintptr // 操作系统错误代码

var errors = [...]string{
    1:   "operation not permitted",   // EPERM
    2:   "no such file or directory", // ENOENT
    3:   "no such process",           // ESRCH
    // ...
}

func (e Errno) Error() string {
    if 0 <= int(e) && int(e) < len(errors) {
        return errors[e]
    }
    return fmt.Sprintf("errno %d", e)
}
```

以下语句创建了一个持有 `Errno` 值 `2` 的接口值，表示 POSIX `ENOENT` 状况：

[点击此处查看代码图像](#part0137_split_066.html#id197pro01_r)

```
var err error = syscall.Errno(2)
fmt.Println(err.Error()) // "no such file or directory"
fmt.Println(err)         // "no such file or directory"
```

`err` 的值如[图 7.6](#part0068.html#id-figures-iface-errno)所示。

![An interface value holding a syscall.Errno integer.](images/00030.jpeg)

**图 7.6.** 一个持有 `syscall.Errno` 整数的接口值。

`Errno` 是从有限集合中提取的系统调用错误的高效表示，并满足标准 `error` 接口。我们将在[第 7.11 节](#part0071.html#id-discriminatingerrors)中看到其他满足此接口的类型。

## 7.9 示例：表达式求值器

在本节中，我们将构建一个简单算术表达式的求值器。我们将使用一个接口 `Expr` 来表示该语言中的任意表达式。目前该接口不需要任何方法，但我们稍后会添加。

[点击此处查看代码图像](#part0137_split_067.html#id197pro02_r)

```
// An Expr is an arithmetic expression.
type Expr interface{}
```

我们的表达式语言包含浮点字面量；二元运算符 `+`、`-`、`*` 和 `/`；一元运算符 `-x` 和 `+x`；函数调用 `pow(x,y)`、`sin(x)` 和 `sqrt(x)`；变量如 `x` 和 `pi`；当然还有括号和标准运算符优先级。所有值均为 `float64` 类型。以下是一些示例表达式：

```
sqrt(A / pi)
pow(x, 3) + pow(y, 3)
(F - 32) * 5 / 9
```

下面的五个具体类型分别代表特定种类的表达式。`Var` 表示对变量的引用。（我们很快就会看到为什么它是导出的。）`literal` 表示浮点常量。`unary` 和 `binary` 类型分别表示具有一个或两个操作数的运算符表达式，操作数可以是任意 `Expr`。`call` 表示函数调用；我们将其 `fn` 字段限制为 `pow`、`sin` 或 `sqrt`。

[点击此处查看代码图像](#part0137_split_068.html#id198pro01_r)

```
gopl.io/ch7/eval

// A Var identifies a variable, e.g., x.
type Var string

// A literal is a numeric constant, e.g., 3.141.
type literal float64

// A unary represents a unary operator expression, e.g., -x.
type unary struct {
    op rune // one of '+', '-'
    x  Expr
}

// A binary represents a binary operator expression, e.g., x+y.
type binary struct {
    op   rune // one of '+', '-', '*', '/'
    x, y Expr
}

// A call represents a function call expression, e.g., sin(x).
type call struct {
    fn   string // one of "pow", "sin", "sqrt"
    args []Expr
}
```

为了求值包含变量的表达式，我们需要一个将变量名映射到值的*环境*：

```
type Env map[Var]float64
```

我们还需要每种表达式定义一个 `Eval` 方法，返回该表达式在给定环境中的值。因为每个表达式都必须提供此方法，所以我们将其添加到 `Expr` 接口中。该包仅导出 `Expr`、`Env` 和 `Var` 类型；客户端无需访问其他表达式类型即可使用求值器。

[点击此处查看代码图像](#part0137_split_069.html#id198pro02_r)

```
type Expr interface {
    // Eval returns the value of this Expr in the environment env.
    Eval(env Env) float64
}
```

具体的 `Eval` 方法如下所示。`Var` 的方法执行环境查找，若变量未定义则返回零值；`literal` 的方法直接返回字面量值。

[点击此处查看代码图像](#part0137_split_070.html#id199pro01_r)

```
func (v Var) Eval(env Env) float64 {
    return env[v]
}

func (l literal) Eval(_ Env) float64 {
    return float64(l)
}
```

`unary` 和 `binary` 的 `Eval` 方法递归求值其操作数，然后将运算符 `op` 应用于它们。我们不将除零或溢出视为错误，因为它们会产生明确定义的结果（尽管非有限）。最后，`call` 的方法对 `pow`、`sin` 或 `sqrt` 函数的参数求值，然后调用 `math` 包中对应的函数。
