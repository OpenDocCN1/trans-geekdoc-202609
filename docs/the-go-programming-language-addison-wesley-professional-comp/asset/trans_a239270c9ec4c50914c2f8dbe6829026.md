

# Package memo

## 实现

```
// Package memo 提供了一个非并发安全的
// Func 类型函数的备忘录模式实现。
package memo

// Memo 缓存调用 Func 的结果。
type Memo struct {
    f     Func
    cache map[string]result
}

// Func 是要备忘的函数类型。
type Func func(key string) (interface{}, error)

type result struct {
    value interface{}
    err   error
}

func New(f Func) *Memo {
    return &Memo{f: f, cache: make(map[string]result)}
}

// 注意：非并发安全！
func (memo *Memo) Get(key string) (interface{}, error) {
    res, ok := memo.cache[key]
    if !ok {
        res.value, res.err = memo.f(key)
        memo.cache[key] = res
    }
    return res.value, res.err
}
```

`Memo` 实例持有要备忘的函数 `f`（类型为 `Func`）和缓存，缓存是一个从字符串到 `result` 的映射。每个 `result` 就是调用 `f` 返回的那对结果——一个值和一个错误。随着设计的演进，我们将展示 `Memo` 的几种变体，但它们都共享这些基本特征。

## 使用示例

下面展示了如何使用 `Memo` 的示例。对于传入 URL 流中的每个元素，我们调用 `Get`，记录调用的延迟和返回的数据量：

```
m := memo.New(httpGetBody)
for url := range incomingURLs() {
    start := time.Now()
    value, err := m.Get(url)
    if err != nil {
        log.Print(err)
    }
    fmt.Printf("%s, %s, %d bytes\n",
        url, time.Since(start), len(value.([]byte)))
}
```

## 并发访问问题

由于 HTTP 请求是并行化的绝佳机会，让我们修改测试，使其并发发起所有请求。测试使用 `sync.WaitGroup` 等待最后一个请求完成后再返回。

```
m := memo.New(httpGetBody)
var n sync.WaitGroup
for url := range incomingURLs() {
    n.Add(1)
    go func(url string) {
        start := time.Now()
        value, err := m.Get(url)
        if err != nil {
            log.Print(err)
        }
        fmt.Printf("%s, %s, %d bytes\n",
            url, time.Since(start), len(value.([]byte)))
        n.Done()
    }(url)
}
n.Wait()
```

测试运行得快多了，但遗憾的是它不太可能始终正确工作。我们可能会注意到意外的缓存未命中、返回错误值的缓存命中，甚至崩溃。

更糟的是，它很可能*有时*能正确工作，所以我们甚至可能注意不到它有问题。但如果我们使用 `-race` 标志运行它，竞态检测器（[§9.6](#part0093.html#id-theracedetector)）通常会打印如下报告：

## 改进版本

### memo2：互斥锁保护

使缓存并发安全的最简单方法是使用基于监视器的同步。我们只需向 `Memo` 添加一个互斥锁，在 `Get` 开头获取锁，在 `Get` 返回前释放锁，使两个 `cache` 操作都发生在临界区内：

```
type Memo struct {
    f     Func
    mu    sync.Mutex // 保护 cache
    cache map[string]result
}

// Get 是并发安全的。
func (memo *Memo) Get(key string) (value interface{}, err error) {
    memo.mu.Lock()
    res, ok := memo.cache[key]
    if !ok {
        res.value, res.err = memo.f(key)
        memo.cache[key] = res
    }
    memo.mu.Unlock()
    return res.value, res.err
}
```

现在即使并发运行测试，竞态检测器也保持静默。遗憾的是，这种对 `Memo` 的更改抵消了我们之前的性能收益。由于在每次调用 `f` 期间持有锁，`Get` 将我们打算并行化的所有 I/O 操作串行化了。我们需要的是一个*非阻塞*缓存，即不会串行化它所备忘函数调用的缓存。

### memo3：双重检查锁定

在下面的 `Get` 实现中，调用 goroutine 获取锁两次：第一次用于查找，如果查找未返回结果，则第二次用于更新。在此期间，其他 goroutine 可以自由使用缓存。

```
func (memo *Memo) Get(key string) (value interface{}, err error) {
    memo.mu.Lock()
    res, ok := memo.cache[key]
    memo.mu.Unlock()
    if !ok {
        res.value, res.err = memo.f(key)

        // 在两个临界区之间，多个 goroutine
        // 可能竞争计算 f(key) 并更新 map。
        memo.mu.Lock()
        memo.cache[key] = res
        memo.mu.Unlock()
    }
    return res.value, res.err
}
```

性能再次提升，但现在我们注意到某些 URL 被获取了两次。当两个或多个 goroutine 大约在同一时间为同一 URL 调用 `Get` 时，就会发生这种情况。两者都查询缓存，发现没有值，然后调用慢速函数 `f`。随后两者都用各自获得的结果更新 map。其中一个结果会被另一个覆盖。

### memo4：使用通道抑制重复

理想情况下，我们希望避免这种冗余工作。此功能有时称为*重复抑制*。在下面的 `Memo` 版本中，每个 map 元素是一个指向 `entry` 结构体的指针。每个 `entry` 包含对函数 `f` 调用的备忘结果，如前所述，但它额外包含一个名为 `ready` 的通道。就在 `entry` 的 `result` 被设置后，该通道将被关闭，以便*广播*（[§8.9](#part0085.html#id-broadcast)）给任何其他 goroutine，告知它们现在可以安全地从 `entry` 读取结果了。

