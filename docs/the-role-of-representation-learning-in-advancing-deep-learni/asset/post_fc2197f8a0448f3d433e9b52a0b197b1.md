
## 2. Second stage operations:

- (a) Flattening: This reshaping operation has complexity of O(1).

- (b) Neighborhood-based transformer encoding: Similar to the window-based attention analysis, the complexity is O(H_l W_l (2n_l + 1)^4). This is because we perform self-attention within each group of (2n_l + 1)^2 nodes, and we have H_l W_l such groups. Assuming a constant n_l, the overall complexity of this step: O(H_l W_l).

- (c) Selection of refined nodes: This involves selecting the refined embedding of the central node in each group, which is an indexing operation with a complexity of O(1).

Therefore, the complexity of constructing a single tree level T_{l+1} is O(H_l W_l), linear in the number of nodes from the previous level.

Now, let's determine the complexity of constructing the entire tree. Without loss of generality, we only consider operations associated with the attention mechanism. This is not a problem, since the complexity of the attention mechanism dominates that of the other operations. Attention operations are repeated L - 1 times, where L is the number of tree levels. The total number of operations is then proportional to:

\sum_{l=0}^{L-2}(K_h K_w)^2 \frac{H_l W_l}{K_h K_w} + (2n_l + 1)^4 H_l W_l \le (K_h K_w + (2n_{max} + 1)^4) \sum_{l=0}^{L-2} \frac{H_0 W_0}{K_h^l K_w^l}
\le H_0 W_0 (K_h K_w + (2n_{max} + 1)^4) \sum_{l=0}^{L-2} (\frac{1}{K_h K_w})^l
\le H_0 W_0 (K_h K_w + (2n_{max} + 1)^4) \frac{1 - (\frac{1}{K_h K_w})^{L-1}}{1 - \frac{1}{K_h K_w}}
\le H_0 W_0 K_h K_w (K_h K_w + (2n_{max} + 1)^4) \frac{1 - (\frac{1}{K_h K_w})^{L-1}}{K_h K_w - 1}
\le H_0 W_0 \frac{K_h K_w (K_h K_w + (2n+1)^4)}{K_h K_w - 1}

The first inequality comes from n_{max} = \max_{0 \le l < L} n_l. The last inequality comes from the fact that K_h K_w > 1 and L \ge 1.

We conclude that the complexity of constructing the entire tree is O \left( H_0 W_0 \frac{K_h K_w (K_h K_w + (2n+1)^4)}{K_h K_w - 1} \right) = O(H_0 W_0) = O(N_E), linear in the number of input (encoder) tokens.

## D.3 Details on Decoder Computational Complexity

Let \(\mathcal{T} = \{T_l\}_{l=0}^{L-1}\) be the tree representation of an input image \(I\), where \(T_l \in \mathbb{R}^{H_l \times W_l \times d_{model}}\) corresponds to the node embeddings at level \(l\). Given the way the tree is constructed, we have that \(H_l = H_0 / K_h^l\) and \(W_l = W_0 / K_w^l\), \(\forall l \in \{0, ..., L-1\}\). Additionally, \(L = \min \left\{ \log_{K_h}(H_0), \log_{K_w}(W_0) \right\}\). Finally, let \(N_E = H_0 W_0\) be number of input encoder tokens and let \(N_D\) be the number of decoder tokens.

### D.3.1 Best-Node Parser

### Parsing Complexity

We analyze the complexity of Algorithm 4.2 by examining the operations within each iteration:

- 1. Children\(\left(\cdot\right)\): This is an indexing operation with a complexity of \(O(1)\).

- 2. Computation of \(K\): Projecting the node embeddings involves matrix-vector multiplication. Assuming a naive implementation this has a complexity of \(O\left(K_h K_w d^2_{model}\right)\), where \(K_h K_w\) is the number nodes being projected. This complexity is independent of the number of input encoder tokens \(N_E\).

- 3. Similarity Scores: Computing the similarity scores between the query vector \(\bar{\mathbf{q}}\) and the projected node embeddings \(K\) involves dot products. This has a complexity of \(O\left(K_h K_w d_{model}\right)\), also independent of \(N_E\).

- 4. arg max operation: Finding the node with the maximum similarity score has a complexity of \(O\left(K_h K_w\right)\).

These operations are repeated \(L\) times, where \(L\) is the number of levels in the tree. Therefore, the overall parsing complexity is:

```
\(O\left(L\left(K_h K_w\right) d^2_{model}\right) = O \left(\min \left\{ \log_{K_h} H_0, \log_{K_w} W_0 \right\} \left(K_h K_w\right) d^2_{model}\right)\)
\(= O \left(\min \left\{ \log_{K_h} H_0, \log_{K_w} W_0 \right\}\right)\)
\(= O\left(\ln \min\{H_0, W_0\}\right)\)
```

Assuming, without loss of generality, that \(H_0 \le W_0\), we have \(N_E = H_0 W_0 \ge H_0^2\). This implies \(\sqrt{N_E} \ge H_0\) and \(\ln \sqrt{N_E} \ge \ln H_0\). Thus, the parsing complexity can be expressed as \(O(\ln \sqrt{N_E})\), logarithmic in the square root of the number of encoder tokens.

### Cross-Attention Complexity

The Best-Node Parser selects \((L-1)(K_h K_w - 1)\) background nodes (siblings of the best-scoring node at each level) and \(K_h K_w\) leaf nodes, resulting in a total of \(L(K_h K_w - 1) + 1\) selected nodes. Therefore, the complexity of the cross-attention operation is:

```
\(O(N_D L) = O(N_D \ln \min\{H_0, W_0\})\)
\(= O(N_D \ln \sqrt{N_E})\)
```

### D.3.2 Sliding Window Parser

### Parsing Complexity

We analyze the complexity of Algorithm 4.3 by examining the operations within each iteration. Similar to the Best-Node Parser, the initial steps involve extracting the children of a node, projecting the node embeddings (i.e. computing \(K\)), calculating similarity scores and finding the node with maximum score. These operations, as detailed in D.3.1, have a combined complexity of \(O((K_h K_w) d_{\text{model}}^2)\). In addition to these steps, the Sliding Window Parser performs the following operations:

- 1. AreaOfInterest(\(\cdot\)): This is an indexing operation with a complexity of \(O(1)\).

- 2. Computation of \(\tilde{K}\): Projecting the node embeddings in the expanded search area has a complexity of \(O(K_h K_w d_{\text{model}}^2)\), similar to the computation of \(K\).

- 3. SelectNodes(\(\cdot\)): This involves:
- (a) 2D convolution: This operation slides a window of size \(\tilde{K}_h \times \tilde{K}_w\) across the attention scores to identify the region with the highest cumulative score. The complexity is \(O((3K_h - \tilde{K}_h + 1)(3K_w - \tilde{K}_w + 1)(\tilde{K}_h \tilde{K}_w)) = O(1)\), constant with respect to \(N_E\).
- (b) Finding the window with the maximum cumulative score has a complexity of \(O((3K_h - \tilde{K}_h + 1)(3K_w - \tilde{K}_w + 1)) = O(1)\), also constant with respect to \(N_E\).

These operations are repeated \( L \) times, where \( L \) is the number of levels in the tree. Following a similar analysis as in the previous section, the overall parsing complexity is \( O(\ln \sqrt{N_E}) \), logarithmic in the square root of the number of encoder tokens.

### Cross-Attention Complexity

The Sliding Window Parser selects a constant number of nodes, \(\hat{K}_h \hat{K}_w\), regardless of the size of the input. Therefore, the complexity of the cross-attention operation is \( O(N_D \hat{K}_h \hat{K}_w) = O(N_D) \).

## D.4 Experimental Setup

Unless otherwise specified, the following experimental setup is the same for all experiments.

**Dataset** We use the COCO 2017 object detection dataset [168] for our experiments. This dataset is divided into two subsets:

- Training Dataset: Contains 117k images, each with 1 to 63 objects of various sizes and from 80 different categories.

- Validation Dataset: Includes 5k images with similar characteristics to the training dataset.

**Transformations** We normalize the pixel values of the input images and the bounding box coordinates (to the range \([0, 1]^4\)), following [35]. During training, we augment the data using random resized cropping (`RandomResizedCrop`), which extracts a randomly sized patch from the original image (with an area between 0.7 and 1.0 times the original area) and resizes it to 512x512 pixels.

**Loss Function** We employ the same loss function as DETR [35], which combines a classification loss and a bounding box regression loss

**Optimization** We use the AdamW optimizer with the following parameters:

- \(\lambda = 10^{-4}\) (weight decay coefficient)

- Learning rates: \(10^{-5}\) for the Backbone, \(10^{-4}\) for the rest of the model

- \((\beta_1, \beta_2) = (0.9, 0.999)\)

- \(\epsilon = 10^{-8}\)

**Gradient Clipping** We apply gradient clipping with a maximum norm of 0.1 to prevent exploding gradients.

**Epochs and Learning Rate Schedule** For the Main Evaluation, models are trained for 300 epochs using a step-based learning rate scheduler (StepLR) with a step size of 250. All other experiments use the same learning rate scheduler but with a step size of 50 and are trained for 60 epochs.

**Hardware and Batch Size** The Main Evaluation is conducted on 2x A100 GPUs with 80GB of VRAM and a batch size of 68. All other experiments are conducted on 4x RTX 3090 GPUs with 24GB of VRAM and a batch size of 20.

**Evaluation Metrics** We evaluate the models using the following metrics:

- mAP: The mean average precision for IoU thresholds ranging from 0.50 to 0.95 in steps of 0.05, averaged over all classes and areas.

- mAP\(_{50}\), mAP\(_{75}\): Mean average precision for IoU thresholds of 0.50 and 0.75, respectively.

- mAP\(_S\), mAP\(_M\), mAP\(_L\): Mean average precision for small (< 32\(^2\) pixels), medium (32\(^2\) to 96\(^2\) pixels), and large (> 96\(^2\) pixels) objects, respectively.

**Reproducibility** To account for randomness in training, each experiment is repeated twice with different random seeds. Due to the computational cost of each run, we were limited to two repetitions.

**Backbone** Following DETR [35], we use a ResNet50 backbone pre-trained on ImageNet. We freeze its batch normalization layers and modify the last stage of the backbone by adding dilation and removing a stride from its first convolution to increase feature resolution. Finally, a 1x1 convolutional layer reduces the dimensionality of the ResNet50 output from 2048 to d_{model} = 256 to match that of the model's embedding dimension.
