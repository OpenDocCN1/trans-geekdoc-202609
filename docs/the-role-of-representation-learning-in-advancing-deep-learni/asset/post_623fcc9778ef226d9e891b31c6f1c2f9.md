## Hierarchical and Searchable Representations for Vision Transformers

### D.1 Details for Methods Section

### D.1.1 Problem Description

Object detection aims to locate and identify objects within an image. This involves determining both the position of each object and its corresponding class label. Formally, we can represent the object detection process as a function f that maps an input image I to a set Y of bounding boxes and their associated class labels:

```
f : \mathbb{R}^{H \times W \times C} \to \mathcal{Y}
I \mapsto Y := \left\{ (\mathbf{b}_i, c_i) \in [0, 1]^4 \times [n_C] : i \in [n_O] \right\}
```

where:

- $I \in \mathbb{R}^{H \times W \times C}$ is the input image tensor, with $H, W,$ and $C$ representing its height, width, and number of channels, respectively.
- $\mathcal{Y}$ is the output space, consisting of sets of detected objects (bounding boxes and class labels).
- $n_O$ is the number of detected objects in image $I$.
- $n_C$ is the number of object classes.
- $\mathbf{b}_i = (b_{ix}, b_{iy}, b_{ih}, b_{iw}) \in [0, 1]^4$ represents the normalized bounding box coordinates for the $i$-th object: the center $(b_{ix}, b_{iy})$, height $b_{ih}$, and width $b_{iw}$, following [35].
- $c_i \in \{1, ..., n_C\}$ is the class label for the $i$-th object.

### D.1.2 Architecture

The model consists of the following main components:

**Backbone.** The backbone processes the input image and generates embeddings that serve as leaf nodes of the tree. These embeddings can be thought of as latent vector representations of image patches. Following DETR [35], we use a ResNet50 backbone pre-trained on ImageNet.

**Tree Encoder.** The encoder takes the leaf node embeddings as input and constructs the remaining levels of the tree in a bottom-up fashion.

**Tree Decoder.** The decoder parses the tree, selecting a subset of nodes relevant to the given task. It takes both the tree and a set of learned decoder embeddings as input. These decoder embeddings are analogous to the object queries in DETR [35], each representing a potential object. The decoder refines these embeddings through cross-attention with the selected tree nodes.

**Output Head.** The output head uses the refined decoder embeddings to predict bounding box coordinates and class labels. Specifically, for each decoder embedding, the output head predicts a vector of dimension $n_C + 4$, where $n_C$ is the number of objects classes and 4 corresponds to the normalized bounding box coordinates.

### Encoder experiments

This tree encoder addresses the computational cost of global self-attention by restricting the receptive field to small, non-overlapping windows of the input (i.e. local window self-attention). Specifically, the one-stage encoder first groups the node embeddings at level $l$ into non-overlapping windows of shape $K_h \times K_w$, where $K_h$ and $K_w$ are the height and width of the window, respectively. For each window, the tree encoder begins by flattening the node embeddings into a sequence of $K_h \cdot K_w$ vectors. This flattened sequence is then passed through a transformer encoder. Finally, the output of the transformer encoder is averaged to produce a single vector, which represents the embedding of the parent node for that window. The resulting parent node embeddings form the set of nodes at level $l+1$. This process is repeated recursively to construct the tree. Stage I in Figure 6.2 illustrates the one-stage encoder architecture.

Unless otherwise specified, the following hyperparameter values are used for all encoder configurations:

- $K_h = 2, K_w = 2$ (window size)
- $d_{model} = 256$ (embedding dimension)
- $n_{heads} = 8$ (number of attention heads)
- Number of encoder layers: 6 (for the two-stage encoder, we use two encoder transformers with 3 layers each to maintain a comparable number of parameters)
- Number of decoder layers: 6
- $d_{mlp} = 2048$ (hidden dimension of the FFN in the transformer block)

N.B. With a window size of 2x2 and input images of size 512x512, the resulting tree has 5 levels (excluding the root)

The goal of these experiments is to evaluate the impact of the different components of the encoder on model performance. We compare an encoder using global attention, an encoder using only stage I and an encoder using both stage I and stage II with different $n_l$-hop neighborhoods for stage II. We test two configurations: $n_l = 2$ and $n_l = 1, \forall l \in \{0, ..., L-1\}$. In the variable n-hop setting, the number of neighboring nodes varies across levels. Specifically, we test the configuration $n_0 = 2$ and $n_l = 1$ for all $l > 0$. To isolate the effects of the encoder, we do not use a parser in these experiments (i.e. all nodes in the tree are used for cross-attention) and keep the number of total parameters the same for all configurations.

### Best Node Parser

Algorithm 4.2 describes the Best-Node Parser. The SimilarityScore function computes the attention scores (i.e. dot product) between the projected node embeddings and the query vector $\bar{\mathbf{q}}$. By focusing solely on the children of the best node at each level, the parser avoids computing attention scores for all nodes, ensuring efficiency. Including sibling nodes provides context, with higher-level nodes summarizing less important information and lower-level nodes capturing finer details.

### Sliding Window Parser

The selection process of the Sliding Window Parser is implemented using a 2D convolution with a kernel of ones, which slides a window across the attention scores to identify the region with the highest cumulative score. This sliding window mechanism gives the parser its name.

Algorithm 4.3 describes the Sliding Window Parser. AreaOfInterest corresponds to the process of expanding the search area to include the children of both the best-scoring node and its one-hop neighbors. The SelectNodes function then performs the sliding window selection.
