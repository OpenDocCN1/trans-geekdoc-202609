  if \(l = L - 1\) then
    \(N \leftarrow T_l\)
  else
    \(N \leftarrow \text{Children}(T_l, (i_{\max}, j_{\max})) \triangleright N \in \mathbb{R}^{K_h \times K_w \times d_{model}}\)
  end if

  \(K \leftarrow NW_K \triangleright \text{Project node embeddings}\)
  \(s \leftarrow \text{SimilarityScore}(\bar{\mathbf{q}}, K) \triangleright s \in \mathbb{R}^{K_h \times K_w}\)

end for

\(\mathcal{S} \leftarrow \mathcal{S} \cup \text{Children}(T_0, (i_{\max}, j_{\max}))\)

## Tree Depth

We analyze how the tree’s depth (i.e. number of levels) influences model performance. Specifically, we test three different tree depths: 5 levels, 3 levels and 1 level. The 5-level configuration corresponds to the default depth used in the previous experiments. The 1-level configuration is equivalent to a simplified model consisting of only a backbone and a standard transformer decoder (i.e. no tree encoder). For the 3-level and 5-level configurations, we use the best model configuration from the previous experiments (trained without using the “all nodes” loss component).

Table D.1.4 presents the evaluation metrics for the different configurations tested. Increasing the tree depth generally improves object detection performance. The model with 5 levels statistically significantly outperforms the others in most metrics (except mAPS). This may be because higher-level nodes capture longer-range dependencies due to their larger receptive fields. This is supported by the fact that, among the size-based metrics (mAPS, mAPM and mAPL), the largest performance difference occurs in mAPL.

However, the Backbone-Decoder baseline (L = 1) outperforms the model with 3 levels. This suggests that shallow tree representations may not fully exploit the benefits of our proposed architecture, and can even reduce performance.

## D.2 Details on Encoder Computational Complexity

Let \(\mathcal{T} = \{T_l\}_{l=0}^{L-1}\) be the tree representation of an input image \(I\), where \(T_l \in \mathbb{R}^{H_l \times W_l \times d_{\text{model}}}\) corresponds to the node embeddings at level \(l\). Given the way the tree is constructed, we have that \(H_l = H_0 / K_h^l\) and \(W_l = W_0 / K_w^l, \forall l \in \{0, ..., L-1\}\). Additionally, \(L = \min \left\{ \log_{K_h}(H_0), \log_{K_w}(W_0) \right\}\). Finally, let \(N_E = H_0 W_0\) be sequence length of the input (encoder) tokens.

### D.2.1 One-Stage Tree Encoder

First, let's determine the complexity of constructing a single tree level \(T_{l+1}\), from the previous level \(T_l\). This involves the following operations:

- 1. Non-overlapping window partitioning: This operation has a complexity of \(O(1)\), as it only rearranges the data without performing any computation.
- 2. Flattening: Similar to window partitioning, this is a reshaping operation with a complexity of \(O(1)\).
- 3. Window-based transformer encoding: This involves processing each window with a transformer encoder, including window-based attention, feedforward network (FFN), and layer normalization. The complexity depends on:
  - The number of windows: \(\frac{H_l W_l}{K_h K_w}\)
  - The per-window complexity:
    - FFNs and layer normalization scale linearly with the number of tokens in a window: \(O(K_h K_w)\).
    - Window-based attention scales quadratically with the window size: \(O((K_h K_w)^2)\).
  - Assuming a constant window size \((K_h, K_w)\), the overall complexity of this step is: \(O\left(\frac{H_l W_l}{K_h K_w} (K_h K_w)^2\right) = O(H_l W_l)\).

Therefore, the complexity of constructing a single tree level \( T_{l+1} \) is \( O(H_l W_l) \), linear in the number of nodes from the previous level.

Now, let's determine the complexity of constructing the entire tree. Without loss of generality, we only consider operations associated with the attention mechanism. This is not a problem, since the complexity of the attention mechanism dominates that of the other operations. This attention operation is repeated \( L - 1 \) times, where \( L \) is the number of tree levels. The total number of operations is then proportional to:

\sum_{l=0}^{L-2} (K_h K_w)^2 \frac{H_l W_l}{K_h K_w} = K_h K_w \sum_{l=0}^{L-2} \frac{H_0 W_0}{K_h^l K_w^l}
= H_0 W_0 K_h K_w \sum_{l=0}^{L-2} \left( \frac{1}{K_h K_w} \right)^l
= H_0 W_0 K_h K_w \frac{1 - \left( \frac{1}{K_h K_w} \right)^{L-1}}{1 - \frac{1}{K_h K_w}}
= H_0 W_0 (K_h K_w)^2 \frac{1 - \left( \frac{1}{K_h K_w} \right)^{L-1}}{K_h K_w - 1}
\le H_0 W_0 \frac{(K_h K_w)^2}{K_h K_w - 1}

The last inequality comes from the fact that \( K_h K_w > 1 \) and \( L \ge 1 \).

We conclude that the complexity of constructing the entire tree is \( O \left( H_0 W_0 \frac{(K_h K_w)^2}{K_h K_w - 1} \right) = O(H_0 W_0) = O(N_E) \), linear in the number of input (encoder) tokens.

### D.2.2 Two-Stage Tree Encoder

First let's determine the complexity of constructing a single tree level \( T_{l+1} \) from the previous level \( T_l \). This involves the following operations:

- 1. First stage operations: These operations are identical to those in the one-stage encoder, which, as shown in Section D.2.1, have a complexity of \( O \left( \frac{H_l W_l}{K_h K_w} (K_h K_w)^2 \right) = O(H_l W_l) \).
