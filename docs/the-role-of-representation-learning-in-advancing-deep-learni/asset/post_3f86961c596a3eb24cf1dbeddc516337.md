**Residual Swin Transformer Block.** The deep feature extraction module comprises several consecutive Residual Swin Transformer Blocks, each ending with a Convolutional Layer. ### Multi-Head Self Attention

Multi-Head Self-Attention is performed as in the original transformer [270]. However, instead of static sinusoidal positional encoding, we add a learnable relative position bias to the attention score. Recent studies have shown that relative positional embeddings are more effective in capturing spatial relationships [240, 213]. In each window dimension \(w\), the relative position of two tokens is limited to the range \([-(w-1), (w-1)]\). We first calculate the relative position of each token to all other tokens in the same window, compute indices for every occurring relative distance, and sample a learnable position bias of shape \(B \in \mathbb{R}^{h \times w_1 \times w_2 \times \dots}\) from \(\tilde{B} \in \mathbb{R}^{h \times (2w_1-1) \times (2w_2-1) \times \dots}\). The bias is added before the SoftMax calculation. The overall process is detailed in eq. (C.2), where \(d = \lfloor \frac{c}{h} \rfloor\) is the embedding dimension \(e\) divided by the number of attention heads \(h\). \(P_Q\), \(P_K\) and \(P_V\) are the learnable projection matrices, and \(X \in \mathbb{R}^{w_1 \times w_2 \times \dots \times e}\) represents an input window, with \(M\) being the attention mask.

```
Q = X P_Q,      K = X P_K,      V = X P_V
Attention(Q,K,V) = Softmax(Q K^T / \sqrt{d} + B + M) V
```

### Generalizing shifting windows beyond 2D

The Swin Transformer architecture [172] we use as a basis for FunctaFormer is a derivation of the original Vision Transformer [67], primarily designed for 2D images. To extend its functionality to arbitrary data, beyond the convolutional layers, we need to modify certain architectural elements. Notably, we must adapt the shifting window and the relative position bias computation to operate on arbitrary dimensions.

In the shifting window attention mask calculation, shown in listing C.1, we begin by assigning a zero mask with the same size as the data. On lines 13 and 14, we assign unique integer values to the last window-halves in each dimension. Then, on lines 29 to 31, we partition the mask into a collection of windows. Finally, in line 32, each element is compared to all other elements in the same window by subtraction. Elements with the same unique integer result in zero, while all others result in non-zero values. At the end, we assign a large negative attention score to all non-zero elements, ensuring they receive no attention.

```
def get_mask(
    dim_data: list[int],
    dim_window: list[int],
) -> torch.Tensor:

    d = dim_data
    w = dim_window
    n = len(d)
    k = 1
    mask = torch.zeros(*d)
    for i in range(n):
        mask = torch.transpose(mask, 0, i)
        mask[d[i] - w[i] : d[i]] += k
        mask[d[i] // w[i] // 2 : d[i]] += k
        mask = torch.transpose(mask, 0, i)
        k *= 3

    part = [
        j
        for i in range(n)
        for j in (d[i] // w[i], w[i])
    ]
    perm = (
        list(range(0, 2 * n, 2))
        + list(range(1, 2 * n, 2))
    )
    wins = torch.prod(torch.tensor(w)).item()

    mask = torch.reshape(mask, part)
    mask = torch.permute(mask, perm)
    mask = torch.reshape(mask, (-1, wins))
    mask = mask.unsqueeze(1) - mask.unsqueeze(2)
    mask[mask != 0] = -100.

    return mask
```

To calculate the Relative-Position-Bias, shown in listing C.2, we first compute the Cartesian product of all possible input coordinates within an n-dimensional window.

```
def get_bias(
    dim_window: list[int],
    num_heads: int,
) -> torch.nn.Parameter:

    w = dim_window
    n = len(w)
    s = 1

    for i in range(n):
        s *= (2 * w[i] - 1)
    bias_table = torch.zeros((s, num_heads))
    coords = torch.cartesian_prod(
        *[torch.arange(d) for d in w]
    )
    if n < 2:
        coords = torch.unsqueeze(coords, -1)
        coords_rel = (
            coords.unsqueeze(1) - coords.unsqueeze(0)
        )
        coords_rel = torch.permute(coords_rel, (2, 0, 1))
        for i in range(n):
            coords_rel[i] += w[i] - 1
            scale_factor = 1
            for j in range(i + 1, n):
                scale_factor *= (2 * w[j] - 1)
            coords_rel[i] *= scale_factor
        coords_rel = torch.sum(coords_rel, 0)
        bias_table = bias_table[coords_rel]
        bias_table = torch.permute(bias_table, (2, 0, 1))
        return torch.nn.Parameter(bias_table)
```

### C.2.1 Network Initialization.

**Functa** We follow the initialization scheme established in [245]. We uniformly initialize the SIREN layer weights with $\mathcal{U} \left[ -\frac{1}{\omega_0} \sqrt{\frac{6}{n_{in}}}, \frac{1}{\omega_0} \sqrt{\frac{6}{n_{in}}} \right]$. The bias vectors are initialized to zero. The only exception is the first layer, since it is not yet scaled by $\omega_0$. Thus, we initialize the weights with $\mathcal{U} \left[ -\frac{1}{n_{in}}, \frac{1}{n_{in}} \right]$. The encoder $\psi$ is initialized with PyTorch's default initialization scheme, which is also uniform with $\mathcal{U} \left[ -\sqrt{\frac{1}{n_{in}}}, \sqrt{\frac{1}{n_{in}}} \right]$ for both weights and biases. Where $n_{in}$ is the dimension of the input tensor, e.g. number of input neurons.

**Backbone** Our adaptation of the SwinTransformer [172] uses the same initialization scheme as in the original implementation. The projection matrices $P_Q, P_K$ and $P_V$ as well as all feed-forward linear layer weights are initialized with values drawn of a truncated normal distribution parameterized as in eq. (C.3), where $a$ and $b$ are the lower- and upper-bound of the distribution and $\varphi$ is the probability density function of a standard normal distribution, with $\Phi$ being its cumulative distribution function. We set $\mu = 0, \sigma = 0.02, a = -2$ and $b = 2$ for all experiments. Biases are set to zero. Convolutional layers of all dimensionalities are initialized with PyTorch's default initialization scheme, which is uniformly drawn of $\mathcal{U}[-\sqrt{k}, \sqrt{k}]$, where $k = (c_{in} \cdot \prod_i d_{kernel}^{(i)})^{-1}$, $c_{in}$ are the input channels and $d_{kernel}^{(i)}$ is the i'th dimension of the kernel.

```
\( f(x \mid \mu, \sigma, a, b) = \frac{1}{\sigma} \cdot \frac{\varphi(\frac{x-\mu}{\sigma})}{\Phi(\frac{b-\mu}{\sigma}) - \Phi(\frac{a-\mu}{\sigma})} \)
```

## C.3 Data

**Images.** For the image modality, we select the well-known DF2K dataset, which combines the DIV2K [6] and FlickR2K [165] datasets. DIV2K consists of 800 high-resolution training images, 100 validation images, and 100 test images. FlickR2K contains over 2560 training images. For our training set, we use the 800 training images from DIV2K along with the 2560 training images from FlickR2K. For ablation studies, we utilize the 100 validation images from DIV2K, splitting them into two halves: the first half for validation and the second half for testing, as the 100 DIV2K test images are not available for download. For comparison against current state-of-the-art methods on super-resolution tasks, we utilized the SET5 [19], SET14 [299], Urban100 [126], Manga109 [186], and BSD100 [184] image sets. These datasets are standard benchmarks in single-image super-resolution. Instead of resizing the entire dataset, we take random crops of size $120 \times 120 \times 3$ during training and validation. In terms of data augmentation, we apply random horizontal flip to the images with a probability of $p = 0.5$. To ensure a fair comparison with previous works, such as those by [65, 163, 124], we padded the test images to a size divisible by the SIREN slicing dimensions and FunctaFormer window sizes. Before evaluation, the images are cropped back to their original sizes, and we do not exclude the border pixels in our evaluation.
