
## Hierarchical and Searchable Representations for Vision Transformers

### Abstract

Transformer-based models have achieved remarkable success in various domains, but their high computational cost restricts their application to large-scale inputs. To address this, we propose a novel tree-based encoder-decoder architecture that reduces self-attention complexity in the encoder to $O(N_E)$ and cross-attention complexity in the decoder to $O(N_D + \ln \sqrt{N_E})$, where $N_E$ is number of input encoder tokens, and $N_D$ is the number of decoder tokens. Our model first constructs a hierarchical tree representation of the input. Subsequently, a decoder parses this tree, selecting relevant nodes for cross-attention. By focusing on a subset of nodes, the decoder avoids attending to the entire tree, reducing the computational cost of cross-attention. We demonstrate the effectiveness of our approach through experiments on the COCO object detection benchmark.

## 6.1 Introduction

Figure 6.1: Overview of the proposed architecture for object detection. The backbone generates leaf node embeddings from the input image. The tree encoder embeds these embeddings into a tree. The tree decoder parses the tree and selects relevant nodes for cross-attention for the decoder tokens. Finally, the output head predicts bounding boxes and class labels.

The self-attention and cross-attention components are part of the widely used transformer architecture enable the network to capture contextual information from its input. Although this architecture is extremely powerful, its complexity is quadratic for self-attention and linear for cross-attention. These scaling properties not only restrict the maximum processable sequence length but also indirectly limit model size, as computational resources must be allocated between processing longer sequences or employing larger, more complex models. This trade-off seems rather unintuitive, since information retrieval and logical processing get mixed. Architectures such as Perceiver IO [134] and DETR [35] avoid this problem by separating these two processes to the encoder and the decoder, respectively. In this chapter, we build on top of DETR by introducing a novel tree-based encoder-decoder architecture designed to address the scalability limitations in information retrieval for transformers. Inspired by recent work on tree cross-attention [90], our model first employs an encoder to construct a hierarchical tree representation of the input. Our encoder avoids global self-attention, achieving a reduced complexity of $O(N_E)$. Subsequently, a decoder parses this tree, selecting nodes relevant to the task at hand. These selected nodes are then used in cross-attention to generate predictions. By focusing on a subset of nodes, the decoder’s cross-attention achieves a complexity of $O(N_D + \ln \sqrt{N_E})$, where $N_D$ is the number of decoder tokens and $N_E$ is the number of encoder tokens.

## 6.2 Related Work

The transformer architecture, originally introduced by [271], and its adaptations have become a fundamental architecture in deep learning [305, 66, 35, 64, 27, 264]. The attention mechanism allows the model to perform weighted aggregation of some inputs. However, this comes at a high computational cost, with quadratic computational complexity in the number of tokens for self-attention and linear computational complexity for cross-attention.

For this reason, hierarchical formulations of the transformer architecture have been proposed, based on the idea of efficient local processing of information at different levels of abstraction. Most of this work has been focused on encoder-only or decoder-only architectures, both for NLP [200, 123, 18] and vision [171, 113, 113]. In the setting of encoder-decoder architectures, [90] proposed a method to reduce the complexity of cross attention. In their formulation, [90] uses a full self-attention encoder to build a tree, where the decoder is then able to parse the tree, reducing the complexity of cross-attention from $O(N_D \cdot N_E)$ to $O(N_D \ln N_E)$, with the number of decoder tokens $N_D$ and the number of encoder tokens $N_E$. Our work builds on top of this by also reducing the complexity of the encoder and enabling an interpretable version of the tree parsing.

## 6.3 Methodology

This chapter proposes a tree-based architecture for object detection to address the limitations of standard transformers in handling large inputs. The model constructs a hierarchical tree representation of the input image. A decoder then traverses this tree, selecting the nodes used to generate the predictions. We conducted all experiments in the setting of object detection, using the COCO 2017 object detection dataset [168]. Object detection is suitable for evaluating the performance of our proposed architecture, because it requires the model to locate information in different parts of the input and at different scales. We also build on top of the encoder-decoder architecture proposed by DETR [35]. In the following, we will expand on the parts of the architecture summarized in Figure 6.1.

### 6.3.1 Tree Encoder

The encoder is responsible for constructing a hierarchical tree representation of the input image. It takes as input the leaf node embeddings generated by the backbone. Starting from these leaf nodes, the encoder builds the remaining levels of the tree in a bottom-up fashion, aggregating the information into more abstract tokens at the higher levels. We divide the process into two stages, see fig. 6.2 for an overview of the process. In stage I, the nodes at each level are generated based on the nodes from the previous level. This is achieved by grouping the nodes into non-overlapping windows and aggregating them into a single parent node. We then repeat this process until we have built the whole tree, sharing the weights for the aggregation function. In stage II, the embeddings of the nodes in the tree can be refined based on the n-hop neighborhood of each node.

**Figure 6.2:** On the left an illustration of the tree built by the encoder. A new level in the tree is being constructed in stage I by aggregating the information from non-overlapping windows. This process is repeated recursively until the top level is reached. In stage II, the embeddings in the tree get refined based on their local neighborhood.

### 6.3.2 Tree Decoder

The decoder performs cross-attention on the tree provided by the encoder in order to generate final prediction for the class and bounding boxes of objects using the output head. Part of the decoder is a parser, which, given the tree and the current decoder tokens, selects the relevant tokens from the tree in an efficient manner. We provide an overview of this process in Figure 6.3.

![](img/c742333bcb21933724ca00794dbfb657_97_0.png)

Figure 6.3: This figure illustrates the tree decoding process for object detection. For each layer, the decoder: (1) generates query vectors from the decoder embeddings; (2) selects relevant nodes from the tree using a parser guided by these queries and key vectors derived from the tree nodes (using the cross-attention weights $W_Q$ and $W_K$); and (3) processes the selected nodes and decoder embeddings through a standard transformer decoder layer (composed of Multi-Head Self-Attention, Layer Normalization, Multi-Head Cross-Attention, and a FFN).

### Parsers

The parser is the core component for selecting the relevant information from the tree. There are different ways for selecting a subset of the nodes, which we will describe below. For details on the parsers as well as the complete algorithms, please refer to section D.1.2.

### Best-Node Parser

The best-node parser employs a top-down approach to select nodes. Starting at the highest level of the tree, the parser computes attention scores between each node and a query vector (derived from its decoder embeddings). The node with the highest score is selected, and its siblings are added to the list of selected nodes. For the next levels, the parser focuses on the children of the selected node and repeats this process until the leaf node level is reached. By selecting nodes from all levels, the parser can select high-level information for some areas while focusing on low-level details for other areas.
