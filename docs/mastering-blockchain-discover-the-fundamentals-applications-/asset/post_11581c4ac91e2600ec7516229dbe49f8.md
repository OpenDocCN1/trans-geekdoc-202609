- a) **Hybrid Blockchains:** Hybrid blockchains combine elements of public and private blockchains to strike a balance between openness and control. Federated blockchains strike a balance between decentralization and control, making them suitable for industries that require collaboration and shared governance, such as banking consortia, intercompany networks, and industry-specific blockchain networks.

### BLOCKCHAIN DATA STORAGE

Blockchain employs a distributed and decentralized approach to store data across a network of computers. Instead of relying on a central authority, blockchain utilizes a peer-to-peer network to maintain a shared ledger. The key data structures used in blockchain data storage are as follows:

- a) **Blocks:** A block is a fundamental unit of data in a blockchain. It serves as a container that stores a collection of transactions and other relevant information. Each block is uniquely identified by a cryptographic hash, which is computed based on the contents of the block. This hash serves as a digital fingerprint of the block, ensuring the integrity of the data within it.

- b) **Transactions:** Transactions represent the transfer or exchange of data, assets, or digital tokens between participants. Each transaction includes essential information, such as sender and receiver addresses, transaction amounts, timestamps, and digital signatures for authentication. Transactions are grouped in a block and processed collectively by the network.

### BLOCKS AND TRANSACTIONS IN DETAIL

a) **Block Structure:** A block consists of several components:

- **Block Header:** The block header contains metadata about the block. It includes information such as the block's unique identifier (hash), timestamp, and a reference to the previous block's hash. The block header also includes a nonce, which is a value used in the Proof of Work consensus mechanism to find a valid hash that satisfies the network's predefined criteria.
- **Transactions:** The block contains a set of transactions that have been validated and added to the blockchain. These transactions record various activities, such as asset transfers, contract interactions, or data storage. Each transaction has its unique identifier and is linked to the previous transactions within the block.
- **Merkle Tree Root:** The Merkle tree root is a hash value that represents the transactions within the block. It is computed by organizing the transactions into a binary tree structure known as a Merkle tree. This Merkle tree allows for efficient verification of the integrity of transactions within the block. Any change to a transaction would result in a different Merkle tree root, indicating tampering.

### b) Transaction Structure:

A transaction typically includes the following elements:

- **Input**: The input specifies the source of funds for the transaction. It includes details such as the sender's address, the amount being transferred, and references to previous transactions that provide the necessary funds.
- **Output**: The output defines the recipient's address and the amount being received. Transactions can have multiple outputs, allowing for multiple recipients or change outputs. Each output includes a locking script that specifies the conditions under which the funds can be accessed in future transactions.
- **Digital Signature**: A digital signature is generated using the sender's private key and serves as proof of authenticity and authorization for the transaction. The signature is verified using the sender's public key, ensuring that only the rightful owner of the private key can create valid transactions.

### IMMUTABLE LEDGER AND DATA INTEGRITY

One of the key attributes of blockchain is its immutability and data integrity. Once a block is added to the blockchain, it becomes nearly impossible to alter or delete the data within it. This is achieved through the following mechanisms:

- a) **Cryptographic Hashing:** Each block in the blockchain is linked to the previous block through a cryptographic hash. This hash is computed using the data of the previous block, creating a chain of blocks that is resistant to tampering. Any change to the data within a block would result in a different hash, breaking the chain and alerting the network to the tampering attempt.
- b) **Consensus Mechanism:** Blockchain relies on a consensus mechanism, such as Proof of Work (PoW) or Proof of Stake (PoS), to validate and agree upon the order of transactions and the state of the blockchain. These consensus mechanisms ensure that all participants in the network reach a shared agreement and prevent malicious actors from modifying the blockchain. PoW requires miners to perform computationally intensive tasks to validate transactions and add blocks to the blockchain, while PoS allows participants to validate transactions based on the stake they hold in the network.
