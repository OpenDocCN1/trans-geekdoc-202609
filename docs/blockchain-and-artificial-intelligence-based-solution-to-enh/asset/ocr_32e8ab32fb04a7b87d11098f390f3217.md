# F) Data Licensing and Consumption Algorithm

**Algorithm 2**: Data Licensing and Consumption

+   1 Individual agent generates DIDs with the *Distributor* agent to establish a DIDComm connection channel.
2 Individual sets up the license schema on distributor app.
3 Distributor agent generates license credential ($cred_{receipt}$), and sends $cred_{receipt}$ to Individual agent.
4 while *Consumer selects the data with intention do*

+   5 Consumer agent generates DIDs with the *Distributor* agent to establish a DIDComm connection channel.
6 Consumer sends request for license credential ($cred_{license}$) to Distributor agent with the payment address.
7 if *Distributor receives the payment then*
8 Distributor adds the payment address to credential definition, issues $cred_{license}$ to Consumer agent.
9 Individual agent generates DIDs with the *Consumer* agent to establish a DIDComm connection by scanning QR code on distributor app.
10 Individual agent generates license proof request ($req_{license}$) and sends to Consumer agent.
11 Consumer agent presents proof ($proof_{license}$) to Individual agent.
12 Individual agent verifies the $proof_{license}$ by checking the signature and DID of the Distributor.
13 if $proof_{license}$ has been verified then
14 Individual sends a request message for proof request of pre-signed URL ($req_{storage}$) to Consumer agent.
15 Consumer sends $req_{storage}$, which uses URL from $cred_{storage}$, and $pka_{es}$ from $cred_{data}$.
16 if pre-signed URL is expired then
17 Client agent sends a message to *Data Manager* agent for an updated pre-signed URL credential ($cred_{storage}$).
18 *Data Manager* agent issues client $cred_{storage}$.
19 end
20 Individual agent presents the storage proof ($proof_{storage}$) to Consumer.
21 Consumer using pre-signed URL and $pka_{es}$ access health data. Distributor transfers the payment to the *Individual*
22 end
