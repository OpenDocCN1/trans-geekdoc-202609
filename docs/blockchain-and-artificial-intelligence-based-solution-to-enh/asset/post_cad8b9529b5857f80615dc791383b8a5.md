# I) Data Sharing and Storage Algorithm

The following algorithm shows the process of data sharing and storage.

1. Create a Meta mask wallet to interact with the Ethereum Blockchain.
2. Download Browser extension & pin to browser for easy access.
3. Remember (and keep secret) private key phrase.
4. Go to Ocean protocol Market Wallet.
5. Connect to the page mask wallet.
6. Go to the publish page option.
7. Fill in the Publish Form.
8. After clicking the publishing, approve transactions in Wallet (Here you can see Meta mask wallet).
9. Deploy a new data token contract.
10. Interact with the Contract.
11. Find the publishing dataset option.
12. Create Pricing (Fixed or Dynamic).
13. If Fixed Pricing.

Go to the published Asset.

If Pricing is not set:
    Click pricing Button (set value of data token with respect to ocean token)
else:
    Fixed Pricing already set
else:
    Let the market discover the right price for data derived from DeFi with liquidity pools. It is implemented using Balancer, an AMM protocol as Liquidity pool holding Ocean tokens & data tokens. Data token has been successfully published on Ocean Market.

# J) Compute-to-Data Algorithm

The following algorithm explains the steps involved in compute to data.

1. **Set up** computing architecture (Aquarius, Operator service & operator Engine)
2. **Publish** data asset on Ocean & receive DID for published data asset.
3. **Receive** compute access request to ocean and receive DID the algorithm to be used to compute on providers’ data by the consumer.
4. **Sell** access to train AI model on data via compute service to consumers.
5. **Notify** consumer to publish the algorithm on Ocean and receive DID (algo DID) for algorithm.
6. **Notify** consumer to sign the SLA and pay for the compute service via escrow smart account which will be used as payment for compute service.
7. **Receive** compute service request from consumer and operator service starts compute.
8. **Find** datasets and algorithms in Aquarius (data DID and algorithm DID) (fixed identifier not dynamic)
9. **Start** compute task After validations of inputs (request is valid and signed SLA).
10. **Instantiate** a Kubernetes cluster process within the given parameters of data and algorithm.
11. **Respond** to data consumers if they require about status of compute job.
12. **Restart** compute execution if customer isn’t satisfied, with the same or a different algorithm, until the compute access expires.
13. **Inform** the data consumer after completion of compute job.
14. **Share** the URL of storage of execution logs and outputs generated.
