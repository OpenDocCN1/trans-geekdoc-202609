## Blockchain and Artificial Intelligence-Based Solution

### E) Data Sharing and Storage

#### Algorithm 1: Data Sharing and Storage

1. Individual agent exchanges DIDs with Data Issuer to establish DIDComm connection.
2. Data Issuer uses the public key of CKKS scheme ($pk_{fe}$) to perform homomorphic encryption on the data. Then, Data Issuer uses the public key of AES scheme ($pk_{aes}$) to encrypt the data.
3. Data Issuer issues the data credential ($cred_{data}$) to Individual agent, with ($pk_{aes}$) as attribute of credential.
4. Individual agent accepts and stores the health credential in mobile wallet.
5. Individual agent exchanges DIDs with Data Manager to establish DIDComm connection through generated invitation QR code on Data Manager app.
6. Individual agent sends schema for proof request to Data agent through message.
7. Data Manager agent generates proof request ($req_{data}$) according to the schema sent by Individual agent, and sends $req_{data}$.
8. Individual agent presents health data proof $proof_{data}$ based on $cred_{data}$.
9. Data Manager agent verifies the $proof_{data}$ by checking signature and DID of Data Issuer.
10. If $proof_{data}$ has been verified, Data Manager agent issues initial storage credential ($cred_{storage}$) to Client agent, with pre-signed URL and $pk_{aes}$ as attributes of $cred_{storage}$.

## Blockchain, AI, and Data Protection in Healthcare

### F) Data Licensing and Consumption

#### Algorithm 2: Data Licensing and Consumption

1. Individual agent generates DIDs with Distributor agent to establish DIDComm connection.
2. Individual sets up license schema on distributor app.
3. Distributor agent generates license credential ($cred_{receipt}$), and sends $cred_{receipt}$ to Individual agent.
4. Consumer selects the data with intention.
5. Consumer agent generates DIDs with Distributor agent to establish DIDComm connection.
6. Consumer sends request for license credential ($cred_{license}$) to Distributor agent with payment address.
7. If Distributor receives the payment, Distributor adds payment address to credential definition, issues $cred_{license}$ to Consumer agent.
8. Individual agent generates DIDs with Consumer agent to establish DIDComm connection by scanning QR code on distributor app.
9. Individual agent generates license request ($req_{license}$) and sends to Consumer agent.
10. Consumer agent presents proof ($proof_{license}$) to Individual agent.
11. Individual agent verifies the $proof_{license}$ by checking signature and DID of Distributor.
12. If $proof_{license}$ has been verified, Individual sends a request message for proof request of pre-signed URL ($req_{storage}$) to Consumer agent.
13. Consumer sends $req_{storage}$, which uses URL from $cred_{storage}$, and $pk_{aes}$ from $cred_{data}$.
14. If pre-signed URL is expired, Client agent sends a message to Data Manager agent for updated pre-signed URL credential ($cred_{storage}$).
15. Data Manager agent issues client $cred_{storage}$.
16. Individual agent presents the storage proof ($proof_{storage}$) to Consumer.
17. Consumer using pre-signed URL and $pk_{aes}$ access health data.
18. Distributor transfers the payment to Individual.
