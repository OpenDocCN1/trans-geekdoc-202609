The first type to appear on the market built on the near-field communication capabilities (NFC) added to smartphone platforms around 2010. Because NFC uses the same radio protocols as smart card readers, they were a natural fit for access control applications. They could be added to existing smart-card-enabled systems in a familiar technical implementation. Users also readily understood how to use them, because the short activation range (about an inch) mimicked the familiar gestures used to present a contactless smart card to a reader. Alas, this was a win only for Android users, as Apple still not provided API access the NFC capabilities on iPhones. As such, this solution does not cover a significant part of the market, especially in the United States

Bluetooth, the second flavor of mobile credit on the market today, is displacing NFC due to its universality across smartphone manufacturers, many other wearables (such as smart watches). Similar to NFC, a Bluetooth mobile device transmits a digital credential to a typically wall-mounted reader, and the access control system behind the scenes makes authentication and authorization decisions about letting the user through the door. Bluetooth differs in how you measure the range of communication in hundreds of feet rather than a few inches. This larger range presents pros and cons for how the technology can be used. On the plus side, the greater range means users don’t necessarily need to hold the phone to a reader. They can just keep it in their pocket, as you would with the newer keyless systems on cars. On the other hand, this greater range presents challenges when doors are close to each other, as it is difficult for the system to understand which one you want to open. Either way, Bluetooth has taken mobile security credentials a big step forward and it’s now probably be the predominant type of solution.

Finally, there are API-based mobile credential solutions. In this model, the smartphone talks directly to a cloud-based access control system and the cloud system in turn unlocks the door. This method exploits the existing capabilities of cloud-based systems to remotely unlock doors via persistent connections to the control panels that manage them, a capability for at least a decade for browser-based systems, and it’s now being connected to mobile platforms. One of the key benefits of this architecture is that it eliminates any need for local wall-mounted readers. It is also an ideal candidate for retrofitting existing installations, as it requires no new hardware and can be performed remotely via app and credential distribution to existing users.
