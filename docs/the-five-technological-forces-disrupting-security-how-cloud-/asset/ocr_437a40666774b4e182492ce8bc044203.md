# REAL TIME ANALYTICS

The relevance of real-time analytics to security is, I hope, self-evident by now. In physical security, it's fair to say that anything we want to know, we would want know sooner. In general, the promise of real-time analytics is to improve the speed and accuracy of business processes. Being able to analyze data quickly is part of fulfilling the promise of IoT. After all, what good are all our sensor data if you cannot take action on?

The term "real time" is often used, but it means different things to different people. In the context of computer engineering, it means an algorithmic process that is guaranteed to return a result within a specified amount of time. In the context of networking, it could mean "wire speed," or being able to keep up with the rate at which data packets are arriving, say, a firewall. For robots, the requirement would be fast enough to keep up with the laws of physics so that the robot doesn't get into an undefined state. In general, it means using data as soon as it arrives in a system, as opposed to being retrospective for reporting or some other forensic purpose.

For security, we will understand real time to mean the interval between events of concern are still taking place. That's a more generous definition than that of the others but puts an emphasis on having analytic results in time to respond with some type of preventive or corrective action. Most of the principal components in security systems deliver their raw data in real time: intrusion, fire, access, and video are all immediate. What's not immediate are analytics about emerging patterns or changes to existing patterns. Many of the real-time decisions we need in security are how to deploy resources or where to focus attention. Real-time analytics could indicate the need for additional manpower in one place or another, for example, it could prevent harm or property damage.
