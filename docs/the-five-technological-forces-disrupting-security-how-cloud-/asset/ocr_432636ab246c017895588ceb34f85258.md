Both adminative and occupant apps have emerged on both cloud- and premise-based systems. However, cloud-based solutions have increasingly gained distance on non-cloud approaches because they leverage more of the power of the cloud itself. These apps import features that other cloud services can provide as part of the API ecosystem. New mapping? It’s right there through the social networks. Need social data? It’s right through Google Maps. Need emergency response information? It’s there from multiple RSS feeds. The cloud-based identity federation and single sign-on (SSO) links that support a seamless user experience across all these services will forever elude the aging premise-constrained, single-tenant application model.

Earlier, I mentioned the relative efficiency of providing a single cloud-based mobile service for the entire universe of users (as opposed to establishing a premise-based mobile service for every client or installation). This clearly favors cloud-based mobile solutions, which can release both mobile and service updates synchronously. A client population with mixed versions of mobile apps and server software cannot be kept uniformly updated and will never get all the advantages of new feature releases.
