# CHAPTER 9: All Security Is Now Cybersecurity

The fly in the ointment for IoT is that the sheer number of devices in need of software updates will become unmanageable—at least with current software updates. Many of us would say that we're already at that point. The reality- is that it's difficult to make it through an entire week, if not a day, without an update request from one or more phones, laptops, tablets, televisions, watches, microwaves, refrigerators, thermostats, or other household gadgets. To say nothing of the mobile apps that control them, all of which seem to be nearly monthly release cycles that we use on the IoT treadmill.

That's without us ever leaving our home. Once we're in a professional work setting—from the factory floor to a high-rise office building—we're surrounded by an even larger number of firmware-laden objects that demand a decision on whether we should update them or not. Anyone who has lived through automatic updates knows that there are frequently undesirable effects.

A frequent response to being on this treadmill is to ignore updates altogether. And why not? If the thing you bought did you wanted it on the day you bought it, can't you leave it that way? In the preconnected era, the answer to might have been yes. But that's no longer true: a vast number of software patches fix serious security holes. A security flaw in a single IoT device could be the crack through which hackers enter your home or business network. From there, they can compromise other devices.

The only conclusion is that everything needs to be automatic (or at least coordinated) update schedules. The problem is simply thousands of IoT devices becoming ubiquitous and invisible, security integrators may not know where or how they are in any network setting. Fortunately, there are products and standards emerging within some domains that aim to make these updates efficient at the device level and manageable at the manufacturing or enterprise level.

For any given security organization or integrator, however, it will be a long time before they see adoption or uniformity across the suite of products that may be using for common security isolation. Aside the logistics of managing software updates, security providers also have a well-established need to check new firmware releases for behavioral changes and security flaws before they are deployed. This is already common practice for every device installed in critical networks in financial institutions and other high-risk/high-value computing environments. It should also be common practice in any industrial setting where compromise of industrial controls could pose harm to human life or large economic losses.
