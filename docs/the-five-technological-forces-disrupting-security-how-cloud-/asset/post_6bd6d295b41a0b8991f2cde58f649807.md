The initial outcomes of unsupervised learning may be useful or not, in the sense that the groupings may provide any practical knowledge that allows you to manage risk. For example, if an unsupervised algorithm was applied to access control records for a large building, it might find two major groupings: people who go in and 10 times a day (smokers) and people who go in and twice a day (nonsmokers). These observations are interesting, if not obvious, but highly relevant to security management. On the other hand, we might find other classifications that provide entirely new insights about groups of people, locations, or times of day under closer scrutiny. That's what's fun about unsupervised learning: it feels like the computer is a genius and can just figure out.

Supervised learning describes methods of data analysis where the investigator is pursuing a particular hypothesis and wants to know whether different groupings of data are useful for predicting the outcome or target value of an interest. Supervised learning works by training an algorithm on set of data that we have explained the relationships to be normative or predictive for future sets. Neural networks are often programmed this way, for example, make associations between inputs and outputs, specifying an exact mathematical or functional relationship between them. The algorithm compares attributes to known outcomes or behaviors and draws inferences about which attributes are relevant predictors of those outcomes or target values. Once the algorithm has been trained, it can be applied to new data sets and predict which elements of that set will behave like the data in the training set. Video object identification, for example, can use this general approach to learn what objects look like. The security application is usually to find bad actors, but it could just as well be identify equipment failures, as in many industrial settings.

Reinforcement learning is an iterative process where an algorithm seeks to maximize some value based on rewards for being right. Think of a laboratory mouse to press a button in order to get food. The difference is that these algorithms can do much quicker and on larger sets of data and choices than human. One of the classic uses of this in a commercial context is elevator scheduling, where the goal is to move the greatest number of people as quickly as possible with little energy as possible. One could extend this to managing the rate at which people were allowed through a turnstile feeding an elevator lobby so that it not only never overcrowdedded but also didn't keep people needlessly waiting.

What's truly interesting and somewhat unsettling about all these algorithms is that we literally don't know exactly how they come to their conclusions—and that's sort of the point. If we knew how to do the calculations, we would just do them, not get a machine to figure out how to do it for us. An output value from a neural network, for example, may involve billions of learned associations with billions of decision weights attached to them. If they were all printed out or somehow visualized in a multidimensional model, we would probably be no closer to true comprehension of what it all meant. ## REAL TIME ANALYTICS

The relevance of real-time analytics to security is, I hope, self-evident by now. In physical security, it's fair to say that anything we want to know, we would want to know sooner. In general, the promise of real-time analytics is to improve the speed and accuracy of business processes. Being able to analyze data quickly is part of fulfilling the promise of IoT. After all, what good are all our sensor data if you cannot take action on?

The term "real time" is often used, but it means different things to different people. In the context of computer engineering, it means an algorithmic process that is guaranteed to return a result within a specified amount of time. In the context of networking, it could mean "wire speed," or being able to keep up with the rate at which data packets are arriving, say, a firewall. For robots, the requirement would be fast enough to keep up with the laws of physics so that the robot doesn't get into an undefined state. In general, it means using data as soon as it arrives in a system, as opposed to being retrospective for reporting or some other forensic purpose.

For security, we will understand real time to mean the interval between events of concern are still taking place. That's a more generous definition than that of the others but puts an emphasis on having analytic results in time to respond with some type of preventive or corrective action. Most of the principal components in security systems deliver their raw data in real time: intrusion, fire, access, and video are all immediate. What's not immediate are analytics about emerging patterns or changes to existing patterns. Many of the real-time decisions we need in security are how to deploy resources or where to focus attention. Real-time analytics could indicate the need for additional manpower in one place or another, for example, it could prevent harm or property damage.

Like many of the other technologies we have examined in these pages, real-time analytics have traditionally been beyond the reach of most security organizations. The expense would be more than most could afford, in turn inhibits suppliers from creating such products in the first place.
