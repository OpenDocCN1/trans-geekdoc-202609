# BIG DATA DEFINED: THE FOUR V'S

Too much data to deal with is pretty close to the working definition of big data: information sets are so large and complex that conventional data processing applications are inadequate.

In this world, the familiar relational databases we grew up with break down the strain of more information than they can handle. Queries take long times to return the requested data, if they return at all. Disk arrays that once seemed to fill are now too small to fit. Bulging data sets require distributed file systems that can grow horizontally to practically infinite dimensions. The handy reporting software that allowed us to make had desktop queries has become useless as a typewriter against new ways of organizing the underlying data. Even the statistical concepts we once took at the height of mathematical sophistication are now passé and inadequate.

There is more to big data than simply being big. The four Vs, as they are known, provide a mnemonic framework that expands on our simple definition:

+   * Volume
* Velocity
* Variety
* Veracity

Volume is the defining characteristic of big data. It's right there in the name itself. But how big is big? That depends. The threshold is not a particular number of bytes, but rather a size that demands new technologies. This is a moving target, of course. Conventional relational databases and conventional business intelligence tools, for example, can manage data sets well into billions of rows. But they can't necessarily do it enough to be useful if the data sets change rapidly or aren't structured.

Velocity is the rate at which data stream into an information system. Think of the rate of all the tweets trades flooding the financial exchanges. Virtualize the rate of video and data flowing through a global security operations center. Stable or slowly changing data sets are usually amenable to traditional database and analytic technologies. That's because standard indexing and segmentation techniques can perform an analysis within the timeframe in which answers are required. High information rates crash classic batch-oriented analytics because the answer to every question changes from nanosecond to nanosecond. This is where the beans won't stay still.
