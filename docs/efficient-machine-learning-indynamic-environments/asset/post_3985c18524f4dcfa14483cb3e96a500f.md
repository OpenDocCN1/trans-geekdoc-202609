## Constructing Elastic ML Models

Many real-world ML inference applications face resource budgets that fluctuate unpredictably from call to call. This chapter studies ML inference under such arbitrary environments and introduces elastic models—models that can trade inference cost for accuracy at runtime. We develop B-DISTIL, an algorithm that constructs an elastic model from a pretrained teacher by progressive ensemble distillation, and we demonstrate its benefits across vision, speech, and sensor tasks. This chapter builds on the techniques developed by Dennis, Shetty, Sevekari, Koishida, and Smith [166].

### 2.1 Elastic Models

A conventional training pipeline produces a rigid network: given a fixed input dimension, the model always incurs the same inference cost. On ImageNet, the smallest ResNet available to us consumes only 0.15 GFLOPs but answers fewer than 12% of queries correctly (Figure 2.1). A large network delivers 83.4% top-1 accuracy yet demands 30.4 GFLOPs. Static selection therefore forces a painful choice between budget compliance and predictive quality.

Elastic models aim to escape that trade-off. We define an elastic model as a predictor f(x, κ), where x is the input and κ is the configurable elasticity value that determines where on the accuracy-cost Pareto frontier this model lies. Given a fixed input x and a resource budget τ, one can now aim to find the elasticity parameter κ corresponding to the best-effort prediction attainable under cost τ.

Note that the inference cost can be defined in various ways, for example— inference latency, floating-point operations (FLOPs), or total energy consumed. By being able to dynamically trade inference costs, elastic models offer a way to break free from static tuning.

A naive way to construct an elastic model is to pre-compute a Pareto frontier:

train a suite of models at different complexity levels, measure their cost (say, FLOPs) and accuracies, and store the Pareto-optimal set (Figure 2.1). At runtime, choose the model whose cost best fits the current budget. In this simple case, the elasticity parameter \(\kappa\) can be thought of as the index of the models in a sorting on cost. Assuming \(\mathcal{F} = \{f_1, \dots, f_K\}\) are the Pareto-optimal set of models, sorted in order of increasing cost, we have

```
f_{naive}(x, \kappa) = f_\kappa(x), \quad f_\kappa \in \mathcal{F}
```

Although simple, this approach has practical downsides in terms of maintenance overhead of managing models, selection latency when switching between models, and, crucially, it assumes the budget is known a priori. In practice the budget is revealed only when it has already been exhausted, rendering an upfront choice of \(\kappa\) impossible.

We pursue a more principled alternative. Starting from a single teacher model \(g(x)\), we decompose its capacity into a sequence of \(K\) weak learners \(\{f_1, \dots, f_K\}\). As we progressively evaluate the first \(\kappa = k < K\) learners, we obtain a prediction whose cost scales with \(k\). Assuming the accuracy at every \(\kappa\) remains competitive with the best-effort predictor, we have an anytime model whose accuracy improves as more budget becomes available. When inference is interrupted, we simply return the most recent prediction.

The key challenge is to distill the capacity of the teacher into a set of inexpensive learners such that greedily evaluating successive learners strictly improves the prediction—without knowing the budget in advance. Since the ordinary distillation procedure [21, 50] is fairly rigid—resulting in a single compressed model of a fixed size—we introduce a related but distinct problem: _progressive ensemble distillation_, and develop an algorithm to address this problem.

**Progressive Ensemble Distillation.** With progressive ensemble distillation, we seek to distill a large pretrained model, _g_, onto an ordered ensemble of ‘cheaper’ models (for instance, low-latency models), such that evaluating the first model is inexpensive but only produces a coarse estimate of the prediction (e.g., covering common cases), and evaluating additional models improves on this estimate (see Figure 2.2). This means that we can trade off between accuracy and inference time (latency) at runtime, by choosing the number of models we evaluate (_elasticity_ parameter).

Beyond elasticity, this decomposition confers additional practical benefits. On-device inference can combine ensemble components to meet latency constraints [94, 144]; the ordered structure naturally supports early-exit [61, 70] and any-time inference [73, 141] scenarios, and the learners can execute either sequentially or in parallel. Concretely: (i) we can control the accuracy-cost trade-off on demand, (ii) we can interleave sequential and parallel execution, and (iii) we can resume and improve upon coarse predictions without re-evaluating earlier learners.

Standard distillation struggles when the student’s capacity is much smaller than the teacher’s [112, 129], and distilling onto any weighted sum of shallow networks rarely outperforms distillation onto a single model [86, 149]. By composing and reusing intermediate activations and by introducing an additional loss term motivated by boosting theory [13], we perform _progressive ensemble distillation_ even when the capacity gap is large. As long as the compositions remain resource-efficient, we enlarge the hypothesis class without incurring significant extra inference cost. The B-DISTIL algorithm retains the theoretical guarantees of classical boosting [36] extended to the distillation setting, while remaining practical and effective.

The remainder of this chapter develops the goals of progressive ensemble distillation (Section 2.2), introduces the B-DISTIL algorithm (Algorithm 1), provides convergence guarantees (Section 2.3), and empirically validates the method on synthetic and real-world benchmarks (2.4).

### 2.2 Progressive Ensemble Distillation

Progressive ensemble distillation seeks to approximate a high-capacity model with an ensemble of smaller, lower-latency models. At runtime, accuracy can be traded for latency by selecting how many ensemble members to evaluate—an _elasticity_ knob exposed to the user. This section formalizes the problem as a two-player game and introduces the resulting algorithm, B-DISTIL.

### 2.2.1 Problem Formulation

Consider repeated plays of a general two-player zero-sum game with the pure strategy sets comprising hypothesis class $\mathcal{F}$ and a probability distribution $\mathcal{P}$. Given a teacher model $g$, our goal is to produce an ensemble of predictors from the set of hypothesis classes $\{\mathcal{F}_m\}$ to approximate $g$ well. Given a loss function $\mathcal{L}$ that measures the quality of a model $f \in \mathcal{F}$, let the loss (and reward) of the players be given by $F(f, p) = \mathbb{E}_{x \sim p}[\mathcal{L}(f, x)]$, and the minimax value of the game is

$$ \max_{p \in \mathcal{P}} \min_{f \in \mathcal{F}} F(f, p) . $$ (2.1)

In the context of distillation, given a training set $\{x_i\}$, the max player in Equation (2.1) selects a distribution over the training set, while the min player chooses a hypothesis that minimizes the loss under this distribution. In this setting, note that $\mathcal{P} = \left\{p \in \mathbb{R}^{N \times L} : p_{i,j} \ge 0, \forall j \sum_i p_{i,j} = 1 \right\}$ is the product of simplices in $N \times L$ dimensions, and

$$ (\nabla_f F(f, p))_j = \sum_i p_{i,j} (f(x_i) - g(x_i))_j . $$ (2.2)

Tools from the framework of stochastic minimax optimization can be used to approximately attain the value in Equation (2.1) (see Appendix A.1 for a more involved discussion). As is common in this setup, we assume our algorithm is provided access _weak gradient_ vector $h$ such that, when queried at distribution $p \in \mathcal{P}$ and for $\beta > 0$,

$$ \langle h, \nabla_f F(f, p) \rangle \ge \beta . $$ (2.3)
