# [执行交换](#toc.xhtml#s216a)

只要满足 `askedAsset` 的价格，任何人都可以执行交换。可供购买的 `offeredAsset`（门票代币）数量将是锁定在交换 UTXO 中的门票代币数量，如*[图 9.12](#c09.xhtml#fig9_12)*所示。交换验证器还将确保信标代币始终被发送回验证器脚本地址，卖家收到正确数量的 `askedAsset`，买家收到正确数量的 `offeredAsset`（门票代币）。

![](images/Figure-9.12.jpg)

**图 9.12：** 执行交换交易

在交换执行交易期间，我们还必须将门票代币转换为唯一的门票代币，以便在入场时将其标记为*已使用*。我们通过在同一交易中同时销毁原始门票代币并铸造一个新代币来实现这一点，如*[图 9.13](#c09.xhtml#fig9_13)*所示。参考代币 Datum 值最初设置为空字符串，但当用户打印门票时，将填充支付 PKH。

**图 9.13：** 转换门票交易

# [开启交换](#toc.xhtml#s222a)

门票铸造完成后，用户可以决定开启交换头寸并出售门票，如*[图 9.19](#c09.xhtml#fig9_19)*所示。第一步是确定属于用户的活动铸造策略哈希（`MPH`）。接下来，我们重建门票持有验证器以获取脚本地址和 UTXO。然后，我们使用钱包 UTXO、门票持有 UTXO、门票持有和信标铸造策略脚本来构建转移门票和铸造信标交易。应用程序还必须使用所有者 `PKH` 对交易进行签名，以便能够铸造信标代币。这不是必须的，但允许应用程序所有者在需要时控制谁可以在应用程序上出售门票。这可用于付费墙、`KYC` 或欺诈预防。

![](images/Figure-9.19.jpg)

**图 9.19：** 开启交换

# [查看交换](#toc.xhtml#s223a)

应用程序创建的所有开放交换均可通过使用信标铸造策略查询区块链来获取，如*[图 9.20](#c09.xhtml#fig9_20)*所示。信标铸造策略源自应用程序所有者的公钥哈希，因此任何人都可以查询它并重建铸造策略脚本。Blockfrost 将返回属于信标铸造策略 ID 的所有资产，这对应于所有开放的交换头寸。然而，对于我们的应用程序，我们已将活动和交换信息存储在数据库中，以减少每次请求的延迟和成本。因此，在我们的案例中，我们将直接查询数据库以获取交换列表，但请记住，区块链始终是事实来源。

![](images/Figure-9.20.jpg)

**图 9.20：** 查看交换

# [执行交换](#toc.xhtml#s225a)

买家现在可以前往门票应用程序查看所有待售门票。如果支付的价格符合要价，且数量足以满足订单，则交换将执行，如*[图 9.23](#c09.xhtml#fig9_23)*所示。使用钱包 UTXO 和交换 UTXO，支付门票的价值将直接发送到卖家地址，买家接收门票代币。在门票转换期间，将为每个铸造的唯一门票代币创建一个参考代币。该参考代币只能由应用程序更新，并包含一个标志，指示代币在活动中是否已被使用。

![](images/Figure-9.23.jpg)

**图 9.23：** 执行交换

# [关闭交换](#toc.xhtml#s226a)

当交换中的门票数量为零，或者卖家不再希望提供门票出售时，卖家将希望关闭交换（参考*[图 9.24](#c09.xhtml#fig9_24)*）。信标资产用于获取构建交换交易所需的交换 UTXO，并将门票代币（如有）发送回门票持有地址。信标代币也会作为关闭交易的一部分被销毁，因此该交换将不再出现在可用交换列表中。

![](images/Figure-9.24.jpg)
