

# 第 6 章：验证器

## 简介

本章将探讨什么是验证器以及它们为何如此重要。我们将展示如何花费锁定在验证器脚本地址上的 UTXO，以及如何访问兑换数据和数据中提供的数据。接下来将深入了解 `ScriptContext` 以及它如何用于访问与交易相关的输入和输出。本章还将回顾使用两种不同方法的代码示例：Helios 和 Lucid + Aiken。

## 结构

在本章中，我们将讨论以下主题：

*   验证器
*   Helios
    *   Helios 链上验证器
    *   Helios 链下解锁
    *   Helios 链下取消
*   Lucid + Aiken
    *   Aiken 链上验证器
    *   Lucid 链下解锁
    *   Lucid 链下取消

## 验证器

验证器是 Cardano 智能合约的基础，因为它们指定了花费锁定在脚本地址上的 UTXO 所需的链上条件。一旦验证器部署到链上，它就是不可变的，代码即“法律”。验证器的一个典型用例是归属合约，资金被锁定在合约中，直到满足特定条件。我们将在后续章节中进一步构建我们的归属示例，并查看链上和链下代码。验证器由两个部分组成：定义规则和逻辑的链上代码，以及创建和提交交易的链下代码。

## Helios

我们首先在[第 5 章，交易构建器](#c05.xhtml)中看到了如何使用 Helios 构建链下交易。在本章中，我们将首先查看构建链上验证器的代码，然后是花费锁定在脚本地址上的 UTXO 所需的链下代码。用于链上代码的 Helios 语言是一种强类型函数式编程语言，具有类似 Haskell 或 Aiken 等语言的代码质量优势。然而，Helios 编译器是用 JavaScript 编写的，并具有仅使用 JavaScript 在运行时编译的独特优势。这使得设置和安装变得微不足道，因为您只需要一个广泛可用于许多操作系统的最新版 Node.js。

## Helios 链上验证器

Helios 链上验证器的第一行指定了 Plutus 脚本的用途。在本例中，它是一个 `spending`（花费）脚本，脚本的名称称为 `vesting`（归属）。在[图 6.1](#c06.xhtml#fig6_1) 的第 7 行，定义了一个数据作为 `struct`，包含一个使用 `PubKeyHash` 数据类型的 `owner` 变量。这将存储在锁定在脚本地址上的 UTXO 中的链上。我们之前在[第 4 章，Plutus](#c04.xhtml) 的[图 4.5](#c04.xhtml#fig4_5) 中看到了这种类型数据的示例。在[图 6.1](#c06.xhtml#fig6_1) 的第 15 行，有一个带有 `enum` 数据类型的兑换数据，包含两个元素：`Cancel`（取消）和 `Claim`（领取）。`Claim` 元素有一个 `msg` 变量，用于在运行时向验证器传递消息。

![](images/Figure-6.1.jpg)

**图 6.1：** Helios 链上验证器声明[¹](#c06.xhtml#ftn1)

**注意**：本地运行时，可用 Helios Visual Studio Code 扩展 (`ext:hl`) 进行语法高亮。对于 Visual Studio Web，您必须将 `.hl` 扩展与 C # 关联。

在[图 6.2](#c06.xhtml#fig6_2) 的第 23 行，声明了一个**合约参数** `MESSAGE`，它将被硬编码到 Plutus 脚本中。**合约参数** 是一个位于主验证器函数之前的 UPLC 值，如果需要，可以在编译时或运行时动态更新。

![](images/Figure-6.2.jpg)

**图 6.2：** Helios 链上验证器主体[²](#c06.xhtml#ftn2)

主验证器函数在[图 6.2](#c06.xhtml#fig6_2) 的第 26 行定义。我们可以看到，三个参数 `Datum`、`Redeemer` 和 `ScriptContext` 被传递给主函数。验证器可能根据验证器逻辑使用这些参数中的无、任意或所有参数。我们已经在[第 4 章，Plutus](#c04.xhtml) 中讨论过 `Datum` 和 `Redeemer`，因此我们将更详细地研究 `ScriptContext`。`ScriptContext` 包括脚本用途以及与提交的交易相关的所有信息，**辅助数据（元数据）**除外。

正如我们从[第 3 章，交易](#c03.xhtml)中回忆的那样，脚本用途是在锁定在脚本地址上的每个 UTXO 的兑换数据中指定的。因此，可在 `ScriptContext` 中使用的四种脚本用途如下：

*   `Spending`：用于验证花费锁定在脚本地址上的 UTXO。
*   `Minting`：用于铸造或销毁原生代币。
*   `Certifying`：用于质押密钥注册和将质押委托给质押池。
*   `Rewarding`：用于提取质押奖励。
