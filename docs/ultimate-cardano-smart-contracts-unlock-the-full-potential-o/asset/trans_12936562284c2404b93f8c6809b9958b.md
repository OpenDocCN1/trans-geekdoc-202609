

Mithril 是区块链可扩展性、钱包和 Stake Pool Operators (SPO) 的重要发展。它是一种解决方案，允许客户端在无需从创世区块下载并重放所有交易的情况下获取区块链的当前状态。[^(36)](#c11.xhtml#ftn36) Mithril 的核心创新在于使用基于权益的阈值多重签名[^(37)](#c11.xhtml#ftn37) (`STM`) 由诚实的大多数利益相关者创建证书，证明 Cardano 快照的有效性。使用此证书，轻客户端或 SPO 可以验证快照，其安全属性类似于完全同步的节点。[^(38)](#c11.xhtml#ftn38)

# Input Endorsers

Input Endorsers 正如 Ouroboros Leios 文档所述，是 Cardano Ouroboros 协议的一项雄心勃勃且深远的设计扩展。[^(39)](#c11.xhtml#ftn39) 特别地，它专注于通过并行化区块生产和交易选择来最大化网络利用率。[^(40)](#c11.xhtml#ftn40) 这将在最大程度减少对网络额外资源需求的同时，显著提高区块生产吞吐量。*[Figure 11.24](#c11.xhtml#fig11_24)* 说明了 Cardano 网络当前的利用不足情况及优化领域。

![](images/Figure-11.24.jpg)

**Figure 11.24:** Network Utilization[^(41)](#c11.xhtml#ftn41)

Ouroboros Leios 引入了三种新的区块类型：

*   Input Blocks
*   Endorsement Blocks
*   Ranking Blocks

从高层来看，Input Blocks 包含从区块生产节点的内存池中获取的交易列表。正如 *[Figure 11.24](#c11.xhtml#fig11_24)* 所示，这可以在空闲期间异步完成。Endorsement Blocks 随后生成有效 Input Blocks 的证书。Ranking Blocks 然后使用 Endorsement 证书并形成 Endorsement Blocks 链。账本状态随后基于 Ranking Blocks 的顺序。值得注意的是，Input Endorsers 不会改变确定最长链的共识机制。[^(42)](#c11.xhtml#ftn42) 关于 Input Endorsers 更详细和彻底的描述，请参阅 Ouroboros Leios 研究论文。[^(43)](#c11.xhtml#ftn43)

# Conclusion

我们现在应该对如何测试智能合约并将其作为整体测试框架的一部分有了很好的理解。我们使用 Vitest 和 fast-check 等工具考察了传统测试和基于属性的测试。接下来，我们回顾了真实审计中的代码示例以及如何避免常见的智能合约漏洞。最后，我们讨论了扩展以及一些工具和技术，例如避免 UTXO 争用、Reference Scripts、Hydra 和 Mithril。我们还回顾了使用 Input Endorsers 的第 1 层可扩展性改进，这将在保持安全性和最大程度减少额外网络资源需求的同时，显著增加区块生产。在下一章中，我们将回顾编写 Cardano 智能合约时可使用的故障排除工具和技术。

# Points to Remember

*   测试智能合约很困难，因为代码在网络中的分布式节点上执行。
*   应用程序设计最佳实践将 UI 代码与链下和后端代码分离。
*   测试策略可以包括传统测试和基于属性的测试。
*   安全性是智能合约开发最重要的方面。
*   Double Satisfaction 漏洞涉及在仅验证（满足）一个输入条件的情况下花费两个或更多输入。
*   Invalid Datum 漏洞发生在并非所有 datum 字段都被检查和验证时。
*   Token Leakage 涉及铸造多个唯一的 Thread 或 Validity token。
*   审计是生产就绪的关键部分，应用于审查智能合约源代码。
*   应用程序扩展技术包括避免 UTXO 争用和利用 Reference Scripts。
*   Hydra 是第 2 层扩展解决方案，但会影响安全性和去中心化属性。
*   Input Endorsers 是 Cardano 第 1 层扩展解决方案，可显著提高区块生产吞吐量。
