

Helios 和 Lucid 都有很好的交易构建错误消息，并且存在许多错误条件和不同的错误原因。最常见的错误是资金不足，因为交易未平衡。这可能是因为 Ada 不足以支付交易费用，或者铸造的代币数量不足以匹配输出。幸运的是，这些错误可以使用本地调试器进行调试，你应该能够识别出问题。如果你仍然有问题，请在 Cardano Stack Exchange[⁴](#c12.xhtml#ftn4) 或 Helios[⁵](#c12.xhtml#ftn5) 和 Lucid/Translucent[⁶](#c12.xhtml#ftn6) Discord 频道中搜索并提问。

# Cardano 节点错误

不幸的是，Cardano 节点（账本）错误是最难诊断的。这是因为你会看到陌生的、格式不佳的错误消息，导致它们难以阅读[⁷](#c12.xhtml#ftn7)和理解。*[图 12.9](#c12.xhtml#fig12_9)* 提供了一个交易失败时可能看到的 Cardano 节点错误示例。

![](images/Figure-12.9.jpg)

**图 12.9：** Cardano 节点错误

为了更好地理解错误消息的含义，你可能需要参考用 Haskell 编写的 Cardano 账本[⁸](#c12.xhtml#ftn8)源代码。你将看到可以解释错误发生原因的代码和注释。*[图 12.9](#c12.xhtml#fig12_9)* 中的示例相当直接，是一个执行预算错误。还有其他不太明显的错误，可能需要查看代码才能理解错误的含义。幸运的是，大多数此类错误现在都会被链下交易构建器捕获，因此遇到 Cardano 节点错误的情况不像过去那样常见了。

# 钱包错误

我们将要回顾的最后一种错误类型是钱包错误。这些错误发生在使用浏览器扩展钱包时，并在*[表 12.1](#c12.xhtml#tab12_1)* 中列出。

|  | `InternalError` | 请求过程中发生内部错误 | -2 |
|  | `Refused` | dApp 未获批准访问浏览器钱包 | -3 |

# 结论

本章概述了 Helios 和 Lucid + Aiken 的调试工具和技术。我们探讨了如何为交易和数据类型生成 `CBOR`，以便与正式规范进行比较。我们还研究了如果 Plutus 脚本超出 CPU 和内存执行限制该怎么办，以及改进脚本性能的建议。然后我们探讨了 Helios 和 Lucid + Aiken 框架在构建和提交交易时如何提供错误消息。还分析了 Cardano 节点错误，以及如果发生这些错误，为什么我们可能需要查看 Cardano 账本源代码进行故障排除。最后，我们通过回顾遵循 CIP-0030 规范的基于浏览器的钱包错误结束了本章。在下一章中，我们将探索和回顾 Cardano 生态系统以及可帮助你在 Cardano 区块链上构建应用程序的资源。

# 要点回顾

*   调试智能合约涉及发射追踪，可打印变量和状态信息。
*   Helios 和 Aiken 都支持追踪，并具备追踪布尔表达式的能力。
*   如果 `optimize` 标志设置为 `true`，Helios 中的 `Trace` 和 `print` 语句将被移除。
*   Aiken 中的追踪默认被移除，仅在 `aiken build` 期间启用时才存在。
*   将交易转换为 `CBOR` 很有帮助，因为你可以将交易结构与正确性的 `CDDL` 规范进行比较。
*   CPU 和内存执行预算错误通常由链下交易构建器框架检测到。
*   通过使用 `cardano-cli` 或区块链浏览器查询链，你可以找到当前的协议参数。
*   使用链下交易构建器时，不平衡的交易是最常见的错误。
*   仅在 Cardano 节点发生且未被链下交易构建器捕获的错误虽然罕见，但可能发生。
*   钱包错误有详细文档，并返回一个状态码，该状态码将映射回定义明确的错误消息和描述。
