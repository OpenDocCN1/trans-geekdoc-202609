# 钱包

在加密货币中，钱包是与区块链交互的用户界面。钱包通常允许用户创建账户，账户是锁定在公钥地址上的 UTXO 集合。这种**账户抽象**有助于用户直观地理解账户余额和交易历史等熟悉概念。许多钱包还允许用户选择质押池并注册其质押密钥以收集质押奖励。[表 5.1](#c05.xhtml#tab5_1) 按字母顺序列出了 Cardano 网络上的部分钱包提供商。

**全节点：** 包含完整 Cardano 节点的钱包，不使用任何第三方服务在区块链上查找交易。

**硬件钱包支持：** 支持使用硬件设备对交易进行签名的钱包。

**移动端应用：** 在 iOS 或 Android 设备上拥有原生移动应用的钱包。

**开源：** 钱包的开源代码可在 GitHub 上获取。

# 助记词

要使用钱包创建账户，必须创建新的助记词或导入现有助记词。如果回顾[第 3 章，交易](#c03.xhtml)，签名交易需要私钥。为了创建这个私钥，钱包通常使用**助记词**来生成随机私钥。这是一个两步过程：首先，使用一组助记词或单词组来创建随机种子[²](#c05.xhtml#ftn2)；然后，使用该随机种子派生公钥和私钥对[³](#c05.xhtml#ftn3)。

# 地址派生

确定性分层（HD）钱包（如 `Eternl`）遵循 CIP-1852[⁵](#c05.xhtml#ftn5) 规范中的派生路径：

`m / purpose' / coin_type' / account' / role / index`

在[图 5.5](#c05.xhtml#fig5_5) 中，我们可以看到接收地址的派生路径为：

`m/1852'/1815'/0'/0/0`

[表 5.2](#c05.xhtml#tab5_2) 解释了派生路径的每个元素：

| **名称** | **值** | **备注** |
| --- | --- | --- |
| Purpose | 1852 | 规范名称（例如 CIP-1852） |
| Coin Type | 1815 | 每种加密货币不同的值（例如 Ada Lovelace 诞辰年份） |
| Account | 0 | 允许创建独立的钱包账户 |
| Role | 0 | 0 = 外部链（接收付款）<br>1 = 内部链（找零地址）<br>2 = 质押密钥 |
| Index | 0 | 从 0 开始的地址索引 |

**表 5.2：** 派生路径

你可以使用 HD 钱包为同一个私钥创建不同的地址来接收付款（和找零）。然而在实践中，通常首选“`single address mode`”（单地址模式），即重复使用同一个地址。为每笔交易创建新地址有助于匿名化，使其无法关联到钱包账户。但在 Cardano 中，一旦为钱包地址注册了质押密钥，该地址的所有交易都可以通过质押密钥关联。为接收和找零地址使用多个地址会增加 dApp 的复杂性，这就是为什么一些钱包仅支持单地址模式。[图 5.6](#c05.xhtml#fig5_6) 展示了如何将 `Eternl` 切换（或保持）为单地址模式。

# 质押

Cardano 网络最重要的功能之一是能够轻松地从钱包进行质押。这被称为流动性非托管质押，这也是 Cardano 网络拥有高质押率的原因，这有助于其安全性和去中心化。要进行质押，用户进入质押标签页，选择一个质押池，并选择“`Delegate`”，如[图 5.7](#c05.xhtml#fig5_7) 所示。

# CIP-30

为了让 dApp 能够连接到浏览器扩展钱包（如 `Eternl`），dApp 应遵循 CIP-30 标准[⁶](#c05.xhtml#ftn6)。该标准描述了一种基于网页的通信桥接，允许网页与浏览器扩展钱包交互。这是通过将 JavaScript 代码注入到正在渲染的网页中来实现的。然后，网页或 dApp 可以调用具有预定义公共方法的 JavaScript 代码，以从钱包检索和提交数据。在本章后面的链下代码示例中，我们将看到如何使用 CIP-30 与钱包交互。
