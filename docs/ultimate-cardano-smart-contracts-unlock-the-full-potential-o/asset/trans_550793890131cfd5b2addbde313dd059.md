

# Aiken 验证器脚本分析

现在，我们准备好查看第一个 Aiken 验证器脚本，如[图 6.10](#c06.xhtml#fig6_10)所示：

![](images/Figure-6.10.jpg)

**图 6.10：** Aiken 链上验证器声明[^(10)](#c06.xhtml#ftn10)

[图 6.10](#c06.xhtml#fig6_10)中的前 5 行是我们将要使用的类的显式导入，随后是 `Datum` 和 `Redeemer` 类型。`Datum` 包含一个 `Hash` 对象，其中包含 `Blake2b_224` 和 `VerificationKey` 对象。值得注意的是，这在链上作为单个 `ByteArray` 存储，代表公钥哈希。在第 15 行，`Redeemer` 包含两个条件（`Cancel` 和 `Claim`），用于花费锁定在此脚本地址上的 UTXO。`Claim` redeemer 还使用 `ByteArray` 数据类型包含一个 `msg` 载荷。在第 21 行，我们将 "`Hello World!`" 消息硬编码为脚本常量。

接下来，在[图 6.11](#c06.xhtml#fig6_11)中，我们在第 23 行定义验证器函数，并创建 vesting 函数，以 `Datum`、`Redeemer` 和 `ScriptContext` 作为参数：

![](images/Figure-6.11.jpg)

**图 6.11：** Aiken 链上验证器主体[^(11)](#c06.xhtml#ftn11)

在第 26 行，我们确定特定交易提供的 `Redeemer` 类型。在 `Cancel` 的情况下，第 29 行的代码会遍历所需签名者列表，并确认是否存在与 datum 中的公钥哈希匹配的公钥哈希。如果为真，则验证器评估为真，并允许花费锁定在脚本地址上的 UTXO。如果 `Redeemer` 是 `Claim`，我们在第 32 行将 `msg` 载荷与硬编码的消息常量进行比较。如果 `Redeemer` 没有匹配项，则验证器将失败，不允许花费锁定在脚本地址上的 UTXO。

# Lucid 链下解锁

我们将创建与使用 Helios 时相同的 `Unlock.tsx` 组件和 `index.tsx` 中的 `unlock function`。我们需要为 unlock function 创建一个 `Redeemer`，但不需要创建 `Datum`，因为它已经是我们想要花费的 UTXO 的一部分。[图 6.12](#c06.xhtml#fig6_12)第 172 行的 `Redeemer` 创建了一个 Plutus Data 对象，对应于我们在第 4 章[Plutus](#c04.xhtml)中看到的 UPLC 数据类型。在这种情况下，我们在索引 1 处创建一个 `Constr`，包含一个十六进制编码的字符串。当脚本被评估时，这个十六进制编码的字符串将被转换为 `Redeemer` `Claim` `ByteArray` 载荷。我们指定索引为 1，因为 `Redeemer` `Cancel` 是在 Plutus 脚本中首先定义的 `Redeemer`，索引为 0。按顺序的下一个 `Redeemer` 将具有索引 1，即 `Claim` `Redeemer`。

![](images/Figure-6.12.jpg)

**图 6.12：** Lucid 链下解锁[^(12)](#c06.xhtml#ftn12)

在第 175 行，通过调用 `lucid.utxosAt` 函数获得锁定在脚本地址上的 UTXO，该函数使用 Blockfrost API 查询区块链。接下来，我们构建交易，并在第 182 行指定输入 UTXO，在第 183 行指定验证器脚本。现在可以使用 `.complete()` 方法组装 lucid 交易。在幕后有大量活动来组装和完成交易。我们将专注于更常用的 `lucid tx` 方法来构建和提交交易。一旦交易完成，钱包将要求用户签名并将其提交到网络。

# 结论

我们查看了使用 Helios 和 Aiken 语言构建的第一个链上 Plutus 验证器。然后我们查看了使用 Helios 和 Lucid 分别执行这些验证器的相应链下代码。我们了解了如何使用 Aiken 初始化项目以及如何编译 Aiken 智能合约。然后，我们研究了 `ScriptContext` 以及它如何包含关键交易信息，如输入、输出、脚本目的等。我们还查看了链上的 `Datum` 和 `Redeemer` 定义以及它们在脚本执行期间如何被访问。示例中还演示了链下 `Redeemer` 和所需签名者的创建。下一章将深入探讨铸造策略、参数化智能合约和铸造原生代币。

# 要点回顾

*   Helios 既用于链上代码也用于链下代码。
*   Helios 链上代码可以即时编译，因为 Helios 编译器是用 JavaScript 编写的。
*   Aiken 用于链上代码，并使用基于 Rust 的 `aiken` 编译器在运行前编译。
*   Aiken 还会生成一个蓝图文件，其中包含 Plutus 脚本元数据和类型定义。
*   `aiken` 程序有几个方便的实用函数，可用于智能合约开发期间。
*   Lucid 用于链下代码，经常与 Aiken 结合使用。
*   Lucid 和 Helios 链下代码依赖区块链 API 提供商来获取区块链信息，例如锁定在脚本地址上的 UTXO。
*   Helios 链下代码可以导入 Helios 链上代码，从而允许共享类型定义。
*   Helios 链下代码不需要任何第三方库，并整合到一个 JavaScript 文件中。
*   花费 UTXO 时，必须为锁定在脚本地址上的每个 UTXO 提供一个 `Redeemer`。
*   所需签名者必须在交易的见证集中包含签名。
