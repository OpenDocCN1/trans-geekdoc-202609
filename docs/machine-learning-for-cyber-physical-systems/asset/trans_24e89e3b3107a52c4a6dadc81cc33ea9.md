为预测每个工序后的产品质量，需要训练不同的 CART 算法，因为在每个工序中，可用于训练 CART 算法的数据量不同。这导致了四个不同的 CART 算法，其性能如图 3 所示。结果包括超参数调优后创建的决策树。通过应用随机搜索，结果可提高 30%，这种情况在其他案例中也可以观察到 [15]。由于第四个工序不会生成新数据，因此未针对从第四个工序到第五个工序的变化学习新的决策树。

指标 MCC 显示了算法在预测工序实际类别方面的性能。对于第一个工序步骤，该指标为 MCC = 0.21。这意味着预测类别与实际类别之间存在匹配，但匹配度相对较低，仍优于随机预测。完成的工序越多，需要执行的工序越少，MCC 越高。当使用更多数据点进行学习任务时，模型质量会提高。此外，未来需要预测的工序和结果更少。第五个工序完成后，指标值为 MCC = 0.70，这意味着决策树是一种适合用于充分预测产品质量的算法 [16]。

## 2.2 经验教训

接下来，将呈现具体的经验教训，首先从管理层开始。随后，将重点介绍针对项目经理以及计算机科学家和开发人员的经验教训。所提出的方法带来两个核心研究需求。

### 管理人员视角的经验教训：

- 原则上，只能分析可用数据。只有当所获取数据的质量可接受时，大数据才能带来有益的结果。
- 管理人员需要明确通过数据分析要实现哪些结果。初始项目的期望必须合适。
- 数据科学项目应从小规模开始。如前所述，像决策树这样的简单算法已能带来有益结果。如果首批项目进展顺利，则可以扩大项目规模。

### 项目经理视角的经验教训：

- 在实施 ML 算法时，理解业务目标并制定精确目标至关重要。
- 过程工程师与数据科学家之间必须建立非常紧密的协作。
- 要了解技术相互依赖关系和数据集特征，通常需要进行多次迭代。与最终实施 ML 算法相比，数据理解和数据准备过程耗时较长。
- 项目经理应意识到该项目是速胜项目、低复杂度项目还是长期承诺项目。

### 计算机科学家和开发人员视角的经验教训：

- 像 Jupyter 这样的 Python 笔记本可以将整个代码分割成合理的部分 [17]。使用 Python 笔记本，代码可以按顺序更新，从而使编码更加轻松快捷。引入的变量在项目结束时仍应可读且可理解。
- 由于合适 ML 算法的选择高度取决于用例、数据集的外观以及相关数据科学家的个人经验，因此 ML 算法的选择既困难又复杂。
- 超参数调优对于最优求解分类问题是必不可少的。基于随机搜索的优化已取得成功，但高级优化可以带来更好的解决方案。

总的来说，我们建议公司应从第一个数据科学项目开始并积累自身经验。基于此可以了解将会遇到哪些具体挑战。换句话说——熟能生巧！

除了经验教训之外，我们还可以从所提出的流程和经验教训中得出两个核心研究需求。首先，应评估更复杂的超参数优化方法是否能够优于随机搜索和网格搜索等基本方法。其次，合适 ML 算法的选择流程是基于我们的经验，并通过将学习任务与文献进行比较而建立的。一个支持我们选择合适 ML 算法的工具将使该过程更加透明和可复现。在接下来的内容中，我们提出了一个此类工具如何运作的概念。

## 3 机器学习算法的选择

使用方法论来解决特定任务可以产生可理解且可复现的结果。因此，专门为数据挖掘和知识发现开发了方法论 [18]。由于上述优势，它们在大多数相关项目中被使用 [3]。

作为前三种方法论，CRISP-DM、SEMMA（采样、探索、修改、建模和评估）以及 KDD（数据库中的知识发现）都包含一个专门用于为问题创建模型的阶段 [19]。由于三种方法论的通用性，“建模”阶段的活动复杂程度各不相同，从应用线性回归一直到深度学习。因此，数据科学家必须决定如何进行“建模”阶段，例如通过应用 ML 算法。通常，此决策包含以下三个方面：个人经验、数据集的外观以及文献回顾。[20]

需要处理的问题和相应的数据集是领域特定的。支持数据科学家选择 ML 算法的工具大多是所谓的“速查表” [21]。团队成员仅将领域特定知识带入解决方案。因此，选择 ML 算法的过程高度依赖于数据科学家的专业知识。由于方法论和工具均不包含这种领域特定知识，选择 ML 算法的过程不可复现。并非所有领域特定知识都能集成到工具中。选择 ML 算法的过程因其所需的数据科学家创造性而脱颖而出。因此，决策工具不能免除数据科学家的责任，但可以作为完成该任务的支持。在接下来的内容中，我们提出了一种建立此类领域特定决策工具的概念。

## 4 生产质量的决策工具

决策工具（DMT）充当数据科学家的领域特定支持，用于选择合适的 ML 算法来创建满足问题特定要求的模型。通过包含图 4 所示的三个主要方面来实现：数据输入的外观、要创建的模型的要求以及关于所考虑用例的领域特定知识。在为用户提供建议时，会包含所有三个因素。

![](img/a2f5eed6507498d886a06be86239344b_59_0.png)

图 4. 选择 ML 算法时需考虑的因素

数据科学家通过用户界面（UI）与 DMT 交互，用以描述他想要使用 ML 算法建模的特定用例。DMT 将输入与历史评估和问题（包括其评估）进行比较。随后，DMT 为数据科学家提供可能适合特定用例的 ML 算法列表以及关于相应选择过程的其他信息。DMT 的概念如图 5 所示，并在以下部分详细描述。

![](img/a2f5eed6507498d886a06be86239344b_60_0.png)

图 5. 决策工具的总体概念

使用 UI，数据科学家将数据集的特征、要创建的模型的要求以及用例的描述加载到 DMT 中。数据集特征示例包括数据维度、特征数量、数据点数量、数据质量、数据分布或数据噪声。要创建的模型的要求示例包括学习时间、模型性能或模型透明度。用例描述包括关于用例类型的信息，例如预测性维护或产品质量预测。维度或最大运行时间等特征是定量的，可以直接加载到 DMT 中。其他特征，如模型透明度，需要使用目标问题度量法 [22] 等方法从其定性状态转换为可衡量的形式。这影响了特征加载到 DMT 中的自动化程度。

两个主数据库充当 DMT 的支柱：一个包含 ML 算法领域特定特征的数据库，以及一个存储 ML 算法问题特定特征的数据库。
