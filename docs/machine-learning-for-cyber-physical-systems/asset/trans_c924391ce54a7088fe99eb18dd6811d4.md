## 基于 Web 的机器学习状态监测平台

Thomas Bernard¹, Christian Kühnert¹, Enrique Campbell²

¹ 弗劳恩霍夫光电子、系统技术和图像利用 IOSB 研究所
德国卡尔斯鲁厄

² 柏林水务公司，柏林新犹登大街 1 号

* 通信作者。电话：+49-721-6091-360
电子邮件地址：thomas.bernard@iosb.fraunhofer.de

**摘要。** 现代水系统基础设施配备了大量传感器。近年来，机器学习（ML）算法已成为数据分析的一个有前途的选择。然而，目前 ML 算法在实际应用中并不常用。一个原因是数据科学家集成和维护 ML 算法的成本高且耗时。为应对这一挑战，本文提出了一种通用、可适应的平台，用于水分配网络的实时数据分析。该平台的架构允许连接到不同类型的数据源，实时处理其测量数据（无论是否使用 ML 算法），并最终将结果推送到不同的接收端，例如数据库或 Web 界面。这是通过平台的模块化、基于插件的软件架构实现的。作为用例，一种数据驱动的异常检测算法被用于监测柏林市多个水处理厂的水质。

**关键词：** 机器学习；水质监测；异常检测；插件架构；数据融合。

### 1 引言

近年来，水分配网络和水处理厂中安装了大量新的水质和水力传感器。这一趋势的原因是：(1) 涌现出许多新的传感器公司和相应的新传感器，这意味着传感器单元的成本降低和性能提升；(2) 由于无线通信技术（例如 GSM）的发展，安装成本大幅下降。因此，有必要开发集成平台，用于存储、可视化和增强分析这些数据。先进数据分析在水基础设施中的优势已针对不同场景进行了研究，例如饮用水质量监测 4、水消耗预测 6 或沉积物输运建模 1。然而，不同的数据供应商以及拥有过时 IT 基础设施的旧工厂，仍然使最先进的数据分析算法的集成变得复杂。尽管如今有许多 IoT 和数据分析平台可用，但将这些平台集成到水务公司的 IT 基础设施中并实施 ML 算法的工作量仍然非常大。为克服其中一些挑战，本文提出了一种通用的数据融合与分析平台，重点使用机器学习算法对 WDN 进行状态监测。该平台遵循基于插件的架构，这意味着根据当前用例的具体需求（例如，将数据保存在数据库中、执行异常检测），可以安装不同的软件组件。作为一个用例，该平台被用于并行监测九个水质测量站的状态，结合使用主成分分析（PCA） 2 和高斯混合模型（GMMs） 9。机器学习算法的结果，包括学习到的过程图、状态轨迹和异常指数，在 Web 界面中针对所有站点进行了可视化。

### 2 平台架构

所提议平台的架构由图 1 所示的三个主要部分组成：(1) 平台核心，(2) 插件结构和 (3) Web 界面。平台核心负责不同软件模块的管理和数据处理，并在第 2.1 节中描述；插件提供特定用例所需的应用功能（例如，分析算法；连接到数据源），并在第 2.2 节中描述。最后，用于向用户提供反馈的 Web 界面在第 2.3 节中说明。

### 2.1 平台核心

平台核心的目的是提供稳定性，以实现所有组件之间的通信——无论其用途、数据速率或生命周期如何。其主要目的是充当信息枢纽，为所有插件提供标准接口。因此，平台核心利用中介者设计模式 3 将所有插件相互解耦。插件和核心的最终通信拓扑是一个以核心为中心的星形网络，从而防止插件之间的任何直接通信。核心本身使用模型-视图-控制器（MVC）模式 3。

核心管理器是平台的控制器。它是所有插件以及核心缓存的所有者，并负责它们的创建和销毁。由于它也是整个核心的门面，因此被所有插件通过引用所知，插件需要为每个想要访问的核心缓存条目请求访问权限。

核心缓存充当模型，以将核心的数据与其逻辑分离。为了与核心缓存建立只读或读/写连接，插件必须获得核心逻辑的授权。一旦建立连接，插件将收到请求的核心缓存数据的本地副本，该副本通过观察者模式 3 与缓存保持同步。

### 2.2 插件

为保持最大灵活性，平台遵循基于插件的架构。这意味着根据当前用例的具体需求，可以将不同的软件组件集成到平台中。基本上，插件代表完成特定任务的软件模块。示例包括连接到水务公司的 SCADA 系统；实现事件检测算法；或自动生成日报、周报或月报。插件使用工厂模式 3 以允许创建多个实例，这些实例可以单独配置、启动和停止。

### 2.3 Web 界面

提供 Web 界面，以便为不同操作系统提供跨设备接口，用于访问和解释数据。因此，该界面的主要目的是为用户提供数据分析算法结果的快速概览。由于它被实现为一个主页，任何带有互联网连接的设备都可以从任何位置通过多个并发客户端访问它。数据通过 Web 套接字传输到 Web 客户端。
