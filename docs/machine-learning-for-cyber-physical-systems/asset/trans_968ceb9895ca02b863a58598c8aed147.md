

然而，这些算法的运行时间在很大程度上取决于输入数据。DLNN 中大部分计算时间都由卷积步骤消耗，该步骤基于通用矩阵乘法（GEMM）。为了加速 DLNN 的计算时间，近年来已经提出了多种针对图形处理单元（GPU）的高度优化 GEMM 实现 [1]。为了实现高计算吞吐量，这些方法中的大多数都基于 GEMM 算法的硬件特定软件内核实现。通常，不同的硬件相关内核参数是手动调整的，这需要关于特定 GPU 架构的专业知识。此外，GEMM 内核的性能受所处理输入数据形状的强烈影响。由于 GPU 加速器的不同内存布局，不同的数据大小对 GEMM 内核的计算运行时间有巨大影响。

为了实现最大性能，GEMM 算法的参数必须针对硬件和任务进行调整。近年来，已提出多种 GEMM 内核参数自动调优方法 [2]——其基本思路是自动调整有限数量的关键 GPU 内核参数，以实现最大性能。通常，这些方法不考虑给定输入数据的大小和形状，从而导致不同的计算运行时间。

所提出工作的动机是为基于 GPU 的 GEMM 内核开发一种自动调优流程，该流程会考虑全面的内核参数集以及输入任务中数据的不同形状。

诸如 [2] 之类的提议自动调优解决方案通常需要大量的计算运行时间来找到最优内核参数集。例如 MAGMA GEMM 内核 [4] 中的内核参数空间非常大，因此进行了限制以减少内核参数的搜索空间，随后采用暴力搜索机制。这通常会导致待设内核参数的搜索时间较长。

## 1.2 相关工作

广为人知的自动调优概念，如自动调优线性代数软件项目（ATLAS）[5] 或优化稀疏内核接口（OSKI）[6]，侧重于 CPU 计算的优化。只有少数方法引入了 GPU 内核参数自动调优概念 [7]。这些方法仅关注少量调优参数，因此其获得的性能无法与本工作中提出的方法合理比较。为了实现最佳性能，必须考虑全面的 GPU 内核参数集。

在文献中还有更多自动调优方法，例如 [8, 9]。虽然 [8] 中提出的工作侧重于 3D TFT，但 [9] 中的方法侧重于稀疏矩阵，并基于统计模型优化 GPU 内核。[10] 和 [11] 中提出的概念侧重于自动生成 GPU 内核代码并对不同生成的内核进行自动调优。由于生成的代码未针对底层 GPU 架构进行优化，这些概念的性能通常不是最优的。

本工作基于广为人知的 MAGMA GEMM 内核。该软件实现的特点是拥有广泛的 GPU 内核参数空间。MAGMA GEMM 内核已在多种自动调优方法中进行过研究 [2, 12–16]。原始内核实现已在 [12] 中描述，第一个自动调优概念在 [13] 中提出。随着 NVIDIA Fermi GPU 架构的推出，内核实现已被修订 [14]，一种自动调优流程已在 [2] 中提出。该方法的特点是 GPU 内核参数拥有巨大的搜索空间，并结合暴力参数搜索机制，这会导致寻找最优内核参数时付出高昂的计算开销。针对小规模 GEMM 操作，[15, 16] 中提出了批量 GEMM 操作方法，[17] 描述了在机器学习流程中利用 MAGMA GEMM 内核。[18] 中提出的自动调优方法侧重于 GPU 在处理 GEMM 操作时的能效。

大部分提出的最先进的工作都基于暴力方法来确定最优 GEMM 内核参数。这通常会导致巨大的参数搜索空间，因此大多数方法都采用参数组合预消除步骤来减少计算开销。用于减少搜索空间的不同启发式方法可能会排除掉最优内核参数组合。鉴于这些假设，所提出的工作侧重于定义最优启发式方法以减少搜索空间，并结合模拟退火（SA）流程，以高效地找到性能最佳的 GEMM 内核参数。

## 2 解决方案

最优 GPU 内核参数在很大程度上依赖于底层 GPU 硬件架构、内存布局和输入数据大小。不同的设置会导致不同的最优参数组合。因此，寻找最优参数组合的搜索空间可能非常大。手动调整参数是不切实际的，因为需要针对每个 GPU 架构和每组输入数据大小重新进行。鉴于这些假设，在以下章节中，我们提出了一种针对基于 GPU 的 GEMM 算法的两步自动调优方法。在第一步中，通过多种启发式性能标准修剪内核参数搜索空间，为一组不同的用例保留性能良好的参数组合。在第二步中，基于修改后的模拟退火（SA）算法，对剩余的参数集进行进一步处理，以找出最佳内核参数组合，该组合针对 GPU 架构和任务特定的数据布局进行了优化。

在以下章节中，提出的自动调优方法将进行介绍。在 2.1 节中，简要介绍了 MAGMA GEMM 内核；在 2.2 节中，我们解释了开发的减少搜索空间的启发式方法，在 2.3 节中，介绍了 SA 方法。

### 2.1 Magma GEMM Stencil 结构

所开发的自动调优方法基于广为人知的 MAGMA GEMM 内核。原始内核实现已在 [12] 中描述，并以广泛的 GPU 内核参数空间为特点。算法 1 显示了内核的伪代码。内核具有 11 个参数——其中两个内核参数仅与复数空间中的计算相关。因此，内核参数空间被减少到九个相关的内核参数——这些参数如下所述：

- **块大小**：块大小 BLK\_M、BLK\_N 和 BLK\_K 定义了线程块将计算多少个元素。
- **线程块维度**：线程块维度 DIM\_X 和 DIM\_Y 决定了线程块的大小，该线程块在结果矩阵上计算一个块。
- **子维度**：子维度 DIM\_XA、DIM\_XB、DIM\_YA 和 DIM\_YB 决定共享内存（SMEM）的填充方式。

### 算法 1：GEMM 内核算法（简化）

```
Data: Matrix A [M x K], Matrix B [K x N], Matrix C [M x N], alpha,
beta
Result: C=A x B * alpha C + beta * B
load $A_t$ and $B_t$ to SMEM;
for $i \leftarrow 0$ to $K step BLK\_K$ do
  $A_{t+1}$ and $B_{t+1}$ to regs;
  for $i \leftarrow 0$ to $BLK\_K$ do
    load $A_t$ and $B_t$ to REG;
    $C_{temp}=A_t * B_t$
  load $A_{t+1}$ and $B_{t+1}$ to SMEM;
C = $C_{temp}$ * alpha + beta
```

### 2.2 减少搜索空间

为了在第一步中减少寻找最优内核参数集的搜索时间，有必要消除那些相对于底层 GPU 硬件布局不可能且可能导致内核执行行为不稳定的参数集。以下参数进行了削减：

- **预限制**：我们首先削减了可行的线程数，即线程块维度。线程块维度（DIM\_X、DIM\_Y）只能是 8、16 或 32，从而产生 64、256、512 或 1024 个线程。GPU 制造商 NVIDIA 建议至少使用 64 个线程 [20]，这是我们应用的下限，上限由 GPU 的硬件规范给出。其他配置将无法映射到 GPU 硬件。
