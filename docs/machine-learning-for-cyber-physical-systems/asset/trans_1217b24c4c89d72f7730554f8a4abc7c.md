分析流水线的核心概念如图1所示。收集机器数据高度依赖于用例，需要根据给定的数据源和目标机器的可访问性进行定制。为了简化后续分析步骤的数据处理，如果目标架构允许，原始数据需要被收集并集中存储。拥有用于流水线进一步数据操作的单一数据源（例如集中式数据库）大大简化了数据处理。

## 3 实施工业分析的挑战

在机械和工厂自动化的背景下，工业分析是一个相对较新的主题，其中在技术和组织实现方面的经验仍然很少。在本节中，我们分享了在实际应用中实施工业分析的经验，并讨论了在为生产环境设计机器学习解决方案时需要考虑的方面。

### 3.1 数据分析流水线的可扩展性和可重用性

与自然语言处理或图像分类等经典大数据应用相反，机械应用通常面临历史数据量少的问题。一方面，用于以高采样率收集机器数据以供机器学习应用的自动化技术几乎不可用。另一方面，对于给定的自动化应用，根本不需要存储大量机器数据。随着对历史数据价值的认识不断加深，机器制造商和操作员开始实施越来越多的传感器技术以提高数据质量。因此，随着实施传感器和存储技术的成本降低，未来机器生成的数据量将会增加。然而，在当前的机械应用中，数据集通常在兆字节到千兆字节范围内，这允许应用小数据处理架构，这些架构应做好可扩展性准备，以便未来处理更大的数据集。为此，我们设计了一种基于容器的架构，其中关键功能（如分析流水线、前端用户界面等）如图2所示，在独立的软件容器中实现。

前端用户界面包含不同的功能，如下所述：状态监控用于跟踪分析流水线的状态，并向用户报告异常行为。分析架构设计用于处理不同用户，并提供身份验证和用户分组功能。分析函数（如模型评分或模型学习）可以在不同时间间隔执行，这些间隔可以在调度器中配置。用户可以从模型数据库中给出的不同模型中选择，并根据目标机器配置和调整模型。绘图创建容器用于基于生成的分析数据生成用户定义的图表。

机器数据被收集并存储在相应的数据库中，该数据库用作数据分析流水线容器的数据源。除了机器数据，该架构还包含一个模型数据库，其中存储了不同的机器学习模型及其预处理流水线。

在分析功能的典型流程中，调度器触发分析流水线的执行，该流水线从数据库加载选定的模型，并将模型应用于指定的输入机器数据。对于模型评分，生成的数据被写入分析结果数据库，该数据库存储用于结果可视化的数据。对于模型学习场景，分析流水线的结果是新的或更新的机器模型，它被存储在模型数据库中，并可用于未来的评分。

该架构设计用于水平可扩展性和平台独立性。该架构不使用单个分析流水线，而是允许同时运行多个分析流水线，这些流水线可用于加快执行速度，或同时运行不同的模型。其基于容器的实现允许该架构部署在单台PC上（配备合理数量的可用资源），也可部署在云端的虚拟环境中。

### 3.2 从想法到生产的流程

工业分析解决方案涉及多个领域，如数据工程、机器学习、UI设计和系统工程。覆盖这些多样化的主题需要一个跨学科的开发团队。典型角色包括：

- 应用工程师：他们涵盖深入了解目标机器应用所需的领域知识。
- 数据科学家：数据科学家从算法角度开发分析流水线。这涉及特征准备和选择，以及算法选择和调优。
- 系统架构师：需要系统架构师帮助定义最适合目标分析应用的系统架构布局。
- 全栈软件开发人员：软件开发人员将所选分析流水线实现到目标系统架构中，该架构例如可以是机器级的工业PC，也可以是云或混合解决方案。
