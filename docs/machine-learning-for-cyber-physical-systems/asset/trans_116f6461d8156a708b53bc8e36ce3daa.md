

## utilization criteria

这种方法背后的想法是利用 [21] 中解释的 GPU 隐藏延迟原则。基本上，当 GPU 芯片从片外全局内存 (GMEM) 加载数据时，它将暂停相应的 warp，warp 是 32 个线程的一束。GPU 会调度另一个 warp，而在之前的 warp 等待时进行切换。通常从 GMEM 加载数据需要几百个 GPU 周期，因此延迟隐藏对性能至关重要。要实现延迟隐藏，GPU 内核必须保持足够的可用 warp，并且 GPU 能够在加载数据时在上下文之间切换。

GPU 上可用 warp 的数量由利用率描述。利用率受可用 SMEM 和 GPU 内核本身使用的寄存器 (REG) 数量的限制。基于这些资源，可以计算可实现利用率的上限。资源消耗和最大利用率可以通过分析内核源代码来确定 - 类似的方法可以在 [2] 中找到。需要注意的是，所呈现的工作以每个流式多处理器 (SM) 的 warp 数量来衡量利用率。GPU 在 warp 中调度所有内容，因此这似乎是一种合理的方法。此外，我们强制 SMEM 和 REG 具有相似的利用率水平。此约束避免了大量利用一种资源而几乎不利用另一种资源的参数组合。由于 REG 而利用率严重受限的参数组合性能较差，那些由于 SMEM 而利用率严重受限的参数组合也是如此。那些由于 SMEM 而利用率严重受限的参数组合，对于其所实现的利用率而言，保留的结果矩阵条目较少。因此，数据必须比必要时更频繁地从 GMEM 加载。受 REG 高度限制的参数组合，为了获得更快的运行时间，保留更少的待读取数据。因此，它们必须更频繁地加载和等待。

## efficiency criteria

所呈现的工作引入了用于查找最优内核参数的进一步标准：效率标准描述了参数组合可以工作多长时间，直到需要从 GMEM 重新加载数据。效率标准基于内核源代码，根据给定的 1 到 3 号公式进行计算。

- 方程 1 描述了从 SMEM 加载数据的次数减去从 GMEM 加载数据的次数。
- 方程 2 描述了从 SMEM 读取数据与从 GMEM 加载数据相比的次数。
- 方程 3 描述了每个线程的工作负载大小。

方程 1 和 2 倾向于高 SMEM 消耗的组合。方程 3 倾向于方形字段，但尚未证明方形字段更好。

```
SMEM Access Difference (SMRW) = BLK.K * ((BLK.M / DIM.X) +(BLK.N / DIM.Y)) - BLK.K / DIM.YA * BLK.M / DIM.XA - BLK.N / DIM.YB * BLK.K / DIM.XB
(1)
```

```
SMEM Reuse (SMR) = BLK.K * ((BLK.M / DIM.X) + (BLK.N / DIM.Y)) / (BLK.K / DIM.YA * BLK.M / DIM.XA + BLK.N / DIM.YB * BLK.K / DIM.XB)
(2)
```

```
Work per Thread (WpT) = (BLK.M / DIM.X) * (BLK.N / DIM.Y)   (3)
```

由于效率标准和利用率标准定义的矛盾性，无法同时优化两者。效率标准将强制上下文，从而减少来自 GMEM 的重新加载操作，因此强制更高的资源消耗。另一方面，利用率标准将通过消耗较少的 SMEM 和 REG 资源来偏好上下文的较短工作时间。这项工作的方法是使用那些参数化配置用于随后的 SA 自动调谐步骤，该步骤强制在特定利用率级别上实现最高效率标准。这确保了在特定利用率级别上具有长寿命的上下文，同时遵循第 2.2 节中的延迟隐藏原则。鉴于这些假设，结果搜索空间减少到 84 个有意义的参数组合。

## 2.3 Simulated Annealing

模拟退火 (SA) 是一种在给定搜索空间中寻找最优参数组合的概率技术 - 该概念的详细概述在 [22] 中给出。对于我们的方法，SA 很合适，因为它能够忽略局部极小值并收敛到全局极小值。按不同标准对搜索空间进行排序，迫使将搜索空间中类似问题上运行时间相似的参数组合分组，从而加快 SA 的收敛速度。第 2.1 节中找到的参数组合根据其在 GPU 上实现的利用率进行排序，并在 SA 步骤中处理。应该注意的是，SA 的其他可能标准可能是第 2.1 节中的块大小 (BLK.M * BLK.N) 或主维度 (DIM.X)。

## 3 Performance Evaluation

所提工作的性能评估基于 NVIDIA Pascal GPU (MSI GeForce GTX 1080 Ti Aero 11G OC) 与搭载 Intel Xeon E5-1620 和 96 GB 内存的主机系统组合。操作系统是 Windows 64 位，NVIDIA 驱动程序版本为 390.65，CUDA 8。为了评估所提方法的性能，使用了不同的数据集 - 表 1 介绍了用于评估的不同矩阵形状。选择这些矩阵形状，是因为 cuBLAS 已被证明性能非常好。评估测试由三个矩阵 A、B 和 C 组成，格式分别为 M x K、K x N 和 M x N ∈ N。此外，为了说明所提方法的灵活性，还评估了几种其他矩阵形状。性能评估结果在图 1 和表 2 中显示。图 1 显示了相对于 cuBLAS 所取得的加速比，对应不同的矩阵形状。可以看出，N 越大，性能加速比越低。在最坏的情况下，所提方法的结果比高度优化的 cuBLAS 例程快 1.3 倍，在最好的情况下，加速比比 cuBLAS 快 187 倍。
