
需被构建 [22]。底层算法基于分析层次过程（Analytic Hierarchy Process，AHP）和模糊 TOPSIS 方法原理 [22]。采用了 AHP 方法来计算标准优先权重，而模糊 TOPSIS 用于评估和选择合适的（组合）数字辅助系统。

### 2.2 设备选择层

设备选择层代表技术数据库，包括硬件和创作软件解决方案。由于该主题的新颖性，我们只能接触到少数在 DAS（尤其是智能眼镜）实际实施方面有实践经验的从业者。出于此原因，我们决定通过系统文献综述和市场分析来提取功能。基于 ISO16290，市场上新兴技术的技术成熟度等级（Technology Readiness Level）已进行评级（参见图 1）。

## 3 案例研究：DAM 的解释性过程模型

为揭示所开发过程模型的功能，在 TU Wien 试点工厂工业 4.0 中开发了一个维护场景。迄今为止，通用机器人（UR5 实验室机器人）上的维护流程仅由专家执行。合适的 DAS 应指导工人逐步完成机器上的维护活动。基于所开发的选择模型（参见第 2 节），建议使用智能眼镜。所选用的底层软件工具称为 MO²GO，这是由弗劳恩霍夫生产系统与设计技术研究所 IPK 开发的过程建模工具。

![](img/a2f5eed6507498d886a06be86239344b_99_0.png)

图 5. 上下文感知型数字辅助系统的示意软件架构。

为建模业务流程，集成企业建模（Integrated Enterprise Modeling，IEM）方法于 20 世纪 90 年代在弗劳恩霍夫 IPK 开发 [23]。IEM 的应用支持对业务流程及其与企业描述元素（如组织、系统、产品或控制）的交互进行描述。它与 DIN EN ISO 19440 “企业集成 - 企业建模构造”兼容，并描述了四种可通过五种连接类型相互关联的元素类。表 1 显示了建模维护流程所需的一组元素类和连接类型。图形建模工具 MO²GO[24] 同样由弗劳恩霍夫 IPK 开发，非常适合建模维护流程，并构成了 DAS[25] 实施的基础。MO²GO 支持 XML（eXtensible Markup Language）交换格式，该格式适用于在不同应用程序之间交换数据。对于数字辅助系统的图形用户界面（GUI）中的流程步骤表示，MO²GO 提供一个接口，以将流程模型的 XML 格式作为 JavaScript 对象表示法提供。然后将元素及其连接转换为 JSON 格式，并由应用程序接口（API）解释，以在各个流程步骤期间链接资源、生成上下文敏感指令并在被维护系统上初始化支持功能。此 JSON 表示随后转换为可 Web 的 HTML5 格式，其中嵌入了 JavaScript 以实现人机交互。

## 4 结论与展望

所提出的方法可以作为支持维护流程的数字辅助解决方案战略评估的指导。结合所提议的过程建模工具，辅助系统可以提供所需信息以提高维护效率。由于所提议的方法目前是一个原型，它包含一些需要进一步研究的局限性。首先，底层决策层次结构基于专家的实验性知识，并且仅通过所提议的用例进行了验证。为了提高建议的质量，我们需要通过将所提议的方法应用于更多实际用例来收集反馈。其次，市场上 DAS 有关硬件和软件的关键信息是手动提取的。通过使用各种网络爬虫和网络分析技术，包括自动化文本和网络挖掘方法，可以从产品手册和专利文档等文档中动态提取信息，以识别现有产品和技术的关键特征。
