## (4) ILB 和 AES 移除攻击

从锁定网表中移除 ILB 和 AES 是困难的，因为：

*   (i) 插入设计中用于锁定的 ILB 连同 AES 块一起被重新合成。这种合成使得 AES 电路的每个组件连同基于 ILB 的锁定网表变得不可区分，攻击者无法将其移除。这是因为两个原因：(1) 首先，如前所述，插入网表的 ILB 结构子集由设计者根据与密钥对应的 AES 加密输出进行重新配置。因此，没有固定的 ILB 模板可用，ILB 的配置取决于 AES 输出，而 AES 输出又取决于密钥和 AES 的输入，从而产生多种可能的结构。此外，通过 AES 喂入 ILB 的密钥输入数量越多，可能性的数量也就越多。因此，在这种情况下，攻击者了解所有可能 ILB 的结构是不切实际的。(2) 其次，由于 Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 设计了他们自己的自定义轻量级 AES 架构，该架构未公开发布，后合成后 AES 结构的组件与 DSP 核心的锁定网表变得不可区分。

*   (ii) 用于生成 DSP 核心锁定网表的 ILB 排序取决于通过 PSO-DSE 过程探索的“μ”变量。因此，无法预先确定 ILB 配置。

## 8.6 用于 DSP 核心功能混淆的优化引擎

用于 DSP 核心的基于 ILB 的功能混淆方法 ([Sengupta *et al.*, 2018](#Chapter8.html#c08_bib35)) 使用 PSO-DSE 框架来实现 DSP IP 核心的低成本混淆网表。该方法中使用的 PSO-DSE 过程包含三个子过程，即粒子编码和初始化、评估粒子的适应度以及生成更优的粒子位置。
