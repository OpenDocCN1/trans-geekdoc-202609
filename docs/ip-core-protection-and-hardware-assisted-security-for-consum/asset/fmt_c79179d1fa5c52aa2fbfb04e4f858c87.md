##### 4.3.2.2 Watermarking process for DSP IP core

As an example, we have used single-phase watermarking approach presented in Sengupta *et al.* (2016) to demonstrate the design process. Watermark in DSP IP core can be embedded as additional design constraints in one of the HLS design phases. Sengupta *et al.* (2016) embed watermarking constraints in the register allocation phase of HLS. To embed additional constraints, a register allocation table is generated using the aid of CIG. In CIG, the nodes indicates the storage variables of the scheduled design, the edges indicates existence of overlapping of lifetime between two storage variables, and the color of the node indicates allocated register of that corresponding node. Therefore, if there is an edge between two storage variables (nodes) then the same register cannot be assigned between them. In other words, if there is an edge between two nodes, then the color of them must be different.

In Sengupta *et al.* (2016) and Koushanfar *et al.* ([2005](#Chapter4.html#c04_bib8)), watermarking constraints are added as supplementary edges between the nodes of a CIG. The color of the nodes are adjusted after embedding additional edges and the register allocation table of an IP core is generated from the final modified CIG. More specifically, inserting each edge as watermarking constraints, force two storage variables of a CIG to execute through distinct registers. Thus, embedding additional edges in a CIG affect the allocation of the register of a design. However, these additional edges should be derived from a vendor’s hidden signature. This mandates designer to design a strong signature encoding process. Sengupta *et al.* (2016) devised a multi-variable signature encoding scheme to embeds a robust watermark. Compared with the authors in Koushanfar *et al.* ([2005](#Chapter4.html#c04_bib8)), who have used two variables signature encoding scheme, a more robust and stronger signature encoding scheme is devised in Sengupta *et al.* (2016). The signature encoding scheme of Sengupta *et al.* (2016) is discussed in the rest of this section.

##### 4.3.2.3 Signature encoding scheme

A four variables signature encoding scheme is devised in Sengupta *et al.* (2016) where each variable indicates an encoded watermarking constraint. More specifically, each decoded signature digit inserts an additional edge between two nodes of a CIG as a watermarking constraint. An IP core owner can select his desired signature using any random combination of four variables, i.e., ‘`i`’, ‘`I`’, ‘`T`’, and ‘`!`’. The encoded rule of each variable is as follows:

*   ‘`i`’ = Add an additional edge between (prime, prime) node pair of CIG.

*   ‘`I`’ = Add an additional edge between (even, even) node pair of CIG.

*   ‘`T`’ = Add an additional edge between (odd, even) node pair of CIG.

*   ‘`!`’ = Add an additional edge between (0, any integer) node pair of CIG.

In Sengupta *et al.* (2016), as IP sellers signature is embedded based on multi-variable signature encoding scheme and distributed throughout the DSP design, it is harder for an adversary to detect and remove the complete watermark. Thus, provides significant robustness and stronger encoding.
