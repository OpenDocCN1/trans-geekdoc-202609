
# 智能医疗安全威胁与固件安全

智能医疗领域存在诸多安全威胁解决方案。由于智能医疗本身是一个不断发展的领域，许多研究人员致力于保障系统安全（[Ghoneim *et al.*, 2018](#Chapter2.html#c02_bib24); [He *et al.*, 2018](#Chapter2.html#c02_bib32); [Li *et al.*, 2011](#Chapter2.html#c02_bib47); [Rauf *et al.*, 2018](#Chapter2.html#c02_bib74); [Wang *et al.*, 2018](#Chapter2.html#c02_bib105); [Xiao *et al.*, 2018](#Chapter2.html#c02_bib108)）。上述章节中讨论的许多硬件辅助安全解决方案可部署于智能医疗设备，因为此类场景中的大多数组件此前已有讨论。数据窃听、隐私、安全及位置隐私问题，可通过采用更安全的加密通信措施来处理。但增加的安全模块会提高功耗并需要更多电池，这在智能设备（尤其是医疗设备）中是一个主要问题（[Sundaravadivel *et al.*, 2016](#Chapter2.html#c02_bib97); Yanambaka *et al.*, [2015](#Chapter2.html#c02_bib114), [2016](#Chapter2.html#c02_bib111)a, [2017](#Chapter2.html#c02_bib113)）。因此，此类应用应采用低功耗模块。

[Figure 2.47](#Chapter2.html#c02_fig47) 展示了胰岛素给药系统的安全方式（[Li *et al.*, 2011](#Chapter2.html#c02_bib47））。按时使用不同 PIN 码，可在不增加系统中已有安全模块的前提下提升系统安全性（[Alrabady and Mahmud, 2005](#Chapter2.html#c02_bib5)）。遥控器与胰岛素泵共享一个可加密的通信通道，以实现更好的安全措施。遥控器中有一个序列计数器，并使用密钥加密计数器生成的数值。当数据发送到泵时，计数器加 1，胰岛素泵将使用相同的密钥解密与泵共享的数值。遥控器与泵之间可能存在部分丢失信号，导致数值出现差异，但若差异过大，则可认为系统正受到攻击。采用滚动码技术后，攻击者将无法获取 PIN 码以发动攻击。但加密和解密算法应更加复杂，以防止攻击者读取 PIN 码。

## 2.8 Firmware

技术进步使我们能够设计出更小、更强大且具备网络功能的应用设备（[Mohanty, 2015](#Chapter2.html#c02_bib56); [Yanambaka *et al.*, 2015](#Chapter2.html#c02_bib114)）。这些设备催生了大量已成为我们生活不可或缺的一部分的应用。当设备具备网络功能后，攻击者便获得了进入全新攻击层级的机会。攻击者现在可以远程访问设备并发起攻击。当今所有嵌入式系统都配备固件。固件是嵌入硬件的软件，充当硬件与外部世界应用程序或操作系统（如有必要）之间的中间件。此固件不会像其他应用程序那样频繁更新。在更新固件时，可能会发生多种攻击，本节将对此进行讨论。

### 2.8.1 Firmware attacks

针对设备固件的攻击数量日益增多。设备的网络功能使其可从远程位置受到攻击。一旦固件遭到攻击，整个硬件可能被攻破。硬件可能被控制、被篡改，或导致数据丢失等，这些都是成功攻击的后果。攻击者还可能控制嵌入式系统，通过网络向许多其他设备或电子邮件发送垃圾信息（[Kaspersky, 2014](#Chapter2.html#c02_bib39)）。拒绝服务攻击是最常见的攻击之一（[Shila *et al.*, 2016](#Chapter2.html#c02_bib89)）。ThingBot 也可用于发起 DDoS 攻击，使服务器瘫痪（[Kaspersky, 2014](#Chapter2.html#c02_bib39)）。事实是，大多数此类攻击之所以可能，是因为固件及固件更新不安全、互联网 Web 接口安全性低、Web 应用程序不安全等（OWASP, 2018）。许多研究机构已针对固件及其更新中的安全缺陷开展工作（[Choi *et al.*, 2016](#Chapter2.html#c02_bib17); [Dacus and Yannakogeorgos, 2016](#Chapter2.html#c02_bib18); [Danese *et al.*, 2017](#Chapter2.html#c02_bib19); [Guin *et al.*, 2017](#Chapter2.html#c02_bib28)）。

固件攻击大致分为两种类型：静态攻击和动态攻击（[Figure 2.48](#Chapter2.html#c02_fig48)）。静态攻击是指在更新或修补过程中，攻击嵌入式系统内存中存在的固件。可通过在更新和修补软件时实施受信任环境来避免此类攻击（[Greene, 2016](#Chapter2.html#c02_bib26)）。但当系统固件遭受动态攻击时，使用此类环境将失效。

Figure 2.48 Firmware and attacks

在动态攻击中，攻击者会将控制流从固件转移到其注入的代码并执行。系统固件存在两种不同的动态攻击类型：代码复用和代码注入。在代码注入攻击中，顾名思义，攻击者会将自己的代码注入系统内存，并将控制流转移以执行恶意代码。数据执行防护（Data Execution Prevention）、堆栈金丝雀（Stack Canaries）等是保护硬件免受此类攻击的方法。在代码复用攻击中，攻击者会尝试通过改变控制流来执行内存中已存在的代码。这可能会危及整个系统的功能。各种代码片段或小工具（gadgets）可以组合，从而开发出新的任意逻辑（[Shila *et al.*, 2016](#Chapter2.html#c02_bib89)）。这使攻击者能够避免向系统注入任何新代码。

### 2.8.2 Firmware solutions

如上所述，正在开发许多用于固件安全的防御措施（[Choi *et al.*, 2016](#Chapter2.html#c02_bib17); [Dacus and Yannakogeorgos, 2016](#Chapter2.html#c02_bib18); [Danese *et al.*, 2017](#Chapter2.html#c02_bib19); [Guin *et al.*, 2017](#Chapter2.html#c02_bib28)）。常用的安全解决方案是地址空间布局随机化（Address Space Layout Randomization, ASLR），它会随机化数据和代码段的地址位置。这将使攻击者无法实施一些已讨论的攻击。[Figure 2.49](#Chapter2.html#c02_fig49) 展示了闪存编程协议的实现。在此过程中，微控制器与编程器之间使用开放通道（Soja, 2014）。此场景中使用 RSA 加密方案以确保安全。对于要加载到微控制器的软件镜像，使用 SHA-256 算法生成哈希值。哈希值在安全的离线环境中生成。将签名添加到哈希值中，用于标识软件的所有者。签名后的哈希值和软件镜像被传输到目标位置。
