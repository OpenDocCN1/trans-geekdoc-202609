
Proof-of-work was initially the decentralized consensus protocol that was proposed by the developer of blockchain, Satoshi, for the consistency and security of Bitcoin. As the transactions of the bitcoin blockchain, they require a consensus for the validation of blocks. There are different nodes in the network and several of them compete with each other to calculate the value of the newly added block. Once a node calculates the value of hash, it waits for the other nodes to complete and verify the values together. Then, the generated hash is added to the blockchain. If an appropriate solution is found by multiple nodes, then there may be multiple blocks generated in the network which can cause a temporary branch. In such scenarios, all of them are acceptable and nodes closer to the miners accept the solution they receive and forward the same to other peers. At any time, the longest chain is accepted by the users in the network. Proof of stake has been developed to avoid the issues of high-power consumption by Proof Of Work in bitcoin. Etherium uses the Proof of Stake as the consensus. In case of a POS, the cryptocurrency is bought and then used in the network which reduces the high-power consumption in calculating the hash.

## 2.9.4 Blockchain – issues

As discussed in this section, there are various advantages to blockchain technology. But there are also some disadvantages when comes to this and the main being scalability. There is also need of the entire blockchain, i.e., the entire list of all the transactions that happened till date for the consensus and validation. This requires huge amounts of storage capacity. Restriction of block size can decrease the entire problem of scalability. But this also decreases the speed of transactions and increases the fees of transaction. But with a high block size, the entire transaction can take very long to execute. Bitcoin-NG was proposed which has a reduced block size and increased security. This can be achieved by dividing the block into two different parts.

When a Fork is created in the blockchain, a long time should be waited to confirm which chain is the longest and correct branch by all the nodes. This can cause much higher delay to the entire transaction. There is also a 50% attack problem in the blockchain where 50% of the nodes can fake the block and also reverse the transactions. In this case, the power of computation holds all the power so legitimate users might face a problem. Power consumption of bitcoin miners is very high. To mine a bitcoin needs very high amount of computational power which can also increase the power consumption drastically. This can lead to the problem where investment can be higher than the return.

## 2.10 Conclusions

This chapter discussed different security flaws of the IoT devices and modules. Appropriate solutions were also presented for the security issues for each of the module. Still there are many security issues that need addressing. There can also be some zero-day vulnerabilities which are still yet to be found. The attackers who find the security flaws can take the advantage of them and need not share the flaw with the world. There may be many security flaws and vulnerabilities that are present but not known to the security community which are not addressed in the solutions. There is a vast scope of future research in this domain where security can be increased, and robust design is implemented in an IoT environment.
