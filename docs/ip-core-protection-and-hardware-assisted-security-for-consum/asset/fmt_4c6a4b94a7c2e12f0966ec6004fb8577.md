## 1.4.2 Different IP core protection and hardware-assisted security mechanisms: advantages and disadvantages

### 1.4.2.1 Hardware metering vs. hardware watermarking

In hardware watermarking, a secret signature is chosen which is implanted on the original design. In IP metering, a distinctive identifier (ID) is injected into the product for validating any unlicensed copy made. In case of watermarking, a design-inspection step is required during signature detection process. IP metering also includes a design-inspection step as the ID is accessible by reading some registers or trivial I/O access. Furthermore, implanting a watermark is certainly secure for cases of false claim of ownership or IP piracy as only the owner can evidently validate the enactment of a secret watermark. Similarly, IP metering is also effective for identifying the IP piracy and for reckoning the likely measure of piracy, which makes it extremely significant in court proceedings to endorse assessments of compensations.

Design-overhead may follow due to implanting a concealed signature in the original IP core, in case of hardware watermarking. This also depends on the type of signature selected and its size. But, in case of IP metering, the design-overhead is non-existent or nominal, as a trivial area of the IP-core is re-configured for each designed/manufactured hardware. IP metering only comprises modification in configuration in a tiny segment of the design.

In the context of DSP IP cores, watermarking techniques are mostly implanted before the RT level synthesis, i.e., as a pre-processing or during in-synthesis, i.e., signature is implanted during the execution of the high-level synthesis process. On the contrary, IP metering is generally executed post-layout or during manufacturing, through memory programming or indenting serial number on device body. During watermark, care should be exercised so that the signature insertion does not damage the functionality of the design and hampers its quality. There is a clear tradeoff in case of watermarking with respect to robustness vs. design overhead. In other words, larger size watermark is certainly more robust but may incur more design overhead. None of these parameters are present for metering ([Sengupta, 2015](#Chapter1.html#c01_bib20)).

### 1.4.2.2 Hardware obfuscation vs. hardware watermarking

Hardware obfuscation is completely different than hardware watermarking of IP core. In hardware obfuscation, the circuit description of the IP core is deliberately obscured either through encryption or by introducing unreadability in the circuit structure, so that the reverse engineering process becomes significantly harder. On the contrary, hardware watermarking introduces ownership information in a concealed manner within the IP core design itself, so that when required, legal ownership of the rightful owner can be proved. Although the threat models of both these protection mechanisms are slightly different, hardware watermarking can be used in unification with hardware obfuscation. In an obfuscated design, watermarking can be effective in providing a next line of defense against unlicensed copying efforts. Both these protection methods may incur design overhead, if not properly implanted/performed.

### 1.4.2.3 Computational forensic engineering vs. hardware watermarking

Computational forensic engineering for IP core protection employs a set of digital forensic evidences to infer the rightful owner. It is a signature-free approach, unlike hardware watermarking for IP core protection. Furthermore, as CFE does not employ signature for resolving IP ownership conflicts, it has zero chance of quality degradation on the original design. Additionally, no extra care is needed for CFE as it does not disturb the functionality of the design. Yet, the general process to execute CFE is more composite than watermarking as it warrants cognizance on the various phases of statistics collection, feature extraction, clustering, and validation. Thus, CFE incurs more time complexity when compared with watermarking in case of DSP IP cores.

## 1.4.3 HLS (architectural synthesis) as design backbone for implementing security algorithms for DSP IP cores

As DSP/multimedia IP cores depend on high level synthesis (HLS) design framework as its backbone, the security/protection algorithms are mostly in-synthesis by nature, i.e., the security constraints/techniques are performed during the high-level synthesis itself. Before reading the subsequent chapters that deal with the details of the security methodologies for DSP cores, it is important to review and study the high-level synthesis design process in this chapter itself.
