
## A. Pre-processing steps

1. Accept an original/non-watermarked DSP application in the form of CDFG with resource configuration as input.

2. Schedule the CDFG of DSP application based on the resource configuration (constraint).

3. Assign storage variable for each operation of the scheduled CDFG.

4. Construct the CIG to identify the minimal registers essential for register allocation.

5. Generate the register allocation table from the constructed CIG.

6. Sort storage variables in ascending order according to their number.

7. Accept an `n`-digit vendor’s signature as a combination of `‘i’`, `‘I’`, `‘T’`, and `‘!’` variables.

## B. Watermark embedding steps

1. Extract the decoded meaning of each signature digit based on encoded rule of each variable.

2. Construct a list of additional edge from the decoded value of vendor’s signature by traversing the sorted nodes.

3. Insert those additional edges in the CIG (constructed in pre-processing step 4) one by one as watermarking constraints and adjust the CIG if required.

4. After embedding all the additional edges in the CIG, modify the register allocation table (constructed in pre-processing step 5) based on the updated CIG.

After following the above steps, IP owner’s watermark gets embedded into the DSP IP core. The watermarking constraints are embedded into the register allocation phase of HLS. Each constraint forces two storage variables to be executed through a distinctive register. Thus, manipulates the register sharing which creates an impact on the final datapath of the IP core and its corresponding gate-level structure (netlist). Therefore, embedding this watermark retains the correctness and functionality of a DSP IP core.
