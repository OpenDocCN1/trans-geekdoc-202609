##### 3.4.1.2 木马安全方法—Sengupta 等人 ([2017a](#Chapter3.html#c03_bib26))

Sengupta 等人 ([2017a](#Chapter3.html#c03_bib26)) 提出了一种硬件木马安全感知方法，该方法能够检测 DSP 核心中的木马。它接受以数据流图 (DFG) 形式的非循环 DSP 应用程序、用户约束、细菌觅食优化算法 (BFOA) 控制参数（例如步长、趋化步数、消除-分散步数、复制步数、终止标准和种群大小）以及模块库。然后，它根据输入的 DSP 核心（以 DFG 形式提供）获得低成本的木马安全设计。

为了获得低成本的木马安全 DSP IP 核心，通过 BFOA 迭代探索由硬件架构配置和供应商分配模式组成的设计方案。该方法在细菌编码中使用变量 `M[v]` 探索最优的供应商分配过程。更具体地说，在此过程中，每个细菌都编码了特定资源类型的资源数量和供应商分配模式。每个细菌的编码可以表示为 `B = (R[n], M[v])`，其中 `R[n]` 表示硬件配置，`M[v]` 表示供应商分配模式。这里，供应商分配模式包括两种变体 (`M[v] = 0` 或 `1`)。在讨论供应商分配过程之前，让我们假设调度设计包括 DMR 逻辑，该逻辑由原始单元（表示为 `U^(OG)`）和重复单元（表示为 `U^(DP)`）组成。

`M[v] = 0` 时的供应商分配模式规则如下：

*   在特定单元（`U^(OG)` 或 `U^(DP)`）的每个控制步骤中，对相似类型的操作进行交替供应商分配。例如，如果在控制步骤 1 中有三个加法操作（opn.1、opn.2 和 opn.3），则 opn.1 和 opn.3 将分配给同一供应商的硬件，而 opn.2 将分配给另一供应商的硬件。

*   在另一个单元中，执行正交供应商分配以保持区别性。换句话说，两个单元中的相同操作必须分配给不同的供应商。例如，如果在 `U^(OG)` 中，opn.1 和 opn.3 分配给供应商类型 1 (V1) 的硬件，opn.2 分配给供应商类型 2 (V2) 的硬件，那么在 `U^(DP)` 中，opn.1 和 opn.3 必须分配给 V2 的硬件，opn.2 必须分配给 V1 的硬件。

`M[v] = 1` 时的供应商分配模式规则如下：

*   特定单元（`U^(OG)` 或 `U^(DP)`）的所有操作必须分配给同一供应商的硬件。例如，`U^(OG)` 的所有操作必须分配给 V1 的硬件。

*   两个单元中相似的操作必须分配给不同的供应商。例如，如果 `U^(OG)` 的所有操作都分配给 V1 的硬件，那么 `U^(DP)` 的所有操作必须分配给 V2 的硬件，反之亦然。

该方法的通用概述如 [图 3.12](#Chapter3.html#c03_fig12) 所示。虽然该方法能够处理非循环 DSP 应用程序 HLS 过程中的硬件木马，但它没有提供处理基于循环的 CDFG DSP 核心的任何过程。

##### 3.4.1.3 木马安全方法—Sengupta 等人 ([2017b](#Chapter3.html#c03_bib27))

Sengupta 等人 ([2017b](#Chapter3.html#c03_bib27)) 在其提出的硬件木马安全感知方法中克服了上述缺陷。该方法能够接受以 CDFG 形式的单循环 DSP 应用程序、用户约束、最大循环迭代次数 (`I`)、PSO 控制参数（例如惯性权重、认知因子和社会因子）以及模块库。它最终输出低成本的木马安全感知 DSP RTL 设计。

该方法通过在用户指定的设计约束内进行基于 PSO 的 DSE 过程来获得低成本设计方案（PSO-DSE 方法的详细信息见第 3.6.3.1 节）。PSO-DSE 每次迭代中的设计方案不仅包含硬件配置和供应商分配模式，还包含循环展开因子，这是基于循环的 CDFG 的关键设计参数。此外，在此方法中，不是在所有可能的展开因子值中搜索，而是通过预处理算法（如 [图 3.13(a)](#Chapter3.html#c03_fig13a) 所示）获得一组选定的展开因子。预处理算法的输入是最大循环迭代次数，输出是筛选后的展开因子列表。算法的工作原理如下：顺序执行次数较多的展开因子以及那些在没有显著提高性能的情况下增加代码复杂度的展开因子，不包括在筛选列表中。这是因为顺序执行次数增加会导致延迟开销，而代码复杂度增加会导致更高的面积/功耗。此外，较大的展开因子并不总是性能的单调递增函数。例如，FIR 滤波器的预处理算法输出如 [表 3.1](#Chapter3.html#c03_tbl1) 所示。FIR 滤波器的 C 代码和 CDFG 在第 3.6.1.3 节 ([Sengupta and Bhadauria, 2015](#Chapter3.html#c03_bib22)) 中描述。

##### 3.4.1.4 木马安全方法—Sengupta 等人 ([2017c](#Chapter3.html#c03_bib28))

Sengupta 等人 ([2017c](#Chapter3.html#c03_bib28)) 在其提出的硬件木马安全感知方法中克服了上述缺陷。该方法能够接受以 CDFG 形式的嵌套循环 DSP 应用程序、用户约束、所有嵌套循环的最大循环迭代次数 (`I[1]`、`I[2]`、… `I[n]`)、PSO 控制参数（例如惯性权重、认知因子和社会因子）以及模块库，最终输出低成本的木马安全 DSP RTL 设计。
