
Various encryption modules are available for the smart vehicles as shown in [Figure 2.38](#Chapter2.html#c02_fig38) and [2.39](#Chapter2.html#c02_fig39) (Freescale, 2013). A cryptographic services engine is shown in [Figure 2.38](#Chapter2.html#c02_fig38), which implements the encryption of the flash modules and prevents the access to other blocks or attackers. A secure communication can be made possible between the components using the ECU and master ECU. A random number is generated and is sent to the central ECU immediately when the car is turned on. Then, the sensor will collect the data and send to the sensor ECU which are encrypted by the CSE module with the random number generated. The central ECU then receives the message that is secured by the CSE. Then, the central ECU will decrypt the message using the CSE that is present in central ECU and receives the message.

## 2.6.2 UAV or drone security

There are many different types of UAV and drones. Drones and UAVs are used in various applications of day-to-day life from military grade to home grade (UAV, [https://www.theuav.com/](https://www.theuav.com/)). These applications are designed to reduce human interaction in dangerous situations such as hostile areas and also to increase efficiency in day-to-day applications. But the drones and UAVs are susceptible to many different attacks like other smart vehicles as discussed in the previous sections. This section describes different security threats for Drones and UAVs and security measures that can protect against them.

### 2.6.2.1 UAV security attacks

The illustration of an UAV with selected components and attached is presented in [Figure 2.40](#Chapter2.html#c02_fig40). There are various parts of an UAV that are connected to the network or a satellite that can be used to breach the security and take control of the UAV. Communications protocol connects to the satellite to receive and send data to the base station, GPS module communicates with the GPS satellites. The different logic components that are necessary for computations are shown in [Figure 2.40](#Chapter2.html#c02_fig40). The control systems and security modules are shown in [Figure 2.40](#Chapter2.html#c02_fig40).

![image](OEBPS/images/PBCS0600-02-f40.jpg)

Figure 2.40 UAV security – a big picture

Many of these components are vulnerable to various attacks originated from a computer. So the attacks can be originated from a remote source and the attacker need not be near to the devices while attacking. Different actions can be performed by the attacker like:

*   Change the control rates by performing a distributed DoS (DDoS) attack.
*   The data that is being collected from the sensors can be modified which can make the flight dangerous.
*   The data from the drone can be analyzed for any design flaws that can be taken advantage of in a later attack.

The attacks that can be performed on a UAV can be broadly classified into two categories: integrity attacks and denial of service attacks ([Sedjelmaci *et al.*, 2017](#Chapter2.html#c02_bib79)). The integrity attacks compromise the functionality of the vehicle by changing and sending a false information. [Figure 2.41](#Chapter2.html#c02_fig41) shows different types of attacks on a UAV. GPS spoofing is a common attack that can be performed on the UAVs receiver which can send the vehicle false coordinates which can make the flight difficult. By performing this attack, the UAV can be led to believe it is in a different location than the original location. Such attacks are performed and vehicles were compromised because of this attack ([Shepard *et al.*, 2012](#Chapter2.html#c02_bib87)). But to perform the attack the spoof signal should be aligned precisely with the original signal and increase the strength of the spoofing signal gradually to control the target. After gaining control, the counterfeit signal can be moved away from the original signal which controls the drone ([Nighswander *et al.*, 2012](#Chapter2.html#c02_bib62); [Shepard and Humphreys, 2011](#Chapter2.html#c02_bib88)). Detecting this attack by the drone is highly difficult as the drone’s navigation system will not raise any alarm when this attack is being performed.

![image](OEBPS/images/PBCS0600-02-f41.jpg)

Figure 2.41 Security attacks on a UAV

UAVs can also be attacked by similar UAVs which can lead to the authentic vehicle transmitting falsified data to the receiver. A counterfeit UAV can be used to communicate with an authentic vehicle and send false data. The authentic vehicle then communicates the falsified data to the base station which can be catastrophic in some conditions. This is called the injection attack. The position of the UAV and other collision avoidance systems are handled by the ADS-B controller which is present on the UAV ([Sedjelmaci *et al.*, 2016](#Chapter2.html#c02_bib80)). These can be taken advantage by the attacker to perform an ADS-B attack that will send false position data to the system. This is called spoofing attack.

Another common attack that can be performed on the UAV is the denial of service attacks. This can be performed by sending huge packets of data which will disrupt the communications of the UAV rendering it useless. Jamming, gray hole, and black hole attacks are some of the DoS attacks. Jamming will jam the communications to the base station which can make it loose control and block any new commands. A gray hole and black hole attacks will initialize a node which can lure the UAV into sending the data and forward the data to the server, but then drop all the data or steal it when received at the node.

Security of a UAV can be increased but with the increase of security there can be many issues as shown in [Figure 2.42](#Chapter2.html#c02_fig42). With added security modules, the weight of the entire UAV increases. When it comes to the aerial vehicles, weight plays a major role in the flight to destination. With an added weight, the aerodynamics are changed. With more components added to the system, more battery consumption is a major issue. With the more battery added, again it loops back to the aerodynamics.
