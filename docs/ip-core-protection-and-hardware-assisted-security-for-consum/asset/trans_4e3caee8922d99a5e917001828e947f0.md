与 JPEG 压缩类似，在 DFG 调度期间，使用相同的资源配置。数据路径单元中使用相同数量的组件，即三个加法器和 16 位乘法器、十个 32:1 类型的多路复用器、两个 16:1 类型的多路复用器、五个 1:32 类型的解多路复用器、一个 1:16 类型的解多路复用器、四十个 16 位寄存器和 18 个锁存器。与 JPEG 压缩 IP 核心类似，JPEG 解压缩 IP 核心的数据路径和控制器也使用 Quartus CAD 工具在 Intel Cyclone II ([Cyclone II FPGA, 2018](#Chapter9.html#c09_bib8)) FPGA 上实现。

### 9.4.3 通过设计的硬件/IP 核心实现端到端 JPEG CODEC

在本节中，我们讨论通过所设计的 JPEG IP 核心实现的端到端 JPEG CODEC 过程。此讨论分为三个部分。在第一部分中，我们通过一个示例讨论从输入图像到生成量化图像的图像压缩的每个步骤。在第二部分中，我们通过一个示例介绍使用 RLE 算法的数据编码和解码过程。在最后一部分中，我们通过另一个示例讨论从去量化图像到生成压缩后重建图像像素的图像解压缩的每个步骤。

从“标准 512 × 512 灰度测试图像数据集”([Standard dataset, 2018](#Chapter9.html#c09_bib9)) 中选取的一张 512 × 512 灰度图像作为输入图像。输入图像如 [图 9.16](#Chapter9.html#c09_fig16)(a) 所示。为了对输入图像执行 DCT，从输入图像形成多个平整化的非重叠 8 × 8 图像像素块。在多个非重叠 8 × 8 块中，输入图像的一个随机选择的块如 [图 9.16](#Chapter9.html#c09_fig16)(b) 所示。该块（包含 64 个像素值）作为所设计的混淆 JPEG 压缩 IP 核心（如 [图 9.16](#Chapter9.html#c09_fig16)(c) 所示）的主要输入之一。混淆 JPEG 压缩 IP 核心的设计过程在 9.4.1 节中讨论。所设计的 IP 核心对输入块执行 DCT 和量化，并生成变换和量化后的图像作为输出。在此示例中，我们基于质量级别 90 执行压缩，即使用量化矩阵 `Q[90]`。此过程重复执行，直到输入图像的所有 8 × 8 块都被变换和量化。生成的变换和量化后的图像如 [图 9.16](#Chapter9.html#c09_fig16)(d) 所示。

![image](OEBPS/images/PBCS0600-09-f16.jpg)

图 9.16. 通过压缩 IP 核心进行 JPEG 压缩的示例

数据编码（一种无损数据压缩形式）在将像素数据存储到存储设备之前，对每个量化块执行。它涉及将量化块的数据按“之字形”排列，然后对其应用 RLE 算法。[图 9.17](#Chapter9.html#c09_fig17)(a) 显示与输入图像块（如 [图 9.16](#Chapter9.html#c09_fig16)(b) 所示）对应的量化块。对量化块执行之字形扫描（之字形扫描的格式如 [图 9.17](#Chapter9.html#c09_fig17)(b) 所示），输出如 [图 9.17](#Chapter9.html#c09_fig17)(c) 所示。按之字形排序的量化数据通过 RLE 算法进行编码。RLE 将 `每个非零交流系数` 值替换为一对 (RUNLENGTH, AMPLITUDE)，其中“RUNLENGTH”是该非零交流系数之前出现的 `零的数量`，“AMPLITUDE”是该特定非零系数的值。使用 RLE 编码的量化数据版本如 [图 9.17](#Chapter9.html#c09_fig17)(d) 所示，其中 (0, 0) 始终表示块的结束。RLE 编码数据的一维数组中的其余元素（从 64 个可用插槽中）不存储，因为它们全是零。（注意：矩阵的第一个值，即 16 是直流系数；它不通过 RLE 编码。）这些编码值中的每个都转换为其等效的二进制形式，以生成块的相应比特流，然后存储在存储设备中。要从比特流数据重新生成量化块，需要执行解码。为了实现数据解码，上述所有步骤都必须按相反顺序执行。因此，在从 RLE 编码数据获取（解码）一维数组时，64 个元素（8 × 8 块）中的空闲插槽会用零填充。执行反之字形扫描以获取量化块的 8 × 8 块的二维数组。

![image](OEBPS/images/PBCS0600-09-f17.jpg)

图 9.17. 通过 RLE 算法进行数据编码的示例

要从变换和量化形式重建图像，每个块都使用压缩时使用的相同量化矩阵进行去量化。如本示例中，我们使用量化矩阵 `Q[90,]` 执行压缩，因此去量化（反量化）仅基于量化矩阵 `Q[90]` 执行。生成的去量化图像如 [图 9.18](#Chapter9.html#c09_fig18)(a) 所示。包含 64 个像素值的 8 × 8 去量化块作为所设计的混淆 JPEG 解压缩 IP 核心（如 [图 9.18](#Chapter9.html#c09_fig18)(b) 所示）的主要输入之一。混淆 JPEG 解压缩 IP 核心的设计过程在 9.4.2 节中讨论。所设计的 IP 核心对去量化块执行 IDCT 和平整化，并生成 8 × 8 解压缩图像像素强度值作为输出。相同 8 × 8 块（如 [图 9.16](#Chapter9.html#c09_fig16)(b) 所示）的相应解压缩图像像素强度如 [图 9.18](#Chapter9.html#c09_fig18)(c) 所示。同样，此过程重复执行，直到所有 8 × 8 去量化块都被反向变换和平整化。最后，通过组合所有 8 × 8 反向变换和平整化的块生成压缩后的重建图像。相应输入图像（如 [图 9.16](#Chapter9.html#c09_fig16)(a) 所示）的重建图像如 [图 9.18](#Chapter9.html#c09_fig18)(d) 所示。
