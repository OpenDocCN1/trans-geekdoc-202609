

典型的 HLS 设计流程接受以 C 代码形式呈现的 DSP 应用程序，并通过解析将其转换为一种称为控制数据流图（CDFG）的图形表示。除了该应用程序外，HLS 还接受用于设计评估的基于模块的技术库。技术库信息基于特定的技术节点，包含单个模块的硅面积、延迟、功耗等详细信息。一旦解析 C 代码后获得控制数据流图（CDFG），它将经历一系列变换以将其转换为优化形式。这些变换可以是编译器驱动或布尔函数驱动的。优化后的 CDFG 接受 HLS pragmas/directives，以将信息传递给 HLS 中的 DSE 系统。DSE 系统的第一步是操作调度，它还接受其自己的一组 HLS pragmas/directives 以及调度配置，为每个操作分配时间（周期）时间戳。此步骤中的指令示例包括链接、多周期、数据流水线、功能流水线、循环展开等。随后是资源分配和绑定阶段，它也接受其自己的一组指令，用于对功能资源执行空间约束。绑定使多个操作能够共享/重用功能硬件资源。随后，通过其自己的一组 HLS 指令执行寄存器分配，以获得在硬件中实现应用程序所需的最优寄存器集数量。这些阶段完成后，通过分析 I/O 连接性、多路复用器、解多路复用器等，基于获得的数据路径来执行数据路径的确定，并确定控制路径生成的时序。这得出了每个硬件资源的逐周期执行详细信息。数据路径和控制器都用硬件描述语言（HDL）描述，并最终集成以形成 DSP/多媒体应用程序的 RTL 系统示意图/HDL 描述。由于 DSP IP 核心的安全算法/功能在一个或多个 HLS 综合步骤中集成，因此理解 HLS 设计框架至关重要。有关 HLS 设计过程的更多详细信息可在 [Sengupta 和 Mohanty (2016)](#Chapter1.html#c01_bib23) 中找到。

## 1.5 硬件辅助媒体保护

CE 系统可能面临的所有权、版权或知识产权（IPR）概念如 [Figure 1.9](#Chapter1.html#c01_fig9) 所示。就所有权而言，硬件、软件、整个 CE 系统或媒体盗版的共同因素是实际或合法所有者的收入损失。但是，这些所有权问题/攻击各不相同，相应部署的解决方案可能有所不同。先前章节已讨论了由硬件盗版导致的硬件 IP 核心保护方面的问题。总体而言，系统盗版或克隆也是 CE 领域的一个问题，因此黑市上有许多假冒的 CE 系统，例如相机、USB 驱动器、智能汽车硬件组件、假电池等。这些可能很便宜，用户可能认为自己买到了好货，却不知道这些会带来许多错误的影响。例如，克隆/假冒硬件可能为使用此类硬件的 CE 系统提供后门入口。想象一下智能汽车的情况，黑客通过这个后门可以访问智能汽车并控制它。这可能导致致命后果，例如，攻击者/黑客可以制造事故。同样，假冒/克隆电池可能对 CE 系统构成安全隐患，因为劣质电池可能会爆炸并起火，互联网上有许多此类案例场景的示例。使用盗版软件也可能为黑客提供潜在的后门以控制系统。每个 CE 系统在其活动状态的每一秒都处理数据、信息、视频、音频和游戏 ([Mohanty, 2017a](#Chapter1.html#c01_bib11), [2017b](#Chapter1.html#c01_bib12))。估计传感器、社交网络、网页、图像和视频应用以及移动设备每天产生超过 2.5 百万亿字节（即 10^(18) 字节）的数据 ([Mohanty *et al.*, 2016](#Chapter1.html#c01_bib15))。随着世界各地智慧城市计划的兴起，这种情况将更加复杂，其中拥有数十亿台连接设备的 IoT 全天候处理数据。有句名言说得好：`it is not oil rather it is data that is the new gold`。在媒体盗版方面，视频和音频对娱乐行业、在线流媒体公司及各相关行业的收入损失产生影响。在与所有权相关的章节中，将介绍媒体保护的硬件辅助解决方案。基于软件和基于硬件的解决方案均有可能，但硬件在实时性能以及从源端到消费端的保护方面具有优势。

## 1.6 物理不可克隆函数

大多数安全、隐私和知识产权解决方案都基于某种形式的加密、混淆、哈希和水印，这是事实。这些机制依赖于某种形式的随机数或伪随机数。通用处理器是一种确定性机器，根据程序计数器计算下一条指令，无法生成真随机数，这也是事实。此外，随机/伪随机数密钥通常存储在内存或驱动器中以备将来使用。黑客攻击系统只是时间问题，黑客有可能访问系统及其包含的信息。原始 PUF 硬件会即时生成随机数，如 [Figure 1.10](#Chapter1.html#c01_fig10) 所示，并完全消除了在硬盘上存储密钥的需求，从而使其安全 ([Yanambaka *et al.*, 2017](#Chapter1.html#c01_bib30), [2018](#Chapter1.html#c01_bib31); [Joshi *et al.*, 2017](#Chapter1.html#c01_bib7))。PUF 依赖于 IC 物理层面的变化，这些变化源于纳米级半导体制造。因此，PUF 很好地利用了工艺变化，而不是设计师试图减少工艺变化对 IC 的影响。特定 PUF 生成的输出是唯一的，因此充当其签名。PUF 章节将讨论 PUF 原理、各种类型的 PUF 以及 PUF 应用等主题。
