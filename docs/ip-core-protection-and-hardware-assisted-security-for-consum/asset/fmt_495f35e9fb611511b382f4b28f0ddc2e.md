The robustness of obfuscated JPEG CODEC IP core is measured through SoO metric, a higher SoO value indicates stronger robustness in the range of [0, 1]. The more a design differs from its original structure the harder it will be for an attacker to identify the application through RE. Therefore, insertion of any malicious logic in the IP design or performing IP piracy is extremely difficult without knowing the actual functionality of the application. The structural obfuscation is obtained using THT which is responsible for obfuscating the original design of JPEG CODEC by transforming the height of the data flow graph representing the JPEG CODEC, thus modifying the nodes in the DFG of the JPEG CODEC. Modification of a node in a DFG indicates whether, (1) the source/parents of a node is changed; (2) the child of a node is changed; or (3) operation type of a node is changed, compared to the original. The effect of modification of nodes is also reflected in the gate structure/netlist of the design. According to the results shown in [Table 9.4](#Chapter9.html#c09_tbl4), more than 10,000 gates are affected due to the modification of nodes in the DFG of the JPEG CODEC. This is achieved due to the transformation in gate-level architecture of functional resources, multiplexers, demultiplexers, and registers. This enormous transformation in gate-level architecture of the complete JPEG CODEC IP core makes it an unobvious structure. Therefore, identifying the correct functionality of this unobvious structure is extremely complex and tedious for an attacker.
