

# MESA 基准测试的 DFG 演示

MESA 基准测试的 DFG 用于演示目的。此外，提供了两个加法器和三个乘法器作为资源配置。使用上述资源配置的 MESA 基准测试的调度 DFG 如 [图 5.5](#Chapter5.html#c05_fig5) 所示。该设计中未嵌入任何签名约束。相同调度的表格表示如 [表 5.1](#Chapter5.html#c05_tbl1) 所示。

现在，假设提供了一个 7 位买方签名：`‘AAABACC’`。然后对买方提供的签名进行解码。签名及其相应的解码约束如 [表 5.2](#Chapter5.html#c05_tbl2) 所示。解码约束是根据第 5.3.E 节中描述的指纹编码规则获得的。

现在，MESA 基准测试的 DFG 需要基于带有指纹约束的资源配置进行调度。在 `cs 1` 中，四个乘法操作，即 `opn 1`、`opn 2`、`opn 3` 和 `opn 4`，已准备好进行调度，但只有三个乘法器单元。这会产生调度操作冲突情况。可以通过在调度阶段插入解码的指纹约束来解决此冲突。例如，第一个数字 `‘A’` 强制偶数乘法操作，即 `opn 2`，进入奇数 `CS`，即 `cs 1`，同时解决调度冲突。同样，下一个数字 `‘A’` 强制乘法 `opn 4` 在奇数 `cs 1` 中，同时解决调度冲突。对于第三个数字 `‘A’`，没有可用的偶数操作进行调度；因此，通过从排序列表中选择第一个操作，将下一个乘法操作安排在 `cs 1` 中。因此，选择 `opn 1` 并安排在 `cs 1` 中。同样，对于第四个数字 `‘B’`，奇数操作，即 `opn 5`，被安排在偶数 `cs 2` 中，同时解决调度冲突。进一步，偶数操作，即 `opn 6`，被安排在奇数 `cs 3` 中，用于数字 `‘A’` 的指纹编码。调度中的此类指纹约束植入机制将一直运行，直到所有操作冲突解决完成。嵌入买方指纹后的最终调度如 [表 5.3](#Chapter5.html#c05_tbl3) 所示。

可以从 [表 5.1](#Chapter5.html#c05_tbl1)（未嵌入约束）和 [表 5.3](#Chapter5.html#c05_tbl3)（带有指纹约束）中观察到，两个调度设计具有相同数量的 `CS` 和相同的资源配置。因此，买方指纹在设计中被植入，完全没有面积开销和延迟开销，且不改变功能。

# 5.5 DSP 核心案例研究分析

Roy 和 Sengupta ([2017](#Chapter5.html#c05_bib32)) 的对称 IP 核心保护机制生成了低开销的高度安全 DSP IP 核心设计。为了验证鲁棒性和低开销，Roy 和 Sengupta ([2017](#Chapter5.html#c05_bib32)) 使用了以下指标：

*   在设计中植入两个签名的成本，表示设计质量。
*   植入指纹和水印时，相对于资源和所需额外寄存器的面积开销。
*   生成签名所消耗的时间。
*   签名在重合概率方面的强度。
*   大尺寸指纹和水印对设计面积、设计延迟和植入成本的影响。
*   处理更大尺寸应用的可扩展性。

因此，分析/案例研究部分分为以下几部分：(i) 对称 IP 核心保护方法（[Roy *et al.*, 2008](#Chapter5.html#c05_bib10)）在设计延迟、设计面积、嵌入成本和签名强度方面的结果，以及 (ii) Roy *et al.* ([2008](#Chapter5.html#c05_bib10)) 与非对称 IP 核心保护方法（[Koushanfar *et al.*, 2005](#Chapter5.html#c05_bib18））之间的比较研究。（注：对于 DSP 核心，不存在对称 IP 核心保护方法。）
