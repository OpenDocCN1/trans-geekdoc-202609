

# 七变量签名编码方案

七变量签名编码方案在 Sengupta *et al.* ([2018](#Chapter4.html#c04_bib22)) 中被设计出来，其中每个变量在综合过程的三个阶段（调度、硬件分配和寄存器分配）中的任何一个阶段嵌入解码的水印约束。更具体地说，每个解码的签名数字通过修改上述表格中的任何一个来插入水印约束。IP 所有者可以使用这七个变量的任何随机组合来选择所需的签名，即，‘`α`’、‘`β`’、‘`γ`’、‘`i`’、‘`I`’、‘`T`’ 和 ‘`!`’。每个变量的编码规则如下：

*   ‘`γ`’ = 将非关键路径中移动性最高的操作移动/移位到紧随其后的控制步骤 (`cs`)。

*   ‘`α`’ = *仅在奇数控制步骤中*：偶数操作必须分配给供应商类型 2 (`U2`) 的硬件，奇数操作必须分配给供应商类型 1 (`U1`) 的硬件。

*   ‘`β`’ = *仅在偶数控制步骤中*：偶数操作必须分配给供应商类型 1 (`U1`) 的硬件，奇数操作必须分配给供应商类型 2 (`U2`) 的硬件。

*   ‘`i`’ = 在 CIG 的 (`prime`, `prime`) 节点对之间添加一条额外边。

*   ‘`I`’ = 在 CIG 的 (`even`, `even`) 节点对之间添加一条额外边。

*   ‘`T`’ = 在 CIG 的 (`odd`, `even`) 节点对之间添加一条额外边。

*   ‘`!`’ = 在 CIG 的 (`0`, any integer) 节点对之间添加一条额外边。

在 Sengupta *et al.* ([2018](#Chapter4.html#c04_bib22)) 中，第 3 阶段水印变量，即 ‘`i`’、‘`I`’、‘`T`’ 和 ‘`!`’ 既独立于第 1 阶段水印变量 ‘`γ`’，也独立于第 2 阶段水印变量 ‘`α`’ 和 ‘`β`’。同样，第 1 阶段的水印变量也独立于第 2 阶段和第 3 阶段的水印变量。这些优势使得三阶段水印方法对对手来说异常强健且具有抗篡改性。然而，第 2 阶段的水印变量依赖于第 1 阶段的水印变量。因此，由于第 1 阶段水印的更改，第 2 阶段的水印约束可能会受到影响，这是该方法的一个局限性。尽管如此，如前所述，对手要检测第 1 阶段水印是在综合的哪个步骤中植入的以及如何植入的，是极其困难的。此外，如果第 1 阶段水印以某种方式被攻击者篡改，那么第 3 阶段水印约束（独立于第 1 阶段和第 2 阶段水印）仍然能够解决所有权冲突并识别真正的 IP 核心所有者。因此，三阶段水印提供了一种强抗篡改的水印 IP 核心设计。

## 4.3.3.2 水印嵌入过程

在前一小节中，我们讨论了三阶段水印七个变量的编码规则。在本小节中，我们将讨论如何在未加水印的 IP 设计中嵌入三阶段水印。三阶段水印嵌入过程分为四个部分，即预处理步骤、第 1 阶段水印嵌入步骤、第 2 阶段水印嵌入步骤和第 3 阶段水印嵌入步骤。该水印过程的详细步骤如下 ([Sengupta *et al.*, 2018](#Chapter4.html#c04_bib22))：

### A. 预处理步骤

1. 接受一个未加水印的 DSP 应用程序作为 CDFG，并根据用户资源配置对其进行调度。

2. 执行功能单元分配和寄存器分配。

3. 从未加水印的 IP 核心设计中构建“非关键操作 (`μ`[`m`] > 0)”的时序表、“功能单元分配”表和“寄存器分配”表。

4. 根据操作编号的递增顺序，按控制步骤对操作进行排序。

5. 接受一个 `n` 位供应商签名，作为 ‘`α`’、‘`β`’、‘`γ`’、‘`i`’、‘`I`’、‘`T`’ 和 ‘`!`’ 变量的组合。

### B. 第 1 阶段水印嵌入步骤

1. 对于每个出现的 ‘`γ`’，将非关键路径的一个操作移动到其紧随其后的控制步骤，同时从控制步骤 1 开始检查（不重复出现），如果满足以下两个条件：

    * (`i`) 相应操作在紧随其后的控制步骤中没有任何子操作。

    * (`ii`) 移位不违反硬件资源约束。

        (*注：如果多个操作有资格在下一个控制步骤中移位，则将优先给予移动性最高的操作*)。

2. 在嵌入所有 ‘`γ`’ 变量后，调整“非关键操作 (`μ`[`m`] > 0)”的时序表。

### C. 第 2 阶段水印嵌入步骤

1. 接受嵌入了第 1 阶段水印的调度设计作为输入，以嵌入第 2 阶段水印。

2. 对于供应商签名中每个出现的 ‘`α`’ 和/或 ‘`β`’ 变量，需要根据 ‘`α`’ 和 ‘`β`’ 的编码规则执行功能单元的重新分配。

3. 在嵌入所有 ‘`α`’ 和 ‘`β`’ 变量后，修改“功能单元分配”表。

### D. 第 3 阶段水印嵌入步骤

1. 接受双阶段（第 1 阶段和第 2 阶段）水印嵌入的设计作为输入，以嵌入第 3 阶段水印。

2. 其余步骤与单阶段水印嵌入步骤 B.1–B.4 相似（参阅第 4.3.B 节）。

## 4.3.3.3 签名检测过程

签名检测过程是解决所有权冲突的关键且必不可少的步骤。检测三阶段水印所需的输入为：(a) 解码的供应商签名，(b) 应用程序，以及 (c) 控制器和数据路径 HDL 形式的加水印 IP 核心。三阶段水印可以在三个步骤中完成，每个步骤验证每个阶段水印约束的存在。在第 1 阶段水印的签名检测和验证过程中，从解码的签名中提取修改操作的控制步骤，然后将其与加水印 IP 的控制器 HDL 进行比较。为了检测和验证第 2 阶段水印，从解码的签名中提取加水印操作的分配硬件，然后借助原始应用程序及其相应的输入进行识别。然后，将从解码水印中获取的加水印硬件信息与加水印 IP 的数据路径 HDL 进行比较。同样，为了检测和验证第 3 阶段水印，应从加水印 IP 的数据路径 HDL 中获取每个多路复用器的共享输入。然后将其与从解码签名中提取的第 3 阶段水印约束进行比较。如果解码签名的所有约束都在加水印 IP 核心中可用，那么提供解码签名的供应商将被授予该 IP 核心的原始所有者。三阶段水印的完整签名检测过程如 [Figure 4.26](#Chapter4.html#c04_fig26) 所示。
