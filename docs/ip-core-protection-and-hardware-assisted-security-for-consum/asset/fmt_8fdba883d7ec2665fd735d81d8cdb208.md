
The previous section presented a ring oscillator PUF and different designs which can be implemented in various applications. Some of the designs that are presented in the previous section are reconfigurable but the others generate a constant set of CRPs and the design itself is not reconfigurable. This section concentrates on the reconfigurability of the PUF design. Reconfigurability is an important aspect of PUF design. There is a chance that if the attacker gets hold of the device and perform attacks such as machine learning, emulation, man-in-the-middle and RE, he/she will be able to regenerate the CRPs. The reconfigurable or dynamic PUFs are introduced in order to increase the security of PUF against these attacks and to be able to generate new set of CRPs when necessary. A feed-forward structure is introduced in the arbiter PUF to avoid the attacks using linear modeling. This introduces some nonlinearity in the design and increases the security and robustness of the design trading-off the design complexity. This can also be achieved using other techniques like preprocessing the challenge input before feeding it to the PUF, postprocessing the output response from the PUF, and adding some components to the output of module which can be used for reconfiguring the response bits. The preprocessing challenge bits can be done by introducing an additional circuitry which can implement linear feedback shift register (`LFSR`) or by introducing some hashing. The postprocessing of response bits can mean the introduction of hashing to the bits. [Figure 12.10](#Chapter12.html#c12_fig10) shows the design of arbiter PUF with an `LFSR` at the input. The challenge inputs given to the PUF are not directly fed to the arbiter PUF. Initially they are passed through the `LSFR`, preprocessed and then they are given as input to the PUF, “Real Challenge” as shown in [Figure 12.10](#Chapter12.html#c12_fig10) ([Lao and Parhi, 2011](#Chapter12.html#c12_bib34)). With the introduction of the input-reconfigurable circuitry, the robustness of the overall design and also the reconfigurability can be increased.

[Figure 12.14](#Chapter12.html#c12_fig14) shows the design of a lightweight PUF. The design is presented by [Majzoobi *et al*. (2008)](#Chapter12.html#c12_bib46) with an improved robustness and increased security. In this PUF design, there are two networks at the input and the output, “Input Network,” which takes in the challenge inputs, and “Output Network,” which gives out the response outputs. The module itself will contain a number of parallel PUF structures which are run by the input and the output networks. For connecting the challenge inputs to a number of parallel PUF structures, an interconnect network is implemented. A single PUF will be satisfying the strict avalanche criterion (`SAC`). Any cryptographic primitive is said to satisfy the `SAC` if a complement in the single input bit induces a change in each of the output bits with a 50% probability. But when the overall parallel network of the design is considered, the `SAC` is not satisfied.

[Figure 12.15](#Chapter12.html#c12_fig15) shows a design of hybrid oscillator arbiter PUF which uses `RO` as a main component in the module and can also be reconfigured ([Yanambaka *et al*., 2018](#Chapter12.html#c12_bib78)). As shown in the figure, there are two different sets of `RO`s which are connected to two multiplexers “Mux 1” and “Mux 2.” The `RO`s will generate the oscillations which are fed to the multiplexers. Challenge input given to the PUF module acts as the select lines to the multiplexers. Based on the challenge input given, the multiplexers select different `RO`s. The output from Mux 1 is given as D-input to the D-flip-flop and output from Mux 2 is given as clock signal to the D-flip-flop. Due to the variations in the `RO`s, the oscillations produced will not be of the same frequency. Therefore, the output of D-flip-flop will change based on the input challenge. Different configurations of inputs can be achieved by changing the select line inputs. The robustness and security offered by the design can be increased by increasing the number of `RO`s in the design, but it also increases the complexity and chip are occupied.

### 12.7 SRAM-based PUF

Many devices and development board have `SRAM` which can be used to design a PUF. [Figure 12.16](#Chapter12.html#c12_fig16) shows the circuit design of a 6T `SRAM` cell ([Mohanty, 2015](#Chapter12.html#c12_bib53)). The start-up value of the `SRAM` cell is used by the PUF to generate the output bits. When compared to the other designs of PUF, the reliability and uniqueness of the `SRAM` PUF are less. As shown in [Figure 12.16](#Chapter12.html#c12_fig16), an `SRAM` cell can be designed using cross-coupled inverters and will be able to store a single bit of binary data, “1” or “0.” When the `SRAM` cell is powered up, its initial condition is taken as the advantage by the PUF to generate the unique output. But there are issues with the behavior of `SRAM` cells at the start-up. Different `SRAM` memory modules were compared and analyzed by [Schrijen and Leest (2012)](#Chapter12.html#c12_bib65), operating at different temperatures and supply voltages. The analysis was performed by calculating the reference bits at the starting, at various temperatures of 20 °C, −40 °C, and 80 °C by [Schrijen and Leest (2012),](#Chapter12.html#c12_bib65) which showed the stability of `SRAM`. The supply voltage of the `SRAM` was also varied by 10%. This does not affect the performance of the PUF as claimed ([Schrijen and Leest, 2012](#Chapter12.html#c12_bib65)) because the start-up conditions are attained during the initial few nanoseconds.
