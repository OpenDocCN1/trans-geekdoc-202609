

# 安全

安全一直是长期存在的主要问题之一，并且至今仍是研究的主要焦点。随着技术的进步，每天都在开发新设备，并在 2.1 节讨论的各个领域产生更好的解决方案。即使引入了许多安全原语，攻击者仍在寻找方法来攻击并对各种受保护设备发动成功攻击。这长期以来一直是一个主要问题。密码学一直是解决方案，其中发送给最终用户的主文本消息使用密钥加密，最终用户将使用相同的密钥或不同的私钥解密文本。这种做法已经实践了很长时间 ([Yanambaka *et al.*, 2017](#Chapter2.html#c02_bib113))。发现的第一把锁和钥匙有 4000 年的历史，同样，在当今的数字时代，这里的锁和钥匙也是数字化的，但基本概念保持不变。应当注意，安全、隐私、保密性和知识产权 (IPR) 不一定相同 ([Bhargava *et al.*, 2018](#Chapter2.html#c02_bib10); Mohanty, [2017](#Chapter2.html#c02_bib54), [2018](#Chapter2.html#c02_bib55))，如 [图 2.12](#Chapter2.html#c02_fig12) 所示。数据安全通常指数据的保密性、可用性和完整性。系统安全通常涉及系统（例如，智能汽车）的可信、安全、正常运行等。数据隐私定义为为不同目的约定使用的适当数据。系统隐私可以是未知系统的位置和功能，例如，智能汽车的位置应对对手未知。只有当信息未提供或未披露给未经授权的个人、实体或进程时，才能保证保密性。IPR 或所有权涉及保留特定硬件或介质所有者的所有权，这类似于书籍的版权或作者身份，即出版商或作者的版权。

## 2.2.1 IoT 安全 – 攻击与对策

安全与隐私的辩论已经持续了很长时间 ([Notario, 2016](#Chapter2.html#c02_bib64))。隐私和安全的定义仍在辩论中，最核心的争议点是保密性部分。安全和隐私都是任何系统的重要组成部分。在 IoT 环境中，这些至关重要，因为 IoT 设备持续连接到网络并在线。这为攻击者以各种方式攻击系统留下了大量空间。该领域正在进行大量研究 ([Asplund and Nadjm-Tehrani, 2016](#Chapter2.html#c02_bib8); [Schinianakis, 2017](#Chapter2.html#c02_bib77); [Schneier, 2017](#Chapter2.html#c02_bib78); [Sivaraman *et al.*, 2018](#Chapter2.html#c02_bib91); [Unwala *et al.*, 2018](#Chapter2.html#c02_bib101))。世界各地正在发生各种安全攻击。网络犯罪企图的数量增加了，用于对抗它们的安全解决方案也随之增加 ([Andrews, 2017](#Chapter2.html#c02_bib7); [Heartfield *et al.*, 2016](#Chapter2.html#c02_bib34); [Kundu *et al.*, 2018](#Chapter2.html#c02_bib44); [Mazurczyk *et al.*, 2016](#Chapter2.html#c02_bib52))。

[图 2.13](#Chapter2.html#c02_fig13) 显示了 IoT 环境中可能发生的不同类型的攻击 ([Nawir *et al.*, 2016](#Chapter2.html#c02_bib60))。存在许多威胁，其中未经授权和未识别的恶意设备可以进入网络并在外部和内部篡改系统。因此，识别 IoT 环境中的用户是一个重要的先决条件。正在广泛开展检测和防止 IoT 僵尸网络的研究 ([Moon *et al.*, 2015](#Chapter2.html#c02_bib59); [Prokofiev *et al.*, 2018](#Chapter2.html#c02_bib73))。设备应具有防篡改性。存在各种类型的攻击，例如侧信道攻击和内存利用，可以通过篡改设备本身成功执行 ([Li *et al.*, 2011](#Chapter2.html#c02_bib47); [Sengupta and Kundu, 2017](#Chapter2.html#c02_bib83))。因此，IoT 设备理应防篡改，以便攻击者无法执行此类攻击。在 IoT 设备上执行之前，应广泛审查其中使用的软件。这可能导致设备未经授权的使用、数据丢失或设备故障。网络和设备安全至关重要。但是，提高设备的安全性也可能增加整个模块的功耗。应避免这种情况，因为 IoT 设备通常由电池供电，无法使用持续电源。这使得为 IoT 设备开发安全原语变得困难。正在为这些设备开发低功耗硬件安全模块 ([Yanambaka *et al.*, 2017](#Chapter2.html#c02_bib113))，以便减轻攻击。通信和设备网络身份验证也应给予最高优先级，以便未经授权的设备无法进入网络且通信信道不会被破坏 ([Yanambaka *et al.*, 2016a](#Chapter2.html#c02_bib111))。身份管理也是此场景中的关键因素。设备的身份应得到保护，以防止克隆攻击。

硬件木马是 IoT 环境中另一个应予以处理的问题。[图 2.14](#Chapter2.html#c02_fig14) 显示了当前活跃的各种硬件木马类型、它们将被引入的位置以及存在插入机会的阶段 ([Mohanty, 2015](#Chapter2.html#c02_bib56))。硬件木马是攻击者在制造的不同阶段引入主设计中的一种不需要的恶意设计，旨在使整个模块无用或从模块中窃取数据。硬件木马可以引入处理器、内存、I/O 设备、电源和时钟网格。这些组件中的每一个都是设备的重要模块，在设备的整体功能中起着至关重要的作用。引入恶意设计可能对设备的高效运行造成致命影响。有两种不同类型的木马，一种是在设备本身开启时始终开启，另一种可以通过事件或信号触发。有许多方法可以检测和避免硬件木马 ([Dupuis *et al.*, 2018](#Chapter2.html#c02_bib20); [He *et al.*, 2017](#Chapter2.html#c02_bib33); Sengupta, [2016](#Chapter2.html#c02_bib81), [2017](#Chapter2.html#c02_bib82); [Shen *et al.*, 2018](#Chapter2.html#c02_bib86); [Xue and Ren, 2018](#Chapter2.html#c02_bib110))。硬件木马可以插入的许多阶段如 [图 2.14](#Chapter2.html#c02_fig14) 所示。改变功能、降低性能、泄露信息和拒绝服务是硬件木马的一些影响。在许多情况下，这些可能是致命的，因为设备在需要时无法发挥全部潜力。
