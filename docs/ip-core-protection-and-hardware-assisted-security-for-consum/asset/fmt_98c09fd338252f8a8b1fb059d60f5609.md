
During formatting and encryption, the message bits that are to be hidden will be oversampled and duplicated. This gives out the watermark of the size of object or host image video frame. Pseudo-random noise that is generated will be XORed to the watermark and is secured. The difference of original image and fractal approximation gives the cover signal. Watermark is then modulated to the cover which includes forcing some of the cover pixels to zero based on the watermark bit and sign. Modulated cover is added to the fractal approximation which gives the watermarked image. The process is reversed to extract the watermark from the frame.

### 11.7.2.4 Invisible-robust wavelet domain chip

A hardware implementation of video watermarking algorithm is presented by [Mathai *et al*. (2003a, 2003b)](#Chapter11.html#c11_bib60). The algorithm is based on the implementation from [Depovere *et al*. (1999)](#Chapter11.html#c11_bib24), Strycker *et al*. ([1999](#Chapter11.html#c11_bib101), [2000](#Chapter11.html#c11_bib102)), and Termont *et al*. ([1999](#Chapter11.html#c11_bib107)). In the paper, both the embedder and the detector are presented with a floating point data path architecture. For the implementation of algorithm, ![image](OEBPS/images/c11-Eqn-in-107.gif)technology is used. The power consumption of the embedder module is 60 mW and detector is 100 mW at an operational voltage of 1.8 V.

The embedder consists of payload modulator, high-pass filter, and a watermark superposition unit. A video frame that is distorted without the degradation of quality is selected by the high-pass filter. The payload modulator modulates the pseudo random noise pattern using input payload to generate a base watermark which is then multiplied with the high-pass filter output to create the desired watermark. Then the raw images of the video will be added to the watermark that is created. Detection process contains the filter that is similar to the high-pass filter which is used for removing unnecessary components. The fold loop consisting of fold buffer and the adder components will accumulate the frames that are filtered. After accumulation, the input is stalled and detection will continue with the FFT computation. Then the pixel-wise multiplication is performed. The scan hardware is a set of registers used to keep track of highest correlation peaks.

### 11.7.2.5 Visible watermarking hardware

A visible watermarking hardware for video copyright protection in compressed domain is shown in [Figure 11.19](#Chapter11.html#c11_fig19) ([Cai, 2006](#Chapter11.html#c11_bib11); [Mohanty and Kougianos, 2011](#Chapter11.html#c11_bib69); [Mohanty *et al*., 2009](#Chapter11.html#c11_bib70)). The watermark-embedding IBP embeds a watermark image into IBP video frame, where I is intra-frame and B and P are inter-frames. The watermark embedding I module embeds a watermark to intra-frame only. The “Frame Buffer” buffers the frames for every block procedure. Its size capacity is enough for one input group of picture (GOP), output motion vectors, and output stream. DCT module performs DCT. Motion estimate (ME) module performs motion estimation among the frames. The quantization module quantizes DCT coefficients. The ZZ module performs scanning procedure. The entropy module performs entropy coding procedure using a Huffman coding. The controller which is an FSM generates addressing and control signals with clock for each individual component module in the system to synchronize the system working functions. The IE module performs the inverse entropy coding or decoding. The inverse zigzag (IZZ) module performs IZZ scanning. The inverse quantization (IQuan) module performs inverse quantization. The motion compensation (MC) module performs motions compensation. A new frame is rebuilt which resembles the original one in terms of reference frame and motion vectors, prediction errors. If it is intra-frame, this block will be skipped. The input and output are buffered to frame buffer. The drifting compensation block has three processing branches as shown in the figure. In branch A, the watermark is embedded to all I, B, and P frames. In effect making two watermarks for inter-frames B and P, one is predicted from intra-frame, and one is embedded. In branch B, the watermark is inserted to intra-frame I only. However, inter-frames B and P have the same watermark by prediction. This watermark is the drift one and needs to be canceled in inter-frames B and P. In branch C, the frames are compressed without any watermark. So after decompressing, branch A has two watermarks, one is stable, another is drifting; branch B has one drifting watermark; branch C has no watermark. So, by subtracting branch B from branch C, the drifting watermark is extracted, and by subtracting branch A from the extracted drifting watermark, the drifting watermark effect in inter-frames is canceled. Overall a good visible watermark is inserted in the video frames. It may be noted that visible watermarking in compressed domain is bit tricky as compared to the watermarking in uncompressed domain. The host video frames are not independent as still images, but they are correlated frames with each other in temporal mode, that is, inter-frames (P or B) predicated from intra-frame. So, every object in base intra-frame is inherited by predicted inter-frames (P or B) such that the watermark in intra-frame appears in inter-frames (P or B) even though they are not embedded with the watermark. However, if it overlaps with any moving objects in the video scene, the watermark drifts around with the moving objects. The drift compensation is needed to cancel the side effect to obtain a stable watermark.

### 11.7.3 Secure better portable graphics (SBPG)

An SDC is a device that consists of all the features of a normal digital camera with additional onboard security features like watermarking. This can help in reducing the more time and resources that are used for watermarking the images taken with a normal camera. A hardware-based design also gives a low-power design with a high performance. Design of an Secure better portable graphics (SBPG) is presented by [Mohanty *et al*. (2018)](#Chapter11.html#c11_bib73). When compared to a JPEG compression, BPG compression gives a better and low image size with a comparatively higher image quality. This makes BPG more suitable for implementations in the real-time bandwidth restricted applications. SDC with SBPG is usually implemented as a SoC. Encryption and watermarking are two different layers of protection that can be attained from this setup. Hence, it can help in safeguarding the DRM, ownership, and so on. This makes it suitable for the implementation in IoT applications and smart health care.
