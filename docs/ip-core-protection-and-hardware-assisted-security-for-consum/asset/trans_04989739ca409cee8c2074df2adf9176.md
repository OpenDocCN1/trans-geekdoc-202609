### 9.4 JPEG CODEC IP 核心的实现

#### 9.4.1 设计混淆 JPEG 压缩 IP 核心

使用所设计的低成本混淆 JPEG 压缩 IP 核心的 JPEG 压缩过程的完整设计流程如 [图 9.11](#Chapter9.html#c09_fig11) 所示。在此完整设计流程中，部分步骤通过硬件执行，其余步骤通过软件执行。更具体地说，2D-DCT 变换和量化步骤通过所设计的 JPEG 压缩 IP 核心执行，而输入图像像素强度的去量化和数据编码通过软件执行。每个 8 × 8 块的去量化像素强度存储在硬件队列中，并作为输入提供给所设计的 JPEG 压缩 IP 核心，同时还提供量化矩阵和 2D-DCT 系数矩阵。在本节中，我们强调 JPEG 压缩 IP 核心设计过程的硬件部分的实现。JPEG 压缩 IP 核心使用 HLS 框架（[Sengupta and Sedaghat, 2011](#Chapter9.html#c09_bib28); [Coussy *et al.*, 2009](#Chapter9.html#c09_bib7)）设计，其中 JPEG 压缩的混淆 DFG（如 [图 9.8](#Chapter9.html#c09_fig8) 所示）首先基于资源配置进行调度。如前所述，生成低成本设计的资源配置通过 PSO-DSE 过程进行探索。在此，DFG 基于列表调度算法进行调度，包含三个加法器（`Adder_A1`、`Adder_A2` 和 `Adder_A3`）以及三个乘法器（`Multiplier_M1`、`Multiplier_M2` 和 `Multiplier_M3`）。这表明，基于依赖性，调度 DFG 的每个控制步骤（CS）最多可以包含三次加法和三次乘法操作，而 DFG 中可用的操作共有 136 个。在每个 CS 中，每个调度的操作都分配给其对应的硬件，分配给同一硬件的操作被绑定（共享）在一起。[表 9.1](#Chapter9.html#c09_tbl1) 表示所有 136 个操作、它们的 CS 和对应的分配硬件。总共需要 30 个 CS 来调度所有操作。加法器和乘法器均采用 IEEE 754 半精度浮点格式设计。因此，所有操作符的位宽均为 16 位。所实现的 JPEG 压缩 IP 核心包含两个单元：数据通路单元和控制器单元。数据通路单元表示所需资源数量及其互连，而控制器单元通过改变其信号（例如，使能、选择器、选通）来同步这些资源。换句话说，控制器单元负责通过在不同时钟周期激活和停用数据通路的不同组件来控制数据通路中的数据流，从而同步每个组件以生成无错误的输出。低成本混淆 JPEG IP 的数据通路单元的通用框图表示如 [图 9.12](#Chapter9.html#c09_fig12) 所示。如图所示，数据通路包含三个加法器和乘法器、十个 32:1 类型的多路复用器、两个 16:1 类型的多路复用器、五个 1:32 类型的解多路复用器、一个 1:16 类型的解多路复用器、四十个 16 位寄存器和 18 个锁存器。主输入通过 `A1`，…`A8`，…`Q1`，…`Q8` 表示，而依赖输入通过 `i[1]`、`i[2]`，…，`i[135]` 表示，`i[136]` 表示输出。数据通路单元和完整 IP 核心的实现示意图分别如图 [9.13](#Chapter9.html#c09_fig13) 和 [9.14](#Chapter9.html#c09_fig14) 所示，完整控制器单元信号描述可在“附录”中找到。数据通路和控制器均使用 Quartus CAD 工具在 Intel Cyclone II ([Cyclone II FPGA, 2018](#Chapter9.html#c09_bib8)) FPGA 上实现。
