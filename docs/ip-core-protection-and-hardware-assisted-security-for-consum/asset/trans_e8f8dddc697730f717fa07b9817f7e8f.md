这种木马通过导致输出故障来影响电路的有效载荷。例如，如[图 3.6](#Chapter3.html#c03_fig6)所示，BCD 加法器有两个主要输入，`A` 和 `B`，每个为 4 位大小（`A[3]−A[0]` 和 `B[3]−B[0]`），一个使能信号 `En` 为 1 位，以及一个主要输出 `O` 为 4 位大小（`O[3]−O[0]`）。当 `En` 信号设置为 1 时，BCD 加法器将正确工作，但当 `En` 信号设置为 0 以禁用组件/模块时，木马将被触发并开始引入故障。系统集成商在测试阶段会保持组件处于启用状态（`En = 1`），因为他/她可能认为 `En` 信号用于启用和禁用组件（[Sengupta, 2017](#Chapter3.html#c03_bib21)）；然而，它是木马的隐蔽触发信号。因此，罕见条件测试可能逃避并通过功能仿真和测试（将在后文中更详细地解释）。

## 性能可降载荷型硬件木马

这种木马通过降低电路性能来影响电路的有效载荷。换句话说，这种类型的硬件木马可能会增加电路的执行延迟或功耗，而不会改变输出的正确性。因此，这种类型的木马可能在功能验证阶段不被察觉。例如，如[图 3.7](#Chapter3.html#c03_fig7)所示，对于输入值 `A` = 1 和 `B` = 0 或 1，木马逻辑不会被触发；因此，在计算和（`S`）时，1 位加法器的传播延迟方面没有性能下降。但是，对于输入值 `A` = 0 和 `B` = 0 或 1，木马逻辑被触发，因此计算 `S` 的传播延迟将增加，从而降低电路的性能。但是，在这两种情况下，都会生成正确的输出，因此，通过功能/仿真验证识别这种类型的木马可能被逃避。这种类型的木马可能导致电路偶尔出现时序违规（[Sengupta, 2017](#Chapter3.html#c03_bib21)）。

## 泄露机密信息和发起拒绝服务（DoS）载荷型硬件木马

这种泄露机密信息的木马的设计方式是，它可以绕过应用于机密信息的加密过程。木马可能对敏感信息构成重大威胁。例如，如[图 3.8](#Chapter3.html#c03_fig8)所示，一旦木马被触发，明文可能跳过加密过程，从而泄露机密信息（[Sinanoglu *et al.*, 2013](#Chapter3.html#c03_bib31)）。

## 3.2.2 高抽象层次下木马安全的优势

如前所述，大多数 CE 设备在其 SoC 设计过程中集成来自 DSP 和多媒体领域的 IP 核心，例如 JPEG CODEC（[Sengupta *et al.*, 2018b](#Chapter3.html#c03_bib30)）、FIR、IIR、FFT、DCT 和 HWT（[Sengupta *et al.*, 2018a](#Chapter3.html#c03_bib29)）。这些 IP 核心包含复杂的算法，如果从寄存器传输级或更低抽象层开始设计，这些算法非常具有挑战性且耗时。此外，实现这些 IP 核心可能存在多种设计架构（硬件变体）。选择任意硬件设计架构可能会导致设计实现成本（面积、延迟、功耗等）方面的巨大开销。与 DSE 引擎集成的高层次综合（HLS）过程能够在可接受的运行时间内，为 DSP/多媒体 IP 核心探索和设计低成本（在功耗、性能、能耗和面积方面）的硬件架构。因此，对于在设计约束内设计复杂算法的硬件，同时满足上市时间压力，HLS 是关键。

在设计 DSP IP 核心时，HLS 工具的模块库中通常有多个 3PIP 核心可用。由于这些 IP 核心是从不可信的 3PIP 供应商处导入的，因此它们包含硬件木马的可能性很大（[Rajendran *et al.*, 2013](#Chapter3.html#c03_bib17））。在典型情况下，HLS 工具供应商的供应商将其库中可用的 IP 核心/模块从 3PIP 供应商处导入。同样，如前所述，这些 IP 核心也可能包含硬件木马。由于设计 DSP IP 核心容易受到此类木马的影响，因此处理 DSP 核心的硬件木马是必要的（[Rajendran *et al.*, 2013](#Chapter3.html#c03_bib17); Sengupta *et al.*, [2017b](#Chapter3.html#c03_bib27), [2017c](#Chapter3.html#c03_bib28)）。在第 3.4 节中，我们讨论文献中可用的不同木马安全 DSP IP 核心设计过程。

## 3.2.3 威胁模型

如第 3.2.1 节所讨论，硬件木马有不同的变体。但是，在 DSP 的背景下，由于影响输出功能的硬件木马威胁是一个研究较为充分的主题，本章只强调那些会改变 IP 核心电路计算（功能）输出的木马类型。如前所述，此类木马可能存在于 HLS 工具库中的 IP 块/模块中。将木马逻辑插入 IP 块/模块有两种方式：(i) 通过 HLS 设计团队内部的对手；或 (ii) 当 HLS 工具供应商的设计团队从 3PIP 供应商处导入 IP 块/模块时。由于此类木马在非常罕见的条件下被触发，因此其检测并不总是可能的（即，逃避的可能性很高）。文献已研究了 DSP 核心上的木马威胁模型，该模型将 3PIP 供应商视为不可信。因此，内部设计集成团队和晶圆厂被视为可信，而 3PIP 供应商在 SoC 设计周期中被视为不可信实体。
