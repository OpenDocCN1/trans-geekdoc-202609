
The complete design flow of JPEG decompression process using devised low-cost obfuscated JPEG decompression IP core is shown in [Figure 9.15](#Chapter9.html#c09_fig15). Similar to the JPEG compression design flow, few steps are performed through software and rest is performed through hardware. More specifically, data decoding and inverse quantization are performed through software and 2D-IDCT transformation and leveling of output image pixel intensity are performed through devised JPEG decompression IP. Finally, each 8 × 8 block with leveled-off decompressed pixel intensity is stored in an output hardware queue.

Figure 9.15. Obfuscated low-cost IP core for JPEG decompression

Similar to JPEG compression, during DFG scheduling, same resource configuration is used. The same number of components, i.e., three adders and multipliers of 16-bits, ten multiplexers of type 32:1, two multiplexers of type 16:1, five demultiplexers of type 1:32, one demultiplexer of type 1:16, Forty registers of 16-bits and 18 latches are used in the data path unit. Similar to the JPEG compression IP core, both data-path and controller of JPEG decompression IP core are also implemented using Quartus CAD tool in Intel Cyclone II ([Cyclone II FPGA, 2018](#Chapter9.html#c09_bib8)) FPGA.

### 9.4.3 End-to-end JPEG CODEC through designed hardware/IP core

In this section, we discuss the end-to-end JPEG CODEC process through the devised JPEG IP core. This discussion has three segments. In the first segment, we discuss about each step of image compression starting from an input image to generating a quantized image through an illustrative example. In the second segment, we present about data encoding and decoding process through RLE algorithm using an illustrative example. In the last segment, we discuss about each step of image decompression starting from a de-quantized image to generate the post-compression reconstructed image pixel through another illustrative example.

A grayscale image of 512 × 512 taken from “dataset of standard 512 × 512 grayscale test images” ([Standard dataset, 2018](#Chapter9.html#c09_bib9)) is selected as an input image. The input image is shown in [Figure 9.16](#Chapter9.html#c09_fig16)(a). To perform DCT on the input image, multiple leveled-off, nonoverlapping 8 × 8 blocks of the image pixel are formed from the input image. Out of multiple nonoverlapping 8 × 8 blocks, a randomly selected block for the input image is shown in [Figure 9.16](#Chapter9.html#c09_fig16)(b). This block (containing 64-pixel values) is provided as one of the primary inputs to the devised obfuscated JPEG compression IP core (shown in [Figure 9.16](#Chapter9.html#c09_fig16)(c)). The designing process of obfuscated JPEG compression IP core is discussed in Section 9.4.1. The designed IP core performs DCT and quantization on the input block and produces transformed and quantized image as output. In this example, we have performed compression based on quality level 90, i.e., using quantization matrix `Q[90]`. This process is repeated until all the 8 × 8 blocks of the input image is transformed and quantized. The generated transformed and quantized image is shown in [Figure 9.16](#Chapter9.html#c09_fig16)(d).

![image](OEBPS/images/PBCS0600-09-f16.jpg)

Figure 9.16. Motivational example of JPEG compression through compression IP core

Data encoding, which is a form of lossless data compression, is performed on each quantized block, before storing the pixel data into a storage device. It involves arranging the data of the quantized block in “zigzag” fashion then employing RLE algorithm on it. [Figure 9.17](#Chapter9.html#c09_fig17)(a) shows the quantized block corresponding to input image block (shown in [Figure 9.16](#Chapter9.html#c09_fig16)(b)). Zigzag scanning (the format of zigzag scanning is shown in [Figure 9.17](#Chapter9.html#c09_fig17)(b)) is performed on the quantized block and the output is shown in [Figure 9.17](#Chapter9.html#c09_fig17)(c). The quantized data sequenced in zigzag fashion is encoded through RLE algorithm. RLE replaces `each nonzero AC coefficient` value with a pair (RUNLENGTH, AMPLITUDE), where “RUNLENGTH” is the `number of zeroes` that came before that nonzero AC coefficient and “AMPLITUDE” is the value of that particular nonzero coefficient. The encoded version of the quantized data using RLE is shown in [Figure 9.17](#Chapter9.html#c09_fig17)(d), where (0, 0) always indicates the end of the block. The remaining elements (from the 64 available slots) of the 1D array in RLE encoded data are not stored, as they are all zeroes. (Note: The first value of the matrix, i.e., 16 is the DC coefficient; it is not encoded through RLE.) Each of these encoded values is converted to its equivalent binary form to generate the corresponding bitstream of the block and then stored in a storage device. To regenerate the quantized block from the bitstream data, decoding needs to be performed. To achieve the decoding of data, all the aforementioned steps have to be performed in reverse order. Thus while obtaining (decoding) 1D array from RLE encoded data, the vacant slots from the 64 elements (of 8 × 8 block) are filled up with zeroes. The inverse zig-zagging is performed to obtain 2D array of 8 × 8 block of quantized block.

![image](OEBPS/images/PBCS0600-09-f17.jpg)

Figure 9.17. Demonstrative example of data encoding through RLE algorithm

To reconstruct the image from its transformed and quantized form, each block is de-quantized using the same quantization matrix used for compression. As in this example, we have performed compression using quantization matrix `Q[90,]`, the de-quantization (inverse quantization) is performed based on quantization matrix `Q[90]` only. The generated de-quantized image is shown in [Figure 9.18](#Chapter9.html#c09_fig18)(a). The 8 × 8 de-quantized block (containing 64-pixel values) is provided as one of the primary input to the devised obfuscated JPEG decompression IP core (shown in [Figure 9.18](#Chapter9.html#c09_fig18)(b)). The designing process of obfuscated JPEG decompression IP core is discussed in Section 9.4.2. The designed IP core performs IDCT and leveling-off of the de-quantized block and produces 8 × 8 decompressed image pixel intensity values as output. The corresponding decompressed image pixel intensity of the same 8 × 8 block (shown in [Figure 9.16](#Chapter9.html#c09_fig16)(b)) is shown in [Figure 9.18](#Chapter9.html#c09_fig18)(c). Again, this process is repeated until all the 8 × 8 de-quantized blocks are inversely transformed and leveled off. Finally, the post-compression reconstructed image is generated by combining all the 8 × 8 inversely transformed and leveled-off blocks. The reconstructed image of the corresponding input image (shown in [Figure 9.16](#Chapter9.html#c09_fig16)(a)) is shown in [Figure 9.18](#Chapter9.html#c09_fig18)(d).
