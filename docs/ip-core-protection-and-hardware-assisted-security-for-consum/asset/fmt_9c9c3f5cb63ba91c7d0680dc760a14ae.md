
Authors on TL-HLS ([Sengupta *et al.*, 2017b](#Chapter3.html#c03_bib27)) presented security analysis to show the robustness of their approach. The number of vulnerabilities detected by this approach is proportional to its robustness. In the design flow of an SoC, each 3PIP core used is considered as potentially untrustworthy. The number of 3PIP cores used in a design is directly proportional to the number of operations in the DMR design. In Sengupta *et al.* ([2017b](#Chapter3.html#c03_bib27)) such vulnerable 3PIP cores are detected using their devised concept. [Figure 3.26](#Chapter3.html#c03_fig26) shows the numbers of vulnerable 3PIP cores that are detected through this approach for different non-loop CDFG, single-loop CDFG, and nested-loop CDFG benchmarks. As it can be observed from [Figure 3.26](#Chapter3.html#c03_fig26), the maximum numbers of vulnerable 3PIP cores are detected for the DHMC nested-loop CDFG.

## 3.8 Conclusion

This chapter presents multiple Trojan security approaches, with emphasis on DSP IP cores. The mechanism mostly used to design a Trojan secured DSP IP core is the CED- or DMR-based approach. Authors have mentioned different types of vendor allocation techniques to achieve that. Rajendran *et al.* ([2013](#Chapter3.html#c03_bib17)) devised collusion prevention in addition to CED, while Sengupta *et al.* ([2017a](#Chapter3.html#c03_bib26)) devised a BFOA-driven low-cost Trojan secured design for non-loop DSP cores. Further, Sengupta *et al.* ([2017c](#Chapter3.html#c03_bib28)) devised a Trojan secured design for nested-loop DSP cores and multiple vendor allocation rules to obtain a PSO-driven low-cost DSP IP core. Finally, it can be observed that both Sengupta *et al.* ([2017a](#Chapter3.html#c03_bib26)) and Sengupta *et al.* ([2017c](#Chapter3.html#c03_bib28)) obtained better design solution in terms of design cost.
