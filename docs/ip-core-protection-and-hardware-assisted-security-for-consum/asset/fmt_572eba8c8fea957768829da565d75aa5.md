## 5.3.5 Encoding rules of buyer fingerprint and seller watermark for DSP IP cores

Signatures for both parties can be embedded into the design during HLS as encoded additional constraints. Roy and Sengupta ([2017](#Chapter5.html#c05_bib32)) encoded fingerprinting and watermarking constraints are implanted covertly in scheduling and register allocation phases of DSP core design methodology (using HLS as backbone). More specifically, buyer fingerprint constraints in scheduling step are performed by forcing particular operations in a particular CS while resolving scheduling conflict. It is a very intelligent process of embedding buyer fingerprint, as it will incur zero hardware and may incur nominal latency overhead. Additionally, during register allocation, the fingerprinting and watermarking constraints are inserted with the notion of colored interval graph (CIG), where each node of the graph indicates storage variables of the design and the connecting edges indicates execution-time overlapping between conforming storage variables.

More explicitly, if there is execution-time overlap between two storage variables, then there will be an edge between those corresponding nodes. Therefore, injecting extra edges as encoded signature constraints will force storage variables of a CIG to implement using distinctive registers. Corresponding illustration of the approach devised in Roy and Sengupta ([2017](#Chapter5.html#c05_bib32)) is shown is [Figure 5.4](#Chapter5.html#c05_fig4).

Fingerprint encoding rules: The fingerprint encoding process devised in Roy and Sengupta ([2017](#Chapter5.html#c05_bib32)) embeds additional constraints in both scheduling and register allocation phases of DSP core design to enhance the signature strength. The definition of fingerprint encoding rule for each variable devised in Roy and Sengupta ([2017](#Chapter5.html#c05_bib32)) is as follows:

*   A = While resolving scheduling conflict force even operation in odd CS in scheduling phase.

*   B = While resolving scheduling conflict force odd operation in even CS in scheduling phase.

*   C = Add additional edge between node pair number (odd, odd) in the CIG.

The operations need to be sorted initially based on their operation number to apply the encoded fingerprinting constraints for ‘A’ and ‘B.’ Similarly, the storage variables need to be sorted before applying encoded fingerprinting constraints for ‘C’ (note: this encoded fingerprint embedding approach is demonstrated using a working application in the upcoming section). The robustness of buyer fingerprint is directly proportional with the signature strength. [Roy and Sengupta (2017)](#Chapter5.html#c05_bib32) are capable to accept and embed any big size fingerprint. As seen, this fingerprint embedding process includes of three different variables and each variable carries a distinctive encoding rule which un-invites significant overhead to the design with respect to area and latency while preserving robustness.

It is recommended that while selecting buyer fingerprint, the signature should have higher number of ‘A’ and ‘B’ digits than ‘C’ digits. The reason is that, the encoding of ‘A’ and ‘B’ digit are formulated in a way that it incurs nil hardware area and trivial latency overhead. This is conceivable as both the digits are injected while resolving operation scheduling conflict, i.e. fingerprint encoding rule acts as conflict resolver. On the contrary, too many ‘C’ digits in the signature may yield hardware overhead. Nonetheless, it is a key digit as it augments additional security layer by implanting the fingerprint constraint in another phase of HLS.

Watermark encoding rules: The watermark encoding mechanism used in Roy and Sengupta ([2017](#Chapter5.html#c05_bib32)) is adopted from ([Sengupta and Bhadauria 2016](#Chapter5.html#c05_bib14)). In ([Sengupta and Bhadauria 2016](#Chapter5.html#c05_bib14)), supplementary constraints for watermark are implanted in the register allocation by injecting the extra edges between the nodes of a CIG. Inserting extra edges mandates storage variables of a CIG to be implemented in distinctive registers. This methodology is flexible for injecting any number of extra edges in the register allocation step. The robustness of the watermark surges with the number of extra edges (i.e. signature magnitude) implanted. Although strength upsurges by increment in size of watermark signature, a bulky signature invites major design overhead. Consequently, it becomes obligatory to use a strong watermarking that delivers extensive protection with marginal design cost burden. As mentioned earlier, ([Roy and Sengupta 2017](#Chapter5.html#c05_bib32)) use a multi-variable watermark process from ([Sengupta and Bhadauria 2016](#Chapter5.html#c05_bib14)). The watermark generation mechanism in Sengupta and Bhadauria ([2016](#Chapter5.html#c05_bib14)) consist of four different variables. The seller can generate unique watermark through an arbitrary blend of these four variables. Each variable depicts a unique encoding rule injects an extra edge between two specific nodes. More explicitly, choice of node pair from CIG to insert an extra edge is well explained in the encoding scheme. The explanation of the encoding scheme has been described below:

*   i = Add additional edge between node pair number (prime, prime) in the CIG.

*   I = Add additional edge between node pair number (even, even) in the CIG.

*   T = Add additional edge between node pair number (odd, even) in the CIG.

*   ! = Add additional edge between node pair number (0, any integer) in the CIG.

Although ‘C’ digit of fingerprint and ‘i’, ‘I’, ‘T’, and ‘!’ digits of watermark, implant signature constraints in register allocation phase through CIG, nevertheless as their encoding rules are distinctive; therefore, the ensuing constraints will be totally dissimilar.

## 5.3.6 Multi-variable signature embedding process

The steps to achieve symmetrical IP protection by implanting fingerprint and watermark process are described in the rest of the section.

Process of implanting fingerprint

**Broad steps:**

1.  Choose buyer signature.

2.  Decode the signature to obtain equivalent fingerprinting constraints.

3.  Resolve operation conflict during scheduling to embed fingerprinting constraints.

4.  Construct the CIG based on assigning storage variables into register.

5.  Perform re-allocation of register if necessary while inserting additional edges in CIG based on fingerprinting constraints.

**Detailed steps:**

1.  Receive a preferred signature as random mixture of: ‘A,’ ‘B,’ and ‘C’ digits from buyer.

2.  Construct a sorted list of operations of the DFG in increasing order based on their operation number.
