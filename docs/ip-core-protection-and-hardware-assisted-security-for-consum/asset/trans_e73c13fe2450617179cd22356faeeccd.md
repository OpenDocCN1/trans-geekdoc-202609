

# 8.7 DSP IP 核的功能混淆与开销分析

如前所述，除了 Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 的强健功能混淆（RF-Ob）外，其他方法均不对 DSP IP 核进行功能混淆。因此，Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 重新实现了 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 的功能混淆技术——强健功能锁定（RFL），并针对 DSP IP 核进行了测试，随后从安全性和设计开销两个方面进行了比较分析。然而，在 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 中，目标应用是 ISCAS-85 基准电路 ([Hansen *et al.*, 1999](#Chapter8.html#c08_bib14)) 中的时序电路和组合电路。另一方面，RF-Ob ([Sengupta *et al.*, 2018](#Chapter8.html#c08_bib35)) 针对的是 EXPRESS 基准套件 ([DSP Benchmark Suite, 2017](#Chapter8.html#c08_bib8)) 中的 DSP 核心。采用了基于 15nm NanGate 技术的开放单元库 ([Open Cell Library, 2017](#Chapter8.html#c08_bib21)) 来评估 FO DSP IP 核心的功耗和执行延迟。设计成本使用公式 ([8.3)](#Chapter8.html#c08_eqn3) 计算。

本章讨论的 DSP 核心案例研究/测试用例的分析分为三个小节：(1) 安全性分析，(2) 设计开销分析，以及 (3) Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 与 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 之间的比较分析。

## 8.7.1 安全性分析

“混淆强度（SoO）”一词被用作安全性指标，用于确定攻击者逆向工程 FO DSP IP 设计的难度。SoO 基于公式 ([8.2)](#Chapter8.html#c08_eqn2) 计算。确定正确密钥组合所需的时间基于每秒应用 10 亿个密钥组合的假设。Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 和 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 对 DSP 核心的 SoO 结果列于 [Table 8.2](#Chapter8.html#c08_tbl2) 中。例如，在 FIR 基准测试中，根据 Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 的方法，总共有 2.13 × 10^(96) 种不同的密钥值输入组合，可用于通过暴力破解攻击解密 FO 网表。同样，在 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 的方法中，总共有 2.23 × 10^(43) 种不同的密钥值组合。因此，与 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 的方法相比，Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 的方法使 SoO 提高了 9.57 × 10^(52) 倍。Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 与 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 在 SoO 方面的比较如 [Figure 8.13](#Chapter8.html#c08_fig13) 所示。

## 8.7.2 开销分析

在本小节中，我们分析了 RF-Ob ([Sengupta *et al.*, 2018](#Chapter8.html#c08_bib35)) 和 RFL ([Yasin *et al.*, 2016](#Chapter8.html#c08_bib44)) 在泄漏功率和由于插入密钥组件而产生的成本方面的设计开销，并将其与等效的非混淆（基准）设计进行比较。非混淆设计，也称为基准设计，表示未插入任何密钥组件的不安全、未锁定的 DSP IP 核心设计。[Table 8.3](#Chapter8.html#c08_tbl3) 报告了 Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 和 Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 与基准设计的功耗比较及其相应的开销百分比。由于插入密钥组件，两种功能混淆技术都会产生功耗开销。然而，Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 的开销相对较低，因为通过 PSO-DSE 框架 ([Sengupta *et al.*, 2017b](#Chapter8.html#c08_bib34)) 探索了低成本的最优 DSP 核心设计方案。更具体地说，Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) 由于缺乏 DSP 架构优化框架而产生更高的功耗开销。在 Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 中，不仅通过 PSO-DSE 过程优化了功耗开销，还额外优化了插入 ILB 后的总门数、总执行延迟以及锁定网表的开销设计成本。在生成混淆 DSP IP 核心时缺乏架构优化框架会导致巨大的设计开销成本。原因在于大多数 DSP 核心体积庞大，可以使用多种替代设计架构进行设计。从备选方案池中选择低成本的设计架构方案需要集成优化框架。在 Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) 中，通过 PSO-DSE（如前面在第 8.6 节中详细讨论）探索了优化锁定网表（包括 ILB 块）总门数的低成本设计方案。
