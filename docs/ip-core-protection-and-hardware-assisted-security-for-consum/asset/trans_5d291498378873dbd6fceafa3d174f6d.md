

## 5. 循环支持特性

循环支持特性旨在检测可作为输入馈送到用于 IP 核心设计的 HLS 工具的应用程序类型。换句话说，此功能提取工具的输入格式是否可以支持以控制数据流图（CDFG）形式表示的基于循环的应用程序，或以 DFG 形式表示的非基于循环的应用程序 ([Gupta, 2003](#Chapter6.html#c06_bib5); [Kurra and Panda, 2007](#Chapter6.html#c06_bib13); [Sengupta *et al.*, 2017](#Chapter6.html#c06_bib34))。识别循环支持特性的设计规则要求输入应用程序为 C 代码。此 C 代码被馈送到 HLS 工具的可执行版本。如果 HLS 工具在没有任何错误的情况下正确运行并生成可理解的 RTL 代码，则它支持相应的输入格式。

注意：此案例研究仅考虑不需要手动干预的 HLS 工具可执行版本。

## 6. 特洛伊安全特性

在硬件领域，特洛伊可以理解为旨在实现攻击者恶意意图的硬件设计的恶意修改 ([Rajendran *et al.*, 2013](#Chapter6.html#c06_bib21); [Bhunia *et al.*, 2013](#Chapter6.html#c06_bib1); [Zhang and Tehranipoor, 2011](#Chapter6.html#c06_bib40))。攻击者可能意图泄露信息、生成错误输出、触发拒绝服务攻击等。可以根据其意图提供多种技术来防御特洛伊。然而，迄今为止，在 DSP IP 核心的文献中，已考虑了旨在通过生成错误输出来损害 IP 正确功能的特洛伊的防护。因此，在特征提取规则期间，仅考虑这种针对 DSP 核心的特殊特洛伊。通常，DSP 核心的特洛伊安全需要来自至少两个不同 IP 供应商的模块。此外，特洛伊检测（安全）通常使用来自至少两个不同供应商的模块，并在如 [图 6.13](#Chapter6.html#c06_fig13) 所示的 DMR 系统中使用它们。因此，特征提取算法接受 IP 核心的数据路径 HDL 以及 HLS 工具的模块库作为输入。DMR 的存在（如可靠性特征提取过程中讨论的）通过识别具有类似于以下端口映射语句的比较器组件的存在来检测：`port map (output register signal 1, output register signal 2, comparator output signal)`。此外，如果模块库包含对应于至少两个不同 IP 供应商的设计目标（如面积、功耗、延迟），则 IP 核心设计中存在特洛伊安全特性。

注意：可靠性和特洛伊安全属性的主要区别在于，可靠性不需要来自两个不同 IP 供应商的模块。另一方面，特洛伊安全需要来自两个不同供应商的模块。

### 6.3.2 IP 核心验证

一旦所有特征都被提取，每个 DSP IP 核心的特征集将分别生成，对应于竞争供应商以及所有权待确定的 IP（即 IP[ID]）。随后，竞争 IP 供应商的特征集将根据 (6.2) 与 IP[ID] 的特征集进行匹配。如果获得 100% 的匹配百分比（*µ*），则 IP[ID] 的所有权将授予该特定 IP 供应商。

![image](OEBPS/images/c06_eqn62.gif)

在典型场景中，CFE 方法 ([Sengupta and Kachave, 2018](#Chapter6.html#c06_bib26); [Inoue *et al.*, 2011](#Chapter6.html#c06_bib7)) 中使用的特征集足以解决 IP 核心所有权冲突。然而，我们希望讨论各种异常场景以及在该场景中解决所有权冲突的程序。

* I. **没有任何竞争 IP 供应商具有 100% 匹配**：在这种情况下，IP[ID] 的所有权将不会授予任何争夺 IP[ID] 所有权的供应商。

* II. **多个竞争 IP 供应商具有 100% 匹配**：在这种情况下（称为“IP 解析死锁”），应通过识别可能区分两个或多个竞争 IP 供应商的其他属性来扩展特征集。这是通过进一步调查每个 IP 核心来识别是否存在可以考虑的其他属性以打破此死锁。基于此进一步调查，将新特征添加到特征集中。换句话说，特征集被扩展以包含这些新特征。此外，需要针对这些新添加的特征制定特征提取规则。接下来，现在对处于死锁状态的 IP 核心执行这些新特征的特征提取。随后，使用更新后的特征集执行特征匹配。最后，如果没有异常场景，所有权将授予其特征集与 IP[ID] 的特征集 100% 匹配的 IP 供应商。

### 6.3.3 定制 CFE 的重要特征

* 定制 CFE 方法 ([Sengupta and Kachave, 2018](#Chapter6.html#c06_bib26)) 适用于每个竞争 IP 供应商都有用于声称 IP[ID] 所有权的唯一 HLS 工具的场景。但是，在两个或多个 IP 供应商基于通过第三方获得的相同 HLS 工具声称所有权的场景中，定制 CFE 的“特征集”不足以解决所有权冲突。

* 如第 6.2 节中已讨论，定制 CFE 方法仅需要 HLS 工具的可执行版本。此外，它不需要这些 HLS 工具的源代码。因此，IP 供应商无需担心源代码或机密信息泄露。此外，如果某个竞争 IP 供应商拒绝提供 HLS 工具的可执行版本，则该供应商将被排除在所有权授予过程之外。这是因为，通常，IP 的合法所有者不会犹豫提供其 HLS 工具的可执行版本，因为 IP 核心的所有权岌岌可危。

* 定制 CFE 适用于 DSP IP 核心的 IP 供应商。但是，FPGA 的 IP 供应商不在 [Sengupta and Kachave (2018)](#Chapter6.html#c06_bib26) 的范围内。

## 6.4 案例研究分析

本节报告了自动化定制 CFE 方法 ([Sengupta and Kachave, 2018](#Chapter6.html#c06_bib26)) 和 ([Koushanfar *et al.*, 2005](#Chapter6.html#c06_bib12)) 的案例研究分析。定制 CFE 方法 ([Sengupta and Kachave, 2018](#Chapter6.html#c06_bib26)) 在 Express Benchmark Suite ([http://www.ece.ucsb.edu/EXPRESS/benchmark/](http://www.ece.ucsb.edu/EXPRESS/benchmark/)) 的 express DSP 基准测试套件上进行了测试。这些基准测试主要包含 DSP 应用程序。定制 CFE 方法针对数据密集型 IP 核心（如 ARF、BPF 和 DCT）、控制密集型 IP 核心（如 FFT 和 FIR）以及多媒体数据密集型 IP 核心（如 JPEG IDCT）进行了执行。
