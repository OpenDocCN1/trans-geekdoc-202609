

Koushanfar *et al.* ([2005](#Chapter4.html#c04_bib8)) 提出了一种动态水印过程，用于保护 DSP IP 核心 ([Coussy *et al.*, 2009](#Chapter4.html#c04_bib3))。一组设计和时序约束以供应商水印的形式嵌入到 IP 核心中。在此方法中，供应商的签名被转换为其等效的二进制形式，其中每个数字（0 或 1）表示一个水印约束。更具体地说，这些水印约束被嵌入到寄存器分配和绑定阶段。这是通过在 IP 设计的等效彩色区间图（CIG）中添加额外边缘来实现的。在 CIG 中，每个节点表示一个存储变量。存储变量的生命周期介于其创建（值写入其中）和最后一次使用（从中读取值）之间。两个节点之间的边缘表示这些存储变量的生命周期存在重叠。节点的颜色表示分配给相应存储变量的寄存器。因此，生命周期重叠的两个存储变量不能存储在同一个寄存器中。换句话说，两个之间有公共边缘的节点不能具有相同的节点颜色。因此，将额外边缘作为水印约束添加到 CIG 中将强制两个存储变量在两个不同的寄存器中执行。Koushanfar *et al.* ([2005](#Chapter4.html#c04_bib8)) 方法的概览如 [Figure 4.3](#Chapter4.html#c04_fig3) 所示。

与 Koushanfar *et al.* ([2005](#Chapter4.html#c04_bib8)) 中双变量（0 和 1）签名编码规则不同，Sengupta 和 Bhadauria (2016) 提出了一种单阶段多变量（四种组合）水印方法论，用于保护可重用 IP 核心。每个携带唯一编码规则（攻击者未知）的变量在 CIG 中的两个节点对之间添加一条额外边缘。因此，与 Koushanfar *et al.* ([2005](#Chapter4.html#c04_bib8)) 相比，Sengupta *et al.* (2016) 嵌入了更强大且防篡改的水印。由于在 Sengupta *et al.* (2016) 和 Koushanfar *et al.* ([2005](#Chapter4.html#c04_bib8)) 中都插入了水印约束，可能会出现面积开销。因此，为了最小化设计成本，Sengupta *et al.* (2016) 通过粒子群优化探索了一种低成本设计方案。可以通过检查带水印 IP 的数据路径硬件描述语言（HDL）文件来检测嵌入的签名。由于编码规则对攻击者隐藏，因此几乎不可能从其数据路径中识别水印约束。Sengupta *et al.* (2016) 方法的概览如 [Figure 4.4](#Chapter4.html#c04_fig4) 所示。

Sengupta *et al.* ([2018](#Chapter4.html#c04_bib22)) 提出了一种三阶段水印过程，用于保护 DSP IP 核心 (Sengupta and Sedaghat, 2011)。在此方法中，供应商签名由 7 个变量组成。IP 所有者签名作为水印约束嵌入到高层综合（HLS）的三个不同（但相互连接）阶段中，即调度阶段、硬件分配阶段和寄存器分配阶段。由于在三个不同阶段插入了水印约束，供应商签名分布在 IP 核心设计中。因此，水印的完全移除或恶意篡改极其困难。此外，嵌入 7 变量编码使该方法极其强大。此外，调度阶段的水印与硬件分配和寄存器分配阶段的水印独立。同样，寄存器分配阶段的水印与调度和硬件分配阶段的水印独立。由于这些优势，三阶段水印方法既极其强大又防篡改。可以通过检查带水印 IP 的数据路径和控制器 HDL 文件来检测嵌入的签名。由于水印约束在 IP 设计中分布良好且编码规则对攻击者隐藏，因此对手从其数据路径和控制器中识别水印约束极其困难。Sengupta *et al.* ([2018](#Chapter4.html#c04_bib22)) 方法的概览如 [Figure 4.5](#Chapter4.html#c04_fig5) 所示。

### 4.3 带水印 IP 核心/硬件的设计过程

如前所述，IP/硬件水印是将所有者的签名隐蔽地嵌入到 IP/硬件设计中的过程，以便在发生任何冲突时证明其所有权 ([Sengupta *et al.*, 2017](#Chapter4.html#c04_bib21))。在本节中，我们详细讨论两种（即单阶段和三阶段）IP 核心水印过程的问题公式和设计过程。这两种方法都通过一个激励示例来演示。

#### 4.3.1 问题公式

**输入：** (i) DSP 应用程序，(ii) 资源配置，(iii) 模块库，以及 (iv) 供应商签名。

**输出：** 带水印的 IP 核心设计。

Sengupta *et al.* (2016, [2018](#Chapter4.html#c04_bib22)) 接受以数据流图（DFG）形式表示的 DSP 应用程序，以 NanGate 15-nm 技术 ([NanGate Open Cell Library, 2018](#Chapter4.html#c04_bib12)) 或 90-nm 库/其他库形式表示的模块库，以及用户指定的资源配置（*R*）。这里，*R* 表示为：*N(X*[1])*, N*(*X*[2])*, …, N*(*X*[*D*])，且 *N*(*X*[*D*]) 表示类型 *X*[*D*] 的资源数量。Sengupta *et al.* (2016) 提出了一个包含四个编码变量的供应商签名，用于生成水印约束。这些水印约束嵌入到 DSP IP 核心设计过程的单个 HLS 阶段中。另一方面，[Sengupta *et al.* (2018](#Chapter4.html#c04_bib22)) 提出了一个包含七个编码变量的供应商签名。这些水印约束嵌入到 DSP IP 核心设计过程的三个不同 HLS 设计阶段中。[Figure 4.6](#Chapter4.html#c04_fig6) 描绘了 IP 核心水印过程的输入和输出。

![image](OEBPS/images/PBCS0600-04-f06.jpg)

**目标平台：** Sengupta *et al.* (2016, [2018](#Chapter4.html#c04_bib22)) 水印方法的目标平台是任何现代计算机辅助设计（CAD）工具。两种水印方法都在 HDL 中生成最终的带水印 DSP IP 核心设计；因此，任何用于生成 IP 核心的基于 HDL 的 CAD 工具都可以轻松采用这些水印算法。
