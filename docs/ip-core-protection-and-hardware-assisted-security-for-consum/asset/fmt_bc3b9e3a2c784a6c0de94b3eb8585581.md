## 7.3.2 Multistage high-level transformation techniques

As mentioned earlier, the multistage structural obfuscation methodology ([Sengupta *et al.*, 2017a](#Chapter7.html#c07_bib36)) is achieved using ROE-, LT-, THT-, LU-, and LICM-based techniques. In this approach, a DSP core is taken as input as C-Code/CDFG or DFG. Each of these transformation techniques is then applied to the input application in order to transform it. Each transformation technique is explained and demonstrated through an example. For example, a nonsecured CDFG (present in [Figure 7.5](#Chapter7.html#c07_fig5)) is accepted as input for demonstration purpose. (Note: Application in [Figure 7.5](#Chapter7.html#c07_fig5) is chosen, as it enables all the five multistage transformations to be demonstrated over a single example. However, any application could have been used.) The application is then scheduled based on user-defined resource configuration (example: three adders and four multipliers). The respective nonobfuscated scheduled CDFG and its corresponding circuit representation are depicted in [Figures 7.6](#Chapter7.html#c07_fig6) and [7.7,](#Chapter7.html#c07_fig7) respectively. The circuit presented in [Figure 7.7](#Chapter7.html#c07_fig7) employs 6 numbers of 4:1 switches, 4 numbers of 2:1 switches, 10 numbers of input registers, 1 number of output register, and 8 numbers of delay elements. This nonobfuscated CDFG is used as an example to explain each transformation technique in the following subsections.

### 1. Redundant operation elimination, process

This compiler-driven transformation technique removes the redundant or duplicate operations from a set of operations in a DSP application and then performs necessary adjustment if required. In the context of DFG/CDFG, each operation is represented by a node. Therefore, in the input DFG/CDFG of a DSP core, a node can be recognized as a redundant node, if another node with the same pair of parents and operation type (i.e., adder, multiplier, comparator, etc.) is also available in that DSP application. According to Sengupta *et al.* ([2017a](#Chapter7.html#c07_bib36)), if a pair of such nodes is found, then the nodes with higher node number are removed from the application. However, to keep the correct functionality of the application, necessary adjustment is required in the graph. Lastly, ROE-based structurally obfuscated DSP circuit is generated as intermediate output which is fed to the next obfuscation stage.

For instance, in the nonobfuscated design depicted in [Figure 7.5](#Chapter7.html#c07_fig5), the redundant operations are nodes 9, 11, 12, 13, 15, which are removed using ROE method as depicted in [Figure 7.8](#Chapter7.html#c07_fig8). In order to preserve the functionality of the circuit, the inputs of nodes 14 and 16 are adjusted accordingly, as shown in [Figure 7.8](#Chapter7.html#c07_fig8).

![image](OEBPS/images/PBCS0600-07-f08.jpg)

Figure 7.8 ROE-based obfuscated design

### 2. Logic transformation process

This compiler-driven transformation technique modifies the functionality of an application by generating a different logically equivalent function. In the context of DFG/CDFG, logic transformation alters the nodes of the input graph such that the structure of the graph appears significantly different compared to the original while satisfying the correct functionality of the application. Finally, LT-based structurally obfuscated DSP circuit is produced as output. This transformation is powerful to reflect change at the gate level after HLS.

For example, [Figure 7.9](#Chapter7.html#c07_fig9) represents the logic transformation-driven obfuscated form of the input graph ([Figure 7.8](#Chapter7.html#c07_fig8)); newly added/modified nodes are shown through node numbers 20 & 7 and the modified dependencies are marked with dotted line. Post HLS, the design is functionally equivalent but structurally obfuscated.

![image](OEBPS/images/PBCS0600-07-f09.jpg)

Figure 7.9 Logic transformation-based obfuscated design

### 3. THT process

This transformation technique changes the critical path dependency of the input application accepted as DFG/CDFG, thus modifying the height of the graph. More specifically, THT divides the critical path computation into multiple sub-computations and then executes each sub-computation in parallel. Thus, THTs generate structurally dissimilar yet functionally equivalent graphs. Finally, THT-based structurally obfuscated DSP circuit is produced as output post-HLS design process.

For example, in [Figure 7.10](#Chapter7.html#c07_fig10), THT-based structurally obfuscated form of the input graph (shown in [Figure 7.9](#Chapter7.html#c07_fig9)) is shown. It reduces the height of the obfuscated graph from 10 to 8 compared to its input design. The computation of nodes 17 and 18 in obfuscated design is executed earlier compared to the original design. The dependencies of the obfuscated graphs are adjusted to maintain the correct functionality. The modified dependencies are marked with deep lines.

![image](OEBPS/images/PBCS0600-07-f10.jpg)

Figure 7.10 THT-based obfuscated design

### 4. LU process

This loop transformation approach unfolds or unrolls a loop-based application considering the unrolling factor. LU can be performed by executing the same calculation present inside a loop multiple times. Lastly, LU-driven structurally obfuscated DSP circuit is generated as output, post HLS.

For instance, [Figure 7.11](#Chapter7.html#c07_fig11) unrolls the input CDFG based on the unrolling factor 2. In Sengupta *et al.* ([2017a](#Chapter7.html#c07_bib36)), a low-cost unrolling factor can be explored through PSO-driven DSE process ([Sengupta *et al.*, 2017b](#Chapter7.html#c07_bib37)). LU minimizes the execution time as well as, concurrently, structurally obfuscates the IP design.
