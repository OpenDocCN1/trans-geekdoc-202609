Further, this DFG is fed to a HLS engine to obtain a JPEG decompression IP core. ### 9.4 Implementation of JPEG CODEC IP core

#### 9.4.1 Designing obfuscated JPEG compression IP core

The complete design flow of JPEG compression process using devised low-cost, obfuscated JPEG compression IP core is shown in [Figure 9.11](#Chapter9.html#c09_fig11). In this complete design flow, partial steps are performed through hardware and the remaining steps are performed through software. More specifically, 2D-DCT transformation and quantization steps are performed through devised JPEG compression IP core and leveling of input image pixel intensity and data encoding is performed through software. Each 8 × 8 block leveled-off pixel intensity, stored in a hardware queue, is provided as input to the devised JPEG compression IP core, along with quantization matrix and 2D-DCT coefficient matrix. In this section, we emphasize the implementation of hardware portion of JPEG compression IP core design process. The JPEG compression IP core is designed using HLS framework ([Sengupta and Sedaghat, 2011](#Chapter9.html#c09_bib28); [Coussy *et al.*, 2009](#Chapter9.html#c09_bib7)), where the obfuscated DFG of JPEG compression (shown in [Figure 9.8](#Chapter9.html#c09_fig8)) is first scheduled based on a resource configuration. As mentioned earlier, the resource configuration which generates a low-cost design is explored through PSO-DSE process. Here, the DFG is scheduled based on the list-scheduling algorithm with three adders (`Adder_A1`, `Adder_A2`, and `Adder_A3`) and three multipliers (`Multiplier_M1`, `Multiplier_M2`, and `Multiplier_M3`). This indicates, based on the dependency, each CS of the scheduled DFG can have maximum three additions and three multiplication operations out of 136 operations available in the DFG. In each CS, every scheduled operation is assigned to its corresponding hardware and operations assigned to a same hardware are bound (shared) together. [Table 9.1](#Chapter9.html#c09_tbl1) represents all the 136 operations, their CS, and corresponding assigned hardware. Total 30 CS are required to schedule all the operations. Both adders and multipliers are designed in IEEE 754 half precision floating-point format. Therefore, all the operators have bit-width 16 bits. The implemented JPEG compression IP core consists of two units: data path unit and controller unit. The data path unit represents the required number of resources and their interconnections while the controller unit synchronizes those resources by changing their signals (e.g., enables, selectors, strobes). In other words, controller unit is responsible for controlling the data flow through the data path by activating and deactivating different components of data path in different clock cycle, thus synchronizing each component to generate an error-free output. The generic block diagram representation of data path unit of low-cost obfuscated JPEG IP is shown in [Figure 9.12](#Chapter9.html#c09_fig12). As shown in this figure, the data-path consist of three adders and multipliers, ten multiplexer of type 32:1, two multiplexer of type 16:1, five demultiplexer of type 1:32, one demultiplexer of type 1:16, forty registers of 16-bits and 18 latches. The primary inputs are represented through `A1`,…`A8`,…`Q1`,…`Q8` and the dependent inputs are represented through `i[1]`, `i[2]`, …, `i[135]`, while `i[136]` represents the output. The implemented schematic representation of the data path unit and the complete IP core are shown in Figures [9.13](#Chapter9.html#c09_fig13) and [9.14](#Chapter9.html#c09_fig14), respectively, and the complete controller unit signal description is available in the “Appendix.” Both data path and controller is implemented using Quartus CAD tool in Intel Cyclone II ([Cyclone II FPGA, 2018](#Chapter9.html#c09_bib8)) FPGA.
