
There are various solutions available to sense an attack and defend against it. In a typical embedded system, there are various sensors that are deployed around the entirety of the system. These different sensors are used to detect various parameters of the system. When the system is being attacked by the attacker, there will be changes in various parameters of the system like current fluctuations, increased power consumption, and thermal variations. These parameters can be constantly monitored with the help of sensors and detect any abnormal variations in them. The memory integrity verifications are performed only when these values sensed by the sensors are abnormal. In a traditional embedded system, the integrity verification is performed for all the blocks of memory which will increase the power consumption of the entire module for the preservation of data integrity in the memory.

The definition of any memory integrity verification approach can be structured as follows. Initially, the memory `M` is communicated by a processor. There are two attributes to the memory `M`, the contents of memory `V`, and addressed `A`. `M[R,A]` denotes that the memory at the address `A` is read and it will return the data that is associated at `A`. `M[W,A,V]` denotes that the value `V` is written into the address `A`. To return the value `V`, the write of value `V` should be immediately followed by address `A`. The writes and reads of the memory have a notion of time. In order to associate the same into the reads and writes, it should be addressed as: `M[W,A,V,T]` and `M[R,A,T]`. The association between the values that is present in the memory locations and the addresses of the locations is called as splicing attack. Let us consider an example, address `A` should return the value `V[A]` and `A′` should return the value ![image](OEBPS/images/c2-Eqn-in-1.gif), when the memory is subjected to a successful splicing attack, the `A` will return the value ![image](OEBPS/images/c2-Eqn-in-2.gif). When the value that is stored in the memory location associated with an address `A` is changed to a random value ![image](OEBPS/images/c2-Eqn-in-3.gif), this is called spoofing attack. When the association between the value and the time is disoriented, it is called as replay attack. For example, let us consider `V[A]` as the value at the address location `A` at a time `T[A]` and the value of the same location at the time `T[B]` as ![image](OEBPS/images/c2-Eqn-in-4.gif)and `T[A]` < `T[B]`. When a successful replay attack is performed on the memory, at a time `T` > `T[B]`, the value that will be returned is `V[A]`.

Implementing various sensors in a trusted environment boundary of the embedded system for monitoring various parameters of the processor have been around for a long time ([McGowen *et al.*, 2006](#Chapter2.html#c02_bib53); [Oh *et al.*, 2010](#Chapter2.html#c02_bib66)). Research has been conducted to use the variations in power consumption and current fluctuations to monitor the attacks that are being performed on the devices. [Figure 2.23](#Chapter2.html#c02_fig23) shows the implementation of such a system that can perform the memory integrity verification when the sensors detect an abnormal values of the parameters ([Nimgaonkar *et al.*, 2013](#Chapter2.html#c02_bib63)).

As shown in [Figure 2.22](#Chapter2.html#c02_fig22), various sensors that are present in the hardware is represented as sensor module (SM). The memory bus is constantly monitored by the sensors present in the SM for the fluctuations. The memory integrity verification mechanism is present in the special cache, the ‘hash cache.’ The hash addresses are present in the hash cache. Hash of the memory block is written to the off-chip memory. The hash and the hash addresses are used to verify the integrity of memory. The processor in the embedded system is a trusted chip. So, the cache and the SM are present in the processor boundary. An encryption/decryption block is present in the architecture.

The read and write operations performed on the memory are described in [Figure 2.22](#Chapter2.html#c02_fig22). When data are being written to the memory, the hash address and the hash are computed by the processor and are stored in the hash cache. After storing them, the memory block is encrypted and stored. During the read operation, the memory block which is read is decrypted. During this decryption operation, the SM continuously monitors the memory bus for any abnormalities. If the voltage fluctuations in the memory bus cross a previously set threshold value, the system is considered to be under attack and in this scenario, the hash address is computed again. It is verified with the previously stored hash addresses in the cache. If there is a hit, the hash of the data itself is checked and verified using the hash stored. In case if these two did not match, the system is under attack and the data get corrupt. All the operations that are being performed by the processor are aborted. Once the voltage fluctuations in the memory bus are reduced below a threshold value, the processes stop and the threat is considered to be stopped or mitigated.

### 2.4 Radio-frequency identification (RFID) security

Radio-frequency identification (RFID) is an old technology and has been used in various applications. It can be said to be a starting for IoT in some ways. Tracking, security, and locating are some of the applications of RFID. In IoT, RFID is implemented in many ways. Even though the range of RFID is very less, it can be used for various purposes in IoT environments. But like every communication protocol, RFID is also vulnerable to many attacks and threats. This section discusses various security vulnerabilities and threats of RFID and solutions to some of them.

#### 2.4.1 RFID security attacks

There are different security threats for RFID ([Jayakrishnan *et al.*, 2018](#Chapter2.html#c02_bib37); [Li *et al.*, 2012](#Chapter2.html#c02_bib48); [Thompson *et al.*, 2014](#Chapter2.html#c02_bib99)). [Figure 2.24](#Chapter2.html#c02_fig24) shows various attacks on RFID ([Mohanty, 2015](#Chapter2.html#c02_bib56)). The attacks are categorized into three types: physical threats, channel threats, and system threats.

![image](OEBPS/images/PBCS0600-02-f24.jpg)

Figure 2.24 Attacks on the RFID modules of an IoT device

Physical threats are the security threats that are performed on the physical RFID device, transmitter, or receiver ([Li *et al.*, 2012](#Chapter2.html#c02_bib48)). Due to the low cost of the devices, the RFID tags are not tamper resistant and can be easily exploited. There is a great chance of reverse engineering the RFID tags and clone them. This allows the attacker to get the data that is stored in the tag. Every RFID tag will have a unique identification number and copying the label is not a difficult task with the device itself in hands of the attacker. The RFID tags can be easily disrupted with the electromagnetic waves which can disable them temporarily making them vulnerable. To disrupt the RFID tag, the electromagnetic radiation should be of the same frequency as that of the RFID system.
