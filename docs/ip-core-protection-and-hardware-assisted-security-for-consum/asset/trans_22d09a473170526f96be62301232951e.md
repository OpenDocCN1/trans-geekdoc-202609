

另一种针对 IP 核心保护的技术是硬件混淆。混淆旨在防止 IP 盗版和木马插入（[Yasin *et al.*, 2016](#Chapter6.html#c06_bib37)）。其目的是通过结构混淆（[Sengupta *et al.*, 2017](#Chapter6.html#c06_bib34); [Li and Zhou, 2013](#Chapter6.html#c06_bib15)）或功能混淆（[Lao and Parhi, 2014](#Chapter6.html#c06_bib14））来混淆设计。主要目的是增加攻击者识别 IP 正确功能的工作量（[Yasin *et al.*, 2016](#Chapter6.html#c06_bib37)），从而使攻击者难以在 IC 设计的测试阶段不被发现地秘密插入木马。此外，这也使得 IP 核心难以转售或使用，因为对手不知道其正确功能。混淆并不旨在防止所有权冲突（因为它不插入唯一 ID 或签名）。但是，功能混淆可用于防止 IP 核心的逆向工程。功能混淆实现了一种锁定技术，可用于防止 IP 核心的网表被逆向工程。但是，对手可以逆向工程 IP 核心，通过各种攻击识别正确的密钥，并滥用 IP 核心。

另一种名为“IP 计量”的技术旨在防止 IP 盗版和 IP 过度构建。这种方法旨在区分通过相同制造工艺制造的不同 IP（[Koushanfar and Qu, 2001](#Chapter6.html#c06_bib11)）。因此，当 IP 核心经过通用 IC 设计流程中不可信的设计阶段（[Yasin *et al.*, 2016](#Chapter6.html#c06_bib37)）时，那些被盗版或未被晶圆厂报告（过度构建）的 IP 核心可以被检测出来。由于每个 IC 包含一个唯一 ID，因此可以在需要时检测盗版或过度构建。

另一种主要旨在防止虚假所有权声明的机制是水印（Sengupta *et al.*, [2016](#Chapter6.html#c06_bib22), [2018](#Chapter6.html#c06_bib32); [Sengupta and Bhadauria, 2016](#Chapter6.html#c06_bib24)）。水印在设计阶段将签名嵌入 IP 中，并检测它以解决虚假所有权声明（参见第 3 章）。但是，它容易受到基于逆向工程的攻击，例如签名篡改。此外，签名插入可能会产生硬件开销（[Sengupta *et al.*, 2018](#Chapter6.html#c06_bib32); [Sengupta and Roy, 2017](#Chapter6.html#c06_bib28)）。为了克服硬件水印的一些局限性，提出的另一种替代方法是基于计算机取证工程的 IP 核心保护，它可以以 0% 的设计开销和零签名篡改可能性来解决所有权冲突。

## 6.1.1 取证工程概述

FE 一直是解决刑事案件中冲突的一种有影响力的技术。尽管它已被广泛用于图像篡改和失效分析等领域，但在文献中几乎没有努力利用这种有影响力的技术来保护知识产权核心。关于计算机取证的良好描述可以在 Franke 和 Srihari ([2008](#Chapter6.html#c06_bib4)) 中找到。通用计算机取证工程问题可以表述如下：给定问题 *P* 的解决方案 S，拥有一个有限的算法/工具集 A\_n（*n* = 1, …, *I*），适用于问题 P 并可产生解决方案 *S*，CFE 旨在自动识别算法/工具 A\_i 是否已被应用以产生解决方案 *S*，且置信度非常高。利用 FE 进行 IP 保护的方法有 Kachave 和 Sengupta ([2016](#Chapter6.html#c06_bib9))，[Sengupta 和 Kachave (2018)，](#Chapter6.html#c06_bib26) 以及 Wong *et al.* ([2004](#Chapter6.html#c06_bib36))。但是，Wong *et al.* ([2004](#Chapter6.html#c06_bib36)) 提出的方法需要多个 IP 核心实例（通过算法的不同实现获得）来提供 IP 保护，这在现实世界场景中并不总是可行。此外，该方法中提出的技术（“特征集”）仅限于/仅适用于图着色和布尔可满足性。另外，Wong *et al.* ([2004](#Chapter6.html#c06_bib36)) 提出的方法不适用于 DSP IP 核心。

通用 CFE 方法包含四个步骤，即特征和统计数据收集、特征提取、实体聚类和验证（如 [图 6.2](#Chapter6.html#c06_fig2) 所示）。这些步骤的目的解释如下：

*   特征和统计数据收集：在此步骤中，目标是观察算法 A\_*i*（*i* = 1, …, *n*）对问题 *P* 得到的解决方案，并确定各种有助于区分一个 IP 核心解决方案与另一个解决方案的特征。这些独特特征通常通过一些统计技术进行处理。因此，此步骤被称为特征和统计数据收集。

*   特征提取：一旦确定了特征，就可以区分一个 IP 核心解决方案与另一个解决方案，下一个目标是通过一些特征提取规则从每个 IP 核心解决方案中提取所有这些特征。

*   实体聚类：在此步骤中，我们的目标是将“s”个解决方案划分为“k”个聚类，使每个聚类包含紧密匹配的解决方案。通过此步骤，目标是降低问题的复杂性。因此，不再单独考虑“s”个解决方案，而是根据相似性对其进行分组，然后考虑“k”个组而不是“s”个解决方案。此外，一个通用假设是，通过同一算法 A\_*i* 的不同实现产生的解决方案将具有紧密匹配的特征。因此，一个聚类应包含来自同一算法不同实现的解决方案。

*   验证：在此步骤中，通过算法 A\_*i* 获得的 IP 核心解决方案“S”的特征与待测 IP 核心的特征进行匹配（参见问题描述）。
