

由于这种方法处理基于嵌套循环的应用程序，因此会对所有循环的展开因子进行筛选，以剔除每个循环不适合的展开因子。预处理算法的输入是每个循环的最大循环迭代次数，输出是该循环筛选后的展开因子列表。与 Sengupta *et al.* ([2017b](#Chapter3.html#c03_bib27)) 相比，在这种方法中，筛选算法需要针对多个循环多次执行。因此，这种方法的实现复杂度高于 Sengupta *et al.* ([2017b](#Chapter3.html#c03_bib27))。此外，与 Sengupta *et al.* ([2017b](#Chapter3.html#c03_bib27)) 类似，在这种方法中，通过在用户指定的设计约束内进行基于 PSO 的 DSE 过程，获得低成本的设计方案。但是，这种方法中每个粒子的编码与 Sengupta *et al.* ([2017b](#Chapter3.html#c03_bib27)) 有显著差异，可以表示为 *P* = (*R*[*n*], *M*[*v*], UF[1], UF[2], …UF[*n*])，其中 UF[1] 表示最外层嵌套循环的展开因子值，UF[*n*] 表示最内层嵌套循环的展开因子值。此外，为了实现区分性，这种方法使用四种供应商分配模式来获取 DSP 核心的低成本特洛伊安全设计架构。这里，四种不同的供应商分配模式是 *M*[*v*] = 00、01、10 和 11，其中 *M*[*v*] = 00 和 01 分别与 *M*[*v*] = 0 和 1 相同（如前所述）。剩余的供应商分配模式将在下文中定义。

`M[v] = 10` 的供应商分配模式规则如下：

*   在特定单元（`U^(OG)` 或 `U^(DP)` 中的任一单元）内，所有关键路径操作必须分配给一家供应商的硬件，所有非关键路径操作必须分配给另一家供应商的硬件。例如，如果 `U^(OG)` 的所有关键路径操作分配给 V1 的硬件，那么 `U^(OG)` 的所有非关键路径操作必须分配给 V2 的硬件。

*   两个单元的相似操作必须分配给不同的供应商。例如，如果 `U^(OG)` 的所有关键路径操作分配给 V1 的硬件，那么 `U^(DP)` 的所有关键路径操作必须分配给 V2 的硬件，反之亦然。

`M[v] = 11` 的供应商分配技术规则如下：

*   在特定单元（`U^(OG)` 或 `U^(DP)` 中的任一单元）内，对属于后续展开嵌套循环迭代的操作执行交替供应商分配。例如，如果 `U^(OG)` 的第一个展开循环的所有操作分配给 V1 的硬件，那么 `U^(OG)` 的第二个展开循环的操作必须分配给 V2 的硬件，随后 `U^(OG)` 的第三个展开循环的操作必须分配给 V1 的硬件，依此类推。

*   两个单元的相似操作必须分配给不同的供应商。例如，如果 `U^(OG)` 的第一个展开循环的所有操作分配给 V1 的硬件，那么 `U^(DP)` 的第一个展开循环的所有操作必须分配给 V2 的硬件，反之亦然。

这种方法的通用概览如 [Figure 3.14](#Chapter3.html#c03_fig14) 所示。但是，与 Cui *et al.* ([2014](#Chapter3.html#c03_bib8)) 不同，这种方法不在运行时执行特洛伊恢复。尽管如此，可以使用 TMR 逻辑通过 CED 执行特洛伊纠正。

#### 3.4.2 组合/时序电路的特洛伊安全方法

代码覆盖率分析是文献中可用的有前途的特洛伊检测方法之一。Hu ([1997](#Chapter3.html#c03_bib9)) 从 RTL 设计中识别出可疑信号列表。在此过程中，如果信号在覆盖率分析期间保持稳定（不改变其状态），则被识别为可疑信号。选择这些类型的信号作为可疑信号的原因是，特洛伊通常在被触发之前不会改变其状态。此后，通过添加测试向量来激活设计中未覆盖的部分。但是，这种方法存在验证时间长的问题。

仅对可疑信号（而不是设计的所有可用信号）进行等效分析，可以有效地检测特洛伊逻辑 ([Bushnell and Agrawal, 2013](#Chapter3.html#c03_bib5))。但是，这种方法也会带来一些运行时开销。此外，并非所有可疑信号都一定是特洛伊逻辑。而且，可疑信号的数量会随插入特洛伊的复杂性而增加。因此，通过这种方法为所有 IP 核心实现 100% 的代码覆盖率是困难的。Salmani *et al.* ([2009](#Chapter3.html#c03_bib19)) 通过插入虚拟触发器来设计一种特洛伊检测机制，以增加特洛伊活动。虚拟触发器的插入方式是增加网络的转换概率。最后，它们能够在降低特洛伊激活时间的同时增加特洛伊活动。文献中还提供了多种用于 C 系列基准测试的低设计抽象层特洛伊安全方法论 ([Agrawal *et al.*, 2007](#Chapter3.html#c03_bib1); [Narasimhan *et al.*, 2010](#Chapter3.html#c03_bib13); [Jin and Makris, 2008](#Chapter3.html#c03_bib10); [Wang *et al.*, 2008](#Chapter3.html#c03_bib33))。Agrawal *et al.* ([2007](#Chapter3.html#c03_bib1)) 的特洛伊检测过程基于对制造芯片特征（如路径延迟和功耗）与预期值进行比较。在检测特洛伊时，Narasimhan *et al.* ([2010](#Chapter3.html#c03_bib13)) 依赖于这样一个事实：插入设计的硬件特洛伊会改变电路的设计参数。这种方法能够在存在大工艺变化引起的噪声的情况下检测特洛伊。Wang *et al.* ([2008](#Chapter3.html#c03_bib33)) 设计了一种多电源瞬态电流积分方法来检测硬件特洛伊。这种方法能够通过局部电流分析方法隔离特洛伊。但是，用于检测和隔离非常小的特洛伊电路（少于几个门）的工艺变化可能是负面的。
