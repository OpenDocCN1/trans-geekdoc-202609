
A PUF module that contains on-chip hash function can increase the cost of the entire chip but can also increase the robustness of the entire design. An index-based syndrome encoding has been shown to be implemented with RO PUF for a better reliability ([Yu and Devadas, 2010](#Chapter12.html#c12_bib82)). There are also variations in the output bits that get flipped due to the environmental and operational conditions. So error correction mechanisms can also be implemented with a PUF so that the output can be read without errors. But error correction mechanism can increase the chip area and hence the total cost of the chip. There is also a power trade-off that has to be considered while adding additional circuitry. Man-in-the-middle attacks can be controlled by implementing PUF modules in various applications like distributed computing ([Gassend *et al*., 2002](#Chapter12.html#c12_bib15)). Different steps involved in such an attack are as follows:

*   “A” should interact with the PUF module by using the CRPs shared between A and PUF.

*   “B” is an attacker who has access to the PUF module. Therefore, B will be able to gather the responses from the module by giving the challenge inputs that are chosen by B. B wants to use it with the identity of “A” and impersonates with fake results.

*   A gives out PUF challenges from CRP list and compares responses that come from the output of PUF module with a private list.

*   B has access to the challenges and PUF, so gets the response from PUF for that specific challenge.

*   B will be able to fool A by pretending that A has PUF access and can impersonate the PUF as if it is A.

The applications of PUF are very broad as shown in [Figure 12.29](#Chapter12.html#c12_fig29). They can also be used in applications or devices where randomness is needed. In case of the cryptographic and security applications, the random number generation can be used for generating the encryption and decryption keys, initial seed values, and in some cases, where required, introduce some randomness to the padding schemes and protocols. Pseudo-random number generation (PRNG) is not truly random and in that case, the pattern will repeat after a certain number of iterations. Each of the number generated by the PRNG has to go through a very complex algorithm. Initial seed value should be kept highly secret in case of PRNG. Due to all these different issues with the PRNG, hardware random number generation (HRNG) has been implemented in various cases ([O’Donnell *et al*., 2004](#Chapter12.html#c12_bib55)). In case of an HRNG, an initial seed is not required for generating a truly random number. A delay-based PUF circuit will have the rising edge of the input signal and challenge bits as select lines to the multiplexers. Input will propagate through the series of multiplexers and depending on the delay offered by each of them, a D-flip-flop will generate the output bit “1” or “0.” An unbiased output response will be given by a meta-stable PUF. A Von Neumann correction gives a 32-bit output response from an *N*\-bit input. Similarly, there are various designs of PUF which can be implemented based on the requirements of application. For using the authentication schemes of PUF on a chip, a trusted party or the manufacturer should store the CRPs which are exponential in number in a secure database which can be matched for authentication ([Suh and Devadas, 2007](#Chapter12.html#c12_bib69)). For an input challenge, the output of PUF is the same, in that case, the device that has been challenged will be authentic. But when using the challenge inputs, the man-in-the-middle attack should be avoided by discarding the challenge once used.

A controlled PUF module can also be used for certified execution. It is a process of executing or running a program on a remote server where the client can rely on the results produced by the server ([Gassend *et al*., 2002](#Chapter12.html#c12_bib15)). [Figure 12.31](#Chapter12.html#c12_fig31) shows the process of authenticating a person over the network using PUF. In this case, the PUF device will generate a challenge input and has the response respectively. When authentication is needed, the response is sent to the server where it confirms the identity of the client. This can help avoid identity fraud and rendering the results of the client useless. This can also avoid an attacker from generating different malicious results and sending it to the user. This scenario is often seen in case of a distributed computing where one processor cannot handle the workflow. This type of PUF modules can also be used to restrict the usage of a specific software to a respective amount of processors.
