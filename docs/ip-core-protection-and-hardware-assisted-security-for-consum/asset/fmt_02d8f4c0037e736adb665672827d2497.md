
### 8.2.2 Threat model

The functional obfuscation approach aims to protect an IC/IP core (such as a DSP core or combinational/sequential circuit) by generating a locked netlist of it, in order to enhance the complexity of RE attack. In this threat model, it is assumed that an adversary may be present in an untrusted foundry.

### 8.3 Selected functional obfuscation approaches

This section discusses few selected functional obfuscation-based IC/IP core protection mechanisms with emphasis on the functional obfuscation of DSP cores.

As mentioned earlier, functional obfuscation hides the implementation and functionality of a design by inserting key-components into it. The original circuit integrated with key-components is known as locked design. These key-components could be designed using FSM ([Chakraborty and Bhunia, 2009](#Chapter8.html#c08_bib5)), XOR/XNOR gates ([Roy *et al.*, 2008](#Chapter8.html#c08_bib26); [Rajendran *et al.*, 2015](#Chapter8.html#c08_bib24)), AND/OR gates ([Dupuis *et al.*, 2014](#Chapter8.html#c08_bib10)), lookup table (LUT) ([Baumgarten *et al.*, 2010](#Chapter8.html#c08_bib2)), muxes ([Wang *et al.*, 2016](#Chapter8.html#c08_bib41); [Zhang, 2016](#Chapter8.html#c08_bib46)), ILBs ([Sengupta *et al.*, 2018](#Chapter8.html#c08_bib35)), or a combination of these elements ([Lee and Touba, 2015](#Chapter8.html#c08_bib18)). All these key-components are inserted into the design in such a way that the correct functionality of the circuit will only depend on the correct key value.

Authors in Sengupta *et al.* ([2018](#Chapter8.html#c08_bib35)) propose ILBs to generate FO DSP cores. Among other functional obfuscation techniques available in the literature, this approach targets to generate a locked design for DSP cores. This approach inserts 8-bit key value-based ILB on each bit of output data. It can generate several different structures of ILBs (of similar area/delay) based on the key value. The ILBs are designed using various combinations of AND, NAND, NOT, XOR, and XNOR gates. Each ILB structure produces correct output for a unique key value. Moreover, these ILBs are capable to provide multi pair-wise security feature against sensitization attack and defense against SAT attack through a light-weight custom AES block integrated with the key bits. Thus, this approach ensures strong counter against the RE attack. Additionally, a PSO-driven DSE process is performed to explore optimal design architecture for obfuscated DSP cores. Therefore, it is capable to generate a low-cost, low-power, and secured FO netlist for DSP IP core. Further detailed explanation of this approach is discussed in the next section. Other popular functional obfuscation techniques (except Lao and Parhi ([2015](#Chapter8.html#c08_bib17)) which partially uses functional locking) available in the literature mostly target to generate a locked netlist for sequential or combination circuits but not DSP cores. Authors in Lao and Parhi ([2015](#Chapter8.html#c08_bib17)) perform both structural and functional obfuscations. Structural obfuscation is performed through folding-based transformation technique and functional obfuscation is achieved by using the correct initialization key. Incorrect initialization key value fails to enable the reconfigurator, resulting in activating either a meaningful but nonfunctional mode or a non-meaningful mode.

Authors in Chakraborty and Bhunia ([2009](#Chapter8.html#c08_bib5)) insert dummy states as key-components within the original states of the FSM of a design. FSM enters into an invalid state (obfuscation mode) with incorrect key value and will reach a valid state (normal mode) with correct key value. Desai *et al.* ([2013](#Chapter8.html#c08_bib9)) generated a locked design based on Code-Word, which is similar to an internally generated key sequence based on a specific state transition function. For incorrect key value, the FSM will deviate from the correct transition path and will resume normal transition with the correct key value. Both these approaches generate a locked design for sequential circuits.

In the combinational circuits, Roy *et al.* ([2008](#Chapter8.html#c08_bib26)) proposed the framework for generating locked design using XOR/XNOR gates for the first time. However, in this approach, key-components are inserted at random locations of the design which becomes vulnerable to key-sensitization and removal attacks. Additionally, random insertion of key-component may not always guarantee to produce incorrect output for the locked design on applying incorrect key value. Yasin *et al.* ([2016](#Chapter8.html#c08_bib44)) proposed selection algorithm for the key-component location which will maximize the Hamming distance between incorrect and correct output. Additionally, this approach provides pairwise security through prohibiting isolated key-gates, runs of key-gates, and mutable convergent key-gates to prevent key-sensitization attack. For example, in [Figure 8.3(a)](#Chapter8.html#c08_fig3), both the key-gates K1 and K2 are pairwise secure. Therefore, sensitizing K1 in the output bit is not possible without controlling the K2, and vice versa. This mandates to apply brute force on the key bits.
