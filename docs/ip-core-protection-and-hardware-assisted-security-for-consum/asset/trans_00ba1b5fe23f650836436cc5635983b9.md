因此，混淆 JPEG IP 核心的设计成本是无单位的。根据 [表 9.3](#Chapter9.html#c09_tbl3) 所示的结果，所设计的 JPEG CODEC IP 核心设计的设计成本比未优化混淆 JPEG CODEC IP 核心设计低 5% 以上。实现较低设计成本的原因是涉及 PSO-DSE 引擎，该引擎探索了低成本设计配置。因此，它被称为“低成本”JPEG CODEC IP 核心。

所设计的结构混淆且低成本的 JPEG CODEC IP 核心还与另一个未进行结构混淆的 JPEG CODEC IP 核心进行比较，表明 JPEG CODEC 的 DFG 中未执行任何结构变换技术来隐藏其结构身份。因此，缺乏任何结构变换技术会导致不安全的设计，该设计易受 RE 攻击。[表 9.4](#Chapter9.html#c09_tbl4) 报告了上述两个 IP 核心在设计面积、延迟、成本和 SoO 方面的比较分析。JPEG CODEC IP 核心的 SoO 通过一个指标进行测量，该指标部分采用自 Sengupta *et al.* ([2018b](#Chapter9.html#c09_bib32))，表示如下：

其中 `a[JPEG]` 表示由于结构变换，JPEG CODEC 的 DFG 中节点数量发生改变；`a[JPEG]^(Total)` 表示在应用 THT 技术之前 JPEG CODEC 的 DFG 中可用的总节点数。混淆 JPEG CODEC IP 核心的鲁棒性通过 SoO 指标进行测量，较高的 SoO 值表示在 [0, 1] 范围内具有更强的鲁棒性。换句话说，SoO 指标表示混淆 IP 核心的结构与其原始结构有多大差异。设计与原始结构差异越大，攻击者通过 RE 识别应用程序就越困难。因此，在不知道应用程序实际功能的情况下，在 IP 设计中插入任何恶意逻辑或进行 IP 盗版都极其困难。根据 [表 9.4](#Chapter9.html#c09_tbl4) 所示的结果，所设计的混淆 JPEG CODEC IP 核心设计的 SoO 比未混淆 JPEG CODEC IP 核心设计高出 76% 以上。结构混淆是通过 THT 实现的，THT 负责通过变换表示 JPEG CODEC 的数据流图的高度来混淆 JPEG CODEC 的原始设计，从而修改 JPEG CODEC 的 DFG 中的节点。DFG 中节点的修改表示，与原始设计相比，(1) 节点的源/父节点发生改变；(2) 节点的子节点发生改变；或 (3) 节点的操作类型发生改变。节点修改的效果也体现在设计的门级结构/网表中。根据 [表 9.4](#Chapter9.html#c09_tbl4) 所示的结果，由于 JPEG CODEC 的 DFG 中节点的修改，超过 10,000 个门受到影响。这是由于功能资源、多路复用器、解多路复用器和寄存器的门级架构变换实现的。完整 JPEG CODEC IP 核心门级架构的这种巨大变换使其成为一种不明显的结构。因此，对于攻击者来说，识别这种不明显结构的正确功能极其复杂且繁琐。[图 9.19](#Chapter9.html#c09_fig19)(a)–(c) 分别显示了所设计、未混淆和未优化 JPEG CODEC IP 核心在面积、延迟和成本方面的比较。
