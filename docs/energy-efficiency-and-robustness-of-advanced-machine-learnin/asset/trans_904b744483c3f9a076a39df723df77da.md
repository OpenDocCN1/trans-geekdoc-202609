
在近年来，许多深度神经网络（DNN）模型被提出以实现特定任务的高性能。例如，ILSVRC 竞赛推动研究人员开发高精度的 DNN 用于 ImageNet 数据集 \[[43](#refbib.xhtml#refbib43)\]。*随着精度的提高，DNN 模型在过去几年中在深度和复杂度上不断增长，这使得它们在微型嵌入式设备上部署变得具有挑战性。* 传统上，最流行的 DNN 模型如下列表所示。

*   **`LeNet`** \[[118](#refbib.xhtml#refbib118)\] (1998)：它是最早使用反向传播训练的卷积神经网络（CNN），专为学习灰度手写数字识别任务设计。它由两个 `Conv` 层序列和三个 `FC` 层组成。

*   **`AlexNet`** \[[113](#refbib.xhtml#refbib113)\] (2012)：它是首个为 ImageNet 数据集设计并训练的深度 CNN，显著超越了以往 ILSVRC 竞赛中非卷积模型的表现。它还引入了 `ReLU` 激活函数。为简化训练，计算被分布到两块 GPU 上。

*   **`VGG`** \[[251](#refbib.xhtml#refbib251)\] (2014)：基于 `AlexNet` 的结构，它进一步增加了 `Conv` 层的数量。其成功得益于硬件资源的可用性，能够支持大量训练计算。然而，过深的层序会因消失梯度问题而变得困难。随着网络深度增加，梯度的幅度急剧下降，早期层的梯度可能很小，从而阻碍正确的训练。

*   **`ResNet`** \[[84](#refbib.xhtml#refbib84)\] (2015)：为克服消失梯度问题，残差网络（ResNets）在 `Conv` 层序列之外引入跳跃连接。该结构使网络深度可达 200 层。此外，还引入了批量归一化层作为正则化策略。

*   **`MobileNet`** \[[93](#refbib.xhtml#refbib93)\] (2017)：该模型基于深度可分离卷积。其结构比传统卷积 DNN 执行更快，因而适合在移动设备上实现。

*   **`NasNet`** \[[291](#refbib.xhtml#refbib291)\] (2018)：它是最早通过神经架构搜索（NAS）获得的 DNN 模型之一。它开启了通过求解优化问题（目标是最大化准确率）来确定 DNN 架构的常见趋势。

### 2.1.4 DNN Hardware Architectures

DNNs 是一类具有内在并行性的算法，可通过并行计算实现高效实现 \[[23](#refbib.xhtml#refbib23)\]。在硬件层面，它们基于大量 *Processing Elements (PEs)*，这些 PEs 能够并行执行操作。它们可分为空间架构和时间架构 \[[262](#refbib.xhtml#refbib262)\]。其基本功能概览如 [Figure 2.3](#chapter2.xhtml#fig2_3) 所示。在时间架构中，控制是集中化的，因为 PEs 只能从中央内存获取数据，而不与其他 PEs 直接连接。相反，在空间架构中，每个 PE 可能拥有本地存储单元和自己的控制逻辑。最重要的是，空间架构中的 PEs 相互连接以交换数据，从而形成 PE 阵列。

#### 2.1.4.1 Temporal Architectures

时间架构通常用于通用处理器，如 CPU 和 GPU。CPU 可以实现为向量处理器，能够同时处理多个数据元素。向量处理器包含多个算术逻辑单元（ALUs），能够同步在向量数据上执行指令。因此，向量处理器采用单指令多数据（SIMD）范式。GPU 是专为大规模并行计算设计的 manycore 架构，拥有数千个核心。类似于向量 CPU，GPU 采用单指令多线程（SIMT）范式。Nvidia 最早提出了 SIMT 模型，它能够在多个核心上同时执行单一指令。每个核心接收不同的数据，对应于并行运行的多个线程。得益于 PyTorch \[[204](#refbib.xhtml#refbib204)\] 和 TensorFlow \[[1](#refbib.xhtml#refbib1)\] 等流行的机器学习框架对 Nvidia GPU 的支持，GPU 是训练大型复杂 DNN 的常用平台。在底层，cuDNN \[[34](#refbib.xhtml#refbib34)\] 是一种用于将 DNN 映射到 GPU 的优化库。在高端 Nvidia GPU 中，传统的 CUDA 核心与 Tensor Cores \[[167](#refbib.xhtml#refbib167)\] 结合，Tensor Cores 专门用于大矩阵运算。

#### 2.1.4.2 Spatial Architectures

空间架构针对特定任务进行定制和优化，灵活性较低，通常在 FPGA 或 ASIC 上实现。由于 DNN 的操作序列在设计时已知，DNN 非常适合此类实现。计算基于大规模的简单乘加（MAC）操作。因此，获取输入并存储 MAC 结果的内存访问成为性能瓶颈。此外，最新的 DNN 加速器的 DRAM 访问能耗远高于 MAC 能耗 \[[262](#refbib.xhtml#refbib262)\]。由于 DRAM 成本高昂，DNN 加速器主要关注利用 *数据复用*，即通过优化架构和数据流，在寄存器文件或缓冲区中复用权重和特征图，从而减少 DRAM 访问。利用数据复用的不同技术归类于 \[[30](#refbib.xhtml#refbib30)\] 所提出的数据流分类（见 [Figure 2.4](#chapter2.xhtml#fig2_4)）。

*   **`Weight Stationary`**：它利用权重复用，最小化从 DRAM 读取权重的能耗。由于权重在 PEs 中保持静止，输入和部分和会在 PE 阵列中协同移动，以优化数据搬运。Weight Stationary 数据流特征是空间展开操作，即将 *for* 循环替换为 *parallel for* 循环。该映射相当于从软件角度对循环进行重新排序。Weight Stationary 数据流的示例是 Tensor Processing Unit (TPU) \[[100](#refbib.xhtml#refbib100)\]，其中静止权重存储在 PEs 中，输入特征图水平向前传播，部分和沿垂直方向累加。

*   **`Output Stationary`**：它最小化将部分和存储到并从全局缓冲区（GLB）加载所需的数据搬运。使用 weight stationary 数据流时，单个输出值的部分和需要多次存储和重新加载到全局缓冲区；而在 output stationary 数据流中，每个 PE 被修改为本地累加 MAC 结果。每个 PE 计算获得输出特征图所需的全部操作，因为部分和被累加到单个寄存器中。采用 output stationary 数据流的热门架构是 ShiDianNao \[[46](#refbib.xhtml#refbib46)\]，其 2D 阵列中的每个 PE 计算单个输出特征图的值。此时，权重在每个操作周期广播到所有 PEs，输入特征图水平向前传播。
