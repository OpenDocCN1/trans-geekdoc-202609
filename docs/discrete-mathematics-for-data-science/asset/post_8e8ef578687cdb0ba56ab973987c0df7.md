### Abstract

Being able to distinguish between simple and complex data types is an important basic skill for data science.

There are generally two types of data. There is a single number that, by itself needs no interpretation. It is _atomic_ in that it is irreducible and we can refer to it as a singular object or element. Atomic elements may also be referred to as foundational or _primitive_ elements. Conversely, there are complex data that are the organization of a collection of both primitive and other complex elements, as well as functions. Such element organizations may be referred to as _abstract data types_ or simply _abstractions_ and are often symbolized by a name.

### 2.1 THE MEANING OF DATA

#### 2.1.1 Atomic Data

Data elements that are *atomic* are irreducible.¹ That includes singular numeric data that is not associated with other values in some collection or abstract object. Such singular or atomic data includes numbers like integers and fractional numbers, as well as characters. In a machine's context, at the hardware level, a single value of data is represented in a binary, base 2, format.

¹The word “data” is from Latin and is the plural form of datum. In English technical works, data is often used as a singular concept.

In terms of a programming language's compiler, a program that translates source code into machine code, the characters of its syntax are associated with integers that, these days, conform to the *Unicode Standard*. Each character is a glyph, a graphical representation of the character. And each character is associated with a particular integer in accordance with the Unicode Standard.

The image of the glyph is, itself, actually a file consisting of data. During compilation, the numeric values that are assigned to Unicode characters are ingested into a data structure. A data structure is a particular organization of data. Data structures are discussed in depth in the *Data Organization* section of this book.

A single atomic data value will fit into a single register of a computer's *Central Processing Unit (CPU)*. The register is a container for the 1 and 0 bits that comprise the CPU's binary data and instructions. On the typical retail computer these days, a single register accommodates a 64 bit number. Memory, on the other hand, is usually stored in bytes (eight bits each), meaning that a 64-bit number occupies eight addresses in memory.

Boolean types are the simplest atomic values, as they merely evaluate to true and false. In machine terms, that is 1 for true and 0 for false. Such Boolean logic in terms of 1s and 0s forms the logical basis of computer architecture.

For example, to evaluate whether or not two numbers, 5 and 5, are the same, one might use a built-in word NEQ, for *not equivalent*. NEQ results in 1 if the statement is true and 0 if the statement is false.

```
5 5 NEQ ( → 0)
```

Conversely, one may wish to define elaborate words for evaluating equivalency in terms of *true* and *false*, such as:

```
{ 1 } t WORD ( define t as 1)
{ 0 } f WORD ( define f as 0)
{ 1 EQ t f ?? } true WORD ( define a true condition)
{ 0 EQ t f ?? } false WORD ( define a false condition)
1 true ( → 1 for true)
1 false ( → 0 for false)
```

Incidentally, the definitions in the above code which consist of other values are abstractions. That includes the definitions for *true, false, t,* and *f*. Conversely, those values which cannot be reduced, such as the numbers in the definitions, are considered atoms. The ?? symbol is an alias for IFELSE, which in this case activates either *t* or *f*, depending on the Boolean output of EQ. (More context to the above syntax is provided in Appendix A, Coding Conventions.)

The Lisp programming language might be the first to define a single element called an *atom*. Because a value such as a number is irreducible, it was referred to as an atom, a term that was probably coined around 1958 by Lisp's inventor, John McCarthy. Lisp also considers a single word (known in computer science as a *string*) to be an atom, leading to some debate. 2

Atoms are evaluated when they are invoked (executed). That is, the simple statement of a word or datum is enough to execute it and expose its behavior. However, evaluation may be postponed until the word is needed at a later time, as is the case when a word is a component of another word's definition. Such treatment is a form of what is referred to as *lazy evaluation*.

The following example in *epop* demonstrates the difference between immediate and lazy evaluation. First, two lists x and y are defined. Then, a list xy is defined that contains two uninvoked list definitions, x and y:3

```
{ 1 2 } x LIST
{ 3 4 } y LIST
{ x, y, } xy LIST ( The commas delay evaluation of x and y.)
```

Invoking xy will, in turn, invoke the LIST constructors of each of its constituent members, x and y.

```
xy
{ 1 2 } x LIST { 3 4 } y LIST ( The result of xy.)
```

Alternatively, consider if xy were defined to allow the immediate evaluation of its members, x and y, such as:

```
{ x y }xy LIST
```

Then, the contents of xy would be { 1 2 3 4 }.

When functions are treated as data, they may be referred to as higher order functions, a concept germane to the modern discipline of functional programming. Higher order functions can either take functions as arguments or return functions as a result.

For example, the word IFELSE in the code below takes as arguments the words if and else, evaluating if only when istrue? is true, with 2 being the result. Otherwise, else is evaluated, with 5 being the result. (Note that istrue? is defined here to randomly select 0 for false or 1 for true.)

```
{ 2 } if WORD
{ 5 } else WORD
```

#### 2.1.2 Abstract Data

Data is not limited to simple characters and numbers. There are also custom or user-defined data types. These are known as abstract data types, or ADTs. An abstract data type may consist of primitive values, such as characters, numbers, and functions, as well as other abstract data types. Forms of abstraction include the names (variables) associated with data values and machine instructions (functions).

The primitive values that ultimately comprise abstract data are the lifeblood of computers. At the lowest levels of a computer, machine instructions are given as binary operational codes or opcodes.
