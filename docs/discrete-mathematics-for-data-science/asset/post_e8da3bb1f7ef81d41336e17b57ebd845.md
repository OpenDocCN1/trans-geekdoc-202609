
A lambda expression is a nameless function containing functions and/or data. A lambda expression may formally be referred to as a *combinator* if it has no external dependencies. Words inside of lambda expressions, such as { w1 w2 ... wN }, can serve as arguments for other words following the expression in a postfixed operation. For example, a lambda expression may be used temporarily to define a new word, such as:

```
{ DUP * } square WORD
```

The words enclosed inside the { braces } of a lambda expression may be referred to as *higher order functions*, as they are passable to other functions (words). For example, consider the following statement that increments a variable n:

```
n = n + 1
```

Here, n + 1 is assigned to the variable n.

Likewise, in *epop* we can define a word called n+. This example uses *epop*'s pre-existing i+ word to increment by 1 the value on top of the data stack:

```
{ n @ i+ n ! } n+ WORD
```

To test this new word, initialize the variable n to 0 as:

```
0 n !
```

Apply n+ a couple times by entering:

```
n+ n+
```

To see the new value of n, use the @ symbol:

```
n @ . CR -> 2
```

Those versed in *functional programming* might ask if *epop* facilitates currying.¹ For *epop* as well as Forth, currying seems *inapplicable*, with *values sequentially processed* from the top of the data stack. Nonetheless, we can finagle a word to behave in a curried way. Consider here the word *csos*, for a curried sum of squares:

```
{ DUP * + 0 > ? } csos WORD
3 csos 4 csos .
25
```

Because curried functions process only one argument at a time, the function *csos* must be invoked twice in order to exercise two arguments.

Note the difference between a word sequence and a word that uses a proceeding word as an argument. Consider the word sequence: word1 word2. If word1 outputs to the data stack and word2 uses the data stack, then word2 will depend on word1. This is because word1 is invoked first.

Due to the compiler's compilation techniques, certain words cannot be used directly as arguments. These include the following words: EAGER, WORD, EXEC, LE, UIF, IFELSE, LREPEAT, LWHILE, ELE, ECOMPILE. A workaround to use these words as arguments is to define a temporary wrapper word. For example:

```
{ UIF } wrapper WORD
```

Pipes are useful for directing output to a certain place within the sequence of a subsequent expression or word. For example, if w2 is defined as:

```
{ DUP * | | + } w WORD
```


## B.5 DEFINING NEW WORDS

New words can be defined a couple of different ways:

- 1. Using the prefixed “:” compile operator and then terminating definitions using the “;” end-compile operator.
- 2. Using braces { } to enclose the word definition postfixed by the name and WORD.

Here are some examples:

```
: myword w1 w2 ;
```

This operation literally “compiles” myword, meaning that its definition is appended to the epop dictionary. If myword already exists in the dictionary, then its definition is updated.

Alternative postfixed syntax for defining a new word is:

```
{ w1 w2 } myword WORD
```

Words can be defined in terms of other user-defined words or abstract words, as well as primitive words. User-defined words decompose to primitive words (functions) on the program stack. Because of this, user-defined words are also referred to as *reference* words. The composition of a reference word is displayed by using the SEE word, such as:

```
myword ' SEE
w1 w2
```

## B.6 TICK WORDS

TICK symbolized as “ ’ ”, saves the execution token of a word to the data stack for delayed (lazy) evaluation (similar to a function pointer in C). For example, we can store a mini program on the data stack such as:

```
4 5 + ' 7 8 - '
```

We can then run that stored program from the data stack with the following instructions:

```
{ EXEC >> } 2 LREPEAT
-1
9
```

The “>>” operator rotates the value on the top of the stack to the bottom of the stack, allowing LREPEAT to execute all of the operations on the data stack.

There is special handling of in-line expressions containing tick words. For example, the following four expressions each give the same result of 8:

```
3 5 + '
3 5 { + ' } LE
3 5 + '
+ ' 3 5 GSC i- MOVE
```

Note that “LE” executes a lambda expression and “GSC i-MOVE” moves 2nd value from the bottom of the data stack to the top, where GSC provide the count of items on the data stack.

Two notable words are HD and TL, for getting the head and tail of lists. In terms of stack oriented lists, the head of a list is the element at the bottom of the stack, and the tail of a list consists of all elements in the stack except the head element. Many function definitions can be based on HD and TL. Even though HD and TL are built-in to epop, for the sake of explanation, one could define them in epop as follows.

```
( Remove all but the first element on the stack. )
: hd DROP ' GSC 2 - REPEAT ;
( Fetch the first item from the stack and drop it. )
: tl GSC i- MOVE DROP ;
```

HD and TL are considered list reducers. Similarly useful list reducers in functional programming are fold left and fold right functions. Starting from one end of a list, these functions apply a specified operator to each element of a list, “folding” the result into the next element in the list until there is a final value. A fold right function starts at the leftmost value in a list and “folds” to the right. A fold left function does the opposite. A fold left application can be understood by examining the following foldl definition and invocation, which results in 25:

```
{ GSC i- REPEAT } foldl WORD
1 3 5 7 9 +' foldl .
25
```

If a word is defined with component words or lists that are changed in some way, then these component words must be followed by a tick “ ’ ” mark (made a _tick word_). Otherwise, the elements of the original word or list will be employed. For example, the following task updates a data list, replacing it's x's with y's.

```
{ 1 x 3 x 5 x 7 x 9 } data LIST
{ DROP y } replacement WORD
{ x } target WORD
{ DUP target EQ replacement ? >> } task WORD
{ { task } GSC LREPEAT data ’ S2LIST } update-data WORD
data
update-data
```

Now the data list will be { 1 y 3 y 5 y 7 y 9 }.

## B.7 INLINE WORDS

Inline words expect their arguments to proceed them on the same line (and not from the data stack). There will be an error message otherwise. The following are inline words:

- UIF ( alias ?)
- IFELSE ( alias ??)
- PIPE ( alias —)
- TICK ( alias ’)
- WORD

## B.8 WORD OVERRIDES

Abstract words can be redefined, as they are *overridable*. User-defined words are abstract words.

Primitive words are not overridable. Therefore, if a primitive word requires modification, then consider wrapping it in an abstract word. For example, suppose we want an addition operation that automatically emits the result. We can define a word myadd that wraps the addition operator “+” followed by the *pop* operator denoted “.” and “CR” (carriage return) to display the result.

```
{ + . CR } myadd WORD
1 2 myadd
3
```

## B.9 DEEP COPY VS SHALLOW COPY

Words can control their own data and need not only reference the data of the other words comprising their definitions. That is, words may get a *deep copy* of data from their constituent words. For example:

```
: lista 2 4 6 8 ;
: listb lista ;
listb ’ SEE
2 4 6 8
```

Consider now if we re-define lista:

```
: lista 1 3 5 ;
listb ' SEE
2 4 6 8
lista ' SEE
1 3 5
```

Note how the two data sets remain independent. listb maintains the original lista elements, { 2 4 6 8 }, even though lista was later changed. We say that listb has a deep copy of data as opposed to a shallow copy. A deep copy makes words immune to the changes to data (side-effects) of their constituent words.

Conversely, a *shallow* copied word will have its changes reflected in the host word. One way to make a shallow copy of a word is to use the TICK " ' " mark. For example:

```
: listc 1 2 3 ;
: listd listc ' EXEC ;
: listc 4 5 6 ;
listd ' SEE
4 5 6
```
