## 13.2.1 Big-O: The Worst Case Scenario

The worst case scenario for an algorithm's efficiency corresponds to its upper bound as the problem size grows. By definition, Big-O represents the worst case scenario.

Suppose the function f(n) represents the problem size of an algorithm for input size n. The function representing the upper bound of f is g(n). The relationship of functions f(n) and g(n) for some input n and a positive constant c is:

```
f(n) = O(g(n)), as n increases,
where f(n) ≤ c · g(n)
```

In other words, the growth rate of f(n) is proportional to, or less than, the growth rate of g(n). The statement f(n) = O(g(n)) can be thought of as “the problem size has a maximum growth rate of g(n)," and O(g(n)) is called the algorithm's Big-O.

To show that f(n) = O(g(n)), we show that the function f(n) is limited by the upper bound of g for all n. This relationship is proven by ignoring constant factors, such as c, and non-recurring operations.

For example, to find the Big-O for the function:

```
f(n) = n + 1
```

first note that 1 ≤ n, for all n ≥ 1. Then substitute n for 1 in f(n) = n + 1 as follows:

```
n + 1 ≤ n + n = 2n, for n ≥ 1
or: f(n) ≤ 2n, for n ≥ 1
```

If we let g(n) = n, then we have f(n) ≤ 2 × g(n), for n ≥ 1.

Thus, the Big-O for f(n) is O(n) and we can write f(n) = O(n).

As another example, to find the Big-O for f(n) = 5n + 8, note that 8 ≤ 8n, for all n ≥ 1. Substituting for 8, we can reason:

```
5n + 8 ≤ 5n + 8n = 13n for n ≥ 1
```

So, we can conclude:

```
5n + 8 ≤ 13n for n ≥ 1
```

We can rewrite the above as:

```
f(n) ≤ 13 × g(n) where g(n) = n
```

Thus, the Big-O for f(n) is O(n) and we can write f(n) = O(n).

## 13.2.2 Worst vs Average vs Best Case Scenarios

Consider a search algorithm, where a comparison operation is repeated until a targeted value is found in some data structure. The count of repetitions will be somewhere between 1 and n.

For example, the following code searches a list of numbers for a target value of 5:

```
{ >> DUP target @ EQ > R search ?? } search WORD
{ search R > target @ EQ. CR } findnum WORD
5 target !
```

```
1 3 5 7 9
findnum ( returns 1 for true and 0 for false)
```

While the search may be satisfied by any element before the n^th, the upper bound, we still assume the worst-case scenario, n, or O(n) in Big-O. That includes the Average-case complexity, denoted Big-Theta such as Θ(f(n)). So, with n/c operations with some constant c, the Big-O is expressed as O(n).

Thus, the average case has the same order of magnitude as the worst case for this algorithm. This makes sense as we do not know n in advance. Therefore, n can represent any size, including the worst case scenario.

If we were instead interested in the best-case scenario, the lower bound, then our notation is technically denoted as Ω(1), a notation called Big-Omega. Big-Omega occurs when the sought element is expected to be found in the very first operation. This is characteristic of operations on sorted data structures where a single direct or random access to the structure affords the result.

If the solution is defined by performing a specific number of operations, such as where n is the integer 100, then we effectively have a constant time complexity, or O(1).

## 13.2.3 Algorithm Efficiency vs Elegance

The more elegant or concise algorithm is not always the better performing algorithm.

Consider the time complexity of the recursive Fibonacci function, detailed in the Repetition & Recursion chapter.

The Fibonacci numbers, f(n), are recursively defined as:

```
f(1) : 1
f(2) : 1
f(n) : f(n - 1) + f(n - 2), for all n ≥ 3
```

Accordingly, any value in the Fibonacci sequence, beginning with the third term, is the sum of the previous two terms.

An algorithm that uses the above recursive definition to generate the \(n^{th}\) term in the Fibonacci sequence requires a large number of steps as \(n\) increases. The function that represents an upper bound of the time complexity is \(g(n) = \phi^n\), where \(\phi = (1 + \sqrt{5})/2\). \(\phi\) is known as the _golden ratio_, the irrational number 1.618...

As concluded by proofs using induction that are beyond the scope of this text, \(O(\phi^n)\) is the time complexity of the recursive Fibonacci algorithm. Nonetheless, we can see where the value \(\phi = (1 + \sqrt{5})/2\) originates. These proofs generally involve the equation \(\alpha^n = \alpha^{(n-1)} + \alpha^{(n-2)}\) which, when \(n = 2\), is the quadratic equation \(\alpha^2 = \alpha + 1\). Using the quadratic formula gives a positive solution of \(\alpha = (1 + \sqrt{5})/2\).

However, an algorithm for generating Fibonacci numbers need not be so inefficient. Consider the following non-branching _epop_ code that, despite being recursive, has \(O(n)\) time complexity. This is accomplished by building the Fibonacci sequence on a stack while decrementing \(n\) from its original input value until it is not greater than 2.

```
10 n !
{ n @ i- DUP n ! } n- WORD
{ DUP2 + n 2 > fibonacci ? } fibonacci WORD
1 1 fibonacci ( → 55)
```

The above approach to generating a Fibonacci number is referred to as _memoization_. The term derives from the Latin word “memorandum,” meaning “to remember.” Memoization leads to greater efficiency, as when expensive computations are avoided by storing interim results in a data structure, such as a stack in the above example. When a memoized solution overlaps with a prior memoized solution, as when the computation of a Fibonacci number depends on a previous computation, the approach may be referred to as _dynamic programming_.¹

Memoization can make branching algorithms more efficient as well. For example, the above fibonacci function can be modified to include two recursive calls as follows. The time complexity is still \(O(n)\), as there are \(2n\) operations.

```
10 n !
{ n @ i- DUP n ! } n- WORD
{ n- 2 > } checkn WORD
{ DUP2 + checkn fibonacci ? checkn fibonacci ? } fibonacci WORD
1 1 fibonacci ( → 55)
```
