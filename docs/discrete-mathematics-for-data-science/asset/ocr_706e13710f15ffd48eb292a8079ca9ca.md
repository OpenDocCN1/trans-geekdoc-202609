```
{ >> DUP target @ EQ > R search ?? } search WORD
{ search R > target @ EQ. CR } findnum WORD
5 target !
```

```
1 3 5 7 9
findnum ( returns 1 for true and 0 for false)
```

While the search may be satisfied by any element before the n^th, the upper bound, we still assume the worst-case scenario, n, or O(n) in Big-O. That includes the Average-case complexity, denoted Big-Theta such as Θ(f(n)). So, with n/c operations with some constant c, the Big-0 is expressed as O(n).

Thus, the average case has the same order of magnitude as the worst case for this algorithm. This makes sense as we do not know n in advance. Therefore, n can represent any size, including the worst case scenario.

If we were instead interested in the best-case scenario, the lower bound, then our notation is technically denoted as Ω(1), a notation called Big-Omega. Big-Omega occurs when the sought element is expected to be found in the very first operation. This is characteristic of operations on sorted data structures where a single direct or random access to the structure affords the result.

If the solution is defined by performing a specific number of operations, such as where n is the integer 100, then we effectively have a constant time complexity, or O(1).

# 13.2.3 Algorithm Efficiency vs Elegance
