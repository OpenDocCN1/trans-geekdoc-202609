## Linear Structures

DOI: 10.1201/9781032687759-16

### Abstract

Before dealing with the complexities of branched structures, the data scientist should have a firm grasp of the simpler linear structures. Linear structures are fundamental data collections in data science and they accommodate the processing of sequences of data.

Linear structures have connected elements with each element having one leader and one follower, with exceptions for the first and last elements. The term connection is synonymous with linking, as in linked lists. Linear structures include arrays, lists, stacks, queues, random access lists, and sorted lists. Lists and arrays are commonly used in programming languages as the basis of other structures, including stacks and queues.

### 16.1 PROPERTIES OF LISTS

A list is a finite sequence of elements of the same data type, in a particular order. It may include duplicated elements. Lists are the basis of *sorted lists*, *stacks*, and *queues*, which are common data structures in data science. Strictly speaking, lists do not have *random access* capability, though this condition is relaxed for some practical applications.

Random access is a property that allows immediate or direct access to any element, without having to traverse (cross over) other elements in the structure. This contrasts with *sequential access* which requires traversing a hierarchical order before reaching a targeted element.

A list may be illustrated as connected objects.

![](img/ff796e63b14a88ab72583e78f3994e90_351_0.png)

Figure 16.1 A connected list of objects.

Because order matters, each element of a list depends on a preceding element and a following element.

A list can simply be comprised of numbers or characters, as long as it is one type or the other.¹

A list can also consist of a finite set of objects that conform to the same predefined definition. A list can include other lists (for a list of lists) and abstract type objects, wherein each object may represent a variety of other data types.

Any of the following sequences is a list, with or without commas:

- a, b, c, x, y, z
- 5 7 2 8
- cat dog goat

As can be seen, list elements can have different delimiters or separators. Typically either commas or spaces are used as delimiters.

![](img/ff796e63b14a88ab72583e78f3994e90_352_0.png)

Figure 16.2 A connected list of characters.

To distinguish lists from non-list entities, enclose the list with open { and closing } braces. For example, the following sequence is of two lists of characters followed by an operation.

```
{def}{hij}operation
```

1In data science and computer science, the term for a list of characters is string, also known as a word. If the sequence were infinite, the applicable term would be stream. In mathematics, a list is more commonly called a tuple.

Presenting the list in braces as such suggests an implicit naming of the lists, such as \( l_0, l_1, ..., l_N \). In other words, the above entry is effectively:

```
l_0 l_1 operation
```

Alternatively, explicitly defining lists better distinguishes the lists from other data. For example, we can construct and name an empty list, or null list, by using a list constructor operation named LIST as follows.

```
{ } l_0 LIST
```

Or we could create two named lists that contain some data:

```
{ a b c } l_1 LIST
```

```
{ x y z } l_2 LIST
```

We could then use these list labels for list operations, such as:

```
l_1 l_2 operation
```

### 16.2 STANDARD LIST OPERATIONS

Lists are generally expected to accommodate the following operations:

- Append: Put a new element on the back of a list.
- Insert: Put an element somewhere in a list.
- Concatenate: Attach one list to the back of another list.
- Remove: Remove an element from a list.
- Retrieve: Retrieve an element from some place in a list.
- Map: Apply a function to each element of a list.
- Reduce: Apply an aggregating function to a list (such as adding all elements together).
- Length: Return the length (size or count) of a list.

There are other names for the above operations. For example, *reduce* is also known as *fold*, and *append* may be referred to as *push*. Additional aliases will be introduced below.

The *cardinality* of a list is its element count or length. We denote the cardinality of a list *l* as:

![](img/ff796e63b14a88ab72583e78f3994e90_354_0.png)

By getting the length of a list, we effectively check if it is empty. For example, applying an operation called LEN to a list *l* retrieves its element count:²

```
l:LEN ( → 3)
```

Because order matters, two lists are equivalent only if they contain the same elements in the same order. For example, given:

```
{ x a y b } l₀ LIST
{ x a y b } l₁ LIST
```

Therefore,

```
l₀ l₁ EQ ( → 1(true))
```

Here, the EQ word signifies an evaluation of equivalence.
This is called a Boolean operation because it results in one
of two outcomes, true or false. Boolean operations are
covered in the Propositional Logic chapter.

Due to the connectedness of list elements, element access
depends on sequential processing, with one element
traversed before reaching the next. Such list processing
can be done by various list functions that are typically
predefined in programming languages.

The head of a list is defined as the first element that was
put into a list. The tail of a list is defined as a list of all of its
elements, excluding the head.

Suppose the operation HD retrieves the head of a list and
the operation TL retrieves the tail of a list. Therefore,
given:

```
{ x a y b } l0 LIST
```

The head:

```
l0 HD ( → x)
```

The tail:

```
l0 TL ( → a y b)
```

We could use that same operation to assign a new list, l1:

```
{ l0 TL } l1 LIST
```

To see the composition of $l_1$, use the SEE operation:

```
l1 'SEE ( → a y b)
```

With mere repetition of head and tail operations we can achieve somewhat complex list processing, as would be done for computing statistics. However, to be practical, such operations should be relegated to functions that we define, if not predefined in the programming language being used.

To append an element to the back of a list:

```
{ x a y b } z PUSH ( → { x a y b z })
```

To concatenate two lists:

```
{ a b c }{ x y z } CONCAT ( → { a b c x y z })
```

To append an element to the front of a list:

```
{ z }{ x a y b } PUSH ( → { z x a y b })
```

To multiply all values in a list by 2, a map operation can apply a function, defined here as *double*, to each element in the list:

```
{ 2 * } double WORD
{ 2 4 6 8 } double MAP ( → { 4 8 12 16 })
```

The sum of a list numbers can be obtained by using a fold left operation:⁴

```
0 2 4 6 8 + FOLDL ( → 20)
```

Note how the fold operation results in a single value, while the map operation alters all values in a list.

³Please refer to the Functions & Abstractions chapter.

⁴In functional programming, fold left and fold right functions are known as list reducers, as they fold each item of a list into the initial value, at right or left respectively.
