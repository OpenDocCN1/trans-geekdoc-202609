## 17.3.6 Graph Traversal

The origin or start of a graph's traversal can be from any vertex. Traversing a vertex does not require accessing its data. That is, the vertex need not be visited during its traversal. Only connected vertices can be traversed.

The general methods of graph traversal are Depth First Search and Breadth First Search. Note the key terms, depth - exhaustively visiting the first neighbor of each neighbor before moving to the next neighbor, and *breadth* - exhaustively visiting each neighbor in succession.

Because graphs do not necessarily have levels like trees and may also have cycles, level-order traversals are usually not relevant. However, if the graph had no cycles such that we actually had a tree, then the breadth-first search would correspond to a level-order traversal, and the depth-first search would correspond to a pre-order traversal.

A depth-first algorithm starts with a neighbor of the origin, and proceeds to a neighbor of that neighbor, and so on, advancing as far as possible from the origin. A stack data structure is typically used, ensuring that each path of neighbors is traversed in reverse to get back to the origin.

The general algorithm for a depth-first search:

- 1. Select an origin vertex.
- 2. Create a list of adjacency stacks (a list of sublists).
- 3. Compare the first adjacent vertex's value to the searched value.
- 4. Move to that neighbor's first adjacent neighbor and so on.
- 5. When the depth is exhausted, backtrack to the origin, successively popping the stack if using a stack.
- 6. Repeat steps 3 through 5 with the next neighbor, then the next neighbor's neighbor, etc.

For a variation on the depth-first search, consider a graph given as a list of lists, where in each list is a value a list of adjacent vertices (delimited by “:”).

```
{ 2 b:d:f } a LIST
{ 4 e } b LIST
{ 9 b } c LIST
{ 8 e:f } d LIST
{ 1 c:f } e LIST
{ 3 c:d:e } f LIST

{ a b c d e f } graph LIST
```

To search the graph, say for the value of 9, first invoke the _graph_ list. While invoking each sublist, evaluate each element of the sublist, such as was done for the _linear search_.

Invoking a sublist allows us to evaluate its component vertices. For example:

```
a → 2 b:d:f
b → 4 e
e → 1 c:f
c → 9 ... a match in 4 iterations.
```

Unlike depth-first approaches, breadth-first algorithms traverse each neighbor of a vertex, before moving on to the first neighbor's set of neighbors, and then the second neighbor's neighbors, etc. Breadth-first algorithms commonly use a queue data structure to ensure that no neighbor is traversed more than once.

The general algorithm for a breadth-first search:

- 1. Select an origin vertex.
- 2. Create a list of adjacent vertices.
- 3. For each neighbor vertex, compare its value to the searched value.
- 4. Move to the next neighbor's neighbors.
- 5. Repeat steps 3 and 4.

Using the same graph above and the value 9 as the target, start the breadth-first search by invoking the graph list, and then each vertex sublist, without visiting the neighbors in the vertex.

```
a -> 2 b:d:f
b -> 4 e
d -> 8 e:f
f -> 3 c:d:e
e -> 1 c:f
c -> 9 ... a match in 6 iterations.
```

## 17.3.7 Graph Paths

Graph theory includes a category of problems for computing the shortest path between any two vertices. This involves computing the cumulative weights of all adjoining vertices between any two terminal vertices. The solution for a shortest-path problem is the path having the minimum cumulative distance. To avoid infinite loops, traversal of the graph must avoid cycles by not revisiting vertices.3

There are variety of complex algorithms for computing path lengths. Some are considered brute-force approaches, as they compute the shortest path between all vertex pairs. Such brute-force algorithms generally have O(n^3) efficiency. One example is the all-pairs or Floyd-Warshall algorithm. However, a variation on the breadth-first search is *Dijkstra's shortest path* algorithm, which has $O(n^2)$ efficiency.

## 17.3.8 Computing Distance

For computing distance, vertex objects need not contain data about edges. Instead, distance metrics may be obtained from vertex coordinates, provided the graph is mapped to an N-dimensional space. In this context, dimensions are analogous to factors.

Consider an analysis of two factors within a two dimensional X-Y plane. The Euclidean distance between any two element pairs (*a*, *b*) is computed as:

$$distance(a, b) = \sqrt{(a_1 - a_2)^2 + (b_1 - b_2)^2}$$

Figure 17.19 is a visualization of that distance.

The formula is still applicable when the points are in different quadrants of the coordinate system, as when \(a_i\) and/or \(b_i\) are negative.

For example, find the distance between \((-1, 5)\) and \((-10, 11)\):

```
distance(a, b) = \sqrt{(-21 - 10)^2 + (5 - -11)^2}
= \sqrt{(-12)^2 + (16)^2}
= \sqrt{144 + 256}
= 20 units
```

Consider the points in one dimension, on a number line, ranging from negative to positive. The distance between points \(a_1\) and \(a_2\) is:

```
d(a_1, a_2) = |a_1 - a_2| = \sqrt{(a_1 - a_2)^2}
```

Suppose that we have a negative point \(a_1 = -5\) and positive point \(a_2 = 7\). Calculate the distance between these points, such as:

```
d(-5, 7) = | - 5 - 7| = \sqrt{(-5 - 7)^2} = \sqrt{(-12)^2} = \sqrt{144} = 12
```

A similar pattern works to find distances in higher dimensions as well. For two points in 3-dimensions, \((a_1, b_1, c_1)\) and \((a_2, b_2, c_2)\), the distance between them is:

```
distance(a, b) = \sqrt{(a_1 - b_1)^2 + (a_2 - b_2)^2 + (c_1 - c_2)^2}
```

Given that the path between two pairs \((a_1, b_1)\) and \((a_n, b_n)\) is indirect and exists only via intermediary pairs \((a_2, b_2) ...\), the cumulative distance is computed as:

\( cumdistance(a, b) = \sum_{i=1}^{n} \sqrt{(a_i - a_{i+1})^2 + (b_i - b_{i+1})^2} \)

The iterations of this formula are elucidated as follows:

Distance between\((a_1, b_1)\) and \((a_2, b_2)\) :

\( i = 1 : \sqrt{(a_1 - a_2)^2 + (b_1 - b_2)^2} \)

Distance between\((a_2, b_2)\) and \((a_3, b_3)\) :

\( i = 2 : \sqrt{(a_2 - a_3)^2 + (b_2 - b_3)^2} \)

\(\vdots\)

Distance between\(n^{th}\) point and the point just before\(n^{th}\) point:

\( i = n - 1 : \sqrt{(a_{n-1} - a_n)^n + (b_{n-1} - b_n)^2} \)
