IEEE 754's bias computation allows us to represent negative numbers in an unsigned system. The concept is analogous to declaring that the number 127 shall represent the number 0, such that the number 120, for example, can then represent the number -7.

As an example. Consider an 8-bit binary floating point number for 0d123.456, which is equivalent to 0b011110111.01110100. This is a whole number part of 0d123, or 0b01111011, and a fraction part of 0d0.456, or 0b01110100.

+   1. First, convert 0d123 to binary. (Assuming that, by now, you already know how to convert 0d123 to binary, we exclude that conversion to binary in these steps.)

+   2. next, determine the fraction:
+   2⁻¹ = 0.5. 0.5 into 0.456? .... 0
+   2⁻² = 0.25. 0.25 into 0.456? .... 1 rem 0.206
+   2⁻³ = 0.125. 0.125 into 0.206? .... 1 rem 0.081
+   2⁻⁴ = 0.0625. 0.0625 into 0.081? .... 1 rem 0.0185
+   2⁻⁵ = 0.03125. 0.03125 into 0.0185? .... 0
+   2⁻⁶ = 0.015625. 0.015625 into 0.0185? .... 1 rem 0.002875
+   2⁻⁷ = 0.0078125. 0.0078125 into 0.002875? .... 0
+   2⁻⁸ = 0.00390625. 0.00390625 into 0.002875? .... 0
+   The fraction is 0b01110100.

+   3. Now normalize 11110111.01110100 as 1.111011101110100 × 2⁶ and discard the leading bit. The mantissa is 111011011110100 and the exponent is 0d6 or 0b110. Therefore, in terms of a 32 bit binary number, we have:
+   8 exponent bits → 6 + 127 exponent bias → 0d133 = 10000101.
+   23 mantissa bits → 111011011110100 + 000000000 for padding in unused bits.
