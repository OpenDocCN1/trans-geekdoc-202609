Accordingly, the performance is much worse.

O(n!): Factorial. Consider applying an operation to all possible permutations of n elements. Examples of this include _brute-force_ searches of all possible permutations. Such algorithms are extremely slow.

In summary, in evaluating the efficiency of an algorithm, we are interested in the worst case scenario, the upper bound of the problem size that may be met by the algorithm.

For algorithms whose problem size is represented by a polynomial function, the upper bound can be identified by observing the greatest exponent on the variable. For example, in the quadratic expression _n_<sup>2</sup> + 4_n_ + 2, 2 is the greatest exponent. Such _O_(_n_<sup>2</sup>) quadratic efficiency is shown in the following example code.

```
for (i = 0; i < n; i++)
for (j = 0; j < n; j++)
operation ... _n_<sup>2</sup> operations

for (i = 0; i < n; i++) {
operation
operation
operation
operation
} ... 4_n_ operations

operation ... 1 operation
operation ... 1 operation
```

The above code amounts to _n_<sup>2</sup> + 4_n_ + 2 operations, or _O_(_n_<sup>2</sup>) in terms of Big-O efficiency.
