## 3.2 COMPUTER NUMBERS

At the machine level, numbers are computed and stored as *binary*, which is a base 2 representation of the number. A computer's *Central Processing Unit* (CPU) operates on binary numbers in CPU registers, a series of binary 1s and 0s termed *bits*, for binary digits.

Registers nowadays are typically 64 bits wide. Memory allocations for 64-bit variables may be referred to as *double precision*, versus 32-bit *single precision* allocations, depending on the underlying architecture of the computing system (the CPU type and a program's instructions). There is more about the topic of precision in the *IEEE 754 Floating Point Standard* sections of this book.

The CPU stores and retrieves data from *computer memory*, where one byte (8 bits) of data is stored per memory address.

Different computers and programming languages require different amounts of memory space for storing numbers and characters. For example, a CPU with 32-bit registers will most likely have 32-bit memory addressing, with four contiguous bytes of memory required to store an integer.

For an alphabetical character, the first eight bits of a 32-bit register will typically map an integer representation of that character to one or two bytes of memory. That integer will accord with the character's Unicode value. For example, the character 'A' is represented by the integer 65 in Unicode. In 8-bit binary, the integer 65 is 01000001.

The total possible number of combinations of these eight character bits is 2^8, meaning that any one of 256 characters may be accommodated by one byte of storage, and a string of four characters may reside at a single memory address in a system that has 32-bit addressing.

Some mysterious programming errors can be avoided by ensuring that such *character encodings* are consistent across your programming environment. Therefore, it is common today for computing systems and languages to conform to the *Unicode Character Set*, which is generally accepted.

Unicode assigns a distinct integer to each character in a language locale, such as English. Unicode's predecessor is ASCII (American Standard Code for Information Interchange), which is now a subset of Unicode.[^1]

Inside operating system libraries are files of data that are used to generate alpha-numeric characters in various font styles. These character fonts are also known as *glyphs*. Each character's glyph is associated with a Unicode integer. Having such a number accommodates the machine's retrieval, sorting, searching, and other processing of text.[^2]

## 3.3 FILE EXTENSIONS

A file's extension will normally identify the type of data in a file. Common extensions are .csv, .html, .json, .sql, .txt, xml, and .yaml. However, binary files may have various extensions, such as .dat, .o, .obj, .png, and .raf. Further, executable binary files tend to have no extension in Unix and have the .exe extension in Windows.

## 3.4 COMPUTER NUMBER TERMINOLOGY

- Bit - A state of ON or OFF, or 0 or 1 in a machine's logic gate or register; a single place of memory. Bit states in computer hardware depend on voltage thresholds, such as 0v to 2v for OFF and 3v to 5v for ON.

- Binary Number - A base 2 number that is readily accommodated by a machine's logic gates and registers. Modern systems automatically convert a number's various base representations into binary to affect machine instructions. For example, binary 0b10101 is equivalent to decimal 0d21, where the binary number is identified by the 0b prefix and the decimal number is identified by the 0d prefix.

- Byte – 8 bits. Memory is addressed by byte and one byte is the minimum amount of data read into the CPU from memory.

- Nibble – A half-byte or 4 bits. A nibble allows storage of two 4-bit values in one byte.

- Word – 4 bytes for 32-bit systems or 8 bytes for 64-bit systems. Unless operating on single bytes or 2-byte half words, modern CPUs by default read data from memory into the CPU by word.

- Kilobit (Kb) – 1024 bits. A common unit used in describing data transfer speed per second.

- Kilobyte (KB) – 1024 bytes. A common unit used in describing memory usage.

- Octal – A base 8 representation of numbers. Octal is used in Unix file systems for designating file permissions. For example, octal 0o21 is equivalent to decimal 0d17, where the octal number is identified by the 0o prefix and the decimal number is identified by the 0d prefix.

- Hexadecimal – A base 16 representation of numbers. Base 16 eases the visualization of large numbers, such as memory addresses. Two hexadecimal digits store one full byte. One hexadecimal digit stores one nibble. For example, hexadecimal 0x21 is equivalent to decimal 0d33, where the hexadecimal number is identified by the 0x prefix and the decimal number is identified by the 0d prefix.

Hexadecimal is useful for viewing large numbers in a smaller space. Contrast that to binary, which entails long strings of 1s and 0s. Given that hexadecimal accommodates decimal digits 0 through 15, we use A B C D E F for the six digits 10 through 15. The decimal number 16 is 10 in hexadecimal, or 0x10.

Depending on the kind of program or computer hardware with which you are dealing, you may want to enforce a particular number base. If your program models a particular number of states, then that number base can be implemented.

For example, the use of octal in Unix/Linux operating systems conforms to the eight possible permutations of file permissions, representing a file's read (r), write (w), and execute (x) permissions. File permissions are designated using numbers 0 for none, 4 for read, 2 for write, or 1 for execute. Those numbers can represent up to a total of 8 levels of permissions, 0 through 7 (hence, the use of octal).
