
## 14.2.1 Element Access

Element access depends on the *connectedness* of the data collection.

With connected collections, sequential elements may be traversed until arriving at a particular index or value.

With unconnected collections, there is no structure to traverse and no permanent index. Therefore, element access requires random selection until arriving at a particular value, or until the collection is empty.

## 14.3 COLLECTION OPERATIONS

The various types of collections have both distinct and common operations.

Common collection operations with respect to single elements include counting, inserting, removing, replacing, searching, and retrieval.

Common operations that entail entire collections include copying and comparing two collections, as well as sorting connected collections.

Each of these operations have an *algorithmic efficiency*, depending on the specific implementation of the algorithm for the operation.

## 14.4 RELAXED PROPERTIES

Unconnected data as found in sets and bags is defined as unordered. However, to be practical for storage and processing, unordered data must actually exist in the machine in a structured collection, such as a list. Unorderedness is therefore assumed, as we ignore any index of the sequence in which the data was entered to keep the appearance of randomness.

For a formal set, having no duplicates and no order, the data processed from a list representing the set should be drawn at random. Thus, the requirements of the connected list structure are relaxed to allow direct, non-sequential, random access.¹

If we are interested in preserving order and duplicates within lists having set operations, then we should use a more relaxed variation of sets called a multiset.² The concept of the multiset accommodates multiple instances certain elements.

Data structures that are already ordered according to some trait of its elements, provide an expedient way to extract meaningful data via random access. For example, pre-sorted collections such as sorted lists, allow us to immediately determine values such as the maximum, minimum, median, and other elements that can be found at specific intervals. Therefore, in a practical sense, the sorted list and random access list are fairly synonymous.³

The indexing scheme of a data structure pertains to the ordered numbers or keys associated with its values. For a list, indexing is a typically a linear sequence of whole numbers, such as 0, 1, 2, ... For example, for the list { cat dog goat }, it might be that cat is at index 0, dog is at index 1, and goat is at index 2. Random access to a data structure will depend on the structure's indexing scheme. If the collection is not linear, but instead branched such as with trees and graphs, then the indexing will depend on a certain computation that accounts for branches, as discussed in the Branched Structures chapter.

## 14.5 UNCONNECTED DATA COLLECTIONS

A collection that is unconnected has elements free of order. This means that elements in the collection have no relationship to one another, apart from possibly being of the same type of object or value. Because these elements are unconnected, drawing them from a collection entails no particular sequence and is instead a random process. Collections of unconnected data include sets and bags.

## 14.6 LINEAR STRUCTURES

Linear data structures have connected elements with each element having one leader and one follower, with exceptions for the first and last elements. The term connection is synonymous with linking, as in linked lists. Linear structures include lists, stacks, queues, and sorted lists.

- A list, stack, or queue.
- Ordered by position.
- Each item has parent (except 1st).
- Each item has child (except last).
- The order and position together are meaningful (consider a step-by-step process).

## 14.7 BRANCHED STRUCTURES

Branched structures are hierarchical collections, namely trees and graphs, which are commonly based on linked structures. A tree is essentially a graph without loops.

Trees and graphs lend to modeling real-world systems that are more complex than linear systems. In systems engineering, consider the graph aspects of network topologies, or the tree-like hierarchies of operating systems processes and file systems. The indexing of trees and graphs can be mapped to various linear structures to facilitate processing.

Due to the branches in trees and graphs, access to an element from another element may be direct (the elements are adjacent) or indirect (the element is accessible via intermediary elements).

![](img/ff796e63b14a88ab72583e78f3994e90_335_0.png)

Figure 14.3 (a) A tree. (b) A graph.

Generally, relations between two data structures may be equal, identical, or isomorphic.

- Equal – The structure, data, and order are the same.
- Identical – The structure may differ while having the same data and order. Identical structures may or may not be equal.
- Isomorphic – The structures have the same form or shape. The data is irrelevant.

Two data structures are isomorphic if they can be mapped one-to-one to each other and preserve the relationships between vertices.

## Abstract

Data science relies conceptually on special data collections for random data referred to as _sets_ and _bags_, also referred to as _multisets_. Such collections have data elements that are _unconnected_ and, thus, free of order. This means that elements in the collection have no relationship to one another, apart from possibly being of the same type of object or value. Because these elements are unconnected, drawing them from a collection entails no particular sequence and is instead a random process. The process of selecting elements at random relies on a function called a _pseudo random number generator_.

## 15.1 BAGS VERSUS SETS

A bag is like a set, except that duplicates are permitted. Like sets, bags are unordered. Therefore, of the various types of collections, bags are the most unrestricted. Bags are also referred to as _multisets_.

Although element order does not formally matter for multisets, duplicate elements may be distinguished with subscripts denoting their order of selection, such as _e_<sub>0</sub>_e_<sub>1</sub>..._e<sub>n</sub>_.
