
a 3 OBJECT
b 7 OBJECT
c 5 OBJECT

Next, link object pairs by their common edge weights. For example, suppose that there exist the following edge weights linked vertices a, b, and c:

```
a - 0.52 - b
b - 0.65 - c
```

Provided that vertex objects and their linked weight are already on the data stack, in the sequences a b 0.52 and a c 0.65, then linking these vertices can be done by invoking the LINK word for each pair, such as:

```
b.o c.o 0.65 LINK ( → b.o)
a.o b.o 0.52 LINK ( → a.o)
```

The result of those linked instructions creates a root vertex object a, which internally references vertex object b, which itself internally references vertex object c. Each nested object is a neighbor of its encompassing object.

A nested series of objects in a root vertex can be extracted to reveal the component values, such as:

```
a EXTRACT → a 3 b 7 0.52 c 5 0.65
```

Objects can be traversed and their neighbors and data extracted as needed for searches or shortest-path computations.

Another reason for programming with objects is to protect function data. The incentive becomes more clear when we define multiple complex words with similar functionality, as we leave the door open to unintended side effects. The situation is compounded when operations involve a complex nesting of data structures, making resource conflicts more likely. For example, we may have multiple operations simultaneously vying for the use of a single data stack. In such cases, it would be better to have the data isolated and protected, as can be achieved by defining objects that contain their own data.

## 17.3.10 Graph Glossary

- Edge: A connection between a distinct pair of vertices.
- Subgraph: A graph that exists within a graph. Given G = G(V, E), a subgraph may be denoted as H = H(V', E').
- Digraph: A directed graph, wherein edges enforce direction of traversal.
- Connected graph: Defined by a path between any two vertices.
- Complete graph: A graph in which there exists an edge between every distinct vertex pair.
- Directed and complete graph: Each vertex pair is connected by two directed edges, one in each direction.
- Strongly connected: When a digraph has a path from every vertex to every other vertex.
- Weighted graph: the edges have numeric values in terms of weight, cost, distance, ....
- Degree of vertex: The number of edges incident to a vertex. The degree of vertex 1 can be denoted such as deg(v1) = 2.
- In-degrees and out-degrees: Pertain to the degrees in a directed graph.
- Isolated vertex: Has no degree of incidence (no associated edges).
- Regular graph: A graph in which every vertex has the same degree.
- Path: A sequence of connected vertices from an origin vertex to a destination vertex.
- Distance: The sum of the values for all intermediate edges of a path.
- Cyclic graph: When a path within a graph returns to a vertex within, a cycle exists.
- Acyclic graph: A graph with no cycles.
- Multigraph: When multiple edges connect the same vertex pairs of a graph. Not all vertices need be connected.
- Euler graph (path): A path through a finite graph that traverses every edge exactly once.
- Eulerian circuit: Euler path that ends and begins at the same vertex.
- Loop: When an edge connects a vertex back to itself (self-reference). Multiple loops on a single vertex can allow a graph to be a multigraph.
- Sparse graph: Most vertices of the graph are not connected.
- Dense graph: Most vertices of the graph are connected.

### Abstract

The mathematics of counting is important in data science with respect to the organization and analysis of discrete components of information. For the task of determining total possible outcomes for various scenarios, counting is considered fundamental for studies in statistics and probability.

Applications of counting relevant to data science include: Choosing the best path between points in the design of a system. Minimizing algorithmic complexity with various data structures. Analysis of symbols for encoding and decoding. And minimizing principal component combinations in highly dimensional data.

Computing the number of possible combinations of elements of a system is called combinatorial analysis and involves the mathematical principles of permutations and combinations.

### 18.1 BASIC COUNTING

Basic counting measures include the techniques of the sum rule and the product rule.

#### Sum Rule:

The sum rule is generally for problems having an OR condition between sets. The sum rule applies to the union of disjoint sets. The sum rule is stated as:

```
|A \cup B| = |A| + |B|
```

Suppose that one element is selected from among the elements of two sets, A and B. Then there are |A| + |B| possible selections. Note the mutually exclusive choice between the sets, a choice to select from one set or the other.

The sum rule can be extended to selecting one element from more than two sets. For example, suppose we have three disjoint sets containing integers, where set A has 4 elements, set B has 2 elements, and set C has 3 elements. The number of ways of selecting any one element from among these three sets is:

```
4 + 2 + 3 = 9
```
