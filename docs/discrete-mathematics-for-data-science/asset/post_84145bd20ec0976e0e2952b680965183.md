
For \( k \in \mathbb{W} \), assume that the statement “ \( P(k) : 3^k - 1 \) is even” is true. This means that in our work below, we can replace \( 3^k - 1 \) with \( 2m \), for some \( m \in \mathbb{W} \). (\( 3^k - 1 \) contains a factor of 2.)

Consider \( P(k + 1) : 3^{k+1} - 1 \). We must show that \( 3^{k+1} - 1 \) is also even.

```
3^{k+1} - 1 = 3 · 3^k - 1
               = 3(3^k - 1 + 1) - 1
               = 3(2m + 1) - 1, for some m ∈ W
               = 6m + 3 - 1
               = 6m + 2
               = 2(3m + 1)
```

Since \( 3^{k+1} - 1 \) contains a factor of 2, \( 3^{k+1} - 1 \) is even.

Therefore, by the inductive hypothesis, \( 3^n - 1 \) is even, for all \( n \in \mathbb{W} \).

## Abstract

An understanding of computability can help data scientists recognize the limits of algorithms. The feasibility of algorithms is an important consideration before embarking on substantial data science initiatives, before significant time and investment have been allocated toward presumed solutions. It could be that a problem is not solvable or that it may only be solvable after an extraordinary outlay of funds. It would be best if, in advance, the decision to proceed was based on the proven logic of computability.

Data science is concerned with empirical proof, evidence based on observed conditions from sets of data. However, observation is not always immediately possible because computations can take significant time. For such cases, mathematical logic expedites analysis of the relative performance of algorithms.

Empirical data is that which is encountered outside a model. Such data may be considered factual and may be recorded from the outside world. In contrast, logical data is internal to models, as it may be assumed or induced logically. The overlap of these concepts with respect to machine states is the essence of *computability*.

### 9.1 NP-COMPLETENESS

*NP-completeness* refers to problems for which there is a verifiable solution. *NP Completeness Theory* is concerned with *P* and *NP* problems. *P problems* are solved in *polynomial time* (also referred to as an algorithm's time *complexity*).¹ *NP problems* are solved in *non-deterministic polynomial time*.

The solution to a *deterministic problem* will be a certain expected result for a given set of inputs. In contrast, the solution to a *non-deterministic problem* can vary, even with the same set of inputs.

Polynomial time is a measure of the amount of work that an algorithm must perform in order to solve a given problem. Polynomial time is expressed in terms of *Big-O* notation, such as *O(n^k)*, where *n* is the input size and *k* is a constant. The “O” refers to the *order of magnitude*, the exponent *k*. (Hence, it may be said that an algorithm has a certain “Big-O”).

In computer science, algorithm efficiency is also known by the terms *time complexity* and *algorithm complexity*. An algorithm's complexity and its efficiency go hand-in-hand.

Analysis of algorithms for their time complexity allows us to estimate the relative performance of different algorithms and whether a problem might be solved quickly or slowly. These are important considerations for data science, where processing *Big Data* can require a significant investment in computing resources and run-time before a useful solution is discovered.²

¹Related concepts are covered in the *Algorithmic Complexity* and *Data Dimensions* chapters. ⇨

²Informally, *Big Data* is hereby defined to exist when its processing cost exceeds the value of your local processing resources. ⇨

In the *Theory of Computation*, problems are classified as *computable* or *decidable*. Computable problems are those for which computational solutions can be generated in a finite amount of time. Decidable problems are those for which a correct “yes” or “no” (or true or false) answer can be produced in a finite amount of time.

Computability is the broader concept, encompassing both computable and decidable problems. Determining if and when the upper limit of a program's repeating operation will be met is a matter of the halting problem. Think of cases where an algorithm is unable to arrive at a solution. Perhaps there is no possible solution and the algorithm was not given a condition by which to stop.

Suppose that we need to set n number of cycles for an algorithm to repeat:

```
operations 'n REPEAT
```

What should be the value of n?

There could possibly be an infinite loop in that the program runs indefinitely.³ Or, maybe the solution is simply not feasible for the current algorithm and machine. In these contexts the question of computability becomes one of decidability, as in: “Should the program proceed or stop?”

The bounded halting problem is one in which its number of steps, its bounds, is finite. That is, it is decidable. This contrasts with the general halting problem, which is undecidable.

At first thought, one might create an algorithm checker to verify if guest algorithms are decidable (able to complete task). A conundrum arises when a guest algorithm depends on the checker for input, and the checker in turn depends on the guest for its output. The general arrangement could look as follows:

```
{ input guest halts? checker ? } checker WORD
```

The checker program repeatedly checks the guest program with new input as long as the guest halts for some input. If the guest does not halt, then the checker waits indefinitely. Either way, the system runs forever and is undecidable.

³Related material is in the section titled *Infinite Cycles* in the *Repetition & Recursion* chapter.

In practice, attempting to solve the general halting problem may be considered an exercise in futility, as it is not possible to have a solution for all problems. Nonetheless, a study of the halting problem illuminates the limits of computation, making it not completely futile.

For example, the *epop* programming language includes statistical heuristics to guess if a user's running code is locked in an infinite loop. If so determined, rightly or wrongly, *epop* warns the user and eventually breaks the loop on the user's behalf.

In cases where a model's solutions are probabilistic rather than deterministic, each possible output state is assigned a probability. Such models may be referred to as *probabilistic state machines*.⁴
