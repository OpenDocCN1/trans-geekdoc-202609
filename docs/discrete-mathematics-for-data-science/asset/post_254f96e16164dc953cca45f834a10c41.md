
Or, the same application can be expressed as a partially and explicitly curried addition:

```
{ 0 + GSC 1 EQ add ? } cadd WORD
{ + GSC 1 > add cadd ?? } add WORD
1 2 4 add ( → 7)
```

Suppose f is a more complex function or operation and consider the following example of β reduction:

```
(λs.(s s) λf.(λf.f f)) → (λf.f λs.(s s)) → (λf.f λf.f) → λf.f
```

This series of lambda calculus reductions can be explained as follows:

- (λs.(s s) λf.(λf.f f)) reduces to (λf.f λs.(s s)).
- (λf.f λs.(s s)) reduces to (λf.f λf.f).
- (λf.f λf.f) reduces to λf.f.
- λf.f is the final result. This is an identity function.

Each step applies the beta reduction rule, substituting the argument into the body of the lambda function.

Consider next applying β reduction to ((λf.λx.(f x) x) b):

```
(b (a λf.λx.(a f))) → (b λa.(a a)) → (b b)
```

The argument x has been substituted in the scope of the bound variable x and appears to create a new occurrences of that bound variable. We can avoid this by replacing the bound variable x in the function with c:

```
(b (x λf.λc.(c f))) → (b λc.(c x)) → (b x)
```

The replacement shown above is a form of alpha conversion. A name clash arises when a β reduction places an expression with a free variable in the scope of a bound variable with the same name as the free variable. Alpha conversion removes the name clash.

### 12.4.1 Other Conversions

Eta η conversion: An eta specifies a different function that gives the same results, such as λx.fx. Substitution by a longer function is η-expansion and substitution by a shorter function is η-reduction.

Simplification through eta reduction: Consider an expression of the form:

```
λx.(x E)
```

This is equivalent simply to E.

The application of this expression to an arbitrary argument gives:

```
(arg λx.(x E)) → (arg E)
```

## 12.5 COMPUTING WITH LAMBDA CALCULUS

Computing with lambda calculus is done by the rules of:

- Alpha α-conversion: renaming bound variables to avoid naming conflicts.
- Beta β-reduction: replace parameters with named function to evaluate (reduce) to some value.

### Algorithm for beta β reduction

- Employ alpha α conversion to rename as needed.
- Bind the argument to the name. For example: $2 (\lambda x.x) \rightarrow \lambda x.2$
- Strip function head and name. For example: $\lambda x.2 \rightarrow 2$
- If the statement cannot be reduced, then we have a final parameter, in this case 2.
- Repeat for the next argument and lambda (curried, one at a time).

First, to establish a set of positive integers, suppose 0 is represented by the lambda expression $\lambda fx.x$. Successive integers are thus represented with a function f for each n, such as:

```
λnfx.f(nfx) → λfx.f(f(… f(fx)…))
```

Suppose zero is defined as $\lambda s.(\lambda z.z)$ for a successor function s with argument z of positive integers $\mathbb{Z}+$. For each subsequent successor we can repeat $\lambda sz.z$ and append a nested call of function s. Thus, for the integer sequence 0, 1, 2, and 3 as defined by a successor function, we have:

```
λsz.z ... 0
λsz.s(z) ... 1
λsz.s(s(z)) ... 2
λsz.s(s(s(z))) ... 3
```

Consider the definitions of a successor function in terms of lambda calculus.

add1 = λf.λx.f(nfx) → λf.λx.f n 1 x + = n 1 +

Further addition repeats the successor n + m times:

```
(m λx.(x add1n)) → (m add1n) → m n +
```

Similarly, there can be multiplication as repeated addition, and exponentiation defined by repeated multiplication. Subtraction is similar to addition, but with a predecessor function instead of a successor function. Division would then be by repeated subtraction.

Some basic addition:

```
1 2 (λx.(λy.(x y +))) → 2 (λy.(1 y +)) → 1 2 + = 3
```

Beta reduction example (one argument):

- 2 (λx.λy.x 1 +) Identify first argument and variable for binding.
- λx.λy.2 1 + Bind 2 to x.
- λy.2 1 + Strip λx head.
- 2 1 + Strip λy head.
- 3 Evaluate.

### Beta reduction example (two arguments)

```
1 2 (λx.λy.x y +)   Identify first argument and variable for binding.
2 (λx.λy.1 y +)     Bind 1 to x.
2 (λy.1 y +)        Strip λx head.
2 (λy.1 y +)        Identify first argument and variable for binding.
(λy.1 2 +)          Bind 2 to y.
1 2 +               Strip λy head.
3                   Evaluate.
```

### Beta reduction example (two arguments)

```
(λz.z) 2 (y λx.λy.x)   Identify first argument and variable for binding.
2 (y λx.λy.(λz.z))    Bind (λz.z) to x.
2 (y λy.(λz.z))       Strip λx head.
2 (y λy.(λz.z))       Identify first argument and variable for binding.
(2 λy.(λz.z))         Bind 2 to y.
2 (λz.z)              Strip λy head.
2 (λz.z)              Identify first argument and variable for binding.
(λz.2)                Bind 2 to z.
λz.2                  Strip λz head.
```

### 12.5.1 Boolean Functions

As with numbers, lambda calculus does not have any representation of *true* or *false*. These conditions must be defined. Therefore, one must define *true (t)* and *false (f)* values and related Boolean functions. This can be done as follows:

```
true=λt.λf.t
false=λt.λf.f
```

Using those functions, we can next define an *if* function that returns *true* if the argument x is true and returns *false* otherwise. In other words, *if* is an identity function. For example:

```
if = λx.λt.λf.x t f
```

Using *if* we can define additional Boolean functions in lambda calculus as follows:

```
and(x,y)=λxy.if x y f
or(x,y)=λxy.if x t y
not(x)=λx.if x f t
```

For another perspective, the above Boolean functions are translated from lambda calculus to *epop*. As before, the key component is the *if* function, defined here as “{ t f ?? } if WORD". epop's IFELSE function, alias ??, is used to select t or f based on a preceding Boolean argument. For example:

```
{ 1 } t WORD
{ 0 } f WORD
{ t f ?? } if WORD
1 if ( -> 1)
0 if ( -> 0)
```

Next, we define the and, or, and not functions in terms of if. The "DROP" and "???" word usage here selects either t or f, depending on the binary input arguments.

```
{ f if f DROP ?? } and WORD
{ t SWAP if t DROP ?? } or WORD
{ if f t ?? } not WORD
1 1 and ( -> 1)
0 1 or ( -> 1)
1 not ( -> 0)
```

## 12.6 COMBINATORS

A combinator can be defined as a closed lambda expression. This means there are no free variables.

A particular implementation is Curry's paradoxical combinator Y, represented in lambda calculus by:

```
Y = λf.(f(x x)) λf.(λx.(f(x x)))
```

This Y combinator takes a curried function and its arguments and treats it as a non-curried multi-argument function. Having more than one argument, one of those can be used to define a recursive function call. In this way, the Y combinator concept facilitates recursion in non-recursive programming languages via *indirect recursion*. For example, in *epop*, a form of indirect recursion called *mutual recursion* may be defined as follows.

```
{ i- DUP 0= FALSE isOdd ?? } isEven WORD
{ i- DUP 0= TRUE isEven ?? } isOdd WORD
4 isEven ( → 1)
6 isOdd ( → 0)
```

Recursion in lambda calculus uses the Y combinator function form Yf = f(Yf), which is a *beta reduction* of the following:

```
λf.(λs.f(ss)) (λs.f(ss))
(λs.f(ss))(λs.f(ss))
f(λs.f(ss))(λs.f(ss)) → Yf = f(Yf)
```

The Y combinator implies that recursion is possible without a named function, by simply referring to itself. This is demonstrated as follows in *epop*:

```
{ + GSC 1 > LL ? }
1 3 5 7 9 LL ( → 25)
```

The above braced expression refers to itself via the function LL, which is used to invoke the last lambda expression. The expression is repeatedly invoked as long as the data stack contains enough data for addition (the value of GSC must be greater than one).

For more depth on the subject of lambda calculus, please refer to Greg Michaelson's book, *An Introduction To Functional Programming Through Lambda Calculus*.⁷
