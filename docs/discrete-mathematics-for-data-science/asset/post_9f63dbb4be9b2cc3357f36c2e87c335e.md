
If a function can either take another function as an argument, or return a function as a result, then a function is known as a *higher order function*. Otherwise, a function is referred to as a *first order function*.

Higher order functions may be referred to as *combinators*, although there is some argument that the parameter (guest) functions must actually be *lambda expressions*, which are nameless functions consisting only of a function body. A lambda expression is a nameless function containing functions and/or data. A lambda expression may formally be referred to as a combinator if it has no external dependencies.

Lambdas provide a means to statically enclose parameters from a nameless guest function so that they persist after being returned to an outside host function.⁵ These parameters are bound in the scope of the guest function.

```
{ bound_variables bound_operations } guest WORD
{ || } host WORD
free_vars guest | host
```

⁵More about enclosures is discussed in the chapters on *Lambda Calculus* and *Computability*.

For example:

```
{ 1 + } guest WORD
{ || EXEC } host WORD
3 guest | host ( → 4)
```

In the above example, the integer 1 is bound to a variable in the scope of the guest function, whereas the integer 3 is not, as it is represented by a free variable.

An abstract function is the synthesis of other functions, be they also abstract or primitive functions that are not reducible to other functions, such as CPU instructions. This is graphically illustrated in Figure 9.1. The abstract function describes _what_ is to be done and its composition of primitive functions describes _how_ something is done. Directly or indirectly, program functions will rely on at least one primitive function.<sup>6</sup>

The reduction of abstract functions to their primitive components relates to the concept of an _abstract syntax tree_.

As multisets, the set of a machine's primitive symbols _P_ and a programming language _D<sub>L</sub>_ are related as:

$$D_L \subseteq (P \cup D_L)$$

This treatment of abstract functions somewhat differs from that used in _object oriented programming_, such as with the Java programming language, which defines abstract functions as a basis (the _what_) that must be modified in a way that makes it usable (the _how_).

Those machine instructions that cannot be decomposed to primitives are analogous to axioms, as defined earlier.7 It can be demonstrated that primitive machine instructions are, themselves, abstractions of the logic that is defined in hardware, such as digital logic consisting only of NOR and NAND gate combinations.8

## 10.9 CURRYING

*Currying* is the process of converting a multi-argument function into a series of single argument functions for the same net output.

In programming language theory, a concept called Curry-Howard isomorphism considers a direct relationship between computer programs and mathematical proofs. In that context, the currying process may be used to decompose abstract functions into their primitive constituent functions. This relates to a process referred to by Haskell Curry as *abstraction elimination*.9

Consider a function *curry* that maps a function f which takes three arguments (inputs), a, b, and c, all at once, to a function f that takes these arguments one at a time:

curry(f(a, b, c)) → f(a)(b)(c)

In practice, currying may be implemented by replacing the multi-argument function with a series of single argument nested functions, such as:

curry(f(a, b, c)) → f2(f1(f0(a)))

The right side is the composition of three functions where:

b = f0(a)
c = f1(b)
result = f2(c)

One interest in currying is the enforcement of a data flow model of computation.10 In the data flow context, single argument functions may be connected by data pipes in some programming environments. For example:

curry(f(a, b, c)) → f0(a) | f1(b) | f2(c)

Partial Functions: A partial function is a function that is only defined for a subset of the elements in its domain, its inputs. A curried function is a partial function, but a partial function is not necessarily a curried function.

If a function needs to be evaluated later because the values are currently unknown, perhaps awaiting user input, then some function arguments will remain unassigned. This is an aspect of computing known as partial application.

Partial application accommodates another computing concept known as lazy evaluation.

Similar to the data flow approach above, with f(a,b,c) → f(a) | (b,c) the full application is comprised of calling two partial functions.

Lazy evaluation delays the evaluation of an expression until it is required by a dependent expression. This contrasts with eager evaluation which evaluates an expression as soon as it is bound to a variable.

## Abstract

Recursion is an important approach that data scientists can take to wrestle with complex algorithmic problems. This is because the self-referential aspect of recursion inherently breaks larger tasks into smaller subtasks. Furthermore, common to data science are tree and graph data structures whose self-similar inner structures naturally accommodate recursive processing.

Often in programming we need to repeat a set of operations many times, such as when processing various data structures. Such repetition can be made to occur until met by a specific condition, such as the value of a variable. When a function's repeated operations include the name of the function itself, the technique of this repetition is termed recursion. Recursion can sometimes provide an elegant alternative to an otherwise complex repetitious task. Recursion is related to the principle of mathematical induction.

- An input value.
