## 23.5 GENERALIZATION VERSUS OVER-FITTING

By training a model (classifier) to match exact data patterns, the model will fail when there is no exact match in the testing data. In other words, the model was overfit to the training data.

Conversely, by training a model to match variations of data patterns, the model can better “generalize” to capture patterns that did not exist in the training data.

For example, consider the dimensions of price and time in financial time-series data. Commonly observed data patterns include the double bottom and double top patterns. The double bottom pattern exhibits a W shape and tends to precede price increases. The double top pattern resembles the letter M and tends to precede price drops. The graph in Figure 23.3 depicts the W pattern.

To programmatically recognize such patterns, we can utilize the coordinate parameters of patterns in classifiers. For example, the W pattern can be represented with five (x, y) pair vertices in the Price × Time or XY plane.

Assume that dates are given for a starting date D0 and an ending date Dn. Given prices Pi normalized as a percentage of the range of a period's maximum and minimum values in a sample, each of the five point patterns would be computed as:

```
Yi = (Pi - Pmin)/(Pmax - Pmin)
Xi = Di / Dn
```

Using such points from several sample data sets, we can train a classifier to find any W patterns present in the data. The classifier's W pattern parameters can consist of the average of several similar patterns that were found. For example, with five distinct patterns, the set of the W pattern's points would be:

```
W = { (X1, Y1) (X2, Y2) (X3, Y3) (X4, Y4) (X5, Y5) }
```

where the condition for pattern W is:

```
W : IF (Y2 < Y1 AND Y3 > Y2 AND Y4 < Y3 AND Y5 > Y4)
```

The condition for the M pattern is similar but with opposite inequality symbols:

```
M : IF (Y2 > Y1 AND Y3 < Y2 AND Y4 > Y3 AND Y5 < Y4)
```

To ensure that a pattern matching classifier works, the conditions for classification should allow for some deviation. In that way, less exact W patterns can be matched. For example:

```
M : IF ((Y2 > Y1 AND Y3 < Y2 AND Y4 > Y3 AND Y5 < Y4) OR ((Y2 + 0.01) > Y1 AND Y3 < (Y2 + 0.01) AND (Y4 + 0.01) > Y3 AND Y5 < (Y4 + 0.01)))
```

More sophisticated classifiers can entail additional dimensions, perhaps even accounting for the scale of patterns.

### A.2 POSTFIX

The notation used for mathematical expressions in this book includes postfix as well as the more common infix. Postfix is also called Reverse Polish Notation (RPN).

In postfix, the operation symbol is written last, after the arguments. (This pertains to words that require arguments.)

Examples of infix as postfix:

```
1 + 2 becomes: 1 2 +
x * 2 + 1 becomes: x 2 * 1 +
```

The distinguishing characteristics of postfix operations:

- All arguments are listed before the operation.
- No use of parenthesis (versus infix, which uses parenthesis for algebraic expressions).
- No assignment operator, such as the “=” symbol.
- No need for arithmetic operator precedence (order of operation) rules.

Because of these characteristics, postfix operations are more compact and require less computing resources than infix systems. The same benefits can be said of prefix.

The most significant programming languages that use either postfix or prefix notation are Assembly programming (prefix or postfix depending on CPU), Forth (postfix), and Lisp (prefix). C primarily uses infix.

### A.3 POSTFIX OPERATIONS

Unlike the standard infix notation, such as 3 + 4, wherein the + operator is between the operands 3 and 4, postfix notation has the operator last, such as:

```
operand1 operand2 operator
```

For example:

```
3 4 +
```

The result is 7.
