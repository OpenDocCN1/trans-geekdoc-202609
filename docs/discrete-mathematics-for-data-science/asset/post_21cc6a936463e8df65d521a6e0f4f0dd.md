## 16.7 POSTFIX EXPRESSIONS

Operations using a stack are normally done in accordance with postfix notation. That is because operations are presented after the operands. Postfix is also referred to as *Reverse Polish Notation*, or RPN, a reverse of Polish mathematician Jan Łukasiewicz's prefix notation, otherwise known as *Polish Notation*.

Some computer languages are stack-oriented, such as Forth and Postscript, as are some hand-held calculators, such as the HP 32S-RPN Scientific. Postfix requires relatively less memory and CPU usage, as it does not entail the rules of precedence and parentheses () that are required by the more familiar infix notation, with its operator between the operands. Linear processing, from left to right (or from top to bottom) avoids the need to preprocess sections of an expression. Indeed, individual functions for the assembly language of CPUs are similarly linear, though commonly in prefixed order.

Postfix has this pattern, which conforms to a stack:

```
o_0 o_1 ... o_N f
```

where operands o_0 o_1 ...o_N are provided to the function f.

Because the stack is a First-In-First-Out (FILO) structure, the element on the top of the stack is o_N, and the bottom element on the stack is o_0, the first element that was entered.

The equivalent of 3 + 4 in postfix is:

```
3 4 +
```

The result is of course 7.

Arithmetic operations are functions and functions can exist for more than arithmetic. There may exist functions for swapping and duplicating elements, perhaps called swap and dup, depending on the programming language one is using. Their effect on the number sequence 3 7 9 would be as follows:

```
3 7 9 SWAP
3 9 7 DUP
3 9 7 7
```

Notice that the operation SWAP switches only the two values preceding it and the operation DUP duplicates only the one value preceding it.

## 16.8 LIST IMPLEMENTATION OF A QUEUE

A queue is a data structure that has a First-In-First-Out (FIFO) sequence of processing. This ordering is similar to the entry-ramp for a freeway – the first car to enter the ramp is the first car to exit the ramp. The first item to enter a queue is the first to exit – FIFO for first in, first out. This contrasts with a stack, which is LIFO – last in, last out.

We see queues used by operating systems to prioritize processes, by digital communications to buffer packets of data, and in software for ordering financial transactions in the manufacturing supply chain or the stocks of an investment portfolio.

### Common queue functions:

- Enqueue: Add an element to the rear of the queue.
- Dequeue: Remove and return an element from the front of the queue.
- Front: See the first element in the queue.
- Back: See the last element in the queue.
- Length: Return the number of elements in the queue.

A _double ended queue_ (deque) can work frontwards and backwards. As such, it accommodates the addition and removal of elements from either end of the queue.

A _priority queue_ is one in which order depends on some prioritization or ranking of its elements. Two elements having the same priority are treated on a FIFO basis. Due to this ordering property, a priority queue may be based on a sorted list.

A _circular queue_ connects the last and first elements. This is achieved by having the last element in the list reference the memory address of the first object, or by using _modular indexing_ of the elements.

Modular indexing resets the index value when the current value is equivalent to the queue's length. It does this by using a modulo operation, often denoted as mod, to compute a remainder.

For example, for a circular queue of eight elements, q0, q1, ..., q7, the computation of each element's index is:

```
index = (index + 1) MOD 8
```

where MOD 8 refers to the remainder when a given value is divided by 8.

In postfix, the computation is:

```
index 1 + 8 MOD
```

Suppose the index for an element is currently 7. Incrementing the index by 1 results in the index being computed as 8. However, incrementing the index again by 1 results in the index being computed as 1. Therefore, whenever the index is 8, the next index is reset to 1.

A hybrid queue may be implemented with the properties of both a priority queue and a circular queue. In such a queue, certain priority conditions lead to a re-indexing of the circular queue. Examples of such queues are found in operating systems where, for stability, system processes must be prioritized for CPU time over less critical processes, such as a user's programs. Figure 16.10 depicts this kind of queue with indices q and priorities p.

![](img/ff796e63b14a88ab72583e78f3994e90_373_0.png)

Figure 16.10 A hybrid circular/priority queue of p data and q indices.

The appeal of a circular queue in data science and in computer science is that it can be used to automatically re-allocate memory space. Consider a signal processor that takes analog sound samples. Meta-data representing that sound sample, such as decibel level and frequency, is temporarily stored in buffers of a certain length, say 32 bytes.9 Each sample requires minimal temporary register storage, such as a circular queue, before it is directed to a permanent storage medium or transformed back into analog for amplification through audio speakers.

## 16.9 SIMPLE SEARCHING & SORTING ALGORITHMS

Linear data structures can be searched and sorted in ways that depend on the design of the data structure.

> ⁹S. Smith, *The Scientist & Engineer's Guide to Digital Signal Processing*, First. California Technical Pub, 1997. (A good take on hardware applications of the circular queue in found in Chapter 28.) ISBN: 0966017633. DOI: https://dspguide.com/ch28.htm.

Some searching algorithms depend on sorted data so that elements can be retrieved from specific positions. With a sorted list, a search can directly retrieve such values as the maximum, minimum, median, or some other element according to the ordered rank of a sequence.

Without sorting, a *linear search* is required to search a linear structure. A linear search, or *sequential search*, begins at one end of the sequence and examines each element, one after another, until either the sought value is found or the other end of the sequence is encountered.

> An example of a linear search of a stack is found in Appendix C.5. The code incrementally checks if the element on the top of the data stack matches a targeted value. In contrast is a *random search* of the stack, shown in Appendix C.6, which searches a stack at random until the target is found, up to a maximum number of tries.

One interesting sort method is the *bubble sort*. This sort processes elements by comparing adjacent pairs, swapping them as required for a certain order. To sort in ascending order, a swap takes place only when the first value of a pair is greater than the second value. After the first pass of the search, the largest element will be the last in the ordered sequence. After the second pass, the second largest element will be in the second-to-last place of the ordered sequence. Because each element must be compared to all the other elements, there are potentially n – 1 passes required for a sequence to be completely sorted.

The following is a trace of the steps required for a bubble sort to put the sequence "5, 4, 6, 3, 7" in ascending order. Each pass is denoted by the iteration i.

| i = 1 | i = 2 | i = 3 | i = 4 |
| :--- | :--- | :--- | :--- |
| 5, 4, 6, 3, 7 <br> swap | 4, 5, 3, 6, 7 <br> keep | 4, 3, 5, 6, 7 <br> swap | 3, 4, 5, 6, 7 <br> keep |
| 4, 5, 6, 3, 7 <br> keep | 4, 5, 3, 6, 7 <br> swap | 3, 4, 5, 6, 7 <br> keep | |
| 4, 5, 6, 3, 7 <br> swap | 4, 3, 5, 6, 7 <br> keep | | |
| 4, 5, 3, 6, 7 <br> keep | | | |
