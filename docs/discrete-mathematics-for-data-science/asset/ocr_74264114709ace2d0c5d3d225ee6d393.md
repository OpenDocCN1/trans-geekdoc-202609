Formally, algorithm complexity analysis is limited to abstract functions that we can control and, hence, analysis may ignore code that is responsible for significantly complex underlying computations.

Algorithm performance is relative to the problem at hand. If real-time processing for game graphics is of interest, latency in microseconds or milliseconds may be a concern. If processing terabytes of data for statistical analysis is the objective, then processing run-times of minutes and much longer may be acceptable.

To corroborate function efficiency, we can record the run-time of different versions of the same function. Example *epop* code in Appendix C.13 does just that. The benchtest program there shows a recursive Fibonacci sequence algorithm that is generally 20 nanoseconds slower than an iterative version.
