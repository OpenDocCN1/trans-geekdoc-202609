## 9.3 LANGUAGE SYMBOLS

The grammars comprising a metalanguage can be represented by symbols. For example, a common framework of grammars is symbolized as follows:

G = { N T S P }

Here N is the set of non-terminals, T is the set of terminals, S is an element of N and is the starting symbol for all strings, and P is the set of production rules.

Sets N and T are disjoint. That might seem incorrect considering that N derives from T. But, it is the symbol sets which matter in this context, not their derivation. To convince yourself, compile a program for a guest language that contains a word that is unique to the host language. There will be an error. Of course, once a program is compiled, all words will be converted into the host language, all becoming Ts.

Words and the alphanumeric characters comprising a word are subsets of the language's universal set of symbols. A programming language's universal set of symbols is also referred to as the language's symbol table or dictionary.

In contrast, a word that is defined as a set of no words or characters represents an empty set, also known as an identity element. An identity word I may be defined as follows:

```
{ } I
```

Identity words serve as place holders for words or strings that may later take on characters. The common symbol for an empty word or string is ε.

The initial words in a programming language's dictionary are primitives. Words that are defined using a programming language's primitives are abstractions and are added to the dictionary. It should be emphasized that this level of abstraction pertains only inside the scope of the guest language, and not to that of the host language.9

Abstract words are defined in terms of other words, including other abstract words as well as primitive words.

Abstract words represent word subsets of the universal set which is the language dictionary. Because the sets that comprise word definitions may contain duplicates, they are technically defined as *bags* or *multisets* rather than proper sets, which are restricted to distinct elements.

Defining a word appends it to the language's dictionary. For example, here we define words w and x:

```
{ ab cd mn } w WORD
{ pq rs } x WORD
```

Because abstract words are comprised of other words, they can also be decomposed into their constituent words, which is the task of a compiler program.

Symbolically, a language's dictionary $D_L$ is a multiset of primitive $P$ words that are combined to form abstract words. Thus, for language $L$, the dictionary $D_L$ is defined as:

```
$D_L \subseteq (P \cup D_L)$
```

If the set of language primitives $P$ were a proper set containing distinct elements, then $D_L \subseteq P \rightarrow false$. However, if $P$ is a multiset, then $D_L \subseteq P \rightarrow true$.

Although element order does not formally matter for multisets, duplicate elements may be distinguished by arbitrarily denoting their order, such as $e_0 e_1 ... e_n$.

A language L that is oriented to a particular machine M may be denoted L(M).

Consider the set of words { w x z I } consisting of four subwords: w, x, z, and the identity word I. Because the identity word has no effect,

{ w x z I } = { w x z }

We may also define an abstract word based on the w and x words that were previously defined using ab cd mn and pq rs respectively.

```
{ w x } y WORD
```

The word y is the set of symbols of the word w followed by the symbols of the word x.

y → ab cd mn pq rs

To append an element to the word set y, we can either redefine the word, such as:

```
{ w x z } y WORD
```

Or, use the following approach, which is less tedious with larger sets:

```
{ y z } y WORD
```

The concatenation operation is used to join two strings of characters.<sup>10</sup>

- ac \to ac
- a.c \to ac
- a\tilde{c} \to ac
- a(c) \to ac
- aca \to aca
- ac.a \to aca
- ac\tilde{c} \to aca
- (ac)c \to acc

Using the asterisk superscript * indicates all possible word combinations of a given sequence. For example:

$(ac)^* = \{ I \ ac \ acac \ acacac \ ... \}$

Similarly, the plus + superscript indicates all words of a given sequence, but does not include the empty set.

$(ac)^+ = (ac)^* - I$

Note that while concatenation is an associative operation, as $a(ac) = (ac)a$, it is not commutative. That is $ac \neq ca$.

The union operation symbol is used to create any possible combination of words using given symbols.

$a \cup c = \{ I \ a \ c \ aa \ ac \ ca \ cc \ aaa \ aac \ ... \}$

## 9.4 A MACHINE

Programming languages are designed for the machines on which they run. Machines can be physical or logical models of computation.

One simple memory-less model of computation is known as a finite state machine, or finite automata (FA). These can be of a class of deterministic finite automata (DFA) or non-deterministic finite automata (NFA). Deterministic systems produce a predetermined output state that is always the same for given inputs. Conversely, non-deterministic systems depend on possible or probable inputs, which are not known to the system in advance.

Like digital logic, finite state machines have input state encodings and related output that can be modeled in functional form, state diagram, digraph, adjacency matrix, or truth table. The truth table used to describe FAs is called a state transition table. An FA also has the characteristics of a graph data structure, such as vertices representing states, which is described in the Branched Structures chapter.

Real world finite state machines include traffic lights, vending machines, elevators, subway turnstiles, combination locks, and industrial logical controllers. Abstract real-world applications include classifiers for data science and lexers in programming language compilers.

Consider the operator IF as a minimalist finite state machine. Given an input state of 0 or 1 (false or true), IF will affect one operation or another. Assembling a sequence of several IF operations will effectively form a hierarchy of decisions, a decision tree. If some of those decisions involve unknown inputs and repeat a branch of the tree until a particular output is generated, then this system in non-deterministic.

Such a non-deterministic branching system is demonstrated here. This code merely executes function this, that or other based on the choice of the user.

```
{ choice @ 1 EQ this ? } a WORD
{ a choice @ 2 EQ that ? } b WORD
{ b choice @ 2 > other ? } c WORD
```

Provided that the user's input for choice was 2, executing the word c would indirectly cause the word that to be executed via word b. This code is non-deterministic because choice is not known until an instruction in the sequence is evaluated which reveals the input choice.

Once the instruction sequence of a non-deterministic finite automata (NFA) is complete and its branches determined, it may then be possible to convert the NFA into a DFA provided that any new data seen by the model does not render different decisions. Accordingly, we would record the true or yes states and then remove all other possible states from the machine. This is more feasible when using a full universal data set such as a *population* and less likely when using sample data sets.

The set of NFA vertices (states) that are set to *yes* defines a DFA.

$dfa = nfa \cap yes$

After converting the NFA to a DFA, the set of instructions that remain is said to be closed. That is, the remaining branch of instructions do not change. This concept parallels that of *closures* in the practice of *functional programming*,<sup>11</sup> which temporarily cache (store) a subset of executable functions for use by nameless functions called lambdas. Lambdas provide the means of statically enclosing the parameters of a nameless guest function that can be used for a separate host function.
