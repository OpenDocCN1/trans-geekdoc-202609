
## Resampling

DOI: 10.1201/9781032687759-21

## Abstract

The development of models for estimation requires testing. Generally, this means splitting the original data source into separate data sets, one for training and one for testing. Using testing data to evaluate a model based on separate training data is known as *cross validation*. The cross validation process may be repeated for multiple testing sets with the results averaged for a single estimation.

For training and test data sets to be relevant, the data must be randomly drawn from the same population or data stream. If the sample is too small or the selections are not sufficiently random, then the training and test sets may be too different and cross validation will not be relevant.

In addition to covering random sampling for obtaining training and test data, this chapter discusses a method for comparing the means of two samples to check for randomness. This chapter also discusses frequency graphs, running averages, and calculating errors in estimates.

### 21.1 RANDOM SAMPLES

Population data includes data that is unknown, either because it is evolving and is not yet deemed complete, or because the population is simply too large to assess. Therefore, population data is sampled. The same can be said for streaming data, as it is said to have no beginning and no end.

For the random selection of data we rely on some kind of random function or procedure.

Recall the concept of randomness in the Unconnected Data and Probabilities & Statistics chapters. An ideal random number function will generate a uniform distribution without any particular repeated sequential pattern. In a uniform distribution, values are evenly spread out over their range. For example, when generating random digits, 0, 1, 2, ..., 9, each digit has approximately the same frequency, as seen in Figure 21.1.

Random number generation is important for applications in statistical re-sampling. However, true randomness is difficult to achieve because the random number function depends on the interactions of a computer system's internal states that are not actually random. This is why we call a random number function a *pseudo-random number generator*, or a *PRNG*.

Various measures of worldly phenomena and probabilistic events tend to exhibit a *normal* or *Gaussian* distribution.

Normally distributed data have a frequency graph that is a bell-shape, with more values close to the mean and fewer values away from the mean, in the *tail* areas, as seen in Figure 21.2

![](img/ff796e63b14a88ab72583e78f3994e90_480_0.png)

Figure 21.2 A normal distribution.

Therefore, we may want to record the output of a pseudo random number generator in a way that more appropriately models events and phenomena. One approach to ensure the relevance of a PRNG is to record output frequencies for wider ranges of values. This is known as the *running* probability (not to be confused with a cumulative probability, which is the sum of the probabilities of events).

The running probability is the average of the current and the prior n probabilities. For example:

```
P_i = \frac{(P_i + P_{i-1} + P_{i-2} + \cdots + P_{i-n})}{n + 1}
```

For example, the following code generates a list of 2000 random probabilities, offset by -0.5 to simulate a mean of 0 in a range of -0.5 to +0.5, and then sorted. In order to achieve some data smoothing, each output number is the moving average of 2 (n = 2) random probabilities, a concurrent probability and the one before it.

```
{ 1 10000 RAND } prng WORD
{ { + } 2 i- LREPEAT 2 / DUP >R } avg WORD
{ { avg } GSC 2 / LREPEAT } mavg WORD
{ prng 5000 - 10000 / } 2000 LREPEAT
mavg SSORT
```

The moving averages have different frequencies and ordering them reveals a curve, as seen in Figure 21.3. Still, the curve in 21.3 is not exactly a normal shape, as the left and right tails are barely noticeable. More pronounced tails can be created by using a larger window for the moving average, such as n = 4, as seen in Figure 21.4. Note that doubling n also halves the output of the moving average number function. Therefore, for a consistent comparison, we should first double the number of random numbers generated.<sup>1</sup>

The running probability is similar in concept to that of *data smoothing*, as is used in the analysis of time series data. For example, for analyzing a stock's price trend, we might compute a weekly *moving average* of its daily closing prices over the course of a year. Given 280 business days, the calculation would entail 275 (280 days minus 5) repeated calculations of the mean closing price of the prior five days.

This requires invoking an adequate random number generating function until the sampled data approximates a known parameter of the population data. ### 21.2 RESAMPLING

The development of models for estimation requires testing. Generally, this means splitting the original data source into separate data sets, one for training and one for testing. Using testing data to evaluate a model based on separate training data is known as *cross validation*. The cross validation process may be repeated for multiple testing sets with the testing results averaged for a single estimation.

A sampled data set can be partitioned into $K$ equal size sets, where $K - 1$ of the sets are designated as training sets and 1 set is retained for testing. This is known as $K$-fold validation. A $K$ of 10 is common.

For the training and test data sets to be relevant, the data must be randomly drawn from the same population or data stream. If a sample set is too small or the selections not random enough, then the training and test sets may be too different and cross validation may not be relevant.

To corroborate the relevance of sampled data, we can use a hypothesis test called a *two-sample t-test*, which checks for a significant difference between the means of two sets. For the purposes of resampling, we compare the means of each training set (one at a time) to that of the test set.

A two-sample t-test statistic is computed as follows:

\( t = \frac{(\bar{x}_1 - \bar{x}_2) - (\mu_1 - \mu_2)}{\sqrt{\frac{s_1^2}{n_1} + \frac{s_2^2}{n_2}}} \)

where for both the test set and a training set, \(\bar{x}_1\) and \(\bar{x}_2\) are sample means, \(s_1\) and \(s_2\) are standard deviations, and \(n_1\) and \(n_2\) are sample sizes. The components \(\mu_1\) and \(\mu_2\) are population means. However, since both samples come from the same population, \(\mu_1 - \mu_2 = 0\). Also, because the computation compares a pair of statistics, we lose two degrees of freedom.
