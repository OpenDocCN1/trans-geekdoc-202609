### 2.2 ABSTRACT FUNCTIONS

An abstract function will *generalize away* or hide the details of other functions that it embodies. Details that are common to multiple instances of the same code represent opportunity for consolidation, using a more general form that can be copied and extended. That way we can create a hierarchy: a parent object containing general attributes and child objects, which can have specialized attributes, as well as those inherited from the parent. This provides the efficiencies of code reuse and modularization.

An abstract solution exists to solve a general category of problems. A concrete solution depends on honing an abstract solution into a specific application for a specific problem. Thus, problem solving depends on isolating a problem as one of a general abstract category, and then modifying the abstract solution with additional functionality and data.

Here is a simple concrete operation consisting of two primitive values and an addition function. Note that in postfix notation, to add 2 and 3, we write the addends first and the operation last.

```
2 3 +
```

In contrast, here is an abstract word w1 that is based on another abstract word w0, which is itself defined by the primitive value p0.

```
{ p0 } w0
{ w0 p0 } w1
```

By the *substitution property of equality*, the following expressions are equivalent to w1:

```
{ { p0 } p0 }
{ p0 p0 }
p0 p0
{ p0 } { p0 }
w0 w0
```

Suppose that we wish to define an operation to compute the area of various rectangular shapes. Since we don't know in advance the dimensions of all the rectangles that might be presented, we define a general formula that includes abstractions for height as h and width as w. The formula for area is thus:

```
h w *
```

We further this abstraction by representing it with a label. We will use the term WORD to denote its purpose as a *constructor* that defines the parameter and operation sequence of a word.

To begin, we can define rectangle_area simply as:

```
{ * } rectangle_area WORD
```

By definition of the multiplication operator *, the word rectangle_area must take two arguments, a number for height and a number for width. Accordingly, we can compute the area of a rectangle as:

```
5 7 rectangle_area ( → 35)
```

If we wish to embed as parameters the abstractions of h and w inside area, then we could first define a list such hw as:

```
{ 5 7} hw LIST
```

Then use the hw list as an argument for the area word:

```
hw area ( → 35)
```

This exemplifies how concrete values are substituted for labels during a function's application.

With the nesting of abstract types, with one inside another, we have in effect a hierarchy, a parent-child relationship. This permits us to exercise code re-use, reusing the code of a more general context for a distinct or concrete application. For example, in the code below, the word shape embodies the words h and w. Similarly, the word rectangle embodies the words shape and area.

```
{ 5 } h WORD
{ 7 } w WORD
{ h w } shape WORD
{ * } area WORD
{ shape area } rectangle_area WORD
rectangle_area ( → 35)
```

As you may have deduced, abstraction as such can include not only abstract data, but other words in the context of what is referred to as *higher order functions*, as already mentioned.

Consider the word *average* as a user defined function to compute an average in terms of a user defined list of numbers *list*, an operation for the sum of those numbers, a count of those numbers given by *n*, and a division operation given by /.

```
{ 2 3 5 } list LIST
{ list sum n / } average WORD
```

These components are abstractions for operations internal to computing an average. Their treatment here is both as data and as functions, indicating that these words are higher order functions.

The length of *list*, *n* can be defined as:

```
{ list ' LEN } n WORD
```

A *sum* function can be defined to repeat until all elements from *list* have been processed. That is, repeat until size of the stack as determined by the GSC function is no longer greater than 1.

```
{ + GSC 1 > sum ? } sum WORD
```

An *average* function can be defined to perform sum and division operations on the list:

```
{ list sum n / } average WORD
```

Invoking *average* generates a result:

```
average ( → 3.33)
```

## Numbers

### Abstract

In data science, the organization of data types is an early step in the process of data analysis and storage, just after data is ingested from a source in some raw format.

Numbers are classified in a variety of ways, with a number's sign, fractional pattern, and base being the most general considerations. For example, a number might be whole, such as 5, or a repeating decimal such as 0.333.... The number base system to which people are generally accustomed is base 10 (decimal). In programming languages, a number's classification is integral to its data typing.

Machine representations of numbers are an application of discrete mathematics. Digital computers segment (quantize) continuous analog input into a series of discrete values. At the machine level in computers common today, numbers that are negative, irrational, and real are operated upon and stored as binary (base 2) 1s and 0s.
