
The checker program repeatedly checks the guest program with new input as long as the guest halts for some input. If the guest does not halt, then the checker waits indefinitely. Either way, the system runs forever and is undecidable.

In practice, attempting to solve the general halting problem may be considered an exercise in futility, as it is not possible to have a solution for all problems. Nonetheless, a study of the halting problem illuminates the limits of computation, making it not completely futile.

For example, the *epop* programming language includes statistical heuristics to guess if a user's running code is locked in an infinite loop. If so determined, rightly or wrongly, *epop* warns the user and eventually breaks the loop on the user's behalf.

In cases where a model's solutions are probabilistic rather than deterministic, each possible output state is assigned a probability. Such models may be referred to as *probabilistic state machines*.⁴
