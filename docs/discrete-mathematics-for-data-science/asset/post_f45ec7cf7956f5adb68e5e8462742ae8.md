In data science, an array is a list of indexed elements. If the array is of one dimension and its elements are numbers, then the array is termed a *vector*. A numeric array of multiple dimensions is termed a *matrix*. We generally refer to an array-of-arrays, which may or may not be numeric, as a *multi-dimensional array*.

In data science, only some data structures are afforded the property of *random access*. While this capability may or may not be facilitated by a programming language, random access is generally expected for arrays, and array-derived structures, but not for linked lists. A *linked list* is a linear sequence of elements connected by an internal memory reference. Because of this internal chain of dependency, linked lists do not usually afford direct or random access to any element except the first.

The indexing schemes for randomly accessed data structures vary. For an array implementation of either a list, stack, or queue, the indexing is literally straight forward: 0, 1, 2, ... N. Depending on the programming language, indexing could start at 0 or 1.

Defining a presorted random access list, or sorted list, allows immediate access to specific values in order to most quickly compute statistics, such as maximum, minimum, median, midrange, and various percentiles. With values immediately available at an index, it is unnecessary to use the more time-consuming operations of list traversal. For these direct access benefits, a sorted list must have the random access property. A sorted list would be of less use otherwise. Therefore, for our purposes a sorted list is assumed to also be a random access list.

The order of a sorted list may be numeric, lexical (such as alphabetical) or have some arbitrary sequential pattern. For example, consider the alphabetical ranking of a sorted list of elements, ls
{ a b x y } ls LIST

We can directly access the fourth element, y, by specifying its index. Because indexing typically begins at 0, the fourth element of a list is associated with an index of 3. For example, using the NTH operation, we retrieve the fourth element from $l_s$ as follows:

```
$l_s$ 3 NTH ( → y)
```

### 16.4 LISTS OF LISTS

Just as each element of a list may be comprised of singular data element, each element may instead be another list. As such we have a *host list* comprised of *constituent lists*. Traversal to any constituent object must begin with the host list. This contrasts with the two-dimensional array or matrix, which does not require such traversal.

Consider these several lists:

```
{ a0 a1 a2 a3 } b LIST
{ b0 b1 b2 b3 } b LIST
{ c0 c1 c2 c3 } c LIST
{ d0 d1 d2 d3 } d LIST
{ l0 l1 l2 l3 } lLIST
```

Lists a, b, c, and d can be constituents of list l in what is referred to as a *list-of-lists*. This can be accomplished with l0 = a0, l1 = b0, l2 = c0, and l3 = d0.

Graphically, such a list of lists may be presented as shown in Figure 16.4.

| a0 | b0 | c0 | d0 |
|----|----|----|----|
| a1 | b1 | c1 | d1 |
| a2 | b2 | c2 | d2 |
| a3 | b3 | c3 | d3 |

Figure 16.4  A list of lists.

Note how elements having a subscript of 0, such as $a_0$, are both an element of the host list and a first element of a constituent list.$^7$ The host list shares one element with each of its constituent lists.

Each constituent list, $a\ b\ c$ and $d$, as well as the lists of lists, $l$, has a cardinality of 4. That is the count of their respective elements. We may denote:

$|a| \equiv |b| \equiv |c| \equiv |d| \equiv |l|$

### 16.5 LISTS OF ABSTRACT DATA TYPES

The data of a list is not limited to characters and numbers. Custom or abstract data type definitions can comprise lists.$^8$ Abstract data types are sometimes called ADTs.

Given a list of ADTs, we call the elements *instances* or *objects* of the ADT.

Suppose we have an ADT named $A$. Then we should denote instances of $A$ such as $a_0\ a_1 \dots a_N$. As an abstract type, $A$ may be composed of objects of various types, including integers, characters, lists, and other abstract objects.

In the following example, the ADT $a_0$ consists of an integer (5), a character list ($l_0$), and a character (x).

```
{ e f g } $l_0$ LIST
{ 5 $l_0$ x } $a_0$ ADT
```

The abstract object, $a_0$, can in turn be put into another list, such as $l_1$ here:

```
{ $a_0$ $a_1$ $a_2$ $a_3$ } $l_1$ LIST
```

### 16.6 LIST IMPLEMENTATION OF A STACK

Lists are the basis of *stacks*, a common data structure in data science, particularly for logical memory architectures.

Stacks are used because they enforce a particular order of elements and so facilitate the CPU's means of memory management.

The First In Last Out (FILO) properties of the stack are often used for enforcing, in a certain sequence, the temporary memory allocation and de-allocation of functions and their constituent methods and variables, or *function scope*. A variable that is declared in a function will see its associated value *pushed* onto the stack when the function is invoked during runtime. While a function executes, its constituent variables are *popped* (removed) from the stack.

Think of the *Undo* command in a word processor. When you enter words you effectively push them onto the stack. The first word entered goes to the bottom of the stack. When you select *Undo*, you effectively pop a word off the top of the stack.

Stack operations affect only those elements on top of the stack. That includes:

- Push: Add an element to the top of the stack.
- Pop: Return/remove an element from the top of the stack.
- Peek: See the value of the stack's top element.

Other stack operations may include:

- Length: Return the number of elements on the stack.
- Clear: Empty the stack.

Types of stacks include:

- Operand: A stack of elements (values).
- Operator: A stack of functions (a program stack).
- Combined: Operands and operators on the same stack.
- Return: A stack of results from operations.

Some systems have separate stacks for data, functions and results. For example, in Figure 16.6 the integer 4 is at the top of the stack as it was the last number put on the stack.
