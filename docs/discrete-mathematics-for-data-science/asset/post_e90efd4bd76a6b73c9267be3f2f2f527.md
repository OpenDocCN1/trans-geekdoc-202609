
We can further define a word *factorial* that invokes map and reduce in succession.

## Lambda Calculus

DOI: 10.1201/9781032687759-12

### Abstract

Lambda calculus is a formal system of mathematical logic for expressing computation with functions and recursion.

An understanding of lambda calculus allows the data scientist to better recognize and leverage concepts of function abstraction for *functional programming*. Functional programming is a paradigm that is implemented in various programming languages in order to facilitate recursion, compact expressions, and immutable objects for more reliable distributed processing.

Ideally, functional programming is characterized by concise functions that describe *what* is to be done, hiding the composition of more complex functions that depict *how* something is done. The latter scenario is more characteristic of standard procedural programming.

### 12.1 LAMBDA λ CALCULUS

Lambda calculus was invented by the American mathematician and logician Alonzo Church in the 1930s in his quest to come up with a theoretical system to represent functions for computation. Since then, aspects of lambda calculus have made their way into various programming languages, perhaps most notably Lisp in the late 1950s and Haskell in the early 1990s.¹

Lambda calculus is a minimal way to model computation. It provides a means of abstraction that may expedite modeling in comparison to the typical programming language's syntax, allowing what may be considered verbose syntax to be condensed. These are aspects the *functional programming* paradigm, which is based on lambda calculus. While lambda calculus has a formal set of rules for computation, its interpretations and its programming language implementations vary.

In lambda calculus all operations are defined by an inductive abstraction of a function called a *lambda*, which may be considered the only primitive object. All functions are unary (single argument), as opposed to *multi-arity* (multiple argument). Lambda calculus does not define an evaluation order, leaving it to the coder to specify as left-right, right-left, infix, postfix, or applicative, and related eager or lazy behavior. (The examples in this chapter emphasize postfix arithmetic.)

The flexibility of evaluation order in lambda calculus is corroborated by the *Church-Rosser Theorem*, which essentially states that whether or not an algorithm takes a lazy or eager path, the final solution is the same.²

Typically in lambda calculus, lower case characters are used for variables (x, y, z, ...), upper case is for applications, (E, F, G, EG, ...), and a combination of these such as λ x.E is used for an abstraction. All of these are lambda terms. A function's application is its operation, as when a function takes an argument.

Lambda calculus deals with just three expressions:

- • Variables
- • Function abstraction
- • Function application

Function abstraction is symbolized by the Greek character λ, called lambda.

A lambda expression may be either a name to identify an abstraction point, a function to introduce abstraction, or a function application to define some specialization for an abstraction. An abstraction point is the input variable of a function, allowing for the creation of anonymous functions. Anonymous functions are functions with a function body, but no name.

Abstraction in lambda calculus has this form:

```
λIdentifier.Expression
```

An identifier is a symbol or a name for a variable (parameter) or function. It may consist of any sequence of non-blank characters. For example, λx.E denotes a lambda function x that evaluates a lambda expression E as a parameter.

The symbol for the lambda expression, λ, precedes the name x used for an abstraction. The name used for the abstraction is called the function's bound variable x. (A bound variable is one which exists inside of a function's scope or body.) A dot “.” separates a bound variable from the expression body.

Equivalent to λidentifier.expression is the expression:

```
{ expression } identifier WORD
```

While parameters are enclosed and bound in the inner scope of E, they can be used outside that scope. 3

```
{ inner_scope } E WORD
{ E outer_scope } λx.E WORD
```

For example:

```
{ 1 + } E WORD
{ E ’ EXEC } λx.E WORD
3 λx.E ( → 4)
```

3 More about this is discussed in the chapter on Computability.

In the above example, the lambda expression λx.E is a function in which every element in E is bound to its local scope. The integer 1 is bound to a variable in the scope of the guest function E, whereas the integer 3 is not. If 3, a concrete parameter, were replaced by a variable, such as y, then y would be considered a free variable.

Some languages use a let keyword to explicitly relegate a variable's effectiveness to a local environment, or to that of a lambda expression. This may be referred to as let over lambda. 4 Consider for example the use of the LET word in the following application that computes the λx.2x + 1:

```
{ 2 * y LET } λy.y WORD
{ TEL 1 + } λx WORD
{ λy.y λx } λx.λy.y WORD
3 λx.λy.y ( → 7)
```

The word TEL complements LET, getting the value of the variable that was set by LET.

### 12.2 FUNCTION APPLICATION

Function application in lambda calculus pertains to applying a function (a lambda abstraction) to an argument. The process is one of reduction by substituting the argument for the bound variable in the function body.

In lambda calculus, function application has the form:

```
(function_expression argument_expression)
```

The application form turns an abstract function into a concrete implementation that can compute. For example:

```
2(λx.x1+) → 3
```

Reminder: we are using arithmetic operators in a postfix manner. So, x 1 + is an operation of addition (a function with two operands, x and 1). While such operations and numbers do not technically exist in lambda calculus, they are often used for internal function expressions to expedite examples. (Formally, lambda calculus uses abstractions of the successor function for numbers and operations.)
