### 17.2.2 Binary Tree Traversal Patterns

Tree traversal can take various approaches, namely *level-order*, *in-order*, *pre-order*, and *post-order*. These traversal patterns are shown in Figure 17.7.

- Level-order: Starting at root node [0], visit all nodes from left to right on each level before descending to the next level.
- In-order: Starting at the left-most node [0], visit left → root → right.
- Pre-order: Starting at root node [0], visit nodes in order of root → left → right.
- Post-order: Starting at root node [0], visit nodes in order of left → right → root.

A breadth-first search of a tree entails a level-order traversal, starting at the root and, going from left to right, visiting all the nodes at each level before descending to the next level.

A depth-first search of a tree entails a pre-order traversal that starts at the tree root, then traverses the left-most branch as far as possible before moving to the next (right) branch and subtree. Also of the depth-first variety are the in-order traversal (First traverse the left subtree, then the root node, and then the right subtree) and the post-order traversal (First traverse the left, then right subtrees, and then visit the root node).

### 17.2.3 Parse Tree Evaluation

One type of binary tree is a *parse tree* for modeling and evaluating binary operations of arithmetic, and also for converting between infix, prefix, and postfix notations. A parse tree may also be referred to as a *syntax tree*.²

Figure 17.8 A parse tree of (A - B) + (C × D).

Inside the parse tree we have subtrees, each representing the expression of an arithmetic operator and its two operands.

Each operator in the expression is the root of a two node subtree. The arrangement is the same for infix, prefix, and postfix expressions.

To assist visualizing the respective operations of the full expression (A - B) + (C × D), let us substitute each sub expression with the symbols I and II.

I = (A - B) and II = (C × D)

Thus:

(A - B) + (C × D) = I + II

Or, in postfix:

A B - C D × = II +

Trees showing the sequence of these operations are shown in Figure 17.9.

![](img/ff796e63b14a88ab72583e78f3994e90_391_0.png)

Figure 17.9 A parse tree of (A - B) + (C × D).

A mathematical expression tree allows us to generate computations as well as conversions to other notations, such as prefix, infix, etc. The evaluation of an expression tree generally entails a tree traversal algorithm of the depth-first (in-order, pre-order, or post-order) or breadth-first (level-order) variety.

We will deal here with depth-first traversals, as they work well for stack-based evaluation and recursive processing of subtrees.

Pre-order traversals generate prefix expressions by visiting the root, then the left subtree, and then the right subtree, all in pre-order.

Post-order traversals generate postfix expressions by visiting the left subtree, then the right subtree, and then the root, all in post-order.

In-order traversals generate infix expressions by visiting the left subtree, then the root, and then the right subtree, all in in-order.

Given a level-order index, postfix code can be used to evaluate a syntax or parse tree, such as in Figure 17.9.

An algorithm to evaluate a level-order expression tree can be developed as follows:

- Index the nodes, as was done in for a level-ordering (the LR column in Figure 17.10).
- According to the index, push each associated node value onto a stack.
- Evaluate each postfix operation on the stack, rotating each result to the bottom of the stack.

The steps for this particular algorithm are demonstrated in Figure 17.10.

For coding the operations in Figure 17.10, we first define a list ls as:

```
{ + ' 13 -' 24 × ' } ls LIST
```

Note that list ls is merely the flattened sequence of the operations and operands from the parse tree in Figure 17.9, which corresponds with the left column in Figure 17.10.

For a binary parse tree, the operator count is defined as:

opcount = n/2 − 1

Related code for the operator count of the list ls is:

```
ls
{ GSC 2 / i- } opcount WORD
```

where GSC gives us the stack count or the number of objects on the stack.

With those parameters established, we can evaluate the list sequence ls, using the functions EXEC and >> repeatedly for each operation in list ls.

For example:

```
ls { EXEC >> } opcount LREPEAT ( → 6)
```

Therefore, the result of “+ 1 3 - 2 4 ×” in postfix is 6.

EXEC executes any operation that is on top of the stack. >> rotates any data from the top of the stack to the bottom of the stack. The LREPEAT operation repeats the operations inside the { } braces, depending on the operator count variable.

### 17.2.4 Binary Search Tree

A *binary search tree* is one which flattens to a sorted list. Recall from the *Linear Structures* chapter that a sorted list has its elements in either an ascending or descending order. The structure accommodates O(log n) time efficiencies for a binary search when the binary tree is balanced. A *balanced binary tree* is a binary tree wherein the heights of the left and right subtrees of any node do not differ by more than 1.

Note the subtree patterns in Figure 17.11, where the value of the root is greater than that of the left branch and less than that of the right branch. The insertion of a new element entails first comparing its value to that of the root. If less than the root, then the element is directed to the left branch. Otherwise, the element is directed to the right branch. If the applicable branch is already occupied, then the process of comparison is repeated. Inserting elements in this manner effectively sorts the tree.

If the tree is balanced, then only one branch of the tree needs to be traversed with each root comparison and, thus affording the O(log n) efficiency. Otherwise, if the tree is unbalanced, the time complexity is O(n). If the tree were perfectly balanced, with all interior nodes having two children and all leaf nodes being on the same level, then traversal is considered a relatively efficient O(log2 n) operation.

The tallest subtree of n nodes has linear-list-like efficiency of O(n). Conversely, the shortest subtree of n nodes is full and most efficient, having O(log n).

To convert a binary search tree into a sorted list, perform an in-order traversal of the tree, as seen in Figure 17.7(d). During traversal, obtain the value of each node and append it to the sorted list. The resulting list will be in ascending order. To reverse the order to be descending, simply reverse the indexing.

To convert a sorted list to a binary search tree, starting with the element at index 0 in the sorted list, insert each element into the tree, as discussed above for insertion into a binary search tree.
