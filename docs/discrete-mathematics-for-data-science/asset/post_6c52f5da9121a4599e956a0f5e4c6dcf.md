
The channel between a sender and a receiver may be considered a medium or a route. The channel may carry electrical pulses representing the bit-stream of a networking protocol.

Suppose that a channel carries data at a maximum rate of 8 bits per second. The channel's bandwidth is 8 bits/s. Beyond that, transmission becomes unreliable with too many errors and too much entropy.

Shannon's Fundamental Theorem for a Noiseless Channel presents a maximum set of symbols S in a period, a data rate of symbol transmission in terms of channel capacity C divided by the entropy H. That is:

```
S=C / H
```

We can re-arrange the symbols to get C = HS and see that channel capacity depends on the product of the symbol rate and entropy.

Channel capacity may also be considered the maximum mutual information. As such, it is computed as:

```
C(A, B) = I(A, S)
```

Suppose that the sender has symbol set { 1 0 1 0 } as A to transmit. Given a data rate that is limited to half capacity, S would be { 1 0 } and it would not be clear which part of A was received.⁶

## 22.10 DATA COMPRESSION & HUFFMAN ENCODING

Data compression is an achievement of Information Theory. Compressing data allows us to represent information with fewer bits for transmission and storage. The receiver restores the original information using decompression.

Shannon entropy tells us that information may be represented by more bits than necessary, indicating opportunity for compression.

The effectiveness of compression can be measured as the size of the compressed data set relative to the original data set.

Lossy methods of compression allow some bits to be lost after decompression. This may be acceptable for some types of data, such as sound and graphics. The ear and the eye may not be able to perceive the missing bits. Conversely, lossless methods of compression are generally necessary for record keeping. For example, information from medical diagnostics and financial transactions must often be complete.

Huffman Encoding is a type of lossless compression that encodes and decodes using a binary tree called a Huffman tree.

As an example, suppose that we have a text message consisting of 120 characters, using only the characters A, B, C, X, Y, and Z. These characters have different frequencies of occurrence in the message. Their probabilities and entropy are given as follows:

| Symbol | Probability | Entropy | Entropy total |
| :--- | :--- | :--- | :--- |
| A | 27 / 120 | 0.48 | 13.07 |
| B | 9 / 120 | 0.28 | 2.52 |
| C | 21 / 120 | 0.44 | 9.24 |
| X | 15 / 120 | 0.38 | 5.63 |
| Y | 12 / 120 | 0.33 | 3.99 |
| Z | 16 / 120 | 0.39 | 6.20 |

To compress or decompress, start with one of the symbols, such as ‘A’, to signify the root node of the Huffman tree. Left branches in the tree will be labeled with 0s and right branches will be labeled with 1s.

Re-order the symbols in terms of frequency:

| B | Y | X | Z | C | A |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 9 | 12 | 15 | 16 | 21 | 27 |

From left to right, add the frequencies of each pair, using each sum for the root nodes in the lowest level of the tree, as shown in Figure 22.2.

![](img/ff796e63b14a88ab72583e78f3994e90_503_0.png)

Figure 22.2 Level 1 and leaves of a Huffman tree.

Repeat until there is one root. Then label the left branches with 0s and the right branches with 1s, as follows:

![](img/ff796e63b14a88ab72583e78f3994e90_503_1.png)

Figure 22.3 A Huffman tree.

The corresponding Huffman code for each symbol is the series of 1s and 0s, starting from the top node along the path to each individual symbol on the bottom level. Thus, we get the following distinct Huffman codes:

```
B → 0 0 0
Y → 0 0 1
X → 0 1 0
Z → 0 1 1
C → 1 0
A → 1 1
```

How much compression does this afford us? Notice that it takes only 2 or 3 bits to represent each symbol. Contrast that to the size of a character in a programming language like C (8 bits) or Java (16 bits). Thus, Huffman encoding should save us at least 5 bits per character symbol.

The total bits used in the example with respect to their frequency in the message is as follows:

| Symbol | Frequency | Bits | Frequency x Bits |
|---|---|---|---|
| A | 27 | 2 | 54 |
| B | 9 | 2 | 18 |
| C | 21 | 3 | 66 |
| X | 15 | 3 | 45 |
| Y | 12 | 3 | 36 |
| Z | 16 | 3 | 48 |
| | | | Total: 267 |

*Saved bits* = ((120 × 8) − 267) / (120 × 8) = 0.722

In this case, Huffman compression saves 72% over the typical amount of space required for character encoding.

Now on to decompression and decoding. Because the Huffman codes that were generated are distinct and unambiguous, we can recreate the original symbol set with certainty.

Given a symbol, it can be checked using the same Huffman tree. For example, given the binary sequence 000, start at the top of the tree and trace the route connecting three 0s (the left branch of the tree). The route leads to B. Similarly, for the binary sequence 10, trace the route from the top node rightward down the 1 branch and then the 0 branch, which leads to C. Repeat this process for each set of bits in the message.

It should be said that Huffman compression produces *prefix free code*, meaning that an encoding of one symbol is not a prefix for any other. The prefix free property makes Huffman encoded bit strings uniquely decipherable, allowing us to reconstruct the symbol sequences of a message.

For example, using our prior symbol encodings, suppose the bit string 1011000 is to be deciphered. Traversing that bit string from left to right we look for a bit that matches in the tree path. The first match is 10, which is C. Remove those two bits, 1 and 0, from the bit string. Resume by processing the remaining bit string, 11000, from left to right. The sequence of 11 connect to A. Remove those bits. The last three bits, 000, connect to B. In the sequence that the symbols were deciphered, we get the word CAB.
