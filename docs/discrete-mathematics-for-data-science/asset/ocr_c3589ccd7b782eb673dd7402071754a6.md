Of the 23 mantissa bits, the first bit is called the _implicit leading bit_. Because this implicit leading bit is always 1 for non-zero numbers, there is no need to allocate space for it. Therefore, we will reallocate that space to the mantissa bits, now referred to as _fraction bits_.

As seen in the following table, the IEEE 754 floating-point standard accommodates zero, infinity and illegal results, such as the square root of -1. The _fraction_ heading is for the mantissa, without the implicit leading bit.

| Number | Sign | Exponent | Fraction |
| :--- | :--- | :--- | :--- |
| 0 | N/A | 00000000 | 00000000000000000000000 |
| +∞ | 0 | 00000000 | 00000000000000000000000 |
| -∞ | 1 | 11111111 | 11111111111111111111111 |
| illegal | N/A | 11111111 | NaN (not a number) |

The IEEE 754 conversion procedure:

+   1. Convert the number to binary.
+   2. Normalize: Shift the decimal point left until there is only a 1 in the most significant bit.
+      (a) Exponent value = number of shifts.
+      (b) Mantissa = that set of bits to the right of the decimal.
+   3. Compute the exponent bias to adjust for negative values. Eight bits for the bias allows for a signed exponent, ranging from -126 to +127, given that we set 0 as 127. That is, _bias_ = 2^(8-1) - 1 = 127, where eight bits represent 256 possible bit combinations, including 3 bits for 0, infinity, and NaN. The biased exponent = exponent + 127 (in binary).
+   4. The floating point number = sign bit, exponent bits, and mantissa bits.
+   5. Pad with 0s the empty bits on the right of the mantissa.
