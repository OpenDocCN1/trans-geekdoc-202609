# How to do it...

+   Probably the most difficult part of the process is determining which factors to include in the ACL. For the purposes of illustration, let's say that our users are all assigned a level and a status. In this illustration, the level is defined as follows:

    'levels' => [0, 'BEG', 'INT', 'ADV']

+   The status could indicate how far they are in the membership signup process. For example, a status of 0 could indicate they've initiated the membership signup process, but have not yet been confirmed. A status of 1 could indicate their e-mail address is confirmed, but they have not paid the monthly fee, and so on.

+   Next, we need to define the resources we plan to control. In this case, we will assume there is a need to control access to a series of web pages on the site. Accordingly, we need to define an array of such resources. In the ACL, we can then refer to the key:

    'pages' => [0 => 'sorry', 'logout' => 'logout',
               'login'  => 'auth',
               1 => 'page1', 2 => 'page2', 3 => 'page3',
               4 => 'page4', 5 => 'page5', 6 => 'page6',
               7 => 'page7', 8 => 'page8', 9 => 'page9']

+   Finally, the most important piece of configuration is to make assignments to pages according to level and status. The generic template used in the configuration array might look like this:

    status => ['inherits' => <key>, 'pages' => [level =>
                [pages allowed], etc.]]
