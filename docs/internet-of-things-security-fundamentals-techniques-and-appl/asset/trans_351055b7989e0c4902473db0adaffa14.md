
# 内存计算

内存计算（IMC）本质上与之前讨论的那些计算范式相当不同。IMC 的概念并非全新，但在近期之前并未得到深入探索。在传统计算中，数据被带到计算单元，这是一个耗时且资源密集的过程 \[[17](#Ch03.xhtml#ref3_17)\]。传统的数据处理方式是先将数据存储在硬盘上，然后将其一部分传输到主内存（RAM），处理器会从那里（可能通过缓存）获取数据进行处理。处理完成后，处理过的数据会被送回硬盘，随后的数据块被加载到 RAM 中，循环继续，直到磁盘上需要处理的数据块全部完成。该过程中的主要瓶颈是数据传输延迟：（a）磁盘与 RAM 之间以及（b）CPU 与 RAM 之间。因此，很明显总处理时间会随着待处理磁盘数据的量而增加。这就是为什么基于磁盘的技术似乎无力应对实时物联网数据洪流的需求。IMC 通过颠覆传统的计算原则来遏制延迟。其目标是将处理单元带到数据所在的 RAM 中，通常绕过磁盘。这是通过将处理器和 RAM 放置得非常接近，理想情况下在同一芯片上实现的。通过这种策略，数据移动将被最小化，从而降低内存延迟。此外，数据移动的减少使系统总线保持空闲且始终可用。所有这些优势确保了显著提升的处理速度。这就是为什么 IMC 被认为是最适合实时物联网数据处理的解决方案。IMC 尤其理想，可用于从流数据中生成实时事件。

为了分析流数据，我们需要能够在不将数据存储到磁盘的情况下处理实时数据的即时处理系统。事实上，IMC 可能是有效处理在途数据的唯一手段 \[17\]。动态 RAM（DRAM）足以比数据源更快地处理流中的数据。如果采用足够数量的 DRAM 并恰当地利用，可以实现惊人的速度性能。RAM 尺寸越大，处理速度越快。这些高速 DRAM 的集群将能够为我们提供超快的高性能计算设施。随着内存成本每年下降 30% \[[18](#Ch03.xhtml#ref3_18)\]，DRAM 的性能成本比大幅提升。这帮助组织在获得卓越性能体验的同时，为数据处理系统实现更低的总拥有成本（TCO）。高性能内存计算的利用不仅限于流数据处理，还可用于对运营数据集进行实时分析 \[18\]。随着组织从包括物联网在内的不同来源被数据淹没，如果处理能力不匹配，许多洞察可能仍未被发掘。IMC 使企业和组织能够在接近实时中发现模式和解决方案，并做出及时决策。通过在接近实时中识别和分析客户偏好和行为，企业可以提供适时的服务，提升服务质量（QoS），从而丰富客户体验（QoE）。采用 IMC，企业可以从其数据中获得无限可能，并实现以前不可行的业务收益 \[17\]。像 Oracle、Microsoft、SAP、IBM、Tableau Software、Tibco Software 等大多数 IT 巨头都在提供大数据解决方案，尤其是基于 IMC 平台的大数据分析工具 \[[19](#Ch03.xhtml#ref3_19)\]。组织可以借助 Amazon Spark 构建内部内存数据计算，后者提供用于内存数据处理的开源平台。GridGain 提供了一个内存处理平台，可同时用于数据网格和计算网格 \[[20](#Ch03.xhtml#ref3_20)\]。

我们假设到现在为止，几个问题可能已经敲响了你审慎的思维。首先非常明显的是，DRAM 作为易失性内存，它如何保证不丢失数据？简单的解决方案是持续备份并同步。另一种选择是使用非易失性 RAM。其次，我们能否应用同样的逻辑来实现缓存内计算？毕竟缓存至少比 DRAM 快三倍，因此我们可以获得更快的处理速度。理论上，这将是一个很棒的选择，但缓存的物理限制是导致缓存内计算不可行的主要障碍，至少对于当前计算机架构而言 \[20\]。而且在可预见的未来这种情况不会改变，IMC 将继续成为未来几年实时数据处理和分析的巨大前景。

## 3.5 各范式涉及的安全和隐私问题

### 网格计算
由于在网格计算中，物联网数据保留在组织内部并位于防火墙之后，因此安全和隐私方面的担忧极小。入侵检测技术可应用于任何可能的外部威胁。并且受到拒绝服务（DoS）攻击的影响的可能性最小。但如果网格由跨组织和跨管理域组成，安全和隐私可能会受到损害。

### 云计算
云是公共服务；因此，安全和隐私问题始终存在。传输中的数据存在安全漏洞的可能性。隐私得不到保证，因为数据位于外国服务器上。云中一个值得注意的问题称为账户劫持，即欺诈者通过劫持某人的账户来访问计费到他人账户的服务 \[[21](#Ch03.xhtml#ref3_21)\]。这对组织来说可能非常有害，因为它会损害其完整性和声誉。如果机密数据泄露或被伪造，组织可能会遭受重大损失。在另一种称为服务流量劫持的攻击形式中，如果攻击者获得用户凭据，他们会窃听用户的活动和交易。他们可以操纵或将可处理数据转移到不期望的位置。云更常需要应对的另一种更常见的攻击形式是拒绝服务攻击，即合法用户被拒绝云服务。因此，除非在云端采取强有力的安全措施，否则从安全角度考虑处理物联网数据并不是一个好主意。

### 雾计算
在雾计算中，初步处理在网络内完成。因此，据认为它比云更安全。当预处理数据被发送到云端进行存储和进一步处理和分析时，它会暴露于威胁之下。但位于家庭网络边缘并连接到公共网络的雾设备容易受到攻击。攻击者可能会针对这些设备向系统注入恶意代码。他们可以通过用伪造的设备（虚拟地）替换真正的雾设备来发起中间人攻击 \[[22](#Ch03.xhtml#ref3_22)\]。因此，保护雾计算中的这些网关设备至关重要。

### 移动边缘计算
MEC 服务器并不是真正的内部资产。如果这些服务器被攻破，数据安全也会被妥协。此外，在 MEC 中，使用移动网络进行数据通信，这并不难被拦截。这对数据隐私构成担忧。

### 云小站
Cloudlet 的安全和隐私方面与雾计算非常相似。除非 Cloudlet 和 Cloudlet 中的网关设备未被入侵，否则物联网数据应是安全的。但与雾计算一样，当数据传输到中央云时，数据可能得不到保护。
