
正如我们提到的，物联网将产生海量的数据。但由于大多数物联网系统包含各种具有不同硬件的设备，物联网数据不仅庞大，而且还表现出以下特征：

* 异构的
* 多维的
* 连续且速度高
* 动态且不一致
* 实时且流式
* 易变且临时
* 具有强烈的空间和时间依赖性
* 数据质量各异
* 多样的数据结构和数据类型

## 3.3 物联网数据处理的挑战

物联网仍处于青少年阶段，但考虑到其产生的数据量，它已对传统数据处理技术提出了严峻挑战。前一节提到的特定属性带来了额外的挑战，使得使用传统数据处理方法和平台处理物联网数据变得困难。一些突出的挑战包括：

* 处理能力有限或无
* 通信限制
* 内存大小有限
* 实时处理
* 处理高摄取率
* 保持情境和上下文感知
* 能量受限
* 支持可扩展性
* 提供容错能力
* 确保安全和隐私

## 3.4 物联网数据处理架构

### 3.4.1 网格计算

网格计算是一种分布式系统，允许无缝访问由网络连接的计算资源集合组成的计算网格。网格计算提供类超算的计算能力，利用组织内部和/或组织间的计算资源，如桌面电脑、集群、RAIDs 等。网格计算特别适合组织物联网。它需要强大的计算基础设施来处理、存储和评估物联网数据，这无疑会大幅提高 IT 预算。组织无需花费在第三方计算资源（如云）上，可以利用现有的 IT 基础设施。内部计算资源，如桌面电脑以及员工的个人便携式电脑，包括智能手机和平板电脑，可以被利用来形成资源网格或资源池。物联网数据应由指定的中央实体收集，该实体将分配、分发并调度处理任务到潜在的计算站点。完成后，结果将被收集、组装并发送给相关实体。使用网格计算处理物联网数据具有许多优势，例如：

* 更好地利用现有基础设施，无需额外设置。
* 相比其他选项更便宜，无需为外部服务付费。
* 自给自足，无需依赖第三方服务。
* 物联网数据的即时处理，因此响应时间更好。
* 避免了通信成本和延迟。

但网格计算的明显缺点是组织必须承担管理和维护基础设施、应用程序和数据的开销。因此，中小型以及新手组织可能不会偏好这种选择。

### 3.4.2 云计算

云计算一直是物联网数据处理最受欢迎的平台。它以较低的成本提供对计算资源的集中访问。应用程序和服务托管在云中。物联网数据被收集并发送到云进行处理、存储和分析。用户和应用程序要么提前订阅事件，要么向云查询所需服务。强大处理器和海量存储是云计算提供的物联网所利用的有吸引力的选项。得益于云的可扩展服务，物联网可以从任意数量的设备收集数据并无限期地存储它们，最重要的是安全地存储。物联网可以利用强大的基于云的应用程序和大数据技术，例如 HBase 和 MapReduce 用于处理和分析 [[3](#Ch03.xhtml#ref3_3)]。云计算在物联网中被广泛接受，尤其适用于那些没有足够现有 IT 基础设施且不愿在此方面进行前期投资的组织。

**云计算作为物联网数据处理架构的问题：** 有一个令人担忧的方面，云计算可能不适合物联网数据，即在大多数物联网系统中，操作的数据是实时的，而消费这些数据的应用程序是不容延迟的。例如，灾难监测和控制系统或工业自动化或智能交通都要求实时访问传感器数据。这些应用程序无法承受将原始数据带到远程站点进行处理。在这些情况下，生成的数据应在靠近设备的站点处理，以便将处理延迟降至最低以实现即时响应。云计算的另一个问题是所有物联网数据都被发送到云服务器进行处理。这给底层网络带来了巨大负担。最糟糕的是，其中大部分数据根本不需要处理。实际上，在物联网发展的早期阶段，应用程序逻辑嵌入在物联网设备的固件中，处理在设备上完成 [[4](#Ch03.xhtml#ref3_4)]。尽管它允许实时处理和即时响应，但如果需要对应用程序进行任何更改，很难升级和重新编程这些设备 [[5](#Ch03.xhtml#ref3_5)]。而且，由于资源限制，复杂的算法无法在物联网设备上运行。因此，建议将应用程序逻辑和处理从数据源设备中取出并委托给云服务器 [[6](#Ch03.xhtml#ref3_6)]。因此，现在整个原始物联网数据被传输到云中处理，而不是在设备上处理。由于数据处理任务已从本地网络转移到远程数据中心，这一概念被称为“*网络外处理*” [5]。但正如我们所见，这引入了网络拥塞和延迟的典型复杂性。为了摆脱这些问题，研究人员考虑了一种中间方法，并提出了“*网络内处理*”这一创新解决方案。他们建议在途中进行处理任务，即在设备和云之间某个地方。网络设备在处理和存储能力方面的进步推动了这一概念的有效性。这些设备通常放置在网络边缘，因此也称为边缘设备。由于与物联网设备接近，实时处理可以实现。而且由于大部分数据在发送到云之前已被处理，网络拥塞已显著减少。网络内数据处理对传感器网络将是极其有益的。

由于传感器节点花费大部分能量在发送和/或接收数据流 [[7](#Ch03.xhtml#ref3_7)]，将所有感知数据传输到远程站点会耗尽设备的电池电量 [[8](#Ch03.xhtml#ref3_8)]。随着这一概念的普及，人们提出了不同的“网络内处理”策略，尽管它们的基本目标都相同。之所以为同一概念创造不同术语的主要原因是缺乏对网络边缘的标准共识 [[9](#Ch03.xhtml#ref3_9)]。在以下章节中，我们将讨论名为 *雾计算，移动边缘计算，* 和 *云节点* 的三种架构。

### 3.4.3 雾计算
