
> 对于 CASP 考试，你应该理解使用对称加密的三个主要问题。这些包括密钥交换问题、密钥管理问题以及对称加密仅提供机密性的问题。

当你使用 ECB 时，请记住，固定密钥和已知的重复明文将始终产生相同的密文。

## 密码文链模式 (Cipher Block Chaining Mode)

当 DES 在密码文链 (CBC) 模式运行时，它与 ECB 有些相似，不同在于 CBC 将上一个块生成的部分密文插入下一个块中。这个过程被称为异或（XOR）。它使得密文更加安全，不易被破解。CBC 的命名非常恰当，因为一个块的数据被用于下一个块，各个块被链在一起。这种链结构产生了依赖性，但也产生了更随机的密文。

## 输出反馈模式 (Output Feedback Mode)

输出反馈 (OFB) 模式实现为流密码，并使用明文反馈到密文流中。传输错误不会传播整个加密过程。初始化向量用于创建第一个加密块的种子值。DES 将明文与种子值进行异或，应用于后续数据。

## 密码文反馈模式 (Cipher Feedback Mode)

密码文反馈 (CFB) 模式可以实现为流密码并用于加密单个字符。CFB 与 OFB 的相似之处在于之前生成的密文会被添加到后续流中。由于密文是流式传输的，错误和损坏可能会渗透加密过程。

DES 有多安全？它不像以前那样安全了。多年来，计算能力不断提高，缩短了暴力破解 DES 所需的时间。1998 年，电子前沿基金（Electronic Frontier Foundation）能够在大约 23 小时内破解 DES。

## 三重 DES (Triple DES)

三重 DES (3DES) 被设计为一种临时解决方案。DES 最初是以五年为期进行认证的，并要求每五年重新认证一次。在早期通过这些认证后，DES 在 1987 年的重新认证左右开始遇到问题。到 1993 年，NIST 表示 DES 开始过时了其实用性。他们开始寻找替代它的候选方案。这个新标准 AES 将是长期替代方案，但在 AES 准备好之前之前还需要其他东西来填补空白。因此，为了延长 DES 加密标准的有效性，采用了 3DES。根据实现方式的不同，它可以使用两个或三个密钥加密数据。它的有效密钥长度为 112 或 168 位，并执行 48 轮置换和替换。尽管它安全得多，但速度只有 56 位 DES 的三分之一。

## 高级加密标准 (Advanced Encryption Standard)

2002 年，NIST 选择了 Rijndael 来取代 DES。它的名字源于它的两个开发者 Vincent Rijmen 和 Joan Daemen。它是一种快速、简单、稳健的加密机制。Rijndael 也以抵抗各种类型的攻击而闻名。Rijndael 算法使用三层变换来加密和解密消息块：

- 线性混合变换
- 非线性变换
- 密钥加变换

Rijndael 使用四步并行系列轮次。Rijndael 是一种迭代分组密码，支持 128、192 或 256 位的可变密钥和块长度：

- 如果密钥和块大小均为 128 位，则有 10 轮。
- 如果密钥和块大小均为 192 位，则有 12 轮。
- 如果密钥和块大小均为 256 位，则有 14 轮。

每轮中都会执行以下每个步骤：

1. 字节替换：每个字节都通过 s-box 替换。
2. 行移：字节排列在矩形中并进行移动。
3. 矩阵混合：根据排列的矩形进行矩阵乘法。
4. 密钥加：状态的每个字节与轮密钥结合。

在最后一轮中，跳过第四步并重复第一步。

## 国际数据加密算法 (International Data Encryption Algorithm)

国际数据加密算法 (IDEA) 是一种 64 位分组密码，使用 128 位密钥。它与其他算法不同，因为它避免了对 s-box 或查找表的使用。尽管 IDEA 是一家瑞士公司的专利，但它可以免费用于非商业用途。它被认为是一种安全的加密标准，并以不同的模式运行。曾几何时人们认为 IDEA 可以取代 DES，但专利问题使其变得不实际。

## 里维斯特密码算法 (Rivest Cipher Algorithms)

RC 系列密码包括 RC2、RC4、RC5 和 RC6（它们由 Rivest 设计）。RC2 是一种较旧的算法，具有可变密钥大小，64 位分组密码，可以作为 DES 的替代品。RC4 实现为流密码。40 位的版本最初用于 WEP。它是最常见的 128 位密钥版本。RC5 是一种分组密码，其轮数可以从 0 到 255 变化。最后，RC6 具有可变密钥大小和额外的轮数。对称加密提供了速度，但如果你在寻找一种便于密钥交换的系统，你将考虑非对称加密。

## 非对称加密 (Asymmetric Encryption)

非对称加密（或公钥密码学）与对称加密不同。它克服了对称加密的一个巨大障碍：密钥交换。（注：原文后续部分存在大量重复的乱码文本，已根据逻辑提取核心内容翻译）

RSA 算法以其发明者的名字命名。Ron Rivest、Adi Shamir 和 Len Adleman 在 1977 年开发了 RSA。RSA 与其他非对称算法一样，速度比对称加密系统慢，它提供了安全的密钥交换并被认为非常安全。RSA 使用的密钥大小高达 3,072 位。RSA 的设计使得为了安全考虑，它必须使用乘积远大于 129 位的素数；129 位的十进制数是通过数域筛法算法进行因数分解的。RSA 公钥和私钥的生成方式如下：

1. 选择两个等长的素数 $p$ 和 $q$，并计算 $p \times q = n$，即为模数。
2. 选择一个随机公钥 $e$，使得 $e$ 与 $(p-1)(q-1)$ 互质。
3. 计算 $e \times d = 1 \pmod{[(p-1)(q-1)]}$，其中 $d$ 为私钥。
4. 因此，$d = e^{-1} \pmod{[(p-1)(q-1)]}$。

通过这些计算，$(d, n)$ 是私钥，$(e, n)$ 是公钥。明文 $P$ 被加密以生成密文 $C$，如下所示：

$C = P^e \pmod n$

并通过以下方式解密恢复明文 $P$：

$P = C^d \pmod n$

RSA 的工作原理是将明文分成等长度的数据块，每个数据块的位数少于 $n$。每个数据块都被单独进行加密和解密。任何试图破解 RSA 密钥的人都会面临一项严峻的挑战，因为将一个大整数分解为其两个因数具有困难性。破解 RSA 密钥需要极其大量的计算机处理能力和时间。RSA 算法已成为工业加密加密的事实标准，特别是在 2000 年专利过期之后。它被内置在许多协议中，例如 PGP；软件产品；以及 Mozilla Firefox、Google Chrome 和 Microsoft Internet Explorer 等系统。

# 椭圆曲线加密

椭圆曲线加密 (ECC) 可见于智能手机和手持设备等较小、性能较低的设备。ECC 被认为比其他一些非对称算法更安全，因为椭圆曲线系统比基于离散对系统的更难破解。椭圆曲线通常定义在有限数域（如实数和有理数）上，它们实现了对离散对问题的模拟。

# ElGamal

ElGamal 发布于 1985 年，其安全性部分取决于解决离散对问题的困难性。它是 Diffie–Hellman 密钥交换的扩展。

ElGamal 由三个离散部分组成：一个密钥生成器、一个加密算法和一个解密算法。它可以用于数字签名、密钥交换和加密。

# 混合加密

有时将两个东西混合在一起是有意义的。你还记得那条广告吗，“你把巧克力放进我的花生酱里了吗？”你可能不认为加密像巧克力一样，但结合对称加密和非对称加密有真正的益处。对称加密很快，但密钥分配是一个问题。非对称加密不适用于大量数据。将两者结合成混合加密利用了各者的优点，产生了一个真正强大的系统。公钥加密被作密钥封装方案，私钥加密用作数据封装方案。以下是系统的工作原理。如果 Bob 想给 Alice 发送消息，会发生以下情况：

1. Bob 为数据封装方案生成一个随机私钥。该会话密钥是一个对称密钥。
2. Bob 使用步骤 1 中生成的对称密钥通过数据封装方案加密消息。
3. Bob 使用 Alice 的公钥对对称密钥进行加密。
4. Bob 将这两项内容（加密的消息和加密的密钥）都发送给 Alice。
5. Alice 使用她的私钥解密这两项内容。这一过程如图 1.4 所示。

## SHA

安全哈希算法（SHA）与 MD5 类似。某些人认为它是 MD5 的继承者，因为它产生了更大的加密哈希。SHA 输出 160 位的消息摘要。SHA-1 以 512 位块处理消息，并在需要时添加填充，使数据总位达到目标位数。SHA-1 的有效性仅为 111 位。SHA-1 是 SHA 算法族的一部分，包括 SHA-0、SHA-1、SHA-2 和 SHA-3。SHA-0 不再被认为是安全的，SHA-1 现在也容易受到攻击。目前可用的最强版本之一是 SHA-256 和 SHA-512。SHA-3 于 2012 年发布，使用了 Keccak 算法。

## HAVAL

HAVAL 是另一个与 MD5 类似的单向哈希算法。与 MD5 不同，HAVAL 不绑定到固定的消息摘要值。HAVAL-3-128 进行三次处理并输出 128 位的指纹，而 HAVAL-4-256 进行四次处理并产生长度为 256 位的指纹。

## 消息认证码

消息认证码（MAC）与数字签名类似，不同之处在于使用了对称加密。MAC 使用相同的秘密（对称）密钥进行创建和验证。在你的安全专业人员职业生涯中，可能会遇到四种类型的 MAC：无条件安全的、基于哈希函数的、基于流密码的和基于块密码的。

## HMAC

有时仅靠哈希本身是不够的，在这些情况下，可能需要哈希消息认证码（HMAC）。HMAC 设计用于能够免疫多重碰撞攻击。这种功能通过包含共享秘密密钥来实现。基本上，HMAC 的原理是使用 MD5 或 SHA-1 等哈希算法，然后通过添加密码来更改初始状态。即使有人可以拦截并修改数据，如果该人没有秘密密钥，也无用于事。如果没有密钥，该人员没有简单的方法重新创建哈希值。

## 数字签名

数字签名是一类基于公钥密码学的算法。它们被用于验证消息的真实性和完整性。要创建数字签名，需要将消息通过哈希算法。生成的哈希值然后由发送者的私钥加密。接收消息时，接收者解密加密后的和，并使用发送者的公钥重新计算预期的消息哈希。这两个值必须匹配才能证明消息的有效性，并验证其确实是由认为的方发送的。数字签名之所以有效，是因为只有该方可以访问私钥。让我们逐步分解这个过程以帮助详细说明操作：

1. Bob 通过将消息通过哈希算法产生消息摘要。
2. 然后使用 Bob 的私钥对消息摘要进行加密。
3. 消息被转发给接收者 Alice。
4. Alice 使用与 Bob 相同的哈希算法从消息中创建消息摘要。然后 Alice 使用 Bob 的公钥解密 Bob 的签名摘要。
5. 最后，Alice 比较两个消息摘要，一个是 Bob 原始创建的，另一个是她创建的。如果两个值匹配，Alice 就可以放心消息未被改动。

## PKI 基础设施

PKI 是一个一个用于创建、管理、分发、使用、存储和撤销数字证书及密钥的硬件、软件、人员、策略和程序的框架。基本上，HMAC 的原理是使用 MD5 或 SHA-1 等哈希算法，然后通过添加密码来更改初始状态。即使有人可以拦截并修改数据，如果该人没有秘密密钥，也无用于事。如果没有密钥，该人员没有简单的方法重新创建哈希值。

在现代世界中，PKI 解决了这些担忧带来了安全性。从用户的角度来看，PKI 看起来可能是无缝的——但实际上它由许多组件组成。PKI 包含硬件、软件和策略。密钥分发的一个非技术问题是访问控制。任何 PKI 系统都必须仔细控制，以确保错误的人无法访问密钥。从用户的角度来看，PKI 看起来可能是无缝的——但实际上它由许多组件组成。PKI 的组件包括：

- 证书机构 (CA)
- 注册机构 (RA)
- 证书撤销列表 (CRL)
- 数字证书
- 证书分发系统

## 证书撤销列表 (CRL)

就像护照一样，数字证书并非终身有效。证书由于许多原因会失效，例如员工离开公司、信息更改或私钥泄露。由于这些原因，必须维护证书撤销列表（CRL）。

CRL 由证书颁发机构（CA）维护，CA 对列表进行签名以维护其准确性。每当报告数字证书出现问题时，它们就会被视为无效，CA 会将其序列号添加到 CRL 中。任何请求数字证书的人都可以检查 CRL 以验证证书的完整性。证书可能损坏的原因有很多，包括以下这些：

- 证书已过期。
- DNS 名称或服务器的 IP 地址发生更改。
- 服务器崩溃导致证书损坏。

## 数字证书

数字证书对于 PKI（公钥基础设施）过程至关重要。数字证书承担着两个角色：首先，它确保了公钥的完整性，并确保密钥保持不变且处于有效；其次，它验证公钥与指定的所有者绑定，并且所有关联信息均真实准确。实现这些目标所需的信息被添加到数字证书中。

> 注意：在执行电子交易时，数字签名在证明您的身份方面起着关键作用。

数字证书遵循 X.509 标准。X.509 的最新版本是第 3 版。版本 3 的主要进展之一是增加了扩展。该版本包含了支持桥接和网格等其他拓扑结构的灵活性。它可以像 PGP 一样作为信任网运行。X.509 证书包含以下元素：

- 版本
- 序列号
- 算法 ID
- 发行者
- 有效期
- 生效日期（指定日期）
- 期日期（指定日期）
- 主体
- 主体公钥信息
- 公钥算法
- 主体公钥
- 发行者唯一标识（可选）
- 主体唯一标识（可选）
- 扩展（可选）
