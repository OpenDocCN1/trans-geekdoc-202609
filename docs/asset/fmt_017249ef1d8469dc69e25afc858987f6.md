
# 数据库系统通常使用国家代码或国家名称来标识国家

许多国家名称包含嵌入空格（例如，“Czech Republic”），因此不能直接用作 IRI（尽管使用下划线或连字符代替空格的修改后名称可以）。

在实践中，许多 OWL 本体使用无意义的、自动生成的标识符作为 IRI，就像一些关系数据库设计者倾向于为其表模式使用人工代理键一样。可以使用 `rdfs:label` 注解属性将人类可读的标签与 IRI 关联起来，并且像 Protégé ([`protege.stanford.edu/`](http://protege.stanford.edu/)) 这样的 OWL 软件工具可以配置为显示标签而不是 IRI，以使本体更具可读性。

数据模型中指定的约束*不会*被翻译成 OWL 中实际的*约束*，而是被翻译成逻辑*命题*，这些命题基于开放世界语义来理解，其中某些个体可能是未命名的。例如，针对 `Politician` 的子类限制“hasPoliticianName min 1”仅表示每个政治家都有一个政治家名称——它并不要求系统知道该代码是什么。

## 并集、交集和补集

回顾一下，集合 `A` 和 `B` 的*并集*是包含 `A` 或 `B` 或两者中所有元素的集合。并集运算符在除 OWL Lite 之外的所有 OWL 版本中均受支持，并可应用于类或数据范围（例如，数据类型或其他字面量集合）。由并集产生的复杂类表达式或数据范围表达式可用于任何可使用简单类或数据范围的地方。两个或多个类的并集包含至少出现在这些类之一中的所有个体。在 Manchester 语法中，并集运算符显示为“or”，置于中缀位置。这是一个*包含性或*运算符。例如，我们可以将有前途的学生定义为聪明或勤奋（或两者兼备）的学生，如下所示：

```
Class: PromisingStudent
EquivalentTo: BrightStudent or IndustriousStudent
```

这意味着 `BrightStudent` 和 `IndustriousStudent` 是 `PromisingStudent` 的子类。可以推断出关于超类成员资格的信息。例如，给定 `Individual: Hermione Types: BrightStudent, IndustriousStudent`，我们可以推断出 `Individual: Hermione Types: PromisingStudent`。

可以通过向并集运算添加*不相交类*声明，在 OWL 中声明类*划分*。在 Manchester 语法中，要声明两个或多个不相交的类（即互斥），只需在前面加上“DisjointClasses:”。将其添加到包含性或运算符后，会得到一个*排他性或*运算符。例如，我们可以将 `Party` 定义为一个人或一个组织，但不能两者兼备，如下所示：

```
DisjointClasses: Person, PrivateCompany, PublicOrganization
Class: Party
EquivalentTo: Person or Organization
```

可以用类似的方式指定两个以上类的划分，例如：

```
DisjointClasses: Person, PrivateCompany, Organization
Class: Party
EquivalentTo: Person or PrivateCompany or PublicOrganization
```

作为声明划分的替代方案，OWL 支持*不相交并集*运算符。在 Manchester 语法中，这通过使用“DisjointUnionOf:”来呈现。例如，刚才讨论的划分可以更简洁地声明为：

```
Class: Party
DisjointUnionOf: Person, PrivateCompany, PublicOrganization
```

回顾一下，集合 `A` 和 `B` 的*交集*是同时出现在 `A` 和 `B` 中的所有元素的集合。在 OWL 中，交集运算符可应用于类或数据范围，由交集产生的复杂类表达式或数据范围表达式可用于任何可使用简单类或数据范围的地方。在 Manchester 语法中，交集运算符显示为“and”，置于中缀位置。例如，以下 OWL 代码的最后一行将类 `StudentEmployee` 定义为 `Student` 和 `Employee` 的*交集*，它们本身都是 `Person` 的子类。

```
Class: Person
Class: Student
SubClassOf: Person
Class: Employee
SubClassOf: Person
Class StudentEmployee
EquivalentTo: Student and Employee
```

将此示例与以下声明进行对比，后者基于官方 OWL 2 Primer 中的示例。此处，类 `Grandfather` 只是被断言，而非被定义。相反，它仅被约束为包含在（而非等同于）`Man` 和 `Parent` 类的交集中。并非所有作为父母的男性都是祖父。

```
Class: Grandfather SubClassOf: Man and Parent
```

回顾一下，集合 *A* 的*补集*是全集中不在集合 *A* 内的所有元素的集合。在 OWL 中，补集运算符可应用于类或数据范围，所得的复杂类表达式或数据范围表达式可用于任何可使用简单类或数据范围的地方。

一个类的补集包含不是该类成员的每个个体。在 Manchester 语法中，补集运算符显示为 `not`。例如，类 `NonHuman` 可定义为类 `Human` 的补集，如下所示：

```
Class: Human
Class: NonHuman EquivalentTo: not Human
```

下面 `NonDriver` 类的定义是另一个示例：

```
Class: Person
Class: Driver EquivalentTo: Person and drives min 1 Car
Class: NonDriver EquivalentTo: Person and not Driver
```

到目前为止的所有示例都使用了类。在 OWL 2 中，并集、交集和补集运算也可应用于数据范围。例如：

```
Datatype: StringOrInteger EquivalentTo: xsd:string or xsd:integer
Datatype: PassGradeNr EquivalentTo: GradeNr and not FailGradeNr
```

## 自反、非自反、对称、非对称和传递谓词

在 OWL 中，所有属性均为二元谓词。如果定义域和值域相同或兼容，则可比较主语和宾语实例。在 ORM 中，此类谓词称为*环谓词*，专门适用于它们（或更普遍地，兼容角色对）的约束称为*环约束*。

ORM 包含多种环约束的图形表示法，其中一些只是被简单定义（如非自反、非对称），而另一些则是递归定义的（如非循环、强非传递）。OWL 2 仅支持环谓词的以下五种限制：自反、非自反、对称、非对称和传递。其中，OWL 1 仅支持对称和传递。与 ORM 不同，OWL 仅允许将环谓词的限制应用于对象属性表达式，而不适用于数据属性表达式。

当且仅当关系 *R* 的定义域中的每个个体都与自身保持关系 *R* 时，该关系 *R* 为*自反*。如果定义域为 `owl:Thing`，唯一可能为自反的谓词是恒等关系“=”。

OWL 允许通过将对象属性表达式表征为*自反属性*来声明其为自反。在 Manchester 语法中，我们将“Reflexive”声明为一种特征。例如，如果每个人都知道自己，“knows”谓词可声明为自反，如下所示：

```
ObjectProperty: knows
Domain: Person
Range: Person
Characteristics: Reflexive
```

鉴于此，可进行以下推理：

*   ```
    Individual: Einstein
    ```

*   Types: Person → Individual: Einstein Facts: knows Einstein.

*   ```
    Individual: Terry
    ```

*   Facts: knows Tony → Individual: Terry Types: Person

*   Individual: Tony Types: Person

作为并集定义域的示例，以下 `isAsOldAs` 谓词的声明断言每个 `Person`、每个 `Cat` 和每个 `Dog` 都与自身年龄相同。

```
ObjectProperty: isAsOldAs
Domain: Person or Cat or Dog
Characteristics: Reflexive
```

当且仅当没有个体能与自身保持关系 *R* 时，环谓词 *R* 为*非自反*。例如，父母关系是非自反的，因为没有任何事物能成为其自身的父母。OWL 通过将对象属性表达式表征为*非自反属性*来声明其为非自反。在 Manchester 语法中，我们将“Irreflexive”声明为一种特征。例如，`isaParentOf` 谓词声明为非自反，如下所示。随后任何断言某人是其自身父母的行为都会导致 OWL 本体不一致。

```
Class: Person
ObjectProperty: isaParentOf
Domain: Person
Range: Person
Characteristics: Irreflexive
```

当且仅当 ∀*x*∀*y*(*xRy* → *yRx*) 时，环谓词 *R* 为*对称*；即对于每个个体 *x* 和 *y*（不必不同），若 *xRy* 则 *yRx* 也成立。例如，兄弟姐妹关系是对称的，因为如果一个人是另一个人的兄弟姐妹（兄/弟/姐/妹），则第二个人也是第一个人的兄弟姐妹。

OWL 通过将对象属性表达式表征为*对称属性*来声明其为对称。在 Manchester 语法中，我们将“Symmetric”声明为一种特征，例如，`isaSiblingOf` 可在 OWL 中声明为对称，如下所示。为完整起见，该谓词的非自反性质也被声明。

```
Class: Person
ObjectProperty: isaSiblingOf
Domain: Person
Range: Person
Characteristics: Symmetric, Irreflexive
```

在 OWL 中，若谓词被声明为对称，且我们断言了其事实实例，则可推断出其逆关系。例如，若我们添加以下声明：

```
Individual: Romulus
Facts: isaSiblingOf Remus
```

则可推断：

*   Individual: Remus Facts: isaSiblingOf Romulus.

在 ORM 中，将谓词约束为对称意味着断言的事实填充必须是对称的。例如，如果我们断言 Romulus 是 Remus 的兄弟姐妹，则必须同时断言 Remus 是 Romulus 的兄弟姐妹（两个事实均被存储）。然而在 OWL 中，你只需断言其中一个事实，另一个事实即可被推断。要在 ORM 中实现这一点，你需提供用于推断逆关系的推导规则，而非将事实类型约束为对称。

例如，在 ORM 中，你可将事实类型“Person is a sibling of Person”声明为*半派生*，意味着其部分实例可被断言，部分可被推导，并使用以下规则推导逆事实：`Person[1] is a sibling of Person[2] if Person[2] is a sibling of Person[1]`。在这种情况下，你会将兄弟姐妹事实类型约束为非自反，但不对称。

当且仅当对于每个个体 *x* 和 *y*（不必不同），若 *xRy* 则 *yRx* 不成立时，环谓词 *R* 为*非对称*。换言之，若关系成立，则其逆关系必不成立。例如，父母关系是非对称的，因为如果一个人是另一个人的父母，则第二个人不可能是第一个人的父母。

OWL 通过将对象属性表达式表征为*非对称属性*来声明其为非对称。在 Manchester 语法中，我们将“Asymmetric”声明为一种特征。例如，`isaParentOf` 谓词可在 OWL 中声明为非对称，如下所示。

```
Class: Person
ObjectProperty: isaParentOf
Domain: Person
Range: Person
Characteristics: Asymmetric
```

请注意，若谓词为非对称，则它自动也是非自反的（考虑 *x* = *y* 时非对称性的定义）。虽然非对称性蕴含非自反性，但反之不成立。例如，`isaSiblingOf` 是非自反的但非非对称。

若已声明上述非对称约束，且我们断言 Ann 是 Bill 的父母，则任何添加 Bill 是 Ann 的父母的事实的尝试都会导致 OWL 本体不一致。

### 环谓词 *R* 是*传递的*当且仅当，对于每个个体 *x*、*y* 和 *z*（不必互异），如果 *xRy* 和 *yRz*，那么 *xRz* 也成立。例如，祖先关系是传递的，因为如果一个人是另一个人的祖先，而第二个人是第三个人的祖先，那么第一个人就是第三个人的祖先。

忽略转世因素，祖先谓词实际上是非循环的（一个对象永远不可能通过应用一个或多个祖先事实而循环回到自身）。与 ORM 不同，OWL 不支持非循环约束。然而，OWL 确实允许通过将对象属性表述为传递的来声明其为传递的。在 Manchester 语法中，我们将“Transitive”声明为一个特征来实现这一点。例如，`isanAncestorOf` 谓词可以被声明为传递的，如下所示。为保持完整性，该谓词的非对称性质也被声明了。

```
Class: Person
ObjectProperty: isanAncestorOf
  Domain: Person
  Range: Person
  Characteristics: Transitive, Asymmetric
```

在 OWL 中，将祖先谓词声明为传递的并不要求必须断言其所有实例。例如，如果你将谓词声明为传递的，并断言 Ann 是 Bill 的祖先，Bill 是 Chris 的祖先，那么 OWL 推理器可以推断出 Ann 是 Chris 的祖先。

## OWL 2 中的枚举类型

回顾一下，OWL 允许你通过指定已声明的类或数据类型上的操作来定义一个新类或数据类型的*内涵*（即含义）。指定一个项目成为类型成员的必要且充分条件的类型定义，被称为该类型的*内涵定义*。例如，假设引用的类型（`Student`、`Employee`、`GradeNr`、`FailGradeNr`）已预先声明，则 `StudentEmployee` 和 `PassGradeNr` 的内涵定义可以在 Manchester 语法中声明如下：

```
Class: StudentEmployee
  EquivalentTo: Student and Employee
Datatype: PassGradeNr
  EquivalentTo: GradeNr and not FailGradeNr
```

一个类型所有可能实例的集合被称为该类型的*外延*。如果一个类或数据范围由一个已知的、有限的项目集合组成，它可以通过*枚举*（即列出）这些项目来定义。例如，虽然 `EvenDigit` 可以内涵地定义为 {*x* | *x* 是能被 2 整除的数字}，但它也可以外延地定义为 {0, 2, 4, 6, 8} 的成员。通过枚举其外延来定义的类型被称为*枚举类型*，其定义被称为*外延定义*。在 Manchester 语法中，使用常规的集合符号来指定外延，用大括号作为集合定界符，用逗号作为元素分隔符，例如：

```
Class: Weekday
  EquivalentTo: { Monday, Tuesday, Wednesday, Thursday, Friday }
Datatype: EvenDigit
  EquivalentTo: {0, 2, 4, 6, 8}
```

## 谓词上的“值”限制

OWL 松散地使用术语“*值*”，意指个体实体或字面值。基于此理解，一个命名类或（未命名）类表达式可以被定义为某个谓词的主语，其范围被限制为包含以下三种选项之一：(1) 某个特定值；(2) 来自指定类或数据范围的某个值；(3) 仅来自指定类或数据范围的值。我们依次考察这些情况。

在 Manchester 语法中，通过二元关系 *R* 与值 *v* 相关联的所有元素的集合简单地表示为“*R* value *v*”。作为选项 (1) 的示例，如果我们将 `Gender` 视为包含两个个体（male 和 female）的枚举类，以下 OWL 代码将 `MalePerson` 定义为性别为 male 的人的类。

```
ObjectProperty: Person hasGender
  Domain: Person
  Range: Gender
Class: Gender
  EquivalentTo: { male, female }
Class: MalePerson
  EquivalentTo: Person and hasGender value male
```

在 Manchester 语法中，通过 *R* 与指定子范围 *D* 中的某个值相关联的所有元素的集合简单地表示为“*R* some *D*”。作为选项 (2) 的示例，以下 OWL 代码将 `CarDriver` 定义为开车的人的类。

```
ObjectProperty: drives
  Domain: Person
  Range: Vehicle
Class: Car
  SubclassOf: Vehicle
Class: Driver
  EquivalentTo: Person and drives some Car
```
