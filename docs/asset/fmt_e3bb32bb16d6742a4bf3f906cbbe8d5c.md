
例如，许多企业在线培训网站使用联合 SSO 系统。当组织与在线培训公司协调员工访问权限时，也会协调联合访问所需的细节。一种常见方法是将用户的内部登录 ID 与联合身份匹配。用户使用其正常的登录 ID 在组织内登录。当用户使用网页浏览器访问培训网站时，联合身份管理系统使用其登录 ID 检索匹配的联合身份。如果找到匹配项，它将授权用户访问授予该联合身份的网页。

管理员在后台管理这些细节，该过程通常对用户透明。用户无需再次输入凭据。

多家公司在联盟中通信面临的一个挑战是寻找一种通用语言。它们通常拥有不同的操作系统，但仍需要共享一种通用语言。为解决这一挑战，联合身份系统通常使用安全断言标记语言 (SAML) 和/或服务供应标记语言 (SPML)。作为背景知识，以下是一些标记语言的简短描述。

### 超文本标记语言

超文本标记语言 (HTML) 通常用于显示静态网页。HTML 源自标准通用标记语言 (SGML) 和通用标记语言 (GML)。HTML 使用标签操纵文本的大小和颜色来描述数据如何显示。例如，以下 H1 标签将文本显示为一级标题：

```
<H1>I Passed The CISSP Exam</H1>
```

### 可扩展标记语言

可扩展标记语言 (XML) 不仅描述如何显示数据，还通过实际描述数据本身来超越这一点。XML 可以包含标签，将数据描述为任何期望的内容。例如，以下标签将数据标识为参加考试的结果：

```
<ExamResults>Passed</ExamResults>
```

来自多个供应商的数据库可以将数据导入和导出到 XML 格式，使 XML 成为交换信息的通用语言。已经创建了许多特定的模式，以便公司确切知道特定标签用于特定目的。这些模式中的每一个实际上都创建了一种新的 XML 语言。此处列出了一些用于联合身份的常用语言。

### 安全断言标记语言

安全断言标记语言 (SAML) 是一种基于 XML 的语言，常用于在联合组织之间交换认证和授权 (AA) 信息。它常用于为浏览器访问提供 SSO 功能。

### 服务供应标记语言

**服务供应标记语言 (SPML)** 是由 OASIS 开发的一个较新框架，OASIS 是一个鼓励开发开放标准的非营利性联盟。它基于 XML，专门设计用于为联合身份 SSO 目的交换用户信息。它基于目录服务标记语言 (DSML)，后者可以以 XML 格式显示基于 LDAP 的目录服务信息。

### 可扩展访问控制标记语言

**可扩展访问控制标记语言 (XACML)** 是由 OASIS 开发的标准，用于在 XML 格式中定义访问控制策略。它通常将策略实现为基于属性的访问控制系统，但也可以使用基于角色的访问控制。它有助于向联合体中的所有成员提供保证，即他们授予不同角色相同级别的访问权限。

### OAuth 2.0

**OAuth 2.0**（意指开放授权）是一个用于访问委派的开放标准。举个例子，假设你有一个 Twitter 账户。然后你下载了一个名为 Acme 的应用程序，它可以与你的 Twitter 账户交互。当你尝试使用此功能时，它会将你重定向到 Twitter，如果你尚未登录，系统会提示你登录 Twitter。随后 Twitter 会询问你是否要授权该应用程序，并告知你将授予哪些权限。如果你批准，Acme 应用程序就可以访问你的 Twitter 账户。一个主要优势是你永远不需要将 Twitter 凭据提供给 Acme 应用程序。即使 Acme 应用程序遭遇重大数据泄露并暴露其所有数据，也不会暴露你的凭据。许多在线网站支持 OAuth 2.0，但不支持 OAuth 1.0。OAuth 2.0 与 OAuth 1.0 不向后兼容。RFC 6749 记录了 OAuth 2.0。

### OpenID

**OpenID** 也是一个开放标准，但它由 OpenID 基金会维护，而非作为 RFC 标准。它提供去中心化认证，允许用户使用由第三方服务（称为 OpenID 提供商）维护的一组凭据登录多个不相关的网站。当用户访问启用了 OpenID 的网站（也称为信赖方）时，系统会提示他们提供作为统一资源定位符 (URL) 的 OpenID 身份。这两个网站交换数据并创建一个安全通道。然后用户被重定向到 OpenID 提供商并提示提供密码。如果正确，用户将被重定向回启用了 OpenID 的网站。

### OpenID Connect

**OpenID Connect** 是一个使用 OAuth 2.0 框架的认证层。与 OpenID 一样，它由 OpenID 基金会维护。它基于 OpenID 创建的技术构建，但使用 JavaScript 对象表示法 (JSON) Web 令牌 (JWT)，也称为 ID 令牌。OpenID Connect 使用符合表述性状态转移 (REST) 的 Web 服务来检索 JWT。除了提供认证外，JWT 还可以包含用户的配置文件信息。

#### 脚本访问

**脚本访问** 或登录脚本通过提供自动化流程在登录会话开始时传输登录凭据来建立通信链接。脚本访问通常可以模拟 SSO，即使环境仍然需要唯一的认证过程来连接到每个服务器或资源。在真正的 SSO 技术不可用的环境中，可以使用脚本来实现 SSO。脚本和批处理文件应存储在受保护的区域，因为它们通常包含明文访问凭据。

### 凭据管理系统

**凭据管理系统** 为用户提供存储空间以在 SSO 不可用时保存其凭据。用户可以存储需要不同凭据集的网站和网络资源的凭据。管理系统通过加密保护凭据以防止未经授权的访问。

例如，Windows 系统包含凭据管理器工具。用户将凭据输入凭据管理器，并在必要时，操作系统检索用户的凭据并自动提交它们。当用于网站时，用户输入 URL、用户名和密码。稍后，当用户访问该网站时，凭据管理器会自动识别该 URL 并提供凭据。

第三方凭据管理系统也可用。例如，KeePass 是一款免费工具，允许你存储凭据。凭据存储在加密数据库中，用户可以使用主密码解锁数据库。解锁后，用户可以轻松复制密码粘贴到网站表单中。也可以将应用程序配置为自动将凭据输入网页表单。当然，使用强主密码保护所有其他凭据非常重要。

### 集成身份服务

身份服务为识别和认证提供额外工具。一些工具专门为基于云的应用程序设计，而另一些则是设计用于组织内部（本地部署）的第三方身份服务。

**身份即服务**，或身份与访问即服务 (IDaaS)，是一种提供身份和访问管理的第三方服务。IDaaS 实际上为云提供 SSO，当内部客户端访问基于云的软件即服务 (SaaS) 应用程序时特别有用。Google 通过其“一个 Google 账户畅享所有 Google 服务”的座右铭实现了这一点。用户登录其 Google 账户一次，即可访问多个基于云的 Google 应用程序，而无需再次登录。

作为另一个例子，Office 365 将 Office 应用程序作为安装型应用程序和 SaaS 应用程序的组合提供。用户在其系统上安装了完整的 Office 应用程序，这些应用程序也可以使用 OneDrive 连接到云存储。这允许用户从多个设备编辑和共享文件。当人们在家使用 Office 365 时，Microsoft 提供 IDaaS，允许用户通过云进行认证以访问其 OneDrive 上的数据。

当员工在企业内部使用 Office 365 时，管理员可以将网络与第三方服务集成。例如，Centrify 提供可与 Microsoft Active Directory 集成的第三方 IDaaS 服务。配置完成后，用户登录域，然后即可访问 Office 365 云资源，无需再次登录。

### 管理会话

使用任何类型的认证系统时，管理会话以防止未经授权的访问非常重要。这包括常规计算机（如台式机）上的会话以及与应用程序的在线会话。

台式机和笔记本电脑包含屏幕保护程序。当计算机未被使用时，这些程序会通过显示随机图案、不同图片或仅仅是将屏幕变黑来更改显示。屏幕保护程序保护了旧式计算机的屏幕，但新型显示器不再需要它们。然而，它们仍在使用，并且屏幕保护程序具有可启用的密码保护功能。此功能显示登录屏幕，并强制用户在退出屏幕保护程序前再次进行认证。

屏幕保护程序有一个以分钟为单位的可配置时间范围。它们通常设置为 10 到 20 分钟之间。如果你将其设置为 10 分钟，它将在 10 分钟后激活。这要求用户在系统空闲 10 分钟或更长时间后再次登录。

安全的在线会话通常也会在一段时间后终止。例如，如果你与银行建立了安全会话，但在 10 分钟内未与该会话交互，应用程序通常会将你注销。在某些情况下，应用程序会给你一个通知，提示即将注销。这些通知通常会给你一个机会，点击页面以保持登录状态。如果开发人员不实现这些自动注销功能，就会允许用户的浏览器会话在用户处于登录状态下保持打开。即使用户在未注销的情况下关闭浏览器标签页，也可能会使浏览器会话保持打开状态。如果其他人访问该浏览器，这会使得用户的账户容易受到攻击。

### AAA 协议

有几种协议提供认证、授权和审计，被称为 AAA 协议。这些协议为远程访问系统（如虚拟专用网络（VPN）和其他类型的网络接入服务器）提供集中式访问控制。它们有助于保护内部局域网认证系统和其他服务器免受远程攻击。当使用单独的系统进行远程访问时，对该系统的成功攻击仅影响远程访问用户。换句话说，攻击者将无法访问内部账户。移动 IP（为智能手机移动用户提供接入）也使用 AAA 协议。

这些 AAA 协议使用本章前面所述的访问控制要素：标识、认证、授权和问责。它们确保用户拥有有效的凭据进行认证，并基于用户已证明的身份验证用户是否被授权连接到远程访问服务器。此外，审计要素可以跟踪用户的网络资源使用情况，可用于计费目的。下面介绍一些常见的 AAA 协议。

#### RADIUS

`Remote Authentication Dial-in User Service (RADIUS)` 为远程连接集中认证。通常在组织拥有多个网络接入服务器（或远程访问服务器）时使用。用户可以连接到任意网络接入服务器，后者将用户的凭据传递给 RADIUS 服务器以验证认证和授权并跟踪审计。在此背景下，网络接入服务器是 RADIUS 客户端，而 RADIUS 服务器充当认证服务器。RADIUS 服务器还为多个远程访问服务器提供 AAA 服务。

许多互联网服务提供商（ISP）使用 RADIUS 进行认证。用户可以从任何地方访问 ISP，然后 ISP 服务器将用户的连接请求转发给 RADIUS 服务器。

组织也可以使用 RADIUS，且通常结合基于位置的安全性实施。例如，如果用户通过 IP 地址连接，系统可以使用地理定位技术识别用户的位置。虽然现在不太常见，但一些用户仍使用综合业务数字网（ISDN）线路连接到 VPN。RADIUS 服务器可以使用回拨安全性提供额外的保护层。用户拨入，认证后，RADIUS 服务器终止连接并回拨用户预定义的电话号码。如果用户的认证凭据泄露，回拨安全性可防止攻击者利用它们。

RADIUS 使用 `User Datagram Protocol (UDP)` 且仅加密密码的交换过程。它不加密整个会话，但可使用额外的协议来加密数据会话。当前版本定义在 `RFC 2865` 中。

#### TACACS+

`Terminal Access Controller Access-Control System (TACACS)` 作为 RADIUS 的替代方案被引入。Cisco 后来推出了作为专有协议的扩展 TACACS（`XTACACS`）。然而，TACACS 和 XTACACS 如今不常用。后来创建了作为开放公开文档协议的 TACACS Plus（`TACACS+`），它是三者中最常用的。

与早期版本和 RADIUS 相比，TACACS+ 提供了多项改进。它将认证、授权和审计分离为独立的进程，如需要可托管在三台独立的服务器上。其他版本将其中两个或三个进程合并。此外，TACACS+ 加密所有认证信息，而不仅像 RADIUS 那样仅加密密码。TACACS 和 XTACACS 使用 `UDP` 端口 49，而 TACACS+ 使用 `Transmission Control Protocol (TCP)` 端口 49，为数据包传输提供了更高的可靠性。

#### Diameter

基于 RADIUS 和 TACACS+ 的成功，开发了 RADIUS 的增强版本 `Diameter`。它支持广泛的协议，包括传统 IP、移动 IP 和 IP 语音（`VoIP`）。因为它支持额外的命令，所以在需要漫游支持的场景（如无线设备和智能手机）中越来越流行。虽然 Diameter 是 RADIUS 的升级版，但它不向后兼容 RADIUS。

Diameter 使用 `TCP` 端口 3868 或 `Stream Control Transmission Protocol (SCTP)` 端口 3868，比 RADIUS 使用的 UDP 提供了更好的可靠性。它还支持 `Internet Protocol security (IPsec)` 和 `Transport Layer Security (TLS)` 进行加密。

### 管理身份与访问配置生命周期

`identity and access provisioning lifecycle`（身份与访问配置生命周期）指账户的创建、管理和删除。虽然这些活动看似平常，但它们对系统的访问控制能力至关重要。如果没有正确定义和维护的用户账户，系统就无法建立准确的身份、执行认证、提供授权或跟踪问责。如前所述，标识发生在主体声称身份时。这种身份最常见的是用户账户，但也包括计算机账户和服务账户。

访问控制管理是在账户生命周期内管理账户、访问权限和问责所涉及的任务和职责的集合。这些任务包含在身份与访问配置生命周期的三个主要职责中：配置、账户审查和账户撤销。

#### 配置

身份管理的初始步骤是创建新账户并为其配置适当的特权。创建新用户账户通常是一个简单的过程，但该过程必须通过组织安全策略程序得到保护和保障。用户账户不应随管理员意愿创建，也不应响应随意请求而创建。相反，适当的配置确保人员在创建账户时遵循特定程序。

新用户账户的初始创建通常称为 `enrollment`（注册）或登记。注册过程创建新身份并建立系统执行认证所需的因素。注册过程必须完整且准确地完成至关重要。同样至关重要的是，通过组织认为必要且充分的任何手段，证明被注册人员的身份。照片 ID、出生证明、背景调查、信用检查、安全许可验证、FBI 数据库搜索，甚至致电推荐人，都是在将人员注册到任何安全系统之前验证其身份的有效形式。

许多组织都拥有自动化供给系统。例如，一旦录用某人，人力资源部门完成初始身份识别和入职步骤，然后向 IT 部门转发创建账户的请求。IT 部门内的用户通过应用程序输入信息，如员工姓名及其分配的部门。然后，应用程序使用预定义规则创建账户。自动化供给系统能一致地创建账户，例如始终以相同方式创建用户名，并一致地处理重复用户名。如果策略规定用户名包含名和姓，则应用程序将为名为 Suzie Jones 的用户创建用户名 `suziejones`。如果组织雇佣了第二名同名员工，则第二个用户名可能是 `suziejones2`。

如果组织使用组（或角色），应用程序可以根据用户的部门或工作职责，自动将新用户账户添加到适当的组中。这些组已分配有适当的特权，因此此步骤可为账户供给适当的特权。

作为招聘流程的一部分，新员工应接受组织安全策略和程序的培训。在招聘完成前，员工通常需要审查并签署一份协议，承诺遵守组织的安全标准。这通常包括可接受使用策略。

在用户账户的整个生命周期中，都需要持续的维护。拥有静态组织层级、低员工流动率或晋升率的组织，所进行的账户管理工作将显著少于拥有灵活或动态组织层级、高员工流动率和晋升率的组织。大多数账户维护涉及更改权利和特权。应建立类似于创建新账户时使用的程序，以管控用户账户生命周期内访问权限的变更方式。账户访问能力的未授权增加或减少可能导致严重的安全后果。

#### 账户审查

应定期审查账户，以确保安全策略得到执行。这包括确保禁用非活动账户，以及员工不拥有过度特权。

许多管理员使用脚本定期检查非活动账户。例如，脚本可以定位过去 30 天内用户未曾登录的账户，并自动禁用它们。同样，脚本可以检查特权组（如管理员组）的组成员身份，并移除未授权账户。账户审查通常在审计程序中正式化。

必须防范与访问控制相关的两个问题：过度特权和特权蔓延。`过度特权` 是指用户拥有的特权超出了其分配的工作任务所要求的范围。如果发现用户账户具有过度特权，应立即撤销不必要的特权。`特权蔓延`（有时称为 `privilege creep`）涉及用户账户随着工作角色和分配任务的变化，随时间积累特权。这可能是因为向用户的工作中添加了新任务并增加了相应特权，但从未移除不再需要的特权。特权蔓延会导致过度特权。

这两种情况都违反了最小特权这一基本安全原则。最小特权原则确保主体仅被授予执行其工作任务和职能所需的特权，而不多授予任何额外特权。账户审查能有效发现这些问题。

#### 账户撤销

无论出于何种原因，当员工离开组织时，尽快禁用其用户账户非常重要。这包括员工休假的情况。只要有可能，人力资源人员应具备执行此任务的能力，因为他们知晓员工因任何原因离职的情况。例如，人力资源人员知道员工即将被解雇，他们可以在员工离职面谈期间禁用账户。

如果已解雇的员工在离职面谈后仍保留对用户账户的访问权限，破坏活动的风险极高。即使该员工不采取恶意行动，如果其他员工发现了密码，也可能使用该账户。日志将以已解雇员工的名义记录活动，而不是实际执行操作的人。

该账户可能仍被需要，例如用于访问加密数据，因此不应立即删除。当确定不再需要该账户时，应将其删除。账户通常在禁用后 30 天内删除，但这可能因组织需求而异。

许多系统都有为任意账户设置特定过期日期的功能。这些对于临时或短期员工很有用，并可在过期日期自动禁用账户，例如为期 30 天合同雇佣的临时员工，在 30 天后自动禁用。这在不需要持续管理监督的情况下保持了一定程度的控制。

### 摘要

CISSP 通用知识体系的第 5 领域是身份与访问管理（IAM）。它涵盖了授予或限制对资产访问的管理、行政和实施方面。资产包括信息、系统、设备、设施和人员。访问控制基于主体和客体之间的关系来限制访问。主体是主动实体（如用户），客体是被动实体（如文件）。

三种主要的访问控制类型是预防性、检测性和纠正性。预防性访问控制试图在事件发生前防止事件。检测性访问控制试图在事件发生后检测事件。纠正性访问控制试图在检测到事件后纠正事件造成的问题。
