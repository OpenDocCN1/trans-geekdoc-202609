
```sql
select Employee.name, Department.name
from Employee join Department
using (deptCode)
where gender = 'F'
```

正如您可能意识到的，前两个模式中的列命名选择并不理想。如果不同表中的两列意图表示同一事物，最好在这些表中给这些列相同的名称（只要可能）。虽然这非正式，但它使表之间预期的语义联系更易于察觉，尤其是那些没有外键引用的表。对于讨论中的模式，“deptCode”可统一用于部门代码，员工姓名和部门名称可区分为“empName”和“deptName”，如下所示：

![](img/u12-08-9780443237904.jpg)

使用这个新模式，前面考虑的条件连接查询需要限定连接中使用的列名，因为它们的非限定名称出现在两个表中。这给出：

*   ```sql
    select empName, deptName
    ```
*   ```sql
    from Employee join Department
    ```
*   ```sql
    on Employee.deptCode = Department.deptCode
    ```
*   ```sql
    where gender = 'F'
    ```

对于新模式，列表查询不需要对列名进行任何限定，如下所示。

*   ```sql
    select empName, deptName
    ```
*   ```sql
    from Employee join Department
    ```
*   ```sql
    using (deptCode)
    ```
*   ```sql
    where gender = 'F'
    ```

正如您可能注意到的，前两个查询中的底层连接操作现在是*自然连接*，因为我们在*所有*同名列上进行等值连接（在本例中只有一个这样的列：`deptCode`）。

正如关系代数中所讨论的，*自然内连接*执行等值连接以匹配所有具有相同本地名称的列，然后移除这些列的额外副本。在 SQL-89 中，自然内连接通过首先形成（`from`子句中列出的表的）笛卡尔积，然后在`where`子句中指定连接条件，使用`select`列表过滤掉不需要的重复列来指定。在 SQL-92（及更高版本）中，自然内连接可以通过在`from`子句中的`join`前插入`natural`或`natural inner`来简单声明（限定连接和自然连接默认为内连接）。

新符号有三个主要优势：它更具描述性；`natural join`运算符直接支持关系代数的`natural inner join`运算符（⨝）；并且通常更简洁。例如，刚才考虑的查询可以更简洁地重新表述为：

*   ```sql
    select empName, deptName
    ```
*   ```sql
    from Employee natural join Department
    ```
*   ```sql
    where gender = 'F'
    ```

无需显式声明连接条件 `Employee.deptCode = Department.deptCode`，因为这由`natural`的使用以及“deptCode”是`from`子句中列出的表的唯一公共列名这一事实隐含。随着查询中自然连接数量的增加，这种新符号的紧凑性变得更加明显。例如，考虑以下关系模式。

目前，大多数 SQL 方言（包括 SQL Server）不支持自然连接语法。相反，通常使用条件连接语法来处理自然连接。例如，图 12.43 中的查询可以重新表述如下：

```sql
select Employee.empNr, empName, carModel
from Employee join Drives
on Employee.empNr = Drives.empNr
join Car
on Drives.carRegNr = Car.carRegNr
```

或者，也可以使用 SQL-89 语法，如下所示：

```sql
select Employee.empNr, empName, carModel
from Employee, Drives, Car
where Employee.empNr = Drives.empNr
and Drives.carRegNr = Car.carRegNr
```

当使用自然连接运算符时，`select` 列表中的任何连接列必须用其局部（非限定）名称表示。如果使用其他语法（例如条件连接或 SQL-89 语法）指定自然连接，则连接列必须限定。

虽然实践中大多数连接都是自然内连接，但有时应避免使用自然连接。自然连接操作不能用于连接名称不同的列。例如，它无法在图 12.42 的查询中连接 `dept.` 和 `deptCode`。此外，如果 `from` 子句中的不同表包含同名但不应等同的列，则不得使用自然连接操作。例如，考虑我们列表连接示例的表模式：*Department* (`deptCode`, `name`)；*Employee* (`empNr`, `name`, `deptCode`, `gender`)。

*Department* 和 *Employee* 之间的自然连接不仅会等同 `deptCode`，还会等同 `name`。结果中的任何行都会将员工姓名与部门名称等同，这毫无意义。

有时，我们确实希望在多个列上自然连接两个表。例如，回顾关系代数部分讨论的以下模式。

![](img/u12-10-9780443237904.jpg)

要列出所有账户的余额和客户详细信息，需要在 `account`（复合标识符）上进行复合连接，在 `client` 上进行简单连接。这可以用自然连接语法指定为：

```sql
select * from Account natural join AcUser natural join Client
```

或者作为条件连接：

```sql
select Account.branchNr, Account.accountNr, balance,
       Client.clientNr, clientName
from Account join AcUser
on Account.branchNr = AcUser.branchNr
and Account.accountNr = AcUser.accountNr
join Client
on AcUser.clientNr = Client.clientNr
```

对于条件连接、列列表连接和自然连接，除非显式指定外连接（见后文），否则 `join` 默认指内连接。在这些情况下，可以显式声明 `inner`（例如 `inner join` 或 `natural inner join`）。如果声明了 `natural`，则不得使用 `on` 子句或 `using` 子句。如果连接表达式中包含三个或更多表，连接通常按从左到右的顺序求值。也可以通过插入括号来控制连接顺序。因为自然内连接具有结合性，所以其顺序不影响实际结果。

到目前为止，我们已经讨论了表 12.8 中列出的八种连接中的四种。还有三种外连接，以及一种联合连接。联合连接很少使用，不再进一步讨论。*外连接*可以是*左*、*右*或*全*外连接。左外连接和右外连接在商业应用中经常遇到。给定两个表 *A* 和 *B*，它们的左/右/全外连接是通过先计算它们的内连接，然后添加左/右/两个表中在内连接中没有匹配的行，并用 null 填充结果表中的额外列来形成的。

自然内连接产生两个驾驶员（员工 001 和 003）的三行结果。员工 002 和 004 在 *Drives* 表中没有匹配项。左外连接添加它们的行，并用 `carRegNr` 的 null 值填充。我们将 null 值显示为“？”。某些系统将其显示为空白或“NULL”。许多系统允许您选择如何显示 null 值。

虽然条件连接语法要求连接列使用限定列名，但当显示结果表时，某些系统（如 SQL Server）足够智能，可以从列标题中省略表限定（如图 12.45 所示）。某些系统支持在外连接成为 SQL-92 标准一部分之前引入的替代外连接语法。这种语法通常具有不同的语义，除非不支持标准语法，否则绝不应使用。

SQL-92 及更高版本是*正交*的。任何合法值的地方，返回该值的任何表达式也合法。这使语言更易于使用，并增加了单个查询的表达能力。然而，许多商业系统并非完全正交，且经常对外连接查询施加限制（例如，最多允许一个外连接，或外连接后不允许其他连接）。对于此类系统，有时有必要将单个标准查询表述为一系列使用中间表存储中间结果的查询。

## SQL 连接类型与语法

右外连接类似于左外连接。全连接是左连接和右连接的并集。关键字 `outer` 在左/右/全连接中是隐含的，因此可以省略（例如 `natural left join` 或 `left join`）。外连接不满足结合律，因此在对三个或更多表进行外连接时，要小心连接顺序。正如稍后讨论的那样，外连接可以通过 `union` 和子查询在旧的 SQL-89 语法中进行模拟。

当必须比较同一表的不同行时，我们需要将表与自身连接。这种*自连接*在第 12.1 节中已讨论过。回顾一下，这需要为该表引入一个别名。在 SQL 中，*临时别名*可以在 `from` 子句中它所代替的表之后，作为*元组变量*声明。该变量可以被赋予表中的任意行，有时被称为“相关变量”、“范围变量”或“表标签”。为了清晰起见，可以使用 `as` 来引入别名。

图 12.46 提供了一个简单示例。基表 `Scientist` 存储各科学家的姓名和性别，查询列出性别相反的科学家对。别名 `S1` 和 `S2` 在 `from` 子句中声明。要理解自连接，可将 `S1` 和 `S2` 视为原始基表的副本，如图所示。条件连接对性别执行 `<>`-连接（以确保性别相反），并对 `PersonName` 执行 `<`-连接（以确保每对仅出现一次，而不是按两种顺序都出现）。

![图 12.46 使用自连接列出性别相反的科学家对。](img/f12-46-9780443237904.jpg)

图 12.46 使用自连接列出性别相反的科学家对。

某些 SQL 版本还提供“创建同义词”命令，用于声明永久别名定义。然而，这不属于标准的一部分。以简化形式，SQL 查询的 `from` 子句语法可按以下 BNF 进行总结（对于大括号中的备选项，恰好需要一个）：

*   ```bnf
    from table [ [as] alias ]
    ```
*   ```bnf
                [ , | cross join table [ [ as ] alias ]
    ```
*   ```bnf
                | natural [ inner | { left | right | full } [ outer ] ] join table [ [as] alias ]
    ```
*   ```bnf
                                        | [ inner | { left | right | full } [ outer ] ] join table [ [ as ] alias ]
    ```
*   ```bnf
                                                                        { on condition | using ( col-list ) }
    ```
*   ```bnf
                                        | union join table [ [ as ] alias ]
    ```
*   ```bnf
                                        [ ,... ] ]
    ```

在构思 SQL 查询时，关系代数中讨论的指导原则通常适用。首先，用英语清晰地陈述查询。然后尝试自己解决查询，观察你是如何做到的。然后将你的步骤形式化为 SQL。这通常包含以下步骤。

哪些表包含所需信息？在 `from` 子句中命名这些表。你想要哪些列，以及按什么顺序？在 `select` 列表中命名这些列（如有必要请加上限定符）。如果 `select` 列表不包含键，而你希望避免重复行，请使用 `distinct` 选项。

如果你需要 *n* 个表，请指定 *n − 1* 个连接条件。你想要哪些行？在 `where` 子句中指定搜索条件。你想要行按什么顺序排列？为此使用 `order by` 子句。

SQL-92 中引入的新连接语法很方便，但在功能方面增加的不多。最有用的表示法是条件连接和自然连接（包括内连接和外连接）的表示法。

如果你使用的 SQL 版本不支持新语法，你应该特别小心，详细指定连接条件，并在需要时限定列名。

任何 SQL 语句都可以包含*注释*。这些可用于解释、文档记录，或仅仅是为了调试而注释掉某些代码（注释在执行时会被忽略）。

在 SQL-92 中，注释以两个连续的连字符“--”开始，并在行尾结束。除了这些单行注释外，SQL:1999 还引入了多行注释，以“/*”开始，以“*/”结束。SQL Server 同时支持这两种注释风格。示例如下：

```sql
-- 此查询检索开车的员工详情
select *        -- 选择所有列
from Employee natural join Drives
/* 如果不支持自然连接语法，
     则省略 "natural"，并在 on-子句
     中指定连接条件 */
```
