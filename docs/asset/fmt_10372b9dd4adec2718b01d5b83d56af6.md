
* 现有多个 **Hyperledger** 框架，如 `Hyperledger Burrow`、`Fabric`、`Indy`、`Iroha` 和 `Sawtooth`。此外，还有一些相关工具，包括 `Hyperledger Caliper`、`Composer`、`Cello`、`Explore` 和 `Quilt`。

* **Corda** 平台旨在以隐私和法律确定性管理现实世界的交易，并可在同一个开放网络上跨多个参与者群体及相关应用运行，这与其他“许可制”区块链平台形成对比。

* 金融行业的需求构成了 **Corda** 设计的基础，但实践经验表明，Corda 技术似乎广泛适用于银行业以外的用例。

## 摘要

第 8 章是本书中涉及区块链应用设计、开发和测试的三章中的第一章。本章首先概述了一系列考量因素，区块链应用开发人员必须在设计过程中对其进行评估。这些因素包括：应用程序是需要功能繁多还是功能精简；应用程序需要在多大程度上进行专业化；应用程序的支持需要是中心化还是去中心化；以及应用程序需要在多大程度上具备可扩展性。此外，本章还介绍了一个虚构的案例研究，包含两个用户画像及其用户故事，旨在让读者熟悉创建用户画像及其用户故事的必要性，以此作为确定应用程序功能需求的第一步。随后，功能需求被转化为技术需求，进而引出创建与完成应用程序设计流程相关的具体任务和步骤的过程。

## 区块链设计指导原则与考量因素

### 首先，我们是否需要区块链解决方案？

正如前几章所讨论的，数据库应用程序是一种存储、操作和检索数据的计算机程序。数据范围可以从数字到复杂结构 [5]。区块链由一种数据结构组成，用于保存网络中交易的记录 [3]。重要的是要注意，虽然区块链是一种数据库，但数据库不一定是区块链 [5]。进一步解释，区块链技术与数据库技术之间存在显著差异，如下所示：

* **存储**：区别于其他技术的主要特性是区块链存储记录的不可篡改性。为实现这种不可篡改性，它结合加密和共识机制，将数据存储在分布式节点中。虽然区块链设计为去中心化运行，但数据库始终是中心化的，这意味着它们运行在一台服务器上，用户无法下载它们。数据库通常经过安全防护，因为它们往往包含敏感的用户和业务数据。另一方面，区块链没有中心化结构。数据分布在整个网络中，网络的任何用户都可以下载它们 [3]。

* **共识与权限**：另一个需要考虑的要点是，区块链依赖共识概念，而数据库依赖权限。共识算法是一种规定在何种条件下可将数据应用于区块链的公式。尽管共识关注的是如何将新数据应用于区块链并进行验证，但去中心化指的是区块链不为单一实体所有这一理念。这确保了数据库不托管在属于单一组织的中央服务器上。任何想要下载区块链的机器都可以拥有一份副本 [5]。

* **管理**：数据库包含有关数据性质的详细信息。另一方面，区块链作为存储媒介，用于存放称为*区块*的捆绑信息块 [2]。

* **修改**：数据库是可修改的。这意味着如果用户拥有权限，他们可以记录、修改甚至删除已备份数据库中的记录。区块链包含一项额外的安全功能，使其难以被黑客攻击或篡改 [18]。

* **透明度**：区块链的另一个重要特性是，在开放的公共区块链情况下，用户可以访问区块链上的数据。另一方面，数据库因其中心化的本质，无法提供同等程度的透明度。

* **成本**：由于数据库技术已存在数十年，传统数据库包的部署成本通常低于区块链解决方案。因此，传统数据库技术可能是企业更具成本效益的替代选择，特别是在考虑相关成本/收益分析中的各种人工成本时。

* **人才获取**：由于区块链是一项相对较新的技术，目前可用于处理各种区块链开发应用的人才库较小。此外，雇佣合格区块链人才的相关获取成本目前相当可观。另一方面，数据库相关人才相对容易寻找。他们也具有成本效益，因此即使是小企业也能负担得起聘请数据库专家 [13]。

* **仅追加**：最后，区块链“仅追加”的特性将其与传统数据库区分开来。也就是说，新数据不会替换旧数据；相反，它们以一种可以追溯所有变更的方式被添加到数据库中。在传统关系型数据库中，除非经过专门设计，否则新数据不会替换旧数据。这是因为区块链将数据组织成区块，每个区块由时间戳和前一个数据区块的哈希值（或签名）标识。这使得跨时间关联数据和跟踪区块链上的变更成为可能。这种功能可以融入传统数据库中（例如银行的交易历史），但它不是传统数据库的必备特性 [5]。

就实用性、速度和准确性而言，数据库技术往往是明显的赢家。然而，在创造性、认证和自动化方面，区块链可以提供额外优势。简而言之，对于信任、问责和验证，区块链通常是首选。另一方面，数据库非常适合高性能应用和服务。它也是需要扩展的应用程序的绝佳选择 [13]。

### 应用程序需要是功能繁多还是功能精简？

在开发去中心化应用（DApp）时，了解用户需求至关重要。如果无法满足用户标准，会使 DApp 使用起来非常复杂和/或令人沮丧。为用户提供大量功能乍看似乎是一个合理的目标，但功能过多可能会让用户不知所措，从而不愿选择具有额外功能的应用程序 [22]。

渐进式 Web 应用（PWA）是一种现代网站，它通过浏览器提供原生应用的交互体验。即使计算机未连接互联网，PWA 也能正常工作。为了实现丰富的基于 Web 的交互，PWA 使用了推送通知、缓存和稳定连接等现代 Web 功能。应用设计中的 PWA 功能需要更长的设计时间。在短时间内设计具有额外功能的应用程序可能会产生问题。原生应用可直接访问设备硬件。与原生应用不同，Web 无法完全访问设备的硬件功能。手机上可以实现硬件的完整功能，尽管由于 JavaScript 相关的限制，Web 浏览器上并不总是能使用这些功能。进一步解释说，JavaScript 是单线程程序；这意味着在执行一个操作时，必须延迟另一个操作。在这种情况下，使用 `C` 语言或其他提供同时运行多条命令能力的编程语言编写的原生代码将是可行的 [23]。

任何用户的首要任务都是以最小的干扰，有效且高效地使用应用程序。应用程序必须简单、直接且易于用户理解。用户界面是使应用程序简单化的第一步，但这种简洁性并不单纯取决于用户界面。此外，应用程序必须符合用户需求，并应专注于使 DApp 独具特色的不同功能。因此，应用程序功能和设计的大多数属性应当功能精简 [22]。

### 协作与安全，哪个更重要？

协作在建立和执行协作流程方面可带来显著的成本和时间节省，尤其是在参与协作的第三方之间存在信任问题时。协作流程可通过依赖受信任的第三方合作伙伴来执行 [7]。

#### 为安全与隐私而设计

由于区块链应用连接到没有中央权威的公共或私有网络，因此安全性和隐私性是在设计区块链应用时最基本的考量。除政府机密网络外，区块链应用像其他网络一样通常连接到互联网。因此，公司必须妥善实施安全和隐私措施。
