
# SSL 和 TLS

SSL 和 TLS 分别代表 Secure Sockets Layer（安全套接字层）和 Transport Layer Security（传输层安全），它们是一套用于确保互联网上安全通信的规则和程序。这些协议确保了通过网络发送的数据的机密性和可靠性，例如在访问网站或进行电子商务交易时。

## Internet Protocol Security (IPSec)

IPSec 是一组用于保护 IP 网络上通信安全的协议。它常用于通过互联网保护两个私有网络之间的通信，例如建立 VPN 时。

## Secure Shell (SSH)

SSH 是一种用于保护远程登录和其他网络服务安全的加密协议。它为网络上传输的数据提供机密性和完整性，常用于服务器和其他网络设备的远程管理。

## Pretty Good Privacy (PGP)

PGP 是一种用于加密和数字签名的协议，常用于电子邮件和文件加密。它是一个软件包，结合使用了对称密钥和公钥密码学。

## Kerberos

Kerberos 是一种网络认证协议，用于在非安全网络上保护通信安全。它为网络服务提供认证和机密性，常用于企业环境。

## Open Authorization (OAuth)

OAuth 是一种用于访问委托的开放标准，常用于互联网用户授权网站或应用程序访问其在其他网站上的信息，而无需提供密码。

每种协议都有其自身的优缺点，选择使用哪种协议将取决于应用程序的具体需求。

# 密钥管理

密钥管理是在密码学网络中处理用于各种目的的密钥的实践。密码学密钥的功能类似于我们日常生活中用来解锁财物的物理钥匙。密码学密钥由一组用于保护或解密密码学特性的数据组成。密钥管理的主要目标是监督密钥的创建、分发、保存、应用、替换和销毁。这涵盖了密码学协议开发、密钥服务器、用户协议、认证、授权、加密和其他相关协议。

正如物理钥匙有各种形状和大小且具有不同的应用一样，密码学密钥在形式和功能上也各不相同。这些密钥根据其在密码学操作中的具体角色被分为多个类别。

密钥管理主要有三种方法，可分为去中心化、分布式和中心化。

- **去中心化方法**：最终用户独自负责管理自己的密钥，组织不参与密钥的治理过程。
- **分布式方法**：组织内的每个团队或部门根据其各自的流程和策略实施自己的密钥管理协议。这些团队在密钥管理方面可能协作或协调，也可能不协作。
- **中心化方法**：实施适用于整个组织的统一策略，所有团队和部门均需遵守。组织内的所有用户遵循相同的密钥管理协议。

此外，密码学密钥还根据基本类型衍生出许多变体，通过增加细微的安全缓解措施使其更难被破解。

密钥管理对密码系统的安全至关重要。它是密码学中最困难的过程之一，涉及系统策略、用户培训、机构和部门间交互等广泛视角。

## 密钥管理流程

密钥管理包含以下阶段：

### 密钥交换

密码学操作需要密码学密钥。公钥可以公开共享，而对称密钥需要安全连接。传统方法涉及通过外交邮袋等安全渠道传输密钥，并采用 `Diffie-Hellman` 密钥交换等协议。

### 密钥存储

密钥存储是指对密码学密钥的安全管理，确保其正确分配和保护。安全存储分布式密钥有多种方法。应用程序负责处理密钥，并使用访问密码来控制其使用。

### 密钥使用

随着密钥使用时间周期的增加，风险因素也会上升。因为黑客攻击的风险与同一密钥的使用时长成正比。因此密钥应频繁更换，以限制被攻破的机会。

# 公钥密码学

公钥密码学使用两个不同的密钥进行加密和解密，因此也称为非对称密钥密码学。公钥密码学源于可逆数学函数，这使其从根本上区别于传统的对称密钥密码学。

并非对称密钥密码系统不如公钥密码系统有效，也非公钥密码系统优于对称密钥密码系统。任何密码系统的安全性仅取决于密钥长度和解密加密密文所需的计算工作量。

## 公钥密码学原理

在对称密码学中，确保机密性和真实性是关键问题。这种密码学类型使用共享密钥进行加密和解密内容。然而，在各方之间安全地共享此密钥存在风险。此外，对称密钥密码学在认证方面面临挑战。为解决这些问题并获得更广泛接受，引入了数字签名以确保消息由特定个人发送。相比之下，公钥密码学成功实现了机密性和真实性原则。

让我们分析公钥密码学涉及的过程。

最初，为确保数据完整性和来源认证，使用发送方的私钥加密内容，从而充当数字签名。此外，这确认了未经发送方私钥，加密内容无法被篡改。公钥密码学在数据完整性和来源方面实现了认证。

随后，使用发送方私钥加密的内容再使用接收方的公钥加密一次。最终的密文只能使用接收方专有的私钥解密，从而确保机密性。

然而，这种方法有一个缺点。公钥密码学依赖数学函数，这使其更复杂且计算密集度高。为同时实现机密性和真实性，公钥算法必须应用四次。

公钥密码学涉及多个步骤以确保双方间的安全通信：

1. 首先，每个用户必须生成一对密钥，一个用于加密消息，另一个用于解密。
2. 其次，每个用户必须公开其中一个密钥，同时保留另一个私有。

当用户想向特定接收者发送消息时，必须使用接收者的公钥加密消息，然后传输加密后的消息。

收到消息后，接收方可以使用其私钥对其进行解密以读取原始消息。通过遵循这些步骤，公钥密码学可以提供安全通信，同时确保只有预期的接收方才能读取消息。

## 公钥密码系统应用

公钥密码学在数字平台的安全通信方法和身份验证机制领域被认为至关重要。它有各种应用，其中一些显著的应用如下：

*   **解密/加密**：如果应用程序的目标是对消息进行编码和解码，则发送方必须使用预期接收方的公钥对消息进行编码，而接收方可以使用其自己的私钥对消息进行解码。
*   **认证**：它可以证明消息或用户是否合法。认证表示用户就是他们声称的那个人。可用性描述资源可由授权方访问，例如拒绝服务攻击，这是国家信息的敏感事项，属于针对可用性的攻击。
*   **数字签名**：当应用程序的主要目标是确认发送方的真实性时，可以使用数字签名。这涉及使用发送方的私钥对消息进行加密或签名。由于只有发送方能访问其私钥，这向所有相关方保证该消息确实由该特定个人发送。
*   **密钥生成**：每个用户生成两个密钥，包括公钥和私钥。私钥由用户保管，公钥在网络中自由可访问。
*   **验证**：签名通过相关用户的公钥进行验证。

## RSA

RSA 以其创建者 Rivest、Shamir 和 Adleman 的名字命名。它是一种非对称加密算法，便于生成公钥和私钥。RSA 实现密钥交易，其中交易涉及的每一方都被分配自己的一组公钥和私钥。随后，生成一个对称密钥，并使用公钥/私钥对安全地传输该密钥。非对称加密虽然通常比对称加密慢且可扩展性较差，但常用于安全地交换对称密钥。

RSA 使用一种基于分组密码概念的非对称加密算法，该概念在接收方一侧将明文转换为密文，反之亦然。如果使用用户 A 的公钥进行加密，则必须使用同一用户的私钥进行解密。

要实现 RSA 加密算法，需采取以下步骤：

1. 首先，选择两个素数 `X` 和 `Y`。这些素数必须足够大以确保安全性。
2. 计算两个素数的乘积，记为 `N = X * Y`。该乘积构成了加密算法的基础。
3. 接下来，选择一个公钥 `E`。它不能是 `(X-1)` 和 `(Y-1)` 的因数。
4. 选择一个私钥 `D`，使得等式 `(D * E) mod (X-1) * (Y-1) = 1` 成立。
5. 对于加密，密文 `CT` 计算为 `CT = (plaintext)^E mod N`。生成的 `CT` 随后发送给接收方。
6. 最后，对于解密，明文 `PT` 计算为 `PT = (ciphertext)^D mod N`。

这些步骤构成了 RSA 加密算法的基础，由于其在确保机密性和真实性方面的有效性，该算法广泛用于安全通信系统。

> **注意**：在 RSA 算法中，选择和生成公钥和私钥是一项关键任务。

## El Gamal 密码算法

这是一种公钥密码算法。该密码系统基于在循环群中寻找离散对数的困难性；即，即使我们知道 `ga` 和 `gk`，计算 `gak` 也极其困难。

*   首先选择两个大素数 `P` 和 `Q`，其中 `P` 为公钥，`Q` 为私钥。
*   选择第二个加密密钥为 `E1`。
*   计算第三个加密密钥 `E2`，使得 `E2 = E^Q mod P`，用于 El Gamal 密钥加密。
*   选择一个随机数 `R`。
*   计算密文为 `CT = E1^R mod P`。
*   计算第二个密文为 `CT2 = (PT * E2^R) mod P`，用于 El Gamal 密钥解密。最后，计算明文为 `PT = (CT2 * (CT^Q)^-1) mod P`。

# 椭圆曲线密码学

椭圆曲线密码学 (ECC) 是一类现代公钥加密系统，利用有限域上椭圆曲线的代数结构和椭圆曲线离散对数问题 (ECDLP) 的复杂性。ECC 提供了非对称密码系统的所有基本功能，包括加密、数字签名和密钥交换。它被视为 RSA 密码系统的天然继任者，这归功于其使用更小的密钥和签名，在提供与 RSA 相同安全级别的同时，实现了更快的密钥生成、密钥协商和签名处理速度。请参阅图 1.8，了解 ECC 的工作原理。

椭圆曲线被用于创建加密方案。它们定义在特定域上，是不连续曲线，意味着它们由有限个点组成。椭圆曲线密码学在传输和接收交易时构成了去中心化信任的基础。事实上，它被用于生成交易签名，这类似于物理签名，可以证明用户有权参与交易。在没有中央机构认证交易的去中心化系统中，广播到网络的每笔交易都必须拥有有效签名。这些签名必须能够验证交易是由特定用户发起的。这是通过非对称加密实现的，用户拥有一个或多个公钥/私钥对。签名方案包含一个问题，只有拥有公钥和私钥的用户才能计算该问题，但任何拥有公钥的其他用户都可以将其验证为真实签名。

一个例子是基于椭圆曲线的签名方案，它使用户能够证明他们拥有交易中声称的资金。这允许在无需中央机构的情况下发送和接收交易。选择椭圆曲线而非其他签名方案（如 RSA）是因为其密钥尺寸更小，有助于减少网络上存储的信息量。

## 哈希函数

哈希函数是一种数学算法，它接收可变数量的字符（称为消息），并将其转换为具有固定数量字符的字符串，称为哈希值或哈希。哈希算法是单向函数，意味着它们在一个方向上易于执行，但不可能逆向。哈希对于确保数据完整性和检测任何篡改非常有价值，因为消息的微小变化都会产生完全不同的哈希。哈希函数是现代密码学的基础工具，用于信息安全以验证交易、消息和数字签名。它们在区块链和分布式账本技术中有各种应用，包括链接区块和创建压缩数据结构。图 1.9 说明了哈希运行所涉及的顺序阶段。

# 哈希函数与分布式系统基础

鉴于分布式账本上交易的大量数据，有必要使用压缩数据结构（如默克尔树）来存储区块内的信息。这减少了在网络上运行节点所需的存储空间。

哈希函数也用于工作量证明算法中，这是网络上的节点就交易状态达成共识的机制。哈希函数接收一个输入（或对象），并生成一个固定长度的输出，称为摘要。无论输入的大小如何，输出始终保持相同的大小。此外，使用相同机制进行哈希时，相同的输入将始终产生相同的摘要。哈希函数还具有抗碰撞性，意味着两个不同输入的摘要之间没有可辨别的规律。

## 哈希算法的内部工作原理

哈希函数通常通过首先将输入数据划分为预定大小的数据块，然后利用算法计算出一个固定长度的哈希值来工作。数据块的大小可能因所采用的特定算法而异，如果块太小则可能应用填充。无论算法如何，生成的哈希值始终是固定长度的，并且该函数会迭代地应用于每个数据块。

另一方面，加密涉及对数据进行打乱以创建编码消息，只有持有相应密码的人才能对其进行解扰和解码。与哈希不同，加密是可逆的，旨在稍后由授权方解密。相比之下，哈希使用一种将任意大小的数据转换为固定长度哈希的公式，使其在计算上难以逆向。虽然加密主要用于保护传输中的数据，但哈希用于验证文件或数据的真实性，并检测其是否被篡改。

从本质上讲，加密类似于将数据放入保险箱，只有收件人知道组合密码才能打开。然而，哈希更像是一个防篡改封条，它提供保证，证明数据未被篡改或更改。

## 常见加密货币哈希函数

比特币采用的 `SHA-256` 算法属于安全哈希算法（`SHA`）家族。由美国国家安全局（`NSA`）开发，`SHA` 家族包含多种算法，如 `SHA-1`、`SHA-2`（包含 `SHA-224`、`SHA-256`、`SHA-384` 和 `SHA-512`）以及 `SHA-3`（成员包括 `SHA3-224`、`SHA3-256`、`SHA3-384` 和 `SHA3-512`）。

`SHA-256` 是一种广泛使用且高度安全的哈希算法。它被认为是 `SHA` 家族中最稳健、最可靠的加密技术之一。

其他常见的哈希算法包括消息摘要（`MD`）算法，包含 `MD2`、`MD4`、`MD5` 和 `MD6`。`MD5` 曾是一种广泛使用的算法，但因哈希碰撞已被视为不安全。Windows NT 哈希，也称为 Unicode 哈希或 `NTLM`，是 Windows 系统常用的另一种流行哈希算法。其他著名的哈希算法包括 RACE 完整性原语评估消息摘要（`RIPEMD`）、Whirlpool 和 `RSA`。

一般来说，最常用的哈希算法的哈希长度范围在 160 到 512 位之间。`SHA-256` 算法以其高安全性和可靠性著称，使其成为许多密码学应用的热门选择。

# 数字签名

数字签名是一种常用的数学过程，用于确认消息（如电子邮件、信用卡交易或数字文档）的真实性和完整性。这些数字签名会生成一个专属于个人或实体的独一无二的数字指纹，用于识别用户并保护数字消息或文档中的信息。在电子邮件的语境下，电子邮件内容本身会被整合进数字签名中。数字签名比其他类型的电子签名安全得多，并增强了在线交互的透明度，在客户、业务合作伙伴和供应商之间建立信任。

数字签名通过证明数字消息或文档自签名以来未被修改（无论是有意还是无意）来发挥作用。数字签名通过生成消息或文档的唯一哈希值，并使用发送方的私钥对其进行加密来实现这一点。生成的哈希值对于该消息或文档是唯一的，更改其中任何部分都会完全改变哈希值。

完成后，消息或数字文档被数字签名并发送给接收方。接收方随后生成该消息或数字文档的自己的哈希值，并使用发送方的公钥解密发送方的哈希值（包含在原始消息中）。接收方将自己生成的哈希值与解密后的发送方哈希值进行比较，如果两者匹配，则表明消息或数字文档未被修改，且发送方身份得到验证。

# 分布式系统基础

分布式系统是一组协同工作以实现共同目标的独立计算机的集合。这些系统可以是局域网（`LAN`）中的小型计算机网络，也可以是跨越全球的大型网络。分布式系统的基本概念是允许多台计算机协同工作，就像它们是一台计算机一样。

分布式系统的关键组件之一是分布式算法的使用。这些算法旨在以高效且容错的方式协调多台计算机的动作。分布式算法的一个例子是分布式排序算法。该算法允许多台计算机并行对大型数据集进行排序，然后以确保最终结果正确排序的方式合并结果。分布式系统中的另一个重要概念是共识协议的使用。这些协议用于确保分布式系统中的所有计算机就系统状态达成一致。例如，分布式数据库可能会使用共识协议来确保系统中的所有计算机就数据库的内容达成一致。共识协议的一个例子是 Paxos 算法，它用于确保分布式系统中的所有计算机就一系列事件的顺序达成一致。

容错性是分布式系统的另一个重要方面。这指的是系统在一个或多个组件发生故障时仍能继续正常运行的能力。容错性通过使用冗余组件以及检测和从故障中恢复的机制来实现。例如，分布式存储系统可能会使用数据的多个副本，以确保即使一个或多个存储设备发生故障，数据仍然可用。

许多人熟悉的一个分布式系统例子是万维网。万维网是一个用于共享信息和资源的庞大互联计算机网络。当你访问一个网站时，你的计算机向 Web 服务器发送请求，后者再返回所请求的信息。这一过程通过使用分布式算法和协议成为可能，它们确保信息被发送到正确的计算机并正确传输。

分布式系统的另一个例子是分布式版本控制系统（`DVCS`）。这类系统用于管理软件项目的源代码。`DVCS` 允许多个开发者同时在同一代码库上工作，并确保他们的更改被正确合并。流行的 `DVCS` 示例包括 `Git` 和 `Mercurial`。

# 总结

分布式系统是一种强大的工具，允许多台计算机协同工作以实现共同目标。这些系统使用分布式算法和共识协议来确保计算机的动作协调一致，并利用容错机制确保即使组件发生故障，系统仍能继续正确运行。分布式系统的例子包括万维网和分布式版本控制系统。随着云计算和物联网等技术日益普及，分布式系统未来将变得更加重要。

## 分布式系统核心术语速览

### 分布式算法

分布式算法是一种用于相互连接的系统或节点网络中的算法类型，不同的处理器同时处理算法的不同部分。这使得并行处理和处理器间的通信成为可能，以确保软件正常运行。普通算法与分布式算法的区别在于，后者设计为在独立处理器上运行。每个处理器并发执行整体算法的不同部分，并相互共享结果。然而，分布式算法也面临挑战。例如，如果一个处理器发生故障，可能会破坏算法的对应部分。此外，处理器间的通信问题可能阻碍分布式算法的进展。程序员通常研究分布式算法以应对这些挑战，确保算法即使在存在技术错误时也能成功执行。

### 共识协议

共识协议本质上是网络运行的规则。网络中的对等节点受网络共识协议管辖，因为它定义了网络如何实现去中心化。区块链或分布式账本是一个分布在许多不同计算机上的网络。这些计算机协同工作，确保网络上的所有交易正确准确。这正是区块链的特殊之处，因为它不依赖单一中央权威进行控制。

由于任何人都可以向区块链添加信息，因此必须制定规则，确保所有人就添加什么信息、忽略什么信息达成一致。这些规则称为共识协议。它们验证交易并帮助维护网络安全。

通常，共识协议在区块链首次创建前就已确定。然而，某些网络（如以太坊）可以在运行过程中更改其共识协议，这意味着它们可以随时间适应和改进。

区块链网络核心的共识机制提供了一种特定方法来验证交易是否有效。它提供了一种审查和确认哪些数据应添加到区块链账本的手段。由于区块链网络通常缺乏确定正确性的中央权威，网络中的节点必须根据预定义的规则或协议共同就网络状态达成一致。
