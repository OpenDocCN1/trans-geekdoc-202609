### 哈希算法

在上一节中，您了解到公钥密码系统结合消息摘要可提供数字签名功能。消息摘要是由哈希算法生成的消息内容摘要（类似于文件校验和）。从理想哈希函数推导出原始消息极其困难，甚至不可能，且两条不同消息产生相同哈希值的可能性极低。哈希函数为两个不同输入产生相同值的情况称为`碰撞`，碰撞的存在通常会导致哈希算法被弃用。

### 对称密码学

您已了解对称密钥密码学、非对称密钥密码学和哈希函数的基本概念。在以下章节中，我们将深入探讨几种常见的对称密码系统：数据加密标准（`DES`）、三重 DES（`3DES`）和高级加密标准（`AES`）。

#### 数据加密标准

美国政府于 1977 年发布了数据加密标准，作为所有政府通信的提议标准密码系统。由于算法存在缺陷，密码学家和联邦政府不再认为 `DES` 安全。人们普遍认为情报机构会常规性地解密 `DES` 加密的信息。`DES` 于 2001 年 12 月被高级加密标准取代。理解 `DES` 仍然很重要，因为它是三重 DES（`3DES`）的构建基块，后者是下一节将讨论的一种强加密算法。

`DES` 是一种 64 位分组密码，具有五种操作模式：电子密码本（`ECB`）模式、密码分组链接（`CBC`）模式、密码反馈（`CFB`）模式、输出反馈（`OFB`）模式和计数器（`CTR`）模式。这些模式将在以下章节中解释。所有 `DES` 模式一次对 64 位明文进行操作，生成 64 位密文分组。`DES` 使用的密钥长度为 56 位。

`DES` 使用一长串异或（`XOR`）操作生成密文。每次加密/解密操作重复此过程 16 次。每次重复通常称为一`轮`加密，这解释了 `DES` 执行 16 轮加密的说法。

##### 电子密码本模式

电子密码本（`ECB`）模式是最容易理解但安全性最低的模式。算法每次处理一个 64 位分组时，只是使用选定的密钥加密该分组。这意味着如果算法多次遇到相同的分组，会产生相同的加密分组。如果窃听者监听通信，他们可以简单地建立所有可能加密值的“密码本”。收集足够数量的分组后，即可使用密码分析技术破译部分分组并破解加密方案。

这种漏洞使得 `ECB` 模式除极短传输外均不实用。在日常使用中，`ECB` 仅用于交换少量数据，例如用于启动其他 `DES` 模式的密钥和参数，以及数据库中的单元格。

##### 密码分组链接模式

###### 密码分组链接（CBC）模式

在密码分组链接（`CBC`）模式中，每个未加密文本分组在使用 `DES` 算法加密之前，都会与紧邻其前面的密文分组进行组合。解密过程只是简单地解密密文并反向执行加密操作。

`CBC` 使用 `initialization vector`（初始化向量，`IV`），这是一个随机选择的值，用于启动加密过程。`CBC` 获取 `IV` 并使用一种称为异或（`XOR`）的操作将其与消息的第一个分组相结合，每次执行该操作都会产生唯一的输出。`IV` 必须发送给接收者，也许是将 `IV` 以明文形式附加在完成的密文前面，或者使用用于消息的同一密钥通过 `ECB` 模式加密来保护它。使用 `CBC` 模式时一个重要的考虑因素是错误会传播——如果传输过程中一个分组损坏，将无法解密该分组和下一个分组。

##### 密文反馈模式

密文反馈（`CFB`）模式是 `CBC` 的流密码版本。换句话说，`CFB` 针对实时产生的数据进行操作。然而，它不是将消息分成分组，而是使用与分组大小相同的内存缓冲区。当缓冲区变满时，它会被加密并发送给接收者。然后系统等待下一个缓冲区随着新数据的生成而填满，随后依次被加密并传输。除了从预存数据变为实时数据外，`CFB` 的操作方式与 `CBC` 相同。

##### 输出反馈模式

在输出反馈（`OFB`）模式中，`DES` 的操作方式与 `CFB` 模式几乎相同。然而，`DES` 不再是将前一个密文分组的加密版本进行异或，而是将明文与种子值进行异或。对于第一个加密分组，使用初始化向量来创建种子值。未来的种子值通过在前一个种子值上运行 `DES` 算法来得出。`OFB` 模式的主要优势在于没有链接功能，且传输错误不会传播以影响未来分组的解密。

##### 计数器模式

在计数器（`CTR`）模式下运行的 `DES` 使用类似于 `CFB` 和 `OFB` 模式的流密码。然而，它不是根据前一个种子值的结果为每次加密/解密操作创建种子值，而是使用一个简单的计数器，该计数器在每次操作时递增。与 `OFB` 模式一样，错误不会在 `CTR` 模式中传播。

#### 三重 DES

如前几节所述，面对现代密码分析技术和超级计算能力，数据加密标准的 56 位密钥不再被认为是足够的。然而，`DES` 的一个改进版本，三重 DES（`3DES`），使用相同的算法产生更安全的加密。

`3DES` 有四个版本。第一个版本只是使用三个不同的密钥：`K[1]`、`K[2]` 和 `K[3]` 对明文加密三次。它被称为 DES-EEE3 模式（`E` 表示有三次加密操作，而数字 3 表示使用了三个不同的密钥）。DES-EEE3 可以用以下符号表示，其中 `E(K,P)` 表示使用密钥 `K` 对明文 `P` 进行加密：

```
E(K1,E(K2,E(K3,P)))
```

DES-EEE3 具有 168 位的有效密钥长度。

第二个变体（DES-EDE3）也使用三个密钥，但用解密操作替换了第二次加密操作。

```
E(K1,D(K2,E(K3,P)))
```

第三个版本的 `3DES`（DES-EEE2）仅使用两个密钥，`K[1]` 和 `K[2]`，如下所示：

```
E(K1,E(K2,E(K1,P)))
```

第四个变体（DES-EDE2）也使用两个密钥，但在中间使用解密操作，由 `D(K,C)` 函数表示，其中 `K` 是解密密钥，`C` 是待解密的密文。

```
E(K1,D(K2,E(K1,P)))
```

第三和第四个变体都具有 112 位的有效密钥长度。

多年来开发这四种 `3DES` 变体是因为几位密码学家提出理论认为某个变体比其他变体更安全。然而，目前的观点是所有模式同样安全。

#### 高级加密标准

2000 年 10 月，美国国家标准与技术研究院宣布 Rijndael（发音为“rhine-doll”）分组密码被选为 `DES` 的替代品。2001 年 11 月，`NIST` 发布了 FIPS 197，强制美国政府使用 AES/Rijndael 对所有敏感但非机密的数据进行加密。

`AES` 密码允许使用三种密钥强度：128 位、192 位和 256 位。`AES` 仅允许处理 128 位分组，但 `Rijndael` 超出了这一规范，允许密码学家使用等于密钥长度的分组大小。加密轮数取决于所选的密钥长度：

*   128 位密钥需要 10 轮加密。
*   192 位密钥需要 12 轮加密。
*   256 位密钥需要 14 轮加密。

#### 对称密钥管理

由于加密密钥包含密码系统安全所必需的信息，密码系统用户和管理员有责任采取特别措施来保护密钥材料的安全。这些安全措施统称为 `key management practices`（密钥管理实践）。它们包括围绕秘密密钥的创建、分发、存储、销毁、恢复和托管的保障措施。

##### 对称密钥的创建与分发

如前所述，`key exchange`（密钥交换）是对称加密算法的主要基础问题之一。`Key exchange` 是安全分发运行算法所需的秘密密钥。安全交换秘密密钥的三种主要方法是离线分发、公钥加密和 Diffie–Hellman 密钥交换算法。

###### 离线分发

技术上最简单的方法涉及密钥材料的物理交换。一方向另一方提供一张纸或一块存储介质，其中包含秘密密钥。在许多硬件加密设备中，这种密钥材料以类似于实际钥匙的电子设备形式出现，插入加密设备即可使用。然而，每种离线密钥分发方法都有其固有的缺陷。如果密钥材料通过邮件发送，可能会被拦截。电话可能被窃听。包含密钥的纸张可能被无意丢弃在垃圾桶中或丢失。

###### 公钥加密

许多通信者希望获得秘密密钥加密的速度优势，而不想承受密钥分发的麻烦。因此，许多人使用公钥加密来建立初始通信链路。一旦链路成功建立且双方对彼此的身份感到满意，他们就会通过安全的公钥链路交换一个秘密密钥。然后他们将通信从公钥算法切换到秘密密钥算法，享受更快的处理速度。一般来说，秘密密钥加密比公钥加密快数千倍。

###### Diffie–Hellman

在某些情况下，公钥加密和离线分发都不足够。双方可能需要相互通信，但他们没有物理手段交换密钥材料，也没有公钥基础设施来促进秘密密钥的交换。在这种情况下，像 Diffie–Hellman 算法这样的密钥交换算法被证明是极其有用的机制。

##### 对称密钥的存储与销毁

使用对称密钥密码学的另一个主要挑战是，密码系统中使用的所有密钥都必须保持安全。这包括遵循围绕加密密钥存储的最佳实践：

### 密钥管理最佳实践

*   切勿将加密密钥存储在存放加密数据的同一系统上。这只会让攻击者更容易得手！
*   对于敏感密钥，可考虑将密钥的一半提供给一名人员，另一半提供给另一名人员。随后，他们必须协作才能重建完整的密钥。这被称为 `split knowledge`（分散知识）原则（本章前面已讨论过）。

当知晓密钥的用户离开组织，或不再被允许访问受该密钥保护的资料时，必须更换密钥，并使用新密钥对所有加密资料重新加密。在对称密码系统中，销毁密钥以移除用户的困难，是组织转向非对称算法的主要原因之一。

###### 密钥托管与恢复

密码学是一种强大的工具。像大多数工具一样，它可用于多种有益目的，但也可能被用于恶意意图。为了控制密码技术的爆发式增长，世界各国政府都提出了实施密钥托管系统的想法。这些系统允许政府在有限情况下（如法院命令），从中央存储设施获取特定通信所用的加密密钥。

过去十年间，主要提出了两种密钥托管方法。

*   **公平密码系统** — 在此托管方法中，通信中使用的密钥被分成两份或多份，每份交给一个独立的第三方。每一份单独来看毫无用处，但可重组以获得密钥。当政府获得访问特定密钥的法律授权时，它向各第三方提供法院命令的证据，然后重组密钥。
*   **托管加密标准** — 此托管方法为政府提供了一种解密密文的技术手段。该标准是 Skipjack 算法的基础。

政府监管机构极不可能克服在广泛范围内实施密钥托管所必需的法律和隐私障碍。技术当然是可用的，但公众极不可能接受其所助长的潜在政府侵入性。

### 非对称密码学

回顾本章前面的内容，`public key cryptosystems`（公钥密码系统）依赖于分配给每个密码系统用户的一对密钥。每个用户同时维护一个公钥和一个私钥。顾名思义，公钥密码系统用户将其公钥免费提供给任何想要通信的人。第三方仅持有公钥并不会给密码系统带来任何弱点。另一方面，私钥仅供密钥所有者个人使用。它绝不与任何其他密码系统用户共享。

公钥密码系统用户之间的正常通信非常直接，如图 7.8 所示。请注意，该过程不要求共享私钥。发送方使用接收方的公钥加密明文消息（`P`）以生成密文消息（`C`）。当接收方打开密文消息时，他们使用自己的私钥对其解密，以重建原始明文消息。

一旦发送方使用接收方的公钥加密消息，在不知道接收方私钥（用于生成消息的公私钥对的另一半）的情况下，任何用户（包括发送方）都无法解密该消息。这就是公钥密码学的妙处——公钥可通过不安全通信自由共享，随后用于在互不相识的用户之间创建安全通信通道。

您在上一章还了解到，公钥密码学涉及更高程度的计算复杂性。公钥系统中使用的密钥必须比私钥系统中的密钥更长，才能产生同等强度的密码系统。

#### RSA

最著名的公钥密码系统以其创建者的名字命名。1977 年，Ronald Rivest、Adi Shamir 和 Leonard Adleman 提出了 `RSA public key algorithm`（RSA 公钥算法），该算法至今仍是全球标准。他们为该算法申请了专利，并成立了名为 RSA Security 的商业企业，以开发其安全技术的主流实现。如今，RSA 算法已发布到公共领域，并广泛用于安全通信。

RSA 算法依赖于分解大素数所固有的计算难度。密码系统的每个用户使用该算法生成一对公钥和私钥。密钥生成的具体细节超出了考试范围，但您应记住，它基于分解大素数的复杂性。

#### 椭圆曲线

1985 年，两位数学家——华盛顿大学的 Neal Koblitz 和 IBM 的 Victor Miller——独立提出将 `elliptic curve cryptography`（ECC，椭圆曲线密码学）理论应用于开发安全密码系统。

任何椭圆曲线均可由以下方程定义：

```
y2 = x3 + ax + b
```

在该方程中，`x`、`y`、`a` 和 `b` 均为实数。每条椭圆曲线都有一个对应的 `elliptic curve group`（椭圆曲线群），由椭圆曲线上的点以及位于无穷远处的点 `O` 组成。同一椭圆曲线群内的两个点（`P` 和 `Q`）可通过椭圆曲线加法算法相加。该运算表示为：

```
P + Q
```

通过假设 `Q` 是 `P` 的倍数，即以下含义，可将此问题扩展为乘法运算：

```
Q = xP
```

计算机科学家和数学家认为，即使已知 `P` 和 `Q`，找到 `x` 也极其困难。这个被称为 `elliptic curve discrete logarithm problem`（椭圆曲线离散对数问题）的难题，构成了椭圆曲线密码学的基础。人们普遍认为，该问题比 RSA 密码系统所基于的素因子分解问题，以及 Diffie-Hellman 所利用的标准离散对数问题，都更难解决。

### 哈希函数

本章稍后您将了解密码系统如何实现数字签名，以证明消息源自密码系统的特定用户，并确保消息在双方传输过程中未被篡改。在完全理解该概念之前，我们必须先解释 `hash functions`（哈希函数）的概念。我们将探讨哈希函数的基础知识，并介绍现代数字签名算法中使用的几种常见哈希函数。

哈希函数的目的非常简单——它们接收一条可能很长的消息，并根据消息内容生成一个唯一的输出值。该值通常称为 `message digest`（消息摘要）。消息摘要可由消息发送方生成，并随完整消息一起传输给接收方，主要有两个原因。

首先，接收方可使用相同的哈希函数，从完整消息中重新计算消息摘要。然后，他们可将计算出的消息摘要与传输的摘要进行比较，以确保发送方发送的消息与接收方收到的消息完全一致。如果消息摘要不匹配，则意味着消息在传输过程中以某种方式被修改了。重要的是要注意，消息必须 `exactly`（完全）相同，摘要才会匹配。如果消息在间距、标点或内容上即使有细微差别，消息摘要值也会完全不同。无法通过比较摘要来判断两条消息的差异程度。即使是细微的差别，也会生成完全不同的摘要值。

其次，消息摘要可用于实现数字签名算法。本章后面的“数字签名”部分将介绍这一概念。

加密哈希函数有五个基本要求：

*   它们接受任意长度的输入。
*   无论输入长度如何，它们都产生固定长度的输出。
*   哈希值相对容易计算。
*   哈希函数是单向的（意味着在提供了输出的情况下，极难确定输入）。
*   哈希函数是 `collision` 免疫的（意味着极难找到产生相同哈希值的两条消息）。

#### SHA

安全哈希算法（`SHA`）及其后继者 `SHA-1`、`SHA-2` 和 `SHA-3`，是由美国国家标准与技术研究院（`NIST`）推广的政府标准哈希函数，并在一份官方政府出版物——安全哈希标准（`SHS`）中规定，该标准也称为联邦信息处理标准（`FIPS`）180。

`SHA-1` 接受几乎任意长度的输入（实际上，该算法的上限约为 2,097,152 TB），并生成 160 位的消息摘要。`SHA-1` 算法以 512 位分块处理消息。因此，如果消息长度不是 512 的倍数，`SHA` 算法会用额外数据填充消息，直到长度达到下一个 512 的倍数。

密码分析攻击表明 `SHA-1` 算法存在弱点。这促使了 `SHA-2` 的诞生，后者有四个变体：

*   `SHA-256` 使用 512 位分块大小生成 256 位消息摘要。
*   `SHA-224` 使用 `SHA-256` 哈希的截断版本，利用 512 位分块大小生成 224 位消息摘要。
*   `SHA-512` 使用 1,024 位分块大小生成 512 位消息摘要。
*   `SHA-384` 使用 `SHA-512` 哈希的截断版本，利用 1,024 位分块大小生成 384 位摘要。

密码学界普遍认为 `SHA-2` 算法是安全的，但它们理论上存在与 `SHA-1` 算法相同的弱点。2015 年，联邦政府宣布发布 `Keccak` 算法作为 `SHA-3` 标准。`SHA-3` 套件的开发旨在作为 `SHA-2` 哈希函数的直接替代品，使用更安全的算法提供相同的变体和哈希长度。

#### MD5

1991 年，Ron Rivest 发布了其消息摘要算法的下一个版本，称为 `MD5`。它同样以 512 位分块处理消息，但使用四轮不同的计算来生成与早期 `MD2` 和 `MD4` 算法长度相同的摘要（128 位）。

`MD5` 实现了显著降低消息摘要生成速度的安全特性。不幸的是，最近的密码分析攻击表明 `MD5` 协议易受碰撞攻击，这使其无法用于确保消息完整性。

### 数字签名

一旦选择了一个密码学上可靠的哈希算法，就可以用它来实现 `digital signature` 系统。数字签名基础设施有两个不同的目标：

*   经数字签名的消息向接收者保证该消息确实来自声称的发送者。它们强制执行不可否认性（即防止发送者事后声称消息是伪造的）。
*   经数字签名的消息向接收者保证该消息在发送者和接收者之间传输时未被篡改。这既防止恶意篡改（第三方改变消息含义），也防止无意篡改（因通信过程中的故障，如电气干扰）。

数字签名算法依赖于本章已介绍的两个主要概念的结合——公钥密码学和哈希函数。
