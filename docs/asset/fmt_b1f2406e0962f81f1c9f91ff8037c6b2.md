## 选择合适的 ML 服务

Google Cloud ML 服务和解决方案根据易用性和实现难度分为三层，如图 5.1 所示。

![图 5.1：Google AI/ML 栈](img/c05f001.png)

### 图 5.1：Google AI/ML 栈

顶层是 AI 解决方案，例如 `Document AI`、`Contact Center AI` 和 `Enterprise Translation Hub`。这些是托管的软件即服务 (SaaS) 产品，无需代码即可更轻松地实现和管理。AI 解决方案构建在中间层的 `Vertex AI` 服务之上。

中间层由 `Vertex AI` 组成，包含以下内容：

*   **Vertex AI 预训练 API**，适用于视觉、语言、对话和结构化数据中最常见的用例。这些 API 是无服务器且可扩展的。
*   **Vertex AI AutoML**，用于利用你自己的数据丰富 Vertex AI API 用例，以创建针对你业务用例的特定模型。例如，你可以通过提供一些公司徽标的示例来训练 `AutoML Vision` 模型，以检测道路上带有你公司徽标的卡车图像。
*   **Vertex AI Workbench**，这是整个数据科学工作流的开发环境。这可以涵盖从数据标注、训练、调优、部署到监控你自己的自定义模型，这些模型不适合使用 AI 服务和 AutoML 的任何用例。一个例子是构建文本摘要模型。

底层由基础设施组成，例如计算实例和容器（`Google Kubernetes Engine`），可选择 TPU、GPU 和存储。你需要自行管理基础设施以实现可扩展性和可靠性。

Google Cloud 提供 `BigQuery ML` 和 `Vertex AI AutoML` 来帮助自动创建针对某些常见问题领域的自定义模型。`Vertex AI` 提供的其余工具帮助你为任何问题领域构建完全自定义的模型。我们将在第 14 章“BigQuery ML”中详细介绍 `BigQuery ML`。表 5.2 讨论了何时使用 AutoML 与 BigQuery ML 与 Vertex AI 自定义模型。

## 数据收集与数据管理

Google Cloud 提供了多种数据存储，以满足您对特征在延迟、负载、吞吐量和规模方面的组合要求：

*   Google Cloud Storage
*   BigQuery
*   `Vertex AI's datasets`，用于管理训练集和标注集
*   Vertex AI Feature Store
*   NoSQL 数据存储

### Google Cloud Storage (GCS)

Google Cloud Storage 是一项在 Google Cloud 中存储对象的服务。您可以使用 GCS 存储图像、视频、音频和非结构化数据。您可以将这些单独的数据类型合并为大小至少为 100 MB 的大文件（https://cloud.google.com/architecture/ml-on-gcp-best-practices#store-image-video-audio-and-unstructured-data-on-cloud-storage），并分成 100 到 10,000 个分片，以提高读写吞吐量。如果您使用 TensorFlow，这适用于分片 TFRecord 文件；如果您使用任何其他框架，则适用于 Avro 文件。

### BigQuery

最佳实践是将表格数据存储在 BigQuery 中。对于训练数据，最好将数据作为表存储，而不是视图，以获得更好的速度。可以通过以下方式使用 BigQuery 功能：

*   Google Cloud 控制台，搜索 BigQuery
*   `bq` 命令行工具
*   BigQuery REST API
*   使用 BigQuery Magic 或 BigQuery Python 客户端的 Vertex AI Jupyter Notebook。

我们将在第 14 章介绍 BigQuery ML。

表 5.3 列出了可让您更轻松地使用 API 的 Google Cloud 工具。

### Vertex AI 托管数据集

Google Cloud 建议使用 Vertex AI 托管数据集来训练自定义模型，而不是编写训练应用以直接从 Google Cloud Storage 或本地存储等存储系统中摄取训练数据。主要支持四种数据格式：图像、视频、表格（CSV、BigQuery 表）和文本。

使用托管存储的优势如下：

*   在中心位置管理数据集。
*   使用 Vertex AI 数据标注，对视频、文本和图像等未标注的非结构化数据进行集成数据标注。
*   易于追踪模型谱系，以便进行治理和迭代开发。
*   使用相同的数据集训练 AutoML 和自定义模型，以对比模型性能。
*   生成数据统计信息和可视化结果。
*   自动将数据拆分为训练集、测试集和验证集。

当您拥有未标注的非结构化数据时，可以使用 Vertex AI 数据标注服务，对 Google Cloud Storage 或 Vertex AI 托管数据集中的数据进行标注。这只是一项标注数据的服务，并不存储数据。您可以使用第三方众包标注人员或您自己的标注人员来标注数据。

### Vertex AI Feature Store

Vertex AI Feature Store 是一个全代管的中心化存储库，用于组织、存储和服务 ML 特征。您可以独立使用 Vertex AI Feature Store，也可以将其作为 Vertex AI 工作流的一部分使用。例如，您可以从 Vertex AI Feature Store 获取数据，在 Vertex AI 中训练自定义模型或 AutoML 模型。当您使用结构化数据训练模型时，用户可以定义特征，然后从各种数据源摄取（导入）特征值。任何获授权的用户都可以搜索并从 Feature Store 检索值。例如，您可以查找特征，然后执行批量导出以获取用于创建 ML 模型的训练数据，或者如果特征不存在，则创建一个新特征。您还可以实时检索特征值，以执行快速在线预测。

使用 Feature Store 的好处是，您无需计算特征值并将它们保存在各种位置，例如 BigQuery 中的表和 Google Cloud Storage 中的文件。此外，由于特征是在中心化的方式下创建的，Feature Store 可以帮助检测漂移并缓解数据倾斜。

### NoSQL 数据存储

对于预测期间的静态特征查找，BigQuery 等分析型数据存储并非为低延迟的单例读取操作而设计，此类操作的结果是包含许多列的单行数据。此类查询的示例是“为特定客户 ID 从多个表中选择 100 列”。因此，静态参考特征会被收集、准备并存储在针对单例查找操作进行了优化的 NoSQL 数据库中。

## 自动化与编排

### 机器学习工作流与流水线编排

机器学习工作流定义了在机器学习项目期间实施的各个阶段。典型阶段包括数据收集、数据预处理、构建数据集、模型训练与优化、评估以及部署到生产环境。要在生产环境中集成 ML 系统，您需要编排 ML 流水线中的各个步骤。此外，您还需要实现流水线的自动化执行，以便对模型进行持续训练。

ML 流水线用于连接 ML 解决方案的各个步骤。`Kubeflow` 是一个机器学习工具包，它提供了一个名为 `Kubeflow Pipelines` 的流水线解决方案，构建在 `Kubernetes` 之上。Google 推出了 `Vertex AI Pipelines`，因为维护 `Kubernetes` 可能具有挑战性且耗时。它是一个用于运行流水线的无服务器产品，因此您的机器学习团队可以专注于他们的本职工作：ML。

#### 使用 Vertex AI Pipelines 编排 ML 工作流

`Vertex AI Pipelines` 是一项托管服务，它通过以无服务器方式编排您的 ML 工作流并使用 `Vertex ML Metadata` 存储工作流的工件，帮助您自动化、监控和治理 ML 系统。通过将 ML 工作流的工件存储在 `Vertex ML Metadata` 中，您可以分析工作流工件的血缘关系，例如用于创建模型的训练数据、超参数和代码。`Vertex AI Pipelines` 可以运行使用 `Kubeflow Pipelines SDK` v1.8.9 或更高版本或 `TensorFlow Extended` v0.30.0 或更高版本构建的流水线。

对于 `TensorFlow`，请使用 `TensorFlow Extended` 来定义您的流水线及每个步骤的操作，然后在 `Vertex AI` 的无服务器流水线系统上执行它。

对于所有其他框架，请将 `Kubeflow Pipelines` 与 `Vertex AI Pipelines` 结合使用。使用 `Vertex AI` 来启动平台并与其交互。

这会产生两个结果：

*   您可以使用流水线，而无论您选择哪种 ML 环境。
*   您只需要少量配置适度 CPU 和内存的节点，因为大部分工作将在托管服务中完成。

#### 使用 Kubeflow Pipelines 进行灵活的流水线构建

`Kubeflow` 是一个开源 `Kubernetes` 框架，用于开发和运行可移植的 ML 工作负载。`Kubeflow Pipelines` 是一项 `Kubeflow` 服务，可让您组合、编排和自动化 ML 系统。您可以选择在本地、本地部署或云环境（如 `Google Cloud` 或其他云平台）中部署 `Kubernetes` 工作负载。`Kubeflow Pipelines SDK` 推荐给大多数想要编写托管流水线的用户。`Kubeflow Pipelines` 灵活多变，让您可以使用简单的代码构建流水线，并提供 `Google Cloud Pipeline Components`，允许您在流水线中包含 `AutoML` 等 `Vertex AI` 功能。

`Kubeflow Pipelines` 通过执行所需的 `Google Cloud` 服务，让您能够编排和自动化生产级 ML 流水线。在图 5.2 中，`Cloud SQL` 作为 `Kubeflow Pipelines` 的 ML 元数据存储。

`Kubeflow Pipelines` 组件不仅限于在 `Google Cloud` 上执行 `TensorFlow Extended (TFX)` 相关服务。这些组件可以执行用于 `Spark` ML 作业的 `Dataproc`、`AutoML` 和其他计算工作负载。

#### 使用 TensorFlow Extended SDK 利用预构建组件处理常见步骤

`TensorFlow` 为 `Vertex AI` 工作流中的常见步骤（如数据摄取、数据验证和训练）提供预构建组件。`TFX` 提供了一系列框架、库和组件，用于在生产环境中定义、启动和监控机器学习模型。如果满足以下任一条件，建议使用 `TensorFlow Extended SDK`：

*   您已经在使用 `TensorFlow`。
*   您使用结构化数据和文本数据。
*   您处理大量数据。

我们在第 3 章“特征工程”中介绍了 `TFX` 流水线的 `Google Cloud` 实现。另请参阅此页面：

`https://neptune.ai/blog/deep-dive-into-ml-models-in-production-using-tfx-and-kubeflow`

#### 何时使用哪种流水线

`Vertex AI Pipelines` 可以运行使用 `Kubeflow Pipelines SDK` v1.8.9 或更高版本或 `TensorFlow Extended` v0.30.0 或更高版本构建的流水线。

如果您在处理 TB 级结构化数据或文本数据的 ML 工作流中使用 `TensorFlow`，我们建议您使用 `TFX` 构建流水线。默认情况下，`TFX` 会创建 ML 流水线的有向无环图 (DAG)。它在底层使用 `Apache Beam` 来管理和实现流水线，并且可以轻松地在 `Apache Spark`、`Google Cloud Dataflow` 和 `Apache Flink` 等分布式处理后端上执行。

虽然在 `Cloud Dataflow` 上运行 `Apache Beam` 的 `TFX` 很酷，但配置、监控和维护已定义的流水线和工作流却很困难。这催生了我们称为*编排器*的工具。

像 `Kubeflow` 这样的编排器使配置、操作、监控和维护 ML 流水线变得容易。它们大多附带易于理解的 GUI。您可以使用 `Kubeflow Pipelines` 来调度和编排 `TFX` 流水线。

对于其他用例，我们建议您使用 `Kubeflow Pipelines SDK` 构建流水线。

虽然您可以考虑其他编排器，如 `Cloud Composer`（请参阅 Apache `Airflow`），但 `Vertex AI Pipelines` 是更好的选择，因为它内置了对常见 ML 操作的支持，并跟踪特定于 ML 的元数据和血缘关系。血缘关系对于验证流水线在生产环境中是否正常运行尤为重要。

## 服务

在训练、评估和调优机器学习 (ML) 模型后，该模型将被部署到生产环境以进行预测。ML 模型可以通过两种方式提供预测：离线预测和在线预测。

### 离线或批量预测
