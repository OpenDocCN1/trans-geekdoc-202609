
作为一家中型公司的安全从业人员，你被要求确定一个文件服务器的`ALE`。你的组织安装了一个数据价值为`$25,000`的文件服务器。组织使用该服务器让远程办公室上传每日记录，以便在第二天早晨进行处理。目前，该服务器未完全打补丁，且没有安装杀病毒程序。你的研究表明，新文件服务器在一年内被感染的概率为`95%`。如果发生此类感染，你估计`75%`的数据可能会丢失。在没有杀病毒软件的情况下，恢复丢失的文件和恢复服务器可能需要长达四小时，并使支持团队离开其他工作。一家经批准的供应商提供以`$175`的价格出售所需软件的站点许可。

1. 检查暴露因子。该因子计算结果为`75%`。记住，暴露因子识别了由于威胁成功执行而受影响的资产价值百分比。

2. 确定`SLE`。公式如下：

```
SLE = AV × EF
```

由于已知资产价值为`$25,000`，暴露因子为`75%`，得出的`SLE`为`$18,750`。

3. 评估`ARO`。`ARO`是一个代表给定威胁预期发生频率的数值。它被定义为该事件预计在一年发生的次数。你的研究表明，一年内发生感染的概率为`95%`。

4. 计算`ALE`。`ALE`是由于特定威胁在一年内发生导致组织 IT 资产的年度预期财务损失。

```
ALE = SLE × ARO
```

或

```
$18,750 × 0.95 = $17,812
```

在现实世界中，风险计算严重依赖概率和期望。软件产品、精算表、行业信息和之前事件的历史可以提供帮助，但某些事件很难计算。风暴或其他自然现象并不容易归类为模式。此类事件可以被认为是随机的（`stochastic`）。随机事件基于随机行为，因为单个事件的发生是预测的，但衡量所有观测值的分布通常遵循可预测的模式。

定量风险管理在估计风险时面临挑战，因此你必须依赖定性方法的某些要素。

# 定性分析

完成风险评估的第二种方法是通过定性手段。定性评估基于场景的，并不尝试为风险分析的组件分配美元价值。该过程的一部分要求团队进行极端场景规划并查看最坏的情况。例如，如果飓风袭击了位于加尔斯顿岛（`Galveston Island`）的冲板制造厂会有多糟糕？这就像在玩一个“如果……？”的游戏。

定性评估通过等级或范围（如低、中、高）对威胁的潜力和资产的敏感性进行分类。你可以在`NIST 800-53`中看到此类示例。该文档通过等级或范围（如低、中、高）对威胁的潜力和资产的敏感性进行分类。……（此处省略重复性文本，已遵循原文逻辑）

这一过程的结果是优先级的排序以及数据生成，这些数据可用于确定如何处理风险。你处理风险的方式取决于组织的风险胃口——即公司愿意接受的风险程度。处理潜在风险有四种可能的方法：

- **回避（Avoid）**：回避风险意味着消除、从某项活动中退出或不参与。虽然这可能是一个可行的方案，但避免该活动可能会产生相关的机会成本。

- **接受（Accept）**：接受风险意味着对风险已理解并已进行评估。高层管理人员决定继续推进的收益大于风险。如果负责人没有获得有关风险的良好数据，或者做出了错误的假设，就可能会做出错误的选择。这可能导致具有全球影响的灾难（如`BP`、福岛、切尔诺贝利、挑战者号等）。

- **转移（Transfer）**：转移风险意味着将其推卸给第三方。例如，购买保险。

- **缓解（Mitigate）**：缓解风险意味着使用控制措施来降低风险。例如，安装防火墙就是缓解风险的一种方法。

记住，你永远无法消除所有风险。总会有某些残留风险。此外还有固有风险，定义为执行特定活动时产生的风险。例如，骑摩托车的固有风险是你可能会被汽车撞到。

无论你做何种决定，都应该在关于如何处理识别风险的决策中纳入利益相关者的意见。由于有许多风险需要考虑，最好的起点是那些风险分值高的项目。这些项目具有对组织造成巨大伤害的潜力，应该首先处理。有时存在例外情况，例如当人员生命损失是一个因素时。

> 在`CASP`考试中，记住这些内容的一种简单方法是将其视为`AATM`（回避、接受、转移、缓解）。虽然它不是取款机，但它可能帮助你通过考试。

## 实施控制措施

一旦决定了如何处理已识别的风险，就是时候执行缓解计划、策略和控制措施了。用于推动流程的文档是风险评估报告。该报告将包含组织所有的发现、信息、评估和建议。最终的评估报告成为管理层就应实施哪些控制措施做出明智业务决策的工具。

这些系统要求你设计某种信息分类系统。无论你所使用的分类系统的机密性或完整性如何，你必须根据组织/行业将信息类型分类为`CIA`（机密性、完整性、可用性）级别。例如，国防部（`DoD`）可能更关注信息的机密性，而云供应商可能更关注可用性。风险团队将根据总分确定所需的最低安全控制措施。如果没有资产估值，很难理解安全防御措施投资的投资回报率（`ROI`）或成本效益分析。控制措施可以是物理的、技术的或操作的。

### 物理控制

示例包括锁、栅栏、视频监控（`CCTV`）、灯光、保安人员。

### 技术控制

你将根据`CIA`要求和组织的策略实施技术控制措施。此类控制的示例包括加密、`VPN`、安全协议（`IPSec`、`SSL`、`TLS`等）、`VLAN`、防火墙和`IDS`。

### 操作控制

示例包括招聘实践、雇佣实践、离职实践、业务连续性以及灾难演练和培训。

控制措施还可以用于许多目的，例如预防、威慑、纠正、缓解等。一旦设计了适当的控制措施，必须将其到位。例如，栅栏是一种物理控制，但可以用于检测甚至延迟攻击者。实施控制措施的目的是解决识别出的风险、威胁和漏洞。为了实施控制，必须建立预算。虽然风险评估过程的大部分已由团队完成，现在轮到管理层进行优先级排序、创建预算，并制定实施最终报告中所提建议的战术和战略计划了。要确定实施哪些控制措施，你必须考虑总拥有成本（`TCO`）。`TCO`可以帮助确定资产或防御措施的总成本。它包含了价格、维护费用、更新、保险等等方面。风险评估团队必须尝试找到一种在保持最低年度成本的同时提供最大风险削减的解决方案。

这些建议可能对整个组织产生影响，可能需要数月甚至几年才能完全实施。这种对战术和战略建议的优先级排序将使组织能够根据定义的目标和任务做出明智的业务决策。

控制措施实施后仍有很多工作要做，必须对员工进行培训。安全部门必须与管理层合作实施持续的安全意识培训。实施组织变革需要组织系统、资源和数据的所有员工和用户。

## 持续监控

风险管理过程的最后阶段是监控。你可以将监控视为一种变更管理。当系统发生变化时，都应该进行重新评估以查看变化如何影响潜在风险。

持续监控允许组织实时评估控制措施的运行有效性。由于持续监控发生在关键控制措施使用的事件之后或期间，它使企业能够快速发现故障并找到改进方法。`NIST 800-37`《将风险管理框架应用于联邦信息系统的指南》将持续监控描述为一种有效的全组织计划，其应包含以下内容：

- 配置管理

- 控制过程

- 安全影响分析

- 选定安全评估

- 安全状态报告

- 资产所有积极参与

`SP 800-37`还指出，持续监控应该涵盖这些功能：

- 报告进度。

- 处理漏洞。

- 描述信息系统所有者打算处理这些漏洞。

在资产的生命周期内，会发生变化。人员更替、设备更换、配置更改、流程修订。这些变化将影响组织的安全态。必须对结果进行评估，以确定这些变化是否以不利的方式改变了预期的安全状态。

## 企业架构框架与治理

企业安全架构（`ESA`）框架描述了规划、分配和控制信息安全资源的过程。`ESA`框架用于 IT 治理，包括人员、过程和技术。以下是`ESA`框架的两个示例：

- **企业架构 (EA)**：联邦政府用于确保业务战略和 IT 投资保持一致。

- **谢尔伍应用业务安全架构 (SBSA)**：另一种基于架构视角的策略视角。

无论使用何种架构，目标都是衡量性能并确保公司获得安全投资的最佳回报。`ESA`通常包括战略、行动计划和监控条款，以及定义的指标如下：

- 战略对齐

- 有效风险管理

- 价值交付

- 资源管理

- 性能衡量

- 过程集成

所选`ESA`必须平衡技术和程序解决方案，以支持业务的长期需求并提供实质性的长期效率和有效性。

# 风险评估的最佳实践

如果你被指派参加风险评估，关键关注点将是定义目标。一个很好的起点是企业的使命声明（`mission statement`）。使命声明通常定义了公司的主要目标。

在进行风险和漏洞评估时，有许多技术可以考虑。这些最佳实践或方法取决于评估范围以及团队试图保护的内容。为了妥善地保护和保护资产，需要大量的时间、资金和资源。只有这样，才能正确定义并充分实施适当的安全水平。在准备和进行风险评估时，请考虑以下最佳实践或方法：

- 创建风险评估策略。

- 建立 IT 基础设施组件和 IT 资产的清单并维护数据库。

- 根据组织的业务驱动因素定义风险评估目标和目的。

- 为你的组织确定一种一致的风险评估方法和途径。

- 根据组织的标准定义进行资产估值或资产关键性估值。

- 通过识别和将 IT 基础设施组件及资产分为关键、主要和次要，来限制风险评估范围。

- 理解并评估针对这些分类 IT 基础设施组件和资产的风险、威胁和漏洞。

- 为组织的关键、主要和次要 IT 基础设施定义统一的标准或衡量基准。

- 创建业务连续性计划，以确保在灾难或紧急情况下关键流程和活动能够继续。

- 按照定义的标准执行风险和漏洞评估。

实施这些风险评估最佳实践并非易事。它需要根据组织独特的业务驱动因素和优先事项进行仔细的分析和决策。年化损失预期的示例摘要见表`6.5`。

# 表 6.5 DMZ 资产的年化损失预期 (ALE)

| 资产 | 威胁 | SLE | ARO | ALE | 对策 |
|---|---|---|---|---|---|
| Web 服务器 | DoS | $9,800 | 1 | $9,800 | 冗余 Web 服务器 |
| 邮件服务器 | 开放中继 | $500 | .01 | $5.00 | 关闭中继 |
| DNS 服务器 | 缓存中毒 | $7,500 | .25 | $1,875 | DNSSec |
| 防火墙 | 举 | $0 | .2 | $0 | 加固 |
| 数据库 | SQL 注入 | $50,000 | 2 | $100,000 | Web 应用防火墙和输入验证 |

你可以看到，风险评估过程的结果是确定优先处理哪些项目。你必须记住，所有公司的资产都是有限的，并不是每一个漏洞都能解决。最好的开始方法是确定哪些项目会造成最大的损害，或者哪些对组织构成了最大的威胁。例如，在表`6.5`中提到，`SQL`注入攻击的`ALE`为`$100,000`。从检查这一威胁并评估对策成本开始将是至关重要的。

最后，你还需要记住风险评估过程不是一次性事件。随着项目的变化或根据定期性要求，必须重复风险评估过程。

# 总结

`CASP`（认证高级安全专业人员）必须理解业务面临的威胁、潜在风险以及减轻此类风险的方法。风险我们在个人和业务层面每天必须处理的问题。政策是处理风险的一种方式。在业务的人员方面，政策应该规定员工可以做什么和不能做什么。即使识别了风险并将其与漏洞关联，也必须确定潜在成本。这种成本可以通过定量或定性方法得出。每种方法都有其优缺点，并有助于提供工具来判断是否应该接受、避免、减轻或转移威胁。你将需要基本的风险公式以及如何对`SLE`和`ALE`等项目进行计算，考试可能会要求你完成这些。最后，`CASP`还必须理解超出基础 IT 安全的业务方面。这些项目包括合作伙伴关系、外包以及并购。

# 能力要求 (Be able Essentials)

能够描述各种业务模式。今天，企业比以往任何时候都更加全球化，总部可能在一个地区，而在另一个遥远地区制造。从 IT 安全的角度来看，此类合作伙伴关系的主要风险是知识和技术转移，包括有意的/透明的和无意的/隐蔽的。业务模式：`CASP`需要理解合作伙伴关系、外包以及并购。

能够描述内部和外部影响。许多因素影响着业务。在美国和大多数工业化国家，越来越多的监管法规影响着公司的运营。在美国，有诸如`HIPAA`和`SOX`等指令。内部因素（如审计结果和高层政策）对业务的日常运营产生巨大影响。

了解网络边界的改变如何影响业务。云计算将改变我们今天所知的大部分计算方式。由于模糊了网络边界，这是一个重大的范式转变。20 90 年的网络很容易定义，因为公司资产位于防火墙、`IDS`和其他防御技术之后。云计算改变了这一点，因为你可能不知道你数据的确切位置。你可能无法完全理解云拥有的保护机制。

能够描述允许个人管理的设备连接到公司环境的风险。从手机、智能手机、`PDA`、`iPad`甚至`MP3`音乐播放器，每个人对基于计算机设备的访问权限都比过去大。这让安全专业人员非常担心，因为其中许多设备最终会进入工作场所。如何处理这些设备、哪些设备可以连接到网络、哪些是不被允许的，都是必须回答并通过政策强制执行的问题。

能够根据`CIA`的总分对信息进行分类。机密性、完整性和可用性（`CIA`）的概念对于现代安全原则至关重要。作为`CASP`候选人，你必须理解这些概念以及它们如何应用于风险评估过程中。

能够描述特定的风险分析技术。可以使用两种基本技术进行风险分析：定性和定量风险分析。定性风险评估不以金额为基准，使用关键、高、中、低等属性。定量风险评估以金额为基准，为已知风险分配金额。

了解如何进行风险确定分析。风险和漏洞评估提供了有关组织 IT 基础设施及其资产当前安全水平的必要信息，以便评估人员能够为增加或增强 IT 资产的安全水平提供建议。

理解进行风险评估是困难且容易出错的。一旦识别并评估了风险，要意识到分析结果本身往往也是问题。

了解如何以及何时应用安全控制。控制可能会应用也可能不应用。所有公司的实施控制的资金都是有限的，控制的成本不应超过资产价值。执行定量或定性风险评估可以为是否应该应用控制提供依据。
