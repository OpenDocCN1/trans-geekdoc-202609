
"github.com/go-sql-driver/mysql"

)

```

正如我们在 2.6.1 节 中提到的，Go 语言规范并未定义这些字符串的含义，也未定义如何确定包的导入路径，而是将这些问题留给工具处理。在本章中，我们将详细探讨 `go` 工具如何解释它们，因为大多数 Go 程序员使用它进行构建、测试等操作。当然也存在其他工具。例如，使用 Google 内部多语言构建系统的 Go 程序员遵循不同的规则来命名和定位包、指定测试等，这些规则更贴合该系统的约定。

对于打算共享或发布的包，导入路径应该是全局唯一的。为了避免冲突，除标准库包之外的所有包的导入路径都应以拥有或托管该包的组织的互联网域名开头；这也使得查找包成为可能。例如，上面的声明导入了由 Go 团队维护的 HTML 解析器和一个流行的第三方 MySQL 数据库驱动程序。

## 10.3 包声明

每个 Go 源文件开头都需要有 `package` 声明。其主要目的是确定当该包被另一个包导入时的默认标识符（称为 `包名`）。

例如，`math/rand` 包的每个文件都以 `package rand` 开头，因此当你导入此包时，可以通过 `rand.Int`、`rand.Float64` 等方式访问其成员。

```
package main

import (

    "fmt"

    "math/rand"

)

func main() {

    fmt.Println(rand.Int())

}
```

按照惯例，包名是导入路径的最后一个片段，因此，即使两个包的导入路径必然不同，它们也可能拥有相同的名称。例如，导入路径为 `math/rand` 和 `crypto/rand` 的包名称都是 `rand`。我们稍后将看到如何在同一个程序中同时使用它们。

"最后一个片段" 惯例有三个主要例外。第一个例外是，定义命令（可执行 Go 程序）的包名称始终为 `main`，无论该包的导入路径是什么。这向 `go build` (§10.7.3) 发出信号，表明它必须调用链接器来生成可执行文件。

第二个例外是，如果文件名以 `_test.go` 结尾，目录中的某些文件其包名可能带有后缀 `_test`。这样的目录可能定义*两个*包：常规包，外加一个称为 `外部测试包` 的包。`_test` 后缀向 `go test` 发出信号，表明它必须构建这两个包，并指示哪些文件属于哪个包。外部测试包用于避免测试依赖导致的导入图中的循环；它们将在 11.2.4 节 中详细介绍。

第三个例外是，某些依赖管理工具会在包导入路径后追加版本号后缀，例如 `"gopkg.in/yaml.v2"`。包名不包含该后缀，因此在这种情况下包名仅为 `yaml`。

## 10.4 导入声明

Go 源文件可以在 `package` 声明之后、第一个非导入声明之前，包含零个或多个 `import` 声明。每个导入声明可以指定单个包的导入路径，或在圆括号列表中指定多个包。下面两种形式等价，但第二种形式更常用。

```
import "fmt"

import "os"

import (

    "fmt"

    "os"

)
```

导入的包可以通过插入空行进行分组；这种分组通常表示不同的领域。顺序并不重要，但按照惯例，每组内的行按字母顺序排序。（`gofmt` 和 `goimports` 都会为你分组和排序。）

```
import (

    "fmt"

    "html/template"

    "os"

    "golang.org/x/net/html"

    "golang.org/x/net/ipv4"

)
```

如果我们需要将两个同名包（如 `math/rand` 和 `crypto/rand`）导入到第三个包中，导入声明必须为其中至少一个指定替代名称以避免冲突。这称为 `重命名导入`。

点击此处查看代码图像

```
import (

    "crypto/rand"

    mrand "math/rand" // 替代名称 mrand 避免冲突

)
```

替代名称仅影响导入它的文件。同一包中的其他文件，甚至同一包中的文件，可以使用其默认名称导入该包，或使用不同的名称。

重命名导入即使在没有冲突时也很有用。如果导入包的名称笨重（自动生成的代码有时会出现这种情况），使用缩写名称可能更方便。应始终如一地使用相同的短名称以避免混淆。选择替代名称有助于避免与常见的局部变量名发生冲突。例如，在一个包含许多名为 `path` 的局部变量的文件中，我们可以将标准包 `"path"` 导入为 `pathpkg`。

每个导入声明都会建立从当前包到被导入包的依赖关系。如果这些依赖关系形成循环，`go build` 工具会报错。

## 10.5 空白导入

将包导入文件却不在该文件中引用其定义的名称是错误的。然而，有时我们必须导入包仅仅为了其副作用：求值其包级变量的初始化表达式并执行其 `init` 函数（§2.6.2）。为了抑制原本会遇到的“未使用导入”错误，我们必须使用重命名导入，其中替代名称为 `_`（空白标识符）。和往常一样，空白标识符永远不能被引用。

点击此处查看代码图片

```
import _ "image/png" // register PNG decoder
```

这被称为**空白导入**。它最常用于实现一种编译时机制，即主程序通过空白导入额外的包来启用可选功能。首先我们将看到如何使用它，然后了解其工作原理。

标准库的 `image` 包导出了一个 `Decode` 函数，该函数从 `io.Reader` 读取字节，判断数据使用哪种图像格式编码，调用相应的解码器，然后返回生成的 `image.Image`。使用 `image.Decode`，很容易构建一个简单的图像转换器，以一种格式读取图像并以另一种格式写出：

点击此处查看代码图片
gopl.io/ch10/jpeg

```
package main

import (

    "fmt"

    "image"

    "image/jpeg"

    _ "image/png" // register PNG decoder

    "io"

    "os"

)

func main() {

    if err := toJPEG(os.Stdin, os.Stdout); err != nil {

        fmt.Fprintf(os.Stderr, "jpeg: %v\n", err)

        os.Exit(1)

    }

}

func toJPEG(in io.Reader, out io.Writer) error {

    img, kind, err := image.Decode(in)

    if err != nil {

        return err

    }

    fmt.Fprintln(os.Stderr, "Input format =", kind)

    return jpeg.Encode(out, img, &jpeg.Options{Quality: 95})

}
```

如果将 `gopl.io/ch3/mandelbrot`（§3.3）的输出传递给转换程序，它会检测到 PNG 输入格式并写入 图 3.3 的 JPEG 版本。

点击此处查看代码图片

```
$ go build gopl.io/ch3/mandelbrot

$ go build gopl.io/ch10/jpeg

$ ./mandelbrot | ./jpeg >mandelbrot.jpg

Input format = png
```

注意 `image/png` 的空白导入。没有该行，程序照常编译链接，但无法再识别或解码 PNG 格式的输入：

点击此处查看代码图片

```
$ go build gopl.io/ch10/jpeg

$ ./mandelbrot | ./jpeg >mandelbrot.jpg

jpeg: image: unknown format
```

其工作原理如下。标准库提供了 GIF、PNG 和 JPEG 的解码器，用户也可以提供其他解码器，但为了保持可执行文件体积小，除非显式请求，否则解码器不会包含在应用程序中。`image.Decode` 函数查阅支持格式的表。表中的每个条目指定四项内容：格式名称；所有以这种方式编码的图像的前缀字符串（用于检测编码）；一个解码已编码图像的 `Decode` 函数；以及一个仅解码图像元数据（如尺寸和色彩空间）的 `DecodeConfig` 函数。通过调用 `image.RegisterFormat` 向表中添加条目，通常在每种格式的支持包的包初始化器中进行，例如 `image/png` 中的这个：

点击此处查看代码图片

```
package png // image/png

func Decode(r io.Reader) (image.Image, error)

func DecodeConfig(r io.Reader) (image.Config, error)

func init() {

    const pngHeader = "\x89PNG\r\n\x1a\n"

    image.RegisterFormat("png", pngHeader, Decode, DecodeConfig)

}
```

其效果是：应用程序只需空白导入所需格式的包，即可使 `image.Decode` 函数能够解码该格式。

`database/sql` 包使用类似的机制让用户仅安装所需的数据库驱动程序。例如：

点击此处查看代码图片

```
import (

    "database/mysql"

    _ "github.com/lib/pq"              // enable support for Postgres

    _ "github.com/go-sql-driver/mysql" // enable support for MySQL

)

db, err = sql.Open("postgres", dbname) // OK

db, err = sql.Open("mysql", dbname)    // OK

db, err = sql.Open("sqlite3", dbname)  // returns error:

                                               unknown driver "sqlite3"
```

**练习 10.1：** 扩展 `jpeg` 程序，使其能将任意支持的输入格式转换为任意输出格式，使用 `image.Decode` 检测输入格式，并使用标志选择输出格式。

**练习 10.2：** 定义一个通用的归档文件读取函数，能够读取 ZIP 文件（`archive/zip`）和 POSIX tar 文件（`archive/tar`）。使用类似上述的注册机制，以便通过空白导入插入对每种文件格式的支持。

## 10.6 包与命名

本节将提供一些建议，说明如何遵循 Go 语言独特的包及其成员命名约定。

创建包时，保持名称简短，但不要短到晦涩难懂。标准库中最常用的包名为 `bufio`、`bytes`、`flag`、`fmt`、`http`、`io`、`json`、`os`、`sort`、`sync` 和 `time`。

在可能的情况下要具有描述性且明确。例如，当 `imageutil` 或 `ioutil` 这样具体且简洁的名称可用时，不要将工具包命名为 `util`。避免选择常用于相关局部变量的包名，否则可能会迫使包的客户端使用重命名导入，就像 `path` 包那样。

包名通常采用单数形式。标准包 `bytes`、`errors` 和 `strings` 使用复数形式是为了避免隐藏对应的预声明类型，而在 `go/types` 的情况下，是为了避免与关键字冲突。

避免使用已有其他含义的包名。例如，我们最初在 第 2.5 节 中将温度转换包命名为 `temp`，但这名字没用多久。这是个糟糕的主意，因为“temp”几乎是“temporary”的通用同义词。我们短暂地用过 `temperature`，但太长且没说明包的功能。最终它变成了 `tempconv`，这更短且与 `strconv` 并行。

现在转到包成员的命名。由于对另一个包成员的每次引用都使用限定标识符（如 `fmt.Println`），描述包成员的责任由包名和成员名共同承担。我们无需在 `Println` 中提及格式化概念，因为包名 `fmt` 已经涵盖了。设计包时，应考虑限定标识符的两部分如何协同工作，而非仅考虑成员名本身。以下是一些典型示例：

## 10.7 Go 工具

本章剩余部分介绍 `go` 工具，它用于下载、查询、格式化、构建、测试和安装 Go 代码包。

`go` 工具将一组多样化工具的功能整合到一个命令集中。它是一个包管理器（类似于 `apt` 或 `rpm`），可回答关于其包库存的查询、计算依赖关系，并从远程版本控制系统下载它们。它是一个构建系统，可计算文件依赖关系并调用编译器、汇编器和链接器，尽管它有意设计得不如标准 Unix `make` 完整。正如我们将在第 11 章中看到的，它还是一个测试驱动器。

其命令行界面采用“瑞士军刀”风格，拥有十多个子命令，其中一些我们已经见过，如 `get`、`run`、`build` 和 `fmt`。你可以运行 `go help` 查看其内置文档的索引，但为了方便参考，我们在下面列出了最常用的命令：

```
$ go

...

    build       编译包和依赖项

    clean       移除目标文件

    doc         显示包或符号的文档

    env         打印 Go 环境信息

    fmt         对包源码运行 gofmt

    get         下载并安装包和依赖项

    install     编译并安装包和依赖项

    list        列出包

    run         编译并运行 Go 程序

    test        测试包

    version     打印 Go 版本

    vet         对包运行 go tool vet

Use "go help [command]" for more information about a command.

...
```

为了将配置需求降至最低，`go` 工具严重依赖约定。例如，给定一个 Go 源文件的名称，该工具可以找到其所属的包，因为每个目录只包含一个包，且包的导入路径对应于工作区中的目录层级。给定一个包的导入路径，该工具可以找到存储其目标文件的相应目录。它还可以找到托管源代码仓库的服务器 URL。

### 10.7.1 工作区组织

大多数用户唯一需要的配置是 `GOPATH` 环境变量，它指定工作区的根目录。切换到不同工作区时，用户需更新 `GOPATH` 的值。例如，编写本书时我们将 `GOPATH` 设置为 `$HOME/gobook`：

```
$ export GOPATH=$HOME/gobook

$ go get gopl.io/...
```

使用上述命令下载本书所有程序后，你的工作区将包含如下层级结构：

```
GOPATH/

    src/

        gopl.io/

            .git/

            ch1/

                helloworld/

                    main.go

                dup/

                    main.go

                ...

        golang.org/x/net/

            .git/

            html/

                parse.go

                node.go

                ...

    bin/

        helloworld

        dup

    pkg/

        darwin_amd64/

            ...
```

`GOPATH` 有三个子目录。`src` 子目录存放源代码。每个包位于一个目录中，该目录相对于 `$GOPATH/src` 的名称即为包的导入路径，例如 `gopl.io/ch1/helloworld`。请注意，单个 `GOPATH` 工作区在 `src` 下包含多个版本控制仓库，如 `gopl.io` 或 `golang.org`。`pkg` 子目录是构建工具存放编译后包的地方，`bin` 子目录存放可执行程序，如 `helloworld`。

第二个环境变量 `GOROOT` 指定 Go 发行版的根目录，其中提供了标准库的所有包。`GOROOT` 下的目录结构类似于 `GOPATH`，因此，例如 `fmt` 包的源文件位于 `$GOROOT/src/fmt` 目录中。用户无需设置 `GOROOT`，因为默认情况下 `go` 工具将使用其安装位置。

`go env` 命令打印与工具链相关的环境变量的有效值，包括缺失变量的默认值。`GOOS` 指定目标操作系统（例如 `android`、`linux`、`darwin` 或 `windows`），`GOARCH` 指定目标处理器架构，如 `amd64`、`386` 或 `arm`。虽然 `GOPATH` 是你必须设置的唯一变量，但其他变量偶尔会出现在我们的解释中。

```
$ go env

GOPATH="/home/gopher/gobook"

GOROOT="/usr/local/go"

GOARCH="amd64"

GOOS="darwin"

...
```
