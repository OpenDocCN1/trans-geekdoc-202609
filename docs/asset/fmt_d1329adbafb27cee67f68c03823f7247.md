
Почин дороже дела。 – 俄语谚语：*“开头至关重要。”* (Mertvago, 1995)

信息收集是进行渗透测试的第一步，而且认为是最重要的一步。在完成这一阶段后，我们应该拥有一份关于目标网络的详细地图，并理解进行完整评估所需的工作量。此外，我们还应该能够识别网络内的系统类型，包括操作系统（OS）信息，这将允许我们为渗透测试项目的剩余部分完善人员配备配置和工具选择。客户通常会提供许多关于其网络的信息来协助你的工作，但如果这些信息是错误的，请不要感到惊讶，这就是为什么无论如何我们都需要执行这一步。

信息收集可以分为两种不同类型——被动和主动。在被动信息收集中，我们试图在不直接连接到目标网络和系统的情况下，尽可能收集有关目标网络的所有信息。我们还将尝试收集公司信息，包括所有权、公司位置、网络和系统位置、物理设施信息（以防我们需要进行物理渗透测试）等，具体取决于渗透测试项目的目标。第二种信息收集类型是主动的，即我们连接到我们的目标。这种类型的信息收集旨在更好地理解项目中的工作范围、类型和系统数量。稍后我们将更详细地列出这些信息，但现在我们只想更好地了解我们正在面对的是什么样的对手。

人们倾向于认为，主动信息收集比被动信息收集要有用得多。然而，这种假设通常是不正确的。过去泄露的信息并不罕见，而且这些泄露的信息往往被存档了，即使后来被纠正了也是如此。正是这类错误可以极大地有利于我们的渗透测试工作，特别是当信息与网络有关时。找到配置和系统安装文件的存档，以及包括公司机密的私有数据并非不可能。

从项目管理的角度来看，这一阶段将直接影响项目的“执行过程”（Executing Process）组，并将帮助完善你来自质量保证（QA）、项目团队流程（包括获取和开发过程）的输出，并且会影响《项目管理知识体系》（PMBOK）定义的“请求卖方响应”（request seller responses）活动。由于这一过程组通常是成本波动最大的地方，因此确保你的项目团队良好执行信息收集阶段至关重要。

在本节中，我们将主要处理信息系统安全评估框架（ISSAF）方法。这是因为 ISSAF 将渗透测试的这一阶段分解为更细粒度的步骤。然而，在该阶段结束时，我们将满足开源安全测试方法手册（OSSTMM）的目标，该手册将大部分信息收集压缩在一个名为“物流”（Logistics）的模块中，并包括以下领域：

- 框架
- 网络质量
- 时间框架

## 被动信息收集

如前所述，被动信息收集侧重于收集存储在非我们客户网络系统中的存档信息。在信息收集阶段，会进行许多不同类型的搜索，包括与目标网络并非特定相关的信息，例如员工信息、物理位置和业务活动。列表中包括以下可能的搜索项：

- 定位目标的 Web 存在形式（注意：这不仅是指网页）
- 收集有关目标的搜索引擎搜索结果
- 寻找包含员工和/或公司评论的 Web 群组
- 检查员工的个人网站
- 获取证券和交易委员会的信息，以及任何关于目标的额外财务信息
- 寻找任何运行时间统计网站（uptime statistics sites）
- 搜索存档网站以获取额外信息
- 寻找目标发布的招聘公告
- 搜索新闻组
- 查询域名注册商
- 查看目标是否通过第三方服务提供反向域名系统（DNS）信息

在该阶段结束时，渗透测试人员将获得大量关于目标的丰富信息，而无需访问目标网络。所有的被动信息都是从第三方来源收集的，这些来源收集了关于我们目标的信息，或者有法律义务保留这些数据。在该阶段结束时，可能会让你印象深刻的一点是，存在的信息是如此巨大——往往是那些本不该公开的信息。在你完成本章末的信息收集练习后，你可能会发现确保个人隐私已变得多么困难，以及由于互联网扩张直接导致的过去几十年发生了多少变化。

## Web 存在（Web Presence）

此阶段通常提供关于你客户公司的丰富信息，包括员工信息、物理和逻辑位置、系统类型（包括品牌和操作系统）以及网络架构。幸运的是，渗透测试的这一阶段使用了一些简单的工具，它们列在 ISSAF 方法列表中：

字体 浏览器

- [Dogpile.com](http://Dogpile.com)
- [Alexa.org](http://Alexa.org)
- [Archive.org](http://Archive.org)
- `dig`
- `nslookup`

我们将主要使用这些网站，也会使用其他可以扩展我们对目标知识的网站。与 usual，OSSTMM 没有任何推荐工具，而是依靠渗透测试人员的经验来选择最合适、最有用的工具。ISAF 推荐的网站（以及 浏览器）用法是不言而喻的；真正的困难在于理解你正在寻找什么信息。答案基本上是“你能拿到的所有”。以下是一个建议列表，但绝非全部，并将根据你的合同协议和目标系统进行添加（或删除）。然而，这个列表是一个很好的开始，应该引导你思考根据目标可能获得的其他类型的信息。你在这个阶段收集的信息越多，你的后续任务就越容易执行：

- 网站地址
- Web 服务器类型
- 服务器位置
- 日期，包括“最后修改日期”
- Web 链接——包括内部和外部
- Web 服务器目录树
- 使用的技术（软件/硬件）
- 加密标准
- 适用于 Web 的语言
- 表单字段（包括隐藏字段）
- 表单变量
- 表单提交方法
- 公司联系信息
- 元标记（Meta tags）
- Web 页面中的任何注释
- 电子商务能力
- 提供的服务和产品

**警告工程师：** 在此阶段收集的信息可能不在公共领域。作为渗透测试人员，将所有信息处理得像被标记为“限制”一样是关重要的，即使这些信息是在公共访问的网站上发现的。由于通过实践来理解概念比仅仅阅读要容易得多，让我们来看一个真实世界的例子。如果你遵循本书中的步骤，这些信息可能会在本书编写的时间与你阅读的时间之间发生变化；但这个练习的重点是学习我们为什么想要收集必要的信息——而不是仅仅提供一份一步步的操作的手册，手册往往是僵化的且会产生知识漏洞。通过理解我们为什么在这个阶段要做我们要做的事情，你作为一名专业渗透测试人员的能力将比你仅仅死记硬背地通过重复相同的步骤来运行所有渗透测试要强得多。假设我们从未听说过一个名为 `Nmap` 的工具。如果我们通过搜索引擎查询来查找更多关于该工具及其创建者的信息，我们会发现可能存在与 `Nmap` 相关的三个不同的 Web 网站，如图 9.1 所示。[Nmap.org](http://Nmap.org) 看起来是一个自然的选择，但 [Insecure.org](http://Insecure.org) 和 [Sectools.org](http://Sectools.org) 似乎与 `Nmap` 扫描器间接相关。
