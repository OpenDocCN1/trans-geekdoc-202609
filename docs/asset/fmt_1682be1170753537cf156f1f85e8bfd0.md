
# 语义网基础

## RDF 和 RDFS

RDF 模型本质上是有向图，其中每个节点要么是资源，要么是字面值，每条有向弧表示节点之间的二元关系。资源基本上是一个实体实例或一个逻辑谓词。

### RDF 1.0 和 RDFS

RDF 1.0 通过*统一资源标识符 (URI)*引用来标识资源。URI 可以是*统一资源定位符 (URL)*或*统一资源名称 (URN)*。URL（例如 `http://www.orm.net`）包含网络访问类型（例如用于超文本传输协议的 `http`）以及用于定位资源的网络地址。URN（例如 `urn:isbn:1-55860-672-6`）包含命名空间（例如用于国际标准书号的 `ISBN`）以及在该命名空间内标识该资源的名称。与 URL 不同，URN 不提供在 Web 上定位资源的方法。URL 和 URN 都是全局标识符，因此当在不同文档中使用时，它们指代同一资源。

URI 引用（或 URIref）是一个 URI，后面可选地跟一个片段标识符。例如，URI 引用 `https://ww.w3.org/TR/rdf-primer/#basicconcepts` 由 URI `https://www.w3.org/TR/rdf-primer/`、一个“#”分隔符和片段标识符 `basicconcepts` 组成。用于 URIref 的字符串由 Unicode 字符组成。

图 18.20 展示了一个简单的 RDF 1.0 模型，以图的形式描绘。此处，资源节点显示为命名的圆角矩形；字面值显示为命名的直角矩形；关系显示为从主语节点指向宾语节点的命名箭头。该图旨在传达这样的语义：存在一本由 ISBN 1-55860-672-6 标识的书，其作者是名为“Terry Halpin”的人。

![图 18.20 一个简单的 RDF 1.0 模型。](img/f18-20-9780443237904.jpg)

图 18.20 一个简单的 RDF 1.0 模型。

RDF 将信息捕获为简单的*语句*，每个语句表示为一个*三元组*（主语、谓语、宾语）。主语和谓语是资源，因此由 URIref 标识。宾语可以是资源或字面值。字面值可以是无类型的（如此处所示）或有类型的（通过将值与数据类型配对，该数据类型本身由指向标准 XML Schema 数据类型的 URIref 标识）。每个谓语包含一个谓语读法，例如 `authored_by`。由于相同的谓语读法在不同上下文中含义不同，因此需要 URIref 为谓语分配唯一含义。

图 18.20 左侧的资源节点表示一本具体的书和一个具体的人。然而，右侧的资源节点表示类型 Book 和 Person。类型谓语将实例关联到类型，意为“是……的实例”。RDF 还允许描述资源集合（例如集合和列表），且 RDF 图可以使用 RDF/XML 序列化为 XML 格式。

正如图 18.20 所示，RDF 图允许作为实例或类型的节点，并允许表示实例间关系或实例与类型间关系的弧。RDF 还允许类型与类型之间的关系（例如 `Woman is_a Person`）。RDF 甚至允许声明一个类型是其自身的实例（例如 `Class is_of_type Class`），这可能导致诸如罗素悖论之类的形式化问题。此外，没有为任何谓语分配特殊语义，因此 `is_an_instance_of` 关系和 `is_a_subtype_of` 关系与 `has_name` 关系受到相同对待（除了用于 URIref 的不同字符串）。因此，无法基于对某些谓语特殊属性的了解（例如 `is_a_subtype_of` 的传递性）执行推理。

RDFS 在 RDF 基础上构建，为类和子类化提供内置支持。例如，资源可被类型化为类（使用 `rdfs:Class`），预定义谓语 `rdfs:subClassOf` 被定义为传递的。对于给定的谓语，扮演主语和宾语角色的实例集合分别称为*定义域*和*值域*。RDFS 允许通过分别限制定义域（使用 `rdfs:domain`）和值域（使用 `rdfs:range`）来为谓语指定类型。集合中的成员资格也可使用 `rdfs:member` 属性指定。

尽管有这些改进，RDFS 仍然既不够表达力（例如，它无法将关联约束为除 `m:n` 之外的其他基数，也无法通过合取现有属性来表达复杂属性），又过于表达力（例如，像 RDF 一样，它允许声明 Class 是其自身的实例，且其底层逻辑是不可判定的）。

2014 年，RDF 升级为 RDF 1.1，RDFS 升级为 RDFS 1.1。这两个标准都通过*国际化资源标识符 (IRI)* 来标识资源。URI 使用 ASCII 字符，而 IRI 使用通用编码字符集（Unicode/ISO/IEC 10646）以适应非英语字符。

有关 RDF 1.1 的详细入门指南，请参阅 `https://www.w3.org/TR/rdf11-primer/`。RDFS 1.1 标准可在 `http://www.w3.org/TR/2014/REC-rdf-schema-20140225/` 访问。2023 年，W3C 发布了 RDFS 1.2 的工作草案（见 `https://www.w3.org/TR/rdf-schema/`）。

## OWL 及其子语言

与 RDFS 一样，OWL 仅限于二元事实类型（无 *n* 元或一元）。OWL 的形式语义比 RDFS 更简单，禁止了 RDFS 中的某些自由度，同时增加了捕获进一步约束的能力。OWL 用于为业务领域指定本体模式（称为术语盒或 *Tbox*），而 RDF/XML 用于标记符合要求的实例数据（事实填充称为断言盒或 *Abox*）。

由于 Web 上的信息通常不完整，OWL 采用*开放世界假设*（找不到或无法推断某命题并不意味着该命题为假）。OWL 于 2004 年 2 月被 W3C 推荐为标准。2009 年 10 月，该语言的一个主要升级版本，称为 *OWL 2*，被 W3C 推荐，之前的版本更名为 *OWL 1*。2012 年 12 月，OWL 2 的第二版被推荐，且仍是当前版本（见 `https://www.w3.org/TR/owl-overview/`）。

OWL 1 有三种风格：OWL Lite、OWL DL 和 OWL Full。OWL Lite 是 OWL DL 的子集，而 OWL DL 本身是 OWL Full 的子集。*OWL Lite* 用于所有约束均简单的基本分类层次。它基于描述逻辑 *SHIF(D)*，具有较低的形式复杂性，且是可判定的。OWL Lite 只能表达简单约束，且仅支持简单推理（例如基于传递性的推理）。*OWL DL* 表达能力强得多，同时仍保持可判定性，它基于描述逻辑 *SHOIN(D)*。OWL DL 包含 OWL Full 的所有构造，但限制其使用。OWL DL 是一阶逻辑的一个片段，因此不允许在同一模型中声明一个类为另一个类的实例。*OWL Full* 表达能力更强，允许所有 RDF 表达，包括允许一个类成为其自身的实例。OWL Full 是不可判定的，超越甚至了一阶逻辑。尽管具有不可判定性，OWL Full 仍无法表达某些在 ORM 中可表达的重要约束（例如非循环性）。

### OWL 2 子语言

OWL 2 作为 OWL DL 的子集引入了三种新的子语言：`OWL 2 EL`、`OWL 2 QL` 和 `OWL 2 RL`。

- **`OWL 2 EL`** 旨在为大型本体上的基本推理任务提供良好的性能，它基于 `EL` 描述逻辑族，该族提供存在量化但不提供全称量化。

- **`OWL 2 QL`** 旨在为大型本体上的基本查询提供良好的性能，这些查询可通过重写为标准关系查询语言（如 SQL）中的查询来实现。

- **`OWL 2 RL`** 旨在为使用规则语言（如直接在 RDF 三元组上操作的规则扩展数据库技术）管理本体提供良好的性能。

### OWL 1 中的基数限制

默认情况下，所有关系类型均为可选且为 `m:n`。OWL Lite 允许将事实角色声明为强制的，并使用 `minCardinality` 和 `maxCardinality` 限制将事实类型指定为 `n:1`、`1:n` 或 `1:1`。图 18.21 通过将这些限制与 ORM 中的等价表示相关联，解释了它们的含义。ORM 事实类型 `A R B` 被绘制为 RDF 图，其中假设主体和客体节点为类。谓词 `R` 从 `A` 指向 `B`。

![图 18.21 ORM 与 OWL 中基数限制之间的一些对应关系。](img/f18-21-9780443237904.jpg)

图 18.21 ORM 与 OWL 中基数限制之间的一些对应关系。

OWL 本身没有图形化符号，因此事实类型及其限制是以文本方式声明的（见后面的示例）。用 1 的 `minCardinality` 限制 `R` 意味着 `A` 的每个实例至少与 `B` 的一个实例参与该关系类型。用 ORM 术语来说，`R` 的第一个角色是强制的。在 OWL DL 和 OWL Full 中，可以指定大于 1 的 `minCardinality`（在 ORM 中，这会在强制约束上增加一个频率约束）。

分配 0 的 `minCardinality` 意味着该角色是可选的。将 `maxCardinality` 限制为 1 意味着 `A` 的每个实例最多与 `B` 的一个实例参与该关系类型。用 ORM 术语来说，`R` 的第一个角色具有简单唯一性约束。在 OWL DL 和 OWL Full 中，可以指定大于 1 的 `maxCardinality`（在 ORM 中，这会用频率约束替换唯一性约束）。

将 `maxCardinality` 限制为 0 意味着所讨论的类（我们称之为类 `C`）的每个实例（可能是在查询中）都不与 `B` 的任何实例参与该关系类型。用 ORM 术语来说，这可以通过如图所示的子类型定义显式处理，或简单地作为条件包含在 ORM 查询中。例如，我们可以将滴酒不沾者定义为不饮酒的人。

作为一些基数声明的示例，以下 OWL 代码声明 `hasFaxNr` 谓词是可选且 `n:1` 的。

```
<owl:Restriction>
  <owl:onProperty rdf:resource="#hasFaxNr"/>
  <owl:minCardinality rdf:datatype="&xsd;nonNegativeInteger">0</owl:minCardinality>
</owl:Restriction>
<owl:Restriction>
  <owl:onProperty rdf:resource="#hasFaxNr"/>
  <owl:maxCardinality rdf:datatype="&xsd;nonNegativeInteger">1</owl:maxCardinality>
</owl:Restriction>
```

作为一种快捷方式，当最小和最大基数相同时，该值可赋给 `cardinality` 属性。因此，将 `owl:cardinality` 设为 0 意味着禁止，设为 1 意味着恰好一个。

总体而言，我们认为 Manchester 语法是这五种语法中最便于向非技术人员传达典型本体的语法。从现在开始，我们通常将使用 Manchester 语法来表述 OWL 示例。我们现在使用 Manchester 语法讨论 OWL 2 的一些基本特性。

命名空间前缀可作为缩写声明，使用形式为 `Prefix: namespacePrefix: IRI` 的前缀命令。前缀 `rdf:`、`rdfs:`、`owl:` 和 `xsd:` 是预定义的。本体文档中使用的每个用户定义前缀在该本体文档中必须恰好有一个前缀声明，例如 `Prefix: owl:` `Prefix: gup:` [`www.galacticUni.edu/programs#`](https://www.galacticUni.edu/programs#)。如果未提供前缀，则假定当前文档为命名空间。

字面量由双引号界定（例如 `"64"`），且可带类型（例如 `"64"^^xsd:integer`）。个体可通过在其名称前加上 `Individual:` 来声明，后面可选择性地跟上适用于它的属性声明。例如，该个体所属的类可在 `Types:` 后列出。一个个体可同时属于多个类，例如 `Individual: Biden Types: Politician, MalePerson`。

类可在 `Class:` 后声明，并使用 `SubClassOf` 声明为某个（通常是其他）类的子类，例如 `Class: Politician SubClassOf: Person`。在 OWL 中，子类关系是自反的（因此每个类都是其自身的子类）且传递的（因此如果 `A` 是 `B` 的子类，且 `B` 是 `C` 的子类，则 `A` 是 `C` 的子类）。这与 ORM 中的子类型关系不同，后者出于效率原因仅用于真子类型（因此是非自反的）且为直接的（因此是非传递的）。

关联个体的二元事实可通过将主体声明为个体，然后在 `Facts:` 后列出该语句的谓词和客体来指定。可使用逗号分隔符列出一个或多个事实。例如，我们可以陈述 Terry 是 Norma 的丈夫且 Terry 是 Selena 的父亲，如下所示：`Individual: Terry Facts: isHusbandOf Norma, isFatherOf Selena`。Manchester 语法允许使用 `some` 表示存在量词。因此，我们可以这样陈述 Terry 是某人的父亲：`Terry isFatherOf some Person`。

二元谓词的**定义域**是其主语必须所属的类，而二元谓词的**值域**是其宾语必须所属的类。在 Manchester 语法中，谓词可声明为 `ObjectProperty`，其定义域和值域分别在 `Domain:` 和 `Range:` 之后指定。例如：

```
ObjectProperty: isFatherOf     Domain: MalePerson     Range: Person
```

一个谓词可被赋予多个定义域和值域，此时主语必须属于该谓词所有定义域的**交集**，宾语必须属于该谓词所有值域的**交集**。

#### OWL 2 分类简介

图 18.22 展示了 OWL 2 中若干概念的 UML 类图。该图基于 <https://www.w3.org/TR/owl2-syntax/>。我们在 RDF 讨论中称为“资源”的内容，在 OWL 中称为 `entities`（实体）。OWL 实体可以是命名个体、类、属性（二元谓词）或数据类型。这与 ORM 和 ER 中“实体”一词的用法不同，在后者中，所有实体都是非词汇个体（而非类型或类）。

![图 18.22 基本 OWL 2 概念的类图（基于 OWL 2 规范）。](img/f18-22-9780443237904.jpg)

在 OWL 中，实体由 IRI 标识，但与某些方法不同，OWL **不**采用 `Unique Name Assumption`（唯一名称假设，UNA）。因此，在 OWL 中，同一实体可能被分配不同的 IRI，即使在同一文档内也是如此。因此，图 18.22 中 `entityIRI` 的多重性约束 1 应改为 1..\*（1 或多个）。如前所述，OWL 包含 `SameAs` 谓词，用于指示两个不同的 IRI 表示同一实体（例如，`DownUnder SameAs Australia`）。

`Literals`（数据值，如名称或数字）不被视为个体。这种做法与形式逻辑不同，在形式逻辑中字面量确实算作个体。只有 OWL 个体（而非字面量）可以是 OWL 类的成员。
