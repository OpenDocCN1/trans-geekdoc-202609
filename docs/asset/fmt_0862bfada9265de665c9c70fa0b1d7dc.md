# PHP 8 中的单元测试与调试

## 第 11.1 节：单元测试最佳实践

单元测试是确保 PHP 8 代码库可靠性和可维护性的重要实践。在本节中，我们将探讨 PHP 单元测试的最佳实践，包括可帮助您编写有效测试的工具、技术和策略。

### 为什么单元测试很重要

单元测试涉及将代码分解为更小的单元（通常是函数或方法），并隔离测试每个单元。主要目标是验证各个代码单元是否按预期执行。以下是单元测试至关重要的原因：

1. **早期缺陷发现**：单元测试可以在开发的早期阶段捕获缺陷和问题，从而减少后期调试所需的成本和精力。
2. **提升代码质量**：编写单元测试能促进更好的代码设计，使您的代码库更加模块化和可维护。
3. **文档作用**：单元测试可作为文档，提供代码应如何使用的示例。
4. **防止回归**：单元测试充当安全网，确保对代码的更改或增强不会引入新的缺陷。
5. **持续集成**：自动化单元测试可集成到您的开发工作流中，每次更改代码时自动运行。

### 选择单元测试框架

PHP 提供了多种单元测试框架，但 `PHPUnit` 是最广泛使用和支持的选择。您可以使用 `Composer` 安装 `PHPUnit`，它为编写和运行测试提供了一个功能丰富的环境。

```bash
composer require --dev phpunit/phpunit
```

### 编写可测试的代码

要编写有效的单元测试，创建可测试的代码至关重要。以下是一些关键原则：

1. **关注点分离**：确保您的代码遵循单一职责原则（SRP），以便每个函数或方法都有单一且明确的目的。
2. **依赖注入**：使用依赖注入将依赖项注入到您的类中，而不是对其进行硬编码。这允许您在测试期间用模拟对象替换依赖项。
3. **避免全局状态**：尽量减少全局状态的使用，因为它会增加单元测试的难度。相反，请使用参数或依赖注入。
4. **隔离单元**：编写测试时，专注于一次测试一个代码单元。将被测单元与外部依赖项隔离开来。

### 编写您的第一个单元测试

让我们创建一个简单的示例来演示单元测试。假设您有一个带有 `add()` 方法的 `Calculator` 类：

```php
class Calculator {
    public function add($a, $b) {
        return $a + $b;
    }
}
```

现在，您可以使用 `PHPUnit` 为这个 `add()` 方法编写单元测试：

```php
use PHPUnit\Framework\TestCase;

class CalculatorTest extends TestCase {
    public function testAdd() {
        $calculator = new Calculator();
        $result = $calculator->add(2, 3);
        $this->assertEquals(5, $result);
    }
}
```

在该测试用例中，我们创建了 `Calculator` 类的一个实例，使用参数 `2` 和 `3` 调用其 `add()` 方法，并断言结果为 `5`。

### 运行单元测试

您可以使用 `phpunit` 命令运行单元测试：

```bash
vendor/bin/phpunit CalculatorTest.php
```

`PHPUnit` 将执行测试并提供结果摘要，指示测试是通过还是失败。

本节介绍了单元测试的重要性，并提供了一个使用 `PHPUnit` 编写和运行单元测试的示例。在后续章节中，我们将深入探讨 `PHPUnit` 并探索高级测试技术。

## 第 11.2 节：PHP 8 中的调试技术

调试是识别和修复 PHP 8 应用程序中问题的必备技能。在本节中，我们将探讨 PHP 8 中可用的各种调试技术和工具，以简化调试过程。

### 基础调试技术

1. **使用 `echo` 和 `var_dump()`**：最简单的调试技术是在代码中插入 `echo` 或 `var_dump()` 语句以输出变量和值。这有助于您在不同点检查代码的状态。

   ```php
   $variable = "Hello, World!";
   echo $variable; // 输出: Hello, World!
   ```

2. **错误消息**：当出现问题时，PHP 提供描述性的错误消息，可显示在浏览器中。但是，请谨慎在生产环境中显示错误消息，因为它们可能会泄露敏感信息。

3. **日志记录**：PHP 允许您将消息记录到文件或集中式日志系统中。`error_log()` 函数常用于此目的。

   ```php
   error_log("An error occurred: Something went wrong.");
   ```

### 使用 Xdebug 进行交互式调试

[Xdebug](https://xdebug.org/) 是一个功能强大的 PHP 调试扩展，提供交互式调试功能。它可与 PhpStorm、Visual Studio Code 等流行的 IDE 集成。

要使用 Xdebug：

1. 使用适合您 PHP 设置的方法安装 Xdebug（例如 `pecl install xdebug` 或通过 Composer）。
2. 通过在 `php.ini` 文件中添加以下行来配置 PHP 设置以启用 Xdebug：

   ```ini
   zend_extension=xdebug.so
   xdebug.mode=debug
   ```

3. 设置您的 IDE 以监听 Xdebug 连接。
4. 通过在您想要开始调试的位置添加 `xdebug_break()` 函数来在代码中设置断点。

   ```php
   $value = 42;
   xdebug_break();
   ```

5. 在启用 Xdebug 的情况下触发您的 PHP 脚本。
6. IDE 将捕获断点，并允许您逐步执行代码、检查变量并查看调用堆栈。

### 调试工具

PHP 8 提供了各种用于调试的内置函数和工具：

* `error_log()`：将消息记录到 PHP 错误日志或自定义日志文件。
* `debug_backtrace()`：检索函数调用的回溯。
* `assert()`：提供一种测试断言的方式，如果断言失败则触发错误。
* `get_defined_vars()`：返回所有已定义变量的数组。

### 在 PHPStorm 中调试

如果您使用 PHPStorm 作为 IDE，它为 PHP 应用程序提供了强大的调试支持。要开始调试，请通过单击代码编辑器左侧边栏来设置断点。然后，以调试模式运行您的 PHP 脚本，PHPStorm 将自动捕获断点，允许您检查变量、计算表达式并逐步执行代码。

### 远程调试

PHP 还支持远程调试，这对于调试在远程服务器或容器上运行的应用程序非常有用。要启用远程调试，请相应地配置您的 PHP 设置和 IDE，并在它们之间建立连接。

在本节中，我们探讨了使用 `echo`、`var_dump()`、错误消息和日志记录的基础调试技术。此外，我们介绍了用于交互式调试的强大 Xdebug 扩展，并讨论了 PHP 8 中可用的调试工具和远程调试选项。调试是任何 PHP 开发人员的宝贵技能，掌握这些技术将帮助您高效地识别和解决应用程序中的问题。

## 第 11.4 节：PHP 8 的静态分析工具

PHP 的静态分析工具对于在无需运行时执行的情况下检测代码中的错误和潜在问题至关重要。在本节中，我们将探讨一些流行的静态分析工具，它们可以帮助您维护代码质量，并在 PHP 8 项目的早期发现 Bug。

### PHPStan

[PHPStan](https://phpstan.org/) 是一个强大的 PHP 静态分析工具，它检查代码的正确性、潜在 Bug 和不一致性。它采用类型推断、注解和规则相结合的方式来分析您的代码库。以下是开始使用 PHPStan 的方法：

1. 通过 Composer 全局安装 PHPStan：

   ```bash
   composer require --dev phpstan/phpstan
   ```

2. 在项目根目录下创建 `phpstan.neon` 配置文件：

   ```neon
   includes:
       - vendor/autoload.php

   parameters:
       level: 7
   ```

   调整 `level` 参数以指定所需的严格级别（1-8）。

3. 从项目根目录运行 PHPStan：

   ```bash
   vendor/bin/phpstan analyse
   ```

   PHPStan 将对您的代码执行静态分析，并报告发现的任何错误或警告。

### Psalm

[Psalm](https://psalm.dev/) 是另一个专为 PHP 设计的静态分析工具，专注于代码正确性和类型安全。它提供广泛的检查，可帮助您捕获与可空性、类型提示等相关的问题。以下是设置 Psalm 的方法：

1. 通过 Composer 全局安装 Psalm：

   ```bash
   composer require --dev vimeo/psalm
   ```

2. 初始化配置文件：

   ```bash
   vendor/bin/psalm --init
   ```

3. 运行 Psalm 分析您的代码：

   ```bash
   vendor/bin/psalm
   ```

   Psalm 将分析您的代码库，并就错误和潜在问题提供反馈。

### PHP CodeSniffer

PHP CodeSniffer 是一个专注于强制执行编码标准和风格指南的静态分析工具。它根据预定义规则检查您的代码并报告违规情况。使用 PHP CodeSniffer：

1. 通过 Composer 全局安装 PHP CodeSniffer：

   ```bash
   composer require --dev squizlabs/php_codesniffer
   ```

2. 在您的代码库上运行 PHP CodeSniffer：

   ```bash
   vendor/bin/phpcs
   ```

   PHP CodeSniffer 将识别代码中的编码标准违规情况。

### PHP Mess Detector (PHPMD)

[PHP Mess Detector (PHPMD)](https://phpmd.org/) 是一个静态分析工具，用于识别 PHP 代码中的“异味”或潜在问题。它检查与复杂性、命名约定等相关的问题。使用 PHPMD：

1. 通过 Composer 全局安装 PHPMD：

   ```bash
   composer require --dev phpmd/phpmd
   ```

2. 在您的代码上运行 PHPMD：

   ```bash
   vendor/bin/phpmd path/to/your/code text ruleset.xml
   ```

   将 `path/to/your/code` 替换为您要分析的目录。PHPMD 将生成一份报告，突出显示代码库中的问题。

### 静态分析的优势
