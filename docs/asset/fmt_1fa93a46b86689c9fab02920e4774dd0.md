
攻击者发送以下步骤：攻击者发送大量的`ICMP`包，通过任何不确定方法或通过僵尸发送到任何系统的端口。

损失响应包通过受害者的区域传输，而不是僵尸的区域。

### 最大攻击

这种攻击的目的是利用集中的、特定的显示能力来利用其他攻击者的资源。`TCP SYN`攻击是这种攻击的典型定义。各种显示攻击整合了`PUSH+ACK`攻击、授权服务器攻击和 CGI 应用攻击。

### 资源耗尽攻击

拒绝服务 DDoS 攻击旨在消耗防御者的系统资源，使合法客户端无法获得服务。

### B. 防御机制

为了防御 DDoS 攻击，研究人员已采取了不同的应对措施。

### 预防技术

下面列出最主要的预防和保护性措施：

- **入站过滤 (Ingress Filtering)** - 此协作停止具有虚假源地址的接入数据包。利用交换机来实现。该框架破坏了通过 IP 地址伪造进行的 DDoS 攻击。
- **出站过滤 (Egress Filtering)** - 在此策略中，利用出站通道。该系统允许那些仍然存在的具有巨大 IP 地址的数据包离开网络。
- **基于路由的分布式包过滤 (Route-Based Distributed Packet Filtering)** - 通道使用路由数据来引导伪造 IP 数据包并阻止攻击。同时也使用了 IP 回溯。然而，它需要关于组织地理位置的完整信息。
- **安全叠加网络服务 (Secure Overlay Services)** - SOS 计划具有传输功能，可以保护丢失的连接或特定系统。它假设接入的数据包如果是来自合法服务器，则应该是重要的。使用复制部分来验证允许进入叠加网络连接的真实客户端身份。

其他预期防御系统包括禁用未使用的组织、使用安全补丁、更改 IP 地址、禁用/启用 IP 传输、使用权重更改和蜜罐。尽管如此，缓解技术无法完全消除 DDoS 攻击带来的风险，但它们提供了基础或扩展的安全防护 [1]。

## DDoS 检测技术

### 异常检测

此 DDoS 识别系统通过观察连接或结构执行过程中的异常来识别攻击。这应该通过区分当前存在的特征与最近观察到的正常系统显示来实现。恶意侧在系统中直接被识别。很少有异常检测系统整合了以下：

> `NOMAD` - 一种灵活的连接查看框架，通过隔离 IP 数据包头部数据来识别连接异常。

> 带有拥塞的包采样和过滤技术 - 利用丢弃包子集进行了一种量化分析，当识别到异常时，会向切换发送信号以处理有害数据包。使用丢弃数据组子集进行了量化评估，当发现异常时，会向切换发送信号以处理有害或表现出异常的数据包。

> `D-WARD` - 在核心路由器处检测 DDoS 攻击。它防止攻击扩散到故障的邻居。它被部署在边缘交换机上，以识别接入和动态的连接流量。

> `MULTOPS26` - 这是一个构造的数据结构，其灵感来自区分 DDoS 攻击的证明。它处理假设参与 DDoS 攻击的连接 IP 区域可能是可能的，因此采取措施仅阻止/停止这些特定区域。它跟踪识别追寻攻击者的结构，或通过在攻击协调模式或故障组织模式下运行而遭受洪水的系统。一个交错树记录了在不同级别遇到的数据包速率。然而，它需要重新配置交换机并使用新的内存计划 [1]。

### i. 检测滥用

通过意识到信息集合中异常的特征或滥用实例，这是识别攻击的方法。当观察到这些模型中的任何一个时，DDoS 攻击就会被标记。

## 响应式检测

当检测到 DDoS 攻击时，后续措施应该是阻止攻击者，并追踪攻击者的系统机器以寻找攻击者的真实特征。这种方法通常需要二三天；它应该在随后实现，或者应该通过`ACL`实际实现。

有某些技术可以用于执行和追踪攻击者的特征，如表 3.1 所示。有许多策略可以用于阻止/防御 DDoS 攻击；遗憾的是，并不是每一个都能被识别和预防。最多能做到的是减少攻击的影响/打击 [1]。

### C. 配置 DDoS 执行

与其他类型的网络攻击不同，DDoS 攻击并不试图破坏你的安全防线。相反，DDoS 攻击意味着让你的网站和服务器对合法客户端不可用。DDoS 因此可以被用作其他恶意活动的干扰，并削弱安全机器，进入目标的安全防线。

一个令人信服的连接攻击本质上是一个影响整个网络客户端的事件。这使其成为黑客主义者、机械罪犯、恶棍和其他其他希望实现巨大目标或对特定说明产生影响的人的决策武器。

在预期和驱动 DDoS 攻击时，发生以下活动：

> **代理选择**：攻击者选择一个专家来执行攻击。这些机器应该处于攻击者可以用来获取访问的某种风险中。你需要大量的资源来执行可靠的攻击。从开始，该策略是手动执行的，但很快就使用查看工具实现了自动化。

> **入侵**：攻击者利用专家硬件的安全漏洞和缺陷并执行攻击代码。你还需要保护你的代码不被发现和禁用。诸如`Ramen worm` [14] 和`Code Red` [15] 等设计工具很快就陷入这种配置。专家系统的所有者和客户通常不知道他们的结构将受到损害并连接 DDoS 攻击。在调查 DDoS 攻击时，每个主程序只使用二三个资源（内存和数据传输），因此 PC 客户端的执行变化很小。

> **通信**：攻击者联系不同的主管，以弄明哪位专家正在运行、何时组织攻击，或者哪位专家正在进行中。取决于攻击者如何准备 DDoS 攻击的关联，专家可能被配置为与类似一个服务器的东西进行通信。攻击者与宿主机之间、以及宿主机与主节点之间的通信可以通过`TCP`、`UDP`或`ICMP`协议来实现。

> **攻击**：目前，攻击者命令它们发送攻击。受害者、攻击时间以及攻击的表达特征，如类型、长度、`TTL`、端口号。

> **带宽**：我们承认信息传输是准备 DDoS 攻击中不可或缺的一部分。如果你想获得更多信息移动限制，那么你对目标机器的攻击可能会导致失败并彻底终结。

关于 DDoS 攻击，有不同类型的攻击，每种攻击类型都有其独特的方式。由于每种攻击类型都有自己的功能，因此针对每种攻击类型都有相应的解决方案。在表 3.2 中，我们提到了 DDoS 攻击的名称、其功能以及防御该攻击的解决方案。

## D. DDoS 示例

各种类型的 DDoS 攻击针对联盟网络的不同部分。为了理解不同的 DDoS 攻击如何工作，了解联盟网络是如何构建的是必不可少的。

考虑到互联网的关联是使用各种组件或“层”产生的。就像规划一栋房子的上下结构一样，模型中的每一层都有相应的解释。下文显示的`OSI`模型是一个用于用 7 个显性层来描述网络的解析化结构。

虽然在每个真正重要的方面，所有 DDoS 攻击都汇于通过流量压垮目标设备或连接，但攻击可以归纳为三种策略。攻击者可以使用一个或多个不同的攻击向量，或者根据目标所采取的对策检查来循环使用攻击向量。

## 应用层攻击

### 攻击目标

有时，这被称为第 7 层 DDoS 攻击（根据`OSI`模型的第七层），这些攻击的目标是耗尽目标的资源以实现组织的拒绝服务。攻击基于在服务器上创建页面并考虑到`HTTP`请求进行传输的层级。单个`HTTP`请求在客户端执行的计算成本很低，但对于目标服务器来说，回答是非常贵的，因为服务器通常会堆栈各种记录并运行信息文件请求来创建一个网站。

第 7 层攻击试图受到保护，因为从合法流量中隔离出恶意流量是困难的。

### 应用层攻击示例：HTTP 洪水攻击

这种攻击就像在大量电脑上立即反复点击 Web 程序的刷新按钮——海量的`HTTP`请求淹没服务器，实现拒绝服务。这种攻击从简单到复杂不等。

更简单的执行可以通过对`IP`区域、引用者和客户端专家进行近似程度的搜索来访问一个 URL。复杂的设计可以利用搜索`IP`区域的大量地址，并利用具有冲突的引用者和客户端专业人员针对不规则的 URL。

## 协议攻击

### 攻击目标

显示攻击，通常被称为状态耗尽攻击，通过过度消耗服务器资源以及带有防火墙和负载均衡器的联盟设备资源，导致帮助服务中断的影响。显示攻击利用显示栈中第 3 层和第 4 层的漏洞来实现所阻止的目标。

### 协议攻击示例：SYN 洪水攻击

`SYN Flood`类似于一个休息室的接待员从店门口接收请求。接待员收到通知，继续获取包，并等待确认以带入包。接待员随后获取更多的请求，直到他们无法交付更多包，变得过载且请求无响应。

这种攻击利用`TCP`握手——两台电脑建立关联连接的社会事件——通过使用伪造源`IP 地址`发送目标无限多个`TCP "起始连接请求" SYN 包`。

目标机器回答每个关联并因此等待握手的最后进展，而该进展从未发生，在此期间破坏了目标的资源。

## 流量型攻击

### 攻击目标

此类攻击试图通过消耗目标与更大的互联网之间所有可用的数据传输来制造阻塞。通过使用某种放大或其他产生巨大流量的技术，向目标交付大量数据，例如来自僵尸网络的请求。

## E. DDoS 攻击案例

### 2020 年 AWS 攻击

这是有史以来最持续的 DDoS 攻击，它针对一个未定义的 AWS 客户端，该客户端利用了一种名为无连接轻量级目录访问协议（CLDAP）的反射。这种程序依赖于脆弱的外部 CLDAP 服务器，并将从伪造 IP 地址传输的信息增加了 56 倍。该攻击持续了三天，峰值达到了惊人的每秒 2.3 TB。

### 为什么 AWS 攻击至关重要

虽然 AWS DDoS 攻击实现的阻断效果确实没有想象中那么严重，但攻击的巨大规模以及对 AWS 与客户可能导致收入损失和声誉受损的影响是巨大的。

### 2014 年 CLOUDFLARE DDoS 攻击

2014 年，基于 Web 的安全提供商和内容优化连接服务 CloudFlare 遭受了一场流量约为每秒 400 Gbps 的 DDoS 攻击。该攻击由单一 CloudFlare 客户端发起并部署在欧洲的服务器上，通过利用网络时间协议（NTP）显示的漏洞来实现，该协议用于确保电脑时钟准确。尽管攻击仅针对 CloudFlare 的其中一个客户端，但对于 CloudFlare 自身的整个联盟来说，这具有重大的意义。

### 为什么 CloudFlare 攻击至关重要？

这种攻击采用了一种策略，即攻击者利用伪造源区域向攻击目标服务器发送伪造的 NTP 服务器响应。这种攻击被称为“反射攻击”，因为攻击者可以“跳过”来自 NTP 服务器的伪造声明，同时隐藏自己的区域。由于 NTP 协议缺乏某种机制，攻击的某些部分可以真实地放大数倍，这使得 NTP 服务器成为一种极其强大的 DDoS 工具。攻击发生不久后，美国计算机应急准备小组将 NTP 放大攻击描述为“特别难以防御”，因为“响应是来自真实服务器的真实信息”。

### 2012 年六大银行的 DDoS 攻击

2012 年 3 月 12 日，六家美国银行遭到了 DDoS 攻击的洪水洗击：美国银行、摩根大通银行、美国银行、花旗银行、富国银行和 PNC 银行。这些攻击是由一个名为 Brobot 的僵尸网络中的许多 get 服务器实施的，每次攻击产生的 DDoS 流量每秒超过 60 GB。

那时，这些攻击在持续性上令人惊叹。相关的社会团体并没有尝试执行一次攻击后撤退，而是使用大量的攻击策略对目标进行轰击，以寻找可行的方法。这样，无论银行被要求应对何种类型的 DDoS 攻击，它们都会受到各种类型攻击的影响。

### 为什么六大银行攻击至关重要

2012 年银行攻击最重要的一点是，攻击据测是由加沙阿尔-卡萨姆旅团（巴勒斯坦哈马斯组织的主要支柱）实施的。同样，这些攻击严重影响了受影响银行，导致了赔偿、援助成本、客户信任问题以及银行的信誉形象。

## 3.4 DDoS 缓解

缓解意味着在合理的预期范围内尽可能减少受攻击机器的损害。完全预期 DDoS 攻击是不可能的。它应该被减少到某种程度。

### A. DDoS 缓解技术

干扰防御强度评估表明，完全停止或阻止 DDoS 攻击是不可能的，重点在于尽可能在预期范围内减少攻击的影响，并增强组织的韧性。干扰防御可以分为两类：针对非基础故障的容错和服务质量（QoS）。

### 容错性

一种大型评估办公室，其设计集成在基础设施中并在三个级别运行：设备、软件和结构 [18]。容错的意义在于，通过复制连接优势并隔离其通道，当流量导致单个交互中心故障时，连接可以继续提供此类服务。

### 服务质量 (QOS)

QoS 描述了网络为特定类型的应用程序或流量传输明确结果的能力。已经开发了不同的 QoS 块结构和 QoS 系统来减少 DDoS 攻击。

在集成式服务（IntServ）和区分服务（DiffServ）之外的 QoS 框架已成为关键方案 [19]。IntServ 使用资源预留协议（RSVP）协调流量流中的资源任务。DiffServ 是一种根据需求限制的结构。DiffServ [20, 21] 使用 IP 区域的服务类型（TOS）标记位，并考虑每个数据包的 TOS。

### 队列技术

队列技术是用于对抗 DDoS 攻击的其他方法。目前有多种类型正在开发中。一种旧且通用的队列技术是基于类的队列（CBQ） [22]。

### 资源定价

这是 Mankins *et al.* 提出的另一种减少 DDoS 攻击的策略。Mankins *et al.* [23] 注意到，DDoS 攻击是有效的，因为成本固地落在服务器上，而在攻击期间，攻击流量处于与真实流量极其模糊的中心水平。他们建议开发一种分布式分段框架，在连接、服务器和数据资源上设置不同的速率，以根据费用以及数学权重降低完成服务请求的实际成本。

通过使用不同的费用和购买限制，属性可以提供服务质量，并选择客户最有效的行为方式和处理异常行为的方式。关键是将基本技术与理想客户分离，并驱逐导致服务器负载的客户端。该程序的最终结果是，攻击者可以以极廉的成本通过虚假应用程序淹没系统，从而增加有效用户的数量。

### 推回架构

当目标是让驱动程序感知进度或停止恶意（充满）流量时，推回设计是一种减少速率非常有前景的技术。在基于聚合的拥塞控制（ACC） [17] 中，速率被描述为包含材料的小型集合 [24]。因此，[17] 推回守护进程使用独特的确认计算来检查攻击迹象。该系统的部分可以扩展，且不需要上游领导节点。显然，对于速率限制器和一个可以检查滑动结果线的推回守护进程有巨大且有限的需求。

### 反向 Web 代理

中间服务器是一种主机服务器，它利用资源帮助客户端从一个服务器获取。这些资源随后被返回给客户端，是在真实服务器还是原始服务器上。转换主从互联网获取请求并将其移动到内部联盟内的服务器。客户端与专家协作，可能不知道内部联盟。反向代理可以隐藏真实服务器的存在和性质 [16]。

负载均衡应用程序中有几个组件可以保护你免受典型的网络攻击。如果没有经过训练的反向专业人员，通常很难杀灭恶意软件或开始规模缩减。一个溯源中间服务器可以堆叠移动到跨越不同服务器的请求上，每个服务器都运行着自己的应用程序空间。由于它从相邻的 Web 服务器获取中介，该溯源中间件可能需要更改每个传入请求的 URL，以匹配其所引资源的内部区域。提取专家可以通过放置独特的静态内容（通常称为 Web 加速 26）来减轻根服务器的压力。

## 防火墙 (FIREWALL)

防火墙是用于阻断不可信网络的关键设备。通常，拒绝服务（DoS）的主要攻击手段是针对这些设备的彻底防护。

普通的防火墙（包过滤、应用层或状态检测防火墙）实际上会查看数据包报头，以检查是否存在许可从一个源起始并传输到后续的流量。阻止尝试向未经批准的源或目标区域发送数据。防火墙可以识别是否建立了一个网络对端（客户端和服务器）正尝试扩展会话（连接）。

这些信息在网络表中处理，为了筛选通信，即使是不完善的连接也应该保留在网络表中，因为对于防火墙决定是否有继续跟踪数据包至关重要。在任何情况下，操作风险的可能性都会危及防火墙 27。
