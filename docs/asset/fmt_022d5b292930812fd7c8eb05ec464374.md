
上下文向量被传递给解码器 RNN，后者输出预测序列，即 $\widehat{\mathbf{y}}_{n}$，$n = 1, 2, \dots, N^{\prime}$。注意，通常解码器端的输出序列长度 $N^{\prime}$ 与编码器端的输入序列长度 $N$ 是不同的。编码器-解码器网络的训练目标是使解码器充当*预测器*。换句话说，解码器被训练为在第 $n$ 个阶段预测对应的目标词（$\mathbf{y}[n]$），即输出 $\widehat{\mathbf{y}}_{n}$，给定的条件是输入编码（即 $\mathbf{c}[n]$）以及之前的目标词（即 $\mathbf{y}[1], \mathbf{y}[2], \dots, \mathbf{y}[n - 1]$）。关于翻译任务背景下 RNN 网络的详细描述，可从本书网站“附加材料”部分下载，该部分与当前章节相关。

使用 RNN 编码器，上下文相关信息通过两种机制揭示。一种是通过隐藏状态。然而，回顾一下，状态是按顺序处理的。因此，消除词义歧义（例如 "bank"）必须延迟到最后一个词 "river"（或 "road"）被处理之后。第二种机制是应用注意力机制，旨在通过为按顺序形成的状态分配权重来提取更多信息。这些权重经过训练，用于量化解码器状态向量与编码器状态向量之间的*相似性*（更多细节请参阅本书网站的附加材料）。此外，该信息必须与解码器中按顺序形成的状态进行*对齐*。只要短语足够短，RNN 就能工作良好。

然而，当考虑长短语时，问题就会出现。例如，在 NLP 任务中，涉及一组多个相关短语的情况非常普遍。这些短语在*上下文*上相关，并且依次一个接一个地馈送给编码器的输入。正如第 18.13.1 节所讨论的，对于此类长序列，RNN 面临着梯度消失现象的严重挑战。

除了上述缺点之外，仔细审视典型 RNN 演化所依赖的状态概念，要求网络用单个向量状态编码整个历史可能要求过高！事实上，注意力机制的使用试图通过状态向量的加权组合，以互补的方式利用系统的记忆。此外，通过这种加权，可以建模*依赖关系*，而不受输入或输出序列中距离的限制。

除了前面的缺点之外，还存在计算问题。正如第 18.13 节所讨论的，典型 RNN 的循环/顺序特性给相关计算的并行化带来了严重障碍。

在一篇开创性论文 \[189\] 中，作者提出了废除循环、仅保留注意力机制以计算输入和输出表示的想法。正如他们在论文标题中所言：“Attention is all you need（注意力就是你所需要的一切）。”

### 19.3.3 Transformer 网络

一个（完整的）Transformer 网络由两部分组成，即编码器和解码器。对应的框图如图 19.9 所示。编码器和解码器均由结构相同的模块堆叠而成。通常情况下，编码器中涉及的模块数量（设为 `L`）可能与解码器中的模块数量（设为 `L'`）不同。一如既往，编码器的作用是输出其输入序列的信息丰富的表示/编码。然后，如图所示，该信息被传递给解码器模块。在继续详细描述编码器和解码器模块之前，让我们先对编码器和解码器中的输入和输出序列做一些评论。

![Figure 19.9 A (full) transformer consists of two parts: the encoder and the decoder. The input to the encoder consists of the tokens/embeddings of the input phrase. The information-rich outputs of the encoder are passed on to the decoder. During training, the input to the decoder is the target output associated with the input to the encoder. For example, in a translation task, the decoder is fed with the sequence of tokens associated with the translation of the input phrase. The decoder outputs vectors of probabilities. Both the encoder and the decoder comprise a stack of building blocks.](img/gr009.jpg)

图 19.9 一个（完整的）Transformer 由两部分组成：编码器和解码器。编码器的输入由输入短语的 token/嵌入组成。编码器的信息丰富的输出被传递给解码器。在训练期间，解码器的输入是与编码器输入相关联的目标输出。例如，在翻译任务中，解码器被馈送与输入短语翻译相关联的 token 序列。解码器输出概率向量。编码器和解码器均由构建模块堆叠而成。

在第 19.3.1 节中，我们讨论了用向量表示单词的第一步是为词汇表中的每个单词分配一个 ID 编号，然后采用 `l` 维独热向量编码，其中 `l` 是语言语料库词汇表的大小。随后，通过所谓的嵌入矩阵，将这些向量中的每一个投影到一个合适维度的低维空间，设为 `d[m]`。我们将生成的向量称为嵌入向量、token 或简称嵌入。我们稍后将讨论嵌入在 Transformer 上下文中是如何实现的。

请注意，在图 19.9 中，解码器顶层模块（模块 #`L'`）的输出首先经过线性变换，然后通过 softmax 非线性函数。线性变换的目的是将解码器顶层模块的输出向量（维度为 `d[m]`）投影回词汇维度 `l`，而 softmax 非线性函数的目标是归一化生成的 `l` 维向量的元素值，以便将其解释为概率。换句话说，解码器中输出向量的元素对应于概率。这些概率的性质以及如何利用它们做出决策将在稍后解释。

### 19.3.4 编码器：输入序列

在基于 RNN 的编码器中，输入是按顺序逐个 Token 提供的。相比之下，在 Transformer 的编码器中，构成输入序列的所有 Token 会同时呈现。让我们专注于一个将法语短语“Je suis étudiant”翻译成英语（即“I am a student”）的简单示例。那么，编码器的输入将是 `⟨SOS⟩, x[1], x[2], x[3], ⟨EOS⟩`，其中 `⟨SOS⟩` 和 `⟨EOS⟩` 是分别指示序列开始和结束的特殊 Token（另见第 19.3.1 节）。在目前的讨论中，我们假设 `x[1] (→ Je)`、`x[2] (→ suis)`、`x[3] (→ étudiant)` 是将原始独热向量嵌入到维度为 `d[m]` 的低维空间后得到的向量，即 `x[n] ∈ ℝ^(d[m]), n = 1, 2, …, N`，其中 `N` 是输入序列的长度，在本例中 `N = 3`。按照惯例，除非另有说明，我们将 `⟨SOS⟩` 的嵌入表示为 `x[0]`，将 `⟨EOS⟩` 的嵌入表示为 `x[N + 1]`。符号 `d[m]` 保留用于表示嵌入空间的维度，下标“m”用于提醒我们单词“model”。这是因为通过编码器和解码器不同模块传播的所有向量/Token/嵌入都具有相同的维度，即 `d[m]`，这是一个用户定义的模型参数。

然而，嵌入的选择需要特别注意。请注意，由于输入序列作为一个整体出现在 Transformer 的输入端，而不是按顺序出现，因此需要协助网络并提供关于每个单词/Token 相对于其他单词/Token 的位置的额外信息。换句话说，提供指示哪个 Token 是第一个、哪个是第二个等的信息。我们将此过程称为*位置嵌入*。

将原始词汇表单词嵌入到输入 Token 涉及两个步骤：

*   **词汇表单词嵌入**：为了满足我们当前的符号需求，让我们用 `x[n]^(oh) ∈ ℝ^(l)` 表示对输入单词序列进行分词后得到的独热向量。^[137]

    `x[n]' ∈ ℝ^(d[m]) = E x[n]^(oh), n = 0, 1, …, N + 1`

#### 嵌入矩阵与位置编码

*   其中 *E* 是相应维度的嵌入矩阵。该矩阵的元素在训练过程中被**学习**。嵌入空间的维度 *d*[*m*] 是预先选定的。例如，在文献 [189] 中，*d*[*m*] = 512。

*   **位置嵌入**：多年来提出了各种技术。在原始论文 [189] 中，使用了正弦位置编码。

*   对于输入短语中第 *k* 个位置的 token，以及相应向量/token 的每个向量维度 *i*，采用以下公式：

```
PE_{(k,2i)} = sin( k / b^{(2i/d_m)} ),
```

(19.28)

```
PE_{(k,2i + 1)} = cos( k / b^{(2i/d_m)} ),
```

(19.29)

*   其中 `i = 0, 1, ..., d_m/2 - 1`，为简单起见，我们假设 `d_m` 为偶数。在文献 [189] 中，`b = 10000`。因此，对于每个位置 *k*，向量的偶数维度按正弦函数编码，奇数维度按余弦函数编码，所有位置均从 `k = 0` 开始计数。因此，位置嵌入取决于两个索引，等价地定义了一个矩阵。

| `k = 0` | `k = 1` | `k = 2` |

嵌入矩阵变为

$$\\text{PE} = \\begin{bmatrix} {0} & {1} & {0} & 1 \\\\ {0.84} & {0.54} & {0.1} & 1 \\\\ {0.91} & {- 0.42} & {0.2} & 0.98 \\\\ \\end{bmatrix}.$$

人们可能会疑惑，为什么不直接使用位置索引 `k` 作为位置嵌入。在实践中，然而，这个数字可能变得相当大，并会导致序列末尾的 Token 产生巨大的偏差。另一方面，在范围 $[0, 1]$ 内进行直接归一化，当涉及变长序列时可能会导致问题，特别是当它们被归一化在同一个值区间内时。毫无疑问，多年来针对公式 (19.28) 和 (19.29) 的替代方案已被提出，包括可学习的方案，它们在训练过程中学习，参见文献 [57]、[114]。在文献 [176] 中，提出了*旋转位置嵌入*（RoPE），它通过一个包含 Token 间相对位置依赖的旋转矩阵来编码位置信息。事实证明，RoPE 具有一些理想的特性，例如相对于序列长度的灵活性，以及随着相对距离增加而衰减的 Token 间依赖性。

对于每个 Token，提供给 Transformer 编码器第一个块作为输入的最终嵌入向量，计算为以下求和形式：

$$

$$

### 19.3.5 编码器：自注意力

图 19.10 展示了编码器块的结构。我们重点关注第一个块，它接受输入嵌入作为输入，即 $\\mathbf{x}[0], \\mathbf{x}[1], \\dots, \\mathbf{x}[N+1]$。

![Figure 19.10 Each block of the encoder consists of four layers. The outputs of each layer become the inputs to the layer above. The outputs of each block are provided as inputs to the block above. The normalization layers are implemented as residual networks, which justifies the “add” operation, as it is explained in the text.](img/gr010.jpg)

**图 19.10** 编码器的每个块由四层组成。每层的输出成为上一层的输入。每个块的输出被作为上一个块的输入。归一化层作为残差网络实现，这解释了文中提到的“加法”操作。

编码器的其他块具有完全相同的结构，唯一的区别在于各自的输入是下方块的输出。每个块包含四层。图 19.10 中的第一层是所谓的*自注意力*层，它是 Transformer 网络构建所依赖的主要突破性思想。

#### 自注意力层原理

自注意力层的主要原理是应用一种注意力机制，该机制*关联*输入序列的不同标记/位置，以生成相应的信息丰富的上下文表示。正如我们在第 19.3.2 节、公式 (19.27) 中所见，关联两个实体/向量的注意力系数是它们相互*相似度*的函数。在那里，两个向量之间的相似度度量用它们*内积*的函数来表示。原则上，可以使用任何其他相似度度量。在 Transformer 框架中，采用了一种更精细的相似度测量过程。为此，针对每个标记 **x**[*n*]，*n* = 0, 1, …, *N* + 1，首先形成三个辅助向量。

##### 查询向量

*   **查询向量**：这些向量通过将输入嵌入投影到一个新的子空间来定义，即

```
**q**[*n*]^(*T*) := **x**[*n*]^(*T*) *W*^(*q*), *W*^(*q*) ∈ ℝ^(*d*[*m*] × *d*[*k*]), **q**[*n*] ∈ ℝ^(*d*[*k*])
```

其中维度 *d*[*k*] 是用户定义的参数。

##### 键向量

*   **键向量**：这些向量也是投影到一个 *d*[*k*]-维子空间中，即

```
**k**[*n*]^(*T*) := **x**[*n*]^(*T*) *W*^(*k*), *W*^(*k*) ∈ ℝ^(*d*[*m*] × *d*[*k*]), **k**[*n*] ∈ ℝ^(*d*[*k*])
```

##### 值向量

*   **值向量**：这些向量是投影到另一个 *d*[*v*]-维子空间中，即

```
**v**[*n*]^(*T*) := **x**[*n*]^(*T*) *W*^(*v*), *W*^(*v*) ∈ ℝ^(*d*[*m*] × *d*[*v*]), **v**[*n*] ∈ ℝ^(*d*[*v*])
```

其中，*d*[*v*] 也是用户定义的参数。

在实践中，`d[k]`和`d[v]`都被选择为小于`d[m]`，特别是`d[m]`的因子。例如在文献[189]中，`d[m] = 512`且`d[k] = d[v] = 64`。矩阵`W^(q)`、`W^(k)`、`W^(v)`在训练过程中学习得到。为了计算两个嵌入向量（如`x[i]`、`x[j]`）之间的相似性，首先计算相应的查询向量和键向量。基于获得的相似性，针对每个涉及的输入向量嵌入，通过生成的值向量计算一个“更新后的表示”。此过程包含以下步骤：
