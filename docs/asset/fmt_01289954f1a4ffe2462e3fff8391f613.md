
`范围指标` 描述了该漏洞是否会影响漏洞范围之外的系统组件。范围指标根据 表 5.8 中的标准进行分配。请注意，范围指标表不包含分数信息。范围指标的值反映在较早前 表 5.3 所示的所需权限指标的值中。

**表 5.8** CVSS 范围指标

| 值 | 描述 |
| --- | --- |
| 未改变 (U) | 被利用的漏洞只能影响由同一安全机构管理的资源。 |
| 已改变 (C) | 被利用的漏洞可影响管理包含该漏洞组件的安全机构范围之外的资源。 |

### 解读 CVSS 向量

`CVSS 向量` 使用单行格式来传达漏洞在前几节所述所有六个指标上的评级。例如，回顾 图 5.12 中呈现的漏洞的 CVSS 向量：

```
CVSS:3.0/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N
```

该向量包含九个组件。第一部分“CVSS:3.0”仅告知读者（人或系统）该向量是使用 CVSS 3.0 版本编写的。接下来的八个部分对应八个 CVSS 指标中的每一个。在本例中，图 5.1 中的 SSL 漏洞获得了以下评级：

*   攻击向量：网络（分数：0.85）
*   攻击复杂性：低（分数：0.77）
*   所需权限：无（分数：0.85）
*   用户交互：无（分数：0.85）
*   范围：未改变
*   机密性：高（分数：0.56）
*   完整性：无（分数：0.00）
*   可用性：无（分数：0.00）

### CVSS 分数汇总

`CVSS 向量` 提供了关于漏洞所构成风险性质的详细信息，但向量的复杂性使其难以用于优先级排序练习。因此，分析师可以计算 `CVSS 基础分`，这是一个代表漏洞总体风险的单一数字。得出基础分需要首先计算其他一些 CVSS 组件分数。

#### 计算影响子分数 (ISS)

分析师执行的第一项计算是计算影响子分数 (ISS)。该指标使用以下公式汇总三个影响指标：

```
ISS = 1 - [(1 - Confidentiality) × (1 - Integrity) × (1 - Availability)]
```

代入我们的 SSL 漏洞的值，得到

```
ISS = 1 - [(1 - 0.56) × (1 - 0.00) × (1 - 0.00)]
ISS = 1 - [0.44 × 1.00 × 1.00]
ISS = 1 - 0.44
ISS = 0.56
```

#### 计算影响分数

要从影响子分数获得影响分数，必须考虑范围指标的值。如果范围指标为未改变（如本例所示），我们将 ISS 乘以 6.42：

```
Impact = 6.42 × ISS
Impact = 6.42 × 0.56
Impact = 3.60
```

如果范围指标为已改变，我们使用一个更复杂的公式：

```
Impact = 7.52 × (ISS - 0.029) - 3.25 × (ISS - 0.02)^15
```

#### 计算可利用性分数

分析师可以使用以下公式计算漏洞的可利用性评分：

```
Exploitability = 8.22 × AttackVector × AttackComplexity × PrivilegesRequired × UserInteraction
```

代入我们的 SSL 漏洞的值，我们得到：

```
Exploitability = 8.22 × 0.85 × 0.77 × 0.85 × 0.85
Exploitability = 3.89
```

### 计算基础评分

掌握所有这些信息后，我们现在可以使用以下规则确定 CVSS 基础评分：

*   如果影响评分为 0，则基础评分为 0。
*   如果范围指标为 `Unchanged`，则通过将影响评分和可利用性评分相加来计算基础评分。
*   如果范围指标为 `Changed`，则通过将影响评分和可利用性评分相加，并将结果乘以 1.08 来计算基础评分。
*   最高可能的基础评分为 10。如果计算值大于 10，则将基础评分设置为 10。

在我们的示例中，影响评分为 3.60，可利用性评分四舍五入为 3.9。将它们相加，我们得到基础评分 7.5，这与 Figure 5.12 中找到的值相同。

### CVSS 基础评分分类

许多漏洞扫描系统通过使用风险类别而非数字风险评级来进一步总结 CVSS 结果。这些通常基于 CVSS 定性严重程度评级标准，如 Table 5.9 所示。

**TABLE 5.9** CVSS 定性严重程度评级标准

| CVSS 评分 | 评级 |
| --- | --- |
| 0.0 | None |
| 0.1-3.9 | Low |
| 4.0-6.9 | Medium |
| 7.0-8.9 | High |
| 9.0-10.0 | Critical |

继续以 Figure 5.12 中的 SSL 漏洞示例为例，我们计算出该漏洞的 CVSS 评分为 7.5。这将其归入 High 风险类别，如 Figure 5.12 标题所示。

## 验证扫描结果

解读报告的网络安全分析师通常会进行自己的调查，以确认漏洞的存在和严重程度。这些调查可能包括使用提供额外信息的外部数据源，这些信息对分析很有价值。

### 误报

漏洞扫描器是有用的工具，但它们并非万无一失。扫描器有时会由于各种原因出错。扫描器可能没有足够的访问权限来确认目标系统上的漏洞，或者它可能只是插件中存在错误，从而生成错误的漏洞报告。当扫描器报告一个不存在的漏洞时，这被称为 `false positive error`（误报错误）。

当漏洞扫描器报告一个漏洞时，这被称为 `positive report`（阳性报告）。该报告可能是准确的（`true positive` 报告）或不准确的（`false positive` 报告）。同样，当扫描器报告不存在漏洞时，这是一个 `negative report`（阴性报告）。阴性报告可能是准确的（`true negative` 报告）或不准确的（`false negative` 报告）。

网络安全分析师应确认扫描器报告的每个漏洞。在某些情况下，这可能只是验证补丁缺失或操作系统过时那么简单。在其他情况下，验证漏洞需要复杂的手动过程来模拟攻击。例如，验证 SQL 注入漏洞可能需要实际尝试针对 Web 应用程序的攻击，并在后端数据库中验证结果。

验证漏洞时，分析师应利用自己的专业知识以及组织内其他人的主题专业知识。数据库管理员、系统工程师、网络技术员、软件开发人员和其他专家拥有对评估潜在误报报告至关重要的领域知识。

### 将扫描结果与其他数据源协调

漏洞扫描绝不应在真空环境中进行。解读这些报告的网络安全分析师在执行分析时还应求助于其他安全信息来源。此过程的宝贵信息来源包括：

*   来自服务器、应用程序、网络设备和其他来源的 `Log reviews`（日志审查），这些来源可能包含关于试图利用检测到的漏洞的信息
*   `Security information and event management (SIEM)`（安全信息和事件管理）系统，它们关联来自多个来源的日志条目并提供可操作的情报
*   `Configuration management systems`（配置管理系统），它们提供有关系统上安装的操作系统和应用程序的信息

当分析师尝试将扫描报告与组织计算环境的现实相协调时，这些信息来源中的每一个都可能证明是无价的。

# 安全漏洞

每个漏洞扫描系统都包含能够检测数千种可能漏洞的插件，范围从 Web 应用程序中的主要 SQL 注入缺陷到网络设备中更平常的信息泄露问题。虽然不可能在任何长度的书中讨论每一个漏洞，但网络安全分析师应该熟悉最常见的检测到的漏洞以及涵盖许多不同漏洞变体的一些通用类别。

## 补丁管理

向系统应用安全补丁应该是任何信息安全计划的核心实践之一，但由于缺乏预防性维护资源，这项例行任务经常被忽视。漏洞扫描中最常见的警报之一是网络上的一个或多个系统正在运行过时版本的操作系统或应用程序，并需要安全补丁。

Figure 5.13 显示了这些扫描结果的一个示例。位于 `10.64.142.211` 的服务器存在远程代码执行漏洞。虽然扫描结果相当简短，但它确实包含相当多的有用信息。

幸运的是，有一个简单的方法可以解决这个问题。Solution 部分告诉我们，Microsoft 为受影响的操作系统发布了补丁，See Also 部分提供了指向 Microsoft 安全公告（`MS15-034`）的直接链接，该公告更详细地描述了问题和解决方案。

Figure 5.13 中显示的漏洞突显了运行 `patch management`（补丁管理）计划的重要性，该计划例行修补安全问题。Figure 5.13 中显示的问题暴露了操作系统层面不当或薄弱的补丁管理，但这些弱点也可能存在于应用程序和固件中。

## 遗留平台

### 软件生命周期结束

软件供应商最终会停止对其生产的每一款产品提供支持。操作系统和应用程序均不例外。一旦供应商宣布某产品最终停止支持，继续运行该过时软件的组织将面临重大的攻击风险。供应商将不再调查或修复该日期后出现的产品安全缺陷。从安全角度来看，继续运行不受支持产品的组织将独自面对风险，除非你碰巧维护着一支操作系统开发团队，否则这绝不是一个好局面。

也许最著名的主要操作系统停止支持事件发生在 2015 年 7 月，当时微软停止了对使用了十多年的 Windows Server 2003 的支持。图 5.14 展示了 Nessus 在识别出运行此过时操作系统的服务器时生成的报告示例。

从该报告中我们可以看到，扫描检测到网络上有两台服务器运行着 Windows Server 2003。漏洞描述对继续运行任何不受支持操作系统的组织将面临的局势给出了严峻的评估：

> 缺乏支持意味着供应商将不再为该产品发布新的安全补丁。因此，它很可能包含安全漏洞。此外，微软不太可能调查或确认漏洞报告。
