
数据包分析的焦点是所研究数据包的内容，而协议分析处理的是数据包符合其本应实现的协议的方式。例如，互联网控制消息协议（ICMP）允许回显请求包和回显应答包具有负载，只要数据包总长度不超过网络最大传输单元（MTU）。此功能旨在支持诊断消息，尽管在实践中这几乎从未见过。然而，我们确实看到的是威胁者利用该协议建立 ICMP 隧道，两个主机使用回显请求和应答包创建一个秘密的通信通道。对 ICMP 进行分析将揭示这些通道。

协议分析的另一个应用是确定给定协议的安全性，或者相反，确定其漏洞。假设你购买或开发了一个部署在你的组织系统中的应用程序。除非你对其协议在网络上的具体表达方式有清晰的了解，否则你如何知道它会引入哪些风险？执行协议分析可以简单到嗅探网络流量以确保所有流量都加密，也可以复杂到使用数学模型和仿真来量化意外影响的概率。

## NetFlow 分析

NetFlow 是由 Cisco 在 20 世纪 90 年代作为数据包交换技术开发的系统。尽管它担任该角色的时间并不长，但它被重新用于提供网络流量统计信息，这就是为什么它对今天的分析师来说非常重要。它的工作原理是将所有具有以下特征的数据包分组为“流”：

- 网络设备（例如交换机或路由器）的到达接口
- 源和目的 IP 地址
- 源和目的端口号（如果不是 TCP 或 UDP，则值为零）
- IP 协议
- IP 服务类型

当数据包到达启用 NetFlow 的网络设备且它不属于任何已知流时，设备将为它创建一个新流并开始跟踪任何其他相关数据包。当流在预设时间内没有更多数据包后，该流被认为已结束。启用 NetFlow 的设备将聚合有关该流的统计信息，例如持续时间、数据包数量和字节数，然后导出记录。NetFlow 收集器将接收数据，在必要时进行清理，并存储。系统的最后一个组件是分析控制台，它允许分析师检查数据将其转换为可操作的信息。

注意，流数据只有在流结束*后*才可用于分析。这意味着这种分析更适用于取证调查，而不是对攻击的实时缓解。此外，NetFlow 捕获的是聚合统计数据，而不是数据包的详细信息。这种分析在调查的早期阶段很有帮助，可以引导分析师指向应详细分析特定数据包（假设组织也在进行数据包捕获）。

## 无线分析

在不考虑无线网络影响的情况下，很难运行任何类型的企业网络。即使你不在建筑内完全不允许任何无线设备（甚至是手机），你又如何知道所有员工一直遵守该政策呢？诚然，大多数组织不会（通常也无法）实施此类严厉的措施，这使得无线局域网（WLAN）审计和分析变得尤为重要。

要进行 WLAN 分析，必须首先捕获数据。通常，当 WLAN 接口卡连接到无线接入点（WAP）时，客户端设备处于管理模式（managed mode），而 WAP 处于主模式（master mode）。主模式（也称为 `infrastructure` 模式）意味着接口将负责管理 WLAN 配置的所有方面（如通道和 SSID）。处于管理模式的客户端由主机管理，因此在收到指令时会更改信道或其他设置。无线接口还可以在网格模式（mesh mode）下直接通信，允许接口与另一个接口直接进行协商，这种关系不分主节点和从属节点（也称为 `ad hoc` 模式）。在上述三种模式中，接口都被限制为连接到一个网络。为了同时监控多个网络，我们需要第四种工作模式。在监控模式（monitor mode）下，无线接口将看到所有可用的 WLAN 及其特征，无需连接到任何一个。这是我们进行 WLAN 审计时需要的模式。幸运的是，`Kismet` 等 WLAN 分析器会处理这些细节，让我们只需运行应用程序并查看外部环境即可。

对 WLAN 进行安全分析最重要的一步是了解你的设备。其中最重要的是 WAP，但跟踪无线客户端同样重要。你如何知道发生了异常情况呢？简单来说，就是跟踪“正常”情况是什么样的。在分析 WLAN 结构时，你必须从已知的良好的接入点和客户端设备列表开始。推测，你的组织安装了（或让别人安装了）所有的 WAP，你应该有一份它们设置的记录（例如协议、通道和位置）以及它们的介质访问控制（`MAC`）地址和 IP 地址。当你进行定期审计时，将能够判断扫描结果中是否出现了新的 WAP，这可能预示着存在非法接入点（rogue access point）。

寻找非法或未经授权的客户端要棘手一些，因为在许多网络设备上更改 `MAC` 地址并不困难。事实上，所有主流操作系统都内置了工具，允许你执行此操作。由于终端设备身份的主要指标非常容易被伪造，除非实施某种形式的认证（例如实施 `WPA Enterprise` 和 `IEEE 802.1x`），否则你可能无法检测到未经授权的节点。如果没有认证，你将很难识别连接到你 WLAN 的最幼稚入侵者以外的所有人员。

### 关联分析

现在，你已经对网络进行了侦察，并在过程中收集了大量数据。此时，你可能拥有数据包捕获文件、`NetFlows` 以及来自防火墙、`IDS` 和系统事件的日志文件。从何处开始？关于这一点至少有两种学派观点：你可以从手头的工具开始，也可以从一个观察结果开始。

当你使用工具（或一组工具）开始分析时，你可能在遵循一个熟悉的工作流。你用于捕获数据的工具通常会至少包含一些用于分析这些数据的基础工具。即使没有别的东西，大多数工具也提供了过滤器，允许你关注感兴趣的项目。然而，这些功能通常只在那种没有其他可用工具的权宜之计下才有帮助。对于实际的分析工作，你需要一个全面的工具，用以同时查看你所拥有的所有数据。广而言之，这些工具分为三类：

- `安全信息和事件管理 (SIEM) 系统`收集来自各种传感器的数据，对事件进行模式匹配和关联，生成告警，并提供允许分析师查看网络状态的仪表板。最著名的商业解决方案之一是 `Splunk`，而在开源领域，`Elasticsearch-Logstash-Kibana (ELK)` 栈非常流行。
- `大数据分析解决方案`旨在处理通常超出 `SIEMs` 范围的海量数据集。`大数据`一词指的是在容量（即记录数量）、速度（新记录添加的速率）和多样性（不同数据格式的数量）方面大到传统数据库无法处理的数据集。大数据平台通常用于补充 `SIEM`，而不是取代它们。
- `本地开发的分析解决方案`通常是安全分析师在公司内部开发的脚本。`PowerShell` 和 `Python` 是开发这些工具的流行语言，这些工具通常构建用于在 `SIEM` 之外或替代其执行非常特定的功能。

另一种分析方法是从观察结果开始，无论产生该结果的工具是什么。基于该观察结果，你提出了一个可以解释它的假设。下一步是通过额外的观察或实验来证明或反驳该假设。如果这听起来很熟悉，那是因为我们刚刚描述了科学方法，正如你可能想象的，它与安全分析有很大关系。这种方法迫使我们思考跳出可用工具的限制，并提出答案可能不在我们现有数据中的问题。这就是为什么我们在这里简要提一下这一点。如果我们把自己和问题限制在眼前的工具和信息上，我们可能会错过新颖且潜在具有破坏性的攻击。

### 关于统计学的简短旁路

统计学的实用知识对于执行严谨的安全分析非常有益。统计学允许我们对数据做出描述性陈述，例如“这是正常的”，然后断言地说明某事不“正常”。尽管我们都根据经验对正常性有一种直觉，但我们都受到各种偏见的影响，这些偏差往往会导致我们得出错误的结论。如果你从未学过（或后来忘记了）统计学，我们强烈建议你温习。如果没有一些统计知识，很难进行某些分析，例如异常和趋势分析。

***

### 异常分析

从根本上说，异常分析试图回答“这正常吗？”的问题。显然，在回答这个问题之前，我们必须建立什么是正常。学习系统正常状态或流的过程被称为 `basining`（基准化）。虽然我们可以为单个系统创建基准，但有时对系统组创建基准更有帮助。异常分析侧重于测量与此基准的偏差，并判断该偏差在统计上是否具有显著性。最后这部分特别重要，因为一切都在不断变化。异常分析的目的是确定这种变化在正常情况下是否是预期的，或者它是否值得调查。

异常分析的一个应用示例是用户工作站网络流量的突然增加。如果没有基准，我们无法判断流量激增是否正常。假设我们已经对该特定系统建立了基准，而此种流量明显高于任何其他数据点。该事件可以被归类为离群值并被视为异常。但如果我们退后一步，查看工作站集群的基准，我们可能会发现该事件与特定类型用户（例如媒体团队）使用工作站是一致的。偶尔，他们中的某会发送一次突发流量（例如上传一个完成的电影片段），但在大多数时间里他们相当安静。

#### 行为分析

行为分析（Behavioral analysis）与异常分析密切相关，因为它们都试图发现异常行为。事实上，这两个术语经常互换使用或者结合使用，例如`网络行为异常分析`（network behavior anomaly analysis）。尽管实践中确实存在差异，但也微乎其微：行为分析通过观察多个相关数据点来定义异常行为。例如，用户在工作时间内向 Amazon 云平台上传大文件可能是正常行为，但如果该用户在下班后向 Google 云平台上传大文件则是不寻常。因此，与大小、目的地和时间相关的数据点被结合在一起使用。在异常分析的严格解释中（数据点可以孤立地提取），你可能会收到两条告警：一个针对目的地，一个针对时间，然后你必须手动地对它们进行关联。

## 趋势分析

趋势分析（Trend analysis）是对随时间变化的模式的研究，以确定这些模式如何、何时以及为何变化。这种技术有许多应用。最常见的是通过跟踪对手行为模式的演变，将趋势分析应用于安全领域。每年，许多著名的安全公司都会发布他们的趋势分析，并根据他们发现的模式对明年做出预测。例如，如果分布式拒绝服务（DDoS）攻击呈现上升趋势和/或向你所在的特定行业发展，这种方法会促使优先考虑 DDoS 缓解。

## 内部趋势

内部趋势可以揭示新兴的风险领域。例如，你的组织可能存在一种在 `Dropbox` 等云资源中存储越来越多数据的趋势。尽管从业务角度来看这可能完全合理，但它可能会对机密性、可用性、取证调查甚至法规合规性带来新的或增加的风险暴露。通过注意这一趋势，你能够更好地判断在何种情况下风险需要更改策略或购买托管解决方案。

## 时间趋势

时间趋势（Temporal trends）显示了与时间相关的模式。有许多例子表明，组织在周五深夜被入侵，是希望事件直到三天后才被检测到。矛盾的是，因为周末网络上的用户较少，这本应该让告警防御人员更容易检测到攻击，因为背景流量预计会较低。另一个时间趋势可能是季度报告发布前几天事件的增加，或者报税季期间钓鱼尝试的增加。这些趋势可以帮助我们更好地为可能到来的威胁对技术和人力资产做好准备。

## 空间趋势

趋势也存在于特定区域。尽管我们倾向于认为网络空间几乎独立于物理世界，但实际上，每个设备都存在于非常特定的地点（移动设备则是一系列地点）。例如，在员工访问某些国家时，为他们提供一台“一次性”（burner）笔记本电脑是一种常见做法。该设备不允许连接到公司网络，拥有有限的文件，并在用户返回后立即进行数字擦除。这种做法是观察到前往这些国家旅行的设备面临复杂攻击的趋势而产生的。另一个例子是设备连接到当地咖啡馆免费 Wi-Fi 网络的情况日益增加，这可能导致针对性的安全意识培训，并强制使用虚拟专用网络（`VPN`）连接。

## 可用性分析

有时，我们的重点放在保护系统的机密性和完整性上，以牺牲防止对其可用性的威胁保护为代价。可用性分析（Availability analysis）侧重于确定在各种场景下我们的系统对授权用户可用的概率。其中最常见的可能是缓解 DDoS 攻击，这部分通过获取诸如 `Akamai` 等反 DDoS 公司的服务来实现。这些服务可能价格昂贵，因此可用性分析可以帮助为这些服务提供业务理由，通过确定在何种情况下本地控制将无法应对 DDoS 攻击，以及系统对客户不可用的每个单位时间内组织会损失多少资金。

可用性分析的另一个应用是确定特定资产或一组资产丢失的后果。例如，丢失 Web 服务器、存储会计数据的数据服务器或 CEO 的电脑对业务流程会产生什么影响。显然，你无法在现实中分析你系统中的每种资产，但存在某些关键资源，它们的不可用可能会瘫痪一个组织。对这些资源进行可用性分析，可以阐明如何减轻其丢失的风险。

## 启发式算法（Heuristics）

`heuristic`（启发式方法）是一种“经验法则”，或者更准确地说，一种基于经验而非理论的方法。计算科学中有些问题被证明是无法解决的，但我们能够使用启发式方法来获得足够实用的结果。网络安全中的启发式分析是应用启发式方法以实际（尽管不完美）的方式发现威胁。这种分析常见于恶意软件检测。我们知道无法 100% 准确地找到恶意软件，但我们也知道大多数恶意软件样本表现出某些特征或行为。因此，这些就成了我们检测恶意软件的启发式方法。

下一代防火墙（`NGFs`）除了普通的防火墙功能外，还包含恶意软件检测等功能的设备。这种检测通常在 `NGFs` 中通过对入站数据进行启发式分析完成。第一方法是获取可疑负载，并在 `NGF` 内部或受其控制的特殊监测虚拟机（`VM`）中打开它。然后观察负载的执行情况，寻找具有特征的恶意软件动作，例如自我复制、添加用户账户和扫描资源。显然，某些恶意软件家族可能不会尝试这些动作的任何一个，这使得这种方法具有启发性：它是实用的，但不是保证的。

### 安全信息和事件管理系统

网络安全分析师的精髓工具可能是安全信息和事件管理（`SIEM`）系统。我们已经提到了 `Splunk` 和 `ELK`，但现在我们深入探讨，以确保你了解它们的一些特性。值得注意的是，从技术上讲，这两个系统都是数据分析平台，而不仅仅是 `SIEM`。

在本书编写时，使用 Splunk 的组织多于任何其他 SIEM，这意味着你可能已经与它打过道，或者在未来的某个时候会用到它。Splunk 可以从几乎任何源摄取数据。这些数据随后会被索引并存储。Splunk 的功能之一是允许你通过 `Universal Forwarder` 直接将原始数据摄入 `Indexer`，或者你可以使用 `Heavy Forwarder` 在源端进行预处理和索引，然后将准备好存储的较少数据发送到 `Indexer`。第二种方法有助于从各个源到索引器需要传输的数据量。当你考虑到大型企业环境每天可能产生数百 GB 的数据时，`Heavy Forwarders` 就显得非常有意义。一旦到达 `Indexers`，数据将被冗余存储，以提高可用性和生存能力。除了 `Forwarders` 和 `Indexers` 之外，Splunk 的另一个主要组件是 `Search Heads`，它们是允许用户搜索和查看数据的 Web 端前端。图 2-4 显示了顶部带有搜索栏的 Splunk 界面。

### ELK

ELK 与其说是一个工具，不如说是一个工具系统。该名称是 `Elasticsearch`、`Logstash` 和 `Kibana` 的缩写，它们都是开源的且基于 Java 的。这些是 ELK 的三个主要组件工具。`Elasticsearch` 是最流行的搜索引擎之一。它的主要目的是索引数据，以便能够快速地从大型数据集中搜索特定属性。`Elasticsearch` 负责存储数据，但与其他数据管理系统相比，它提供的持久性程度并不高。`Logstash` 是一个数据处理流水线，它可以从各种源（如防火墙和事件日志）摄取数据，对其进行转换（例如，从记录中移除个人身份信息，即 `PII`），然后将其转发到数据存储器（或 `stash`）。`Kibana` 如图 2-5
