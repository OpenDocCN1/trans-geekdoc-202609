
# 权益证明

**权益证明** 是指一种负责证明节点在系统中拥有足够权益的机制。权益证明算法的创建是为了解决工作量证明算法的一些感知不足。权益证明算法通过要求验证者（矿工）质押加密货币作为参与前提，然后允许验证者向区块链网络添加区块以赚取交易费来运作。如果不诚实的验证者将无效交易添加到区块链网络，其质押的权益将作为惩罚而损失。权益证明作为工作量证明算法的一种替代方案 [[79]](#ch10.xhtml#r122)。与工作量证明算法不同，PoS 的能源效率显著更高。然而，持币较少的人可能无法频繁参与区块创建过程。换句话说，在网络中持有的权益越高，被选中在网络中验证区块的概率就越高 [[15]](#ch10.xhtml#r058)。

## 委托权益证明

**委托权益证明** 算法是权益证明算法的进阶形式。详细来说，持有代币的参与者可以为“生产者”投票，得票最高的生产者将被允许生产区块。委托权益证明比权益证明更具优势，因为它确保了参与者与生产者之间的关注点分离，并确保网络内的适当治理 [[50]](#ch10.xhtml#r093)。委托权益证明高度依赖于区块链投票社区中的活跃用户 [[79]](#ch10.xhtml#r122)。

## 燃烧证明

**燃烧证明** 常用于启动新项目时，以维持初始代币分配的公平性。燃烧证明是工作量证明算法的一种替代方案，但不浪费能源。将原生货币或另一条区块链的货币发送到一个钱包地址。然后区块链矿工可以获得其所在区块链等量的货币 [[27]](#ch10.xhtml#r070)。

## 经过时间证明

**经过时间证明** 算法利用可信执行环境，通过保证的等待时间提供随机性和安全性。节点根据自上次获得创建区块机会以来等待了多久来被允许验证交易 [[79]](#ch10.xhtml#r122)。经过时间证明依赖于一种称为软件保护扩展 (`SGX`) 的专用硬件，它允许应用程序在受保护的运行时环境中运行可信代码。它支持用户级代码分配飞地（内存私有区域），并保护这些代码免受高权限进程的侵害。

# 共识机制

## Proof of Importance (PoI)

与权益证明算法不同，PoI 不仅依赖用户在区块链网络中的质押量。相反，它通过密切监控代币的流动和使用情况来建立信任和重要性。因为它决定了网络中哪些节点有资格向区块链添加新区块，所以它与权益证明非常相似。然而，重要性证明还通过使用图论来确定每个节点的评级，从而考虑节点的重要性 [79]。

## Proof of Storage (PoS)

存储证明机制衍生出了多种变体，如空间证明、时空证明、复制证明等。它允许将存储容量外包作为参与网络的条件 [15]。

## Proof of Authority (PoA)

权威证明主要设计用于许可网络，根据验证者在区块链中的声誉和身份来选择交易验证者。有意向的验证者必须提供必要的文件以披露其身份和声誉 [50]。

## Proof of Activity (PoACT)

活动证明通过结合工作量证明和权益证明算法，以统一但伪随机的方式选择利益相关者，以实现最大安全性。这种混合组合也确保了能源效率。

## Proof of Deposit (PoD)

存款证明简单指其他想要参与区块链的节点所作支付的证据 [8]。存款证明支付被称为保证金，在任何节点创建新区块之前需要缴纳 [3]。

## Ordering-based Consensus (OBC)

基于排序的共识与权威证明概念相似，因为基于排序的共识机制也主要用于许可网络。然而，它根据节点的身份服务来选择参与网络的节点 [21]。身份服务指一种系统，其中处理节点因作为经过验证机构的成员而被识别并被视为可靠。

## Proof of Capacity (PoC)

容量证明也称为硬盘挖矿，因为它利用硬盘空间进行挖矿。PoC 是一种共识机制，允许网络中的处理节点验证交易，并根据可用硬盘空间确定挖矿权利。拥有更多闲置硬盘空间的节点可以挖掘可用的加密货币 [13]。

## Practical Byzantine Fault Tolerance (PBFT)

实用拜占庭容错最早由 Miguel Castro 和 Barbara Liskov 提出，旨在通过投票机制在分布式系统中实现共识，如果状态发生变化，则提供安全性和活性 [63]。然而，由于需要发送的消息数量会随着网络增长呈指数级增加，因此它不可扩展。该算法适用于异步系统（如互联网），并对系统进行优化，使其更高效、更有效 [21]。

最大消息数计算如下：

```
M = 1 + 3F + 3F + (2F) (3F + 1) + 3F + 1
```

```
F = (n - 1) / 3
```

其中：

- `M` = 最大消息数
- `F` = 最大允许故障节点数
- `N` = 活跃共识节点数

PBFT 应与企业组织联盟一起使用，其中每个组织代表网络上的一个节点。在 PBFT 中，区块创建者可能不是任何特殊矿工，但提交给链的提议区块将是最受认可的区块 [47]。

## Simplified Byzantine Fault Tolerance (SBFT)

简化拜占庭容错是对实用拜占庭容错 (`PBFT`) 的改进。它所需的消息量约为 PBFT 的三分之一，并能更快地达成共识——通常在 0.2 秒内。SBFT 共识中的每个节点都可以自主行动，无需与其他节点通信 [62]。

SBFT 的消息计数计算如下：

```
M = (3f + 1) (2f + 1) + 1
```

其中：

- `M` = 最大消息数
- `F` = 允许故障节点数

## Delegated Byzantine Fault Tolerance (DBFT)

委托拜占庭容错由一种名为 `NEO` 的加密货币推广。它使用“记账人”——一组节点——通过代理投票达成共识，以在网络中生成更多区块。通过代理达成共识是指一种机制，其中被选为发言人的记账人提议其区块进行验证。发言人随后将区块发送给网络中的其他代表，以确认该区块有效。当三分之二的代表确认其有效性时，该区块将被添加到网络中。一旦共识确认，极少被撤销。交易生成速度也非常高——约每秒 1,000 笔交易 [63]。

其容错计算如下：

```
F = (n - 1) / 3
```

其中：

- `F` = 允许故障节点数

## Federated Byzantine Fault Tolerance

联邦拜占庭容错用于国家间的关键金融交易。该协议中的节点保留一组公开受信的对等节点，并仅传播那些由最受信任节点验证的交易 [13]。

# 密码学入门

密码学是在第三方（称为对手）存在的情况下保护信息的科学。密码学的主要目标是通过提供机密性、完整性、认证和抗抵赖性来确保数据安全 [11]。如果双方（Alice 和 Bob）想要通信，Alice（此处称为发送者）使用不安全的通信信道向接收者 Bob 发送消息。该信道可以是计算机网络或电话线。如果消息包含机密信息，它可能被窃听者拦截并读取，或者更糟，消息可能被对手篡改，而 Bob（接收者）可能无法检测到这种操纵。密码学的目标之一是提供防止此类攻击发生的方法。

读者应熟悉以下密码学相关术语和概念：

- **Cryptosystem（密码系统）**：指加密和解密过程中所用密钥及技术的完整规范 [49]。
- **Cryptoanalysis（密码分析）**：攻击者试图破解密码系统时使用的技术。成功的攻击可能从密文中恢复明文（或部分明文），然后用原始消息的部分内容替换，或伪造数字签名。Cryptology（密码学）常被用作指代密码分析的通用术语 [49]。
- **Confidentiality（机密性）**：只有拥有密钥的人才能访问消息。如果消息在传输过程中被拦截，应受到保护，不被未授权方访问。机密性可使用高级加密标准 (`AES`) 和 `RC4` 等算法实现 [37]。
- **Data integrity（数据完整性）**：消息接收者应能确认消息在传输过程中未被损坏、更改或截断，无论是故意还是意外。任何人都不应能用虚假消息更改原始消息或其部分内容。
- **Data authentication（数据认证）**：消息的来源应可由接收者验证。不应有人冒充发送者 (Alice) 向接收者 (Bob) 发送消息。发送者和接收者在发起通信时应能相互识别（实体认证）。消息认证码 (`MAC`) 算法可用于实现数据完整性和认证 [37]。

## 不可抵赖性

发送方事后不应否认发送过该消息。应确保消息的来源无法被否认。

## 分组密码与流密码

**分组密码与流密码** 是密码系统的组成部分。在分组密码中，明文被分割成称为“分组”的固定块。分组是一串比特，具有固定长度。此外，加密和解密是一次一个分组地进行的。相反，流密码密码系统使用密钥流构建其密钥，加密过程从明文和密钥流构造密文，解密则使用密文和密钥流进行 [73]。

现代密码学的两大主要类别是对称密码学和非对称密码学。

## 对称密码学

**对称密码学** 为受信任的各方提供了一个秘密通信通道。假设 Alice 和 Bob 已商定一个密钥。稍后当 Alice 和 Bob 决定互发秘密消息时，该密钥被用于将消息转换为无密钥无法处理的乱码形式。原始消息通常称为“明文”，而乱码消息称为“密文”。此过程称为“加密”。Bob 接收密文并使用密钥将其转换回明文的过程称为“解密” [68]。在对称加密中，通信双方使用单个密钥来加密明文和解密密文，且双方均知晓该密钥。加密和解密算法是公开的。因此，必须妥善保管密钥。对称密码学的主要问题是密钥分发问题。密钥分发必须在信息传输之前完成。因此，通信双方（Alice 和 Bob）之间需要一个秘密通道以及身份认证来分发密钥材料。

### 对称密码学算法

#### 高级加密标准 (AES)

**高级加密标准 (`AES`)** 于 1998 年由美国国家标准与技术研究院 (`NIST`) 推荐作为易受攻击的数据加密标准 (`DES`) 的替代品。AES 是一种对称分组密码，使用 128、192 和 256 位的可变密钥长度。如果密钥长度和分组长度均为 126 位，AES 将执行 9 轮处理；如果密钥和分组长度为 192 位，则执行 11 轮处理。如果密钥和分组长度均为 256 位，AES 将执行 13 轮处理 [2]。

处理轮涉及四个步骤：

1.  **字节代换** – 在此步骤中，使用 S 盒执行逐字节替换。
2.  **行移位** – 执行简单置换。
3.  **列混淆** – 一种替换方法，将行移位步骤中每列的数据与矩阵算法相乘。
4.  **轮密钥加** – 将轮密钥与数据进行异或运算。

#### Blowfish

**Blowfish** 是 Bruce Schneider 于 1993 年设计的一种算法。它是一种 64 位分组密码，密钥长度可变，范围从 32 位（4 字节）到 448 位（56 字节）。它是现有所有加密算法中最高效的算法 [22]。Blowfish 算法包含两个步骤 [2]：

1.  **密钥扩展** – 密钥扩展步骤将 448 位转换为 4168 字节。P 数组包含 18 个 32 位子密钥。有四个 32 位 S 盒，每个均包含 256 个条目。
2.  **数据加密** – 数据加密使用异或运算完成。总共执行 16 轮数据加密。

#### RC4

**RC4** 是由 Ronald Rivest 开发的一种对称算法。RC4 的密钥长度可变，范围从 1 到 256 字节。RC4 算法涉及两个阶段，即密钥生成和加密。由加密密钥生成的可变加密使用两个数组（状态数组和密钥数组）及合并操作结果。生成伪随机字节以产生密钥流，该密钥流通过异或运算实现密文与明文的相互转换。异或是一种用于比较两个二进制位的逻辑运算。若两者有显著差异，则产生值 1；若两位相等，则结果为 0 [22]。

## 非对称密码学

非对称密码学也称为公钥密码学。这种革命性的密码学思想由 Whitfield Diffie 和 Martin Hellman 于 20 世纪 70 年代提出。Diffie 和 Hellman 认为，可能存在开发一种密码系统的可能性，其中包含两个不同的密钥。公钥用于明文的加密，而私钥用于将密文解密为明文 [73]。在这种技术中，发送方（Alice）使用接收方（Bob）的公钥加密秘密消息，接收方使用其私钥解密消息。公钥可以为所有人所知，但私钥仅为接收方所知，并需要受到保护。密钥通过数字签名进行认证。只要私钥保持完好，非对称密码学既方便又提供更高的安全性。Diffie-Hellman 密钥交换是最流行的密钥分发方法之一 [58]。

### 非对称密码学算法

#### Rivest Adi Adleman (RSA) 算法

`Rivest Adi Adleman (RSA)` 算法由 Ron Rivest、Adi Shamir 和 Leonard Adleman 于 1978 年发明。RSA 作为一种密码算法被引入，取代了安全性较低的美国国家标准局（NBS）算法。RSA 算法基于因式分解问题，该问题在于将两个大素数的乘积进行因式分解在实际中具有困难性 [58]。也使用不同的加密密钥；即公钥（非对称密钥）和私钥（对称密钥）。RSA 算法涉及三个步骤，即密钥生成、加密和解密。

#### Elgamal 加密

`Elgamal` 加密由 Taher Elgamal 于 1984 年开发。非对称密钥加密是基于 Diffie-Hellman 密钥交换原理建立的。与 Diffie-Hellman 算法不同，Elgamal 密码系统是一个完整的加密和解密系统，依赖于离散对数问题。Elgamal 算法由三个组件组成：密钥生成器、加密和解密 [58]。

#### 背包算法

`Knapsack algorithm` 是最早的公钥密码系统之一，由 Ralph Merkle 和 Martin Hellman 于 1978 年发明。在背包密码系统中，也执行三个过程：密钥生成、加密和解密。一些公钥密码系统是基于背包（或子集和）问题提出的 [58]。由于其 NP（非确定性多项式时间）完全性的性质以及加密和解密过程的高速度，背包密码系统曾被认为是最有前途的密码系统之一。然而，大多数基于背包的密码系统被认为是不安全的，因为这些密码系统中的加密函数本质上是线性的。
