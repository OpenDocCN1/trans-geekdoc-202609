
# 国际标准与事件响应框架

## ISO/IEC 27035 标准

最具权威性的国际标准是 `ISO/IEC 27035-1:2023`，该标准涉及信息安全事件、事件和漏洞的管理。`ISO/IEC 27035` 取代了 `ISO/IEC TR 18044:2004 – Security techniques – Information Security incident management`。27035 的完整标题 —— `Information technology – Information security incident management` —— 在 `ISO/IEC 27002` 最初提供的内容基础上，侧重于响应方面。与大多数标准一样，其内容和框架对所有组织均适用，无论规模、目的或运行环境如何。安全标准提供了基本框架和控制目标：真正的落地工作在于组织自行为员工的信息安全设定战略与操作色彩，并为员工定下基调。

### ISO 27035 第一部分：五阶段事件管理流程

`ISO 27035` 第一部分提供了 **五阶段** 的事件管理流程：

**1. `Prepare`（准备）** —— 针对重大事件的预案。例如，设计并准备事件管理政策与计划，建立专业的计算机应急响应团队（CIRT）以预见并处理事件（`ISO Security Blog`: 2023）。

**2. `Identify`（识别）并报告信息安全事件** —— 该过程应包括主动检测与报告。可以由个人或安全运营中心（SOC）负责，识别并报告潜在威胁，防止其演变为正式事件。

**3. `Assess`（评估）** —— 在此阶段进一步评估事件，SOC 经理或相关高层决策者会决定如何应对威胁或风险。例如，是只需进行“轻度”修补后快速恢复业务，还是需要进行取证取样，即使会产生延迟。

> 风险评估与制定“应对方案”是评估阶段的关键。

**4. `Respond`（响应）** —— 有效遏制事件，防止其对业务造成损害，并进一步调查。完整解决并处理所有发现，按事件管理计划有效应对持续的声誉、财务、以及安全与安全性问题。

**5. `Learn lessons`（吸取经验）** —— 系统识别、列出并处理所有发现的弱点与改进点。将漏洞与对应的缓解措施系统化地纳入持续改进的安全政策与计划中。

### ISO/IEC 27035 第二部分

`ISO/IEC 27035` 第二部分 *“提供事件响应规划与准备的指南，以及从事件响应中汲取经验的方法”* (`ISO/IEC 27035-2`: 2023)。第二部分旨在确保组织具备应对事件的战斗力。它强调学习经验的重要性，并将组织学习融入未来的规划与准备。第二部分通过 **九个主要条款**（原文编号）来组织内容，并在附录中提供事件表单、分类方法以及法律建议（尤其是隐私相关）等示例：

*   *4.* `信息安全事件管理政策`
*   *5.* `信息安全政策的更新`
*   *6.* `创建信息安全事件管理计划`
*   *7.* `建立事件管理能力`
*   *8.* `建立内部与外部关系`
*   *9.* `定义技术及其他支持`
*   *10.* `创建信息安全意识与培训`
*   *11.* `测试信息安全事件管理计划`
*   *12.* `汲取经验` (`ISO/IEC 27035:2-2023`)

## 美国方法：NIST 与事件响应

根据网络安全专家 **ConsultDTS** 的说法，“组织自愿遵循 NIST 标准，并在政府合同或其他认证中自行评估其对特定标准的符合程度。NIST 本身不提供任何认证”。 (`[ConsultDTS.com](http://ConsultDTS.com)`: 2023)。NIST 标准在非美国公司中广为人知，这些公司要么希望出口美国市场，要么在美国开展业务。NIST 是 *“负责制定指南和标准，包括为所有机构运营和资产提供适当信息安全的最低要求，但可以由非政府组织自愿使用”* (`NIST SP 800-61 Rev. 2`: 2012: 13)。NIST 指南对信息安全成熟度尚不高的组织尤为有用，因为它提供了更具体的规划与目标设定细节。

*`NIST SP 800-61 Rev. 2 (2012) Computer Security Incident Handling Guide`* 是一份全面的业务安全与连续性框架，帮助组织在重大信息安全事件中 **遏制、管理和恢复**。该指南将事件响应的理解与管理划分为一个 **生命周期**（见 Figure 4）。

### NIST 事件响应生命周期中的关键控制目标

#### 准备

在平时制定作战计划。即在任何重大事件发生前，组织应做好准备。根据 `NIST SP 800-61 Rev. 2` 的指导，主要的准备工作包括：

**招聘与培训** 专门的组织计算机应急响应团队（CIRT）。

*   提供和提供团队及事件管理（IM）运营所需的必要工具和资源，包括用于集中协调和通信的“战斗室”，以及用于保存证据的安全存储区域。
*   收集包括 CIRT、核心业务职能、领导层和关键利益相关者（包括供应链和媒体）的主要和备用联系人信息，并整合成具体的 IM 联络计划。
*   保持备用 IT 设备，包括笔记本电脑、工作站、布线、网络设备、空白可移动介质、新智能手机、便携式打印机、电池以及电源备用等。
*   取证工具，包括数字取证软件（数据包嗅探器和网络分析仪）、硬装笔记本、数码相机、存储袋（包括法拉第袋以保护电子设备）、大量预印的链条管理表格、以及事件报告表格和反馈机制，部分用于实现匿名报告。
*   记住，预防优于治疗。开展全员网络安全意识培训。加密并保护所有安全、事件管理和业务连续性计划。开展风险评估，积极处理和审查安全威胁和漏洞。

#### 检测

根据 `NIST SP 800-61 Rev. 2` 的指导，您的主要检测和分析功能包括：

*   了解常见的威胁向量，并通过全员基线网络安全意识培训进行宣传。在网络恐怖主义领域，常见的威胁向量包括：
    1.  使用可移动介质进行网络渗透/数据外泄。
    2.  钓鱼邮件和数字媒体链接针对个人、群体和组织。
    3.  分布式拒绝服务（DDoS）攻击，使网络失效。
    4.  社会工程和冒充攻击，通常针对个人（包括护卫和通信经理，他们拥有对 VIP 的特权访问）。
    5.  用于擦除数据系统、勒索和勒索（恐怖主义筹款）的恶意软件。
    6.  恶意通信，包括传播可能描绘酷刑和谋杀（可能是朋友/同事）的视频，以针对群体和组织。
    7.  计算机设备的盗窃。
*   入侵检测和防范系统（IDPS）可以部署以自动化和持续监控您的信息系统。IDPS 包括防病毒软件、下一代防火墙（NGFWs）（提供勒索软件、垃圾邮件防护和终端安全），以及日志分析器。许多 IDPS 解决方案效果显著且价格适中。它们提供额外的安全层和保障，特别是对微型企业和中小企业，这些企业可能过于自信于其使用的软件即服务（SaaS）产品（例如客户关系管理系统）能提供 100% 的网络安全。
*   经验丰富或受过训练的员工。许多 IT 管理员技术熟练但缺乏安全意识。此外，许多安全官员在物理和环境领域有效，但缺乏理解或识别网络威胁的能力。负责检测和分析潜在计算机安全事件的人员必须能够注意并理解“网络流量典型模式的异常偏差”（NIST 800-61 Rev. 2: 2012: 27）。
*   威胁情报的艺术——将人类和技术安全情报结合以提升组织弹性——在本章的风险识别部分已简要提及。然而，负责技术安全检测和威胁分析的人员需要深入学习，我们指向：`NIST SP 800-94`，入侵检测与防范系统指南（2007），获取完整的指导和建议框架控制。2012 年曾尝试更新该文档，但最终未发布。经验丰富的 NIST IDPS 标准可在 NIST 图书馆在线获取，并在本书参考章节末尾的参考文献中提供链接。此外，`NIST 800-61 Rev. 2: 2012`（第 27 至 44 页）也包含大量网络威胁情报信息，同样在参考章节中提供出版链接。（截至本书撰写时，这些资源均为免费且开源。）

#### 应对

*   **Containment（遏制）** 是关键的安全目标，在事件压倒或严重损害业务之前必须实施。Containment 可以阻碍威胁并为遏制、清除和恢复策略争取时间。根据 `NIST SP 800-61 Rev. 2` 的指导，您的主要 containment、清除和恢复功能包括：
*   **Containment（遏制）**：组织应为每种实现的威胁制定单独且不同的 containment 策略。虽然许多重大事件的业务影响相似，但 containment 策略可以截然不同且多样。有效 containment 策略的根本要求是决策以及实施适当的技术响应。必须做出以下决定：
    1.  真实的持续时间估计。
    2.  所需资源的真实评估（内部和外部）。
    3.  立即加强的安全控制，以维持系统的可用性和完整性。
    4.  证据保护要求以及向监管机构等当局通报的要求。

**Eradication（根除）**：对于某些事件，不需要或在恢复阶段进行根除。Swift 转向“根除可能是必要的，以消除事件的组件，例如删除恶意软件和禁用受损用户账户，以及识别和缓解所有被利用的漏洞”（`NIST SP 800-61 Rev. 2`: 2012: 37）。但总体而言，“根除和恢复应在分阶段进行，以便将修复步骤进行优先排序”（`NIST SP 800-61 Rev. 2`: 2012: 37）。根除有时会与证据收集和存储产生冲突。这种战术困境经常在 CIRT 或 SOC 内部讨论。证据收集和处理指南见 `NIST SP 800-61 Rev. 2`（见第 3.3.2 节），包括如何维护事件日志以及记录证据链的所有权。此类信息应包括访问或处理证据的人员的姓名、时间、日期、地点、原因和操作，以及最终对证据负责的个人姓名。关于收集、存储和处理证据（物理和数字）的更详细信息，请参阅 `NIST SP 800-86`，Guide to Integrating Forensic Techniques into Incident Response（2006），这是网络安全专业人员可靠的老工作马。此外，国际标准 `ISO/IEC 27037:2012 Information technology – Security techniques – Guidelines for identification, collection, acquisition and preservation of digital evidence` 也可供参考。另一项老旧但亟待与其他四项相关数字证据标准统一的标准，仍然在捕获以下设备和情形的数据方面提供了适当的流程指导：“用于标准计算机的数字存储媒体，如硬盘、软盘、光盘和磁光盘，以及功能类似的设备；移动电话、个人数字助理（PDA）、个人电子设备（PED）、存储卡；移动导航系统；数码照片和视频摄像机（包括闭路电视）；带网络连接的标准计算机；基于 TCP/IP 和其他数字协议的网络；以及功能类似的设备”（ISO [Security.com](http://Security.com): 2023）。

**Recovery（恢复）**：也许是事件响应生命周期中最微妙的阶段，类似“在高度光滑的地板上搬运明代瓷器”（英国政客罗伊·詹金斯的著名引语，形容领导人面对政治险境）。大规模事件的恢复可能需要数月甚至数年，甚至可能无法实现完全恢复。恢复应包含广泛的技术和非技术干预措施。黄金法则：不要强行加快恢复速度。分阶段恢复：不要一次性投入太多；不要让仍在异常运行的信息系统承受过大压力。同样，不要让表面看似完全有效的员工感到压力，尤其是在确认威胁是否已完全根除时。另一条经验法则：仅在可察觉的恢复期结束后，才引入长期、重大的变更。

*技术干预措施包括以下内容：*

1.  优先处理修复步骤。
2.  使用清洁备份恢复系统。
3.  用新版本替换可能被篡改的文件和软件。
4.  为整个网络更改密码。
5.  在使用时间较少的时段缓慢、谨慎地重新启动系统。
6.  即使已查明内部威胁，也要增强边界安全（如检查并加固防火墙规则和路由器访问控制列表）。
7.  考虑从零重新构建系统。

*非技术干预措施包括以下内容：*

1.  通过保持常规且有足够资源的危机恢复小组，确保亲自领导力持续。该小组应包括高层管理人员以及必要时的主要利益相关者。
2.  媒体处理：继续使用严格的脚本（已商定的发言词）并实施结构化、定期的通信计划。危机通信计划及其主要内容（包括指定的发言人和“应对话线”）应在准备阶段（即“事前危机”阶段）已制定并获批准，以便在危机管理行业中广泛使用。
3.  谨慎保持内部沟通的相关性和专业性，以让员工了解情况并防止对组织产生打击情绪。在大型组织中，这类信息往往会泄露到数字媒体平台或被记者获取。因此，根据整体情境和影响严重程度，避免使用轻率的幽默、消极的不确定性或猜测，也不应转移或接受责任。持续强调组织及个人的积极行为与成就，并提供乐观的保 reassurance（隐含或明确），表明公司是并将继续是一个积极且有弹性的环境，把员工视为其首要资产。
4.  认识到重大事件后，组织处于最脆弱的状态。（尽管组织高层随后需要进行充满动力的演讲）。与物理环境不同，网络环境中的攻击者通常更匿名，识别过程更长，因此执法机构介入也更久。正如 `NIST SP 800-61 Rev. 2: 2012: 37` 所述：“一旦资源成功被攻击，往往会再次被攻击，或组织内的其他资源以相同方式受到攻击”。
5.  鉴于上述原因——尤其是要理解对手和最严厉批评者的心态（请记住，公开安全事件后，两种威胁类型的数量会增加）——在作出任何明确的“任务完成”类声明时要格外谨慎。你必然会受到压力做出此类声明，但要思考：公开声明的必要程度是多少？除了向对手提供“Catch Me If You Can”式的诱饵外，还有其他必要吗？更好是保持组织的恢复低调，用适当的感谢和在正确位置加强监控来表达支持。

#### Recover（恢复后复盘）

此阶段主要关于学习事件原因以及评估其业务影响。在此评估和评估之后，可制定并分享一份后 incident 报告，其中包含建议措施或行动方案。详细列出成本、其他影响以及向执行层提出的建议的后 incident 报告，将为组织提供防止类似事件再次发生的最佳机会。

在高层管理团队（SMT）层面，应举办一次全面的“经验教训”研讨会。这可以以“离 site 日”或两天的形式进行。董事会成员应参与原因、影响以及建议的缓解措施讨论，采用无指责的方式，并在由独立同行主持的会议中分别就这三个方面进行互动讨论。

# 结论性评论

与犯罪学研究领域中复杂且含糊的术语一样，本文作者承认，对于许多读者而言，“网络恐怖主义”一词仍然是一个本质上具有争议性的概念，包含多种含义和细微差别。（告诉我一个犯罪学术语不是这样吗？！）本书的目的并非证明该短语的有效性或字面解释，尽管在第 1 章中提供的定义无疑很有帮助，并支撑了本出版物的内容。对于那些仍保持审慎怀疑的读者，希望作者至少已经表明，除了数字媒体和其他先进技术的演进之外，一个明确的后果就是出现了更高水平的普遍恐怖威胁。舆论调查显示，公众广泛认识到这一点，但迄今为止在大多数国家司法管辖区内，用于更快、更坚决防范威胁实现的工具和资源却一直进展缓慢且应用不一致（到目前为止）。在恐怖主义防范工作中，一个棘手的问题在于理解暴力单独行动者的现象，有时被理解或误解为“独狼”。这项研究得出结论，在大多数严重的所谓单一行动恐怖案件中，互联网及其他互联网用户在培养和激活特定个人方面发挥了重要或关键的作用。无论某人觉得自己在推动全球哈里发的目标、种族至上主义，还是激进 feminism 的推翻，自数字媒体出现以来，大多数单独行动者都受到、得到或在某些情况下被指挥于其在线网络中的其他人。事实是，如果没有 cybersphere 的赋能，至少有几起惨案是不会发生的。

此外，本书试图实际阐述我们在应对人类最新技术安全挑战时所能现实地采取的若干步骤。从本出版物所展示的内容来看，要假设大型科技公司或立法者拥有大部分预防权力似乎有些牵强。事实上，我们越仔细观察，就越发现大多数解决方案基本上是自下而上、由所有终端用户推动的。因此，据我所见，很难得出结论认为大型科技公司、政府和国际论坛拥有与当前问题相匹配的“魔法”解决方案。立法者和科技公司根本没有足够的“克里普顿 ite”（kryptonite）来对在线恐怖主义造成实质性打击，尤其是当我们考虑到许多国家在网络恐怖主义方面视而不见或甚至“助长”这种行为的国家，已经发展出自己先进的技术和规模与 Meta、Alphabet 相当的 ISP 之时。
