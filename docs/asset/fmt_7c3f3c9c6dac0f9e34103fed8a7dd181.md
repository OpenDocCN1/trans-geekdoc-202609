这些地址在网络内部的使用不受限制，其功能与其他任何 IP 地址相同。当这些地址中的某一个需要外部资源（即互联网提供的资源）时，就需要 `NAT` 为该资源生成一个有效的外部 IP 地址。`NAT` 的工作原理是在流量通过 `NAT` 设备（如防火墙）时对地址进行翻译。所使用的外部地址与内部地址之间不是 1:1 的外部映射关系，因为这将违背重用和地址空间节省的目的。通常，`NAT` 设备使用一个外部 IP 地址池，由设备记录在任何时刻哪个内部地址正在使用哪个外部地址。这提供了一个重大的安全层，因为它使得从外部映射到防火墙后的内部网络变得非常困难。

实现 `NAT` 使用了以下几种技术：

- `static NAT`：提供外部地址到内部地址的 1:1 绑定；适用于引用内部源的服务，例如 Web 服务器或电子邮件服务器。

- `DMZ`：引用外部地址的资源可以通过 `dynamic NAT` 共享，在这种模式下，边缘设备会构建并使用一张表来管理翻译，因为地址可能会随时间而变化。

- `Port Address Translation (PAT)`：实际的 `TCP/UDP` 端口也会被翻译。这将允许单个外部 IP 地址通过端口（如端口 `80` 或 `25`）为内部 IP 地址提供服务。

### 远程访问

远程访问是跨网络到设备的连接。有多种协议可以用于启用远程访问。`Remote Access Service (RAS)` 是 `Windows OS` 的一部分，允许通过拨号连接在客户端和服务器之间。虽然速度比 `DSL` 连接慢，但这仍然是连接到远程网络的常用方法。当用户拨号接入计算机系统时，将通过一系列远程访问协议进行身份验证和授权。为了获得更高的安全性，可以使用回调系统，即服务器在设定的时间内拨回客户端。`RAS` 也可以指 `Remote Access Server`（远程访问服务器），这是一个允许远程用户访问网络并监管其访问的术语。今天，远程访问通常通过使用 `VPNs` 和远程桌面软件来实现。

### 电话

数据和语音通信在企业中已共存数。近期企业内部 `Voice over IP (VoIP)` 与传统程控交换 (`PBX`) 的连接增加了功能性，但也增加了风险。可以使用特定的防火墙来防止电话连接上的未经授权的流量。`PBX` 是公共电话网络向业务领域的延伸。尽管被认为是与数据系统不同的实体，但 `PBXs` 经常互连，并作为这种互连的一部分具有安全性。`PBXs` 是基于计算机的交换设备，旨在将电话连接到本地系统。它们基本上是数字交换系统，可能会从外部被破解，并被黑客用来通过企业的费用拨打电话。尽管随着低成本远程服务的出现，这种类型的攻击有所减少，但它并没有消失，正如公司每年学到的那样，语音信箱和 `PBXs` 可能会被破解，风险可能会变得很高。

`PBXs` 的另一个问题出现在当它们与数据系统互连时，无论是通过企业连接还是通过用户手中的非法调制调器。在何种情况下，都存在通往外部数据网络和互联网的路径。正如数据连接需要防火墙来确保安全一样，这些连接也需要防火墙。电信防火墙是一种特殊的防火墙，旨在同时保护 `PBX` 和数据连接。电信防火墙的功能与数据防火墙相同：其目的是执行安全策略。电信安全策略甚至可以通过实施访问代码和/或限制服务，来覆盖数小时的使用时间。

### 网络访问控制 (NAC)

网络由连接的工作站和服务器组成。网络安全管理涉及管理来自各种连接硬件以及运行这些设备的软件的广泛问题。假设网络是安全的，那么每个额外的连接都涉及风险。在端点连接时逐种情况地进行管理，这种安全方法被称为网络访问控制（Network Access Control）。存在两种主要的竞争方法论：

- `Network Access Protection (NAP)`：微软的一种用于控制计算机主机网络访问的技术。

- `Network Admission Control (NAC)`：思科的用于控制网络准入的技术。

微软的 `NAP` 系统基于测量连接机器的系统健康状况，包括 `OS` 的补丁级别、反病毒保护情况和系统策略。`NAP` 首次在 `Windows XP Service Pack 3`、`Windows Vista` 和 `Windows Server 2008` 中被利用，它需要额外的基础设施服务器来实现健康检查。该系统包含执行代理，用于询问客户端并验证准入标准。每当建立网络连接时，客户端都会启动。响应选项包括拒绝连接请求或限制进入子网的访问。

思科的 `NAC` 系统围绕一个设备构建，该设备执行网络管理员选择的策略。一系列第三方解决方案可以与该设备接口，允许验证各种选项，包括客户端策略设置、软件更新和客户端安全态势。第三方设备和软件的使用使得该系统在广泛设备上具有可扩展性。

思科的 `NAC` 和微软的 `NAP` 都处于采用的早期阶段。客户端部分已经就绪，但企业在完全部署该技术的服务器端方面进展缓慢。基于客户端设备特征的自动准入检查概念将一直存在下去，因为它为当今企业瞬息万变的网络世界提供了及时的控制。随着企业中自备设备 (`BYOD`) 的兴起，人们对使用 `NAC` 来帮助保护网络免受不安全设备的兴趣再次增加。

### 虚拟化

虚拟化是创建虚拟系统而非实际硬件和软件。硬件与软件的分离增加了企业的灵活性。在实际硬件之上，虚拟化层允许创建完整的系统，包括作为虚拟机的计算机和网络设备。这种硬件与软件的分通过一系列改进提高了安全性。复制整个系统、备份它们或在硬件平台之间移动它们的能力可以增加系统的安全性。

与虚拟化相关的实用元素之一是`snapshot`（快照）。快照是系统在某一时间点的映像。快照实现了许多实用功能。快照允许系统恢复到之前的某个点。快照能够更快的备份、更快的恢复，并作为使系统更稳定的手段。

尽管存在某些漏洞可能允许一个虚拟环境中的进程突破虚拟环境之间的隔离或突破到宿主机层，但这些情况非常罕见且极难利用。必须解决一种新形式的漏洞——创建完整虚拟系统副本的能力，因为这可能导致数据和知识产权的损失。虚拟系统的存储保护必须与普通系统的备份同等，以避免大规模的损失。

## 云计算

`Cloud computing`（云计算）是一个通用术语，用于描述通过网络提供的计算机服务。这些计算服务是通过互联网协议提供的计算、存储、应用程序和各项服务。云计算的特点之一是对终端用户透明的。这提高了这种服务提供形式的易用性。云计算为用户提供了许多益处：包括性能、可扩展性、灵活性、安全性和可靠性的提升等。这些改进是与云服务实现方式相关的特定属性的直接结果。

当数据和计算由远程方处理时（如在云计算中），安全性是一项特殊的挑战。具体的挑战在于如何允许数据离开你的企业，同时仍保持对数据使用的控制。常见的答案是加密。通过在数据离开企业之前对其进行适当的加密，可以通过适当使用加密元素安全地执行外部存储。

云可以由许多组织内部和外部的实体创建。商业云服务已经可用，并由从 Google 和 Amazon 等大公司到较小的本地供应商的各种公司提供。公司内部的服务可以复制云计算的优势，同时提高有限资源的实用性。云计算的承诺是提高实用性，并以平台即服务（PaaS）、软件即服务（SaaS）和基础设施即服务（IaaS）的概念进行营销。

云服务的使用已成为普通用户的常规，通过如 `iCloud`（苹果）、`OneDrive`（原 `SkyDrive`）以及 `Dropbox` 等文件服务。这些服务易于使用、易于配置，并以最小的用户困难提供所需的基本服务。

### 平台即服务

平台即服务（PaaS）是一个营销术语，用于描述在云中提供计算平台。多组协同工作的软件提供的服务（如数据库服务）可以通过云以平台的形式交付。PaaS 产品通常专注于安全性和可扩展性，这两者都是符合云和平台需求的特征。

### 软件即服务

软件即服务（SaaS）是从云内部向终端用户提供软件。SaaS 不是在客户端机器上安装软件，而是充当按需软件，软件从云端运行。这有几个优势：更新对终端用户来说是无缝的，组件之间的集成可以得到增强。SaaS 的常见示例是通过订阅服务通过 Web 的产品，如 `Microsoft Office 365` 和 `Adobe Creative Suite`。

### 基础设施即服务

基础设施即服务（IaaS）是一个术语，用于描述作为计算虚拟平台交付的云系统。IaaS 无需构建数据中心，允许公司根据需要签订公用事业计算。IaaS 特别地按需付费的基础上进行营销，并可根据需求直接扩展。

### 私有云

如果你的组织对资源共享非常敏感，你可能希望考虑使用私有云。私有云本质上是仅供你的组织使用的保留资源——你在云内部的自己的小云。这种服务将昂贵得多，但它的风险也较少，并且应该让你的组织能够更好地定义云内发生的安全性、处理、数据处理等。

### 公有云

`public cloud`（公有云）一术是指是指云服务是在供公众使用的系统上提供的。在大多数情况下，公有云和私有云架构在操作上的区别很小，但安全影响可能是巨大的。尽管公有云服务将通过安全限制区分用户，但根据定义，这些限制的深度和程度在公有云中要少得多。

### 混合云

混合云结构是结合了私有云、公有云和社区云结构元素的结构。在检查混合结构时，你需要意识到在操作上，这些不同的环境可能并没有实际连接，而是一起使用。敏感信息可以存储在私有云中，与问题相关的信息可以存储在社区云中，所有这些信息由一个应用程序访问。这使得整个系统成为混合云系统。

### 社区云

社区云系统是几个具有共同利益的组织为了共同努力的特定目的共享云环境。例如，本地公共实体和关键当地公司可以共享一个专门用于服务社区倡议利益的社区云。这可以是特定数据共享倡议的一种极具吸引力的成本共享机制。

## 分层安全/深度防御

安全网络设计依赖于许多元素，关键元素之一是深度防御。深度防御是一种安全原则，通过采用多个、不同的安全元素来提高安全级别。如果攻击者能够绕过某项安全措施，重叠控制之一仍然可以捕获并阻止入侵。在网络中，可以以叠加的方式采用一系列防御，包括访问控制列表、防火墙、入侵检测系统和网络隔离，以实现保护。

### IPsec

IPsec 是由 IETF 开发的一组协议，用于在 OSI 模型网络层（第 3 层）安全地交换数据包（RFC 2401–2412）。尽管这些协议仅与 IP 网络配合，但一旦建立了 IPsec 连接，就可以跨越 OSI 模型中较低层次的网络进行隧道传输。IPsec 提供的安全服务发生在 OSI 模型的网络层，因此高层协议（如 `TCP`、`UDP`、`网络控制消息协议 (ICMP)`、`边界网关协议 (BGP)` 等）不会因为 IPsec 服务的实现而发生功能变化。

IPsec 协议系列设计用于提供广泛的服务，包括但不限于访问控制、无连接完整性、流量流机密性、拒绝重放数据包、数据安全（加密）以及数据源认证。IPsec 定义了两种方法——传输模式（transport）和隧道模式（tunneling），它们可提供不同级别的安全保护。IPsec 还有三种连接模式：主机到服务器、服务器到服务器以及主机到主机。

### IPsec 方法

传输方法仅对加密数据包的数据部分，因此外部人员可以看到源 IP 和目的 IP 地址。传输方法保护与数据包相关的高层协议并保护正在传输的数据，但允许传输过程本身被感知。对数据包数据部分的保护被称为 `content protection`（内容保护）。

隧道模式对源 IP、目的 IP 地址以及数据本身进行加密。这提供了最大的安全性，但只能在 IPsec 服务器（或路由器）之间进行，因为交付时需要知道最终目的地。对头部信息的保护被称为 `context protection`（上下文保护）。
