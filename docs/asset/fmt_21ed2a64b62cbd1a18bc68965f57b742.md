
| 应用安全 | 客户 | 客户 | 客户/服务提供商 |
|---|---|---|---|
| 平台安全 | 客户 | 客户/服务提供商 | 服务提供商 |
| 基础设施安全 | 客户/服务提供商 | 服务提供商 | 服务提供商 |
| 物理安全 | 服务提供商 | 服务提供商 | 服务提供商 |

*   **企业/客户责任**：云客户始终最终负责数据保护和账户访问控制 [23]。满足合规标准的要求对云服务提供商来说通常是一个挑战，因为他们必须遵守多项 IT 流程管理要求。重要的是要重申，云客户始终最终对适用的合规授令负责 [24]。
*   **云服务责任 (CSR)**：无论服务类型如何，云提供商始终负责保护数据中心所在的物理设施 [23]。
*   **按服务类型划分的责任**：监控和审计对于确保平台安全非常重要。IaaS 服务提供商仅管理设施；因此，客户负责实施必要的保护措施，以保护应用程序、虚拟机和数据。

尽管 PaaS 模型构建在 IaaS 模型之上，但云服务提供商负责操作系统 (OS) 维护，而客户负责数据和应用安全。在 PaaS 和 SaaS 模型中，当客户更新其安装的软件时，服务提供商共同承担更新硬件和确保适用安全控制的责任 [23, 24]。

## 云计算角色与职责

此外，了解云计算的各种属性和模型是必要的；但了解其主要角色和职责同样必要，如下所述 [21]。

*   **云服务提供商 (CSPs)**：云提供商是提供云服务的供应商。如前所述，此类实体拥有云计算数据中心，并管理其各种硬件、软件和人力资源，此外还负责监控服务提供和保障平台安全。云数据中心使云提供商能够构建、配置、部署和运营云服务 [21]。

### 云角色

*   **云客户**：云客户可以是购买或租赁各种云服务的个人或组织 [23]。
*   **云用户**：云用户通常指随时随地在线使用计算服务的用户或企业。值得注意的是，“云用户”一词主要指应用程序的最终用户；而云客户则是购买并支付云服务费用的一方。例如，当一个组织购买 Office 365 订阅供使用时，该组织扮演客户角色，而使用该服务的用户则是云用户 [21, 23]。
*   **云访问安全代理 (CASB)**：CASB 是一个安全执行点，位于最终用户和云之间，充当独立的第三方身份和访问管理执行者。CASB 作为监控和管理云资源访问的中心点 [10]。
*   **监管机构**：除了确保组织遵守其监管授权外，监管机构还维护组织的完整性。组织会接受监管机构在安全性和性能方面的审查 [23]。

## 云计算的优势

云计算为组织提供了许多好处。其中，成本降低是组织实施云存储解决方案所获得的主要收益，因为这些组织只需为所使用的服务付费。此外，云计算还能降低前期 IT 成本，并消除对负责维护服务器和本地基础设施的技术人员的需求。

多租户的概念是云计算的另一个方面，涉及多个用户共享服务器和应用程序。以分布式和共享的方式使用云，不同的用户和应用程序可以更高效地协同工作，并通过共享通用基础设施来降低成本。

由于数据和应用程序不再存储在本地，即使失去对台式机或笔记本电脑的访问权限，数据也将始终可用。此外，即使发生服务故障，数据也不会丢失，因为云服务提供商会有备份 [26]。

## 什么是 BaaS？

得益于区块链的分布式、不可篡改和透明特性，开发区块链应用程序的趋势近年来日益流行。作为引入 IT 行业的各种创新之一，区块链即服务 旨在支持云平台上的区块链功能。BaaS 概念是指一种基于云的“即服务”解决方案，旨在促进区块链平台的实施，允许用户从中央云构建、托管和管理区块链应用程序 [40]。

区块链即服务提供运营支持能力，就像 IaaS、PaaS 和 SaaS 云模型一样。BaaS 被视为区块链市场的一个重要里程碑，为分布式账本技术在商业世界的普及提供了强有力的机遇。此外，BaaS 的概念模型源自 SaaS 云计算模型 [32]。

通过采用 BaaS 模型，客户可以专注于业务网络的逻辑和工作流，从幕后硬件、软件和专业知识的责任中解脱出来，并将这些责任转移给服务提供商 [20]。目前市场上有多家 BaaS 服务提供商，如 IBM、Oracle 和 Microsoft，它们提供开箱即用或基于平台的 BaaS 解决方案。开箱即用的 BaaS 解决方案类似于可定制的 SaaS 解决方案，而基于平台的解决方案则允许客户自行管理和构建应用程序 [11]。一般来说，大多数大型公司提供的 BaaS 实现都使用开源项目，如以太坊、Hyperledger Fabric、Quorum 和 R3 Corda [20]。

### BaaS 模型如何工作？

要建立 BaaS 平台，组织需向服务提供商订阅区块链服务。区块链基础设施将按照客户需求进行设计，并由服务级别协议提供支持。该协议定义了带宽、监控、安全控制和基础设施维护的条款。根据客户的业务需求，服务提供商可基于任何分布式账本（如以太坊、Hyperledger Fabric、R3 Corda、Chain Core 或 Quorum）配置区块链网络。服务提供商随后代表客户实施必要资源并支持所需技术。因此，客户可以专注于业务，而非性能和网络问题 [32]。

在许多方面，Web 托管服务提供商和 BaaS 很相似。因为网站每天都会被许多用户访问，维护和基础设施问题可以由 Web 托管服务提供商（如 Amazon Web Services (AWS)、Microsoft Azure 或 Google）处理。同样，BaaS 使客户免于管理区块链应用程序的框架 [4]。

### BaaS 的优势

采用 BaaS 模型，公司无需投资在本地开发区块链平台，即可获得多项优势。这些优势将在下文讨论：

*   **成本与时间节约**：在本地实施区块链技术可能涉及大量的前期资本投资。即使投资后，如果结果不符合预期，组织可能会遭受资本损失 [29]。然而，在 BaaS 模式下，由于基础设施是外包的，公司无需投资进一步扩展组织 IT 基础设施。因此，客户无需在本地构建、管理和维护平台，从而节省了时间和金钱 [20]。
*   **人员成本降低**：由于实施 BaaS 架构所需的本地 IT 服务有限，客户的人员将不参与实施区块链所需的设备、电力和制冷管理。因此，招聘和培训员工的相关成本大幅降低，使组织现有的 IT 员工能够专注于业务需求。
*   **易用性**：BaaS 提供对可定制模板的快速访问，可轻松集成到现有应用程序中，无需从头构建架构 [32]。因此，即使不需要任何技术专长，也能更轻松地管理和操作平台 [27]。
*   **定价与客户支持**：通常，BaaS 服务提供商提供基于订阅的服务 [32]。因此，客户可以根据需求扩大或缩减服务级别，降低与按使用付费模型相关的风险。此外，BaaS 提供商为客户提供全方位的支持服务，包括系统的补丁管理、监控和升级 [20]。

### BaaS 面临的挑战

尽管 BaaS 在成本、人员和易用性方面具有诸多优势，但 BaaS 的采用也可能给组织带来挑战。

#### 隐私与数据合规

BaaS 的实施可能会产生隐私和数据合规问题。考虑到第三方为 BaaS 提供托管服务，数据可能存储在多个网络中，从而引发合规方面的担忧。虽然过去几年区块链法规有所增加，但监管机构仍需填补重要的区块链特定监管空白 [29, 32]。

#### 选择有限

目前，客户在选择 BaaS 服务提供商时，可选范围相对有限。例如，BaaS 主要由亚马逊、微软和甲骨文等大型公司主导，因为 BaaS 是一种基于云的服务 [29]。

#### 资源可用性有限

目前，市场上拥有区块链技术深度知识的人力资源有限。因此，缺乏适当规划和专业知识的资源可能会增加组织失败的概率 [32]。此外，区块链仍是一项新兴技术；因此，组织可能面临无法在其现有网络环境中正确实施所需 BaaS 需求的风险，这可能会增加 BaaS 计划集成相关的时间和成本 [29]。

#### 对 BaaS 的当前及预期未来的关注度

BaaS 通过增加对各种基于区块链技术项目的投资，推动了大大小小企业中区块链经济的市场增长。此外，去中心化应用的增加导致区块链技术在零售、金融和互联网银行等各个领域的使用不断上升。例如，大韩民国政府于 2019 年投资约 8 亿美元用于扩展区块链技术 [5]。

许多大型企业最近推出了其 BaaS 平台，包括 `IBM’s Blockchain` 和 `Amazon’s Managed Blockchain`。一般来说，提供区块链即服务的平台通常采用一种特定的区块链技术（如 `Hyperledger Fabric` 或 `Ethereum`）作为其底层平台。例如，微软 Azure 的 `Ethereum Blockchain-as-a-Service (EBaaS)` 是基于 `Ethereum` 框架构建的；而 `IBM’s blockchain` 则使用 `Hyperledger Fabric`。服务提供商管理 BaaS 环境，以确保基础设施的灵活性、可操作性和可访问性。此外，服务提供商持续开发 BaaS 工具，以满足不断增长的市场需求 [30]。

随着更多公司采用该技术，全球 BaaS 市场有望增长。市场覆盖亚太地区、非洲、中东、欧洲和拉丁美洲。在这些地区中，北美以 25.1 亿美元的市场规模领先，通过跨多个行业（包括金融服务、国防等）投资区块链解决方案。大量 BaaS 提供商还将区块链解决方案与人工智能 (AI) 和机器学习 (ML) 等先进技术相结合，以提升其安全功能。*Fortune Business Insight* 预测，全球 BaaS 市场规模将在 2027 年达到 249.4 亿美元，在预测期内复合年增长率 (CAGR) 为 39.5%。尽管如此，BaaS 对中小企业 (SMEs) 的多重优势预计将在未来引领市场发展 [5]。

由于在众多领域拥有巨大的潜在应用，BaaS 有望经历类似于 Web 应用的病毒式普及。区块链充当网络上共享信息的验证机制。Frontier Solutions 总裁 Reshma Murthy 表示：“BaaS 将发挥非常重要的作用。软件即服务和基础设施即服务刚刚作为节省原本过于昂贵资源成本的方式出现。BaaS 可以以同样的方式使用，并为组织提供了一个机会，在其行业内对区块链的接受程度尚未确定时尝试使用区块链” [20]。

## BaaS 与无服务器计算有何不同？

术语 `Function-as-a-Service (FaaS)` 通常指无服务器计算。`FaaS` 服务器为在无服务器环境中托管业务提供基本服务。无服务器计算的核心思想涉及由第三方处理资源分配，以及计算与存储的解耦、实例的扩展。

无服务器计算和 BaaS 共同点很少。与无服务器计算不同，BaaS 依赖有状态交易。与 BaaS 中智能合约实现加密签名且不可篡改的消息不同，`FaaS` 缺乏这一特性。然而，这两种技术都是分布式和事件驱动的 [39]。

## BaaS 服务端能力

区块链技术凭借其服务端功能，确保了数字交易的高度安全性和可靠性。如果没有适当的服务端安全性，任何恶意外部方完全访问系统的几率将会更高。

一般来说，去中心化应用是一种基于 `Ethereum` 的无服务器应用，它使用 HTML/JavaScript 前端并可与后端交互。去中心化应用 (DApp) 有两个组件：一个充当 `Ethereum` 网络上服务器的智能合约，以及一个供用户与智能合约交互的界面 [12]。

智能合约具有四个特性，包括可观察性、可验证性、隐私性和可强制执行性。这些属性通过创建高机密性、弹性和可扩展性，帮助智能合约记录交易。顺便提醒一下，智能合约平台的示例包括 `Hyperledger Fabric`、`Corda Enterprise` 和 `Ethereum`，后者在过去几年的使用量显著增加。每个智能合约具有不同的设置、共识机制和支持语言，以满足业务需求。智能合约提供用支持语言编写并在特定环境（如虚拟机和点对点网络）中执行的代币化功能 [22]。区块链数据库是一个验证数据库新增内容并可将新数据录入数据库的去中心化节点网络。通过达成共识，区块链免受篡改。开发人员可以使用区块链构建业务逻辑，并让该逻辑以特定编程语言编写、在执行环境中运行 [20]。

## BaaS 与 PaaS 有何不同？

虽然 SaaS 的概念是 BaaS 模型的核心，但由于基础设施支持的可用性，它可以在 PaaS 中显式重写 [27]。在考虑它们的相似点和差异时，比较 BaaS 和 PaaS 模型会变得更清晰。PaaS 模型用于创建应用程序，而无需管理其基础设施；而 BaaS 模型则利用区块链构建定制化应用程序 [38]。在成本降低、可扩展性和订阅制方面，BaaS 的优势与 PaaS 相似 [33]。与 BaaS 一样，PaaS 也让企业能完全控制应用程序开发，而无需担心基础设施和存储问题 [27]。BaaS 模型还提供其他益处，包括增强的数据安全性、透明度、隐私性和不可篡改性 [2]。通常，BaaS 服务将容器分发到云端，并利用它们创建点对点网络。这些容器包含作为分布式节点运行区块链所需的软件和数据 [20]。此外，BaaS 自行管理分叉和共识机制 [27]。

## BaaS 应用程序如何运行？

凭借其透明的本质，区块链技术通过在整个网络中向公众传递信息，提供了一个值得信任的环境，同时促进了信任与完整性。BaaS 在幕后提供了大部分应用程序和所需专业知识，使专注于业务逻辑变得更加容易。

目前，四个主要层构成了 BaaS 平台的当前架构，即应用层、中间件层、区块链框架层和区块链基础设施层。通常，每一层可被视为一个单独的容器，其中包含多个功能组件。图 15.1 展示了 BaaS 架构概览。

*   **应用层**：在 BaaS 架构中，应用层是用户与支持其后端的 BaaS 服务进行交互的最高层级。随着区块链技术从其作为加密货币基础的传统角色演变，不同类型的工具支持网络执行必要功能。与所有平台一样，区块链应用程序构建在区块链基础设施之上。包括 `Amazon`、`Oracle` 和 `Samsung` 在内的多家区块链提供商，为客户提供预定义或通用的应用程序以供直接使用 [19]。这种方法对开发者更高效，且不要求完全理解区块链的内部机制。因此，BaaS 提供商仅需部署运行在区块链基础设施上的去中心化应用程序。
*   **中间件层**：中间件层作为接口层，允许 BaaS 应用层在 BaaS 架构中与区块链框架层连接。资源调度、数据分析、监控和访问控制服务被视为在该层内执行的基本操作活动。资源调度算法用于确定如何分配有限资源以确保最大化利用率。监控服务监控和审计网络性能，通知开发者网络中可能存在的任何问题。此外，区块链数据也可被记录和分析以改进区块链应用程序。在 BaaS 实现中，访问控制可通过使用正确的授权和认证措施避免未经授权的数据访问，从而提供高保障。通过提供这些操作服务，中间件层使 BaaS 具有高可靠性和可扩展性。
*   **区块链框架层**：区块链框架层是智能合约的服务器，在 BaaS 架构中承载智能合约平台。智能合约运行在支持用特定语言编写的代币化程序的平台上，并在满足特定条件时自动执行。该层支持 `Ethereum`、`Hyperledger Fabric`、`R3 Corda` 和其他平台 [22]。

`Hyperledger Fabric` 是一种广泛使用的分布式账本技术。许多提供 BaaS 服务的提供商（如 `Huawei`、`Oracle` 和 `IBM`）均采用 `Hyperledger Fabric` 作为底层区块链平台。`Hyperledger Fabric` 是一个由 Linux 基金会和 `IBM` 管理的模块化区块链平台，在各个领域有众多应用。此外，`Hyperledger Fabric` 是一个许可型公共网络，新成员必须经过筛选和批准才能加入。因此，只有经过批准的网络成员才拥有访问权限。在企业级区块链解决方案的背景下，这些能力尤为宝贵。另一种分布式账本技术是 `Ethereum`，一种公共且无许可的协议。`Ethereum` 为各类应用程序和交易提供通用平台。在 DLT 提供商中，`Quorum`（`Ethereum` 的许可版本）促进了交易和智能合约的隐私保护。除了 `Ethereum` 和 `Hyperledger Fabric`，`R3 Corda` 也是一种许可型分布式账本技术协议，主要用于金融交易 [19]。

*   **区块链基础设施层**：就基础设施而言，大多数提供商在供应商提供的硬件上运行其区块链平台。典型设置包括在提供商的云产品中托管区块链。大型 IT 服务提供商通常提供此类设置，因为它们拥有现成的云基础设施。也可能存在提供商在第三方基础设施上托管 BaaS 的情况。例如，`IBM` 为客户提供在其云中托管 BaaS 或使用 `AWS` 等第三方基础设施的选择 [19]。一般来说，BaaS 架构要求区块链平台的开发和实施，这涉及一个需要计算资源来实现智能合约的分布式网络。计算资源可以是物理机或虚拟机，也可以是 `docker`。例如，`Ethereum` 智能合约利用虚拟机，而 `Hyperledger Fabric` 智能合约则使用 `dockers`。智能合约应保持在沙箱中隔离，以防止病毒或漏洞的传播。区块链增长的两大限制是：部署区块链基础设施的复杂性，以及高昂的相关运营和维护成本。然而，BaaS 摒弃了搭建基础设施的繁琐任务，使开发者能够专注于应用程序 [22]。

### 共识机制

大多数 BaaS 服务采用崩溃容错（CFT）或拜占庭容错（BFT）。目前，Hyperledger Fabric 提供的 BaaS 最常用的共识机制是 `Kafka` 和 `Raft`，两者均为 CFT 排序服务。CFT 设置指定一个被假定为可信的领导节点。由于网络中的所有节点都将复制领导者的条目，因此领导者必须值得信任。由于 CFT 共识或排序服务仅可由获得授权的人员访问，因此领导者被推定为可信。如果当前领导者崩溃，将指定新领导者。通过利用交易终局性，CFT 还有助于加快共识进程。基于 Hyperledger Fabric 构建时，`Alibaba`、`Amazon`、`Huawei`、`Oracle`、`SAP`、`IBM` 和 `Samsung` 可使用 Kafka CFT，而 `Raft` 仅由 `Baidu` 提供。
