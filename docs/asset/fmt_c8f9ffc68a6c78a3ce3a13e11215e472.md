## RDS 只读副本与性能优化

### 127. 为什么要跨所有可用 AZ 配置只读副本，而不是将它们配置在与主数据库源相同的区域？

1. 拥有全球客户群。
2. 想确保灾难恢复。
3. 想最大化网络吞吐量。
4. 绝不应在主数据库实例所在区域之外配置只读副本。

### 128. 为什么要在与主数据库实例相同的单一区域内跨所有可用 AZ 配置只读副本，而不是跨所有 AWS 区域配置？

1. 拥有全球客户群。
2. 想确保灾难恢复。
3. 拥有靠近目标区域的本地化客户群。
4. 绝不应在主数据库实例所在的同一区域内配置所有只读副本。

### 129. 所有客户都在单一地理区域，您已在该区域的 AZ 中创建了数据库实例和多个只读副本。在额外区域创建副本是否有价值？

1. 没有价值。
2. 有，在另一区域拥有副本可获得某些灾难恢复优势。
3. 有，因为客户请求数据时可能被路由到不同区域。
4. 有，因为 S3 存储桶也在不同区域。
