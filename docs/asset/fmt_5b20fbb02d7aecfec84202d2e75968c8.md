
考虑以下查询：列出家族及每个家族中的粒子数量。这可以用 SQL 表述如下。在本节中，结果表的列标题下用连字符划线（这是大多数 SQL 的典型做法）。

```sql
select family, count(*)          →                    family      count(*)              - - 函数表头
from   Particle                                                                - - - - - - - - - - - - - - - - - -          - - 部分 SQL 中可省略
group by family                                                       baryon         8                             - - in some SQLs
                                                               lepton           4
                                                               meson         7
```

这里，`group by` 子句指示将粒子按家族*分组*（即，具有相同家族名称的粒子被放在同一组中）。然后将 `select` 列表中的*项目应用于每个组作为一个整体*。

## SQL 分组与聚合

### Count 函数与列标题

如果使用 `count(*)`，它将返回组中的行数。在本例中，我们有八个重子、四个轻子和七个介子。如果在 `select` 列表中使用的表达式不是列名，某些 SQL 实现会将该表达式作为结果中的列标题（如此处所示），而其他实现（包括 SQL Server）则会省略列标题。通常最好在表达式后使用 `as` 子句来提供您自己的标题。

### GROUP BY 的默认排序

在许多 SQL 版本中，使用 `group by` 会导致默认排序，这相当于匹配的 `order by` 子句（本例中即 `order by family`）。然而，这并不属于 SQL 标准。`group by` 子句的语法是：

```
group by col-name [, ...]
```

同一组的成员必须在 `group by` 子句中指定的所有列上具有匹配的值。

### 按多列分组

下一个示例将粒子分组，要求它们具有相同的家族名称和相同的电荷。

```
select family, charge, count(*) as tally        →                    family          charge          tally
from Particle                                                                                                        - - - - - - - - - - - - - - - - - - - - - - - - - -
group by family, charge                                                                           baryon                     −1                 2
order by family, charge                                                                            baryon                       0                  4
                                                                                         baryon                       1                 2
                                                                                         lepton                      −1                  2
                                                                                         lepton                        0                  2
                                                                                         meson                     −1                 2
                                                                                         meson                       0                  3
                                                                                         meson                       1                  2
```

如果使用多列进行分组，这些列的指定顺序与结果的内容无关。这是因为必须形成相同的分组集合。例如，如果我们按属性 `a, b` 或 `b, a` 分组，那么值为 `a` = a1、`b` = b1 的组与值为 `b` = b1、`a` = a1 的组是相同的，以此类推。

然而，如果行顺序基于分组顺序，结果中的行顺序可能会不同。例如，以下查询返回与前一个查询相同的行，但顺序不同。您可以调整 `order by` 子句来更改顺序：

```
select family, charge, count(*) as tally        →                    family          charge          tally
from Particle                                                                                                         - - - - - - - - - - - - - - - - - - - - - - - - -
group by charge, family                                                                           baryon                    −1                  2
order by charge, family                                                                            lepton                      −1                  2
                                                                                                                                                     meson                     −1                  2
                                                                                                                                                     baryon                       0                 4
                                                                                                                                                     lepton                        0                  2
                                                                                                                                                     meson                       0                 3
                                                                                                                                                     baryon                       1                  2
                                                                                                                                                     meson                       1                  2
```

### 在 ORDER BY 中使用别名

如果 `select` 列表中的函数调用被用作排序标准，您应该为其引入别名，以便在 `order by` 子句中通过名称引用它。例如，以下查询列出每个家族及其最轻粒子的质量，并按该最小质量排序。作为一种不推荐的替代方案，您可以按其在 `select` 列表中的位置引用它（例如 `order by 2`）。

```
select family, min (mass) as minMass         →         family      minMass
from Particle                                                                                               - - - - - - - - - - - - - - - - - -
group by family                                                                                        lepton                       0
order by minMass                                                                                 meson               264
                                                                                                                                            baryon            1836
```

### GROUP BY 与 SELECT 列表的限制

使用 `group by` 子句意味着 `select` 列表中的项目将作为一个整体应用于每个组，每个组仅返回一个值。因此，`select` 列表中提到的任何列必须是分组列，或者必须作为内置函数的参数出现在那里（如前面查询中的 `family` 和 `mass`）。因此，在执行分组时，将非分组列作为整体项目包含在 `select` 列表中是毫无意义的，实际上也是非法的。例如：

```
select family, mass from Particle     →     Error!
group by family
```

因为同一个家族可能包含多个质量不同的粒子，这个请求显然很愚蠢（我们该选哪个质量？）。然而，我们可以通过使用内置函数（如 `min(mass)` 或 `avg(mass)`）来获得与质量相关的单个分组值，就像前面的查询那样。

虽然 `select` 列表不得包含任何非分组列，但按 `select` 列表中未提及的列进行分组是合法的。例如，以下查询列出了每个家族的最小质量，但不列出家族名称。

```
select min (mass) as minMass          →      minMass
from Particle                                                                            - - - - - - - - -
group by family                                                                                        0
                                                                                                                                     264
```

### SQL 分组查询：WHERE、HAVING 与关系除法

在 `select` 语句中，可以包含 `where` 子句，在分组形成和函数应用之前过滤掉不需要的行。合理地，`where` 子句必须放在 `group by` 子句之前。例如，以下查询列出了每个家族及其不带电粒子的平均质量。为了适配 SQL Server 等会截断平均值的方言，质量通过乘以 `1.0` 强制转换为 real 类型，并使用 `cast` 函数仅显示小数点后两位。请注意，将标量函数应用于聚合函数（例如 `cast(avg(...))`）是合法的。但是，将聚合函数应用于聚合函数（例如 `min(avg(...))`）是非法的。

```sql
select family, cast (avg (1.0*mass) as decimal (6,2)) as avgUnchargedMass
from   Particle
where charge = 0
group by family
```

**结果：**

| family | avgUnchargedMass |
| :--- | :--- |
| baryon | 2232.25 |
| lepton | 0.00 |
| meson | 770.65 |

有时，我们希望将注意力限制在仅满足特定条件的那些组上。正如 `where` 子句可用于对单个行施加搜索条件一样，`having` 子句可用于对单个组施加搜索条件。在这种情况下，`having` 子句必须紧跟在它逻辑上关联的 `group by` 子句之后。语法如下：

```sql
group by col-name [, ...]
having group-condition
```

搜索条件的常规规则适用。逻辑运算符和比较运算符可以包含在条件中。每个比较将组的某个属性（如 `min(mass)`）与常量或另一个组属性进行比较。（虽然罕见，但可以在没有关联 `group by` 子句的情况下包含 `having` 子句；在这种情况下，整个表被视为一个组。）作为一个简单的例子，以下查询列出了粒子数超过四个的家族，以及每个家族的粒子数。虽然在 `having` 子句中允许别名（如 `tally`）讲得通，但在许多 SQL 实现中（如 SQL Server）这是不允许的。

```sql
select family, count (*) as tally
from Particle
group by family
having count (*) > 4
```

**结果：**

| family | tally |
| :--- | :--- |
| baryon | 8 |
| meson | 7 |

下一个示例更难。为了帮助阐明其工作原理，添加了数字 1 到 6 以指示查询行的处理顺序。这些数字不是查询的一部分。请自行跟踪步骤以确保你遵循此顺序。关于 `having` 子句，请注意：带电轻子被包含在内（不带电且质量为零的轻子被 `where` 子句过滤掉了），而带电重子被排除在外（它们的最大质量超过 2000）。

> **需求：** 仅考虑带电粒子，按相同的家族名称形成组，其中该组最轻粒子的质量大于 0 且最重粒子的质量小于 2000。列出每个组的家族名称、粒子数量和最大质量，成员较多的组优先显示。
