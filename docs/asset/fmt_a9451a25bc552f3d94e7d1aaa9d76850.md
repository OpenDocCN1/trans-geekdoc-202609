
攻击者可以通过在第 1 步（检查时间）和第 2 步（使用时间）之间，将文件“test”从普通文件更改为符号链接（类似于桌面快捷方式），来读取系统上的任意文件：

1. 如果文件“test”可被用户读取
2. 攻击者删除“test”，创建从“test”到 `/etc/shadow` 的符号链接
3. 运行另一个进程
4. 然后打开文件“test”（现在是指向 `/etc/shadow` 的符号链接）

如果攻击者赢得了竞争（在“if”和“then”之间更改了“test”的状态），“test”就是一个指向 `/etc/shadow` 的符号链接。该 setuid root 程序将打开该符号链接，从而打开 `/etc/shadow` 文件。

### 跨站脚本和跨站请求伪造

跨站脚本攻击（XSS）利用受信任站点的安全上下文，执行第三方 Web 脚本语言（如 JavaScript）。跨站请求伪造（CSRF，有时也称为 XSRF）利用受信任站点的安全上下文，重定向第三方静态内容。跨站脚本攻击和跨站请求伪造经常被混淆。它们都是 Web 攻击：区别在于 XSS 在受信任的上下文中执行脚本：

```
<script>alert("XSS Test!");</script>
```

上述代码会弹出一个无害的“XSS Test!”警告框。真实的攻击会包含更多 JavaScript，通常用于窃取 Cookie 或认证凭据。XSS 还可用于“挂马”浏览器，这允许攻击者远程控制用户的浏览器，并以此为跳板。跳板允许攻击者在“敌后”（防火墙内部）建立立足点，并访问内部网站等。要了解更多关于此概念的信息，请参阅 BeEF（浏览器利用框架项目）项目，网址为 [`beefproject.com/`](http://beefproject.com/)。

CSRF 通常诱骗用户处理一个 URL（有时通过在 HTML 图像标签中嵌入该 URL），从而执行恶意行为，例如，诱骗白帽黑客渲染以下图像标签：

```
<img src=”https://bank.example.com/transfer-money?from=WHITEHAT&to=BLACKHAT”>
```

### 权限提升

*权限提升*漏洞允许拥有（通常是有限）访问权限的攻击者能够访问额外的资源。垂直提升利用非特权访问获取更高级别的访问权限。一个例子是将权限从普通 UNIX 用户提升为 root 访问权限（UID 0）。

水平提升允许攻击者访问其他账户，例如从一个非特权账户跳转到另一个非特权账户（该账户拥有不同资源的访问权限）。

不当的软件配置以及糟糕的编码和测试实践往往会导致权限提升漏洞。

### 后门

后门是系统中的捷径，允许用户绕过安全检查（如用户名/密码认证）进行登录。攻击者在攻陷系统后通常会安装后门。例如，攻击者通过利用缺失补丁导致的漏洞获得了系统的 Shell 访问权限。攻击者希望维持访问权限（即使系统打了补丁），因此她安装了一个后门以允许未来的访问。

## 软件能力成熟度模型集成 (CMMI)

软件*能力成熟度模型集成*（CMMI）是一个用于评估和改进软件开发过程的成熟度框架。卡内基梅隆大学（CMU）软件工程研究所（SEI）开发了该模型。现在由 CMMI 研究院管理：“CMMI 最初是在软件工程研究所开发的，该研究所是卡内基梅隆大学内部一个联邦资助的研发中心。2016 年，CMMI 研究院被 ISACA 收购” [\[32\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0165)。

CMMI 的目标是开发一种系统化的框架，用于创建高质量软件，从而实现可度量和可重复的结果：“即使在非规范化的组织中，某些个别软件项目也能产生优秀的结果。当此类项目成功时，通常是通过一个专门团队的英勇努力，而不是通过重复成熟软件过程组织的经验证方法。在缺乏组织级软件过程的情况下，重复成功完全取决于下一个项目是否有相同的人员可用。仅依赖特定个人可用性的成功，无法为组织的长期生产力和质量改进提供基础。持续改进只能通过专注且持续的努力，建立有效的软件工程和管理实践的过程基础设施来实现” [\[33\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0170)。

CMMI 的五个级别描述如下（参见 [`resources.sei.cmu.edu/library/asset-view.cfm?assetid=11955`](https://resources.sei.cmu.edu/library/asset-view.cfm?assetid=11955)）：

1. *初始级*：软件过程的特点是临时性的，甚至偶尔是混乱的。很少定义过程，成功取决于个人努力。
2. *可重复级*：建立了基本的项目管理过程来跟踪成本、进度和功能。必要的过程规范到位，能够在具有类似应用的项目上重复早期的成功经验。
3. *已定义级*：管理和工程活动的软件过程已文档化、标准化，并整合为组织的标准软件过程。项目使用组织标准软件过程的经批准、剪裁版本来开发和维护软件。
4. *已管理级*：收集、分析并使用软件过程和产品质量的详细度量来控制过程。软件过程和产品都能被定量地理解和控制。
5. *优化级*：通过来自过程的定量反馈以及试点创新想法和技术，实现持续的过程改进 [\[33\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0170)。

## 验收测试

验收测试测试软件是否满足来自用户或客户、合同或合规视角的各种最终状态需求。ISTQB（国际软件测试资格委员会）将验收测试定义为：“一种正式测试，针对用户需求、要求和业务流程进行，以确定系统是否满足验收标准，并使用户、客户或其他授权实体能够决定是否接受该系统” [\[34\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0175)。

ISTQB 还列出了验收测试的四个级别：

* **用户验收测试**：主要关注功能，从而验证系统对业务用户的**适用性**。用户验收测试由用户和应用程序管理员执行。
* **运营验收测试**：也称为生产验收测试，验证系统是否满足运行要求。在大多数组织中，运营验收测试由系统管理员在系统发布前执行。运营验收测试可能包括备份/恢复测试、灾难恢复、维护任务以及安全漏洞的定期检查。
* **合同验收测试**：针对合同的验收标准执行，用于定制开发的软件。验收标准应在商定合同时正式定义。
* **合规验收测试**：也称为法规验收测试，针对必须遵守的法规执行，例如政府、法律或安全法规” [\[35\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0180)。

## 评估所获取软件的安全影响

我们希望能够信任供应商关于产品能力的声明。在被证明为真之前，供应商的声明应被视为营销宣传。不要仅依赖供应商的声明，即使是关于基本能力的声明。

一个重要的观点是在评审产品**之前**收集需求。如果在评审产品**之后**才定义需求，供应商可能会说服组织，使其认为自己有特定需求，而只有该供应商的产品能满足。不要让产品或营销决定组织在产品中“需要”什么。

### 商用现成软件 (COTS)

对于商用现成软件 (COTS)，供应商的声明更容易验证。对于 COTS，应进行**实地对比测试**，比较已满足需求的产品。不要依赖产品路线图会成为现实。一个特别重要的安全需求是寻找与现有基础设施和安全产品的集成能力。虽然**最佳单品**可能是组织的总体偏好，但要认识到增加一个管理控制台（以及随之而来的额外用户配置）会增加产品的运营成本。要考虑产品的**总拥有成本 (TCO)**，而不仅仅是资本支出和年度维护成本。

由于产品可以被评估以确定其是否提供声称的能力，因此对于 COTS 软件，供应商的声明更容易验证。

第三方研究和分析机构提供特定领域各参与者的评估，这可以在不需要大量内部测试的情况下提供产品的基本（尽管可能有偏见）对比。

通常可以联系供应商的客户。当然，如果这些联系人是由供应商自己提供的，那么在接受其声明时要谨慎。更好的方法是自行寻找正在使用该产品的人，并询问他们的优缺点及喜好/厌恶。

针对 COTS 的一些问题/顾虑：如果供应商倒闭了怎么办？如果缺少关键功能怎么办？寻找供应商产品的内部或第三方支持有多容易？

### 定制开发的第三方产品

COTS 的替代方案是采用定制开发的应用程序。这些定制开发的第三方应用程序提供了超越 COTS 的额外风险和潜在收益。在与第三方开发商打交道时，合同条款和**服务级别协议 (SLA)** 至关重要。除非合同强制要求提供安全能力，否则永远不要假设安全性会成为产品开发过程中的一个考量因素。

应在签署合同和制定 SLA **之前**讨论基本安全需求，以确保供应商预期能够交付这些能力。与 COTS 非常相似，关键问题包括：如果供应商倒闭了怎么办？如果缺少关键功能怎么办？寻找供应商产品的内部或第三方支持有多容易？

## 人工智能

计算机进行计算：它们完全按照指令行事。“计算机”一词最早于 1613 年被用来描述从事加法运算的人。人工智能是让电子计算机更“智能”地“思考”的科学，有时模仿哺乳动物大脑的能力。

### 专家系统

*专家系统*由两个主要组件组成。第一个是*知识库*，由“如果/那么”语句组成。这些语句包含专家系统用于做决策的规则。第二个组件是*推理引擎*，它遵循知识库形成的树状结构，并在有匹配时触发规则。

下面是一个示例“互联网中断”专家系统，当用户致电抱怨无法访问互联网时，服务台可能会使用它：

1. **如果您的计算机已开启**
   * 否则：开启您的计算机
2. **那么如果您的显示器已开启**
   * 否则：开启您的显示器
3. **那么如果您的操作系统已启动且您能打开 `cmd.exe` 提示符**
   * 否则：修复操作系统
4. **那么如果您能 ping 通 `127.0.0.1`**
   * 否则：检查网络接口配置
5. **那么如果您能 ping 通本地网关**
   * 否则：检查本地网络连接
6. **那么如果您能 ping 通互联网地址 `192.0.2.187`**
   * 否则：检查网关连接
7. **那么如果您能 ping 通 `syngress.com`**
   * 否则：检查 DNS

**正向链接**从无前提开始（在前面的示例中为“计算机是否开启”），向前推导以确定解决方案。**反向链接**从一个前提开始（例如“可能是 DNS 坏了”），向后推导。

知识库的完整性至关重要。整个知识库应形成一棵逻辑树，始于一个树干（在前面的示例中为“计算机是否开启”）。知识库随后应分支展开。推理引擎遵循这棵树，根据如果/那么语句的回答进行分支或触发。

不应有循环规则；使用前面示例的一个循环规则例子：“如果您的计算机已开启，那么如果您的显示器已开启，那么如果您的操作系统已启动且您能打开 `cmd.exe` 提示符，那么如果您的计算机已开启……”。也不应有未引用的规则（不连接到知识库树的分支）。

### 人工神经网络

人工神经网络 (ANN) 模拟人类和动物大脑中的神经网络。人脑的神经网络拥有 1000 亿个神经元，每个神经元通过数千个或更多突触相互连接。每个神经元可能会根据突触输入而激发。这种多层神经网络能够基于数千个或更多输入做出单一决策。

#### 真实神经网络

让我们来讨论真实神经网络是如何运作的：想象你在深夜独自走在城市的街道上，有人紧跟在你身后。你开始变得紧张：时间很晚；四周很暗；身后的人离你太近了。你必须做出决定：战斗还是逃跑。你必须决定是转身面对追逐者，还是设法摆脱他们。

在你做决定的过程中，你在权衡成千上万的输入。你回忆起过往经历；你的本能指引着你，你通过五官感知世界。这些感官每毫秒都在向你的大脑发送新的输入。你的记忆、本能、视觉、嗅觉、听觉等，都在持续不断地向神经元发送突触输入。不太重要的输入（在这种情况下如味觉）具有较低的突触权重。更重要的输入（如听觉）具有较高的突触权重。接收到较高输入的神经元更有可能激发，最终输出神经元激发（做出决定）。

最后，你决定转身面对追逐者，欣慰地发现那只是一个戴着耳机听音乐的人，并没有注意周围环境。成千上万个输入导致了一个二元决定：战斗还是逃跑。人工神经网络（ANN）旨在复制这一复杂的决策过程。

#### 人工神经网络如何运作

ANN 旨在复发生物神经网络的能力。节点用于描述人工神经元。与其生物对应物一样，这些节点从突触接收输入，并在超过某个权重时发送输出。单层 ANN 有一层输入节点；多层 ANN 拥有多层节点，包括隐藏节点，如图 9.13 所示。图 9.13 中的箭头代表突触权重。单层和多层人工神经网络最终都会触发一个输出节点激发：这个输出节点做出决定。

#### 贝叶斯过滤

贝叶斯过滤以托马斯·贝叶斯命名，他是一位英国牧师，设计了多种概率和统计方法，包括“一种用于计算条件概率的简单数学公式”[\[36\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0185)。

贝叶斯过滤常用于识别垃圾邮件。保罗·格雷厄姆在其论文《垃圾邮件计划》（见 [www.paulgraham.com/spam.xhtml](http://www.paulgraham.com/spam.xhtml)）中描述了利用贝叶斯过滤识别垃圾邮件的方法。他描述了使用“语料库”中的“垃圾邮件”和“正常邮件”，即人工挑选的垃圾邮件组和非垃圾邮件组。然后，他利用贝叶斯过滤技术自动分配一个数学概率，判断某些“标记”（邮件中的词汇）是否为垃圾邮件的指征。

#### 遗传算法与编程

遗传算法与编程从根本上改变了软件的开发方式：软件不再由程序员编写，而是通过进化来解决问题。遗传算法与编程旨在复制自然界的进化过程，即动物通过进化解决问题。遗传编程指创建完整的软件程序（通常以 Lisp 源代码形式）；遗传算法指创建较短的代码片段（表示为称为染色体的字符串）。

两者都是自动生成的，然后通过多代“繁殖”，遵循达尔文原则进行改进：“遗传算法是基于自然选择和自然遗传学机制的搜索算法。它们将字符串结构中优胜劣汰的生存法则与结构化但随机的信息交换相结合，形成了一种具有人类搜索某些创新才能的搜索算法。在每一代中，利用旧种群中最优秀个体的片段创建一组新的人工个体（字符串）；偶尔会尝试一些新部分以求万全。虽然具有随机性，但遗传算法绝非简单的随机漫步。它们高效地利用历史信息，推测具有预期改进性能的新搜索点”[\[37\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0190)。

遗传编程创建随机程序并分配给它们解决问题的任务。`fitness function`（适应度函数）描述它们执行任务的效果如何。`Crossover`（交叉）将两个程序“杂交”在一起（交换它们的代码）。`Mutation`（变异）在某些程序中引入随机变化。约翰·R·科扎在《遗传编程：通过自然选择实现计算机自主编程》中描述了这一过程。该过程总结如下：

* “生成初始随机计算机程序种群。
* 执行种群中的每个程序，并根据其解决问题的效果分配适应度值。
* 创建新的计算机程序种群。
  * 复制现有的最佳程序。
  * 通过变异创建新的计算机程序。
  * 通过交叉（有性生殖）创建新的计算机程序”[\[38\]](#Ch009_459-508_B9780443187346000088.xhtml#bb0195)。

遗传算法和遗传编程已被用于编写吃豆人游戏程序、机器人足球队、网络入侵检测系统等众多应用。

## 考试目标总结

我们生活在一个日益计算机化的世界中，软件无处不在。软件处理的数据的机密性、完整性和可用性至关重要，软件自身的正常功能（可用性）同样关键。本领域展示了软件如何工作，以及程序员在试图编写无错误代码以保护数据（和软件本身）抵御攻击时面临的挑战。

遵循正式的软件开发方法论，并辅以严格的测试制度，是最佳实践。我们已经看到，遵循软件开发成熟度模型（如能力成熟度模型集成 CMMI）可以显著降低程序员犯错的数量。CMMI 的五个步骤遵循了大多数编程组织遵循的过程，从非正式过程到总是寻求改进的成熟过程：初始级、可重复级、已定义级、已管理级和优化级。
