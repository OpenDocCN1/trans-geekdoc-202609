
由于没有中心权威指导所有其他节点达成共识，它们必须独立这样做。节点如何在没有中心权威的情况下达成共识？在比特币和以太坊的情况下，矿工节点玩一种被称为密码哈希概率游戏，即工作量证明，以赢得奖励并将提议的区块添加到区块链。

为了赢得游戏，矿工节点必须猜一个称为 `nonce` 的数字，该数字与区块链中所有之前的数据结合，在通过 `SHA-256` 函数时输出一个哈希值（或数字指纹）。加密哈希函数获取数据并将其转换为很长的字母和数字字符串。第一个猜出正确 `nonce` 的矿工获得创建下一个区块的权利。只有特定的 `nonce` 结合经过验证之前的区块链数据才会产生正确的哈希。如果输入不准确或欺诈的先前记录，则无法猜出正确的哈希。

工作量证明是比特币、以太坊和达什等使用的最广知的共识机制。其他共识机制包括权益证明（PoS）、委托权益证明（DPoS）和时间证明（PoET）。工作量证明机制比其他机制经历了更多的市场、技术和智力审查。以太坊从 2.0 版本开始转向权益证明共识。

权益证明不依赖奖励来实现安全性，而是依赖惩罚。验证者质押资金（押金），并获得作为锁定资金和维护节点的补偿。验证者还为确保私钥安全的采取额外预防措施获得奖励，但撤销交易的大部分成本来自惩罚，这些惩罚是其所获得奖励的数百或数倍。

你为什么需要担心哪种共识机制比另一种更好呢？如果客户问你概念验证或试点项目应该使用哪种机制，你会怎么说？大多数时候，我会告诉他们这并不重要，因为测试项目是在受控环境中进行的，而且所有上述共识机制都能在有限测试节点的受控环境测试中实现高吞吐量和高频率。

我们将看到更多的共识机制进入生态系统，包括对现有机制的改进，例如 `Lightning` 和 `Plasma`。由于全球范围内开发和采用的增加，我们不再处于共识机制的黄金时代。

我经常被问：“如果我部署了智能合约并发送交易，谁来为挖矿付费？”“我必须支付挖矿费吗？”尽管这听起来是一个初学者的问题，但对于运营以终端用户为中心的平台的人来说，这实际上是合理的。终端用户并不熟悉 `Ethereum` 和 `Bitcoin` 等公链，也不了解参与者是如何获得财务激励的。因此，如果你熟悉这些内容，请随时跳过本节。

让我们逐个问题或逐个用例来解决这个问题。如果你在 `Ethereum` 主网上添加一个智能合约，你只需要支付创建智能合约的极小费用。当你向智能合约发送交易时，你需要支付交易费用，金额仅为几分钱。你不需要支付“挖矿”费。验证交易并将其添加到区块的矿工会获得网络的奖励，他们也会获得交易费。

对于一个编写了数千个智能合约和数百万交易的应用来说，将所有智能合约和交易费用加起来，成本可能会非常巨大。然后我会被问：“你们如何处理不断上升的交易成本？”我回答：“就像我们处理交易成本下降的方式一样”，要么将成本转给用户，要么将其作为行政/基础设施成本吸收。

上述所有观点都基于你使用的是公链，例如 `Ethereum`、`EOS` 或 `NEM`。如果你使用 `Ethereum` 节点的私有网络或 `Hyperledger`，则不存在挖矿或交易费用，因为这些节点由财团或单一实体管理，不需要经济激励来挖掘区块或保持交易的不可篡改性。

### 智能合约

`Ethereum` 的意义过去是现在也是，它提供了一个基于区块链的平台，利用底层加密货币作为网络安全和治理的金融工具来编写合约。`Ethereum` 体现了经济与加密融合的概念，正如 Szabo 先生在他 1996 年的文章中所理论化的样。公链上的其他智能合约平台包括 `EOS`、`Stellar` 和 `Cardano`。`Rootstock`、`Corda` 和 `Hyperledger Fabric` 等项目被广泛使用。

简单来说，智能合约是存储在区块链上的代码，其条款是不可篡改的。由于智能合约存储在区块链上，它提供了真实性并可以在双方之间转移代币。智能合约还根据代码中编码的逻辑持有数字资产。

`Ethereum` 智能合约的典型结构所示：

编写合约代码 -> 部署到区块链 (`Ethereum`) -> 接收合约代码已部署的通知 -> 与合约交互（输入参数） -> 支付 gas 费用

当智能合约部署后，它们会被正式添加到区块链上，任何拥有合约地址的人都可以与其交互。合约也可以由合约创建者销毁。

最常见的智能合约处理双方之间的货币交易。典型智能合约中某些接收同质化代币、持有余额或发送代币的功能使用了 `ERC-20` 标准：

- `totalSupply()` 返回智能合约持有的代币总量。
- `balanceOf(address)` 返回给定地址的代币余额。
- `transfer(address, unit)` 将代币转移给给定地址，只要调用函数的 `msg.sender` 有足够的币可以发送，就会返回 true。

第二类智能合约不涉及货币交易，而是根据逻辑提到的条件将资产从一个参与者转移给另一个。例如，它展示了将集装箱所有权从发运人转移到承运商，或者为立法或董事会成员投票：

```
address public shipperAddress
address public carrierAddress
address public consigneeAddress
string containerID
```

`containerTransfer(address from, address to, containerID)` 事件将 `containerID` 从发运人的公共地址分配到承运商的地址，并记录在区块链上。同样地，同一个函数可以将集装箱转移给收货人，如果成功，智能合约可以将代币从初始供应量转移到承运商地址。

可以说区块链的出现是因为运行在区块链上的加密货币，这并不是一个误读。近期，出现了两种观点。一派认为，如果没有加密货币的采用，区块链是毫无意义的；另一派则认为，加密货币是一种麻烦，或者是一个庞氏骗局；然而，他们坚持认为区块链技术本身是革命性的。

无论你属于哪一派，让我们来谈谈加密货币最初存在的原因。我们还将探讨当一个无许可区块链应用没有加密货币时会发生什么。稍后我们将深入探讨博弈论，这涉及到保持开放网络持续性的经济激励概念。最后，我们将绕个路描述加密货币（coin）与代币（token）之间的区别。

## 加密货币的角色

加密货币除了是一种金融工具外，还是每个网络诚实参与者积极行为的经济激励。积极行为是公共、无许可区块链中不可或缺的一部分。加密货币通过确保诚实的网络参与者因验证交易和添加新区块的工作获得无偏奖励，从而威慑了不诚实参与者的计算攻击。

在 `Bitcoin` 中，每 10 分钟链上就会添加一个区块。能够将该区块添加到网络的矿工将获得底层协议奖励的 `X` 数量的 `Bitcoin`，称为区块奖励。添加区块需要矿工消耗计算能力资源。没有经济激励，挖矿活动将无法维持。在许多方面，区块链用户正在为不可篡改性以及这种安全感买单——这种安全感源于：诚实参与者正在维护底层区块链的安全，免受区块攻击的想法。

## 币 (Coins) 与 代币 (Tokens)

从 2015 年开始，我们开始在区块链领域看到“代币”（token）一词出现，它经常与“币”（coin）交替使用。代币是数字资产，或者是一种加密货币，它们构建在已经拥有自己加密货币的开放区块链之上。因此，“币”一词通常指任何具有自己独立、单独区块链的加密货币。

代币没有自己的区块链，但在 `Ethereum`、`Waves` 等现有基础设施上，使用 `ERC-20`、`ERC-721` 等协议构建。代币也是支持 `dApps`（或去中心化应用）的数字资产。代币本身没有内在价值，但代表了 `dApp` 或项目内部的利用价值。在底层应用生态系统中具有特定用途的代币也被称为实用代币（Utility Tokens）。代币并不代表构建应用的公司和/或发行代币的实体的所有权。

`Bitcoin` 和 `Litecoin` 等币通常是有上限的或固定的，并带有一个很小的通胀因子作为维护区块链的奖励。与币不同，机构并不被禁止发行更多代币，这可能会稀释流通现有代币的价格。为什么有人要努力在现有区块链上创建代币呢？简单因为创建它很容易。在 `Ethereum` 中，可以使用智能合约通过几行代码来定义代币。智能合约本质上定义了代币的总供应，并促进交易以显示谁拥有多少代币。在现有区块链上创建代币的缺点是，该代币依赖于网络的底层区块链，因此依赖于其他对区块链进行技术改进的团队。今天有越来越多的代币被创建，以代表物理和数字资产，如发票、股票、债务、房地产和存储空间。

## 梅尔克树 (Merkle Trees)

区块链中一个迷人的概念是：矿工如何在不遍历区块链下方数百个区块的情况下，验证多年前存储的交易？我们知道所有区块都是线性且顺序地链接到另一个的。答案在于一种在 `Bitcoin` 之前发明的数据结构，称为 `Merkle Tree`。

图 3.9 显示了一个简化的 `Merkle Tree`。有四个独立区块的唯一哈希值或数字指纹（它们可以由一个或多个单独交易组成）。在 `Merkle Tree` 术语中，这些数字指纹被称为叶节点。然后将前两个哈希合并为一个哈希（`H1`）。另外两个区块执行相同的操作。然后将这两个哈希（`H1` 和 `H2`）再次合并并哈希，创建所谓的根哈希（`H3`）或 `Merkle root`。

上述树的有趣之处在于，根哈希取决于下方叶节点的哈希。如果任何地方的交易或数据块被更改，根哈希也会随之改变。因此，`Merkle Tree` 可以显示记录是否被更改。此外，`Merkle Tree` 可用于在不查询下方区块的情况下验证特定交易是否包含在链中。这一任务的完成是通过确保区块哈希完整来实现的。矿工验证交易的存在以及区块之间的时间顺序链接。

# 第 4 章

## 需要关注的协议与概念

协议是系统运行的规则和程序。网络化系统构建在参与者达成一致的协议之上，这种一致是参与的先决条件。在区块链早期，协议意味着共识机制——即交易如何添加到区块中的规则和算法，以及区块是如何被挖掘的。在过去的几年里，协议的定义已经扩展到包含隐私、智能合约、互操作性、代币化等许多领域。这些协议从区块链早期开始，将区块链的用例从金融转账扩展到其他类型的价值转移。

协议是区块链用例的基础。因此，从业者关注现有协议的修订以及新协议的出现至关重要，这可能会影响你正尝试构建的系统。协议的发展是动态的。在以太坊和其他公共区块链生态系统中，任何人都可以提交提案来改进一个或多个底层协议。这种开放性促进了协议的快速开发、测试和发布。尽管如此，我简要解释了几个我认为对未来区块链技术的采用具有重要意义的协议和概念。

### 零知识证明

在日常的模拟生活中，当有人问你“你是公民吗或者你有驾驶资格吗？”时，我们会掏出护照或驾照。尽管对方只是在验证你的身份，但你泄露的信息比要求的更多——护照号码、出生日期等。零知识证明 (`ZKP`) 是一种数学构造，用于向验证者证明某条信息是正确的，而无需揭露信息中的细节。

Wikipedia 对 `ZKP` 有一个很好的定义：

> “零知识证明，或称零知识协议，是一种一方（证明者）向另一方（验证者）证明他们知道 `x` 的值的方法，除了他们知道 `x` 的值这一事实外，不传递任何信息。零知识证明的本质在于，通过简单揭示某些信息来证明拥有该信息是轻而易举的；挑战在于不揭露信息本身或任何额外信息的情况下证明这种所有权。”

我们不会深入探讨数学证明的细节，因为它非常复杂；然而，零知识证明已经存在了 20 多年了。

这里是该概念的简单说明。Alice 和 Bob 想要知道双方的小时工资是否相等，而不必透露实际金额。为了简单起见，让我们假设他们每小时赚 $10、$20、$30 或 $40。

1. Bob 得到四个可以锁上的盒子，并在每个盒子里放了一张写有 $10、$20、$30 和 $40 的标签。所有盒子都有独立的钥匙。
2. 然后 Bob 丢弃除了标记为小时 $20.00 的盒子钥匙以外的所有钥匙（因为他每小时赚 $20.00），并带着钥匙离开。当 Alice 稍后看到盒子时，她不知道 Bob 带着哪把钥匙。
3. Bob 将锁着的盒子交给 Alice，这些盒上有可以插入纸条的狭缝。在私下，Alice 拿出四张小纸条，在其中一张上写上“是”，在其他上面写上“否”。
4. [...省略步骤 4-8 以保持核心语义...]

ZKP 在区块链领域已演变为零知识非交互式知识论 (`zk-SNARK`)，以提供隐私和机密性。这里提供了 `zk-SNARK` 的算法描述。最著名的使用 `ZKPs` 的区块链系统是 `ZCash` 和 `Monero`。

在开放区块链中，当资产从一方发送到另一方时，交易细节对每个其他方都是可见的。在这种情况下，可以使用 `zk-SNARKs` 证明交易是有效的，而无需透露发送者、接收者以及可以存储在链外的其他细节。ZKPs 也用于智能合约，可以证明已采取了必要的步骤或行动，而无需揭露具体是什么。例如，在证明交付或所有权转移后释放付款的智能合约，在需要信息机密性的情况下，不需要记录交付细节。

我们不是在区块链上发布实际数据，而是可以在区块链上记录数学证明，并向智能合约证明我们的交易遵守业务规则，而无需透露交易的实际内容。在我们的用例中，我们可以通过向另一方发送机密消息来更改资产的托管。该方可以使用区块链上的数学证明来验证消息的发送者是资产的实际托管人，如图 4.1 所示。

`zk-SNARK` 概念也有助于追踪多方之间交易的来源，而不必披露这些交易的所有内容。对于在复杂供应链（如医药和海运）中移动高价值货物是有益的。当物理货物和有关商品的数字信息通过智能合约在供应链利益相关者之间移动时，可以向其他方证明确认和货物托管，而无需揭露有关商品的详细信息。

`private key` 是一个随机生成的 32 字节数字，对用户唯一，且绝不与他人共享。`private key` 用于生成公钥。公共地址是公钥的哈希版本。公共地址类似于我们的银行账户信息。我们向其他方提供公共地址以便发送或接收加密货币和其他相关数据。

在公有区块链中，没有用户名或密码。身份仅在于创建自己的 `private/public key`，并使用这些密钥对对智能合约或加密货币传输中的交易进行身份验证。发送比特币或 `Ether`，或在 `Ethereum` 网络或其他公有区块链基础设施上与智能合约交互，不需要政府颁发的身份。`private` 和 `public keys` 的组合足以让区块链节点如前章节所述地验证交易。当用户不需要出政府颁发的身份证明时，他们可以使用 `MetaMask` 或 `uPort` 等应用创建 `private` 和 `public keys`，以与智能合约和 `dApps` 交互。

对于 `dApps` 以及其他需要政府颁发身份验证的应用，可以使用第三方去中心化身份解决方案。示例包括 `ShoCard`、`Civic`、`BitID` 和 `ID.me`。这些服务基于现有的信任凭据（如护照或驾照）对用户进行身份证明。随后服务将在区块链上记录身份证明，以供身份请求者稍后验证，从而防止了 `dApp` 和应用开发者直接存储政府颁发的身份。由于隐私信息泄露泛滥，“主权身份”的概念正受到广泛关注。

目前存在三种身份架构：

### 中心化信任身份

这是一种传统的身份模型，其身份由应用提供者拥有并控制。用户依赖提供者来创建和管理身份，并存在身份被剥夺的可能性。在“联邦身份”（`Federated Identity`）的情况下，应用可以使用 `Google`、`Facebook`、`LinkedIn` 等提供的单点登录程序。

### 主权身份

身份由所有者（即用户）拥有并控制，不需要依赖外部管理机构，也不存在该身份被剥夺的可能性。主权身份可以通过去中心化身份生态系统来实现，该系统促进了身份属性的记录与交换，以及参与实体之间的信任传递。示例包括 `Sovrin`、`uPort` 和 `OneName` 等。主权身份类似于目前在 `Ethereum` 或 `Bitcoin` 上交易的模式，任何人都可以创建 `public` 和 `private key`，而无需从中心化机构获得证明或撤销权限。

总来说，主权身份的工作原理是将政府或其他机构颁发的身份锚定到公有区块链上。在这种情况下，发行者（政府）提交一个关于用户身份存在的声明。用户持有该身份（类似于一张不包含个人识别信息的卡片），并使用区块链对声明进行反签名。验证者仅需检查公有区块链上是否存在该声明即可。在这种情况下，验证者可以是一个网站。通过锚定在区块链中的身份，用户可以在网站上注册或登录，而无需添加出生、社会安全号码或年龄验证等个人信息。

### 去中心化信任身份

由中心化服务提供的身份，基于现有的信任凭据（如护照或驾照）对用户进行身份证明，并在区块链上记录身份证明，以供第三方稍后验证。

示例包括 `ShoCard`、`Civic`、`BitID` 和 `ID.me`。去中心化信任身份是传统模型（用户名和密码）与公私钥之间的一种折中方案。作为身份的公私钥对不适用于需要政府发行身份证明的应用。去中心化信任身份还用于证明个人与公司之间的关系。只有这些个人可以登录应用程序。它还将满足了解您的客户（KYC）要求，因为信任凭据是身份的一部分。

## 稳定加密货币

加密货币波动性而闻名，至少目前如此。分析波动原因不是本书的范围。希望使用加密货币进行交易的企业面临着在接收和结算发票期间价格即时升值或贬值的风险。解决此问题的唯一方法是立即结算这些交易并转换为更稳定的货币。然而，许多其他企业几周甚至几个月才结算发票。在这种情况下，接收方和支付方都面临不知道将支付或接收多少金额的困境。

稳定币解决了波动问题，设计通过挂钩本地法币来保持稳定。稳定币只是具有稳定值的加密货币。通用理论是法币的波动小于加密货币，因此挂钩的稳定币在企业甚至个人中可能更具吸引力。它们共享了使 `Bitcoin` 和其他加密货币如此具有吸引力的大多数特征，但没有承受同样的波动，使其作为交换媒介和记账单位更具实用性。根据名为《稳定币现状》（State of Stable Coins）的报告，在本书时有 23 种稳定币在流通。稳定币通常分为以下三类：

**链下支持**——在此模型中，代币基于储备金中的本地法币进行“支持”，以实现 1:1 发行。稳定币发行者必须通过审计或证明向公众他们拥有足够的抵押金额，以确保每个发行的代币都有等额的法币支持。这种模型对于消费者来说易于理解。然而，发行者需要持有大量的储备金，并寻找收益的方法，而不是让其留在银行账户。
