
```php
#[Attribute]
class MyCustomAttribute {
    public function __construct(string $value) {
        $this->value = $value;
    }

    public function getValue(): string {
        return $this->value;
    }
}
```

在本例中，`MyCustomAttribute` 是一个接受单个字符串参数的自定义属性。你可以使用此属性来注解代码元素，并将它们与特定值关联。

### 2.4.3. 应用属性

属性可应用于各种代码元素，包括类、方法、属性、参数和函数声明。以下是如何将 `MyCustomAttribute` 应用于类和方法：

```php
#[MyCustomAttribute("Class annotation")]
class MyClass {
    #[MyCustomAttribute("Method annotation")]
    public function myMethod() {
        // 方法逻辑
    }
}
```

在本例中，`MyCustomAttribute` 同时应用于 `MyClass` 类和 `myMethod` 方法，但具有不同的注解值。

### 2.4.4. 访问属性值

你可以使用反射来访问应用于代码元素的属性值。PHP 提供了 `ReflectionAttribute` 类来实现此目的。以下是检索和使用属性值的方法：

```php
$reflectionClass = new ReflectionClass(MyClass::class);
$classAttributes = $reflectionClass->getAttributes(MyCustomAttribute::class);

foreach ($classAttributes as $attribute) {
    $attributeInstance = $attribute->newInstance();

$reflectionMethod = new ReflectionMethod(MyClass::class, 'myMethod');

foreach ($methodAttributes as $attribute) {
    $attributeInstance = $attribute->newInstance();

```

在这段代码中，我们使用反射来检索应用于 `MyClass` 类和 `myMethod` 方法的属性。然后我们创建属性类的实例并访问它们的值。

### 2.4.5. 内置属性

PHP 8 包含多个内置属性，为各种目的提供功能。示例包括：

总之，PHP 8 中的属性提供了一种标准化且结构化的方式，用于使用元数据和注解来标注代码元素。你可以为特定用例创建自定义属性，或利用内置属性处理常见场景。属性是 PHP 功能集的宝贵补充，增强了代码文档、质量以及与框架和库的集成。

### 2.5. Match 表达式：一种新的控制结构

PHP 8 引入了 match 表达式，这是一种用于处理条件逻辑的多功能且强大的控制结构。在本节中，我们将探讨 match 表达式的语法和用法，并了解它们与传统 switch 语句的区别。

#### 2.5.1. 什么是 Match 表达式？

Match 表达式允许你对一个表达式求值，并将其与多个可能的值进行比较。根据匹配的值，你可以执行特定的代码块。Match 表达式比传统的 switch 语句更具表现力和灵活性，使你的代码更整洁、更易于理解。

#### 2.5.2. Match 表达式语法

Match 表达式的基本语法由 `match` 关键字、其后的一个表达式，以及包裹在花括号 `{}` 中的一组可能的值或模式列表组成。每个值或模式后跟一个冒号 `:` 以及匹配时要执行的代码。以下是一个简单的示例：

```php
$result = match ($value) {
    1 => "One",
    2 => "Two",
    3 => "Three",
    default => "Other",
};
```

在本例中，`$result` 变量将根据 `$value` 的值接收相应的字符串值。如果 `$value` 为 `1`，则为 "One"；如果为 `2`，则为 "Two"，以此类推。如果没有值匹配，将执行 `default` 块，将 "Other" 赋值给 `$result`。

#### 2.5.3. Match 表达式与 Switch 语句

与传统的 switch 语句相比，Match 表达式提供了多项优势：

*   **基于表达式**：Match 表达式允许你使用表达式作为比较的主体，而 switch 语句依赖于简单的值或变量。
*   **类型安全**：Match 表达式是类型安全的，这意味着你不必担心类型强制转换或宽松比较，这在 switch 语句中有时会发生。
*   **无贯穿行为**：与 switch 语句不同，Match 表达式没有贯穿行为。一旦找到匹配项，执行即停止，使代码更具可预测性。
*   **Default 块**：Match 表达式包含内置的 `default` 块，明确规定了未找到匹配时应发生的情况。

#### 2.5.4. 在 Match 表达式中使用模式

Match 表达式最强大的功能之一是能够使用模式进行匹配。模式允许你根据值的结构和属性执行复杂的匹配。以下是一个使用模式的示例：

```php
$result = match ($value) {
    1 => "One",
    2 => "Two",
    default => match {
        is_string($value) => "String",
        is_numeric($value) => "Number",
        default => "Other",
    },
};
```

在本例中，`default` 块本身包含一个嵌套的 match 表达式，用于检查该值是字符串、数字还是其他类型。这种嵌套匹配允许实现更复杂的逻辑。

#### 2.5.5. 组合模式

你可以在 Match 表达式中组合模式以处理更复杂的场景。例如，你可以使用数组模式同时匹配数组的存在性及其中的特定值：

```php
$result = match ($data) {
    [] => "Empty Array",
    [1, 2, 3] => "Array with 1, 2, and 3",
    default => "Other",
};
```

在这种情况下，`$data` 变量将与一个空数组和一个包含特定值的数组进行匹配，提供了清晰简洁的逻辑。

#### 2.5.6. Match 表达式与框架

在使用 PHP 框架和库时，Match 表达式尤为宝贵。它们提供了一种整洁且富有表现力的方式，基于各种条件和模式来处理路由、请求处理和响应生成。

`Symfony` 和 `Laravel` 等框架已采用 Match 表达式来提高代码的可读性和可维护性。你可以在路由定义、请求处理和中间件执行中找到 Match 表达式的应用。

总之，PHP 8 中的 Match 表达式是该语言功能集中一个通用且强大的补充。与传统的 switch 语句相比，它们提供了一种更具表现力和类型安全的方式来处理条件逻辑。Match 表达式结合模式，允许你编写更整洁、更易维护的代码，使其成为现代 PHP 开发中的宝贵工具。

# 第 3 章：PHP 8 改进的类型系统

### 3.1. 类型转换与严格类型简介

PHP 以其动态和弱类型的本质而闻名，允许变量在运行时改变类型。然而，PHP 8 引入了增强类型处理并提供更好变量类型控制的特性。在本节中，我们将探讨类型转换、严格类型及其对 PHP 开发的影响。

#### 3.1.1. 理解类型转换

类型转换是 PHP 的一项特性，允许变量根据需要自动更改其数据类型。如果不小心使用，这种动态类型转换可能导致意外行为。例如：

```php
$number = "42"; // $number 是字符串
$result = $number + 10; // $result 是整数 (52)
```

在本例中，执行加法运算时，PHP 会自动将字符串 "42" 转换为整数。虽然类型转换很方便，但如果不显式控制，也可能引入微妙的 Bug。

#### 3.1.2. 启用严格类型

PHP 7 引入了严格类型的概念，允许你为函数参数和返回值显式指定期望的数据类型。PHP 8 将此功能扩展到了类属性和类方法返回类型。

要在 PHP 文件中启用严格类型，应在脚本顶部包含以下声明：

```php
declare(strict_types=1);
```

启用后，严格类型确保函数参数、返回类型和类属性遵循其声明的类型。任何类型不匹配都将导致致命错误。

#### 3.1.3. 严格类型的优势

严格类型在 PHP 开发中提供了多项优势：

*   **类型安全**：通过为函数参数和返回值显式定义类型，你可以在编译时或运行时捕获类型相关错误，降低意外行为的风险。
*   **提升代码质量**：严格类型使代码更具自文档性，因为开发者可以清晰地看到函数参数和返回值的期望类型。
*   **增强可预测性**：有了严格类型，你可以依赖函数和方法的一致行为，知道它们将始终接收和返回期望的类型。

#### 3.1.4. 在函数中使用严格类型

要在函数中使用严格类型，应为参数和返回类型显式声明期望的类型。示例如下：

```php
declare(strict_types=1);

function add(int $a, int $b): int {
    return $a + $b;
}
```

在此函数中，启用了严格类型，参数 `$a` 和 `$b` 以及返回类型均显式声明为整数。任何尝试传递非整数值或返回非整数值的操作都将导致致命错误。

#### 3.1.5. 类属性和方法中的严格类型

在 PHP 8 中，你也可以将严格类型应用于类属性和方法。定义类属性时，你可以指定其类型，确保其仅存储该类型的值：

```php
declare(strict_types=1);

class MyClass {
    private int $count = 0;

    public function increment(): void {
        $this->count++;
    }

    public function getCount(): int {
        return $this->count;
    }
}
```

在本例中，`$count` 属性声明为整数，`increment()` 和 `getCount()` 方法均遵循严格类型。

#### 3.1.6. 类型转换与严格类型对比

类型转换和严格类型在 PHP 中服务于不同目的：

*   **类型转换**：PHP 的默认行为是在需要时动态转换类型。类型转换虽方便，但若不加以妥善管理，可能导致意外结果。
*   **严格类型**：启用严格类型可确保函数参数、返回值、类属性和类方法返回类型遵循其声明的类型。它增强了代码的可预测性，降低了类型相关错误的风险。

总之，PHP 8 改进的类型系统引入了严格类型的概念，它提供了对类型处理更好的控制，并增强了代码的安全性和可预测性。通过启用严格类型并为函数参数、返回值、类属性和类方法显式声明类型，你可以编写更可靠、更易维护的 PHP 代码。

### 3.2. 面向对象编程中的弱映射

PHP 8 引入了弱映射的概念，这是面向对象编程的一项宝贵补充。弱映射提供了一种将数据与对象关联的方式，而不会阻止这些对象在代码中其他地方不再被引用时被垃圾回收。在本节中，我们将探讨弱映射的概念及其在 PHP 中的应用。

#### 3.2.1. 理解弱映射

在传统的关联数组或映射中，对象被用作键来与其关联数据。然而，使用对象作为数组键会导致对这些对象的强引用，即使它们不再需要，也会阻止它们被垃圾回收。

另一方面，弱映射允许你将数据与对象关联，而无需创建强引用。这意味着，如果对某个对象的唯一引用仅存在于 `WeakMap` 中，那么当该对象在代码的其他地方不再被使用时，它就可以被垃圾回收。

#### 3.2.2. 创建弱映射

你可以在 PHP 8 中使用 `WeakMap` 类来创建弱映射。以下是创建一个空弱映射的方法：

```php
$weakMap = new WeakMap();
```

#### 3.2.3. 将数据与对象关联

要使用弱映射将数据与对象关联，可以使用 `set()` 方法，指定一个对象作为键，关联的数据作为值：

```php
$object = new stdClass();
$weakMap->set($object, "Associated Data");
```

在本例中，我们创建了一个新的 `stdClass` 对象，并使用 `set()` 方法将字符串“Associated Data”与其关联。

#### 3.2.4. 从弱映射中检索数据

你可以使用 `get()` 方法从弱映射中检索关联的数据，提供对象作为键：

```php
$data = $weakMap->get($object);
```

此时 `$data` 变量将包含关联的数据，本例中即为“Associated Data”。

#### 3.2.5. 检查对象是否存在于弱映射中

要检查对象是否作为键存在于弱映射中，可以使用 `has()` 方法：

```php
if ($weakMap->has($object)) {
    echo "Object found in Weak Map";
} else {
    echo "Object not found in Weak Map";
}
```

此代码片段将判断 `$object` 是否作为键存在于弱映射中。

#### 3.2.6. 从弱映射中移除对象

如果你不再需要在弱映射中将对象与数据关联，可以使用 `delete()` 方法将其移除：

```php
$weakMap->delete($object);
```

执行此操作后，该对象将不再与弱映射中的任何数据关联。

#### 3.2.7. 弱映射的用例

弱映射在以下场景中特别有用：你希望暂时将数据与对象关联，或者以一种不阻止对象在不再需要时被垃圾回收的方式进行关联。弱映射的一些常见用例包括：

*   **缓存**：你可以使用弱映射来缓存与对象关联的数据，而不会阻止这些对象在不再使用时被清理。
*   **事件监听器**：在事件驱动编程中，弱映射可用于将事件监听器与对象关联。当对象不再需要时，关联的事件监听器可以被自动移除。
*   **对象相关元数据**：在使用面向对象编程时，你可能希望将元数据或附加信息附加到对象上。弱映射提供了一种无需创建对对象的强引用即可实现此目的的方法。
*   **资源管理**：在管理与对象关联的资源（例如数据库连接）时，弱映射有助于确保在对象不再被引用时释放资源。

总之，PHP 8 中的弱映射提供了一种强大的工具，用于将数据与对象关联，而不会阻止这些对象在不再需要时被垃圾回收。它们在面向对象编程场景中尤为宝贵，适用于需要临时或非侵入式关联的场景，有助于编写更高效、更节省内存的 PHP 代码。

### 3.3. 静态返回类型及其用法

PHP 8 引入了为方法声明 `static` 返回类型的能力。此功能通过允许你指定方法返回其所属类的实例，增强了面向对象代码的类型安全性。在本节中，我们将探讨静态返回类型的概念，并了解如何在 PHP 开发中使用它们。

#### 3.3.1. 理解静态返回类型

在 PHP 中，返回类型声明指定了函数或方法应返回的值的类型。在 PHP 8 之前，你可以指定 `int`、`string`、`array` 或类名等返回类型。然而，没有内置的方法来指定某方法应返回其所属类的实例。静态返回类型的引入解决了这一限制。

静态返回类型通过在返回类型声明中使用 `static` 关键字来表示。这意味着该方法应返回其定义所在类的实例，从而实现更好的类型提示和代码清晰度。

#### 3.3.2. 声明静态返回类型

要为方法声明静态返回类型，请在方法的返回类型声明中使用 `static` 关键字。示例如下：

```php
class MyClass {
    public function newInstance(): static {
        return new static();
    }
}
```

在本例中，`newInstance()` 方法被声明为返回同一个类的实例（`static`）。这意味着当你在 `MyClass` 的实例上调用 `newInstance()` 时，它将返回一个 `MyClass` 的实例。

#### 3.3.3. 静态返回类型的用例

静态返回类型在面向对象 PHP 开发中提供了多种优势和用例：
