### 认证目标 5.01

### 漏洞安全顾虑

在深入探讨针对系统的不同威胁类型之前，让我们先谈谈系统存在漏洞的一些原因，以及脆弱系统对组织的影响。在第 2 章中，您接触到了*漏洞*一词，它是指产品或系统中的弱点。在本章中，您将进一步了解这些漏洞存在的原因，以及您可以采取哪些措施来减少系统上的漏洞数量。

本章重点关注“内部部署”（即在您的局域网上）的系统中发现的漏洞，而非云端的系统或应用程序。如果您的组织使用云资源，请务必评估云中存在的漏洞类型。

一个非常重要的漏洞类型是*零日漏洞*，它是指创建软件的软件供应商未知的漏洞，因此尚未为该漏洞创建修复程序或补丁。零日漏洞容易遭受零日攻击，这是一种非常危险的攻击类型，因为软件尚未打补丁。

为了帮助防止零日攻击，请结合使用多种安全控制，包括定期修补系统和应用程序，使用应用层防火墙控制可到达系统或应用程序的流量类型，以及实施入侵防御系统（`IPS`）以监控活动、识别威胁并阻止攻击。

#### 系统脆弱的原因

系统上存在大量漏洞或弱点，允许攻击者访问系统及其数据。在本节中，您将了解系统上最常见的漏洞。

##### 弱配置

# 系统脆弱的首要原因是配置薄弱

系统的弱配置有多种不同形式，以下是最常见的配置错误：

- **开放权限** 未在系统或应用程序中配置权限，会使系统完全暴露在攻击者面前。确保来宾或匿名账户没有对系统上数据的写入访问权限至关重要。

- **不安全的根账户** 应遵循管理员账户的最佳实践，例如 Linux 中的 `root` 账户和 Windows 中的 `administrator` 账户。常见的最佳实践包括重命名默认账户、为账户设置强密码，以及限制创建额外的根级账户。

- **错误** 错误是配置中出现的失误，可能会使系统暴露在攻击之下。例如，未限制 DNS 服务器上的区域传送，可能会使 DNS 数据暴露给攻击者。

- **弱加密** 静态数据和传输中数据未加密是一个严重错误。对于所有设备、应用程序和协议，都要考虑如何对数据进行加密以保护公司数据的机密性，并确保所用的加密算法符合当今标准下的强算法要求。例如，您将在第 12 章了解加密算法，以及 `DES` 和 `3DES` 被视为弱加密协议这一事实。如果应用程序正在使用 `DES` 或 `3DES`，您应检查是否可以更改配置并使用更安全的 `AES` 算法。请参阅第 12 章和第 13 章以了解更多关于加密的内容。

- **不安全的协议** 确保应用程序使用协议的安全版本，以便通信经过加密。例如，确保 Web 应用程序使用 `HTTPS` 而非 `HTTP`。

- **默认设置** 审查系统或应用程序的默认配置，寻找可能使系统处于风险中的默认设置。例如，旧版 Windows Server 默认安装了 Microsoft 的 Web 服务器软件。这意味着您的 Windows Server 开箱即面临 Web 攻击。作为管理员，您会被教导在安装 Windows 后移除 Web 服务器软件（如果不需要该软件）。

- **开放端口和服务** 务必限制系统上运行的服务，这能减少系统上开放的端口。

## 第三方风险

与第三方公司合作也存在风险。您合作的第三方公司执行的操作可能会使您的公司变得脆弱。以下是几个示例：

- **供应商管理** 供应商管理其产品的方式，可能会给使用该供应商产品的您的环境带来漏洞。例如，供应商的系统如何集成到您的网络中？是否使用安全协议？是否需要网络上的账户？如果产品较旧，供应商可能不再支持该产品。不再受支持的产品不再创建补丁，这意味着您可能面临零日攻击。

- **供应链** 如果您与不遵循安全最佳实践的供应商合作，您可能会收到已被篡改的产品，随后将其连接到您的网络。

- **外包代码开发** 不安全的应用程序代码是导致系统漏洞的主要原因。将组件的开发外包给您的应用程序使用，如果外包公司不遵循安全编码实践，可能会导致这些应用程序不安全。

- **数据存储** 您可能将数据存储在第三方公司——也许作为存储数据备份的备用站点。验证第三方公司是否保护了存放您数据的系统，但也要采取自己的措施确保数据已加密，且只有您的公司能够解密数据。

## 不当或薄弱的补丁管理

缺乏补丁策略是导致系统脆弱的最大原因之一，因为补丁包含已知漏洞的安全修复。请务必定期对以下内容应用补丁：

- **固件** 对服务器、路由器、交换机等设备以及公司内可能存在的任何其他硬件设备的固件应用更新。

- **操作系统 (OS)** 定期修补操作系统，并寻求补丁管理软件以实现补丁部署的自动化。

- **应用程序** 确保应用程序也已打补丁。应用程序中的漏洞可能导致整个系统容易受到攻击。

## 遗留平台

遗留系统是您应在网络中留意的对象，因为许多遗留系统不再获得供应商支持，这意味着它们极有可能不再接收补丁。此外，遗留系统可能正在使用不安全的旧协议。如果您的网络上使用遗留系统，请考虑将它们放置在自己的网络段上，以帮助降低系统受到攻击的几率。

## 理解漏洞的影响

不学习如何管理系统上存在的漏洞的公司，可能会面临灾难性后果。以下是未减少其产品中现有漏洞的企业可能面临的潜在影响：

- **数据丢失** 系统上的漏洞可能导致您失去对数据的访问。例如，攻击者可能利用漏洞删除数据或使用勒索软件对其进行加密。

- **数据泄露** 当未经授权的人员访问机密数据时，就会发生数据泄露。数据泄露也称为 `data leak` 或 `data spill`。数据泄露可能包括健康记录、财务数据和知识产权等信息。数据泄露的影响可能对公司造成灾难性后果，原因在于调查和恢复数据泄露的成本，但公司也可能面临声誉受损。

- **数据渗漏** 数据渗漏是指某人未经许可将数据从计算机或网络传输出去。攻击者可能想要从系统传输的敏感数据示例包括财务数据（如信用卡号）、个人身份信息 (`PII`) 以及用户名和密码。为防止数据渗漏，您可以禁用 `USB` 端口，使 USB 闪存驱动器和 USB 外置硬盘等便携式存储设备无法连接到系统，或者使用数据丢失防护 (`DLP`) 功能阻止敏感数据被复制或通过电子邮件发送到组织外部。

- **身份盗窃** 系统中的漏洞可能导致身份盗窃，即个人信息被窃取，允许攻击者冒充受害者身份。

- **财务损失** 漏洞可能因多种原因导致财务损失。首先，漏洞可能允许攻击者使生产系统崩溃，导致收入损失，但也存在恢复系统的成本以及声誉受损的无形成本。

- **声誉受损** 正如前面多次提到的，漏洞被利用导致系统沦陷，可能会损害公司声誉。如果客户觉得他们的数据不安全，可能会选择不再与贵公司开展业务。

- **可用性丧失** 漏洞可能导致系统或服务可用性丧失。例如，后端数据库中的漏洞可能导致电子商务 Web 应用程序无法显示产品或接受在线订单。

## 常见安全问题与设备输出

系统和网络可能以多种不同的方式遭到攻破，但好消息是，大多数漏洞利用和攻击都针对少数几个我们可以识别和解决的安全问题。在本节中，你将学习排查常见安全问题的策略，以及不同安全技术的常见输出。你还将了解组织用于制定安全策略的常见安全框架和指南。

### 排查常见安全问题

Security+ 认证考试要求你了解安全事件发生的常见原因，例如黑客利用系统漏洞、用户意外或故意删除文件，甚至用户将敏感数据通过电子邮件发送给公司外部人员。

#### 弱配置或错误配置

许多安全事件是由于配置错误或安全配置薄弱导致的。例如，一家小公司可能使用无线路由器建立了无线网络，却未更改任何默认设置。

以下是导致安全问题的常见系统或设备错误配置：

- **未加密的凭据/明文** 许多互联网技术和协议默认不加密网络流量，包括用于登录设备的用户名和密码。请务必在可能的情况下使用加密技术，如 `SSL/TLS`、`VPN` 以及协议的安全版本。

- **日志和事件异常** 查看事件日志和活动日志时，请务必留意日志中出现的异常事件。任何可疑活动都需要进一步调查。从错误配置的角度来看，请验证日志记录功能已启用，并且你知道系统和设备的日志存储位置。

- **权限问题** 未正确配置资源权限是内部攻击如此成功的常见原因。请务必定期审查资源权限，并仅授予所需的权限（最小权限原则）。

- **访问违规** 当未获授权访问系统的人员获得了访问权限时，就会发生访问违规。请确保在任何人访问网络或系统前都要求进行身份验证，并确保登录流量经过加密。在资源上配置权限，以确保无人能访问其不应访问的资源。

- **证书问题** 证书是包含用于加密通信的密钥的电子文件。证书至少应用于保护 Web 流量、电子邮件流量和服务器间通信。请确保所使用的证书未过期、未被吊销，且来自受信任的证书颁发机构（`CA`）。你将在 第 12 章 和 第 13 章 了解更多关于证书的内容。

- **数据泄露** 如前所述，数据泄露是指某人未经许可将信息从系统中传输出去。考试重点：为防止数据泄露，你可以禁用 `USB` 端口，或使用 `DLP` 功能阻止敏感数据被复制或通过电子邮件发送到组织外部。

- **设备配置错误** 设备配置错误是攻击者能够访问本不应访问的系统的主要原因。请务必配置以下内容：

  - **防火墙** 确保使用防火墙将网络划分为不同的网段。规则配置错误的防火墙会允许用户访问他们不应访问的网段。请确保每个网段的防火墙都已正确配置，以控制什么流量可以穿过防火墙到达该特定网段。

  - **内容过滤器** 内容过滤设备用于控制员工可以访问互联网上的哪些内容。如果内容过滤规则配置不当，用户可能会访问不安全的网站，导致代码在其系统上执行。

  - **接入点** 无线接入点和家用无线路由器通常配置错误。请务必检查无线接入点的配置，确保你已配置诸如 `MAC` 地址过滤、`WPA2` 加密和强加密密钥等功能，并已修改默认管理员密码。

- **薄弱的安全配置** 安全事件的一个主要原因是安全配置薄弱。例如，网络管理员可能在无线网络上配置了加密，但选择了较弱的加密方法，或者使用了弱加密密钥。请务必审查设备上的所有安全设置，如访问控制列表、密码、加密密钥、加密算法以及任何可用的过滤功能。

#### 人员问题

如果你不专注于培训员工提高安全意识，即使你在设备上配置了最好的安全设置，它们仍然容易被攻破。你还必须警惕内部威胁。以下是涉及人员问题的关键安全考量：

- **违反策略** 许多安全事件是因为员工违反公司安全策略而发生的。请务必教育员工了解安全策略及其生效的原因。如果员工理解策略存在的原因，以及遵守策略如何保护公司及其资产，他们就不太可能违反安全策略。

- **内部威胁** 大多数公司将防火墙作为其安全防护的重点。这固然重要，但你也需要保护公司资产免受内部威胁（如不满的员工）的侵害。请务必使用身份验证、权限和访问控制列表来控制员工的访问权限。同时也要确保实施反恶意软件以保护内部系统免受病毒侵害。

- **社会工程学** 教育员工了解常见的社会工程学攻击，以便他们能识别何时成为攻击目标。教育是防范社会工程学攻击的关键。

- **社交媒体** 教育员工了解哪些信息可以发布在社交媒体上，哪些不可以。你应该制定严格的政策，限制在社交媒体上发布工作场所照片，因为这些照片可能包含敏感信息。例如，一张员工坐在办公桌前的照片，背景屏幕上可能正打开着敏感文档，或者桌面上可能放着文档。

- **个人电子邮件** 许多员工在工作中使用个人电子邮件账户，并可能利用它将公司数据发送到公司外部。请务必部署 `DLP` 功能以防止数据泄露。还要注意员工可能用来在工作间传输数据的个人云存储。你可以考虑在防火墙或内容过滤设备上阻止访问这些网站。

### 应用程序问题

软件是安全方面的另一个关注领域。你应该考虑以下所有与应用程序相关的问题：

- **未经授权的软件** 组织应制定严格的策略，规定允许或不允许在公司系统上运行哪些软件。`应用程序白名单` 是指定义允许在系统上运行的软件。你可以使用 `Windows AppLocker` 等工具作为策略的一部分，来限制允许在系统上运行的软件。

### 基线偏差

安全基线是系统必须遵守的既定安全状态，不得有任何偏离。任何可能使系统暴露并降低其安全性的修改，都需要先经过审查，若实施则需密切监控。组织可以使用 `PowerShell Desired State Configuration (DSC)` 等技术来防止系统发生偏离基线的更改。

### 许可合规违规（可用性/完整性）

如果公司被发现软件许可不合规，可能面临巨额罚款。有可用的工具可让你跟踪软件安装情况，确保不超出允许的许可安装数量。

### 资产管理

系统投入生产后，你需要对其进行维护以保持其安全。集中维护系统是资产管理成功的关键。使用 `Group Policy Objects (GPOs)` 和 `Microsoft Endpoint Configuration Manager (MECM)` 等产品来管理配置、补丁、驱动程序和应用程序的部署。

### 身份验证问题

确保应用程序以最安全的方式配置身份验证，以防他人窃听身份验证流量，并利用应用程序使用的凭据获取网络访问权限。确保应用程序使用自己的账户，而非连接数据库时使用 `System` 账户或 `sa` 账户等默认账户。

## 分析和解读安全技术的输出

有许多不同的安全设备和技术会向用户显示消息或向系统管理员提供信息，使他们知晓发生的潜在安全事件。以下列表列出了你将从这些安全技术中看到的输出：

### HIDS/HIPS

基于主机的入侵检测系统 (`HIDS`) 或基于主机的入侵防御系统 (`HIPS`) 会在应用程序中显示潜在威胁的通知，或将其发送到指定的电子邮件地址。你需要查看通知事件，以识别系统上的任何可疑活动。查看输出时，请检查事件的日期和时间、事件来源（大多数 `HIDS`/`HIPS` 产品会审查来自多个来源的日志）以及导致事件发生的账户。利用这些信息，你可以决定是否需要进行配置更改。

### 杀毒软件

杀毒软件提供日志和通知。查看这些日志和通知以获取信息，例如计划扫描的结果，它将报告是否发现恶意软件，如果发现，则报告恶意软件的名称和受感染文件的名称。你还将收到有关采取的任何纠正措施的信息，例如受感染文件是否已从系统中删除或移至隔离区。

# 文件完整性检查

运行文件完整性检查工具时，它们会告知你自计算文件哈希值以来文件是否发生过更改。你可能会收到文件完整性检查的输出，例如 `hash mismatch` 或 `signature mismatch`，这两者都意味着文件已被篡改。`hash match`、`hash valid` 或 `signature verified` 等输出则表明文件未被更改。
