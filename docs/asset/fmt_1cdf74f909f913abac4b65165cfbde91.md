
从安全角度来看，环模型使操作系统能够保护并隔离自己，防止用户和应用程序的侵害。它还允许在高度特权的操作系统组件（如内核）和较低特权的操作系统部分（如操作系统的其他部分、驱动程序和实用程序）之间强制执行严格的边界。在此模型中，仅在特定环内才能直接访问特定资源；同样，某些操作（如进程切换、终止和调度）也仅允许在特定环内进行。

进程所占据的环决定了其对系统资源的访问级别（并决定了它必须从较低编号、更高特权的环中的进程请求哪些类型的资源）。进程只有在资源驻留在其自己的环内，或驻留在其当前边界之外的某个环内（按数字术语，例如，环 1 的进程可以直接访问其自己的资源，以及与环 2 和 3 关联的资源，但无法访问仅与环 0 关联的资源）时，才能直接访问对象。实现中介访问的机制——即前面提到的驱动程序或处理程序请求——通常称为 `系统调用`，通常涉及调用特定的系统或编程接口，旨在将请求传递给内层环以获取服务。然而，在任何此类请求得到满足之前，被调用的环必须检查以确保调用进程拥有正确的凭据和授权，以访问数据并执行满足请求所涉及的操作。

## 进程状态

也称为 `操作状态`，`进程状态` 是进程可能运行的各种执行形式。就操作系统而言，在任何给定时刻，它可以处于两种模式之一：在称为 `管理员状态` 的特权全访问模式下运行，或在称为 `问题状态` 的用户模式下运行，在该模式下特权较低，所有访问请求在被授予或拒绝前都必须根据凭据进行授权检查。之所以称后者为问题状态，并非因为问题一定会发生，而是因为用户访问的非特权性质意味着问题可能发生，系统必须采取适当措施来保护安全性、完整性和机密性。

进程在操作系统的处理队列中排队等待执行，当处理器可用时，它们将被调度运行。由于许多操作系统仅允许进程以固定增量或块消耗处理器时间，当创建新进程时，它首次进入处理队列；如果进程在未完成的情况下消耗了其整个处理时间块（称为 `时间片`），它将在下一次轮到它时返回处理队列以获取另一个时间片。此外，进程调度程序通常选择最高优先级的进程执行，因此排到队首并不总能保证获得 CPU 访问权（因为进程可能在最后一刻被另一个优先级更高的进程抢占）。

根据进程是否正在运行，它可以在以下几种状态之一中运行：

### 进程状态详解

#### Ready（就绪状态）

在**就绪状态**下，进程已准备好在被调度执行后立即恢复或开始处理。如果进程到达此状态时 CPU 可用，它将直接转入运行状态；否则，它将停留在就绪状态直到轮到它。这意味着进程拥有立即开始执行所需的所有内存和其他资源。

#### Waiting（等待状态）

**等待状态**也可以理解为“等待资源”——即进程已准备好继续执行，但正在等待设备或访问请求（某种中断）得到服务后才能继续处理（例如，请求从文件读取记录的数据库应用程序必须等待该文件被定位、打开，并找到正确的记录集）。某些参考资料将此状态标记为阻塞状态，因为进程可被认为因外部事件未发生而无法继续执行。

#### Running（运行状态）

运行中的进程在 CPU 上执行，并持续运行直到完成、时间片用尽，或因某些原因被阻塞（通常是因为它产生了一个访问设备或网络的中断，并正在等待该中断得到服务）。如果时间片结束而进程未完成，它将返回就绪状态（和队列）；如果进程因等待资源可用而阻塞，它将进入等待状态（和队列）。

#### Supervisory（监管状态）

当进程必须执行需要高于问题状态特权集的操作时，将使用**监管状态**，包括修改系统配置、安装设备驱动程序或修改安全设置。基本上，任何不在用户模式（Ring 3）或问题状态下发生的功能都在监管模式下进行。

#### Stopped（停止状态）

当进程完成或必须终止（因错误发生、所需资源不可用或资源请求无法满足）时，它将进入**停止状态**。此时，操作系统可以回收分配给该进程的所有内存和其他资源，并根据需要将其重用于其他进程。

图 9.2 展示了这些各种状态如何相互关联的示意图。新进程总是转入就绪状态。从那里，就绪进程总是转入运行状态。在运行时，进程可以转入停止状态（如果完成或被终止）、返回就绪状态以获取另一个时间片，或转入等待状态直到其挂起的资源请求得到满足。当操作系统决定下一个运行哪个进程时，它会检查等待队列和就绪队列，并选取优先级最高的、准备好运行的作业（因此只有那些挂起请求已被服务、或已准备好被服务的等待作业才有资格参与考量）。内核的一个特殊部分，称为 `程序执行体` 或 `进程调度器`，始终驻留在内存中（等待中），以便在必须发生进程状态转换时，能介入并处理相关机制。

## 安全模式

美国政府为处理机密信息的系统指定了四种批准的**安全模式**。下文将进行描述。在第 1 章“通过原则和策略进行安全治理”中，我们回顾了联邦政府使用的分类系统以及安全许可和访问批准的概念。此语境下唯一的新术语是 `need to know`（需知原则），它指的是一种访问授权方案，其中主体访问客体的权利不仅考虑特权级别，还考虑涉及数据与主体所扮演角色（或执行的工作）的相关性。这表明主体需要访问该客体以正确执行其工作或履行某特定角色。没有需知权的人不得访问该客体，无论其持有何种特权级别。如果您需要复习这些概念，请在继续之前回顾第 1 章。在部署安全模式本身之前，必须存在三个特定要素：

*   分层强制访问控制（MAC）环境
*   对可访问计算机控制台的主体的完全物理控制
*   对可进入计算机控制台所在房间的主体的完全物理控制

### Dedicated Mode（专用模式）

**专用模式**系统基本等同于本章前面“处理类型”部分所述的单状态系统。专用系统的用户有三项要求：

*   每个用户必须具有允许访问系统处理的所有信息的安全许可。
*   每个用户必须具有对系统处理的所有信息的访问批准。
*   每个用户必须对系统处理的所有信息具有有效的需知权。

### System High Mode（系统高模式）

**系统高模式**系统的用户必须满足略有不同的要求：

*   每个用户必须具有允许访问系统处理的所有信息的有效安全许可。
*   每个用户必须具有对系统处理的所有信息的访问批准。
*   每个用户必须对系统处理的*某些*信息具有有效的需知权，但不一定是*所有*信息。

请注意，专用模式和系统高模式的主要区别在于：系统高模式计算设备上的所有用户不一定对系统处理的所有信息都有需知权。因此，虽然同一用户可以同时访问专用模式系统和系统高模式系统，但该用户可以访问前者的所有数据，却可能被限制访问后者的某些数据。

### Compartmented Mode（分区模式）

**分区模式**系统进一步放宽了这些要求：

*   每个用户必须具有允许访问系统处理的所有信息的有效安全许可。
*   每个用户必须具有对其将在系统上访问的任何信息的访问批准。
*   每个用户必须对其将在系统上访问的所有信息具有有效的需知权。

请注意，分区模式系统与系统高模式系统的主要区别在于：分区模式系统的用户不一定具有对系统上所有信息的访问批准。然而，与系统高模式和专用系统一样，系统的所有用户仍必须具有适当的安全许可。在一种称为**分区模式工作站（CMW）**的特殊实现中，具有必要许可的用户可以同时处理多个分区的数据。

CMW 要求在对象上放置两种形式的安全标签：敏感度级别和信息标签。敏感度级别描述对象必须受保护的级别。这些在所有四种模式中通用。信息标签防止数据过度分类，并将附加信息与对象关联，这有助于进行不涉及访问控制的正确、准确的数据标记。

### Multilevel Mode（多级模式）

政府对**多级模式**系统的定义与前一节给出的技术定义基本平行。然而，为保持一致性，我们将用许可、访问批准和需知权来表述它：

#### 安全模式要求

*   部分用户没有有效的安全许可来访问系统处理的所有信息。因此，访问控制取决于主体的许可级别是否主导客体的敏感度标签。
*   每个用户必须拥有其将在系统上访问的所有信息的访问批准。
*   每个用户必须拥有其将在系统上访问的所有信息的有效“知悉必要性”。

当你浏览联邦政府批准的各种操作模式的要求时，你会注意到，随着从专用系统过渡到多级系统，控制访问系统的用户类型的管理要求会减少。然而，这并不降低限制个人访问的重要性，以便用户只能获取他们合法有权访问的信息。正如上一节所讨论的，这只是将执行这些要求的负担从行政人员（他们物理上限制对计算机的访问）转移到硬件和软件（它们控制多用户系统中每个用户可以访问的信息）的问题。

### 操作模式

现代处理器和操作系统旨在支持多用户环境，在这种环境中，单个计算机用户可能不会被授予访问系统所有组件或存储在其中的所有信息的权限。因此，处理器本身支持两种操作模式：用户模式和特权模式。

#### 用户模式

**用户模式** 是 CPU 在执行用户应用程序时使用的基本模式。在此模式下，CPU 仅允许执行其完整指令集的一部分。这旨在防止用户因执行设计不良的代码或无意中误用代码而意外损坏系统。它还可以保护系统及其数据免受恶意用户的侵害，后者可能会尝试执行旨在绕过操作系统安全措施的指令，或错误地执行可能导致未经授权的访问或对系统或有价值的信息资产造成损害的操作。

通常，用户模式下的进程在称为 `虚拟机 (VM)` 的受控环境中执行。虚拟机是由操作系统创建的模拟环境，为程序执行提供安全高效的场所。每个 VM 都与所有其他 VM 隔离，并且每个 VM 都有自己的分配内存地址空间，可供托管的应用程序使用。特权模式（又称内核模式）中的元素负责创建和支持 VM，并防止一个 VM 中的进程干扰其他 VM 中的进程。

#### 特权模式

**特权模式** CPU 还支持*特权模式*，旨在授予操作系统访问 CPU 支持的完整指令范围的权限。此模式有多种名称，具体术语因 CPU 制造商而异。一些更常见的名称包括在以下列表中：

*   特权模式
*   监督模式
*   系统模式
*   内核模式

无论使用哪个术语，基本概念保持不变——此模式授予在 CPU 上执行的进程广泛的权限。因此，设计良好的操作系统不允许任何用户应用程序在特权模式下执行。出于安全性和系统完整性的目的，只有操作系统本身的组件进程才被允许在此模式下执行。

## 内存

系统的第二个主要硬件组件是 `内存`，即计算机需要保持随时可用的信息的存储库。有许多不同种类的内存，每种都适用于不同的目的，我们将在后续章节中逐一介绍。

### 只读存储器 (ROM)

*只读存储器 (ROM)* 顾名思义——它是 PC 可以读取但无法更改的内存（不允许写入）。标准 ROM 芯片的内容在出厂时被“烧录”进去，最终用户根本无法更改。ROM 芯片通常包含计算机在从磁盘加载操作系统之前启动时使用的“引导”信息。这包括熟悉的 `加电自检 (POST)` 诊断系列，每次启动 PC 时都会运行。

ROM 的主要优势在于它无法被修改。用户或管理员错误绝无可能意外擦除或修改此类芯片的内容。这一属性使 ROM 成为协调计算机最内部工作原理的极佳选择。

有一种 ROM 管理员可以在一定程度上修改。它称为可编程只读存储器 (PROM)，其几种子类型将在下文描述：

#### 可编程只读存储器 (PROM)

**可编程只读存储器 (PROM)** 基本的 `可编程只读存储器 (PROM)` 芯片在功能上类似于 ROM 芯片，但有一个例外。在制造过程中，PROM 芯片的内容不像标准 ROM 芯片那样在工厂被“烧录”。相反，PROM 结合了特殊功能，允许最终用户稍后烧录芯片的内容。然而，烧录过程有着类似的结果——一旦数据被写入 PROM 芯片，就无法进行进一步更改。烧录后，PROM 芯片基本上就像 ROM 芯片一样运行。

PROM 芯片为软件开发人员提供了在高速、定制化内存芯片上永久存储信息的机会。PROM 常用于需要某些自定义功能但一旦编程后很少更改的硬件应用中。

#### 可擦除可编程只读存储器 (EPROM)

**可擦除可编程只读存储器 (EPROM)** 将 PROM 芯片相对较高的成本与软件开发人员编写代码后不可避免地想要修改代码的愿望相结合，便得出了开发 `可擦除 PROM (EPROM)` 的基本原理。EPROM 有两个主要子类别，即 UVEPROM 和 EEPROM（见下一项）。`紫外线 EPROM (UVEPROM)` 可以用光擦除。这些芯片有一个小窗口，当用特殊的紫外线照射时，会导致芯片内容被擦除。此过程完成后，最终用户可以将新信息烧录到 UVEPROM 中，就像它从未被编程过一样。

#### 电可擦除可编程只读存储器 (EEPROM)

**电可擦除可编程只读存储器 (EEPROM)** 一种比 UVEPROM 更灵活、更友好的替代方案是 `电可擦除 PROM (EEPROM)`，它利用传送到芯片引脚的电压来强制擦除。

### 闪存

**闪存** 是 EEPROM 的衍生概念。它是一种非易失性存储介质，可以被电子擦除和重写。EEPROM 和闪存的主要区别在于，EEPROM 必须完全擦除才能重写，而闪存可以以块或页为单位进行擦除和写入。最常见的闪存类型是 NAND 闪存。它广泛应用于存储卡、U 盘、移动设备和 SSD（固态硬盘）。

### 随机存取存储器 (RAM)

**随机存取存储器 (RAM)** 是可读可写的内存，包含计算机在处理过程中使用的信息。只有在持续供电的情况下，RAM 才能保留其内容。与 ROM 不同，当计算机断电时，存储在 RAM 中的所有数据都会消失。因此，RAM 仅适用于临时存储。关键数据绝不应仅存储在 RAM 中；应始终在另一存储设备上保留备份副本，以防止因突然断电导致数据丢失。以下是 RAM 的类型：

#### 实存

**实存**（也称为**主存**或**主存储器**）通常是计算机可用的最大 RAM 存储资源。它通常由若干动态 RAM 芯片组成，因此必须由 CPU 定期刷新（有关更多信息，请参阅侧边栏“动态 RAM 与静态 RAM”）。

#### 高速缓存 RAM

计算机系统包含许多缓存，当数据可能被重复使用时，它们通过从较慢的设备获取数据并暂时存储在较快的设备中来提高性能；这就是**高速缓存 RAM**。处理器通常包含一个板载极高速内存缓存，用于存放其将要操作的数据。这可以称为 L1、L2、L3 甚至 L4 缓存（L 代表 level，即级别）。许多现代 CPU 包含多达三级片上缓存，其中一些缓存（通常是 L1 和/或 L2）专用于单个处理器核心，而 L3 可能是核心间共享的缓存。某些 CPU 可能涉及 L4 缓存，它可能位于主板上或 GPU（图形处理单元）上。同样，实存通常也包含存储在磁性介质或 SSD 上的信息的缓存。这一链条沿着内存/存储层级向下延伸，使计算机能够通过将可能接下来要用到的数据保存在更近的地方（无论是用于 CPU 指令、数据获取、文件访问还是其他用途）来提高性能。

许多外设也包含板载缓存，以减轻它们给 CPU 和操作系统带来的存储负担。例如，许多高端打印机包含大容量 RAM 缓存，以便操作系统能快速将整个打印作业脱机输出到打印机。之后，处理器就可以不再理会该打印作业；它无需等待打印机实际生成请求的输出、一次次地喂给它数据块。打印机可以从其板载缓存预处理信息，从而释放 CPU 和操作系统去处理其他任务。许多存储设备，如硬盘驱动器 (HDD)、固态驱动器 (SSD) 和某些 U 盘，都包含缓存以帮助提高读写速度。然而，在断开连接或断电之前，这些缓存必须刷新到永久或辅助存储区，以避免驻留在缓存中的数据丢失。

### 寄存器

CPU 还包含少量板载内存，称为**寄存器**，它们为 CPU 提供直接可访问的内存位置，CPU 的大脑——**算术逻辑单元 (ALU)**——在执行计算或处理指令时会使用这些位置。事实上，除非数据作为指令的一部分直接提供，否则 ALU 要操作的任何数据都必须加载到寄存器中。这种内存的主要优势在于它是 ALU 本身的一部分，因此以典型的 CPU 速度与 CPU 同步运行。

### 内存寻址

在使用内存资源时，处理器必须有某种方法来引用内存中的各个位置。解决此问题的方法称为**寻址**，根据不同情况会使用多种不同的寻址方案。以下是五种较常见的寻址方案：

#### 寄存器寻址

正如您在上一节所学，寄存器是 CPU 中直接的小内存位置。当 CPU 需要从其寄存器之一获取信息以完成操作时，它使用 `寄存器地址`（例如，“寄存器 1”）来访问其内容。

#### 立即寻址

**立即寻址** 本身并非一种内存寻址方案，而是一种将作为指令一部分提供给 CPU 的数据的引用方式。例如，CPU 可能会处理“将 2 加到寄存器 1 中的值”这一命令。该命令使用了两种寻址方案。第一种是立即寻址——CPU 被告知要加上值 2，不需要从内存位置检索该值——它作为命令的一部分被提供。第二种是寄存器寻址；它被指示从寄存器 1 检索值。

#### 直接寻址

在**直接寻址**中，CPU 获得要访问的内存位置的实际地址。该地址必须位于与正在执行的指令相同的内存页上。直接寻址比立即寻址更灵活，因为内存位置的内容比立即寻址的硬编码数据更容易修改。

#### 间接寻址

**间接寻址** 使用的方案类似于直接寻址。然而，作为指令一部分提供给 CPU 的内存地址不包含 CPU 要用作操作数的实际值。相反，该内存地址包含另一个内存地址（可能位于不同的页上）。CPU 读取间接地址以得知所需数据所在的地址，然后从该地址检索实际的操作数。
