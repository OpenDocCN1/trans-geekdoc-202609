### 初始化的计算方面

为了实现其目标，`k-means` 需要经过一定数量的示例从错误簇到正确簇的转移。需要多少次转移取决于初始聚类的内容。至少在理论上，可能会出现随机创建的初始聚类已经是完美的，不需要移动任何示例。这固然是一个极端情况，但读者一定理解，如果初始化是“幸运”的，那么执行的重新定位将比其他时候少。初始化的重要性在于，更好的起点可以确保更快地找到解决方案。

### 如何初始化

在某些领域，我们可以利用有关当前问题的某些背景知识。例如，在试图在公司员工数据库中创建初始聚类时，数据分析师可能会推测，根据年龄、工资或其他直观标准对他们进行分组是有意义的，由此得到的组将构成良好的初始聚类。

然而，在其他应用中，没有这样的指南。此时最简单的程序是选取 `k` 个随机训练示例，并将它们视为代码向量，以定义初始质心。然后，通过将每个示例与其最近的代码向量关联来创建初始聚类。

### 归一化的性质

读者会记得，在讨论 `k-NN` 分类器时，第 3 章指出不适当的属性缩放会扭曲属性向量之间的距离。聚类分析中也存在同样的问题。因此，对向量进行归一化始终是一个好主意，使得所有数值属性的值处于相同的范围，例如从 0 到 1。

实现此最简单的方法是确定给定属性在训练集中的最大值（`MAX`）和最小值（`MIN`）。然后，使用以下公式重新计算该属性的每个值：

```
x - MIN / MAX - MIN
```

## 尝试不同的 k 值

`k-means` 的一个显而易见的缺点是要求用户提供 `k` 的值。这说起来容易做起来难，因为通常情况下，工程师并不知道可用数据自然地会聚成多少个类。除非使用更复杂的技术（关于这些，请见后文），否则解决办法是尝试几个不同的值，然后根据适当的标准（例如在 `Eq. (14.3)` 中定义的标准）选择最好的。正如我们所知，该标准的缺点是它倾向于选择较小的簇。因此，数据分析师通常会将 `SD` 值除以 `k`（聚类数）进行归一化。

### 后处理：合并与分裂簇

`k-means` 创建的簇集通常可以通过后处理技术来提高质量，通过分裂增加簇的数量，或通过合并减少数量。

![image](img/image434.png)

对于合并，如果两个相邻簇的相互距离很小，它们将被合并。为了确定该距离是否值得合并，我们只需计算两个质心之间的距离，然后将其与通过以下和计算出的平均簇间距离进行比较，其中 `ci` 和 `cj` 是质心：

```
SD = d(ci, cj)  (14.4)
i≠j
```
