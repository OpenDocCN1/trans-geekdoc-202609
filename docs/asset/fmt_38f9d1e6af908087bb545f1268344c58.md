### 22.

HTML 表单包含几种往来传输数据的方法。在表单内部，以下哪种方法将输入编码为统一资源标识符 (URI)？

**A.** HEAD

**B.** PUT

**C.** GET

**D.** POST

![Image](img/r.jpg) **C.** HTTP `GET` 是一种从表单返回数据的方法，它将表单数据“编码”到 URI 的末尾（一种识别 Web 资源的字符字符串，例如文本页面、视频剪、图像或应用程序）。例如，如果你在使用 `GET` 的表单中输入信用卡号，生成的 URL 可能会看起来像 `https://somesite.com/creditcard.asp?c#=4013229567852219`，其中那串长长的数字显然是一个静静待在那儿等待任何人使用的信用卡号。

总的来说，`POST` 比 `GET` “更安全”，尽管它们都有各自的用处。如果你在好奇什么时候应该使用 `GET` 而不是 `POST`，答案涉及一个词汇课程：定义*等幂性*（idempotent）这一术语。等幂性常与 HTTP `GET` 一起提到，是一个关于操作属性的数学概念：如果该操作可以在不改变结果的情况下执行（即使运行多次也是如此），就被认为是等幂的。因此，如果确保输入返回对表单的总状态没有产生持久影响，那么使用 `GET` 是完全合理的。此外，`GET` 通常只能传输多达 8KB，而 `POST` 通常可以处理多达 2GB。然而，请记住，它可能会在那个 URI 中包含敏感信息。假设你的表单返回一个信用卡号，而坏人正在记录 URI：如果使用了 HTTP `GET`，攻击者可能推导出这些信息。简而言之，用户可以操纵 `GET` 和 `POST`，但由于 `GET` 依赖于浏览器渲染到屏幕上的可编辑字段内容，它更加可见。`POST` 用于直接推送数据，而 `GET` 则用于预期服务器从 URL 提交的数据中提取某些内容。

![Image](img/w.jpg) **A** 是错误的，尽管 `HEAD` 和 `GET` 相似，但表单中不使用 `HEAD`。它通常用于从 Web 服务器获取标头信息（例如，横幅抓取）并测试链接。

![Image](img/w.jpg) **B** 是错误的，因为表单中不使用 HTTP `PUT`。它用于将文件传输到 Web 服务器。

![Image](img/w.jpg) **D** 是错误的，因为 `POST` 不在 URI 中包含表单数据。根据世界维网联盟 (`www.w3.org/`)，HTML 定义了 `GET` 和 `POST` 的区别。`GET` 意味着表单数据将被浏览器编码到 URL 中，而 `POST` 意味着表单数据出现在消息主体中。
