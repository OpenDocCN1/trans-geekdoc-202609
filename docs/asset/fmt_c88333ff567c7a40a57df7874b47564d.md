#### NAT and Ad Hoc Networking

许多防火墙解决方案提供网络地址转换（NAT），它允许您在网络内部使用专用地址范围，然后将其转换为 NAT 设备上使用的公共地址。这是通过 NAT 设备的一个接口连接到互联网（称为公共接口），而其他接口连接到专用网络（称为专用接口）来实现的。公共接口连接到互联网并获取一个 IP 地址（公共 IP 地址）。NAT 设备上的其他接口被分配专用地址，网络内的所有系统在同一范围内都有一个专用地址。当专用网络上的人尝试浏览互联网时，例如，数据包首先从客户端计算机传送到 NAT 设备，该设备将数据包的专用源 IP 地址切换为 NAT 设备上公共接口的 IP 地址。然后数据包被发送到互联网上，就互联网上的任何人而言，是 NAT 设备在浏览互联网。其余系统仍隐藏在专用网络上。

Ad hoc 网络涉及一种没有中央服务器或设备来创建网络的拓扑；您只需将两个设备连接在一起，例如即时连接两台笔记本电脑，即可创建网络。一个很好的例子是 Ad hoc 无线网络，其中没有无线接入点，只有两台带有无线网卡的笔记本电脑直接相互连接，以便笔记本电脑用户可以共享信息。

#### Proxy Servers

根据定义，代理服务器是代表另一个系统执行功能的服务器。代理服务器负责代表组织内的系统发出互联网资源请求（因为它使用 NAT 技术）。图 8-11 和以下列表详细说明了代理服务器的工作原理：

![Image](img/f0342-01.jpg)

**图 8-11 代理服务器的工作原理**

1. 网络上的工作站（客户端）被配置为将互联网请求发送到代理服务器。

2. 一台工作站向代理服务器提交互联网上网页的请求。

3. 代理服务器代表用户连接到互联网站点，并将请求传输到互联网 Web 服务器。

4. 互联网网站将回复发送给代理服务器。

5. 代理服务器将回复发送给发出请求的原始工作站。

代理服务器的好处是，从外部世界的角度来看，请求来自代理服务器（实际上确实如此）。如果有人查看请求的源 IP 地址并决定攻击该源 IP 地址，那么他们攻击的是代理服务器，而不是内部系统。内部网络中的工作站从未与互联网资源建立连接！

一些代理服务器还实现了缓存功能，它将客户端请求的网页存储在代理服务器上。其好处是，请求同一网页的下一个客户端可以更快地接收该页面，因为代理服务器已经拥有内容，不需要从互联网检索它。

代理服务器还允许管理员有一个中心点，可以在该点记录和过滤用户被允许访问的网站。大多数代理服务器都有报告功能，以便管理员可以查看访问量最大的网站列表。然后，管理员可以选择是否继续允许访问某个站点，或者如果该站点与业务无关，则拒绝访问该站点。

代理服务器的关键功能之一是用户通常向代理服务器进行身份验证，以便代理服务器可以控制用户可以访问哪些网站或可以使用哪些互联网应用程序。

- **Forward and reverse proxy（正向代理和反向代理）**

  正向代理是前面描述的那样——客户端将请求发送到代理服务器，代理服务器在互联网上检索资源并将响应发送给客户端。使用正向代理时，内部系统不会直接与互联网上的系统通信。反向代理用于您希望互联网上的系统能够向您的内部系统（如 Web 服务器或邮件服务器）发送请求的场景。在这种情况下，通信方向被反转，但所有通信仍然通过代理（在这种情况下是反向代理）。互联网上的系统将请求发送到反向代理服务器，后者在检查请求不是恶意的后，将请求转发给内部服务器。

### 透明代理

透明代理是一种代理解决方案，不需要在客户端安装任何软件或进行额外配置。例如，非透明代理解决方案要求你安装代理客户端或代理程序，并配置应用程序将出站请求指向代理服务器。使用透明代理，你无需安装或配置客户端软件；只需将 IP 默认网关设置配置为指向代理服务器即可。用户不会意识到他们已配置为使用代理；他们只会认为默认网关的 IP 地址指向的是路由器地址。

### 应用程序/多用途

代理服务器被称为应用层防火墙，可以检查数据包的许多不同区域，例如数据包的头部和数据部分。这意味着你可以像使用包过滤防火墙那样，按源和目标 IP 地址以及源和目标端口号过滤数据包，但使用应用层代理，你还可以按数据包的数据部分进行过滤。例如，代理会阻止 FTP `put` 命令，但允许 FTP `get` 命令通过代理/防火墙。

### 内容/URL 过滤

代理服务器具备根据网站的 URL 或 URL 中发现的关键字，阻止用户访问不同网站的能力。

#### 路由器和 ACL

企业级设备（如思科等厂商的路由器）内置了许多安全功能。例如，在思科路由器上，你可以创建访问控制列表 (ACL)，配置路由器在每个数据包到达时进行检查，并分析数据包中的第 3 层 (IP) 和第 4 层 (TCP/UDP) 地址，以确定是否允许其通过路由器。

路由器还内置了许多安全功能，可防范已知的安全漏洞，例如 DDoS 防护功能可阻止疑似 DDoS 攻击的流量，反欺骗功能可阻止疑似被欺骗的数据包（有人篡改了其源地址），以防止欺骗路由器允许数据包通过 ACL。

# 使用入侵检测系统

让防火墙保护网络免受不必要流量的侵害绝对是必须的，但网络安全远不止实施防火墙解决方案。你需要确保配置系统以监控内部网络活动，以便在潜在威胁失控之前识别它们。

在本节中，你将了解入侵检测系统以及如何对 Snort（一种非常流行的基于网络的入侵检测系统）进行基本配置。

#### IDS 概述

`入侵检测系统 (IDS)` 负责监控系统或网络上的活动，然后记录或通知管理员任何可疑活动。

##### 分析方法

IDS 如何确定存在可疑流量，取决于 IDS 执行的分析类型。以下部分概述了 IDS 用于确定是否存在可疑流量的不同方法。

**基于特征的系统**  

对于基于特征的 IDS，IDS 具有一个特征文件，其中列出了被视为可疑的活动。当 IDS 捕获活动时，它会将该活动与特征数据库进行比较，如果匹配，则发出入侵通知。

例如，你可能有一个系统，当在短时间内从单个 IP 地址向同一目标系统的多个端口发送大量 SYN 消息时发出通知。这是端口扫描的典型特征。

基于特征的系统的优点是误报很少——意味着极少的虚假警报——因为基于特征的系统完全基于你在系统上配置的特征。因为你在寻找特定活动，所以虚假警报的数量有限。

**基于异常的系统**  

基于异常的系统了解什么是正常活动（基线），然后将超出该正常活动范围的任何行为视为“可疑”活动。基于异常的监控系统通常根据使用系统的人的行为来确定基线。这被称为 `基于行为的异常` 监控系统。

基于行为的异常系统的优点是你不需要配置已知可疑活动的定义文件；系统根据用户的活动学习什么是正常的。基于行为的系统的缺点是任何超出常规的行为都被视为可疑，这会导致大量的虚假警报（误报）。

**启发式/行为分析**  

启发式分析是一种基于存储在数据库中的供应商生成规则来识别恶意活动的分析类型，这些规则随后被检测软件使用。供应商规则是基于过往处理恶意活动的经验创建的。启发式分析是防病毒软件常用的方法。在病毒检测中，启发式分析的目标是检测未知的新病毒。病毒防护软件通常在称为 `虚拟机 (VM)` 的隔离区域中运行程序。然后病毒防护软件分析程序执行时的所有行为，并将其与过往经验进行比较。例如，防病毒软件可能会查找文件覆盖、程序自我复制或试图隐藏自身等恶意活动迹象。

![Image](img/exam.jpg)

> **对于 Security+ 考试，请记住：基于特征的系统根据文件中的特征来判断可疑活动，而这些特征需要你编程或保持最新。基于异常的系统根据活动是否异常来判断恶意活动。启发式分析监控活动，并根据过去的事件判断什么是可疑的。**

## IDS 的类型

在实施入侵检测系统时，你可以选择实施基于主机的 IDS 或基于网络的 IDS。以下是这两种 IDS 类型区别的概述。

### 基于主机的 IDS

你在 第 7 章 中了解到，基于主机的 IDS (HIDS) 安装在单个系统上，并监控该系统上的活动。HIDS 通过监控内存、系统文件、日志文件和网络连接等区域（仅举几例）来识别可疑活动。

实施 HIDS 存在局限性，即它只能监控安装了该软件的系统上的活动。如果你想监控多个系统上的可疑活动，就必须在多个系统上安装 HIDS 软件。

### 基于网络的 IDS

基于网络的 IDS (NIDS) 可以作为独立的网络设备安装，也可以作为软件安装在系统上。无论哪种方式，NIDS 都会分析网络上传输的所有流量。NIDS 分析网络流量，寻找可疑活动，记录活动详情，并发送管理警报。

如 图 8-13 所示，NIDS 由几个协同工作的组件组成，用于识别可疑流量：

![Image](img/f0348-01.jpg)

**图 8-13**  

基于网络的 IDS 的组件

- **传感器** 传感器是放置在每个网段上的软件或硬件，负责收集该网段的流量，然后将流量转发给分析引擎——如果你的基础设施中有收集器，则转发给收集器。收集器是一个从传感器收集所有流量并将其发送给分析引擎的组件。

- **分析引擎** 也称为 `correlation engine`（关联引擎），分析引擎负责接收来自传感器（或收集器）的数据包，然后对数据包执行分析，以确定它们是否被视为可疑。例如，如果在这种情况下 NIDS 是基于特征的 IDS，则分析引擎将数据包与已知可疑流量的数据库进行比较。

- **控制台** 控制台也称为 `administrative console`（管理控制台），通常是发送警报和通知的地方。管理员从控制台配置 NIDS。

## IDS 的类别

对于 Security+ 认证考试，你需要熟悉不同类别的 IDS。IDS 的类别指示 IDS 如何响应可疑活动——它是仅记录活动，还是也采取某种形式的纠正措施？

### 被动 IDS 与内联 IDS

被动 IDS 监控可疑活动，当它检测到认为可疑的活动时，只是将活动记录到日志文件中并向管理员发送通知。重要的是要理解，被动 IDS 不会采取任何措施来尝试保护网络免受进一步的可疑活动侵害。请注意，以这种方式配置的被动 IDS 通常连接到监控端口或网络分流器，以允许 IDS 接收所有网络流量。

内联 IDS 是放置在数据包路径中的 IDS，因此数据包必须通过 IDS 才能到达目的地。这样做的好处是 IDS 可以采取行动（从技术上讲这使它成为 `IPS`，稍后详述），例如在流量可疑时阻断流量。内联 IDS 的另一个好处是，如果 IDS 故障，在 IDS 修复之前，没有数据包能通过该系统。而对于仅接收所有数据副本并监控数据的被动 IDS，如果 IDS 故障，流量仍会到达目的地，但不会被检查。

### 主动 IDS 和 IPS

主动 IDS 监控可疑活动，当它检测到认为可疑的任何活动时，可能会将活动记录到文件中并向管理员发送通知，但它也会采取行动来保护环境。例如，如果主动 IDS 发现某系统正在执行 ping 扫描，它可能会将该系统从网络中断开，以便该可疑系统无法发送更多流量。

重要的是要注意，“主动 IDS” 这一术语已被淘汰，现在主动 IDS 被称为网络 `intrusion prevention system (IPS)`（入侵防御系统），因为它采取措施防止可疑活动继续。

> **针对 Security+ 认证考试，请了解：被动 IDS 仅发送通知或记录可疑活动，因此被视为一种检测控制。入侵防御系统 (IPS) 将采取纠正措施。例如，IPS 可能会将可疑系统从网络中断开，以防止嫌疑系统进行任何其他活动。“主动 IDS” 现在称为 IPS，并被视为一种预防控制。**
