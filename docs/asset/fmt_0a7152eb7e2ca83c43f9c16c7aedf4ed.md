
管理员应将这些扫描配置为在检测到新漏洞时提供自动警报。许多安全团队将其扫描配置为生成扫描结果的自动电子邮件报告，例如图 5.3 所示的报告。

许多不同的因素会影响组织决定对其系统进行漏洞扫描的频率：

*   组织的`风险偏好`是其容忍环境中风险的意愿。如果一个组织极度厌恶风险，它可能会选择更频繁地进行扫描，以最小化漏洞产生到被扫描检测到之间的时间窗口。
*   `法规要求`，例如支付卡行业数据安全标准 (PCI DSS) 或联邦信息安全管理法案 (FISMA) 施加的要求，可能会规定漏洞扫描的最低频率。这些要求也可能来自企业政策。

![FIGURE 5.3 Sample Nessus scan report](img/c05f003.png)

**图 5.3** Nessus 扫描报告示例

*   `技术限制`可能会限制扫描频率。例如，扫描系统每天可能只能执行一定数量的扫描，组织可能需要调整扫描频率以确保所有扫描都能成功完成。
*   `业务限制`可能会阻止组织在业务高峰期进行资源密集型的漏洞扫描，以避免中断关键流程。
*   `许可限制`可能会限制扫描器消耗的带宽或可同时进行的扫描数量。

网络安全专业人员在规划漏洞扫描计划时，必须平衡上述每一项考量。通常明智的做法是从小规模开始，并随着时间的推移缓慢扩大漏洞扫描的范围和频率，以避免使扫描基础设施或企业系统不堪重负。

#### 配置漏洞扫描

漏洞管理解决方案为管理员提供了配置与扫描相关的许多不同参数的能力。除了安排自动扫描和生成报告外，管理员还可以自定义扫描器执行的检查类型、提供访问目标服务器的凭据、在目标服务器上安装扫描代理，并从各种网络视角进行扫描。定期对漏洞扫描器进行`配置审查`非常重要，以确保扫描设置符合当前需求。

##### 扫描灵敏度级别

配置漏洞扫描的网络安全专业人员应仔细关注与扫描灵敏度级别相关的配置设置。这些设置决定了扫描器将执行的检查类型，并应进行自定义，以确保扫描达到其目标，同时最大限度地降低干扰目标环境的可能性。

通常，管理员通过从模板开始来创建新的扫描。这可能是由漏洞管理供应商提供并内置于产品中的模板，例如图 5.4 所示的 Nessus 模板，也可能是为组织内部使用而创建的自定义模板。当管理员创建自己的扫描配置时，应考虑将通用配置设置保存到模板中，以便高效地重复利用工作成果，在配置未来的扫描时节省时间并减少错误。

##### 补充网络扫描

基本漏洞扫描通过网络运行，从远处探测系统。这通过模拟攻击者从另一个网络视角可能看到的内容，提供了系统安全性的现实视图。然而，扫描器与目标服务器之间路径上存在的防火墙、入侵防御系统和其他安全控制可能会影响扫描结果，从而提供一个独立于这些控制之外的、不准确的服务器安全视图。

此外，许多安全漏洞仅靠远程扫描难以确认。通过网络运行的漏洞扫描可能检测到漏洞存在的可能性，但无法有信心地确认它，从而导致误报结果，这需要管理员耗费大量时间进行调查。

现代漏洞管理解决方案可以利用关于服务器配置的可信信息来补充这些远程扫描。收集此信息主要有两种方式。首先，管理员可以向扫描器提供凭据，允许扫描器连接到目标服务器并检索配置信息。然后可以使用这些信息来确定漏洞是否存在，与非凭据扫描相比，提高了扫描的准确性。例如，如果漏洞扫描检测到一个可通过操作系统更新修复的潜在问题，凭据扫描可以在报告漏洞之前检查该更新是否已安装在系统上。

**图 5.6** 配置凭据扫描

###### 扫描视角

全面的漏洞管理计划提供从多种`扫描视角`进行扫描的能力。每个扫描视角从网络上的不同位置进行扫描，提供不同的漏洞视图。例如，外部扫描从互联网运行，让管理员了解组织外部的攻击者会将什么视为潜在漏洞。内部扫描可能从通用企业网络上的扫描器运行，提供恶意内部人员可能遇到的视图。最后，位于数据中心内的扫描器和位于服务器上的代理通过显示可能被网络上其他安全控制阻止的漏洞，提供服务器真实状态的最准确视图。可能影响扫描结果的控制包括：

*   防火墙设置
*   网络分段
*   入侵检测系统（`IDSs`）
*   入侵防御系统（`IPSs`）

##### 漏洞扫描工具

当你构建网络安全工具包时，你会希望拥有网络漏洞扫描器、应用程序扫描器和 Web 应用程序扫描器以供使用。漏洞扫描器常用于预防性扫描和测试，也存在于渗透测试人员的工具包中，帮助他们识别可利用的系统。这一事实也意味着它们是攻击者的最爱工具！

###### 基础设施漏洞扫描

网络漏洞扫描器能够探测各种网络连接设备的已知漏洞。它们连接到网络上连接的任何系统，尝试确定设备类型及其配置，然后启动有针对性的测试，旨在检测这些设备上是否存在任何已知漏洞。

以下工具是网络漏洞扫描器的示例：

*   Tenable 的 `Nessus` 是一款知名且广受尊敬的网络漏洞扫描产品，是该领域最早的产品之一。
*   `Qualys` 的漏洞扫描器是一款较新开发的商业网络漏洞扫描器，提供了一种独特的部署模型，使用软件即服务（`SaaS`）管理控制台，利用位于本地数据中心和云中的设备运行扫描。
*   Rapid7 的 `Nexpose` 是另一款商业漏洞管理系统，提供与 `Nessus` 和 `Qualys` 类似的功能。
*   开源的 `OpenVAS` 为商业漏洞扫描器提供了免费替代方案。

这四款是最常用的网络漏洞扫描器。市场上还有许多其他产品，每个成熟的组织工具包中都应至少有一款扫描器。许多组织选择在同一环境中部署两种不同的漏洞扫描产品作为纵深防御控制。

###### 应用程序扫描

应用程序扫描工具通常用作软件开发过程的一部分。这些工具分析定制开发的软件以识别常见的安全漏洞。应用程序测试使用三种技术进行：

*   `静态测试` 在不执行代码的情况下分析代码。这种方法直接指向开发人员的漏洞，并通常提供具体的修复建议。
*   `动态测试` 作为测试的一部分执行代码，使用各种输入运行代码向用户公开的所有接口，搜索漏洞。
*   `交互式测试` 结合了静态和动态测试，在测试人员通过公开接口与应用程序交互时分析源代码。

应用程序测试应成为软件开发过程的组成部分。许多组织将测试要求引入软件发布流程，要求代码在发布到生产环境前通过测试。

###### Web 应用程序扫描

Web 应用程序扫描器是用于检查 Web 应用程序安全性的专用工具。这些工具测试特定于 Web 的漏洞，例如 SQL 注入、跨站脚本（`XSS`）和跨站请求伪造（`CSRF`）漏洞。它们通过将 Web 服务器的传统网络扫描与使用诸如发送已知恶意输入序列和模糊测试等技术对 Web 应用程序的详细探测相结合来工作，试图破坏应用程序。

`Nikto` 是一款流行的 Web 应用程序扫描工具。它是一款开源工具，任何人都可以免费使用。如图 5.10 所示，它使用命令行界面，使用起来有些困难。

另一款可用于 Web 应用程序扫描的开源工具是 `Arachni`。该工具如图 5.11 所示，是一款适用于 Windows、macOS 和 Linux 操作系统的打包扫描器。

大多数组织确实使用 Web 应用程序扫描器，但它们选择使用提供高级功能和用户友好界面的商业产品。虽然市场上有专用的 Web 应用程序扫描器（如 `Acunetix`），但许多公司使用传统网络漏洞扫描器（如 `Nessus`、`Qualys` 和 `Nexpose`）的 Web 应用程序扫描功能。

#### 理解 CVSS

*通用漏洞评分系统（CVSS）* 是评估安全漏洞严重性的行业标准。它提供了一种根据多种度量对每个漏洞进行评分的技术。网络安全分析师通常使用 CVSS 评级来确定响应行动的优先级。

分析师在对新漏洞评分时，首先根据八个不同的度量对漏洞进行评级。每个度量都会获得一个描述性评级和一个数值评分。前四个度量评估漏洞的可利用性，而后三个度量评估漏洞的影响。第八个度量讨论漏洞的范围。

##### 攻击向量度量

*攻击向量度量* 描述攻击者如何利用该漏洞，并根据表 5.1 所示标准进行赋值。

**表 5.1** CVSS 攻击向量度量

| 值 | 描述 | 评分 |
| --- | --- | --- |
| 物理 (P) | 攻击者必须物理接触易受攻击的设备。 | 0.20 |
| 本地 (L) | 攻击者必须拥有对受影响系统的物理或逻辑访问权限。 | 0.55 |
| 相邻网络 (A) | 攻击者必须拥有受影响系统所连接的本地网络的访问权限。 | 0.62 |
| 网络 (N) | 攻击者可通过网络远程利用该漏洞。 | 0.85 |

##### 攻击复杂性度量

*攻击复杂性度量* 描述利用该漏洞的难度，并根据表 5.2 所示标准进行赋值。

**表 5.2** CVSS 攻击复杂性度量

| 值 | 描述 | 评分 |
| --- | --- | --- |
| 高 (H) | 利用该漏洞需要难以满足的“特殊”条件。 | 0.44 |
| 低 (L) | 利用该漏洞不需要任何特殊条件。 | 0.77 |

##### 所需权限度量

*所需权限度量* 描述攻击者利用漏洞所需的账户访问类型，并根据表 5.3 中的标准进行赋值。

**表 5.3** CVSS 所需权限度量

| 值 | 描述 | 评分 |
| --- | --- | --- |
| 高 (H) | 攻击者需要管理员权限才能发起攻击。 | 0.270（若范围已改变则为 0.50） |
| 低 (L) | 攻击者需要基本用户权限才能发起攻击。 | 0.62（若范围已改变则为 0.68） |
| 无 (N) | 攻击者无需认证即可利用该漏洞。 | 0.85 |

##### 用户交互度量

*用户交互度量* 描述攻击者是否需要让另一个人参与攻击。用户交互度量根据表 5.4 中的标准进行赋值。

**表 5.4** CVSS 用户交互度量

| 值 | 描述 | 评分 |
| --- | --- | --- |
| 无 (N) | 成功利用不需要攻击者以外的任何用户采取行动。 | 0.85 |
| 需要 (R) | 成功利用需要攻击者以外的用户采取行动。 | 0.62 |

##### 机密性度量

`机密性指标` 描述了如果攻击者成功利用该漏洞可能发生的信息泄露类型。机密性指标根据表 5.5 中的标准进行分配。

**表 5.5** CVSS 机密性指标

| 值 | 描述 | 分数 |
| --- | --- | --- |
| 无 (N) | 没有机密性影响。 | 0.00 |
| 低 (L) | 可能访问某些信息，但攻击者无法控制泄露哪些信息。 | 0.22 |
| 高 (H) | 系统上的所有信息均被泄露。 | 0.56 |

##### 完整性指标

`完整性指标` 描述了如果攻击者成功利用该漏洞可能发生的信息篡改类型。完整性指标根据表 5.6 中的标准进行分配。

**表 5.6** CVSS 完整性指标

| 值 | 描述 | 分数 |
