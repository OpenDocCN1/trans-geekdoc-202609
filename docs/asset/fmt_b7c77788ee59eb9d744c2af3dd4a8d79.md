## 20.2 传输问题

尽管这些隐藏信息的方法有着悠久而有趣的历史，但在实践中它们的重要性正在下降。

一个原因（尽管可能不是主要原因）是使用物理材料传输信息的后果。例如，使用 `invisible ink` 假设我们有某种介质来沉积这种墨水。传统上，这可能是一封写在纸上的带有无害信息的信，上面涂有隐形墨水。然后信必须到达目标，可能通过邮政服务或快递。但在电子传输几乎是瞬时且能够处理庞大得的消息或带宽的今天，谁会在纸质上传输此类信息呢？

事实上，在假设电子手段随处可用的情况下，仅仅通过邮件信递进行传输这一事实就可能引起怀疑。例子可能包括几年前寄往华盛顿特区地址（包括 `U.S.` 参议员）的信中的炭疽菌威胁，以及最近通过邮件寄给前总统 `Obama` 和 `Clinton` 的炸弹案例。

然而，减少使用纸张等物理媒介进行隐写术的第二个、且可能更重要的原因是，在文本中嵌入消息面临挑战，例如上述几个例子——编码非常困难！

“fishing freshwater”示例是 23 个字母的隐写；approximately neutral’s protest”隐藏了 24 个字母。尝试在文本中构建一个例如 100 个字母的详细消息而不让容器完全毫无意义，从而引起怀疑。

## 20.3 图像隐写

因此，随着当前的电子时代，隐写术已转向将秘密消息转换为 `bitstring`，然后将 `bitstring` 逐位注入不是文本，而是其他文件格式，例如图像（`JPEG`、`TIFF`、`BMP` 或 `GIF`）或音频或电影文件（`MPEG`、`WAV` 或 `AVI`）。

在图像中嵌入数据时通常有两种类型的文件。持有信息的无害图像是“容器”。“消息”是要隐藏的信息。消息可以是明文、密文、其他图像或可以嵌入图像最低有效位（`LSBs`）的任何内容。

当数字图像文件格式开发出来时，一个主要关注的问题是代表图像的文件大小。因此，开发了两种缩小文件大小的策略。这些策略分别被称为“无损压缩”和“有损压缩”（Kurak and McHugh, 1992）。这两种方法都能节省存储空间，但在信息解压时可能会产生不同的结果。

这两种方法的设计目的都是通过减小图像文件的大小来节省存储空间。无损压缩技术的特性是可以在减小原始图像尺寸的同时，重建出完整的原始图像。有损压缩技术通常能提供更小的文件大小；然而，在压缩之后，无法逐像素地还原精确的图像。因此，如果随后对隐写文件的大小进行压缩，需要小心，因为有损压缩方法可能会导致隐藏信息的破坏。

### 20.5 图像文件格式

图像文件的大小与图像中的像素数量和色深（`每像素比特数`）正相关。然而，图像可以通过多种方式进行压缩。如上所述，压缩算法以较少的字节数存储原始图像的精确表示或近似表示，这些字节可以通过相应的解压缩算法扩展回其未压缩的形式。具有相同像素数量和色深的图像可能具有非常不同的压缩文件大小。

例如，一个 24 位色彩的 640x480 像素图像将占用近一兆的空间：

```
640 × 480 × 24 = 7,372,800 bits = 921,600 bytes = 900 kB
```

最常见的图像文件格式如下。

#### JPEG（联合图像专家小组）

`JPEG (Joint Photographic Experts Group)`

`JPEG`（联合图像专家小组）是一种有损压缩方法。几乎每台数字相机都能以 `JPEG` 格式保存图像，该格式支持 8 位灰度图像和 24 位 RGB 彩彩图像（红、绿、蓝各 8 位）。`JPEG` 有损压缩可以显著缩小文件大小。当压缩程度不是太大时，压缩不会明显影响或损害图像质量，但 `JPEG` 文件在反复编辑和保存时会遭受代际衰减。

#### TIFF（标记图像文件格式）

`TIFF (tagged image file format)`

`TIFF`（标记图像文件格式）格式是一种灵活的格式，通常为每个 RGB 颜色保存 8 或 16 位，分别对应 24 位和 48 位，通常使用 `TIFF` 或 `TIF` 文件扩展名。`TIFF` 可以是有损的也可以是无损的，取决于用于存储像素数据选择的技术。某些格式对双级（黑白）图像提供较好的无损压缩。一些数字相机可以以 `TIFF` 格式保存图像。`TIFF` 图像格式并未被 Web 浏览器广泛支持。

#### BMP（Windows 位图）

`BMP (Windows bitmap)`

`BMP` 文件格式（Windows 位图）用于处理 Microsoft Windows 操作系统中的图形文件。通常，`BMP` 文件是未压缩的，因此体积大且是无损的；它们的优势是结构简单且在 Windows 程序中被广泛。

#### GIF（图形交换格式）

`GIF (graphics interchange format)`

`GIF`（图形交换格式）的正常使用限于 8 位调色板，即 256 色颜色（尽管技术上可以实现 24 位色深）。`GIF` 最适合存储为图表，因为。
