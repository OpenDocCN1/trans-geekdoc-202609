
## 命令行编程与基于浏览器的界面

*   **命令行编程**：此格式提供了一种直接的基于文本的方法来编程交换机的设置。命令行编程要求管理员了解可用于设置不同参数的 `指令集` 和参数变量。

*   **基于浏览器的界面**：这些界面提供了一种图形化的、菜单驱动的工具，用于设置关键交换机参数。使用 `简单网络管理协议` (`SNMP`) 工具，允许管理员通过远程客户端的 Web 浏览器访问交换机的参数。

## 路由器

`路由器` 是网络连接设备，其转发网络信息的方式与交换机类似。然而，与交换机不同的是，路由器可以跨不同网段转发信息，如图 3.13 所示。这使路由器能够通过一种称为路由的过程将不同的网络连接在一起。例如，路由器通常用于将小型住宅网络连接到世界上最大的网络——互联网。

![图 3.13 网络路由器](img/c03f013.png)

**图 3.13** 网络路由器

路由器是基于微处理器的智能设备，用于控制网络间的数据流。微处理器是一种专用设备，经过优化可作为 `路由处理器` 运行。与其他基于微处理器的设备一样，路由器包含用于启动的 `ROM BIOS`、用于保存操作配置参数的 `NVRAM CMOS` 配置区，以及存储在闪存单元中的板载操作系统。

路由器还包含不同区段的 `DRAM` 内存，用于存放消息路由信息，并在其端口间缓冲数据流。路由信息存储并更新在一个称为 `路由表` 的逻辑内存表中。

每个网段均通过路由器的一个物理端口接口连接。这些接口可实现为不同类型的物理/逻辑接口规范，例如 `RJ45/8P8C` 以太网连接端口。

几乎所有路由器都具有一个物理接口，可用于连接外部控制台电缆以进行配置。它们还可能包含一个异步 `RS-232` 串行硬件端口，供管理员执行远程路由器管理功能。

在大型网络中，路由器使用 `路由协议` 与其他路由器通信，以构建和维护其路由表。这些表用于记录不同网络位置之间的最佳路由。与交换机中使用的 `MAC` 表不同，路由表存储设备间路径的地址和跳数信息。

## 安全分区模型

`安全区域` 是一个网段，根据网络资产（资源和数据）的安全漏洞或关键性，为其提供特定级别的安全性。其理念是将更有价值或更关键的网络资产置于提供更多保护的网段或安全结构中。`网络分段` 也称为 `分区`，安全计划的各个层称为 `安全区域`，如图 3.14 所示。

`安全拓扑` 由组织的各个网络安全区域互联组成。安全拓扑超越了简单的网络拓扑，因为它们专门设计用于保护网络每个唯一网段内的关键资产。必须完整规划并实施互补的网络策略和安全拓扑，才能为组织资产提供有效的运行和安全性。

![图 3.14 网络分区](img/c03f014.png)

**图 3.14** 网络分区

良好的安全拓扑旨在将组织资产（如服务器、防火墙、路由器、交换机和客户端工作站）定位并连接在受保护的网段内，以防止未经授权的访问或攻击。

组织的安全拓扑必须基于其安全目标的总体意图。这些目标通常由产品安全官或系统信息安全官 (`CISO`) 确定。他们负责在网络的安全风险与预算限制之间取得平衡，将这些风险降低或最小化至可接受的水平。这需要周密的规划、部门协调、员工认同和管理层支持。

例如，某组织可能需要宽松的远程访问和互联网连接以有效开展业务。因此，在整个组织中严格限制远程访问和互联网访问将不是该组织可接受的选择。

然而，逻辑上需要受限访问的组织部门，如产品开发、会计、人力资源和高管部门，可通过实施网络分段来创建提供网络隔离的特殊安全区域，从而使其更加安全。

应创建可视化拓扑图，以显示服务器、防火墙、路由器、交换机和 `VLAN` 等关键资产，以及它们支持的子网、安全区域或部门。该图应清晰标识分段网络和采用静态 `IP` 地址配置的设备。将所有这些要素以图形格式显示后，设计缺陷应变得显而易见，从而允许将关键资源重新定位到更合适的区域或部门。

大多数 IT 网络分区的逻辑模型可视为类似于图 3.15 所示的多层 `信任区域` 安排。在此示例中，有四个安全区域按安全要求递增的顺序呈环状排列。内部区域存放最安全的资产，受周围安全层的保护。同样，每个后续层为其相邻的环提供安全保护。

![图 3.15 分层区域](img/c03f015.png)

**图 3.15** 分层区域

通常，给定的安全区域将由具有共同安全特征的相似网络资产组成。这些特征包括共享的数据机密性和完整性要求、访问控制，以及审计、日志记录和监控要求。然而，每个区域可包含任意数量的子网，并覆盖任意数量的物理位置。通常用于创建区域间 `分区` 的技术包括交换 `VLAN`、防火墙或路由器等设备，如图 3.16 所示。

### 数据区域与分层安全策略

数据通常被视为企业组织最有价值的资产。这包括从员工信息、财务信息、客户信息到健康信息等不同类型的数据。因此，信息的分类范围可以从机密、内部到公开。当然，机密信息存储在拓扑结构的最内层区域，称为**数据区**。这通常涉及包含机密客户数据的数据库、高度安全的设备、基础设施、策略和政策。

访问该区域中的资源必须经过授权和认证。数据存储加密也在该区域采用。**应用层加密**是首选，但如果没有应用层加密选项，则应采用**文件系统加密**。

组织的机密数据子集通常会定期移动到其他安全区域进行处理和分发。这些内部层的安全策略因分配给资产的机密性和可用性要求而异。

例如，紧邻数据区外侧的**应用区**包含用于处理数据的应用程序。该区域通常部署文件服务器。该区域的信息仍被视为组织的内部数据，受到比“公共”数据更严格的安全措施保护。

与数据区一样，访问应用区需要用户授权和认证，以及服务认证。通常在此级别部署入侵检测系统，以便在发生入侵事件时通知管理员。

将应用区与最外层安全层（通常是互联网）隔开的**呈现区**是组织用户网段的所在地。这可以包括专用于管理局域网的网段。呈现区还用于托管公共接口，如提供“公共”信息的 Web 服务器，以及组织的传输安全工具和结构。

访问该区域的资源仍然需要认证，即使内容被指定为公共。呈现层实施的常见安全措施包括：

*   **防火墙**：防火墙用于控制呈现区与应用区/互联网区之间，以及区域内子网之间的信息流。仅接受来自区域内部或相邻区域的访问请求。

*   **病毒和恶意软件扫描器**：该区域的所有资产都应被要求具备防病毒和反恶意软件保护。

*   **审计工具**：这些工具在此级别实施，用于记录重要的应用程序和安全事件，以便问责和取证。记录的数据绝不能包含被分类为机密的信息。

*   **加固技术**：该区域的所有资产都应通过对其及其应用程序应用加固技术来保护。这些技术将在本章后面详细介绍。

*   **传输安全结构**：这些是 DMZ、VPN 或反向代理，用于为外部用户提供认证（这些结构将在本章后面讨论）。

*   **数据传输加密**：所有被分类为机密的数据在通过网络移动时必须加密。必须使用安全协议（如 HTTPS 和 SSL）替换不太安全的协议（如 HTTP 和 SFTP）。

在此安全拓扑示例中，最外层的**互联网区**代表不受控（互联网）或外部受控（第三方合作伙伴）的网络。该区域包括组织无法控制的所有网络。因此，内容可以是公开的，也可以是属于受信任合作伙伴或客户的机密数据。该区域的访问要求可以是经过认证的，也可以是匿名的。

### 扁平网络拓扑

并非每个企业网络都采用分层、分段的安全拓扑设计。图 3.18 展示了一个通用的**扁平网络拓扑**，许多企业网络（甚至一些非常大的网络）都在使用。扁平网络策略也广泛应用于 OT 网络。

![FIGURE 3.18 A flat network configuration](img/c03f018.png)

**FIGURE 3.18** A flat network configuration

该模型基本上最小化了网络中连接设备（路由器和交换机）的使用。取而代之的是，使用集中式交换机将网络节点连接在一起。在大多数情况下，这些网络通常通过单个路由器与互联网隔离。

这种策略确实降低了网络实施和维护的成本，并降低了管理操作的复杂性。然而，它也导致网络安全级别非常低。在扁平网络中，流量可以在所有网络节点之间自由移动，为所有连接用户提供访问权限。

实际上，它是一个大的广播域。任何发送 ARP 广播以查找有效网络 IP 地址的设备都会收到回复。这意味着如果攻击者获得网络访问权限，他们可以看到网络中的每个资产，包括服务器、终端设备和数据。凭借合适的技能和足够的时间，他们可以利用所有这些设备。

如果恶意软件或恶意代码（如蠕虫，例如著名的 Stuxnet 病毒）获得网络访问权限，则没有任何东西能阻止它蔓延到整个网络。此外，对于源自网络内部的任何恶意活动，几乎没有保护措施。

不幸的是，大多数 OT 网络都是建立在大型扁平网络拓扑之上的。这使得网络攻击或干扰在初始渗透发生后能在网络中快速传播。扁平拓扑还使 OT 网络容易受到网络地图上未显示但构成重大威胁的威胁，当过程控制系统联网时这些威胁会显现。这些威胁包括可能进入工厂并与 ICS 网络通信的无线设备，以及基于 USB 的设备被引入 ICS 系统的能力。

#### OT 安全分区

在 OT 网络内部，应分析流程以确定过程控制网络是否可以按本章前面所述组织成安全段。如果可能，OT 网络应根据管理权限、统一信任级别或网络流量划分为**安全区域**。与 IT 网络一样，良好分段的 OT 网络可以使攻击者更难成功入侵系统，并最大限度地减少非恶意错误的影响。

考虑本章前面介绍的多层纵深防御网络安全拓扑。对于 OT 网络，通常不需要高度受保护的数据库层。相反，ICS 安全拓扑更有可能将网络分段为运营区、控制区、DMZ 和非 ICS 区，如图 3.19 所示。

#### ICS 参考架构

在考察了本章为 IT 和 OT 网络呈现的所有网络模型后，您可能仍会疑惑：如何实际实施这些概念以创建一个安全的 IT/OT 网络环境？

在第 1 章“工业控制系统”中，您已简要了解了 *Purdue ANSI/ISA 95 参考模型架构*。它已成为互联 IT 和 OT 网络的国际标准。

回顾一下，该模型将通用 IT/OT 网络定义为五个层级，范围从工艺与传感器/执行器级别延伸至业务、规划与物流网络级别。在此过程中，它还展示了每个层级上发生的设备类型、网络连接和业务操作。

对于本次安全分区讨论而言，最感兴趣的区域是第 4 级与第 3 级之间描绘的区域，如图 3.20 所示。这是放置 DMZ 以将网络的业务规划与物流部分与制造运营与管理部分分隔开的地方。DMZ 在区域的每一端放置一台防火墙，并编程不同的规则集，以便为每个接口提供所需的安全功能。

![FIGURE 3.20 Where OT meets IT](img/c03f020.png)

**图 3.20 OT 与 IT 的交汇处**

此配置还使得入侵者更难攻破这两台设备以到达网络内部。在某些组织中，这两台防火墙可能由两位不同的管理员管理：IT 网络管理员可能负责管理企业防火墙，而过程控制管理员控制 ICS 防火墙。

基本的 ISA-95 结构常被扩展以满足特定组织需求所带来的安全要求。例如，如果组织拥有强大的互联网业务，例如提供 B2C 和/或 B2B 服务的企业网站，则应扩展网络模型，以提供额外的企业 DMZ 将组织的企业网络与互联网隔离开来，如图 3.21 所示。

*   **数据库区域**：如前所述，企业网络应分层以提供纵深防御策略，例如将存放最敏感数据的数据库隔离在网络的最内层区域。

*   **监控区域**：创建这些区域是为了监控处理和存储生产信息的区域。在这种情况下，在第 3 级和第 4 级均增加了监控区域。这两个区域均由一台防火墙和一个入侵检测系统 (IDS) 组成。

*   **安全区域**：正如第 1 章所述，生产系统通常包含一个独立的仪表与控制系统 (SIS)，专门用于工艺的运行安全。当纳入 ISA-95 架构模型时，该系统显示为独立的一级，位于结构底部，即工艺与 OT 传感器、执行器和控制器所在的位置。之所以显示在此级别，是因为 SIS 必须是一个独立的冗余系统，与 OT 网络断开连接（物理隔离/气隙隔离）。

##### 演进的架构模型

被称为 *Industry 4.0*（工业 4.0）的行业趋势推动 ICS 环境开始将更新技术集成到其 IT/OT 网络拓扑中。这些技术包括云服务、边缘计算和先进的 5G 无线网络以及其他智能设备技术。这一趋势产生了标准安全架构的许多变体，包括一个三部分的 *Industrial Internet of Things* (*IIoT*) 参考架构，如图 3.23 所示。

![FIGURE 3.23 IIoT Purdue Architecture Model](img/c03f023.png)

**图 3.23 IIoT Purdue 架构模型**

该模型的 IIoT 版本将分层 Purdue 模型的五个级别重新归类为三个截然不同的水平层级：

*   **边缘层**：该层包含 Purdue 模型的第 0、1 和 2 级功能。

*   **平台层（云）**：该层通常是一个平台即服务 (PaaS) 云，包含数据存储、分析系统和网络通信设施。该层取代了第 3 级。

*   **企业层**：该层代表组织的 IT 网络，包括其服务器、用户设备和互联网连接。该层对应 Purdue 模型的第 4 级和第 5 级。

除了位于边缘层的传统传感器和执行器外，智能 IIoT 传感器和执行器可以直接与平台层通信，或通过 IIoT 网关通信。企业层（也可能是云环境）也直接与平台层通信。

欧洲联盟网络安全局 (ENISA) 提出的一个 IIoT/Purdue 集成版本修订了分层模型，通过将 IIoT 控制平台与传统的 ISA-95 第 3 级功能相结合，以适应 IIoT 设备的运行。图 3.24 描绘了 ENISA 模型。

目前，尚无广泛接受的 ISA-95/IIoT 集成标准。然而，世界各地的 ICS 标准组织正在致力于 ISA-95 模型的整体替代方案，以及将 IIoT 技术集成到模型中并保持分段和传统 IT/OT 数据移动控制的混合解决方案。

### SANS ICS410 参考模型

SANS（系统管理、审计、网络与安全）组织创建并发布了 Purdue 模型的一个扩展版本，命名为 ICS410 参考模型。该扩展参考架构（如图 3-25a 所示）为向 OT 环境添加云技术和其他技术进步，以及通过 IT 网络将 OT 数据不断向组织上层推送的日益增长的需求做出了规定。

与原始的 ISA-95 Purdue 模型一样，ICS410 模型将 IT/OT 设备和网络划分为功能层，并在分界点部署适当的网络安全设备和系统。然而，它比 Purdue 模型走得更远，将第 0 级至第 2 级层划分为独立但分离的孤岛（单元/生产线/工艺）。ICS410 还将安全系统作为本地第 0-2 级孤岛的一部分。

该模型包含用于集成云服务和其他 WAN 通信通道的控制，以适应更大或广泛分布的站点。传统 Level 0-2 与 Level 3 之间的划分，通过在 Cloud/WAN 系统两侧设置的边界保护来强制执行。在 Level 0-2 侧建立次要执行边界，而在 Level 3 侧应用主要边界执行解决方案。组织的管理服务器、HMI、工程站、测试和预演系统、远程访问以及网络安全运营被划分到 Level 3 层的子层中。

与 Purdue 模型的更高级版本一样，DMZ 在 ICS410 模型中被战略性地部署，以提供 A 到 B 的推送和 B 到 C 的拉取，但在所有 IT 和 OT 层之间不提供 A 到 C 或 C 到 A 的通信路径。防火墙是该模型 Layer 3 和 Layer 4 之间的首选控制设备。这些防火墙应配置为阻止进出 OT 网络的所有流量，并为最小必要流量实施显式允许规则。Level 3 和 Level 4 之间，以及 Level 4 和 Level 5 之间也需要部署防火墙。

包括多因素认证在内的额外认证方法，应用于所有通往 OT 网络的访问路径。应对进出 OT 网络的所有文件执行恶意软件检查。同样，进出 OT 网络的所有流量都应被记录。最后，Level 4 以下不应允许互联网访问。

## 网络分段

*网络分段* 是一种子网划分技术，用于根据组织的职能划分将网络分成分层段。例如，处理高度机密信息的部门通常没有充分理由直接与其他非涉密部门联网。

通常，使用物理防火墙和路由器来创建网络分段，以控制网络层级（段）之间的流量流动。图 3.25 描绘了一个通用的分段业务网络。在该示例中，路由器配置为与互联网连接，并将 IP 地址在 134.141.x.x 范围内的所有数据包传递给本地网络内指定的子网。当数据包到达子网时，它会被地址中指定的第四个八位字节（0-254）的主机接受。
