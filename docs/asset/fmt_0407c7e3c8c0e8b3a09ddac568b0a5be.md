# 如何黑客攻击网站：在线黑客攻击网站示例

比以往任何时候都有更多人访问互联网。这促使许多组织开发基于 Web 的应用程序，用户可以在线使用这些应用程序与组织互动。编写糟糕的 Web 应用程序代码可能被利用以获得对敏感数据和 Web 服务器的未经授权的访问。在本教程中，你将学习如何黑客攻击网站，我们将向你介绍 Web 应用程序黑客技术以及你可以采取的保护措施以防范此类攻击。

## 什么是 Web 应用程序？什么是 Web 威胁？

Web 应用程序（又称网站）是基于客户端-服务器模型的应用程序。服务器提供数据库访问和业务逻辑。它托管在 Web 服务器上。客户端应用程序运行在客户端 Web 浏览器上。Web 应用程序通常用 `Java`、`C#`、`VB.Net`、`PHP`、`ColdFusion Markup Language` 等语言编写。Web 应用程序中使用的数据库引擎包括 `MySQL`、`MS SQL Server`、`PostgreSQL`、`SQLite` 等。大多数 Web 应用程序托管在可通过互联网访问的公共服务器上。这使得它们因易于访问而容易受到攻击。以下是常见的 Web 应用程序威胁。

*   **SQL 注入** – 此威胁的目标可能是绕过登录算法、破坏数据等。
*   **拒绝服务攻击** – 此威胁的目标可能是拒绝合法用户访问资源
*   **跨站脚本 XSS** – 此威胁的目标可能是在客户端浏览器上注入可执行代码。
*   **Cookie/Session Poisoning（Cookie/会话投毒）** – 此威胁的目标是攻击者修改 cookie/会话数据以获得未经授权的访问。
*   **Form Tampering（表单篡改）** – 此威胁的目标是修改表单数据，如电子商务应用程序中的价格，以便攻击者以优惠价格获取商品。
*   **Code Injection（代码注入）** – 此威胁的目标是注入可在服务器上执行的代码，如 `PHP`、`Python` 等。该代码可以安装后门、泄露敏感信息等。
*   **Defacement（篡改/破坏）** – 此威胁的目标是修改网站上显示的页面，并将所有页面请求重定向到包含攻击者信息的单个页面。

## 如何保护你的网站免受黑客攻击？

组织可以采取以下策略来保护自己免受 Web 服务器攻击。

*   **SQL 注入** – 在将用户参数提交到数据库进行处理之前对其进行清理和验证，有助于降低通过 SQL 注入被攻击的几率。`MS SQL Server`、`MySQL` 等数据库引擎支持参数化查询和预处理语句。它们比传统的 `SQL` 语句安全得多。
*   **拒绝服务攻击** – 如果攻击是简单的 DoS，可以使用防火墙丢弃来自可疑 `IP` 地址的流量。网络的正确配置和入侵检测系统也有助于降低 DoS 攻击成功的几率。
*   **跨站脚本** – 验证和清理通过 URL 传递的头部、参数、表单参数和隐藏值，有助于减少 XSS 攻击。
*   **Cookie/Session Poisoning** – 可以通过加密 cookie 内容、在一段时间后使 cookie 超时、将 cookie 与创建它们时使用的客户端 `IP` 地址关联来防止此情况。
*   **Form tempering（表单篡改）** – 可以通过在处理前验证和核实用户输入来防止此情况。
*   **Code Injection（代码注入）** - 可以通过将所有参数视为数据而非可执行代码来防止此情况。清理和验证可用于实现此目的。
*   **Defacement（篡改/破坏）** – 良好的 Web 应用程序开发安全策略应确保封堵访问 Web 服务器的常用漏洞。这可以是操作系统的正确配置、Web 服务器软件以及开发 Web 应用程序时的最佳安全实践。

# 如何在不到 10 分钟内黑客攻击任何 Instagram 账户

一位安全研究人员在发现一个严重漏洞后获得了 30,000 美元奖励，该漏洞可能使任何 Instagram 账户面临被黑客攻击的风险。在 Facebook 和 Instagram 近期增加针对关键账户接管漏洞发现的奖励后，印度安全研究人员 Laxman Muthiyah 选择仔细研究这项照片分享服务。正如他在博客文章中所述，Muthiyah 探索了 Instagram 在处理忘记登录凭据的用户密码重置请求时是否存在漏洞。Muthiyah 发现，当用户通过 Instagram 的 Web 界面请求密码重置时，网站会向用户的电子邮件账户发送重置链接。

经过几分钟的测试，Muthiyah 找不到任何漏洞，于是将注意力转向智能手机用户如何恢复对其 Instagram 账户的访问。Muthiyah 发现，Instagram 为被锁定在账户外的用户提供了一种选择，请求将一个六位数的秘密安全码发送到他们的手机号码或电子邮件账户。如果输入该密码，用户可以重新获得对其 Instagram 账户的访问权限。理论上，如果黑客能够输入该六位数安全码，他们就能闯入 Instagram 账户（并重置密码将合法所有者锁在外面。）现在，如果黑客设法获得了目标的电子邮件账户访问权限，或通过 SIM 卡交换诈骗劫持了受害者的手机号码控制权，该密码可能会被窃取。但 Muthiyah 想知道，如果这两种选择都不可用，是否还有其他方式闯入账户。

Muthiyah 意识到，黑客只需在 Instagram 接受该代码过期前的十分钟窗口期内，输入正确的六位数代码——该代码可能是 `000000` 到 `999999` 之间的任何组合。在十分钟内输入多达一百万个数字，以更改 Instagram 账户的密码。当然，Facebook 和 Instagram 不会坐视自动化脚本尝试暴力破解攻击以猜测正确的安全码。相反，它们设有速率限制，以检测何时多次尝试通过安全检查并减缓后续尝试——这意味着十分钟的机会窗口会过期。在 Muthiyah 的测试中，他发现当他循环尝试 1000 次猜测 Instagram 账户的安全码时，250 个通过了，随后的 750 个请求被速率限制。然而，经过几天的测试，研究人员发现 Instagram 的速率限制机制可以通过轮换 `IP` 地址（换句话说，不使用同一台计算机暴力破解恢复码）并从不同的 `IP` 地址并发发送请求来绕过。使用多个 `IP` 发送并发请求允许我发送大量请求而不受限制。我们可以发送的请求数量取决于 `req` 的并发性和我们使用的 `IP` 数量。此外，我意识到代码在 10 分钟内过期，这使得攻击更难，因此我们需要数千个 `IP` 来执行攻击。” Muthiyah 表示，他使用了 1000 台不同的机器和 `IP` 来实现轻松的并发性，并在测试中发送了 200,000 个请求。他与 Facebook 和 Instagram 的安全团队分享了一个 YouTube 视频，演示了攻击的实际操作：当然，200,000 个请求还不足以保证输入正确的恢复密码以允许 Instagram 账户被劫持，这需要一百万个请求。Muthiyah 的调查结论是，在真实攻击中，需要 5000 个 `IP` 地址来黑客攻击一个 Instagram 账户。虽然这听起来数量很大，但实际上可以以低廉的价格轻松实现（Muthiyah 表示，如果使用 Google 或 Amazon 等云服务提供商，成本约为 150 美元）。所有 Instagram 用户都应该感激 Laxman Muthiyah 选择负责任地向 Instagram 安全团队披露安全漏洞，而不是通过将其出售给网络犯罪分子来获利。很容易想象，这种技术对许多有兴趣攻破 Instagram 账户的黑客极具吸引力，他们可能愿意支付比 Muthiyah 以漏洞赏金形式获得的 30,000 美元多得多的费用。提醒所有互联网用户使用强大、唯一的密码更好地保护他们的在线账户，并在可能的情况下启用双因素认证。
