
#### 7.5.3 Horn clauses and definite clauses

分辨率的完备性使其成为一种非常重要的推理方法。但在许多实际情境中，分辨率的全部力量并不必要。某些真实世界知识库满足其包含句子形式的特定限制，从而可以使用更受限且高效的推理算法。

一种受限形式是 **definite clause**，它是一个由文字组成的析取，其中 *exactly one* 为正。例如，句子 `(¬L[1,1] ⋁ ¬Breeze ⋁ B[1,1])` 是一个 definite clause，而 `(¬B[1,1] ⋁ P[1,2] ⋁ P[2,1])` 不是。

Slightly more general is the **Horn clause**，它是一个文字的析取，其中 *at most one is positive*。因此，所有 definite clauses 都是 Horn clauses，不含正文字的子句也是 Horn clauses；这些被称为 **goal clauses**。Horn clauses 在解析下封闭：如果你解析两个 Horn clauses，得到的仍是一个 Horn clause。

#### 7.5.4 Forward and backward chaining

前向链接算法 `PL-FC-ENTAILS?(KB, q)` 判定单个命题符号 *q*（查询）是否由 definite clauses 知识库蕴涵。它从知识库中的已知事实（正文字）开始。如果一个蕴涵的所有前提均已知，则将其结论加入已知事实集。例如，若 `L[1,1]` 和 `Breeze` 已知，且 `(L[1,1] ⋀ Breeze) ⇒ B[1,1]` 在知识库中，则可加入 `B[1,1]`。此过程持续直到查询 *q* 被加入或无法再进行推理。详细算法见图 7.15；关键点是它在线性时间内运行。

理解该算法的最佳方式是通过示例和图解。图 7.16(a) 显示了一个包含 Horn clauses 的简单知识库，`A` 和 `B` 为已知事实。图 7.16(b) 将同一知识库绘制为 **AND–OR graph**（见第 4 章）。在 AND–OR 图中，由弧连接的多条链接表示合取——每条链接都必须被证明；无弧连接的多条链接表示析取——任意链接被证明即可。很容易在图中看出前向链接的工作原理。已知叶节点（此处为 `A` 和 `B`）被设定，推理尽可能向上传播。出现合取时，传播将等待所有合取项已知后再继续。建议读者详细研究该示例。

> ![image](img/00192.jpg)
>
> **Figure 7.15** The forward-chaining algorithm for propositional logic. The *agenda* keeps track of symbols known to be true but not yet “processed.” The *count* table keeps track of how many premises of each implication are as yet unknown. Whenever a new symbol *p* from the agenda is processed, the count is reduced by one for each implication in whose premise *p* appears (easily identified in constant time with appropriate indexing.) If a count reaches zero, all the premises of the implication are known, so its conclusion can be added to the agenda. Finally, we need to keep track of which symbols have been processed; a symbol that is already in the set of inferred symbols need not be added to the agenda again. This avoids redundant work and prevents loops caused by implications such as *P* ⇒ *Q* and *Q* ⇒ *P*.
