
# DNS 漏洞与交换机安全

## DNS 系统漏洞

名称与 IP 地址之间不必是一对一的映射。将一个名称映射到多个 IP 地址是常见做法，用于负载均衡，使流量分散到不同的物理系统。这种能力也提供了一种应对拒绝服务攻击的方法，通过无缝分发大量入站流量，甚至可能将参与攻击的位置的流量分流，使攻击流量仅干扰其他攻击流量。热门网站也可以在繁忙时段透明地添加额外服务器。

虽然 DNS 是一个低级系统，但它也通过 `whois` 命令提供应用层接口。该命令将提供域名与 IP 地址之间的当前映射，以及关于地址所有者及其权威名称服务器的信息。

DNS 系统存在重大漏洞。如果攻击者能导致 DNS 服务器将请求转发给更高级别的服务器，然后模拟来自该服务器的虚假响应，就能导致虚假条目被包含在该 DNS 服务器的映射表中。普通应用程序随后对映射的请求将被不可见地重定向到错误位置。

DNS 服务器也容易受到拒绝服务攻击。攻击者可以生成大量针对不存在域名的映射请求。这些域名的映射当然是未知的，因此会触发级联请求到更高级别的服务器，而没有任何一台服务器知道该映射，以此类推。

DNS 的弱点已通过允许请求和响应加密部分得到解决。这使得攻击者更难插入虚假内容，因为虚假内容无法被正确加密。然而，旧系统仍需支持，因此在域名请求和响应的加密成为强制要求之前，这帮助不大。

## 6.3 交换机漏洞

交换机只是配置为能够处理大量数据传输的计算机系统，因此它们可以在无需人工直接干预的情况下运行。它们拥有自己的 IP 地址，并运行标准系统软件。交换机是特殊的脆弱点，因为它们参与了数据移动的各个方面。操纵交换机的能力创造了前所未有的攻击和破坏力量。

### 交换机漏洞详解

交换机与其他节点具有相同的漏洞。特别是，它们必须能够安装更新，因此拥有通往外部世界的专用连接——以及一个允许远程访问的管理账户，尽管其正常运行并不需要人工操作员。此类账户必须拥有高权限，因为整个交换机环境必须能够被远程操控——许多交换机部署在难以或无法直接接触的位置。这意味着交换机可能从互联网上的任何地方遭受恶意操控——修改其配置，甚至导致其关机。

交换机也是一种漏洞，因为出于必要，它们能看到流经它们的所有流量。如果它们被攻破，则无需攻击管道即可收集用于流量分析的数据。

交换机还容易遭受物理攻击，因为它们通常在物理上和地理上是隔离的。可以物理接触许多交换机并直接将其移除或销毁。它们的环境也可能被篡改，例如将其加热至超过热额定值，从而阻止其运行。

## 6.4 发起攻击

我们已经看到，某些攻击很容易发起，因为它们依赖于待攻击系统用户的无意配合（特别是网络钓鱼和鱼叉式网络钓鱼）。此类攻击也可能成为攻击其他系统的垫脚石。

无法依赖用户协助的攻击必须采取不同的方法。虽然此类攻击可能以机会目标为对象，但它们更多是针对特定组织的特定计算机。例如，攻击者想要窃取的敏感数据可能存储在合同数据库中。目标计算机可能深藏于该组织的网络环境内部，受多层防火墙保护，或许还部署了入侵检测系统。

此类攻击通常需要一种策略性方法，涉及以下步骤：

### 侦察

没有直接的方法来识别特定的目标计算机。非面向互联网的计算机没有传播到 DNS 服务器的名称，因此难以找到 IP 地址，即使找到了，也只能揭示计算机所在的子网，而无法知道如何到达它。

攻击可能必须从面向互联网的计算机向内渗透，到达其内部邻居，再进而到达预期目标（因此一次攻击实际上需要多次其他攻击作为垫脚石）。显然，垫脚石集合应经过最脆弱的计算机，即使以走更长路径为代价。

因此，侦察的另一个方面是识别可能脆弱的计算机。这就是协议栈指纹识别有用的原因之一——它允许攻击者识别计算机使用的软件版本。了解漏洞列表后，攻击者可以评估每个可见系统作为目标的难易程度。

侦察还可能包括查看每台计算机发起和接收的流量。这可能揭示其用途：是打印服务器？数据库前端？许多看起来不像计算机的设备，例如打印机或物联网设备，也可能面临攻击风险，并为后续步骤提供立足点。这些设备功能齐全，尽管我们往往因其似乎仅具备单一功能而对此视而不见。

`ping` 和 `traceroute` 等工具也可用于探索组织内部环境，尝试推算 IP 地址和结构。例如，子网上并非每个可能的 IP 地址都必然关联设备，攻击不存在的设备毫无意义。

ICMP 中的生存时间特性可用于探测防火墙。如果发送一个生存时间比到达防火墙所需步数大 1 的数据包，若防火墙拦截了它则不会有响应，但若它通过了防火墙（随后耗尽生存时间）则会返回反弹包。攻击者可利用此法查看特定地址和端口组合的流量是否被允许通过防火墙。

这种探测还能提供目标计算机特征的信息。例如，如果 80 端口流量（用于网页浏览）被阻断，则目标计算机不太可能有普通用户。

### 攻击规划

一旦攻击者了解了外部世界与目标系统之间的系统和网络，就可以设计攻击。这需要为所需路径上的每个系统选择攻击手段，以及在攻击不如预期时的备选方案。攻击者必须拥有一套攻击技术和工具储备，并知晓哪些系统易受每种攻击。

### 实际攻击

实际攻击要求按顺序执行每个规划步骤。某些攻击阶段可能涉及探测，以查看特定攻击是否会成功。如果不行，则必须改用另一种方法。

由于攻击通常需要入侵沿途节点链，攻击者通常会在已攻破的系统中植入机制，以便日后无需再次发起攻击即可访问。这些被称为**后门**，可能通过创建新的管理员用户账户，或重新配置接口使其安全性降低来实现，从而可毫不费力地再次利用。

### 清理痕迹

所有计算机系统和交换机都保存记录发生动作的日志文件。这些日志粒度各异，从 TCP 会话到每个登录用户发出的命令均有记录。这些日志文件的主要目的是在节点或管道出现故障时追溯发生了什么。然而，它们同样记录了无辜者和攻击者的活动。

因此，攻击者有动机删除或篡改日志文件以不留痕迹，要么隐瞒攻击发生的事实，要么阻止正确归因。删除日志文件会清除被记录活动的痕迹，但删除行为本身即属可疑。篡改日志文件更佳，但需要更高技巧，且当日志文件众多时，攻击者极易遗漏某个日志中留下的痕迹。

### 留置后门

在攻击者付出所有努力后，自然而然会修改目标系统，使后续攻击（如有需要）变得更容易。我们已提到过让沿途系统更易复用，但让目标系统更易再次攻击更为有用。（当然，为实现此目的而修改目标系统有产生额外痕迹的风险。因此对于数据窃取和其他隐蔽类攻击，保持系统外观完好无损可能更为合适。）

## 6.5 抵御攻击

如果防御者留意观察，可能会发现正在进行的攻击痕迹，甚至是准备阶段的攻击。但现实是，大多数系统持续遭受低强度攻击，几乎全部被防火墙和入侵检测系统挫败。这些系统可配置为在攻击看起来比典型背景噪音更强时向人工发出警报，但设定这些警报的阈值颇具难度。阈值设得太高，会遗漏重要攻击；设得太低，则会产生持续的误报。误报过多时，人员会学会忽略它们。攻击者可利用社会工程学故意触发警报直到被忽视；随后再实施真正的攻击。

最棘手的情况是所谓的**高级持续性威胁（APT）**，这是一种潜在严重但发生频率极低的攻击准备活动，间隔可能长达数周或数月。人们普遍认为这类威胁源自国家行为体，它们耐心地积累关于潜在目标的信息。它们难以被察觉，因为每个单独的步骤看起来都微不足道，且由于步骤之间存在时间间隔，整个攻击序列难以被检测出来。

人们自然会问，为什么计算机系统不都做到尽可能完善的防御？我们在第 4 章中涉及过这一点——管道的行为实际上无法更新；而节点则按固定计划定期更新，通常是每月或每两周一次。

然而，许多系统甚至没有更新到当前的最佳水平，因为人们担心更新会破坏节点的持续运行。企业可能无法承受更新与其核心创收系统交互不良所导致的停机时间。此类企业可能会在隔离环境中试用每个更新，以判断其部署是否会引发问题，而这个过程需要时间。因此，可能存在一些组织的更新状态比其潜在水平滞后数月，这些尚未更新的系统自然成为攻击者的目标。

此外，还有数量惊人的无人值守系统，已被其所有者遗忘。此类系统可能永远不会更新，因此代表了其组织的严重漏洞。某些系统，特别是物联网设备和路由器，根本无法（或极其耗时地）更新。

维护大量计算机保持最新状态涉及资源投入，因此许多组织也被迫进行分级处理，以最好地保护其最关键的系统，并接受对不太重要的系统保留一定风险。组织可以使用**攻击图**来了解其风险水平。这些图表展示了面向互联网的系统有多容易受到攻击，然后基于所有已安装软件的版本，传递性地评估距离互联网一步之遥的系统有多容易受到攻击，以此类推。攻击图可以指示系统人员在哪里进行干预最具成本效益，从而保护整个系统。（攻击图也是攻击者最渴望拥有的，他们试图通过监视隐性地构建攻击图。）

防御者还可以追踪作为监视或早期攻击指标的事件。一种方法是查看记录系统上许多活动的日志。这样做的频率远低于应有的水平，因为日志非常详细（且增长迅速），很难挑选出可能预示探测或攻击准备的异常活动。用于部分自动化此步骤的工具正在出现。尽管如此，日志通常仍只在事后被查看，以弄清攻击是如何发生并将其归因，而不是作为实时防御工具。

一些组织会设置称为**蜜罐**的系统，这些系统被设计成看起来像极具吸引力的目标，但实际上不包含任何真正有价值的东西。防御者可以比监控其他计算机更仔细地监视蜜罐，使其充当触发线，在潜在攻击发生时通知防御者。它们的另一个优势是，防御者可以在攻击者攻击蜜罐的过程中考察其策略，从而了解该攻击者可能如何攻击组织中的其他计算机。

在安全至上的组织中，计算机可能每天都会重新加载其全部软件和系统。这意味着攻击者利用成功攻击的时间非常有限，且无法留下后门以便进一步攻击。

## 6.6 恢复

当成功攻击发生时，防御者必须执行一系列任务以进行恢复，并可能需要在法律层面应对攻击者。

显然，第一阶段是损害控制。某些事件会导致防御者意识到攻击已经发生。防御者必须设法弄清组织遭受了何种损害，并在可能的情况下进行补救。随后，防御者需要弄清攻击是如何实施的。这通常需要对日志进行仔细分析，以寻找攻击的痕迹。

第二阶段是堵住允许攻击发生的漏洞。如果弱点是缺乏更新，这可能很简单；但如果攻击利用了零日机制，可能会更加困难，因为防御者无法轻易确切地弄清发生了什么。

第三阶段是弄清如何（如果可能）将攻击归因于特定主体，并可能进行报复。从原则上讲，归因很困难，因为攻击源很容易隐藏在伪造的源地址背后。然而在实践中，攻击者往往粗心大意，有时甚至不了解有关活动收集了哪些信息，因此有时可以有一定把握地推断出是谁实施了攻击。有趣的是，开发人员在构建恶意软件时似乎无法抗拒在作品上签名的诱惑，这经常有助于归因。

谈到报复，企业等组织可以尝试寻求执法部门介入。这往往效果不佳，因为警力中缺乏具备理解攻击所需技能的员工，法院也是如此。

政府往往在归因问题上采取主动，因为它们需要了解攻击如何融入更大的国际关系框架，并可能诉诸主动网络行动作为一种网络威慑手段。这是一个快速发展的领域。

# 第 7 章：应用安全

大多数应用程序通过使用我们已经讨论过的协议进行通信，特别是 `TCP/IP`。然而，也存在一些协议，允许运行在不同系统上的特定应用程序在更高的抽象层级上相互通信，即将整个管道系统视为一种通信机制，而无需关注其工作细节。

在这种更高的抽象层级上工作，也使得更容易看出某些类型的流量不应被允许。这是由**入侵检测系统**完成的，它们类似于防火墙，但运行在各个节点内部，而不是在管道中。由于其位置特性，它们能更好地判断哪些流量模式（针对正在运行的应用程序的进出流量）是合理的，哪些是不合理的，并阻止那些不合理的流量。因为它们运行在节点内部，也拥有资源以更详细、更宽松的时间限制来检查流量，从而能做得更彻底。

我们现在考虑其中两个应用层系统。

## 7.1 电子邮件

发送电子邮件要求发件人的电子邮件客户端将消息发送到其本地电子邮件服务器。然后，该电子邮件服务器必须将消息传输到目标地址的电子邮件服务器，后者再将其传递给收件人的电子邮件客户端。两台服务器之间的通信机制使用一种称为**简单邮件传输协议（SMTP）**的应用层协议。电子邮件是网络的早期用途之一，该协议可以追溯到可信网络时代。在定义该协议时，安全性并未被纳入考量，因为电子邮件只是一种将简单文本从发件人传递给收件人的方式。

此后，电子邮件被赋予了许多其他功能，例如作为附件传输任意文件，或组织会议。最初极其有限的安全机制并未跟上所有这些新功能的步伐。

### 电子邮件安全的本质

电子邮件的本质决定了其安全性天生难以保障。电子邮件服务器必须易于被发现；否则发送方的邮件服务器就不知道将每封邮件发往何处。（实际情况比这稍微复杂和微妙一些：发送至 `jsmith@corporation.com` 形式地址的邮件，实际上会被发送到诸如 `mailserver.corporation.com` 这样的域，因此涉及的不仅仅是 DNS。）这意味着任何组织至少必须有一台计算机对外部世界可见，这为攻击者了解该组织内部计算机系统的设置提供了一个不可避免的切入点。

根据设计，邮件本应从一台邮件服务器传递到另一台，因此防火墙无法阻断此类流量。入侵检测系统（IDS）必须承担决定是否允许邮件通过的任务。电子邮件系统是开放的，因为任何人都被允许向他们知道或能猜到邮箱地址的任何其他人发送邮件，所以 IDS 规则通常不会根据邮件来源来阻断邮件。垃圾邮件问题表明，这一弱点给用户带来了骚扰，而反垃圾邮件系统对此仅能起到中等程度的缓解作用。

邮件内容通常不加密，因此经过邮件传递路径上的任何系统或交换机都可以读取其内容。曾有许多尝试试图解决这一问题，但所有尝试都因操作过于繁琐而未能得到广泛采用。公钥密码系统当然行之有效。如果你知道收件人的公钥，你可以用该密钥加密内容，接收方便可解密，并确信其在传输途中未被窃读。实现这一点需要知晓接收方的邮箱地址和公钥，发送方可针对单次发送手动完成，但要实现自动化，则需要对整个电子邮件系统进行彻底重新设计。

早期邮件仅为纯文本，但如今的邮件可包含各种格式的附件。许多附件合法地包含可执行代码。例如，Microsoft Word 文档可包含影响其显示方式的可执行宏，尽管 Word 文档看起来似乎只是文本和图像的容器。这使得构建攻击成为可能：附件中的可执行代码在邮件被打开的系统上安装恶意软件，这是网络钓鱼的基本机制。尽管防病毒和反恶意软件会例行扫描这些附件，但很难判断某个特定附件何时或是否包含恶意软件。

邮件客户端通过让用户轻松点击附件以打开它们（这是一种便利，也是一种弱点），以及允许发送方选择显示的文件名（从而使可执行文件伪装成文本文档），加剧了这一问题。电子邮件还可包含链接，用户可在邮件客户端中点击这些链接，从而被导向任意位置；同样，链接文本显示的目标地址未必是链接实际指向的位置。

整个电子邮件系统不包含对邮件内容的任何检查，甚至不验证发件人的身份。伪造 `From:` 地址以隐藏发件人真实身份易如反掌。恶意邮件不会平白无故地暴露发件人是谁。

电子邮件会记录其经过的系统，尽管这些信息通常不在邮件头中直接可见，需要特殊操作才能查看。这有一定优势：可将伪造的发件人追溯到发送消息的系统（或接近源头的系统）。然而，这也影响了普通发件人的隐私，他们可能不愿让他人知晓自己的发帖位置。

能够从家庭位置以外的地方（例如酒店、飞机和火车上）发送邮件非常方便。邮件服务器常被配置为允许任何连接到它们的用户发送邮件，这种做法称为开放中继。遗憾的是，垃圾邮件发送者利用这些系统发送大量垃圾邮件。越来越多的情况下，要发送邮件，必须先连接到自己的家庭系统，或以其他方式向自己的本地邮件服务器进行身份验证。

电子邮件系统中不存在流量控制，因此只需在短时间内向特定系统发送大量邮件，即可使其不堪重负。电子邮件通信是异步的，因此邮件会堆积在目标服务器上，等待用户下载到客户端。这种数据存储极易耗尽大量空间，从而意外或蓄意地瘫痪邮件服务器。

电子邮件是一种尽力而为的通信机制。某些邮件系统提供通知发件人特定邮件已被阅读的功能，但这功能常被滥用——例如垃圾邮件发送者用它来验证某个邮箱地址是否活跃——以至于大多数用户即使在提供该功能的系统上也会将其关闭。然而，大多数人假定电子邮件是可靠的，这有时会导致问题和沟通失误。

## 7.2 Web 流量

万维网是大多数人与网络空间交互的方式。因此，它成为恶意活动的主要目标。

Web 最初是一个信息分发平台。使用浏览器，任何人都可以输入一个 `URL`，获取一个包含内容的网页。网页包含链接，用户可通过点击链接从一个页面跳转到相关页面。当 URL 未知时，Web 搜索引擎使得使用搜索词获取排序后的相关页面列表成为可能。

用于 Web 流量的应用层协议是*超文本传输协议*（`HTTP`），它定义了浏览器与 Web 服务器如何交互。Web 流量使用端口 80，即浏览器使用目标 IP 地址和端口 80 向 Web 服务器发送请求，并通过同一端口号接收结果。由于 Web 访问无处不在，几乎所有系统都允许访问此端口，即防火墙几乎从不阻断它。

越来越多地，`HTTP` 已被 `HTTPS`（`HTTP Secure`）取代，后者是该协议的一个版本，可加密浏览器与网站之间双向的流量。这保护了内容，但当然无法保护所访问的 URL。使用 `HTTPS` 要求网站建立公钥加密机制，这带来了开销，且对于规模较小或技术不够成熟的组织的网站来说可能过于复杂。因此，`HTTPS` 仍未被广泛使用，尽管它已成为最大、最流行的 Web 服务器的常态。一些浏览器开发商曾试图通过威胁强制要求使用 `HTTPS` 来推动其更广泛的采用，但迄今为止尚未成功。`HTTPS` 流量使用端口 443 而非端口 80，因此该端口也几乎必然被防火墙放行。

浏览器-服务器接口的设计初衷是完成一项相对良性且简单的任务（将网页从服务器传送到浏览器），但该接口现已具备更强大的功能：浏览器可向 Web 服务器发送内容，Web 服务器可向浏览器发送由浏览器执行的代码（因此代码在用户本地运行）。这使用户能在浏览器中玩游戏或观看视频。这种新功能导致 `HTTP` 协议定义发生变更，但并非所有变更都经过深思熟虑或精心设计，且（照旧）便利性压倒了安全性。

浏览器可以向 Web 服务器传输数据。有时这仅仅是表单的内容，通常作为使用用户名和密码向 Web 服务器进行身份验证的方式。但浏览器还允许用户在银行账户之间转账、购买产品或从图书馆借阅电子书。相同的机制允许用户向网站发布内容，然后该网站上的其他人也能看到这些内容。例如，用户可以上传视频、状态更新、博客文章，并分享他们的活动，例如他们购买了什么。

除了浏览器与 Web 服务器之间的显式通信外，还存在大量旨在跟踪用户行为的隐式通信（例如，使用 `cookies`）。由于许多用户同时与多个网站交互（可能使用单独的标签页），因此一个网站的交互有机会泄露关于与另一个网站交互的信息。
