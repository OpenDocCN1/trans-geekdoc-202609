
# 网络安全设计与设备

大多数环境中的安全设计依赖于**纵深防御**的概念。换句话说，它们围绕多重控制构建，旨在确保单个控制（甚至多个控制）的失效不太可能导致安全漏洞。在备考时，请考虑如何使用这些组件构建有效的纵深防御设计，以及如何实施它们以确保故障或错误不会使组织面临更大的风险。

牢记纵深防御，了解网络也是分层构建的会有所帮助。开放系统互连（OSI）模型用于概念性地描述设备和软件如何通过网络协同工作。除了概念层面，设计人员还将使用在信任边界分离网络的设备创建安全区域，并部署适合每个安全区域的威胁和安全要求的保护措施。

## 网络分段

### 网络分段与访问控制

网络安全中最常见的概念之一是**网络分段**的理念。网络分段根据信任边界、功能需求或其他有助于组织实施控制或辅助功能的原因，将网络划分为逻辑或物理分组。许多技术和概念用于分段，但最常见的之一是使用**虚拟局域网（VLAN）**。VLAN 在数据链路层建立一个被分段的广播域。交换机或其他设备利用 VLAN 标签创建 VLAN，使跨越多个网络设备（如交换机）的不同端口都能属于同一个 VLAN，而插在这些交换机上的其他系统则不在同一个广播域中。

许多网络设计概念描述了网络分段的具体实现：

*   **DMZ（非军事区）**：包含暴露于低信任区域的系统的网络区域。DMZ 通常用于容纳 Web 服务器或其他面向互联网的设备，但也可描述信任级别不同的内部用途。
*   **内部网**：为向员工或组织其他成员提供信息而建立的内部网络，通常受保护免受外部访问。
*   **外部网**：为外部访问而建立的网络，通常由合作伙伴或客户访问，而非面向大众公众。

尽管许多网络设计过去假定威胁来自用于定义网络段的安全边界之外，但**零信任**网络的核心概念是：无论是内部还是外部的人员或系统，均不予信任。因此，零信任网络应在系统之间以及安全边界处都包含安全措施。

## 网络访问控制

网络分段有助于将网络划分为逻辑安全区域，但保护网络免受未授权访问同样重要。这就是**网络访问控制（NAC）**，有时称为网络准入控制，发挥作用的地方。NAC 技术专注于确定系统或设备是否应被允许连接到网络。如果通过了准入要求，NAC 会将其置于适当的区域中。

为完成此任务，NAC 可使用安装在计算机上的软件代理执行安全检查。或者该过程可能是无代理的，通过浏览器或其他方式运行，无需在本地安装软件。功能各异，软件代理通常能更深入地通过验证补丁级别、安全设置、杀毒软件版本及其他设置和细节来确定机器的安全状态，然后再准许系统接入网络。某些 NAC 解决方案还会跟踪用户行为，如果系统从事可疑行为，可将其从网络中移除。

由于 NAC 能够验证系统的安全状态，它可以成为一种有效的策略执行工具。如果系统不满足安全目标，或存在问题，可将其置于隔离网络中。在那里对系统进行修复并重新检查，或者直接禁止其连接到网络。

NAC 检查可在设备被允许接入网络前（准入前）或连接后（准入后）进行。代理或无代理解决方案与准入前或准入后设计的组合，取决于安全目标和组织所选工具的技术能力。基于代理的 NAC 需要安装，因此增加了复杂性和维护工作，但提供了更深入的洞察和控制。无代理安装轻量级且易于处理，适用于机器可能不受集中管理或设备可能不支持 NAC 代理的用户。然而，无代理安装提供的细节较少。准入前 NAC 决策可将潜在危险系统拒之门外；准入后决策有助于响应，并防止失败的 NAC 接入尝试阻碍业务。

## 端口安全与端口级防护

保护网络免受连接设备的威胁，不仅需要使用 NAC 验证其安全状态。许多防护措施专注于确保网络本身不因在其上传输的流量而陷入危险。

**端口安全**是一项允许你限制单个端口上可使用的 MAC 地址数量的功能。这可防止许多可能的问题，包括 MAC（硬件）地址欺骗、内容可寻址存储器（CAM）表溢出，以及在某些情况下插入额外网络设备以扩展网络。尽管端口安全实现各异，但大多数端口安全功能允许你通过设置最大 MAC 地址数量来动态锁定端口，或静态锁定端口以仅允许特定 MAC 地址。虽然这种类型的 MAC 过滤不如 NAC 细致且提供的信息较少，但它依然有用。

由于欺骗 MAC 地址相对容易，不应依赖端口安全来防止不受信系统连接。尽管如此，配置端口安全有助于在 NAC 不可用或未使用时，防止攻击者轻易连接到网络。它还可防止原本可能发生的 CAM 表溢出攻击。

除了端口安全，协议级防护是交换机和其他网络设备提供的重要安全功能。这些包括：

*   **环路防护**：专注于检测环路并禁用端口，以防止环路引发问题。生成树协议（STP）使用桥协议数据单元，以及思科的环回检测功能等防环实现，发送带有交换机标识符的帧，交换机随即监控这些帧以防止环路。虽然环路可以简单到一根网线两端插在同一交换机上，但环路也可能由插在不同交换机上的网线、反向插入的防火墙、多张网卡插在同一网络不同部分的设备，以及网络中发现的其他错误配置导致。
*   **广播风暴防护**（有时称为风暴控制）：防止广播数据包在遍历网络时被放大。防止广播风暴依赖多项功能，如在将连接用户设备的端口上提供环路保护、在交换机上启用 STP 以确保检测并禁用环路，以及限制广播流量速率。
*   **桥协议数据单元（BPDU）防护**：通过防止不应发送 BPDU 消息的端口发送它们来保护 STP。它通常应用于将插入用户设备和服务器的交换机端口。连接交换机的端口不会开启 BPDU，因为它们可能需要发送 BPDU 消息，作为网络底层管理和控制的一部分，提供关于端口、地址、优先级和成本的信息。
*   **动态主机配置协议（DHCP）侦听**：专注于防止流氓 DHCP 服务器向托管网络中的客户端分发 IP 地址。DHCP 侦听会丢弃任何不在受信服务器列表中的 DHCP 服务器发来的消息，但也可配置附加选项，如阻止源 MAC 与网卡硬件 MAC 不匹配的 DHCP 消息。最后一个安全选项是：如果释放或拒绝 DHCP 提供的消息不是来自发出请求的同一端口，则丢弃该消息，防止攻击者导致 DHCP 提供或续约失败。

这些保护措施看似是显而易见的选择，但网络管理员需要在网络中每个端口的实施管理成本和时间，以及安全设置影响服务时可能产生的意外影响之间取得平衡。实施选择必须考虑攻击发生的可能性、网络段或网络端口访问的受控程度，以及配置和维护所有必须设置的网络端口的难易程度。集中式网络管理工具以及动态和基于规则的管理功能可以减少维护和配置所需的时间，但初始设置和持续支持仍需要投入精力。

## 端口跨接/端口镜像

安全和网络专业人员依赖的最后一个端口级工具是使用`交换机端口分析器 (SPAN)`或`端口镜像`的能力。端口镜像将发送到一个交换机端口的所有流量的副本发送到另一个交换机端口以进行监控。SPAN 可以做同样的事情，但也可以将来自多个端口的流量合并到单个端口进行分析。两者对于故障排除和监控都非常有用，包括为入侵检测系统等设备提供数据，这些设备需要观察网络流量以识别攻击。

## 虚拟专用网络

虚拟专用网络（VPN）是一种跨越公共网络创建虚拟网络链路的方式，使端点表现得就像在同一个网络上一样。虽然很容易将 VPN 视为加密隧道，但加密并非 VPN 隧道的必要条件。

现代网络中主要使用两种 VPN 技术。第一种是 IPSec VPN，它在第三层运行，需要客户端，并且可以在隧道模式或传输模式下运行。在隧道模式下，发送到 VPN 连接另一端的整个数据包受到保护。在传输模式下，IP 头部不受保护，但 IP 有效载荷受到保护。IPSec VPN 常用于站点到站点 VPN，以及需要传输不仅仅是 Web 和应用流量的 VPN。

第二种常见的 VPN 技术是 SSL VPN（尽管它们在当前实现中实际上使用 TLS——此处沿用了以 SSL 代替 TLS 的通用习惯）。SSL VPN 可以使用基于门户的方法（通常使用 HTML5），用户通过网页访问，然后通过该连接访问服务；或者它们可以提供类似 IPSec VPN 的隧道模式。SSL VPN 很受欢迎，因为它们无需安装客户端或 IPSec VPN 通常所需的特定端点配置即可使用。SSL VPN 还提供了细分应用程序访问的能力，使其能够在无需额外复杂配置的情况下实现更细粒度的控制，而大多数 IPSec VPN 工具则需要使用不同的 VPN 名称或主机来创建安全段。

除了 VPN 使用的底层技术外，还有一些实施决策是由 VPN 的用途和需要承载的流量决定的。

许多 VPN 实施的第一个决策点是 VPN 将用于远程访问，还是用作`站点到站点 VPN`。远程访问 VPN 通常用于出差员工和其他远程工作者，而站点到站点 VPN 用于在两个或更多站点之间创建安全的网络通道。由于站点到站点 VPN 通常用于扩展组织的网络，因此它们经常是始终在线的 VPN，意味着它们始终保持连接和可用，并且如果发生故障，会自动尝试重新连接。远程访问 VPN 最常以按需模式使用，远程工作者在需要连接到特定资源或系统时，或需要受信任的网络连接时开启 VPN。

VPN 实施的第二个重要决策是它们将是`分隧道 VPN`还是`全隧道 VPN`。全隧道 VPN 将所有网络流量通过 VPN 隧道发送，使其在前往远程受信任网络的过程中保持安全。分隧道 VPN 仅将发往远程受信任网络上系统的流量通过 VPN 隧道发送。分隧道的优势在于为托管站点节省带宽，因为非发往该网络的流量将通过 VPN 用户连接的任何互联网服务提供商发送。然而，这意味着流量不受 VPN 保护，也无法被监控。

# 网络设备和安全工具

作为网络设计的一部分，您应该考虑许多不同类型的网络设备。组织使用专用硬件设备、虚拟机和基于云的软件设备，以及开源和专有商业版本中的混合模型。

硬件设备具有专用构建的优势，可实现极高速度的流量处理能力或其他功能。软件和虚拟机设备可以轻松部署，并可根据需求进行扩展，而云设备可以根据需要动态创建、扩展和使用。无论底层系统如何，设备都为供应商提供了一种提供集成系统或设备的方式，该系统或设备可以通过已知方式部署和使用，相比于部署在客户自有服务器上的软件包或服务，能提供更受控的体验。

## 跳板服务器和跳板盒

管理员和其他员工需要在具有不同安全级别的安全区域中安全操作的方法。`跳板服务器`，有时称为跳板盒，是一种常见解决方案。跳板服务器是一个经过加固和监控的系统，用于提供这种访问。它通常配置有管理工作所需的工具，并经常通过 SSH、RDP 或其他远程桌面方法进行访问。跳板盒应配置为创建和维护安全的审计跟踪，并在单独的环境中保留副本，以便进行事件和问题调查。

## 负载均衡

负载均衡器用于将流量分发到多个系统、提供冗余，并便于升级和修补。它们通常用于 Web 服务基础设施，但其他类型的负载均衡器也可在许多网络中找到。负载均衡器通常呈现一个`虚拟 IP (VIP)`，客户端在服务端口上向其发送服务请求。然后负载均衡器将这些请求分发给池或组中的服务器。

负载均衡器常见的两种主要运行模式：

*   `主动/主动`负载均衡器设计将负载分发给同时在线并使用的多个系统。
*   `主动/被动`负载均衡器设计在主动系统被移除或未能正确响应健康检查时，将备份或辅助系统上线。这种环境更可能作为灾难恢复或业务连续性环境的一部分，并且被动系统可能提供较少的功能以确保保留某些功能。

负载均衡器依赖各种`调度`或负载均衡算法来选择流量发送的位置。以下是一些最常见的选项：

*   `轮询`：通过遍历列表将每个请求发送给服务器，每个服务器轮流接收流量。
*   `最少连接`：将流量发送给活动连接数最少的服务器。
*   `基于代理的自适应平衡`：监控负载和影响服务器响应能力的其他因素，并根据代理的报告更新负载均衡器的流量分发。
*   `源 IP 哈希`：使用源 IP 的哈希值将流量分配给服务器。这本质上是一种使用客户端驱动输入的随机化算法。

除了这些之外，加权算法还会考虑权重或评分。加权算法包括以下内容：

### 负载均衡算法

*   **加权最少连接**：使用最少连接算法，并结合每台服务器的预定权重值。
*   **固定加权**：依赖每台服务器的预分配权重，通常基于能力或容量。
*   **加权响应时间**：将服务器的当前响应时间与权重值结合以分配流量。

最后，负载均衡器可能需要建立持久会话。**持久性**意味着客户端和服务器在会话期间持续通信。这有助于服务器提供更流畅的体验，并保持关于客户端的一致信息，而不需要让整个负载均衡池都知道客户端的会话。当然，粘性会话也意味着负载将保持在会话开始时的那台服务器上，这需要谨慎，以防过多的长时间运行会话在单台服务器上运行，而所使用的负载均衡算法不监控这种情况。

持久性的使用、不同的服务器能力或可扩展架构的使用等因素，都可以驱动调度算法的选择。通过基于代理的自适应均衡算法等方法跟踪服务器利用率可能很有吸引力，但这比简单的轮询算法需要更多的基础设施和开销。

## 代理服务器

**代理服务器**接受并转发请求，集中处理请求，并允许对请求和响应采取行动。它们可以过滤或修改流量、缓存数据，并且由于它们集中了请求，因此可用于支持基于 IP 地址的访问限制或类似要求。代理服务器主要有两种类型：

*   **正向代理**：位于客户端和服务器之间，接受来自客户端的请求并将其转发给服务器。由于正向代理隐藏了原始客户端，它们可以匿名化流量，或提供对可能因 IP 地址或地理位置而被阻止的资源的访问。它们也常用于允许访问图书馆订阅等资源。
*   **反向代理**：位于服务器和客户端之间，用于帮助负载均衡和内容缓存。因此，客户端可以查询单个系统，但流量负载会分散到多个系统或站点。

## 网络地址转换网关

网络地址转换（NAT）允许将一组地址转换为一个或多个外部地址。通常，NAT 用于允许多个私有 IP 地址使用单个公共 IP 地址访问互联网。**NAT 网关**是提供网络地址转换并跟踪数据包在传输过程中应发送到每个设备的设备。

NAT 网关是常见的网络工具——事实上，它们以互联网路由器的形式存在于许多家庭中，该路由器提供一组私有 IP 地址，并使用 NAT 允许单个外部公共 IP 为路由器后的许多设备提供服务。

NAT 网关常用于云基础设施即服务环境，其中私有地址用于内部网络。NAT 网关服务可用于允许系统连接到互联网。由于 NAT 网关不允许外部系统发起入站连接，除非专门制定规则允许，因此它们可以在不给网关后面的系统带来额外风险的情况下允许安全的出站访问。

## 内容/URL 过滤器

**内容过滤器**是根据内容规则允许或阻止流量的设备或软件。这些规则可以像阻止特定 URL、域或主机一样简单，也可以很复杂，包含模式匹配、IP 信誉和其他内置于过滤规则中的元素。与其他技术一样，它们可以配置允许列表或拒绝列表，以及基于其过滤的内容或流量运行的规则。

代理通常具有内容过滤功能，但内容过滤和 URL 过滤也可以是其他网络设备和设备（如防火墙、网络安全设备、IPS 等）的一部分。

## 数据保护

确保数据不会被提取或无意中从网络发送，这就是**数据丢失防护（DLP）**解决方案发挥作用的地方。DLP 解决方案通常将系统上的代理与网络边界、电子邮件服务器和其他可能的数据渗漏点的过滤功能相结合。当组织担心敏感、专有或其他数据丢失或泄露时，DLP 解决方案是常见的选择。DLP 系统可以使用模式匹配功能，或依赖标记，包括使用元数据来识别应标记的数据。DLP 系统采取的行动可以包括阻止流量、发送通知，或强制识别的数据被加密或以其他安全方式传输，而不是通过未加密或不安全的模式发送。

## 入侵检测和入侵防御系统

基于网络的**入侵检测系统（IDS）**和**入侵防御系统（IPS）**用于检测威胁，在 IPS 的情况下，还可以阻止它们。它们依赖以下三种不同的检测方法中的一种或多种来识别不需要的和潜在的恶意流量：

*   **基于特征的检测**：依赖已知的哈希或特征匹配来检测威胁。
*   **启发式检测**，或**基于行为的检测**：寻找与威胁行为匹配的特定模式或动作集。
*   **基于异常的检测**：为组织或网络建立基线，然后在发生异常行为时标记。

虽然 IPS 需要部署在可以与流量流交互以阻止威胁的直通位置，但 IDS 和 IPS 也可以部署在被动模式下。被动模式可以检测威胁但无法采取行动——这意味着以被动部署方式放置的 IPS 实际上就是一个 IDS。图 12.1 展示了这些部署在简单网络中的样子。

## 硬件安全模块

**硬件安全模块（HSM）**可以作为网络设备部署，用于生成、安全存储和管理加密密钥。它们还可以处理加密处理，允许服务器将 CPU 密集型任务卸载到专用的加密硬件。除了作为硬件设备可用外，HSM 还广泛作为云基础设施即服务产品的一部分提供，包括专用和虚拟选项。

## 数据收集

数据中心的许多组件依赖网络设备来获取数据。硬件和软件设备可以充当传感器，收集关于物理环境、网络流量或其他信息的数据，集中式服务和管理需要这些信息以确保组织的持续运营。由于从传感器获取的数据量可能巨大，因此通常也采用分层设计，使用数据收集器和聚合器来集中数据的子集。收集器和聚合器还可以提供预处理、去重或其他信息管理服务，以确保它们提供数据的中央管理和分析服务器不会不堪重负。

# 防火墙

防火墙是网络设计中最常见的组件之一。它们以网络设备的形式部署，或部署在单个设备上，许多系统都实现了简单的防火墙或类防火墙功能。

*Security+* 考试大纲中包含两种基本类型的防火墙：

*   **无状态防火墙**（有时称为包过滤器）：根据源/目标 IP 和端口、协议以及可从数据包头部获取的其他信息等数据过滤每个数据包。它们是最基本类型的防火墙。
*   **有状态防火墙**（有时称为动态包过滤器）：关注系统间流量的状态。它们可以对会话做出决策，一旦会话被批准即允许其继续，而无需检查每个数据包。它们在状态表中跟踪此信息，并利用收集到的信息查看整个流量流，而非单个数据包，从而提供更多上下文以做出安全决策。
