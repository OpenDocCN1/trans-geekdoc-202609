组织还可能对无线网络进行专门的漏洞评估。Aircrack 是常用于执行这些评估的工具，通过测试无线网络的加密和其他安全参数。它可结合被动监控技术使用，后者可能识别网络上的流氓设备。

### Web 漏洞扫描

Web 应用程序对企业安全构成重大风险。由于其本质，运行许多 Web 应用程序的服务器必须向互联网用户暴露服务。防火墙和其他安全设备通常包含允许 Web 流量无阻碍地通过到 Web 服务器的规则。Web 服务器上运行的应用程序复杂，且通常对底层数据库拥有特权访问。攻击者经常试图利用这些情况，使用结构化查询语言（SQL）注入和其他针对 Web 应用程序安全设计缺陷的攻击。

*Web 漏洞扫描器* 是专门用于搜寻 Web 应用程序已知漏洞的特殊工具。它们在任何安全测试计划中都发挥着重要作用，因为它们可能发现网络漏洞扫描器不可见的缺陷。当管理员运行 Web 应用程序扫描时，该工具使用自动化技术探测 Web 应用程序，通过操纵输入和其他参数来识别 Web 漏洞。然后该工具提供其发现的报告，通常包括建议的漏洞修复技术。图 15.5 显示了使用 Nessus 漏洞扫描工具执行 Web 漏洞扫描的示例。此扫描针对运行在同一服务器上的 Web 应用程序，该服务器曾在图 15.1 中接受网络发现扫描，在图 15.4 中接受网络漏洞扫描。当你阅读图 15.5 中的扫描报告时，请注意它检测到了网络漏洞扫描中未显示的漏洞。

### Web 漏洞扫描

Web 漏洞扫描是组织安全评估和测试计划的重要组成部分。在以下情况下运行扫描是一种良好的实践：

*   当您首次开始执行 Web 漏洞扫描时，扫描所有应用程序。这将检测遗留应用程序的问题。
*   在首次将任何新应用程序移至生产环境之前对其进行扫描。
*   在代码变更移至生产环境之前，扫描任何已修改的应用程序。
*   定期扫描所有应用程序。有限的资源可能要求根据应用程序的优先级安排这些扫描。例如，您可能希望比那些不涉及敏感信息的应用程序更频繁地扫描与敏感信息交互的 Web 应用程序。

在某些情况下，Web 应用程序扫描可能是满足合规要求所必需的。例如，第 4 章“法律、法规和合规”中讨论的支付卡行业数据安全标准（PCI DSS）要求组织至少每年执行一次 Web 应用程序漏洞扫描，或安装专用的 Web 应用程序防火墙，以增加针对 Web 漏洞的额外保护层。

除了 Nessus 之外，其他常用的 Web 应用程序漏洞扫描工具包括商业工具 Acunetix 扫描器、开源工具 Nikto 和 Wapiti 扫描器，以及 Burp Suite 代理工具。

#### 数据库漏洞扫描

数据库包含组织一些最敏感的信息，是攻击者极具诱惑力的目标。虽然大多数数据库受防火墙保护，免受直接外部访问，但 Web 应用程序提供了通往这些数据库的门户，攻击者可能利用数据库支持的 Web 应用程序针对数据库发起攻击，包括 SQL 注入攻击。

数据库漏洞扫描器是允许安全专业人员扫描数据库和 Web 应用程序以查找可能影响数据库安全的漏洞的工具。`sqlmap` 是一种常用的开源数据库漏洞扫描器，允许安全管理员探测 Web 应用程序中的数据库漏洞。图 15.6 展示了 sqlmap 扫描 Web 应用程序的示例。

#### 漏洞管理工作流

采用漏洞管理系统的组织还应制定一种工作流方法来管理漏洞。此工作流中的基本步骤应包括以下内容：

1.  **检测**：漏洞的初始识别通常是漏洞扫描的结果。
2.  **验证**：扫描器检测到漏洞后，管理员应确认该漏洞，以确定它不是误报。
3.  **修复**：然后应修复已验证的漏洞。这可能包括应用供应商提供的安全补丁、修改设备配置、实施变通方法以避免漏洞，或安装 Web 应用程序防火墙或其他防止漏洞被利用的控制措施。

工作流方法的目标是确保以有序的方式检测和解决漏洞。工作流还应包括根据漏洞的严重性、被利用的可能性和修复的难度，对漏洞修复进行优先级排序的步骤。

### 渗透测试

`渗透测试` 超越了漏洞测试技术，因为它实际上会尝试利用系统。漏洞扫描仅探测漏洞的存在，通常不对目标系统采取进攻行动。（也就是说，某些漏洞扫描技术可能会破坏系统，尽管这些选项通常默认处于禁用状态。）另一方面，执行渗透测试的安全专业人员会尝试击败安全控制并闯入目标系统或应用程序，以证明缺陷的存在。

与漏洞扫描相比，渗透测试需要受过训练的安全专业人员投入更多的专注精力。执行渗透测试时，安全专业人员通常以单个系统或一组系统为目标，并使用多种不同的技术来获取访问权限。该过程通常包含以下阶段，如图 15.7 所示：

*   **规划** 包括就测试范围和交战规则达成一致。这是一个极其重要的阶段，因为它确保测试团队和管理层就测试的性质达成一致，并且测试已获得明确授权。
*   **信息收集与发现** 使用手动和自动化工具收集有关目标环境的信息。这包括执行基本侦察以确定系统功能（如访问系统上托管的网站）以及进行网络发现扫描以识别开放端口。
*   **漏洞扫描** 使用网络漏洞扫描、Web 漏洞扫描和数据库漏洞扫描来探测系统弱点。
*   **利用** 尝试使用手动和自动化利用工具来击败系统安全。
*   **报告** 总结渗透测试的结果并提出改进系统安全的建议。

渗透测试人员通常使用一种名为 `Metasploit` 的工具来自动针对目标系统执行利用代码。如图 15.8 所示，Metasploit 使用一种脚本语言来允许自动执行常见攻击，通过消除执行攻击所涉及的许多繁琐、常规步骤，为测试人员（和黑客！）节省了大量时间。

渗透测试人员可能是将这些测试作为其职责一部分的公司员工，也可能是受雇执行渗透测试的外部顾问。测试通常分为三类：

#### 白盒渗透测试

向攻击者提供有关其目标系统的详细信息。这绕过了攻击前通常所需的许多侦察步骤，缩短了攻击时间，并增加了发现安全缺陷的可能性。

#### 灰盒渗透测试

也称为部分知识测试，有时会选择这种测试来平衡白盒和黑盒渗透测试的优缺点。当需要黑盒结果但成本或时间限制意味着需要某些知识来完成测试时，这种情况尤为常见。

#### 黑盒渗透测试

在攻击前不向攻击者提供任何信息。这模拟了外部攻击者试图在发起攻击前获取有关业务和技术环境的信息。

执行渗透测试的组织应当小心谨慎，确保了解测试本身的危害。渗透测试旨在利用漏洞，因此可能会中断系统访问或破坏存储在系统中的数据。这就是为什么在测试规划阶段明确规定交战规则，以及在开始任何测试之前获得高级管理层的完全授权非常重要的主要原因之一。

渗透测试耗时且需要专业资源，但它们在健全的信息安全测试计划的持续运行中发挥着重要作用。

### 测试您的软件

软件是系统安全的关键组件。请思考一下现代企业中许多正在使用的应用程序所共有的以下特征：

*   软件应用程序通常拥有对操作系统、硬件和其他资源的特权访问。
*   软件应用程序例行处理敏感信息，包括信用卡号、社会安全号和专有业务信息。
*   许多软件应用程序依赖也包含敏感信息的数据库。
*   软件是现代企业的核心，执行业务关键功能。软件故障可能会中断业务，造成非常严重的后果。

这些只是仔细测试软件对于每个现代组织的机密性、完整性和可用性要求至关重要的众多原因中的几个。在本节中，您将了解可以集成到组织软件开发生命周期中的多种软件测试类型。

#### 代码审查与测试

软件测试计划中最关键的组成部分之一是进行代码审查和测试。这些程序在代码移入生产环境之前，提供对开发人员所执行工作的第三方审查。代码审查和测试可能会在应用程序上线并对业务运营产生负面影响之前，发现其中的安全、性能或可靠性缺陷。

##### 代码审查

`Code review` 是软件评估计划的基础。在代码审查期间，也称为“同行评审”，编写代码的开发人员以外的其他开发人员会审查代码以查找缺陷。代码审查可能会导致批准应用程序移入生产环境，也可能会将代码连同针对审查中发现的问题的重新修改建议一起退回给原开发人员。

代码审查有多种不同的形式，其正式程度因组织而异。最正式的代码审查流程称为 Fagan 检查，遵循包含六个步骤的严格审查和测试流程：

1.  规划
2.  概述
3.  准备
4.  检查
5.  返工
6.  跟进

Fagan 检查的概述见 图 15.9。这些步骤中的每一个都有定义明确的进入和退出标准，必须满足这些标准，流程才能正式从一个阶段过渡到下一个阶段。

Fagan 检查这种正式程度通常只存在于代码缺陷可能造成灾难性影响的高度受限环境中。大多数组织使用不那么严格的流程，采用包含以下措施的代码同行评审：

*   开发人员在与一个或多个其他团队成员的会议中演示其代码
*   高级开发人员执行手动代码审查，并在代码移入生产环境前对所有代码签署确认
*   使用自动化审查工具在移入生产环境前检测常见的应用程序缺陷

每个组织都应采用适合其业务需求和软件开发文化的代码审查流程。

### 静态测试

`Static testing` 通过分析源代码或编译后的应用程序，在不运行软件的情况下评估软件的安全性。静态分析通常涉及使用旨在检测常见软件缺陷（如缓冲区溢出）的自动化工具。在成熟的开发环境中，应用程序开发人员可以访问静态分析工具，并在设计、构建和测试过程中全程使用它们。

### 动态测试

`Dynamic testing` 在运行时环境中评估软件的安全性，对于部署他人编写的应用程序的组织来说，这通常是唯一的选择。在这些情况下，测试人员通常无法访问底层源代码。动态软件测试的一个常见示例是使用 Web 应用程序扫描工具来检测 Web 应用程序中是否存在跨站脚本、SQL 注入或其他缺陷。在生产环境上进行的动态测试应始终经过仔细协调，以避免无意中中断服务。

动态测试可能包括使用 `synthetic transactions` 来验证系统性能。这些是具有已知预期结果的脚本化事务。测试人员针对被测代码运行合成事务，然后将事务的输出与预期状态进行比较。实际结果与预期结果之间的任何偏差都代表代码中可能存在的缺陷，必须进一步调查。

##### 模糊测试

`Fuzz testing` 是一种专门的动态测试技术，它向软件提供多种不同类型的输入，以测试其极限并发现先前未被检测到的缺陷。模糊测试软件向软件提供无效输入，这些输入要么是随机生成的，要么是专门设计用于触发已知软件漏洞的。模糊测试人员随后监控应用程序的性能，留意软件崩溃、缓冲区溢出或其他不良和/或不可预测的结果。

模糊测试主要分为两大类：

**变异（哑）模糊测试** 从软件实际运行期间的先前输入值获取数据，并对其进行操作（或变异）以创建模糊输入。它可能会改变内容的字符、在内容末尾追加字符串，或执行其他数据操作技术。

**生成（智能）模糊测试** 开发数据模型，并基于对程序所用数据类型的理解创建新的模糊输入。

`zzuf` 工具根据用户规范操作输入，实现了变异模糊测试过程的自动化。例如，图 15.10 显示了一个包含一系列 1 的文件。

### 模糊测试的局限性

模糊测试是一项重要工具，但它也有局限性。模糊测试通常无法实现代码的全覆盖，且通常仅限于检测那些不需要复杂业务逻辑操纵的简单漏洞。因此，模糊测试应被视为一套测试工具中的仅一项工具，进行测试覆盖率分析（本章后面将讨论）以确定测试的完整范围是很有用的。

#### 接口测试

*接口测试*是复杂软件系统开发的重要组成部分。在许多情况下，多个开发团队分别负责复杂应用程序的不同部分，这些部分必须协同工作以实现业务目标。这些独立开发模块之间的交接使用定义良好的接口，以便团队能够独立工作。接口测试根据接口规范评估模块的性能，以确保当所有开发工作完成时，它们能够正常协同工作。

软件测试过程中应测试三种类型的接口：

**应用程序编程接口 (API)** 为代码模块交互提供了一种标准化方式，并可能通过 Web 服务暴露给外部世界。开发人员必须测试 API，以确保它们强制执行所有安全要求。

**用户界面 (UI)** 示例包括图形用户界面 (GUI) 和命令行界面。UI 为最终用户提供与软件交互的能力。接口测试应包括对所有用户界面的审查，以验证其功能是否正常。

**物理接口** 存在于那些操纵机械、逻辑控制器或物理世界中其他对象的应用程序中。软件测试人员应密切关注物理接口，因为如果它们失效，后果可能很严重。

接口为复杂系统的计划内或未来互联提供了重要机制。Web 2.0 世界依赖这些接口的可用性来促进不同软件包之间的交互。然而，开发人员必须小心，接口提供的灵活性不应引入额外的安全风险。接口测试提供了额外的保证，确保接口满足组织的安全要求。

#### 误用用例测试

在某些应用程序中，软件用户可能尝试误用应用程序的方式显而易见。例如，银行软件的用户可能会尝试操纵输入字符串以访问另一个用户的账户。他们还可能尝试从已透支的账户中取款。软件测试人员使用一种称为*误用用例测试*或*滥用用例测试*的过程，来评估其软件针对这些已知风险的脆弱性。

在误用用例测试中，测试人员首先列举已知的误用用例。然后，他们尝试利用手动和/或自动攻击技术来利用这些用例。

#### 测试覆盖率分析

虽然测试是任何软件开发过程的重要组成部分，但遗憾的是，无法完全测试任何一款软件。软件可能发生故障或遭受攻击的方式实在太多。软件测试专业人员通常会进行*测试覆盖率分析*，以估算针对新软件所进行测试的程度。测试覆盖率使用以下公式计算：

```
测试覆盖率 = 已测试用例数量 / 用例总数
```

当然，这是一个高度主观的计算。准确计算测试覆盖率需要列举可能的用例，这是一项异常困难的任务。因此，任何使用测试覆盖率计算的人都应小心理解开发输入值所用的过程，以便在解读结果时做到心中有数。

测试覆盖率分析公式可调整为使用许多不同的标准。以下是五个常见标准：

*   **分支覆盖率**：每个 `if` 语句是否已在所有 `if` 和 `else` 条件下执行？
*   **条件覆盖率**：代码中的每个逻辑测试是否已在所有输入集下执行？
*   **函数覆盖率**：代码中的每个函数是否已被调用并返回了结果？
*   **循环覆盖率**：代码中的每个循环是否已在导致代码多次执行、仅执行一次以及完全不执行的条件下执行？
*   **语句覆盖率**：代码的每一行是否已在测试期间执行？

#### 网站监控

安全专业人员也经常参与网站的持续监控，以进行性能管理、故障排除和识别潜在安全问题。这种监控主要有两种形式。

*   **被动监控** 通过在网络传输过程中或到达服务器时捕获实际发送到网站的网络流量来进行分析。这提供了真实世界的监控数据，让管理员深入了解网络上实际发生的情况。**真实用户监控 (RUM)** 是被动监控的一种变体，其中监控工具重组单个用户的活动以追踪他们与网站的交互。
*   **合成监控**（或**主动监控**）对网站执行人工事务以评估性能。这可能只是从网站请求一个页面以确定响应时间，也可能执行一个复杂的脚本，旨在识别事务的结果。
