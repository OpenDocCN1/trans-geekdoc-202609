
套接字可以“监听”（等待连接）；监听套接字在图 5.6 中显示为 `127.0.0.1:631`。连接期间，套接字对随后变为“已建立”。你可能拥有从同一主机（如 `192.168.80.144`）到同一主机（`192.168.2.4`），甚至到同一端口（`22`）的多个连接。操作系统和路由器等中间设备能够因套接字对而保持这些连接的唯一性。在前面的例子中，两个来自相同源 IP 且发往相同 IP/目的端口的连接将拥有不同的源端口，从而使套接字对（和连接）唯一。

### TCP 标志

最初的六个 TCP 标志是：

*   `URG`：数据包包含紧急数据
*   `ACK`：确认收到的数据
*   `PSH`：将数据推送至应用层
*   `RST`：复位（拆除）连接
*   `SYN`：同步连接
*   `FIN`：结束连接（优雅地）

2001 年新增了两个 TCP 标志：`CWR`（拥塞窗口减小）和 `ECE`（显式拥塞通知回显），利用了 TCP 首部中以前保留的位。2003 年又新增了第三个标志：`NS`（Nonce Sum，随机数和）。这些标志用于管理网络路径上的拥塞（延迟）。所有 9 个 TCP 标志如图 5.7 所示。

### TCP 握手

TCP 使用三次握手建立可靠连接。连接是全双工的，双方相互同步 (`SYN`) 并确认 (`ACK`)。这四个标志的交换分三步完成：`SYN`、`SYN-ACK`、`ACK`，如图 5.8 所示。

![图 5.8 TCP 三次握手。](img/f05-08-9780443187346.jpg)

图 5.8 TCP 三次握手。

客户端选择一个初始序列号，设置在第一个 `SYN` 数据包中。服务端也选择自己的初始序列号，设置在图 5.8 所示的 `SYN/ACK` 数据包中。双方通过将对方的序列号加 1 来确认：这就是确认号。序列号和确认号的使用使双方能够检测丢失或乱序的段。

连接建立后，通常每个段都会跟随 `ACK`。连接最终将以 `RST`（复位或拆除连接）或 `FIN`（优雅地结束连接）结束。

### UDP

UDP 是用户数据报协议，是 TCP 更简单、更快的“表亲”。UDP 没有握手、会话或可靠性保证：因此它非正式地被称为“发送后祈祷”。与 TCP 默认 20 字节的头部相比，UDP 拥有更简单、更短的 8 字节头部（如图 5.9 所示）。UDP 头部字段包括源 IP、目的 IP、数据包长度（头部和数据）以及一个简单的（且可选的）校验和。如果使用校验和，它将为 UDP 头部和数据提供有限的完整性保护。与 TCP 不同，数据通常会立即传输，在第一个 UDP 数据包中完成。UDP 工作在第 4 层。

![图 5.9 UDP 头部 [7]。](images/B9780443187346000039/f05-09-9780443187346.jpg)

图 5.9 UDP 头部 [[7]](#Ch005_225-293_B9780443187346000039.xhtml#bb0040)。

UDP 通常用于“可容忍丢包”的应用程序（能够处理一定的数据包丢失），例如流式音频和视频。它也用于查询-响应应用程序，例如 DNS 查询。

### ICMP

ICMP 是互联网控制消息协议，一种辅助协议，用于辅助第 3 层（IP，参见注释）。ICMP 用于排查故障和报告错误状况：如果没有 ICMP 协助，IP 在面对路由环路、端口、主机或网络宕机等情况时将会失败。与 TCP 和 UDP 不同，ICMP 没有端口的概念，而是使用类型和代码。常用的 ICMP 类型包括回显请求和回显应答（用于 ping）以及传输过程中生存时间超时（用于 traceroute）。

> **注意**
>
> “哪个协议运行在哪一层”通常是激烈争论的主题。我们称之为“归桶游戏”。例如，ICMP 应该归入哪个桶：第 3 层还是第 4 层？ICMP 头部位于第 4 层，就像 TCP 和 UDP 一样，所以许多人会回答“第 4 层”。另一些人则认为 ICMP 是第 3 层协议，因为它协助 IP（一种第 3 层协议），且没有端口。
>
> 这表明归桶游戏是多么随意：抓包显示 ICMP 头部位于第 4 层，因此许多网络工程师倾向于回答“第 4 层”：永远不要与数据包争辩。许多路由协议也存在同样的争论：例如，BGP 用于第 3 层路由，但 BGP 本身由 TCP（和 IP）承载。本书将在正文和自测题中引用界限分明的归桶游戏协议/层，但避开模糊不清的例子（正如考试所应做的那样）。

#### Ping

`Ping`（得名于用于“探测”潜艇的声纳）向节点发送 ICMP 回显请求并监听 ICMP 回显应答。Ping 的设计目的是确定节点是启动还是关闭。

在 ARPAnet 或早期互联网上，当防火墙不常见（或不存在）时，Ping 是节点状态的可靠指示器。如今，ICMP 回显应答是节点处于启动状态的一个相当可靠的指示器。攻击者利用 ICMP 绘制目标网络拓扑，因此许多站点会过滤诸如回显请求和回显应答之类的 ICMP 类型。

无应答的 ping（发出 ICMP 回显请求但未收到回显应答）并不意味着主机已关闭。节点可能已关闭，也可能节点已启动，但回显请求或回显应答可能在某处被过滤了。

#### Traceroute

`traceroute` 命令利用 ICMP 时间超时消息来追踪网络路由。正如在讨论 IP 时所述，生存时间字段用于避免路由环路：每当数据包经过一个路由器，路由器就会递减 TTL 字段。如果 TTL 降为零，路由器将丢弃该数据包，并向原始发送者发送一个 ICMP 时间超时消息。

Traceroute 巧妙地利用了这一 TTL 特性。假设客户端距离服务器四跳：客户端的 traceroute 客户端发送一个 TTL 为 1 的数据包给服务器。路由器 A 将 TTL 递减为 0，丢弃数据包，并向客户端发送一个 ICMP 时间超时消息。路由器 A 由此被识别。

随后客户端发送一个 TTL 为 2 的数据包给服务器。路由器 A 将 TTL 递减为 1 并将数据包转发给路由器 B。路由器 B 将 TTL 递减为 0，丢弃数据包，并向客户端发送一个 ICMP 时间超时消息。路由器 B 由此被识别。此过程持续进行，直到到达服务器，如图 5.10 所示，从而识别出路径上的所有路由器。

## 应用层 TCP/IP 协议与概念

TCP/IP 应用层存在大量协议，该层融合了 OSI 模型的会话层、表示层和应用层。

### Telnet

Telnet 提供网络上的终端仿真。“终端”意指基于文本的 VT100 风格终端访问。Telnet 服务器监听 TCP 端口 23。Telnet 曾是通过网络访问交互式命令 Shell 的标准方式，延续了 20 多年。

Telnet 的弱点在于它不提供机密性；Telnet 会话期间传输的所有数据均为明文，包括用于向系统认证的用户名和密码。能够嗅探网络流量的攻击者可通过这种方式窃取认证凭据。

Telnet 也只有有限的完整性：拥有网络写入权限的攻击者可以篡改数据，甚至劫持 Telnet 会话。安全 Shell（SSH）提供安全认证、机密性和完整性，是 Telnet 的推荐替代品。

### FTP

FTP 是文件传输协议，用于向服务器传输文件或从服务器下载文件。与 Telnet 一样，FTP 既无机密性也无完整性，不应用于通过不安全信道传输敏感数据。

> **注意**
>
> 当讨论 Telnet 和 FTP 等不安全协议时，“无机密性”这类陈述假设它们使用默认设置，且未进行额外加固或加密（例如通过 IPsec VPN 隧道使用它们）。您可以通过在加密 VPN 隧道上运行 Telnet 或 FTP，或用 SSH 替代它们等方式来缓解缺乏机密性的问题。此外，“无完整性”意味着应用层几乎没有或完全没有完整性保护：某些完整性可能由较低层（如传输层）提供。

FTP 使用两个端口：控制连接（发送命令的地方）是 TCP 端口 21；“主动 FTP”使用的数据连接（传输数据的地方）源自 TCP 端口 20。以下是两个套接字对（接下来的两个示例使用任意临时端口）：

*   客户端:1025 → 服务器:21（控制连接）
*   服务器:20 → 客户端:1026（数据连接）

请注意，数据连接源自服务器，方向与控制通道相反。这打破了经典的客户端-服务器数据流向。因此，许多防火墙会阻断主动 FTP 的数据连接，导致主动 FTP 失效。被动 FTP 通过保持所有通信均从客户端发向服务器来解决此问题：

*   客户端:1025 → 服务器:21（控制连接）
*   客户端:1026 → 服务器:1025（数据连接）

FTP 服务器告知客户端要连接的监听数据连接端口；客户端随后发起第二个连接。被动 FTP 更有可能顺利穿越防火墙，因为它符合经典的客户端-服务器流向。

### TFTP

**TFTP** 是简单文件传输协议，运行在 UDP 端口 69 上。它提供了一种更简单的文件传输方式，常用于保存路由器配置，或由无盘工作站通过网络进行“引导”（下载操作系统）。

TFTP 没有认证或目录结构：文件从一个目录读取和写入，通常称为 `/tftpboot`。也没有机密性或完整性。与 Telnet 和 FTP 一样，TFTP 不建议用于通过不安全通道传输敏感数据。

### SSH

SSH 旨在作为 Telnet、FTP 和 UNIX “R” 命令（`rlogin`、`rshell` 等）的安全替代品。除其他功能外，它还提供机密性、完整性和安全认证。SSH 包含用于传输文件的 SFTP (SSH FTP) 和 SCP (Secure Copy)。SSH 还可用于安全地隧道传输其他协议，如 HTTP。默认情况下，SSH 服务器监听 TCP 端口 22。

SSH 版本 1 是最初版本，后来被发现容易受到中间人攻击。SSH 版本 2 是该协议的当前版本，建议优于 SSHv1、Telnet 或 FTP 等使用。

### SMTP、POP 和 IMAP

**SMTP** 是简单邮件传输协议，用于在服务器之间传输电子邮件。SMTP 服务器监听 TCP 端口 25。**POP**v3（邮局协议）和 **IMAP**（互联网消息访问协议）用于客户端-服务器电子邮件访问，分别使用 TCP 端口 110 和 143。

### DNS

**DNS** 是域名系统，一个分布式的全球层级数据库，可将名称转换为 IP 地址，反之亦然。DNS 同时使用 TCP 和 UDP：简短回答使用 UDP 端口 53；大量回答（如区域传输）使用 TCP 端口 53。

两个核心 DNS 函数是 `gethostbyname()` 和 `gethostbyaddr()`。给定一个名称（如 `www.syngress.com`），`gethostbyname()` 返回一个 IP 地址，如 `192.0.2.187`。给定一个地址（如 `192.0.2.187`），`gethostbyaddr()` 返回名称 `www.syngress.com`。

权威名称服务器为给定域内的名称提供“权威”解析。递归名称服务器将尝试解析其尚不知晓的名称。缓存名称服务器将暂时缓存先前解析过的名称。

#### DNS 弱点

DNS 对大多数请求使用不可靠的 UDP 协议，且原生 DNS 不提供认证。DNS 的安全性依赖于 16 位源端口和 16 位 DNS 查询 ID。能够盲目猜测这两个数字的攻击者可以伪造 UDP DNS 响应。

DNS 缓存投毒攻击是指试图欺骗缓存 DNS 服务器缓存伪造的响应。如果 `bank.example.com` 位于 `192.0.2.193`，而 `evil.example.com` 位于 `198.18.8.17`，攻击者可能会尝试通过发送伪造响应“`bank.example.com` 位于 `198.18.8.17`”来投毒 DNS 服务器的缓存。如果缓存 DNS 名称服务器接受了虚假响应，它将对后续的 `bank.example.com` 请求返回投毒后的响应（直到记录过期）。

#### DNSSEC

**DNSSEC**（域名系统安全扩展）通过使用公钥加密为 DNS 响应提供认证和完整性。请注意，DNSSEC 不提供机密性：它的作用类似于 DNS 响应的数字签名。

构建互联网规模的公钥基础设施是一项艰巨的任务，因此 DNSSEC 的采用进展缓慢。安全研究员 Dan Kaminsky 于 2008 年公开了一种改进的 DNS 缓存投毒攻击，这引发了对更广泛采用 DNSSEC 的新呼吁。有关改进的缓存投毒攻击和防御的更多详细信息，请参阅 `https://www.kb.cert.org/vuls/id/800113`。

#### DoT 和 DoH

**DNS over TLS (DoT)** 和 **DNS over HTTPS (DoH)** 是两种竞争标准，它们通过 TLS 传输并加密 DNS 流量。DoT 使用专用端口（TCP 端口 853），而 DoH 使用 TCP 端口 443 上的 HTTPS。与 DNSSEC 不同，两者都在客户端解析器与 DoT 或 DoH 服务器之间提供机密性。DoH 赢得了更大的市场份额，目前在美国 Firefox 中默认使用。

### SNMP

**SNMP** 是**简单网络管理协议**，主要用于监控网络设备。MRTG 等网络监控软件使用 SNMP 轮询网络设备上的 SNMP 代理，并报告接口状态（启用/禁用）、带宽利用率、CPU 温度等众多指标。SNMP 代理使用 UDP 端口 161。

SNMPv1 和 v2c 使用读写团体字符串访问网络设备。许多设备使用默认团体字符串，如“public”用于读访问，“private”用于写访问。此外，这些团体字符串通常很少更改（甚至从不更改），且通常在网络中以明文形式传输。能够嗅探或猜测团体字符串的攻击者可以通过 SNMP 访问网络设备。对写字符串的访问允许远程更改设备，包括关闭或重新配置接口等许多其他选项。

SNMPv3 旨在通过加密为 SNMP 提供机密性、完整性和认证。虽然 SNMPv2c 的使用仍然非常普遍，但由于之前所有版本缺乏安全性，强烈建议使用 SNMPv3。

### HTTP 和 HTTPS

**HTTP** 是超文本传输协议，用于传输未加密的基于 Web 的数据。**HTTPS**（超文本传输安全协议）通过 SSL/**TLS**（见下文“SSL 和 TLS”部分）传输加密的基于 Web 的数据。HTTP 使用 TCP 端口 80，HTTPS 使用 TCP 端口 443。**HTML**（超文本标记语言）用于显示 Web 内容。

> **注意**
>
> HTTP 和 HTML 经常被混淆。区别在于：你通过 HTTP 传输 Web 数据，通过 HTML 查看它。

### BOOTP 和 DHCP

**BOOTP** 是引导协议，用于无盘系统通过网络进行引导。许多系统 BIOS 现在直接支持 BOOTP，允许 BIOS 在没有磁盘的情况下通过网络加载操作系统。BOOTP 启动分两个阶段进行：使用 BOOTP 确定 IP 地址和操作系统镜像名称，然后使用 TFTP 下载操作系统。

**DHCP**（动态主机配置协议）旨在通过添加额外功能来替换和改进 BOOTP。DHCP 允许更多配置选项，并为系统分配临时 IP 地址租约。DHCP 系统可配置为接收 IP 地址租约、DNS 服务器和默认网关等信息。

BOOTP 和 DHCP 都使用相同的端口：服务器使用 UDP 端口 67，客户端使用 UDP 端口 68。

## 传输介质

传输介质包括传输比特的第 1 层技术：网络布线和无线技术。我们现在讨论布线，稍后在本章讨论无线。OSI 模型中最简单的部分是你可以触摸的部分：第 1 层的网络电缆。了解常用的布线类型及其各自的优缺点非常重要。

需要理解的基本网络布线术语包括 EMI、噪声、串扰和衰减。**电磁干扰 (EMI)** 是由电产生的磁性引起的干扰。网络电缆上任何不需要的信号（如 EMI）称为噪声。**串扰** 是指信号从一根电缆串扰到另一根电缆。**衰减** 是指信号随离源头距离增加而减弱。

### 双绞线布线

**非屏蔽双绞线 (UTP)** 网络布线（如图 5.12 所示）使用绞合在一起的线对。所有电流都会产生磁场；将两根传输方向相反的电流的导线（如发送和接收）绞合在一起可以抵消磁场。这使得双绞线布线对 EMI 的敏感度较低。
