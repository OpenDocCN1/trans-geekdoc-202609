
成员服务将为要在区块链上进行交易的用户提供身份概念。这种身份将是一个数字证书，用户将使用此数字证书对其交易进行签名并提交到区块链。签名此类交易的好处是向区块链验证该用户是合法用户，并确保用户对其在网络上执行的交易拥有正确的访问权限。数字证书由证书颁发机构提供。证书颁发机构或默认的 Fabric 证书颁发机构是一个可插模块，可以是任何外部证书颁发机构或默认的 Fabric 证书颁发机构。这一切都使用了基于公钥的基础设施。

### 9.3.2 Fabric SDK

SDK 用于与区块链网络交互，提供 NodeJS、Python 和 Java 等多种语言。我们可以使用这些任何一个 SDK 在区块链上执行交易。

### 9.3.3 背书节点 (Endorsing Peer)

背书节点执行提议的交易但不更新账本。背书节点收集在交易执行期间写入和读取的数据元素。这些在执行期间被读取和写入的数据元素被称为 RW 集，然后背书者对它们进行数字签名并发送回客户端应用程序。

背书节点也可以是提交节点，也可以仅是背书节点。背书节点必须持有链码，但它可能也可能没有账本。

### 9.3.1.4 提交节点 (Committing Peer)

提交节点在验证区块中的交易后，将从排序器接收到的区块提交到其账本中。一旦 commit 验证了收到的区块中的所有交易，该区块就会被添加到提交节点的账本中，并根据交易中收到的写入集（Write Set）更新世界状态。提交节点也可以是背书者，即它可以拥有智能合约。

### 9.3.1.5 排序节点 (Ordering Peer)

排序节点的主要功能是接收经过背书的交易并将它们排序成一个区块。这些排序后的区块由排序节点交付给提交节点。排序服务的主要功能是为节点提供一组完全排序的交易。排序服务本身是去中心化的，可能由许多节点组成。这些节点不拥有智能合约和账本。

### 9.3.2 链码 (Chaincodes)

链码基本上是 Hyperledger 中的智能合约。它们在满足其中写的特定条件时执行。链码用 Go、node.js 或 Java 等多种语言编写。链码部署在背书节点上，一旦部署，就可以通过交易进行调用，并通过交易更新账本状态。

## 9.4 当前电子健康记录 (EHR) 系统的挑战

在当前技术进步之前，医疗行业依赖于纸质系统来存储医疗记录，这是一种手写系统。该系统的问题是效率低下、不可靠且不安全。它在访问性方面存在严重问题，而且一次只能由一个人使用。

随着技术的进步，出现了 EHR 系统，用于以数字格式存储患者的健康记录。然而，这些 EHR 系统在医疗记录的安全性、隐私性、用户数据所有权以及数据完整性方面存在担忧。目前大多数 EHR 数据共享通过传真或邮件进行，这可能导致患者护理的严重延误，这是由于缺乏安全且可靠的医疗记录共享系统造成的。不同机构正在使用多个 EHR 系统，每个系统都有自己的一套术语、技术能力和功能能力；因此，没有全球公认的标准。跨多个 EHR 访问碎片化的患者数据仍然是一个挑战。患者必须经过漫长而费力的过程才能查看他们所有的医疗记录。

医疗行业的数据泄露也是一个严重关注的问题。未经授权访问患者信息不会触发警报，并且不知道哪些信息被访问了。

## 9.4.1 当前健康监测系统的挑战

虽然有越来越多的老年人需要长期护理，但许多人仍希望尽可能保持独立，并居住在自己的家中。在家里，由于缺乏必要的医疗设备，患者无法得到治疗和照顾。在医院里，持续监测患者的基本生命体征是一项关键任务。现在通常是通过使用固定在患者身上和显示器旁边的多个传感器完成的。因此，患者必须在床边固定设备以监测他们的生命体征。

## 9.5 将区块链引入系统的动力

鉴于上述问题，寻求一个可能帮助医疗行业转型为更以患者为中心的平台是合理的。区块链可以提供这样一个既安全又透明的平台，并可以在没有第三方干预的情况下为患者医疗记录提供数据完整性。通过区块链，患者可以跟踪是谁的医疗记录，并且对医疗记录的每次访问都可以以交易的形式永久存储在区块链中。此外，为了提供访问控制，可以使用许可链区块链，使得只有特定的参与者可以访问系统。在这种情况下，我们希望只有患者和患者授权的医生可以查看 EHR。

## 9.6 提议的基于 IoT 的区块链 EHR 系统

我们提出了一种基于 IoT 的许可链区块链系统，该系统可用于医疗领域，部署区块链技术用于 EHR 和远程监测。我们提议的系统的目标是以安全的方式存储医疗记录和患者生命体征数据，并将患者允许的人员访问这些医疗记录，以便我们的系统是以患者为中心的。此外，通过利用云存储，许可链区块链可以利用区块链技术用于 EHR 和远程监控。

## 9.8.2 基于物联网和云服务的健康监测系统

这是我们系统的第二个模块，用于监测患者的生命体征并将其发送到云端进行存储。该模块的工作原理如下。

患者将配备 IoT 传感器（如心电图仪 ECG、血压计、血糖计、体温计等），由于这些传感器将用于收集生物数据。安装在患者身上的 IoT 传感器将无线方式连接到其移动设备，并用于处理数据，生成固定期间整个数据的聚合值（如平均值、最小值、最大值等），然后发送到云端。移动设备将实时从 IoT 传感器接收数据，如果收到的特定数值低于或高于设置的阈值，它将立即发送到云端，云端将向医生发送通知。医生只有在患者允许的情况下才能查看这些数据，并且只能通过在区块链上交易来实现。这样，患者可以看到被访问的数据，并可以控制数据的访问权限，而不是由医生控制。患者获取数据后，可以移除特定医生对其传感器生物数据的访问权限，以便医生无法再次查看。
