#### 9.4.1.3 模型更新

我们始终维护一个固定大小的模型集合（此处为 `K` 个）。因此，当处理新数据块时，集合中已有 `K` 个模型，而第 `K + 1` 个模型将由当前数据块创建。我们需要通过用这个新模型替换一个受害模型来更新集合。受害模型的选择可以通过多种方式进行。一种方法是计算每个模型在最近数据块上相对于多数投票的预测误差。此处，我们假设最近数据块上的 `ground truth`（真实标签）不可用。如果真实标签可用，我们可以利用该知识进行训练。新模型将替换集合中产生最大预测误差的现有模型。

### 9.4.2 无监督基于流的序列学习 (USSL)

正常用户画像被视为重复的日常或每周活动，即命令、系统调用等的频繁序列。这些重复的命令序列被称为规范模式。这些模式揭示了用户的常规或正常行为。当用户突然表现出异常活动，表明其行为显著偏离正常模式时，会针对潜在的内部威胁发出警报。

因此，为了识别内部威胁，首先我们需要找到正常用户行为。为此，我们需要收集命令序列，并以无监督的方式发现这些命令序列中观察到的潜在规范模式。这种无监督方法还需要在单次遍历中识别正常用户行为。这些重复序列的一个主要挑战是其长度的可变性。为了解决这个问题，我们需要生成一个字典，其中将包含采集到的数据流中存在的任何可能的规范模式组合。数据中可能出现的潜在变化包括新事件的开始、现有事件的省略或修改，或序列中事件的重新排序。例如，`liftliftliftliftliftcomcomecomecomecome-come` 是数据流中由给定字母表示的命令序列。我们将把所有模式 `li, if, ft, tl, lif, ift, ftl, lift, iftl` 等视为我们可能的规范模式。然而，字典的巨大规模带来了另一个重大挑战。

我们通过以下方式解决了上述两个挑战。首先，我们使用单遍算法（例如 `LZW`，Lempel-Ziv Welch 算法 [ZIV1977]）从当前数据块中提取可能的模式，以准备一个我们称为 `LZW dictionary`（LZW 字典）的字典。`LZW dictionary` 根据以下公式拥有一组模式及其对应的权重：

$$w_i = \frac{f_i}{\sum_{i = 1}^{n}f_i} \tag{9.6}$$

其中 `w[i]` 是当前数据块中特定模式 `p[i]` 的权重，`f[i]` 是模式 `p[i]` 在当前数据块中出现的次数，`n` 是该数据块中发现的不同模式的总数。

接下来，我们根据模式的关联权重和长度，仅保留最长、频繁的唯一模式来压缩字典，同时丢弃其他被包含的子模式。这种技术称为压缩方法 (`CM`)，新字典称为量化字典 (`QD`)。量化字典包含一组模式及其对应的权重。此处，我们使用编辑距离来寻找最长模式。编辑距离是衡量字符串对之间相似性的指标 [BORG2011, VLAD1966]。它是将一个字符串转换为另一个字符串所需的最少操作次数，其中操作可以是字符的替换、添加或删除。就前面提到的例子而言，量化字典中的最佳规范模式将是 `lift`、`come` 等。

此过程属于有损压缩，但足以提取有意义的规范模式。原因在于我们提取的模式是被包含的子模式的超集。此外，由于频率是我们实验中的另一个控制参数，不常出现的模式不可能是规律的用户模式。

与内部威胁相关的数据通常积累于组织和系统运行的多年间，因此最好将其表征为无界数据流。由于我们的数据是连续的数据流，我们使用基于集成的学习来持续更新我们的压缩字典。这个连续数据流被划分为一系列离散的数据块。例如，每个数据块可能包含一天或几周的数据，并可能包含多个用户会话。我们从每个数据块生成量化字典 (`QD`) 及其关联权重。权重衡量为该模式在该数据块内的归一化频率。

当新数据块到达时，我们生成一个新的量化字典 (`QD`) 模型，并如前所述更新集成。图 9.8 展示了我们的 `dynamic`（动态）、基于集成的无监督流序列学习方法的流程图。算法 9.4 展示了更新集成的基本构建模块。它接收最近的数据块 `S`、集成 `E` 和测试数据块 `T`。第 3-4 行从最近的数据块 `S` 生成一个新的量化字典模型，并暂时将其添加到集成 `E` 中。第 5-9 行使用集成中的每个模型对测试数据块 `T` 进行异常检测。第 13-24 行根据集成中模型的多数投票，在测试数据块 `T` 中查找并标记异常模式。最后，第 29 行通过丢弃准确率最低的模型来更新集成。如果多个模型具有相同的低性能，则丢弃任意一个模型。

#### 9.4.2.1 通过选择数据流中的模式构建 LZW 字典

起初，我们认为数据未被标注（即无监督）。换句话说，我们不知道用户未来可能的操作序列。因此，我们使用 `LZW` 算法 [ZIV1977] 来提取可添加到字典中的可能序列。这些也可以是类似 `liftliftliftliftliftcomcomecomecomecomecome` 的命令，其中每个唯一字母代表唯一的系统调用或命令。我们使用 Unicode 为每个命令建立索引。例如，`ls`、`cp`、`find` 分别索引为 `l`、`c` 和 `f`。添加到我们字典中的可能模式或序列将是 `li, if, ft, tl, lif, ift, ftl, lift, iftl, ftli, tc, co, om, mc, com, come` 等。当序列 `li` 在数据流中第二次被看到时，为了避免重复，它不会被包含在 `LZW` 字典中。相反，我们将频率加 1，并通过将其与数据流中的下一个字符连接来扩展模式，从而产生一个新模式 `lif`。我们将继续此过程直到到达当前数据块的末尾。图 9.9 演示了我们如何从数据流生成 `LZW` 字典。

#### 9.4.2.2 构建量化字典

一旦我们有了 LZW 字典，就会保留最长且最频繁的模式，并丢弃所有被其包含的子模式。算法 9.5 逐步展示了如何从 LZW 字典生成量化字典。该算法的输入如下：包含一组模式 `P` 及其关联权重 `W` 的 LZW 字典 `D`。第 5 行选取一个模式（例如 `li`）。第 7-9 行查找所有编辑距离为 1 的最近模式。第 13-16 行保留权重乘以长度乘积最高的模式，并丢弃其他模式。我们重复这些步骤（第 5-16 行），直到找到最长、最频繁的模式（`lift`）。之后，我们从一个完全不同的模式（`co`）开始，重复这些步骤，直到探索完字典中的所有模式。最终，我们得到一个更紧凑的字典，其中将包含许多有意义且有用的序列。我们称该字典为量化字典。图 9.9 演示了如何从 LZW 字典生成量化字典。一旦我们识别出不同的模式 `lift`、`come` 等，任何与所有这些模式偏离 `X`% （在我们的实现中 ≥ 30%）的模式都将被视为异常。这里，我们将使用编辑距离来识别偏差。

### 9.4.3 异常检测

给定一个量化字典，我们需要找出数据流中可能引起潜在威胁的序列。为了形式化该问题，给定数据流 `S` 和集成 `E`，其中 `E` = `QD`1, `QD`2, `QD`3, …，且 `QD[i]` = `qd[i]`[1]*, `qd`[*i*2]*, …*，如果数据流中的任意模式与 `E` 中的所有模式 `qd[ij]` 的偏差超过 `X`% （例如 >30%），则该模式被视为异常。为了找出异常，我们首先需要找到匹配的模式并从流 `S` 中删除它们。具体而言，我们从数据流 `S` 中找到与 `E` 中任意模式 `qdij` 完全匹配或编辑距离为 `α` 的模式。该模式将被视为匹配模式。`α` 可以是 `qdij` 中该特定模式长度的一半、三分之一或四分之一。接下来，流中剩余的模式将被视为异常。

为了识别数据流 `S` 中的非匹配模式，我们计算一个距离矩阵 `L`，其中包含 `E` 中的每个模式 `qd[ij]` 与数据流 `S` 之间的编辑距离。如果我们有完美匹配，即模式 `qd[ij]` 与 `S` 之间的编辑距离为 0，我们可以在 `S` 中精确向后移动 `qd[ij]` 的长度，以找到该模式的起始点，然后将其从数据流中删除。另一方面，如果匹配中存在大于 0 但小于 `α` 的误差，为了找到该模式在数据流中的起始点，我们需要根据 `L`[`i`, `j-`1]、 `L`[`i-`1, `j-1`]、 `L`[`i-`1, `j`] 中哪个值最小，在矩阵中相应地向左、向对角线或向上遍历。最后，一旦找到起始点，我们就可以将该模式从数据流中删除。数据流中剩余的模式将被视为异常。

## 9.5 总结与展望

我们的方法是将内部威胁检测定义为一个流挖掘问题，并同时处理非序列和序列数据。对于非序列数据，我们描述了两种方法（有监督和无监督学习），用于高效检测流数据中的异常。具体而言，我们提出了一种有监督学习解决方案，利用单类 SVM 应对概念演化。我们通过加权假阴性的代价来提高有监督方法的准确性。我们提出了一种基于 GBAD 的无监督学习算法来应对变化。我们有效地解决了有限标记训练数据（稀有实例问题）的挑战。我们通过统一的方式有效结合了流挖掘和基于图的挖掘的力量。据我们所知，这是首个利用这两种方法进行内部威胁检测的工作。

总之，为了应对概念演化，我们的有监督方法维护一个多个 OCSVM 模型的演化集成。我们的无监督方法将多个 GBAD 模型结合在一个分类器集成中。在两种情况下，集成更新过程的设计都是为了随着流的演化保持集成的时效性。这种演化能力提高了分类器在概念漂移下的生存能力，因为合法和非法代理的行为都会随时间变化。

接下来我们讨论序列数据的内部威胁。与内部威胁检测相关的序列数据本质上是基于流的。序列数据可能随时间收集，甚至长达数年。在这种情况下，我们假设连续数据流将被转换为若干数据块。例如，每个数据块可能代表一周，并包含该时间段内到达的序列数据。关于序列数据，我们提出了一个框架，利用无监督学习（USSL）通过基于流的序列学习，从连续的用户动作或命令中发现模式序列。我们有效地将多个 USSL 模型集成在一个分类器集成中，以利用基于集成的流挖掘和序列挖掘的力量。关于可扩展性问题，我们利用大数据技术。具体而言，可扩展性是构建用于量化字典的良性模式序列时的一个问题。为此，我们利用基于 MapReduce 的框架，并展示了我们工作的有效性。

我们计划在以下方向扩展这项工作。对于无监督学习，我们假设没有可用的真实标签。事实上，随着时间的推移，可能会以反馈的形式获得一些真实标签。一旦以无监督方式创建了模型，我们希望根据用户反馈更新模型。目前，一旦模型创建完成，它就保持不变。当真实标签随时间变得可用时，我们将立即基于此反馈完善所有模型（另见 [MASU2010a]、[MASU2010b] 和 [MASU2010c]）。此外，当我们更新模型时，可能会发生串通攻击 [WANG2009, ZHAO2005]。在这种情况下，`K` 个模型中的一组模型将在一段时间内不被替换。每次选择受害者时，这些串通模型都将存活下来。回顾一下，“串通”是指两个或多个模型之间达成的协议，即它们将始终在预测上达成一致。具体而言，如果我们有 `K` = 3 个模型，两个模型可能保持秘密协议，它们的预测将相同并被用作真实标签。因此，两个串通/隐秘的模型将始终存活，永远不会在模型更新中成为受害者。回顾一下，学习是无监督的，少数服从多数的投票将被视为真实标签。因此，我们将无法捕捉到内部攻击。我们的目标是识别串通攻击。为此，在模型的受害者选择过程中，我们将考虑模型随时间推移的一致性。如果模型的一致性持续很长时间并存活下来，我们将从中选择受害者。
