## 293. 向 VPC 添加第二个互联网网关能带来什么好处？

2. 第二个 VPC 可用于促进与 S3 和 DynamoDB 的 VPC 终端节点
3. 无法向单个 VPC 添加第二个互联网网关
4. 在同一区域内无法拥有两个互联网网关

## 294. 你已创建自定义 VPC、在该 VPC 中创建实例并搭建了 Web 服务器。要向公共互联网提供此 Web 内容，最简单的步骤是什么？（选择两项）

2. 为实例创建 NAT 网关。
3. 创建 ALB 并将其指向实例。
4. 为实例设置公有 IP 地址。

## 295. 你已创建自定义 VPC、在该 VPC 中创建实例、向 VPC 附加了互联网网关并搭建了 Web 服务器。然而，用户无法访问 Web 内容。可能的问题是什么？（选择两项）

1. 安全组不允许出站 HTTP 流量。
2. 安全组不允许入站 HTTP 流量。
3. 实例没有弹性 IP 地址。
4. VPC 子网的 NACL 允许所有入站流量。

## 296. 以下哪项陈述是错误的？

1. 一个 VPC 只能有一个互联网网关。
2. 一个 VPC 可以有多个子网。
3. 单个实例在 VPC 中停止并重新启动时会保留其公有 IP。
4. 单个实例在 VPC 中停止并重新启动时不会保留其公有 IP。

## 297. 以下哪项陈述是错误的？

1. 子网不能跨越多个可用区。
2. 一个 VPC 最多只能与两个其他 VPC 对等连接。
3. VPC 可以与其他 AWS 账户中的 VPC 对等连接。
4. 如果 VPC 附加了互联网网关，子网可以是公有或私有的。

## 298. 为什么要选择 NAT 实例而不是 NAT 网关？

1. NAT 实例比 NAT 网关快。
2. NAT 实例会自动调整大小以适应流量增长，而 NAT 网关不会。
3. NAT 实例由 AWS 自动打补丁保持更新，而 NAT 网关不会。
4. 不会选择；总体而言，NAT 网关比 NAT 实例是更好的解决方案。

## 299. 如何将设置为使用专用宿主租赁的 VPC 更改为使用默认租赁？

1. 可以在不影响运行中实例的情况下更改 VPC 的宿主租赁。
2. 停止 VPC 中的所有实例，然后更改 VPC 的宿主租赁。
3. 移除 VPC 中的所有实例，然后更改 VPC 的宿主租赁。
4. 无法更改；必须重新创建 VPC。

## 300. 对自定义 VPC 内安全组的更改应用的速度有多快？

1. 立即生效
2. 60-90 秒内
3. 下次各实例重启时，或如果实例不重启则在 24 小时内
4. 安全组不与 VPC 关联。

## 301. 你拥有一个带有公有子网的自定义 VPC，且 VPC 已附加互联网网关。为确保子网内的实例能访问互联网，还应执行什么操作？

1. 向路由表添加一条路由，将目标为公共互联网的流量导向互联网网关。
2. 向安全组添加一条规则，允许通过 HTTP 的出站流量。

4. 凭此配置，实例应已具备公共访问权限。
