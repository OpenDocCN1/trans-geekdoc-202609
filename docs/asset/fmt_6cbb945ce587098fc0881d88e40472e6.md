
# 第 3 章：静态返回类型与混合类型声明

## 3.3. 静态返回类型

### 3.3.1. 静态返回类型的用例

静态返回类型在以下场景中特别有用：

- **流式接口**：静态返回类型常用于流式接口，其中方法返回同一个类实例以允许方法链调用。例如，你可以像 `$object->method1()->method2()->method3()` 这样链式调用多个方法。

- **工厂方法**：静态返回类型在创建并返回同一类或子类实例的工厂方法中很有用。这在扩展类时提供了更大的灵活性。

- **构建器模式**：在构建器设计模式中，静态返回类型支持通过方法链逐步构建复杂对象。

- **方法重写**：当子类重写父类的方法时，可以使用静态返回类型来指明重写的方法应返回子类的实例。

### 3.3.2. 示例：流式接口

以下是使用静态返回类型为构建查询对象创建流式接口的示例：

```php
class QueryBuilder {
    private array $query = [];

    public function select(string ...$fields): static {
        $this->query['select'] = $fields;
        return $this;
    }

    public function from(string $table): static {
        $this->query['from'] = $table;
        return $this;
    }

    public function where(string $condition): static {
        $this->query['where'] = $condition;
        return $this;
    }

    public function getQuery(): array {
        return $this->query;
    }
}
```

通过此流式接口，你可以链式调用方法来构建查询：

```php
$queryBuilder = new QueryBuilder();
$query = $queryBuilder->select('id', 'name')
    ->from('users')
    ->where('status = 1')
    ->getQuery();
```

### 3.3.3. 结合静态返回类型的方法重写

在扩展类并重写方法时，你可以使用静态返回类型来确保重写的方法返回子类的实例。这允许更精确的类型提示，并有助于保持代码一致性。示例如下：

```php
class ParentClass {
    public function createChild(): static {
        return new static();
    }
}

class ChildClass extends ParentClass {
    // 使用相同的静态返回类型重写 createChild 方法
}
```

在本例中，当在 `ChildClass` 的实例上调用 `createChild()` 时，它将返回一个 `ChildClass` 的实例。

### 3.3.4. 静态返回类型的优势

静态返回类型在 PHP 开发中提供了多项优势：

- **增强类型安全**：静态返回类型确保方法返回同一类的实例，降低运行时错误的风险，并提高代码的可预测性。

- **方法链**：静态返回类型支持流式接口和方法链，使代码更具表现力且更易读。

- **继承的灵活性**：使用静态返回类型时，子类可以重写方法并返回其自身类的实例，为类层级结构提供了灵活性。

总之，PHP 8 中的静态返回类型为面向对象编程提供了宝贵的增强功能。它们允许你指定方法应返回其所属类的实例，从而提高类型安全性、代码清晰度，并在流式接口和方法链等各种用例中增强灵活性。

## 3.4. 混合类型声明

PHP 8 引入了 `mixed` 类型声明，这是一种通用且灵活的类型提示，可表示任意类型的值。它常用于值的确切类型不确定或可动态变化的场景。在本节中，我们将探讨 `mixed` 类型声明的概念及其在 PHP 开发中的实际应用。

### 3.4.1. 理解 `mixed` 类型

当你预期变量或参数可拥有任意类型的值，且不指定特定类型提示时，可使用 PHP 中的 `mixed` 类型。与 `int`、`string` 或 `bool` 等其他标量类型相比，它是一种更宽容的类型提示。

以下是声明 `mixed` 类型变量的方式：

```php
$variable = "Hello, World"; // $variable 可容纳任意类型的值
```

在此示例中，`$variable` 可容纳字符串、整数、布尔值、对象或任意其他类型的值。

### 3.4.2. `mixed` 类型的用例

`mixed` 类型在需要灵活处理不同类型数据的场景中特别有用。`mixed` 类型的一些常见用例包括：

- **动态数据**：处理可能来自各种来源（如用户输入、API 或数据库）的数据时，实际数据类型可能各不相同。使用 `mixed` 可让你在无类型相关错误的情况下处理这些数据。

- **返回类型**：当函数或方法可根据特定条件返回不同类型的值时，可使用 `mixed` 作为返回类型以适应这些变化。

- **动态函数参数**：在接受可变数量参数或可变类型参数的函数中，使用 `mixed` 可实现更灵活的参数处理。

- **遗留代码集成**：集成未使用严格类型提示的旧代码或库时，可使用 `mixed` 类型处理其数据，而无需进行大量修改。

### 3.4.3. 示例：处理动态数据

以下示例展示如何使用 `mixed` 类型处理动态数据：

```php
function processUserData(mixed $data): void {
    if (is_string($data)) {
        echo "Processing string data: $data";
    } elseif (is_array($data)) {
        echo "Processing array data: ";
        print_r($data);
    } elseif (is_numeric($data)) {
        echo "Processing numeric data: $data";
    } else {
        echo "Unsupported data type";
    }
}

// 用法
processUserData("John Doe"); // 字符串数据
processUserData([1, 2, 3]);  // 数组数据
processUserData(42);         // 数值数据
processUserData(new stdClass()); // 不支持的数据类型
```

在此示例中，`processUserData` 函数接受任意类型的数据（指定为 `mixed`），并根据其实际类型以不同方式处理。这种灵活性让你能优雅地处理各种类型的数据。

### 3.4.4. 将 `mixed` 与其他类型结合使用

你可以在参数类型声明中将 `mixed` 类型与其他类型结合使用。例如：

```php
function processMixedData(mixed $data, string $message): void {
    // ...
}
```

在此示例中，`processMixedData` 函数接受一个 `mixed` 类型的参数和一个 `string` 类型的参数。这种组合让你能在处理动态数据的同时，确保消息始终为字符串。

### 3.4.5. 优势与注意事项

`mixed` 类型为处理动态和不确定的数据提供了灵活性，使代码更健壮、更适应变化。然而，应审慎使用，因为过度使用 `mixed` 会降低类型提示的优势，并减弱代码的可预测性。

虽然 `mixed` 很方便，但必须在代码注释或文档中记录其所代表数据的预期类型和条件。这有助于保持代码清晰，并使开发者更易理解预期的数据行为。

总之，PHP 8 中的 `mixed` 类型是类型提示的一项宝贵补充，为处理不确定或多变类型的数据提供了灵活性。它在处理动态数据源或集成未使用严格类型提示的代码时特别有用。不过，应审慎使用并清晰记录，以保持代码的可读性和可预测性。

## 3.5. 空安全运算符

PHP 8 引入了空安全运算符（`?->`），这是一项实用功能，简化了在潜在为 null 的对象上访问属性和方法的过程。该运算符在处理可能存在也可能不存在的对象时，显著减少了对显式空值检查和条件语句的需求。在本节中，我们将探讨空安全运算符及其在 PHP 开发中的实际应用。

### 3.5.1. 理解空安全运算符

在 PHP 8 之前，使用对象属性或方法时，通常需要执行空值检查，以避免“Call to a member function on null”（在 null 上调用成员函数）或“Trying to access an array offset on null”（尝试在 null 上访问数组偏移量）等错误。空安全运算符（`?->`）通过自动检查对象是否为 null 并在对象为 null 时返回 null，简化了这一过程。

以下是空安全运算符工作原理的基本示例：

```php
$object = null; // 或一个对象实例

// 不使用空安全运算符
$result = $object !== null ? $object->method() : null;

// 使用空安全运算符
$result = $object?->method();
```

使用空安全运算符，你可以简化代码并消除对显式空值检查的需求。

### 3.5.2. 实际用例

当你想访问对象的属性或方法，但不想担心 null 值时，空安全运算符特别有用。空安全运算符的一些常见用例包括：

- **API 响应**：处理 API 响应时，如果请求的数据不可用，对象或属性可能为 null。空安全运算符使优雅处理此类情况变得更容易。

- **数据库查询**：查询数据库时，若无数据匹配条件，查询结果可能为 null。空安全运算符简化了这些情况的处理。

- **对象组合**：在面向对象编程中，当对象被组合且一个对象依赖于另一个对象的方法或属性时，空安全运算符确保对依赖对象的调用在其为 null 时不会触发错误。

### 3.5.3. 示例：空安全运算符的实际应用

以下示例演示了在处理潜在 null 对象时，空安全运算符如何简化代码：

```php
class User {
    public function getName(): string {
        return "John Doe";
    }
}

$currentUser = null; // 或 User 的实例

// 不使用空安全运算符
if ($currentUser !== null && $currentUser instanceof User) {
    $name = $currentUser->getName();
} else {
    $name = "Guest";
}

// 使用空安全运算符
$name = $currentUser?->getName() ?? "Guest";
```

在此示例中，我们想获取当前用户的名称，它可以是 `User` 类的实例，也可以是 null。空安全运算符简化了代码，并在 `$currentUser` 为 null 时提供默认值。

### 3.5.4. 链式调用空安全运算符

空安全运算符还可链式调用，以安全地访问嵌套属性或方法：

```php
$object = null; // 或一个对象实例

// 不使用空安全运算符
```

### 3.5.5. 空安全运算符的优势

空安全运算符在 PHP 开发中提供了多项优势：

- **代码简化**：它减少了显式空值检查和条件语句的需求，从而产生更整洁、更简洁的代码。

- **错误预防**：该运算符有助于防止“Call to a member function on null”（在 null 上调用成员函数）及类似错误，提高了代码可靠性。

- **可读性提升**：使用空安全运算符的代码通常更具可读性且更易于理解，因为它明确传达了处理潜在空值的意图。

- **减少样板代码**：它消除了空值检查所需的样板代码，使您的代码库更高效、更易维护。

总之，PHP 8 引入的空安全运算符（`?->`）是该语言的一项宝贵补充，它简化了对潜在空对象的处理。它简化了代码，降低了出错风险，并增强了代码可读性，使其成为各种 PHP 开发场景中的实用工具，特别是在处理 API 响应、数据库查询和对象组合时。

# 第 4 章：错误处理与异常改进

## 4.1. 理解并利用构造函数属性提升

PHP 8 引入了一项称为**构造函数属性提升**的特性，它简化了在类的构造函数中声明和初始化对象属性的过程。此特性增强了代码可读性，并减少了具有许多属性的类的冗长度。在本节中，我们将探讨构造函数属性提升的概念并演示其用法。

### 4.1.1. 属性初始化的问题

在 PHP 中，当你创建一个具有多个属性的类时，通常需要在类中声明这些属性，在构造函数中初始化它们，并逐个为它们赋值。这可能导致冗长且重复的代码，尤其是在处理拥有许多属性的类时。

请看下面不使用构造函数属性提升的示例：

```php
class User {
    private string $username;
    private string $email;
    private int $age;

    public function __construct(string $username, string $email, int $age) {
        $this->username = $username;
        $this->email = $email;
        $this->age = $age;
    }
}
```

对于拥有大量属性的类，这种方法会变得笨重。构造函数属性提升简化了这一过程。

### 4.1.2. 使用构造函数属性提升

使用构造函数属性提升，你可以直接在构造函数的参数列表中声明并初始化属性。以下是使用构造函数属性提升后的同一个 `User` 类：

```php
class User {
    public function __construct(
        private string $username,
        private string $email,
        private int $age
    ) {}
}
```

在本例中，我们直接在构造函数的参数列表中声明并初始化了属性 `$username`、`$email` 和 `$age`。这种紧凑的语法不仅减少了代码量，还使其更具可读性和可维护性。

### 4.1.3. 构造函数属性提升的优势

构造函数属性提升提供了多项优势：

- **减少样板代码**：它消除了单独声明属性并在构造函数中初始化它们的需要，减少了代码冗余。

- **提高代码可读性**：构造函数属性提升使构造函数参数与属性之间的关系变得显式且更易于理解。

- **简化对象创建**：创建具有许多属性的类的实例时，你可以直接将值传递给构造函数，使对象创建更加简洁。

- **降低出错风险**：由于属性在构造函数内初始化，忘记初始化属性或错误初始化的可能性更小。

### 4.1.4. 使用默认值

你也可以为提升的属性分配默认值：

```php
class User {
    public function __construct(
        private string $username = 'Guest',
        private string $email = '',
        private int $age = 0
    ) {}
}
```

在本例中，如果创建 `User` 对象时未提供 `$username`、`$email` 或 `$age` 的值，将使用默认值。

### 4.1.5. 类型声明与可见性

你可以像传统属性声明一样，对提升的属性应用类型声明和可见性修饰符（`public`、`private`、`protected`）。

### 4.1.6. 兼容性

构造函数属性提升在 PHP 8 及更高版本中可用。如果你需要维护与旧版本 PHP 的兼容性，则需使用传统的属性声明和初始化方法。

### 4.1.7. 何时使用构造函数属性提升

构造函数属性提升在以下情况下特别有用：

- 你拥有具有许多属性的类。

- 你希望提高代码可读性和可维护性。

- 你希望减少属性声明和初始化的冗长度。

总之，构造函数属性提升是 PHP 8 引入的一项宝贵特性，它简化了在构造函数中声明和初始化对象属性的过程。它减少了代码冗余，增强了代码可读性，并改善了整体开发体验，使其成为创建更简洁、更易维护类的便捷工具。

## 4.2. Throw 表达式：新的错误处理机制

PHP 8 引入了 **Throw 表达式**，这是一种抛出异常和处理错误的新的、更简洁的方式。此特性简化了错误处理，并允许你在单行代码中抛出异常，减少了对冗长 `try-catch` 块的需求。在本节中，我们将探讨 Throw 表达式的概念并演示其用法。

### 4.2.1. 抛出异常的传统方式

在之前的 PHP 版本中，当你需要抛出异常时，通常使用 `try-catch` 块来处理错误。例如：

```php
try {
    // 可能抛出异常的代码
    if ($someCondition) {
        throw new MyException('An error occurred.');
    }
} catch (MyException $e) {
    // 处理异常
    echo 'Caught exception: ' . $e->getMessage();
}
```

这种方法要求你编写抛出和捕获代码，这可能导致冗长且杂乱的代码，尤其是对于简单的错误处理场景。

### 4.2.2. 引入 Throw 表达式
