
# 了解每种访问控制模型的细节

了解访问控制模型及其功能。状态机模型确保主体访问客体的所有实例都是安全的。信息流模型旨在防止未经授权、不安全或受限的信息流。非干扰模型防止一个主体的行为影响系统状态或另一个主体的行为。获取-授予模型规定了权限如何从一个主体传递给另一个主体，或从主体传递给客体。访问控制矩阵是一个主体和客体的表格，指示每个主体可以在每个客体上执行的动作或功能。贝尔-拉帕杜拉模型中的主体具有许可级别，仅允许其访问具有相应分类级别的客体。这强制执行了机密性。比巴模型阻止较低安全级别的主体写入较高安全级别的客体。克拉克-威尔逊是一种完整性模型，依靠审计来确保未授权主体无法访问客体，且授权用户正确访问客体。比巴和克拉克-威尔逊强制执行完整性。戈根-梅塞格尔和萨瑟兰关注完整性。格雷厄姆-德宁侧重于主体和客体的安全创建和删除。

# 了解认证和认可的定义

认证是对计算机系统的每个部分进行技术评估，以评估其与安全标准的一致性。认可是指定机构正式接受经过认证的配置的过程。

# 能够描述开放系统和封闭系统

开放系统是使用行业标准设计的，通常易于与其他开放系统集成。封闭系统通常是专有硬件和/或软件。其规范通常不公开，且通常较难与其他系统集成。

# 了解限制、边界和隔离

限制将进程限制在只能读取和写入特定内存位置。边界是进程在读取或写入时不能超过的内存限制。隔离是进程在通过内存边界进行限制时运行的模式。

# 能够从访问角度定义 `对象` 和 `主体`

主体是发出请求以访问资源的用户或进程。客体是用户或进程想要访问的资源。

## 评估和缓解安全漏洞

*计算机体系结构*是一门工程学科，关注计算系统在逻辑层面的设计与构建。许多大学级别的计算机工程和计算机科学专业发现，在一个学期内涵盖计算机体系结构的所有基本原则颇具挑战，因此这些内容通常被分为两门一学期的本科课程。计算机体系结构课程深入探讨`中央处理单元 (CPU)`组件、存储设备、设备通信及类似主题在比特层面的设计，为构成简单“0 或 1”决策的单个逻辑设备定义处理路径。大多数安全专业人员不需要这种深度的知识，这远超出了本书和 CISSP 考试的范围。然而，如果你将参与计算系统在此层面的设计安全工作，建议你对该领域进行更深入的研究。

最初对计算机体系结构的讨论乍看之下似乎与 CISSP 无关，但大多数安全架构和设计要素都建立在对计算机硬件的扎实理解和实现之上。

### 硬件

任何计算专业人员都熟悉硬件的概念。正如建筑行业一样，硬件是构成计算机的物理“东西”。术语*硬件*涵盖了计算机中你能实际伸手触摸到的任何有形部分，从键盘和显示器到其`CPU`、存储介质和内存芯片。请仔细注意，虽然存储设备（如硬盘或闪存）的物理部分可被视为硬件，但这些设备的内容——构成其中存储的软件和数据的 0 和 1 的集合——则不属于硬件。毕竟，你无法伸手进计算机内部抓出一把比特和字节！

#### 处理器

*中央处理单元 (CPU)*，通常称为*处理器或微处理器*，是计算机的神经中枢——它是管理所有主要操作并直接执行或协调复杂计算交响乐的芯片（或多处理器系统中的多个芯片），使计算机能够执行其预期任务。令人惊讶的是，尽管 CPU 让计算机能够执行复杂的任务，但它本身只能执行有限的计算和逻辑操作集。将用于设计软件的高级编程语言翻译成 CPU 能理解的简单汇编语言指令，是操作系统和编译器的责任。这种有限的功能范围是有意为之——它使 CPU 能够以极快的速度执行计算和逻辑操作。

##### 执行类型

随着计算机处理能力的提升，用户要求更高级的功能，以使这些系统能以更快的速度处理信息并同时管理多个功能。计算机工程师设计了多种方法来满足这些需求：

**多任务处理** 在计算中，*多任务处理*意味着同时处理两个或更多任务。过去，大多数系统并不真正支持多任务处理，因为它们依赖操作系统通过精心安排发送给 CPU 执行的命令序列来模拟多任务处理。当处理器以多吉赫兹的速度运行时，很难察觉它是在任务间切换，而不是同时处理两个任务。单核多任务系统能够在任何给定时间同时处理多个任务或进程。

**多核** 如今，大多数 CPU 都是多核的。这意味着过去单个的 CPU 或微处理器芯片，现在变成了一个包含两个、四个、八个，甚至潜在数十个独立执行核心的芯片，这些核心可以同时运行。

**多处理** 在*多处理*环境中，多处理器计算系统（即拥有多个 CPU 的系统）利用多个处理器的力量来完成多线程应用程序的执行。例如，数据库服务器可能运行在一个包含四个、六个或更多处理器的系统上。如果数据库应用程序同时接收多个独立查询，它可能会将每个查询发送给单独的处理器执行。

现代多 CPU 系统中最常见的两种多处理类型是：刚才描述的场景，即单台计算机包含多个地位平等、由单一操作系统控制的处理器，称为*对称多处理 (SMP)*。在 SMP 中，处理器不仅共享一个公共操作系统，还共享公共数据总线和内存资源。在这种安排中，系统可能使用大量处理器。幸运的是，这种计算能力足以驱动大多数系统。

### 处理类型

许多高安全系统控制分配给不同安全级别的信息处理，例如美国政府分配给与国防相关的信息的非密、敏感、机密、秘密和绝密等分类级别。计算机的设计必须使其不会——理想情况下是不能——无意中向未授权接收者泄露信息。

计算机架构师和安全策略管理员已在处理器级别通过两种不同方式解决此问题。一种是通过策略机制，另一种是通过硬件解决方案。以下列表探讨了这两种选项：

#### 单态系统

**单态系统**需要使用策略机制来管理不同级别的信息。在这种安排中，安全管理员批准处理器和系统一次仅处理一个安全级别。例如，系统可能被标记为仅处理秘密信息。该系统的所有用户必须经过批准才能处理秘密级别的信息。这将保护系统上处理的信息的负担从硬件和操作系统转移到了控制系统访问的管理员身上。

#### 多态系统

**多态系统**能够实现更高级别的安全。这些系统通过使用专用安全机制（如下一节“保护机制”中所述）获得认证，可同时处理多个安全级别。这些机制旨在防止信息在安全级别之间跨越。一位用户可能正在使用多态系统处理秘密信息，而另一位用户同时在处理绝密信息。技术机制防止信息在两个用户之间跨越，从而防止其在安全级别之间跨越。

在实际应用中，多态系统相对少见，因为实施必要技术机制的成本较高。然而，当您处理非常昂贵的资源（如大规模并行系统）时，这种费用有时是合理的；获取多个系统的成本远超在单个此类系统上实施启用多态操作所需的额外安全控制的成本。

#### 保护机制

如果计算机未运行，它只是一块惰性的塑料、硅和金属，什么也不做。当计算机运行时，它会操作一个运行时环境，该环境代表操作系统以及可能处于活动状态的任何应用程序的组合。运行时，计算机还具备访问文件和其他数据的能力，前提是用户的安全权限允许。在该运行时环境中，必须集成安全信息和控制，以保护操作系统本身的完整性，管理允许哪些用户访问特定数据项，授权或拒绝针对这些数据的操作请求，等等。运行中的计算机在运行时实现和处理安全的方式，可以广泛地描述为一组保护机制的集合。以下将描述各种保护机制，如保护环、操作状态和安全模式。

#### 保护环

环保护方案由来已久但依然有效。它可以追溯到 Multics 操作系统的研究工作。这个实验性操作系统于 1963 年至 1969 年间由贝尔实验室、麻省理工学院和通用电气公司合作设计和构建。它在霍尼韦尔的实现中得到了商业应用。Multics 在计算界留下了两大不朽遗产。首先，它激发了一个更简单、结构更清晰的操作系统 Unix（谐音 *multics*）的诞生；其次，它将保护环的概念引入了操作系统设计。

从安全角度来看，**保护环** 将操作系统中的代码和组件（以及在操作系统控制下运行的应用程序、实用程序或其他代码）组织成同心环，如 图 9.1 所示。越靠近圆心，占据特定环的代码所关联的特权级别越高。虽然最初的 Multics 实现允许多达七个环（编号 0 到 6），但大多数现代操作系统使用四环模型（编号 0 到 3）。

作为最内层的环，环 0 拥有最高特权，基本上可以访问任何资源、文件或内存位置。操作系统中始终驻留在内存中的部分（以便随时按需运行）称为 **内核**。它占据环 0，并可以抢占在任何其他环运行的代码。操作系统的其余部分——随着各种任务被请求、操作被执行、进程被切换等而来去不定——占据环 1。环 2 也具有一定特权，I/O 驱动程序和系统实用程序驻留于此；它们能够访问外围设备、特殊文件等，而应用程序和其他程序无法直接访问这些资源。那些应用程序和程序占据最外层的环，即环 3。

**图 9.1** 在常用的四环模型中，保护环将操作系统隔离为环 0 到 2 中的内核、组件和驱动程序，而应用程序和程序在环 3 运行。

环模型的本质在于优先级、特权和内存分段。任何想要执行的进程都必须排队（待处理进程队列）。关联环号最低的进程总是比关联较高编号环的进程先运行。较低编号环中的进程可以访问更多资源，并比较高编号环中的进程更直接地与操作系统交互。运行在较高编号环中的进程通常必须向较低编号环中的处理程序或驱动程序请求所需服务；这有时称为 **中介访问模型**。在其最严格的实现中，每个环都有其关联的内存段。因此，来自较高编号环的进程对较低编号环中地址的任何请求，都必须调用与该地址关联的环中的辅助进程。在实践中，许多现代操作系统仅将内存分为两个段：一个用于系统级访问（环 0 到 2），通常称为 **内核模式** 或 **特权模式**；另一个用于用户级程序和应用程序（环 3），通常称为 **用户模式**。
