
为避免不必要的数据传输，`PR-SCTP` 通过降低每个数据的重复率，根据数据优先级改变传输。在发送数据前，`TC-SCTP` 对每个数据的传输时间进行同样的目的性检查。因此，上述有线网络协议需要一种新协议来使用 `IEEE 802.15.4` `WSN` 算法。

该协议用于限制 `TC-SCTP` 持续时间，并决定接收端缓冲区上的数据是否可播放 [[32]](#chapter14.xhtml#ref14_32)。该建议协议仅使用单个缓冲区，不需要唯一的时间限制。发射时间根据发射端接收部分允许播放所有数据的最大时间进行评估分配。

- `Tp` 为接收端数据播放时间
- `Tos` 为偏移延迟
- `Tr` 为从顶层获取数据的时间

`Tos` 定义为从顶层在接收端接收数据的最大时间量。因此：

$$T_p = T_{os} + T_r$$

为确保源和目标之间可靠的数据传输，避免不必要的传输，以便缓冲区控制传输前传输所有数据的传输时间 `T[x]`。如果传输时间较长，数据将成功传输到接收端。否则，发射端将不继续传输并删除缓冲区数据。

$$T_x = T_p - T$$

计算传输时间后，检查数据类型是 `I` 帧、`P` 帧还是 `B` 帧，以满足传输时间 `T[X]` 的条件。

`Th1`、`Th2` 和 `Th3` 是使用重传超时 (`RT`) 确定的阈值。

$$Th_1 = (RT \times 2) + a[1]$$

$$Th_2 = (RT \times 1) + a[2]$$

$$Th_3 = (RT \times 2) + a[3]$$

其中 `a[1]`、`a[2]` 和 `a[3]` 为常数。

- 若数据为 `I` 帧，则 `T[x]` 大于 `Th1`，随后数据将传输到流 1。
- 若数据为 `P` 帧，则 `T[x]` 大于 `Th2`，随后数据将传输到流 2。
- 若数据为 `B` 帧，则 `T[x]` 大于 `Th3`，随后数据将传输到流 3。
- 若 `T[x]` 小于 `Th3`，则数据被丢弃而不传输。

### 14.4 协议比较

在本部分中，根据消息传递的可靠性、能量效率和干扰控制，对某些现有的传输协议进行了比较。现有协议无法满足所有需求。许多协议不关注可靠性方法，仅关注拥塞控制。但目前有三种协议同时提供传输层、可靠性和拥塞控制能力 [[33]](#chapter14.xhtml#ref14_33)–[[36]](#chapter14.xhtml#ref14_36)。几乎所有协议都使用隐式拥塞通知方法、队列长度过程进行拥塞检测阶段，以及精确速率调整方法。子节点可以通过改变速率来降低传输速率，以防止更多父节点拥塞 [[11]](#chapter14.xhtml#ref14_11)。精确速率调整是一种已知技术，其中节点在指定时间调度数据包传输，以满足预期速率进行特殊速率调整 [[11]](#chapter14.xhtml#ref14_11)。

传输层最关键的功能是可靠性，它确保数据从源正确传递到目标或汇聚节点。由于大多数建议协议基于应用，因此存在许多可靠性策略。此外，许多协议采用否定确认 (`NACK`) 和超时来检测丢失，以及通知和数据包重传来恢复丢失。未来应开发与广泛应用程序互操作的协议。提供可靠性机制的现有传输协议总结见表 14.1。提供干扰控制的现有传输协议总结见表 14.2。

### 14.5 结论

本章研究了各种传输协议。同时，还针对实时应用对现有传输协议进行了对比。建议的传输协议旨在提供一个可靠的数据传输系统以及一个有效的拥塞控制系统。拥塞控制和可靠性问题无疑将有助于降低丢包率，从而使 WSN 上的整体系统更加节能。所提出的协议能够同时满足 WSN 上多媒体通信和 WSN 特性的要求。即将到来的 WSN 传输协议需要重点考虑的主要问题包括高带宽需求、能源效率、最小实时延迟、处理能力和有限内存。

### 14.6 未来展望

建议的传输协议未来可用于网络模拟器 2（Network Simulator 2）以计算协议性能。MPEG-4 视频编码器可被用于通过 IEEE 802.15.4 网络发送数据。跨层优化算法可能是提高所提议传输协议效率的一个额外方面。跨层优化还有助于网络可信度和卓越性的提升。网络的不同层可以协作共享信息，这有助于保持低能耗。
