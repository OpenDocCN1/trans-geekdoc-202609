
# 工业网络中的计算和控制设备安全

工业网络中的计算和控制设备需要与其 IT 对应设备相同类型的本地安全。对工业控制设备（或 ICS 控制室）的物理访问可为攻击者提供破坏或损坏流程、系统或设备的手段。获得对控制室的物理访问也使攻击者处于更有利的位置，以获取对系统或其设备的逻辑控制。如果达到这种渗透级别，攻击者就有机会控制物理过程。如果他们获得对服务器或 ICS 主系统的访问权限，他们可能会控制整个 OT 系统。

OT 系统相对于企业网络的一个优势是，其计算和控制设备通常运行在专有操作系统和网络基础设施上，熟悉这些系统的人较少。因此，拥有这些软件和网络类型足够知识的潜在攻击者比企业环境中要少。这被称为`通过隐匿实现安全`。

然而，这也创造了一个环境，即负责这些系统的个人必须具备组件和软件的高级知识，以保持系统正确运行。虽然企业和公开分发的操作系统和应用程序具有相对简单的安装、设置和维护，但 OT 版本的管理可能要复杂得多。ICS 软件变更必须谨慎进行。

虽然 ICS 行业已经生产了具有原生安全工具的设备以及可添加到现有 OT 网络的安全设备超过 10 年，但仍有许多 OT 网络和设备在几乎没有或完全没有安全能力的情况下运行。在许多情况下，ICS 系统包含专门为执行特定任务而设计的组件，或者是在网络安全成为工业控制环境中的一个问题之前开发的组件。

由于 `PLC` 和 `RTU` 拥有的自我保护资源极少，因此通过加固其周围的边界来为这些设备提供保护变得非常重要。与企业网络设备一样，该边界的主要重点是通过执行以下操作来防止对 OT 资产的逻辑访问：

*   将 IT 和 OT 计算设备物理固定在基础设施上（扩展坞、锁定线缆、链条、可上锁的机柜）。
*   要求强访问控制（复杂密码）。
*   采用强身份验证方法（智能卡、生物识别扫描仪等）。
*   在组织的 ICS 部分的所有计算和控制设备上禁用或卸载可移动媒体驱动器和端口（CD/DVD 驱动器、USB/FireWire 端口、SD 卡插槽）。ICS 安全策略应禁止在 OT 中（或连接到 OT 的）任何计算/控制设备上使用任何未经授权的可移动媒体，以防止引入恶意软件或无意中丢失或窃取数据。
*   控制打印输出（处置和销毁策略、碎纸、焚烧）。
*   控制对备份数据和介质的访问（使用异地存储、上锁的机柜、防火保险柜）。如果攻击者能够访问 ICS 备份介质，他们可能会利用其内容。这些利用范围从从认证文件中提取密码到恢复可用于发起不同类型网络攻击的数据。
*   禁用电源按钮或防止其被未经授权的访问/使用。

# 电表

任何 `utility meter`（公用事业电表）的主要功能是测量客户对电力、水、燃气等的使用量。除了测量电力外，电力 `smart meter`（智能电表）还需要识别并与 HAN 组件通信、存储客户和用量数据、显示消费模式，并与公用事业的 WAN 通信。图 4.20 显示了典型智能电表的功能框图。

![FIGURE 4.20 Anatomy of a smart meter](img/c04f020.png)

**图 4.20** 智能电表剖析

使智能电表变得 `smart`（智能）的是嵌入式 `microcontroller`（微控制器）或 `mC`（一种专用微处理器）的存在。该设备按固定时间间隔采集流经电表“主接点”（触点）的电流量数据，根据其编程分析数据，并将数据和结果存储在 `Flash random access memory (RAM)`（闪存随机存取存储器）区域中。它还处理从公用事业接收的指令，并将来自 `home area network (HAN)`（家庭区域网络）的数据转发给公用事业。

电流测量由电流传感器执行，这些传感器检测流经电表的每根导体中的电流水平。传感器将该模拟信息馈送至 `analog-to-digital converter (ADC)`（模数转换器）电路，该电路生成微控制器可理解的每次测量的数字表示。图 4.21 说明了典型 A/D 转换器的操作。16 位和 24 位 A/D 转换器版本常用于数字电力仪表（位数越高——也称为 `resolution`（分辨率）——产生的数字表示越精确）。

![FIGURE 4.21 Typical A/D converter operation](img/c04f021.png)

**图 4.21** 典型 A/D 转换器操作

微控制器通常还与客户显示设备（如 `liquid crystal display (LCD)`（液晶显示器））连接，可显示客户用量数据或消息。

智能电表的另一个关键组件是其 `Input/Output (I/O) controller`（输入/输出控制器）。该单元负责为其他系统组件与外部世界之间提供物理连接兼容性。具体而言，它将在系统不同数字设备之间移动的并行数据转换为更适合长距离传输的串行比特流。它还接收来自外部的串行数据，并将其转换为与数字设备（如微控制器和 RAM 模块）兼容的并行数据。

I/O 控制器还为数据进出电表的移动提供硬件协议控制。如图所示，该 I/O 控制器提供了一个支持标准 USB 端口以及 `Power Line Carrier (PLC)`（电力线载波）连接设备的串行通信端口。

在无线通信的情况下，数据通过发射器/接收器单元在外部世界与 I/O 控制器之间移动。根据特定电表的设计，发射器/接收器可设计为适用不同的通信解决方案，包括 RF 无线、电力线载波和 `General Packet Radio System (GPRS)`（通用分组无线业务）数据通信。

微控制器及其所有智能支持设备运行都需要电力。这些模块从电力主线获取电源，意味着电表会使用来自电网的一部分电力。对于单个电表而言，这种功耗几乎可以忽略不计。然而，当大量建筑物接入电网时，仅为了拥有智能系统就会消耗大量能源。

## 汇聚器

典型的公用事业电网汇聚数千个客户。面对如此庞大的装机量，让每个客户的智能电表直接与公用事业总部的服务器通信在经济和技术上都是不切实际的。取而代之的是使用称为 `data concentrators`（数据汇聚器）的设备将多个智能电表分组，并聚合其数据传输以传送给中心局的公用事业服务器。每个数据汇聚器创建一个称为 `neighborhood area network`（邻域网络）或 `NAN` 的结构，如图 4.22 所示。

## 安全问题

在 OT 网络环境中保护嵌入式设备有许多方法。然而，保护这些系统的一般流程如下：

1.  物理保护每个位置的本地传感器和执行器及其到网络的连接。
2.  保护每个位置的现场总线和局域控制网络介质。
3.  保护每个位置的 `PLC`、`RTU` 和 `IED`。在许多情况下，这些设备位于由围栏和锁门保护的无人值守现场站中。
4.  保护所有现场站点与控制中心之间的长距离通信链路。历史上，SCADA 协议往往不具备大量内置安全功能，因为它们主要是为最大化性能、可靠性、鲁棒性和功能性而设计的。
5.  保护控制中心的 SCADA 控制器、服务器和历史服务器。虽然这些设备通常部署在安全设施中，但应由高效的补丁管理（加固）策略进行管控。
6.  如前所述，保护组织 OT 网络与 IT 网络之间的任何互联。如果这两个网络必须连接，将连接点的数量限制为单一通道。使用防火墙、路由器和 DMZ 来控制两个网络之间的流量流动。

对于公用事业而言，最令人担忧的安全风险之一是位于公用事业与客户分界点处的 `smart meter`（智能电表）。在大型配电网络中，可能有成千上万个此类设备安装在广阔的地理区域内。每个设备都代表了公用事业消费者数据采集网络的一个潜在接入点。每个电表通常也安装在公众可接触到的开放位置。

由于这些网络代表的目标价值足够高，极具吸引力，攻击者可以通过在智能电表附近非法放置兼容的接收设备，捕获其信号，然后解密其内容，从而利用其射频 AMI 传输。

一旦攻击者获得电表通信信道的访问权限，他们可能会利用完整的客户数据采集网络。通过访问该网络，攻击者只需向网络发送一个小脚本，就可能禁用本地公用事业客户的服务。他们还可能利用此信道恶意地以正面或负面方式修改客户数据。

在控制中心或企业办公室设施中，物理安全通常呈现出更多 IT 安全的性质。这些环境中的主要关注点涉及限制对 OT 环境中任何信息资产的物理访问。

*   未经授权物理访问敏感位置
*   未经授权物理访问服务器、SCADA 主设备和历史服务器及其上的数据
*   未经授权物理访问用户计算机、网络设备和数据

与 IT 网络环境类似，ICS 主站、服务器和历史服务器应位于安全区域，用于这些位置身份验证的设备和机制也应受到保护。同样，OT 网络上的任何企业网络连接设备（端点、网络交换机、网关、路由器和介质）应位于安全区域，最好放在只有授权人员才能访问的区域。

正如您所见，SCADA 系统可以部署在工业处理设施的本地控制网络中，也可以跨越大型地理区域部署在分布式过程中（如电网）。这些系统容易受到攻击，攻击方式包括中断其网络通信或伪造其现场设备产生的数据。

如果通信网络中断，控制器将无法确定过程状态，也无法向现场控制器提供正确的控制信息。这可能会产生严重后果，导致过程失控。

同样，如果传感器和现场控制器产生的数据被伪造，控制器将无法采取控制过程所需的纠正措施。过程控制器可能会采取错误或有害的行动。此外，即使是人工操作员，如果无法确定过程的实际状况，也可能无法采取适当的纠正措施。

### 默认配置管理

嵌入式设备的另一个主要隐患是安装后保留设备的默认配置设置。配置不当的设备或系统会为攻击者提供容易得手的目标，形式为轻松获取提升的权限或已知的默认设置。

事实上，默认设置代表最常见的配置漏洞类型。这些漏洞包括：

*   允许默认账户和密码（如默认路由器密码）保持激活状态。
*   使用默认配置设置（如启用 TFTP）。
*   允许使用不充分的软件或硬件配置设置（如启用“用户可修改设置”选项）。
*   使用为易用性而非安全性设计的配置选项（如启用 AutoRun 功能）。
*   错误配置权限设置，而非使用最小权限或需知原则设置。

为消除这些漏洞，应创建并实施*配置设置管理*（`CSM`）策略及其相关流程，以识别不良和不安全的配置设置。这包括为新增网络设备的配置设置开发质量保证检查流程，以及制定防止未授权用户更改配置的策略。

在美国，*网络安全和基础设施安全局*（`CISA`）提供 `CSM` 工具，作为其*持续诊断与缓解*（`CDM`）计划的一部分。该计划为安全从业者提供网络安全工具、集成服务和仪表板，帮助他们改善网络安全态势。

# 网络加固

*网络加固*是一项主动的、持续的网络管理过程，包括面向网络计算和控制设备的操作系统和应用程序加固。此部分加固过程涉及收紧并正确配置网络服务、协议和访问控制列表。

然而，除了加固网络中的软件外，还必须详细记录并评估其当前配置，以便制定可行的计划进一步提高网络安全性。这包括评估网络的通信介质和连接设备（交换机、路由器、硬件防火墙）。此加固领域涉及的典型步骤包括：

*   根据组织的安全策略保护系统服务器。如果可能，将其放置在受监控的、集中的服务器机房内，并配备双锁门。
*   检查是否存在规格不符合当前安全目标的网络设备，因此构成网络的易攻击访问点。
*   验证网络配置能否执行其通信功能，同时仍满足组织安全策略要求的安全级别。确保交换机、防火墙和路由器等设备不再处于默认配置设置。
*   评估网络安全计划，确保关键设备（如生产服务器）安装在正确的网络段、安全区域或子网中。
*   在网络连接设备上建立并配置 `ACL`，以根据组织安全策略的要求限制或阻止对资产的访问。
*   `SSH`/`HTTPS` 访问的身份验证方法。
*   所有设备的备份配置。
*   使网络设备保持所有可用和当前补丁的最新状态。

## OT/IT 网络安全

如前所述，IT 功能已成为 OT 网络不可或缺的一部分，提供关键接口和交互。当然，这也使得原本依靠默默无闻而保持安全的 OT 网络暴露于与 IT 网络和互联网相关的漏洞中。然而，随着两者相互依赖程度加深，连接这两个网络的趋势持续升级。

不幸的是，大多数 OT 网络构建在大型扁平网络拓扑上，如第 3 章所述。回顾一下，扁平拓扑不实施分段，无法为功能和安全要求不同的网络区域创建安全区域。这使得网络攻击或干扰在初始渗透发生后能在网络中快速传播。

扁平拓扑还使 OT 网络易受网络拓扑图上未显示但对网络化的过程控制系统构成重大威胁的威胁。这些威胁包括但不限于：

*   来自 IT 网络的访问
*   通过 IT 网络从互联网进行的访问
*   具有极少或无内置安全功能的 `PLC`、`RTU` 和 `DCS` 设备
*   因网络未分段导致的设备缺乏隔离

扁平网络的其他重大威胁涉及可能进入工厂并与 OT 网络通信的无线设备，以及将基于 `USB` 的设备引入连接 ICS 的主机的能力。在 OT 环境中，无线网络技术的使用也必须受到严格控制，因为它们使潜在攻击者无需获得物理访问权限，仅需接近无线设备或网络即可控制过程设备和网络结构。

另一方面，OT 网络中任何位置存在 `USB` 接口都为各类恶意软件进入系统敞开了大门。一旦进入 ICS，恶意软件可通过未分段或分段不善的 OT 网络迅速传播。

如果企业网络提供了通往互联网连接的路径，必然会引发关于利用该连接进行远程 ICS 管理和维护的讨论。从成本角度看，从单一来源远程提供这些服务，比在组织可能拥有的每个地点都配备技术高超且薪酬优厚的网络管理员和技术人员要划算得多。

## OT 网络远程访问安全

正如纯 IT 网络一样，在 OT 网络中开放远程访问通道会为未经授权的访问、恶意软件或不当流量进入网络及其设备提供窗口。不同之处在于，OT 网络通常拥有较少的安全工具来防止干扰或攻击，或限制其影响范围。

因此，对于涉及 ICS 的任何类型的远程访问功能，强烈建议使用加密协议、强身份验证机制（基于令牌的、多因素认证方案）和 VPN。被授予 OT 网络远程访问权限的任何个人，都应被要求在企业网络层面和控制 OT 网络访问的网络防火墙层面进行双重身份验证。

当所有这些威胁汇聚在一起时，ICS 突然显得非常容易受到攻击，即使是最小的网络干扰也能迅速蔓延至整个 OT 网络，甚至波及远程位置的网段和设备。

为了应对工业控制行业这一日益增长的趋势，NIST SP 800-82 r2《工业控制系统 (ICS) 安全指南》在企业网络与 OT 网络融合时，针对网络整体设计提出了三项实际考量：

*   **网络分段与隔离**：逻辑和物理网络分离
*   **边界防护**：安全分层、权限控制和白名单机制
*   **防火墙的使用**：流量过滤

# 服务器安全

服务器需要特殊的安全考量和网络部署位置。正如前面的列表所示，组织网络中可能运行着多台不同的服务器，为用户提供各种服务。在大多数情况下，这涉及向多个用户提供至少一项关键服务。因此，组织的用户依赖这些服务器来开展工作。

正如本章前面提到的，网络中的某些服务器（如数据库服务器）可能肩负存储大量数据的任务。其中部分或全部数据可能是关键或机密信息，例如包含医疗、财务或人事记录在内的机密用户信息。它们也可能用于处理和存储专有的组织信息，如商业机密、专利、发明或生产信息。运行操作系统和应用程序的网络服务器必须通过补丁和更新持续维护，以保持其安全性。

基于这些原因，网络服务器代表了攻击者最感兴趣的目标之一。虽然攻击者的部分工作是绕过网络中的所有防护设备，但其行动的获利部分在于访问服务器上存储的数据。因此，服务器在网络安全架构中需要特殊的考量和部署位置。

*   对服务器共享资源的访问应仅限于既有需求又拥有适当授权的用户。应注意确保未经授权的员工无法访问机密资料。
*   某些类型服务器的网络访问通常应由一个或多个防火墙保护，以限制通往服务器的流量。
*   使用子网或路由器为不同类型的服务器创建安全的网络段或区域。例如，特定部门（如会计部）可受保护于其自身的安全子网内，并使用其自身的部门服务器资源。
*   由于服务器常用于用户身份验证，作为预防措施，服务器的密码应进行哈希处理。
*   定期审核关键服务器资源，以在潜在问题升级为实际问题之前将其识别出来。

与独立主机安全一样，在确保系统物理访问安全后，服务器安全的下一层级是保护其操作系统和应用软件。这涉及安全地安装、配置和维护服务器操作系统及选定用于服务器的软件包。

最重要的服务器软件组件是操作系统。保护操作系统涉及五个基本步骤。

1.  使用制造商的安装指南安装服务器操作系统。
2.  对新安装的系统打补丁并更新。操作系统开发商无法知晓特定组织服务器的全部安全需求。此外，每天都会出现新的安全威胁，因此软件创建时与安装时之间存在安全缺口。在投入运行前对新安装应用补丁和更新，应能修复任何已知的当前漏洞。
3.  配置并加固新操作系统以实施组织的安全策略。配置和加固操作系统涉及的关键步骤包括：
    *   移除或停止不必要的服务、应用程序和协议。
    *   配置管理员和用户身份验证系统。
    *   按需配置资源控制。
4.  安装并配置解决组织安全策略所需的任何额外第三方安全控制。此步骤包括安装和配置网络防护系统，包含：
    *   安装和配置反恶意软件产品。
    *   安装和配置 EDR 产品。
    *   安装基于主机（服务器）的 IDPS 软件。
    *   安装和配置基于主机（服务器）的防火墙。
    *   安装或配置磁盘加密软件，以防止获得服务器物理访问权限的攻击者窃取存储数据。
5.  测试新安装的安全性，确保其解决了组织的所有安全问题。此步骤涉及使用漏洞扫描和渗透检测工具来测试服务器的安全能力。在服务器的整个生命周期内，此步骤应每年执行一次，以确保其安全能力保持可接受水平。
