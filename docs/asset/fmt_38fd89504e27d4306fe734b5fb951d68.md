
`面部扫描`使用面部的几何图案进行检测和识别。Facebook 多年来一直使用面部识别软件来提供标签建议。例如，如果你的照片和名字存在于 Facebook 上（例如在你的个人资料图片中），它可以利用这些信息来识别你。它扫描新发布的照片并提供标签建议（照片中人物的姓名）。每当有人在照片中标记你时，它都会为 Facebook 正确识别你下次发布的照片提供更多信息。Facebook 最近开始允许用户结合另一种认证方法使用面部识别来解锁账户。赌场用它来识别作弊者。执法机构一直在边境和机场使用它来抓捕罪犯。面部扫描也用于在访问安全空间（如保险库）之前识别和认证人员。

#### 视网膜扫描

`视网膜扫描`关注眼球后部血管的模式。它们是生物识别认证中最准确的形式，可以区分同卵双胞胎。然而，一些隐私倡导者反对其使用，因为它们可能揭示医疗状况，如高血压和怀孕。较早的视网膜扫描会向用户的眼睛吹一口气，但较新的扫描通常使用红外光。此外，视网膜扫描仪通常要求用户距离扫描仪近至三英寸。

#### 虹膜扫描

聚焦于瞳孔周围的有色区域，`虹膜扫描`是生物识别认证中第二准确的形式。与视网膜一样，虹膜在一个人的一生中相对保持不变（除非眼睛受损或患病）。虹膜扫描通常被普通用户认为比视网膜扫描更可接受，因为扫描可以从远处进行。扫描通常可以在 6 到 12 米外（约 20 到 40 英尺）完成。然而，一些扫描仪可能会被高质量的图像代替人的眼睛而欺骗。此外，准确性可能会受到光线变化以及某些眼镜和隐形眼镜使用的影响。

#### 掌纹扫描

`掌纹扫描仪`扫描手掌以进行识别。它们使用近红外光测量手掌中的静脉模式，这些模式与指纹一样独特。个人只需在注册过程中将手掌放在扫描仪上几秒钟。稍后，他们再次将手放在扫描仪上进行识别。例如，研究生管理入学委员会（GMAC）使用掌静脉阅读器来防止代考，并确保休息后重新进入考场的是同一个人。

#### 手部几何结构

`手部几何结构`识别手的物理尺寸。这包括手掌和手指的宽度和长度。它捕获手的轮廓，但不捕获指纹或静脉模式的细节。手部几何结构很少单独使用，因为很难仅使用此方法唯一地识别个人。

#### 心率/脉搏模式

测量用户的脉搏或心跳可确保真人提供生物识别因素。它通常作为辅助生物识别手段来支持另一种类型的认证。一些研究人员推测个体之间的心跳是独特的，并声称心电图可用于认证。然而，可靠的方法尚未被创建或完全测试。

#### 语音模式识别

这种类型的生物识别认证依赖于一个人说话声音的特征，称为声纹。用户说出一个特定短语，由认证系统记录。为了认证，他们重复相同的短语并将其与原始短语进行比较。`语音模式`识别有时用作额外的认证机制，但很少单独使用。

#### 签名动力学

这识别主体书写一串字符的方式。`签名动力学`检查主体执行书写行为的方式以及书写样本中的特征。签名动力学的成功依赖于笔压、笔画模式、笔画长度以及笔从书写表面抬起的时间点。创建书写样本的速度通常不是一个重要因素。

#### 击键模式

`击键模式`（也称为`击键动力学`）通过分析`飞行时间`和`停留时间`来衡量主体使用键盘的方式。`飞行时间`是按键之间的时间间隔，`停留时间`是按键被按下的时长。使用击键模式成本低廉、无侵入性，且通常对用户透明（无论是使用还是注册）。不幸的是，击键模式容易出现巨大差异。用户行为的简单变化会极大地影响这种生物识别因素，例如单手操作、感到寒冷、站立而非坐着、更换键盘，或手部或手指受伤。

### 生物识别认证

生物识别技术的应用有望为地球上的每个人提供通用的唯一标识。遗憾的是，生物识别技术尚未兑现这一承诺。然而，专注于物理特征的技术对于认证非常有用。

#### 生物识别因子错误率

生物识别设备最重要的方面是其准确性。要将生物识别技术用于识别，生物识别设备必须能够检测信息中的细微差异，例如个人视网膜血管的变化或个人手掌静脉的差异。由于大多数人基本相似，生物识别方法经常导致假阴性和假阳性认证。生物识别设备通过检查它们产生的不同类型错误来评定性能。

##### 误拒率

误拒是指有效主体未被认证。例如，Dawn 已注册其指纹并曾用其进行自我认证。假设她今天使用指纹进行自我认证，但系统错误地拒绝了她的有效指纹。这有时称为假阴性认证。误拒次数与有效认证次数之比称为 `误拒率 (FRR)`。误拒有时称为 `I 类错误`。

##### 误纳率

误纳是指无效主体被认证。这也称为假阳性认证。例如，假设黑客 Joe 没有账户且未注册其指纹。然而，他使用指纹进行认证，系统却将其识别通过。这是一个假阳性或误纳。假阳性次数与有效认证次数之比称为 `误纳率 (FAR)`。误纳有时称为 `II 类错误`。

大多数生物识别设备都有灵敏度调节功能。当生物识别设备过于灵敏时，误拒（假阴性）更常见。当生物识别设备不够灵敏时，误纳（假阳性）更常见。

您可以使用 `交叉错误率 (CER)`（也称为等错误率 (ERR)）来比较生物识别设备的整体质量。图 13.1 显示了设备在不同灵敏度级别下设置时的 FRR 和 FAR 百分比。FRR 和 FAR 百分比相等的点即为 CER，CER 被用作比较不同生物识别设备准确性的标准评估值。CER 较低的设备比 CER 较高的设备更准确。

并非必须（且通常也不理想）将设备灵敏度设置在 CER 级别下运行。例如，组织可能使用人脸识别系统来允许或拒绝进入安全区域，因为他们希望确保未经授权的人员绝不会获得访问权限。在这种情况下，组织会将灵敏度设置得非常高，从而使误纳（假阳性）的可能性极小。这可能会导致更多的误拒（假阴性），但在这种场景下，误拒比误纳更可接受。

#### 生物识别注册

由于注册时间、吞吐率和接受度等因素，生物识别设备可能无效或不可接受。要使生物识别设备作为识别或认证机制工作，必须进行一个称为 `注册` 的过程。在注册期间，采集主体的生物识别因子并将其存储在设备的数据库中。这种生物识别因子的存储样本称为 `参考档案`（也称为 `参考模板`）。

扫描和存储生物识别因子所需的时间取决于所测量的物理或性能特征。用户不太愿意接受耗时较长的生物识别方法带来的不便。一般来说，超过 2 分钟的注册时间是不可接受的。如果您使用的生物识别特征会随时间变化，例如一个人的声调、胡须或签名模式，则必须定期重新注册，这会增加不便。

`吞吐率` 是系统扫描主体并批准或拒绝访问所需的时间。生物识别特征越复杂或详细，处理时间越长。主体通常接受约 6 秒或更快的吞吐率。

#### 多因子认证

`多因子认证` 是指使用两个或更多因子进行的任何认证。`双因子认证` 需要两个不同的因子来提供认证。例如，智能卡通常要求用户将卡插入读卡器并输入 PIN 码。智能卡属于“你拥有的东西”因子，而 PIN 码属于“你知道的东西”因子。一般来说，使用更多类型或因子会导致更安全的认证。

当同一因子的两种认证方法一起使用时，认证强度不会大于仅使用一种方法时的强度，因为能够窃取或获取其中一种的攻击也能获取另一种。例如，同时使用两个密码并不比使用单个密码更安全，因为密码破解尝试可能在一次成功攻击中同时发现两者。

相反，当采用两个或更多不同因子时，必须有两个或更多不同的攻击方法同时成功，才能收集所有相关的认证要素。例如，如果令牌、密码和生物识别因子都用于认证，那么物理窃取、密码破解和生物识别复制攻击必须同时全部成功，入侵者才能进入系统。

#### 设备认证

历史上，用户只能从公司拥有的系统（如台式电脑）登录网络。例如，在 Windows 域中，用户计算机加入域，并拥有类似于用户账户和密码的计算机账户和密码。如果计算机未加入域，或其凭据与域控制器不同步，用户无法从该计算机登录。

如今，越来越多的员工自带移动设备上班并将其连接到网络。一些组织拥抱这一趋势，但实施安全策略作为控制措施。这些设备不一定能加入域，但可以为这些设备实施设备识别和认证方法。

一种方法是设备指纹识别。用户可以向组织注册其设备，并将其与其用户账户关联。在注册期间，设备认证系统会采集设备的特征。这通常通过让用户使用该设备访问网页来完成。注册系统随后使用操作系统及版本、Web 浏览器、浏览器字体、浏览器插件、时区、数据存储、屏幕分辨率、Cookie 设置和 HTTP 标头等特征来识别设备。

当用户从该设备登录时，认证系统会检查用户账户是否有注册设备。然后，它会将用户设备的特征与已注册设备进行验证。即使其中一些特征会随时间变化，这已被证明是一种成功的设备认证方法。组织通常使用第三方工具（如 `SecureAuth Identity Provider (IdP)`）进行设备认证。

如前所述，许多 MDM 系统使用上下文感知身份验证方法来识别设备。它们通常与网络访问控制 (NAC) 系统配合工作，以检查设备的健康状况，并根据 NAC 系统中配置的要求授予或限制访问权限。

802.1x 是另一种用于设备身份验证的方法。它可用于某些路由器和交换机上的基于端口的身份验证。此外，它常与无线系统配合使用，强制用户在获得网络访问权限前使用账户登录。最近，一些 802.1x 解决方案已与 MDM 和/或 NAC 解决方案结合实施，以控制来自移动设备的访问。如果设备或用户无法通过 802.1x 系统进行身份验证，则不会被授予网络访问权限。

#### 服务身份验证

许多服务也需要身份验证，它们通常使用用户名和密码。服务账户就是为服务而非个人创建的用户账户。

例如，为监视 Microsoft Exchange Server 中电子邮件的第三方工具创建服务账户是一种常见做法。这些第三方工具通常需要权限来扫描所有邮箱，查找垃圾邮件、恶意软件、潜在的数据渗漏尝试等。管理员通常会创建一个 Microsoft 域账户，并赋予该账户执行任务所需的特权。

通常会设置账户属性，使密码永不过期。对于普通用户，你会将最长使用期限设置为 45 天左右。密码过期时，用户会收到必须更改密码的通知，并由用户自行更改。然而，服务无法响应此类消息，只会被锁定。

由于服务账户拥有高级别的特权，因此会为其配置强复杂密码，且比普通用户更频繁地更换。管理员需要手动更改这些密码。密码保持不变的时间越长，被泄露的可能性就越大。另一种选择是将账户配置为非交互式，这可以防止用户使用传统登录方法登录该账户。

服务可配置为使用基于证书的身份验证。证书颁发给运行服务的设备，并在服务访问资源时由服务呈现。基于 Web 的服务通常使用应用程序编程接口 (API) 方法在系统间交换信息。这些 API 方法因基于 Web 的服务而异。例如，Google 和 Facebook 提供 Web 开发人员使用的基于 Web 的服务，但它们的实现方式不同。

#### 实施身份管理

身份管理技术通常分为两类：集中式和分散式/分布式。

*   **集中式访问控制** 意味着系统内的所有授权验证均由单个实体执行。
*   **分散式访问控制**（也称为 **分布式访问控制**） 意味着系统中分布的各个实体执行授权验证。

集中式和分散式访问控制方法提供了任何集中式或分散式系统中所具有的相同优缺点。一个小团队或个人即可管理集中式访问控制。管理开销较低，因为所有更改都在单一位置进行，且单次更改即可影响整个系统。

分散式访问控制通常需要多个团队或多名个人。管理开销较高，因为更改必须在众多位置实施。随着访问控制点数量的增加，维护系统间的一致性变得更加困难。对任何单个访问控制点所做的更改都需要在每个访问点重复执行。

##### 单点登录

**单点登录 (SSO)** 是一种集中式访问控制技术，允许主体在系统上经过一次身份验证后，无需再次验证即可访问多个资源。例如，用户可以在网络上进行一次身份验证，然后访问整个网络中的资源，而无需再次接受身份验证提示。

SSO 对用户非常方便，但也能提高安全性。当用户必须记住多个用户名和密码时，他们往往会将其记录下来，最终削弱安全性。用户不太可能记录单个密码。SSO 还通过减少主体所需的账户数量来简化管理。

SSO 的主要缺点是一旦账户被攻破，攻击者将获得对所有授权资源的无限制访问权限。然而，大多数 SSO 系统都包含保护用户凭据的方法。以下几节将讨论几种常见的 SSO 机制。

###### LDAP 和集中式访问控制

在单个组织内，通常使用集中式访问控制系统。例如，**目录服务** 是一个集中式数据库，包含有关主体和对象的信息。许多目录服务基于轻量级目录访问协议 (LDAP)。例如，Microsoft Active Directory 域服务基于 LDAP。

你可以将 LDAP 目录视为网络服务和资产的电话簿。用户、客户端和进程可以搜索目录服务，以查找所需系统或资源所在的位置。主体在执行查询和查找活动前，必须向目录服务进行身份验证。即使经过身份验证，目录服务也仅根据主体分配的特权向其透露特定信息。

多域和信任关系常用于访问控制系统。安全域是共享通用安全策略的主体和对象的集合，各个域可以独立于其他域运行。域之间建立 **信任关系** 以创建安全桥接，允许一个域中的用户访问另一个域中的资源。信任关系可以是单向的，也可以是双向的。

###### LDAP 和 PKI

公钥基础设施 (PKI) 在将数字证书集成到传输中时会使用 LDAP。第 7 章将更深入地介绍 PKI，简而言之，PKI 是一组用于在证书生命周期内管理数字证书的技术。客户端经常需要查询证书颁发机构 (CA) 以获取证书信息，LDAP 是使用的协议之一。

LDAP 和集中式访问控制系统可用于支持单点登录功能。

###### Kerberos

票据身份验证是一种采用第三方实体来证明身份并提供身份验证的机制。最常见且最知名的票据系统是 **Kerberos**。

Kerberos 为用户提供单点登录解决方案，并保护登录凭据。当前版本 Kerberos 5 依赖对称密钥加密（也称为密钥加密），使用高级加密标准 (AES) 对称加密协议。Kerberos 通过端到端安全为身份验证流量提供机密性和完整性，并有助于防范窃听和重放攻击。它使用几个不同的重要元素：

**密钥分发中心** **密钥分发中心 (KDC)** 是提供身份验证服务的受信任第三方。Kerberos 使用对称密钥加密将客户端向服务器进行身份验证。所有客户端和服务器均向 KDC 注册，KDC 维护所有网络成员的密钥。

#### Kerberos 认证服务器

认证服务器承载 KDC 的功能：票据授予服务 (TGS) 和认证服务 (AS)。不过，也可以将票据授予服务托管在另一台服务器上。`authentication service`（认证服务）负责验证或拒绝票据的真实性和时效性。这台服务器通常被称为 KDC。

#### 票据授予票据

票据授予票据 (TGT) 证明某主体已通过 KDC 认证，并获授权请求票据以访问其他对象。TGT 经过加密，包含一个对称密钥、过期时间和用户的 IP 地址。主体在请求访问对象的票据时会出示 TGT。

#### 票据

票据是一条加密消息，证明某主体获授权访问某对象。它有时被称为服务票据 (ST)。主体请求票据以访问对象，如果它们已通过认证且获授权访问该对象，Kerberos 就会向它们颁发票据。Kerberos 票据具有特定的生命周期和使用参数。一旦票据过期，客户端必须请求续订或获取新票据，才能继续与任何服务器通信。

Kerberos 需要一个账户数据库，该数据库通常包含在目录服务中。它通过客户端、网络服务器和 KDC 之间的票据交换来证明身份并提供认证。这使得客户端能够向服务器请求资源，且客户端和服务器都能确信对方的身份。这些加密票据还确保登录凭据、会话密钥和认证消息永远不会以明文形式传输。

#### Kerberos 登录过程

Kerberos 登录过程如下：

1.  用户在客户端输入用户名和密码。
2.  客户端使用 AES 加密用户名，以便传输给 KDC。
3.  KDC 根据已知凭据数据库验证用户名。
4.  KDC 生成一个将由客户端和 Kerberos 服务器使用的对称密钥。它使用用户密码的哈希值对该密钥进行加密。KDC 还生成一个加密的带时间戳的 TGT。
5.  KDC 随后将加密的对称密钥和加密的带时间戳的 TGT 传输给客户端。
6.  客户端安装 TGT 以供使用，直到其过期。客户端还使用用户密码的哈希值解密该对称密钥。

#### 请求票据以访问对象

当客户端想要访问某个对象（如网络上托管的资源）时，必须通过 Kerberos 服务器请求票据。此过程涉及以下步骤：

1.  客户端将其 TGT 连同资源访问请求一起发送回 KDC。
2.  KDC 验证 TGT 是否有效，并检查其访问控制矩阵，以确认用户是否拥有足够的特权访问所请求的资源。
3.  KDC 生成一张服务票据并将其发送给客户端。
4.  客户端将票据发送给托管该资源的服务器或服务。
5.  托管资源的服务器或服务与 KDC 验证票据的有效性。
6.  一旦身份和授权得到验证，Kerberos 活动即告完成。服务器或服务主机随后与客户端打开一个会话，并开始通信或数据传输。

#### Kerberos 的局限性

Kerberos 是一种通用的认证机制，适用于本地局域网、远程访问以及客户端-服务器资源请求。然而，Kerberos 存在单点故障——即 KDC。如果 KDC 被攻破，网络上每个系统的密钥也将随之泄露。此外，如果 KDC 离线，将无法进行任何主体认证。

它对时间也有严格要求，默认配置要求所有系统的时间同步在彼此五分钟之内。如果系统未同步或时间被更改，先前颁发的 TGT 将不再有效，系统也将无法接收任何新票据。实际上，客户端将被拒绝访问任何受保护的网络资源。

#### 联合身份管理与 SSO

SSO 在内部网络中很常见，在互联网上也有使用。许多基于云的应用程序使用 SSO 解决方案，使用户更容易通过互联网访问资源。许多基于云的应用程序使用联合身份管理 (FIM)，这是一种形式的 SSO。

身份管理是对用户身份及其凭据的管理。FIM 将这一范围扩展到单一组织之外。多个组织可以加入一个联盟或群组，在其中就共享身份的方法达成一致。每个组织中的用户可以在自己的组织中登录一次，其凭据将与一个联合身份相匹配。然后，他们可以使用此联合身份访问群组内任何其他组织中的资源。

联盟可以由单一大学校园内多个不相关的网络、多个大学校园、多个共享资源的组织，或任何其他能就通用联合身份管理系统达成一致的群体组成。联盟成员将组织内的用户身份与联合身份进行匹配。
