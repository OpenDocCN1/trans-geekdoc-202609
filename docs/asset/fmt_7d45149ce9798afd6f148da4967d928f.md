
其次，在企业环境中，工具的管理、部署和监控至关重要。允许集中可见性和报告的反恶意软件工具可与其他安全工具集成，以便轻松查看系统和设备的状态。第三，您部署的检测能力以及反恶意软件产品检测、阻止和删除恶意软件的总体可能性在决策过程中起着重要作用。由于恶意软件是一种不断演变的威胁，许多组织选择部署多种反恶意软件技术，希望提高检测可能性。

### 允许列表和拒绝列表

防止恶意软件在系统上被使用的一种方法是控制可以安装或使用的应用程序。这就是允许列表和拒绝或阻止列表工具发挥作用的地方。允许列表工具允许您构建一个允许在系统上存在和运行的软件、应用程序和其他系统组件列表。如果它们不在列表中，将被移除或禁用，或无法安装。阻止列表或拒绝列表是不能安装或运行的软件或应用程序列表，而不是允许列表。解决方案的选择取决于管理员和安全专业人员想要实现的目标。如果系统需要极高的安全级别，允许列表将比阻止或拒绝列表提供更高的安全性，但如果特定程序被认为是不受欢迎的，阻止列表不太可能干扰未知或新的应用程序或程序。

尽管这些工具听起来很有吸引力，但由于维护列表所需的工作量，它们在大多数组织中并未广泛部署。有限部署和特定用途在组织中更为常见，允许列表和阻止列表的其他版本以防火墙和类似保护技术的形式实现。

### 端点检测和响应

#### 端点检测与响应

当反恶意软件工具不足以应对威胁时，可以部署端点检测与响应（EDR）工具。EDR 工具将使用客户端或软件代理在端点设备和系统上的监控能力，与网络监控和日志分析能力相结合，以收集、关联和分析事件。EDR 系统的关键功能包括搜索和探索收集到的数据并将其用于调查的能力，以及检测可疑数据的能力。

随着安全分析工具的持续发展，EDR 系统倾向于使用自动化规则和检测引擎来查找异常和妥协指标（IoC），同时也允许人工调查。EDR 系统的强大之处在于，它能让处理海量安全数据的组织也能轻松使用并受益于这种检测和报告能力。

如果您正在考虑部署 EDR，您需要关注组织需求，例如：事件响应能力；处理来自各种来源的威胁的能力，范围涵盖从恶意软件到数据泄露；以及在组织更广泛的背景下过滤和审查大量端点数据的能力。

### 数据丢失防护

保护组织数据免遭窃取和无意泄露，是驱动使用 `data loss prevention`（DLP）工具的原因。DLP 工具可以以客户端或应用程序的形式部署到端点。这些工具通常也具有网络和服务器驻留组件，以确保数据在其整个生命周期和各种处理过程中都得到管理。

DLP 系统的关键要素包括：对数据进行分类的能力，以便组织了解哪些数据应受保护；数据标记或标记功能，以支持分类和管理实践；用于按照组织设定的标准管理数据的策略管理和执行功能；以及监控和报告能力，以便快速通知管理员或安全从业人员有关问题或潜在问题。

某些 DLP 系统还提供额外功能，在数据发送到受保护区域之外时对其进行加密。此外，它们可能包含旨在允许共享数据而不造成潜在泄露的功能，通过令牌化、擦除或以其他方式修改数据，以允许在不违反 DLP 环境中设定的数据策略的前提下使用数据。

绘制组织数据图谱，然后根据数据分类系统或策略应用适当的控制，对于 DLP 系统的成功至关重要。与反恶意软件和 EDR 系统非常相似，某些 DLP 系统还会跟踪用户行为，以识别可疑行为或常见错误，例如给文件分配过于宽泛的权限，或通过电子邮件或云文件服务共享敏感文档。

当然，即使部署了 DLP，也很可能存在绕过系统的方法。拍摄屏幕照片、剪切和粘贴、或打印敏感数据，都可能让恶意或粗心的用户从环境中提取数据，即使已部署有效且管理良好的数据丢失防护工具。因此，DLP 系统是分层安全基础设施的一部分，它将技术和管理解决方案（如数据丢失防护）与基于组织及其数据所面临风险的策略、意识和其他控制相结合。

### 网络防御

可以使用基于主机的防火墙来阻止不需要的流量，从而保护端点免受网络攻击。基于主机的防火墙内置于大多数现代操作系统中，且通常默认启用。当然，基于主机的防火墙无法深入洞察其过滤的流量，因为它们通常只是简单地阻止或允许特定的应用程序、服务、端口或协议。更高级的过滤需要更深入地了解被分析流量的本质，这正是基于主机的入侵防御系统或入侵检测系统发挥作用的地方。

基于主机的入侵防御系统（HIPS）会在主机上的服务或应用程序处理流量之前对其进行分析。HIPS 可以对该流量采取行动，包括过滤掉恶意流量或阻断接收到的数据中的特定元素。HIPS 会检查分散在多个数据包中或贯穿整个通信系列的流量，从而能够捕获可能分散或复杂的恶意活动。由于 HIPS 可以主动阻断流量，将合法流量误判为恶意、配置错误或其他问题可能导致合法流量被阻断，从而潜在地造成中断。如果您选择部署 HIPS 或任何其他可以主动阻断流量的工具，您需要考虑如果出现问题会发生什么。

基于主机的入侵检测系统（HIDS）执行类似的功能，但像传统的入侵检测系统（IDS）一样，它无法采取行动阻断流量。相反，HIDS 只能报告问题并发出警报。因此，HIDS 在实时安全方面用途有限，但它导致问题的可能性要低得多。

在部署和管理基于主机的防火墙、HIPS 或 HIDS 之前，请确定如何管理它们、单个配置的复杂程度如何，以及如果基于主机的保护出现问题会发生什么。这并不意味着您不应该部署它们！细粒度控制是零信任设计的重要组成部分，强化主机有助于确保安全边界后的受损系统不会给组织带来更广泛的问题。

### 强化端点和系统

确保系统安全启动只是保持其安全的第一步。强化端点和其他系统依赖于多种技术，以保护系统及其上运行的软件。

#### 强化

强化系统或应用程序涉及更改系统上的设置，以提高其整体安全级别并降低其受攻击的脆弱性。系统攻击面的概念（即可能受到攻击的位置）在执行系统强化时非常重要。强化工具和脚本是对系统执行基本强化过程的常用方法，互联网安全中心（CIS），网址为 [`www.cisecurity.org/cis-benchmarks`](http://www.cisecurity.org/cis-benchmarks)，以及国家安全局，网址为 [`apps.nsa.gov/iaarchive/library/ia-guidance/security-configuration/?page=3`](http://apps.nsa.gov/iaarchive/library/ia-guidance/security-configuration/?page=3)，为操作系统、浏览器和各种其他强化目标提供强化指南。

#### 服务强化

##### 减少系统攻击面的最快方法之一是减少其提供的开放端口和服务的数量

毕竟，如果攻击者无法远程连接到系统，他们直接利用系统漏洞的难度将大大增加。端口扫描器常用于快速评估网络上系统的开放端口，使安全从业人员能够识别并确定加固目标的优先级。加固的简单经验法则是：只有必须可用以提供必要服务的服务和端口才应开放，并且这些端口和服务应仅限于它们需要交互的网络或系统。不幸的是，对许多服务器而言，这可能意味着系统需要面向全球开放。

在 Linux 中启动和停止服务需要知道你的 Linux 发行版如何处理服务。对于 Ubuntu Linux 系统，可以通过使用 `service –status-all` 命令来检查正在运行的服务。启动和停止服务可以通过多种方式完成，但 `service` 命令是一种简便的方法。发出 `sudo service [`*`服务名称`*`] stop` 或 `start` 命令将启动或停止一项服务，只需使用 `service -status-all` 命令提供的信息来识别你要关闭的服务即可。然而，永久停止服务将要求你进行其他更改。对于 Ubuntu，将调用 `update-rc.d` 脚本，而 RedHat 和 CentOS 系统则使用 `chkconfig`。

#### 操作系统加固

操作系统加固依赖于更改设置以匹配给定系统所需的安全态势。流行的基准和配置标准可用作基础，并根据组织需求进行修改，从而允许在整个组织中使用诸如 CIS 基准之类的工具。幸运的是，存在一些工具和脚本可以帮助更轻松地应用这些设置。

CIS 基准针对 Windows 10 推荐的配置设置类型示例包括以下内容：

*   将密码历史记录设置为记住 24 个或更多密码
*   将最大密码使用期限设置为“60 天或更少，但不为 0”，防止用户仅通过更改 24 次密码就恢复使用相同的密码，同时要求每 2 个月更换一次密码
*   将最小密码长度设置为 14 个或更多字符
*   要求密码必须符合复杂性要求
*   禁用使用可逆加密存储密码

上面的列表只是一份包含超过 1,300 页信息的文档中的一个章节，该文档详细介绍了如何锁定 Windows，包括每个设置的描述、推荐理由、推荐设置的影响，以及如何设置和审核该设置的信息。好消息是，考试不要求你了解加固 Windows、Linux 或 macOS 的所有细节。你需要知道的是：操作系统加固使用系统设置来减少操作系统的攻击面，存在工具和标准来协助该过程，并且为组织评估、审核和维护操作系统加固是整体安全管理过程的一部分。

##### 加固 Windows 注册表

Windows 注册表是 Windows 跟踪系统状况的核心。因此，注册表是攻击者的重要目标，他们可以利用它来自动启动程序、收集信息，或在目标计算机上采取其他恶意行动。加固 Windows 注册表涉及配置注册表权限、在不需要特定需求时禁止远程注册表访问，以及限制对 `regedit` 等注册表工具的访问，以便攻击者即使获得了系统访问权限，也更难更改或查看注册表。

##### 配置、标准和模式

要在企业环境中加固系统，你需要通过组织来管理系统的配置。事实上，*配置管理*工具是安全专业人员和系统管理员确保其组织中众多系统具有正确安全设置并帮助保护它们安全的最强大选项之一。第三方配置管理系统（如用于 macOS 的 Jamf Pro）、供商提供的工具（如用于 Windows 的 Configuration Manager），甚至开源配置管理工具（如 CFEngine），都有助于强制执行标准、管理系统，并报告系统不符合预期设置的领域。

配置管理工具通常从组织中具有代表性的系统或操作系统类型的*基线配置*开始。例如，你可以选择为 Windows 10 桌面、Windows 10 笔记本电脑和 macOS 笔记本电脑配置基线配置。然后，根据需要，通过将它们放入具有这些修改后设置的组中，可以针对特定群组、团队、部门甚至个人用户修改这些标准。基线配置是构建的理想起点，有助于降低复杂性，并使配置管理和系统加固能够跨多台计算机（甚至数千台）成为可能。

除了配置管理标准和工具外，文档也是配置管理的重要组成部分。图表（包括架构图、网络图和数据流图）用于理解和记录组织的技术和系统是如何设置的。建立制作系统和架构图的组织习惯，确保它们符合质量标准，并在事物发生变化时进行更新，有助于确保部署符合组织标准。在执行事件响应和灾难恢复操作时，这些相同的图表至关重要，因为它们使响应人员能够快速了解基础设施和系统的配置方式、互连方式、数据流向、数据如何从一处传送到另一处，以及系统或应用程序架构中存在哪些依赖关系。图表和文档也可提供给审计员，作为评估设计的有用工件。

###### 命名标准和寻址模式

### 端点加固

加固端点涉及了解您正在管理哪些系统，并确保网络上的系统是您预期存在的系统。标准对此有所帮助。Security+ 考试将标准命名约定列为一种选项。命名约定发挥多种作用：

*   它们可以帮助您根据命名约定中包含的目的、位置或其他要素来识别系统。
*   它们可用于使系统更加匿名；例如，`examplecorp123` 对攻击者的意义小于 `examplesqlserver` 或 `examplewebserver`。
*   它们使脚本编写和管理更容易，因为您可以使用标准命名约定更轻松地进行筛选、排序和执行其他操作。

使用标准化的互联网协议（IP）模式也很有用。根据目的、位置或其他因素对系统进行分段，并确保您正在管理组织使用的 IP 地址空间，有助于避免地址冲突、避免网络段地址耗尽，并识别不应使用给定地址的系统。当您设计数据中心或云基础设施并分配 IP 地址时，这种能力变得更加重要。如果您用完了地址并不得不重新寻址数据中心，可能需要大量的返工来更新防火墙规则、基础设施即代码（IaC）脚本和工具，或其他您投入了大量时间的地方。

#### 补丁管理

确保系统和软件是最新的，通过消除已知漏洞有助于确保端点安全。及时打补丁可以减少漏洞利用和缺陷被用来攻击系统的时间，但打补丁也有其自身的风险。补丁可能会引入新的缺陷，或者打补丁过程本身有时会导致问题。打补丁的重要性，以及确保打补丁过程受控和托管的必要性，这就是补丁管理的由来。

现代软件（包括软件、浏览器、办公套件和许多其他包）中很大一部分都内置了自动更新工具。这些工具检查更新，并通知用户请求安装更新的权限，或自动安装更新。虽然此模型对单个设备很有用，但企业解决方案对组织更有意义。

操作系统的补丁管理可以使用微软的 `Endpoint Configuration Manager` 等工具针对 Windows 进行，但第三方工具提供对各种软件应用程序的补丁管理支持。使用系统管理工具跟踪版本和补丁状态对组织安全很重要，特别是因为组织可能部署的大量应用程序和包的第三方更新可能是一项艰巨的任务。

管理移动设备的软件仍然是一个挑战，但移动设备管理（MDM）工具也包含验证软件版本的能力。这些工具通常除了控制安全设置外，还具有更新应用程序和设备操作系统的能力。

当您考虑端点安全时，请思考如何更新您的端点设备、它们运行的软件和应用程序，以及您需要了解哪些信息才能知道打补丁是否一致且最新。关键功能（如报告、确定哪些系统或应用程序获取更新及何时获取、阻止更新的能力，当然还有强制安装更新的能力）对于当今组织中各种不同类型设备的企业补丁管理都至关重要。

#### 磁盘安全与清理

保持磁盘内容安全可在系统或磁盘丢失或被盗时保护数据。这就是磁盘加密的用武之地。**全盘加密（FDE）** 加密磁盘，并要求引导加载程序或硬件设备提供解密密钥以及软件或硬件来解密驱动器以供使用。这种加密最常见的实现之一是透明加密（有时称为实时加密）。透明加密实现对用户基本不可见，驱动器在使用期间显示为未加密状态。这也意味着针对使用透明 FDE 的系统最简单的攻击方法是在驱动器解锁时获得对系统的访问权限。

卷加密（有时称为文件系统级加密）保护驱动器的特定卷，允许不同的信任级别，并提供超出使用单个密钥加密整个磁盘所提供的额外安全性。文件和文件夹加密方法也可用于保护特定数据，同样允许不同的信任级别，以及以安全方式传输数据。

全盘加密可以使用**自加密驱动器（SED）** 在硬件级别实现。自加密驱动器在其硬件和固件中实现加密功能。配备自加密驱动器的系统需要密钥才能从驱动器启动，该密钥可以手动输入，也可以由硬件令牌或设备提供。由于这是一种全盘加密形式，相同类型的攻击方法也适用——只需找到已登录的系统或处于睡眠模式的系统即可。

磁盘加密确实带来了潜在的缺点。如果加密密钥丢失，驱动器上的数据将很可能无法恢复，因为保护它的强加密也使得暴力破解密钥并获取数据的可能性极小。技术支持可能更具挑战性，数据损坏或其他问题可能影响更大，导致数据无法恢复。尽管存在这些潜在缺点，全盘加密的显著优势是：丢失或被盗的全加密驱动器系统通常可作为系统丢失处理，而不是作为该系统所含数据的丢失或泄露处理。

##### 清理

确保磁盘在不再需要并报废或将被重复使用时被安全擦除，是驱动器生命周期的重要组成部分。对驱动器或介质进行清理涉及两个过程之一：擦除数据或销毁介质。

磁带和类似的磁性介质通常使用消磁器进行擦除，消磁器将磁性介质暴露在非常强的电磁场中，打乱写入驱动器的位模式。消磁器是销毁磁性介质上数据的相对快速方法。然而，SSD、光学介质和驱动器以及闪存驱动器需要不同的处理方式。
