
独立于主流 ORM 运动，Dave Embley 和其他人认为在概念建模中使用属性是个坏主意，因此他们开发了面向对象系统分析（OSA），其中包含一个无属性的“对象-关系模型”组件，这与 ORM 有很多共同点（Embley et al., 1992；Embley, 1998）。对象管理组织于 2007 年采用的业务词汇与业务规则语义（SBVR）方法是面向事实家族的最新成员，与 ORM 2 有很多共同之处，支持道义规则以及真理规则。撰写时最新版本的 SBVR 规范可在 `www.omg.org/spec/SBVR/1.5` 访问。

## 软件工具

各种 `software tools` 已被开发以支持面向事实方法的不同流派。Nijssen、Meersman 和其他人在 Control Data 开发的最早工具（例如 IAST、RIDL*）不再可用。Bloesch、Halpin 和其他人开发了 VisioModeler（已停止但可免费获取）、ActiveQuery（目前不可用）以及用于 Microsoft Visio for Enterprise Architects 的 ORM 建模解决方案（Halpin et al., 2003）。FCO-IM 版本由商业工具 CaseTalk 支持（`www.casetalk.com`）。Nijssen 在 PNA 的小组开发了基于 CogNIAM（认知增强 NIAM）的工具，包括各种 iKnow 工具（`www.pna-group.com`）。Meersman 和其他人开发了用于指定本体的学术 ORM 工具，如 Dogma Modeler 和 T-Lex（Trog et al., 2006）。

NORMA（Curland and Halpin, 2010）是一个开源插件，用于 Microsoft Visual Studio，为 ORM 2（下一代 ORM）提供深度支持，可从 `ormsolutions.com/` 或 `sourceforge.net/projects/orm` 下载。有关安装和使用 NORMA 的详细信息，请参阅 `www.orm.net/resources`。

Clifford Heath 开发了 ActiveFacts（`dataconstellation.com/ActiveFacts/`），另一套旨在支持 ORM 2 的工具套件。

Victor Morgante（`victormorgante.medium.com/`）是多种工具的主要开发者，如 Boston 和 FactEngine，它们包含对 ORM 2 和其他建模方法的支持（`www.factengine.ai/`）。

## 摘要

本章讨论如何向 ORM 概念模式添加唯一性约束（UC）。内容涵盖一元、二元及更长事实类型的内部唯一性约束，以及事实类型之间的外部唯一性约束。随后展示如何检查事实类型是否为原子的。

## 4.1 CSDP 步骤 4 简介

到目前为止，概念模式设计程序（CSDP）一直专注于指定基本事实类型，包括断言的和派生的。CSDP 的其余部分主要关注指定**约束**。约束适用于数据库，且为静态或动态。*静态约束*适用于数据库的每个单独状态，通常可在模式图上指定，如 CSDP 步骤 4-7 所述。示例包括唯一性、强制角色、集合比较、值、子类型、频率和环约束。*动态约束*限制状态间的转换，通常用其他方式表达（如状态图），并在步骤 7 中与其他约束一起考虑。在实践中，我们通常在转向模型的另一部分之前，捕获与正在讨论的事实类型相关的所有约束。

本章讨论**唯一性约束**（UC）。向事实类型添加 UC 后，会进行检查以查看该事实类型是否具有正确的元数或长度。有一个简单的唯一性检查，可表明某些类型的事实类型并非基本类型，因此应予以拆分。

静态约束常被描述为“事实类型上的约束”。更准确地说，*静态约束适用于数据库的每一种可能状态*。这里的“每种状态”是指“*每一个状态，单独考虑*”。因此，静态约束适用于事实类型的所有可能*实例集*。例如，给定事实类型 `Person(Surname) has Weight(kg:)`，让我们添加约束**每个** Person **至多有一个** Weight。两个状态的示例实例集如图 4.1 所示。

![图 4.1 单独考虑每个状态时，每个人至多有一个体重。](img/f04-01-9780443237904.jpg)

在信息系统的生命周期内，数据库会经历一系列状态。在某一状态下，记录 Smith 体重 90 公斤，Jones 体重 100 公斤（图 4.1(a)）。在稍后的状态下，Smith 体重不变，但 Jones 通过锻炼或节食减轻了体重（图 4.1(b)）。随着时间的推移，Jones 有不同的体重，但在每个数据库状态中，Jones、Smith 或任何其他人的当前体重至多只记录一个。

这就是如何解释静态约束**每个** Person **至多有一个** Weight。诸如 Person has Weight 之类的事实类型是“快照事实类型”——每个实例适用于数据库的单个状态或快照。记录历史的一种方法是使用带有时间引用的“历史事实类型”，例如，Person had Weight on Date（人在日期拥有体重）。

### 概念模式图上的唯一性约束

本章讨论如何在概念模式图上指定 UC。每个基本事实类型必须至少分配一个 UC。鉴于基本事实类型上的约束，派生事实类型上的约束通常由派生规则隐含。例如，如果一扇窗户最多有一个高度和最多一个宽度，那么派生规则 `area = height * width` 就意味着每扇窗户最多有一个面积（这就是派生事实类型“窗户拥有面积”上的 UC）。

本章其余部分讨论 CSDP 步骤 4。首先，我们讨论如何在一元和二元谓词上标记 UC。然后我们考虑更长谓词上的 UC。之后，我们检查外部 UC（这些适用于不同谓词之间）。最后，我们讨论检查事实类型是否具有正确元数（角色数量）的方法。
