
# Feast 与 Vertex AI Feature Store

`Feast` 是由 Google 和 Gojek 创建的开源特征存储，可作为软件下载获得。`Feast` 的设计采用了 `Redis` 和 Google Cloud 服务 `BigQuery` 及 `Apache Beam`。Google Cloud 还提供了一项名为 `Vertex AI Feature Store` 的托管服务，可根据您的需求动态扩缩。

## 数据模型

我们现在将讨论 `Vertex AI Feature Store` 服务使用的数据模型。它使用时间序列模型来存储所有数据，这使您能够管理随时间变化的数据。`Vertex AI Feature Store` 中的所有数据都按层级排列，顶层称为特征存储。此特征存储是一个容器，可以包含一个或多个实体类型，代表特定类型的特征。在您的实体类型中，您可以存储相似或相关的特征。

*   `Featurestore` → `EntityType` → `Feature`

例如，表 13.1 包含棒球击球手的数据。第一步是创建一个名为 `baseballfs` 的特征存储。

**表 13.1** 棒球击球手数据表

| 行 | `player_id` | `Team` | `Batting_avg` | `Age` |
| --- | --- | --- | --- | --- |
| 1 | `player_1` | `RedSox` | `0.289` | `29` |
| 2 | `player_2` | `Giants` | `0.301` | `32` |
| 3 | `player_3` | `Yankees` | `0.241` | `35` |

然后，您可以创建一个名为 `batters` 的 `EntityType`，并将列标题 `player_id` 映射到该实体。接着，您可以将 `team`、`batting_avg` 和 `age` 作为特征添加到此 `EntityType` 中。

此处 `player_1` 和 `player_2` 是此 `EntityType` 中的实体。实体必须始终唯一，且必须始终为 `String` 类型。

`RedSox`、`Giants` 和 `Yankees` 是特征存储中的特征值。

## 摄取与服务

`Vertex AI Feature Store` 支持批量和流式摄取。一种典型的方法是将特征存储在 `BigQuery` 中，然后摄取到特征存储中。

对于从特征存储检索特征，有两种方法：批量和在线。批量方法用于模型训练阶段，在线方法用于在线推理。当您请求时间 `t` 的数据时，`Vertex AI Feature Store` 返回时间 `t` 或之前的值。

## Vertex AI 权限模型

管理对数据集、模型等各种不同资源的访问，以及提供执行训练、部署和监控等各种操作的权限至关重要。身份与访问管理 (IAM) 是强制执行此操作的机制。请参阅第 6 章“构建安全的 ML 流水线”，了解关于 IAM 的讨论。

您可能已经有 GCP IAM 模型的经验——例如在 Compute Engine 或 Google Cloud Storage 中——这将派上用场。

强调遵循最佳实践以使用 IAM 安全性非常重要。以下是一些高层级要点：

*   **最小权限：** 限制用户和应用仅执行必要的操作。
*   **管理服务账号和服务账号密钥：** 积极管理这些安全资产并定期检查它们。
*   **审计：** 启用审计日志并使用 Cloud Logging 角色。
*   **策略管理：** 使用更高层级的检查，确保策略在每个层级得到实施。

有关 IAM 最佳实践的更多详细信息，请参阅此网址：

`https://cloud.google.com/blog/products/identity-security/iam-best-practice-guides-available-now`

我们了解了通用的 IAM 最佳实践，现在将了解 Vertex AI 的一些特殊情况。

### 自定义服务账号

当您运行 Vertex AI 训练作业时，它会使用 Google 为您的 Google Cloud 项目自动创建的几个*服务账号*之一。然而，这些服务账号可能拥有超出需求的权限，例如访问 BigQuery 和 GCS 的权限。最好使用仅具有所需权限集的自定义服务账号。

### Vertex AI 中的访问透明度

要验证谁在访问您的内容以及访问了什么内容，您需要日志。在许多领域，对此类日志记录有法律和合规性要求。重要的是，它还为您提供访问日志，记录 Google 人员在您项目中的操作。有两种类型的访问日志。*Cloud Audit 日志* 是您组织中用户的日志。*Access Transparency 日志* 是 Google 人员的日志。大多数服务都支持此功能，但有一些功能不在覆盖范围内。

有关支持的服务的完整列表，请参阅此网址：

`https://cloud.google.com/vertex-ai/docs/general/access-transparency`

## 常见训练和服务错误

在以下部分中，我们将了解训练和服务期间常见的一些错误。了解错误类型将帮助您有效地调试问题。虽然错误取决于所使用的框架，但我们将在本讨论中使用 TensorFlow 作为框架。

### 训练时错误

在训练阶段，当您运行 `Model.fit()` 时会看到最相关的错误。当发生以下情况时会出现错误：

1.  输入数据未转换或未编码。
2.  张量形状不匹配。
3.  由于实例大小（CPU 和 GPU）导致内存溢出错误。

### 服务时错误

服务时错误仅在部署期间出现，错误的性质也不同。典型错误如下：

1.  输入数据未转换或未编码。
2.  发生签名不匹配。

有关 TensorFlow 错误的完整列表，请参阅此网址：

`www.tensorflow.org/api_docs/python/tf/errors`

### TensorFlow 数据验证

为了防止和减少这些错误，您可以使用 TensorFlow 数据验证 (TFDV)。TFDV 可以按如下方式分析训练和服务数据：

1.  计算统计信息
2.  推断架构
3.  检测异常

有关完整文档，请参阅此处：

`https://cloud.google.com/vertex-ai/docs/training/monitor-debug-interactive-shell`

### Vertex AI 调试 Shell

Vertex AI 提供了一个交互式 Shell 来调试预构建容器和自定义容器的训练。您可以使用交互式 Shell 检查训练容器，以调试训练代码或 Vertex AI 配置中的问题。使用它，您可以执行以下操作：

1.  运行跟踪和分析工具。
2.  分析 GPU 利用率。
3.  验证容器的 IAM 权限。

有关完整文档，请参阅此网址：

`https://cloud.google.com/vertex-ai/docs/training/monitor-debug-interactive-shell`

## 摘要

在本章中，我们探讨了 ML 应用的长期维护。ML 运维或 MLOps 基于维护软件应用的 CI/CD 原则。在此过程中，我们了解了如何自动化训练、部署和监控。模型的重新训练策略是一个重要概念，必须在模型质量和训练成本之间取得平衡。大型企业中出现的另一个重要问题是部门间无法共享特征，这导致了大量的低效。为了解决这个问题，特征存储的概念应运而生，它可以使用开源软件或 Vertex AI Feature Store 来实现。

## 考试要点

*   **理解 MLOps 成熟度。** 学习 MLOps 的不同成熟度级别以及它们如何与组织目标相匹配。了解实验阶段的 MLOps 架构，然后是具有一定自动化的战略阶段，最后是完全成熟的受 CI/CD 启发的 MLOps 架构。
*   **理解模型版本控制和重新训练触发器。** MLOps 中面临的一个常见问题是知道何时触发新的训练。这可能基于模型监控中观察到的模型性能下降，也可能基于时间。重新训练模型时，了解如何将其作为新版本或新模型添加。
*   **理解特征存储的用途。** 特征工程是一项昂贵的操作，因此使用这些方法生成的特征如果在团队间共享会更有用。Vertex AI Feature Store 是一项托管服务，Feast 是 Google 的开源特征存储。

# 第 14 章：BigQuery ML

BigQuery 是 Google Cloud 的旗舰数据仓库产品。它是一项全托管的无服务器服务，可处理 PB 级数据。BigQuery 于 2011 年 11 月发布（正式上线）。10 多年来，这项广受欢迎的服务在用户群和功能数量上都有了显著增长。

你可能已经注意到，在前面的许多章节中都提到了 BigQuery ML。虽然当前的考试指南（截至本书撰写时）没有单独的章节介绍它，但这是 ML 认证最重要的主题之一。

在 BigQuery 中，数据是使用 SQL 进行分析的，包括创建和训练模型。我们将通过一个示例解释 BigQuery 的用法。假设我们有一个包含信用卡客户数据的数据集，目标是判断客户是否拖欠了信用卡付款。

BigQuery ML 彻底改变了行业，因为它对现状进行了根本性的变革。传统上，机器学习只对编写代码（如 Python）的专家机器学习工程师开放。BigQuery ML 使得熟悉 SQL 的数据分析师也能利用 ML 工具。

在很大程度上，BigQuery ML 实现了机器学习的普及，让更多人能够使用它。这导致机器学习的使用发生了快速变化，特别是针对结构化数据。
