
*   如果您有大型数据集，请使用简单的验证集代替交叉验证。与 k 折交叉验证相比，这将使速度提高约 k 倍。如果您没有足够的数据，这种方法效果不好。

*   通过使用带有超参数优化的分布式训练，将问题并行化到多台机器上。每台机器可以使用不同的超参数选择来拟合模型。对于 n 台机器，这将使速度提高约 n 倍。

*   通过预先计算或缓存可为后续模型拟合重用的计算结果，避免冗余计算。

*   如果使用网格搜索，请减少您愿意考虑的超参数值的数量。由于组合总数按乘法方式扩展，这可能会带来潜在的巨大加速。

要了解更多信息，请访问以下页面：

*   `https://cloud.google.com/blog/products/ai-machine-learning/hyperparameter-tuning-cloud-machine-learning-engine-using-bayesian-optimization`

*   `https://cloud.google.com/ai-platform/training/docs/hyperparameter-tuning-overview`

### Vertex AI 超参数调优的工作原理

超参数调优通过运行您训练应用的多次试验来工作，在这些试验中使用您指定并在限制范围内设置的超参数值。超参数调优需要 Vertex AI 与训练应用之间的通信。训练应用定义模型所需的所有信息。您定义要调整的超参数（变量）以及用于评估每次试验的目标变量。超参数调优会优化您指定的目标变量，称为超参数指标。指标必须是数值型的。

配置超参数调优作业时，您需要定义每个指标的名称和目标。目标指定您是希望调整模型以最大化还是最小化该指标的值。

请按照以下步骤使用带有自定义作业的 `gcloud` CLI 命令配置超参数调优作业：

1.  对于自定义容器，请在 Dockerfile 中安装 `cloud-ml hypertune` Python 软件包。

2.  在 `trainer/task.py` 中，在主函数中添加超参数调优代码，并按如下所示添加参数。

    ```python
    def main():
        args = get_args()
        train_data, validation_data = create_dataset()
        model = create_model(args.num_units, args.learning_rate, args.momentum)
        history = model.fit(train_data, epochs=NUM_EPOCHS, validation_data=validation_data)

        # 定义指标
        hp_metric = history.history['val_accuracy'][-1]

        hpt = hypertune.HyperTune()
        hpt.report_hyperparameter_tuning_metric(
            hyperparameter_metric_tag='accuracy',
            metric_value=hp_metric,
            global_step=NUM_EPOCHS)
    ```

3.  构建并将此容器推送到 Artifact Registry。设置训练后，您可以使用训练流水线或自定义作业配置超参数调优作业。

```yaml
studySpec:
  metrics:
  - metricId: METRIC_ID
    goal: METRIC_GOAL
  parameters:
```

**配置参数：**

*   `METRIC_ID`：要优化的超参数指标的名称。您的训练代码在运行时必须报告此指标。

*   `DOUBLE_MIN_VALUE`：您希望 Vertex AI 为此超参数尝试的最小值（数字）。

*   `DOUBLE_MAX_VALUE`：您希望 Vertex AI 为此超参数尝试的最大值（数字）。

*   `MACHINE_TYPE`：用于训练的虚拟机类型。

*   `CUSTOM_CONTAINER_IMAGE_URI`：包含您训练代码的 Docker 容器镜像的 URI。

### 重新训练/重新部署评估

模型在真实世界中训练并部署后，随着时间的推移，模型性能会发生变化；由于用户行为和训练数据随时间不断变化，您的模型对变化很敏感。尽管所有机器学习模型都会衰退，但衰退的速度随时间而异。这主要是由数据漂移、概念漂移或两者共同导致的。让我们来了解这些术语。

#### 数据漂移

**数据漂移**是指生产数据的统计分布与用于训练或构建模型的基准数据的统计分布发生了变化。如果模型的特征归因发生变化，或者数据本身发生变化，则可以检测到数据漂移。例如，假设您使用从 IoT 传感器收集的华氏度温度数据构建了一个模型，但单位变成了摄氏度。这意味着输入数据发生了变化，因此数据发生了漂移。您可以通过检查特征分布或特征间的相关性，或使用监控系统检查相对于基准的数据架构来检测数据漂移。

#### 概念漂移

**概念漂移**是一种现象，即您试图预测的目标变量的统计特性随时间发生变化。例如，假设您构建了一个模型来对围绕特定主题的 Reddit 信息流的正面和负面情绪进行分类。随着时间的推移，人们对这些主题的情绪会发生变化。属于正面情绪的推文可能会随着时间演变为负面情绪。

为了检测漂移，您需要监控已部署的模型，这可以通过 Vertex AI Model Monitoring 来完成。我们将在 第 12 章 “模型监控、跟踪和审核元数据” 中详细介绍此主题。

#### 何时应重新训练模型？

根据 表 8.7 确定重新训练策略。我们将在 第 12 章 中讨论如何使用 Vertex AI Pipelines 和 Vertex AI Model Monitoring 设置重新训练。

**表 8.7** 重新训练策略

| 策略 | 说明 |

| :--- | :--- |

| 定期训练 | 您可以选择每周、每月或每年等间隔来重新训练模型。这取决于您的训练数据更新的频率。仅当基于间隔的模型重新训练与您的业务用例一致时才有意义。为模型重新训练选择随机周期可能会导致模型比之前的模型更差。 |

| 数据变更触发器 | 如果发生数据漂移，则应触发模型重新训练的构建。通常，生产环境中的模型性能变化会导致数据漂移。 |
