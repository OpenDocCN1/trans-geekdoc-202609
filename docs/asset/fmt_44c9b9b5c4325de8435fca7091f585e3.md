
IPv6 为 IPSec 提供内置支持。这为传输中的数据提供了更好的保护，并实现了端到端的数据认证和隐私保护。IPv6 还消除了 NAT，并提供了无状态自动配置的能力。然而，IPv6 可能仍然为攻击者提供攻击区域。

我经常问我咨询的一些公司他们何时会实现纯 IPv6 环境，答案通常是“某一天”。为什么许多公司推迟采用 IPv6？在很多情况下，这取决于资金。当采用 IPv6 时，一个真实的顾虑是攻击者可能利用 IPv6 绕过为 IPv4 流量设计的安全控制。

当 IPv6 完全部署后，不再需要 ARP。IPv6 不支持 ARP，而是使用 NDP。用于 IPv6 的常用协议包括 RIPng、OSPFv3、IS-IS 和 BGP。尽管美国在实现 IPv6 方面缓慢，其他国家已经开始为了满足当前和未来需求制定 IPv6 方案。IPv4 和 IPv6 之间的过渡技术示例是站点内自动隧道 (ISATAP)。IPv4 和 IPv6 的一些关键差异如表 2.2 所示。

# 传输层

传输层提供端到端交付。主机到主机层位于两种主要的协议：TCP 和 UDP。

**TCP** TCP 设计为可靠通信而设计的。其目的是允许主机建立连接并可靠地交换数据。TCP 具有内置的可靠性：它执行三次握手，使用序列号和确认号，并完成一个四步关闭过程，以优雅地结束会话。如果发生任何问题，TCP 还可以利用重置（reset）机制来终止通信。启动序列如图 2.12 所示。

TCP 可靠通信的核心是一个字节位的标志字段（flags）。标志有助于控制 TCP 进程。常见的标志包括同步（SYN）、确认（ACK）、推送（PSH）和完成（FIN）。TCP 安全问题包括 TCP 序列号攻击、会话劫持和 SYN 洪水攻击。扫描程序通过调整 TCP 标志来识别活动主机或区分不同的操作系统。

实践“拒绝所有”方法并阻塞所有显式定义的端口是安全的良好方法。如果一个端口没有被使用，它应该被关闭。安全是一个永无的过程。今天端口关闭并不意味着明天也会关闭。你需要定期测试开放端口。并不是所有应用程序都是平等的。虽然像 SSH 这样的是安全的，但像 Telnet 等不是。以下列表讨论了一些应用程序的操作和安全问题：

**文件传输协议 (FTP)** FTP 是一种 TCP 服务，运行在端口 20 和 21。FTP 是一种基本文件传输协议。端口 20 用于数据流并在客户端和服务器之间传输数据。端口 21 是控制流，用于在客户端和 FTP 服务器之间传递命令。针对 FTP 的攻击目标是配置不当的目录权限和被破解的明文密码。FTP 被黑客广泛攻击，强烈建议更安全的变体，如 FTPS、SFTP 或 FTP over SSH。

**Telnet** 是运行在端口 23 的 TCP 服务。Telnet 允许一个地点的客户端与另一个地点的主机建立会话。程序将键盘输入的信息传递给主机。尽管 Telnet 可以配置为匿名连接，但它仍然以明文发送用户名和密码。考虑使用 Secure Shell (SSHv2) 等应用程序。

**简单邮件传输协议 (SMTP)** SMTP 是运行在端口 25 的 TCP 服务。它设计用于网络系统之间的电子邮件交换。通过 SMTP 发送的消息有两个部分：头部和消息正文。所有类型的计算机都可以与 SMTP 交换消息。欺骗和垃圾邮件是与 SMTP 相关的两个漏洞，此外它也以明文传输。Ettercap 是来自 dnsiff 包的工具，可以以自动方式嗅探 SMTP 和 POP 流量。当然，你也可以用协议分析器来实现。

**简单文件传输协议 (TFTP)** TFTP 运行在端口 69。它的运行方式类似于 FTP，但开销更小。它不仅缺乏 TCP 提供的会话管理，而且不需要身份验证，这可能带来巨大的安全风险。它用于传输路由器配置文件，以及电缆公司配置调制调器。TFTP 是黑客的最爱，已被 Nimda 病毒等程序用于在无需输入用户名或密码的情况下移动数据。

**超文本传输协议 (HTTP)** HTTP 是最著名的应用程序之一。HTTP 使用 TCP 端口 80。尽管 HTTP 使用 TCP，但它使用的是无状态连接。HTTP 使用请求-响应协议，客户端发送请求，服务器发送响应。利用 HTTP 的攻击针对服务器或运行在浏览器上的脚本。跨站脚本 (XSS) 和跨站请求伪造 (XSRF 或 CSRF) 攻击是两个例子。基本上，黑客构造特殊数据包来利用 Web 服务器上的漏洞代码。有很多自动化工具可以做到，研究这项技术的良好起点是开放 Web 安全项目 (OWASP) 网站 www.owasp.org/index.php/Main_Page。

**简单网络管理协议 (SNMP)** SNMP 是运行在端口 161 和 162 的 UDP 服务，用于网络管理。SNMP 允许代理收集网络统计等信息并报告给其管理站。大多数大公司都实现了某种 SNMP 管理。困扰 SNMP 的一些安全问题是因为 v1 和 v2 团体字符串可以作为明文传递，并且默认团体字符串（公共/私有）是广为人知的。SNMP 版本 3 是最新版本；它提供了加密以实现更强大的安全性。

# TCP/IP 协议族通信解决方案

TCP/IP 协议族并不是为了安全而构建。它的首要考虑是可用性，尽管这在早期互联网是可以接受的，但为了满足变化的业务需求，需要安全的数据流。这些缺陷中的一些源于协议本身的缺陷，而另一些则源于实现协议的软件缺陷。许多传输协议并不提供加密。CASP 候选人必须知道如何利用这些数据来满足当前和未来的数据需求。

# 网络数据流

在本章之前的练习中，你使用了 Wireshark 工具；它是网络嗅探器的一个示例。本节的主题并不是网络嗅探器；然而，如果你使用网络嗅探器查看本地网络上的流量，你可能会对所看到的内容感到惊讶。这是因为流经或跨越典型网络的大多数网络数据非常容易被检查。反之，是因为大多数协议（如 FTP、HTTP、SMTP、NTP、Telnet 等）都是通过明文跨网络发送数据的。这仅意味着流量没有加密，且容易查看。TCP/IP 以及现代互联网的早期设计者并不关心加密；他们只是在尝试让一切正常运行。对于安全专业人员来说这是一个问题，因为攻击者可以轻易地拦截和查看你的网络流量。数据保护概念以及如 SSH 和 SSL 等安全协议出现得晚得多。

即使使用 SSL 和 IPSec 等技术保护了数据，入侵者仍然可能破解你的网络。检测当前威胁以及来自内外的多种信息源的一种方法是分析网络数据流。这被称为网络流分析。该概念涉及利用现有的基础设施。流分析为网络中的流量移动提供了一个不同的视角。它允许你查看某个事件在给定时间内发生的频率。例如，在周末的午夜到凌晨 2 点之间，包含加密文件的流量离开你的网络并发往俄罗斯的频率有多高？通过流分析工具，安全专业人员可以实时查看此类活动。

提炼流经现代网络的海量数据，需要能够进行数据聚合和关联的工具。思科系统（Cisco Systems）是 20 世纪 90 年代推出该技术的公司之一，开发了 NetFlow。许多公司现在在该领域随其后，例如 Vitria、Riverbed Technology 和 Arbor Networks；它们都提供流分析工具。

# SSL 检查

上一节帮助你意识到在流量跨越网络时加密流量的必要性。常见的解决方案是安全套接层（SSL）。SSL 是一种设计用于在互联网上提供通信安全的加密协议。

它在第 1 章“加密工具与技术”中有详细描述。SSL 广泛用于保护传输过程中的信息。

尽管 SSL 提供了高水平的安全性，但它并非无一击之。我的观点是，像 SSL 这样的每防御措施都有漏洞。SSL 检查的其中一个漏洞简单意味着攻击者可能会监控流量的流、方向和数量。这可能导致所谓的推理攻击（inference attack）。当攻击者注意到流量激增并推断存在待处理事件时，攻击就会发生。防止此类攻击的一种方法是通过流量填充（traffic padding）。例如，一个军事机构可以在美国和乌克兰之间建立连接。尽管俄罗斯监控器可能看到流量正在流动，但传输量保持在恒定流量，从而防止攻击者进行推理攻击。

# 域名服务
