
尽管无线网络是有线网络的廉价替代方案，但缺乏适当的安全措施可能给公司带来风险。进行无线攻击的要求是使用带有可以设置为“监听模式”（Monitor Mode）的无线适配器的攻击系统。WPA 比 WEP 更容易破解，但只有在使用弱密码时 WPA 才能被破解。WEP 的破解时间可能比 WPA 长，但 WEP 总是可以被破解。

# 项目管理

在此阶段，渗透测试项目最大的风险是系统崩溃时的通信问题。利益相关者不需要了解渗透测试此阶段发现的所有漏洞——在许多情况下，警报系统和网络管理员会阻碍渗透测试。如果工程师发现了可能导致系统完全崩溃的漏洞，可能需要采用进度压缩技术来为工程师提供额外时间。

**Q：** 我无法获取目标系统的管理权限。我该怎么办？

**A：** 在专业的渗透测试中，并不总是能够获得管理员访问。在没有此类访问的情况下结束渗透测试是合理的。

**Q：** 我如何从不同的网络嗅探网络流量？

**A：** 你只能嗅探当前连接的网络流量。要嗅探与你自己的不同的网络流量，你需要攻破目标网络中的一个系统（或在目标网络放置一个系统）。

**Q：** 我从无线 WEP 攻击中获得了大量的 IV，但 `aircrack-ng` 仍然无法破解密钥。我哪里做错了？

**A：** 虽然在减少破解密钥所需的 IV 数量方面已经改进，但有时渗透测试人员的方方面面都会出错，导致未能捕捉“正确”的 IV。破解 WEP 密钥的精确时刻在每次渗透测试之间会有显著差异。

常客会招人厌。—— 俄罗斯谚语：“常客是不受欢迎欢迎的。”(Mertvago, 1995) 一旦获得了目标系统的访问权限，我们需要维持这种访问。在渗透测试期间，出现系统维护窗口并不罕见——如果计划中的维护部分是为了修复我们所利用的漏洞，那么我们的访问可能会被终止。此外，如果系统重启或我们丢失了网络连接，远程 shell 访问可能会永久丢失。

在渗透测试中，使用后门非常常见。通常需要找到方法绕过防御障碍，例如防火墙或访问控制列表。后门可以绕过所有这些防御，让专业的渗透人员对受侵害的系统获得不受限制的访问。后门还可以加速对服务器的访问，例如第 10 章中和第 11 章中的 Webmin 示例——执行 Debian Open Secure Sockets Layer (SSL) 漏洞利用需要几个小时，而每次需要访问时都重复执行该利用将过于繁琐。

快速访问受害者机器的另一个优势是，一旦进入网络，工程师就有了更大的自由来扫描和攻击系统，因为网络防御通常只寻找外部攻击——来自网络内部系统的攻击可能不会被察觉。如果我们使用加密建立后门，就可以更好地隐藏我们的活动。在第 11 章中，我们使用 `CORE IMPACT` 向目标系统注入代理（agents）。这些代理可以被持久化，有效地成为根据需要访问访问后后门。如果我们必须跨越多个网络的多个系统以到达最终目标，这些代理也可以用于从一个系统跳到下一个系统。`CORE IMPACT` 将所有代理加载到内存中，这降低了检测到的概率，因为受侵害系统上没有安装任何文件。在内存中安装的缺点是如果系统重启，代理将会丢失。如果我们绝对需要一个持久连接，我们可能希望在系统上安装后门应用程序，而不仅仅是内存。有使用 `IMPACT` 创建持久连接的方法，但在受侵害系统中创建后门最简单的方法是使用 `netcat`。

# Shell 与反向 Shell (Shells and Reverse Shells)

`netcat` 是一种系统管理员用于提供两个系统之间连接的应用程序。`netcat` 可以作为服务器也可以作为客户端——如果我们希望 `netcat` 监听连接，我们也可以配置它在连接建立时产生 shell，为我们提供对系统的命令行访问。如果我们持续访问网络，我们可能希望设置 `netcat` 在受利用的系统上监听连接。然而，大多数使用 `netcat` 的渗透测试配置将设计为“拨家”（phone home）或请求从受利用系统到渗透测试工程师控制的攻击服务器的连接。最后这种方法被称为`反向 shell`（reverse shell）。对于我们使用 shell 和反向 shell 作为维持服务器访问方法的示例，我们将使用在图 13.1 所示的网络配置，并使用实验室中的 Hackerdemia LiveCD 服务器作为我们的目标。我们还假设已经利用了该系统（例如通过使用 Debian OpenSSL 漏洞），只是在尝试安装后门。
