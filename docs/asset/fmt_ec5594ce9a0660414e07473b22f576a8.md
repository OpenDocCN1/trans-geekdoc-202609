
在 [[KHAD2012b]](#ch04.xhtml#ref4_42) 中，作者设计了一个 `Jena-HBase` 框架。其基于 `HBase` 的三元组存储可与 `Jena` 框架配合使用。`Jena-HBase` 为最终用户提供了一个可扩展的存储和查询解决方案，支持 RDF 规范的所有特性。更多 `HBase` 详情可参见 [`HBASE`] 和 [[GEOR2011]](#ch04.xhtml#ref4_28)。

### 4.4.3.2 来源集成

虽然我们针对社交网络应用在云中实现可靠信息共享的方法足够通用，适用于包括网络安全数据在内的任何类型数据，但我们以来源数据为例进行了说明。我们将讨论在来源数据集成工作中考察的各种方法。更多工作详情可参见 [[THUR2014]](#ch04.xhtml#ref4_66)。

在 [[IKED2011]](#ch04.xhtml#ref4_39) 中，作者考虑了一类称为广义 Map 和 Reduce 工作流（`GMRWs`）的工作流。输入数据集由 Map 和 Reduce 函数的有向无环图处理以产生输出结果。他们还展示了如何透明地捕获 Map 和 Reduce 函数的数据来源（谱系）。

在 [[CHEB2013]](#ch04.xhtml#ref4_19) 中，作者探索并解决了在 `Apache HBase` 数据库中高效且可扩展地存储和查询大量序列化为 RDF 图的来源图集合的挑战。

在 [[PARK2011]](#ch04.xhtml#ref4_55) 中，他们提出了 `RAMP`（Reduce 和 Map 来源）作为 `Hadoop` 的扩展，支持 `MapReduce` 作业工作流的来源捕获和追踪。

[[ABRA2010]](#ch04.xhtml#ref4_1) 中讨论的工作提出了一个系统，展示了如何利用 `HBase` 类 Bigtable 的能力，对用 RDF 表示的来源数据进行分布式存储和查询。特别是，他们的 `ProvBase` 系统包含一个 `HBase`/`Hadoop` 后端、一个用于存储来源三元组的存储模式，以及一个用于在其系统中评估 `SPARQL` 查询的查询算法。

在 [[AKOU2013]](#ch04.xhtml#ref4_3) 中，作者的研究引入了 `HadoopProv`，这是一个实现了 `MapReduce` 作业中来源捕获和分析的修改版 `Hadoop`。其系统旨在通过 (i) 分别处理 Map 和 Reduce 阶段的来源跟踪，以及 (ii) 将来源图的构建推迟到查询阶段，来最小化来源捕获开销。来源图随后在 Map 和 Reduce 来源文件的匹配中间键上进行连接。

## 4.5 分析与保护社交网络

### 4.5.1 社交网络简介

在线社交网络（`OSNs`）在互联网上获得了极大普及，成为一个重要的研究课题，吸引了来自不同领域的众多专业人士。自 `Facebook`、`Twitter` 和 `LinkedIn` 等 `OSNs` 网站出现以来，`OSNs` 持续影响并改变着我们生活的方方面面。从政治到商业营销，从名人到新闻制造者，每个人都沉迷于这一现象。`Facebook` 用于与朋友联系并分享各种个人和专业数据以及照片和视频；`LinkedIn` 完全是一个专业网络，用于与同事建立联系。`Google+` 类似于 `Facebook`，而 `Twitter` 是一项免费的社交网络和微博服务，允许用户发送和阅读称为推文的消息。推文是显示在作者个人资料页面上并分发给作者订阅者（称为 `followers`）的约 140 字符的文本帖子。每个网络都有其自身的优势，这些网络主要通过广告盈利，因为它们提供的服务在很大程度上是免费的，除非当然有人想在 `LinkedIn` 等网络中获得高级服务。

我们在社交媒体分析方面的大量工作都集中在分析推文上。特别是，我们分析推文以检测可疑人员以及进行情感分析。此外，我们开发的许多实验系统都侧重于使用语义 Web 技术表示的社交媒体数据。我们的工作还考察了 Facebook，研究人们发布的信息，并确定是否可以提取用户的敏感属性。我们还在社交网络访问控制的工作中使用了基于语义 Web 的社交网络表示。我们将讨论社交媒体分析应用，然后讨论安全和隐私问题。第 IV 部分将讨论我们开发的一个用于分析和保护基于语义 Web 的社交媒体系统的系统。图 4.9 展示了社交媒体分析、安全和隐私的各个方面。关键点将在第 4.6.2 节至第 4.6.4 节中详细阐述。更多详情请参阅 [THUR2016]。

### 4.5.2 社交媒体分析应用

#### 4.5.2.1 提取人口统计信息的应用

在此任务中，分析社交媒体数据并提取位置和年龄等人口统计数据。如果社交媒体用户已经指定了其位置，则此处无需进一步工作。否则，提取位置的一个简单方法是检查其朋友的位置，然后根据用户住在其朋友附近这一假设来确定位置。年龄属性可以通过查看 LinkedIn 了解一个人何时毕业，然后计算年龄来提取。应当注意，可能存在偏离常态的情况，因此存在产生假阳性和假阴性的可能性。

#### 4.5.2.2 情感分析

此处分析推文并提取诸如“我喜欢披萨”或“我不喜欢巧克力”之类的词语。这里的思路是分析不同个体的推文，确定他们对特定物品（如披萨或巧克力）或话题（如体育或音乐）的情感倾向。

#### 4.5.2.3 检测兴趣社区

网络中的某些人将拥有相似的目标和兴趣。因此，可以通过 Facebook 中的帖子将兴趣相似的各类人群连接起来，使他们能够形成一个社区。此处的分析将提取兴趣相似的个体并将他们连接起来。

#### 4.5.2.4 确定领导者

在此应用中，分析网络以查看一个人拥有的三个连接数量以及关系的强度。如果许多人与某人建立连接或关注某人，则该人将成为领导者。存在显而易见的领导者，如名人和政治家，也存在通过分析网络可以发掘出的非显性领导者。

#### 4.5.2.5 检测关注人员

如果例如与来自特定国家的人通信会使某人变得可疑，则该人可能是关注人员。这样可以对该人进行进一步调查。通常，关注人员不像与特定国家的人通信那样容易直接发现。因此，挑战在于通过数据分析技术提取隐藏的链接和关系。

#### 4.5.2.6 确定政治倾向

这里的思路是确定个人的政治倾向，即使他们没有明确说明他是自由派还是保守派。在这种情况下，可以考察他们钦佩的政治领袖（例如撒切尔夫人或希拉里·克林顿）以及他们是否去教堂，以此判断该人是自由派还是保守派。

以上示例仅是应用中的一小部分。还有许多其他应用，如确定性别偏见、检测可疑行为，甚至预测未来事件。这些 SNA（社交网络分析/挖掘）技术使用各种分析工具，执行关联规则挖掘、聚类、分类和异常检测等。我们将在下一节讨论各种数据挖掘技术如何应用于 SNA。

### 4.5.3 面向社交网络的数据挖掘

第 3 章概述了我们在工作中使用的一些数据挖掘技术，以及一些为 SNA 提出的其他技术。在本节中，我们将考察各种数据挖掘技术如何应用于 SNA。这些技术的目标是为确定人口统计信息和检测可疑行为等各种应用提取知识金块。图 4.10 展示了应用于 SNA 的各种数据挖掘技术。

![图 4.10 面向 SNA 的数据挖掘技术。](img/fig4_10.jpg)

图 4.10 面向 SNA 的数据挖掘技术。

#### 4.5.3.1 关联规则挖掘

关联规则挖掘技术从海量信息中提取规则。这些规则确定一起购买的商品或一起出现的人员。因此，在 SNA 的背景下，关联规则挖掘技术将提取规则，指明彼此具有强关系的人员。

#### 4.5.3.2 分类

分类技术将根据一组预定义标准确定类别。将此类技术应用于 SNA，可以形成兴趣社区。例如，一个社区可能由喜欢网球的个体组成，而另一个社区可能由喜欢高尔夫的个体组成。请注意，存在一个预定义标准：如果一个人参与某项运动且也观看该运动，则认为他喜欢该运动。

#### 4.5.3.3 聚类

当没有预定义标准时，聚类技术将形成群组。因此，通过分析数据，可以提取出诸如居住在东北部的人大多吸烟卷烟，而居住在西南部的人大多吸雪茄等模式。

#### 4.5.3.4 异常检测

异常检测技术确定偏离常态的变化。例如，John 社交网络中的每个人都喜欢看间谍电影，只有 Paul 和 Jane 例外。

#### 4.5.3.5 Web 挖掘

Web 挖掘技术在 SNA 中有天然的应用。这是因为 WWW 可以被视为一个网络，其中节点是网页，链接是网页之间的链接。因此，Web 结构挖掘确定网页如何相互连接，而 Web 内容挖掘将分析 WWW 的内容。Web 日志挖掘将分析对网页的访问。同样，可以挖掘社交图谱并提取图的结构。可以挖掘图的内容（即数据）以提取各种模式。也可以挖掘对 Facebook 页面等的访问，这类似于 Web 日志挖掘。

### 4.5.4 安全和隐私

由于数据挖掘，用户可以访问社交网络中各成员的信息并提取敏感信息。这可能包括个人可能希望保密的财务数据、健康数据和旅行数据。可以提取的其他敏感信息包括政治倾向和性别偏好，以及饮酒和吸烟习惯。在我们之前的工作中，我们考察了由于数据挖掘和分析导致的社交媒体数据中发生的各种隐私侵犯。我们应用了各种数据分析技术，并展示了如何推断私人信息 [ABRO2016]。

安全的另一个方面是机密性。也就是说，必须控制对社交媒体中敏感信息的访问。用户应该有选项仅授予特定朋友访问权限。此外，人们可能会更信任某些朋友。我们已经研究了使用语义 Web 技术表示的社交网络的访问控制。我们还开发了实验系统，包括社交网络中的推理控制以及基于云的可靠信息共享。

## 4.6 总结与展望

在本章中，我们讨论了三种类型的大数据系统。首先，我们讨论了所谓的用于托管大数据系统的基础设施。这些本质上是大规模数据处理平台，例如 `Apache Hadoop`、`Spark`、`Storm` 和 `Flink`。然后我们讨论了各种大数据管理系统。这些包括基于 SQL 的系统和基于 NoSQL 的系统。随后我们讨论了大数据管理与分析系统。我们已经试验了其中的几个系统。它们包括 `Apache Hadoop`、`Storm`、`MapReduce`、`Hive`、`MongoDB` 和 `Weka`。

我们相信，在过去十年中，大数据技术呈爆发式增长。仅仅 15 年前，本章讨论的许多系统还不存在。我们预计技术将继续爆发式发展。因此，我们不仅要跟进文献，还要试验大数据技术，这非常重要。随着进展的推进，我们将更清楚地知道何时、何地、为何以及如何使用何种系统。

接下来，我们介绍了云和语义 Web 技术的概念。我们首先讨论了云计算的概念，包括虚拟化的各个方面。我们还讨论了云的各种服务模型和部署模型，并简要概述了存储管理和数据管理等云功能。此外，还讨论了一些云平台，特别是与大数据技术相关的平台。接下来，我们讨论了语义 Web 技术，包括 `XML`、`RDF`、本体和 `OWL`。随后讨论了语义 Web 的安全问题。最后，我们讨论了基于语义 Web 技术的云计算框架。关于云计算和语义 Web 的更多细节，请参阅 `[THUR2007]` 和 `[THUR2014]`。

我们对云计算和语义 Web 的讨论将有助于理解本书第 IV 部分中讨论的一些实验系统。例如，我们讨论了在云中运行的实验性安全超大规模数据处理系统。我们还讨论了云中的可靠信息共享，其中数据使用语义 Web 技术表示。大数据、云和语义 Web 是第 IV 部分讨论所需的一些基础数据科学技术。
