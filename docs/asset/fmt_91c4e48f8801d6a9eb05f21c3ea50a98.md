
# Forward Checking

One of the simplest forms of inference is called **forward checking**. Whenever a variable `X` is assigned, the forward-checking process establishes arc consistency for it: for each unassigned variable `Y` that is connected to `X` by a constraint, delete from `Y`’s domain any value that is inconsistent with the value chosen for `X`. Because forward checking only does arc consistency inferences, there is no reason to do forward checking if we have already done arc consistency as a preprocessing step.

## FORWARD CHECKING

---

Figure 6.7 shows the progress of backtracking search on the Australia CSP with forward checking. There are two important points to notice about this example. First, notice that after `WA = red` and `Q = green` are assigned, the domains of `NT` and `SA` are reduced to a single value; we have eliminated branching on these variables altogether by propagating information from `WA` and `Q`. A second point to notice is that after `V = blue`, the domain of `SA` is empty. Hence, forward checking has detected that the partial assignment `{WA = red, Q = green, V = blue}` is inconsistent with the constraints of the problem, and the algorithm will therefore backtrack immediately.

- Combining MRV heuristic with forward checking search is more effective for many problems. Consider Figure 6.7 after the assignment `{WA = red}`. Intuitively, this assignment seems to constrain its neighbors `NT` and `SA`, so we should handle these variables first, and the rest will fall into place. This is exactly how MRV works: `NT` and `SA` each have two values, so one is chosen first, then the other, followed by `Q`, `NSW`, and `V`. Finally, `T` still has three values, any of which works. We can view forward checking as an efficient way to incrementally compute the information needed by the MRV heuristic.

Although forward checking detects many inconsistencies, it does not detect them all. The problem is that it makes only the current variable arc-consistent, and does not check arc consistency for other variables. For example, consider the third row of Figure 6.7, showing that when `WA` is red and `Q` is green, both `NT` and `SA` are forced to be blue. Forward checking is not sufficient to detect this inconsistency: `NT` and `SA` are adjacent, so they cannot have the same value.

An algorithm called MAC (Maintaining Arc Consistency) detects this inconsistency. After variable `X[i]` is assigned, the INFERENCE procedure calls AC-3, but instead of using a queue containing all arcs in the CSP, it starts with only the arcs `(X[j], X[i])` from unassigned neighbors `X[j]` of `X[i]`. AC-3 then propagates constraints as usual; if any variable has its domain reduced to the empty set, AC-3 fails and the algorithm backtracks immediately. MAC is strictly more powerful than forward checking because forward checking performs exactly the same operations as MAC on the initial arcs in MAC's queue, whereas MAC recursively propagates constraints as domains shrink.

### 6.3.3 Intelligent Backtracking: Backjumping

The BACKTRACKING-SEARCH algorithm in Figure 6.5 uses the simplest strategy when a branch of the search fails: it goes back to the preceding variable and tries a different value. This is called **chronological backtracking** because it revisits the **most recent** decision point. This section considers better alternatives.

---

## CHRONOLOGICAL BACKTRACKING

---

Consider the scenario in Figure 6.1 using a fixed variable ordering `Q`, `NSW`, `V`, `T`, `SA`, `WA`, `NT` with simple backtracking. Suppose the partial assignment `{Q = red, NSW = green, V = blue, T = red}` has been generated. When the next variable `SA` is tried, all its values violate constraints. The algorithm then backs up to `T` and tries a new color! This is clearly silly—recoloring Tasmania cannot possibly solve the problem for South Australia.

A more intelligent approach is to backtrack to the variable that might actually fix the problem—the one that caused some value of `SA` to become impossible. To do this, we maintain a **conflict set** for each variable, containing the assignments that conflict with some value of that variable (in this case `{Q = red, NSW = green, V = blue}`). The **backjumping** method backtracks to the most recent assignment in the conflict set; in this example, it would skip Tasmania and try a new value for `V`. This method can be implemented simply by accumulating conflict sets during BACKTRACK.

## BACKJUMPING

---

The alert reader will have noticed that forward checking can supply conflict sets with no extra work: whenever forward checking deletes a value from the domain of `Y` based on assignment `X = x`, it should add `X = x` to `Y`'s conflict set. If the last value in `Y`'s domain is deleted, the assignments in `Y`'s conflict set are added to `X`'s conflict set. Thus, when `Y` is reached, the algorithm knows immediately where to backtrack.

The astute reader will also notice a strange thing: backjumping occurs when a variable's domain becomes empty, but forward checking prevents the search from ever reaching such a node! In fact, it can be shown that **every** branch pruned by backjumping is also pruned by forward checking. Hence, simple backjumping is redundant in a forward-checking search or a search with stronger consistency such as MAC.

Despite this observation, the idea of backjumping—backtracking based on the reason for failure—remains valuable. Backjumping detects failure when a variable's domain becomes empty, but in many cases a branch is doomed long before this happens. Consider again the partial assignment `{WA = red, NSW = red}` (noted earlier as inconsistent). If we then try `T = red`, followed by assignments to `NT`, `Q`, `V`, `SA`, we know that no combination of values for these four variables can satisfy the constraints, and eventually `NT` will run out of values. Where should we backtrack? Backjumping fails because `NT` still has values consistent with the assigned variables—it does not have a complete conflict set causing failure. We need to consider the failure caused by the **set** of variables `NT`, `Q`, `V`, and `SA` collectively, determined by the set of preceding variables they conflict with directly. In this case, the conflict set is `WA` and `NSW`, so the algorithm should backtrack to `NSW`, skipping Tasmania. Backjumping using conflict sets is called **conflict-directed backjumping**.

---

## CONFLICT-DIRECTED BACKJUMPING

---

We now need to explain how these new conflict sets are computed. The method is actually quite simple. A "terminal" failure in a branch-and-bound search always occurs because a variable's domain becomes empty; that variable has a standard conflict set. In our example, `SA` fails, and its conflict set is (for example) `{WA, NT, Q}`. We backtrack to `Q`, and `Q` absorbs `SA`'s conflict set minus `Q` itself (i.e., `{NT, NSW}`) into its own direct conflict set, yielding a new conflict set `{WA, NT, NSW}`. This means there is no solution from `Q` onward, given the preceding assignments to `{WA, NT, NSW}`. We therefore backtrack to `NT`, the most recent of these. `NT` absorbs `{WA, NT, NSW} - {NT}` into its own direct conflict set `{WA}`, yielding `{WA, NSW}` (as noted above). The algorithm then backtracks to `NSW`, as desired. In summary: let `X[j]` be the current variable and `conf(X[j])` its conflict set. # 6.4 LOCAL SEARCH FOR CSPS

Local search algorithms (see Section 4.1) are effective for many CSPs. They use a complete-state formulation: the initial state assigns a value to every variable, and the search changes the value of one variable at a time. For example, in the 8-queens problem (see Figure 4.3), the initial state might be a random configuration of 8 queens in 8 columns, and each step moves one queen to a new position in its column. The initial configuration usually violates many constraints. The goal of local search is to eliminate these violated constraints.

When selecting a new value for a variable, the most obvious heuristic is to choose the value that results in the fewest conflicts with other variables—the **min-conflicts** heuristic. The algorithm is shown in Figure 6.8, and its application to the 8-queens problem is shown in Figure 6.9.

Min-conflicts is surprisingly effective for many CSPs. Remarkably, on the n-queens problem (excluding the initial placement of queens), the runtime of min-conflicts is roughly independent of problem size. It solves even million-queens problems in an average of 50 steps (after initial placement). This observation sparked a great deal of research in the 1990s on local search and the distinction between easy and hard problems, which we discuss in Chapter 7. Intuitively, n-queens is easy for local search because solutions are densely distributed in the state space. Min-conflicts also works well on hard problems. For example, it has been used to schedule observations for the Hubble Space Telescope, reducing the time to schedule a week of observations from three weeks (!) to about 10 minutes.

All the local search techniques from Section 4.1 can be applied to CSPs, and some have proven particularly effective. Under the min-conflicts heuristic, the state space of a CSP often exhibits a series of plateaus. There may be millions of variable assignments that are only one conflict away from a solution. **Plateau search**—allowing sideways moves to states with the same score—can help local search escape plateaus. This wandering on plateaus can be guided by **tabu search** (keeping a small list of recently visited states and forbidding return to them).

Another technique, **constraint weighting**, helps focus search on important constraints. Each constraint is initially assigned a numeric weight `W[i]`, all set to 1. At each step, the algorithm chooses a variable/value pair that minimizes the total weight of violated constraints. The weights of violated constraints are then incremented. This has two benefits: it adds topography to plateaus, ensuring improvement is possible from the current state; and over time, it weights the difficult constraints more heavily, forcing them to be addressed.

---

## CONSTRAINT WEIGHTING

---

Another advantage of local search is its ability to operate in online environments where the problem changes, which is especially important for scheduling problems. For example, a weekly airline schedule may involve thousands of flights and tens of thousands of personnel, but if bad weather closes an airport, the schedule may become infeasible. We can use a local search algorithm to repair the schedule starting from the current state, making minimal changes. Re-solving with backtracking search typically takes much longer and may produce a schedule with many more changes than local search.

# 6.5 THE STRUCTURE OF PROBLEMS

In this section, we examine how the **structure** of a problem—represented by the constraint graph—can be used to find solutions quickly. Most of these methods apply to problems beyond CSPs, such as probabilistic reasoning. After all, the only way we can hope to deal with the real world is by decomposing it into subproblems. Looking again at the constraint graph for Australia (Figure 6.1(b), repeated as Figure 6.12(a)), one striking fact is that Tasmania is not connected to the mainland. Intuitively, this is obvious: coloring the mainland and coloring Tasmania are independent subproblems—any solution for the mainland combined with any solution for Tasmania yields a solution for the whole map. Independence can be detected by finding **connected components** in the constraint graph. Each component corresponds to a subproblem `CSP[i]`. If `S[i]` is a solution to `CSP[i]`, then `⋃ S[i]` is a solution to `⋃ CSP[i]`. This is important because consider the following: suppose each `CSP[i]` contains `c` variables, and the total number of variables is `n`, where `c` is a constant. Then there are `n/c` subproblems, each taking at most `d^c` work to solve, where `d` is the domain size. Total work is `O(d^c n/c)`, which is linear in `n`; without decomposition, total work is `O(d^n)`, which is exponential in `n`. To make this concrete: dividing a Boolean CSP with 80 variables into four subproblems reduces the worst-case solution time from the lifetime of the universe to less than a second.

## CONNECTED COMPONENT

---

Fully independent subproblems are delicious but rare. Fortunately, other graph structures are also easy to solve. For example, a constraint graph is a **tree** when any two variables are connected by only one path. We show that any tree-structured CSP can be solved in time linear in the number of variables. The key is a new kind of consistency called **directed arc consistency (DAC)**. A CSP is defined to be directed arc consistent under an ordering `X[1]`, `X[2]`, ..., `X[n]` if and only if every `X[i]` is consistent with every `X[j]` for `j > i`.

---

## DIRECTED ARC CONSISTENCY

---

![hand](img/00006.jpg)

To solve a tree-structured CSP, first pick any variable as the root of the tree and choose an ordering of variables such that each variable appears after its parent in the tree. This ordering is called a **topological sort**. Figure 6.10(a) shows a sample tree and (b) shows a possible ordering. Every tree with `n` nodes has `n-1` arcs, so we can make the graph directed arc consistent in `O(n)` steps, each step comparing up to `d` domain values for two variables, for a total time of `O(nd²)`. Once we have a directed arc consistent graph, we can simply sweep through the variables in order, choosing any remaining value. Because every arc from parent to child is consistent, we are guaranteed that for any value chosen for the parent, there will be a valid value remaining for the child. This means no backtracking is required; we just pass through the variables linearly. The complete algorithm is given in Figure 6.11.
