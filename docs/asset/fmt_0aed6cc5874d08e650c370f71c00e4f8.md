
# 嵌入式系统还可以利用专门为其设计的射频协议

`Zigbee` 就是一种为个人局域网设计的网络协议示例，此类网络常见于家庭自动化场景。`Zigbee` 和 `Z-wave` 等协议为那些不需要 `Wi-Fi` 和 `Bluetooth` 所提供的带宽及附加功能的设备提供了低功耗、点对点的通信。这意味着它们在通信范围和可传输数据量方面存在限制，并且由于它们是为家庭自动化及类似用途设计的，因此不具备强大的安全模型。作为安全从业者，你应该意识到，使用 `Zigbee` 等协议通信的设备可能会作为楼宇监控或其他用途的一部分被部署，且不太可能具备企业级的管理、监控或安全能力。

`Zigbee` 等射频系统可以是窄带或宽带。窄带无线电系统通常噪声较小，因此具有更好的范围和灵敏度；而宽带无线电因为拥有更多可用的无线频谱，可以传输更多数据。Security+ 考试大纲还提到了基带无线电，这是一种包含接近零频率的信号类型。

## 嵌入式系统的安全约束

嵌入式系统存在许多约束，安全解决方案必须将其纳入考量。由于嵌入式系统可能能力有限、部署和管理选项各异，且生命周期延长，因此保护它们需要投入额外的思考。

当你考虑嵌入式系统的安全性时，应考虑以下因素：

*   嵌入式系统的整体计算能力和容量通常远低于传统 PC 或移动设备。尽管这可能因情况而异，但嵌入式系统可能使用低功耗处理器、拥有较少内存，且存储空间非常有限。这意味着可能不具备加密处理所需的算力，或者必须在 CPU 周期的其他需求之间进行平衡。同时，有限的内存和存储容量意味着可能没有能力运行额外的安全工具，如防火墙、反恶意软件工具，或你习惯在设计中包含的其他安全工具。
*   嵌入式系统可能不连接网络。它们可能完全没有网络连接，或者虽有连接但因环境、运营或安全顾虑而未启用或使用。事实上，由于许多嵌入式系统部署在传统网络之外，或处于连接性可能受限的区域，即使它们具备内置无线网络能力，也可能没有足够的有效范围连接到可用网络。因此，你可能无法远程修补、监控或维护这些设备。嵌入式设备可能需要作为独立单元进行保护。
*   没有网络连接、CPU 和内存容量以及其他要素，身份认证也很可能无法实现。事实上，由于安全或可用性因素，对嵌入式系统进行身份认证可能并不合乎需求。你将遇到的许多使用嵌入式系统的设备内置于工业机械、传感器和监控系统，甚至家用电器中。没有身份认证，就需要确定其他安全模型，以确保对嵌入式系统的更改经过授权。
*   嵌入式系统成本可能很低，但许多实际上成本极高，因为它们是大型工业或专用设备中的一个组件。因此，简单地更换有漏洞的设备可能是不可能的，这要求采取补偿控制或做出特殊的设计决策，以确保设备保持安全，且不会给其所属组织带来问题。

鉴于所有这些限制，嵌入式设备可能依赖隐含信任。它们假定操作员和与其交互的人员之所以这样做是因为他们受信任，并且物理接触设备意味着用户被授权使用并可能更改设置、更新设备或以其他方式修改它。嵌入式设备随物理访问而来的隐含信任模型使其成为组织的潜在漏洞，并且必须在部署前对其进行审查和设计。

## 总结

终端是大多数组织中最常见的设备，也是种类最繁多的。因此，你必须特别关注它们从启动那一刻起是如何被保护的。你可以利用系统固件内置的安全启动技术来保持启动完整性。

作为安全专业人员，你需要了解许多常见的终端安全工具类型，以及何时和如何使用它们。防病毒和反恶意软件工具有助于检测恶意程序和感染。在不同位置（如终端和邮件服务器）使用多种工具，可以帮助检测通过另一种工具防线的恶意代码。允许列表和阻止/拒绝列表也可用于控制终端系统可运行的应用程序和软件。它们需要更多的维护和精力，因为它们要么只允许运行清单内的应用程序，要么完全阻止清单外的程序。`EDR` 工具通过将检测和监控工具与集中报告及事件响应能力相结合，为终端设备的安全防护增加了另一层保护。最后，数据丢失防护（`DLP`）工具被部署用于确保数据不会无意或故意泄露。

终端系统还使用各种网络防御。最常见的是防火墙，基于端口、协议或应用程序控制流量。主机入侵防御系统（`HIPS`）可以阻止进入或离开系统的攻击流量，而主机入侵检测系统（`HIDS`）只能对恶意或不需要的流量发出警报或警示，但无法阻止它。下一代防火墙主要作为网络设备存在，但高级终端防护工具可以具有类似功能，包括行为分析和高级系统保护。

所有这些工具都很有帮助，但系统加固也很重要。加固技术专注于通过禁用不必要或不需要的服务、将安全选项从默认值配置为符合设备风险概况和安全需求的更安全设置，以及进行其他更改来减少终端系统的攻击面。修补和更新系统也有助于保持其安全，拥有完全修补的系统通常是加固过程的一部分。此外，系统配置标准、命名标准、IP 地址方案、加固脚本、程序和流程有助于确保企业中的系统得到适当的清点和保护。

驱动器加密可在驱动器被盗或丢失时保护数据安全。在生命周期结束时，当设备退役或损坏，或介质需要重复使用时，会采用清理程序以确保残留数据不泄露。擦除驱动器和物理销毁都是常见选项。选择与介质及存储在介质或驱动器上的数据所需安全级别相匹配的清理方法至关重要。

常见命令行命令是 Security+ 考试的一部分，你可能会遇到 `tail`、`head`、`cat`、`grep`、`chmod` 和 `logger` 等工具，应了解如何使用它们以及它们的功能。`Bash` 等 Shell、`Python` 等脚本语言和 `PowerShell` 等环境也是安全从业者的关键知识。安全 Shell（`SSH`）和 `SSL/TLS` 及其在远程访问和保护传输中数据方面的用途，也是安全专业人员工具箱的一部分。

## 端点安全：专用系统与嵌入式系统

端点安全的最后一个组成部分是组织如何保护专用系统和嵌入式系统。物联网、SCADA、ICS 及其他设备无处不在，广泛分布于组织的医疗系统、智能电表、车辆、工业流程与制造设备、无人机、智能设备以及许多其他场所。鉴于这些设备通常能力有限、采用不同的安全模型，且拥有许多其他特殊需求，保护嵌入式系统需要额外的关注和规划，以确保其保持安全状态。

## 考试要点

**系统加固与保护依赖安全工具和技术来维持系统安全。** 保护端点设备需要考虑设备的方方面面：其启动方式、数据如何保护、如何配置、提供何种服务、通信是否安全，以及如何防御网络威胁。幸运的是，安全专业人员拥有大量工具，包括安全启动和可信启动，可用于防范针对启动过程或驱动程序的攻击。`Antivirus`（防病毒）、`antimalware`（反恶意软件）、`sandboxes`（沙箱）、`allow lists`（允许列表）和 `deny lists`（拒绝列表）可控制在端点上运行的应用程序和程序。`Endpoint detection and response`（端点检测与响应）和 `data loss prevention`（数据丢失防护）工具等，能深入洞察系统活动及潜在问题所在，同时增加管理员和安全专业人员可用的控制手段，以保障系统和数据安全。`host intrusion prevention and detection systems`（主机入侵防御与检测系统）、`host firewalls`（主机防火墙）等网络安全工具能检测并通常能阻止来自网络的攻击。

**端点加固还依赖配置、设置、策略和标准来确保系统安全。** 虽然工具和技术对保护端点很重要，但配置和设置也是该过程的重要组成部分。禁用不必要的服务、更改 `Windows registry`（Windows 注册表）中的设置或 `Linux` 中的操作系统设置，以及以其他方式使用内置配置选项，使安全配置与设备的风险概况相匹配，至关重要。组织还使用命名和 `IP` 寻址标准来管理、追踪和控制其环境中的端点。最后，对操作系统和设备上安装的应用程序进行 `patch management`（补丁管理），可防范已知漏洞和问题。

**驱动器加密和清理有助于防止数据泄露。** 加密驱动器和介质有助于在它们被盗或丢失时保持其安全。`Full-disk encryption`（全盘加密）覆盖整个驱动器，而 `volume`（卷）或 `file encryption`（文件加密）则保护内容的特定部分。对驱动器和介质进行清理涉及使用安全删除流程擦除它们，或将其销毁，以确保数据无法恢复。根据数据的安全要求以及所涉及的驱动器或介质类型使用适当的流程，对于确保数据被妥善移除至关重要。

**安全分析师需要熟悉命令行工具、Shell 和安全传输协议。** `Security+` 考生需要了解命令行工具的基础知识，包括 `head`、`tail`、`cat` 和 `grep`，这些工具允许你操作和查看文本文件。使用 `chmod` 管理权限以及通过 `logger` 向日志文件添加信息，也是安全专业人员需要熟悉的任务。除了这些工具，同样重要的是通过 `SSH` 使用安全 Shell、使用 `OpenSSL` 保护传输中的数据，以及了解 `Python` 和 `PowerShell` 等脚本语言，以及何时以及为何可能会使用它们。

**SCADA、ICS 和 IoT 系统等专用系统遍布整个组织，需要独特的安全解决方案。** `SCADA` 和 `ICS`（工业控制系统）用于管理和监控工厂、发电厂以及现代企业的许多其他主要组件。`IoT`（物联网）系统是连接互联网的设备，执行从监控到家庭自动化等各种任务。它们可能由第三方控制，或具有其他安全隐患，必须将其作为安全计划的一部分加以解决，以保持每个端点的安全。

**嵌入式系统具有独特的安全约束。** 嵌入式系统通常比传统系统拥有更少的计算能力、内存和存储。有限的资源意味着嵌入式系统可能没有资源提供加密、防病毒或其他安全功能，并且可能无法记录数据。某些嵌入式系统没有网络连接，或者它们可能使用专用通信协议进行通信，这使得远程修补和管理变得困难。嵌入式系统使用的操作系统和软件通常不具备桌面或移动操作系统的相同功能，并且可能缺乏身份验证能力或传统系统中预期的其他关键功能。

# 第 12 章 网络安全

网络是组织的核心，负责传输数据并支持我们赖以开展业务的服务。这使它们成为攻击者的主要目标，也是防御架构和设计中的关键层。

在本章中，您将了解安全网络设计中的重要概念和要素，例如基于风险和安全要求的网络分段和区域划分。您还将探索保护措施，如端口安全、端口跨越和镜像以进行数据收集，以及如何使用 VPN 保护网络流量，即使在遍历不受信任的网络时也是如此。

接下来，您将了解网络设备和安全设备。跳板机/跳板服务器、负载均衡器及其调度技术和功能模型、代理服务器、URL 和内容过滤器，以及各种其他网络安全工具和选项构成了本章的中间部分。

了解了设备和设计概念后，您将继续学习如何在管理层面上管理和保护网络，包括带外管理技术、访问控制列表和服务质量选项。您还将了解路由安全问题对安全专业人员和网络管理员的意义。随后，您将探索 DNS 安全、传输层安全的作用及其利用临时密钥实现完美前向保密的机制，以及监控在网络安全中的作用。最后，您将研究欺骗和中断策略，这些策略可以帮助您了解攻击者将在您的网络中尝试什么，以及当他们捕获并试图提取数据时如何检测他们。

在了解了管理工具之后，您将继续探索安全协议及其用途，包括用于实时流媒体、安全邮件和 Shell 访问的协议，以及各种其他选项。您将学习如何根据其服务端口和协议识别安全协议，它们能做什么和不能做什么，以及它们在现代网络中如何被频繁使用。

一旦涵盖了工具和技术，您将回顾常见的网络攻击，如中间人攻击、DNS 攻击、第 2 层攻击、分布式拒绝服务 (DDoS) 攻击和运营技术 DDoS 攻击，以及如何检测并有时阻止它们。

本章的最后一部分将向您介绍各种用于网络侦察和发现的重要工具，以及利用这些工具的技术。您将探索如何追踪数据包路由、收集有关系统和设备及其网络配置和流量模式的信息、扫描服务和漏洞、传输数据、收集开源情报，以及捕获和分析数据包和网络流量。

## 设计安全网络

作为安全专业人员，您必须理解并能够实施企业网络中关键的设计和架构要素，以便妥善保护它们。您需要知道部署了哪些工具和系统以及原因，还要知道如何将它们作为分层安全设计的一部分进行部署。
