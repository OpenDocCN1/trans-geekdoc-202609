
# 隧道技术

隧道技术常用于实现原本不连通的系统之间的通信。如果两个系统因缺乏网络连接而分离，可以通过调制解调器拨号链路或其他远程访问或广域网（`WAN`）网络服务建立通信链路。实际的 `LAN` 流量被封装在临时连接所使用的任何通信协议中，例如调制解调器拨号情况下的点对点协议。如果两个网络由采用不同协议的网络连接，分离网络的协议通常可以封装在中间网络的协议内以提供通信路径。

无论实际情况如何，隧道技术通过将内部协议和流量数据包置入（或包裹在）中间网络或连接所使用的授权协议中来保护其内容。如果主协议不可路由，或者为了将网络上支持的协议总数保持在最低限度，可以使用隧道技术。

如果封装协议的行为涉及加密，隧道技术可以提供一种手段，在不担心丢失机密性和完整性的情况下，跨不受信任的中间网络传输敏感数据。

隧道技术并非没有问题。它通常是一种低效的通信方式，因为大多数协议都包含自己的错误检测、错误处理、确认和会话管理功能，因此同时使用多个协议会增加传输单条消息所需的开销。此外，隧道技术会产生更大的数据包或额外的数据包，从而消耗额外的网络带宽。如果带宽不足，隧道技术会迅速使网络饱和。另外，隧道技术是一种点对点通信机制，并非设计用于处理广播流量。在某些情况下，隧道技术也使得监控流量内容变得困难，甚至不可能，给安全从业者带来了问题。

## VPN 如何工作

`VPN` 链路可以在任何其他网络通信连接上建立。这可以是典型的 `LAN` 电缆连接、无线 `LAN` 连接、远程访问拨号连接、`WAN` 链路，甚至是客户端使用互联网连接访问办公室 `LAN`。`VPN` 链路的表现就像典型的直接 `LAN` 电缆连接；唯一可能的区别在于基于中间网络以及客户端系统与服务器系统之间的连接类型的速度差异。通过 `VPN` 链路，客户端可以执行相同的活动并访问相同的资源，就像直接通过 `LAN` 电缆连接一样。

`VPN` 可以连接两个独立系统或两个完整网络。唯一的区别在于，传输的数据仅在 `VPN` 隧道内受到保护。网络边界上的远程访问服务器或防火墙充当 `VPN` 的起点和终点。因此，流量在源 `LAN` 内不受保护，在边界 `VPN` 服务器之间受保护，到达目标 `LAN` 后再次变为不受保护。

用于连接远程网络的通过互联网的 `VPN` 链路通常是专线或租用线路的低成本替代方案。两条连接到本地 `ISP` 的高速互联网链路以支持 `VPN` 的成本，通常远低于任何其他可用连接方式的成本。

## 常见 VPN 协议

VPN 可以使用软件或硬件解决方案来实现。无论哪种情况，都有四种常见的 VPN 协议：`PPTP`、`L2F`、`L2TP` 和 `IPsec`。`PPTP`、`L2F` 和 `L2TP` 在 OSI 模型的数据链路层（第 2 层）运行。`PPTP` 和 `IPsec` 仅限于在 IP 网络上使用，而 `L2F` 和 `L2TP` 可用于封装任何 LAN 协议。

### 点对点隧道协议

**点对点隧道协议 (PPTP)** 是一种从拨号点对点协议开发而来的封装协议。它在 OSI 模型的数据链路层（第 2 层）运行，并用于 IP 网络。`PPTP` 在两个系统之间创建点对点隧道并封装 `PPP` 数据包。它通过 `PPP` 支持的相同认证协议为认证流量提供保护：

*   Microsoft 质询握手认证协议 (`MS-CHAP`)
*   质询握手认证协议 (`CHAP`)
*   密码认证协议 (`PAP`)
*   可扩展认证协议 (`EAP`)
*   Shiva 密码认证协议 (`SPAP`)

`PPTP` 使用的初始隧道协商过程未加密。因此，包含发送方和接收方 IP 地址的会话建立数据包——可能还包括用户名和哈希密码——可能会被第三方拦截。`PPTP` 用于 VPN，但通常会被 `L2TP` 取代，后者可以使用 `IPsec` 为 VPN 提供流量加密。大多数现代 `PPTP` 用法都采用了 Microsoft 定制实现，该实现支持使用 Microsoft 点对点加密 (`MPPE`) 进行数据加密，并支持各种安全认证选项。

`PPTP` 不支持 `TACACS+` 和 `RADIUS`。

### 第 2 层转发协议和第 2 层隧道协议

Cisco 开发了自己的 VPN 协议，称为第 2 层转发 (`L2F`)，这是一种相互认证隧道机制。然而，`L2F` 不提供加密。`L2F` 未被广泛部署，很快就被 `L2TP` 取代了。顾名思义，两者都在第 2 层运行。两者都可以封装任何 LAN 协议。

**第 2 层隧道协议 (L2TP)** 是通过结合 `PPTP` 和 `L2F` 的元素而衍生出来的。`L2TP` 在通信端点之间创建点对点隧道。它缺乏内置加密方案，但通常依赖 `IPsec` 作为其安全机制。`L2TP` 还支持 `TACACS+` 和 `RADIUS`。`IPsec` 通常用作 `L2TP` 的安全机制。

### IP 安全协议

目前最常用的 VPN 协议是 `IPsec`。**IP 安全 (IPsec)** 既是一种独立的 VPN 协议，也是 `L2TP` 的安全机制，并且只能用于 IP 流量。`IPsec` 由 `IPv6` 的安全元素组成，被打包成 `IPv4` 的附加包。`IPsec` 仅在 IP 网络上工作，并提供安全认证以及加密数据传输。`IPsec` 有两个主要组件或功能：

#### 认证头 (AH)

`AH` 提供认证、完整性和不可抵赖性。

#### 封装安全载荷 (ESP)

`ESP` 提供加密以保护传输数据的机密性，但也可以执行有限的认证。它在网络层（第 3 层）运行，可用于传输模式或隧道模式。在传输模式下，IP 数据包的数据被加密，但数据包的头部不被加密。在隧道模式下，整个 IP 数据包被加密，并向数据包添加新头部以控制通过隧道的传输。

# 虚拟局域网

**虚拟局域网 (VLAN)** 是由交换机创建的硬件强制网络分段。默认情况下，交换机上的所有端口都属于 `VLAN 1`。但随着交换机管理员逐端口更改 `VLAN` 分配，各个端口可以被分组在一起，并与其他 `VLAN` 端口指定区分开。`VLAN` 也可以基于设备 `MAC` 地址分配或创建，镜像 IP 子网划分，围绕指定协议，或基于认证。`VLAN` 管理最常用于区分用户流量和管理流量。而 `VLAN 1` 通常被指定为管理流量 `VLAN`。

`VLAN` 用于流量管理。同一 `VLAN` 成员之间的通信无障碍进行，但 `VLAN` 之间的通信需要路由功能，该功能可由外部路由器或交换机的内部软件提供（这是 **L3 交换机** 和 **多层交换机** 术语出现的原因之一）。`VLAN` 被视为子网，但不是子网。`VLAN` 由交换机创建。子网由 IP 地址和子网掩码分配创建。

**VLAN 管理** 是利用 `VLAN` 出于安全或性能原因控制流量。`VLAN` 可用于隔离网络段之间的流量。这可以通过不定义不同 `VLAN` 之间的路由，或通过在特定 `VLAN` 之间（或 `VLAN` 的特定成员之间）指定拒绝过滤器来实现。任何不需要与另一个网段通信以完成工作任务/功能的网段都不应能够这样做。使用 `VLAN` 允许必要的内容，并阻止/拒绝任何不必要的内容。请记住，“默认拒绝；例外允许”不仅是防火墙规则的指导原则，也是安全的一般原则。

`VLAN` 的运作方式与传统子网非常相似。为了使通信从一个 `VLAN` 传输到另一个 `VLAN`，交换机执行路由功能以控制和过滤其 `VLAN` 之间的流量。

`VLAN` 用于在不改变物理拓扑的情况下对网络进行逻辑分段。它们易于实施，管理开销小，且是基于硬件的解决方案（具体来说是第 3 层交换机）。随着网络在虚拟环境或云中构建，通常会使用软件交换机。在这些情况下，`VLAN` 不是基于硬件的，而是基于交换机软件的实现。

`VLAN` 让你能够控制和限制广播流量，并降低网络对嗅探器的脆弱性，因为交换机将每个 `VLAN` 视为一个单独的网络分区。要在段之间通信，交换机必须提供路由功能。正是路由功能阻止了子网和 `VLAN` 之间的广播，因为路由器（或任何执行第 3 层路由功能的设备，如第 3 层交换机）不会转发第 2 层以太网广播。交换机的这一特性阻止了 `VLAN` 之间的以太网广播，从而有助于防止广播风暴。**广播风暴** 是不需要的以太网广播网络流量的洪流。

## VLAN 部署中的端口隔离

VLAN 部署的另一个要素是端口隔离或私有端口。这些是配置为使用专用或保留上行端口的私有 VLAN。私有 VLAN 或端口隔离 VLAN 的成员只能相互交互，并通过预定的出口端口或上行端口进行通信。端口隔离的常见实现场景出现在酒店中。酒店网络可配置为使每个房间或套房中的以太网端口在唯一的 VLAN 上隔离，以便同一单元内的连接可以通信，但单元之间的连接无法通信。然而，所有这些私有 VLAN 都有一条通往互联网的路径（即上行端口）。

# 虚拟化

**虚拟化** 技术用于在单台主机计算机的内存中托管一个或多个操作系统。此机制允许几乎任何操作系统在任何硬件上运行。这种操作系统也称为客户操作系统。从直接安装在计算机硬件上存在原始或主机操作系统的角度来看，由管理程序系统托管的额外操作系统是客户机。它还允许多个操作系统在同一硬件上同时工作。常见示例包括 `VMware/vSphere`、`Microsoft Hyper-V`、`VirtualBox`、`XenServer` 和 `Apple Parallels`。

从用户角度来看，虚拟化服务器和服务与传统服务器和服务无法区分。

虚拟化有几个优势，例如能够根据需要启动单个服务器或服务实例、实时可扩展性，以及能够运行所需应用程序所需的确切操作系统版本。此外，从损坏、崩溃或损坏的虚拟系统中恢复通常很快：只需将虚拟系统的主硬盘文件替换为干净的备份版本，然后重新启动它即可。

在安全方面，虚拟化提供了几个优势。与同等的原生硬件安装系统相比，备份整个虚拟系统通常更容易、更快。此外，当发生错误或问题时，虚拟系统可在几分钟内通过备份替换。恶意代码对虚拟系统的入侵或感染很少影响主机操作系统。这允许进行安全的测试和实验。

**VM 逃逸** 是指客户操作系统中的软件能够突破管理程序提供的隔离保护，从而侵犯其他客户操作系统的容器或渗透主机操作系统。近期已发现多个逃逸漏洞。幸运的是，供应商迅速发布了补丁。例如，虚拟化环境被忽视的操作操纵 (`VENOM`) 能够突破采用受损开源虚拟软盘驱动程序的众多 VM 产品，允许恶意代码在 VM 之间跳转，甚至访问主机。

VM 逃逸可能是一个严重问题，但可以采取措施将风险降至最低。首先，将高度敏感的系统和数据保留在单独的物理机器上。组织本应关注过度整合导致的单点故障，因此运行多台硬件服务器，使每台仅支持少量客户操作系统，有助于降低此风险。保持足够的物理服务器以维持高度敏感客户操作系统之间的物理隔离，将进一步防范 VM 逃逸。其次，保持所有管理程序软件为供应商发布的最新补丁（特别是与 VM 逃逸漏洞相关的更新）。第三，监控攻击、暴露和滥用指数，以发现针对您环境的新威胁。

虚拟化用于各种新架构和系统设计解决方案。云计算终究是一种虚拟化形式（有关云计算的更多信息，请参见第 9 章“安全漏洞、威胁和对策”）。在本地（或至少在组织的私有基础设施内），虚拟化可用于托管服务器、客户操作系统、受限用户界面（即虚拟桌面）、应用程序等。

## 虚拟软件

**虚拟应用程序** 是以一种方式部署的软件产品，使其误以为正在与完整的主机操作系统交互。虚拟（或虚拟化）应用程序已打包或封装，使其具有可移植性，并能在无需完全安装其原始主机操作系统的情况下运行。虚拟应用程序在其封装气泡（技术上称为虚拟机，或 `VM`）中包含了足够的原始主机操作系统组件，使其运行/功能如同传统安装一般。某些形式的虚拟应用程序用作 USB 驱动器上的便携式应用（应用程序的简称）。其他虚拟应用程序设计为在替代主机操作系统平台上执行——例如，在 `Linux` 操作系统中运行 `Windows` 应用程序。

术语**虚拟桌面** 指至少三种不同类型的技术：

*   一种远程访问工具，通过允许远程查看和控制远程桌面的显示器、键盘、鼠标等，授予用户访问远程计算机系统的权限。
*   虚拟应用程序概念的延伸，封装多个应用程序和某种形式的“桌面”或 Shell，以实现可移植性或跨操作系统操作。此技术将一个平台的某些功能/优势/应用程序提供给另一个平台的用户，而无需多台计算机、双重启动或虚拟化整个操作系统平台。
*   一种比所用显示器更大的扩展或扩充桌面，允许用户采用多种应用程序布局，使用按键或鼠标移动在它们之间切换。

有关虚拟化作为安全架构和设计一部分的更多信息，请参见第 8 章“安全模型、设计和能力原则”和第 9 章“安全漏洞、威胁和对策”。

## 虚拟网络

操作系统虚拟化的概念催生了其他虚拟化主题，例如虚拟化网络。虚拟化网络或**网络虚拟化** 是将硬件和软件网络组件组合成单个集成实体。生成的系统允许通过软件控制所有网络功能：管理、流量整形、地址分配等。单个管理控制台或界面可用于监督网络的各个方面，而过去这项任务需要亲临每个硬件组件现场。虚拟化网络已成为全球企业进行基础设施部署和管理的流行手段。它们允许组织实施或调整其他有趣的网络解决方案，包括软件定义网络、虚拟 SAN、客户操作系统和端口隔离。

**软件定义网络 (`SDN`)** 是一种独特的网络操作、设计和管理方法。该概念基于这样一种理论：具有设备上配置（即路由器和交换机）的传统网络的复杂性，往往迫使组织坚持使用单一设备供应商（如 `Cisco`），并限制网络适应不断变化的物理和业务条件的灵活性。`SDN` 旨在将基础设施层（即硬件和基于硬件的设置）与控制层（即数据传输管理的网络服务）分离。此外，这还消除了传统网络概念（如 `IP` 寻址、子网、路由等）被编程到托管应用程序中或需要由其解读的必要性。

# SDN

SDN 提供了一种新的网络设计，该设计可从中心位置直接编程，具有灵活性、供应商中立性，并基于开放标准。使用 SDN 使组织无需从单一供应商处采购设备。相反，它允许组织根据需要混合搭配硬件，例如选择最具成本效益或吞吐量评级最高的设备，而不受供应商限制。然后通过集中式管理界面控制硬件的配置和管理。此外，应用于硬件的设置可根据需要动态更改和调整。

## 静态和动态 NAT

NAT 可在两种模式下使用：静态和动态。

### 静态 NAT

当特定内部客户端的 IP 地址被分配了到特定外部公共 IP 地址的永久映射时，请使用静态模式 NAT。即使您正在使用 `RFC 1918` IP 地址，这也允许外部实体与您网络内的系统进行通信。

### 动态 NAT

使用动态模式 NAT 可授予多个内部客户端访问少量租用公共 IP 地址的权限。因此，大型内部网络无需租用大量公共 IP 地址块即可访问互联网。这将公共 IP 地址使用滥用降至最低，并有助于将互联网接入成本保持在最低水平。

在动态模式 NAT 实现中，NAT 系统维护一个映射数据库，以便将来自互联网服务的所有响应流量正确路由到最初发起请求的内部客户端。NAT 通常与代理服务器或代理防火墙结合使用，以提供额外的互联网接入和内容缓存功能。

NAT 与 IPsec 不直接兼容，因为它会修改数据包头部，而 IPsec 依赖数据包头部来防止安全违规。但是，存在专门设计用于支持 IPsec over NAT 的 NAT 代理版本。具体而言，`NAT-Traversal` (`RFC 3947`) 旨在通过 UDP 封装 IKE 来支持 IPsec VPN。IP 安全 (IPsec) 是一种基于标准的机制，用于为点对点 TCP/IP 流量提供加密。

# 自动专用 IP 寻址

`自动专用 IP 寻址 (APIPA)`，又称链路本地地址分配（定义于 `RFC 3927`），在动态主机配置协议 (DHCP) 分配失败时为系统分配 IP 地址。APIPA 主要是 Windows 的一项功能。APIPA 为每个失败的 DHCP 客户端分配 `169.254.0.1` 到 `169.254.255.254` 范围内的 IP 地址，以及默认的 B 类子网掩码 `255.255.0.0`。这允许系统与同一广播域内的其他 APIPA 配置客户端通信，但无法跨路由器与任何系统或正确分配了 IP 地址的系统通信。

# APIPA

APIPA 通常不直接涉及安全问题。然而，它仍然是一个需要理解的重要问题。如果你发现某个系统被分配了 APIPA 地址而不是有效的网络地址，这表明存在问题。这可能只是像坏线缆或 DHCP 服务器断电这样平常的原因，但也可能是 DHCP 服务器遭受恶意攻击的症状。你可能会被要求在给出 IP 地址的场景中判断问题。你应该能够辨别某个地址是公网地址、`RFC 1918` 私有地址、APIPA 地址还是环回地址。
