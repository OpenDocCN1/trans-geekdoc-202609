
根据员工在网络安全风险管理计划中的角色，XYZ 信息安全政策中描述了向内部员工传达网络安全信息的方式，该政策在公司内网上对所有员工开放。此外，员工手册根据员工在组织内的角色，明确了特定的信息安全责任和实践。在受雇时，所有员工必须签署确认书，确认接受并遵守公司政策。

在受雇时以及此后每年，所有员工必须成功完成涵盖基本信息安全实践的课程，这些实践支持有效的网络安全风险管理计划的运作。培训课程旨在帮助员工识别和应对社会工程攻击（如钓鱼、尾随进入）以及避免不当的安全实践（例如，写下密码或无人看管敏感材料）。XYZ 定期通过尝试尾随进入建筑物、发送模拟钓鱼电子邮件和进行桌面检查等策略，评估员工对公司政策的意识水平。如果发现员工违反公司政策，将提供额外培训或采取其他纪律行动。

工作职责直接属于网络安全风险管理计划范围内的员工（如 IT 人员、IT 管理层、内部审计等）需要在整个年内完成额外的技术和岗位特定培训。此外，那些直接访问客户和员工数据的员工（例如，销售、客户服务、人力资源、IT 服务台和财务部门）将接受关于事件管理、信息处理和数据保护的专门培训。

与员工网络安全意识相关的培训和其他计划，结合了 XYZ 与行业及网络安全相关供应商或合作伙伴内部开发的材料。这些供应商或合作伙伴提供专业知识和工具，用于开发、执行、跟踪和测试员工对网络安全意识政策和标准的合规性。

XYZ 已建立一个网络安全意识计划（CAP），定期向所有员工分发信息安全实践提醒，并发送内部通讯以促进安全意识并提供最新的安全新闻。CAP 还负责：
- (a) 监测与访问实体系统的供应商和商务伙伴相关的网络安全风险；
- (b) 监测论坛和新闻网站，获取有关潜在数据泄露的信息；
- (c) 每年审查供应商和商务伙伴的网络安全审计报告；以及
- (d) 与供应商和商务伙伴保持持续的直接联系，以解决已识别的任何问题。

每年，XYZ 更新网络安全培训计划和 CAP，以纳入威胁态势的变化以及威胁行为者正在实施的新策略。XYZ 还评估从以前事件中吸取的经验教训，并根据需要将这些变化纳入计划中。

公司为所有员工提供事件热线，用于报告他们参与或目睹的信息安全事件（如钓鱼攻击、恶意软件、丢失或被盗设备以及不当的信息披露）。XYZ 每季度从外包呼叫中心获得保证，确认所有热线人员已完成 XYZ 的 CAP，并知晓与信息保护、数据处理和事件响应相关的既定政策。

首席信息安全官（CISO）向董事会提交季度更新，报告实体网络安全风险管理计划的状态。在更新期间，CISO 报告针对以下事项的开发和维护计划的努力状态：
- (a) 组织以前的安全事件，
- (b) XYZ 运营程序的变化，
- (c) 影响组织的法律和监管要求的变化，
- (d) 内部和外部方审计和测试的结果，以及
- (e) 组织面临的新兴和出现的网络安全风险。

### DC14：与外部各方沟通影响实体网络安全风险管理计划运作事项的流程

XYZ 有一项披露政策，定义了何时、由谁以及在何种程度上向外部各方通报与 XYZ 网络安全风险管理计划运作相关的事项。所有对外的披露均按照州和联邦层面的适用法律和法规执行。在年度审查期间，在制定和维护披露政策时，会考虑任何此类法律要求。员工通过 XYZ 信息安全政策和 XYZ 员工手册接受关于报告和披露网络安全事件或事件的策略和程序的教育。

XYZ 可能会通过其现有的监测流程，以及第三方或执法部门的通报，获知影响实体网络安全风险管理计划运作的事项。当出现此类事项时，XYZ 风险治理委员会会立即审查其相关性和适用性。在必要或适当的情况下，该事项可能被视为安全事件，并通过 XYZ 的安全事件响应流程进行处理，如后文所述。

正如大多数组织的典型商业做法一样，XYZ 限制与 XYZ 网络安全计划运作相关的事项沟通，仅向需要了解此类信息的利益相关者和商务伙伴进行。此类信息可通过适合信息性质和情况紧迫性的媒介进行传达，可能包括会议电话、电子邮件、备忘录或面对面会议。在极少数情况下，如果此类事项的公开披露是必要或适当的，XYZ 的法律顾问和企业通讯代表负责联合分发和传达此类披露。

### 网络安全风险管理计划的监测

#### DC15：对与网络安全相关的内部控制关键控制活动和其他组件的运作有效性进行持续和定期评估的流程

XYZ 使用几种机制来评估旨在降低网络安全风险的内部控制的持续有效性。该计划的评估和监测设计旨在满足 NIST 网络安全框架和 ISO 27001 的要求。

内部审计定期进行网络安全评估和内部控制测试，包括：
- (a) 与流程所有者和 IT 支持人员合作，识别具体的安全威胁和漏洞，以及相关的风险是如何被处理的；以及
- (b) 测试解决网络安全风险的内部控制的设计、实施和运作有效性。

内部审计团队成员具备必要的网络安全风险和控制方面的知识和经验。

XYZ 还使用外部方独立评估网络安全风险管理计划的状态。外部服务提供商每季度进行漏洞评估，每年进行渗透测试，以识别具体的技术威胁和漏洞，并参照领先的网络安全实践对环境进行基准测试。此外，该实体还会为其 SaaS 供应商获取年度 Web 应用安全评估报告。每两年，XYZ 聘请服务提供商对网络安全风险管理计划进行独立评估，以评估其与行业领先实践的对齐程度以及与公司政策的一致性，从而识别差距和改进的潜在机会。

内部和外部评估均采用基于风险的方法，可能会改变测试的性质、时间和范围。此类评估的标准（包括此类评估的性质和频率）在年度风险评估期间进行审查，并根据需要修改，同时考虑 XYZ 运营流程的变化，包括业务规模、范围和运营性质的变化、最近的安全威胁或事件、新兴或出现的风险以及行业标准的变化。

#### DC16：用于及时评估和沟通已识别的安全威胁、漏洞和控制缺陷的流程，以通知负责采取纠正措施的相关方（包括管理层和董事会，视情况而定）

每季度，信息安全团队执行风险评估更新，识别组织内部和外部网络威胁和漏洞的变化。结果由风险治理委员会评估，以确定是否需要新的保护措施或增强的信息安全政策和程序。风险治理委员会还负责监测漏洞、分配资源以解决它们，并在必要时重新确定补救措施的优先级。还定义并监测与平均关闭时间相关的关键绩效指标，委员会每月对此进行监测。

无论来源如何，所有监测活动的结果都会录入漏洞跟踪系统中，以评估并识别可能需要采取的补救活动。识别出的漏洞将根据被利用的可能性和影响程度进行评估。所有评估的漏洞都需确定是进行补救还是进行额外监测。纠正措施计划的责任被分配，并确定完成日期。信息安全委员会每月审查未解决漏洞列表，以监控解决进度并识别趋势和应对措施。每季度，风险治理委员会和高管层接收漏洞管理活动的汇总报告。

此外，CISO（首席信息安全官）在每次定期会议上向董事会汇报网络安全风险管理计划的结果，其中包括漏洞管理活动。

### 网络安全控制活动

#### DC17：制定针对已评估风险响应的流程，包括控制流程的设计与实施

XYZ 设立了一个风险治理委员会，以协调实体及其各部门的风险评估和管理工作。该委员会由 CRO（首席风险官）主持，成员包括 CISO、CCO（首席合规官）、外部专家以及 IT 和业务线人员。该委员会确保对风险进行评估，并设计、实施和运行控制措施，以适当的方式检测、响应、缓解和从安全事件中恢复，从而应对所有领域的风险。评估的领域包括系统开发、计算机操作、程序变更以及对程序和数据访问。已实施的控制措施包括预防性和检测性控制，如根据实体运营环境、业务的性质和范围及其特定特征而采用的手动、自动化或依赖 IT 的控制。

业务流程记录在标准操作手册中；然而，风险治理委员会也在每个业务领域设有业务运营联络人，他们负责业务运营关键风险领域的所有权和文档记录。2014 年，风险治理委员会增强了其对各业务领域主要风险的考量，其中包括对网络安全风险的具体考量。

风险治理委员会的业务联络人每年重新审视风险评估，并验证是否存在缓解已识别风险的控制措施。这些控制措施记录在公司的控制库（CR）中，该库是每个业务领域相关的操作、风险和控制措施的清单。CR 用于进行季度性的控制自我评估，并作为公司年度控制成熟度评估的输入之一，该评估由内部审计部门执行，并向风险治理委员会报告。

公司针对无法通过其他技术以有效成本缓解的风险，签约购买保险保障，包括业务中断险。

#### DC18：实体 IT 基础设施及其网络架构特征的概述

XYZ 采用内部托管和基于云的应用程序来支持其制造、零售和批发业务。基于云的应用程序通过 XYZ 与 ABC Cloud 达成的服务协议提供，根据该协议，XYZ 保留对特定服务器配置和操作系统变更管理的责任，而 ABC Cloud 提供服务器支持和维护。公司应用程序主要运行在 Unix 系列操作系统上，并使用行业标准数据库管理系统。制造系统使用由一家主要 IT 制造商提供的专有中型操作系统。该应用程序是使用集成操作系统数据库在内部开发的。现场销售应用平板电脑使用行业标准操作系统。

XYZ 使用思科 ASA 防火墙将其 ERP 财务报告系统与其面向外部的零售、批发和呼叫中心接口进行隔离，这些防火墙由 XYZ IT 人员配置、管理和支持。防火墙配置和规则遵循 XYZ IT 管理层在 CISO 指导下制定的标准。所有与外部用户的连接均通过由冗余防火墙复合体保护的预定义访问点进行。防火墙还用于对公司内部网络进行分段。

批发呼叫中心服务被外包，呼叫中心的系统与 ERP 系统集成，以促进订单处理和问题解决。呼叫中心接口通过虚拟网络连接实现。使用客户自开发的软件将呼叫中心系统接口连接到 ERP 接口。

XYZ 通过其预定义的供应商和商业伙伴监督计划，每年对呼叫中心服务提供商的设施进行审核。这些供应商和商业伙伴评估重点在于托管应用的安全配置特定领域，以及与 XYZ 供应商接口的网络架构相关的领域。

ABC Cloud 的 SaaS 也通过 XYZ 的供应商和商业伙伴监督计划每年进行审核；然而，鉴于云协议中定义的责任性质，XYZ 根据其企业标准配置其服务器设置。XYZ 已为基于云的服务器配置定义了标准构建，并以其作为基准来配置支持 SaaS 环境的服务器。此外，XYZ IT 支持人员以及公司内部审计和风险管理团队会监控配置对定义标准的遵守和合规情况。

现场销售自动化通过运行经公司定制化的第三方软件的公司自有平板电脑设备提供。平板电脑通过基于蜂窝的 VPN 系统访问 ERP 系统，该系统使用双因素、基于令牌的认证。

#### DC19：实施和运行以应对实体网络安全风险的关键安全政策和流程，包括针对以下方面：

- a. 防止有意和无意的安全事件
- b. 检测安全事件、识别安全事件（事故）、制定针对这些事件的响应，以及实施缓解和恢复已识别安全事件的活动
- c. 管理处理能力，以在安全、操作和环境事件期间提供持续运营
- d. 检测、缓解和从环境事件中恢复，以及使用备份程序支持系统可用性
- e. 在接收或创建机密信息时对其进行识别，确定该信息的保留期限，在指定期限内保留该信息，并在保留期结束时销毁该信息

XYZ 制定了一套信息安全标准和政策，在 CIO（首席信息官）的指导和管理下实施，并通过 CISO 推行。这些标准和政策涵盖了从设施和设备的物理安全到数据元素层逻辑安全的控制措施的管理和实施。信息安全政策和标准旨在为员工、承包商和供应商提供与其工作或职能职责相符的信息，同时考虑到职能分离，以避免可能产生的职责分离冲突。

安全政策发布在公司内网上，包含在入职资料包中，并通过所有员工必须参加并确认知晓的年度培训进行重申。与供应商和商业伙伴关系相关的安全政策通过合同承诺和相关服务协议（SLA）执行，并尽可能通过 XYZ 的供应商和商业伙伴监督计划监控其执行情况。

XYZ 信息安全政策的关键组件在以下段落中讨论。

**防止有意和无意的安全事件。** 公司制定了以下流程以防止有意和无意的安全事件：
- 1. **物理和逻辑访问的开通、取消及转移（包括远程访问）。** XYZ 员工仅在完成安全意识培训后才会被授予网络访问权限。用户根据其职位角色被授予对 XYZ 系统和数据的访问权限。在授予访问权限之前，访问请求需由用户的管理员批准。离职时，人力资源部通过工单系统发送通知，该工单路由至用户管理团队，以移除离职用户的账户访问权限。人力资源部提供每周的离职名单，然后将其与用户账户列表进行交叉核对，以识别任何未正确终止的用户账户。闲置 60 天的用户账户会自动禁用。对于访问权限修改，用户的管理员必须通过工单系统提交并批准访问请求工单，该工单随后路由至用户管理团队进行处理。
- 2. **认证。** 用户在授予网络访问权限之前，必须使用唯一的用户 ID 和密码进行身份验证。网络域密码策略配置包括密码最小长度、过期间隔、复杂性、历史记录以及无效密码账户锁定阈值。新用户的账户密码设置为预先过期，以便用户首次登录网络时必须重置密码。
- 3. **凭证管理。** 访问权限基于提供职责分离并限制事务访问权限的角色安全配置文件授予。XYZ 应用程序和数据所有者每半年审查一次访问权限。每年必须审查角色及分配给角色的事务。
- 4. **特权用户管理。** 特权用户或超级用户账户的访问权限由管理层授权。拥有特权用户账户的用户被提供一个标准（非特权）用户账户，用于日常使用（如电子邮件和个人生产力软件），并且仅在执行管理任务时才允许使用其超级用户账户。所有超级用户账户访问均被记录并监控。每季度，用户管理团队对特权访问进行一次访问审查。

### 226 关于实体网络安全风险管理计划和控制的报告

#### 数据库安全

数据库管理员是访问 XYZ 数据库的唯一人员。所有数据库访问和活动均被记录日志。数据库账户访问权限每半年审查一次，以确认其持续适用性。直接数据更改需要审批，应在公司的工单系统中记录，并通过变更管理流程进行处理。

#### 数据防泄漏 (DLP)

公司拥有 DLP 解决方案，用于监控并发出警报（并可采取行动）针对机密数据传输到公司外部或在非公司所有设备上的移除行为。DLP 解决方案已配置为加密外部存储设备并防止将敏感数据保存到可移动介质。所有服务器、工作站和笔记本电脑的硬盘均已加密。XYZ 制造及其供应商使用传输层安全（TLS）对互联网上传输到 XYZ Web 服务器和邮件系统的数据进行加密。所有对 XYZ 内部网络的远程访问均使用需要多因素身份验证的 VPN，以确保数据在从公司计算机系统通过互联网传输时处于加密状态。此外，还使用站点到站点 VPN 与某些 XYZ 供应商建立加密通道，以实现位置之间的通信。

#### 数据销毁

超过保留期的数据将从系统和所有备份介质中移除。标记为机密的数据使用美国政府批准的 securely 删除技术（多次覆写）进行擦除。所有计算机硬盘在处置前都要求进行 securely 删除，并且从负责处置 XYZ 所有计算机设备的第三方机构获取销毁证明。

#### 数据备份

每天对所有生产服务器进行增量备份，对生产数据库进行每日备份。每月月末，公司必须对生产服务器执行完全备份。备份磁带经过加密并发送给第三方供应商存储。已实施自动备份系统以监控计划备份的完成情况。当备份作业未成功完成时，运营人员创建事件工单并指派人员解决故障。

#### 病毒检测和预防

必须在所有 XYZ 服务器、桌面、笔记本电脑和邮件基础设施上安装防病毒软件，并集中管理以确保及时提供特征码更新。防病毒软件设置已预配置为自动更新，并锁定以防止任何用户篡改或禁用。部署了邮件过滤软件，限制和拒绝包含特定恶意文件类型（包括可执行文件）的电子邮件。公司的防病毒管理员必须每季度对照系统清单进行一次库存核对。

#### 防火墙和边界安全

XYZ 制造在网络边界和其他战略位置部署企业级防火墙，采用活动故障转移配置。仅允许最少数量的端口和服务进入 XYZ 环境。所有防火墙均通过集中控制台进行管理，XYZ 在防火墙上安装监控软件，以便在管理层级发生更改时提供警报。防火墙规则集每半年审查一次，以确保其配置适当。

#### 安全系统配置

在系统部署到生产环境之前，会在所有系统上安装配置规范。每月执行漏洞和配置扫描，以验证所有系统是否仍按照 XYZ 的安全加固标准进行配置。当对现有标准进行更新时，这些更改将在生产系统上实施。

#### 入侵预防

威胁情报数据库定期更新。由威胁情报数据库识别出且达到特定风险阈值或表现出特定特征的 packets 会自动被丢弃并阻止进入 XYZ 网络。

#### 变更管理

已成立由 XYZ 内所有 IT 部门代表组成的变更审批委员会（CAB）。CAB 每周召开会议，审查即将进行的系统和应用程序变更，这些变更是通过公司的在线工单软件请求的。所有变更都需要有记录在案的备用方案。所有变更都需要有记录在案的测试计划。CAB 的所有成员必须在变更实施前批准该变更。在每周的 CAB 会议上，会审查前一周的变更。对于任何未按计划进行的变更，必须在重新考虑之前完成根本原因分析报告。

#### 应用程序变更

变更请求人在公司的工单系统中提交变更请求。应用程序分析师审查变更请求并制定项目变更预算估算。每月，IT 和业务负责人会对应用程序变更请求及相关预算进行审查和分类，并根据优先级进行排序。开发在独立于生产环境的开发环境中进行，使用测试数据。开发完成后，将进行用户验收测试。用户验收测试完成后，发起变更的业务负责人和相应的应用程序分析师必须在工单内批准该变更。IT 运营团队在 CAB 批准后，将变更迁移到生产环境。紧急变更必须在更改完成后在工单系统中记录和登录，CAB 将进行事后审查以追溯批准这些变更。

#### 补丁管理

当新补丁发布时，将由包括信息安全团队代表在内的一组 IT 人员进行审查。团队为每个补丁分配优先级级别。被评为“严重”的补丁必须在 7 天内应用到所有受影响系统。被评为“高”的补丁必须在 30 天内应用到所有受影响系统。被评为“中”的补丁必须在 60 天内应用。所有其他补丁将通过定期系统更新应用，这些更新通常每季度发生一次。一旦确定了补丁严重性评级，该补丁将分配给相应的 IT 系统管理员，以便在 XYZ 测试实验室中进行评估和测试。测试完成后，在工单系统中录入变更工单，补丁由 CAB 审查和批准。每月，信息安全团队必须对所有系统进行漏洞扫描，以确保补丁已妥善就位。任何缺失的补丁会立即开单，并需要在 5 个工作日内解决。
