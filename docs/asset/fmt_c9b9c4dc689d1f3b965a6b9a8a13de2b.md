
![FIGURE 3.25 A segmented network](img/c03f025a.png)

**图 3.25** 分段网络

就我们的目的而言，网络分段的主要优势是通过使段的内部结构对其他网络段和外部世界不可见，从而增加了安全性。分段网络将限制入侵企业网络的深度，并最小化攻击的传播。

然而，安全性增强并非网络分段的唯一优势。由于限制了来自其他段的流量，本地段内的性能水平也会提高。另一个优势是分段将局部故障隔离在段内，使其更易于检测、排查和修复。然而，分段也会影响网络的整体性能，并需要额外的管理。

在以下章节中，我们将探讨另外两种也可用于创建网络分段的方法：`NAT` 分段和使用第 2/3 层交换机的网络虚拟化。

### 网络地址转换分段

*网络地址转换 (NAT)* 是大多数路由器、服务器和防火墙的功能。虽然 `NAT` 的主要目的是将内部网络的 IP 地址对外部网络屏蔽，但它也提供了一种简单直接的方法来分割组织内部网的物理结构。**图 3.26** 说明了一个 `NAT` 分段网络。

![FIGURE 3.26 A NAT-segmented network](img/c03f026.png)

**图 3.26** NAT 分段网络

例如，在一个按功能分段的网络中，可以安装 `NAT` 防火墙为既需要最低安全性又需要互联网访问的部门提供分段，而不使用其他安全协议。

然而，`NAT` 并非安全万能药。它需要仔细配置，且提供的安全性有限。事实上，`NAT` 会妨碍您可能想在 LAN 上使用的许多其他安全协议。主要是，`NAT` 无法与任何加密 IP 信息的协议良好配合。这使得诸如 *点对点隧道协议 (PPTP)* 之类的隧道协议与 `NAT` 防火墙不兼容。

最流行的协议之一 *IPSec* 采用 *认证头 (AH)* 协议来防止传输中的数据包被篡改。由于 `NAT` 旨在更改源 IP 地址，如果在同一网段上使用，`IPSec` 认证将会失败。此外，`IPSec` 采用 *封装安全载荷 (ESP)* 在 *传输模式* 下检查 IP 地址，如果 `NAT` 转换了源 IP 地址，这也会失败。

任何将源 IP 地址与认证密钥绑定的协议，都将无法认证或协商会话，因为 `NAT` 会更改源 IP 地址。这对 *互联网密钥交换 (IKE)* 以及 *证书颁发机构 (CA)* 同样适用。同样，由于 *文件传输协议 (FTP)* 将源 IP 地址转换为 ASCII 文本，它也与同一网段上的 `NAT` 不兼容。

然而，可以使用一种称为 *NAT 穿越 (NAT-T)* 的 UDP 封装技术，跨 `NAT` 网关建立 `IPSec` 连接。如前所述，`NAT` 设备会改变导致数据包被丢弃的数据包真实性。`NAT-T` 添加一个未加密的 UDP 头来封装 `IPSec ESP` 头。这导致数据包被视为普通 UDP 数据包，从而通过网关。`NAT-T` 操作需要三个端口开放：UDP 端口 4500 (`NAT-T`)、UDP 端口 500 (`IKE`) 和 IP 协议 50 (`ESP`)。

### 网络虚拟化

并非所有网络结构都是表面看起来那样。*虚拟局域网 (VLAN)* 是覆盖在一个或多个物理 LAN 之上的逻辑局域网。可以使用虚拟化软件将一个物理 LAN 划分为多个逻辑 LAN，或将多个物理 LAN 组织成一个逻辑 LAN。在这两种情况下，虚拟 LAN 的组织和运行可能与其运行所在的实际硬件几乎没有相似之处。每个虚拟 LAN 由一个 *VLAN ID* 标识，例如 `VLAN10`。

`VLAN`（连同 `VPN` 和 `VPLS`）是 *基于协议的虚拟网络结构*。作为一种安全拓扑，`VLAN` 通过限制指定端口和分组之间的流量流动，限制了网络流量的可见性。这些结构通常使用第 2 层管理型交换机创建，沿逻辑或功能通信链分离网络段，而不管其物理位置如何。交换机上的物理端口被分配给特定用户组以创建其自己的段。这使得逻辑 `VLAN` 组能够跨越多个物理网络段，而无需使用防火墙。

#### VLAN 示例

例如，一个组织的财务部门可以连接到一个专门为财务组建立的唯一 `VLAN`。该 `VLAN` 被创建为一组特定的交换机端口，如 图 3.27 所示。在此示例中，交换机端口被配置为创建三个独立的 `VLAN`：高管网络（`VLAN10`，端口 1 和 2）、财务部门（`VLAN20`，端口 3、4 和 5）以及销售部门（`VLAN30`，端口 6、7 和 8）。

![图 3.27 VLAN 组织示例](img/c03f027.png)

**图 3.27** VLAN 组织示例

在虚拟局域网中，数据包属于 `VLAN`，而不属于网络设备。在此示例中，财务部门资产连接到配置为 `VLAN20` 的物理交换机端口。因此，交换机将仅把财务数据包分发到指定的 `VLAN20` 端口，即使组成员位于组织网络中地理位置不同的区域。

连接到给定 `VLAN 端口` 的设备无法与网络中其他 `VLAN` 的设备进行通信。如果其他 `VLAN` 中的设备请求一个位于财务 `VLAN` 内的 MAC 地址，该请求将在交换机中被过滤掉，永远不会到达网络。因此，无法建立连接。

#### 网络隔离

仅仅将网络划分为段实际上并不能提高网络的安全性，因为流量仍可从一个子网移动到另一个子网。然而，当分段与网络隔离策略相结合时，这两种策略相互配合，可将网络不同区域的攻击面降至最低。

*网络隔离* 涉及制定并强制执行通信 `规则集`，以控制网段之间的访问（即控制允许哪些计算设备跨越网段边界与其他设备通信）。它们还控制何种类型的信息可以在安全区域之间移动。这些规则通常基于数据源和目标信息、数据类型或数据内容。

在识别出网络的各个段后，下一步是确定每个区域要采用的控制技术。这些技术包括可阻止或过滤流量的 `主动控制` 以及监控活动并进行审计或报告的 `被动控制`。这也是确定为每个段实施何种规则的时刻。这可以通过分析组织业务需求所决定的通信路径来完成。

一般来说，在设计分段/隔离网络环境时，有几条基本建议需要牢记：

*   *根据通用信息安全要求对网络进行分段*。此处的总体目标是为最敏感的数据创建最安全的段。安全性较低的数据可以存储或处理在安全性较低的段中，而公共数据可以放置在仅具有最低安全措施的段中。基于此方法绘制网络图，并查看对任何段的访问是否过于开放或过于严格。

*   *根据需要实施安全控制段*。虽然似乎创建的安全层越多越好，但从前面的讨论中你应该能看出这并不总是正确的。创建适当数量的安全段，以充分保护组织数据的不同分类。创建过少的段可能会使某些数据比应有的更脆弱，而创建过多的段则会拖累组织的业务流程。

*   *基于最小权限原则建立访问控制*。正如本章前面的讨论中提到的，你可能需要为受信任的供应商提供对企业 IT 网络的第三方访问。然而，你应该将他们的访问权限限制在绝对需要的网络区域，以高效地开展与组织关系相关的业务。

*   *确定每个段可接受的安全级别*。在网络环境中，试图完全阻挡每一种威胁从来都不切实际。相反，应确定哪些活动很重要，为这些活动实施具有可接受通信路径的策略，然后阻止其他所有内容。这可以通过创建 `允许列表` 来指定什么网络流量可以访问不同的段来实现，而不是使用指定什么网络流量不能访问的 `拒绝列表`。此外，在向用户或组授予段访问权限时，应应用“最小权限”和“需知”原则。

分段和隔离可以通过多种技术和手段来实现，包括 `VLAN`、使用加密协议的 `VPN` 以及数据二极管。这些技术应应用于网络的多个层，从数据链路层到应用层。

### 分区

*分区* 是一种网络隔离形式，涉及将网络划分为多个较小规模的网络（广播域），并在它们之间创建过滤器，仅允许指定的服务跨越每个域的边界。网络管理员使用分区工具和技术在组织网络内创建内部网，并提供复杂的边界保护结构，以及创建外部网和分支网络。

分区为管理员提供了集中控制和管理能力，可用于在整个组织中实施统一的安全策略，这些策略由组织的安全策略定义。^(\*) 它还支持单点登录功能、远程过程调用和高效的入侵检测操作。

由于此描述是传统防火墙操作的自然延伸，物理防火墙和 `访问控制列表 (ACL)` 一直是网络分区的主力工具。这些工具提供了受网络安全专家信赖的经验证的分段功能。然而，以这种方式定义和配置分段的过程耗时且容易出现人为错误，可能导致安全漏洞。此外，这种实施方式需要彻底了解特定设备配置语法、网络寻址、应用端口和协议。

网络分区的主要缺点集中在当前 IP 过滤设备相关的性能问题上。然而，随着新型连接设备进入市场，如交换机和路由器上的第 4 层过滤，预计 IP 过滤性能将不再是一个问题。

企业网络也可以通过将网络组织为多个 `VLAN` 来有效且安全地分段。分段和隔离都是网络虚拟化的基本产物。每个 `VLAN` 成为一个独立的广播域，仅向该域的授权成员显示相关资产。数据包只能通过路由器（第 3 层分段设备）从一个 `VLAN` 传递到另一个 `VLAN`。

此外，每个 `VLAN` 段可根据该段资产的要求配置独特的安全措施。在 `VLAN` 中，这种多层网络安全环境是通过使用 `分布式防火墙规则` 建立的，如 图 3.28 所示。

![图 3.28 VLAN 分区](img/c03f028.png)

**图 3.28** VLAN 分区

在本例中，物理网络被划分为四个二层 `VLAN` 段，区域之间采用三层分割。各个二层段可被虚拟化为微段，以提升二层段的整体性能，并在段内提供额外的安全选项。这种分割与隔离相结合的做法，造就了一个最内层的数据库层、一个中间的应用层，以及一个面向外部的客户 Web 层。

### 隧道技术

当机密数据在区域间传输时，必须对其进行保护。这通过使用 `data transfer encryption`（数据传输加密）来保护传输中的数据来实现。

`Tunneling`（隧道）技术和技巧可用于安全控制安全区域间的数据移动，如图 3.30 所示。因此，当在两个区域（如与外联网安全区域）之间进行私密通信时，这是一种值得考虑的可行安全拓扑。隧道协议提供数据封装，并与特定加密协议协同工作，以构建一个功能正常的 `VPN`。

![图 3.30 安全隧道](img/c03f030.png)

**图 3.30** 安全隧道

隧道协议（如 `PPTP`）配合微软的点到点加密（`MPPE`）协议使用时，可创建一个 `VPN`。同样，第二层隧道协议（`L2TP`）配合 `IPSec` 使用时，也可创建一个 `VPN`。尽管 `IPSec` 是 `VPN` 的一个组成部分，但它不像 `L2F`、`L2TP` 或 `PPTP` 那样是一种隧道协议。

使用隧道技术在安全区域间传输私有数据的安全优势在于：分隔区域的连接设备无法察觉该通信属于私有网络的一部分。通过将私有数据和协议信息封装在公共传输数据包中，私有数据对系统而言是隐藏的。任何人在网络上扫描隧道传输流量，都无法知晓消息内容。

## 无线网络

另一项开始影响 OT 网络传统结构的技术是 `industrial wireless technology`（工业无线技术）。`Wireless networks`（无线网络）已被用于在组织网络的企业侧，利用高频无线电波连接智能设备。利用无线传感器、控制器和执行器来消除过程控制网络中 ICS 设备之间的长距离布线，这一想法已被讨论和追求多年。然而，实际实施无线 OT 网络的进展一直很缓慢。

无线网络技术存在一些众所周知的挑战，使其作为 ICS 组件的吸引力降低。这些缺点包括安全性降低、鲁棒性差、延迟、可靠性问题和安全性隐患。即便如此，克服这些挑战并生产无线 ICS 技术的推动仍在继续。

### 无线传感器

无线传感器提供了讨论和开发用于 OT 网络无线应用的最大设备池。这些传感器包括压力变送器、差压变送器、温度变送器、模拟量输入变送器和通用 I/O 变送器等设备。大多数设计用于替代传感器，以及工业过程控制长期依赖的旧式 `4-20mA current loop`（4-20mA 电流环）信号标准。

传感器设备实际上是物理传感器和无线发射器或收发器的封装版本。传感器将过程变量转换为可应用于其无线电发射器的有意义电子信号。在另一端，控制器要么直接使用自己的无线电接收无线电信号，要么使用单独的接收器获取信号，然后将其转换为可应用于控制器的信号。这些选项如图 3.32 所示。

![图 3.32 无线传感器通信](img/c03f032.png)

**图 3.32** 无线传感器通信

在过程控制回路的另一端，可实施无线技术来接收控制命令和数据，并将其传递给远程执行器的最终设备。无论哪种情况，链路两端的无线电必须使用相同的传输和信令协议进行通信。用于此目的的常见无线电技术包括：

*   `Wi-Fi`
*   `Bluetooth`
*   `ZigBee`
*   `WiMax`
*   `Proprietary communication protocols/links`（专有通信协议/链路）

正如多次所见，OT 网络需要实时、可靠的数据才能正确且安全地运行。在 OT 网络中使用无线技术的主要缺点之一是其易受 `electrical interference`（电气干扰）影响，以及数据受干扰时可能产生的后果。

工业生产环境本质上往往嘈杂。电机和开关设备在正常运行期间会向空气中辐射电气噪声。这种噪声以波的形式在空气中传播，可能干扰同样在空气中传播的无线电信号。这种干扰可能会中断或破坏编码在无线电信号上的数据，导致延迟和数据丢失。这对实时过程控制系统来说极为成问题。

与无线传感器网络相关的另一个潜在问题是需要本地电源或电池。在每个传感器位置增加本地交流电源连接成本可能相当高昂。此外，工艺安全运行可能要求每个传感器位置都有备用电源（电池）。这同样安装和维护成本高昂。如果出于任一原因需要电池供电，跟踪和更换电池的任务可能成为维护问题。

## 工业和公用事业无线通信协议

工业和公用事业网络采用不同的无线通信协议，在其流程中传输数据和遥测数据。IEEE 组织在 `IEEE-802.xx` 旗下监管一组无线网络规范：

### Wi-Fi

**Wi-Fi**：`IEEE 802.11x`（也称为*无线保真*）无线标准已被广泛接受，成为商业和住宅网络应用的首选无线网络技术。

### 蓝牙 (IEEE 802.15.1)

**蓝牙 (`IEEE 802.15.1`)**：这是一种用于个人区域网 (PAN) 的无线网络规范，在某些领域得到了广泛应用，例如将扬声器、手机、数码相机等个人设备以及 PC、笔记本电脑和打印机进行组网。这种将不同类型的数字设备汇聚在一个共同平台上的现象被称为*融合*。

蓝牙设备使用低功耗、短距离的射频信号，提供低成本、安全的通信链路。该规范提供了三种功率级别/范围选项：`100mW/100meters`、`2.5mW/10meters` 和 `1mW/1meter`。

蓝牙规范在免许可的 `2.4 GHz` 频段实现了*自适应跳频扩频*（**AFHSS**），以提供安全性并避开拥挤的频段。蓝牙协议将 `2.4 GHz` 频段划分为 79 个不同的 `1MHz` 通信信道。跳频机制每秒最多可切换信道 1,600 次。蓝牙 1.1 和 1.2 设备的数据传输速率为 `723.1 Kbps`，蓝牙 2.0 设备为 `2.1 Mbps`。

蓝牙设备一次只能连接到一台设备。一旦蓝牙设备连接到另一台蓝牙设备，它将无法连接到其他设备，也不会出现在查询中，直到它与原始蓝牙设备断开连接。

然而，该标准也支持使用蓝牙技术构建多点无线网络。根据蓝牙规范，最多八台设备可以组成一个*微微网*。任何设备都可以成为主设备，并通过发出广播请求来控制网络。其他七台设备成为从设备，直到主设备释放其位置。

主设备使用时分复用在网络中快速在各从设备之间切换。通过这种方式，蓝牙网络的运行类似于无线 USB 网络。网络中的任何设备在可用时都可以承担主设备的角色。

在计算机网络环境中，蓝牙规范使多个蓝牙外围设备能够同时与主机设备通信。特别是，蓝牙用于本地主机计算机与无线输入输出设备（如鼠标、键盘和打印机）之间的通信。

### Zigbee (IEEE 802.15.4)

**Zigbee (`IEEE 802.15.4`)**：与蓝牙类似，`Zigbee` 标准是一种无线、网状组网的 PAN 协议，提供 `10-meter` 通信范围，数据传输速率为 `250 kbps`。`Zigbee` 标准已被智能家居自动化和工业控制社区以及智能电网联盟的多个领域所采用。它也正被考虑用于*个人生物医学传感器*，以提供安全的远程医疗数据采集。

### WiMAX (IEEE 802.16)

**WiMAX (`IEEE 802.16`)**：该规范的建立旨在为更广域的无线网络能力提供指导。`WiMAX` 是一种宽带无线接入标准，旨在跨越城市、县甚至国家等大面积地理区域提供互联网接入。它还旨在提供与 `802.11` Wi-Fi 标准的互操作性。

## 无线连接设备

根据无线控制器、传感器和执行器之间的距离，网络中可能包含几种不同类型的无线网络连接设备。例如，前面的插图表明各传感器与控制器之间存在直接无线电链路。然而，就像在住宅或企业 IT 网络中一样，数字无线设备可能通过*无线接入点*（**WAP**）或*无线路由器/网关*设备与工业过程控制器通信。
