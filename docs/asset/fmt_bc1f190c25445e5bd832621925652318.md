## 4.4 提出的方案运行模式

在我们的方案中，CSP 支持两种运行模式：优先级模式和常规模式。在优先级模式下，CSP 的能源供应不足以满足当前 EVs 的充电需求。因此，它会优先处理请求并以不超过总能源供应的前提下为高优先级请求进行充电。在相同优先级水平内，请求按先到先充（FCFC）的顺序处理。多权限 ABE 用于保护优先级确定过程 [6]。在常规模式下，CSP 的能源供应足以满足所有 incoming 充电请求。接下来的章节解释了每种运行模式所使用的协议。

## 4.4.1 提出的方案的优先级模式

在该模式下，CSP 首先通过使用多权限 ABE 对 EVs 进行挑战以确定其充电优先级。思路是 CSP 发送使用多权限 ABE 加密的消息。只有拥有特定优先级的 EVs 才能获取解密挑战消息所需的秘密键。随后，每个 EV 应发送解密消息的证明，以证明其对应的优先级。最后，CSP 在不超过能源供应的前提下为最高优先级请求进行充电，并对具有相同优先级的 EVs 使用 FCFC 程序。以下是确定优先级的详细步骤：

- 1. CSP 的挑战：从 CSP 向 EVs 发送挑战是优先级确定过程的第一步。最初，CSP 通过使用来自多个属性授权机构的属性创建其自身的不同优先级的优先级策略。然后，CSP 广播这些优先级策略以及相应的挑战（ABEs）和 EV 可充电的最大能量量。挑战的格式为 `challenge_p = CT_p, TS, Sig(CT_p, TS)` \tag{3}，其中 `TS` 为时间戳，`Sig(CT_p, TS)` 是 CSP 对密文 `CT_p` 的签名。
