### 优点

定性评估有几个主要优点：

- 使用专家的意见
- 易于完成
- 使用单词而非数字，更易表达和理解

数据从最了解系统的专家那里收集。他们丰富的系统知识和经验使他们能够快速识别问题源。只要有专家参与数据收集，风险评估就很容易完成。可以为他们提供调查按自己的进度完成，他们甚至不需要聚在一起；可以分别进行访谈。

定性风险评估使用量表，可以很容易地适应组织的文化。量表允许个人通过他们使用的日常词来理解值的含义，这使得更容易让那些可能是其领域专家但不是安全或 IT 专家的人参与。

例如，人力资源（HR）专家可能对 `HIPAA` 的要求有深入了解。他们了解未受保护数据的危险，以及可以评估的实际罚款或判处监期。HR 专家可以为风险评估提供实质性的投入。

### 使用德尔斐法进行评估

执行定性评估的一种常用方法是德尔斐法，它可以用于收集数据以创建或识别共识。

德尔斐法的主要优点是它允许个人在没有压力的情况下自由分享意见。不是让所有参与者在会议上讨论某个问题，而是独立地收集回复。

德尔斐法可以通过几种方式实现。一种方法是按照以下步骤操作：

1. **识别问题**—问题可能出现在单个 IT 系统或一组服务器上。该问题应在加入团队的专家的知识范围内。例如，问题可能与网站故障有关，可以表述为“WebServer1 在过去一年内发生了四次故障，导致了损失”。
2. **收集专家意见**—将问题发送给专家组，要求他们做出。对于 Web 服务器故障，可以要求他们识别主要风险。如果原因已知，可以要求他们识别主要风险。
3. **汇总回复**—回复在不同阶段会有不同的形式。例如，回复可以是风险列表、按优先级排序的风险列表或缓解风险的措施列表。
4. **共享结果**—结果的共享取决于项目阶段的不同形式。如果刚刚汇总了风险列表，现在可以要求团队识别每个风险的概率和影响。当开始研究措施时，可以重复该过程。可以请求缓解风险的措施列表。然后，可以要求团队识别不同措施对特定风险的有效性。
5. **根据需要重复**—重复该过程直到收集到所有数据。

德尔斐法非常灵活。今天，调查通常可以通过电子邮件完成。许多电子邮件程序允许发送调查，用户只需点击按钮。用户还可以填写在内部 Web 服务器上创建的调查，这可能需要一些时间，但结果可以快速汇总。

独立收集数据是重要的。如果数据是在会议上收集的，参与者的可能会受他人的意见而偏斜。强势的参与者可能会影响他人并防止团队充分参与。

### 局限性

定性评估有几个局限性，包括：

- **主观性**—分析和结果更多基于意见而非事实。对这些意见的不同视角可能会产生不同的结果。如果意见是在小组中收集的，强势参与者可能会塑造整个小组的想法。
- **基于专家水平**—评估价值取决于专家的水平。如果专家拥有坚实的知识基础和丰富的经验，结果将很有价值。另一方面，如果没有接触真正的专家，结果的价值可能有限。
- **没有 CBA**——定性评估不包含成本效益分析（CBA）。控制措施的有效性没有定量分析那样清晰。尽管专家的意见仍然具有价值，但结果对管理层来说可能不够清晰。管理层在决定使用哪些保护措施时可能会面临更大的困难。
- **没有真实的标准**——公司需要定义过程中使用的刻度。例如，刻度可以简单地分为低、中、高。然而，需要为参与者开发并定义这些刻度，这需要理解风险评估以及数据将如何用途的专业人士。

## 定量与定性风险评估的比较

提醒一下，这两种方法都不被认为优于对方。它们都有自己的优点和局限性。总结来说，以下是定量与定性风险评估之间的几点比较。

### 定量分析：

- 客观性
- 使用数值，例如金额
- 可靠的可重复性
- 更耗费时间
- 需要访问大量的历史数据
- 数据并不总是容易获得
- 基于 `SLE`、`ARO` 和 `ALE` 公式
- 以金额显示清晰的损失和节省
- 数据可以很容易地用于 `CBA`

### 定性分析：

- 主观性
- 基于专家的意见
- 比定量分析更快、成本更低地完成
- 使用词汇值，例如低、中、高
- 需要定义风险评估中使用的刻度

## 风险评估大纲示例

风险评估以报告结束，管理层可以根据报告来决定实施哪些控制措施。以下是风险评估报告中通常包含的主列表：

- **引言**——引言提供了风险评估的目的和范围。它包括对风险评估中考虑的系统的组件、用户和位置的描述。
- **风险评估方法**——该部分识别了用于完成风险评估的方法。它包含了有关如何收集数据以及参与人员的细节。如果使用定性方法，该部分将描述风险刻度。
- **系统特征描述**——该部分提供了有关系统的更多细节。它可能包括硬件、软件或网络连接的细节，并可能包含以图形化方式显示评估系统的图表。
- **威胁声明**——该部分列出了潜在的威胁、威胁源和威胁行为。例如，一个威胁可能是攻击者对面向互联网的服务器发起 `DoS`攻击。
- **风险评估结果**——结果可以以威胁/漏洞对的形式列出，代表一种风险。通过现有的安全措施对风险进行描述。列出当前控制措施下风险发生的概率。风险的描述方式取决于使用了哪种分析。定量方法使用 `SLE`、`ARO` 和 `ALE` 等术语。定性方法根据定义的刻度识别概率和影响。所有这些数据都通过识别结果如何获取的讨论提供了支持。
- **控制建议**——提供一份建议的保护措施或控制措施列表。该列表可以包含对控制措施有效性的注释。定量方法通常会为每种控制措施带上 `CBA`。定性方法通常会对控制措施的有效性进行排名。
- **总结**——总结可以用一个或多个汇总结果的表格形式。这种格式使管理层很容易根据风险分级查看最高风险。总结还使易于批准任何建议。

## 风险评估面临的挑战

在完成风险评估时，必须解决并克服若干挑战。其中许多挑战取决于所选择的评估类型。定量和定性评估都有各自的挑战。这些挑战在上一节中作为局限性被列出。

存在一些额外的挑战，包括：

- 使用静态过程来评估移动目标
- 资源和数据的可用性
- 数据一致性
- 估算影响因素
- 提供支持资源分配和风险接受的结果

这些挑战在接后的章节中将被探讨。

### 使用静态过程评估移动目标

如前所述，风险评估是一个时间点上的评估。它在特定时间针对已知风险对系统进行评估，并根据当前的控制措施考虑风险。换句话说，风险评估是一个静态过程。然而，安全不是静态的。风险可以且确实在变化，因为攻击者和攻击手段不断变化。

当攻击者成功攻击时，安全专家会实施控制措施。在某个时刻，这些攻击的成功率会降低。攻击者随后学习新的攻击方法。安全专家修改控制措施或实施新的控制措施，战斗每天持续。

某些威胁和漏洞看起来已经成功缓解，不再是风险。但突然之间，它们又作为另一种威胁出现。域名系统（`DNS`）缓存中毒就是一个很好的例子。`DNS`缓存中毒会导致系统将网站名称解析为虚假的互联网协议（`IP`）地址。用户可能尝试用网络浏览器访问 `Acme.com`，但他们被重定向到了 `Malware4u.com`。`DNS`缓存中毒在年前被确定为重大威胁。它曾被成功缓解并不再使用。从 IT 安全的角度来看，它几乎成了一个历史脚注。

随后，在 2008 年夏天，Dan Kaminsky 发现并发布了一个漏洞。快如闪电，`DNS`缓存中毒再次成为问题。一旦结果发布，攻击者就学会了如何利用该漏洞。`DNS`缓存中毒再次被引起严重关注。安全措施解决了这一缺陷，`DNS`缓存中毒再次变得罕见。

如果风险评估在 3 月完成，但在 6 月公布了影响系统的漏洞，那么评估的有效性就会受到影响。因此，了解新出现的风险是必要的。

#### 提示

了解漏洞的一种方法是订阅美国计算机应急响应小组（`US-CERT`）的警报。关注警报显示每周都有新的漏洞被发现。漏洞中的一些代表非常严重的风险。可以通过 `http://www.us-cert.gov/mailing-lists-and-feeds/` 接收 `US-CERT` 团队的电子邮件和警报。

#### 资源和数据的可用性

可用性挑战存在两个主要领域。一个领域涉及资源的可用性，另一个领域涉及数据的可用性。这两个领域在风险评估过程的早期解决至关重要。如果不解决，将严重影响质量。

关于资源，参与评估的人员应该了解他们所评估的系统。具有更高水平的知识可以获得更高质量的评估。如果风险评估团队没有所需的水平知识和经验，他们可能不得不采取猜测。

就数据而言，其可用性也同样重要。数据的可用性将决定所执行的评估类型。例如，如果有大量与实际性能和故障相关的内部历史数据，则可以使用这些数据来进行定量风险评估。这些历史数据可用于确定 `SLE` 和 `ARO` 的值。如果这些数据可用，则可能会转而进行定性风险评估。

如果没有合适的人员和准确的数据，风险评估的完成将变得困难得多。如果问题能尽早得到解决，成功的机会会更高。

#### 提示

即使能够访问历史数据，可能仍然选择进行定性风险评估。选择定性而非定量风险评估的原因之一可能是时间考虑。定性风险评估通常比定量风险评估能更快完成。

## 数据一致性

风险评估的另一个挑战是数据一致性。数据一致性指的是数据的准确性。多个问题会影响数据一致性，这些包括：

- 数据格式的差异
- 数据收集方式的变化
- 业务本身的变化

这些每一个都可能直接影响数据的准确性。然而，即使数据准确率未达到 100%，也不意味着这些数据无法使用。

某些风险评估通过不确定性水平来处理数据的准确性，该水平指示数据的有效性。如果所有条件都理想，数据将是 100%准确的。在这种情况下，不确定性水平将为 0%。但在现实世界中，0%的不确定性水平是不可能的。

例如，历史数据可能显示网站每小时产生约 $2,000 的收入。当前数据可能显示这一趋势仍在持续并有轻微增长。数据准确的确定性可能是 80%，即有 20%的不确定性水平。在使用这些销售数据计算 `SLE` 时，也可以提供不确定性水平。

### 数据格式差异

数据格式会影响数据如何使用、处理和解释。通常，数据库在查询和处理大量数据方面效率更高。然而，数据最初可能是在文字处理文档或电子表格中创建的。如果数据是从一种格式迁移另一种格式，可以选择对数据的准确性进行不同的权重。

例如，数据之前存储在 Microsoft Excel 工作表中，但现在存储在 Microsoft SQL Server 数据库中。存储在工作表中时，它满足了用户的需求。但从不同角度查看数据或通过查询显示不同的总计和分项合计并不容易。在数据库中，现在可以使用查询从多个角度查看数据。数据可能非常相似，但数据库现在允许对数据获得更深层次的视角。

考虑到这一点，使用 Excel 工作表的用户可能得出了准确的结论。然而，这些结论可能没有从存储在数据库的数据中得出的结论那样实质。

如果数据来自不同的来源，意识到它们可能被不同的解释是非常重要的。这可能会在比较数据时导致不一致性。所有这一切都会影响数据的不确定性水平。

### 数据收集的变化

数据收集方式的变化也会影响数据的准确性。可能看到的这种变化是从手动数据收集转向自动数据收集。

对人类有很多赞誉，但事实是，人类并不擅长处理枯燥的重复任务。计算机擅长。当人们手动收集和输入数据时，应该预考虑到错误的。

控制和检查有助于发现这些错误。输入验证方法验证数据的有效性。例如，`ZIP Code` 有五位数。输入验证方法可以检测四位或六位的无效 `ZIP Code` 输入。此外，一名员工可以双检另一名员工输入的数据。

手动数据输入会对不确定性水平产生负面影响。未能双检数据的准确性也会影响不确定性水平。

另一方面，如果使用自动方法收集数据，数据的预测性要高得多。如果使用自动方法收集、存储和处理数据，其不确定性水平将低得多。

### 业务的变化

一家公司今年的业务量通常与去年不同，这通常是由于增长导致的。然而，对于某些业务来说，业务量的变化可能是由于市场份额的流或其他业务原因。事实是，销售额很少是停滞的。事实上，销售停滞被视为负面信号。

了解过去发生了什么非常重要，以便预测未来将发生什么。然而，未来永远不会与过去完全相同。例如，某个网站去年的每小时收入可能是 $2,000。然而，圣诞期间的销售额可能比去年增加了一倍，目前的预测是今年的销售额也可能翻倍。所有这些因素可能要求将每小时平均销售额从 $2,000 修改为 $4,000。

同样，公司可能在某个销售市场中失去了市场份额。这种损失可能是因为公司为研发或营销分配的资金较少，或者由于其他十几个原因中的任何一个。所以，如果销售额正在下降，应该考虑这一事实。

话虽如此，尽管销售数据可能显示销售额正在下降，但新经理可能正在实施增加销售额的变革，初步迹象可能显示正在增长。所有这些因素可能导致所用数字的不确定性水平发生变化。

## 影响效应估计

任何风险的潜在影响都很难估计。最重要的一点是意识到影响只是一个估计。如果未来发生的事情可以被准确预测，从事 IT 或网络安全领域可能就不是了。

在估计影响效应时，多个因素会起作用，即使在有准确历史数据的情况下也是如此。例如，网站可能遭受了攻击，导致数小时的故障。在排除故障期间，技术人员学到了很多。是的，首要任务是解决当前的故障。然而，从中获得的知识和经验被积累了起来。下次服务器发生故障时，恢复时间可能会快得多。

这个例子也取决于多个变量。IT 专业人员流失率高的公司无法像流失率低的公司那样积累经验。如果系统由于六个月前相同的原因宕机，但这是新技术人员第一次看到它，故障时间可能和以前一样长。

另一方面，之前的攻击成功可能是由于系统中的漏洞。如果这些漏洞被发现，它们通常会被修复。然而，即使被修复了，这些修复可能也没有被记录。

如果没有对之前修复的记录，今天看起来可能与之前攻击时完全一样。相反，可能已经实施了多项变化，减少了攻击发生的概率或影响。在这个例子中，不确定性水平可能取决于组织管理实践的变化。

#### 注意

变更管理是一个流程，它确保只有在经过审查流程后才进行变更，并对变更进行记录。它是信息技术基础架构库（ITIL）涵盖的一个重要流程。许多公司即使没有直接遵循 ITIL 实践，也会使用变更管理流程。

## 提供支持资源分配和风险接受的结果

风险评估的结果需要是有实际用的，这并不意外。然而，安全专业人员可能会掉入“必须不惜代价地追求安全”的陷阱，但事实并非如此。必须不断考虑盈利能力与生存能力之间的适当平衡。

两个需要考虑的重要点是：

- 资源分配
- 风险接受

### 资源分配

安全团队的资金或人员数量不是无限的。相反，安全部门将获得有限百分比的资源，在进行风险评估时，这一点是非常重要的。
