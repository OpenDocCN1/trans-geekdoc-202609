
# 工作站领域

工作站可以是台式机或笔记本电脑、特殊用途终端，或任何连接到组织网络的设备；工作站是用户首次访问系统、应用程序和数据的地方。工作站领域需要严格的安全和访问控制。此外，操作系统和应用程序中不断发现 Bug 和漏洞。软件供应商定期发布补丁和修复程序，必须应用这些程序以帮助保护系统。

## LAN 领域

LAN 领域是防火墙内部的区域。局域网（LAN）可以是小型家庭办公室网络中的单台工作站和打印机，也可以是拥有成千上万设备的大型网络。由于这些设备共享网络资源，它们容易受到攻击单个设备的威胁的影响。例如，用户可能会访问危险网站，并在不知情的情况下下载会感染整个网络的病毒。

## LAN-to-WAN 领域

局域网到广域网（LAN-to-WAN）域是 IT 基础设施连接到广域网（WAN）和互联网的地方。该域为整个组织提供互联网访问服务，并作为广域网的进出口。边界的公侧通常连接到互联网，是黑客频繁寻找的目标，他们试图寻找允许未经授权访问局域网的漏洞。

## 广域网（WAN）领域

广域网（WAN）域连接远程位置。管理广域域的目标是让用户能够获得尽可能的访问权限，同时确保进出数据是安全的。为了确保广域域内主机的安全，需要大量的安全防护。与该域相关的风险包括窃听和授权访问，因为该域中的大多数流量都是以明文发送的，这意味着黑客可以获取用户名和密码。此外，数据还受到损坏和恶意攻击的影响。

## 远程访问域

远程访问域将远程用户连接到组织的 IT 基础设施。对于在现场或从家里工作的员工，例如外勤销售代表、技术支持专家或医疗保健专业人员来说，远程访问至关重要。Wi-Fi 热点让用户能够连接到虚拟专用网络（VPN）以访问电子邮件和其他业务应用程序，但如果员工的设备被盗或未妥善保护，也会对组织的专有数据构成风险。

VPN 连接使用隧道协议来降低数据被捕获的风险。隧道协议加密通过网络发送的流量，这使得攻击者更难捕获和读取数据。

## 系统/应用域

系统/应用域是存储组织数据的地方，这些数据可以是私人客户数据、知识产权或国家安全信息。数据是攻击者在 IT 系统深处寻求的东西。无论是由于攻击、灾难还是疏忽导致数据丢失，都是系统/应用域中最大的威胁。

# 风险识别技术

本章前面的部分介绍了风险和损失。风险是指某些意外情况发生的可能性或概率。某些风险会导致损失。当威胁暴露漏洞并损害资产时，损失就会发生。要识别风险，需要遵循以下三个步骤：

1. 识别威胁
2. 识别漏洞
3. 估算威胁利用漏洞损害资产的可能性

接下来的章节将探讨这些概念。

## 识别威胁

威胁是任何可能导致损失的状况或事件。换句话说，它是任何代表可能危险的活动。损失或危险与以下内容之一直接相关：

*   **机密性丢失**——某人看到了某一个人的密码或公司的“秘密配方”。
*   **完整性丢失**——电子邮件邮件在传输过程中被篡改、病毒感染了文件，或有人对网站进行了未经授权的更改。
*   **可用性丢失**——电子邮件服务器宕机导致无人能访问电子邮件，或文件服务器宕机导致数据文件无法使用。

威胁识别是创建威胁列表的过程。公司应该尝试识别对组织所有可能的威胁，这绝非一项易事。列表可能会非常详尽。

为了编制此威胁列表，企业通常会从以下类别中考虑威胁：

*   **外部或内部**——外部威胁位于组织边界之外。它们也可以被认为是组织控制范围之外的风险。内部威胁位于组织边界之内。它们可能与拥有公司资源访问权限的员工或其他人员有关。内部威胁可能与受业务控制的任何硬件或软件有关。
*   **自然或人为**——自然威胁通常与天气有关，例如飓风、龙卷风和冰风暴。地震和海啸也是自然威胁。人类或人为威胁是指人引起的。由于访问公司资源的人员引起的可能是内部威胁。火灾可能是人为的或自然的，取决于火是如何引发的。
*   **故意或意外**——试图破坏机密性、完整性、可用性的尝试是故意的。员工错误或用户错误是意外的。损坏数据的应用程序可以被视为意外。

识别威胁的一种方法是头脑风暴会议。在头脑风暴会议中，参与者会提出脑海中产生的任何想法。所有想法都会记录下来，而不对问题仅进行逻辑分析。

对组织的威胁示例包括：

*   未经授权访问数据的员工
*   任何类型的恶意软件
*   攻击者污改网站
*   任何 `DoS` 或 `DDoS` 攻击
*   试图访问数据的外部攻击者
*   任何数据丢失
*   任何服务中断
*   社会工程学诱骗员工泄露秘密
*   地震、洪水或飓风
*   雷击
*   电力、供暖或空调故障
*   火灾

如果这些威胁暴露了漏洞并可能损害资产，那么它们都代表了可能的风险。

当然，还会识别出特定组织的威胁和漏洞。事实上，拥有多个地点的业务每个地点可能都有独特的威胁和漏洞。

## 识别漏洞

在本章前面介绍了漏洞是一种弱点。漏洞在威胁利用它们时变得显现。理想情况下，在威胁利用之前就能识别漏洞。幸运的是，大多数组织都有许多可以帮助此事的来源。

常用的来源包括：

*   **审计**——许多组织定期进行审计。检查系统和流程以验证公司符合现行的法律法规。审计人员在报告中记录发现，列出与漏洞直接相关的发现。
*   **认证和认可记录**——存在多种标准用于检查和认证 IT 系统。如果系统符合标准，IT 系统即可获得认可。整个过程包括详细文档。通过审查这些文档可以识别现有和潜在漏洞。
*   **系统日志**——许多类型的计算机系统日志可以识别威胁。审计日志可以确定用户是否正在访问敏感数据。防火墙日志可以识别试图入侵网络的流量以及被恶意软件接管作为僵尸的计算机。域名系统（DNS）日志可以识别未经授权的数据传输。
*   **先前的事件**——之前的安全事件是极佳的数据来源。作为已经发生的风险的证据，它们有助于证明控制措施的合理性。它们展示了已经发生的问题并可以显示趋势。理想情况下，安全事件产生的漏洞会在发生后立即解决。在实践中，有时员工希望尽快忘记事件并尽早遗忘它。
*   **故障报告**——大多数公司使用数据库来记录故障电话。这些数据库可以包含丰富的信息。通过简单的分析，可以利用它们来识别趋势和弱点。
*   **事件响应团队**——某些公司设有事件响应团队。这些团队将调查公司内部所有的安全事件。可以对团队成员进行访谈以获取丰富的信息，因为他们通常乐于帮助降低风险。

## 使用典型 IT 基础设施的七领域识别弱点

识别弱点的另一种方法是检查典型 IT 基础设施的七个领域，这些领域在本章前面已经过。可以对每个领域进行单独检查。此外，每个领域还可以由该领域的专家进行检查。以下列表提供了这些领域中漏洞的示例：

*   **用户领域**——社会工程学是一个巨大的漏洞。例如，Sally 接到一个电话：“你好，我是帮助台的 Bob。我们在你的电脑上发现了一个病毒。”Bob 随后尝试引导 Sally 完成一个漫长而详细的过程，然后说：“我为什么不直接帮你修好它，这样你就能回去工作了？我只需要你的密码。”
*   **工作站领域**——未打补丁的计算机可能会被攻击利用。如果它们没有防病毒软件，就可能被感染。
*   **LAN 领域**——网络上任何未使用适当访问控制保护的数据都是脆弱的。弱密码可以被破解。分配不当的权限会导致未经授权的访问。
*   **LAN 到 WAN 领域**——如果允许用户访问恶意网站，他们可能会误下载恶意软件。开启了不必要端口的防火墙允许从互联网访问内部网络。
*   **WAN 领域**——任何面向公众的服务器都容易受到 `DoS` 和 `DDoS` 攻击。允许匿名上传的文件传输协议 (`FTP`) 服务器可能会托管来自黑客的盗版软件。
*   **远程访问领域**——远程用户可能感染了病毒但不知情。当他们通过远程访问连接到内部网络时，病毒可能会感染网络。
*   **系统/应用领域**——数据库服务器可能会受到 SQL 注入攻击。在 SQL 注入攻击中，攻击者可以读取整个数据库。SQL 注入攻击还可以修改数据库中的数据。

本节并不代表完整的列表；这是无法做到的。IT 系统中发现的漏洞数量不断增加。MITRE 公司的目录常见漏洞与披露 (CVE) 目前包含超过 40,000 项。

### ![](img/Tip.png) TIP

某些恶意软件可以控制多台计算机并将它们像机器人一样控制。控制计算机发出攻击命令，计算机便进行攻击。单台计算机被称为 `zombies`（僵尸）。受控计算机的网络被称为 `botnet`（僵尸网络）。

### ![](img/Tip.png) TIP

`Warez`（读作 wares）是一个描述盗版文件的术语。示例包括盗版游戏、MP3 文件和电影。Warez 网站通常包含黑客工具，任何人（包括黑客）都可以下载这些工具。

### ![](img/Tip.png) TIP

`SQL 注入攻击` 试图访问来自网站的数据。SQL 语句被输入到文本框中。如果网站没有进行防御性编程，这些 SQL 语句就可以针对数据库执行。目前有许多程序可以发起 SQL 注入攻击并检索整个数据库。

## 评估影响和可能性

识别风险的第三步是估计威胁利用漏洞损害资产的概率。将威胁与现有的漏洞进行匹配，以确定威胁对组织的影响。

在前面的“识别威胁”章节中列出了几种威胁。表 1-1 取了其中几种威胁并将它们与漏洞匹配，以识别可能损失的影响。

**表 1-1** 评估威胁的影响

| 威胁 | 漏洞 | 影响 |
| --- | --- | --- |
| 未经授权的员工尝试访问托管在服务器上的数据。 | 未使用适当的身份验证和访问控制。 | 可能的损失取决于数据的敏感性及其使用方式。例如，如果未经授权的员工访问了薪资数据并自由分享，可能会影响士气和生产力。 |
| 任何类型的恶意软件（如病毒或蠕虫）进入网络。 | 防病毒软件未检测到病毒。 | 病毒可能会安装在系统中。病毒通常会导致机密性、完整性或可用性的丢失。 |
| 攻击者修改或篡改网站。 | 网站未受保护。 | 根据攻击者修改网站的方式，公司的信誉可能会受到影响。 |
| 社会工程师欺骗员工泄露密码。 | 用户未经过充分培训。 | 密码可能会泄露。获得密码的攻击者可以控制用户的帐户。 |

在将威胁与漏洞配对时通常使用以下公式：

```
风险 = 威胁 × 漏洞
```

然而，这不是一个真正的数学公式。威胁和漏洞并不总是有数值。相反，该公式显示了两者之间的关系。

如果可以确定资产价值，则对公式稍作修改为：

```
总风险 = 威胁 × 漏洞 × 资产价值
```

## 平衡风险与成本

管理风险的成本必须与影响值进行平衡。如果可用，可以用实际货币价值来衡量成本。也可以通过使用相对值（如 `低`、`中` 和 `高`）来平衡成本。

表 1-2 显示了分配相对值的示例。可能性在垂直方向显示，影响在水平方向显示。如果一个威胁发生的概率为 0% 到 10%，则被赋值为 `低`。如果概率在 11% 到 50% 之间，则赋值为 `中`。如果概率在 51% 到 100% 之间，则赋值为 `高`。同样，影响可以评为 `低`、`中` 和 `高`。

有时，风险发生的可能性和影响很高，这提供了一个容易的选择。例如，没有防病毒软件的系统会受到感染。这种威胁很常见。可能性很高。当这种情况发生时，受感染的系统可能会导致业务数据的泄露或破坏。影响也很大。这种风险需要缓解。防病毒软件的成本远低于影响成本。因此，防病毒软件在业务中很常见。

其他时候，可能性较低但影响很大。例如，数据中心火灾的风险较低，但影响很大。企业通常会配备火灾检测和灭火设备，以防止火灾发生时产生影响。还会购买保险以减少火灾造成损害的影响。

## 合理性

面对许多威胁公司业务的风险，意识到公司不需要管理每一个可能的风险应该是一个好消息。某些风险的管理是合理的，而另一些则不是。

合理性 是一种可以应用于风险管理的测试，用于确定是否应该管理该风险。该测试源于法律中的理性人标准。简而言之，这个问题应该回答：“一个理性的人是否会被预期会管理这个风险？”

不符合合理性测试的风险是可以接受的。例如，核战争的威胁确实存在。公司可能会投入资源为所有员工建造避难所，并储备足够维持 30 年的食物和饮用水。然而，这种情景并不合理。

另一个例子是考虑一家位于佛罗里达州东岸的公司。飓风是一个非常真实的威胁，应该被在范围内。然而，重大地震袭击佛罗里达州东岸的概率相对较小，不需要处理。但是，位于旧金山的企业就有不同的考量。那里的地震是真实的威胁，但飓风不是。因此，对于旧金山来说，飓风风险是可以轻易接受的，而地震风险则不被接受。

### ![](img/Tip.png) TIP

可以创建一个更详细的威胁-可能性-影响矩阵。例如，与其为威胁可能性分配低、中、高值，不如分配实际具体的百分比。此外，可以使用更多的类别，而不仅仅是三个。使用更多的类别可以实现它们之间更大的区分度。同样，影响可以分配一个范围内的任何数字。`表 1-2`中的矩阵使用了 10、50 和 100 的范围，但 1 到 100 之间的任何数字都可以使用。

合理性的另一个标准是仅关注组织内部或被评估系统内部的漏洞。外部漏洞通常不被处理。例如，如果空调故障，服务器很可能会故障。这种情况在识别服务器机房漏洞时会被处理。这种漏洞不会针对服务器机房内 50 台服务器中的每一台进行单独处理。同样，商业用电可能会中断。这种情况可以通过不间断电源（`UPSs`）和发电机来解决。然而，不需要为商业电力公司寻找替代方案。

### 风险管理流程

在本章前面的部分，风险管理被定义为识别、评估、控制和缓解风险的实践。识别与组织相关的威胁和漏洞是一个重要步骤，就像了解资产的价值有助于确定其损失的影响一样。有了这些信息，就可以采取行动。

意识到风险管理不等同于消除是非常重要的。相反，风险管理试图的是减少。这包含了几个要素：

*   **评估风险**——风险管理从`风险评估`开始。
*   **识别威胁和漏洞**——收集数据以识别成本和收益。
*   **识别可能性**——检查损失的成本。
*   **识别影响**——确定潜在影响。
*   **识别风险响应**——决定风险是规避、转移还是缓解。
*   **选择控制措施**——比较影响与实施成本。
*   **实施和测试**——一旦实施控制措施，就会对其进行定期测试。
*   **评估控制措施**——风险管理是一个持续的过程。

### ![](img/Tip.png) TIP

控制措施并不总是消除损失。相反，控制措施减少了损失。例如，某项风险的年度损失平均为 $100,000。如果实施了控制措施，这些损失可能会减少到 $10,000。因此，该控制措施的收益为 $90,000。

可以使用以下公式来确定应该使用该控制措施：

`控制前的损失 − 控制后的损失 = 控制成本`

例如，该公司去年在没有实施任何控制措施的情况下损失了 $100,000。如果实施了控制措施，预计每年损失为 $12,000。控制的成本估计为 $7,000。公式为：

`$100,000 − $7,000 (控制成本) − $12,000 (预期剩余损失) = $81,000`

# 成本效益分析

可以进行`成本效益分析 (CBA)` 来帮助确定实施哪些控制措施或对措施。如果收益大于成本，通常会选择该控制措施。

开始 CBA 始于收集数据，以识别控制措施的成本以及实施后可能获得的收益。

*   **控制成本**——控制成本包括购买成本加上控制措施整个生命周期内的运营成本。
*   **预期收益**——预期收益包括实施控制措施后获得的潜在收益。这些收益通过检查损失的成本以及在实施控制措施后损失将减少多少来确定。

执行成本效益分析（CBA）时面临的最大挑战之一是获取准确的数据。虽然当前的损失通常很容易获得，但未来的成本和收益需要进行估算。成本往往被低估，而收益往往被高估。

控制措施的即时成本通常是可见的。然而，有时持续成本是隐藏的。某些隐藏成本可能：

*   培训员工的成本
*   持续维护的成本
*   软件和硬件更新成本，例如订阅费用

根据比例原则，如果成本超过了收益，组织可能会选择不实施该控制。相反，它可能会选择接受、分担、转移或规避风险。

## 盈利能力与生存能力

在评估风险管理成本时，必须考虑盈利能力和生存能力：

*   **盈利能力（Profitability）**——盈利能力是指公司盈利的能力。其计算方法为收入减去成本。
*   **生存能力（Survivability）**——生存能力是指公司遭受因风险导致的损失的能力。某些损失（如火灾）可能是灾难性的，并将导致业务失败。

从盈利能力来说，损失可能会摧毁一家企业。从生存能力来说，损失可能导致公司永远无法盈利。与风险管理相关的成本并不直接有助于增加收入。相反，这些成本有助于确保公司在遭受损失时能够继续运营。

关于盈利能力和生存能力，应考虑以下事项：

*   **自付现金成本（Out-of-pocket costs）**——减少风险的成本来自现有资金。
*   **机会成本（Lost opportunity costs）**——用于减少风险的资金无法用于其他地方，如果这些资金可以用于其他用途，可能会导致机会流失。
*   **未来成本（Future costs）**——一些应对措施需要持续或未来的成本。这些成本可能用于更新硬件或软件。未来成本还包括实施应对措施所需的人员成本。
*   **客户和利益相关者的信任（Client and stakeholder confidence）**——客户和利益相关者的信任价值同样重要。如果风险得不到解决，当威胁利用漏洞时，客户和利益相关者可能会失去信任，给公司带来巨大损失。
*   **安全总成本（Total cost of security）**——安全总成本包括一次性成本（例如，在 `IDS` 上花费资金）以及持续或经常性的成本（例如，防病毒软件的订阅费用）。这种成本可能很高，花费的资金会减少公司的总利润。但替代方案是什么呢？如果不采取这些保护，整个业务可能会停滞。如果这种情况发生得太频繁或持续过长，业务可能会失败。

数据通常是企业拥有的最有价值资产之一。它可以包括客户数据、会计数据（如应付账款和应收账款）以及员工数据。列表可以一直延伸。这些数据对于企业的成功至关重要，因此通常会定期备份。
