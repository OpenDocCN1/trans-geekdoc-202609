### 网络设备

在今天的商业环境中，完整的网络计算机解决方案不仅包括客户端和服务器。设备用于连接客户端和服务器并调节它们之间的流量。还需要设备将这种网络从简单的客户端和服务器扩展到包括其他设备和手持系统。设备有多种形式和功能，从集线器、交换机到路由器、无线访问点以及专用的 VPN 设备。每个设备都有特定的网络功能，并在维护网络基础设施安全方面发挥作用。

### 防火墙

防火墙可以是硬件、软件或者的结合，其目的是跨网络连接执行一组安全策略。它非常像带窗户的墙：墙的作用是将东西挡在外面，除非通过窗户允许（参见图 1-1）。网络安全策略就像窗玻璃；它们允许某些东西通过（如光），同时阻止其他东西（如空气）。防火墙的核心是它执行的安全策略集。管理层决定了设备之间允许的网络流量，这些策略被用于构建用于过滤网络流量的防火墙设备的规则集。

![image](img/f0004-01.jpg)

* *

**图 1-1** 防火墙的工作原理

`Security policies`是定义哪些流量是被允许的、哪些流量应该阻止或拒绝的规则。这些规则并非通用的，对于具有多个连接的单一公司，会创建许多不同的规则集。例如，连接到互联网的 Web 服务器可能配置为仅允许端口`80`上的 HTTP 流量，并阻塞所有其他端口。电子邮件服务器可能只开放电子邮件所需的必要端口，而阻塞其他端口。网络防火墙可以编程为阻止除端口`80`流量以外的所有指向 Web 服务器的流量，并阻止除端口`25`流量以外的所有指向邮件服务器的流量。通过这种方式，防火墙充当了安全过滤器，通过机器、端口以及在某些情况下基于应用层细节来实现对网络流量的控制。防火墙设置安全策略的关键与其他安全策略相同——**最小权限原则**。仅允许某功能所需的必要访问；阻止或拒绝所有不需要的功能。公司部署防火墙的方式决定了每个防火墙安全策略所需的内容。

正如后文将讨论的，安全拓扑结构将决定在网络的何种节点使用哪些网络设备。至少，公司到互联网的连接应该通过防火墙。该防火墙应阻止所有非公司专门授权的网络流量。阻塞端口上的通信非常简单——只需告诉防火墙关闭该端口即可。问题在于决定需要哪些服务以及由谁需要，从而决定哪些端口应该开启，哪些应该关闭。这就是安全策略变得实用的原因。防火墙完美的网络安全策略集是终端用户永远看不见的，且绝不允许即使是一个未经授权的数据包进入网络。就像任何其他完美事物一样，在企业中很难找到完美的防火墙安全策略集。在开发防火墙规则时，最好使用最小权限原则；你希望防火墙尽可能阻挡流量，同时允许授权的流量通过。

要制定一个完整且全面的安全策略，首先需要对你的网络资源及其用途有一个完整全面的理解。一旦你知道网络将如何被使用，你就会知道允许什么。此外，一旦你了解你需要保护什么，你就会知道应该阻止什么。防火墙的设计是在攻击到达目标机器之前将其拦截。常见目标是 Web 服务器、电子邮件服务器、DNS 服务器、FTP 服务和数据库。这些每项都有独立的功能，且各有独特的漏洞。一旦你决定了谁应该接收什么类型的流量以及应该阻止哪些类型，就可以通过防火墙进行管理。

## 防火墙是如何工作的？

防火墙通过多种机制执行已建立的安全策略，包括以下机制：

- 网络地址翻译 (NAT)

- 基础数据包过滤

- 状态检测数据包过滤

- 访问控制列表 (ACLs)

- 应用层代理

防火墙提供的最基本的安全功能之一是`NAT`，它允许你从网络外部屏蔽（mask）大量信息。这允许外部实体与防火墙内部的实体通信，而无需真正知道其地址。`NAT`是`IPv4`中用于将私有 IP 地址映射到公共 IP 地址的技术。私有 IP 地址是任何人都可以使用的 IP 地址集，根据定义，它们在互联网上是不可路由的。`NAT`可以通过防止在通过`NAT`设备更改地址之前从公司外部直接访问设备来协助安全。这样做的好处是需要更少的公共 IP 地址，从安全角度来看，内部地址结构对外部不可知。如果黑客攻击源地址，他仅仅是在攻击`NAT`设备，而不是数据包的实际发送者。`NAT`在第 3 章中有详细描述。

`NAT`的产生是为了解决与`IPv4`相关的地址短缺问题，许多人认为它对`IPv6`来说是不必要的。强制流量翻译和从外部直接连接中隐藏内部网络细节的额外安全功能，将使`NAT`在`IPv6`时代继续发挥作用。

基础数据包过滤是次常见的防火墙技术，涉及查看数据包、其端口、协议以及源地址和目的地址，并将这些信息与防火墙上配置的规则进行比对。可以禁止向邮件或数据库服务器建立`Telnet`和`FTP`连接，但可能允许相应的服务服务器建立。这是一种基于每个数据包头部信息（如`IP`地址和`TCP/UDP`端口）的简单过滤方法。数据包过滤无法检测并捕获所有不需要的数据包，但它是快速且高效的。

查看所有数据包并确定每个数据包的需求及其数据需要`stateful`（状态）数据包过滤。`Stateful`意味着防火墙维护或知道对话的上下文。许多情况下，规则取决于特定通信连接的上下文。例如，从外部服务器到内部服务器的流量如果是被请求的则被允许，如果没有请求则被阻止。一个常见的例子是请求 Web 。此请求实际上是对多个服务器的一系列请求，每个请求都可以被允许或被阻止。高级防火墙采用状态检测数据包过滤来防止几种类型的不需要的通信。如果数据包来自网络外部并伪装成对网络内部消息的响应，防火墙将没有其被请求的记录并将其丢弃，从而阻止不需要的外部访问尝试。由于许多通信将传输到高端口（`1023`以上），状态监控将使系统确定哪些组高端口通信是允许的，哪些应该被阻止。状态监控的缺点是执行这种类型的监控需要大量的资源和处理，这会降低效率并需要更强大、昂贵的硬件。

* *

![image](img/examtip.jpg)

**考试提示** 防火墙通过检查数据包并根据一组规则选择性地拒绝某些来工作。防火墙充当特定网络节点的门卫或哨兵，隔离流量并允许某些通过而阻止其他通过。

防火墙还可以充当网络流量调节器，因为它们可以配置为缓解特定类型的网络攻击。在拒绝服务和分布式拒绝服务（`DoS/DDoS`）攻击中，攻击者会试图向网络泛洪大量流量。防火墙可以经过调以检测此类攻击并充当泛洪保护器，减轻对网络的影响。防火墙在阻止各种泛洪攻击方面非常有效，包括端口泛洪、`SYN floods`泛洪和 ping 泛洪。

**考试提示** `ACLs`的建立和维护可能耗费大量精力。创建它们是一项简单的任务，但明智地使用它们可以在少量维护的情况下产生安全收益。这对于`DMZ`（非军事特区）和边缘设备等安全区域非常重要，可以在阻止不必要的外部接触的同时，允许已知的内部流量。

路由器的一个严重的操作安全问题涉及对路由器的访问以及对其内部函数的控制。路由器可以使用简单网络管理协议（`SNMP`）和`Telnet`进行访问并进行远程编程。由于路由器的地理隔离，这可能成为一种需要，因为世界上许多路由器可能相隔数百英里，位于不同的锁定结构中。对路由器进行物理控制绝对必要的，因为如果任何设备（无论是服务器、交换机还是路由器）被黑客物理访问，应被视为已被破解；因此必须防止此类访问。确保管理密码绝不明文传输、仅使用安全机制访问路由器，并将所有默认密码重置为强密码是非常重要的。

与交换机一样，路由器管理控制最可靠的访问点是通过串口控制接口或特定的路由器管理以太网接口。这允许访问路由器的控制部分，而无需处理与流量相关的问题。对于路由器地理分布可能有限的公司内部网络，存在允许进行带外远程管理的第三方解决方案。这允许即使从远程位置也能以安全的方式对路由器进行完全控制，尽管需要额外的硬件。

## 负载均衡

某些系统（例如服务器）对业务运营至关重要，因此它们应该是容错措施的对象。容错中用的一种常用技术是`负载均衡`。该技术旨在将处理负载分布到两个或多个系统上。它被用于帮助提高资源利用率和吞吐量，同时也具有增加整个系统容错能力的额外优势，因为关键进程可能会被拆分到几个系统上。如果任何一个系统发生故障，其他系统可以接管其原本正在处理的任务。虽然对整体吞吐量可能会有影响，但操作不会完全中断。负载均衡通常用于处理网站、高带宽文件传输和大型互联网即时聊天 (IRC) 系统。负载均衡通过一系列健康检查工作，这些检查会告知负载均衡器哪些机器正在运行，并通过调度机制来均匀地分配工作。负载均衡对于无状态系统最好，因为随后的请求可以由任何服务器处理，而不仅仅是处理上一个请求的那个服务器。

## 代理

虽然`代理服务器`不是严格意义的安全工具，但它可以用来过滤掉不需要的流量，并防止员工访问潜在的恶意网站。代理服务器从客户端系统接收请求并代表客户端将其转发到目标服务器。代理服务器可以是完全透明的（这些通常称为`网关`或`隧道代理`），也可以在发送请求之前修改客户端请求，甚至在不需要联系目标服务器的情况下为客户端提供服务。目前正在使用的代理服务器主要分为几类：

* **匿名代理**：匿名代理旨在隐藏请求系统的信息，并使用户浏览体验变得“匿名”。这种代理服务通常被那些关注互联网传输个人信息量、以及使用跟踪 cookie 和其他机制跟踪浏览活动的个人使用。

* **缓存代理**：这种代理保留热门客户端请求的本地副本，通常用于大型组织以减少带宽占用并提高性能。当请求被发出时，代理服务器首先检查缓存中是否有请求内容的最新副本；如果有，它将立即为客户端提供服务，而无需联系目标服务器。如果内容过旧或缓存代理没有请求内容的副本，则请求将转发到目标服务器。

* **内容过滤代理**：内容过滤代理检查每个客户端请求并将其与既定的可接受使用策略 (AUP) 进行比较。请求可以通过多种方式进行过滤，包括根据请求的 URL、目标系统、域名或内容本身中的关键词。内容过滤代理通常支持用户级认证，以便对访问进行控制和监控，并对通过代理的活动进行记录和分析。这种代理在学校、企业环境政府网络中非常流行。

* **开放代理**：开放代理本质上是任何互联网用户都可以使用的代理，通常也具有某些匿名功能。这种代理类型一直是争议的话题，辩论的一方是互联网隐私和自由的倡导者，另一方则是执法部门、公司和政府实体。由于开放代理经常被用于绕过公司代理，许多公司尝试阻止员工使用开放代理。

* **反向代理**：反向代理通常安装在网络连接的服务器端，通常位于一组 Web 服务器之前。反向代理拦截所有入的 Web 请求，并可以执行许多功能，包括流量过滤、安全套层协议 (SSL) 解密、提供图形等常见静态内容以及执行负载均衡。

* **Web 代理**：Web 代理专门用于处理 Web 流量，有时被称为`Web 缓存`。大多数 Web 代理本质上都是缓存代理。

在网络环境中部署代理解决方案通常通过设置代理并要求所有客户端系统配置使用代理，或者通过部署一个拦截所有请求的代理来实现（无需客户端配置）。

从安全角度来看，代理在控制和过滤出站请求方面最有用。通过限制员工访问的内容和网站，许多管理员希望避免数据丢失、系统被劫持以及恶意网站感染。管理员还利用代理来执行公司接受使用策略并跟踪资源的使用。

## 安全网关

某些安全厂商将代理功能与内容过滤功能相结合，创建一个名为`安全网关`的产品。安全网关旨在解决针对 Web 流量的安全威胁和漏洞。安全网关通常提供以下功能：

* **实时恶意软件防护**（也称为恶意软件检查）：某些安全网关能够扫描所有出入 Web 流量，检测并阻止恶意软件、间谍软件、广告软件、恶意脚本、基于文件的攻击等不良流量。

* **内容监控**：某些安全网关提供监控正在检查的 Web 流量内容的能力，以确保符合组织策略。

* **生产力监控**：某些安全网关衡量特定用户、用户组或整个组织产生的 Web 流量，以及流量类型。

* **数据保护与合规**：某些安全网关可以扫描 Web 流量，检查发送到组织外的敏感或专利信息，以及社交网络网站或不良网站的使用。
