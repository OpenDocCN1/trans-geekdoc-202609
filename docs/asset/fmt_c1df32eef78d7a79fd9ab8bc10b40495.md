大多数网络管理员宁愿在深夜备份操作执行时待在家里。这就是为什么他们要计划备份操作，以便不必在深夜留在办公室启动它。大多数备份软件支持备份操作的计划，这绝对是在选择备份软件时要寻找的功能之一。

在整体规划备份和灾难恢复时，您需要考虑关于物理位置的许多地理因素：

- **异地存储** 请务必在另一位置存储备份副本，以防火灾、洪水或地震等灾难。

- **距离考量** 您希望异地备份足够近，以便在需要时能快速获取，但同时它应足够远，以免受到影响您当前位置的任何灾难的波及。

- **地点选择** 请务必选择一个能获得消防部门等应急服务快速响应的地点。您还应确保该地点能获得电力公司等公用事业服务的快速响应。此外，请审查周边区域，确保您不在洪水区或高犯罪率区域内。

- **法律影响** 在为您的站点和磁带备份选择物理位置时，请务必了解该国家或州的任何法律，这些法律可能会影响您的数据如何被访问或管理。

- **数据主权** 与上一点相关，请务必了解谁拥有数据并对数据拥有完全的权利和控制权。通过将数据存储在特定国家或州，您是否隐性地赋予了第三方访问数据的权利？对于云存储，您可能需要了解云提供商的服务器位于何处，并确保您的数据放置在您所在的国家内，以便您国家的法律管辖该数据。

# 准备灾难恢复：容错与冗余

准备灾难恢复的很大一部分工作是确保系统正常运行，包括在组件发生故障时。例如，公司会确保服务器中至少有两个电源，这样如果一个电源发生故障，另一个可以继续供电。在本节中，您将了解容错和冗余的不同解决方案。

## 引入冗余

实施网络安全弹性的很大一部分是在不同资产（如硬盘、网络设备和电源）上实施冗余。在本节中，您将了解可用于为这些资产添加冗余的技术，同时也将了解复制技术作为一种添加冗余的方法。

添加冗余可确保资产不存在单点故障。例如，确保服务器中有多个电源，可确保电源方面不存在单点故障。

在创建冗余时，特别是涉及数据和服务的冗余时，您需要确定是要使用本地部署解决方案（即物理网络上的解决方案）还是基于云的解决方案来实现冗余。例如，您可以有一台本地部署的电子邮件服务器，如果它发生故障，可以使用托管在云中的电子邮件服务。使用云解决方案的好处是，如果您想防范物理位置的灾难，不需要寻找备用站点。此外请注意，正如第 16 章所述，您可以将所有资源迁移到云中托管，并利用服务提供商提供的内置冗余。

### 磁盘冗余

要考虑添加冗余的第一个组件是硬盘。您可以实施冗余硬盘解决方案，以帮助防范服务器硬盘上的单点故障。考试需要了解硬盘冗余的两种主要解决方案：

*   **廉价磁盘冗余阵列（RAID）级别** 您可以通过使用 RAID 解决方案来帮助保护数据免受硬盘故障的影响。RAID 允许您创建使用多个硬盘来提供数据冗余的卷。例如，您可以创建一个称为镜像卷的 RAID 卷，将数据存储在两个物理磁盘上，以防其中一个发生故障。您将在本章后面了解 RAID 卷类型。

*   **多路径** 为数据或磁盘添加冗余的另一种方法是使用多路径，也称为多路径 I/O。多路径是创建多条访问数据的路径，无论数据存储在何处。例如，如果您将数据存储在 SAN 上，您的服务器可能有多个连接到 SAN 的光纤通道控制器，而 SAN 由多个交换机组成，因此存在多条访问 SAN 上数据的路径。

### 网络冗余

通过实施 RAID 等磁盘冗余解决方案来实现数据冗余非常重要，但您也应该在网络组件上实现冗余。以下列出了网络组件冗余的两项关键技术：

*   **负载均衡器** 负载均衡器是一个将工作负载分发到多个组件以服务请求的组件。例如，您可以在负载均衡器后面部署多台 Web 服务器，负载均衡器将针对网站的任何请求发送给其中一台服务器。如果您向负载均衡器添加另一台 Web 服务器，则工作负载将分散在所有三台服务器之间——如果一台服务器发生故障，负载均衡器会检测到这一点，然后将未来的请求分发给剩余的两台服务器。您将在本章后面了解更多关于负载均衡的内容。

*   **网络接口卡（NIC）组合** NIC 组合是许多服务器操作系统和设备的一项功能，允许您合并多张网卡的带宽。这用于需要处理大量流量的场景，加快数据包处理速度的一种方法是让多个 NIC 作为一个整体工作。如果一个 NIC 发生故障，组合中的其他存活 NIC 仍可用于发送和接收流量。

### 电源冗余

如前所述，在电源上实施冗余非常重要，这样如果发生电源故障，您仍然有办法为服务器和路由器等关键资产供电。以下是添加电源冗余时的注意事项：

*   **不间断电源（UPS）** UPS 是一种硬件组件，当初始电源故障时提供应急电源。UPS 拥有已充电并随时待命的电池，可在断电时立即为连接的设备（如服务器）供电。电池续航时间相当短，用于正常关闭连接到 UPS 的设备，或等待发电机启动。

*   **发电机** 发电机是一种备用电源，通常使用汽油或丙烷运行，在原始电源故障时提供备用电源。发电机可以手动启动，也可以在转换开关检测到断电时自动启动。

*   **双电源** 您可以在服务器、交换机和路由器等设备中安装多个电源，这样如果一个电源发生故障，设备仍有另一个电源可用。

*   **托管配电单元（PDU）** 托管 PDU 是一种将电力分配给网络机柜或计算机的组件。托管 PDU 允许您远程开启或关闭 PDU 上不同电源插座的电源。

### 通过复制实现冗余

添加冗余的另一种技术是定期将数据从源复制到目标。以下是两种使用复制的常见技术：

*   **存储区域网络（SAN）** 存储区域网络是一组通过高速链路连接的存储驱动器。您可以通过复制将一个 SAN 上的数据复制到另一个站点的 SAN——即所谓的 SAN 到 SAN 复制。这确保了数据位于多个位置，以防某个位置发生灾难。

*   **虚拟机（VM）** 您可以让运行在一台服务器上的 VM 复制到另一台服务器。VM 复制技术允许您控制当前运行哪个 VM。这是确保虚拟机冗余的好方法。

## 非持久性与多样性

Security+ 考试目标中提到了与网络安全弹性相关的非持久性和多样性。*非持久性* 根据定义，是指系统关闭或应用程序关闭时数据丢失。系统具有非持久性的方式如下：

*   **恢复到已知状态** 诸如 Deep Freeze 之类的应用程序可用于将系统恢复到以前的状态。使用 Deep Freeze 时，管理员保存计算机的状态，然后在系统重启时，它会恢复到该保存状态，从而丢失任何更改。这是学校计算机实验室中常见的应用程序。另一个示例是 Windows 系统还原功能，可用于恢复到以前的状态。

*   **最后一次正确配置** 有些工具允许您恢复到之前的正确配置。例如，Windows 有一个启动选项，允许您恢复到您上次登录时的系统配置。

# 实时启动介质

**实时启动介质** 是一种实时操作系统，可从 DVD 或 USB 驱动器启动。例如 WinPE 磁盘或 Ubuntu 的实时版本，它们允许你启动到驻留在可移动介质上的操作系统。实时介质允许你从实时操作系统运行工具，但在关闭系统后不会永久存储数据。

在实施这些冗余技术中的任何一项时，确保解决方案的多样性非常重要。多样性通过确保如果解决方案的某一部分受到攻击并被攻破，同一攻击不会在解决方案的下一部分成功，从而增加了安全性。将多样性融入安全解决方案的方法有很多：

- **技术**：使用不同的技术。例如，你可以使用 NIC 组合为每台服务器的网卡提供冗余，使用集群为数据库服务提供高可用性，并使用 RAID 为存放数据库文件的存储驱动器提供冗余。

- **供应商**：使用不同供应商的产品以增加多样性。一个很好的例子是防火墙——考虑在网络的不同层使用来自不同供应商的防火墙产品。

- **加密**：在每次实施中使用不同的加密算法和不同的密钥，这样如果加密被破解，同一破解方法将不适用于每一次加密使用。

- **控制**：使用不同类型的安全控制组合来保护资产。例如，在端点（工作站）上，你应该修补系统，使用防病毒/反恶意软件，使用基于主机的防火墙，并确保用户接受过良好的计算和互联网实践教育。这些控制中的每一个都会增加工作站的安全性。

## 理解 RAID

执行数据备份是个好主意，将该备份的副本存储在异地是个更好的主意，有助于确保你能从任何类型的灾难中恢复。仅依赖备份解决方案的问题之一是，如果服务器上的驱动器发生故障，用户将需要等待你更换驱动器，然后恢复所有数据——根据你要恢复的数据量，这可能需要数小时。

为了避免在工作时间的白天中间更换驱动器并恢复数据，你可以利用容错解决方案，例如*廉价磁盘冗余阵列*，也称为*独立磁盘冗余阵列*。RAID 是一种将数据跨驱动器复制的技术，因此如果一个驱动器发生故障，解决方案中的其他驱动器可以提供数据。好处是，如果驱动器发生故障，你可以等到工作日结束时再修复问题，因为你解决方案的冗余性将确保没有数据丢失（RAID 0 的情况除外）。

RAID 有不同的类型，称为级别，每个级别提供不同类型的冗余和不同的优势。以下小节介绍不同网络操作系统支持的常见 RAID 级别。

### RAID 0

RAID 0 级称为*条带化*或*条带卷*。使用 RAID 0 时，多个磁盘用于创建一个卷；当数据保存到该卷时，数据会被拆分并分散到卷中的所有磁盘上。条带卷的优势是所有磁盘同时写入，从而带来性能提升。例如，如果你将一个 12MB 的文件保存到驱动器 D:，而驱动器 D: 是由四个磁盘组成的条带卷，我们可以概括保存操作：每个磁盘将保存 3MB 数据，所有磁盘将同时工作以完成总计 12MB 的保存操作。如果只有一个磁盘执行该 12MB 的保存操作，将需要四倍的时间。

RAID 0 的缺点是不进行数据复制；因此，如果卷中的一个硬盘发生故障，你将无法读取任何数据。RAID 0 严格用于读写操作的性能优势。图 18-2 展示了 RAID 0 设置的示例。

请注意，磁盘已从基本磁盘转换为动态磁盘。Windows 要求使用动态磁盘才能使用 RAID 卷类型。旧版 Windows 要求你在创建 RAID 卷之前将磁盘从基本磁盘转换为动态磁盘，但较新版本的 Windows 会在你创建 RAID 卷时自动为你完成此操作。

![Image](img/exam.jpg)

> **RAID 0，即磁盘条带化，将数据分割到卷中的所有磁盘上。RAID 0 同时向所有磁盘写入数据，减少了读取或写入数据所需的时间。RAID 0 中没有容错能力；它严格用于性能优势。**

### RAID 1

RAID 1 称为*磁盘镜像*。磁盘镜像使用两个硬盘，将数据从一个驱动器复制到另一个驱动器。RAID 1 在卷的另一个成员上存储数据的第二个副本这一事实意味着该解决方案确实提供了容错能力。*容错* 是指如果解决方案的某一部分发生故障，另一部分将接管工作负载，解决方案将继续运行且不会丢失数据的概念。

如果镜像中的某个磁盘发生故障，您可以通过打破镜像、添加一个新的正常工作磁盘，然后从未发生故障的现有磁盘重建镜像来替换故障磁盘。一旦您重新建立了镜像，您就恢复了容错能力。

图 18-3 显示了镜像卷的概念。当用户将数据保存到镜像卷时，数据会被写入组成该卷的两个磁盘。
