
评估系统或网络安全性的另一种技术是深入研究系统的架构。例如，计算机处理器使用环形架构来运行软件（请参见图 20-4）。运行在较低环（环 0 是最低层）中的软件比运行在较高环中的软件拥有更高的特权。环形架构的部分机制在于：运行在某一环中的软件可以访问该环或更高环（数字更大的环）中的资源。因此，运行在环 0 中的核心操作系统代码可以访问环 1、2 和 3 中的任何内容。然而，运行在环 3 中的系统应用程序无法访问核心操作系统代码，因此也无法破坏这些进程。

### 设计评审

您可以用来评估安全性的另一个工具是在解决方案实施前后执行设计评审。从一开始就识别系统的安全顾虑也至关重要，这样您才能宣称具有“`secure by design`”（安全设计）地位（意味着从解决方案创建的始至终都将安全作为重点）。一旦解决方案完成，无论是应用程序还是网络解决方案，都要进行设计评审，确保实际实施的内容确实是作为解决方案所请求的内容。

## 执行安全评估

本节将为您提供执行优秀渗透测试所应采取步骤的良好概览。请务必严格遵循每个步骤，以保护您作为渗透测试人员的自身利益。您不希望公司或组织事后找上门来，声称他们并未要求您执行该测试。

执行安全评估时，请确保花时间规划步骤并遵循一种方法论。该方法论可以是您自己的，也可以遵循行业标准方法论（推荐）。作为安全专业人员，您应了解以下一些标准方法论：

- **OVAL** — 开放漏洞评估语言是一项用于评估系统漏洞的国际标准。OVAL 评估分三个阶段：表征系统信息、评估漏洞和报告漏洞。请访问 [`oval.mitre.org/about/index.html`](http://oval.mitre.org/about/index.html) 了解更多关于 OVAL 的信息。

- **OCTAVE** — 运营关键威胁、资产和漏洞评估是一种自我指导的安全评估方法论。“自我指导”意味着组织从自己的员工中选拔一个团队来进行安全评估。OCTAVE 包含四个阶段：(1) 制定与业务目标一致的风险管理标准，(2) 为每个信息资产创建档案以明确安全需求，(3) 识别针对这些资产的威胁，以及 (4) 识别和分析风险并开始缓解措施。请访问 [`www.cert.org/octave/`](http://www.cert.org/octave/) 了解更多关于 OCTAVE 的信息。

- **OWASP** — 开放 Web 应用程序安全项目是一个将 Web 应用程序安全测试流程标准化的项目。您可以访问 [`www.owasp.org`](http://www.owasp.org) 了解更多信息。OWASP 发布了一些关于 Web 应用程序测试和代码审查的优秀指南。

### 威胁狩猎

*威胁狩猎* 是指在资产遭到攻击者攻击和破坏之前，识别针对公司资产的威胁这一行动的术语。威胁猎手监控网络和系统活动，以发现其环境中可能存在的潜在新威胁和漏洞。威胁猎手可能会使用多种工具，包括以下内容：

- **情报融合** — 情报融合是收集单独的“情报”流或监控数据，并将这些数据结合在一起，以获得对当前态势的完整图景。例如，在 IT 安全领域，您可以“融合”防病毒数据、网络传感器数据、服务器日志和防火墙连接信息，以证明攻击的发生及其影响范围。

- **威胁情报源** — 威胁情报源是通过网站发布和分发的威胁指标列表，用于自动共享威胁指标。威胁情报源数据库可能包含恶意 IP 地址或恶意电子邮件发件人等信息。其好处是，任何订阅该情报源的人都能在信息更新时获知这些情报。

- **通告和公告** — 可以发送安全通告和安全公告，以通知公众新的安全威胁。

- **机动** — 机动是指为获得竞争优势而进行战略性移动的概念。在威胁管理中，您的策略应具有动态性以发现新威胁（例如，在网络的特定区域部署蜜罐以检测威胁）。

### 漏洞扫描

执行漏洞评估时，您可以使用漏洞扫描作为一种技术，以自动化识别环境中漏洞的过程。本节列出了执行漏洞扫描时应考虑的多项因素，以及识别漏洞的不同方式。

#### 漏洞扫描的注意事项

使用漏洞扫描器自动化识别漏洞的过程时，您应牢记以下要点：

- **侵入式与非侵入式** — 重要的是要了解，漏洞扫描被视为非侵入式扫描，因为您并非真正尝试入侵系统或利用漏洞（渗透测试才会尝试利用系统）。

- **有凭据与无凭据** — 执行漏洞扫描时，您应确保以未经身份验证的用户（无凭据）身份执行一次扫描，以了解向网络中未知人员暴露了哪些信息。然后您应以管理员账户登录并执行扫描，以便收集尽可能多的系统信息。

- **误报** — 与任何类型的扫描一样，密切关注误报非常重要——即被报告为漏洞但实际并非漏洞的情况。

- **漏报** — 漏报可被视为比误报更严重，因为它们是实际发生但未被系统检测到的事件。就漏洞扫描而言，漏报是指存在但未被漏洞扫描器识别出的漏洞。

#### 检查类型

正如本章前面所讨论的，漏洞扫描器可以对系统执行多种不同类型的检查：

- **配置审查** — 漏洞扫描器可以检查系统的配置，并向您报告应更改的任何脆弱设置。

- **日志审查** — 漏洞扫描器可能会审查系统上的日志文件，以识别可能被视为可疑的已发生事件。

- **应用程序** — 漏洞扫描器可能会对应用程序执行漏洞检查，并查找应用程序设计中的缺陷。

- **Web 应用程序** — 存在专门针对 Web 应用程序的漏洞扫描器，例如 `Nikto`，它们会查找网站上可能存在的常见漏洞。

- **网络** — 漏洞扫描器可能具备扫描网络上多个系统以及扫描网络设备（如交换机、路由器和打印机）的能力。

#### 理解 CVE 和 CVSS

### 常见漏洞与暴露 (CVE)

**常见漏洞与暴露 (CVE)** 是针对不同操作系统和产品的公开披露漏洞的列表。该已知漏洞列表由 MITRE 在 [`cve.mitre.org/cve`](https://cve.mitre.org/cve) 进行管理。每个漏洞都会被分配一个 CVE ID、描述、日期以及该漏洞的任何相关评论。您可以手动搜索 CVE，或者许多漏洞扫描器可以为您搜索它，以报告有关漏洞的详细信息。

### 常见漏洞评分系统 (CVSS)

**常见漏洞评分系统 (CVSS)** 是一种用于报告漏洞严重程度级别的标准评分系统。例如，CVSS 评分为 1 或 2 的漏洞不被视为严重，但 CVSS 评分为 9 的漏洞被视为严重漏洞，应立即修复或打补丁。

许多细节因素都会纳入 CVSS 评分的计算中，例如漏洞是否可以被远程利用（风险较高）或必须在本地系统上才能利用。CVSS 评分还考虑了诸如漏洞是否对机密性、完整性或可用性构成风险等特征。

# 认证目标 20.03

## 执行渗透测试

执行渗透测试时，您是在模拟组织从真实攻击者那里会经历的真实攻击。这意味着您将建立一套常见的渗透测试工具包，这些是攻击者用来攻破系统、破解加密或窃听通信的程序。

## 渗透测试中使用的注意事项和技术

在深入渗透测试的有趣部分（即使用执行渗透测试的工具）之前，您需要了解许多注意事项和技术。在本节中，您将学习许多渗透测试术语，Security+ 考试目标专门引用了这些术语。

### 测试类型

执行安全测试，特别是渗透测试时，请理解存在不同类型的测试。您可以执行以前称为黑盒测试、白盒测试或灰盒测试的测试。以下概述了三者之间的区别：

- **未知环境测试**  

  以前称为 `black box` 测试。执行未知环境测试时，或聘请渗透测试人员执行测试时，目标是测试人员不掌握组织或其网络配置的任何信息。测试人员必须充当黑客，自行发现组织及其配置的详细信息，然后模拟攻击。这种测试耗时最长，因为测试人员必须在尝试攻破资产之前弄清楚组织拥有哪些资产。

- **已知环境测试**  

  以前称为 `white box` 测试。在已知环境测试中，您（或您聘请的顾问）会获得组织资产和配置的所有详细信息。这种测试的目标是查看系统是否会被攻破。虽然这种测试比未知环境测试快，但它无法让测试人员了解他人发现组织信息可能有多容易或多难。

- **部分已知环境测试**  

  以前称为 `gray box` 测试。部分已知环境测试介于两者之间：测试人员获得关于组织及其配置的一些详细信息，但仅限于有限的详细信息。例如，测试人员可能获得组织使用的 IP 地址列表，并必须弄清楚这些 IP 地址上运行着什么，然后模拟攻击。

![Image](img/exam.jpg)

> **Security+ 考试目标使用 `已知`、`未知` 和 `部分已知环境测试` 这些术语，但我发现考试中仍存在对黑盒、白盒和灰盒测试的引用。因此，为了备考认证考试，请了解这两套术语。请记住，黑盒测试是指测试人员未获得任何网络设置详细信息，而白盒测试则是指测试人员获得环境的所有详细信息。**

### 渗透测试概念

执行渗透测试时，您应该熟悉一些核心概念。以下概念列表包含 Security+ 目标确定的关键点，但这些并非唯一需要了解的概念（PenTest+ 涵盖了执行渗透测试的更多细节）：

- **交战规则**  

  交战规则应在渗透测试的初始阶段制定。它们是渗透测试的规则，例如应测试什么、何时进行测试，以及谁被允许与渗透测试团队通信。

- **横向移动**  

  横向移动是指利用已攻破的系统来攻破网络上的另一个系统。例如，在一台服务器上获取密码哈希后，渗透测试人员可能会尝试使用密码哈希连接到一个不存在漏洞的系统，这种技术称为 `pass-the-hash`（传递哈希）。

- **漏洞赏金**  

  漏洞赏金是向在软件中发现缺陷并将该缺陷报告给软件供应商的人员支付的补偿和认可。

- **跳板攻击**  

  跳板攻击是指测试人员攻破一台服务器（如 Web 服务器），然后利用该系统访问连接到同一网络的其他系统。重要的是要注意，渗透测试是一个漫长、拖沓的过程，类似于黑客攻击，在最终系统被攻击之前可能需要花费时间。

### 被动和主动侦察

执行渗透测试时，您将执行被动和主动侦察，即通过不与目标系统通信（被动）或通过扫描目标系统（主动）来发现信息。以下是在渗透测试期间用于发现资产的一些技术：

#### 无人机

您可以使用无人机飞越设施，拍摄土地布局和建筑物的视频录像。这有助于您了解物理安全控制中的弱点，例如了解围栏、警卫和出口的使用情况。

#### 战争驾驶

战争驾驶是一种无线网络攻击技术，攻击者驾驶车辆四处移动，使用无线扫描器（如 `Kismet`）来发现无线网络及其特征，例如操作信道、频率和配置的安全协议。

#### 战争飞行

战争飞行是战争驾驶的一种形式，攻击者使用低空飞行的私人飞机扫描区域以寻找无线网络。使用无线扫描器（如 `Kismet`），攻击者在 1500 英尺的高度飞行，以发现大量无线网络。

#### 踩点

正如您将在本章后面了解到的，`footprinting` 是侦察的另一个术语，即发现有关预期目标的信息。您可以使用互联网资源被动地发现有关公司的信息，也可以使用扫描工具主动发现目标网络上运行的系统的信息。

#### OSINT

您可以在互联网上找到大量关于公司的信息，例如电子邮件地址以及连接到互联网的服务器或设备。使用开源情报 (OSINT) 工具，您可以轻松检索公开可用的公司信息。`Maltego` 是一个 OSINT 工具的示例，它可以收集公司的电子邮件地址、文件、电话号码、DNS 记录、IP 地址和资产地理位置。

### 演练类型

在执行渗透测试时，您可以使用不同类型的测试。您可能执行渗透测试是为了尝试入侵公司资产（红队的目标），或者您的目标可能是查看防御团队（即蓝队）能否检测到攻击正在发生并将其阻止。以下是贵公司可能雇佣的不同安全团队：

#### 红队

红队是采取系统性方法攻击系统并尝试绕过安全控制的网络安全团队。他们是攻击者。

#### 蓝队

蓝队是负责检测攻击并通过在攻击初期将其阻止来保护公司资产的网络安全团队。他们是防御者。

#### 白队

网络安全中的白队是监督安全测试、记录红队和蓝队双方进度并分配分数的团队。白队还会审查红队和蓝队创建的安全报告，根据其准确性对它们进行评级。

#### 紫队

网络安全中的紫队是同时执行红队和蓝队职能的团队。

![Image](img/exam.jpg)

**考试提示：请记住，红队负责在安全测试期间对系统执行攻击（坏人），而蓝队负责检测攻击并防止妥协（好人）。**

### 理解黑客攻击过程

您可以通过遵循黑客攻击过程来执行渗透测试，这是黑客在计划攻击组织时遵循的方法论。以下各节概述了黑客攻击过程的阶段。

#### 画像

黑客攻击过程的第一阶段称为侦察阶段或画像阶段。在此阶段，黑客使用互联网资源发现有关组织的信息。以下是黑客收集组织信息的一些示例方法：

##### 网站

黑客访问组织的网站以获取联系人姓名、电话号码和电子邮件地址，这些可用于社会工程学攻击。黑客还会查看招聘启事，了解组织正在运行什么软件。例如，如果组织正在寻找 Exchange Server 管理员，那么它很有可能正在运行微软的电子邮件服务器。

##### Google

黑客将花费一些时间在 Google 上搜索他们想要攻击的组织的特定信息。在此步骤中，黑客将使用被称为“Google 黑客语法”的 Google 关键字来定位有关组织的特定信息。您可以在 Google 中用于执行搜索的关键字示例包括：`site:` 用于搜索特定网站的内容，`inurl:` 用于搜索网站 URL 中的内容，以及 `filetype:` 用于搜索特定文件，如 PDF 或 Word 文件。以下是一些您可以使用的 Google 搜索示例：

##### DNS 画像

一旦黑客掌握了组织购买的 IP 地址，他们就准备好进入下一阶段——扫描阶段。但在离开画像阶段之前，黑客将尝试从组织的 DNS 服务器检索信息。以下代码列表显示了黑客使用 `dig`（一种流行的 Linux 程序）查询 DNS 并从 DNS 检索信息：

```
dig www.certworld.loc
```
此命令报告 www.certworld.loc 的 IP 地址。

```
dig certworld.loc MX
```
