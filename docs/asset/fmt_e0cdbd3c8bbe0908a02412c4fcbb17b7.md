
事件响应以某事的形式开始并演变成另一种形式的情况并不罕见。特别是当涉及可能具有法律影响的问题（例如取证调查）时，在应急包里准备一份计划副本是一个好主意。这样，即使你与网络断开连接，你也会知道在遇到的任何情况下被预期或要求做什么。

### 事件日志

每位优秀的调查员都会做笔记。当你进行复杂的调查时（大多数数字取证调查都是如此），记录你所采取的每一个行动和正在考虑的每一个假设是非常关重要的。这种详尽程度最重要的原因是，你的结论有效性仅取决于你的过程是否具有可重复性。换句话说，任何可以访问你相同证据的合格个人都应该遵循你的笔记并获得与你相同的结果。在应急包里放一个笔记本和一支笔可以确保你随时准备记录你所做的事情。

### 电话/升级列表

如果现场情况与你开始调查时预想的不符，你可能需要给某人打电话通知他们重要的进展，或请求执行某些操作的授权。虽然电话/升级列表实际上应该是你事件响应计划的一部分，但将其作为你应急包中的一个重要物品单独列出是值得的。

### 章节总结

数字取证调查需要极高的纪律和对既定流程的严格遵守。对这些活动采取草率的方法可能意味着成功解决事件与目睁睁看着威胁者实施犯罪行为并逃脱之间的区别。挑战在于如何在对不需要这种程度努力的事件做出快速响应，与尽早识别那些足够早调整团队应对策略的案例之间取得正确的平衡。因为你可能不知道哪些事件会升级为取证调查，所以你应该随时准备在没有任何通知的情况下以这种方式执行。

`CSA+` 考试将要求你了解四步流程（扣押、获取、分析、报告）以及你在每个阶段采取的行动。例如，你可能会看到这样的问题：向你展示一个流程某部分已经完成的场景，并询问你下一步做什么。这可能要求你熟悉如何使用一些最常用的工具，例如 Linux `dd` 工具。虽然你可能不会看到要求你发布带参数的命令的问题，但你可能需要解释此类工具的输出，并对可能发生的情况进行某种简单分析。

### 诊断简介

英语单词 *diagnosis* 源于希腊语 *diagignōskein*，字面意思是“彻底了解”。因此，诊断意味着能够看透错杂事实，聚焦于相关事实并找到真实原因。与好莱坞电影不同，现实世界中的安全事件会为你提供许多误导性选择，因此保持专注至关重要。

### 网络相关症状

我们从这里开始，因为你可能会从外部向内部开始。我们的网络传感器通常会提供某些出现异常的首要指标。有了这些信息后，我们就可以询问主机以及运行在它们上的进程。在接下来的讨论中，我们假设你已经通过各种传感器构建了网络，我们将使用它们的输出。

### 带宽利用

在计算中，*带宽*（Bandwidth）被定义为数据通过介质的速率，通常以每秒比特计。网络的设计是为了在峰值使用时间支持组织的需求，但在非高峰期间通常有空余容量。每个网络都有自己的利用模式。攻击者可以通过两种方式利用这些特性：首先，有耐心的攻击者可以使用“低速缓慢”的方法在用量高峰期间隐藏数据外泄；然而，大多数攻击者会尝试快速下载敏感信息，从而产生明显的信号。

### 信标 (Beaconing)

攻击者经常暴露马脚的另一种方法是使用常用方法来与受感染主机保持联系。大多数防火墙的配置为对入站连接请求非常谨慎，但对出站连接则较宽松。最常用的恶意软件命令与控制（`C2`）方案让受感染主机定期向 `C2` 节点发送消息或信标。`Beaconing` 是感染计算机与外部控制器之间的周期性出站连接。这种信标行为可以通过其两个共同特征检测到：周期性和目的地。虽然某些恶意软件变种会随机化信标周期、目标地址或两者，但大多数仍然具有可预测的模式。

通过简单的视觉检查来检测信标极其困难，因为连接通常很短（每个方向可能只有几个数据包），并且很容易消失在典型网络节点的流量中。进行端点分析并查看给定主机与任何其他主机通信的频率要容易得多。要做到这一点，你需要按照内部源地址对流量日志排序，然后按目标地址排序，最后按时间排序。这样，典型的信标就会跳出来并变得显而易见。

**注意** 某些合法连接在你的网络上看起来像信标。我们个人经验中的一个例子是某些高端软件，它们会定期检查许可服务器以确保其被允许使用。

### 不规则的点对点通信

大多数网络流量遵循熟悉的客户端/服务器范式，即有（相对）较少的已知服务器为较多计算机提供服务，而这些计算机本身通常不是服务器。显然，存在例外情况，例如 n 层架构，其中前端服务器与后端服务器进行通信。尽管如此，这种范式解释了大多数网络流量的本质，至少在我们的组织内部区域是如此。在架构良好的公司网络中，两个对等工作站之间进行通信是稀见的现象。这种点对点通信通常是可疑的，并可能表明主机已受感染。

复杂的攻击者在攻破初始入口点后，往往会深入渗透你的网络。无论他们拥有的第一个主机是某个点击了恶意链接的倒霉员工的工作站，还是一个配置不当的外部服务器，它很少是攻击者的最终目标。`Lateral movement`（横向移动）是攻击者在网络中建立立足点后，攻破额外主机的过程。实现此点的最常见方法是利用主机内置的信任工具。他们只需要有效的用户名和密码，就可以在 Windows 中使用 `SMB` 和 `PsExec` 工具或在 Linux 中使用 `SSH`。所需的凭据可以通过多种方式获取，包括受感染主机上缓存/存储的凭据、密码猜测以及对某些 Windows 域的哈希传递攻击（pass-the-hash attacks）。以下是需要关注的列表：

- **非特权账户连接到其他主机**：除非遵循了某个（对你而言）已进程（例如，共享打印机的主机），否则任何普通用户到对等主机的连接都可能表明已受感染，并应对此进行调查。

- **特权账户从普通主机连接**：系统或域管理员完全可能在别人的计算机上工作（例如，修复用户问题），并需要使用特权凭据连接到另一个资源，但这应该是罕见的。我们在第 3 章中讨论跳板机时已经描述了为什么这会导致问题。这些连接应该引起你的注意。

- **重复的远程登录失败**：许多攻击会尝试通过简单猜测远程调用的密码来实现横向移动。任何重复失败登录尝试的事件都应及时调查，特别是如果其后紧跟了成功的登录。

检测此处描述的不规则点对点通信可能极其困难，因为你看到的只是合法用户使用信任工具连接到网络内的其他计算机。然而，背景至关重要，作为分析师应该问的问题是：该用户账户是否有正当理由从此主机连接到另一个资源？

### 战地经验：包分析

我们的一位同事曾告诉我们，他对一个安全性相当良好的组织进行了一次黑盒渗透测试。在几天毫无进展后，他决定给一名员工发送一个包裹（根据其社交媒体资料证明，该员工将离开办公室几周）。包里有一部手机，以及一张开给该员工的金额为全市场价值的发票（以确保手机最终会被退）。手机中加载了无线黑客工具，并通过蜂窝数据网络连接回他的工作站。一天之内，电池就耗尽了，但我们的同事已经能够在不被察觉的情况下将他的非法设备连接到无线网络并攻破了多个工作站，而这一切都是在办公室里地完成的。是的，他确实通过邮件收回了手机。

### 网络上的非法设备

构建和维护安全网络所能做的最好的事情之一就是了解网络上有什么。硬件和软件资产管理是构建你其他安全工作的基础基石。如果你不知道哪些主机属于你的网络，那么你就无法判断何时有未经授权的主机接入。遗憾的是，许多组织都缺乏这种资产意识，这使得攻击者很容易将他们的设备接入网络并对其进行攻破。

攻击者连接主要有两种方式：物理上通过网络插座和无线连接。虽然你可能认为很容易检测到坐在大堂里并将笔记本电脑连接到墙壁的可疑人物，但真正的威胁是那些将自己的无线接入点连接到网络的员工，以便在之前可能没有无线接入的地方提供无线访问。虽然这种情况罕见，但其破坏性足以让我们提及。更可能的情况是攻击者通过无线连接。

无论何种情况，你都需要一种方法来判断何时有新主机连接。最好的方法是部署网络访问控制（`NAC`），以确保每个设备经过身份验证、可能的扫描，然后加入适当的网络。`NAC` 解决方案随处可见，并为你提供细粒度的控制以实施你的策略。它们还为你提供了集中日志，可用于检测非法设备的尝试连接。

如果你在环境中没有 `NAC`，你的下一个最佳选择是让所有来自接入点（`APs`）的日志发送到中央存储中，你可以在其中寻找未见过的物理（`MAC`）地址。显然，这个过程繁琐得多且效率较低。攻击者绕过这种监控最简单的方法是将 `MAC` 地址更改为合法用户使用的地址。挑战在于，如果该用户也在网络上使用相同的 `MAC` 地址，可能会导致问题，但人们可以简单等待用户离开后再尝试冒充。

### 扫描遍历

某些攻击者（特别是那些对规模而非隐蔽性更感兴趣的人）在攻破首台主机后，会使用扫描遍历（scan sweeps）来绘制环境。他们可能会下载并运行类似 `nmap` 的工具，也可以使用自定义脚本，甚至使用其在暗网上购买的黑客工具包中的功能。无论他们采取何种方法，网络上的症状大多是相同的：一个主机对大量端点产生异常大量的连接尝试（但通常不会建立完全连接）。

检测扫描遍历的一种良好方法是关注 `ARP` 消息。地址解析协议（`ARP`）是接口确定数据包最终终目的地的下一跳地址的手段。`ARP` 请求仅仅是节点向其局域网（LAN）内的所有其他节点广播提问：“谁负责往此 IP 地址的流量？”如果该 IP 地址属于同一局域网内的另一台主机，则该主机将通过提供自己的媒体访问控制（`MAC`）地址或物理地址来响应。此时，源主机将把封装在点对点以太网帧中的 IP 数据包发送到响应者的接口地址。反之，如果 IP 地址属于不同的局域网，默认网关（即 IP 路由器）将通过声称由其负责来响应。

### 主机相关症状

在注意到像我们在前几节中讨论的异常网络行为后（或在收到 IDS/IPS 或其他传感器的警报后），你的下一步是查看可疑主机，看看该异常行为是否有良性的解释。遵循证据而不是急于下结论是重要的，因为仅仅通过检查网络流量或行为，往往很难获取入侵的清晰全貌。

### 运行进程

曾有人说过：“恶意软件可以隐藏，但它必须运行。”当你响应事件时，你的首要任务之一应该是检查运行中的进程。每个操作系统都提供了一个执行此操作的工具，但你必须警惕过度信任这些工具，因为攻击者可能使用 rootkit 在这些工具面前隐藏他们的活动。尽管如此，大多数事件并不涉及此类复杂的隐藏手段，因此在 Linux 中运行 `top` 或 `ps`，或者查看 Windows 任务管理器中的进程选项卡（并显示所有用户的进程）会非常有帮助。

**考试提示** 对于我们许多人来说，在决定是否捕取易失性内存之前，首先会查看系统上运行的进程。在考试中，最好先捕取内存，然后再查看运行的进程。出于教学考虑，我们在这里反倒了顺序。

在典型系统中，运行的进程列表可能只有几十个。其中许多进程的名称类似于 Windows 的 `svchost.exe` 和 `lsass.exe`，或 Linux 的 `kthreadd` 和 `watchdog`。除非你知道什么是正常的，否则你将很难发现可疑进程。解决这一挑战的方案是对你环境中的主机建立基准，并记录你在健康系统中通常看到的进程。这将允许你快速过滤掉（可能是）好的进程，并关注剩余的内容。在执行此操作时，请记住，攻击者通常会使用与良性进程相似的名称，特别是当你正在快速扫描列表时。常见的示例包括在 `svchost.exe` 的末尾添加 `s`，或将 `lsass.exe` 的第一个字母替换为数字 `1`。显然，任何此类更改都应该自动接受调查。

进程揭示其邪恶本质的另一种方式是通过它们所利用的资源，例如网络套接字、CPU 周期和内存。恶意软件在某个时刻不具备某种网络套接字的情况是极罕见的。一些复杂性不那么高的恶意软件甚至会让这些连接保持很长时间。因此，如果你有一个从未见过的名称的进程，并且它正连接到外部主机，你可能想要进一步挖掘。查看哪些套接字属于哪些进程的简单方法是使用 `netstat` 命令。遗憾的是，每个操作系统实现此工具的方式略有不同，因此你需要使用正确的参数，如下所示：

- Windows

```
netstat -ano
```

- Mac OS

```
netstat -v
```

- Linux

```
netstat -nap
```
