
让我们逐步遵循该步骤。根节点查询`crust-size`。意识到该值较小时，分类器将示例沿着右边缘向下，对`shape`（形状）进行测试。在这里，似乎只有两种可能的结果：圆形或正方形，但不是三角形。原因是，创建这棵树的人并不知道`crust-size=small`的物体可能是三角形的：在训练集中没有发现任何此类种的样本。因此，似乎没有理由创建相应的对应边。即使创建了该边，也不清楚它应该引向何处。

在计算机程序中实现此分类器的工程师必须确保程序在出现“缺失边”时“知道”该做什么。随机选择类别或倾向于选择频率最高的类别是最显而易见的可能性。

## 6.2 决策树的归纳

![image](img/chapter_title_below.png)

我们将从一个非常粗糙的归纳算法开始。将其应用于训练集，我们会发现可以获得许多不同的备决策树。简短的讨论将让我们相信，在这些树中，较小的是更优的。这一观察将促使我们改进该技术，从而为后续章节做好准备。

![image](img/image576.png)![image](img/image630.png)![image](img/image358.png)

### 分治与攻

让我们尝试手动创建一个决策树。假设我们决定根节点应该测试`shape`的值。在训练集中，发现了三种不同的结果：圆形、三角形和正方形。对于每种结果，分类器都需要一条从根节点引出的单独边。第一个由`shape=circle`定义，将紧随示例`TC e1; e2; e8`；第二个由`shape=triangle`定义，将紧随示例`TT e4`；最后一个由`shape=square`定义，将紧随示例`TS e3; e5; e6; e7`。

每个分支本质上都是相同类型的子问题。我们继续这个过程，直到到达一个所有示例具有相同类别的叶节点。在我们的情况下，`shape=circle`的叶节点包含`TC e1, e2, e8`，它们都是正样本。`shape=triangle`的叶节点包含`TT e4`，它是负样本。`shape=square`的叶节点包含`TS e3, e5, e6, e7`，它是正负样本的混合。

为了解决`TS`叶节点，我们必须选择另一个属性。让我们选择`crust-size`。如果`crust-size`很小，我们有`e5`和`e6`，它们是正样本。如果`crust-size`大，我们有`e3`和`e7`，它们是负样本。我们还需要一个属性，比如`filling-size`。如果`filling-size`很小，我们有`e3`（正样本）；如果`filling-size`大，我们有`e7`（负样本）。

这个过程一直持续直到每个叶节点都是纯净的。

注意，如果我们先选择`filling-size`，我们可能根本不会使用`crust-size`。生成的树会有所不同，但执行的任务是相同的。这说明对于同一个训练集有许多可能的决策树。

### 备选树

考虑属性的顺序会显著影响结果树的结构。如果我们从`filling-size`开始，树的外观会非常不同。例如，如果`filling-size`很小，我们将有`e1, e2, e5, e6`，它们并不全为正。如果`filling-size`大，我们将有`e3, e4, e7, e8`，它们并不全为负。

我们随后需要使用其他属性划分这些子集。这导致了一个观察：分治算法对属性的初始选择非常敏感。为了改进这一点，我们需要一种系统的方法在每一步中选择最佳属性。

### 树的大小

树的大小通常由它包含的节点数来衡量。通常更倾向于较小的树，因为它更容易解释且较不容易过拟合。然而，“最佳”树并不总是最小的那个。另一个标准是所需的测试次数。

例如，在一个形状几乎总是圆形或三角形的领域（很少是正方形），6.1b 所示的平均测试次数不会超过 1，因为`shape=circle`和`shape=triangle`直接指向叶节点。在这种情况下，大树会导致更少的测试。

### 小树与大树

倾向小树有几个原因。其中之一是可解释性。树越大，人类专家越难以分析、解释、甚至纠正一个测试次数不超过几次的决策树。

小树的另一个优势是倾向于消除无关和冗余信息。虽然 6.1a 使用三个属性，但 6.1b 的较小树同样很好——不需要考虑`crust-size`。这种节省在属性值获取昂贵或耗时的领域非常有用。

最后，大树容易过拟合训练示例。这是因为分治方法不断将训练集划分成越来越小的子集，这些划分的数量等于树中的属性测试次数。最终，训练子集可能会变得非常小，以至于类别可能由于偶然或噪声在剩余的正负样本中具有不同的值而被分离。

```

```

得到的结果`H.T; at/`是系统的熵，在该系统中，对于每个训练示例不仅知道类别标签，还知道`at`的值。很容易证明这种差异不会为负；通过考虑`at`只能获得信息，永远不会丢失。但在某些罕见的情况下，`I.T; at/` = 0，这意味着也没有获得任何信息。

## 属性贡献的信息量

`at`贡献的信息量是考虑`at`之前的熵与考虑该属性之后的熵之间的差值：

```
I.T; at/ = H.T/ - H.T; at/
```

将公式 (6.5) 分别应用于每个属性，我们可以找到哪些属性提供了最大的信息量，并作为表 6.2 中算法第一步中“根节点”测试的最佳选择。
