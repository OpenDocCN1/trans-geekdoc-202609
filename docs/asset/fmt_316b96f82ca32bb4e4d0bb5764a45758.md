
操作员设置和系统状态信息通过标题为“输入/输出”或“I/O”的模块进行输入和获取。`I/O` 模块可以是控制器的组成部分，也可以位于某个远程位置。`I/O` 模块的一部分可能专门用于显示和控制机构，使人工操作员能够与控制系统进行交互。

从控制器发出的纠正信号可以直接施加到 `执行器` (`actuator`) 模块，也可以施加到一个可选的输出信号转换器，用于使控制器的输出信号与执行器兼容。执行器的任务是施加必要的纠正动作，以将过程变量调节到既定的设定点。典型的工业控制执行器包括电动机启动器、气动阀或电磁阀等设备。

为了理解这些元素如何协同工作以提供过程控制，请考虑图 1.2 中描绘的简单温度控制系统。该示例描述了一个采用液体填充感应装置、一组简单的电气触点和一个电动电磁燃气阀的控制系统。

![图 1.2 简单的温度控制系统](img/c01f002.png)

**图 1.2** 简单的温度控制系统

在图 1.2 的示例中，`PV`（液体温度）由密封球和毛细管中的流体持续监测。随着外壳内温度升高，球和管中的流体膨胀，导致其压向管端的隔膜。隔膜的运动反过来推动一对电气触点中的一个，使其向另一个触点靠近。

当外壳内的温度达到由传感器流体的膨胀系数和开关触点间距确定的预定水平时，触点将闭合，形成一个电路来激活电磁控制阀。阀中的电磁铁产生电磁场，将阀杆向上拉起，切断流向外壳内加热元件（最终元件）的气体（被操纵变量）流动。

热源的移除将导致外壳内温度下降，直到感温包收缩并将隔膜从开关触点处拉离。当这种情况发生时，触点将断开，切断流向电磁阀的电流。阀门将打开，气体将再次流入加热元件，导致温度再次升高。

### 闭环控制系统

这种简单的温度控制系统是一种称为**闭环**控制的过程控制类型。正如图 1.3 所示的框图，存在一条从过程输出（外壳温度）反馈到控制器（隔膜和开关触点）的**反馈**路径，控制器随后对过程输入（气动燃气阀和燃烧器）施加适当的纠正动作。

![图 1.3 闭环过程模块](img/c01f003.png)

**图 1.3** 闭环过程模块

通过控制器的反馈回路使闭环系统能够自我调节。控制器检查测量的过程变量并将其与设定点参考值进行比较（在前面的例子中，参考点是固定开关触点的位置）。然后根据比较结果产生误差响应。

通常，如果过程变量值高于参考值，将产生正向动作，例如向加热元件施加更多燃气。相反，如果过程变量值等于或低于参考值，控制器将产生负向纠正动作，例如切断流向加热元件的燃气流。

在图 1.3 的示例中，过程控制模式仅为开/关：阀门要么完全打开，要么完全关闭。然而，如果采用模拟输出设备和输入传感器，且控制器是智能的（具有先进的决策能力，如基于微处理器的控制器），闭环系统可以构建和配置为提供平滑、精确和灵敏的控制响应。这些系统是所有自动化过程控制系统的基础。

### 工业过程控制器

如前所述，任何过程控制系统的核心是其控制器。历史上，过程控制器基于多种不同技术，包括机械装置、气动装置、模拟电子、离散数字电子或基于微处理器的计算机电子技术。然而，目前大多数过程控制器都是基于某种类型的基于微处理器的计算机控制技术构建的。

虽然**工业过程控制器**（`IPCs`）与为**信息技术**（`IT`）行业设计的基于微处理器的计算设备（个人电脑和网络服务器）共享许多特性，但它们在许多方面截然不同。与 IT 计算机不同，工业过程控制器不是设计用于存储数据并稍后处理。相反，它们根据内部配置或编程，基于输入的当前状态产生输出条件。

以下是工业过程控制器的关键要求：

*   **可用性**：许多过程是连续操作，要求控制器具有高可用性、可靠性和可维护性评级。可用性通常是工业控制系统中的最高目标，与数据完整性并列。机密性传统上是过程控制系统的次要关注点；这与与 IT 系统相关的通用机密性、完整性和可用性（`CIA`）要求完全相反。

*   **及时性**：过程控制是一种时间敏感型操作，要求快速响应时间。IT 系统通常没有及时性约束。因此，一线智能过程控制器在实时操作系统上运行。

*   **工业接口**：工业控制器通常提供极少甚至没有用户友好的界面功能，如键盘、指点设备或 LCD 显示器。相反，它们提供工业风格的输入和输出端口，用于连接传感器和执行器。

*   **物理加固**：`IPCs` 设计用于在恶劣环境中运行，如工业工厂和露天场所。

#### 现场设备

设计为部署在靠近被控制过程附近的工业控制器（相对于更常规地放置在办公室或控制室环境中的监控计算设备）称为**现场设备**。这些是在工业和公用事业过程控制系统中遇到的最常见现场设备：

*   可编程逻辑控制器（`PLCs`）
*   远程遥测单元（`RTUs`）
*   智能电子设备（`IEDs`）

在专用控制系统中，现场设备位于从物理过程收集信息的传感器和向物理过程提供纠正动作的执行器之间。然而，在分布式控制系统中，现场设备在逻辑上位于传感器和执行器与具有其人机界面的监控系统之间。图 1.4 展示了现场设备在工业控制系统中的典型实现方式。

#### 可编程逻辑控制器

现代工业处理和公用事业环境中首选的本地控制设备是**可编程逻辑控制器**，或 `PLC`。`PLCs` 是专门设计用于执行工业控制功能的智能数字计算设备，例如开启和关闭阀门、开关和继电器以控制过程。

在内部，如图 1.5 所示的 `PLCs` 与 IT 计算设备共享其大部分技术。它们包含微处理器、`RAM` 内存、只读固件和操作系统。然而，相似之处到此为止。

## 常见 PLC 模块类型

常见的 PLC 模块类型包括以下几种：

*   **电源单元 (PSU) 模块**：该单元通过背板总线为 CPU 和 I/O 模块供电。PLC 电源通常为其组件提供 24Vac 电压。

*   **中央处理单元 (CPU) 模块**：这是相当于个人计算机主板的 PLC 核心部件。它包含微处理器、`RAM` 和 `ROM` 存储器、`I/O` 接口电路以及通信支持。

*   **输入模块**：可安装在 PLC 机架中的输入模块有两种基本类型：模拟量输入模块和数字量输入模块。

    *   **模拟量输入**：模拟量输入模块设计用于配合传感设备（如热电偶和压力传感器）工作，这些设备在最小值和最大值之间产生连续变化的输出值范围（如 0–10V）。由于基于微处理器的控制设备无法理解模拟信号，因此模块必须对信号执行 A/D 转换过程，以获得 CPU 可处理的测量模拟值的数字等效值。

    *   **数字量输入**：此类模块用于处理离散的数字量输入设备，如行程开关、光电开关、接近开关，以及任何提供两态输出的其他设备。这些模块可处理从 8 个设备多达 128 个设备。

*   **输出模块**：与输入模块一样，输出模块也有两种基本类型：模拟量和数字量。

    *   **模拟量输出**：这些输出提供模拟信号，可用于驱动模拟执行器，如阀门定位器。为了产生此类输出信号，模块必须在从 CPU 接收到的数值上执行 D/A 转换过程，然后才能将其应用于输出端子。

    *   **数字量输出**：这些模块提供开/关输出信号，用于控制两位置执行器。与数字量输入模块一样，数字量输出模块可提供从 8 到 128 个不同的输出连接。

*   **通信模块**：这些是允许 CPU 通过背板的 `I/O` 总线与其他智能设备通信的通信模块。历史上，这一直通过标准异步串行通信协议（如 `RS-232` 和 `RS-485` 通道）来完成。然而，更新的工业通信选项正被引入 PLC 通信中，包括不同的 IT 和电话协议，如基于以太网的 TCP/IP 通信、蓝牙和 Zigbee。

## 远程遥测单元

另一种常见的工业控制器是`远程遥测单元`，通常简称为 `RTU`。RTU 是部署在工艺过程或一组工艺过程中的选定位置的小型智能控制单元，用于从不同传感器收集数据并发送命令以控制继电器输出。图 1.9 展示了一款典型的 RTU。

![FIGURE 1.9 An RTU controller](img/c01f009.png)

**图 1.9** RTU 控制器

与 PLC 一样，RTU 可以使用数字或模拟量输入传感器设备，旨在测量电流和电压、压力、光照度、流速、液位、浊度、pH 值、旋转速度等变量。模拟量输入接受给定范围内来自传感器的输入信号。常见的模拟量输入信号范围包括 0 到 1mA 或 4 到 20mA 电流范围，或 0 到 10Vdc 电压范围，以及 +/-2.5V 或 +/-5.0V 范围。对于产生超出这些参数信号范围的传感器类型，必须在传感器和输入端口之间安装某种信号电平转换接口设备。这些行业标准的信号传输方法和范围由不同的设备制造商根据不同应用中使用的传感器进行选择。

电压信号传输用于许多传感器应用，因为它的实现相对简单。然而，电压信号传输易受电气噪声干扰和传输距离限制的影响。电流信号标准历史上一直是传输传感器信息的公认方法，因为其响应比电压信号方法更线性，且提供更强的抗噪能力。

虽然曾出现过不同的电流环标准，但 4 到 20 mA DC 电流标准一直是工业传感器市场的首选标准。该标准提供线性信号响应、良好的抗噪能力、更长的传输距离，以及对人员和危险环境条件的本质安全性。

RTU 还可以提供模拟量和数字量输出，以配合各种不同的控制设备工作。然而，模拟量输出在 RTU 中不常用。数字量输出根据管理工艺的需要，为电路、电磁阀、灯、加热器等执行器提供开/关控制。确实提供模拟量输出通道的 RTU 可用于对阀门定位器和加热元件等设备提供连续变化的控制。

与 PLC 不同，RTU 并非设计为独立控制器。相反，它们更适合广泛分布式控制系统中的操作。虽然它们拥有内部存储器并能控制局部活动，但它们设计用于在分布式或基于 SCADA 的控制系统中与监控控制器协同工作。不过，它们也可以接收来自本地 IED 控制器的工艺数据。

与监控控制器和 IED 控制器的通信是使用标准通信介质和协议进行的。这些包括 `RS-232` 和 `RS-485` 串行连接以及以太网网络连接。`Modbus` 是与 RTU 通信的主流协议。

### 智能电子设备

在电力生成和配电环境中，第三种类型的智能过程控制器正变得越来越普遍——*智能电子设备*，或 *IED*。这些控制器是 RTU 的一种形式，旨在直接与监控控制器提供保护、控制、监视和通信。这些设备为监视和控制过程中的不同传感器和执行器提供了直接接口，并且可以直接与监控控制器、本地 RTU 或其他 IED 通信。

与 RTU 一样，IED 通常具有存放控制本地过程编程的小型存储单元，因此它们可以在没有来自监控控制器的直接或持续指令的情况下运行；但是，它们并非设计用于接管过程的完全控制。常见的 IED 应用包括智能保护继电器、数字故障记录仪、功率/电流/电压表以及 RTU 功能。

### 分布式控制系统

当过程对于单个控制器而言过于复杂，或者其组件在地理上是分离的，就有必要将控制功能分配到多个控制器上，以形成*分布式控制系统* *(DCS)*。

### 监控控制器

在分布式过程操作中，高效控制多个过程单元的另一种常用方法是向 ICS 添加*监控控制器*，如图 1.13 所示。在此配置中，监控控制器被编程为监视每个本地现场控制设备的运行，并根据需要向每个控制器发送协调指令。在这样的系统中，监控控制器不直接控制不同的过程单元；它仅监督和协调其本地控制器的操作。

![FIGURE 1.13 Adding a supervisory controller](img/c01f013.png)

**图 1.13** 添加监控控制器

这种布局代表了一个典型的 DCS，可用于高效控制复杂或广泛分布的过程。与前面的示例一样，该分布式 ICS 中的控制器可以通过多种现场总线类型中的任意一种互连。

这种分布式智能模型优化了所有控制设备的计算能力，以执行、控制、管理和保护完整的过程。本地控制器通常是直接连接到用于监视和控制其所负责的整体过程部分的输入和输出设备的智能设备。

大多数工业过程控制场景需要高速、实时数据采集和控制功能，以维持对过程的适当控制。这与通常应用于企业计算设备的要求截然不同，后者通常不需要实时处理数据。

由于监控控制器不直接参与控制过程的细节，因此无需针对速度进行优化。这些控制器通常是运行监控和数据采集软件应用程序的普通独立计算机或工业服务器。

本地现场控制器的存在使得更多特定任务的智能处理能够在靠近过程的本地执行，而监控控制器则通过某种类型的行业标准通信通道为这些设备提供协调与配合。

除了与现场级控制器接口外，监控计算机通常还为参与过程的人工操作员提供交互式可视控制面板，如图 1.14 所示。该控制面板被称为*人机接口* *(MMI)* 或*人机界面* *(HMI)*。界面的交互部分为人工操作员提供屏幕工具，以调整或覆盖他们看到或感觉到的未按预期发生的控制动作。

### 其他 ICS 总线

正如您在之前的插图中所见，除了连接到现场总线外，控制器还可以连接到一个将其与两个标准 OT 网络组件相连的局域网。

*   *工程工作站*：此计算设备用于为当前操作编程现场设备。
*   *数据历史服务器*：此设备包含一个数据库，用于收集和存储过程值以供检查和处理。

这些单元通过一个称为**本地控制回路**的独立局域网（LAN）与控制器互连。图 1.15 描绘了一个带有本地控制网络回路的典型 ICS。这种类型的网络回路通常以基于 TCP/IP 的以太网网段形式实现。在 ICS 环境中，通常将此网段称为**运营技术（OT）网络**，以将其与组织的 IT 网络区分开来。
