调查人员必须能够证明所发现证据的完整性，这至关重要。这就是为什么必须将嫌疑人的驱动器进行哈希处理，以生成驱动器和文件的哈希值，以便调查人员能够确切地说：“这是我们扣押时嫌疑人驱动器的样子，这是我们在该驱动器中发现的证据。”如果辩护团队声称证据是在扣押后被植入驱动器的，调查人员可以展示包含证据的驱动器的哈希值，并将其与扣押时的原始哈希值进行比较。

## 认证目标 21.02

### 收集数字证据

现在您已经了解了证据背后的概念和不同类型的证据，接下来让我们学习如何收集和分析数字证据。

## 理解流程

在进行需要处理数字证据的调查时，请确保遵循流程来收集相关证据，且不修改证据。处理数字证据需要特殊技能，以确保不污染证据。本节概述了查找数字证据的基本步骤。

### 扣押证据

处理数字证据的第一步是扣押证据。证据可能存在于台式机、服务器、笔记本电脑甚至移动设备的硬盘驱动器上，因此您可能负责从这些电子设备中收集证据。扣押证据意味着前往存有证据的嫌疑人电子设备所在位置，断开电子设备的电源，并将设备带回您的取证实验室。在企业案件中，这可能涉及等到员工不在场的下班时间，然后带走员工的工作站。或者，根据违规行为的性质，您可能会立即扣押电子设备。在处理公共调查时，执法部门必须为任何需要扣押的物品获取搜查令，这一点很重要。

在扣押证据期间，记录现场至关重要，包括做自己的笔记、用标签标记证据和拍照，如前文所述。

### 获取证据（数据获取）

证据扣押后，您便可以*获取*证据。获取证据涉及制作证据的镜像，以便您从证据的副本而非原件进行调查。使用*取证专用*成像软件（专为计算机取证设计、不会对源驱动器做任何修改的软件），对嫌疑人系统上的任何驱动器获取逐位副本（原始扇区级副本）至关重要。

*工件*是用来描述数字内容中可作为证据的项目的术语。工件的示例包括 Internet 搜索记录、已删除文件、注册表项和事件日志。

### 静态镜像

获取镜像时，通常将驱动器从嫌疑人的系统中取出，然后连接到您的取证工作站。取证工作站是您配置好取证软件且未连接网络或互联网的系统。

将嫌疑人驱动器连接到取证工作站的正确方法是将*写保护器*连接到工作站（通常通过 USB）。写保护器将具有用于连接 IDE（集成驱动器电子设备）、SATA（串行高级技术附件）和 SCSI（小型计算机系统接口）驱动器的接口。写保护器是一种不允许修改任何连接到它的驱动器的设备（请参见图 21-4）。

## 考试内幕

### 制作驱动器镜像的重要性

对于 Security+ 认证考试和实际工作，请记住：必须确保创建嫌疑人驱动器的逐位副本（称为*系统镜像*或*驱动器镜像*），而不能依赖普通的文件复制操作。原因在于逐位副本会逐扇区复制驱动器，而逻辑文件复制操作则不会。文件复制仅复制文件，而非整个磁盘，也无法捕获删除后仍残留在磁盘上的已删除文件。

创建驱动器镜像可捕获整个驱动器（因为它复制每个扇区），包括已删除文件和磁盘上的隐藏信息。请始终记住创建多个驱动器镜像，并使用不同的成像工具，以防其中一个镜像损坏。创建镜像后，您将在镜像上而非原始驱动器上进行调查。

![Image](img/exam.jpg)

**对于 Security+ 考试和实际工作，请始终记住：使用硬件写保护器或启用只读模式的软件功能，以只读模式将证据驱动器连接到系统。**

### 实时镜像

虽然大多数情况下您将处理静态镜像，但有时可能需要进行实时获取。对于静态镜像，由于扣押时已切断系统电源，您无法捕获内存内容。在扣押证据前，请规划是需要实时获取还是静态获取。实时获取的好处是，您可以通过在活动系统上运行成像软件，将内存内容转储到磁盘镜像或通过网络传输，从而获取内存内容。实时获取的缺点是，运行软件会修改系统——您必须提前与主管调查员核实这是否可接受。

执行实时获取可让您完成两项非常重要的任务：

- **捕获内存内容** 如前所述，通过实时获取，您可以在嫌疑人系统关闭前捕获内存内容。Forensic Toolkit (FTK) 是一款流行的实时分析工具，允许您将内存内容捕获到远程位置。

- **捕获加密驱动器的内容** 如今全盘加密越来越普遍，系统关机时驱动器会自动加密。系统启动时，如果提供正确的密钥，驱动器会被解密并授予文件访问权限。从取证角度来看，驱动器加密构成了一个问题，因此如果您怀疑驱动器已加密，应在断电前进行实时获取。

## 计算机取证调查最佳实践

创建取证镜像的多个副本，并使用不同的成像工具进行创建，以防某个成像方法出现问题，这是最佳实践。

## 验证证据完整性

取证过程的很大一部分是通过在数据上运行哈希算法生成哈希值，来验证取证镜像内容的完整性。其概念在于：基于证据中的数据，生成的哈希值将是唯一的。如果您需要证明您正在使用的驱动器副本与原始数据相同，可以比较哈希值。

大多数取证工具在创建位流镜像时会生成哈希值，但您也可以使用其他工具（如 `MD5sum`）来计算数据的哈希值。您还应确保工具通过使用校验和对镜像执行某种形式的验证。

正如本章前面所讨论的，您还可以通过维护证据的**保管链**来提供证据的完整性。请注意，Security+ 考试目标明确指出了 `provenance`（来源/来历）一词——即对象的保管清单。

## 分析证据

在获取嫌疑人驱动器的镜像并生成哈希值后，您就可以开始取证分析了。您应该仅在证据副本上进行分析，而绝不在原始证据上进行。

执行分析时，您将使用取证软件定位驱动器上的数据，包括已删除的文件。根据案件性质，您可能需要检查嫌疑人的电子邮件、互联网历史记录和已删除文件，以查找相关文件。

## 文件过滤

大多数取证软件都具有允许您从分析工具中过滤掉已知文件的功能。其好处在于：系统上有数千个文件需要审查，如果能让取证软件识别已知的操作系统文件并将其从过程中移除，那么您需要查看的文件就会减少！

文件过滤功能通过拥有已知操作系统文件和违禁品（例如儿童色情制品）的哈希值数据库来工作，将数据库中的这些哈希值与磁盘上文件的哈希值进行比较。这使取证软件能够识别已知文件，即使嫌疑人已重命名文件。

`EnCase Forensic` 和 `Forensic Toolkit (FTK)` 是具有哈希文件过滤功能的流行取证软件工具。此功能的常用术语是 `known file filter (KFF)`。

### RAID 阵列

取证软件的另一个重要功能是其是否能获取 RAID 阵列中驱动器的镜像。这可以通过两种方式完成。某些取证软件允许您将阵列作为单个逻辑磁盘进行成像，然后您可以复制和分析该磁盘。其他软件可能会为 RAID 阵列中的每个物理磁盘创建镜像，然后创建一个组文件，以确保同时加载所有磁盘镜像。

### 网络流量和日志

根据您正在调查的事件类型，可能需要查看网络设备和软件的网络流量和日志文件。例如，如果您正在调查一起涉及某人通过互联网入侵系统的安全事件，您将需要查看受损系统的服务器日志，以及路由器和防火墙日志。查看日志时，请务必查看相关服务的活动日志（例如显示网站请求的 Web 服务器日志），同时也要查看事件日志以获取任何安全事件的详细信息。

### 证人访谈

在进行调查时，请务必与可能对发生的事情有所了解的证人交谈。在企业环境中，这意味着与系统用户交谈，了解系统的正常活动与异常活动的区别。

### 大数据分析

确定可能需要的大数据分析。大数据是指数据集大到无法使用典型的数据管理工具进行处理或分析。请记住，被认为太大而无法作为单个集合处理的数据量达 EB（Exabytes）级别！您可能会在气象学、金融和互联网搜索等行业发现这种情况。

## 报告调查结果

在证据分析期间，大多数取证软件允许您为感兴趣的项目添加书签，并将它们添加到可生成的报告中。在进行调查时，通过记录所有步骤并标记感兴趣的项目来规划调查结果报告至关重要。报告应包含以下内容：

- **感兴趣的项目** 您的报告应列出来自镜像的任何感兴趣项目。这可能包括电子邮件、图片、视频和已删除的文件。

- **采取行动的日志** 某些取证软件会记录您在软件中执行的每项操作。这对于验证您采取的行动非常有用。如果软件不记录您的操作，您将需要手动记录，以便解释您采取的步骤并通过遵循相同步骤重现结果。

- **调查报告** 报告应包含调查期间发现的证据摘要。例如，如果您恢复了一个包含潜在定罪证据的已删除文件，则应予以记录。

在执行调查时，记录所有活动及每项活动的时间至关重要。记录每项操作的开始时间及其耗时对调查的成功至关重要。`Record time offset`（记录时间偏移）是调查员在执行调查时需要配置的重要设置。配置记录时间偏移涉及调查员在取证软件中配置时区，使其与嫌疑人系统的时区匹配，从而确保证据中的所有时间戳信息准确。

## 证据获取来源

在进行计算机取证调查时，了解可以在哪里找到证据并理解**易失性顺序**至关重要。以下是进行计算机调查时可能找到证据的位置列表：

- **内存/RAM** 内存包含近期使用的信息。这可能包括文档内容甚至近期使用的密码。这被视为易失性证据，因为信息只会在内存中保留很短的时间。请确保准备好 `dd` 或 `FTK Imager` 等工具，以便在需要时捕获内存内容。

- **交换文件/页面文件** 信息不断从 RAM 转储到 Windows 系统上的 `pagefile.sys` 交换文件中。较新版本的 Windows（如 Windows 10）还有一个名为 `swapfile.sys` 的文件，也用于将内存内容交换到磁盘。在尝试查找易失性内存时，请务必检查交换文件。

- **硬盘** 大多数调查涉及对硬盘（或多个驱动器）进行成像，并在注册表、电子邮件或文件系统中查找存储在磁盘上的证据。

- **可移动存储介质** 如果在扣押计算机时发现现场有其他类型的介质，请务必也带走这些介质（假设搜查令涵盖了它们）。嫌疑人可能将文件存储在 CD、DVD 或闪存驱动器等可移动介质上。

- **移动设备** 如果您发现笔记本电脑、手机、平板电脑甚至 iPod 等移动设备，可能也需要搜查这些物品以获取证据。

- **缓存** 证据可能存储在缓存中——无论是安装在系统中的物理缓存内存，还是缓存文件。缓存内存用于存储近期项目，被认为比 RAM 更易失性。

### 网络

证据可能存储在网络上，例如用户的主目录，或网络上的其他服务器。这也可能包括 SharePoint 服务器上的库、FTP 服务器、代理服务器、防火墙或电子邮件服务器等位置。

我还应该提到，证据可以在许多不同的地方找到，包括以下内容：

### 操作系统

操作系统可能会存储有关用户活动的信息，例如显示登录/注销时间的日志文件，您可以搜索这些文件。操作系统还会缓存数据，例如操作系统最近通信过的系统（ARP 缓存），以及前面提到的交换文件。

### 快照

如果您处理的是虚拟化环境，可能能够在虚拟机的先前快照中找到证据。如果是常规系统，例如 Windows 10 系统，您可能能够使用操作系统功能，如系统还原或文件历史记录，轻松访问系统上的旧信息。

### 固件

您也可能能够在固件中访问证据。固件显示系统的唯一标识符，例如 GUID，但也包含代表扣押时设备状态的信息。

#### 易失性顺序

在讨论不同内存位置时，重要的是要理解不同区域的易失性程度不同。*易失性* 意味着数据可能不会长久保留，因此作为取证调查人员，至关重要的是您要先从易失性区域收集证据，然后再查看非易失性区域。例如，由于内存（RAM）的内容是易失性的，意味着信息不会永久存储在那里，如果您决定内存内容可能包含证据，那么时机至关重要。作为一般规则，先从易失性区域（如内存）收集证据，然后转移到易失性递减的数据，如交换文件、硬盘，最后是光盘（如 DVD）。以下是考试需要了解的易失性顺序（意味着您应该按此顺序收集数据）：

1. 缓存内存
2. RAM
3. 交换文件/页面文件
4. 硬盘
5. 远程系统上的日志（网络）
6. 光盘（DVD）

![Image](img/exam.jpg)

**针对 Security+ 考试，请了解您应该先从易失性区域收集数据，然后转移到非易失性区域。这被称为 *易失性顺序*——您应该按易失性顺序收集数据。易失性顺序为：缓存、内存（RAM）、交换文件、硬盘、远程日志（网络），最后是光驱（DVD）。**

#### 使用的工具

各种工具可以帮助您执行计算机取证并捕获和分析计算机证据。本节介绍一些用于获取和分析数字证据的常用工具。

##### 获取工具

扣押计算机后的第一步是获取驱动器的位流副本（镜像），以便您执行分析。重要的是您要使用取证上可靠的成像软件，这意味着它已被证明不会以任何方式改变源驱动器，并且它按扇区逐个捕获磁盘数据，而不是逻辑复制文件。作为一种安全措施，您应该始终将驱动器连接到写保护器，以确保不会向驱动器写入更改。

您可以用来获取镜像的一款免费软件是称为 *Forensic Acquisition Utilities (FAU)* 的工具套件。FAU 可用于获取镜像，但不提供任何分析证据的方法。让我们看看一些可用于执行取证任务的程序。

**安全擦除**  

如果您打算将嫌疑人驱动器的内容复制到目标驱动器，则需要安全擦除驱动器。从法律角度来看，重要的是目标驱动器已被清理，以免污染嫌疑人的驱动器。FAU 包含一个安全擦除程序 (`wipe.exe`)，它对您要安全擦除的目标驱动器进行三次遍历，以确保驱动器上的先前数据被擦除。以下语法用于在我调查系统上安全擦除 E: 驱动器，而图 21-5 显示了安全擦除操作的输出：

**获取镜像**  

一旦您安全擦除了所有目标驱动器，就可以捕获嫌疑人驱动器的镜像了。当您捕获嫌疑人驱动器的镜像时，通常有几种选择来决定如何捕获镜像：

- **磁盘到镜像** 进行调查的一种非常流行的方法是创建磁盘的镜像并将镜像保存在镜像文件中。

- **磁盘到磁盘** 从事计算机取证的大型组织通常通过从一个磁盘到另一个磁盘进行低级复制（在扇区级别）来获取证据。

- **镜像到磁盘** 最后一种情况是获取从嫌疑人驱动器获得的镜像文件，然后将其发送到磁盘以在目标磁盘上进行调查。

执行磁盘到镜像文件的好处是您不需要准备备用磁盘来捕获镜像。很多时候，取证调查人员会将驱动器捕获到镜像文件中，然后当准备好进行分析时，他们可能会将镜像发送到目标驱动器。在这种情况下，调查人员将在目标驱动器上执行分析——这样，嫌疑人的原始驱动器未被触动，并且初始镜像在分析期间也未被触动。一个 Linux 用户值得记住的很酷的一点是，Linux 具有直接挂载 `dd` 镜像文件以进行只读分析的能力！这意味着您不需要额外的软件来执行分析。

如果您想使用 FAU 捕获磁盘的镜像，可以使用以下命令（`dd` 是用于获取镜像的命令行工具，`if` 代表“输入文件”，`of` 代表“输出文件”）：

```
dd if=/dev/sda of=/mnt/evidence/image.dd
```

如果您想使用 FAU 捕获内存内容并将其发送到网络上的共享文件夹，可以使用以下命令（注意这仅在某些版本的 `dd` 上受支持）：

```
dd if=/dev/mem of=//server/share/memory.dd
```
