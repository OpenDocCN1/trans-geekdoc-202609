
# PII 和 PHI 数据保护

PII 是一类允许识别特定个人身份的数据。它包括与特定个人相关的任何信息，例如姓名、地址、社会安全号码 (SSN)、出生日期、财务信息、护照号码、电话号码和电子邮件地址。

《健康保险流通与责任法案》(HIPAA) 隐私规则为受保护实体持有的 PHI 提供联邦保护，并赋予患者关于该信息的一系列权利。同时，隐私规则在保护与披露之间取得了平衡，允许为患者护理和其他重要目的所需的个人健康信息披露。

## Google Cloud Data Loss Prevention

**Google Cloud Data Loss Prevention (DLP) API** 可以对文本内容（包括存储在表格等容器结构中的文本）中的敏感数据进行去标识化。**去标识化** 是从数据中移除识别信息的过程。该 API 检测 PII 等敏感数据，然后使用去标识化转换来掩盖、删除或以其他方式模糊化数据。

所使用的去标识化技术如下：

*   通过用符号（如星号 (`*`) 或井号 (`#`)）部分或完全替换字符，来掩盖敏感数据
*   使用加密哈希等技术，用令牌替换每个敏感数据实例
*   使用随机生成或预先确定的密钥，对敏感数据进行加密并替换
*   使用分桶技术，用区分度较低的值替换区分度较高的值

以下是与 DLP 相关的一些关键概念：

*   **数据概要文件：** 数据分析器可让您通过识别敏感数据和高风险数据的驻留位置，来保护整个组织中的数据。当您开启数据分析时，Cloud DLP 会自动扫描整个组织、单个文件夹和项目中的所有 BigQuery 表和列。随后，它会在表级、列级和项目级创建数据概要文件。
*   **风险分析：** 您可以在去标识化之前使用风险分析方法，以帮助确定有效的去标识化策略；也可以在去标识化之后使用，以监控任何变化或异常值。Cloud DLP 可以计算四种重识别风险指标：`k`-匿名性、`l`-多样性、`k`-映射和 `δ`-存在性。（更多信息请参阅 `https://cloud.google.com/dlp/docs/concepts-risk-analysis`。）
*   **检查（作业和触发器）：** **作业** 是 Cloud Data Loss Prevention 为扫描敏感数据内容或计算重识别风险而运行的一个操作。每当您指示 Cloud DLP 检查数据时，它就会创建并运行一个作业资源。您可以通过创建作业触发器来安排 Cloud DLP 运行作业的时间。**作业触发器** 是一种事件，它可自动创建 DLP 作业以扫描 Google Cloud Storage 存储库，包括 Cloud Storage 存储桶、BigQuery 表和 Datastore。每当有文件上传到 Cloud Storage 时，您也可以使用 Cloud Functions 触发 DLP 扫描作业。

## 用于 PHI 识别的 Google Cloud Healthcare API

根据美国《健康保险流通与责任法案》(HIPAA)，基于 18 个标识符列表（如姓名、病历号、社会安全号码、IP 地址等）关联的 PHI 必须受到特殊保护。有关标识符的完整列表，请参阅此 Wikipedia 页面：`https://en.wikipedia.org/wiki/Protected_health_information`。

**Google Cloud Healthcare API** 具有去标识化操作，可从医疗数据中移除 PHI 或其他敏感信息。Healthcare API 的去标识化功能具有高度可配置性，可从文本、图像、快速医疗保健互操作资源 (FHIR) 以及医学数字成像和通信 (DICOM) 数据中编辑 PHI。来源 `https://cloud.google.com/healthcare-api/docs/concepts/de-identification` Cloud Healthcare API 还会检测 DICOM 实例和 FHIR 数据中的敏感数据（如受保护的 PHI），然后使用去标识化转换来掩盖、删除或以其他方式模糊化数据。

去标识化命令针对的 PHI 包括 HIPAA 隐私规则去标识化标准中描述的 18 个标识符。由于去标识化的健康信息不再被视为受保护的健康信息，因此 HIPAA 隐私规则不限制其使用或披露。

## 移除敏感数据的最佳实践

根据数据集的结构，移除敏感数据需要不同的方法，如表 6.2 所示。

**表 6.2** 处理敏感数据的策略

| 数据类型 | 使用的策略 |
| --- | --- |
| 数据仅限于结构化数据集中的特定列。 | 您可以创建一个不提供对相关列访问权限的视图。数据工程师无法查看数据，但同时数据是实时的，且不需要人工干预即可对其进行去标识化以用于持续训练。 |
| 敏感数据是非结构化内容的一部分，但可以使用已知模式或正则表达式识别。 | 您可以使用 Cloud DLP 来处理此类数据。 |
| 敏感数据存在于图像、视频、音频或非结构化自由格式数据中。 | 使用 NLP API、Cloud Speech API、Vision AI 和 Video Intelligence API 即开即用地识别电子邮件和位置等敏感数据，然后对其进行遮盖或移除。 |

有关更多详情，请参阅 `https://cloud.google.com/architecture/sensitive-data-and-ml-datasets`。

保护多列数据的方法之一是使用 ML 算法（如主成分分析 (PCA)）或其他降维技术来组合多个特征，然后仅对生成的 PCA 向量进行 ML 训练，详见 `https://medium.com/lizuna/beacon-the-use-of-principal-components-analysis-to-mask-sensitive-data-in-machine-learning-7904b01445d0`。例如，给定年龄、吸烟者（用 1 或 0 表示）和体重这三个不同字段，数据可能会被浓缩为单个 PCA 列，并使用以下公式：

*   `1.5age + 30smoker + 0.2 * body‐weight`

一位 20 岁、吸烟、体重 140 磅的人会生成 88 这个值。一位 30 岁、不吸烟、体重 215 磅的人生成的值也是 88。

这种方法非常稳健，因为即使识别出在某些方面独一无二的个体，如果没有 PCA 向量公式的解释，也很难确定是什么使他们独一无二。

粗化是另一种用于降低数据粒度的技术，旨在使数据集中的敏感数据更难被识别，同时仍能提供与使用粗化前数据训练的模型相比可媲美的效果。表 6.3 中的字段特别适合这种方法。

**表 6.3** 处理数据中敏感字段的技术

| 字段 | 说明 |
| --- | --- |
| IP 地址 | 将 IPv4 地址的最后一个八位字节归零（如果使用 IPv6，则为最后 80 位）。 |
| 数值 | 数字可以分箱，使其不太可能识别出个人；例如，年龄和生日可以转换为范围。 |
| 邮政编码 | 可以粗化为仅包含前三位数字。 |
| 位置 | 使用城市、州或邮政编码等位置标识符，或使用较大范围来混淆某一行的独特特征。 |

## 框架选择与模型并行性

现代深度学习模型的参数数量越来越大，数据集规模也在急剧增加。要在大型数据集上训练复杂的现代深度学习模型，必须使用多节点训练；否则耗时极长。在分布式深度学习训练中，你总会看到数据并行性和模型并行性。

### 数据并行性

**数据并行性**是指将数据集拆分为多个部分，然后分配给并行的计算机器或图形处理单元（GPU）。对于每个 GPU 或节点，前向传播使用相同的参数。一小批数据被发送到每个节点，梯度正常计算并发回主节点。分布式训练实践中有两种策略：**同步**和**异步**。对于数据并行性，如果计算节点过多，我们必须降低学习率以保持平滑的训练过程。详情请参考 `https://analyticsindiamag.com/data-parallelism-vs-model-parallelism-how-do-they-differ-in-distributed-training`。

#### 同步训练

在同步训练中，模型将数据的不同部分发送到每个加速器或 GPU。每个 GPU 拥有模型的完整副本，并仅在数据的一部分上进行训练。每个部分同时开始前向传播，并计算不同的输出和梯度。同步训练使用全归约算法，从各个工作器和加速器收集所有可训练参数。

#### 异步训练

同步训练难以扩展，且可能导致工作器有时处于空闲状态。在异步训练中，工作器在维护停机期间无需相互等待，所有工作器独立地在输入数据上训练并异步更新变量。一个例子是 TensorFlow 分布式训练的参数服务器策略。请参阅图 7.1 以了解带有参数服务器的数据并行性。

### 模型并行性

在**模型并行性**中，每个模型被划分为多个部分，这与数据并行性类似。然后每个模型部分被放置在单个 GPU 上。
