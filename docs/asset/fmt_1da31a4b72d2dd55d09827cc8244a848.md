
## EV 验证接收到的 e-coin

EV 按如下方式验证接收到的 e-coin：
`Z_4 = Z_2^x`，`e(Z_1, u_2) = e(Z_2, g)`，以及 `e(Z_3, g) = e(Z_1, Z_4, u_1)`。

## 4.4 提出方案的运行模式

在我们的方案中，CSP 支持两种运行模式：优先模式和常规模式。

在优先模式下，CSP 没有足够的能量供应来满足 EV 当前的充电需求。因此，它对请求进行优先级排序，并在不超过总能量供应的前提下为高优先级请求充电。在同一优先级内，请求按先来先充（FCFC）顺序服务。多授权 ABE 用于保护优先级确定过程 [6]。

在常规模式下，CSP 有足够的能量供应来满足所有传入的充电请求。下一节将解释每种运行模式下使用的协议。

## 4.4.1 提出方案的优先模式

在此模式下，CSP 首先应通过使用多授权 ABE 对 EV 发起挑战来确定 EV 的充电优先级。其思路是 CSP 使用多授权 ABE 发送加密消息。然后，只有拥有给定优先级的 EV 才应具备解密挑战消息所需的密钥。接着，每个 EV 应发送解密消息的证明以获得相应的优先级。最后，CSP 在不超过能量供应的前提下为最高优先级请求充电，并对具有相同优先级的 EV 使用 FCFC 程序。确定优先级所涉及的详细步骤概述如下：

### 1. CSP 的挑战

从 CSP 向 EV 发送挑战是优先级确定过程的第一步。最初，CSP 通过使用来自多个属性授权机构的属性创建其不同优先级的优先级策略。然后，CSP 广播这些优先级策略以及相应的挑战（ABE）和 EV 可充电的最大能量量。挑战的格式为：

`challenge_p = CT_p, TS, Sig(CT_p, TS)` \tag{3}

其中 `TS` 为时间戳，`Sig(CT_p, TS)` 为 CSP 对密文 `CT_p` 的签名。

为了计算优先级策略的密文，CSP 对不同优先级加密不同的消息 `g_t^{r_p}`，其中 `g_t ∈ G_T`，`r_p \stackrel{R}{\leftarrow} Z_p^*` 为 CSP 为每个优先级 `p` 选择的随机元素，且 `{1 ≤ p ≤ N}`，`N` 为优先级数量。对于每个优先级，CSP 创建一个访问策略 `(A, δ)`，其中 `A ∈ {Z_p^*}^{l×n}`，`l` 为该访问矩阵的行数，`δ` 为将访问矩阵的行映射到属性的函数。`ρ` 是另一个将属性映射到其授权机构的函数 `ρ: [l] → U_θ`，定义为 `{ρ(·): T(δ(·))}`。为加密消息 `g_t^{r_p}`，CSP 需要相关属性授权机构的公钥和公共参数。CSP 首先创建两个随机向量 `v = (z, v_2, ..., v_n)^T` 和 `w = (0, w_2, ..., w_n)^T`，其中 `{z, v_2, ..., v_n, w_2, ..., w_n}` 为从 `Z_p^*` 随机选择的元素。我们将 `λ_x` 表示为对应于第 `x` 行的随机秘密 `z` 的份额，即 `λ_x = (A_x · v)`；`w_x` 表示 0 的份额，即 `w_x = (A_x · w)`，其中 `A_x` 为访问矩阵 `A` 的第 `x` 行。然后，CSP 为每一行选择一个随机元素 `t_x \stackrel{R}{\leftarrow} Z_p^*` 并计算密文 `CT_p` 如下：

```
C0 = g_t^{r_p} · e(g, g)^z;

{C1,x = e(g, g)^{λ_x} e(g, g)^{a_{ρ(x)} t_x}, C2,x = g^{-t_x}, C3,x = g^{y_{ρ(x)} t_x} g^{w_x}; C4,x = F(δ(x))^{t_x}, x∈[l].
```

以相同的方法，CSP 为每个优先级使用不同的策略创建不同的密文，然后广播不同优先级的挑战。

### 2. EV 的响应

为了获得优先充电服务，每个 EV 需要检查优先级策略，确定其属性是否能满足某个优先级，然后解密相应的密文以向 CSP 证明其优先级，如图 6 所示。每个 EV 使用其密钥解密相应的密文，并使用解密出的消息 `g_t^{r_p}` 计算会话密钥。然后，EV 使用会话密钥加密解密出的消息，作为拥有相关优先级的证明。

EV 获取策略 `(A, δ)` 和相应的密文 `(CT)`，并使用其密钥 `(K_{GID,u}, K'_{GID,u})` 针对访问矩阵中满足属性的行子集 `A_x`，然后对每一行 `x`，EV 计算：

`C1,x · e(K_{GID,δ(x)}, C2,x) · e(H(GID), C3,x) · e(K'_{GID,δ(x)}, C4,x) = e(g, g)^{λ_x} · e(H(GID), g)^{w_x}`

然后，它计算常数 `c_x ∈ Z_p` 使得 `Σ_x c_x A_x = (1, 0, ..., 0)` 并计算：
`Π_x e(g, g)^{λ_x} · e(H(GID), g)^{w_x}^{c_x} = e(g, g)^z`。

这成立是因为 `λ_x = (A_x · v)` 和 `w_x = (A_x · w)`，其中 `⟨(1, 0, ..., 0) · v⟩ = z` 且 `⟨(1, 0, ..., 0) · w⟩ = 0`。消息可解密为 `g_t^{r_p} = C0 / e(g, g)^z`。EV 使用接收到的消息 `g_t^{r_p}` 与 CSP 计算会话密钥 `k = g_t^{r_i · r_p}`，其中 `r_i ∈ Z_p^*` 为 `EV_i` 选择的随机数。EV 发送 `H_k(g_t^{r_p})`、`g_t^{r_i}` 给 CSP，CSP 将用其建立会话密钥。`H_k(g_t^{r_p})` 被 EV 用作其正确解密了基于属性加密挑战的证明。此外，EV 还应发送其所需充电的能量量。

### 3. 支付

EV 从 CSP 收到充电请求的确认后，应发送匿名 e-coin `(g_s, t_s)` 的加密、匿名化的银行签名 `σ'_B = (Z'_1, Z'_2, Z'_3, Z'_4)`（其中 `t \leftarrow Z_p^*`）及其自身的签名 `π` 给 CSP，如图 6 所示，其中 `π = C^x` 为 EV 的签名，`C = H(σ'_B, t_s, g_s, ID_{CSP}, TS)`。CSP 按如下方式验证签名。

为验证银行签名以确保硬币由银行发行，需要进行以下两项验证。第一项验证为：

$$e(Z'_1, u_2) = e(Z'_2, g). \tag{4}$$

验证证明如下：

$$
\begin{aligned}
e(Z'_1, u_2) &= e(g^{t r}, g^{\beta}) \\
&= e(g^{t r \beta}, g) \\
&= e(Z'_2, g).
\end{aligned}
$$

第二项验证为：

$$e(Z'_3, g) = e(Z'_1 \cdot Z'_4, u_1). \tag{5}$$

然后，CSP 应通过执行以下两项验证来验证 EV 的签名。第一项验证为：

$$e(Z'_2, t_s) = e(Z'_4, g_s). \tag{6}$$

$$e(\pi, g_s) = e(C, t_s). \tag{7}$$

最后，CSP 在验证提交的凭证后向 EV 发送认证令牌。这些令牌将允许 EV 向 RSU 认证并获取用于向 CP 认证以进行充电的秘密令牌。
