
你最近加入了一家小型企业，担任唯一的网络安全分析师。公司拥有一套合理的安全架构，使用了一些旧的 Cisco 路由器和防火墙，但没有 IPS（入侵预防系统）。你很快意识到这是一个亟需改进的关键领域，但同时也知道资金非常紧张。你编写了一些基础的 Snort 规则，但并不真正精通它或任何其他系统。下周与 IT 主监的一次预定会议可能是你在该领域提出一些改进建议的机会。

## Bro

Bro 的初衷并不是为了用作 IPS，但它强大的脚本语言确实可以实现这一点。从核心功能来说，这种 IDS（入侵检测系统）做两件事：捕获各种事件（不将它们标记为好或坏），然后运行脚本来分析这些事件，寻找可能指示安全事件的特征或异常。这些脚本可以执行各种范围的操作，从发送警告消息到更改系统配置以阻止威胁。Bro 之所以可能特别适合这种场景的原因是，它会记录*一切*，即使在你正处于熟悉它并构建脚本库的阶段。这意味着你可以在已经获取的数据上运行新脚本，以检测在你完全掌握之前发生过的事情。它是免费的，这一事实也符合你有限的预算。

## Snort

Snort 虽然也是一种 IDS，但比 Bro 更经常被用作 IPS。它的脚本语言没有 Bro 那么强大，但对于阻止任何你能开发出特征的网络威胁来说足够了。这是 Snort 和 Bro 之间的关键区别，后者既可以寻找特征，也可以寻找异常行为。与 Bro 不同，Snort 不会自动记录它在网络上看到的所有内容，如果你存储海量事件数据的手段有限，那么这可能很具吸引力。然而，和 Bro 一样，Snort 是免费开源的，这意味着你应该能够负担得起它。由于你（在此场景中）拥有一些 Snort 经验，因此在新的组织中部署它时已经占了优势。

## Sourcefire

Sourcefire 起初是 Snort 的商业版本。它的功能迅速增长，后来扩展为 Firepower 安全产品线下的系列备用方案。Sourcefire 公司于 2013 年被 Cisco 收购，Firepower IPS 在进一步改进的同时被集成到了 Cisco 产品中。该系统作为 Cisco 的自适应安全设备 (ASA) 产品线以限时（通常为年度）许可的形式提供。其许可模式随支持的主机数量增加而增加，因此像场景中的这种小型组织可能负担得起，特别是如果你已有的 Cisco 防火墙可以支持 Sourcefire Firepower 的话。与 Bro 和 Snort 不同，这种 IPS 带有商业支持，这可能在你适应新角色时让事情变得更轻松。

## 基于主机的入侵预防系统

顾如其名，基于主机的入侵预防系统 (HIPS) 是一种 IPS，它只检查和响应进出主机网络网络接口的流量。与其基于网络的同类相比，这种保护只提供给一个设备。虽然这看起来像是一个局限性，但它实际上增强了整体安全态势，因为它允许 HIPS 针对某个特定主机的流量和模式进行精细调优。对于一个不仅依赖特征，还结合了行为或启发式方法的 HIPS 来说，这一点尤为不争事实。

你之所以*不*想在整个组织中部署 HIPS 的唯一理由是，你没有足够的资源（例如时间、金钱或人员）来正确地安装和维护它们。除了许可的直接成本外，重要的是，基于异常的 HIPS 在训练期间可能需要大量的人工监督（即系统学习什么是“正确”的这段时间）。在此期间，由于 HIPS 错误地将良性流量归类为恶意，你可能还会面临生产力损失。通过确保你的解决方案包含集中化管理和监控功能，可以缓解部分此类成本。

## 反恶意软件

反恶意软件（有时称为防病毒软件）旨在检测和中和恶意软件，包括病毒、蠕虫和特木马。市面上可用的大多数反恶意软件都是基于规则的，每周（或更短周期）从供应商处下载新的恶意软件定义文件。该软件的工作原理是识别恶意软件的独特属性，将其提取作为特征，然后用它更新所有软件系统。反恶意软件识别的是供应商已知的恶意软件，这意味着它可能检测不到新的恶意软件（或经过修改的“旧”恶意软件）。

在本文时，市场上至少有 16 种主要的反恶意软件产品。尽管没有一种产品能对恶意软件提供 100% 的保护，但根据独立测试的多份独立报告，它们对*已知*恶意软件的效率在 96% 到 99.9% 之间。这使得反恶意软件产品成为性价比最高的保护手段之一。尽管如此，开发专门设计为对任何单一产品都不可见的恶意软件并不困难。这意味着，如果一个老练对手知道你使用哪种反恶意软件产品，绕过它一点都不困难。

## 增强缓解体验工具包

增强缓解体验工具包 (EMET) 是微软的一款免费产品，旨在增强 Windows 系统对各种威胁的防护，特别是未知的（或零日）威胁。EMET 中提高安全态势的关键特征包括：

- **数据执行保护 (DEP)**：当进程调用一个函数时，它会为（可执行的）代码和（假设为不可执行的）数据分配内存空间。缓冲区溢出攻击会超出数据空间并导致“数据”覆盖内存空间，从而允许任意代码执行。DEP 通过将数据空间标记为不可执行并防止数据写入代码空间来防止这种情况的发生。
- **地址空间布局随机化 (ASLR)**：缓冲区溢出和其他形式的攻击需要攻击者知道（或能够猜测）内存中特定数据（通常是代码）的位置。正确实施使得确定特定指令或数据项的位置变得不可能（或至少非常困难）。
- **控制流防护 (CFG)**：面向返回的编程 (ROP) 是一种攻击技术，攻击者劫持进程的正常流并导致其执行恶意操作。CFG 通过创建程序内允许流的虚拟映射并阻止任何未映射的流来降低 ROP 的风险。

需要注意的是，这些功能通常是未安装 EMET 的 Windows 系统自带的。然而，为了使其生效，每个程序都需要由开发者进行编译以利用这些功能。遗憾的是，许多程序并不是以此方式编译的，导致它们容易受到多类攻击。EMET 的工作原理是在程序未构建以利用这些功能时弥补这些缺陷，并允许用户控制哪些程序启用哪些功能，如图 15-1 所示。

## 网络代理 (Web Proxies)

`web proxy`（Web 代理）是一种拦截并转发客户端与服务器之间网络流量的系统。此类代理通常用于执行内容过滤，以确保互联网的使用符合组织的可接受使用策略。它们可以阻止不可接受的网流量、提供有关特定用户访问网站的详细信息日志、监控带宽使用统计、阻止限制网站的使用，并针对特定关键词（如色情、机密或社会安全码）对流量进行筛选。代理服务器可以配置为缓存服务器，保留频繁请求资源的本地副本，从而允许组织在大幅减少上行带宽使用和成本的同时，显著提升性能。

值得注意的是，尽管大多数 Web 代理支持 HTTPS 流量，但要有效地实现这一点需要额外的步骤。首先，你将检查一段加密的“对话”内容，因此（用户）可以合理地预期它是私密的。你的组织政策必须向用户明确这种情况可能会发生，否则你可能会发现自己陷入法律麻烦。

下一步是确保你组织中的所有客户端都信任你将用于签署内部证书的证书颁发机构 (CA)。问题在于，使用 HTTPS 时，客户端向服务器请求由受信任 CA 颁发且与请求资源的域名相匹配的证书。当 Web 代理调解这段对话时，它将向客户端出自己的证书以保护内部连接，并使用服务器的证书来保护连接的外部部分。如果代理的 CA 不被客户端信任，浏览器每次都会生成证书警告，这是我们并不希望用户习惯于点击跳过的。

![Images](img/00005.jpeg)

**考试提示** Web 代理通常关注客户端，确保其不访问或上传被禁止的内容，同时保护其免受恶意数据的下载。

## Web 应用防火墙 (Web Application Firewalls)

Web 代理控制 Web 客户端的行为以及对 Web 客户端的操作，但我们还需要为服务器提供类似的保护，以确保外部客户端无法轻易攻击它们。`web application firewall (WAF)`（Web 应用防火墙）是一种调解指向受保护服务器外部流量的系统。WAF 针对其旨在保护的特定 Web 应用（或类 Web 应用）进行配置。换句话说，WAF “精通 Web 应用的语言”，以便识别针对它的异常或不允许的请求。它能够确定哪些 URL、目录和参数是允许的，哪些是可疑的。这是传统防火墙无法到的。

## 场景 (Scenario)

你的朋友正在开始一项在线业务，在听你刚刚通过了 CSA+ 考试后，他向你寻求关于保护他的 Web 商店并符合 PCI DSS 要求的建议。支持该初创公司的风险投资者期望业务能够快速增长，并投入了大量的首轮资金。Web 基础设施尚未开发，因此没有遗留问题需要考虑。被雇佣的唯一系统管理员精通 `Apache`，但对 `Nginx` 比较熟悉。

### SecureSphere

Imperva 的 `SecureSphere` 是市场上领先的 WAF 之一。它的特色之一是 `dynamic profiling`（动态分析），它可以自动学习受保护应用程序的合法结构和行为，以及用户的正常行为。借鉴了下一代防火墙 (NGFW)，`SecureSphere` 能够与云端威胁情报系统交换已知威胁源和新攻击指标，从而减少对在其他地方已看到的攻击和攻击者的脆弱性。凭借丰富的功能集、学习正常和异常模式的能力以及与威胁情报资源的连接，`SecureSphere` 疑是市场上最强大的 WAF 之一。然而，代价是每台设备的费用高达数万美元，这使得 `SecureSphere` 超出了许多小型组织的承受能力。

由于该初创公司资金充足且基础设施尚未开发，这可能是考虑长期计划并投资 `SecureSphere` 的正确时机。尽管在公司成立初期可能大材小用，但它将支持非常快速的增长。

### ModSecurity

`ModSecurity` 是一个用于 Web 应用监控、日志和控制的开源工具包。它最初被开发为 `Apache` 服务器模块（因此名称中带有“Mod”部分），但此后已适配 `Microsoft Internet Information Server (IIS)` 以及 `Nginx`（尽管存在一些问题和局限性）。`ModSecurity` 能够利用开放 Web 应用安全项目 (OWASP) 的核心规则集 (CRS)，这是一组针对常见 Web 应用攻击的检测规则。`CRS` 由 `OWASP` 专门为 `ModSecurity` 开发的，尽管它也适用于兼容的 WAF。除了这种传统的基于规则的检测外，`ModSecurity` 还能聚合多个（不那么重要的）规则匹配，从而共同触发高级别的警报。这种基于异常的方法旨在捕捉那些原本在分析师屏幕上显示的微量攻击。

### NAXSI

`NAXSI` 代表 `Nginx Anti XSS and SQL Injection`（Nginx 反跨站脚本和 SQL 注入），`XSS` 代表 `跨站脚本`。作为一个相关的说明，`Nginx` 是一种专为在高并发环境下优于 `Apache` 的开源 Web 服务器。由此推，`NAXSI` 也关注性能，其实现方式是集中在一个较小的规则集，该规则集据称可以识别 99% 的已知 Web 应用攻击特征。通过对这些规则采取相当严厉的措施，`NAXSI` 实施了默认拒绝策略。然后由系统管理员创建白名单以允许合法流量通过，同时让 `NAXSI` 拦截所有其他内容。显然，调优 `NAXSI` 实现至关重要，但这种 WAF 可以使用的半监督自学习功能促进了这一点，它可以自动生成白名单。

场景中的系统管理员可能需要大量的学习才能运行 `NAXSI` 解决方案。尽管如此，如果资金有限且快速增长阶段的性能非常重要，这可能是最合适的选择。它可能比 `Apache ModSecurity` 方案贵一点，但未来可能也能更好地支持庞大的客户群。

即使我们的防御工具能够有效阻止绝大多数针对系统的威胁，我们仍然需要密切关注这些工具（以及整个系统），以确保它们在瞬息万变的威胁环境中依然有效。现实中，我们的工具和其他措施失效的频率比我们愿意承认的要高。这强调了收集信息进行单点分析或历史分析的重要性。聚合工具的范围涵盖了从非常集中的命令行工具（如常用的 `ping`）到极其复杂的安全信息和事件管理 (`SIEM`)解决方案。

## 安全信息和事件管理

安全信息和事件管理 (`SIEM`) 系统的分析性并不亚于其聚合属性。该类别的所有工具都执行四个基本功能：收集、存储、分析和报告。大多数收集的信息来自各种系统的日志，这些日志被导出并发送到 `SIEM` 系统。随后，`SIEM` 通常会对来自这些异源的数据格式进行规范化处理，以便它们可以相互比较。然后它会将所有内容存储在一个针对快速检索优化的系统中，这对于分析海信息是必要的。无论分析是简单用户查询的结果，还是复杂关联过程的最终产物，`SIEM` 都必须为不同目的生成各种报告，范围从内部经验总结到监管合规。

## 场景

在几次（相当）小型的安全事件后，你的中型公司准备投资更强大的事件管理能力。作为公司的高级网络安全分析师，你被分配了识别并获取最佳解决方案的任务。你并没有空支，但仍有一笔合理的资金，因此不需要寻找免费解决方案。时机至关重要，因为你的预测显示未来 18 个月内将有重大增长，涉及新员工和几次小型收购。你从事大量的政府工作，因此没有太大的云端业务（选择将数据保留在本地），但这类客户也使你成为高级持续性威胁 (APT) 的可能目标。

### 统一安全管理平台

AlienVault 统一安全管理 (`USM`) 系统是开源安全信息管理器 (`OSSIM`) 的专有扩展，我们稍后会讨论。除了 `OSSIM` 的功能外，`USM` 还包含了数据分析和可视化、日志管理、电话和电子邮件支持、文档、知识库以及全整天的培训。AlienVault 还提供订阅制的威胁情报服务，以及支持 `OSSIM` 和 `USM` 的众包威胁交换 (Threat Exchange)。所有这些都可以以虚拟机或硬件设备的形式提供，可以部署在本地或紧密集成到亚马逊云服务 (`AWS`) 中，并拥有良好的客户服务。

由于场景中指定你没有足够的 `SIEM` 能力，像 `USM` 这样的产品可以让你以相当少少的资金获得巨大的效能。威胁情报服务的订阅也可以帮助缓解来自 `APTs` 的威胁，特别是通过该产品中复杂的分析和报告功能。

### ArcSight

`ArcSight` 拥有三个不同但相关的平台，能够为中大型组织提供服务。其独特特征之一是其关联和分析引擎的成熟度。针对特定功能组集（如用户行为分析 `UBA` 和 `DNS` 恶意软件分析）的多个可选模块仅为那些有需要的人提供额外功能。`ArcSight` 与其他 `SIEMs`（截至本文编写）的区别特征之一是开放架构，这促进了它与大多数其他安全解决方案的集成。这从它可以进行自己的数据分析，或者与 `Hadoop` 和 `Kafka` 等其他系统接口以向第三方大数据平台提供数据这一点可见。

`ArcSight` 是市场上最受尊敬的平台之一，因此在这种场景中选择它是不会出错的。可选模块将为你提供一条良好的增长路径，尽管基础产品已经提供了一套强大的功能。此外，如果你的组织发展到能够利用大数据分析的程度，`ArcSight` 与该领域最常见的解决方案集成良好。

### Kiwi Syslog

`Kiwi Syslog` 是由 `SolarWinds` 开发的工具，用于监控、归档和告报 `syslog` 事件。从技术上讲，它不是一个 `SIEM`，尽管它与这类工具共享一些基本功能（例如，对消息进行优先级排序和告报）。`Kiwi` 真是为了帮助监控性能和解决监管合规问题，但这些功能也可以帮助识别入侵情况，这就是 `CompTIA` 将其归类为 `SIEMs` 的原因。然而，从现实角度来看，`Kiwi` 作为一个独立的 `SIEM` 是不够的。

场景中并没有特别提到 `Kiwi Syslog` 是一个很好的解决方案。尽管如此，如果你的主要挑战是整合来自 `Linux` 和 `Windows` 系统的日志文件，它可以作为解决方案。

### OSSIM

开源安全信息管理器 (`OSSIM`) 是组件的集成集合，而不是一个单体产品。`OSSIM` 起于 2003 年，五年后成为此前描述的商业产品 `AlienVault` 的基础。它包含了用于漏洞评估的开源漏洞评估系统 (`OpenVAS`)、用于网络入侵检测的 `Suricata`、用于主机入侵检测的 `OSSEC`，以及文件完整性监控等。许多开源工具连贯地集成到一个统一的基于 Web 的界面中，带有向导引导你完成常见的设置，如图 15-2 所示。`OSSIM` 以 `ISO` 发行，可以安装在虚拟机或物理主机上。这些主机可以参与开放威胁交换 (Open Threat Exchange)，这是一种众包的 IP 信誉服务，允许 `OSSIM` 系统共享有关已知或可疑恶意地址的信息。

### QRadar

IBM 的 `QRadar` 出于其他 `SIEMs` 的地方在于它能够集成 `NetFlows`、数据包捕和事件日志以支持事件响应。该系统不仅跟踪事件（事件可能变成事故），还跟踪“违规行为 (offenses)”，即关联的事件更有可能表明存在安全入侵。检查违规行为的分析师可以查看支持它的所有网络和日志数据、所有受影响主机以及所有相关的漏洞。`QRadar` 的另一个独特特征是能够自动开始获取取证数据和/或启动事件工单。

如果你的 SIEM 和响应流程之间需要紧密集成，那么 QRadar 在该场景下会非常合适。特别是，如果你的响应通常涉及网络数据捕获或 NetFlow 数据，且这些数据必须与事件日志相关联，那么在能够负担得起的情况下，这可能是你的最佳选择。由于场景中没有明确说明这一需求，在做出决定之前，你还需要深入研究。

## 安全智能平台

Splunk 可能是 SIEM 市场中知名度最高的名称。它的安全智能平台 (`SIP`) 由两个产品组成：`Splunk Enterprise` 和 `Splunk Enterprise Security`。前者提供事件和日志收集、索引及分析，而后者具有传统的 SIEM 功能，可以使这些数据具有可操作性。Splunk 最初只是一个日志文件分析引擎，后来成长为 SIEM，这解释了为什么它在第一个角色上表现出色，但在第二个角色上面临激烈的竞争。事实上，如果你正在寻找高级事件关联，其他平台可能提供更好的产品且需要的精力更少。像 ArcSight 一样，`SIP` 也能提供用户行为分析 (`UBA`)，这对于高级威胁监控非常有用。

场景中没有任何元素能让 `SIP` 脱颖而出成为显而易见的选择，因此将归结为你所需基本功能的最佳成本。Splunk 与其他解决方案相比非常有竞争力，因此你需要明确自己的需求并从多个供应商处获取报价。然后你可以对比功能和成本，并根据这些标准选择合适的平台。

## 网络扫描

网络扫描是对一组主机进行特定信息的质询。例如，水平网络扫描向一组主机地址发送消息并询问“你在那里吗？”。其目标是确定哪些地址对应于活跃（有响应）的系统。另一方面，垂直扫描向一组协议/端口组合（例如 `UDP 53` 或 `TCP 25`）发送消息并询问相同的问题，目标是确定哪些端口正在监听客户端连接尝试。也可以结合水平扫描和垂直扫描，如图 15-3 所示。任何形式网络扫描的意义在于发现谁在网络上监听（并做出响应）。这对于发现行为不符合要求的系统很有用。

## Nmap

Nmap 是一个与网络扫描同义的工具。该名称是“network mapper”（网络映射器）的缩写，对其功能的描述非常恰当。Nmap 通过向目标主机发送特意构造的消息并检查响应来工作。这不仅可以告诉我们哪些主机在网络上活跃，以及它们的哪些端口正在监听，还可以帮助我们确定某些系统的操作系统、主机名，甚至是补丁级别。尽管它是一个命令行界面 (CLI) 工具，但许多前端都提供了图形用户界面 (GUI)，包括 `Zenmap` (Windows)、`NmapFE` (Linux) 和 `XNmap` (Mac OS)。

### Ping

`ping` 实用程序只是向你指定的任何主机发送四个（Windows）或持续（其他操作系统）的互联网控制消息协议（ICMP`）回显请求。如果目标主机配置为响应这些请求，它将为收到的每个消息发送一个 `ICMP` 回显回复消息。`ping` 将比较发送请求的时间与接收响应的时间，然后为交换提供总（往返）时间。这些往返时间可以提供通/自该目标的延迟和抖动指标。

### Traceroute

`traceroute` 实用程序（用于 `BSD`、`Linux` 和 `Mac OS`）及其 Windows 兄弟版本 `tracert` 利用传输 `ICMP` 回显请求的 `IP` 数据包中的生存时间（`TTL`）字段。`traceroute` 通过向同一主机的一系列消息递增 `TTL`（从 1 开始来工作。根据 `IP` 的工作原理，接收主机首先减少到达数据包的 `TTL`。如果该新值大于零，主机将正常处理数据包。否则，它将向源地址发送 `ICMP` “时间超时”消息。通过增加 `TTL`，`traceroute` 强制源主机和最终目的地之间的每个连续主机暴露其 IP 地址。值得注意的是，`IP` 数据包并不保证按照路径运行。

### Ifconfig

`ifconfig` 实用程序用于配置网络接口。它用于查看和管理网卡的 IP 地址、子网掩码和网关。在许多现代系统中，`ifconfig` 已被 `ip addr` 代替。

### Nslookup

`nslookup` 命令用于查询域名系统（DNS）。它允许用户查找 DNS 记录的映射，例如域相关的 IP 地址。

### OpenSSL

`OpenSSL` 是一个强大的商业级工具包，实现了安全套接字和 TLS 协议。它用于各种加密操作，包括生成证书、加密/解密数据以及签名。

### Sysinternals

`Sysinternals` 工具集是用于 Windows 的高级工具集合。这些工具被管理员用于诊断和分析操作系统。其中许多是微软工具的一部分。

- **Process Explorer**: 提供有关所有进程的丰富信息，包括它们使用的内存和 CPU。
- **Autoruns**: 允许快速确定哪些程序在系统启动或用户登录时自动启动。
- **Process Monitor**: 提供有关进程拥有或使用的特定资源的详细信息，包括注册表项、`DLLs`、文件和其他进程。

## 哈希（Hashing）

哈希是一种常用技术，通过创建一个无论原始文件大小如何的固定大小的较小唯一值来验证文件的完整性。这就像在发送货物前放置防篡封胶带一样，哈希值旨在让文件内容发生变化时变得显而易见。哈希函数依赖于这样一个概念：任何两个文件都不应该具有相同的消息摘要。

### 工具

**Cain and Abel** `Cain and Abel` 是一个 Windows 密码破解工具，可以对嗅获的网络流量或本地获取的密码哈希进行操作。注意，`Cain` 官方不支持比 `Windows Vista` 更新的操作系统，在这些现代系统上使用它可能需要变方法。像 `John` 一样，`Cain` 支持字典攻击和暴力破解，还可以使用彩虹表（rainbow tables）来加速分析。通常，使用字典的密码破解工具会获取给定的明文，计算哈希，并在密码文件中搜索该哈希。`彩虹表`是预计算的哈希列表，程序将用它对可能的密码进行反向查找。在彩虹表的情况下，只需要搜索哈希，因此这显著加快了破解过程。代价是彩虹表的大小可能非常巨大。

## 镜像

镜像工具无论卷上运行的是什么文件系统，都能从源复制数据。这意味着运行 `Mac OS`、`Windows` 或 `Linux` 的硬盘可以使用相同的工具以相同的方式复制。镜像工具通常允许将驱动器的整个内容复制到远程目的地的一个文件中。与普通文件复制不同，取证镜像还包括文件系统的空隙（slack space）和空空间，删除文件的残留部分可能存在那里。

## dd

使用 `dd` 工具几乎是制作硬盘位对位位的拷贝的最简单方法。你可以在几乎每个 Linux 发行版以及 `Mac OS` 中找到该程序。它的主要用途是复制或转换文件，因此在镜像过程中，有几个关于块大小和镜像转换的选项，这些可能有助于后续分析。以下命令将执行硬盘“hda”的位对位复制到名为 `case123.img` 的文件中，并使用的选项是将块大小设置为 4096 字节，并在遇到错误时用空符号填充块的其余部分：

```
dd if=/dev/hda of=case123.img bs=4096 conv=noerror,sync
```
