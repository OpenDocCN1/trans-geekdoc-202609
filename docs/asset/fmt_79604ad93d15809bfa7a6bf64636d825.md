
# CISSP® 指南：资产生命周期安全管理

## 供应与取消供应

CISSP® 指南中常见的一个主题是适当管理资产整个生命周期内的安全。供应和取消供应这两个术语进一步凸显了这一重点。

**供应** 是指将资产带入运行状态的过程，有时称为投入生产。必须在供应前考虑安全性，以确保该过程以足够的严谨性处理，且不会对已认定可接受的安全态势产生负面影响。

不可避免地，资产不再需要保持运行状态的时刻终将到来。**取消供应** 是指将资产安全地从生产环境中移除的过程。这一过程同样需要从安全角度进行考量。虽然供应/取消供应仅代表可适用于任何资产的通用过程，但这些术语更常见于用户账户、系统和应用程序的讨论中。自然，与 IAM（身份与访问管理）最相关的考量是与用户供应/取消供应相关的安全性。在对用户进行供应/取消供应时，或许最关键的考量是与访问控制相关的问题。

显然，供应在雇佣新员工时相关，取消供应在员工随后离职时相关，但当员工在组织内发生重大角色变更时，也应给予应有的考量。理想情况下，如果员工的角色性质发生实质性变化，则应取消供应其初始访问权限，并重新供应其现在所需的访问权限。然而在现实中，完整地走完取消供应和供应流程可能过于繁琐。尽管如此，仍应极力避免员工仅不断积累越来越多的访问权限，而不撤销不必要的访问权限这一常见情况。

## 即时访问（JIT）

虽然“即时”（JIT）一词在商业界已使用多年，但其在信息安全领域的应用则近得多。访问控制领域的即时现象，与传统的、典型的永久性和持续性访问形成鲜明对比，在 JIT 视角中，后者被称为“常驻访问”。在 JIT 访问中，需要注意在可用性与安全性之间取得适当平衡。如果 JIT 访问工作流变得过于繁琐，往往会产生恢复常驻访问范式的愿望。

设想一个经典场景：员工入职，其账户被供应了组织预期该员工所需的所有权利和权限。其中一些权限会每天使用，而另一些可能很少用到。特别是在那些不常用但具有重大安全影响的访问权限场景中，可能存在实施 JIT 访问的机会。采用 JIT 可能涉及这样一个流程：当员工需要利用该不常用但敏感的访问权限时，必须启动一个审批流程，以允许提供临时访问权限。

JIT 不仅涉及按需向用户提供特权，还涉及用户和系统供应以及远程访问。JIT 远程访问的一个示例是：仅在需要访问时临时开放远程访问端口（例如 `TCP/3389`），而不是让该服务始终可访问、从而始终处于攻击之下。JIT 账户供应涉及仅在明确需要时创建账户，然后在所需账户及其关联访问权限被使用后自动取消供应该账户。

## 账户访问评审

无论在访问控制管理中投入了多少关怀和严谨，必然会出现过度授权的情况，即提供了超出严格必要范围的访问权限。虽然应用程序可能因权限不足而中断、员工可能会抱怨，但因账户被提供过多访问权限而引发的抱怨会少得多。定期访问评审可作为控制多余访问的一种手段。

虽然理论上审慎的做法是审查每个主体和对象的所有访问权限，但这样做极其繁琐。通常应采用基于风险的方法，优先审查高权限账户、重要交易或服务、敏感数据以及关键系统和应用程序。

根据内部审计师协会全球技术审计指南，“作为 IAM（身份与访问管理）流程的一部分，权利管理应旨在启动、修改、跟踪、记录和终止分配给用户账户的权利或访问权限。无论组织采用何种方法将用户账户归类为相似功能（例如工作组、角色或配置文件），都需要妥善管理每个用户的权利。因此，组织应定期审查访问权限，以检测用户在组织内部流动时积累权利的情况，或用户被分配了不当权利的情况” [\[19\]](#Ch006_295-335_B9780443187346000052.xhtml#bb0095)。

## 访问聚合

*访问聚合* 是指单个用户获得对更多系统的更多访问权限。这可能是有意为之，作为单点登录（SSO）的一种功能。也可能是无意发生的：用户在承担新角色或职责时往往会获得新的权利（也称为访问权限）。这可能导致 *授权蔓延*：用户获得更多权利却不放弃旧权利。这些权利的威力会随时间累积，从而破坏最小权限和职责分离等控制措施。用户权利必须定期审查和审计。应建立流程来审查，并理想情况下减少或消除旧权利，同时授予新权利。

### 权限提升

权限提升涉及获得比最初授予的更高级别的特权。攻击者可能会利用漏洞来实现权限提升。合法用户，尤其是执行管理职能的用户，也可能需要使用比标准账户可用的更高级别的特权。即使是合法用户的情况，鉴于提升特权所关联的更实质性能力，权限提升也必须受到控制。

即使是持续执行需要更高特权操作的用户，仍在操作那些不需要这些更高特权的系统/应用程序。虽然仅利用单个高度特权账户可能非常高效，但这会在特权账户用于网页浏览、发送电子邮件等操作时增加其暴露风险。对于需要使用更高特权的员工，利用一个足够特权的账户执行所有操作的替代方案是为其提供多个用户账户。其中一个账户将作为用于通用计算的事实标准账户，是一个标准的非特权用户账户。他们的额外账户将用于执行需要更实质性特权的操作。

虽然根据需要使用不同账户登录/注销理论上是一个可行的选择，但操作负担和烦恼将是巨大的。值得庆幸的是，现代操作系统提供了专门用于处理这种多账户场景的内置功能。

#### 使用 su 和 sudo 提升特权

基于 Linux 和 UNIX 的系统长期以来一直支持使用标准特权登录，然后允许提升特权。经典方法（通常仍然可用）涉及使用二进制文件 `su`（substitute user，替代用户）。虽然 `su` 允许使用用户知道密码的任何账户，但最常见的默认场景是系统管理员使用 `su` 以特权 root 用户身份执行二进制文件。`su` 最大的缺点是使用该二进制文件要求用户知道他们要利用的账户的密码。这种使用模式因此要求任何利用 `su` 的用户都知道 root 的密码，这从安全角度来看显然是次优的。

为了解决与 `su` 相关的共享 root 密码问题，可以使用较新的 `sudo` 二进制文件。使用 `sudo` 时，用户只需通过提供自己账户的密码来重新验证其账户，而不是像 `su` 方法那样提供将要使用其特权的账户的密码。

#### 托管服务账户

应用程序经常需要作为经过身份验证的、且通常是高度特权的用户账户来运行。服务账户一词用于指示这些面向应用程序且不直接映射回个人的用户账户。历史上，这些服务账户与典型的面向人类的用户账户几乎没有区别。托管服务账户这一短语表明，针对这些面向应用程序的账户，有不同且更严格的控制措施来区别对待。最重要和最显著的特征差异之一是托管服务账户密码的处理方式。

托管服务账户拥有自动生成的复杂密码，并自动维护。某些托管服务账户的实现还可以确保服务账户只能在与该服务关联的系统上下文中使用。因此，即使与该账户关联的凭据被泄露，滥用这些凭据的影响也可以得到限制。

# 考试目标总结

如果将安全比作城堡，访问控制就是护城河和城墙。身份与访问管理确保从逻辑和物理两个视角出发，边界保护机制都是安全的。访问控制的目的是允许授权用户访问适当的数据并拒绝未授权用户的访问——这也称为限制主体对客体的访问。即使这项任务复杂且繁琐，但也可以在不给依赖系统访问的用户造成过重负担的情况下实施强有力的访问控制计划。

保护 CIA 三要素是实施访问控制的另一个关键方面。维护机密性、完整性和可用性至关重要。维护系统 CIA 的安全意味着制定特定的数据访问程序。这些程序将根据用户所需的功能和系统上存储数据的敏感性而变化。
