
# DRP 至关重要，但如果不定期更新，它将迅速过时

与 `IRP` 一样，`DRP` 的变更必须记录在案，因为它提供了避免灾难的`经验教训`，并可用于改进安全策略和程序。计划应包含组织安全策略设定的要求，规定如何以及何时更新，以及如何存储和保存。还必须有流程确保所有利益相关者知晓该计划，并在必要时能够实施。

`DRP` 应包含针对各类数据丢失和系统故障进行恢复的规定。这些情况可能包括自然灾害（洪水、火灾等）、电力相关故障（停电等）或系统数据丢失（病毒、破坏、黑客攻击等）。

`DRP` 文档应以硬拷贝形式复制，不仅在现场可用，还应与异地系统备份一起存储。随着计划的更新，所有副本也必须同步修订。灾难恢复计划至少应包含以下支持文档：

*   正式 `DRP` 的打印副本，以便分发给灾难恢复团队的所有相关方
*   `DRP` 文档包内容的完整清单
*   灾难恢复团队所有成员的姓名和联系信息清单
*   与所有端点和网络连接设备相关的硬件和软件清单，以及任何适用信息手册的副本
*   存储在移动硬盘或其他介质上的关键软件和硬件驱动程序副本，这些介质可安全地存放在远离设施的地方，并采用加密和密码保护格式
*   主要和异地备份数据包的位置和联系数据
*   基准指标，包括最新和必要的历史数据

# 灾难响应/恢复团队

视灾难事件性质而定，灾难恢复团队中的特定人员可能被指定继续执行关键运营，而其他员工则被允许离开或疏散。

如前所述，大型组织可能会开发并培训广泛、多方面的灾难恢复团队。团队构成因组织而异；然而，每个灾难恢复团队都应有指定的负责人。即使在小型组织中，也应有一人接受灾难恢复经理培训，并能在灾难发生后立即做出短期决策。

灾难恢复团队成员必须接受培训，以记录与灾难响应和恢复工作相关的事件、变更和修订。尽管在紧急情况尤其是灾难期间有效记录这些活动可能很困难，但这对灾难恢复工作的有效性至关重要。

## 测试 DRP

与任何组织范围的安装、升级或故障排除操作一样，在公司的实际工作环境中测试 `DRP` 可能很困难。`灾难恢复演练`应是一项年度计划活动。如果没有经验，就无法充分理解实施 `DRP` 所涉及的困难。演练 `DRP` 将强化及时且持续执行备份的重要性，以确保数据恢复始终可行。

可以制定多种策略，在不关闭网络的情况下测试 `DRP`。为了熟悉关键要素，灾难恢复团队成员应研究计划并在全年对其部分内容进行演练。通过这样做，他们将揭示、考虑并纠正计划中的各种弱点，并根据需要添加新功能。即使是最周密的计划也可能存在弱点，但持续排练和修订的计划将有助于将其降至最低。

测试 `DRP` 时，灾难恢复团队必须确保其功能正常，且所有人员都了解各自的角色。值得审查的计划领域包括以下内容：

## 文档排版示例

### 核心目标

*   确保文档可用，且任何必要组件都能轻松定位。
*   测试通知程序，以便在网络或其关键组件瘫痪时，始终有可靠的方式联系人员。例如，如果公司的电子商务网站宕机，相关主管需要知情。
    *   确保随时掌握这些人员的当前电话号码（全天候）。
    *   核实所有设备供应商和制造商的电话号码可用且正确。
    *   检查所有支持合同，确保仍在生效的合同有可用的电话号码。
*   核实计划中列出的所有备用组件或服务器的位置和标识是否正确。

### 备份测试策略

备份介质和技术应至少每月测试一次，对于更关键的网络段，可每周测试一次。管理员应至少每季度执行一次完整恢复测试。此恢复测试应通过将数据还原到不同于其原始位置的文件夹来执行，以确保备份包含所有必要数据，且不受预存文件的污染。

大型企业通常会定期测试完整的灾难恢复计划。为在测试恢复计划的同时保持业务连续性，它们通常会启用商业热站设施作为系统备份。该设施拥有组织在线数据的完整备份，可在主站点因测试而停机期间提供业务连续性。这种安排为 IT 人员在 `DRP` 的知识与执行方面提供了实时测试环境。

完成 `DRP` 测试后，结果可能表明需要更多规划或故障排除。例如，如果数据被意外恢复到本应恢复到文件服务器的邮件服务器上，必须仔细检查 `DRP` 以确定出错原因。随后需对其进行编辑并再次测试，以确保问题已消除。

### 更新计划

无论 `DRP` 多么关键，如果不定期更新，它很快就会过时。计划应包含有关如何以及何时更新、存储和保存的详细程序。此外，`DRP` 文档应以硬拷贝形式复制并即时可用于现场。副本还应与所有异地系统数据备份一起存储。随着计划的更新，这些副本也必须持续修订。

### 实施 DRP

发生实际灾难时，应按顺序遵循 `DRP` 中概述的步骤，以确保网络恢复全面运行，并找出故障的实际原因。

1.  采取措施查明导致网络或其某个组件瘫痪的原因。
2.  确定如何执行必要的修复。
3.  识别任何故障组件。
4.  将故障组件与现有的正常组件匹配。
5.  按照 `DRP` 实施恢复和还原过程。

`DRP` 应提供足够的文档和测试结果，以允许组织的 `IT/OT` 运营和数据完全恢复。实施后，网络应恢复正常运行。

# NERC CIP-009-6

`NERC CIP-009-6 标准`“关键网络资产恢复计划”指导 `BES` 组织为其关键网络资产创建、实施和测试业务连续性及灾难恢复计划。该部分 `CIP` 标准包含三大主要领域：

*   **恢复计划规范**：指导 `BES` 组织根据 `CIP-002` 标准识别的关键网络资产，制定并审查一份或多份恢复计划：
    *   指定会触发恢复计划激活的事件或活动。
    *   定义当计划激活时将投入行动的 `CIRT` 团队成员的角色和职责。
    *   计划还必须包含存储和测试备份介质的策略，以确保其可用于恢复 `BES` 网络系统功能。根据 `CIP-009` 标准，此做法必须至少每年进行一次。
    *   `BES` 组织必须创建、实施和测试备份及存储所有数据的策略，这些数据用于在事故后将网络资产恢复运行。这也可能包括维护与关键网络资产相关的备用组件或软件副本。
    *   组织必须开展模拟实际事故的活动，这些事故会激活恢复计划。这些演练可以是基于纸面的，也可以是全面运行的。根据 `CIP-009` 标准，这些演练必须至少每年进行一次。
*   **恢复计划实施与测试**：应包括以下内容：
    *   **测试**：计划必须包含恢复计划有效运行的证据。此信息可以基于实际事故恢复的报告、桌面演练或运行演练的形式呈现。此证据必须至少每 15 个日历月在计划中更新一次。
    *   **功能性**：计划必须包含证据，验证来自 `BES` 网络系统恢复的代表性样本可用且与当前配置兼容。
    *   **运行测试**：组织的每份恢复计划必须通过运行演练进行测试，至少每 36 个月一次。
*   **经验教训，包括恢复计划审查、更新和沟通**：包括以下内容：
    *   **时间框架**：要求在完成恢复计划测试或实际恢复操作后的 90 个日历日内进行恢复计划审查和更新。
    *   **通知**：计划必须通知恢复计划中有明确角色的每个人员或群体，告知基于经验教训的所有计划更新。

## GICSP 目标映射

`Global Industrial Cyber Security Professional (GICSP)` 考试是一项厂商中立的工业控制系统安全认证，旨在弥合 `IT` 网络安全与工业控制网络环境之间的差距。考试目标旨在评估候选人，确保其具备在运营技术/工业控制系统（`OT/ICS`）、工程、网络安全工作角色中成功履职所需的最低知识水平。该认证满足美国国防部（`DoD`）`8570.0.1` 信息保障劳动力改进计划的要求。它还被批准用于 `DoD` 的 `CND-A`、`CND-IS` 和 `IAT Level II` 劳动力类别。

考试由 `SANS` 研究所的认证机构 `Global Information Assurance Certification (GIAC)` 管理和交付，该组织专注于信息和网络安全培训。

`GICSP` 是一项包含 115 道题目的单一考试。完成考试的时间限制为三小时，及格最低分数为 71%。考试由受监考的 `Pearson VUE` 考试中心提供，必须提前预约。可使用以下网址的说明进行预约：

`www.giac.org/information/schedule_proctored_exam.pdf`

该认证有效期为四年，必须在到期前更新以保持有效。`GICSP` 考试涵盖的主题列于下一节。
