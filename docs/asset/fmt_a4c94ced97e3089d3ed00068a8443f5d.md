风险矩阵，也称为热力图，是一种用于为特定事件分配风险值以帮助决定风险级别的工具。查看图 17-1，您可以看到风险矩阵左侧列出了事件的影响级别，顶部则是事件发生的概率级别。假设针对您的电子商务网站的 DoS 攻击等事件影响为高 (3)，但概率为中 (2)。这将得出 6 (3 × 2) 的风险值。另请注意，每个风险值通常都会着色，以便您直观地判断事件的风险程度。风险值为 1 时为绿色（意味着风险最小），黄色方框用于标识风险级别 2 和 3，风险级别 4 和 6 可能为橙色，而风险级别 9 则使用红色方框直观地指示高风险。这些颜色和值可根据您组织的风险处理方法进行修改。

## 风险控制评估和风险控制自我评估

*风险控制评估*是指由了解业务风险目标的第三方执行评估，并审查安全控制措施在将风险降至最低方面的有效性。

*风险控制自我评估 (RCSA)* 是指内部员工识别风险并评估保护资产免受风险影响的控制措施有效性的过程。RCSA 的目标是确保现有控制的可靠性，确保资产安全，并确保遵守法律、法规和安全策略。

## 风险术语

Security+ 考试将测试您关于风险和执行风险分析的许多其他术语。其中一些术语已在其他章节中讨论过，但将这些术语列在一起可以方便您在参加认证考试前进行复习：

- **风险意识** 涉及提高对资产风险的认识，并理解风险的影响、如何缓解这些风险以及如何管理任何残余风险。

- **固有风险** 是指在应用缓解技术以降低风险之前，与特定活动或业务流程相关的自然风险。

- **残余风险** 是指应用缓解技术以降低风险后剩余的风险量。

- **控制风险** 也称为*风险控制*，这是识别针对资产的威胁并识别可用于保护它们的控制措施的过程。

- **风险偏好** 公司根据其目标和宗旨愿意接受的风险水平。风险偏好将有助于确定是否需要控制措施来保护资产。

## 影响风险状况的法规

每个网络安全计划都应包含一份用于保护公司资产（如系统、网络设备和数据）的控制措施清单。*安全状况*一词是指基于实施的缓解技术，这些资产有多安全。公司可以采取许多措施来改善其安全状况并降低其风险状况，例如执行风险评估、实施安全控制以缓解风险、教育员工了解安全和风险，以及实施事件响应计划。

管辖您组织的法规会直接影响您的风险状况。例如，如果公司处理信用卡，则必须遵循*支付卡行业数据安全标准 (PCI DSS)* 规定的合规要求。遵循这些要求有助于在处理信用卡信息时创建更安全的环境，从而降低您的风险状况。

# 云计算和第三方的风险

当今世界的一个热门话题是云计算的概念。通过云计算，您可以订阅一项云服务，该服务在互联网上的某台服务器上提供数据存储空间，或者您可以让他人为您托管服务，例如 Web 服务器、数据库服务器和电子邮件服务器。订阅云服务的好处之一是，您的公司无需购买硬件来托管公司电子邮件和数据库——您只需订阅云服务，它们就会为您提供功能。然后，您只需登录管理界面（通常是 Web 界面）并管理服务（如电子邮件）。

订阅此类服务可让贵公司节省前期成本（如硬件采购），同时也能节省时间，因为您无需担心物理硬件和操作系统本身的管理。服务提供商将负责硬件、管理操作系统和更新，并确保高可用性（这值得花费成本）。

不幸的是，云服务的主要顾虑之一是隐私。云提供商将数据存储在何处？如何保护数据安全？这些都是您应该询问并寻找答案的问题。根本在于，您正将信息托付给第三方组织。多年来，我交谈过的许多客户因隐私顾虑及管控其组织的法规，不愿考虑使用云服务，但我看到这一趋势正在转变，因为云提供商正在解决安全问题。

决定使用云服务需要周密规划。还应考虑混合解决方案，例如：敏感数据存储在公司站点（称为本地部署），而非敏感数据存储在云中，以利用备份服务甚至该数据的高可用性。

请注意，存在不同类型的云模型，例如公有云（您的数据托管在互联网上）和私有云（意味着您在公司内部托管数据）。重要的是要注意，公有云关联的风险更多，因为它们并非托管在您的组织内部。要了解有关云模型和服务类型的更多信息，请查看第 16 章。

以下是将系统和数据与云服务及第三方公司集成时应考虑的一些要点：

- **业务合作伙伴入职/离职** 当与需要访问您系统的业务合作伙伴合作时，您需要制定程序，将新人员（合作伙伴的员工）添加到身份和访问管理（`IAM`）系统中。该系统用于识别公司外部人员并控制其对系统的访问。将新员工添加到系统的过程称为`入职`，而从系统中移除员工的过程称为`离职`。

- **社交媒体网络和/或应用程序** 随着当今社交媒体网络的增长，组织需要实施政策并教育员工，哪些信息允许发布在社交媒体网络上，哪些信息不允许发布。

- **互操作性协议** 确保您已与云提供商或第三方公司定义了运营协议。诸如`服务级别协议 (SLA)`之类的协议规定了保证的正常运行时间。检查是否需要`框架采购协议 (BPA)`，该协议用于覆盖产品或服务的重复性需求。确保存在`谅解备忘录 (MOU)`，有时也称为`协议备忘录 (MOA)`。这是一份在双方之间建立协议并规定其相互关系的文件。此外，确保您熟悉`互联网服务协议 (ISA)`，并满意于其中的任何数据限制和互联网连接的保证正常运行时间。如果您利用云服务，这一点至关重要，因为您需要互联网连接才能访问云中的任何服务或数据。

- **隐私考量** 如前所述，您需知晓将信息存储在第三方或云中存在风险。您是在信任服务提供商保护该信息的安全。

- **风险意识** 了解与云服务和第三方集成的风险非常重要。存在数据存储在不安全位置的风险，以及如果网络传输的数据未加密，可能被他人窥视的风险。您应确保提供商保证对该信息的访问。还有其他风险需要注意——您可能会失去互联网接入而无法访问云中的数据。您也可能遇到云提供商倒闭的情况——那时您将如何访问数据？或者云提供商的硬件因法律原因被传唤怎么办？所有这些情况都可能导致您无法访问云中的数据。

- **未授权数据共享** 与第三方组织合作时，始终存在该第三方员工未经授权将信息共享给他人的风险。

- **数据所有权** 确保互操作性协议规定了存储在云中或第三方公司的数据归谁所有。一些第三方公司可能认为，如果您将数据存储在他们那里，数据就归他们所有。阅读所有协议，并确保数据所有权有明确规定。

- **数据备份** 只要您明白理论上一旦将数据存储在云中，您就无法知道谁在访问它，那么云存储空间非常适合用于数据备份。如果这是一个顾虑，而您确实想将数据存储在云中（特别是非敏感信息），则在备份到云之前加密该信息。

- **遵循安全策略和程序** 使用云服务和第三方公司时，确保遵循组织的安全策略和程序。如果您是负责更新策略的安全主管，则确保更新策略以包含组织关于云服务的规则。

- **审查协议要求以验证合规性和性能标准** 此项非常重要。您必须阅读所有协议，以确保您遵守管控组织的任何法规。例如，由于隐私顾虑，许多政府机构和医疗部门无法将信息存储在云中或第三方公司。

## 认证目标 17.02

### 风险评估类型

执行风险评估时，了解两种流行的风险分析类型——定性和定量——非常重要。`定性`风险分析涉及根据等级为威胁分配值，而不必计算与风险相关的美元数字；而`定量`风险分析涉及将以美元和美分计算的成本与每个风险关联。在本节中，您将学习这两种类型的区别。

![Image](img/exam.jpg)

**针对 Security+ 考试，请非常熟悉定性和定量风险分析的区别。定性使用等级来识别威胁的严重性，而定量使用美元数字。**

#### 定性

如前所述，定性风险分析在不实际计算美元损失数字的情况下确定风险和缓解技术。通过定性风险分析，您创建一个值的等级，根据等级中的数字为每个威胁评级。

在查看等级示例之前，您首先需要理解计算风险的公式，即使在定性风险分析中也是如此。公式是风险等于概率乘以损失（也称为影响）：

```
Risk = Probability × Loss
```

在定性风险分析中，您不必花时间计算实际的美元和美分，而是专注于根据您创建的等级分配值。这在分析过程中节省了时间，因为您不必实际计算确切的美元数字。让我们看一个例子。

## 定量

另一种风险分析类型是定量分析。定性分析的缺点是您使用别人创建的等级来判断威胁的严重性，而严重性取决于执行评估的人的观点。

通过定量分析，您可以计算每个风险的美元金额以及威胁的影响。这是一种关键的评估类型，因为高层管理人员希望看到美元数字，以证明购买安全控制措施以保护资产的成本是合理的。例如，通过定量分析，如果您说：“该威胁每年将花费我们 1,400 美元，因此我们应该购买一款每年花费 6,500 美元、为期三年的防火墙解决方案”，管理层很可能会让您寻找更便宜的解决方案。

定量分析的第一步是评估资产的价值。例如，您可能确定您的电子商务网站每天带来数千美元的收入——这将帮助您计算资产的价值。

一旦知道了资产的价值，您必须确定每个针对该资产的威胁将产生的影响。在定量分析中，影响被指定为*暴露因子 (EF)*，即如果威胁发生，资产价值损失的百分比。

一旦知道了资产的价值并为每个威胁关联了暴露因子，您就可以计算所谓的*单次损失期望值 (SLE)*，这是一个美元数字，代表公司每次威胁发生时将损失多少钱。以下是单次损失期望值的公式：

```
SLE = value ($) × EF (%)
```

例如，假设您确定电子商务网站的价值为 200,000 美元，每次 Web 服务器发生硬盘故障时，您会损失 8% 的*资产价值*。这意味着您的单次损失期望值是 200,000 美元 × .08，即 16,000 美元。因此，服务器每发生一次硬盘故障，您的业务就会损失 16,000 美元！

![Image](img/exam.jpg)

**针对 Security+ 考试，请记住如何计算单次损失期望值：`SLE = 资产价值 × 暴露因子`。**

一旦计算出单次损失期望值，您就可以着手计算*年化损失期望值 (ALE)*，这是计算您每年因每个威胁将损失多少钱的计算。计算年化损失期望值的公式是获取单次损失期望值并将其乘以*年化发生率 (ARO)*。年化发生率是您预计威胁一年内发生的次数。

```
ALE = SLE × ARO
```

例如，您可能预计威胁一年发生三次，或每五年发生一次。以下示例计算如果硬盘故障威胁一年发生三次的 ALE：

```
ALE = $16,000 × 3
```

这意味着基于硬盘一年故障三次的 ALE 将使公司花费 48,000 美元。您需要确保实施的保护硬盘故障的解决方案每年的成本不超过 48,000 美元。

![Image](img/exam.jpg)

**针对认证考试，请记住年化损失期望值是通过 `SLE × 年化发生率` 计算的。**

让我们看一个不同的 ARO。如果预计硬盘故障威胁每五年发生一次，那么您的 ARO 将是 1/5，即 .20。这意味着计算年化损失期望值的公式将是

```
ALE = $16,000 × .20
```

这导致 ALE 为 3,200 美元。因此，您需要找到一种保护资产的安全解决方案，其成本每年不超过 3,200 美元。

定量分析的优势在于您计算的是确切的美元数字，这正是管理层所喜欢的，因为很容易看出实施解决方案在财务上是否合理。定量分析的缺点是计算这些数字所需的时间；例如，给资产定价很困难，因为涉及太多变量。

![Image](img/exam.jpg)

**定量风险分析的优势在于您能够根据安全控制措施在财务上是否值得而做出明智的决策。**

## 认证考点 17.03

### 风险缓解策略

一旦您识别出针对资产的所有威胁，并通过定性分析或定量分析确定了关键威胁，接下来您需要决定采取何种 `风险响应技术`。这也称为 `风险缓解策略`，代表您的 `风险管理策略`。以下是应对威胁可采取的方法：

- **缓解风险（缓解）** 应对风险的第一种方式是缓解它。缓解涉及实施安全控制以保护资产免受威胁。例如，为防止 Web 服务器硬盘故障，您可以购买 `RAID` 解决方案。

- **接受风险（接受）** 处理风险的另一种方式是接受它。接受风险意味着您不实施任何解决方案来防范威胁，因为您认为威胁发生的可能性及其影响不足以证明实施安全控制的成本是合理的。

- **转移风险（转移）** 您也可以考虑转移风险，这意味着您将威胁变成别人的问题！例如，您可以购买保险以帮助从安全事件中恢复。应注意，对于考试而言，请记住获取网络安全保险是转移风险的一个例子。

- **规避风险（风险规避）** 风险规避的思路是：无论使您处于风险中的活动是什么，您决定不再执行该活动以规避风险。例如，您可能担心将高度敏感的系统连接到主网络（而主网络连接到互联网）会带来敏感系统被攻破的风险。在此示例中，您可以将高度敏感的系统放置在一个与主网络物理隔离的隔离网络上，以避免基于网络或互联网的攻击。`物理隔离` 意味着两个网络之间没有任何连接（Security+ 考试的重要知识点）。

- **威慑风险（威慑）** 应对风险的一种不太常见的方法是威慑风险。威慑风险的一个例子是威胁惩罚（通常是法律制裁）任何攻击资产的人——您正在威慑该事件的发生。

**请务必熟知 Security+ 考试的风险缓解策略，特别是获取网络安全保险是一种转移风险的方式。**

您可以遵循许多实践来帮助缓解组织内的风险。以下是您需要为 Security+ 认证考试熟悉的常见缓解策略列表：

- **强制执行技术安全控制** 缓解风险最常用的方法是实施安全控制，例如 `RAID`、高可用性解决方案、防火墙、加密、入侵检测系统、蜜罐、补丁管理和恶意软件防护。另一个对企业至关重要的常见安全控制是 `数据丢失防护 (DLP)` 解决方案——通常是允许管理员定义被视为机密或敏感信息的规则，并防止该信息被共享或复制的软件。

- **变更管理** 请务必在业务中实施变更管理程序，并教育所有员工正确的变更方法。例如，确保开发人员在开发机器上对 Web 应用程序进行更改，然后将这些更改发布到测试服务器以验证其成功，最后再复制到生产服务器。

- **事件管理** 安全的关键部分是确保建立了事件管理团队，并制定了团队在发生安全事件时遵循的事件响应程序。

- **用户权利和权限审查** 花时间定期评估系统的配置。这包括审查系统上授予的特权（权限）以及授予数据的任何权限。确保遵循最小权限原则，因为这将有助于减少安全事件的发生。

- **执行例行审计** 拥有安全环境的关键部分是执行例行审计。您可以执行多种不同的审计，从配置审查到漏洞评估。

- **强制执行策略和程序** 组织的安全始于制定良好的安全策略并要求员工知晓这些策略和程序。制定严格的策略和程序供员工遵循，有助于防止数据丢失和盗窃。例如，您应确保所有员工在其移动设备上配置了密码。这样，如果设备丢失或被盗，他人将更难访问设备上的信息。

### 考场内幕

**处理风险**

对于 Security+ 考试，请记住应对风险的不同方式。处理风险最常用的方法是缓解它，即实施控制措施来降低风险。
