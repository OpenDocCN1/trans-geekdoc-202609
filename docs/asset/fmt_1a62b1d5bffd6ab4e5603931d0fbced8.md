# 300. A

# 301. A

这是一个路由问题。实例需要将其出站流量导向 VPC 上的互联网网关，然后该流量才能流向互联网。

# 302. A

CloudFront 支持静态和动态内容。

# 303. A, C

仅根据提供的信息，最佳选择是关注数据库和动态内容；根据题目有限的信息，Web 应用服务器不是问题所在。这意味着要检查数据库实例规格 (A) 和缓存动态内容 (C)。B 和 D 关注 Web 应用实例，这似乎不是问题所在。

# 306. A, D

# 308. B

这属于死记硬背的内容。所有实例元数据均可在 `http://169.254.169.254` 的 `/latest/meta-data` 下获取。`/latest/instance-data` 实际上不是一个响应请求的 URL。

# 309. A

S3 具有高持久性，并以键值对形式存储数据。

# 310. B

B 是唯一不假设至少半频繁访问的答案。Glacier 最适合极少访问且不需要快速访问时间的文件。

# 311. A, D

# 312. C

对于所有新 AWS 账户，每个区域允许 20 个实例。但是，您可以通过 AWS 支持申请提高此限制。

# 313. C

这些选项中唯一合理的是 C，增大 NAT 实例的规格。无法向已有互联网网关的 VPC 添加额外的互联网网关 (A)，增加额外的弹性 IP 需要使用更新的 EC2 实例，且在这种情况下不会影响性能 (B)。

# 314. B

如果实例快速扩缩容，意味着触发添加和移除实例的阈值被频繁满足。既然您不想减少扩容以满足需求，就应该增加系统缩容所需的条件；这正是 B 所建议的。主动循环 (A) 无助于解决问题，C 完全是捏造的。

# 315. A, C

路由配置是最重要的步骤之一 (A)；您必须将通往公共互联网的路由指向 NAT 实例。此外，您需要禁用源/目标检查，这是一个常被遗忘的步骤 (C)。NAT 实例*不能*位于私有子网中 (B)，D 在此语境下讲不通。

# 316. B

这道题比较难，因为必须死记硬背。CloudWatch 默认提供磁盘读取操作、CPU 使用率和入站网络流量，但*不*提供内存使用率。

# 317. A, B

实例需要弹性 IP 进行公网通信 (A)，并且应位于与其他实例相同的 ELB 后面 (B)。将其放入私有子网 (C) 将失去其与公共互联网通信的能力。D 看起来不错，但如果实例与其他实例在同一子网中，它会自动获得它们的路由；路由表应用于子网，而非特定实例。

# 318. D

公共互联网通过 `0.0.0.0/0` 寻址。

# 319. A

公共互联网通过 `0.0.0.0/0` 寻址，因此如果这是目标，目标应为 VPC 内的互联网网关。

## 领域 2：定义高性能架构

### 1. D

无法通过推理得出此题答案；这属于死记硬背的内容。在此场景下，数据复制不收取费用。

### 2. C, D

### 4. D

# AWS RDS 与负载均衡器考题解析

## 5. B

目前，RDS 中的只读副本仅由 MariaDB、MySQL 和 PostgreSQL 支持。

## 6. A, C

只读副本是根据主实例的快照创建的数据库的只读实例（A）。只读副本可以与主实例位于同一实例中，也可以位于不同实例中（因此 B 错误）。只读副本通过来自主数据库的异步复制进行更新——这是性能最佳的方法。

## 7. C, D

只读副本可以位于与主实例不同的区域（D），并且它们会复制主实例中的所有数据库（C）。对于单个实例，一次最多可拥有五个只读副本（因此 A 错误）。虽然支持 MySQL 和 MariaDB（B），但不支持 Aurora。

## 8. D

根本问题在于只读副本设置仅允许五个只读副本。这不是一个可以由 AWS 提高的限制（因此 C 排除）。选项 A 无法解决问题，选项 B 不准确；此处没有影响该问题的欧盟限制。唯一能导致能够在所需区域中创建实例的答案是 D：通过关闭现有实例，您可以在所需区域中创建一个新的第五个副本。

## 9. C, D

只读副本专注于性能，因此通常可以排除任何与灾难恢复相关的答案——在本例中为 A。只读副本也适用于 RDS 数据库，因此 B 排除；不支持本地数据库。这留下了 C 和 D，两者均有效。

## 10. B, C

不会自动从任何实例（包括主实例）获取备份，因此 A 错误。由于每个只读副本都有自己的数据库实例在运行，因此 B 和 C 均有效。复制是异步的而非同步的（因此 D 错误）。

## 11. A, B

A 错误，因为您可以在与主实例相同的 AZ 中创建只读副本。与 Multi-AZ 设置不同，没有使用多个 AZ 的要求。B 也错误；只读副本不提供灾难恢复选项。C 和 D 均为真。

## 12. A

仅 A 正确。Multi-AZ 设置专注于灾难恢复和容错，而只读副本提供性能和可扩展性。

## 13. D

应用程序与只读副本通信的方式与与非副本实例通信的方式没有区别。事实上，应用程序除了无法进行写入外，“不知道”它们正在与只读副本通信。

## 14. A, D

A 和 D 均为将受益于额外只读实例的解决方案。B 不是有效答案，因为更新记录仍然只能通过主实例进行；只读副本不支持写入。C 不正确，因为只读副本不提供自动故障恢复。

## 15. B

此处需要小心。虽然只读副本未被宣传甚至建议作为灾难恢复的解决方案，但选项 B 确实提供了一种在该方面使用它们的某种手动过程。虽然您无法获得自动备份或故障转移（A 或 C），但如果必须，您可以手动将只读副本实例提升为独立实例。尽管如此，Multi-AZ 设置几乎总是容错的更稳健解决方案。

## 16. A, B

A 和 B 均为只读副本的理想使用场景。C 是常见的错误答案：只读副本不提供自动备份。D 不准确；实际的数据库处理并未改进；您只是为客户端增加了更多的数据读取来源。

## 17. D

AWS 不支持通过 RDS 进行循环复制。虽然 RDS 支持的某些数据库支持此功能，但 RDS 本身不提供对此功能的访问。

## 18. A, C

您可以通过 AWS 控制台（A）、AWS API（C）和 AWS CLI（未提及，但同样适用）创建只读副本。

## 19. B

正如多次所述，只读副本不是备份策略，也不会导致自动备份被设置。但是，您必须为主数据库实例开启自动备份以启用只读副本。

## 20. A

这需要仔细阅读。Amazon RDS 不支持循环复制，这意味着一个数据库从第二个数据库读取，但随后又被该第二个数据库复制回去。然而，一个数据库复制另一个数据库，然后作为第三个数据库的源，这是完全允许的。这使得选项 A 正确。

## 21. D

根据备份窗口更改的方式（API、控制台等），对备份窗口更改的响应没有区别。所有更改立即生效。

## 22. B

这是另一道纯记忆题：Amazon RDS 备份最多可保留 35 天，不能更久。

## 23. C

此问题有两个组成部分：使用 RDS 还是 EC2 托管 Oracle 以及要选择的存储类别。虽然 RDS 在一般情况下是更好的选择，但由于需要自定义插件，在此场景下可能无法使用 RDS。这排除了 A 和 B。假设在 EC2 上安装，那么问题变成哪种存储类别更快：预置 IOPS 还是磁性存储。答案始终是预置 IOPS。

## 24. B, C

选项 C 应为显而易见的首选。任何时候您有自定义插件，很可能需要将数据库安装在 EC2 实例上，而不是使用 RDS。选项 A 和 D 实际上都与数据库周围的网络路由和服务有关，两者均可在不影响 EC2 与 RDS 决策的情况下完成。这留下了 B，这在逻辑上也讲得通：如果您有一个非常大的数据库，并且它会增长（几乎所有数据库都会增长），那么 RDS 上的大小限制可能成为限制因素。

## 25. A, C

如果您有准备，这应该是一道简单的题。虽然很容易忘记 Aurora 和 MariaDB 是否为 RDS 选项——它们是！——但您应该知道 DynamoDB 是 AWS 的 NoSQL 数据库，而 Redshift 是数据仓库解决方案。

## 26. A

只要您理解 Multi-AZ 部署关注的是故障转移而非性能，这并不特别困难。选项 A 正确：Multi-AZ 部署中没有特定的性能提升，除非同时开启了只读副本（题目未指定）。B 错误，因为在 Multi-AZ 部署中只有主数据库响应请求。C 实际上是真实陈述，但与问题主题（性能）无关。D 在问题上下文中根本讲不通！

## 27. A

这有点棘手，因为它需要理解 AWS 设置的默认选项。默认情况下，根卷会在实例删除时终止，默认情况下，附加到实例的额外 EBS 卷不会。这使得选项 A 为真。但请注意这些设置是可以更改的！另请注意选项 D 在任何配置下均不为真。

## 28. B

所有新账户的默认值为允许 100 个 S3 存储桶；这在 AWS 中是一致的，且不因配置而改变（意味着 C 和 D 不正确）。但是，该值可以通过向 AWS 申请例外并提供合理理由来提高，这使得 B 为正确答案。

## 29. B

在 Multi-AZ 设置中，复制从主实例同步发生到辅助实例。异步复制仅发生在只读副本设置中（可在 Multi-AZ 设置之外启用）。

## 30. C

在只读副本设置中，复制从主实例异步发生到各个只读副本。因此，无法保证更新在只读副本上即时生效。同步复制发生在 Multi-AZ 设置中。

## 31. A, B

经典负载均衡器同时支持 IPv4 和 IPv6。它们支持 HTTP/1 和 HTTP/1.1，但只有应用程序负载均衡器支持 HTTP/2。此外，您必须向经典负载均衡器注册单个实例，而不是目标组；注册目标组是仅应用程序负载均衡器可用的功能。

# AWS 认证考试题解析

## 32. 弹性 IP 地址默认限额

**A.** AWS 账户默认允许每个区域拥有五个弹性 IP 地址。与大多数 AWS 默认限制一样，可以通过联系 AWS 并提供合理的理由来提高该限额。

## 33. 实例可挂载的 EBS 卷数量

**C.** 官方规定，实例最多可有 28 个挂载点。其中一个被网络接口占用，剩下 27 个可用于 EBS 卷。但更好的记忆方法是：实例可以挂载一个根卷和多个额外卷（超过两个）；这排除了选项 A 和 B。此外，实例不能有无限数量的挂载点。因此正确答案是 C。

## 34. EBS 卷的挂载限制

**A.** 注意措辞，不要误读为“一个 EC2 实例可以挂载多少个 EBS 卷”（这是完全不同的问题）。**单个 EBS 卷同一时间只能挂载到一个实例上。**

## 35. 应用负载均衡器支持的协议

**B, C.** 这应该是个简单的答案：应用负载均衡器以及经典负载均衡器仅支持 HTTP 和 HTTPS。

## 36. RDS 数据库备份方式

**A, C.** 目前 RDS 仅提供两种备份 RDS 数据库的方法：自动备份和自动快照。S3 生命周期管理策略不适用于 RDS 数据库，且 Data Pipeline 在此上下文中不相关。

## 37. 缓存数据的快照一致性

**B.** 写入和读取缓存的数据是临时的，如果实例频繁读写该数据，确保快照不丢失缓存数据的唯一方法是**完全停止实例运行**，然后再创建快照（选项 B）。选项 A 和 C 虽然会创建快照，但很可能会丢失缓存数据。选项 D 无法从实例分离根卷（题目未明确缓存数据写入的是 EBS、EFS 还是其他存储机制），因此不是安全的选择。

## 38. 减少数据库延迟的方案

**B, C.**

- 选项 A 无效，因为 Multi-AZ 是灾难恢复方案；正常操作下只有主数据库实例能响应流量（除非同时配置了只读副本）。
- 选项 B 有效；缓存用户数据可减少往返数据库的次数，从而降低用户延迟。
- 选项 C 也合理，因为增加可供读取的数据库实例应能降低对单个 RDS 实例的网络延迟。
- 选项 D 无帮助，因为问题出在检索凭证上，而非 Web 层本身。

## 39. 照片存储的成本优化选择

**C.** 标准 S3（A）虽非坏选择，但成本最高；它和 S3-IA（B）因可用性和弹性更高，均比 S3 One Zone-IA 昂贵。关键在于照片丢失不造成问题，因此 **S3 One Zone-IA 是更优选项**。AWS 不再推荐使用 S3 RRS。

## 40. 大数据传输解决方案

**C.** 这应是自动反应：涉及大数据传输时（尤其是在 AWS 考试中！），答案应为 **Snowball**。这类题目高频出现，应轻松拿下。

## 41. S3 分段上传

**A, D.** 唯一棘手的选项是 B。虽然**分段上传**绝对能改善大文件（如大于 10 GB）的上传体验，但它**不是必须的**；因此 B 不是最佳选项。选项 A 和 D 仅在启用分段上传时才可能实现。选项 C 错误，因为安全性与分段上传无关。

## 42. 置放群组的核心关注点

**C.** 置放群组主要关注网络吞吐量，并降低单一可用区内 EC2 实例间的延迟。AWS 确实支持通过分散置放群组跨越多个 AZ，但除非明确提到“分散”，否则应假设题目指的是“普通”（或“集群”）置放群组。

## 43. 集群置放群组特性

**A, B.** 集群置放群组（默认类型）必须由位于**单一可用区**内的实例组成（A）。这会带来网络活动吞吐量的增加（B），但不影响写入 S3 时的实际磁盘性能（C）。实例也可以是不同类型，因此 D 也是错误的。

## 44. 分散置放群组特性

**B, C.** 分散置放群组可跨越可用区，并支持每区最多七个实例（C）。与集群群组一样，这会带来网络活动吞吐量的增加（B）。必须为分散置放群组指定不同的底层硬件，因此 D 是错误的。

## 45. S3 存储类别的持久性

**D.** 这是一个反直觉的问题。**所有 S3 存储类别具有相同的持久性**。即使是 S3 One Zone-IA，在其所驻留的单个可用区内也拥有 11 个 9 的持久性。

## 46. S3 存储类别的可用性

**A.** 可用性从 S3 的 99.99% 起步，降至 S3-IA 的 99.9%、S3 One Zone-IA 的 99.5%，最后到 Glacier 的 N/A。

## 47. 生命周期转换支持的存储类别

**D.** 如果回忆起生命周期转换涉及在这些存储类别间移动，这题很简单。**因此，所有这些类别都支持这些转换。**

## 48. S3 数据存储的区域性

**A, C.** 所有 S3 和 S3-IA 数据均存储在单一区域内，且位于该区域内至少三个可用区中。**不存在用于 S3 存储的“全局”区域。**

## 49. 适合 OLAP 的数据库服务

**C.** **Redshift** 是此列表中唯一适合联机分析处理（OLAP）的数据库或服务。DynamoDB 是对象数据库（NoSQL），Aurora 和 Oracle 均为关系型数据库，更适合事务处理。

## 50. RDS 预置 IOPS 卷存储上限

**B.** RDS 支持的所有主流数据库——MariaDB、SQL Server、MySQL、Oracle 和 PostgreSQL——均允许预置 IOPS 卷拥有高达 **16 TB** 的存储空间。

## 51. 预置 IOPS EBS 卷类型

**A.** **预置 IOPS EBS 卷**是一种固态硬盘（SSD），提供最高性能的卷。

## 52. 冷 HDD EBS 卷特性

**B.** **冷 HDD** 是最便宜的 EBS 选项，故 B 正确。它不是固态（A），不适合数据仓储（C），也不可用作启动卷。

## 53. 可用作启动卷的 EBS 类型

**A, D.** 最容易的记忆方式是：**HDD 类型不可用作启动卷**。SSD 类型（A、D）可以，故为正确答案。
