
# 恶意软件检测与特征提取

恶意软件是网络攻击的主要来源。某些恶意软件变种纯粹是静态的；每个实例都是传播它的实例的精确副本。一旦识别出单个实例，这些恶意软件相对容易检测和过滤。然而，当今更大量的恶意软件是多态的。多态恶意软件在传播过程中自我修改，使得每个实例都具有独特的语法，但携带语义相同的恶意载荷。防病毒社区投入了大量精力和人力，设计、自动化并部署算法，以检测已被人类专家识别和分析的特定恶意软件实例和多态恶意软件家族。这导致恶意软件作者与防病毒防御者之间陷入不断升级的军备竞赛，双方都在寻求开发能够抵消对方最新进展的进攻和防御手段。随着恶意软件开发难度的降低和恶意软件变种的指数级增长，许多人认为这场竞赛最终将以防御者的失败告终。

恶意代码检测问题可以建模为一个数据挖掘问题，针对的是一个既具有无限长度又存在概念漂移的数据流。概念漂移发生在多态恶意软件变异时，以及攻击者和防御者在军备竞赛中引入新技术时。这种概念化引入了我们的流分类技术，以实现对新恶意可执行文件的自动化检测。

使用 *n*-gram 分析进行特征提取涉及从给定数据集（训练集）中提取所有可能的 *n*-gram，并从中选择最佳的 *n*-gram。每个这样的 *n*-gram 都是一个特征。也就是说，*n*-gram 是一个 *n* 字节的序列。在提取 *n*-gram 之前，我们通过将二进制可执行文件转换为十六进制转储文件来对其进行预处理。这里的粒度级别为一个字节。我们应用 UNIX `hexdump` 实用程序将二进制可执行文件转换为文本文件（十六进制转储文件），其中包含对应于二进制文件每个字节的十六进制数字。执行此过程是为了确保二进制可执行文件的安全和便捷移植。在非分布式框架中，特征提取过程包含两个阶段：特征提取和特征选择，稍后将进行描述。本章介绍了这种传统技术的云计算变体。

## 8.5.2 非分布式特征提取与选择

在非分布式设置中，特征提取按如下方式进行。通过在十六进制转储文件的内容上滑动一个 *n* 字节的窗口来扫描每个文件。窗口中出现的每个 *n* 字节序列都是一个 *n*-gram。对于每个 *n*-gram *g*，我们统计包含 *g* 的文件实例总数 *tg*，以及其中属于正类（即恶意可执行文件）的总数 *pg* ≤ *tg*。

这涉及维护一个包含迄今遇到的所有 *n*-gram 的哈希表 *T*。如果在 *T* 中未找到 *g*，则将 *g* 添加到 *T* 中，计数为 *tg* = 1 且 *pg* ∈ {0, 1}，具体取决于当前文件具有负类还是正类标签。如果 *g* 已在 *T* 中，则 *tg* 增加，并根据文件标签有条件地增加 *pg*。当所有十六进制转储文件扫描完毕后，*T* 包含数据集中所有唯一的 *n*-gram 及其在正类实例中的频率和总频率。

并不总是切实际使用从当前块对应的所有文件中提取的所有 *n*-gram 特征。此类 *n*-gram 的指数级数量可能会引入不可接受的内存开销，拖慢训练过程，或用大量嘈杂、冗余或无关的特征干扰分类器。为避免这些陷阱，必须根据选择标准对候选 *n*-gram 特征进行排序，以便仅选择最佳特征。

我们选择**信息增益**作为选择标准，因为它是文献中用于选择最佳特征的最有效标准之一。信息增益可定义为属性（即特征）对训练数据分类有效性的度量。如果我们基于该属性的值分割训练数据，则信息增益度量分割后熵的预期减少量。属性减少训练数据熵的程度越高，该属性对数据分类就越有效。

我们在文献 [MASU2011] 中表明，当考虑新特征时，将它们的信息增益与堆根进行比较。如果新特征的增益大于根的增益，则丢弃根并将新特征插入堆中。否则丢弃新特征，继续特征选择。

## 8.5.3 分布式特征提取与选择

上述非分布式特征提取和选择方法存在几个缺点。

*   提取的 *n*-gram 特征总数可能非常大。例如，一个块中 4-gram 的总数约为 2 亿。可能无法将它们全部存储在主内存中。一个显而易见的解决方案是将 *n*-gram 存储在磁盘文件中，但由于磁盘读/写操作的成本，这会引入不可接受的开销。

*   如果哈希表 *T* 中的冲突特征未排序，则在特征提取期间，为测试每个扫描的 *n*-gram 是否已在 *T* 中，都需要进行线性搜索。如果它们已排序，则插入时需要线性搜索。无论哪种情况，提取所有 *n*-gram 所需的时间在每个块中 *n*-gram 总数 *N* 上都是最坏情况下的二次方时间，当 *N* ≈ 10⁸ 时，这是不切实际的时间。同样，非分布式特征选择过程要求对每个块中的 *n*-gram 进行排序。通常这需要 *O*(*N* log *N*) 时间，当 *N* 很大时也是不切实际的。

为了高效且有效地解决非分布式特征提取和选择方法的缺点，我们利用云计算的力量。这使得特征提取、*n*-gram 排序和特征选择能够并行执行，利用 Hadoop `MapReduce` 框架。

`MapReduce` [DEAN2008] 是一种在云计算环境中日益流行的分布式编程范式。该模型并行处理大型数据集，以无共享方式将工作负载分发到许多节点（机器）上。主要重点是简化使用廉价集群计算机处理大型数据集的过程。另一个目标是易用性，兼具负载均衡和容错能力。

`MapReduce` 因其两个主要函数而得名。`Map` 函数将作业分解为子任务以分发给可用节点，而其对偶函数 `Reduce` 聚合已完成子任务的结果。我们将从今往后分别把执行这些函数的节点称为 **mapper** 和 **reducer**。`MapReduce` 处理 *n*-gram 特征提取和选择的过程详见文献 [MASU2011]。本节给出该方法的高层概述。

包含 *N* 个训练文件的每个训练块被用于提取 *n*-gram。这些训练文件首先由 Hadoop 分布式文件系统 (HDFS) 分发到 *m* 个节点（机器）上（图 8.3，步骤 1）。数量 *m* 由 HDFS 根据系统可用性选择。然后每个节点使用 4.1 节 中讨论的技术，独立地从提供给该节点的训练文件子集中提取 *n*-gram（图 8.3，步骤 2）。当所有节点完成作业后，从每个节点提取的 *n*-gram 被汇总（图 8.3，步骤 3）。

例如，假设节点 1 在一个正实例（即恶意训练文件）中观察到 *n*-gram `abc`，而节点 2 在一个负实例（即良性实例）中观察到它。这在图 8.3 中分别用节点 1 和节点 2 下的 `abc`、+ 和 `abc`、− 表示。当 *n*-gram 合并时，包含相同 *n*-gram 的实例的标签会被聚合。因此，`abc` 的聚合对为 `abc`、+−。合并后的 *n*-gram 被分发到 *q* 个 Reducer（由 HDFS 根据系统可用性选择 *q*）。每个 Reducer 首先统计聚合标签以获得正计数和总计数。以 *n*-gram `abc` 为例，我们得到的统计结果为 `pabc` = 1 和 `tabc` = 2。Reducer 利用这些统计结果从提供给该节点的 *n*-gram 子集中选择最佳的 *S* 个 *n*-gram（图 8.3，步骤 5）。这可以通过大小为 *S* 的最小堆高效完成；该过程需要 *O*(*W* log *S*) 时间，其中 *W* 是提供给每个 Reducer 的 *n*-gram 总数。相比之下，非分布式版本需要 *O*(*W* log *W*) 时间。因此，从 *q* 个 Reducer 节点，我们获得 *qS* 个 *n*-gram。从中，我们通过运行另一轮 MapReduce 再次选择最佳的 *S* 个，其中 Map 阶段不执行任何操作，而 Reduce 阶段仅使用一个节点执行特征选择（图 8.3，步骤 6）。特征集中的每个特征都是二元的；如果在给定实例（即可执行文件）中存在，其值为 1，否则为 0。对于每个训练或测试实例，我们计算特征向量，其位由相应特征集的特征值组成。这些特征向量被分类器用于训练和测试。

## 8.6 实验

我们在合成数据、受控环境中生成的僵尸网络流量和恶意软件数据集上评估了我们的方法。实验结果与几种基线方法进行了比较。

### 8.6.1 数据集

#### 8.6.1.1 合成数据集

为了生成具有概念漂移的合成数据，我们使用了一个移动超平面，由 $\sum_{i = 1}^{d}{a_{i}x_{i} = a_{0}}$ 给出 [WANG2003]。如果 $\sum_{i = 1}^{d}{a_{i}x_{i} \leq a_{0}}$，则该示例为负；否则为正。每个示例是一个随机生成的 *d* 维向量 {`x`[1], …, `x`[*d*]}，其中 `x`[*i*] ∈ [0, 1]，权重 {`a`[1], …, `a`[*d*]} 也在范围 [0, 1] 内随机初始化为实数。`a`[0] 的值会被调整，以便生成大致相同数量的正负示例。这可以通过选择 $a_{0} = \frac{1}{2}\sum_{i = 1}^{d}a_{i}$ 来完成。我们还通过随机切换 *p*% 示例的标签来引入噪声，在我们的实验中 *p* = 5。有几个参数用于模拟概念漂移。我们使用与 [WANG2003] 中相同的参数。总共生成 250,000 条记录和四个不同的数据集，其块大小分别为 250、500、750 和 1,000。每个数据集包含 50% 的正实例和 50% 的负实例。

#### 8.6.1.2 僵尸网络数据集

僵尸网络是被称为 *bot* 的受感染主机网络，全部由被称为 *botmaster* 的人类攻击者控制 [BARF2006]。Botmaster 可以向 bot 发布命令以执行恶意操作，例如发起 DDoS 攻击、发送垃圾邮件、间谍活动等。僵尸网络被广泛视为对互联网社区的巨大新兴威胁。许多前沿僵尸网络应用对等 (P2P) 技术，以便在僵尸网络拓扑演变时可靠且隐蔽地通信。这些僵尸网络是分布式且小规模的，使其更难以检测和摧毁。P2P bot 的示例包括 Nugache [LEMO2006]、Sinit [STEW2003] 和 Trojan.Peacomm [GRIZ2007]。

僵尸网络流量可以被视为具有无限长度和概念漂移的数据流。概念漂移发生在 bot 承担新的恶意任务或根据新的 botmaster 指令采用不同的通信策略时。因此，我们认为我们的流分类技术非常适合检测 P2P 僵尸网络流量。

我们使用 Nugache P2P bot [LEMO2006] 在受控环境中生成真实的 P2P 僵尸网络流量。特征提取过程的细节在 Masud 等人的文献 [MASU2008b] 中讨论。总共有 81 个连续属性。整个数据集包含 30,000 条记录，代表一周的网络流量。我们生成四个不同的数据集，其块大小分别为 30 分钟、60 分钟、90 分钟和 120 分钟。每个数据集包含 25% 的正实例（僵尸网络流量）和 75% 的负实例（良性流量）。

#### 8.6.1.3 恶意软件数据集

我们从不同的 Windows 机器中提取了总共 38,694 个良性可执行文件，并从在线恶意软件库 VX Heavens [VX2010] 收集了总共 66,694 个恶意可执行文件，该库包含大量恶意可执行文件（病毒、蠕虫、特洛伊木马和后门）。良性可执行文件包括 Windows 安装文件夹中发现的各种应用程序，以及默认程序安装目录中的其他可执行文件。

在这两种情况下，我们仅选择 Win32 可移植可执行文件 (PE)。ELF 可执行文件的实验是未来潜在的工作方向。收集的 105,388 个文件（良性和恶意）形成了一个包含 130 个块的数据流，每个块包含 2,000 个实例（可执行文件）。流的顺序是通过按版本和发现日期对恶意软件进行排序来选择的，模拟了互联网恶意软件的演变性质。每个块包含 1,500 个良性可执行文件（75% 负实例）和 500 个恶意可执行文件（25% 正实例）。该数据集的特征提取和选择过程在前面的章节中已描述。

请注意，所有这些数据集本质上都是动态的。它们无界（潜在无限长度）的大小使其超出了纯静态分类框架的范围。合成数据也表现出概念漂移。虽然无法准确确定真实数据集是否具有概念漂移，但从理论上讲，当在很长一段时间内观察时，可执行文件流应该表现出概念漂移。恶意软件数据表现出特征演化，这从为每个块识别出的不同区分特征集得到了证明。

### 8.6.2 基线方法

对于分类，我们使用 Weka 机器学习开源包 [HALL2009]。我们应用了两种不同的分类器：J48 决策树和 Ripper。然后将以下每种基线技术与我们的 EMPC 算法进行比较。

*   **BestK**：这是一种单分区、单块 (SPC) 集成方法，使用最佳 *K* 个分类器的集成。集成通过存储迄今为止见过的所有分类器，并根据在最近训练块上的预期误差选择最佳 *K* 个来创建。实例通过简单多数投票进行测试。

*   **Last**：在这种情况下，我们仅保留在最近训练块上训练的分类器。这可以被视为 *K* = 1 的 SPC 方法。

*   **AWE**：这是使用准确率加权分类器集成 [WANG2003] 实现的 SPC 方法。它构建一个包含 *K* 个模型的集成，其中每个模型都从一个数据块训练而来。集成更新如下。设 `Cn` 为在最近训练块上构建的分类器。从现有的 *K* 个模型和最新模型 `Cn` 中，根据它们在最近训练块上的误差选择最佳的 *K* 个模型。选择基于加权投票，其中每个模型的权重与其在最近训练块上的误差成反比。

### 8.6.3 Hadoop 分布式系统搭建

我们实验所用的分布式系统由一个包含十个节点的集群组成。每个节点具有相同的硬件配置：Intel Pentium IV 2.8 GHz 处理器、4GB 主内存和 640GB 硬盘空间。软件环境包括 Ubuntu 9.10 操作系统、Hadoop-0.20.1 分布式计算平台、JDK 1.6 Java 开发平台以及 100MB 局域网链路。

## 8.7 讨论

我们的工作考虑了一个纯粹由句法特征组成的特征空间：从可执行代码段、静态数据段、头部以及不可信文件的所有其他内容中提取的二进制 `n`-gram。更高层级的结构特征（如调用图和控制流图）以及动态特征（如运行时轨迹）超出了我们当前的研究范围。尽管如此，`n`-gram 特征已被观察到对恶意软件检测具有极高的判别能力，这既得到了大量先前工作的证明，也得到了我们实验的验证。部分原因在于，跨越整个二进制文件内容（包括头部和数据表）的 `n`-gram 集合捕获了重要的底层结构细节，而这些细节往往被更高层级的表示形式所抽象掉了。例如，恶意软件通常包含使用非标准工具汇编和链接的手写汇编代码。这使得攻击者能够实现高级源语言和标准编译器无法提供的二进制混淆和底层漏洞利用。因此，恶意软件通常包含异常的指令编码、头部结构和链接表，它们的异常只能在原始二进制层面看到，而无法在汇编代码清单、控制流图或系统 API 调用轨迹中发现。将特征空间扩展以包含这些额外的高层级特征，需要一种高效可靠的方法来收集它们，并在特征选择期间评估其相对判别能力，这被保留为未来的研究课题。

文献 [MASU2011] 中报告的实证结果证实了我们的分析，即多划分、多块方法的表现应优于单块、单划分方法。直观上，基于多个块训练的分类器应比基于单个块训练的分类器具有更高的预测准确性，因为其拥有更大的训练数据。此外，如果通过多划分训练数据来训练多个分类器，所得分类器集成的预测准确性应高于基于相同训练数据训练的单个分类器，这是由于集成相对于单一分类器具有错误降低的能力。另外，EMPC 的准确性优势可归结为我们的工作与 AWE 之间的两个重要差异。首先，当 AWE 在集成更新过程中移除一个分类器时，来自相应块的所有信息都会被遗忘；但在 EMPC 中，来自较早块的一个或多个分类器可能会保留下来。因此，EMPC 的集成更新倾向于保留比 AWE 更多的信息，从而形成更好的集成。其次，AWE 至少需要 `Kv` 个数据块，而 EMPC 至少需要 `K + r − 1` 个数据块即可获得 `Kv` 个分类器。因此，AWE 倾向于在集成中保留比 EMPC 古老得多的分类器，导致一些过时的分类器可能对分类准确性产生负面影响。
