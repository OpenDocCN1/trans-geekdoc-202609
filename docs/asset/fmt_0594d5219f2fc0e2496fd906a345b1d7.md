**B.** 使用 UDP 代替 TCP 发送所有流量。

**C.** 破解防火墙并打开通信所需的端口。

**D.** 对连接防火墙的交换机进行 MAC 泛。

![Image](img/r.jpg)

**A.** 如果你恰好拥有 *CEH Certified Ethical Hacker All-in-One Exam Guide, Fifth Edition*（这本练习题集的配套书籍），你无疑已经意识到我一直在强调，在现实世界中，协议并不一定绑定到特定的端口号。当然，`FTP` 应该在 `TCP` 端口 `21` 上，`SMTP` 应该运行在 `25` 端口上，`Telnet` 应该在 `23` 端口上，但残酷的实实是*它们并不非如此*。一个 `HTTP tunnel` 就是这种技术的绝佳例子。对于防火墙和其他所有观察者来说，来自你机器的流量正通过无害的旧端口 `80` 运行——大家看，没什么好玩的，只是普通的 HTTP 流量。但看一眼那个无害的小隧道内部，你会发现你可以运行*任何你想运行的内容*。通常，你通过端口 `80` 连接到外部服务器，一旦你绕过了那个讨厌人的防火墙，它就会替你解包并转发你的其他协议流量。

![Image](img/w.jpg)

![Image](img/w.jpg)

![Image](img/w.jpg)

**D** 是错误的，因为 MAC 泛是指在交换机上进行主动嗅探，而不是绕过防火墙。

### 25. 一位道德黑客被分配扫描一个服务器，并希望避免 IDS 检测。她使用了一种策略，将 TCP 头部拆分成许多数据包，使得难以检测这些数据包的意图。以下哪项最能描述所采用的技术？

**A.** TCP 扫描

**B.** IP 分段扫描

**C.** ACK 扫描

**D.** 反向 TCP 扫描

![Image](img/r.jpg)

**B.** 尝试规避 IDS 有多种方法，`IP fragment scan` 是其中之一。它通过将原始 `TCP` 头部拆分成多个较小的数据包来工作。这些较小的数据包单独对 `IDS` 来说毫无意义，但在目的地重组后可以进行扫描（这并不是说这种方法总是有效——几乎没有什么东西是无懈可击的——但我几乎可以保证你在某处会看到这种规避技术）。

**A, C** 和 **D** 都是错误的，原因相同：所使用的扫描*类型*与题目询问的规避方法无关。将头部拆分段规避方法适用于任何扫描类型。
