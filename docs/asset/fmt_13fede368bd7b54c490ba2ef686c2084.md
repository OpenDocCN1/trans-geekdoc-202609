
> **针对 Security+ 考试，请务必了解不同的认证因素和不同的认证属性。例如，请记住 `Something you have`（你所拥有的）是一种认证因素，而 `Something you can do`（你能做的事）是一种认证属性。**

双因素认证方案将基于两种认证因素，例如 `Something you know`（你所知晓的）和 `Something you have`（你所拥有的）。例如，你拥有一张银行卡（`Something you have`）并且知道该银行卡的 PIN 码（`Something you know`）。这种认证方案比仅凭持有银行卡即可访问账户要强得多。如果是那种情况，任何持有银行卡的人都能从账户中取款。

对于考试，请知道智能卡属于双因素认证，因为你需要拥有智能卡并且需要知道 PIN 码。双因素认证的另一个例子是进行指纹扫描然后输入密码。在该示例中，两个因素分别是 `Something you are`（你本身的特征）和 `Something you know`（你所知晓的）。

三因素认证方案将基于所有三个因素——`Something you know`（你所知晓的）、`Something you have`（你所拥有的）和 `Something you are`（你本身的特征）。例如，员工可能需要进行视网膜扫描、刷卡，并知道该卡的 PIN 码。

### 认证管理

当我们谈论认证时，我们大多数人通常会想到一个环境，在那里我们必须输入冗长、复杂的密码或使用加密密钥来访问加密信息。Security+ 考试要求你熟悉许多有助于管理这些密码和加密密钥的术语和技术：

#### 密码密钥

密码密钥是用户用于访问本地系统或网站的秘密值。

#### 密码保管库

密码保管库是一种加密数据库，用于存储用户可能访问的本地系统和网站的许多不同密码。密码管理器软件生成复杂密码，并为不同系统检索它们。

#### TPM

可信平台模块（`TPM`）是系统上的一个计算机芯片，可用于存储具有加密驱动器的系统的加密密钥。`TPM` 还可与安全启动配合使用，以确保启动环境的完整性。

#### HSM

硬件安全模块（`HSM`）是一种可添加到系统的卡，用于生成和存储加密密钥。它还可根据需要对系统上的数据执行加密和解密。

#### 基于知识的认证

当验证您身份的系统或人员询问只有您知道的信息时。例如，如果您致电银行，他们可能会询问您账户上次购买的信息；如果您致电加拿大税务局（`CRA`），他们会询问您去年纳税申报表的详细信息，例如“您去年纳税申报表第 150 行的金额是多少？”

#### 单点登录

关于认证的一个重要概念是单点登录，也称为 `SSO`。单点登录的原则是：当您向网络进行身份验证时，您有能力根据您的身份验证信息访问多个系统。使用 `SSO`，您无需向访问的每个不同系统进行身份验证——您只需验证一次，然后即可在无需再次验证的情况下访问多个系统。

为什么 `SSO` 如此有价值？多年前，您必须单独向每台服务器进行身份验证。这意味着每个系统都存储一个单独的用户名和密码数据库，用户必须记住各种密码才能访问多台服务器。使用 `SSO`，用户使用一组凭据登录，然后访问许多不同的服务器，甚至是其他组织的服务器。针对您组织中的身份存储进行身份验证，并被授权使用其他组织的网络服务，称为*身份联合*。

![Image](img/exam.jpg)

**Security+ 考试要求您知道单点登录（`SSO`）允许用户向网络进行一次身份验证，并访问多个系统，而无需提供额外的凭据。**

`SSO` 的好处在于，作为网络管理员，您无需为每台服务器管理多个用户名和密码。然而，同时 `SSO` 的缺点是，如果黑客攻破了账户，他们可以访问多台服务器。如果您不在 `SSO` 环境中，黑客攻破了账户，他们将只能访问那台服务器，并需要攻破另一个密码才能访问不同的服务器。

![Image](img/exam.jpg)

**对于 Security+ 考试，请知道 `SSO` 环境存在风险。如果黑客能够破坏认证方案，例如破解密码，那么他们就能访问网络上的多个系统。**

##### 访问令牌

当用户登录到系统或网络时，会为该用户创建一个访问令牌，用于确定他们是否应被允许访问资源或执行操作系统任务。此逻辑令牌维护资源验证所需的所有信息，并包含以下信息：

- **安全标识符（`SID`）** `SID` 是分配给用户的唯一编号。`SID` 是 Windows 用来识别用户的标识，而不是实际的用户名。我们知道 Bob 是 `bsmith` 用户账户，但 Windows 通过他的 `SID` 认识 Bob，看起来类似于 `S-1-5-21-2752813485-788270693-1974236881-116`。

- **组安全标识符** 访问令牌包含用户所属的任何组的列表。这很重要，因为当用户双击资源时，资源通常配置有分配给组的权限。Windows 通过访问令牌检查用户属于哪些组，然后检查这些组中是否有一个拥有对所访问资源的权限。如果访问令牌中包含的组被允许访问该资源，用户将获得对该资源的访问权限。

- **主要组安全标识符** 为符合 POSIX 标准，您可以指定主要组——即在 POSIX 环境中成为文件和目录所有者的组。主要组默认设置为“域用户”，在 Microsoft 环境中很少使用。

- **访问权限** 在登录过程中，Windows 确定您在操作系统中的权利，并将权利列表存储在访问令牌中。例如，如果您拥有“更改系统时间”权利，该信息会在登录过程中存储在访问令牌中。如果您尝试更改计算机上的时间，将检查您的访问令牌中是否有该权利；如果权利在访问令牌中，则允许您更改系统时间。

重要的是要注意，访问令牌仅在登录时创建，因此如果您将用户添加到新组，该用户需要注销并重新登录，访问令牌才会在组成员列表中包含新组。再次登录后，用户应该能够访问新添加的组可以访问的任何资源，因为访问令牌已更新。

#### 云与本地部署需求

当我们查看本地部署环境的认证方案时——即您日常访问的本地 LAN 或 WAN 上的服务器——大多数系统要求您首先向网络进行身份验证。对于常规网络，您通常只需使用用户名和密码登录，但对于高安全性网络，您可能会使用某种形式的多因素认证（`MFA`）。

对于基于云的环境或任何需要身份验证的网站，您应该考虑实施 `MFA`。大多数云服务允许用户将移动设备注册到其用户账户，以便当他们登录时，验证码会发送到他们的手机，然后他们必须输入该验证码以证明他们是他们声称的人。这确保了即使有人弄清了您的用户名和密码，也无法进入该网站或云服务。

### 认证目标 10.02

### 认证协议

当用户提供用户名和密码等凭据时，它们会通过认证协议传递给认证服务器。认证协议决定了认证信息如何从客户端传递到服务器。在本节中，您将了解不同的认证协议。

#### Windows 认证协议

我要介绍的第一类认证协议是 Windows 认证协议。这些认证协议存在于 Internet 信息服务（`IIS`）和 Exchange Server 等 Microsoft 产品中。以下是 Microsoft 世界中使用的许多认证方法的说明：

- **匿名认证** 您无需登录服务器。Windows 使用实际服务的账户，您将作为该账户被传递。匿名账户拥有什么权限，您在匿名连接时就拥有什么权限。这是网站和 FTP 服务器常用的认证方法。

- **基本认证** 您需要登录，用户名和密码以明文形式发送到服务器。这意味着如果有人在您和服务器之间使用数据包嗅探器，该人将能够捕获您的密码并查看它，因为它未加密。

#### 集成 Windows 身份验证

您需要登录到服务器，但您的用户名和密码将以加密格式发送到服务器。如果要求用户登录，此身份验证方法比基本身份验证更安全。

#### Kerberos

一种流行的相互身份验证协议，默认用于 Microsoft Active Directory 环境。Active Directory 遵循轻量级目录访问协议（`LDAP`）标准，这是用于访问和查询目录的 Internet 协议。Kerberos 使用密钥分发中心（`KDC`）服务器，该服务器负责颁发票据。客户端要从网络（称为领域）上的任何其他服务器请求服务，都需要这些票据。当客户端登录到网络时，Kerberos 过程即开始。`KDC` 有一个称为身份验证服务器（`AS`）的组件，它向客户端提供票据授予票据（`TGT`），授予客户端请求服务票据的权限。请求网络上服务器的服务需要服务票据。当客户端想要连接到网络上的特定服务器时，它必须从票据授予服务（`TGS`）请求票据，`TGS` 是 `KDC` 的另一个组件。`TGS` 向客户端授予票据，以便客户端可以访问网络上所需的服务器。

**Security+ 考试要求您了解刚才列出的不同身份验证方法。请务必知道 `KDC` 在 Kerberos 中用作向需要访问网络服务的客户端发送票据的系统。**

#### 常见身份验证协议

前述身份验证方法非常“以 Microsoft 为中心”，但标准协议也用于执行身份验证。这些标准身份验证协议被各种网络服务使用，例如远程访问服务（`RAS`）和虚拟专用网络（`VPN`）。

`RAS` 是一种远程访问技术，它使用点对点协议（`PPP`）作为电话应用程序（用于拨号）连接到 `RAS` 服务器的远程访问协议，支持点对点连接。`VPN` 通过不受信任的网络（如 Internet）上的安全通道连接到远程服务器（`VPN` 服务器）。无论使用带有 `RAS` 的拨号连接还是安全的 `VPN` 连接，`RAS` 和 `VPN` 都支持以下身份验证协议：

#### 密码身份验证协议（`PAP`）

密码身份验证协议以明文形式发送用户的凭据，非常不安全，因为分析和解读登录流量非常容易。这是前面提到的基本身份验证方法所使用的身份验证协议。

#### 质询握手身份验证协议（`CHAP`）

使用质询握手身份验证协议时，服务器向客户端发送质询，随后在身份验证过程中使用。`CHAP` 执行以下步骤：

1. 服务器向客户端发送质询（一个密钥）。

2. 客户端将质询与密码结合。用户的密码和质询都通过 `MD5` 哈希算法（一种公式）运行，生成一个哈希值（一个数学结果）。哈希值被发送到服务器进行身份验证。

3. 服务器使用相同的密钥与存储在服务器上的密码创建一个哈希值，然后将生成的值与客户端发送的哈希值进行比较。如果两个哈希值相同，则客户端提供了正确的密码。其优势在于用户的凭据根本没有通过网络传输。

#### Microsoft 质询握手身份验证协议（`MS-CHAP`）

`MS-CHAP` 是 `CHAP` 的一种变体，它使用 `MD4` 作为哈希算法，而 `CHAP` 使用 `MD5`。`MS-CHAP` 还使用 Microsoft 点对点加密（`MPPE`）协议加密从客户端到服务器的所有流量。

#### MS-CHAPv2

使用 `MS-CHAP` 版本 2 时，身份验证方法已扩展为对客户端和服务器进行双向身份验证。`MS-CHAPv2` 还比 `CHAP` 和 `MS-CHAP` 使用更强的加密密钥。

#### 可扩展身份验证协议（`EAP`）

可扩展身份验证协议允许多种登录方法，例如智能卡登录、证书、Kerberos 和公钥身份验证。`EAP` 也经常与 `RADIUS` 一起使用，`RADIUS` 是一种中央身份验证服务，可被 `RAS`、无线和 `VPN` 解决方案使用，详见下一节。

如果您有通过 Internet 连接以访问公司资源的远程用户，您应该使用加密从用户计算机到 `VPN` 服务器通信的 `VPN`。

#### 身份验证服务

现在您已经了解了考试所需的一些不同身份验证协议，让我们继续了解身份验证服务。提到身份验证服务，我们通常会想到以下内容：

### 标识

向系统提供关于您自己的标识信息的过程。标识过程通常要求用户输入用户名，但也可能要求用户将智能卡插入读卡器，例如。

### 身份验证

身份验证服务负责验证用户提供的凭据，通常涉及拥有一个包含标准的身份验证数据库。例如，当用户使用用户名和密码登录时，该信息将针对账户数据库进行验证。

### 授权

一旦账户信息得到验证，用户即被授予网络访问权限。授权组件可能需要除账户信息以外的其他标准才能授予访问权限。例如，授权服务可能要求身份验证请求来自特定子网。

### 审计

审计处理活动日志记录。这可能是记录活动以便跟踪用户在做什么并让他们负责，也可能是跟踪服务或应用程序的使用情况，以便为不同部门使用系统的情况计费。

重要的是要注意，身份验证、授权和审计这三项身份验证服务在业界统称为 `AAA`。多年来出现了许多 `AAA` 服务，例如 `RADIUS`、`DIAMETER` 和 `TACACS+`。这些服务提供中央身份验证系统的优势，可为多种环境（如无线、`RAS` 和 `VPN`）提供身份验证、授权和审计。

##### RADIUS

远程认证拨号用户服务（`RADIUS`）是一种流行了很多年的中央身份验证服务。顾名思义，它最初用于拨号服务。需要访问网络的客户端计算机通过拨号连接到 `RAS` 服务器，或通过 Internet 连接到 `VPN` 服务器来连接网络。在这种情况下，`RAS` 或 `VPN` 服务器被称为 `RADIUS` 客户端，因为它将身份验证请求发送给在后台运行的 `RADIUS` 服务器。该 `RADIUS` 服务器验证凭据并发回回复，指示是授予还是拒绝网络客户端访问（参见图 10-1）。

# 认证协议与实现

回顾第 8 章，`802.1X` 是一种常见的认证协议，它通过要求客户端针对中央认证数据库（如 `RADIUS` 服务器）进行认证，来控制谁能访问有线或无线网络。你可以使用 `802.1X` 来控制对支持 `802.1X` 认证的无线网络和交换机的访问。这是一种实现*网络访问控制（NAC）*的方法，即控制谁可以连接到网络。
