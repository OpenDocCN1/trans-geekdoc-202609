
# 编写正确算法的一个非正式步骤是能够对你的代码做出不同种类的断言。

## 前置条件

任何代码片段（无论是方法、循环还是代码块）的**前置条件**是关于该代码执行前立即为真的陈述。

## 后置条件

代码片段的**后置条件**是关于该代码执行后立即为真的陈述。

## 效率

高效算法是指在以下方面经济的算法：

*   **CPU 时间**。这指执行算法所需的机器操作数量（算术运算、比较、数据移动等）。
*   **内存**。这指所用变量的数量和复杂度。

影响运行时效率的一些因素包括：不必要的测试、数据元素的过度移动以及冗余计算，尤其是在循环中。

应始终力求尽早检测输出条件：你的排序算法应在列表已排序时停止；你的搜索应在找到关键元素时停止。

在讨论算法效率时，我们提到**最好情况**、**最坏情况**和**平均情况**。最好情况是导致算法以最少可能时间运行的数据配置。最坏情况是导致最大可能运行时间的配置。典型配置（即非特意挑选的数据）给出平均情况。最好、最坏和平均情况的运行时间可能相差不大。

例如，假设必须在一个由不同随机数组成的列表中搜索给定的键值。所用算法是从列表开头开始的顺序搜索。在最好情况下，键将在第一个被检查的位置被找到。在最坏情况下，它将在最后一个位置或根本不在列表中。平均而言，键将位于列表的中间位置。

## 答案解析

1.  **(E)** 程序员绝不应单方面决定程序规格说明。存疑时，应与编写规格说明的人核对。

2.  **(D)** 在 I 和 II 中，被操作的对象是一个三位数。然而对于 III，对象是一个六字符字符串，这暗示了一个不同于`ThreeDigitNumber`的类。

3.  **(E)** 自顶向下编程包含列出主对象的方法，然后使用逐步求精将每个方法分解为子任务列表。排除选项 A、C 和 D：自顶向下编程指的是设计和规划阶段，不涉及任何实际代码编写。选项 B 更接近要点，但“自顶向下”意味着操作列表，而非描述方法的文章。

4.  **(E)** 选择算法时，这三个考量因素均有效。如果你的代码将成为由多位程序员创建的大型项目的一部分，因素 III 尤为重要。然而，即使你是某软件的唯一编写者，也要意识到你的代码将来可能需要由他人修改。

5.  **(B)** 导致过度数据移动的过程是低效的。将元素插入其正确（已排序）的位置涉及移动元素以腾出空位。在最坏情况下，新元素必须插入第一个位置，这涉及将每个元素都向上移动一个位置。类似地，删除元素涉及将元素向下移动一个位置以填补“空隙”。在最坏情况下（删除第一个元素），数组中的所有元素都需要移动。对列表中最小的五个元素求和意味着对前五个元素求和。这不需要测试元素，也不涉及过度数据移动，因此是高效的。在已排序列表中查找最大值非常快——只需选取列表适当一端的元素即可。

6.  **(C)** “健壮性”意味着能够处理用户输入的所有数据，并即使对于极端数据值也能给出正确答案。一个不健壮的程序完全可能在另一台计算机上无需修改即可运行，而一个健壮的程序在另一台计算机上运行前可能需要修改。

7.  **(C)** 排除选项 D，因为 0 是无效重量，且从方法描述可推断无效数据已被筛除。排除选项 E，因为它测试了 10–25 范围内的两个值（这并非错误，但选项 C 更好）。排除选项 A，因为它仅测试端点值。排除选项 B，因为它*不*测试任何端点值。

8.  **(A)** 该语句在语法上是正确的，但按原样编写将无法求出这些整数的平均值。因此该 bug 属于意图错误或逻辑错误。要按预期执行，该语句需要加上括号：

    ```
    double average = (n1 + n2 + n3 + n4) / (double) 4;
    ```

9.  **(D)** 发生的错误是由尝试除以零（`ArithmeticException`）引起的运行时错误。不要被选项 C 迷惑。仅从输入文件读取表达式`8/0`不会导致错误。注意如果操作数类型为`double`，正确答案将是 E。在这种情况下，除以零不会导致异常；它会给出`Infinity`作为答案。只有检查输出时才会清楚地发现出了问题。

10. **(D)** 游戏 I 和 II 非常适合使用整数值来描述下一步移动。对于猜数字游戏，`getMove()`将返回下一次猜测；对于筹码游戏，`getMove()`将返回玩家回合移除的筹码数量。游戏 III 井字棋要求玩家的下一步移动是 3×3 网格上的一个位置：简单的整数值不适合作为`getMove`方法的返回类型。

11. **(A)** 前置条件不关心方法的动作、局部变量、算法或后置条件。它也不初始化参数。它仅断言方法执行直接之前必须为真的条件。

12. **(A)** 最佳情况导致最少的计算机操作，最坏情况导致最多的操作。在给定算法中，初始测试`if (a1 > a2)`和对`max`的赋值无论哪个值最大都会发生。第二个测试`if (max < a3)`也将始终发生。最终语句`max = a3`仅在最大值位于`a3`时发生；因此这代表最坏情况。所以最佳情况必须是在`a1`或`a2`中包含最大值。

13. **(D)** 前置条件是关于循环执行前变量的断言。变量`N`、`k`和`sum`均已初始化为选项 D 所示的值。选项 C 错误，因为`k`可能等于`N`。选项 A 错误，因为`k`可能小于`N`。选项 E 错误，因为`mean`直到循环退出后才被定义。选项 B 错误，因为它省略了关于`N`和`k`的断言。

14. **(C)** 排除选项 A 和 B，因为`i`在`for`循环中被初始化为`3`。选项 D 和 E 错误，因为第一次循环时`i`等于`3`。

15. **(D)** 量`a`被加到`total`中`b`次，这意味着执行结束时`total = a*b`。

16. **(D)** 让`Item`负责其名称、单价、数量和总价是合理的。让它负责*其他*`Item`是*不*合理的。然而，既然`ItemList`将包含所有购买`Item`的信息，让它同时计算总`amountDue`（应付金额）是合理的。让`Invoice`（发票）负责显示购买物品的信息以及提供最终总计`amountDue`同样合理。
