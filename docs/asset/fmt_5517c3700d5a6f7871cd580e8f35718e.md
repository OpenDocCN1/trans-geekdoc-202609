
技术的发展改变了多媒体通信中数据传输的状况。数据传输现在更快，复制所需的工作量更少。互联网的使用为社会、科学、商业和娱乐行业的数据交换提供了一种简单的方式。数据（即音频、语音、图像或视频等）可以在 WWW 上非常快速地传输 [1]。视频是网络上大量交换的常见多媒体对象。它已通过各种设备共享，如数字电视、手机和 PDA。

数据完整性和所有权领域的问题在全球范围内引起了极大关注。这为原创者防止任何滥用或不当行为提供了真正的挑战。所有者希望确保未经事先许可不得有任何未经授权的访问。其中一种解决方案是借助加密技术限制内容访问。然而，加密方法对于整体保护并不可靠。解密后它们不再安全。甚至难以追踪非法用户。当两个用户同时声称拥有同一对象时，如图 13.1 所示，将会出现困境来解决该问题。

以下问题可能需要合理的答案。

- 1. 谁是内容的原创者？
- 2. 我们如何证明所有权？
- 3. 原始内容是否被篡改？
- 4. 内容是在哪里创建的？
- 5. 谁篡改了内容？
- 6. 如果所有者发现其内容的非法副本，他/她应去哪里投诉？

应该有一些证据可以作为法庭证据生成，以解决此类所有权问题。借助各种编辑工具，内容视频能够被大量复制和传播。传统的保护方案不再非常适合视频安全。数字水印领域用于解决任何多媒体对象的身份验证问题。我们在本章讨论了视频水印。

## 13.1.1 动机

水印的想法相当古老，几乎有 700 年历史。它被造纸商用来授权产品。

在软件水印中，算法在 PC 上运行，有助于对视频进行水印处理，之后将被分发。然而，当视频被捕获且水印被插入时，这种延迟的主要缺点是，如果攻击者在水印嵌入之前攻击视频，则可能为原创者造成所有权问题。

水印系统的开发主要需求是由于对知识产权 (`IPR`) 的担忧。如果在捕获视频时插入水印，则基于 `HEVC`（高效视频编码）的实时水印可以缓解此类问题。

对于无压缩水印，比特流会被部分解码以插入水印，然后再次编码以生成安全的比特流。在压缩域水印中，水印与压缩标准一起嵌入。本章重点介绍基于 `HEVC` 标准的视频水印的硬件实现。因此，捕获和嵌入水印之间的延迟正在减少是软件水印的缺点。我们方案的硬件模块支持整数运算，因此可以适配 `HEVC` 编码器，生成实时安全的比特流。水印嵌入单元的并行数据通路架构被设计为前向编码器通路中的关键部分。

各章节的暂定流程如下：第13.2节包含视频水印的基本背景理论，讨论了实时视频水印所需的期望特性，并阐述了视频水印硬件实现的相关工作。第13.3节强调 `HEVC` 视频编码的基本概念。第13.4节描述所提出的视频水印算法，将解释水印嵌入过程和水印提取过程中涉及的步骤。第13.5节重点介绍我们安全水印系统的实现，同时解释整数 `DCT`（离散余弦变换）的架构。第13.6节通过 `MATLAB®` 和硬件平台上的结果分析所提出的视频水印，所提出方案的硬件结果涵盖现场可编程门阵列（`FPGA`）和专用集成电路（`ASIC`）实现。最后，第13.7节得出结论并讨论进一步工作的范围。

## 13.2 背景与相关工作

在当今多媒体世界中，视频被频繁用于交换。因此，视频媒体内容发生版权侵权的可能性最大[3]。视频被视为帧的集合，其中每一帧被视为一幅静止图像[4]。早期，水印算法主要面向软件平台[5]。任何水印方案的设计都需要若干特性，例如不可见性、盲检测和鲁棒性。计算复杂度是 `VLSI` 实现的关键因素[6]。目前缺乏面向硬件平台的实时水印方案。`Shoshan` 等人[7]和 `Li` 等人[8]提到了硬件实现的多种挑战及其应用。

`Petitjean` 等人[9]描述了针对 `DSP` 和 `VLIW` 处理器的新型视频水印方案，该方案后来扩展到硬件实现。然而，基于 `MPEG` 标准的算法需要某种使用浮点运算的分形编码方法。由于计算密集，该方法无法直接应用于实时应用。

`Brunton` 和 `Zhao`[10]为实时应用设计了空间域视频水印。该算法利用传入视频帧中的像素变化检测概念，并进一步面向可编程硬件。该算法在空间域中演示，因此鲁棒性较差，不适合滤波和压缩攻击。

`Jeong` 等人[11]提出了一种使用 `Haar` 小波插入不可见水印的鲁棒水印方案。该算法在伪影方面存在一些问题，影响了含水印视频的感知特性。

`ElAraby` 等人[12]演示了一种基于 `FPGA` 实现的视频水印，其中伪随机序列（作为水印）以低值嵌入到 `DCT` 中。该方法用于在视频的每一帧中添加不可见水印。该方法不适用于任何压缩标准，且基于未压缩视频。

`De Strycker` 等人[13]展示了用于广播监控的实时水印。该算法在 `Trimedia` 处理器上以 4 BOPS 实现。水印过程中将伪随机值嵌入输入流。水印嵌入过程使用未压缩视频，提取过程中应用相关性。该算法计算复杂度高，阻碍了实时实现。

`Maes` 等人[14]实现了用于 `DVD` 版权保护的 `Millennium` 水印方案。该算法在水印嵌入的同时使用额外的安全级别进行加密。该系统对内存需求较大，这阻碍了其与消费设备定制硬件的集成。

`Mathai` 等人[15]提出了使用 `JAWS`（另一种水印系统）方法进行视频水印的 `VLSI`（超大规模集成电路）实现。该概念使用 `FFT`、滤波过程和浮点数据通路在接收端进行变换。该算法同样基于未压缩视频，不适用于压缩标准。

`Tsai` 和 `Wu`[3]设计了基于空间域和变换域的扩频水印。设计了可集成到 `MPEG` 编码器中的 `VLSI` 架构。然而，浮点数据通路设计限制了其在实时应用中的范围。

`Vural` 等人[16]设计了一种使用小波的可追踪水印方案，其中水印嵌入到视频每一帧的低频分量中。使用伪随机生成器选择帧进行水印嵌入。水印有助于在编码器端实现安全传输。水印的提取遵循盲过程。该算法基于小波变换，而大多数标准使用 `DCT`。因此，水印嵌入模块的集成与视频标准不兼容。

`Mohanty` 和 `Kougianos`[17]提出了一种用于视频广播的实时可见水印方案。提出了 `VLSI` 架构，并完成了适用于 `MPEG-4` 标准的 `FPGA` 原型设计。然而，该算法使用感知水印概念，实际应用有限。

`Roy` 等人[18]开发了一种半脆弱且不可见的水印嵌入过程，用于视频认证目的。该方案针对 `MJPEG` 压缩设计。该算法使用浮点运算进行 `DCT` 计算。使用浮点 `DCT` 使其不适用于 `HEVC` 标准。

`Joshi` 等人[19]开发了一种高效的水印嵌入过程。该算法面向 `H.264` 标准，涵盖不可见和盲视频水印。值得注意的是，所有方案都是针对 `MPEG` 或 `H.264` 视频压缩标准开发的。其中少数方案完全未用于视频压缩标准。所提出的基于 `HEVC` 的算法在水印过程中使用 `AC` 预测概念。它具有以下特性：

- 涉及整数运算，降低了计算复杂度
- 使用场景变化检测概念，将同一水印的位平面嵌入到场景的不同帧中，以获得更强的鲁棒性

## 13.3 HEVC 视频编码标准

用于视频压缩的编码方法和比特流结构在称为视频编码标准的文档中描述。视频编码标准定义了一组用于压缩的工具。标准不包含所有解码设计技术。消费者在选择不同制造商时具有很大的灵活性。工作组——动态图像专家组（`MPEG`）与国际标准化组织（`ISO`）、视频编码专家组（`VCEG`）与国际电信联盟电信标准化部门（`ITU-T`）——独立或联合制定了一系列视频标准。`ISO` 制定的常见标准包括 `MPEG-4`、`MPEG-2` 和 `MPEG-1`。`ITU-T` 制定了 `H.263`、`H.262`、`H.261`。`H.264/AVC`（高级视频编码）或 `MPEG-4 Part-10` 视频编码由 `VCEG` 和联合视频组（`JVT`）开发。高效视频编码（`HEVC`）由视频编码联合协作组（`JCT-VC`）设计。

`H.265/MPEG` 或 `HEVC` 几乎包含了先前标准 `H.264/MPEG AVC` 的所有特性，同时强调高清视频编码和并行处理。`HEVC` 在相同的视觉质量下实现了非常高的比特率。`HEVC` 具有以下重要特性：

- 实现非常高的压缩率
- 高清视频的高吞吐量
- 低功耗
- 高度并行的架构
- 更轻松地向移动设备流式传输高清视频

最流行的视频压缩格式是基于 `DCT` 的 `MPEG-X`（`ISO` 标准）和 `H.264-x` 格式（`ITU-T` 标准）[20]。

## 13.4 盲且鲁棒的视频水印算法

所提出的算法使用整数 `DCT`，可以轻松与 `HEVC` 集成。它涉及整数运算，从而提高了实时性能。它利用预测概念，通过邻近块的 `DC` 系数值来估计中间块的 `AC` 系数值。

![](img/f4c3bcc9f5332d57a8ec85a75075f8da_383_0.png)

图 13.2 8 × 8 子块的频率分布。 (引自 Lam, E.Y. and Goodman, J.W., IEEE Trans. Image Process., 9, 1661–1666, 2000.)

在视频的帧（或静止图像）的情况下，相邻像素值之间存在帧内相关性。每个帧被划分为 3 × 3 大小的块组，其中每个块包含一个 8 × 8 子块（共 64 个像素）。该过程生成共九个块，如图 13.2 所示。中心块（第 5 个块）的 `AC` 系数值是使用相邻块 `DC` 系数值预测的。水印嵌入在低频值中以获得更大的鲁棒性。常见的信号处理攻击和低通滤波器倾向于比中频或高频分量更少地改变低频分量。在 8 × 8 `DCT` 的子块中，左上角系数是携带一个 `DC` 分量和 5 个 `AC` 分量的低频值，如图 13.2 所示。

应用水印时不使用 `DC` 分量，因为它会引入视觉失真。用于水印的低频的五个最高 `AC` 值 `AC(0,1)`、`AC(0,2)`、`AC(1,1)`、`AC(2,0)` 和 `AC(1,0)` 被考虑在内。

### 13.4.1 水印嵌入步骤

输入为未压缩视频，原水印为图像。处理完成后，生成水印视频。水印单元是 `HEVC` 编码器的一部分。

- Step 1: 使用直方图差异检测视频中的场景变化，如下式方程 13.1 所示：

`H = Σ_{k=1}^{N} Σ_{i=0,j=0}^{N} (P₁(i,j,k) − P₂(i,j,k+1))²`   (13.1)

`P₁` 和 `P₂` 是特定视频的连续帧。`N` 是帧中像素的总数。

- Step 2: 8 位原始水印使用位平面切片方法分为多个平面，即从 `LSB` 到 `MSB`（从最低有效位到最高有效位）（共 8 个平面）。每个平面被视为一个水印。

- Step 3: 这些位平面（称为水印）被插入特定场景的各个帧中。其优点是如果发生任何失真，则不会影响整个水印，其余部分的水印仍可从剩余帧中提取。

- Step 4: 场景中的每一帧再次进一步划分为 8 × 8 大小的块。对于每个块，计算整数 2D `DCT`，得到一个 `DC` 值和其它 63 个 `AC` 值。

- Step 5: 如图 13.3 所示，使用周围块的 `DC` 值对中间块（第 5 个块）的 `AC` 值进行预测。预测过程使用方程 13.2 至 13.6 如下：

`AC_(0,1) = p1 * (DC4 − DC6)`  (13.2)

`AC_(1,0) = p1 * (DC2 − DC8)`  (13.3)

`AC_(0,2) = p2 * (DC4 − DC6 − 2 * DC5)`  (13.4)

`AC_(2,0) = p2 * (DC2 + DC8 − 2 * DC5)`  (13.5)

`AC_(1,1) = p3 * (DC1 + DC9 − DC3 − DC7)`  (13.6)

其中，`p1 = 9/64`, `p2 = 1/32`, `p3 = 3/128`。

预测过程涉及常数 `p1`、`p2` 和 `p3`，其分母值以 2^N 的形式表示，这里 `N` 为自然数。这具有优势，因为它只需要移位操作，从而避免了除法需求。与除法器相比，移位器的硬件实现更简单。所开发的水印基于整数运算，适用于整数 `DCT`。该算法在计算复杂度方面优于其他算法。

![](img/f4c3bcc9f5332d57a8ec85a75075f8da_384_0.png)

图 13.3 使用相邻块预测中心块。 (引自 Küçük tunç, O. et al., Comput. Vis. Image Underst., 114, 125–134, 2010.)

现有算法具有浮点结构，这会降低实时系统的性能。

- Step 6: 以 Δ 值为形式的水印被插入预测的 `AC` 值中以生成新的 `AC` 值，如方程 (13.7) 所示。Δ 的取值范围为 1 到 5。Δ 的特定值必须根据帧质量对鲁棒性的要求来选择。

```
If watermark bit = 1 then, set
$AC_i \ge AC_i' + \Delta$
else
$AC_i < AC_i' - \Delta$ (13.7)
```

- Step 7: 一旦水印嵌入，则执行每个块的 `Int IDCT`（整数逆 `DCT`）以获得水印。再次将所有帧累积以获得安全嵌入视频。

### 13.4.2 水印提取过程

该算法的检索是盲的。生成的加密水印视频用于提取过程。检索过程的输出为提取出的水印。

- Step 1: 安全水印视频再次使用场景变化检测方法，从特定场景收集各个帧。

- Step 2: 从场景中提取的每一帧被分离为 8 × 8 块以计算块的整数 `DCT`。

- Step 3: 第 5 个块的 `AC` 值根据相邻块的 `DC` 值再次预测，如嵌入过程中使用的方程 (13.2) 至 (13.6) 所示。

- Step 4: 通过比较原始 `AC` 值和估计 `AC` 值来找到水印位，如 (13.8) 所示。

```
If
$AC_i \ge AC_i'$
Watermark bit = 1
Else
Watermark bit = 0; (13.8)
```

- Step 5: 每个水印位有助于获得位平面。

- Step 6: 位平面被组合以获得提取的水印图像。

## 13.5 建议安全 HEVC 的实现

我们的安全系统使用基于整数 `DCT` 的水印用于 `HEVC`。因此，本节讨论整数 `DCT` 和水印过程的硬件实现。

### 13.5.1 整数 DCT 算法的实现

在 `HEVC` 标准中，2-D 整数变换借助可分离特性计算，其中首先计算 1-D 水平变换（按行），然后计算 1-D 垂直（按列）变换计算。流程如图 13.4 所示。
