
一旦检测到 rootkit，就需要对其进行删除和清理。由于 rootkits 具有侵入性，而且 rootkits 的许多方面并不易于检测，大多数系统管理员甚至不会尝试清理或删除 rootkit。与尝试确定损坏的深度和范围并尝试修复单个文件相比，使用以前捕获的干净系统镜像并对机器重新装映像要简单得多。

## 后门

`Backdoors` 最初（有时现在仍然）仅仅是软件开发人员使用的一种方法，以确保即使将来发生某些阻止正常访问方法的情况，他们也能访问应用程序。一个例子是硬编码密码，当管理员忘记自己的系统密码时，可以使用该密码获取程序的访问。这种后门（有时也称为 `trapdoor`，即陷阱门）明显的问题在于，由于它是硬编码的，因此无法被删除。如果攻击者获知了该后门，所有运行该软件的系统将受到攻击的威胁。

`backdoor` 一词也且更常见地用于指绕过加密系统、计算机或（在某些情况下）物理屏障的正常身份验证的方法。后门的一个常见例子是程序中的硬编码密码。另一个例子是开发者为了维护目的而创建的后门，后来被攻击者利用。后门可能非常危险，因为它们为攻击者访问系统提供了便利的途径。

## 逻辑炸弹

`Logic bombs` 是故意插入软件系统中的一段代码，当满足某些条件时会触发该功能。这些条件可能是特定的日期或时间，或者是用户的操作。逻辑炸弹通常被用于对系统造成破坏。

## 多态恶意软件

反病毒软件对恶意软件的检测主要通过使用特征码来实现。程序会扫描可执行文件中的代码段，作为标记，这些标记是能够实现检测的唯一代码模式。就像人体会产生与标记蛋白匹配的抗原一样，反病毒软件通过恶意软件代码中存在的唯一标记来检测恶意软件。

恶意软件编写者了解这一功能，并调整了方法来击败它。规避传感器的主要手段之一是使用 `polymorphic code`（多态代码），即定期更改的代码。这些更改或变异的设计目的不是影响代码的功能，而是为了掩盖任何特征以防止被检测。多态程序可以在每次使用后更改其编码，使得从检测的角度来看，每个复制品都是不同的。

## 加壳病毒

当发现新形式的恶意软件/病毒时，防病毒公司和安全研究人员会对程序进行反编译，尝试对其功能进行逆向工程。通过逆向工程可以确定很多信息，例如恶意软件来自哪里、如何工作、如何通信的、如何传播等。加壳恶意软件可以使确定这些信息的过程变得困难得多，甚至不可能。某些恶意软件（如 `Zeus`）以加密形式出现，以防止犯罪分子窃取他们所使用的恶意软件的知识产权。

## 攻击方法

尽管黑客和病毒在新闻中受到关注，但它们并不是攻击计算机系统和网络的唯一方法。本节介绍了每天计算机和网络遭受攻击的许多不同方式。每种类型的攻击都会威胁到三个安全要求之一：机密性、完整性和可用性（安全的 CIA 三要素）。

从高层角度来看，对计算机系统和网络的攻击可以分为大类：针对特定软件（如应用程序或操作系统）的攻击，以及针对特定协议或服务的攻击。针对特定应用程序或操作系统的攻击通常是因为代码中的（可能也包括测试中的）疏忽，或者是因为代码中的缺陷或漏洞（再次表明缺乏彻底测试）。针对特定协议或服务的攻击则是试图利用协议或服务的特定功能，或者以非预期的方式使用该协议或服务。本节将讨论安全专业人员需要注意的各种攻击形式。

### 中间人

正如名称所示，`man-in-the-middle attack`（中间人攻击）通常发生在攻击者能够将自己置于两个通信的主机之间的情况下。理想情况下（从攻击者的角度来看），通过确保所有发送到目标主机或从目标主机发出的通信都通过攻击者的主机来实现（如果攻击者能够攻破目标主机的路由器，就可以实现）。攻击者可以在转发流量之前观察所有流量，并实际上可以修改或阻塞流量。对于目标主机来说，通信似乎正常进行，因为收到了所有预期的回复。图 12-1 展示了这种攻击。

实例化中间人攻击的方法有很多。一种常见方法是通过 `session hijacking`（会话劫持），这可能发生在 `cookie` 等信息被盗取时，允许攻击者冒充合法会话。这种攻击可能是跨站脚本攻击的结果，该攻击欺骗用户执行代码导致 cookie 被盗取。如果通信是加密的，那么在中间人攻击中可以获得的信息将是有限的。尽管如此，仍然可以获得敏感信息，因为知道正在进行什么通信以及在哪些个人之间进行，在某些情况下实际上提供了非常有价值的信息。

#### 针对加密流量的中间人攻击

“中间人攻击”一词有时用于指一种更特定的攻击类型——即处理加密流量问题的攻击。在第 23 章中详细讨论的公钥加密需要两个密钥：你的公钥（任何人都可以用它来加密或“锁定”你的消息）以及你的私钥（只有你知道，并用于“解锁”或解密用你的公钥锁定的消息）。

如果你想和朋友 Bob 安全地通信，你可能会向他索要公钥，以便向他加密消息。反之，你也会向 Bob 提供你的公钥。攻击者可以通过拦截你向 Bob 索要公钥以及你发送公钥的过程来进行中间人攻击。攻击者会将你的公钥替换为她的公钥，并将其发送给 Bob。攻击者还会把她的公钥发送给你，而不是 Bob 的公钥。现在，当你或 Bob 加密消息时，它都将使用攻击者的公钥进行加密。攻击者现在可以拦截它、解密，然后使用适用于你或 Bob 的相应密钥重新加密并发送出去。你们双方都认为自己正在安全地传输，但实际上，你们的通信已经被破解了。设计良好的加密产品使用诸如双向认证等技术来避免这个问题。

### 拒绝服务

拒绝服务（DoS）攻击可以利用特定应用程序或操作系统的已知漏洞，也可以攻击特定协议或服务的特性（或弱点）。在 DoS 攻击中，攻击者试图阻止授权用户访问特定信息或访问计算机系统或网络。这可以通过崩溃系统（使其离线）或通过发送大量请求导致机器过载来实现。

DoS 攻击的目的可能只是阻止访问目标系统，也可以与其他操作结合，以获得对计算机或网络的未经授权访问。例如，`SYN flooding`（SYN 洪水）攻击可以用于临时阻止系统服务，以便利用该系统与另一个系统之间存在的信任关系。

SYN 洪水是 DoS 攻击的一个示例，它利用了 TCP/IP 网络的设计方式，并可以用来说明任何 DoS 攻击的基本原理。SYN 洪水使用建立两个间连接的 TCP 三次握手。在正常情况下，第一个系统向它想要通信的系统发送 `SYN` 数据包。如果第二个系统能够接受请求，它会响应 `SYN/ACK`。当初始系统接收到第二个系统的 `SYN/ACK` 时，它会响应一个 `ACK` 包，然后通信就可以进行。这一过程在图 12-2 中所示。

在 SYN 洪水攻击中，攻击者向目标系统发送伪造的通信请求。这些请求中的每一个都会得到目标系统的响应，目标系统会等待握手的第三部分。由于请求是伪造的（请求中使用了一个不存在的 IP 地址，因此目标系统正在响应一个不存在的系统），目标将等待永远不会等来的响应，如图 12-3 所示。目标系统会在特定的超时后丢弃这些连接，但如果攻击者发送请求的速度快于超时消除它们的速度，系统将很快被请求充满。系统能够支持的连接数是有限的，因此当进入的请求超过可处理的数量时，系统很快就会将其所有连接留给伪造请求。此时，任何进一步的请求将直接被丢弃（忽略），想要连接到目标系统的合法用户将无法连接，因为他们被拒绝使用该系统。

另一种简单的 DoS 攻击是臭名昭著的死亡之包（POD），它说明了另一种类型的攻击——针对特定应用程序或操作系统的攻击，而 SYN 洪水攻击是针对协议的。在 POD 攻击中，攻击者发送一个互联网控制消息协议（ICMP）ping 包，大小等于或超过 64KB（这意味着大于 64 × 1024 = 65,536 字节）。这种类型的数据包不应该自然产生（没有理由让一个 ping 包大于 64KB）。某些系统无法处理这种大小的数据包，会导致系统挂起或崩溃。

## 分布式拒绝服务

DoS 攻击使用单个攻击系统进行。使用多个攻击系统进行的 DoS 攻击被称为分布式拒绝服务（DDoS）攻击。DDoS 攻击的目标同样拒绝使用或访问特定的服务或系统。DDoS 攻击在 2000 年因对 eBay、CNN、Amazon 和 Yahoo! 的广受关注的攻击而闻名。

在 DDoS 攻击中，通过来自许多不同系统的流量淹没目标来拒绝服务。攻击者会创建一个攻击代理网络（有时称为 `zombies`，僵尸），在收到攻击者的攻击命令后，攻击代理开始向目标发送特定类型的流量。如果攻击网络足够大，即使是普通的网络流量也能迅速淹没最大的网站，例如 2014 年初的 400-Gbps CloudFlare 攻击。

创建一个 DDoS 网络并非易事。攻击代理不是自愿的——它们是已经被攻破并安装了 DDoS 攻击软件的系统。要攻破这些代理，攻击者必须获得对系统的未经授权的访问，或者欺骗授权用户运行安装了攻击软件的程序。攻击网络的创建实际上可能是一个多步骤，攻击者首先攻破几个系统，然后将它们用作 `handlers`（处理节点）或 `masters`（主节点），进而攻破其他系统。一旦网络建立，代理就会在发起攻击之前等待包含特定目标数据的攻击消息。DDoS 攻击的一个重要方面是，仅需向代理发送几条消息，攻击者就可以让向目标系统发送大量的消息。图 12-3DDoS 攻击的一个重要方面是，仅需向代理发送几条消息，攻击者就可以让向目标系统发送大量的消息。

如何停止或缓解 DDoS 攻击？一个重要的预防措施是确保修补了 `vulnerability`（漏洞）。许多当前的防病毒/间谍软件安全工具会检测已知的 `zombie` 类型感染。然而，这种方法的问题在于，它不是你防止攻击的方法——而是你对自己的网络采取的操作。你必须依靠网络管理员社区测试他们的系统，以防止针对你系统的攻击。

你应该考虑的另一个可以解决多种形式 DDoS 攻击的选项是在你的边界阻塞 `ICMP` 包。但在实施这种方法之前，请仔细考虑，因为它也会阻止可能实用的工具的使用。

### 重放

`replay attack`（重放攻击）发生在攻击者捕获双方之间通信的一部分并在稍后重新发送时。例如，攻击者可能会重放用于金融交易的系列命令和代码，导致交易执行多次。通常，重放攻击与尝试绕过身份验证机制有关，例如证书或票据的捕获和重用。

防止重放攻击的最佳方法是加密、加密认证和时间戳。如果证书或票据的一部分包含加密的时间戳，那么稍后重放它将是徒劳的，因为它将由于过期而被拒绝。

### 欺骗

`Spoofing`（欺骗）仅仅是让数据看起来像是来自不同的源。这在 `/IP` 中是可能的，因为协议背后的友好假设。在开发这些协议时，假设能够访问网络层的人员是可以信任的特权用户。

当数据包从一个系统发送到另一个系统时，它不仅包含目标 IP 地址和端口，还包含源 IP 地址。你本应该在源地址处填写自己的地址，但没有什么能阻止你填写另一个系统的地址。这是几种欺骗（spoofing）形式中的一种。

### 电子邮件欺骗

在电子邮件欺骗中，发送的消息的 `From`（发件）地址与发送系统的地址不同。使用几种不同的程序可以轻松实现这一点。为了演示伪造电子邮件地址有多简单，你可以 `Telnet` 连接到邮件服务器上的 `25` 端口（与电子邮件相关的端口）。从那里，你可以为消息的 `From`（发件）和 `To`（收件）部分填写任何地址，无论这些地址是否属于你，也无论它们是否真实存在。

你可以使用几种方法来判断一封邮件可能不是由其声称的来源发送的，但大多数用户并不会质疑自己的邮件，并接受它们看起来源自的地方。不过，电子邮件欺骗的一种变体（虽然在技术上不属于欺骗）是攻击者获取一个与他们想要伪造的 URL 类似的 URL，这样从他们系统发送的电子邮件看起来就像是来自官方网站——直到你仔细阅读地址为止。例如，如果攻击者想要伪造拥有 `[XYZ.com](http://www.XYZ.com)` 的 `XYZ Corporation`，攻击者可能会获得 URL `[XYZ.Corp.com](http://www.XYZ.Corp.com)` 的访问。接收来自伪造公司网站消息的人通常不会怀疑它是欺骗，而是认为它是官方的。同样的方法也可以、也已经被用于伪造网站。最著名的例子可能是 `[www.whitehouse.com](http://www.whitehouse.com)`。`[www.whitehouse.gov](http://www.whitehouse.gov)` 网站是白宫的官方网站。而 `[www.whitehouse.com](http://www.whitehouse.com)` URL 会带你进入色情网站。在这种情况下，可能没人会将该网站视为官方政府网站，而且它的目的也不是为了这样理解。然而，如果攻击者让他们伪造的网站看起来与官方网站相似，他们就可以说服许多潜在观众他们正处于官方网站。

### IP 地址欺骗

IP 的设计旨在让任何 IP 包的发送者在数据包的 `From` 部分包含自己的 IP 地址。虽然这是设计意图，但没有什么能阻止系统在数据包的 `From` 部分插入不同的地址。这被称为 `IP 地址欺骗`。IP 地址可能由于多种原因而被欺骗。

### Smurf 攻击

在一种名为 `Smurf` 攻击的特定 DoS 攻击中，攻击者向网络的广播地址发送伪造的数据包，该数据包会分发到该网络上的所有系统。在 Smurf 攻击中，攻击者发送到广播地址的数据包回显请求（echo request），其 `From` 地址经过伪造，使其看起来是另一个系统（目标系统）发出的回显请求。系统对回显请求的正常响应是回显回复（echo reply），它用于 `ping` 工具让用户知道远程系统是否可访问以及是否有响应。在 Smurf 攻击中，请求被发送到网络上的所有系统，因此所有系统都会向目标系统响应回显回复，如 `图 12-5` 所示。攻击者发送了一个数据包，就能产生多达 254 个针对目标的响应。如果攻击者发送多个此类伪造请求，或将其发送到几个不同的网络，目标可能会因为收到的回显回复数量而迅速瘫痪。

### 欺骗与信任关系

欺骗还可以利用两个系统之间的`信任关系`（trusted relationship）。如果两个系统被配置为接受对方完成的身份验证，那么登录到其中一个系统的个人可能不需要再次通过身份验证过程即可访问另一个系统。攻击者可以通过向一个系统发送一个看起来来自受信任系统的数据包来利用这种安排。由于信任关系的存在，目标系统可能会在不进行身份验证的情况下执行请求的任务。

由于一旦收到数据包通常会发送回复，因此被冒充的系统可能会干扰攻击，因为它将收到一个它从未发送过的请求的确认。攻击者通常会先发起 DoS 攻击（例如 `SYN 泛滥攻击`），在攻击者利用信任关系期间临时禁用被伪造系统。一旦攻击完成，对伪造系统的 DoS 攻击就会终止，管理员除了发现一个暂时无响应的系统外，可能永远不会察觉到攻击的发生。`图 12-6` 展示了一个包含 `SYN 泛滥攻击`的欺骗攻击。

## 欺骗与序列号

欺骗的复杂程度很大程度上取决于几个因素，包括流量是否加密以及攻击者相对于目标的位置。例如，从网络内部进行欺骗攻击比从网络外部进行要容易得多，因为内部攻击者可以观察进和目标的流量，并能更好地构造必要的数据包。

对于外部攻击者来说，构造数据包更为复杂，因为序列号与 `TCP` 数据包相关。序列号是由发送主机建立的 32 位数字，每发送一个包都会递增。包并不保证按顺序接收，序列号可以帮助在接收时对包进行排序，并引用传输过程中可能丢失的数据包。

在 TCP 三次握手中，会创建两组序列号，如 `图 12-7` 所示。第一个系统为原始 `SYN` 数据包选择一个序列号。接收此 `SYN` 数据包的系统通过 `SYN/ACK` 进行确认。它回传一个确认号，该号基于第一个序列号加一（即它将收到的序列号加一）。然后它还创建了自己的序列号并随之发送。原始系统接收到带有新序列号的 `SYN/ACK`。它将序列号加一，并将其作为响应的 `ACK` 数据包中的确认号。

从网络内部和外部尝试欺骗攻击的难度差异在于对序列号的确定。如果攻击者位于网络内部，并且可以观察到目标主机做出响应的流量，那么攻击者就能轻松地看到系统生成的序列号，并使用正确的序列号进行响应。如果攻击者位于网络外部，且没有观察目标系统生成的序列号，攻击者几乎不可能提供正确序列号的最终 ACK。因此，攻击者必须猜测序列号可能是什么。

序列号在某种程度上是可以预测的。每个会话的序列号并非从同一个数字开始，因此来自不同并发连接的不同数据包不会具有相同的序列号。相反，每个新连接的序列号会增加一个很大的数字，以保持数字不相同。序列号可能每秒（或或其他时间段）增加一个很大的数字。外部攻击者必须确定用于这些增量的取值是什么。攻击者可以通过在不同的时间间隔上尝试连接，观察序列号是如何增加的来实现这一点。一旦确定了模式，攻击者就可以尝试建立合法连接以确定当前值，然后立即尝试欺骗连接。欺骗连接的序列号应该是合法连接加上已确定的值或多个值。

序列号在会话劫持中也非常重要，该内容在本章的“TCP/IP 劫持”部分进行了讨论。

### 垃圾邮件 (Spam)

尽管通常不被认为是社会工程学问题，也不是安全问题，但垃圾邮件确实可能成为安全隐患。正如大家所知的，`spam` 是大量未经请求的电子邮件。它在某种意义上可能是法的，因为它是由广告产品或服务的公司发送的，但它可能是恶意的，可能包含旨在破坏你系统的恶意软件附件，或者指向可能尝试从你处获取个人信息的恶意网站链接。
