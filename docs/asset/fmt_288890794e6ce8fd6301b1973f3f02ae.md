
## 第二种场景中的模块执行时间

第二种场景中的模块执行时间可以通过公式 (`16.12`) 估算，其中 `M` 表示实例分割网络中的所有模块。数据传输时间也可以通过公式 (`16.10`) 估算，其中 `d` 表示传感器生成的原始图像或视频数据。因此，总时间开销可以表示为公式 (`16.13`)：

```
(16.12)

$$t_{exec} = \sum\limits_{m \in M}t_{c}(m)$$
```

```
(16.13)

$$t_{total} = \sum\limits_{m \in M}t_{c}(m) + t(d,R2,CB)$$
```

## 最终场景中的总时间成本

在最终场景中，移动机器人执行整个实例分割网络，总时间成本为公式 (`16.14`)：

```
(16.14)

$$t_{total} = \sum\limits_{m \in M}t_{r}(m)$$
```

## 16.4.2.2.3 能耗模型

由于移动机器人的电池容量有限，且能耗对机器人的待机时间影响显著，本文仅考虑移动机器人的能耗。相比之下，云系统拥有恒定的电源，可无论特定进程消耗多少能量都能持续运行。在实例分割网络执行期间，数据传输能耗 `E_trans` 和模块执行能耗 `E_exec` 如公式 (`16.15`) 所示，共同构成移动机器人的能耗。

```
(16.15)

$$E_{robot} = E_{exec} + E_{trans}$$
```

第 16.4.2.2.2 节中描述的三种情况也被考虑在内。第一种场景的能耗可通过公式 (`16.16`) 估算，其中 `C(m)` 表示机器人执行模块 `m` 时的电池消耗，`C(d)` 表示机器人向云传输数据 `d` 时的电池消耗。电池使用量以 `mAh` 计量，1 mAh = 0.001A × 3600 s，即 3.6 A。第二种场景仅因数据传输产生能耗，可通过公式 (`16.17`) 计算。第三种场景中，所有模块均在移动机器人上运行，不使用云资源，因此 `E_trans = 0`。于是能耗可通过公式 (`16.18`) 估算：

```
(16.16)

$$E_{robot} = \sum\limits_{m \in M_{R}}3.6 \ast (C(m) \ast U + C(d) \ast U)$$
```

```
(16.17)

$$E_{robot} = 3.6 \times C(d) \times U$$
```

```
(16.18)

$$E_{robot} = \sum\limits_{m \in M}3.6 \ast C(m) \ast U$$
```

主要待解决的问题是如何将实例分割网络的计算卸载到云端，以借助云实现移动机器人上的实时实例分割。基于上述公式，卸载问题可简化为在有向无环图（DAG）中选择哪些节点在移动机器上执行、哪些节点在云平台上执行，以最小化整个实例分割的时间和能耗成本，如公式 (`16.19`) 所示：

```
(16.19)

$$\min\limits_{M_{R},M_{C}}\alpha t_{total} + \beta E_{robot}.$$
```

# 16.5 基于边缘计算的 AIoT

边缘计算技术是最重要的计算技术之一，旨在网络边缘靠近工业现场处理和分析工业数据，以满足实际应用的要求，包括实时性能、低设备能耗和数据安全 [18, 19, 20]。边缘计算技术改变了传统制造的范式。在最近几十年中，国内外工业界开发了各种边缘计算架构和模型。

2014 年，欧洲 ETSI 成立了移动边缘计算标准化工作组（MEC）。2015 年，OpenFog 计算联盟（OFC）对 OpenFog 架构和计算模型进行了研究。国内边缘计算产业联盟和工业互联网产业联盟联合发布了白皮书“边缘计算参考架构 3.0”以及 20 多个边缘计算测试床。在标准制定方面，2020 年，由中国联通等在 ITU-T SG20 推动的国际标准“边缘计算需求和能力要求”（ITU-T Y.4208）正式发布。同时，“边缘计算网关”国际标准也在稳步推进。2016 年 10 月，IEEE/ACM 边缘计算研讨会由 IEEE 和 ACM 正式设立。边缘计算网关形成了一个由学术界、工业界和政府（美国国家基金会）共同认可的学术论坛。2017 年，中国科学院沈阳自动化研究所牵头成立了中国自动化学会边缘计算专业委员会。在微软 2018 年年度开发者大会上，微软发布了“Azure IoT Edge”等边缘产品，将其业务重心从 Windows 操作系统转移到智能边缘计算。同时，亚马逊发布了其“AWS Greengrass”边缘侧软件，可无缝将 AWS 云服务扩展到设备。阿里云宣布 2018 年将在边缘计算技术领域进行战略投资并推出边缘计算产品 Link Edge。

边缘计算的优势包括以下三个方面：

1.  边缘侧网关为现场设备提供多种接口和协议，可解决现场设备间的网络连接和通信问题，并集成汇聚来自不同设备和传感器的大量数据。
2.  业务数据可上传至云端，也可在边缘服务器实时处理，显著降低数据传输时延和网络带宽消耗，并保障数据安全。
3.  边缘计算基于智能分布式架构和平台。系统运维人员、决策者和开发者可通过边缘计算系统相互协作。

## 16.5.1 工业视觉

工业视觉用于控制和监控生产流程，包括自动检测、工件加工和装配自动化，如图 16.10 所示。工业视觉主要取代人工检测，降低企业的人工成本，提高检测效率和精度。具体而言，生产线的 4K、8K 等高清摄像机采集大量图像信息，这些信息必须进行处理和分析以支持实时反馈控制。在工业场景中，这些图像数据通常需要 5–150 Mbps/300 Mbps 的大带宽用于成像数据回传，以及 20–50 ms 的低延迟用于 PLC 控制反馈。因此，5G+ 边缘计算可作为工业视觉的有希望解决方案。图像信息通过 5G 的高上行带宽传输，满足工业视觉对大带宽的需求。在边缘计算平台上部署机器视觉 AI 算法，可实现生产线的实时智能检测。此外，还需与云端合作进行大数据存储和 AI 算法训练。

## 16.5.5 UAV 检查

UAV 检查广泛用于智能物流、智能公园、设备检查等领域，用于保障人员、财产、公共安全和防火安全，如图 16.14 所示。UAV 将摄像机视频（可见高清、红外等）实时传输到工厂综合控制中心。通过对视频的智能分析（如目标识别和模式识别），控制中心可判断检查地点是否存在安全异常或火灾警报，并实现智能警报，以最大程度降低安全人员的日常工作强度。遗憾的是，大多数前端设备仅具备感知和简单处理能力，无法进行密集的智能分析计算。数据必须传输到数据中心进行处理。视频分析和处理服务部署在靠近感知设备的 MEC 平台上。UAV 摄像机采集的数据通过 5G 基站传输到 MEC 平台进行本地分析和预处理，这可以降低核心网络和骨干网络的带宽占用，并缩短总延迟。AI 训练服务部署在云端数据中心，依赖云计算的强大计算能力训练数据并获得更精确的模型。5G 上行速率可达 200 Mbps，能够支持 4K、8K 甚至全景视频传输。5G 毫秒级的低延迟和高可靠性可有效保障 UAV 的精确控制和定位。
