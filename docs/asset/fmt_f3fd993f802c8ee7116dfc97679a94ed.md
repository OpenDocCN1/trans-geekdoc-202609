
2011 年，人们发现 `PIN` 方法最快可以在几小时内被暴力破解。一旦 `PIN` 被破解，就可以发现 WPA/WPA2 预共享密钥。由于 WPS 默认在大量设备上出厂，因此在设置期间，禁用此功能非常重要。

## 应用程序攻击

针对系统的攻击可能发生在网络层、操作系统层、应用层或用户层（社会工程学）。早期的攻击模式针对网络，但今天大多数攻击都指向应用程序，这主要是因为大多数攻击的目标就在那里；正如臭名昭著的匪威利·萨顿那句名言所说：“因为那里有钱。”事实上，今天许多针对系统的攻击结合了网络、操作系统和应用程序中的漏洞，所有这些手段都是为了获取攻击的预期目标，该目标通常是某种形式的数据。

应用层攻击利用了与计算机应用程序相关的几个事实。首先，大多数应用程序是由一群程序员编写的大型程序，其本质决定它们在设计和编码上存在错误，从而产生漏洞。典型漏洞的列表请参阅 MITRE 维护的常见漏洞与披露（`CVE`）列表，`http://cve.mitre.org`。其次，即使软件供应商发现并修复了漏洞，终端用户应用补丁的速度也很缓慢，2003 年 1 月份的 `SQL Slammer` 事件就证明了这一点。被利用的漏洞是缓冲区溢出，供应商在爆发前六个月就已提供了补丁，但由于大量未打补的系统，蠕虫仍然迅速传播。

### 跨站脚本 (XSS)

跨站脚本缩写为 `XSS`，以区分于层叠样式表（`CSS`）。跨站脚本攻击是一种代码注入攻击，攻击者响应输入请求发送代码。这些代码随后由 Web 服务器渲染，导致代码被 Web 服务器执行。跨站脚本攻击利用了基于 Web 的系统的几个常见元素。首先是未能进行完全的输入验证。`XSS` 在响应输入请求时发送脚本，即使脚本不是预期的。

### SQL 注入

SQL 注入攻击是一种针对任何基于结构化查询语言（`SQL`）数据库的注入形式，无论供应商为何。这种攻击的主要方法目的是将 `where` 子句更改为提供错误答案的子句。假设目标 SQL 语句是

```
select count(*) from users_table where username = 'JDoe' and password = 'newpass'
```

值 `JDoe` 和 `newpass` 由用户提供并简单地插入到字符串中。虽然在功能上看似安全，但通过使用序列

```
' or 1=1 --
```

很容易被破坏，因为添加了 `or` 子句、配合始终为真的语句以及注释行的开头（用于阻止末尾的单引号），会将 SQL 语句更改为 `where` 子句失效的状态。这会返回所有记录：

```
' or 1=1 --
```

### LDAP 注入

基于 LDAP 的系统也会受到注入攻击。当应用程序根据用户输入构建 LDAP 请求时，未能验证输入会导致不良的 LDAP 请求。正如 SQL 注入可以用于在数据库中执行任意命令，LDAP 注入可以在目录系统中执行的操作。搜索框中一个简单的通配符（`*`）就能返回通常超出查询范围的结果。

### XML 注入

XML 也可以通过注入进行篡改。XML 注入可用于操纵基于 XML 的系统。由于 XML 在 Web 应用世界几乎无处不在，这种形式的攻击具有广泛的目标。

目录遍历攻击（Directory traversal attack）是指攻击者利用特殊输入来绕过文件系统的目录树结构。在未验证的输入框中添加 `../..` 的编码符号，可能会导致解析器将编码解析为遍历代码，从而绕过许多检测元素，并将输入传递给文件系统，导致程序在与设计不同的位置执行命令。当它与命令注入（command injection）结合时，输入可能导致未经授权的执行执行。此类问题被归类为输入验证错误，如果不进行代码走读并针对性地查找，将很难检测。这说明了在代码审查中使用“前 25 种编程错误清单”的用处，因为它可以在开发期间提醒开发人员此类问题。

目录遍历可以通过对输入流进行编码来掩盖。如果安全检查在系统解析器解码字符串之前完成，那么对攻击形式的识别可能会受到影响。表示特定输入形式有许多方法，最简单的被称为“规范形式”（`canonical form`）。解析器被用于为操作系统渲染规范形式，但这些嵌入式解析器可能会在输入验证之后运行，使得仅通过字符串匹配更难检测某些攻击。

### 缓冲区溢出 (Buffer Overflow)

攻击者经常利用的一个常见弱点是缓冲区溢出。当程序提供的输入数据量超过其设计处理的能力时，就会发生 `buffer overflow`（缓冲区溢出）。例如，如果一个要求输入 7 到 10 个字符电话号码的程序接收到了 150 个字符的字符串，会发生什么？许多程序会提供一些错误检查以确保这不会引起问题。然而，某些程序无法处理此错误，额外的字符将继续填充内存，覆盖程序的其他部分。这可能导致许多问题，包括导致程序终止或系统崩溃。在某些情况下，程序可以执行攻击者提供的命令。缓冲区溢出通常会继承被利用程序所享有的权限级别。这就是为什么使用 root 级访问权限的程序在受到缓冲区溢出攻击时如此危险，因为将执行的代码是在 root 级权限下运行的。

事实证明，缓冲区溢出在各种程序中都可以被利用，从 UNIX 到 Windows，再到 Internet Explorer、Firefox (Mozilla) 等许多应用程序。从历史来看，按类型划分，超过 50% 的安全事件是由于缓冲区溢出攻击引起的。它是最常用的黑客手段之一，用户主要的防御措施是让机器保持软件制造商提供的补丁更新。遗憾的是，补丁并未证明是一种非常有效的保护方法。许多人没有更新补丁，正如 Slammer 蠕虫攻击所示的那样，该攻击发生在微软发布针对该漏洞的特定补丁近六个月之后。即使补丁已通过热修复和服务程序包的形式广泛可用，许多 SQL 服务器仍未收到补丁，并受到了这种利用缓冲区溢出传播的蠕虫的影响。

![image](img/examtip.jpg)

**考试提示 (EXAM TIP)** 缓冲区溢出可能发生在任何代码中，而带有特权运行的代码具有更大的风险。2014 年，OpenSSL 库中一个名为 Heartbleed 的缓冲区溢出导致数十万系统处于易受状态，并暴露了全球数千万到数亿用户的关键数据。

缓冲区溢出是输入验证攻击，旨在利用那些不验证输入长度的输入例程。惊讶的是，解决这个问题非常简单，只需要在写入内存之前验证所有输入长度即可。这可以通过多种方式实现，包括对输入使用安全的库函数。这是已被证明可以解决的漏洞之一，事实上，在在关注安全的安全的软件公司中，这种漏洞的流行程度正在大幅下降。

### 整数溢出 (Integer Overflow)

`integer overflow`（整数溢出）是一种编程错误状态，当程序尝试将一个数值（整数）存储在无法容纳它的变量中时，就会发生。结果因语言和数值类型而异。在某些情况下，该值会饱和变量，假设定义类型的最大值。在其他情况下，特别是对于符号整数，它可能会溢变为负值，因为最高位通常预留给符号。这可能会导致程序出现严重的逻辑错误。

整数溢出很容易测试，静态代码分析器可以指出它们可能发生的地方。鉴于此，生产代码中不允许这些错误。

### 零日漏洞 (Zero-day)

`zero-day`（零日）是一个术语，用于定义新发现尚未修复的漏洞。大多数漏洞在研究人员或开发人员发现之前处于未知状态。如果研究人员或开发人员发现了漏洞但不共享信息，该漏洞可以在主机无法修复的情况下被利用，因为除了发现者之外，该问题是未知的。从发现到修复或补丁发布，该漏洞被称为零日，意味着它尚未被处理。零日漏洞最令人担忧的是未知因素——其能力的影响是未知的。

### Cookie 与附件 (Cookies and Attachments)

`Cookies` 是在 HTTP 流中传递的小型 ASCII 文本，用于在网络浏览器中临时存储数据。Netscape 发明的 Cookie 在 Web 服务器和浏览器之间传递，作为在无状态世界中维护状态的机制。`状态` 是描述依赖之前操作的术语。根据定义，Web 服务器提供的 HTTP 流量是 `stateless`（无状态的）——每个请求都与之前的请求完全独立，服务器没有之前请求的记忆。这极大简化了 Web 服务器的功能，但也使提供超出基本功能的功能变得异常复杂。Cookie 的出现是为了弥补这一空白。Cookie 通过 HTTP 消息头部部分的 Set-Cookie 消息传递。

Cookie 实际上是浏览器实例期间存储在内存中的系列键值对。Cookie 规范为特定用途建立了几种特定的键值对。开发人员可以根据定义额外的键值对。

- **Path**：此键值对将 cookie 的适用范围进一步解析为域名内的特定路径。如果 `path = /directory`，则 cookie 仅会在针对给定域名内 `/directory` 路径的请求时发送。这允许对浏览器和服务器之间传递的信息进行细粒度的控制，并限制了不必要的数据交换。

- **Secure**：cookie 中存在 `[secure]` 关键字表示 cookie 仅在通过 SSL/TLS 会话连接时使用。这并不表示任何其他形式的安全性，因为 cookie 是以明文形式存储在客户端机器上的。事实上，一种基于浏览器的安全问题是能够从浏览器缓存中读取另一个网站的 cookie 并使用脚本确定其值。

在浏览器上的 cookie 管理通常是一个不可见的过程，但大多数浏览器都提供了让用户在客户端检查和操作 cookie 的方法。Chrome 用户可以通过图 14-1 所示的界面检查、删除和阻止单个 cookie。

那么 cookie 有什么用呢？在浏览器中禁用 cookie 并访问你经常的一些常用网站，你就能很快学会 cookie 的用处。cookie 存储了各种信息，从客户 ID 到以前访问过的网站数据等。由于 cookie 以允许进行简单操作的形式存储在用户的机器上，因此必须始终被视为可疑的，且不适合作为安全机制。然而，它们可以允许浏览器向 Web 服务器提供关键信息。广告商可以使用它们根据你以前看过的广告来控制向你展示哪些广告，无论广告在网站的位置如何。特定网站可以使用 cookie 在页面之间传递状态信息，从而实现用户所需级别的功能。cookie 还可以记住你在天气网站的邮政编码、你在股票跟踪网站的 ID、你购物购物车中的物品——这些都是典型的 cookie 用法。最后分析认为，cookie 是日常 Web 体验的一部分，它们将一直存在，只要不被误用（例如用于存储安全数据以及提供 ID 和身份验证），它们就是有用的。

#### 禁用 Cookie

如果用户在浏览器中禁用了 cookie，那么 Web 服务器将无法使用此类信息。IETF RFC 2109 描述了 HTTP 状态管理系统（cookie），并规定了必须在浏览器中启用的若干 cookie 功能，具体包括：

- 开启和关闭 cookie 使用的能力

- 关于 cookie 是否正在使用的指示器

- 指定 cookie 域值和生命周期的方法

这些功能中的几个已经讨论过了，但要实现无 cookie 浏览并不需要一个简单的步骤。告诉浏览器停止接受 cookie 是通过“选项”菜单提供的提供的设置选项，但它对已经接收并存储在系统中的 cookie 没有影响。为了防止浏览器发送已接收的 cookie，用户必须从系统中删除这些 cookie。这种批量操作很容易完成，然后浏览器就可以在无 cookie 的情况下运行。若干第三方工具可以实现更细粒度的 cookie 控制。

#### 附件

附件也可以用作攻击向量。例如，如果用户输入图形文件（例如 JPEG 文件），并且该文件被修改为包含如 Java 等可执行代码，那么当图像渲染时，代码就会执行。这可以启用某些功能。

#### 本地共享对象

本地共享对象（LSOs）是存储在用户机器上以保存信息的数据段。通常，这些是 Flash 使用的 cookie，因为这些可以在应用程序之外进行操纵，所以它们可能构成安全或隐私威胁。

#### 恶意插件

插件是分发以允许现有程序提供附加功能的代码。这些插件的一个例子是浏览器辅助对象（BHOs），它们随 Internet Explorer 加载。BHO 对 Internet Explorer 事件模型有无限制的访问，并可以执行如捕获击键等的操作。你应该只使用来自信任源的插件，并且你需要理解它们可能带来的交互级别。ActiveX 是微软实现的一项技术，通过添加用户控件来增强支持 Web 的系统。除非经过信任机构的签名，否则不应允许浏览器运行 ActiveX 内容。

#### 会话劫持

在 Web 上进行通信时，通常会创建一个会话来控制通信流。可以使用多种方法（包括 SSL/TLS 和 cookie）建立并控制会话。安全地实现会话的建立和销毁非常重要，因为如果一方结束通信而没有正确销通信会话，入侵者就可以接管该会话，在一方离开后继续操作并冒充该方。如果你登录银行进行交易，但允许会话劫持者进入，那么劫持者就可以在你离开后使用你的账户继续操作。这就是为什么从银行和财务网站注销而不是仅仅关闭浏览器是非常重要的原因之一。

会话劫持的方法有很多，从中间人攻击到侧持攻击（sidejacking）和浏览器接管。侧持攻击是指使用数据包嗅探来窃会话 cookie。仅保护登录过程然后切换回标准 HTTP 就会启用这种攻击方法。

最好的防御是正确使用加密（不使用 SSL 2.0 或之前的版本），并在完成后注销并关闭应用程序。在使用多标签页浏览器时，最好关闭整个浏览器实例，而不仅仅是标签页。

### 客户端攻击

Web 浏览器已成为用户访问网络资源的主要应用程序。该界面的流行性和实用使得 Web 浏览器成为攻击者获取访问权限和控制系统的主要目标。多种攻击可以通过浏览器发生，通常是由于在使用输入之前未对其进行适当验证。

当用户输入在未经过验证的情况下被使用时，为攻击者提供了一个机会，通过构造输入，在应用程序解析和使用输入时触发特定的事件。`SQL injection` 攻击涉及对输入的操纵，导致产生与设计者意图不符的 `SQL statement`。`XML` 和 `LDAP injections` 是以相同的方式实施的。由于 `SQL`、`XML` 和 `LDAP` 被用于存储数据，这可能允许攻击者访问违反业务规则的数据。当输入以一种允许命令行操纵的方式使用时，就会发生 `Command injection` 攻击。这可以让攻击者以应用程序的权限级别获得命令行访问权限。

## 头部操控

当通过用户输入动态生成 HTTP 时，未验证的输入可能给攻击者更改 HTTP 元素的机会。当用户提供的信息被用于标头时，可能会创建多种攻击，包括缓存污染、跨站脚本、跨用户篡改、页面劫持、cookie 操纵或开放重定向。

![image](img/examtip.jpg)

**考试提示** 针对客户端机器可以使用多种攻击向量，包括缓存污染、跨站脚本、跨用户篡改、页面劫持、cookie 操纵和开放重定向。考试中应掌握所有攻击类型。

### 任意/远程代码执行

在获取用户输入并将其用于创建在系统中执行的命令时涉及的风险之一是任意或远程代码执行。这种攻击涉及攻击者准备一个输入来改变程序的格式或功能。作为 `command injection` 的形式，这种攻击允许用户在系统上插入并远程执行任意代码。这是一种输入验证失败的形式，因为用户不应具有在定义之外与操作系统交互的能力。
