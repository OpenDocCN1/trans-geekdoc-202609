
该协议使用起来相当简单。它规定了 27 个基本功能码，可用于主设备和从设备之间的数据交换。有些用于从远程设备获取数据，而其他的则用于配置远程设备的设置。有一个代码保留供远程设备使用，当其操作中发生告警条件时通知主站。TCP 端口 `2000` 用于促进网络中 DNP3 设备之间的通信。

DNP3 通常用于在公用事业变电站内提供串行连接，以及变电站与位于远程控制中心的 SCADA 主站之间的连接。在变电站内，DNP3 运行在 RS-232/485 串行连接或 TCP/IP 以太网网络上。远距离链路通过使用调制解调器和电话线，或使用前文所述的其他远距离通信技术来实现。

DNP3 的设计初衷是优化 OT 数据和命令从一台设备到另一台设备的传输。这使得 DNP3 容易受到各类传统网络攻击，包括中间人攻击和欺骗攻击。后续的发展为该协议增加了认证功能，以增强 SCADA 安全性。这些功能包括将 DNP3 协议封装在 SSL/TLS 和 IPSec 协议封装器中。

#### ICCP

*控制中心间通信协议*（*ICCP*）已被全球各地的公用事业单位采用，用于 SCADA 主站服务器、公用事业控制中心以及跨广域网的公用事业之间的实时数据通信。在美国，该协议用于互联公用事业集团，以改善区域电网参与者之间的生产和分配协调。

ICCP 是一个主要运行在 TCP/IP 以太网上的客户端-服务器网络系统。然而，它不提供固有的认证或加密保护，因此必须通过替代方式提供这些功能。

#### OPC

*开放平台通信*（*OPC*）协议标准是一种广泛接受的工业客户端-服务器规范，旨在促进工业控制应用与智能控制设备之间的数据交换。OPC 最初旨在将 Microsoft/Windows 产品引入工业控制领域。然而，随着时间的推移，OPC 标准已演进为也可用于非 Microsoft 平台。

开发该协议的目的是创建一个通用结构，SCADA 硬件和软件制造商可据此进行设计。这提高了硬件服务器和 SCADA 软件包（服务器和客户端）的互操作性。

#### BACnet

*楼宇自动化与控制网络*（*BACnet*）协议由美国采暖、制冷与空调工程师学会开发，用于将楼宇自动化设备联网。一些 BACnet 网络基于 IP（BACnet/IP），而其他的则是 RS-485、主/从令牌传递（BACnet MS/TP）系统。

符合 BACnet 标准的设备通过这些网络相互通信。典型的 BACnet 设备包括用于暖通空调控制系统、火灾探测系统、照明系统和门禁控制系统的设备。BACnet 还采用许多符合 BACnet 标准的网络连接设备，如 BAS 路由器、网关和控制器。TCP 端口 `47808` 用于支持 BACnet/IP 设备之间的 TCP/IP 连接。

BACnet 已被证明存在设计漏洞，使其面临多种不同类型的网络安全攻击——这与大多数 OT 网络协议的情况一样。一项评估列出了 19 种不同的 BACnet 服务和 5 项 BACnet 功能，它们均易受不同类型的网络安全攻击。

### 企业网络协议

由于组织将其 IT 网络建立在以太网技术和*传输控制协议/互联网协议*（*TCP/IP*）协议套件之上，OT 网络工程师和管理员自然也必须处理这些技术。本章剩余部分将详细讨论这些技术。

#### TCP/IP

美国国防部最初开发 TCP/IP 协议作为跨网络传输数据的协议。它被认为是最安全的网络协议之一。由于 TCP/IP 由美国政府开发，无人实际拥有其所有权，因此它被采纳为互联网的传输标准。凭借连接多种类型计算机和服务器的能力，TCP/IP 被用于绝大多数网络，是所有当前系统的首选网络协议。

无论使用何种类型的计算设备或软件，信息都必须以 TCP/IP 数据包的形式跨网络移动。该协议要求将数据分组捆绑在一起，称为*网络数据包*。TCP/IP 数据包的设计主要是为了允许消息分片和重组。它由两个首部字段（IP 首部和 TCP 首部）以及随后的数据字段组成，如图 2.34 所示。

![图 2.34 TCP/IP 数据包](img/c02f034.png)

**图 2.34** TCP/IP 数据包

TCP/IP 协议被互联网社区广泛接受，几乎每种计算机操作系统都支持它，包括 Apple、Android、Windows、UNIX、Linux，甚至网络打印机。它也可用于任何拓扑结构。因此，所有这些计算机类型都可以使用 TCP/IP 协议跨网络交换数据。

随着时间的推移，TCP/IP 协议已扩展为包含许多选项，网络技术人员和管理员必须理解这些选项，以确保 TCP/IP 系统的正确配置和运行。首先，TCP/IP 协议不是单一协议；它实际上是一套协议，最初由国防部于 1969 年开发。TCP/IP 由两个主要部分组成：传输控制协议 (TCP) 和互联网协议 (IP)。这些协议与许多其他协议协同工作，形成一种称为*协议栈*的结构。

如前所述，网络协议最重要的功能是确保信息到达其预定的网络位置。归根结底，这是 TCP/IP 协议的真正功能。它通过将信息数据包路由到 IP 地址指定的位置来实现这一点。在前一张图中，你应该注意到 TCP/IP 首部包含两个地址：消息来源的源地址和发送目标的目的地址，如图 2.35 所示。

![图 2.35 TCP/IP 路由](img/c02f035.png)

**图 2.35** TCP/IP 路由

因为人类不善于记忆数字串，计算机通常由名称标识。为了让信息到达人类期望的地址，必须在计算机理解的数字 IP 地址和我们赋予的字母数字名称之间进行某种解析。为此，TCP/IP 依赖一组协议和服务，它们代表特殊的高级名称和地址解析功能。

这些协议和服务包括以下内容：

*   *域名系统 (DNS) 服务*：一种配合分层 DNS 命名系统工作的服务，可将可读的域名转换为用于定位连接到网络的计算设备的数字 IP 地址
*   *动态主机配置协议 (DHCP)*：一种由 ISP 和其他网络使用的协议，用于从可用地址的旋转池中自动向用户分配 IP 地址

## 地址解析协议 (ARP)

**地址解析协议 (ARP)**：该协议/工具用于将 IP 地址转换为 MAC 地址。网络设备使用称为 ARP 缓存的表来存储它们已通信过的其他网络设备的 ARP 信息（IP 和 MAC 地址）。

由于互联网基本上是一个巨大的 TCP/IP 网络，其中连接到它的任意两台计算机不能拥有相同的地址，因此连接到互联网的网络必须遵循由 **互联网服务提供商 (ISP)** 分配的特定 IP 寻址方案。然而，只要您的网络未连接到互联网，就可以使用任何 IP 寻址方案。这称为 **专用网络**。

配置专用网络时，您必须设计一个在整个网络中使用的 IP 寻址方案。虽然从技术上讲，您可以在专用网络中使用任何您想要的 IP 寻址方案而无需咨询 ISP，但每个 IP 类别中都保留了特殊的网络地址范围供专用网络使用。这些是未在互联网上注册给任何人的保留地址。

如果您正在配置专用网络，应使用以下地址选项之一，而不是创建随机的寻址方案。网络上的客户端总数通常决定了您应使用哪种 IP 寻址类别。可以使用以下专用网络 IP 地址列表：

*   **IP 地址为 `10.0.0.0`，子网掩码为 `255.0.0.0`**：此 A 类范围提供超过 1600 万个专用 IP 地址。
*   **IP 地址为 `169.254.0.0`，子网掩码为 `255.255.255.0`（Microsoft AIPA 默认值）**：此 C 类范围提供 254 个专用 IP 地址。
*   **IP 地址为 `172.(16-32).0.0`，子网掩码为 `255.240.0.0`**：此 B 类范围提供 65,000 个专用 IP 地址。
*   **IP 地址为 `192.168.0.0`，子网掩码为 `255.255.0.0`**：此 C 类范围提供 254 个专用 IP 地址。

此外，请记住，在建立专用 IP 寻址方案时，所有主机必须具有相同的网络 ID 和子网掩码，并且网络上的任意两台计算机不能具有相同的 IP 地址。

## 域名系统

要在 TCP/IP 网络中与另一台计算机通信，您的计算机必须拥有目标主机的 IP 地址。作为用户，我们在建立连接时通常指定计算机的名称，例如 Marcraft，而不是 IP 地址。这些名称需要转换为目标计算机的 IP 地址。将计算机名称与 IP 地址匹配的过程称为 **名称解析**。**域名系统 (DNS)** 可用于为任何 TCP/IP 客户端执行名称解析。

DNS 是在网络中一台或多台服务器上运行的服务。这些服务器拥有数据库，用于为网络执行 DNS 名称到 IP 地址的解析功能。如果您的网络使用 DNS 进行名称解析，则必须为所有客户端配置一台或多台 DNS 服务器的 IP 地址。DNS 也是互联网使用的名称解析服务。

### DNS 名称解析

每个域都必须有一台 **DNS 名称服务器**，负责将其客户端注册到网络的下一级更高层级。提供域名服务的任何计算机在技术上称为 **DNS 服务器**。在较大的 IT 网络中，DNS 服务器通常位于公司的数据中心。对于较小的企业和住宅网络，DNS 服务器由其互联网服务提供商作为其服务套餐的一部分提供。

所有 **DNS 服务器** 都维护一个 **DNS 数据库**，列出了它们负责的名称到 IP 地址的映射。当 **DNS 客户端** 向本地 DNS 服务器提交名称解析请求时，服务器将搜索其 DNS 数据库，并在必要时搜索分层 DNS 系统，直到找到提交给它的主机名或 **完全限定域名 (FQDN)**。此时，它会解析所请求主机名的 IP 地址并将其返回给客户端。

如图 2.36 所示，简化的 DNS 过程如下：

1.  当您在 Web 浏览器中输入网页地址时，客户端会向特定的计算机名称（例如 `www.marcraft.com`）发出查询（访问请求）。
2.  本地 DNS 服务器（分配给客户端计算机的 DNS 服务器）检查其内存缓存中是否有该域名。
3.  如果本地 DNS 服务器无法回答查询，通常会将查询转发到根 DNS 服务器以寻找匹配项（所有功能正常的 DNS 服务器，包括本地 DNS 服务器，都包含所有根 DNS 服务器 IP 地址的静态列表）。
4.  根服务器会将本地 DNS 服务器引荐给一组主要的 .com（域）服务器。反过来，本地 DNS 服务器将从列表中选择一台 .com 服务器并查询 `marcraft.com` 的地址。作为响应，.com 域 DNS 服务器会将您引荐给一组子域服务器（如果存在——`Example1.com` 和 `Example2.com`）。然后本地 DNS 服务器将向 `marcraft.com` 子域 DNS 服务器（或其中之一）查询 `marcraft.com` 的地址。
5.  根据 `marcraft.com` 子域的结构，所选的 `marcraft.com` 服务器可能会将您引荐给一组用于 `marcraft.com` 地址的 `marcraft.com` 子域 DNS 服务器；如果不存在其他子域，它将返回 `marcraft.com` 的 IP 地址。

除了域名跟踪功能外，DNS 系统还将单个计算机的域名解析（链接名称到地址）为其当前的 IP 地址列表。某些 IP 地址永久分配给特定的域名，因此每当在互联网上发出该域名时，它总是访问同一个 IP 地址。这称为 **静态 IP 寻址**。然而，大多数 ISP 使用动态 IP 寻址方案来分配 IP 地址。

## 动态主机配置协议

**动态主机配置协议 (DHCP)** 是一种互联网协议，可用于使用 TCP/IP 自动向网络上的设备分配 IP 地址。使用 DHCP 可简化网络管理，因为是软件而非管理员分配和跟踪 IP 地址。因此，许多 ISP 使用 DHCP 的动态 IP 寻址功能为拨号用户提供接入。该协议自动向网络上的设备提供 IP 地址、子网掩码和默认路由器配置参数以及其他配置信息。

该协议的动态寻址部分还意味着可以将计算机添加到网络中，而无需手动为其分配唯一的 IP 地址。事实上，设备每次连接到网络时都可以被分配不同的 IP 地址。在某些网络中，设备的 IP 地址甚至可以在其保持连接时发生变化。DHCP 还支持静态和动态 IP 地址的混合使用。

DHCP 是由 **互联网工程任务组 (IETF)** 开发的开放标准。它是一种客户端-服务器安排，其中 DHCP 客户端联系 DHCP 服务器以获取其配置参数。DHCP 服务器使用适合当前网络结构的参数动态配置客户端。

DHCP 携带的最重要的配置参数是 IP 地址。计算机必须最初被分配一个适合其所连接网络且未分配给该网络上任何其他计算机的特定 IP 地址。

如果计算机移动到新网络，则必须为该新网络分配一个新的 IP 地址。`DHCP` 可用于自动管理这些分配。`DHCP` 客户端支持内置于所有计算机操作系统中。所有计算机服务器操作系统版本均包含 `DHCP` 的客户端和服务器支持。

虽然 `DHCP` 是 IT 网络环境中备受推崇、节省时间的工具，但在 OT 网络中却未被广泛接受。在这些网络中，`DHCP` 的第一个主要缺点是设备每次启动时都可能获得不同的 IP 地址。虽然这是 IT 网络中的常见且可接受的做法，但工业控制系统通常需要控制设备（如 `PLC`）在每次需要通信时都位于同一 IP 地址。

控制设备不仅通常需要始终保持相同的 IP 地址，而且如果该设备发生故障，其替换设备也需要采用该 IP 地址，以便与控制系统的其他组件正常交互。实现这一点最直接的方法是在将设备安装到网络之前连接到该设备，并使用软件实用程序直接为其配置静态 IP 地址。第二种选择是从包含通用 `DHCP` 服务器的网络连接到该设备，该服务器已配置为为该设备保留租用的静态 IP 地址。在此类配置中，IP 地址租约预留与设备的 `MAC` 地址绑定。
