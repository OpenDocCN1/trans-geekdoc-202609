# 第 10 章：云与虚拟化安全

云计算正在改变所有行业的信息技术。各种规模的组织都被云计算解决方案的敏捷性、灵活性、成本效益和可扩展性所吸引，并迅速将其集成到其技术环境中，如果不是完全转向云端的话。新企业采取“生于云端”的方法，使它们能够在不运营一台服务器的情况下运行整个业务。

本章讨论了对安全专业人员最重要且 Security+ 考试涵盖的云计算方面。您将探索不同的云计算模型、常见的云安全顾虑，以及用于保护云操作的机密性、完整性和可用性的安全控制。

## 探索云

**云计算**可能是一个令人生畏的术语，但其基本理念很简单：云服务提供商通过互联网向客户提供计算服务。这可以像 `Google` 在网页浏览器中向客户提供 `Gmail` 服务一样简单，也可以像 `Amazon Web Services (AWS)` 向企业客户提供虚拟化服务器以供其构建自己的技术环境一样复杂。在每种情况下，提供商都构建一项 IT 服务，并利用互联网将该服务交付给其客户。

以下是美国国家标准与技术研究院 (`NIST`) 对云计算的一个更正式的定义：

> 云计算是一种模型，用于实现普遍、便捷、按需的网络访问，进入可配置的计算资源共享池（例如网络、服务器、存储、应用程序和服务），这些资源能够以最少的管理工作或服务提供商交互快速配置和释放。

让我们浏览一下该定义的一些组成部分。云计算是普遍且便捷的。云提供的资源可供客户随时随地使用。如果您有互联网接入，就可以访问云。无论您坐在办公室还是在海滩上，这都无关紧要。

云计算也是按需的。在大多数情况下，您可以在几分钟内通过几次点击来配置和取消配置云资源。当您需要时，几乎可以立即获取新的云资源；当不再需要时，可以快速将其关闭（并停止付费！）。

云的许多关键优势源于这样一个事实：它使用可由不同用户为不同目的配置的共享资源池。这种共享允许**过度订阅**，因为并非所有人会同时使用其所有资源，并实现了规模经济。许多不同用户在同一云基础设施中共享资源这一事实称为**多租户**。在多租户环境中，相同的物理硬件可能支持许多不同客户的工作负载和存储需求，所有这些客户都在彼此不知情且无交互的情况下运行。

云提供各种可配置的计算资源。我们将在本章后面讨论不同的云服务模型，但您可以通过云服务提供商获取基础设施组件、平台或完整的应用程序，然后对其进行配置以满足您的需求。

云服务的快速配置和释放也只需最少的管理工作和服务提供商交互即可进行。与本地硬件采购不同，您可以自行配置云服务，无需与客户代表打交道，也无需等待订单处理时间。如果您需要一台新的云服务器，不必致电 `Microsoft`、`Amazon` 或 `Google`。您只需在其网站上点击几个按钮即可搞定。从大多数用户的角度来看，云呈现出了看似无限的容量。

### 云的优势

当组织考虑云在其技术基础设施中的适当角色时，他们寻求解决的关键问题是本地资源与云/异地资源之间的适当平衡。正确的平衡因组织而异。了解云提供的一些关键优势有助于找到正确的平衡：

* **按需自助计算**。云资源在您需要的时候和地点可用。这为开发人员和技术人员提供了难以置信的敏捷性，缩短了周期时间并提高了部署速度。
* **可扩展性**。随着对基于云的服务需求增加，客户可以手动或自动增加其运营容量。在某些云环境中，云服务提供商可能会以一种对客户完全透明的方式在后台扩展资源来实现这一点。云提供商通过两种方式实现可扩展性：
    * **垂直扩展**增加现有服务器的容量，如图 10.1(a)所示。例如，您可能会更改分配给服务器的 CPU 核心数或内存量。在物理世界中，这意味着打开服务器并添加物理硬件。在云中，您只需点击几个按钮即可添加内存或计算容量。
    * **水平扩展**向集群服务器池中添加更多服务器，如图 10.1(b)所示。如果您运行一个由两台服务器支持 2,000 个并发用户的网站，每当典型使用量再增加 1,000 个用户时，您可能就会添加一台新服务器。云计算使这变得非常容易，因为您只需点击几下即可复制现有服务器。

![图 10.1 (a) 垂直扩展 vs. (b) 水平扩展](img/c10f001.png)

**图 10.1** (a) 垂直扩展 vs. (b) 水平扩展

* **弹性**。弹性和可扩展性密切相关。可扩展性侧重于快速增加容量。弹性意味着容量应随需求变化而**扩展和收缩**，以优化成本。如果您的网站开始经历活动爆发，弹性允许您自动添加服务器，直到满足该容量需求，然后在不再需要该容量时移除这些服务器。
* **计量服务**。您在云中所做的一切都会由提供商进行计量。提供商会跟踪您消耗的处理时间秒数、您占用的存储空间量、您生成的日志条目数量以及许多其他指标。他们利用这些信息根据您的使用情况来评估费用。您只需为您所用的内容付费——不多也不少。
* **敏捷性**和**灵活性**。预配云资源的速度以及短期使用它们的能力，为技术组织提供了极大的敏捷性和灵活性。希望尝试新想法的开发人员和工程师可以快速启动测试环境，评估该方法，并以最小的工作量和成本决定是否将其移入生产环境。

### 云角色

在任何云计算环境中，不同的组织扮演不同的角色。云中有五个关键角色：

* **云服务提供商**是向客户提供云计算服务的公司。他们可能会建立自己的数据中心，或者与其他云提供商紧密合作以提供服务，但他们的决定性特征是他们提供云服务供销售。
* **云消费者**是从云服务提供商处购买云服务的组织和个人。他们使用这些服务来满足自身的业务需求。
* **云合作伙伴**（或云代理）是提供辅助产品或服务以支持或集成云服务提供商产品的组织。云合作伙伴可能提供培训或咨询以帮助客户使用云服务，提供软件开发和集成服务，或执行任何其他促进云产品使用的服务。
* **云审计员**是对云服务和运营提供第三方评估的独立组织。根据审计业务的范围，他们可能会对云环境提供总体评估，或专注于特定范围运营的安全控制。
* **云承载商**充当中介，提供连接服务，使云服务能够从提供商交付给消费者。

### 云服务模型

我们根据产品/服务的性质，将云服务提供商提供的服务类型分为几类。云中可用的各种服务通常被称为“一切即服务”，或缩写为 **XaaS**，其中 **X** 表示特定服务的性质。尽管有许多不同类型的云服务，但我们通常使用三种主要服务模型来描述它们：**基础设施即服务**、**软件即服务** 和 **平台即服务**。

#### 基础设施即服务

**基础设施即服务** 产品允许客户购买技术基础设施的基本构建模块并与之交互。这些包括计算、存储和网络。然后，客户可以灵活地以任何他们喜欢的方式配置和管理这些服务，以满足自己的业务需求。客户无需担心底层硬件的管理，但他们确实有能力自定义组件以满足其需求。在 `IaaS` 模型中，云服务提供商负责管理物理设施和底层硬件。提供商还必须实施安全控制，以防止客户互相窃听或干扰彼此对基础设施环境的使用。

尽管市场上有数十家 `IaaS` 提供商，但目前市场由三大主要参与者主导：`Amazon Web Services (AWS)`、`Microsoft Azure` 和 `Google Cloud Platform (GCP)`。这三家提供商服务于绝大多数 `IaaS` 客户，并提供广泛的计算、存储和网络产品，以及位于堆栈更高层的补充服务，例如安全监控、内容分发网络和应用流式传输。

#### 软件即服务

**软件即服务** 产品为客户提供对在云中运行的完全托管应用程序的访问。提供商负责从物理数据中心的运营到应用程序本身的性能管理的一切事务，尽管其中一些任务可能会外包给其他云服务提供商。在 `SaaS` 模型中，客户仅负责应用程序本身的有限配置、选择他们希望与云解决方案一起使用的数据，以及使用应用程序提供的访问控制来限制对该数据的访问。

`SaaS` 模型广泛用于交付从基于 Web 的电子邮件到企业资源规划 (`ERP`) 和客户关系管理 (`CRM`) 套件等各类应用程序。客户可持续访问尖端软件，并通常使用订阅模式支付 `SaaS` 服务费用。产品用户通常通过标准 Web 浏览器访问应用程序，甚至可能使用瘦客户端设备，例如图 10.2 所示的 `Google Chromebook`。

#### 平台即服务

**平台即服务** 产品处于 `SaaS` 和 `IaaS` 解决方案之间的中间地带。在 `PaaS` 产品中，服务提供商提供一个平台，客户可以在其中运行他们自己开发的应用程序。云服务提供商构建并管理基础设施，并为客户提供执行环境，其中可能包括促进代码执行的代码库、服务和工具。

![图 10.2 瘦客户端，如这款三星 Google Chromebook，足以访问 SaaS 应用程序。](img/c10f002.png)

**图 10.2** 瘦客户端，如这款三星 `Google Chromebook`，足以访问 `SaaS` 应用程序。

**函数即服务** 平台是 `PaaS` 计算的一个示例。这种方法允许客户将自己的代码函数上传到提供商，然后提供商将按计划、响应事件和/或按需执行这些函数。`AWS Lambda` 服务（如图 10.3 所示）是 `FaaS/PaaS` 产品的一个示例。`Lambda` 允许客户使用 `Python`、`Java`、`C+`、`PowerShell`、`Node.js`、`Ruby`、`Go` 和其他编程语言编写代码。图 10.3 中所示的 `Lambda` 函数是一个 `Python` 函数，旨在从 `物联网` 温度传感器读取当前温度。

由于 `FaaS` 环境不会向客户暴露执行其代码的实际服务器实例，因此它们通常被称为 **无服务器计算** 环境。然而，这在一定程度上是一个误称，因为 `FaaS` 环境确实有运行代码的服务器，但它们以对 `FaaS` 客户透明的方式进行。

### 云部署模型

云部署模型描述了云服务如何交付给客户，以及用于向一个客户提供服务的资源是否与其他客户共享。

#### 公有云

当我们想到“云”时，通常首先想到的是 **公有云** 产品。公有云服务提供商部署基础设施，然后以多租户模式使其可供任何希望利用它的客户访问。单个客户可能在分布在一个或多个数据中心的服务器上运行工作负载，而这些服务器可能同时为许多不同的客户运行工作负载。

公有云支持所有云服务模型。公有云提供商可能会向其客户提供 `IaaS`、`PaaS`、`SaaS` 和 `FaaS` 服务。关键区别在于，这些服务并非运行在专属于单个客户的基础设施上，而是运行在面向公众开放的基础设施上。`AWS`、`Microsoft Azure` 和 `Google Compute Platform` 均采用公有云模型。

#### 私有云

术语 `private cloud`（私有云）用于描述为单个客户使用而配置的任何云基础设施。该基础设施可能由将使用该基础设施的组织构建和管理，也可能由第三方构建和管理。此处的关键区别在于，只有一个客户使用该环境。因此，私有云服务往往拥有过剩的未使用容量以支持峰值需求，因此与公有云服务相比，其成本效益不高。

#### 社区云

`community cloud`（社区云）服务兼具公有云和私有云模型的特征。社区云服务确实运行在多租户环境中，但租户仅限于特定设计社区的成员。社区成员资格通常基于共同的使命、相似的安全与合规要求或其他共性来定义。

如图 10.4 所示的 `HathiTrust` 数字图书馆，就是社区云实际应用的一个例子。学术研究图书馆联合起来形成一个联盟，提供对其馆藏图书的访问。`HathiTrust` 成员机构的学生和教职员工可以登录社区云服务以访问资源。

#### 混合云

`Hybrid cloud`（混合云）是一个统称，用于描述将公有云、私有云和/或社区云服务融合在一起的云部署。它不仅仅是同时购买公有云和私有云服务并一起使用。混合云要求使用能够将不同云产品统一为单一连贯平台的技术。

例如，一家公司可能为其大部分工作负载运行自己的私有云，然后在需求超过其私有云基础设施容量时利用公有云容量。这种方法称为公有云 `bursting`（云爆发/突发）。

![图 10.4 HathiTrust 是社区云计算的一个例子。](img/c10f004.png)

**图 10.4** `HathiTrust` 是社区云计算的一个例子。

`AWS Outposts`，如图 10.5 所示，是混合云计算的例子。该服务的客户会收到一机架计算设备，并在自己的数据中心安装。机架中的设备由 `AWS` 维护，但由客户以与其 `AWS` 公有云资源相同的方式进行配置。这种方法属于混合云，因为客户可以通过同一管理平台同时管理其本地 `AWS Outposts` 私有云部署及其公有云 `AWS` 服务。

## 共享责任模型

在某些方面，以云为中心的环境中的网络安全工作与本地网络安全非常相似。无论我们的系统托管在何处，我们仍然需要考虑数据的机密性、完整性和可用性，并实施强有力的访问控制和其他机制来保护这些主要目标。

![图 10.5 AWS Outposts 提供混合云能力。](img/c10f005.png)

**图 10.5** `AWS Outposts` 提供混合云能力。图片归 `Amazon Web Services` 所有；经许可使用

然而，云安全运营在很大程度上也不同于本地环境，因为云客户必须在一个或多个服务提供商与客户自身的网络安全团队之间划分责任。这种类型的运营环境称为 `shared responsibility model`（共享责任模型）。图 10.6 展示了 `IaaS`、`PaaS` 和 `SaaS` 环境中常见的责任划分。

![图 10.6 云计算共享责任模型](img/c10f006.png)

**图 10.6** 云计算共享责任模型

在某些情况下，这种责任划分是明确的。云提供商因其本质，始终负责硬件和物理数据中心环境的安全。如果由客户处理其中任何一项，该解决方案将不符合云计算的定义。

责任的差异出现在堆栈的更高层，并根据所使用的云服务性质而有所不同。在 `IaaS` 环境中，客户承担除基础设施以外所有内容的安全责任——即他们在 `IaaS` 环境中运行的操作系统、应用程序和数据。

在 `PaaS` 解决方案中，供应商也承担操作系统的责任，而客户保留对放入环境中的数据及其安全配置的责任。应用层的责任由服务提供商和客户共担，具体的责任划分根据服务的性质而变化。例如，如果 `PaaS` 平台为客户代码提供运行时解释器，则云提供商负责这些解释器的安全。

在 `SaaS` 环境中，提供商承担几乎所有的安全责任。客户对其放置在 `SaaS` 环境中的数据以及围绕该数据的访问控制配置保留一定的共享控制权，但 `SaaS` 提供商因获得报酬而承担大部分运营任务（包括网络安全）的负担。

## 虚拟化

云计算提供商以及大多数其他现代数据中心运营商，广泛使用 `virtualization`（虚拟化）技术，允许多个客户系统共享同一底层硬件。在虚拟化数据中心中，虚拟主机硬件运行一种称为 `hypervisor`（管理程序/虚拟机监视器）的特殊操作系统，它协调对底层硬件资源的访问。

虚拟机随后运行在 `Hypervisor` 提供的此虚拟基础设施之上，运行标准操作系统，如 `Windows` 和 `Linux` 变体。虚拟机可能不知道它们正在虚拟化环境中运行，因为 `Hypervisor` 欺骗它们，让它们以为拥有对底层硬件的正常访问权限，而实际上，这些硬件与其他系统共享。

### Hypervisor

`Hypervisor` 的主要职责是强制执行虚拟机之间的 `isolation`（隔离）。这意味着 `Hypervisor` 必须向每个虚拟机呈现一个完全独立的物理环境的假象，该环境专供该虚拟机使用。从运营角度来看，隔离确保虚拟机不会相互干扰彼此的操作。从安全角度来看，这意味着虚拟机无法访问或更改分配给另一个虚拟机的信息或资源。

`Hypervisor` 主要有两种类型：

* **Type I Hypervisor**（第 I 类 Hypervisor），也称为 **Bare Metal Hypervisor**（裸金属 Hypervisor），直接在底层硬件之上运行。随后，`Hypervisor` 为每个虚拟机支持 `Guest OS`（客户操作系统），如图 10.9 所示。这是数据中心虚拟化中最常用的模型，因为它效率极高。
