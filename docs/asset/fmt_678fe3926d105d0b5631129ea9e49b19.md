# 理解 Syslog

# 安全信息和事件管理

`安全信息和事件管理 (SIEM)` 系统是允许你从单个系统实时监控安全信息和事件的产品（通常为软件）！SIEM 产品提供对网络上多台设备的安全信息和事件的集中监控和报告。

SIEM 系统通常提供丰富的功能，帮助你从单个应用程序集中监控跨多个系统和网络设备的安全相关事件。以下列表列出了其中一些功能：

- **日志聚合** 从多个系统和网络设备收集日志文件到 SIEM 软件中，以便能从单一位置进行分析。
- **关联分析** SIEM 软件具备比较不同日志文件中事件的能力，以便将这些事件关联起来作为安全相关事件。
- **自动警报和触发器** 基于管理员配置的、在日志文件中发生的事件，触发并发送警报。
- **时间同步** SIEM 软件可确保跨设备的时间同步，以便跨设备的安全事件在同一时间被记录。
- **事件去重** SIEM 系统可精简事件日志记录，使同一事件不会反复记录，从而填满日志空间。
- **日志/WORM** 在写入日志文件时，SIEM 系统采用一次写入、多次读取 (WORM) 的方法，即日志条目只写入一次但可读取多次。

## 监控工具的考量因素

安全监控系统（包括 SIEM 系统）拥有许多功能和能力，你应该利用它们来帮助密切关注你的企业环境。以下是关于监控的一些考量因素，你应该为了 Security+ 考试而了解它们：

- **审查报告** 使用任何监控工具时，你都要确保定期审查报告，以深入了解环境中发生的活动类型。
- **数据包捕获** 监控工具应能捕获网络上的流量，并将捕获的数据存储在捕获文件中，以便使用监控工具进行查看。
- **数据输入** 监控工具应有多种不同的数据输入，以便你能集中监控不同系统和设备上的活动。
- **用户行为分析** 监控工具应具备监控用户行为的能力，以帮助检测潜在的内部威胁。
- **情感分析** 监控系统可能具备执行情感分析的能力，即审查信息以确定该信息是积极、消极还是中性的。
- **安全监控** 监控工具应执行安全事件监控，这通常来自不同系统上的安全日志。
- **日志聚合** 如前所述，工具应能使用来自不同系统的各种日志类型，并将它们汇总以进行完整分析。
- **日志收集器** 监控工具应具备日志收集器组件，使其能够从网络上的不同系统和设备收集日志。

## 使用 SOAR

在讨论帮助我们监控安全事件的企业级解决方案时，我们还应该讨论 *Security Orchestration, Automation, and Response*（安全编排、自动化与响应）的概念，简称 **SOAR**。**SOAR** 不仅仅是一个监控工具；它更像是一个安全管理工具。借助 **SOAR**，您可以使用软件工具帮助您简化并自动化安全运营，重点关注三大领域——威胁与漏洞管理、安全事件响应和安全运营自动化。

公司可以使用 **SOAR** 从不同来源收集安全事件数据，检测安全威胁，然后自动响应威胁以采取某种形式的纠正措施。

# 实施日志记录和审计

现在您了解了一些可用于监控系统的工具，让我们来谈谈审计和日志记录。作为一名安全专业人员，您需要确保评估系统和应用程序上已启用的审计和日志记录级别。以下是审计和日志记录区别的快速定义：

- **Auditing（审计）** 通常是指您出于安全目的希望在系统或应用程序上监控的操作。例如，您可能希望审计系统上的用户账户管理或应用程序中的客户记录删除操作。
- **Logging（日志记录）** 通常是指记录应用程序或系统中发生的所有活动。例如，您可以记录对网站的所有请求，稍后再查看日志。

## 理解审计

作为任何环境中的安全专业人员，请确保已在所有关键系统和设备上启用审计，并确定已配置的审计级别。至关重要的是，必须有人接受过如何查看审计日志的培训，并知道如何将其归档到安全位置，以防需要回溯。

配置审计主要有四个步骤：

1. 决定审核哪些事件。
2. 决定您关心每个事件的成功还是失败。
3. 配置审计。
4. 定期查看审计日志。

### 配置审计

配置审计的第一步是定义您的审计策略。在定义审计策略时，为操作系统中的特定事件启用审计。*事件* 是指系统中发生的事情，通常由用户调用。例如，登录或注销网络是一个事件。访问文件夹也是一个事件。因此，您需要确定希望收到通知的事件——相信我，您在启用哪些事件方面必须极其挑剔！重要的是要记住，您审计的事件越多，收集的信息就越多——您不想收集不必要的信息，因为这可能会掩盖重要的审计数据。

在 Windows 中，您可以通过单个系统的本地安全策略实施审计，也可以使用 Active Directory 中的组策略将审计设置部署到多个系统。要在 Windows 中配置审计，请从以下工具中选择一项来管理审计策略：

- **Start | Administrative Tools | Local Security Policies（开始 | 管理工具 | 本地安全策略）** 在单个独立系统上实施审计。
- **Start | Administrative Tools | Domain Controller Security Policy（开始 | 管理工具 | 域控制器安全策略）** 在网络上的所有域控制器上实施审计。
- **Start | Administrative Tools | Domain Security Policy（开始 | 管理工具 | 域安全策略）** 在整个 Active Directory 域中的所有系统上实施审计。

启动正确的管理工具后，您可以为许多事件启用审计（请参阅 Figure 19-5），并且在启用审计时，您必须决定关心此类事件的成功还是失败。例如，您是否关心某人成功登录网络还是登录失败？

### 查看审计日志

配置审计后，您将使用 Windows 事件查看器来监控您已启用审计的安全相关事件。以下是您可以在 Windows 事件查看器中查看的一些日志列表：

- **Application log（应用程序日志）** 存储在 Windows 上运行的应用程序的错误和信息
- **System log（系统日志）** 存储操作系统组件的错误、警告和信息，例如服务启动失败时
- **Security log（安全日志）** 存储审计信息和其他安全相关事件

## Linux 中的审计

Linux 使用 `syslogd` 守护进程来审核活动（守护进程是一种始终在主机上运行的计算机程序，即使没有用户登录也会运行——类似于 Windows 服务）。`syslogd` 从 `/etc/syslog.conf` 读取其配置，以确定审核内容以及是否向管理员通报可疑活动。Linux 管理员还拥有大量操作系统命令；例如，`last` 列出当前已登录的用户，`lastlog` 列出所有用户的上次登录时间。以下是 Linux 中一些常用的日志文件：

- **`/var/log/faillog`** 显示用户账户的失败登录尝试。您可以在大多数 Linux 发行版上使用 `faillog` 命令来查看失败的登录记录。
- **`/var/log/lastlog`** 显示用户列表及其上次登录时间。使用 `lastlog` 命令可显示该日志的输出。
- **`/var/log/wtmp`** 显示已登录系统的用户。使用 `last` 命令可显示该日志文件的内容。
- **`/var/log/messages`** 包含有关系统相关事件的信息。
- **`/var/log/auth.log`** 某些 Linux 发行版使用此文件记录认证尝试和认证事件的信息。

您可以使用任何文本编辑器打开大多数这些 Linux 日志文件，或者在某些 Linux 发行版中，您可以使用系统日志查看器来显示常用日志文件的内容。要在 Linux 中查看系统日志查看器（参见图 19-8），请选择“系统”菜单，然后选择“管理 | 系统日志”。

## 其他日志

在监控系统或设备并寻找安全事件时，您可能需要检查各种日志，因为存在许多不同类型的系统和设备。以下概述了审核活动时可能会查看的一些常用日志系统：
