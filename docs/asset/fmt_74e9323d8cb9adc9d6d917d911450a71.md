
`Printf` 有十多种此类转换，Go 程序员称之为 `verb`（动词/格式动词）。下表远非完整规范，但展示了许多可用特性：

| Verb | 含义 |
| --- | --- |
| `%d` | 十进制整数 |
| `%x, %o, %b` | 十六进制、八进制、二进制整数 |
| `%f, %g, %e` | 浮点数：`3.141593 3.141592653589793 3.141593e+00` |
| `%t` | 布尔值：`true` 或 `false` |
| `%c` | rune（Unicode 码点） |
| `%s` | 字符串 |
| `%q` | 带引号的字符串 `"abc"` 或 rune `'c'` |
| `%v` | 任意值的自然格式 |
| `%T` | 任意值的类型 |
| `%%` | 字面百分号（无操作数） |

`dup1` 中的格式字符串还包含制表符 `\t` 和换行符 `\n`。字符串字面量可包含此类 `escape sequences`（转义序列），用于表示其他不可见字符。`Printf` 默认不写入换行符。按照惯例，名称以 `f` 结尾的格式化函数（如 `log.Printf` 和 `fmt.Errorf`）使用 `fmt.Printf` 的格式化规则，而以 `ln` 结尾的函数遵循 `Println`，将参数按 `%v` 格式化后加上换行符。

许多程序要么从标准输入读取（如上），要么从一系列命名文件读取。`dup` 的下一个版本可以从标准输入读取，或使用 `os.Open` 处理文件名列表：

gopl.io/ch1/dup2

```
// Dup2 打印输入中出现次数超过一次的行的计数和文本。
// 它从标准输入或一系列命名文件中读取。
package main

import (
    "bufio"
    "fmt"
    "os"
)

func main() {
    counts := make(map[string]int)
    files := os.Args[1:]
    if len(files) == 0 {
        countLines(os.Stdin, counts)
    } else {
        for _, arg := range files {
            f, err := os.Open(arg)
            if err != nil {
                fmt.Fprintf(os.Stderr, "dup2: %v\n", err)
                continue
            }
            countLines(f, counts)
            f.Close()
        }
    }
    for line, n := range counts {
        if n > 1 {
            fmt.Printf("%d\t%s\n", n, line)
        }
    }
}

func countLines(f *os.File, counts map[string]int) {
    input := bufio.NewScanner(f)
    for input.Scan() {
        counts[input.Text()]++
    }
    // NOTE: ignoring potential errors from input.Err()
}
```

函数 `os.Open` 返回两个值。第一个是打开的文件（`*os.File`），供 `Scanner` 后续读取使用。

`os.Open` 的第二个返回值是内置 `error` 类型的值。若 `err` 等于特殊内置值 `nil`，则文件打开成功。读取文件，到达输入末尾时，`Close` 关闭文件并释放资源。反之，若 `err` 不为 `nil`，则出错。此时错误值描述了问题。我们的简单错误处理使用 `Fprintf` 和 verb `%v`（以默认格式显示任意类型值）向标准错误流打印消息，随后 `dup` 继续处理下一个文件；`continue` 语句跳转到外层 `for` 循环的下一次迭代。

为保持代码示例规模合理，早期示例有意在错误处理上略显随意。显然我们必须检查 `os.Open` 的错误；但我们忽略了使用 `input.Scan` 读取文件时发生错误的可能性较小的情况。我们会标注跳过错误检查的地方，并在 5.4 节详细介绍错误处理。

注意 `countLines` 的调用先于其声明。函数及其他包级实体可按任意顺序声明。

Map 是对 `make` 创建的数据结构的 `reference`（引用）。将 map 传递给函数时，函数接收引用的副本，因此被调函数对底层数据结构的任何修改都将通过调用者的 map 引用可见。在本例中，`countLines` 插入 `counts` map 的值在 `main` 中可见。

上述的 `dup` 版本以“流式”模式运行，即根据需要读取输入并将其拆分为行，因此原则上这些程序可以处理任意数量的输入。另一种方法是一次性将整个输入读入内存，一次性将其拆分为行，然后处理这些行。下面的版本 `dup3` 采用这种方式。它引入了函数 `ReadFile`（来自 `io/ioutil` 包），用于读取指定文件的全部内容，以及 `strings.Split`，用于将字符串分割成子字符串切片。(`Split` 是 `strings.Join` 的逆操作，我们之前见过。)

我们对 `dup3` 做了一些简化。首先，它只读取命名文件，不读取标准输入，因为 `ReadFile` 需要一个文件名参数。其次，我们将行计数移回了 `main` 函数中，因为现在它只在一个地方需要。

点击此处查看代码图像

gopl.io/ch1/dup3

```
package main

import (
    "fmt"
    "io/ioutil"
    "os"
    "strings"
)

func main() {
    counts := make(map[string]int)
    for _, filename := range os.Args[1:] {
        data, err := ioutil.ReadFile(filename)
        if err != nil {
            fmt.Fprintf(os.Stderr, "dup3: %v\n", err)
            continue
        }
        for _, line := range strings.Split(string(data), "\n") {
            counts[line]++
        }
    }
    for line, n := range counts {
        if n > 1 {
            fmt.Printf("%d\t%s\n", n, line)
        }
    }
}
```

`ReadFile` 返回一个字节切片，必须将其转换为 `string` 以便能被 `strings.Split` 分割。我们将在 3.5.4 节详细讨论字符串和字节切片。

在底层，`bufio.Scanner`、`ioutil.ReadFile` 和 `ioutil.WriteFile` 使用 `*os.File` 的 `Read` 和 `Write` 方法，但大多数程序员很少需要直接访问那些底层例程。来自 `bufio` 和 `io/ioutil` 等包的高级函数更容易使用。

## 1.4 动画 GIF

下一个程序演示了 Go 标准图像包的基本用法，我们将用它们创建一系列位图图像，然后将该序列编码为 GIF 动画。这些图像被称为*利萨如图形*，是 20 世纪 60 年代科幻电影中的常见视觉效果。它们是由二维谐振产生的参数曲线，例如将两个正弦波分别输入示波器的 `x` 和 `y` 输入端。图 1.1 展示了一些示例。

![四个利萨如图形。](img/lissajous.png)

**图 1.1.** 四个利萨如图形。

这段代码包含几个新结构，包括 `const` 声明、结构体类型和复合字面量。与大多数示例不同，本示例还涉及浮点数计算。我们将简要讨论这些主题，大部分细节留待后续章节，因为目前的主要目标是让你了解 Go 的外观，以及使用该语言及其库可以轻松完成哪些事情。

```
// Lissajous 生成随机利萨如图形的 GIF 动画。
package main

import (
    "image"
    "image/color"
    "image/gif"
    "io"
    "math"
    "math/rand"
    "os"
)

var palette = []color.Color{color.White, color.Black}

const (
    whiteIndex = 0 // 调色板中的第一种颜色
    blackIndex = 1 // 调色板中的下一种颜色
)

func main() {
    lissajous(os.Stdout)
}

func lissajous(out io.Writer) {
    const (
        cycles  = 5     // x 振荡器完成的完整周期数
        res     = 0.001 // 角分辨率
        size    = 100   // 图像画布覆盖 [-size..+size]
        nframes = 64    // 动画帧数
        delay   = 8     // 帧间延迟，单位为 10ms
    )
    freq := rand.Float64() * 3.0 // y 振荡器的相对频率
    anim := gif.GIF{LoopCount: nframes}
    phase := 0.0 // 相位差
    for i := 0; i < nframes; i++ {
        rect := image.Rect(0, 0, 2*size+1, 2*size+1)
        img := image.NewPaletted(rect, palette)
        for t := 0.0; t < cycles*2*math.Pi; t += res {
            x := math.Sin(t)
            y := math.Sin(t*freq + phase)
            img.SetColorIndex(size+int(x*size+0.5), size+int(y*size+0.5),
                blackIndex)
        }
        phase += 0.1
        anim.Delay = append(anim.Delay, delay)
        anim.Image = append(anim.Image, img)
    }
    gif.EncodeAll(out, &anim) // 注意：忽略了编码错误
}
```

导入路径包含多个组件的包（如 `image/color`）后，我们使用由最后一个组件派生的名称来引用该包。因此变量 `color.White` 属于 `image/color` 包，而 `gif.GIF` 属于 `image/gif`。

`const` 声明（§3.6）为常量命名，即编译时固定的值，例如周期数、帧数和延迟等数值参数。与 `var` 声明一样，`const` 声明可以出现在包级别（这样名称在整个包中可见）或函数内部（这样名称仅在该函数内可见）。常量的值必须是数字、字符串或布尔值。

表达式 `[]color.Color{...}` 和 `gif.GIF{...}` 是*复合字面量*（§4.2，§4.4.1），这是一种简洁的表示法，用于从一系列元素值实例化 Go 的任意复合类型。这里，第一个是切片，第二个是*结构体*。

类型 `gif.GIF` 是一个结构体类型（§4.4）。结构体是一组被称为*字段*的值的集合，通常类型不同，它们被收集在一个可以作为一个单元处理的单一对象中。变量 `anim` 是 `gif.GIF` 类型的结构体。结构体字面量创建了一个结构体值，其 `LoopCount` 字段被设置为 `nframes`；所有其他字段都具有其类型的零值。结构体的各个字段可以通过点号表示法访问，如最后两个赋值语句所示，它们显式更新了 `anim` 的 `Delay` 和 `Image` 字段。

`lissajous` 函数有两个嵌套循环。外层循环运行 64 次迭代，每次生成动画的一帧。它创建一个新的 201×201 图像，调色板包含白色和黑色两种颜色。所有像素初始设置为调色板的零值（调色板中的第零种颜色），我们将其设为白色。内层循环的每次迭代通过将某些像素设为黑色来生成新图像。结果连同 80ms 的指定延迟，使用内置的 `append` 函数（§4.2.1）追加到 `anim` 的帧列表中。最后，帧序列和延迟被编码为 GIF 格式并写入输出流 `out`。`out` 的类型是 `io.Writer`，这让我们可以写入各种可能的目标，稍后我们将展示。

内层循环运行两个振荡器。*x* 振荡器就是正弦函数。*y* 振荡器也是正弦波，但其相对于 *x* 振荡器的频率是 0 到 3 之间的随机数，其相对于 *x* 振荡器的相位初始为零，但随着动画的每一帧而增加。循环运行直到 *x* 振荡器完成五个完整周期。在每一步中，它调用 `SetColorIndex` 将对应于 (*x*, *y*) 的像素着色为黑色，即调色板中位置 1 的颜色。

`main` 函数调用 `lissajous` 函数，指示其写入标准输出，因此该命令会生成一个动画 GIF，其帧如图 1.1 所示：

## 1.5 获取 URL

对于许多应用程序而言，从互联网获取信息与访问本地文件系统同样重要。Go 提供了一组包，归类在 `net` 下，它们使得通过互联网发送和接收信息、建立低级网络连接以及搭建服务器变得容易，而 Go 的并发特性（将在第 8 章第 8 章中介绍）对于服务器编程特别有用。

为了演示通过 HTTP 检索信息所需的最小代码量，这里有一个名为 `fetch` 的简单程序，它获取每个指定 URL 的内容并将其作为未经解释的文本打印出来；它的灵感来源于不可或缺的工具 `curl`。显然，通常我们会对这些数据做更多处理，但这展示了基本思路。我们将在本书中频繁使用该程序。

点击此处查看代码图像

gopl.io/ch1/fetch

```
// Fetch prints the content found at a URL.
package main

import (
    "fmt"
    "io/ioutil"
    "net/http"
    "os"
)

func main() {
    for _, url := range os.Args[1:] {
        resp, err := http.Get(url)
        if err != nil {
            fmt.Fprintf(os.Stderr, "fetch: %v\n", err)
            os.Exit(1)
        }
        b, err := ioutil.ReadAll(resp.Body)
        resp.Body.Close()
        if err != nil {
            fmt.Fprintf(os.Stderr, "fetch: reading %s: %v\n", url, err)
            os.Exit(1)
        }
        fmt.Printf("%s", b)
    }
}
```

该程序介绍了来自两个包的函数：`net/http` 和 `io/ioutil`。`http.Get` 函数发起一个 HTTP 请求，如果没有错误发生，则在响应结构体 `resp` 中返回结果。`resp` 的 `Body` 字段包含一个可读的流作为服务器响应。接下来，`ioutil.ReadAll` 读取整个响应；结果存储在 `b` 中。关闭 `Body` 流以避免资源泄漏，`Printf` 将响应写入标准输出。
