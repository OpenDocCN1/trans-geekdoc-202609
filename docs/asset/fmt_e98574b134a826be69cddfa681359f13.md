
在你的应用程序中使用异常来以优雅的方式处理错误，并使用 `try` 块来确保这些异常得到适当的处理。我保证，这会让让你成为一名更好的程序员。

## 24. 特性 (Traits)

在继承章节中，我们学习了如何扩展类来共享公共功能。扩展类的问题在于，你只能扩展另外一个类。这有点局限性。

### 实现

在 PHP 5.4 中，语言引入了一种名为“trait”（特性）的新结构。通过使用 trait，PHP 类可以从多个源继承方法和属性。这是对单继承问题的直接解决方案。

让我们来看一个 trait 吧，好吗？

**示例 01：我的第一个 trait。**

```php
trait SomethingTrait
{
}
```

如你所见的，一个 trait 看起来和类非常相似。相反，它是使用 `trait` 关键字声明的。以 `Trait` 后缀命名 trait 的惯例非常流行，所以这可能是你应该考虑采用的。

与类不同，重要的是需要记住的一点是，你不能在 trait 中添加 `extends` 或 `implements`。你无法实例化一个 trait。它们的唯一目的是支持我们的类，而不是取代它们。

Trait 可以拥有方法，就像类一样。让我们先回想一下我们的 `Animal` 类。你还记得它吗？这里在这里再次列出来以刷新我们的记忆。

**示例 02：一个抽象类。**

```php
<?php
abstract class Animal
{
}
```

我们名为 `Animal` 的类是一个抽象类。这意味着它是为了让我们代表实际动物的类来扩展的。

考虑我们想添加一个 `stroke()` 方法的可能性。例如，我们想 `stroke()` 我们的小熊猫让它们发出呼噜声。我们可以添加类似下面的代码。

**示例 03：stroke 方法。**

```php
<?php
abstract class Animal
{
    /**
     * 抚摸该动物。
     * @return void
     */
    public function stroke()
    {
        echo 'This animal purrs contentedly.';
    }
}
```

当然！那样行得通，对吧？问题是，你不会去摸蛇，对吧？不，摸每种动物是没有意义的……嗯，我们可以做什么？哦，trait！

你会发现，trait 非常适合为对象添加一个新的……嗯……特性（trait）。我们想为可以抚摸的动物添加一个特性，所以我们寻找的是一个 `StrokeableTrait`。当然，这对我来说很有道理！让我们沿着这个想法继续吧。

**示例 04：StrokableTrait。**

```php
<?php

trait StrokableTrait
{
    /**
     * 抚摸该动物。
     *
     * @return void
     */
    public function stroke()
    {
        echo 'This animal purrs contently.';
    }
}
```

我们已经将 `stroke()` 方法移动到了 trait。你会发现这里没有其他区别。这意味着我们也可以这样从 `Animal` 中移除该方法。

**示例 05：抽象 Animal。**

```php
<?php
abstract class Animal
{
}
```

完美，我们都准备好了。让我们创建一个小熊猫类，好吗？毕竟，这本书的核心就是这个。嗯，我想也包括 PHP……

**示例 06：RedPanda 类。**

```php
class RedPanda extends Animal
{
    /**
     * 熊猫的名字。
     * @var string
     */
    private $sname = 'Jasmina';
}
```

很漂亮，不是吗？我们扩展了 `Animal` 类，虽然它目前可能是空的，但假设它可以充满许多有用的方法，例如 `eat()`、`sleep()` 和 `poop()`。

现在，让我们考虑一下熊猫吧。她绝对是可以抚摸的，不是吗？让我们继续使用这个 trait。

**示例 07：使用 StrokeableTrait。**

```php
<?php
class RedPanda extends Animal
{
    use StrokeableTrait;
    /**
     * 熊猫的名字。
     * @var string
     */
    private $sname = 'Jasmina';
}
```

我觉得这有点烦人，但不幸的是，将 trait 应用于类的使用的关键字又是 `use` 关键字。这是你在命名空间（namespaces）章节中会找到相同关键字。这种命名很遗憾，但是

**示例 08：使用 trait。**

```php
<?php
```

## 25. 命名空间

### 全局命名空间

这里有一个非常简单的类。

**示例 01：Eddard 类。**

```php
<?php
// app/models/Eddard.php
class Eddard
{
}
```

**示例 02：创建一个新的 Eddard。**

```php
<?php
// app/routes.php
$eddard = new Eddard();
```

Dayle，我懂一些 PHP...

好吧，好吧，抱歉。基本上，我们可以把这个类看作是位于“全局”（global）命名空间中的。我不知道这个术词是否准确，但对我来说听起来很合适。它本质上意味着这个类在没有命名空间的情况下存在。它只是一个普通的类。

### 简单命名空间 (Simple Namespacing)

让我们在原始的全局 Eddard 旁边创建另一个类。

**示例 03：Stark 命名空间。**

```php
<?php
namespace Stark;
// app/models/another.php
class Eddard
{
}
```

在这里我们有另一个 Eddard 类，有一个微小的变化：添加了命名空间指令。`namespace Stark` 这一行告诉 PHP，我们所做的一切都是相对于 Stark 命名空间的。这也意味着在此文件中创建的任何类都存在于 'Stark' 命名空间内。

现在，让我们再次尝试使用 'Stark' 类。

**示例 04：再次创建 Eddard。**

```php
<?php
// app/routes.php
$eddard = new Eddard();
```

我们再次得到了我们在上一节中创建的第一个类的实例，而不是 'Stark' 命名空间中的那个。让我们尝试在 'Stark' 命名空间内创建一个 'Eddard' 实例。

**示例 05：创建一个 StarkEddard。**

```php
<?php
// app/routes.php
$eddard = new Stark\Eddard();
```

我们可以在命名空间内实例化类，在前面加上命名空间的名字，并用反斜杠 `\` 将两者分隔。现在我们有一个 'Stark' 命名空间下的 'Eddard' 类实例。我们不是很神奇吗？

你应该知道，命名空间可以根据需要具有任意级别的层次结构。例如：

**示例 06：一个糟糕但合法的命名空间。**

`This\Namespace\And\Class\Combination\Is\Silly\But\Works`
