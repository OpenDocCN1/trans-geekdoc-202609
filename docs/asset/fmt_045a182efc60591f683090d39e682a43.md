
```php
class CustomObject implements Serializable {

    private $data;

    public function __construct(array $data) {
        $this->data = $data;
    }

    public function serialize(): string {
        return serialize($this->data);
    }

    public function unserialize($data): void {
        $this->data = unserialize($data);
    }

}

$data = ['name' => 'John', 'age' => 30];

$customObject = new CustomObject($data);

// 序列化对象
$serialized = serialize($customObject);

// 反序列化对象
$unserialized = unserialize($serialized);

var_dump($unserialized);
```

在本例中，`CustomObject` 类实现了 `Serializable` 接口，为其内部数据提供了自定义的序列化和反序列化逻辑。这使你能对序列化过程进行细粒度控制。

### 7.4.2. 序列化上下文选项

PHP 8 引入了序列化上下文选项，允许你在序列化对象时指定额外选项。这些选项提供了对对象序列化方式的更多控制，并有助于防止潜在的安全漏洞。上下文选项作为关联数组传递给 `serialize()` 函数。示例如下：

```php
$data = ['name' => 'John', 'age' => 30];

// 使用上下文选项序列化数据
$serialized = serialize($data, ['allowed_classes' => false]);

// 尝试在未将 allowed_classes 设置为 false 的情况下反序列化数据将导致错误
$unserialized = unserialize($serialized);
```

在本例中，`allowed_classes` 选项被设置为 `false`，这将阻止任何类被反序列化。这可以作为一项安全措施，防止反序列化期间任意对象实例化。

### 7.4.3. 自定义序列化和反序列化逻辑

正如前面所示，你可以通过实现 `Serializable` 接口为对象定义自定义序列化和反序列化逻辑。这允许你控制对象在序列化形式中的表示方式以及反序列化时的重建方式。

实现自定义序列化和反序列化时，请考虑以下几点：

*   仅序列化必要的数据，以最小化序列化字符串的大小。
*   确保反序列化逻辑安全，不会引入安全漏洞。
*   彻底测试序列化和反序列化，以验证数据完整性。

通过利用 PHP 8 与序列化和反序列化相关的增强功能，你可以在 PHP 应用程序中更安全、更高效地处理数据，尤其是在使用自定义对象和复杂数据结构时。

## 7.5. Reflection API：理解并使用新特性

PHP 中的 Reflection API 提供了一种在运行时动态内省和操作类、方法、属性及其他代码元素的方法。PHP 8 为 Reflection API 引入了多项新特性和改进，使其更加强大和通用。

### 7.5.1. 命名属性

PHP 8 中一个重要的新增功能是 Reflection API 对命名属性的支持。命名属性允许您使用反射来访问和处理附加到类、方法、函数和属性上的属性。

您可以使用 `ReflectionClass`、`ReflectionMethod`、`ReflectionFunction` 或 `ReflectionProperty` 类的 `getAttributes()` 方法来检索属性信息。以下是一个示例：

```php
#[Author("John Doe")]
class MyClass {
    #[Version("1.0")]
    public string $name;

    #[Deprecated("This method is deprecated.")]
    public function myMethod() {}
}

$reflectionClass = new ReflectionClass(MyClass::class);
$classAttributes = $reflectionClass->getAttributes();

foreach ($classAttributes as $attribute) {
    echo "Attribute: {$attribute->getName()}";
    foreach ($attribute->getArguments() as $argument) {
        echo "Argument: {$argument}\n";
    }
}

$reflectionProperty = new ReflectionProperty(MyClass::class, 'name');
$propertyAttributes = $reflectionProperty->getAttributes();

foreach ($propertyAttributes as $attribute) {
    echo "Attribute: {$attribute->getName()}";
    foreach ($attribute->getArguments() as $argument) {
        echo "Argument: {$argument}\n";
    }
}

$reflectionMethod = new ReflectionMethod(MyClass::class, 'myMethod');
$methodAttributes = $reflectionMethod->getAttributes();

foreach ($methodAttributes as $attribute) {
    echo "Attribute: {$attribute->getName()}";
    foreach ($attribute->getArguments() as $argument) {
        echo "Argument: {$argument}\n";
    }
}
```

在本示例中，我们定义了一个类 `MyClass`，分别在类本身、一个属性和一个方法上应用了命名属性 `Author`、`Version` 和 `Deprecated`。然后我们使用反射来访问并显示属性信息，包括属性名称及其参数。

### 7.5.2. 联合类型

PHP 8 还在 Reflection API 中引入了联合类型支持，允许您确定方法签名或属性声明中声明的联合类型。

您可以使用 `ReflectionFunctionAbstract` 类（`ReflectionMethod` 和 `ReflectionFunction` 均继承自该类）的 `getReturnType()` 方法来检索方法的返回类型。以下是一个示例：

```php
class MyClass {
    public function myMethod(): string|int {}
}

$reflectionMethod = new ReflectionMethod(MyClass::class, 'myMethod');
$returnType = $reflectionMethod->getReturnType();

if ($returnType instanceof ReflectionNamedType) {
    echo "Return Type: {$returnType->getName()}\n";
} elseif ($returnType instanceof ReflectionUnionType) {
    echo "Union Types: ";
    foreach ($returnType->getTypes() as $type) {
        echo "{$type->getName()} ";
    }
}
```

在本示例中，`myMethod` 方法的返回类型声明为 `string|int`，这是一个联合类型。我们使用反射来检索并显示返回类型信息，如果存在联合类型则一并显示。

### 7.5.3. 改进的参数反射

PHP 8 还增强了 Reflection API 中的参数反射功能。您现在可以使用 `isDefaultValueAvailable()` 方法来检查参数是否有默认值，并使用 `getDefaultValue()` 在可用时检索默认值。以下是一个示例：

```php
function myFunction(int $param1, string $param2 = 'default') {}

$reflectionFunction = new ReflectionFunction('myFunction');
$parameters = $reflectionFunction->getParameters();

foreach ($parameters as $parameter) {
    echo "Parameter: {$parameter->getName()}";
    if ($parameter->isDefaultValueAvailable()) {
        echo "Default Value: {$parameter->getDefaultValue()}\n";
    }
}
```

在本示例中，我们定义了一个带有参数的函数 `myFunction`，其中一个参数具有默认值。我们使用反射来访问并显示有关参数的信息，包括它们的名称和默认值。

PHP 8 对 Reflection API 的改进使其成为动态检查和操作代码的宝贵工具。无论您需要处理命名属性、联合类型还是参数默认值，Reflection API 都为您提供了有效的手段。

# 第 8 章：PHP 8 进阶特性

### 8.1. 参数列表中的尾随逗号

PHP 8 引入了一项虽小却影响深远的语法改进：在函数和方法调用的参数列表中使用尾随逗号的能力。这一看似微小的变化可以显著提高代码的可读性和可维护性，尤其是在处理冗长的参数或属性列表时。

设想这样一个场景：您有一个包含多个参数的函数调用，并且想要添加或移除一个参数。如果没有尾随逗号，修改列表容易出错，因为您需要确保正确调整逗号并保持适当的格式。有了尾随逗号，这变得更加简单。

让我们通过一些示例来更好地理解这一概念。

#### 8.1.1. 函数调用

在 PHP 7 及更早版本中，带有多个参数的函数调用可能如下所示：

```php
$result = calculateTotal($price, $quantity, $discount);
```

如果您想添加另一个参数，必须记得在最后一个参数后添加逗号：

```php
$result = calculateTotal($price, $quantity, $discount, $tax);
```

在 PHP 8 中，您可以使用尾随逗号：

```php
$result = calculateTotal(
    $price,
    $quantity,
    $discount,
    $tax,
);
```

这使得添加或移除参数变得更加容易，无需担心调整逗号，并确保您的代码保持整洁和一致。

#### 8.1.2. 方法调用

同样的概念也适用于方法调用。在 PHP 7 及更早版本中，带有多个参数的方法调用可能如下所示：

```php
$result = $object->performCalculation($value1, $value2, $value3);
```

在 PHP 8 中使用尾随逗号：

```php
$result = $object->performCalculation(
    $value1,
    $value2,
    $value3,
);
```

#### 8.1.3. 数组定义

尾随逗号在数组定义中也受支持。在 PHP 7 中，数组定义可能如下所示：

```php
$data = [1, 2, 3];
```

在 PHP 8 中，您可以使用尾随逗号：

```php
$data = [
    1,
    2,
    3,
];
```

在处理大型数组、配置文件或值列表时，这可能特别有用。

#### 8.1.4. 尾随逗号的优势

在参数列表、方法调用和数组定义中使用尾随逗号的优势包括：

1.  **提高可读性**：尾随逗号使代码更易于直观解析和理解，尤其是在处理冗长的参数列表或数组元素时。
2.  **简化代码维护**：在向列表中添加或移除项目时，尾随逗号降低了引入语法错误的几率，因为您无需担心调整逗号和确保正确格式。
3.  **更清晰的版本控制历史**：尾随逗号有助于减少版本控制历史中不必要的变更。如果没有尾随逗号，对列表的每次修改都可能导致多行代码被修改，从而使有意义的变更更难追踪。
4.  **一致性**：强制使用尾随逗号可以使项目内的代码风格更加一致，因为所有开发人员都能从其提供的改进的可读性和可维护性中受益。

总之，虽然尾随逗号看似是 PHP 8 的一项次要添加，但它们对代码质量、可读性和维护性可能产生重大影响。考虑在您的项目中采用这一语法改进，以享受这些优势并编写更整洁、更易维护的代码。

### 8.2. 使用非捕获捕获

PHP 8 引入了非捕获捕获，这是一项增强代码中异常处理方式的特性。此特性允许您捕获并处理异常，而无需将其赋值给变量，从而使您的代码更加简洁和易读。

在之前的 PHP 版本中，捕获异常时必须指定一个变量名来捕获异常对象，即使您不打算在 catch 块中使用它。这可能导致代码杂乱，特别是在您只想记录异常或执行某些通用错误处理的情况下。

非捕获捕获提供了一个更优雅的解决方案。你可以使用下划线（`_`）来表明你不想捕获异常对象，而不必将异常赋值给变量。这使你的代码更整洁，并消除了声明未使用变量的需要。

以下是如何在 PHP 8 中使用非捕获捕获：

```php
try {
    // 可能抛出异常的代码
} catch (ExceptionType $exception) {
    // 处理异常
}
```

使用非捕获捕获：

```php
try {
    // 可能抛出异常的代码
} catch (ExceptionType) {
    // 处理异常
}
```

#### 8.2.1. 非捕获捕获的优势

使用非捕获捕获有以下几个优势：

1.  **提高代码清晰度**：非捕获捕获明确表明你对异常对象不感兴趣，减少了代码中不必要的杂乱。
2.  **降低认知负荷**：通过省略变量赋值，你使开发者更容易专注于实际的异常处理逻辑。
3.  **消除未使用变量**：非捕获捕获防止了未使用变量的创建，这在代码质量和可维护性方面可能是一个问题。
4.  **增强可读性**：catch 块中没有变量名使代码更简洁、更易读，提高了整体代码质量。
5.  **强制最佳实践**：使用非捕获捕获鼓励异常处理中的最佳实践，强调了在没有不必要变量干扰的情况下进行适当错误处理的重要性。

#### 8.2.2. 何时使用非捕获捕获

非捕获捕获在以下场景中特别有用：

*   当你想记录异常日志，但不需要异常对象时。
*   当你有不依赖特定异常类型的通用异常处理逻辑时。
*   当你想强调异常正在被处理，但异常对象本身对当前上下文不重要时。

以下示例演示了在日志记录场景中使用非捕获捕获：

```php
try {
    // 可能抛出异常的代码
} catch (DatabaseException) {
    logError("发生了一个数据库错误。");
} catch (NetworkException) {
    logError("发生了一个网络错误。");
}
```

在这个例子中，我们对异常对象本身不感兴趣；我们只是想根据异常类型记录适当的消息。

总之，当你不需要在 catch 块中捕获和使用异常对象时，PHP 8 的非捕获捕获提供了一种更整洁、更简洁的异常处理方式。此功能增强了代码可读性，并鼓励异常处理中的最佳实践。考虑在你的 PHP 8 项目中采用它，以实现更优雅和可维护的错误处理。

### 8.3. 探索用于异步编程的 Fiber

异步编程是一种提高 PHP 应用程序性能和响应能力的强大技术。它允许你并发执行多个任务，而不会阻塞主执行线程。PHP 8 引入了 Fiber（纤程），这是一种用于编写异步代码的轻量级高效机制。

#### 8.3.1. 理解异步编程

在深入了解 Fiber 之前，让我们简要了解一下异步编程的概念。在传统的同步编程中，任务是按顺序依次执行的。如果一个任务需要很长时间才能完成，它会阻塞整个应用程序，使其无响应。

另一方面，异步编程允许你启动任务并继续执行其他代码，而无需等待任务完成。当任务完成时，会执行回调，允许你处理结果。这种非阻塞方法对于 I/O 密集型操作特别有益，例如网络请求或数据库查询，因为等待响应是低效的。

#### 8.3.2. Fiber 简介

Fiber 是一种轻量级、协作式多任务处理形式。与由操作系统管理且可能资源密集的线程或进程不同，Fiber 由 PHP 运行时管理，更加轻量。

Fiber 本质上是在单个 PHP 进程内的一个独立执行上下文。你可以把它想象成一个轻量级线程，当它在等待某些事情（例如 I/O 操作）完成时，会协作式地将控制权交还给主程序。

#### 8.3.3. 创建和使用 Fiber

要在 PHP 8 中创建和使用 Fiber，你需要使用 `Fiber` 类。以下是创建 Fiber 并异步执行它的基本示例：

```php
$fiber = new Fiber(function () {
    echo "Fiber started\n";
    Fiber::yield();
    echo "Fiber resumed\n";
});

echo "Main program started\n";
$fiber->start();
echo "Main program resumed\n";
```
