### 20. `IPSec`是是一种防止会话劫持的有效预防措施。哪种 IPSec 模式只加密数据载荷？

**A.** `Transport`

**B.** `Tunnel`

**C.** `Protected`

**D.** `Spoof`

![Image](img/r.jpg) **A.** IPSec 是一种极佳的加密机制，可以在两个端点之间很容易设置，如果适当配置了主机，甚至可以在整个子网之间设置。对于考试，你不需要了解 IPSec 的所有细节（谢天谢地，因为有很多内容要写），但你确实需要了解基础。传输模式（Transport mode）完全不影响数据包头部，仅加密有效负载。它通常用于两个端点之间的安全连接，而隧道模式（Tunnel mode）则创建一个类似 VPN 的连接来保护整个会话。此外，传输模式与传统的网络地址转换 (`NAT`) 兼容。

![Image](img/w.jpg) **B** 是错误的，因为隧道模式封装了整个数据包，包括头部。这通常用于形成 VPN 连接，其中隧道跨越不可信的网络（如 Internet）。由于一些非常显而易见的原因，它与传统的`NAT`不兼容；当数据包通过路由器（或任何为你执行`NAT`的设备）时，数据包中的源地址因为隧道模式而发生变化，从而导致接收端的数据包无效。这个问题有解决方法，通常统称为 NAT 穿透（`NAT-t`）。许多家用路由器利用所谓的`IPSec passthrough`来允许这种操作。

![Image](img/w.jpg) **C** 和 **D** 是错误的，因为它们在 IPSec 的语境下是无效的术语。

### 22. 下述哪个陈述最描述欺骗（spoofing）与会话劫持（session hijacking）之间的比较？

**A.** 欺骗和会话劫持是同一件事。

**B.** 欺骗中断了客户端的通信，而劫持不会。

**C.** 劫持中断了客户端的通信，而欺骗不会。

**D.** 劫持模拟了外地 IP 地址，而欺骗指的是 MAC 地址。

![Image](img/r.jpg) **C.** 会话劫持和欺骗有时会被混淆，尽管它们本不应该这样。`Spoofing`（欺骗）是指攻击机器伪装成它不是身份的过程。无论是通过伪造 MAC 地址还是 IP 地址，其核心思想是网络上的其他系统将像目标系统一样与你的机器进行通信（即建立和拆除会话）。通常这被用于辅助嗅探工作。劫持则是完全不同的物种。在劫持中，攻击者跳入一个已存在的会话，将客户端踢出并欺骗服务器继续交换。在许多情况下，客户端将只需通过另一个会话重新连接到服务器，而无人察觉：服务器甚至不知道发生了什么，客户端只是在另一个会话中重新连接。顺带一下，EC-Council 将会话劫持描述为使用以下步骤：

1. 嗅探客户端和服务器之间的流量。

2. 流量并预测序列号。

3. 预测会话。

4. 向服务器注入数据包。

5. 接管。

![Image](img/w.jpg) **B** 是错误的，因为密钥交换（`IKE`）是产生安全密钥的协议。

![Image](img/w.jpg) **C** 是错误的，因为`OAKLEY`是用于创建主密钥以及数据传输过程中每个会话特定密钥的协议。它在此过程中利用了 Diffie-Hellman 算法。
