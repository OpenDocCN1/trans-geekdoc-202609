
```go
func WithApiKey(key string) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.apiKey = key
    }
}

func WithUserId(id string) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.userId = id
    }
}

func WithTimeout(timeout time.Duration) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.timeout = timeout
    }
}

func WithRetry(shouldRetry bool) ShoppingClientOption {
    return func(c *ShoppingClient) {
        c.shouldRetry = shouldRetry
    }
}
```

让我们演示该模式的两种用法：

```go
client := NewShoppingClient("https://api.shopping.com/v1",
    WithApiKey("my-api-key"),
    WithTimeout(10*time.Second),
)
fmt.Printf("%+v\n", client) // &{endpoint:https://api.shopping.com/v1 apiKey:my-api-key userId: shouldRetry:false timeout:10000000000}

clientV2 := NewShoppingClient("https://api.shopping.com/v2",
    WithRetry(true),
    WithUserId("my-user-id"),
)
fmt.Printf("%+v\n", clientV2) // &{endpoint:https://api.shopping.com/v2 apiKey: userId:my-user-id shouldRetry:true timeout:0}
```

在示例中，我们创建了两个具有不同配置的客户端。我们在每个示例中仅应用了所需的配置，这就是该模式的优势。请记住这一重要的设计模式，因为它在本书后续内容中将变得非常实用。

## 泛型

泛型是一项新特性，在 v1.18 版本中引入。Go 从 1.18 版本开始支持泛型。在语言的重大新增特性中，泛型作为一个突出的概念脱颖而出。

编程中的泛型让我们能够通过以更灵活的方式处理不同类型的数据，来编写灵活且可复用的代码。

### Go 语言中的泛型

本节将介绍 Go 语言泛型的基础知识以及它们与其他语言的不同之处。泛型适用于函数、结构体、接口和映射。Go 语言中的泛型行为与其他语言相似，但存在一些差异。我们假设读者已具备泛型的相关知识。基于此假设，我们将不在此详述泛型的概念。

好的解释始于最简单的示例；以下是一个泛型函数：

```go
func printIt[T any](item T) {
    fmt.Println(item)
}

printIt(1)       // 1
printIt("Hello") // Hello
```

通过使用 `[` 和 `]` 来声明函数的泛型类型，在本例中为 `any`，用 `T` 表示。与其他拥有泛型的语言主要不同的只有 `any` 关键字。每个泛型表示（在前面的示例中为 `T`）都必须实现一个接口或约束。

对于约束，有两个内置约束：`any` 和 `comparable`。

对于接口，Go 团队为我们提供了一个方便的包 `golang.org/x/exp/constraints`，它为泛型提供了常用的约束接口。

1.  **`Any`**：任意类型，意味着每种类型都能满足此约束。

2.  **`Comparable`**：适用于可以应用比较运算符（如 `==` 和 `!=`）的任何类型。映射的键必须是可比较的。

3.  **接口**：我们可以创建自定义接口作为泛型函数的约束；请见下例：

```go
type Number interface {
    int | float64
}

func bigger[T Number, K any](a, b T, prefix K) {
    if a > b {
        fmt.Println(prefix, a)
        return
    }
    fmt.Println(prefix, b)
}

bigger(1, 2, "The bigger integer is:") // The bigger integer is: 2
bigger(3.0, 2.0, "The bigger float is:") // The bigger float is: 3
```

我们声明了一个名为 `Number` 的自定义接口，它使用管道符号 `|` 包含两种类型。其他示例与第一个示例类似。

我们也可以将泛型应用于结构体。为多种类型构建灵活的 `struct` 可能很有优势。让我们以一个存储 `struct` 为例，它可以存储一个项目并获取该项目。

```go
type StorageInter[T any] interface {
    GetItem() T
    StoreItem(T)
}

type Storage[T any] struct {
    Item T
}

func (s *Storage[T]) GetItem() T {
    return s.Item
}

func (s *Storage[T]) StoreItem(item T) {
    s.Item = item
}
```

与上一节讨论的示例相比，前面的代码片段逻辑更复杂。首先，我们声明了一个泛型接口，这在 Go 中是可行的。然后，我们声明了一个简单的泛型结构体，带有一个名为 `Item` 的属性，其类型为 `T`，且 `T` 的约束为 `any`。接着，我们实现了 `StorageInter` 接口的函数签名。为了确保结构体实现了该接口，我们声明了以下行：

```go
var _ StorageInter[int] = &Storage[int]{}
```

值得一提的是，这是一种非常棒的通用做法（无论是否涉及泛型），用于确保结构体满足接口（声明一个空变量 - `_`）。该函数的用法与 Go 中任何结构体的用法相同。唯一的区别是我们需要实例化类型（`[int]`），因为它是泛型。为了更好地理解这一点，让我们讨论以下代码示例：

```go
var intStorage StorageInter[int] = &Storage[int]{}
intStorage.StoreItem(789)
fmt.Println(intStorage.GetItem())

var stringStorage StorageInter[string] = &Storage[string]{}
stringStorage.StoreItem("This is a string")
fmt.Println(stringStorage.GetItem())
```

在前面的两个示例中，我们演示了如何在 Go 中使用泛型 `struct`。在第一个示例中，我们将 `int` 类型应用于 `struct` `Storage`，在第二个示例中，我们将 `string` 类型应用于 `struct` `Storage`。因为 `StoreItem` 函数的签名是 `StoreItem(item T)`，所以我们在第一个示例中可以传递 `int`，在第二个示例中可以传递 `string`。

## 理解 Go 语言中的 Context

在 Go 语言中，Context 是每个 Go 开发者都应了解的核心支柱之一。

Go 团队创建了一个 `Context` 包，帮助我们管理上下文。就这么简单。在幕后，context 是一个结构体。我们只能观察其接口 - `context.Context`（来自 `context` 包），其定义如下：

```go
type Context interface {
    Deadline() (deadline time.Time, ok bool)
    Done() <-chan struct{}
    Err() error
    Value(key any) any
}
```

深入探讨接口签名超出了本章的范围。简单来说，为了理解，我们可以将其分为三个概念：

1.  **管理键值存储**：瞬间之间，我们可以通过键在 context 中保存和检索值。我们可以通过 `context` 包中的函数 `Value(key any) any` 从 context 获取值。

2.  **处理并发**：在下一章中，我们将探讨并发。Context 是一种基本工具，帮助我们利用 goroutine 之间的通信。

3.  **管理任务**：使用 `context`，我们可以通过传递值、取消信号和截止时间（超时）来确保相关任务在需要时能优雅地停止。

要开始使用 `context`，让我们看看如何使用函数 `context.Background()` 从无到有地创建一个 `context`：

```go
ctx := context.Background()
```

如果非必要，我们应避免使用此函数，并努力使用父 `context`。稍后我们将看到如何做到这一点。

正如我们所见，context 的目标之一是充当键值存储。让我们看一个示例，旨在将 API 密钥包含在 context 中。

```go
func main() {
    ctx := context.Background()
    childContext := context.WithValue(ctx, "apiKey", 123456)
    printAPIKey(childContext)
}

func printAPIKey(ctx context.Context) {
    apiKey := ctx.Value("apiKey")
    fmt.Println("API Key:", apiKey) // API Key: 123456
}
```

我们使用了函数 `context.WithValue`，它接收父 context 和键值。注意这些函数接收 `any` 类型作为参数（`any` 是空接口 `interface{}` 的别名）。

Context 服务于多种目的，如任务管理、超时、环境变量等。为了演示 context 的用法，考虑一个任务管理场景，我们必须停止并优雅地终止任务。`Context` 包通过 `WithCancel` 函数提供了解决方案，该函数生成一个用于取消 context 并添加错误的副函数。这使我们能够使用 `WithCancel` 函数优雅地终止任务，并可以使用 `Err()` 函数检索错误。让我们看一个取消 context 的示例以便更好地理解。

```go
contextWithCancel, cancel := context.WithCancel(ctx)
cancel()
fmt.Println("What happened ?", contextWithCancel.Err()) // What happened ? context canceled
```

控制 context 的另一种方式是使用超时。作为演示，我们知道任务必须遵守 30 秒的超时，否则可能会影响我们的数据库。让我们看一个使用函数 `context.WithTimeout(parent Context, timeout time.Duration) (Context, CancelFunc)` 的示例。

```go
contextWithTimeout, _ := context.WithTimeout(ctx, 30*time.Second)
fmt.Println("What happened ?", contextWithTimeout.Err()) // What happened ? <nil>
time.Sleep(35 * time.Second)
fmt.Println("What happened ?", contextWithTimeout.Err()) // What happened ? context deadline exceeded
```

另一个有用的函数是 `WithDeadline`。该函数允许我们定义 context 完成的具体时间。注意 `WithTimeout` 函数在幕后使用了 `WithDeadline` 函数。

```go
func WithTimeout(parent Context, timeout time.Duration) (Context, CancelFunc) {
    return WithDeadline(parent, time.Now().Add(timeout))
}
```

以下是使用 context 时的最佳实践：

### Context 最佳实践

*   **避免使用** `Background()`：我们应致力于从父 Context 启动一个新的 Context，而不使用 `context.Background()`。我们不想打破当前的生命周期并启动一个新的。我们通常在程序启动时使用此函数。

*   **并发最佳实践**：将在后续章节中讨论。

*   **显式传递 Context**：我们应致力于将其作为参数在函数间传递，而不将其用作全局变量。

*   **优先使用 Cancel 而非 Timeout**：我们始终致力于使用手动取消而非自动取消。手动取消与自动取消的区别在于 `context.WithCancel` 和 `context.WithTimeout` 之间的差异。

所有这些最佳实践引导我们进行 Context 传播。

Context 传播涉及持续地传递上下文信息（通常通过函数参数），以在程序或系统的执行过程中保持相关数据。Context 传播确保上下文细节在代码的不同部分之间无缝流动。

我们必须避免使用全局环境变量，或反复将同一字段或结构体通过许多函数传递。Context 传播在代码的不同逻辑之间创建了层级关系。例如，如果我们处理一个事件，该事件会触发其他几个子事件。子事件需要来自父 Context 的所有键值项，但每个子事件需要不同的超时时间。这个例子证明了层级关系至关重要。

正如所讨论的，Go 团队发明这门语言的初衷是为了在云端运行。怀揣这一想法，Context 显得至关重要。在云环境中工作时，服务间的通信非常频繁。在微服务架构中，这种通信变得更加频繁。

在微服务架构中，每个服务都依赖于其他服务或第三方服务的依赖。Context 传播对于传输这些信息至关重要，这些信息可以是认证和授权数据、可观测性数据（追踪、日志）、请求元数据等。

## 错误 —— 谈谈错误传播

错误处理对任何编程语言都至关重要且必不可少。本节将讨论使用 Go 进行错误处理的用法和实现。

错误处理在 Go 中至关重要，特别是在微服务架构中开发代码时。为什么呢？

当我们遇到 Bug（这会大量发生）时，我们必须做好准备并建立适当的基础设施来调查 Bug。最令人恼火的是在调查 Bug 时“两眼一抹黑”。我们在编写代码时能做的最好准备，就是进行令人满意的错误处理。

有时，错误可以在许多服务之间传播——例如，一个服务调用内部 API 失败（由于其内部原因）。乍一看，Bug 在该服务中，但实际上 Bug 在 API 中。如果错误处理做得正确，我们能迅速明白这一点！

Go 中默认的错误值是 `nil`，`error` 是 Go 中的一种类型。在 Go 中有三种创建错误类型的方法：

第一种方法是使用 `fmt` 包，如下所示：

```go
err := fmt.Errorf("a height of %0.2f is invalid", -2.3333)
fmt.Println(err.Error()) // a height of -2.33 is invalid
```

该示例非常直观。要使结构体成为错误类型，它必须包含 `error` 类型的方法，其签名为 - `Error()`。该函数将错误作为字符串返回。注意仅在你知道错误不为 nil 时使用它。否则，它会 panic。在 Go 中创建错误的第二种方法是使用 `errors` 包，如下所示：

```go
err = errors.New("this is an invalid height")
fmt.Println(err.Error()) // this is an invalid height
```

它的效果与第一个示例相同，但更简洁。在某些场合，按照惯例会使用这种风格而非第一种。我们将在后续章节详细阐述该惯例。在 Go 中创建错误的第三种方法是通过自定义错误类型。我们需要声明一个结构体，且该结构体应有一个名为 `Error()` 并返回字符串的方法。让我们观察一个示例：

```go
type ApiError struct {
    Path       string
    StatusCode int
}

func (e *ApiError) Error() string {
    return fmt.Sprintf("API error: %s returned a %d", e.Path, e.StatusCode)
}

func main() {
    err = &ApiError{Path: "/api/users", StatusCode: 500}
    fmt.Println(err.Error()) // API error: /api/users returned a 500
}
```
