
您可能遇到的另一种认证选项是 `knowledge-based authentication (KBA)`（基于知识的认证）。KBA 经常以安全问题的形式用于密码重置。基于知识的认证问题也用于验证创建账户的用户，方法是动态生成账户请求者预期知道的问题。一个例子是在登录美国国税局（IRS）网站时，询问您上一年的纳税申报金额。国税局知道您应该已经知道此信息，而且极少数其他人应该知道。银行和其他机构将使用类似的问题，涉及抵押贷款余额、以前的地址或其他详细信息，以帮助验证您的身份。

在任何 KBA 实施中，重要的是他人无法轻易发现答案，答案是唯一的，并且答案是用户应该能够轻松记住或很可能知道的事情。密码问题越来越多地摒弃了询问您最喜欢的宠物或第一辆汽车等固定的特定问题，因为这些信息更有可能通过社交媒体或其他方法被找到。允许用户设置自己的问题或询问更冷门的信息是一个更安全的选项。

#### 管理认证

管理密码和其他认证数据可能具有挑战性，尤其是当您运营一个拥有大量设备和账户的大型企业时。

对于个人而言，提供高级别安全性的一种选择是 `password key`（密码密钥，通常称为安全密钥）。这些是支持一次性密码、用于安全证书的公钥加密以及 FIDO 和通用第二因子（U2F）等各种安全协议的硬件设备。它们有多种外形规格和不同类型的连接方式；大多数提供 USB 和/或蓝牙。

`Password vaults`（密码保管库，通常称为密码管理器）是认证管理的另一种常见解决方案。它们是存储、管理和保护密码及其他信息的软件解决方案，允许用户使用强密码，而无需记住数十个甚至数百个单独的复杂密码。企业密码管理器应用程序在组织中广泛部署，以帮助管理服务器、应用程序和设备，它们还具有日志记录和审计等附加功能，以及管理工具以确保密码得到适当轮换并监控使用和滥用情况。

计算机还可以拥有内置或附加的安全模块，如 `Trusted Platform Module (TPM)`（可信平台模块）标准。TPM 模块或芯片具有内置的加密处理器，用于存储由系统所有者设置的密码保护的 RSA 密钥对。TPM 模块可以帮助防止未经授权的固件和软件更改，作为可信或安全启动过程的一部分，并且它们受操作系统支持，允许驱动器加密和其他基于加密的安全功能。虽然一些系统（包括许多企业级笔记本电脑）内置了 TPM 芯片，但它们也可以作为附加模块添加到支持它们的系统中。

您应该了解的最后一个选项是使用 `hardware security modules (HSMs)`（硬件安全模块）。HSMs 通常以独立的物理设备或计算机的插入式扩展卡的形式出现，集成了加密处理器，以安全地创建、存储和管理加密密钥；提供加密和解密服务；并以安全的方式执行其他加密处理。云提供商现在提供 HSM 即服务，允许以安全的方式将 HSM 添加到云基础设施中。

HSM 设计的一个重要部分是设备本身的安全性，HSM 通常带有第三方安全认证，以证明它们已通过评估和验证，符合 FIPS-140 等标准，即美国政府的加密安全标准。

### 账户

声明身份并获得授权访问系统或服务需要一个账户。账户包含有关用户的信息，包括与账户关联的权利和权限等内容。

#### 账户类型

##### 账户类型和访问控制方案

账户类型繁多，但几乎所有类型都可以归纳为以下几种基本账户类型：

*   **用户账户**，权限范围涵盖从对系统、设备或应用程序的基本访问，到拥有广泛权利和特权的高级用户。
*   **特权或管理账户**，如 Linux 和 Unix 系统上的 `root` 账户或 `wheel` 组成员，以及 Windows 默认的 `Administrator` 账户。
*   **共享和通用账户或凭证**，通常被安全策略所禁止。尽管共享账户可能很有用，但许多组织会构建委派功能，允许多个用户以相同方式或拥有相同权利行事，以避免共享账户问题，例如无法确定是谁登录了共享账户，或共享该账户的每个用户采取了什么操作。
*   **来宾账户**，提供给临时用户，通常具有非常有限的特权，但也很可能几乎没有（或完全没有）使用该账户用户的相关信息。
*   **服务账户**，与应用程序和服务相关联。服务账户不应用于交互式登录，许多组织都制定了特定的安全策略来确保服务账户安全。

#### 账户策略和控制

账户策略旨在提供控制，规定账户如何以及何时可以使用，控制密码复杂度、生命周期及其他细节。让我们探讨几个常见的账户策略设置，这些是你参加 Security+ 考试时需要准备实施的内容。

**密码复杂度**决定了密码的组成。在 MFA（多因素认证）技术广泛实施之前，密码复杂度是最常用的控制措施之一，旨在防止简单密码被暴力破解。密码复杂度设置将规定密码可使用哪些字符、不可使用哪些字符、最小长度、是否可包含单词或包含特定禁用单词，以及决定密码复杂程度的任何相关设置。密码复杂度的权衡在于：要求额外的复杂度可能会降低用户记住密码的可能性，并可能在密码重置支持上花费额外的时间和金钱。复杂度还可能导致用户记录密码（可能存放在不安全的位置），或重复使用复杂密码，以免记忆过多密码。

**密码生命周期**也曾被普遍使用，尽管 MFA 的使用日益增加，导致许多组织不再要求定期更换密码。当密码是账户的唯一保护时，密码生命周期被视为一种限制密码在泄露后最大暴露时间的方法。这引发了关于生命周期与用户行为的各种实验，许多研究指出：要求更换越频繁，密码越有可能只是在旧密码基础上做微小更改。**密码历史记录**设置用于防止**密码重用**。基本的密码历史记录会跟踪管理员设定的特定迭代次数内的过往密码。更高级的密码历史记录系统可能能够识别密码是否与之前的条目过于相似，以确保未使用仅做微小更改的密码。

除了与密码相关的控制外，账户控制还可以利用登录过程中的其他信息。常见控制包括：

*   **一天中的时间**，可防止员工在轮班结束后访问系统，从而潜在地减少攻击者在账户所有者不会察觉时利用账户的机会，或内部人员滥用特权。**基于时间的登录**对于轮班制或小时工更为常见。
*   **正在认证的系统的网络位置**。这有助于防止数据从错误的网络被访问，或通过确保系统仅从受保护网络内部进行认证来帮助维护信任边界。
*   **地理位置数据**可用于仅允许来自地理围栏区域（基于预定 GPS 数据的位置）的登录。地理标记有时也会与此结合使用，以标记可在特定位置使用的特定数据或系统。地理信息还用于判断是否发生**不可能的旅行时间**问题，即用户从一个地点登录，随后又从另一个地点登录，两地距离足以确保用户不可能在给定时间内抵达新位置。此类技术可识别高风险登录，最有可能使用安全信息和事件管理（`SIEM`）工具或类似工具实现，这些工具能协调来自多个系统的数据。

尽管密码控制、地理位置和网络位置设置以及基于时间的控制都有助于确保用户以安全方式登录，但**账户审计**有助于确保账户得到良好管理、账户拥有适当的权限，且已实施适当的控制。账户审计（可能是手动或自动的）侧重于确保账户按预期配置，根据用户角色或组织针对该类账户或用户的规则和标准，拥有适当的权限和权利。

最后，当账户遇到问题时，账户可以被锁定或禁用。账户锁定通常是自动化的，基于错误的登录尝试。锁定可能需要人工干预，也可能在一段时间后自动解锁。经过设定时期后自动解锁的锁定称为**退避算法**，存在各种退避算法设计，旨在减缓或阻止暴力破解攻击者，同时仍允许合法用户有机会登录其账户，而无需联系支持部门。

在因泄露或生命周期变更（如离职或退休）或其他问题导致需要终止账户的情况下，禁用账户是一个重要选项。**禁用账户而非删除账户**可能令人担忧，因为它们可能仍保留特权，如果账户被有意或意外恢复，攻击者可能利用这些特权。因此，账户审计通常会审查禁用账户，以查看其是否得到妥善管理，以及组织是否有重新启用它们的习惯，或是否验证了重新启用的原因。

##### 特权访问管理

**特权访问管理（PAM）**工具可用于处理本节前面提到的管理和特权账户。PAM 工具专注于通过帮助管理员仅指定角色或任务所需的最小特权集，来确保**最小权限**概念得以维持。PAM 工具通常提供更详细、更细粒度的控制；增强的审计能力；以及对特权账户状态的额外可见性和报告。

### 访问控制方案

用户账户和账户控制固然重要，但系统还实施**访问控制方案**，以确定哪些用户、服务和程序可以访问它们托管的各种文件或其他对象。Security+ 考试涵盖许多常见的访问控制方案，我们接下来将进行探讨。

**基于属性的访问控制（ABAC）**依赖于由用户属性驱动的策略。这允许基于属性组合的复杂规则集，授予用户与其拥有的属性相匹配的特定权利。由于属性可以在特定上下文中设置，这也意味着 ABAC 方案可以非常灵活。ABAC 策略的缺点是，由于其灵活性，管理起来也可能非常复杂。

基于属性的访问控制方案对于应用安全非常有用，它们常用于拥有复杂用户角色和权限的企业系统中，这些角色和权限会因用户与系统交互的方式和角色而异。出于类似的原因，它们也用于数据库和内容管理系统、微服务以及 API。

#### 基于角色的访问控制 (RBAC)

**基于角色的访问控制 (RBAC)** 系统依赖于角色，这些角色随后与分配给这些角色的特权相匹配。这使得 RBAC 成为企业的热门选择，企业可以快速使用“收银员”或“数据库管理员”等角色对员工进行分类，并根据这些角色为用户提供对系统和数据的适当访问权限。RBAC 系统归结为三条主要规则：

*   **角色分配**，规定主体只能使用与其被分配角色相匹配的权限。
*   **角色授权**，规定主体的活动角色必须经主体授权。这可以防止主体承担其不应具备的角色。
*   **权限授权**，规定主体只能使用其活动角色被允许使用的权限。

这三条规则共同描述了如何在 RBAC 系统中应用权限。有了这三条规则，就可以构建角色层级，使得特定权限可以根据任何给定环境中的角色在适当的层级上可用。

#### 基于规则的访问控制

**基于规则的访问控制**，有时也称为 RBAC（有时称为 RuBAC 以便将其与基于角色的访问控制区分开），是使用一组规则或访问控制列表 (ACL) 来应用的，这些规则或列表适用于各种对象或资源。当尝试访问某个对象时，系统会检查规则以确定是否允许访问。防火墙规则集是基于规则的访问控制的一个常见示例。

#### 强制访问控制 (MAC)

**强制访问控制 (MAC)** 系统依赖操作系统来强制执行由安全策略管理员设置的控制。在 MAC 实现中，用户没有能力授予对文件的访问权限，或以其他方式更改集中设置的安全策略。MAC 实现曾仅存在于政府和军事系统中，但现在它们可以在特定的高安全系统中找到，如 `SELinux`，以及 Windows 中的 `强制完整性控制 (MIC)`。总体而言，与自主访问控制相比，MAC 实现仍然相对罕见。

#### 自主访问控制 (DAC)

**自主访问控制 (DAC)** 是一种许多人从自家 PC 就习惯了的访问控制方案。最常见的自主访问控制类型为文件和目录等对象分配所有者，然后允许所有者根据需要将权利和权限委派给这些对象。Linux 文件权限提供了一个简单的示例。文件（或目录）的所有者可以设置适用于所有者、组或其他人的权限，并可以选择允许文件被读取、修改或执行。

#### 具体的访问控制实现

除了访问控制方案外，Security+ 考试大纲还涵盖了两种你需要熟悉的具体访问控制系统实现：

*   **特权访问管理** 是用于处理提升账户和权利的特权的一组控制、工具和流程。管理员、root 或类似的高级账户需要被管理和保护。管理管理和特权账户通常始于确保强制执行最小权限，仅为用户和账户提供执行其工作所需的权利。PAM 解决方案可以部署来管理和控制这些账户，作为风险降低策略的一部分。
*   **条件访问** 描述了在允许访问数据、网络或其他资源之前，测试设备和用户安全状态的过程。Microsoft 已通过 `Active Directory` 和 `Intune` 实施了条件访问控制，但其他控制方案也符合此描述。条件访问的优势在于，它不仅仅寻找权限来提供访问控制。相反，你需要既拥有访问对象的权限或权利，又拥有足够安全或受信任、能够访问该对象的系统或设备。

##### 文件系统权限

### 总结

身份是组织安全的关键要素。认证是通过提供一个或多个因素（包括你知道的、你拥有的或你本身的特征）来证明你对身份的声称的过程。授权为经过认证的用户提供完成其角色所需的特权和权利。用户账户范围从来宾和普通用户到服务账户和特权管理账户。账户策略规定了每个账户的细节和要求，包括何时应锁定或禁用账户。

组织中部署了各种认证方法和技术。本地技术包括 `TACACs+`、`Kerberos`、`EAP`、`CHAP`、`802.1x`，常见的云认证和授权技术包括 `OAuth`、`OpenID` 和 `SAML`。单点登录允许用户登录一次并在许多系统中使用其身份，而联合身份认证使用身份提供者来认证用户，然后这些用户可以在各种服务提供者和信赖方位置使用这些身份，而无需在那里拥有不同的身份。当资源考量发挥作用时，会使用认证、授权和审计 (AAA) 系统（如 `RADIUS`），因为它们除了跟踪用户认证和授权外，还跟踪使用情况。

### 多因素认证与访问控制

多因素认证有助于限制密码相关的问题，例如密码窃取、重复使用和暴力破解攻击。生物识别认证利用指纹、视网膜扫描或面部识别等身体特征，已变得司空见惯，但了解它们错误地允许错误人员进入或拒绝合法用户的频率至关重要。

认证管理工具如密码保管库（或保险箱）、安全密钥和密码密钥，以及专用硬件设备如 `Trusted Platform Modules (TPM)` 和硬件安全模块 (`HSM`) 提供加密处理和存储，以保障系统安全。

访问控制方案如基于属性的访问控制、自主访问控制、强制访问控制和基于角色的访问控制，都提供了确定主体可对客体执行哪些操作的方法。特权访问管理确保管理员用户得到妥善管理，而条件访问系统确保用户在使用其特权时是从安全的系统进行连接。

### 考试重点

**身份标识是认证和授权的基础。** 用户通过认证过程声明身份标识。除了用户名，身份标识通常还通过证书、令牌、`SSH` 密钥或智能卡来声明，它们各自提供额外的功能或特性，有助于安全或其他有用功能。身份标识使用属性来描述用户，各种属性（如工作、职位，甚至个人特征）作为该用户身份标识的一部分存储。

**认证技术用于保护系统和服务。** 如今广泛使用各种认证技术。可扩展认证协议 (`EAP`) 正如其名所示旨在可修改，这意味着 `EAP` 实现被用于许多环境中。`Kerberos`、`CHAP`、`TACACS+` 和 `802.1x` 都是你可能遇到的认证协议；`PAP` 不再广泛部署。`SAML`、`OAuth` 和 `OpenID` 对于网站以及云和互联网服务及提供商的认证和授权互操作至关重要。

**账户类型和账户策略决定用户能做什么。** 用户账户类型包括普通用户、来宾、管理员（特权）账户和服务账户。账户通过账户策略进行控制，这些策略决定密码复杂度、历史记录和重用，以及账户是否可在特定时间、从特定位置使用，或账户是否有其他要求。账户也可以通过在不再需要或可能不安全时禁用它们，或在认证失败时将其锁定来保护，以帮助防止暴力破解攻击。

**许多不同的认证方法和技术用于确保用户可以声明身份标识。** 一次性密码可能使用基于 `HOTP` 的迭代事件算法，或基于 `TOTP` 的时间算法，两者都可以通过硬件令牌或软件应用程序交付。一次性密码也经常通过 `SMS` 推送提供。生物识别作为“你是谁”因素，在移动设备和其他系统中越来越普遍，指纹和面部识别已得到广泛采用。作为安全专业人员，你需要了解广泛的认证因素，为什么在特定情况下可能选择或避免使用每一种，以及为什么多因素认证在许多环境中是一项关键的安全控制。

**访问控制方案决定账户拥有什么权限。** 重要的访问控制方案包括基于属性的访问控制 (`ABAC`)，它利用用户属性来确定用户应获得什么访问权限。基于角色的访问控制 (`RBAC`) 基于角色做决策，而基于规则的访问控制（有时也称为 `RBAC`）使用规则来控制访问。除了了解这些访问控制方案外，还应熟悉强制访问控制 (`MAC`)，它依赖系统管理员控制访问，以及自主访问控制 (`DAC`)，它允许用户对其拥有权限的文件和目录做出访问决策。条件访问控制哪些设备可以访问环境，通常基于其安全状态或其他要求。`PAM`（特权访问管理）专注于控制管理员账户。最后，考生还需要知道如何使用和应用常见的文件系统权限。
