
# JSON 编组与解组

JSON 是 JavaScript 值（字符串、数字、布尔值、数组和对象）的编码，以 Unicode 文本形式呈现。它是对基本数据类型和复合类型（数组、切片、结构体和映射）的一种高效且可读的表示。

基本 JSON 类型包括数字（采用十进制或科学计数法）、布尔值（`true` 或 `false`）和字符串，字符串是包含在双引号中的 Unicode 码点序列，使用类似 Go 的反斜杠转义表示法，尽管 JSON 的 `\U`*hhhh* 数字转义表示 UTF-16 码位，而非 rune。

这些基本类型可以通过 JSON 数组和对象递归组合。JSON 数组是值的有序序列，写作用方括号括起来的逗号分隔列表；JSON 数组用于编码 Go 数组和切片。JSON 对象是从字符串到值的映射，写作用逗号分隔、用大括号包围的 `name:value` 对序列；JSON 对象用于编码 Go 映射（具有字符串键）和结构体。例如：

```
boolean            true
number             -273.15
string             "She said \"Hello, \""
array              ["gold", "silver", "bronze"]
object             {"year": 1980,
                    "event": "archery",
                    "medals": ["gold", "silver", "bronze"]}
```

## Movie 示例

考虑一个收集电影评论并提供推荐的应用程序。其 `Movie` 数据类型和典型值列表声明如下。（`Year` 和 `Color` 字段声明后的字符串字面量是*字段标签*；我们稍后会解释它们。）

`gopl.io/ch4/movie`

```
type Movie struct {
    Title  string
    Year   int  `json:"released"`
    Color  bool `json:"color,omitempty"`
    Actors []string
}

var movies = []Movie{
    {Title: "Casablanca", Year: 1942, Color: false,
        Actors: []string{"Humphrey Bogart", "Ingrid Bergman"}},
    {Title: "Cool Hand Luke", Year: 1967, Color: true,
        Actors: []string{"Paul Newman"}},
    {Title: "Bullitt", Year: 1968, Color: true,
        Actors: []string{"Steve McQueen", "Jacqueline Bisset"}},
    // ...
}
```

像这样的数据结构非常适合 JSON，且双向转换都很容易。将像 `movies` 这样的 Go 数据结构转换为 JSON 称为*编组*。编组由 `json.Marshal` 完成：

```
data, err := json.Marshal(movies)
if err != nil {
    log.Fatalf("JSON marshaling failed: %s", err)
}
fmt.Printf("%s\n", data)
```

`Marshal` 生成一个包含非常长字符串的字节切片，没有多余的空白字符；我们折叠了行以便显示：

```
[{"Title":"Casablanca","released":1942,"Actors":["Humphrey Bogart","Ingr
id Bergman"]},{"Title":"Cool Hand Luke","released":1967,"color":true,"Ac
tors":["Paul Newman"]},{"Title":"Bullitt","released":1968,"color":true,"
Actors":["Steve McQueen","Jacqueline Bisset"]}]
```

这种紧凑表示包含所有信息但难以阅读。为了方便人类阅读，一种名为 `json.MarshalIndent` 的变体会生成整齐缩进的输出。两个额外的参数分别定义每行输出的前缀和每级缩进的字符串：

```
data, err := json.MarshalIndent(movies, "", "    ")
if err != nil {
    log.Fatalf("JSON marshaling failed: %s", err)
}
fmt.Printf("%s\n", data)
```

上述代码打印：

```
[
    {
        "Title": "Casablanca",
        "released": 1942,
        "Actors": [
            "Humphrey Bogart",
            "Ingrid Bergman"
        ]
    },
    {
        "Title": "Cool Hand Luke",
        "released": 1967,
        "color": true,
        "Actors": [
            "Paul Newman"
        ]
    },
    {
        "Title": "Bullitt",
        "released": 1968,
        "color": true,
        "Actors": [
            "Steve McQueen",
            "Jacqueline Bisset"
        ]
    }
]
```

编组通过*反射*（正如我们将在第 12.6 节中看到的）使用 Go 结构体字段名作为 JSON 对象的字段名。只有导出字段会被编组，这就是为什么我们为所有 Go 字段名选择了大写字母开头的名称。

您可能已经注意到，输出中 `Year` 字段的名称变成了 `released`，`Color` 变成了 `color`。这是因为*字段标签*。字段标签是一个在编译时与结构体字段关联的元数据字符串：

```
Year  int  `json:"released"`
Color bool `json:"color,omitempty"`
```

字段标签可以是任何字面字符串，但通常被解释为空格分隔的 `key:"value"` 对列表；因为它们包含双引号，字段标签通常使用原始字符串字面量编写。`json` 键控制 `encoding/json` 包的行为，其他 `encoding/...` 包遵循此约定。`json` 字段标签的第一部分为 Go 字段指定了一个替代的 JSON 名称。字段标签常用于为 Go 字段（如 `TotalCount`）指定惯用的 JSON 名称（如 `total_count`）。`Color` 的标签有一个额外选项 `omitempty`，表示如果字段具有其类型的零值（此处为 `false`）或为空，则不应生成 JSON 输出。果然，*Casablanca* 这部黑白电影的 JSON 输出中没有 `color` 字段。

## 解组

编组的逆操作，即解码 JSON 并填充 Go 数据结构，称为*解组*，由 `json.Unmarshal` 完成。下面的代码将 JSON 电影数据解组到一个结构体切片中，该结构体只包含 `Title` 字段。通过这种方式定义合适的 Go 数据结构，我们可以选择解码 JSON 输入的哪些部分并丢弃哪些部分。`Unmarshal` 返回时，已用 `Title` 信息填充了切片；JSON 中的其他名称被忽略。

```
var titles []struct{ Title string }
if err := json.Unmarshal(data, &titles); err != nil {
    log.Fatalf("JSON unmarshaling failed: %s", err)
}
fmt.Println(titles) // "[{Casablanca} {Cool Hand Luke} {Bullitt}]"
```

## GitHub Issues 示例

许多 Web 服务都提供 JSON 接口——发起一个 HTTP 请求，返回的就是 JSON 格式的所需信息。为了演示，我们将使用 GitHub 的 Web 服务接口来查询其问题追踪器。首先我们将定义必要的类型和常量：

`gopl.io/ch4/github`

```
package github

import "time"

const IssuesURL = "https://api.github.com/search/issues"

type IssuesSearchResult struct {
    TotalCount int `json:"total_count"`
    Items      []*Issue
}

type Issue struct {
    Number    int
    HTMLURL   string `json:"html_url"`
    Title     string
    State     string
    User      *User
    CreatedAt time.Time `json:"created_at"`
    Body      string    // Markdown 格式
}

type User struct {
    Login   string
    HTMLURL string `json:"html_url"`
}
```

和之前一样，所有结构体字段的名称都必须首字母大写，即使它们的 JSON 名称不是。然而，在反序列化过程中将 JSON 名称与 Go 结构体名称关联的匹配过程是大小写不敏感的，因此只有当 JSON 名称中包含下划线而 Go 名称中不包含时，才需要使用字段标签。同样，我们在解码时选择了特定的字段；GitHub 的搜索响应包含的信息比我们这里展示的要多得多。

`SearchIssues` 函数发起一个 HTTP 请求并将结果解码为 JSON。由于用户提供的查询词可能包含 `?` 和 `&` 等在 URL 中具有特殊含义的字符，我们使用 `url.QueryEscape` 来确保它们被按字面意思处理。

`gopl.io/ch4/github`

```
package github

import (
    "encoding/json"
    "fmt"
    "net/http"
    "net/url"
    "strings"
)

// SearchIssues 查询 GitHub 问题追踪器。
func SearchIssues(terms []string) (*IssuesSearchResult, error) {
    q := url.QueryEscape(strings.Join(terms, " "))
    resp, err := http.Get(IssuesURL + "?q=" + q)
    if err != nil {
        return nil, err
    }

    // 我们必须在所有执行路径上关闭 resp.Body。
    // （第 5 章将介绍 'defer'，这会让这更简单。）
    if resp.StatusCode != http.StatusOK {
        resp.Body.Close()
        return nil, fmt.Errorf("search query failed: %s", resp.Status)
    }

    var result IssuesSearchResult
    if err := json.NewDecoder(resp.Body).Decode(&result); err != nil {
        resp.Body.Close()
        return nil, err
    }
    resp.Body.Close()
    return &result, nil
}
```

前面的示例使用 `json.Unmarshal` 将字节切片的全部内容解码为单个 JSON 实体。为了多样化，本示例使用了*流式*解码器 `json.Decoder`，它允许从同一个流中按顺序解码多个 JSON 实体，尽管我们这里不需要该特性。正如你所料，还有一个对应的流式编码器叫 `json.Encoder`。

对 `Decode` 的调用会填充变量 `result`。我们有多种方式来美观地格式化其值。最简单的方式由下面的 `issues` 命令演示，即作为一个固定列宽的文本表格，但在下一节我们将看到一种基于模板的更复杂的方法。

`gopl.io/ch4/issues`

```
package main

import (
    "fmt"
    "log"
    "os"

    "gopl.io/ch4/github"
)

func main() {
    result, err := github.SearchIssues(os.Args[1:])
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("%d issues:\n", result.TotalCount)
    for _, item := range result.Items {
        fmt.Printf("#%-5d %9.9s %.55s\n",
            item.Number, item.User.Login, item.Title)
    }
}
```

# 4.6 文本和 HTML 模板

前面的示例仅演示了最简单的格式化，对此 `Printf` 完全足够。但有时格式化必须更加复杂，并且最好将格式与代码更彻底地分离。这可以通过 `text/template` 和 `html/template` 包来实现，它们提供了一种将变量值替换到文本或 HTML 模板中的机制。
