#### 混合密码学

非对称密码学有一个主要缺点；它比对称密码系统慢得多。因此，非对称密码系统主要用于加密少量数据，例如信用卡号。幸运的是，有一种更好的方法可以结合对称和非对称密码学，以获得两者的优势。所使用的技术称为混合密码学。假设发送方（Alice）想要在没有预先共享的密钥的情况下加密并发送一条长消息给接收方（Bob）。Alice 使用一种（快速的）对称密码系统来选择一个随机密钥并加密明文。然后 Alice 使用 Bob 的公钥加密这个密钥。Alice 将密文和加密后的密钥发送给 Bob。Bob 使用他的私有解密密钥解密该密钥，然后使用解密后的密钥解密密文。非对称密钥用于加密短密钥，而速度快得多的对称密钥用于加密较长的明文。因此，混合密码学（几乎）实现了对称密钥密码学的效率。在发送方和接收方之间没有预定密钥的情况下，可以使用混合密码学 [73]。

#### 同态密码学

“同态”一词最早由 Rivest、Adleman 和 Dertouzous 于 1978 年提出，作为一种无需解密即可进行加密的可能解决方案。同态加密是一种密码系统，用户可以在加密数据上进行计算。同态技术提供了数据隐私，因为它在处理数据时不会发生数据泄露，且数据只能由持有私钥的人访问 [1]。同态加密仍处于发展阶段。

##### 椭圆曲线密码学

椭圆曲线密码学是公钥密码学中的一种方法，基于有限域上椭圆曲线的代数结构 [45]。Neal Koblit 和 Victor S. Miller 于 1985 年分别独立建议在密码学中实现椭圆曲线 [45]。

椭圆曲线密钥是使用椭圆曲线方程计算的，密钥尺寸较小，占用内存空间较少，与 RSA 密码学相比速度更快 [23, 45]。椭圆曲线密钥交换 (`ECKE`) 可用于不安全信道上的通信 [16]。

椭圆曲线密码学的优势在于使用 164 位密钥即可实现安全性，这意味着它比 RSA 和 Diffie-Hellman 算法更安全，同时消耗的功率更低，从而使便携设备电池的利用更加高效 [23]。椭圆曲线密码学的缺点是其加密消息尺寸、算法的复杂性，以及与 RSA 相比实现起来更具挑战性 [23]。

##### 零知识证明

零知识证明和知识证明是识别密码的先进方式，也是密码学中的强大工具 [66]。在零知识证明系统中，验证者被证明者说服，确信某陈述为真，而无需披露实际信息，仅通过验证断言即可。进一步解释，“证明”或“证明系统”是双方之间的一种交互式协议，其中一方（证明者）试图说服另一方（验证者）某个给定陈述为真 [51]。证明者展示其知晓满足给定论证（证明性或知识性）的秘密值，而不向验证者透露该秘密（零知识性） [8]。

要被视为零知识证明，必须满足以下标准 [39]：

*   **完整性**：如果证明者的陈述为真，验证者将被说服。
*   **可靠性**：如果证明者的陈述为假，验证者不会被说服。
*   **零知识性**：如果信息为真，验证者除获知证明者的陈述为真外，不会获得任何其他信息。

## 哈希函数

哈希是区块链网络的基础。哈希函数将任意大小的输入文件、文本或图像转换为固定长度的加密输出。这种技术称为哈希。哈希允许用户随机选择输入数据，对数据进行哈希运算并获得相同的输出。即使输入发生微小变化，也会导致截然不同的输出 [33, 81] (图 2.2)。

### 哈希是如何工作的？

一串固定长度的数字和字母序列，它与输入不匹配，从而产生一个加密值，被称为**哈希**或**哈希值**。使用固定长度的输出增加了保护，因为任何试图解码哈希或破坏区块链的人，仅通过查看输出长度都无法预测输入是长还是短。

解哈希始于区块头中的可访问数据，因此也就是解决一个数学难题。每个区块头包含版本号、时间戳、前一个区块的哈希、默克尔根哈希、随机数和目标哈希。为了解决这个数学难题，区块创建者可能需要多次尝试，以决定使用哪串数字作为随机数。随机数是一串任意数字，它被应用到前一个区块的哈希上，然后再次进行哈希运算。如果哈希后的输出小于或等于目标哈希，则被批准为该难题的解，并将该区块添加到区块链中。构建满足目标哈希要求的哈希越复杂，解决该难题所需的时间就越长 [33]。

### 哈希函数用在哪里？

加密哈希函数在区块链上用于许多活动。部分活动列举如下 [81]：

*   **保护区块头**：发布节点对区块头进行哈希运算。如果区块链网络使用工作量证明共识模型，发布节点会使用不同的随机数值对区块头进行哈希运算，直到满足难题规范。然后，当前区块头的哈希输出被存储在下一个区块的区块头中，从而保护当前区块头的数据。
*   **保护区块数据**：发布节点对区块数据进行哈希运算，哈希输出被存储在区块头中 [81]。
*   **用于地址派生**：地址是一串简单的字母数字字符，作为转账中的“收款方”和“付款方”地址。地址是通过区块链网络用户的公钥，使用加密哈希函数并结合一些附加数据（如版本号或校验和）获得的 [81]（图 2.3）。

### 哈希函数的安全属性

*   **原像抗性**：这意味着哈希函数是单向的。对于给定的输出值，要在计算上确定输入值非常困难。例如，对于给定的摘要，如果 `hash(x) = digest`，则不可能找到 `x` 的值。
*   **第二原像抗性**：这意味着无法识别出具有特定输出的输入。加密哈希函数的构造方式使得，对于特定的输入，要在计算上找到一个产生相同输出的第二个输入值非常困难。例如，对于给定的 `x`，如果 `hash(x) = hash(y)`，则不可能以任何成功概率找到 `y`。
*   **抗碰撞性**：这意味着在计算上很难找到产生相同输出值的两个输入。例如，如果 `hash(x) = hash(y)`，则不可能找到 `x` 和 `y` [81]。
*   **非局部性**：这意味着在非局部哈希函数中，相似的输入会产生截然不同的输出。
*   **大状态空间**：哈希碰撞只能通过暴力搜索来确定。根据鸽巢原理，暴力搜索涉及测试尽可能多的输入。这个数字应该足够大，以使暴力搜索变得困难 [60]。

对哈希算法的成功攻击，是指能够违反该哈希函数任一安全属性的攻击。由于哈希函数产生的位长度较短，所有安全哈希函数都容易受到通用攻击。针对哈希函数的攻击包括暴力攻击、生日悖论攻击、差分攻击和长度扩展攻击 [5]。

### 哈希函数的实际应用

*   **密码验证**：大多数网站将密码以哈希形式保存，因为以明文形式保存密码被认为是不安全的。每当用户输入密码时，系统会对其进行哈希运算，并将输出与组织服务器上保存的哈希值集合进行比对。
*   **签名生成与认证**：签名认证是一种用于验证数字签名或消息完整性的加密方法。有效的数字签名为接收者提供了明确证据，证明消息是由已知发送者生成的，且在传输过程中未被篡改。
*   **数据认证与消息完整性**：哈希也用于确保从源发送到接收者的消息和数据在传输过程中未被修改。为实现这一点，源发布其数据的哈希版本和一个密钥，以便接收者可将计算出的哈希值与发布的哈希值进行比对，确保两者匹配 [32]。

### 常见加密哈希函数

**MD4** 由 Ronald L. Rivest 于 1990 年设计 [61]。它将长度短于 `2⁶⁴` 位的输入消息转换为 128 位输出。它是第一个允许在 32 位处理器上高效使用逻辑运算和整数计算的加密算法。密码学家 Dobbertin 使用代数和优化方法攻击 MD4，导致出现“碰撞”。除几十字节外，整个消息都处于攻击者的控制之下。在 Den Boer 和 Bosselaers 发起攻击后，Rivest 立即建议了一个名为 MD5 的改进变体 [76]。

**MD5** 由 Ronald L. Rivest 开发，他也设计了 MD4 [61]。MD5 算法使用可变长度的输入消息并产生 128 位输出 [60]。输入消息被分割成 512 位块。输入消息经过填充，使其总长度能被 512 整除。根据需要添加尽可能多的前导零，以将消息长度最大化至比 512 的倍数少 64 位。剩余位填充 64 位，表示原始消息的长度。MD5 算法在 128 位状态下运行，分为四个 32 位字，映射到一组固定常量。然后算法利用 512 位消息块来改变状态 [59]。

MD5 算法在 32 位处理器上具有快速优化，包含 64 次操作，分为四轮，每轮 16 次操作 [61]。这些操作基于非线性函数、模加和左旋转 [59]。与 MD4 相比，MD5 更安全，但比 MD4 慢 [41]。Boer 和 Bosselaers 证明了 MD5 不具备抗碰撞性 [76]。

MD4 和 MD5 在工业和军事领域都有广泛应用 [41]。尽管 MD5 容易受到攻击，但它仍被用作数据认证的校验和，以防止无意的欺诈。MD5 摘要用于区块链应用中，以保证文件在传输过程中未被修改。文件服务器拥有文件的 MD5 校验和，以便用户将该文件的校验和与接收到的文件进行匹配 [59]。

#### SHA-256

**SHA-256**：SHA-256 由美国国家安全局（NSA）开发。缩写“SHA”代表安全哈希算法，“256”代表 256 位输出，即 32 字节 [75]。SHA-256 将长度短于 2⁶⁴ 位的输入消息转换为 256 位输出 [61]。它是对数字数据执行的一种数学函数。为了确认数据完整性，需将计算出的哈希值与预期的哈希值进行比较 [75]。该哈希函数的主要特性是抗碰撞性，要找到一次碰撞，该算法大约需要运行 2¹²⁸ 次 [81]。然而，MD4 和 MD5 均不具备抗碰撞性 [76]。

SHA-256 被用于许多区块链实现中 [81]。它用于比特币协议的各种功能，如比特币挖矿、默克尔树和比特币地址生成 [75]。

##### 比特币挖矿

当区块创建者必须生成前一个区块哈希时，会使用 SHA-256 [74]。为了生成前一个区块哈希，矿工使用以下公式 [75]：

```
Previous Block Hash = SHA-256 (SHA-256 (Block Header))
```

##### 比特币地址生成

公钥是比特币地址的基础。该密钥先由 SHA-256 哈希，再由 RIPEMD160（160 位竞赛完整性原语评估消息摘要）哈希。创建比特币地址的公式为 [75]：

```
Bitcoin Address = RIPEMD160 (SHA256 (Public Key))
```

SHA-256 还用于创建安全套接字层（SSL）证书。这些证书用于建立和验证网站及在线服务的安全通信。在 SSL 证书中，加密组件由 SHA-256 创建。服务器与互联网服务提供商（ISP）之间的安全连接称为“SSL 握手”。信用卡号、登录详情及其他机密数据通过该链接受到 SHA-256 的保护。在该过程中，SHA-256 对所有用户信息进行哈希运算 [75]。

## 默克尔树

默克尔树由拉尔夫·默克尔构想 [82]。罗伯特·默克尔于 1979 年为默克尔树申请了专利。默克尔树通过为整组交易创建数字指纹，记录区块中的所有交易 [64]。默克尔树类似于书籍的索引部分，因为它们允许用户检查某笔交易是否包含在区块中。使用默克尔树的一些哈希函数示例包括 SHA-0、SHA-1、SHA-2、RIPEMD 和 RIPEMD-160 [6]。

### 默克尔树的工作原理

默克尔根或根哈希是通过持续哈希成对节点以生成默克尔树而留下的哈希值 [64]。默克尔树中的每个节点都是一个哈希值 [82]。节点分为两类：叶子节点和非叶子节点。叶子节点是单笔交易的哈希值，非叶子节点是前一个哈希值的哈希值。因为默克尔树是二叉的，所以需要相等数量的叶子节点。如果交易数量为奇数，则最后一个哈希值会被复制，直到产生偶数个叶子节点 [64]。

在 图 2.4 的一个区块中有四笔交易：A、B、C 和 D。每笔交易被哈希后存储在叶子节点中，分别为哈希 A、哈希 B、哈希 C 和哈希 D。通过分别哈希哈希 A 和哈希 B、哈希 C 和哈希 D，顺序成对的叶子节点被汇总，从而产生哈希 AB 和哈希 CD。哈希 AB 和哈希 CD 称为父节点。然后通过哈希哈希 AB 和哈希 CD（称为哈希 ABCD）来创建默克尔根。默克尔根随后存储在区块头中，用于检测交易数据是否被修改，从而维护数据完整性 [82]。如果进行了任何修改，默克尔根也会随之改变 [64]。

### 默克尔树的优势

默克尔树减少了对大量内存空间的需求；通过认证数据来证明完整性，且计算快速简便。区块链矿工/验证者在从其他成员接收交易时，可以稳定地计算哈希值。此外，区块链用户可以验证区块中的交易。因此，默克尔树管理只需在网络中分发少量信息 [64]。

## 数字签名

数字签名是传统手写签名的电子表示形式。数字签名用于证明数据已由声称的“签名人”签署，并可用于确定数据在签署后是否被修改。该签名由计算机中的一系列比特组成，可针对传输的数据或从存储中恢复的数据创建。

*   **声称签名人**：在签名信息经过认证、确认签名人真实身份之前，签名人被称为声称签名人。
*   **密钥对持有者**：签名人也称为密钥对持有者，因为他们拥有一对公钥和私钥。
*   **预期签名人**：打算在未来生成签名的个人或组织称为预期签名人 [29]。
