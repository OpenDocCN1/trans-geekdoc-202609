
此时，客户端发送给 TGS 的消息包含两个部分。第一部分是`TGT`，它仍然使用密钥进行加密。第二部分是`authenticator`，它包含客户端 ID，并使用 TGS 会话密钥（TGS 目前尚不知道该密钥）进行加密。由于 TGS 拥有该密钥，因此它能够无问题地解密`TGT`消息。它将使用在该条消息中找到的`TGS session key`副本来解密`authenticator`。现在 TGS 能够读取这两条消息了，它将执行几个步骤，例如验证票据是否过期以及`authenticator`是否已经存在。现在 TGS 准备两条消息，其方式与客户端最初的操作类似。其中一条消息将包含服务会话密钥，该密钥使用`TGS session key`加密；另一个消息将包含一个服务票据，其中包含服务会话密钥的副本，并使用服务密钥加密。客户端将能够使用存储的`TGS session key`解密第一条消息，但无法解密第二条。

客户端将再次为服务准备两条消息。第一条是服务票据，它仍由服务密钥加密；第二条消息是`authenticator`，它包含客户端数据并由服务会话密钥加密。请求的服务将使用其服务密钥解密服务票据，从而显示服务会话密钥，并使用该密钥来解密`authenticator`。最后，如果所有用户和时间戳检查通过，服务将向客户端返回它自己的`authenticator`，其中包含用服务会话密钥加密的服务 ID。由于客户端机器已拥有此密钥，它将解密该`authenticator`消息并验证服务 ID。从现在开始直到票据过期，客户端可以使用缓存的服务票据继续访问服务。

Kerberos 已使用几十年，你需要了解关于其用法的一些关键点。KDC 数据库对于整个 Kerberos 系统的完整性至关重要。未能保护此资源免受未经授权的访问将使你的组织面临巨大风险。此外，Kerberos 是一种必须由网络中的每个节点支持的解决方案。只有在所有服务器、服务和客户端都“感知 Kerberos”并支持加密交换的网络中，Kerberos 才有用。时间在整个 Kerberos 身份验证过程中起着主要作用。在所有的交换中，时间戳都是验证过程的一部分。整个过程涉及多个设备，这意味着所有时钟都需要同步。如果时钟偏差过大，Kerberos 将无法正常身份验证。在微软的 Kerberos 实现中，此值可以在策略的“计算机时钟同步最大容忍度”设置中设置。最佳实践规定此值不超过五分钟。

## 服务

伪装成服务是诱骗用户提供敏感数据的有效方法。在用户级别，检测虚假服务极其困难。然而，根据网络环境，有相应的解决方案来确保服务的真实性。为了防止流氓服务的滥用，微软的 .NET Framework 有一个名为“服务身份和验证”的功能。Windows 通信基础 (WCF) 基础设施将确保所请求服务的身份值与预设值匹配。图 12-2 显示了 WCF 中身份元素的语法。当客户端尝试使用此功能连接到服务时，它将首先执行任何已有的标准身份验证程序。一旦服务成功验证了客户端机器，它将会将名为`endpoint identity`的存储值与服务在交互期间提供的值进行比较。如果这些值匹配，客户端机器就可以访问该服务。身份值的元素包括证书信息、DNS、RSA 值、服务名称和用户名。这本质上是后台发生的第二次身份验证过程。

## 角色

你可能记得我们在第 3 章中讨论过基于角色的访问控制。例如，一个博客用户可能拥有用户名“tony”并被分配“编辑者”角色。另一个名为“karen”的用户可能拥有“管理员”角色。每个用户可能同时拥有多个角色（例如：贡献者、编辑者和批准者），每个角色将允许访问某些资源。这些访问控制级别基于用户为了履行组织内职责需要执行的必要操作任务。这种方法可能会很复杂，因为管理员在配置访问控制时必须将组织授权策略翻译为权限。随着环境中对象和用户数量的增加，用户不可避免地会被授予某些对象的非必要访问，从而违反了最小权限原则并增加了公司的风险。

攻击者经常会尝试根据角色确定哪些用户具有特权权限。有时，拥有特权角色的用户可能并没有意识到这些特权，这产生了安全问题。角色审计应该是你的评估的一部分，以确保用户只获得其任务所需的角色。

**注意** 在大多数情况下，角色与身份相关联，而不是直接进行身份验证。你可以将其认为是身份的扩展，描述可以执行何种活动。这种关系可能是一对多的关系，意味着一个单一身份可以拥有多个角色，并根据任务调用所需的权限。

## 应用程序

应用程序是寻找进入系统方法的恶意攻击者的不断目标。设计供公众访问的 Web 应用程序将限制公共用户查询或执行的内容。攻击者经常会尝试操纵这些应用程序的输入以实现`权限提升`，即获得对目标应用程序或操作系统的提权访问权限。成功的攻击通常是软件缺陷或配置错误的结果。我们可以利用之前在第 5 章和第 6 章中讨论的漏洞评估原则来识别并处理这些漏洞。

### 与身份存储库相关的安全问题

身份库是任何存储验证用户网络访问所需凭据的资源。攻击者经常针对身份存储库以添加或更改用户属性。常规监控这些存储库以发现操纵迹象将会提醒你攻击者的存在。

### 目录服务

目录服务服务器本质上是一个用于存储和管理信息的中央存储库。管理员依靠目录服务来提供大规模的管理和安全选项。对于用户而言，目录服务允许他们快速定位网络资源，而无需记住具体的地址。关于网络的几乎任何信息都可以存储在目录服务数据存储器中。用户及其寻求的资源都被分配了唯一标识符，用户通常可以根据这些信息对企业服务和应用程序进行身份验证和授权。目录服务需要具有扩展性，并能够与网络上的各种其他服务良好集成。

### Active Directory (活动目录)

Active Directory (AD) 在许多组织中起着至关重要的作用。作为 Windows 环境的目录服务，AD 允许组织集中管理资源的同时提供网络安全策略。AD 环境中的任何用户、系统、资源或服务都被视为一个`object`，它关联有`attributes`，包括名称和描述。许多针对 AD 环境的攻击者的目标是获取网络立足点，跨系统移动，并最终获得 AD 域控制器的访问。这种访问权限将赋予攻击者对组织相关的所有对象的完全控制权。

保护这些环境两种主要方法是减少 AD 的攻击面和启用审计功能。默认情况下，AD 具有几个特权账户组，如`Enterprise Admins (EA)`、`Domain Admins (DA)`和`Built-in Admins (BA)`。根据最小权限原则 (`POLP`)，你只应在网络上保持必要的管理员数量，并仅赋予日常管理所需的适当权限。改进 AD 安全性的第二种技术是开发事件日志监控系统并启用详细的对象审计。如果启用了正确的审计和报告级别，就可以很早发现许多事件。通过将`Object Access Auditing`等高级功能作为全目录安全策略的一部分，你可以确定敏感对象何时被访问或被更改，并根据需要报告这些更改。默认情况下，此值是不启用的，但当与良好的 SIEM 解决方案结合时，它将为您在损害发生前识别异常网络行为的速度和灵活性。

![Images](img/00005.jpeg)

**考试贴士**：在任何情况下都不应共享对 AD 服务的管理权限。获得 AD 域控制器管理访问的恶意人员对网络拥有完全控制权。即使是具有访问权限的非恶意但缺乏经验的用户，如果他们进行了错误的配置更改，也会导致意想不到的问题。

### LDAP

目前使用的大多数目录服务底层基础是轻量级目录访问协议 (`LDAP`)。LDAP 为在网络上维护目录服务提供了跨平台的开放标准。用户可以查询 LDAP 服务器以根据特定格式的语句获取响应。攻击者可能构造某些语句，触发 LDAP 服务器提供请求者通常未被授权的额外信息——更糟糕的是，让服务器执行任意代码。假设该系统允许请求者仅搜索特定类型的资源——在这种情况下是打印机和存储设备。图 12-3 显示了普通用户及其请求和响应与攻击者提供的响应的对比示例。在合法请求中，用户指定搜索存储设备或打印机。请注意，攻击者格式化其查询的方式使得在被解释时，输入值看起来像 LDAP 命令，并在比用户通常允许的更高的级别上执行。系统根据其对`(uid=\*)`的解释为所有用户提供结果。

### TACACS+

终端访问控制系统加 (`TACACS+`) 是一种由思科在 20 世纪 90 年代提出的身份验证、授权和计费 (`AAA`) 协议。作为 Kerberos 的替代方案，TACACS+ 使用客户端/服务器方法来确定用户访问级别。在连接时，用户与用户数据库进行比较，然后应用策略。在 TACACS+ 中，身份验证、授权和计数功能被视为分离且独立的。尽管它主要设计用于用于设备 AAA，但它也经常用于网络 AAA。尽管非常适合网络 AAA，但 TACACS+ 在其协议中存在一些根本性缺陷。尽管它使用 TCP，但它特别容易受到重放攻击，因为序列号从 1 开始。这意味着攻击者不需要猜测序列在哪里中断的，因为 TACACS+ 系统总是接受从序列号 1 开始的会话。此外，TACACS+ 的会话 ID 相对较短，可能的 ID 池也足够小，容易受到所谓的“生日攻击”或加密哈希函数碰撞的影响。

**注意**：尽管与 TACACS 和 XTACS 共享大部分名称，但较新的 TACACS+ 是一个完全不同的协议，与旧方法不兼容。

### RADIUS

远程认证拨号用户服务 (`RADIUS`) 类似于 TACACS+，因为两种 AAA 协议都为管理员和用户提供身份验证服务。然而，TACACS+ 在身份验证过程中加密用户名和密码，而 RADIUS 只加密用户密码。此外，RADIUS 使用 UDP 而非 TCP，这意味着可靠性可能会取决于网络状态。由于 UDP 是一种尽力而为的传输协议，很难确定事务过程中何时发生了故障。从安全的角度来看，这意味着在欺骗尝试中伪造数据包更容易，因为没有数据包接收的确认。RADIUS 还允许在网络中使用“共享密钥”；因此，如果任何一个弱终端被攻破，整个网络的破解将容易得多。这结合共享密钥缺乏复杂性（或熵），意味着针对密钥的离线攻击更有可能成功。

某些 RADIUS 实现还容易受到*缓冲区溢出*攻击，当过多的数据被强制输入内存空间（或缓冲区）时，产生的额外数据溢出专用内存限制并进入内存的其他区域。针对 RADIUS 系统的此类攻击可用于利用任意恶意代码、泄露敏感用户数据或作为拒绝服务攻击的一部分。

## 与联合和单点登录相关的安全问题

联邦身份（Federated identity）是一种使用个人的数字身份来访问各种服务的概念，且通常跨越多个组织。该身份由称为`federated identity manager`（联邦身份管理器）的经纪人提供。当用户验证其身份时，仅需向管理器进行身份验证，而请求身份信息的应用程序也随需要信任该身份。许多流行平台（如 Google、Amazon 和 Twitter）利用其庞大的用户群为第三方网站提供联邦身份服务，从而省去了用户为每个网站创建单独账户的麻烦。

使用联邦身份提供身份验证通常通过单点登录（SSO）实现。在业务环境中，用户可能需要为电子邮件服务、CRM、目录或其他任何业务 Web 应用程序提供凭据。`SSO`通过要求用户仅维护一套凭据，简化了登录单一组织内多个系统的过程，并且它通常与现有的`LDAP`数据库相接。使用`SSO`的主要优势体现在用户和管理员双方。用户只需要记住一个密码或 PIN 码，这减少了管理多个密码带来的疲劳。此外，他们还节省了为每个所需服务重复输入凭据的时间。对于管理员来说，这意味着关于密码问题的电话会减少。图 12-4 显示了使用安全断标记语言 (`SAML`) 标准的`SSO`请求流程，这是一种实现`SSO`的广泛使用的方法。

`SAML`使用一个系统在用户、身份提供者 (`IDP`) 和服务提供者 (`SP`) 之间交换信息来提供访问和授权决策。当用户请求访问服务提供者的资源时，`SP`会为`IDP`创建身份验证请求。`IDP`将提供关于用户的反馈，`SP`可以根据其内部规则以及来自`IDP`的正面或负面响应做出访问控制决策。如果允许访问，则会生成一个令牌代替实际凭据并传递给`SP`。

尽管`SSO`改进了访问多个系统时的用户体验，但它确实有一个重大的缺点：如果凭据被泄露，影响可能会增加。因此，使用`SSO`平台需要更加关注用户凭据的保护。这就是包含多个因素和基于上下文的解决方案可以针对恶意活动提供强保护的地方。此外，由于`SSO`集中了身份验证机制，该系统变成了一个关键资产，从而成为攻击的目标。`SSO`系统的遭到破坏或可用性丢失，意味着失去对依赖`SSO`系统的整个组织应用程序集的访问权限。

## 手动与自动配置/撤销

`Provisioning`（配置）是指在服务上创建用户账户并设置与之相关的适当角色和访问权限的协调工作。让`SSO`受管理员如此青睐的部分之一是能够非常快速地为服务创建和删除账户。自动配置（Auto-provisioning）是在用户对新系统进行身份验证时即时创建账户的方法。自动配置意味着`IDP`断言该用户应允许在`SP`拥有账户。这显然要求`SP`信任`IDP`对用户的验证，这进一步说明了该过程的关键性。

## 漏洞

为什么身份验证系统会成为攻击者的首要目标？要回答这个问题，我们必须提醒自己，身份验证是验证身份并授予访问的过程。一旦接受了这些信息，系统通常会根据客户端提供的初始凭据做出后续决策。如果攻击者用虚假凭据欺骗系统，他就可以冒用用户的身份。

挑战的核心在于识别并通信恰好所需的信息。毕竟这些都是机器，它们永远无法真正知道我们是谁或我们的意图是什么。它们只能根据我们提供给它们的信息以及我们在提供这些数据时表现出的行为线索做出决策。如果攻击者足够聪明，能够伪造足够的信息，那么在身份验证系统眼里，他实际上就是同一个人。

有时攻击者会伪装成服务以收集凭据或截获通信。欺骗客户端可以通过几种方式实现。首先，如果服务器密钥被盗，攻击者看起来就像服务器，而客户端可能不会察觉。此外，如果攻击者以某种方式获得客户端作为证书机构（CA）的信任，或者客户端没有检查攻击者是否确实是受信任的 CA，那么伪装就会成功。

本质上，`MITM`攻击是双向的伪装攻击：攻击者既向真实服务器伪装客户端，又向真实客户端伪装服务器。作为代理或中继，攻击者将利用其在双方对话中间的位置来收集凭据、捕获流量或引入虚假通信。即使使用加密连接，也可能进行与未加密攻击类似的`MITM`攻击。在`HTTPS`的情况下，客户端浏览器与攻击者建立 SSL 连接，而攻击者又与 Web 服务器建立第二个 SSL 连接。客户端可能会看到也可能看不到关于客户端有效性的警告。如果出现了警告，受害者很可能会忽略或点击通过警告，这突显了用户培训的重要性。警告也可能完全不出现，这表明攻击者已成功获得了受信任的证书机构签署的证书。

会话劫持（Session hijacking）是一种攻击手段，攻击者利用有效的会话信息（通常通过窃取和重放）来实现。HTTP 流量是无状态的，且通常使用多个 TCP 连接，因此它使用会话来跟踪客户端的身份验证。会话信息只是出现在 cookie 文件、URL 本身或 HTTP 流量其他部分的字符字符串。攻击者可以通过流量捕获、中间人攻击（MITM）或预测会话令牌（token）信息来获取现有的会话信息。捕获并重复会话信息是攻击者接管或劫持现有网络会话并冒充受害者的方法。

## 跨站脚本

跨站脚本（XSS）是一种注入攻击，它利用用户的浏览器执行恶意代码，这些代码可以访问用户浏览器中的敏感信息，例如密码和会话信息。由于恶意代码存在于用户访问的网站上，用户的浏览器往往不知道该代码不应被信任。因此，XSS 利用了浏览器与网站之间这种固有的信任，在网站的安全级别运行恶意代码。XSS 有两种形式：持久型和非持久型。在持久性攻击中，恶意代码存储在网站上，通常通过留言板或评论帖子发布。当其他用户尝试使用该网站时，他们会在无意中执行隐藏在之前发布的内容中的代码。非持久性攻击也称为`reflected` XSS，利用服务器软件的漏洞。如果攻击者注意到某个网站存在 XSS 漏洞，他可以创建一个特殊的链接，当其他用户接收并点击该链接时，将导致浏览器访问网站并将攻击反射回受害者。这可能导致会话详情或用户信息无意中泄漏到攻击者指定的任何服务器。这些链接通常通过电子邮件和短信传递，看起来无害且合法的。

## 权限提升

权限提升（Privilege escalation）简单是指任何允许用户执行其通常不被允许的操作。这通常通过利用漏洞、实现缺陷或配置错误来实现。提升可以以`vertical`（垂直）方式发生，意味着用户获得了高用户的权限。或者，可以执行`horizontal`（水平）权限提升以获取相同权限他人的访问权限。攻击者将利用这些权限修改文件、下载敏感信息或安装恶意代码。

## 越狱与 Root

越狱（Jailbreaking）是绕过 Apple iOS 限制的行为，它利用权限提升允许用户执行通常无法执行的功能。越狱允许 Apple 设备用户安装自定义软件或修改过的操作系统。同样，对 Android 进行“root”赋予了用户对设备子系统的特权访问。开发这类漏洞是一项大工程，因为移动设备制造商花费了大量资源来标准化他们的设备。虽然安装额外应用和修改移动设备的自由看起来是一个好主意，但它会让设备变得不安全，因为为了实现越狱或 root，原本防止恶意活动的保护措施可能已经被删除了。
