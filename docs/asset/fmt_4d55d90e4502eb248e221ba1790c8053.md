
## 关系代数查询示例

### 查询 QA
```text
(QA) ( Sales where monthCode = ‘Jan’ and qtySold > 20 [ cdNr ] )
       ∩
       ( Sales where monthCode = ‘Feb’ and qtySold > 20 [ cdNr ] )
       ∪
       ( Track [ cdNr ] − Track where duration > 300 [ cdNr ] )
       ⋈
       CD ) [ cdNr, cdName ]
```

查询 QB 表述了查询 (b)。交集处理 `and` 操作，而关系除法用于强制执行 `each` 要求。

### 查询 QB
```text
(QB) ( Vocals ⋈ Track ) where duration >= 250 [ singer ]
       ∩
       ( Vocals [ singer, cdNr ]
         ÷
         ( Sales ⋈ CD ) where monthCode = ‘Feb’ and qtySold > stockQty [ cdNr ] )
```

此类查询最好通过注意整体结构（例如并集）来构思，然后分别处理每个部分。这些查询不寻常之处在于频繁要求使用 `∪`、`∩` 和 `−`。在使用这些运算符时，请记住确保操作数兼容——这通常意味着必须先进行投影。

有时，查询需要连接多张表。在这种情况下，如果你要连接 `n` 张表，请记住要指定 `n − 1` 个连接。例如，图 12.28 的查询连接了三张表，因此需要两个连接。

在所涉及的表操作中，只有五种是基本的（即不能用其他操作来定义）。虽然对哪些视为基本操作有不同选择，但通常列表如下：`∪`；`−`；`⨉`；选择；和投影。其他三种（`∩`、`⨝` 和 `÷`）可以用这五种操作来定义（证明留作练习）。说到练习，你一定迫不及待想在一些问题上试试你的关系代数技巧了。那么，这里就是。

## 12.2 关系数据库系统

### 关系型 DBMS 定义与 SQL 历史概述

#### 关系型 DBMS 定义

我们现在可以将关系型 DBMS 定义为：一种以关系表作为其唯一基本数据结构，且支持选择、投影和连接操作，而无需指定物理访问路径的 DBMS。支持关系代数中所有八种表操作的关系系统被称为“关系完备”。这并不意味着必须有八个不同的操作符来完成这些任务；而是这八种操作必须能用系统提供的表操作来表达。

两种主要的关系语言是 SQL 和 QBE，其中 SQL 最为重要。大多数 SQL 系统都是关系完备的。支持关系模型所有方面（包括域和两条基本完整性规则：实体完整性和参照完整性）的系统有时被称为“完全关系型”。数据的关系模型本身也在不断演进。

##### 关系模型版本 1：Codd 的 12 条规则

对于关系模型版本 1，Codd 提出了关系型 DBMS 必须满足的 12 条基本规则。现总结如下：

1.  所有信息均以关系表形式表示。
2.  所有数据均可通过表名、主键值和列名访问。
3.  必须系统地支持缺失信息（空值，独立于数据类型）。
4.  关系模式本身以表形式表示，并可像数据库一样访问。
5.  必须提供一种关系查询语言，支持数据定义、视图定义、数据操纵、完整性约束、授权和事务边界（开始、提交和回滚）。
6.  提供基本的视图可更新性支持。
7.  提供一次一表的检索和更新操作。
8.  应用程序在逻辑上不受内部存储或访问方法变更的影响。
9.  应用程序在逻辑上不受保留信息的基表变更的影响。
10. 完整性约束必须可在查询语言中定义并存储在系统表中。
11. DBMS 具有分布独立性。
12. 如果支持逐记录处理，则不能用它来绕过面向集合的查询语言中声明的约束。

##### 关系模型版本 2

Codd (1990) 提出的关系模型版本 2 包含 333 条规则，包括对两种缺失信息的支持。虽然某些提议的修订有其价值，但其他一些有争议，且任何商业 DBMS 都不太可能尝试满足所有这些规则。在实践中，SQL 语言本身在关系型 DBMS 的标准化工作中比关系模型更具影响力。

一些 SQL 系统就 Codd 最初的 12 条规则而言是完全关系型的，但大多数对域的支持较弱。例如，许多系统要求将身高和体重定义为数值数据类型，从而允许进行 `height = weight` 这样的比较。

在 SQL-89 中，`union` 操作仅允许在 `select` 语句之间进行，而不允许在表表达式之间进行，且没有为 `∩`、`−` 和 `⨝`（自然连接）提供单独的显式操作符（尽管可用其他 SQL 基本元素表达）。

1992 年，SQL 标准得到了大幅改进，SQL-92 显式包含了所有表操作符（例如，`∩`、`−` 和 `⨝` 分别称为 `intersect`、`except` 和 `natural join`）。声明约束的能力也得到了大幅增强。

SQL:1999 新增的特性包括触发器、用户定义数据类型、对象标识符、数组值字段、递归并集和过程控制结构。

最新版 SQL 标准 ISO/IEC 9075-1:2023 于 2023 年 6 月获批（参见 [`www.iso.org/standard/76584.html`](https://www.iso.org/standard/76584.html)），但其某些特性在商业系统中仍不受支持。关于 SQL 标准的更多细节将在后续章节讨论。

关系型 DBMS 提供的查询功能比前关系型 DBMS 更高级，但最初速度较慢。因此，它们最初用于决策支持和低容量在线应用。如今，其性能已大幅提升，甚至在大规模在线事务处理（OLTP）应用中也占主导地位。

SQL 产品（如 `DB2`、`Microsoft SQL Server`、`Oracle`）在大型关系系统中占主导地位。最初，许多小型关系系统（如 `Access`、`Paradox`、`FoxPro`）使用 QBE 或 Xbase 的某个版本作为其主要查询语言。如今，大多数关系系统（无论大小）都提供良好的 SQL 支持，并提供基本的 QBE 支持作为简单查询的替代方案。

除了关系代数运算外，关系型 DBMS 还提供进一步的功能，如排序、算术、分组和格式化。大多数系统还提供用于创建外部接口（如屏幕表单）、报表编写和安全性的强大工具。尽管有这些生产力优势，任何数据库应用的成功仍关键取决于数据库设计。

## 12.3 SQL：历史与结构概述

本章其余部分重点介绍 SQL。全面覆盖需要一整本书，因此省略了该语言的许多高级特性。本节假设读者熟悉关系模式和关系代数的主要操作（如前所述）。本节简要介绍 SQL 的历史和结构概况。

在 Codd 博士关于数据关系模型的经典论文发表后（Codd, 1970），开发了一些早期原型以提供关系型 DBMS，包括用于查询和更新关系数据库的语言。1974 年，Don Chamberlin 和 Raymond Boyce 发表了一篇论文，介绍一种名为“SEQUEL”（Structured English Query Language）的语言，该语言由 IBM 圣何塞研究实验室的一个团队实现，作为其 System R 关系原型的接口，该项目也称为 System R。到 1977 年，该语言的一个修订版本（SEQUEL/2）已被定义并主要由 IBM 实现。20 世纪 70 年代末，人们发现“SEQUEL”是一个现有商标，因此该语言更名为“SQL”。虽然“SQL”常发音为“SEQUEL”，但官方发音仅为“ess-cue-ell”。

System R 项目从 1971 年运行到 1979 年，后来演变为一个分布式数据库项目（System R*）。利用从 System R 项目获得的经验，IBM 构建了其第一个商业关系型 DBMS，称为 `SQL/DS`，于 1981 年发布。其第二个且极具影响力的 SQL 产品 `DB2` 于 1983 年发布。

由于 SQL 语言在 20 世纪 70 年代通过研究论文广为人知，其他公司开始开发自己的系统。Relational Software Inc.（后更名为 Oracle Corporation）实际上比 IBM 更早于 1979 年发布了其商业 SQL 产品。1982 年，美国国家标准协会（ANSI）开始对该语言进行标准化工作。第一个 SQL 标准于 1986 年完成，称为 SQL-86。

1987 年，ANSI SQL-86 标准被国际标准化组织（ISO）采纳。1989 年，一个更全面的标准 SQL-89 被 ANSI 和 ISO 同时采纳。该标准定义了一个基础的 Level 1 版本、一个更丰富的 Level 2 版本，并包含一个关于完整性增强的附录（包括声明式实体完整性和参照完整性）。

### SQL 标准演进

#### 早期标准

1992 年，下一个标准 SQL-92 获得 ANSI 和 ISO 双方批准。由于其规模庞大（超过 600 页），它被定义为三个级别：入门级、中间级和完整级。

SQL:1999 于 1999 年 12 月 8 日获批。SQL:1999 在引入面向对象特性（如对象标识符和引用、数组值字段、过程控制结构）方面与早期版本有显著不同。SQL 现在是对象-关系型的，而不再是纯关系型的。由于规模庞大，SQL:1999 标准（ANSI 1999）被分为五个独立部分：

*   框架
*   基础
*   调用级接口
*   持久存储模块
*   主语言绑定

仅基础部分就包含 1151 页。

#### SQL:2003 与 XML 集成

标准的下一个版本 SQL:2003 于 2003 年发布。一个重大增补是首次出现对 XML 的支持，但也包含对许多其他领域的增强。到那时，标准已增长到九个部分，仅基础部分就超过 1300 页。

在 SQL:2003 的开发过程中，XML 领域也在不断演进。为了反映最新的 XML 概念，SQL 标准中单独处理 XML 的部分（有时称为 "SQL/XML"）于 2006 年进行了修订，允许用户导入、存储和操作 XML 数据；它还支持 XML 查询语言 XQuery 的使用，而其他部分保持在 2003 年的修订版本。

#### 后续修订

2008 年，SQL 标准修订为支持游标定义之外的 `ORDER BY` 子句（而非触发器）、`TRUNCATE` 语句和 `FETCH` 子句。

2011 年的进一步修订增加了对时态数据（如 `PERIOD`）的支持，并增强了窗口函数和 fetch 子句。
