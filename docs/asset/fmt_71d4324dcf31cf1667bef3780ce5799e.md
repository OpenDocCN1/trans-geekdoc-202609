
## 防火墙技术术语

除了有状态和无状态防火墙外，还有一些术语用于描述特定的防火墙技术。**下一代防火墙（NGFW）**设备远不止是简单的防火墙。事实上，在许多情况下，它们更准确地被描述为一体化网络安全设备。该通用术语用于描述包含一系列功能的网络安全设备，如深度包检测、`IDS/IPS` 功能、防病毒和反恶意软件以及其他功能。

最后，**Web 应用防火墙（WAF）**是一种安全设备，旨在拦截、分析 Web 流量并应用规则，包括数据库查询、`API` 和其他 Web 应用工具等。在许多方面，如果将 `WAF` 视为防火墙与入侵防御系统的结合体，会更容易理解。它们对发送到 Web 服务器的流量进行更深度的检查，寻找攻击和攻击模式，然后根据所见应用规则。这使它们能够实时阻断攻击，甚至修改发送到 Web 服务器的流量，以移除查询或请求中潜在的危险元素。

### 统一威胁管理

**统一威胁管理（UTM）**设备通常包含防火墙、`IDS/IPS`、反恶意软件、`URL` 和邮件过滤及安全、数据丢失防护、`VPN` 以及安全监控和分析功能。`UTM` 和 `NGFW` 设备之间的界限可能令人困惑，随着双方都提供额外功能，市场持续缩小设备间的差距。

`UTM` 设备常部署在网络边界，特别是针对整个组织或部门。由于它们拥有广泛的安全功能，可以替代多个安全设备，同时提供单一界面进行管理和监控。它们通常还提供管理功能，可一次处理多个 `UTM` 设备，允许拥有多个站点或部门的组织部署 `UTM` 设备以保护各个区域，同时仍能集中管理和监控它们。

## 网络安全、服务与管理

以安全的方式管理网络，并利用网络设备内置的安全工具和功能，是设计安全网络的另一个关键要素。无论是通过 `QoS` 优先处理流量、提供路由安全，还是在现有网络架构之上实施安全协议，网络设备和系统都提供了多种选择。

### 带外管理

必须保护网络设备或设备的管理界面访问，以防攻击者夺取控制权，并确保管理员在需要时能可靠地获得访问权限。只要可能，网络设计必须包含一种安全**带外管理**的方式。应存在一种单独的访问管理界面的方法。由于大多数设备现在通过网络连接进行管理，现代实现使用单独的管理 `VLAN` 或完全独立的物理网络进行管理。对管理界面的物理访问是带外管理的另一种选择，但在大多数情况下，物理访问仅用于紧急情况，因为前往网络设备现场通过 `USB`、串口或其他接口连接并管理它既耗时，又远不如基于网络的管理平面对管理员有用。

### 访问控制列表

当你想到访问控制时，首先想到的可能是带有防火墙规则的防火墙，但许多网络设备和设备也支持某种形式的访问控制列表（`ACL`）。`ACL` 是一组用于过滤或控制网络流量的规则。`ACL` 可能包含的示例见表 12.1。

### 服务质量

确保应用程序、服务或网络流量获得优先级并能满足其设计用途的能力由**服务质量（QoS）**功能处理。用于 `Wi-Fi` 网络的 `802.11E` 和用于有线网络的 `802.1Q`（或 `Dot1Q`）等 `QoS` 协议定义了流量如何被标记和优先处理，从而定义了如何管理服务质量。

服务质量考虑了网络性能的多个重要要素：可用和使用中的带宽、流量延迟、延迟变化量（抖动）以及错误发生率。这些有助于提供 `QoS` 指标，允许根据基于应用程序、用户、端口、协议或 `IP` 地址的 `QoS` 规则对流量进行优先级排序和管理。

`QoS` 为带宽和流量管理以及排队提供支持，以处理优先级较低且需要等待的数据包。它们还可以为优先流量提供成比例或保证的带宽。

所有这些意味着 `QoS` 可以成为一个重要的安全工具，因为它允许重要流量通过网络，即使网络正遭受攻击或因拥塞而受损。这也意味着配置不当的 `QoS` 可能对网络构成威胁。

### 路由安全

网络依赖路由协议来确定流量到达其他网络应采取的路径。常见协议包括 `BGP`、`RIP`、`OSPF`、`EIGRP` 等。针对路由的攻击可能导致中间人（中间人）攻击、因环路或流量发送延迟导致的中断、或流量丢弃。它们还可能导致网络拥塞，或导致路由器无法确定到达远程网络的路由。

尽管存在许多路由协议，但在考虑路由安全时，通过示例来理解会有所帮助。这些协议及其安全功能的示例包括：

*   **BGP（边界网关协议）**内置安全性不强。事实上，`BGP` 路由默认被接受，这偶尔会导致意外或故意的 `BGP` 劫持，即路由器宣告自己为一条路由，最终将互联网流量重定向至自身。若为故意所为，意味着流量可能被攻击者拦截。若为意外，可能破坏互联网的大部分区域，导致拒绝服务状况和延迟等问题。

*   **开放最短路径优先 (OSPF)** 确实集成了一些安全特性，包括基于 `MD5` 的认证，尽管它默认未开启。与其他经过认证的协议一样，`OSPF` 并不保护实际数据，但它确实验证数据是完整的，且来自预期的路由器。

*   **增强型内部网关路由协议 (EIGRP)** 是一种思科专有协议，提供认证功能，有助于防止攻击者或其他人发送伪造的路由消息。

网络管理员需要了解他们部署的路由协议，以及如何配置它们以尽可能防止更多问题。不幸的是，由于 `BGP` 缺乏安全性等问题，路由安全仍然是一项挑战。

## 安全协议

### DNS

**域名系统 (DNS)** 服务器和服务可能成为攻击者的诱人目标，因为系统依赖 `DNS` 来告知它们在尝试使用人类可读名称访问站点时将流量发送到何处。

`DNS` 本身并非安全协议——事实上，与许多最初的互联网协议一样，它以未加密、无保护的状态传输，且内置无认证能力。幸运的是，可以使用 **域名系统安全扩展 (DNSSEC)** 来帮助弥补其中一些安全漏洞。`DNSSEC` 提供 `DNS` 数据的认证，允许验证 `DNS` 查询，即使它们未加密。

正确配置 `DNS` 服务器本身是 `DNS` 安全的关键组成部分。防止区域传输等技术，以及确保开启 `DNS` 日志记录并阻止对恶意域的 `DNS` 请求，是常见的 `DNS` 安全技术。

#### DNS 沉坑

用于帮助防范 `DNS` 问题的一种工具是 **DNS 沉坑**。`DNS` 沉坑是一种 `DNS` 服务器，配置为对特定 `DNS` 查询提供错误答案。这允许管理员使恶意和不需要的域名解析到无害地址，并可记录这些查询以帮助识别受感染或被攻陷的系统。

### 安全套接字层/传输层安全

在传输过程中加密数据的能力是许多协议安全的关键。虽然脑海中浮现的第一个例子可能是通过 `HTTPS` 实现的安全 Web 流量，但 **传输层安全 (TLS)** 广泛用于封装现代系统和网络中的各种协议。

Security+ 考试的一个关键概念是在 `TLS` 中使用 **临时密钥**。在临时 `Diffie-Hellman` 密钥交换中，每个连接都会接收一个唯一的临时密钥。这意味着即使密钥被泄露，过去发生的通信，或新会话中未来的通信也不会暴露。临时密钥用于提供 **完美前向保密**，这意味着即使用于密钥交换的秘密被泄露，通信本身也不会被泄露。

### 监控服务和系统

没有服务，系统和网络几乎无事可做。确保组织的服务在线且可访问需要监控和报告能力。虽然检查服务是否响应可能很简单，但验证服务是否按预期运行可能更复杂。

组织通常使用多层级的服务监控。第一层也是最简单的一层验证服务端口是否开放并响应。这种基本功能有助于识别重大问题，例如服务无法加载、崩溃或被防火墙规则阻止。

下一级监控要求与服务交互，并对有效响应的样子有所了解。这些事务需要额外的功能，并且可能还会使用验证性能和响应时间的指标。

最后一级监控系统寻找可能故障的指标，并使用广泛的数据来识别潜在问题。

服务监控工具内置于许多运维监控工具、`SIEM` 设备和其他组织管理平台中。配置服务级监控可以为安全管理员提供对持续问题的洞察，因为服务故障或问题可能是事件的指标。

### 文件完整性监视器

构成网络的基础设施和系统是攻击者的目标，他们可能会更改配置文件、安装自己的服务，或以其他方式修改需要值得信赖的系统。检测这些更改并对其进行报告或将其恢复正常是 **文件完整性监视器** 的职责。虽然市场上有许多产品可以处理文件完整性监控，但最古老且最知名的之一是 **Tripwire**，这是一款拥有商业版和开源版本的文件完整性监控工具。

像 `Tripwire` 这样的文件完整性监控工具为文件创建签名或指纹，然后监控文件和文件系统中受监控文件的更改。它们集成了许多功能以允许修补或用户交互等正常行为，但重点关注意外和非预期的更改。文件完整性监视器可以成为系统安全设计的关键要素，但如果未仔细设置，配置和监控它也可能具有挑战性。由于文件在网络和系统上不断变化，文件完整性监视器可能会产生大量噪音，并需要时间和精力来设置和维护。

### 欺骗与破坏

最后一类网络相关工具是那些旨在捕获攻击者及其技术信息并破坏正在进行的攻击的工具。捕获攻击者信息可以为防御者提供关于其工具和流程的有用细节，并帮助防御者基于现实经验构建更好、更安全的网络。

Security+ 考试大纲中包含三种主要类型的信息收集工具。第一种也是最常见的是 **蜜罐** 的使用。蜜罐是故意配置为看似脆弱的系统，但实际上是经过大量仪表化和监控的系统，它们会记录攻击者的所有行为，并保留其使用的每个文件和命令的副本。它们看起来是合法的，并且可能包含诱人的虚假信息。与蜜罐非常相似，**蜜网** 是为收集网络攻击信息而设置和仪表化的网络。本质上，蜜网是一组蜜罐，设置得更具说服力，并由于通过系统网络所需的各种系统和技术，能提供关于攻击者工具的更多细节。

与用于对抗研究的蜜网和蜜罐不同，**蜜文件** 用于入侵检测。蜜文件是一个故意设置的诱人目标文件，包含唯一的、可检测的数据，放置在攻击者若攻击成功可能会访问的区域。如果蜜文件中包含的数据被检测到离开网络，或稍后在网络外被发现，组织就知道系统已被攻破。

你需要了解的该类别中 Security+ 考试的最后一个概念是提供 **虚假遥测数据** 的做法。虚假遥测是欺骗工作的一部分，为攻击者提供额外目标。虚假遥测的概念非常类似于蜜文件——它为攻击者提供一个目标，要么误导他们，要么让你检测到对该信息的访问。

## 网络与安全协议

网络通过在不同网络层运行的多种不同协议来传输流量。虽然可以通过为每个可能的系统使用加密通道来保护网络，但在大多数情况下，网络并不会加密每一个端到端的连接。因此，正确选择和实施安全协议对于纵深防御策略至关重要。安全协议有助于确保系统或网络遭到入侵时，不会导致网络流量进一步暴露。

### 使用安全协议

安全协议在网络和基础设施的许多部分都有其用武之地。安全专业人员需要能够为以下每种场景推荐合适的协议：

*   **语音和视频**依赖许多常见协议。视频会议工具通常依赖 `HTTPS`，但会话发起协议（`SIP`）和实时传输协议（`RTP`）的安全版本分别以 `SIPS` 和 `SRTP` 的形式存在，它们也被用于确保通信流量的安全。

*   网络时间协议（`NTP`）的安全版本称为 `NTS`，但 `NTS` 尚未被广泛采用。正如你在本章将了解到的许多其他协议一样，`NTS` 依赖 `TLS`。与其他协议不同，`NTS` 并不保护时间数据本身。相反，它专注于认证，以确保时间信息来自受信任的服务器且在传输过程中未被篡改。

*   **电子邮件和 Web 流量**依赖许多安全选项，包括 `HTTPS`、`IMAPS`、`POPS`，以及域名消息认证、报告和一致性（`DMARC`）、域名密钥识别邮件（`DKIM`）和发件人策略框架（`SPF`）等安全协议。

*   文件传输协议（`FTP`）已在很大程度上被 `HTTPS` 文件传输以及 `SFTP` 或 `FTPS` 的组合所取代，具体取决于组织的偏好和需求。

*   目录服务（如 `LDAP`）可以迁移到 `LDAPS`，即 `LDAP` 的安全版本。

*   **远程访问技术**——包括 Shell 访问，曾经通过 `telnet` 实现，现在几乎完全通过 `SSH` 完成——也可以得到保护。微软的 `RDP` 默认加密，但其他远程访问工具可能使用其他协议（包括 `HTTPS`）来确保其流量不被暴露。

*   **域名解析**仍然是一个安全挑战，长期以来的多次努力对 `DNS` 协议安全性的影响有限。

*   **路由和交换协议安全**可能很复杂，边界网关协议（`BGP`）等协议缺乏内置安全功能。因此，`BGP` 劫持攻击和其他路由攻击仍然可能发生。在许多情况下，组织无法依赖安全协议，需要围绕这一缺陷进行设计。

*   使用 `DHCP` 进行**网络地址分配**不提供安全协议，针对 `DHCP` 攻击的网络保护依赖于检测和响应，而非安全协议。

*   **订阅服务**（如云工具和类似服务）通常利用 `HTTPS`，但也可能为其特定用例提供其他安全协议。可能的订阅和服务类型种类繁多，这意味着如果可用选项存在，必须单独评估这些服务，架构和设计审查以及数据流审查都是保护订阅服务流量最佳实践的一部分。

上述可能的安全选项清单很长，但 `DHCP`、`NTP`、`BGP` 和 `DHCP` 缺乏安全协议这一显著事实表明，虽然安全协议是安全设计的有用组成部分，但它们只是设计过程的一部分。作为安全专业人员，你的评估应确定是否包含合适的安全协议选项、是否正在使用以及是否配置正确。即使正在使用安全协议，你还必须评估现有的其他安全层，以确定设计或实施是否具有适当的安全性，以应对使用过程中将面临的风险。

### 安全协议详解

Security+ 考试重点关注许多常见协议，考生需要了解如何识别和实施它们。在阅读本节时，请考虑何时建议切换到安全协议、两种协议是否可能在环境中共存，以及如果实施该协议还需要考虑哪些额外因素。这些因素包括客户端配置要求、切换到备用端口、不同的客户端软件包、对可能无法直接监控加密流量的安全工具的影响等类似问题。

组织依赖各种各样的服务，其中许多服务的原始实现（如文件传输、远程 Shell 访问、电子邮件检索、Web 浏览等）均为明文实现，这使得流量很容易被捕获、分析和修改。这意味着这些服务所依赖的流量的机密性和完整性无法得到保证，从而促使这些协议的安全版本得以实施。安全分析师经常被要求识别不安全的服务，并推荐或协助实施安全替代方案。

表 12.2 列出了 Security+ 考试大纲中常见的协议及其安全替代方案。许多安全协议依赖 `TLS` 来保护流量，而其他协议则实现 `AES` 加密或使用其他技术来确保其传输数据的机密性和完整性。许多协议为安全版本使用不同的端口，但其他协议则依赖初始协商或服务请求来确定流量是否将被保护。

| `FTP` | `TCP 21 (and 20)` | `FTPS` | `TCP 21` 显式模式和 `990` 隐式模式 (`FTPS`) | 使用 `TLS` |
| `FTP` | `TCP 21 (and 20)` | `SFTP` | `TCP 22` (`SSH`) | 使用 `SSH` |
| `HTTP` | `TCP 80` | `HTTPS` | `TCP 443` | 使用 `TLS` |
| `IMAP` | `TCP 143` | `IMAPS` | `TCP 993` | 使用 `TLS` |
| `LDAP` | `UDP and TCP 389` | `LDAPS` | `TCP 636` | 使用 `TLS` |
| `POP3` | `TCP 110` | `POP3S` | `TCP 995` | 使用 `TLS` |
| `RTP` | `UDP 16384-32767` | `SRTP` | `UDP 5004` | |
| `SNMP` | `UDP 161 and 162` | `SNMPv3` | `UDP 161 and 162` | |

考生应识别出上述每一项：

*   **域名系统安全扩展**（`DNSSEC`）专注于确保 `DNS` 信息未被修改或篡改，但它不像此处列出的许多其他安全协议那样提供机密性。`DNSSEC` 使用数字签名，允许查询 `DNSSEC` 服务器的系统验证服务器的签名是否与 `DNS` 记录匹配。`DNSSEC` 还可用于为 `IPSec` 密钥、`SSH` 指纹和类似记录建立信任链。

*   **简单网络管理协议第 3 版**（`SNMPv3`）通过提供消息源认证、消息完整性验证和通过加密实现的机密性，改进了 `SNMP` 的早期版本。它支持多个安全级别，但只有 `authPriv` 级别使用加密，这意味着不安全的 `SNMPv3` 实现仍然可能存在。仅使用 `SNMPv3` 并不能自动使 `SNMP` 信息变得安全。

*   **安全外壳协议 (SSH)** 是一种用于远程控制台访问设备的协议，是 `Telnet` 的安全替代方案。`SSH` 也常被用作隧道协议，或用于支持 `SFTP` 等其他用途。`SSH` 可以使用 `SSH` 密钥，用于身份验证。与许多基于证书或密钥的身份验证用法一样，缺少密码或使用弱密码，以及密钥管理不善，都会使 `SSH` 在实际使用中安全性大打折扣。

*   **基于 SSL/TLS 的超文本传输协议 (HTTPS)** 在现代实现中依赖 `TLS`，但尽管如此，仍常被称为 `SSL`。与此处讨论的许多协议一样，底层的 `HTTP` 协议依赖 `TLS` 来为 `HTTPS` 实现提供安全性。
