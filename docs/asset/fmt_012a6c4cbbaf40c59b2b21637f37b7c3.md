### 错误处理：Go 与其他语言的区别

Go 中的错误处理是不同的。Go 团队在这方面采取了不同的方法。大多数语言包含 `try-catch-finally`。错误最终都会发生，正如我们所知。迟早，我们必须考虑如何处理它们。得益于优秀的错误处理，开发者无法忘记处理错误，并能返回精确的错误信息。

通常，在其他编程语言中，许多错误信息会在大量的 `try-catch` 块中被“吞没”。Go 为我们提供了一种非常方便的多返回值方式，这使得我们能更轻松地正确返回错误。

### 错误是为了讲述一个故事

在 *第二章，Go 的易用性* 中，我们讨论了在 Go 中使用错误来“讲述一个故事”。当我们在微服务的语境下交谈时，讲述故事成为一种力量倍增器。因为单个服务的故事可能很简单，但跨越多个服务的错误故事会复杂得多。我们可以通过服务间的追踪来解决它。我们将在 *第九章，部署到生产环境* 中更详细地讨论追踪。简而言之，追踪是服务间代码和错误的跟踪。

### 测试 - 最佳实践、Mock 与模糊测试

我们非常喜欢 Go 的一点是 `testing` 包是由 Go 团队维护的核心包。我们在其他语言中遇到过许多情况，因测试框架太多且各有所短，而苦恼于寻找合适的测试框架。我们的建议是尽量避免使用外部测试框架。

本节将讨论 Go 中测试的样子、它们与其他语言的区别，以及 Go 测试的最佳实践。

注意：测试是一个庞大的主题，我们不旨在全面学习它。单元测试、组件测试、集成测试、冒烟测试，以及 Mock、Stub、Fake 和 Spy 等都是测试生态系统中的术语和定义示例。我们的目标是了解 Go 语言中的测试调整及其优势，特别是在 Go 中的优势。此外，我们还将学习在构建微服务架构时需要测试什么。

我们对测试的总体看法如下：

1. 测试必须是独立的。
2. 不稳定测试是任何系统的毒瘤 —— 测试必须是可复现的。
3. 测试是记录代码的绝佳方式。

在 Go 中创建测试的步骤是什么？测试文件放在哪里？

1. 创建一个以 `_test.go` 为后缀的文件。该文件可以放在被测试文件附近（请参阅本章代码中的示例）。我们也可以在专门的目录中创建测试文件。
2. 在测试文件中，声明一个签名为 `func TestName(t *testing.T)` 的函数。将 `Name` 替换为你想要测试的内容。通常我们测试一个函数，`Name` 即为该函数的名称。但 `Test` 前缀是必须的。
3. 使用 Go CLI 运行测试，执行命令 `go test ./...`。

我们有一个名为 `GetBigger` 的函数（见 `example.go`）：

```go
func GetBigger(a, b float64) float64 {
    return math.Max(a, b)
}
```

测试文件应如下所示（`example_test.go`）：

```go
package main

import "testing"

func TestGetBigger(t *testing.T) {
    type args struct {
        a float64
        b float64
    }
    tests := []struct {
        name string
        args args
        want float64
    }{
        {
            name: "a is the bigger one",
            args: args{
                a: 9,
                b: 6,
            },
            want: 9,
        },
        {
            name: "b is the bigger one",
            args: args{
                a: 3,
                b: 7,
            },
            want: 7,
        },
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            if got := GetBigger(tt.args.a, tt.args.b); got != tt.want {
                t.Errorf("GetBigger() = %v, want %v", got, tt.want)
            }
        })
    }
}
```

`testing` 包下有许多工具函数帮助我们执行更精确的测试。文中提供了一个指向 Go `testing` 包详细文章的链接。

#### Mock

这是一个宝贵的工具，帮助我们为测试设置常量（即不可变数据）。我们可以 Mock 数据，也可以 Mock 函数。Mock 数据的方式有很多；最方便的方式是使用 `gofakeit` 包。这是一个非常方便的包，帮助我们 Mock 数据。接下来我们讨论 Mock 函数。

在 Go 中我们无法直接 Mock 函数。我们实际上能 `mock` 的是接口。在 Mock 接口之前，我们必须知道如何 Mock `struct`。要在 Go 中 Mock `struct`，我们需要该结构体兼容某个接口，然后我们就可以 Mock 该接口。稍后我们将看到如何操作。

在此之前，我们先尝试 Mock 一个函数。要 Mock 一个函数，正如你可能猜到的，我们需要将函数赋值给一个结构体。在这里，我们可以利用空结构体（`struct{}`）的存在。以下是一个用例：一个函数调用了另外两个函数。

```go
// Valid name is between 8 and 16 chars and doesn't contain number
func IsValidName(name string) bool {
    numbersValid := IsNumbersValid(name)
    lengthValid := IsLengthValid(name)
    return numbersValid && lengthValid
}

func IsNumbersValid(name string) bool {
    return !strings.ContainsAny(name, "0123456789")
}

func IsLengthValid(name string) bool {
    length := len(name)
    return length >= 8 && length <= 16
}
```

假设我们要为 `IsValidName` 函数创建测试，但想 Mock `IsNumbersValid` 和 `IsLengthValid` 函数。第一步是创建一个接口和空 `struct`，如下所示：

```go
type ValidationClient struct{}

type ValidationClientInter interface {
    IsNumbersValid(name string) bool
    IsLengthValid(name string) bool
}
```

然后，将我们想要 Mock 的函数赋值给该 `struct`。

```go
func (c *ValidationClient) IsNumbersValid(name string) bool {
    return !strings.ContainsAny(name, "0123456789")
}

func (c *ValidationClient) IsLengthValid(name string) bool {
    length := len(name)
    return length >= 8 && length <= 16
}
```

之后，我们应该创建该结构体的实例，并使用该实例来调用我们想要 Mock 的函数。

```go
var Client ValidationClientInter = &ValidationClient{}

func IsValidName(name string) bool {
    numbersValid := Client.IsNumbersValid(name)
    lengthValid := Client.IsLengthValid(name)
    return numbersValid && lengthValid
}
```

按照示例，现在我们有一个函数 `IsValidName` 通过结构体客户端（`Client`）调用另外两个函数，该客户端满足接口 `ValidationClientInter`。

请记住，我们必须拥有该接口。因为在 Go 中，我们可以使用组合来“`override`”接口。之后，让我们使用一个名为 `mockery` 的工具。`mockery` 通过运行命令帮助我们生成 Mock。另一种选择是 `gomock`，它在 Go 中也非常流行。运行 `mockery` 的命令如下：

```bash
mockery --all --inpackage
```

这将为每个接口生成一个单独的文件。运行此命令时，工具将创建文件 `mock_ValidationClientInter.go`。剩下的唯一工作就是确定 Mock 函数的行为，然后将 `Client` 赋值为我们之前创建的 Mock 客户端。这样做后，运行测试时将使用 Mock 客户端而不是原始客户端。

```go
mockedClient := &MockValidationClientInter{}
mockedClient.On("IsNumbersValid", mock.Anything).Return(true)
mockedClient.On("IsLengthValid", mock.Anything).Return(true)
Client = mockedClient
```

此功能发生在测试文件中。

#### 模糊测试

模糊测试使用提供的种子数据为函数生成输入。模糊测试被证明是发现代码中不可预见行为的有效方法。它有助于找出代码可能发生 `panic` 的位置，以便我们处理那些我们未曾想到的特定用例。

模糊测试是 Go 的一项新功能。从 1.18 版本开始支持模糊测试。让我们看一个将字符串解析为名和姓的简单函数。

```go
// ParseName parses a name into first and last.
func ParseName(s string) (string, string, error) {
    parts := strings.Split(s, " ")
    return parts[0], parts[1], nil
}
```

我们为此函数创建了一个模糊测试，如下所示：

```go
func FuzzParseName(f *testing.F) {
    f.Add("John Adams")
    f.Add("George Washington")
    f.Fuzz(func(t *testing.T, s string) {
        _, _, err := ParseName(s)
        if err != nil {
            t.Errorf("%v", err)
        }
    })
}
```

现在，让我们用 12 秒的超时时间运行模糊测试。注意，模糊测试的超时时间是无限的（因为它总是尝试寻找更多用例）。我们可以通过运行以下命令来运行模糊测试：

```bash
go test -fuzz FuzzParseName -fuzztime=12s
```

运行此命令后，我们遇到了一个 `panic` 错误：

```text
panic: runtime error: index out of range [1] with length 1
```

原因非常直接：`panic` 的原因是我们没有检查字符串为空或不包含空格的情况。为了解决它，我们需要处理该用例。同时在测试中忽略新的错误类型。

```go
var ErrInvalidName = errors.New("invalid name")

// ParseName parses a name into first and last.
func ParseName(s string) (string, string, error) {
    parts := strings.Split(s, " ")
    if len(parts) != 2 {
        return "", "", ErrInvalidName
    }
    return parts[0], parts[1], nil
}

func FuzzParseName(f *testing.F) {
    f.Add("John Adams")
    f.Add("George Washington")
    f.Fuzz(func(t *testing.T, s string) {
        _, _, err := ParseName(s)
        if err != nil {
            if errors.Is(err, ErrInvalidName) {
                return
            }
            t.Errorf("%v", err)
        }
    })
}
```

注意：模糊测试函数名必须以 `Fuzz` 为前缀。

### 微服务测试

微服务因其固有设计而具有简单、自包含的特点。遵循适配器设计模式，我们应通过封装 HTTP 客户端来实现服务间通信的封装。关于该设计模式的参考资料请见“参考文献”部分。

在创建与其他服务通信的自定义客户端（封装后的客户端）时，我们应尽量将这些客户端创建为结构体（`struct`）。这些结构体必须实现一个接口。关于在微服务中使用客户端接口，有两种最佳实践：

*   每个服务客户端拥有自己的接口 —— 灵活性更高，但工作量更大。
*   所有服务共享一个通用接口 —— 灵活性较低，但工作量较少。

无论选择哪种方案，引入接口的原因都是为了具备模拟客户端响应的能力，正如前文（“模拟”）所述。我们希望在单个服务的测试范围内模拟客户端响应。

一种更强大的测试类型是服务间测试。虽然它功能更强，但也需要投入大量时间和精力。关于此类服务间测试存在无数理论。核心在于正确设置这些测试的 `Setup` 和 `Teardown`，同时确保测试的可复现性。通常，这类测试在敏捷性方面容易变得不稳定。我们应致力于使用本章介绍的 `Functional Options Pattern`。在最佳场景下，`Setup` 函数应表现为定义多个 `Options`（基本上即配置）。

Go 语言在构建微服务架构时提供了两个相关的高效工具：

*   性能基准测试
*   竞态检测器

### 性能基准测试

基准测试是测试 CLI 的内置选项。它有助于我们测试函数的性能。基准测试是一种强大的方法论，帮助我们实现良好的性能。构建微服务时它甚至更强大，因为我们可以在特定端点变慢时进行调查。让我们看看如何执行基准测试。

```go
func Fib(n int) int {
    if n < 2 {
        return n
    }
    return Fib(n-1) + Fib(n-2)
}
```

我们想要查看该函数在大输入下的性能表现。我们需要创建一个以 `Benchmark` 为前缀、签名为 `(b *testing.B)` 的测试函数，测试代码如下：

```go
func BenchmarkFib(b *testing.B) {
    for n := 0; n < b.N; n++ {
        Fib(20)
    }
}
```

运行基准测试需使用 Go CLI，命令如下：

`go test -bench=.`

还有多种运行基准测试的配置可供探索。

### 竞态检测器

Go CLI 内置选项可用于检测竞态条件。竞态条件是微服务系统中常见的情况。此外，由于 Go 的并发模型，竞态条件很容易发生。竞态检测器可针对可执行程序或测试运行。让我们看一个针对简单情况运行竞态检测器的示例：

```go
func main() {
    i := 0
    go func() {
        i++
    }()
    fmt.Println(i)
}
```

在上述示例中，函数第二行启动了一个 goroutine。当我们打印 `i` 时，可能得到两种结果：`0` 或 `1`。原因是存在竞态条件。我们无法确定 goroutine 是否会在 `Println` 调用前执行完毕，因为它们是并行运行的。运行竞态检测器的命令为：

`go run -race race-detector.go`

我们将得到如下警告：
