
数据流模型的一个核心特征是流随时间演变，算法必须对变化做出反应。例如，让我们考虑电子邮件垃圾邮件分类器，它决定新到达的邮件是否为垃圾邮件。随着分类器学习以提高其准确性，垃圾邮件发送者将修改其构建垃圾邮件的策略，试图欺骗分类器使其相信这些邮件不是垃圾邮件。客户行为预测是另一个例子：实际或潜在客户会随着价格涨跌、新产品出现和旧产品过时，或仅仅是随着季节更替而改变偏好。在这些及其他情况下，预测器需要随时间推移进行调整、修订或替换，以保持合理的准确性。

在本章中，我们将首先讨论数据流研究中通常理解的变化概念，并指出其与其他也考虑变化数据领域的差异，然后讨论可能的变化类型、变化存在时使用的一些性能度量，以及在流上设计变化感知算法的一般策略（第 5.1 节）。随后我们将探讨准确估计演变数据流统计量的方法（第 5.2 节），以及检测和量化变化的方法（第 5.3 节）。最后我们将给出一些关于时间感知草图和多维流变化检测的参考文献（第 5.4 节）。

关于数据变化检测有大量文献，我们优先介绍最适用于数据流、易于实现且计算量轻的方法，特别是那些在 `MOA` 中可用的方法。适用于所有数据类型的综合讨论见 [27]，针对流的最新讨论见 [116]。[41] 中介绍了一个在 `MOA` 中试验变化检测和管理的框架。

## 5.1 流中变化的概念

让我们首先相对于其他范式中的概念，以及在仔细定义随时间变化时出现的一些细微差别，来讨论流中变化的概念。

首先，数据的非平稳分布也可能出现在批量数据分析中。批量数据集中的数据也可能带有时间戳，并在统计上随时间变化。算法在从数据得出结论时可能会考虑这种可能性，但除此之外，可以执行多次遍历，并检查任何给定记录时间之前和之后的数据。而在流处理中，我们无法显式存储所有过去数据以检测或量化变化，当然也无法使用未来的数据来做出当下的决策。

其次，与庞大的时间序列分析领域存在一些相似性，那里的数据也由带时间戳的项目序列（或一组序列）组成。然而，在时间序列分析中，分析过程通常被假定为离线的，使用批量数据，且没有流固有的低内存和每个项目低处理时间的要求。（当然，我们也可以考虑流式、实时的时间序列分析。）更重要的是，在时间序列分析中，重点通常在于预测数据的未来演变。例如，如果过去六个月平均销售额每月增长 1%，则合理预测下个月销售额将比本月高 1%。相比之下，流处理中的大多数工作不一定假设变化以可预测的方式发生，或具有趋势。变化可能是任意的。任务是根据我们当前观察到的情况，构建描述世界当前行为方式的模型。

第三，数据流中使用的变化概念不同于（或是 [182] 中描述的更一般的“数据集漂移”概念的一个特例）。每当训练数据集和测试数据集来自不同分布时，就会发生数据集漂移。流处理是这种设置的一个实例；例如，我们迄今构建的预测模型将用于预测稍后到达的数据，后者可能遵循不同的分布。但它也适用于其他情况，例如用某地理区域的批量数据训练的分类器被应用于预测来自另一区域的数据。

当我们说数据流发生变化或演变时，究竟意味着什么？这并不意味着我们今天观察到的项目与昨天观察到的项目不完全相同。一个更合理的概念是：数据的统计特性发生的变化超过了可归因于随机波动的范围。为了使这一想法精确化，有助于假设数据实际上是一个随机过程的结果，该过程在每个时刻根据该确切时刻使用的概率分布生成一个项目，该分布可能与任何其他给定时刻使用的分布相同，也可能不同。当这个底层生成分布保持平稳时，不存在变化。每当它从一个时间步变化到下一个时间步时，就会发生变化。

回顾上一章，我们假设了一个对抗模型，其中流中不假设有任何随机性——仅可能在算法中（如果它使用随机位和数字）。算法必须即使在对抗性选择的最坏情况下输入下也能表现良好。相反，在随机生成流模型中，通过根据生成分布下的概率对所有可能的流进行平均，来考虑算法的“平均情况”性能是有意义的。这种 `随机数据流` 的概念几乎贯穿后续所有章节。例如，如果流由独立生成的比特组成，1 出现的概率为 1/2，那么我们期望 0 和 1 随机交错出现。包含前 `n/2` 个 1 后跟 `n/2` 个 0 的唯一 `n` 比特序列概率可忽略不计，但如果它恰好是算法的最难情况，则可能在对抗模型中决定算法的性能。

通常，会隐式或显式地使用一个额外的*独立性*假设：即时刻 `t` 生成的项目独立于先前时刻生成的项目。换句话说，通常假设该过程是马尔可夫的。这承认是可疑的，或显而易见是错误的：在许多情况下，流具有记忆，并经历高度相关事件的爆发。例如，系统中某个组件的故障很可能在相关组件中引发一连串故障。该假设的一个放宽版本是：相关性以某种方式是短期的，并且在足够长的子流上，统计特性是马尔可夫过程的。设计考虑这种自相关性的算法是一个活跃的研究领域。

## 5.1 数据流中的变化

尽管项目分布的变化可能是任意的，但给几种通用类型命名会有所帮助，这些类型在流内并非互斥。遗憾的是，文献中的命名并不一致。事实上，文献中通常将变化笼统地称为 `concept drift`（概念漂移）；我们在下文中力求更加精确。

*   **突然** 变化是指分布长时间保持不变，然后在几步内变为一个显著不同的分布。这通常被称为 `shift`（突变/平移）。
*   **渐进** 或 **增量** 变化是指长时间内，分布在每个时间步都经历微小的、几乎难以察觉的变化，但这些累积的变化随时间变得显著。
*   根据变化是影响整个项目空间还是仅影响其中一部分，变化可分为 **全局** 或 **局部**。在机器学习术语中，局部变化可能仅影响特定形式的实例，或仅影响部分实例属性。
*   **循环概念** 是指过去出现过的分布倾向于在稍后重新出现。一个例子是季节性，夏季的分布彼此相似，但与冬季的分布不同。另一个例子是由于大型活动或事故导致的城市交通和公共交通的扭曲，这些事件发生在不规则、不可预测的时间。
*   在预测场景中，我们需要根据项目中观测到的输入特征 `X` 的值，预测该项目的某个结果特征 `Y`。**真实变化** 是指 `Pr[Y|X]` 发生变化，无论 `Pr[X]` 是否变化。**虚拟变化** 是指 `Pr[X]` 发生变化但 `Pr[Y|X]` 保持不变。换句话说，在真实变化中，用于标记实例的规则发生了改变；而在虚拟变化中，输入分布发生了改变。

我们还应将 **异常值** 和 **噪声** 的概念与分布变化的概念区分开来。将真实变化与瞬态异常值和持久性噪声区分开来，是数据流挖掘和学习中的挑战之一。

总而言之，我们需要考虑构建模型（如预测器、聚类器或模式挖掘器）的数据流算法的以下要求 [116]：

1.  尽快检测流中的变化（并在需要时调整模型）。
2.  同时，对噪声和异常值保持鲁棒性。
3.  在小于实例到达时间的时间内运行，并使用亚线性内存（理想情况下，使用某个固定的、预设的内存量）。

变化管理策略大致可分为三类，或其组合。它们可以使用相关统计量的自适应估计器，然后由一个算法根据这些统计量维护模型。或者，当变化检测器指示发生了变化时，它们可以创建经过调整或重建的模型。又或者，它们可以是集成方法，维护动态的模型种群。我们将在下文详细描述这三种方法。

第一种策略依赖于这样一个事实：许多模型构建器通过监控流中的一组统计量，然后将它们组合成模型来工作。这些统计量可能是计数、绝对或条件概率、属性间的相关性、特定模式的频率等。此类算法的例子包括 `Naive Bayes`（朴素贝叶斯），它保存属性值与类值共现的计数；以及 `perceptron`（感知机）算法，它根据属性与待预测结果之间的一致性来更新权重。该策略通过为每个相关统计量配备一个动态估计器来反映其当前值，并让模型构建器利用这些估计器。该架构如图 5.1 所示。

## 5.2 估计器

**估计器算法** 在输入数据上估计一个或多个统计量，这些数据可能随时间变化。我们关注的情况是：该统计量是（或可重写为）数据当前分布的期望值，因此可通过该分布的一个样本的平均值来近似。部分难点在于，由于存在漂移的可能性，很难确定流中哪些过去元素仍可作为当前分布的可靠样本，哪些已过时。

估计器分为两类：显式存储数据流样本的估计器（我们将此存储称为“内存”）和无内存估计器。前者中我们解释线性估计器在滑动窗口上的应用。后者中我们解释 `EWMA` 和 `Kalman filter`（卡尔曼滤波器）；其他运行时高效的估计器包括 `autoregressive model`（自回归模型）和 `autoregressive-moving-average estimator`（自回归移动平均估计器）。

### 5.2.1 滑动窗口与线性估计器

期望值最简单的估计器算法是 **线性估计器**，它仅返回内存中所含数据项的平均值。内存的一种简单实现是滑动窗口，它存储最近接收到的 `W` 个项目。大多数情况下，`W` 是估计器的一个固定参数；更复杂的方法可能会随时间改变 `W`，或许是根据数据本身的性质做出反应。

使用滑动窗口的估计器所用的内存可以减少，例如通过使用第 4.7 节讨论的 `Exponential Histogram`（指数直方图）草图，代价是估计中引入一些近似误差。

### 5.2.2 指数加权移动平均

指数加权移动平均（`EWMA`）估计器通过将变量的最近一次测量值与所有先前测量值的 `EWMA` 相结合，来更新变量的估计值：

```
A[t] = α * x[t] + (1 - α) * A[t-1]
```

其中 `A[t]` 是时间 `t` 处的移动平均值，`x[t]` 是最新的测量值，而 `α ∈ (0, 1)` 是一个反映赋予最新测量值权重的参数。它通常被称为*衰减*或*消退*因子。确实，通过展开上述递推公式，我们可以看到时间 `t` 处的估计值为

```
A[t] = α * Σ_{i=0}^{∞} (1-α)^i * x[t-i]
```

因此，每个测量值的权重以 `1 − α` 为底呈指数级快速衰减。较大的 `α` 值意味着对旧测量值的遗忘更快，而较小的值则赋予历史更高的重要性。

### 5.2.3 一维卡尔曼滤波器

一维卡尔曼滤波器解决了估计离散时间受控过程隐藏状态 `x ∈ ℜ` 的问题，该过程由线性随机差分方程控制：

```
x[t] = x[t-1] + w[t]
```

其中 `x` 通过测量值 `z ∈ ℜ` 间接观测，其关系为：

```
z[t] = x[t] + v[t]
```

此处 `w[t]` 和 `v[t]` 是分别代表过程噪声和测量噪声的随机变量。假设它们相互独立，且服从正态概率分布：

```
w[t] ~ N(0, Q)
v[t] ~ N(0, R)
```

在我们的场景中，`x[t]` 是时间 `t` 流数据项某属性的期望值，`z[t]` 是时间 `t` 实际观测到的数据项上该属性的值，而 `w[t]`、`v[t]` 分别是 `x[t]` 的随机变化量和 `z[t]` 中的观测噪声。时间 `t` 状态的估计值 `y[t]` 在卡尔曼滤波器中按如下方式更新，其中 `P` 和 `K` 为辅助量：

```
K[t] = P[t|t-1] / (P[t|t-1] + R)
y[t] = y[t|t-1] + K[t] * (z[t] - y[t|t-1])
P[t|t] = (1 - K[t]) * P[t|t-1]
P[t+1|t] = P[t|t] + Q
```

卡尔曼滤波器在任何特定应用中的有效性取决于随机方程的有效性、噪声高斯假设的有效性，以及对方差 `Q` 和 `R` 估计的准确性。

这是卡尔曼滤波器的一个非常简单的版本。更一般地，它可以是多维的，此时 `x` 是一个向量，且 `x` 的每个分量都是其在上一时刻所有分量的线性组合加上噪声。它还允许存在控制变量，我们可以改变这些变量来影响状态，从而创建反馈回路；这实际上是卡尔曼滤波器最初的主要目的。此外，它还可以扩展到非线性的测量-过程关系。卡尔曼滤波器的完整阐述见文献 [245]。

## 5.3 变化检测

数据中的变化检测是一个广泛的主题，在统计学中有着悠久的传统；参见 [27]。并非所有方法都适用于流式处理，通常是因为它们需要对数据进行多次遍历。我们仅介绍几种适合流式处理的方法。

### 5.3.1 变化检测的评估

以下标准与评估变化检测方法相关。它们涉及此类算法必须面对的根本权衡 [130]，即检测真实变化与避免虚假警报之间的权衡。许多标准取决于我们想要检测的变化的最小幅度 `θ`。

*   **平均虚假警报间隔时间，MTFA：** 度量在没有变化发生时产生虚假警报的频率。虚假警报率 (FAR) 定义为 `1/MTFA`。
*   **平均检测时间，MTD(θ)：** 度量学习系统在变化发生时检测并响应变化的能力。
*   **漏报率，MDR(θ)：** 度量发生变化却未产生警报的概率。
*   **平均运行长度，ARL(θ)：** 该指标泛化了 MTFA 和 MTD，指示变化发生后需要等待多久才能检测到该变化。我们有 `MTFA = ARL(0)`，且对于 `θ > 0`，有 `MTD(θ) = ARL(θ)`。

### 5.3.2 CUSUM 检验和 Page-Hinkley 检验

累积和 (CUSUM) 检验 [191] 旨在当输入数据的均值显著偏离其先前值时发出警报。

在其最简单的形式中，CUSUM 检验如下：给定观测序列 `{x[t]}[t]`，定义 `z[t] = (x[t] − μ)/σ`，其中 `μ` 是 `x[t]` 的期望值，`σ` 是其在“正常”条件下的标准差；如果 `μ` 和 `σ` 无法预先得知，则从序列本身进行估计。然后 CUSUM 计算指数和警报：

```
g[t] = max(0, g[t-1] + z[t] - k)
if g[t] > h then alarm
```

CUSUM 无记忆，且处理每个数据项所需时间恒定。其行为如何精确地取决于参数 `k` 和 `h` 很难分析 [27]。一个指导原则是将 `k` 设为待检测变化值（以标准差衡量）的一半，将 `h` 设为 `ln(1/δ)`，其中 `δ` 是可接受的虚假警报率；3 到 5 范围内的值是典型的。一般来说，CUSUM 的输入 `z[t]` 可以是任何滤波器残差，例如卡尔曼滤波器的预测误差。

CUSUM 检验的一个变体是 Page-Hinkley 检验：

```
g[t] = g[t-1] + (x[t] - μ - δ)
g_min = min(g_min, g[t])
if g[t] - g_min > λ then alarm
```

这些公式是单侧的，因为它们仅在均值增加时发出警报。通过对称性可以轻松推导出双侧版本，见练习 5.3。

### 5.3.3 统计检验

统计检验是一种判断关于总体定量特征的假设是真还是假的程序。我们通过从相关总体中抽取随机样本，并计算其项目上的适当统计量来检验此类假设。如果在这样做的过程中，我们获得了一个在假设为真时极少出现的统计量值，我们就有理由拒绝该假设。

为了检测变化，我们需要比较两个数据源，并判断假设 `H[0]`（即它们来自同一分布）是否为真。假设我们有两个总体的平均值和标准差的估计值

```
μ̂_0, σ̂_0
```

和

```
μ̂_1, σ̂_1
```

这两个总体来自等大小的样本。如果两个总体中的分布相同，这些估计值应当是一致的。否则，假设检验应拒绝 `H[0]`。构建此类假设检验有几种方法。最简单的一种是研究差值

```
μ̂_0 - μ̂_1
```

对于大样本，它满足

```
(μ̂_0 - μ̂_1) / sqrt(σ̂_0²/n + σ̂_1²/n) ~ N(0, 1)
```

例如，假设我们想利用统计检验设计一个变化检测器，其虚假警报概率为 5%，即

```
P(|Z| > threshold) = 0.05
```

高斯分布表显示 `P(X < 1.96) = 0.975`，因此检验变为

```
|μ̂_0 - μ̂_1| > 1.96 * sqrt(σ̂_0²/n + σ̂_1²/n)
```

在流挖掘的情况下，这两个总体是流的两个不同部分，`H[0]` 是这两个部分具有相同分布的假设。不同的实现可能在于它们如何选择要比较的流部分。例如，我们可以固定一个不滑动的参考窗口，和一个每个时间步滑动 1 个单位的滑动窗口。参考窗口的平均值为

```
μ̂_ref
```

滑动窗口的平均值为

```
μ̂_slide
```

当基于这两个估计值检测到变化时，当前滑动窗口成为参考窗口，并使用后续元素创建一个新的滑动窗口。除其他参数外，该方法的性能取决于所选两个窗口的大小。

我们可以对方差执行 `χ²检验` 来代替基于正态分布的检验，因为

```
(n-1) * σ̂² / σ² ~ χ²(n-1)
```

由此可以构建标准的假设检验。

还可以从 Hoeffding 不等式导出另一种检验，前提是分布的值在某个范围内，例如 `[0, 1]`。假设我们有两个总体（如窗口），大小分别为 `n[0]` 和 `n[1]`。定义它们的调和平均数 `n = 1/(1/n[0] + 1/n[1])` 以及

```
ε = sqrt( (1/(2n)) * ln(1/δ) )
```

我们有：

*   如果 `H[0]` 为真且 `μ[0] = μ[1]`，则

```
P(|μ̂_0 - μ̂_1| > ε) < δ
```

*   反之，如果 `H[0]` 为假且 `|μ[0] − μ[1]| > ε`，则

```
P(|μ̂_0 - μ̂_1| < ε) < δ
```
