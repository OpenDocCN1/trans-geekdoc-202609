
```
GET http://netbank.com/transfer.do?acct=AttackerA&amount=$200 HTTP/1.1
```

然后攻击者可将此请求嵌入到一个看似无害的链接中：

```html
<a href="http://netbank.com/transfer.do?acct=AttackerA&amount=$200">Read more!</a>
```

攻击者的下一步是通过电子邮件将此链接发送给尽可能多的银行客户。任何在登录银行账户时点击该链接的人，都可能无意中向黑客转账 200 美元。如果银行仅使用 `POST` 请求，则使用 `<a>` href 标签执行的恶意请求无法成功。尽管如此，攻击者仍可结合自动执行的嵌入式 JavaScript 使用 `<form>` 标签。

例如：

```html
<body onload="document.forms[0].submit()">
<form action="http://netbank.com/transfer.do" method="POST">
<input type="hidden" name="acct" value="AttackerA"/>
<input type="hidden" name="amount" value="$100"/>
<input type="submit" value="View my pictures!"/>
</form>
</body>
```

# CSRF 攻击预防与缓解

有多种方法可以预防和缓解 CSRF 攻击。对于用户而言，可以通过拒绝未经授权的行为者访问应用程序以及保护其登录凭据来预防 CSRF 攻击。

以下是一些很好的实践：

- 使用安全的密码和用户名
- 不使用 Web 应用程序时及时注销
- 防止浏览器记住密码
- 登录应用程序时避免同时浏览其他网站

Web 应用程序也可以利用可用的解决方案来阻止恶意流量并制止攻击。一种常见的缓解方法是为每个 ID 或会话请求创建随机令牌。服务器随后会检查并验证这些令牌。任何缺少值或包含重复令牌的会话请求都会被阻止。如果请求与其会话 ID 的令牌不匹配，也会被阻止访问应用程序。CSRF 攻击也可以通过双重提交 Cookie 的方法来阻止。就像上述方法一样，请求参数和 Cookie 都被分配了随机令牌。在授予应用程序访问权限之前，服务器必须确保令牌匹配。令牌并非 100% 有效。

## 第 21 章：结构化查询语言 (SQL) 注入

**SQL 注入** 或 **SQLI** 是指使用恶意 SQL 代码操纵后端数据库，以访问敏感信息（私人客户详情、用户列表等）。SQL 注入对企业的影响可能非常大。如果此类攻击成功，未经授权的人员可能查看用户列表，整个表可能被删除，在极端情况下，攻击者可能获得数据库的管理员权限。在谈论组织因 SQLI 而遭受的损失时，必须提及如果个人信息（信用卡详情、地址和电话号码）被盗，将导致与客户的关系受损。任何 SQL 数据库都可能遭受此攻击，但网站是最常见的目标。SQL 是用于访问和操作数据库的标准化语言，旨在为每个用户创建可定制的视图。SQL 查询有助于执行记录删除、数据检索和更新等命令。有不同的 SQL 元素用于执行这些任务。以下是电子商店典型的 SQL 数据库查询：

```
SELECT ItemName, ItemDescription
FROM Item
WHERE ItemNumber = ItemNumber
```

根据此查询，Web 应用程序创建一个字符串查询，并将其作为一条 SQL 语句发送到数据库：

```
sql_query = "
SELECT ItemName, ItemDescription
FROM Item
WHERE ItemNumber = " & Request.QueryString("ItemID")
```

用户提供的输入 `http://www.estore.com/items/items.asp?itemid=999` 随后生成此查询：

```
SELECT ItemName, ItemDescription
FROM Item
WHERE ItemNumber = 999
```

从语法可以看出，此查询返回物品编号 999 的描述。

## SQL 注入示例

当攻击者想要实施 SQLI 时，他们会使用典型的 SQL 查询来利用数据库中未经验证的输入漏洞。攻击者可以通过多种方式执行此攻击向量，此处列举部分示例。上述输入例如提取特定产品的信息。它可以被更改为 `http://www.estore.com/items/items.asp?itemid=999 or 1=1`

相应的 SQL 查询将变为：

```
SELECT ItemName, ItemDescription
FROM Items
WHERE ItemNumber = 999 OR 1=1
```

`1=1` 是一个永远为真的语句，因此该查询将返回数据库中每一个物品的名称和描述，包括那些你无权访问的。

攻击者还可以利用过滤不当的字符来更改 SQL 命令——这包括用于分隔字段的分号。例如，此输入 `http://www.estore.com/items/iteams.asp?itemid=999; DROP TABLE Users` 将生成如下 SQL 查询：

```
SELECT ItemName, ItemDescription
FROM Items
WHERE ItemNumber = 999; DROP TABLE USERS
```

这可能导致用户数据库被删除。

## SQLI 缓解与预防

你可以通过多种方式防止 SQLI 攻击的发生，并在攻击发生时进行防护。

一些最佳方法包括：

- **输入清理/验证** —— 编写能够识别非法用户输入的代码。这是一个好习惯，但仍不是 100% 有效。
- **WAF (Web 应用程序防火墙)** —— 它能在其他网络威胁中过滤掉 SQLI。

## 第 22 章：DNS 欺骗

**DNS (域名服务器) 欺骗** 也称为 **DNS 缓存投毒**。这是一种利用篡改的 DNS 记录将流量重定向到恶意网站而非预期网站的攻击。这个欺诈网站看起来与合法网站非常相似。一旦受害者进入攻击者的网站，就会被提示登录看起来像是他们自己的账户。在此过程中，恶意行为者窃取用户的敏感信息和登录凭据。此外，攻击者还可以在用户计算机上安装病毒或蠕虫，从而长期访问其他类型的数据。

DNS 欺骗攻击可以通过特定方法执行，包括：

- **中间人攻击 (MITM)**：攻击者拦截 DNS 服务器与用户之间的通信，并将受害者路由到欺诈性 IP 地址。
- **DNS 服务器入侵**：攻击者直接劫持 DNS 服务器并将其配置为返回欺诈性 IP 地址。

在本例中，攻击者（IP 为 `192.168.6.300`）拦截了 `www.estores.com` 的服务器计算机（IP 为 `192.168.4.200`）与其客户端（IP 为 `192.168.1.100`）之间的通信通道。在这种情况下，客户端被 `arpspoof` 等工具欺骗，误以为攻击者的 IP 地址是服务器的。同样，服务器也被欺骗，误以为攻击者的 IP 地址是客户端的。

过程如下：

1. 攻击者使用 `arpspoof` 发出此命令：`arpspoof 192.168.1.100 192.168.2.200`。服务器 ARP 表中的 MAC IP 地址被修改，使其认为攻击者的 PC 是客户端。
2. 攻击者再次使用 `arpspoof` 发出此命令：`arpspoof 192.168.2.200 192.168.1.100`。这使客户端认为攻击者的 PC 属于服务器。
3. 攻击者的下一步是发出 Linux 命令：`echo 1 > /proc/sys/net/ipv4/ip_forward`，以便在服务器和客户端之间交换的数据包被转发到攻击者的计算机。
4. 攻击者在其本地计算机上创建主机文件 `estores.com 192.168.3.300`。它将合法网站映射到其本地 IP。
5. 攻击者在本地计算机的 IP 地址上创建 Web 服务器，并建立一个外观类似合法网站的恶意网站。
6. 最后，攻击者使用 `dnsspoof` 等工具，将所有 DNS 请求定向到其本地主机文件。当用户尝试访问真实网站时，会弹出虚假网站，当他们与之交互时，其计算机会感染恶意软件。

## 第 24 章：网页抓取

这是指使用机器人从网站提取数据和内容。它不同于屏幕抓取，因为它不是复制屏幕上的像素，而是连同数据库中的数据一起提取底层的 HTML 代码。随后，抓取器可能在别处复制该网站内容。

有许多类型的数字业务依赖数据采集，并为此使用网页抓取。一些合法用途包括：

- 搜索引擎机器人抓取网站以分析其内容用于排名。
- 比价网站部署机器人从卖家网站获取产品描述和价格。
- 市场研究机构可能使用抓取器从社交媒体和论坛获取数据。

网页抓取可能被不法分子用于非法目的，如窃取受版权保护的内容和恶意压价。此类行为可能给在线实体带来严重后果，如经济损失——如果业务是内容分发商或依赖竞争性定价模型，后果更甚。

**抓取工具和模型** 是设计用于遍历数据库并获取数据的软件。会使用不同类型的机器人。它们被定制用于：

- 识别独特的 HTML 网站结构
- 存储抓取的数据
- 提取 API 信息
- 提取并修改内容

所有类型的抓取机器人都旨在从网站访问数据，因此很难区分恶意机器人和合法机器人。不过，有两个主要区别可能有助于区分两者：

- 如果机器人是合法的，它会标识使用它的公司。以 `Googlebot` 为例。在 HTTP 头中，它标识自己为 Google。
- 可疑机器人伪装成真实流量并创建虚假的 HTTP 用户代理。
- 来自合法组织的机器人遵守网站的 `robot.txt` 文件，其中列出了机器人可以访问和不能访问的所有页面。
- 恶意机器人抓取网站时不顾及任何允许规则。

运行网页抓取机器人需要大量资源。当攻击者无法承担这些资源时，会选择僵尸网络。

## 第 25 章：中间人 (MITM) 攻击

这是一个通用术语，指攻击者拦截应用程序与用户之间的对话。攻击者可以伪装成其中一方或窃听，使对话看起来正常。中间人攻击（MITM）的目的是窃取信用卡号、账户详情、登录凭证和其他敏感信息。攻击者通常针对电商网站、SaaS 企业、金融应用及其他需要登录的网站的用户。攻击者收集的信息可用于未经授权的密码修改、非法资金转移和身份盗窃。此外，攻击者可在高级持续性威胁（APT）的渗透阶段利用它在安全网络中建立立足点。为了更好地理解 MITM 攻击，可以想象邮递员查看你的银行对账单，记下你的详细信息，然后重新封好信封投递给你。成功的 MITM 攻击有两个不同阶段：拦截和解密。在第一步中，攻击者利用其网络在用户流量到达预期目的地之前将其拦截。最简单且最常见的方法是创建恶意的免费 Wi-Fi 热点并向公众开放。这些热点通常不受密码保护。当用户将设备连接到此网络时，攻击者即可访问其在线数据交换。部分攻击者可能倾向于通过以下方法采取主动方式：

- **IP 欺骗**：攻击者更改 IP 地址数据包头部并伪装成应用程序。任何尝试访问该应用程序 URL 的用户都会被重定向到攻击者的网站。
- **ARP 欺骗**：攻击者使用伪造的 ARP 消息将合法用户的 IP 地址与其 MAC 地址关联。一旦发生这种情况，本应从用户发往主机 IP 地址的数据会转发给攻击者。
- **DNS 欺骗**：攻击者渗透 DNS 服务器并更改网站的地址记录。

拦截步骤成功后，必须在应用程序和用户不知情的情况下隐蔽地解密双向 SSL 流量。有几种实现方法：

- **HTTPS 欺骗**：在首次成功连接到安全网站后，向受害者的浏览器发送伪造证书。
- **SSL BEAST**：将恶意 JavaScript 注入用户计算机，从而拦截从 Web 应用程序发送的任何加密 Cookie。
- **SSL 劫持**：在 TCP 握手期间，攻击者向应用程序和用户传递伪造的认证密钥。
- **SSL 剥离**：将 HTTPS 连接降级为 HTTP。

- 留意浏览器关于不安全网站的警告
- 始终从应用程序登出

## 第 26 章：定向钓鱼攻击

这是一种社会工程学攻击，攻击者伪装成受信任的个人，诱骗受害者点击短信或伪造邮件中的恶意链接。用户随后在不知情的情况下在其计算机/网络上安装恶意软件、执行 APT 的第一阶段或泄露敏感信息等。虽然定向钓鱼看起来像鲸钓攻击和普通钓鱼，但它与典型的社会工程学攻击略有不同，且执行方式异常。因此，在制定安全策略时需要给予特别关注。以下是一个定向钓鱼攻击及其后果的示例。一名声称代表数据库管理 SaaS 提供商 `www.itservices.com` 的人员向企业系统管理员发送伪造邮件。他使用的邮件模板属于 `itservices.com`。邮件称 `itservices.com` 正在限时提供一项新服务，并邀请用户使用附带链接注册。系统管理员点击链接后，会被带到一个网站 `itservice.com` 的登录页面，该页面酷似 `itservices.com` 的注册页面。此时，攻击者在系统管理员的计算机上安装了控制与命令代理。随后，攻击者可将其作为后门进入企业网络并执行 APT 的第一阶段。

## 钓鱼攻击、鲸钓攻击与定向钓鱼攻击的对比

鲸钓攻击、钓鱼攻击和定向钓鱼攻击在目标受害者和复杂程度上有所不同。在钓鱼攻击中，攻击者伪装成受信任方向尽可能多的用户发送恶意邮件。例如，攻击者可能发送一封看似来自 PayPal 的邮件，要求用户点击链接验证凭证，这可能导致恶意软件安装在接收者计算机上。钓鱼邮件通常不具个性化，包含拼写错误等失误，且批量发送。许多人从未注意到这些提示。定向钓鱼邮件难以检测，它们看起来像来自目标身边的人，且邮件内容个性化。鲸钓攻击针对组织高层的决策者，这些高管可访问管理员账户密码、商业机密等高度敏感信息。攻击者伪装成组织或个人（如客户）发送邮件。鲸钓攻击利用来自新闻、网站或社交媒体的信息针对特定个人。虽然鲸钓攻击针对高层个人，但定向钓鱼攻击的目标则是低调的目标。

## 定向钓鱼攻击缓解措施

- **双因素认证**：要求用户通过两层/步骤验证。
- **密码管理策略**：确保员工不在恶意网站上使用企业密码。
- **教育活动**：培训员工并提高安全意识。

## 第 27 章：Rootkit
