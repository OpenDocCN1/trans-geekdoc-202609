
```
if x := f(); x == 0 {
    fmt.Println(x)
} else if y := g(x); x == y {
    fmt.Println(x, y)
} else {
    fmt.Println(x, y)
}
fmt.Println(x, y) // 编译错误: x 和 y 在此处不可见
```

第二个 `if` 语句嵌套在第一个内部，因此在第一个语句的初始化子句中声明的变量在第二个语句中可见。`switch` 语句的每个 case 也适用类似规则：条件有一个块，每个 case 主体也有一个块。

在包级别，声明出现的顺序不影响其作用域，因此声明可以引用其自身或后面出现的另一个声明，从而允许声明递归或相互递归的类型和函数。不过，如果常量或变量声明引用其自身，编译器会报错。

在以下程序中：

```
if f, err := os.Open(fname); err != nil { // 编译错误: unused: f
    return err
}
f.ReadByte() // 编译错误: undefined f
f.Close()    // 编译错误: undefined f
```

`f` 的作用域仅限于 `if` 语句，因此后续语句无法访问 `f`，导致编译错误。视编译器而定，可能会额外报告局部变量 `f` 未被使用的错误。

因此，通常需要在条件之前声明 `f`，以便后续访问：

```
f, err := os.Open(fname)
if err != nil {
    return err
}
f.ReadByte()
f.Close()
```

你可能想通过将 `ReadByte` 和 `Close` 调用移至 `else` 块，来避免在外层块声明 `f` 和 `err`：

```
if f, err := os.Open(fname); err != nil {
    return err
} else {
    // f 和 err 在此处也可见
    f.ReadByte()
    f.Close()
}
```

但 Go 的常规做法是在 `if` 块中处理错误并返回，使成功执行路径保持不缩进。

短变量声明要求对作用域有清醒的认识。请看下面的程序，它首先获取当前工作目录并保存在包级变量中。这可以在 `main` 函数中调用 `os.Getwd` 完成，但最好将此关注点与主要逻辑分离，特别是当获取目录失败属于致命错误时。函数 `log.Fatalf` 会打印消息并调用 `os.Exit(1)`。

```
var cwd string

func init() {
    cwd, err := os.Getwd() // 编译错误: unused: cwd
    if err != nil {
        log.Fatalf("os.Getwd failed: %v", err)
    }
}
```

由于 `init` 函数块中尚未声明 `cwd` 和 `err`，`:=` 语句将它们俩都声明为局部变量。内层的 `cwd` 声明使外层的包级 `cwd` 不可访问，导致该语句未能按预期更新包级 `cwd` 变量。

当前的 Go 编译器会检测到局部 `cwd` 变量从未使用并报错，但规范并未强制要求此检查。此外，微小的改动（如增加一条引用局部 `cwd` 的日志语句）就会绕过该检查。

```
var cwd string

func init() {
    cwd, err := os.Getwd() // 注意: 错误!
    if err != nil {
        log.Fatalf("os.Getwd failed: %v", err)
    }
    log.Printf("Working directory = %s", cwd)
}
```

全局 `cwd` 变量保持未初始化状态，而看似正常的日志输出掩盖了该 Bug。

有多种方法可以处理这个潜在问题。最直接的方法是避免使用 `:=`，而是在单独的 `var` 声明中声明 `err`：

```
var cwd string

func init() {
    var err error
    cwd, err = os.Getwd()
    if err != nil {
        log.Fatalf("os.Getwd failed: %v", err)
    }
}
```

我们现在已经了解了包、文件、声明和语句如何表达程序的结构。在接下来的两章中，我们将探讨数据的结构。

# 3. 基本数据类型

归根结底，一切皆比特，但计算机从根本上操作的是称为*字*的固定大小数字，它们被解释为整数、浮点数、位集或内存地址，然后组合成更大的聚合体，以表示数据包、像素、投资组合、诗歌以及其他一切事物。Go 提供了多种组织数据的方式，拥有一系列数据类型，一端匹配硬件特性，另一端提供程序员方便表示复杂数据结构所需的功能。

Go 的类型分为四类：*基本类型*、*聚合类型*、*引用类型*和*接口类型*。基本类型是本章的主题，包括数字、字符串和布尔值。聚合类型——数组（§4.1）和结构体（§4.4）——通过组合多个更简单的值来形成更复杂的数据类型。引用类型是一个多样化的群体，包括指针（§2.3.2）、切片（§4.2）、映射（§4.3）、函数（第 5 章）和通道（第 8 章），但它们的共同点是都*间接*引用程序变量或状态，因此对某个引用应用的操作效果会被该引用的所有副本观察到。最后，我们将在第 7 章中讨论接口类型。

## 3.1 整数

Go 的数值数据类型包括多种大小的整数、浮点数和复数。每种数值类型决定了其值的大小和符号性。让我们从整数开始。

Go 同时提供有符号和无符号整数运算。有四种不同大小的有符号整数——8、16、32 和 64 位——分别由类型 `int8`、`int16`、`int32` 和 `int64` 表示，以及对应的无符号版本 `uint8`、`uint16`、`uint32` 和 `uint64`。

还有两种类型仅称为 `int` 和 `uint`，它们是在特定平台上有符号和无符号整数的自然或最高效大小；`int` 是迄今为止使用最广泛的数值类型。这两种类型具有相同的大小，要么是 32 位，要么是 64 位，但不能假设是哪一种；即使在相同的硬件上，不同的编译器也可能做出不同的选择。

类型 `rune` 是 `int32` 的同义词，通常表示某个值是 Unicode 码点。这两个名称可以互换使用。类似地，类型 `byte` 是 `uint8` 的同义词，强调该值是一段原始数据，而不是一个微小的数值。

最后，还有一种无符号整数类型 `uintptr`，其宽度未指定，但足以容纳指针值的所有位。`uintptr` 类型仅用于底层编程，例如在 Go 程序与 C 库或操作系统的边界处。当我们在第 13 章处理 `unsafe` 包时将会看到相关示例。

无论其大小如何，`int`、`uint` 和 `uintptr` 都与其显式指定大小的同类类型不同。因此 `int` 与 `int32` 不是同一类型，即使整数的自然大小是 32 位，将 `int` 值用于需要 `int32` 的地方（反之亦然）也需要显式转换。

有符号数采用二进制补码形式表示，其中高位保留用于数字的符号，*n* 位数字的取值范围是从 −2^(*n*−1) 到 2^(*n*−1)−1。无符号整数将所有位用于非负值，因此取值范围是 0 到 2^(*n*)−1。例如，`int8` 的范围是 −128 到 127，而 `uint8` 的范围是 0 到 255。

Go 的算术、逻辑和比较二元运算符按优先级递减顺序列在下面：

```
*    /    %    <<    >>    &    &^
+    -    |    ^
==   !=   <    <=    >     >=
&&
||
```

二元运算符只有五级优先级。同一级别的运算符从左结合，因此为了清晰起见，或者为了使运算符按预期顺序求值（如表达式 `mask & (1 << 28)`），可能需要使用括号。

例如，上表前两行中的每个运算符（如 `+`）都有一个对应的*赋值运算符*（如 `+=`），可用于缩短赋值语句。

整数算术运算符 `+`、`-`、`*` 和 `/` 可用于整数、浮点数和复数，但取余运算符 `%` 仅适用于整数。不同编程语言中 `%` 对负数的行为各异。在 Go 中，余数的符号总是与被除数的符号相同，因此 `-5%3` 和 `-5%-3` 结果都是 `-2`。`/` 的行为取决于其操作数是否为整数，因此 `5.0/4.0` 是 `1.25`，但 `5/4` 是 `1`，因为整数除法会将结果向零截断。

如果算术运算的结果（无论有符号还是无符号）所需的位数超过了结果类型所能表示的范围，则称为*溢出*。无法容纳的高位会被静默丢弃。如果原始数字是有符号类型，当最高位为 1 时结果可能为负，如下面的 `int8` 示例所示：

```
var u uint8 = 255
fmt.Println(u, u+1, u*u) // "255 0 1"

var i int8 = 127
fmt.Println(i, i+1, i*i) // "127 -128 1"
```

两个相同类型的整数可以使用下面的二元比较运算符进行比较；比较表达式的类型是布尔值。

| `==` | 等于 |
| --- | --- |
| `!=` | 不等于 |
| `<` | 小于 |
| `<=` | 小于或等于 |
| `>` | 大于 |
| `>=` | 大于或等于 |

事实上，所有基本类型的值——布尔值、数字和字符串——都是*可比较的*，这意味着相同类型的两个值可以使用 `==` 和 `!=` 运算符进行比较。此外，整数、浮点数和字符串是*有序的*，可由比较运算符排序。许多其他类型的值不可比较，也没有其他类型是有序的。随着我们遇到每种类型，将介绍其值的*可比较性*规则。

还有单目加法和减法运算符：

| `+` | 单目正号（无效果） |
| --- | --- |
| `-` | 单目负号（取反） |

对于整数，`+x` 是 `0+x` 的简写，`-x` 是 `0-x` 的简写；对于浮点数和复数，`+x` 就是 `x`，`-x` 是 `x` 的取反。

Go 还提供以下按位二元运算符，前四个将操作数视为位模式，不涉及算术进位或符号概念：

| `&` | 按位与 |
| --- | --- |
| `|` | 按位或 |
| `^` | 按位异或 |
| `&^` | 位清除（AND NOT） |
| `<<` | 左移 |
| `>>` | 右移 |

### 位运算

当作为二元运算符使用时，运算符 `^` 是按位异或 (XOR)；但当作为一元前缀运算符使用时，它是按位取反或补码；也就是说，它返回一个值，该值的操作数中每一位都被取反。`&^` 运算符是位清除 (AND NOT)：在表达式 `z = x &^ y` 中，如果 `y` 对应的位为 1，则 `z` 的每一位为 0；否则它等于 `x` 对应的位。

下面的代码展示了如何使用位运算将 `uint8` 值解释为一组紧凑且高效的 8 个独立位。它使用 `Printf` 的 `%b` 动词来打印数字的二进制位；`08` 修饰 `%b`（一个副词！）以零填充结果，使其恰好为 8 位数字。

```
var x uint8 = 1<<1 | 1<<5
var y uint8 = 1<<1 | 1<<2

fmt.Printf("%08b\n", x)    // "00100010", 集合 {1, 5}
fmt.Printf("%08b\n", y)    // "00000110", 集合 {1, 2}

fmt.Printf("%08b\n", x&y)  // "00000010", 交集 {1}
fmt.Printf("%08b\n", x|y)  // "00100110", 并集 {1, 2, 5}
fmt.Printf("%08b\n", x^y)  // "00100100", 对称差集 {2, 5}
fmt.Printf("%08b\n", x&^y) // "00100000", 差集 {5}

for i := uint(0); i < 8; i++ {
    if x&(1<<i) != 0 { // 成员测试
        fmt.Println(i) // "1", "5"
    }
}

fmt.Printf("%08b\n", x<<1) // "01000100", 集合 {2, 6}
fmt.Printf("%08b\n", x>>1) // "00010001", 集合 {0, 4}
```

（第 6.5 节 展示了整数集合的实现，其大小可以远超一个字节。）

在移位运算 `x<<n` 和 `x>>n` 中，`n` 操作数决定移位的位数，且必须是无符号数；`x` 操作数可以是无符号或有符号数。从算术上讲，左移 `x<<n` 等同于乘以 2^(`n`)，右移 `x>>n` 等同于除以 2^(`n`) 后向下取整。

左移用零填充空出的位，无符号数的右移也是如此，但有符号数的右移用符号位的副本填充空出的位。因此，当你将整数视为位模式处理时，使用无符号运算非常重要。

尽管 Go 提供了无符号数和运算，但我们倾向于使用有符号的 `int` 形式，即使对于不可能为负的量，例如数组的长度，尽管 `uint` 似乎是更明显的选择。确实，内置的 `len` 函数返回有符号的 `int`，如这个按逆序宣布奖牌的循环所示：

```
medals := []string{"gold", "silver", "bronze"}
for i := len(medals) - 1; i >= 0; i-- {
    fmt.Println(medals[i]) // "bronze", "silver", "gold"
}
```

另一种做法将是灾难性的。如果 `len` 返回无符号数，那么 `i` 也将是 `uint`，且根据定义，条件 `i >= 0` 永远为真。在第三次迭代（此时 `i == 0`）之后，`i--` 语句将导致 `i` 变为不是 −1，而是最大的 `uint` 值（例如 2⁶⁴−1），并且对 `medals[i]` 的求值将在运行时失败，或 *panic*（§5.9），因为它试图访问切片边界之外的元素。

因此，无符号数通常仅在需要其位运算符或特殊算术运算符时使用，例如实现位集、解析二进制文件格式，或用于哈希和加密。它们通常不用于仅仅是非负的量。

通常，将值从一种类型转换为另一种类型需要显式转换，并且算术和逻辑的二元运算符（移位除外）必须具有相同类型的操作数。虽然这偶尔会导致表达式变长，但它也消除了一整类问题，并使程序更易于理解。

作为一个从其他上下文中熟悉的例子，考虑以下序列：

```
var apples int32 = 1
var oranges int16 = 2
var compote int = apples + oranges // 编译错误
```

尝试编译这三个声明会产生一条错误消息：

```
invalid operation: apples + oranges (mismatched types int32 and int16)
```

这种类型不匹配可以通过几种方式修复，最直接的方法是将所有内容转换为通用类型：

```
var compote = int(apples) + int(oranges)
```

正如 §2.5 所述，对于每种类型 `T`，转换操作 `T(x)` 会在允许转换的情况下将值 `x` 转换为类型 `T`。许多整数到整数的转换不会导致值的任何变化；它们只是告诉编译器如何解释该值。但将大整数收窄为较小整数的转换，或整数到浮点数或反之的转换，可能会改变值或丢失精度：

```
f := 3.141 // 一个 float64
i := int(f)
fmt.Println(f, i)   // "3.141 3"
f = 1.99
fmt.Println(int(f)) // "1"
```

浮点数到整数的转换会丢弃任何小数部分，向零截断。你应该避免操作数超出目标类型范围的转换，因为其行为取决于实现：

```
f := 1e100  // 一个 float64
i := int(f) // 结果取决于实现
```

任意大小和类型的整数字面量可以写作普通十进制数，如果以 `0` 开头则写作八进制数，如 `0666`，或者如果以 `0x` 或 `0X` 开头则写作十六进制数，如 `0xdeadbeef`。十六进制数字可以是大写或小写。如今八进制数似乎只用于一个目的——POSIX 系统上的文件权限——但十六进制数被广泛用于强调数字的位模式而非其数值。

使用 `fmt` 包打印数字时，我们可以使用 `%d`、`%o` 和 `%x` 动词控制基数和格式，如以下示例所示：

```
o := 0666
fmt.Printf("%d %[1]o %#[1]o\n", o) // "438 666 0666"
x := int64(0xdeadbeef)
fmt.Printf("%d %[1]x %#[1]x %#[1]X\n", x)
// 输出：
// 3735928559 deadbeef 0xdeadbeef 0XDEADBEEF
```

请注意两个 `fmt` 技巧的使用。通常包含多个 `%` 动词的 `Printf` 格式字符串需要相同数量的额外操作数，但 `%` 后的 `[1]` “副词”告诉 `Printf` 反复使用第一个操作数。其次，`%o`、`%x` 或 `%X` 的 `#` 副词分别告诉 `Printf` 输出 `0`、`0x` 或 `0X` 前缀。

Rune 字面量写作单引号内的字符。最简单的例子是 ASCII 字符，如 `'a'`，但也可以直接或通过数字转义写入任何 Unicode 码点，我们稍后将看到。

Rune 使用 `%c` 打印，如果需要带引号则使用 `%q`：
