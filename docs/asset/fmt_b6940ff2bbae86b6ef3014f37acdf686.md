## 区块链应用程序的测试计划策略

### 有效的测试策略需要充分的规划

规划是项目的一个基本方面，应在区块链开发的早期阶段予以考虑。这种方法使测试环境向前迈进了一大步，从而产出高质量的最终产品和有效的测试程序。为了实施高效的测试方法，拥有详细信息非常重要。这些信息应包括测试范围、覆盖率、限制、持续时间和所用工具的详细情况。这些信息将在项目的每个测试阶段发挥关键作用，并帮助团队高效地构建和监督测试流程。适当的文档记录是测试策略的一部分，它帮助团队在测试区块链应用时遵循既定顺序。根据测试场景，测试方法论由组织酌情设计。

在开始项目前分析和理解项目需求也很重要。同样，测试也始于需求，这些需求必须经过仔细分析，以便推进各个测试阶段。对应用有深入了解的测试人员能更精确地测试区块链应用所需的特性。因此，拥有针对不同区块链应用平台的工具和技术的广泛技能组合的测试人员是宝贵的组织资产。此外，当前部署的大多数区块链应用使用 API 协议作为编程接口，这要求测试人员也要具备足够的 API 测试技能 [27]。

### 改进测试策略的机会

测试是一个重复的过程，涉及尽最大可能发现缺陷和漏洞。每次测试都能提供更好的输出，然后多次迭代以达到预期结果。改进测试策略取决于考虑导致故障的各种输入事件。由输入事件引起的故障需要被跟踪和监控，以获得更好的测试性能。对于给定的测试场景，可能存在多个输入事件。在测试区块链应用时，这些输入事件应被视为关键考量因素。

*   **服务启动**：有时应用在测试的早期阶段启动服务时就会失败。换句话说，应用无法调用待测试的服务。这是一个重要的输入事件，需要足够的测试范围，即确保具有长时间运行服务的应用在重启服务时不会失败。

*   **节点不可达**：这是在网络和单个站点上都常见的场景。不可达的节点会导致测试失败。导致此类故障的原因可能多种多样。因此，应部署使用导致故障的网络错误输入进行测试。同时也应熟练使用适当的工具以达到预期输出。

*   **应用配置变更**：基于系统需求，任何应用的配置变更都非常频繁。事实上，先进的系统可以自动检测配置变更。这种类型的测试事件要求测试有效和无效的配置，以最终获得稳定且功能完善的应用。

*   **节点添加**：对于区块链应用，任何节点添加都会产生一个触发器。作为测试范围的一部分，测试向网络添加节点至关重要。测试应重点关注节点添加方面的正向和负向测试场景 [14, 31]。

### 回归测试

回归测试要求重新执行功能和非功能测试，以帮助确保先前开发的软件模块在变更后仍能按预期工作。这需要自动化工具和软件来运行测试套件。这些工具也用于维护和处理应用的功能。选择作为回归套件一部分执行的测试用例需要时间。测试用例分析完成后，会形成用于测试的测试子集顺序。开发回归套件的目的是优化应用中常用的功能。由于其迭代过程，回归测试的输出是高效的。应用可能包含广泛的测试场景，但优先考虑以业务为中心的测试场景对于通过回归测试获得最佳结果非常重要。

如前所述，测试人员的角色是尽最大可能发现故障。测试人员的重点是在回归测试的早期阶段跟踪和监控发现的故障。任何待测试的应用都需要测试人员对其功能有敏锐的了解。因此，测试人员探索应用功能以了解所需的测试场景覆盖率至关重要。报告故障和错误是有效测试过程的基本要素。因此，高严重级别的故障应立即报告。

### 自动化测试

自动化测试确保区块链开发中的持续交付流程，允许开发人员将变更部署到生产环境中。对于大多数项目而言，时间表是重中之重，自动化测试有助于将项目发布和推向实时环境。考虑到项目的时间敏感性，高质量测试套件的快速实施提高了开发人员的生产力。

每个团队成员应根据各种业务功能的需要执行代码变更。代码变更直接影响测试过程，尤其是在自动化测试方面。代码和版本变更需要在一个适应性强且经常变化的业务流程中实现自动化。持续集成 (CI) 对开发和测试周期中的所有团队都至关重要。持续集成的原因是确保开发和测试团队都了解项目的进度，以保持在同一轨道上。自动化对开发团队是一大福音，因为代码审查所需的时间显著减少。因此，可以投入更多时间开发额外功能。简而言之，自动化测试有助为开发人员和测试人员创建一个强有力的基线，以构建和实施稳健的区块链应用 [19, 20]。

### 测试管理注意事项

有效的测试管理对于创建和维护一个有组织、受控的测试环境至关重要。管理测试阶段可增强在测试应用程序时对每个步骤进行报告、验证和确认的过程。高效的测试管理取决于对指定应用程序测试需求的透彻理解。测试需求分析有助于制定高效的管理策略以实现预期结果。明确定义的测试覆盖率也有助于获得所需的资源和预算分配。团队成员之间以及与跨职能团队（开发人员和支持团队）的同步有助于实现成功的工作协作环境。有各种工具、平台和代码库可帮助持续地共享和记录项目进度。时间线是测试管理中的一个重要因素，应在项目开始时充分考虑并最终确定。测试策略的实施及其相应的持续时间应在项目的最早阶段宣布。最后，为各种测试程序定义报告标准也很重要，这有助于优化沟通 [3]。

### 用户验收测试

应用程序上线前的最后阶段也应包含一套完整的应用程序测试，以符合设计要求。这些测试应考虑到用户的最终期望以及使用该应用程序的舒适度来执行。因此，该过程必须让用户参与真实场景来测试应用程序。这种方法通常被称为*用户验收测试*或*用户界面测试*。让用户参与此阶段不仅有助于避免与应用程序开发和测试相关的潜在财务和声誉损失，还有助于确保最终用户的接受度。用户测试为组织提供了所需的用户反馈，从而带来应用程序的进一步改进。前几个测试阶段遗留的任何缺陷都可能在用户验收测试期间以及正式上线前被发现 [4]。

参与应用程序测试的最终用户应具备理解该技术的正确知识和技能组合。让合适的用户参与测试有助于根据初始需求和最终应用程序进行高效对比。让主题专家（SME）参与是用户验收测试（UAT）的一种高度推荐的策略。UAT 需要足够的时长以实现其预期结果。虽然执行 UAT 很重要，但记录测试结果和成果对于验收测试同样至关重要。整合整个 UAT 流程需要适当的治理。跟踪和解决发现的故障的最佳模型之一是 RAID（风险、行动、问题和决策） [12]。

## 区块链应用审计考量

持续审计区块链应用的安全性以提供所需的保证级别，确保企业内使用安全的区块链解决方案，这也极为重要。因此，需要采用一个审计框架来协助审计人员验证和审查正在实施的区块链解决方案。

### 区块链解决方案审计框架

由 KPMG（印度）开发的审计框架可以帮助区块链审计师评估与区块链平台相关的特定风险。KPMG 的区块链审计框架由以下审计关注领域组成：

*   **密钥所有权与管理**：该审计领域涉及加密私钥的安全性、传输、维护和存储，以及哈希函数的管理。

*   **互操作性与集成**：该领域的重点在于各区块链平台与企业遗留系统及当前整体 IT 基础设施之间一致且有效的集成。

*   **共识机制**：在此审计模块中，将评估共识协议的设计和性能。其他共识相关考量，例如区块链上的节点如何得到验证，以及变更控制程序，也会由审计团队进行审查。

*   **异构共识合规**：该审计领域检查旨在保持区块链平台合规的适用框架、标准、程序和指南。数据分类和敏感性也在此审计模块中进行评估。

*   **访问与权限管理**：该审计模块重点检查对组和用户权限的监控与管理，以及提供给各种角色的访问级别和控制权。

*   **基础设施与应用管理**：该审计领域关注软件开发的安全实践、区块链应用测试和代码管理。

*   **网络与节点治理**：该审计模块的重点围绕旨在解决资产身份争议和问责制，以及信息保护和交易有效性的治理框架和标准 [7]。

## 总结与结论

区块链技术正朝着全球市场的指数级增长迈进。作为本时代开创性且颠覆性的技术，组织绝不能低估充分测试和将有效审计方法论应用于区块链环境的重要性。随着业务依赖持续转型和客户满意度，若未纳入适当考量就将区块链技术植入企业架构，极可能产生不利影响。因此，在区块链应用的开发生命周期中，应强制执行有效的测试和缺陷管理原则，以实现平滑集成。

本章首先讨论了测试阶段需考虑的测试程序及随之而来的挑战。测试——作为一个过程——核心在于发现缺陷/漏洞。在本章后续章节中，介绍了各类漏洞分类及推荐测试工具。最后，展示并讨论了 `KPMG` 提出的审计框架。利用拟议的审计清单制定有效的审计框架和测试策略，将有助于构建安全的区块链应用。

## 核心概念

*   为了对数字化转型做出积极贡献，区块链技术必须经过成功测试，并与其他软件和技术成功集成。因此，应将在开发生命周期各阶段测试区块链应用的关键性纳入考量，因为这能暴露新区块链应用可能存在的漏洞。

*   为支持区块链应用的高效、高标准发布，应在有效且全面的测试方法论之外，实施质量保证和缺陷管理策略。文中讨论的四步缺陷管理策略有助于确定消除漏洞所应采取的纠正措施。

*   测试区块链应用至关重要，因为一旦区块链交易被处理，便无法撤销。利用本章讨论的工具识别出漏洞后，需对其进行妥善分类和记录。该文档能进一步帮助新开发人员理解漏洞的行为及其发生频率。可用且推荐使用开源工具进行漏洞分析和智能合约分析。不同工具采用不同的漏洞检测技术。例如，`Mythril` 使用控制流检查，`Oyente` 通过源代码分析漏洞，`Securify` 使用基于 `UI` 的界面，`SmartCheck` 分析 `Solidity` 源代码。

*   在采用成熟测试方法论执行测试时，需考虑多个因素，如区块大小、链大小、负载、安全性、数据传输、区块添加及加密安全数据等。根据区块链应用的组件不同，会执行不同的软件测试方法论，如功能测试、API 测试、集成测试、性能/负载测试和安全测试等。

*   区块链测试存在不同的框架和工具。开发人员和测试人员应根据自身需求和目标选择测试区块链的工具和框架。

*   `Truffle` 是一款流行的 `Ethereum` 开发框架。偏好命令行界面的测试人员可使用 `Hyperledger Composer`。`Rust` 程序员可考虑使用 `Exonum` 测试套件对交易逻辑执行测试。本章介绍的所有工具均可在 `Github` 上获取。

*   世界正演变为日常活动迈向自动化环境的阶段。通过实施称为自动化测试的测试模型，降低了区块链应用中人工干预的需求。可能存在需要在固定时间间隔持续测试的业务场景。这些场景实现自动化并接受回归测试。

*   为跟踪和监控测试过程，必须建立高效的测试管理策略。测试管理包括对区块链应用整个测试过程的跟踪和维护。从最终用户视角测试成品应用以获取必要反馈至关重要。根据收到的反馈，部署区块链应用前需分配足够时间解决所有问题。
