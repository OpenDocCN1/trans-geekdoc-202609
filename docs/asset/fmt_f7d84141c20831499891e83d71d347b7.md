
```go
p := Point{1, 2}
pptr := &p
pptr.ScaleBy(2)
fmt.Println(p) // "{2, 4}"
```

或这样：

```go
p := Point{1, 2}
(&p).ScaleBy(2)
fmt.Println(p) // "{2, 4}"
```

但后两种方式显得笨拙。幸运的是，语言对此提供了帮助。如果接收器 `p` 是类型为 `Point` 的变量，但方法需要 `*Point` 接收器，我们可以使用这种简写：

```go
p.ScaleBy(2)
```

编译器会对变量隐式执行 `&p` 操作。这仅适用于变量，包括结构体字段（如 `p.X`）和数组或切片元素（如 `perim[0]`）。我们不能在不可寻址的 `Point` 接收器上调用 `*Point` 方法，因为无法获取临时值的地址。

```go
Point{1, 2}.ScaleBy(2) // 编译错误：无法获取 Point 字面量的地址
```

但我们可以使用 `*Point` 接收器调用像 `Point.Distance` 这样的 `Point` 方法，因为可以通过地址获取值：只需加载接收器指向的值。编译器会为我们隐式插入 `*` 操作。这两个函数调用是等价的：

```go
pptr.Distance(q)
(*pptr).Distance(q)
```

让我们再次总结这三种情况，因为它们是常见的困惑点。在每一个合法的方法调用表达式中，以下三个陈述恰好有一个为真。

要么实参接收器与形参接收器具有相同的类型，例如都是类型 `T` 或都是类型 `*T`：

```go
Point{1, 2}.Distance(q) //  Point
pptr.ScaleBy(2)         // *Point
```

要么实参接收器是类型 `T` 的变量，而形参接收器类型为 `*T`。编译器会隐式获取变量的地址：

```go
p.ScaleBy(2) // 隐式 (&p)
```

或者接收者实参的类型是 `*T`，而接收者形参的类型是 `T`。编译器会隐式地解引用接收者，换句话说，加载该值：

```go
pptr.Distance(q) // implicit (*pptr)
```

如果一个命名类型 `T` 的所有方法的接收者类型都是 `T` 本身（而不是 `*T`），那么复制该类型的实例就是安全的；调用其任何方法必然会产生一个副本。例如，`time.Duration` 的值会被大量复制，包括作为函数参数传递时。但如果有任何方法使用了指针接收者，你应该避免复制 `T` 的实例，因为这样做可能会破坏内部不变量。例如，复制 `bytes.Buffer` 的实例会导致原始值和副本别名引用（§2.3.2）同一个底层字节数组。后续的方法调用将产生不可预测的效果。

### 6.2.1 Nil 是合法的接收者值

正如某些函数允许 `nil` 指针作为参数一样，某些方法也允许其接收者为 `nil`，特别是当 `nil` 是该类型有意义的零值时，就像映射和切片那样。在这个简单的整数链表中，`nil` 代表空列表：

```go
// An IntList is a linked list of integers.
// A nil *IntList represents the empty list.
type IntList struct {
    Value int
    Tail  *IntList
}

// Sum returns the sum of the list elements.
func (list *IntList) Sum() int {
    if list == nil {
        return 0
    }
    return list.Value + list.Tail.Sum()
}
```

当你定义一个其方法允许 `nil` 作为接收者值的类型时，在其文档注释中显式指出这一点是值得的，就像我们上面所做的那样。

这里是 `net/url` 包中 `Values` 类型定义的一部分：

```go
package url

// Values maps a string key to a list of values.
type Values map[string][]string

// Get returns the first value associated with the given key,
// or "" if there are none.
func (v Values) Get(key string) string {
    if vs := v[key]; len(vs) > 0 {
        return vs[0]
    }
    return ""
}

// Add adds the value to key.
// It appends to any existing values associated with key.
func (v Values) Add(key, value string) {
    v[key] = append(v[key], value)
}
```

它将其底层表示作为映射暴露出来，但也提供了简化映射访问的方法，其值是字符串切片——这是一个多重映射。它的客户端可以根据喜好使用其内在操作符（`make`、切片字面量、`m[key]` 等）、其方法，或两者兼用：

```go
m := url.Values{"lang": {"en"}} // direct construction
m.Add("item", "1")
m.Add("item", "2")

fmt.Println(m.Get("lang")) // "en"
fmt.Println(m.Get("q"))    // ""
fmt.Println(m.Get("item")) // "1"      (first value)
fmt.Println(m["item"])     // "[1 2]"  (direct map access)

m = nil
fmt.Println(m.Get("item")) // ""
m.Add("item", "3")         // panic: assignment to entry in nil map
```

在最后一次调用 `Get` 时，`nil` 接收者的行为类似于空映射。我们本可以等价地写成 `Values(nil).Get("item"))`，但 `nil.Get("item")` 无法编译，因为 `nil` 的类型未被确定。相比之下，最后一次调用 `Add` 会引发 panic，因为它试图更新一个 `nil` 映射。

因为 `url.Values` 是一个映射类型，而映射间接引用其键/值对，`url.Values.Add` 对映射元素所做的任何更新和删除对调用者都是可见的。然而，与普通函数一样，方法对引用本身所做的任何更改，如将其设为 `nil` 或使其引用不同的映射数据结构，都不会反映在调用者中。

## 6.3 通过结构体嵌入组合类型

考虑类型 `ColoredPoint`：

```go
import "image/color"

type Point struct{ X, Y float64 }

type ColoredPoint struct {
    Point
    Color color.RGBA
}
```

我们本可以将 `ColoredPoint` 定义为一个包含三个字段的结构体，但我们选择嵌入一个 `Point` 来提供 `X` 和 `Y` 字段。正如我们在第 4.4.3 节所见，嵌入让我们能以一种语法捷径来定义一个包含 `Point` 所有字段以及一些额外字段的 `ColoredPoint`。如果我们愿意，可以在不提及 `Point` 的情况下选择由嵌入的 `Point` 贡献的 `ColoredPoint` 字段：

```go
var cp ColoredPoint
cp.X = 1
fmt.Println(cp.Point.X) // "1"
cp.Point.Y = 2
fmt.Println(cp.Y) // "2"
```

类似的机制适用于 `Point` 的方法。我们可以使用 `ColoredPoint` 类型的接收者来调用嵌入的 `Point` 字段的方法，即使 `ColoredPoint` 没有声明任何方法：

```go
red := color.RGBA{255, 0, 0, 255}
blue := color.RGBA{0, 0, 255, 255}
var p = ColoredPoint{Point{1, 1}, red}
var q = ColoredPoint{Point{5, 4}, blue}
fmt.Println(p.Distance(q.Point)) // "5"
p.ScaleBy(2)
q.ScaleBy(2)
fmt.Println(p.Distance(q.Point)) // "10"
```

`Point` 的方法已被提升到 `ColoredPoint`。通过这种方式，嵌入允许通过多个字段的组合来构建拥有许多方法的复杂类型，每个字段提供几个方法。

熟悉基于类的面向对象语言的读者可能会倾向于将 `Point` 视为基类，将 `ColoredPoint` 视为子类或派生类，或者将这两种类型之间的关系理解为 `ColoredPoint`“是一个” `Point`。但这将是一个错误。请注意上面对 `Distance` 的调用。`Distance` 有一个 `Point` 类型的参数，而 `q` 不是 `Point`，所以虽然 `q` 确实有一个该类型的嵌入字段，但我们必须显式地选择它。尝试传递 `q` 将会报错：

```go
p.Distance(q) // compile error: cannot use q (ColoredPoint) as Point
```

`ColoredPoint` 不是 `Point`，但它“有一个” `Point`，并且它拥有从 `Point` 提升的两个额外方法 `Distance` 和 `ScaleBy`。如果你更倾向于从实现角度思考，嵌入字段指示编译器生成额外的包装方法来委托给声明的方法，等价于以下代码：

```go
func (p ColoredPoint) Distance(q Point) float64 {
    return p.Point.Distance(q)
}

func (p *ColoredPoint) ScaleBy(factor float64) {
    p.Point.ScaleBy(factor)
}
```

当第一个包装方法调用 `Point.Distance` 时，其接收者值是 `p.Point`，而不是 `p`，并且该方法无法访问嵌入了 `Point` 的 `ColoredPoint`。

匿名字段的类型也可以是命名类型的指针，在这种情况下，字段和方法会从被指向的对象间接提升。增加一层间接引用让我们能够共享通用结构并动态地改变对象之间的关系。下面的 `ColoredPoint` 声明嵌入了一个 `*Point`：

```go
type ColoredPoint struct {
    *Point
    Color color.RGBA
}

p := ColoredPoint{&Point{1, 1}, red}
q := ColoredPoint{&Point{5, 4}, blue}
fmt.Println(p.Distance(*q.Point)) // "5"
q.Point = p.Point                 // p and q now share the same Point
p.ScaleBy(2)
fmt.Println(*p.Point, *q.Point) // "{2 2} {2 2}"
```

一个结构体类型可以有多个匿名字段。如果我们像下面这样声明 `ColoredPoint`：

```go
type ColoredPoint struct {
    Point
    color.RGBA
}
```

那么这种类型的值将拥有 `Point` 的所有方法、`RGBA` 的所有方法，以及直接在 `ColoredPoint` 上声明的任何额外方法。当编译器将选择器（如 `p.ScaleBy`）解析为方法时，它首先查找名为 `ScaleBy` 的直接声明方法，然后查找从 `ColoredPoint` 的嵌入字段提升一次的方法，接着查找从 `Point` 和 `RGBA` 内部嵌入字段提升两次的方法，以此类推。如果选择器有歧义，因为有两个方法从同一层级提升，编译器会报错。

方法只能声明在命名类型（如 `Point`）及其指针（`*Point`）上，但得益于嵌入，未命名结构体类型也可以拥有方法，这有时很有用。

这里有个很好的技巧来说明这一点。这个例子展示了一个简单缓存的部分实现，使用了两个包级变量：一个互斥锁（§9.2）和它所保护的映射：

```go
var (
    mu sync.Mutex // guards mapping
    mapping = make(map[string]string)
)

func Lookup(key string) string {
    mu.Lock()
    v := mapping[key]
    mu.Unlock()
    return v
}
```

下面的版本功能等价，但将两个相关变量归组在一个单一的包级变量 `cache` 中：

```go
var cache = struct {
    sync.Mutex
    mapping map[string]string
} {
    mapping: make(map[string]string),
}

func Lookup(key string) string {
    cache.Lock()
    v := cache.mapping[key]
    cache.Unlock()
    return v
}
```

新变量为与缓存相关的变量提供了更具表达力的名称，并且因为 `sync.Mutex` 字段嵌入其中，其 `Lock` 和 `Unlock` 方法被提升到了未命名结构体类型，使我们能够用不言自明的语法来锁定 `cache`。

## 6.4 方法值与方法表达式

通常我们在同一个表达式中选择并调用方法，如 `p.Distance()`，但这两个操作也可以分开。选择器 `p.Distance` 生成一个方法值，这是一个将方法（`Point.Distance`）绑定到特定接收者值 `p` 的函数。随后可以在没有接收者值的情况下调用该函数；它只需要非接收者参数。

```go
p := Point{1, 2}
q := Point{4, 6}

distanceFromP := p.Distance        // 方法值
fmt.Println(distanceFromP(q))      // "5"
var origin Point                   // {0, 0}
fmt.Println(distanceFromP(origin)) // "2.23606797749979", √5

scaleP := p.ScaleBy // 方法值
scaleP(2)           // p 变为 (2, 4)
scaleP(3)           //      然后 (6, 12)
scaleP(10)          //      然后 (60, 120)
```

当包的 API 需要一个函数值，而客户端希望该函数的行为是调用特定接收者上的方法时，方法值很有用。例如，函数 `time.AfterFunc` 在指定延迟后调用一个函数值。这个程序用它在 10 秒后发射火箭 `r`：

```go
type Rocket struct { /* ... */ }
func (r *Rocket) Launch() { /* ... */ }

r := new(Rocket)
time.AfterFunc(10 * time.Second, func() { r.Launch() })
```

方法值语法更简短：

```go
time.AfterFunc(10 * time.Second, r.Launch)
```

与方法值相关的是方法表达式。调用方法时，与普通函数不同，我们必须使用选择器语法以特殊方式提供接收者。方法表达式写作 `T.f` 或 `(*T).f`（其中 `T` 是类型），生成一个函数值，其第一个常规参数取代了接收者，因此可以用常规方式调用。

```go
p := Point{1, 2}
q := Point{4, 6}

distance := Point.Distance   // 方法表达式
fmt.Println(distance(p, q))  // "5"
fmt.Printf("%T\n", distance) // "func(Point, Point) float64"

scale := (*Point).ScaleBy
scale(&p, 2)
fmt.Println(p)            // "{2 4}"
fmt.Printf("%T\n", scale) // "func(*Point, float64)"
```
