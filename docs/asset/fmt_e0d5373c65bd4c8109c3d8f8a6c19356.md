
# SAMOA

SAMOA 可用于两种不同的模式：它可以作为一个运行平台，向其中添加新算法；或者开发人员可以实现自己的算法，并在自己的生产系统中运行它们。SAMOA 的另一个特性是流处理平台抽象，开发人员也可以通过使用可用的 API 添加新平台。通过这种角色分离，SAMOA 项目分为 **SAMOA API 层** 和 **DSPE 适配器层**。SAMOA API 层允许开发人员为 SAMOA 进行开发，而无需担心将使用哪种分布式流处理引擎 (SPE)。当发布新的 SPE 或有兴趣与另一个平台集成时，可以添加一个新的 DSPE 适配器层模块。目前，SAMOA 支持四种当前最先进的 SPE：**Apache Flink**、**Storm**、**Samza** 和 **Apex**。

SAMOA 的模块化组件包括 `processor`、`stream`、`content event`、`topology` 和 `task`。

## Processor

SAMOA 中的 `processor` 是一个计算单元元素，它在 `特定的 SPE` 上执行算法的某一部分。处理器包含算法的实际逻辑。**处理项 (PI)** 是针对每个 SPE 的处理器的不同内部具体实现。

SPE 适配器层负责处理 PI 的实例化。PI 有两种类型：`入口 PI` 和 `普通 PI`。`入口 PI` 将外部源的数据转换为实例，或独立生成实例。然后，它使用正确类型的 `content event` 通过相应的流将实例发送给目标 PI。`普通 PI` 从传入流中消费 `content event`，处理 `content event`，并可能将相同的 `content event` 或新的 `content event` 发送到传出流。开发人员可以指定 `并行度提示`，即 SAMOA 执行期间的 `运行时 PI` 数量，如图 11.5 所示。`运行时 PI` 是底层 SPE 在执行期间创建的实际 PI。SAMOA 根据底层 SPE 动态实例化 PI 的具体类实现。

![图 11.5 SAMOA 中的并行度提示。](img/Fig11-5.png)

**图 11.5** SAMOA 中的并行度提示。

PI 通过组合包含其对应的处理器和流。处理器是可复用的，这允许开发人员在多个机器学习算法实现中使用相同的处理器实现。PI 和处理器之间的分离使开发人员能够专注于开发他们的算法，而无需担心 PI 的 SPE 特定实现。

## Stream

`stream` 是从一个 PI 到其对应的目标 PI 的连接。开发人员将流视为 PI 之间的连接器，以及在 PI 之间发送 `content event` 的媒介。`content event` 封装了通过流从一个 PI 传输到另一个 PI 的数据。此外，与处理器类似，`content event` 也是可复用的。开发人员可以在多个算法中使用一个 `content event`。

`源 PI` 是通过流发送 `content event` 的 PI。`目标 PI` 是通过流接收 `content event` 的 PI。开发人员通过将流与恰好一个 `源 PI` 关联来实例化流。当 `目标 PI` 想要连接到流时，它们需要指定 `分组` 机制，该机制决定了流如何路由传输的 `content event`。

## Topology

`topology` 是连接的处理项和流的集合。它代表一个处理传入数据流的组件网络。在 SAMOA 之上实现的分布式流式算法对应一个 `topology`。

## Task

`task` 是一项与机器学习相关的活动，例如对分类器执行特定评估。`task` 的一个例子是 `预测性评估任务`，即使用每个实例测试模型性能，然后使用相同的实例通过特定算法训练模型的 `task`。在 SAMOA 中，`task` 也对应一个 `topology`。

平台用户本质上调用 SAMOA `task`。他们指定想要执行哪种 `task`，SAMOA 会根据 `task` 自动构建一个 `topology`。接下来，平台用户需要确定可用于部署的 SPE 集群，并配置 SAMOA 在该集群上执行。一旦配置正确，SAMOA 会将 `topology` 无缝部署到配置好的集群中，平台用户可以通过执行的专用日志文件观察执行结果。

SAMOA 中的 **ML 适配器层** 由封装其他机器学习框架中 ML 算法实现的类组成。目前，SAMOA 有一个用于 MOA 算法或学习器的包装类，这意味着 SAMOA 可以轻松使用 MOA 学习器来执行某些 `task`。SAMOA 不会改变 MOA 学习器的底层实现，因此学习器仍然在 SAMOA 底层 SPE 之上以顺序方式执行。

开发人员使用 `processor`、`content event`、`stream` 和 `processing item` 的抽象来设计和实现分布式流式机器学习算法。使用这些模块化组件，他们可以灵活地通过复用现有的 `processor` 和 `content event`，或从头编写新的组件来实现新算法。他们还可以通过 **ML 适配器层** 复用现有机器学习框架中的现有算法和学习器，从而获得灵活性。

开发人员也可以使用相同的抽象实现 `task`。由于 `processor` 和 `content event` 可复用；`topology` 及其对应的算法也可复用。这意味着他们也可以灵活地通过复用现有算法和组件，或从头编写新算法和组件来实现新的 `task`。

目前，SAMOA 包含以下算法：

*   **垂直霍夫丁树 [149]：** 垂直并行方法按属性对实例进行划分以实现并行处理。具有垂直并行性的决策树诱导器处理划分后的实例（由属性子集组成）以并行计算分裂标准。例如，如果我们有包含 100 个属性的实例，并将实例划分为 5 个部分，则每部分将有 20 个属性。在每个部分中，算法并行处理这 20 个属性以确定局部最佳分裂属性，并结合并行计算结果以确定全局最佳分裂属性并增长树。

*   **AMRules [241]：** SAMOA 使用垂直和水平并行性的混合体在集群上分发 AMRules。AMRules 构建的决策规则是可理解的模型，其中规则的前件是属性值条件的合取，后件是属性的线性组合。

*   **自适应装袋：** 这是一种易于并行化的方法。每个装袋副本被分配给不同的处理器。

*   **分布式聚类：** SAMOA 中的聚类分为两层：第一层对拆分后的数据执行聚类，第二层使用第一层输出的微簇执行元聚类。

# 12 图形用户界面

MOA 图形用户界面 (GUI) 允许通过菜单选择和表单填写来使用 MOA。顶部包含多个选项卡，对应四种学习任务：分类、回归、聚类和异常检测。本章将介绍评估、分类和聚类的主要选项；建议读者进一步探索，并阅读 MOA 文档以获取更多细节，例如每种方法可用的参数。

用于配置和运行任务的 GUI 通过以下命令调用：

```
bin/moa.sh
```

在 Linux 或 Mac 中，以及

```
bin\moa.bat
```

在 Windows 中。这些命令使用以下方式调用 GUI：

```
java -Xmx1G … moa.gui.GUI
```

有多个选项卡，分别用于分类、回归、聚类和异常检测。在以下章节中，我们将介绍如何使用它们。

### 12.2.1 任务

MOA 中的主要任务如下：

*   **WriteStreamToARFFFile** 将数据流输出到 ARFF 文件。ARFF 是 WEKA 项目 [107] 使用的一种方便的数据格式，它通过包含指定属性类型、名称和值的头部来扩展 CSV 格式。
*   **MeasureStreamSpeed** 测量数据流的速度。
*   **LearnModel** 从数据流中学习预测模型。
*   **EvaluateModel** 在数据流上评估静态预测模型。
*   **EvaluatePeriodicHeldOutTest** 通过定期在保留集上测试，在数据流上评估分类器。
*   **EvaluateInterleavedTestThenTrain** 通过按顺序对每个实例先测试后训练，在数据流上评估分类器。没有遗忘机制，因此所有实例在评估中同等重要。
*   **EvaluatePrequential** 通过按顺序对每个示例先测试后训练，在数据流上评估分类器。它可以选择使用滑动窗口或衰减因子作为遗忘机制。
*   **EvaluatePrequentialCV** 通过执行 *k* 折分布式交叉验证，在数据流上评估分类器；每次新实例到达时，随机选择一个分类器用于测试，使用其他分类器进行训练。它可以选择使用滑动窗口或衰减因子作为遗忘机制。
*   **EvaluateInterleavedChunks** 通过按顺序对数据块先测试后训练，在数据流上评估分类器。

评估方法在第 6.1 节中定义。

*   **ArffFileStream** 从 ARFF 文件读取数据流。

*   **generators.AgrawalGenerator** 生成十种不同的预定义贷款函数之一。

该生成器由 Agrawal 等人在文献 [8] 中提出。它是早期决策树学习器扩展研究工作的常用数据来源。该生成器产生一个包含九个属性的数据流，其中六个为数值型，三个为分类型。尽管作者未明确说明，但一个合理的推测是这些属性描述的是假设的贷款申请。定义了十个函数用于根据属性生成二元类标签。推测这些函数决定了贷款是否应被批准。

C 语言源代码公开可用。内置函数基于所引用论文（第 924 页），在公开的 C 语言实现中对应 `pred20` 至 `pred29` 函数。扰动函数的工作方式遵循 C 语言实现，而非论文中的描述。

*   **generators.HyperplaneGenerator** 生成预测旋转超平面类别的问题。

该问题在文献 [138] 中被用作 CVFDT 与 VFDT 对比的测试平台。*d* 维空间中的超平面是满足 ![](img/pg206-in-2.png) 的点 *x* ∈ℜ^(*d*) 的集合，其中 *x*[*i*] 是点 *x* 的第 *i* 个坐标。满足 ![](img/pg206-in-3.png) 的点示例被标记为正类，满足 ![](img/pg206-in-4.png) 的点示例被标记为负类。超平面适用于模拟时变概念，因为我们可以通过改变权重的相对值，以平滑的方式改变超平面的方向和位置。我们通过给每个权重属性添加漂移来引入变化：*w*[*i*] = *w*[*i*] + *dσ*，其中 *σ* 是变化方向反转的概率，*d* 是变化速度。

*   **generators.LEDGenerator** 生成预测七段 LED 显示器上显示数字的问题。

该数据源源自 CART 书籍 [56]。目标是预测七段 LED 显示器上显示的数字，其中每个属性有 10% 的几率被反转。其最优贝叶斯分类率（最佳可能分类器的速率）为 74%。实验中使用的特定生成器配置（led）产生 24 个二元属性，其中 17 个是无关属性。

*   **generators.LEDGeneratorDrift** 生成预测七段 LED 显示器上显示数字（带漂移）的问题。
*   **generators.RandomRBFGenerator** 生成随机径向基函数数据流。

设计该生成器是为了提供一种替代的复杂概念类型，这种类型不易用决策树近似。RBF（径向基函数）生成器的工作原理如下：生成固定数量的随机簇。每个簇有一个随机中心、一个标准差、一个类标签和一个权重。通过按权重成比例的概率选择一个簇，然后从以该簇中心为中心、以该簇在每个轴上的标准差为标准差的高斯分布中生成一个点，从而产生新示例。这实际上在每个中心周围创建了一个密度各异的正态分布超球体示例。仅生成数值属性。被选中的簇也决定了示例的类标签。

*   **generators.RandomRBFGeneratorDrift** 生成带漂移的随机径向基函数数据流。漂移通过以恒定速度移动中心来引入。
*   **generators.RandomTreeGenerator** 基于随机生成的树生成数据流。

该生成器基于文献 [88] 中的提议，产生的概念应有利于决策树学习器。它通过随机选择属性进行分裂，并为每个叶节点分配随机类标签来构建决策树。树构建完成后，数据流中的示例通过为属性分配均匀分布的随机值来生成，这些值再通过树确定类标签。该生成器具有参数以控制类别数量、属性数量、名义属性标签和树的深度。

生成示例后可引入噪声。对于离散属性和类标签，噪声概率参数决定了某个特定值被切换为非原始值的几率。对于数值属性，会向所有值添加一定程度的随机噪声，该噪声源自标准差等于原始值标准差乘以噪声概率的随机高斯分布。

*   **generators.SEAGenerator** 生成 SEA 概念函数。

该生成器在文献 [233] 中提出，用于研究对突发概念漂移的反应。数据流使用三个属性生成，只有前两个相关。所有三个属性的值均在 0 到 10 之间。数据流中的点被划分为四个具有不同概念的块。在每个块中，0/1 类由不等式 *f*[1] + *f*[2] ≤ *θ* 确定，其中 *f*[1] 和 *f*[2] 代表前两个属性，*θ* 为阈值。这四个类最常用的阈值分别为 9、8、7 和 9.5。

*   **generators.STAGGERGenerator** 生成 STAGGER 概念函数，由 Schlimmer 和 Granger 在文献 [223] 中提出。

STAGGER 概念是三个属性的布尔函数，用于编码对象：大小（小、中、大）、形状（圆、三角、矩形）和颜色（红、蓝、绿）。概念是两个属性的合取或析取，例如 *(颜色=红 且 大小=小)* 或 *(颜色=绿 或 形状=圆)*。

*   **generators.WaveformGenerator** 生成预测三种波形类型之一的问题。

它与 LED 数据集同源。该任务的目标是区分三种不同的波形类别，每种类别由两个或三个基础波组合生成。最优贝叶斯分类率已知为 86%。该问题有两个版本：wave21 拥有 21 个数值属性，均包含噪声；wave40 则额外引入了 19 个无关属性。

*   **generators.WaveformGeneratorDrift** 生成预测三种波形类型之一（带漂移）的问题。

### 12.2.3 贝叶斯分类器
