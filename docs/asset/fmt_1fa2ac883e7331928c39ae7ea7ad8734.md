低功耗网络适用于需要低功耗和广泛覆盖的设备。相比之下，传统的局域网倾向于高速数据传输、稳定性和更高的功耗。

低功耗 Mesh 网络是一种旨在低功率内连接设备的无线通信网络。局域网（LAN）是连接有限地理区域（如家庭、学校或办公楼）内的计算机和设备以共享资源信息的网络。

Mesh 网络的特征如下：

- **设计原理**：低功耗 Mesh 网络是基于短距离通信技术设计的。它采用 Mesh 架构，允许设备之间直接或通过其他设备进行通信，形成节点网格。
- **用途和场景**：低功耗 Mesh 网络主要针对低功耗、低带宽的应用。它是物联网（IoT）场景、智能业务自动化以及在没有路由器的情况下需要广泛覆盖应用的理想选择。
- **能量效率**：低功耗 Mesh 网络具有极高的效率，适用于电池供电的设备。
- **范围和速度**：虽然低功耗 Mesh 网络通过设备间的跳跃传输扩展了范围，但与传统局域网相比，其速度较低，因为它针对小数据数据包进行了优化。
- **可扩展性**：低功耗 Mesh 网络可以支持数个节点，便于大规模设备网络。

局域网（LAN）的特征如下：

- **设计原理**：传统的局域网通常基于 `Ethernet`（有线）或 `Wi-Fi`（无线）技术，旨在短距离内的高速传输。
- **用途和场景**：局域网适用于办公、家庭和工业网络，这些环境需要计算机、服务器和其他网络设备的高数据吞吐量和可靠连接。
- **能量效率**：对于传统局域网（尤其是有线的），能量效率不是主要考虑，因为它们通常持续电源。
- **范围和速度**：传统局域网提供更高的数据传输速度和稳定的连接，但在没有中继器或桥接器等额外硬件的情况下，范围通常限于建筑物或特定的地理区域。
- **可扩展性**：虽然局域网可以支持许多设备，但其可扩展性通常受中央路由器或交换机的容量以及管理扩展网络的复杂性。

该策略的核心不在于选择某种单一的技术，而是利用每种网络的优势。低功耗网格网络通常用于边缘侧的外部，以便与分布在 TinyML 应用覆盖区域内的传感器和执行器进行通信。其中一个低功耗网格节点可以作为网关，使命令和状态更新跳转到更广泛的广域网。根据项目的不同，广域网可以是 `Wi-Fi` 连接或有线 `LAN`；如果这些网络不可用或难以访问，可以使用 `LTE-M` 网络连接互联网。如果因为成本或可用性无法选择蜂窝网络，则使用 `LoRA` 网关进行远距离的数据传输。

请注意，我们并没有创建一个用于发送大量数据的流水线。而是小数据包在网络间跳转并最终到达目的地。少量的延迟是可以接受的，因为我们接收的只是状态更新；操作在微控制器中实时完成。数据正在被采集，分类正在进行，异常正在被检测，控制命令被现场发送到执行器。不需要在每次需要决策时调用云端或远程系统。

书中使用的低功耗网格网络技术是蓝牙低功耗网格网络（`BLE Mesh`）。还有其他一些优秀的选择，例如 `ZigBee` 或 `Thread`。请自由探索它们，并根据你的项目选择你认为最合适的一个。

`BLE mesh` 网络采用发布-订阅（Pub/Sub）模型来促进网络内设备之间的通信。该模型是 `BLE mesh` 设计的基础部分，能够实现高效、可扩展且灵活的消息分发，而不需要设备之间的直接连接。

在 `Pub/Sub` 模型中，网络设备被配置为发布者、订阅者或两者兼顾。发布者向特定主题（topic）发送消息，而无需知道设备会接收这些消息。订阅者监听感兴趣的主题上发布的消息。在 `BLE Mesh` 的语境下，主题通常由“组地址”表示，订阅者可以注册该地址以接收来自该处的消息。

当设备（发布者）有数据要共享时（例如传感器读数或状态更新），它会在预定义的主题上发布这些信息。所有订阅了该主题的设备（订阅者）都会自动接收发布的消息。这种机制允许网络内设备解耦，意味着设备不需要维护关于其他设备网络地址的信息。相反，它们根据共同的兴趣（主题）进行通信，从而形成高度灵活且动态可配置的系统。

`BLE mesh` 中的 `Pub/Sub` 模型对于物联网和智能环境特别有利，在这些环境中，设备可能会频繁加入或离开网络，系统配置可能随时间而变化。它简化了跨越大量设备（从照明系统、温度传感器到报警器和自动化机械）发送命令或传播信息的过程，能够相对轻松地编写复杂的交互和行为。

书中的每个用例都包含一个表格，规定了每个设备使用 `BLE mesh network` 的发布和订阅配置。源代码包含一个 `ReadMe` 文档，其中提供了有关配置节点的详细说明。

TinyML 实现中的电源管理是一个至关重要的方面，确保了 ML 模型能够在微控制器和嵌入式系统等低功耗、资源受的设备上有效运行。鉴于 TinyML 应用通常部署在电池供电或能量采集的环境中（如 IoT 设备、可穿戴设备和远程传感器），优化功耗对于延长这些设备的使用寿命并维持功能至关重要。

TinyML 中的电源管理涉及若干种策略和技术：

- **高效的模型设计**：设计所需计算和内存更少的轻量级 ML 模型。模型剪枝、量化和知识蒸馏等技术有助于在不显著影响准确性的情况下降低模型复杂度。
- **职责循环（Duty cycling）**：通过在激活模式和睡眠模式之间切换来实现职责循环这是一种常用策略。设备仅在激活阶段执行计算（如数据采集、推理和通信），在其余时间内进入低功耗睡眠模式。
- **能量感知算法**：开发对能耗感知并能根据可用电量调整行为的算法。例如，算法在电量较低时减少推理或数据传输的频率。
- **硬件优化**：利用低功耗硬件特性，例如用于 ML 任务的专用低功耗处理器、高效的传感器管理以及节能通信协议。
- **选择性感知与处理**：实施根据预定义标准或事件检测来选择性采集和处理数据，从而避免不必要的计算和传输。
- **自适应计算**：根据任务复杂性和设备当前的能量状态动态调整计算负载。这可能涉及在不同模型之间进行选择，或调整模型参数以平衡功耗与性能。

TinyML 实现中的有效电源管理需要一种全方位的方法。这种方法结合了硬件和软件优化，在提供计算和推理能力的同时最小化能耗。通过这种方式，TinyML 应用可以实现长期自主运行，即使在电力最受限的环境中也能释放智能连接设备的潜力。

在 TinyML 实现中，物料清单（`BOM`）是一份详细清单，列出了构建和部署 TinyML 设备或系统所需的所有组件。`BOM` 在概述支持每个设备 ML 功能所需的硬件以及可能的软件组件起着至关重要的作用。

TinyML 实现的 `BOM` 通常包括微控制器、传感器、执行器、电源（如电池或太阳能电池板）、连接模块（用于数据传输的 `蓝牙` 或 `WiFi` 组件）以及设备物理组装运行所需的任何其他组件。它可能还会详细说明组件的版本或型号以确保兼容性和性能。

此外，TinyML `BOM` 还可以扩展硬件之外，包括设备运行所需的软件许可或服务、开发工具以及 ML 模型部署。这份综合文档对于项目规划、成本估算、采购和组装过程至关重要，确保所有零件都经过准确指定和计入。它通过提供所有必要材料和资源的清晰有序概述，促进了 TinyML 项目的高效实现。

训练数据集的主要目标是帮助模型进行 `generalize`（泛化）。`generalization` 是模型能够可靠且准确地推断某一类别的特性。良好的训练集应该是 `balanced`（平衡的）、`diverse`（多样化的）且 `sufficient`（充分的）。假设你正在尝试分类狗和猫的声音。如果你大部分用狗的声音来训练模型，模型将了解更多关于声音产生的细微差别。当出现一个可能是两者其中之一的声音时，它将倾向于宣布该声音来自狗，因为它可能也知道猫也会这样叫。`diverse` 数据集展示了同一类别的许多不同但保持了定义其为同一组特征的实例。以狗和猫的为例，`diverse` 数据集将包含来自许多类型狗和猫的声音样本。`sufficient` 数据集足够大，足以允许模型达到 `generalization`。经验法是数据越多越好。然而，存在一个收益递减的拐点，更多的数据将不会产生更大的影响。如果你发现自己处于这种情况，并且在添加大量数据后仍未达到所需的准确率，那么你应该重新考虑你的方法。

## 模拟量数字转换

这一过程是将模拟声波转换为数字信号的行为。其实现方式是：每隔一万万分之一秒（即 `16KHz`），微控制器将读取其其中一个引脚（连接到麦克风的引脚）的电压。然后，它会将该电压转换为存储在内存寄存器中的数字数字。如果寄存器是 8 位的，声波只能有 256 个电平，其中 0 表示无声音，256 表示最大音量。16 位效果更好，因为每次读取都可以用 65,536 个电平来表示。

你可能会奇怪，为什么用更多的电平来表示声波很重要。想一下你从网上下载的一张低分辨率图像。即使放大，也看不到很多细节，这种感觉是令人沮丧的。声音也是如此。如果你以低分辨率采集声波，你的模型将无法识别声音中的许多细节，并可能在区分两种相似的声音时遇到困难。尽管如此，请记住我们处于 TinyML 的世界，这里的资源是极其受限的。你的应用场景使用 8 位声波可能是可以的。
