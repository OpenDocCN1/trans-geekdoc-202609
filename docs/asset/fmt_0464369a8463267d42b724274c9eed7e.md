在本分步过程中，您将通过使用上一练习中创建的两个动态磁盘，在 Windows Server 上创建一个镜像卷。请记住，镜像卷将所有数据存储在该卷的两个成员（磁盘）上。

1.  登录到 ServerA，然后启动“计算机管理”控制台。
2.  在“计算机管理”控制台中，在左侧“存储”下选择“磁盘管理”。

## RAID 5

RAID 5 称为 `带奇偶校验的条带化`，因为 RAID 5 卷的作用类似于 RAID 0 卷，但添加了奇偶校验信息以创建冗余。RAID 5 卷将数据写入卷中的所有磁盘，但在每个条带的一个磁盘上存储冗余信息（`条带` 是由每个磁盘上的 64KB 块组成的一行，如图 18-5 所示）。例如，当您将数据保存到由四个磁盘组成的 RAID 5 卷时，数据会被分割成 64KB 数据块（这可能会因产品或实现而异）并写入每个磁盘（假设为磁盘 0、1 和 2）。但磁盘 3 将存储已保存的三个 64KB 块的冗余数据（奇偶校验数据）。如果三个 64KB 块不足以完成文件保存，保存操作将继续到下一行。该行也将有奇偶校验信息，但奇偶校验信息存储在每行的不同磁盘上。

### 理解高可用性

重要的是要理解，拥有 RAID 阵列并不能确保您的用户能够访问数据。例如，如果您有一台连接到 RAID 阵列的电子邮件服务器，如图 18-6 所示，请注意客户端连接到电子邮件服务器以检索数据，而不是直接连接到 RAID 阵列。如果电子邮件服务器发生故障怎么办？尽管您在 RAID 阵列上有电子邮件数据，但用户无法访问这些数据，因为他们必须通过电子邮件服务器发出请求。

![Image](img/f0726-01.jpg)

**图 18-6** 识别高可用性的需求

`高可用性` 是确保客户端始终能够访问他们所需的服务，无论是电子邮件服务器、数据库服务器还是 WAN 链路。要实现高可用性，您必须首先识别所有单点故障，然后在这些领域创建冗余。以下是一些常见单点故障的关键领域：

#### 服务器

提供网络服务（如电子邮件或网站）的服务器是单点故障。可以使用群集或负载均衡来提供这些服务的高可用性。群集通常为维护数据的后端服务器（如数据库服务器）提供高可用性。负载均衡是一种为解决方案增加可扩展性（以及高可用性）的方法。例如，如果您在两台 Web 服务器之间对网站进行负载均衡，随后您的公司网站变得非常流行，可扩展性体现在您可以向负载均衡解决方案中添加更多服务器，以便将工作负载分配给负载均衡解决方案中的所有服务器。

#### 硬盘驱动器

硬盘驱动器存储我们宝贵的公司数据，是单点故障。您可以使用 RAID 为驱动器提供容错能力。

#### 路由器和交换机等网络设备

路由器和交换机是重要的网络硬件，它们允许系统在网络上进行通信。你应确保拥有多个交换机和路由器，并且在这些设备之间存在多条通信路径，以确保容错能力。

#### WAN/互联网链路

为确保与互联网或 WAN 的连接，你应购买多条链路。如果你依赖基于云的解决方案（无论是办公效率软件、虚拟机、存储还是备份），这一点尤为重要。

#### 电源

确保路由器、交换机和服务器等硬件拥有多个电源，以提供电源容错。此外，确保拥有备用电源，如 UPS 或发电机，以提供一定程度的电源容错。

在本节中，你将了解一些用于创建高可用性解决方案的不同技术。

## 故障转移群集

确保高可用性的第一种常用技术是 `failover clustering`（故障转移群集）。使用故障转移群集时，你需要安装多台运行相同软件的服务器（称为 `nodes` [节点]）。两个或更多节点作为一个团队协同工作，其中一个节点充当活动节点，其他节点充当被动节点。当活动节点发生故障时，一个被动节点会上线接管工作负载。

要使故障转移群集正常工作，你需要某种形式的共享磁盘存储连接到群集中的所有节点，并通过 RAID 进行保护。然后，群集节点通过高速连接直接相连，该连接用作心跳线。心跳线定期在活动节点和被动节点之间传递信号，当被动节点未收到来自活动节点的信号时，被动节点就会接管工作，因为活动节点必定已不可用。图 18-7 显示了一个双节点群集，但请记住，大多数群集环境支持更多节点。

![Image](img/f0728-01.jpg)

**图 18-7** 查看故障转移群集

### 网络负载均衡

网络负载均衡是一项重要技术，旨在提高应用程序（如网站）的性能和可扩展性。例如，如果你发现网站越来越受欢迎，因请求过多而变得不堪重负，你可以将多台服务器安装到负载均衡阵列中。客户端随后连接到分配给负载均衡阵列的 IP 地址（参见图 18-8 中的步骤 1），然后该阵列将客户端重定向到阵列中可用的服务器之一（参见图 18-8 中的步骤 2）。

### 冗余硬件

确保高可用性的很大一部分是在所有领域创建冗余，包括环境中的硬件。硬件冗余不仅限于拥有多个驱动器以防其中一个发生故障，还应包括以下内容的冗余：

#### 服务器

如果高可用性是关注重点，请确保在群集或负载均衡解决方案中拥有冗余服务器。确保服务器拥有冗余硬件组件，如冗余驱动器、网卡和电源。

#### WAN 链路

高可用性解决方案将要求 WAN 链路具有冗余。你可以从服务提供商处购买两条 WAN 链路，或从不同的服务提供商处获取 WAN 链路，以防其中一个出现技术问题。

#### 电源

高可用性中一个被忽视的方面是，我们依赖的所有技术都需要电力。你需要通过购买发电机作为备用电源，确保为组织及其资产提供冗余电源。

## ✓ 两分钟演练

### 业务连续性与灾难恢复简介

- 组织需要业务连续性计划 (BCP)，以确保在面临灾难时能继续业务运营。
- 灾难恢复计划 (DRP) 是 BCP 的一部分，更侧重于技术驱动，因为它处理从不同类型故障中恢复系统的分步程序。
- 业务影响评估 (BIA) 是制定 BCP 的一个阶段，涉及识别业务功能、每个功能的允许停机时间、与每个功能相关的风险以及缓解技术。
- 确保定期审查和测试你的 BCP，以便发现任何疏漏，并使每个部门在灾难发生时都知道自己的职责。

### 备份和还原数据：备份概念

- 不同的备份类型包括完全备份、差异备份和增量备份。通常，你会将完全备份与差异备份结合使用，或将完全备份与增量备份结合使用。
- 完全备份会备份你指定的任何内容，然后清除存档位。
- 差异备份会备份自上次完全备份以来发生变化的内容，**不**清除存档位。
- 增量备份会备份自上次完全备份或增量备份以来发生变化的内容，**并**清除存档位。
- 备份磁带应使用密码或加密进行保护，副本应存储在异地，以便如果设施发生灾难，你仍能访问磁带副本。
- 云备份越来越流行，如果组织允许，可将其用作主要或额外的备份策略。请注意，由于隐私担忧和法规限制，许多组织不允许将数据存储在云中。

### 实施容错

- 容错是指确保当故障发生时，你拥有多个项目（如 RAID 卷）来承担工作负载。
- RAID 0 称为磁盘条带化，**不**提供数据冗余。RAID 0 用于提高读/写磁盘数据的性能。
- RAID 1 是磁盘镜像，用于将存储在一个磁盘上的数据复制到另一个磁盘，以便在一个磁盘故障时，另一个磁盘仍保有数据。
- RAID 5 涉及跨多个磁盘进行条带化，奇偶校验信息分布在每个磁盘上。奇偶校验信息用于在磁盘故障时重建数据。

### 理解高可用性

- 拥有容错并不代表拥有高可用性——但它有助于实现高可用性。要实现高可用性，你需要确保消除所有单点故障。

![Image](img/boxsq.jpg) 群集用于确保虚拟化、DHCP、文件共享、电子邮件服务器和数据库服务器等服务的高可用性。

![Image](img/boxsq.jpg) 负载均衡是一种通过将多个系统安装到负载均衡阵列中来提高特定服务性能的方法。当请求发送到负载均衡阵列时，其中一个系统会处理该请求。
