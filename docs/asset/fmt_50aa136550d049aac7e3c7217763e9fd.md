
要配置上述错误设置，最直接的方法是修改`php.ini`文件。我们已经在第 2 章中做过那样的，在那里我们将`error_reporting`设置为`E_ALL`并将`display_errors`设置为`On`。如果你没有编辑`php.ini`的权限，可以使用两个内置函数`error_reporting`和`display_errors`（注：原文此处可能有误，应为`ini_set`）来修改设置。为了这样做，在你的脚本中添加以下语句：

```php
error_reporting(E_ALL);
ini_set('display_errors', '1');
```

在上面的语句中，我们使用`error_reporting()`函数将`error_reporting`设置为`E_ALL`。接下来，我们使用`ini_set()`函数将`display_errors`设置为`'1'`。网站上线后，你应该将`display_errors`设置为`'0'`：

```php
echo
```

（缺少引号）。

使用`ini_set()`更改`display_errors`有其局限性。如果你的脚本中有任何语法错误，`ini_set()`函数将不起作用。例如，如果你的脚本中有以下行：

```php
echo;
```

### 12.2.3 错误处理器和停机函数

在上一节中，我们学习了调整`display_errors`。在在线网站上，鼓励你关闭`display_errors`。然而，有时不显示任何错误消息并不是最好的方法。与其在出现问题时让用户完全困惑，我们可以为他们提供一个“用户友好”的错误消息。为了这样做，我们需要创建一个错误处理器。自定义错误处理器允许我们自己处理错误，而不是依赖默认处理器。为了查看它是如何工作的，在编辑器中创建一个新文件并保存为`errorHandling.php`。向其添加以下代码：

```php
<?php

function myErrorHandler($errno, $errstr, $errfile, $errline) {

    echo '<BR>Oppsss... An error occurred.

    echo '<BR'.$errstr;

}

set_error_handler('myErrorHandler');
```

在上面的代码中，我们首先创建一个名为`myErrorHandler()`的函数，它有四个参数`$errno`、`$errstr`、`$errfile`和`$errline`。前两个参数是强制性的，后两个是可选的。这四个参数分别用于存储错误代码、错误消息、发生错误的文件和行号。当错误发生时，PHP 会提供所有四个信息。在函数内部，我们使用`echo`语句向用户输出自定义的错误消息。在编写函数后，我们使用一个内置函数`set_error_handler()`将`myErrorHandler()`设置为自定义错误处理器。

此时，你可能会注意到这个自定义错误处理器与我们在第 12.1.4 章编写的自定义异常处理器非常相似。事实上，它们确实相似。然而，自定义异常处理器处理未捕获的异常，而自定义错误处理器处理错误。此外，自定义错误处理器不会导致脚本终止。为了测试上面的错误处理器，在`errorHandling.php`的末尾添加以下代码：

```php
echo $a;

echo '<BR>Script is not terminated';
```

现在运行`errorHandling.php`，你将得到如下输出：

```
Oppsss... An error occurred.

Undefined variable: a

Script is not terminated
```

# 脚本未终止

当我们尝试访问未定义的变量时，首先会执行自定义错误处理器为我们提供自定义的错误消息。之后，脚本将继续运行并执行第二个`echo`语句。自定义错误处理器替换了默认的 PHP 错误处理器，为我们提供了一种修改显示给用户的错误信息的方便方法。然而，它无法处理所有的错误。例如，它无法处理致命错误（fatal errors）。这些错误会导致脚本终止。为了处理这些错误，我们需要另一个名为`register_shutdown_function()`的内置函数。该函数告诉 PHP 在脚本即将终止时运行哪个函数。

要查看它是如何运作的，请将以下代码添加到`errorHandling.php`的末尾：

```php
function myShutDownHandler(){  

  $lastError = error_get_last(); 

  if (isset($lastError)) {  

    echo '<BR>Oppsss... Script terminated.<BR>';  

  }  

} 

register_shutdown_function('myShutDownHandler');
```

在这里，我们声明了一个名为`myShutDownHandler()`的函数。在函数内部，我们需要判断脚本终止是否是由错误引起的。为了做到这一点，我们使用`error_get_last()`函数。如果没有发生错误，该函数将返回`NULL`（例如，如果脚本终止是因为用户导航到另一个页面）。相反，如果发生了错误，它会将最后一个错误以关联数组的形式返回。该数组包含四个键：`type`（提供错误类型）、`message`（提供错误消息）、`file`（提供错误发生的文件）和`line`（提供错误发生的行）。在调用`error_get_last()`函数后，我们使用`if`语句来检查是否发生了错误。如果发生了，我们就向用户`echo`一个自定义的错误消息。

在编写完`myShutDownHandler()`函数后，我们使用另一个名为`register_shutdown_function()`的内置函数将其注册为关闭函数。为了测试我们的关闭函数，请将以下代码添加到`errorHandling.php`的末尾：

```php
hello();
```

在这里，我们尝试调用一个不存在的函数。如果你现在加载`errorHandling.php`，你将看到下面的错误消息：

`Fatal error : Uncaught Error: Call to undefined function hello() in ...errorHandling.php:27 Stack trace: #0 {main} thrown in ...errorHandling.php on line 27 Oppsss... Script terminated.`

“Fatal error”消息仅在`display_errors`设置为`On`（或`'1'`）时才会显示。如果你将`display_errors`改为`Off`（或`'0'`），则只显示最后一行。这一行是由我们的关闭函数生成的。懂了吗？

## 12.3 汇总

在之前的章节中，我们讨论了异常和错误以及如何分别处理它们。在这一节中，让我们把所有内容整合到一个文件中。为此，请在你的`htdocs`文件夹中创建一个名为`debugging.php`的文件。在该文件中，我们需要首先创建一个名为`myDebugger()`的函数；该函数将以后处理任何未捕获异常或错误的主函数。要创建该函数，请将以下代码添加到`debugging.php`：

```php
function myDebugger($msg, $file, $line, $trace = '') { 

  $message = $trace.'<BR><BR> <strong>'.$msg.'</strong> found on <u>line '.$line.'</u> in file <u>'.$file.'</u>'; 

  if (ini_get('display_errors')) {  

    echo $message;  

  } else {  

    error_log($message);  

    header('Location: error.html');  

  } 

}
```

在这里，我们定义了一个名为`myDebugger()`的函数，带有四个参数`$msg`、`$file`、`$line`和`$trace`。前三个参数分别用于存储错误或异常的消息、文件名和行号。最后一个参数用于存储异常的堆栈跟踪。当发生错误或异常时，PHP 会提供这四个信息。在函数内部，我们拼接这四个参数并使用 HTML 格式化生成的字符串，然后将其赋值给变量`$message`。接下来，我们使用`if`语句来决定在浏览器中显示什么内容。为了实现这一点，我们使用内置函数`ini_get()`获取`'display_errors'`的设置。当`'display_errors'`设置为`On`（或`'1'`）时，`if`条件为真，我们使用`echo`语句在浏览器中显示错误消息。否则，我们使用另一个内置函数`error_log()`将`$message`记录到我们的错误日志文件中。
