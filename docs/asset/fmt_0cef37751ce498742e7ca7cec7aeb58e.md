认真说，这七个字（原文七个单词）应指引你在机器学习旅程中的下一步。请花一点时间，让这个方向（强有力的指引）沉淀下来，并反思它对你的组织真正意味着什么。你必须花一点时间，从为组织构建战略价值倒推，回到你正在开展的实际机器学习工作中。在这项工作内部，你会迅速发现，要将机器学习工作投入运营以产生战略价值，将依赖于一份可靠的投资回报率（ROI）计划。确保你从一开始就以此为终极目标，以增加成功的几率。在不了解潜在投资回报率或潜在损失的情况下，在任何类型的组织内采取机器学习所能实现规模的行动，是极其可疑的。这就是为什么你必须从头到尾在机器学习工作上保持战略性。

## 从上到下建立并运行机器学习策略

高管领导层必须从一开始就理解并致力于引导事务走向正确的道路（一条真正具有战略意义的道路）。首先要努力在机器学习领域制定一个可靠的策略。这在实践中听起来可能比实际更难。你不需要复杂的卓越中心或大规模投资来制定策略。你的策略只需与预算挂钩，理想情况下与预算关键绩效指标（KPI）挂钩。每一笔预算都会导致宝贵资金的支出过程，围绕机器学习投资回报率（ROI）水平保持可靠的 KPI，将有助于确保你的策略在未来多年内站在稳健的财务基础上。组织所有宝贵资源的支出都应转化为某种类型的 KPI。这就是你的结果如何让你确认资金花得好、决策可靠的方式。当你将组织的战略愿景落地为与预算在财务上对齐的执行时，你必须真正专注并确保所有支出都与该框架挂钩。

这意味着你投资的机器学习策略必须致力于实现直接与可靠的预算级 KPI 挂钩的特定 ROI。你可能觉得这句话重复了。如果你注意到了这种重复，说明你很专注，已在通往未来成功的道路上。阅读理解能力在将书面论点转化为行动方面大有裨益。你正在创建的这种 KPI 关联回溯，只有在建立可靠的机器学习策略后才会发生。它必须基于对 ROI 的优先级排序和规划。你的机器学习流水线和框架必须朝着该目标对齐。这最终是实施机器学学习作为长期战略一部分时，可靠战略计划的基石。

我们已经读了约 500 个单词，也许是时候简单回顾一下目前传达的信息了。准备好以可定义、可重复的方式做事。高质量执行策略的部分在于以可定义、可重复的方式做事。这是质量来源的本质。你必须知道正在执行什么计划，并以能使计划在你期望的运行速率下成功的方式专注于并支持该计划。就在企业内部署机器学习工作而言，你必须弄清楚技术将如何建立和投资，以及该投资将如何转化为具有正确 ROI 的用例。

了解用例的业务价值，而不是让解决方案追逐问题。仅仅因为你能做某事，并不总意味着你应该做。拥有部署技术的能力确实会产生让技术驱动的解决方案追逐问题的潜在可能。以非常理论化和实验室为基础的方式构建机器学习技术，然后再追逐用例，这是一种极其糟糕的方式，只能靠运气偶然发现行之有效的 ROI 模型。更好的前进方式是了解用例，并拥有可靠的策略来应用你的技术。这意味着找到合适的机器学习框架和流水线，以强有力的方式支持整个组织的用例。

这是一个需要周密计划的时刻。就在这里、就现在、就在这一刻的考量中，你可以选择从今往后做事有计划。机器学习技术正变得越来越易得且丰富。无代码、低代码以及可靠的集成解决正在技术版图中变得无处不在。来自整个组织的团队可能都想尝试概念验证，供应商也带来了各种选项。人们总是准备好向组织推销机器学习的价值。内部和外部选项都很丰富。这是应用机器学习的大好时机。你可以通过多种方式快速且毫不费力地入局。要让实施正确，并让数据、流水线和框架与你最大可能的结果对齐，需要规划和可靠的执行。

你的机器学习策略不能是一个“拍脑袋”的项目。你必须具有战略眼光。它必须是更广泛战略的一部分。你不能让所有的概念验证和供应商方案驱动组织对机器学习技术的采用。那将意味着整体战略愿景未被定义。之所以普遍发生这种情况，可能是因为它拥有可靠的 ROI，且正确的用例可能碰巧从组织底层自下而上被选中。那不是一个有计划的策略。

了解你想用机器学习增强的工作流，并超越流行词汇去看技术的实际行动。你真的必须知道工作流中的哪个位置、哪些流水线将使你的用例能够提供可靠的 ROI。

在机器学习旅程的某个节点，你将需要做出一些决策……

- Q: 你将从哪里服务机器学习模型？
- Q: 这是你的第一次模型构建和部署吗？
- Q: 实际管理了哪些模型服务部署？
- Q: 你是为训练在本地工作，还是在工作流中调用应用程序编程接口（API）和模型服务？
- Q: 你是否选择通过外部 API 调用使用预训练模型？
- Q: 你是从市场购买模型，还是购买商业 API 的访问权限？
- Q: 模型效率多久会下降并需要调整？
- Q: 你是否计算出模型效率的“无法回头点”在哪里，即 ROI 跌破盈亏平衡点？

# Substack 第 2 周：机器学习框架与流水线

发布于 2021 年 2 月 5 日

与机器学习流水线相关的生态系统开始发展。不同的平台（公司）正在构建不同的方法来管理它们支持的机器学习框架和流水线。现在是你的组织启动这项工作的时候了。你可以构建一个易于管理的端到端方法，用于将模型更新推送到生产环境。如果你此刻停下阅读手稿去做研究或启动环境，你最终可能会使用一个你安装的 `TensorFlow Serving` 实例、`Amazon SageMaker` 流水线或 `Azure` 机器学习流水线 [1]。这些方法中的任何一种都能让你启动并运行。它们拥有实践社区提供支持 [2]。也就是说，你正在走的这条路以前走过，且已在大规模场景下使用。使用机器学习框架和流水线的路径已经相当清晰。人们正在这么做。他们为了好玩在构建东西。他们已有东西在生产环境运行。而当所有这些在外部发生时，大量编排和流水线管理公司正在商业世界的前沿涌现 [3]。

开始你的机器学习之旅。一种快速上手并真正开始思考如何实现这一点的方法是去 `GitHub` 下载 `TensorFlow Extended (TFX)` 作为你自己的硬件或某种云实例上的流水线平台 [4]。你同样可以轻松地走云原生路线，在没有数据中心机箱或桌面设备的情况下构建技术。你可以在 `Google Cloud Platform (GCP)`、`Azure` 或 `Amazon Web Services (AWS)` 上启动，而不会在实现梦想的过程中遇到任何真正的摩擦。你的某些人员可能只是建立这些工具的本地版本，以便在过程中摆弄和进行一些开发。

## 构建模型

当然，你也可以购买模型 [5]。这里有步骤帮助你构建模型。如果没有利用整套装置的模型，机器学习流水线的所有设置步骤都显得相当学术。根据你的用例，将机器学习引入相关工作流的一种方法是直接集成 API，以避免设置框架和流水线。这是一种可行的途径，对于某些场景非常合理。对于其他机器学习工作，复杂性会使得使用开箱即用且具有可调用 API 的解决方案变得不可行。你会惊讶于如今提供了多少复杂的 API，但它们并不能为所有用例提供全面的覆盖 [6]。

### 模型服务与 ROI

你打算拿这些模型怎么办？你需要保存它们以供服务。建立可靠的框架和机器学习流水线，关键在于在满足具有明确且可预测 ROI 模型的用例的工作流中提供这些模型服务。

从实施的那一刻起，你将与时间赛跑，以弄清楚市场上的那些模型何时会遭遇效率下降并需要某种调整。你必须了解潜在的模型退化，并计算在 ROI 条件被违反时必须在何时终止工作 [7]。这听起来可能有点难，但如果你的模型效率下降到对财务结果产生负面影响的地步，你就会想知道如何关闭开关，并且可能会纳闷为什么那个开关没有自动化。

在此过程中，需要对模型或参数进行某种调整。回顾一下，我看待 ROI 的方式相当直接。你必须从投入了什么以及可能获得什么的角度来考虑机器学习模型的价值。这只会给你一个积极或消极的视角，来判断该 ROI 是否对你有利。那时你只是在遵循你的策略并思考 ROI 模型。

所以再次强调，严格的 ROI 建模可能不是你想要使用的方法。我建议不要在不了解财务后果的情况下长时间工作。在大规模应用时，你可能会非常快地在机器学习用例中造成故障和其他问题。甚至可能发展到你发现这对你的业务案例不再值得的地步。将机器学习插入工作流可能并不是正确的做法，这就是为什么计算结果并做出基于事实的决策如此重要。

实际上，只要你以一种可规划、可定义且可重复的方式去做，效果都会很好。考虑到基于事实的决策制定以及在必要时愿意“按下关闭开关”将有助于防止失控问题演变成对业务的生存威胁，这一点说起来相当容易。因此，拥有机器学习策略、以可定义和可重复的方式做事、以及无情地基于事实行事，就是我的建议。

### 技术选择

显然，你应该对我所说的一切持保留态度；你应该提前知道我是 `TensorFlow` 的忠实拥护者。这也是我将其作为主要示例的原因之一，但这并不意味着它就是你的绝对正确答案。它只是我最频繁关注、且在转向其他解决方案前首选的答案。这始终基于用例，我坚决避免让技术去寻找问题。你需要让用例和手头的问题来适配解决方案，而不是不断尝试应用解决方案直到有一个奏效或你放弃为止。

### 管理模型

故事发展到此，你正在思考或开始构建这一切，并且开始进入状态。兴奋感可能正积聚成某种高潮。现在你需要一个地方来管理你的模型。你可能需要想象一下你已经拥有模型了。也许你从市场上买来了它们，完全跳过了训练环节。这是一个激动人心的时刻，你已准备好启程。所以在本例中，你将从刚刚构建（或最近获得）一个机器学习模型，转向实际做点什么。在那一刻，你可能意识到需要反复提供该模型服务，以创建真正的机器学习驱动工作负载。这不仅意味着你要管理那些模型，还可能意味着你需要随着时间的推移提供不同模型的服务。

当你进行调整和修正、引入不同的建模技术时，你的实现会变得更高级。你会发现的一点是，即使是你拥有的那个完美模型——在发布时完全符合你的预期——也在慢慢等待着背叛你和你对它的信心，通过退化来实现。你必须准备好根据用例对性能进行建模和评估。这才能让你对模型质量和结果影响做出高质量的决策。

### 关键要点

我有几个要点来结束本期《林达尔通讯》。你必须记住，此时机器学习模型和流水线几乎已经**民主化**了。你可以获取它们。它们已在外面“野蛮生长”。人们以各种不同的方式在使用它们。你可以直接将这项技术引入你的组织，几乎没有任何摩擦。

# Substack 第 3 周：机器学习团队

发布于 2021 年 2 月 12 日

## 学习与团队建设

学习。持续学习。做一个终身学习者是个可靠的计划。我诚心认为我们生活在机器学习培训和人才的**黄金时代**。人们在 `GitHub` 上无私地分享世界级的培训材料和代码。共享的学术论文数量正在飙升 [1]。对于那些能够在过程中逐步融入一点专业知识的人来说，你可以从零开始建立团队。这始于帮助人们投资于理解这种机器学习知识。这为他们奠定了基础，以便他们能够使用类似 `TensorFlow Extended` 示例 [2] 这样的工具构建你所需的机器学习流水线。这是帮助他们理解这些流水线如何用于构建和部署的一种方式。我认为所有能够做到这一点的培训都令人惊叹地在线上触手可及；人们在分享这类知识方面表现得极其慷慨。

## 困难在于将领域知识与深度机器学习技能相结合

这意味着你需要开始在组织内部寻找主题专家（SME）的知识。当你真正开始将那些在极其细粒度、深层次上了解业务的人员，与能够操作模型并进行部署的人员配对在一起时，事情就会起飞。这最终很可能会变成一项团队工作。你拥有来自主题专家的深厚知识，也有来自机器学习专家的深厚知识。在实践中，将这两个群体结合在一个团队里，就是推动事情完成的方式。你可能需要引入一位真正擅长构建不同层和网络的专家；他们能够构建精细的模型，从而增强团队实力并加快进度。有时你必须引入合适的人才，在过程中为项目注入动力。

### 1. 人才从何而来？

就我个人而言，我相信你可以从组织内部培养人才。如果你对这一断言持怀疑态度，请在脑海中记下一点：真正要挑战那种对内部成长和发展的偏见。在我的整个职业生涯中，我有着帮助内部人才成长的切实记录。这行得通，但它需要投入时间，并拥有与构建工具包相匹配的正确计划。我最引以为豪的职业成就之一，就是见证某人获得晋升。看到人们开始将先进的方法和技术带到组织的不同部门，是一件令人惊叹的事。你也可以体会这种感觉。你只需要走出去，开始为现有人员构建他们的工具包。真正花时间投资于他们作为团队成员和个人贡献者的成长与发展。

我们正处于学习机器学习的黄金时代 [3]。现在网上存在的培训资源多到你无法全部消化。它们以各种不同的形式存在。我最喜欢的是现在可用的在线实验室。我用得最多的一个叫作 `Coursera`。人们已经构建了完善的工具示例，展示如何进行机器学习。你不仅可以阅读相关内容，还能深入示例中实际操作一番。这正是自产品发布以来 `TensorFlow` 一直吸引我的地方。如此多的人慷慨地分享他们的知识、技能和能力 [4]。他们通过易于获取的课程、讲座，甚至一些证书，在网上分享着通往机器学习王国的钥匙。我已经学习了 50 多门课程。如果你真想深入了解我的学习历程，可以在我的 `LinkedIn` 个人主页上看到这些课程。那将展示我投入个人时间完成的课程。你也可以直接查看脚注中的链接，找到一个起点。

有时，组建内部团队的速度根本不够快。帮助内部人才开发出机器学习领域的世界级技能——事实上是任何领域——都需要时间。我认识到这是一个长期目标，也是你必须在过程中逐步建设的目标。你有几个选择可以开始寻找补充人才的途径。其中一种是雇佣承包商，让他们帮你启动项目。另一种是找到合适的产品或公司，帮你快速起步。目前有几家公司正在做这件事，其中一些能为你的组织带来实质性影响。

通常，组织内部的数据源并未建立良好的索引，也没有清晰映射的特征和关联。即使获取现成的数据源也是一个真正的挑战。在大多数情况下，人们使用的那些数据集是专门为这种用途而创建的。这些数据集并非自然产生于“野外”。即使制作定制的合成数据集，对于试图大规模落地机器学习的组织来说也是一项挑战。这就是为什么使用外部产品来管理数据、甚至访问 API 都需要规划和持续的投入。发送给 API 的数据必须保持一致。不断变化的数据流无论在内部还是外部管理起来都是噩梦。许多像 `Databricks` 这样的公司正涌入这一领域，帮助理清复杂的数据存储 [5]。

这些思考一次性消化可能有点多，但当组建团队解决机器学习问题成为刚需时，所有这些都会变得清晰明了。我对于“人才从何而来”的回答是：随着时间推移，融合优秀的专业人士，打造高绩效团队。这可能涉及招聘关键技能人员来补充团队，或者如果有足够的缓冲时间，则投资培训团队。缓冲时间越短，快速引入外部人才的需求就越迫切。

### 2. 如何让人才协同工作？

既然我们已经讨论了人才从何而来以及如何思考团队投资，现在让我们换个话题，聊聊如何让团队协同工作。这属于“说起来容易做起来难”的事情之一。你可以这样思考这一信条：让领导者领导，让管理者管理，让员工成功。当你拥有能够自我组织、快速完成工作的敏捷团队时，这套方法效果很好。如果你现在正处于这种状态，那么恭喜你，请珍惜你所拥有的。

团队关乎不同角色的人员如何协同工作。我倾向于将机器学习项目视为拥有两个关键支柱。首先，你需要弄清楚谁拥有关于产品、数据以及数据如何关联客户旅程的深度知识。这可能显而易见，也可能很困难。有时，这些对数据拥有最大机构知识的人是发挥关键作用的主题专家，他们可能深藏在组织的分析师岗位上，或者可能已经转岗到了其他角色。
