# 7.15 几点建议

在设计新包时，初学者 Go 程序员通常首先创建一组接口，然后再定义满足它们的具体类型。这种方法会导致许多接口，每个接口只有一个实现。不要这样做。这种接口是不必要的抽象；它们也有运行时成本。你可以使用导出机制（§6.6）来限制类型的方法或结构体的字段在包外的可见性。只有当有两个或更多具体类型必须以统一的方式处理时，才需要接口。

当接口由单个具体类型满足，但由于依赖关系，该类型无法与接口位于同一个包中时，我们对此规则作例外处理。在这种情况下，接口是解耦两个包的好方法。

因为接口在 Go 中只有在被两个或更多类型满足时才会使用，所以它们必然抽象掉了任何特定实现的细节。结果是接口更小，方法更少、更简单，通常只有一个，就像 `io.Writer` 或 `fmt.Stringer`。小接口在新类型出现时更容易满足。接口设计的一个好经验法则是*只请求你需要的东西*。

这结束了我们对方法和接口的探索。Go 对面向对象编程风格有很好的支持，但这并不意味着你必须专门使用它。并非所有东西都需要是对象；独立函数有它们的位置，未封装的数据类型也是如此。请注意，前五章的示例总共调用的方法（如 `input.Scan`）不超过两打，而普通函数调用（如 `fmt.Printf`）则多得多。

# 8. Goroutine 和 Channel

## 并发编程

并发编程——将程序表示为若干自主活动的组合——从未像今天这样重要。Web 服务器同时处理成千上万个客户端的请求。平板电脑和手机应用在用户界面渲染动画的同时，在后台执行计算和网络请求。即使是传统的批处理问题——读取一些数据、计算、写入一些输出——也利用并发来隐藏 I/O 操作的延迟，并利用现代计算机的众多处理器，这些处理器每年都在数量上增长，而非速度上。

Go 语言支持两种风格的并发编程。本章介绍 **goroutine（协程）** 和 **channel（通道）**，它们支持*通信顺序进程*（CSP），这是一种并发模型，其中值在独立的活动（goroutine）之间传递，但变量在很大程度上局限于单个活动。第 9 章 涵盖了更传统的*共享内存多线程*模型的某些方面，如果您在其他主流语言中使用过线程，这将会很熟悉。第 9 章 还指出了并发编程的一些重要危害和陷阱，我们将不会在本章深入探讨。

尽管 Go 对并发的支持是其最大优势之一，但推理并发程序固有地比推理顺序程序更难，从顺序编程获得的直觉有时会误导我们。如果这是您第一次接触并发，我们建议花费一些额外时间思考这两章中的示例。

## 8.1 Goroutine

在 Go 语言中，每个并发执行的活动被称为 **goroutine**。设想一个包含两个函数的程序，一个执行某些计算，一个写入某些输出，且假设两个函数互不调用。顺序程序可能先调用一个函数，然后调用另一个，但在拥有两个或更多 goroutine 的*并发*程序中，对*两个*函数的调用可以同时处于活跃状态。我们稍后将看到这样一个程序。

如果您使用过操作系统线程或其他语言中的线程，那么目前可以假设 goroutine 类似于线程，您将能够编写正确的程序。线程和 goroutine 之间的差异本质上是数量上的，而非质量上的，将在 9.8 节 中描述。

程序启动时，其唯一的 goroutine 是调用 `main()` 函数的那个，因此我们称之为 **main goroutine（主 goroutine）**。新的 goroutine 由 `go` 语句创建。从语法上讲，`go` 语句是一个在普通函数或方法调用前加上关键字 `go` 的形式。`go` 语句会在一个新创建的 goroutine 中调用该函数。`go` 语句本身会立即完成：

```
f()      // 调用 f()；等待其返回
go f()   // 创建一个调用 f() 的新 goroutine；不等待
```

在下面的示例中，主 goroutine 计算第 45 个斐波那契数。由于它使用了极其低效的递归算法，运行一段可感知的时间，在此期间我们希望通过显示动画文本“旋转器”向用户提供程序仍在运行的视觉指示。

**gopl.io/ch8/spinner**

```go
func main() {
    go spinner(100 * time.Millisecond)
    const n = 45
    fibN := fib(n) // 慢
    fmt.Printf("\rFibonacci(%d) = %d\n", n, fibN)
}

func spinner(delay time.Duration) {
    for {
        for _, r := range `-\|/` {
            fmt.Printf("\r%c", r)
            time.Sleep(delay)
        }
    }
}

func fib(x int) int {
    if x < 2 {
        return x
    }
    return fib(x-1) + fib(x-2)
}
```

经过几秒钟的动画后，`fib(45)` 调用返回，`main()` 函数打印其结果：

```
Fibonacci(45) = 1134903170
```

随后 `main()` 函数返回。当这发生时，所有 goroutine 都会被突然终止，程序退出。除了从 `main()` 返回或退出程序外，没有编程方式让一个 goroutine 停止另一个，但正如我们稍后将看到的，有方法与 goroutine 通信以请求其自行停止。

请注意程序是如何表示为两个自主活动的组合的：旋转和斐波那契计算。每个都被编写为单独的函数，但两者都能并发取得进展。

## 8.2 示例：并发时钟服务器

网络是使用并发的自然领域，因为服务器通常一次性处理来自客户端的许多连接，每个客户端本质上独立于其他客户端。在本节中，我们将介绍 `net` 包，它提供了用于构建通过 TCP、UDP 或 Unix 域套接字通信的网络客户端和服务器程序的组件。我们自 第 1 章 以来一直在使用的 `net/http` 包构建在 `net` 包的函数之上。

我们的第一个示例是一个顺序时钟服务器，它每秒向客户端写入一次当前时间：

**gopl.io/ch8/clock1**

```go
// Clock1 是一个定期写入时间的 TCP 服务器。
package main

import (
    "io"
    "log"
    "net"
    "time"
)

func main() {
    listener, err := net.Listen("tcp", "localhost:8000")
    if err != nil {
        log.Fatal(err)
    }
    for {
        conn, err := listener.Accept()
        if err != nil {
            log.Print(err) // 例如，连接中止
            continue
        }
        handleConn(conn) // 一次处理一个连接
    }
}

func handleConn(c net.Conn) {
    defer c.Close()
    for {
        _, err := io.WriteString(c, time.Now().Format("15:04:05\n"))
        if err != nil {
            return // 例如，客户端断开连接
        }
        time.Sleep(1 * time.Second)
    }
}
```

`Listen()` 函数创建一个 `net.Listener`，一个在网络端口（本例中为 TCP 端口 `localhost:8000`）上监听传入连接的对象。监听器的 `Accept()` 方法阻塞直到有传入连接请求，然后返回一个代表该连接的 `net.Conn` 对象。

`handleConn()` 函数处理一个完整的客户端连接。在一个循环中，它将当前时间 `time.Now()` 写入客户端。由于 `net.Conn` 满足 `io.Writer` 接口，我们可以直接写入它。当写入失败时循环结束，最可能是因为客户端已断开连接，此时 `handleConn()` 通过延迟调用 `Close()` 关闭其端的连接，并回到等待另一个连接请求的状态。

`time.Time.Format()` 方法提供了一种通过示例格式化日期和时间信息的方法。其参数是一个模板，指示如何格式化一个参考时间，具体为 `Mon Jan 2 03:04:05PM 2006 UTC-0700`。该参考时间有八个组成部分（星期、月、日等）。它们的任意集合可以以任何顺序和多种格式出现在 `Format` 字符串中；日期和时间的选定组成部分将以选定的格式显示。这里我们只使用了时间的小时、分钟和秒。`time` 包为许多标准时间格式定义了模板，例如 `time.RFC1123`。解析时间时使用 `time.Parse()` 采用相同的机制（反向操作）。

要连接到服务器，我们需要一个客户端程序，如 `nc`（“netcat”），一个用于操作网络连接的标准实用程序：

```bash

$ ./clock1 &
$ nc localhost 8000

13:58:55
13:58:56
13:58:57
^C
```

客户端每秒显示服务器发送的时间，直到我们用 Control-C 中断客户端，在 Unix 系统上，shell 会将其回显为 `^C`。如果您的系统未安装 `nc` 或 `netcat`，可以使用 `telnet` 或这个使用 `net.Dial` 连接到 TCP 服务器的简单 Go 版 `netcat`：

**gopl.io/ch8/netcat1**

```go
// Netcat1 是一个只读 TCP 客户端。
package main

import (
    "io"
    "log"
    "net"
    "os"
)

func main() {
    conn, err := net.Dial("tcp", "localhost:8000")
    if err != nil {
        log.Fatal(err)
    }
    defer conn.Close()
    mustCopy(os.Stdout, conn)
}

func mustCopy(dst io.Writer, src io.Reader) {
    if _, err := io.Copy(dst, src); err != nil {
        log.Fatal(err)
    }
}
```

该程序从连接中读取数据并将其写入标准输出，直到发生 end-of-file 条件或错误。`mustCopy` 函数是本节多个示例中使用的工具函数。让我们在不同的终端上同时运行两个客户端，一个显示在左侧，一个显示在右侧：

```bash

13:58:55
13:58:56
^C
                                       13:58:57
                                       13:58:58
                                       13:58:59
                                       ^C
$ killall clock1
```

`killall` 命令是一个 Unix 实用程序，用于终止所有具有给定名称的进程。

第二个客户端必须等到第一个客户端完成，因为服务器是*顺序*的；它一次只处理一个客户端。只需一个小小的改动即可使服务器并发：在调用 `handleConn` 时添加 `go` 关键字，会使每次调用都在自己的 goroutine 中运行。

**gopl.io/ch8/clock2**

```go
for {
    conn, err := listener.Accept()
    if err != nil {
        log.Print(err) // 例如，连接中止
        continue
    }
    go handleConn(conn) // 并发处理连接
}
```

## 8.3 示例：并发 Echo 服务器

时钟服务器为每个连接使用一个 goroutine。在本节中，我们将构建一个每个连接使用多个 goroutine 的 echo 服务器。大多数 echo 服务器只是写入它们读取的任何内容，这可以通过这个微不足道的 `handleConn` 版本来完成：

```go
func handleConn(c net.Conn) {
    io.Copy(c, c) // 注意：忽略错误
    c.Close()
}
```

一个更有趣的 echo 服务器可能会模拟真实回声的余音，响应起初很大声 (`"HELLO!"`)，延迟后变得中等 (`"Hello!"`)，然后变小声 (`"hello!"`) 最后渐渐消失，如这个版本的 `handleConn` 所示：

**gopl.io/ch8/reverb1**
