
任何企业的关键任务之一是帮助确保其用户和员工数据的安全。Google Cloud 提供内置的安全措施来促进数据安全，包括静态数据加密和传输中数据加密。让我们看看云系统中的静态加密和传输加密分别是什么。

### 静态加密

对于机器学习模型，你的数据将位于 `Cloud Storage` 或 `BigQuery` 表中。Google 默认对 `Cloud Storage` 和 `BigQuery` 中静态存储的数据进行加密。默认情况下，Google 管理用于保护数据的加密密钥。你也可以使用客户管理的加密密钥 (CMEK)。你可以使用带关联数据的认证加密 (AEAD) 加密函数在 `BigQuery` 中加密单个表值。请参考 `https://cloud.google.com/bigquery/docs/reference/standard-sql/aead-encryption-concepts` 以了解 `BigQuery` AEAD 加密函数。

#### 传输中加密

为了保护数据在读写操作期间通过互联网传输时的安全，Google Cloud 使用传输层安全性 (TLS)。

#### 使用中加密

使用中加密通过在数据处理过程中对其加密，保护内存中的数据免遭泄露或数据渗漏。`Confidential Computing` 通过在数据处理过程中对其加密，保护内存中的数据免遭泄露。您可以使用 Confidential VMs 和 Confidential GKE Nodes 对使用中的数据进行加密。阅读此博客以了解有关数据安全概念的更多详情：`https://cloud.google.com/blog/topics/developers-practitioners/data-security-google-cloud`。

#### 身份和访问管理

身份和访问管理 (IAM) 是在 Google Cloud 中管理对数据和资源访问的方式。（有关 IAM 的更多信息，请参阅 `https://cloud.google.com/vertex-ai/docs/general/access-control`。）Vertex AI 使用 IAM 管理对资源的访问。您可以在项目级别或资源级别管理访问权限：

*   **项目级角色**：要在项目级别授予对资源的访问权限，请向主体（用户、组或服务账号）分配一个或多个角色。服务账号是应用或计算工作负载的账号，而非个人最终用户的账号。服务账号主要用于创建 Vertex AI Workbench、Vertex AI 自定义训练和 Vertex AI 预测。
*   **资源级角色**：要授予对特定资源的访问权限，请在该资源上设置 IAM 政策；该资源必须支持资源级政策。该政策定义将哪些角色分配给哪些主体。

您可以使用这两个粒度级别来自定义权限。例如，您可以通过设置项目级政策，向所有 Vertex AI Feature Store 用户授予对所有特征存储的读取权限。Vertex AI Feature Store 以集中方式存储特征。对于一部分用户，您可以通过使用资源级政策，授予其对特定特征存储的写入权限。

以下是可在 Vertex AI 中使用的 IAM 角色：

*   **预定义角色**允许您在项目级别向 Vertex AI 资源授予一组相关权限。Vertex AI 的两个常见预定义角色是 Vertex AI 管理员和 Vertex AI 用户。
*   **基本角色**（如所有者、编辑者和查看者）提供对 Vertex AI 资源在项目级别的访问控制。这些角色适用于所有 Google Cloud 服务。
*   **自定义角色**允许您选择一组特定权限，使用这些权限创建自己的角色，并将该角色授予组织中的用户。

并非所有 Vertex AI 预定义角色和资源都支持资源级政策。

##### 使用 Vertex AI 保护网络安全

在深入了解如何使用 Vertex AI 保护网络安全之前，您应该了解 Google Cloud 共担责任模型和共担命运模型。在确定如何最好地保护您在 Google Cloud 上的数据和工作负载时，理解这些术语非常重要。

**共担责任模型**：根据 Google 共担责任模型，云提供商必须监控并响应与云本身及其底层基础设施相关的安全威胁。同时，最终用户（包括个人和公司）负责保护他们存储在任何云环境中的数据和其他资产。

**共担命运模型**：此模型旨在解决共担责任模型未涉及的挑战。共担命运侧重于各方如何更好地互动以持续改进安全性。共担命运建立在共担责任模型之上，因为它将云提供商与客户之间的关系视为一种持续改进安全性的长期合作伙伴关系。共担命运有几个组成部分：

*   **入门帮助**：安全蓝图，让您使用基础设施即代码 (IaC) 部署和维护安全解决方案。蓝图默认启用安全建议，例如 Vertex AI Workbench 笔记本蓝图。
*   **风险保护计划**

###### 保护 Vertex AI Workbench

默认情况下，您的托管笔记本实例使用 Google 托管网络。（我们在上一节介绍了如何使用 IAM 保护 Vertex AI Workbench。）保护 Workbench 的一些最佳实践如下：

*   **使用私有 IP 地址** Vertex AI Workbench 默认分配公共 IP 地址，这会增加攻击面并暴露敏感数据。最佳实践是在创建 Workbench 时使用私有 IP 地址。要创建私有 Vertex AI Workbench，您需要指定 `--no-public-ip` 命令。以下是使用私有 IP 地址创建 Workbench 的 Google CLI 命令：

```
gcloud beta notebooks instances create example-instance \
  --vm-image-project=deeplearning-platform-release \
  --vm-image-name=tf2-2-1-cu101-notebooks-20200110 \
  --machine-type=n1-standard-4 \
  --location=us-central1-b \
  --no-public-ip
```

*   **将您的实例连接到同一项目中的 VPC 网络** 要将托管笔记本实例连接到与您的托管笔记本实例位于同一项目中的 VPC 网络，您需要配置私有服务访问。私有服务访问使您能够访问托管在 VPC 网络中的内部 IP 地址。如果您希望 VPC 网络中的虚拟机实例使用内部 IP 地址而不是外部 IP 地址，这非常有用。请参阅此链接了解更多信息：

`https://cloud.google.com/vpc/docs/private-services-access`

*   **共享 VPC 网络** 您还可以指定位于您项目内的 VPC 网络，或您有权访问的共享 VPC 网络。如果您指定了 VPC 或共享 VPC 网络，该网络需要建立私有服务访问连接。共享 VPC 允许组织将来自多个项目的资源连接到一个通用的虚拟私有云 (VPC) 网络，以便它们可以通过使用该网络中的内部 IP 地址安全高效地相互通信。

    *   **VPC Service Controls** 这是一项功能，允许您控制 VPC 中可用的服务。您可以使用 VPC Service Controls 允许或拒绝对特定服务的访问，或限制特定服务可产生的流量。当您使用 VPC Service Controls 保护 Vertex AI 时，以下工件无法离开您的服务边界：
        *   AutoML 模型或自定义模型的训练数据
        *   您创建的模型
        *   在线预测请求
        *   批量预测请求的结果

###### 联邦学习

根据 Google AI 博客 `https://ai.googleblog.com/2017/04/federated-learning-collaborative.html`，*联邦学习* 是一种技术，用于使移动电话能够协作学习共享预测模型，同时将所有训练数据保留在设备上。设备下载模型并从设备数据中学习。然后通过加密通信将此更新后的模型发送到云端。由于所有训练数据都保留在您的设备上，联邦学习在确保隐私的同时，实现了更智能的模型、更低的延迟和更低的功耗。

一个例子是全球一组参与同一临床试验的医院。单个医院收集的患者数据不在医院外部共享。因此，医院无法将患者数据传输或共享给第三方。联邦学习让关联医院能够在仍保留每家医院内部患者数据的安全性、隐私和控制权的同时，使用所有医院共享的中心化模型训练共享机器学习模型。该模型在医院本地训练数据，仅将模型更新发送回中心化云服务器。模型更新被解密、平均并集成到中心化模型中。迭代轮次进行，协作训练持续进行，直到模型完全训练完成。这样，联邦学习将进行机器学习的能力与在云端存储数据的需求解耦了。更多信息请参阅此链接：`https://cloud.google.com/architecture/federated-learning-google-cloud`。

###### 差分隐私

根据 `https://en.wikipedia.org/wiki/Differential_privacy`，*差分隐私 (DP)* 是一种系统，通过描述数据集内个体群组中的模式来公开共享关于数据集的信息，同时隐瞒数据集中每个个体的信息。例如，为医学诊断训练机器学习模型，我们希望拥有不会记住训练集敏感信息（如个别患者的具体病史）的机器学习算法。差分隐私是一种概念，允许量化算法为其运行的底层（敏感）数据集提供的隐私保护程度。通过差分隐私，我们可以设计负责任地在私有数据上训练模型的机器学习算法。

### 格式保留加密与令牌化

#### 格式保留加密 (FPE)

**格式保留加密**，或 **FPE**，是一种在加密过程中保留信息格式的加密算法。它是以这样的方式加密数据，使得输出（密文）与输入（明文）保持相同的格式。更多信息请参阅 `https://en.wikipedia.org/wiki/Format-preserving_encryption`。

此技术有两个用例，如下所示：

*   **支付卡验证：** 在零售和电子商务领域，必须收集并存储支付卡数据以进行支付。此外，员工可能需要查看并验证客户支付卡信息的后四位数字。FPE 使得仅向员工暴露所需信息变得更加容易，同时让其他 12 位数字保持受保护状态。
*   **遗留数据库：** 电信系统可能拥有大量需要使用加密数据以保障安全的遗留系统。但是，重构数据库以存储加密数据可能不是该组织的可选方案。借助 FPE，数据库的结构可以保持不变。（更多信息请参阅 `www.ubiqsecurity.com/what-is-format-preserving-encryption-fpe-and-its-benefits`。）

#### 令牌化

**令牌化** 是指用一个称为令牌的替代值来替换一段敏感数据（如信用卡号）的过程。敏感数据通常仍需安全地存储在一个中心位置，以供后续参考，并需要对其采取强有力的保护措施。令牌化方法的安全性取决于敏感值的安全性，以及用于创建替代值并将其映射回原始值的算法和过程。

FPE 对敏感信息进行混淆，而令牌化则将其完全移除（至另一位置）。
