
# 漏洞利用框架

漏洞利用框架（Exploit frameworks）在渗透测试方面取得了巨大进展。漏洞利用框架允许用户对漏洞计算机进行目标攻击、利用并获取控制。这些工具设计用于合法的渗透测试。漏洞利用框架通过提供一键利用，将漏洞评估工具提供的功能提升到了另一个水平。该类别中一些最著名的工具包括 `Metasploit`、`CANVAS` 和 `Core Impact`。

> 如果你从未用过漏洞利用框架，你应该下载 `Metasploit` 并查看其功能。你可以从 [www.metasploit.com/download/](http://www.metasploit.com/download/) 下载。

## 总结

本章重点介绍了应用程序测试的重要性。对于安全专业人员来说，这至关重要，因为应用程序是一个高度有针对性的领域。几年前，Web 服务器是攻击者的主要目标之一。今天，客户端系统正受到广泛攻击。它们成为目标部分原因是因为它们目标丰富。大多数客户端系统运行着许多应用程序，例如 `Adobe Reader`、`Microsoft Office`、`Flash` 和 `Java`。存在漏洞的应用为攻击者提供了进入系统的便利条件。

尽管应用程序很重要，但这只是一个关注领域。网络也同样重要。网络必须能够抵抗拒绝服务攻击（DoS）、后门攻击、欺骗攻击、中间人攻击、密码破解等。每种攻击都利用了网络技术固有的弱性。防御此类及许多其他威胁的最佳方法之一是进行定期测试。这种测试可以安全审计、漏洞扫描和渗透测试的形式进行。每种测试都在保护关键基础设施和防御网络受攻击方面发挥着作用。

## 考试要点

了解软件利用（Software exploitation）是如何发生的。软件利用涉及以一种软件制造商未计划或未预到的方式使用软件产品的功能或能力。在许多情况下，原始功能增强了产品的功能，但遗憾的是，它也创建了潜在的漏洞。

- 能够描述应用程序问题。一些常见的应用程序问题包括 XSS（跨站脚本）、CSRF（跨站请求伪造）、点击劫持（clickjacking）、SQL 注入和糟糕的输入验证。

- 能够描述安全开发的方法。可以通过遵循结构化流程（如 SDLC）来实现安全开发。有许多不同的模型和方法，有些步骤较多，但总体目标相同：控制过程并增加安全性以构建深度防御。一些行业认可的方法包括 `SDLC`、`OWASP` 和 `NIST` 指南。

- 了解漏洞扫描和渗透测试之间的区别。漏洞扫描通常使用软件包程序如 `SAINT`、`Nessus` 或 `Retina`。这些程序可以帮助识别需要补丁的系统和应用程序。渗透测试通常以对抗的方式进行，提出的问题包括攻击者可以看到什么以及利用这些信息做什么。渗透测试类似于计算机犯罪的非法攻击，但是经过所有者许可。

- 能够描述密码破解。密码破解是检索和破解存储或传输系统中传输的过程。密码破解工具可以使用几种基本方法测试密码强度，包括字典、混合、暴力破解和彩虹表。

- 定义渗透测试技术。渗透测试可以在完全了解或非常了解目标网络的情况下进行。每种技术都有其优势。渗透测试也可以在不通知所有内部人员的情况下进行。

- 能够描述何时使用代码审查或黑盒测试。在应用程序部署之前，必须对其进行审查和测试。测试类型取决于具体情况。例如，如果一个组织在内部开发应用程序，代码很可能是提供的，可以进行完整的代码审查。在其他情况下，如果公司购买现成应用程序，源代码可能不可用。在这些情况下，可能会进行黑盒审查。

- 能够描述为什么社会工程学攻击难以防御。社会工程学攻击难以防御，因为它不针对硬件或软件，而是针对个人。如果没有适当的培训，员工可能不知道某些安全策略的存在，或者不知道在特定情况下应如何应对。培训和意识培养是防御社会工程攻击的最佳防御手段。

# 风险术语

在讨论风险管理之前，确保定义一些基本术语是重要的。所有行业都有共同的基础术语和语义。IT 安全也不例外，在风险主题中，有一些你会反复看到的术语。让我们从回顾这些术语开始：

**资产 (Asset)** *资产*是机构的具有价值的项，例如数据、硬件、软件或物理属性。资产是对于公司具有定量或定性价值的项或项集合。

**风险 (Risk)** *风险*是威胁发生或实现的概率或可能性。

**漏洞 (Vulnerability)** *漏洞*可以描述为硬件、软件或组件中的缺陷，这些缺陷可能被利用以通过威胁破坏、损害或侵害资产。

**威胁 (Threat)** *威胁*是任何可能对 IT 资产或数据资产造成危害、损失、损害或侵害的代理、条件或情况。威胁的可能性是发生的概率或事件实际发生的几。

**动机 (Motivation)** *动机*是活动背后的驱动力。例如，黑客可能出于许多不同原因。一些常见原因包括声望、金钱、名声和挑战。

**风险源 (Risk Source)** 这种风险的*源*可以是内部的，也可以是外部的。内部风险可以是从不满的员工到硬盘故障的任何情况。外部风险包括洪水等自然灾害以及罢工和抗议等人为事件。例如，当威胁是有人偷取服务器硬盘时，风险源可能是服务器机柜的锁了。

从 IT 安全的角度来看，威胁是任何影响 IT 资产（数据、系统、软件或硬件）机密性、完整性或可用性的情况。常见的威胁示例包括：

**自然灾害 (Natural Disaster)** 这些是我们无法控制的事件，例如恶天气（飓风、雪暴、龙卷风）、火灾、地震海啸。

**恶意代码 (Malicious Code)** 恶意代码包括所有形式的破坏程序，如病毒、蠕虫、木马、键盘记录器等。此类软件的特征在于，它们是为了破坏、更改、暴露或破坏系统或数据而开发的。例如，病毒是可执行程序，它们会复制并附加于感染其他可执行对象。某些病毒在复制和感染完成后还会执行破坏性或隐蔽活动（载荷）。

**物理安全泄露 (Breach of Physical Security)** 这种威胁可能是受信任的内部人员或不受信任的外部人员造成的。入侵者、破坏者和窃窃者移除敏感信息、破坏数据，或物理上损坏或移除硬件，如硬盘和。

**黑客攻击 (Hacker Attack)** 黑客攻击通常导致数据被盗、丢失、损坏或修改。如果组织在数据恢复和业务连续性计划中对数据进行备份或外部存档，那么组织数据的丢失或损坏可能成为关键威胁。此外，如果数据具有机密性并遭到破坏，根据此类泄露可能造成的潜在损害，这对组织来说也可能是一个关键威胁。

**分布式拒绝服务 (DDoS)** 针对网络或基于网络的系统的 DDoS 攻击旨在通过大量无用流量来瘫痪网络或防止访问特定设备。DDoS 攻击可以通过多种方式发起。一种方法是使用如 Ping of Death 和 Teardrop 等基础 DoS 工具。攻击者还可能使用更先进的分布式 DDoS 工具，如 Tribal Network、Shaft 或 Low Orbit Ion Cannon。目前，大多数 DDoS 攻击是通过僵尸网络发起的。结果是目标系统的通信能力降低或受到限制。

这种理念是有动机的黑客利用计算机、互联网通信和工具来渗透关键国家基础设施，如水厂、电力和燃气厂；石油和汽油精工厂；核电厂；废物处理厂等。

此列表并非涵盖所有。

# 识别漏洞 (Identifying Vulnerabilities)

安全专业人员的一项大任务是识别漏洞。漏洞是系统设计、操作程序实现或软件或代码开发方式中的缺陷（例如漏洞、后门、代码中的漏洞等）。通过正确实施防护措施和安全对抗措施，可以消除或减少漏洞。

在处理风险时，软件是安全专业人员必须关注的领域之一。各种软件中的漏洞非常常见。示例包括：

- **固件 (Firmware)** 通常存储在 ROM 中并在系统上电期间加载的软件。由于固件是嵌入的，它可以被用于隐藏恶意代码，如固件根特攻击程序。

- **操作系统 (Operating System)** 加载在工作站、服务器、笔记本电脑、平板电脑和智能手机中的操作系统软件。未修补的操作系统可能是巨大的风险，特别是对于服务器和连接互联网的系统。

- **配置文件 (Configuration Files)** 设备的配置文件和配置设置。配置文件可以被修改以运行未经授权的程序或批处理文件。

- **应用程序 (Application Software)** 在笔记本电脑、工作站或智能手机上运行的应用程序或可执行文件。未修补的应用程序是今天攻击者最大的目标之一。在过去的几年里，Adobe Reader、Java、Flash 甚至 Microsoft Office 等应用程序一直是漏洞利用的目标。

在练习 6.1 中，你将学习如何识别和跟踪漏洞。

### 练习 6.1

跟踪软件中的漏洞

漏洞由美国计算机应急准备小组 (US-CERT) 在一个公开访问的数据库中进行跟踪。一旦发现漏洞，它就会被赋予一个编号并添加到数据库中。CVE 列表中包含的每个漏洞或暴露都有一个通用的、标准的 CVE 名称。

了解 CVE 的结构是重要的。

1. 访问 http://web.nvd.nist.gov/view/vuln/search。

2. 搜索 CVE-2011-1551。

3. 识别与 SUSE Linux 相关的漏洞。

4. 现在搜索最新的漏洞。今年已经发布了多少个？

软件供应商意识到，他们无法创建完美的代码，因此他们必须保护自己免受漏洞可能带来的风险和潜在责任。

当代码中发现漏洞时，供应商可以以多种方式做出响应。在一种方法中，供应商可能会宣布该程序或应用程序不再支持。例如，如果有人发现了 Windows ME 的问题，不要期待微软会解决它。如果供应商仍然支持该产品（如 Windows 7），他们很可能会提供更新或补丁来修复发现的漏洞。他们从发现漏洞之前到完成补丁的过程通常遵循以下阶段：

1. 供应商向公众发布带有未知漏洞的软件和代码。

2. 发现了一个漏洞。

3. 供应商创建了对抗措施或补丁。

4. 发布了补丁并供公众使用。

5. 在受影响的系统或设备上下载并安装补丁。

从发现漏洞到应用补丁之间的时间被称为漏洞时间 ($Vt$)。这表示为

$Vt = Vt_{open} - Vt_{closed}$

这个漏洞窗口是 IT 资产最脆弱的时期。这个窗口对安全专业人员至关重要，因为比过去要大得多。这种基于已知漏洞创建恶意软件的循环变得越来越短，如图 6.1 所示。
