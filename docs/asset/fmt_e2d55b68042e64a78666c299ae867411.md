
# 大多数当前的边界安全工具（如防火墙和 IPS）远离应用程序在内存中的运行时环境

这些设备无法知晓应用程序的运行时条件，因此无法区分真实威胁和潜在威胁。同样，漏洞扫描器也跟不上云容器快速启动和关闭的节奏，因此无法区分暴露在外部的漏洞和受边缘保护设备保护的漏洞。

然而，较新的**运行时应用自我保护 (RASP)** 工具已被开发出来，通过监控应用程序运行时环境的输入以发现潜在的意外更改或篡改，从而提高应用程序安全性。当检测到这些活动时，受 RASP 保护的应用程序会采取行动予以阻止，并通知用户或安全人员。其他可能的操作包括关闭应用程序或终止会话。

## 应用程序执行控制

**应用程序执行控制** 是一种网络安全缓解策略，旨在防止恶意代码在计算系统上执行。该策略始于识别环境中所有机器上获准运行的应用程序。应用程序识别完成后，下一步是创建规则，确保仅允许这些应用程序在机器上运行。最后，实施加密哈希规则、发布者证书规则和路径规则，以强制执行应用程序执行控制。必须配置文件夹、文件和应用程序权限，以阻止所有未经授权的修改。

应用程序控制策略应包含记录被阻止的恶意代码执行尝试的条款。这些事件日志应配置为提供所有被阻止尝试的文件名、日期/时间戳和用户名。这些信息对于识别尝试攻击的个人或组织非常有价值。

这些规则应作为组织变更管理策略的一部分进行维护，并且应至少每年进行一次审查和验证。

## 用户访问管理

网络中基本上有两类用户——`administrators`（管理员）和 `users`（用户）。这些类别也可能存在于两个不同层级——位于单个客户端设备上的本地账户数据库和位于网络服务器上的网络账户数据库。请回顾一下，网络账户设置通常优先于本地设置。

在 Microsoft Windows 环境中，安装后会有几个 `default user accounts`（默认用户账户）。这些账户包括以下内容：

*   **Administrator**（管理员）：这是主要的管理账户，拥有对系统及其所有管理工具的完全访问权限。
*   **Guest account**（来宾账户）：这是一个统称账户，用于为没有计算机用户账户的用户提供访问权限。建立用户账户后，应禁用此账户。
*   **HelpAssistant**：这是一个特殊的 Windows 账户，配合其远程协助实用程序使用，用于验证通过它连接的用户。每当创建远程协助邀请时，此账户即被启用，当所有邀请过期后，会自动禁用。
*   **SUPPORT_XXXXX**：这是一个特殊的 Microsoft 账户，用于通过其帮助和支持服务实用程序提供远程支持。
*   **DefaultAccount**（默认账户）：在 Windows 10 后期版本和 Windows Server 2016 中，引入了一个新的系统管理账户，称为默认系统管理账户 (DSMA) 或 DefaultAccount。

这些默认用户账户可以重命名，但无法删除。初始 Windows 管理员账户的密码在安装过程中设置。

与基于 Microsoft 的网络环境类似，Linux 系统采用“用户和组”结构来控制对本地和网络资源（文件、目录和外围设备）的访问。每个获准访问 Linux 系统的人员都必须被分配一个用户名。除 `root superuser`（root 超级用户）外，用户名由管理员根据需要创建。

通过 `useradd` 命令行工具将用户添加到 Linux 系统，而现有用户账户信息可通过 `usermod` 命令进行修改。结合 `useradd` 创建的用户名使用 `passwd` 命令（`passwd username`），可为以新用户身份访问系统建立密码要求。

给定网络可能采用单一管理员，其对系统的所有方面（包括服务器、网络介质和连接设备）拥有全面控制权。然而，较大的网络通常有多个管理员，他们分担特定的网络职责，如服务器管理员、网络管理员和安全管理员。在这些情况下，最佳实践是仅保留必要数量的管理员账户，并将这些账户配置为仅拥有执行其职能所需的权限。

对于可以访问计算机服务的网络用户，安全性始终与功能性相平衡。某些网络环境可能拥有授权用户名单（员工或代理），但仍需容纳公众（未授权用户或客户）。在这些情况下，必须设置认证方法以同时适应这两类用户。通常这涉及为不同类别的用户建立不同的组账户，然后严格地为每个组提供所需的资源。

### 建立用户和组账户

企业和工业网络中的管理员为网络成员创建用户和组账户，其中包含对网络及其资源的特定 `access rights`（访问权限）和 `permissions`（权限）。根据为网络用户建立的访问控制策略（无论是针对个人还是其所在的不同网络 `groups`（组）），允许或拒绝用户读取、修改和检查文件和文件夹的访问权限。

认证可通过基于包含在已启用组中的继承过程应用于特定个人。例如，由于包含在公司的 `accounting group`（会计组）中，会计部门的所有成员可能会获得对会计程序和文件的 `inherited access`（继承访问权限）。

管理员使用 `group accounts`（组账户）来统一处理具有共同需求的用户账户。这样做可节省时间，允许他们一次性向组内所有人授予用户权限和资源访问权限。然而，即使授予用户访问特定资源的权限，管理员也可以限制用户对不同文件和文件夹可执行的活动范围。

#### Windows Active Directory 默认安全组账户

Windows Server 版本提供了大量默认组来管理各种用户类型。Windows Server 2019 提供了 45 多个默认 `Active Directory (AD) groups`（Active Directory 组）供使用。从 2008 版至今的 Windows Server 版本的 Active Directory 安全组完整列表可在 `https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups` 找到。Windows Server 系统中的一些关键默认组账户包括以下内容：

*   **Administrators**（管理员）：此组成员拥有对计算机及其工具的完全访问权限，可执行所有管理功能。此组自动包含 Administrator 用户账户作为成员。

## Windows 内置组

*   **Guests（来宾）**：此默认组对系统的访问权限最小化，且所有成员共享同一用户配置文件。Guest 用户账户自动成为该组的成员。
*   **Power Users（高级用户）**：Power Users 是一个特殊组，拥有在系统上执行许多管理任务的权限，但不具备 Administrator（管理员）账户的完全管理特权。Power Users 可以创建和管理用户及组。此外，除非通过其他来源被授予权限，否则他们无法访问 NTFS 卷上的文件和文件夹。创建该组时没有任何成员。
*   **Backup Operators（备份操作员）**：顾名思义，该组成员可以备份和还原计算机上的所有文件。通过备份实用程序，该组成员拥有对系统整个文件系统的访问权限。创建该组时没有任何成员。
*   **Network Configuration Operators（网络配置操作员）**：该组成员可以管理系统网络配置的不同方面。具体而言，他们可以修改 TCP/IP 属性；启用、禁用和重命名连接；并执行 `ipconfig` 操作。创建该组时为空。
*   **Users（用户）**：这是一个包罗万象的组，拥有有限的默认权限。除 Guest 账户外，系统上创建的所有用户账户（包括 administrator 账户）默认均为此组成员。
*   **Remote Desktop Users（远程桌面用户）**：此 Windows 组的成员拥有远程登录系统以执行远程桌面活动的用户权利。该组默认没有成员。

### Windows 域账户

Windows 服务器系统在*域环境*中使用时，也支持*域用户和组账户*。在域环境中，网络的所有成员共享一个通用的目录数据库，并被组织到不同层级。域由唯一名称标识，并作为一个具有通用规则和程序的单一单元进行管理。

域账户通过 Windows *域控制器*上的“Active Directory 用户和计算机”实用程序创建，并存储在 *Active Directory 数据库* 中。当 Windows 客户端设备被置于域环境中时，某些组成员身份会自动更改以反映这一变化。

*   **Domain Admins（域管理员）**：此组被添加到本地 Administrators 组，以便域管理员对其域内的所有计算机拥有管理控制权。
*   **Domain Users group（域用户组）**：此组被添加到本地 Users 组。
*   **Domain Guests group（域来宾组）**：此组被添加到本地 Guests 组。

这些组均为 Windows 域控制器的功能，仅存在于 Windows 域环境中。在域环境中自动添加这些组，使得域管理员更易于配置对本地计算机资源的访问。这些组并非永久添加，管理员可酌情将其移除。

### Linux 组账户

与其他多用户操作系统一样，出于管理目的，单个 Linux 用户通常被设为组的成员。由于组内存在的关系，用户生成的文件归该组成员所有。

与 Windows 不同，安装后存在的默认组列表因不同的 Linux 发行版而异。大多数发行版中常见的 Linux 组包括以下内容：

*   **games**：此组提供对游戏软件的访问权限。
*   **users**：这是标准的默认 Linux 用户组。
*   **wheel**：一个管理组，通常提供对用户创建和配置实用程序（`su` 和 `sudo` 命令）的访问权限。
*   **daemon**：这是一个标准的默认用户/组，拥有执行守护程序（后台进程）的特权，这些程序无需用户指导即可运行。在 Microsoft 体系中，此类程序被称为“驻留程序”，最类似于 Windows 环境中运行的服务。
*   **bin**：这是一个标准的默认 Linux 组，历史上提供运行可执行文件的权限。`bin` 的引用基于存储在那里的二进制（可执行）文件类型。该文件夹包含可执行以执行任务的脚本和命令。该目录中的命令可由每个用户运行。
*   **mail**：此组拥有特殊的邮件特权。
*   **root**：root 管理员组是一个标准的默认 Linux 组，拥有对系统的完全管理控制权。
*   **nobody**：这是非特权组。
*   **disk**：此组提供对“块设备”（如磁盘驱动器和光驱）的访问权限。

此列表仅显示了可能安装在特定 Linux 系统中或添加到其中的常见组中的一部分。Linux 中添加组的工具是 `groupadd`。组信息通过 `groupmod` 命令修改，用户通过 `usermod` 命令添加到组中。

## 组账户安全

在处理组账户时，有几个安全相关的操作需要牢记。

*   **删除或禁用未使用的默认账户**，例如 Guest 账户。如果置之不理，攻击者可能利用这些账户进行攻击。如果必须保留默认账户，请更改其名称，因为其标准身份验证凭据为潜在攻击者所熟知。此外，严格限制这些账户的访问权限、权利和权限。
*   **创建用户组**，涵盖具有共同需求的不同类型用户相关的功能，然后根据组的功能需求为每个组分配权利和权限。
*   **创建用户账户**，并根据其在组织中的工作职能将其分配到组。采用此方法可防止管理员必须单独配置每个用户的账户设置。仅创建所需账户，因为如果被发现，未使用的账户可能造成安全漏洞。
*   **设置账户密码**，使其在组织的密码策略下工作。
*   **安装并配置任何额外的身份验证系统**，例如选定用于网络的生物识别扫描设备或其他多因素身份验证应用程序。

## 网络身份验证选项

在网络层面，`username` 和 `password` 系统仍然是使用中的第一道 `authentication options`（身份验证选项）防线。即使您可能是一个或多个组账户的成员，也无法使用这些账户之一登录网络。您只能通过使用合法的用户账户登录来获得系统访问权限。在客户端-服务器网络中，经过身份验证的用户列表存储在服务器上，而非本地计算机。

此外，在网络层面，网络登录通常会覆盖任何本地系统登录。因此，管理员通过密码策略声明控制谁可以登录网络的任何部分。他们还设置网络密码策略，规定用户必须多久更改一次密码，以及设置长度和复杂性要求。

通常，网络管理员可以为网络用户配置以下与密码相关的设置：

*   **Enforce password history（强制密码历史）**：此选项用于指定将为每个用户跟踪的密码数量。当用户尝试更改密码时，将不允许重用任何正在跟踪的密码。

### 密码策略设置

*   **最大密码使用期限/最小密码使用期限**：这两个设置允许管理员设定密码在指定天数后过期，并防止用户在特定天数内更改密码。密码过期时，系统会提示用户更改，确保即使密码泄露，也会在短时间内更换以堵住安全漏洞。
*   **最小密码长度**：此选项用于指定密码可包含的最小字符数。这允许管理员强制用户使用更长、更难猜测的密码。对于安全系统，建议密码至少包含八个字符。
*   **密码必须符合复杂性要求**：管理员可使用此选项强制用户使用更安全、更复杂的密码，这些密码需包含小写字母、数字、符号和大写字母的某种组合。管理员通过在域控制器级别建立密码筛选器来设定复杂性级别。

### 建立资源控制

服务器操作系统提供为文件、文件夹/目录及其他系统资源指定单独*访问权限*的功能。管理员的工作是仔细设置访问控制，使其允许授权用户访问和使用指定的系统资源，并拒绝未授权用户的访问以防止安全漏洞。

通过将*最小权限原则*应用于这些配置（如前所述），管理员可以减少恶意和无意安全漏洞发生的机会。例如，拒绝对文件和目录的读取访问有助于保护信息的机密性，而拒绝不必要的写入（修改）访问有助于维护信息的完整性。

将大多数系统相关工具的执行权限限制在授权系统管理员范围内，可以防止用户进行可能降低安全性的配置更改。这也能限制攻击者利用这些工具攻击服务器或网络上其他主机的能力。

#### NTFS 权限

Windows 环境中使用的 NTFS 文件管理系统包含安全功能，允许将权限级别分配给磁盘上的文件和/或文件夹。*NTFS 权限*设定用户可对指定文件或文件夹执行的操作参数。它们可由管理员直接分配，也可通过组设置继承（如默认的 Everyone 组）。

NTFS 权限可配置为*允许*或*拒绝*选项。如果用户对特定文件夹或文件仅具有读取权限，但被分配到了一个对该文件夹或文件拥有更广泛权限的组，则该用户将通过该组获得额外权利。另一方面，如果用户被分配了针对特定权限级别的拒绝选项，则即使其所属的另一个组授予了该权限，也会被拒绝。在服务器环境中，文件的默认权限设置为“无访问权限”。

*标准 NTFS 文件夹权限*包括：

*   **读取**：允许用户或组查看父文件夹的文件、文件夹或子文件夹及其属性和权限。
*   **写入**：允许用户或组添加新文件或子文件夹、更改文件和文件夹属性、向现有文件添加数据，以及更改父文件夹内的显示属性。
*   **读取和执行**：允许用户或组更改子文件夹、显示属性和权限，并运行可执行文件类型。
*   **修改**：允许用户删除文件夹，并执行与写入、读取和执行权限相关的所有活动。
*   **列出文件夹内容**：允许用户或组查看文件夹内的文件和子文件夹。
*   **完全控制**：允许用户或组取得文件夹所有权并更改其权限，以及执行所有其他权限允许的活动。

*标准 NTFS 文件权限*包括：

*   **读取**：允许用户或组查看文件及其属性和权限。
*   **写入**：允许用户或组覆盖文件、更改其属性，并查看其所有权和属性。
*   **读取和执行**：允许用户或组运行和执行应用程序，以及拥有读取权限的所有选项。
*   **修改**：允许用户修改和删除文件，并执行与读取、写入、读取和执行权限相关的所有活动。
*   **完全控制**：允许用户或组取得文件所有权并更改其权限，以及执行所有其他权限允许的活动。

#### Linux 权限

Linux 操作系统也采用文件和目录权限来防止未授权访问。在 Linux（和 UNIX）系统中，除文档和可执行文件外的其他结构也被定义为文件。磁盘驱动器、光驱、调制解调器、输入输出设备和网络通信等其他系统资源也作为文件进行访问。

Linux 系统中的每个文件都分配有*所属用户*和*所属组*，以及针对每种所有者类型的访问权限。*权限*也针对*非特权用户*建立。可配置三种类型的访问权限：

*   **读取 (r)**：指定后，允许用户读取文件或目录的内容。
*   **写入 (w)**：指定给文件时，允许用户通过写入来修改文件。分配给目录时，写入权限允许用户在目录中创建或删除文件。
*   **执行 (x)**：允许用户执行具有此权限的文件和脚本。

每种权限均针对每个用户类别独立建立。典型的文件权限显示（如通过列表命令 `ls` 获取）将呈现以下格式：

```
drwxrwxrwx user group filesize Jan 01 08:00 filename
```

左侧列的每个 `rwx` 片段分别显示所属用户、所属组和其他用户的活动权限设置。本示例中出现所有三种权限类型，表明这三组均启用了所有权限。当某用户的特定权限被禁用时，其位置包含一个简单的破折号字符：

```
drwxrw-r-- user group filesize Jan 01 08:00 filename
```

在本示例中，所属用户仍拥有所有权限，但所属组权限降为读取和写入，而其他用户权限仅降为读取。

在 Linux 系统中创建目录或文件时，它会与其创建者关联，创建者默认成为其*所有者*。通常，Linux 用户会为其非可执行文件分配 `–rw-r--r--` 权限。此设置允许其他人读取其文件，但无法更改。同样，目录通常分配 `–rwxr-xr-x` 权限。这允许其他人浏览目录并执行，但无法在其中写入新文件或删除现有文件。
