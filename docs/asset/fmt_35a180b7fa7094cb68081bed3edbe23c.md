### 2.

你正在作为评估的一部分运行多个枚举扫描。在其中一次特定的扫描中，你让 `nmap` 发送一个初始的 `FIN` 包，紧接着发送一个 `ACK` 包。以下哪项最能描述你正在运行的扫描类型？

**A.** 反向 TCP (Inverse TCP)

**B.** TCP Maimon

**C.** XMAS

**D.** 半关闭 (Half-closed)

![Image](img/r.jpg)`B.` 根据 `nmap` 关于扫描的文档（[`nmap.org/book/scan-methods-maimon-scan.html`](https://nmap.org/book/scan-methods-maimon-scan.html)），早在 1996 年，一位名叫 Uriel Maimon 的先生写了一篇名为《无 SYN 标志的端口扫描》的文章。文章描述了发送一个初始 `FIN` 包随后跟随一个 `ACK` 包，利用 `TTL` 值之间的差异来评估端口。

EC-Council `TCP Maimon` 放回了官方教材，显然想让你了解它。根据学习材料，如果端口是打开，你将得不到响应；但如果它处于关闭状态，你将收到一个 `RST` 包。

![Image](img/w.jpg)`A` 是错误的，因为反向 TCP 扫描是带有或不带标志发送 TCP 探测标志的扫描。无响应表示开放端口，而 `RST` 则发送到关闭的端口。此扫描中通常使用的标志包括 `FIN`、`URG` 和 `PSH`。顺便提一下，如果不使用任何标志，也可以称为“空扫描 (null scan)”。

![Image](img/w.jpg)`C` 是错误的，因为 `XMAS 扫描` 是开启所有 TCP 标志（`FIN`、`URG`、`PSH`）的扫描。这种扫描对 Windows 系统无效，仅对使用基于 `RFC-793` 的 TCP 栈设备有效。

![Image](img/w.jpg)`D` 是错误的，因为这种扫描类型不存在。

### 3.

你准备好了一个僵尸系统并开始进行 `IDLE scan`。随着扫描的进行，你注意到从僵尸机器上收集到的碎片标识符正在随机递增。这意味着什么？

**A.** 你的 `IDLE scan` 结果对你没有用。

**B.** 该僵尸系统是一个蜜罐机 (honeypot)。

**C.** 你和僵尸机器之间存在一个异常的防火墙。

**D.** 这是 `IDLE scan` 期间的预期结果。

![Image](img/r.jpg)`A.` `IDLE scan` 利用了僵尸机器和 IP 递增碎片标识符 (`IPIDs`) 的特性。然而，在扫描期间，僵尸对所有其他流量保持空闲是至关重要的。攻击者将使用僵尸的（伪造）源地址向目标发送包。如果端口是打开的，目标将用 `SYN/ACK` 响应 `SYN` 包，但这会被发送给僵尸。僵尸系统将对这个未请求的 `SYN/ACK` 构造一个 `RST` 包，此时 `IPID` 就会增加。如果这种情况随机发生，那么可能你的僵尸实际上并不是空闲的，你的结果就是徒劳的。你看，如果它不空闲，就会杂乱地递增，因为来自设备的通信会肆无忌惮地到处发送。你依赖的是这台机器正在安静地执行你的指令——而不做其他任何事。

![Image](img/w.jpg)`B` 是错误的，因为没有足够的信息将僵尸机器识别为任何东西——更不用说设置为“蜜罐”的机器了。

![Image](img/w.jpg)`C` 是错误的，因为你和僵尸之间的防火墙对僵尸的 `IPIDs` 不产生任何影响。

![Image](img/w.jpg)`D` 是错误的，因为这绝对不是 `IDLE scan` 期间的预期行为。预期行为是 `IPID` 随着每个发现的开放端口定期递增，而不是像活动系统上的流量那样随机增加。
