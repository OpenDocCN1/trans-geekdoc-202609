# 前言

在2022年，全球物联网（IoT）支出将超过1万亿美元。到2025年，将有750亿台连接的设备。IoT 产品和信息物理系统（CPS）正被应用于几乎每一个学科。此外，智能产品正变得越来越先进，以提高我们的健康和舒适度。医疗领域的 IoT 应用不仅能提供基于实时数据的决策支持信息，还能改善需要全天候监测的疾病的治疗方案。一些能够感知、学习并适应用户偏好的产品正日益受欢迎。IoT 也在让我们的城市、政府和家庭运行得高效。

IoT 设备具有无处不在的特性；它们正被集成到每一个领域。随着这种增长，至关重要的是传达这项技术（具有感知和决策等独特的系统功能）如何支持并挑战许多领域的所有相关利益方以及所有相关资产。

本书有三个目标。第一个目标是提供一个每个工程学科都能理解并欣赏的 IoT 介绍。我们包含了重点介绍 IoT 顶级应用（智能家居、智能医疗、智能城市和智能教育）的章节，针对对设计感兴趣的工程师，提供了 IoT 要求与架构、IoT 与区块链，以及美国国家标准与技术研究院（NIST）对“物”网络的定义及其关于 IoT 信任问题的白皮书。第二个目标是为工程教育者提供见解，帮助他们培养构建 IoT 系统所需的下一代工程师。我们希望这本书能让你对 IoT 及其许多应用有新的认识，因为它们很快就会被整合到我们生活的每一个部分。

## 1.1 引言

如果你让一个普通人解释“物联网”（IoT²），他们可能会回答说他们从未听过物联网，或者不知道如何解释。如果他们进行推测，他们会说物联网是“智能”的“东西”。他们很可能并不理解设备感知到了什么。事实上，“智能”一词似乎也变成了某些并不需要描述的产品的营销术语。考虑一下可以从手机操作的户外灯。除非这些灯还能感知运动等某些信号，然后向你的手机发送通知，否则它们就不是智能的的。换句话说，“智能”应该指符合某些标准（如嵌入式传感器和分析软件）的设备。具体而言，除了传感外，该设备还可以收集和分析数据，连接到有线或无线网络，然后根据数据分析执行某些操作，它可以被称为物联网设备或“智能”设备。关于物联网有许多不一致且不准确的定义；因此，本书的目标之一是为理解物联网及其应用提供清晰且准确的内容。此外，作为工程师，我们需要了解物联网的一切——特别是优势、风险，并不断提高物联网系统的安全性、隐私性、可扩展性、性能、互操作性和可用性。

## 1.2 物联网定义

维基百科将物联网定义为“物理对象的网络——即嵌入了传感器、软件和其他技术的‘东西’，其目的是与其他设备以及通过互联网进行连接和数据交换”。物联网概念源于 RFID（射频识别）社区，最初关注追踪物理对象的位置并提供其状态的能力（Greer 等人，2019）。这极地提高了供应链的可见性。

“物联网”自 1999 年以来一直存在。麻省理工学院 Auto-ID 实验室的创始人 Kevin Ashton 创造了 IoT 一术语，指代通过识别技术（例如 RFID）、定位系统（全球定位系统 (GPS)）、传感器（例如温度传感器）和执行器（例如电动机）连接的真实和虚拟信息的组合。有许多类型的传感器，如 RFID 标签、GPS 和加速度计。‘东西’可以

美国国家标准与技术研究院（NIST）特别出版物 800-183 描述了治理物联网运行、信度和生命周期的构建块（Voas，2016）。NIST 是一个联邦机构，其核心使命是支持创新。为了设计和实现物联网创新，理解物联网背后的基础科学至关重要；因此，描述了用于构建物联网系统的五个原语（传感器、聚合器、通信通道、工具和决策触发器）。这包含了本书的第 2 章。

“东西”做什么？它们捕捉数据并通信/传输数据或执行某些操作（例如执行器）。物联网实现了许多新应用，帮助扩展了大数据、业务和数据分析以及人工智能等领域。重要的是，物联网对许多人的生活质量产生了影响。

## 1.3 物联网生态系统

物联网对我们的关键基础设施系统也产生了巨大影响。当“东西”是网络系统时，它被称为信息物理系统（CPS）。关键基础设施系统属于 CPS 类别。当一个系统的资产、系统和网络至关重要，一旦受到损害就会对美国安全、经济安全以及国家健康或安全产生破坏性影响时，物联网允许这些物理设备连接、联网、交换数据并提供实时决策支持。网络基础设施和安全局（CISA）– https://www.cisa.gov/ 命名并定义了以下 16 个关键基础设施部门：

- 化学品部门：制造、储存、使用和运输潜在危险化学品的经济部门。
- 商业设施部门：吸引大量人群进行购物、商务、娱乐或住宿的各种场所。
- 通信部门：业务、公共安全和政府的底层运营。
- 关键制造业部门：基础金属、机械设备、电气设备、家电器、运输工具和组件制造。
- 大坝部门：航道闸门、堤坝、防风屏障、蓄水设施等。
- 国防工业基础部门：对军事武器、子系统和组件进行维护，以满足美国军的需求。
- 应急服务部门：负责各范围应急服务预防/准备/响应：恢复的机构。
- 能源部门：能源供应。
- 金融服务部门：存款机构、投资产品提供者、保险公司、其他信贷和融资机构，以及关键金融公用事业和服务的提供者。
- 食品与农业部门：食品制造/加工/储存设施——对其他关键基础设施（水利、交通、能源、化学）也具有关键性。
- 医疗保健与公共卫生部门：公共和私立医疗机构，在发生自然或人为灾害时，对所有其他部门进行响应并提供恢复。
- 信息技术部门：生产和提供硬件、软件、信息技术系统及服务以及互联网的虚拟分布式功能。
- 核反应堆、材料和废物部门：为数百万美国人提供电的反应堆，治疗癌症患者的医学同位素，核反应堆、材料和废物部门。
- 交通系统部门：该部门包括航空、公路、海上运输、客运、管道、货运和邮政。
- 水水和废水系统部门：公共饮用水和废水系统。

医疗保健：物联网正在以非常有益的方式转型医疗保健领域。医疗监测和合规性所需的物联网工具已经并正在发展中。智能医疗是指任何利用技术收集和存储信息，并允许患者、提供者或其他设备进行动态访问的健康服务。一个很好的例子是预防医疗相关感染（HAI）的设备。在任何一天中，1/3 的医院患者会感染 HAI（疾病控制中心）。多项研究报告称，使用酒精湿巾擦手仅需几秒钟即可防止 HAI 并拯救生命、降低死亡率并减少成本（Haque 等人，2018）。然而，手部清洁并不一致。目前已开发出一种工具自动检测工作人员进出患者房间时是否洗手。此外，该工具还为感染预防者提供了所需的合规数据。其工作原理如下：皂液/胶分配器带有内置软件，可检测医疗专业人员佩戴的 Wi-Fi频段——然后报告手卫生数据。个人报告将包含医疗专业人员的手卫生交易（地点、时间、人员）。经理随后可以确定需要解决的卫生差距以改进卫生流程。其他物联网医疗产品跟踪医药和生物技术行业移动设备和系统的位置，以便远程监控并对网络中断以及温度、湿度和二氧化碳水平超过所需参数提供通知。

另一个重要的医疗类别是可穿戴设备。某些用于位置监测，以确保老年人和婴儿在住院期间的安全。患者可穿戴医疗设备的最佳示例是一型糖尿病（TID）患者的闭环胰岛素输送系统（即人工胰腺）。TID 是一种慢性胰岛素自身免疫性疾病，患者对此*依赖*。挑战在于患者所需的胰岛素量取决于许多因素。

如果没有设备，一型患者使用胰岛素疗法，他们需要两种胰岛素：长效（也称为“基础”）和快效（也称为“餐”）。闭环胰岛素输送系统使用物联网架构控制胰岛素输送。为了理解这种物联网设备以及自动化护理的风险，需要一些 TID 护理知识。最大的风险是如果使用的胰岛素过多，患者可能会出现低血糖，这可能是致命的。如果患者没有获得足够的胰岛素，器官受损的风险以及其他自身免疫疾病的风险将会增加。挑战在于每个患者所需的胰岛素量各异并取决于许多因素。为了保持血糖水平在正常范围内，量取决于食物（和种类）、体型、激素水平、活动、当前健康状况、一天中的时间、人体当前的胰岛素量，有时甚至天气（https://www.diabetes.co.uk/）。

胰岛素泵在进食或纠正高血糖时仍需手动输入剂量。换句话说，用户需要手动将连续血糖监测（CGM）（或指尖血）的血糖读数输入泵中。

物联网在何处发挥？CGM 和胰岛素泵两种设备都由患者佩戴，CGM 将血糖水平直接无线传输到泵。该连接形成回路，自动输送所需的*部分*胰岛素。具体而言，泵接收 CGM 的信号，泵使用算法检测血糖水平的上升或下降。重要的是理解间隙液读数滞后于实际血糖读数，因为血糖水平到达间隙液需要时间。通过解释趋势的斜率，泵将自动分配胰岛素，或在血糖水平下降时减少基础胰岛素。因此，闭环系统仍需在摄入食物时分配胰岛素。令人兴奋的是，针对 TID 患者的更先进的物联网设备正在开发和测试，这不仅意味着报告，还能在餐后/活动后维持正常的血糖范围（Palais 等人，2021）。

教育：教育行业也把物联网整合到从库存管理到实验室的各个方面。与医疗领域类似，存在用于管理和跟踪便携式投影仪、实验室设备和体育设备的物联网系统。跟踪设备收集的数据可确定模式和趋势。其他教育设备使用传感器检测水平并管理环境条件（例如光线/热量）。智能环境中用于创新的物联网系统用于支持学习并提高教育质量，例如通过根据学生的知识和水平整合/发布内容到任务，为学生提供适应学习资源。另一个例子是虚拟实验室，为面临资源问题的学区提供可及性，但通过使用数据分析监控学生的进度和课程提供个性化体验。这将在第 7 章和第 8 章中介绍。

智慧城市：智慧城市是一个宏大的的话题，本书的几个章节中对其进行了讨论。智慧城市利用技术来改进交通模式、能量分配、空气质量等。智慧城市的元素还可以提高其市民的便利性和生活质量。信息技术集成到市民互动的许多方面中，例如简化对城市许多服务的访问。医疗保健、教育、文化和购物领域都可以整合到智慧城市的核心中，创建出一种让市民生活得更便利的设施。

## 1.5 IoT 挑战

显然，经过 IoT 增强的系统具有许多优势，如无处不在的网络连接、实时响应、增强的情境感知和流程优化（CISA, 2019）。IoT 系统的挑战与任何系统都应具备的质量要求相同。以下是一些示例，它们将在本书第 12 章（即需求章节）中进行详细阐：

- 安全性：系统应具有抵抗攻击的韧性（例如，避免单点故障）；验证检索回的数据；实施访问控制；维护隐私。
- 信任：这是一个复杂的话题，因为 IoT 连接和系统继承了一系列核心信任问题。信任很难测试和证明。这将在第 10 章中回避，该章节包含了 NIST 内部报告 8222 (NISTIR 8222 (DRAFT))。该报告详细列了个人和组织在采用 IoT 前后的 17 个与信任相关的关注点（Voas et al., 2018）。
- 可靠性：IoT 系统应按预期运行，不应异常终止。应避免维护和修理的可靠性问题。
- 安全：IoT 应用应具有显示在特定范围内的参数。安全（及安全）违规可能会对其运行环境造成伤害（Zalewski, 2019）。考虑图 1.1 所示的安全关注事项级别。个人佩戴着药物 IoT 设备，家庭拥有保护主主的 IoT 设备，智慧城市拥有自动化系统（例如交通、电力/能量分配），工业行业拥有关键基础设施。
- 可扩展性：系统应该能够在以最少中断的方式增长。解决流量和负载问题——特别是在私有云中。
- 漏洞性：应应对可能的攻击进行系统测试。随着 IoT 系统连接性的增加，攻击面也随之增大。漏洞可能会被无意或刻意地植入。

## 1.6 IoT 开发方法

IoT 系统开发需要一种全面且可靠的方法，涵盖开发流程（例如，需求工程、设计、构建和测试）、参与开发的人员（即通过认证和执照进行的资质认定）以及适当认证工具的使用。应用治理实体为开发这些系统涉及的适当资质、认证和标准设定了规范。例如，在美国，有负责航空电子（联邦航空管理局）、医疗设备（食品药品监督管理局）以及车辆和基础设施运输（交通部）的管理机构，仅列举几个。对于其他类型的系统，其他管理机构、专业组织和标准委员会有助于确保流程的纪律。

无论 IoT 系统是在适当的监管或指导机构的纪律下开发的关键系统，还是没有特定规则的非正式系统，用结构化、有纪律的方法来构建系统都是至关重要的。使用这种流程纪律还可以促进标准化、复用、互操作性和最佳实践。我们建议采用一种涵盖以下活动的 IoT 系统开发方法：

1. 任务识别
2. 目标识别
3. 相关利益者分析
4. 标准识别
5. 需求编写/协议/验证/确认
6. 设计
7. 构建
8. 测试

任务识别涉及清晰地定义系统的整体意图、其运行的应用领域或多个领域以及适当的管理实体。从任务声明中可以识别出高级目标。从这些目标、任务声明以及应用领域识别中，可以确定利益相关者（直接用户、间接用户、受影响的人和系统等）。任何系统的相关利益相关者包括系统中被考虑的并可能与之交互的启用 IoT 功能的物的制造商、所有者和用户。识别利益相关者允许对其关注点和可能交互的来源进行分析。然后可以采取缓解这些交互的方法。
