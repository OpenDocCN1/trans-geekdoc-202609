
对于考试和现实世界，请记住位数越大，加密越强！例如，使用相同的加密标准时，128 位加密比 64 位加密更好。

# 认证目标 12.03

## 非对称加密

现在您已经了解了对称加密，让我们继续了解另一种加密方法：非对称加密。

## 非对称加密概念

**非对称加密** 涉及使用两个数学上相关的密钥来执行加密和解密过程。关于非对称加密有两个主要要点：

- 密钥对中的一个密钥执行的任何操作，另一个密钥都会撤销该操作。
- 这两个密钥是相关的，但您无法从一个密钥推导出另一个密钥。

### 公钥和私钥

## 非对称加密

在非对称加密中，生成的两个密钥被称为 `public key`（公钥）和 `private key`（私钥）。它们的名称来源于你应该如何使用它们。例如，如果你决定使用非对称加密允许 Bob 向 Sue 发送加密的电子邮件，首先你需要为 Bob 生成密钥对，然后为 Sue 创建一套密钥。图 12-5 直观地展示了密钥之间的关系（请注意，Sue 的私钥绝不会与 Bob 的私钥混淆，因为它与 Bob 的公钥不匹配）。

![Image](img/f0528-01.jpg)

**图 12-5**  
非对称加密使用两个数学上相关的密钥。

当你为 Bob 创建密钥对时，公钥会分发给任何将与 Bob 进行安全通信的人（在本例中是 Sue）。在大多数环境中，公钥会被放置在中央服务器上供所有人访问。请记住，每个人都可以访问 Bob 的公钥。

Bob 的私钥则交给 Bob，你要告诉他这是他的私钥，必须妥善保管，不让任何其他人获取。向 Bob 解释私钥在网络上标识他的身份，如果其他人获得了该密钥，他们就可以冒充他，这可不是好事。

接下来，对 Sue 执行相同的操作。生成 Sue 的密钥对，然后将公钥放在所有员工都能访问的位置。将私钥交给 Sue，并要求她确保绝不将私钥交给任何其他人。

我们的设置如图 12-6 所示。一旦你将公钥放置在所有员工都能访问的位置，并配置好 Bob 和 Sue 将使用其私钥访问的应用程序，就可以开始使用这些密钥了。

![Image](img/f0528-02.jpg)

**图 12-6**  
公钥存储在中央位置；私钥由用户持有。

Security+ 认证考试要求你知道哪个密钥用于执行不同的加密操作。例如，当 Bob 想要加密消息并发送给 Sue 时，使用哪个密钥？（请记住，Sue 将使用密钥对中对应的密钥来撤销该操作，即解密。）以下哪个是正确的密钥？

- **`Bob's private key`（Bob 的私钥）** 不正确。如果 Bob 用他的私钥加密消息，那么他的公钥将用于解密。虽然 Sue 可以访问 Bob 的公钥，但其他所有人也可以。因此，如果使用 Bob 的私钥，将不存在机密性，因为每个人都可以解密该消息。
- **`Bob's public key`（Bob 的公钥）** 不正确。如果使用 Bob 的公钥加密消息，则需要用他的私钥解密，而 Sue 没有 Bob 的私钥。因此，她将无法解密发给她的消息。
- **`Sue's private key`（Sue 的私钥）** 不正确。Bob 无法访问 Sue 的私钥，所以他永远无法用 Sue 的私钥加密消息。
- **`Sue's public key`（Sue 的公钥）** 正确。在非对称加密环境中，消息始终使用**接收者的公钥**进行加密。Bob 可以访问 Sue 的公钥，而 Sue 是唯一拥有数学上相关密钥（即私钥）的人，因此她是唯一能解密该消息的人。

![Image](img/exam.jpg)

> **针对 Security+ 考试，请记住：使用非对称加密时，消息（或数据）是用接收者的公钥加密的。同时也要记住：为确保不可抵赖性，消息是使用发送者的私钥进行签名的。**

如果 Bob 想要对消息进行签名，以便 Sue 确信消息绝对来自他，Bob 将使用他的私钥对消息进行数字签名，然后发送给 Sue。当 Sue 收到消息时，她会将该密钥与所有公钥进行比对，发现数学上相关的密钥是 Bob 的公钥。这就是实现 `nonrepudiation`（不可抵赖性）的方式。Bob 永远无法否认他发送过该消息，因为他的系统使用他的私钥对消息进行了签名。我们将在 第 13 章 中进一步讨论非对称环境中的身份验证。

## 非对称加密的优缺点

非对称加密的优势在于你可以安全地将公钥传达给其他方，这与对称加密不同。在非对称系统中，你可以自由分发公钥，而私钥始终由用户持有。

密钥管理也是使用非对称加密的一个优势。你已经看到，在对称加密中，随着用户数量的增加，密钥数量会急剧上升。而使用非对称加密，每个用户只需一个密钥对，即可让每个用户为所有其他用户加密消息。

非对称加密的缺点是它比对称加密慢。如果性能是关键因素，对称加密可能是更好的选择。

### 非对称加密算法

非对称加密算法的数量不如对称加密算法多。以下是一些常见的非对称算法：

- **`Rivest Shamir Adleman (RSA)`** 这是第一个实现签名和加密的非对称算法。RSA 的名称来源于其三位创造者。
- **`Diffie-Hellman`** 该算法同样以其创造者命名。Diffie-Hellman 是一种密钥交换协议，用于以安全的方式交换密钥。
- **`Elliptic curve`（椭圆曲线）** 这是一种较新的非对称算法，基于 Diffie-Hellman 进行密钥交换，基于数字签名算法 (`DSA`) 进行消息签名。这也被称为 `elliptical curve cryptography`（椭圆曲线密码学）。

## 量子密码学

量子计算是基于量子理论的计算机技术。量子理论定义了原子层面能量和物质的行为。虽然比特层面的计算机数据非 0 即 1，但量子计算可以处理包含多个值的数据位，例如同时为 0 和 1。

近年来出现的一种较新的加密方法称为 `quantum cryptography`（量子密码学），更准确的说法是 `quantum communication`（量子通信）。量子密码学/通信目前用于量子计算终端之间的光纤网络。它基于将加密信息作为光子（光粒子）发送，然后将其转换为二进制数据。

量子密码学的优势在于，如果有人进入通信通道并窃听通信，光子在通过窃听者时状态会发生改变。通信参与者可以轻松检测到光子状态的变化，从而知道他们应该更换加密密钥。

量子计算机的挑战在于它们可能能够破解传统加密方法。因此，美国国家标准与技术研究院 (`NIST`) 创建了后量子密码学，这是一种既能抵御传统计算机也能抵御量子计算机攻击的密码系统。

#### 轻量级密码学和同态加密

对于认证考试，你还应该熟悉另外两种密码学和加密形式：轻量级密码学和同态加密：

- **`Lightweight cryptography`（轻量级密码学）** 一种需要较低计算能力、旨在对系统造成极小负载的密码学方法。它设计用于没有足够处理能力执行常规密码学操作的小型设备上。
- **`Homomorphic encryption`（同态加密）** 一种在现有加密数据上进行计算的加密类型。生成的结果值随后可以被解密，其产生的结果与从数据的未加密形式获得的结果相同。

#### 带内与带外密钥交换

Security+ 认证考试要求你了解 `in-band key exchange`（带内密钥交换）和 `out-of-band key exchange`（带外密钥交换）这两个术语。在 `in-band key exchange` 中，加密密钥作为通信的一部分在各方之间交换。使用 `out-of-band key exchange` 时，双方必须在一个独立的通信信道中交换密钥，该信道不同于双方交换数据的通信信道。

### 认证目标 12.04

##### 理解哈希

哈希是一项重要的密码学服务，因为它旨在确保数据或消息的完整性。完整性涉及确保信息自创建或发送给接收者以来未被篡改。

#### 哈希概念

要使用哈希，发送方首先将数据通过哈希算法运行，该算法根据数据计算出一个哈希值。其理念是没有两段不同的数据会产生相同的哈希值。哈希值计算完成后，会随消息一起存储或发送。接收到消息时，接收方将其通过相同的哈希算法运行，以计算消息的哈希值。然后将计算出的哈希值与随消息发送的哈希值进行比较，如果两者相同，则意味着信息未被篡改。

哈希值被称为 `one-way hash values`（单向哈希值），因为不可能执行反向操作，即从哈希值反推计算出消息（或数据）。这也是大多数供应商在系统上存储密码时对其进行哈希处理的原因——哈希值无法被检索并用于计算用户账户的密码。

请记住关于哈希的以下要点：

- 哈希值具有固定长度，取决于所使用的哈希算法。无论哈希多少数据，哈希算法生成的哈希值大小始终相同。
- 哈希值也称为 `message digest`（消息摘要）。
- 哈希基于数据，而非文件的头部。例如，如果你计算一个文件的哈希值，然后更改文件名并再次计算哈希，结果将是相同的哈希值。这是为了防止有人通过重命名文件来隐藏或伪装文件。从技术上讲，如果你想证明是同一个文件，只需计算其哈希值即可。
- 虽然可能性极小，但技术上两段不同的数据有可能生成相同的哈希值，这取决于算法生成的哈希值大小。例如，64 位哈希值只有有限的可能值，因此计算时可能会出现重复哈希。另一方面，128 位哈希值有更多可能的值可作为哈希计算。这意味着有更多机会生成唯一的哈希值。
- `Collision`（碰撞）是指两段不同数据计算出相同哈希值的情况。

#### 哈希算法

正如对称加密算法执行加密信息所涉及的数学运算一样，哈希算法执行从数据计算哈希值的数学运算。

以下是近年来常用的一些哈希算法：

- **Message Digest (MD，消息摘要)** MD 算法由 Ron Rivest 创建，有不同版本，如 MD2、MD4 和 MD5。MD5 算法是当今最常用的哈希算法之一。它生成 128 位哈希值。
- **Secure Hash Algorithm (SHA，安全哈希算法)** 由国家安全局创建，SHA 算法有不同版本，如 SHA-0、SHA-1 和 SHA-2。这三者中目前最常用的哈希协议 SHA-1 生成 160 位哈希值。
- **SHA-256 和 SHA-512** 这是 SHA 算法的两个较新版本，分别生成 256 位和 512 位哈希值。它们被认为不易受碰撞攻击。
- **LANMAN** 也称为 LM hash，此哈希算法被旧版 Microsoft 操作系统用于哈希和存储密码。LM hash 通过使用 DES 加密密码来创建。它被认为是一种不安全的密码哈希存储方法。
- **NT LAN Manager (NTLM)** 从 Windows NT 操作系统开始，采用了一种新的改进方法在注册表中存储密码。密码通过 NTLM 进行哈希处理，它使用 MD4 而非 DES（LANMAN 使用）。NTLMv2 是比 NTLM 更强的认证协议，它使用 HMAC-MD5 对客户端和服务器之间的质询和响应进行哈希处理。
- **RACE Integrity Primitive Evaluation Message Digest (RIPEMD)** RIPEMD 有多种不同哈希级别的版本，如 128 位、160 位、256 位和 320 位。版本号体现在哈希算法的名称中，例如 RIPEMD-160。
- **Hash-based Message Authentication Code (HMAC，基于哈希的消息认证码)** HMAC 涉及将密钥与哈希算法结合使用来计算 `message authentication code (MAC，消息认证码)`。MAC 是生成的哈希值。

![Image](img/exam.jpg)

MD5 和 SHA-1 目前是用于确保消息和数据完整性的最流行哈希算法。当你从互联网下载软件时可以看到这些协议的应用：提供软件的供应商通常会在网站下载链接旁显示 MD5 和 SHA-1 哈希值，以便你在下载完成后想要检查完整性时，知道原始哈希值。

#### 理解局限性

Security+ 考试要求您了解不同的加密协议以及每种协议局限性所涉及的风险。例如，如果应用程序使用 `DES` 或 `3DES`，安全风险在于它们是薄弱的加密方法，因为这些是已被破解的旧标准。以下是一些需要注意的加密标准局限性：

- **速度** 请了解对称加密比非对称加密快，这就是为什么许多技术同时使用这两种方法——对称加密用于速度，非对称加密用于密钥管理。
