You might have noticed that the select() and the mutate() commands were used right after the data was loaded with import() — before the ecipeWine was defined. This raises the question:

# When should we use select() and mutate(), and when should we use
 recipe to pre-process data?

Here are some suggestions:

+   1. Generally, using a recipe is advisable because we can reuse a recipe
of other data frames.
2. It is good practice to use select() before to reduce the
columns of an original frame to only those columns (vari-
ables) for the analysis. This allows us to use the
notation in the formula argument of the recipe() command.
3. When transforming outcome variables, it is advised to do
this outside of a recipe. For example, in the R code above, we used
mute() to convert the outcome variable WineColor from a char-
 data to a factor data type outside the recipe. If a recipe
is later used on another dataset for prediction, this dataset might
contain a column for the outcome variable. More about why
recipes should not be used on outcome variables in Kuhn and Silge
(2022), Section 8.4.

# 4.7.4 Creating a Model-Design

A model design determines which machine learning model from which R pack-
age be used for the analysis.

To define a model design within the tidymodels environment, only three com-
ands (connected with |>) are required. The following code shows how
to generate a learning design for a k-Nearest Neighbors model:

```
ModelDesignKNN=nearest_neighbor(neighbors=4,
set_engine("knn") |>
set_mode("classification")
```

As you see, the k-Nearest Neighbors model is designed with only three\commands:

> If the dataset contains the outcome variable, such as the testing data, some

leakage. Data Leakage occurs when information from the training process is used (often
inadvertently) in the testing phase of the model. This can lead to poor prediction quality
when the model is used in the production phase.
