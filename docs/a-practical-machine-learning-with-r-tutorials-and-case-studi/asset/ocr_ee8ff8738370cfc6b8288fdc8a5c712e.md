Above, you can see that Population (i.e., the population of the related U.S. county)$^{14}$ was selected as one of the variables, although *Population* is neither an outcome nor a predictor variable for this research. *Population* will be used later in the workflow method to weight the observations. To mark the variable *Population* as being neither outcome predictor variable, we used the command `frequency_weights()`.

The recipe() in the code block below is the same as in Section 10.3.2 except that now *PercVacFull* is chosen as the outcome variable.

```
RecipeVacFull=recipe(PercVacFull-, data=DataTrain)
```

The dot in the argument *PercVacFull-*, indicates that all variables in Data-Train except the outcome, *PercVacFull*, should be used as predictor variables. However, the variable *Population* is also excluded because we marked it as *frequency_weight* when we loaded the data and selected the variables.

In the code block below, we define the *model* and use the `rand_forest()` to command a *Random Forest* model from the *R* ranger package set_engine()`. To keep things simple, we set the *hyper-parameters* rather than tuning them:

```
library(parallel)
ModelDesignRandForest=rand_forest(min_n5, mtry=2, trees=2000) |>
  set_engine("ranger", num.threads=detectCores()) |>
  set_mode("regression")
```

We min *n5*, which means that at least five observations are required in a node of a *Decision Tree* to split and create two new *child nodes*. The *hyper-parameter* *mtry* determines the number of randomly chosen variables candidates for a split in the *Decision Trees*. It is set to *mtry=2*. Both coincide with the defaults for *Random Forest*$^{15}$

We increased the number of *Decision Trees* used for the *Random Forest* from the default (trees=500) to trees=2000. In contrast to the *hyper-parameters* *min_n* and *n*, a high number of trees in a *Random Forest* cannot cause overfitting.
