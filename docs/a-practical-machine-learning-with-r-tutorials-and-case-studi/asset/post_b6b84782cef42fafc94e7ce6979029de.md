### 10.3.1 The Idea Behind a Decision Tree

The best way to introduce the idea behind Decision Trees is to see the algorithm in action. We will use the Titanic dataset¹ to generate a Decision Tree and discuss the resulting graph.

In the code block, we download the data, rename the variables into UpperCamel form, and select(Survived, Sex, Class (renamed from Pclass), Age, and Fare (renamed from FareInPounds) for the analysis. We use mutate() to convert data type (Survived = TRUE for a passenger that survived and Survived = FALSE otherwise). Since we perform a classification task, the outcome survived also has been converted into a factor variable:

```
library(rio);library(titanicmodels);library(janitor)
DataTitanic=import("https://ai.lang-analytics.com/data/Titanic.csv") |
```

The command extract_fit_engine(WfTitanic) extracts the model from the workflow WfTitanic and rpart.plot plots the graphical representation of the Decision Tree (see Figure 10.1).

We will explain how the Decision Tree works in Figure 10.1. For now, we focus on how it can be used for predicting survival.

A Decision Tree like the one in 10.1 consists of hierarchically organized nodes (blue and green rectangles). It can be compared to an ancestry tree. The root node on top of the tree has no ancestors but is a parent to two children. Each of these children is a parent to two children. This process continues until it reaches the bottom of the tree. The terminal nodes at the bottom have parents but no children.

In contrast to an ancestry tree, a Decision Tree is not used to display any ancestry. Instead, it guides observation from a dataset starting at the root node to one of the terminal nodes. Decision rules are used after each parent node to determine to which of the two child nodes an observation is moved on its way towards the terminal nodes.

### Decision Rules

A decision rule determines if an observation is moved to the left child or the right child of a parent node. A decision rule states a condition such as Sex=male (see the first decision rule between the root node and its two children in Figure 10-1). The condition is fulfilled (YES) or not fulfilled (NO):

> If the condition is fulfilled, the observation moves to the left child node. Otherwise, it moves to the right child node.

Now you know how an observation descends from the root node to one of the terminal nodes, and how the labels are assigned inside each node interpreted, and how are they determined?
