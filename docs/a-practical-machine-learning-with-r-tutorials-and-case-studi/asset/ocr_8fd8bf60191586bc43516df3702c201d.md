# 4.11 When and When Not to Use knn Models

+   * $k$-Nearest Neighbors can be used to solve classification problems similar to the ones in this section. $k$-Nearest Neighbors usually produces good prediction results.

+   * In principle, $k$-Nearest Neighbors can be used for regression problems. First, it finds the $k$ nearest neighbor observations. Afterward, the mean of the output variable of the $k$ nearest neighbors is used to generate the prediction. However, $k$-Nearest Neighbors is rarely used for regression models such as *Ordinary Least Square (OLS)* regression , *Neural Networks*, or Random Forest models, usually perform better.

+   * Using $k$-Nearest Neighbors for prediction purposes, it is also useful to identify similar observations. For example, when somebody is using a dating website, the website often searches its database for similar partners in terms of age, income, education, and interests. If 20 partner recommendations are required, $k$-Nearest Neighbors ($k = 20$) finds the 20 most compatible potential partners (similar in terms of *Euclidean Distance*).

Some recommendation systems work similarly. The machine learning algorithm would first find customers with a similar viewing history and then recommend videos that those customers had rated and rated high.

+   * A disadvantage of $k$-Nearest Neighbors models is their slow performance. When the number of variables and/or the number of observations becomes large, $k$-Nearest Neighbors can be prohibitively slow.

Consider that the original MNIST dataset contains 60,000 training observations and 10,000 testing observations. This means that $k$-Nearest Neighbors needs to compare each of the 10,000 testing images with all of the 60,000 training images for each of the 784 pixels. This would lead to 470,400,000,000 (10,000 · 60,000 · 784) pixel comparisons. While this is still possible with a fast computer, a faster comparison algorithm, and a lot of patience, it becomes very problematic when we consider images with better resolution—e.g., $1280 \cdot 1024$. This would lead to $(10,000 \cdot 60,000 \cdot 1280 \cdot 1024)$ pixel comparisons. You do do the math.
