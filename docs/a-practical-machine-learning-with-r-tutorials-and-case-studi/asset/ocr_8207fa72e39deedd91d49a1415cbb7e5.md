# 6.4 Demonstrating Overfitting with a Polynomial Model

```
library(tidymodels); library(rio); library(janitor)
DataHousing=\import("https://ai.large-analytics.com/data/HousingData.csv") |>
clean_names("upper_camel") |>
select(Price, Sqft=SqftLifting)
```

```
set.seed(777)
Split01=DataHousing |>
initial_split(prop=0.01, strata=Price, breaks=5)
DataTrain=training(Split01)
DataTest=testing(Split01)
```

Note that the argument split=0.01 command assigns only 20 observations to the training data. The remaining 21,503 observations will be used as testing data. The reason to consider only 20 observations for training, although enough observations are available to create a bigger dataset, is that we purposely create circumstances that can lead to an overfitting scenario. In real-world analysis, we work with bigger datasets, overfitting is even more subtle and difficult to identify.

We use the prediction to estimate the price of a house based on living square footage (Sqft). The model is polynomial because Sqft is with various values:

> $Price = \beta_1Sqft + \beta_2Sqft^2 + \beta_3Sqft^3 + \beta_4Sqft^4 + \beta_5Sqft^5 + \beta_6$ (6.1)

Since the price of a house (Price) is estimated based only on its square footage, the model is classified as univariate. A univariate model was chosen because it will allow us to present the results in a 2D diagram with the price on the vertical and square footage on the horizontal axis.

As we see in Equation (6.1) the predictor Sqft is used with powers ranging from 1–5, which makes the model non-linear.
