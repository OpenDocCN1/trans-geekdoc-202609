A *Neural Network* with a sufficiently large number of hidden neurons can take the form of a highly non-linear surface to approximate training data almost perfectly. In fact, a “(...) standard multilayer feedforward network architecture using arbitrary squashing functions can approximate virtually any function of interest to any desired degree of accuracy, provided sufficiently many hidden units are available” (Hornik et al. 1989).

To intuitively understand the outstanding approximation ability of a *Neural Network*, consider that a *Neural network* consists of many hidden neurons and thus of many *Sigmoid* functions. *Sigmoid* functions are squashing functions because they squash all input values between two output values (0 and 1 in the case of the *Logistic* function). As Figure 9.3 shows, each *Sigmoid* function forms a step similar to a step in a staircase. Although smoother than a staircase step, a *Sigmoid* function like a staircase, is flat first, then upward (or possibly downwards), and finally flat again.

Changing the $\beta$ values that impact the *effective input* $z_{ij}$ of a specific *Sigmoid* activation function and changing the $\beta$ value that weighs the resulting activity $(\beta A_{ij}^k)$, can move a (*Sigmoid function*) horizontally, increase or decrease the step size, change the steepness, and also convert from up to a downward step.

Since a *Neural Network* consists of hidden neurons, many *Sigmoid* (steps) functions can be combined into a staircase-like structure with smaller and bigger steps as upwards and downward steps — depending on the $\beta$ parameter values. This staircase-like structure — if it has enough steps — can approximate a function in any given range to any degree.

The mathematical formula behind which staircase-like structure is the *Neural Network* prediction function. It combines the *Sigmoid* (steps) to approximate whatever continuous function needs to be approximated (in a given range) with various up- and downward steps.

Consequently, with this procedure, a *Neural Network* can approximate a function to any degree of smoothness in a given range by increasing the number of hidden neurons.

Figure 9.6 shows an example of the arguments outlined above. The goal is to approximate a sine function (the orange dots in the upper diagram in Figure 9.6) in an input range between 0 and 9 with a *Neural Network*. The sine function to be approximated is:

```
$y_i = \sin(x_i + 5) + 1$
```

We use a *Neural Network* with one input $(x_i)$, three hidden neurons with *Logistic* activation functions, and one output $\tilde{y}_i$.

When all $\beta$ values are appropriately chosen$^{11}$ the three $\beta$ weighted activation functions of the three hidden neurons form three steps (the lower two diagrams in Figure 9.6). When these steps are combined (added) together with the bias for the output neurons $(\beta_0 = 2)$ they form the *Neural Network* prediction function (the blue line in the upper diagram of Figure 9.6). As you can see, we get a good approximation of the sine function. The *Neural Network* prediction function forms a staircase-like structure with one step up, one step down, and line in the upper diagrams of Figure 9.6). If we want to increase the smoothness of the approximation, we could work with six hidden neurons (six steps). With appropriate values for the $\beta$ parameters, we could form a staircase-like structure with two (smaller) steps up, two (smaller) steps down, and two (smaller) steps up.

> $^{11}$The underlying $\beta$ values are not the result of an *Optimizer* process. They have been chosen manually by *trial-and-error* to generate a good approximation.

## 9.6 NNet vs. PyTorch (bTorch)

PyTorch is a machine learning framework initially developed by Facebook (now Meta AI). Since 2022, it is curated by the Linux Foundation. PyTorch was for a long time only accessible through Python, but in 2021, the developers of tidymodel created the R package breeze (Kuhn and Fabian (2022)), which makes some of the functionality from PyTorch available. This includes an MLP implementation.

In this section, we will discuss the differences between a Neural Network created with oet and by PyTorch (via the breeze package).

The oet package (Venables and Ripley (2002)) was one of the earliest R packages to support Neural Networks. It is well suited for educational purposes, especially to demonstrate how Neural Networks can be used for predictions and to display Neural Networks as graphs¹¹

In contrast, PyTorch is an advanced science toolkit, and its Neural Network functionality is more up-to-date. Some of PyTorch's functionality, including support for MLP was recently included in R through breeze.

There are quite a few differences between networks supported by oet and by PyTorch. In this section, we will focus on two aspects:

- **Hyper-Parameters:** In PyTorch, you can set and tune numerous hyperparameters that are either unavailable in oet or are available, but not as advanced as. For example, in oet, you can tune the number of hidden neurons for one hidden layer. In PyTorch, you can set and tune the number of hidden neurons for multiple hidden layers.
- **Activation Functions:** PyTorch allows us to use the Rectified Linear Unit (ReLU) activation function, while oet does not support ReLU activation function. In what we follow, we will introduce ReLU functions work and why they are superior to classical Sigmoid activation functions, which are supported in oet.

¹¹Using the oet package in combination with the NeuralTools package (Beck (2018)) allows us to convert any oet Neural Network into a graph and save as a peg-file.
