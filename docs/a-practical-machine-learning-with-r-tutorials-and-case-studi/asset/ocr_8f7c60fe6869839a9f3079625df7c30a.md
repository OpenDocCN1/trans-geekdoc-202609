Let us start with `downsampling`. In the code below, we first load the recipe package (Hvitefeld (2023)) and then add `step_downsample()` to the recipe that we use in Section 8.4 for the churn model.

```
library(themisc)
set.seed(678)
Recipe(Churn~, data=DataTrain) |
  step_dummy(Gender)|
  step_downsample(Churn)
```

Later, we will add a similar recipe to a workflow, and the workflow will execute the recipe that balances the minority and majority classes.

At this point, we want to find out if the recipe successfully changes the position of the training data. To test this, we must explicitly apply the recipe to the training data and store it in a new frame `DataTrainBal` for analysis.

For this, we use the `juice()` command.10 It extracts the training data from the recipe like a squeezes lemon juice out of a lemon. Note, you have to add prep(prepare) after the recipe to ensure its execution before the data are extracted with `juice()`.

```
DataTrainBal<-RecipeChurn |
  prep(|
  juice()
count(DataTrainBal, Churn)
```

> The skip argument determines if a `step_*` command is applied to the testing data or if the testing data will be skipped. For most `step_*` commands, the default is `FALSE` because usually, we want a `step_*` to be applied to the training and testing data. However, the default for `step_downsample()`, `step_upsample()`, and `step_smote()` is `isTRUE` to skip the testing data. You can change the default values for `skip`, but it is not recommended.
