Since the argument degree needs something to be determined, we use tune() as a placeholder. It is important not to over-interpret the meaning of tune(). It is only a placeholder that, later, will be replaced by values for degree which we try and evaluate different values for degree—.

This also makes sense: because the degree for the polynomial function is not determined, fitting the model is not possible. Consequently, the workflow cannot be used for predictions. It is only a blueprint for the workflow is used for tuning that we will later perform. To clarify that the only R object is prefixed with the word Tune(TuneModelHouses).

In order to evaluate the performance of several different degrees for the Polynomial Model, we have to decide which degrees we would like to try out. This is an arbitrary decision.

Nevertheless, the tidymod package can provide some guidance. For most hyper-parameters a related command exists that returns a recommended hyper-value range. The name of the command is often the same as the name of the hyper-parameter. For example, you can use the command degree() to find a recommended range for the hyper-parameter degree:

```
degree()
```

```
# Polynomial Degree (quantitative)
## Range: [1, 3]
```

The command returns a recommended range for the hyper-parameter degree from 1 – 3. We will extend this range and evaluate polynomial degrees from 1 – 10.

For purposes, the tidymodel package expects a data frame with the values for each hyper-parameter in the columns. The column names must be the same as the name of the respective hyper-parameter. Since we tune only one hyper-parameter in this case, the data frame ParGridHouses contains only one column named Degree with values from 1 – 10.

```
ParGridHouses=data.frame(degree=c(1:10))
print(ParGridHouses)
```
