# 7 Ridge, Lasso, and Elastic-Net — Regularization Explained

The advantage of the Elastic-Net approach is that you can run any mixture of Lasso and Ridge regularization. The disadvantage is that you get to tune with $\alpha$ (mixture) another hyper-parameter that either needs to be set in the linear\_reg command or needs to be tuned together with the hyper-parameter $\lambda$ (penalty).

You will tune these hyper-parameters later in an interactive project with Section 7.5. Here, in this section, we implement Elastic-Net into tidymodels by arbitrarily setting the hyper-parameters to keep things simple.

The commands to set up a tidymodels workflow for the Elastic-Net model are almost the same as in the previous section, except we arbitrarily set penalty=10000 and mixture=0.5.

```
seed(7777)
ModelDesignElasticNet=linear_reg(penalty=10000, mixture=0.5) |>
  set_engine("glmnet") |>
  set_mode("regression")

WFModelElasticNet=workflow() |>
  add_model(ModelDesignElasticNet) |>
  add_recipe(RecipeMouses) |>
  fit(DataTrain)
```

For the recipe that creates the various powers of the Sqft and normalizes the resulting predictors, we can use the recipe from Section 7.3.

Since the workflow WFModelRidge is a fitted workflow model (it was calibrated with the training data), we can extract the model with the tidy() command:

```
tidy(WFModelElasticNet)
```
