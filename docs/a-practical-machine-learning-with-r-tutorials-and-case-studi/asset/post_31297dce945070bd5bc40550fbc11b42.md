
## 6.6 10-Step Template to Tune with tidymodels

If you plan to tune a hyper-parameter in a model design, you have to assign the tune() placeholder rather than a value to the related argument. For example, neighbors=tune() in the nearest_neighbor() command.

You can find the names for various machine learning models together with the related package names for the set_engine() command at: https://parsip.tidymodels.org/reference.

### Step 4 - Add the Recipe and the Model Design to a Workflow: In the code block the recipe (named: Recipe) and the model design (named: ModelDesign) are added to the workflow TuneWFModel:

```
TuneWFModel<-workflow() |>
  add_recipe(Recipe) |>
  add_model(ModelDesign)
```

### Step 5 - Create a Hyper-Parameter Grid: The hyper-parameter values need to be tried out must be listed in a data column with the same name as the hyper-parameter:

```
ParGrid$data.frame(<HYPER-PAR1>=c(<LIST OF VALUES>),
<HYPER-PAR2>=c(<LIST OF VALUES>), <ETC>)
```

The data.frame() command is used to create the required data frame. <HYPER-PAR1> is the name of a hyper-parameter, and the c() can be utilized to provide a list of values. If you more than one hyper-parameter, add these in the same way.

If you only one hyper-parameter, for example, only the number of neighbors in k-Nearest Neighbors model, the code could look like this:

```
ParGrid$data.frame(neighbors=c(1,3,6))
```

### Step 6 - Create Resamples for Cross-Validation: To create the samples for Cross-Validation, you can use the following:

```
FoldsForTuning<-vfold(dataTrain, v=10, strata=<OUTCOME VARIABLE>)
```

A typical Cross-Validation setup includes ten folds. If you like to work with a smaller number of folds, especially for smaller datasets, change v=10 to correctly reflect the number of folds.

To ensure the outcome variable is similarly distributed in each section of the folds, substitute <OUTCOME VARIABLE> with the name of your outcome variable.

### Step 7 - Tune the Workflow and Train All Models: The tune_grid() trains models for all hyper-parameter combinations stored in the data frame ParGrid using all resampled stored in the previous step in FoldsForTuning.

```
TuneResults=tune_grid(TuneWFModel, resamples=FoldsForTuning,
grid=ParGrid, metrics=metric_set(<LIST OF METRICS>),
control_grid(verbose=TRUE))
```

The optional metrics argument specifies the metrics that are calculated. For example, metric_set(<LIST OF METRICS>) with metric_set(rmse, rsq, max) for a regression or with metric_set(accuracy, specificity) for a classification problem.

The argument control_grid(verbose=TRUE) is optional. When used like here with verbose=TRUE, the tuning reports its progress to the R Console.

### Step 8 - Extract the Best Hyper-Parameter(s): Because all results for the specified metrics are stored in the tuning object TuneResult, we can use select_best() to extract the best hyper-parameter(s) for the metrics we are interested in:

```
BestHyperPar=select_best(TuneResults, "<METRIC>")
```

You need to specify which metric should be used to identify the best-performing model by substituting <METRIC> with the metric of your choice. Note that only metrics specified previously in Step 7 can be chosen.

### Step 9 - Finalize and Train the Best Workflow Model: You can use the command finalize_workflow() to substitute the TuneWFModel with the values from BestHyperPar. Afterward, the fit(DataTrain) trains the finalized workflow model with your training data:

```
BestWFModel=TuneWFModel |
  finalize_workflow(BestHyperPar) |
  fit(DataTrain)
```

### Step 10 - Assess Prediction Quality Based on the Testing Data: This step should only be performed after the model is completed and no further changes are planned otherwise, you cannot use the testing data.

```
DataTestWithBestModel<-augment(BestWFModel, DataTest)
metrics(DataTestWithBestModel, truth=<OUTCOME VARIABLE>,
estimate=.pred)
```
