The linear regression model is represented by the following equation:

$$Price = \beta_0 + \beta_1 Sqft + \beta_2 Grade + \beta_3 Waterfront\_yes + \beta_4$$

OLS assumes all predictor variables have additive and independent impact on the outcome variable. The related $\beta$ scale of these impacts. Using OLS to find the optimal values for the variables, we have to solve one problem: the $Waterfront$ variable in the data frame `dataTrain` is not normal. It contains the values 'yes' and 'no'. To tackle this problem, we can transform $Waterfront$ into a `dummy` variable using `step_dummy()` in the recipe. The command `step_dummy()` assigns a value of 1 when $Waterfront$ is 'yes' and a value of 0 when it is 'no'. There is common practice to assign 1 to 'yes' and 0 to 'no'.

The recipe in the code below determines the variables used for analysis and converts $Waterfront$ into a dummy variable. First, $Price$ is defined as the outcome variable, and all other variables ($Sqft, Grade,$ and $Waterfront$) are defined as predictor variables notation.

```r
library(tidymodels)
recipe(Price, data=dataTrain) %>%
  step_dummy(Waterfront)
```

Note that `step_dummy()` changes the variable name (the column name in the data frame) to indicate which category is set to '1'. Since 'yes' is assigned to 1, the command `step_dummy()` renames $Waterfront$ to $Waterfront\_yes$. Consequently, if $Waterfront\_yes = 1$, a house is located at the waterfront.

## Dummy Variables and One-Hot Encoding

A dummy variable is a dummy because it fills in the presence of a category. For example, the 1 of the dummy variable $Waterfront\_yes$ indicates a numerical value that a waterfront is present and 0 that it is not. In the waterfront case, creating the dummy variable seems straightforward. However, in the case of red and white wines, one might create two dummy variables $WineColor\_white$ and $WineColor\_red$ with a value of 1 for white (0 otherwise) and red, respectively. Creating a variable for each of a categorical variable is called *one-hot encoding*.

One-hot encoding can be advantageous for some machine learning models (e.g., Random Forest) because it allows for a more straightforward interpretation of the variables. In OLS regressions one-hot encoding leads to a situation that mathematically impossible to calculate $\beta$ (dummy trap).

The dummy trap occurs when using one-hot encoding for OLS because one dummy variable is redundant. For example, in the case of red and white wines, when we have $WineColor\_white = 1$, it follows that $WineColor\_red = 0$ (an observation can be either red or white). This redundancy is also reflected in an algebraic property: if we use the values for $WineColor\_white$, we can calculate the values for $WineColor\_red = 1 - WineColor\_white$. If we can calculate one from one or more predictor variables, these are perfectly correlated. The absence of perfect correlation is one of the conditions to be fulfilled for OLS regression.

Consequently the multivariate model design for the housing analysis does not differ from the univariate model design in Section 5.4.2. From the package `lm`, we use the model `linear_reg()` with mode "Regression".
