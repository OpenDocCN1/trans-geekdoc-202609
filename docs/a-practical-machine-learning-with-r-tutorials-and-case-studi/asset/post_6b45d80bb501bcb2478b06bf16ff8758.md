# 8.5 Balancing Data with Downsampling, Upsampling, and SMOTE

In the previous section, due to an imbalanced dataset, predictions are biased toward the over-represented Churn = No class, called the majority class. The majority class represents the most prevalent classification in a dataset. In contrast, the minority class represents the classification that occurs rarely or in a dataset (Churn = Yes in the Telco dataset).

A slightly imbalanced dataset does not cause any problems, but a dataset like the Telco dataset with 3,621 observations for the majority class and 1,038 observations in the minority class (see Table 8.2 further below) can cause predictions biased toward the majority class.

The most common approaches to work with imbalanced datasets are removing from the majority class (downsampling) and/or adding observations to the minority class (upsampling):

- **Downsampling:** This procedure randomly deletes observations from the majority class until the ratio of the observations from the majority and the minority class reaches the desired ratio (e.g., 1:1).
- **Upsampling:** In its simplest version, upsampling creates new observations for the minority class by copying randomly chosen observations from the minority class until the ratio of the observations from the majority and the minority class reaches the desired ratio (e.g., 1:1).

Often, a combination with up- and downsampling, we must decide to balance both the training and testing data or only the training data. The right decision is to balance the training data but not the testing data. This is because when the model is fully trained, the testing data is used to assess how the model will perform in the real world when facing new data in the production stage. Therefore, since the real world contains imbalanced data, the testing data should also contain imbalanced data neither treated with downsampling nor with upsampling.

In what follows, we will introduce one downsampling and two upsampling methods. These methods can be used in combination or individually. The thesis provides the related commands `step_downsample()`, `step_upsample()`, and `step_smote()`. These commands process, by default, only the training data but not the testing data.⁹

Let us start with `downsampling`. In the code below, we first load the recipe package (Harsley (2023)) and then add `step_downsample()` to the recipe that we use in Section 8.4 for the churn model.

```r
library(recipes)
set.seed(678)
recipe(Churn~, data=DataTrain) |
  step_dummy(Gender)|
  step_downsample(Churn)
```

Later, we will add a similar recipe to a workflow, and the workflow will execute the recipe that balances the minority and majority classes.

At this point, we want to find out if the recipe successfully changes the position of the training data. To test this, we must explicitly apply the recipe to the training data and store it in a new frame `DataTrainBal` for analysis.

For this, we use the `juice()` command.¹⁰ It extracts the training data from the recipe like a squeezes lemon juice out of a lemon. Note, you have to add `prep()` after the recipe to ensure its execution before the data are extracted with `juice()`.

```r

The idea behind upsampling is to randomly copy observations in the minority class until the minority class reaches the desired number of observations (the default is the same as the majority class). As you can see comparing the printout with Table 8.2, the data set is balanced. However, we did not gain any information because we copied existing observations to increase the minority class.

In this context, it is important to point out that having identical observations through upsampling is not the best solution. Consequently, improved methods are needed to increase the number of observations in the minority class. One of these methods is SMOTE (Synthetic Minority Over-sampling Technique; see Chawla et al. (2002)). The idea behind SMOTE is to artificially generate new observations for the minority class, which is similar but not identical to existing observations. The SMOTE algorithm is implemented by the `recipes` package through `step_smote()` and works as:

1. Randomly choose an observation from the minority class.
2. Find the next neighbor to this observation using k-Nearest Neighbors (see Section 4 for details about the k-Nearest Neighbors algorithm).
3. Calculate a randomly weighted average for each predictor variable from the chosen observation from Step 1 and its nearest neighbor.
4. Use the calculated values for the predictor variables to create a new observation for the minority class.

Repeat Steps 1 – 4 until the number of observations in the minority class reaches the desired number of observations (the default is the same number as the majority class).
The code block below is identical to the code blocks above, except that we use `step_smote()`:

```r
library(recipes)
set.seed(678)
recipeChurn = recipe(Churn~, data=DataTrain) |
  step_dummy(Gender) |
  step_smote(Churn)

DataTrainBal = recipeChurn |
  prep() |
  juice()

count(DataTrainBal, Churn)
```

```
## # tibble: 2 x 2
## Churn n
## <fct> <int>
## 1 Yes 3621
## 2 No 3621
```
