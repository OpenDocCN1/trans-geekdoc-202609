# FIGURE 7.2 Parameter Estimates for Different Ridge Penalty Estimates

Figure 7.2 shows the $\beta$ estimates of the related predictor variables for penalty multipliers ranging from $\lambda = 19$ to $\lambda = 190, 385, 312^4$.

In the Lasso model, when $\lambda$ increases, the calibrated $\beta$ values have a tendency to move toward zero. In contrast to the Lasso model (see Figure 7.1), individual predictor variables are not eliminated ($\beta$ values are not set to zero). Yet, you can see in Figure 7.2 that the paths for the $\beta$ values converge to a common value. Afterward, when further increasing $\lambda$, this common value decreases further, until all $\beta$ values reach zero—none of the $\beta$s reach zero individually in the Lasso case. Consequently, many of the predictor variables are eliminated individually.

This phenomenon can be explained by the Ridge penalty term. When $\lambda$ is large, the penalty term has a high weight compared to the MSE. Consequently, the Optimizer focuses mainly on the penalty term. Since larger (in absolute) $\beta$ values impact the penalty-over-proportionally, the Optimizer has an incentive to favor smaller values first. This leads to a situation where $\beta$ values converge to similar values (Figure 7) at large $\lambda$ values.

## 7.4.3 Elastic-Net — Combining Lasso and Ridge

In the previous two sections, we introduced Lasso and Ridge. Lasso tends to reduce $\beta$ parameter values to zero. Consequently, it eliminates predictors from the model and makes overfitting less likely. It is the model of choice if you want to reduce the number of predictors to those with the strongest explanatory power. In contrast, Ridge lowers the $\beta$ parameter variables to avoid overfitting without eliminating variables. If you like to keep all predictor variables in the model, Ridge is the model of choice to avoid overfitting.

Often, we are ambivalent about keeping all predictor variables or not. The goal is to maximize predictive performance and minimize overfitting. Therefore, it is often difficult to determine which algorithm is superior. So why not combine Lasso and Ridge?

This is exactly how the Elastic-Net approach does. It uses both — the penalty for Lasso and the one for Ridge — adds their weighted average to the MSE in the target function:

```
$T_{Elastic}^{2} = \frac{1}{MSE} \sum_{i=1}^{20} (Price_{i} - Price_{i})^{2} + \lambda (\alpha \frac{penalty_{Lasso}}{MSE} + (1-\alpha) \frac{penalty_{Ridge}}{MSE})$  (7.8)
```

```
$T_{Elastic}^{2} = \frac{1}{MSE} \sum_{i=1}^{20} (Price_{i} - Price_{i})^{2} + \lambda (\alpha \sum_{j=1}^{5} |\beta_{j}| \frac{penalty_{Lasso}}{MSE} + (1-\alpha) \sum_{j=1}^{5} \beta_{j}^{2} \frac{penalty_{Ridge}}{MSE})$  (7.9)
```

with: $Price_{i} = \beta_{1}Sqft_{i} + \beta_{2}Sqft_{i} + \beta_{3}Sqft_{i} + \beta_{4}Sqft_{i} + \beta_{5}Sqft_{i} + \beta_{6}$

In Equation (7.5) you can see that the penalty for $penalty_{Lasso}$ and $penalty_{Ridge}$ is calculated as a weighted average. The hyper-parameter $\alpha$ ($0 \le \alpha \le 1$) determines the share of the Lasso penalty. For example, if $\alpha=0.5$ the share of the Lasso penalty is 50% and the share of the Ridge penalty $(1-\alpha)=0.5$ is also 50%. If $\alpha=0.3$ the share of the Lasso penalty is 30%, and the share of the Ridge penalty $(1-\alpha)=0.7$ is 70%.

The hyper-parameter $\alpha$ corresponds to the argument mixture in the linear_reg() function. Worked with it already in Section 7.4.1 when you set mixture=1 assigning a share of 100% to the Lasso penalty and a share of 0% $((1-\alpha)=0)$ to the Ridge penalty — basically running a pure Lasso model.

In Section 7.4.2 you can run a pure Ridge by setting mixture=$\phi$ ($\alpha=0$) and thus implying the share of the Ridge penalty is 100% $((1-\alpha)=1)$.

## 7 Ridge, Lasso, and Elastic-Net — Regularization Explained

The advantage of the Elastic-Net approach is that you can run any mixture of Lasso and Ridge regularization. The disadvantage is that you get to tune with $\alpha$ (mixture) another hyper-parameter that either needs to be set in the linear\_reg command or needs to be tuned together with the hyper-parameter $\lambda$ (penalty).

You will tune these hyper-parameters later in an interactive project with Section 7.5. Here, in this section, we implement Elastic-Net into tidymodels by arbitrarily setting the hyper-parameters to keep things simple.

The commands to set up a tidymodels workflow for the Elastic-Net model are almost the same as in the previous section, except we arbitrarily set penalty=10000 and mixture=0.5.

```
seed(7777)
ModelDesignElasticNet=linear_reg(penalty=10000, mixture=0.5) |>
  set_engine("glmnet") |>
  set_mode("regression")

WFModelElasticNet=workflow() |>
  add_model(ModelDesignElasticNet) |>
  add_recipe(RecipeMouses) |>
  fit(DataTrain)
```

For the recipe that creates the various powers of the Sqft and normalizes the resulting predictors, we can use the recipe from Section 7.3.

Since the workflow WFModelRidge is a fitted workflow model (it was calibrated with the training data), we can extract the model with the tidy() command:

```
tidy(WFModelElasticNet)
```
