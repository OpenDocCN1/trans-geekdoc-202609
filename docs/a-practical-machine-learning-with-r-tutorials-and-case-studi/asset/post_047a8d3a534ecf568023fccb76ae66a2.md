
## 6.4 Demonstrating Overfitting with a Polynomial Model

```r
library(tidymodels); library(rio); library(janitor)
DataHousing=import("https://ai.large-analytics.com/data/HousingData.csv") |>
clean_names("upper_camel") |>
select(Price, Sqft=SqftLifting)
```

```r
set.seed(777)
Split01=DataHousing |>
initial_split(prop=0.01, strata=Price, breaks=5)
DataTrain=training(Split01)
DataTest=testing(Split01)
```

Note that the argument `split=0.01` assigns only 20 observations to the training data. The remaining 21,503 observations will be used as testing data. The reason to consider only 20 observations for training, although enough observations are available to create a bigger dataset, is that we purposely create circumstances that can lead to an overfitting scenario. In real-world analysis, we work with bigger datasets; overfitting is even more subtle and difficult to identify.

We use the prediction to estimate the price of a house based on living square footage (Sqft). The model is polynomial because Sqft is with various values:

> $Price = \beta_1Sqft + \beta_2Sqft^2 + \beta_3Sqft^3 + \beta_4Sqft^4 + \beta_5Sqft^5 + \beta_6$ (6.1)

Since the price of a house (Price) is estimated based only on its square footage, the model is classified as univariate. A univariate model was chosen because it will allow us to present the results in a 2D diagram with the price on the vertical axis and square footage on the horizontal axis.

As we see in Equation (6.1), the predictor Sqft is used with powers ranging from 1–5, which makes the model non-linear.

If you look at the charts that likely lead to overfitting in the info box at the end of the previous section, you can see that all conditions are fulfilled here:

- 1. The training dataset does not have a sufficient number of observations (20 observations in our case).
- 2. The model contains many variables, and thus many parameters to calibrate (five variables and six parameters to calibrate is usually not considered many, but compared to only 20 observations the number of parameters can be considered large).
  - Multivariate real estate model will be covered in Chapter 7.
- 3. Later in this chapter, Polynomial Models with various degrees will be used.

## 6 Polynomial Regression — Overfitting/Tuning Explained

- 3. The model is highly non-linear (a polynomial of degree 5 is highly non-linear).

To create the Polynomial Model with `tidymodels` we use the same model design as the interactive Section 5.5. To introduce non-linearity, we use the recipe (data:

```r
ModelDesignLinReg=linear_reg() |>
  set_engine("lm") |>
  set_mode("regression")

RecipeHouses=recipe(Price~, data=DataTrain) |>
  step_update(Sqft2=Sqft^2, Sqft3=Sqft^3,
Sqft4=Sqft^4, Sqft5=Sqft^5)
```

The recipe utilizes `step_update` to create four additional variables that are calculated as the square, cubic, quartic, and quintic of the variable Sqft:

- Sqft2=Sqft^2
- Sqft3=Sqft^3
- Sqft4=Sqft^4
- Sqft5=Sqft^5

Because Sqft is not only used in its original form, but also with various powers (squared, cubic, quartic, and quintic), the model is non-linear (in the data).

When looking at Equation (6.1) you can see why the model is linear in its parameters. If we treat the variables $Sqft, Sqft^2, ..., Sqft^5$ as the same as any other variable in a univariate OLS model, then each variable is multiplied by a parameter $\beta_1-\beta_5$, and added to the equation. Thus (6.1) is a linear function as long as we treat the different powers of Sqft as separate variables.

### A Polynomial Model is linear in parameters but non-linear in data.

Consequently, the Polynomial Model from Equation (6.1) can still be optimized the same way as a regular OLS model because it is still linear in its parameters, when we treat each power of Sqft as separate variables.

We optimize by adding the recipe and the linear model design to the workflow WFModelHouses, which is fitted to the 20 observations in the training dataset with `fit(DataTrain)`:

```r
WFModelHouses=workflow() |>
add_recipe(RecipeHouses) |>
add_model(ModelDesignLinReg) |>
fit(DataTrain)
```

Since the workflow WFModelHouses is fitted to the training data, we can use it to predict and measure the model's predictive performance. We start with measuring the performance during the training data.

As before, we use the `augment()` command to append the predictions to the training dataset and then we use the `metrics()` command to calculate performance metrics (see Sections 4.7.6 and 4.7.7 for details):

```r
DataTrainWithPred=augment(WFModelHouses, DataTrain)
metrics(DataTrain, truth=Price, estimate=.pred)
```
