### 10.4.2 Predicting Vaccination Behavior with Random Forest

Now it is time to showcase an application for Random Forest. In this section, we will use a Random Forest model to predict the U.S. vaccination rates during the COVID-19 pandemic. The analysis is based on research conducted by the author and his co-author, published in October 2022.

The data are from September 2021 and the outcome variable is the proportion of fully vaccinated (two shots) residents in 2,630 continental U.S. counties (PercVacFull).

The predictor variables were used:

- **Race/Ethnicity:** Proportion of African Americans (PercBlack), Asian Americans (PercAsian), and Hispanics (PercHisp) for the county.
- **Political Affiliation:** The proportion of voters who voted for the Republican presidential candidate (PercRep). Since only Republican and Democratic voters were considered, the proportion of voters who voted for the Democratic presidential candidate equals (1–PercRep).
- **Age Groups:** Proportion of young adults (20–25 years; PercYoung25) and proportion of older adults (65 years and older; PercOld65).
- **Income-related:** To control for income effects, we use the country’s proportion of households receiving food stamps (PercFoodSt).

In the code below, we load the data, select the variables to use, and split the observations into training and testing data:

```
DataVax=import("https://analytics.com/Data/Vax.rds") |
select(PercVacFull, PercRep,
PercAsian, PercBlack, PercHisp,
PercYoung25, PercOld65,
PercFoodSt, Population) |>
mutate(Population=frequency_weights(Population))
set.seed(2021)
Split8=initial_split(DataVax, prop=0.8, strata=PercVacFull, breaks=3)
```

Above, you can see that Population (i.e., the population of the related U.S. county)$^{14}$ was selected as one of the variables, although *Population* is neither an outcome nor a predictor variable for this research. *Population* will be used later in the workflow to weight the observations. To mark the variable *Population* as neither outcome predictor, we used the command `frequency_weights()`.

The recipe() in the code below is the same as in Section 10.3 except that now *PercVacFull* is chosen as the outcome.

```
RecipeVacFull=recipe(PercVacFull, data=DataTrain)
```

The dot in the argument *PercVacFull* indicates that all variables in DataTrain except the outcome, *PercVacFull*, should be used as predictor variables.

In the code below, we define the model and use the `rand_forest()` command to create a Random Forest model from the ranger package `set_engine()`. To keep things simple, we set the hyperparameters rather than tuning them:

```
library(parallel)
ModelDesignRand=rand_forest(min_n=5, mtry=2, trees=2000) |>
  set_engine("ranger", num.threads=detectCores()) |>
  set_mode("regression")
```

min_n means that at least five observations are required in a node of a Decision Tree to create two new child nodes. The parameter mtry determines the number of randomly chosen variables for a split in the Decision Trees. It is set to mtry=2. Both coincide with the defaults for Random Forest$^{15}$

We increased the number of Decision Trees used for Random Forest from the default (trees=500) to 2000. In contrast to the hyperparameters min_n and n, a high number of trees in Random Forest cannot cause overfitting.

> ¹14 Source: Centers for Disease Control and Prevention (CDC) (2021b).
> ¹15 min_n is the default for regression problems, and the default for mtry is $\sqrt{7} \approx 2$ (rounded down), as we have seven predictor variables.

The set_engine() command of Random Forest implementation in tidymodels allows us to execute code parallel on multiple cores to speed up computation. Random Forest is well suited for parallel computing because various Decision Trees can be developed independently from each other and afterward combined into Random Forest. We set the argument num.threads (the number of processes that run in parallel) to be the number of computer cores (num.threads=detectCores()).

In the code below, we create the workflow and add the recipe, model design, and we add_weights(Population) to weigh the observations with their respective population.

```
set.seed(2021)
WModelVax <- workflow() |>
  add_recipe(RecipeVax) |>
  add_model(ModelDesignRand) |>
  add_weights(Population) |>
  fit(DataTrain)
```

Using unweighted observations would imply assigning the same weight to counties with a few hundred residents as counties with millions of residents, which would not be reasonable. When printing WModelVax, you can see the setup of the fitted workflow, in addition, how it performed the OOB dataset.

## 10.5 Boosting Trees Algorithms

As mentioned, Boosting Trees algorithms are an improvement of Random Forest. They are based on many Decision Trees like Random Forest. However, the underlying Decision Trees are not randomly modified in Random Forest. Instead, they are boosted by weighing the training data used for Decision Tree or by changing how the Decision Trees are created and combined. Examples for Boosting Trees algorithms are:

- **AdaBoost:** AdaBoost is an ensemble algorithm like Random Forest. The AdaBoost algorithm uses tree stumps (Decision Trees with one level depth) for its trees. It starts by using the outcome and predictor variables from the training dataset to create the first tree and following Decision Trees, the errors of the previous Decision Tree are used as outcome variables. When these Decision Trees are combined to generate a prediction, they are weighted according to their predictive quality. Higher weight is assigned to trees with better predictive quality. This weighting of the trees is in contrast to a Random Forest, which uses an unweighted average for combining the predictions from its Decision Trees.

We mention AdaBoost because it was one of the earliest Boosting Trees algorithms. We will not go into more detail, meanwhile, while powerful Boosting Trees algorithms have been developed.

- **Gradient Boosting:** This is a very powerful algorithm. Gradient Boosting starts with a first prediction based on the mean of the training dataset's output variable. To create the first tree, it uses the errors from the first prediction as output and the variables as predictor variables. After, it combines the initial prediction and the prediction from the first Decision Tree. Then, based on the resulting new prediction errors, it creates a second tree. This process continues until a predefined number of trees is created, or another stopping criteria is reached.

We will cover Boosting in more detail in Section 10.5.1.

- **XGBoost:** The XGBoost algorithm is a variation of Gradient Boosting. The major difference is that it is optimized for performance as it supports parallelization using multiple cores, and it supports distributed computing on a cluster of computers. This makes XGBoost significantly faster than regular Boosting for large datasets. In addition, XGBoost penalizes complex models, which helps avoid overfitting.

You will use the models of XGBoost in the interactive Section 10.5.2 to predict vaccination behavior with the same dataset that was used in the previous section with Random Forest.
