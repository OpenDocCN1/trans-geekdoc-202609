In order to separate the predictor variables from each other, a plus sign (+) is used. It is essential to understand that the + sign is unrelated to any type of addition. The second required argument in the recipe command determines which data frame is used for the pre-processing. This data frame is usually the training data frame.

The recipe() command is followed by instructions on how to process the data by step. Each step starts with step_, indicating that the instruction (command) is part of a recipe.

The recipe() and all steps in a recipe are connected with the piping operator (%) to form the recipe. A recipe is usually saved into an R object recipe. We named the object using the word recipe to indicate that the object contains a recipe.

The recipe() command in the code block lists the predictor variables Sulfur and Acidity explicitly separated by a + sign. There is also a short form for defining variables as outcome and predictor variables that can be used when the processed data frame excludes the outcome and predictor variables. That is, there are no extra unused variables in the data frame.

We use the short form in the code to replicate the recipe before using. As you see, there is only a minimal change in the first argument of the recipe() command — called the formula. We still list the outcome wineColor followed by the - symbol. On the right-side of the - symbol, we simply add a dot (.) indicating listing the predictor variables. The - represents all other variables in the data frame (dataTrain) that are not outcome variables — all predictors.

```
RecipeWine=recipe(wineColor, data=dataTrain) |
step_nomist()

```

Previously we learned that predictor variables must be scaled before using them in a k-Nearest Neighbors model. Scaling variables with greater values having a stronger influence on the prediction results than variables with lower values. Recall that Z-score normalization was introduced as an effective scaling method (see Section 4.6 for details).
