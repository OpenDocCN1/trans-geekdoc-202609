#  7.4.2 Ridge Regularization

In this section, we will work with $Ridge$ regularization. As you will see, this approach differs only slightly from the $Lasso$ approach we introduced in Section 7.4.1.

The most significant difference is that $Ridge$ uses a different method to penalize large $eta$ values. Instead of adding the absolute values to calculate $penalty$, Ridge squares the $eta$ values before adding them up to calculate the Ridge $penalty(P_{Ridge}^{penalty})$.

This becomes more obvious when you substitute the definition for the $Ridge$ penalty from equation (7.5) into the target (7.3) in the target for the Ridge approach:

```
$MSE_{Ridge}^{target} = \frac{\sum_{i=1}^{20}(Price_i - Price_i)^2 + \lambda \sum_{i=1}^{5}\beta_j^{P_{Ridge}^{penalty}}}{MSE} (7.7)
```

with: $Price_i = \beta_1 Sqft_i + \beta_2 Sqft_i^2 + \beta_3 Sqft_i^3 + \beta_4 Sqft_i^4 + \beta_5 Sqft_i^5 + \beta_6$

Since the $eta$ parameters are now squared when considering to the $Ridge$ penalty, larger $eta$ values have an over-proportional impact on the $penalty$, a major difference compared to the $Lasso$ approach.

When using the Ridge model with tidymodels, we can use the same code as in the $Lasso$ Section 7.4.1. The only two changes are that we set the argument $mixture=0$ in the $linear\_reg()$ code to $mixture=0$, indicating that we use a $Ridge$ model and we arbitrarily set the argument $penalty=1000000$ $(\lambda = 100000)$.

```
set.seed(7777)
ModelDesignRidge=linear_reg(penalty=1000000, mixture=0) |>
  set_engine(\`"glmnet\`") |>
  set_mode(\`"regression\`") |
```

```
WFModelRidge=workflow() |>
  add_model(ModelDesignRidge) |>
  add_recipe(RecipeHouses) |>
  fit(DataTrain)
```
