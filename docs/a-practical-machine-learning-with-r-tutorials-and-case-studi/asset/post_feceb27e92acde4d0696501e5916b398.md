
# 7.4 The Idea Behind Regularization

The glnet package is a highly efficient package developed by Friedman et al. (2010). It supports multiple machine learning algorithms including Lasso with linear_reg(mixture=1) and Ridge with linear_reg(mixture=0). We will discuss the hyper-parameter mixture in more detail in Section 7.4.3. In the code block above, we use mixture=1 to work with a Lasso model.

The other hyper-parameter penalty in the code block above stands for the λ in Equation (7.6). This tidyymse hyper-parameter name is a little confusing because it determines the strength of the penalty but not the penalty itself. Just remember, penalty and lambda are essentially the same.

The hyper-parameter penalty can either be set to a specific numerical value or determined in the tuning process. In the case, tuning and regularization are combined. In the interactive project in Section 7.4.3 we will tune the penalty (the λ). In the code block above, we arbitrarily chose penalty=500 to keep things simple.

## 7.4.2 Ridge Regularization

In this section, we will work with Ridge regularization. As you will see, this approach differs only from the Lasso approach introduced in Section 7.4.1. The most significant difference is that Ridge uses a different method to penalize large $\beta$ values. Instead of adding the absolute values to calculate penalty, Ridge squares the $\beta$ values before adding them up to calculate penalty. This becomes more obvious when you substitute the definition for the Ridge penalty from equation (7.5) into the target (7.3) for the Ridge approach:

$MSE_{Ridge} = \frac{\sum_{i=1}^{n}(Price_i - Price_i)^2 + \lambda \sum_{j=1}^{p}\beta_j^2}{n}$ (7.7)

with:
$Price_i = \beta_1 Sqft_i + \beta_2 Sqft_i^2 + \beta_3 Sqft_i^3 + \beta_4 Sqft_i^4 + \beta_5 Sqft_i^5 + \beta_6$

Since the $\beta$ parameters are now squared when considering the Ridge penalty, larger $\beta$ values have an over-proportional impact on penalty, a major difference compared to the Lasso approach.

When using the Ridge model with tidymodels, we can use the same code as in the Lasso Section 7.4.1. The only two changes are that we set the argument mixture=0 in the linear\_reg() code to $mixture=0$, indicating that we use a Ridge model and we arbitrarily set the argument $penalty=1000000$ $(\lambda = 100000)$.

```
set.seed(7777)
ModelDesignRidge=linear_reg(penalty=1000000, mixture=0) |>
  set_engine("glmnet") |>
  set_mode("regression") |
```

```
WFModelRidge=workflow() |>
  add_model(ModelDesignRidge) |>
  add_recipe(RecipeHouses) |>
  fit(DataTrain)
```

The *recipe* that creates the various powers of the *Sqft* and normalizes the resulting predictors, we again use the *recipe* from Section 7.3.
