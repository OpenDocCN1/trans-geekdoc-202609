# 4.5 The Idea Behind k-Nearest Neighbors

A k-Nearest Neighbors analysis considers only one neighbor (the nearest: $N_1$) and the bold magenta in Figure 4.6 might suffer from this type of exception. Therefore, we might consider more than one neighbor ($k > 1$).

Figure 4.6 shows an example for a $k=4$ Nearest Neighbors model. The four nearest neighbors to the blue predicting point ($N_1, N_2, N_3, N_4$) and their distance to the predicting point are marked with magenta lines. The majority of these $k$-nearest neighbors are red wines (compared to 1). Consequently, the prediction is that the probability of the unknown wine being $red$ is $75\%$ ($\frac{3}{4} = 0.75$), and the probability of being $white$ is $25\%$ ($1 - 0.75 = 0.25$).

If one of the three red wines were white, we would end up with a tie. In this case, the predicted color would be determined randomly.

Tuning the *hyper-parameter* for a *Nearest Neighbors* model is covered in detail in Chapter 6, Section 6.7.

Right now, you might be tempted to run the model for different values of $k$ and then use the dataset to see which $k$ delivers the best prediction performance. However, this is not an appropriate way to optimize hyper-parameters.

Using the testing dataset to optimize hyper-parameters can lead to overfitting.

Overfitting occurs when a prediction model performs well on the training data, but when it is for predictions based on new data that the model has "never seen before", we have to find ways to limit ourselves to the training data when optimizing *hyper-parameters* such as the $k$ in *k-Nearest Neighbors* (see Section 6.7 for methods, for how we can do this.

In general, a $k$ that is too low is prone to be influenced by isolated outliers, although the surrounding neighborhood would suggest otherwise. On the other hand, a $k$ that is too high would consider a neighborhood so large that it does not represent the neighborhood surrounding the prediction point anymore.
