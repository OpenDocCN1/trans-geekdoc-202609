## 7.5.2 Unregularized Benchmark Model

As a benchmark, we begin with an unregulated model. In this case, a multi-variate Degree-2 Polynomial Model. It includes the variables Sqft, Bedr, and Year. They are used in their original form, and as various interaction terms:

```

$+ \beta_4Sqft^2 + \beta_5Bedr^2 + \beta_6Year^2$
$+ \beta_7SqftBedr + \beta_8SqftYear + \beta_9BedrYear$
$+ \beta_{10}Sqft^2Bedr + \beta_{11}SqftBedr^2 + \beta_{12}Sqft^2Bedr^2$
$+ \beta_{13}SqftYear^2 + \beta_{14}SqftYear^2 + \beta_{15}Year^2$
$+ \beta_{16}Bedr^2Year + \beta_{17}BedrYear^2 + \beta_{18}BedrYear^2$ (7.10)
```

## 7.5.3 Regularized Elastic-Net Polynomial Model

When you substitute the ... after mixture= and penalty=β further below with values of your choice and execute, the model’s β values will be calibrated and printed. Also, the metrics for the testing data are calculated and printed.

Recall, if mixture=0, you will run a Ridge model; if mixture=1, you will run a Lasso model. For anything in between, you will run a mixed model.

Finding an appropriate value for the argument penalty= is more tricky. The Ridge penalty, values between 15,000 and 154,000 will work. For the Lasso penalty, values between 15 and 154,000 will work. A few settings can help see how the results are changing. For example, mixture=1 (Lasso) and penalty=10000. You can also set mixture=0.5 or 0.7 to try out different Elastic-Net models. Playing with different hyper-parameter values and observing the beta and metrics will help you better understand regularization.

```r
ModelDesignRegularized=linear_reg(penalty=..., mixture=...) |>
set_engine("glmnet") |>
set_mode("regression")

WFModelRegularized=workflow() |>
add_model(ModelDesignRegularized) |>
add_recipe(RecipeHousesMultivar) |>
fit(DataTrain)

print("Beta Values (see Column Estimate):")
tidy(WFRegularized)

DataTestWithPredRegularized=augment(WFRegularized, DataTest)
print("Metrics for Testing Data:")
metrics(DataTestWithPredRegularized, truth=Price, estimate=.pred)
```

**Warning:** Never use the testing data to find the best-parameters. Instead, use validation data derived from the training dataset to evaluate the performance.

## 7.5.4 Tuning the Elastic-Net Model

In this section, you will use the Template to tune the hyper-parameters penalty and mixture.

- Step 1 - Generate Recipe and Training Data: The training and testing data have already been generated (Section 7.5.3 above).
- Step 2 - Create a Recipe: The recipe to create the predictors for the multivariate Degree-2 polynomial model (RecipeHousesMultivar) was created in connection with the unregulated model and establishes the various powers and interactions.
- Step 3 - Create a Model Design: The model design from the previous section needs slight modifications. You will have to add the tune() placeholder for the hyper-parameters:

```r
ModelDesignElasticTune <- linear_reg(penalty=tune(), mixture=tune()) |>
set_engine("glm") |>
set_mode("regression")
```

- Step 4 - Add the Recipe and the Model Design to a Workflow: we add the recipe and the (modified) model design to the workflow:

```r
TuneWorkflow <- workflow() |>
add_recipe(RecipeHousesMultivar) |>
add_model(ModelDesignElasticTune)
```

- Step 5 - Create a Hyper-Parameter Grid: Previously, when only one hyper-parameter was tuned, you added the values to be tried out in a column with the same name as the hyper-parameter. When you have more than one hyper-parameter, it gets a little more complicated because you want to try different combinations of hyper-parameters.

If you decide to try all combinations of the values from two or more hyper-parameters, you can use the crossing() command. The arguments of the crossing() command are the hyper-parameters you would like to try out. The assigned values to these arguments are the values you want to try out for each of the hyper-parameters. They are assigned to each argument as R vector objects. The crossing() command then generates all possible combinations for the values of the hyper-parameters.

For example, in this project you later try 66 penalty values from 15,000 to 80,000 with an increment of 1,000 and three mixture values (0, 0.5, and 1). You can use the crossing() command to generate all possible combinations:

```r
ParGridHouses=crossing(mixture=c(0, 0.5, 1),
              penalty=seq(15000, 80000, 1000))
```
