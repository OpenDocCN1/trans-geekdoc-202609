
Therefore, we have proposed quantizing in a supervised fashion, using a simulated and labeled training set. The general idea is to interpret the target bins $\overset{\rightarrow}{f}_i$ as classes and to train a classifier that predicts the $\overset{\rightarrow}{f}_i$ from the given features. To work as a quantization method, the classification model needs to partition the feature space to make predictions. As one instance of this general proposal, we have evaluated decision trees [[90](#9783110785951_034588.xhtml#b_9783110785968-011_ref_090)] which recursively partition the feature space until a predetermined depth is achieved. We interpret the leaves of such a tree as the clusters to which each event is assigned. We count the number of events in each leaf and thereby obtain a count vector $\overset{\rightarrow}{g}$. Like in the k-means quantization, all features can be used by the tree. But unlike k-means quantization, the clusters are highly correlated with the target quantity $\mathcal{Y}$. In fact, they are designed to predict $\mathcal{Y}$, and are thus well-aligned with the goal of deconvolution.

### 10.3.3 Optimization

The core of our TRUEE software [[272](#9783110785951_034588.xhtml#b_9783110785968-011_ref_272)] is the RUN algorithm [85, 86], which maximizes Equation 10.38 numerically via the Newton-Raphson method [[293](#9783110785951_034588.xhtml#b_9783110785968-011_ref_293)]. Recall from Section 3.2.2 that this method evaluates a local second-order approximation $\hat{\mathcal{l}}^{(k)}$ of the objective $\ell$ in iteration $k$. The minimizer of each $\hat{\mathcal{l}}^{(k)}$ is chosen as the respectively next estimate $\hat{\overset{\rightarrow}{f}}(k + 1)$. Taking out multiple iterations will eventually reach a local minimum of the actual objective function $\ell$. Such an iterative approach is necessary because the actual function $\ell$, in the case of likelihood-based deconvolution, can not be maximized analytically. Letting $\overset{\rightarrow}{f}_i = \overset{\rightarrow}{\theta}_i$, we obtain the following local model:

$$
\hat{\mathcal{l}}^{(k)}(\overset{\rightarrow}{f}) = \frac{1}{2}\overset{\rightarrow}{f}^{\top}H\overset{\rightarrow}{f} - \overset{\rightarrow}{f}^{\top}\left( H\hat{\overset{\rightarrow}{f}}^{(k)} - \overset{\rightarrow}{h} \right),
$$

where $\overset{\rightarrow}{h} = \nabla\mathcal{l}\left( \hat{\overset{\rightarrow}{f}}^{(k)} \right)$ is the gradient and $H = \nabla^{2}\mathcal{l}\left( \hat{\overset{\rightarrow}{f}}^{(k)} \right)$ is the Hessian of $\ell$ at the latest deconvolution estimate $\hat{\overset{\rightarrow}{f}}^{(k)}$.

### 10.3.4 Regularization with a Fixed Number of Degrees of Freedom

RUN does not fix the value of the regularization parameter $\tau$, as other methods in machine learning, optimization, and statistics usually do. Instead, it controls the regularization strength by another parameter, $n_{df}$, the effective number of degrees of freedom. This parameter has a clearer interpretation, but it is still a hyperparameter that needs to be tuned just like a fixed value of $\tau$ would.

To fix $n_{df}$, RUN has to change $\tau$ in every iteration of the algorithm. Computing the value of $\tau$ for a given $n_{df}$ requires an eigen-decomposition $H = U^{\top}VU$ of the Hessian matrix $H$. Based on this decomposition, a new matrix $C^{\prime} = V^{- \frac{1}{2}}U^{\top}C^{\top}CUV^{- \frac{1}{2}}$ with the eigen-decomposition $C^{\prime} = U^{\prime\top}V^{\prime}U^{\prime}$ is defined. By setting $\overset{\rightarrow}{f}^{\prime\prime} = U^{\prime\top}V^{\frac{1}{2}}U^{\top}\overset{\rightarrow}{f}$, the regularized local model $\hat{\mathcal{l}}_{r}^{(k)}$ can be reformulated as

$$
\hat{\mathcal{l}}_{r}^{(k)}(\overset{\rightarrow}{f}) = \frac{1}{2}\overset{\rightarrow}{f}^{\prime\prime\top}\left( I + \tau \cdot V^{\prime} \right)\overset{\rightarrow}{f}^{\prime\prime} - \overset{\rightarrow}{f}^{\prime\prime\top}\left( UV^{- \frac{1}{2}}U^{\prime} \right)^{\top}\left( H\overset{\rightarrow}{f}^{(k)} - \overset{\rightarrow}{h} \right),
$$

where the minimizer of $\hat{\mathcal{l}}_{r}^{(k)}$ is $\hat{\overset{\rightarrow}{f}} = UV^{- \frac{1}{2}}U^{\prime}\hat{\overset{\rightarrow}{f}}^{\prime\prime}$. In turn, $\hat{\overset{\rightarrow}{f}}^{\prime\prime}$ is the minimizer of the reformulated problem, being given by

$$
\begin{array}{l}
\hat{\overset{\rightarrow}{f}}_{i}^{\prime\prime} = \frac{1}{1 + \tau V_{ii}^{\prime}}\hat{\overset{\rightarrow}{f^{i}}}_{i}^{\prime\prime} \\
\hat{\overset{\rightarrow}{\overset{\rightarrow}{f}}}^{\prime\prime} = \left( UV^{- \frac{1}{2}}U^{\prime} \right)^{\top}\left( H\overset{\rightarrow}{f}^{(k)} - \overset{\rightarrow}{h} \right).
\end{array}
$$

Finally, the effective number of degrees of freedom of the minimizer $\hat{\overset{\rightarrow}{f}}$ is $n_{df} = \sum\limits_{i}\frac{1}{1 + \tau V_{ii}^{\prime}}$. In case of $\tau = 0$, each of the $I$ components of $\hat{\overset{\rightarrow}{f^{\prime}}}^{\prime\prime}$ fully contributes to the solution with $n_{df} = I$. Accordingly, the total contribution of $\hat{\overset{\rightarrow}{\overset{\rightarrow}{f}}}^{\prime\prime}$ to $\hat{\overset{\rightarrow}{\overset{\rightarrow}{f}}}$ is reduced whenever $\tau$ is greater than zero. A low value of $n_{df}$ will smooth the deconvolution result by penalizing high curvatures.

The Newton-Raphson steps of the RUN algorithm assume a meaningful starting point $\overset{\rightarrow}{f}^{(1)}$. This first estimate is implemented as a basic least squares solution, which does not yet take the assumptions of bin-wise Poisson distributions and smoothness into account but already gives a starting point that is sufficiently close to the true solution. Here, $\overset{\rightarrow}{h}_{LSq}$ is the gradient, and $H_{LSq}$ is the Hessian of the least-squares loss $\ell_{LSq}$ at the zero vector:

$$
\mathcal{l}_{LSq}(\overset{\rightarrow}{f}) = \frac{1}{2}(A\overset{\rightarrow}{f} - \overset{\rightarrow}{g})^{2}\rightarrow\min
$$

The original implementation of the RUN algorithm was written in Fortran77 and last updated in 1996. This led to a couple of compatibility issues, especially with the analysis framework ROOT [[56](#9783110785951_034588.xhtml#b_9783110785968-011_ref_056)].
