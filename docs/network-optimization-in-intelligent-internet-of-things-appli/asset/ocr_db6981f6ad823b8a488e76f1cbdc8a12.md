# TABLE 15.1

Summary of Pertinent Work

| Reference | Year | Mechanism | Limitations |
| --- | --- | --- | --- |
| Lin et al. [10] | 2018 | Privacy-preserving authentication and identity-based encryption | - The inherent limitations of resources within the IoD architecture hinder the implementation of Identity-based encryption (IBE).<br>- No mutual authentication |
| Teng et al. [11] | 2019 | Elliptic Curve Cryptography (ECC) and Public Key Infrastructure (PKI) | - Implementation could be burdensome for devices with limited resources, such as drones |
| He et al. [12] | 2019 | Proxy blind signature scheme | - Length of the signature is large.<br>- Signature processing requiring more time. |
| Tian et al. [13] | 2019 | Efficient preserving authentication | - Security features such as in-the-middle and mutual authentication are missing.<br>- No formal security assessment method. |
| Huang et al. [14] | 2020 | Triangular-oriented strategy | - Exorbitant expenses for communication and storage. |
| Gope et al. [15] | 2020 | One-way hash and PUF | - It falls in short terms of preserving the privacy of location. |
| Zhang et al. [16] | 2020 | One-way hash and 2-factor authentication | - Un-traceability is not part of package. |
| Alladi et al. [17] | 2021 | Drone-MAP | - No security assessment method like the random oracle model was provided.<br>- Does not meet all security requirements like Identity verification and physical attack resistance |
Rajasekaran et al. [18] | 2022 | Anonymous mutual and batch authentication | - Bilinear guards are expensive and hard to implement due to complex in nature.<br>- Trusted servers can be vulnerable to adversary attacks. |
| Salam et al. [19] | 2023 | SELTHA (Secure, Efficient, and Lightweight TOTP-based Hashed Authentication) | - No formal security analysis approach like ProVerif Scyther etc. |
