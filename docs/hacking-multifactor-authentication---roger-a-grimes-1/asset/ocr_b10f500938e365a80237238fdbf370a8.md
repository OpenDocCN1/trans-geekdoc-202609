The first four "laws" are essentially (redundantly) stating that if a malicious person can control your software or device, then they can do really bad things. This is true. Any trusted device that is in a malicious person's hands or that is running malicious code is no longer trusted. If an attacker can modify an operating system, it's no longer the creator's operating system; it's the attacker's. The risk of malicious compromise or physical access is any attack, possibly only by the ability of the device and software to operationally accomplish it.

NOTE Conversely, security defenders mistakenly oversimplify malware risks when they say or think an attacker "can do anything! when the attackers control the endpoints. This is almost true, but the attacker's maliciousness is limited to the type of access they have and what the software and device is capable of doing. For decades, some early virus writers making spurious claims said they had written malware that could "slam" the read/write heads of drives against the drive central spindle, over and over, until the heads flew apart, irreversibly physically damaging the drives. I laughed when I heard this and taunted them because I knew that all hard drive read/write heads were physically incapable of landing inside their central spindles. The physical, mechanical, metal components of a hard drive prevent it. And no amount of "genius" malware coding was going to get around a physical limitation. Sometimes unskilled, immature attackers make impossible, overreaching, salacious claims to induce additional panic in unknowable degrees of their diatcribes.

Many people forget that although an attacker having physical access or code control over an endpoint is not a good thing, it's not easy to be the hacker. It's not guaranteed that an attacker having that sort of control will absolutely bypass all security defenses.
