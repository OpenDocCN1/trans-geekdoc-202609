Let me go into more detail about the authentication experience involving UAC so you'll better understand what I'm talking about. What Windows developers could easily stop malicious programs simulating the entire UAC experience when it did not really happen. With the real UAC experience, the UAC prompt comes up when the user, or Windows requests it. But there is nothing to stop a malicious program that is actively running from faking the UAC experience is happening when it isn't. All a malicious program has to take a desktop picture or offer a single-colored, dimmed background; make a fake UAC prompt appear; ask the user to click OK or type in their login credentials; and have to see what the user did. The user can even be tricked into providing their credentials to the UAC prompt, which is made to appear as if it, and then a real UAC prompt is called. The user will likely just think they've typed in their credentials the first time and then think the "second time" that they typed in correctly. There is no way for Windows or U to accurately detect that a fake UAC experience occurred or to block it with a high level of accuracy. Even if Windows actively tried to look for and detect instances of fake UAC prompts, the fake UAC prompt could be changed so much that Windows detects it no matter how much it tries.

If the user types in their credentials, the malicious program can record the user's elevated credentials and then use them behind to do anything the user can. The hacker or malware program will "own" the system. They can install more malware, record the user's keystrokes with a keystroke logger, dump all the system credentials, manipulate data, and spread around the network. What the malware or attacker can do is limited only by their malware developer's or hacker's imagination and what is possible the software and hardware constraints.

The user can also be tricked into providing other confidential information or believing they had performed some necessary administrative action, such as fooling the user into thinking they had a run (a) antivirus scan or install a new, (but really fake) Microsoft patch. A real UAC prompt will often show the legitimate vendor of the program if that program is signed by a trusted digital certificate. So, all the malicious program has to do the whole experience, including showing a fake trusted digital certificate that Windows appears to be saying is real and trusted. Fake authentication can be used to do many things, including:

+   * Steal credentials.
* Perform a man-the-middle attack, which is then used by the attacker to access the real site/service as the victim.
* Steal other confidential information.
* Take over the logon account.
* Make the victim think some legitimate action occurred that did not in actuality.
