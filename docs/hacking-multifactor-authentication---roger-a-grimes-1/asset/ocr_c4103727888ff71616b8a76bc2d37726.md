# Introduction

As covered earlier in Chapter 3, “Types of Authentication,” application programming interfaces (APIs) are created by developers of their underlying technologies or services to allow other developers and users to graphically interface with their product. APIs allow other people and services to quickly interact with a product and easily extend its functionality. APIs are a staple of the computer world, especially if you want yours to be widely adopted and used. If an API is created and the general public can access and use it, it is known as an open or public API.

As an example, the HaveBeenPwned website (havebeenpwned.com), which can tell you if a particular name or password has been part of a known breach, has an API (havebeenpwned.com/API/v3) anyone can use. In fact, it's third that HaveBeenPwned's API allows a different account lookup every 1.5 seconds. If you tried to look up different accounts or passwords using the website, you'd probably be lucky to receive one every 10–15 seconds. So, using the API is at least a10x speed increase when doing multiple lookups. On top of that, what the website can look for is limited to what the website has preprogrammed to. With its API, you can look for dozens of types information and perform actions that aren't possible using the default website interface.

Many other sites and services link to HaveBeenPwned using the API, and its availability and low-cost use ($3.50 per month as this is) is likely responsible for the overall scale of its success. Instead of having to look up compromised accounts one at a time, an external programmer or service can look up a batch of accounts and passwords (HaveBeenPwned stores over 500 million stolen passwords) much more quickly.
