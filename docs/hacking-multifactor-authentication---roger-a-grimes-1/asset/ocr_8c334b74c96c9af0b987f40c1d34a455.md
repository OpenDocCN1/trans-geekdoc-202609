The key difference is that a HOTP device will change the code at a preset period of time or event but doesn't actually use the current time in the calculation, whereas a TOTP actually uses the current time value in the calculation to generate a new code.

Some OTP devices key off a particular event or action and are known as event-one-time-password (EOTP) devices. Most EOTP devices have a button that the user clicks. The button click generates a new number, which is used in the OTP code generation. Often the button click seriously advances a counter in the EOTP device. In these instances, the counter is used in the OTP calculation.

OTP devices have globally unique identifiers (i.e., serial numbers) that are hard-coded into the device and also stored in the backend authentication database. A seed is randomly generated by the device and/or database shared with the other. Then the seed value and supplied information (possibly including the unique identifier) are used with a documented algorithm to generate future codes. TOTPs are very popular and have been in use for decades. Probably their one usability drawback is the limited time a user has to access and view the code on the TOTP device before another code must be used. Every TOTP user has experienced the anxiety of hoping to be able to type in the current code and hoping it stays valid enough to be authenticated before the next one appears. Every TOTP user understands the slight feeling of failure when they are too late and the authentication is rejected as the next code pops up.
