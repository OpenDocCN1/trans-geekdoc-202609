Using a good cryptographic hash, like SHA-256, with an additional random portion ensures that any hacker viewing one session ID won't be easily to guess another. The session ID should be time bound (i.e., expire after a specified time limit) to ensure that one session ID can't be reused for the same user in another session after the first ones. If someone can view or guess the identifying information, they can easily craft an identical access token. Access control tokens often look for predictable patterns in what is supposed to be random and unpredictable. Hackers will authenticate to a website many times with different identities and review the resulting access token information for predictable patterns. If they see a suspect pattern in the cookie's supposedly identifying information, they will begin to construct additional cookies, modifying them in their way, and connect to the website to see if it (a) accepts the cookie, and (b) authenticates as another valid user account. Many of the data breaches you read about in the news are really hackers who figured out a session ID pattern and used it to dump an entire database.

# Token Theft

If the attacker has the appropriate access, it's probably just easy to steal a user's legitimate access token. Most access tokens contain correctly generated randomly session IDs, as shown in Table 6.1, and so trying to guess them or find a repeatable pattern is nontrivial (i.e., very hard to implement using known technologies and techniques in a reasonable amount of time). Access control theft can happen locally or over the network. If an attacker has complete control of a user's computer or device, usually this is enough to let access, view, steal, and/or manipulate and use the access control token.

Admin does not guarantee immediate access to an access token. Many operating systems provide special protections to access control tokens and the processes around them, and even the highest admin access won't let a user directly access the token. Most of the time, ultimately, if an attacker has unencumbered access to a device or network, with enough time and resources, access to the access token will be gained, one way or another.

Other times, especially if the token is stored on a cryptographically protected token device, it can be outside of exceptional attempts to access and duplicate the access token. Instead, it would be easier for attackers to manipulate or reuse the token when it is being used by the legitimate user. You'll learn more about this latter type of scenario in later chapters.
