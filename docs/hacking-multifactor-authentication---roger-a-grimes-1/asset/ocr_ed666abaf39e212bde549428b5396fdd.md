# 54 Hacking Multifactor Authentication

# Least Privilege Principle

One of the bedrock security principles is that subjects should have the least amount of per-missions and privileges necessary to delimit their legitimate task. This holds true whether using passwords or for people using MFA solutions. You never want someone with the highest permissions and privileges all the time, especially if they are doing regular tasks (e.g., checking email, writing a document) that doesn’t require those permissions and privileges.

# On-Demand

Some authentication mechanisms allow a single person to use multiple logons, one privileged and nonprivileged, and the user picks which one they need at a single time. Other systems will allow you to perform step-up authentication, say, moving from a regular user to admin or root user (using sudo in Linux, for example) when the higher or different account is needed. Other systems require specific credentials at the time of need. All highly privileged accounts may be stored in a centralized database, and any potential administrator has to successfully authenticate the privilege account and “check out”. The checkout is tracked in an event log. The highly privileged account may be further limited by duration, security domain, or allowed actions. These systems are generally known as privileged account managers (PAMs). Other types of access control systems act as SSO systems and will automatically regulate regular users to privilege status when needed and predefined.

# Authorization

You've successfully authenticated your identity and obtained an access control token. Now you want to use it as a license to access protected objects (i.e., file, folders, websites, services). The process of an access control manager submitting access control token and comparing it to a list of per-missions associated with a protected resource is called authorization. Determining “can this person or device access that” is the key function of an access control manager. How well it enforces the comparison between the identity and its access control token and what is allowed the permissions and privileges attached to the protected object (often known as access control lists) tells us how the system is overall.

# Accounting/Auditing

All the critical steps of the three previous steps (IDM, authentication, and authorization) should be noted and saved to an event log. In general, accounting refers to tracking how of something (e.g., how many times they have logged on, in the system) and auditing refers to a detailed an-ysis of the involved action. However, in today’s world we usually lump them into auditing or event log management. Any good authentication system will log all critical steps from provisioning to deprovisioning and everything in between.
