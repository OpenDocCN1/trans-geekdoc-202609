# Chapter 7 Endpoint Attacks

The MFA device should stop operations reuse (i.e., “brick”) on any critical error. Any detected anomaly should be displayed descriptively to the end user if possible and the MFA solution should error out or refuse to operate. Most developers work with an attitude of trusting the other components to be uncompromising and reliable. A good MFA developer takes the opposite attitude, threat-models, plans, and codes accordingly.

# Secure All Network Communications

Ensure that all communications between an MFA device and the system and networks are secure against attack. These days most network connections are protected by HTTPS/TLS, which is a great default as long as the code can be updated in the future if the current version is found to have flaws. HTTPS/TLS is frequently updated over time to fix identified flaws.

# Tie Access Control Tokens to Registered Devices

If possible, tie access control tokens to previously registered devices. That way, an attacker cannot compromise the token and move it to another device and reuse it.

# Prevent or Notify the User of Second Instances

Stop or communicate with users when a second, concurrent, authenticated instance using the same MFA or access control token is used by an additional process or additional instance of the same process. This can be very difficult to do in practice for least two reasons. First, allowing multiple instances to share the same MFA or access control token at the same time makes the user's life easier. Users not want to completely reauthenticate every time they are starting a new instance to connect or to do the same things. Having to authenticate for each additional instance, depending on how it is done and when it is needed, can be overly burdensome to the end user. And if you make it hard on the end user to use it, they will often choose not to use your product or work in such a way that it invalidates the overall process.

Second, many operating systems do not easily allow programmers the ability to prevent one security identity instance from being used with a second process. In fact, the only that allows this by default is Qubes (www.qubes-os.org), which is used by very few people though it is open source and free. Some other versions of Linux allow separation but do not enable it. Enabling strict process separation can cause operational issues. Microsoft Windows is still, as of 2020, struggling to allow stricter process separation and handling by default, but they are working toward that goal and toward something to what Qubes has achieved.

If MFA or access control reuse cannot be prevented, to notify the user or make sure they are easily aware of the second instance. To prevent “hidden” instances Additionally, you might want to log all uses by location and process and let the user know that information.
