# Chapter 18 DNS Hijacking 39

DNS was officially put to use on the Internet in 1983. Prior to DNS, each communicating computer or device that wanted to connect to another computer or device across the Internet (at the time called ARPANET) had to use the destination computer's IP address, even though most computers also had more typed-in English-language hostnames. The humans using and configuring these computers were not as good at remembering a bunch of long numbers (i.e., IP addresses) as were hostnames. Everyone agreed that using hostnames for connections would be easier; they just needed a method for converting hostnames to IP addresses.

Initially, computers' operating systems (and/or applications) were updated to include and use a file named hosts (or hosts, hosts.TXT, hosts.txt), which listed the names of the desired computers followed by their IP address. Users could then use a computer's hostname and the OS or application would look to the HOSTS file to convert the hostname to an IP address, which it then needed to connect to the destination computer(s).

> You can still find a HOSTS file on most computer systems. In a Microsoft Windows computer, the HOSTS file is located under \Windows\System32\drivers\etc.

This method still required a local or human process to update the HOST file on each participating computer with the necessary computer hostnames and IP addresses any time wanted to use the hostname with a computer not already documented. There was a manual pain before it began to scale to larger networks. According to lore I've heard, by the time the HOST file included just eight computer names, many people started to see that a more robust, automated, centralized service was needed to handle the hostname-to-IP address conversion. A computer scientist named Paul Mockartner, with Jon Post, created DNS. Within a few years, a computer server/component named Berkeley Internet Name Domain (BIND) was created in Unix so that any Unix-like computer could participate. Today, BIND (www.isc.org/bind) and Microsoft's DNS server (server and client) handle the variety of DNS queries.

> manipulates the HOSTS file in order to maliciously redirect computers to rogue routers. The HOSTS file, if present, is often checked by OSs and applications before they use DNS. But it's an older, legacy file that is rarely used, so humans don't often look there when investigating suspicious redirection behavior. Or, if malware modifies the HOSTS file, this malicious modification can go undetected for a long period of time.

The DNS namespace is a hierarchical, tree-like structure, where the upper layers control and link lower layers. On the Internet, the top-level DNS zones are known as top-level domains (TLDs). Many of the Internet TLDs are well known, such as COM, EDU, MIL, OR, with others such as BIZ and INFO. Each country has its own two-letter domain if some wanted to use them, such as RU for Russia and AU for Australia. DNS addresses are written in reverse order, with the TLD portion always at the right end of a fully qualified DNS domain name.
