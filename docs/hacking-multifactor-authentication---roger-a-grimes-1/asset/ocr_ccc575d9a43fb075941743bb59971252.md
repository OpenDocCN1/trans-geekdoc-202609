# Physical

Many hacking attacks require physical access to the object being hacked. The simplest type of physical attack is the theft of the device MFA solution protection (i.e., stolen phone) or the theft of the MFA solution itself (e.g., someone steals the authentication token itself). This is a denial-of-service (DoS) attack.

But in this book, as it related to MFA, physical attacks refer more to the secrets of an MFA solution be compromised or bypassed by an attacker having physical access to the MFA device. Physical possession is the key to the method to pull off this type of attack. For this category, the attack cannot be done remotely or nearly as easily. Some of the physical attacks require great expertise and virtually, little to no hardware. For example, in Chapter 17, “Physical Attacks,” I’ll detail an MFA attack that requires a million-dollar electron microscope and another that requires only $5 of compressed air. You can’t get any cheaper than that

# Two or More Hacking Methods Used

Many of the MFA attacks shown in this book use two or all of these main hacking methods. Often social engineering is used to start the attack and to get the victim to click on a link or activate a process, which uses one of the other methods to actually accomplish the necessary technical hacking. For example, a user gets a phishing email that directs them to a fake website, which accompanies a man-in-the-middle(MitM) attack, which steals credentials secrets. Physical theft of a hardware token is performed and then the token is forensically examined to find the stored authentication secrets. MFA hacking often requires two or all of these main hacking methods used.

# “You Didn’t Hack the MFA!”

On a related note, learning that many of the attacks against MFA require or involve methods not directly related to the MFA method (say, hacking a DNS entry), many MFA vendors have accused me of being disingenuous in my claim that no MFA can be hacked.\You didn’t hack MFA solution! You hacked something else that I don’t have control over!” My retort is, “Did a user rely on your MFA solution to protect them from hacking? Did you tell the user why they should buy it? And if relying on your solution, was the user still hacked?” Too bad hackers can be artificially constrained to hacking only in specific ways in a lab under controlled conditions the vendor determines the “correct way” to hack!
