Not allowing regular users and programs to run with the highest privileges and permissions (known as root) by default Linux to have a stronger default user security profile than Microsoft Windows. The new default security posture broke a lot of programs, and Linux users had to be retrained in a new way of doing things, but for most it worked. Users complained early, but within a few weeks the complaints stopped and Linux people now know to use sudo when they needed to. After you've used Linux for a few months, you don't even think about it. It’s “muscle memory”—do it without thinking about it.

Because Windows didn’t have a similar sudo command, Windows users were far more likely to run in elevated contexts all the time. Until Vista, Microsoft could easily take a large part of the blame. They really didn't care about the issue or highlight it beyond a list of some general recommendations that no one followed. Microsoft made it easy to run as a non-administrator. In the waning days of Windows XP, some professional colleagues and I decided to follow Microsoft’s advice (and our own advice that had been given for years) and run as non-administrators as much as we could. Turned out it was very hard to do. Many applications broke or had critical errors, and we had to go out and back as administrators all the time to do very, frequently. Logging in and out, and saving all our applications, could take minutes each time. In most cases, our “tests” lasted only a few days to a weeks before we cried and just went back to being logged in as Administrator the time. Microsoft heard our collectives.

While moving from Windows XP to Vista, Microsoft agreed they needed something similar to sudo, many more complex and confusing. Microsoft created a new default feature called User Account Control (UAC). By default, if a user logged in as Administrator (or a member of any elevated group or elevated privileges), UAC would automatically “de-elevate the logged-user’s permissions, and group memberships to that of a normal user. If the user or program needed to run with higher privileges, they would need to approve a logon prompt (by clicking OK or elevating logon credentials) to get to the higher level of access. Overall, even though it looks friendly and easy to use in the picture, I (and millions of others) were not quite fine. Behind the scenes, the way it worked was complex, complicated and clunky; It took me months to figure what it did and how it worked. I did a presentation during this time, and it took me over 100 slides to discuss, in detail, how it really worked. Most people didn't understand it much at all. But even with a thorough understanding most users and vendors hated it!
