# Chapter 2 Authentication Basics

**NOTE** Some single-factor hardware solutions that look like MFA solutions (and people often assume they are) don't require an additional factor. For example, existing versions of Google Security Keys and YubiKeys can be used for one-factor or multifactor. In their one-factor implementations, simply inserting the physical authentication device into a USB slot (and pressing a button) successfully accomplishes the authentication. It also means that if an unauthorized user finds those hardware, they can use them and take over the digital identity associated with the token. It might be more difficult for a hacker to obtain another person's single-factor hardware token than phishing out of a password, but once the token is obtained, that would mean immediate compromise of identity.

Authenticators can be bound to only one location device, or vice can be used in multiple locations and/or multiple devices. For a bounded example, most of the fingerprint scanners you on laptops and phones only on the laptop and where they were registered. So even though my and I both have phones that can be unlocked using our individual fingerprints, my wife's fingerprints don't unlock my, and vice versa, which also could be made to do if we registered again on each other's device. An example of a roaming authenticator might be a Windows Active Directory (AD) login. I can register my AD login credentials anywhere and readily use them at any device registered in the same AD domain/forest. As long as I remember my password, I can use it on any device that can access the website or service.\ Some authenticators. For example, if I have a FIDO device, FIDO/allows a different authenticator for each website and service it is used. Different authenticators all can be stored and used with the same FIDO device. In this sense, the FIDO ID is bound for each site and service. I can use the FIDO device on any FIDO-participating host to log on to those sites and services. The individual IDs are bound to the same FIDO device, but I can roam with it. In general, the FIDO device is to be considered bounded, the authenticators are absolutely bound to a single FIDO device. And if you buy another FIDO device, you can't just easily (or at directly) copy the authenticators to it.\Another similar term is channel binding. Channel binding refers to a unique authentication session being bound to a particular network channel. Without each authentication session being bound to a specific network channel, it is possible for an in-process authentication to be maliciously redirected to another channel. In most cases, authentication involving channel binding (or not requiring channel binding because it's elsewhere in protection) is considered stronger than authentication not capable of channel binding or capable of stopping channel misdirection.
