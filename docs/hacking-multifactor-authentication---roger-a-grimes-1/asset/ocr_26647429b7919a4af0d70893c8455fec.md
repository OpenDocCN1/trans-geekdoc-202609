# Hacking Multifactor Authentication

Some SSO uses use APIs to programmatically interface with applications. Others script-ing to essentially "type" in what the user otherwise do, but faster than the user could it. The logon information or passwords that the SSO uses on behalf of the user may be supplied by the user and created without using the user involved in the process. How they depends on the SSO product. Proxies are technically different in that a user may be prompted for a different password or secret for each login, but the actual logon used to log the user onto the remote location is different from what the user supplied.

NOTE Privileged account managers (PAMs) and password "vaulting" solutions, which are usually very feature rich, are similar to SSO and proxies, many people would not loop them into the same category. But in both cases, you have centralized shared repositories of logon credentials used by others. PAM and vaulting systems would probably require their own chapter to properly cover.

Although SSO programs and proxies are different from password managers, they suffer from the same problems. SSO and proxies are single points of failure. When they go down, the user may be unable to log on any websites and services. A hacker can access all the logon information stored within the SSO/proxy database and compromise all their passwords at once. Essentially, you can take the good and bad of a password manager and just multiply their shared characteristics across the advantages and disadvantages.

Also, the centralized SSO or proxy often has one or more administrators to manage them. That way, the administrator can dictate appropriate policies, configure and troubleshoot to work with the "foreign" systems, and reset logon information if needed. It's a dual-edged sword—that also has access to everyone's logon information, potentially acting as both an additional attack vector or an additional attacker themselves.

# Cryptography

Cryptography is involved in nearly all digital authentication and is often the primary reason the authentication is to be successful. And sometimes it fails when poorly implemented. It is crucial that any reader wanting to understand digital authentication understand cryptography fairly well at a basic level. For that reason, this part of the chapter will be longer and go into more than the other sections.

Cryptography is the science, study, and practice of securing and authenticating people, data, transactions, and other objects between authorized parties. It is done by encryption, integrity checks, and algorithmic implementations.
