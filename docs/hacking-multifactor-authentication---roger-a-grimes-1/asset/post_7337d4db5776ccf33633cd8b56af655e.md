
# Hacking Multifactor Authentication

- Every time the same input is hashed, it should result in the same hash output.
- No different inputs should result in the same hash output. This type of protection is called second preimage resistance.
- If the hash output is, it should be nontrivial for anyone to derive the original content input. This type of protection is officially known as preimage resistance.

A good hash has all these attributes and, even under sustained attack, retains these protective capabilities. Collision resistance is related to and is similar to second-preimage resistance, but they are not the same. And being good at both does not guarantee preimage resistance because they are unrelated attributes. If a hash fails any of these tests, it is considered weak and should no longer be used.

Hash algorithms usually result in fixed-length hashes regardless of the input. Common hash lengths range from 128 to 256 bits. There are many different generally accepted standards over the years, including Message Digest 5 (MD5), Windows LANManager (LM), Windows NT (NT), and Secure Hash Algorithm-1 (SHA-1). All of these standards, for NT, are considered weak and broken. Today, the most popular hash algorithm is Secure Hash Algorithm-2 (SHA-2 or SHA2), although in 2015 NIST recommended that SHA-2's successor, Hash Algorithm-3 (SHA-3 or SHA3), be used because SHA-2 has been weakened over time for cryptographic attack improvements. So far, most people are still using SHA-2. SHA-2 has many different output sizes including 224, 256, and 512 bits. Hashing is often used as part of an authentication solution. Asymmetric encryption, key exchange, digital signing, symmetric encryption, and hashing play heavily into many forms of digital authentication. And if appropriately implemented, cryptography is usually not a weak link in MFA solutions. If poorly implemented, it can create a critical error that undermines the whole solution. # Hardware Tokens

A common type of MFA solution is a hardware device or physical token of some sort. It uses the “Something You Factor” as its core benefit. Usually they are piggybacked with “Something You Know,” but can be used with “Something You Are” (biometrics) or alone (IFA). They are so popular that most of the general public equates MFA with a hardware device of some sort. The hardware devices may display an authentication factor that the user views and retypes into another device's console, or the user may need to interact with the device in some way. Some MFA devices are stand-alone, and some require and work networks. MFA hardware devices can require physical connections, such as plugging the device into a USB smart card or using a wireless connection. The and network connection distances can be local and very limited (i.e., a maximum of a few centimeters) or able to connect and participate with other authentication resources across the globe.

# One-Time Password Devices

Stand-alone hardware-authenticators, which do not need a network connection, are very popular, and have been popular for decades. The most popular of these are one-password (OTP) devices. OTP devices automatically generate a “random” code (which is not random at all), which can be typed in an MFA login screen that is synchronized with a similar process associated with the authentication check.

Usually the user types in a login name or identity code, then provides a code generated by the OTP device as sort of a password. Depending on the OTP solution, another method may also be needed along with the changing code to make a resulting larger code. Whatever code is generated, it is only for a preset amount of time, that will never repeat, and is often not regenerated within a reasonable period of time. OTP devices may involve a hash function and, if so, are known as HMAC-OTP or hash-based OTP (HOTP) devices.

The security theory behind an OTP device is that if an attacker learns the code, code can be used for a preset time and will never be used or generated again. Thus, time-limits the amount of damage that can be done of a simple compromise. Most OTP devices generate new code changes on a preset time schedule (every 30 seconds, a minute, every 5 or 10 minutes, once an hour, etc.). When an OTP device generates a new code based on involving the current time, it is known as a time-based-one-time-password (TOTP) device. The key difference is that a HOTP device will change the code at a preset period of time or event but doesn't actually use the current time in the calculation, whereas a TOTP actually uses the current time value in the calculation to generate a new code.

Some OTP devices key off a particular event or action and are known as event-one-time-password (EOTP) devices. Most EOTP devices have a button that the user clicks. The button click generates a new number, which is used in the OTP code generation. Often the button click seriously advances a counter in the EOTP device. In these instances, the counter is used in the OTP calculation.

OTP devices have globally unique identifiers (i.e., serial numbers) that are hard-coded into the device and also stored in the backend authentication database. A seed is randomly generated by the device and/or database shared with the other. Then the seed value and supplied information (possibly including the unique identifier) are used with a documented algorithm to generate future codes. TOTPs are very popular and have been in use for decades. Probably their one usability drawback is the limited time a user has to access and view the code on the TOTP device before another code must be used. Every TOTP user experiences the anxiety of failure when they are too late and the authentication is rejected.

Other downsides include that TOTPs are relatively expensive versus other MFA solutions. In modern times, many MFA solutions involve plugging an authentication device into the base computing computer's USB port. Nearly every computer and laptop has multiple USB ports, USB-based authentication devices have been popular for at least two decades. USB-based authentication devices may need to be plugged in to boot up a device, to unlock an encrypted hard drive, or to authenticate to participating sites and services.
