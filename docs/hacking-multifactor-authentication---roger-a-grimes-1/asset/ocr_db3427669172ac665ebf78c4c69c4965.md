# 24 Hacking Multifactor Authentication

A challenge-response session makes it harder for an attacker, because they can't "sniff" the network and get a plaintext response right away. With a complete challenge-response session, the only unknown variable between the challenge and response is the password hash. So, if an attacker can get both sides, the involved password hash can be easily computed.

# Email Hash Theft Trick

It's also possible to steal passwords remotely one at a time in some uncommon edge cases. For example, one very interesting method involves sending a phishing attack to an intended victim. The email contains an embedded Universal Name Convention (UNC) file moniker link, file:///URL link. Emails usually connect Uniform Resource Locator (URL) links and file monitors like http://. The fact that the email contains a UNC file moniker, which is normally associated with local NetBIOS connections, confuses many email clients, and they can be tricked into connecting to any referenced remote (often malicious) server and resource. The remote server can state to the connecting email client (which is often a browser) that it requires the client to authenticate the access referred to by the UNC/URL link (example: file:///bad.com/anyfilename.html).

The email or browser client, if it supports Windows Authentication (Windows, Mac and Linux clients usually do connect to Windows networks), will automatically, unbek to most users and attempt, authenticate with the server holding the remote resource. The client will participate in a challenge-response NTLM authentication connection session, and from that a rogue server can drive the user's password hash. Here is a great discussion on the overall technique: www.securify.in/blog/SFY20180501/living-off-the-land-stealing-netntl-hashes.html.

To summarize, an attacker can send an email that the victim simply opens, or most clicks on the embedded link, and the remote attacker gets the victim's Windows password hash, which they then convert to a plaintext response. Infamous hacker, boss, and my friend, Kevin Mitnick, has a YouTube video demonstrating this attack method: blog.knowbe4.com/kevin-mitnick-demos-password-hack-no-link-click-or-attachments-memory.

> NOTE Kevin's video he demonstrates "previewing" the email is to kick off the connection to the embedded UNC/URL link resource, but most of the time users will be tricked into clicking the embedded link (i.e., the connection doesn't initiate automatically). Still, tricking people clicking on malicious links is not all hard. In fact, it's how phishing emails work.

Without converting the hash to its plaintext equivalent, there is lot a hacker can do. The attacker can create additional logon sessions, log on remotely to access RDS sessions, manipulate group memberships, connect to network drives and resources, and even create brand-new, temporary, rogue domain controllers (look up "golden ticket" attacks—they are vicious).
