The TOTP return will be the same code every time measured during the same 30-second Epoch cycle. Every 30 seconds a new code is generated and is only good for 30 seconds, although it appears that a second or two is after the expiration period to account for a user typing in a just-coded space. The TOTP code can be typed in sequential digits, although it is often displayed and may be taken as two different of numbers separated by a space.

There are dozens of vendors creating OTP, HOTP, and TOTP MFA solutions, using hard-coded and soft tokens. In the world of MFA, TOTP-based solutions are hot. Microsoft also uses a TOTP soft token known as Microsoft Authenticator (docs.microsoft.com/en-sg/azure/active-tokens/directory/user-help-auth-app-download-install). It, too, can use a QR code, as one of few different methods, to communicate the initial seed.

As great as they are, OTP and TOTP solutions are not hackable.

# Example OTP Attacks

Like everything in the world, OTP MFA solutions can be attacked and hacked. This section examines some methods and examples.

# Phishing OTP Codes

Without a doubt, one of the most common ways to hack OTP-based MFA solutions is for the hackers to phish and intercept the resulting codes, especially if all that is needed to log on is the account identifier and the OTP code. The OTP code is essentially just replacing a password as the secret needed to get in.

The most popular hacking method to get the OTP code is similar to what was shown in Chapter 6, "Access Control Tokens," with the Kevin Mitnick hacking LinkedIn Video. The attacker somehow convinces an OTP-based MFA user to use a rogue, lookalike website that is functioning as a man-in-the-middle proxy site between the victim and their intended destination. Everything the victim types is proxy to the ultimate server/service, and everything from the real server/service is proxied to the user. When the user is prompted to enter their OTP code, the hacker grabs it and uses it to log on the real server.

With HOTP tokens, a hacker could trick a user into inputting valid, sequential HTOP codes. Maybe they create a simulated logon page that asks the user to log on. The user types in their current HOTP code, and the fake website returns an error and asks the user to type in their next HOTP code, which the fake logon website then records.
