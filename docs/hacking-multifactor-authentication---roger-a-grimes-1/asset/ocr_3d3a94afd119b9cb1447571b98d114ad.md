# # Educate About Dependency Abuses

Educate everyone, developer and customer, about possible dependency abuses. For example, in the dynamic access control example earlier, would everyone suddenly realize that the Department and Country attributes were not used for making access control decisions? Did anyone put stronger security and monitoring around those fields? Users should be educated about any threat models that the developers have defined, how they are minimized, and what risks remain.

I can think of no better example than the FIDO Alliance's Security Specification document (fidoalliance.org/specs/fido-v2.0-id-20180227/fido-security-ref-v2.0-id-20180227.html). Every MFA solution is so forthcoming and it covers each as shown in Figure 10.7. I think all readers reviewers will have more faith in a solution that does good threat modeling and is not afraid to show known risks and the mitigations and the steps they have taken to minimize them. This document gives increased faith in the family of FIDO solutions.

# ## 3. Attack Classification

The following attacks all result in user impersonation if successful. However, they have distinguishing characteristics which we use as the basis of

+   1. Automated attacks not focused on users systems, which affect the user.
2. Automated attacks which are focused on the user's device and which are performed once and lead to the ability to impersonate the user or
3. Automated attacks which involve the user or their device for each successful impersonation.
4. Automated attacks to sessions authenticated by the user.
5. Not automatable attacks to the user or their device which are performed once and lead to the ability to impersonate the user on an on-going
6. Not automata attacks to the user or their device which involve the user or their device for each successful impersonation.
