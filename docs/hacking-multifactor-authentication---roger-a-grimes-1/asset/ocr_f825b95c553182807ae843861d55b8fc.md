# Authy API Injection

Authy is a popular MFA vendor. In 2015, a security researcher found out Authy's MFA initial token response to a new connection did not encode user parameters of the token (sakury.com/blog/2015/03/15/authy_bypass.html). This allowed an attacker to supply any valid token user's ID, after the original user started there, to log without MFA. Auty traced the vulnerability back to a dependency called Sinitack "rack protection." Turned out other MFA vendors also had the same dependency and were susceptible to the same bug. The researcher also found a traversal attack (covered in Chapter 15, "Buggy Software") to throw in for. To quote the researcher, Yes, the attacker was able to bypass 2 factor authentication on any website using Authy as simple as ...sms in the token field!
