# 246 Hacking Multifactor Authentication

Microsoft has so to come up with security solutions that cause no problems or at least the least numbers of problems possible for the risk being mitigated. Using too many problems could lead existing customers to use other platforms that don't have as many issues. It is something Microsoft worries about each security decision. Many times, otherwise great solutions had to be shelved because they caused too many end-user problems. The security risk was so big that Microsoft decided to implement the solution if they could. And a few times they implemented a security decision intentionally knowing it was going to cause a lot of issues and anger. In fact, it was the unintended intent, but the risk they were trying to make that important.

During the creation of Windows Vista, one of the big problems was that despite Microsoft's best efforts to control, too many users (nearly all) were constantly logged out all the time as the fully permitted and privileged Administrator-so much, most programs (nearly all) expected to run in that context. Nearly all the time, most users and programs were running with the highest level of permissions. It was a fact that hackers and malware loved to abuse. When a malware-program or hacker "takes over" a program, they get whatever access the user and/or-that's what permissions the malware or hackers get when they break in. And at that level of elevation, they can do anything while using the software and hardware. It's a hacker's dream scenario.

In the Linux world, most Linux versions (called distributions, or distros for) short to run all users and programs in a less privileged mode by default and require that all users and most programs intentionally elevate themselves if they needed elevated permissions. This is often done in Linux using the sudo (super user) command. Figure 11.1 shows sudo in use. With the first command, without sudo, I tried to open and view the Linux password file called shadow. Without sudo, I was denied. With the second command attempt, I added sudo to the beginning of the command and was prompted for a root (like Administrator in Windows) password and the file opened. This is a common example, where a user attempts to run something, it fails, and the users remember have to add sudo to the command to make it work.
