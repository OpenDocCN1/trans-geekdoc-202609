# Keyboard Eavesdropping

For decades I have read studies conducted in a laboratory in which an "attacker" could record the sounds of keystrokes on a keyboard and later determine which keys were struck. There are two early studies on the hacking attacks: www.davidsalon.name/CompSec/auxiliary/KybdEmanation.pdf and www.csnell.com/sshat/courses/cs6431/zhuang.pdf. In one of the papers, the authors describe being able to recover 96 percent of keystrokes typed in over a 10-minute period. In another study, someone typed eavesdropped if they were using Skype (spritz.math.upid.it/projects/dst). Acoustic eavesdropping even works with smart keyboards (koddos.net/blog/hackers-detect-passwords-from-the-sound-of-keystrokes). Wireless keyboards and mice can be eavesdropped wirelessly, even if the communication is supposedly encrypted. You can read about it here:

+   * thehackernews.com/2016/02/mouse-hack-computer.html
* www.computerworld.com/article/3101006/keysniffer-hackers-can-snag-wireless-key-board-keystrokes-from-250-foot-away.html
* blog.emisoft.com/en/12317/keysweeper-proof-that-is-relatively-simple-to-hack-a-wireless-keyboard

So, if your MFA solution involves typing something into a keyboard there is a chance someone could record your typing and replay keystrokes. I have heard of a real-world attack that used these methods, but a nation-state attack force might have such capabilities.

# Password Hints

Many software and phone-based MFA solutions are ultimately protected by a login name and password. Once the user logs on, the user can continue to use the MFA solution in perpetuity or for some interval of time. But logically it means the solution's strength is tied to login name and password.
