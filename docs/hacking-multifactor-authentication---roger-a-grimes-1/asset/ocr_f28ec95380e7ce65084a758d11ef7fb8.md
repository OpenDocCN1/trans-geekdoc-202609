But knowledgeable hackers can register WPAD on their local DNS servers. For example, they can name their Windows computer WPAD and reboot. When they do this on a Windows network, most DNS servers will automatically register their WPAD hostname and IP address in the local DNS servers authoritative for the domain. Any other computer on the same network or using the same DNS server asking for WPAD will then be given the IP address of the hacker's computer. All the hacker has to do is set up a proxy server (many free proxy services are available download on the Internet), and they can start stealing all the victim's traffic to their computer or to other locations. It is a dastardly tactic.

Corp is involved in this namespace collision example as well. Microsoft released Active Directory, their primary network name, in 1999. AD uses DNS as its primary name service (along with NetBIOS and LDAP), and using Active Directory has to set up their network using DNS conventions. Not any AD administrator understands DNS servers well, and for a decade, tens of thousands of legitimate instructors used the corp.com domain as example when telling others how to build or configure something, including Active Directory. As a result, tens of thousands of private domains have corp in their Active Directory name (e.g., roger.corp.com). Before any network were connected to the Internet full, this was a problem. But the corp.com part of the address started to cause a name collision. If one (or more likely, a computer or program on my behalf) looked for we on roger.corp.com network, the way DNS resolution works, the hostname of we would be looked for not only roger.corp as well. Someone owning corp.com could end up causing a lot of havoc if they wanted to.

For a decade, a single American private citizen actually owned the over 375,000 computers were trying to find his domain information it did not request. One day, as a nonetheless test, the user set up an email server "answering" in the corp.com domain to see what would happen. Within an hour, he had over 12 million emails sent to the server. Many of these emails contained confidential information. The owner understood the problem well, and he eventually sold the corp.com domain to Microsoft for $1 million. Kudos to the owner and to Microsoft. The man did not have to sell the valuable domain to Microsoft and Microsoft didn't have to spend $1 million because people didn't understand how DNS worked on Active Directory networks.
