# Chapter 10 Subject Hijack Attacks 235

**Figure 10.10:** Help Desk user's smartcard certificate

The "hack" is the Help Desk user changing the Super Admin's UPN to `helpdesk@victim.com` so when the Help Desk user logs in using their smartcard with a UPN of `helpdesk@victim.com`, AD maps the Admin's account to the Help Desk user's login. To do this, he must first rename Help Desk's UPN to almost anything (`frogtemp@victim.com` in this demo) because there are two UPNs with the same values (i.e., `helpdesk@victim.com`) at the same time in the same AD forest. So, by renaming the Help Desk UPN to something else, the Help Desk user can rename Super Admin's UPN to `helpdesk@victim.com`. This sequence of steps is illustrated in Figure 10.11.

After the UPN change, the Help Desk user must log out and wait for the account change to replicate across Active Directory so that all account databases get the new change. This can take up to 10 minutes (or longer) in some environments, but often takes only 1–2 minutes. At the very least, the UPN must be replicated to the Active Directory domain controller helper the Help Desk user is logging on.

Then all the Help Desk user logs into Windows and Active Directory using their smartcard and PIN (as shown in Figure 10.12). During the logon, anyone watching in real time would see the Help Desk username suddenly change to Super Admin a split second before the logon screen goes away to reveal the successful logon.
