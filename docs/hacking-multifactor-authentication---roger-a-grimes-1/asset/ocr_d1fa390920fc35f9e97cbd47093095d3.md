The "official" term to describe password randomness is covered by the entropy. A password's entropy is a measure of its randomness. A truly random password—might be picked by a password manager, say #kF&Bn1A—is considered to have high entropy. Most humans pick, like Frog1. Low-entropy passwords are considered to be easier to guess and hack with high entropy. High-entropy passwords are harder for humans to create, remember, and use. But if we use only high-entropy passwords, password guessers and crackers would have much harder time seriously compromising them.

NOTE The longer a password is, even without special characters or using a longer password, use a longer password. It will provide more entropy protection and will be easier to remember and use (for humans).

# Password Storage

Passwords can be stored in their plaintext format as exactly typed in, but they can also be slightly modified in ways the user may be unaware of. For example, especially in older password systems, all alphabetic characters, whether in uppercase or lowercase, will be converted and stored in a single case. Or overly long passwords would be silently truncated. The user may think they are using a very long and hard-to-crack password, not aware that the system only cares and stores the first six characters.

The location where the passwords are stored may be on a local file or stored in a network location, stored in one or more cached locations (on disk or memory), other non-file locations (like the Windows registry or memory), or a combination of two or more. Passwords or their subsequent representations (covered more in a moment) can be stored in multiple separate databases, appear distinctly, and be used in different ways in each location.

It's important that wherever identity and password information (and all required attributes used in authentication and authorization) be stored in secure locations. If an attacker can access the authentication database, wherever it is stored, it's game over! Most authentication databases and storage locations can be accessed only by highly privileged administrators.

# Password Hashes

In most of today's password authentication systems, any typed-in are immediately converted to another non-plaintext representation. These representations are the result of cryptographically hashing the plaintext password. Cryptographic hashing algorithms return a consistent, but unique, output for any unique input. For example, if you type a password of frog (the SHA2) hashed output is 74FA5327CC04E94789DD5E989A6A82986A596F17064AC90337B1DAEE4. And it will be the same every time you type in frog (without an additional salt).
