# Select a Winner

You've reached the end of the first part of your long journey. If you are using points scoring, have everyone rank the solutions from best to worst and pick the winner that makes more people happy than all the others. It is good etiquette to let the losing vendors know why they lost. That information can help them improve their solution.

# Deploy to Production

Now's time to roll out the solution. I'm a big believer in baby steps, if that is possible, don't make an implementation plan where the old authentication solution is all that can be done and the next one new method can be used. It is best to do side-by-side runs if possible, opening the new MFA solution to more people and departments as time goes on. A trickle-in methodology is possible, rarely will you regret it. I have regretted replacement, "go-live" projects where something went wrong was not detected in the pilot project and other testing a critical system down. Save yourself the heartache and frustration. Try to move from one authentication solution to stages, increasing the number of people involved and impacted time.

Be sure to update your policies and account for the new MFA solution. Provide training to IT, help support staff, train-trainers, trainers, and end users. Continue to keep your eyes and ears out for developing MFA trends. MFA is constantly improving. Most MFA solutions end up having significant improvements (or being bought by another company) every few years. Don't be surprised if the MFA solution you select has another name or owner within a few years you buy it.
