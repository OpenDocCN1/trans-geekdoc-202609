# AuthO MFA Bypass

Auth0 (auth0.com) is a popular authentication vendor offering MFA solutions. Their API auth0.com/api/authentication uses OAuth, OpenID Connect, REST, JSON, and SAML. Auth0 MFA users use this API when they authenticate using an Auth0 MFA solution. The API uses a JSON web token standard (JWT), and tokens can assert claims (as 'I'm MFA and I'm using this for my digital signatures').

The issue is that the JWT standard allows a digital signature algorithm value (alg) of None

It's also good in dependencies. The initial problem wasn't Auth0's. Auth0 responded to the initial report by looking for and reportedly treating any JWT message with an alg value of None. Problem solved, right?

No. In April 2020, another person discovered (insniac.com/blog/auth0-jwt-validation-bypass) that Auth0 treated an alg value of None correctly, but any other case-sensitive value (i.e., none, nOne, nONE) would be treated as a valid JWT value of None but not subject to the offset, offsetting mitigations.
