Regardless of how you used to authenticate, the resulting access control token is usually the same. It formatted the same. It looks the same. It is treated the same. There are some edge cases where you authenticated could impact the token, and some of the contained claims are different because of how you authenticated, but most of the system there is little or no difference.

Let me explain by an example. Suppose you log on to your Windows laptop using a name and password. When you log in using a biometric fingerprint, you get an access control token. And both are identical or close to identical. In most systems, the process of authenticating and the process of getting the authentication token are essentially unrelated events. The system component giving you the access control token doesn't really care how you authenticated, only that you successfully authenticated. Regardless of how you did, here's your resulting access control token. In the access control system's view, both tokens are identical. Both are used the exact same way behind the scenes to access protected information.

Before I understood this correctly, I thought that different authentication methods created dramatically different access control tokens. For example, I believed that if you logged on using a fingerprint, however fingerprint was used in authentication and authorization comparisons behind the scenes. Suppose I wanted to access a database file that had legitimate access to. I imagined that when I went to access that database file the access control process somehow took my fingerprint and used it in an access control comparison to see if I could access the database. I imagined there were some sort of "smart" in the system that would look at my fingerprint and go "Yeah, looks like right, get him out! That's not at all what happens.

Instead, when I successfully authenticate using my fingerprint (or password or smart card key), what happens after I successfully authenticate is identical for all successfully authenticated users. And this is an important point, especially when added to the previous fact that possession of the token is usually treated the same as the subject that had successfully authenticated. Regardless of how I authenticated, if my resulting access control token gets compromised, it's game over. We'll come back to this in Chapter 6, "Access Control Tricks."
