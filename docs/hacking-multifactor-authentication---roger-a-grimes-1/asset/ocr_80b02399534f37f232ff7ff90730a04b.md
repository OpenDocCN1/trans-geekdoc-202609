# Simulated Demo Environment

To demonstrate this simulated hack, we are going to consider two users in the same Active Directory forest victim.com for this example. One user, called Super Admin, is a super administrator with every possible right and permission in Active Directory. Super Admin belongs to highly privileged group, including Schema Admins, Enterprise Admins, and Domain Admins. For all intents and purposes, Super Admin is an all-powerful "god account" of the network.

The second user, called Help Desk, is a regular user with no special permissions or privileges beyond of a regular user except they have the ability to change user UPNs. They do not have elevated group memberships. Both users have valid smartcards and must use those smartcards to log on their computers and Active Directory. For the simulated attack, let's assume that the Help Desk user decides to steal the Super Admin's credentials and do something malicious he is not capable of doing with his regular permissions and privileges.

> Microsoft goes to length to protect who has permission to modify the UPN value, by this demo attacks the Help Desk user has the ability to write this value (as do other admins). In my demo I give the Help Desk user only one extra permission to demonstrate the power of one small change on one field.

The rest of the demo will be a series of narrated steps and pictures starting with the Super Admin logging on to their computer as they normally to demonstrate what a regular login looks like.
