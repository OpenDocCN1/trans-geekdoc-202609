# 36 Hacking Multifactor Authentication

Essentially any predefined label has been agreed on as the unique identifier can be used. Identity labels can be made by registering users, or they can be automatically assigned by the system. A single subject may have multiple identities on the same system (also known as personas), and multiple subjects may share the same identities (although this is frowned upon in computer security circles) on the same system. Different identities, belonging to the same subject, may have different attributes, permissions, and privileges. For example, an administrator may have a regular user account for everyday, regular user-type computing tasks (such as reading email and browsing the Internet) as well as an elevated admin account when they need to perform actions requiring privilege.

Many subjects have different identities in different systems. In fact, for users that's highly common, the average adult can easily have up of a hundred separate systems they log on, each having a different identity system. Separate systems often separate, isolated authentication systems, but they may share and interface with a common authentication system.

Although it is common for subjects to authenticate to a system to begin their computing experience, after that login the remaining interactions with the various future processes are done automatically using the subject's identity or access control token (which we cover in a moment). The process of other software and processes using another subject's identity is known as impersonation or delegation. The software or process that does the impersonation is known as the user agent.

For example, when the typical user browses the Internet, the user's browser is often running in context the authenticated user. If the user is working in an email client, the email client is the user agent. When a user opens a word processing program or accesses their own stored document files, the word processor is considered the user agent, and the processes to access the user's access-controlled documents are done by the word processor using impersonation of that user's identity.

It is common for a computer system running many different processes to be running processes using different identities, some of which belong to the user and others that belong to the operating system or other previously installed applications. A single process can choose which identities they use for particular actions. For example, when you browse to a website authentication, an browser, by default, will usually try to log on as "anonymous" user three times, and only after rejection each time, try to log on the subject identity that started the browser. And if the website and browser prompts you to manually supply logon credentials, it is possible for the user agent (i.e., the browser) to "spawn" another process using another identity. With operating systems, it is not unusual for a parent process to spawn a child process, and typically, by default, that new process will have the same subject identifier (although it can be another separate identity).
