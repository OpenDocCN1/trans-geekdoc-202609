Early on, OTP creators used algorithms and their own methods to create their seemingly random-looking OTP codes. Unfortunately, creating secure OTP codes is really hard to do. # HMAC-Based OTP

Enter hash-based message authentication codes (HMAC-based OTP, or HOTP). Cryptographic hash algorithms (also known as hash functions or hashes) are used to create unique output results for every unique input. In our discussion, the unique input would be whatever values the OTP solution supplies as part of the initial code calculations (i.e., see and counter values), although in circles it would simply be known as the message to be hashed. The hash output after the 'hashing' is known as the message digest, hash result, or simply hash.

A secure, trusted has four important traits:

+   - For every unique input, a unique output must be generated.
- Every time the same input is hashed, it should result in the same hash output (i.e., a collision).
- If two different inputs result in the same hash output, it would be impossible or near impossible (known as nontrivial in the crypto world) for anyone to derive the original content input.

A good has has all these attributes. Hash algorithms usually result in fixed-length hash results regardless of the length of the input. Common hash lengths range from 128 to 256 bits.
