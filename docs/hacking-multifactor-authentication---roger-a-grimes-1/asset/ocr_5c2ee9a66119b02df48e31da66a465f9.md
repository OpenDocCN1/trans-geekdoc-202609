# 418 Hacking Multifactor Authentication

In the computer security world, fail open means that something doesn't work, ignore it or just proceed as if the action worked. In this particular scenario, it says "If the Duo API URL involved in this authentication transaction cannot be contacted, don't require MFA to log on."

Fail open configuration are not thought of highly in the computer security world. And if fail open option is the default option, it likely even even. Many people who install software all the default options. The average person installing software just clicks Next, Next, Next. They assume the vendor made safe choices for them. Users even get warnings from some software programs if they change a default option to safer. They worry that their change could cause operational interruption. Why understand Duo Security choose a default open, because they don't want an administrator to log on to one of them (Duo) servers because there is not a network problem or the API link involved (it's different per instance) is down for some reason. Instead, they wait the login to proceed. The user (or hacker) still needs to provide a name and password in most cases. And the risk is very minimal. On top of that, if a particular user is concerned with the risk they can change the default option. It's a win-win.

But if an attacker (insider) knows about this feature, they can bypass the MFA requirement by creating a connection between the computer being logged into and the API connection point. Before Duo had their "offline login" feature added in late 2018, bypassing Duo's MFA requirement could be as easy as unplugging a network cable. But unplugging is a physical attack and requires physical access to the device or network attacked. Network interruption can also be accomplished quickly.

This was first brought to my attention by this article: www.n00py.io/2018/08/bypassing-duo-factor-authentication-fail-open. The penetration tester came up with a few ways to cause a connection problem that already having local access to the server. They began the question: does a local attacker attack a targeted server to bypass MFA in the first place? Well, there is a chance they have some sort of access (say, using Microsoft's PsExec utility), but they want access using a GUI console (say, Windows Remote Desktop Protocol (RDP)). They could leverage their non-console access as a way to bypass the Duo MFA requirement.

If they have local access, they can "poison" the target's DNS service by creating a DNS entry that redirects the Duo API URL link to somewhere else. If the Duo connection fails for any reason, it fails open. The penetration tester also suggested using a MitM network attack, where the target's Duo API URL is captured on the network and replaced on the fly, to do the same thing. I can with admin access to the victim's DNS server create a bogus API link link address so that when the victim tries to connect, it would get a fake IP address. Another attack method could take place anywhere the target's network connectivity is interrupted; an attacker could attempt a DDoS attack against the target's network connection so that a valid response from the Duo API URL link never gets received.
