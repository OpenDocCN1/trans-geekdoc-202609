# Hacking Multifactor Authentication

RSA SecurID I don't know if RSA SecurIDs (see an example in Figure 9.1) were the first hardtoken TOTP-based MFA, but they have been around for decades. For many of us long-term, experienced computer security users, a SecurID was the first-token MFA device we had ever seen, and of the time, the only TOTP device we had used. If it wasn't, it was one of the most popular. The little parallel bars on the left-hand side of the token device were countdown timer bars. By by one, they went away as the time for the current TOTP code expired. When they all went away, a new code with a full set of bars would be displayed and the timer and countdown bars would begin all over again.

The RSA SecurID Wikipedia page (en.wikipedia.org/wiki/RSA_SecurID)—yes, it has its own Wikipedia page—says that in 2003 they commanded 70 percent of the MFA market. RSA themselves claim that 93 percent of Fortune 500 companies used one of their products, although that figure includes both hard-token and software solutions.

Early on, most implementations required that a user in a static set of characters that only the user and the authentication system know, in combination with the newly generated TOTP code portion. Eventually this requirement was relaxed or made optional that RSA could provide a more seamless experience, as some of their competitors required the TOTP code and not the combination of both the static password and TOTP code. Requiring both the static code and TOTP is a more secure method, but frequently in the computer security world, higher security requirements are often relaxed to make a better user experience. RSA SecurID and other RSA remain among the top, most popular, MFA solutions today, although there is a lot more competition now.

**Google Authenticator** Giving RSA a strong run for its money, or perhaps surpassing it in popularity now, is the Google Authenticator, created in 2010.
