# Cache Poisoning

Another less common DNS hack today is DNS caching poisoning. As discussed earlier, when a computer gets a DNS query answer, it will cache the answer in memory for a set period of time. Normally, only a DNS server that is authoritative for a particular domain can return a particular DNS query answer (e.g., only KnowBe'4 legitimate DNS servers can return answers for any host located in the knowbe4.com domain).

But misconfigured (or older) clients and servers will sometimes accept answers for DNS hosts that were never requested and cache them for future use. For example, a user clicks in a phishing email, which takes them to a rogue domain. If it exists and works, it will be on a particular DNS server. A phisher can trick their DNS server to return not only the IP address for the rogue domain, but also a rogue, malicious IP address for google.com (the user did not request). The DNS client gets tricked into caching both responses in memory. The user, unaware of the DNS cache poisoning, might be directed to a fake Google site on their next query.

DNS cache poisoning were super popular, but they did occur. Over a decade ago, Microsoft DNS servers and clients prevented DNS poisoning (by default), and BIND stood for (not allowing DNS servers to serve for domains not in their authority). Because the two biggest DNS servers and clients in the world periodically prevent DNS caching, cache cache poisoning died in a long time ago. Still, you will occasionally cache across a DNS server or service that is susceptible to cache poisoning, as in home Internet modems or routers, so you will still hear about these types of attacks occurring in rare instances and scenarios.

# Name Collisions

Most namespaces have "reserved" names, which refer to specific services or objects. For example, on Windows systems at the command-line prompt, you cannot create files or folders with the name of AUX, CON, or LPT1, or CON2, because they are reserved words that refer to specific objects or handles used by the operating system.

There are also words that mean something in one namespace can conflict or be used with objects or words in another namespace. These are known as name collisions or namespace collisions. Let's look at two common, real-examples.

# WPAD

A dangerous, easily hackable name collision that isn't well known by the general public is the WPAD (Web Proxy Auto-Discovery) protocol. WPAD allows Windows and Microsoft applications to automatically discover proxy settings that applications (like Internet Explorer and Edge) can use to connect to the Internet. Microsoft intended WPAD to be used as a way to help Windows computers connect to the Internet easily without having to manually hunt down the proxy settings and enter them. Every Windows computer and related applications will generate WPAD-enabled applications generate DNS queries for the location for WPAD. Most networks don't use WPAD, so the query gets ignored and receives no response.
