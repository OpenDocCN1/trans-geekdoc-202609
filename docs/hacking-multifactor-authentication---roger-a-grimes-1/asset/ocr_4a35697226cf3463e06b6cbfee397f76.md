# 380 Hacking Multifactor Authentication

Subdomains (such as knowbe4.com) and their devices are hosted by lower-layer DNS servers. Each DNS server hosts its own domain(s) or points to other DNS servers in other domains that have their resolution information. DNS servers that are the "owners" of a DNS registration record (i.e., hostname to IP address) Every device that can directly access from the Internet is registered on one or more DNS servers within its domain by its hostname and IP address. For example, the www in www.knowbe4.com refers to a DNS hostname within the knowbe4 domain that falls under the TLD.

DNS servers provide services to DNS clients. DNS clients point to DNS servers to ask name-to-IP address queries. A server can be both a DNS server and a DNS client. The major majority of devices connecting to the Internet are DNS clients, asking DNS servers (which are naturally fewer) DNS queries. For example, when someone on the Internet types www.knowbe4.com on their computer to look for the KnowBe4, Inc. website, their computer and DNS client typically do a DNS query that looks like

+   1. It checks to see if the IP address of www.knowbe4.com is already cached in memory from a previous query.
2. If not, the application/OS checks the local HOSTS file.
3. If it is not located, the DNS sends out a single DNS query to its locally defined DNS server essentially asking, "What is the IP address of www.knowbe4.com?"
4. The local DNS server returns the IP address if it is already cached in its local memory from a previous successful query, and if not, may or not check its own HOSTS file.
5. The DNS service checks its own DNS database if it is authoritative for the domain (i.e., knowbe4.com) being requested.
6. If the DNS answer is not in either location, or if DNS server does not respond, the server attempts to ask another DNS server to resolve the query or directly connect to the "root" DNS servers.
Most DNS servers are configured with a list of 13 root DNS servers (www.iana.org/root/servers/), which then point to the TLD DNS servers that are authoritative for the TLD domains. Most of the time, because of previous queries, at least a few of these are already cached in memory.

8. The root DNS server returns one or more IP addresses of TLD DNS servers for the TLD.
