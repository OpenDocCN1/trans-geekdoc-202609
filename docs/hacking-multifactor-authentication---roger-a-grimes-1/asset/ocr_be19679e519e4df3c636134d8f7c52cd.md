Another common XSS example is an example of what is called a reflected XSS attack. An attacker sends you a link that looks like any link you would click on and use to visit a website. Unknown to the user, it has additional commands to the end of the link that executing extra, malicious content. For example, you link to connect to a website that looks familiar to you, but the link not only goes to that website, but also abuses a feature of that website allows users to be redirected somewhere else. Here’s an example: www.reddit.com/r/sysadmin/comments/d9dnf/heres_a_phishing_url_to_give_you_nightmares/. In this instance, any user connecting on have been redirected to a website of the attacker’s choosing (before the bug was corrected). An attacker would usually redirect the user to a look-alike website and then get them to download trojan Adobe software.

Defending against XSS attacks relies on any program that can accept and display scripting or coding to ensure that the scripting or coding is always displayed like regular data or writing and not executed. For example, web application developers need to write or use mechanisms to sanitize inputs by looking for and removing “escaping” characters that often get used to indicate to a browser that a script or piece of code is involved or being injected. In general, developers should always sanitize inputs to ensure clients only enter the specific type of data required for that particular input. Nowadays, programming tools use sorts of input sanitation controls built in, but they aren’t always enabled by default and it’s up to developers to take advantage of them.

# Directory Traversal Attacks

Directory traversal attacks are a vulnerability where an attacker tries to navigate to otherwise security-protected directories, files, and folders without supposedly being allowed to go to those locations or the parent folders. A good, super-simple, example is suppose that I can get to the folder C:\child when I’m not allowed to get to C:\ or C:\parent. Simply having and using the full pathname (i.e., C:\parent\child) allows me to bypass the parent directories I had less permissive access.

A real-life example of a common hacker directory traversal bypass test string is ../ or something like that. The forward slashes represent folder subdirectories and the dot-dot (...) represents a parent folder in many operating systems.
