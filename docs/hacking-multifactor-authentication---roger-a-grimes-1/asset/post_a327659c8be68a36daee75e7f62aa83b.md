> - I forgot my B-Unit, Can I still access the Bloomberg Professional Services software?

Yes. Your Bloomberg Terminal, when prompted for B-Unit code, click "Log Assistance" in the bottom-left corner of the window, click "Request an order" and follow the instructions. If you log into BIA, click "Log in with your B-Unit" and follow the prompts.

Bloomberg users with supported Android phones can access the Terminal via the B-Unit app. For more information about how to download the app and get started, visit https://www.bloomberg.com/professional/product/b-unit-app-android.

## Mobile Versions Have Less Security?

I don't know for sure, but this public link (mb_bliproessional.com/m/android) seems to suggest that users can use a different "token" mode (see Figure 21.7). From what I could learn, this appears to be a secondary B-Unit OTP mode. Other information found online I could enter a password or token code.

This begs the question: if the token code is an OTP code (which is likely), how likely is it that could be cloned, reused, or used in another of the attack methods shown in Chapter 9, "One-Time Password Attacks?" Help documentation also states that the code would be needed only the first time when using a mobile solution, seeming to suggest that after it is entered the first time, the user's mobile device is being treated as the MFA device (instead of the B-Unit). Well, compared to B-Units mobile phones are distinctly easier to attack and “powned.” A hacker getting one token code could perhaps create a second Bloomberg Anywhere instance that the victim does not know about (although I read that when an individual is using their mobile device, the Bloomberg Terminal service can lock out or the other instance, depending on the devices involved). I wonder why mobile devices are not forced to use B-Unit authentication. If there is a reason, it might reveal an additional exploitation to pursue.

## Possible to Get a Second Unit?

Bloomberg Anywhere explicitly states (as shown in Figure 21.8) that a user cannot have two B-Unit devices. This is a secure, good policy. I applaud Bloomberg and their excellent security for it.

![](img/c78b0f79db62998ee317a35df5629d85_461_1.png)

Figure 21.8: Bloomberg policy statement that a user cannot have two B-Unit devices

In other help information, Bloomberg offers scenarios where a legitimate user can get a second unit, such as when a user’s first unit is displaying a low-battery message (www.bloomberg.com/faq/question/my-b-unit-is-displaying-a-low-battery-message-what-do-i-do-2). When that happens, a user can order a second unit. The question is if Bloomberg is strict about allowing only one device to be enabled at one count at time. Likely this is the case. As a professional hacker for 30 years, I've also seen these types of scenarios where technical enforcement is weaker than the policy. Or perhaps the decommissioning of the old device, when the new device is activated, happens slowly or takes a day. In general, if you're going to have a technical enforcement.
