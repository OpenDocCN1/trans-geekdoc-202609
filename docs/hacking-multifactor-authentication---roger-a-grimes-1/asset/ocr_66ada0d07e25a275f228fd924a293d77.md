# Denial of Service
Hacker could interrupt a legitimate user's use of a B-Unit in any number of ways. They could steal or destroy it. They could scratch the B-Unit's fingerprint reader. Or, thinking more superbly, they could mess with the optical communications between the user's computer screen and the B-Unit's photoelectric diode sensor. In many of Bloomberg's publicly accessible troubleshooting guides, it is clear that a common user complaint is that B-Units aren't "sync". The troubleshooting guides suggest the B-Unit close to the screen or varying its distances and angles. They suggesting monitor resolution and brightness. A hacker in control of the user's main host device could change resolution or mess with brightness to interrupt optical communications. I could see really why hacker using a laser pointer or infrared light source directed at the screen communication path or the path between the screen and the sensor to surreptitiously cause problems.

# API Bypass
It's very common for APIs not to require MFA. Bloomberg Terminal has a ton of APIs (www.bloomberg.com/professional/support/api-library). You can download documentation and examples. In little I can see (as shown in the code snippet in Figure 21.9), it appears that their APIs will use user login names and passwords.

```
- 
  "\n OPTIONS (specify all or none):\"
  "\[ts-client-credentials <file>]\"
  "\name a PFC#812 file to use as a source of client\n  credentials\"
  "\[ts-client-credentials password <pwd>]\"
  "\name a PASSWORD password for screening client credentials\"
  "\[ts-trust-material <file>]\"
  "\name a PFC#97 file to use as a source of trusted certificate\"
  "\[read-certificate-files]\"
  "\[optional] read the TLS files and the blobs\n"
  << std::flush;
}
```
