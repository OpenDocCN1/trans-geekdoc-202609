

# 运行时攻击

运行时攻击是基于内存的攻击，利用应用程序在运行时内存中执行的代码。攻击者利用应用程序代码与数据之间缺乏边界的特性，将恶意代码注入内存结构。这类攻击传统上极难检测和防御。

大多数当前的边界安全工具（如防火墙和 IPS）远离应用程序在内存中的运行时环境。这些设备无法知晓应用程序的运行时条件，因此无法区分真实威胁和潜在威胁。同样，漏洞扫描器也跟不上云容器快速启动和关闭的节奏，因此无法区分暴露在外部的漏洞和受边缘保护设备保护的漏洞。

然而，较新的**运行时应用自我保护 (RASP)** 工具已被开发出来，通过监控应用程序运行时环境的输入以发现潜在的意外更改或篡改，从而提高应用程序安全性。当检测到这些活动时，受 RASP 保护的应用程序会采取行动予以阻止，并通知用户或安全人员。其他可能的操作包括关闭应用程序或终止会话。

# 应用程序执行控制

**应用程序执行控制** 是一种网络安全缓解策略，旨在防止恶意代码在计算系统上执行。该策略始于识别环境中所有机器上获准运行的应用程序。应用程序识别完成后，下一步是创建规则，确保仅允许这些应用程序在机器上运行。最后，实施加密哈希规则、发布者证书规则和路径规则，以强制执行应用程序执行控制。必须配置文件夹、文件和应用程序权限，以阻止所有未经授权的修改。

应用程序控制策略应包含记录被阻止的恶意代码执行尝试的条款。这些事件日志应配置为提供所有被阻止尝试的文件名、日期/时间戳和用户名。这些信息对于识别尝试攻击的个人或组织非常有价值。

这些规则应作为组织变更管理策略的一部分进行维护，并且应至少每年进行一次审查和验证。

# 用户访问管理

网络中基本上有两类用户——`administrators`（管理员）和 `users`（用户）。这些类别也可能存在于两个不同层级——位于单个客户端设备上的本地账户数据库和位于网络服务器上的网络账户数据库。请回顾一下，网络账户设置通常优先于本地设置。

在 Microsoft Windows 环境中，安装后会有几个 `default user accounts`（默认用户账户）。这些账户包括以下内容：

*   **Administrator**（管理员）：这是主要的管理账户，拥有对系统及其所有管理工具的完全访问权限。
*   **Guest account**（来宾账户）：这是一个统称账户，用于为没有计算机用户账户的用户提供访问权限。建立用户账户后，应禁用此账户。
*   **HelpAssistant**：这是一个特殊的 Windows 账户，配合其远程协助实用程序使用，用于验证通过它连接的用户。每当创建远程协助邀请时，此账户即被启用，当所有邀请过期后，会自动禁用。
*   **SUPPORT_XXXXX**：这是一个特殊的 Microsoft 账户，用于通过其帮助和支持服务实用程序提供远程支持。
*   **DefaultAccount**（默认账户）：在 Windows 10 后期版本和 Windows Server 2016 中，引入了一个新的系统管理账户，称为默认系统管理账户 (DSMA) 或 DefaultAccount。

这些默认用户账户可以重命名，但无法删除。初始 Windows 管理员账户的密码在安装过程中设置。

与基于 Microsoft 的网络环境类似，Linux 系统采用“用户和组”结构来控制对本地和网络资源（文件、目录和外围设备）的访问。每个获准访问 Linux 系统的人员都必须被分配一个用户名。除 `root superuser`（root 超级用户）外，用户名由管理员根据需要创建。

通过 `useradd` 命令行工具将用户添加到 Linux 系统，而现有用户账户信息可通过 `usermod` 命令进行修改。结合 `useradd` 创建的用户名使用 `passwd` 命令（`passwd username`），可为以新用户身份访问系统建立密码要求。

给定网络可能采用单一管理员，其对系统的所有方面（包括服务器、网络介质和连接设备）拥有全面控制权。然而，较大的网络通常有多个管理员，他们分担特定的网络职责，如服务器管理员、网络管理员和安全管理员。在这些情况下，最佳实践是仅保留必要数量的管理员账户，并将这些账户配置为仅拥有执行其职能所需的权限。

对于可以访问计算机服务的网络用户，安全性始终与功能性相平衡。某些网络环境可能拥有授权用户名单（员工或代理），但仍需容纳公众（未授权用户或客户）。在这些情况下，必须设置认证方法以同时适应这两类用户。通常这涉及为不同类别的用户建立不同的组账户，然后严格地为每个组提供所需的资源。

## 建立用户和组账户

企业和工业网络中的管理员为网络成员创建用户和组账户，其中包含对网络及其资源的特定 `access rights`（访问权限）和 `permissions`（权限）。根据为网络用户建立的访问控制策略（无论是针对个人还是其所在的不同网络 `groups`（组）），允许或拒绝用户读取、修改和检查文件和文件夹的访问权限。

认证可通过基于包含在已启用组中的继承过程应用于特定个人。例如，由于包含在公司的 `accounting group`（会计组）中，会计部门的所有成员可能会获得对会计程序和文件的 `inherited access`（继承访问权限）。

管理员使用 `group accounts`（组账户）来统一处理具有共同需求的用户账户。这样做可节省时间，允许他们一次性向组内所有人授予用户权限和资源访问权限。然而，即使授予用户访问特定资源的权限，管理员也可以限制用户对不同文件和文件夹可执行的活动范围。

### Windows Active Directory 默认安全组账户

Windows Server 版本提供了大量默认组来管理各种用户类型。Windows Server 2019 提供了 45 多个默认 `Active Directory (AD) groups`（Active Directory 组）供使用。从 2008 版至今的 Windows Server 版本的 Active Directory 安全组完整列表可在 `https://docs.microsoft.com/en-us/windows/security/identity-protection/access-control/active-directory-security-groups` 找到。Windows Server 系统中的一些关键默认组账户包括以下内容：

*   **Administrators**（管理员）：此组成员拥有对计算机及其工具的完全访问权限，可执行所有管理功能。此组自动包含 Administrator 用户账户作为成员。
