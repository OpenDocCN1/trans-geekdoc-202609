

## 12. Vulnerability Scanners

Vulnerability scanning uses a network vulnerability scanner package to scan an organization's network to find different types of common vulnerabilities, such as system misconfigurations and default password usage, as well as generating malformed packets to create DoS attacks. See the "Security Testing Tools" section for more details.

## 13. Port Scanners

Port scanners are software tools designed to probe computing devices to find open logical ports and their associated services. Attackers use these tools to locate and exploit vulnerabilities on target devices, such as servers or endpoints. See the "Port Scanning" section for more details.

## 15. Black Box Penetration Testing

The ultimate goal of black box penetration testing is to attempt to simulate an attack by an outside entity on a client's infrastructure, because unless the attacker is an insider threat, an outside entity should not have access to details of the corporate network infrastructure and defenses. See the "Types of Penetration Testing" section for more details.

## Chapter 10: ICS Security Monitoring and Incident Response

### Review Question Answers

1.  **Security Baseline**. After determining the potential impact of all identified risks, the organization's next step is to create a security baseline that defines the level of risk they can accept—their risk tolerance. See the "Establishing a Security Baseline" section for more details.

2.  **Configuration auditing** is an ongoing process that compares detected changes in the environment against approved change requests. See the "Configuration Auditing" section for more details.

3.  A patch review team (again composed of IT, cybersecurity, process engineering, production operations, and senior management) is recommended to analyze and determine if a patch should be applied to the ICS. See the "Control System Patch Distribution and Installation" section for more details.

4.  The Responsible Entity shall ensure that new Cyber Assets within the Electronic Security Perimeter and significant changes to existing Cyber Assets do not adversely affect existing cybersecurity controls. For the purposes of Standard CIP-007, a significant change shall include, at a minimum, the implementation of security patches, cumulative service packs, vendor releases, and version upgrades of operating systems, applications, database platforms, or other third-party software or firmware. See the "Software Reloads and Firmware Management" section for more details.

5.  **Monitoring** involves using systems or tools to continuously watch devices and network objects for specific types of activity or events. See the "Monitoring" section for more details.

6.  **Logging** is the process of recording and storing specific events and transactions for analysis (auditing) purposes. Virtually all computing and networking devices in use today generate logs in some format. See the "Logging and Auditing" section for more details.

7.  Will the log file format remain viable for the specified time period, and what storage media should be used? If storage requirements are long (not just days or weeks), logs need to be archived. This may require the administrator to determine if the log file format will likely remain viable for the specified time period. Another consideration for long-term archiving of log files involves the selection of storage media to be used. While there are many different storage media options available for archiving log data, the expected viability of the media (and its supporting hardware and software) for the required retention period must be considered. If any format is at risk of becoming unavailable or inaccessible, the administrator must take action to migrate the logs to another media type. See the "Archiving Logs" section for more details.

8.  Contact designated members of the incident response team, document activities occurring at the time of the incident, and keep the compromised computer powered on. When an individual detects an anomalous event or incident occurring on the network, they must be trained to follow the organization's security policy, which requires them to take appropriate actions as part of incident response. An individual's role in responding to an observed incident typically includes contacting designated members of the incident response team, documenting activities occurring at the time of the incident, and keeping the compromised computer powered on. See the "Detection and Analysis" section for more details.

9.  **Anomaly-based IDS/IPS systems** apply statistical analysis techniques to data flows to determine if they are "normal" or "anomalous" at any given time. See the "Automated Intrusion Detection Tools" section for more details.

10.  **Threshold-based anomaly detection systems**. These IDS systems are designed to track the number of times a specific event occurs over time, and generate an intrusion alert if the number of events exceeds a predetermined number. See the "Automated Intrusion Detection Tools" section for more details.
