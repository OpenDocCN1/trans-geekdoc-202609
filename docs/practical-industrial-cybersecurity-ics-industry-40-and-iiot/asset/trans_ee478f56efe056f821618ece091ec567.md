
由于可能会用 ping 请求淹没网络，ICMP 流量通常会被阻断。大多数防火墙设备可用于完全阻断此类流量。虽然在公共网络上通常允许 ICMP 流量是良好的做法，但出于多种原因，防火墙阻断本地网络的 ICMP 流量至关重要。事实上，对于大多数网络而言，将防火墙设置为不回复这些请求可能更为可取。

有许多工具可用于发起 ping 洪水攻击。其中之一是 `Low Orbit Ion Cannon (LOIC)`，这是一种基于 GUI 的工具，用于向指定目标发起非常有效的 ping 洪水攻击。该工具通常会被主机上的防病毒程序阻止，安装它需要设置豁免。

### Smurf 攻击

**Smurf 攻击**是一种用 ICMP 数据包淹没网络的 DDoS 攻击。这种攻击在 ping 洪水攻击的基础上增加了反射特性。这种反射特性是通过在攻击中利用更多参与者（称为 **Smurf 放大器**）来创建的。

攻击者通过获取发送者地址（最初是攻击者的地址）并将其设定为受害者的地址来伪造一个 ping 请求数据包，如[图 5.23](#c05.xhtml#c05-fig-0023)所示。然后，攻击者将目标地址更改为网络的广播地址。

![FIGURE 5.23 Smurf amplification](images/c05f023.png)

[**图 5.23**](#c05.xhtml#R_c05-fig-0023) Smurf 放大

当攻击者发送 ping 请求时，网络上能够响应 ping 请求的 Smurf 放大器将使用受害者的 IP 地址作为目标地址进行回复。由于许多设备都在向受害者回复，受害者会被流量淹没，从而几乎瘫痪。

ICMP 隧道也可用于传递恶意数据包。此处的最佳防御是配置网络设备不响应 ICMP 回显请求。另一种选择是直接阻断所有 ICMP 流量以及入站广播流量。

### UDP 洪水攻击

**UDP 洪水攻击**是一种类似于 ping 洪水攻击的 DoS 攻击，它使用 **用户数据报协议 (UDP) 数据包**。由于 UDP 是无连接的，且缺乏 TCP 那样的错误检查能力，因此它不具备 TCP 的三次握手过程。

在这种攻击中，攻击者会向受害者的随机端口发送大量 UDP 数据包。由于这些数据包被发送到特定端口，受害者必须检查是否真的有应用程序在监听这些端口。

当受害者发现没有程序在监听时，它将回复一个 ICMP 目标不可达数据包。在这种情况下，受害者将难以发回所有 ICMP 数据包，任何其他试图连接受害者的尝试都将被拒绝。此外，攻击者很可能会欺骗用于发送 UDP 数据包的 IP 地址以避免被发现。

**Fraggle 攻击**在概念和缓解措施上与 Smurf 攻击类似，只是它使用 UDP 数据包代替 ICMP。

### SYN 洪水攻击

**SYN 洪水攻击**是一种拒绝服务攻击形式，攻击者利用使用 SYN 和 ACK 消息建立两个主机间可靠连接的 TCP 握手过程。与 UDP 可以丢弃数据包而无需任何错误纠正不同，TCP 使用三次握手来确保消息被正确可靠地发送，如[图 5.24](#c05.xhtml#c05-fig-0024)所示。

![FIGURE 5.24 SYN flooding](images/c05f024.png)

[**图 5.24**](#c05.xhtml#R_c05-fig-0024) SYN 洪水

三次握手的工作原理如下：

1.  客户端希望在自己和服务器之间建立连接。它向服务器发送一个 SYN 消息。
2.  服务器收到消息并回送一个 SYN 确认，表示为 SYN-ACK。
3.  客户端随后通过向服务器发送一个 ACK 消息来响应 SYN 确认。

在 SYN 洪水攻击中，攻击者利用三次握手过程。攻击者将向服务器发送大量 SYN 消息，每秒几十个甚至上百个。服务器试图跟上节奏并回送 SYN-ACK 消息给攻击者，但攻击者从不回复 ACK 消息。随后，当合法客户端想要连接服务器时，他们无法做到，因为服务器被 SYN 消息淹没，无法回复。

因为这也可能看起来像网络拥塞，服务器通常会等待一小段时间再响应，希望拥塞能缓解。真正的恶意攻击将继续耗尽服务器资源，拒绝为其他客户提供服务。此时某些服务器可能会发生故障甚至崩溃。

根据所涉及的操作系统，有针对 SYN 洪水的有效对策。处理 SYN 洪水的一种方法是使用 **计算序列号** 而不是 **状态表**。不幸的是，这种计算可能非常消耗 CPU，因此这种技术通常涉及实施专用负载均衡器或专门设计用于处理 DoS 攻击的网络设备。

现代防火墙也可以通过丢弃半开连接在一定程度上应对 SYN 洪水。然而，大流量的 SYN 洪水通常仍会对网络性能产生明显影响。

### 数据操纵攻击

并非所有攻击都旨在窃取数据；有些仅旨在操纵数据以降低其完整性。许多网络安全专家认为 **数据操纵** 比传统的数据窃取或物理基础设施攻击是一个更大的问题。这类攻击破坏了组织、客户和政府对其所掌握数据的信心。最终结果是无法基于态势感知数据做出明智的商业决策或军事决策。

例如，Stuxnet 攻击的主要手段基于数据操纵而非窃取。该攻击篡改了伊朗离心机的运行速度数据，导致操作员不知道其系统的真实速度。因此，他们根本不知道离心机面临毁坏的危险。

随着物联网 (IoT) 和工业物联网 (IIoT) 市场在生活的方方面面（包括工业加工和公用事业运营）持续增长，基于数据操纵的攻击机会呈指数级增长。这包括传感器网络、住宅恒温器、胰岛素泵、交换设备等。

因为数据操纵攻击是隐蔽的、有针对性的攻击，且发生在前面描述的网络链的多个环节中，所以组织协调其网络安全工具以检测、调查和缓解网络中覆盖数据的企图非常重要。

### 会话劫持攻击

在 TCP 会话中，身份验证通常仅在会话开始时发生。通常登录网站时会给用户一个 **会话 Cookie** 以标识其后续身份。如果攻击者能够嗅探此连接并获取会话 Cookie，他们就能访问该网站。这种攻击称为 **会话劫持**，如[图 5.25](#c05.xhtml#c05-fig-0025)所示。

![FIGURE 5.25 Session hijacking](images/c05f025.png)

[**图 5.25**](#c05.xhtml#R_c05-fig-0025) 会话劫持

**点击劫持攻击**采用欺骗性框架技术，诱使用户点击其内容而非预期内容。这是一种在被黑网站上常用的伎俩，因为它易于实施且回报丰厚，如[图 5.26](#c05.xhtml#c05-fig-0026)所示。攻击者大多隐藏合法框架，使用户点击攻击者的框架。这常针对社交媒体框架进行。网页开发人员可以在其网页文档中添加少量防框架代码，但这也可能被绕过。
