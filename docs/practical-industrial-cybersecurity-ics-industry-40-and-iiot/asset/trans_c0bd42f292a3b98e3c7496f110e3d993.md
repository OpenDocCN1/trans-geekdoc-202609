

# 最新的 WPA 版本 (WPA3)

最新的 WPA 版本 (`WPA3`) 采用了一种名为 `Device Provisioning Protocol` (`DPP`) 的高级连接协议，该协议将连接过程自动化，使其不再依赖共享密码。相反，它使用一种称为**同时认证平等** (`SAE`) 的技术，取代了 PSK 模式四次握手连接中使用的共享密钥。此注册过程发送网络注册指令，而无需传输密码。这些消息可以采用二维码或 NFC 标签的形式，以认证设备并授予其网络访问权限。

WPA3 的加密方式与 WPA 和 WPA2 有很大不同，使得 KRACK 攻击和字典攻击等旧式攻击方法失效。它使用 256 位 Galois/Counter Mode Protocol (`GCMP-256`) 加密代码，将生成破解该代码所需的所有计算可能性所需的计算次数提高到超过 1 x10^(77) 次。WPA3 包含 384 位哈希消息认证模式加密，用于在密钥在路由器和连接设备之间传递时对其进行加密。

## 802.11 信标泛洪

无线接入点定期广播 `beacon frames`（信标帧），让附近的客户端知道它们正在广播哪些网络。这些帧还包含无线设备连接到 AP 所需的相关信息，例如 SSID 和 `beacon intervals`（信标间隔），以及可用于将本地时钟设置为网络时间以进行认证的 `timestamps`（时间戳）。

接入点采用信标间隔来确定信标之间的时间量。增加信标间隔会减少发送的信标数量。相反，减小间隔会增加发送的信标数量。

有许多工具可供黑客利用信标及其漏洞。其中一种工具是 `MDK3`。如 [图 5.33](#c05.xhtml#c05-fig-0033) 所示，该实用程序支持多种不同的攻击，包括信标泛洪和取消认证攻击，以及其他 DoS 攻击。

![FIGURE 5.33 MDK3](images/c05f033.png)

[**图 5.33**](#c05.xhtml#R_c05-fig-0033) MDK3

`MDK3` 可以发起信标泛洪攻击，如 [图 5.34](#c05.xhtml#c05-fig-0034) 所示，通过为某个网络广播伪造的信标数据包。例如，命令：

```
mdk wlan1 b -n mynetwork -n -t -c 6 -s 70
```

将导致 `mdk3` 对 `mynetwork` 发起信标泛洪攻击（`b` 标志），该网络是一个无线 N 网络（`n` 标志），在信道 6 上使用 TKIP 安全协议（`-c 6`），并将以每秒 70 个数据包的速度发送（`-s 70`）。一旦发起攻击，尝试连接到 `mynetwork` 网络的设备将无法连接，直到攻击停止。

## 802.11 取消认证泛洪

另一种无线攻击类型是取消认证泛洪攻击，通常称为 `deauth attack`（取消认证攻击）。取消认证攻击涉及攻击者向接入点发送一个 `deauthentication packet`（取消认证数据包），进而将所有连接到该接入点的设备踢下线。有许多不同的工具可用于执行此攻击，如前所述的 `MDK3`，以及更常用的 `aireplay-ng` 工具。

如果出于任何原因想阻止客户端连接到无线接入点，取消认证攻击会很有用。例如，经验不足的系统管理员可能会尝试将加密方式更改为安全性较低的方式，希望解决接入点的问题。另一方面，他们可能只是简单地禁用 AP。

# 密码学

`Cryptography`（密码学）是一个用于描述保护信息和为数据提供不可否认性的概念和方法的术语。许多密码技术涉及密钥的使用。密钥仅仅是一个用于加密或解密信息的数据字符串。密钥的使用方式以及字符串的长度都会影响加密的强度。

加密密钥可以基于仅为加密和解密数据的软件所知的“秘密”字符串，也可以是随机生成的。它也可能是已知因素和随机因素的组合。执行此加密或解密的算法称为 `cipher`（密码/加密算法）。密码可能是一次处理一个字符的 `stream cipher`（流密码），也可能是一次处理输入字符串的多个块的 `block cipher`（分组密码）。

如果加密和解密使用相同的密钥，则称为 `symmetric key`（对称密钥）。如果加密和解密使用不同的密钥，则称为 `asymmetric keys`（非对称密钥），即使这些密钥是基于彼此生成的。[图 5.35](#c05.xhtml#c05-fig-0035) 展示了两者的区别。

![FIGURE 5.35 Symmetric vs. asymmetric keys](images/c05f035.png)

[**图 5.35**](#c05.xhtml#R_c05-fig-0035) 对称密钥与非对称密钥

`Public-key cryptography`（公钥密码学）使用包含 `public key`（公钥）和 `private key`（私钥）（或 `secret key`（密钥））的非对称密钥。公钥和私钥是不同的，但私钥可以从公钥计算得出。相反，从私钥计算公钥几乎是不可能的。

这种密码学的强度显然与逆向工程这种计算的难度有关。初始认证过程通常涉及使用私钥处理某些凭据以生成数字签名。后续验证则通过将公钥与此签名进行处理来完成，以验证原始凭据或消息。

公钥密码学用于许多不同的加密协议和系统，包括以下内容：

*   传输层安全和安全套接字层 (`TLS` 和 `SSL`)
*   安全外壳协议 (`SSH`)
*   PGP (Pretty Good Privacy，优良隐私协议)
*   GNU Privacy Guard (`GPG`)
*   安全/多用途互联网邮件扩展 (`S/MIME`)
*   数字签名标准 (`DSS`)
*   RSA 加密算法

`Symmetric-key cryptography`（对称密钥密码学）对加密和解密使用相同或易于转换的密钥。这些密钥被称为交易双方之间的共享密钥。对称密钥加密用于 `Advanced Encryption Standard` (`AES`) 加密、`Blowfish`、`RC4`、`3DES` 以及许多其他方案。

简单的流密码安全性较低，因此大多数方案使用 64 位或更高的分组密码。某些方案会通过提及其加密的分组大小（例如 256 位加密）来宣示其强度。原始明文输入也必须进行填充，使其成为分组大小的偶数倍。

对称密钥密码主要容易受到暴力攻击，攻击者根据已知列表或预测性数学方案系统地猜测密钥，因此认证方案应尝试识别这些活动并自动采取适当措施加以阻止。这通常意味着在一段时间内限制认证尝试的次数，这虽然会给用户带来不便，但却是一个必要的功能。

基于密钥的安全方案强度的另一个组成部分是密钥生成中使用的随机性程度。随机密钥可以通过称为 `pseudorandom key generators`（伪随机密钥生成器）的应用程序以算法方式生成。随机化器使用某种 `entropy`（熵）（或不确定性程度）作为随机化的种子。熵的程度可以测量，通常以位为单位，有时会在加密方案的强度分析中提及。

理想情况下，熵的大小与密钥相同。该熵的来源通常是系统随手可得的数据的组合，可能经过某些乘数或代数方程的转换。例如，随机化器可能会将自过去某个时间以来的毫秒数除以进程 ID 并填充至指定长度，将这些组合起来。
