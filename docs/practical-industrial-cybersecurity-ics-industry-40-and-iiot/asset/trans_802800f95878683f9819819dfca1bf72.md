

# 企业网络中的目录服务

您在当前企业网络中可能遇到的目录服务均基于 `Lightweight Directory Access Protocol` (`LDAP`)，也称为 `X.500-lite standard`。该协议提供了一种与供应商无关的协议，用于通过 IP 网络创建和访问控制分布式网络目录服务。已有许多不同的 DS 软件产品基于 LDAP 协议开发。以下章节将讨论用于 Microsoft Windows 和 Linux 网络环境的目录服务。

## Active Directory

Microsoft Windows 网络架构的核心特性是 `Active Directory` (`AD`) 结构。Active Directory 是一个用户和资源信息的分布式数据库，用于描述网络的构成（即用户和应用程序设置）。它也是实现分布式身份验证过程的一种方法。

Windows 仍然是一个依赖域的操作系统。它将域用作管理、安全和复制目的的边界。每个域必须至少由一个域控制器来代表。域控制器是一台设置为保存网络目录数据库的服务器。

此数据库包含有关用户账户、组账户和计算机账户的信息。它跟踪域内所有对象的名称和资源请求。您可能还会发现此数据库被称为 `Security Accounts Manager` (`SAM`)。此功能有助于在 Windows 客户端网络中集中管理系统和用户配置，以及服务器上的数据备份。

Active Directory 结构采用了两种常见的 Internet 标准——LDAP 和 DNS。LDAP 协议用于定义目录信息如何被访问和交换。DNS 是将域名解析为实际 IP 地址的 Internet 标准。它也是与客户端和其他目录交换目录信息的标准。

Active Directory 以层次结构排列域，并在树状结构中建立所有域之间的信任关系，如 [图 7.4](#c07.xhtml#c07-fig-0004) 所示。

![FIGURE 7.4 Basic Active Directory structure](images/c07f004.png)

[**图 7.4**](#c07.xhtml#R_c07-fig-0004) 基本 Active Directory 结构

`树` 是共享相同 DNS 名称的对象集合。Active Directory 可以将域细分为包含其他单元或 `叶对象`（如打印机、用户等）的 `组织单位`（销售部、管理部等）。

相反，Windows 可以创建包含多个树的组织结构。这种结构称为 `林`。[图 7.5](#c07.xhtml#c07-fig-0005) 扩展了 AD 结构以演示这些关系。

![FIGURE 7.5 Active Directory relationships](images/c07f005.png)

[**图 7.5**](#c07.xhtml#R_c07-fig-0005) Active Directory 关系

Windows 操作系统通过双向信任自动将树内的所有域连接起来。`信任` 是允许用户在域之间移动并执行规定操作类型的关系。

如果在示例中销售域与市场域之间建立了信任关系，且销售域与管理域之间存在类似的信任，则市场域与管理域之间也存在信任关系。信任使管理员能够为用户和组提供对对象的不同权限。

`权限` 是控制用户（或用户组）访问对象和执行操作（如读取或写入文件）权威的权限设置。管理权限提供对用户的权威，直至组织单位 (OU) 级别。OU 是容纳网络域内所有对象的容器。这些单位可通过容纳其他 OU 来为域提供层次结构。

管理权限不跨越域级别建立的边界，但可以被同一树中具有从属位置的其他 OU 继承。另一方面，用户权限必须为单个用户或组成员建立。使用组可以通过单个管理操作将通用权限分配给多个用户（这与为每个人单独设置和维护权限形成对比，例如为 150 人的会计人员设置权限）。

处理 Active Directory 的主要工具是 `Active Directory Users and Computers` 控制台，如 [图 7.6](#c07.xhtml#c07-fig-0006) 所示。域的组织单位包含用户、组和资源。Active Directory Manager 工具用于向目录中添加用户、组和组织单位。

![FIGURE 7.6 Active Directory Users and Computers](images/c07f006.png)

[**图 7.6**](#c07.xhtml#R_c07-fig-0006) Active Directory Users and Computers

Windows 环境的整体运行由 `系统策略` 管辖。基本上，策略赋予管理员对用户的控制权。使用系统策略，系统管理员可以授予或限制用户对本地资源（如驱动器和网络连接）的访问。

管理员可以建立策略，强制特定用户在指定时间登录，并在其他所有时间将其锁定在系统之外。系统策略还使管理员能够发送更新并为网络客户端配置桌面。从根本上说，控制面板中找到的任何项目都可以通过系统策略进行管控。

通过组策略，管理员可以为整个企业的用户制定大量详细设置，而无需手动建立每一项设置。GPO 可用于通过 AD 向计算机和用户应用大量更改。

## Linux 目录服务

较旧的 Linux 发行版支持一种称为 `Network Information Services` (`NIS`) 的目录服务结构。然而，较新的发行版已转向基于 LDAP 的目录服务。这些包括 Red Hat 的 389 Directory Server、Apache Directory Server 和 OpenLDAP，以及一系列鲜为人知或专有的目录服务器平台。

与 Active Directory 一样，基于 LDAP 的 Linux 平台为系统信息查找和身份验证提供单一目录源。将用户信息存储在基于 LDAP 的目录服务器中，使网络具有可扩展性、可管理性和安全性。

与 Microsoft 的 AD 不同，目录服务不是 Linux 操作系统结构的组成部分。相反，它们是在操作系统安装后添加到结构中的。然而，安装后，基于 Linux 的目录服务模块采用基于 GUI 和菜单驱动的工具（如 [图 7.7](#c07.xhtml#c07-fig-0007) 所示）来定义网络的组织单位。

![FIGURE 7.7 Linux directory service menu](images/c07f007.png)

[**图 7.7**](#c07.xhtml#R_c07-fig-0007) Linux 目录服务菜单

通常，这些目录服务服务器提供基于网络的注册表，使管理员能够集中存储用户身份和应用程序信息，例如：

*   应用程序设置
*   用户配置文件
*   组权限
*   策略
*   访问控制数据

通过在目录结构中存储和检索此类信息，用户和应用程序变得与位置无关。用户能够登录到网络中的任何位置，并访问其在指定位置或网络中任何其他位置所拥有的相同应用程序和数据。

# 应用程序运行时与执行控制

软件应用程序变得日益复杂、分布式和互联。向云计算、容器化和混合架构解决方案的转变增加了这些应用程序的攻击面。随着这些变革重新定义了我们 IT/OT 网络架构模型中的边缘和边界术语，提供额外安全性的压力也随之增加。
