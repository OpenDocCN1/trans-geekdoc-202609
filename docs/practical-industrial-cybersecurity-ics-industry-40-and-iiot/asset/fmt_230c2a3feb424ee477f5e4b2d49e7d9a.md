
# 网络监控与审计

正如前文所述，网络监控和审计是任何组织网络管理/安全运营的关键组成部分。监控涉及使用系统或工具持续观察设备和网络对象，以查找特定类型的活动或事件。一般来说，任何网络中都应检查三种常见类型的活动：

*   **事件监控** 跟踪监控系统配置设置所要求的特定类型事件。当发生指定类型的活动时，监控系统会记录该事件并将其提交到日志以供后续检查。监控系统也可配置为创建并发送通知给指定接收人。
*   **网络监控** 检查监控系统配置设置所要求的网络流量和活动。网络监控职责可分布在多种不同类型的设备上，例如：监控来自网络外部威胁活动的入侵检测系统；监控网络流量的网络连接设备，如托管交换机、路由器、防火墙和工具设备；以及监控计算设备活动的服务器。
*   **安全监控** 跟踪已被定义为安全事件的特定类型活动的发生。这些事件通常包括登录/认证失败、尝试访问关键系统文件等项目。

## 事件监控

**事件监控** 是跟踪活动并监视某些事件（发生）出现的做法。当指定事件出现在活动流中时，事件信息会被存储在日志中，并可能发出通知以告知指定人员该事件的发生。端点设备、服务器和网络设备都具备监控其不同类型事件操作的能力。

在 Microsoft Windows 环境中，主要的事件监控工具是内置的 `Event Monitor` 应用程序。该工具通过过滤器进行配置，过滤器定义了要监控和记录的事件的 Category（类别）、Description（描述）和 Type（类型）。可监控的事件类型包括 Errors（错误）、Warning Information（警告信息）、Success Audits（成功审核）和 Failure Audits（失败审核）。监控任务返回的信息存储在操作系统的 **Windows Event Log** 中。Windows 产品默认包含三种类型的事件日志——Application（应用程序）、Security（安全）和 System（系统）日志。

Linux 操作系统包含 12 个关键事件日志文件，服务器管理员需要监控这些文件以跟踪其设备上发生的重要事件。这些是与服务器、内核、服务及其设备上运行的应用程序相关的 Linux 日志文件。这些日志文件通常可分为四类：Application logs（应用程序日志）、Event logs（事件日志）、Service logs（服务日志）和 System logs（系统日志）。监控这些日志使管理员和信息安全人员能够在问题发生前预判即将出现的问题。

以下是需要监控的关键 Linux 日志：

*   `/var/log/messages`——通用系统活动日志，跟踪非内核启动错误和系统启动时的应用程序相关服务错误。
*   `/var/log/syslog`——基于 Debian 的通用系统活动日志，跟踪非内核启动错误和系统启动时的应用程序相关服务错误。
*   `/var/log/auth.log`——基于 Debian 和 Ubuntu 的认证和授权事件。失败的登录尝试、暴力破解攻击等。
*   `/var/log/secure`——基于 RedHat 和 CentOS 的认证和授权事件。失败的登录尝试、暴力破解攻击等。还跟踪 SSH 登录和错误。
*   `/var/log/boot.log`——系统初始化脚本启动消息。与不当关机、非计划重启和启动失败相关的问题。
*   `/var/log/dmesg`——关于设备状态和硬件错误的内核缓冲区消息。
*   `/var/log/kern.log`——关键内核信息。
*   `/var/log/faillog`——失败登录尝试的列表。是识别企图安全入侵活动的关键。
*   `/var/log/cron`——关于 cron 作业操作的信息。
*   `/var/log/yum.log`——使用 YUM 安装相关的新软件包安装信息。
*   `/var/log/mail.log`——邮件服务器日志，用于邮件服务器上运行的电子邮件相关服务——发送和接收的邮件、可能的垃圾邮件尝试、传入邮件的来源。
*   `/var/log/httpd`——与 httpd 错误相关的 Apache 服务器日志。
*   `/var/log/mysqld.log`——MySQL 日志。

有许多开源工具可用于集中监控和分析这些日志，以减轻管理员的负担。一款广泛使用的用于管理服务器日志的商业软件包是 `Nagios Log Server`。这些应用程序使管理员能够查看、排序、配置和分析来自网络中不同来源的日志。

## 网络监控

IT 和 OT 网络通常都会采用多种不同的网络监控工具，包括防火墙、IDS/IPS 系统、操作系统日志、商业监控工具、定制监控工具和高级日志管理系统，以及 **Security Information Event Management (SIEM)** 工具。此外，还有许多 NSM 软件包用于提供对这些监控系统的自动化管理。提供有效的主动管理和监控计划需要以下组件：

*   **监控软件**——在监控软件配置期间，会选择各种硬件和软件操作进行跟踪。生成的事件信息可存储在日志文件中。
*   **报警/警告系统**——如果网络或其设备之一显示入侵或故障迹象，可立即以向管理控制台发送警报或向管理员发送寻呼的形式发出即时警告。
*   **远程管理功能**——管理员可从远程位置登录其端点、服务器和网络设备以检查其状况。诊断日志可远程查看，故障服务器系统可远程开机、关机甚至重启以恢复运行，无需等待技术人员到场。

使用这些关键网络管理组件，管理员可以主动监控和管理其网络以优化其可用性。通过在故障发生前向系统管理员提供预警，网络监控软件帮助他们识别并处理问题，防止其演变为灾难性故障，从而避免组织损失生产力和利润。

网络管理员通常将其监控/审计工具配置为评估特定网络对象或事件，然后在审计日志中跟踪这些结果以供后续评估。另一方面，一些防火墙、**入侵检测系统 (IDSs)** 和 NSM 软件可配置为在识别出异常模式或事件时，向管理员提供即时警报或通知。

组织网络模型的 OT 侧通常不必处理给基于 IT 的 NSM 操作带来困难的项目。这些项目包括加密网络、NAT 的广泛使用、设备在网段间移动、极端的网络流量水平和隐私担忧。应用于此功能的常用工具包括：

*   **Security Onion**——一个开源 Linux 发行版，专为威胁狩猎、企业级安全监控和日志管理而设计。它常用于 NIDS、HIDS、SOC 分析和静态分析。（参见 `www.securityonionsolutions.com`。）
*   **FlowBAT**——一个基础网络分析工具，提供网络可见性、安全监控、事件响应和低存储开销。（参见 `www.flowbat.com`。）
