## 数据区域与分层安全策略

数据通常被视为企业组织最有价值的资产。这包括从员工信息、财务信息、客户信息到健康信息等不同类型的数据。因此，信息的分类范围可以从机密、内部到公开。当然，机密信息存储在拓扑结构的最内层区域，称为**数据区**。这通常涉及包含机密客户数据的数据库、高度安全的设备、基础设施、策略和政策。

访问该区域中的资源必须经过授权和认证。数据存储加密也在该区域采用。**应用层加密**是首选，但如果没有应用层加密选项，则应采用**文件系统加密**。

组织的机密数据子集通常会定期移动到其他安全区域进行处理和分发。这些内部层的安全策略因分配给资产的机密性和可用性要求而异。

例如，紧邻数据区外侧的**应用区**包含用于处理数据的应用程序。该区域通常部署文件服务器。该区域的信息仍被视为组织的内部数据，受到比“公共”数据更严格的安全措施保护。

与数据区一样，访问应用区需要用户授权和认证，以及服务认证。通常在此级别部署入侵检测系统，以便在发生入侵事件时通知管理员。

将应用区与最外层安全层（通常是互联网）隔开的**呈现区**是组织用户网段的所在地。这可以包括专用于管理局域网的网段。呈现区还用于托管公共接口，如提供“公共”信息的 Web 服务器，以及组织的传输安全工具和结构。

访问该区域的资源仍然需要认证，即使内容被指定为公共。呈现层实施的常见安全措施包括：

*   **防火墙**：防火墙用于控制呈现区与应用区/互联网区之间，以及区域内子网之间的信息流。仅接受来自区域内部或相邻区域的访问请求。
*   **病毒和恶意软件扫描器**：该区域的所有资产都应被要求具备防病毒和反恶意软件保护。
*   **审计工具**：这些工具在此级别实施，用于记录重要的应用程序和安全事件，以便问责和取证。记录的数据绝不能包含被分类为机密的信息。
*   **加固技术**：该区域的所有资产都应通过对其及其应用程序应用加固技术来保护。这些技术将在本章后面详细介绍。
*   **传输安全结构**：这些是 DMZ、VPN 或反向代理，用于为外部用户提供认证（这些结构将在本章后面讨论）。
*   **数据传输加密**：所有被分类为机密的数据在通过网络移动时必须加密。必须使用安全协议（如 HTTPS 和 SSL）替换不太安全的协议（如 HTTP 和 SFTP）。

在此安全拓扑示例中，最外层的**互联网区**代表不受控（互联网）或外部受控（第三方合作伙伴）的网络。该区域包括组织无法控制的所有网络。因此，内容可以是公开的，也可以是属于受信任合作伙伴或客户的机密数据。该区域的访问要求可以是经过认证的，也可以是匿名的。

## 扁平网络拓扑

并非每个企业网络都采用分层、分段的安全拓扑设计。[图 3.18](#c03.xhtml#c03-fig-0018)展示了一个通用的**扁平网络拓扑**，许多企业网络（甚至一些非常大的网络）都在使用。扁平网络策略也广泛应用于 OT 网络。

![FIGURE 3.18 A flat network configuration](images/c03f018.png)

[**FIGURE 3.18**](#c03.xhtml#R_c03-fig-0018) A flat network configuration

该模型基本上最小化了网络中连接设备（路由器和交换机）的使用。取而代之的是，使用集中式交换机将网络节点连接在一起。在大多数情况下，这些网络通常通过单个路由器与互联网隔离。

这种策略确实降低了网络实施和维护的成本，并降低了管理操作的复杂性。然而，它也导致网络安全级别非常低。在扁平网络中，流量可以在所有网络节点之间自由移动，为所有连接用户提供访问权限。

实际上，它是一个大的广播域。任何发送 ARP 广播以查找有效网络 IP 地址的设备都会收到回复。这意味着如果攻击者获得网络访问权限，他们可以看到网络中的每个资产，包括服务器、终端设备和数据。凭借合适的技能和足够的时间，他们可以利用所有这些设备。

如果恶意软件或恶意代码（如蠕虫，例如著名的 Stuxnet 病毒）获得网络访问权限，则没有任何东西能阻止它蔓延到整个网络。此外，对于源自网络内部的任何恶意活动，几乎没有保护措施。

不幸的是，大多数 OT 网络都是建立在大型扁平网络拓扑之上的。这使得网络攻击或干扰在初始渗透发生后能在网络中快速传播。扁平拓扑还使 OT 网络容易受到网络地图上未显示但构成重大威胁的威胁，当过程控制系统联网时这些威胁会显现。这些威胁包括可能进入工厂并与 ICS 网络通信的无线设备，以及基于 USB 的设备被引入 ICS 系统的能力。

### OT 安全分区

在 OT 网络内部，应分析流程以确定过程控制网络是否可以按本章前面所述组织成安全段。如果可能，OT 网络应根据管理权限、统一信任级别或网络流量划分为**安全区域**。与 IT 网络一样，良好分段的 OT 网络可以使攻击者更难成功入侵系统，并最大限度地减少非恶意错误的影响。

考虑本章前面介绍的多层纵深防御网络安全拓扑。对于 OT 网络，通常不需要高度受保护的数据库层。相反，ICS 安全拓扑更有可能将网络分段为运营区、控制区、DMZ 和非 ICS 区，如[图 3.19](#c03.xhtml#c03-fig-0019)所示。
