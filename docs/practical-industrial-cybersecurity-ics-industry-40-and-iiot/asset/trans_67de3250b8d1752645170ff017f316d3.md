

## Windows 内置组

*   **Guests（来宾）**：此默认组对系统的访问权限最小化，且所有成员共享同一用户配置文件。Guest 用户账户自动成为该组的成员。
*   **Power Users（高级用户）**：Power Users 是一个特殊组，拥有在系统上执行许多管理任务的权限，但不具备 Administrator（管理员）账户的完全管理特权。Power Users 可以创建和管理用户及组。此外，除非通过其他来源被授予权限，否则他们无法访问 NTFS 卷上的文件和文件夹。创建该组时没有任何成员。
*   **Backup Operators（备份操作员）**：顾名思义，该组成员可以备份和还原计算机上的所有文件。通过备份实用程序，该组成员拥有对系统整个文件系统的访问权限。创建该组时没有任何成员。
*   **Network Configuration Operators（网络配置操作员）**：该组成员可以管理系统网络配置的不同方面。具体而言，他们可以修改 TCP/IP 属性；启用、禁用和重命名连接；并执行 `ipconfig` 操作。创建该组时为空。
*   **Users（用户）**：这是一个包罗万象的组，拥有有限的默认权限。除 Guest 账户外，系统上创建的所有用户账户（包括 administrator 账户）默认均为此组成员。
*   **Remote Desktop Users（远程桌面用户）**：此 Windows 组的成员拥有远程登录系统以执行远程桌面活动的用户权利。该组默认没有成员。

### Windows 域账户

Windows 服务器系统在*域环境*中使用时，也支持*域用户和组账户*。在域环境中，网络的所有成员共享一个通用的目录数据库，并被组织到不同层级。域由唯一名称标识，并作为一个具有通用规则和程序的单一单元进行管理。

域账户通过 Windows *域控制器*上的“Active Directory 用户和计算机”实用程序创建，并存储在 *Active Directory 数据库* 中。当 Windows 客户端设备被置于域环境中时，某些组成员身份会自动更改以反映这一变化。

*   **Domain Admins（域管理员）**：此组被添加到本地 Administrators 组，以便域管理员对其域内的所有计算机拥有管理控制权。
*   **Domain Users group（域用户组）**：此组被添加到本地 Users 组。
*   **Domain Guests group（域来宾组）**：此组被添加到本地 Guests 组。

这些组均为 Windows 域控制器的功能，仅存在于 Windows 域环境中。在域环境中自动添加这些组，使得域管理员更易于配置对本地计算机资源的访问。这些组并非永久添加，管理员可酌情将其移除。

### Linux 组账户

与其他多用户操作系统一样，出于管理目的，单个 Linux 用户通常被设为组的成员。由于组内存在的关系，用户生成的文件归该组成员所有。

与 Windows 不同，安装后存在的默认组列表因不同的 Linux 发行版而异。大多数发行版中常见的 Linux 组包括以下内容：

*   **games**：此组提供对游戏软件的访问权限。
*   **users**：这是标准的默认 Linux 用户组。
*   **wheel**：一个管理组，通常提供对用户创建和配置实用程序（`su` 和 `sudo` 命令）的访问权限。
*   **daemon**：这是一个标准的默认用户/组，拥有执行守护程序（后台进程）的特权，这些程序无需用户指导即可运行。在 Microsoft 体系中，此类程序被称为“驻留程序”，最类似于 Windows 环境中运行的服务。
*   **bin**：这是一个标准的默认 Linux 组，历史上提供运行可执行文件的权限。`bin` 的引用基于存储在那里的二进制（可执行）文件类型。该文件夹包含可执行以执行任务的脚本和命令。该目录中的命令可由每个用户运行。
*   **mail**：此组拥有特殊的邮件特权。
*   **root**：root 管理员组是一个标准的默认 Linux 组，拥有对系统的完全管理控制权。
*   **nobody**：这是非特权组。
*   **disk**：此组提供对“块设备”（如磁盘驱动器和光驱）的访问权限。

此列表仅显示了可能安装在特定 Linux 系统中或添加到其中的常见组中的一部分。Linux 中添加组的工具是 `groupadd`。组信息通过 `groupmod` 命令修改，用户通过 `usermod` 命令添加到组中。

## 组账户安全

在处理组账户时，有几个安全相关的操作需要牢记。

*   **删除或禁用未使用的默认账户**，例如 Guest 账户。如果置之不理，攻击者可能利用这些账户进行攻击。如果必须保留默认账户，请更改其名称，因为其标准身份验证凭据为潜在攻击者所熟知。此外，严格限制这些账户的访问权限、权利和权限。
*   **创建用户组**，涵盖具有共同需求的不同类型用户相关的功能，然后根据组的功能需求为每个组分配权利和权限。
*   **创建用户账户**，并根据其在组织中的工作职能将其分配到组。采用此方法可防止管理员必须单独配置每个用户的账户设置。仅创建所需账户，因为如果被发现，未使用的账户可能造成安全漏洞。
*   **设置账户密码**，使其在组织的密码策略下工作。
*   **安装并配置任何额外的身份验证系统**，例如选定用于网络的生物识别扫描设备或其他多因素身份验证应用程序。

## 网络身份验证选项

在网络层面，`username` 和 `password` 系统仍然是使用中的第一道 `authentication options`（身份验证选项）防线。即使您可能是一个或多个组账户的成员，也无法使用这些账户之一登录网络。您只能通过使用合法的用户账户登录来获得系统访问权限。在客户端-服务器网络中，经过身份验证的用户列表存储在服务器上，而非本地计算机。

此外，在网络层面，网络登录通常会覆盖任何本地系统登录。因此，管理员通过密码策略声明控制谁可以登录网络的任何部分。他们还设置网络密码策略，规定用户必须多久更改一次密码，以及设置长度和复杂性要求。

这些选项（如[图 7.8](#c07.xhtml#c07-fig-0008)所示）使管理员能够使用户账户和密码更安全。密码策略适用于登录系统的所有用户，无法为单个用户单独配置。

通常，网络管理员可以为网络用户配置以下与密码相关的设置：

*   **Enforce password history（强制密码历史）**：此选项用于指定将为每个用户跟踪的密码数量。当用户尝试更改密码时，将不允许重用任何正在跟踪的密码。
