
# 围棋游戏与蒙特卡洛树搜索

## 启发式 alpha–beta 树搜索的弱点

围棋游戏说明了启发式 `alpha–beta` 树搜索的两个主要弱点：首先，围棋的分支因子从 361 开始，这意味着 `alpha–beta` 搜索最多只能达到 4 或 5 层。其次，很难为围棋定义一个好的评估函数，因为子力价值不是强指标，而且大多数局面在终局之前都处于变化之中。为应对这两个挑战，现代围棋程序已放弃 `alpha–beta` 搜索，转而使用一种称为蒙特卡洛树搜索（`MCTS`）的策略。[3](#Chapter06-09.xhtml#sup06-3)

## 蒙特卡洛树搜索（MCTS）

基本的 `MCTS` 策略不使用启发式评估函数。相反，状态的价值被估计为从该状态开始的若干完整游戏模拟的平均效用。模拟（也称为回放或展开）在一个玩家然后另一个玩家之间选择移动，反复进行直到达到终止位置。此时，游戏规则（而非易错的启发式）决定谁赢了或输了，以及比分如何。对于仅有胜负两种结果的游戏，“平均效用”与“胜率”相同。

### 模拟 / 回放 / 展开

在回放期间我们如何选择要进行的移动？如果我们只是随机选择，那么经过多次模拟后，我们得到的是“如果双方都随机下棋，最佳移动是什么？”的答案。对于某些简单游戏，这恰好与“如果双方都下得好，最佳移动是什么？”的答案相同，但对于大多数游戏则不是。为了从回放中获得有用的信息，我们需要一种回放策略，使移动偏向于好的移动。对于围棋和其他游戏，回放策略已成功地通过使用神经网络从自我对弈中学习。有时使用特定于游戏的启发式，例如国际象棋中的“考虑吃子移动”或奥赛罗中的“占据角落方格”。

### 回放策略

给定一个回放策略，我们接下来需要决定两件事：从什么位置开始回放，以及为每个位置分配多少次回放？最简单的答案，称为 `pure Monte Carlo search`，是从游戏的当前状态开始进行 `N` 次模拟，并跟踪从当前位置的可能移动中哪个具有最高的胜率。

### 纯蒙特卡洛搜索

对于某些随机游戏，随着 `N` 的增加，这会收敛到最优对局，但对于大多数游戏来说是不够的——我们需要一种选择策略，选择性地将计算资源集中在游戏树的重要的部分上。它平衡两个因素：对很少进行回放的状态的探索，以及对过去回放中表现良好的状态的利用，以更准确地估计其价值。（参见 [第16.3节](#Chapter16-03.xhtml#sec16-3) 了解更多关于探索/利用权衡的内容。）蒙特卡洛树搜索通过维护一个搜索树并在以下四个步骤的每次迭代中扩展它来实现这一点，如 [图6.10](#Chapter06-04.xhtml#fig6-10) 所示：

## 选择策略 / 探索 / 利用

•选择：从搜索树的根开始，我们选择一个移动（由选择策略指导），导致一个后继节点，并重复该过程，沿树向下移动到叶节点。[图6.10(a)](#Chapter06-04.xhtml#fig6-10) 显示了一个搜索树，其根表示白方刚刚移动的状态，且迄今为止已进行的 100 次回放中白方获胜 37 次。粗箭头显示了黑方选择一个移动，导致一个黑方在 79 次回放中获胜 60 次的节点。这是三个移动中最高的胜率，因此选择它是一个利用的例子。但出于探索的目的，选择 2/11 节点也是合理的——仅有 11 次回放，该节点的估值仍存在高度不确定性，如果我们获得更多关于它的信息，它可能会最终成为最佳。选择继续到标记为 27/35 的叶节点。

•扩展：我们通过为所选节点生成一个新的子节点来扩展搜索树；[图6.10(b)](#Chapter06-04.xhtml#fig6-10) 显示了标记为 `0/0` 的新节点。（某些版本在此步骤中生成多个子节点。）

•模拟：我们从新生成的子节点开始进行回放，根据回放策略为双方选择移动。这些移动不会记录在搜索树中。在图中，模拟导致黑方获胜。

•反向传播：我们现在使用模拟的结果来更新从根部向上到根部的所有搜索树节点。由于黑方赢得了回放，黑方节点在获胜次数和回放次数上都递增，因此 27/35 变为 28/36，60/79 变为 61/80。由于白方输了，白方节点仅在回放次数上递增，因此 16/53 变为 16/54，根部 37/100 变为 37/101。

我们重复这四个步骤，要么进行设定的迭代次数，要么直到分配的时间到期，然后返回回放次数最多的移动。

## UCT 与 UCB1

一种非常有效的选择策略称为“上置信界应用于树”或 `UCT`。该策略根据称为 `UCB1` 的上置信界公式对每个可能的移动进行排名。（参见 [第16.3.3节](#Chapter16-03.xhtml#sec16-3-3) 了解更多详情。）对于节点 `n`，公式为：

$UCBI = \\,\\frac{U(n)}{N(n)} + C \\times \\sqrt{\\frac{\\log N\\text{(PARENT(}n\\text{))}}{N\\text{(}n\\text{)}}}$

其中 `U(n)` 是通过节点 `n` 的所有回放的总效用，`N(n)` 是通过节点 `n` 的回放次数，`PARENT(n)` 是树中 `n` 的父节点。因此 $\frac{U(n)}{N(n)}$ 是利用项：`n` 的平均效用。带平方根的项是探索项：它在分母中有计数 `N(n)`，这意味着该项对于仅被探索过几次的节点会很高。在分子中它有父节点被探索次数的对数。这意味着如果我们以非零的比例选择 `n`，随着计数的增加，探索项会趋向于零，最终回放会分配给平均效用最高的节点。

`C` 是一个平衡利用和探索的常数。理论上认为 `C` 应该是 $\sqrt{2}$，但在实践中，游戏程序员会尝试多个 `C` 值并选择表现最好的一个。（一些程序使用略有不同的公式；例如，`ALPHAZERO` 添加了一个移动概率的项，该概率由从过去自我对弈中训练的神经网络计算。）当 `C = 1.4` 时，[图6.10](#Chapter06-04.xhtml#fig6-10) 中的 60/79 节点具有最高的 `UCB1` 分数，但当 `C = 1.5` 时，将是 2/11 节点。
