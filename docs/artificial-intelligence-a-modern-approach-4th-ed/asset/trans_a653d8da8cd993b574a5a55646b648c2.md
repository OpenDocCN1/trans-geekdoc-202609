
极小化极大算法对博弈树进行完整的深度优先探索。如果树的最大深度为 `m`，并且在每个节点上有 `b` 个合法走法，那么极小化极大算法的时间复杂度为 `O(bm)`。空间复杂度对于一次性生成所有动作的算法为 `O(bm)`，或对于一次生成一个动作的算法为 `O(m)`（参见 [第98页](#Chapter03-04.xhtml#page_98)）。指数级复杂度使得 `MINIMAX` 对于复杂游戏不切实际；例如，国际象棋的分支因子约为 35，平均游戏深度约为 80 层，并且搜索 `3580 ≈ 10123` 个状态是不切实际的。`MINIMAX` 然而确实为博弈的数学分析提供了基础。通过以各种方式近似极小化极大分析，我们可以推导出更实用的算法。

## 6.2.2 多人游戏中的最优决策

许多流行游戏允许超过两名玩家。让我们研究如何将极小化极大思想扩展到多人游戏。从技术角度来看这很直接，但提出了一些有趣的新概念问题。

首先，我们需要用一组值向量来代替每个节点的单一值。例如，在三名玩家 `A`、`B` 和 `C` 的游戏中，每个节点都关联一个向量 `⟨vA, vB, vC⟩`。对于终止状态，该向量给出从每个玩家视角来看该状态的效用。（在两人零和游戏中，双元素向量可以简化为单一值，因为值总是相反的。）实现此目的最简单的方法是让 `UTILITY` 函数返回一个效用向量。

现在我们需要考虑非终止状态。考虑 [图6.4](#Chapter06-02.xhtml#fig6-4) 所示博弈树中标记为 `X` 的节点。在该状态下，玩家 `C` 选择做什么。两个选择导致效用向量分别为 `⟨vA = 1, vB = 2, vC = 6⟩` 和 `⟨vA = 4, vB = 2, vC = 3⟩` 的终止状态。由于 6 大于 3，`C` 应该选择第一个走法。这意味着如果状态 `X` 被达到，后续对局将导致效用为 `⟨vA = 1, vB = 2, vC = 6⟩` 的终止状态。因此，`X` 的回溯值为该向量。一般来说，节点 `n` 的回溯值是该节点决策玩家价值最高的后继状态的效用向量。

例如，假设 `A` 和 `B` 处于弱势地位而 `C` 处于更强势地位。那么通常对 `A` 和 `B` 两者来说攻击 `C` 而不是互相攻击是更优的，否则 `C` 会单独摧毁他们中的每一个。以这种方式，协作从纯粹的自私行为中产生。当然，一旦 `C` 在联合打击下变弱，联盟就失去了价值，`A` 或 `B` 中的任何一方都可能违反协议。

在某些情况下，明确的联盟只是使本就会发生的事情具体化。在其他情况下，违背联盟会带来社会污名，因此玩家必须在违背联盟的即时优势与被视为不可信任的长期劣势之间取得平衡。参见 [第17.2节](#Chapter17-02.xhtml#sec17-2) 了解这些复杂情况的更多信息。

如果游戏不是零和，那么协作也可以在只有两名玩家的情况下发生。例如，假设存在一个效用为 `⟨vA = 1000, vB = 1000⟩` 的终止状态，并且 1000 是每个玩家可能获得的最高效用。那么最优策略是两名玩家都尽一切可能达到该状态——也就是说，玩家将自动合作以实现共同期望的目标。
