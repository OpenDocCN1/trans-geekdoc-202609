# 16.3.1 WALLET CREATION

In the proposed system approach, we have considered that each of the stakeholders willing to take part, as any of the roles listed in Table 16.1, must be registered with the blockchain process with their details. The information they need to share while in the registration phase must include at least two identity proof: for example, Indians provide Aadhaar card, voter id, driving license, or passport as proof of identity. Once they are registered and proofs are verified, stakeholders need to apply for wallet assignment process, as shown in Figure 16.3. This wallet assignment process deals with a generation of public-private key combinations, Moreover, each of the stakeholders uses those keys as per the cryptographic applications' requirement. This WiD has a wallet ID WiD to identify the corresponding stakeholder. This WiD also works as pseudonymity of the stakeholder. WiD is generated by applying hash function on the social identity proof. We can use any candidate cryptographic hash function (which we have selected SHA-512) for the process. The private key to protect the privacy of the users, the private key is generated, and mapped to Wi$_{ID}$ information such as name, location, and social identity proofs is all mapped to Wi$_{ID}$ by b bits from the hashed output taking random b bits concatenated with timestamp. The public key is generated by the ring modulo operation on the private keyringing generator.
