# 4.2 BLOCKCHAIN SECURITY

The underlying encryption standard is effectively unbreakable, but cyber-security is always a game of cat and mouse, and there are always side-channel attacks on many technologies, not to mention the dangers associated with securing digital wallets (McCall, 2019).

Blockchain can be applied to secure the software supply chain. Hackers are increasingly finding new vectors of attack, as operating systems and software companies take steps to patch known exploits. One such new method of compromise is through the distribution of software libraries and programs that trick unsuspecting users into installing. In 2017, the official repository for the widely used Python-programming language was infected with modified code packages, which were uploaded to the Package Index. The packages contained the same code as the upstream libraries, but the hackers had also an installation script, which was modified to include malicious code. Source software packages are traditionally verified as authentic by running the file(s) with MD5 hash check. However, this has gained wide use, and methods are found to bypass this mechanism. Blockchain provides an alternative for the verification of ownership. A blockchain, of course, is a distributed database that maintains an ever-growing list of data records secured from tampering. It is decentralized, which is important, as there is no single point of failure and no individual or group can claim ownership, so the groups work together to confirm legitimate new transactions. It is composed of data blocks, where each block holds hashes of individual transactions and the results of blockchain executables. These blocks contain a timestamp and a link to a previous block. The blockchain can, therefore, serve as a public ledger of transactions that cannot be reversed at least without great difficulty or near-system failure.

There is active research in using Byzantine consensus protocols to leverage collective signing to commit transactions irreversibly within seconds (Martino, 2016; Miller et al., 2016). SkipChains can be used to create a blockchain that is cryptographically traceable and efficiently verifiable both forward and backward in time (Malkhi et al., 2000; Malkhi and Reiter, 2013). Here, hashes are used for blockchains and collective signatures for forwarding links. The peer-to-peer (P2P) verifiability properties that SkipChains add will extend the applicability of future blockchain technology. This will also increase its robustness and resilience to communication failures and potentially provide hack-proof verification of software packages.
