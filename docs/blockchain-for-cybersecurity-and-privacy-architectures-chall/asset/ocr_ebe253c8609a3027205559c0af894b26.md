# Blockchain for Cybersecurity and Privacy

Although there may be a direct channel to send a request and receive responses between nodes, they work asynchronously by publishing and subscribe method.
Every single and regular node of Interchain-based IoT environment corresponds to a virtual object (VO) (Farris et al., 2015). Nodes have reserved their own space at the edge of the cloud, no matter what prepared/runs the cloud-based Interchain service. Every node must be equipped with a specific ledger technology and the ability of transaction handling over the environment. It must be able to report its states, both its mission states and its health states. The VO schema of an end node is defined in mention Table 6.1. The VO is not a part of the superblock, and it could be located anywhere in the cloud.

# TABLE 6.1
Virtual Object Schema in an End Node

| No. | Field Name | Access Levela | Description |
| --- | --- | --- | --- |
| 1. | Owner | Public | Owner's identity (machine/human) |
| 2. | Missions | Public | It is a list that is selectable from the person superblock category |
| 3. | Identity | Public | Valid and unique identity in the superblock |
| 4. | Relationships | First friends | Hierarchy of lists |
| 5. | Address (IPv6/Any Valid Uri) | Private/partners | Valid network-level address to make working connections |
| 6. | Ledger transactions | Private | A ledger to keep all transaction information from friendship requests or friends' states to partnership activity logs |
| 7. | Mobility state | Friends | Determines whether the device moves or is fixed |
| 8. | Geolocation | Public | Single-point location, latitude, and altitude of object's location, or if it is a moving object, the value contains the geo-fence |
| 9. | Power mode | Friends | It may contain DC, AC, or both |
| 10. | Latest states | Private/partner | The latest health states that are generated by the node to in monitoring levels |
| 11. | Superblock address | Public | Superblock's valid address (A valid Uri) |
| 12. | Update frequency | Public | The frequency of status update |
| 13. | Uptime level | Public | Determines whether it is a full-time working object or works in specific periods |
