In other ledger technologies such as blockchain, hash-graph also has forking attacks; if, a malicious node creates an event considering the self-parent to be ancestor z after it creates another event and again gives the self-parent hash of z instead of x, then the node has created forking. In order to avoid such attacks, hashgraph makes use of two concepts: a state seeing another event is the red event, which means that it has an entirely downward path to the red event; however, in order to strongly see another, multiple directed paths should be, passing through enough members. Figure 2.3 depicts that the yellow event can strongly see five nodes in the network; so, in order to achieve the supermajority, four of them should strongly see the bottom event; i.e., four will be greater than 2/3. Thus, if an attacker tries to violate the hashgraph by forking, it is not able to violate the consensus process.

Hashgraph works in the following manner: there are four nodes in a network: A, B, C, and D. To start a gossip, B randomly chooses to gossip with D. Therefore, B sent all events that D did not know. After this, D creates another event and records his events along the ones that B has shared; this signifies D's sync between the two places. The new event is created directly to D's previous event and B's last event comprises two hashes, self-parent and the other-parent, which means transactions event, developing a graph of the order in which the nodes communicated. An event creates an event recording the sync. A then gossips to C and sends all his events. D sends all his events to A, and as a result, A creates an event recording the sync. C creates a fresh event recording the events, and this goes on until the information is disseminated in the whole network. Each event has the hashes of the events before it, and all are digitally signed by their creator. Therefore, it is said to be cryptographically secure. The round created for each event is N or N + 1, where N is the maximum of its parents-created rounds. The first event of each round is called a witness, but it's not necessary for each node to have a witness. Further, after determining the witness, we need to find out the next round's witnesses. A node is said to be famous if the majority of the witnesses are seeing it in the next round. After their consent, an election is conducted, the result of which will specify if the witnesses are famous. The witness can see a specific event if has a direct downward link from it.

Distributed consensus has been used very long, but the hashgraph along with the consensus algorithm is said to permit a new platform for it. The distributed algorithm is said to permit permission to reach an agreement on transactional order generated by individuals from the community, keeping in mind that nobody trusts any. Any individual cannot temper with the order of transactions in a hashgraph. For instance, both A and B are being the only headphones that were used at an online store at the same time. If this scenario occurs in blockchain, the transactions could be placed in a single block by the miner, who has the entire authority to choose the order in which the transactions occur. In another case, A's transaction might get included in the block, and B's might get delayed. In the same scenario when plotted in hashgraph, no one can disturb the consensus order of transactions. Another way to justify the fairness of hashgraph is that none of the nodes have the authority to let transactions enter the network or to delay them. Whereas in blockchain, transactions can only be delayed by two or less mining periods. In hashgraph, manipulators cannot stop anyone to record a transaction; the only way that one can do is by disconnecting the user from the network. Therefore, hashgraph is considered to be fair.

In hashgraph, speed depends on the bandwidth. The number of transactions an individual can download per second is the bandwidth 4500 tps, then it appears to be fast enough to grab the whole transaction volume of VISA. Whereas the Bitcoin can handle 7 tps, which are very less compared with hashgraph. Improving the speed may worsen the fairness of blockchain. The property of hashgraph, being provable, is as important as others. When an event takes place in a network, all individuals in the network know quickly about its existence and the order where it needs to be placed. Every individual in the network is certain that all others know about the event. Therefore, if we consider it a cryptocurrency, every individual just has to save the present balance of all wallets that are not void. Any transactions or blocks are not to be remembered, which makes the current size of Bitcoin storage from 60 gigabytes to barely some gigabytes.

The BFT is a property of hashgraph that attains it. In hashgraph, each individual is assigned a time for consensus, and it is the average time at which every individual first received. It, hence is to be timestamped. The timestamp is said to be reliable automatically if the supermajority population is truthful and their clocks are trustworthy. It is considered to be part of consensus; therefore it to Byzantine and provable. The timestamp is beneficial for smart contracts, as the consensus will be if the event occurred in a given time. Whereas in blockchain, every block has a timestamp, but it only redirects the miner's clock who mined the block.

An individual cannot stop the network, and hence is fair. It is considered to be fair-compliant. Efficiency in the blockchain is not 100%, as the block that has been mined at times be marked as stale; therefore, the gets wasted. Whereas in hashgraph, there's no concept of stale; hence, it is considered to be 100% efficient. In Bitcoin, a lot of time, effort, and proof are wasted in calculations (proof of work), which also have to make the speed of mining slower. Expensive hardware needs to be used in order to drive the mining. Whereas in hashgraph, no such mechanism is used; therefore, it is inexpensive.

The Dos resistance is found in both hashgraph and blockchain. An enemy might cease a miner's bandwidth by sending packets and cut off them from the rest for a while, the network keeps working normally. If an enemy needs to attack the entire network, then it will require him to send unwanted packets to a larger population. A lot of blockchain variants have been suggested to evade proof of work. Nonetheless, they are not DOS resilient. If the current leader is being attacked by an intruder and it quickly attacks the new leader, the whole system will be halted in this way.
