# 9.4.7 TENDERMINT

Tendermint is responsible for enabling blockchain features in a BigchainDB network. It first checks the validity of a transaction. Once validated, Tendermint broadcasts the transaction to all nodes in the network. Tendermint also plays a very important role in consensus process. Each node gets a chance to push forward a block for inclusion in a round-robin fashion.

# 9.4.8 MongoDB

MongoDB is a distributed database that stores data in a flexible JSON-like documents. BigchainDB uses MongoDB to query data from the blockchain. BigchainDB, together with MongoDB, provides decentralized control, immutability, and asset autonomy on top of a distributed database. MongoDB consists of different datasets by after installing BigchainDB software. All blockchain data is stored in BigchainDB.

In BigchainDB, there are many collections with each type of data stored. The most used collections are assets, blocks, elections, metadata, and transactions. Collectors store all the assets created by the members in the network and stored in the blockchain, as seen in Figure 9.6. Blocks collection stores the blocks committed to the blockchain. Elections collection stores the data regarding the elections carried out to include a new validator/member in the blockchain. Metadata stores the metadata associated with each asset created. Transactions collections store the data regarding all the transactions that happened between members in the network. Validators show the list of validators along with their power, as seen in Figure 9.7.
