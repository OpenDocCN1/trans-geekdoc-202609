
# Gradient Alignment
This refers to shaping training examples so that their gradients push the model's weights in a specific direction. In poisoning attacks, this technique helps adversaries fine-tune exactly how the model shifts during learning. It's crucial because it makes poisoning highly targeted and efficient, especially during fine-tuning.

# Backdoor Trigger
A backdoor trigger is a pattern or signal hidden in the training data that causes the model to misbehave when seen during inference. We saw how these can be embedded subtly and only activate under specific conditions. These are dangerous because they don't affect the model's normal performance but can be used later to hijack behavior.

# Experience Replay Buffer
In RL, this buffer stores past experiences for training. This chapter showed that attackers can poison this buffer with misleading experiences to corrupt policy learning. Understanding this risk is vital because RL systems depend heavily on accumulated data to make decisions.

# Reward-Shaping Attack
This occurs when attackers manipulate the reward signal during RL. The chapter described how changing the reward—even slightly—can teach agents to prefer bad behaviors. It's critical because it proves that RL systems can be tricked not by inputs, but by the incentives that drive their learning.

# Sybil Attack
In federated learning, a Sybil attack involves an adversary creating multiple fake clients to manipulate the global model. The chapter explained how this amplifies poisoned contributions. This is key because it breaks the assumption that most clients are honest—a cornerstone of federated trust models.

# Transfer Poisoning
This technique poisons a model during fine-tuning after it has been pretrained. The attacker only needs to tamper with a small part of the process to cause lasting effects. It's important because so many organizations reuse pretrained models without knowing their full history.

# Data Camouflage
This involves making poisoned examples look statistically normal to avoid detection. The chapter showed how attackers can blend their poisons into natural data distributions. This matters because it means standard outlier detection may not catch poisoned data.

# Temporal Poisoning
This tactic targets sequences in RL to introduce misleading cause-effect relationships. The chapter highlighted how these patterns can shift policy learning over time. It's a subtle but powerful attack because it exploits the time-based nature of RL learning.

# Layer-Targeted Poisoning
This refers to poisoning that only affects specific trainable layers during fine-tuning. This chapter illustrated how this can bypass detection by leveraging architectural choices. It's significant because many models freeze layers for performance, not realizing those decisions can hide security flaws.

# Policy Distillation Poisoning
This happens when an attacker poisons either the teacher or student model in a transfer-learning setup. We saw how poisoned behavior can survive distillation and be passed down. It's a cautionary point that even secondary training stages carry poisoning risk.

# Latent Space Collision
This is when different-looking inputs end up close together in the model's internal representation space. This chapter showed how this can cause misclassification without affecting surface features. It highlights how adversaries target what the model “thinks,” not just what it sees.

# Poisoned Embedding
A poisoned embedding is a corrupted internal representation learned during pretraining that affects later tasks. The chapter discussed how embedding-level poisoning can propagate into downstream applications. It's a structural vulnerability that reinforces the importance of trusted pretraining sources.

### Adversary Spotlight
If you're an attacker targeting AI, poisoning is a dream scenario: It lets you compromise a system before it's even finished learning. What makes this method so appealing is that it doesn't rely on traditional hacking—it exploits trust in training data, processes, and tools. From the adversary's point of view, models trained on aggregated, third-party, or crowdsourced data are especially juicy. If they can insert just a few malicious examples into a massive dataset or subtly shape gradients through repeated fine-tuning, they can bend the model's behavior to their will—often with no alarms raised.

Backdoors are particularly attractive for attackers who want a persistent foothold. Embedding a trigger during training gives them the ability to activate misbehavior only when it suits them, all while the model performs perfectly under normal use. For example, a facial recognition system might work flawlessly—until it sees a particular hat, patch, or lighting condition that flips its prediction. The precision and stealth of backdoor poisoning make it an ideal tool for long-term subversion.

Federated and RL systems also open interesting opportunities. In federated learning, the adversary sees a chance to join the system as multiple fake clients, each submitting poisoned gradients that the server dutifully aggregates. They exploit the trust assumptions of the protocol. Meanwhile, in RL, the attacker doesn't need to touch the model directly—just the environment or the reward. A small nudge in what counts as “success” can send the agent down an entirely different path.

From a strategic perspective, poisoning isn't about causing chaos immediately—it's about planting quiet, reliable vulnerabilities. A model trained under these conditions may pass every test and perform admirably in production until it's activated. For the attacker, that's the ultimate win: compromise without detection, with the timing and payload of failure fully under their control.

### Common Misunderstandings
* Poisoning doesn't always involve changing labels—many effective attacks use clean, correctly labeled data.
* Just because a model performs well on test data doesn't mean it hasn't been poisoned.
* Fine-tuning isn't inherently safer than pretraining; it can actually be the moment when vulnerabilities are introduced.
* Not all triggers are obvious or visible—some are encoded in subtle feature patterns or temporal sequences.
* Poisoning in RL doesn't require access to the model—it can happen through reward or environment manipulation.
* Using a pretrained model from a public source doesn't eliminate poisoning risk; it may introduce it.
* Aggregation in federated learning doesn't guarantee safety; multiple malicious clients can coordinate to corrupt it silently.

### Defense Framing
The key mindset shift for defenders is to stop viewing training as a trusted, internal activity and start treating it as an attack surface. Whether models are built in-house, fine-tuned on user data, or aggregated from distributed clients, the training process must be scrutinized with the same rigor as runtime behavior. Poisoning happens when trust is misplaced—either in datasets, update procedures, or assumptions about contributors. This means defenders need to monitor inputs, validate contributors, and trace model behavior back to its learning history.

Security teams should build policies around provenance and versioning, not just model accuracy. Knowing where your data came from, how it was labeled, and who touched it is just as critical as knowing what your model predicts. Model updates—especially fine-tuning—should be logged, audited, and treated like code changes with security implications. The idea that a model can be updated freely, without oversight, is no longer sustainable.
