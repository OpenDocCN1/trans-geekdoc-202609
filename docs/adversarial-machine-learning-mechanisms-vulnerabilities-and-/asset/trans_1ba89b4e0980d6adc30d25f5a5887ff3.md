
Multi剂RL系统由于依赖于剂与剂之间的交互作用和共享环境反馈，其攻击面呈现出扩展态势。在该类系统中，中毒行为可能涉及对通信协议的微妙污染、奖励函数的错位或对抗性角色分配，从而破坏合作机制。单个被妥协的剂可能导致整个群体出现连锁学习错误，尤其是当策略相互依赖或共适应时。这些干扰可能在剂在不确定性下需要协作的场景中才显现，此时已学习的策略与预期行为偏离，且通常缺乏明确的归因路径。

RL环境的高维性和随机性为攻击者提供了充足的机会来隐藏其操控行为。中毒经验、伪造的转移或奖励异常可以在复杂环境的自然变异中被统计隐藏。此外，大多数RL系统缺乏严格的数据溯源机制，使得事后中毒检测在实际操作中几乎不可行。记录每个状态、动作和奖励转移的日志在实际应用中成本过高，即便做到了，区分对抗性模式与探索行为也需要深厚的领域知识和取证工具，而这正是少数组织所具备的。[Table 5.3](#c05.xhtml#c05-tbl-0003) 突出了后门触发器的属性及其在部署中带来的相关风险。

持续的中毒攻击在RL领域常常被忽视，因为剂在验证阶段仍表现出名义上的成功。标准评估基准通常是静态的，并未针对边缘或对抗性行为及环境不一致性进行测试。攻击者利用这一点，设计在罕见或攻击者控制的条件下才激活的中毒策略，从而在策略空间中“嵌入”逻辑炸弹。这些隐蔽漏洞可能仅在策略空间的特定状态-动作区域触发，长时间潜伏，直至在高风险决策或罕见操作配置出现时才被激活。

在RL中对中毒进行缓解的难点在于缺乏针对序列决策的形式化验证技术。虽然监督模型可以通过测试集和对抗性示例进行探测，但RL剂本质上具有交互性和状态依赖性。验证其鲁棒性需要在广阔的策略空间中进行模拟并跟踪长序列轨迹，这一过程计算开销巨大且对初始条件敏感。此外，现有的防御措施主要针对显性故障模式，而非持续中毒所引入的微妙、功能性错误行为。

随着RL系统在物理系统、金融、自主控制和工业自动化等领域的部署日益增多，中毒的后果变得更加严重。一个在99%的情况下表现正确但在1%的情况下因嵌入中毒而发生灾难性失败的剂，构成了存在性风险。此类失败难以追溯、难以预见，且部署后几乎无法逆向工程。理解RL动态和策略学习阶段的攻击者能够植入技术上正确但战略上被妥协的策略，从而构建出脆弱、错位或易受利用的系统。

## 转移学习和精调过程中的中毒攻击

转移学习已成为现代机器学习实践的基石，它使开发者能够通过在相对小的数据集上微调预训练网络，快速构建高性能模型。虽然该方法大幅降低了训练时间和数据需求，但也为 adversarial poisoning（对抗性中毒）打开了独特的攻击通路。由于下游模型继承了上游模型的表征，攻击者无需妥协整个架构，而是可通过微调输入数据来微妙地引导预训练模型朝向持续的对抗行为。这些漏洞往往因精调模型在常规评估指标上的表现优异而被忽视。

其中最隐蔽的技术之一是使用中毒的精调数据集。攻击者构造标签正确、结构合法但特征分布微妙扭曲的输入示例。这些中毒样本设计用于在潜在空间中已有的决策边界附近产生局部偏移，特别是针对预训练模型已塑造的区域。当这些中毒示例被注入精调集时，它们利用模型现有的表征，强化错误关联，这些关联在常规验证范围内看似无害。此策略使得对抗性误分类攻击只需少量数据即可实施，并能规避异常检测。

特征碰撞中毒利用高维嵌入空间的结构诱导受控的错误行为。攻击者通过注入在视觉或语义上相似但标签为另一类的精调示例，使模型在类别边界上产生重叠，导致语义上不同的输入在特征空间中趋于接近。这扭曲了精调阶段学习的类别边界，制造模糊性，后续被攻击者利用以强制误分类。由于预训练模型提供固定的嵌入空间，特征碰撞中毒在理解上游模型的表征偏差时尤为有效。即便中毒示例仅占精调集的一小部分，其影响仍可能因模型的强诱导偏见而持续。

梯度对齐中毒提供了一种更精细的影响手段。该技术通过选择或合成精调样本，使其反向传播的梯度能够引起可预测的参数偏移，从而实现与攻击目标一致的调整。攻击者通常使用代理模型优化这些中毒输入，确保每个中毒样本在最大程度上将决策边界朝所需方向推进。随着多个epoch的迭代，这种梯度操控在不显著影响常规性能指标的前提下，逐步重新定位模型权重。被中毒的模型在常规输入下表现正常，但在攻击者设计的测试案例下会表现出受控的失败。
