
: Layer-targeted poisoning is a form of model corruption in which poisoned data is crafted to affect specific internal layers of a neural network. Instead of altering output behavior directly, the attack changes how particular layers represent or process information. This can result in latent vulnerabilities that are only revealed under specific conditions or inputs. 

`# Layer-Wise Relevance Propagation`

: Layer-wise relevance propagation (LRP) is a technique used to explain model predictions by tracing how input features contribute to the final output across each layer of a network. It helps visualize which features are most influential and can uncover hidden biases or backdoors. LRP is a core tool in explainable AI and model auditing. 

`# Lifecycle-Aware Threat Modeling`

: Lifecycle-aware threat modeling is the practice of assessing adversarial risks across all stages of an AI system's lifecycle—from data collection and training to deployment, monitoring, and decommissioning. This comprehensive view helps identify attack surfaces that change over time. It is essential for building resilient and trustworthy AI pipelines. 

`# Linguistic Perturbation`

: Linguistic perturbation involves modifying natural language input—such as by changing synonyms, syntax, punctuation, or grammar—to deceive language models without altering semantic meaning. These changes are used to evade filters, confuse classifiers, or test model robustness. It is a common method in adversarial attacks on text-based systems. 

`# Logic Bomb`

: A logic bomb is a hidden piece of code or condition embedded in a model that triggers malicious behavior when specific criteria are met. These are typically planted during training or fine-tuning and lie dormant until activated. Logic bombs are difficult to detect and pose a serious threat to AI supply chain integrity. 

`# Logit Margin Check`

: Logit margin check refers to evaluating the difference between the top two logits—unnormalized output values of a model—to assess confidence and decision sharpness. Small margins may indicate uncertainty, adversarial influence, or label ambiguity. This check is used in robustness analysis and model auditing. 

`# Low-Frequency Perturbation`

: Low-frequency perturbation is a visual attack technique where changes are made in smooth, broad patterns rather than pixel-level noise. These perturbations are harder to detect and can be more robust to compression, scaling, or environmental noise. They are effective in fooling image classifiers and detection models in real-world settings. 

`# Membership Inference`

: Membership inference is a privacy attack where an adversary determines whether a specific data sample was included in a model's training set. This reveals potentially sensitive information and violates data protection principles. It is especially concerning for models trained on private or regulated datasets. 

`# Memory Module`

: A memory module is a component within a machine learning system—often used in agentic or sequence-processing architectures—that stores and retrieves past observations, decisions, or interactions. If improperly secured, it can be manipulated to reinforce biased patterns or leak sensitive data. Attackers may target memory to induce long-term behavioral drift. 

`# Memory Poisoning`

: Memory poisoning occurs when adversaries inject corrupted or malicious data into a model's memory module, influencing future predictions or decisions. This is particularly dangerous in systems that rely on retrieval-augmented generation or experience replay. Poisoned memory may persist long after the initial attack. 

`# Memory Retrieval Vulnerability`

: Memory retrieval vulnerability refers to weaknesses in how an AI system accesses and ranks previously stored information from its internal or external memory. Attackers may exploit this by injecting misleading content into memory or manipulating query mechanisms to retrieve harmful or false entries. These vulnerabilities are particularly relevant in agentic systems and chatbots with long-term memory. 

`# Memory Sanitization`

: Memory sanitization is the process of auditing, filtering, or clearing stored data from a model's memory to prevent the accumulation of harmful, sensitive, or adversarial content. This process is critical for maintaining trust in systems that learn from user interactions. Improper sanitization can leave residual exploits embedded in memory systems. 

`# Metadata Spoofing`

: Metadata spoofing involves forging or manipulating metadata—such as timestamps, sources, authorship, or tags—to mislead models that rely on contextual or auxiliary data. It can be used to inject false authority, manipulate ranking algorithms, or misguide generative systems. It is a stealthy vector for influencing outputs without altering core content. 

`# Model Alignment`

: Model alignment is the process of ensuring that an AI system's goals, behaviors, and outputs remain consistent with human intentions, values, and expectations. Alignment challenges arise when models generalize in unpredictable ways or misinterpret instructions. Misalignment can lead to unsafe actions, especially in high-autonomy or high-stakes settings. 

`# Model Extraction`

: Model extraction is a type of attack where an adversary recreates a target model by querying it repeatedly and observing outputs. This reverse-engineering process can leak intellectual property or expose the model to further attacks. Even black-box models exposed through public APIs are vulnerable to extraction with enough queries. 

`# Model Inversion`

: Model inversion is a privacy attack where adversaries use model outputs to reconstruct input features or entire records from the training data. This can reveal sensitive attributes such as medical details, images, or private identities. The attack exploits overfitting or memorization tendencies in the model. 

`# Model Lineage`

: Model lineage tracks the ancestry and modification history of a model, including base checkpoints, fine-tuning stages, and data sources. Maintaining clear lineage is essential for auditing, reproducibility, and verifying model trust. Gaps in lineage records can mask the presence of inherited vulnerabilities or backdoors. 

`# Model Poisoning`

: Model poisoning is the act of deliberately corrupting the training process—through poisoned data, gradients, or loss functions—to degrade performance or embed malicious behaviors. Unlike data poisoning, model poisoning can also involve modifying learning algorithms or injecting harmful logic directly. It is one of the most persistent and difficult-to-detect attack classes. 

`# Model Reprogramming`

: Model reprogramming is an adversarial technique where an attacker uses crafted inputs to repurpose a model to perform an entirely different task than intended. This is often done without altering the model's architecture or weights. Reprogramming exploits the model's flexibility to perform tasks outside its original scope. 

`# Model Supply Chain Contamination`

: Model supply chain contamination refers to the introduction of vulnerabilities—such as backdoors, bias, or poisoned data—during any phase of the model's creation, transfer, or deployment. This includes risks from pre-trained models, third-party libraries, or deployment infrastructure. It represents one of the most dangerous and least visible threats to trustworthy AI. 

`# Model Versioning Exploit`

: A model versioning exploit targets weaknesses introduced through updates or changes to model versions over time. Attackers may test old and new versions for behavioral drift, vulnerabilities, or regressions that allow successful adversarial inputs. Improper change management can lead to inconsistent security guarantees across model releases.
