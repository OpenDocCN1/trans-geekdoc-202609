
随着生成模型在内容创作、决策支持和自主代理中变得日益中心化，通过微调梯度来隐藏决策逻辑的能力成为高影响力的威胁向量。攻击者不再需要从零训练模型或入侵托管环境；他们只需获得微调流程及适当的接口，即可引入经过梯度优化的负载。防御者必须调整策略，不仅要关注运行时监控和静态评估，还需引入梯度感知的验证方法，以在模型投入生产环境前检测并中和深度植入的特洛伊木马。

## 跨模型和可转移的对抗性微调攻击

跨模型对抗性微调攻击旨在利用生成模型家族之间的架构相似性和共同漏洞，使恶意行为能够在一次嵌入后在广泛的下游系统中激活。攻击者不再为单一目标模型定制攻击，而是构建微调数据集或扰动策略，使其在多种模型架构上产生一致、可转移的行为。这些攻击认识到许多组织使用相似的基础模型（如基于GPT的变压器），并通过迁移学习或领域自适应而非从零训练模型。因此，一个精心构建的微调攻击即可在不同环境、应用甚至行业中影响多个系统。

该攻击模型的有效性取决于在微调数据中识别出能够利用预训练模型共享嵌入结构的扰动。这些扰动可能包括语义构造、触发短语或始终影响输出行为的上下文模式，无论具体架构如何。通过分析不同变压器变体在自回归生成时如何编码意义并调整token概率，攻击者识别出可靠触发的共同敏感点。这些触发模式随后嵌入到微调数据集中，该数据集不仅优化恶意影响，还兼顾跨模型兼容性。

执行此类攻击需要在多个模型家族上进行大量实验，通常涉及GPT、基于BERT的生成器或编码器-解码器混合架构等流行结构。攻击者系统地评估候选扰动在各模型上的响应，跟踪哪些触发-响应关系跨越架构边界保持一致。评估指标包括激活一致性、输出偏差和语义忠实度。在多个模型中表现出高度一致行为激活的扰动会被保留并优化，而导致模型特定或不稳定输出的扰动则被舍弃或修改。

一种特别有效的技术是利用普遍采用的预训练检查点作为特洛伊嵌入的基底。这些包括开源或商业发行的模型，它们是许多下游应用的基石。攻击者通过公开仓库或微调贡献，在其中一个通用基线上植入恶意行为，确保后续采用或适配该模型的组织在不知情的情况下继承该 adversarial behavior。这种模型供应链污染策略实现了低投入、高覆盖范围的妥协，下游开发者在不知情的情况下将易受攻击的模型部署到生产环境。[Table 11.2](#c11.xhtml#c11-tbl-0002) 列出了在敏感部署领域中被重新编程模型中常见的行为指标。

这些攻击还利用了许多生成模型虽然独立训练，但由于共享语料库的普遍性，在常见token上会趋于相似的表示。当token嵌入、位置编码或注意力头配置在架构之间对齐时，在一个模型中诱导行为转变的微调更新往往在其他模型中产生类似效果。这种跨模型嵌入相似性使攻击者能够构建行为锚点——让模型在特定语言模式与攻击者定义的输出关联时，即使架构存在细微差别，也能可靠触发。

为提升可转移性，攻击者在设计对抗性微调数据集时会采用多模型 ensemble 优化。这意味着在并行训练和测试多个模型的过程中，计算一个综合损失，该损失惩罚跨架构的行为不一致。最终，只有在所有候选模型中都可靠触发恶意输出的示例才会被纳入最终数据集。这些扰动形成一种通用的对抗性刺激，能够在任何使用该数据集训练或适配的模型上激活嵌入行为，即使原始模型架构未知。

在多租户 AI 环境（如云 API 服务）中，这种技术具有特别高的危害性。不同客户共享基础模型基础设施，但为其专有用例微调模型。嵌入式特洛伊可以隐藏在共享基础设施中，待下游用户以某种方式微调模型时，未经意间保留或强化了 adversarial 路径。由于嵌入行为设计为跨任务域和采样配置的鲁棒性，即使模型被定制，攻击者的条件仍会持续存在。

可转移性还扩展到不同的推理环境和任务类型。精心设计的跨模型微调攻击可以在生成对话、摘要、代码合成甚至图像说明模型中诱导误行为，只要它们共享基础结构或token嵌入策略。这在多模态或跨域部署环境中尤为危险，因为同一模型骨架被重复使用时，特洛伊行为可能在意想不到的上下文中复苏，导致有害完成或偏向输出，远离攻击者原始领域。
