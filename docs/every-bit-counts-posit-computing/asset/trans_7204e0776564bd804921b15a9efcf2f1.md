
这与“单精度”、“双精度”或“8位精度”等术语一致：它是指可用于表示数字的位数，与“准确性”**不**同。这在[第2章](#chapter2.xhtml)中已有介绍，但值得重申，因为许多本该懂得更多的人仍然混淆精度和准确性。例如，浮点格式中相对准确性的锯齿模式最初被称为“摆动精度”，这个术语沿用至今，尽管`precision`稳如磐石。有效位的精度也是恒定的；那里没有摆动。摆动的是`relative accuracy`。这在[第2章](#chapter2.xhtml)中已有解释。

`quire`是一种定点格式，拥有足够的精度来**精确**计算posit点积（乘积之和）。它功能强大且重要，以至于专门用一整章来介绍它的用法。硬件支持精确点积（有时称为`scalar`积）的想法源自卡尔斯鲁厄理工学院的Ulrich Kulisch教授，他在1970年代提出了这一想法，但未能将其纳入任何IEEE标准中。

请注意`quire`和`quire value`的区别。`quire`是一种格式（一组位域及其含义），而`quire value`是quire格式中位模式所表示的实数。Posit标准同样小心区分`posit`（一种数字格式）和`posit value`。我们的工作组成员Hauke Rehr功不可没，他发现了早期草案中措辞不一致的地方，并确保了措辞的一致性。在本书中，我经常用“posit”指代“posit value”，只要上下文清楚即可，例如“两个posits的乘积”。

如果quire能存储两个长度为`m`的向量的点积`a[1] · b[1] + a[2] · b[2] + … + a[m] · b[m]`（最大长度可达约二十亿个元素），那么它也能精确计算长度上限内的求和。只需设想其中一个向量全为1值：`b[1] = b[2] = … = b[m]`；此时点积就是`a[i]`值的和。对数字求和比对数字的`products`求和要求低得多，因此能保证无溢出或舍入错误可能性的求和最大长度远大于二十亿。你必须反复将`maxPos`加到求和中，共`2^(23+4) *^n`次，求和才会溢出。即使对于8位posits，quire求和上限也约为36千万亿次求和。浮点程序中累积舍入误差的最大来源之一是大量数字的求和，因此Posit标准明确指出quire可以消除这种舍入误差的累积，还能让并行处理器完美执行累加，使结果与串行执行相匹配。

[第1章](#chapter1.xhtml)和[第3章](#chapter3.xhtml)已解释过regime和regime位，但由于Posit标准将指数位数固定为2，因此无需定义`uSeed`，许多定义也大大简化了。在Posit标准中，`uSeed`值始终为`2^(2²) = 16`。

Posit标准中无需使用“正确舍入”这一短语，因为所有舍入都必须是正确的。每个实数都舍入到恰好一个posit值，且只有一种方法可以做到这一点。

请注意`sign`（其值为–1、0、1或NaR）和`sign bit`（其值可以是`0`或`1`）的区别。Posit标准避免了将符号视为`(−1)^s`（其中`s`是符号位的值）这种过度简化。

因为负posit值的隐含值为−2，正posit值的隐含值为1，隐含值加上`[0, 1)`范围内的小数部分，会产生落在`[−2, −1)`或`[1, 2)`范围内的尾数。与浮点数不同，尾数包含值的符号。

## 5.4 Posit和Quire格式章节

计算机通常设计为数据大小为2的整数次幂（如16、32、64）有一个简单的原因：它消除了索引数组时两个整数相乘的开销。你只需将索引左移并加上基地址。这种情况大概率会持续，因此Posit标准给出了8、16、32位的示例尺寸，尽管它也适用于`posit5`等奇特尺寸。

64位示例明显缺失；这是因为使用posit格式时，对这种高精度的需求要小得多。对于两个指数位的情况，quire总是`16*n`位长，且每一位都算作尾数位，因为它是定点数。这意味着`posit16`在`fovea`（中央凹区）约有5位十进制精度，却由一个拥有`16 × 16 = 256`位精度的quire支持，约合76位十进制精度。这比IEEE八倍精度浮点数的精度还高。当需要更高精度时，quire不仅能做精确点积；还能通过稍后描述的技术进行扩展精度除法和平方根运算。

虽然通常将浮点数或posit描述为`±(1 + f) × 2^e`（其中`f`是`[0, 1)`范围内的`fraction`），但它们也可以用两个`integers`表示为`K × 2^M`。与IEEE浮点数不同，posits具有优雅的特性：`K`和`M`的范围总是关于0对称的。例如，对于`posit16`，`K`范围是-4095到4095，`M`范围是-56到56。对于精度为`n`且`n > 4`的posits，

如果`n = 2, 3, or 4`，`K`范围是-1到1，因为小数位始终是幂灵位（ghost bits），即`0`。上述所示的`M`范围对`n = 2, 3, or 4`仍然适用。`K`范围对硬件设计很重要，因为除其他原因外，它决定了整数乘法器需要多大。乘法器在芯片面积方面通常是算术逻辑中较昂贵的部分之一。

相比之下，对于IEEE binary16（半精度浮点数），`K`范围是-2047到2047，`M`范围是-24到15，不同精度的范围确实没有规律，因为指数位数不是作为精度的简单数学函数设计的。

描述右侧有`m`位小数位的定点格式的一种方法是说它是一个整数，代表`2^(-m)`的倍数。这与Posit标准中的解释类似。该脚注源于一位研究人员提出的一个有趣问题：“两个`n`位posits的乘积是否总是适合放入一个`2n`位的posit中？”答案是肯定的，尽管证明很棘手。

一些数值分析师声称，单精度浮点数的点积——*几乎*总是——可以通过使用双精度来保存成对乘积和累加和，然后将和转换回单精度来变得准确。论据是，双精度IEEE浮点数总是有足够的小数位和指数位来容纳两个IEEE单精度浮点数的乘积，这是真的，但累加呢？
