
约翰·阿塔纳索夫于1937年底（独立于楚泽）意识到了二进制表示和布尔运算的必要性，但他想要一台全电子机器，因此使用了真空管。该机器使用50位（相当于15位十进制）整数而非浮点数，来求解线性方程组。阿塔纳索夫构想了将数据存储与执行运算的设备分离的想法，并为计算设备的该部分创造了“存储器”一词。

![1942年重建的阿塔纳索夫-贝里计算机及其前所未有的创新思想](images/pg76_1.jpg)

1938年完成了一个缩小版原型机，而用于求解最多29元一次方程组的全尺寸设计于1942年完成。第二次世界大战实际上终结了阿塔纳索夫和楚泽的努力。

1940年，约翰·莫克利和J·普雷斯珀·埃克特在宾夕法尼亚大学计划制造一台*模拟*设备，但当阿塔纳索夫向莫克利传达他所谓的“真正”计算理念（即我们现在称之为*数字*计算）时，莫克利和埃克特从构建模拟电子数值积分仪（ENI）转向构建数字电子数值积分计算机（ENIAC），于1946年2月完工。他们没有采用带有布尔逻辑的真正二进制，而是希望ENIAC按人们的方式进行算术运算，因此利用真空管的通断状态从0计数到9，然后进行进位操作，这模仿了斐波那契从印度人那里传来的小学算术经典算法。常数是十位十进制整数，通过机械旋钮设置；它可存储二十个此类常数。

这就是奎维多和楚泽所做的。如果奎维多真的制造了他的设计，他就会意识到魔鬼藏在细节里。楚泽注意到表示零很难，这造成了科学计数法规则的一个例外。位域设计源于拟人化的冲动，并导致了低效和非数学化的行为。

20世纪50年代初，当IBM刚刚推出电子（真空管）计算时，他们用位域思维来设计*整数*。“让我们用第一位表示整数的符号，其余位表示大小。”当时，这似乎和其他方法一样好。工程师们可以查看位模式，并（几乎）读出二进制，稍加练习即可，因为符号-幅度表示法模仿了人类在位值数字前加“+”或“-”来书写整数的方式。例如，在六位精度下，`000101`表示+5，`100101`表示-5。

但如何表示零的两种方式，即“正零”`000000`和“负零”`100000`？它们代表同一个实数零吗？还是有别的情况？如果我测试`100000 < 000000`，计算机会返回真还是假？变通方法是，*如果幅度位为零，则符号位不计数。*这意味着硬件必须测试特殊情况，这会降低速度；这也意味着“每一位都算数”并不成立，至少不总是成立。这是冗余位模式的最早案例之一：用多个位模式表示同一个数字。

当你将位域思维与拟人化的科学计数法相结合时，就会得到*浮点格式*。这与首先将格式的理想属性确立为设计目标的工程方法截然不同。这也不同于询问一组位到实数词汇表的逻辑映射是什么的数学方法。

20世纪50年代最成功的科学计算机来自IBM，一个数据“字”是36位，而非32位。IBM 704是第一个支持浮点运算的商用系统，以真空管作为开关元件。

“特征数”一词加引号是因为它是IBM对指数的称呼，但这不是正确的数学术语。在使用对数表进行乘除运算的年代，log(*x*)的小数部分称为*尾数*，如果从log(*x*)中减去小数部分，剩下的整数部分称为*特征数*。所以如果log(*x*)是2.30，尾数是0.30（查表的部分），特征数是2（预期你能用笔算加减）。但如果log(*x*)是-2.30，尾数是0.70，特征数是-3，始终保持尾数在0到1之间。如上图所示，这*不是*IBM浮点数的工作方式。“特征数”位域本应称为“偏移指数”，偏移量为128。更糟糕的是，阿瑟·伯克斯开始称小数部分为“尾数”，再次将浮点数与对数混淆，术语上的混淆延续至今。

在上例中，指数位代表*m* = 6，小数位代表$n = \frac{18513}{2^{16}} \approx 0.\text{282486}$。符号位为`1`表示值为负（符号-幅度表示法，就像IBM在1950年代用于有符号整数那样）。所以值为$- n \times \text{2}^{m} = - \text{2}^{\text{6}} \times \frac{18513}{2^{16}} = - \frac{18513}{1024} \approx - \text{18}.0\text{791}0\text{1}$（精度略高于8位小数）。该计算机的文档使用上述例子，并说明所表示的值为-18.0790，这表明其作者是手工计算的，并出现了抄写错误或舍入错误。

因为IBM还在1956年推出了Fortran，这是第一种比汇编语言级别更高的商用语言，且能识别浮点指令，IBM开始了其统治科学计算的道路，其主要竞争对手是Sperry（UNIVAC系列）和Burroughs。
