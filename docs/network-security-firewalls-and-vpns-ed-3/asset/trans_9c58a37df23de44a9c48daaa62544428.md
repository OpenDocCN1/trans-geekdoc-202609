

## 重放攻击

重放攻击也称为[回放攻击](#30_glossary.xhtml#gloss349)。当黑客使用网络嗅探器捕获网络流量，然后在稍后的时间将该流量重新传输回网络时，就会发生[重放攻击](#30_glossary.xhtml#gloss401)。重放攻击的目标是获得对系统的交互或会话访问权限。

为重放攻击而捕获并重传的流量是认证数据包（**图 2-7**）。在这种类型的攻击中，黑客捕获客户端和服务器之间的流量，然后稍后将其重传给与原始通信相同的服务器。重放攻击通常专注于认证流量，希望重传允许真实用户登录系统的相同数据包能授予黑客相同的访问权限。

**图 2-7** 重放攻击收集认证数据包，然后在稍后的时间重传这些数据包。

幸运的是，您可以通过使用几种常见的通信改进来挫败大多数重放攻击。许多认证事务包含一个无法重放的随机质询-响应对话。该对话由一端生成一个发送给另一端的随机种子值组成。第二端使用双方都知道的共享密钥，通过单向计算得出响应。响应返回给原始端点，在那里会与预期的响应进行比对。如果接收到的响应与预测的响应匹配，则用户通过认证。

时间戳是防御重放攻击的另一种手段。某些认证交换包含编码的时间详情，如果不被检测到，这些详情很难复制或修改。此外，使用一次性密码本或基于会话的加密可以使重放攻击变得不可能。

### 插入攻击

[插入攻击](#30_glossary.xhtml#gloss239)形式多样，但都涉及向原本安全的基础设施引入未经授权的内容或设备。三种常见的基于插入的攻击包括 SQL 注入、IDS 插入和流氓设备插入。了解网络上应该有什么，并丢弃意外的或格式不正确的数据包，能极大地减少这类攻击。

[SQL 注入](#30_glossary.xhtml#gloss478)是一种将黑客代码插入到网站托管的脚本中或通过数据库查询进行的攻击。SQL 注入攻击可使黑客访问 Web 应用程序的后端数据库。该技术利用了常见 Web 通信中的一个弱点，即某些字符因被赋予特殊含义或用途而受到不同对待，而非仅作为文本处理。这些被称为[元字符](#30_glossary.xhtml#gloss297)，充当编程标记。如果您不以防御方式编写脚本以阻止或忽略元字符，那么注入攻击就可以根据黑客提交的内容有效地重写脚本。注入的代码几乎可以执行任何可想象的命令行任务。

[跨站脚本 (XSS)](#30_glossary.xhtml#gloss106) 类似于 SQL 注入，但其结果是攻击网页的未来访问者，而不是授予黑客访问后端数据库的权限。XSS 攻击向网站提交脚本代码。XSS 可能导致 Web 源文件持续遭到恶意修改。这会导致该网站的所有未来访问者接收到被篡改的内容。

XSS 攻击可能包含发送给受害者的电子邮件，其中带有伪造的超链接，当受害者点击电子邮件中的嵌入链接时，将脚本注入指向目标站点。此类攻击可授予黑客访问受害者看似安全的 Web 事务的权限。这种攻击形式是非持久性的，因为它仅影响点击恶意邮件中链接的人。

[IDS 插入](#30_glossary.xhtml#gloss233)是一种利用网络型 IDS 特性的攻击形式；它收集并分析每个数据包，欺骗 IDS 认为发生了攻击，而实际上并未发生。IDS 插入攻击的常见目的是欺骗对恶意网络事件的特征或模式匹配检测。通过将攻击流量与目标主机会拒绝但 IDS 会查看的数据包穿插在一起，IDS 无法识别攻击模式，但攻击仍然会发生。例如，假设一个攻击由四个数据包 A、B、C 和 D 组成，而 IDS 特征是 ABCD 数据包流。如果黑客以 AXBCYD 的形式传输攻击，其中 X 和 Y 是目标拒绝的无效数据包，则 IDS 无法识别该模式。在 X 和 Y 被丢弃后，ABCD 攻击将针对目标发生。

[流氓设备插入](#30_glossary.xhtml#gloss414)是一种物理形式的插入攻击，黑客将冒充设备插入基础设施中。最常见的例子是插入一个配置类似于真实授权接入点的流氓无线接入点 (WAP)。一些用户可能会被骗连接到流氓接入点。这将构成中间人攻击，黑客将拦截受损系统的所有事务。智能手机可以模仿 WAP。另一种插入攻击是前面讨论的物理键盘记录器。

每种插入攻击方法都要求您创建独特的防御措施。您可以通过防御性编程和输入过滤来防止 SQL 注入攻击。如果您使用防御性编码技术、元字符过滤和输入验证，通常可以防止 XSS 攻击。对于最终用户，防御措施包括 Cookie 管理以及在浏览器和电子邮件客户端中禁用脚本支持。通过使用现代 IDS 技术（如异常检测、行为检测和启发式检测）来平息 IDS 插入攻击。您可以通过加密通信、预配置网络访问、禁止无线网络、用户培训和定期现场勘测来挫败流氓设备插入。

### 分片攻击

[分片攻击](#30_glossary.xhtml#gloss189)是对 IP 数据包分片偏移特性的滥用。当许多不同的网络链路连接在一起构建全球基础设施时，就会发生[分片](#30_glossary.xhtml#gloss188)。某些网段支持的数据报（数据包或帧的另一个术语）比其他网段小，因此较大的数据报会被分片成较小、更兼容的大小。当原始数据报的分片元素重新组装时，对分片的操纵可能导致几种潜在的恶意重组，如重叠和溢出。请想象《星际迷航》中的传送器：如果有任何东西妨碍了被传送者的重组，您可能会得到一个留着山羊胡的邪恶斯波克先生。

重叠可能导致数据报组件的完全或部分覆盖，从而由先前数据报的部分创建出新的数据报。溢出可能导致过大的数据报。其他分片攻击会导致 DoS 或混淆 IDS 检测和防火墙过滤。

防范分片攻击的措施包括现代 IDS 检测和防火墙过滤功能，以及执行发送端分片。发送端分片查询网络路由以确定最小的[最大传输单元 (MTU)](#30_glossary.xhtml#gloss292) 或数据报大小。然后发送端预先对数据进行分片，以确保在途中无需进行分片。“斯科蒂先生，把我传上来——并确保我完好无损地回来。”
