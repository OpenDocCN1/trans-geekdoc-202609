
From the Troubleshooting webpage, clicking the “Hardware” link in the left pane displays a list of troubleshooting topics, including one for halting and powering off the firewall. This may be required for system or network upgrades, hardware replacement, or troubleshooting network problems. This section also includes information on how to access various console types, such as if a physical connection is required through a serial console.

A part of every testing and troubleshooting session should include log review. Logs capture information on specific events occurring on a device. Some logs have set defaults that are sufficient for most businesses, while other logs should be reviewed to ensure that what your organization requires is captured. Once an event ends, it is usually too late to recreate that information. Evaluate log details and storage options (such as length of retention, location of storage, and backup of logs) against company policies to ensure compliance. Consider the type of activity where logs would be consulted (testing, troubleshooting, nonrepudiation, and tracking a hacking attempt) and identify whether the information stored will be sufficient. Some of the available log files include firewall logs, system logs, routing logs, gateway logs, filtering logs, copying logs, and routing logs.

### CHAPTER SUMMARY

Firewalls provide protection from Internet threats to servers, workstations, and devices, and they can be configured to allow only specific traffic based on what an organization wants to allow. Organizations typically define what kind of traffic is acceptable in a comprehensive, written security policy. IT professionals then identify a firewall solution that can fulfill and comply with the policy within the established budget.

pfSense is an Internet firewall that can protect an organization’s network. This chapter demonstrates how to configure and use a firewall such as pfSense using a web-based GUI. pfSense is an open-source firewall, requiring no knowledge of Linux to install or use. pfSense turns any typical PC, or Internet-capable device that meets the specifications, into a network appliance with functionality to route network traffic to and from the Internet, assign IP addresses, and protect the private side of the network from intrusion.

## Firewall Deployment Considerations

## CHAPTER 7

FIREWALLS CAN BE COMPLEX security solutions. You should plan the deployment of a firewall carefully, whether for a small home office or for a large corporation. Evaluate as many firewall deployment considerations as possible before you begin to ensure that you are making the best choice for your network and circumstances.

Make a clear determination as to which types of traffic you will allow to cross the network border and which types you will block. Evaluate common security strategies, including security through obscurity, principle of least privilege, simplicity, defense in depth, defense diversity, chokepoint, weakest link, fail-safe, and forced universal participation. Integrate each strategy you want to use into the organization’s security policy and its firewall deployment.

The actual deployment of a firewall is a fairly straightforward process. This process begins with understanding the network environment, it includes selecting a product that satisfies security needs, and it ends with a more secure network infrastructure. Toward that end, this chapter examines a few of the remaining concepts that are often part of the decision-making process.

Determine whether features such as reverse proxy and port forwarding are necessary to the infrastructure’s network communications. Weigh the benefits of bastion host OSs before using new firewalls. Understand how monitoring and logging, interpreting firewall logs and alerts, and intrusion detection and prevention complement firewalls.

Every organization is different and must evaluate its own business and security needs. Determine which tasks are essential, which are optional, which are personal, and which are malicious. Use firewalls and other controls to support necessary traffic and block everything else. Security administrators are responsible for evaluating needs and solutions, and for preparing a response when security and business needs are incompatible.
