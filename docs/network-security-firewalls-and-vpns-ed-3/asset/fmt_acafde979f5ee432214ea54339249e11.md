
# Computer Networks and Network Devices

Computer networks are an essential part of most businesses today. Whether that business is a small home-based office or a multinational organization, computer networks often reduce the cost and time of sharing resources and increase business efficiency. Understanding how a computer network functions is essential to understanding how to secure such a network environment.

In the context of networks, the term [topology](#30_glossary.xhtml#gloss502) references the order and arrangement of the elements of a communications network. Topology has often been described as what the computer network would look like if the roof were open and you could see all the computers and peripherals clearly connected together below. The way in which computers and network peripherals are connected determines which communication methods may be used on the network, what hardware is required, and whether redundancy exists.

Obviously, it is not easy to look down into a building from the roofline, but you can create network diagrams and network maps that aid in understanding the connections and communication pathways that exist. These diagrams are an essential tool in troubleshooting network problems and issues, because the difference between what you expect to find and the way the network is configured is often the issue to be addressed or corrected.

Before continuing into the various topology options available for configuring a network, it is logical to define the different types of devices and appliances that are commonly found in networks, which helps make a network topology more understandable.

## Types of Network Devices

Computers and servers, including blade servers and special-purpose computers, are typically found on networks, but there are many other devices used for efficiency, segregation, or security.

A [hub](#30_glossary.xhtml#gloss227) is a device that consolidates or collects the wires and connections of other computers and devices. Often, a server supports more than a few computers, which would require each computer to connect to the server individually. Most servers do not come equipped with enough individual ports to accommodate this type of connection. A hub simply collects the individual physical wires and provides a single connection to the server ([**FIGURE 3-1**](#12_chapter03_02.xhtml#fig3-1)), limiting the physical wiring and streamlining the connections. A simple collection hub is commonly considered a [dumb hub](#30_glossary.xhtml#gloss150) or [passive hub](#30_glossary.xhtml#gloss335) because there is no logic or power within the box—it is only a collection point for wires.

![FIGURE 3-1 A hub on a simple local area network.](Images/9781284183658_CH03_FIGF01.png)

**FIGURE 3-1** A hub on a simple local area network.

A [punchdown block](#30_glossary.xhtml#gloss382), also known as a [punch panel](#30_glossary.xhtml#gloss381), is an example of a hub, although it is not shaped like a traditional passive hub. A hub is an Open Systems Interconnection (OSI) Layer 1 (Physical Layer) device because it physically connects the wires together into a single appliance. A hub is nondiscriminating, and many data collisions occur due to the pass-through behavior of the device. Traffic coming in on an inbound port is sent to all other ports connected to the device, whether or not the data is intended for that port and the connected devices, which makes for additional traffic generation and bandwidth usage.

Another type of hub is the [smart hub](#30_glossary.xhtml#gloss465) or [active hub](#30_glossary.xhtml#gloss5). This type of hub has some intelligence built into it. These are the most common hubs on the market and often do not include “smart” or “active” in the naming convention of the product. Other common terms for these devices include [concentrators](#30_glossary.xhtml#gloss95) and repeaters. These terms are applied because this type of hub often concentrates the signal as it enters the device, and it can strengthen the signal through the repeating process as the signal exits the device.

Historically, smart hubs included some simple management software that enabled network administrators to perform basic commands and elicit statistics about the network’s performance, such as throughput measures, uptime percentages, routing table entries, and other valuable information for troubleshooting and baselining. Many of these same measures can be performed from the various servers and devices on the network. However, because a hub is a consolidation point, information consolidation typically performed by the user is done by the smart hub instead.

A [repeater](#30_glossary.xhtml#gloss400) is a type of hub that rebuilds the signal received through a bit-by-bit process. It does not amplify the data; it rebuilds it to pass it on. This function is necessary because a natural consequence of long segments of network cable, or distance between wireless devices, is that the signal can become weak or degraded. A repeater prevents data loss by offering the newly reconstructed packet at a stronger signal strength so it can continue through the network to its destination. Active hubs extend the distance available between devices or network segments.

A [switch](#30_glossary.xhtml#gloss487) is a Layer 2 (Data Link Layer) device that uses Media Access Control (MAC) addresses to differentiate traffic. A typical switch is shown in [**FIGURE 3-2**](#12_chapter03_02.xhtml#fig3-2). The MAC address is a unique hardware identification number assigned by the manufacturer under guidance of the Federal Communications Commission (FCC). Each node on the network has a network interface controller (NIC), which has a unique MAC address. Because the switch reviews the MAC address in determining where each data packet is meant to go, there are no collisions; the data packet is sent only to the intended destination (if it exists). If the destination address does not exist, the packet is dropped. Switches are typically used in large networks. They become a point of connection within a network because they switch to the proper port when sending packets to the intended recipient device. A switch can perform some error checking and discard any packets with detected errors.

Switches provide network segmentation through hardware. Across a switch, temporary dedicated electronic communication pathways connect the endpoints of a session (such as a client and server). This switched pathway prevents collisions. Additionally, switches allow you to use the full potential throughput capacity of the network connection by the communication, instead of wasting 40 percent or more by collisions (as occurs with hubs). See [**FIGURE 3-3**](#12_chapter03_02.xhtml#fig3-3).

![FIGURE 3-3 An example of switch deployment.](Images/9781284183658_CH03_FIGF03.png)

You can see this basic function of a switch as a security benefit once you examine how this process takes place. A switch operates at Layer 2, the Data Link Layer, of the OSI model, where the MAC address is defined and used. Switches manage traffic through the use of the source and destination MAC address in an Ethernet frame. The Ethernet frame is a logical data set construction at the Data Link Layer (Layer 2), consisting of the payload from the Network Layer (Layer 3) with the addition of an Ethernet header and footer ([**FIGURE 3-4**](#12_chapter03_02.xhtml#fig3-4)).
