

# VPN、代理服务器和网络地址转换

您可以使用 VPN 进行远程访问、远程控制，或在不受信任的网络中进行高度安全的通信。

## 代理服务器

[代理服务器](#30_glossary.xhtml#gloss374)是防火墙的一种变体。代理服务器会过滤流量，但也会以几种特定方式对该流量进行处理。首先，代理服务器充当内部客户端和外部服务器之间的中间人。或者，在反向代理的情况下，这种关系可以颠倒，变为内部服务器和外部主机。其次，代理服务器将通过称为[网络地址转换 (NAT)](#30_glossary.xhtml#gloss312)的过程，向服务器隐藏原始请求者的身份。本质上，代理服务器作为中介站在另一台服务器的前面。

代理服务器的另一项功能可以是内容过滤。这种过滤侧重于服务器的地址（通常按域名或 IP 地址）或传输内容中出现的关键字。您可以采用这种形式的过滤来阻止员工访问与业务任务无关或无益，或可能对业务网络产生直接影响的互联网资源。这可能包括恶意代码、黑客工具、过度的带宽消耗（如视频流或 P2P 文件交换），以及不当或令人反感的网站或材料。

代理服务器还可以提供缓存服务。[缓存](#30_glossary.xhtml#gloss70)是一种数据存储机制，它保存性质相对静态且众多内部客户端有规律请求的内容的本地副本。热门网站的首页，如搜索引擎的首页，通常由代理服务器缓存。当用户请求一个存储在缓存中的互联网页面时，代理服务器会从缓存中向用户提供该页面，而不是再次从互联网站点获取。这为用户提供了更快的性能，并减轻了互联网链路的负载。

这种类型的缓存通常会导致所有用户体验到更快的互联网性能，即使提供给他们的页面是从互联网获取的。显然，这种缓存必须经过调整，以防止缓存中出现陈旧页面。调整是指在缓存页面上设置超时值，使每个页面以合理的速率过期。所有过期的缓存页面都会被来自互联网上原始源服务器的新内容所替换。

## 网络地址转换

网络地址转换 (NAT) 将内部地址转换为外部公共地址，反之亦然。网络对进入或离开网络的数据包执行此转换，以掩盖和修改内部客户端的配置。NAT 的主要目的是防止内部 IP 和网络配置详细信息被外部实体（如黑客）发现。

[**图 1-3**](#10_chapter01_09.xhtml#fig1-3) 显示了一个示例，即内部客户端通过使用 NAT 的代理或防火墙到达外部服务器的路径。在本例中，外部服务器是运行在默认 HTTP 端口 80 上的 Web 服务器。Web 服务器使用 IP 地址 `208.40.235.38`。发起请求的内部客户端使用 IP 地址 `192.168.12.153`。客户端在 1,024 和 65,535 之间随机选择一个源端口（如 `13,571`）。有了这些源详细信息，客户端生成初始请求数据包。这是步骤 1。该数据包通过网络发送到外部服务器，途中遇到 NAT 服务。

![图 1-3 NAT 功能示例。](Images/9781284183658_CH01_FIGF03.png)

**图 1-3** NAT 功能示例。

### 步骤 1 初始请求：

```
S: 192.168.12.153: 13571
D: 208.40.235.38: 80
```

### 步骤 2 NAT 在转换映射表中创建条目：

```
内部: 外部:
192.168.12.153: 13571 <- -> 72.254.149.76: 27409
```

NAT 服务在其转换或映射表中为该请求创建一个条目。该表包含源 IP 地址和端口，以及转换后的 IP 地址和端口。NAT 服务器使用其自身的公共 IP 地址作为转换后的 IP 地址，并为数据包选择一个当前未使用的随机端口作为新的源端口。这是步骤 2。

### 步骤 3 转换后的请求：

```
S: 72.254.149.76: 27409
D: 208.40.235.38: 80
```

步骤 3 是使用转换后的源信息构建新数据包，然后通过互联网传输到外部服务器。Web 服务器接收到一个请求，其来源看起来像是代理/防火墙系统。

### 步骤 4 来自外部服务器的响应：

```
S: 208.40.235.38: 80
D: 72.254.149.76: 27409
```

步骤 4 是由 Web 服务器生成并传输的响应。

### 步骤 5 NAT 将响应发送给客户端：

```
S: 208.40.235.38: 80
D: 192.168.12.153: 13571
```

代理/防火墙接收到对 Web 服务器请求的响应。NAT 服务使用转换表将原始客户端的信息作为目标地址放回数据包头部。这是步骤 5。此过程以线速进行。对于参与通信的客户端和服务器来说，这通常是透明的，因为它们不知道发生了转换。

NAT 的另一个目的或用途是减少从互联网服务提供商 (ISP) 租用大量公共 IP 地址的需求。如果没有 NAT，您将需要为每个曾经连接到互联网的单个系统提供一个唯一的[公共 IP 地址](#30_glossary.xhtml#gloss376)。有了 NAT，您可以租用一组较小的公共 IP 地址来服务更多的内部用户。在许多小型办公室/家庭办公室 (SOHO) 网络中，所有内部网络设备都可以转换为单个公共地址。

这种整合之所以成为可能，有两个原因。首先，IPv4 地址的短缺要求某些网络整合地址。其次，仅当使用[静态 NAT](#30_glossary.xhtml#gloss483) 时，NAT 才会为单个内部客户端保留特定的公共地址。相反，NAT 会为每个后续的内部客户端请求随机分配一个可用的公共地址。一旦客户端的通信会话结束，该公共地址就会返回到可用地址池中，供未来的通信使用。

此外，NAT 通常不采用 IP 到 IP 的地址转换，而是使用一种称为[端口地址转换 (PAT)](#30_glossary.xhtml#gloss353)的更细粒度选项。使用 PAT 时，客户端的端口和 IP 地址都会被转换为一个随机的外部端口和公共 IP 地址。这允许多个同时通信在单个 IP 地址上进行。这一过程反过来又允许您支持来自单个客户端或多个客户端的更多数量的通信，而只需租用更少数量的公共 IP 地址。

NAT 在仍支持互联网通信的同时，启用了[私有 IP 地址](#30_glossary.xhtml#gloss364)的使用。这些地址被称为 RFC 1918 地址，源自详述该协议的技术规范。范围如下：

*   **A 类**—`10.0.0.0–10.255.255.255/8`（1 个 A 类网络）
*   **B 类**—`172.16.0.0–172.31.255.255/12`（16 个 B 类网络）
*   **C 类**—`192.168.0.0–192.168.255.255/16`（256 个 C 类网络）

[RFC 1918 地址](#30_glossary.xhtml#gloss408)仅用于私有网络。根据定义，它们是不可路由的地址空间。互联网路由器会丢弃使用这些地址的任何数据包。如果没有 NAT，使用这些私有 IP 地址的网络将无法与互联网通信。通过使用 RFC 1918 地址，网络在抵御基于互联网的攻击方面建立了另一道屏障，并且无需为租用内部地址付费。
