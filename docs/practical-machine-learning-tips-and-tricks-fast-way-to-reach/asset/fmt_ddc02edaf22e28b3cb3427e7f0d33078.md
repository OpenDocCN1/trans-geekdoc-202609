## 8.6.1 Pros and Cons of Each Approach to Amplify a Discriminative Objective (Salojarvi et al. 2005)

*   **Handle missing elements without any problem?**
    Sometimes a portion of the sources of info (parts of `x`) are not noticed. In a generative classifier, there is a straightforward technique for managing this, as we examine in Section 8.6.2. Nonetheless, in a discriminative classifier, there is no principled answer for this issue, since the model expects that `x` is consistently accessible to be molded on (despite the fact that see Marlin 2008 for some heuristic approaches).

*   **Can deal with unlabeled preparing information?**
    There is a lot of interest in semi-supervised learning, which utilizes unlabeled information to assist with tackling a directed assignment. This is genuinely simple to do utilizing generative models (see e.g., Lasserre et al. 2006; Liang et al. 2007), however is a lot harder to do with discriminative models.

*   **Symmetric in data sources and results?**
    We can run a generative model in reverse, and deduce plausible data sources given the result by figuring `p(x|y)`. This is unimaginable with a discriminative model. The explanation is that a generative model characterizes a joint appropriation on `x` and `y`, and consequently treats the two information sources and results symmetrically.

*   **Can handle feature preprocessing?**
    A big advantage of discriminative methods is that they allow us to preprocess the input in arbitrary ways, e.g., we can replace `x` with `ϕ(x)`, which could be some basis function expansion, etc. It is often hard to define a generative model on such preprocessed data, since the new features are correlated in complex ways.

*   **Well-aligned probabilities?**
    Some generative models, like naive Bayes, make solid autonomy suspicions which are frequently not substantial. This can bring about exceptionally outrageous back class probabilities (extremely close to 0 or 1). Discriminative models, like logistic regression, are normally better adjusted as far as their likelihood estimates.

*   **Easy to fit?**
    As we have seen, it is typically exceptionally simple to fit generative classifiers. For instance, in Sections 3.5.1 and 4.2.4, we show that we can fit a naive Bayes model and an LDA model by straightforward counting and averaging. Conversely, logistic regression requires taking care of a curved improvement issue (see Section 8.2 for the subtleties), which is much slower.

*   **Fit classes independently?**
    In a generative classifier, we gauge the boundaries of each class restrictive thickness autonomously, so we don't need to retrain the model when we add more classes. Interestingly, in discriminative models, every one of the boundaries communicate, so the entire model should be retrained on the off chance that we add another class. ## 8.6.2 Dealing with Missing Data

Sometimes a portion of the sources of info (parts of `x`) are not noticed; this could be because of a sensor disappointment, or an inability to finish a section in a study, etc. This is known as the missing information issue (Little & Rubin 1987). The ability to deal with missing information in a principled manner is probably the greatest benefit of generative models.

To formalize our suppositions, we can relate a parallel reaction variable `ri ∈ {0,1}` that indicates whether or not each value `xi` is noticed. The joint model has the structure:

`p(xi, ri | θ, ϕ) = p(ri | xi, ϕ) p(xi | θ)`

where `ϕ` are the boundaries controlling whether the thing is noticed or not.

*   **MCAR (Missing Completely At Random):** If we expect `p(ri | xi, ϕ) = p(ri | ϕ)`, we say the information is missing completely at random.
*   **MAR (Missing At Random):** If we accept `p(ri | xi, ϕ) = p(ri | xo, ϕ)`, where `xo` is the noticed part of `xi`, we say the information is missing at random.

Any generative probabilistic model (e.g., HMMs, Boltzmann machines, Bayesian networks, etc.) can be turned into a classifier by using it as a class conditional density.
