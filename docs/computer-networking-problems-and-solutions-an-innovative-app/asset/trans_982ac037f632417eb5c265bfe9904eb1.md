### 在物理链路上、广播和故障域

当考虑广播域和物理连接的概念时，[图 2-5](#ch02.xhtml#ch02fig05) 中说明的清晰模型变得更加复杂。某些媒体类型（尤其是以太网，详细内容见 [第 4 章](#ch04.xhtml#ch04)，“[Lower Layer Transports](#ch04.xhtml#ch04)”）设计为连接到同一物理链路的每个设备都会接收到传输到物理介质上的每个数据包——主机只是忽略未寻址到与物理线路连接的物理接口相关联的地址的数据包。然而，在现代网络中，物理以太网布线很少允许每个设备接收到每个其他设备的包；相反，网络中间有一个交换机，它会阻止未发往特定设备的数据包在连接到该主机的物理线路上传输。

然而，在这些协议中，预留了显式地址用于数据包，这些数据包 `should be` 传输给如果没有交换机时本应接收到每个数据包的所有主机，或所有主机都应接收并处理的数据包（通常，这是地址的全 1 或全 0 版本）。这些被称为广播。任何会接收并处理由某设备发送的广播的设备都被认为属于该设备的广播域。广播域的概念传统上与故障域密切相关，因为影响广播域上某台设备的网络故障通常会影响广播域上的每个设备（有关故障域的更多信息，请参阅 [第 23 章](#ch23.xhtml#ch23)，“[Redundant and Resilient](#ch23.xhtml#ch23)”）。

不要惊讶如果你发现这一切相当令人困惑，因为它确实相当令人困惑。广播和广播域的基本概念仍然存在，并且对于理解网络的运行仍然很重要，但在某些情况下，术语的含义可能会改变，甚至不适用。在考虑任何情况时要小心，确保你真正理解广播域的实际位置以及特定技术如何影响物理连接、寻址和广播域之间的关系。

#### Multicast

**Note**
这个简短的解释无法真正体现构建组播树的全部解决方案范围；请参阅本章末尾的“Further Reading”部分，了解该领域的更多资料。

如果你有一个像 [图 2-6](#ch02.xhtml#ch02fig06) 所示的网络，并且需要 A 将相同内容分发给 G、H、M 和 N，你将如何进行？

你可以生成四份流量的副本，使用正常的 `unicast` 转发将一个流发送给每个接收者，或者你可以以某种方式将流量发送到网络知道要复制以便所有四个主机都接收到副本的单个地址。后一种选项称为组播，这意味着使用单个地址向多个接收者传输流量。组播要解决的关键问题是在流量通过网络时进行转发和复制，以便对流感兴趣的每个接收者都会收到一份副本。

**Note**
对来自组播源的数据包流感兴趣的设备集合称为组播组。这可能有点令人困惑，因为用于描述组播流的地址在某些情况下也称为组播组。这两种用法在 `practically` 上可以互换，因为对特定组播数据包集感兴趣的设备集合将加入组播组，这实际上意味着监听特定的组播地址。

**Note**
在组播流量为双向的情况下，解决此问题要困难得多。例如，假设有一个要求构建一个组播组，其中包含 [图 2-6](#ch02.xhtml#ch02fig06) 中所示网络中的每个主机，除了 N，并且进一步要求任何传输到组播组地址的组播都交付给组播组内的每个主机。

![Image](graphics/02fig06.jpg)

**图 2-6** *一个组播示例*

组播要解决的关键问题可以分为两个问题：
• 如何发现哪些设备希望接收发送到组播组的流量的副本？
• 如何确定网络中哪些设备应该复制流量，以及它们应在哪些接口上发送副本？

一种可能的解决方案是使用本地请求构建一棵树，通过该树将组播流量转发通过网络。这样的系统的一个例子是协议无关组播 (`PIM`) 中的 `Sparse Mode`。在这个过程中，每个设备为其感兴趣的组播流发送一个 `join` 消息；这些加入请求在网络中向上游传递，直到到达发送者（通过组播流发送数据包的主机）。[图 2-7](#ch02.xhtml#ch02fig07) 用于说明此过程。

![Image](graphics/02fig07.jpg)

**图 2-7** *稀疏模式组播*

在 [图 2-7](#ch02.xhtml#ch02fig07) 中：
1. A 正在向一个组播组（地址）发送一些流量；称其为 `Z`。
2. N 希望接收 Z 的副本，因此它向其上游路由器 D 发送一个请求（加入）以获取此流量的副本。
3. D 没有此流量的源，因此它向其连接的路由器发送请求以获取此流量的副本；在这种情况下，D 发送请求的唯一路由器是 B。

在每个跳点，接收请求的路由器会将其接收请求的接口放入其 `Outbound Interface List (OIL)` 中，并开始转发在任何其他接口上接收到的给定组播组中的流量。以这种方式，可以从接收者到流量源构建一条路径；这称为 `reverse path tree`。
