

给定 C 将选择到目的地的最短路径，它会选择 `[C,F]`，因此不会将流量转发回 A。将其转化为一个问题：为什么 C 不会将流量转发回 A？因为它有一条*成本低于通过 A 的任何路径*到达目的地的路径。这可以被概括并称为*下游邻居：*

**任何具有比本地到目的地的路径更短的路径的邻居都不会将流量循环回我（发送节点）。**

或者说，给定本地成本表示为 LC，邻居的成本表示为 NC，则

**如果 NC < LC，则该邻居是下游的。**

现在考虑 [Figure 12-4](#ch12.xhtml#ch12fig04) 中显示的第二条替代路径：`[A,D,E,F]`。同样，如果 A 将流量向目的地发送给 D，D 会将流量循环回 A 吗？D 可用的路径有

• `[D,A,C,F]`，总成本为 5

• `[D,A,B,F]`，总成本为 4

• `[D,E,F]`，总成本为 3

假设 D 将使用最短可用路径，D 会将此类流量通过 E 转发，而不是通过 A 返回。这可以被概括并称为无环备选路径 Loop-Free Alternate (LFA)：

**任何具有比本地到目的地的路径加上邻居到达我（本地节点）的成本更短的路径的邻居都不会将流量循环回我（本地节点）。**

或者说，给定本地成本表示为 LC，邻居的成本表示为 NC，以及回到本地节点（从邻居的角度）的成本为 BC：

**如果 NC + BC < LC，则该邻居是 LFA。**

解释无环备选路径的另外两种常用模型是瀑布模型和 P/Q 空间。详细了解这些模型是有用的。

### Waterfall (or Continental Divide) Model 瀑布（或大陆分水岭）模型

防止控制平面计算的路由出现环路的一种方法是简单地不向会将流量转发回我的（发送节点）的邻居通告路由。这称为水平分割；它导致网络中流量的流动像瀑布或溪流床中的水一样，沿着阻力最小的路径流向目的地，如 [Figure 12-5](#ch12.xhtml#ch12fig05) 所示。

![Image](graphics/12fig05.jpg)

**Figure 12-5** *Traffic Flow from a Metric-based Packet Divide* **图 12-5** *基于度量的数据包分区的流量流向*

在 [Figure 12-5](#ch12.xhtml#ch12fig05) 中，如果流量在 C 处进入网络（在源 2）并且目的地在 E 之外，它将沿环的右侧向下流动。然而，如果流量在 A 处进入网络并且目的地在 E 之外，它将沿环的左侧向下流动。为了防止目的地在 E 之外的流量在此环上循环，控制平面可以做的一件简单的事情是，要么不允许 A 向 C 通告目的地，要么不允许 C 向 A 通告目的地。阻止这两个路由器中的一个向另一个通告称为水平分割，因为它阻止路由在地平线上传播，或者说阻止在任何特定设备知道沿特定链路传递的流量会被循环的点之外传播。

水平分割是通过只允许设备通过其未用于到达相关目的地的接口通告可达性来实现的。在本例中：

• D 使用 E 到达目的地，因此它不会向 E 通告可达性

• C 使用 D 到达目的地，因此它不会向 D 通告可达性

• B 使用 E 到达目的地，因此它不会向 E 通告可达性

• A 使用 B 到达目的地，因此它不会向 B 通告可达性

因此，A 阻止 B 知道它通过 C 到达目的地的替代路径，而 C 阻止 D 知道它通过 A 到达目的地的替代路径。无环备选路径将跨越网络中的此水平分割点。在 [Figure 12-5](#ch12.xhtml#ch12fig05) 中，A 可以计算出 C 的路径成本小于 A 的路径成本，因此 A 向 C 转发到目的地的任何流量都将沿着 A 所知的路径以外的某条路径转发。在 LFA 术语中，C 是 A 的下游邻居。

因此，另一种看待 LFA 计算的方法是找到环中的水平分割点，并确定分割点两侧的设备是否会通过数据包分水岭转发流量。

### P/Q Space

描述 LFA 如何工作的另一种模型是 *P/Q Space；* [Figure 12-6](#ch12.xhtml#ch12fig06) 说明了这一点。

![Image](graphics/12fig06.jpg)

**Figure 12-6** *P Space and Q Space* **图 12-6** *P 空间和 Q 空间*

最容易从两个空间的定义开始。假设 `[E,D]` 链路需要从故障中保护：

• 从 E 计算一棵反向最短路径树（E 在计算此树时使用通往自身的路径成本，而不是远离自身的成本，因为流量沿此路径流向 D）。

• 删除 `[E,D]` 链路，以及只能通过该链路到达的任何节点。

• E 仍可到达的剩余节点为 Q 空间。

• 从 D 计算一棵最短路径树。

• 删除 `[E,D]` 链路，以及只能通过该链路到达的任何节点。

• D 仍可到达的剩余节点在 P 空间中。

如果 D 能在 `[E,D]` 链路故障时找到 Q 空间中的一个路由器来转发流量，这就是一个 LFA。

### Remote Loop-Free Alternates 远程无环备选路径

如果没有 LFA 怎么办？有时可以找到远程无环备选路径 rLFA，它也可以承载流量到目的地。rLFA 并未直接连接到计算路由器，而是距离一个或多个跳；这意味着流量必须通过计算路由器和远程下一跳之间的路由器承载；这通常是通过隧道传输流量来实现的。

这些模型可以在不查看计算所需的数学的情况下解释 rLFA。了解环将在何处“分割”为 P 和 Q，或分割为水平分割划分的两半，有助于你快速了解即使没有 LFA 存在时 rLFA 也可用于规避故障的位置。回到 [Figure 12-6](#ch12.xhtml#ch12fig06)，例如，如果 `[E,D]` 链路故障，D 必须简单地等待网络收敛后再开始向目的地转发流量。E 的最佳路径已因故障而从 D 的树中移除，而 E 没有可转发流量的 LFA。

回到本节开始时对无环路径的受限定义——任何设备可以转发流量而不被返回的邻居。设备在本地链路故障情况下发送数据包的邻居没有特别的理由必须是本地连接的。[Chapter 9](#ch09.xhtml#ch09)，“[Network Virtualization](#ch09.xhtml#ch09)，” 描述了创建可承载网络中任意两个节点之间流量的隧道或覆盖拓扑的能力。

鉴于能够通过 C 隧道传输流量，以便 C 不基于实际目的地转发流量，而是基于隧道头，D 可以直接将流量转发给 A，从而绕过环路。因此，当 `[E,D]` 链路故障时，D 可以执行以下操作：

1. 计算网络中可隧道传输流量且不会返回到 C 本身的最接近点。
2. 形成到该路由器的隧道。
3. 将流量封装到隧道头中。
4. 转发流量。

**Note**

在实际实现中，rLFA 隧道会在故障发生时之前预先计算，而不是在故障时计算。这些 rLFA 隧道也不一定需要对正常转发过程可见。本文档是为了清晰地说明此过程的*如何*工作而安排的，而不是关注其通常的实现方式。
