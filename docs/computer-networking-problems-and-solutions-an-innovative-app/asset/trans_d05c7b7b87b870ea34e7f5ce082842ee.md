

[Figure 13-15](#ch13.xhtml#ch13fig15) 显示了每个链接的修改后成本；每个属于原始 SPT 的链接（每个树边，以实线显示）具有两个成本，一个在每个方向，而不原本属于 SPT 的链接（非树边，以虚线显示）保持其原始成本。注意显示每个情况下成本方向的箭头；这在计算的下一步中将很重要。计算每个树边的两个方向链接的成本：

1. 将链接的一端称为 `u`，另一端称为 `v`；注意方程在两个方向上运行。
2. 从源到 `v` 的成本从从 `u` 到 `v` 的链接成本中减去。
3. 加上从源到 `u` 的成本。

如果源是 `s`：

`d[sp](u,v) = d(u,v) − d(s,v) + d(s,u)`

这本质上将树边的成本设置为 0，正如通过对 `[B,E]` 链接进行数学运算所能看到的那样：

- `B` 是 `u`，`E` 是 `v`，`A` 是 `s`
- `d(u,v) = 2`，`d(s,v) = 3`，`d(s,u) = 1`
- `2 − 3 + 1 = 0`

然而，所有非树边将被设置为某个（通常更大）非零成本。对于 [Figure 13-15](#ch13.xhtml#ch13fig15) 中的网络：

- 对于 `[B,A]` 链接（注意 `[A,B]` 不是正在计算的方向树中的链接）：

`B` 是 `u`，`A` 是 `v`，`A` 是 `s`

`d(u,v) = 0`，`d(s,v) = 0`，`d(s,u) = 1`

`0 − 0 + 1 = 1`

- 对于 `[E,B]` 链接：

`E` 是 `u`，`B` 是 `v`，`A` 是 `s`

`d(u,v) = 2`，`d(s,v) = 1`，`d(s,u) = 3`

`2 − 1 + 3 = 4`

- 对于 `[C,A]` 链接：

`C` 是 `u`，`A` 是 `v`，`A` 是 `s`

`d(u,v) = 2`，`d(s,v) = 0`，`d(s,u) = 2`

`2 − 0 + 2 = 4`

- 对于 `[F,D]` 链接：

`F` 是 `u`，`D` 是 `v`，`A` 是 `s`

`d(u,v) = 1`，`d(s,v) = 4`，`d(s,u) = 5`

`1 − 4 + 5 = 2`

- 对于 `[D,B]` 链接：

`D` 是 `u`，`B` 是 `v`，`A` 是 `s`

`d(u,v) = 1`，`d(s,v) = 1`，`d(s,u) = 2`

`1 − 1 + 2 = 2`

下一步，如 [Figure 13-16](#ch13.xhtml#ch13fig16) 所示，是删除所有指向源的方向边，该源沿原始 SPT 指向特定目的地（本例中为 Z），反转沿同一路径的零成本边（链接）的方向，然后再次运行 Dijkstra 的 SPF，创建同一拓扑上的第二个 SPT。

回到原始 SPT，从 X 到 Z 的路径沿路径 `[A,B,D,F]`。因此，指向源 A 的四个非零成本边（虚线）沿此路径已被删除。沿同一路径 `[A,B,D,F]`，每条边的方向已被反转；例如，`[A,B]` 原本从 A 指向 B，现在从 B 指向 A。下一步是运行此图上的 SPF，记住 *流量不能逆着链接的方向流动*。 resulting tree 显示在 [Figure 13-17](#ch13.xhtml#ch13fig17) 中。

[Figure 13-17](#ch13.xhtml#ch13fig17) 显示了原始树和新计算的树叠加在原始拓扑上作为两条不同的虚线。两个拓扑仍然共享 `[B,D]` 链接，因此它们尚未真正分离。此时，从 X 到 Z 有两条最短路径：

- `[A,B,D,F]`
- `[A,C,D,B,E,F]`

这两个图合并形成一组边，任何在两个图中但方向相反的链接都被丢弃；合并后的集合如下所示：

`[A->B, B->E, E->F, A->C, C->D, D->F]`

再次注意每个链接的方向性——对于剔除重叠链接至关重要，该链接将被同时列为 `[B->D]` 和 `[D->B]`。有了图上这部分可能的边，就可以看到正确的最短路径集是 `[A,B,E,F]` 和 `[A,C,D,F]`。

Suurballe 算法很复杂，但展示了计算不相交树的原理要点——包括它们计算起来有多困难。

### 最大冗余树

计算不相交树的 Suurballe 算法的更简单替代方案是计算最大冗余树（MRT）。理解 MRT 的最佳起点是谦逊的深度优先搜索（DFS），特别是编号 DFS。 [Figure 13-18](#ch13.xhtml#ch13fig18) 用作说明。

在 [Figure 13-18](#ch13.xhtml#ch13fig18) 中，左侧代表一个简单的拓扑；右侧是使用 DFS 编号的同一拓扑。假设用于“遍历”树的 DFS 算法总是选择左侧节点而不是右侧，过程将如下所示：

[Click here to view code image](#ch13_images.xhtml#p13pro02a)

```
01 main {  
02   dfs_number = 1  
03   root.number = dfs_number  
04   recurse_dfs(root)  
05 }  
06 recurse_dfs(current) {  
07   for each neighbor of current {  
08     child = left most neighbor (not visited)  
09     if child.number == 0 {  
10       dfs_number++  
11       child.number = dfs_number  
12       if child.children > 0 {  
13         recurse_dfs(child)  
14       }  
15     }  
16   }  
17 }
```

理解这段代码的最佳方法是遍历递归几次以了解其工作原理。使用 [Figure 13-18](#ch13.xhtml#ch13fig18)：

- 第一次调用 `recurse_dfs` 时，A 或 `root` 被设为当前节点。
- 进入 `recurse_dfs` 后，A 的最左侧节点被选中，即 B。
- 进入循环时 B 没有 `number`，因此第 09 行的 `if` 语句为真。
- B 被分配下一个 DFS 编号（第 11 行）。
- B 有子节点（第 12 行），因此 `recurse_dfs` 再次被调用，当前节点为 B。
- 进入（第二层的）`recurse_dfs` 后，B 的最左侧邻居被选中，即 E。
- E 没有 DFS 编号，因此第 09 行的 `if` 语句为真。
- E 被分配下一个 DFS 编号（3）。
- E 没有子节点，因此处理回退到循环顶部。
- F 现在是 B 的尚未访问的最左侧邻居，因此被分配给 `child`。
- F 没有编号，因此第 09 行的 `if` 语句为真。
- F 被分配下一个 DFS 编号（4）。
- B 没有更多子节点，因此第 07 行的 `for` 循环失败，`recurse_dfs` 退出。
- 然而，`recurse_dfs` 并未真正退出——它只是“回退”到之前的递归级别，即第 14 行；该递归级别仍在处理 A 的邻居。
- C 是 A 的下一个尚未触及的邻居，因此 `child` 被设为 C。
- 等等。

检查 [Figure 13-18](#ch13.xhtml#ch13fig18) 右侧节点编号会得出以下有趣观察：

- 如果 A 总是遵循递增编号到达 D，它将遵循路径 `[A,C,G,D]`。
- 如果 D 总是遵循递减 DFS 编号到达 A，它将遵循路径 `[D,A]`。
- 这两条路径实际上是不相交的。

此属性适用于通过 DFS 搜索分配编号的所有拓扑：始终遵循递增编号的路径将始终与始终遵循递减编号的路径不相交。这正是 MRT 构建不相交路径所依赖的属性。然而，DFS 编号的问题在于在接近实时中执行它很困难。必须有某种选举的 `root`，流量在局部水平上是次优的（就像最小生成树 MST 可能一样），并且拓扑的任何更改都需要重建整个 DFS 编号方案。

为了解决这些问题，MRT 使用相同原理但以不同方式构建不相交拓扑。 [Figure 13-19](#ch13.xhtml#ch13fig19) 用于解释。

![Image](graphics/13fig19.jpg)

**Figure 13-19** *Sample Network for Building an MRT*

构建 MRT 的第一步是找到从根通过拓扑的短环（通常这些环是使用 Dijkstra 的 SPF 算法找到的）。在这种情况下，A 将被选为根，环将为 `[A,B,C,D]`。这个第一个环将用作两个拓扑中的第一个，称为 *red* 拓扑。将环反转为 `[A,D,C,B]` 生成一个不相交的拓扑，称为 *blue* 拓扑。通过这个短环的这对拓扑称为 *ear*。
