### Mapping Database and Protocol

如果表中条目的数量变得足够大，参与维护该表的人员数量变得足够大，或者信息动态性足够强，以至于需要在进行映射时学习该信息，而不是在软件部署时学习，那么构建并动态分发数据库是有意义的。此类系统应包括协议以同步数据库分区，以便向外部查询呈现一致的视图，以及主机和服务可以使用这些协议通过一个标识符查询数据库以发现来自网络不同层的匹配标识符。

动态映射数据库可以通过手动配置或自动化流程接受输入（例如，收集有关网络状态的信息并将所得信息存储在动态数据库中的发现流程）。它们也可能是分布式的，这意味着数据库的副本或部分存储在多个不同的主机或服务器上，或者是集中的，这意味着数据库存储在少数主机或服务器上。

域名系统（DNS）被描述为基于动态分布式数据库的身份映射服务的示例。动态主机配置协议（DHCP）被描述为主要用于地址分配的类似系统的示例。

### Advertising Identifier Mappings in a Protocol

如果映射问题的范围可以被限定，但身份对的数量很大，或者可能迅速变化，那么创建一个允许实体直接从设备请求映射信息的单一协议可能是一个最佳解决方案。例如，在 [Figure 6-1](#ch06.xhtml#ch06fig01) 中，D可以直接询问E其本地MAC（或物理）地址是什么。

互联网协议版本4（IPv4）地址解析协议（ARP）是这种解决方案的一个很好的例子，IPv6邻居发现（ND）协议也是如此。这些示例将在后面的章节中更详细地讨论。

### Calculating One Identifier from the Other

在某些情况下，可以从另一层的地址或标识符计算出一层的地址或标识符。很少有系统使用这种技术进行地址映射；大多数使用这种技术的系统都是为了 `assign` 地址。一个这样的系统示例是无状态地址自动配置（SLAAC），这是一种IPv6协议，主机可以使用它来确定应分配给接口的IPv6地址，该协议将在本章后面IPv6 ND讨论的一部分中更详细地考虑。

使用下层地址计算上层地址的另一个示例是在国际标准化组织（ISO）协议套件中端系统地址的形成中，例如中间系统到中间系统（IS-IS）。该示例将在 [Chapter 16](#ch16.xhtml#ch16) 中更详细地讨论，“[Link State and Path Vector Control Planes](#ch16.xhtml#ch16).”

### The Domain Name System

DNS在人类可读的字符串，例如 [Figure 6-1](#ch06.xhtml#ch06fig01) 中使用的名称 `service1.example`，与IP地址之间进行映射。 [Figure 6-3](#ch06.xhtml#ch06fig03) 说明了DNS系统的基本操作。

![Image](graphics/06fig03.jpg)

**Figure 6-3** `An Overview of the Operation of the DNS System`

在 [Figure 6-3](#ch06.xhtml#ch06fig03) 中，假设没有任何缓存（因此整个过程都被说明）：

1. 主机 A 尝试连接到 [www.service1.example](http://www.service1.example)。主机操作系统检查其本地配置以查找应查询的DNS服务器的地址以发现该服务的位置，并找到递归服务器的地址。主机操作系统的DNS应用程序向该地址发送DNS查询。

2. 递归服务器接收此查询，并且——由于没有缓存——检查正在请求地址的域名。递归服务器注意到域名的右手部分是 `example`，因此它询问根服务器在哪里可以找到有关 `example` 域的信息。

3. 根服务器返回包含有关顶级域（TLD） `example` 的信息的服务器的地址。

4. 递归服务器现在请求有关应联系哪个服务器获取 `service1.example` 的信息。递归服务器一次通过域名的一个部分，使用关于名称右侧部分发现的信息来发现应询问关于左侧信息哪个服务器。此过程称为通过域名 `recursing`；因此服务器称为递归服务器。

5. TLD服务器返回 `authoritative server` 的地址，用于 service1. example。如果从先前的请求缓存了有关服务位置的信息，则将其作为非权威答案返回；如果配置为保存有关域的信息的实际服务器回复，其答案就是 `authoritative`。

6. 递归服务器从权威服务器请求有关 [www.service1.example](http://www.service1.example) 的信息。

7. 权威服务器用服务器 B 的IP地址作出响应。

8. 递归服务器现在用到达所请求服务的正确信息响应主机 A。

9. 主机 A 联系在IP地址 `2001:db8:3e8:100::1` 上运行 [www.service1.example](http://www.service1.example) 的服务器。

这个过程看起来可能非常冗长；例如，为什么不将所有信息都保存在根服务器上以节省大量步骤呢？然而，这会违反DNS的基本思想，即尽可能将每个域的信息控制权保留在域所有者手中。此外，这会使根服务器的构建和维护变得非常昂贵，因为它们需要能够保存数百万条记录并每天回答数亿次DNS信息查询。信息的分离允许每个所有者控制其数据并使DNS系统能够扩展。

通常，通过DNS查询过程返回的信息会被沿途的每个服务器缓存，因此主机每次需要访问新服务器时都不需要请求映射。

这些DNS表是如何维护的？通常通过世界各地域和顶级域所有者以及边缘提供商的手工工作来维护。DNS不会自动发现连接到网络的每个实体的名称及其地址是什么。

DNS将手工维护的数据库，与工作分散在许多不同的人手中，配以用于查询数据库的协议；因此DNS属于 `mapping database with a protocol` 类解决方案。主机如何知道应查询哪个DNS服务器？此信息要么是手动配置的，要么是通过IPv6 ND或DHCP等发现协议学习的。
