  Dataflow graphs    In TensorFlow, algorithms and its operations are represented by dataflow or computational graph. Dataflow graph is a form of a directed graph in which all nodes are connected, and edges are directed from one node to another. In this graph, each node represents operations and an edge represents output value (tensors) of these operations. As each vertex represents the flow of tensors so it is called TensorFlow. Each node can have zero or more than one input and consequently zero or more output. Nodes are generally represented by box or circle and vertices represented by an arrow as notation. Example of directed graph is shown in Figure    ![](image-z56jbtcm.jpg)  Figure 1.2    There are various reasons that help to understand why dataflow graph is chosen as the computational model in TensorFlow. In deep learning, models are generally visualized as a directed graph which helps to implement and debug the networks. Deep learning model requires gradient computation of output node with respect to other node and by creating nodes for each operation it becomes easier to compute the derivatives. It also helps to distribute the operations in multiple CPUs or GPUs.

  Overfitting and Underfitting    Now we understand what the feedforward neural network is, the different cost functions that are used to train the network along with different approaches to optimize those cost functions, and how the activation functions help in introducing no-linearity in neural network.    In any model learning, it is very important that the model is able to generalize from the training data to make predictions in the future on the data the model has never seen. But, in practical problems, either the model is able to learn too well from the training data that it even captures the noise and less important details, known as overfitting, or the model is not able to learn even the significant details i.e., it is neither able to fit the training data nor it is able to generalize for the unseen data, known as underfitting.    Ideally, with enough parameters, we can fit any data set. The fact that the model is agreeing well with the available training data set doesn’t make it a good one. The model should be able to generalize the scenario. In deep neural networks, we can have millions of parameters. So, it’s very easy for the model to overfit with those many free parameters (weights and biases). To train effectively, we should be able to detect when the model overfits.    It is not always easy to detect overfitting in a model. The general rule is when accuracy on the unforeseen data (test data) is low as compared to the training set accuracy, the model is overfitting the training data.    How to prevent overfitting in deep neural networks?     Obtaining more data     More the data, the easier it is for the model to capture all the significant details and estimate the parameters appropriately.    Train/Dev/Test set     In neural networks, there are a lot many hyperparameters to play with. Using the test set accuracy to set the hyperparameters leads to leaking of the test (unforeseen) data information, due to which the model fails miserably in production systems. Since in deep neural networks, we deal with millions of data points, it is always recommended to have a separate dev/validation set to fine tune the hyperparameters, keeping the test set completely unforeseen.    Reduce the size of the network     This approach is not used very often as larger networks have the potential to be more powerful than smaller networks.    Regularization: It is the most commonly used method for preventing overfitting. It basically adds an extra component (penalty term) to the cost function (Eg-4a) or modifies the network (Eg-4b), which punishes the model for being too complex and hence the model generalizes better. Different regularization techniques are explained below.    L1 and L2     Both L1 and L2 add an extra penalty term in the cost function so that network is able to learn smaller weights. We know that 3D input consists of 3 layers where each layer is 2D, one stacked behind the other as shown in Figure To perform convolution with 3D input, kernel should also be 3D. In general, we can say that if an input is n dimensional, then to perform convolution, kernel should also be n dimensional. Let’s understand this with a 3D input consisting of 3 channels R, G, and B and kernel of depth 3\. It means the size of the input is m × n × 3 and that of kernel is k × l × 3\. We can see that the depth of both input and kernel is same. In general, we can write that if the size of an input is m × n × d then to perform the convolution, size of the kernel should be k × l × where, k and l are normally several orders magnitude smaller than m and n respectively.    ![](image-e9rsbtfg.jpg)  Figure 3.38: Example of RGB layer of a 3D image    Why do we keep the depth of the input matrix and kernel same?   Pooling layer    Now, let’s understand the pooling layer. Pooling layer is somewhat similar to dropout layer in feedforward networks that was discussed in the last chapter. It helps to reduce the co-adaption between pixels and hence it reduces variance. In pooling layer, certain elements of the output are replaced with new elements based on the statistics of local output. Hence, it helps to down sample the data that eventually increases statistical efficiency and reduces memory requirements.    Right now, images are being used as examples, so we will use term pixels instead of elements and also because they are more familiar. For example, in average pooling, local pixels get replaced by average of those local pixels. Similarly, in max pooling, maximum value of pixel among local pixels replaces the remaining local pixels. There are other different types of pooling, such as weighted average pooling, norm pooling, or stochastic pooling, etc. Figure 3.46 represents two most commonly used variants, max pooling and average pooling. The left matrix in Figure 3.46 represents input image, the upper right matrix represents the output by applying max pool function, and the lower right matrix represents output of average pooling function. In this example, we can think that we are using filter of size 2 x 2 and stride \= 2\. These are the hyperparameters in pooling layers. Hyperparameters in the pooling layer remain fixed, meaning these parameters do not change during backpropagation, unlike weights and biases in convolutional layer which change during backpropagation.    ![](image-k077fj1e.jpg)  Figure 3.46: Output after pooling function    The main function of pooling is to add invariance to small translation of the input which, essentially, means that a pooling function prevents the change in value of the output due to small translational perturbation in the input. Generally, selective search algorithm is used to find RoIs, which is a clustering-based approach that groups pixels and generate RoIs based on the generated clusters. These regions are represented with the help of bounding boxes encompassing the complete image. In the earlier object detection models, sliding window detector was used, and each window of a specific size from the original image was used instead of specific regions.    Next, we extract features from each of the bounding boxes, pass those features in the ConvNet created in step 1 for classification, and classify each of the bounding boxes into an appropriate class.    In the last step, overlapping bounding boxes are combined into a single bounding box, an approach known as non-maximum    The intuitive framework discussed above is R-CNN. Though it is very slow, it has inspired and helped the evolution of advanced object detection algorithms that we will be discussing further.  

  Fast R-CNN    Fast R-CNN is the immediate descendant of R-CNN. Although, it is quite similar to Fast R-CNN, it improved on its detection speed through two main augmentations, as discussed below.     Instead of first finding the RoIs and then extracting features from those bounding boxes, Fast R-CNN proposed to first extract features from the image and then use the appropriate feature RoIs for classification. Thus, running one CNN over the entire image instead of running 2k CNNs for 2k region proposals.    Instead of creating a separate model for classification, Fast R-CNN further extended the feature extraction model and included few fully connected layers and a softmax layer for end-to-end feature extraction and classification.  

  Faster R-CNN    Faster R-CNN proposed an alternative to selective search algorithm for finding region proposals in the form of a neural net. It introduced a Region Proposal Network (RPN) for this specific purpose. Now, let’s understand how RPN works.    After generating the feature map through CNN, a 3 X 3 sliding window is moved across the feature map, which maps the feature map into lower dimension. For each sliding window location, multiple possible regions are generated based on k default bounding boxes, known as anchor boxes. For each of these anchor boxes, we output an objectness score that tells whether or not the box contains an object and coordinates of the box.    Once we have these region proposals through RPN, they are fed straight into the Fast R-CNN, discussed earlier.  

  Single Shot Detector (SSD)    Single Shot Detector or SSD is a state-of-the-art real time object detection algorithm that provides enormous speed as compared to Faster R-CNN and also performs comparably well, but with a different approach.    So far, every model that we discussed had two components. First, we generate RoIs or region proposals and then we use ConvNets for classifying those regions. SSD does the two steps in a single shot. As it processes the image, it predicts both, the bounding box and the class.    Now, let’s understand how SSD achieves this once we have the input image and ground truth table for bounding boxes i.e. their coordinates and the objects they contain. Firstly, image is passed through a ConvNet (a series of convolutional layers) which generates sets of feature maps at different scales (to include different object size possibilities) – 10 X 10, 5 X 5, and 3 X 3\. Now, for each location of different feature maps, 3 X 3 filter is used to evaluate a small set of default bounding boxes or anchor boxes. During training, ground truth box (GTB) is matched with the predicted box (PB) based on IoU (Intersection over Union metric). IoU is calculated as shown below:    IoU \= (Common area shared by GTB and PB)/(Area of GTB \+ Area of PB-Common area shared by GTB and PB)    “The best predicted box is labeled as positive”, along with all other boxes that have an IoU with the truth \> 0.5. Through this approach, a large number of bounding boxes are generated, as we classify and draw bounding boxes from every single position in the image, using multiple shapes, at several different scales. To overcome this, NMS or non-maximum suppression, discussed earlier, is used to combine highly overlapping boxes into one.    To summarize, SSD carries out region proposal and classification steps simultaneously. Given n classes, each bounding box is associated with 4+n dimensional vector that outputs 4 box offset coordinates and n class probabilities, and training is carried out by matching this vector with ground truth labels. Let’s get on to how YOLO actually works.    In the past couple of years, researchers have come up with different versions of YOLO, each one an inspired and improved version of the previous one — YOLOv1, YOLOv2, and YOLOv3 are the latest ones.   Feature upsampling and concatenation    YOLOv3 predicts boxes at 3 different scales to successfully capture small as well as large objects. Several convolutional layers are added to the base feature extractor Darknet-53. The last of these layers predicts the bounding box, objectness, and class predictions.   Why RNN?    RNN exploits one of the early and important ideas of statistical learning, called parameter sharing across different parts of a model. Parameter sharing enables a model to generalize on the varying length of input sequence that is not seen during training. Let’s understand the importance of parameter sharing with these two sentences, It was raining in the morning and In the morning, it was raining. When we feed these two lines in a model and look for weather conditions in the morning, we expect raining as an answer, irrespective of the position of the word raining in both sentences.    Now, if we pass these sentences as inputs to a fully connected neural network, the network will have separate parameters for each of the sentences. So, a fully connected neural network needs to learn all the rules of a language separately at each position in the sentence, resulting in a large complex model with huge number of parameters. On the other hand, due to the parameter sharing property, RNN shares the same weights across several time steps, resulting in a less complex model and a lesser number of parameters. Also, a fully connected feedforward network maps only input to output vectors, whereas an RNN maps the entire history of previous inputs to each output.    We can understand the above statements more using Figure Suppose we have a sequential input in the form of Input1, Input2, and Input3, and our objective is to establish a relationship among these sequential inputs. To understand the vanishing gradient problem, let’s take a closer look at the gradient we calculated for W .    Let’s take another look at the gradient propagation through time, , which is a chain rule, along temporal path.    These gradients are stored in a matrix called Jacobian matrix, which contains all pairs of first order gradient propagation. If we apply the overall gradient update for any unit,    ![](image-vcykuzri.jpg)  it turns out that the 2-norm (which we can think of as an absolute value) of the above Jacobian matrix has an upper bound of 1\. As a result, the chain rule of gradient propagation, from layers that capture long range dependencies, exponentially reduces and finally vanishes. In other words, the that is the error propagation through time from the layer 3 to layer k through the temporal connection might vanish as k is large. This is popularly known as the vanishing gradient problem.    There is a related problem called exploding gradient. This happens on the portion of sigmoid or tanh curve where learning is very steep. As a result, the gradients are very large and if it happens in consecutive layers, the error propagation can exponentially increase and lead to an overflow of the variable storing the gradient. This is usually mitigated by capping the gradient over a certain value. It depends on the activation functions and network parameters; it can lead to exploding instead of vanishing gradients if the values of the Jacobian matrix are large.    There are a few ways to avoid the vanishing gradient problem.     Using proper activation function, i.e. using ReLU instead of sigmoid or tanh is effective in combating the vanishing and exploding gradient problem.    Initializing the network parameter using standard techniques.    Using other variants of RNNs, like LSTM or Grated Linear Units (GRUs).  

  Long Short-Term Memory (LSTM)    How to solve the Vanishing gradient problem? The previous section actually contains the solution. To make the gradient propagate through a large context is not always required, especially near the training saturation. This means, when the network is near convergence, the activation function of the nodes is in the saturation region, where the gradient is small. In those instances, the gradient doesn’t need to be propagated through large context length. On the contrary, short-term context representation will mostly contribute to the error at that time. So, the network should have some control on what to remember and what to forget. In other words, the network should have some control based on the input and the hidden state which lets the gradient from previous state pass to the present state. LSTM does exactly that. Long Short-Term Memory, commonly known as LSTM, is another kind of RNN network, which can handle long-term dependencies between data. LSTM stemmed out as a saver for the vanishing and exploding gradient problem. LSTM has been used to solve many practical problems and has become a de facto standard for RNNs. The core idea behind LSTM is compared to RNN; it has several gates. This gate allows the LSTM cell to focus on or forget a specific part of the input sequence depending on the input and output.    LSTM becomes very popular by overcoming this problem and setting benchmarks in a number of fields in natural language processing, like language modeling, machine translation, image captioning, speech recognition, etc.    ![](image-tylzy8sk.jpg)  Figure 5.14: Simple structure of RNN    Figure 5.14 depicts an overview of the simple structure of RNN.   Object recognition and captioning in video    In the field of computer vision, recognition and description of images and videos is a fundamental challenge. The object recognition task is more complicated in videos than in images, as different frames can refer to different objects, making detection more challenging. Ideally, a video model should allow processing of variable length input sequences, and also provide for variable length outputs, including generation of full length sentence descriptions that go beyond conventional one-versus-all prediction tasks. Networks that can play this role is called Long-Term Recurrent Convolutional Networks (LRCNs), a class of architectures for visual recognition and description which combines convolutional layers and long-range temporal recursion. Figure 5.25 shows the architecture of LRCNs.    ![](image-9j2lomcs.jpg)  Figure 5.25: Long-Term Recurrent Convolutional Networks (LRCNs)    In Figure 5.25 CNN (middle-left) extracts features from a variable-length visual input (left), those features are fed into a stack of LSTMs networks(middle-right), which finally produce a variable-length prediction (right). RNNs allow us to understand the context of a video frame, relative to the frames that came in sequence. Combination CNN \- RNN architecture has shown good results in video classification problems. The video classification framework is a broad class of video analytics problem, which includes motion tracking, action recognition, and video type detection.    Video classification explores the application of LSTM beyond the prediction of short snippets related to video or video captioning. It explores the application of stacked CNN and LSTM for video classification. Given a set of videos V \= … vn and label Yv \= … the video classification problem tries to implement the CNN-LSTM stacked network to learn what type of frames distinguish one class from another. Here the LSTM, unlike the captioning problem, doesn’t learn the distribution over words; instead, it tries to learn the context of the video frame by frame. Alternatively, this is a problem of video understanding; as the previous CNN layer helps in image processing and feature generation.    Figure 5.28 depicts a two stream CNN-LSTM network for video classification. Specifically, the spatial and the short-term motion features are extracted separately by two Convolutional Neural Networks. The two streams have different functionality. One stream has the raw image as input. It captures the spatial features which is essential for object detection or recognizing the action in the video frames. Action detection is a difficult problem than object detection because, in action recognition, a lot of frames need to be summarized to form the action. This is where the second stream helps. The second stream has motion feature detection using Shift-CNN framework. The input are the shift features in the frame, and the CNN further tracks the object through the shift vector. Finally, LSTM networks are applied on top of the two features to further model longer-term temporal clues.    ![](image-cgjbimgt.jpg)  Figure 5.28: Video classification    Figure 5.28 depicts that for an input video, two types of features are extracted using the CNN from spatial frames and stacked motion optical flows respectively. The features are separately fed into two sets of LSTM networks for long term temporal modeling (Left and Right). In addition, we also employ a regularized feature fusion network to perform video-level feature fusion and classification (Middle). The outputs of the sequence-based LSTM and the video-level feature fusion network are combined to generate the final prediction.
