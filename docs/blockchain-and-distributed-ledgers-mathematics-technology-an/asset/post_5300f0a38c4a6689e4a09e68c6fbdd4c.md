
Let a message be $m = 66$. Choose random $l = 83$. It is easy to check that:

$l^{-1} = 101,$
$B = l \times G = (122, 3),$
$s = (m + kr) l^{-1} = 79 \pmod{127},$
$s^{-1} = 82,$
$ms^{-1} = 78 \pmod{127},$
$P_1 = ms^{-1} \times G = (85, 77),$
$rs^{-1} = 98 \pmod{127},$
$P_2 = rs^{-1} \times A = (18, 88),$
$P_3 = P_1 + P_2 = (122, 3) = B.$

Since $P_{3,x} = B_x$, the signature is valid.

## 4.7.11 Diffie-Hellman key exchange

The elliptic curve based Diffie-Hellman key exchange (ECDH) follows the same reasoning as above; see Eqs (4.22) and (4.23). As before, the key exchange uses two-way functions, $f, g$. Not surprisingly, elliptic curve multiplication of the base point $G$ by secret keys can do the trick because

```
$$d \times (c \times G) = c \times (d \times G).\quad$ (4.158)$$
```

As with the discrete log version, this cannot be used for encryption or signing but can be used for the key exchange.
Public parameters $T = (p, a, b, G, n, h)$, the ECDH proceeds as follows:

- (1) Alice chooses a secret $c$ and makes $C = c \times G$ public;
- (2) Bob chooses a secret $d$ and makes $D = d \times G$ public;
- (3) Both create the same key $k$, which is the coordinate of $E = D \times c = c \times D$.

```
$$k_E = (d \times (c \times G))_x = (c \times (d \times G))_x.\quad$ (4.159)$$
```

To make the abstract more concrete, we consider a simple example. For obvious reasons, using cryptographically suitable numbers is out of the question, so instead, we consider the curve $E_{127}$ shown in Figure 4.2 (b). As was mentioned earlier, the number of points on $\#E_{127} = 127$ is prime, so we can choose any point on the curve as base point, say $G = (45, 33)$. The order of this point is 127. Let Alice choose a random secret $c = 97$, and Bob choose $d = 34$.

```
$$C = (94, 30), D = (51, 109).\quad$ (4.160)$$
```

```
$$E = 34 \times C = 97 \times D = (86, 89), k = 86.$$
```

Thus, on the surface, EC cryptography is highly advantageous compared to RSA cryptography. However, there is one crucial aspect to think about. RSA-based PKI relies on user-supplied parameters, namely $(n, e, d)$. In contrast, EC-based PKI partially depends on a specific EC, say secp256r1, with parameters given by Eq. (4.146) that are provided by a third party, and partially on a random secret key k, chosen by the user. Although highly likely, there is no guarantee that the third party holds nothing-up-sleeve and has inserted backdoors, allowing to find secret keys associated with public addresses faster via brute-force attack. ## 4.9 Cryptographic hash functions

### 4.9.1 Hash functions

Hash functions are somewhat different from one-way functions, but not completely. Recall that a one-way function is easy to compute but hard to invert. A hash function is easy to compute but difficult to find a preimage for. Thus, it is easy to calculate y = h(x) from x. However, it is hard to find x' such that h(x') = y, even though there are plenty of possible candidates.

By very nature, every hash function with longer inputs than outputs has collisions. For example, a hash function such as SHA-256 produces 256 bits of output from any input (which can be up to 2^64–1 bits long). Thus, SHA-256 generates 2^256 outputs, for the much larger set of 2^n inputs so that many inputs hash to the same output (the-called pigeonhole principle). Collision resistance means that collisions are hard to find; see, e.g., Goldwasser and Bellare (2008). We show how to build collision-resistant functions, which are very important for cryptography, next.

### 4.9.2 Collision-resistant functions

Strongly-resistant hash functions are those where it is computationally hard to find any two distinct inputs $x_1, x_2$ such that $h(x_1) = h(x_2)$. In contrast, weakly-resistant hash functions are those where it is hard to find any input $x$ for a given output $y$.

### 4.9.3 Signatures and hash functions

As mentioned earlier, it is practical to sign the message. However, it is often more efficient to sign a hash of the message instead of the message itself. This is because the hash is much shorter than the message, making the signature smaller.

### 4.9.4 Birthday attacks

The birthday problem arises in probability theory. The problem is to find the probability that, in a set of n chosen people, there is a pair of them with the same birthday. In its present form, the problem was formulated by Richard von Mises; see Frank et al. (1964). Occasionally, the problem is also called the birthday paradox, not because it is a paradox but because the results seem to be very counterintuitive. This probability is nearly 100% for n=367 since 366 birthdays are possible. Below, with all due respect to leptons, we disregard leap year and all days of the year are equally probable. It turns out that 50% probability is reached with 23 people, n = 23, and 99.9% probability is reached with 70 people, n = 70.
