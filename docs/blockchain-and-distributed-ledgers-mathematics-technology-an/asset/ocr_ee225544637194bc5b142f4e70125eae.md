# 5.5.1 Consensus

As mentioned in Chapter 3, a distributed ledger, such as Bitcoin, is worth its salt only if it can maintain its integrity via a proper consensus algorithm. In other words, all participants should be able to agree on the validity of all the transactions for the most recent ones. Of course, it is a difficult task in a distributed system, which was viewed as practically impossible for many years. However, by its very existence, the Bitcoin protocol has shown that such a consensus is indeed possible, albeit challenging and expensive to achieve; see Pass et al. (2017).

One can build a simplified consensus algorithm based on the assumption of a random, but fair, node selection. Such selection cannot give every node equal chance because it will make the whole system vulnerable to the so-called Sybil attacks, since acquiring a node, represented by an address, is practically costly, see Subsection 3.6.1. Thus, the consensus by the majority of nodes does not guarantee the system's integrity. Accordingly, an opportunity to be selected as a validator should be proportional to the node's resources spent participating in the game. Of course, miners are not selfless. Their objective is to collect rewards by the system for validating transactions and all the transaction fees they get.

As shown in Figure 5.12, participants broadcast new transactions to the entire Bitcoin ecosystem. Every miner collects some of the recent transactions and, for other reasons, blocks are not identical. It is possible to have a situation when a miner decides to mine a block to get the block-mining reward. More importantly, if a particular transaction does not pay an attractive transaction fee, it can be left dangling in a memory pool for a very long time, or be dropped altogether, which is a feasible aspect of the protocol.

Achieving consensus by mining is done along the following lines, see Subsection 3.6.2. Once the previous block is included in the blockchain, and new transactions announced, miners assemble them into blocks (2,000 transaction per block), hash them, and form a new block header.
