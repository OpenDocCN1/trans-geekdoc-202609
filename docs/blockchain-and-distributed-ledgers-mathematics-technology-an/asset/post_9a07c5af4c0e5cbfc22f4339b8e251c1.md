Assume Charlie knows Alice is prepared to sign a document $d'$ and claim Alice signed it. Charlie takes the fraudulent contract $d'$ and produces small changes in it. $K$ will vary with $2^K$ different documents, $d_1, \dots, d_K$, and similarly, $2^K$ different documents $d'_1, \dots, d'_K$. If the hash values are shorter than $2K$, then a match's probability is very high due to the birthday paradox.

## 4.9.5 The random oracle hash

A random hash function ROHF is a function that produces a fixed-length output for any input. When it receives a particular input for the first time, it gives a random output. If it gets the same input, it will reproduce the same output. A ROHF is an ideal collision-resistant hash function. It can be used to protect the security of encryption/signing provided that the assumption that the functions used behave like a random oracle is valid. However, to show that a given hash function is ROHF usually prefers strong evidence rather than real proof. Still, if a hash function fails a ROHF test, we should look for new candidate hash functions.

## 4.9.6 A practical hash function

While ROHF is more of a theoretical construct, it is crucial to design hash functions that one can successfully use in practice. A practical hash function transforms messages of any length to a fixed-length digest. It has to depend on every bit of the message so that changes of one bit will result in changes in the hash. In the simplest case, the algorithm has to be completely transparent, so that anyone who should be able to check the validity of the hash. In general, a practical hash function could depend on a secret parameter, which restricts possible verification to the group of participants who know the secret.

A general hash function has to have the following properties:

- (1) Input is a string of any size, size $n$-bit, where $n$ is a large number;
- (2) Output is a string of fixed size, size 256-bit;
- (3) Computation is efficient and requires $O(n)$ operations.

A cryptographic hash function has to have additional properties:

- (1) Collision-resistance — it is infeasible to find two values $x$ and $z$, such that $x \neq z$ and $H(x) = H(z)$;
- (2) Obfuscation — given $y$, it is infeasible to find $x$, such that $y = H(x)$;
- (3) Binding — it is infeasible to find $x, x'$, such that

```
H(r|x) = H(r'|x)
```

where || denotes concatenation of inputs.

## 4.9.7 Search puzzles and hash functions

A puzzle can be formulated as follows: given a hash function, a value $x$ from a high min-entropy distribution, i.e., a sufficiently random distribution, and a target set $Z$, find a solution $y$, such that

```
H(x|y) \in Z
```

where || denotes concatenation. A hash function H() is puzzle-friendly, if for an $x$, chosen from a high min-entropy distribution, it is infeasible to find $y$, such that

```
H(x|y) \in Z
```

faster than $O(2^n)$ time. For a puzzle-friendly hash function, there is no better strategy than a random try. As we see in the next chapter, such functions are ideal instruments for the so-called proof-of-work consensus algorithms.

Here is a simple example. Let $H$ be SHA-256 considered in Section 4.10.3 and $x = aaa$: a hexadecimal number. ## 4.10 Secure hash algorithms

### 4.10.1 Background

Although designing a reliable, secure hash algorithm (SHA) is difficult, there are numerous candidates. Bitcoin and many other systems use SHA-256 and RIPEMD-160 (RIPE Digest). As its name says, SHA-256 maps any arbitrary string into a 256-bit digest.

Below briefly use SHA-256; however, for practical purposes, it is sufficient to note that SHA-256 uses the Merkle–Damgård transform and turns a fixed-lengthresistant compression function into a function with arbitrary-length inputs by applying it sequentially. The input is padded as necessary to make its length a multiple of 512 bits.

Several hashing algorithms are used in practice, such as MD5, SHA1, SHA2. However, older algorithms, such as MD5, are broken and can no longer be used for cryptographic purposes (even occasionally they are still used for less sensitive tasks).

In 2007 NIST started a contest for replacements for SHA1 and SHA2. The proposed algorithms’ quality was judged based on their speed, security, depth of analysis, and other considerations. Five SHA3 candidates were chosen for the final evaluation: BLAKE, Grøstl, JH, Keccac, and Skein. In 2012 NIST announced Keccac as the winner.
