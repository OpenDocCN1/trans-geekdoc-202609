We note that in the Bitcoin protocol, and by extension, most crypto protocols, which predominantly use hexadecimal numbers rather than strings, are always hashed twice:

```
x → SHA256(x) → z = SHA256(y) . (4.188)
```

The second hashing is used as a safety mechanism against the so-called "length-extension" attack; see Ferguson et al. (2010). A length extension attack allows an attacker who knows the length of a message m1 and its Hash(m1) to calculate the Hash(m1||m2) of the message m1 concatenated with an attacker-chosen message m2, without knowing m1. Algorithms, relying on the Merkle–Damgård construction, as MD5, SHA-1, and SHA-2, can be vulnerable against such an attack. The new SHA-3 algorithms are secure in this respect.
