# 5.3.5 Transaction verification

In this book, we consider a relatively straightforward script — P2PKH. For a detailed analysis of more complicated scripts, the reader can consult several useful sources; see, e.g., Antonopoulos (2017). The P2PKH script has the following form

```
<sig>
<publicKey>
OP_DUP
OP_HASH160
<pubKeyHash>
OP_EQUALVERIFY
OP_CHECKSIG
```

Here, quantities in brackets denote the inputs. Recall that in the modern version of the Bitcoin protocol, an address is a hash <pubKeyHash> of the actual address <publicKey>, so the sender sends to hash. For reasons, the recipient, who wishes to redeem these outputs and send them to someone else, must provide the signature and the public key, which produces the correct address. The assuming that the right signature and address are provided, the stack undergoes the following push and pop transformations:

```
$S_1 = <sig>$,n$S_2 = <sig> <publicKey>$,n$S_3 = <sig> <publicKey> <publicKey>$,n$S_4 = <sig> <publicKey> <pubKeyHash>$, (5.13)
$S_5 = <sig> <publicKey> <pubKeyHash>$,n$S_6 = <sig> <publicKey>$,n$S_7 = TRUE$.
```

Here, <pubKeyHash> is the hash of the payee's address. Otherwise, the output is FALSE, and the transaction is invalid. The push and pop steps, executed from left to right, are presented graphically in Figure 5.11.
