As any other consensus mechanism, the Ripple protocol is based on three plausible assumptions about the behavior of validating servers: Every non-faulty server decides whether to accept or reject a proposal in time. Furthermore, all non-faulty servers arrive at the same decision. And finally, both true and false decision regarding a given transaction is possible.

The Ripple protocol consensus algorithm consists of sequential rounds: Every proposal compiles a valid list of candidate transactions. Each server includes all candidate transactions coming from its UNL and notes the validity of these transactions. Transactions passing the minimum voting threshold proceed to the next round. The final round requires 80% agreement. Voting rounds continue until the 80% threshold is reached.

It is straightforward to show that $N$ validators maintain correctness of the Ripple protocol, provided that the number of faulty ones, $f$, is bounded as follows:

> $f \le \frac{N-1}{5}$

Alternatively, if the probability of malicious behavior is $p_c$, then the probability of correctness $p^*$ has the form:

> $p^* = \sum_{i=0}^{N-1} \binom{N}{i} p_c^i (1-p_c)^{N-i}$

where $\binom{N}{i}$ is the binomial coefficient.
