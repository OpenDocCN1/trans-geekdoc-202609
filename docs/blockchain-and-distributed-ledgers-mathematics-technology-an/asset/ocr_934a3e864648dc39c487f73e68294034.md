# 9.7.5 On-chain validation

Most ledger protocols allow the definition of accounts controlled by more than one party, as illustrated in Figure 9.12. One can implement transaction approval workflows requiring on-chain validation of multiple signatures, as an m-by-n$ scheme. The approach has been common in the Bitcoin protocol, which natively supports multi-signature scripts; it can also be trivially implemented in Ethereum via smart contracts.

On the flip side, on-chain validation of non-trivial approval workflows suffers from a series of drawbacks:

+   (1) it makes the validation process visible to the blockchain observers, who can infer the security model of the wallet and track in real-time of the respective approvals have been submitted;
(2) it increases transaction fees because of the additional complexity of multi-signature wallets as compared to basic transactions;
(3) it is not guaranteed to exist on all distributed ledger protocols — some of them not supporting multi-signature — and its implementation may differ largely from one to another. For instance, Bitcoin supports multi-signature scripts natively; Ethereum supports them through the definition of smart contracts only. Ethereum would support amount-dependent approval workflows whereas Bitcoin would not.
