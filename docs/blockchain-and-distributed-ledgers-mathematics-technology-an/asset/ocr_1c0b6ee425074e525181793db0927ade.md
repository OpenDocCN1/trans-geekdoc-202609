so that Alice's signature is valid. Thus, the signing of a message requires one exponentiation, while its verification requires three exponentiations and is expensive.

As always, it is imperative not to forget the OTP. Accordingly, Alice has to choose the parameter $k$ at random for every new signature. If she fails to do that, the first half of a DSA signature $r$,

```
$r = a^k \bmod p.$
```

will tell Charlie that $k$ is reused. By knowing this, Charlie can do the following calculation:

```
$s_1 = (m_1 + ar)k^{-1} \bmod (p - 1)$,
```

```
$s_2 = (m_2 + ar)k^{-1} \bmod (p - 1)$,\n\n$s_2(m_1 + ar) = s_1(m_2 + ar) \bmod (p - 1)$,
```

```
$a = (s_2m_1 - s_1m_2) ((s_1 - s_2) r)^{-1} \bmod (p - 1)$.
```

Thus, Alice recovers the secret key and decodes the corresponding message as easily as the intended recipient.

# 4.6.5 Schnorr digital signature algorithm

The Schnorr DSA is an influential and ingenious extension of the ElGamal DSA; see Schnorr (1988). The algorithm chooses suitable primes $p, q$, and a generator $\alpha$, such that

```
$$\alpha^q = 1 \bmod p$.
```

The triple $(p,q,a)$ is common for all users. The recommendation is to choose 1024-bit prime $p$, and 160-bit prime $q$.

The signature algorithm proceeds in four steps:

+   (1) Alice chooses a random integer $a, 0 < a < q$ and calculates $eta = \alpha^a \bmod p$;
(2) Alice's public key is $(p, q, \beta)$, while her secret key is $a$;
(3) Alice chooses a random integer $0 < k < q$, and computes $\gamma = a^k \bmod p$;
(4) Alice concatenates the message $m$ and $\gamma$, hashes the result $r = h(m|\gamma) \bmod q$, and creates the signature pair $(r,s)$

```
$(r,s) = (r, (k + ar) \bmod q)$.
```

The verification algorithm proceeds in two steps:

+   (1) Bob computes $t = \alpha^a\beta^{-r} \bmod p$ and $u = h(m|t) \bmod q$;
(2) Bob compares $r$ and $u$.
