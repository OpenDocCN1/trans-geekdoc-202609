# 4.3.2 Cryptographic one-way functions

One-way functions are the main building blocks of asymmetric cryptography. A one-way function is a function that is easy to compute, but computationally hard to invert. It is easy to find $f(x)$ given $x$, but it is (very) hard to find $x=g(y)$ given $y$. As mentioned in the introduction, we have no proof that no one-way functions exist; and rely on evidence instead. Trapdoor one-way functions are one-way cryptographic functions that are hard to invert in general but easy to invert, provided that some information is available. Below we consider some representative examples.

# 4.3.3 Abstract encryption-decryption algorithm

Abstract encryption-decryption algorithm (EDA) consists of three steps:

+   (1) Bob generates a secret key $sk$ and a public key $pk$:

$$(sk, pk) := generatekeys();$$ (4.16)

+   (2) Alice applies the encryption method, which uses her message and Bob's $pk$ to generate a cipher:

$$cipher := encrypt(pk, message);$$ (4.17)

+   (3) Bob applies the decryption method, which uses the cipher, and his $sk$ to get the plaintext:

$$message := decrypt(sk, message);$$ (4.18)

In asymmetric cryptography, a recipient keeps his secret key, while making his public key readily available to everyone. By encrypting a message with her public key, the sender allows only the recipient to decrypt the cryptogram with the secret key. Figure 4.3 (a) shows the corresponding flowchart.

# 4.3.4 Abstract digital signature algorithm

Abstract digital signature algorithm (DSA) consists of three steps:

+   (1) Alice generates a secret key $sk$ and a public key $pk$:

$$(sk, pk) := generatekeys();$$ (4.19)

+   (2) Alice applies the sign method, which uses a message and her $sk$ to generate a signature:

$$sig := sign(sk, message);$$ (4.20)

+   (3) Bob applies the verify method, which uses a message, a signature, and Alice's $pk$ to verify if the signature is valid:

$$is Valid := verify(pk, message, sig);$$ (4.21)
