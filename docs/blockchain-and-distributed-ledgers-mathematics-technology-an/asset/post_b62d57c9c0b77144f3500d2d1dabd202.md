## 4.2.2 Caesar’s cipher

As the name suggests, Caesar’s cipher goes back to antiquity. Every plaintext letter is replaced by the letter k positions further to the right in the alphabet, which is cyclically called. For example, we can transform the letter Affine to F, so that:

```
ABCDEFGHIJKLMNOPQRSTUVWXYZ
↓
FGHIJKLQRSTUVWXYZABCDE  (4.1)
```

We can replace every letter with a number, $A \rightarrow 0, B \rightarrow 1, \dots, Z \rightarrow 25$, and express the key as an integer, for instance, $F \rightarrow k = 5$. Assuming that the $i$-th letter in the message is represented by an integer $m_i$, $0 \leq m_i < 26$, the $i$-th letter in the cryptogram is an integer $c_i$:

```
$c_i = (m_i + k) \pmod{26}$.  (4.2)
```

Thus,

```
$C A T = 02 00 19 \Rightarrow 07 05 24 = H F Y$.  (4.3)
```

The decryption is performed as follows:

```
$m_i = (c_i - k) \pmod{26}$.  (4.4)
```

Thus,

```
$H F Y = 07 05 24 \Rightarrow C A T = 02 00 19$.  (4.5)
```

To break Caesar’s cipher, try each key and stop when the plaintext becomes clear. Caesar’s cipher is monoalphabetic so that one letter in the plaintext is always represented by a single letter in the cipher. If, the message is sufficiently long, or its general content can be guessed, Caesar’s cipher can be broken by the frequency analysis.

## 4.2.3 Affine cipher

Caesar’s cipher uses one of 25 keys to produce a simple mapping. A more general affine cipher uses a pair of keys $(l, k)$, $0 < l \leq 12$, $0 \leq k < 26$, to produce a mapping

```
$c = (lm + k) \pmod{26}$.  (4.6)
```

The reader should verify that the number of different keys, $(l, k)$ is $12 \times 26 = 312$.

## 4.2.4 A simple substitution cipher

A simple substitution creates a table of plaintext characters and their corresponding crypto images. For example, this is a substitution table used in the first rotor of the celebrated Enigma machine (see below):

```
ABCDEFGHIKLMNOPQRSTUVWXYZ
\downarrow
EKMFLGDQZNTOWHXUSPABRCJ \quad (4.7)
```

Similarly to Caesar's cipher, a substitution cipher is monoalphabetic, so that it can be broken by the frequency analysis, even though there is an enormous number of possible substitutions. More precisely, $26! = 4.03 \times e^{26}$. Thus, the number of possible substitutions alone does not make a cipher secure.

## 4.2.5 The Vigenère cipher

The cipher, mistakenly attributed to Blaise de Vigenère, then invented by Giovan Battista Bellaso in 1553, creates a stream of key letters, and uses one after another for Caesar's encryption of the plaintext letter, thus using the polyalphabetic substitution; see Singh (2000). If the key is longer than the message, which is usually the case, the key is repeated until it matches the message's length. For centuries, it was known as *le chiffre indéchiffrable* (the indecipherable cipher). Eventually, Friedrich Kaski published a general method of decrypting Vigenère ciphers in 1863.

Assuming that the $i$-th letter in the message is represented by $m_i, 0 \le m_i < 26$, the cryptogram is $c_i$:

```
$c_i = (m_i + k_i) \pmod{26} \quad (4.8)
```

where $k_i$ is the $i$-th letter of the key. For example, if we use a key with "KEY", the keys for each round are 10, 04, 24, ..., or equivalently, A->K, A->E, A->Y, ..., then the word CAT becomes MER,

```
$C A T = 00 02 19 \Rightarrow 12 04 17 = M E R. \quad (4.9)
```

## 4.2.6 The Enigma machine

The Enigma machine, also called the Enigma, was invented by the German engineer Arthur Scherbius at the end of World War I. Initially, it was commercially mostly to private enterprises, who wished to keep their communications confidential. Eventually, the German Armed Forces and several other militaries started to use it. The Enigma relies on the same principle as the Vigenère cipher and performs a very long substitution sequence.

Surprisingly, the secret source is in the automated process of the key generation. The electro-mechanical Enigma uses three rotors, a plugboard, and a reflector to achieve its goal. Rotors move after each keystroke, creating a very long key sequence longer than any of the messages sent. The number of possibilities is seemingly huge. ## 4.2.7 A one-time pad

A one-time pad (OTP) is the only theoretically secure cipher. It was discovered by Frank Miller in 1882, and rediscovered by Gilbert Vernam and Joseph Mauborg in 1918; see Kahn (1996); Miller (1882). In simple terms, the OTP generates a Vigenere sequence with a randomly chosen key as long as the message. The one-time pad has perfect security in the sense that

$$H(M|C) = H(M)$$

where $H(\cdot)$ is the so-called Shannon entropy and $H(\cdot)$ is the conditional entropy. Thus, M and C are statistically independent. In other words, for every message M and ciphertext C, we can find at least one K that binds them as a one-time pad.

The intuition behind OTP security is relatively simple. Assume that we have complete statistics for every possible plaintext of the length L. For a given cryptogram and a plaintext M, there is a corresponding key K encrypting M into the cryptogram. Since every key is as likely as another, there is no clue to prove which plaintext is more likely.

In binary notation, OTP operates with XOR (exclusive or) bitwise arithmetic, so that

```
0 oplus 0 = 0, 1 oplus 0 = 1, 0 oplus 1 = 1, 1 oplus 1 = 0.
```

For instance, if

```
m = (1111000000), k = (0011000101),
```

then

```
c = m + k = (1100101011), m = c + k = (1111000000).
```

Despite its theoretical appeal, there is a problem with OTPs — to use the OTP, we must generate a truly random key sequence, which is as long as the message we want to encode. Transferring the key is as hard as the message itself. If you wish to encrypt a computer drive, you need another drive of the same length — obviously an issue! In practice, we can use a stream cipher, which we describe.

## 4.2.8 A stream cipher

To succeed with an application of OTP, we need to have a perfectly random key. What if, instead, we try to generate a pseudo-random (but not random) “keystream” from a seed? We call the seed “real key,” the advantage that it is much shorter than the full “keystream” added to the message. Still, the set of “real keys” or seeds has to be so large, to make an exhaustive search of the search space practically impossible. If this approach is used, pseudo-randomness (rather than full randomness) is a prerequisite, since both sender and receiver must receive the same key from the seed. The very nature of pseudo-random generators, their output is periodic, which is a problem in theory, but less so in practice, provided that the period is long enough. In this case, if the key is unknown, every output bit is unpredictable.
