# TABLE 8.2 Microsoft Threat ModelingTool Mitigations (continued)

| Category | Description |
| :--- | :--- |
| Authorization | What can you do? Resource and operation access is controlled by authorization within your application.<br>The following are recommendations from Microsoft for specific products/services from an authorization standpoint.<br><b>Web Application</b><br>- Ensure that business logic flows are processed sequentially.<br>- To prevent enumeration, implement a rate limiting mechanism.<br>- Follow the principle of least privilege and ensure proper authorization.<br>- Request parameters should not be used to determine business logic and authorization decisions for resource access.<br>- Don’t allow forceful browsing or enumeration of content and resources.<br><b>Database</b><br>- When connecting to a database server, use the least-privileged account.<br>- Data access by tenants can be prevented by implementing row-level security (RLS).<br>- There should be only valid users in the sysadmin role. |
| Communication Security | Who are you talking to? All communication is secured using communication security.<br>The following are recommendations from Microsoft for specific products/services from a communication security standpoint.<br><b>Web Application</b><br>- SSL, TLS, and DTLS connections are authenticated with X.509 certificates.<br>- In Azure App Service, configure TLS/SSL certificates for custom domains.<br>- Traffic to Azure App Service should be sent over HTTPS.<br>- HTTP Strict Transport Security (HSTS) should be enabled.<br><b>Database</b><br>- Ensure that SQL Server connections are encrypted, and certificates are validated.<br>- Communication with the SQL Server must be encrypted. |
