## 7.7.8 Strength of ECC-Based Schemes

- Let $E_p(a, b)$ be an Elliptic Curve where $p$ is a large prime number.
- Let $G \in E_p(a, b)$ be the Base Point chosen, and $n$ is the Order of Base Point $G$. The Base Point $G$ is chosen so that its Order $n$ should be very large.
- Let $n_i$ be an integer such that $(1 < n_i < n)$.
- Knowing $n_i$ and $G$, it is easy to compute $P_i = n_iG$.
- But, knowing $P_i$ and $G$, it is very difficult (computationally infeasible) to determine $n_i$. This is equivalent to taking discrete logarithms. This provides the strength to ECC-based Schemes.

## 7.7.9 ECC-Based Key-Exchange Algorithm

1. Suitable Global Parameters are chosen, which are shared among all users in the system:
$E_p(a, b)$: Elliptic Curve Set, where $p$ is a large number and $a, b$ are coefficients of the congruence $Y^2 \equiv (x^3 + ax + b) \pmod p$
$G$: Base Point in $E_p(a, b)$ such that it has large Order
$n$: Order of Base Point $G$ in $E_p(a, b)$

2. A key exchange between two Users "A" and "B" is accomplished by the following steps in Figure 7.4:
![](img/d3b642c75fbcc011ff06b9f530343.png)
7.4 A schematic diagram of ECC-Based Key-Exchange Algorithm.

A. User "A" selects a private key $n_A$ such that $1 < n_A < n$ and computes a public key $P_A = n_AG$.
$P_A$ will be a point from $E_p(a, b)$. User "A" keeps $n_A$ secret and sends $P_A$ to User "B."

B. User "B" selects a private key $n_B$ such that $1 < n_B < n$ and computes a public key $P_B = n_BG$.
$P_B$ will be a point from $E_p(a, b)$. User "B" keeps $n_B$ secret and sends $P_B$ to User "A."

It can be verified that the secret keys $K_A$ and $K_B$ computed by "A" and "B" respectively are:
$K_A = n_AP_B = n_A(n_BG) = n_B(n_AG) = n_BP_A = K_B$

## 7.7.10 Strength of Key-Exchange Algorithm

$E_p(a, b), G$, and $n$ are global parameters, known to all users in the system. It is presumed that an adversary will also have access to these parameters. In addition, it is presumed that an adversary can access $P_A$ and $P_B$ from the communication media. But, an adversary needs knowledge of either $n_A$ or $n_B$ which are known only to User "A" and User "B" respectively. Computing $n_A$ from $P_A$ and computing $n_B$ from $P_B$ are considered very difficult (or infeasible), since $n$ is very large. Thus, an adversary would not be able to determine the secret key.

## 7.7.11 ECC-Based Encryption/Decryption Scheme

1. Selection of Suitable Global Parameters: Global Parameters are chosen, which are shared among all users in the cryptystem:
$E_p(a, b)$: Elliptic Curve Set, where $p$ is a large number and $a, b$ are coefficients of the congruence $Y^2 = (x^3 + ax + b) \pmod p$
$G$: Base point in $E_p(a, b)$ such that its order will be very high.
$n$: Order of Base Point $G$ in $E_p(a, b)$

2. Determination of Keys by the Users: Each user (User "A") in the cryptystem determines its Private Key and Public Key as follows:
* "A" selects a large integer $n_A$ as its Private Key, which "A" keeps private (secret).
Then "A" determines its Public Key $P_A = n_AG$ and makes it available to all other users in the cryptosystem.

3. Encryption of Plaintext by Sender: Supposing any user in the cryptosystem intends to send a message $M$ over "A," then it proceeds as follows:
- First message $M$ is encoded in $E_p$ for mapping it to one of the points (say $P_m$ in $(a, b)$) is reversible, that for each possible value of plaintext $M$, there will be a unique point from $E_p$ $(a, b)$.
- Encryption of $P_m$ by Sender
- Sender selects a random integer $k$ such that $1 < k < n$
- Using the public key $P_A$ of intended recipient "A," the sender encrypts the plain text $P_m$ and creates a cipher-text $C_m$:
$C_m = \{kG, P_m + kP_A\}$
The cipher-text $C_m$ comprises two components. Both components are points from $E_p(a, b)$. The first component $kG$ is called "clue," since it provides a clue about parameter $k$ to the recipient, since $k$ is known only to the sender.

4. Decryption of $C_m$ by recipient "A": "A" receives the cipher-text $C_m$ and decrypts it using its private key $n_A$, which is known only to "A."
- Multiplies $kG$ by $n_A$
- Subtracts the result of step (i) from $P_m + kP_A$ i.e., $P_m + kP_A - n_AG = P_m$
Thus, the recipient "A" is able to extract the encoded plaintext $P_m$, without having any knowledge of parameter $k$.
