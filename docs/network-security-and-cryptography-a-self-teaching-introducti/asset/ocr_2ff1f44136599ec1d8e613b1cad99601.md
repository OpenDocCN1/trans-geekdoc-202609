The transmitted package, comprising cipher-text and MAC, is then transmitted.

At the recipient end, MAC is generated from the received cipher-text and this MAC is compared with the MAC received from the sender. If the two match, then the message is considered to be authenticated.

Then message $M$ is recovered from the cipher-text by decrypting it using symmetric decryption and key $K_2$.

# 8.3.6 Chosen Plaintext Attack on MAC

If the message is not encrypted, then an opponent has access to the plaintext messages and their associated MAC values. Suppose $k$ is the size of the secret key and $n$ is the size of MAC and $k > n$. Then, given a known plaintext message $M_i$ and its $MAC_i = C_K(M_i)$, a cryptanalyst may apply all possible values of the key to message $M$ and determine corresponding MAC values. At least one of the keys $(K)$ will produce a MAC value matching $MAC_i$. In fact, all $2^k$ values will be produced. Since $k > n$, we have $2^k > 2^n$; thus, more than one key will produce a match for $MAC_i$. On the average, $2^k/2^n = 2^{k-n}$ keys will produce a match for $MAC_i$.

Based on these facts, there is a chosen plaintext attack on MAC, which is summed up as follows:

# Round 1

+   - Randomly choose a message $M_i$ and its $MAC_i$

+   - The adversary will determine the set of keys that satisfy $MAC_1 = C_K(M_1)$

+   - The number of keys that will produce a match for $MAC_1 = 2^{(k-n)}$

# Round 2

+   - Now, choose another message $M_2$ along with its $MAC_2$

+   - Now, use $2^{(k-n)}$ keys, determined in the previous round, and determine MAC value of message $M_2$

+   - The number of keys that are likely to produce a match for $MAC_2 = 2^{(k-n)}$
