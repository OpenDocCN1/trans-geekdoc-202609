# 9.5.2 Kerberos Version 5 Authentication Sequence

Message 1 Authentication Service Request (KRB AS_REQ) from Client to Authentication Server (AS)

C→AS: Options || ID_e || Realm_e || ID_{tgs} || Times || Nounce_e

Where

Options: Client specified options for the Ticket Granting Ticket (TGT) requested from AS:

FORWARDABLE: The Ticket to be forwardable

PROXABLE: The ticket to be proxy-able, etc.

The Authentication Server's response to the Options' request will be reflected in a Flag.

ID_e: User ID on the Client

Realm_e: Realm of the Client

ID_{tgs}: TGS Identification tgs

TIMES: includes validation period (From ... To)

Nounce_e: A random integer value to prevent replay attacks

Message 2 Authentication Service Reply (KRB_AS_REP) from AS to C, for obtaining Ticket Granting Ticket (TGT) Ticket_{tgs} and a Session Key K_{c,tgs} for communication between C and TGS.

AS→C: Realm || ID_e || Ticket_{tgs} || E_{k_{c,tgs}} || Times || Nounce_e || Realm_{tgs} ID_{tgs}

Ticket_{tgs} || E_{k_{c,tgs}} [Flags || Realm || ID_e || AD_e || Times]

The Flag contains the options available for use of Ticket_{tgs}, like Forward-able, Proxy-able, and so on. Times will indicate the validity period, and this can be post-dated in the Flag.

Message 3 Ticket Granting Service Request (KRB_TGS_REQ) from C to TGS, for obtaining Service Ticket Ticket and a Session Key K_{c,s} for communication between C and Application Server V.

AS→C: Options || ID_e || Times || Nounce_e || Ticket_{tgs} || Authenticator Authenticator_{c1} = E_{k_{c,tgs}} [ID_e || Realm_e || TS_1]
