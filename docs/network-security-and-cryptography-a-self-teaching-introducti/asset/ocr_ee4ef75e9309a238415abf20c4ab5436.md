# 8.8.3.1 Global Parameters

DSS make of three global parameters $(p, q, g)$ that are made available to all the users in the cryptosystem:

+   1. $q$: 160-bit prime number
2. $p$: $512...1024$-bit prime number, such that $q$ divides $\Phi(p)$.
3. $g$: an integer of order $(q \mod p)$. The integer $g$ is determined as follows:
   $A = (h)^{\wp(q)} \mod p$, where $1 < h < \Phi(p)$ such that $g > I$
   B. If $g=1$ then choose another value of $h$ and repeat step iii (a). If $g=1$ then $y$ and $r$ will always be equal to 1.

# 8.8.3.2 Key Generation

A user (say "A") generates its private key and public key as follows:

+   1. Chooses an integer $x$ such that $1 < x < q$
2. Computes $y = g^x \mod p$
3. Now $(p, q, g, x)$ forms the Private Key, and $(p, q, g, y)$ forms the Public Key of "A".

# 8.8.3.3 Signature Algorithm

Given a message $M$ to be signed, user "A" proceeds as follows:

+   1. Computes Hash Function $m = H(M)$ such that $0 \leq m < q$.
2. Selects an integer $k$ such that $1 < k < q$. Since $k < q$ $k$ is relatively prime to $q$. The user does not have to make the extra effort to establish that $k$ and $q$ are co-primes. This is in contrast to the ElGam Signature Scheme, wherein determining $k$ relatively prime to $\Phi(p)$ involves significant overheads.
