## 8.8.1.3 Signature Verification

Figure 8.17 illustrates the Signature verification. The recipient of the signed message verifies the Signature as follows:

- Computes the Hash Value of the received message $M$.

- Decrypts the Sign using the sender's public key $(e, n)$ and extracts the hash value of the message that was computed at the sender end.

$H(M) = (Sign)^n \mod n = ((H(M))^d \mod n$

- Compares the hash value of the message computed at the recipient end with the one computed at the sender end. If both match exactly, the signature is considered to be verified.

## Example 8.1: RSA Signature Scheme

Let $p = 11, q = 7$
Then $n = p \times q = 77$
$\Phi(n) = 10 \times 6 = 60$

Let public key $e = 13$

Private Key $d \equiv e^{-1} \mod \Phi(n) = 13^{-1} \mod 60 = 37$

### 8.8.1.3.1 Signing

Let $m = H(M) = 2$

$Sign = m^d \mod n = 2^{37} \mod 77 = 51$

$2^{10} \mod 77 = 1024 \mod 77 = 23$

$2^{30} \mod 77 = (23)^3 \mod 77 = (67 \times 23) \mod 77$
$= (-10 \times 23) \mod 77 = 1$

$2^{37} \mod 77 = (1 \times 128) \mod 77 = 51$

### 8.8.1.3.2 Signature Verification at the Recipient End

$(Sign) \mod 77 = (51)^{13} \mod 77 = 2 = m$

$(51)^2 \mod 77 = (2601) \mod 77 = 60$

$(51)^4 \mod 77 = (60)^2 \mod 77 = (-17)^2 \mod 77 = 58$

$(51)^3 \mod 77 = (58)^2 \mod 77 = (-19)^2 \mod 77$
$= 361 \mod 77 = 53$

$(51)^{13} \mod 77 = (53 \times 58 \times 51) \mod 77$
$= (-24 \times -19 \times -26) \mod 77$
$= (624 \times -19) \mod 77$
$= (8 \times -19) \mod 77$
$= -152 \mod 77 = 2$

Since $(Sign) \mod 77 = m = H(M)$; the signature is verified.

### 8.8.2.1 Global Parameters

The ElGamal Signature Scheme makes use of two Global Parameters that are made available to all users in the cryptystem:

- $p$: A large prime number
- $g$: a primitive root of $p$

The scheme comprises Key Generation, Signature Algorithm, and Signature Verification Algorithm.

### 8.8.2.2 Key Generation

Each user in the cryptystem will generate a Private Key and a Public Key, as follows:

- Chooses a random integer $x$ such that $1 < x < \Phi(p)$.
- Computes $y = g^x \pmod p$.
- $(p, g, x)$ forms the private key and $(p, g, y)$ forms the public key of the user.
- The user keeps the private key secret and distributes the public key to all other users in the cryptystem.

### 8.8.2.3 Signature Algorithm

Given a message $M$, the sender sends it as follows:

- 1. Computes a hash function $m = H(M)$ such that $0 \le m < p$.
- 2. Selects a random number $k$ such that $1 < k < \Phi(p)$ and $GCD(k, \Phi(p)) = 1$, that is, Integer $k$ must be relatively to $\Phi(p)$ so that $k^{-1} \pmod{\Phi(p)}$ is defined. (It is a time-consuming function to determine $k$ relatively prime to $\Phi(p)$).
- 3. Computes $r = g^k \mod \Phi(p)$.
- 4. Computes $s = k^{-1}(m - rx) \mod \Phi(p)$.
- 5. Now, $(r, s)$ forms the digital signature of the sender, which is appended to the message prior to its transmission.

### 8.8.2.4 Signature Verification Algorithm

Having the public key $(p, g, y)$ of the signer, the recipient verifies the signature $(r, s)$ as follows:

- Computes Hash Function $m = H(M)$.
- Verifies $0 < r < \Phi(p)$; else rejects the signature.
- Computes $v = g^m \mod \Phi(p)$ and $w = y^r \mod \Phi(p)$.
- Signature is accepted if $v = w$; else rejected.

Note: $r$ is reduced mod $\Phi(p)$ and $r$ is one of base values for the computation of $w$, thus $w$ is also to be reduced mod $\Phi(p)$. Since $v$ is compared with $w$, so $v$ is also to be reduced $\Phi(p)$. Thus both $v$ and $w$ are also to be computed mod $\Phi(p)$; not $p$.

Proof of Correctness:
```
$w = (y \times r^s) \mod \Phi(p)$
$y = g^x \mod p$
$r = g^k \mod \Phi(p): w = (g^r) \mod \Phi(p)$
$s = k^{-1}(m - rx): w = (g^{rx}) \mod \Phi(p)$
$w = g^m \mod \Phi(p) = v$
```

Example 8.2 (ElGamal Signature Scheme)
Let $p = 11$ and $g = 2$ be global parameters.

### 8.8.2.5 Determination of Keys

The signer determines its keys as follows:
Let $x = 3$ and $(x, g, p) = (3, 2, 11)$ be the private key of the signer
$y = g^x \pmod p = 2^3 \pmod{11} = 8$: Public key

### 8.8.2.6 Signing of the Message

Let $m = H(M) = 5$
Suppose the signer chooses $k = 3$ (which is relatively prime to $\Phi(p) = 10$)
Then $r = g^k \pmod{\Phi(p)} = 2^3 \pmod{10} = 8$
$s = k^{-1}(m - rx) \pmod{\Phi(p)} = 3^{-1}(5 - 8 \times 3) \pmod{10}$
$s = 7 \times (-19) \pmod{10} = 7$: Digital Signature $(r, s) = (8, 7)$

### 8.8.2.7 Signature Verification

$w = g^m \pmod{\Phi(p)} = 2^5 \pmod{10} = 2$
$w = (y^s) \pmod{\Phi(p)} = (8^7) \pmod{10} = 2$
$v = w = 2$: The Digital Signature stands.

Example 8.3 (ElGamal Signature Scheme)
Let $p = 19, g = 2$
Let private key $x = 3$
Public Key $y = g^x \mod p = 2^3 \mod 19 = 8$

### 8.8.2.8 Signing of Message by the Sender

Let $m = H(M) = 5$
Let $k = 7$
$r = g^k \mod \Phi(p) = 2^7 \mod{18} = 14$
$s = k^{-1}(m - rx) \mod \Phi(p) = 7^{-1}(5 - 8 \times 3) \mod{18}$
$s = 13 \times (-19) \pmod{18} = 5$: So, $(r, s) = (14, 5)$ is transmitted to the intended recipient.

### 8.8.2.9 Verification of Signature by the Intended Recipient

$v = g^m \mod \Phi(p) = 2^5 \mod 18 = 14$
$w = (y^r \times r^s) \mod \Phi(p) = (8^{14} \times 14^5) \mod 18$
$= (64 \times 32) \mod 18 = (10 \times 14) \mod 18 = 14$
$w = w = 14$; Signature stands.

## 8.8.3 Digital Signature Algorithm and Technology (NIST)

The National Institute of Standards and Technology (NIST) has published a Federal Information Processing Standard (FIPS 186), known as the Digital Signature Standard (DSS). It makes use of the Secure Hash Algorithm (SHA) and incorporates a Digital Signature Algorithm (DSA). The DSA is based on the difficulty of computing Discrete Logarithms on the scheme originally presented by ElGamal. The DSS approach is an improvement of the original scheme proposed by ElGamal and Schnorr (explained previously). For its security, it relies on the difficulty of computing discrete logarithms.

### 8.8.3.1 Global Parameters

DSS make of three global parameters $(p, q, g)$ that are made available to all users in the cryptosystem:

- 1. $q$: 160-bit prime number
2. $p$: $512...1024$-bit prime number, such that $q$ divides $\Phi(p)$.
3. $g$: an integer of order $q$. The integer $g$ is determined as follows:
   $A = (h)^{q} \mod p$, where $1 < h < \Phi(p)$ such that $g > 1$
   B. If $g=1$ then choose another value of $h$ and repeat step (a). If $g=1$ then $y$ and $r$ will always be equal to 1.

### 8.8.3.2 Key Generation

A user (say "A") generates its private key and public key as follows:

- 1. Chooses an integer $x$ such that $1 < x < q$
2. Computes $y = g^x \mod p$
3. Now $(p, q, g, x)$ forms the Private Key, and $(p, q, g, y)$ forms the Public Key of "A".

### 8.8.3.3 Signature Algorithm

Given a message $M$ to be signed, user "A" proceeds as follows:

- 1. Computes Hash Function $m = H(M)$ such that $0 \le m < q$.
- 2. Selects an integer $k$ such that $1 < k < q$. Since $k < q$ $k$ is relatively prime to $q$. The user does not have to make the extra effort to establish that $k$ and $q$ are co-primes. This is in contrast to the ElGamal Signature Scheme, wherein determining $k$ relatively prime to $\Phi(p)$ involves significant overheads.
