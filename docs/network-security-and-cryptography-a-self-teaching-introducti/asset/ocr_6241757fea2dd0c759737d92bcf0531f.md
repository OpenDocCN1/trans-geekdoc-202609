Suppose the messages are 1024 bits long and the MACs are 64 bits long, the message space will have $2^{1024}$ distinct messages and the MAC space will have $2^{64}$ distinct MAC Codes. On the average, $2^{1024}/2^{64} = 2^{960}$ long, then if the secret key is 256 bits long, there will be $2^{256}$ different mappings from the message space to the MAC space.

# 8.3.5 Use of MAC for Message Authentication

# 1. Message Authentication only

![](bbox=[0.198, 0.488, 0.842, 0.678])

**FIGURE 8.5** A schematic diagram of the use of MAC for Message Authentication.

+   * If the MAC value generated at the recipient matches exactly with the hash value received from the sender end, the message is considered to be authenticated.
* Also, it ensures Data Integrity, no adversary could have modified the message $M$, since the adversary cannot generate another MAC-without knowledge of key $K$.
* But it does not assure source non-repudiation since key $K$ is also known to the recipient.
