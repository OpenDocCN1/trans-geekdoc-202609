
## 3. Public Key Encryption: Arbitrator cannot see the Message

- A. X → A: $ID_X || E_{Kuy}[E_{Kin}[M]] || ID_X || E_{Kkr}[H(E_{Kuy}[M])]]$
- B. A → Y: $E_{Kuy}[ID_X || E_{Kin}[M]] || ID_{Y} || E_{Kkr}[H(E_{Kuy}[M])]] || T$

A can decrypt the outer encryption using the Public Key of X, that is $KU_x$, and verify that the message has been received from X only. But the arbitrator cannot read the message M. Only Y can decrypt fully using Public Key $KU_y$, of A, its own private $KR_y$, and the public key $KU_y$ of X.

This scheme has a distinct advantage over earlier schemes, that there is no shared secret used. So, it protects the alliances from fraud. Second, no correct-dated message can be sent even if $KR$ is compromised, Finally, the message from X to Y is kept secret from everyone else, including from A.

## 8.5 AUTHENTICATION PROTOCOLS

### 8.5.1 Mutual Authentication

These protocols enable the communicating parties to be mutually satisfied about each other's identity and to exchange session keys. The messages pertaining to the exchange of session keys have the prior existence of shared secret keys or public/private keys specifically meant for this purpose. The second issue is to prevent message replays. The techniques used to counter the message replays are:

- 1. Time-Stamps: This approach requires synchronization of clocks among the communicating parties. This scheme must allow a sufficiently large window of time to accommodate network delays; at the same time the window should be sufficiently small to prevent attacks.

- 2. Nonce Value: Party A, expecting a fresh message from B, sends Ba Nonce (random integer value) and requires that the subsequent message from B contains the correct Nonce value N. This scheme is unsuitable for connectionless communication, since it requires a prior “handshake” of the communication parties, which goes against the basic principle of the connectionless approach.

### 8.5.2 Symmetric Encryption Approaches

This approach involves the use of a trusted Key Distribution Center (KDC). Each party in the network shares a secret key (called a Master Key) with the KDC. The KDC is responsible for issuing one-time Session Keys to the network. A Session Key is meant for a single session use only. Supposing party $A$ wishes to have a session with party $B$ as depicted here. While $K$ is a secret key shared between the KDC and $A$ and $B$, and $K_s$ is the secret key shared between the KDC and $B$, $N_i, N_1$ and $N_2$ are Nonce values used for preventing Replay Attacks. $K_s$ is the session key issued for one session only.

### 8.5.3 Needham Schroeder Protocol

1. $A \rightarrow KDC: ID_A || ID_B || N_1$
2. $KDC \rightarrow A: E_{K_A}[K_s || ID_B || N_1 || E_{K_B}[K_s || ID_A]]$
3. $A \rightarrow B: E_{K_B}[K_s || ID_A]$
4. $B \rightarrow A: E_{K_A}[N_2]$
5. $A \rightarrow B: E_{K_s}[f[N_2]]$

The protocol has a drawback. If an opponent $(X)$ is able to compromise an old session key, then it can use Step 3, impersonate $A$, and trick $B$ into using the old session key. Now, if $X$ can intercept the Step 4 message, it can send the response of Step 5. Now, $X$ can send fraudulent messages to $B$, who in turn will consider the messages as coming from $A$. Denning proposed the inclusion of a time stamp in Step 2 and Step 3 to remove the weakness of the Needham Schroeder Protocol.

### 8.5.4 Denning Protocol

1. $A \rightarrow KDC: ID_A || ID_B || N_1$
2. $KDC \rightarrow A: E_{K_A}[K || ID_B || T || E_{K_B}[K || ID_A || T]]$
3. $A \rightarrow B: E_{K_B}[K || ID_A || T]$
4. $B \rightarrow A: E_{K_A}[N_1]$
5. $A \rightarrow B: E_{K_s}[f[N_1]]$

The Denning Protocol ensures a higher degree of security as compared to the Needham Schroeder Protocol, but it relies on Time-Stamps, the efficiency of which depends on accurate synchronization of clocks. However, in case of the failure of the synchronization of clocks, the scheme would provide ample scope for replay attacks.

Another approach avoids use of time-stamps and instead prevents replay attacks, is depicted as follows:

### 8.5.5 NEUM Protocol

- 1. A → KDC: $ID_a \parallel N_s$
- 2. B → KDC: $ID_b \parallel N_b \parallel E_{kd} [ID_a \parallel T_b]$
- 3. KDC → A: $E_{kb} [ID_b \parallel N_a] \parallel E_{kd} [ID_a \parallel T_b] \parallel N_b$
- 4. A → B: $E_{kd} [ID_a \parallel T_b] \parallel E_{kb}$

where $T_b$ is the time-limit for session key $K_s$ is valid. Let us follow this protocol step-by-step:

1. The Nonce $N_s$, sent by A to B, is returned to A with session key $K_s$ at Step 2, thus assuring of the timeliness of the session key $K_s$.
2. The Nonce $N_b$, sent by B to the KDC is returned back to B with session key $K_b$ at Step 3, thus assuring B of the timeliness of the session key $K_s$.
3. B instructs the KDC about the validation of the session key to be issued, preventing replay of old keys.
4. In Step 4, A encrypts the Nonce $N_b$ by the session key $K_s$, which authenticates at B that the message has been sent by A and is not a replay.

This protocol provides secure means for issue of a session key. This key can be used between A and B for multiple sessions, but within the time-limit $T_b$, thus avoiding overhead for issue of a fresh session key. To avoid attacks, $T_b$ should not have too high value. Since the time is specified with respect to B's clock, its validity is with respect to B's clock. For repeat session, A and B will proceed as follows:

1. $A \rightarrow B: E_{ab}[ID_A \parallel K \parallel T_b] \parallel N_a$
2. $B \rightarrow A: N_b \parallel E_{ab}[N_a]$
3. $A \rightarrow B: E_{ab}[N_b]$

### 8.5.6 Public-Key Encryption Approaches

A protocol using a time-stamp is depicted as follows:

1. $A \rightarrow AS: ID_A \parallel ID_B$
2. $AS \rightarrow A: E_{as}[ID_A \parallel KU_A \parallel T] \parallel E_{bs}[ID_B \parallel KU_B \parallel T]$
3. $A \rightarrow B: E_{ab}[ID_A \parallel KU_A \parallel T] \parallel E_{ab}[ID_B \parallel KU_B \parallel T] \parallel E_{ab}[E_{Kas}}[K_s \parallel K_y \parallel T]]$

Here, the Authentication Server only provides the Public Keys; it does not issue Session Keys. The Session Key is determined by A. Thus, AS cannot compromise the session keys. The main limitation of this algorithm is that it depends on the synchronization of clocks. The following algorithm is free of this:

1. $A \rightarrow KDC: ID_A \parallel ID_B$
2. $KDC \rightarrow A: E_{ath}[ID_B \parallel KU_A]$
3. $A \rightarrow B: E_{ub}[N_a \parallel ID_A]$
4. $B \rightarrow KDC: ID_B \parallel ID_A \parallel E_{ub}[N_a]$
5. $KDC \rightarrow B: E_{bth}[ID_A \parallel KU_A] \parallel E_{bth}[N_a \parallel K_s \parallel ID_A]$
6. $B \rightarrow A: E_{auth}[N_a \parallel K_s \parallel ID_B] \parallel N_b$
7. $A \rightarrow B: E_{ab}[N_b]$

### 8.5.7 One-Way Authentication

The protocol of one-way authentication is two-fold:

- 1. For an e-mail type of application, the message is forwarded to the intended receiver’s electronic mailbox. Route the message is handled by a store-and-forward protocol such as Simple Mail Transfer Protocol (SMTP) or X.400. However, it is often desirable that the mail protocol should not have access to the plaintext of the message. Accordingly, the e-mail message must be encrypted such that only the intended receiver has the decryption key.
- 2. The recipient should be able to authenticate the identity of the alleged sender.

### 8.5.8 Symmetric Encryption Approach

1. $A \rightarrow KDC: ID_A || ID_B || N_1$
2. $KDC \rightarrow A: E_{K_s}[ID_B || N_1] || E_{K_b}[K_s || ID_A]$
3. $A \rightarrow B: E_{K_b}[K || ID_B]] || E_{K_s}[M]$

The approach ensures that only the intended recipient will be able to read the message M. It also authenticates to B that the sender is A. However, it provides no protection against replays.
