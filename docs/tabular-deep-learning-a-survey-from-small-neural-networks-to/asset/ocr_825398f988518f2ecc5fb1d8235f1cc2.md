Federated Learning. Federated Learning (FL) is an ML approach that allows multiple devices or organizations to train a shared model collaboratively without sharing their data [1]. By operating locally, the model is trained across various organizations, providing privacy and reducing costs. FL makes it possible to collaboratively train a neural network without the need to collect data in a central server. In FL, a model is trained locally, and the global model aggregates the information and returns an updated version to the various users. All parties benefit from the model and information from other organizations without data sharing. This is advantageous in domains where privacy is important, and sharing is complicated by various factors or other. In FL, each model is trained locally, and each sends only model updates (weights or gradients) to a central server, which then collects and aggregates them into a global model that is sent back to participants. This process can be repeated several times, while the global model continues to improve. Despite being a promising idea, there remain some challenges, such as the heterogeneity of data. Each client may have a different distribution, with different resources at their disposal, limiting the possible model to share. FL then must optimize for the potential heterogeneity of data and participants by finding an aggregation function that is robust. The simplest technique is Federated Averaging (FedAvg), which averages model parameters across clients, but more sophisticated variants also exist. Federated learning has some work exploring the possibility of using on tabular data. Lindskog [210] shows FL with TabNet, which is algorithm compatible. FedGAN [408] is a framework to use GAN in FL, which features a privacy-preserving multi-source encoding for model initialization and a de-identification mechanism for local models. TabDiff [300] combines FL and generative models to generate tabular data. Most work focuses on federated learning, although data synthesis has been extensively thought of for privacy. TabFSI [346] aims to adapt tabular data through segmentation to make the model more robust and compatible with distributed settings. Tabula [72], on the other hand, is designed for predictive models with genomic data, thus preserving privacy in clinical applications. Implementations benchmark between decision trees and deep learning for FL. In their benchmark, it seems that federated XGBoost gets the best results. AutoML. Automated Machine Learning (AutoML) is a new paradigm in ML pipelines that automate feature engineering and model selection and hyperparameter tuning. AutoML allows to handle structured datasets (spreadsheets, databases, CSV files) as input, which produce a model, and results to the user. AutoML automatically searches for data imputation, categorical encoding, feature selection, identification of outliers), feature process (feature selection, creation and transformation), model selection (choosing a model for a particular task), model optimization (finding the best hyperparameters) and visualizations. Specifically for users who are unfamiliar with data science, AutoML helps save time, hours of effort, and find the best models and hyperparameters. However, AutoML still lacks customization, a few generic models are implemented, full process control does not work well for complex datasets and tasks. Not least, AutoML for tabular data requires specialized field, as the data has particular complexity, and social models can also go wrong (Tab. 14). AutoGAN is an example of an AutoML library that handles variety of models. One of the best features is that it allows multi-layer stacking/ensemble of many models. AutoGAN handles the entire process, starting from feature engineering to training. H2O AutoML trains different types of models (e.g., gradient-based methods, random forests, GLMs, with neural networks) and searches analytically to identify the top performing models. H2O AutoML is designed to work with large datasets and to enable distributed and multi-threading support. PyCat is another low-code library that seeks to simplify the model training process, and is compatible with other libraries (it can be used on top of other libraries). FLAM (Fast Lightweight AutoML) introduces an adaptive strategy to optimize the process of choosing hyperparameters.
