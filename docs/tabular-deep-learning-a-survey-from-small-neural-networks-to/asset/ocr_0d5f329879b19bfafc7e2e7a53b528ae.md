Graph encoding. Tabular data can be encoded as graphs, where different methods transform tabular data into graphs. Once a graph is obtained, Graph Neural Networks (GNNs) can be used. One of the advantages of this approach is the flexibility; it is possible to design different types of graphs to represent the data (graphs, bi-partite, hyper-graph, multi-graph, and so on). This reduces feature engineering by being able to select the type of best feature from data and task. GNNs handle the relationship between features without the need to be explicitly coded (e.g., building a feature that is part of two features). For example, TabGNN [66] extends GNNs to learn similarity with the correlation and the interaction between features. In addition, these approaches work well when there are several columns linked together, as in relational databases. For example, in this work [66] uses a GNN to contain the data in relational databases to reduce feature engineering with good performance. There are similar approaches that use similarity measures (e.g., cosine similarity, Jacobi index, correlation, or Euclidean distance) to refer to edges. Alternatively, K-Nearest Neighbors (KNN) [81] are used, where we connect each example (node) with its k-nearest neighbors in feature space. Another interesting approach is to connect data into a graph; this study [71] exploits metadata to connect to nodes and leverage prior knowledge. GNNs also have other interest-

ing, as the fact that they can be used for classified nodes in semi-supervised learning, propagate the information of similar examples (message passing), and learn embedding where similar examples are near. Similar approaches have been used for applications such as anomaly detection, Click Through Rate (CTR) prediction, missing data imputation, medical prediction, and more. CARTE (Attention-based Representation of Tabular) [77] uses tabular transformation to solve two types of schemes data change (variations in columns, orders, or naming) and entity matching (terminologies or representations). CARTE represents each table as a graph where nodes connect entries to the respective column names and neighboring entries within the same row. Both table and column names are embedded similarly and captured within both rows and columns. After, the system uses a graph-attention network (GAT) to generalize the entities and relationships. The model is pre-trained on a large knowledge base to align entities, thus being able to learn a wide range of problems. The model, once pre-trained, CARTE simplifies the integration of different datasets, with a wide array of representations and relations, improves performance, and can be used for small datasets. On the other hand, using G makes it interpretable, has considerable computational cost, and is not easy. HYREL uses a tabular model to capture the structural properties of tabular data, such as permutation invariance and hierarchical structures.
