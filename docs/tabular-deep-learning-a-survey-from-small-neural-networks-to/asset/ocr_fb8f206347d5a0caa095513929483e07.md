# 3.11. Label noise impact

In real world, labels are rarely perfect [174, 24]. Errors can be generated by human annotation, automated labeling pipelines, proxy outcomes, or ambiguous definitions of targets. This problem is amplified in tabular data as labels derived from operational decisions (e.g. loan defaults, fraud flags, customer) are not from ground truth. Even these labels can be approximate or imperfect. For example, billing codes can be used as proxies for medical diagnosis, or user satisfaction from click, or other heuristics used to automate the labeling process. Label noise can determine the performance of deep learning, as distorts true discovery (with reduced generalization), limits its accuracy, and makes learning patterns more complex. Deep models, especially those with large number of parameters can store noisy labels (especially in the absence of small regularization) in labels [315]. In tabular data, this phenomenon can be amplified when there is a limited sample size. In instance, many datasets may contain ambiguous or subjective labels, especially in business, or medical domains. Also is the redundancy present in text or images (the semantic context or pixels) that helps model interpret correct labels from neighbors.

For Grinzain [117], another reason is that non-feature networks are less robust to noise (which is shown by the figures). Including non-feature features decreases the gain between neural networks and tree-based models. Also, because decision-tree algorithms use binary splits on a single feature, they can find an exact split for the split while ignoring other features. Using information gain and entropy is another trick that makes them more robust to noninformative features.

There are other factors. Neural networks also risk imputing of missing values, whereas tree-based models handle innate of missing values. Deep learning is sensitive to unbiased datasets, with the risk of predicting only the majority class. # 5. Growing interest in deep learning for tabular data

Although some reason shows an alleged survey of tree-based algorithms [375, 117] there is interest in using neural networks with tabular data. However the performance of deep learning increases with the size of the data, and more data are available. There is indeed power-law for deep-learning [136] and scaling has been highly beneficial for other types of data.

Deep learning requires the need for feature-engineering and can to generate data. Neural networks conduct feature engineering and selection by intervening in parameters and learning a data transformation. This abstraction process involves layers gradually more patterns along the depth of the network [412]. On the other hand, it has been argued that feature engineering is critical for small datasets where the model does not have enough examples to learn an efficient representation of the data.
