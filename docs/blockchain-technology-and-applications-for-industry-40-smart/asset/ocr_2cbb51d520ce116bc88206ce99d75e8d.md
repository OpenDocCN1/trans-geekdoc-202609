# 2.3.2.1 Transaction throughput and latency

Transaction throughput is the number of committed transactions in a given time interval. However, not every unit of the work process counts as a transaction, as in this case. Only transactions that result in a state change should be considered. Examples of such transactions are transferring funds from one account to another in Bitcoin (BTC) or invoking a smart contract via the consensus in Ethereum. The smart contract reads are not executed with state-changing transactions, so they should be excluded from this metric. This is also true for the pass-through transactions, where the same transaction is passed among various smart contracts. It should be counted as one. Invalid transactions rejected by the validating node and, thus do not qualify for inclusion in the ledger be excluded. This might seem obvious, but there are network performance reports where it is impossible to determine what actions were counted and not.

The overall transaction latency depends on times needed for:

+   1. transaction generation, that is composing the data structure, calculating hashes
2. submission through an access node
3. propagation over the P2P network and validation of the transaction in the miner
4. block creation and the consensus in the network
5. extra time to reach a sufficient level of finality.

The first two factors reflect the off-chain factors, as the resources of the end device that is generating a transaction. The remaining factors reflect the network performance.

The theoretical limit for transaction throughput can be calculated from the average block time and the average number of transactions in a block. Block time distributions depend on the consensus algorithm. In PoW, the block time is a consequence of the current block difficulty and the overall hashing power of the network. The difficulty is automatically adapted to the changes in hashing power, the jitter in blocks is always present in PoW. The Proof of Authority (PoA), on the other hand, can provide very consistent block times because the target block times in the PoA network genesis. Blocks blockchain carry a limited number of transactions. In the BTC network, the maximum block size is 1 MB. With an average size of 500 B, the maximum number of transactions is about 2,000 per block. A new block is produced about every 10 minutes. This results in an average BTC network throughput of 3ps. In Ethereum, the sum of gas (Section 2.3.2.3 for gas and transaction costs) of all transactions in a block has to be less than the maximum gas (per block). In the Ethereum mainnet, with the maximum block size of 10,000,000 and minimum gas per transaction of 21,000 (or average size) can be up to 476 (138 for average size) transactions in a block. A new block is generated, on average, in 13 s. The maximum transaction throughput of the Ethereum mainnet is about 37 tps (10 tps for average size).
