A node that has created an event also signs it digitally. When the node gossips to another node, the signature is set together with the gossiped event(s). The whole hashgraph structure is firmly bonded and protected, that is, cryptographically immutable, since each event contains hashes of its parents – that is, each received sync message and creating a new event, a node can pass through the hashgraph from the starting (or from some later) event/s and calculate by itself, the hashes of the events below the other parent, as well as the other parent's hash. In that way, the node can check the correctness of the other-parent event (and the events below) and validate it, which it does. After sync is received, only validated events are contained in the node's code of the hashgraph. Furthermore, node in the hashgraph's P2P network communicate to each other using TLS encryption protocol (on top of TCP), which protects the exchange of sync messages.

Figure 1.7 shows an example of a hashgraph (with five nodes/participants) of the first few events, where it can be seen who gossiped to whom and in order. For example, participant (node) C first gossips (sends sync) event C1 to participant A, upon the receipt of C1, creates event A2. Node saves event C1 and A2 in its file system and the transactions that can be contained in them. Event A2 payload contains only transactions (if any collected in the meantime) with the timestamp of the event's creation and the hashes of its parents A1 and C1 as overhead. Then, participant E gossips event E1 to D, after which D creates event D2. In the next step, A synchronizes with B, so A gossips everything he knows (events A1 and C1) to B, who creates event B2.
