Having finished this (easier) first step, that is, the confirmation of A's solvency, the second and more difficult step follows. There, miners compete with each other: the winner is the first one to embed the new transaction; that is, to append it to the end of the blockchain.

Only one particular transaction has been mentioned so far (between person A and person B) as the single one, which should be validated and added to the blockchain. In reality, a block that is to be appended to the end of the BTC blockchain contains, on average, 1,500 transactions accumulated around the world in ten minutes. For, different types of blockchain (other than BTC blockchain), the frequency of appearance of new blocks is different, so there are blockchains where one block of transactions appears every five minutes.

The transaction data of each block (of the BTC blockchain) consists of the latest valid transactions, whereby the size of the block is limited to 1 MB (although the use of Segregated Witness protocol upgrade [4] from August 2017, block limit has been extended to 4 MB, for practical purposes). The participants' identities in a transaction are encrypted prior, using their private keys. All transactions in a block are hashed through a匣 scheme known as a hash tree or Merkle tree [5]. The 256-bit result of hashing, that is, the root of the Merkle tree, is put into the block header as well.

The links between blocks make a blockchain practically unbreakable, as each block contains the hash value of the previous block's header. The catch is in the 32-bit block header field nonce which all the miners are trying to guess every ten minutes, to append a new block to the blockchain (and, consequently, to get a reward for the invested work, if successful). Once a block is put to the blockchain, all the transactions from that block are considered verified, and miners immediately go on finding new nonce for the next block of transactions. The first miner who verifies these transactions by guessing the right value of nonce (in the previous block) gets a reward. With a BTC blockchain, the reward consists of two parts - the first is a transaction fee, paid in BTC by money-transactions from the justified block, and the second part is a certain amount of new BTC generated from nothing.

What is the right value of nonce? There is no such value, that is, no tangible value has seen in advance. More specifically, the algorithm is designed, so that the goal to be achieved is adjust the hash value of the last verified block header in blockchain be small enough, to be less than or equal to a given number (target). This practically means that this hash value, which is to be put in the header of the next (i.e., of the newest block), begins with zeros. The adjustment of the hash value is performed through an iterative process of incrementing the value of nonce and computing a new hash (of the complete block header) for each new nonce. The process stops when the currently computed hash satisfies the given condition.
