In the graph representation, for example, when a node A receives a gossip (sync) from node B, that gossip event is shown on the graph as a circle (vertex) in column A, with two lines (edges) going down to the preceding gossip events nodes A and B (Fig. 1.7). The hashgraph diagram (such as the one in Fig. 1.7c) is used only for its representation and explanation, there is no actual graph stored in memory anymore.

For sharing of transactions, each node runs two endless parallel programs in its software. It asynchronously receives and collects transactions from its clients (wallets) and the sync messages from other nodes (thereby creating events) in the first loop. In the second loop, the node occasionally sends syncs to its neighbor nodes. This process of gossip spreading, that is, sharing the existing and the new events, starts when each node collects every piece of information (on all transactions) created or received at the hashgraph, that is, when a consensus about all transactions and the timeline of their occurrences is reached. However, as new transactions appear all, the process never stops, since there is always something new to gossip about. At the same time, nodes are continually reaching the consensus on the previous events and fact. Practically, at any moment, every node can see the same picture (ie., the history) of all events as the other nodes are seeing. In contrast, the differences (between nodes') views on gossip history are only related to the latest events (which may be only a few seconds, maximally).

Knowing that sync messages include information not only on the events' transactions but on the events per se, as well, it can be said that hashgraph represents gossip as as gossip. This is important because, from the history of gossip, a node can conclude what information other nodes know and which they do not.

Let us consider, that, hashgraph is a hybrid structure – the combination of a hash and a graph, which keeps records about who gossiped to whom and in what order. Hashgraph does not require any PoW (so there is no mining), since reaching consensus relies on a procedure as virtual voting. Unlike blockchain, where transaction data is stored in blocks, hashgraph stores data in events, so an event can be represented as a container of transactions, although an event may be empty. In the hashgraph, an event and all the transactions in it immediately become part of a permanent record, that is, the copy of a ledger on every node. This is performed as soon as the node gossips that and all other nodes hear about it. Also, in only a few seconds, every node will know, with 100% certainty, about the event's position in the hashgraph's history, and every node will know that every other node knows this (which is of even greater importance).
