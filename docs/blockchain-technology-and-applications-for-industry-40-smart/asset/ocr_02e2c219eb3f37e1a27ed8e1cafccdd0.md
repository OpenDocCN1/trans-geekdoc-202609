This special transaction is sent to an empty receiver address, with the EVM bytecode as data. The transaction sender is a valid Ethereum account. This account becomes the owner of the smart contract. Once the smart contract deployment transaction is added to the chain by validating nodes in the BC, the smart contract obtains a unique smart contract address. Now, transactions can be sent to the address of the newly deployed smart contract. A smart contract has its balance, code, and some persistent storage to execute its operations. We can now check for possible compilation flaws at the bytecode level or ensure that the deployed bytecode logic matches the source code.

In the Ethereum BC, the ABI stipulates the de facto mechanism for encoding/decoding data into/out of a smart contract, that is, how call functions in a contract or get data back. Slightly different approaches are taken in other distributed ledger architectures, for example, Hyperledger [32]. Other smart contracts call smart methods to read the smart contract parameters or send BC transactions to the smart contract to change its state. A smart contract can emit events filtered by the DL network and can be passed to the external applications by any node. Different smart contracts in the same network reside within the same virtual machine. Their communication is straightforward and limited only by the access rights encoded in a smart contract. Off-chain applications need to access a DL account and an API to communicate with the DL node. For the Ethereum off-chain applications, several frontend JavaScript APIs are provided, including frontend libraries. One example is the Web3js – Ethereum JavaScript API a collection of libraries that allows interacting with a local or remote Ethereum node using HTTP, IPC, or WebSocket.

It is common for the traditional Web applications to access various resources on the Internet, using various protocols, for example, HTTP, HTTPS, WebSockets, WebRTC, and RPC. On the other hand, the smart contract execution environments limit the scope of the smart contract execution to the DL network. A smart contract can call only smart contracts in the network but cannot access resources out of the DL.

The smart contract methods can be accessed in two ways by the DL network participants. Suppose an off-chain application or another smart contract requires, for a simple example read of a smart contract parameter. In this case, this is done with a local invocation (occurring only in the local DL node) of the smart contract method.
