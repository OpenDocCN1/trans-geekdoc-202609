To disperse the administration (governance) of the system so that there is no single entity having over the system, we need a different approach, that is, decentralization of control. Such a system has to be distributed as many instances are building the system. Unlike the decentralized and centralized database, each instance is controlled by a different entity in a decentralized system. These can be, for example, users who install a DL network and run blockchain nodes or consortium partners who agree to run a DL network and, therefore, all set up their node instances. Decentralization in DLs is, thus, more organizational in nature and not technical. The underlying technology has to a distributed system, which is a prerequisite for its decentralized governance. The actions in the system cannot be based on an arbitrary decision of a single proprietor but on a mutual consensus. The same consensus mechanism is implemented in every node instance. These mechanisms ensure that all the actions can be conducted only in the pre-agreed way, even if some of the system participants act maliciously.

A DL is distributed, by nature. If, in addition, we implement it in a way like decentralized trusted systems, where we need to trust the system proprietor (e.g., a bank, holding a database with client account and balance information), in decentralized trusted systems, there is no central entity we would have to trust. The trust is assured by DL protocols, which are commonly open source and, hence, available for verification to anyone.

In distributed systems with centralized governance, no decentralized trust can be assured either. Only those systems, which are distributed and decentralized, can provide decentralized trust.
