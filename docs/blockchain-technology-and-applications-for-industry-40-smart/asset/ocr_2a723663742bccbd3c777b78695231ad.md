To be specific, the hashgraph's honest members will be able to keep running given application (e.g., cryptocurrency) correctly, even when the number of fraudulent members/nodes is very close to 1/3 of the whole population. The BFT property of a hashgraph is a direct consequence of the implemented rules (i.e., of the Byzantine protocols) within virtual voting. The strongly seeing and the supermajorities of nodes and witnesses are required.

The second advantage is that all voting processes and getting consensus are stamped virtually and independently by each node. Every member/node does everything on its own, as if it were alone on a desert island and without the need for any communication with anyone (except the regular gossip). Besides a reduced demand for Internet bandwidth, the benefit of this is an increased speed of realization and verification of transactions. To be specific, an alternative consensus algorithm that would obtain BFT property certainly should be running separate Byzantine protocols, including a large amount of communication between all members. Thus, if the aim is to determine the order of events in time, each separate communication between two nodes would contain either Yes/No questions (in both directions), where each question would have the form, "did X come before Y? such an algorithm would be very slow due to the delays in communication between nodes over the Internet, and perhaps due to its complexity.

Instead of mentioned so far, by applying the virtual voting algorithm, the Byzantine agreement protocol is run only for witnesses, whereas famous witnesses are chosen as a result of a small number of witnesses, such as: "Is this witness famous?" In this way, the process of time ordering (through performing some sorting algorithm) is as obvious. Already explained, the time order of events is (automatically) determined as soon as their consensus timestamps are found, as the median values of the candidate timestampsed by the nodes that created the famous witnesses.
