
## 2.7.1.5 IOTA ecosystem

IOTA is an open-source DLT developed by the IOTA Foundation. The Foundation has announced an ambitious roadmap towards the IOTA 2.0. It will be a challenge to keep with it. The roadmap envisages a new DLT protocol suite, new wallet, and new library suite is a major shift compared to 1.0. Version 2.0 should remove the need for (centralized) Coordinator nodes, also smart contract protocol, secure messaging and disposable self-identities. IOTA plans to standardize the IOTA protocols and has announced collaboration with IEEE and OMG.

In the current version 1.0 of the IOTA network, the transactions are referenced when transactions reference them. However, they only become truly valid when the network Coordinator, a special node operated by the IOTA Foundation, confirms them. Due to IOTA's unique ledger style, it has some unique properties. Theoretically, the transaction throughput increases, and the latency decreases as the number of nodes and users increases. The IOTA ledger is distributed, but the network is not decentralized by the consensus, requiring Coordinator nodes.

There is a public network and a public test network. IOTA uses a public cryptocurrency, MIOTA. Transactions are essentially free, but the transaction must submit proof of work.

For support contracts is the alpha stage for v2.0 but is not available in current v1.0, which means IOTA can only store and transmit data not process it. This makes it, for the moment, not usable for building DApps. Therefore, IOTA has not attracted a larger developer community. Developers would appreciate systematic documentation and clear guidance on how to participate in the IOTA network. Version 2.0 promises relevant improvements but takes immense effort to be finalized and brought to production grade.

## 2.7.2 Deploying and accessing blockchain networks

DApps require an underlying DLT network (see Sections 2.2 and 2.3) for their operation. This can be a new, dedicated private or consortium network that we customize to our needs and construct from scratch. Nevertheless, it could also be an existing prominent public network, where we would like to attach a cache of additional nodes to participate in blockchain network operations.

A scalable self-proven blockchain network is complex to set up and hard to manage. Each node operator needs to manually provision hardware, software, create and manage certificates for access control, and configure networking components. This can be done as very basic editing of node files, for example, the genesis file. Some manual tasks can be done instead with a CLI wizard, for example, Puppeth, which aids in creating a new Ethereum network. Lately, tools like Hyperledger Cello – a blockchain provision and operation system – help use and manage blockchains efficiently. It supports various infrastructures like bare-metal, virtual-machine platforms, and container cloud (e.g., Swarm, Kubernetes).

Once the blockchain is running, one needs to monitor the infrastructure and adapt to change, continuously. From self-hosted nodes, Blockchain-as-a-Service (BaaS) providers facilitate efficient blockchain node deployment and management. Many of the key players in cloud service provisioning, for example, Amazon, Microsoft, Alibaba, and IBM, provide some of BaaS.

The off-chain DApps part needs to access the DL node's APIs (Section 2.2 and 2.4). These APIs can be exposed in the nodes under our supervision or obtained from a dedicated service provider, for example, Inura. The latter ensures reliable infrastructure connecting a user to the Ethereum public network. This is essential for the instant operation of the machine and user interfaces in the DApps. Relying on hosted APIs disengages the application developers completely from the DL network provisioning.

The content of a public ledger can always be obtained through network nodes. However, this might not be the most efficient structure for queries needed in the advanced DL data analyses. Therefore, public datasets of historical data from various DL networks placed in big data platforms make the analysis more efficient.

### 2.7.2.1 Blockchain-as-a-service

BaaS provides blockchain services in the cloud or edge computing environments, such as node and network deployment, system monitoring, and smart contracts analysis and testing. BaaS implementation outsources a major technical and operational overhead for deploying and accessing the BC network to the cloud service provider. BaaS providers offer adjusted pricing and instance types optimized to fit different blockchain use cases. Based on these services, the developers can focus on the business code to explore how to apply the blockchain technology properly to their business scenarios, without the having to maintain and monitor the blockchain platform [45]. BaaS is improving the productivity of DApp development and initiates a broad adoption of blockchain technologies.

### 2.7.2.1 Amazon Managed Blockchain

Amazon Managed Blockchain⁴⁷ is a fully managed service that lets us create and manage private or consortium networks using popular-source frameworks Hyperledger Fabric and Ethereum. The service scales up to meet the demands of applications. Managed Blockchain also monitors the network and automatically scales. There are prebuilt templates for easy to join public networks.

### 2.7.2.2 IBM blockchain platform

IBM is a founding member of the Linux Foundation Hyperledger Project, so Platform⁴⁸ is a commercial distribution of Hyperledger Fabric and comes with SLAs and full-time support. Enterprises can connect to nodes in any environment (on-premises, public, or hybrid clouds) and deploy only the components they need (Peer, Ordering Service, Certificate Authority) and manage all network components through a single console. There is no vendor lock-in, so companies maintain complete control of identities. IBM Platform is working with the Hedera Consensus Service to increase interoperability, the latter providing public consensus while a private blockchain network is based on Hyperledger Fabric. The leading use cases based on the IBM platform are banking and financial markets, supply chain, health care, insurance, media, advertising, and government.

### 2.7.1.3 Microsoft Azure BaaS

Microsoft Azure BaaS⁵⁰ lets us create and configure consortium blockchain infrastructure and rapidly deploy managed blockchain networks. It facilitates the Quorum ledger using the Istanbul Byzantine Tolerance (IBFT) consensus mechanism and will eventually support multiple blockchain platforms like Ethereum, Hyperledger Fabric, Corda, and Chaincode.

The service is comprised of three sets of products. Azure Blockchain Workbench is the foundation for building, governing and deploying fully managed blockchain networks and applications at scale. Azure Blockchain Service is a starting point for easy prototyping and simplified development with prebuilt networks and infrastructure. Azure Blockchain Development Kit is a comprehensive GitHub repository of developer blockchain content, including code samples and accelerators. Modular controls built in for easy member onboarding, consortia management and codeless provisioning, and simplified policy enforcement. Blockchain data manager enables flexible, reliable, and scalable data streaming and application integration. In this way, users can monitor their smart contracts, react to transactions and events, and stream on-chain data to off-chain data stores to boost the desired end-to-end solutions.
