Suppose we want to assure that a block is verified every 10 min. In case, Difficulty should be tuned relative to the computational power of the entire Bitcoin network, so that it can make a target number of calculations per second needed for achieving of the goal that average time for finding a hash below or target_value is ten minutes. This number of hash operations per second (known as hash or hash rate) can be derived and calculated from Difficulty as follows:

$Hash rate = \frac{N(Difficulty)}}{10\text{min}}$

where $N(Difficulty)$ is the expected number of hash attempts (for a given difficulty) before finding a valid hash:

$N(Difficulty) = \frac{2^{256}}{target\value}$

By combining (2), (6), and (7), we have:

$Hash rate = \frac{1}{10\text{min}} \times \frac{2^{256}}{difficulty\target} \times 600\text{s} \times \frac{2^{256}}{Difficulty} = Difficulty \cdot 2^{32}/600s$

For example, if Difficulty = 5.95 T, using (1.8), the hash rate is 42,587,731,567,771, 900,000 hashes/s, or 42.6 Exash per second (42.6 EH/s). With the same Difficulty, a computer with 16 TH/s power could be mined for 50 years to find a solution (time = $600\text{s} \times 42.6\text{EH/s} / 16\text{TH/s}$).
