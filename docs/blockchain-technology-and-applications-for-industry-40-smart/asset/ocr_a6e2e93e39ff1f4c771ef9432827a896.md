Shards are not mutually isolated – occasionally, any member in a shard can send a message to a randomly chosen member in some other shard. Each shard maintains outgoing message queues for all shards. Suppose client, $C_a$ of node A in the shard $\alpha$ wants to send some cryptocurrency to client, $C_b$ of node B in the shard $eta$. This transaction is first noticed by node A to the nodes in the shard $\alpha$, the account state of client, $C_a$ is decreased by the amount being sent.

An inter-shard message is also created and put in the outgoing queue for the shard $eta$. Subsequently, at one moment, node, X, from the shard $\alpha$ will check that queue, and seeing that it is not empty, X will send this inter-shard message (which contains transaction $C_a 	o C_b$) together with other transactions (actions from the shard $\alpha$ to $eta$, if any) to a randomly chosen node, Y, in the shard $eta$. When Y receives the list of messages and submits it to the nodes in the shard $eta$ through gossip. When a transaction, $C_a 	o C_b$ reaches consensus in the shard $eta$ (and if the sequence number of the assigned inter-shard message is correct), the effect of the transaction will be applied on all nodes in $eta$, and the account balance of $C_b$ will be increased by the amount being sent.

The positive effects of the sharding architecture can be seen from the above described (and simplified) example of the communication between shards in a situation when the number of nodes in the network is very large. The number of gossips in the entire network would be many times greater without it, consensus and transactions delay would be much longer, and the nodes' ledger files would be much bigger. The separation on shards minimizes the total amount of gossip messages in the network, since each transaction is gossiped only within shards relevant for that transaction.

The Hedera hashgraph platform comprises three layers: the Internet layer, hash consensus layer and service layer. The Internet layer provides a basic communication infrastructure for the network, that is, for the computers connected to a P2P network, communicating by TCP/IP connections with TLS encryption. The hash consensus layer represents the process in which nodes take transactions from their clients. They share them throughout the network using gossip protocol and run the hash consensus algorithm to reach the consensus in time order. Then, each node applies the transactions' effects in consensus order, that is, modifies its state (of the clients' accounts), which is identical with the copies on all other nodes of a given shard.

- Cryptocurrency
- File storage
