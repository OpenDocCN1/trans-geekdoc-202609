Either, all transactions inside the bundle will be accepted by the nodes of IOTA network or none of them. In the process of bundle creation, at first, the output containing the address b of client B in the Address field and the positive value of 700 in the Value field is prepared. This transaction gets assigned index 0 (this is indexed as the beginning of N transactions, but it will be issued last in time, in the burst of N bundled transactions).

Next, the input and meta transactions are prepared. If client A, for example, three addresses (i.e., three accounts) $a_1, a_2$, and $a_3$ generated from the same private keys, with the account counts of 200, 600, and 350 Iotas on them, the three corresponding input transactions will have the following values written in the Index, Address and Value fields: $[1, a_1, -200]$, $[3, a_2, -600]$ and $[5, a_3, -350]$. Since input transactions need to contain transaction signatures where the address security level is by default, a meta transaction is added after each input transaction to carry the second part of the signature of the preceding transaction. These three meta transactions will have the following indices, addresses, and values: $[2, a_1, 0]$, $[4, a_2, 0]$ and $[6, a_3, 0]$.

In the output, the bundle is prepared as the last one to handle the transfer (the called remaining transaction). Client A spends $200 + 600 + 350 = 1150$ tokens through the three input transactions, and client B received 700 tokens through the first output, a new output transaction is created, which returns the difference of $1150 - 700 = 450$ tokens to client A. This transaction has index 7 (the biggest in the bundle), value 450 (positive), and address $a_4$ (created from the same seed as the addresses $a_1, a_2$, and $a_3$ of client A).

In the end, the complete bundle contains eight individual transactions with the "Index", "Address", "Value" triplets: $[0, b, 700]$, $[1, a_1, -200]$, $[2, a_1, 0]$, $[3, a_2, -600]$, $[4, a_2, 0]$, $[5, a_3, -350]$, $[6, a_3, 0]$, and $[7, a_4, 450]$. The first and last transactions in this example are of the output type, while the actions in the middle are of input or meta-type. The total number of transactions in a bundle is limited, but practically, given network constraints and limitations of the PoW difficulty, the issuance of bundles with over 30 transactions is discouraged. A typical bundle for a transfer between two clients (sender and receiver of tokens) consists of four transactions: one output (to receiving client), one input (from sender), one meta-transaction, and the balancing transaction.
