* Underestimating the value of efficiency in work patterns. Understanding tool shortcuts and diving into the features of any tool makes users become more proficient users. When learning new tools, a child’s curiosity is the right attitude.
* Underestimating the value of experience. Nothing beats experience. Learning something on paper or in theory is rarely good enough. Trial and error is key to obtaining experience to improve efficiency.
* Not selecting the right tools for the job. Any analytics tool should have an explicit purpose for being used, even general purpose analytics tools.
* Making incorrect assumptions about the data. A common mistake is to assume a normal distribution, when one does not exist. It may be useful to check aspects of the data through visualization. In this case: use a histogram to check that’s distribution. If we need to, we could trim the data (exclude data), transform the data (e.g. using a power transformation) - a useful technique to stabilize variance, making the data more distribution-like, or improve the validity of measures of association), winsorizing (i.e. reduce the effect of extreme outliers), or data imputation (i.e. replacing missing data with substituted values, usually averages)
* The tool is not showing the expected answers. For such concerns, it is worth checking the data input is well-formed, correct answers have been made about that data input (e.g. we are assuming a normal distribution where one does not exist?), the tool otherwise being used correctly, and finally (and perhaps the least favourable to realise), the data itself does not contain the answer we want to see (but what we are seeing indeed correct).
* Inappropriate and unjustified use of visual encoding in visualizations. Inappropriate use of variables or a design for commonly known colour facts (e.g. red and green do not complement each other when placed in close proximity, particularly as blind people may mix the two). People are able to distinguish between ranges of colours, however, very similar looking colours (esp. used in small sized visual variables) diminishes a user’s ability to quickly distinguishing between variables.
* 3D visualizations is always better than 2D. It is dangerous to make this assumption by default. Not all data has. In many instances 2D representations of data are perfectly suitable, it can be projected onto a 2D image in the end (a monitor or projector), and for 3D scenes, data can be overlapping, limiting the amount of information visible on screen. In the end it is necessary to identify the purpose of the visualization, and whether 3D or 2D representations make the most sense.

## 3.5. Analytics: Practical Concerns

Analytics has its benefits, however, there are a significant number of practical challenges to overcome when we use analytics – particularly when envisaging analytics being the arctic. These might include:

* Raw data can only convey so much. Data only tells what has been observed, and rarely or how. This has to be deduced or inferred. Tools that allow for these types of reasoning are not particularly mature today.
* Models of the real-world need to be updated frequently. The world continuously changes, and any data is subject to be out of date as it reaches an analyst's eye. It is necessary for tools to improve their ability to make sense of data, through constant situational awareness updates that make sense when combating threats or responding to incidents.
* Knowing when to observe more to assess a situation further. This is especially applicable in security incidents or natural forces, or observing potential dangers in the real world: we may see the threats continue in order to gather more intelligence about the situation. However, at some stage it will be necessary to take an action.
* Knowing when and what is missing. Complete situational awareness is missing, but being able to have an intuition for where to place sensors, how many technologies to deploy and sensor data to collect for any type of mission in the arctic is something that comes from experience. With IoT devices becoming widespread, it is not unreasonable to assume they will also be deployed in the arctic moving forward.
* Using analytics incorrectly will lead to misinformation. This point is in concert with the previous point about making incorrect assumptions about the data. Making use of machine learning algorithms or visualizations will lead to the incorrect message about the data being communicated to the analyst or decision maker.
* Number of data points matters. The arctic is vast, and sensors can be placed sparsely. Having enough data points matters for good coverage for situational awareness. Identifying where to place sensors is of benefit to anyone using an analytics tool.
* Noise in the data. With any real-world sensors taking measurements from the physical world, we run the danger of acquiring noisy data (imprecise and inaccurate measurements) — especially in cold weather. This also applies to cyberspace in that alerting systems generate false positives.
* Delivery of and response to the analytics. Currently, most analytics tools are either bespoke, heavily integrated into environments, or generic systems that need to be used more meaningfully. 
* Not everything can be quantified. This is challenging for many. Prior work has been able to show progress towards some high-level theoretical and methodological objectives, but is still lacking in progress.

## 4.1. Recommendations

It remains to be whether the extent of the utility of analytics tools can sufficiently support analysts, risk-owners and decision-makers. Below follows an outline of recommendations for investigating.

* Setting Objectives for the Topic of Resilience. The central aim of any possible pathways would be to develop pragmatic, usable solutions to improve proactive and reactive system resilience has a strong foundation in academic and scientific research. To meet this objective, fundamental breakthroughs should be made with both theoretical and tool-implementation challenges. Some objectives may include:

* Empirical Objectives. Identify which sensors and KPIs are best suited for analytics in the arctic landscape, and how to deploy them to create useful empirical evidence for decision making. It will be necessary to collect and evaluate insight about how real-world systems of different types operate in a heterogeneous space, how they both dissimilar and similar in their resilience needs, and identify critical factors that affect performance, including usability and functional relationships.

* Theoretical Objectives. Establish a sound, universally-accepted theory of resilience (from the empirical). We need to establish a sound theoretical foundation for the development of methods to support resilience research. This can be achieved by demonstrating how lack of resilience affect real-world systems, and how new methods can effectively measure, assess, improve and communicate resilience. A sound theory can facilitate informed decision-making, and in the long term, help best-practices.
