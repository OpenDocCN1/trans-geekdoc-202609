The manager minimizes the number of countermeasures to deploy by selecting shared countermeasures e.g. those that affect attacks in distinct chains. The focus on shared countermeasures dramatically reduces the number of countermeasures to deploy that, in our experience, is never larger than 5% of the current vulnerabilities.

However, the focus on countermeasures is one of the innovative features of the *manager*, another one is its iterative behavior. The tool assumes an intelligent adversary that reacts to countermeasures by selecting and implementing a distinct chain to a goal. For this reason, the *manager* loops it over, after selecting a set of countermeasures, it updates the system model to describe its deployment and executes a new experiment to discover how the agents react to countermeasures it has selected. If the experiment shows that the attackers can implement some distinct chains, the *manager* selects a set of countermeasures that stop both the previous chains and those the experiment has just discovered. Then, it runs a new experiment and so on. In this way, the tool sequentially evaluates sets of countermeasures to discover that that no agent can reach a goal despite its reactions. At the end, the manager returns a database that describes the updated version of the system.

The Harpex methodology minimizes the number of countermeasures to deploy and favors a solution that prevents the attackers from reaching their goals by minimizing the lowest number of vulnerabilities. Hence, it accepts some vulnerabilities in the modules without forcing a patch-all solution to remove any vulnerability.

# 4. A Case Study

We describe briefly a risk assessment of the ICT + OT infrastructure of a 4.0 ship that is currently under development by a main international shipbuilder. The assessment has been executed as a step of the design to minimize the overall risk. Some of the modules to be used were already available. These modules have been scanned to discover the corresponding vulnerabilities. Other modules were not available yet and their vulnerabilities have been acquired either through a vulnerability database or other sources. Both system scanners and web ones have been used.

The whole infrastructure includes about one hundred computers that are partitioned into two subnets and run more than OS instances.

The attack surface of the overall ICT + OT infrastructure includes any system that is connected to the Internet as well as USB ports that enable external operators to connect their devices. The attacker goals include the navigation system, the power control as well as the fire system. The latter enables DOS as well as attacks with a high impact on the people on board.

The assessment has considered a scenario with a number of attackers adopting a distinct strategy so that the assessment covers any of the attacker parameters.

The shipbuilder required a high confidence level that Harpex has reached through experiments with more than a million runs. Only model-based approach can implement this using simulations because it is unrealistic to run these experiments on the target system, even when it already exists.
