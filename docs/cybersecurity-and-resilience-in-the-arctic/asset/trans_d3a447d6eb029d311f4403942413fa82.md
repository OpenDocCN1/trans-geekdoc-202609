## 3. 航运韧性的波浪类比

本文通过用于识别网络攻击前后存在的元素，探讨了该框架在航运运营中的实用性。特别是，本文分析了 NotPetya 攻击，该攻击影响了马士克航运公司（AP Moller-Maersk，2017年的马士克 (Van Niekerk, 2018)）。这次攻击最初表面上是勒索软件，但事实证明是一个破坏器（Furnell & Emma, 2017），其中即使执行了所需的比特币支付，数据恢复也可能是可能的。将波浪类比框架应用于 NotPetya 攻击的事实，得出了如下分析，并新闻数据（McQuade, 2018）的支持。

- 1. 合规性：航运业的规范和法规包括全球性规范，如 ISO 27000 (Disterer, 2013)、NIST SP-800-53 (D. Budeau & Graubert, 2013)，以及行业相关规范，如丹麦海洋部门网络与信息安全战略、BIMCO 船载网络安全指南、IMO 海事网络管理指南以及公司的任何内部准则。

- 2. 情境感知：NotPetya 利用了最近发现的一个 Windows 漏洞（被称为 EternalBlue），该漏洞与 Mimikatz 等其他工具结合时可以提取密码。2017 年早些时候，EternalBlue 在 NSA 文件泄露后为公众所知，随后某些 Windows 发布了针对 EternalBlue 漏洞的补丁。尽管有报道称，(McQuade, 2018) 指出网络分段等问题——NotPetya 内部大范围的影响——已在内部指出，但认为以下观点是合理的：马士克低估了跨 IT 基础设施的灾难性网络事件的风险，认为在短期内作为立即采取的后续行动，这种风险是不可能的，甚至是不可可行的。

- 3. 治理：马士克从 2015 年起就设有首席信息安全官，它是首批实施此类数字化战略的大型航运公司之一。因此，马士克在其 IT 基础设施的决策过程中有一个层级结构，位于英国，负责监督公司近 80,000 名员工的数字化需求。因此，尽管马士克拥有管理这一治理结构的资源，但情境感知显然不足，未能触发足够的行动来防止和缓解公司全球 IT 崩溃的风险。利用漏洞的应用程序

- 4. 事件前知识：使用了 EternalBlue 和 Mimikatz，但前者是相对较新的，而且之前没有广泛观察到两者结合使用的情况。因此，在对某些进行逆向工程之前，对于如何防止或处理这一特定威胁还没有初始知识。

- 7. 适应能力：马士克的数字化系统。
