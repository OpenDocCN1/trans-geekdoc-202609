# 3.1. Resilience as a System Property

In determining how to create a resilient USN, it is important to be aware that resilience is a system property. As Linkov et al. (2013) describe:

> Real-world networks are comprised of technological, sociological, ecological, and economic components, such that a combination of interconnected elements, communication devices, humans, and environmental forces form an integrated whole (Halvin et al. 2012). Resilience is a property of the entire system and should be assessed accordingly. [152]

A system is only as resilient as its weakest component. Because all elements of a system are working together as an “integrated whole”, the failure of any single element can trigger substantial losses, potentially incapacitating the entire system.
Perrow (1984) describes how failure is a normal element of complex, tightly-coupled systems [158]. It defines a complex system with complex interactions between components, such that “two or more failures among components” will interact in some unexpected way” [158]. A tightly-coupled system is one in which “processes happen fast and can’t be turned off, the failed parts cannot be isolated from other parts, or there is no other way to keep going safely,” that is, individual components of the system are so closely linked that if one fails it will affect the others around it, like domino topping each other [158]. Most modern systems, especially those built by NATO and the U.S. Navy, are tightly-coupled and [159]. As Little (2003) notes, “a particularly troubling characteristic of these tightly-coupled, complex systems is that they predictably fail in unpredictable ways” [160]. This makes resilience all the more relevant for the Navy. It also means that in order to optimize Navy resilience, we must examine individual components of systems to identify perform accomplish the first stage of resilience (preparedness / bread utility).
