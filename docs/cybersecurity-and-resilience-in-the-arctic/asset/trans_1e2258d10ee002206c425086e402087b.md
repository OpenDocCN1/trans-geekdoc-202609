- **空间韧性 (Resilience in Cyberspace)**：适应不断变化的情况并对干扰做好准备、承受并从中快速恢复的能力。
- **国家韧性 (Resilience for the Nation)**：适应不断变化的情况并对干扰做好准备、承受并从中快速恢复的能力。
- **关键基础设施的韧性 (Critical Infrastructure Resilience)**：减少破坏性事件规模或持续时间的能力。韧性基础设施或企业的有效性取决于其预测、吸收、适应和/或从潜在破坏性事件中快速恢复的能力。
- **社区韧性 (Community Resilience)**：社区对预期危害做好准备、适应不断变化的情况，并承受和从干扰中快速恢复的能力。
- **关键基础设施的安全与韧性 (Critical Infrastructure Security and Resilience)**：对不断变化的情况做好准备和适应，并承受干扰并快速恢复的能力。韧性包括对蓄意攻击、事故或自然发生的威胁或事件的承受和恢复能力。
- **信息系统韧性 (Information System Resilience)**：系统在不利条件或压力下继续运行的能力（即使处于降级或虚弱状态），同时保持基本的运营能力；并在与任务需求一致的时间范围内恢复到有效的运营态势。
- **网络韧性 (Network Resilience)**：网络在面对各种故障和对正常运行的挑战时提供并维持可接受服务水平的能力。
- **运营韧性 (Operational Resilience)**：系统在运行期间抵抗、吸收并从不利事件中恢复的能力，这些事件可能导致损害、破坏或执行任务相关功能的能力丧。
- **韧性工程 (Resilience Engineering)**：构建能够预测并规避不利因素、通过适应和调整生存，并通过尽可能恢复到受干扰前状态来从干扰中恢复的能力。

每一项都代表一个特定领域，用于量化韧性的含义以及预期的恢复。每项的定义方式使得最高层级的指标几乎可以自成体系。例如，*空间韧性*可以被分解为衡量系统如何适应不断变化的情况以承受并从干扰中快速恢复。这还列出了其中一个更大的集合，在其中定义韧性可以用于进一步定义和区分一个领域与其他领域，例如，为什么网络安全不同于网络或运营韧性。审查 NIST 集合意义在于，“韧性”一词及其用法令人困惑，指标及其实际测量也是如此。这仅仅是当今行业中韧性主题可能有多令人困惑的一个例子。为了在指标结构中进一步定义和量化测量结果，还需要理解组织的韧性目标。Berkeley 和 NI 模型 [3] 提供了一种通用方法，首先确定确定组织的韧性特征，然后确定其韧性目标。使用这些由韧性专家 Stephen Flynn [4] 最初构思的“四大目标”：

# E.P. Yakabovich / 网络韧性测量与指标

- **稳健性 (Robustness)**：面对危机时维持关键运营和功能的能力。
- **资源利用 (Resourcefulness)**：熟练地准备、响应和管理随危机或干扰演变为行动方案和业务连续性的能力。
- **快速恢复 (Rapid recovery)**：在干扰发生后尽可能返回并/或恢复正常运营的能力。
- **冗余 (Redundancy)**：被提作为另一个关键特征，可能意味着在故障时有备用资源支持原始资源，这在规划韧性时也应被考虑。

Berkeley 和 Wallace [3] 为 NIAC 也将这些称为“4Rs”，其中韧性被认为是多学科的，并且应该与其他学科达成一致，以确保组织获得积极且成功的结果（第 16 页）。在没有此类一致的情况下，他们继续说将不会“成功或高效的基础设施”（第 16 页）。

上述两种方法提供了预定义定义和自定义定义的使用。预定义侧重于使用基于美国关键基础设施国家框架的预想定义，而 NIAC 模型 [3] 反映了通过组织希望实现的既定目标和特征来构建定义。这两个例子反映了在定义并随后跟踪组织韧性特征的使用方法上的差异。这让人们理解在选择模型时所需的精力，以及开发指标以跟踪和向组织报告所需的精力。下一节将提供指标的背景，以及为什么它们对 ICT 和业务专业人士都很重要。

# 3. 指标的价值

作为一名 ICT 专业人士，理解为什么指标重要以及它们为组织提供的价值是非常重要的。由于 ICT 专业人士通常认为指标是繁琐且麻烦的，本节提供了指标重要性的原因和更细微的观点。作为一种标准，指标为组织提供了性能衡量，以向不同受众（如领导层、员工和股东）告知跨业务运营的有效性。运营指标必须易于重复，并且在每次向任何人报告时都具有相关性，以便从时间范围内进行任何衡量和测量，任何指标都应该尽可能客观且易于理解。这些测量必须是重复的，否则它们就没有用处。
