At the beginning of each run, an attacker owns its legal privileges. At each step of the run, the first engine determines the action of each attacker. Possible actions include the scanning of a module to discover its vulnerability or an attack. If an agent implements an attack, the engine integrates the corresponding strategy to choose which attack to execute. Based on the success probability of the selected attacker, the engine determines whether it is successful, and, in this case, it grants to the attacker proper privileges. This creates a further run in the attack chain. The agent will exploit the new privileges after a delay that depends on the time to execute it. If the attack fails, the agent is idle for the same number of slices and repeats the selection. The knowledge of attack success probability to simulate an attack independently of the actions to execute and of the underlying technology. Hence, the simulation can cover any attack, independently of the attacked module, if it knows the success probability and the time to execute it. This enables the engine to discover which cross components in distinct subsystems of the overall ICT+OT system. The success probability is an attribute, the engine considers how defense mechanisms are proper. Whatsapp integrates the Monte Carlo method for the probabilistic part of the model to simulate both the intelligent behavior of adversaries and the time they spend to discover vulnerabilities before attacking a module.

At the end of a run, the engine reinitializes the privileges of each attacker before starting a new run. In each run, the engine collects data on the attackers in the attack chain, on the modules and on the goals, they have reached. In other words, each run returns one value in the database the engine returns. The engine can collect any information of interest between the attackers and the system because it simulates both the attacker behavior and the system reaction.

Further tools to use the assessment database to compute statistics on the attackers, their success probability, and their impact. Since the confidence level of each statistic increases with the number of runs in the engine, the engine may start a new run until it achieves the required confidence level.

In this way, the assessment can compute a sample with enough values on the chains the agents have implemented to assess the required robustness against the attackers in the scenario. The assessment can discover not only the average time for an attacker to reach a goal but also the best case for the attacker.

# 3.2.3. The Manager

This is the most important tool that uses the engine outputs because it computes a set of countermeasures to deploy or minimize the risk, i.e. the success probability of the attackers. The manager aims to stop at least one attacker in each chain that enables an attacker to reach a goal. All the chain becomes useless if we stop at least one of its attacks. The manager includes the assessment database and a catalog, a database that stores pairs of the attacks with vulnerable countermeasures. Possible countermeasures include, among others, patching, updating a firewall or routing one network, and micro-segmentation.
