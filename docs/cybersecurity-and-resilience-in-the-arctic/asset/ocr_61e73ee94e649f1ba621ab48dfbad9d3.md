# 4.4. The forensics issues in Smart Grid

During forensics, several practical issues may occur and, the following should be considered (Kotsiuba et al., 2019):

+   * A complete forensics toolkit should be available in advance, thus avoiding unnecessary time to search and print out forms or wipe/overwrite media. The toolkit is complete when all media, tools and cables are available.

+   * Select appropriate file system for the storage of the (log) files, considering that FAT16 and FAT32 file systems have a maximum size of 2GB and 4GB respectively, while Linux and OSX file formats are almost inaccessible from Microsoft Windows.

+   * Consider availability of qualified staff, able copy or export forensic files (log files).

+   * Never work with the original evidence. A complete copy of the evidence for forensic analysis should be made prior to examination. This safeguard is needed because errors are made to working copies or comparisons are required, it will be necessary to compare the original and copies

+   * Ensure forensically cleaning media, as this prevents the original copies from damage.

+   * Ensure secure evidence storage.

+   * Forbid access to the evidence by third parties.

In addition, the Smart Grid system is continuously evolving due to the involvement of private networks. New connections can be added daily, changing the configuration and data channels.

Furthermore, advanced forensic frameworks that preserve users’ privacy, are developed, but the trade-off between forensic effectiveness and user privacy has not been addressed. Current forensic tools from various attacks in their log and event files, making the forensic investigation infeasible. as attackers launch an attack, and then erase their traces by deleting logs. This suggests, that Advanced Readiness Framework (FRK) should be designed to collect necessary information from the smart grid systems while being able to protect personal data, and thus ensuring the fundamental user rights during the preparation of the forensic procedures that will secure a detailed and complete report of the attack to the court.

A key aspect here relates to the collection and protection of network traffic data that may be useful for evidentiary purposes, which raises two main forms of legal compliance issues. The first is the need for data to meet accepted standards of evidentiary reliability and cogency (so as to be usable in subsequent criminal investigation and possible judicial proceedings); the second, the need for processing of such data, where it qualifies as personal data, to satisfy the requirements of applicable data protection law.
