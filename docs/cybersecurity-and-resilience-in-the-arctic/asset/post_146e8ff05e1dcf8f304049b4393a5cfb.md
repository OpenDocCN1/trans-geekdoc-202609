The adoption of a Monte Carlo approach results in larger freedom for defining the complexity of the models of the system and of each agent. The assessment can freely choose the complexity of the various models to cover all the aspects of interest. In general, an assessment selects the model complexity according to both the level of details and the computing power that is available to simulate the joint evolution of the target system and its attackers.

## 3.2 The Harpex Platform

To support the proposed methodology and the corresponding Monte Carlo approach, we have developed the Harpex platform, an integrated suite of tools that supports the building and the interactive execution of the models. The main platform tools are:

- the builders that collect information to define the various models,
- the engine that interact executes these models and the Monte Carlo method to produce an assessment database,
- the manager that uses the assessment database to select from a catalog the countermeasures to deploy to minimize ICT risk.

The assessment database includes information about the attack chains that the attackers have executed in the simulations of the Monte Carlo method. The database is an accurate statistical sample of the attack chain the attacker can select and implement. The platform returns static countermeasures to deploy to manage the risk. A static countermeasure updates the target system in a permanent way to minimize risk. However, the assessment database is one of the inputs of Harpex CAT, a security information event platform that monitors in real-time the attacks against the target system and deploys dynamic countermeasures, a set of dynamic updates to the system that are effective the attackers are defeated. As, a dynamic countermeasure may close some network connections to stop all attacks. Proper databases store the various models and the samples the interaction among the builders, the engine and the manager. The input builders requires the output of out-of-the-shelf scanners that identify the systems, as network nodes, their operating systems and the applications they support. At first, the builders map each module into its vulnerabilities and each vulnerability into the attacks it enables. The first mapping exploits a vulnerability database to discover the properties of each vulnerability. As an example, the mapping may use the Common Vulnerabilities and Exposures as deduced from the CVE Details but an assessment may use a primary database as well.

### 3.2.1 The builders

A builder pair each attack with its attributes as the privileges it requires and those it grants. Builders enrich this first digital twin through information they discover about the real system. Any of these tools increases the accuracy and the truthfulness of the adversary simulation. As an example, an important builder is the one that computes the logical system to determine the modules each module can attack. If the target system is not deployed, the builders produce their output from the system specifications the design has. As an example, a builder can compute a list of the module vulnerabilities from the OS and the systems it run.

Each builder builds the target system model in a database or it enriched the database other tools have built. An assessment may update this database to insert further vulnerabilities of some modules or of some users. This simplifies the introduction of both suspected vulnerabilities and those involved in phishing attacks.

Distinct builders produce another database that stores the attackers. Each attacker model is the digital twin of an adversary and describes the attack it can implement, the privileges and the information on the system it initially owns and the goals it aims to achieve. Some attributes of an attack determine the chance of an intruder. The main attributes are the ranking strategy and stubbornness. The latter determines the number of times the attacker repeats a failed attack before choosing another. The ranking strategy selects the attack to implement among its current privileges. A strategy may rank attacks at random or according to the number of privileges, they grant, to the success probability or to the difference between the privileges it grants and those in a goal. All the information to build the attacker digital twin may be collected by threat intelligence. Furthermore, several models of distinct attackers can be built to simulate their behaviors and discover the most dangerous one for the target system.
