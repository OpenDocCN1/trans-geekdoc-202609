+   * Underestimating the messiness of data. Data is rarely in a neatly packaged format

* Underestimating the value of efficiency in work patterns. Understanding

* Underestimating the value of experience. Nothing beats experience. Learning
sothing on paper or in theory rarely good enough. Trial and error is key to

* Not selecting the right tools for the job. Any analytics tool should have
an explicit purpose for being used, even general purpose analytics tools.
* Making incorrect assumptions about the data. A common mistake is to assume
an normal distribution, when one does not exist. It may be useful to check
asects of the data through visualization. In this case: use a histogram to check
theta’s distribution. If we need to, we could trim the data (exclude data),
transform the data (e.g. using a power transformation) - a useful technique to
stabilize variance, making the data more distribution-like, or improve the
validity of measures of association), winsorizing (i.e. reduce the effect of extreme
outliers), or data imputation (i.e. replacing missing data with substituted values,
usually averages)
* The tool is not showing the expected answers. For such concerns, it is worth
checking the data input is well-formed, correct answers have been made about
theta data input (e.g. we are assuming a normal distribution where one does not
extist?), the tool otherwise being used correctly, and finally (and perhaps the least
favourable to realise), the itself does not contain the answer we want to see
(but what we are seeing indeed correct).
* Inappropriate and unjustified use of visual encoding in visualizations.
Inappropriate use of variables or a design for commonly known colour
feacts (e.g. red and green do not complement each other when placed in
close proximity, particularly as blue people may mix the two). People are
able to distinguish between ranges of colours, however, very similar looking
colours (esp. used in small sized visual variables) diminishes a user’s ability to
ququickly distinguishing between variables.

+   * 3D visualizations is always better than 2D. It is dangerous to make
this assumption by default. Not all data has. In many instances 2D representations of data are
perfectly suitable, it be projected onto a 2D image in the
end (a monitor or projector), and for 3D scenes, data can be overlapping,
limiting the amount of information visible on screen. In the end it is
ncessary to identify the purpose of the visualization, and whether 3D or 2D
resentations make the most sense.
