韧性通过图 1 中的性能值随时间进行测量，具有以下属性：

- 'Inp' 是初始性能，
- 'P' 是变化率或性能，
- 'Tip' 是恢复到初始性能的时间，如果不同则为达到最终性能的时间，
- 'Tfp' 是达到最终性能的时间，
- 'imp' 是通过性能下降衡量的威胁影响（用于衡量风险），
- 'Imx' 是最低性能值，
- Ap 分为：
    * 最终性能与初始性能之间的正差（表现良好），
    - 最终性能与初始性能之间的负差（表现不佳），或，
    - Inp 等于 Enp 时无变化，
- 'Enp' 是性能结束值，以及
- 'Time' 是测量的整个时间段。

创建易于理解的韧性指标所需的必要知识。以下“五步韧性指标流程”将包括：

- 从 NIST 关键基础设施列表中选择一个部门/行业，并获取该部门的定义；
- 审查 4R，这将有助于指标的特征描述和目标（或意图）；
- 选择一个组织通常使用的行业或监管指南，以及；
- 选择一个代表指南并符合第 1 和第 2 步目标的低层级指标（下文将解释）。
- 创建韧性图表。

此示例将是创建指标的一种简单且易于理解的方法。可能，此示例可能适用于或不适用于其他行业，并且根据组织的实际韧性目标和要求，实施可能会更加困难。它是作为一个示例和方法，帮助并理解在构建韧性指标的一些实际构建中的基本概念。

- 定义：适应不断变化的能力，以及准备承受和从干扰中快速恢复的能力。

指标并提供“韧性”术语。以下示例将基于步骤 #1 并构建：

- NIST 项目：“网络空间中的韧性”
- 目标：适应不断变化的能力，以及准备承受和从干扰中快速恢复的能力
- 4R：如表 2 所示，将 4R 放在左侧、描述，然后是是或否列，并带有一列来解释原因。所有词汇应尽量减少，使用“能力以”、“准备好”等词汇：

# 表 2 4R 表

| 4R 标题 | 描述 | 适用 (Y/N) | 原因 |
|---|---|---|---|
| 稳健性 (Robustness) | 维持关键操作和功能的能力 | | 述于 4R 目标 |
| 资源性 (Resourcefulness) | 准备、应对和管理危机或干扰的能力 | Y | 与 4R 相似 |
| 快速恢复 (Rapid recovery) | 快速高效地返回或重建正常运行的能力 | Y | 与 4 目标相似 |
| 冗余 (Redundancy) | 有备份资源 | N | |

根据表 2 的选择，前三个适用（稳健性、资源性和快速恢复），第四个不适用（冗余）。方法可能与其他指标创建有所不同。这些结果应存储，以便在指标生成过程中使用。
