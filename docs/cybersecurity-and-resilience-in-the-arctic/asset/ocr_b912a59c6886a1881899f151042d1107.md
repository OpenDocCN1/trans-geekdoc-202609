Background and Objectives - contains all relevant background information, including a description of why a forensic examination of a specific network node, evidence, data, etc., was necessary and what initial hypotheses (if any) were considered. It also includes outline of all tasks accomplished in the investigation;
3. Evidence Analysed - introduces all collected and analysed evidences during our investigation. The use of a chart is strongly suggested, illustrating the main points about each piece of evidence and the relationships among them;
4. Relevant findings and Supporting Details - presents the main findings of the investigation, including all conclusions and opinions of the forensic analyst. Each relevant finding must come with the in-depth analysis of how we arrived at conclusion, including all technical means used during the analysis;
5. Investigative Leads corresponds to incomplete tasks. It includes evidences that we are not able to analyse;
6. Conclusions and Annexes, summarizes the main technical findings of the investigation.

The report must be understandable by non-technical people like managers, judges, etc. It must be factual and defensible in detail. It should be mentioned also that all claims must be supported by evidences.

# 4.3 Logging and Monitoring

Within this area, logging is defined as the passive mechanism used by networking components, which issue notifications (log messages) periodically or when certain conditions are met (NCSC, CSC). Monitoring is defined as the active probing in order to get information about the state of systems and networks.

Logs are the most widely-used source for network and endpoint investigations. They contain application or platform-specific information characterizing handled or observed by the log creator. Logs are widely available and process in place to analyze them. Parsing is required in order to add context. Moreover, if not already aggregated, finding a specific log entry can significant time and effort before analysis can start.

Logging by itself is not for detecting attacks. Together with monitoring, it allows to generate alerts and notifications in a case of a known pattern detected. Logging Dynamic Host Configuration Protocol (DHCP) server logs about the assigned IP addresses, webservers logs store network information about the visitors of the webservers pages, network logs store network traffic metadata such connections as IP address, connection date and time, used ports and protocols. Moreover, the majority of logs contain IP address that is considered personal information and as such, they should be protected and not kept longer than strictly necessary. During investigation, event logs provide valuable information, such as system access (in particular, server logs), startup and shutdown times, errors and problems, information related to network functions, such as DHCP lease histories or network logs include records of network activity, such as remote logging.
