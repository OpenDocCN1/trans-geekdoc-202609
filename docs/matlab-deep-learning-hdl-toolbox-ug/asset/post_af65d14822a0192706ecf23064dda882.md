helperCreateRGBfromTF uses cwtfilterbank(Wavelet Toolbox) to obtain the continuous wavelet transform of the ECG signals and generates the scalograms from the wavelet coefficients. The helper resizes the scalograms and writes them to jpeg images.

```matlab
function helperCreateRGBfromTF(ECGData,parentFolder,childFolder)
% This function is only intended to support the ECGDeepLearningExample.
% It may change or be removed in a future release.

imageRoot = fullfile(parentFolder,childFolder);
data = ECGData.Data;
labels = ECGData.Labels;

[-,signlength] = size(data);

fb = cwtfilterbank('SignalLength',signLength,'VoicesPerOctave',12);
for ii = 1:r
  cfs = abs(fb.data(ii,:));
  im = ind2rgb(imuint8(rescale(cfs)),jet(128));
  imgLoc = fullfile(imageRoot,char(labels(ii)));
  imFileName = strcat(char(labels(ii)),'_',num2str(ii),'.jpg');
  imwrite(imresize(im,[224 224]),fullfile(imgLoc,imFileName));
end
```

# Quantization of Neural Networks

In digital hardware, numbers are stored in binary words. A binary word is a fixed-length sequence of 1s and 0s. The data type defines how hardware components or software interpret this sequence of 1s and 0s. Numbers are represented as either scaled integer (usually referred to as fixed-point) or floating-point types.

Most pretrained networks and neural networks trained using Deep Learning Toolbox use single-precision floating point types. Even small neural networks require a considerable amount of memory, and require hardware that can perform floating-point arithmetic. These restrictions can inhibit deployment of deep learning capabilities to low-power microcontrollers and FPGAs.

Using the Deep Learning Model Quantization Library support package, you can quantize a network to use 8-bit integer data types.

Quantization of a network requires a GPU, Interface for Deep Libraries support package, and the Deep Learning Toolbox Model Quantization support package. Using a GPU requires CUDA enabled NVIDIA GPU with compute capability 6.1, 6.3 or higher.

# Precision and Range

Scaled 8-bit integer data types have limited precision and range compared to single-precision floating point types. There are several numerical considerations when casting from a larger floating-point type to a smaller type of fixed length.

- Precision loss: Precision loss is a rounding error. When precision loss occurs, the value is rounded to the nearest number that is representable by the data type. In the case of a tie it rounds:
- Positive numbers to the closest representable value in the direction of positive infinity.
- Negative numbers to the closest representable value in the direction of negative infinity.
- Underflow: Underflow is a type of precision loss. Underflows occur when the value is smaller than the smallest representable by the data type. When this occurs, the value saturates to zero.
- Overflow: When a value is larger than the largest value that a data type can represent, an overflow occurs. When an overflow occurs, the value saturates to the largest value representable by the data type.
