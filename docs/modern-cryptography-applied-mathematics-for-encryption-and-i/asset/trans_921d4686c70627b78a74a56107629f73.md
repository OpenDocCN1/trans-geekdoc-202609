
-   [盲签名](https://wiki.example.org/feynmans_learning_method) 也存在一种第三类数字签名——`blind signature`。基本上，发送者让签名者对消息 `m` 进行签名，而不需要知道 `m`；因此，这被视为盲签名。盲签名可以通过发送者和签名者之间的两方协议实现，该协议具有以下属性。

`![image](Images/image00484.jpeg)`  为了对消息 `m` 进行签名（由签名者完成），发送者使用模糊化过程，从 `m` 和 `m*` 生成，而 `m` 在未知秘密的情况下无法从 `m*` 获得，并将 `m*` 发送给签名者。

`![image](Images/image00484.jpeg)`  签名者对 `m*` 进行签名，得到签名 `s[m*]`（即 `m*` 的签名），并将 `s[m*]` 发送给发送者。签名方式使得发送者随后可以使用解模糊化过程，从签名者的签名 `s[m*]` 中计算出对 `m*` 的签名 `s[m]`（即 `m` 的签名）。

这使得仲裁者可以在不了解消息内容的情况下，对消息进行签名，确认该消息是在特定日期由特定发送者创建的。

###### 数字签名算法

数字签名可以使用任何非对称算法实现；然而，有些算法是专门为数字签名而设计的。数字签名算法（DSA）描述于美国专利 5,231,668，该专利于 1991 年 7 月 26 日提交，并归属于 David W. Kravitz。该算法于 1993 年被美国政府采用，作为 FIPS 186。实际算法的实现步骤如下：

**1.**  选择哈希函数（传统上使用 SHA1，但哈希强度越高越好）。

**2.**  选择密钥长度 L 和 N。

    注意，原始数字签名标准将 *L* 限制为 64 的倍数且在 512 到 1024 之间。现在推荐使用 2048 长度。美国政府文档现在指定 L 与 N 的长度组合为 (1024,160)、(2048,224)、(2048,256) 和 (3072,256)。

**3.**  选择一个小于或等于哈希输出长度的质数 q。

**4.**  选择一个质数 p，使得 p – 1 是 q 的倍数。

**5.**  选择 g，该数必须是其在 p  mod q 的乘数阶为 q 的数。

**6.**  选择一个随机数 x，其中 0 < x < q。

**7.**  计算 y = g^x mod p。

    公钥是 (p, q, g, y)。

    私钥是 x。

使用 DSA 对消息进行数字签名的步骤如下：

**1.**  设 H 为哈希函数，m 为消息。

**2.**  为每条消息生成随机值 k，其中 0 < k < q。

**3.**  计算 r = (g^k mod p) mod q。

**4.**  计算 s = (k^(–1)(H(m) + x*r)) mod q。

**5.**  如果 r 或 s = 0，则重新计算以获得非零结果（即选择不同的 k）。

**6.**  签名是 (r, s)。

DSA 是广泛使用的数字签名算法。在 [第 11 章](#part0021.xhtml#ch11) 中，你将看到 DSA 的椭圆曲线变体。

##### 数字证书

数字证书是一份数字文档，包含证书持有者的信息，如果是 X.509 证书，则还包含验证该信息的可信第三方的方法。数字证书是网站向终端用户分发其公钥的方式，也是网站进行身份验证的方式。

最常见的证书类型是 X.509。在深入此主题之前，你应先了解 X.509 证书的内容：

`![image](Images/image00484.jpeg)`  **版本**  该 X.509 标准使用的版本。

`![image](Images/image00484.jpeg)`  **证书持有者的公钥**  使用数字证书的原因之一是让接收方获得证书持有者的公钥。如果你访问使用 SSL/TLS 的网站（本章后面讨论），你的浏览器会从该网站的数字证书中获取其公钥。

`![image](Images/image00484.jpeg)`  **序列号**  标识具体的证书。

`![image](Images/image00484.jpeg)`  **证书持有者的 distinguished name**  用于唯一标识证书持有者，通常是电子邮件地址或域名。

以下是一些与数字证书相关的通用术语，你应当熟悉：

`![image](Images/image00484.jpeg)`  **PKI (public key infrastructure)**  利用非对称密钥对，结合软件、加密和服务，提供保护业务通信和交易安全的手段。

`![image](Images/image00484.jpeg)`  **PKCS (Public Key Cryptography Standards)**  由 RSA 制定，用于确保互联网上统一管理证书。

`![image](Images/image00484.jpeg)`  **CA (certification authority)**  一种被用户或多个用户信任的实体，用于发行和管理证书。

`![image](Images/image00484.jpeg)`  **RA (registration authority)**  在证书发行前处理验证工作，卸载 CA 的负担。RA 充当用户和 CA 之间的代理——接收请求、验证后转发给 CA。

`![image](Images/image00484.jpeg)`  **X.509**  国际标准，规定数字证书的格式和包含的信息。X.509 是全球最常见的数字证书类型，是一种数字文档，包含由受信任的第三方（证书颁发机构）签名的公钥。

`![image](Images/image00484.jpeg)`  **CRL (certificate revocation list)**  由 CA 发行但已不再有效的证书列表。CRL 的分发方式主要有两种：推送模型，即 CA 自动定期发送 CRL；拉取模型，即用户下载 CRL 以验证证书。

`![image](Images/image00484.jpeg)`  **Online Certificate Status Protocol (OCSP)**  一种用于获取 X.509 数字证书撤销状态的 Internet 协议，定义于 RFC 2560，属于 Internet 标准跟踪。它被设计为 CRL 的替代方案，以解决在 PKI 中使用 CRL 时遇到的某些问题。OCSP 可即时验证证书的真实性。
