### 6.2.4 个人资料设置

Bugcrowd 平台的最后一部分（宽泛地说，因为还有很多东西要学）是“个人资料和企业”侧边栏，其中还包含一些支付和日常管理功能（[图 6.41](#c06.xhtml#c6-fig-0041)）。设置中包括优化账户安全、使用 API 凭据以及管理项目会计功能的能力。项目经理应立即调整其个人资料设置，以充分保护其项目登录。为漏洞赏金项目登录本身维护最佳安全实践，可以说与解决漏洞同等重要。如果威胁行为者获得了漏洞赏金项目登录的访问权限，他们将能够查看所有预先存在的漏洞。因此，保护注册到项目的任何关联账户绝不可掉以轻心。

#### 6.2.4.3 通知设置

项目经理对将从漏洞赏金项目接收到的通知拥有完全的透明度和控制权。调整通知面板应是项目经理的重要优先事项。否则，可能会发生“警报疲劳”，换句话说，就是因有太多东西要看而产生的压倒性感觉（[图 6.46](#c06.xhtml#c6-fig-0046))。通过管理通知来防止警报疲劳是工程中经常被忽视的一个方面。想象一个家庭报警系统，它还有摄像头并根据规则集发出警报。如果房主每天收到二十次警报，可能会感到负担沉重，从而导致他们忽略真正需要审查的实际事件。警报管理也需要同样的考量。

![图 6.46 通知设置选项。](images/c06f046.png)

[**图 6.46**](#c06.xhtml#rc6-fig-0046) 通知设置选项。

正如[图 6.46](#c06.xhtml#c6-fig-0046)所示，似乎有很多内容需要拆解，但实际上比想象的要少。例如，电子邮件通知选项非常直接，允许项目经理在订阅的提交有活动时、团队成员 @提及 他们时，或提交分配给其项目管理账户用户名时接收电子邮件。是否开启“订阅提交上的活动”取决于项目经理的偏好。如果公司规模不是特别大，或者工程师的近乎全职工作就是管理漏洞赏金项目，那么开启所有通知很可能是最佳决定。作为一个折中考量，可以将“订阅提交上的活动”设为“开启”，并结合“当提交达到给定状态时订阅我”设为“已分类”。启用上述折中考量将允许项目经理在收到已分类工单的重要更新时收到警报。但请注意，有时可能会遇到过于咄咄逼人的安全研究人员，因此尝试调整通知直到合适为止将是项目经理的最佳选择。并非每个项目经理都有相同的偏好。关于通知的建议应因人而异，酌情参考。

#### 6.2.4.4 API 凭据

项目经理可能希望开发利用脚本进行 API 调用或各种外部工具的工作流。Bugcrowd 允许这种灵活性，因为安全工程师和软件工程师都可能希望利用此功能。生成 API 密钥很简单。要生成密钥，项目经理只需在“应用程序名称”字段中输入应用程序名称，然后点击“创建凭据”按钮。离开该页面后，凭据将生成且不再可访问（[图 6.47](#c06.xhtml#c6-fig-0047)）。
