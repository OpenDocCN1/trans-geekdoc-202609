## 什么是强化学习？

强化学习是不同的。强化学习可以引导智能体在现实世界中行动。

所以强化学习的接口比简单的数据要广泛得多，它是整个环境。

这个环境可以是现实世界，也可以是像视频游戏这样的模拟世界。

例如，你可以创建一个强化学习智能体来打扫房屋。那么它就会与真实世界交互。你可以创建一个强化学习智能体学习走路。那也会与真实世界交互。

你可以确定军事军事对这类技术感兴趣——他们想要强化学习智能体可以替代士兵。不仅是走路，还有战斗、拆除炸弹，并在执行任务期间做出重要决策。

所以你现在明白为什么强化学习相对于基础的监督和无监督学习是一个如此巨大的跨越了。




# 强化学习概述

强化学习算法具有基于“目标”的目标。这与监督学习不同，监督学习的目标是获得良好的准确率或最小化代价函数。

强化学习算法在智能体（agent）与环境交互时获取反馈。因此，反馈信号，或者我们喜欢称之为“奖励”（rewards），是由环境自动提供给智能体的。

这与监督学习大不同，后者获取人工标注的数据可能极其昂贵且耗时。从这个意义上说，强化学习与监督学习非常不同。监督学习需要人工标注的数据集，而强化学习从环境信号中自动学习，因此不需要人工标注。

## 目标概念

让我们扩展一下这个目标概念。将我们的任务表述为目标，可以允许我们解决更广泛的问题。

- `AlphaGo` 的目标是赢得围棋。
- 视频游戏 AI 的目标是在游戏中尽可能得远，或者获得高分。

有趣的是，当你考虑到动物，特别是人类时。进化心理学家说，我们的基因是“自私”的，它们唯一想做的就是产生更多的自身。这非常有趣，因为就像 `AlphaGo` 一样，我们发现了许多“迂回”且不太可能实现这一点的方法。专家评论说 `AlphaGo` 使用了一些令人惊讶且不寻的技术。

例如，你可能想要变得富有并赚大钱。但你是否想过你为什么会有这种感觉？也许那些拥有富有欲望相关的特定基因组的人，由于自然选择最终在我们的基因库中变得更加突出。也许拥有许多钱带来了更好的医疗保健和社交地位，从而帮助你的基因最大化了它们的核心目标，即产生更多的自身。

尽管银行账户里的数字在物理定律上与你的寿命长短没有直接关系，但它是该问题的一个新颖解决方案。“渴望并成功挣钱”只是我随口想出的随机例子，但你可以将其替换为任何你特质，比如“健康强壮”或“具有强大的分析能力”。知道确切的因素是社会科学家的工作，我们只感兴趣只有一个我们想要最大化的主要目标，以及实现它的各种新颖方法。

而且这些事物随着时间不断波动。在历史的某一点，尽可能寻求糖会为你提供能量并帮助你生存。今天，我们保留了这种特征，是因为进化是缓慢的，但在当今世界，这种特征实际上在杀死我们。我们基因最大化奖励的方法是通过突变和自然选择，这是缓慢的，但 AI 最大化其奖励的方法是强化学习，它是快速的。

## 技术细节：状态

现在让我们进入一些技术细节。当然，你永远不会一次性感知整个世界，即使人类也不是这样做的。我们有传感器从环境向大脑提供信号。这些信号甚至不能告诉我们关于所在房间的所有信息，更不用说世界了。因此，我们对环境的信息必然是有限的，那些具有有限数量和类型的机器人也是如此。

我们从这些传感器（视觉、听觉和触觉）获得的测量值构成了一个“状态”（state）。在本课程中，我们只观察具有少量有限状态的环境，但当然，也可以考虑具有无限状态的环境。

## 示例：五井棋

让我们做一个简单的例子。考虑一个井棋盘，我们不在乎谁赢，我们只想在棋盘上放置 X 和 O。棋盘起初是空的，我们继续添加 X 或 O 直到棋盘填满。

例：

```
+---+---+---+
| x | o | x |
+---+---+---+
| x | x | x |
+---+---+---+
| x | o | o |
+---+---+---+
```

如果你不知道五井棋是如何运作的，可以进行 Google 搜索并在浏览器中自己玩这个游戏。记住井棋盘是 `3x3` 的棋盘。这个环境中的状态总数是多少？思考这个问题一分钟，然后回到书中。

由于我们没有考虑在获得连续 3 个 X 或 3 个 O 后就有胜者的井棋游戏，所以这个问题非常简单。棋盘上的每个位置有 3 种可能的状态：空、X 或 O。棋盘上有 9 个位置。因此，状态总数是 `3⁹`。

## 关键术语回顾

让我们回顾一下目前为止讨论过的术语——有 3 个，可能还有我偷偷插进去的。这 3 个重要的是：

- **智能体（Agent）**：这是感知环境的实体，也是我们试图为其编码智能和学习能力的实体。
- **环境（Environment）**：这是你的智能体所在的真实世界或模拟世界。
- **状态（State）**：这些是智能体可以感知环境的不同配置。

## 奖励概念

强化学习中还有几个需要定义的概念，它们是该主题的核心。

首先，有一个`奖励`（reward）的概念。这是强化学习算法与其他类机器学习算法的区别。智能体不仅尝试最大化其即时奖励，还最大化未来奖励。通常，强化学习算法会找到实现这一点的新颖方法。

我本身不是棋手，但我们听说 `AlphaGo` 程序学习了独特且不可预测的策略，这些策略导致它成为世界冠军。这些东西对人类来说是不直观的，但强化学习算法可以自动发现它们。其中一个潜在的危险方面是意外后果。想象你程序化 AI 来减少死亡人数，然后它决定由于人类将指数级增长，未来死的人也会增加，现在消灭所有人对减少未来的死亡更好。所以对于与真实世界交互的 AI，存在某些副作用。为了给你一个关于如何以及为什么要编写奖励的低级示例，考虑一个机器人试图解决迷宫。一个合理的目标可能是简单的解决迷宫。如果你解决了迷宫，你会获得 `1` 的奖励，否则获得 `0`。在这种奖励结构下，机器人可能会执行随机策略并最终解决迷宫。因为我们从未告诉过它应该高效地解决迷宫，所以随机移动直到解决迷宫仍然能让你获得奖励。

现在想象我们对 AI 在迷宫中走的每一步都给予 `-1`。现在 AI 有动力用最少的步骤解决迷宫，因此它倾向于通过这种方式找到更好的解决方案。我们将在书后的代码中演示这一点。注意负奖励就像是惩罚，事实确实如此。奖励只是我们一直使用的术语，无论是正还是负。它告诉你做得好还是坏。注意奖励总是实数。

## 动作

到目前为止我们定义了这些术语：`agent`、`environment`、`state`和`reward`。我们需要讨论的最后一个重要概念是`actions`（动作）。动作是智能在其环境中的行为。例如，如果你是一个 `2-D` 视频游戏角色，你的动作可能是`上`、`下`、`左`、`右`和`跳`。这是一个有限动作集的示例。也有无限动作集的例子，但我们不会在书中讨论它。

我们讨论的最后 3 件事通常被认为三元组：你处于一个`状态`，采取一个`动作`，并获得一个`奖励`。





我们将这些组称为 `(S,A,R)` 或 `(state,action,reward)` 三元组。

在强化学习中，时机也是一个重要的概念，因为你每次玩游戏时都会获得一系列状态、动作和奖励。

在这个框架内，你从一个状态 `S(t)` 开始，采取一个动作 `A(t)`，但你收到的奖励是 `R(t+1)`。

因此，你获得的奖励总是来自于你上一个时刻所采取的状态和动作。

这个动作也会导致你处于一个新状态 `S(t+1)`。

所以，另一个重要的三元组是 `(S(t), A(t), S(t+1))`。我们通常将其记为 `(s, a, s')`。

## 问题设置与探索-利用的困境

在书的这一部分，我们将重新审视多臂老虎机问题，你最初在我关于贝叶斯机器学习和 A/B 测试的课程中见过它。如果你没有上过那门课程，不用太担心，因为我们将在书中完全涵盖这个问题。

假设你去了一家赌场，你有 3 台老虎机可供选择。每台老虎机都可以给你 0 或 1 的奖励，所以目前这就像是抛硬币一样。这被称为多臂老虎机问题，因为当你玩老虎机时，必须拉动机器的手臂（arm），而它们被称为“强匪”（bandits），是因为它们在掠夺你的钱。

每台老虎机的获胜率都是未知的。例如，它们可能是 0.1、0.3 和 0.5。但你并不知道这些，你只能通过收集数据来发现它们。现在你在赌场的目标显然是使收益最大化。如果你是预言者，能利用你的能力判断哪台机器的获胜率最高，你只会玩那一台机器，这样你就能实现收益最大化。

但由于你不知道获胜率，你需要通过收集数据来估计它们，这意味着你必须玩每台机器。困境就在这里产生。你需要收集大量数据使你的估计准确。但如果你收集了大量数据，你将花费大量时间在次优的老虎机手臂上。因此，你需要在尝试收益最大化与尝试获取每台老虎机获胜率的准确测量之间取得平衡，因为为了收益最大化，你需要准确地知道这一点。

在 A/B 测试中，你需要玩的次数取决于许多因素，例如获胜率的差异。如果差异越大，你需要的样本越少；如果差异越小，你需要的样本越多。这有点愚蠢，因为在开始之前并不知道差异，这是 A/B 测试的缺点之一。A/B 测试的一个重要规则是你不要提前停止测试。所以如果你预先决定每台老虎机要玩 1000 次，当你玩到 500 次时已经计算出 90% 的获胜率，你是不允许停止的。

有趣的是，人类的行为恰恰相反。假设你在一台机器上赢了 2/3 次，在另一台上赢了 0/3 次。你可能会产生一种冲动，从现在起只那那 2/3 的机器，尽管有很大概率另一台更好。如果我用统计学的方法问你——如果你认为 2/3 和 0/3 就能给你准确的测量结果，你会说“不可能！”作为一个数据科学家，你知道第一台机器实际获胜率为 67% 的概率较低，第二台实际获胜率为 0% 的概率较低。你知道这一点是因为 3 是一个非常小的样本量。然而，当你玩老虎机时，你却强迫自己相信第一台机器更好。

在接下来的章节中，我们将学习系统地权衡探索与利用的算法。这些算法允许我们改进上述两种糟糕的解决方案，即人类情感和传统的 A/B 测试。

## 贪婪策略

解决探索-利用困境的第一种解决方案被称为 贪婪策略。这是最重要的，因为这是我们在整个课程中使用的（尽管任何其他技术都可以等效应用）。我们喜欢它是因为简单。它的工作原理是：我们使用一个名为 `epsilon` 的小数值作为探索的概率。`epsilon` 的典型值为 10% 或 5%。以下是执行此操作的伪代码。

```python
if random() < eps:
    play random arm
else:
    choose current best arm
    update estimate for the arm played (i.e. avg = sum / N)
```




在每一轮中，我们生成一个随机数。如果随机数小于 `epsilon`，我们就进行探索（explore），意味着随机选择一个机械臂。如果随机数大于 `epsilon`，我们就进行开发（exploit），意味着选择到目前为止具有最大平均值的机械臂。

因此显而易见的是，最终你将学到哪条臂是真正的最好的，尽管你的初始猜测可能是错误的，因为每个臂始终都有机会被更新。

---

从长远来看，`epsilon-greedy` 允许我们对每条臂进行无限次探索。

然而，这种方法的问题在于，最终你会达到这样一个点：即在你不再真正需要探索时仍在进行探索。

所以，如果 `epsilon` 是 `10%`，那么你仍将花费 `10%` 的时间来选择次优臂。

A/B 测试在这里也可能有用，你可以在预定的时间进行测试以检查统计显著性。如果你发现了统计学显著性，可以将 `epsilon` 设置为 `0`，这样你实际上只执行了贪婪部分。

不过，在不久的将来，我们将看到更好的方法来适应我们所学的内容。

## 更新均值

假设我们的奖励不仅仅是硬币掷，所以我们不只需要存储成功和失败的次数。

解决这个问题的通用方法是使用均值。

这对于硬币掷也有效，因为如果你将所有的 `0` 和 `1` 相加并除以 `N`，你就会得到获得 `1` 的最大似然概率。

那么，我们如何计算随机变量的样本均值呢？

我们知道它是总和除以样本数量。

```
Xmean(N) = sum[i=1..N]{ X(i) } / N
```

这个方程有什么问题？

这个方程的问题在于，它需要存储所有的 `N` 个元素才能计算均值。

有没有办法让这种计算更高效？

确实有。

诀窍在于，第 `N` 次样本的均值可以根据第 `(N-1)` 次样本的均值计算出来。

```
Xmean(N) = (1 - 1/N)Xmean(N-1) + (1/N)X(N)
Xmean(N) = Xmean(N-1) - (1/N)[Xmean(N-1) - X(N)]
```

如果你没有立即看出它的原理，请尝试在纸上自己推导一下。

所以这个方程允许我们以计算效率更高的方式计算均值。

记住这种形式的更新方程，它在书的其余部分将非常重要。

## 在代码中比较不同的 epsilon

在这一节中，我们将用代码实现 `epsilon-greedy`，并演示不同 `epsilon` 设置的影响。

如果你不想尝试自己编写代码（尽管我强烈鼓励你这样做），课程仓库中的相关文件是 `comparing_epsilons.py`。

```python
import numpy as np
import matplotlib.pyplot as plt

## represents one bandit arm
class Bandit:
    def __init__(self, m):
        self.m = m # true mean
        self.mean = 0
        self.N = 0

    # simulates pulling the bandit’s arm
    # is a Gaussian with unit variance
    def pull(self):
        return np.random.randn() + self.m

    # this is the update equation we just learned
    def update(self, x):
        self.N += 1
        self.mean = (1 - 1.0/self.N)*self.mean + 1.0/self.N*x

## N = number of times we play
## m1, m2, m3 = mean rewards for the 3 arms
## eps = epsilon for the epsilon greedy strategy
def run_experiment(m1, m2, m3, eps, N):
    bandits = [Bandit(m1), Bandit(m2), Bandit(m3)]

    data = np.empty(N)
    for i in xrange(N):
        # epsilon greedy
        p = np.random.random()
        if p < eps:
            j = np.random.choice(3)
        else:
            j = np.argmax([b.mean for b in bandits])
        x = bandits[j].pull()
        bandits[j].update(x)

        # for the plot
        data[i] = x
    cumulative_average = np.cumsum(data) / (np.arange(N) + 1)

    # plot moving average reward
    plt.plot(cumulative_average)
    plt.plot(np.ones(N)*m1)
    plt.plot(np.ones(N)*m2)
    plt.plot(np.ones(N)*m3)
    plt.xscale('log')
    plt.show()

    for b in bandits:
        print b.mean

    return cumulative_average

if __name__ == '__main__':
    c_1 = run_experiment(m1, m2, m3, eps, N)
```




细节超出了本课程的范围，但该算法与我们看过的其他算法一样简单。

其核心思想是，我们将上置信区间设为 `regular sample mean + sqrt(2 * ln(N) / Nj)`。

`Xmean= Xmean(j)+2ln(N)/Nj`

这等同于“选择”一个等于根号及其内部内容的 `epsilon`。

所以，让我们来聊聊这些符号的含义。

`Xmean(j) = 第 j 个老虎机手臂的常规样本均值`

`N` 是你玩老虎机的总次数。

`Nj` 是你玩第 `j` 个老虎机的总次数。

### 现在我们如何使用这个公式呢？

嗯，这个想法与乐观初始值法类似。

我们只使用贪心策略，但我们贪婪的对象不仅是样本均值，而是样本均值的上置信区间。

问题是，为什么这种方法有效呢？

嗯，这个置信区间看起来是两个东西的比例值：`N`（你玩任何老虎机的总次数）和 `Nj`（你玩第 `j` 个老虎机的总次数）。

所以，如果你玩过其他老虎机很多次，但 `Nj` 很小，那么这个比例 `ln(N)/Nj` 就会很大，导致上置信区间更高，从而导致你选择这个老虎机来玩。

同时，如果 `Nj` 很大，那么比例就很小，此时上置信区间会缩小。

但关于这个比例的一个关键点是，分子是随着 `N` 的对数增长的。这意味着它的增长速度最终会比 `Nj` 慢。

这意味着，随着你玩的老虎机越来越多，上置信区间将会缩小，你将只使用样本均值，这是可以的，因为你收集了大量数据。

所以这也收敛于纯粹的贪心策略。

让我们看一些伪代码，以便更好地理解它的原理。

它本质上和乐观初始值法一样简单。我们只是替换了进入 `argmax` 的公式，现在它变成了上置信区间。

```
for n=1..N:
j = argmax[j’]{ bandit[j’].mean + sqrt(2*ln(n) / n_j) }
pull bandit j
update bandit j
```

注意，当 `n_j` 为 0 时，这个公式有一个无法运行的小问题。为了修复这个问题，你只需要在分母上添加一个小数字即可。

## 贝叶斯 / 汤普采样 (Thompson Sampling)

在本节课程中，我们将讨论我最喜欢的解决探索-利用困境的方法之一，使用贝叶斯方法。

你可能在某些来源中看到这种技术被称为 `Thompson sampling`。

为了引入贝叶斯方法背后的思想，我们想再次查看置信区间或置信边界。

我们直观地知道，从 10 个样本计算出的样本均值没有从 1000 个样本计算出的样本均值准确。

我们可以利用中心极限定理来说，置信区间是“近似高斯分布的”，其真实均值等于随机变量的期望值，方差等于 `variance / N`。

`Xmean ~ Normal(true_mean, variance/N)`
`X ~ Normal(true_mean, variance)`

`Xmean` 具有分布是因为它是随机变量之和。正如你所知，任何随机变量的函数也是随机变量。

贝叶斯范式进一步扩展了这一思想。真实均值（我们称之为 `mu`）不再固定的，`mu` 变成了随机变量。贝叶斯范式的基本思想是数据是固定的，而参数是随机的。

在贝叶斯范式中，参数具有分布，我们想要知道的是给定数据的参数分布。这非常有道理。

给定一些数据，我应该能够根据数据得出一个比没有数据时更准确的分布。我们称之为后验概率：`p(param | data)`

在贝叶斯范式中，关键工具是 `Bayes rule`（贝叶斯公式），因此我们可以翻转后验概率，并从似然概率和先验概率来计算它。

`Likelihood = p(data | param)`
`Prior = p(param)`

贝叶斯方法的一个缺点是我们需要自己选择先验，这有时会对后验概率产生不可忽视的影响。

`p(param | data) = p(data | param) / p(data)`
`p(param | data) 比例于 p(data | param)`

由于 `p(data)` 是对 `p(data | param)` 的积分，分母是一个常数。这个公式存在一些问题。由于它非常通用，分母中的积分并不总是可行。幸运的是，存在特殊的分布集合，使得后验分布与先验分布具有相同的类型。这些被称为 `conjugate priors`（共轭先验）。

让我们做一个短例子，看看如何将共轭先验应用于点击率。我们知道点击率类似于硬币抛掷，因此它们具有 `Bernoulli likelihood`（伯努利似然）。如果你在维基百科上查阅 `Bernoulli likelihood` 的共轭先验，你会发现它是 `Beta distribution`（Beta 分布）。

`Beta distribution` 始终在 0 到 1 之间，它有两个参数 `a` 和 `b`。当我们更新参数时，后验分布将与先验具有相同的分布类型。这就是 `conjugate priors`。



在我的第一门贝叶斯机器学习课程中，你学习了高斯似然分布与均值的高斯先验是共轭的。

如果我们**只**对均值 `mu` 放置先验，并假设方差是固定的，我们可以从这些形式的似然和先验开始。

你可以看到我们正在使用精度参数（precision parameters），它是方差的倒数。这使得数学计算更容易一些。

```
X ~ Normal(mu, tau ^ (-1)),
mu ~ Normal(m, lambda ^ (-1))
```

`mu` 分布的参数是 `m` 和 `lambda`，因此我们寻找的是 `m` 和 `lambda` 的更新方程。

我们可以再次使用贝叶斯公式来求解新的 `m` 和新的 `lambda`：

```
p(mu | X) proportional to p(X | mu)p(mu)
```

你将会发现：

```
lambda’ = lambda + tau*N
m’ = [ m*lambda + tau*sum[i=1..N]{ X(i) } ] / lambda’
```

记住 `N` 是我们收集的样本数量，而 `X(i)` 代表一个样本。

我强烈建议仔细读一遍数学推导，以便你自己自己求解（在这个电子书格式中表示公式是非常困难的）。

---

这一步的最后一步是讨论我们如何将其应用于老虎机问题（bandit problem）。

答案是采样（sampling）。

关键部分再次是选择老虎机的那行代码。

我们不再像在使用 `UCB1` 时那样选择上置信边界的 `argmax`，而是将选择从每个老虎机均值中抽取的样本的 `argmax`。

记住均值现在是概率分布，所以我们可以从中抽取样本。

这如何帮助我们进行探索（explore）和利用（exploit）呢？

嗯，你从之前的演示中看到，分布开始时总是是肥胖的，然后逐渐变得很窄。

当分布很宽时，我们仍很有概率采样到一个非常大的数值，因此当分布很宽时，我们被鼓励更多地探索。

当分布变窄且我们对自己的估计更有信心时，我们就会减少探索并增加利用，因为样本将始终在一个非常窄的范围内。

所以，从贝叶斯后验分布中采样会自动控制我们进行多少探索和利用。

## 汤普斯采样与其他方法的比较

在这一节中，我们将编写一个大脚本来比较所有的探索-利用解决方案。

我们有 4 种技术需要比较：epsilon-greedy（epsilon-greedy）、乐观初始值（optimistic initial values）、`UCB1` 和贝叶斯采样。

由于我们已经知道 epsilon-greedy 一般，我们将对其进行修改。我们的方法是使用衰减 epsilon。具体来说，我们将 `epsilon` 设置为 `1/t`，其中 `t` 是迭代次数。

我们将看到最后这些方法的性能大大相同，这证明了在书中中使用 epsilon-greedy 是合理的。

如果你不想自己写代码（尽管我强烈建议你这么做），课程仓库中的相关文件是 `comparing_explore_exploit_methods.py`。

```python
import numpy as np
import matplotlib.pyplot as plt

class BayesianBandit:
    def __init__(self, m):
        self.m = m
        # parameters for mu - prior is N(0,1)
        self.m0 = 0
        self.lambda0 = 1
        self.sum_x = 0 # for convenience
        self.tau = 1

    def pull(self):
        return np.random.randn() + self.m

    def sample(self):
        return np.random.randn() / np.sqrt(self.lambda0)

    def update(self, x):
        # assume tau is 1
        self.lambda0 += 1
        self.sum_x += x
        self.m0 = self.tau*self.sum_x / self.lambda0

def run_experiment_decaying_epsilon(m1, m2, m3, N):
    bandits = [Bandit(m1), Bandit(m2), Bandit(m3)]

    data = np.empty(N)
    for i in xrange(N):
        # epsilon greedy
        p = np.random.random()
        if p < 1.0/(i+1):
            j = np.random.choice(3)
        else:
            j = np.argmax([b.mean for b in bandits])
        x = bandits[j].pull()
        bandits[j].update(x)

        # for the plot
        data[i] = x
        cumulative_average = np.cumsum(data) / (np.arange(N) + 1)

        # plot moving average ctr
        plt.plot(cumulative_average)
        plt.plot(np.ones(N)*m1)
        plt.plot(np.ones(N)*m2)
        plt.plot(np.ones(N)*m3)
        plt.xscale('log')
```

## 非平稳老虎机

在本节中，我们将讨论非平稳性问题，并更深入地观察之前的一些公式。这对于后续课程非常有帮助，因为相同的公式会反复出现。

那么，什么是非平稳性？

平稳过程是指统计特性不随时间变化的过程。

我们关注的是均值，但严格来说，有不同的平稳类型。

弱平稳是指均值和自协方差不随时间变化。自协方差是一个二阶统计量。

还有强平稳性，即整个概率密度函数（PDF）必须随时间保持不变。这就是我们拥有的平稳性，因为每次你拉动老虎机的手臂时，它的分布都是相同的。

注意，强平稳过程也是弱平稳过程，但反之不然。

问题是，如果老虎机不是平稳的，那么像之前这样计算均值还有意义吗？



回想我们之前的均值更新方程。

`Xmean(t)=(1-1/t)Xmean(t-1) + (1/t)X(t)`

为了方便起见，我们将 `Xmean` 称为 `Q`。我们可以重新排列项，使得 `1/t` 项单独出现。

`Q(t)=Q(t-1) - (1/t)(Q(t-1) - X(t))`, `Q(t) = Xmean(t)`

我们可以进一步泛化此方程，让 `1/t` 项由学习率 `alpha` 表示，这样它看起来有点像梯度下降。

`Q(t) = Q(t-1) - alpha*(Q(t-1) - X(t))`

这个方程的关键在于，我们不需要使用 `alpha = 1/t` 作为学习率。

如果你还记得深度学习第 2 部分，`1/t` 学习率是我们学习过的自适应学习率技术之一。

但学习率可以是任何值。如果我们把 `alpha` 设置为常数呢？这看起来也应该很熟悉。

`Q(t) = (1 - alpha)*Q(t-1) + alpha*X(t)`

这是我们在研究 `Theano scan` 函数作为如何使用 `Theano scan` 的简单示例时看过的。

如果你还没有看过我关于 `Theano scan` 函数的 YouTube 教程，可以免费观看：[`youtu.be/R-7OGU3V4IY`](https://youtu.be/R-7OGU3V4IY)

记住这实现了一个简单的低通滤波器。如果我们去掉递归，就可以用 `X` 的所有过去值来表示 `Q`。

`Q(t) == alpha * sum[k=0..t]{ (1 - alpha)^k X(t - k) }`

从这一点我们可以看出，`Q` 对 `X` 的依赖呈指数衰减。通过这种方式，`Q` 对 `X` 的近期值更侧重点，而不是过去的 `X` 值，所以它就像是一个移动平均，换句话说，是一个低通滤波器。

如果你想运行 `Theano scan` 教程中的低通滤波器，相关文件夹是 `hmm_class`（与本书在同一个仓库），相关文件是 `scan3.py`。

你可以在这里看到，我们从一个非常嘈杂的正弦波开始，经过低通滤波器后，大部分高频噪声消失了。

---

在强化学习文献中，你通常会看到关于 `Q` 收敛性的流行结果。

结果是：如果所有 `alphas` 之和为无穷大，但所有 `alphas` 的平方之和为常数，则 `Q` 将收敛。

`sum[t=1..inf]{ alpha(t) } = inf`

`sum[t=1..inf]{ alpha(t)² } < inf`

如果你回想起微积分 2，从这些标准中可以看出常数 `alpha` 不符合这两个条件，但 `alpha = 1/t` 符合。

你经常看到使用常数 `alpha` 的原因是强化学习问题通常是非平稳的，因此尝试对收集过的每一个样本计算样本均值是没有意义的。

---

让我们做一些简单的题来巩固这个概念。我们已经知道 `1/t` 是收敛的。那么 `alpha(t) = 1/t²` 呢？答案：这不收敛，因为 `alphas` 的和不是无穷大。

那么 `alpha = 1/t^(2/3)` 呢？答案：在这种情况下，将会收敛，因为 `alphas` 的和是无穷大的，但如果我们对 `alpha` 平方，分母的幂将大于 1，因此它收敛到一个常数。

# 井字棋 (Tic-Tac-Toe)

在课程的这一部分，我们将从编程的角度来处理井字棋。大一学生通常刚刚开始学习 `Java` 或 `C++` 等语言的基础知识，而编写像井字棋这样的一个游戏本身就是一个挑战。在本课程中，我们将直接编写所有环境以理解整体框架。系统的每个部分都包括 `agent`（代理）和 `environment`（环境）以及两者之间接口的任何代码。

在下一本书，一旦你更熟悉强化学习的思想，我们将抽象掉环境，使得你无法查看其内部。因此，在讲座中，我们实际上是在看你如何在“上帝模式”（God-mode）下玩井字棋。你了解游戏的一切，所以你永远不会失败。

列出所有这些规则是可能的，但这不是本课程的主题。例如，如果棋盘是空的且轮到你的回合，你希望你的第一步是中心或或角。另一个规则可能是，如果对手在某一行有两个棋子，你想放下自己的棋子来阻挡他们，以免他们获得三个连成线。另一条规则是，如果你看到自己的两个棋子连在一起且没有被阻挡且轮到你的回合，你应该完成该行以赢得游戏。

这在代码中看起来是什么样的？本质上它将是一堆 `if` 语句。一堆 `if` 语句有什么问题呢？嗯，它违背了机器学习的整个理念。也就是说，我们希望有一个可以泛化到许多问题的算法。就像我们可以使用神经网络对动物图片进行分类，也可以训练相同的算法对音乐进行分类。如果我们写一个由 `if` 语句组成的井字棋代理，该程序将永远无法做除井字棋之外的任何事情。所以我们需要更好的东西，这就是为什么我们想要学习强化学习。

这其中的一个重要方面是，我们有一个关于游戏如何运作的模型。我们了解井字棋的一切。我们知道什么状态会导致最高奖励。换句话说，任何你有三个棋子连成的状态，你都会获得一个赢得游戏的奖励，否则你就会失败或一无所获。我们知道如何从一个状态转换到下一个状态。换句话说，通过执行某些 `action`（动作），给定当前状态确切知道下一个状态是什么。这似乎是显而易见的，但在某些环境中并非如此。在井字棋中，我们在棋盘上放置一个棋子，棋子会进入我们选择的位置，我们到达预期的下一个状态。情况并不总是如此。

这些想法稍后会发挥作用，但我建议现在就开始思考它们。你会发现，我们学习的某些算法要求我们拥有环境的模型，就像我们在井字棋中那样。其他算法不需要我们知道任何事情，我们将在探索中获取信息。

## 强化学习系统的组件

在本节中，我们将定义强化学习系统的组件。起初这可能看起来有些重复，因为我们在介绍部分已经做过这些，但你会注意到，随着书中不断深入，我们每次都会查看相同的概念，但会使其更加严谨。我们每次还会添加更多组件，所以每次你将在之前知识的基础上学习一些新术语。

在本节中，我们将再次查看一些你已经熟悉的概念：

- `agent`（代理）：是玩游戏的实体，也是你想要编写强化学习算法的对象。
- `environment`（环境）：是 `agent` 交互的实体。它是 `agent` 的世界。
- `state`（状态）：是 `agent` 感知的环境特定配置。

注意，`state` 只涉及 `agent` 可以感知到的内容，而不是环境的一切。例如，如果我在澳大利亚有一个扫地机器人在清理房子，那么印度别人家里发生的事情都不会影响我的扫地机器人的 `state`。

另一个例子是，如果你有一辆自动驾驶汽车，它对周围的一切都有 360 度的视野。在你面前有一辆卡车，卡车前面还有一辆车，那么那辆车就不属于你的 `state`，因为你看不见。所以，无论那辆车是否在你面前卡车的前面，你的 `state` 都是相同的。



最后，我们来看下动作和奖励。

### 动作 (Actions)
动作是智能体可以执行并影响其状态的操作。在我们的井棋游戏中，动作就是在棋盘上落一个棋子。

执行动作总是会带我们进入下一个状态，该状态也伴随着一个可能的奖励。

---

奖励的一个方面是，奖励仅仅是告诉你你的动作“有多好”，而不是它是否是一个正确/错误的动作。它并不会告诉你这是否最好/最坏的动作。它仅仅是一个数字。

所以，如果你是一个智能体，你在存续期间获得的奖励并不一定代表你未来可能获得的奖励。

你可能正在搜索状态空间中一个糟糕的部分，并碰到了 `10` 分的局部最大值，而全局最大值是 `1000` 分。

但如果你是那个智能体，你永远无法得知这一点。我们之所以知道，是因为是我们设计了这个游戏。这又是一个“上帝视角（God-mode）”知识的实例。

---

这与动物或人类的生活非常相似。你出生在一个特定的环境中，过着日常例常。你可能会发现一些让你快乐的事物，并可能将其视为一种局部最大奖励。

但如果那个人生活在一个没有现代医学或技术的地方，而你将其与现代文明的现代生活进行比较，你会发现局部最大值远不是全局最大值。

所以一切都是相对的，奖励是某种无意义的数字，它们只有在相互比较时才有意义。

在强化学习中，奖励多总比奖励少好。

---

现在这里有一些有趣的符号表示。

我们知道，处于状态 `S(t)` 并采取动作 `A(t)` 将引导我们获得奖励 `R(t+1)` 和状态 `S(t+1)`。

但当我们舍弃时间索引时，我们将这个四元组表示为 `(s, a, r, s’)`。我们没有像你可能的那样给 `r` 加撇号（prime），这很奇怪，但它是标准的表示法。

所以，撇号并不代表“在时间=t+1”。

---

现在我们要定义一些新术语。

### 回合 (Episode)
我们要讨论的第一个新术语是“回合”。

一个回合代表游戏的一次运行。

例如，我们将从一个空棋盘开始一局井棋游戏。

一旦一名玩家有 `3` 个棋子连线，该回合就结束了。

你可以想象到，我们的强化学习智能体将在许多回合中不断学习。

例如，在玩了 `1000` 或 `10,000` 或 `100,000` 个回合后，我们可能训练出一个智能智能体。

这需要多长时间当然取决于超参数，这取决于所玩的游戏、状态的数量、游戏的随机程度等。

如果你以前上过深度学习课程，你应该对超参数已经熟悉了。

---

我们将玩井棋游戏称为“回合任务（episodic task）”，因为你可以反复玩。

这与永不结束的“连续任务（continuous task）”不同。在某种程度上，你只玩一次那种游戏。

我们在书中将不会涉及连续任务。

### 终端状态 (Terminal States)
我们如何知道处于一个回合的“结束”？状态空间中存在某些状态可以告诉你游戏已经结束。

对于井棋来说，当 `2` 名玩家之一有 `3` 个棋子连线，或者棋盘满员时，游戏结束。

这些状态被称为“终端状态”。

所以，“终端状态”是一个你无法再采取更多动作的状态。这意味着回合结束了。

对于井棋来说，这意味着玩家 1 获胜、玩家 2 获胜，或者是平局。

---

强化学习和控制系统中的另一个著名问题是倒摆问题（inverted pendulum），在控制系统中它被称为倒摆，在强化学习中它被称为小车倒立摆（cart-pole）。它们是同一个问题。

如果你在 Google 上搜索“inverted pendulum”，你会看到控制系统领域的论文；如果你在 Google 上搜索“cart-pole”，你会看到看到强化学习领域的论文。

在一个回合的开始时，小车是静止的，杆子垂直于地面。但由于这是一个不稳定系统，小车是静止的，杆子垂直于地面。



想象这样一个场景。

你正在考虑为明天的考试复习。但你更想和朋友一起出去玩。

你的朋友会让你感到快乐，对你来说这就是一种奖励。你会获得多巴胺的刺激。

如果你今晚学习，你会感到疲惫和无聊，也许你的多巴胺会减少，所以这某种程度上是一种负奖励。

那么，我们为什么要为了考试学习呢？

因为我们不仅考虑即时奖励，还会根据未来奖励制定行动计划。

如果你学习，你的考试就会考好，获得好成绩，并找到一份薪水不错的工作。

所以，我们想要为这种状态：你留在家里为考试学习分配一些价值。

我们称之为**价值函数（value function）**，这就是我们在这一节要讨论的内容。

---

现在让我们反过来来考虑这个问题。

你获得了一个奖励，比方说是被录入了梦想中的工作。

现在，如果你回顾自己在职业生涯和学校期间所做的各种事情，你会将你的成功归功于什么？

你过去的哪种状态导致了你今天获得了梦想中的工作？

**归因分配问题（credit assignment problem）**是指解决以下问题：

你过去的哪种行为导致了你现在收到的奖励？

---

归因分配问题也出现在在线广告中，但形式略有不同。在在线广告中这被称为“归因（attribution）”。

其核心是，如果用户最终转化并购买了你的产品，在不同的广告展示中，谁应该得功？

分配功劳有各种方案，比如线性分配。

但你可以看到，对我们来说这是一个更深层次的问题。也许用户只看了前 9 次广告，在第 10 次时才购买。所以从这个意义上说，第 10 次广告应该得功。

在强化学习中，我们关注的是整个状态序列以及该序列是如何导致最终奖励的。

延迟奖励（Delayed Rewards）

与归因分配问题密切相关的是“延迟奖励”的概念。

请记住，这些只是描述同一种问题的不同方式，而且解决方案也是一样的。

延迟奖励是从另一个角度来看问题的。

在归因分配中，我们回顾过去：做了什么导致了我们现在收到的奖励？

在延迟奖励中，我们问：我正在做的动作与未来可能收到的奖励有什么关系？

延迟奖励的想法告诉我们，AI 需要具备预见未来的能力，即“规划”。

---

想象这样一个场景。你处于状态 `A`，这是游戏的最后状态。只有两个可能的后续状态：`B` 或 `C`，它们都是终止状态。

```
oA
0.5 / 0.5
/ \
oB oC
R=1 R=0
```

B 给你奖励 1，而 C 给你奖励 0。你有 50% 的概率进入其中一个状态，因为你的智能体还不知道哪一个最好。

我们可以把状态 `B` 的价值看作 1，状态 `C` 的价值看作 0。

状态 `A` 的价值是多少？

我们可以将其看作 0.5，因为你有 50% 的机会进入终止状态。

---

假设你处于状态 `A`，状态 `A` 只能到达状态 `B`，没有其他可能的后续状态。

如果 B 给你奖励 1，那么 `A` 的价值也应该是 1，因为唯一能到达的地方是奖励为 1 的 B。

```
oA
1 / 0
/ \
oB oC
R=1 R=0
```

因此，这个价值告诉我们一个状态的“未来好程度”。

---

为了更正式一点，我们实际上将这种价值称为**价值函数（value function）**。

它是我们可能获得的未来奖励的衡量。

我认为“价值（value）”这个词很糟糕，因为它非常模糊，但它是强化学习术语的一部分。

---

奖励和价值是混合在一起的。区别在于，状态的价值是处于该状态后可能获得的未来奖励的衡量。

奖励是即时的。即跳过障碍会立即增加你的分数。

站在障碍面前不会增加你的分数，因此不会产生任何奖励。然而，处于这个状态是有价值的，因为我们可以很快跳过去并在未来获得奖励。

---

所以，在障碍附近准备跳可能比站在障碍边缘具有更高的价值。因此，我们根据下一个状态的价值来选择动作，而不是进入该状态所获得的奖励。

奖励是主要目标，但我们无法用奖励来告诉我们状态有多好，因为它没有告诉我们任何关于未来的信息。

---

思考价值函数的一种方式是，它是一种快速或高效的方法，用来确定处于某个状态“有多好”，而不需要搜索整个游戏树。

你可以尝试列举游戏中每一个可能的状态转换并确定所有的状态转换概率，但你可以想象这将是一项耗时的任务。

事实上，大多数游戏在计算上是不可行的。井棋很容易处理，因为它只有 3x3 的棋盘，所以状态数约为 `3⁹ = 19683`。但它随着棋盘的大小呈指数级增长。例如，如果你有一个 4x4 的棋盘（如连棋），那么你会得到 `3¹⁶ = 4300 万。你可能已经知道指数级增长永远不是好事。搜索状态空间只在最简单的情况下可行。因此，一个仅根据当前状态就能告诉你未来表现如何的价值函数是非常有的。

到此为止，我还没有告诉你们如何实际上找到价值函数，所以我们甚至不知道是否可行，但我们在这里说的是，如果我们拥有了它，那就是它能告诉我们的信息，它可以立即告诉我们信息，而无需创建整个游戏树和转换概率模型。

事实上，这是一个常数时间查找，因为状态直接映射到一个值。你可能会将值存储在一个具有常数时间查找的数组中。

顺便说一下，这个问题是“维度灾难”的另一个实例，我们在我的机器学习课程中也见过它。

---

估计价值函数是强化学习中的核心任务。但请注意，并不是所有的 RL 策略都需要它。例如，遗传算法只需产生具有随机基因突变的后代，活得最长的那些将在下一代继续产生后代。所以，通过纯的演化或自然选择，我们可以培育出在游戏中变得越来越好的 AI。

然而，这通常不是我们强化学习所感兴趣的算法类型。

---

让我们来看数学部分。

正如我们讨论过的，价值函数接受一个参数：状态。所以我们将其标记为 `V(s)`。

它是给定当前状态为 `s` 的情况下，所有未来奖励的期望值。换句话说，给定当前状态为 `s` 的情况下，所有可能的未来奖励的平均值。

`V(s) = E[all future rewards | s]`

非常简单。

我们将在稍后的章节中更严谨地定义价值的概念。

---

现在让我们来看一种可以用来找到价值函数的通用算法。




在本本书的这一章节，我们将引入一些不现实的限制，以便问题能够被解决，但你将在后面的章节中看到我们并不需要这样做。

我们将使用的算法是一种迭代算法，这意味着我们将运行一个循环，并且每次通过循环时，都会越来越接近真实的价值函数。

我们做的第一件事是初始化价值函数。对于智能体胜利的所有状态，我们认为其值为 1。对于智能体失败或平局的所有状态，我们认为其值为 0。对于所有其他状态，我们认为其值为 0.5。

### `init`

`V(s) = 1 if s = winning state`

`V(s) = 0 if s = losing state or draw`

`V(s) = 0.5 otherwise`

对于我们未来将看到的算法，我们不需要进行如此仔细的初始化。

理解价值函数的一种方法（仅适用于此游戏，而不通用）是：它是获胜的概率。

值始终在 0 和 1 之间，所以这是有意义。

---

更新方程看起来很简单，但包含一些隐藏的细节。

`V(s) = V(s) + alpha*(V(s’)-V(s))`

### `s = current state, s’ = next state`

第一个细节是，这里的 `s` 指我们在一个回合（episode）中遇到的所有状态。

这意味着对于循环的每次迭代，我们实际上需要玩一次游戏并记住我们所处的每个状态。

然后我们遍历状态历史中的每个状态，并使用这个方程更新价值。

注意，终止状态（terminal state）的值永远不会被更新，因为这个方程根据下一个状态的值来更新当前状态的值，而如果我们处于终止状态，则下一个状态是不存在的。

`i.e. if s = terminal, then s’ doesn’t exist`

---

在伪代码中它可能像这样：

```python
for t in range(max_iterations):
    state_history = play_game()
    s = state_history[0]
    for s’ in state_history[1:]:
        V(s) = V(s) + learning_rate*(V(s’) - V(s))
```

---

我们必须讨论的下一个细节是实际上如何玩游戏。

我们仅仅是采取随机动作吗？

在这种情况下，我们不必这样做，因为我们已经有了价值函数。

价值函数告诉我们一个状态的好坏取决于未来状态的好坏，所以我们所做的就是执行通往最佳下一个状态的动作。

在伪代码中它可能像这样：

```python
maxV = 0
maxA = None
for a, s’ in possible_next_states:
    if V(s’) > maxV:
        maxV = V(s’)
        maxA = a
perform action maxA
```

---

现在这个策略有什么问题呢？

问题在于价值函数是不准确！如果我们已经有了一个准确的价值函数，从一开始我们就不需要进行这些工作。

你可能认出这是我们已经讨论过的问题。它是探索与利用的困境（explore-exploit dilemma）。

特别是，通过采取随机动作，我们可以学习到否则永远不会去的新状态。

通过这样做，我们可以改进对那些状态的价值函数的估计。

但为了获胜，我们需要执行产生最大价值的动作。

所以，我们将使用 epsilon-贪婪策略（epsilon-greedy strategy）在探索和利用之间进行权衡。

---

让我们来看看为什么这种迭代更新有效的直观理解。

首先，你会认出之前的这个更新方程。它应该让你想起之前见过的低通滤波器和迭代平均值求解方程。

如果你以前遇到过梯度下降，它看起来也像梯度下降。`V(s’)` 就像是目标值，我们想让 `V(s)` 向该值移动。

然而，在强化学习中存在多个可能的下一个状态，因此有多个 `s’`。

因此，通过多次执行这个更新方程，我们为每个不同的 `s’` 将 `V(s)` 拉向多个不同的方向。

这种想法是，通过玩无限的回合，我们花费在 `s’`上的时间比例将接近真实的下一个状态概率。

随着游戏次数趋于无穷大，我们实现了精确的期望值：

`p(s1)*V(s1) + p(s2)V(s2) + ...`

---

另一个极其重要的、且仅凭更新公式极难察觉的细节是，你必须更新任何给定状态价值的顺序。

我们知道，对于任何特定的回合，我们只会更新出现在该回合中的状态值。

但这个方程的关键在于，我们正在让 `V(s)` 靠近 `V(s’)`。

这意味着我们是在假设 `V(s’)` 比 `V(s)` 更准确的情况下进行这种更新。

对于终止状态，这是正确的，因为那总是 0 或 1 且永远不会改变。

但如果 `V(s)` 和 `V(s’)` 的准确性相同，也就是说它们完全都不准确，那么让其中一个靠近另一个就没有意义了。


请记住，这个解决方案并非唯一，而且事实上，对象之间存在一些糟糕的耦合，这些可能并不是最优的。

所以，如果你自己尝试实现它，很有可能你的解决方案看起来会完全不同，但只要它运行良好就没关系。

如果你不想跟着代码一起编写，只想直接运行代码，课程仓库中的相关文件是 `tic_tac_toe.py`。

## 高级设计 (High Level Design)

在高级层面上，我们将有两个主要对象：智能体（Agent）和环境（Environment）。

`Agent <-----> Environment`

`play_game(agent1, agent2, environment)`

在任何游戏过程中，会有 2 个智能体对象实例，它们都将与同一个环境实例进行交互。

为了让这些内容产生交互，我们可以创建一个名为 `play_game()` 的函数，它接受玩家 1 的智能体、玩家 2 的智能体以及环境对象。

---

那么，`play_game()` 函数内部应该放什么呢？

首先是代码，然后是讨论。

```python
def play_game(p1, p2, env, draw=False):
    # 循环直到游戏结束
    current_player = None
    while not env.game_over():
        # 在玩家之间切换
        # p1 总是先行
        if current_player == p1:
            current_player = p2
        else:
            current_player = p1

        # 在想要查看视图的用户移动之前绘制棋盘
        if draw:
            if draw == 1 and current_player == p1:
                env.draw_board()
            if draw == 2 and current_player == p2:
                env.draw_board()

        # 当前玩家执行动作
        current_player.take_action(env)

        # 更新状态历史
        state = env.get_state()
        p1.update_state_history(state)
        p2.update_state_history(state)

        if draw:
            env.draw_board()

        # 执行价值函数更新
        p1.update(env)
        p2.update(env)
```

在这个函数内部，本质上是一个单一循环。我们会在 2 个玩家之间切换，在循环的每次迭代中，我们需要完成几项操作。

首先，我们需要让当前玩家执行一个更新环境的动作。

其次，我们需要切换当前玩家，以便进行交替。

第三，我们需要检查游戏是否结束，因为循环会在结束时终止。

所以你可以看到，我们在这里为我们的对象可能需要的某些实例方法创建了一个部分 API。

环境需要一个 `game_over()` 函数，它返回一个布尔值：如果游戏结束则返回 true，否则返回 false。你可以想象，这个函数将必须扫描棋盘以检查是否有胜者，或者棋盘是否已填满导致平局。

智能体需要一个 `take_action()` 函数，它接受环境作为参数。这将更新环境，从而更新状态。

我们在智能体上需要的另一个函数是 `update()` 函数，它用于更新该智能体对价值函数的内部估值。这就是我们讨论过的更新方程将所在的地方。`update()` 函数也需要接受环境，因为它必须从环境中查询最新的奖励。

另一个对我们非常有有用（但不是严格必须）的函数是 `draw_board()` 函数，它将显示当前哪些位置被占据，以及被什么种棋子占据。

## 表示状态 (Representing States)

在这一节中，我们将讨论如何在井跳棋游戏中表示状态。



所以你将看到的状态总数为 $9! = 362,880$。

这比 $3⁹ = 19683$ 大了几个数量级。

因此，我们想要用于枚举所有状态的算法绝对只是生成排列。

---

好了，那么我们如何生成排列呢？

再次想一下一个二进制数。

这本质上是一个递归问题，因为长度为 $N$ 的二进制数可以 $0$ 或 $1$ 开头，然后可以在后面加上长度为 $N-1$ 的二进制数的所有排列。

`长度为 N 的所有排列 =`
`[1] + 长度为 N-1 的所有排列`
`[0] + 长度为 N-1 的所有排列`

---

在伪代码中，我们可以这样做。首先，我们获取递归结果，即所有长度为 $N-1$ 的二进制数。我们在循环外执行操作，因为执行多次是冗余的。在外层循环中，我们遍历所有可能的前缀；在内层循环中，我们遍历所有的子结果。在循环内部，我们通过组合前缀和后缀来创建新结果，并将其添加到我们的结果列表中。

为了简单起见，我在这里没有展示基础（base case）。

```python
def generate_all_binary_numbers(N):
    results = []
    child_results = generate_all_binary_numbers(N-1)
    for prefix in ('0', '1'):
        for suffix in child_results:
            new_result = prefix + suffix
            results.append(new_result)
    return results
```

---

这只是通用的排列方法的一个例子。对于我们来说，情况会略有不同。

我们将有一个名为 `get_state_hash_and_winner` 的递归函数，它将返回一个三元组列表。每个三元组将包含：哈希后的状态数值、胜者是谁（如果有），以及该状态是否代表游戏已结束。

该函数的 3 个参数是 `env`（我们只需要它的棋盘矩阵），以及用于放置下一个值的 `(i, j)` 坐标，值可以是 $0$（空）、`"X"` 或 `"O"`。

---

```python
def get_state_hash_and_winner(env, i=0, j=0):
    results = []
    for v in (0, env.x, env.o):
        env.board[i,j] = v # 如果是空盘，它应该是 0
        if j == 2:
            # j 回到 0，增加 i，除非 i = 2，则我们完成了
            if i == 2:
                # 棋盘填满了，收集结果并返回
                state = env.get_state()
                ended = env.game_over(force_recalculate=True)
                winner = env.winner
                results.append((state, winner, ended))
            else:
                results += get_state_hash_and_winner(env, i + 1, 0)
        else:
            # 增加 j，i 保持不变
            results += get_state_hash_and_winner(env, i, j + 1)
    return results
```

在这个函数里将向你们展示基础。如果 $i=2$ 且 $j=2$，那么我们正在填充棋盘上的最后一个位置，这意味着我们现在应该检查游戏状态、胜者是谁以及游戏是否结束。

注意，尽管我是在说棋盘现在被“填满了”，但我的意思是它也可以被 $0$ 值（代表空）填满，所以这并不意味着游戏结束，仅仅意味着排列完成。

现在，如果不是基础，我们想要递归地调用此函数，但有两个数字可以增加：`i` 或 `j`，但绝不能同时增加。

如果我们在一行的末尾（意味着 $j=2$），我们就想要跳转到下一行的第一列，所以设置 `j=0` 并增加 `i`。

如果不在一行的末尾，我们只需增加 `j` 并保持 `i` 不变。

---

最后，我想指出，两名玩家的初始值函数是不等价。

记住，一个玩家必须是 `"X"`，另一个玩家必须是 `"O"`。

所以，如果 `"X"` 的价值函数为 $1$（X 胜），那么对于 `"O"` 来说就是 $0$（O 输），反之亦然。但它们并不完全相反，因为如果是平局，两个玩家都会得到 $0$。

所以我们将有两个几乎相反的函数：`initializeV_x` 和 `initializeV_o`。

`state_winner_triples = get_state_hash_and_winner(env)`

```python
def initialV_x(env, state_winner_triples):
    # 初始化状态值如下：
    # 如果 x 胜，V(s) = 1
    # 如果 x 输或平局，V(s) = 0
    # 否则，V(s) = 0.5
    V = np.zeros(env.num_states)
    for state, winner, ended in state_winner_triples:
        if ended:
            if winner == env.x:
                V[state] = 1
            else:
                V[state] = 0
        else:
            V[state] = 0.5
    return V
```



接下来是奖励函数。

正如我们之前所说的，如果我们赢了游戏，奖励为 1，否则奖励为 0。

```python
def reward(self, sym):
    # 在游戏结束之前没有奖励
    if not self.game_over():
        return 0

    # 如果我们到了这里，说明游戏结束了
    # sym 将是 self.x 或 self.o
    return 1 if self.winner == sym else 0
```

强化学习的定义是：在每一个状态转换时都会给予奖励作为反馈，因此我们需要这个函数能够在任何情况下返回一个有效的结果，这就是为什么我们不能只在游戏结束时才调用它。

当智能体调用 `reward(self, sym)` 时，它需要传入自己的 `sym`，这告诉我们每个智能体都需要知道自己的符号。

## 更复杂的函数

现在我们来看更复杂的函数。

实际上，在课程早些时候讨论枚举状态时，我们已经见过 `get_state` 了。

```python
def get_state(self):
    k = 0
    h = 0
    for i in xrange(LENGTH):
        for j in xrange(LENGTH):
            if self.board[i,j] == 0:
                v = 0
            elif self.board[i,j] == self.x:
                v = 1
            elif self.board[i,j] == self.o:
                v = 2
            h += (3**k) * v
            k += 1
    return h
```

这个想法是：如果我们将状态按三进制数字进行排序，那么整个结构就是一个三进制数，我们可以将其转换为一个十进制数。

---

接下来是 `game_over()` 函数。这可能是 `environment` 类中是最复杂的函数了。

```python
def game_over(self, force_recalculate=False):
    # 如果游戏结束（某玩家获胜或平局）返回 true
    # 否则返回 false
    # 同时设置 'winner' 实例变量和 'ended' 实例变量
    if not force_recalculate and self.ended:
        return self.ended

    # 检查行
    for i in xrange(LENGTH):
        for player in (self.x, self.o):
            if self.board[i].sum() == player*LENGTH:
                self.winner = player
                self.ended = True
                return True

    # 检查列
    for j in xrange(LENGTH):
        for player in (self.x, self.o):
            if self.board[:,j].sum() == player*LENGTH:
                self.winner = player
                self.ended = True
                return True

    # 检查对角线
    for player in (self.x, self.o):
        # 左上 -> 右下对角线
        if self.board.trace() == player*LENGTH:
            self.winner = player
            self.ended = True
            return True
        # 右上 -> 左下对角线
        if np.fliplr(self.board).trace() == player*LENGTH:
            self.winner = player
                self.ended = True
                return True

    # 检查是否平局
    if np.all((self.board == 0) == False):
        # 胜利者保持为 None
        self.winner = None
        self.ended = True
        return True

    # 游戏未结束
    self.winner = None
    return False
```

这里有一个可能会好奇的 `force_recalculate` 参数。

首先，你会注意到 `game_over` 在此脚本中被多次调用。如果游戏已经结束，我们不想反复地进行这个复杂的操作，所以我们直接利用它已经结束这一事实作为快捷径。

但如果你记得我们之前枚举状态的递归函数，我们递归地填充了棋盘上的每个位置。这涉及到在棋盘上放置棋子、取出棋子、放置其他棋子等。因此我们会在游戏结束状态和非结束状态之间来回，这意味着我们不能使用那个快捷径。

所以 `force_recalculate` 让我们确保每次都执行整个操作（如果我们需要的话）。

`game_over()` 函数的后续部分正如预期：我们检查是否有胜利者，如果没有胜利者，我们检查棋盘是否填满（这意味着平局）。

我们通过先检查所有行，然后是所有列，最后是对角线来判断是否有胜利者。

将 `X` 和 `O` 的值赋值为 `-1` 和 `+1` 真的非常有帮助。因为如果某行有 3 个 `X`，总和将是 `-3`；如果有 3 个 `O`，总和将是 `+3`。

如果我们找到了胜利者，就会将 `winner` 实例变量设置为获胜的玩家，并将 `ended` 实例变量设置为 `true`。我们还返回 `true`，因为 `game_over()` 函数需要返回一个布尔值。

唯一有点复杂的地方在于检查对角线时。

我们知道矩阵的 `trace`（迹）是主对角线上所有元素之和。

## 智能体 (Agent)

在这一部分我们将讨论另一个主要类：`Agent`。

到目前为止我们知道它是 AI。

这与普通的机器学习不同，因为在这种情况下我们不仅仅是提供数据。

相反，智能体必须与环境交互，这是我们刚刚讨论过的。我们的学习算法只是智能体的一小部分，但它负责了 100% 的智能。

---

让我们概述我们将查看的所有实例方法。

首先是 `setV(V)`，它允许我们初始化价值函数。如所知，价值函数将以非常特定的方式初始化。

有 `set_symbol(sym)`，允许我们给这个智能体一个它在棋盘上使用的符号。

有 `set_verbose(b)`，接收一个布尔值。顾如其名，如果 `b` 被设置为 `true`，就会打印更多信息。例如，在智能体移动之前，它会打印棋盘以及每个可能的价值。

有 `reset_history()`。我们需要它是因为我们想要跟踪每个回合的状态历史，但一旦回合结束且学习完成，我们就不再需要该状态历史，可以开始新回合。

有 `take_action(env)`，接收环境作为输入。它将检查棋盘的有效移动并根据策略做出移动，如果你记得我们在在这个游戏中使用 epsilon-贪婪策略。

有 `update_state_history(s)`，它将状态添加到状态历史中。我们不想将其放在 `take_action` 函数中，因为我们只每隔一个回合调用 `take_action`，而状态历史需要在任何玩家移动时都更新。

最后是 `update(env)` 函数，它也接收环境作为输入。它查询环境获取最新的奖励，由于我们只会在回合结束时调用 `update()`，因此这将对应于回合的结束。这是所有学习发生的地方。

---

这前 5 个函数非常简单。

```python
class Agent:
def __init__(self, eps=0.1, alpha=0.5):
```




```python
self.eps = eps # 选择随机动作而非贪婪动作的概率

self.alpha = alpha # 学习率

self.verbose = False

self.state_history = []

def setV(self, V):
    self.V = V

def set_symbol(self, sym):
    self.sym = sym

def set_verbose(self, v):
    # 如果为真，将打印棋盘上每个位置的值

    self.state_history = []
```

构造函数设置了 `epsilon`，这是实现 epsilon 贪婪策略所需要的。它设置了 `alpha`，即我们更新方程中的学习率。它设置了默认为 False 的 `verbose`，并如你所预期的那样将状态历史设置为空空列表。

`SetV`、`set_symbol` 和 `set_verbose` 是简单的 setter 方法。

`reset_history()` 只是将状态历史重置为空列表。

```python
def take_action(self, env):
    # 根据 epsilon-贪婪策略选择动作
    r = np.random.rand()
    best_state = None
    if r < self.eps:
        # 采取随机动作
        if self.verbose:
            print "正在采取随机动作"

        possible_moves = []
        for i in xrange(LENGTH):
            for j in xrange(LENGTH):
                if env.is_empty(i, j):
                    possible_moves.append((i, j))
        idx = np.random.choice(len(possible_moves))
        next_move = possible_moves[idx]
    else:
        # 根据状态的当前值选择最佳动作
        # 遍历所有可能的移动，获取它们的值
        # 记录最大值
        pos2value = {} # 用于调试
        next_move = None
        best_value = -1
        for i in xrange(LENGTH):
            for j in xrange(LENGTH):
                if env.is_empty(i, j):
                    # 如果我们移动这一步，状态会是怎样的？
                    env.board[i,j] = self.sym
                    state = env.get_state()
                    env.board[i,j] = 0 # 忘记改回来！
                    pos2value[(i,j)] = self.V[state]
                    if self.V[state] > best_value:
                        best_value = self.V[state]
                        best_state = state
                        next_move = (i, j)

        # 如果开启详细模式，则带有数值绘制棋盘
        if self.verbose:
            print "正在采取贪婪动作"
            for i in xrange(LENGTH):
                print "-----------------"
                for j in xrange(LENGTH):
                    if env.is_empty(i, j):
                        # 打印值
                        print "%.2f|" % pos2value[(i,j)],
                    else:
                        print " ",
                    if env.board[i,j] == env.x:
                        print "x |",
                    elif env.board[i,j] == env.o:
                        print "o |",
                    else:
                        print " |",
                    print ""
            print "-----------------"

    # 执行移动
    env.board[next_move[0], next_move[1]] = self.sym
```

记住我们正在执行 epsilon 贪婪策略。所以以 `epsilon` 的概率，我们将执行随机动作。

现在，为了采取随机动作，我们需要创建一个所有可能的移动的列表。这等同于棋盘上所有 `is_empty` 返回 True 的位置，由于我们传入了环境，我们可以调用它。

一旦我们有了可能的移动列表，就会以均匀概率选择其中一个。

接下来是 epsilon 贪婪策略中的贪婪部分。

在最简单的形式中，我们需要做的与随机策略非常相似。我们将遍历棋盘上的所有位置，检查它是否为空，如果为空，则检查它的值。

如果它的值大于我们当前的最大值，我们就记录这个值和这个位置，将其变为新的最大值。

完成这些后，我们就可以在选定的位置上放置自己的符号。

```python
def update(self, env):
    # 遍历 state_history
    # 每一个状态
    # 计算 target 值
    # 更新 V[state]
    for state in reversed(self.state_history):
        target = env.reward
        if env.winner == state:
            target = 1
        elif env.draw:
            target = 0.5
        else:
            target = 0
        self.V[state] += self.alpha * (target - self.V[state])
```

在网格世界中，你的 `agent` 是机器人，而环境正如你可能猜的那样，是一个网格。

```
+-----+-----+-----+-----+

+-----+-----+-----+-----+
2|start| | | |
+-----+-----+-----+-----+
```

在位置 `(1, 1)` 处有一个 `wall`（墙），所以机器人不能去那里。如果它尝试去那里，只会撞到 `wall`。

## 马尔可夫属性 (Markov Property)

在本节中，我们将讨论马尔可夫属性。从名称可以看出，马尔可夫属性是马尔可夫决策过程的核心组件。

我们之所以花整节课讨论马尔可夫属性，是因为在强化学习的语境下，它看起来与我们过去看到的有所不同。

---

让我们从严格的数学意义上回顾马尔可夫属性。

假设我们有一个从 `x(1)` 到 `x(t)` 的序列。

```
{x(1), x(2), ..., x(t)}
```

我们可以根据所有之前的 `x` 来定义 `x(t)` 的条件概率。

`p(x(t) | x(t-1), x(t-2), ..., x(1))`

通常情况下，这是无法简化的。

但如果我们假设马尔可夫属性成立，那么它可以简化的。

一阶马尔可夫：

`p(x(t) | x(t-1), x(t-2), ..., x(1)) = p(x(t) | x(t-1))`

二阶马尔可夫：

`p(x(t) | x(t-1), x(t-2), ..., x(1)) = p(x(t) | x(t-1), x(t-2))`

马尔可夫属性（阶）规定了当前的 `x` 取决于多少之前的 `x`。

一阶马尔可夫意味着 `x(t)` 只依赖于 `x(t-1)`。二阶马尔可夫意味着 `x(t)` 依赖于 `x(t-1)` 和 `x(t-2)`。在本课程中，我们将仅处理一阶马尔可夫，并通常将其称为马尔可夫属性。

---

让我们来看马尔可夫属性的一个简单例子。

考虑句子：“马尔可夫属性是”。如果我告诉你：“这些是之前的词，预测下一个词”。你可能猜下一个词是“属性”。现在我说：“之前的词是”，你能预测下一个词吗？可能可以，但更难。

如果之前的词只是“属性”，你能预测下一个词吗？可能不能。但这就是马尔可夫假设。

所以你会发现马尔可夫假设可能是很有局限性的，但你也可以定义你的问题使其不受此限制。

---

那么在强化学习中，马尔可夫属性是什么样子的？

记住，在状态 `S(t)` 下执行动作 `A(t)` 会产生两个结果。它产生下一个状态 `S(t+1)` 和一个奖励 `R(t+1)`。在这种情况下，马尔可夫属性说的是 `S(t+1)` 和 `R(t+1)` **仅**依赖于 `A(t)` 和 `S(t)`，而不依赖于之前的任何 `A` 或 `S`。

`p(S(t+1),R(t+1) | S(t),A(t),S(t-1),A(t-1),...,S(1),A(1)) = p(S(t+1),R(t+1) | S(t),A(t))`

为了方便，我们也可以使用我们的简写符号 `s`、`a`、`r` 和 `s'`。

`p(s',r | s,a) = p(S(t+1)=s',R(t+1)=r | S(t)=s,A(t)=a)`

这与我们“通常”编写马尔可夫属性的方式何不同？

注意这是 `s'` 和 `r` 的联合分布。所以它告诉我们在给定另外两个变量的情况下，这两个变量的联合分布。

---

给定这个联合分布，当然只是使用概率规则寻找边缘条件分布的问题。例如，如果我们只想知道在给定 `s` 和 `a` 的情况下 `s'`，可以使用这些方程：

`p(s' | s,a) = integral{p(s',r | s,a)}dr`

`p(r | s,a) = sum{p(s',r | s,a)}`

（假设 `r` 是连续的）。

注意，对于我们考虑的几乎所有情况，这些概率将是确定性的。在一个状态中执行动作始终会将你带到相同的下一个状态。

但知道这些概率在需要时是定义好的是好的，而且它们也是核心理论的一部分。

---

作为一个马尔可夫假设并不一定具有局限性的例子，我们可以看看强化学习的一个近期应用。

DeepMind (Mnih et al. 2013) 使用最近 4 帧的拼接来表示当前状态。

严格来说，状态可以由从过去到现在的任何时间点的任何内容组成。我们通常认为现在的状态是我们现在正在测量的东西，但事实并非如此。

注意，我们也不一定需要原始数据来表示状态。状态也可以由派自原始数据的数据组成。你可能认为那是对原始数据的特征转换。

本质上，来自智能体传感器的任何输入都可以用于形成状态。

##形式化马尔可夫决策过程

在本节中，我们将以更正式的方式观察马尔可夫决策过程。

我们直以来一直在观察马尔可夫决策过程，只是从未给它命名。

任何遵循马尔可夫属性的具有状态、动作和奖励的强化学习任务都是马尔可夫决策过程。

从形式上说，马尔可夫决策过程是一个五元组，由状态集合、奖励集合、动作集合、状态转移概率和奖励概率（我们之前作为联合分布讨论过）以及折扣因子组成（我们将在稍后的课程中定义）。

---

然而，我们还需要另一个碎片块来完成这个拼图。

“马尔可夫决策过程”中的另一个关键术语是“决策”。




我们决定在什么状态下采取什么动作的方法被称为**策略**（policy）。

我们通常用符号 `pi` 来表示策略。

从技术上讲，策略并不是 `MDP` 本身的一部分，但它是解决方案的一部分，与价值函数（value function）一起（我们就会对其进行更正式的定义）。

我之前没有提到策略的原因是因为这个符号有点奇怪。我们把 `pi` 写成一个数学符号，但并没有一个关于 `pi` 的方程。

例如，如果 `pi` 是 `epsilon-greedy`（ε贪心策略），我们如何将其写成方程呢？它更像是一个算法。例如：`pi = epsilon-greedy`？这并不是一个方程。

唯一的例外是你想要写下**最优策略**（optimal policy）时，它可以根据价值函数用数学方式进行定义。我们将在后面的讲座中讨论最优策略及其含义。

所以目前，`pi` 更多是智能体用于导航环境的算法的简记符号。

---

由于马尔可夫决策过程满足马尔可夫属性，你可以想象我们可以像为马尔可夫模型和隐马尔可夫模型那样，也为 `MDPs` 绘制状态转移图。我不经常这样做，但你可能会发现这对你自己很有用。

---

让我们再次观察转移概率 `p(s’ | s, a)`。记得我提到过这通常是确定性的，但情况并不总是如此。为什么会这样呢？

记住，状态只是根据智能体从环境中感知到的信息所得出的。它不是环境本身。状态可能是对环境的不完美表示。在这种情况下，你会预期状态转移是概率性的。例如，你测量的状态可能代表环境的多种配置。

作为环境不完美表示的例子，想一下黑杰游戏（think-jack）。你可能认为发牌员下一张牌是状态的一部分。但如果你是智能体，你看不见下一张牌。所以它不是你状态的一部分。它是环境的一部分。

---

有时，对于什么构成了智能体和环境存在困惑。想象你正在自己的环境中。你可能认为自己是智能体，但什么构成了“你”？

你是你的身体吗？更准确地说，你的身体是环境的一部分。你的身体并不做决策或学习。你的身体拥有传感器并将信号传递给你的大脑，但是你的大脑或思想在进行所有的学习和决策。所以，你要留意区分智能体和环境的边界划在哪里。

## 未来奖励

在本节中，我们将正式化总奖励的概念。特别是，我们感兴趣的衡量的是总未来奖励。即从 `t+1` 开始之后的所有内容。

我们将其称为“**回报”（return），并使用符号 `G(t)` 来表示它。

`G(t) = R(t+1) + R(t+2) + ... + R(t+infinity)`

注意它不依赖于当前时间的奖励。这是因为，严格来说，当我到达一个状态时，我收到了该状态的奖励。我无法对其进行任何预测，因为它已经发生了。

---

现在想一个非常长的任务。一个包含长数千步序列的任务。你的目标是使总奖励最大化。

但现在获得奖励和 10 年后获得同样的奖励之间有区别吗？考虑一下金融。你知道今天的 `$1000` 价值低于 10 年前的 `$1000`。如果我问你，你更愿意在现在拿 `$1000`，还是愿意在 10 年后拿 `$1000`，你当然会选择现在。

---

因此，我们对未来奖励引入了所谓的**折扣因子**（discount factor）。我们将折扣因子称为 `gamma`，并使用 0 到 1 之间的一个数字来表示它。

`G(t) = sum[t’=0...inf]{ gamma^t’ R(t+t’+1) }`

很显然，`gamma` 为 1 意味着我们不在乎奖励在未来有多远，所有未来奖励应该具有相同的权重。如果 `gamma` 为 0，则意味着我们完全不在乎未来。因为，这样做将是一个真正的贪心算法。

## 价值函数

在本节中，我们终于准备好讨论价值函数了。




因此，我们也可以用它来计算之前看到的期望值的第二部分。

`V(s) = E[R(t+1)+gamma*G(t+1) | S(t)=s]`

`V(s) = sum[a]{{ pi(a | s) sum[s’, r]{{ p(s’,r | s,a)(r + gamma*E[G(t+1) | S(t+1)=s’]) }}`

`V(s) = sum[a]{{ pi(a | s) sum[s’, r]{{ p(s’,r | s,a)r+V(s')} }}`

这个递归方程在强化学习中具有特殊地位，它是我们学习的所有算法所基于的方程。

它被称为“贝尔曼方程”（`Bellman equation`），以著名的数学家理查德·贝尔曼（Richard Bellman）的名字命名。

贝尔曼开创了被称为“动态规划”的技术，你可能在算法课上学过它。它和递归有关，但它是高效的，因为它使用自底向上的方法来构建解决方案。

事实上，我们将学习的解决 MDP（马尔可夫决策过程）的技术之一被称为“动态规划”。

---

在讨论价值函数时，我们还需要学习另一种价值函数。

我们刚刚学习的 `V(s)` 被称为状态价值函数（state-value function）。

有另一个价值函数 `Q(s, a)`，被称为动作价值函数（action-value function）。之所以这样，是因为动作 `a` 也是函数的参数。

注意，由于 `Q` 有 2 个输入，存储它所需的空间是二次方的。具体来说，我们需要的空间是状态集合的大小乘以动作集合的大小（`|S|`）。




`old_v = V(s)`

`V(s)=sum[a]{pi(a | s)sum[s’,r]{p(s’,r | s,a)(r+V(s’))}}`

`𝛥 = max(𝛥, |V(s) - old_v|)`

`if 𝛥 < threshold: break`

`return V(s)`

迭代策略评估的输入是策略 `pi`，输出是该策略的值函数。

我们首先将所有状态的 `V(s)` 初始化为 0。在一个无限循环中，初始化一个名为 `𝛥` 的变量。`𝛥` 代表当前迭代期间的最大变化。我们将使用 `𝛥` 来决定何时退出。当 `𝛥` 足够小时，我们就跳出循环。

然后对于状态空间中的每个状态，我们保留一个旧 `V(s)` 的副本，然后使用贝尔曼方程来更新 `V(s)`。

我们将 `𝛥` 设置为该迭代中 `V(s)` 的最大变化。

一旦收敛，我们就返回 `V(s)`。

---

算法中主要感兴趣的部分无疑是包含贝尔曼方程的部分。

`V [k+1] (s) = sum\[a\]{ pi(a | s) sum\[s’, r\]{ p(s’,r | s,a)(r+V [k] (s’)) }}`

注意严格来说，迭代 `k+1` 处的值仅依赖于迭代 `k` 的值。

然而，事实并非如此。

事实上，我们始终可以通过就地更新（in-place update）来对任何状态使用最新的值函数版本。

这实际上会导致更快的收敛。

---

最后一点：

我们通常将为给定策略寻找值函数的过程称为预测问题（prediction problem）。

在本节的稍后部分，我们将学习一种寻找最优策略的算法。这被称为控制问题（control problem）。

因此，我们在书中剩余章节中遵循这一模式。

我们将首先研究预测问题以找到给定策略的值函数，然后研究控制问题以找到最优策略。

## 代码中的迭代策略评估

在这一节中，我们将在代码中实现迭代策略评估。

为了演示我们如何找到不同策略的价值函数，我们将对 2 种不同的策略进行迭代策略评估。

我们将看到的第一个策略是完全随机的策略。

记住，贝尔曼方程中涉及 2 个概率分布，一个是 `pi(a | s)`，另一个是马尔可夫状态转移概率 `p(s’, r | s, a)`。

你认为哪一个与实现贝尔曼方程有关？

---

答案是 `pi(a | s)`。这是当我处于状态 `s` 时，执行动作 `a` 的概率。

对于均匀随机策略，该概率将是 `1 / 状态 s 的所有可能动作数`。

另一个概率 `p(s’, r | s, a)` 仅在状态转移本身是随机时才相关。

那种情况是，你尝试向左移动，结果却向右移动了。

---

我们将看到的第二个策略是完全确定的策略。为了方便起见，我把它粘贴在这里：

```

---------------------------
U | R |
---------------------------
U | R | U |
---------------------------
```

从起始位置开始，你直接走向目标状态。然而，如果你从任何其他状态开始，策略是直接走向失败状态。

因此，我们应该期望左上路径的值为正，而其他状态的值为负。

## 策略改进

在这节课程中，我们将开始讨论控制问题，换句话说，如何找到更好的策略并最终获得最优策略。

到目前为止，我们知道如何在给定固定策略的情况下找到值函数。

让我们再次看一遍 `Q` 的递归定义。

`Q(s,a) = sum[s’,r]{ p(s’,r | s,a)(r+V(s’)) }`

这告诉我们使用策略 `pi` 时在状态 `s` 执行动作 `a` 的值。

---

使用当前策略，我们简单地获得当前的状态值函数。
`V(s) = Q(s, pi) = sum[s’,r]{ p(s’,r | s, pi)(r+V(s’)) }`

但假设我们只想改变策略中的一个动作。我们可以这样做吗？

---

我们有一个有限的动作集合，所以我们只需要选择一个比 `pi(s)` 提供更大 `Q` 的动作即可：`find a in A s.t. Q(s,a) > Q(s, pi)`。

这就是所有编程变得非常实用的地方。这看起来像是一个非常抽象的方程，但它的意思是，如果“向上”的策略、让我们看看“向右”或“向下”带给我们更大的 `Q`。如果是这样，我们就改变该状态的策略。

---

从正式地说，当我们为该状态选择新动作时，我们是在寻找一个新的策略 `pi’`，它对该状态的值比 `pi` 大。
`pi <= pi’ --> V(s | pi) <= V’(s | pi’)`
`pi’(s) = argmax[a]{ Q(s,a) }`
`pi’(s) = argmax[a]{ sum[s’,r]{ p(s’,r | s,a)(r+V(s’)) }}`

我们只需要选择一个能提供最大 `Q` 的动作。注意我们可以将其写成使用 `Q` 的形式，或者写成对 `V` 进行前瞻查找的形式。

---

关于策略改进，有两点你应该注意：

第一，注意它是贪婪的。我们根本没有考虑所有状态的值函数。我们只看当前状态并根据值函数选择最佳动作。

第二，注意它使用了一个不完美的值函数。一旦我们改变了 `pi`，`V(s)` 就会改变。你将在随后的章节中看到为什么这不是一个问题。

你可能有一个问题是，我们如何知道何时完成了策略改进？当我们找到最优策略时，策略将不再随值函数发生改变。此外，值函数将不再改进，它将保持恒定。注意我们之前使用的不等式是“小于或等于”。在这种情况下，如果它是“相等”，说明我们找到了最优策略。

## 策略迭代

在本节课程中，我们将讨论用于找到最优策略的算法。具体来说，当我们改变策略时，值函数也会改变。

当我们改变策略且值函数过时时该怎么办？我们只需要简单地重新计算值函数。幸运的是我们已经知道如何这样做，因为我们在上节写过了。在层面，算法非常简单：我们在策略评估和策略改进之间交替，直到策略不再变化。

```python
## 重直到收敛 - 当策略不再改变时将跳出
while True:
    # 策略评估步 - 我们已经知道怎么做了！
    while True:
        biggest_change = 0
        for s in states:
            old_v = V[s]
            # 如果 s 不是终端状态，V(s) 就值
            if s in policy:
                a = policy[s]
                grid.set_state(s)
                r = grid.move(a)

                biggest_change = max(biggest_change, np.abs(old_v - V[s]))
        if biggest_change < SMALL_ENOUGH:
            break

    # 策略改进步
    is_policy_converged = True
    for s in states:
        if s in policy:
            old_a = policy[s]
            new_a = None
            best_value = float('-inf')
            # 遍历所有可能的动作以寻找当前的最佳前瞻值
            for a in ALL_POSSIBLE_ACTIONS:
                grid.set_state(s)
                r = grid.move(a)
                v = r + GAMMA * V[grid.current_state()]
                if v > best_value:
                    best_value = v
                    new_a = a
            policy[s] = new_a
            if new_a != old_a:
                is_policy_converged = False
    if is_policy_converged:
        break
```

在本节中，我将向你描述我们对环境的一种修改，称为“风力网格”。回顾一下我们需要处理的概率分布。首先是 `pi(a | s)`，即状态 `s` 下执行动作 `a` 的概率。然后是状态转移概率 `p(s', r | s, a)`。到目前为止都是确定性的。当我们在状态 `s` 执行动作 `a` 时，总是进入相同的状态 `s'`。这与奖励也有关，因为 Gridworld 根据你落入的状态来给予奖励。在本节中，我们将考虑这种概率分布不是确定性的情况，换句话说，概率将在 0 到 1 之间。

## 价值迭代 (Value Iteration)

在本节中，我们将讨论一种解决控制问题的备选技术，称为价值迭代（value iteration）。记得我们之前学习的技术是策略迭代（policy iteration）。很容易把所有这些都搞混，因为所有算法看起来和听起来都一样，所以编写代码绝对会帮助你熟悉针对马尔可夫决策过程（MDP）的各种解决方案。策略迭代的一个缺点是它是迭代算法，因此我们必须等待它收敛。同时，主循环包含两个步骤，而第一步本身也是一个迭代算法，所以你在一个迭代算法内部另一个迭代算法。人们可能会问是否有更高效的方法来解决这个问题。

记得策略评估在 `V` 收敛时结束。一个合理的问题是，在收敛之前是否存在某一个点，使得贪婪策略不再变化？事实上，经验研究表明，在仅进行几次策略评估后，得到的贪婪策略就是恒定的。这告诉我们，当我们在执行策略迭代时，我们实际上不需要等待策略评估收敛，只需要执行几步然后跳出，因为策略改进步骤在额外的策略评估迭代下会找到相同的策略。

然而，我们在本讲座中学习的算法又进了一步。它被称为价值迭代。它的作用是将策略评估和策略改进步骤合并为一步。它执行的是：`Vk+1 = max[a]{sum[s', r]{p(s', r | s, a)(r + Vk)}`。它的有趣之处在于，它看起来和我们见过的公式几乎完全一样。事实上，如果你没留神，它看起来和我们见过的公式一模一样。这就是为什么我一直在说编写代码来尝试理解差异是非常重要的。你需要仔细观察这个，以查看它与我们过的其他贝尔曼方程的区别。这个方程与策略评估方程非常相似，只是我们对所有可能的动作取 `max`。

从 `k` 索引可以看出，它也是迭代的。类似于策略评估，我们并不真的需要等待整个 `k` 次迭代的 `V` 可用后再开始计算 `(k+1)` 次迭代的 `V`。我们可以直接“就地”更新它。注意它是如何在一个步内完成策略评估和策略改进的。这是因为策略改进是通过对右侧表达式取 `ARGMAX` 来实现的。所以通过直接取 `max`，我们实际上是在执行如果我们取了 `argmax` 时会选择的策略的评估步骤。

让我们把这些都写成伪代码，这样你就有机会看一看。第一步是任意初始化 `V`。这可以是随机数或全为 0，这并不重要。然后我们进入一个无限循环。和策略评估一样，我们跟踪最大的变化，并在最大变化低于某个阈值时跳出循环，这表示收敛。这种方法与策略评估之间的唯一区别在于，我们对右侧的贝尔曼方程对所有动作取 `max`。在我们收敛后，通过对每个 `V(s)` 取 `argmax` 来输出策略 `pi(s)`。

```
initialize V(s) = 0 for all s in S
while True:
    delta = 0
    for each s in S:
        old_v = V[s]
        V(s) = max[a]{sum[s', r]{p(s', r | s, a)(r + V(s'))}}
        delta = max(delta, |V(s) - old_v|)
    if delta < threshold:
        break
for each s in S:
    pi(s) = argmax[a]{sum[s', r]{p(s', r | s, a)(r + V(s'))}}
```

在本节中，我们将重点关注蒙特卡洛方法，我们将按照游戏设计的初衷来玩，并纯粹从经验中学习。

---

“蒙特卡洛”是一个定义相当模糊的术语。它通常指的是任何包含显著随机成分的算法。

在强化学习（RL）的蒙特卡洛方法中，随机成分是回报（return）。

记住，我们始终寻找的是给定状态 `s` 时的期望回报。

在蒙特卡洛方法中，我们不是计算需要概率分布的真实期望值，而是取样本平均值。

例如：

`E(X) ~= sum[i=1..N]{ X(i) } / N`

为了让这种方法生效，我们需要假设我们只处理回合式任务（episodic tasks）。

这是因为在计算任何回报之前，回合必须结束。

这也意味着蒙特卡洛方法不是“完全”的在线算法（诸如多臂老虎机问题）。我们不会在每个动作后都进行更新，而是在每个回合结束后进行更新。

---

我们在蒙特卡洛章节使用的方法应该会让人联想起多臂老虎机问题。

在多臂老虎机问题中，我们总是在每个动作后对奖励取平均。

在马尔可夫决策过程（MDP）中，我们总是对回报取平均。

思考蒙特卡洛的一种方式：每个状态都是一个独立的多臂老虎机问题，我们正在试图同时学习针对所有多臂老虎机问题的最优行为。

然后我们将研究控制问题，换句话说，如何找到最优策略。

## 状态价值函数的蒙特卡洛预测

在本节中，我们将使用蒙特卡洛估计来解决预测问题。

记住，价值函数的定义是：给定当前状态为 `s` 时，未来回报的期望值。

`V(s) = E[G(t) | S(t)=s]`

我们知道可以通过累加样本并除以样本总数简单地估计任何期望值。

`V(s) = (1/N) sum[i=1..N]{ G(i, s) }`

在这个方程中，`i` 是回合的索引，`s` 是状态的索引。

问题是，我们如何获得这些采样的回报？

---

答案是，我们只需要玩很多回合并生成它们。

对于你运行的每一个回合，你将获得一个状态和奖励序列。

`s1 s2 s3 … sT`

`r1 r2 r3 … rT`

`g(t) = r(t+1) + gamma*g(t+1)`

根据定义，我们可以从奖励中计算回报，它只是所有未来奖励的总和。

注意，在代码中实际实现这一点时，反序遍历状态和奖励将非常有用，因为 `G` 只依赖于未来值。

一旦我们对许多回合执行了此操作，我们就会有多个 `s` 和 `G` 的列表，然后我们可以取样本平均值。

```python
def play_game(grid, policy):
    # 返回状态列表和对应的回报列表

    # 重置游戏以从随机位置开始
    # 我们需要这样做，因为在我们当前的确定性策略下，
    # 我们永远无法到达某些状态，但我们仍然想测量它们的价值
    start_states = grid.actions.keys()
    start_idx = np.random.choice(len(start_states))
    grid.set_state(start_states[start_idx])

    s = grid.current_state()
    states_and_rewards = [(s, 0)] # (state, reward) 元组列表
    while not grid.game_over():
        a = policy[s]
        r = grid.move(a)
        s = grid.current_state()
        states_and_rewards.append((s, r))
    # 从终止状态反向计算回报
    G = 0
    states_and_returns = []
    first = True
    for s, r in reversed(states_and_rewards):
        # 根据定义，终止状态的价值为 0
        # 我们应该忽略遇到的第一个状态
        # 并忽略最后一个 G，因为它是没有意义的，不对应于任何移动
        if first:
            first = False
        else:
            states_and_returns.append((s, G))
        G = r + GAMMA*G
    states_and_returns.reverse() # 我们希望它按照访问状态的顺序排列
    return states_and_returns
```

我们的策略与我们之前使用的同一个，即一直采取左上方的路径到达目标状态。对于不在该路径上的任何状态，则通向失败状态。

```python
        s = grid.current_state()

    # 从终端状态开始反向计算回报
    G = 0
    states_and_returns = []
    first = True
    for s, r in reversed(states_and_rewards):
        # 根据定义，终端状态的价值为 0
        # 我们应该忽略遇到的第一个状态
        # 并忽略最后一个 G，它是没有意义的，因为它不对应于任何动作
        if first:
            first = False
        else:
            states_and_returns.append((s, G))
        G = r + GAMMA*G
    states_and_returns.reverse() # 我们希望按照访问状态的顺序排列
    return states_and_returns
```

接下来，我们将按照当前策略从该起始位置生成一个回合（episode）。

由此，我们将得到一个包含状态、动作和回报的三元组列表。

我们将这些内容添加到以状态-动作对为键的回报字典中。

接下来，我们将重新计算 `Q(s,a)`，它是该状态-动作对所有回报的平均值。

接下来，我们执行策略改进步骤，即分配 `Q` 的 `argmax` 动作。

---

这个算法存在一个微妙的问题。

记住，如果我们执行的动作导致我们撞到墙，我们最终会停在之前的同一个状态。

所以，如果我们遵循这个策略，我们将永远无法到达终止状态，因此永远无法结束回合。

为了避免这个问题，我们将引入一种“黑操作”（hack）：如果在执行某个动作后我们落在了相同的状态，我们将给它一个为 `-100` 的奖励（这比环境提供的任何其他奖励都低），并结束该回合。

---

有趣的是，这种方法是可以收敛的，尽管我们为 `Q` 平均的回报是针对不同策略的。

直觉上，`Q` 必须收敛，因为如果 `Q` 不是最优的，策略就会改变，而反过来又会导致 `Q` 的改变。

只有当价值和策略都收敛到最优价值和最优策略时，我们才能实现稳定性。

一个有趣的事实是这从未被正式证明过。

```python
def play_game(grid, policy):
    # 返回状态和对应回报的列表

    # 重置游戏从随机位置开始
    # 如果我们有确定性策略，我们需要这样做
    # 否则我们永远无法到达某些状态，但我们仍然想测量它们的价值
    # 这被称为“探索启动”方法
    start_states = grid.actions.keys()
    start_idx = np.random.choice(len(start_states))
    grid.set_state(start_states[start_idx])

    s = grid.current_state()
    a = np.random.choice(ALL_POSSIBLE_ACTIONS) # 第一个动作是均匀随机的

    # 注意计时
    # 每个三元组为 s(t), a(t), r(t)
    # 但 r(t) 来自于 s(t-1) 取动作 a(t-1) 并落在 s(t)
    states_actions_rewards = [(s, a, 0)]
    while True:
        old_s = grid.current_state()
        r = grid.move(a)
        s = grid.current_state()
        if old_s == s:
            # 使用黑操作以防止我们陷入无限的回合
            # 重复撞墙
            states_actions_rewards.append((s, None, -100))
            break
        elif grid.game_over():
            states_actions_rewards.append((s, None, r))
            break
        else:
            a = policy[s]
            states_actions_rewards.append((s, a, r))

    # 从终止状态反向计算回报
    G = 0
    states_actions_returns = []
    first = True
    for s, a, r in reversed(states_actions_rewards):
        # 根据定义，终止状态的价值为 0
        # 我们应该忽略遇到的第一个状态
        # 并忽略最后一个 G，它是没有意义的，因为它不对应任何移动
        if first:
            first = False
        else:
            states_actions_returns.append((s, a, G))
        G = r + GAMMA*G
    states_actions_returns.reverse() # 我们希望它按照访问状态的顺序排列
    return states_actions_returns
```

```python
def max_dict(d):
    # 返回字典的 argmax 和最大值
    max_key = None
    max_val = float('-inf')
    for k, v in d.iteritems():
        if v > max_val:
            max_val = v
            max_key = k
    return max_key, max_val
```

## MC 总结

在本次课程中，我们将总结在本章中看到过的所有内容。

这一部分完全关于蒙特卡洛（Monte Carlo）方法。

在动态规划的最后一部分，我们做了一个奇怪的假设，假设知道所有的状态转移概率且从未真正玩过游戏。因此，我们无法从经验中学习，正如预期强化学习智能体应该做的那样。我们遵循惯模式：首先研究预测问题，然后研究控制问题。

我们在蒙特卡洛中使用的主要技术是价值函数是给定状态的期望回报。我们从概率中知道，期望值可以通过样本平均值来近似。为了使用蒙特卡洛，我们需要生成回合（episodes）并计算每个回合的回报。这给了我们一个状态和回报的对列表。我们对这些回报取平均值以找到每个状态的值。记住，平均回报有两种：“首次访问”（first-visit）和“每次访问”（every-visit）。虽然这两种方法都被证明收敛于相同的结果，但我们使用了首次访问，因为它更简单。

我们看到蒙特卡洛方法可能比动态规划更高效，因为它不需要我们遍历整个状态空间。正因如此，我们可能永远无法获得“完整的”价值函数，但如果其中许多状态永远不会到达，或很少到达，这可能并不重要。也就是说，我们访问某个状态越频繁，该值就越准确。由于蒙特卡洛方法导致每个状态被访问的次数不同，取决于策略，我们使用了探索启动（探索 starts）来确保每个状态都有足够的数据。

然后我们研究了控制问题。蒙特卡洛的区别在于现在我们需要使用 `Q` 而不是 `V`，以便我们可以对所有动作取 `argmax`。这是因为我们可以像动态规划中做的那样进行前瞻搜索（look-ahead）。我们看到可以继续使用策略迭代（policy iteration）的思想，我们在动态规划章节中在策略评估和策略改进之间交替进行。我们谈到了蒙特卡洛的一个主要缺点：为了准确，它需要大量的样本，并且必须在循环内部进行，这使得它非常低效。我们采取了与值迭代相同的方法，即每次迭代只进行一次更新。这令人惊讶的是，对于不同的策略，策略是演变的。同样惊讶的是，这从未被正式证明收敛。

蒙特卡洛的一个主要缺点是，我们需要使用探索启动来获得 `Q` 的完整测量。如果我们使用 epsilon 贪婪（epsilon-greedy）而不是探索启动，就不需要了，因为 epsilon 贪婪允许我们不断探索所有的状态空间。

# 时分学习（Temporal Difference）

## TD 简介

在本节中，我们将学习一种强化学习的第三种技术，称为时分学习（temporal difference learning），简称为“TD”。时分学习是强化学习中最重要的技术之一，它结合了前两个章节中动态规划和蒙特卡洛的思想。

你会记得动态规划的一个缺点是它需要环境的完整模型，且从未从经验中学习。另一方面，蒙特卡洛从经验中学习。在蒙特卡洛方法中，我们看到在完成一个回合后才能更新价值函数。另一方面，动态规划使用了自助（bootstrapping），即基于现有估计值进行改进。我们将看到时分学习也使用自助，而且它是完全在线的（fully online）。所以我们不需要等待回合结束就可以更新估计值。

在本章中，我们将采取与前两个章节相同的方法。我们首先研究预测问题，或者说给定策略的情况下寻找价值函数。接下来，我们将研究控制问题。与前两个章节类似，我们将探索处理控制问题的两种方法：`SARSA` 和 `Q-Learning`，后者最近变得非常流行。

## TD(0) 理论

在本节中，我们将学习如何将时分学习应用于预测问题，或者说寻找价值函数。起初你觉得这个名字很奇怪。为什么名字里是 0 而不是其他数字？原因是存在其他的 TD 学习方法，例如 `TD(1)` 以及更通用的 `TD(lambda)`，但这些超出了本书的范围。它们是类似的，但对于理解 `Q-Learning` 和我们最终想要的近似方法并不是必要的。

那么 `TD(0)`是如何工作的？首先，回想蒙特卡洛。记得蒙特卡洛的缺点是我们需要等待回合结束才能计算回报，因为回报取决于未来的奖励。还记得蒙特卡洛方法是对回报取平均，而且在课程早期我们研究了计算平均值的不同方法。

特别是，让我们看看不需要实际存储所有回报的方法：
```python
V(S(t)) = V(S(t)) + alpha*[G(t)-V(t)]
```
记得 `alpha` 可以是常数也可以随时间衰减。所以如果我们使用这个公式，它就是计算状态平均回报的另一种方法。

现在记得 `V` 的定义。记得它是给定状态的回报的期望值。但也记得我们可以递归地定义它：
```python
V(s) = E[G(t) | S(t)=s] = E[R(t+1)+gamma*V(S(t+1)) | S(t)=s]
```

所以，合理的提问是，是否可以使用这个 `V` 的递归定义替换更新方程中的回报？
```python
V(S(t)) = V(S(t)) + alpha*[R(t+1) + gamma*V(S(t+1)) - V(S(t))]
V(s) = V(s) + alpha*[r+V(s’)-V(s)]
```
我们从中得到 `TD(0)` 方法。如果你仔细观察，就会发现这是一个完全在线的自助方法。我们现在不再计算完整的回 `G`。相反，我们只是在使用另一个 `V` 估计值，特别是下一个状态的 `V`。




在蒙特卡洛方法中，随机性来自于每个回合（episode）可能以不同的方式进行。

因此，如果后续所有的状态转移具有某种随机性，那么某个状态的回报（return）将会不同。

在 `TD(0)` 中，我们又有了另一个随机来源。

具体来说，我们甚至不知道回报是多少，因此我们使用 `r + gamma*V(s’)` 来估计回报 `G`。

---

在本节中，我们学习了为什么时序分差学习（temporal difference learning）与动态规划和蒙特卡洛方法相比都更具优势。

与动态规划不同，我们不需要环境模型。我们从经验中学习，并且只更新我们实际访问过的状态。

与蒙特卡洛方法不同，我们不需要等待回合结束就可以开始学习。这在回合非常长的情况下是有优势的。我们可以在回合进行过程中改进性能，而不需要一直等到等到下一个回合。

它甚至可以用于连续性任务（continuing tasks），即完全没有回合的任务。

```python
def play_game(grid, policy):
    # 返回状态列表和对应的奖励（不是 MC 中的那种回报）
    # 从指定的起始状态开始
    s = (2, 0)
    grid.set_state(s)
    states_and_rewards = [(s, 0)] # (状态, 奖励) 的元组列表
    while not grid.game_over():
        a = policy[s]
        a = random_action(a)
        r = grid.move(a)
        s = grid.current_state()
        states_and_rewards.append((s, r))
    return states_and_rewards
```

## SARSA 

在 SARSA 中，我们需要知道状态 `s` 下所有动作 `a` 的 `Q(s,a)`，以便准确选择 argmax。

由于更新依赖于知道五元组 `(s,a,r,s’,a’`，这种方法被命名 SARSA。

---

由于 SARSA 需要知道状态 `s` 下所有动作 `a` 的 `Q(s,a)`，我们面临着与蒙特卡洛方法相同的问题。

回想一下问题在于：如果你遵循确定性策略，只会执行 `1/|A|` 的可能动作，这会导致大部分 `Q` 未定义。

所以为了解决这个问题，我们要么使用探索启动（exploring starts），要么使用允许探索的策略，比如 epsilon-greedy。

由于我们已经知道探索启动是不现实的，我们将使用 epsilon-greedy。

---

让我们看一些伪代码来巩固这个概念。

```
Q(s,a) = 任意值, Q(terminal, a) = 0
for t=1..N
    s = start_state, a = epsilon_greedy_from(Q(s))
    while not game over:
        s’, r = do_action(a)
        a’ = epsilon_greedy_from(Q(s’)
        Q(s,a) = Q(s,a) + alpha*[r + gamma*Q(s’,a’) - Q(s,a)]
        s = s’, a = a’
```



我们然后根据 epsilon-greedy 策略和当前的 `Q` 选择下一个动作。我们称之为 `a’`。

接下来，我们对 `Q(s,a)` 进行更新，它取决于：`Q(s,a)`、`r` 以及 `Q(s’,a’)`。

接着，我们将 `s` 更新为 `s’`，并将 `a` 更新为 `a’`。

--- 关于 SARSA 的一个有趣事实是，从未发表过收敛性证明。

然而，非正式地说明，如果策略收敛到贪婪策略，SARSA 就会收敛。

实现这一目标的一种方法是让 `epsilon = 1/t`，其中 `t` 代表时间。

这是我们在代码中使用的形式。

注意，分子不一定是 1。你可以使用 `0.5/t` 或 `0.8/t` 等任何你想要的数值。

此外，你**不一定**得使用 `1/t` 衰减，你可以使用 `1/t²/3` 或任何你选择的幂。

你应该将其视为一个超参数。

--- 同样记住，学习率也可以衰减。

使用 `1/t` 衰减存在一个问题。

考虑一下，在每个时刻，`Q` 中只有一个状态-动作对会被更新。

因此，对于那些从未更新过的 `Q` 值，学习率也会发生衰减！

你可以尝试弥补这一点，即每个回合（episode）只衰减一次学习率，但你仍然面临相同的问题。

在一个回合中，只有完整状态集的一个子集会被访问。

而且每个状态只会采取所有可能动作中的一个。

所以，即使你每回合只衰减一次学习率，你仍然对那些从未更新过的 `Q` 部分进行了衰减。

--- 为了解决这个问题，我们从深度学习中汲取了灵感——特别是 `AdaGrad` 和 `RMSprop` 算法。

记住，这些算法独特之处在于，当过去的梯度很大时，有效学习率下降得更多。换句话说，事物过去变化得越多，我们未来降低学习率的就越大。

我们的版本将比这些技术简单，但原理是相同的。我们将记录看到状态-动作对的次数。

我们将 `alpha` 设置为原始的 `alpha / the count`。

`alpha(s,a) = alpha0/count(s,a)`

或者更通用地：

`alpha(s,a)=alpha0/(k+m*count(s,a))`

通过这样，每个状态-动作对都有自己的 `alpha`，因此它们都将拥有各自各自独立衰减的学习率。

## 那么 Q-Learning 是如何工作的？

它实际上看起来非常像 SARSA。

如果你看一眼这两个公式，并发现它们在你看来完全一模一样，这并不会令人惊奇。

`Q(S(t),A(t)) = Q(S(t),A(t))+alpha*[R(t+1) + max[a’]{ Q(S(t+1),a’) } - Q(St,At)]`

`Q(s,a) = Q(s,a) + alpha*[r+max[a’]{ Q(s’,a’) } - Q(s,a)]`

所以主意是，我们不是根据 `Q` 的 `argmax` 来实际选择 `a’`，而是根据所有动作的 `max` 来更新 `Q`。

现在你的第一个想法可能是：“嗯，这不就是完全一样吗？”

如果我们选择 `a’` 作为 `Q` 的 `argmax`，那么乘以 `gamma` 的项将是 `Q(s’, a’`，它是对 `a’` 取最大值。

---

## 这里的区别在于

记住，对于 Q-Learning，它是一种离策略（off-policy）方法。

`Q(s’,a’)` 可能是所有 `a’` 的 `max`，但这并不意味着 `a’` 必须是我们的下一个动作。

我们使用 `Q(s’,a’)` 的 `max` 来更新 `Q(s,a)`，即使我们最后在下一步中没有执行动作 `a’`。

这表明我们遵循什么策略完全不重要。我们可以随机选择动作，并且仍然得到相同的答案。代码将证明这一点。

在现实中，如果你最终确实采取了纯随机的动作，结果将是你的智能体经常表现出非最优行为，这将使得你的回合（episodes）持续时间更长。

正因如此，对于相同数量的回合，脚本运行的时间会更长。

---

所以 Q-Learning 的关键区别在于，我们使用什么策略并不重要。

那么合理的问题是，在什么情况下 Q-Learning 等同于 SARSA？

如果你在 Q-Learning 期间使用的策略是贪婪策略（greedy policy），这意味着你总是选择 `Q` 的 `argmax`，那么你的 `Q(s’,a’)` 将对应于你采取的下一个动作。

因此，在这种情况下，你既在做 SARSA，也在做 Q-Learning。

正如你所知，我们将类别编码为特征向量的方法是独热编码（one-hot-encoding）。

---

让我们讨论一下如果我们对每个状态进行独热编码会发生什么。

我们有 `|S|` 个状态，因此 `X` 的维度（我们称之为 `D`）是 `|S|` 的基数。

`D=|S|`

所以我们有一个大小为 `|S|` 的长型特征向量 `X`。

然后，对于每个状态，我们将 `X` 中的其中一个值设置为 1。

`s = (0,0) → x = [1, 0, 0, …]`
`s = (0,1) → x = [0, 1, 0, …]`

---

这种方法的问题在于，它无法允许我们压缩存储值函数所需的空间，而这正是我们最初想要这样做的根本。

回一下，如果我们把 `V` 存储为一个字典，它将会有 `|S|` 个键和 `|S|` 个值。

所以，如果我们使用独热编码，并没有带来任何改进。

事实上，这与我们之前所做的等价的，因为在这种情况下，每个 `theta` 都代表对应状态的值。

`V(s=0) = theta.dot([1,0,0,...]) = theta[0] = theta 的第 0 个分量`

---

然而，在特征变换中使用独热编码也有一个积极的方面。

假设你的算法不起作用，且 `V_hat` 不能很好地表示真实的 `V`。

你的 `V_hat` 可能不好的原因之一是你的特征可能不好。

所以，你的代码可能是完美且没有 true 的，但仍然因为特征不好而没有产生良好的结果。

因此在这种情况下，你可以更改特征转换器来使用独热编码，其中你单独预测每个 `V(s)`。

如果你这样做并且代码运行正常，那么它告诉你的你的特征很糟糕。

---

那么，如果独热编码并不好，那么什么才是好的呢？

在网格世界（Gridworld）的情况下，考虑每个 `(i, j)` 位置实际上代表二维空间中的一个位置。

因此，它更像是一个实数而不是一个类别。

所以你可以直接将 `X` 向量表示为 `(i, j)` 本身。你可能想对其缩放，使其均值为 0，方差为 1。

`(x1,x2) = (i,j)`

我们将此特征向量简单视为原始数据 - 无需任何特征工程。

---

将 `x` 仅设置为智能体的位置有什么问题？

记住我们的模型是线性的。

假设 `j` 是固定的。

这意味着，`V` 只能随 `i` 线性变化。

这意味着，`V` 对于这个 `x` 坐标只能是一条直线。

所以它要么始终增加的，要么始终减少的。

这种表表达能力不高。

回想我的线性回归课程，创建新特征的一种简单方法是创建多项式。

你可能在微积分学习中学习过，无限的泰勒展开可以近似任何函数。

所以，如果我们从 `x1` 和 `x2` 开始，我们可以创建项 `x1²`、`x2²` 和 `x1*x2`。

如果你需要，你也可以创建高阶多项式，但你必须注意过拟合。

## MC 预测理论

现在我们已经为将监督线性模型整合到我们的标记尔决策过程过程中奠定了基础，我们可以开始将它们应用于预测问题和控制问题。

我们当然将从预测问题开始。

特别在本讲座中，我们将使用蒙特卡洛估计，但用我们的值函数线性模型替换值函数字典。

---

回想起蒙特卡洛估计，我们有两个重复执行的两个步骤。

第一步是玩游戏，并计算状态和回报（returns）列表。

第二步是以回报为目标、以 `V(s)` 为预测来更新 `V(s)`。记住这是梯度下降，但它等同于计算该状态所有回报的平均值。

`V(s) = V(s) + alpha*(G - V(s))`

---

由于在本讲座中我们用参数 `theta` 来近似 `V(s)`，因此我们想要更新的是 `theta`。

所以现在我们继续进行随机梯度下降，但是是针对 `theta` 而不是 `V`。

`theta = theta + alpha*(G - V_hat(s))x`

---

记住这是针对固定策略的，因为我们正在解决预测问题。

让我们看一些伪代码来巩固这个想法。

我们首先输入一个策略 `pi`，并随机初始化 `theta` 向量。

接下来，我们进入一个迭代若干次的循环。

在每次迭代中，我们玩游戏，它返回一系列状态和回报。

我们遍历这些状态和回报，并将我们的更新方程应用于 `theta`，将回报视为目标。

```python
    # 使用 policy 生成回合

    seen_states = set()

        if s not in seen_states:

            x = s2x(s)

            # grad(V_hat) wrt theta = x
            theta += alpha*(G - V_hat)*x
            biggest_change = max(biggest_change, np.abs(old_theta - theta).sum())
        seen_states.add(s)
    deltas.append(biggest_change)
```

## TD(0) 半梯度预测理论

既然我们能够将近似方法应用于蒙特卡洛（Monte Carlo），那么提问我们是否也能将近似方法应用于 TD 学习也是合理的。

答案是肯定的，但有一个注意事项。

---

让我们先来看算法。

记住，蒙特卡洛和时序差分学习（Temporal Difference Learning）的主要区别在于，在时序差分学习中，我们不使用实际回报（return），而是根据奖励和下一个状态的价值函数来估计回报。

`theta = theta + alpha*[r+gamma*V_hat(s’) - V_hat(s)] d(V_hat(s))/d(theta)`

`theta = theta + alpha*[target - prediction] d(prediction)/d(theta)`

这个算法存在一个小问题。

问题在于我们在这里使用的目标（target）并不是真实的目标，因为它依赖于模型做出的预测，特别是 `V_hat(s’`。

所以从某种意义上说，我们正在使用模型的输出作为目标来修正模型参数，这看起来很奇怪。

但同时，它是通的，所以我们还是做了。

我们称这种为“半梯度”（semi-gradient）方法，因为我们使用的目标不是真实的目标，所以梯度也不是真实的梯度。

---

现在我们来看代码。

如果你不想尝试自己编写这些代码（尽管我强烈建议你这样做），相关文件是 `approx_semigradient_td0_prediction.py`。

记住，这与蒙特卡洛之间有两个主要区别。

第一点，如你所见，我们在更新 `theta` 时不使用回报。

正因如此，当我们玩游戏时，也不需要费心计算回报，因为我们将直接使用奖励。

```python
class Model:
    def __init__(self):
        self.theta = np.random.randn(4) / 2
    def s2x(self, s):
        return np.array([s[0] - 1, s[1] - 1.5, s[0]*s[1] - 3, 1])

    def predict(self, s):
        x = self.s2x(s)
        return self.theta.dot(x)

    def grad(self, s):
        return self.s2x(s)
```

所以我们有一个 `init` 函数，用它来初始化 `theta`。

我们有 `s2x` 函数，它将状态转换为特征向量。注意，我们使用了与蒙特卡洛阶段相同的特征转换。请注意，这些可能不是好的特征。

我们有 `predict` 函数，它接收状态 `s`，将其转换为 `x`，并返回 `theta` 和 `x` 之间的点积。

最后我们有梯度函数，它只返回 `x`。

## 近似方法

我们将近似方法应用在了课程早期学过的 3 种算法上。

有些来源指出，对于离策略控制方法使用近似方法没有良好的收敛特性。

## 解决 MDPs

在接下来的章节中，我们研究了解决 MDP 的 3 种不同方法。特别是，我们对解决两个问题感兴趣：预测问题（在给定策略的情况下寻找价值函数）和控制问题（寻找最优策略）。

### 动态规划
在动态规划的第一部分，我们直接应用了贝尔曼方程（Bellman’s Equation）来解决这两个问题。你学习了策略迭代（policy iteration）的思想，以及更高效的方法，即价值迭代（value iteration）。

我们学习到动态规划并不真正实用，因为它不从经验中学习，并且假设我们知道所有相关的概率分布。

### 蒙特卡洛方法
在下一节中，我们研究了蒙特卡洛方法，它只从经验中学习。通过蒙特卡洛，我们不再使用概率分布精确地计算期望值，而是使用样本平均值来估计它们。蒙特卡洛方法的问题是它不是完全在线的，如果你有非常长的回合或持续任务，就会出现问题。

### 时序差分学习
我们研究的最后方法是时序差分学习，结合了动态规划和蒙特卡洛的特性。`TD` 学习使用了自助引导（bootstrapping），这意味着它基于其他估计来做出估计，这使得它能够完全在线，因为我们不需要等待回合结束就可以进行更新。同时，`TD` 学习也从经验中学习，这意味着我们不需要 `MDP` 的概率模型。
