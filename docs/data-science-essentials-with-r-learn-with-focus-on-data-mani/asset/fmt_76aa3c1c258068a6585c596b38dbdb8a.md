# Calculations with dates and times

In this section, we will explore how to calculate lead and lag values, durations, periods, and intervals using the `lubridate` package.

## Leading and lagging calculations

The functions `lead()` and `lag()` from the `dplyr` package enable us to access previous (lagged) or subsequent (leading) values in a sequence, whether it is a numeric progression or a date sequence. These functions become particularly apparent when you need to compute changes or differences between consecutive time units.

However, it is crucial to note that the order of rows in your dataset carries significant importance when using `lead()` or `lag()`. Whether your dates or numbers are arranged in ascending or descending order can profoundly impact the results.

In the following analysis, we will explore the `electricity_subset` dataset by introducing a `previous_month_Value` column, to monitor values from the preceding month. Building on this, we will compute the value compared to the previous month, the numerical differences between consecutive months. We will also represent these variances as percentages in the `Percentage_Difference` column.

### 1. Create `previous_month_Value` column

```r
electricity_subset <- electricity_subset %>%
  select(Time, Value) %>%
  mutate(
    previous_month_Value = lead(Value)
  )
```

### 2. Calculate 'Value compared to previous month' and `Percentage_Difference`

```r
electricity_subset <- electricity_subset %>%
  mutate(
    Value_Compared_To_Previous_Month = Value - previous_month_Value,
    Percentage_Difference = round(((Value - previous_month_Value) / previous_month_Value) * 100, 2)
  )
```

In the `lubridate` package, there are multiple ways to represent a time span—through durations, periods, and intervals. Each representation serves its unique purpose and offers distinct functionalities.

## Durations

Duration allows you to measure periods of time in terms of seconds. The `lubridate` package also provides several functions to work with durations such as `dweeks()`, `ddays()`, `dminutes()`, and `dseconds()`. With these functions, you can easily convert between different units of time and perform calculations on them.

The following example tracks the duration of service downtime incidents to assess their impact. It creates a vector of downtime durations using the `duration()` function and calculates the total downtime by adding up the given list of downtime durations.

### 1. Downtime durations

```r
downtime_durations <- c(duration(hours = 1), duration(minutes = 30), duration(hours = 2))
```

## Periods

Periods are flexible representations of time spans that allow you to work with human-friendly units such as years, months, weeks, days, hours, minutes, and seconds. Unlike durations, periods do not specify a fixed length in seconds but instead adjust their length based on the underlying date-time. This makes periods ideal for tracking changes in clock time over long periods without worrying about specific second-level details. `lubridate` provides various methods to manipulate periods, including addition and subtraction operations, making it easy to perform complex temporal analysis tasks.

Let us look at an example of setting up reminders for subscription renewals by defining the renewal period in weeks:

### 1. Subscription renewal periods

```r
renewal_periods <- c(period(weeks = 2), period(weeks = 4), period(weeks = 6))
```

## Intervals

Intervals provide a way to define a time range between two specific points, allowing for greater precision when working with date-time data. The `interval()` function from `lubridate` creates an `Interval` object representing the specified start and end dates. The following code schedules events by defining intervals with start and end times.

### 1. Define event intervals

```r
event_intervals <- c(
  interval(ymd_hms("2023-08-01 10:00:00"), ymd_hms("2023-08-01 12:00:00")),
  interval(ymd_hms("2023-08-03 15:30:00"), ymd_hms("2023-08-03 17:00:00"))
)
```

### 2. Check if an event overlaps with a specific time

```r
check_time <- ymd_hms("2023-08-01 11:30:00")
overlapping_events <- event_intervals[check_time %within% event_intervals]
```
