

# 组修饰符

组修饰符是特殊的语法扩展，用于改变正则表达式中量词的行为。它们允许你指定量词应匹配其前面模式的次数。理解这些修饰符对于微调正则表达式以精确匹配文本数据至关重要。

使用下面的组修饰符，你可以指定特定模式应重复的次数，无论是零次或多次、一次或多次、特定次数，还是在某个范围内。

| 组修饰符 | 解释 |
| --- | --- |
| `*` | 匹配前一个模式的零次或多次重复（贪婪量词） |
| `+` | 匹配前一个模式的一次或多次重复（贪婪量词） |
| `?` | 使前一个模式变为可选（匹配零次或一次）。 |
| `{n}` | 精确匹配前一个模式的 n 次重复 |
| `{n,m}` | 匹配前一个模式 n 到 m 次重复 |
| `*?` | 匹配前一个模式的零次或多次重复（非贪婪量词） |
| `+?` | 匹配前一个模式的一次或多次重复（非贪婪量词） |

## 贪婪与非贪婪匹配

在正则表达式中，量词用于指定模式应匹配的次数。当应用于一组字符时，量词决定了在输入字符串中的匹配范围。贪婪和非贪婪修饰符是控制量词行为的特殊扩展。下表总结了贪婪和非贪婪量词之间的主要区别：

| 量词 | 行为 |
| --- | --- |
| 贪婪 | 匹配尽可能多的内容 |
| 非贪婪 | 匹配尽可能少的内容 |

表 6.13：正则表达式中的贪婪与非贪婪量词

`str_extract()` 函数默认使用贪婪匹配。这意味着如果你有一个包含量词（如 `*`、`+` 或 `{}`）的正则表达式模式，`str_extract()` 将尝试匹配满足该模式的最长可能字符串。

考虑这样一个场景：你有一段 HTML 代码，想要提取特定 HTML 标签内的内容。让我们创建一个示例 HTML 文本：

```r
# 示例 HTML 文本
text <- "<div class='main'><h1>Machine Learning & AI</h1><div> <a href='DataSciencewithR.pdf'>Data Science with R</a> </div></div>"

# 打印 'text'
text
```

```
## "<div class='main'><h1>Machine Learning & AI</h1><div> <a href='DataSciencewithR.pdf'>Data Science with R</a> </div></div>"
```

贪婪匹配是正则表达式的默认行为，即模式匹配尽可能多的输入字符串。

```r
# 贪婪匹配
str_extract(text, "<div>.*</div>")
```

```
## "<div> <a href='DataSciencewithR.pdf'>Data Science with R</a> </div></div>"
```

正则表达式 `<div>.*</div>` 匹配任何以 `<div>` 开头并以 `</div>` 结尾的字符串，中间的 `.*` 量词匹配零个或多个任意字符的序列。

现在，让我们在 `.*` 量词后添加一个 `?` 来将模式修改为非贪婪：

```r
# 非贪婪匹配
str_extract(text, "<div>.*?</div>")
```

这一次，函数返回了不同的结果：

```
## "<div> <a href='DataSciencewithR.pdf'>Data Science with R</a> </div>"
```

正则表达式 `<div>.*?</div>` 与之前的正则表达式相同，只是在 `.*` 量词后添加了一个 `?`。这个 `?` 告诉正则引擎尝试匹配满足该模式的最短可能字符串。

区别在于非贪婪模式 `<div>.*?</div>` 一遇到第一个闭合的 `<div>` 标签就停止匹配，而贪婪模式 `<div>.*</div>` 则继续匹配直到输入字符串的末尾。

## 检测与提取模式

本节将教授正则表达式在分析和从数据框中提取信息方面的实际应用。下面的数据框包含两条银行短信，一条用于借记交易，一条用于贷记交易。我们可以使用正则表达式从这些短信中提取信息，例如交易类型、金额和日期。

```r
# 创建数据框 "bank_messages"
bank_messages <- data.frame(
  message = c(
    "Your Bank Acc XX998006 is debited for INR 555.68 on 10-Nov-23 towards paytmqroihh5855ap@paytm. UPI Ref No 368033761556. If you have any concerns, please contact us at 1800-267-3456.",
    "Dear Customer, Your A/C XXXXX123456 has a credit by Cheque of Rs 80,000.00 on 30/10/23."
  )
)
```

让我们首先从 `bank_messages` 数据框的 `message` 列中提取提到的金额。这里我们假设所需的金额前面带有 INR 或 Rs。

```r
# 提取前面带有 "INR" 或 "Rs" 的金额
bank_messages <- bank_messages %>%
  mutate(amount = str_extract(message, "(?<=\\bINR\\s|\\bRs\\s)[0-9,]+\\.?[0-9]*"))

# 查看结果
View(bank_messages)
```

让我们分解一下 `str_extract` 函数中使用的正则表达式：

`"(?<=\\bINR\\s|\\bRs\\s)[0-9,]+\\.?[0-9]*"`

*   `(?<=\\bINR\\s|\\bRs\\s)`：这是一个正向后顾断言。它检查文本前面是否带有单词 INR 或 Rs（区分大小写）、单词边界 (`\\b`) 和空格 (`\\s`)。`\\b` 确保 INR 或 Rs 是一个完整的单词，而不是另一个单词的一部分。
*   `[0-9,]+`：这部分匹配一个或多个数字（0-9）或逗号。这允许捕获使用逗号作为千位分隔符的金额，例如 80,000。
*   `\\.?`：这匹配一个可选的小数点 (`.`)。反斜杠 (`\\`) 用于转义点号，因为在正则表达式中，点号是一个匹配任意字符的特殊字符。问号 (`?`) 使小数点成为可选的，从而允许整数和小数金额。
*   `[0-9]*`：匹配小数点后零个或多个数字，捕获金额的小数部分。

接下来，我们将创建两列 `credit` 和 `debit`，指示 `message` 列是否包含单词 credit 和 debit，包括 credited 和 debited 等变体。正则表达式使用 `str_detect` 函数来检查 "message" 列中是否存在指定的模式。

```r
# 添加列以指示消息是否包含 "credit" 或 "debit"
bank_messages <- bank_messages %>%
  mutate(
    has_credit = str_detect(message, "\\bcredit(ed)?\\b"),
    has_debit = str_detect(message, "\\bdebit(ed)?\\b")
  )

# 查看数据框
View(bank_messages)
```

上述命令确定每条消息是否包含单词 credit 或 debit 及其变体。`dplyr` 包中的 `mutate` 函数用于向银行短信数据框添加两个新列 `has_credit` 和 `has_debit`。

*   `\\b`：这是一个单词边界断言。它确保匹配 credit 或 debit 作为完整单词，而不是作为另一个单词的一部分。
