## 在线预测的模型部署

我们将打包成 Docker 镜像进行部署的模型包，包含执行模型所需的所有部分，包括运行环境、ML 框架、存储的模型文件和支持的后端微服务。另一方面，端点是计算资源所在的位置，您的模型在那里真正处理预测查询。对于自动扩缩，用户可以选择机器类型和其他因素。

模型必须部署在端点上，才能接受基于它的预测。请按照以下步骤部署模型。

### 步骤 1：模型部署

可以在**部署和测试**下发起模型部署，如[图 2.24](#ch02.xhtml#fig2-24)所示：

![](images/Figure_2.24.png)

**图 2.24：模型部署**

1.  转到**部署和测试**标签页。
2.  选择**部署到端点**。

### 步骤 2：端点定义

端点定义涉及的步骤可见于[图 2.25](#ch02.xhtml#fig2-25)：

![](images/Figure_2.25.png)

**图 2.25：端点创建**

1.  选择**创建新端点**。如果模型需要部署到现有端点，将提供**添加到现有端点**选项。
2.  为端点提供名称。
3.  除非用于私有访问，否则访问权限可以是标准的。
4.  点击**继续**。

### 步骤 3：模型设置

可以选择用于预测的流量分配和硬件，如[图 2.26](#ch02.xhtml#fig2-26)所示：

![](images/Figure_2.26.png)

**图 2.26：部署的模型设置**

1.  如果模型部署在多个端点中，可以在它们之间进行流量分配。如果模型仅部署在一个端点中，则必须设置为 100%。
2.  预测所需的节点数量。
3.  选择机器类型（如果模型非常复杂，建议选择配置良好的机器）。

向下滚动以选择日志记录选项，然后点击**继续**。

### 步骤 4：模型监控

按照[图 2.27](#ch02.xhtml#fig2-27)所示步骤，在生产环境中启用模型监控：

![](images/Figure_2.27.png)

**图 2.27：模型监控**

1.  用户可以为已部署的模型启用模型监控（模型也可以在不启用监控的情况下部署）。
2.  为监控作业提供名称。
3.  监控将由多个作业完成。需要提供作业的时间长度。如果预期负载较高，则建议设置较低的数值，反之亦然。
4.  用于接收警报的邮箱地址。
5.  可在监控窗口内选择请求的百分比进行采样。

输入架构对于 AutoML 模型是可选的，可以忽略。向下滚动并点击**继续**。

### 步骤 5：监控目标

模型性能会随时间下降。按照[图 2.28](#ch02.xhtml#fig2-28)所示步骤选择模型监控目标：

![](images/Figure_2.28.png)

**图 2.28：监控目标**

1.  预测请求记录在同一项目的 BigQuery 表中。然后分析记录请求中包含的输入特征值，以检测偏差或漂移（这需要训练数据进行比较）。
2.  模型监控跟踪特征对模型预测贡献随时间的变化（不需要训练数据）。
3.  由于我们选择了偏差检测，用户需要提供训练数据选项。
4.  选择用于训练 AutoML 模型的数据集。
5.  提供目标列名称。
6.  点击**部署**。

将模型部署到端点需要几分钟时间。

### 步骤 6：测试已部署的模型

按照[图 2.29](#ch02.xhtml#fig2-29)所示步骤，在进行在线预测之前，在平台上测试已部署的模型：

![](images/Figure_2.29.png)

**图 2.29：在线预测测试**

1.  模型部署成功。
2.  ID 是已部署模型的模型 ID。（一个端点可以部署多个模型）。相同的 ID 用于在线预测。
3.  即使在用户获得在线预测之前，用户也可以通过填充列值并点击屏幕底部的**预测**，在平台上测试模型输出。
4.  输出预测将填充概率得分。

## 服务账号创建

已部署的模型已准备好为预测请求提供服务。在发送数据和模型详细信息进行预测时，用户也应经过身份验证。在这些场景中，不能使用用户 GCP 账号详细信息进行身份验证；需要服务账号。请按照以下步骤创建服务账号。打开 **IAM 和管理** 并按照[图 2.30](#ch02.xhtml#fig2-30)所示步骤操作：

### 步骤 1：服务账号创建

![](images/Figure_2.30.png)

**图 2.30：服务账号**

1.  在 **IAM 和管理** 部分下选择**服务账号**。
2.  点击**创建服务账号**。

### 步骤 2：服务账号详细信息

按照[图 2.31](#ch02.xhtml#fig2-31)所示步骤添加账号详细信息：

![](images/Figure_2.31.png)

**图 2.31：服务账号详细信息**

1.  为服务账号提供名称。
2.  提供服务账号 ID。
3.  为服务账号提供描述。
4.  点击**创建并继续**。

更改服务账号的访问权限对此练习不是必需的。

### 步骤 3：为服务账号分配角色

在服务账号创建过程中，我们也授予该服务账号所需的某些角色访问权限。授予这些角色很重要，因为我们将使用同一个服务账号进行自定义模型构建、流水线等操作。按照[图 2.32](#ch02.xhtml#fig2-32)所示步骤授予角色。（这是可选步骤，也可根据需要随时完成）。

![](images/Figure_2.32.png)

**图 2.32：授予服务账号 AI Platform 访问权限**

1.  点击**选择角色**。
2.  在操作下选择 **AI Platform**。
3.  选择 **AI Platform 管理员**。

同样，添加[图 2.33](#ch02.xhtml#fig2-33)中显示的属于 Cloud Storage 和 Vertex AI 的其他一些角色：

![](images/Figure_2.33.png)

**图 2.33：授予服务账号其他访问权限**

### 步骤 4：服务账号管理密钥

创建服务账号后，用户需要创建密钥。按照[图 2.34](#ch02.xhtml#fig2-34)和[图 2.35](#ch02.xhtml#fig2-35)所示步骤创建密钥：

![](images/Figure_2.34.png)

**图 2.34：服务账号管理密钥**

1.  服务账号现已创建。
2.  点击已创建服务账号的操作，然后点击**管理密钥**。

### 步骤 5：服务账号添加密钥

![](images/Figure_2.35.png)

**图 2.35：服务账号密钥创建**

1.  点击**添加密钥**并选择**创建新密钥**。

弹出窗口将提供以 `json`/`P12` 格式创建密钥的选项。选择 `json` 格式，将下载一个 `.json` 文件。

> **注意：** 用户需要在 Python 代码中提供 `json` 文件的完整路径以进行身份验证。我们可以在下一章中使用相同的密钥。
