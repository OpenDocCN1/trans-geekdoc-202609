The example shows how anchors can provide essential insights into a model's prediction and its underlying reasoning. The result shows which attributes were taken into account by the model, which in this case, is the female sex and first class. Humans, being paramount for correctness, can use this to validate the model's behavior. The anchor also tells us that it applies to 15% of perturbation space's instances. In those cases the explanation is 97% accurate, meaning the displayed predicates are almost exclusively responsible for the predicted outcome.

An anchor A is formally defined as:

> $D_{x}(z|A)[f(x)=f(z)] \geq \tau, A(x) = 1$

Where:

- x represents the instance being explained (e.g. one row in a tabular data set).
- A is a set of predicates, i.e. the resulting rule or anchor, such that $A(x) = 1$ when all feature predicates correspond A to $x$'s feature values.
- f represents the classification model to be explained (e.g. an artificial neural network model). It can be queried to predict a label for $x$ and its perturbations.
- $D_{x}(|A)$ indicates the distribution of neighbors of $x$, matching $A$.
- $0 \leq \tau \leq 1$ specifies a precision threshold. Only rules that achieve a high fidelity of at least $\tau$ are considered a valid result.

The formal description may intimidating and can be put in words:

Given an instance $x$ to be explained, a rule or anchor A is to be found, such that it applies to $x$, the same class as $x$ gets predicted for a fraction of at least $\tau$ of $x$'s neighbors where the same A is applicable. A rule's precision from evaluating neighbors or perturbations (following $D_{x}(z|A)$) using the provided machine learning model (denoted by the indicator function $f(x)=f(z)$).

### 8.4.1 Finding Anchors

Although anchors' mathematical description may seem clear and straightforward, constructing particular rules is infeasible. It would require evaluating $all z \in \mathcal{D}_{f(x)=z)}(eg A)$ which is not possible in continuous or large input spaces. Therefore, the authors propose to introduce the parameter $0 \le \delta \le 1$ to create a probabilistic definition. The samples are drawn until there is a statistical confidence interval concerning their precision.

> $P(prec(A) \ge \tau) \ge 1 - \delta \quad \text{with} \quad prec(A) = \mathbb{E}_{\mathcal{D}_x(A)}[1_{\{f(x)=f\}}]$

The previous two definitions are combined and extended by the notion of coverage. Its rationale consists finding rules that apply to a preferably large part of the model's input space. Coverage is formally defined as an anchor's probability of applying to its neighbors, i.e. its perturbation space:

> $cov(A) = \mathbb{E}_{\mathcal{D}_x(z)}[A(z)]$

Including this element leads to anchor's final definition taking into account the maximization of coverage:

```
$\max \quad cov(A) \n\text{s.t.} \ P(prec(A) \ge \tau) \ge 1 - \delta$
```

Thus, the proceeding serve for a rule for that that has the highest coverage among all eligible rules (all those who satisfy the precision threshold given the probabilistic definition). These rules are thought to be more important, as they describe a larger part of the model. Note that rules with more predicates tend to have higher precision than rules with fewer predicates. In particular, a rule that fixes every feature of x reduces the evaluated neighborhood to identical instances. Thus, the model classifies all neighbors equally, and the's precision is 1. At the same time, a rule that fixes many features is overly specific and only applicable to a few instances. Hence, there is a trade-off between precision and coverage.

The anchors approach uses four main components to find explanations.

**Candidate Generation:** Generates new explanation candidates. In the first round, one candidate of x gets created and fixes the value of possible perturbations. In every other round, the best candidates of previous round are extended by one feature predicate that is not yet contained therein.

**Best Candidate Identification:** Candidate rules are to be compared in regard to which rule explains the best. To this end, perturbations that the currently observed rule are created and evaluated by calling the model. However, these calls need to be minimized as limit computational overhead. This is why, at the core of this component, there is a pure-exploration Multi-Armed-Bandit (MAB: KL-LUCB²), to be precise).

**Candidate Validation:** Takes samples until there is statistical confidence the candidate exceeds the threshold.

**Modified Beam Search:** All the above components are assembled in beam search, which is a variant of breadth-first algorithm. It carries the B candidates of each round over to the next (where B is called the Width). Since each feature can only be included in a rule at most once, the search conducts at most Count(x) rounds. Then, at every round, it generates B best out of B-p candidates. This makes it more likely to avoid local optima. MABs are used to efficiently explore and exploit different strategies with the model's input by observing respective outputs. In turn, this drastically reduces the algorithm's runtime.

### 8.4.2 Complexity and Runtime

Knowing the approach' asymptotic runtime behavior helps evaluate how well it is expected to perform on specific problems. Let $B$ denote the width and $p$ the number of all features. Then the anchors algorithm is subject to:

$\mathcal{O}(B \cdot p^2 + p^2 \cdot \mathcal{O}_{MAB}[B,p])$,

This boundary abstracts from problem-independent hyperparameters, such as the statistical confidence $\delta$. Ignoring hyperparameters helps reduce the boundary's complexity (see original paper for more info). Since the MAB extracts the $B$ best out of $B$-p candidates in each round, MABs and their runtime multiply the $p^2$ factor more than any other parameter. It thus becomes apparent: the algorithm's efficiency decreases when many features are present.
