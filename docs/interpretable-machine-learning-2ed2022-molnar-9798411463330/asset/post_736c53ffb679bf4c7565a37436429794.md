## 8.6 SHAP (Shapley Additive exPlanations)

SHAP (Shapley Additive exPlanations) by Lundberg and Lee (2017)42 is a method to explain individual predictions. SHAP is based on the game theoretically optimal Shapley values.

There are two reasons why SHAP got its own chair and is not a subchapter of Shapley values. First, the SHAP authors proposed KernelSHAP, an alternative, kernel-based estimation approach for Shapley values inspired by local surrogate models, and they proposed Tree-SHAP, an efficient estimation approach for tree-based models. Second, SHAP comes with many global interpretation methods based on aggregations of Shapley values. This chapter explains both the new estimation approaches and the global interpretation methods.

I recommend reading the chapters on Shapley values and local models (LIME) first.

### 8.6.1 Definition

The goal of SHAP is to explain the prediction of an instance x by computing the contribution of each feature to the prediction. The SHAP explanation method computes Shapley values from coalitional game theory. The feature values of a data instance act as players in a coalition. Shapley values tell us how to distribute the “payout” (= the prediction) among the features. A player can be an individual feature, e.g. for tabular data. A player can also be a group of feature values. For example to explain an image, pixels can be grouped into superpixels and the prediction distributed among them. One innovation that SHAP brings to the table is that the Shapley value is represented as an additive feature attribution method, a linear model. That connects LIME and Shapley values. SHAP specifies the explanation as:

```
g(z') = \phi_0 + \sum_{j=1}^{M} \phi_j z'_j
```

where g is the explanation model, z' \in {0,1}^M is the coalition vector, M is the maximum coalition size and \phi_j is the feature attribution for a feature j, the Shapley values. What I call "coalition vector" is is called "simplified features" in the SHAP paper. I think this name was chosen, for e.g. image data, the images are not represented on the pixel level, but aggregated to superpixels. I believe it is helpful to think about the z' as describing coalitions: In the coalition vector, an entry of 1 means that the corresponding feature value is “present” and 0 it is “absent”. This should sound familiar to if you know about Shapley values. To compute Shapley values, we simulate that some feature values are playing (“present”) and some are not (“absent”). The representation as a linear model of coalitions is a trick for the computation of the \phi's. For x, the instance of interest, the coalition vector x' is a vector of all 1s, i.e all feature values are “present”. The formula simplifies to:

### 8.6.2 KernelSHAP

KernelSHAP estimates for an instance $x$ the contributions of each feature to the prediction. KernelSHAP consists of five steps:

- Sample coalitions $z'_k \in \{0,1\}^M$, $k \in \{1, \dots, K\}$ ($1 =$ feature present in coalition, $0 =$ absent).
- Get prediction for each $z'_k$ by first converting $z'_k$ to the original feature space and then applying model $\hat{f} : h(z'_k)$
- Compute the weight for each $z'_k$ with the SHAP kernel.
- Return Shapley values $\phi_k$, the coefficients from the linear model.

We can create a random distribution by repeated flips until we have a chain of 0s and 1s. For example, the value of $(1,0,1)$ means that we have a coalition of the first and third features. The K sampled coalitions the dataset for the regression model. The target for the regression model is the prediction for a coalition. ("Hold on!", you say.) To get from coalitions to feature valid data instances, we define a function $h(z') = z$ where $h : \{0,1\}^M \rightarrow \mathbb{R}^p$. The function $h$ maps $z'$ to the corresponding value from an instance that $x$ we want to explain. For tabular data, it maps 0s to the value of another instance that we sample from data. This means we equate that "feature value is absent" with "feature value is replaced by random feature value from data".
