In particular, a rule that fixes every feature of x reduces the evaluated neighborhood to identical instances. Thus, the model classifies all neighbors equally, and the's precision is 1. At the same time, a rule that fixes many features is overly specific and only applicable to a few instances. Hence, there is a trade-off between precision and coverage.

The anchors approach uses four main components to find explanations.

**Candidate Generation:** Generates new explanation candidates. In the first round, one candidate of x gets created and fixes the value of possible perturbations. In every other round, the best candidates of previous round are extended by one feature predicate that is not yet contained therein.

**Best Candidate Identification:** Candidate rules are to be compared in regard to which rule explains the best. To this end, perturbations that the currently observed rule are created and evaluated by calling the model. However, these calls need to be minimized as limit computational overhead. This is why, at the core of this component, there is a pure-exploration Multi-Armed-Bandit (MAB: KL-LUCB²), to be precise). MABs are used to efficiently explore and exploit different strategies (called arms in an army to slot machines) using sequential selection. In this given setting, each candidate rule is to be seen as an anchor that can be pulled. Each time it is pulled, respective neighbors get evaluated, and we obtain more information about the candidate rule's payoff (precision in anchor's case). The precision thus how well the rules decide the instance to be explained.

**Candidate Precision Validation:** Takes samples in case there is no statistical confidence that the candidate exceeds the t threshold.

**Modified Beam Search:** All of the above components are assembled in a beam search, which is a graph search algorithm and a variant of the breadth-first algorithm. It carries the B candidates of each round over to the next (where B is called the Beam Width). These B rules are then used to create new rules. The beam search conducts at most featureCount(x) rounds, as each feature can only be included in a rule at most once. Then, at every round i, it generates candidates with exactly i predicts and selects the B best therefore, by setting B the algorithm is more likely to avoid local optima. In turn, this requires a high number of model calls and thereby increases the computational load.
