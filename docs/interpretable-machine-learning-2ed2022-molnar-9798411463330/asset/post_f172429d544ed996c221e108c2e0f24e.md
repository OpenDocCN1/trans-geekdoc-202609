The big difference between LIME is the weighting of the instances in the regression model. LIME weights the instances according to how close they are to the original instance. The 0's in the color vector, the smaller weight in LIME. SHAP weights the sampled instances according to the weight in the coalition would get the Shapley value estimation. Small coalitions (few 1s) and large coalitions (many 1s) get the largest weights. The intuition behind it: We learn more about individual features if we can study their effect in isolation. If a coalition consists of a single feature, we can learn about that feature's isolated effect on the prediction. If a coalition consists of all but one, we can learn about feature interactions. If a coalition consists of half the features, we can learn about an individual feature's contribution, as there are many possible coalitions with half of the features. To achieve Shapley weighting, Lundberg et al. propose the SHAP kernel:

```
$$\pi_x(z') = \frac{(M-1)}{|z'|(|M-|z'|)}$
```

Here, M is the maximum coalition size and $|z'|$ the number of present features in instance z'. Lundberg and Lee show that linear regression with this kernel weight yields Shapley values. If you would use the SHAP kernel with LIME on the coalition data, LIME would also estimate Shapley values!

For absent features (0), $h_i$ greys out the corresponding area. We can be a bit smarter about the sampling of coalitions: The smallest and largest coalitions take up most of the weight. We get better Shapley value estimates by using some sampling budget K instead of sampling blindly. We start with all coalitions 1 and M-1 features, which make 2M coalitions in total. When we have enough budget (current budget is K), we can include coalitions with M-2 features and so on. From the remaining coalition sizes, we use readjusted weights to build our linear regression:

```
$g(z') = \phi_0 + \sum_{j=1}^{M} \phi_j z'_j
```

We train the linear model g by optimizing the following loss function:

$L(\hat{f}, g, \pi_x) = \sum_{z' \in Z} [\hat{f}(h_x(z')) - g(z')]^2 \pi_x(z')$

Where $Z$ is the training data. This is the sum of squared errors that we usually optimize for linear models. The estimated coefficients $\phi_j$ are the Shapley values. Since we are in a linear regression setting, we can also use the standard tools. For example, we can add regularization terms to make the model sparse. If we add an L1 penalty to the loss L, we can create sparse explanations. I am not sure whether the resulting coefficients would be valid Shapley values though.

### 8.6.3 TreeSHAP

Lundberg et al. (2018) proposed TreeSHAP, a variant of SHAP for tree-based machine learning models such as decision trees, random forests and gradient boosted trees. TreeSHAP was introduced as a fast, model-specific alternative to KernelSHAP, but turned out it can capture feature attributes.

TreeSHAP defines the value function using the conditional expectation $E_{X_S}(x)|x_S)$ instead of the marginal expectation. With the conditional expectation that features have no influence on the prediction function $f$ we can get TreeSHAP estimate different from zero when the feature is correlated with another feature that actually has influence on the prediction. Sundarajan et al. (2019) and Janjing et al. (2019) showed this.

How much faster is TreeSHAP? Compared to exact KernelSHAP, it reduces the computational complexity from $O(TL^M)$ to $O(TD^2)$, where T is the number of trees, L is the maximum number of leaves in any tree and D the maximum depth of any tree. TreeSHAP uses the conditional expectation $E_{X_S}(f(x)|x_S)$ to estimate it. If we use some intuition on how we can compute the expected prediction for a single tree, an instance $x$ and feature $S$. If S is the set of all features — then the prediction in the node in which instance $x$ falls would be the expected prediction. If we would not condition on any feature — if S is empty — we would use weighted average of all terminal nodes. If S contains some, but not all, feature predictions of unreachable nodes. Unreachable nodes mean the decision path that leads to this contradicts values in $x_s$. From the remaining nodes, we average the weights by node size (i.e. number of training samples in that node). The mean of the remaining nodes, weighted by the number of instances per node, is the expected prediction for $x$ given S. The problem is that we have to apply this procedure for each possible subset $S$ of the feature values. TreeSHAP computes in polynomial time instead of exponential. The basic idea is to push all possible subsets down at the same time. For each decision node we have to keep track of the number of subsets. This depends on the subsets in the parent node and the split feature. For example, when the first split in a tree is on feature x3, then all the subsets that contain feature x3 will go to one node (the one we x). Subsets that do not contain feature x3 go to both nodes with reduced weight. Unfortunately, subsets of different sizes have different weights. The algorithm has to keep track the overall weight of the subsets in each node. This complicates the algorithm. I refer to the original paper for details of TreeSHAP. The computation can be expanded to many trees. Thanks to the Additivity property of Shapley values, the Shapley values of a tree ensemble is the (weighted) average of the Shapley values of the individual trees.
