The interaction term changes the interpretation of the weighted features. Does the temperature have a negative effect if it is a working day? The answer is no, even if the table suggests it to an untrained user. We cannot interpret the "workingdayWORKINGDAY:temp" interaction weight in isolation, since the interpretation would be: "Leaving all other feature values unchanged, the interaction effect of working day decreases the predicted number of bikes." But the interaction effect only adds to the main effect of the temperature. Suppose it is a working day and the temperature is 1 degree warmer today. Then we need to sum both weights for "temp" and "workingdayWORKINGDAY:temp" to determine how much the increases.

It is easier to understand the interaction visually. By introducing an interaction term between a categorical and a numerical feature, we get two slopes for the temperature instead of one. The temperature slope for days which people do not have to work ("NO WORKING DAY") The temperature slope for days on which people have to work ("WORKING DAY") is the sum of temperature weights (125.4 - 21.8 = 103.6). The intercept of the "NO WORKING DAY"-line at temperature = 0 is determined by the intercept term of the linear model (2185.8). The intercept of the "WORKING DAY"-line at temperature = 0 is determined by the intercept term + the effect of working day (2185.8 + 451.9 = 2637.7).

### 4.3.3 Nonlinear Effects - GAMs

**The world is not linear.** Linearity in linear models means that no matter value an instance has in a particular feature, increasing the value by one unit has the same effect on the predicted outcome. It is reasonable to assume that increasing the temperature by one degree at 10 degrees has the same effect as increasing from 40 degrees, which is also the case, as you will see throughout the book. The temperature has a linear positive effect on the number of rentals, but at some point it flattens out and has a negative effect at high temperatures. The linear model does not find the best linear plane (by minimizing Euclidean distance). You can model nonlinear relationships using one of the following techniques:

- Simple transformation of the feature (e.g. logarithm)
- Categorization of the feature
- Generalized Additive Models (GAMs)

Before I go into the details of each method, let us start with an example that illustrates all three them. I took the bike rental dataset and trained a linear model with only the temperature feature to predict the number of bikes. The following figure shows the estimated slope: the standard linear model, a linear model with transformed temperature (log), a linear model with temperature treated as categorical and using splines (GAM).

### Feature transformation

Often the logarithm of the feature is used as transformation. Using the logarithm indicates that every degree increase has the same effect on the number of bikes as changing from 0 to 1. Other examples for feature transformations are the square root and the exponential function. Using feature transformation means that you replace the column of this feature in the data with a function of the feature and fit the linear model as usual. Some statistical programs also allow you to specify transformations in the call of the linear model. You can be creative when you transform the feature. The interpretation of the feature changes according to the selected transformation. If you use a log transformation, the interpretation in a linear model becomes: "If the logarithm of the feature is increased by one, the prediction is increased by the corresponding weight." When you use a GLM with a link function that is not the identity function, then the interpretation gets more complicated because you have to incorporate both transformations into the interpretation (except when they cancel each other out, like log and exp, then the interpretation gets easier).

### Feature categorization

Another possibility to achieve a nonlinear effect is to discretize the feature; turn it into a categorical feature. For example, you could cut the temperature into intervals with the levels [-10, -5], [-5, 0], and so on. When you use the categorized temperature instead of the continuous feature, the linear model would estimate as a step function because each level gets its own estimate. The problem with this approach is that it needs more data, it is more likely to overflow and it is unclear how to discretize the feature meaningfully (equidistant intervals or quantiles? how many intervals?). Is there a very strong case for it? For example, to make the model comparable to another study.

### Generalized Additive Models (GAMs)

Why 'simply' allow the (generalized) linear model to learn nonlinear relationships? That is the motivation behind GAMs. GAMs relax the restriction that the relationship must be a simple weighted sum, and instead assume that the outcome can be modeled by a sum of arbitrary functions of each feature. Mathematically, the relationship in a GAM looks like this:

```
E(y|x) = β_0 + f_1(x_1) + f_2(x_2) + ... + f_k(x_k)
```

The formula is similar to the GLM formula with the difference that the linear term $\beta_jx$ is replaced by a more flexible function $f_j(x)$. The core of a GAM is still a sum of feature effects, but you have power to allow nonlinear relationships between features and the output. Linear effects are also covered by the framework, but for features to be handled linearly, you can limit their $f_j(x_j)$ to only the form of $x_j\beta_j$.

The big question is how to learn nonlinear functions. Another is called "splines" or "spline functions". Splines are functions that are constructed from simpler basis functions. Splines can be used to approximate more complex functions. Although there is a confusing number of ways to define these spline functions, if you are interested in learning more about all the ways to define basis functions, I wish you luck on your journey. I am not going to go into details here, I just going to build an intuition. What helped me the most for understanding splines was to visualize the basis functions and to look into how the data matrix is modified. For example, to model the temperature with splines, we remove the temperature feature from the data and replace it with, say, 4 columns, each representing a spline basis. Usually you would have more spline basis functions, I only reduced the number for illustration purposes. The value for each instance of these new spline basis depends on the instances' temperature values. Together with all linear effects, the GAM then also estimates these spline weights. GAMs also introduce a penalty term for the weights to keep them close to zero. This effectively reduces the flexibility of the splines and prevents overfitting.
